Distinct enforcement sites for memo visibility:

- **gRPC/API v1 service layer** — per-memo access check in the memo service (`memo.Visibility != store.Public` → require auth; `Private` → creator only) — `server/router/api/v1/memo_service.go:55-66`; the same pattern gates related RPCs: comments (`server/router/api/v1/memo_service_comments.go:41`), reactions (`server/router/api/v1/reaction_service.go:30-38, 83`), attachments (`server/router/api/v1/attachment_service.go:451`, `server/router/api/v1/memo_attachment_service.go:214-222`), and list queries injected as CEL filters like `visibility in ["PUBLIC","PROTECTED"]` (`server/router/api/v1/memo_service_comments.go:158-160`, `server/router/api/v1/memo_relation_service.go:109-111`)
- **File server (attachment/blob serving)** — anonymous access only for `Public` memos on public instances, `Private` restricted to creator/admin — `server/router/fileserver/fileserver.go:674-699`
- **RSS feeds** — queries are hard-restricted to `VisibilityList: []store.Visibility{store.Public}` — `server/router/rss/rss.go:90` and `:141`
- **Frontend router (server-rendered meta/OG pages)** — only `store.Public` memos are looked up — `server/router/frontend/frontend.go:150`
- **SSE real-time event hub** — server-side delivery filtering in `SSEClient.canReceive`: `Private` events delivered only to the creator or an admin — `server/router/api/v1/sse_hub.go:134-144`
- **Notification/email surface** — email content is redacted/suppressed based on `memo.Visibility` (`Private`/`Protected` handling) — `server/notification/email.go:313-316`; likewise notification conversion at `server/router/api/v1/user_service_notifications.go:309-312`, and mention notifications skip users who can't see a `Private` memo (`server/router/api/v1/memo_mention_helpers.go:62-67`)
