**Delivery function: `Post()` — `internal/webhook/webhook.go:120`; protection mechanism: dial-time reserved/private-IP blocking via `safeDialContext` / `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

Details:

- **Where delivery executes:** `webhook.Post()` (`internal/webhook/webhook.go:120-180`) builds the JSON POST, adds Standard Webhooks HMAC-SHA256 signature headers if a signing secret is set, and sends it via the shared `safeClient`. Callers usually go through `PostAsync()` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded channel drained by four worker goroutines (`init()` at `internal/webhook/webhook.go:42-55`) that each call `Post()`. Server-side triggers live in e.g. `server/router/api/v1/memo_service_webhooks.go`.
- **SSRF protection:** the HTTP client's transport replaces the dialer with `safeDialContext` (`internal/webhook/webhook.go:32-37, 59-77`), which resolves the hostname and refuses to connect if any resolved IP falls in a reserved range — loopback, RFC-1918, link-local/cloud IMDS (169.254.169.254), and IPv6 equivalents, listed in `reservedCIDRs` (`internal/webhook/validate.go:14-23`) and checked by `isReservedIP` (`internal/webhook/validate.go:44`). Enforcing this at dial time also defeats DNS-rebinding. There is additionally an input-time check, `ValidateURL` (`internal/webhook/validate.go:62`), applied when webhooks are registered, and an `AllowPrivateIPs` escape hatch (`internal/webhook/validate.go:41`) for self-hosted deployments.
