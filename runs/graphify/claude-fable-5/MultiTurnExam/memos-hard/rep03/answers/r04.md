**Premise correction: neither.** There is no message broker in this codebase — no NATS, RabbitMQ, Kafka, or any external queue dependency. Webhook delivery uses a **plain in-process Go channel**.

**Actual mechanism** (all in `internal/webhook/webhook.go`):

- The "queue" is a buffered channel declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`.
- The "workers" are four goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`); each ranges over `asyncPostQueue` and calls `Post()` (`:120`) to perform the actual HTTP delivery.
- Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send — if the 128-slot buffer is full, the dispatch is **dropped with a logged warning**, not persisted or retried, underscoring that there's no durable broker semantics.

So there is no queue declaration in any broker: the entire async delivery pipeline is the channel plus goroutines within the `internal/webhook` package, living and dying with the server process.
