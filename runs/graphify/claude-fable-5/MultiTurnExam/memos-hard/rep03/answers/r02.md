**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** A repo-wide search for rate-limiting constructs (`ratelimit`, `rate limit`, `throttle`, `limiter`, `RateLimiter`, `golang.org/x/time/rate`) finds nothing registered on any router. The Echo server registers only `middleware.Recover()` and a CORS middleware at startup (`server/server.go:51-52`), plus auth/ACL interceptors in the API layer (`server/router/api/v1/v1.go`) — none of which count requests per user.

The closest things that exist are **concurrency caps, not rate limits**:

- Thumbnail generation is bounded by a weighted semaphore (`maxConcurrentThumbnails`) in the file server — `server/router/fileserver/fileserver.go:106-116, 447-451`.
- The API service similarly holds `thumbnailSemaphore` (3) and `imageProcessingSemaphore` (2) — `server/router/api/v1/v1.go:39-41, 59-60`.
- The webhook dispatch queue is bounded (channel of 128 with 4 workers) — `internal/webhook/webhook.go:39-55`.

These limit simultaneous expensive operations server-wide; they are not per-user, have no request-per-time-window limits, and are not middleware. So there is no registration site or request limit to cite — the feature doesn't exist in this repository.
