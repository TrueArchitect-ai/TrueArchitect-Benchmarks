**Premise correction:** There is no Redis connection anywhere in this codebase — a repo-wide search for "redis" in Go sources returns nothing. The cache layer is a purely **in-process, in-memory cache** built on `sync.Map`.

**Actual mechanism:**
- The cache implementation is `store/cache/cache.go` — a thread-safe in-memory `Cache` with per-item TTL, periodic cleanup, and a max-item cap (`Cache` struct and `New()` at `store/cache/cache.go:66-80`; `DefaultConfig` at `:56-63`).
- It is instantiated in `store.New` (`store/store.go:38-58`), which creates three caches — `instanceSettingCache`, `userCache`, `userSettingCache` — all with the same config: **`DefaultTTL: 10 * time.Minute`**, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:40-45`).
- **User entries therefore live for 10 minutes**: `Store.GetUser` populates `userCache` via `s.userCache.Set(...)` (`store/user.go:167`), and `Set` applies the default TTL (`store/cache/cache.go`, `Set` → `SetWithTTL` with `config.DefaultTTL`).
- The caches are torn down in `Store.Close` (`store/store.go:74-76`), which stops the cleanup goroutines — no external cache service is ever contacted.
