**Computation site**: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74-88`. It runs the memo's raw markdown through `markdownService.ExtractAll` (goldmark single-pass parser, `internal/markdown/markdown.go:356`) and writes the results into the memo's `Payload` (`storepb.MemoPayload`), which is persisted alongside the memo and used for list filtering/previews.

**Triggers** (operations that recompute it):

- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (before `Store.CreateMemo`); this also covers comment creation, which goes through the memo-creation path.
- `UpdateMemo` when the `content` field is in the update mask — `server/router/api/v1/memo_service.go:447` (recomputes payload, then persists via `update.Payload`).
- The batch backfill runner `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:52` — which rebuilds payloads for all memos in batches (declared but not wired into server startup in production code).

**Extracted properties** (`ExtractedData`, `internal/markdown/markdown.go:21-25`, stored at `runner.go:85-86`):

- `Tags` — all `#tag` occurrences (via the tag extension).
- `Property` (`storepb.MemoPayload_Property`, `proto/gen/store/memo.pb.go:87-90`) — four booleans computed from the AST: `HasLink`, `HasCode`, `HasTaskList`, and `HasIncompleteTasks` (`internal/markdown/markdown.go:394-404`).
- `ExtractAll` also returns `Mentions` (`@user` references), but those are used for notification dispatch rather than stored in the payload — `RebuildMemoPayload` persists only `Tags` and `Property`.
