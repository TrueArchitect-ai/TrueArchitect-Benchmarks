**Premise correction: neither. There is no message broker in this codebase — no NATS, RabbitMQ (AMQP), Kafka, or any broker client appears anywhere in the Go code or `go.mod`.**

Actual mechanism: webhook delivery is queued entirely in-process using a buffered Go channel.

- The "queue" is declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a plain buffered channel, capacity 128.
- The "workers" are four goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`); each ranges over `asyncPostQueue` and calls `Post(payload)` to perform the actual HTTP delivery.
- Producers call `webhook.PostAsync(...)` (`internal/webhook/webhook.go` bottom), which does a non-blocking send into the channel; if the buffer is full, the dispatch is dropped with a logged warning rather than being persisted or retried.

So delivery is best-effort and in-memory only — nothing survives a process restart, and there's no external queuing infrastructure involved.
