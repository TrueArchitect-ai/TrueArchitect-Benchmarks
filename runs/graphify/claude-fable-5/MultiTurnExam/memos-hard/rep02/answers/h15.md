Distinct memo-visibility enforcement sites across server surfaces:

- **gRPC/Connect API read check** — `APIV1Service.checkMemoReadAccess` — `server/router/api/v1/memo_service.go:39-68`: on `GetMemo` (and archived-memo access) it requires authentication for non-public memos and denies `Private` memos to anyone but the creator.
- **gRPC/Connect API list filtering** — `ListMemos` — `server/router/api/v1/memo_service.go:219-225`: constrains the store query's `VisibilityList` to `Public` for anonymous callers and `Public, Protected` when viewing other users' memos.
- **File server (attachment/media downloads)** — `FileServerService.checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650-704`: gates serving attachment bytes by the owning memo's visibility (anonymous access only for `Public` on instances allowing it, share-token fallback, `Private` restricted to creator or admin).
- **RSS feeds** — `server/router/rss/rss.go:90` and `:141`: both feed queries hard-filter to `VisibilityList: []store.Visibility{store.Public}`, so only public memos ever appear in RSS.
- **Frontend sitemap** — `FrontendService.getSitemapXML` — `server/router/frontend/frontend.go:149-151`: lists only `store.Public` memos for sitemap URLs.
- **SSE real-time event delivery** — `SSEClient.canReceive` — `server/router/api/v1/sse_hub.go:134-144` (events tagged with visibility in `server/router/api/v1/sse_event_helpers.go:29-37`): `Private` memo events are delivered only to the creator or an admin; unknown visibility is denied.
