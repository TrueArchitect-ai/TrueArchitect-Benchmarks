**Premise correction: there is no nightly database-cleanup job, and no cron scheduler is actually running in the server — so no such schedule exists.**

What the repo actually contains:

- A cron-capable scheduler library exists at `internal/scheduler/` (with a cron-expression parser in `internal/scheduler/parser.go` and a job runner in `internal/scheduler/scheduler.go`), but it is **never imported by any production code** — a repo-wide grep shows its only usages are its own docs, examples, and tests (`internal/scheduler/doc.go`, `example_test.go`, `integration_test.go`).
- The only scheduled background work the server runs is the S3 presigned-URL refresh runner, which uses a plain `time.Ticker` every 12 hours (`server/runner/s3presign/runner.go:26`), wired in `server/server.go:162-171`. It refreshes URLs; it is not a database cleanup.
- No vacuum/purge/cleanup job exists anywhere: cleanup-related code is all inline with request handling (e.g. attachment storage cleanup during user deletion in `server/router/api/v1/user_service.go:421-450`, memo relation/attachment cleanup in `store` delete paths), and the periodic "cleanup" that does exist is the in-memory cache's expired-entry sweep every 5 minutes (`store/cache/cache.go`), which has nothing to do with the database.
