**Premise correction: there is no per-user API rate-limiting middleware in this codebase — it doesn't exist, so it isn't registered anywhere and has no limits.**

What I checked:

- A repo-wide search for rate-limiting terms (`rate limit`, `ratelimit`, `throttle`, `limiter`) in Go code finds only a documentation comment suggesting rate limiting as a *future* consideration for email sending (`internal/email/doc.go:86`) — no implementation.
- The full HTTP middleware stack is registered in `NewServer` at `server/server.go:51-52` and consists of exactly two middlewares: `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`). Echo's built-in `RateLimiter` middleware is not used.
- The gRPC-Gateway/Connect layer (`server/router/api/v1/v1.go:67-97`) adds only authentication/authorization middleware, not rate limiting.

The closest things to request limiting in the server are concurrency semaphores, not per-user rate limits: `thumbnailSemaphore` (3 concurrent thumbnail generations) and `imageProcessingSemaphore` (2) in `server/router/api/v1/v1.go:59-60`, and a matching thumbnail semaphore in `server/router/fileserver/fileserver.go:106-107`. There's also a bounded webhook dispatch queue (`internal/webhook/webhook.go`). None of these track users or request rates.
