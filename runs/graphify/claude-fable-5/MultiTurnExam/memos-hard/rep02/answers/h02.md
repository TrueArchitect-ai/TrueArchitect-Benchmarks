**Delivery function: `webhook.Post()` — `internal/webhook/webhook.go`; protection mechanism: `safeDialContext` dial-time SSRF guard (backed by `isReservedIP`/`reservedCIDRs`, plus create-time `ValidateURL`) — `internal/webhook/webhook.go` and `internal/webhook/validate.go`.**

How it works:

- **Where delivery executes**: `Post()` in `internal/webhook/webhook.go` builds the JSON body, adds Standard-Webhooks HMAC signature headers when a signing secret is set, and sends the POST via the shared `safeClient`. Callers on the API side (e.g. `server/router/api/v1/memo_service_webhooks.go`) go through `PostAsync()`, which enqueues the payload onto `asyncPostQueue`; four worker goroutines started in the package `init()` drain the queue and each call `Post()` — so the actual outbound HTTP happens in those background workers inside `internal/webhook/webhook.go`.
- **What blocks internal addresses**: `safeClient`'s `http.Transport` uses `safeDialContext` (`internal/webhook/webhook.go`) as its `DialContext`. At dial time it resolves the target hostname and refuses the connection if any resolved IP falls in a reserved range — checked by `isReservedIP()` against `reservedCIDRs` in `internal/webhook/validate.go` (loopback, RFC-1918 ranges, link-local/cloud-IMDS `169.254.0.0/16`, and IPv6 equivalents). Doing this at dial time also defeats DNS-rebinding, since the check applies to the IPs actually used for the connection. A second, earlier layer is `ValidateURL()` in `internal/webhook/validate.go`, which rejects non-http(s) schemes and reserved-IP hostnames when a webhook is created/updated. The `AllowPrivateIPs` flag in `validate.go` can disable the guard for self-hosted deployments that intentionally target LAN services.
