**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in Go code returns nothing — the cache layer is a purely **in-process, in-memory cache**, not an external store.

Actual mechanism:

- The cache is implemented in `store/cache/cache.go`: `Cache` is described as "a thread-safe in-memory cache with TTL and memory management" (`cache.go:66`), backed by a mutex-protected map with a background cleanup goroutine — no network connection or external service is configured at all.
- User entries live in `Store.userCache` (`store/store.go:28`), created in `store.New` at `store/store.go:52` with `cache.New(cacheConfig)`.
- **The TTL that applies to user entries is 10 minutes**: `cacheConfig.DefaultTTL: 10 * time.Minute` (`store/store.go:40-41`, matching the package default in `store/cache/cache.go:59`), with a cleanup sweep every 5 minutes and a 1000-item cap. Entries are written via `Set(...)` (e.g. `Store.GetUser`/`UpdateUser` in `store/user.go`), which applies that default TTL (`store/cache/cache.go:92-94`).
