**Premise correction:** there is no Redis anywhere in this codebase. A repo-wide grep for "redis" in Go sources returns nothing — no Redis client dependency, connection config, or DSN exists.

**Actual mechanism:** the cache layer is a purely **in-process, in-memory cache** implemented in `store/cache/cache.go` — a mutex/`sync`-based map of items with per-entry expiration, a background cleanup goroutine, and an item cap (`Config` at `store/cache/cache.go:41-54`, `New` at `cache.go:76`).

The user cache is constructed in `store.New` at `store/store.go:38-53`: `userCache: cache.New(cacheConfig)` with a hard-coded config of **`DefaultTTL: 10 * time.Minute`** (plus `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`) at `store/store.go:40-45`. User entries are written via plain `Set` (e.g. `store/user.go:143,167`), which applies the default TTL — so **user cache entries live for 10 minutes**, in process memory, with no external cache server involved.
