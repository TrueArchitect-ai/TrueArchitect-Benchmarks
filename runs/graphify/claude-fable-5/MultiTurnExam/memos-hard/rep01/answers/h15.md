Memo visibility is enforced at (at least) six distinct sites across five server surfaces:

- **API single-memo read guard** — `checkMemoReadAccess` at `server/router/api/v1/memo_service.go:39-67`: non-public memos require an authenticated user; private memos require creator (archived memos creator-only). Reused by GetMemo, comment, reaction, and related handlers.
- **API list-query filtering** — `ListMemos` at `server/router/api/v1/memo_service.go:216-227`: anonymous callers get `VisibilityList = [Public]`; authenticated callers get a `creator_id == me || visibility in ["PUBLIC","PROTECTED"]` filter pushed into the store query.
- **File server (attachment serving)** — access check in `server/router/fileserver/fileserver.go:660-705`: public memo attachments served anonymously only when the instance allows it; a valid non-expired per-memo share token can grant access; otherwise requires an authenticated user, and private-memo attachments require creator or admin (`fileserver.go:699`).
- **SSE event delivery** — `(*SSEClient).canReceive` at `server/router/api/v1/sse_hub.go:134-144`: private-memo events are delivered only to the creator or an admin; unknown visibility values are denied (event visibility attached in `server/router/api/v1/sse_event_helpers.go:29-37`).
- **RSS feeds** — `server/router/rss/rss.go:90` and `rss.go:141`: feed queries hard-restrict to `VisibilityList: []store.Visibility{store.Public}`.
- **Frontend HTML meta rendering** — `server/router/frontend/frontend.go:150`: memo pages get OpenGraph/meta injection only for `store.Public` memos.
