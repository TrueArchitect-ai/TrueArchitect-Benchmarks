**No.** The MySQL driver is only ever constructed inside the driver-selection factory.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:14`, which calls `mysql.NewDB(profile)` in its `case "mysql"` branch (`store/db/db.go:22`).
- A repo-wide grep for the import path `github.com/usememos/memos/store/db/mysql` finds exactly one importer: `store/db/db.go:8`. Since `mysql.NewDB` (defined at `store/db/mysql/mysql.go:20`) can only be called by code that imports that package, no other file can construct it.
- Everything else that needs a MySQL-backed driver goes through the factory instead: the test harness calls `db.NewDBDriver(profile)` at `store/test/store.go:28` and `store/test/store.go:50` (with the driver name selected as a string, e.g. `"mysql"` in `store/test/store.go:88` and `store/test/main_test.go:25`), and the benchmark at `server/router/api/v1/test/memo_service_benchmark_test.go:70` does the same. Other files mentioning "mysql" (`store/test/containers.go`, `internal/filter/*`, etc.) only deal with DSNs, containers, or SQL dialect strings — not driver construction.
