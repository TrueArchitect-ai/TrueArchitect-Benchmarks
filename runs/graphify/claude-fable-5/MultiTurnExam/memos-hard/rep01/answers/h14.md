The derived metadata is the memo's **payload** (`MemoPayload` with `Tags` and `Property`), computed from the markdown content.

**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`. It calls `markdownService.ExtractAll(memo.Content)` (single goldmark parse, `internal/markdown/markdown.go:356`) and writes the results into `memo.Payload.Tags` and `memo.Payload.Property`. The property extraction logic itself lives in the markdown service's AST walk (`internal/markdown/markdown.go:192-240`).

**Triggers (production call sites):**
- **Memo creation** — `CreateMemo` handler calls `RebuildMemoPayload` before persisting, at `server/router/api/v1/memo_service.go:108` (this also covers comment creation, since `CreateMemoComment` routes through `CreateMemo` internally, per `memo_service.go:23`).
- **Content update** — `UpdateMemo` recomputes it whenever the `content` field is updated, at `server/router/api/v1/memo_service.go:447`.
- (A batch rebuild-all exists in `memopayload.Runner.RunOnce` at `server/runner/memopayload/runner.go:27,52`, but that runner is never constructed/invoked in production code.)

**Extracted properties:**
- `Tags` — all `#tags` found in the content (`internal/markdown/markdown.go:22`, tag extension enabled at `server/router/api/v1/v1.go:48`).
- `Property.Title` — text of the document's first block if it's an H1 heading (`internal/markdown/markdown.go:208-213`).
- `Property.HasLink` — any markdown link node (`markdown.go:216-217`).
- `Property.HasCode` — code block, fenced code block, or inline code span (`markdown.go:219-220`).
- `Property.HasTaskList` and `Property.HasIncompleteTasks` — task checkboxes, and whether any is unchecked (`markdown.go:222-228`; proto fields in `proto/gen/store/memo.pb.go:87-90`).

These feed list/preview features (e.g. filtering by tag, showing task/link/code indicators) without the user setting them.
