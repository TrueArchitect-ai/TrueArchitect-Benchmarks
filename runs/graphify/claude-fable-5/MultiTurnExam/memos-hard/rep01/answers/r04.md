**Premise correction: neither.** There is no message broker in this codebase — no NATS, RabbitMQ, Kafka, or any external queue client appears in the Go sources or module dependencies.

**Actual mechanism:** webhook delivery uses a plain **in-process Go channel** as a bounded queue:

- The "queue" is declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`.
- The "workers" are four goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over the channel and calling `Post()` (`internal/webhook/webhook.go:120`) to execute the outbound HTTP delivery.
- Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184`), which does a non-blocking send and **drops the event with a log warning if the 128-slot buffer is full** — there is no persistence, retry, or acknowledgment semantics as a real broker would provide.

So delivery is entirely in-memory within the server process; if the process exits, queued webhook deliveries are lost.
