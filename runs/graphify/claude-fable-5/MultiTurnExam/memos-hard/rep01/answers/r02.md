**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** A repo-wide search for rate-limit/throttle/limiter code in Go sources finds nothing (the only hit is a documentation comment suggesting rate-limiting email sending, `internal/email/doc.go:86` — not implemented as middleware).

What is actually registered:

- Echo HTTP middleware is only `middleware.Recover()` and a CORS middleware — `server/server.go:51-52`.
- The Connect/gRPC API stack registers exactly four interceptors: metadata, logging, recovery, and auth — `server/router/api/v1/v1.go:133-138`. None performs rate limiting.

The closest things to request limiting are not per-user rate limits:

- A request **size** cap on the API: `connect.WithReadMaxBytes(maxAPIRequestBytes)` — `server/router/api/v1/v1.go:141`.
- **Concurrency** semaphores, global not per-user: 3 concurrent thumbnail generations and 2 concurrent image-processing operations in the API service (`server/router/api/v1/v1.go:59-60`), and a thumbnail semaphore in the file server (`server/router/fileserver/fileserver.go:107,116`).

So no registration site or request-per-user limits exist to cite.
