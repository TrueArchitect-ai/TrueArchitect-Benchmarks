**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in the Go sources returns nothing — no client library, no connection config, no external cache service at all.

**Actual mechanism:** the cache layer is a purely in-process, thread-safe in-memory cache implemented in `store/cache/cache.go` (a `sync.Map` with TTL expiration, a background cleanup goroutine, and item-count-based eviction). The store constructs three instances of it — including the user cache — in `Store.New` at `store/store.go:40-53`.

**TTL for user entries:** user entries use the shared `DefaultTTL` of **10 minutes** (`store/store.go:41`), with cleanup running every 5 minutes and a 1,000-item cap (`store/store.go:42-43`). Entries are written via `Set` (default TTL) on user reads/writes, e.g. in `Store.GetUser`/`ListUsers` (`store/user.go:136-168`), and the caches are torn down in `Store.Close` (`store/store.go:74-76`).
