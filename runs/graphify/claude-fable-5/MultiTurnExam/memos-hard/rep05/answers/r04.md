**Premise correction: neither — there is no message broker in this codebase.** No NATS, RabbitMQ, Kafka, or any other broker client appears in the Go sources or `go.mod`.

**Actual mechanism:** webhook delivery uses a plain in-process Go channel as a bounded queue, declared in `internal/webhook/webhook.go:39`:

- `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel holding up to 128 pending deliveries.
- The package's `init()` (`internal/webhook/webhook.go:42-55`) starts **4 worker goroutines** that range over the channel and call `Post(payload)` for each item — `Post` (`webhook.go:120`) performs the actual signed HTTP POST via the SSRF-guarded `safeClient`.
- Producers enqueue via `PostAsync` (`webhook.go:184-196`), which does a non-blocking send: if the channel buffer is full, the dispatch is **dropped with a logged warning** rather than blocking the request path.

So delivery is fire-and-forget within the server process; there's no persistence, broker, or retry queue — a full buffer or a process restart loses pending webhook deliveries.
