Memo visibility is enforced independently on six server surfaces:

- **gRPC/Connect API (memo endpoints)** — centralized check `checkMemoReadAccess` — `server/router/api/v1/memo_service.go:39` (used by `GetMemo`/comments at `memo_service.go:356`, `memo_service_comments.go:148`); list endpoints additionally constrain the query's `VisibilityList`. Related API endpoints repeat the private-memo owner/admin check inline: reactions (`server/router/api/v1/reaction_service.go:38,83`), attachments (`server/router/api/v1/attachment_service.go:445-451`), memo attachments (`server/router/api/v1/memo_attachment_service.go:222`), and comment creation (`server/router/api/v1/memo_service_comments.go:41`).
- **File server (attachment/media downloads)** — `checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650`: public memos served only when anonymous access is allowed, share-token fallback, otherwise authenticated owner/admin required for private memos (`fileserver.go:677-699`).
- **RSS feeds** — queries are hard-restricted to `store.Public` memos only — `server/router/rss/rss.go:90` and `rss.go:141`.
- **Frontend router (SSR/meta/sitemap for public pages)** — memo lookup restricted to `VisibilityList: []store.Visibility{store.Public}` — `server/router/frontend/frontend.go:150`.
- **SSE realtime delivery** — the hub filters which connected users may receive a memo event by its visibility in `canReceive` — `server/router/api/v1/sse_hub.go:135` (visibility attached to events in `server/router/api/v1/sse_event_helpers.go:29-37`).
- **Notification emails / mention notifications** — content is withheld based on visibility before notifying: `server/notification/email.go:313-316`, `server/router/api/v1/user_service_notifications.go:309-312`, and mention targets are only notified if they can see the memo (`server/router/api/v1/memo_mention_helpers.go:62-67`).
