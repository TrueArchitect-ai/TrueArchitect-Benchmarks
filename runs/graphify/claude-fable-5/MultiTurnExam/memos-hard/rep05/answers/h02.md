**Delivery function: `webhook.Post` — `internal/webhook/webhook.go:120`; protection mechanism: dial-time SSRF guard `safeDialContext`/`isReservedIP` — `internal/webhook/webhook.go:59` + `internal/webhook/validate.go:44`**

Details:

- **Outbound delivery** executes in `Post()` at `internal/webhook/webhook.go:120`, which builds the JSON POST (optionally signed with Standard-Webhooks HMAC headers) and sends it via the shared `safeClient` (`webhook.go:152`). Asynchronous dispatch goes through `PostAsync()` (`webhook.go:184`), which enqueues onto a bounded channel drained by 4 worker goroutines that each call `Post` (`webhook.go:42-55`). The API layer triggers these from `server/router/api/v1/memo_service_webhooks.go` (e.g. `DispatchMemoCreatedWebhook`) and `server/router/api/v1/user_service_webhooks.go`.
- **Protection against internal addresses** is layered:
  1. At delivery time, `safeClient`'s transport uses `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the hostname and refuses to connect if any resolved IP falls in a reserved/private range per `isReservedIP` (`internal/webhook/validate.go:44`). Blocking at dial time also defeats DNS-rebinding attacks.
  2. At configuration time, `ValidateURL` (`internal/webhook/validate.go:62`) rejects webhook URLs that are non-http(s) or resolve to reserved ranges.
  
  The blocked ranges (`reservedCIDRs`, `validate.go:14`) cover loopback, RFC-1918 private space, link-local/cloud IMDS (169.254.0.0/16), and IPv6 equivalents; the escape hatch `AllowPrivateIPs` (`validate.go:41`) disables the guard for self-hosted deployments.
