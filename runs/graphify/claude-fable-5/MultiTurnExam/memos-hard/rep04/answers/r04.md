**Premise correction: neither.** There is no message broker in this codebase — no NATS, RabbitMQ, AMQP, or Kafka dependency or reference exists anywhere (repo-wide grep over Go sources and `go.mod` comes up empty).

**Actual mechanism:** webhook delivery is entirely in-process, using a buffered Go channel as the "queue":

- The queue is declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39`.
- The workers are 4 plain goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`); each ranges over the channel and calls `Post(payload)` to perform the HTTP delivery (`Post` at `internal/webhook/webhook.go:120`).
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send and **drops** the event with a warning log if the 128-slot buffer is full — so there's no durable broker semantics at all: no persistence, no acknowledgements, no retries beyond the single attempt.
