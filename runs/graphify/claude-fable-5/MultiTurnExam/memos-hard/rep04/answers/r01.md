**Premise correction:** there is no Redis in this codebase. A repo-wide search for "redis" finds nothing — the cache layer is a homegrown, thread-safe **in-memory** cache (`Cache` in `store/cache/cache.go`), living in the server process. No external cache connection is configured anywhere.

**Actual mechanism:** the store constructs three of these in-memory caches — including the user cache — in `store.New` at `store/store.go:38-53`, all with the same hard-coded config: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:40-45`; matching `DefaultConfig()` in `store/cache/cache.go:55-63`). User entries are written via `Set` (e.g. `s.userCache.Set(...)` in `store/user.go`), which applies the default TTL (`store/cache/cache.go:92-94`), so **user cache entries live 10 minutes**, with expired items lazily rejected on read (`cache.go:135`) and swept by a cleanup goroutine every 5 minutes (`cache.go:201`).
