**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** No such middleware is registered anywhere, and no request limits exist.

What I checked:

- A repo-wide search for rate-limit/throttle/limiter terms in Go code turns up nothing except a doc comment suggesting rate limiting as a *future* consideration for email sending (`internal/email/doc.go:86` — "Rate limit email sending to prevent abuse").
- The only global Echo middleware registered at server startup is `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`); the API layer adds authentication/authorization interceptors (`server/router/api/v1/v1.go:95` and surrounding gateway setup), not rate limiting.
- `go.mod` has no rate-limiter dependency; `golang.org/x/time` appears only as an indirect dependency (`go.mod:151`) and is not used for limiting.

The closest things that exist are not per-user rate limits: bounded concurrency semaphores for expensive image work (3 concurrent thumbnail generations, 2 concurrent image-processing ops, `server/router/api/v1/v1.go`), a bounded async webhook queue (128 entries, `internal/webhook/webhook.go`), and API pagination caps (`MaxPageSize` in the memo service). None of them count or limit requests per user.
