The derived metadata is the memo's **payload** (`MemoPayload`): tags plus content "properties," stored alongside the memo and used by list views/filters/previews.

**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`. It runs the goldmark-based `markdownService.ExtractAll` (`internal/markdown/markdown.go`, interface at line 31–33, single-pass extraction) over `memo.Content` and writes `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers (operations causing recomputation):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (every new memo)
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only when the update mask includes the `content` path (recomputed before persisting the new content)
- A batch rebuild path exists in the `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:52`) for rebuilding all memos' payloads, but that runner is never invoked from production code.

**What it extracts** (via `ExtractedData`, `internal/markdown/markdown.go:21-25`, into `MemoPayload_Property`, `proto/gen/store/memo.pb.go:85-92`):
- `Tags` — all `#tags` in the content
- `Property.HasLink`, `Property.HasTaskList`, `Property.HasCode`, `Property.HasIncompleteTasks` — boolean content features
- `Property.Title` — the title taken from the first H1 heading, if present

(Separately, the preview *snippet* shown in lists is not stored in the payload — it's computed on the fly at read time via `getMemoContentSnippet` in `server/router/api/v1/memo_service_converter.go:76` using `GenerateSnippet`.)
