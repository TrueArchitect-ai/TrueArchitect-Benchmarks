**Tables: memo_relation, attachment, memo**

When `Store.DeleteMemo` (`store/memo.go:140-158`) runs, the explicit cascade code touches:

1. **memo_relation** — deleted twice, for rows where the memo is the source (`MemoID`) and where it is the target (`RelatedMemoID`) (`store/memo.go:142-147`).
2. **attachment** — each attachment linked to the memo is deleted via `Store.DeleteAttachment` (`store/memo.go:149-156`, `store/attachment.go` — which also removes the underlying file/blob storage, though that isn't a table).
3. **memo** — the memo row itself, last (`store/memo.go:158`, SQL `DELETE FROM memo` in e.g. `store/db/sqlite/memo.go`).

Additionally, the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:568-578`) first deletes all comment memos (relations of type `COMMENT`), calling `Store.DeleteMemo` for each — which hits the same three tables again for every comment. Reactions are listed for the webhook payload but not deleted by this path.
