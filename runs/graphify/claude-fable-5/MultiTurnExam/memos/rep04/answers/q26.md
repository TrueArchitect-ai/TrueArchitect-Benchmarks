**Tables: `memo_relation`, `attachment`, `memo`**

When `Store.DeleteMemo` runs (`store/memo.go:140-159`), the explicit cascade code affects:

1. **memo_relation** — deleted twice, for rows where the memo is the source (`MemoID`) and where it is the target (`RelatedMemoID`) (`store/memo.go:142-147`)
2. **attachment** — every attachment linked to the memo is deleted via `Store.DeleteAttachment` (`store/memo.go:149-157`, `store/attachment.go:132-149` — this also removes the underlying file from local/S3 storage, which is filesystem/object storage, not a table)
3. **memo** — the memo row itself, via the driver's plain `DELETE FROM memo` (`store/db/sqlite/memo.go:237-247`)

At the API layer, `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) additionally deletes all comment memos first (each a recursive `Store.DeleteMemo`, hitting the same three tables). No other tables (e.g. `reaction`) are deleted by explicit cascade code — reactions are only listed for the webhook payload, and the schema (`store/migration/sqlite/LATEST.sql`) defines no foreign-key cascades.
