**Interceptor: `authInterceptor` in web/src/connect.ts** (defined at line 156, attached to the main transport at line 188; token storage helpers in `web/src/auth-state.ts`).

**Tokens managed:**
- **Short-lived access token** — attached to every request as an `Authorization: Bearer <token>` header (`setAuthorizationHeader`, `web/src/connect.ts:97`), kept in frontend state via `getAccessToken`/`setAccessToken`.
- **Refresh token** — an HttpOnly cookie sent with `credentials: "include"` through a separate interceptor-free `refreshTransport` (`web/src/connect.ts:64-72`); on expiry or a 401 the interceptor calls the `RefreshToken` RPC (deduplicated by `tokenRefreshManager`) to get a new access token, then retries once (marked with the `X-Retry` header).

**Backend validation package: server/auth** — `server/auth/authenticator.go` validates short-lived access tokens (`AuthenticateByAccessTokenV2`), refresh tokens from the cookie (`AuthenticateByRefreshToken`), and Personal Access Tokens (`AuthenticateByPAT`), with token parsing in `server/auth/token.go` and header/cookie extraction in `server/auth/extract.go`. It's invoked via the shared `Authorizer` in `server/router/api/v1/authz.go` for both gateway and Connect requests.
