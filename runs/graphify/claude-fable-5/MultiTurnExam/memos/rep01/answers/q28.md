Background workers the server actually starts:

- **S3 presign runner (`s3presign.Runner`) — timer-driven**: started in `Server.startBackgroundRunners` (`server/server.go:153-173`); it runs once at startup (`RunOnce`) and then on a `time.Ticker` every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). It is the **only** runner the server starts.
- **Webhook async delivery workers — queue-driven**: 4 goroutines started in the `init()` of `internal/webhook/webhook.go:42-55`, draining the buffered channel `asyncPostQueue`; they're triggered by enqueued webhook payloads, not by any schedule.

**Unused scheduling infrastructure:** the memo-payload runner in `server/runner/memopayload/runner.go` defines a `Runner` with `NewRunner` and `RunOnce` (a rebuild-all sweep), but the server never constructs or starts it — `server/server.go` only starts the s3presign runner. Only the package's standalone helper `memopayload.RebuildMemoPayload` is used, called synchronously from the memo handlers (`server/router/api/v1/memo_service.go:108`, `:447`). So the memopayload Runner scheduling machinery is present but not wired into the server.
