**Computation site:** The derived metadata is the memo's `Payload` (tags + content properties), computed by `memopayload.RebuildMemoPayload()` in `server/runner/memopayload/runner.go:74`. It calls the markdown service's single-pass extractor `ExtractAll()` in `internal/markdown/markdown.go:356` (a standalone `ExtractProperties()` variant also exists at `internal/markdown/markdown.go:193`), then stores the results into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers for recomputation:**
- **Memo creation** — `CreateMemo` calls `RebuildMemoPayload` before inserting (`server/router/api/v1/memo_service.go:108`).
- **Memo content update** — `UpdateMemo` calls it whenever the update mask includes the `"content"` path (`server/router/api/v1/memo_service.go:447`).
- **Bulk rebuild** — `Runner.RunOnce` in `server/runner/memopayload/runner.go:27` re-derives the payload for all memos in batches of 100 (a maintenance/migration rebuild; I found no live call site wiring this runner into server startup in the current tree, so it appears to be invoked only ad hoc).

**Extracted properties:** From a single goldmark AST walk of the content:
- `Tags` — all `#tag` nodes in the content.
- `Property.Title` — plain text of the first block-level element if it's an H1 heading.
- `Property.HasLink` — any link node present.
- `Property.HasCode` — any code block, fenced code block, or inline code span.
- `Property.HasTaskList` — any task checkbox.
- `Property.HasIncompleteTasks` — any unchecked task checkbox.

(`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` persists only `Tags` and `Property` into the payload.) These `MemoPayload_Property` fields (`storepb`) are what list views and previews consume without reparsing the markdown.
