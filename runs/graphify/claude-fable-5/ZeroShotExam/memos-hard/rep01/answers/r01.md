**Premise correction:** There is no Redis in this repository. A repo-wide search for "redis" returns nothing — the cache layer is not Redis-backed, so there's no Redis connection to configure anywhere.

**Actual mechanism:** The cache is a custom thread-safe **in-memory** cache built on `sync.Map`, defined in `store/cache/cache.go` (the `Cache` type at `store/cache/cache.go:67`, with TTL-stamped items and a background cleanup goroutine).

Its configuration lives in two places:
- Defaults: `DefaultConfig()` in `store/cache/cache.go:57` — `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`.
- The store's actual wiring: `store.New()` in `store/store.go:38` builds a `cache.Config` with the same values (10-minute TTL, 5-minute cleanup, 1000 max items) and creates three separate caches from it: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`).

**TTL for user entries:** User objects are written to `userCache` via `Set()` (e.g. `store/user.go:98`, keys from `userCacheKey()` at `store/user.go:88`), and `Set()` applies the default TTL (`store/cache/cache.go:93-95`). So user cache entries live for **10 minutes**, with expired items also swept by the cleanup loop every 5 minutes. Entries can be evicted earlier if the cache exceeds 1000 items (oldest-first eviction), and are explicitly invalidated on user deletion (`store/user_delete.go:40`).
