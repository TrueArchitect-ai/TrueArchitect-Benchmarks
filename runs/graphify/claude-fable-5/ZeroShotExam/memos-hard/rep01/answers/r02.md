The premise of the question is incorrect: **this repository has no per-user API rate-limiting middleware.** There are no request limits to report because none are implemented.

What the middleware/interceptor stack actually contains:

- `server/server.go:51-52` — Echo registers only `middleware.Recover()` and a CORS middleware (`newCORSMiddleware` from `server/cors.go`).
- `server/router/frontend/frontend.go:54-63` — static file serving and an SPA fallback middleware.
- `server/router/api/v1/v1.go:67-135` — API-layer middleware/interceptors: a gRPC-Gateway auth middleware, plus Connect interceptors (`NewMetadataInterceptor`, `NewLoggingInterceptor`, and auth). None of them throttle requests.

A repo-wide search for rate-limiting terms (`rate limit`, `ratelimit`, `throttle`, `limiter`, `tollbooth`, `golang.org/x/time/rate`) finds only documentation *suggesting* rate limiting as future work for the email subsystem — `internal/email/README.md:286-295` shows an example using `rate.NewLimiter(rate.Every(time.Second), 10)` (10 emails/second), and `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a recommendation. That is unimplemented example code for outbound email, not registered per-user API middleware.
