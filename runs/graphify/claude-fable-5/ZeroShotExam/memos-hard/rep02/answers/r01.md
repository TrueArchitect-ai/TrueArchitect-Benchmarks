**Premise correction:** There is no Redis in this codebase. A repo-wide search for "redis" (Go, TypeScript, config files) returns zero matches, and the knowledge graph shows the entire cache layer living in a single in-process package. The cache is not a network-backed store at all — there is nothing to configure a connection for.

**Actual mechanism:** The cache layer is a thread-safe **in-memory** cache built on `sync.Map`, defined in `store/cache/cache.go`. It's configured (not via any connection string, but as a plain struct) in `store/store.go:40-45`, where `Store.New()` creates three cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing this config:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute` (background `cleanupLoop` goroutine evicts expired items)
- `MaxItems: 1000` (over the limit, `cleanupOldest` evicts by expiration order)

**TTL for user entries:** User entries are written via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. `store/user.go:98,122,132,143,167`). `Set` delegates to `SetWithTTL` using the default TTL (`store/cache/cache.go:93-95`), so **user cache entries live for 10 minutes**, subject to the 5-minute cleanup sweep and eviction if the 1000-item cap is exceeded.
