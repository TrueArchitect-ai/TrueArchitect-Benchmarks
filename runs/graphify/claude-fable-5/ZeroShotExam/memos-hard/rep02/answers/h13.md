Markdown processing in this repo sits behind the `markdown.Service` interface defined at `internal/markdown/markdown.go:31` (ExtractAll, ExtractTags, RenderMarkdown, RenderHTML, GenerateSnippet, etc.).

**impl** — The single concrete implementation is the unexported `service` struct (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown` instance configured with GFM plus the custom tag/mention extensions (`internal/markdown/extensions/`). For markdown re-rendering it internally uses `renderer.NewMarkdownRenderer()` (`internal/markdown/renderer/markdown_renderer.go`), but that is a helper, not a second `Service` implementation. No other type implements the interface.

**construction** — At runtime it is constructed exactly once, by `apiv1.NewAPIV1Service` via `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())` (`server/router/api/v1/v1.go:48`; the factory itself is `NewService` at `internal/markdown/markdown.go:85`). `server/server.go:76` creates the API service and then reuses that same instance for RSS at `server/server.go:85` (`rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)`). Tests construct their own instances (`server/router/api/v1/test/test_helper.go:44`, `server/router/fileserver/fileserver_test.go:427`, `server/router/rss/rss_test.go:54`), but those don't run in production.

**holders** — Components holding the interface as a field:
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — used throughout memo handling, e.g. passed into `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)` at `server/router/api/v1/memo_service.go:108` and `:447`.
- `RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — receives the shared instance for server-side HTML rendering of feeds.
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) also declares the field, but I found no runtime call to `memopayload.NewRunner` — only the standalone `RebuildMemoPayload` function is used, so the Runner holder is effectively dormant.

So at runtime there is one shared goldmark-backed `service` instance, built in `NewAPIV1Service` and held by `APIV1Service` and `RSSService`.
