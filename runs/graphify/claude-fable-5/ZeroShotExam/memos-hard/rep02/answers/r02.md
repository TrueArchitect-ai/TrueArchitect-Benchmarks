**Premise correction: this repository has no per-user API rate-limiting middleware.** The question assumes something that doesn't exist in the codebase, so there is no registration point or request limit to cite.

What actually exists:

- The HTTP middleware stack is registered in `server/server.go:51-52`, and it consists only of `middleware.Recover()` and a CORS middleware (defined in `server/cors.go`). No rate limiter (e.g. Echo's `middleware.RateLimiter`) is used.
- The API layer's interceptors in `server/router/api/v1/connect_interceptors.go` handle metadata conversion and logging, and `server/router/api/v1/authz.go` handles authorization — again, no rate limiting.
- The only mentions of rate limiting anywhere in the repo are advisory documentation, not implementation: `internal/email/README.md:286-295` shows an example of how a caller *could* wrap email sending with `rate.NewLimiter` (10 emails/second), and `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a security recommendation. Neither is wired into the server, and neither is per-user API rate limiting.
