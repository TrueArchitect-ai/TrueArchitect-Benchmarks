The premise of the question is incorrect: this repository (the `usememos/memos` codebase) has no cron scheduler and no nightly database-cleanup job, so there is no scheduled time to report.

What the codebase actually has for background work:

- No cron library is imported anywhere (no `robfig/cron`, `gocron`, or similar in `go.mod` or the server code), and there is no crontab or scheduler configuration file.
- Background jobs are plain Go goroutines started in `server/server.go` (`startBackgroundRunners`, around line 153). There are only two runners, in `server/runner/`:
  - `server/runner/s3presign/runner.go` — refreshes S3 presigned URLs on a `time.Ticker` every 12 hours (`const runnerInterval = time.Hour * 12`, lines 26–27). This is interval-based, not scheduled at a clock time, and it isn't a database cleanup.
  - `server/runner/memopayload/runner.go` — rebuilds memo payloads once (`RunOnce`), not on a schedule.

The only cron-like syntax in the repo is in `.github/workflows/stale.yml`, which is a GitHub Actions workflow for marking stale issues/PRs — not a database-cleanup job in the application.
