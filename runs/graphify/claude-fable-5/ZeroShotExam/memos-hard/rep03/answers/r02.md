What the API layer actually registers:

- **Echo HTTP middleware** in `server/server.go:51-52`: `middleware.Recover()` and a CORS middleware — no rate limiter.
- **Connect RPC interceptors** in `server/router/api/v1/v1.go:133-137`: `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, and `NewAuthInterceptor()` (defined in `server/router/api/v1/connect_interceptors.go`) — again, no rate limiting.
- The only request-size-related constraint is `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`, which caps request body size, not request rate.

The sole mention of rate limiting anywhere is an aspirational comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which describes a future consideration for the email package, not implemented middleware. So there are no request limits to report — the feature doesn't exist in this codebase.
