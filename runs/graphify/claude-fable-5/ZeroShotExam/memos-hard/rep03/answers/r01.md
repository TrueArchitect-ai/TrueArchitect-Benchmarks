**Premise correction:** There is no Redis in this repository. A search for "redis" across the Go source, web frontend, configs, and `go.mod` returns zero hits — the cache layer is not backed by Redis or any external store.

**Actual mechanism:** The cache is a custom thread-safe **in-memory** cache built on `sync.Map`, defined in `store/cache/cache.go`. Each `Store` instance creates three separate caches (instance settings, users, user settings) in `store/store.go:40-53`, all sharing the same config:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute` (background goroutine sweeps expired items)
- `MaxItems: 1000` (oldest ~20% evicted when exceeded)

**TTL for user entries:** User entries are written via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. `store/user.go:98,122,132,167`). `Set` delegates to `SetWithTTL` with the default TTL (`store/cache/cache.go:93-95`), so user cache entries live for **10 minutes**. Expired entries are also lazily evicted on read in `Get` (`store/cache/cache.go:135-144`). The cache key format is defined by `userCacheKey()` at `store/user.go:88`.
