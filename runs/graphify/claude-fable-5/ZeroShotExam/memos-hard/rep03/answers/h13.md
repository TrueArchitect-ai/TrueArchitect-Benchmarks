**impl** — The single concrete implementation is the unexported `service` struct wrapping a `goldmark.Markdown` instance (`internal/markdown/markdown.go:57`–59). It implements the `Service` interface declared at `internal/markdown/markdown.go:31` (ExtractAll, ExtractTags, ExtractProperties, RenderMarkdown, RenderHTML, GenerateSnippet, ValidateContent, RenameTag). There is only one runtime implementation; no alternates exist.

**construction** — `markdown.NewService(opts...)` (`internal/markdown/markdown.go:85`) builds it, configuring goldmark with GFM plus the optional custom Tag and Mention extensions (`internal/markdown/extensions/`). At runtime it is constructed exactly once, in `NewAPIV1Service` (`server/router/api/v1/v1.go:48`) with `WithTagExtension()` and `WithMentionExtension()`. The server then reuses that same instance: `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService`. (A second construction site, `server/router/api/v1/test/test_helper.go:44`, is test-only.)

**holders** — Three components hold the `markdown.Service` interface as a field:
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — used for snippets, mention extraction, and payload rebuilds (`memo_service_webhooks.go:85`, `memo_mention_helpers.go:32`, `memo_service.go:108,447`)
- `RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — for server-side HTML rendering of feeds
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) — though at runtime the API layer calls the package-level `RebuildMemoPayload(ctx, memo, markdownService)` function directly rather than going through a constructed `Runner`; no call site for `memopayload.NewRunner` exists outside its definition.

So: `service` (goldmark-backed) — constructed once by `markdown.NewService` inside `NewAPIV1Service`, shared with RSS via `server.go` — held by `APIV1Service`, `RSSService`, and `memopayload.Runner`/`RebuildMemoPayload`.
