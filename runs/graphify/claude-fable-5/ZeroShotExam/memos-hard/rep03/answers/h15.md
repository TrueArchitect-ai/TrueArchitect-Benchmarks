The graph query surfaced the memo/visibility neighborhood but was too coarse for exact sites, so I verified each one in the source. Memo visibility is enforced independently at these server surfaces:

- gRPC memo read access (`checkMemoReadAccess`, used by GetMemo, parent-memo expansion, and ListMemoComments) — `server/router/api/v1/memo_service.go:39-68` (caller in `server/router/api/v1/memo_service_comments.go:148`)
- Memo list filtering (anonymous callers forced to `Public` only; authenticated callers to own memos plus Public/Protected) — `server/router/api/v1/memo_service.go:219-225`
- Attachment service access check for attachments linked to a memo — `server/router/api/v1/attachment_service.go:436-455`
- Memo-attachment listing (`ListMemoAttachments` re-checks the memo's visibility before returning attachments) — `server/router/api/v1/memo_attachment_service.go:214-224`
- Reaction service (checks memo visibility before listing/creating reactions) — `server/router/api/v1/reaction_service.go:30-38` and `:83`
- File server blob delivery (visibility check plus anonymous-instance and share-token rules when serving attachment files over HTTP) — `server/router/fileserver/fileserver.go:677-701`
- SSE real-time event delivery (`SSEClient.canReceive` drops events for private memos unless the subscriber is the creator or an admin) — `server/router/api/v1/sse_hub.go:134-143`
- RSS feeds (queries restricted to `VisibilityList: []store.Visibility{store.Public}`) — `server/router/rss/rss.go:90` and `:141`
- Frontend sitemap/OpenGraph rendering (only Public memos are exposed) — `server/router/frontend/frontend.go:150`
- Mention/notification helpers (suppress notifications that would reveal a private memo to a non-creator) — `server/router/api/v1/memo_mention_helpers.go:62-84`

The first three or four are the primary API enforcement points; the fileserver, SSE hub, RSS, and frontend routers are separate surfaces that each duplicate the check because they bypass the gRPC service layer.
