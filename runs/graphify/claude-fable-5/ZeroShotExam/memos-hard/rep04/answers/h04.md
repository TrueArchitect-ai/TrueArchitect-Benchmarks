Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14`, which calls the MySQL constructor `mysql.NewDB(profile)` at `store/db/db.go:22` when `profile.Driver == "mysql"`.
- A repo-wide search for calls to `mysql.NewDB` finds exactly one call site: `store/db/db.go:22`. The factory's import at `store/db/db.go:8` is also the only place outside `store/db/mysql/` that imports the `store/db/mysql` package at all, so no other package can construct the driver.
- All other consumers go through the factory: `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(...)`.
- The one direct construction: `store/db/mysql/auth_config_test.go:12` builds a zero-value driver with `db := &DB{}` (bypassing `NewDB`, defined at `store/db/mysql/mysql.go:20`) to unit-test the `IsRetryableAuthenticationMutationError` method. This is inside the `mysql` package's own test file, not production code.

So: the `mysql.NewDB` constructor is never invoked outside the factory, but the `DB` struct is instantiated directly via a struct literal in one intra-package test.
