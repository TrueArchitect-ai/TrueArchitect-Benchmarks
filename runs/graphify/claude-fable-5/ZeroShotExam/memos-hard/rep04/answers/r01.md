**Premise correction:** There is no Redis in this repository. A repo-wide search for "redis" turns up nothing, and the graphify knowledge graph confirms the cache community (`store/cache/cache.go`) has no external-store dependencies. The cache layer is a purely in-process, in-memory cache.

**Actual mechanism:**

- The cache implementation is `store/cache/cache.go` — a thread-safe in-memory cache (`Cache` struct at `store/cache/cache.go:67`) built on `sync.Map`, with per-item TTL expiration and a background cleanup goroutine (`cleanupLoop`, `store/cache/cache.go:200`). No connection is configured anywhere because there's no external cache server.
- The cache instances are configured in `store/store.go:38-58` (`store.New`), which creates three caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing this config (`store/store.go:40-45`):
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
- **TTL for user entries: 10 minutes.** User entries are written to `userCache` via plain `Set` calls (e.g. `store/user.go:98,122,132,143,167`), which delegates to `SetWithTTL` using `config.DefaultTTL` (`store/cache/cache.go:93-95`) — so users get the default 10-minute TTL; no custom TTL is applied. The same default is also mirrored in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`). Entries are keyed by `userCacheKey()` (`store/user.go:88`) and explicitly invalidated on delete (`store/user_delete.go:39-40`).
