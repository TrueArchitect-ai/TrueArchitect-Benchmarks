h15.

This repository is a memos-style server, and memo visibility (`PUBLIC` / `PROTECTED` / `PRIVATE`) is enforced independently at several server surfaces. I verified each by reading the code (the graphify graph pointed at the memo/server communities, but the precise checks come from the source). The distinct enforcement sites are:

- **Memo API read/list (gRPC API v1)** — `server/router/api/v1/memo_service.go` (visibility check for single-memo access at lines 55–66: non-public requires auth, private requires creator; plus `ListMemos` injecting a `VisibilityList`/creator filter at lines 218–226)
- **Memo comments API** — `server/router/api/v1/memo_service_comments.go` (private parent memo blocks commenting/listing unless creator or superuser, line 41)
- **Reactions API** — `server/router/api/v1/reaction_service.go` (listing reactions, lines 30–38, and upserting a reaction, line 83, are gated on the memo's visibility)
- **Attachment API (linked attachments)** — `server/router/api/v1/attachment_service.go` (attachment access gated by the linked memo's visibility, lines 445–451)
- **Memo attachment listing API** — `server/router/api/v1/memo_attachment_service.go` (same visibility gate before listing a memo's attachments, lines 214–222)
- **File server (HTTP binary serving)** — `server/router/fileserver/fileserver.go` (serves attachment bytes only if the memo is public on an anonymous-allowed instance, a valid non-expired share token is presented, or the user passes the private/creator check, lines 677–702)
- **SSE event delivery** — `server/router/api/v1/sse_hub.go` (`canReceive` filters server-sent events so private-memo events reach only the creator or an admin, lines 134–144)
- **User stats API** — `server/router/api/v1/user_service_stats.go` (stats queries restricted to `Public`/`Protected` or own memos, lines 84–90 and 218–220)
- **Sitemap (frontend router)** — `server/router/frontend/frontend.go` (sitemap lists only `store.Public` memos, line 150)

Related but secondary: notification paths also honor visibility before telling a user about a memo — `server/notification/email.go` (lines 313–316), `server/router/api/v1/user_service_notifications.go` (lines 309–312), and `server/router/api/v1/memo_mention_helpers.go` (lines 62–67), which suppress mention/comment notifications the target isn't allowed to view.
