The webhook subsystem in the memos server handles this, and both the delivery and the guard live in `internal/webhook/`.

**Delivery function** — `Post()` in `internal/webhook/webhook.go:120`. It marshals the payload, optionally adds Standard-Webhooks HMAC-SHA256 signature headers, and executes the outbound HTTP POST via `safeClient.Do(req)` (`internal/webhook/webhook.go:152`). Callers usually go through `PostAsync()` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded channel drained by four worker goroutines started in `init()` — those workers call `Post()`. Content-change triggers come from the API layer, e.g. `server/router/api/v1/memo_service_webhooks.go`.

**Protection mechanism** — a dial-time SSRF guard: `safeClient`'s transport uses `safeDialContext()` (`internal/webhook/webhook.go:59`), which resolves the target hostname and refuses to connect if any resolved address matches `isReservedIP()` (`internal/webhook/validate.go:44`), backed by the `reservedCIDRs` list (`internal/webhook/validate.go:14`) covering loopback, RFC-1918 private ranges, link-local/cloud-IMDS (169.254.0.0/16), and their IPv6 equivalents. Because the check happens at dial time rather than only at URL-save time, it also defeats DNS-rebinding attacks. A complementary registration-time check, `ValidateURL()` (`internal/webhook/validate.go:62`), rejects webhook URLs that resolve to reserved IPs up front, and the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) can disable the guard for self-hosted local-network deployments.

In the requested format:
- delivery function — `Post()` / `safeClient.Do()` in `internal/webhook/webhook.go`
- protection mechanism — `safeDialContext()` + `isReservedIP()`/`reservedCIDRs` (with `ValidateURL()` at registration) in `internal/webhook/webhook.go` and `internal/webhook/validate.go`
