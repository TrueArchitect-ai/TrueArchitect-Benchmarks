**computation site; triggers; extracted properties**

- **Computation site:** `server/runner/memopayload/runner.go:74` — `RebuildMemoPayload()` calls `markdownService.ExtractAll(memo.Content)`, whose single-pass AST walk lives in `internal/markdown/markdown.go:356` (`ExtractAll`; the property logic also exists standalone as `ExtractProperties` at `internal/markdown/markdown.go:193`). The result is stored on the memo as `memo.Payload.Tags` and `memo.Payload.Property` (`MemoPayload.Property`, defined in `proto/store/memo.proto:15`, commented "The calculated properties from the memo content").

- **Triggers:**
  1. **Memo creation** — `CreateMemo` at `server/router/api/v1/memo_service.go:108`.
  2. **Memo update when the `content` field is in the update mask** — `UpdateMemo` at `server/router/api/v1/memo_service.go:447` (other field updates like visibility don't recompute).
  3. **Bulk rebuild of all memos** — `Runner.RunOnce` at `server/runner/memopayload/runner.go:27`, which batches through every memo and rewrites payloads. (Note: this runner exists but isn't wired into `server/server.go`'s `startBackgroundRunners` — only the s3presign runner runs at startup — so it's a maintenance/rebuild entry point rather than a scheduled job.)

- **Extracted properties:** from a single goldmark parse:
  - `tags` — from memo tag nodes
  - `property.title` — text of the first H1 heading if it's the document's first block
  - `property.has_link` — any link node
  - `property.has_code` — code block, fenced code block, or code span
  - `property.has_task_list` — any task checkbox
  - `property.has_incomplete_tasks` — any unchecked task checkbox
  - (`ExtractAll` also collects `mentions` from mention nodes, though those aren't stored in `Property`)

These payload fields are what memo lists/previews and filters use without re-parsing content.
