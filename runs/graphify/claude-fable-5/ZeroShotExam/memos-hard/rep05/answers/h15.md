Memo visibility is enforced independently at these server surfaces (all confirmed by reading the code):

1. gRPC MemoService read access (`checkMemoReadAccess`, used by GetMemo etc.; non-public requires auth, private requires creator) — `server/router/api/v1/memo_service.go:39-66`
2. gRPC MemoService list filtering (`ListMemos` constrains `VisibilityList`/filters by current user: anonymous → PUBLIC only; other users' memos → PUBLIC/PROTECTED) — `server/router/api/v1/memo_service.go:218-226`
3. HTTP file server for attachment blobs (`checkAttachmentPermission`: public + anonymous-allowed served; private only to creator/admin or share token) — `server/router/fileserver/fileserver.go:650-699`
4. SSE realtime event delivery (`SSEClient.canReceive` filters events: private memo events only to creator or admin) — `server/router/api/v1/sse_hub.go:134-144` (visibility attached to events in `server/router/api/v1/sse_event_helpers.go`)
5. gRPC attachment metadata access (`checkAttachmentAccess` resolves the owning memo and applies the same private/creator/superuser rule) — `server/router/api/v1/attachment_service.go:422-455`
6. gRPC memo-attachment listing (`ListMemoAttachments` re-checks memo visibility before listing) — `server/router/api/v1/memo_attachment_service.go:200-225`
7. Reaction service (ListMemoReactions/UpsertMemoReaction check the memo's visibility before exposing reactions) — `server/router/api/v1/reaction_service.go:29-41, 82-85`
8. Comment creation (private memo → only creator/superuser may comment) — `server/router/api/v1/memo_service_comments.go:41-43`
9. RSS feeds (queries are hard-restricted to `store.Public` memos) — `server/router/rss/rss.go:90, 141`
10. Frontend sitemap/OG rendering (only `store.Public` memos listed) — `server/router/frontend/frontend.go:150`

The three core, structurally distinct surfaces are the gRPC API layer (`memo_service.go` and the attachment/reaction/comment services that call the same pattern), the HTTP file server (`fileserver.go`), and the SSE hub (`sse_hub.go`) — with RSS/frontend as additional read-only surfaces that enforce visibility by restricting queries to public memos.
