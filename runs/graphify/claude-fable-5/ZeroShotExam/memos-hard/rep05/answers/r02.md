**The premise is incorrect — this repository has no per-user API rate-limiting middleware.** There is nothing to register and no request limits to report.

I checked both the graphify knowledge graph of the repo and the source directly:

- The API middleware/interceptor chain is registered in `server/router/api/v1/v1.go:133-137`, and it consists only of `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, and `NewAuthInterceptor()` — no rate limiter. The gRPC-Gateway mux (around `server/router/api/v1/v1.go:95`) likewise only wires auth middleware.
- The only other middleware in the codebase is for the internal job scheduler (`internal/scheduler/middleware.go`), which provides `Recovery()` and `Logging()` — again, no rate limiting.
- A repo-wide search for `rate limit` / `ratelimit` / `throttle` / `limiter` finds only a documentation comment in `internal/email/doc.go:86` suggesting "Rate limit email sending to prevent abuse" as a future consideration — it is not implemented.

The closest thing to a request restriction is a request **size** limit, not a rate limit: `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`, which caps request body size, and it applies per-request, not per-user.
