The server starts exactly **one** background runner:

- **`s3presign` runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners()` at `server/server.go:153-174` (called from `Server.Start()` at `server/server.go:129`). Scheduling: an immediate `RunOnce(ctx)` at startup, then a plain `time.Ticker` firing every **12 hours** (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:26-41`), stopped via a per-runner `context.CancelFunc` and tracked with a `sync.WaitGroup` for graceful shutdown.

Not a background runner, for clarity:

- **`memopayload` "Runner"** (`server/runner/memopayload/runner.go`) — despite living under `server/runner/` and having a `RunOnce` method, it is never instantiated or started by the server. Only its standalone helper `memopayload.RebuildMemoPayload()` is called synchronously inside API request handlers (`server/router/api/v1/memo_service.go:108,447`). Nothing schedules it.

Unused scheduling infrastructure:

- **`internal/scheduler`** — a complete cron-style job scheduler (a `Scheduler` with `Start()`/`Stop()`, `Job` type, middleware, and a cron-expression parser in `internal/scheduler/scheduler.go`, `job.go`, `middleware.go`, `parser.go`, with tests and a README). It is **not imported anywhere outside its own package** — the server never uses it. The one active runner (`s3presign`) uses a raw `time.Ticker` instead, so this cron infrastructure is entirely dormant.
