When the API deletes a memo (`DeleteMemo` in `server/router/api/v1/memo_service.go` calls `s.Store.DeleteMemo`), the store layer at `store/memo.go:140-158` cleans up two kinds of related records before deleting the memo row itself:

- **Memo relation records** (`memo_relation`) — deleted twice, covering both directions: rows where the memo is the source (`MemoID`) and rows where it is the target (`RelatedMemoID`), via `s.driver.DeleteMemoRelation` (`store/memo.go:142-147`).
- **Attachments linked to the memo** — listed with `s.ListAttachments(&FindAttachment{MemoID: ...})` and each removed with `s.DeleteAttachment` (`store/memo.go:149-157`).

Only after those does it call `s.driver.DeleteMemo`, which is a plain `DELETE FROM memo` at the driver level (e.g. `store/db/sqlite/memo.go:237-248`) with no additional cascading cleanup.
