`web/src/connect.ts`; short-lived JWT access tokens (attached as the `Authorization` bearer header, held in memory via `web/src/auth-state.ts`) plus refresh tokens (an HttpOnly cookie used to obtain new access tokens); `server/auth`.

Details: the frontend `authInterceptor` in `web/src/connect.ts` (defined around line 156, registered on the Connect transport at line 188) attaches the current access token to each RPC via `getRequestToken()`, proactively refreshes it when near expiry, and reactively calls `refreshAccessToken()` on `Unauthenticated` (401) responses by hitting the auth service's `refreshToken` RPC through a separate interceptor-free transport (to avoid recursion). Token state — including cross-tab sharing over a BroadcastChannel — lives in `web/src/auth-state.ts`.

On the backend, the Connect `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go:205` reads the `Authorization` header and delegates to an `Authorizer`/`Authenticator` backed by the `server/auth` package (`server/auth/token.go`, `server/auth/authenticator.go`), which parses and validates the JWT access tokens (`ParseAccessTokenV2`), refresh tokens (`ParseRefreshToken`, checked against the database for revocation/expiry, read from the refresh-token cookie), and also personal access tokens.
