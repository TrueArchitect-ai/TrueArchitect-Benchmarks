**Engine:** Google CEL (Common Expression Language), via `github.com/google/cel-go` — the parsing/compilation lives in the repo's own filter package at `internal/filter/` (`engine.go`, `parser.go`, `render.go`, `schema.go`).

**Mechanism:** The ListMemos handler (`server/router/api/v1/memo_service.go`) passes the filter string into `store.FindMemo.Filters`; each store driver calls `filter.DefaultEngine()` and `filter.AppendConditions(...)` (`internal/filter/helpers.go:9`), where `Engine.Compile` (`internal/filter/engine.go:48`) compiles the string in a CEL environment and `parser.go` walks the CEL AST into a dialect-agnostic `Condition` IR tree; the renderer (`internal/filter/render.go`) then turns that tree into a parameterized SQL `Statement` for a given `DialectName` (`sqlite` / `mysql` / `postgres`, defined in `internal/filter/schema.go:11-16`), using per-dialect expression templates in the schema (e.g. `'users/' || %s` for SQLite vs `CONCAT('users/', %s)` for MySQL) plus dialect-specific helpers like `jsonExtractExpr`/`placeholder`. Each driver picks its dialect at the call site: `store/db/sqlite/memo.go:61`, `store/db/mysql/memo.go:69`, `store/db/postgres/memo.go:58`.
