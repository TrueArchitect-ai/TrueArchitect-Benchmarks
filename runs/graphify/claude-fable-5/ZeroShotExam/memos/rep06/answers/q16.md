When the API handler (`server/router/api/v1/memo_service.go:518`) calls `Store.DeleteMemo`, the store layer (`store/memo.go:140-158`) deletes these records before calling `s.driver.DeleteMemo` on the memo row itself:

- **Memo relation records** where the memo is the source — `DeleteMemoRelation` with `MemoID` (`store/memo.go:142`)
- **Memo relation records** where the memo is the target — `DeleteMemoRelation` with `RelatedMemoID` (`store/memo.go:145`)
- **Attachments** linked to the memo — listed via `ListAttachments` and deleted one by one with `DeleteAttachment` (`store/memo.go:149-157`)

So in short: memo relations (in both directions) and linked attachments. (At the API layer, comment memos are also deleted first via the same `Store.DeleteMemo`, which recursively performs the same relation/attachment cleanup for each comment — `memo_service.go:567-580`.)
