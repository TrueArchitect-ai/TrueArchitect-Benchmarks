MemoService is served over both the **gRPC-Gateway (REST/HTTP JSON)** protocol and the **Connect RPC** protocol, from a single shared implementation (`APIV1Service`):

- **gRPC-Gateway (HTTP/JSON REST)** — `server/router/api/v1/v1.go` (`RegisterGateway`, which calls `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` at `server/router/api/v1/v1.go:108` and mounts the mux on `/api/v1/*` via Echo; the generated gateway code lives in `proto/gen/api/v1/memo_service.pb.gw.go`)
- **Connect RPC** — `server/router/api/v1/connect_handler.go` (`ConnectServiceHandler.RegisterConnectHandlers`, which wraps the service with `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` at `server/router/api/v1/connect_handler.go:40` and mounts it on an `http.ServeMux`)

The comment in `connect_handler.go` states the design explicitly: the wrapper "supports both native gRPC and Connect protocols" while keeping one source of truth for business logic.
