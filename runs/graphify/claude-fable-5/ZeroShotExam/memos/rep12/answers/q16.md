When `Store.DeleteMemo` runs (`store/memo.go:140-159`), it deletes these other record kinds before issuing the memo-row delete (`s.driver.DeleteMemo`, which just runs `DELETE FROM memo` — e.g. `store/db/sqlite/memo.go:237`):

- **Memo relation records where the memo is the source** — `driver.DeleteMemoRelation` with `MemoID` set (`store/memo.go:142`)
- **Memo relation records where the memo is the target** — `driver.DeleteMemoRelation` with `RelatedMemoID` set (`store/memo.go:145`)
- **Attachments linked to the memo** — it lists attachments with `FindAttachment{MemoID: ...}` and calls `DeleteAttachment` for each (`store/memo.go:149-157`)

So: memo relations (in both directions) and memo-linked attachments, in that order, then the memo row itself.
