The server starts exactly one background runner, and the cron scheduler package in the repo is dead code from the server's perspective.

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners()` at `server/server.go:153-174` (called from `Server.Start()` at `server/server.go:129`). It executes `RunOnce()` immediately at startup, then runs a continuous loop driven by a `time.NewTicker` with a fixed 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-30`). Shutdown is handled via a per-runner `context.CancelFunc` and a `sync.WaitGroup` (`server/server.go:176-201`).

That is the only runner: `startBackgroundRunners` contains no other goroutines.

Two clarifications on things that look like runners but aren't started by the server:

- **memopayload "runner"** (`server/runner/memopayload/runner.go`) — despite living under `server/runner/`, it is never started as a background worker. Only its synchronous helper `RebuildMemoPayload()` is called on-demand from the memo API handlers (`server/router/api/v1/memo_service.go:108, 447`); its `NewRunner`/`RunOnce` are not invoked by `Server`.

- **Unused scheduling infrastructure:** `internal/scheduler/` is a complete cron-style scheduler (`Scheduler` with `Start()`/`runJobWithSchedule()` in `internal/scheduler/scheduler.go`, cron parsing via `ParseCronExpression()` in `internal/scheduler/parser.go`, plus `job.go` and tests). A repo-wide grep shows no imports of `internal/scheduler` outside its own package and tests — the server never instantiates it. The only scheduling actually in use is the plain 12-hour `time.Ticker` in the s3presign runner.
