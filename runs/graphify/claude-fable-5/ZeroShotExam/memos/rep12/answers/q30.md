Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook` (`memo_service_webhooks.go:15`, called from `memo_service.go:157`)
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook` (`memo_service_webhooks.go:20`, called from `memo_update_helpers.go:67`)
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook` (`memo_service_webhooks.go:25`, called from `memo_service.go:562`)
- memo comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`, called from `memo_service_comments.go:119`)

Convergence for delivery: the created/updated/deleted trio all funnel through the private helper `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which — like `DispatchMemoCommentCreatedWebhook` — looks up the owner's webhooks and calls `webhook.PostAsync(payload)`. So the ultimate convergence point for all four is `PostAsync` in `internal/webhook/webhook.go:184`, which enqueues the payload onto a bounded 128-slot `asyncPostQueue` drained by 4 worker goroutines that perform the actual HTTP delivery via `Post` (`internal/webhook/webhook.go:120`), using an SSRF-guarded HTTP client and optional signing.
