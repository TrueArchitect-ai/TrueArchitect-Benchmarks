MemoService (the backend `APIV1Service` implementation) is exposed over two protocols, both HTTP-mounted — there is no native gRPC listener (`grpc.NewServer`/`RegisterMemoServiceServer` appears nowhere in the repo):

1. **Connect (ConnectRPC)** — `server/router/api/v1/connect_handler.go` (line 40: `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` inside `RegisterConnectHandlers`). The per-method wrapping that adapts the gRPC-style implementation to Connect's request/response types lives in `server/router/api/v1/connect_services.go` (the `// MemoService` section starting around line 304, e.g. `CreateMemo`, `ListMemos`).

2. **REST/JSON via gRPC-Gateway** — `server/router/api/v1/v1.go` (line 108: `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` on the `runtime.NewServeMux` gateway mux, served under `/api/v1/*`).

Both registrations wrap the same `APIV1Service` struct, so the business logic has a single source of truth — the `ConnectServiceHandler` doc comment in `connect_handler.go` states this pattern explicitly.
