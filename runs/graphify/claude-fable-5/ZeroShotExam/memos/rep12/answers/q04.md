**APIV1Service.SignIn — server/router/api/v1/auth_service.go** (defined at `server/router/api/v1/auth_service.go:51`)

This is the function that implements the SignIn RPC's business logic on the backend — it handles both password-based authentication and SSO (OAuth2 authorization code) sign-in, then returns user info and an access token.

Note there is also a thin Connect-RPC transport wrapper, `ConnectServiceHandler.SignIn` in `server/router/api/v1/connect_services.go:78`, but it simply unwraps the Connect request and delegates straight to `APIV1Service.SignIn`, so the actual handler is the one in `auth_service.go`.
