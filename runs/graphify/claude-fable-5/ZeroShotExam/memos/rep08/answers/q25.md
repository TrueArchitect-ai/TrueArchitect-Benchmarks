**Engine:** Google's CEL (Common Expression Language) via `github.com/google/cel-go`, with the custom filter engine living in `internal/filter/` (`engine.go`, `parser.go`, `render.go`, `schema.go`, `helpers.go`).

**Mechanism:** The `ListMemos` filter string is compiled by a CEL environment (`Engine.Compile` in `internal/filter/engine.go` uses `cel.NewEnv`/`env.Compile`) and the CEL AST is converted by the parser (`internal/filter/parser.go`, e.g. `buildCondition`, `buildComparisonCondition`) into a dialect-agnostic `Condition` tree; each store driver (e.g. `store/db/sqlite/memo.go:57-61`, similarly `store/db/mysql` and `store/db/postgres`) then calls `filter.DefaultEngine()` + `filter.AppendConditions(...)` with its `DialectName` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`, defined in `internal/filter/schema.go`), and the `renderer` in `internal/filter/render.go` walks the condition tree emitting dialect-specific SQL fragments and bound args, using per-dialect expression templates from the schema (e.g. `('users/' || %s)` for SQLite vs `CONCAT('users/', %s)` for MySQL) plus dialect-aware JSON helpers like `jsonExtractExpr`/`jsonArrayExpr`.
