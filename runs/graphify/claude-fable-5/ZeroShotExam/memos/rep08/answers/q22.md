**Answer:** `dispatchMemoRelatedWebhook` — `server/router/api/v1/memo_service_webhooks.go`; delivery package `internal/webhook` (`github.com/usememos/memos/internal/webhook`); signing via Standard Webhooks-style HMAC-SHA256.

Details, with citations:

- **Dispatcher:** When a memo is created, the handler calls `DispatchMemoCreatedWebhook`, which delegates to `dispatchMemoRelatedWebhook` in `server/router/api/v1/memo_service_webhooks.go:48` with activity type `"memos.memo.created"` (`server/router/api/v1/memo_service_webhooks.go:14-17`). It resolves the memo creator, fetches their webhooks via `s.Store.GetUserWebhooks`, builds a `webhook.WebhookRequestPayload` per hook (attaching the hook's URL and signing secret), and fires each one asynchronously with `webhook.PostAsync(payload)` (`server/router/api/v1/memo_service_webhooks.go:61-72`).

- **Delivery package:** `internal/webhook` (`internal/webhook/webhook.go`) performs the actual HTTP POST of the JSON payload to the webhook URL.

- **Signing mechanism:** Standard Webhooks-format HMAC-SHA256. If a signing secret is configured (secrets use the `whsec_` base64 prefix, generated by `GenerateSigningSecret`), the package computes `hmac.New(sha256.New, key)` over the message, base64-encodes it, and sets the `webhook-signature: v1,<sig>` header along with `webhook-id` and `webhook-timestamp` (`internal/webhook/webhook.go:88-149`); unsigned requests omit these headers entirely, as verified in `internal/webhook/webhook_test.go`.
