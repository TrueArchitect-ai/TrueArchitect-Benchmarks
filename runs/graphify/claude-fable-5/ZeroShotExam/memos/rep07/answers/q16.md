When the API's `DeleteMemo` handler (`server/router/api/v1/memo_service.go:518`) calls into the store, `Store.DeleteMemo` (`store/memo.go:140-159`) deletes these other kinds of records before deleting the memo row itself:

- **Memo relation records** — `memo_relation` rows where the memo is the source (`MemoID`, `store/memo.go:142`) and where it is the target (`RelatedMemoID`, `store/memo.go:145`), via `driver.DeleteMemoRelation`.
- **Attachment records** — attachments linked to the memo are listed (`store/memo.go:149`) and each is deleted with `Store.DeleteAttachment` (`store/memo.go:153-156`).

Only after both cleanups does it call `s.driver.DeleteMemo` to remove the memo row (`store/memo.go:158`). (At the API layer, comment memos are also deleted first via recursive `Store.DeleteMemo` calls — `memo_service.go:567-574` — but within the store layer itself, the record kinds cleaned up are memo relations and attachments.)
