The server (`server/server.go`) starts exactly **one** background runner, in `startBackgroundRunners()` at `server/server.go:153`:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started with an immediate `RunOnce(ctx)` at server startup (`server/server.go:163`), then run continuously in a goroutine. Its scheduling is a plain `time.NewTicker(runnerInterval)` with `runnerInterval = 12 hours` (`server/runner/s3presign/runner.go:27-36`); each tick re-checks S3 objects and re-presigns URLs older than ~4 days. Shutdown is driven by a per-runner `context.CancelFunc` plus a `sync.WaitGroup` (`stopBackgroundRunners`/`waitBackgroundRunners`, `server/server.go:176-200`).

Not a background runner despite living under `server/runner/`:

- **memopayload runner** (`server/runner/memopayload/`) — its `Runner`/`RunOnce` (full rebuild of all memo payloads) is never instantiated or scheduled by the server. Only the standalone helper `memopayload.RebuildMemoPayload(...)` is called synchronously from the memo API handler (`server/router/api/v1/memo_service.go:108,447`) during memo create/update. No ticker, no goroutine.

**Unused scheduling infrastructure:** the entire cron scheduler package `internal/scheduler/` (`scheduler.go` with `New()`/`Start()`/`runJobWithSchedule()`, `parser.go` with `ParseCronExpression()`, `job.go`) is imported by **nothing outside its own tests** (`internal/scheduler/integration_test.go`, `example_test.go`). The server never uses it — the only runner it actually starts is scheduled by a raw `time.Ticker`, not by this cron infrastructure.
