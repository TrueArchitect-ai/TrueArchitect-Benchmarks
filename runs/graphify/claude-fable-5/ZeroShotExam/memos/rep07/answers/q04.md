This is the function that implements the SignIn RPC's business logic on the backend. Note there is also a thin transport wrapper, `ConnectServiceHandler.SignIn` at `server/router/api/v1/connect_services.go:78`, which the Connect RPC framework invokes first — but it only adapts the request/response envelope and delegates directly to `APIV1Service.SignIn`, which is the actual handler. (The generated stub `_UserService_..._Handler` functions in `proto/gen/api/v1/` are protoc-generated plumbing, not the implementation.)
