**Engine:** CEL (Common Expression Language, via `github.com/google/cel-go`), housed in the `internal/filter` package — `internal/filter/engine.go`, `parser.go`, `render.go`, `schema.go`.

**Mechanism:** The `ListMemos` handler (`server/router/api/v1/memo_service.go:211-223`) validates the filter and passes it into the store's `FindMemo.Filters`; each driver (`store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo.go:65-69`, `store/db/postgres/memo.go:54-58`) calls `filter.DefaultEngine()` and `filter.AppendConditions(...)` with its own `DialectName`. The engine compiles the CEL expression against a schema-defined `cel.Env` (`engine.go`), the parser walks the CEL AST into a dialect-agnostic condition tree (`parser.go`'s `buildCondition` and friends), and the renderer (`render.go`) turns that tree into parameterized SQL, switching on `DialectSQLite`/`DialectMySQL`/`DialectPostgres` (`schema.go:11-16`) for dialect-specific fragments (e.g. JSON extraction, string concat, timestamp accessors), with `AppendConditions` (`internal/filter/helpers.go:9`) appending the resulting WHERE fragments and args to the query.

One sentence: CEL expressions are compiled once into a dialect-agnostic condition tree, then rendered per-dialect into parameterized SQL WHERE clauses at query-build time in each store driver.
