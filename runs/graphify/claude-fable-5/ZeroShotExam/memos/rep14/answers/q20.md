**Mechanism: Server-Sent Events (SSE); hub: `server/router/api/v1/sse_hub.go`; handlers: CreateMemo, UpdateMemo, DeleteMemo, CreateMemoComment, SetMemoAttachments, SetMemoRelations (plus UpsertMemoReaction / DeleteMemoReaction for memo reactions).**

Details:

- **Mechanism** — Server-Sent Events. The `SSEHub` (`server/router/api/v1/sse_hub.go:56`) manages client connections and broadcasts `SSEEvent`s via `Broadcast()` (`sse_hub.go:115`), with per-client buffered channels so slow clients drop events instead of blocking. The HTTP endpoint lives in `server/router/api/v1/sse_handler.go`, with event-building helpers in `sse_event_helpers.go`. On the browser side, `web/src/hooks/useLiveMemoRefresh.ts` consumes the stream.

- **Memo handlers that broadcast through `s.SSEHub.Broadcast(...)`:**
  - `CreateMemo` — `server/router/api/v1/memo_service.go:163` (skipped when suppressed via the `suppressSSEKey` context used by comment creation)
  - `UpdateMemo` — indirectly via `dispatchMemoUpdatedSideEffects` (`memo_service.go:513` → `server/router/api/v1/memo_update_helpers.go:71`)
  - `DeleteMemo` — `memo_service.go:585`
  - `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:126` (broadcasts `memo.comment.created` for the parent memo)
  - `SetMemoAttachments` — via `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_attachment_service.go:48`)
  - `SetMemoRelations` — via `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_relation_service.go:48`)
  - Memo reactions also broadcast: `UpsertMemoReaction` (`server/router/api/v1/reaction_service.go:106`) and `DeleteMemoReaction` (`reaction_service.go:161`)
