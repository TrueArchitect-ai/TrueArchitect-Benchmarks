The server starts exactly one background runner. From `server/server.go:153` (`startBackgroundRunners`, called from `Server.Start` at `server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — the only runner started. It executes `RunOnce` immediately at startup (`server/server.go:163`), then runs continuously in a goroutine (`server/server.go:167-171`) driven by a plain **`time.Ticker` with a hard-coded 12-hour interval** (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27`). It refreshes expiring S3 presigned URLs for attachments, and is cancelled via a per-runner `context.CancelFunc` on shutdown.

Not started as background workers:

- **memopayload runner** (`server/runner/memopayload/runner.go`) — has a `NewRunner`/`RunOnce` runner shape, but the server never starts it. Only its `RebuildMemoPayload` helper is called synchronously from the API layer (`server/router/api/v1/memo_service.go:108` and `:447`) when memos are created/updated. There is no scheduling for it.

**Unused scheduling infrastructure:** the `internal/scheduler` package (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`) is a complete cron-style scheduler — `ParseCronExpression`, `Scheduler.Start`, `runJobWithSchedule`, job validation, middleware, tests, and a README — yet a repo-wide grep shows it is imported **nowhere outside its own package**. Neither `server/server.go` nor any runner uses it; the one scheduled worker (s3presign) uses a raw `time.Ticker` instead. The cron scheduler is dead infrastructure as far as the server is concerned.
