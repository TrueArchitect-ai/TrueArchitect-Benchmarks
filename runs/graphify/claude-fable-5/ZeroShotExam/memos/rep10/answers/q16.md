When the API's `DeleteMemo` handler (`server/router/api/v1/memo_service.go:580`) calls into the store, `Store.DeleteMemo` in `store/memo.go:140` deletes these record kinds before deleting the memo row itself:

- **Memo relation records** where the memo is the source (`DeleteMemoRelation{MemoID: ...}`, `store/memo.go:142`)
- **Memo relation records** where the memo is the target/related memo (`DeleteMemoRelation{RelatedMemoID: ...}`, `store/memo.go:145`)
- **Attachments** linked to the memo — it lists them with `ListAttachments` and deletes each via `DeleteAttachment` (`store/memo.go:149-157`)

Only after that does it call `s.driver.DeleteMemo` to remove the memo row (`store/memo.go:158`). (For completeness: reaction records and comment memos are also cleaned up on API delete, but that happens in the API layer of `memo_service.go`, not inside the store's `DeleteMemo`.)
