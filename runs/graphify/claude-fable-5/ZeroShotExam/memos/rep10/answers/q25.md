**Engine:** CEL (Common Expression Language), via `github.com/google/cel-go`. **Path:** the engine lives in `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go`) passes the filter strings into the store's `FindMemo` (`store/memo.go`); the `filter.Engine` (`internal/filter/engine.go:24`) compiles each string in a CEL environment built from the memo `Schema` (`internal/filter/schema.go`), then `parser.go` walks the parsed CEL AST into a **dialect-agnostic condition tree** (the IR in `internal/filter/ir.go`), and `render.go` renders that tree into dialect-specific SQL + args based on a `DialectName` in `RenderOptions` — e.g. `ILIKE $1`/`~` for Postgres vs `LIKE ?`/`REGEXP ?` for MySQL/SQLite. Each store driver invokes this with its own dialect via `filter.DefaultEngine()` + `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args)` (`store/db/sqlite/memo.go:57-61`, with `DialectMySQL`/`DialectPostgres` equivalents in `store/db/mysql/memo.go` and `store/db/postgres/memo.go`; the helper is `internal/filter/helpers.go:9`).
