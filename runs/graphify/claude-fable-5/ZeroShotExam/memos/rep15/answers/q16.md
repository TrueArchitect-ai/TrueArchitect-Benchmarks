When `Store.DeleteMemo` runs (called from the API's memo-delete handler), it removes the following before deleting the memo row itself (`store/memo.go:140-159`):

- **Memo relation records** — two `DeleteMemoRelation` calls: one where the memo is the source (`MemoID`) and one where it is the target (`RelatedMemoID`) (`store/memo.go:142-147`)
- **Attachments linked to the memo** — it lists attachments with `FindAttachment{MemoID: ...}` and deletes each via `DeleteAttachment` (`store/memo.go:149-157`)

Only after these does it call `s.driver.DeleteMemo`, which issues the plain `DELETE FROM memo` for the row itself (e.g. `store/db/sqlite/memo.go:237`); the driver-level delete has no additional cascades.
