The server starts exactly one background runner, and the standalone cron scheduler package in the repo is never wired into it.

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:153-174`, called from `Server.Start` at `server/server.go:129`). Scheduling: an immediate `RunOnce(ctx)` at startup, then a continuous `Run` loop driven by a `time.NewTicker(runnerInterval)` where `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27-30`). It is shut down via a per-runner `context.CancelFunc` and a `sync.WaitGroup` (`server/server.go:176-201`).

That is the only worker: `startBackgroundRunners` contains no other goroutines.

**Unused scheduling infrastructure:** the cron scheduler package `internal/scheduler/` (`Scheduler`, `Scheduler.Start`, `runJobWithSchedule` in `internal/scheduler/scheduler.go`; `ParseCronExpression`/`Schedule` in `internal/scheduler/parser.go`) is NOT used by the server — or by any production code at all. The only files importing `usememos/memos/internal/scheduler` are its own tests (`internal/scheduler/integration_test.go`, `internal/scheduler/example_test.go`). The s3presign runner uses a plain `time.Ticker`, not this cron infrastructure.

Note also that `server/runner/memopayload/runner.go` lives under the `runner/` directory but is not a started background worker — it's called synchronously as a library (`memopayload.RebuildMemoPayload`) from `server/router/api/v1/memo_service.go:108` and `:447`.
