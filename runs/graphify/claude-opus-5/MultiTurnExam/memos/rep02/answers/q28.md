**Runners the server actually starts:**

```
s3presign.Runner — RunOnce at startup, then a 12-hour time.Ticker loop
webhook async dispatch pool — 4 goroutines draining a 128-slot channel, fed on demand by webhook.PostAsync
SSE heartbeat — a 30-second per-connection ticker, one per open SSE client
PAT last-used recorder — fire-and-forget goroutine per authenticated PAT request
```

Details:

- **`s3presign.Runner`** — the only entry in `Server.startBackgroundRunners` (`server/server.go:153-174`): `RunOnce(ctx)` immediately, then `go s3presignRunner.Run(s3Context)`. `Run` (`server/runner/s3presign/runner.go:29-41`) is a `time.NewTicker(runnerInterval)` loop with `runnerInterval = time.Hour * 12` (line 27), refreshing presigned URLs for S3-backed attachments in batches. It has its own cancel func for graceful shutdown, tracked by `backgroundRunnerWG`.
- **Webhook dispatch pool** — started by a package `init()` in `internal/webhook/webhook.go:42-54`: 4 worker goroutines ranging over `asyncPostQueue` (buffered 128, line 39). Trigger is event-driven — `PostAsync` enqueues on memo create/update/delete/comment; a full queue drops the delivery with a warning.
- **SSE heartbeat** — `time.NewTicker(sseHeartbeatInterval)` at `server/router/api/v1/sse_handler.go:64`, 30s (`:17`), per connected client rather than a singleton runner.
- **PAT last-used** — `Authenticator.recordPATUsage` spawns a goroutine per PAT-authenticated request (`server/auth/authenticator.go:180`).

**Unused scheduling infrastructure:** `internal/scheduler` — a full GitHub-Actions-style cron scheduler (`scheduler.go` with `New`/`Register`/`Start`/`Stop`, `job.go`, `middleware.go` with `Recovery()`/`Logging()`, `doc.go`) — **is not wired into the server at all.** Grepping for `scheduler.` outside the package itself returns only its own doc-comment examples; no production code calls `scheduler.New()` or registers a job.

Also unused as a *runner*: `server/runner/memopayload` is packaged under `server/runner/` but is not a background loop — its `RebuildMemoPayload` is called synchronously from the memo handlers (`server/router/api/v1/memo_service.go:108` and `:447`).
