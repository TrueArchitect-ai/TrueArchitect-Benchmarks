**`web/src/connect.ts` (`authInterceptor`, line 156); short-lived JWT access token (Bearer) + HttpOnly refresh-token cookie — with backend also accepting Personal Access Tokens; `server/auth`**

**Interceptor** — `authInterceptor` at `web/src/connect.ts:156-178` is attached to the shared Connect transport (`:184-189`). Per request it:
1. Fetches a token via `getRequestToken()` (`:124-150`) and sets `Authorization: Bearer <token>`.
2. Pre-emptively refreshes when the access token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry — important for public endpoints like `ListMemos`, where an expired token would silently return guest-scoped data.
3. On a `Code.Unauthenticated` response, refreshes once, retries with an `X-Retry` marker to prevent loops, and calls `redirectOnAuthFailure()` if the refresh fails.

**Tokens** — managed in `web/src/auth-state.ts`:
- **Access token**: short-lived JWT, held in memory and mirrored to `localStorage` (`memos_access_token` / `memos_token_expires_at`), shared across tabs over a `BroadcastChannel` so only one tab refreshes.
- **Refresh token**: HttpOnly cookie, never touched by JS — it rides along because the transport uses `fetch` with `credentials: "include"` (`web/src/connect.ts:57-62`). Refresh goes through a *separate* interceptor-free transport and `refreshAuthClient` (`:65-72`) to avoid recursion, deduplicated by `tokenRefreshManager` (`:30-51`).

**Backend validation** — `server/auth/`:
- `Authenticator.AuthenticateByAccessTokenV2` (`authenticator.go:41`) → `ParseAccessTokenV2` with the instance secret.
- `Authenticator.AuthenticateByRefreshToken` (`:61`) → parses, then checks the token ID against the DB (`GetUserRefreshTokenByID`) so tokens can be revoked/rotated.
- `Authenticator.AuthenticateByPAT` (`:102`) → prefix check, SHA-hash lookup via `GetUserByPATHash`, expiry check; usage timestamp recorded asynchronously (`:179`).
- `resolveBearer` (`:149`) dispatches on the `PersonalAccessTokenPrefix`; JWT parsing/hashing helpers live in `server/auth/token.go`, header extraction in `extract.go`, context plumbing in `context.go`.

It's applied on both serving paths: the Connect interceptors (`server/router/api/v1/connect_interceptors.go`) and the gateway middleware `gatewayAuthMiddleware` in `server/router/api/v1/v1.go`, plus the SSE endpoint, which authenticates the `Authorization` header directly (`server/router/api/v1/sse_handler.go:34-40`).
