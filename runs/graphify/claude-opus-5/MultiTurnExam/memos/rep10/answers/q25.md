**CEL (Google Common Expression Language, `github.com/google/cel-go`) + `internal/filter`; mechanism:** the CEL string is compiled once into a dialect-agnostic condition tree (IR), which is then rendered into a parameterized SQL `WHERE` fragment per dialect and appended to the query with its bind args.

**Engine.** `filter.Engine` at `internal/filter/engine.go:14` wraps a `cel.Env` built from a `Schema` (`internal/filter/schema.go`) that declares the allowed identifiers and functions. `Engine.Compile` (`engine.go:47`) runs `env.Compile`, converts the AST, and produces a `Program` holding a `Condition` tree (`internal/filter/ir.go`, with parsing in `parser.go`). `go.mod:13` pins `cel-go v0.28.1`. Docs for the grammar are in `internal/filter/README.md`.

**To SQL.** `internal/filter/render.go` walks the IR and emits dialect-specific SQL, switching on `DialectSQLite` / `DialectPostgres` / `DialectMySQL` — e.g. date extraction becomes `strftime(...)` on SQLite vs. `EXTRACT`/`DATE_FORMAT`-style calls on Postgres/MySQL (`render.go:231-238`), and `PlaceholderOffset` handles `?` vs `$N` numbering.

**Wiring.** Each dialect driver calls `filter.DefaultEngine()` and then `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect*, &where, &args)` (`internal/filter/helpers.go:9`), which appends `(<sql>)` to the WHERE list and its args to the arg list:
- `store/db/sqlite/memo.go:57,61`
- `store/db/postgres/memo.go:58`
- `store/db/mysql/memo.go:69`

The same path is used for attachments (`store/db/*/attachment.go`) and memo relations. On the API side, `server/router/api/v1/memo_service_filter.go` handles the `ListMemos` filter argument before it reaches the store; the same CEL grammar backs saved shortcuts (`Shortcut.filter`, `proto/api/v1/shortcut_service.proto`).
