**web/src/connect.ts; JWT access token + refresh-token cookie (+ PAT for programmatic clients); server/auth**

- **Interceptor:** `authInterceptor` in `web/src/connect.ts:156-178`, installed on the shared Connect transport (line 188). It attaches `Authorization: Bearer <token>` and, on a `Code.Unauthenticated` response, refreshes once and replays the request with an `X-Retry` marker, redirecting to login if the refresh fails. Token state (localStorage + cross-tab `BroadcastChannel` sync, expiry helpers) lives in `web/src/auth-state.ts`; the dedicated refresh path uses a separate interceptor-free transport to avoid recursion (`web/src/connect.ts:65-91`), with concurrent refreshes deduplicated by `tokenRefreshManager`.

- **Token kinds:**
  - Short-lived **JWT access token** — 15 min, audience `user.access-token`, sent in the `Authorization` header (`server/auth/token.go:37-40`).
  - Long-lived **refresh token** — 30 days, audience `user.refresh-token`, delivered as the `memos_refresh` HTTP-only cookie (`credentials: "include"`, `web/src/connect.ts:57-62`; constants at `server/auth/token.go:43-49`).
  - **Personal Access Token** — prefix `memos_pat_`, for API/programmatic use rather than the browser (`server/auth/token.go:51-52`).

- **Backend validation:** `server/auth` — `Authenticator.AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`, `resolveBearer`, `Authenticate` (`server/auth/authenticator.go:41,61,102,149,213`), with header/cookie parsing in `server/auth/extract.go` and context plumbing in `server/auth/context.go`. It is invoked per request by the Connect `NewAuthInterceptor` (`server/router/api/v1/connect_interceptors.go`, wired at `server/router/api/v1/v1.go:137`) and by the gRPC-Gateway middleware (`server/router/api/v1/v1.go:75-89`), with per-method access rules in `server/router/api/v1/acl_config.go` / `authz.go`.
