**Engine: Google CEL (`cel-go`), wrapped by the in-repo filter package at `internal/filter/` — `engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`**

**Mechanism:** The CEL environment declared in `internal/filter/schema.go` (variables like `content`, `creator_id`, `tag`, `tags`, `pinned`, `visibility`, `created_ts`, `updated_ts` — `schema.go:232-241`) compiles the filter string into a CEL AST, `buildCondition` lowers that AST into a dialect-agnostic condition tree (`engine.go:47-69`, `parser.go`/`ir.go`), and each dialect driver then renders that tree into a parameterized SQL `WHERE` fragment plus args by calling `engine.CompileToStatement(ctx, filter, filter.RenderOptions{Dialect: ...})` — `store/db/sqlite/memo.go:57`, `store/db/postgres/memo.go:54`, and the MySQL equivalent — with the per-dialect SQL differences (e.g. `strftime(...)` vs `EXTRACT(...)` vs MySQL date functions, string length, JSON access) handled in `internal/filter/render.go` (`:231-238`, `:297-298`, `:365-464`).

The engine is a process-wide singleton via `filter.DefaultEngine()` (`engine.go:107`), with a separate `DefaultAttachmentEngine()` for attachment filters; `APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:178`) simply passes the raw filter string down as `store.FindMemo`'s filter field. Docs for the syntax live in `internal/filter/README.md`.
