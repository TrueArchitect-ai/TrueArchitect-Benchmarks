**Runners the server actually starts** (all in `Server.startBackgroundRunners`, `server/server.go:153-174`):

```
s3presign.Runner — RunOnce at startup, then a 12h time.Ticker loop in a goroutine
store/cache janitor (per-cache cleanupLoop) — 5-minute time.Ticker, started when the Store's caches are constructed
SSE heartbeat — per-connection time.Ticker, one goroutine per connected browser
```

Details:
- **s3presign**: `s3presignRunner.RunOnce(ctx)` fires synchronously at boot (`server/server.go:163`), then `Run(s3Context)` loops on `time.NewTicker(runnerInterval)` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27-40`). It re-presigns S3 attachment URLs via `CheckAndPresign` (`:47`). Shutdown is by context cancel + WaitGroup (`server/server.go:176-199`).
- **cache janitor**: `Cache.cleanupLoop` on `config.CleanupInterval` (`store/cache/cache.go:199-213`), defaulted to 5 minutes at `store/store.go:42` and `store/cache/cache.go:60`; stopped via `Cache.Close` (`:186`).
- **SSE heartbeat**: `time.NewTicker(sseHeartbeatInterval)` per connection in `handleSSE` (`server/router/api/v1/sse_handler.go:64`) — request-scoped, not a server-wide runner.

**Unused infrastructure note:** `server/runner/memopayload/` sits under the runner tree but is **not** started as a background runner — it has no `Run`/ticker at all. Its `RebuildMemoPayload` is called inline from the API handlers on memo create and update (`server/router/api/v1/memo_service.go:108`, `:447`). So the `runner` package name is misleading there; nothing schedules it.

Also worth noting: there is no cron library in the project (no `robfig/cron` or equivalent in `go.mod`) — all scheduling is plain `time.Ticker`. Webhook delivery is fire-and-forget goroutines via `webhook.PostAsync` (`internal/webhook/webhook.go`), not a scheduled worker or queue.
