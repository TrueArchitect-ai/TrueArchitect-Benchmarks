**Google CEL (Common Expression Language) via cel-go — internal/filter/ (engine at `internal/filter/engine.go:24,48`, `cel.NewEnv` at :25)**

**Mechanism:** each dialect's `ListMemos` calls `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect{SQLite,MySQL,Postgres}, &where, &args)`, which compiles the CEL expression to a parsed AST, lowers it into a dialect-independent condition-tree IR, and then renders that IR into a parameterized `WHERE` fragment plus bound args using per-dialect templates — so one expression yields different SQL per backend while values always travel as placeholders, never string-interpolated.

Supporting detail:

- **Package layout** (`internal/filter/`): `schema.go` declares `DialectName` and the three constants (:11-16) plus the CEL environment and per-field SQL templates; `parser.go`/`ir.go` build the condition tree; `render.go` emits SQL; `helpers.go:9` is the `AppendConditions` entry point; `engine.go:111` provides `DefaultEngine()` (memos) and `:119` `DefaultAttachmentEngine()`.
- **Call sites:** `store/db/sqlite/memo.go:57,61` and the corresponding lines in `store/db/mysql/memo.go` and `store/db/postgres/memo.go`.
- **Where dialects diverge** — string concat is `('users/' || %s)` on SQLite/Postgres but `CONCAT('users/', %s)` on MySQL (`schema.go:105-107`); timestamps use `UNIX_TIMESTAMP(%s)` on MySQL and pass through elsewhere (`:132-135`); JSON payload comparisons get a `::boolean` cast on Postgres (`render.go:402-405`). Placeholder style also differs per dialect (`render.go:231-237`), with `PlaceholderOffset` threading the running arg count so Postgres `$N` numbering stays correct when filters are appended to existing conditions.
- `server/router/api/v1/user_service_filter.go` uses cel-go directly for a separate, simpler user filter rather than going through this package.
