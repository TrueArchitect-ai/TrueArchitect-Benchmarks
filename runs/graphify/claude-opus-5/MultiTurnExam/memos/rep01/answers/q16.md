`Store.DeleteMemo` (`store/memo.go:140-159`) removes, in this order, before deleting the memo row:

1. **memo_relation rows where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (line 142)
2. **memo_relation rows where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (line 145)
3. **attachments linked to the memo** — listed via `FindAttachment{MemoID}` and deleted one by one (lines 149-157). Each `Store.DeleteAttachment` (`store/attachment.go:132-149`) also deletes the underlying **blob/file in storage** (local file or S3 object) via `DeleteAttachmentStorage` before removing the `attachment` row.
4. then `driver.DeleteMemo` deletes the **memo row** (line 158).

The API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518+`) adds one more layer above this: it first finds all **comment memos** (memo relations of type `MemoRelationComment` pointing at this memo) and calls `Store.DeleteMemo` on each (lines 568-577), so every comment's own relations and attachments are cleaned up too. It also dispatches the memo-deleted webhook beforehand.
