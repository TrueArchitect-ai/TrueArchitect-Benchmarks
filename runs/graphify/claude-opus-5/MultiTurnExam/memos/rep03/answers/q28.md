**Runners the server actually starts** (`Server.startBackgroundRunners`, `server/server.go:153`):

```
s3presign.Runner — 12-hour time.Ticker loop (plus one synchronous RunOnce at startup)
store/cache janitor goroutines (×3) — CleanupInterval time.Ticker, started implicitly by cache.New
SSE heartbeat — per-connection time.Ticker, started when a browser opens /api/v1/sse
```

Details:

- **`s3presign.Runner`** — constructed at `server/server.go:162`, run once synchronously (`:163`), then launched as a goroutine on its own cancellable context (`:166-171`). Its loop is `Runner.Run` at `server/runner/s3presign/runner.go:29`, driven by `time.NewTicker(runnerInterval)` where `runnerInterval = 12 * time.Hour` (`:27`). It refreshes expiring S3 presigned URLs (`CheckAndPresign`, `:47`). This is the only entry in `backgroundRunnerCancels`/`backgroundRunnerWG`, so it's the only runner with managed shutdown (`server/server.go:176-201`).
- **Cache janitors** — `cache.New` starts `go c.cleanupLoop()` at `store/cache/cache.go:83`; the loop tickers on `config.CleanupInterval` (`:200-201`). Three instances are created in `store/store.go:51-53` (instance settings, users, user settings), so three goroutines run for the life of the process. They're incidental to `NewStore` rather than registered as background runners.
- **SSE heartbeat** — `time.NewTicker(sseHeartbeatInterval)` at `server/router/api/v1/sse_handler.go:64`, one per live SSE connection, keeping the stream open. Event-driven rather than scheduled work.

**Unused scheduling infrastructure:** `server/runner/memopayload/runner.go` defines a full runner (`NewRunner` at `:19`, `RunOnce` at `:27`) that rebuilds memo payloads across all memos — and **nothing ever constructs or starts it**. `server/server.go` doesn't import the package at all. The only thing used from it is the standalone helper `RebuildMemoPayload` (`:74`), called inline from the API handlers at `server/router/api/v1/memo_service.go:108` (create) and `:447` (update). So payload rebuilds happen synchronously per-request; the batch runner is dead code.

There is no cron library in the project — no `robfig/cron` or equivalent; all periodic work is plain `time.Ticker`.
