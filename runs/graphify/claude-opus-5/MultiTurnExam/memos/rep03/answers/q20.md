**Mechanism:** Server-Sent Events (SSE) over HTTP — endpoint `GET /api/v1/sse`, registered by `RegisterSSERoutes` at `server/router/api/v1/sse_handler.go:25` and mounted on the CORS-enabled gateway group in `server/router/api/v1/v1.go:129`. Clients authenticate with a Bearer token (`sse_handler.go:34-37`).

**Hub:** `server/router/api/v1/sse_hub.go` — `type SSEHub` (:56), `NewSSEHub` (:63), `Subscribe` (:71), `Unsubscribe` (:89), `Close` (:99), `Broadcast` (:115). Event types and payload helpers are in `server/router/api/v1/sse_event_helpers.go`; the hub instance is created in `NewAPIV1Service` (`v1.go:58`).

**Memo handlers that broadcast:**

| Handler | Site | Event |
|---|---|---|
| `CreateMemo` | `memo_service.go:163` | `SSEEventMemoCreated` |
| `DeleteMemo` | `memo_service.go:585` | `SSEEventMemoDeleted` |
| `UpdateMemo` | `memo_service.go:513` → `memo_update_helpers.go:71` | `SSEEventMemoUpdated` |
| `SetMemoRelations` | `memo_relation_service.go:48` → same helper | `SSEEventMemoUpdated` |
| `SetMemoAttachments` | `memo_attachment_service.go:48` → same helper | `SSEEventMemoUpdated` |
| `CreateMemoComment` | `memo_service_comments.go:126` | `SSEEventMemoCommentCreated` |
| `UpsertMemoReaction` | `reaction_service.go:106` | `SSEEventReactionUpserted` |
| `DeleteMemoReaction` | `reaction_service.go:161` | `SSEEventReactionDeleted` |

The three update-shaped handlers share `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`) rather than broadcasting inline. One behavioral detail: `CreateMemo`'s broadcast is guarded by `!isSSESuppressed(ctx)` (`memo_service.go:162`) so that comment creation — which calls `CreateMemo` with a suppressing context — emits only the `MemoCommentCreated` event instead of a duplicate `MemoCreated`.
