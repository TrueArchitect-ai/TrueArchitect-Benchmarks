**CEL (Common Expression Language, via `cel-go`) — `internal/filter/`**

**Mechanism:** each dialect driver's `ListMemos` calls `filter.DefaultEngine()` and `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)`, which parses the CEL text against a memo-specific schema, normalizes it into a dialect-agnostic IR, then renders that IR into a SQL fragment plus placeholder args for the target dialect — appended to the query's `WHERE` clause.

The three-phase pipeline, documented in `internal/filter/README.md`:

1. **Parse** — `cel-go` parses the expression, validated against the memo environment declared in `internal/filter/schema.go`; only schema-declared fields are allowed. Conversion to IR is in `internal/filter/parser.go`.
2. **Normalize** — IR node definitions in `internal/filter/ir.go` — a dialect-agnostic condition tree enforcing operator/type rules.
3. **Render** — `internal/filter/render.go` walks the IR per `DialectSQLite` / `DialectMySQL` / `DialectPostgres`, handling `?` vs `$n` placeholders, JSON access on `memo.payload` (`json_extract` vs `->>`), `LIKE` vs `ILIKE`, and tag predicates (`LIKE` / `JSON_CONTAINS` / `@>`).

Entry point `filter.DefaultEngine()` is in `internal/filter/engine.go` (exposing `Compile` / `CompileToStatement`); the store-integration helper `AppendConditions` is at `internal/filter/helpers.go:9`. Call sites: `store/db/sqlite/memo.go:57,61` and the equivalents in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`. On the API side, filter handling for the RPC lives in `server/router/api/v1/memo_service_query.go`, and the `filter` field is documented on `ListMemosRequest` in `proto/api/v1/memo_service.proto`.
