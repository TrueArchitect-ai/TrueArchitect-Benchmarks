**Interceptor: `web/src/connect.ts` (`authInterceptor`, :156) — token state in `web/src/auth-state.ts`; Tokens: short-lived JWT access token (Bearer header, localStorage) + long-lived refresh token (httpOnly `memos_refresh` cookie); backend validator: `server/auth/`**

How it works:

- `authInterceptor` (`web/src/connect.ts:156-178`) is installed on the shared Connect transport (:188). On every request it resolves a token via `getRequestToken` (:124) and sets `Authorization: Bearer <token>` (:97). If the token is missing or within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` of expiry it refreshes preemptively (:140-147); on a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry` marker, and redirects to login if that fails (:164-176).
- The **access token** is stored in localStorage with its expiry (`web/src/auth-state.ts:52-96`). The **refresh token** is never touched by JS — all requests use `credentials: "include"` (`web/src/connect.ts:57-62`) so the httpOnly cookie rides along. Refresh goes through a dedicated interceptor-free transport and client (:65-72) to avoid recursion, and concurrent refreshes are de-duplicated by `tokenRefreshManager` (:30-51).
- **Backend: `server/auth/`** — `Authenticator.Authenticate` / `resolveBearer` (`server/auth/authenticator.go:213`, :149) validate the Bearer credential, which may be an access token (`AuthenticateByAccessTokenV2`, :41) or a **Personal Access Token** with the `memos_pat_` prefix (`AuthenticateByPAT`, :102) — a third token kind, used by API clients rather than the web UI. `AuthenticateByRefreshToken` (:61) handles cookie-based refresh. Constants and JWT generation live in `server/auth/token.go` (access 15 min :40, refresh 30 days :43, cookie `memos_refresh` :49), extraction helpers in `server/auth/extract.go`, context plumbing in `server/auth/context.go`.
- It is invoked per-request by the Connect interceptors (`server/router/api/v1/connect_interceptors.go`), the grpc-gateway middleware (`server/router/api/v1/v1.go`), and the SSE endpoint (`server/router/api/v1/sse_handler.go:26`); per-method access rules are in `server/router/api/v1/acl_config.go` / `authz.go`.
