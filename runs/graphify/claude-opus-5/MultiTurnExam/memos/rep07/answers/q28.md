```
s3presign runner (server/runner/s3presign/runner.go) — one immediate RunOnce at startup, then a 12-hour time.Ticker
SSE hub (server/router/api/v1/sse_hub.go) — event-driven; goroutines per subscribed client, woken by Broadcast calls, not a timer
webhook async dispatcher (internal/webhook/webhook.go) — event-driven; background worker draining a bounded queue fed by PostAsync
```

`Server.startBackgroundRunners` (`server/server.go:148-171`) starts exactly one runner: it calls `s3presignRunner.RunOnce(ctx)` immediately, then launches `Run` in a goroutine under its own cancellable context tracked by a `WaitGroup`. `Run` is a `time.NewTicker(runnerInterval)` loop (`server/runner/s3presign/runner.go:29-41`) with `runnerInterval = 12 * time.Hour` (:27); it refreshes S3 presigned URLs older than ~4 days (:88). Shutdown cancels it via `stopBackgroundRunners`/`waitBackgroundRunners` (`server/server.go:173-197`).

The other two are long-lived goroutines rather than scheduled runners — I include them because they are the server's other background activity: the SSE hub's per-client loops (started from `SSEHub.Subscribe`, closed at shutdown via `closeLongLivedConnections`, `server/server.go:200-205`), and the webhook queue consumer started in `internal/webhook/webhook.go:42`'s `init()`.

**Unused infrastructure — two items:**

1. **`internal/scheduler/`** is a complete cron scheduler (parser, jobs, middleware, graceful shutdown, README documenting it as "production-ready") that **nothing in the server imports**. The only references anywhere in the repo are its own `example_test.go:10` and `integration_test.go:13`. No production code schedules a job with it.
2. **`server/runner/memopayload/`** is packaged as a runner but has no `Run`/ticker loop — its `RebuildMemoPayload` is called synchronously from the API handlers on memo create and update (`server/router/api/v1/memo_service.go:108` and `:447`).
