Inside `Store.DeleteMemo` (`store/memo.go:140-158`), before the memo row is removed:

1. **`memo_relation` rows where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **`memo_relation` rows where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `FindAttachment{MemoID: ...}` and deleted one by one (`store/memo.go:149-157`)

Only then does it call `driver.DeleteMemo` for the memo row itself (`store/memo.go:158`).

The API handler does one additional step first: it deletes the memo's **comment memos** — each memo joined by a `MemoRelationComment` relation is passed through `Store.DeleteMemo` recursively, so their own relations and attachments are cleaned up too (`server/router/api/v1/memo_service.go:567-577`), before deleting the parent memo at `:579`.

Note that reactions are read at `server/router/api/v1/memo_service.go:545` only to build the webhook payload — they are not explicitly deleted on either path.
