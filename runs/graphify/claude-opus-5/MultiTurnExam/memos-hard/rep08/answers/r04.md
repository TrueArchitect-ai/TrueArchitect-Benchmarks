**Premise correction: neither.** There is no message broker in this codebase — no NATS, no RabbitMQ, no AMQP, no Kafka. A case-insensitive grep for `nats`, `rabbit`, `amqp`, `kafka`, and `pubsub` across every Go source file returns zero hits, and `go.mod` declares no such dependency. There is no queue declaration to point at, because there is no external queue.

**Actual mechanism — an in-process buffered Go channel**, all of it in `internal/webhook/webhook.go`:

- **The "queue"** is a package-level channel with a fixed capacity of 128:
  `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`. It is declared in the same `var` block as the HTTP client; there is no broker connection, topic, exchange, or routing key anywhere.
- **The "workers"** are four goroutines started in `func init()` — `internal/webhook/webhook.go:42-55`. Each ranges over the channel and calls `Post(payload)`, logging a warning via `slog.Warn` on failure. They live for the lifetime of the process and are never explicitly stopped.
- **The producer** is `PostAsync` (`internal/webhook/webhook.go:184-196`). It does a **non-blocking** send via `select` with a `default` branch: if all 128 slots are full, the payload is **dropped** and a warning is logged ("Dropped webhook dispatch because the async queue is full"). There is no retry, no dead-letter path, and no persistence — a webhook lost to a full queue or a process restart is gone.
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120`), which marshals the JSON body, optionally attaches Standard-Webhooks HMAC headers, and sends through the SSRF-guarded `safeClient` (`internal/webhook/webhook.go:32-37,152`) with a 30-second timeout.

Callers reach this from the memo RPC handlers — `server/router/api/v1/memo_service_webhooks.go:43` and `:71` — which is the only entry into the channel.

The practical consequence of it being in-process: delivery is best-effort and per-instance. Nothing survives a crash, and in a multi-replica deployment each replica has its own independent 128-slot buffer and its own four workers.
