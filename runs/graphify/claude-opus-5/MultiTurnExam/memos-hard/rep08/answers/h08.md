**Two declarers, both named `Runner` in different packages:**

| Declarer | Invoked from production code? | Caller |
|---|---|---|
| `s3presign.Runner.RunOnce` — `server/runner/s3presign/runner.go:43` | Yes | `server/server.go:163` (in `startBackgroundRunners`), plus the runner's own ticker loop at `server/runner/s3presign/runner.go:36` |
| `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:27` | No | — no callers anywhere |

Evidence:

- A repo-wide grep for `RunOnce` returns exactly five hits: the two declarations, one doc comment on each, and the two call sites — `server/server.go:163` and `server/runner/s3presign/runner.go:36`. Both call sites resolve to the s3presign receiver (`r` is `*s3presign.Runner` inside `Run`). There are no hits in test files and none in the TypeScript frontend (`web/src`).
- `s3presign.Runner.RunOnce` (`runner.go:43`) is a one-line wrapper around `CheckAndPresign`. It runs synchronously at boot (`server/server.go:163`) so S3 links are refreshed immediately, and again every 12 hours from `Run`'s ticker (`runner.go:36`).
- `memopayload.Runner.RunOnce` (`runner.go:27`) rebuilds every memo's payload in batches of 100. It is dead code: its constructor `memopayload.NewRunner` (`runner.go:19`) has no callers either, and `startBackgroundRunners` (`server/server.go:153-175`) only ever constructs the s3presign runner. The `memopayload` package *is* used in production — but only via the standalone function `memopayload.RebuildMemoPayload`, called from `server/router/api/v1/memo_service.go:108` (create) and `:447` (update), which never goes through the `Runner` type.
