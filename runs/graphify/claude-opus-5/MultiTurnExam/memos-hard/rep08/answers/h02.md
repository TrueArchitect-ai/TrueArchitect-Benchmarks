**`webhook.Post` — `internal/webhook/webhook.go:120` (enqueued via `webhook.PostAsync`, `internal/webhook/webhook.go:184`, and executed by the 4 background workers started in `init`, `internal/webhook/webhook.go:42-55`); SSRF guard = `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`, with creation-time checks in `webhook.ValidateURL` — `internal/webhook/validate.go:62`.**

How it fits together:

- **Delivery.** Memo create/update/delete handlers call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which drops the payload on a bounded 128-slot channel (`internal/webhook/webhook.go:39`). Four goroutines drain that queue and call `Post`, which marshals the JSON body, optionally adds Standard-Webhooks HMAC headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`, `internal/webhook/webhook.go:139-149`), and issues the actual `POST` via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.
- **Protection.** The shared `safeClient` (`internal/webhook/webhook.go:32-37`) installs a custom `Transport.DialContext` = `safeDialContext`. At dial time it resolves the host itself and rejects the connection if *any* resolved address falls in a reserved range (`internal/webhook/webhook.go:59-77`). Because the check happens at dial rather than at URL-registration time, it also defeats DNS rebinding, where a hostname validated as public later resolves to `127.0.0.1` or `169.254.169.254`.
- **The blocklist** is `reservedCIDRs` in `internal/webhook/validate.go:14-23` — IPv4 loopback, all three RFC-1918 ranges, link-local (covering the cloud IMDS address `169.254.169.254`), plus IPv6 loopback, unique-local, and link-local — parsed once into `reservedNetworks` in `init` (`internal/webhook/validate.go:28`).
- **Second layer, at configuration time**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user saves a webhook URL (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`); it enforces http/https scheme and the same reserved-IP rule, returning gRPC `InvalidArgument`.
- **Escape hatch**: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted setups targeting LAN services. Note it is declared but never assigned anywhere in non-test code — no CLI flag or env var currently wires it up, so in practice the guard is always on.
