**Premise correction: no nightly database-cleanup job exists, and the cron scheduler is not wired into the running server at all.** There is no schedule to report.

What's actually true:

- **The scheduler package exists but is unused in production.** `internal/scheduler/` is a self-contained cron implementation (5- and 6-field expressions, timezone support, logging/recovery/timeout middleware, `internal/scheduler/doc.go:1-8`). Grepping for the import path `github.com/usememos/memos/internal/scheduler` across the repo returns hits in exactly two files — `internal/scheduler/integration_test.go` and `internal/scheduler/example_test.go`. Nothing under `server/`, `store/`, or `cmd/` imports it, so `scheduler.New(...)`, `Register`, and `Start` are never called outside tests. It is a library sitting on the shelf.
- **The `0 2 * * *` you may be thinking of is documentation, not configuration.** `internal/scheduler/doc.go:14-17` shows a sample job literally named `"daily-cleanup"` with `Schedule: "0 2 * * *" // 2 AM daily`. That's an illustrative snippet inside a package doc comment. A similar `"0 9 * * *"` appears in a test at `internal/scheduler/integration_test.go:183`. Neither registers anything at runtime.
- **The server's only recurring background work is not cron-driven and not cleanup.** `startBackgroundRunners` (`server/server.go:153-175`) launches exactly one runner: `s3presign.Runner`, which re-signs S3 attachment URLs on a `time.Ticker` every 12 hours (`server/runner/s3presign/runner.go:27,29-40`), plus one immediate pass at boot (`server/server.go:163`). No cron expression is involved.
- **Cleanup that does happen is event-driven, not scheduled.** Attachment/blob removal occurs inline during user deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`) and memo deletion (`server/router/api/v1/memo_service.go:579`). The one periodic sweep in the codebase is the in-memory cache's expiry goroutine, running every 5 minutes (`store/store.go:42`) — application memory, not the database.
