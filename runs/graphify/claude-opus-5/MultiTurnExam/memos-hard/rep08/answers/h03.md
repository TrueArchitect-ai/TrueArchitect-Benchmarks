**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`) — OAuth2 is the only concrete implementation.**

Details:

- **Abstraction**: `internal/idp/idp.go` is a deliberately thin package — it defines just the provider-neutral result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) at `internal/idp/idp.go:3-8`. There's no Go interface; the "abstraction" is this shared user-info struct that every provider implementation must produce, plus the `storepb.IdentityProvider` config message and its `Type` enum in `proto/gen/store/idp.pb.go:24-29` — which currently has exactly two values, `TYPE_UNSPECIFIED` and `OAUTH2`.
- **Implementation**: `internal/idp/oauth2/oauth2.go` — package comment "implements the OAuth2 identity provider integration". `NewIdentityProvider` (`oauth2.go:26`) validates the required config fields (`clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, `fieldMapping.identifier`), `ExchangeToken` (`oauth2.go:45`) performs the code-for-token exchange via `golang.org/x/oauth2` with optional PKCE `code_verifier` support, and the user-info fetch maps arbitrary provider JSON onto `idp.IdentityProviderUserInfo` through the configured `FieldMapping`.
- **Consumer**: `server/router/api/v1/auth_service_sso.go` imports only `internal/idp/oauth2` (line 13) and builds the generic `*idp.IdentityProviderUserInfo` in `resolveSSOIdentity` (`auth_service_sso.go:104-119`), which `resolveSSOUser` (`auth_service_sso.go:19`) then turns into a local user.

No SAML, OIDC-specific, or LDAP package exists in the tree — `internal/idp/` contains only `idp.go` and the `oauth2/` subdirectory.
