**Premise correction: no per-user API rate-limiting middleware exists in this repository.** There is nothing to point at — no registration site and no limits, because the feature isn't implemented.

Evidence:

- A case-insensitive grep across all Go sources for `ratelimit`, `rate_limit`, `rate limit`, `throttl`, and `golang.org/x/time/rate` returns exactly one hit, and it's aspirational prose in a doc comment: "Rate limit email sending to prevent abuse" (`internal/email/doc.go:86`) — a future-work note, not code.
- `golang.org/x/time` appears in `go.mod:151` but is marked `// indirect`, i.e. pulled in transitively by another dependency, not imported by this project. Nothing in the tree imports `x/time/rate`.
- The complete global middleware stack is two entries, both at `server/server.go:51-52`: `middleware.Recover()` and `newCORSMiddleware(profile)`. The only other `Use(...)` calls anywhere are the static-file and SPA-fallback handlers in `server/router/frontend/frontend.go:54,59`. No limiter is registered on the Echo server, the gRPC-Gateway, or the Connect interceptor chain.
- Echo's own `middleware.RateLimiter` / `RateLimiterWithConfig` is never referenced.

**What does exist — concurrency limiting, which is a different control.** These bound simultaneous work server-wide, not requests per user over time, and they queue rather than reject:

- `thumbnailSemaphore` — `semaphore.NewWeighted(3)` via `maxConcurrentThumbnails = 3` (`server/router/fileserver/fileserver.go:46,116`), capping concurrent thumbnail generation to prevent memory exhaustion.
- `APIV1Service.thumbnailSemaphore` — weight 3, and `imageProcessingSemaphore` — weight 2 (`server/router/api/v1/v1.go:57-58`, acquired at `server/router/api/v1/attachment_service_image.go:71`).
- The webhook dispatch queue is bounded at 128 with 4 workers (`internal/webhook/webhook.go:39,43`), dropping overflow — an outbound backpressure valve, not inbound rate limiting.

Adjacent abuse controls that are also not rate limiting: memo content-length caps (`getContentLengthLimit`, `server/router/api/v1/memo_service.go:595`) and the SSRF guard on webhooks.
