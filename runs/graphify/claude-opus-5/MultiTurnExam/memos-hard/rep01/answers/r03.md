**Premise correction: there is no nightly database-cleanup job, and the cron scheduler that exists is never used by the running server — so there is no scheduled time to report.**

Two separate corrections:

**1. No database-cleanup job exists at all.** Grepping for `cron`, `nightly`, and `cleanup` across the Go tree turns up no scheduled database maintenance. Every `cleanup` hit is something else: the in-memory cache's expiry sweeper (`store/cache/cache.go:201,217,253`, on a 5-minute `CleanupInterval` set at `store/store.go:42`), or inline best-effort cleanup during a request — e.g. orphaned S3 objects after user deletion (`server/router/api/v1/user_service.go:421-450`) and provisional SSO rows (`server/router/api/v1/auth_service_sso.go:76`). None of these are scheduled jobs, and none prune the database on a timer.

**2. The cron scheduler package is dead code.** `internal/scheduler` does implement real cron parsing and job registration (`internal/scheduler/parser.go:30` `ParseCronExpression`, used at `internal/scheduler/scheduler.go:104`), but nothing outside the package imports it: the only files referencing `internal/scheduler` are its own `example_test.go` and `integration_test.go`. There are no `Register(...)` calls or `Job{...}` literals anywhere in production code, so zero cron expressions are ever parsed at runtime.

**What actually runs on a schedule** is a single hand-rolled ticker, not a cron job: the S3 presign refresher. `Server.startBackgroundRunners` (`server/server.go:153-174`) calls `RunOnce` immediately at startup and then loops it every 12 hours via `time.NewTicker(runnerInterval)` where `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27,29-41`). It refreshes presigned attachment URLs — it does not clean up anything. Because the interval is relative to process start, it has no fixed wall-clock time.

There is also `server/runner/memopayload`, whose `RunOnce` would rebuild all memo payloads, but nothing constructs that runner (`server/runner/memopayload/runner.go:27`), so it never executes either.
