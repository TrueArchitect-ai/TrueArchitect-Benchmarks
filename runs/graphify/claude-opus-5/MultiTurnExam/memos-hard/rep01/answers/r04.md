**Premise correction: neither. There is no message broker anywhere in this repository** — no NATS, RabbitMQ/AMQP, Kafka, SQS, or Pub/Sub. Grepping all Go files for `nats|rabbitmq|amqp|kafka|streadway|pubsub|sqs` returns zero hits, and `go.mod` declares no such dependency (the single `go.sum` match is `cespare/xxhash`, an unrelated hashing library). So there is no queue declaration, no broker connection, and no external durability.

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool**, all in `internal/webhook/webhook.go`:

- **The "queue"** is a package-level channel with a hard capacity of 128: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`.
- **The workers** are 4 goroutines started in the package's `init()`, each looping over the channel and calling `Post` — `internal/webhook/webhook.go:42-55`. Because this is `init()`, the pool spins up on package import rather than at explicit server startup, and there is no shutdown path that drains it.
- **The producer** is `PostAsync` (`internal/webhook/webhook.go:184-196`), the single convergence point for all RPC handlers that dispatch webhooks. It does a non-blocking `select` send and, on a full buffer, **drops the delivery** with only a `slog.Warn`:
  ```go
  select {
  case asyncPostQueue <- requestPayload:
  default:
      slog.Warn("Dropped webhook dispatch because the async queue is full", ...)
  }
  ```
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120-180`) via `safeClient.Do(req)` at line 152, with a 30s timeout and SSRF-guarding dialer.

Practical consequences of it being a channel rather than a broker: enqueued webhooks are lost on process exit or crash (nothing is persisted), there are no retries — a failed `Post` is logged and discarded by the worker loop at lines 46-51 — and overflow is silently dropped rather than backpressured. Callers can't observe any of this, since every RPC handler only logs the dispatch error at warn level.
