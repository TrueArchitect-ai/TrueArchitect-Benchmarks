**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

Details:

**Abstraction — `internal/idp`**
`internal/idp/idp.go` is the whole package: it defines just the shared result type `IdentityProviderUserInfo` with `Identifier`, `DisplayName`, `Email`, `AvatarURL`. Note this is a thin data-contract abstraction rather than a Go `interface` — there is no `IdentityProvider` interface for implementations to satisfy; the common shape is the user-info struct that every provider must produce.

**Implementation — `internal/idp/oauth2`**
`internal/idp/oauth2/oauth2.go` is the only concrete provider that ships (the `internal/idp` tree contains only `idp.go`, `oauth2/oauth2.go`, and `oauth2/oauth2_test.go`). It wraps `golang.org/x/oauth2` and provides:
- `NewIdentityProvider` (line 27) — validates required `storepb.OAuth2Config` fields (`clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, `fieldMapping.identifier`).
- `ExchangeToken` (line 47) — authorization-code exchange with optional PKCE `code_verifier`.
- `UserInfo` (line 83) — fetches the userinfo endpoint with a 10s timeout and maps JSON claims onto `idp.IdentityProviderUserInfo` using the configured `FieldMapping`.

**Corroboration that OAuth2 is the only protocol:** both the store and API protos define a single enum value and a single `oneof` arm — `OAUTH2 = 1` / `OAuth2Config oauth2_config = 1` (`proto/store/idp.proto:13,22-24`, `proto/api/v1/idp_service.proto:79,83-87`). The SSO login path branches on exactly that one type: `if identityProvider.Type == storepb.IdentityProvider_OAUTH2` in `server/router/api/v1/auth_service_sso.go:120-131`, with no other provider branch — so an unrecognized type silently leaves `userInfo` nil.
