**Premise correction: there is no Redis in this repository.** Grepping the entire tree for `redis`, `valkey`, and `memcache` across `*.go`, `go.mod`, `go.sum`, and config/docs files returns zero hits. There is no external cache server, no connection string, and no place where one would be configured.

**Actual mechanism:** the cache layer is a hand-rolled, in-process, in-memory cache.

- **Implementation:** `store/cache/cache.go` — a `Cache` struct backed by a `sync.Map` plus an atomic item counter (`store/cache/cache.go:65-71`), satisfying the `cache.Interface` declared at `store/cache/cache.go:11-32`. Entries are `item{value, expiration, size}` (`store/cache/cache.go:35-39`), and a `cleanupLoop` goroutine sweeps expired entries.

- **"Connection" configuration** is just a `cache.Config` literal — there is nothing to connect to. `store.New` builds one config and hands the same values to three separate cache instances (`store/store.go:40-53`):
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  for `instanceSettingCache`, `userCache`, and `userSettingCache` (fields at `store/store.go:27-29`). `cache.DefaultConfig()` (`store/cache/cache.go:56-63`) carries the identical values but is not what the store uses — `store.New` duplicates them inline.

- **TTL for user entries: 10 minutes**, inherited from `DefaultTTL`. Every user write goes through `Set`, never `SetWithTTL`: `store/user.go:98, 122, 132, 143, 167`. `Cache.Set` forwards to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:94`), so no user entry gets a custom TTL anywhere in the codebase.

Two behavioral details worth knowing: the user cache is keyed by ID only, so `Store.GetUser` consults it solely when `find.ID != nil` (`store/user.go:149-156`) — lookups by username or email always hit the database. And deletion explicitly invalidates the entry via `s.userCache.Delete` (`store/user_delete.go:40`). Because the cache is per-process and unreplicated, multiple memos instances would each hold independent copies with up to 10 minutes of staleness.
