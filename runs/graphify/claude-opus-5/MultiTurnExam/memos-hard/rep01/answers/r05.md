**Premise correction: there is no GraphQL anywhere in this repository.** Searching all Go, TypeScript, JSON, and module files for `graphql`, `gqlgen`, and `apollo` returns zero hits (excluding `node_modules`), and there are no `.graphql`/`.gql`/`.graphqls` schema files. So there is no GraphQL schema to point to.

**Actual API surface: Protobuf/gRPC service definitions, exposed over three transports.**

**Schema source of truth** — `.proto` files under `proto/api/v1/`:
- `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto`

Codegen is driven by buf (`proto/buf.gen.yaml`, `proto/buf.yaml`, `proto/buf.lock`) into `proto/gen/api/**` — including gRPC stubs, gRPC-Gateway `.pb.gw.go` files, and Connect handlers under `proto/gen/api/v1/apiv1connect/`.

**How it's served** — `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`) mounts, on the Echo server:
1. **gRPC-Gateway** — RESTful JSON/HTTP transcoding of the proto services.
2. **Connect RPC** — registered at `server/router/api/v1/v1.go:140-141` via `NewConnectServiceHandler` (`server/router/api/v1/connect_services.go`), which is what the browser client uses; the web app depends on `@connectrpc/connect` and `@connectrpc/connect-web` (`web/package.json:27-28`) and configures it in `web/src/connect.ts`. The comment at line 131 notes this replaced grpc-web.

**Machine-readable spec** — an **OpenAPI** document, not a GraphQL SDL: generated to `proto/gen/openapi.yaml` and embedded into the binary via `//go:embed` in `proto/openapi_embed.go`, exposed through `proto.OpenAPIYAML()`.

**Additional non-proto HTTP surfaces**, for completeness: the file server (`/file/attachments/...`, `/file/users/:identifier/avatar` — `server/router/fileserver/fileserver.go:122-125`), RSS feeds (`server/router/rss/rss.go`), an MCP endpoint (`server/router/mcp`), and the frontend/sitemap routes (`server/router/frontend/frontend.go`).
