**`webhook.Post` — `internal/webhook/webhook.go:120-180`; SSRF guard via a dial-time reserved-IP check (`safeDialContext` → `isReservedIP`) on the shared `safeClient` transport — `internal/webhook/webhook.go:32-77` + `internal/webhook/validate.go:14-54`**

How it fits together:

**Delivery path**
- Content-change events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43,71`) for `memos.memo.created/updated/deleted` and `memos.memo.comment.created`.
- `PostAsync` (`internal/webhook/webhook.go:184-196`) only enqueues onto a bounded 128-slot channel `asyncPostQueue`, dropping with a warning when full.
- Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call **`Post`**, which is where the actual outbound HTTP request executes: it marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), then does `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

**Protection — two layers, the dial-time one being the real guard**
1. **Dial-time (authoritative):** `safeClient`'s `http.Transport` uses `DialContext: safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59-77`) resolves the target host itself and refuses the connection if *any* returned IP is reserved. Because the check happens on the address actually being dialed, it also defeats DNS rebinding — a validated-at-save-time hostname that later flips to `127.0.0.1` still fails.
2. **Admission-time (early feedback):** `webhook.ValidateURL` (`internal/webhook/validate.go:62-83`) rejects non-http(s) schemes and reserved-resolving hostnames when a webhook is created/updated, called from `server/router/api/v1/user_service_webhooks.go:74,161,182`.

Both share `isReservedIP` (`internal/webhook/validate.go:44-54`) against `reservedCIDRs` (`internal/webhook/validate.go:14-23`) — IPv4/IPv6 loopback, RFC-1918, unique-local, and link-local `169.254.0.0/16`, which covers the cloud IMDS endpoint.

One caveat worth flagging: the package-level `var AllowPrivateIPs bool` (`internal/webhook/validate.go:41`) disables both layers when true. Nothing in the non-test tree assigns it — grep finds no setter in `cmd/` or `server/` — so it is currently always `false` at runtime and there is no flag or env var exposing it, despite the doc comment describing it as an option for self-hosted deployments.
