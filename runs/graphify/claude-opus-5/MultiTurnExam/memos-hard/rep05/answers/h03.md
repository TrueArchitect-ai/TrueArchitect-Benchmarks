**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package**: `internal/idp` (`internal/idp/idp.go`) — a deliberately thin abstraction. It defines only the shared result type `IdentityProviderUserInfo` with `Identifier`, `DisplayName`, `Email`, `AvatarURL` (`internal/idp/idp.go:3-8`). There's no Go `interface` declared; the "contract" is the informal pair of methods `ExchangeToken` / `UserInfo` returning `*idp.IdentityProviderUserInfo`.

- **Implementation package**: `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`) — the only concrete protocol that ships. `IdentityProvider` wraps a `storepb.OAuth2Config` (`oauth2.go:20-22`); `NewIdentityProvider` validates that clientId, clientSecret, tokenUrl, userInfoUrl, and `fieldMapping.identifier` are all non-empty (`oauth2.go:27-43`). `ExchangeToken` performs the authorization-code exchange via `golang.org/x/oauth2`, with optional PKCE by passing `code_verifier` (`oauth2.go:47-80`). `UserInfo` does a bearer-token GET against the configured userinfo endpoint with a 10s timeout and maps raw JSON claims onto the struct through the configurable `FieldMapping` (`oauth2.go:83-141`).

Supporting evidence that OAuth2 is the sole implementation:
- The store proto enum has exactly one non-unspecified member: `IdentityProvider_OAUTH2 = 1` (`proto/gen/store/idp.pb.go:27-28`), and `IdentityProviderConfig` is a oneof whose only variant is `Oauth2Config` (`proto/gen/store/idp.pb.go:158`, `:214-218`).
- The only non-test consumer is the SSO auth path, which imports both packages (`server/router/api/v1/auth_service_sso.go:12-13`) and funnels the resulting `*idp.IdentityProviderUserInfo` into `resolveSSOUser` for account linking/provisioning (`auth_service_sso.go:19`).

OIDC is not implemented separately — an OIDC provider would be configured as a generic OAuth2 provider by pointing `userInfoUrl` at the OIDC userinfo endpoint.
