All four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go`; the three memo-lifecycle ones funnel through the shared `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:47`), and the comment one has its own loop (`:30-45`). Each looks up `s.Store.GetUserWebhooks(...)` and, per registered hook, sets `payload.URL = hook.Url` — the user-configured URL — then calls `webhook.PostAsync(payload)` at `memo_service_webhooks.go:43` and `:71`. Those two call sites are the only ones in the repo.

**Convergence**: `webhook.PostAsync` (`internal/webhook/webhook.go:184`) is the single chokepoint every path passes through before delivery. It enqueues onto the bounded 128-slot `asyncPostQueue` (`webhook.go:39`, dropping with a warning when full at `:191-195`); four worker goroutines started in `init()` (`webhook.go:42-55`) then call `Post` (`webhook.go:120`), which performs the actual `safeClient.Do(req)` (`webhook.go:152`).

If you want the last function before the wire rather than the last function reachable from the handlers, that's `webhook.Post` — but the handler goroutines never reach it directly; the queue boundary at `PostAsync` is where the RPC paths actually converge.

Note that all six call sites treat dispatch failure as non-fatal — errors are logged via `slog.Warn` and the RPC still succeeds.
