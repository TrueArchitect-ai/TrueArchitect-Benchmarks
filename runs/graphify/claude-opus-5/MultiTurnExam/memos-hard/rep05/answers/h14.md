**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, which delegates the parse to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`.**

**Triggers (recomputation happens on exactly two paths):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`. This also covers `CreateMemoComment`, which routes through `CreateMemo` internally.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but **only** inside the `if path == "content"` arm of the update-mask loop (`memo_service.go:435-451`). The recomputed payload is then assigned to `update.Payload` (`:451`) so it persists. Updating visibility, pinned state, timestamps, etc. does not re-derive anything.
- A third, dormant path exists: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) rebuilds every memo in batches of 100 — but nothing constructs that runner, so it never executes (see the fan-in on `NewRunner`).

**What the computation extracts** — `RebuildMemoPayload` writes two fields onto `memo.Payload` (`runner.go:85-86`):

1. **`Payload.Tags`** — `[]string` of every `#tag` node, deduplicated with original case preserved (`markdown.go:379-380`, `:417`).
2. **`Payload.Property`** — a `storepb.MemoPayload_Property` (`proto/gen/store/memo.pb.go:85-95`) with five derived fields:
   - `Title` — text of the first H1 heading, only if it's the document's first block-level child (`markdown.go:383-389`)
   - `HasLink` — any `KindLink` node (`markdown.go:393-394`)
   - `HasCode` — any code block, fenced code block, or inline code span (`markdown.go:396-397`)
   - `HasTaskList` — any task checkbox (`markdown.go:399-400`)
   - `HasIncompleteTasks` — at least one unchecked checkbox (`markdown.go:401-404`)

All of it comes from a single `gast.Walk` over the goldmark AST — one parse, not one per property — which is why `ExtractAll` is preferred over the individual `ExtractTags`/`ExtractProperties` methods.

Two things worth separating out, since they're derived-from-content but *not* part of this stored payload:

- `ExtractAll` also returns `Mentions` (lowercased `@username` nodes, `markdown.go:381-382`), but `RebuildMemoPayload` discards them. Mentions are consumed live from `s.MarkdownService.ExtractAll` at `server/router/api/v1/memo_mention_helpers.go:32` for notifications, never persisted.
- The list/preview **snippet** is computed on read, not stored: `getMemoContentSnippet` → `GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-85`), called during memo conversion (`memo_service_converter.go:76-80`), relation rendering (`memo_relation_service.go:154-173`), and notification payloads (`user_service_notifications.go:318-391`).

A consequence of the trigger set: since only the `content` mask path recomputes, and `Payload.Location` is merged in separately after the rebuild on create (`memo_service.go:111-113`), any memo whose payload predates a change in extraction logic keeps stale `Tags`/`Property` until its content is next edited — and the bulk backfill that would fix that (`RunOnce`) is not wired up.
