**1st: `store.User` (~6 packages outside the data layer, 83 non-test references); 2nd: `store.Memo` (~4 packages, 56 references).**

Measured by grepping `store.<Type>` across all Go files and grouping hits by package directory, excluding `store/` and its `store/db/{sqlite,postgres,mysql}` driver sub-packages (those are the data layer itself, and every entity is naturally referenced by all three).

**`store.User` — 6 consumer packages:**
- `server/auth` — session/PAT resolution
- `server/notification`
- `server/router/api/v1` — the bulk of the RPC surface
- `server/router/api/v1/test` — test harness (non-`_test.go` support code)
- `server/router/fileserver` — e.g. `getUserByUsername` at `server/router/fileserver/fileserver.go:715`
- `server/router/rss`

**`store.Memo` — 4 consumer packages:**
- `server/notification`
- `server/router/api/v1`
- `server/router/rss`
- `server/runner/memopayload` — e.g. `RebuildMemoPayload` at `server/runner/memopayload/runner.go:74`

Type declarations: `store.User` in `store/user.go`, `store.Memo` in `store/memo.go`.

Two caveats on the ranking:

- **Third place is close.** `store.Attachment` (`store/attachment.go`) reaches 3 packages — `server/router/api/v1`, `server/router/fileserver`, `server/router/rss` (4 counting the test harness) — but has 68 non-test references, *more* than `Memo`'s 56. So by raw reference count the order is User (83) → Attachment (68) → Memo (56); by package spread it's User (6) → Memo (4) → Attachment (3/4). I ranked by package count since that's what was asked.
- **Including `_test.go` files** adds `server/router/frontend` and `store/test` to both User and Memo, pushing them to 8 and 6 packages respectively, but doesn't change the relative order.

The remaining entities are notably narrower: `Inbox` and `MemoShare` reach 2–3 outside packages, and `UserSetting`, `IdentityProvider`, and `InstanceSetting` are referenced outside the data layer only via `proto/gen/store` — they never escape into the router packages as `store.` types at all.
