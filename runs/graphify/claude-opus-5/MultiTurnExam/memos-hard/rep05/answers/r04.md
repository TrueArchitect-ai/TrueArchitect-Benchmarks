**Premise correction: neither. There is no message broker in this repository — no NATS, no RabbitMQ, no AMQP, Kafka, SQS, or Redis pub/sub. A case-insensitive grep for all of those across the Go sources, `go.mod`, and `go.sum` returns no real dependency (the single `go.sum` hit is a coincidental substring inside a base64 checksum for `cespare/xxhash`). There is no queue declaration to point at, because nothing external is being declared.**

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool, entirely inside `internal/webhook/webhook.go`.**

- **The "queue"** is a package-level buffered channel of 128 slots: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`). That declaration line is the closest analogue to a queue declaration.
- **The "workers"** are 4 goroutines started in the package `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over the channel and calls `Post(payload)`, logging a warning on failure. They live for the process lifetime — there is no shutdown path, no ack, no retry, and no dead-letter handling.
- **The producer** is `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send: if the buffer is full, the event is **dropped** with a `slog.Warn` rather than blocking the caller. Its two call sites are `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120`), which signs the payload (Standard Webhooks HMAC-SHA256 headers) and issues `safeClient.Do(req)` at `webhook.go:152` through the SSRF-guarded dialer.

Two consequences of this being in-process rather than broker-backed: pending webhooks are lost on restart or crash (nothing is persisted), and each server replica has its own independent 128-slot buffer and worker pool — there is no shared or coordinated queue across instances.
