**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never started. Nothing is scheduled, so there is no run time to report.**

What's actually there:

1. **A cron scheduler package exists but is dead code in production.** `internal/scheduler/` is a complete, self-contained cron implementation — `New`/`Register`/`Start`/`Stop` (`internal/scheduler/scheduler.go:54`, `:70`, `:91`, `:169`), a 5- and 6-field expression parser (`internal/scheduler/parser.go:30`), and middleware (`internal/scheduler/middleware.go`). But `grep -rln "internal/scheduler"` shows exactly two importers, both inside the package's own tests: `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. No server, command, or runner imports it. `scheduler.New()` is never called in non-test code, so no job is ever registered and `Start()` never runs.

2. **The `"0 2 * * *"` / "2 AM daily" you may be thinking of is a doc comment, not a job.** It appears in the package documentation example at `internal/scheduler/doc.go:14-21`, under a job literally named `"daily-cleanup"` whose handler body is the comment `// Your cleanup logic here` followed by `return nil`. It is illustrative sample code in a `//` block — nothing parses or executes it.

3. **The only real recurring background work is unrelated to cleanup.** The single production runner is the S3 presign refresher: a `time.Ticker` on a 12-hour interval (`server/runner/s3presign/runner.go:27,29-41`), started from `Server.startBackgroundRunners` at `server/server.go:162-170`. It's interval-based, not cron-based, and it refreshes presigned URLs rather than cleaning anything up.

4. **No database cleanup/retention/vacuum logic exists at all.** Grepping for `cleanup|vacuum|prune|purge|retention` across `server`, `store`, `cmd`, and `internal` turns up only: the in-memory cache's expiry sweep on a 5-minute interval (`store/cache/cache.go:201-218`, configured at `store/store.go:42`), and per-request attachment cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`). Both are event- or interval-driven, neither is nightly, and neither is a scheduled database maintenance job.
