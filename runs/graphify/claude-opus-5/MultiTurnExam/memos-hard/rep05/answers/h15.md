The three primary read surfaces, if you want the short list: `checkMemoReadAccess` (gRPC/Connect API), `checkAttachmentPermission` (raw file serving), and the `VisibilityList` pinning in RSS/sitemap (unauthenticated HTTP).

Two structural notes:

- **These are independent implementations, not one shared helper.** `fileserver` re-derives the rule from scratch (`fileserver.go:699`) because it authenticates via its own `auth.Authenticator` rather than the gRPC interceptor, and it uniquely honors a `share_token` query param (`fileserver.go:686`) plus the instance-level `AllowAnonymous()` gate (`fileserver.go:677`). The v1 API path has no share-token equivalent.
- **`memo_share_service.go` is not a visibility site.** Share create/update/delete check ownership only (`CreatorID != user.ID && !isSuperUser`, at `:43`, `:92`, `:133`); the share token deliberately bypasses visibility, and that bypass is enforced/expiry-checked in the fileserver via `isMemoShareExpired` (`fileserver.go:778-780`).
