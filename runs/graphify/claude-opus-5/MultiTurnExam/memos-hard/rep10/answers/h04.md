Evidence:

- **The factory is the only importer.** Grepping the whole repo for the package path and constructor (`grep -rn "db/mysql\|mysql\.NewDB\|mysql\.DB{" --include=*.go .`, excluding `store/db/mysql/` itself) returns exactly two hits, both in the factory: the import at `store/db/db.go:8` and the call `driver, err = mysql.NewDB(profile)` at `store/db/db.go:22`, inside the `switch profile.Driver` (`store/db/db.go:18-27`). No `cmd/`, `server/`, `internal/`, or `store/` file reaches for it.
- **`NewDB` is called once.** `store/db/mysql/mysql.go:20` declares `func NewDB(profile *profile.Profile) (store.Driver, error)`; the only call site anywhere is `store/db/db.go:22`. It returns the `store.Driver` interface rather than `*DB`, so callers can't get a concrete handle from it either.
- **The one in-package construction is a test fixture.** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — a zero-value struct with a nil `*sql.DB`, used to exercise pure query/SQL-building logic without a database. That's not a driver construction in the sense of an initialized connection, and it's test-only.

For symmetry, the same holds for the sibling drivers: `sqlite.NewDB` and `postgres.NewDB` are likewise reached only through `store/db/db.go:20` and `:24`. Driver selection is fully centralized in `NewDBDriver`, with the driver name coming from the profile.
