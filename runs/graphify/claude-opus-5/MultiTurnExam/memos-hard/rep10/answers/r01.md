**Premise correction: there is no Redis anywhere in this repository — no client library, no connection config, no `redis` string in any Go file, `go.mod`, or YAML. The cache layer is a hand-rolled, in-process, in-memory cache. User entries carry a 10-minute TTL.**

Actual mechanism:

- **Implementation.** `store/cache/cache.go` defines an `Interface` (`:11-32`) and a `Cache` struct backed by a `sync.Map` plus an atomic item counter (`:66-72`). It's per-process and non-shared: two Memos instances behind a load balancer would each hold their own copy, and the cache is empty on restart.
- **Where user caching is configured.** `store.New` builds one `cache.Config` literal and hands the same values to three separate caches (`store/store.go:39-53`):
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  applied to `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:50-52`). `cache.DefaultConfig()` (`store/cache/cache.go:56-63`) declares the identical values but is not what the store uses — the store inlines its own copy.
- **TTL for user entries: 10 minutes.** Every user write goes through `Set`, never `SetWithTTL`, so the default applies — `store/user.go:98`, `:122`, `:132`, `:143`, `:167`, all keyed by `userCacheKey(user.ID)`. `SetWithTTL` exists (`store/cache/cache.go:16`) but is only exercised in `store/cache/cache_test.go:26`; no production code overrides the TTL.
- **Eviction and invalidation.** A background goroutine sweeps expired entries every 5 minutes, and the cache is capped at 1000 items. Explicit invalidation happens on user deletion (`store/user_delete.go:40`). Note the read path is ID-only: `Store.GetUser` consults the cache solely when `find.ID != nil` (`store/user.go:149-156`), so username or email lookups always hit the database and merely refresh the entry afterward.
- **Lifecycle.** `Store.Close` stops all three cleanup goroutines (`store/store.go:74-76` → `store/cache/cache.go:187`).

There's no configuration surface for any of this — no flag, env var, or setting exposes TTL, cleanup interval, or max items; changing them requires editing `store/store.go:40-45`.
