**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` (six total); convergence function — `webhook.Post` at `internal/webhook/webhook.go:120`**

The six RPC entry points and how each reaches the network:

| Handler | Path |
|---|---|
| `CreateMemo` — `server/router/api/v1/memo_service.go:70` | `DispatchMemoCreatedWebhook` at `:157` |
| `UpdateMemo` — `server/router/api/v1/memo_service.go:401` | `dispatchMemoUpdatedSideEffects` at `:513` |
| `DeleteMemo` — `server/router/api/v1/memo_service.go:518` | `DispatchMemoDeletedWebhook` at `:562` (fires *before* the rows are removed) |
| `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` at `:119`, targeting the *parent* memo's owner |
| `SetMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:16` | `dispatchMemoUpdatedSideEffects` at `:48` |
| `SetMemoRelations` — `server/router/api/v1/memo_relation_service.go:16` | `dispatchMemoUpdatedSideEffects` at `:48` |

The funnel below them:

1. All four `Dispatch*Webhook` methods (`server/router/api/v1/memo_service_webhooks.go:15-46`) resolve the owner's webhooks via `s.Store.GetUserWebhooks` and call `webhook.PostAsync` (`:43`, `:71`). The last three handlers share the intermediate hop `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook`.
2. `webhook.PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a 128-slot channel; four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it.
3. **`webhook.Post` (`internal/webhook/webhook.go:120`) is the single convergence point** — every path, sync or async, ends there. It marshals the payload, optionally signs it, and issues the one outbound request at `internal/webhook/webhook.go:152` (`safeClient.Do(req)`).

The URL is fully user-controlled (`payload.URL = hook.Url`, from the user's stored webhook settings), which is why `Post` goes through `safeClient` with the SSRF-blocking `safeDialContext` (`internal/webhook/webhook.go:32-77`).

Two scoping notes: `dispatchMemoUpdatedSideEffects` is called at three sites, so if you count only that helper you'd miss the create/delete/comment paths — hence four distinct dispatch functions above one `Post`. All dispatch errors are logged and swallowed (`slog.Warn`), so a webhook failure never fails the RPC.
