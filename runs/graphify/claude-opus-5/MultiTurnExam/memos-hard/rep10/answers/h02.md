**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual `safeClient.Do(req)` call is `internal/webhook/webhook.go:152`); SSRF protection is `safeDialContext`, installed as the HTTP transport's `DialContext` — `internal/webhook/webhook.go:59` (wired at `internal/webhook/webhook.go:32-37`), backed by `isReservedIP`/`reservedCIDRs` — `internal/webhook/validate.go:14-54`**

How it fits together:

- **Trigger path:** memo create/update/delete and comment-created call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43`, `:71`), which only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:39`, `:184-196`) and drops with a warning when full.
- **Where delivery executes:** four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, which marshals the payload, adds Standard Webhooks HMAC-SHA256 headers when a signing secret is set (`webhook-id`/`webhook-timestamp`/`webhook-signature`, `internal/webhook/webhook.go:133-150`), and issues the POST through `safeClient` with a 30s timeout and a 1 MiB response read limit (`:158`).
- **Protection:** `safeClient`'s transport dials via `safeDialContext`, which resolves the host and rejects the connection if *any* resolved address falls in a reserved range (`internal/webhook/webhook.go:59-77`). Because the check happens at dial time rather than only at URL-registration time, it also defeats DNS rebinding. The blocked ranges are loopback, RFC-1918, link-local/cloud IMDS `169.254.0.0/16`, and IPv6 equivalents (`internal/webhook/validate.go:14-23`, parsed once in `init()` at `:28-36`).
- **Second layer at registration:** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) enforces http/https scheme and the same reserved-IP check when a user creates or updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

One thing worth flagging: `AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both layers when true, but nothing in the repo ever sets it — no flag, env var, or config binding assigns it (grep across non-test `.go` files returns only its own declaration and use). So today it is effectively a compile-time-only escape hatch that defaults to `false`, i.e. protection always on; self-hosters wanting LAN webhook targets have no exposed way to enable it.
