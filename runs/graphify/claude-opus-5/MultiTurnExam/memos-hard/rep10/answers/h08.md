h08.

**Two declarers, both named `Runner` in different packages; only the s3presign one is invoked from production code.**

```
s3presign.Runner.RunOnce — server/runner/s3presign/runner.go:43 — yes — Server.startBackgroundRunners at server/server.go:163, and Runner.Run's ticker loop at server/runner/s3presign/runner.go:36
memopayload.Runner.RunOnce — server/runner/memopayload/runner.go:27 — no — no caller anywhere (production or test)
```

Evidence:

- **Declarations.** A repo-wide grep for `func .*RunOnce` returns exactly two hits: `server/runner/s3presign/runner.go:43` and `server/runner/memopayload/runner.go:27`. Both are methods on a type named `Runner`, distinguished only by package.
- **s3presign is live.** Called twice: synchronously at startup in `startBackgroundRunners` (`server/server.go:163`), and on every tick of the 12-hour ticker inside `Runner.Run` (`server/runner/s3presign/runner.go:36`), which the server launches as a goroutine at `server/server.go:169`.
- **memopayload is dead code.** Its `RunOnce` (a bulk re-derivation of every memo's tags/properties, batched 100 at a time) has no call sites — the grep for `RunOnce(` finds none. Its constructor is unused too: the only external references to the package are `memopayload.RebuildMemoPayload` at `server/router/api/v1/memo_service.go:108` (CreateMemo) and `:447` (UpdateMemo). `memopayload.NewRunner` (`server/runner/memopayload/runner.go:19`) is never called, so a `Runner` value is never constructed, in production or in tests. Only the package-level helper `RebuildMemoPayload` (`:74`) is actually used.

So the `Runner`/`RunOnce` shape is a convention shared by the two packages under `server/runner/`, but only `s3presign` is wired into the server; `memopayload.Runner` is a vestigial backfill utility.
