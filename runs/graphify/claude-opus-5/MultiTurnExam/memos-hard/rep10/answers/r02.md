**Premise correction: there is no rate-limiting middleware in this codebase — per-user or otherwise. No rate limiter is registered, and no request limits exist to report.**

Evidence:

- A case-insensitive search across all Go files and `go.mod` for `ratelimit`, `rate_limit`, `rate limit`, `throttl`, `RateLimiter`, and `golang.org/x/time/rate` returns exactly one hit, and it's a comment describing future work, not code: `internal/email/doc.go:86` — `//   - Rate limit email sending to prevent abuse`. Echo's `middleware.RateLimiter` is never imported or used, and `golang.org/x/time/rate` is not a dependency.
- The complete Echo middleware stack is two entries, registered in `NewServer`: `middleware.Recover()` (`server/server.go:51`) and `newCORSMiddleware(profile)` (`server/server.go:52`). Route-group registration for the API, file server, and RSS follows, but nothing else is added via `Use`.
- Authentication middleware exists (`NewAuthorizer` / the gateway auth middleware in `server/router/api/v1/v1.go:66-72`, and `server/router/api/v1/authz.go`), but it does authorization only — it counts nothing and tracks no per-user request state.

What does exist, and might be what you're thinking of — these are **concurrency caps and size limits, not rate limits** (they bound simultaneous work or payload size, never requests per unit time, and none are per-user):

- `thumbnailSemaphore` — max 3 concurrent thumbnail generations, in both the file server (`server/router/fileserver/fileserver.go:46`, `:116`) and the v1 API (`server/router/api/v1/v1.go:59`).
- `imageProcessingSemaphore` — max 2 concurrent image operations (`server/router/api/v1/v1.go:60`).
- Upload size ceiling from the instance storage setting, falling back to `MaxUploadBufferSizeBytes` (`server/router/api/v1/attachment_service.go:120-125`).
- Memo content length limit, checked on create and update (`server/router/api/v1/memo_service.go:100-106`, `:438-444`).
- Webhook dispatch queue bounded at 128 with drop-on-full (`internal/webhook/webhook.go:39`, `:189-195`) — outbound, and a backpressure valve rather than a rate limit.

If you want per-user API rate limiting, it would need to be added; the natural insertion point is alongside the existing `echoServer.Use(...)` calls at `server/server.go:51-52`, or in the Connect/gateway interceptor chain in `server/router/api/v1/v1.go`.
