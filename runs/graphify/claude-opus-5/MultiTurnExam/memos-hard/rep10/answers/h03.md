**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`) — OAuth2 is the only concrete protocol that ships**

Details:

- **Abstraction:** `internal/idp/idp.go` is deliberately thin — it defines only the shared result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`). There is no Go `interface` here; the "abstraction" is this common user-info struct plus the protobuf `IdentityProvider` type with a `oneof config` (`proto/store/idp.proto:22-23`, mirrored in `proto/api/v1/idp_service.proto:84-85`) and the `IdentityProvider_OAUTH2` enum value. Both `oneof`s currently have exactly one arm: `OAuth2Config`.
- **Implementation:** `internal/idp/oauth2/oauth2.go` provides `IdentityProvider` with `NewIdentityProvider` (`:27`, validates required config fields), `ExchangeToken` (`:47`, uses `golang.org/x/oauth2` and forwards a `code_verifier` for PKCE when present), and `UserInfo` (`:83`, fetches the userinfo endpoint and maps claims through the configured `FieldMapping`, requiring a non-empty identifier).
- **Dispatch site:** `server/router/api/v1/auth_service_sso.go:120-134` branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` and constructs the OAuth2 provider — a plain `if`, not a registry, so adding a second protocol (OIDC/SAML/LDAP) would mean extending both the proto `oneof` and this branch. Note that because it's an `if` with no `else`, an unrecognized type leaves `userInfo` nil and would panic at `:142`; today that's unreachable since OAUTH2 is the only non-unspecified enum value.
