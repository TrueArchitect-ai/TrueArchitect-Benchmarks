**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, which delegates to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`; Triggers: `CreateMemo` (`server/router/api/v1/memo_service.go:108`), `UpdateMemo` when the update mask includes `content` (`server/router/api/v1/memo_service.go:447`), and transitively `CreateMemoComment` (which calls `CreateMemo` at `server/router/api/v1/memo_service_comments.go:55`); Extracted: `tags` plus the five `Property` fields — `title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`**

How it works:

- **The stored shape.** The derived data lives in `storepb.MemoPayload` (`proto/store/memo.proto:7-28`) — `repeated string tags` (field 3) and the nested `Property` message (field 1), commented in the proto as "the calculated properties from the memo content": `has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, `title`. The sibling `location` field is *not* derived — it's user-supplied and assigned separately right after the rebuild (`server/router/api/v1/memo_service.go:110-112`).
- **The rebuild.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`. It overwrites both wholesale, so stale tags/properties can't survive a content edit.
- **The extraction.** `ExtractAll` (`internal/markdown/markdown.go:356-421`) parses the content once with goldmark and does a single `gast.Walk`, collecting in one pass:
  - **tags** from custom `MemoTagNode`s, deduplicated case-preservingly via `uniquePreserveCase` (`:418`);
  - **title** — only if the document's *first* block-level child is an H1 heading (`:384-390`), guarded by `firstBlockChecked`;
  - **has_link** on `KindLink`; **has_code** on `KindCodeBlock`/`KindFencedCodeBlock`/`KindCodeSpan`; **has_task_list** on `KindTaskCheckBox`, with **has_incomplete_tasks** set when any checkbox is unchecked (`:392-406`).
  
  It also collects `Mentions`, but `RebuildMemoPayload` ignores that field — mentions are consumed separately for notifications (`server/router/api/v1/memo_mention_helpers.go:32`).
- **Trigger precision.** On update, the rebuild is inside the `if path == "content"` branch of the update-mask loop (`memo_service.go:436-452`), so changing only visibility, pinned state, etc. does not recompute. `SetMemoAttachments` / `SetMemoRelations` don't touch content and therefore don't recompute either. There's also a dormant bulk backfill, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), which would re-derive every memo in batches of 100 — but as noted earlier it has no callers.

One adjacent thing that is *not* stored: the list/preview **snippet** is generated on read, not persisted — `MarkdownService.GenerateSnippet` (`internal/markdown/markdown.go:264`) is called during conversion for responses (e.g. `server/router/api/v1/memo_service_webhooks.go:85`).
