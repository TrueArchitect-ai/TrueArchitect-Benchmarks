Notes on the main three:

- **`checkMemoReadAccess`** (`memo_service.go:39-68`) is the canonical per-memo gate: archived memos are creator-only (lines 44-53); non-`PUBLIC` memos require an authenticated user (`Unauthenticated` otherwise); `PRIVATE` additionally requires `memo.CreatorID == user.ID` (`PermissionDenied`). Note it does *not* grant admins access to others' private memos.
- **`ListMemos`** enforces at the query layer instead of per-row: anonymous callers get `VisibilityList = [PUBLIC]`; authenticated callers with no creator filter get the CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`; querying another user's memos narrows to `[PUBLIC, PROTECTED]` (`memo_service.go:218-227`).
- **`checkAttachmentPermission`** re-derives visibility from the owning memo outside the gRPC stack (`fileserver.go:671-704`): orphan attachments are creator/admin-only (lines 660-664), `PUBLIC` passes only when `Profile.AllowAnonymous()` (line 677), a valid non-expired `share_token` scoped to that memo bypasses (lines 684-690), otherwise auth is required and `PRIVATE` allows creator or admin (line 699). This path's admin allowance differs from `checkMemoReadAccess`.
