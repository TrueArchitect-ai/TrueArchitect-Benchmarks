**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`; triggers: memo creation and content updates; extracted: tags plus a `Property` message of `Title`, `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks`.**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) lazily initializes `memo.Payload`, calls `markdownService.ExtractAll([]byte(memo.Content))` for a single-pass extraction, then assigns:
```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```
(`server/runner/memopayload/runner.go:85-86`). The payload is persisted with the memo — it's serialized into the `payload` column on insert (`store/db/sqlite/memo.go:17-27`).

The actual walk is `ExtractAll` (`internal/markdown/markdown.go:356-416`): one `gast.Walk` over the goldmark AST collecting everything at once.

**Triggers.** Only two call sites exist in production code, both in the v1 memo service:
1. **`CreateMemo`** — `server/router/api/v1/memo_service.go:107`, before `s.Store.CreateMemo`. This also covers **`CreateMemoComment`**, which creates the comment by calling `s.CreateMemo` internally (`server/router/api/v1/memo_service_comments.go:56`).
2. **`UpdateMemo`**, but only on the `content` update mask path — `server/router/api/v1/memo_service.go:447`, right after `memo.Content = request.Memo.Content`; the recomputed payload is written back via `update.Payload = memo.Payload` (line 452). Other field paths (`visibility`, `pinned`, etc.) don't recompute.

Nothing else recomputes it: a batch rebuilder exists as `(*memopayload.Runner).RunOnce` (`server/runner/memopayload/runner.go:27`) but has no callers and its `Runner` is never constructed, so there is no periodic or migration-time refresh in the running server.

**What gets extracted** (`internal/markdown/markdown.go:371-411`):
- **`Tags`** — every `#tag` node, skipping tags nested inside links/images (`asMemoTagNode`, `internal/markdown/markdown.go:135`)
- **`Property.Title`** — text of the first block-level child if it's an H1 heading (lines 384-389)
- **`Property.HasLink`** — any `KindLink` node (line 394)
- **`Property.HasCode`** — any code block, fenced code block, or code span (lines 396-397)
- **`Property.HasTaskList`** — any task checkbox (line 400)
- **`Property.HasIncompleteTasks`** — any unchecked task checkbox (lines 401-405)

Field definitions: `MemoPayload_Property` at `proto/gen/store/memo.pb.go:85-95`.

`ExtractAll` also returns `Mentions` (line 380), but `RebuildMemoPayload` doesn't store those — mentions are consumed separately for notifications (`server/router/api/v1/memo_mention_helpers.go`).

**How it reaches lists/previews.** On read, the stored payload is copied straight onto the API message — `memoMessage.Tags = memo.Payload.Tags` and `memoMessage.Property = convertMemoPropertyFromStore(...)` at `server/router/api/v1/memo_service_converter.go:47-49` — so list responses never re-parse markdown. The same stored tags back the per-user tag stats at `server/router/api/v1/user_service_stats.go:138` and `:254`.
