Where the URL comes from: the API rewrites a stored base64 avatar into the path `/file/{user.Name}/avatar` — `server/router/api/v1/user_service_converters.go:36`.

Hops from browser to stored data:

```

```

Notes on each hop:

- **Route registration**: `RegisterRoutes` mounts the `/file` group (`fileserver.go:121-125`); it's wired at server startup in `server/server.go:81-82`.
- **`serveUserAvatar`** (`fileserver.go:168-210`): if the instance isn't public (`s.Profile.AllowAnonymous()` false) it requires a viewer via `s.getCurrentUser` and 401s otherwise (lines 173-181); reads `:identifier` (line 183); 404s on missing user or empty `AvatarURL` (lines 189-194).
- **No separate blob store**: the avatar is not a file on disk or in S3 — it's a base64 data URI stored in the `user.avatar_url` column. `parseDataURI` (`fileserver.go:737`, regex at `fileserver.go:98`) decodes it, the MIME type is checked against `avatarAllowedTypes` (`fileserver.go:75`, `:201`), and the bytes go out via `c.Blob` with security headers and `Cache-Control` (lines 205-209).
- **`getUserByUsername`** (`fileserver.go:715-717`) is a one-line pass-through: `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`.
- **`Store.GetUser`** (`store/user.go:148`) consults `userCache` only when looking up by ID; a username lookup always falls through to `ListUsers` (line 158) and then populates the cache (line 167).
- **`Store.ListUsers`** (`store/user.go:136-146`) delegates to `s.driver.ListUsers` and caches each result.
- **Data layer**: `DB.ListUsers` builds the `WHERE username = ?` clause and runs the `SELECT` that includes `avatar_url` (`store/db/sqlite/user.go:88`, query at lines 151-165, scanned into `user.AvatarURL` at line 189).
