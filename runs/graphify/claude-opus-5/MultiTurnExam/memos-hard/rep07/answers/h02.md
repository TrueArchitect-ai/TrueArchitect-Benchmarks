**Delivery: `webhook.Post` — `internal/webhook/webhook.go:120` (async wrapper `PostAsync` — `internal/webhook/webhook.go:184`); protection: SSRF guard at dial time via `safeDialContext`/`isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`, plus up-front `ValidateURL` — `internal/webhook/validate.go:62`.**

How it fits together:

- **Where delivery executes**: `Post` (`internal/webhook/webhook.go:120`) marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, lines 133–150), and issues the request with `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. Callers don't call it directly — memo changes call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which enqueues onto a bounded 128-slot channel (`webhook.go:39`) drained by 4 worker goroutines started in `init()` (`webhook.go:42-55`); a full queue drops the dispatch with a warning.
- **Primary protection (enforced at connect time)**: `safeClient` uses a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the host and refuses to dial if *any* resolved address is reserved, then dials the same host. Because the check happens per-dial rather than only at configuration time, it also defeats DNS rebinding — noted in the comment at `webhook.go:29-31`.
- **The blocklist**: `reservedCIDRs` in `internal/webhook/validate.go:14-23` covers IPv4 loopback, all three RFC-1918 ranges, link-local incl. cloud IMDS `169.254.0.0/16`, and IPv6 loopback/ULA/link-local; parsed once in `init()` (`validate.go:28`) and tested by `isReservedIP` (`validate.go:44`).
- **Secondary protection (at configuration time)**: `ValidateURL` (`internal/webhook/validate.go:62`) requires an absolute http/https URL that doesn't resolve to a reserved IP, returning a gRPC `InvalidArgument`. It runs when a user creates or updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.
- **Escape hatch**: the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted setups targeting LAN services. Nothing in non-test code sets it, so it defaults to `false` (protection on).
