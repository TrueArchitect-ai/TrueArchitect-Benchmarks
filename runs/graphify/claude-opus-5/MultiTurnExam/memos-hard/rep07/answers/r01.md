**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive grep for `redis` across all `.go` files returns zero hits, and `go.mod` has no Redis dependency (no `go-redis`, `redigo`, or similar). The cache layer is entirely in-process.

**Actual mechanism:**

- **Implementation**: a hand-rolled, thread-safe in-memory cache — `store/cache/cache.go`. `Cache` holds a `sync.Map` plus an atomic item counter (`store/cache/cache.go:66-72`); `New(config)` starts a background `cleanupLoop` goroutine (`store/cache/cache.go:74-83`).
- **Where it's configured**: `store.New` in `store/store.go:36-59`. The config is constructed inline, not read from any flag, env var, or config file:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  (`store/store.go:38-43`). Three caches are created from that same config — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:49-51`, fields declared at `store/store.go:26-28`). `cache.DefaultConfig()` (`store/cache/cache.go:56-63`) carries identical values but isn't what `store.New` calls.
- **TTL for user entries: 10 minutes**, inherited from `DefaultTTL`. Every user write uses the plain `Set` — `store/user.go:98`, `:122`, `:132`, `:143`, `:167` — and `Cache.Set` delegates to `SetWithTTL(ctx, key, value, c.config.DefaultTTL)` (`store/cache/cache.go:90-92`), stamping `expiration: time.Now().Add(ttl)` (`store/cache/cache.go:109`). `SetWithTTL` is never called directly for users, so there is no per-user override.
- **Eviction beyond TTL**: entries are also dropped when the cache exceeds `MaxItems: 1000` via `cleanupOldest()` (`store/cache/cache.go:115-117`), and the cleanup goroutine sweeps expired items every 5 minutes. Explicit invalidation happens on user deletion — `s.userCache.Delete(...)` at `store/user_delete.go:40`.
- **Scope caveat**: because this is per-process memory, the cache is not shared across replicas — two memos instances behind a load balancer each keep their own copy, with up to 10 minutes of staleness.
