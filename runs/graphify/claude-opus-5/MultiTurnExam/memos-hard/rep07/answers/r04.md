**Premise correction: neither. There is no message broker in this repository at all** — grepping all `.go` files for `nats`, `rabbit`, `amqp`, `kafka`, `pubsub`, and `sqs` returns zero hits, and `go.mod` declares no broker client dependency. There is no queue declaration to point at, because nothing external is involved.

**Actual mechanism — an in-process Go channel with a fixed worker pool, all in `internal/webhook/webhook.go`:**

- **The "queue"** is a package-level buffered channel holding 128 payloads:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  `internal/webhook/webhook.go:39` — declared in the same `var` block as the shared HTTP client, so it's created at package initialization.
- **The workers** are 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over the channel and calls `Post(payload)`, logging a warning on failure. There is no broker connection, no ack, and no consumer group.
- **The producer** is `PostAsync` (`internal/webhook/webhook.go:184-196`). It does a non-blocking `select` send: if the buffer is full, the `default` branch **drops the webhook** and logs `"Dropped webhook dispatch because the async queue is full"` (lines 189-195). A nil payload is likewise dropped (lines 185-188).
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120`), which signs the body with HMAC-SHA256 Standard Webhooks headers when a secret is set (lines 133-150) and issues the request via `safeClient.Do(req)` (line 152), with a 30-second timeout (`webhook.go:27`).
- **Producers** are the memo lifecycle dispatchers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

Consequences worth knowing, given the premise assumed a broker: this queue is **not durable** — pending webhooks are lost on process restart; there is **no retry** — a failed `Post` is logged and discarded; and in a multi-replica deployment each process has its own independent 128-slot queue and 4 workers, with no coordination between them.
