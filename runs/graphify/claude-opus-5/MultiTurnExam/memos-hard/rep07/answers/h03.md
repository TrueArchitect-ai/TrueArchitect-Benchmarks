**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation — OAuth2, the only concrete protocol that ships).**

Supporting detail:

- **Abstraction**: `internal/idp/idp.go` is the whole package — it defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider normalizes its user profile into. It's a data contract rather than a Go `interface`; there is no `interface` type in the package.
- **Implementation**: `internal/idp/oauth2/oauth2.go` — "Package oauth2 implements the OAuth2 identity provider integration" (line 1). It provides `IdentityProvider` wrapping a `storepb.OAuth2Config` (line 20), `NewIdentityProvider` with required-field validation (line 27), `ExchangeToken` with optional PKCE `code_verifier` support (line 47), and `UserInfo` returning `*idp.IdentityProviderUserInfo` (line 83).
- **Only one implementation**: `internal/idp/` contains just `idp.go` and the `oauth2/` subdirectory. The proto `oneof` for provider config has a single arm, `oauth2_config` — `proto/store/idp.proto:22-23` and `proto/api/v1/idp_service.proto:84-85`. (OIDC-style providers are handled through this same generic OAuth2 config rather than a separate package.)
- **Consumed at**: `server/router/api/v1/auth_service_sso.go:121-130`, which builds the provider from `identityProvider.Config.GetOauth2Config()`, exchanges the code, and fetches user info during SSO sign-in.
