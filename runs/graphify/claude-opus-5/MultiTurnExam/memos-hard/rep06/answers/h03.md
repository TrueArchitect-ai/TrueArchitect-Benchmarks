**`internal/idp` (abstraction) — `internal/idp/idp.go`; `internal/idp/oauth2` (implementation) — `internal/idp/oauth2/oauth2.go`.**

Details:

- **Abstraction**: `internal/idp/idp.go` is the whole package — it defines only the provider-neutral result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`). Note that it's a shared data contract, not a Go `interface`; there is no `IdentityProvider` interface type to implement. Concrete providers are selected by a type switch on `storepb.IdentityProvider_OAUTH2` in `server/router/api/v1/auth_service_sso.go:120`, and their job is to return this struct.
- **Implementation**: `internal/idp/oauth2` is the only concrete protocol that ships. `IdentityProvider` (`internal/idp/oauth2/oauth2.go:20`) wraps a `storepb.OAuth2Config`; `NewIdentityProvider` (`:27`) requires `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier`. `ExchangeToken` (`:47`) uses `golang.org/x/oauth2` and supports PKCE by passing `code_verifier` when supplied; `UserInfo` (`:83`) fetches the userinfo endpoint with a 10s timeout and maps claims into `idp.IdentityProviderUserInfo` via the configured field mapping, erroring if the identifier claim is missing.
- **Call site**: `resolveSSOIdentity` in `server/router/api/v1/auth_service_sso.go:104-134` constructs the OAuth2 provider, exchanges the code, fetches user info, then applies the optional `IdentifierFilter` regex; `resolveSSOUser` (`:19`) maps that to a local user.

The proto enum backing this (`storepb.IdentityProvider_Type`) confirms OAuth2 is the sole non-unspecified variant, so no OIDC/SAML/LDAP provider exists in this tree.
