**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` — six in total. Convergence function: `webhook.Post` — `internal/webhook/webhook.go:120` (the actual send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`).**

The last three of those share `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `memo_update_helpers.go:67`.

**Convergence.** All four `Dispatch*Webhook` methods (`server/router/api/v1/memo_service_webhooks.go:15,20,25,30`) funnel into `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`) — except the comment variant, which inlines the same loop — where the target comes from `s.Store.GetUserWebhooks(...)` and `payload.URL = hook.Url`, i.e. the user-configured URL. Both loops call `webhook.PostAsync` (`memo_service_webhooks.go:43` and `:71`), which only enqueues onto a bounded channel (`internal/webhook/webhook.go:184`). The four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) then call `webhook.Post` — the single function where every path converges before delivery.

Two notes on scope: `dispatchMemoRelatedWebhook` resolves the webhook list from the *memo creator*, so these fire on the creator's configured endpoints. Separately, `CreateUserWebhook`/`UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:74,161,182`) perform a DNS resolution of the URL via `webhook.ValidateURL` but issue no HTTP request, so I've excluded them. `GetLinkMetadata` does make an outbound fetch via `httpgetter.GetHTMLMeta` (`server/router/api/v1/memo_service.go:28`), but to a URL supplied per-request rather than a configured webhook target, and it does not pass through `webhook.Post`.
