**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive search for `redis` across all Go sources, `go.mod`, YAML, and Markdown returns zero hits. The cache layer is a hand-rolled, in-process, in-memory cache — nothing external, no connection to configure, and no persistence across restarts or sharing between instances.

**Actual mechanism:**

- **Implementation**: `store/cache/cache.go` — a `Cache` struct backed by a `sync.Map` plus an atomic item counter (`store/cache/cache.go:66-72`), satisfying the `cache.Interface` contract (`store/cache/cache.go:11-32`). Each `item` carries a `value`, an `expiration` time, and an approximate size (`:34-38`). A background goroutine started in `cache.New` sweeps expired entries and is torn down by `Close` (`store/cache/cache.go:187`).
- **"Configuration"**: `cache.Config` (`store/cache/cache.go:41-54`) with `DefaultTTL`, `CleanupInterval`, `MaxItems`, and an optional `OnEviction` hook. There are no flags, env vars, or config-file keys for it — the values are hardcoded at `store.New` (`store/store.go:39-44`): **DefaultTTL 10 minutes, CleanupInterval 5 minutes, MaxItems 1000**. `cache.DefaultConfig()` (`store/cache/cache.go:56-63`) declares the same values but isn't what the store uses.
- **Three caches, one shared config**: `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:26-28`), each constructed with that same `cacheConfig` (`store/store.go:50-52`) and closed on shutdown (`store/store.go:74-76`).

**TTL on user entries: 10 minutes** — the `DefaultTTL` from `store/store.go:41`. Every user write path uses plain `Set`, which applies the default TTL rather than a per-entry one; `SetWithTTL` is never called for users. The write sites are `store/user.go:98`, `:122`, `:132`, `:143`, and `:167`, all keyed by `userCacheKey(user.ID)` (`store/user.go:88`). Invalidation is otherwise explicit: `store/user_delete.go:40` deletes the entry on user deletion.

One caveat on effective behavior: the read path only consults the cache when looking up by ID (`store/user.go:149-156`), so lookups by username or email always hit the database regardless of the TTL.
