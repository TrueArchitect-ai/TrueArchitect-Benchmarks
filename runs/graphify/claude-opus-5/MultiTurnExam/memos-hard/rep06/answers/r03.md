**Premise correction: there is no nightly database-cleanup job, and no cron schedule for one.** Nothing in the server registers any cron job at all, so there is no time to report.

Evidence:

- **The cron scheduler exists but is never used by the server.** `internal/scheduler` is a complete, self-contained cron package — `Scheduler` with `Register`/`Start`/`Stop` (`internal/scheduler/scheduler.go:54`, `:68`, `:96`, `:167`), a 5-field cron parser (`internal/scheduler/parser.go:14`), `Job` definitions with validation (`internal/scheduler/job.go`), and timezone/middleware options. But the only files that import it are its own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No production code constructs a `Scheduler` or calls `Register`, so zero jobs are scheduled.
- **The `daily-cleanup` name in the repo is documentation, not a job.** `internal/scheduler/doc.go:15-18` shows a package usage example with `Name: "daily-cleanup"` and the comment `// Your cleanup logic here`. That's a doc comment illustrating the API — likely what the question is recalling — not a registered job.
- **Background work is ticker-based, not cron-based.** The only recurring server task is the S3 presign runner: `startBackgroundRunners` (`server/server.go:153`) runs it once at startup (`server/server.go:163`) and then on a `time.Ticker` every 12 hours (`server/runner/s3presign/runner.go:27,29-41`). It refreshes presigned attachment URLs — it does not clean up the database.
- **Cleanup that does exist is event-driven, not scheduled.** Row removal happens inline on user deletion inside a transaction (`store/db/sqlite/user_delete.go:89`, and the mysql/postgres equivalents) and on memo deletion (`server/router/api/v1/memo_service.go:579`); S3/local object cleanup follows a delete request (`store/attachment.go:171`, `server/router/api/v1/user_service.go:421-450`). The only periodic "cleanup" is the in-memory cache's expiry sweep — `cleanupLoop` at `store/cache/cache.go:199-210`, running on the 5-minute `CleanupInterval` from `store/store.go:42` — which touches no database.
