**`webhook.Post` — `internal/webhook/webhook.go:120` (executing the request at line 152 via the shared `safeClient`); SSRF protection via the client's custom `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44` (with an admission-time check in `webhook.ValidateURL`, `internal/webhook/validate.go:62`).**

How it fits together:

**Delivery path**
- Memo events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which only enqueues onto a bounded 128-slot channel and drops with a warning when full (`internal/webhook/webhook.go:184-196`).
- Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`.
- `Post` (`internal/webhook/webhook.go:120`) marshals the payload, attaches Standard-Webhooks HMAC-SHA256 headers when a signing secret is set (`:133-150`), and performs the actual outbound call at `internal/webhook/webhook.go:152` with `safeClient.Do(req)`. Response reading is capped at 1 MiB (`:158`) and the client timeout is 30s (`:27,33`).

**Protection**
- The two-layer defense is anchored at dial time. `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`), which re-resolves the hostname and refuses the connection if *any* resolved address is reserved (`internal/webhook/webhook.go:59-77`). Because this runs per-dial rather than at URL-save time, it also defeats DNS rebinding.
- `isReservedIP` (`internal/webhook/validate.go:44`) tests against `reservedNetworks`, parsed once at startup from `reservedCIDRs` (`internal/webhook/validate.go:14-36`): IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), and the IPv6 equivalents `::1/128`, `fc00::/7`, `fe80::/10`.
- A second, earlier layer rejects bad URLs at configuration time: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) enforces http/https and non-reserved resolution, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`.

One caveat worth flagging: the whole mechanism can be turned off globally by the `webhook.AllowPrivateIPs` toggle (`internal/webhook/validate.go:41`) — when true, `isReservedIP` returns false unconditionally. I grepped for writes to it and found none outside its declaration and the tests, so in this tree there is no CLI flag or config path that sets it; it is an exported var defaulting to `false`.
