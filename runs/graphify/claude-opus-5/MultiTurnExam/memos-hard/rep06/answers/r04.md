**Premise correction: neither. There is no message broker in this repository at all** — a case-insensitive search for `nats`, `rabbitmq`, `amqp`, `kafka`, and `pubsub` across all Go sources, `go.mod`, and `go.sum` returns zero hits. There is no external queue, so nothing is declared anywhere.

**Actual mechanism — an in-process buffered Go channel:**

- **The "queue"** is a package-level channel declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`. It's a plain buffered channel holding 128 payloads, local to the server process. Nothing is persisted — a restart or crash drops whatever is in flight.
- **The workers** are four goroutines started in that package's `init()` (`internal/webhook/webhook.go:42-55`). Each loops with `for payload := range asyncPostQueue` and calls `Post(payload)`, logging a warning via `slog.Warn` on failure. There's no retry, no dead-letter path, and no acknowledgement — a failed delivery is logged and discarded.
- **The producer** is `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking `select` send: if the buffer is full it takes the `default` branch and logs `"Dropped webhook dispatch because the async queue is full"` (`:191-195`). So backpressure is handled by dropping, not blocking. It also guards against a nil payload at `:185-188`.
- **Enqueue sites** are the memo webhook dispatchers: `server/router/api/v1/memo_service_webhooks.go:43` (comment-created) and `:71` (created/updated/deleted), reached from the `CreateMemo`/`UpdateMemo`/`DeleteMemo`/`CreateMemoComment`/`SetMemoAttachments`/`SetMemoRelations` handlers.
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120`), which signs the body with HMAC-SHA256 Standard Webhooks headers when a secret is configured (`:133-150`) and issues the request via the SSRF-guarded `safeClient` at `:152`.

Practical implication: because the queue is an in-memory channel scoped to one process, webhook delivery is at-most-once and not shared across replicas — each server instance dispatches only for the requests it handled.
