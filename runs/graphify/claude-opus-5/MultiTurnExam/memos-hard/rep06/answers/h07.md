The URL the browser hits is `/file/users/{username}/avatar`, which the API hands out in place of raw base64 (`server/router/api/v1/user_service_converters.go:36`). Hops:

```

serveUserAvatar — server/router/fileserver/fileserver.go:168

Store.GetUser — store/user.go:148
Store.ListUsers — store/user.go:136
driver.ListUsers (store.Driver iface) — store/db/sqlite/user.go:88 (also store/db/mysql/user.go:147, store/db/postgres/user.go:150)
```

Details per hop:

- **Route** — `RegisterRoutes` mounts the `/file` group and binds the avatar path (`server/router/fileserver/fileserver.go:121-125`). The service is constructed and wired at `server/server.go:81-82`.
- **`serveUserAvatar`** (`fileserver.go:168`) — first gates access: if the instance isn't public (`!s.Profile.AllowAnonymous()`), it requires a viewer via `s.getCurrentUser` and returns 401 otherwise (`:173-181`). Then it reads the `:identifier` path param (`:183`).
- **`getUserByUsername`** (`fileserver.go:715`) — a one-line adapter that builds `&store.FindUser{Username: &identifier}`. Note the lookup is by **username**, not user ID.
- **`Store.GetUser`** (`store/user.go:148`) — the caching layer. Its `userCache` fast path only applies when `find.ID` is set (`:149-156`), so an avatar request by username always falls through to the database; the result is then written back into the cache keyed by ID (`:167`).
- **`Store.ListUsers`** (`store/user.go:136`) — delegates to `s.driver.ListUsers` and populates the cache for each row (`:137-144`).
- **Driver** — the dialect-specific `ListUsers` builds the `WHERE username = ?` clause and selects `avatar_url` among the columns: `store/db/sqlite/user.go:88` (column list at `:159`), `store/db/mysql/user.go:147`, `store/db/postgres/user.go:150`. The driver is chosen by `NewDBDriver` (`store/db/db.go:14`).

**Where the bytes come from:** the image is not a file on disk or in object storage — it's stored inline in the `user.avatar_url` column as a data URI. After the store returns, `serveUserAvatar` decodes it with `parseDataURI` (`fileserver.go:737`), rejects anything outside `avatarAllowedTypes` (`fileserver.go:75`, checked at `:201`), sets security and cache headers, and writes the decoded bytes with `c.Blob` (`fileserver.go:209`).
