**Premise correction: there is no per-user API rate-limiting middleware in this repository.** Nothing is registered, and there are no request limits to report.

What I checked:

- A case-insensitive search for `rate limit`, `ratelimit`, `throttle`, `RateLimiter`, and the usual dependency `golang.org/x/time/rate` across all Go sources and `go.mod` returns **zero hits**. Echo's own `middleware.RateLimiter` is never referenced either.
- The complete global middleware chain is two entries, registered in `NewServer`: `middleware.Recover()` (`server/server.go:51`) and `newCORSMiddleware(profile)` (`server/server.go:52`, defined in `server/cors.go:14`). Nothing else is added via `echoServer.Use`.
- The Connect interceptor chain (`server/router/api/v1/connect_interceptors.go`) consists of `MetadataInterceptor` (`:22`), `LoggingInterceptor` (`:98`), and `RecoveryInterceptor` (`:164`) — header translation, logging, and panic recovery. No limiter.
- The gRPC-Gateway path is wrapped only by the shared authorizer (`server/router/api/v1/v1.go:95` and the `NewAuthorizer` middleware around it), which does authentication/authorization, not throttling.

**What exists instead — concurrency caps, not rate limits.** These bound how many operations run *simultaneously* process-wide; they don't cap requests per user over time, and they don't reject based on request frequency:

- `imageProcessingSemaphore` — `semaphore.NewWeighted(2)` at `server/router/api/v1/v1.go:60`. This is the only one that rejects rather than queues: it returns `codes.ResourceExhausted, "too many image processing requests"` at `server/router/api/v1/attachment_service.go:160`.
- `thumbnailSemaphore` — `semaphore.NewWeighted(3)` at `server/router/api/v1/v1.go:59`, and a second one in the file server at `server/router/fileserver/fileserver.go:116` (`maxConcurrentThumbnails`).

Adjacent per-request limits that are size- rather than rate-based: memo content length is enforced per instance setting (`server/router/api/v1/memo_service.go:100-106`, `:439-444`), the webhook async queue is bounded at 128 with drop-on-full (`internal/webhook/webhook.go:39`, `:189-195`), and RSS feeds cap items at `maxRSSItemCount` (`server/router/rss/rss.go:88`).

If per-user rate limiting is needed, it would have to be added — most naturally as an Echo middleware alongside `server/server.go:51-52`, or as a Connect interceptor in `server/router/api/v1/connect_interceptors.go`.
