**No.** `mysql.NewDB` is called from exactly one place in the entire codebase — the driver-selection factory — and the `store/db/mysql` package is imported by nothing else.

Evidence:

1. **Single call site.** Grepping for `NewDB` across all `.go` files yields one call to the MySQL constructor: `store/db/db.go:22`, inside the `case "mysql":` arm of `NewDBDriver` (`store/db/db.go:14-27`). The constructor itself is declared at `store/db/mysql/mysql.go:20`.

2. **Single import of the package.** The only file outside `store/db/mysql/` that imports `github.com/usememos/memos/store/db/mysql` is `store/db/db.go:8`. No production file, test file, or `cmd/` entry point imports it.

3. **No struct-literal back door.** Grepping for `mysql.DB` / `&mysql.` outside `store/db/mysql/` returns nothing, so the driver isn't being constructed by bypassing `NewDB` either.

4. **The one look-alike is unrelated.** `store/test/containers.go` mentions `mysql` heavily, but those are two different packages: `github.com/testcontainers/testcontainers-go/modules/mysql` (`store/test/containers.go:20`, used for `mysql.Run` at `:101` to spin up a `mysql:8` container) and `github.com/go-sql-driver/mysql` aliased as `mysqldriver` (`:16`). Neither is the repo's own driver package.

5. **Tests go through the factory too.** The test harness builds drivers via `db.NewDBDriver(profile)` (`store/test/store.go:28`, `:50`; `server/router/api/v1/test/memo_service_benchmark_test.go:70`), selecting MySQL by setting `profile.Driver`. The only constructor bypasses anywhere are for SQLite (`store/deployment_config_test.go:416`, `store/demo_seed_test.go:24`), not MySQL.
