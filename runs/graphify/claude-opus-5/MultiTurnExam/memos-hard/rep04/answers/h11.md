**1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages).**

Method: I enumerated the exported entity structs declared in `store/*.go` (`User`, `Memo`, `Attachment`, `Reaction`, `Inbox`, `MemoRelation`, `MemoShare`, `UserIdentity`, `IdentityProvider`, `UserSetting`, `InstanceSetting` — the `Find*`/`Update*`/`Delete*` structs are query DTOs, not entities), then counted the distinct packages referencing each as `store.<Type>`, excluding everything under `store/` (the package itself plus the `store/db/*` drivers and `store/test` harness, which are all part of the data layer).

**`store.User` — 7 packages** (`store/user.go`):
`server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`.
Heaviest single files: `server/router/api/v1/user_service.go` (8 refs), `server/auth/authenticator.go` (6), `server/router/api/v1/user_service_notifications.go` and `memo_service_converter.go` (5 each), `server/notification/email.go` (5). It's the only entity that reaches the auth layer — `server/auth/authenticator.go` and `server/auth/context.go` both traffic in `*store.User`.

**`store.Memo` — 6 packages** (`store/memo.go`):
`server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`.
Heaviest: `server/notification/email.go` (10 refs), `server/router/api/v1/user_service_notifications.go` and `memo_service_converter.go` (5 each). It's the only entity referenced from a background runner (`server/runner/memopayload/runner.go`), but it's absent from `server/auth` and `server/router/fileserver`, which is what puts it one package behind `User`.

The ranking is stable if you exclude test-only packages: `User` drops to 6 and `Memo` to 5, same order. Next closest is `store.Attachment` at 4 packages (`server/router/api/v1`, its test package, `server/router/fileserver`, `server/router/rss`), so there's a clear gap below the top two.

One measurement caveat: the `proto/gen/store` package is also named `store`, so a bare `store.<Type>` grep produces a few self-referential hits there for `UserSetting`, `InstanceSetting`, and `IdentityProvider`. Those are protobuf types, not the data-layer entities, and don't affect the top two.
