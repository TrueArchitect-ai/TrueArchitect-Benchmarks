**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoRelations`, `SetMemoAttachments` — all six on `APIV1Service`. Convergence function: `webhook.PostAsync` — `internal/webhook/webhook.go:184` (which hands off to `webhook.Post`, `internal/webhook/webhook.go:120`, where the request is actually issued).**

The six paths:

| RPC handler | Declared at | Reaches webhook via |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:70` | `DispatchMemoCreatedWebhook` (`memo_service.go:157`) |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:518` | `DispatchMemoDeletedWebhook` (`memo_service.go:562`) |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:401` | `dispatchMemoUpdatedSideEffects` (`memo_service.go:513`) |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`) |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:16` | `dispatchMemoUpdatedSideEffects` (`memo_relation_service.go:48`) |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:16` | `dispatchMemoUpdatedSideEffects` (`memo_attachment_service.go:48`) |

The last three share the intermediate hop `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `:67` — so editing a memo, re-linking its relations, or changing its attachments all fire the same `memos.memo.updated` event.

**Convergence.** All four `Dispatch*Webhook` helpers live in `server/router/api/v1/memo_service_webhooks.go`; each loads the target user's webhooks via `s.Store.GetUserWebhooks` and calls `webhook.PostAsync` — at `memo_service_webhooks.go:43` (comment-created) and `:71` (the generic memo path used by created/updated/deleted). `PostAsync` is the single funnel: it enqueues onto the 128-slot `asyncPostQueue` (`internal/webhook/webhook.go:189-195`), and four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it into `Post`, which performs the actual `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. The URL is user-configured — it comes from the memo creator's stored webhook records (`hook.Url`, `memo_service_webhooks.go:41`, `:67`), registered through `server/router/api/v1/user_service_webhooks.go`.

One caveat on scope: if you count admin-configured rather than end-user-configured URLs, two more handlers make outbound HTTP — the SSO sign-in paths at `server/router/api/v1/auth_service.go:80` and `server/router/api/v1/user_service_identities.go:56`, which call `resolveSSOIdentity` (`server/router/api/v1/auth_service_sso.go:104`) and hit the identity provider's `tokenUrl`/`userInfoUrl` (`internal/idp/oauth2/oauth2.go:68`, `:91`). Those don't pass through `PostAsync`.
