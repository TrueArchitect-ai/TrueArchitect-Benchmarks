**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP POST is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); SSRF protection is `safeDialContext` / `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

How it fits together:

**Delivery path.** Memo create/update/delete and comment-created events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43`, `:71`), which only enqueues onto a bounded 128-slot channel `asyncPostQueue` (`internal/webhook/webhook.go:39`, `:184-196`) — dropping with a warning when full. Four goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, which marshals the payload, adds Standard-Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`) when a signing secret is set (`internal/webhook/webhook.go:133-150`), and performs the request.

**Protection — two layers:**

1. **Dial-time (the enforcing one).** All dispatches share `safeClient`, whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). It resolves the hostname itself and refuses the connection if *any* returned IP is reserved (`internal/webhook/webhook.go:59-77`). Because the check happens at dial time on every request, it also defeats DNS rebinding and redirect-based bypasses. Blocked ranges are the parsed `reservedCIDRs` list — IPv4 loopback, all three RFC-1918 blocks, 169.254.0.0/16 (cloud IMDS), plus `::1/128`, `fc00::/7`, `fe80::/10` (`internal/webhook/validate.go:14-36`).

2. **Registration-time.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames with `InvalidArgument` when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`). This is a UX guard only — it's TOCTOU-racy against DNS, which is why layer 1 exists.

**One caveat worth flagging:** the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` and thus disables *both* layers. It defaults to `false`, and grepping the repo it is never assigned outside of `internal/webhook/` itself — no CLI flag, env var, or config field sets it in production code, so it's currently reachable only from tests.
