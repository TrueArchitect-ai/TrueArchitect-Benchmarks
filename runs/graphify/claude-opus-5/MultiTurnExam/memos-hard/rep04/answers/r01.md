**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive search for "redis" across all Go sources, `go.mod`, `go.sum`, and JSON/YAML config files returns zero hits. There is no external cache server, no connection string, no client library — so there's nothing to configure.

**Actual mechanism: a process-local in-memory cache.** `store/cache/cache.go` implements `Cache` as a `sync.Map` with per-item expiry timestamps and an atomic item counter (`store/cache/cache.go:66-73`). It's created directly in `store.New` — no configuration file, no flags, no env vars:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
— `store/store.go:39-45`. Three independent instances are built from it: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:49-51`, fields declared `:27-29`).

**TTL for user entries: 10 minutes.** Every write to the user cache goes through `Set`, which applies `c.config.DefaultTTL` (`store/cache/cache.go:93-95`) — the `SetWithTTL` override exists on the interface (`store/cache/cache.go:16`) but is never called anywhere in the codebase, so user entries always get the 10-minute default. Write sites are `store/user.go:98`, `:122`, `:132`, `:143`, `:167`, all keyed by `userCacheKey(user.ID)` (`store/user.go:88`).

Supporting behaviour worth knowing:

- **Expiry is lazy plus swept.** `Get` checks `time.Now().After(itm.expiration)` and evicts on read (`store/cache/cache.go:135-144`); a background `cleanupLoop` ticks every 5 minutes to sweep expired entries (`:200-215`, `:218-250`). The goroutine is stopped by `Cache.Close`, called from `Store.Close` (`store/store.go:74-76`).
- **Capacity eviction.** Exceeding `MaxItems: 1000` triggers `cleanupOldest`, which drops roughly 20% of capacity (`store/cache/cache.go:117-119`, `:253-313`).
- **Explicit invalidation on delete.** `deleteUserCache` removes the user entry plus its settings entries (`store/user_delete.go:39-47`).
- **Lookup caveat.** `Store.GetUser` only consults the cache when querying by ID (`store/user.go:149-156`); lookups by username or email always hit the database.

Because the cache lives in the process heap, it is not shared across instances — running multiple memos replicas would give each its own copy with independent 10-minute staleness windows.
