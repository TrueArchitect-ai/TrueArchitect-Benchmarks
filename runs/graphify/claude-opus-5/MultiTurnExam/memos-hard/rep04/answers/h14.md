**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: `CreateMemo` and `UpdateMemo` (content-path only). Extracted: `tags[]` plus the `Property` set — `title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`.**

**Where it's computed.** `RebuildMemoPayload` initialises `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, and assigns the two derived fields onto the memo before it's persisted:

```go
memo.Payload.Tags = data.Tags       // server/runner/memopayload/runner.go:85
memo.Payload.Property = data.Property // :86
```

`ExtractAll` does it in a single goldmark AST walk (`internal/markdown/markdown.go:356-421`) — deliberately one pass rather than separate tag/property traversals.

**Triggers — exactly two, both in `server/router/api/v1/memo_service.go`:**

1. `CreateMemo` — `:107-109`, after the content-length check and before `Store.CreateMemo` at `:114`. Note `Payload.Location` is set *after* the rebuild (`:110-112`), since location is user-supplied, not derived.
2. `UpdateMemo` — `:447`, but only inside the `if path == "content"` branch of the update-mask loop (`:436-453`), with the result written to `update.Payload` at `:452`. Changing visibility, pinning, or any other field does **not** recompute — correct, since nothing else affects the derived values.

There is no third trigger. `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) exists to bulk-rebuild every memo's payload, but as established it's dead code — `NewRunner` is never called, so backfill never runs. Consequently the stored payload only ever refreshes when a memo's content is created or edited.

**What's extracted** (per the `MemoPayload` schema, `proto/store/memo.proto:7-22`):

- `tags` (field 3) — every `#tag` node collected during the walk, then deduplicated with case preserved (`internal/markdown/markdown.go:417`).
- `Property.title` — the text of the document's *first* block-level child only if it is an H1 (`internal/markdown/markdown.go:383-389`); a heading later in the document does not count.
- `Property.has_link` — any `KindLink` node.
- `Property.has_code` — any code block, fenced code block, or inline code span.
- `Property.has_task_list` — any task checkbox; and `Property.has_incomplete_tasks` when at least one checkbox is unchecked (`internal/markdown/markdown.go:392-405`).

`ExtractAll` also returns `Mentions`, but `RebuildMemoPayload` discards that — mentions are handled separately in `server/router/api/v1/memo_mention_helpers.go:32`.

**Consumers.** The stored values are attached to API responses at `server/router/api/v1/memo_service_converter.go:48-49` (via `convertMemoPropertyFromStore`, `:315`) and aggregated for user statistics at `server/router/api/v1/user_service_stats.go:138-151` and `:254-267`.

One adjacent thing that is *not* stored: the list/preview `snippet` is derived at response time, not persisted — `getMemoContentSnippet` is called per memo during conversion (`server/router/api/v1/memo_service_converter.go:76-80`, and in the batch path at `:225`/`:248`) and runs `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:85`).
