Notes on the hops:

- **Hop 2 is conditional.** If `s.Profile.AllowAnonymous()` is false (no `InstanceURL` configured — a private instance), the handler requires a valid session/access token/PAT before touching the store (`fileserver.go:171-179`); otherwise avatars are public and this hop is skipped.
- **Hop 3 → 4** passes `&store.FindUser{Username: &identifier}` — the path segment is treated as a username, not an ID.
- **Hop 4's cache is bypassed here.** `Store.GetUser` only consults `s.userCache` when `find.ID != nil` (`store/user.go:149-156`); a username lookup always falls through to `ListUsers` and hits the DB. The result is then written into the cache keyed by ID (`store/user.go:145`, `:167`).
- **The image is not a file or an attachment row.** It's stored inline on the `user` table's `avatar_url` column as a data URI; `parseDataURI` (`fileserver.go:737`) regex-splits it into MIME type and base64-decoded bytes. So "the data layer" for avatars terminates in the `user` row itself — no blob table, filesystem, or S3 hop is involved.
- **Between hops 8 and 9** the handler enforces `avatarAllowedTypes` (`fileserver.go:75`, checked at `:201`) and sets security headers plus `Cache-Control` (`:205-206`).
