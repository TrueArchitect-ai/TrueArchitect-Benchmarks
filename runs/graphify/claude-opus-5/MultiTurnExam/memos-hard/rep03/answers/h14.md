**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: memo create and content-updating memo update (and comment creation transitively). Extracted: `Tags` plus a `Property` struct of `Title`, `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks`.**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) ensures `memo.Payload` is non-nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`. The real work is a single goldmark AST walk in `ExtractAll` (`internal/markdown/markdown.go:356-420`) — one parse producing everything, rather than a pass per field. The payload is persisted on the memo row (JSON-marshalled at `store/db/sqlite/memo.go:21-26`).

**What it extracts** (`internal/markdown/markdown.go:376-419`, target type at `proto/gen/store/memo.pb.go:85-95`):

- `Tags` — every `#tag` node, deduplicated with original case preserved (`markdown.go:417`).
- `Property.Title` — text of the first block-level child *only if* it's an H1 heading (`markdown.go:383-389`).
- `Property.HasLink` — any `KindLink` node.
- `Property.HasCode` — any code block, fenced code block, or inline code span.
- `Property.HasTaskList` — any GFM task checkbox.
- `Property.HasIncompleteTasks` — a task checkbox that is unchecked (`markdown.go:400-404`).

`ExtractAll` also collects `Mentions` (lowercased), but `RebuildMemoPayload` does *not* store those — mentions are consumed separately for notifications via `server/router/api/v1/memo_mention_helpers.go:32`.

**Triggers.** Exactly two call sites, both in the memo service:

1. `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`.
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the `if path == "content"` branch of the update mask; the recomputed payload is then attached to the update at `:450`. Updates that touch only visibility, pinned state, etc. leave the payload untouched.
3. Transitively, `CreateMemoComment` — it delegates to `s.CreateMemo` at `server/router/api/v1/memo_service_comments.go:56`, so comments get the same treatment.

A third potential trigger exists but is dead: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) batch-rebuilds payloads for all memos, and neither it nor `NewRunner` has any caller — so there is no backfill path if extraction logic changes.

**Related but distinct — the snippet.** `Memo.Snippet` is also derived from content but is *not* persisted: it's computed on read during conversion, `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-85`), called from `server/router/api/v1/memo_service_converter.go:76` and, for list responses, `:225` gated on `includeSnippets`. So previews use payload fields (persisted) plus a snippet recomputed per request.
