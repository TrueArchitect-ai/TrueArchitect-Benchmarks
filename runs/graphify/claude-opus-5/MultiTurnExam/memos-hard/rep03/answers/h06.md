**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` (all on `APIV1Service`). Convergence function: `webhook.PostAsync` — `internal/webhook/webhook.go:184`.**

The six RPC handlers and their routes to the webhook layer:

| Handler | Definition | Path to dispatch |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:70` | → `DispatchMemoCreatedWebhook` (`memo_service.go:157`) |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:518` | → `DispatchMemoDeletedWebhook` (`memo_service.go:562`) |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:401` | → `dispatchMemoUpdatedSideEffects` (`memo_service.go:513`) |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:20` | → `DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`) |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:16` | → `dispatchMemoUpdatedSideEffects` (`memo_attachment_service.go:48`) |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:16` | → `dispatchMemoUpdatedSideEffects` (`memo_relation_service.go:48`) |

The last three of those flow through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `:67` (and also broadcasts an SSE event).

The four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go:15-27` and `:29`. Three of them funnel through `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:47`), while the comment-created path builds its payload inline (`:29-45`) — so `dispatchMemoRelatedWebhook` is *not* the common point.

**Convergence.** All six handlers meet at `webhook.PostAsync` (`internal/webhook/webhook.go:184`), reached from exactly two call sites: `server/router/api/v1/memo_service_webhooks.go:43` (comment path) and `:71` (created/updated/deleted path). `PostAsync` enqueues onto the bounded `asyncPostQueue`; four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it and call `webhook.Post` (`internal/webhook/webhook.go:120`), where the actual `safeClient.Do(req)` happens at `:152`.

The URL is user-configured — each payload's `URL` comes from the memo creator's stored webhooks via `s.Store.GetUserWebhooks` (`memo_service_webhooks.go:31`, `:57`), set through the user-webhook RPCs in `server/router/api/v1/user_service_webhooks.go`. That's also why the SSRF guard sits at dial time in `safeDialContext` (`internal/webhook/webhook.go:59`) rather than only at configuration time.
