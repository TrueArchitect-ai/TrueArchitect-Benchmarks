**Premise correction: there is no Redis in this repository.** A case-insensitive grep for `redis` across all Go sources, `go.mod`, YAML, and Markdown (excluding `web/`) returns zero hits — no client dependency, no connection string, no config flag. The cache layer is a hand-rolled, in-process, in-memory cache with no external service and no network configuration at all.

**Actual mechanism.**

The implementation is `store/cache/cache.go`: a `Cache` struct backed by a `sync.Map` plus an atomic item counter (`store/cache/cache.go:66-72`), created by `cache.New(config)` which also spawns a background `cleanupLoop` goroutine (`store/cache/cache.go:76-86`).

Configuration is code-level, not deployment-level. `store.New` builds one `cache.Config` literal and hands the *same* values to three separate cache instances (`store/store.go:39-53`):

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

The three caches are `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`, constructed at `:50-52`). An identical default set also exists as `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), though `store.New` inlines its own copy rather than calling it.

**TTL for user entries: 10 minutes.** Every write to the user cache goes through `Set` — `store/user.go:98`, `:122`, `:132`, `:143`, `:167` — and `Set` delegates to `SetWithTTL` using `c.config.DefaultTTL` (`store/cache/cache.go:92-95`), which for this instance is the 10 minutes from `store/store.go:41`. No user-cache call site uses `SetWithTTL` with a custom duration, so there is no per-entry override. Expiration is stamped at write time as `time.Now().Add(ttl)` (`store/cache/cache.go:112`), with the sweeper running every 5 minutes.

Two practical consequences worth noting: the cache is per-process, so a multi-replica deployment has no shared invalidation; and `Store.GetUser` only consults `userCache` when looking up by ID — username lookups always hit the database (`store/user.go:149-156`).
