**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); SSRF protection is the custom dialer `safeDialContext` — `internal/webhook/webhook.go:59`, backed by the reserved-CIDR check `isReservedIP` in `internal/webhook/validate.go:44`.**

How the pieces fit:

**Delivery path**
- Dispatch is enqueued, not sent inline: `webhook.PostAsync` (`internal/webhook/webhook.go:184`) pushes onto a bounded 128-slot channel `asyncPostQueue` and drops (with a warning) when full.
- Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post`.
- Callers are the memo webhook dispatchers in `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (memo created/updated/deleted and comment-created events).
- `Post` marshals the payload, optionally signs it with HMAC-SHA256 in the Standard Webhooks format (`webhook-id` / `webhook-timestamp` / `webhook-signature` headers, `internal/webhook/webhook.go:133-150`), then sends via the shared `safeClient` (30s timeout) and reads at most 1 MiB of response.

**Protection**
- `safeClient`'s `http.Transport` uses `DialContext: safeDialContext` (`internal/webhook/webhook.go:32-37`). At dial time it resolves the host and rejects the connection if *any* resolved IP is in a reserved range (`internal/webhook/webhook.go:59-77`). Doing this at dial time rather than at URL-parse time is what defeats DNS rebinding — the check applies to the address actually connected to, including after redirects.
- The blocklist is `reservedCIDRs` in `internal/webhook/validate.go:14-23`: IPv4 loopback, all three RFC-1918 ranges, link-local (`169.254.0.0/16`, covering cloud IMDS at 169.254.169.254), plus IPv6 loopback, ULA, and link-local. Parsed once into `reservedNetworks` at init.
- A second, earlier layer validates URLs at configuration time: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) enforces http/https scheme and non-reserved resolution, called when users create/update webhooks in `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.
- Both layers can be disabled by the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`), intended for self-hosted deployments targeting LAN services. Note: in this working tree that variable is only ever set from tests — I found no non-test code assigning it, so it is effectively always `false` at runtime. `CHANGELOG.md:121` references an `--allow-private-webhooks` flag, but no such flag wiring exists in `cmd/` on the current branch.
