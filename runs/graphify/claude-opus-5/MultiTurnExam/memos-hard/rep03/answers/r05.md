**Premise correction: there is no GraphQL in this repository.** Grepping for `graphql`, `gqlgen`, `.graphql`, and `.gql` across Go, `go.mod`, JSON, and TypeScript sources (excluding `node_modules`) returns zero hits, and a filesystem search for `*.graphql`/`*.gql` files finds none. There is no schema file, resolver layer, or GraphQL endpoint.

**Actual API surface: Protocol Buffers / gRPC, exposed three ways from one set of `.proto` definitions.**

**Schema definitions** — `proto/api/v1/`, nine service files: `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, and shared `common.proto`. Store-side messages live in `proto/store/`.

**Code generation** — driven by buf (`proto/buf.gen.yaml`), which runs five plugins into `proto/gen/`: protobuf-go messages, gRPC stubs, ConnectRPC handlers (`proto/gen/api/v1/apiv1connect/`), grpc-gateway REST shims (`*.pb.gw.go`), and a gnostic-generated OpenAPI spec. A sixth plugin emits TypeScript clients into `web/src/types/proto`.

**The three runtime surfaces:**

1. **REST/JSON via grpc-gateway** — each RPC carries `google.api.http` annotations mapping it to a path, e.g. `post: "/api/v1/memos"` and `get: "/api/v1/{name=memos/*}"` (`proto/api/v1/memo_service.proto:22-43`). Registered at `server/router/api/v1/v1.go:128-129` for `/api/v1/*` and `/file/*`.
2. **ConnectRPC** — used by the browser client, mounted on the `/memos.api.v1.*` path prefix (`server/router/api/v1/v1.go:139-144`) with the interceptor chain from `:133-138`.
3. **MCP** — a Model Context Protocol router at `server/router/mcp/`, registered in `server/server.go:93`.

The nearest equivalent to "the schema for the public API" is either the `.proto` files above (source of truth) or the generated OpenAPI document, embedded into the binary as `gen/openapi.yaml` via `proto/openapi_embed.go` and exposed through `proto.OpenAPIYAML()`.

Handler implementations live in `server/router/api/v1/` on `APIV1Service`, which satisfies the generated service interfaces — so the RPC methods named in earlier answers (`CreateMemo`, `UpdateMemo`, etc.) are proto-defined RPCs, not GraphQL resolvers.
