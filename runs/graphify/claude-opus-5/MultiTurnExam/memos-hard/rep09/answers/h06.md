**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoRelations`, `SetMemoAttachments` (all on `APIV1Service`) — convergence function: `webhook.Post` — `internal/webhook/webhook.go:120`.**

The six RPC entry points, in two groups:

**Direct dispatch (3):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:70` → `DispatchMemoCreatedWebhook` at `memo_service.go:157`
- `DeleteMemo` — `server/router/api/v1/memo_service.go:518` → `DispatchMemoDeletedWebhook` at `memo_service.go:562`
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20` → `DispatchMemoCommentCreatedWebhook` at `memo_service_comments.go:119` (fires to the *parent* memo's owner, `relatedMemo.CreatorID`)

**Via the shared side-effect helper (3):** each calls `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which invokes `DispatchMemoUpdatedWebhook` at `memo_update_helpers.go:67`:
- `UpdateMemo` — `server/router/api/v1/memo_service.go:401`, call at `:513`
- `SetMemoRelations` — `server/router/api/v1/memo_relation_service.go:16`, call at `:48`
- `SetMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:16`, call at `:48`

**The funnel.** All four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go`, load the target user's hooks via `Store.GetUserWebhooks`, and call `webhook.PostAsync` (`memo_service_webhooks.go:43` and `:71`). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel; four `init()`-spawned workers (`internal/webhook/webhook.go:42-55`) drain it into **`webhook.Post`** (`internal/webhook/webhook.go:120`), the single function that marshals the body, signs it, and issues the actual request at `safeClient.Do(req)` (`internal/webhook/webhook.go:152`). So `PostAsync` is the common synchronous entry, `Post` the common function immediately before delivery.

The URL is user-configured — it comes from `hook.Url` on the creator's stored webhooks, validated at configuration time by `webhook.ValidateURL` in `server/router/api/v1/user_service_webhooks.go:74,161,182`, and re-checked at dial time by `safeDialContext` (`internal/webhook/webhook.go:59`).

Note the webhook management RPCs themselves (`CreateUserWebhook` / `UpdateUserWebhook`) do a DNS resolution via `ValidateURL` but never issue an HTTP request — there is no "test webhook" RPC in the tree.
