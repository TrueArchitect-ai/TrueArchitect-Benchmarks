Two notes on the accounting. The three driver `Close` methods are dispatched dynamically: `store.Driver` declares `Close() error` (`store/driver.go:12`), and `store/store.go:78` calls it through the interface, so exactly one of the three concrete implementations runs per process depending on what `NewDBDriver` selected (`store/db/db.go:14`). Each in turn just delegates to `d.db.Close()` on the underlying `*sql.DB`.

The whole chain is driven from `Server.Shutdown` (`server/server.go:134`), which closes the SSE hub before the HTTP server and the store last: `closeLongLivedConnections` → `shutdownHTTPServer` → `waitBackgroundRunners` → `Store.Close`. I excluded `.Close()` calls on stdlib/third-party values (`rows`, `resp.Body`, `listener`, `http.Server`, generated gRPC-gateway `conn`) since those aren't declarations in this repo, and `server/router/api/v1/test/test_helper.go:66` (`ts.Store.Close()`) is a test caller of an already-listed declarer.
