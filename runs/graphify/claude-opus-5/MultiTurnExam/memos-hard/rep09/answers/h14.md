**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `markdown.(*service).ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: memo creation, and memo update when the `content` field is in the update mask (plus an unused batch-backfill path). Extracted: tags + five computed properties (`has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, `title`).**

**Where it's computed.** `RebuildMemoPayload` initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`server/runner/memopayload/runner.go:74-87`). The real work is `ExtractAll` (`internal/markdown/markdown.go:356`), which parses the content with goldmark and does a **single** `gast.Walk` collecting everything in one pass. The result is persisted as JSON in the memo's `payload` column.

**Triggers (all callers of `RebuildMemoPayload`):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:107`, after the content-length check and before `Store.CreateMemo`
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `if path == "content"` branch of the update-mask loop; the new payload is then written via `update.Payload = memo.Payload` (`:451`)
- `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:52`, a batch backfill over all memos in pages of 100. As established earlier this runner is never constructed in production, so it's dormant code.

Notably, other update paths do **not** recompute: the `location` branch (`memo_service.go:481-484`) mutates `payload.Location` while leaving tags/properties untouched, which is correct since location is user-set, not derived. `CreateMemoComment` reaches the same logic by going through `CreateMemo`.

**What's extracted** (`internal/markdown/markdown.go:373-419`):
- **Tags** — from `MemoTagNode`s produced by the custom `TagExtension`, deduplicated case-preservingly via `uniquePreserveCase`
- **`Property.Title`** — text of the first block-level child of the document if it's an H1 heading (`markdown.go:383-389`)
- **`Property.HasLink`** — any `gast.KindLink` node
- **`Property.HasCode`** — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`
- **`Property.HasTaskList`** — any `east.KindTaskCheckBox`
- **`Property.HasIncompleteTasks`** — a task checkbox with `IsChecked == false`

These match the proto definition `MemoPayload.Property` at `proto/store/memo.proto:15-22`. `ExtractAll` also returns `Mentions`, but `RebuildMemoPayload` deliberately drops them — mentions are consumed separately for notifications (`server/router/api/v1/memo_mention_helpers.go:32`).

**Consumption.** On read, `convertMemoFromStoreWithCreators` copies the stored values straight onto the API message — `memoMessage.Tags` and `memoMessage.Property` at `server/router/api/v1/memo_service_converter.go:48-49` — so list/preview responses never re-parse markdown. Tags are also aggregated for user stats at `server/router/api/v1/user_service_stats.go:138,254`. Separately, a plain-text `GenerateSnippet(content, 64)` is computed on the fly for webhook payloads (`server/router/api/v1/memo_service_webhooks.go:85`) but is not stored in the payload.
