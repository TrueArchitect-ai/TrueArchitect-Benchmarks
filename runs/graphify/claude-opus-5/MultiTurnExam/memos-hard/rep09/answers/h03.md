**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation).**

- **Abstraction** — `internal/idp/idp.go` is the provider-neutral layer. It's deliberately minimal: it defines only the `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) at `internal/idp/idp.go:3-8`, which is the common shape every provider normalizes into. Note it's a shared data contract rather than a Go `interface` — there is no `IdentityProvider` interface type; dispatch is done by a type switch at the call site.

- **Implementation** — `internal/idp/oauth2/oauth2.go` is the single concrete protocol that ships ("Package oauth2 implements the OAuth2 identity provider integration", line 1). It provides `NewIdentityProvider` (validates required `clientId` / `clientSecret` / `tokenUrl` / `userInfoUrl` / `fieldMapping.identifier` config, `oauth2.go:26`), `ExchangeToken` with PKCE `code_verifier` support (`oauth2.go:45`), and `UserInfo`, which maps raw provider JSON onto `idp.IdentityProviderUserInfo` via the configured field mapping.

- **Wiring** — `server/router/api/v1/auth_service_sso.go:104` (`resolveSSOIdentity`) looks up the stored provider and branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` (`auth_service_sso.go:120`) to construct the OAuth2 provider, exchange the code, and fetch user info. Config comes from `storepb.OAuth2Config`.

OAuth2 is the only implementation: the store enum in `proto/store/idp.proto:11-13` has just `TYPE_UNSPECIFIED = 0` and `OAUTH2 = 1` — no OIDC, SAML, or LDAP provider exists in the tree.
