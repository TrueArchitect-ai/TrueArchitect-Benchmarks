**Premise correction: neither. There is no message broker in this codebase — no NATS, no RabbitMQ, no AMQP, Kafka, or NSQ. `go.mod` and `go.sum` declare no broker client, and there is no queue declaration anywhere.** (A case-insensitive grep for those terms across `.go` files returns only false positives — substrings like `openMigrationSQLDB` and `legacyInsertUserSQL` in `store/test/migrator_upgrade_test.go`.)

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool, all in `internal/webhook/webhook.go`.**

- **The "queue"** is a package-level channel declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — capacity 128, in memory, scoped to the process.
- **The "consumers"** are 4 goroutines started in the package `init()` (`internal/webhook/webhook.go:42-55`), each looping `for payload := range asyncPostQueue` and calling `Post`, logging a warning on failure. There is no consumer group, ack, or redelivery.
- **The "producer"** is `PostAsync` (`internal/webhook/webhook.go:184`), called from the memo webhook dispatchers at `server/router/api/v1/memo_service_webhooks.go:43,71`. It does a non-blocking `select` send: if the buffer is full, the payload is **dropped** with a `slog.Warn` (`webhook.go:189-195`) rather than blocking or persisting.
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120`), which signs the body and issues the HTTP request via `safeClient.Do` at `:152`.

Worth being explicit about the operational consequences, since they're exactly what a broker would otherwise provide: there is **no durability** (queued webhooks are lost on restart — nothing drains the channel during `Server.Shutdown`), **no retry** (a failed `Post` is logged and discarded), and **no cross-replica coordination** (each process has its own independent queue and workers).
