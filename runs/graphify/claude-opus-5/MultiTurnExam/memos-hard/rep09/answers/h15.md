Visibility is enforced independently on many surfaces — there is no single chokepoint. The distinct sites:

**gRPC/Connect API v1 (`server/router/api/v1/`)**
- `checkMemoReadAccess` (shared single-memo gate: archived→creator only; non-public→must be authenticated; private→creator only) — `server/router/api/v1/memo_service.go:39-67`; called from `GetMemo` (`memo_service.go:356`), parent-memo resolution (`memo_service.go:367`), and `ListMemoComments` (`memo_service_comments.go:148`)
- `ListMemos` query scoping (anonymous → `PUBLIC` only; authenticated → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:218-227`
- `CreateMemoComment` parent-memo check (private parent → creator or superuser) — `server/router/api/v1/memo_service_comments.go:41`
- Reaction service (`UpsertMemoReaction` / `DeleteMemoReaction`) — `server/router/api/v1/reaction_service.go:30-38` and `:83`
- Attachment service memo-binding check — `server/router/api/v1/attachment_service.go:445-451`
- `SetMemoAttachments` / memo-attachment listing check — `server/router/api/v1/memo_attachment_service.go:214-222`
- User stats scoping (`PUBLIC` for anonymous, `PUBLIC`+`PROTECTED` for other users) — `server/router/api/v1/user_service_stats.go:84-90` and `:218-220`
- Notification-listing viewer check — `server/router/api/v1/user_service_notifications.go:309-312`
- Mention-notification eligibility (don't notify on private memos you can't see) — `server/router/api/v1/memo_mention_helpers.go:62,67,84`
- Share-token grant/expiry validation (the sanctioned bypass for non-public memos) — `server/router/api/v1/memo_share_service.go:137,200`

**SSE push stream**
- `SSEClient.canReceive` — per-client delivery filter, private events only to creator or admin — `server/router/api/v1/sse_hub.go:134-143` (event visibility populated at `sse_event_helpers.go:29-37` and `memo_update_helpers.go:75`)

**Native file server (`/file/...`, outside gRPC)**
- `checkAttachmentPermission` — public+anonymous-allowed short-circuit, then share-token fallback, then authenticated private→creator/admin — `server/router/fileserver/fileserver.go:677-701`

**RSS feeds**
- Hard-scoped to `VisibilityList: []store.Visibility{store.Public}` — `server/router/rss/rss.go:90` and `:141`

**Frontend/SEO**
- Sitemap generation lists public memos only — `server/router/frontend/frontend.go:149-151`

**Email notifications**
- `canViewerAccessMemo` (admin→all, private→creator, protected→any authenticated) — `server/notification/email.go:311-320`

Two observations worth flagging: the API-layer notification check (`user_service_notifications.go:309`) and the email-layer `canViewerAccessMemo` (`notification/email.go:311`) are separate re-implementations of the same rule, as is the fileserver's check versus `checkMemoReadAccess` — so the private/protected policy is duplicated in at least four places rather than centralized. Also, the fileserver and RSS paths bypass the gRPC interceptors entirely, which is why they carry their own enforcement.
