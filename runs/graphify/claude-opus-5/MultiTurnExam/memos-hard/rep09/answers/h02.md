**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF protection via the shared `safeClient`'s `safeDialContext` transport (backed by `isReservedIP`/`reservedCIDRs`) — `internal/webhook/webhook.go:32-77` and `internal/webhook/validate.go:14-54`.**

How it fits together:

- **Delivery path**: memo events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43,71`), which just enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:39`, `184-196`) — dropping the event with a warning if full. Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post`, which marshals the payload, optionally adds Standard-Webhooks HMAC headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and performs the actual HTTP request at `safeClient.Do(req)` — `internal/webhook/webhook.go:152`.

- **Primary protection (dial time)**: `safeClient` is an `http.Client` with a 30s timeout whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59-77`) resolves the host itself and refuses the connection if *any* resolved IP is reserved. Because the check happens at dial time on every connection rather than only at config time, it also defeats DNS rebinding and redirect-based bypasses.

- **Blocklist**: `isReservedIP` (`internal/webhook/validate.go:44`) tests against `reservedCIDRs` (`internal/webhook/validate.go:14-23`) — IPv4 loopback, all three RFC-1918 ranges, `169.254.0.0/16` (cloud IMDS), and the IPv6 equivalents `::1/128`, `fc00::/7`, `fe80::/10` — parsed once in `init()`.

- **Secondary check (config time)**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-`http(s)` schemes and reserved-IP targets when a webhook is created or updated (`server/router/api/v1/user_service_webhooks.go:74,161,182`), returning a gRPC `InvalidArgument`. This is defense-in-depth only — the dial-time check is what actually protects delivery.

- **Escape hatch**: the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted deployments. Note it is never assigned outside of tests (`internal/webhook/webhook_test.go:91,142`), so in production it stays `false` — there's currently no CLI flag or env var wiring it up.
