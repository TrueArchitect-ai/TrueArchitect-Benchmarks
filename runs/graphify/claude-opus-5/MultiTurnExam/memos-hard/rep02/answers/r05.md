**Premise correction: there is no GraphQL in this repository.** Grepping all Go, TypeScript, `go.mod`, and `package.json` files for `graphql`, `gqlgen`, `apollo`, or `.graphql` returns zero hits, and there are no `.graphql`/`.gql` schema files anywhere. No resolver layer, no schema-first tooling, no GraphQL endpoint.

**Actual API surface: Protobuf/gRPC service definitions, exposed over both Connect and REST via grpc-gateway.**

**Where the schema lives** — `proto/api/v1/`, one `.proto` per service:

| File | Service |
|---|---|
| `proto/api/v1/memo_service.proto` | `MemoService` (declared at line 17) |
| `proto/api/v1/user_service.proto` | `UserService` |
| `proto/api/v1/auth_service.proto` | `AuthService` |
| `proto/api/v1/attachment_service.proto` | `AttachmentService` |
| `proto/api/v1/instance_service.proto` | `InstanceService` |
| `proto/api/v1/idp_service.proto` | `IdentityProviderService` |
| `proto/api/v1/shortcut_service.proto` | `ShortcutService` |
| `proto/api/v1/ai_service.proto` | `AIService` |
| `proto/api/v1/common.proto` | shared types |

RPCs are declared conventionally — e.g. `rpc CreateMemo(CreateMemoRequest) returns (Memo)` at `proto/api/v1/memo_service.proto:21`, with `ListMemos`, `GetMemo`, `UpdateMemo`, `DeleteMemo`, reactions, relations, comments, and shares following (`memo_service.proto:29-137`). Each carries `google.api.http` annotations that define its REST mapping. Generated Go lands in `proto/gen/api/v1/` (message/gRPC stubs, `*.pb.gw.go` gateway code, and `apiv1connect/` Connect handlers). A separate `proto/store/` tree defines persisted payload types like `MemoPayload` and `AttachmentPayload`.

**How it's served** — `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`) wires up two transports against the same handler implementations:

- **Connect RPC** — `NewConnectServiceHandler(s)` and `RegisterConnectHandlers` (`v1.go:140-141`), mounted on the Echo route `/memos.api.v1.*` (`v1.go:144`) with a request-size cap.
- **REST via grpc-gateway** — the gateway mux built at `v1.go:95+`, applying the HTTP annotations from the protos.

Both paths run through a shared `NewAuthorizer` (`v1.go:68`) so authentication and anonymous-access policy are enforced once for either transport. Non-RPC surfaces exist alongside this: the file server (`/file/...`, `server/router/fileserver/fileserver.go:121-125`), RSS feeds (`server/router/rss/rss.go`), and an MCP endpoint that re-exposes a subset of the same RPCs (`server/router/mcp/catalog.go`).
