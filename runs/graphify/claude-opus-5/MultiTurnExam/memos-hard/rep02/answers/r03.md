**Premise correction: there is no nightly database-cleanup job, and the cron scheduler that exists is never used by the server — so there is no schedule to report.**

Two separate corrections:

**1. No database-cleanup job exists.** Nothing in the codebase performs periodic database maintenance — no VACUUM, no pruning of old rows, no purge of orphaned records on a timer. Grepping `server/`, `store/`, and `internal/` for `vacuum`, `prune`, `purge`, and `nightly` turns up nothing of the kind. The "cleanup" hits that do exist are all synchronous and event-driven, not scheduled: attachment storage cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`), relation/attachment cleanup on memo deletion (`server/router/api/v1/memo_service.go:579`), and the in-memory cache's expiry sweep every 5 minutes (`store/cache/cache.go:47, 60, 83`) — which touches the process heap, not the database.

**2. The cron scheduler is dead code.** `internal/scheduler/` is a complete, well-documented cron implementation — a 5-field expression parser (`internal/scheduler/parser.go`), job type (`internal/scheduler/job.go`), middleware (`internal/scheduler/middleware.go`), and runner (`internal/scheduler/scheduler.go`) — but nothing outside the package imports it. Grepping for `internal/scheduler` across the repo returns only two hits, both inside the package's own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No production code constructs a `Scheduler` or registers a `Job`, which is consistent with the earlier finding that `Schedule.Next` has a real fan-in of 1 — from `internal/scheduler/scheduler.go:142`, within the package itself.

**What actually runs on a timer.** The server has exactly one background runner, and it isn't cron-driven: the S3 presign runner, which re-signs S3 attachment URLs on a `time.Ticker` every 12 hours (`server/runner/s3presign/runner.go:27, 29-41`), started with one immediate pass at `server/server.go:163`. It runs on an interval from process start, not at a wall-clock time of day, so there's no "nightly" slot involved.
