**Explicit Go code — the `reaction` table has no foreign key or cascade rule in any dialect, so the delete-user transaction removes reactions with two hand-written `DELETE` statements.**

What I checked:

**1. The Go delete path.** `DeleteUser` runs everything in one transaction (`store/db/sqlite/user_delete.go:29-59`). Inside `deleteUserTargetsTx`, reactions are removed *first*, via two distinct passes (`store/db/sqlite/user_delete.go:96-104`):

- `deleteReactionsByContentIDsTx` (`store/db/sqlite/user_delete.go:380-388`) — `DELETE FROM reaction WHERE content_id IN (...)`, batched at 500. This removes reactions *other people left on this user's memos*. The content IDs come from `memoContentIDsFromRefs`, which builds `"memos/" + memo.UID` strings (`user_delete.go:512-518`), and the memo set is the recursive comment tree rooted at the user's memos (`user_delete.go:133-166`).
- `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:400-403`) — `DELETE FROM reaction WHERE creator_id = ?`. This removes reactions *the user left on anyone else's content*.

Both directions are covered, and the two calls are ordered before `deleteMemosTx` / `deleteUserRowTx` (`user_delete.go:120-125`) so nothing is orphaned mid-transaction.

**2. All three drivers do the same thing.** The identical pair exists in `store/db/postgres/user_delete.go:96,102` (defined at `:380`, `:400`) and `store/db/mysql/user_delete.go:96,102` (defined at `:417`, `:437`). No driver relies on the database to do this.

**3. The schema has no rule that could do it.** The `reaction` table is declared without any `FOREIGN KEY` clause in all three dialects — `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98`. `creator_id` is a plain `INTEGER NOT NULL` with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint; `content_id` is free text, so it couldn't reference `memo` even in principle. Grepping the whole migration tree for `FOREIGN KEY` / `ON DELETE` / `CASCADE` turns up cascades only on `memo_share`, and on legacy sqlite tables from 0.3–0.5 — never on `reaction`.

**4. No triggers.** The only triggers ever defined were modification-time triggers in `store/migration/sqlite/0.6/00__recreate_triggers.sql`, and they were dropped in `store/migration/sqlite/0.7/01__remove_triggers.sql`. Nothing database-level touches reactions.
