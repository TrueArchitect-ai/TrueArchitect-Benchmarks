**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF-blocking dialer `safeDialContext` on the shared `safeClient` transport — `internal/webhook/webhook.go:59` (reserved-range table and check in `internal/webhook/validate.go:14-54`)**

How it fits together:

- **Delivery:** `Post` marshals the payload, sets the Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`) when a signing secret is present, and issues the actual `POST` via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. Callers don't invoke it directly — API code calls `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a 128-slot buffered channel drained by 4 worker goroutines started in `init()` (`webhook.go:39-55`); the workers are what call `Post`. Dispatch sites are `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.
- **Protection:** the dedicated `http.Client` at `internal/webhook/webhook.go:32-37` installs `safeDialContext` as its `Transport.DialContext`. That function resolves the hostname itself and rejects the connection if *any* returned address is in a reserved range (`webhook.go:59-77`). Because the check happens at dial time rather than at URL-validation time, it also defeats DNS rebinding — a host that validated as public can't later resolve to a private IP and get through. It also enforces a 30s timeout, and the response read is capped at 1 MiB (`webhook.go:158`).
- **Reserved ranges:** `reservedCIDRs` in `internal/webhook/validate.go:14-23` covers IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (explicitly including cloud IMDS at 169.254.169.254), plus IPv6 loopback, ULA, and link-local. They're parsed once into `reservedNetworks` in `init()` and tested by `isReservedIP` (`validate.go:44`).

Two supporting notes:

- There's a second, earlier layer: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and private-resolving hostnames at the point a user registers a webhook — called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. This is admission control, not the enforcement boundary; the dialer is what actually protects delivery.
- `AllowPrivateIPs` (`internal/webhook/validate.go:41`) is a global escape hatch that disables both layers for self-hosted deployments targeting local services. In this tree nothing outside `internal/webhook/webhook_test.go` ever sets it, so there is no CLI flag or env var wired up to turn it on — it defaults to `false` and the protection is always active in production.
