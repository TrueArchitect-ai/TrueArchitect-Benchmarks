**Triggers (recomputation happens on exactly two operations):**

| Trigger | Site |
|---|---|
| `CreateMemo` — every memo creation | `server/router/api/v1/memo_service.go:108` |
| `UpdateMemo` — only when the update mask includes `"content"` | `server/router/api/v1/memo_service.go:447` |

`CreateMemoComment` also recomputes, but indirectly: it delegates to `s.CreateMemo` at `server/router/api/v1/memo_service_comments.go:56`. Updates that touch only visibility, pinned state, relations, or attachments do **not** recompute — the `RebuildMemoPayload` call sits inside the `if path == "content"` branch (`memo_service.go:436-450`). The third potential trigger, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:52`), which would rebuild every memo in the database in batches, is never invoked in production — nothing constructs that `Runner`.

**What's extracted.** `RebuildMemoPayload` calls `ExtractAll` once and assigns two fields — `memo.Payload.Tags` and `memo.Payload.Property` (`runner.go:85-86`). `ExtractAll` does a single goldmark AST walk (`internal/markdown/markdown.go:370-411`) and produces:

- **`Tags`** — every `#tag` node, excluding tags nested inside links or images (`asMemoTagNode`, `markdown.go:132-138`), deduplicated with original case preserved (`markdown.go:417`).
- **`Property.Title`** — text of the first block-level child of the document if it's an H1 heading (`markdown.go:383-389`).
- **`Property.HasLink`** — any `KindLink` node.
- **`Property.HasCode`** — any code block, fenced code block, or code span.
- **`Property.HasTaskList`** — any task checkbox; and **`Property.HasIncompleteTasks`** — set when at least one checkbox is unchecked (`markdown.go:392-407`).

The `Property` shape is defined in `proto/store/memo.proto:15-22` (`has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, `title`).

One clarification on "used for lists/previews": the persisted payload above powers list filtering and badges, but the short preview text shown in relation cards is *not* part of it — `Snippet` is computed on the fly at response-conversion time via `getMemoContentSnippet` → `GenerateSnippet` (`server/router/api/v1/memo_service_webhooks.go:83-85`, used at `memo_service_converter.go:76` and `memo_relation_service.go:154`), and is never stored.
