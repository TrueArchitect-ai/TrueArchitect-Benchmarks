**The call chain**

- Handlers 1–3 call `DispatchMemoCreated/Updated/DeletedWebhook` → `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`); handler 4 calls `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:29`); handlers 5–6 go through the shared helper `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook`.
- Each of those loads the target URLs from `s.Store.GetUserWebhooks(...)` — these are the user-configured URLs, registered via `CreateUserWebhook` / `UpdateUserWebhook` (`user_service_webhooks.go:53`, `:106`).
- Every one of them then calls `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue`; four worker goroutines started in `init()` (`webhook.go:43-55`) drain it and call `Post`. So `PostAsync` is the single enqueue funnel and `Post` is the single function that builds and sends the HTTP request.

**Note on other outbound-HTTP paths:** they do *not* converge here. Link-metadata fetching (`memo_service_link_metadata.go`, `internal/httpgetter`) uses a URL supplied per-request rather than a stored config, and the AI service (`ai_service.go`, `internal/ai`) uses an admin-configured provider base URL — separate clients from `safeClient`.

**Safety controls on this path:** `Post` uses `safeClient`, whose transport dials through `safeDialContext` (`webhook.go:59`), rejecting reserved/private IPs at dial time (defeating DNS rebinding); URLs are also validated up front by `webhook.ValidateURL` (`internal/webhook/validate.go`). Both are bypassable via the `AllowPrivateIPs` global (`validate.go:41`).
