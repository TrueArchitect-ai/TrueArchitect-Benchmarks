Memo visibility is enforced in many independent places — there is no single chokepoint. The distinct enforcement sites:

**Core gRPC/Connect API (v1)**
- Single-memo read gate `checkMemoReadAccess` (archived → creator only; non-public → auth required; private → creator only) — `server/router/api/v1/memo_service.go:39-67`; called from `GetMemo` (:356) and its parent-memo check (:367), and from `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)
- `ListMemos` query-level filter (anonymous → `VisibilityList = [PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:216-228`
- `ListMemoComments` child-memo filter (same anonymous/authed split) — `server/router/api/v1/memo_service_comments.go:152-160`
- Comment creation gate on the parent memo — `server/router/api/v1/memo_service_comments.go:41`
- User stats query filters (`GetUserStats` and `ListAllUserStats`) — `server/router/api/v1/user_service_stats.go:84-90` and `:218-220`
- Reactions: list and upsert both re-check visibility — `server/router/api/v1/reaction_service.go:38` and `:83`
- Attachment access via owning memo (`checkAttachmentAccess`) — `server/router/api/v1/attachment_service.go:422-455` (check at :451)
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:222`

**HTTP file server (blob/attachment serving, separate auth path)**
- `checkAttachmentPermission`: public+anonymous-allowed shortcut, share-token fallback, then private → creator/admin — `server/router/fileserver/fileserver.go:650-703` (checks at :677 and :699)

**Share links (visibility deliberately bypassed, token is the authorization)**
- `GetMemoByShare` returns the memo on a valid non-expired token regardless of visibility (archived still hidden) — `server/router/api/v1/memo_share_service.go:153-192`; create/list/delete of shares restricted to creator/admin at `:63`, `:100`, `:139`

**Real-time fan-out**
- SSE per-client filter `canReceive` (private → creator or admin; unknown visibility → deny) — `server/router/api/v1/sse_hub.go:133-143`

**Anonymous/public surfaces**
- RSS feeds — public only — `server/router/rss/rss.go:90` and `:141`
- `sitemap.xml` — public only — `server/router/frontend/frontend.go:150`

**Notification/mention paths (content redaction)**
- Mention eligibility `canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-89`
- In-app notification snippet `canViewerAccessMemo` — `server/router/api/v1/user_service_notifications.go:302-315`
- Email notification `canViewerAccessMemo` (duplicate implementation, uses `RoleAdmin` directly rather than `isSuperUser`) — `server/notification/email.go:305-320`

**Persistence layer (where `VisibilityList` becomes SQL)**
- `store/db/sqlite/memo.go:96`, `store/db/mysql/memo.go:104`, `store/db/postgres/memo.go:89` (field defined at `store/memo.go:69`)

Not a separate site: the MCP server replays tool calls as HTTP requests through the same Echo server (`server/router/mcp/adapter.go:26-42`), so it inherits the v1 API checks above.
