**Premise correction:** There is no GraphQL anywhere in this repository. A case-insensitive grep for `graphql` across the whole tree (excluding `node_modules`) returns zero hits — no schema files, no resolvers, no `graphql-go`/`gqlgen`/`apollo` dependencies in `go.mod` or `web/package.json`. This is **Memos**, and its public API is **Protocol Buffers over gRPC / Connect / REST (grpc-gateway)**.

## Where the API is actually defined

**Source of truth — `.proto` files in `proto/api/v1/`:**

| File | Service |
|---|---|
| `proto/api/v1/memo_service.proto` | `MemoService` |
| `proto/api/v1/user_service.proto` | `UserService` |
| `proto/api/v1/auth_service.proto` | `AuthService` |
| `proto/api/v1/attachment_service.proto` | `AttachmentService` |
| `proto/api/v1/instance_service.proto` | `InstanceService` |
| `proto/api/v1/shortcut_service.proto` | `ShortcutService` |
| `proto/api/v1/idp_service.proto` | `IdentityProviderService` |
| `proto/api/v1/ai_service.proto` | `AIService` |
| `proto/api/v1/common.proto` | shared enums/messages |

REST routes are declared inline as `google.api.http` annotations on each RPC — e.g. `proto/api/v1/memo_service.proto:22-24` maps `CreateMemo` to `POST /api/v1/memos`, and line 35 maps `GetMemo` to `GET /api/v1/{name=memos/*}`. The design convention is stated in `proto/api/v1/README.md` (follows Google AIPs).

**Codegen — `proto/buf.gen.yaml`** runs `buf generate` with plugins for protobuf-go, grpc-go, connect-go, grpc-gateway, gnostic-openapi, and protobuf-es. Outputs:
- Go stubs → `proto/gen/api/v1/` (`*.pb.go`, `*_grpc.pb.go`, `*.pb.gw.go`)
- OpenAPI spec → `proto/gen/openapi.yaml`, embedded via `proto/openapi_embed.go` and consumed by the MCP router at `server/router/mcp/service.go:78`
- TypeScript clients → `web/src/types/proto/` (per `buf.gen.yaml`)

**Serving — `server/router/api/v1/v1.go`:**
- `RegisterGateway` (line 65) builds a grpc-gateway mux with an auth middleware, registers all eight service handlers, and mounts them on Echo at `/api/v1/*` and `/file/*` (lines 128-129).
- Connect handlers for the browser client are mounted at `/memos.api.v1.*` (line 144), wired in `server/router/api/v1/connect_handler.go` / `connect_services.go`.
- The service implementations live alongside, one file per service (`memo_service.go`, `user_service.go`, …).
- Top-level wiring is in `server/server.go:88`.

Non-proto HTTP surfaces exist too: `server/router/rss/rss.go`, `server/router/fileserver/fileserver.go`, `server/router/mcp/` (MCP server), and `/healthz` at `server/server.go:67`.
