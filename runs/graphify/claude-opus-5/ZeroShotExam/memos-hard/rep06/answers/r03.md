**Premise correction: there is no nightly database-cleanup job in this repository.** The cron scheduler package exists, but nothing in the application registers a cleanup job of any kind — the only "cleanup" schedules in the codebase are illustrative snippets in docs and tests.

What's actually there:

- `internal/scheduler/` is a standalone, generic cron library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It provides `New()`, `Register()`, `Start()`, cron-expression parsing, and middleware — but it ships with **zero pre-registered jobs**; callers supply their own.
- The package is imported nowhere outside its own tests — the only `github.com/usememos/memos/internal/scheduler` imports are in `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. The server never starts a scheduler.

The `0 2 * * *` (2 AM daily) figure that looks like an answer comes only from documentation/example code, and none of it touches a database:

- `internal/scheduler/doc.go:15-17` — package doc example, job named `daily-cleanup`, `Schedule: "0 2 * * *"`, handler body is the comment `// Your cleanup logic here`.
- `internal/scheduler/README.md:34-38` — the same `daily-cleanup` snippet, handler just prints `"Running cleanup..."`.
- `internal/scheduler/example_test.go:97-106` — a runnable Go example job named `cleanup` at `"0 2 * * *"` whose handler prints `"Cleaning up old data..."`.
- `internal/scheduler/README.md:240-246` — a "Best Practices" snippet showing a `stale-session-cleanup` job at `"0 3 * * *"` (3 AM), calling a `cleanupSessions` handler that doesn't exist in the codebase.

The only real recurring background work in the server is interval-based, not cron-based, and isn't cleanup: `server/runner/s3presign/runner.go:26-36` re-presigns S3 URLs on a 12-hour `time.Ticker` (started from `server/server.go:163`), and `server/runner/memopayload/runner.go:27` exposes a one-shot `RunOnce` payload rebuild.
