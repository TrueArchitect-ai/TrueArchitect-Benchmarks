**`internal/idp`; `internal/idp/oauth2`**

- `internal/idp/idp.go` — the abstraction package. It's deliberately minimal: it declares only the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any provider implementation must produce.
- `internal/idp/oauth2/oauth2.go` — the single concrete protocol implementation that ships ("Package oauth2 implements the OAuth2 identity provider integration"). It defines `IdentityProvider` backed by `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (including PKCE `codeVerifier` support), and user-info fetching mapped through `config.FieldMapping`.

Wiring: `server/router/api/v1/auth_service_sso.go:12-13` is the only non-test consumer, importing both `internal/idp` and `internal/idp/oauth2`. There is no SAML or dedicated OIDC package — grep for `internal/idp` shows OAuth2 is the only implementation. The IdP CRUD/API surface lives in `server/router/api/v1/idp_service.go` with storage in `store/idp.go` and `store/db/{sqlite,mysql,postgres}`.
