**Premise correction: this repository has no per-user API rate-limiting middleware.** There is nothing to register and no request limits to report. I searched the Go sources, `go.mod`, `web/src`, `docs`, and `scripts` for `rate limit`, `throttle`, `limiter`, `burst`, `quota`, `429`, and the usual libraries (`golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`) — no implementation and no dependency.

**What actually is registered on the request path:**

- `server/server.go:51-52` — the only Echo-level middleware: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go`).
- `server/router/api/v1/v1.go:133-137` — the Connect RPC interceptor chain, in order: `NewMetadataInterceptor()`, `NewLoggingInterceptor(logStacktraces)`, `NewRecoveryInterceptor(logStacktraces)`, `NewAuthInterceptor(authorizer)`. All four are defined in `server/router/api/v1/connect_interceptors.go`. The auth interceptor enforces authentication/anonymous-access policy — identity, not quota.

**The only limits that do exist** are size and concurrency caps, not per-user rate limits:

- **Request body size:** `maxAPIRequestBytes = 256 << 20` (256 MiB) at `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` to the gRPC-gateway mux (line 126) and the Connect mux (line 144), plus `connect.WithReadMaxBytes` (line 141).
- **Global concurrency semaphores** (process-wide, not per user) at `server/router/api/v1/v1.go:59-60`: `thumbnailSemaphore` = 3 concurrent thumbnail generations, `imageProcessingSemaphore` = 2 concurrent EXIF-strip operations. Exhaustion of the latter surfaces as `ResourceExhausted "too many image processing requests"` (`server/router/api/v1/attachment_service.go:160`, acquired in `attachment_service_image.go:68-75`). This is the closest thing to throttling in the codebase, but it queues on the semaphore rather than rejecting by rate, and it is not keyed by user.

Rate limiting appears only as an unimplemented suggestion in email docs: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") and `internal/email/README.md:286` ("### 5. Implement Rate Limiting"), the latter being illustrative sample code, not wired-in behavior.

The unrelated `Middleware` type in `internal/scheduler/middleware.go` is for background job handlers (`Recovery`, `Logging`, `Timeout`), not HTTP/API requests.
