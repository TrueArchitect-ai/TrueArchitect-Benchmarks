**`*markdown.service` (the only impl) — built solely by `markdown.NewService(...)`, once in production at `NewAPIV1Service` — held by `APIV1Service`, `RSSService`, and `memopayload.Runner`.**

### The interface
`markdown.Service` — `internal/markdown/markdown.go:31-55`. Nine methods: `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

### Concrete implementation
Exactly one: the unexported `service` struct at `internal/markdown/markdown.go:57-59`, wrapping a `goldmark.Markdown`. There is **no** second implementation — no mock, fake, or null object anywhere. `RenameTag` (and every other method) has a single receiver, `*service` (`internal/markdown/markdown.go:425`), and `yuin/goldmark` is imported only under `internal/markdown/`. Tests exercise the real type.

What *does* vary is configuration, not type — `NewService` takes `WithTagExtension()` / `WithMentionExtension()` options (`internal/markdown/markdown.go:69-83`), so different call sites get the same struct with different goldmark extension sets.

### Construction
`markdown.NewService(opts ...Option) Service` — `internal/markdown/markdown.go:85` — is the sole factory.

- **Production, single call site:** `NewAPIV1Service` at `server/router/api/v1/v1.go:48-51`, with **both** `WithTagExtension()` and `WithMentionExtension()`. That instance is stored on `APIV1Service.MarkdownService` (`v1.go:56`).
- One instance serves the whole process: `server/server.go:76` builds the `APIV1Service`, and `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService` rather than constructing a second one.
- **Tests** construct their own, with weaker configs: `server/router/api/v1/test/test_helper.go:44`, `server/router/fileserver/fileserver_test.go:427` (tags only — no mentions), `server/router/rss/rss_test.go:54` (no extensions at all), and `internal/markdown/markdown_test.go` throughout.

### Two things worth flagging
- **`memopayload.Runner` is dead wiring.** It holds `markdown.Service` and calls it at `runner.go:52`, but `memopayload.NewRunner` has no callers anywhere in the repo — production reaches the package only through the free function `RebuildMemoPayload`, invoked from `memo_service.go:108` and `:447`. So at runtime only two of the three holders are live.
- **The markdown *renderer* is not behind this interface.** `renderer.NewMarkdownRenderer()` is constructed fresh on every call inside `RenderMarkdown` (`internal/markdown/markdown.go:257`) and `RenameTag` (`markdown.go:452`) — a concrete type used directly, not injected.

Separately, per the interface's own doc comment (`internal/markdown/markdown.go:27-29`), HTML rendering for the UI happens on the frontend via `markdown-it`; the backend's `RenderHTML` exists for RSS and other server-side rendering. That frontend path is outside this interface.
