**Mechanism: explicit Go code** — reactions are deleted by hand-written `DELETE FROM reaction` statements inside the user-delete transaction, in all three DB drivers. There is no database-level cascade for reactions.

## What the code does

`store/db/sqlite/user_delete.go:92-127` (`deleteUserTargetsTx`) runs two reaction deletes as the *first* and *third* steps of the transaction, before the memos and the user row are removed:

1. `deleteReactionsByContentIDsTx` — `store/db/sqlite/user_delete.go:380-388`
   `DELETE FROM reaction WHERE content_id IN (...)` — removes **everyone's** reactions on the deleted user's memos (content IDs built as `"memos/"+uid` at `user_delete.go:512-518`, over the recursive memo tree incl. comments from `listDeleteUserMemoTreeRecursive`, `:133`).
2. `deleteReactionsByCreatorTx` — `store/db/sqlite/user_delete.go:400-403`
   `DELETE FROM reaction WHERE creator_id = ?` — removes the deleted user's own reactions, including those left on **other** users' memos.

Identical logic exists per-driver:
- `store/db/postgres/user_delete.go:96,102,380,400`
- `store/db/mysql/user_delete.go:96,102,417,437`

Entry path: `server/router/api/v1/user_service.go:393` (`DeleteUser`) → `store/user.go:171` (`Store.DeleteUser`, which only delegates to the driver and then evicts caches via `store/user_delete.go:39`). All deletes run in one transaction opened at `store/db/sqlite/user_delete.go:30` and committed at `:51`.

## Why it can't be a DB rule

- The `reaction` table has **no foreign key at all** in any dialect — only a `UNIQUE(creator_id, content_id, reaction_type)`: `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98`. `content_id` is a text string (`"memos/<uid>"`), not a referencing column, so a cascade isn't even expressible.
- The only `ON DELETE CASCADE` in the current schema is `memo_share.memo_id → memo(id)` (`store/migration/sqlite/LATEST.sql:109` and peers). Other cascades exist only in historical migrations (e.g. `store/migration/sqlite/0.5/00__regenerate_foreign_keys.sql`), not the live schema.
- SQLite explicitly disables enforcement anyway: `store/db/sqlite/sqlite.go:53` opens the DSN with `_pragma=foreign_keys(0)`.

`store/test/user_delete_test.go` seeds three reactions (`:97-113`) — peer→deleted-user's memo, deleted-user→peer's memo, peer→peer's memo — and asserts at `:217-220` that only `peerReactionToKeep` survives, confirming both delete paths fire.
