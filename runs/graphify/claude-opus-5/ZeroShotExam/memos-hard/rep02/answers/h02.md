### How it fits together

**Where delivery executes.** Callers never send inline. `server/router/api/v1/memo_service_webhooks.go:43,71` build a `WebhookRequestPayload` and call `webhook.PostAsync`, which only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:184-196`, dropping with a warning when full). Four goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`. `Post` marshals the JSON body, optionally adds Standard Webhooks HMAC headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and issues the POST via the package-level `safeClient`.

**Two layers of SSRF protection:**

1. **Dial-time (the load-bearing one)** — `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37, 59-77`). It splits host/port, resolves the hostname itself, and refuses to dial if *any* returned address is reserved. Because the check happens at connection time rather than at save time, it also defeats DNS rebinding — a hostname that validated as public when the webhook was created still can't connect if it later resolves to a private IP.

2. **Save-time** — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74,161,182`). It enforces an absolute URL, an `http`/`https` scheme, and non-reserved resolution, returning a gRPC `InvalidArgument` for a clean user-facing error.

Both layers share `isReservedIP` (`internal/webhook/validate.go:44`), which tests against `reservedCIDRs` (`internal/webhook/validate.go:14-23`) — parsed once at startup: IPv4 loopback, all three RFC-1918 ranges, `169.254.0.0/16` (explicitly covering the cloud IMDS endpoint at 169.254.169.254), and the IPv6 equivalents `::1/128`, `fc00::/7`, `fe80::/10`.

### Two things worth flagging

- **The escape hatch is code-only.** `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` and disables *both* layers when true. Grepping all non-test Go sources, nothing ever assigns it — no flag, env var, or config wires it up, so it is effectively a hardcoded `false`. It's documented as a self-hosting convenience, but is currently unreachable without a code change.
- **Coverage gaps in the CIDR list.** `0.0.0.0/8`, IPv4-mapped IPv6 (`::ffff:127.0.0.1`), and carrier-grade NAT `100.64.0.0/10` aren't in `reservedCIDRs`. Go's resolver typically won't hand back mapped forms here, so this is a hardening note rather than a demonstrated bypass.
