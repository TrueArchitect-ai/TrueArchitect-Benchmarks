**Convergence function — `webhook.Post`, `internal/webhook/webhook.go:120`**

All four `Dispatch*Webhook` methods in `server/router/api/v1/memo_service_webhooks.go` load the creator's webhooks via `s.Store.GetUserWebhooks`, set `payload.URL = hook.Url` (the user-configured URL, stored per-user), and call `webhook.PostAsync` (`internal/webhook/webhook.go:184`). `PostAsync` only enqueues onto `asyncPostQueue`; the four worker goroutines started in `init()` (`webhook.go:42-52`) call `Post`, which is the sole place the outbound `http.NewRequest("POST", requestPayload.URL, …)` + `safeClient.Do(req)` happens (`webhook.go:126`, `webhook.go:152`).

Supporting detail: the URL is validated at configuration time by `webhook.ValidateURL` (`internal/webhook/validate.go:63`, called from the `CreateUserWebhook`/`UpdateUserWebhook` handlers in `server/router/api/v1/user_service_webhooks.go`), and again at dial time by `safeDialContext` (`webhook.go:57`) to block reserved/private IPs and DNS rebinding.

Two other outbound-HTTP paths exist but do **not** converge on `webhook.Post`: `GetLinkMetadata` (`memo_service_link_metadata.go:46` → `httpgetter.GetHTMLMeta`) fetches a URL supplied in the request rather than a configured one, and SSO login (`auth_service_sso.go:130` → `internal/idp/oauth2/oauth2.go:85`) hits the admin-configured IdP `UserInfoUrl`.
