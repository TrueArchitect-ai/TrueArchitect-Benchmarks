**Mechanism: explicit Go code** — the driver-level `DeleteUser` implementations issue `DELETE FROM reaction` statements inside the delete transaction. There is **no** database-level cascade for reactions: the `reaction` table has no foreign keys at all.

**What I checked**

1. **The delete path** — `server/router/api/v1/user_service.go:393` → `store/user.go:171` (`s.driver.DeleteUser`) → per-driver implementations.

2. **The driver code** — `store/db/sqlite/user_delete.go`, `store/db/postgres/user_delete.go`, `store/db/mysql/user_delete.go` (all three mirror each other). `deleteUserTargetsTx` runs two reaction deletes in one transaction:
   - `deleteReactionsByContentIDsTx` (sqlite `user_delete.go:388`, postgres `:380`, mysql `:417`) — `DELETE FROM reaction WHERE content_id IN (...)`, where the content IDs are `"memos/" + uid` for every memo in the user's memo tree (own memos plus their comment descendants, gathered by the recursive CTE in `listDeleteUserMemoTreeRecursive`). This removes *other people's* reactions on the deleted user's memos.
   - `deleteReactionsByCreatorTx` (sqlite `:407`, postgres `:400`, mysql `:437`) — `DELETE FROM reaction WHERE creator_id = ?`. This removes the deleted user's own reactions, including those on memos that survive.

   Both run before the `user` row delete, batched at 500 IDs per statement (`deleteUserBatchSize`), and the whole thing commits atomically (`tx.Commit`), so a rollback leaves reactions intact.

3. **The schema** — `CREATE TABLE reaction` in `store/migration/sqlite/LATEST.sql:92`, `store/migration/postgres/LATEST.sql:91`, `store/migration/mysql/LATEST.sql:91`. Columns are `creator_id`/`content_id` plain integers/text with a UNIQUE constraint; no `REFERENCES` and no `ON DELETE CASCADE`. Grepping `REFERENCES|CASCADE` across `store/migration/` returns no hits for reaction (the only FK in sqlite `LATEST.sql` is `memo_share.memo_id → memo(id)` at line 109). Same for the original migrations `store/migration/*/0.20/00__reaction.sql` and `*/0.23/00__reactions.sql`.

4. **Tests confirming the behavior** — `store/test/user_delete_test.go:97-220` and `server/router/api/v1/test/user_service_delete_test.go:188-298` assert that reactions on the user's own memos and on their comments are gone, while a third party's reaction on a foreign memo survives; `user_service_delete_test.go:366-431` asserts a reaction still exists after a failpoint-induced rollback.
