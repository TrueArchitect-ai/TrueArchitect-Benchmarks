**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the provider-agnostic `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any IdP implementation normalizes its user data into.
- **Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol implementation shipped. Its header comment reads "Package oauth2 implements the OAuth2 identity provider integration"; it defines `IdentityProvider` over `storepb.OAuth2Config` with `NewIdentityProvider`, exchanges the code for a token via `golang.org/x/oauth2`, and maps the userinfo response through `storepb.FieldMapping` into `idp.IdentityProviderUserInfo`.

Supporting evidence:
- `server/router/api/v1/auth_service_sso.go:13` is the sole non-test consumer, importing `internal/idp/oauth2` for the SSO sign-in flow.
- The protobuf enums list `OAUTH2 = 1` as the only provider type (`proto/store/idp.proto:13`, `proto/api/v1/idp_service.proto:79`), confirming no second protocol (e.g. SAML/LDAP/OIDC-specific) ships.
