**Explicit Go code — no database-level rule.** Emoji reactions are removed by two explicit `DELETE FROM reaction` statements inside the `DeleteUser` transaction, replicated per driver.

## Mechanism

Call chain: `server/router/api/v1/user_service.go:414` → `store/user.go:170` (`Store.DeleteUser`) → the per-driver `DB.DeleteUser`.

Inside `deleteUserTargetsTx` the reaction cleanup happens in **two passes** (sqlite lines cited; postgres/mysql identical at the same line numbers 96/102):

1. `store/db/sqlite/user_delete.go:96` → `deleteReactionsByContentIDsTx` (`:380-388`) — `DELETE FROM reaction WHERE content_id IN (...)`, batched at 500. This removes reactions *placed by anyone* on the deleted user's memos. The content IDs come from `memoContentIDsFromRefs` (`:512`), which formats them as `"memos/" + memo.UID`, over the recursive memo tree (memos plus their `COMMENT` descendants, `:133-147`).
2. `store/db/sqlite/user_delete.go:102` → `deleteReactionsByCreatorTx` (`:400-403`) — `DELETE FROM reaction WHERE creator_id = ?`. This removes the user's *own* reactions on anyone else's memos.

Both run inside the transaction opened at `:30` with a rollback defer, before the `user` row itself is deleted at `:123`.

## What I checked to rule out a DB-level rule

- **Reaction table definitions** in all three dialects: `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98`. `creator_id` is a plain `INTEGER NOT NULL` — no `REFERENCES`, no `ON DELETE CASCADE`.
- **Grepped all of `store/migration/` and `store/seed/`** for `FOREIGN KEY|REFERENCES|CASCADE|CREATE TRIGGER` intersected with `reaction`: zero hits.
- **The only FK in any `LATEST.sql`** is `memo_share.memo_id → memo(id) ON DELETE CASCADE` (sqlite `:109`, postgres `:108`, mysql `:108`). This schema deliberately runs almost FK-free — see `store/migration/sqlite/0.7/00__remove_fk.sql`.
- **Triggers**: the only ones that ever existed were modification-time triggers on `user`/`memo`/`shortcut`/`resource` (`store/migration/sqlite/0.6/00__recreate_triggers.sql`), all dropped in `store/migration/sqlite/0.7/01__remove_triggers.sql`. None touched `reaction`.

## Driver parity

- `store/db/sqlite/user_delete.go:96, 102, 380, 400`
- `store/db/postgres/user_delete.go:96, 102, 380, 400`
- `store/db/mysql/user_delete.go:96, 102, 417, 437`

All three implement the same two-pass deletion; the only differences are placeholder syntax and the memo-tree walk (recursive CTE for sqlite/postgres, iterative for mysql at `store/db/mysql/user_delete.go:133`).
