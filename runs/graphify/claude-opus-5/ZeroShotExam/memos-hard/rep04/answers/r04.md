**Premise correction:** Neither. This repo (memos) has no external message broker at all — no NATS, RabbitMQ, Kafka, or Redis client appears in `go.mod`, and there is no separate worker process. The only repo-wide hit for "nats"/"amqp" is an unrelated string in `web/src/locales/ca.json`.

**Actual mechanism — an in-process buffered Go channel:**

- **Queue declaration:** `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, a package-level buffered channel with capacity 128.
- **Workers:** `internal/webhook/webhook.go:42-55` — a package `init()` spawns 4 goroutines, each ranging over `asyncPostQueue` and calling `Post(payload)`. Failures are only logged (`slog.Warn`); there is no retry, no ack, and no persistence.
- **Producer:** `PostAsync` at `internal/webhook/webhook.go:184-196` does a non-blocking `select` send; if the buffer is full the payload is **dropped** with a warning ("Dropped webhook dispatch because the async queue is full"). Nil payloads are also dropped.
- **Callers:** `server/router/api/v1/memo_service_webhooks.go:43` (comment created) and `:71` (memo created/updated/deleted), which fan out one enqueue per user webhook from `Store.GetUserWebhooks`.
- **Delivery itself:** `Post` at `internal/webhook/webhook.go:120` does a plain HTTP POST via `safeClient` (30s timeout, SSRF-guarded dialer at `:59`), with optional Standard Webhooks HMAC-SHA256 signing headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`).

Practical consequence: because the queue lives in the server process's memory, queued webhooks are lost on restart and are not shared across replicas.
