## How I ruled out the other candidates

Three files implement `CreateMemo` with an INSERT:

| Candidate | INSERT line |
|---|---|
| `store/db/sqlite/memo.go` | :41 (backticked identifiers, `RETURNING`) |
| `store/db/postgres/memo.go` | :38 (unquoted, `$n` placeholders, `RETURNING`) |
| `store/db/mysql/memo.go` | :41 (backticked, no `RETURNING` — uses `LastInsertId`) |

Selection is a runtime `switch` on `profile.Driver` in `NewDBDriver` — `store/db/db.go:14-32` — which returns a `store.Driver` interface value (`CreateMemo` declared at `store/driver.go:29`). So the deciding question is what `profile.Driver` holds by default:

- `cmd/memos/main.go:122` — `viper.SetDefault("driver", "sqlite")`
- `cmd/memos/main.go:130` — the `--driver` flag itself defaults to `"sqlite"`
- `cmd/memos/main.go:43` — `Driver: viper.GetString("driver")` feeds the profile
- The only override paths are `--driver` or the `MEMOS_DRIVER` env var (`viper.SetEnvPrefix("memos")` + `AutomaticEnv()`, `cmd/memos/main.go:167-169`) — neither is set in a default install; the repo only sets `MEMOS_DRIVER` in test containers (`store/test/containers.go:304`).

Corroborating that sqlite is the intended default path: `Profile.Validate` special-cases it to synthesize a DSN — `p.Driver == "sqlite" && p.DSN == ""` → `<data>/memos_prod.db` (`internal/profile/profile.go:110-118`), while `sqlite.NewDB` errors out with `"dsn required"` if none is set (`store/db/sqlite/sqlite.go:26-28`). MySQL and Postgres have no such fallback, so they can't run without an explicit DSN.

Method summary: grep for `INSERT INTO memo` across `store/` to enumerate candidates → read the `store.Driver` interface and `Store.CreateMemo` to confirm dispatch is a plain interface call with no wrapper → read the `NewDBDriver` switch → resolve `profile.Driver`'s default at the Viper/Cobra flag definitions in `cmd/memos/main.go`.
