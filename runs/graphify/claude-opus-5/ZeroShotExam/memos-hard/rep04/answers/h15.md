Memo visibility is enforced independently on each surface that can expose memo data — there is no single choke point; each surface re-derives the rule (PUBLIC → anyone; PROTECTED → any authenticated user; PRIVATE → creator or admin/super-user only), plus archived-only-to-creator.

**Core gRPC/Connect API v1 (memo reads)**

Single-memo read gate `checkMemoReadAccess` — server/router/api/v1/memo_service.go:39 (callers: `GetMemo` :355 and its parent-memo check :367)
List-query visibility filter in `ListMemos` (`VisibilityList` / CEL `creator_id == N || visibility in [...]`) — server/router/api/v1/memo_service.go:217-226
Comment surface: parent-memo gate on create + list, and the comment list filter — server/router/api/v1/memo_service_comments.go:41, :148, :155-160
Share-token path (deliberate bypass of visibility; gated only on a valid, non-expired token and non-archived memo) — server/router/api/v1/memo_share_service.go:151 (`GetMemoByShare`, `getActiveMemoShare` :199)

**Other API v1 surfaces that re-check memo visibility**

Memo attachment listing — server/router/api/v1/memo_attachment_service.go:213-226
Attachment access check (linked attachments inherit their memo's visibility) — server/router/api/v1/attachment_service.go:436-452
Reactions (list + upsert) — server/router/api/v1/reaction_service.go:29-41, :83
User stats aggregation (`ListAllUserStats`, `GetUserStats`) — server/router/api/v1/user_service_stats.go:83-92, :217-221
SSE live-event fan-out `SSEClient.canReceive` — server/router/api/v1/sse_hub.go:133-143 (events tagged with visibility/creator at server/router/api/v1/sse_event_helpers.go)

**Non-gRPC HTTP routers (separate implementations)**

Attachment blob file server (`/file/...`), incl. anonymous-instance and share-token fallback — server/router/fileserver/fileserver.go:650-704
RSS feeds (explore + per-user), public-only — server/router/rss/rss.go:90, :141
Sitemap XML, public-only — server/router/frontend/frontend.go:149-152

**Notification / mention surfaces (redact memo content per viewer)**

Inbox/user notifications `canViewerAccessMemo` — server/router/api/v1/user_service_notifications.go:302-317
Email dispatcher `canViewerAccessMemo` (duplicate implementation) — server/notification/email.go:311-320
Mention-notification eligibility — server/router/api/v1/memo_mention_helpers.go:62-84

Supporting mechanism (not itself a policy site): `FindMemo.VisibilityList` is translated to SQL in store/memo.go:69 and store/db/sqlite/memo.go:96, store/db/postgres/memo.go:89, store/db/mysql/memo.go:104 — the store applies whatever filter the caller sets and enforces nothing on its own.
