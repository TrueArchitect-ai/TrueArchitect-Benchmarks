The premise doesn't hold: **there is no nightly database-cleanup job in this repo's cron scheduler.** No time can be cited for it, because no such job is registered anywhere in production code.

What actually exists:

- `internal/scheduler/` is a standalone, general-purpose cron library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It defines `Register`/`Start`/`Stop` but registers no jobs of its own.
- Nothing in the application imports it. The only importers are its own tests — `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. `server/server.go` never wires it up.
- The "2 AM daily" schedule (`0 2 * * *`) that this question likely refers to appears only as illustrative documentation/example code, not a real job:
  - `internal/scheduler/doc.go:15-16` — a `daily-cleanup` job in the package doc comment
  - `internal/scheduler/README.md` — the same snippet in the Quick Start, plus a `stale-session-cleanup` at `0 3 * * *` in Best Practices
  - `internal/scheduler/example_test.go:97-106` — an `Example_multipleJobs` job named `cleanup` at `0 2 * * *`, printing "Cleaning up old data..." — no database access
- The only real scheduled background work in the server is the S3 presign runner, and it isn't cron-based: it runs once at startup and then on a 12-hour ticker (`server/runner/s3presign/runner.go:27`, started at `server/server.go:153-173`).
- Unrelated to cron, `store/cache/cache.go:199-218` runs an in-memory cache expiry loop every 5 minutes (`store/store.go:42`) — memory only, not the database.

So if you're looking for a nightly DB cleanup, it would need to be written; the scheduler package is available but currently unused by the app.
