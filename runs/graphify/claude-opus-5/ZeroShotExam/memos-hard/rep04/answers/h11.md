**1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages)**

The data layer is `store/` (`store/user.go:29`, `store/memo.go:35`). Counting distinct Go packages outside `store/**` that reference each persistent entity type:

| Type | Packages outside `store/` | Total references |
|---|---|---|
| **`store.User`** | **7** | ~99 |
| **`store.Memo`** | **6** | ~73 |
| `store.Attachment` | 4 | ~43 |
| `store.Inbox`, `store.MemoShare` | 2–3 | 10–14 |
| `store.MemoRelation`, `store.Reaction`, `store.UserIdentity`, `store.IdentityProvider` | 1 | — |

**`store.User`** — `server/router/api/v1`, `server/router/fileserver`, `server/router/api/v1/test`, `server/auth`, `server/notification`, `server/router/rss`, `server/router/frontend`.

**`store.Memo`** — `server/router/api/v1`, `server/router/api/v1/test`, `server/notification`, `server/router/rss`, `server/router/frontend`, `server/runner/memopayload`.

Excluding `_test.go` files, the counts become User = 6 packages and Memo = 4, so User leads either way.

Two notes on method:
- `store/db/{sqlite,mysql,postgres}` reference every entity type but are part of the data layer, so they're excluded. Including them would add a flat +3 to every type and not change the ranking.
- Settings-shaped entities (`InstanceSetting`, `UserSetting`, `IdentityProvider`) look artificially low because callers outside `store/` work with the generated proto payloads (`storepb.UserSetting`, `storepb.InstanceSetting` from `proto/gen/store/`) rather than the store structs — the store struct is essentially an internal envelope. Matches inside `proto/gen/store/*.pb.go` are descriptor strings like `memos.store.UserSetting`, not real Go references, and were filtered out.
