**No** — outside `store/db/db.go`'s `NewDBDriver` factory, nothing in production code constructs the MySQL driver.

Evidence:

- `store/db/db.go:22` — the only call to `mysql.NewDB(profile)`, inside the `switch profile.Driver` factory. It is also the only file that imports `github.com/usememos/memos/store/db/mysql` (`store/db/db.go:8`).
- A repo-wide grep for `mysql.NewDB`, `mysql.New`, and imports of `store/db/mysql` returns exactly those two lines and nothing else (excluding `node_modules`/`graphify-out`).
- Inside the package itself, `store/db/mysql/mysql.go:29` builds `DB{profile: profile}` — that's `NewDB`'s own body, not an external construction.
- The one other direct construction is a same-package unit test: `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` to test the pure helper `IsRetryableAuthenticationMutationError` (no connection needed). Since it's in `package mysql`, it can reach the unexported struct without going through the factory.
- Integration tests go through the factory too: `store/test/store.go` only builds a `*profile.Profile` with `Driver: "mysql"` and a DSN (`store/test/store.go:87-100`), leaving driver selection to `NewDBDriver`. `store/test/containers.go` references `github.com/go-sql-driver/mysql` and the testcontainers `mysql` module — those are the upstream SQL driver and the container harness, not the memos MySQL store driver.
