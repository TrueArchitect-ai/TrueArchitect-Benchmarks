## Concrete implementation

There is exactly **one**: the unexported `service` struct at `internal/markdown/markdown.go:57`, wrapping a `goldmark.Markdown`. No mocks or fakes implement `Service` anywhere — I grepped for every method signature and all receivers are `(s *service)` in `markdown.go`. So `*service` is what executes at runtime *and* in tests.

Its behavior varies by construction options, not by type:

## Two things worth flagging

**`memopayload.NewRunner` has no non-test callers.** Nothing in the repo constructs a `Runner`; the only live path into that package is the standalone `RebuildMemoPayload(ctx, memo, s.MarkdownService)` function, called from `memo_service.go`. The `Runner` struct and its `RunOnce` batch-rebuild loop are currently dead code.

**Most of the interface is unused in production.** Counting non-test callers outside `markdown.go`: `ExtractAll` 2, `RenderHTML` 1, `GenerateSnippet` 1 — and `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `ValidateContent`, `RenameTag` all have **zero**. Those five exist only for the interface surface and its tests, so the single-implementation interface isn't currently buying polymorphism or test substitution.
