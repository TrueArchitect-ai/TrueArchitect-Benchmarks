**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any IdP implementation must produce. The provider type itself is modeled in the store proto as `storepb.IdentityProvider` with a `Type` enum (`storepb.IdentityProvider_OAUTH2`) and a oneof config.

- **Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol implementation that ships. Its header comment reads "Package oauth2 implements the OAuth2 identity provider integration." It exposes `NewIdentityProvider(*storepb.OAuth2Config)`, `ExchangeToken` (with PKCE `code_verifier` support), and `UserInfo`, which maps raw claims through `storepb.FieldMapping` into `idp.IdentityProviderUserInfo`.

Wiring: `server/router/api/v1/auth_service_sso.go:104` (`resolveSSOIdentity`) branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` and is the single consumer of both packages — no SAML/LDAP implementation exists in the tree (the only other match for "saml" is planning docs under `docs/plans/2026-04-21-sso-user-identity-linkage/`).
