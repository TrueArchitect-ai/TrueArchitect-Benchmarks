**r02.**

**Premise correction: this repository (Memos) has no per-user API rate-limiting middleware.** There is no rate limiter registered anywhere in the request path, so there are no per-user request limits to report.

Here is what the middleware/interceptor chain actually contains:

**HTTP middleware** — `server/server.go:51-52`, the only two Echo middlewares registered:
- `middleware.Recover()` (panic recovery)
- `newCORSMiddleware(profile)` (`server/cors.go`)

**Connect RPC interceptors** — `server/router/api/v1/v1.go:133-137`, the full chain:
- `NewMetadataInterceptor()` — HTTP headers → gRPC metadata
- `NewLoggingInterceptor(logStacktraces)`
- `NewRecoveryInterceptor(logStacktraces)`
- `NewAuthInterceptor(authorizer)` — authentication/authorization only, no counting or throttling (`server/router/api/v1/connect_interceptors.go`)

**What does exist, and is probably the source of the premise** — these are *size* and *concurrency* limits, global rather than per-user, and none of them are rate limits:

| Limit | Value | Location |
|---|---|---|
| Max API request body | 256 MiB (`256 << 20`) | `server/router/api/v1/v1.go:20`, applied at `v1.go:126`, `:141`, `:144` |
| Concurrent thumbnail generation (API) | 3 | `server/router/api/v1/v1.go:59` |
| Concurrent image processing (API) | 2 | `server/router/api/v1/v1.go:60` |
| Concurrent thumbnail generation (file server) | 3 | `server/router/fileserver/fileserver.go:46`, `:116` |

The image-processing semaphore is the one place that returns a throttle-flavored error — `codes.ResourceExhausted, "too many image processing requests"` at `server/router/api/v1/attachment_service.go:160` — but that fires on concurrent in-flight work across all users, not on a per-user request rate.

Supporting evidence that no limiter exists: `golang.org/x/time` appears in `go.mod:151` marked `// indirect` and is never imported by project code; there is no `rate.NewLimiter`, tollbooth, or equivalent anywhere outside documentation. The only rate-limiting mention in the repo is aspirational — `internal/email/README.md:286-295` and `internal/email/doc.go:86` suggest implementing rate limiting for outbound *email sending* as a future hardening step, with an illustrative `rate.NewLimiter(rate.Every(time.Second), 10)` example that is not wired into any code. There is also no login-attempt throttling or account lockout.
