**Mechanism: explicit Go code** — the reaction table has no foreign keys, no `ON DELETE CASCADE`, and no triggers on any of the three drivers, so cleanup is done by hand-written `DELETE FROM reaction` statements inside the user-delete transaction.

**How it works**

Each driver implements `DeleteUser` with the same two-part reaction cleanup, both run inside the delete transaction:

- `store/db/sqlite/user_delete.go:93` `deleteReactionsByContentIDsTx` — deletes reactions *on* the user's memos (and comment-tree descendants), matching `content_id IN (...)` where content IDs are built as `"memos/" + memo.UID` (`memoContentIDsFromRefs`, same file). Batched at 500 per statement.
- `store/db/sqlite/user_delete.go:99` `deleteReactionsByCreatorTx` — deletes reactions *authored by* the user: `DELETE FROM reaction WHERE creator_id = ?`.

Identical logic in the other drivers: `store/db/postgres/user_delete.go:96,102` (impls at :380, :400) and `store/db/mysql/user_delete.go:96,102` (impls at :417, :437). Entry point is `store/user.go:171` → `s.driver.DeleteUser`.

**Evidence there is no DB-level rule**

- `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98` — the `reaction` table declares only `id`, `created_ts`, `creator_id`, `content_id`, `reaction_type` and a UNIQUE constraint. No `FOREIGN KEY`, no cascade.
- Contrast with the adjacent `memo_share` table (e.g. `store/migration/sqlite/LATEST.sql:109`), which *does* declare `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` — so cascades are used in this schema where intended, just not for reactions.
- Grepping `ON DELETE` / `TRIGGER` across the schemas returns only that `memo_share` line; the only other `reaction` hits in migrations are the emoji-value backfill in `store/migration/*/0.23/00__reactions.sql`.

**Test coverage:** `store/test/user_delete_test.go:97-112` seeds reactions by the deleted user and a peer's reaction on a peer memo; `:217-220` asserts the peer's reaction survives while the deleted user's are gone — confirming the deletion is scoped, not cascaded.
