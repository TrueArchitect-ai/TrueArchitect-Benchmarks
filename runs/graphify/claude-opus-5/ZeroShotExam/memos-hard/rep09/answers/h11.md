## Method

The data layer is the `store` package (`store/store.go`, `store/driver.go`), whose persistent entity structs are `User`, `Memo`, `Attachment`, `Reaction`, `Inbox`, `MemoRelation`, `MemoShare`, `UserIdentity`, `UserSetting`, `InstanceSetting`, `IdentityProvider` (`store/user.go`, `store/memo.go`, `store/attachment.go`, etc.).

Ten Go packages outside the `store/...` tree import `github.com/usememos/memos/store`. Counting how many of those reference each entity type:

**`store.User` — 7 packages**
- `server/auth` (`server/auth/context.go`, `server/auth/interceptor.go`)
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/fileserver`
- `server/router/frontend`
- `server/router/rss`

**`store.Memo` — 6 packages**
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/frontend`
- `server/router/rss`
- `server/runner/memopayload`

Runner-up: `store.Attachment` at 4 packages (`server/router/api/v1`, `.../test`, `server/router/fileserver`, `server/router/rss`). Everything else is 3 or fewer.

Two notes on the counting: `server/router/api/v1/test` is counted as its own package (it is a separate Go package); excluding it makes the ranking 6 vs. 5 with the same ordering. And `proto/gen/store` shows up in a naive grep for `store.UserSetting`/`store.IdentityProvider`, but those are protobuf descriptor string literals (`memos.store.UserSetting`), not Go references — I excluded them.
