**URL the browser requests** — `convertUserFromStore` rewrites a base64 avatar into a path so the profile image is fetched as a plain `<img src>`: `userpb.AvatarUrl = fmt.Sprintf("/file/%s/avatar", userpb.Name)` (`server/router/api/v1/user_service_converters.go:36`), rendered by `UserAvatar` (`web/src/components/UserAvatar.tsx:13`). So the browser GETs `/file/users/{username}/avatar`.

Notes:
- The avatar bytes live in the `user.avatar_url` column as a base64 data URI — there is no blob/S3/local-file hop like attachments have; `parseDataURI` is the decode step.
- Driver selection happens once at startup (`NewDBDriver`, `store/db/db.go:14`); the MySQL/Postgres equivalents of the final hop are `store/db/mysql/user.go` and `store/db/postgres/user.go`.
- Service wiring: `fileserver.NewFileServerService` + `RegisterRoutes` at `server/server.go:81-82`, registered before the gRPC gateway.
- Access control is inside the handler, not middleware: anonymous requests are rejected only when `Profile.AllowAnonymous()` is false; otherwise any user's avatar is public.
