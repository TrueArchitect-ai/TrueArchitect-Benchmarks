**delivery function — `internal/webhook/webhook.go:120` (`Post`); protection mechanism — `internal/webhook/webhook.go:59` (`safeDialContext`, backed by `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go:14-54`)**

Details:

**Where delivery executes**
- Memo events call `webhook.PostAsync(payload)` from `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (created/updated/deleted/comment-created activity types).
- `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel `asyncPostQueue`, dropping with a warning if full.
- Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`.
- `Post` (`internal/webhook/webhook.go:120`) is where the actual HTTP POST happens: it marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), issues `safeClient.Do(req)` at line 152, and reads a size-limited (1 MiB) response.

**What protects it from internal addresses** — two layers:
1. *Dial-time (the real enforcement)*: the shared `safeClient` uses a `http.Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37, 59-77`). It resolves the host itself and refuses to dial if any resolved IP is reserved. Because the check happens at dial time on every request, it also defeats DNS rebinding (noted in the comment at lines 30-31). The blocklist is `reservedCIDRs` in `internal/webhook/validate.go:14-23` — IPv4 loopback, RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), plus IPv6 loopback/ULA/link-local — parsed once at startup and tested by `isReservedIP` (`validate.go:44`).
2. *Registration-time*: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates/updates webhook URLs, from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. It enforces http/https scheme and rejects hostnames resolving to reserved IPs, returning `InvalidArgument`.

**Escape hatch / gap**: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted deployments. Grepping the non-test tree, nothing ever sets it, so there is currently no CLI flag or config wired to it — it defaults to `false` (protection on) and is only flipped in tests.
