**Computation site** — `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual parsing to the goldmark-based markdown service `ExtractAll` in `internal/markdown/markdown.go:356` (single AST walk). It writes back only two fields: `memo.Payload.Tags` and `memo.Payload.Property` (`runner.go:85-86`). The schema is `MemoPayload.Property` in `proto/store/memo.proto` ("The calculated properties from the memo content").

**Triggers**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`; the user-supplied `Location` is merged in afterwards (`:110-112`), so location survives the rebuild while tags/property are always derived.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `path == "content"` branch of the update mask; the rebuilt payload is put on `update.Payload` alongside `update.Content`. Other mask paths (visibility, pinned, state, timestamps) do not recompute it.
- Batch backfill — `Runner.RunOnce` in `server/runner/memopayload/runner.go:27` rebuilds the payload for every memo in pages of 100 and persists via `Store.UpdateMemo`. Note this runner is not currently wired into startup (`server/server.go` only calls `s3presignRunner.RunOnce`), so it's a migration/repair path rather than a scheduled job.

**Extracted properties** (`internal/markdown/markdown.go:356-419`)
- `Tags` — `#tag` nodes, skipping tags nested inside links/images (`asMemoTagNode`), deduplicated with case preserved.
- `Property.Title` — plain text of the first block-level child of the document if it is an H1 heading.
- `Property.HasLink` — any `KindLink` node.
- `Property.HasCode` — any indented, fenced, or inline code span.
- `Property.HasTaskList` — any GFM task checkbox; `Property.HasIncompleteTasks` — at least one unchecked box.
- `Mentions` (lowercased `@user` names) are also returned by `ExtractAll` but are *not* stored in the payload — they're consumed only for mention notifications in `server/router/api/v1/memo_mention_helpers.go:32`.

These stored properties feed filtering/stats (`internal/filter/schema.go`, `store/memo.go`, `server/router/api/v1/user_service_stats.go`). The other content-derived preview field, `Memo.Snippet`, is *not* stored — it's regenerated on every response conversion at `server/router/api/v1/memo_service_converter.go:76` (and `:225`/`:248` for relation previews) via `getMemoContentSnippet` → `GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83`).
