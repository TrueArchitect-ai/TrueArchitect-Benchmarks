Memo visibility is enforced in many places — there is no single chokepoint. Distinct enforcement sites:

**Single-memo read gate (Connect/gRPC API)** — `checkMemoReadAccess` — server/router/api/v1/memo_service.go:39, called by `GetMemo` (memo_service.go:356, plus the parent-memo re-check at :367) and `ListMemoComments` (server/router/api/v1/memo_service_comments.go:148)

**List-query visibility filter (ListMemos)** — server/router/api/v1/memo_service.go:217-227 (sets `VisibilityList` / injects a `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` filter), pushed down to SQL in store/db/sqlite/memo.go:96, store/db/postgres/memo.go:89, store/db/mysql/memo.go:104

**User stats aggregation** — server/router/api/v1/user_service_stats.go:84-92 (`ListAllUserStats`) and :218-221 (`GetUserStats`)

**Comment creation gate** — server/router/api/v1/memo_service_comments.go:41 (`CreateMemoComment`)

**Reactions** — server/router/api/v1/reaction_service.go:38 (`ListMemoReactions`) and :83 (`UpsertMemoReaction`)

**Memo attachment listing (API)** — server/router/api/v1/memo_attachment_service.go:222 (`ListMemoAttachments`)

**Attachment access check (API)** — `checkAttachmentAccess` — server/router/api/v1/attachment_service.go:422-453

**Raw file/blob HTTP server** — `checkAttachmentPermission` — server/router/fileserver/fileserver.go:650-702 (anonymous-public rule at :677, private rule at :699, plus the `share_token` bypass at :684-689)

**Share-link surface** — server/router/api/v1/memo_share_service.go: an unexpired token substitutes for the visibility check in `GetMemoByShare` (:152-190, `getActiveMemoShare` :197), while creating/listing/revoking shares is restricted to creator-or-admin (:44, :93, :134)

**SSE broadcast filter** — `SSEClient.canReceive` — server/router/api/v1/sse_hub.go:134-144 (visibility carried on the event by server/router/api/v1/sse_event_helpers.go:29-37)

**In-app notifications / inbox** — `canViewerAccessMemo` — server/router/api/v1/user_service_notifications.go:302

**Mention notification dispatch** — `canUserAccessMentionContext` — server/router/api/v1/memo_mention_helpers.go:56 (and `shouldSkipMentionInbox` :74)

**Email notifications** — `canViewerAccessMemo` (a second, independent copy) — server/notification/email.go:306

**RSS feeds** — server/router/rss/rss.go:90 (instance feed) and :141 (per-user feed) — hardcoded to `store.Public`

**Sitemap / frontend SSR** — server/router/frontend/frontend.go:150 — hardcoded to `store.Public`

Two things worth flagging: `canViewerAccessMemo` is duplicated between `user_service_notifications.go:302` and `notification/email.go:306` with a subtle difference — the API copy uses `isSuperUser(user)`, the email copy checks `viewer.Role == store.RoleAdmin` directly. Likewise `isMemoShareExpired` is duplicated at `memo_share_service.go:195` and `fileserver.go:778`.
