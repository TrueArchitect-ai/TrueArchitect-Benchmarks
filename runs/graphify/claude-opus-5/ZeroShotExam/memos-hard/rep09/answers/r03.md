**The premise doesn't hold: there is no nightly database-cleanup job registered in this repository's cron scheduler.**

What actually exists:

- `internal/scheduler/` is a *standalone, general-purpose cron scheduler library* ("GitHub Actions-inspired", zero external dependencies — `internal/scheduler/doc.go:1-9`). It provides `New()`, `Register()`, `Start()`/`Stop()`, cron parsing (`parser.go`) and middleware (`middleware.go`), but it registers no jobs of its own.
- Nothing in the application wires it up. Outside of `internal/scheduler/` itself, no Go file imports or references the package — the only real background workers are ticker-based runners: `server/runner/s3presign/runner.go:27` (every 12 hours) and `server/runner/memopayload/runner.go`, neither of which is a cron job or a database cleanup.

The "2 AM nightly cleanup" figure that this question likely refers to appears only in **documentation and example code**, never in wired-up application code:

- `internal/scheduler/doc.go:15-16` — package doc example: `Name: "daily-cleanup"`, `Schedule: "0 2 * * *"` (2 AM daily)
- `internal/scheduler/README.md:34-37` — quick-start snippet, same `"0 2 * * *"`
- `internal/scheduler/example_test.go:97-101` — `Example_multipleJobs`, a job named `"cleanup"` at `"0 2 * * *"` that just prints "Cleaning up old data..."
- `internal/scheduler/README.md:241-245` — a *different* illustrative example, `"stale-session-cleanup"` at `"0 3 * * *"` (3 AM)

So if you want the doc answer: the examples use 2 AM (`0 2 * * *`). But these are illustrations of the library's API, not a scheduled database cleanup in this codebase, and the two docs disagree (2 AM vs. 3 AM) precisely because they're arbitrary samples.
