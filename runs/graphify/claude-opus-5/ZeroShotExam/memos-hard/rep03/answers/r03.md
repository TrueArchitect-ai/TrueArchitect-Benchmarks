**Premise correction: there is no nightly database-cleanup job in this repository's cron scheduler.** The scheduler has no registered jobs at all — it's a standalone library, not a wired-up job list.

What actually exists:

- `internal/scheduler/` is a self-contained cron library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). `Register` is defined at `internal/scheduler/scheduler.go:70` but is never called anywhere in the application — the only importers are the package's own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`).
- The `"0 2 * * *"` (2 AM daily) cleanup schedule you may be thinking of appears only in **illustrative documentation**, not in running code: `internal/scheduler/README.md:34-37`, `internal/scheduler/doc.go:15-18`, and `internal/scheduler/example_test.go:97-99`. Other doc-only examples include `"0 3 * * *"` for a `stale-session-cleanup` job (`internal/scheduler/README.md:241-245`).

Actual background work in the server does not use the cron scheduler and is interval-based, not clock-scheduled:

- `server/runner/s3presign/runner.go:26-30` — ticker every 12 hours (from process start, not a fixed time of day).
- `server/runner/memopayload/runner.go` — a one-shot/on-demand runner, no schedule.
- `store/cache/cache.go:201` — in-memory cache expiry sweep every 5 minutes (`store/cache/cache.go:60`); this is cache eviction, not database cleanup.

So no job — nightly, database-cleanup or otherwise — is scheduled to run at any time in this codebase.
