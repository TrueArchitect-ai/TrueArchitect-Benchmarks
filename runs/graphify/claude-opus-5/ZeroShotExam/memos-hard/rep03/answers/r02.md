**Premise correction: this repository has no per-user API rate-limiting middleware.** There is no rate limiter registered anywhere — no token bucket, no per-user request counters, no 429/`ResourceExhausted` throttling by identity, and no rate-limiting library in use (`golang.org/x/time` appears in `go.mod:151` only as an *indirect* dependency, not imported by any code).

What actually exists, in case one of these is what you were thinking of:

**1. The middleware/interceptor chains that *are* registered** (this is where a rate limiter would go, and it isn't there):
- Echo-level: `server/server.go:51-52` — only `middleware.Recover()` and `newCORSMiddleware(profile)`.
- Connect RPC-level: `server/router/api/v1/v1.go:133-137` — `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`). Auth, logging, panic recovery — no throttling.

**2. A request *size* limit, not a request *rate* limit** — `maxAPIRequestBytes = 256 << 20` (256 MiB) at `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` to the grpc-gateway mux (line 126) and the Connect mux (lines 141, 144).

**3. Global concurrency semaphores for image work** — `server/router/api/v1/v1.go:59-60`: `thumbnailSemaphore = semaphore.NewWeighted(3)` and `imageProcessingSemaphore = semaphore.NewWeighted(2)`. These cap *simultaneous in-flight* image operations process-wide; they are shared across all users, not per-user, and exceeding them yields `codes.ResourceExhausted, "too many image processing requests"` (`server/router/api/v1/attachment_service.go:158-160`). A user making 1000 sequential uploads is never blocked by these.

**4. Batch-size caps on individual RPCs** — e.g. `maxBatchGetUsers` (`server/router/api/v1/user_service.go:145`), `maxBatchDeleteAttachments` (`attachment_service.go:355`), `maxBatchGetInstanceSettings` (`instance_service.go:78`), `maxBatchGetLinkMetadata` (`memo_service_link_metadata.go:24`). These bound items *per request*, not requests per user per unit time.

Rate limiting appears in this repo only as an unimplemented recommendation: `internal/email/README.md:286` ("### 5. Implement Rate Limiting") and `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") — both are guidance for integrators, not code.
