**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual parsing to the goldmark-based markdown service — `(*service).ExtractAll` in `internal/markdown/markdown.go:356` (single AST walk producing `ExtractedData{Tags, Mentions, Property}`). The same property logic also exists standalone as `(*service).ExtractProperties` at `internal/markdown/markdown.go:193`, but nothing in the server calls it — `ExtractAll` is the live path. `RebuildMemoPayload` writes the result into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers:**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before the store write.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `path == "content"` branch of the update mask (so visibility/pinned/state/create_time updates do not recompute it), then assigned to `update.Payload`.
- A batch backfill exists: `Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) pages all memos 100 at a time, rebuilds each payload, and persists via `Store.UpdateMemo`. Note it is not currently wired up anywhere — no `memopayload.NewRunner` call exists in the tree (`server/server.go` only invokes `s3presignRunner.RunOnce`), so it's a dormant/legacy migration path.

**Extracted properties** (`storepb.MemoPayload_Property`, populated in `internal/markdown/markdown.go:356-410`):
- `Title` — text of the first block-level child of the document if it is an H1 heading (via `extractHeadingText`, `internal/markdown/markdown.go:172`).
- `HasLink` — any `gast.KindLink` node.
- `HasCode` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- `HasTaskList` — any `east.KindTaskCheckBox`.
- `HasIncompleteTasks` — any task checkbox with `IsChecked == false`.

Alongside the property, the same pass fills `Payload.Tags` (deduped `#tag` nodes) and collects `Mentions` (used separately by `server/router/api/v1/memo_mention_helpers.go:32`).

**Exposure:** `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315`) maps all five fields onto the API `Memo.Property`, attached in `convertMemoFromStoreWithCreators` (`server/router/api/v1/memo_service_converter.go:49`). The frontend uses the booleans as filter factors `property.hasLink` / `property.hasTaskList` / `property.hasCode` (`web/src/contexts/MemoFilterContext.tsx:11-13`, `web/src/hooks/useMemoFilters.ts:73-77`).
