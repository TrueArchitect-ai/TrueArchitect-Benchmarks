**delivery function — `Post` in `internal/webhook/webhook.go:120` (dispatched asynchronously via `PostAsync`, `internal/webhook/webhook.go:184`, which feeds a bounded 128-slot channel drained by 4 background goroutines started in `init()` at `internal/webhook/webhook.go:42`); protection mechanism — `safeDialContext` / `isReservedIP`, `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

- **Trigger path:** memo create/update/delete and comment creation call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, after loading each user's configured hooks (`s.Store.GetUserWebhooks`).
- **Actual outbound HTTP:** `Post` marshals the payload, builds the POST, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and executes via the shared `safeClient` at `internal/webhook/webhook.go:152`. Response body reads are capped at 1 MiB and the client has a 30s timeout.
- **SSRF protection (primary, at dial time):** `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`, `:59-77`). It re-resolves the hostname and refuses to dial if *any* resolved address is reserved/private. Because the check happens at connection time rather than at save time, it also defeats DNS rebinding.
- **Blocklist:** `reservedCIDRs` in `internal/webhook/validate.go:14-23` — IPv4 loopback, RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), plus `::1/128`, `fc00::/7`, `fe80::/10`. Parsed once at startup into `reservedNetworks`; `isReservedIP` (`internal/webhook/validate.go:44`) does the containment test.
- **Secondary check at configuration time:** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates/updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`); it enforces http/https scheme and rejects hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument`.
- **Escape hatch:** the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) disables both checks for self-hosted setups targeting the local network. Note it is currently only ever set from tests (`internal/webhook/webhook_test.go:91`, `:142`) — no CLI flag or config wires it up, so in practice it stays `false`.
