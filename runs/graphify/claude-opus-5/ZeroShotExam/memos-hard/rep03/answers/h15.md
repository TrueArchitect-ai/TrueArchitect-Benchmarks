h15.

Memo visibility is enforced independently in several places — there is no single chokepoint. Distinct enforcement sites:

**Core API (Connect/gRPC) — single-memo reads**
- `checkMemoReadAccess` (archived → creator-only; non-PUBLIC → auth required; PRIVATE → creator only), called by GetMemo and by the parent-memo check — `server/router/api/v1/memo_service.go:39-68` (callers at `:356`, `:367`)
- ListMemoComments gate — reuses `checkMemoReadAccess` then re-filters child memos with a CEL filter — `server/router/api/v1/memo_service_comments.go:148-161`
- CreateMemoComment gate (PRIVATE parent → creator/admin only) — `server/router/api/v1/memo_service_comments.go:33-44`

**Core API — list/query-level filtering (pushed into the store query, not a per-memo check)**
- ListMemos visibility list / CEL filter — `server/router/api/v1/memo_service.go:218-227`
- Memo relation (comment) listing filter — `server/router/api/v1/memo_relation_service.go:105-112`
- User stats aggregation (ListAllUserStats and GetUserStats) — `server/router/api/v1/user_service_stats.go:82-92` and `:217-221`

**Sibling resources that re-implement the check inline**
- Reactions (ListMemoReactions and Upsert/Delete reaction) — `server/router/api/v1/reaction_service.go:29-41`, `:83`
- Memo attachment listing — `server/router/api/v1/memo_attachment_service.go:213-226`
- Attachment access via API (`checkAttachmentPermission`) — `server/router/api/v1/attachment_service.go:425-455`

**Non-gRPC HTTP surfaces**
- File server raw attachment serving — separate `checkAttachmentPermission` with its own anonymous-access and `share_token` rules — `server/router/fileserver/fileserver.go:650-703`
- RSS feeds (explore + per-user, PUBLIC only) — `server/router/rss/rss.go:90`, `:141`
- Sitemap XML (PUBLIC only) — `server/router/frontend/frontend.go:148-152`

**Push / notification surfaces**
- SSE broadcast delivery filter (`SSEClient.canReceive`: PRIVATE events only to creator or admin) — `server/router/api/v1/sse_hub.go:134-143`, with visibility stamped in `server/router/api/v1/sse_event_helpers.go:29-37`
- Inbox/notification snippet gating (`canViewerAccessMemo`) — `server/router/api/v1/user_service_notifications.go:302-316`
- Email notification gating (a second, duplicated `canViewerAccessMemo`) — `server/notification/email.go:306-320`
- Mention notification gating (`canUserAccessMentionContext` / `shouldSkipMentionInbox`) — `server/router/api/v1/memo_mention_helpers.go:56-89`

**Alternate authority that bypasses visibility (deliberate)**
- Share tokens: `GetMemoByShare` returns a memo of *any* visibility on a valid, non-expired token (archived treated as not-found); creation restricted to creator/admin — `server/router/api/v1/memo_share_service.go:43-45`, `:151-192`; the same token is honored by the file server at `server/router/fileserver/fileserver.go:682-689`

Note: MCP is not a separate site — its catalog exposes `MemoService_ListMemos` / `MemoService_GetMemo` (`server/router/mcp/catalog.go:12-14`), so it inherits the core API checks.
