**Premise correction: there is no nightly database-cleanup job in this repository's cron scheduler — no cleanup job is scheduled at all.**

What actually exists:

**1. The cron scheduler is a standalone library with zero callers.** `internal/scheduler/` (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) is a self-contained cron package, but nothing in the application wires it up. Grepping for imports of `github.com/usememos/memos/internal/scheduler` across all Go files returns only files inside the package itself:
- `internal/scheduler/example_test.go:10`
- `internal/scheduler/integration_test.go:13`

No job is registered anywhere in `cmd/`, `server/`, or `store/`, so no schedule is live.

**2. The "2 AM cleanup" you may be thinking of is documentation, not a job.** Three places show a cleanup job at `0 2 * * *`, all illustrative:
- `internal/scheduler/README.md:33-38` — Quick Start example, `Name: "daily-cleanup"`, prints "Running cleanup..."
- `internal/scheduler/doc.go:15-18` — package doc, `Name: "daily-cleanup"`, comment `// Your cleanup logic here`
- `internal/scheduler/example_test.go:97-107` — `Example_multipleJobs`, `Name: "cleanup"`, prints "Cleaning up old data..."

None touch a database. The README also contains a `"0 3 * * *"` `stale-session-cleanup` snippet (`internal/scheduler/README.md:239-246`) as a naming best-practice example, likewise not real code.

**3. The real periodic work in this codebase doesn't use cron at all.** It uses `time.Ticker`, on intervals rather than clock times:
- `server/runner/s3presign/runner.go:26-31` — re-presigns S3 object URLs every 12 hours
- `server/runner/memopayload/runner.go` — memo payload rebuild runner
- `store/cache/cache.go:199-218` (interval set at `store/store.go:42`) — in-memory cache expiry sweep every 5 minutes, not a database cleanup

So if you're looking for a scheduled DB-maintenance task to modify or monitor, it doesn't exist yet — it would need to be written and registered.
