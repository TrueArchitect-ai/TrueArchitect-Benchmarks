**Convergence function:** `webhook.Post` — `internal/webhook/webhook.go:120`

The chain: each handler → `DispatchMemo*Webhook` in `server/router/api/v1/memo_service_webhooks.go`, which loads the user's stored webhooks (`s.Store.GetUserWebhooks`), sets `payload.URL = hook.Url`, and calls `webhook.PostAsync` (`internal/webhook/webhook.go:184`). `PostAsync` only enqueues onto the shared 128-slot `asyncPostQueue`; four worker goroutines started in `init()` (`:42-54`) drain it and call `Post`, which is the sole place the request is built, HMAC-signed, and sent via `safeClient.Do` (`:152`).

Notes:
- `PostAsync` is the funnel every handler hits synchronously; `Post` is the single function performing delivery. If you want the pre-queue funnel it's `PostAsync`, but the HTTP request itself only exists in `Post`.
- SSRF guards sit on both ends: `webhook.ValidateURL` at config time (`internal/webhook/validate.go:63`, called from `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`) and `safeDialContext` at dial time (`internal/webhook/webhook.go:59`), which re-resolves and blocks reserved IPs to defeat DNS rebinding — unless `webhook.AllowPrivateIPs` is set.
- Separate path, *not* part of this convergence: `GetLinkMetadata` / `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go:14,19`) fetch a caller-supplied URL through `internal/httpgetter`. That's request-supplied rather than user-*configured*, and it never touches `webhook.Post`.
