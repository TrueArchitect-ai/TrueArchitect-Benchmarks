**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the provider-agnostic `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any IdP implementation must produce. Callers work against this type rather than a concrete provider.

- **Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol implementation. It provides `IdentityProvider` backed by `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (supports PKCE via `codeVerifier`), and `UserInfo`.

Supporting evidence:
- `server/router/api/v1/auth_service_sso.go:12-13` imports both packages; `resolveSSOIdentity` (line 104) constructs the provider via `oauth2.NewIdentityProvider(identityProvider.Config.GetOauth2Config())` and returns an `*idp.IdentityProviderUserInfo`.
- `proto/store/idp.proto` confirms OAuth2 is the sole shipped protocol: the `IdentityProvider.Type` enum has only `TYPE_UNSPECIFIED` and `OAUTH2`, and `IdentityProviderConfig` is a `oneof` with a single `OAuth2Config` member (no OIDC/SAML/LDAP variants).
- Storage/API plumbing lives in `store/idp.go` and `server/router/api/v1/idp_service.go`, but those handle CRUD, not the provider abstraction itself.
