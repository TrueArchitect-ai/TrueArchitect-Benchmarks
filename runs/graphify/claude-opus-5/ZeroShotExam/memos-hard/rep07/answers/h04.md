**No** — outside `NewDBDriver`, the MySQL driver is never constructed through its public constructor anywhere in the codebase. The one exception is an in-package test that builds a bare struct literal, not the constructor.

**Evidence:**

1. **Factory is the only caller of `mysql.NewDB`** — `store/db/db.go:22` inside `NewDBDriver`:
   ```go
   case "mysql":
       driver, err = mysql.NewDB(profile)
   ```
   A repo-wide grep for `mysql.NewDB` returns exactly that one hit.

2. **Only one file imports the package at all** — `grep -rn "store/db/mysql" --include="*.go"` yields a single result: `store/db/db.go:8`. Since Go requires an import to reference `mysql.NewDB` or `mysql.DB`, no other package can construct it.

3. **All other construction sites go through the factory** — `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(profile)`. This is how the MySQL-backed integration tests (`store/db/mysql/user_delete_test.go`, `store/test/*`) get a driver.

4. **The lone direct instantiation is a struct literal in an in-package unit test** — `store/db/mysql/auth_config_test.go:12`:
   ```go
   db := &DB{}
   ```
   This is a zero-valued `DB` (nil `*sql.DB`, nil profile/config) used to exercise pure helper methods without a connection. It bypasses `NewDB` but doesn't construct a usable driver, and being in `package mysql` it needs no import.

**Contrast worth noting:** SQLite *is* constructed directly outside the factory — `sqlite.NewDB(p)` at `store/deployment_config_test.go:416` and `store/demo_seed_test.go:24`. So the "factory-only" discipline holds for MySQL and Postgres, but not SQLite.
