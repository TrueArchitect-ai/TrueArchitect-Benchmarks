**Premise correction: this repository (usememos/memos) has no per-user API rate-limiting middleware.** There is nothing to register, and no request limits exist. I searched the Go server for `rate limit` / `ratelimit` / `throttle` / `limiter` / `429` / `TooManyRequests` and found no implementation.

**What the actual middleware chain is:**

- **Echo-level** (`server/server.go:51-52`): only `middleware.Recover()` and `newCORSMiddleware(profile)`. That's the complete global chain — no rate limiter.
- **gRPC-Gateway** (`server/router/api/v1/v1.go:96-98`): a single `gatewayAuthMiddleware` that does authentication and access-policy checks only.
- **Connect RPC interceptors** (`server/router/api/v1/v1.go:133-138`): `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — all defined in `server/router/api/v1/connect_interceptors.go`. Again, no rate-limit interceptor.

Supporting evidence: `golang.org/x/time` is marked `// indirect` in `go.mod:151`, and no rate-limiting library (tollbooth, ulule/limiter, throttled) is a dependency. Echo's built-in `middleware.RateLimiter` is never used — the only `middleware.*` calls in the tree are `Recover`, `CORSWithConfig` (`server/cors.go:14`), and `StaticWithConfig` (`server/router/frontend/frontend.go:54`).

**The limits that do exist are size and concurrency caps, not per-user request rates:**

| Limit | Value | Location |
|---|---|---|
| Max API request body | 256 MiB (`256 << 20`) | `server/router/api/v1/v1.go:20`, applied at `:126`, `:141`, `:144` |
| Max upload buffer (default) | 32 MiB (`32 << 20`) | `server/router/api/v1/attachment_service.go:27` |
| Concurrent image processing | 2 (process-wide semaphore) | `server/router/api/v1/v1.go:60` |
| Concurrent thumbnail generation | 3 (process-wide semaphore) | `server/router/api/v1/v1.go:59`, `server/router/fileserver/fileserver.go:45-46` |

The image-processing semaphore is the one thing that can return a rate-limit-flavored error — `codes.ResourceExhausted, "too many image processing requests"` at `server/router/api/v1/attachment_service.go:160` — but it's a global concurrency gate shared by all users, keyed to nothing, and it blocks rather than counts requests per interval.

The only mention of rate limiting in the codebase is aspirational: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a documented future consideration.
