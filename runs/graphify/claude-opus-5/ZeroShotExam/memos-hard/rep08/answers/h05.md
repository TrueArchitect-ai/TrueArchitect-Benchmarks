**Mechanism: explicit Go code** — the `reaction` table has no foreign key to `user`, so nothing cascades; deletion is done by hand-written `DELETE FROM reaction` statements inside the delete-user transaction, in all three DB drivers.

**What I checked**

1. **Schema — is there a DB-level rule?** The `reaction` table is declared with no `FOREIGN KEY`/`ON DELETE` clause in any dialect:
   - `store/migration/sqlite/LATEST.sql:92-99` (and the original `store/migration/sqlite/0.20/00__reaction.sql`)
   - `store/migration/postgres/LATEST.sql:91-98` (`store/migration/postgres/0.20/00__reaction.sql`)
   - `store/migration/mysql/LATEST.sql:91-98` (`store/migration/mysql/0.20/00__reaction.sql`)

   By contrast, tables that *do* rely on the DB declare it explicitly — e.g. `memo_share` has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`), and older sqlite tables reference `user(id) ON DELETE CASCADE` (`store/migration/sqlite/0.5/00__regenerate_foreign_keys.sql`). `reaction` is absent from every such grep hit.

2. **Delete path.** `Store.DeleteUser` (`store/user.go:171`) just delegates to the driver and clears caches (`store/user_delete.go:39`). Each driver's `DeleteUser` opens one transaction and calls `deleteUserTargetsTx`, which removes reactions **two ways**:
   - `deleteReactionsByContentIDsTx` — reactions *on* the user's memos (and the recursive comment subtree), keyed by `content_id = "memos/<uid>"`, so other people's reactions on the deleted user's content go too.
   - `deleteReactionsByCreatorTx` — reactions the user *left elsewhere*, `DELETE FROM reaction WHERE creator_id = ?`.

   Locations: `store/db/postgres/user_delete.go:96,102` with the statements at `:380-388` and `:400-403`; identical structure at `store/db/sqlite/user_delete.go:96,102,380,400` and `store/db/mysql/user_delete.go:96,102,417,437`. The content-id list is built by `memoContentIDsFromRefs` (`store/db/postgres/user_delete.go:512`) from the recursive memo-tree query at `:133-166`.

3. **Tests confirming both directions.** `store/test/user_delete_test.go:97-113` seeds reactions by the deleted user and by a peer; `:216-220` asserts only the peer's reaction on the peer's own memo survives. `server/router/api/v1/test/user_service_delete_test.go:188-209,287-289` asserts reactions on the deleted user's memo are gone while a peer's reaction on a foreign memo is kept.
