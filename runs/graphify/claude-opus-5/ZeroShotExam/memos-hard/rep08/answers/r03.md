**Premise correction: there is no nightly database-cleanup job registered in this repository's cron scheduler.** The `internal/scheduler` package is a standalone, general-purpose cron library — nothing in the production code registers any job with it, database-cleanup or otherwise.

What's actually there:

- **`internal/scheduler/`** (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) is a self-contained cron scheduler library. Its only importers are its own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No file under `cmd/`, `server/`, or `store/` imports it, so no job is ever registered or started at runtime.
- The `"0 2 * * *"` (2 AM daily) schedule you may have seen is **documentation/example code only**, not a live job — it appears in `internal/scheduler/doc.go:16` (a `"daily-cleanup"` doc comment), `internal/scheduler/README.md` (Quick Start snippet), and `internal/scheduler/example_test.go:100` (`Example_multipleJobs`, a `"cleanup"` job that just prints "Cleaning up old data..."). None of these touch a database.
- The only background job that actually runs in this codebase is **not cron-based and not a cleanup**: `server/runner/s3presign/runner.go:27` uses a plain `time.NewTicker` with `runnerInterval = time.Hour * 12`, re-presigning S3 attachment URLs every 12 hours from process start (not at a fixed wall-clock time).

So if you're looking for where nightly DB maintenance happens, it doesn't exist yet — the scheduler is available infrastructure that hasn't been wired into the server.
