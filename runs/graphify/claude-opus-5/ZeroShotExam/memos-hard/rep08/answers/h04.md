**No** — outside `NewDBDriver`, nothing constructs the MySQL store driver, with one narrow test-only exception.

**Evidence:**

1. **Single constructor, single call site.** `mysql.NewDB` is defined at `store/db/mysql/mysql.go:20` and is the only exported constructor in that package (`grep "func NewDB\|func New("` over `store/db/mysql/*.go` returns just that one). Its only call site in the whole repo is `store/db/db.go:22`, inside the `case "mysql":` arm of `NewDBDriver`.

2. **The package is imported exactly once.** `grep -rn "db/mysql" --include="*.go"` returns a single hit: `store/db/db.go:8`. No other Go package imports `store/db/mysql`, so no other package *can* construct it.

3. **The struct is unexported-by-fields anyway.** `store/db/mysql/mysql.go:14-18` — `DB{db, profile, config}` has all-unexported fields, so an external package couldn't build a usable value even if it imported the package.

4. **Test/bench helpers go through the factory too.** `store/test/store.go:28`, `store/test/store.go:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(profile)` rather than reaching for `mysql.NewDB`.

**The one exception:** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — an in-package unit test building a zero-value `DB` to exercise `IsRetryableAuthenticationMutationError`. It never opens a connection and isn't reachable from outside the package. (Postgres has the identical pattern at `store/db/postgres/auth_config_test.go:12`.)

One thing to not mistake for a direct construction: `store/test/containers.go:145` calls `sql.Open("mysql", dsn)`. That is the third-party `go-sql-driver/mysql` registered with `database/sql` for container health-checking, not the memos `store.Driver` implementation.
