Notes worth flagging:

- **The image bytes never leave the database.** The avatar is stored inline in the `user.avatar_url` column as a `data:<mime>;base64,...` URI (regex at `fileserver.go:93`), so the last hop is decoding that string — there is no filesystem/S3 hop like attachments have. `parseDataURI` returns the bytes, they're MIME-checked against `avatarAllowedTypes` (`fileserver.go:73`), and written with `c.Blob` under `Cache-Control: public, max-age=3600` plus the security headers from `setSecurityHeaders`.
- **Cache is bypassed here.** `Store.GetUser` only consults `userCache` when `find.ID` is set (`store/user.go:149`); this lookup is by `Username`, so it always falls through to `ListUsers` and hits SQL — though the fetched row is then written into the cache by ID.
- **Authorization is instance-wide, not per-user.** Any other user's avatar is served to any viewer; the only gate is that on a private instance (no `InstanceURL` → `Profile.AllowAnonymous()` false) the requester must authenticate.
