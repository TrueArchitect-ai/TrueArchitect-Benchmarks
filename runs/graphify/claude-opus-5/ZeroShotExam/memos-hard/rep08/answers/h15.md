Memo visibility is enforced independently at these distinct server sites (no single shared gatekeeper — the policy is re-implemented per surface):

**Core API v1 (Connect/gRPC) — single-memo read gate**
`checkMemoReadAccess()` (archived → creator only; non-public → must be authed; private → creator only) — `server/router/api/v1/memo_service.go:39-76`, called from `GetMemo` and its parent-memo walk (`memo_service.go:355, 367`) and from `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)

**Core API v1 — list query scoping (filter pushed into the store, not a post-check)**
`ListMemos` visibility list / CEL filter injection — `server/router/api/v1/memo_service.go:219-231`
`ListMemoComments` comment-level filter — `server/router/api/v1/memo_service_comments.go:154-159`
`ListAllUserStats` / user stats scoping — `server/router/api/v1/user_service_stats.go:84-92, 218-220`
Backing SQL translation of `FindMemo.VisibilityList` — `store/db/sqlite/memo.go:96`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`

**Core API v1 — per-resource inline re-implementations (duplicated logic, not calling `checkMemoReadAccess`)**
`ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-225`
`checkAttachmentAccess` (attachment inherits its memo's visibility) — `server/router/api/v1/attachment_service.go:419-454`
`ListMemoReactions` / `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:29-41, 82-85`
`CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:41`

**SSE real-time delivery**
`SSEClient.canReceive()` — private events only to creator or admin — `server/router/api/v1/sse_hub.go:134-143` (visibility stamped onto the event in `server/router/api/v1/sse_event_helpers.go:29-37`)

**Raw file server (non-gRPC HTTP attachment serving)**
`checkAttachmentPermission()` — public+anonymous-allowed short-circuit, share-token fallback, then private → creator/admin — `server/router/fileserver/fileserver.go:650-703`

**Share-link surface (token replaces the visibility check)**
`GetMemoByShare` — unauthenticated; valid non-expired token authorizes any visibility, only archived/missing rejected — `server/router/api/v1/memo_share_service.go:151-192`

**Notification / inbox content gating**
`canViewerAccessMemo()` (API copy) — `server/router/api/v1/user_service_notifications.go:302-316`, used at `:337, 342, 370, 385`
`canViewerAccessMemo()` (second, independent copy in the email notifier) — `server/notification/email.go:306-320`, used at `:155, 187`
`canUserAccessMentionContext()` / `shouldSkipMentionInbox()` — `server/router/api/v1/memo_mention_helpers.go:56-89`

**Public unauthenticated surfaces (hardcoded PUBLIC-only)**
RSS feeds — `server/router/rss/rss.go:90, 141`
Sitemap — `server/router/frontend/frontend.go:150`

The MCP router is not a separate site — it proxies `MemoService_ListMemos` / `MemoService_GetMemo` through the same Connect handlers (`server/router/mcp/catalog.go:12-14`) and inherits their checks.
