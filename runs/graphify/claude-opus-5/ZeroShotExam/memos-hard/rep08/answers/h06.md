**Convergence function:** `webhook.Post` — `internal/webhook/webhook.go:120`

**Path shape:** each handler calls a `Dispatch*Webhook` method in `server/router/api/v1/memo_service_webhooks.go`, which loads the creator's configured endpoints via `s.Store.GetUserWebhooks`, sets `payload.URL = hook.Url`, and calls `webhook.PostAsync` (`internal/webhook/webhook.go:184`). `PostAsync` only enqueues onto the bounded `asyncPostQueue`; four `init()`-spawned workers (`webhook.go:41-52`) drain it and call `Post`, which is the sole place `http.NewRequest("POST", requestPayload.URL, …)` and `safeClient.Do(req)` happen (`webhook.go:126`, `:150`).

The URL is user-configured through `CreateUserWebhook` / `UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53`, `:106`), which validate it with `webhook.ValidateURL` (`internal/webhook/validate.go`); at dial time `safeDialContext` re-checks resolved IPs against the reserved-range list, unless `webhook.AllowPrivateIPs` is set.

Note those two write handlers themselves make an outbound *DNS* lookup to a user-supplied hostname (`net.LookupHost` in `ValidateURL`), but not an HTTP request. Separate, non-convergent outbound-HTTP paths also exist for OIDC/OAuth2 (`internal/idp/oauth2/oauth2.go:85`), link previews (`internal/httpgetter/`), and AI providers (`internal/ai/`) — those don't route through `webhook.Post`.
