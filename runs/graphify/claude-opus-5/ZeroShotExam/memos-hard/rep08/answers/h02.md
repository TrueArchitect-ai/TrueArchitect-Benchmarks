## How it works

**Where delivery executes.** `webhook.Post()` (`internal/webhook/webhook.go:120`) is the only place an outbound HTTP request is actually made — it marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and calls `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

Callers never invoke it directly on the request path. `webhook.PostAsync()` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel `asyncPostQueue`, drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each of which calls `Post`. So delivery runs on those background workers. The enqueue points are `server/router/api/v1/memo_service_webhooks.go:43` (comment created) and `:71` (memo created/updated/deleted).

**Protection against internal addresses.** Two layers:

1. *Dial-time (the real defense)* — the shared `safeClient` uses a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59-77`) resolves the host itself and rejects the connection if **any** resolved IP is reserved. Because it runs at dial time on every request, it also defeats DNS rebinding — the comment at `internal/webhook/webhook.go:29-31` says exactly this.

2. *Config-time* — `webhook.ValidateURL()` (`internal/webhook/validate.go:62`) enforces absolute URL, http/https scheme only, and non-reserved resolution when a user saves a webhook. Called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

Both layers share `isReservedIP` (`internal/webhook/validate.go:44`), which checks the IP against `reservedCIDRs` (`internal/webhook/validate.go:14-23`) — IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` (explicitly covering cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`. These are parsed once at startup into `reservedNetworks` (`internal/webhook/validate.go:28-36`).

**Escape hatch.** The global `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers at once. It's wired to the `--allow-private-webhooks` CLI flag / viper key, defaulting to `false` (`cmd/memos/main.go:49`, `:133`, `:160`) — intended for self-hosted deployments targeting LAN services.

**One gap worth noting:** the response body read at `internal/webhook/webhook.go:158` is capped at 1 MiB, but the client does not set `CheckRedirect`. A webhook endpoint on a public IP can return a 302 to `http://169.254.169.254/...` — Go's default redirect following re-dials, and since `safeDialContext` is on the Transport it *does* re-check the new target, so this is in fact still blocked. The dial-time placement is what saves it; a validate-only design would not have.
