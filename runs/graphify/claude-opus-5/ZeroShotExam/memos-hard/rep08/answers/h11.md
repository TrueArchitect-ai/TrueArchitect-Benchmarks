**The data layer** is `store/` (per `AGENTS.md` code map: "Store facade, cache, migrations, driver interface"). Its persistent entity types are the row structs — `User` (`store/user.go:29`), `Memo` (`store/memo.go:35`), `Attachment` (`store/attachment.go:16`), `Inbox` (`store/inbox.go:24`), `MemoRelation` (`store/memo_relation.go:16`), `MemoShare` (`store/memo_share.go:6`), `Reaction` (`store/reaction.go:7`), `UserIdentity` (`store/user_identity.go:8`), `UserSetting`, `IdentityProvider`, `InstanceSetting` — as distinct from the `Find*/Update*/Delete*` query-param structs alongside them.

`User` leads because it's the only entity that reaches the auth layer — `server/auth` (`server/auth/*.go`, JWT/PAT handling) uses it while no other entity does, and it's also the heaviest single consumer inside `server/router/api/v1` (57 references). `Memo` trails by one package but is the only entity referenced from `server/runner/memopayload`.

Two caveats on the counts: if you exclude test packages (`server/router/api/v1/test`), the ranking is unchanged at 6 vs. 5. And the `proto/gen/store` hits for `UserSetting`/`IdentityProvider`/`InstanceSetting` are generated protobuf messages in a package that happens to be named `store` — not references to the data-layer types.
