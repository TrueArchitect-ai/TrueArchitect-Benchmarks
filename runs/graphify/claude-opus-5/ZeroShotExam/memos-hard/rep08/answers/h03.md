**`internal/idp`; `internal/idp/oauth2`**

**Abstraction package — `internal/idp`**
- `internal/idp/idp.go:3` defines the single shared type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) — the normalized shape every provider must produce.
- The provider *kind* is modeled in the schema at `proto/store/idp.proto:11-24`: `IdentityProvider.Type` enum (`TYPE_UNSPECIFIED`, `OAUTH2`) plus `IdentityProviderConfig` as a `oneof config`, which is the extension point for additional protocols.

**Implementation package — `internal/idp/oauth2`**
- `internal/idp/oauth2/oauth2.go:20-43` — `IdentityProvider` struct built from `storepb.OAuth2Config` via `NewIdentityProvider`.
- `ExchangeToken` (line 47) does the authorization-code exchange with PKCE support, using `golang.org/x/oauth2`.
- `UserInfo` (line 83) calls the configured `userInfoUrl` and maps raw claims onto `idp.IdentityProviderUserInfo` through the configured `FieldMapping`.

This is the only concrete implementation — `internal/idp/` contains just `idp.go` and the `oauth2/` subpackage, and the only non-test importer is `server/router/api/v1/auth_service_sso.go:12-13`, which imports both the abstraction and `oauth2` (no OIDC- or SAML-specific package exists). Note the abstraction is a plain data type rather than a Go interface; the SSO handler constructs the OAuth2 provider directly, and OAuth2/OIDC providers are configured generically through URL + field-mapping settings (`proto/store/idp.proto:34-42`).
