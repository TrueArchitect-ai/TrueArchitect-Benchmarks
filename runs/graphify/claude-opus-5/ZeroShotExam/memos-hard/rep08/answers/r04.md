**Premise correction:** Neither. This repository (memos) has no message broker at all — there is no NATS, RabbitMQ/AMQP, Kafka, or Redis dependency anywhere in `go.mod`/`go.sum`, and no broker client code. There is also no separate "worker" process; webhook delivery happens in-process inside the single Go server binary.

**Actual mechanism — a buffered Go channel with in-process goroutine workers:**

- **Queue declaration:** `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, a package-level buffered channel holding at most 128 pending payloads.
- **Workers:** `internal/webhook/webhook.go:42-55` — a package `init()` starts a fixed pool of **4 goroutines**, each ranging over `asyncPostQueue` and calling `Post(payload)`; failures are only logged via `slog.Warn` (no retry, no dead-letter).
- **Producer:** `PostAsync` (`internal/webhook/webhook.go:184-196`) does a non-blocking `select` send onto the channel; if the buffer is full the payload is **dropped** with a warning (`webhook.go:191-195`). Delivery is therefore best-effort and non-durable — anything queued is lost on process restart.
- **Delivery itself:** `Post` (`internal/webhook/webhook.go:120-180`) POSTs JSON over HTTP using a shared `safeClient` with a 30s timeout and an SSRF-guarding dialer that rejects reserved/private IPs (`webhook.go:32-37`, `webhook.go:59-77`), optionally adding Standard Webhooks HMAC headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`).

**Call sites that enqueue:** `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (memo created/updated/deleted and comment-created events), which fetch subscriber URLs via `s.Store.GetUserWebhooks` — webhooks are stored as user settings (`store/user_setting.go`), not broker subscriptions.
