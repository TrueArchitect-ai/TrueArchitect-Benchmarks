**Premise correction:** Neither. There is no message broker in this repository — no NATS, no RabbitMQ, no AMQP/Kafka/Redis client appears anywhere in `go.mod` or `go.sum` (zero matches for `nats-io`, `rabbitmq`, `streadway`, `amqp091`, etc.). Webhook delivery never leaves the process.

**Actual mechanism:** an in-process buffered Go channel with a fixed pool of goroutine workers, all inside `internal/webhook/webhook.go`.

- **Queue declaration** — `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  A package-level `chan *WebhookRequestPayload` with a capacity of 128, declared in the same `var` block as the SSRF-guarded HTTP client.

- **Workers** — `internal/webhook/webhook.go:42-53`: a package `init()` spawns exactly 4 goroutines, each ranging over `asyncPostQueue` and calling `Post(payload)` for every item, logging a warning via `slog` on failure. These are ordinary goroutines started at package load; there is no lifecycle management, no graceful shutdown, and no persistence — anything still in the channel is lost if the process exits.

- **Producer** — `PostAsync` at `internal/webhook/webhook.go:184-196` does a non-blocking `select` send onto the channel with a `default` branch that **drops** the payload and logs `"Dropped webhook dispatch because the async queue is full"`. So backpressure is handled by discarding, not by broker-side buffering or retry. It also drops (and warns on) a nil payload.

- **Call sites** — `server/router/api/v1/memo_service_webhooks.go:43` and `:71` are the only producers.

- **Delivery** — `Post` (`internal/webhook/webhook.go:118`) does a plain `http.POST` through `safeClient`, whose transport uses `safeDialContext` to reject reserved/private IPs (SSRF / DNS-rebinding guard). Optional Standard Webhooks HMAC-SHA256 signing adds `webhook-id` / `webhook-timestamp` / `webhook-signature` headers.

Note there is a `store/migration/mysql/0.18/01__webhook.sql` table, but that stores webhook *subscriptions* (user-configured endpoints), not a delivery queue or outbox — there is no retry table and no redelivery path.
