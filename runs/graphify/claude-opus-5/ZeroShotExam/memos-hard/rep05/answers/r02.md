**r02.**

The premise is wrong: **there is no per-user API rate-limiting middleware in this repository.** Nothing registers a rate limiter, and there are no request-per-interval limits to report.

**Evidence**

- The Echo middleware chain in `server/server.go:50-51` is just `middleware.Recover()` and `newCORSMiddleware(profile)` — no limiter.
- The Connect RPC interceptor chain in `server/router/api/v1/v1.go:133-137` is `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`) — no rate-limit interceptor. The gRPC-Gateway path (`server/router/api/v1/v1.go:120-129`) only wraps auth + a byte-size cap.
- `golang.org/x/time` is present in `go.mod:` only as an **indirect** dependency; no rate-limiting library is used anywhere in server code.
- The only `rate limit` text in the repo is aspirational documentation for a feature that doesn't exist: `internal/email/README.md:286-295` ("### 5. Implement Rate Limiting", with an example `rate.NewLimiter`) and a TODO-style bullet at `internal/email/doc.go:86`.

**What does exist (and is likely the source of the confusion)** — all *global* resource caps, not per-user request rates:

| Limit | Value | Location |
|---|---|---|
| Max API request body | 256 MiB (`maxAPIRequestBytes`) | `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` at `v1.go:126` and `v1.go:143`, and `connect.WithReadMaxBytes` at `v1.go:141` |
| Concurrent image EXIF-stripping | 2 in flight, process-wide semaphore | `server/router/api/v1/v1.go:60`; acquired at `attachment_service.go:158`, returns `ResourceExhausted` ("too many image processing requests") at `attachment_service.go:160` |
| Concurrent thumbnail generation | 3 in flight | `server/router/api/v1/v1.go:59` and `server/router/fileserver/fileserver.go:46,116` |
| Upload size | instance setting `UploadSizeLimitMb`, defaulting to 32 MiB (`MaxUploadBufferSizeBytes`) | `server/router/api/v1/attachment_service.go:27,120-125` |

These are concurrency/size guards shared by all callers — an authenticated user can issue unlimited requests per second against any endpoint. If you need per-user throttling, it would be new work: an interceptor added to the list at `server/router/api/v1/v1.go:133-137` (covering Connect) plus Echo middleware in `server/server.go` (covering the gRPC-Gateway, file server, RSS, and MCP routes).
