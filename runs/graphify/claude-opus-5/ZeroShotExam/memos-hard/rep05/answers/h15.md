h15.

Memo visibility is not centralized — each surface that can surface memo content enforces it itself. Distinct enforcement sites:

**Core API (Connect/gRPC v1)**
- `checkMemoReadAccess` single-memo gate (public → open; protected → any authenticated user; private → creator only), called by `GetMemo` (also on the parent memo) and `ListMemoComments` — `server/router/api/v1/memo_service.go:39-67` (callers at `:356`, `:367`, and `server/router/api/v1/memo_service_comments.go:148`)
- `ListMemos` query-level visibility filter (anonymous → `PUBLIC`; self → all own; other creator → `PUBLIC,PROTECTED`) — `server/router/api/v1/memo_service.go:218-227`
- `CreateMemoComment` pre-check + forced inheritance of the parent's visibility — `server/router/api/v1/memo_service_comments.go:33-52`
- Comment listing relation filter (`visibility == "PUBLIC"` / `creator_id == N || visibility in [...]`) — `server/router/api/v1/memo_service_comments.go:156-161`
- `ListMemoRelations` memo filter applied to both directions of the relation — `server/router/api/v1/memo_relation_service.go:105-110`
- Reactions (`ListMemoReactions`, `UpsertMemoReaction`) — `server/router/api/v1/reaction_service.go:30-40`, `:83`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:213-225`
- Attachment read access for memo-linked attachments — `server/router/api/v1/attachment_service.go:437-454`
- User stats aggregation (`ListAllUserStats` / per-user stats) — `server/router/api/v1/user_service_stats.go:83-92`, `:217-221`

**Non-gRPC HTTP surfaces**
- Static file server for attachment blobs, incl. anonymous-instance rule and `share_token` fallback — `server/router/fileserver/fileserver.go:667-702`
- SSE fan-out filter — a client only receives an event if the memo is public/protected, or it is the creator/admin — `server/router/api/v1/sse_hub.go:134-144` (event visibility stamped in `server/router/api/v1/sse_event_helpers.go:29-37`)
- RSS feeds (instance and per-user), hard-restricted to `PUBLIC` — `server/router/rss/rss.go:88-92`, `:138-142`
- Sitemap generation, restricted to `PUBLIC` — `server/router/frontend/frontend.go:148-151`

**Deliberate bypass (share links)**
- `GetMemoByShare` serves any memo regardless of visibility given a valid, non-expired share token; only archived/missing memos are refused — `server/router/api/v1/memo_share_service.go:153-193`, with the matching attachment-side bypass at `server/router/fileserver/fileserver.go:684-691`

**Supporting mechanism (not a policy site)**
- `FindMemo.VisibilityList` / `Filters` translated to SQL `WHERE` clauses — `store/memo.go:69`, `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`

Related but about notification delivery rather than viewing: `server/router/api/v1/memo_mention_helpers.go:62-84`, `server/router/api/v1/user_service_notifications.go:309-312`, `server/notification/email.go:313-316`.
