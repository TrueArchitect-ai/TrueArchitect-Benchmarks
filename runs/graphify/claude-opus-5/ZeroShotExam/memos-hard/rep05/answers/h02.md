### Where delivery executes

- `webhook.Post()` — `internal/webhook/webhook.go:120` — marshals the payload, builds the POST, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and performs the actual HTTP call at `internal/webhook/webhook.go:152` via the shared `safeClient`.
- `webhook.PostAsync()` — `internal/webhook/webhook.go:184` — the entry point callers use. It enqueues onto a bounded 128-slot channel (`asyncPostQueue`, line 39), drained by 4 worker goroutines started in `init()` (lines 42–55) that each call `Post`. Overflow is dropped with a warning, so a slow endpoint can't block request handling.
- Callers: `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (memo created/updated/deleted and comment-created dispatch), which look up per-user webhooks via `s.Store.GetUserWebhooks` and set `URL` + `SigningSecret` on each payload.

### What protects it from internal addresses

Two layers, both keyed on `isReservedIP` in `internal/webhook/validate.go:44`, which tests the IP against the parsed `reservedCIDRs` list (`validate.go:14-23`: IPv4 loopback, RFC-1918 10/8, 172.16/12, 192.168/16, 169.254/16 link-local incl. cloud IMDS, plus `::1/128`, `fc00::/7`, `fe80::/10`):

1. **Dial-time enforcement (the real protection)** — `safeDialContext` at `internal/webhook/webhook.go:59` is installed as the `Transport.DialContext` of `safeClient` (`webhook.go:32-37`). It resolves the host itself and refuses the connection if *any* returned address is reserved. Because this runs per-connection rather than at config time, it also defeats DNS rebinding.
2. **Config-time validation** — `webhook.ValidateURL` at `internal/webhook/validate.go:62` rejects non-absolute URLs, non-http(s) schemes, and hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument`. Called when users save webhooks: `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

An escape hatch exists: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling both layers for self-hosted deployments targeting LAN services. Note that in the current tree nothing outside `internal/webhook/webhook_test.go` ever sets it — there is no CLI flag or env binding wired to it, so it is effectively always `false` in production.
