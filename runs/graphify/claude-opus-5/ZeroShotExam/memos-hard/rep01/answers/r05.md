**Premise correction:** There is no GraphQL in this repository. Zero matches for `graphql`, `apollo`, or `.gql` across all source, and no GraphQL dependency in `go.mod`, `go.sum`, or `web/package.json`. This is [usememos/memos](https://github.com/usememos/memos), and its public API is **Protocol Buffers + gRPC**, exposed over HTTP by grpc-gateway and Connect.

`proto/store/*.proto` holds internal persistence messages — not public API.

**REST mapping** is declarative, via `google.api.http` annotations inside the same `.proto` files — e.g. `proto/api/v1/memo_service.proto:30` maps `ListMemos` to `GET /api/v1/memos`, and `:35` maps `GetMemo` to `GET /api/v1/{name=memos/*}`.

**Codegen** — `proto/buf.gen.yaml` runs buf with five plugins: Go structs, gRPC, Connect, grpc-gateway, and google-gnostic-**OpenAPI** (the closest thing to a schema document, generated not hand-written), plus TypeScript ES output into `web/src/types/proto/`. Generated Go lands in `proto/gen/api/v1/`; regenerate with `buf generate` (`proto/README.md`).

**Server wiring** — `server/router/api/v1/v1.go:22` defines `APIV1Service`, embedding each `Unimplemented*ServiceServer`; `RegisterGateway()` at `server/router/api/v1/v1.go:65` mounts the grpc-gateway and Connect handlers onto Echo with a shared authorizer.

**Design convention** — `proto/api/v1/README.md` states the API follows [Google AIPs](https://google.aip.dev/), which is why resources are addressed by `name` (`memos/*`, `users/*`) rather than by ID.

One possible source of the confusion: `internal/filter/schema.go:60` defines a type named `Schema`, but that is the CEL-expression filter schema used for `filter=` query parameters, unrelated to GraphQL.
