**Computation site; triggers; extracted properties**

**Computation site**
- `server/runner/memopayload/runner.go:74` — `RebuildMemoPayload(ctx, memo, markdownService)`. It ensures `memo.Payload` is non-nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`runner.go:85-86`).
- The actual extraction is a single goldmark AST walk in `internal/markdown/markdown.go:356` (`(*service).ExtractAll`), returning `ExtractedData{Tags, Mentions, Property}` (`markdown.go:20-25`). The stored shape is `MemoPayload` / `MemoPayload.Property` in `proto/store/memo.proto:7-23` ("The calculated properties from the memo content").

**Triggers**
- Memo creation: `server/router/api/v1/memo_service.go:108`, in `CreateMemo`, before `s.Store.CreateMemo` (user-set `Location` is applied to the payload afterwards, at line ~112, so it isn't clobbered).
- Memo update, only when `content` is in the `UpdateMask`: `server/router/api/v1/memo_service.go:447` — the new content is assigned to `memo.Content`, the payload is rebuilt, and both `update.Content` and `update.Payload` are written. Other mask paths (visibility, pinned, state, timestamps…) do not recompute it.
- A batch backfill path exists: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) pages through all memos in batches of 100, rebuilding each payload and persisting via `Store.UpdateMemo`. Note this runner is not currently wired up — `server/server.go:153` (`startBackgroundRunners`) only starts the `s3presign` runner, and the only references to the `memopayload` package outside its own file are the two `RebuildMemoPayload` calls above. So in practice only create and content-update recompute it.

**Extracted properties** (`internal/markdown/markdown.go:356-421`)
- `Tags` — every memo tag node (`#tag`), deduplicated with case preserved via `uniquePreserveCase`.
- `Property.Title` — text of the first block-level child of the document if it is an H1 heading (`extractHeadingText`).
- `Property.HasLink` — any `gast.KindLink` node.
- `Property.HasCode` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- `Property.HasTaskList` — any `east.KindTaskCheckBox`.
- `Property.HasIncompleteTasks` — a task checkbox with `IsChecked == false`.

`ExtractAll` also collects `Mentions` (lowercased `@username`), but `RebuildMemoPayload` does not store them — they're consumed separately by `server/router/api/v1/memo_mention_helpers.go:32`. These five properties are surfaced to clients via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315-326`) as the OUTPUT_ONLY `Memo.property` field (`proto/api/v1/memo_service.proto:256`).

One adjacent thing worth distinguishing: the plain-text **snippet** used for previews is not part of this payload — it's generated on demand by `MarkdownService.GenerateSnippet` and, in the Go backend, only at `server/router/api/v1/memo_service_webhooks.go:85` (64 chars).
