**Delivery function — `Post` in `internal/webhook/webhook.go:120`; protection mechanism — `safeDialContext` + `isReservedIP` in `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

**Where delivery executes**

- `webhook.Post` (`internal/webhook/webhook.go:120`) is the function that actually marshals the payload, builds the `POST` request, attaches Standard-Webhooks HMAC headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`) when a signing secret is set, and issues the request via `safeClient.Do` (`internal/webhook/webhook.go:152`).
- It's normally reached asynchronously: `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each calling `Post`. Overflow is dropped with a warning.
- Callers are the memo lifecycle dispatchers in `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (created/updated/deleted/comment-created), which look up per-user webhooks via `s.Store.GetUserWebhooks`.

**What protects it from internal addresses**

Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which checks against the parsed `reservedCIDRs` list — IPv4 loopback, RFC-1918 ranges, `169.254.0.0/16` (cloud IMDS), and IPv6 loopback/ULA/link-local (`internal/webhook/validate.go:14-23`):

1. **Dial-time enforcement (the real guard):** `safeClient` uses a `Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`, defined at `:59`). It splits the address, resolves the host itself, and rejects the connection if *any* resolved IP is reserved — before dialing. Because the check happens at dial time on the actual resolution, it also defeats DNS rebinding (TOCTOU between validation and request).
2. **Admission-time validation:** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates/updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. It enforces a parseable absolute URL, an `http`/`https` scheme, and that the hostname doesn't resolve to a reserved IP, returning a gRPC `InvalidArgument`.

Note an escape hatch: the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling both layers for self-hosted setups targeting LAN services. Grep shows no code path in this repo that ever assigns it, so it stays at its `false` default — SSRF protection is on unless something outside the tree sets it.

Response size limiting is also in place: the response body is read through `io.LimitReader(resp.Body, 1<<20)` (`internal/webhook/webhook.go:158`), and the client has a 30s timeout.
