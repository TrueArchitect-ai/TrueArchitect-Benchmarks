**No** — outside the driver-selection factory, the MySQL driver is never constructed.

Evidence:

1. **The factory is the sole call site.** `store/db/db.go:14-30` — `NewDBDriver(profile)` switches on `profile.Driver` and calls `mysql.NewDB(profile)` for the `"mysql"` case (`store/db/db.go:20`), alongside `sqlite.NewDB` and `postgres.NewDB`.

2. **Only one file in the whole repo imports the package.** `grep -rn "db/mysql" --include="*.go" .` (excluding the package's own files) returns exactly one hit: `store/db/db.go:8`. Since `mysql.NewDB` / `mysql.DB` are only reachable through that import path, no other Go file can construct the driver.

3. **The constructor itself is the only place the struct is built in non-test code.** `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`) inside `NewDB` (`store/db/mysql/mysql.go:20`) is the only `DB{...}` literal in the package outside tests.

4. **All consumers go through the factory.** `store/test/store.go:28,50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70` call `db.NewDBDriver(...)`, not the MySQL constructor directly.

One caveat worth naming: `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — a bare zero-value struct used to invoke `IsRetryableAuthenticationMutationError` on a pure-logic method. That is inside the `mysql` package itself (not "outside the factory" in the architectural sense) and never opens a connection, so it doesn't contradict the answer.
