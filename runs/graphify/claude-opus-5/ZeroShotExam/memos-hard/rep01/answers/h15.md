Memo view-visibility is enforced independently in several places — there is no single shared authorization helper; each surface re-implements the PUBLIC / PROTECTED / PRIVATE rules.

**Core gRPC/Connect MemoService**
- `checkMemoReadAccess` (single-memo read gate: archived → creator only; non-public → must be authenticated; private → creator only) — `server/router/api/v1/memo_service.go:39-67`, called from `GetMemo` (`:356`), the parent-memo check for comments (`:367`), and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)
- `ListMemos` query-level scoping (anonymous → `VisibilityList = [PUBLIC]`; signed-in → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:217-231`
- `ListMemoComments` child-memo filter (same CEL/visibility scoping applied to the comment list) — `server/router/api/v1/memo_service_comments.go:156-161`

**Other API v1 surfaces that re-check the memo before returning memo-derived data**
- `ListMemoReactions` / `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:29-42, 83`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:213-226`
- `checkAttachmentAccess` (attachment inherits its linked memo's visibility) — `server/router/api/v1/attachment_service.go:422-455`
- User stats aggregation (`ListAllUserStats` / `GetUserStats`) — `server/router/api/v1/user_service_stats.go:82-92, 216-222`
- Share-link read path `GetMemoByShare` — deliberately bypasses visibility, substituting token validity/expiry + archived check — `server/router/api/v1/memo_share_service.go:153-194`, `:195-209` (`isMemoShareExpired`, `getActiveMemoShare`); share creation/list/delete are owner-or-admin only at `:43, :92, :133`

**Non-gRPC HTTP surfaces**
- Raw attachment/file server `checkAttachmentPermission` (public + anonymous-allowed → open; `share_token` query-param fallback; else private → creator or admin) — `server/router/fileserver/fileserver.go:650-703`
- RSS feeds (instance and per-user) hard-restricted to `VisibilityList = [PUBLIC]` — `server/router/rss/rss.go:90, 141`
- Sitemap XML restricted to `VisibilityList = [PUBLIC]` — `server/router/frontend/frontend.go:150`

**Push / notification surfaces**
- SSE broadcast delivery filter `SSEClient.canReceive` (PRIVATE events only to creator or admin) — `server/router/api/v1/sse_hub.go:115-143`, with the event's visibility/creator resolved (comments inherit parent creator) in `server/router/api/v1/sse_event_helpers.go:9-38`
- In-app notification rendering `canViewerAccessMemo` — `server/router/api/v1/user_service_notifications.go:302-316` (used at `:337, :342, :370, :385`)
- Email notifications, a second independent copy of `canViewerAccessMemo` — `server/notification/email.go:306-320` (used at `:155, :187`)
- Mention-notification eligibility `canUserAccessMentionContext` — `server/router/api/v1/memo_mention_helpers.go:55-88`

Related but write-side (not view enforcement): comment creation forces the comment's visibility to be no wider than the parent's — `server/router/api/v1/memo_service_comments.go:41, 52, 100`.
