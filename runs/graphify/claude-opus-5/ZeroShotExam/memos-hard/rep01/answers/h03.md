**`internal/idp`; `internal/idp/oauth2`**

**Abstraction — `internal/idp`** (`internal/idp/idp.go`): the package holds the provider-neutral contract, a single `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any IdP implementation must produce. It has no protocol-specific code.

**Implementation — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol that ships. Its doc comment reads "Package oauth2 implements the OAuth2 identity provider integration." It defines `IdentityProvider` wrapping `*storepb.OAuth2Config`, with `NewIdentityProvider()` (`internal/idp/oauth2/oauth2.go:27`) validating clientId/clientSecret/authUrl/tokenUrl/userInfoUrl, plus token exchange and user-info fetching that maps into `idp.IdentityProviderUserInfo`. Tests in `internal/idp/oauth2/oauth2_test.go`.

Supporting evidence that OAuth2 is the sole implementation:
- `proto/store/idp.proto:11-14` — the `IdentityProvider.Type` enum has only `TYPE_UNSPECIFIED = 0` and `OAUTH2 = 1`; the `IdentityProviderConfig` oneof has just `oauth2_config`. No SAML/OIDC/LDAP variants.
- `server/router/api/v1/auth_service_sso.go` is the only consumer, importing both packages; `resolveSSOIdentity()` (line 104) branches on provider type and calls `oauth2.NewIdentityProvider(identityProvider.Config.GetOauth2Config())` at line 121, returning `*idp.IdentityProviderUserInfo`.

Frontend counterparts (not the abstraction itself): `web/src/utils/oauth.ts`, `web/src/components/IdentityProviderButtons.tsx`, `web/src/components/Settings/SSOSection.tsx`, `web/src/pages/AuthCallback.tsx`.
