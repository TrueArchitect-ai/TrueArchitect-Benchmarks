**Convergence function — `webhook.Post` — `internal/webhook/webhook.go:120`.**

Every one of the above lands in `dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48` and `:30`), which reads the user's configured endpoints via `s.Store.GetUserWebhooks` (`store/user_setting.go:312`), sets `payload.URL = hook.Url`, and calls `webhook.PostAsync` (`internal/webhook/webhook.go:184`). `PostAsync` only enqueues onto `asyncPostQueue`; the four worker goroutines started in `init()` (`webhook.go:41-52`) drain it into `Post`, which is the sole place the HTTP request is actually built and sent (`safeClient.Do` at `webhook.go:152`).

Two notes:
- Outbound requests are SSRF-guarded at dial time by `safeDialContext` (`internal/webhook/webhook.go:58`), which rejects reserved/private IPs unless `webhook.AllowPrivateIPs` is set (`internal/webhook/validate.go:41`). The URL is validated at configuration time by `ValidateURL` in `internal/webhook/validate.go`.
- A separate outbound-HTTP path exists but does **not** converge on `Post`: `GetLinkMetadata` / `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go:14,19`) → `getLinkMetadata` → `fetchHTMLMeta` = `httpgetter.GetHTMLMeta`. That URL is per-request, not user-*configured*, so I've excluded it from the list above.
