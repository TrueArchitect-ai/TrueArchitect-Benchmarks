**Mechanism: explicit Go code** — two hand-written `DELETE FROM reaction` statements inside the user-deletion transaction, one per storage driver. There is no database-level cascade or trigger backing it.

## The deletion code

`store.DeleteUser` delegates straight to the driver (`store/user.go:171-181`), and each driver's `DeleteUser` runs everything in one transaction. Inside `deleteUserTargetsTx` two reaction deletes fire, covering both directions:

| What | Call site (sqlite / mysql / postgres) | Statement |
|---|---|---|
| Reactions *on* the user's memos (incl. others' reactions) | `user_delete.go:96` | `DELETE FROM reaction WHERE content_id IN (...)` — batched at 500 |
| Reactions *authored by* the user elsewhere | `user_delete.go:102` | `DELETE FROM reaction WHERE creator_id = ?` |

Implementations:
- `store/db/sqlite/user_delete.go:380` and `:400`
- `store/db/mysql/user_delete.go:417` and `:437`
- `store/db/postgres/user_delete.go:380` and `:400`

The `content_id` list comes from `memoContentIDsFromRefs(targets.memos)`, where `targets.memos` is the user's memo tree collected recursively by `listDeleteUserMemoTreeRecursive` (`store/db/sqlite/user_delete.go:130+`) — so reply/comment memos are covered too. Both deletes run *before* the memo rows and the user row are removed (`store/db/sqlite/user_delete.go:93-133`), so the IDs are still resolvable.

## What I checked to rule out a DB-level rule

The `reaction` table has no foreign key at all — `creator_id` and `content_id` are plain columns:

- `store/migration/sqlite/LATEST.sql:92-99`
- `store/migration/postgres/LATEST.sql:91-98`
- `store/migration/mysql/LATEST.sql:91-98`

Grepping `foreign key|on delete|create trigger` across all of `store/migration/` returns no hits touching `reaction`. The only cascade in the schema is `memo_share.memo_id → memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`, and the mysql/postgres equivalents at `:108`) — unrelated to reactions. So if the Go code were removed, reactions would be orphaned, not cleaned up.

## Test evidence

`store/test/user_delete_test.go` seeds three reactions (lines 97-113) and asserts after deletion that a peer's reaction on a *peer's* memo survives while the rest are gone (lines 217-220), confirming the delete is scoped rather than global.
