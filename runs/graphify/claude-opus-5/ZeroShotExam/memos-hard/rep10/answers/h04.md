**No** — outside `store/db/db.go`'s `NewDBDriver` factory, nothing constructs the MySQL store driver.

Evidence:

1. **Only one importer of the package.** `grep -rn "db/mysql" --include="*.go" .` (excluding the package's own files) returns exactly one hit: `store/db/db.go:8`, the factory file. Since `mysql.DB`/`mysql.NewDB` can only be reached via that import path, no other package can construct it.

2. **The factory is the sole call site.** `mysql.NewDB(profile)` appears once, at `store/db/db.go:22`, inside the driver switch in `NewDBDriver` (`store/db/db.go:14-30`). All callers go through that function — `store/test/store.go:28`, `store/test/store.go:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(...)`, never the concrete constructor.

3. **Struct literals.** `grep -rn "DB{" store/db/mysql/` yields only:
   - `store/db/mysql/mysql.go:29` — `driver := DB{profile: profile}`, inside `NewDB` itself.
   - `store/db/mysql/auth_config_test.go:12` — `db := &DB{}`, an in-package (`package mysql`) unit test that builds a zero-valued struct purely to call the pure method `IsRetryableAuthenticationMutationError`. No connection or profile is involved, and being in-package it isn't reachable from elsewhere.

Two related things that are *not* counterexamples: `store/test/containers.go:145` calls `sql.Open("mysql", dsn)` and `containers.go:363` uses `mysqldriver.ParseDSN` — those use the `go-sql-driver/mysql` SQL driver directly for test-container setup, not the Memos `store.Driver` implementation. By contrast, the SQLite driver *is* bypassed in places (`sqlite.NewDB` at `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416`), which makes the MySQL driver's exclusive routing through the factory a deliberate contrast rather than an accident of the grep.
