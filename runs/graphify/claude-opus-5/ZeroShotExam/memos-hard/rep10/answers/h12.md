## The three candidates

`CreateMemo` is declared once on the `store.Driver` interface (`store/driver.go:29`) and implemented three times:

- `store/db/sqlite/memo.go:16`
- `store/db/mysql/memo.go`
- `store/db/postgres/memo.go`

Static grep alone can't disambiguate these — the call site is an interface dispatch.

## How the winner was determined

I followed the value that picks the implementation, from process start to dispatch:

1. **Default flag value.** `cmd/memos/main.go:122` sets `viper.SetDefault("driver", "sqlite")`, and the flag itself defaults the same way: `rootCmd.PersistentFlags().String("driver", "sqlite", "database driver")` (`cmd/memos/main.go:130`). With no flags, `viper.GetString("driver")` returns `"sqlite"`.
2. **Into the profile.** That value is read into `Profile.Driver` at `cmd/memos/main.go:43`. `internal/profile/profile.go:110` confirms sqlite is the assumed default — it synthesizes a DSN (`memos_prod.db` under the data dir) only when `Driver == "sqlite" && DSN == ""`, which is exactly the no-flags case.
3. **Factory switch.** `db.NewDBDriver` (`store/db/db.go`) switches on `profile.Driver`; `"sqlite"` → `sqlite.NewDB(profile)` (`store/db/sqlite/sqlite.go`), returning a `*sqlite.DB` as the `store.Driver`.
4. **No decorator in between.** `store.New` (`store/store.go:38`) stores that driver as-is — its caches cover instance settings/users/user settings, not memos — so nothing intercepts memo writes.
5. **Dispatch.** The API handler `APIV1Service.CreateMemo` calls `s.Store.CreateMemo` (`server/router/api/v1/memo_service.go:115`), which after a UID validity check delegates straight to `s.driver.CreateMemo` (`store/memo.go:109-114`) — landing on the sqlite implementation.

The same path is used for comments, which route through `APIV1Service.CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`), so there's no second write path.
