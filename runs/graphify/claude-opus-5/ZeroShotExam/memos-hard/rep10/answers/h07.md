Notes worth flagging:

- **The image bytes are not on disk or S3.** The avatar is stored inline in the `user.avatar_url` column as a base64 data URI; `serveUserAvatar` decodes it with `parseDataURI` (fileserver.go:759) and writes it with `c.Blob`. The attachment storage backends (local/S3) in the same file are not on this path.
- **The user cache is keyed by ID only** (`userCacheKey(user.ID)`, store/user.go:150), so a lookup by username always falls through to `ListUsers` → driver → SQL; the result is then cached by ID.
- **Access control:** before the lookup, `serveUserAvatar` (fileserver.go:171-179) requires an authenticated viewer only when `s.Profile.AllowAnonymous()` is false, via `getCurrentUser` → `auth.Authenticator.AuthenticateToUser` (fileserver.go:709). Otherwise any user's avatar is public. Allowed MIME types are gated by `avatarAllowedTypes` (fileserver.go:74).
