**Premise correction: there is no nightly database-cleanup job in this repository.** The cron scheduler exists as a standalone library, but nothing — cleanup or otherwise — is registered with it in production code.

What's actually there:

- `internal/scheduler/` is a self-contained, GitHub Actions-inspired cron library (`parser.go`, `job.go`, `scheduler.go`, `middleware.go`). It parses 5- and 6-field cron expressions and runs registered jobs, but it registers nothing itself.
- The package is imported **only by its own tests** — `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No file under `cmd/`, `server/`, or `store/` imports it, so the scheduler is never started by the running application.
- The `0 2 * * *` ("2 AM daily") cleanup you may be thinking of appears only in illustrative docs and examples: `internal/scheduler/README.md` (Quick Start, `daily-cleanup`), `internal/scheduler/doc.go:15-18`, and `internal/scheduler/example_test.go:98-107`. Those handlers just `fmt.Println("Cleaning up old data...")` — no database access. `README.md` also shows a `stale-session-cleanup` at `"0 3 * * *"` purely as a naming/tagging example.

The background work that actually runs is interval-based, not cron-based:

- `server/server.go:162-171` starts the S3 presign runner, which uses a `time.Ticker` at `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27-30`). It refreshes presigned URLs; it deletes nothing.
- `store/cache/cache.go:199-218` runs an in-memory cache expiry loop every 5 minutes (`store/store.go:42`) — process memory only, not the database.

If you want a nightly DB cleanup, the library is ready but the wiring (a `scheduler.New()` + `Register` call in `server/server.go`'s background-runner startup) doesn't exist yet.
