**Delivery function — `Post` in `internal/webhook/webhook.go:114`; protection mechanism — `safeDialContext` / `isReservedIP` in `internal/webhook/webhook.go:56` and `internal/webhook/validate.go:44`.**

**Where delivery executes.** `webhook.Post()` (`internal/webhook/webhook.go:114`) does the actual outbound HTTP POST: it marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and calls `safeClient.Do(req)`.

It is almost never called directly by request handlers. Callers use `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded 128-slot channel `asyncPostQueue`, drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:44-52`) that each call `Post`. So delivery physically runs on those background workers, off the request path; a full queue drops the dispatch with a warning.

Dispatch is triggered from `server/router/api/v1/memo_service_webhooks.go` — `DispatchMemoCreated/Updated/DeletedWebhook` via `dispatchMemoRelatedWebhook` (line 71) and `DispatchMemoCommentCreatedWebhook` (line 43), each fanning out over the creator's registered webhooks from `s.Store.GetUserWebhooks`.

**What protects it from internal addresses.** Two layers:

1. **Dial-time SSRF guard (the real enforcement).** `safeClient` is built with a `Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:31-36`). `safeDialContext` (`internal/webhook/webhook.go:56`) splits host/port, resolves the host itself via `net.DefaultResolver.LookupHost`, and refuses the connection if *any* resolved IP is reserved. Because this happens at dial time rather than at registration time, it also defeats DNS rebinding.

2. **Registration-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates or updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument`.

Both layers share `isReservedIP` (`internal/webhook/validate.go:44`), which checks against `reservedNetworks`, parsed at startup from `reservedCIDRs` (`internal/webhook/validate.go:15-24`): loopback `127.0.0.0/8` and `::1/128`, RFC-1918 `10/8`, `172.16/12`, `192.168/16`, link-local `169.254.0.0/16` (explicitly covering the cloud IMDS address `169.254.169.254`), plus IPv6 `fc00::/7` and `fe80::/10`.

**Escape hatch.** The global `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers at once. It's wired to the `--allow-private-webhooks` flag (default `false`) in `cmd/memos/main.go:133`, bound to viper at `:160` and applied at `:49` — intended for self-hosted deployments targeting LAN services.

**Gap worth noting:** the URL is re-parsed by `http.NewRequest` and the dial guard resolves the hostname a *second* time, independently of `ValidateURL`. That's deliberate and correct for rebinding, but note the guard has no redirect policy set — `http.Client` follows redirects by default, and while each redirect hop does get re-dialed through `safeDialContext` (so an internal IP is still blocked), the port is not restricted, so non-reserved-IP-but-sensitive targets on arbitrary ports remain reachable.
