**Convergence function:** `webhook.Post` — `internal/webhook/webhook.go:117`

**The path:** each handler calls a `Dispatch*Webhook` method in `server/router/api/v1/memo_service_webhooks.go`, which loads the creator's webhooks via `s.Store.GetUserWebhooks`, sets `payload.URL = hook.Url` (the user-configured URL, registered through `CreateUserWebhook`/`UpdateUserWebhook` in `user_service_webhooks.go`), and calls `webhook.PostAsync` (`internal/webhook/webhook.go:181`). `PostAsync` only enqueues onto `asyncPostQueue`; four worker goroutines started in `init()` (`webhook.go:42-53`) drain that queue and call `Post`, which builds the request, adds the HMAC `webhook-signature` headers, and issues the actual `safeClient.Do(req)` at `webhook.go:151`.

Two notes:
- `webhook.Post` is the sole delivery point — the shared `safeClient` uses `safeDialContext` (`webhook.go:57`) to reject reserved/private IPs at dial time as SSRF/DNS-rebinding protection.
- `UpdateMemo`, `SetMemoAttachments`, and `SetMemoRelations` all reach it through the same shared helper `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`), so they are three distinct RPCs on one internal path.

Separately, `GetLinkMetadata`/`BatchGetLinkMetadata` (`memo_service_link_metadata.go`) also make outbound requests via `internal/httpgetter`, but that URL comes from the request payload rather than stored user configuration, and it does not pass through `webhook.Post`.
