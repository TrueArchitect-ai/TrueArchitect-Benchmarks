**Convergence for delivery:**

The first three funnel through the shared helper `dispatchMemoRelatedWebhook` (memo_service_webhooks.go:48), which resolves the memo creator and loads their hooks; the comment variant is separate only because it targets the *related* memo's owner (`relatedMemoCreatorID`) rather than the comment creator. Both paths build the payload via `convertMemoToWebhookPayload` (memo_service_webhooks.go:76), stamp `ActivityType`/`URL`/`SigningSecret` from each `store.GetUserWebhooks` entry, and then all four converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`).

`PostAsync` enqueues onto the buffered `asyncPostQueue` (capacity 128, `internal/webhook/webhook.go:39`), dropping with a warning if full. Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and perform the actual HTTP delivery in `webhook.Post` (`internal/webhook/webhook.go:120`), which does the JSON marshal, Standard-Webhooks HMAC signing (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and the POST via the SSRF-guarded `safeClient`.
