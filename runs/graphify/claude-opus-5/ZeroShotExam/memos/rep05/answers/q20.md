**Mechanism:** Server-Sent Events (SSE) over a plain HTTP `GET /api/v1/sse` endpoint (`Content-Type: text/event-stream`, `X-Accel-Buffering: no`, 30s heartbeat comments) — not WebSockets.

**Hub:** `server/router/api/v1/sse_hub.go` — `SSEHub` (`sse_hub.go:56`) is a mutex-guarded `map[*SSEClient]struct{}` with `Subscribe`/`Unsubscribe`/`Broadcast`/`Close`. Each client has a 32-event buffered channel; `Broadcast` (`sse_hub.go:115`) drops events for slow clients rather than blocking, and `canReceive` (`sse_hub.go:139`) filters private memos to the creator or admins.

Supporting pieces:
- `server/router/api/v1/sse_handler.go:25` — `RegisterSSERoutes` / `handleSSE`: authenticates via Bearer token, subscribes, streams `data: …` frames plus heartbeats.
- `server/router/api/v1/v1.go:36,57,125` — hub is constructed on `APIV1Service` and wired into the gateway group.
- `server/server.go:38,77,205` — server holds the hub and calls `Close()` on shutdown.
- Client consumer: `web/src/hooks/useLiveMemoRefresh.ts:203` fetches `/api/v1/sse`.
