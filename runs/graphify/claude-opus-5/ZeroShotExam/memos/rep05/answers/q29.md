`web/src/connect.ts` (authInterceptor, L154–177); access token (JWT, `Authorization: Bearer`, 15 min) + refresh token (`memos_refresh` HttpOnly cookie, 30 days) + personal access tokens (`memos_pat_` prefix); `server/auth/`

**How it works**

**Frontend interceptor — `web/src/connect.ts:154`**
- `authInterceptor` is attached to the Connect-RPC transport (`web/src/connect.ts:184`), so every generated service client (`memoServiceClient`, `userServiceClient`, etc.) goes through it.
- On each request it calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>`.
- Preflight refresh: if the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry it refreshes before sending — this exists so public endpoints like `ListMemos` don't silently return guest-scoped data.
- Reactive retry: on `Code.Unauthenticated` it refreshes once, marks the request with an `X-Retry` header to prevent loops, and retries; if that fails it calls `redirectOnAuthFailure()`.
- A separate `refreshTransport` with `interceptors: []` (`web/src/connect.ts:64`) avoids recursion during refresh, and `tokenRefreshManager` (`web/src/connect.ts:29`) dedupes concurrent refreshes.

**Token storage — `web/src/auth-state.ts`**
- Access token in `localStorage` under `memos_access_token` / `memos_token_expires_at`, plus an in-memory copy.
- A `BroadcastChannel` (`memos_token_sync`) shares freshly refreshed tokens across tabs so only one tab hits the refresh endpoint.
- The refresh token itself is never touched by JS — it's an HttpOnly cookie, which is why the transport uses `credentials: "include"` (`web/src/connect.ts:56`).

**Backend validation — `server/auth/`**
- The request hits `AuthInterceptor.WrapUnary` in `server/router/api/v1/connect_interceptors.go:217`, which reads the `Authorization` header and calls `Authorizer.Authenticate` → `Authenticator.Authenticate` (`server/router/api/v1/authz.go:44`).
- `server/auth/authenticator.go:149` (`resolveBearer`) branches on the token: `memos_pat_` prefix → `AuthenticateByPAT` (SHA-256 hash lookup); otherwise → `AuthenticateByAccessTokenV2` → `ParseAccessTokenV2` (`server/auth/token.go:220`), which validates the JWT signature, signing method, and the `user.access-token` audience.
- Refresh goes through `AuthenticateByRefreshToken` (`server/auth/authenticator.go:61`), with the cookie pulled by `ExtractRefreshTokenFromCookie` (`server/auth/extract.go:23`).
- Result is placed on the context via `auth.ApplyToContext` (`server/auth/context.go`); `CheckAccess` (`server/router/api/v1/authz.go:58`) then applies the anonymous/public-method policy. Role-based admin checks stay in the service layer.
