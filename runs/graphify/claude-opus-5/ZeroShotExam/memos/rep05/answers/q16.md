`store.DeleteMemo` (`/bench/home/work/store/memo.go:140-159`) removes, in order, before calling `s.driver.DeleteMemo` on the memo row itself:

1. **Memo relation records where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relation records where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachment records linked to the memo** — listed via `ListAttachments(FindAttachment{MemoID: &delete.ID})` and deleted one by one with `s.DeleteAttachment` (`store/memo.go:148-157`), which also removes the underlying stored file/blob before the DB row (`store/attachment.go:132-149`)

Then the memo row: `s.driver.DeleteMemo(ctx, delete)` (`store/memo.go:158`).

Note on scope: reactions and comment memos are *not* handled by the store layer — the API handler `APIV1Service.DeleteMemo` deletes child comment memos first by recursing into `store.DeleteMemo` (`/bench/home/work/server/router/api/v1/memo_service.go:568-577`), and reactions are only listed there for the webhook payload, not deleted.
