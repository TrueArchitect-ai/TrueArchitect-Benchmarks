**Background runners the server actually starts**

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:160-172`). Trigger: one synchronous `RunOnce(ctx)` at startup, then a `time.NewTicker` loop on a hard-coded `runnerInterval = 12h` (`server/runner/s3presign/runner.go:28-40`). It has its own `context.CancelFunc` + WaitGroup entry so shutdown cancels it. This is the *only* thing registered under the "background runners" mechanism.
- **Store cache cleanup loops ×3** (`store/cache/cache.go:83`, `cleanupLoop` at :199) — started implicitly by `store.New` (`store/store.go:51-53` creates `instanceSettingCache`, `userCache`, `userSettingCache`). Trigger: ticker on `cacheConfig.CleanupInterval = 5m` (`store/store.go:40-45`); exits via `Close()`/`stopChan`.
- **Webhook dispatch workers ×4** (`internal/webhook/webhook.go:42-54`) — started by package `init()`, not by the server. Trigger: queue-driven, ranging over the buffered `asyncPostQueue` (cap 128); no timer.
- **Email send workers ×2** (`internal/email/email.go:16-34`) — also package `init()`. Trigger: queue-driven over `asyncEmailQueue` (cap 128); no timer.
- **HTTP serve goroutine** (`server/server.go:124`) and **signal/shutdown goroutine** (`cmd/memos/main.go:99`) — event-driven, not scheduled work.
- **Per-connection SSE heartbeat** (`server/router/api/v1/sse_handler.go:64`) — ticker created per SSE request, lives only for that connection; not a server-wide runner.

**Unused scheduling infrastructure**

- `internal/scheduler` — a full cron scheduler package (cron parser, jobs, middleware, timezone support, graceful shutdown; `scheduler.go`, `job.go`, `parser.go`, `middleware.go`, plus a README/doc.go advertising it as "included with Memos"). **It is never wired into the server.** The only non-test importers are its own `example_test.go` and `integration_test.go`; nothing in `cmd/`, `server/`, or `store/` references it. The one real periodic runner (s3presign) uses a raw `time.Ticker` instead of this package.
- `server/runner/memopayload.Runner` (`server/runner/memopayload/runner.go`) — the `Runner` type and its `RunOnce` batch-rebuild are **dead code**; nothing constructs it. Only the free function `memopayload.RebuildMemoPayload` is used, called inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447`.
