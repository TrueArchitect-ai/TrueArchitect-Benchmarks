**Mechanism:** Server-Sent Events (HTTP `text/event-stream`) over a single `GET /api/v1/sse` endpoint, Bearer-token authenticated, with a 30s heartbeat ping — `server/router/api/v1/sse_handler.go`. The browser side consumes it via a `fetch`-based stream in `web/src/hooks/useLiveMemoRefresh.ts:203` (not `EventSource`, since an auth header is needed).

**Hub path:** `server/router/api/v1/sse_hub.go` — `SSEHub` (mutex-guarded `map[*SSEClient]struct{}`, 32-event buffered channel per client, drops events for slow clients). Constructed in `server/router/api/v1/v1.go:57` and routes registered at `v1.go:125`; also held by `server/server.go:38,77` for shutdown. Event types/payload live in the same file (`memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`), with per-client visibility filtering in `canReceive` (private memos only to creator or admin).

**Memo handlers that broadcast:**
- `CreateMemo` — `server/router/api/v1/memo_service.go:163` (`memo.created`; skipped when `isSSESuppressed(ctx)`, i.e. when invoked from `CreateMemoComment`)
- `DeleteMemo` — `server/router/api/v1/memo_service.go:585` (`memo.deleted`)
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:126` (`memo.comment.created`, keyed to the parent memo)
- `dispatchMemoUpdatedSideEffects` — `server/router/api/v1/memo_update_helpers.go:71` (`memo.updated`), the shared helper called by `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`)

Reaction handlers also broadcast through the same hub: `UpsertMemoReaction` (`reaction_service.go:106`) and `DeleteMemoReaction` (`reaction_service.go:161`), both building events via `buildMemoReactionSSEEvent` in `server/router/api/v1/sse_event_helpers.go`.
