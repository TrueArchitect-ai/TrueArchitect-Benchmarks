**Engine:** Google CEL (`github.com/google/cel-go` v0.28.1, `go.mod:13`), wrapped by the project's own memo filter engine at `internal/filter/` — entry point `filter.DefaultEngine()` in `internal/filter/engine.go`.

**Mechanism (one sentence):** `Engine.Compile` runs the filter string through a `cel.Env` built from the memo schema declarations in `internal/filter/schema.go`, `internal/filter/parser.go` (`buildCondition`) lowers the CEL AST into a dialect-agnostic IR of `Condition` nodes (`internal/filter/ir.go`), and `internal/filter/render.go` walks that IR emitting a parameterized SQL fragment plus args for the target `DialectName` (`sqlite`/`mysql`/`postgres`), which `filter.AppendConditions` (`internal/filter/helpers.go`) appends to the query's `WHERE` clause.

**Call path for ListMemos:**
- `server/router/api/v1/memo_service.go:211-215` — validates `request.Filter` via `validateFilter` (defined at `server/router/api/v1/shortcut_service.go:336`, which picks the dialect from `s.Profile.Driver` and does a trial `CompileToStatement`), then appends it to `memoFind.Filters`.
- Each driver compiles the same filter list with its own dialect: `store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo.go:65-69`, `store/db/postgres/memo.go:54-58`.

**Dialect handling details** (`internal/filter/render.go`, `internal/filter/schema.go`): placeholders `?` vs `$n` (tracked via `RenderOptions.PlaceholderOffset`), JSON access (`json_extract` / `->>` / `JSON_EXTRACT`), tags (`LIKE` on SQLite, `JSON_CONTAINS` on MySQL, `@>` on Postgres), `LIKE` vs `ILIKE`, regex `~` vs `REGEXP` (SQLite via a Go-backed function in `store/db/sqlite/functions.go`), and per-dialect column expression templates like `UNIX_TIMESTAMP(%s)`.
