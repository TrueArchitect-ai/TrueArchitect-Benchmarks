**`web/src/connect.ts` (the `authInterceptor`, line 156); short-lived JWT access token (Bearer, in `localStorage` via `web/src/auth-state.ts`) + long-lived HTTP-only refresh-token cookie `memos_refresh`, plus Personal Access Tokens for programmatic callers; `server/auth/` (validated in Connect handlers by `server/router/api/v1/connect_interceptors.go`).**

**Frontend**
- `web/src/connect.ts:156` defines `authInterceptor`, registered on the single Connect-web transport (`web/src/connect.ts:184-189`) that backs every service client (`memoServiceClient`, `userServiceClient`, …). All RPCs go through it.
- Outbound: `getRequestToken()` (`web/src/connect.ts:124`) reads the access token, and *preflight-refreshes* it if it expires within 30 s (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), then sets `Authorization: Bearer <token>` (`web/src/connect.ts:97`).
- Inbound: on `Code.Unauthenticated` it refreshes once and replays the request with an `X-Retry: true` header to prevent loops (`web/src/connect.ts:164-176`); if the refresh fails it calls `redirectOnAuthFailure()`.
- Refresh itself uses a *separate* transport with `interceptors: []` to avoid recursion (`web/src/connect.ts:65-72`), calling `AuthService.refreshToken` with `credentials: "include"` so the cookie is sent. Concurrent refreshes are deduped by `tokenRefreshManager` (`web/src/connect.ts:30`), which also serializes against the proactive `web/src/hooks/useTokenRefreshOnFocus.ts`.

**Token storage** — `web/src/auth-state.ts`: access token + expiry in `localStorage` (`memos_access_token`, `memos_token_expires_at`), synced across tabs over a `BroadcastChannel` (`memos_token_sync`) so only one tab hits the refresh endpoint. The refresh token is never touched by JS — it's the cookie.

**Backend**
- `server/router/api/v1/connect_interceptors.go:218-231` — `AuthInterceptor.WrapUnary` reads the `Authorization` header, calls `Authenticate`, enforces `CheckAccess` (returning `CodeUnauthenticated`, which is what triggers the frontend retry), and stashes the result in context.
- The actual validation package is **`server/auth/`**:
  - `server/auth/authenticator.go:149` `resolveBearer` — routes to Access Token V2 (stateless JWT) or, on the PAT prefix, `AuthenticateByPAT`; also falls back to the refresh cookie in `AuthenticateToUser` (`:191`).
  - `server/auth/token.go` — JWT generation/parsing with audience separation: `user.access-token` vs `user.refresh-token` (`ParseAccessTokenV2:220`, `ParseRefreshToken:236`), `RefreshTokenDuration` 30 days, `RefreshTokenCookieName = "memos_refresh"`.
  - `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie`.

Non-Connect paths reuse the same package: `server/router/fileserver/fileserver.go:707` documents the priority as Bearer (Access Token V2 or PAT) > refresh-token cookie.
