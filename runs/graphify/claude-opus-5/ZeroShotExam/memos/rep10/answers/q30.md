**Convergence for delivery:**

The first three funnel through the shared helper `dispatchMemoRelatedWebhook` (memo_service_webhooks.go:47), which resolves the memo creator and fans out over `Store.GetUserWebhooks`. The comment variant does its own lookup against the *related* memo owner's ID rather than the comment creator's, so it bypasses that helper — but it builds the same payload via `convertMemoToWebhookPayload` (memo_service_webhooks.go:74).

All four converge on `webhook.PostAsync` in `internal/webhook/webhook.go:184`, which enqueues onto the buffered `asyncPostQueue` (capacity 128, `webhook.go:39`; drops with a warning when full). Background workers started in `init()` (webhook.go:42-46) drain that queue and perform the actual HTTP delivery in `webhook.Post` (`internal/webhook/webhook.go:120`), which marshals the payload, adds `webhook-id`/`webhook-timestamp`/`webhook-signature` HMAC headers when a signing secret is set, and POSTs via `safeClient`.
