**Engine + path**

- **Syntax/engine:** Google **CEL** (Common Expression Language), via `github.com/google/cel-go` (`go.mod:13`, plus `ext.Sets()` etc.).
- **Where it lives:** the in-repo filter engine at `internal/filter/` — `engine.go` (entry point / `DefaultEngine()`), `schema.go` (CEL env options + memo field metadata and the `DialectSQLite`/`DialectMySQL`/`DialectPostgres` enum), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL), `helpers.go` (`AppendConditions`). Documented in `internal/filter/README.md`.

**Mechanism (one sentence)**

`ListMemos` (`server/router/api/v1/memo_service.go:178`) validates the filter string via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`, which picks the dialect from `s.Profile.Driver`) and pushes it onto `store.FindMemo.Filters`; each store driver then calls `filter.DefaultEngine()` + `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` (`store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`), which runs the three-phase pipeline — `cel-go` compiles/type-checks the expression against the memo schema env, `parser.go` normalizes the AST into a dialect-agnostic IR, and `render.go` walks the IR emitting a dialect-specific `WHERE` fragment plus bind args (`?` vs `$n` placeholders, `json_extract`/`->>`/`JSON_EXTRACT`, `LIKE` vs `ILIKE`, `LIKE`/`JSON_CONTAINS`/`@>` for tags, `strftime`/`EXTRACT`/`YEAR()` for date parts) that gets AND-ed into the query.
