`Store.DeleteMemo` (`store/memo.go:140-159`) cleans up the following before calling `s.driver.DeleteMemo` on the memo row:

1. **Memo relations where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relations where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments(FindAttachment{MemoID: &delete.ID})` and deleted one by one with `DeleteAttachment` (`store/memo.go:148-157`), which also removes the underlying stored file/blob via `DeleteAttachmentStorage` (`store/attachment.go:132-149`)

For context, the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-582`) additionally deletes each comment memo (memos with a `comment` relation pointing at this memo) by recursively calling `Store.DeleteMemo` first — but reactions are only *listed* there for the webhook payload, not explicitly deleted by the store layer.
