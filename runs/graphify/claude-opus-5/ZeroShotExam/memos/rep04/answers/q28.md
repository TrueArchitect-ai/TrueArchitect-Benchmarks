**Background work the server actually starts**

- **`s3presign` runner (`server/runner/s3presign/runner.go`)** — the only thing registered in `Server.startBackgroundRunners` (`server/server.go:158-180`). Started twice over: one synchronous `RunOnce(ctx)` at boot, then a goroutine running `Run(s3Context)`, which is a plain `time.NewTicker(12 * time.Hour)` loop (`runnerInterval`, `server/runner/s3presign/runner.go:28-40`) calling `RunOnce` on each tick, exiting on `ctx.Done()`. Its cancel func is stored in `backgroundRunnerCancels` and its goroutine tracked by `backgroundRunnerWG` for graceful shutdown (`server/server.go:182-206`). Work per run: re-presign S3 attachment URLs in batches of 100, skipping any presigned within the last 4 days.
- **Store cache cleanup loops ×3 (`store/cache/cache.go:83`, `cleanupLoop` at 199)** — not "runners" in the `server/runner` sense, but three long-lived goroutines started implicitly by `store.New` → `cache.New` for `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:47-57`). Driven by a `time.NewTicker(CleanupInterval)` with `CleanupInterval = 5 * time.Minute` (`store/store.go:39-44`); stopped via `Store.Close()` → `Cache.Close()`.
- **Per-connection SSE heartbeat (`server/router/api/v1/sse_handler.go:64`)** — request-scoped, not a server-wide worker: each open SSE stream runs a `time.NewTicker(30s)` (`sseHeartbeatInterval`, line 17) for keep-alive pings, ending when the request context ends or `SSEHub.Close()` fires during shutdown.
- **Fire-and-forget goroutines (not scheduled workers)**: webhook delivery (`internal/webhook/webhook.go:44`), email send (`internal/email/email.go:18`), PAT last-used update (`server/auth/authenticator.go:180`). These are triggered per event/request, with no timer or queue behind them.
