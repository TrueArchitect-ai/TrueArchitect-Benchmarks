**Tables: `memo`, `memo_relation`, `attachment`** (plus `memo_share` only on Postgres/MySQL, via a DB-level FK cascade — not code).

### Call path

`APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`):
1. Reads the memo, current user, reactions, attachments, relations (reads only — used for the webhook payload).
2. Lists child comment relations and calls `Store.DeleteMemo` for each comment memo (`memo_service.go:567-577`) — recursively hitting the same tables.
3. Calls `Store.DeleteMemo` for the memo itself (`memo_service.go:580`).

`Store.DeleteMemo` (`store/memo.go:140-159`) is where the explicit cascade lives:
- **`memo_relation`** — two `DeleteMemoRelation` calls, one by `memo_id`, one by `related_memo_id` (`store/memo.go:142-147`; SQL at `store/db/sqlite/memo_relation.go:137`, and the postgres/mysql equivalents).
- **`attachment`** — lists attachments by `MemoID` and calls `Store.DeleteAttachment` per row (`store/memo.go:148-157`); that also deletes the underlying file/object storage (`store/attachment.go:132-148`), which is not a table.
- **`memo`** — final `driver.DeleteMemo`, a plain `DELETE FROM memo WHERE id = ?` (`store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`).

### Two things worth flagging

- **`memo_share`** has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`, `postgres/LATEST.sql:108`, `mysql/LATEST.sql:108`). But the SQLite driver opens the DB with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so on SQLite that cascade does **not** fire and `memo_share` rows are orphaned. There is no explicit `memo_share` cleanup in the delete path (contrast `store/db/sqlite/user_delete.go:406-411`, which does it explicitly for user deletion).
- **`reaction`** is *not* touched. Reactions are fetched at `memo_service.go:545` only to build the webhook payload, and the table keys on a text `content_id` with no FK (`store/migration/sqlite/LATEST.sql:92-99`), so reactions for a deleted memo are left behind on all three backends.
