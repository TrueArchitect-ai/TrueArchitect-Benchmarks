**`web/src/connect.ts`; JWT access token (in-memory + localStorage) + refresh token (HTTP-only `memos_refresh` cookie), plus PATs server-side; `server/auth`**

**Interceptor** — `authInterceptor` in `web/src/connect.ts:156`, installed on the Connect-web transport (`web/src/connect.ts:184-189`) that backs every service client (memo, user, attachment, AI, etc.). Per request it:
- calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`web/src/connect.ts:97`)
- preflight-refreshes if the token is within 30s of expiry, so public endpoints like `ListMemos` don't silently return guest-scoped data
- on a `Code.Unauthenticated` response, refreshes once and replays the request with an `X-Retry: true` marker to prevent loops; if the refresh fails it calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`)

**Tokens** — managed in `web/src/auth-state.ts`:
- **Access token**: short-lived JWT held in a module variable and mirrored to `localStorage` under `memos_access_token` / `memos_token_expires_at`; shared across tabs via a `BroadcastChannel` (`memos_token_sync`) so only one tab refreshes.
- **Refresh token**: never touched by JS — the refresh call goes through a separate interceptor-free transport with `credentials: "include"` (`web/src/connect.ts:57-72`), so the cookie rides along. Concurrent refreshes are deduped by `tokenRefreshManager` (`web/src/connect.ts:30`), coordinating the reactive 401 path with the proactive `web/src/hooks/useTokenRefreshOnFocus.ts`.

**Backend validation** — `server/auth`:
- `server/auth/token.go` defines the constants: access-token audience `user.access-token` (15 min), refresh-token audience `user.refresh-token` (30 days), cookie name `memos_refresh`, and PAT prefix `memos_pat_`.
- `server/auth/extract.go` pulls the bearer token from the header and the refresh token from the cookie.
- `server/auth/authenticator.go` validates them — `AuthenticateByAccessTokenV2` is stateless JWT parsing; `AuthenticateByRefreshToken` verifies against the database.

Consumers are `server/router/api/v1/authz.go` (gRPC/Connect interceptor), `server/router/api/v1/sse_handler.go`, `server/router/api/v1/auth_service_session.go`, and `server/router/fileserver/fileserver.go`.
