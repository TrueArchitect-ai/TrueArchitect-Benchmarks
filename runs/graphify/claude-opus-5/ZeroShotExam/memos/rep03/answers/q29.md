**Frontend interceptor — `web/src/connect.ts:156`**
- `authInterceptor` is attached to the Connect-RPC transport (`web/src/connect.ts:184-189`) that backs every generated service client (memo, user, attachment, AI, shortcut, IdP, instance, auth). All API calls go through it.
- On each request it calls `getRequestToken()` (`connect.ts:124`) and sets `Authorization: Bearer <token>` (`connect.ts:97`).
- Two refresh paths: a *preflight* refresh when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30 s) of expiry (`connect.ts:140`), and a *reactive* refresh on a `Code.Unauthenticated` response, which retries once guarded by the `X-Retry` header, then calls `redirectOnAuthFailure()` (`connect.ts:161-177`).
- Refresh itself uses a **separate transport with no interceptors** to avoid recursion (`connect.ts:65-72`), calling `AuthService.refreshToken` with `credentials: "include"` so the refresh cookie is sent.
- Concurrent refreshes are deduped by `tokenRefreshManager` (`connect.ts:30-51`), shared with the proactive `web/src/hooks/useTokenRefreshOnFocus.ts`.

**Token storage — `web/src/auth-state.ts`**
- Access token + expiry in `localStorage` (`memos_access_token`, `memos_token_expires_at`), mirrored in memory.
- A `BroadcastChannel` (`memos_token_sync`) shares newly refreshed tokens across tabs so only one tab hits the refresh endpoint.
- The refresh token is never touched by JS — it's an HTTP-only cookie.

**Backend validation — `server/auth/`**
- `server/auth/authenticator.go` — shared `Authenticator` used by the gRPC interceptor, the Connect interceptor, and the file server, so all entry points behave identically.
- `server/auth/token.go` — defines the token kinds: JWT access tokens (15 min, audience `user.access-token`, stateless signature-only validation), JWT refresh tokens (30 days, audience `user.refresh-token`, cookie `memos_refresh`, checked against the DB for revocation), and Personal Access Tokens (prefix `memos_pat_`) for programmatic access.
- `server/auth/extract.go` — `ExtractBearerToken` for the `Authorization` header and `ExtractRefreshTokenFromCookie` for the cookie.
