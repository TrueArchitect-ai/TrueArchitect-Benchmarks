**Runners the server actually starts** (all from `Server.startBackgroundRunners`, `server/server.go:153-174`, called at the end of `Server.Start`, `server/server.go:129`):

- **s3presign runner (one-shot priming pass)** — `s3presignRunner.RunOnce(ctx)` called synchronously at startup, no timer (`server/server.go:163`).
- **s3presign runner (continuous loop)** — `time.NewTicker` at a hardcoded 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:26-39`); runs in a goroutine tracked by `backgroundRunnerWG`, stopped via its own `context.CancelFunc` on shutdown (`server/server.go:156-171`). Each tick re-presigns S3 attachment URLs whose last presign is older than 4 days.

That is the entire contents of `startBackgroundRunners` — no other runner is registered there.

**Other long-lived goroutines that exist but are not "runners" started by the server:**

- **Store cache cleanup loops (×3)** — started implicitly by `cache.New` (`go c.cleanupLoop()`, `store/cache/cache.go:83`), one each for `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`). Driven by a `time.NewTicker(c.config.CleanupInterval)` = 5 minutes (`store/cache/cache.go:41-44` config, `:201` ticker). Started when the store is constructed, not by `startBackgroundRunners`.
- **Async webhook dispatch pool (4 workers)** — `func init()` in `internal/webhook/webhook.go:42-55`; driven by a buffered channel (`asyncPostQueue`, cap 128), i.e. event-driven, not timer-driven. Starts at package init regardless of server state.
- **Async email send pool (2 workers)** — `func init()` in `internal/email/email.go:15-28`, drained from `asyncEmailQueue` (cap 128); also event-driven, package-init started.
- **Per-connection SSE heartbeat** — `time.NewTicker(sseHeartbeatInterval)` in `server/router/api/v1/sse_handler.go:64`, created per client request, not a background worker.
- **PAT last-used writer** — fire-and-forget `go func()` per authenticated request (`server/auth/authenticator.go:178-185`).
- **Signal handler** — `go func()` waiting on SIGINT/SIGTERM to call `s.Shutdown` (`cmd/memos/main.go:99-103`).

**Unused scheduling infrastructure:**

- **`internal/scheduler` — a full cron scheduler is present but the server never uses it.** It provides cron parsing (5- and 6-field), timezone support, middleware (`Recovery`, `Logging`, `Timeout`), and a `Start`/`Stop` lifecycle with its own goroutine (`internal/scheduler/scheduler.go:191`, `internal/scheduler/doc.go`, `internal/scheduler/README.md`). Grepping for `scheduler.` outside the package itself returns only its own `example_test.go` and `integration_test.go` — no production call site. The one real periodic job (s3presign) uses a raw `time.Ticker` instead.
- **`memopayload.Runner` is also dead as a runner** — `server/runner/memopayload/runner.go` defines `NewRunner`/`RunOnce` (batch rebuild of all memo payloads), but nothing constructs it. Only the standalone helper `memopayload.RebuildMemoPayload` is used, inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447`. So `server/runner/` contains two packages and only one of them is actually run in the background.
