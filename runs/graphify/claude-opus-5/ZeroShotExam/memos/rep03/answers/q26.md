**Tables affected: `memo`, `memo_relation`, `attachment`, and `memo_share` (via DB-level FK cascade on Postgres/MySQL only).**

**Directly, by explicit code:**

1. **`memo_relation`** — `store.DeleteMemo` first clears relations in both directions (`memo_id` and `related_memo_id`): `store/memo.go:141-147` → driver `DELETE FROM memo_relation` (`store/db/sqlite/memo_relation.go:149`, `store/db/postgres/memo_relation.go:164`, `store/db/mysql/memo_relation.go:137`).
2. **`attachment`** — every attachment with `memo_id = <id>` is listed and deleted one-by-one: `store/memo.go:148-157` → `store.DeleteAttachment` (`store/attachment.go:132-148`) → `DELETE FROM attachment` (e.g. `store/db/sqlite/attachment.go:212`). This also removes the underlying blob from local/S3 storage (not a table).
3. **`memo`** — the row itself: `store/memo.go:158` → `DELETE FROM memo` (`store/db/sqlite/memo.go:237-248`, `store/db/postgres/memo.go:246`, `store/db/mysql/memo.go:261`).
4. **`memo`, `memo_relation`, `attachment` again for comments** — the API layer finds all child comment memos (`MemoRelationComment` relations pointing at this memo) and calls `store.DeleteMemo` on each before deleting the parent, so the three tables above are hit once per comment too: `server/router/api/v1/memo_service.go:567-582`.

**By DB-level cascade (not code):**

5. **`memo_share`** — declared `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in all three schemas (`store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`). Caveat worth flagging: SQLite opens the DB with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so on SQLite that cascade does **not** fire and `memo_share` rows are orphaned. There is no explicit `DeleteMemoShare` call anywhere in the delete path.

**Notably not affected:**

- **`reaction`** — reactions are only *read* to build the webhook payload (`server/router/api/v1/memo_service.go:545-550`); nothing deletes them. Since `reaction.content_id` is a free-text memo name rather than an FK (`store/migration/sqlite/LATEST.sql:92-99`), these rows are left orphaned.
