**Server-Sent Events (SSE) over `GET /api/v1/sse`; `server/router/api/v1/sse_hub.go`; `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `UpsertMemoReaction`, `DeleteMemoReaction` (the update path plus attachment/relation setters go through the shared `dispatchMemoUpdatedSideEffects` helper).**

**Mechanism.** SSE, not WebSockets. `server/router/api/v1/sse_handler.go:34` sets `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`, and `X-Accel-Buffering: no`, then streams with a 30s heartbeat (`sseHeartbeatInterval`, `sse_handler.go:17`). The route is registered at `/api/v1/sse` in `sse_handler.go:25-30`, wired up from `server/router/api/v1/v1.go:125`. Auth is a Bearer token on the `Authorization` header, so the browser side uses `fetch` rather than the native `EventSource` (`web/src/hooks/useLiveMemoRefresh.ts:203`).

**Hub.** `server/router/api/v1/sse_hub.go` — `SSEHub` (line 56) holds a mutex-guarded `map[*SSEClient]struct{}` with `Subscribe`/`Unsubscribe`/`Broadcast`/`Close`. Each client gets a 32-event buffered channel; a full buffer drops the event rather than blocking the broadcaster (lines 126-130). `Broadcast` filters per client via `canReceive` (line 134): `Private` memos only reach the creator or an admin. It's constructed in `v1.go:57` and closed on shutdown from `server/server.go:205-206`.

**Broadcast sites** (event types defined at `sse_hub.go:14-21`):

| Handler | File:line | Event |
|---|---|---|
| `CreateMemo` | `memo_service.go:163` | `memo.created` |
| `DeleteMemo` | `memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `memo_service_comments.go:126` | `memo.comment.created` |
| `UpsertMemoReaction` | `reaction_service.go:106` | `reaction.upserted` |
| `DeleteMemoReaction` | `reaction_service.go:161` | `reaction.deleted` |

The `memo.updated` event is emitted indirectly through `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66-77`), which also fires the webhook. Three callers reach it: `UpdateMemo` (`memo_service.go:513`), `memo_attachment_service.go:48`, and `memo_relation_service.go:48`.

Two details worth noting: `CreateMemo`'s broadcast is conditional — it's skipped when invoked from `CreateMemoComment` (`memo_service.go:161`), so a comment creation emits only `memo.comment.created`. And for comments and reactions, `SSEEvent.Name` carries the parent memo's resource name, with `resolveSSECreatorID` picking the creator used for visibility filtering.
