**Engine:** Google CEL (`github.com/google/cel-go`), wrapped by the in-repo memo filter engine at `internal/filter/` — `engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`, `helpers.go` (documented in `internal/filter/README.md`).

**Mechanism (one sentence):** `ListMemos` validates `request.Filter` and pushes it into `memoFind.Filters` (`server/router/api/v1/memo_service.go:211-215`, validation via `validateFilter` at `server/router/api/v1/shortcut_service.go:336`), then each store driver calls `filter.DefaultEngine()` + `filter.AppendConditions(...)` with its dialect constant (`store/db/sqlite/memo.go:57-62`, `store/db/mysql/memo.go:65-69`, `store/db/postgres/memo.go:54-58`), and the engine runs a three-phase pipeline — `cel-go` compiles/type-checks the expression against the memo CEL env declared in `NewSchema()` (`internal/filter/schema.go`, only declared variables like `content`, `tags`, `pinned`, `visibility`, `has_task_list`, `now` are allowed), `buildCondition` normalizes the CEL AST into a dialect-agnostic IR (`internal/filter/parser.go` → `internal/filter/ir.go`, folding `now` to a frozen constant), and the renderer walks the IR emitting a parameterized SQL fragment plus args for the target dialect (`internal/filter/render.go`), which `AppendConditions` appends to the query's `WHERE` list (`internal/filter/helpers.go:9-26`).

**Per-dialect specifics** (all in `internal/filter/render.go` plus `Field.Expressions` overrides in `schema.go:317-327`):
- Placeholders: `?` for SQLite/MySQL, `$n` for Postgres, with `PlaceholderOffset` so fragments compose with pre-existing args (`render.go:842-849`).
- JSON payload access: `json_extract` (SQLite) vs `JSON_EXTRACT`/`JSON_CONTAINS` (MySQL) vs `->`/`->>`/`@> jsonb_build_array(...)` (Postgres) — e.g. `render.go:363-408`, `451-471`.
- Timestamp accessors and string/array length get per-dialect expressions (`render.go:219-241`, `280-308`), and schema fields can override the column expression per dialect (e.g. `UNIX_TIMESTAMP(%s)` on MySQL).
- Trivially-true filters render to empty SQL (skipped) and unsatisfiable ones to `1 = 0` (`render.go:31-57`).
