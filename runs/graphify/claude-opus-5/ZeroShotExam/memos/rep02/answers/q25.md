**Engine:** Google CEL (`github.com/google/cel-go` v0.28.1, `go.mod:13`), wrapped by the in-house memo filter engine at `internal/filter/` — `engine.go` (`NewEngine`/`Compile`/`CompileToStatement`/`DefaultEngine`), `schema.go` (CEL env + field metadata), `parser.go` (AST→IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR→SQL), `helpers.go` (`AppendConditions`).

**Mechanism (one sentence):** `ListMemos` validates `request.Filter` via `APIV1Service.validateFilter` (`server/router/api/v1/memo_service.go:211-216` → `server/router/api/v1/shortcut_service.go:336`) and stashes it in `memoFind.Filters`; at query time each store driver calls `filter.DefaultEngine()` + `filter.AppendConditions(...)` (`store/db/sqlite/memo.go:57,61`, `store/db/mysql/memo.go:65,69`, `store/db/postgres/memo.go:54,58`), which compiles the CEL string against the memo schema into an AST, normalizes it into the dialect-agnostic IR, then renders that IR per `DialectName` (`sqlite`/`mysql`/`postgres`) into a parameterized SQL fragment plus args that are appended to the query's `WHERE` clause.

Dialect differences are localized in the renderer and schema: per-field SQL templates (`Field.Expressions`, e.g. `('users/' || %s)` vs `CONCAT('users/', %s)` in `internal/filter/schema.go`), JSON access/boolean coercion and `LIKE`/`ILIKE`/`JSON_CONTAINS`/`@>` branches in `internal/filter/render.go` (~lines 360-470), and placeholder style — `$n` for Postgres with an offset for pre-existing args, `?` elsewhere (`internal/filter/render.go:842-849`, offset supplied by `AppendConditions` in `internal/filter/helpers.go`). Trivial/unsatisfiable conditions collapse to `""` or `1 = 0` (`internal/filter/render.go:41-56`). The pipeline is documented in `internal/filter/README.md`.
