**Mechanism:** Server-Sent Events (SSE) over a plain HTTP `GET /api/v1/sse` endpoint — `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`, with `: heartbeat` comment pings every 30s (`server/router/api/v1/sse_handler.go:15-52`). Not WebSockets. The browser side doesn't use `EventSource` (it needs a Bearer token) — it does a streaming `fetch("/api/v1/sse")` with `Authorization` and parses the stream in `web/src/hooks/useLiveMemoRefresh.ts:202-210`, invalidating React Query caches on each event.

**Hub:** `server/router/api/v1/sse_hub.go` — `SSEHub` (mutex-guarded `map[*SSEClient]struct{}`) with `NewSSEHub`/`Subscribe`/`Unsubscribe`/`Broadcast`/`Close`. Each client gets a 32-buffered channel; events are dropped rather than blocking a slow client (`sse_hub.go:115-132`). `canReceive` filters delivery: `Private` memos go only to the creator or an admin (`sse_hub.go:134-144`). The hub is constructed in `server/router/api/v1/v1.go:57`, routes registered at `v1.go:125`, and closed on shutdown via `server/server.go:205-207`.

`dispatchMemoUpdatedSideEffects` is the shared broadcast path for updates, called by `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`). Reaction events carry the *memo's* resource name, and comment/reaction events on a comment resolve `CreatorID` from the parent memo so private-parent visibility scoping holds (`sse_event_helpers.go:12-40`).
