**Runners the server actually starts (`Server.Start` → `startBackgroundRunners`, `server/server.go:129,153-174`):**

- **s3presign runner** (`server/runner/s3presign/runner.go`) — the only true background runner. Started twice: one synchronous `RunOnce(ctx)` at boot (`server/server.go:163`), then a goroutine running `Run(s3Context)` on a `time.NewTicker` of `runnerInterval = 12h` (`s3presign/runner.go:27-41`). Each tick re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days (5-day expiry), in batches of 100. Cancelled via a stored `context.CancelFunc` and awaited on a `sync.WaitGroup` at shutdown (`server/server.go:156-171, 176-201`).

**Other long-lived goroutines started outside `startBackgroundRunners`:**

- **HTTP serve loop** (`server/server.go:124-128`) — `httpServer.Serve(listener)`; event-driven, not scheduled.
- **Store cache cleanup loops ×3** (`store/cache/cache.go:83`, `cleanupLoop` at `:199-212`) — one per cache (`instanceSettingCache`, `userCache`, `userSettingCache`, `store/store.go:51-53`), each a ticker at `CleanupInterval = 5 * time.Minute` with `DefaultTTL = 10m`, `MaxItems = 1000` (`store/store.go:40-45`). Started implicitly by `store.New` in `cmd/memos/main.go`, stopped by `Store.Close()`.
- **Signal handler goroutine** (`cmd/memos/main.go:99`) — waits on SIGINT/SIGTERM, then `s.Shutdown`.
- **SSE heartbeat ticker** (`server/router/api/v1/sse_handler.go:64`, `sseHeartbeatInterval = 30s` at `:17`) — per-connection, lives inside the request handler; request-driven, not a server-wide runner. The `SSEHub` itself has no background goroutine (`sse_hub.go:63-67`); it's only closed at shutdown (`server/server.go:203-208`).
- **Fire-and-forget per-request goroutines** (not scheduled at all): PAT last-used update `server/auth/authenticator.go:180`, webhook dispatch `internal/webhook/webhook.go:44`, email send `internal/email/email.go:18`.

**Unused scheduling infrastructure — yes, notably:**

- **`internal/scheduler`** — a complete GitHub-Actions-style cron scheduler (5/6-field cron parser, timezone support, middleware chain, graceful shutdown; `internal/scheduler/doc.go:1-24`, `scheduler.go`, `job.go`, `parser.go`, `middleware.go`) is **never used by the server**. The only non-test importers don't exist: grep for `usememos/memos/internal/scheduler` matches only `internal/scheduler/integration_test.go:13` and `internal/scheduler/example_test.go:10`. Nothing in `cmd/` or `server/` registers a job with it — the one real periodic task (s3presign) uses a hand-rolled `time.Ticker` instead.
- **`server/runner/memopayload`'s `Runner`** (`server/runner/memopayload/runner.go:14-24`) is also dead as a runner: `memopayload.NewRunner` has zero call sites, and `Runner.RunOnce` (full memo-payload rebuild) is never invoked. Only the free function `RebuildMemoPayload` is used, inline on the request path (`server/router/api/v1/memo_service.go:108,447`).
