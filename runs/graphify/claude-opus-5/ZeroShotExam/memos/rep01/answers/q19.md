MemoService is exposed over **Connect RPC** and **REST/JSON via gRPC-Gateway** (both backed by the same `APIV1Service` gRPC method implementations).

**Connect RPC (`/memos.api.v1.MemoService/*`)** — `server/router/api/v1/connect_handler.go:40` registers it via `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` inside `RegisterConnectHandlers`; the per-method Connect wrappers that unwrap `connect.Request`/rewrap `connect.Response` around the gRPC impls live in `server/router/api/v1/connect_services.go:304` onward (under the `// MemoService` section). The mux is mounted at `server/router/api/v1/v1.go:139-144`. Generated client/handler stubs: `proto/gen/api/v1/apiv1connect/memo_service.connect.go`.

**REST/HTTP+JSON via gRPC-Gateway (`/api/v1/*`)** — `server/router/api/v1/v1.go:108`, `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)`, with the gateway mux mounted at `v1.go:128-129`. Generated gateway code: `proto/gen/api/v1/memo_service.pb.gw.go`.

Note: there is no native gRPC socket server — `grpc.NewServer` appears nowhere in non-test code, so the `memo_service_grpc.pb.go` service interface is only used indirectly through these two transports.
