**Memo lifecycle events → dispatch functions** (all defined in `server/router/api/v1/memo_service_webhooks.go`):

- `memos.memo.created`: `DispatchMemoCreatedWebhook` (`memo_service_webhooks.go:15`, called from `memo_service.go:157` in `CreateMemo`)
- `memos.memo.updated`: `DispatchMemoUpdatedWebhook` (`memo_service_webhooks.go:20`, called from `memo_update_helpers.go:67`)
- `memos.memo.deleted`: `DispatchMemoDeletedWebhook` (`memo_service_webhooks.go:25`, called from `memo_service.go:562` in `DeleteMemo`)
- `memos.memo.comment.created`: `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`, called from `memo_service_comments.go:119`)

**Convergence for delivery:**

The first three are thin wrappers over the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks via `Store.GetUserWebhooks`, builds a payload with `convertMemoToWebhookPayload`, and calls `webhook.PostAsync`. The comment case skips that helper (it targets the *related* memo's owner rather than the comment creator) but performs the same steps inline.

All four converge on `webhook.PostAsync` in `internal/webhook/webhook.go:184`, which enqueues onto the bounded `asyncPostQueue` (capacity 128, dropping with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`) drain that queue and perform the actual HTTP delivery in `webhook.Post` (`internal/webhook/webhook.go:120`) — which marshals the payload, adds Standard Webhooks HMAC-SHA256 signature headers when a signing secret is set, and POSTs via the SSRF-guarded `safeClient`.
