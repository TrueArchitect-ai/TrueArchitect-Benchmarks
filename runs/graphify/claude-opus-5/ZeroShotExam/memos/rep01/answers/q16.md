`Store.DeleteMemo` (`store/memo.go:140-159`) performs this cleanup **before** issuing the `DELETE FROM memo` row deletion:

1. **`memo_relation` rows where the memo is the source** — `driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
2. **`memo_relation` rows where the memo is the target/related memo** — `driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})` (`store/memo.go:145`)
3. **Attachments linked to the memo** — it lists them via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and calls `DeleteAttachment` on each (`store/memo.go:149-157`). `Store.DeleteAttachment` (`store/attachment.go:132-149`) additionally removes the backing blob/file via `DeleteAttachmentStorage` (local file removal or object-storage delete) before deleting the `attachment` row.

Only then does it call `driver.DeleteMemo` to remove the memo row itself (`store/memo.go:158`; e.g. the SQLite driver's plain `DELETE FROM memo WHERE id = ?` at `store/db/sqlite/memo.go:237-248`).

Note on scope: reactions and comment memos are *not* handled in the store layer — the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-583`) deletes comment memos first by recursing into `Store.DeleteMemo` for each `MemoRelationComment` relation; reactions are only listed there for the webhook payload, not explicitly deleted.
