**`APIV1Service.SignIn` — `server/router/api/v1/auth_service.go:51`**

That's the real implementation of the `AuthService.SignIn` RPC (defined in `proto/api/v1/auth_service.proto`). It:

1. **Password path** — looks up the user by username, compares the bcrypt hash against `user.PasswordHash`, and rejects if `DisallowPasswordAuth` is set for a `RoleUser` account (`auth_service.go:55-77`).
2. **SSO path** — resolves the identity provider and user via `resolveSSOIdentity` / `resolveSSOUser` (`auth_service.go:78-89`).
3. Rejects archived users, then calls `s.doSignIn(ctx, existingUser)` (`server/router/api/v1/auth_service_session.go:24`) to mint the access token and set the refresh-token cookie, returning `SignInResponse{User, AccessToken, AccessTokenExpiresAt}`.

Two thin wrappers front it, neither containing the logic:
- `ConnectServiceHandler.SignIn` — `server/router/api/v1/connect_services.go:78`, which wraps the call in `connectWithHeaderCarrier` so cookies can be set protocol-agnostically, then delegates to `APIV1Service.SignIn`.
- Generated gRPC-gateway/protobuf stubs in `proto/gen/api/v1/auth_service.pb.gw.go` and `auth_service.pb.go`.
