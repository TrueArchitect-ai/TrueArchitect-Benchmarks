**Mechanism:** Server-Sent Events (SSE) over plain HTTP — `GET /api/v1/sse`, `Content-Type: text/event-stream`, with `: heartbeat` comments every 30s and `X-Accel-Buffering: no` to defeat nginx buffering (`server/router/api/v1/sse_handler.go:25-105`). Not WebSockets. The browser side is `web/src/hooks/useLiveMemoRefresh.ts` (mounted once in `web/src/main.tsx:49`), which uses `fetch("/api/v1/sse")` rather than `EventSource` so it can send a Bearer token.

**Hub path:** `server/router/api/v1/sse_hub.go` — `SSEHub` (line 56) with `Subscribe`/`Unsubscribe`/`Broadcast`/`Close`. Each `SSEClient` gets a 32-slot buffered channel and events are dropped rather than blocking a slow client (`sse_hub.go:115-135`). Per-client filtering happens in `canReceive` (`sse_hub.go:137`): private memos only reach the creator or an admin. It's constructed in `server/router/api/v1/v1.go:57` and closed on shutdown via `server/server.go:205`.

**Memo handlers that broadcast:**

| Handler | Location | Event |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:163` | `memo.created` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:126` | `memo.comment.created` |
| `UpsertMemoReaction` | `server/router/api/v1/reaction_service.go:106` | `reaction.upserted` |
| `DeleteMemoReaction` | `server/router/api/v1/reaction_service.go:161` | `reaction.deleted` |
| `UpdateMemo`, `SetMemoRelations`, `SetMemoAttachments` | indirectly, via `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:71`) | `memo.updated` |

Two details worth noting: `CreateMemo`'s broadcast is conditional (`memo_service.go:161-163`) — it's skipped when invoked from `CreateMemoComment`, so a comment produces one `memo.comment.created` rather than a duplicate pair; there's a regression test for exactly that at `server/router/api/v1/sse_service_test.go:71` (`TestCreateMemoComment_NoDuplicateSSEBroadcast`). And the three `memo.updated` producers share one code path, so `dispatchMemoUpdatedSideEffects` is the single fan-out point for updates rather than three separate `Broadcast` calls.
