**`web/src/connect.ts` (interceptor `authInterceptor`, lines 156–178); access token (JWT, in-memory + localStorage) and refresh token (HttpOnly `memos_refresh` cookie), plus PATs supported server-side; `server/auth`**

**Frontend — how it works** (`web/src/connect.ts`):
- `authInterceptor` (`web/src/connect.ts:156`) is registered on the Connect-Web transport (`web/src/connect.ts:184-189`) used by *every* service client (memo, user, auth, attachment, AI, shortcut, IdP, instance).
- On each request it calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, `web/src/connect.ts:97`).
- Two refresh paths: **preflight** — if the token is expired within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30 s) it refreshes before sending; **reactive** — on a `Code.Unauthenticated` error it refreshes once, sets an `X-Retry: true` header to prevent loops, and retries; on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- Refresh itself goes through a **separate transport with no interceptors** (`refreshTransport`, `web/src/connect.ts:65`) to avoid recursion, calling `AuthService.refreshToken`. `fetchWithCredentials` sets `credentials: "include"` so the refresh cookie is sent.
- Concurrent refreshes are deduped by `tokenRefreshManager` (`web/src/connect.ts:30`), which also coordinates with the proactive `web/src/hooks/useTokenRefreshOnFocus.ts`.

**Token storage** (`web/src/auth-state.ts`):
- Access token in a module variable + `localStorage` keys `memos_access_token` / `memos_token_expires_at`; a `BroadcastChannel` (`memos_token_sync`) shares freshly refreshed tokens across tabs so only one tab hits the refresh endpoint.
- The refresh token is never touched by JS — it's a server-set cookie.

**Backend validation — package `server/auth`**:
- `server/auth/token.go` defines the token model: access tokens (JWT, 15 min, audience `user.access-token`), refresh tokens (JWT, 30 days, audience `user.refresh-token`, cookie `memos_refresh`), and PATs (`memos_pat_` prefix).
- `server/auth/authenticator.go` — `Authenticator.AuthenticateByAccessTokenV2` (stateless JWT parse) and `AuthenticateByRefreshToken` (parses, then checks the DB via `GetUserRefreshTokenByID` for revocation).
- `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie`.
- Wired in via `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:217-231`), which reads the `Authorization` header and delegates to `Authorizer` (`server/router/api/v1/authz.go:44`); `CheckAccess` then applies the public/protected-method and private-instance policy, and `auth.ApplyToContext` stores the result. The HTTP file server (`server/router/fileserver`) uses the same package.
