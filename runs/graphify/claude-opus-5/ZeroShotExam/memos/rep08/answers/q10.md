**`store/migration/sqlite/LATEST.sql`**

This single file contains the complete current schema (126 lines: `system_setting`, `user`, `user_setting`, `memo`, and the rest of the tables plus indexes) and is applied wholesale to a fresh, uninitialized SQLite database instead of replaying the ~50 incremental migrations under `store/migration/sqlite/0.x/`.

Supporting evidence:
- `store/migrator.go:56` — `LatestSchemaFileName = "LATEST.sql"`, documented as "This file is used to initialize fresh installations with the current schema."
- `store/migrator.go:27` — migration flow step 1: "preMigrate: Check if DB is initialized. If not, apply LATEST.sql"
- `store/migrator.go:42` — "LATEST.sql: Full schema for new installations (faster than incremental migrations)"
- `store/test/migrator_test.go:18` — `TestFreshInstall` verifies LATEST.sql applies correctly on a fresh database.

Note the equivalent files exist per driver (`store/migration/mysql/LATEST.sql`, `store/migration/postgres/LATEST.sql`); the SQLite one is the path above. Separately, `store/seed/sqlite/01__dump.sql` is demo-mode seed data, not schema.
