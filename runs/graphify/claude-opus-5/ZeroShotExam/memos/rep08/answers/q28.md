**Background workers the server actually starts**

- **s3presign runner (the only true background runner)** — `server/server.go:153-174` (`startBackgroundRunners`). Driven by a plain `time.NewTicker` at a hardcoded **12-hour interval** (`server/runner/s3presign/runner.go:27-41`). It also does one synchronous `RunOnce(ctx)` at startup (`server/server.go:163`) before the loop goroutine starts, so presigning happens immediately on boot. It gets its own `context.WithCancel` whose cancel is stored in `backgroundRunnerCancels`, and it's tracked in `backgroundRunnerWG` so `Shutdown` can wait for it (`server/server.go:140-143`, `176-201`).
- **HTTP serve goroutine** — `server/server.go:124-128`, `s.httpServer.Serve(listener)`; event-driven (incoming connections), stopped by `http.Server.Shutdown` with a 10s `shutdownTimeout`.
- **Store cache cleanup loops (3 of them)** — started indirectly, not by `Server`: `store.New` creates three `cache.New(...)` instances (`store/store.go:39-53`), and each `cache.New` spawns `go c.cleanupLoop()` (`store/cache/cache.go:83`) with a **5-minute `CleanupInterval` ticker** (`store/cache/cache.go:201`). These live for the process and stop via `Store.Close()`.
- **Signal-handler goroutine** — `cmd/memos/main.go:99-103`; triggered by SIGINT/SIGTERM (`signal.Notify`), calls `s.Shutdown`.
- **Per-request SSE heartbeat ticker** — `server/router/api/v1/sse_handler.go:64`, 30s (`sse_handler.go:17`). Request-scoped, one per connected client, not a background worker.

Fire-and-forget goroutines that are request-triggered rather than scheduled: PAT last-used updates (`server/auth/authenticator.go:180`), async email send (`internal/email/email.go:18`), webhook dispatch (`internal/webhook/webhook.go:44`).

**Unused scheduling infrastructure**

- `internal/scheduler/` is a complete, documented cron scheduler — 5/6-field cron parsing, timezone support, middleware chain, graceful shutdown (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`, `README.md`) — and **nothing in the server uses it**. The only files importing `github.com/usememos/memos/internal/scheduler` are its own tests (`internal/scheduler/example_test.go`, `integration_test.go`). No production code calls `scheduler.New()` or `Scheduler.Start()`; the one real periodic job (s3presign) uses a raw ticker instead.
- Minor related note: `server/runner/memopayload/` sits under the `runner` directory but is not a background runner — `RebuildMemoPayload` is called synchronously from the memo service (`server/router/api/v1/memo_service.go:108,447`).
