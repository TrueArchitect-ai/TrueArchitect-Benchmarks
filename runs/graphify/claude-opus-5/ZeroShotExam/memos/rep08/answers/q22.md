**Flow:**

1. `CreateMemo` calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)` at `server/router/api/v1/memo_service.go:157`, logging a warning on failure rather than failing the request.
2. `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`) delegates to `dispatchMemoRelatedWebhook` with activity type `"memos.memo.created"`. That helper resolves the memo creator, loads `s.Store.GetUserWebhooks(ctx, creatorID)`, builds a `webhook.WebhookRequestPayload` per hook (via `convertMemoToWebhookPayload`), copies in `hook.Url` and `hook.SigningSecret`, and calls `webhook.PostAsync(payload)`.
3. Delivery is done by the `internal/webhook` package (`internal/webhook/webhook.go`). `PostAsync` enqueues onto a bounded 128-slot channel drained by 4 worker goroutines (dropping with a warning if full); each worker calls `Post`, which JSON-marshals the payload and POSTs it with a shared `safeClient` (30s timeout, SSRF-guarding `safeDialContext` that rejects reserved/private IPs).
4. Signing (only when the hook has a secret) follows the Standard Webhooks scheme in `Post`: the secret is resolved by `resolveSigningKey` (a `whsec_<base64>` secret is base64-decoded to raw key bytes, otherwise used verbatim), then HMAC-SHA256 over `msgID + "." + timestamp + "." + body`, base64-encoded. It is sent as headers `webhook-id` (`msg_<uuid>`), `webhook-timestamp` (Unix seconds), and `webhook-signature: v1,<sig>`. Secrets are generated by `GenerateSigningSecret` (32 random bytes, `whsec_` + base64).
