**`web/src/connect.ts`; JWT access token (in-memory + localStorage, `Authorization: Bearer`) and an HttpOnly `memos_refresh` refresh-token cookie (backend also accepts `memos_pat_` personal access tokens); `server/auth`**

How it works:

**Interceptor** — `authInterceptor` in `web/src/connect.ts:151` is registered on the single Connect-Web transport (`web/src/connect.ts:176`) that backs every service client (memo, user, auth, attachment, AI, shortcut, IdP, instance). On each request it calls `getRequestToken()` and sets `Authorization: Bearer <token>`. On a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry: true` marker to prevent loops, and on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).

**Tokens**
- *Access token* — short-lived JWT held in `web/src/auth-state.ts` (module-level var + `localStorage` keys `memos_access_token` / `memos_token_expires_at`, cross-tab sync via a `memos_token_sync` BroadcastChannel). `getRequestToken()` preflight-refreshes when within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s); `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus with a 2-minute buffer.
- *Refresh token* — never touched by JS; it's an HttpOnly cookie (`memos_refresh`, `server/auth/token.go:49`) sent because the transport's fetch uses `credentials: "include"`. Refresh goes through `AuthService.RefreshToken` on a **separate transport with no interceptors** (`web/src/connect.ts:64`) to avoid recursion, and all callers funnel through `tokenRefreshManager` so concurrent refreshes dedupe against server-side token rotation.

**Backend validation** — package `server/auth`: `Authenticator` (`server/auth/authenticator.go`) validates access tokens statelessly (`ParseAccessTokenV2`), refresh tokens against the DB, and `memos_pat_`-prefixed personal access tokens by SHA-256 hash (`server/auth/token.go`). It's wired into the Connect interceptor at `server/router/api/v1/connect_interceptors.go:227` via the `Authorizer` in `server/router/api/v1/authz.go`, and reused by the file server (`server/router/fileserver/fileserver.go:104`) and SSE handler (`server/router/api/v1/sse_handler.go`).
