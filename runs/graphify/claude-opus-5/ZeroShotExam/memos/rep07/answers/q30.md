**Convergence for delivery:**

The three memo-lifecycle dispatchers (created/updated/deleted) are thin wrappers over the shared helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo creator and fans out over `Store.GetUserWebhooks`. `DispatchMemoCommentCreatedWebhook` does not use that helper — it resolves webhooks for the *related* memo's owner instead — but it builds the same payload inline.

All four then converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue` (capacity 128, dropping with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`) drain that queue and call the actual delivery function `webhook.Post` (`internal/webhook/webhook.go:120`) — which marshals the payload, adds Standard Webhooks HMAC-SHA256 signature headers when a signing secret is set, and POSTs via the SSRF-guarded `safeClient`.

Call sites: `memo_service.go:157` (create), `memo_update_helpers.go:67` via `dispatchMemoUpdatedSideEffects` (update, also reached from `memo_attachment_service.go:48` and `memo_relation_service.go:48`), `memo_service.go:562` (delete), and `memo_service_comments.go:119` (comment).
