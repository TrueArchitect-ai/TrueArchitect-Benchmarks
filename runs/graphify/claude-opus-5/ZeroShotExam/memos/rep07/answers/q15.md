This project (usememos/memos) has no ORM tag or `TableName()` method — struct↔table mapping is done by hand-written SQL in the per-driver files under `store/db/{sqlite,mysql,postgres}/`. The domain structs live in the `store` package:

| table | Struct — path |
|---|---|
| `user` | `store.User` — `store/user.go:29` |
| `attachment` | `store.Attachment` — `store/attachment.go:16` |
| `reaction` | `store.Reaction` — `store/reaction.go:7` |

Evidence for the mapping:
- Schemas: `store/migration/sqlite/LATEST.sql:10,55,92`, `store/migration/postgres/LATEST.sql:9,54,91`, `store/migration/mysql/LATEST.sql:9,54,91`
- SQL that binds struct fields to those tables, e.g. `store/db/mysql/user.go:18` (`INSERT INTO user (...)`), `store/db/postgres/attachment.go:33,108` (`INSERT INTO attachment` / `FROM attachment`), `store/db/sqlite/reaction.go:60,113` (`FROM reaction`)

Each table also has companion query-parameter structs in the same files (`FindUser`/`UpdateUser`/`DeleteUser`, `FindAttachment`/`UpdateAttachment`/`DeleteAttachment`, `FindReaction`/`DeleteReaction`), but those are argument holders, not row mappings.
