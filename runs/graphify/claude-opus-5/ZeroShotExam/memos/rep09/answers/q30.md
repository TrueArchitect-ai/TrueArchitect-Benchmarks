**Convergence for delivery**

The three memo-lifecycle events (created/updated/deleted) first funnel through the shared private helper `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks via `s.Store.GetUserWebhooks`, builds the payload with `convertMemoToWebhookPayload`, and stamps the activity type. `DispatchMemoCommentCreatedWebhook` skips that helper (it targets the *related* memo's owner, not the comment creator) but does the equivalent inline.

All four then converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the buffered `asyncPostQueue` (cap 128, dropping with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and perform the actual HTTP delivery via `webhook.Post` (`internal/webhook/webhook.go:120`), which uses the SSRF-guarded `safeClient`.
