**`web/src/connect.ts` (the `authInterceptor` const); access token (JWT, in-memory + localStorage) + refresh token (HttpOnly cookie) + Personal Access Tokens; `server/auth`**

**Frontend interceptor — `web/src/connect.ts`**
- `authInterceptor` is registered on the Connect-RPC transport (`createConnectTransport({ ..., interceptors: [authInterceptor] })`), so every service client (`memoServiceClient`, `userServiceClient`, etc.) goes through it.
- On each request it calls `getRequestToken()` and sets `Authorization: Bearer <token>`. `fetchWithCredentials` adds `credentials: "include"` so the refresh cookie rides along.
- Two refresh paths: a **preflight** refresh when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry, and a **reactive** retry when the call fails with `Code.Unauthenticated` — it refreshes, re-sets the header, marks `X-Retry: true` to prevent loops, and retries once. On failure it calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- The refresh call itself uses a **separate transport with no interceptors** (`refreshTransport` / `refreshAuthClient`) to avoid recursion, and concurrent refreshes are deduped by `tokenRefreshManager`.

**Token storage — `web/src/auth-state.ts`**
- Access token + expiry kept in module state and mirrored to `localStorage` (`memos_access_token`, `memos_token_expires_at`); tabs share freshly-refreshed tokens over a `BroadcastChannel` (`memos_token_sync`). `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus with a larger 2-minute buffer.

**Backend validation — `server/auth`**
- `server/auth/token.go` defines the kinds: JWT access tokens (15 min, audience `user.access-token`), JWT refresh tokens (30 days, audience `user.refresh-token`, cookie `memos_refresh`), and Personal Access Tokens (prefix `memos_pat_`).
- `server/auth/authenticator.go` (`Authenticator.AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`) does the validation; `server/auth/extract.go` pulls the bearer token from the header and the refresh token from the cookie.
- It's wired in via `server/router/api/v1/connect_interceptors.go` and `authz.go`, and reused by `server/router/fileserver/fileserver.go`.
