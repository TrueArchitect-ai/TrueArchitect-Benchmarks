Before deleting the `memo` row itself, `Store.DeleteMemo` (`store/memo.go:140-158`) removes:

1. **Memo relations where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relations where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments(FindAttachment{MemoID: &delete.ID})` and each deleted with `DeleteAttachment` (`store/memo.go:148-157`). That call also removes the attachment's underlying stored blob/local file via `DeleteAttachmentStorage` before the attachment row (`store/attachment.go:132-148`).

Only then does it call `s.driver.DeleteMemo` to delete the memo row (`store/memo.go:158`; e.g. `store/db/postgres/memo.go:244`).

Note the *comment* memos are not handled here — the API layer deletes those separately by looking up comment relations and calling `store.DeleteMemo` on each child memo first (`server/router/api/v1/memo_service.go:567-580`).
