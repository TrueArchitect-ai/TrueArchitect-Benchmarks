**Server-Sent Events (SSE) over `GET /api/v1/sse`; hub at `server/router/api/v1/sse_hub.go`; handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoRelations`, `SetMemoAttachments`, `UpsertMemoReaction`, `DeleteMemoReaction`.**

**Mechanism**
- SSE, not WebSockets. `server/router/api/v1/sse_handler.go:34` sets `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no`, and flushes. The route `/api/v1/sse` is registered by `RegisterSSERoutes` (`sse_handler.go:25`), wired in `server/router/api/v1/v1.go:125`. Auth is a Bearer token on the request.
- Browser side: `web/src/hooks/useLiveMemoRefresh.ts` consumes the stream and invalidates React Query caches, with exponential-backoff reconnect.

**Hub**
- `server/router/api/v1/sse_hub.go` — `SSEHub` (mutex-guarded `clients` set) with `NewSSEHub()`, `Subscribe(userID, role)`, `Unsubscribe`, `Close`, and `Broadcast(*SSEEvent)` (`sse_hub.go:115`), which does a non-blocking send per client through a buffered channel, filtered by `SSEClient.canReceive` (`sse_hub.go:134`) using the event's `Visibility`/`CreatorID`. Constructed at `v1.go:57`, held on `Server` at `server/server.go:77`.
- Event types (`sse_hub.go:15-21`): `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`.

**Handlers that broadcast**
- `CreateMemo` — `server/router/api/v1/memo_service.go:163` (`memo.created`), skipped when `isSSESuppressed(ctx)`.
- `DeleteMemo` — `server/router/api/v1/memo_service.go:585` (`memo.deleted`).
- `UpdateMemo` — via `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:71`, `memo.updated`), called from `memo_service.go:513`.
- `SetMemoRelations` — same helper, `memo_relation_service.go:48`.
- `SetMemoAttachments` — same helper, `memo_attachment_service.go:48`.
- `CreateMemoComment` — `memo_service_comments.go:126` (`memo.comment.created` for the parent memo); it calls `CreateMemo` with `withSuppressSSE(ctx)` so the nested `memo.created` is suppressed in favor of this one.
- `UpsertMemoReaction` / `DeleteMemoReaction` — `reaction_service.go:106` and `:161`, using `buildMemoReactionSSEEvent` (`sse_event_helpers.go:24`); these are memo-scoped and carry the memo's resource name.
