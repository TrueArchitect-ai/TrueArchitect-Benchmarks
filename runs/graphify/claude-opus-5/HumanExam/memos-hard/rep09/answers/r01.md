— **Premise is wrong on both counts: there is no Redis anywhere in this codebase** (no `redis` dependency in `go.mod`/`go.sum`, no match for "redis" in any source file), **and there is no per-entity TTL configuration for users.** The actual mechanism is a process-local in-memory cache: `store/cache/cache.go` (`Cache` backed by `sync.Map`, TTL + `MaxItems` eviction + a cleanup goroutine). The `Store` holds three of them — `instanceSettingCache`, `userCache`, `userSettingCache` — all built with one shared config at `store/store.go:37-52`: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`. So user entries expire 10 minutes after write, keyed by user ID (`userCacheKey`, `store/user.go:88`); they are also refreshed on every `CreateUser`/`UpdateUser`/`ListUsers`/`GetUser` (`store/user.go:99,121,133,142,166`) and invalidated on delete (`store/user.go:178`). Cache lookup only happens when querying by ID (`store/user.go:149-156`); lookups by username go straight to the driver.
