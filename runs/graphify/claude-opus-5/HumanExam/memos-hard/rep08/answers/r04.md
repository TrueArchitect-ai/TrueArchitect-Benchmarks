— Premise is wrong: neither. There is no message broker at all — no NATS, RabbitMQ/AMQP, or Kafka dependency or code in the repo, and no queue declaration. Webhook delivery is entirely in-process: a buffered Go channel `asyncPostQueue` of capacity 128 (`internal/webhook/webhook.go:39`) drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), fed by `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`, which drops the event when the buffer is full) and delivered by `webhook.Post` (`internal/webhook/webhook.go:120`). Deliveries are lost on restart; there is no retry.
