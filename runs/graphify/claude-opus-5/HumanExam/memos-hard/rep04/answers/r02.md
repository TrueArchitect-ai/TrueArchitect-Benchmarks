— False premise: there is no per-user API rate-limiting middleware and no request limits. Nothing in the repo imports a limiter (`golang.org/x/time/rate` is absent from `go.mod`); the only match for "rate limit" is an aspirational comment in `internal/email/doc.go:86`. The full middleware stack is `middleware.Recover()` and the CORS middleware (`server/server.go:51-52`, `server/cors.go:14`), plus static/SPA middleware for the frontend (`server/router/frontend/frontend.go:54,59`) and the auth interceptor/authorizer on the gRPC-Gateway & Connect paths (`server/router/api/v1/v1.go:64-100`). What does exist are non-rate-limit concurrency bounds: semaphores for thumbnail/image work (`server/router/api/v1/v1.go:60-61`, `server/router/fileserver/fileserver.go:106,114`) and the 128-slot webhook dispatch queue (`internal/webhook/webhook.go:39`).
