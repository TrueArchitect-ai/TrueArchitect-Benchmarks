— **Premise is wrong: there is no Redis and no external cache.** The cache is a process-local in-memory `sync.Map` with TTL — `store/cache/cache.go` (`Cache` at `:67`, `New` at `:76`, TTL applied in `SetWithTTL` at `:98-114`). No Redis client is imported anywhere (`go.mod` has no redis dependency; no `redis` string in any Go file). There is no "Redis connection" to configure.
Actual mechanism: three caches are created in `store.New` — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`) — all sharing `cacheConfig` with **`DefaultTTL: 10 * time.Minute`**, `CleanupInterval: 5m`, `MaxItems: 1000` (`store/store.go:40-45`; identical defaults in `cache.DefaultConfig`, `store/cache/cache.go:57-64`). So **user entries expire 10 minutes after being set**, and are evicted early if the 1000-item cap is hit. User entries are keyed by `userCacheKey(user.ID)` (`store/user.go:88`), populated at `store/user.go:98,122,132,143,167` and invalidated on delete at `store/user_delete.go:40`.
