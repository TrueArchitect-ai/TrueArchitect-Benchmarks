— **Premise is wrong: there is no message broker — neither NATS nor RabbitMQ — and no queue is declared.** Neither library appears in `go.mod`, and no Go file references `nats`, `rabbit`, or `amqp`.
Actual mechanism: asynchronous webhook delivery uses an **in-process buffered Go channel**. `asyncPostQueue` is a `chan *WebhookRequestPayload` with capacity 128, declared at `internal/webhook/webhook.go:39`. Four worker goroutines are started in `init()` (`internal/webhook/webhook.go:42-55`) and each drains the channel calling `Post` (`:46`). Producers call `PostAsync` (`:184`), which does a non-blocking send and **drops** the payload with a warning when the buffer is full (`:189-195`). The queue is per-process and non-durable: pending webhooks are lost on restart.
