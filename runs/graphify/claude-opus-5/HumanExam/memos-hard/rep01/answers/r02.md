**Premise is wrong — no rate-limiting middleware exists.** There is no per-user or global rate limiter registered anywhere: no `golang.org/x/time/rate`, no Echo `middleware.RateLimiter`, no throttle code (the only textual match repo-wide is an aspirational comment, `internal/email/doc.go:86`). The Echo middleware chain is just `middleware.Recover()` and CORS (`server/server.go:51-52`), and the API-side interceptors do authentication/authorization only (`NewAuthorizer`, `server/router/api/v1/v1.go:67`; ACL table `server/router/api/v1/acl_config.go`). The closest thing to throttling is concurrency limiting on image work via `semaphore.Weighted` (`server/router/api/v1/v1.go:59-60`, `server/router/fileserver/fileserver.go:116`), which is not request rate limiting.
