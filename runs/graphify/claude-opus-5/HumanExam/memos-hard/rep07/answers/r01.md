— Premise is wrong: there is no Redis anywhere in this codebase. `grep -rni redis` over all `.go` files and `go.mod` returns zero hits, and there is no cache-server dependency.
The actual mechanism is an in-process, in-memory TTL cache: `store/cache/cache.go` (`cache.Interface` at `:11-32`, `Cache` implementation, `Close` at `:187`). `Store` holds three instances — `instanceSettingCache`, `userCache`, `userSettingCache` — created in `store.New` (`store/store.go:27-29, 45-52`). Config for all three: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, no eviction hook (`store/store.go:38-43`; same defaults in `cache.DefaultConfig`, `store/cache/cache.go:56-60`). So user entries get a **10-minute TTL**, swept every 5 minutes, plus explicit invalidation on update/delete (`store/user.go:167` sets, `store/user.go:179` `deleteUserCache`). Note `Store.GetUser` only consults the cache for ID lookups, not username lookups (`store/user.go:149-156`).
