— Premise is wrong: **neither NATS nor RabbitMQ is used**, and there are no webhook "workers consuming from a broker" in the external sense — no message broker of any kind appears in the repo (grep for `nats`/`rabbitmq`/`amqp`/`kafka` in Go sources and `go.mod` returns zero hits). The actual mechanism is an **in-process buffered Go channel**: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39` — drained by **4 goroutines started in `init()`** at `internal/webhook/webhook.go:42-55`, each calling `Post` (`:120`). Producers call `PostAsync` (`:184`), which drops the payload with a warning if the buffer is full (`:189-195`). This means the queue is non-durable: pending webhooks are lost on restart.
