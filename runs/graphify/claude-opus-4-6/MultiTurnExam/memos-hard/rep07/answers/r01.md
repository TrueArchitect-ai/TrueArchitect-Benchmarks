The premise is incorrect — there is no Redis connection. The cache layer uses an **in-memory cache**, not Redis.

The cache is implemented in `store/cache/cache.go` as a `Cache` struct backed by a `sync.Map` with a background cleanup goroutine. It is constructed in `store/store.go:51–53` via `cache.New(cacheConfig)` for three caches: `instanceSettingCache`, `userCache`, and `userSettingCache`.

The TTL for all entries (including user entries) is configured by the `CacheConfig` passed to `cache.New`. In `store/store.go:42–45`, a single `cacheConfig` is defined and shared across all three caches. There is no per-entry TTL differentiation for user entries specifically — all caches use the same configuration. The cache evicts entries based on the configured expiration, and stale entries are cleaned up by a background goroutine started in `cache.New`.
