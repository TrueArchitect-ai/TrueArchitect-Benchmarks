**Mechanism: explicit Go code** — reactions are deleted in a database transaction during user deletion.

**Evidence locations:**

1. **Go deletion code** — Each database driver has a `deleteReactionsByCreatorTx` function called within the user-deletion transaction:
   - `store/db/sqlite/user_delete.go:102` (call site), `:400–401` (implementation: `DELETE FROM reaction WHERE creator_id = ...`)
   - `store/db/postgres/user_delete.go:102` (call site), `:400–401` (implementation)
   - `store/db/mysql/user_delete.go:102` (call site), `:437–438` (implementation)

2. **No database-level cascade** — The `reaction` table schemas have no `FOREIGN KEY ... ON DELETE CASCADE` constraint:
   - `store/migration/sqlite/LATEST.sql:92–98`
   - `store/migration/postgres/LATEST.sql:91–97`

3. **Additionally**, reactions on the deleted user's *own content* are also cleaned up via a separate path in the same transaction (e.g., `store/db/postgres/user_delete.go:383` deletes reactions whose `content_id` matches the user's memos).
