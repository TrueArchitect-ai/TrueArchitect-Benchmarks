**Mechanism: explicit Go code.**

When a user is deleted, their reactions are removed by two explicit SQL `DELETE` statements executed within the user-deletion transaction in each database driver:

1. **Reactions on the user's content** — `DELETE FROM reaction WHERE content_id IN (...)` removes reactions others left on the deleted user's memos:
   - `store/db/sqlite/user_delete.go:383`
   - `store/db/postgres/user_delete.go:383`
   - `store/db/mysql/user_delete.go:420`

2. **Reactions created by the user** — `DELETE FROM reaction WHERE creator_id = ?` removes reactions the deleted user left on others' content:
   - `store/db/sqlite/user_delete.go:401`
   - `store/db/postgres/user_delete.go:401`
   - `store/db/mysql/user_delete.go:438`

There is no database-level `ON DELETE CASCADE` — the reaction table schemas (`store/migration/sqlite/LATEST.sql:92`, `store/migration/postgres/LATEST.sql:91`) define no foreign key constraints at all.
