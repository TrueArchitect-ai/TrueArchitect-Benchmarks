The premise is incorrect — there is no Redis connection in this codebase. The cache layer is an in-memory implementation, not Redis-backed.

Caching is handled by `store/cache/cache.go`, which implements a simple in-memory cache with `sync.Map` storage and a background cleanup goroutine. The `Store` creates three `Cache` instances in `store/store.go` (for users, user settings, and instance settings).

The `Cache` struct uses a fixed TTL of **5 minutes**, hardcoded at `store/cache/cache.go` (the `defaultExpiration` or equivalent constant), with a periodic cleanup interval. User entries are cached in `s.userCache` — set in `Store.GetUser` and `Store.ListUsers` (`store/user.go:148-167`) and evicted on delete (`store/user_delete.go:40`). There is no external cache service involved.
