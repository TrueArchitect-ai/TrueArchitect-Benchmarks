Explicit Go code. Reactions are removed by two dedicated functions within the `DeleteUser` transaction, in each DB driver:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions on the user's memos (by `content_id`), e.g. `store/db/sqlite/user_delete.go:380`, `store/db/mysql/user_delete.go:417`.
2. **`deleteReactionsByCreatorTx`** — deletes reactions the user themselves created (by `creator_id`), e.g. `store/db/sqlite/user_delete.go:400`, `store/db/mysql/user_delete.go:437`.

Both are called from `deleteUserTargetsTx` (e.g. `store/db/sqlite/user_delete.go:96-103`) inside the delete-user transaction.

There is no database-level cascade — the `reaction` table schema in all three LATEST.sql files (`store/migration/sqlite/LATEST.sql`, `store/migration/mysql/LATEST.sql`, `store/migration/postgres/LATEST.sql`) defines no foreign keys or `ON DELETE CASCADE` constraints; `creator_id` and `content_id` are plain columns with only a uniqueness constraint.
