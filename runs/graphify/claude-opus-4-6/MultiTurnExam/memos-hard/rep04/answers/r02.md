The premise is incorrect — there is no per-user API rate-limiting middleware in this codebase. The server does not implement request rate limiting. The middleware stack (registered in `server/server.go` and `server/router/api/v1/v1.go`) includes authentication, CORS, logging, recovery, and timeout, but no rate limiter. The only concurrency controls are semaphores for thumbnail generation and image processing (`thumbnailSemaphore` and `imageProcessingSemaphore` in `server/router/api/v1/v1.go`), which bound concurrent resource-intensive operations — not per-user API request rates.
