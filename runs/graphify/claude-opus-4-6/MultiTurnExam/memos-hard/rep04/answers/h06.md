The webhook path is the clearest case of multiple RPC handlers converging to a single outbound HTTP call to a user-configured URL.

**Handlers (6 that converge through the webhook path):**

1. **`CreateMemo`** — `server/router/api/v1/memo_service.go:157` dispatches `DispatchMemoCreatedWebhook`
2. **`UpdateMemo`** — `server/router/api/v1/memo_service.go:513` → `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:67`) dispatches `DispatchMemoUpdatedWebhook`
3. **`DeleteMemo`** — `server/router/api/v1/memo_service.go:562` dispatches `DispatchMemoDeletedWebhook`
4. **`CreateMemoComment`** — `server/router/api/v1/memo_service_comments.go:119` dispatches `DispatchMemoCommentCreatedWebhook` (and also fires `CreateMemo` internally, so two webhook types)
5. **`SetMemoAttachments`** — `server/router/api/v1/memo_attachment_service.go:48` → `dispatchMemoUpdatedSideEffects` dispatches `DispatchMemoUpdatedWebhook`
6. **`SetMemoRelations`** — `server/router/api/v1/memo_relation_service.go:48` → `dispatchMemoUpdatedSideEffects` dispatches `DispatchMemoUpdatedWebhook`

**Convergence function:** `webhook.Post` — `internal/webhook/webhook.go:120`

All six handlers call one of the four `Dispatch*Webhook` functions in `server/router/api/v1/memo_service_webhooks.go`, which all funnel through `webhook.PostAsync` (enqueues to a buffered channel), drained by worker goroutines that call `webhook.Post`. That function is where the actual `safeClient.Do(req)` HTTP call executes (line 152).
