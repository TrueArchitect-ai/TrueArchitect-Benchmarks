The premise is incorrect — there is no Redis connection in this codebase. The cache layer is entirely in-process, not backed by Redis.

The cache is implemented as a generic in-memory struct `Cache[K, V]` in `store/cache/cache.go`, using a Go `sync.Map` with a background cleanup goroutine. User entries are cached via `userCache` in `store/store.go`, constructed as `cache.NewCache[int32, *User]()`. Individual entries have no per-key TTL; instead, the cache performs periodic expiry sweeps based on a configurable `expireTime` and `cleanupInterval` set at construction time in `store/cache/cache.go`. Cache entries are also explicitly invalidated on writes (e.g., after `CreateUser`, `UpdateUser`, `DeleteUser` in `store/user.go`).
