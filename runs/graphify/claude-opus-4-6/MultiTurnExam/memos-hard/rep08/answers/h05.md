**Mechanism: explicit Go code**, within a database transaction during user deletion.

**Evidence locations:**

- `store/db/postgres/user_delete.go:92-127` — `deleteUserTargetsTx` explicitly calls `deleteReactionsByContentIDsTx` (line 96, removes reactions on the user's memos) and `deleteReactionsByCreatorTx` (line 102, removes reactions the user placed on any content).
- `store/db/postgres/user_delete.go:380` — `deleteReactionsByContentIDsTx` executes `DELETE FROM reaction WHERE content_id IN (...)`.
- `store/db/postgres/user_delete.go:401` — `deleteReactionsByCreatorTx` executes `DELETE FROM reaction WHERE creator_id = ?`.
- The same pattern is replicated in the other two drivers: `store/db/mysql/user_delete.go:420,438` and `store/db/sqlite/user_delete.go:383,401`.

So reactions are removed in two directions — both reactions *on* the deleted user's memos and reactions *by* the deleted user — all via explicit SQL DELETEs in Go code within the deletion transaction, not via database-level cascades.
