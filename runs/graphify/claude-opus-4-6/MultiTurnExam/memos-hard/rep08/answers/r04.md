The premise is incorrect — there is no message broker (neither NATS nor RabbitMQ). The webhook delivery workers consume from a plain **in-memory buffered Go channel**.

The queue is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutines are started in the package's `init()` function (`internal/webhook/webhook.go:42-55`) to drain this channel and call `Post()` for each payload. Callers enqueue webhooks via `PostAsync()` (`internal/webhook/webhook.go:184`), which does a non-blocking send on the channel, dropping the payload with a warning log if the buffer is full. There is no external message broker involved.
