The question's premise is incorrect — there is no nightly database-cleanup job in this codebase. The `internal/scheduler/` package defines a generic cron scheduler (`internal/scheduler/scheduler.go`), but it is never instantiated or used anywhere in the server or startup code (`server/`, `cmd/`). No jobs are registered with it. The only "cleanup" that exists is the in-memory cache eviction loop (`store/cache/cache.go:200`), which runs every 5 minutes to expire stale cache entries — it is not a database cleanup and not driven by a cron schedule.
