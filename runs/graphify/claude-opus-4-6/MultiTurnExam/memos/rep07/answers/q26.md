The following tables are affected when DeleteMemo runs:

- **memo_relation** — explicitly deleted by `Store.DeleteMemo` (both as source and target, `store/memo.go:142-146`)
- **attachment** — explicitly deleted by `Store.DeleteMemo` (`store/memo.go:149-156`)
- **memo** — the memo row itself is deleted (`store/memo.go:158`)
- **memo_share** — cascaded via `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/postgres/LATEST.sql`)

Additionally, at the API handler level (`server/router/api/v1/memo_service.go:567-577`), comment memos (related via `memo_relation` with type Comment) are recursively deleted first, which triggers the same cascade for each comment.
