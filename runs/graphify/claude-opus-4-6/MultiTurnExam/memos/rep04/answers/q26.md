When `DeleteMemo` runs (combining the API layer in `server/router/api/v1/memo_service.go` and the store layer in `store/memo.go`), the following tables are affected:

1. **memo_relation** — relations where the memo is source or target are deleted
2. **attachment** — attachments linked to the memo are deleted
3. **memo** — the memo row itself is deleted
4. **memo** (again, for comments) — at the API layer, comment memos (linked via `memo_relation` with type `Comment`) are recursively deleted, which in turn triggers their own `memo_relation` and `attachment` cleanup

So the directly affected tables are: **memo, memo_relation, attachment**.
