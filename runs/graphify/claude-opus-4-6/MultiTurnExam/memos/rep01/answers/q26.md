The following tables are affected when `DeleteMemo` runs:

1. **memo_relation** — explicitly deleted by `Store.DeleteMemo` (`store/memo.go:142-146`) for both `memo_id` and `related_memo_id` references
2. **attachment** — explicitly deleted by `Store.DeleteMemo` (`store/memo.go:149-157`)
3. **memo** — the memo row itself is deleted by the dialect driver (e.g., `store/db/sqlite/memo.go:239`)
4. **memo_share** — deleted via SQL foreign key `ON DELETE CASCADE` referencing `memo(id)` (`store/migration/sqlite/LATEST.sql`)

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), comment memos are recursively deleted via `Store.DeleteMemo`, which cascades the same set of tables for each comment.
