The `deleteUserTargetsTx` function in each DB driver deletes reactions in two phases within a transaction: (1) `DELETE FROM reaction WHERE content_id IN (...)` removes all reactions on the user's memos (e.g., `store/db/sqlite/user_delete.go:96-98`, implementation at lines 380-387), (2) `DELETE FROM reaction WHERE creator_id = ?` removes reactions the user placed on others' memos (e.g., `store/db/sqlite/user_delete.go:102-104`, implementation at lines 400-402). Same logic in postgres (`store/db/postgres/user_delete.go:96-104`) and mysql (`store/db/mysql/user_delete.go:96-104`). The reaction table has no foreign keys or ON DELETE CASCADE — confirmed via migration files at `store/migration/sqlite/0.20/00__reaction.sql`, `store/migration/postgres/0.20/00__reaction.sql`, `store/migration/mysql/0.20/00__reaction.sql`.
