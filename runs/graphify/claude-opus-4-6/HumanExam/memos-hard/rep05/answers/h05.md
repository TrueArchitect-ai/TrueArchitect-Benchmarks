When a user is deleted, reactions are removed by two explicit SQL `DELETE` statements within the deletion transaction: (1) `DELETE FROM reaction WHERE content_id IN (...)` for reactions on the user's memos (`store/db/sqlite/user_delete.go:383`), and (2) `DELETE FROM reaction WHERE creator_id = ?` for reactions the user created (`store/db/sqlite/user_delete.go:401`). Same logic in postgres (`user_delete.go:383,401`) and mysql (`user_delete.go:420,438`). The `reaction` table has no foreign key constraints (checked all `LATEST.sql` migration files). No CASCADE is involved.
