The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is a **pure in-memory Go cache**, not backed by Redis or any external store.

The cache is implemented in `store/cache/cache.go` as a thread-safe in-memory cache using Go's `sync.Map` with TTL-based expiration. It is instantiated in `store/store.go:38-53`, where a `userCache` field (line 28) is created with the following configuration (lines 40-45):

- **DefaultTTL**: 10 minutes
- **CleanupInterval**: 5 minutes (background goroutine sweeps expired entries)
- **MaxItems**: 1000

The user cache is used in `store/user.go:150-151` to cache `*User` objects keyed by user ID. There is no Redis dependency anywhere in the codebase — `grep` for "redis" across all source files returns zero results. The entire cache lifecycle (set, get, eviction, cleanup) runs in-process via `sync.Map` and a background ticker goroutine (`store/cache/cache.go:200-215`).
