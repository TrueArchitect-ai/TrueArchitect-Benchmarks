The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all.

The actual mechanism is a **buffered Go channel** used as an in-process async dispatch queue. It is declared as a package-level variable in `/bench/home/work/internal/webhook/webhook.go` (line 39):

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

In the same file's `init()` function (lines 42–55), **4 goroutines** are spawned that consume from this channel in a `for payload := range asyncPostQueue` loop, each calling `Post(payload)` to make the HTTP delivery. Work is enqueued via `PostAsync()` (line 184), which performs a non-blocking send — dropping the payload with a log warning if the 128-slot buffer is full, rather than blocking the API handler.
