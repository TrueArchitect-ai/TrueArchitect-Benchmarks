**Mechanism: explicit Go code**, not database-level rules.

The `reaction` table has **no foreign key constraints** at all — `creator_id` is a plain `INT NOT NULL` with no `REFERENCES` or `ON DELETE` clause.

**Go deletion code** — the function `deleteUserTargetsTx` in each driver performs two explicit reaction deletions inside a transaction:

1. **Delete reactions targeting the user's memos** (by `content_id`) — e.g., `store/db/mysql/user_delete.go:96-98` calls `deleteReactionsByContentIDsTx`, which runs `DELETE FROM reaction WHERE content_id IN (...)` (line ~420).

2. **Delete reactions the user created** (by `creator_id`) — e.g., `store/db/mysql/user_delete.go:102-104` calls `deleteReactionsByCreatorTx`, which runs `DELETE FROM reaction WHERE creator_id = ?` (line ~438).

All three drivers implement the same logic:
- `store/db/mysql/user_delete.go`
- `store/db/sqlite/user_delete.go`
- `store/db/postgres/user_delete.go`
