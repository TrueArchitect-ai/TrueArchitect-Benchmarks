The premise is incorrect — the webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain Go buffered channel** acting as an in-process async work queue. It is declared at package level in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

A pool of 4 goroutine workers is started in the `init()` function (`internal/webhook/webhook.go:42-55`), each consuming from this channel in a `for payload := range asyncPostQueue` loop and calling `Post()` to deliver the webhook via HTTP. Producers enqueue payloads by calling `PostAsync()` (`internal/webhook/webhook.go:184-196`), which performs a non-blocking send — if the 128-slot buffer is full, the payload is dropped with a warning rather than blocking. There is no external broker dependency, no persistence, and no retry; queued webhooks are lost on process restart.
