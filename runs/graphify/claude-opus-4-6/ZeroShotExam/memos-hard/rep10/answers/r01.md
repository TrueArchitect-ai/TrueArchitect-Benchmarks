The premise is incorrect: there is no Redis connection in this repository. The cache layer is **not** backed by Redis — it is a **pure in-memory cache** implemented in Go using `sync.Map`.

The cache is defined in `store/cache/cache.go` as a generic in-memory key-value store with TTL support, periodic cleanup, and max-item eviction. It has no external dependencies (no Redis, Memcached, or any other external store).

The user cache is configured in `store/store.go:38-45`, where `Store.New()` creates a `cache.Config` with:

- **DefaultTTL: 10 minutes** (`10 * time.Minute`)
- CleanupInterval: 5 minutes
- MaxItems: 1000

This same config is applied to all three cache instances, including `userCache` (`store/store.go:52`). There is no per-entity TTL override for user entries — they use the shared 10-minute default TTL via `cache.Set()`, which delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). You can see this in `store/user.go:98`, `store/user.go:122`, `store/user.go:134`, and `store/user.go:167`, where user objects are cached with the plain `Set` call (no custom TTL).
