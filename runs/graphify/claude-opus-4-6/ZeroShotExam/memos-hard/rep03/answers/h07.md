`GET /file/users/:identifier/avatar` — browser requests the avatar URL (rewritten from the raw base64 data URI by the API layer). Each hop:

1. `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go`
2. `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go`
3. `Store.GetUser` — `store/user.go`
4. `Store.ListUsers` — `store/user.go`
5. `DB.ListUsers` — `store/db/sqlite/user.go` (also `store/db/postgres/user.go`, `store/db/mysql/user.go`)
6. `FileServerService.parseDataURI` — `server/router/fileserver/fileserver.go`

**Detail per hop:**

- **`serveUserAvatar`** (`server/router/fileserver/fileserver.go:168`) — the Echo HTTP handler registered at line 124. Authenticates if the instance is private, extracts the `:identifier` param (username), fetches the user, parses the stored data URI into raw bytes, and serves them via `c.Blob()`.
- **`getUserByUsername`** (`server/router/fileserver/fileserver.go:715`) — thin wrapper that calls `s.Store.GetUser` with a `FindUser{Username: &identifier}` filter.
- **`Store.GetUser`** (`store/user.go:148`) — checks the in-memory user cache (keyed by ID; misses here since the lookup is by username), then delegates to `ListUsers` and returns the first result.
- **`Store.ListUsers`** (`store/user.go:136`) — calls `s.driver.ListUsers(ctx, find)` on the database driver interface, then populates the cache for each returned user.
- **`DB.ListUsers`** (`store/db/sqlite/user.go:88`) — builds and executes `SELECT id, username, …, avatar_url, … FROM user WHERE username = ?` (line 151–165), scanning `avatar_url` into `user.AvatarURL` (line 189).
- **`parseDataURI`** (`server/router/fileserver/fileserver.go:737`) — back in the handler, extracts the MIME type and base64-decodes the image bytes from the `data:image/…;base64,…` string stored in the `avatar_url` column.

The avatar image is stored inline in the `user` table's `avatar_url` TEXT column as a complete base64 data URI — there is no separate file or object storage.
