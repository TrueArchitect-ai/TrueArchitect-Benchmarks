The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all.

The actual mechanism is a **buffered Go channel** with an in-process goroutine worker pool, declared in `internal/webhook/webhook.go`:

- **Queue declaration** (line 39): `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel with capacity 128.
- **Worker pool** (lines 42–55): An `init()` function spawns 4 goroutines that range over the channel, calling `Post()` for each payload.
- **Enqueue** (lines 184–196): `PostAsync()` performs a non-blocking send into the channel; if the buffer is full, the webhook is dropped with a warning log.

There are no external broker dependencies in `go.mod` — no NATS, AMQP, Kafka, Redis queue libraries, or any other messaging system. The queue is entirely in-process and ephemeral (lost on restart, no retries).
