The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is a custom **in-process, in-memory cache** implemented in `store/cache/cache.go`, built on Go's `sync.Map` with TTL-based expiration and a background cleanup goroutine.

The user cache is configured in `store/store.go:40-45`, where a `cache.Config` is created with:

- **DefaultTTL: 10 minutes** (`10 * time.Minute`)
- CleanupInterval: 5 minutes
- MaxItems: 1000

This config is shared across all three caches instantiated in the `Store` struct (`store/store.go:27-29`): `instanceSettingCache`, `userCache`, and `userSettingCache`. All three are created via `cache.New(cacheConfig)` at `store/store.go:51-53`.

User entries are cached and evicted using this 10-minute default TTL — the `userCache.Set()` calls in `store/user.go` (lines 98, 122, 132, 143, 167) use the `Set` method which applies the default TTL (`cache/cache.go:94`). No per-entry TTL override is used for user objects.
