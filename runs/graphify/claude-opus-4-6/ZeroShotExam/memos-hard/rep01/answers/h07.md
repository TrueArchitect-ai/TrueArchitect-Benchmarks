`GET /file/users/:identifier/avatar` — browser hits this route, registered in `RegisterRoutes`:

`FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go`
`FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go`
`Store.GetUser` — `store/user.go`
`Store.ListUsers` — `store/user.go`
`driver.ListUsers` (interface) — `store/driver.go`
`DB.ListUsers` (e.g. SQLite) — `store/db/sqlite/user.go`

Detail per hop:

1. **`serveUserAvatar`** — `server/router/fileserver/fileserver.go` — Echo handler extracts the `:identifier` (username) param, optionally authenticates on private instances, then delegates lookup.
2. **`getUserByUsername`** — `server/router/fileserver/fileserver.go` — Calls `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`.
3. **`Store.GetUser`** — `store/user.go` — Checks an in-memory cache (keyed by ID; misses here since lookup is by username), then calls `s.ListUsers`.
4. **`Store.ListUsers`** — `store/user.go` — Delegates to `s.driver.ListUsers(ctx, find)` and populates the user cache on return.
5. **`Driver.ListUsers`** (interface) — `store/driver.go` — Dispatches to the concrete DB driver.
6. **`DB.ListUsers`** — `store/db/sqlite/user.go` (or `postgres/user.go`, `mysql/user.go`) — Runs `SELECT … avatar_url … FROM user WHERE username = ?` and scans `avatar_url` into `User.AvatarURL`.

The avatar is stored inline in the database as a base64 data URI (`data:image/png;base64,…`). Back in `serveUserAvatar`, `parseDataURI` (same file) regex-extracts the MIME type and decodes the bytes, which are returned as the HTTP response body.
