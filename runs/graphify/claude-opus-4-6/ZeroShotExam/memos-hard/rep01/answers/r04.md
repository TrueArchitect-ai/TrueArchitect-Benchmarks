The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all.

The actual mechanism is a **plain Go buffered channel** serving as an in-memory queue, declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the package's `init()` function (`internal/webhook/webhook.go:42-55`), each ranging over that channel and calling `Post()` to make the HTTP delivery synchronously. Messages are enqueued via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which uses a non-blocking `select` — if the 128-slot buffer is full, the webhook is silently dropped with a warning log. There is no persistence, no retry, and no external dependency; the entire queue lives in-process and vanishes if the server restarts.
