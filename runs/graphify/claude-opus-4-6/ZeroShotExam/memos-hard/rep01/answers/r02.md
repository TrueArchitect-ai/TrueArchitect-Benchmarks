The premise of the question is incorrect. This repository does not have a per-user API rate-limiting middleware. There is no rate-limiting implementation registered anywhere in the codebase. The only mention of "rate limit" is a comment in `internal/email/doc.go` describing a future aspiration to rate-limit email sending — it is not implemented.

The server middleware stack (visible in `server/server.go`, `server/router/api/v1/v1.go`, and `server/cors.go`) includes CORS handling, authentication/authorization (`server/auth/`, `server/router/api/v1/authz.go`), and frontend routing, but no request-rate-limiting middleware. The `internal/scheduler/middleware.go` file is task-scheduler middleware, not HTTP API rate-limiting.
