The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is **not backed by Redis**; it is a **pure in-memory cache** implemented in Go using `sync.Map`.

The cache is defined in `store/cache/cache.go` as the `Cache` struct (line 67), which stores entries in a `sync.Map` field (`data`). It is instantiated in `store/store.go` (lines 40–52), where the `Store` creates three in-memory cache instances (`instanceSettingCache`, `userCache`, `userSettingCache`) — all using the same `cache.Config`.

The **TTL that applies to user entries** (`userCache`) is the default `10 * time.Minute`, set at `store/store.go:41` and matching `cache.DefaultConfig()` at `store/cache/cache.go:59`. Cleanup of expired entries runs every `5 * time.Minute` (`CleanupInterval`), and the cache is capped at `1000` items (`MaxItems`). There is no external datastore (Redis, Memcached, etc.) involved anywhere in the caching layer.
