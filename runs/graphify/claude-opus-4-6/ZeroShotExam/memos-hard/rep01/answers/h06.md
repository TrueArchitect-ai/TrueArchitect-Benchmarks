The following RPC handler methods can transitively cause an outbound HTTP request to a user-configured webhook URL:

1. **`CreateMemo`** — `server/router/api/v1/memo_service.go`
2. **`UpdateMemo`** — `server/router/api/v1/memo_service.go`
3. **`DeleteMemo`** — `server/router/api/v1/memo_service.go`
4. **`CreateMemoComment`** — `server/router/api/v1/memo_service_comments.go`
5. **`SetMemoRelations`** — `server/router/api/v1/memo_relation_service.go`
6. **`SetMemoAttachments`** — `server/router/api/v1/memo_attachment_service.go`

All six paths converge at **`webhook.Post()`** in `internal/webhook/webhook.go`.

The call chains work as follows:

- `CreateMemo` → `DispatchMemoCreatedWebhook()` → `dispatchMemoRelatedWebhook()` → `webhook.PostAsync()` → **`webhook.Post()`**
- `UpdateMemo`, `SetMemoRelations`, `SetMemoAttachments` → `dispatchMemoUpdatedSideEffects()` → `DispatchMemoUpdatedWebhook()` → `dispatchMemoRelatedWebhook()` → `webhook.PostAsync()` → **`webhook.Post()`**
- `DeleteMemo` → `DispatchMemoDeletedWebhook()` → `dispatchMemoRelatedWebhook()` → `webhook.PostAsync()` → **`webhook.Post()`**
- `CreateMemoComment` → `DispatchMemoCommentCreatedWebhook()` → `webhook.PostAsync()` → **`webhook.Post()`** (and also indirectly via its internal call to `CreateMemo`)

The convergence function `webhook.Post()` (`internal/webhook/webhook.go`) is where the actual `safeClient.Do(req)` HTTP call is made to the user-configured webhook URL. `PostAsync` enqueues onto a buffered channel drained by worker goroutines that each call `Post()`, but `Post()` is the single point where all paths converge before delivery.
