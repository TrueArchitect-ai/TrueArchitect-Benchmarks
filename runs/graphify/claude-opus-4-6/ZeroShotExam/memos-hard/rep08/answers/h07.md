`GET /file/users/:identifier/avatar` → stored base64 data URI in the `user` table:

`serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
`getUserByUsername` — `server/router/fileserver/fileserver.go:715`
`Store.GetUser` — `store/user.go:148`
`Store.ListUsers` — `store/user.go:136`
`Driver.ListUsers` — `store/driver.go:47` (interface), implemented by `store/db/sqlite/user.go:88`, `store/db/mysql/user.go:147`, `store/db/postgres/user.go:150`
`parseDataURI` — `server/router/fileserver/fileserver.go:737`

The handler extracts the username from the URL path, calls `getUserByUsername` which delegates to `Store.GetUser`. `GetUser` calls `Store.ListUsers`, which calls the database driver's `ListUsers` — a `SELECT … avatar_url … FROM user WHERE username = ?`. The returned `User.AvatarURL` (a `data:image/…;base64,…` string stored in the `avatar_url` column — `store/user.go:43`) is decoded by `parseDataURI` (regex + `base64.StdEncoding.DecodeString`) and the raw bytes are returned via `c.Blob()`. No filesystem or object storage is involved; the image lives inline in the database row.
