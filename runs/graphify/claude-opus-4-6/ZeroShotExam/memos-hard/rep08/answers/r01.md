The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer does not use Redis at all.

The cache is a **pure in-memory implementation** built with Go's `sync.Map`, defined in `store/cache/cache.go`. It is a thread-safe in-process cache with TTL-based expiration and periodic cleanup — no external data store is involved.

The user cache is instantiated in `store/store.go:52` via `cache.New(cacheConfig)`, using a `cache.Config` constructed at `store/store.go:40-45` with these defaults:

- **DefaultTTL: 10 minutes** (`10 * time.Minute`) — this is the TTL that applies to user entries
- **CleanupInterval: 5 minutes** — expired entries are swept every 5 minutes
- **MaxItems: 1000** — when exceeded, the oldest 20% of entries are evicted

User entries are cached by user ID (key generated via `userCacheKey()` at `store/user.go:88-90`), and the cache is populated on create, update, list, and get operations (`store/user.go:92-168`). Entries are invalidated on delete (`store/user.go:171-181`). There is no Redis dependency anywhere in the project — not in `go.mod`, not in any source file.
