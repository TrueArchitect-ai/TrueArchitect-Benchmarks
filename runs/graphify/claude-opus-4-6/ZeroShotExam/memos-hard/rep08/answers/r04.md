The premise is incorrect — the webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **Go buffered channel** acting as an in-process async queue, declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutines are spawned in an `init()` function in the same file (lines 42–55) to consume from this channel and call `Post()` to deliver webhooks via HTTP. Payloads are enqueued via `PostAsync()` (line 184), which uses a non-blocking `select` — if the 128-slot channel is full, the webhook is silently dropped with a warning log. There is no retry, persistence, or dead-letter mechanism; pending deliveries are lost on process restart.
