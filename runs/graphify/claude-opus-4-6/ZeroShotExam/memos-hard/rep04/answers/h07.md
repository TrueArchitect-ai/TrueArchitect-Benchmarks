The browser issues `GET /file/users/{username}/avatar`. Here is each hop from the route to stored data:

`RegisterRoutes` — `server/router/fileserver/fileserver.go:121` (registers the `/file/users/:identifier/avatar` route)

`serveUserAvatar` — `server/router/fileserver/fileserver.go:168` (HTTP handler; extracts `:identifier`, checks auth on private instances, returns image blob)

`getUserByUsername` — `server/router/fileserver/fileserver.go:715` (wraps `Store.GetUser` with a `FindUser{Username}` filter)

`Store.GetUser` — `store/user.go:148` (cache-aware lookup; delegates to `ListUsers` for username-based queries)

`Store.ListUsers` — `store/user.go:136` (calls the database driver via `s.driver.ListUsers`)

`Driver.ListUsers` — `store/driver.go:47` (interface method; implemented per DB engine)

`DB.ListUsers` (SQLite impl) — `store/db/sqlite/user.go:88` (runs `SELECT … avatar_url … FROM user WHERE username = ?`)
`DB.ListUsers` (Postgres impl) — `store/db/postgres/user.go:87`
`DB.ListUsers` (MySQL impl) — `store/db/mysql/user.go:84`

`parseDataURI` — `server/router/fileserver/fileserver.go:737` (regex-decodes the `data:image/…;base64,…` string from the `avatar_url` column into a MIME type and raw bytes)
