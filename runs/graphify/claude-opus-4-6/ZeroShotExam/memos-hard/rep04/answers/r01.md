The premise is incorrect — there is no Redis connection in this repository. The cache layer is a **custom in-memory cache**, not Redis-backed.

The cache is implemented in `store/cache/cache.go` as a thread-safe in-memory store built on Go's `sync.Map` with TTL-based expiration and a background cleanup goroutine. It has no external dependencies — no Redis client, no Redis configuration, no Redis container in `scripts/compose.yaml`.

The `userCache` is instantiated in `store/store.go:51` via `cache.New(cacheConfig)` using a shared `cache.Config` defined at `store/store.go:40–45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

The **TTL for user entries is 10 minutes** (`DefaultTTL: 10 * time.Minute`), the same default applied to all three caches (`instanceSettingCache`, `userCache`, `userSettingCache`). Expired entries are lazily evicted on read (`store/cache/cache.go:135–144`) and proactively swept every 5 minutes by a background goroutine (`store/cache/cache.go:200–215`). The cache also enforces a max of 1000 items with oldest-first eviction (`store/cache/cache.go:253–313`).
