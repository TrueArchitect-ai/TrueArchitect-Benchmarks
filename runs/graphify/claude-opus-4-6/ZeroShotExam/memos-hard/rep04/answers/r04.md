The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all. The mechanism is a plain **buffered Go channel** acting as an in-process async queue.

The queue is declared in `internal/webhook/webhook.go` at line 39:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the package's `init()` function (same file, lines 42–55), each consuming from that channel with `for payload := range asyncPostQueue`. Callers enqueue work via `PostAsync()` (lines 184–196), which does a non-blocking send on the channel — dropping the webhook with a log warning if the buffer (capacity 128) is full. There is no external broker dependency, no retry mechanism, and no persistence: if the process crashes, queued payloads are lost.
