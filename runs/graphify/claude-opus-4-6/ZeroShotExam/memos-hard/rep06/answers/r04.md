The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **buffered Go channel** serving as an in-process queue, declared in `internal/webhook/webhook.go` at line 39:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in an `init()` function (same file, lines 42–55) that consume from this channel in a loop, calling `Post()` to deliver each webhook via HTTP. The producer side is `PostAsync()` (lines 184–196), which performs a non-blocking send on the channel and drops the payload with a warning log if the buffer is full. There is no external broker, no persistence, and no retry logic — failed deliveries are logged and discarded.
