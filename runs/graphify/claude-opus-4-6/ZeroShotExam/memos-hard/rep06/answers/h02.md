**Delivery function** — `Post` in `internal/webhook/webhook.go` (with `PostAsync` enqueuing onto a bounded channel drained by worker goroutines that call `Post`).

**Protection mechanism** — SSRF protection is implemented in `internal/webhook/validate.go` via two layers:

1. **`ValidateURL`** (`internal/webhook/validate.go`) — called at webhook registration time (in `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`). It enforces `http`/`https` schemes only and resolves the hostname, rejecting any IP in `reservedCIDRs` (loopback, RFC-1918 private ranges, link-local/IMDS `169.254.0.0/16`, IPv6 equivalents) via `isReservedIP`.

2. **`safeDialContext`** (`internal/webhook/webhook.go`) — a custom `DialContext` on the HTTP transport used by `Post`. It re-resolves the hostname at connection time and re-checks against `isReservedIP`, defeating DNS rebinding / TOCTOU attacks where the DNS answer changes between registration-time validation and actual delivery.

**Answer:** delivery function — `Post` in `internal/webhook/webhook.go`; protection mechanism — `ValidateURL` + `safeDialContext` using `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go` (and `internal/webhook/webhook.go`).
