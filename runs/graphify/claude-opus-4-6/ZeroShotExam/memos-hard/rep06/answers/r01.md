The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is a **pure in-memory Go implementation**, not backed by Redis or any external store.

The cache is implemented in `store/cache/cache.go` as a thread-safe in-memory cache using `sync.Map` with TTL-based expiration. It is instantiated in `store/store.go:38-45` where `Store.New()` creates three separate `cache.Cache` instances — one of which is `userCache` (line 28, line 52).

All three caches (including the user cache) share the same default configuration defined at `store/store.go:40-45`:

- **DefaultTTL**: 10 minutes
- **CleanupInterval**: 5 minutes (background goroutine sweeps expired entries)
- **MaxItems**: 1,000

There is no per-entity TTL override for user entries specifically — `store/user.go` always calls `s.userCache.Set(ctx, ...)` (e.g., lines 98, 122, 132, 143, 167), which uses the default 10-minute TTL. The `SetWithTTL` variant exists on the cache interface (`cache/cache.go:16`) but is never invoked for users.
