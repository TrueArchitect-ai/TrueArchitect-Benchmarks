The premise of the question is incorrect. This repository does **not** have per-user API rate-limiting middleware. No rate limiter is registered anywhere in the server stack.

The server's middleware/interceptor chains are:

- **HTTP middleware** (`server/server.go:51-52`): only `Recover()` and CORS middleware are registered on the Echo server.
- **Connect/gRPC interceptors** (`server/router/api/v1/v1.go:133-138`): only `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` are registered — none of which is a rate limiter.

The codebase does have **concurrency semaphores** (e.g., 3 concurrent thumbnail generations, 2 concurrent image-processing operations in `server/router/api/v1/v1.go:39-41`) and a **request body size limit** of 256 MB (`server/router/api/v1/v1.go:20`), but these are resource-consumption guards, not per-user request-rate limits. No rate-limiting library (e.g., `golang.org/x/time/rate`) appears in `go.mod`, and no login brute-force protection exists either.
