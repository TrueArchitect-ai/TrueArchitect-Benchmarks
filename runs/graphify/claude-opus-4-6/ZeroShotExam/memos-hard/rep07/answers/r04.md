The premise is incorrect — webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker in this codebase at all.

The actual mechanism is a **buffered Go channel** acting as an in-process queue, declared in `internal/webhook/webhook.go`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

An `init()` function in the same file spawns **4 goroutine workers** that consume from this channel in a loop, each calling `Post()` to make a synchronous HTTP POST to the webhook URL. The producer side is `PostAsync()`, which does a non-blocking send on the channel — if all 128 slots are full, the webhook is silently dropped with a warning log.

There are no broker client libraries in `go.mod`, and no references to NATS, RabbitMQ, Kafka, Redis, or any other external queue system anywhere in the project. The entire webhook delivery pipeline is in-process with no persistence, no retries, and no external dependencies.
