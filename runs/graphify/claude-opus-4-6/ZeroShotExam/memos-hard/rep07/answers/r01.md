The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is a custom **in-process, in-memory cache** built on Go's `sync.Map`, not Redis or any external cache store.

The implementation lives in `store/cache/cache.go`, which defines a `Cache` struct backed by `sync.Map` with TTL-based expiration and a background cleanup goroutine.

The user cache is configured in `store/store.go:38-53`, where `New()` creates a `cache.Config` with:

- **`DefaultTTL`: 10 minutes** (`10 * time.Minute`, line 41)
- `CleanupInterval`: 5 minutes (line 42)
- `MaxItems`: 1000 (line 43)

This single config is shared by all three caches — `userCache`, `userSettingCache`, and `instanceSettingCache` (lines 51-53). So the TTL that applies to user entries is **10 minutes**, enforced by the in-memory cache's expiration check in `cache.go:135` (`time.Now().After(itm.expiration)`) and periodic cleanup in `cache.go:200-215`.

There are zero references to Redis anywhere in the codebase — no Redis client library in `go.mod`, no Redis connection strings, no Redis configuration files.
