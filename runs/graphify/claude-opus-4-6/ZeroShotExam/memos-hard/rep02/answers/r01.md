The premise is incorrect — there is no Redis connection in this repository. The cache layer is a **pure in-memory cache** implemented in Go, not backed by Redis or any external cache store.

The cache is defined in `store/cache/cache.go` as a `Cache` struct built on `sync.Map` (lines 67–73). It is configured and instantiated in `store/store.go` (lines 39–53), where the `Store.New()` constructor creates three in-memory cache instances (`instanceSettingCache`, `userCache`, `userSettingCache`) sharing a single `cache.Config`.

The **TTL that applies to user entries is 10 minutes** (`DefaultTTL: 10 * time.Minute`), set at `store/store.go:41`. This same default TTL applies to all three caches. The cache also has a cleanup interval of 5 minutes and a max capacity of 1,000 items per cache instance (`store/store.go:42–43`).

There are no Redis, Memcached, or any other external cache dependencies — `go.mod` contains no Redis client libraries. The entire caching mechanism is process-local, using Go's `sync.Map` with TTL-based expiration and a background goroutine for periodic cleanup (`store/cache/cache.go:200–215`).
