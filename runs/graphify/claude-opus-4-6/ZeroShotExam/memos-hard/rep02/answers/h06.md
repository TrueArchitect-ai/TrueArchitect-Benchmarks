The following RPC handler methods can transitively cause an outbound HTTP request to a user-configured webhook URL:

1. **`CreateMemo`** (`server/router/api/v1/memo_service.go`) — dispatches `memos.memo.created`
2. **`UpdateMemo`** (`server/router/api/v1/memo_service.go`) — dispatches `memos.memo.updated`
3. **`DeleteMemo`** (`server/router/api/v1/memo_service.go`) — dispatches `memos.memo.deleted`
4. **`CreateMemoComment`** (`server/router/api/v1/memo_service_comments.go`) — dispatches both `memos.memo.created` (via its internal `CreateMemo` call) and `memos.memo.comment.created`
5. **`SetMemoRelations`** (`server/router/api/v1/memo_relation_service.go`) — dispatches `memos.memo.updated`
6. **`SetMemoAttachments`** (`server/router/api/v1/memo_attachment_service.go`) — dispatches `memos.memo.updated`

All six converge on a single function before delivery:

**`webhook.Post`** — `internal/webhook/webhook.go`

This is the function that actually constructs and sends the outbound `http.Post` to the user-configured URL (with optional HMAC-SHA256 signing). Every path reaches it through `webhook.PostAsync` (which enqueues work onto an async channel drained by goroutines that call `Post`). The intermediate dispatch layer in `server/router/api/v1/memo_service_webhooks.go` (functions like `DispatchMemoCreatedWebhook`, `DispatchMemoUpdatedWebhook`, `DispatchMemoDeletedWebhook`, `DispatchMemoCommentCreatedWebhook`) all funnels through a shared private helper `dispatchMemoRelatedWebhook`, which calls `webhook.PostAsync` → `webhook.Post`.
