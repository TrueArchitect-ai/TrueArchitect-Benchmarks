The premise is incorrect — the webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **buffered Go channel** declared at package scope in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the `init()` function of that same file (lines 42–55), each ranging over the channel and calling `Post()` to deliver webhooks via HTTP. The producer side is `PostAsync()` (lines 184–196), which does a non-blocking send into the channel and drops the payload with a warning log if the buffer is full. There is no persistence, no retry, and no external broker — it is entirely in-process.
