The premise of this question is incorrect. This repository does not have per-user API rate-limiting middleware. No such middleware is registered anywhere in the codebase.

The server's middleware stack (in `server/server.go`) includes only recovery and CORS middleware. The API router (`server/router/api/v1/v1.go`) registers interceptors for metadata, logging, recovery, and authentication — but none for rate limiting. There are no dependencies on rate-limiting libraries in `go.mod` or `web/package.json`, and no HTTP 429 status codes are used anywhere.

The closest related mechanisms are:

- **Concurrency semaphores** in `server/router/api/v1/v1.go` (lines 39–41, 59–60) that cap concurrent thumbnail generation (3) and image processing (2) — these are resource-protection caps, not per-user rate limits.
- **Request body size limit** of 256 MiB (`server/router/api/v1/v1.go`, line 20).
- **Documentation-only mentions** in `internal/email/doc.go` and `internal/email/README.md` that describe rate limiting as a future improvement, with no actual implementation.
