**`markdown.Service`** (interface defined in `internal/markdown/markdown.go`) is the abstraction for all server-side markdown processing.

**Impl — Construction — Holders:**

**`service`** (unexported struct, `internal/markdown/markdown.go`) — `markdown.NewService()` called in `server/router/api/v1/v1.go:48` — held by `APIV1Service` (`server/router/api/v1/v1.go:35`), `RSSService` (`server/router/rss/rss.go:45`), and `memopayload.Runner` (`server/runner/memopayload/runner.go:16`)

In detail:

- **Concrete implementation:** The single implementation is the unexported `service` struct wrapping a `goldmark.Markdown` instance (`internal/markdown/markdown.go:57`). There are no mocks or alternative backends.
- **Construction:** `markdown.NewService(WithTagExtension(), WithMentionExtension())` is called in `NewAPIV1Service` (`server/router/api/v1/v1.go:48`), which is invoked from `server/server.go:76`. One shared instance is created at server startup.
- **Holders of the interface:**
  - **`APIV1Service.MarkdownService`** (`server/router/api/v1/v1.go:35`) — the primary owner; uses it for memo creation/update payload rebuilding, mention extraction, and webhook snippet generation.
  - **`RSSService.MarkdownService`** (`server/router/rss/rss.go:45`) — receives the same instance from `APIV1Service` at `server/server.go:85`; uses it to render HTML for RSS feed items.
  - **`memopayload.Runner.MarkdownService`** (`server/runner/memopayload/runner.go:16`) — a batch runner struct that also holds the interface, though in production the standalone function `RebuildMemoPayload` (`runner.go:74`) is called directly with the interface as a parameter rather than through the `Runner` struct.
