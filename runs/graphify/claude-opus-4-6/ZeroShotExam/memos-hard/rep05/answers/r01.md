The premise is incorrect — there is no Redis connection in this repository. The cache layer is a **pure in-memory implementation**, not backed by Redis or any external store.

The cache is implemented in `store/cache/cache.go` as a Go struct wrapping a `sync.Map` with TTL-based expiration. It is instantiated in `store/store.go:38-51` inside the `New()` constructor, where all three caches (`userCache`, `instanceSettingCache`, `userSettingCache`) share the same `cache.Config`:

- **Default TTL: 10 minutes** (`store/store.go:41`)
- Cleanup interval: 5 minutes (`store/store.go:42`)
- Max items: 1,000 (`store/store.go:43`)

The `userCache` field (`store/store.go:28`) is a `*cache.Cache` that stores `*User` objects keyed by user ID (converted to string via `userCacheKey` in `store/user.go:88-90`). Entries are set with the default TTL on create, update, list, and get operations (`store/user.go:98,122,132,143,167`), meaning user cache entries expire after **10 minutes**. There is no per-entry custom TTL override used for users — all calls go through `cache.Set()`, which applies `DefaultTTL` (`store/cache/cache.go:93-95`).
