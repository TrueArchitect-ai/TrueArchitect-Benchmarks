The premise is incorrect — the webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all.

The actual mechanism is a **plain Go buffered channel** declared in-process:

- **Queue declaration:** `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, a buffered channel with capacity 128.
- **Workers:** Four goroutines are spawned in the `init()` function (`internal/webhook/webhook.go:42–55`), each ranging over that channel and calling `Post()` to deliver the webhook via HTTP.
- **Enqueuing:** `PostAsync()` (`internal/webhook/webhook.go:184–196`) uses a non-blocking `select`/`default` send — if the buffer is full, the delivery is dropped with a warning log.

There are no broker client libraries (NATS, AMQP, Redis, Kafka, etc.) in `go.mod`, and `scripts/compose.yaml` declares no broker services. The entire webhook delivery pipeline is in-memory and in-process with no persistence, retry logic, or dead-letter handling.
