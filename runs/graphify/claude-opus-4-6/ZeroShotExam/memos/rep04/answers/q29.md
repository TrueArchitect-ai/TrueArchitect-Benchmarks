**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (lines ~156-178) is a ConnectRPC `Interceptor` that attaches an `Authorization: Bearer <token>` header to every outgoing request, proactively refreshes expired tokens before sending, and retries once on `Unauthenticated` responses.

**Token kinds managed:**
1. **Access token** — a short-lived JWT (15 min, HS256), stored in-memory and in `localStorage` (`memos_access_token`) via `web/src/auth-state.ts`. Sent as `Authorization: Bearer <jwt>`.
2. **Refresh token** — a long-lived JWT (30 days), delivered as an `HttpOnly` cookie named `memos_refresh`. The frontend never reads its value directly; it is sent implicitly via `credentials: "include"` on the refresh call. Rotation happens on every use.
3. **Personal Access Token (PAT)** — user-created, prefixed `memos_pat_`, stored as a SHA-256 hash in the database. Also sent as a `Bearer` token; the backend distinguishes it by the prefix.

**Backend validation package:** `server/auth/` — specifically:
- `server/auth/authenticator.go` — `Authenticate()` dispatches to `AuthenticateByAccessTokenV2` (stateless JWT validation) or `AuthenticateByPAT` (hash-based DB lookup); `AuthenticateByRefreshToken` validates refresh JWTs with a DB revocation check.
- `server/auth/token.go` — JWT generation and parsing (`ParseAccessTokenV2`, `ParseRefreshToken`), constants for durations and cookie names.
- `server/router/api/v1/connect_interceptors.go` (lines ~206-239) — the server-side `AuthInterceptor.WrapUnary` that extracts the Bearer token from incoming requests and calls into `server/auth/` for validation.
