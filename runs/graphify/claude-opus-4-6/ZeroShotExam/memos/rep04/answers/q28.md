**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (`server/runner/s3presign/runner.go:27`); launched in `server.go:startBackgroundRunners` with an initial `RunOnce` at startup then a goroutine ticking on the interval
- **Webhook Dispatch Pool (4 goroutines)** — channel-driven (`internal/webhook/webhook.go:39-55`); workers pull from a buffered channel (`asyncPostQueue`, cap 128), started in package `init()`
- **Email Send Pool (2 goroutines)** — channel-driven (`internal/email/email.go:14-36`); workers pull from a buffered channel (`asyncEmailQueue`, cap 128), started in package `init()`
- **Cache Cleanup (3 goroutines)** — `time.NewTicker` every 5 minutes (`store/cache/cache.go:200-215`); one per cache instance (instanceSettingCache, userCache, userSettingCache), started in `store.New()` (`store/store.go:51-53`)
- **SSE Heartbeat (per-connection)** — `time.NewTicker` every 30 seconds (`server/router/api/v1/sse_handler.go:64`); one per active SSE client connection

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — A complete cron-expression-based job scheduler with middleware (recovery, logging, timeout), timezone support, and graceful shutdown. It is fully tested but **never imported by any non-test code** in the repository; the server does not wire it into startup.
- **`server/runner/memopayload/` runner** — Has a `RunOnce` method to rebuild memo payloads in batch, but unlike the S3 presign runner it has **no ticker loop and is never called from `startBackgroundRunners`**. Its `RebuildMemoPayload` function is only used inline (synchronously) during individual memo create/update in `memo_service.go`.
