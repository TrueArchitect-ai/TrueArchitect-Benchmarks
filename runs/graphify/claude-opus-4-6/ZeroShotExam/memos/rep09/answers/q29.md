**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line ~156) wraps every outgoing ConnectRPC request, setting an `Authorization: Bearer <token>` header via `getRequestToken()`, and reactively refreshing on `Unauthenticated` errors. Token state (localStorage keys `memos_access_token` / `memos_token_expires_at`, cross-tab sync via `BroadcastChannel`) is managed in `web/src/auth-state.ts`.

**Token kinds:**
1. **JWT access token** — short-lived (15 min), stateless, audience `"user.access-token"`, sent as `Authorization: Bearer` header.
2. **JWT refresh token** — long-lived (30 days), stateful (stored/revoked in DB), audience `"user.refresh-token"`, transported as an `HttpOnly` cookie named `memos_refresh`, rotated on each use.
3. **Personal access token (PAT)** — prefixed `memos_pat_`, random string, SHA-256 hash stored in DB, also sent via `Authorization: Bearer` (server distinguishes by prefix).

**Backend validation package:** `server/auth/` — specifically:
- `server/auth/authenticator.go` — `Authenticator.Authenticate()` dispatches to stateless JWT validation or stateful PAT/refresh-token DB lookup.
- `server/auth/token.go` — JWT generation/parsing (HS256) and PAT hashing.
- `server/auth/extract.go` — header/cookie extraction helpers.

The server-side interceptor that calls into this package is `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` (line ~205), which delegates to the `Authorizer` policy layer in `server/router/api/v1/authz.go`.
