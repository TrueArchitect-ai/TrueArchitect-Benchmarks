**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line ~156) is a ConnectRPC interceptor that attaches an `Authorization: Bearer <token>` header to every outgoing RPC request, handles 401 responses by refreshing the token and retrying once, and proactively refreshes tokens within 30 seconds of expiry before sending.

**Token kinds managed:**
1. **Access token** — short-lived JWT (~15 min), stored in-memory and `localStorage` (keys `memos_access_token`, `memos_token_expires_at`) via `web/src/auth-state.ts`, sent as `Bearer` header on every request.
2. **Refresh token** — long-lived JWT (~30 days), stored as an HttpOnly cookie (`memos_refresh`), sent automatically with `credentials: "include"` on refresh calls. Never accessible to JavaScript.
3. **Personal Access Token (PAT)** — long-lived, prefixed `memos_pat_`, hashed (SHA-256) in the database, accepted by the backend as a `Bearer` token for programmatic access.

**Backend validation package:** `server/auth/` — specifically `server/auth/authenticator.go` (defines `Authenticator` with `AuthenticateByAccessTokenV2` for stateless JWT validation, `AuthenticateByRefreshToken` for DB-checked refresh tokens, and `AuthenticateByPAT` for hash-verified personal access tokens). The server-side interceptor that calls into this package lives at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`).
