Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

The first three delegate to the private helper `dispatchMemoRelatedWebhook` (same file), while `DispatchMemoCommentCreatedWebhook` has its own implementation (it resolves webhooks for the related memo's owner rather than the comment author). Both paths call `webhook.PostAsync()` to enqueue work.

All dispatches converge for delivery at **`webhook.Post`** in `internal/webhook/webhook.go`. `PostAsync` places payloads onto a buffered channel (`asyncPostQueue`), and a pool of worker goroutines drains that channel by calling `Post()`, which performs the actual HTTP POST with optional HMAC-SHA256 signing.
