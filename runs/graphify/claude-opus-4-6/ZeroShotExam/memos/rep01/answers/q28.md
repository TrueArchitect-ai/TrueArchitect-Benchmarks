**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — 12-hour ticker interval (`server/runner/s3presign/runner.go`); started by `Server.startBackgroundRunners()` in `server/server.go:153–173`, with an immediate `RunOnce` at boot then a goroutine loop
- **Webhook Dispatch Workers (×4)** — channel-driven (`internal/webhook/webhook.go`); 4 goroutines reading from a buffered channel (`asyncPostQueue`, cap 128), started via package `init()`; triggered when `PostAsync()` enqueues a payload
- **Email Dispatch Workers (×2)** — channel-driven (`internal/email/email.go`); 2 goroutines reading from a buffered channel (`asyncEmailQueue`, cap 128), started via package `init()`; triggered when `SendAsync()` enqueues a message
- **Cache Cleanup Goroutines (×3)** — 5-minute ticker interval (`store/cache/cache.go`); one per cache instance (`instanceSettingCache`, `userCache`, `userSettingCache`), started by `cache.New()` during `store.New()` (`store/store.go:51–53`)
- **SSE Per-Connection Heartbeat** — 30-second ticker per connected SSE client (`server/router/api/v1/sse_handler.go:64`); started on each SSE HTTP request, lives for the connection's duration

**Unused scheduling infrastructure:**

- **`internal/scheduler/` — full cron scheduler package, never used by the server.** It provides a complete cron expression parser, job registration, middleware (recovery/logging/timeout), and graceful shutdown — but has zero non-test imports anywhere in the codebase. The server uses ad-hoc tickers and `init()` goroutine pools instead.
- **`server/runner/memopayload/` — `Runner` struct never instantiated by the server.** Its `RunOnce()` batch-rebuilds all memo payloads, but only the standalone function `memopayload.RebuildMemoPayload()` is imported (inline, in `memo_service.go` during create/update). The `Runner` itself is never started.
