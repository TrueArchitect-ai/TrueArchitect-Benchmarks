When `DeleteMemo` runs, the following database tables are affected:

1. **`memo_relation`** — Records where the memo is either the source (`memo_id`) or target (`related_memo_id`) are deleted explicitly in `store/memo.go:142-146` via two calls to `DeleteMemoRelation`.
2. **`attachment`** — All attachments linked to the memo are deleted in `store/memo.go:149-156` via `DeleteAttachment`, which issues `DELETE FROM attachment` (e.g., `store/db/postgres/attachment.go:212`).
3. **`memo`** — The memo row itself is deleted last in `store/memo.go:158` via the driver's `DeleteMemo`, which issues `DELETE FROM memo` (e.g., `store/db/postgres/memo.go:246`).

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (related via `MemoRelationComment`) are recursively deleted by calling `Store.DeleteMemo` for each comment, which cascades through the same three tables for every comment memo.
