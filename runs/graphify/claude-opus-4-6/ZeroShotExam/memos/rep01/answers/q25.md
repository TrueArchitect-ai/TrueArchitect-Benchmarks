**Engine:** [CEL (Common Expression Language)](https://github.com/google/cel-go) via `google/cel-go`; **path:** `internal/filter/engine.go` (with the parser/IR builder in `internal/filter/parser.go` and the SQL renderer in `internal/filter/render.go`).

**Mechanism:** The `Engine.Compile` method uses `cel.Env.Compile` to parse the filter string into a CEL AST, then `buildCondition` (`internal/filter/parser.go`) walks that AST to produce a dialect-agnostic intermediate representation (a `Condition` tree defined in `internal/filter/ir.go`), and `Program.Render` (`internal/filter/render.go`) traverses that IR tree and emits dialect-specific SQL fragments by switching on `RenderOptions.Dialect` (SQLite, Postgres, or MySQL) at each node—handling differences like placeholder style (`?` vs `$N`), JSON operators (`JSON_EXTRACT` vs `->>`/`@>`), case folding (`ILIKE` vs custom `memos_unicode_lower`), and date-part extraction (`strftime` vs `EXTRACT` vs MySQL functions).
