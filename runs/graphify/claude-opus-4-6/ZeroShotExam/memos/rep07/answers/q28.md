**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — 12-hour `time.NewTicker` (plus one synchronous run at startup); refreshes expiring S3 presigned URLs (`server/runner/s3presign/runner.go`, started from `server/server.go:153-173` in `startBackgroundRunners()`)
- **Webhook Dispatch Workers (×4)** — event-driven, draining a buffered channel (`asyncPostQueue`); started via package-level `init()` in `internal/webhook/webhook.go:42-55`
- **Email Dispatch Workers (×2)** — event-driven, draining a buffered channel (`asyncEmailQueue`); started via package-level `init()` in `internal/email/email.go:16-36`
- **Cache Cleanup Goroutines (×3)** — 5-minute `time.NewTicker` per cache instance; started by `store.New()` creating three `cache.Cache` instances (`store/cache/cache.go:200-215`)
- **SSE Heartbeat** — 30-second `time.NewTicker`, one per SSE client connection (`server/router/api/v1/sse_handler.go:64-109`)

**Unused scheduling infrastructure:**

- The `internal/scheduler/` package is a fully-featured cron-expression-based job scheduler (with timezone support, middleware, graceful shutdown) that is **never imported or used** anywhere outside its own package and tests. No server code references it.
- The `server/runner/memopayload/` runner struct and its `RunOnce()` batch method are **never started** as a background worker. Only the standalone `RebuildMemoPayload` helper from that package is called synchronously at request time during individual memo create/update operations (`server/router/api/v1/memo_service.go:108,447`).
