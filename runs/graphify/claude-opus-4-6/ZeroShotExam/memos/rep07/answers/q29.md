**Interceptor path:** `web/src/connect.ts` — defines `authInterceptor` (an `@connectrpc/connect` `Interceptor`) that attaches `Authorization: Bearer <token>` to every outgoing ConnectRPC request, handles `Unauthenticated` errors by refreshing and retrying once, and redirects to login on final failure. Token state is managed in `web/src/auth-state.ts` (in-memory + localStorage).

**Token kinds:**
1. **Access token** — short-lived JWT (HS256, 15-min TTL, audience `user.access-token`), stored in-memory and in `localStorage` (`memos_access_token`), sent as `Bearer` header.
2. **Refresh token** — long-lived JWT (30-day, audience `user.refresh-token`), stored as an `HttpOnly` cookie (`memos_refresh`), sent automatically by the browser; the server performs token rotation on each refresh.
3. **Personal access token (PAT)** — prefixed `memos_pat_`, stored as a SHA-256 hash in the database, validated by hash lookup rather than JWT parsing.

**Backend validation package:** `server/auth/` — specifically `server/auth/authenticator.go` (the `Authenticator` struct with `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`) and `server/auth/token.go` (JWT parsing/generation). The server-side ConnectRPC interceptor that invokes this lives at `server/router/api/v1/connect_interceptors.go`.
