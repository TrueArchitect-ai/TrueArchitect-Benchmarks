**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (lines ~156–178) is a ConnectRPC `Interceptor` that calls `setAuthorizationHeader(req, token)` to attach a `Bearer` token to every outgoing request, and handles 401 responses by refreshing and retrying.

**Token kinds managed:**
1. **Access token** — a short-lived JWT (15 min), stored in-memory and in `localStorage` (`memos_access_token`), sent as `Authorization: Bearer <token>`. State helpers live in `web/src/auth-state.ts`.
2. **Refresh token** — a long-lived JWT (30 days), stored as an `HttpOnly` cookie (`memos_refresh`), sent automatically by the browser when the interceptor calls the `refreshToken` endpoint with `credentials: "include"`. The server rotates it on each use.
3. **Personal Access Token (PAT)** — a long-lived random string prefixed `memos_pat_`, stored as a SHA-256 hash in the database; sent as a `Bearer` token and distinguished server-side by its prefix.

**Backend validation package:** `server/auth/` — specifically `server/auth/token.go` (JWT generation/parsing via `golang-jwt/jwt/v5`, HS256), `server/auth/authenticator.go` (`Authenticate()` resolves bearer tokens and PATs, `AuthenticateByRefreshToken()` checks the cookie), and `server/auth/extract.go` (extracts tokens from headers/cookies). The server-side Connect interceptor that calls into this package is at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`).
