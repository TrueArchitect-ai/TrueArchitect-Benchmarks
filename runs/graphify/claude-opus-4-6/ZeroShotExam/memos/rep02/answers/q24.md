Here is the complete call chain for creating a memo, one hop per line:

1. **Frontend mutation hook:** `web/src/hooks/useMemoQueries.ts` — `useCreateMemo()` calls `memoServiceClient.createMemo()`
2. **Frontend Connect client:** `web/src/connect.ts` — `memoServiceClient` is created via `createClient(MemoService, transport)`
3. **Proto RPC definition:** `proto/api/v1/memo_service.proto` — defines `rpc CreateMemo(CreateMemoRequest) returns (Memo)`
4. **Generated Go Connect router/handler:** `proto/gen/api/v1/apiv1connect/memo_service.connect.go` — wires the HTTP path to the handler's `CreateMemo` method
5. **Connect adapter:** `server/router/api/v1/connect_services.go` — `ConnectServiceHandler.CreateMemo()` unwraps the Connect request and delegates to `APIV1Service.CreateMemo()`
6. **Server RPC implementation:** `server/router/api/v1/memo_service.go` — `APIV1Service.CreateMemo()` contains business logic, calls `s.Store.CreateMemo()`
7. **Store method:** `store/memo.go` — `Store.CreateMemo()` validates the UID, then calls `s.driver.CreateMemo()`
8. **SQL dialect driver (e.g. SQLite):** `store/db/sqlite/memo.go` — executes `INSERT INTO memo (...) VALUES (...) RETURNING id, created_ts, updated_ts, row_status`

(Other dialect drivers: `store/db/mysql/memo.go` and `store/db/postgres/memo.go`)
