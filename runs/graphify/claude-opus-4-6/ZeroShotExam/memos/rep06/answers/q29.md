**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (an `Interceptor` from `@connectrpc/connect`) attaches `Authorization: Bearer <token>` to every outgoing RPC request and handles transparent refresh-and-retry on `Unauthenticated` responses.

**Token kinds managed:**
1. **Access token** — a short-lived (15 min) HS256 JWT stored in `localStorage` under `memos_access_token` (managed in `web/src/auth-state.ts`), sent as `Authorization: Bearer <jwt>`.
2. **Refresh token** — a long-lived (30 days) HS256 JWT stored as an `HttpOnly` cookie named `memos_refresh`, sent automatically by the browser; used to rotate and obtain fresh access tokens.
3. **Personal Access Token (PAT)** — a random string prefixed `memos_pat_`, also sent as `Authorization: Bearer memos_pat_...`, distinguished from JWTs by the prefix and validated via SHA-256 hash lookup in the database.

**Backend validation package:** `server/auth` — specifically `server/auth/authenticator.go` (dispatches validation for all three token types), `server/auth/token.go` (JWT generation/parsing and PAT hashing with `github.com/golang-jwt/jwt/v5`), and `server/auth/extract.go` (header/cookie extraction). The server-side Connect interceptor that calls into this package lives at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`).
