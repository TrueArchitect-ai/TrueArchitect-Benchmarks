Frontend API requests are authenticated via a **ConnectRPC interceptor** in `web/src/connect.ts` (line ~156). Before each RPC call it obtains the current access token and sets an `Authorization: Bearer <token>` header. On an `Unauthenticated` response it attempts a single token refresh and retry.

**Interceptor path:** `web/src/connect.ts`

**Token kinds managed:**
- **Access token** (short-lived, 15 min) — stored in-memory and in `localStorage` (`memos_access_token`), managed by `web/src/auth-state.ts`. Sent as a Bearer token on every request.
- **Refresh token** (long-lived, 30 days) — sent/received as an HTTP-only cookie (`memos_refresh`), never directly touched by JS. Used by a dedicated unauthenticated transport to call `refreshToken` without recursion.
- **Personal access tokens (PATs)** — prefixed `memos_pat_`, also sent as Bearer tokens and validated server-side by hash lookup.

**Backend validation package:** `server/auth/` (Go package `auth`), which uses `github.com/golang-jwt/jwt/v5` with HMAC-SHA256. Key files:
- `server/auth/token.go` — generates and parses access/refresh/PAT tokens.
- `server/auth/authenticator.go` — stateless access-token validation, DB-checked refresh-token validation, PAT hash lookup.
- `server/auth/extract.go` — extracts the Bearer token from `Authorization` and the refresh token from the `Cookie` header.

The server-side ConnectRPC auth interceptor that wires this into request handling lives at `server/router/api/v1/connect_interceptors.go`.
