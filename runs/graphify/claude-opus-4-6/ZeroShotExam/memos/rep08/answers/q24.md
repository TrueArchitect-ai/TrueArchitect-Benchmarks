Here is the complete call chain for creating a memo, one hop per line:

1. **Frontend mutation hook:** `web/src/hooks/useMemoQueries.ts` — `useCreateMemo()` calls `memoServiceClient.createMemo()`
2. **ConnectRPC client:** `web/src/connect.ts` — `memoServiceClient` created via `createClient(MemoService, transport)` sends binary protobuf over HTTP
3. **Proto RPC definition:** `proto/api/v1/memo_service.proto` — `rpc CreateMemo(CreateMemoRequest) returns (Memo)`
4. **Connect server adapter:** `server/router/api/v1/connect_services.go` — `ConnectServiceHandler.CreateMemo()` unwraps the request and delegates to `APIV1Service`
5. **Service handler:** `server/router/api/v1/memo_service.go` — `APIV1Service.CreateMemo()` validates, builds a `store.Memo`, calls `s.Store.CreateMemo()`
6. **Store method:** `store/memo.go` — `Store.CreateMemo()` validates the UID then calls `s.driver.CreateMemo()`
7. **SQL dialect driver (e.g. SQLite):** `store/db/sqlite/memo.go` — executes `INSERT INTO memo (uid, creator_id, content, visibility, payload, ...) VALUES (?, ?, ?, ?, ?, ...) RETURNING id, created_ts, updated_ts, row_status`

(The other two dialect drivers are `store/db/postgres/memo.go` and `store/db/mysql/memo.go`.)
