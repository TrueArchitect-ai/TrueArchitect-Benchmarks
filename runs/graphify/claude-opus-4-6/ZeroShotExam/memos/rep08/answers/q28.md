**Runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours; refreshes expiring S3 presigned URLs. Started in `server/server.go:153-174` via `startBackgroundRunners()`, with an initial synchronous `RunOnce` then a goroutine running `Run`.
- **Cache Cleanup (×3 instances)** — `time.NewTicker` every 5 minutes; evicts expired entries from in-memory caches (instanceSettingCache, userCache, userSettingCache). Each spawned by `cache.New()` in `store/store.go:51-53`.
- **Async Email Workers (×2)** — channel-driven (buffered channel, cap 128); package-level `init()` in `internal/email/email.go:16` spawns 2 goroutines consuming from the queue.
- **Async Webhook Workers (×4)** — channel-driven (buffered channel, cap 128); package-level `init()` in `internal/webhook/webhook.go:42` spawns 4 goroutines consuming from the queue.
- **SSE Hub Heartbeat** — `time.NewTicker` every 30 seconds per SSE client connection (`server/router/api/v1/sse_handler.go:64`); keeps connections alive and forwards broadcast events.
- **PAT Usage Recorder** — fire-and-forget goroutine per auth event (`server/auth/authenticator.go:179`); updates `last_used` timestamp on personal access tokens.

**Scheduling infrastructure present but NOT used by the server:**

- **`internal/scheduler/` package** (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`, `doc.go`) — a fully-implemented cron-expression-based scheduler with timezone support, middleware chain (recovery, logging, timeout), and graceful shutdown. It is never imported by any production code; only referenced in its own example test.
- **Memo Payload Runner** (`server/runner/memopayload/runner.go`) — has a `RunOnce()` batch method to re-parse all memo payloads, but `NewRunner()` is never called by the server. Only the standalone `RebuildMemoPayload()` function is used inline during individual memo create/update operations in `server/router/api/v1/memo_service.go`.
