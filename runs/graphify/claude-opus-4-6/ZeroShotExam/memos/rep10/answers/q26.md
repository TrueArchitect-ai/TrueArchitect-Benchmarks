When `DeleteMemo` runs, the following database tables are affected:

1. **`memo_relation`** — The store-level `DeleteMemo` (`store/memo.go:140-146`) explicitly deletes all `memo_relation` rows where the memo is either the `memo_id` or `related_memo_id`.

2. **`attachment`** — The store-level `DeleteMemo` (`store/memo.go:149-157`) lists and deletes all attachments linked to the memo.

3. **`memo`** — The memo itself is deleted from the `memo` table (`store/memo.go:158`, SQL at `store/db/sqlite/memo.go:239`).

Additionally, the API-level `DeleteMemo` in `server/router/api/v1/memo_service.go:518-593` adds cascade logic for **comments**: it finds child memos via `memo_relation` (comment type) and recursively calls `Store.DeleteMemo` for each comment (`memo_service.go:569-577`), which in turn triggers the same cleanup of `memo_relation`, `attachment`, and `memo` for each comment.

**Tables affected: `memo`, `memo_relation`, `attachment`**
