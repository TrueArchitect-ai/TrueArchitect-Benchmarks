**Engine:** Google CEL (`github.com/google/cel-go`); the filter engine lives at `internal/filter/engine.go`.

**Mechanism:** The `Engine.Compile` method parses the CEL filter string into a checked AST via `cel.Env.Compile`, then `buildCondition` (in `internal/filter/parser.go`) walks the AST to produce a dialect-agnostic `Condition` IR (defined in `internal/filter/ir.go`), and `renderer.Render` (in `internal/filter/render.go`) translates that IR into SQL by switching on `DialectName` (`sqlite`, `mysql`, `postgres`) — each field's `Schema` carries per-dialect column expressions (`internal/filter/schema.go`), and the renderer emits dialect-specific SQL fragments (placeholders, function calls like `LENGTH` vs `CHAR_LENGTH`, date-part extraction, etc.) via per-dialect `case` branches throughout `render.go`.
