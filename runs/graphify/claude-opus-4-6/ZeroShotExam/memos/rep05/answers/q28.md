**Runners the server actually starts:**

- **S3 Presign Runner** — 12-hour `time.Ticker`; refreshes presigned URLs for S3-backed attachments (`server/runner/s3presign/runner.go`; started in `server/server.go:162–171`)
- **Cache Cleanup (×3 goroutines)** — 5-minute `time.Ticker` per cache instance; evicts expired entries (`store/cache/cache.go:200`; started implicitly by `cache.New()` in `store/store.go:51–53`)
- **Webhook Dispatch Workers (×4 goroutines)** — channel-consumer queue (`asyncPostQueue`, capacity 128); drain webhook POST payloads (`internal/webhook/webhook.go:39–55`; started in package `init()`)
- **Email Dispatch Workers (×2 goroutines)** — channel-consumer queue (`asyncEmailQueue`, capacity 128); send notification emails (`internal/email/email.go:14–36`; started in package `init()`)
- **SSE Heartbeat** — 30-second `time.Ticker` per connected SSE client; sends keep-alive pings (`server/router/api/v1/sse_handler.go:64`)

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — A fully-featured cron-expression-based job scheduler with middleware support (recovery, logging, timeout), timezone-aware scheduling, and graceful shutdown. It is **never imported by any production code**; only its own test files reference it (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`).
- **Memo Payload Runner** (`server/runner/memopayload/runner.go`) — Has a `Runner` struct with a bulk `RunOnce()` method that rebuilds all memo payloads in batches, but the runner is **never instantiated or started** by `startBackgroundRunners()`. Only the standalone `RebuildMemoPayload()` function is called inline during individual memo create/update operations in `memo_service.go`.
