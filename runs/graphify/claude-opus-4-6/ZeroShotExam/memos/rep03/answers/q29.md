**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (a Connect RPC `Interceptor`) attaches a `Bearer` access token to every outgoing request via the `Authorization` header, and handles automatic retry with token refresh on `Unauthenticated` errors.

**Token kinds:**
1. **JWT access token** (short-lived, 15 min) — stored in-memory and `localStorage` (`memos_access_token`), sent as `Authorization: Bearer <token>`.
2. **JWT refresh token** (long-lived, 30 days) — stored as an `HttpOnly` cookie named `memos_refresh`, sent automatically via `credentials: "include"`. Implements rotation (new token issued on each refresh, old one revoked).
3. **Personal access token (PAT)** — prefixed `memos_pat_`, SHA-256 hashed and stored in the database for programmatic API access.

**Backend package path:** `server/auth/` — this Go package contains `authenticator.go` (dispatches across all three token types), `token.go` (JWT generation/parsing, PAT hashing, duration constants), and `extract.go` (header/cookie extraction). The server-side Connect interceptor that calls into this package lives at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`).
