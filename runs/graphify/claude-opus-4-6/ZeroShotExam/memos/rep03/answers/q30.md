**Memo lifecycle events that dispatch webhooks:**

- **memo created**: `DispatchMemoCreatedWebhook` — `server/router/api/v1/memo_service_webhooks.go`
- **memo updated**: `DispatchMemoUpdatedWebhook` — `server/router/api/v1/memo_service_webhooks.go`
- **memo deleted**: `DispatchMemoDeletedWebhook` — `server/router/api/v1/memo_service_webhooks.go`
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` — `server/router/api/v1/memo_service_webhooks.go`

The first three delegate to the private helper `dispatchMemoRelatedWebhook` (same file), which resolves the memo creator, fetches their webhooks, and builds payloads. `DispatchMemoCommentCreatedWebhook` has its own implementation (it targets the *parent memo's* creator rather than the comment author) but uses the same delivery path.

**All converge for delivery at:** `webhook.Post` in `internal/webhook/webhook.go`

Specifically, every dispatch calls `webhook.PostAsync()` which enqueues the payload onto a buffered channel (`asyncPostQueue`). Worker goroutines drain that channel and call `webhook.Post()`, which marshals the JSON, optionally signs it (HMAC-SHA256 per Standard Webhooks spec), and sends the HTTP POST request. This is the single delivery point for all memo webhook events.
