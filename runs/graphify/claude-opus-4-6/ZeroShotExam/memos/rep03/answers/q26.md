When `DeleteMemo` runs, the following database tables are affected:

1. **`memo_relation`** — Deleted via `s.driver.DeleteMemoRelation()` in `store/memo.go:142-146`, which removes rows where the memo is either the source (`memo_id`) or target (`related_memo_id`).
2. **`attachment`** — Deleted via `s.driver.DeleteAttachment()` in `store/attachment.go:148`, called from the loop in `store/memo.go:153-156` for each attachment linked to the memo.
3. **`memo`** — The memo row itself is deleted via `s.driver.DeleteMemo()` in `store/memo.go:158`.

Additionally, at the service layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (related via `MemoRelationComment`) are recursively deleted by calling `s.Store.DeleteMemo` for each comment, which in turn cascades through the same three tables (`memo_relation`, `attachment`, `memo`) for each comment.
