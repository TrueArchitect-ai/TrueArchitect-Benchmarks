**Runners the server actually starts:**

- **S3 presign runner** — `time.NewTicker` at 12-hour intervals; re-presigns S3 attachment URLs expiring within 4 days. Started explicitly in `server/server.go:153-171` via `startBackgroundRunners`, which calls `s3presign.RunOnce` synchronously then launches `s3presign.Run` in a goroutine.
- **Webhook async dispatch workers (×4)** — driven by a buffered channel (`asyncPostQueue`, cap 128); goroutines started in `init()` at `internal/webhook/webhook.go:42-55`. Payloads enqueued by memo CRUD/comment events via `PostAsync`.
- **Email async dispatch workers (×2)** — driven by a buffered channel (`asyncEmailQueue`, cap 128); goroutines started in `init()` at `internal/email/email.go:16-36`. Payloads enqueued by the notification system via `SendAsync`.
- **Cache cleanup goroutines (×3)** — `time.NewTicker` at 5-minute intervals per cache instance; started when each `cache.Cache` is created in `store/cache/cache.go:83`. Three instances are created in `store/store.go:51-53` (`instanceSettingCache`, `userCache`, `userSettingCache`).

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — A complete cron-expression-based job scheduler with 5/6-field cron parsing (`parser.go`), middleware support (recovery, logging, timeout in `middleware.go`), named jobs (`job.go`), and graceful shutdown (`scheduler.go`). It is fully tested but **never imported outside its own test files** — no non-test `.go` file in the repository imports `"github.com/usememos/memos/internal/scheduler"`. The server does not use it; all actual periodic work uses raw `time.NewTicker` or channel-driven dispatch instead.
- **`server/runner/memopayload/runner.go`** — Defines a `Runner` struct with a `RunOnce` method for batch-rebuilding all memo payloads. The underlying `RebuildMemoPayload` function is called inline during memo create/update in `server/router/api/v1/memo_service.go`, but the `Runner` itself (and its `NewRunner` constructor) is never instantiated or started by the server.
