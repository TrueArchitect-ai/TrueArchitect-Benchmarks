q26. memo, memo_relation, attachment, memo_share

- `memo` — the row itself is deleted (store/db/postgres/memo.go:244-254, `DELETE FROM memo WHERE id = ...`).
- `memo_relation` — explicitly deleted by `Store.DeleteMemo` for both directions (`MemoID` and `RelatedMemoID`) before the memo row (store/memo.go:142-147).
- `attachment` — explicitly listed and deleted per attachment by `Store.DeleteMemo` (store/memo.go:149-157); note `attachment.memo_id` has no DB-level FK/cascade, so this cleanup is purely application code.
- `memo_share` — not touched by explicit Go code, but the schema defines `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (store/migration/postgres/LATEST.sql:108), so the database cascades the deletion automatically.

`reaction` (content_id is a plain TEXT column, no FK) is not affected by any explicit or cascade mechanism tied to memo deletion.
