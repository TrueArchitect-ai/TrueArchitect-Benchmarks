q26. Tables affected when `DeleteMemo` runs:

- **memo** — the row itself deleted (`store/memo.go:158`)
- **memo_relation** — explicitly deleted both where the memo is source and target (`store/memo.go:142-147`), and comment-relation rows are queried in the handler to recursively delete comment memos (`server/router/api/v1/memo_service.go:566-573`)
- **attachment** — explicitly listed and deleted per-memo (`store/memo.go:149-157`), including their storage blobs
- **memo_share** — deleted via DB-level `ON DELETE CASCADE` foreign key on `memo_id` (`store/migration/postgres/LATEST.sql:108`)

Note: `reaction` rows tied to the memo's `content_id` are listed in the API handler (`memo_service.go:544-548`, for the webhook payload) but are **not** explicitly deleted and have no FK cascade — they appear to be left orphaned.
