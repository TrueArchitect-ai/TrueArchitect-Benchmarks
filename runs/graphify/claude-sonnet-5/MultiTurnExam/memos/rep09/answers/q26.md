q26. `memo`, `memo_relation`, `attachment`, and `memo_share`.

- `memo` — the row itself is deleted (`store/memo.go:158`, driver `DeleteMemo`).
- `memo_relation` — explicitly deleted in code (`store/memo.go:142-147`, both as `memo_id` and `related_memo_id`).
- `attachment` — explicitly deleted in code (`store/memo.go:149-157`, lists then deletes each attachment linked via `memo_id`).
- `memo_share` — has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`), so it's removed automatically by the DB on memo deletion (not explicit Go code).

Note: `reaction` rows reference a `content_id` (not a memo FK) and are not cleaned up by `DeleteMemo`.
