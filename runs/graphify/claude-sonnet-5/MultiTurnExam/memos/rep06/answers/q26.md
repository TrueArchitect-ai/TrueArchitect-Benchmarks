q26. `memo`, `memo_relation`, `attachment`, and `memo_share` (via DB-level `ON DELETE CASCADE`)

- `memo` — the row itself is deleted last (`store/db/sqlite/memo.go` `DB.DeleteMemo`).
- `memo_relation` — explicitly deleted in Go code, both directions (`store/memo.go:142-147`, via `driver.DeleteMemoRelation`).
- `attachment` — explicitly listed and deleted per-row in Go code (`store/memo.go:149-157`, via `Store.DeleteAttachment`).
- `memo_share` — has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:102-109`), so rows are removed automatically by the DB when the memo row is deleted.

Other tables that reference `memo_id` (e.g. `reaction`, `memo_comment_relation` if present) don't appear to have an explicit `ON DELETE CASCADE` in the SQLite schema and aren't cleaned up in `Store.DeleteMemo`'s Go code — I did not verify each such table individually, so treat that as unconfirmed rather than a claim they're unaffected.
