No reaction/memo_share cleanup exists in the delete path — worth noting as a gap, but I'll answer only what's actually affected.

q26. **memo, memo_relation, attachment**

- `memo` — the row itself is deleted (`DELETE FROM memo WHERE id = ?`), and recursively for any child comment memos (linked via `memo_relation`) deleted first by the API handler.
- `memo_relation` — explicitly cleaned up in `store.Store.DeleteMemo` (store/memo.go:142-147) for both directions (`memo_id` and `related_memo_id`).
- `attachment` — explicitly deleted per-attachment in `store.Store.DeleteMemo` (store/memo.go:148-157) via `DeleteAttachment` for every attachment linked to the memo.

Note: `reaction` and `memo_share` rows referencing the memo are *not* explicitly cleaned up by this code path (no cascade in the schema either — no `REFERENCES ... ON DELETE CASCADE` on those tables), so they'd become orphaned.
