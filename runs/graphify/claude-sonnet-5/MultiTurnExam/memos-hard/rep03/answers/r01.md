Premise correction — there is no Redis-backed cache in this codebase; a repo-wide search finds no Redis import, client, or dependency in `go.mod` at all. Actual mechanism — the cache layer is an in-process, in-memory cache implemented in `store/cache/cache.go` (`type Cache` with `Set`/`Get`/`Delete`/`Clear`, TTL-based expiration and periodic cleanup, no external store). It's instantiated in `store/store.go:38-52` (`Store.New`), which builds three separate in-memory caches — `instanceSettingCache`, `userCache`, `userSettingCache` — all sharing one `cache.Config` (`store/store.go:39-44`). The TTL applied to user entries (and all entries, since all three caches reuse the same config) is `DefaultTTL: 10 * time.Minute` (`store/store.go:40`), with a `CleanupInterval` of 5 minutes and a cap of `MaxItems: 1000`.
