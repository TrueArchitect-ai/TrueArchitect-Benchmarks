**Premise correction:** There is no Redis anywhere in this codebase — a full-text search for "redis" across all `.go` files returns zero hits, and no Redis client dependency exists in `go.mod`. The cache layer is not backed by an external cache at all.

**Actual mechanism:** Caching is done with an in-process, in-memory cache implemented in `store/cache/cache.go` (a plain Go map guarded by locks, with TTL expiry and periodic cleanup — see the `Interface`/`Config` types at `store/cache/cache.go:11-52`). The `Store` holds three separate in-memory instances — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:27-29`) — all constructed in `store.New` (`store/store.go:38-58`) using the same `cacheConfig`.

**TTL for user entries:** `userCache` uses the shared default config set at `store/store.go:40-45`: `DefaultTTL: 10 * time.Minute` (with a 5-minute cleanup sweep interval and a 1000-item cap). No per-entry override is applied when user records are cached (`store/user.go:148-168`), so cached users expire after 10 minutes.
