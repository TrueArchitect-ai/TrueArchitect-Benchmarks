**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:76-87` — which calls `markdown.Service.ExtractAll` (implemented at `internal/markdown/markdown.go:356` onward) to parse the memo's markdown content in a single AST walk and populate `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers (recomputation):**

- `UpdateMemo`, specifically when the `content` field is in the update mask — `server/router/api/v1/memo_service.go:447` (only recomputed if the memo's text actually changed)

**Extracted properties** (`storepb.MemoPayload` / `MemoPayload_Property`, populated via the goldmark AST walk in `ExtractAll`, `internal/markdown/markdown.go:356-399+`):
- `Tags` — `#tag` occurrences (`asMemoTagNode`, `markdown.go:376-377`)
- `Property.Title` — text of the first H1 heading if it's the document's first block (`markdown.go:383-388`)
- `Property.HasLink` — presence of a markdown link (`markdown.go:393-394`)
- `Property.HasCode` — presence of code blocks/spans (`gast.KindCodeBlock`/`KindFencedCodeBlock`/`KindCodeSpan`, `markdown.go:396`)
- `Property.HasTaskList` / `Property.HasIncompleteTasks` — task-list items and whether any are unchecked (further down the same switch, not fully shown above but part of the same walk)

(`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` only assigns `Tags` and `Property` back onto the memo — mentions are used elsewhere, e.g. for notification dispatch, not persisted into `MemoPayload` by this path.)
