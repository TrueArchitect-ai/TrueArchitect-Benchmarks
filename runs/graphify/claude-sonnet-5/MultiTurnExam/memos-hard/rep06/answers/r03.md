**Premise correction:** There is no nightly database-cleanup job scheduled anywhere in this codebase, and the cron scheduler is not actually wired into the running server. The repo does contain a general-purpose cron implementation at `internal/scheduler/scheduler.go` (with `New`, `Register`, `Start`, cron-expression parsing, etc.), but a repo-wide search shows it is imported only by its own test files (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`) — never from `server/` or `cmd/`. No `scheduler.Register(...)` call exists in production code, so no job (nightly or otherwise) is ever scheduled through it.

**Actual mechanism:** "Cleanup"-type work in this codebase happens synchronously/inline rather than on a cron schedule — e.g. attachment storage cleanup on user deletion (`server/router/api/v1/user_service.go:421-450`) and memo relation/attachment cleanup during memo deletion (`server/router/api/v1/memo_service.go:579`). The only genuinely time-scheduled background work is the `s3presign.Runner` (12-hour ticker, see earlier), which is unrelated to database cleanup.
