**Premise correction:** Neither. There is no message broker (NATS or RabbitMQ) anywhere in this codebase — no such dependency in `go.mod`, and no NATS/RabbitMQ/AMQP client code exists.

**Actual mechanism:** Webhook delivery workers consume from an in-process, in-memory Go channel, not an external broker. It's declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` in `internal/webhook/webhook.go:39`. Four worker goroutines are spawned in that package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post` for every dequeued payload. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send and drops (with a warning log) if the buffered channel of 128 is full — there's no persistence or external queueing involved.
