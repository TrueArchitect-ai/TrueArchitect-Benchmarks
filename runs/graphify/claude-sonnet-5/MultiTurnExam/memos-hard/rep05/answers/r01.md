**Premise correction:** The repository has no Redis integration at all — there's no `redis` dependency in `go.mod` and no Redis client code anywhere in the codebase. Caching is implemented entirely as an in-process, in-memory cache.

**Actual mechanism:** The cache layer is `store/cache/cache.go`'s `Cache` type — a thread-safe in-memory `sync.Map` with TTL-based expiration and a periodic cleanup goroutine (no external connection to configure). It's instantiated in `(*Store).New` — `store/store.go:38-58` — which creates three separate `*cache.Cache` instances (`instanceSettingCache`, `userCache`, `userSettingCache`, `store/store.go:27-29,51-53`), all using the same `cacheConfig` built at `store/store.go:40-45`.

**TTL for user entries:** `userCache` is created with `cacheConfig.DefaultTTL = 10 * time.Minute` (`store/store.go:41`), and user entries are written via the plain `Set` method (e.g. `store/user.go:150,167,143`), which applies that default TTL (`store/cache/cache.go:93-95`). So a cached user entry expires 10 minutes after being set, with expired-item sweeps run every 5 minutes (`CleanupInterval`, `store/store.go:42`).
