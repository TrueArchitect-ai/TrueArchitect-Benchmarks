Premise correction: neither — there is no external message broker (no NATS, no RabbitMQ) involved in webhook delivery anywhere in this codebase. A repo-wide check found no such dependencies in `go.mod`, and the webhook dispatch path is fully in-process.

Actual mechanism: outbound webhook delivery uses an in-memory, buffered Go channel as its "queue" — `asyncPostQueue` (capacity 128), declared in `internal/webhook/webhook.go`, drained by 4 worker goroutines started in that package's `init()` (`webhook.go:42-55`). `PostAsync` (`webhook.go:184-196`) enqueues payloads onto this channel; each worker goroutine dequeues and calls `Post` (`webhook.go:120-180`), which performs the actual outbound HTTP request via `safeClient.Do`. There's no broker process, no persistence, and no external queue infrastructure — it's purely an in-process worker pool bounded by the channel's buffer size.
