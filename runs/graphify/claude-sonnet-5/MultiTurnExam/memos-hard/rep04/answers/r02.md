Premise correction: no per-user (or any) API rate-limiting middleware exists in this repository. A repo-wide search for rate limiting/throttling terms turns up nothing implemented — `golang.org/x/time/rate` is present in `go.mod`/`go.sum` only as an `// indirect` transitive dependency, never imported by memos' own code (the only textual hit is an aspirational comment in `internal/email/doc.go:86`).

What actually exists and could be confused for it:
- Echo middleware stack registers only `middleware.Recover()` and CORS (`server/server.go:50-53`) — no throttling.
- Connect-RPC interceptor chain is `MetadataInterceptor → LoggingInterceptor → RecoveryInterceptor → AuthInterceptor` (`server/router/api/v1/connect_interceptors.go`) — no rate-limit interceptor.
- A 256 MiB request body-size cap via `http.MaxBytesHandler` (`server/router/api/v1/v1.go:20`) — limits payload size, not frequency.
- Global (not per-user) concurrency semaphores capping in-flight thumbnail/image-processing work (`thumbnailSemaphore`, `imageProcessingSemaphore`, `server/router/api/v1/v1.go:39-41`, backed by `golang.org/x/sync/semaphore`), which return `codes.ResourceExhausted` when exhausted — superficially rate-limit-like but actually a global concurrency cap, not a time-windowed per-user quota.
