Premise correction: there is no Redis integration anywhere in this repository — no import, dependency, or config string matching "redis" exists in `go.mod`, `go.sum`, or any `.go` file. The cache layer is not Redis-backed at all.

Actual mechanism: the cache is a self-contained in-memory implementation, `store/cache/cache.go`, built on `sync.Map` (struct at `store/cache/cache.go:67-73`), with no external process/network dependency. It's instantiated as three independent instances — `instanceSettingCache`, `userCache`, `userSettingCache` — in `store/store.go:38-58` (`New`), each configured with `DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000` (`store/store.go:51-53`). So the "TTL for user entries" is 10 minutes, enforced both lazily on `Get` (`store/cache/cache.go:123-147`, checking `time.Now().After(itm.expiration)`) and proactively by a background `cleanupLoop` ticking every 5 minutes (`store/cache/cache.go:200-250`), plus a 1000-item cap that evicts the oldest ~20% when exceeded (`cleanupOldest`, `store/cache/cache.go:253-313`).
