**Premise correction:** This repository has no Redis integration at all — a repo-wide grep for "redis" (case-insensitive, all `.go` files and `go.mod`) returns zero hits. There is no external cache server involved.

**Actual mechanism:** The cache layer is an in-process, in-memory cache implemented in `store/cache/cache.go` (type `Cache`, with `Set`/`Get`/`Delete`/`Close`, a background cleanup goroutine, and TTL-based expiration — no network client). The `Store` (`store/store.go:13-30`) holds three instances of it — `instanceSettingCache`, `userCache`, `userSettingCache` — all constructed in `store.New` (`store/store.go:38-53`) with a shared `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user entries (`userCache`, `store/store.go:52`) get a **10-minute default TTL**, with a background sweep every 5 minutes evicting expired/over-capacity entries — all local to the server process, not Redis.
