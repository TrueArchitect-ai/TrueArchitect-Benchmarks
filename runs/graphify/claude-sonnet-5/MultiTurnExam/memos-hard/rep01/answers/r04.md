**Premise correction:** Neither. There is no message broker in this codebase — a repo-wide, case-insensitive search for "nats", "rabbitmq", and "amqp" across all `.go` files returns zero hits, and `go.mod` has no such dependency.

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel as its queue: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared in `internal/webhook/webhook.go:39`. A pool of 4 goroutines started in that package's `init()` (`internal/webhook/webhook.go:42-55`) reads from `asyncPostQueue` and calls `Post` for each payload. `PostAsync` (called from the RPC handlers, e.g. `server/router/api/v1/memo_service_webhooks.go`) simply enqueues onto this channel — there's no external broker, persistence, or cross-process delivery involved; the queue is entirely local to the running server process and lost on restart.
