**Premise correction:** There is no per-user API rate-limiting middleware in this codebase. A repo-wide, case-insensitive search for `rate.?limit`, `ratelimit`, and `throttle` across all `.go` files (including tests) returns zero matches.

The only middleware registered globally on the Echo server (`server/server.go:50-52`) is:
```go
echoServer.Use(middleware.Recover())
echoServer.Use(newCORSMiddleware(profile))
```
— panic recovery and CORS handling. No rate-limiter (Echo's own `middleware.RateLimiter`, a token-bucket, or any custom implementation) is wired in anywhere.

The closest things that exist are unrelated *concurrency* limits, not request-rate limits: `semaphore.Weighted` guards on `APIV1Service` (`thumbnailSemaphore`, `imageProcessingSemaphore`, `server/router/api/v1/v1.go:39-41`) and on `FileServerService` (`thumbnailSemaphore`, `server/router/fileserver/fileserver.go:106-107`), which cap concurrent thumbnail/image-processing work per server instance — not per-user request throughput, and with no time-window or quota semantics.
