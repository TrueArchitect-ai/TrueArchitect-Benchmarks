**Premise correction:** There is no Redis connection anywhere in this codebase — a repo-wide search (`grep -rli redis`) turns up zero references. The `memos` cache layer is entirely in-process, not backed by an external cache server.

**Actual mechanism:** The cache is `store/cache/cache.go`'s `Cache` type — a thread-safe in-memory map with TTL and eviction (`store/cache/cache.go:66`). It's instantiated per-`Store` in `store/store.go:38-61` (`store.New`), which creates three separate in-memory caches (`instanceSettingCache`, `userCache`, `userSettingCache`) all sharing one `cache.Config`:
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
(`store/store.go:40-45`)

**TTL for user entries:** every write to `userCache` (`store/user.go:98,122,132,143,167`) uses the plain `Set` method (`store/cache/cache.go:92-95`), which applies `c.config.DefaultTTL` — i.e. **10 minutes** — rather than `SetWithTTL` with a custom duration. So cached `User` records expire after 10 minutes (or earlier if evicted once the cache exceeds 1000 items).
