**Premise correction** — there is no Redis anywhere in this codebase; a repo-wide search for "redis" (case-insensitive, across all `.go` files) returns zero matches. The cache layer is not backed by an external cache server at all.

**Actual mechanism** — the "cache layer" is an in-process, in-memory cache implemented in `store/cache/cache.go` (`Cache` type / `Interface`, backed by a `sync`-guarded map of `item{value, expiration, size}`, with its own background cleanup goroutine — no network connection or configuration of any kind is needed since it never leaves the process). The user cache instance (`userCache`) is constructed in `store/store.go:52` (`cache.New(cacheConfig)`), using the shared `cacheConfig` defined at `store/store.go:40-45`, which sets `DefaultTTL: 10 * time.Minute` (with a 5-minute cleanup sweep interval and a 1000-item cap). So: **user entries expire after 10 minutes**, enforced entirely in-process, not via Redis.
