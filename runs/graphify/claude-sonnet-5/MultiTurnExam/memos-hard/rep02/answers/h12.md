**How I determined it (among the sqlite/postgres/mysql candidates):**
1. `Store.CreateMemo` (`store/memo.go:109`) is a thin wrapper that just calls `s.driver.CreateMemo(...)` — the `store.Driver` interface (`store/driver.go`) has three concrete implementations: `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`.
2. Which one is wired up is decided at startup by `NewDBDriver` (`store/db/db.go:14-32`), which switches on `profile.Driver` and calls `sqlite.NewDB`/`mysql.NewDB`/`postgres.NewDB` accordingly.
3. `profile.Driver` defaults to `"sqlite"` when no `--driver` flag/env is supplied: `viper.SetDefault("driver", "sqlite")` and the flag default `rootCmd.PersistentFlags().String("driver", "sqlite", ...)`, both in `cmd/memos/main.go:122,130`.
4. So with a default install (no DB flags), `NewDBDriver` takes the `case "sqlite"` branch, `store.driver` is a `*sqlite.DB`, and every `Store.CreateMemo` call resolves at runtime to `(*sqlite.DB).CreateMemo` in `store/db/sqlite/memo.go`, ruling out the postgres/mysql implementations as dead code for this configuration.
