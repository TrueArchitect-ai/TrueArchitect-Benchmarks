**Premise correction:** There is no Redis-backed cache anywhere in this repository — a repo-wide search for "redis" turns up zero matches. The cache layer is a plain in-process, in-memory cache with no external connection to configure.

**Actual mechanism:** User entries are cached via `store.userCache`, an in-memory `*cache.Cache` (`store/cache/cache.go`) constructed in `store.New` at `store/store.go:52` (`userCache: cache.New(cacheConfig)`). The TTL comes from the shared `cacheConfig` built at `store/store.go:40-45`: `DefaultTTL: 10 * time.Minute` (with a 5-minute background cleanup interval and a 1000-item cap). Entries are set with this default TTL via `Cache.Set` → `SetWithTTL(ctx, key, value, c.config.DefaultTTL)` (`store/cache/cache.go:94`), and are populated/read by `Store.GetUser`/`Store.ListUsers` (`store/user.go:148-169`, `136-146`).
