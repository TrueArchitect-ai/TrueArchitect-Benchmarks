Premise correction: there is no Redis anywhere in this codebase — I grepped the whole repo case-insensitively for "redis" and checked `go.mod`; no dependency or reference exists. The cache layer is a pure in-process, in-memory implementation, not a Redis-backed one.

Actual mechanism: the user cache is `store/cache/cache.go`'s in-memory `Cache` type (map-backed, with its own TTL/eviction goroutine, no external connection to configure). It's instantiated as `store.userCache` in `store/store.go:52` via `cache.New(cacheConfig)`, using the shared `cacheConfig` built at `store/store.go:38-43`: `DefaultTTL: 10 * time.Minute` (with `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000`). That 10-minute default TTL is what applies to cached user entries (individual calls can override it via `SetWithTTL`, but the default path uses this value).
