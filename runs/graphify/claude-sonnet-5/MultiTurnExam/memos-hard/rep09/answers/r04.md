**Premise correction:** This repository uses neither NATS nor RabbitMQ (or any external message broker) for webhook delivery. There is no such dependency in `go.mod` and no `nats`/`rabbitmq`/`amqp` reference anywhere in the codebase.

**Actual mechanism:** Webhook delivery is queued entirely in-process using a buffered Go channel, declared in `internal/webhook/webhook.go:39`:
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```
`PostAsync` (`internal/webhook/webhook.go:184-196`) enqueues onto this channel (line 190, non-blocking with a fallback), and a fixed pool of worker goroutines spawned in `init()` (`internal/webhook/webhook.go:42-55`) range over `asyncPostQueue` and call `Post` for each payload. This is purely an in-memory channel local to the server process — it does not persist across restarts and involves no external broker or network queue declaration.
