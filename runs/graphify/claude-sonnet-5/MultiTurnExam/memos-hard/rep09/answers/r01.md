**Premise correction:** This repository has no Redis dependency at all — no `redis` import, client, or connection config anywhere in the codebase (`go.mod` has no Redis client library, and a repo-wide search for "redis" returns nothing). The cache layer is not backed by an external Redis instance.

**Actual mechanism:** The cache layer is an in-process, in-memory cache implemented in `store/cache/cache.go` (`type Cache struct`, TTL/eviction logic), with no network connection to configure. `store.New` (`store/store.go:37-53`) constructs three separate in-memory caches — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:27-29,51-53`) — all sharing one `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So the TTL applied to `userCache` entries (user records looked up via `store.GetUser`) is **10 minutes** (`store/store.go:41`), with a background cleanup sweep every 5 minutes and a 1000-item cap — all in-process, no Redis involved.
