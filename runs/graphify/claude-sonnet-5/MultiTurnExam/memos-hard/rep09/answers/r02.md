**Premise correction:** There is no per-user API rate-limiting middleware in this repository. A repo-wide search for rate-limiting terms (`ratelimit`, `throttle`, `RateLimiter`, `x/time/rate`, `Limiter`) turns up nothing under `server/` or elsewhere, and no such middleware is registered on the Echo server or the Connect/gRPC-Gateway stack in `server/server.go` or `server/router/api/v1/v1.go`.

The closest related mechanisms in the codebase are concurrency *limiters*, not request-rate limiters, and they are global (not per-user):
- `APIV1Service.thumbnailSemaphore` and `imageProcessingSemaphore` (`server/router/api/v1/v1.go:39-40`) — `semaphore.Weighted` instances capping concurrent thumbnail/image-processing work (3 and 2 slots respectively, set in `NewAPIV1Service`, `server/router/api/v1/v1.go:52-56`), unrelated to per-user request throttling.

There is no component that tracks or limits requests-per-user-per-time-window anywhere in the server.
