Premise correction: this repository has no per-user API rate-limiting middleware — the premise of the question is incorrect.

The full interceptor chain registered for the API (server/router/api/v1/v1.go:133-137) is only:

- `NewLoggingInterceptor()` (connect_interceptors.go:103)
- `NewRecoveryInterceptor()` (connect_interceptors.go:170)
- `NewAuthInterceptor()` (connect_interceptors.go:213)

None of these implement request throttling or rate limiting. A repo-wide search for "rate limit", "ratelimit", "throttle", and "limiter" across `.go` files turns up no rate-limiting logic (the only incidental hit, `internal/email/doc.go`, is unrelated to the API and doesn't even mention rate limits). There's also no other middleware/interceptor file in the codebase besides `internal/scheduler/middleware.go`, which handles background job cross-cutting concerns (panic recovery, logging) — not HTTP/API requests.

So there's no middleware to point to for request limits, and no numeric limits configured anywhere in the repo.
