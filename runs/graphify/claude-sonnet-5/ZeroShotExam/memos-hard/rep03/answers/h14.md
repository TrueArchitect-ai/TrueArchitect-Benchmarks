h14. Derived memo metadata (tags, title, and content-shape flags used by list/preview UI) is computed by `internal/markdown/markdown.go`'s `service.ExtractAll` (and the single-purpose `ExtractProperties`), which parses the memo's markdown into a goldmark AST and walks it once (`internal/markdown/markdown.go:356-409`, `internal/markdown/markdown.go:192-241`). The extracted data is stored on `MemoPayload`/`MemoPayload.Property` (`proto/store/memo.proto:7-22`, generated into `storepb.MemoPayload_Property`).

- **Computation site:** `internal/markdown/markdown.go` — `(*service).ExtractAll()` walks the parsed AST once to collect tags, `#mentions`, and `Property` fields; `ExtractProperties()` does the same for just the boolean/title fields. The wrapper `memopayload.RebuildMemoPayload()` in `server/runner/memopayload/runner.go:74-88` calls `ExtractAll` and assigns the result onto `memo.Payload.Tags` / `memo.Payload.Property`.
- **Triggers:** 
  - `CreateMemo` — always calls `RebuildMemoPayload` right after building the new memo (`server/router/api/v1/memo_service.go:108`).
  - `UpdateMemo` — calls `RebuildMemoPayload` only when `"content"` is present in the request's `update_mask` (`server/router/api/v1/memo_service.go:434-451`); metadata is left untouched for updates that don't touch content.
  - `memopayload.Runner.RunOnce()` (`server/runner/memopayload/runner.go:26-72`) batch-rebuilds every memo's payload via `RebuildMemoPayload` + `Store.UpdateMemo`, but note it isn't wired into `server/server.go`'s startup/cron flow (only `s3presignRunner.RunOnce` is called there) — it appears to be a standalone/backfill utility, not an active recomputation trigger today.
  - A related but separate extraction, `ExtractAll` in `server/router/api/v1/memo_mention_helpers.go:32`, re-parses content specifically to resolve `@mentions` for notifications (not for the stored `Property`/tags metadata).
- **Extracted properties** (from the AST walk):
  - `Tags` — `#tag` nodes (`asMemoTagNode`), deduplicated case-preserving.
  - `Mentions` — `@username` nodes (used for notifications, not persisted as memo metadata).
  - `Property.Title` — text of the first block-level child if it's an H1 heading.
  - `Property.HasLink` — any `Link` AST node.
  - `Property.HasCode` — any code block, fenced code block, or code span.
  - `Property.HasTaskList` / `Property.HasIncompleteTasks` — presence of task checkboxes, and whether any are unchecked.

These fields (`proto/store/memo.proto:15-22`) are what memo list/preview components (e.g. `web/src/components/MemoContent`, `MemoPreview`, `PagedMemoList`) read to render badges/snippets without re-parsing the full markdown client-side.
