Premise correction: this repository (usememos/memos) doesn't use NATS or RabbitMQ for webhook delivery — there is no external message broker involved at all.

Actual mechanism: webhook dispatch is done via an in-process buffered Go channel. In `internal/webhook/webhook.go:39`, `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)`, and `init()` (webhook.go:42-55) spawns 4 goroutine workers that range over this channel and call `Post()` for each payload. `PostAsync()` (webhook.go:184-196) enqueues payloads into this channel, dropping them with a warning log if the queue is full. A repo-wide search for `nats`/`rabbitmq`/`amqp` found no broker client code or dependency — the only hit was an unrelated Catalan locale string in `web/src/locales/ca.json`.
