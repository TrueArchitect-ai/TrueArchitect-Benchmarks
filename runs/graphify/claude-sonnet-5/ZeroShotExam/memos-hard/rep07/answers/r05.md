**Premise correction:** There is no GraphQL schema in this repository — the premise of the question is false. This is the `usememos/memos` codebase, and its public API is built on **Protocol Buffers + gRPC/gRPC-Gateway (REST)**, not GraphQL. No `.graphql`/`.gql` files or GraphQL server code exist anywhere in the repo (confirmed via full-tree search).

**Actual API surface:**
- Proto definitions (the real schema-of-record): `proto/api/v1/*.proto` (e.g. `memo_service.proto`, `user_service.proto`, etc.)
- Store-layer protos: `proto/store/*.proto` (e.g. `proto/store/memo.proto`, `proto/store/idp.proto`, `proto/store/attachment.proto`, `proto/store/inbox.proto`, `proto/store/user_setting.proto`, `proto/store/instance_setting.proto`)
- Codegen config: `proto/buf.yaml`, `proto/buf.gen.yaml`, `proto/buf.lock` (buf-based generation)
- Generated Go/gRPC-gateway code: `proto/gen/api`, `proto/gen/store`
- Generated OpenAPI/REST spec (derived from the proto definitions via grpc-gateway annotations): `proto/gen/openapi.yaml`, embedded via `proto/openapi_embed.go`
- `proto/README.md` documents the proto/codegen workflow

So the public API's schema-of-record lives in the `.proto` files under `proto/api/v1/` and `proto/store/`, with REST exposed via grpc-gateway (OpenAPI spec auto-generated into `proto/gen/openapi.yaml`) — confirmed by `README.md`'s "full REST and gRPC APIs" description.
