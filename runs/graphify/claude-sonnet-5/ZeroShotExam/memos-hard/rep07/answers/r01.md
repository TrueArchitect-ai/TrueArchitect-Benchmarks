**Premise correction:** There is no Redis connection anywhere in this repository (it's the `usememos/memos` Go app) — a repo-wide `grep -ri redis` returns zero matches. The cache layer is an in-process, in-memory cache, not Redis.

**Actual mechanism:** The cache is implemented in `store/cache/cache.go` as a thread-safe in-memory store (`sync.Map`-backed) with TTL expiry, a cleanup goroutine, and max-item eviction — no external cache service is involved.

It's wired up in `store/store.go:38-58`. In `store.New()`, a shared `cache.Config` is built with `DefaultTTL: 10 * time.Minute` (`store/store.go:41`), and three separate `*cache.Cache` instances are created from it: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29, 51-53`).

So **user entries** (`userCache`, used in `store/user.go:151`) get a **10-minute TTL**, the same `DefaultTTL` applied to the other two caches (`instanceSettingCache`, `userSettingCache`) since they all share the same `cacheConfig`. Cleanup of expired entries runs every 5 minutes (`CleanupInterval`), and each cache is capped at 1000 items (`MaxItems`) with LRU-ish eviction of the oldest 20% when exceeded.
