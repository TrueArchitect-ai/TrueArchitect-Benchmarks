Enforcement site — `server/router/api/v1/memo_service.go` (`checkMemoReadAccess`, lines 39–68, called from `GetMemo` and reused by `memo_service_comments.go:148`) — the Connect/gRPC API service layer's per-request read-access check: rejects archived memos to non-creators, and for non-public memos requires an authenticated user who is either the creator or (for protected) not blocked, else `PermissionDenied`/`Unauthenticated`.

Enforcement site — `server/router/fileserver/fileserver.go` (`checkAttachmentPermission`, lines ~649–702) — a separate Echo-based HTTP surface (raw attachment/file downloads) that independently re-derives the memo's visibility and enforces it (public allowed only if `AllowAnonymous()`, share-token fallback, private restricted to creator/admin) rather than delegating to `checkMemoReadAccess`.

Enforcement site — `server/router/rss/rss.go` (`GetExploreRSS` line 90, `GetUserRSS` line 141) — the RSS/Atom feed HTTP surface enforces visibility by construction, hardcoding `VisibilityList: []store.Visibility{store.Public}` on every `ListMemos` query so private/protected memos are never fetched for the feed.

Enforcement site — `server/router/frontend/frontend.go` (`getSitemapXML`, line ~150) — the frontend/SEO surface (sitemap.xml) likewise restricts to `VisibilityList: []store.Visibility{store.Public}` when listing memos to include as URLs.

Additional independently-duplicated checks within the API v1 surface itself (not routed through the shared `checkMemoReadAccess` helper, so effectively their own enforcement sites): `server/router/api/v1/reaction_service.go` (lines 30, 38, 83), `server/router/api/v1/memo_attachment_service.go` (lines 214, 222), `server/router/api/v1/attachment_service.go` (lines 445, 451), `server/router/api/v1/memo_mention_helpers.go` (lines 62, 67, 84), and `server/router/api/v1/memo_service_comments.go` (lines 41, 100) each re-implement the same `Visibility == store.Private && CreatorID != user.ID` style check inline rather than calling the central helper.
