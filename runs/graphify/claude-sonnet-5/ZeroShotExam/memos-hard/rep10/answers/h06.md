**Handlers whose call paths transitively reach an outbound HTTP request to a user-configured URL** (this is the Memos codebase — `usememos/memos`):

- `CreateMemo` — `server/router/api/v1/memo_service.go:70` (dispatches webhook at `memo_service.go:157`)
- `UpdateMemo` — `server/router/api/v1/memo_service.go:401` (via `dispatchMemoUpdatedSideEffects`, `memo_service.go:513`)
- `SetMemoAttachments` / memo-relation updates — `server/router/api/v1/memo_attachment_service.go:48` and `memo_relation_service.go:48` also call `dispatchMemoUpdatedSideEffects`
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go` (calls `DispatchMemoCommentCreatedWebhook` at line 119)

Each of these calls a `Dispatch*Webhook` method (`server/router/api/v1/memo_service_webhooks.go`), which loads the user's stored webhook URLs (`s.Store.GetUserWebhooks`) and calls `webhook.PostAsync(payload)`.

**Convergence function:** `Post(requestPayload *WebhookRequestPayload) error` — `internal/webhook/webhook.go:126`

`PostAsync` (`internal/webhook/webhook.go:184`) just enqueues onto `asyncPostQueue`; a pool of 4 worker goroutines (`webhook.go:41-53`) drains that queue and calls `Post`, which is where `http.NewRequest("POST", requestPayload.URL, ...)` and `safeClient.Do(req)` (`webhook.go:126,152`) actually perform the outbound request to the user-configured webhook URL (SSRF-guarded via `safeDialContext`, `webhook.go:58`).

(A separate, unrelated convergence point exists for link-metadata fetching — `GetLinkMetadata`/`BatchGetLinkMetadata` in `server/router/api/v1/memo_service_link_metadata.go` both call `getLinkMetadata` → `fetchHTMLMeta` → `httpgetter.GetHTMLMeta` — but there the URL is a per-request argument, not a stored/"configured" one, so the webhook path above better fits "user-configured URL.")
