The premise of this question is incorrect: this repository (usememos/memos — Go backend with an Echo HTTP server and Connect/gRPC-Gateway API) has no per-user API rate-limiting middleware.

What's actually registered:
- HTTP middleware: only panic recovery (`middleware.Recover()`) and a custom CORS middleware are registered in `server/server.go` (~lines 51-52; CORS defined in `server/cors.go`).
- Connect RPC interceptor chain in `server/router/api/v1/v1.go` (lines 133-141): `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` (from `server/router/api/v1/connect_interceptors.go` and `server/auth/context.go`) — none of these throttle or count requests.

The only vaguely related mechanism is a concurrency **semaphore** (not a rate limiter) guarding simultaneous image/EXIF processing in `server/router/api/v1/attachment_service.go:160`, which returns `codes.ResourceExhausted` when too many concurrent image-processing jobs are in flight — this has no time window or per-user request counting. There's also a documentation-only example (not implemented code) in `internal/email/README.md:290-297` suggesting `golang.org/x/time/rate` for throttling outbound SMTP email (10/sec), but no such dependency exists in `go.mod` and nothing is wired up.

So there's no file/line to cite for "per-user API rate-limiting middleware" or its limits, because that component doesn't exist in this codebase.
