h04. yes; evidence

The driver-selection factory is `NewDBDriver` in `store/db/db.go:14-30`, which dispatches on `profile.Driver` and for the `"mysql"` case calls `mysql.NewDB(profile)` (`store/db/db.go:22`) — this is the only call site of `mysql.NewDB` in the codebase (confirmed via `grep -rn "mysql.NewDB"`), and `store/db/db.go` is the only file that imports the `store/db/mysql` package.

However, outside that factory, the MySQL driver is constructed directly via `database/sql`'s `sql.Open("mysql", dsn)` in the test helper `store/test/containers.go`:
- `store/test/containers.go:145` — `db, err := sql.Open("mysql", dsn)` inside `createFreshMySQLDatabase` (or similar helper), used to spin up a fresh database on a MySQL testcontainer.
- `store/test/containers.go:176` — inside `waitForDB(driver, dsn, ...)`, called with `driver="mysql"` (from line 127: `waitForDB("mysql", dsn, ...)`), which internally does `db, err := sql.Open(driver, dsn)`.

Both bypass `store/db/mysql.NewDB` / `NewDBDriver` entirely and open a raw `*sql.DB` against the MySQL driver directly, for test-container setup purposes (creating/polling a MySQL database before tests run) rather than as the application's `store.Driver`.
