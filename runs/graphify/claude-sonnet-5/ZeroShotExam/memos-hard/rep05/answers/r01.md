r01. Premise correction: there is no Redis anywhere in this codebase (this is the `usememos/memos` Go project) — the cache layer is a custom in-process, in-memory cache (`sync.Map`-backed), not Redis.

Actual mechanism: it's implemented in `store/cache/cache.go` (`Cache` struct, lines 66–90), and user entries are cached via a dedicated `userCache` instance constructed in `store/store.go:52` (`userCache: cache.New(cacheConfig)`), using the `cacheConfig` defined at `store/store.go:40-45`:
- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

User records are read/written through this cache with the default TTL in `store/user.go` (e.g. `s.userCache.Set(ctx, userCacheKey(user.ID), user)` at lines 98, 122, 132, 143, 167, and read at line 150), and evicted on delete via `deleteUserCache` in `store/user_delete.go:39-40`. Since `Set` calls `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`), **user entries expire after 10 minutes**.
