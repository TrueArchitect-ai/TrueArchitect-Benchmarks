**Premise correction:** Neither. The webhook delivery workers don't consume from an external message broker at all — there is no NATS or RabbitMQ integration anywhere in this codebase (no `nats`, `rabbitmq`, or `amqp` references in the Go/TS/JS source).

**Actual mechanism:** Webhook delivery is handled entirely in-process via a buffered Go channel used as an in-memory queue, defined in `internal/webhook/webhook.go`:

- The queue is declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a channel with a capacity of 128 pending payloads.
- Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`), each running `for payload := range asyncPostQueue { ... Post(payload) ... }` to drain the channel and dispatch the HTTP webhook request.
- Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send and drops (with a warning log) if the channel is full — i.e., there's no persistence or external broker backing this queue; it's purely an in-memory, non-durable buffer scoped to the single running process.
