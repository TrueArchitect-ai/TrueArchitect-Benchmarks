**Mechanism:** Explicit Go application code (not a database-level constraint). The `reaction` table has no foreign keys at all, so nothing happens automatically at the DB level — deletion is done manually in a transaction by the store layer.

**Evidence locations:**

- `server/router/api/v1/user_service.go:393-414` — `DeleteUser` API handler calls `s.Store.DeleteUser(...)`.
- `store/user.go:171` — `Store.DeleteUser` delegates to the DB driver.
- Driver implementations (identical logic per backend): `store/db/postgres/user_delete.go:29`, `store/db/mysql/user_delete.go:29`, `store/db/sqlite/user_delete.go:29` — each runs `deleteUserTargetsTx` inside a transaction.
- Explicit reaction deletion calls, e.g. `store/db/postgres/user_delete.go:96-104`:
  - `deleteReactionsByContentIDsTx` (`postgres/user_delete.go:380-388`) → `DELETE FROM reaction WHERE content_id IN (...)` — removes reactions **on** the deleted user's own memos/comments (from anyone).
  - `deleteReactionsByCreatorTx` (`postgres/user_delete.go:400-403`) → `DELETE FROM reaction WHERE creator_id = ?` — removes reactions the deleted user made on anyone's content.
- Schema check: `store/migration/postgres/LATEST.sql:91-98` (and MySQL/SQLite equivalents) defines `reaction` with `creator_id INTEGER NOT NULL` and `content_id TEXT NOT NULL` — no `FOREIGN KEY`/`REFERENCES` clause on either column. A `grep -n "REFERENCES"` on that file finds only an unrelated `memo_share.memo_id → memo(id) ON DELETE CASCADE` constraint, confirming reactions have zero DB-enforced linkage to `users`.
- Test coverage confirming behavior: `store/test/user_delete_test.go:97-220` and `server/router/api/v1/test/user_service_delete_test.go:71` (asserts own/received reactions are gone, peer's unrelated reactions survive) and `:328` `TestDeleteUserRollbackPreservesAllResources` (confirms it's all-or-nothing via one transaction).

So: reactions are cleaned up correctly today, but only because every deletion path goes through `Store.DeleteUser`'s transaction — the DB schema itself provides no safety net if a user row were ever deleted by other means.
