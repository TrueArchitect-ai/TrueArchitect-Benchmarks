**Premise correction:** There is no Redis anywhere in this repository — I searched the full tree (`grep -ril "redis"`, all extensions) and found zero matches. This is the [usememos/memos](https://github.com/usememos/memos) codebase (Go backend + React frontend), and it has no external cache dependency at all.

**Actual mechanism:** Caching is done with an in-process, thread-safe in-memory cache (`sync.Map`-backed), defined in `store/cache/cache.go`. The `Store` struct in `store/store.go:13-30` holds three separate instances of this cache — `instanceSettingCache`, `userCache`, and `userSettingCache` — all constructed with the same default config at `store/store.go:40-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

User entries specifically go through `userCache` (`store/store.go:52`), keyed by `userCacheKey(userID)` and populated/read in `store/user.go` (e.g. lines 88, 98, 122, 132, 143, 150-151, 167). Since callers use `Set` (not `SetWithTTL`), user entries get the store-wide default TTL of **10 minutes**, with a 5-minute background cleanup sweep and a 1000-item cap (`store/cache/cache.go:56-64`, 92-95).
