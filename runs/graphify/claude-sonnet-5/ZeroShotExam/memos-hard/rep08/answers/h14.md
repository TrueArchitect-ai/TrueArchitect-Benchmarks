**Triggers (recomputation call sites):**
- `server/router/api/v1/memo_service.go:108` — `CreateMemo`, run on every new memo's content before it's persisted.
- `server/router/api/v1/memo_service.go:447` — `UpdateMemo`, run only when the update mask includes the `content` path (i.e., the memo body actually changed).
- `server/runner/memopayload/runner.go:27` (`Runner.RunOnce`) — a batch job that rebuilds payloads for all memos in pages of 100 via `RebuildMemoPayload` + `store.UpdateMemo`. Note: this runner is not currently wired into `startBackgroundRunners` in `server/server.go` (unlike `s3presign.Runner`, which is), so today it's only invoked directly/manually rather than on a live schedule — the two request-time call sites above are the active triggers.

**Extracted properties** (from a single goldmark AST walk over `memo.Content`):
- `Tags` — `#tag` occurrences (via the tag extension), stored on `MemoPayload.tags`.
- `Property.title` — text of the first block-level node if it's an H1 heading.
- `Property.has_link` — any Markdown link node present.
- `Property.has_code` — any code block, fenced code block, or code span present.
- `Property.has_task_list` — any task-list checkbox present.
- `Property.has_incomplete_tasks` — any unchecked task-list checkbox present.

(Mentions, `@user`, are also produced by `ExtractAll` but are not stored in `MemoPayload` — they're used separately for notifications, e.g. `server/router/api/v1/memo_mention_helpers.go:32`.)
