h05.

**Mechanism: explicit Go application code (within a DB transaction) — not a database-level cascade rule.**

This repo is `usememos/memos`. When a user is deleted, both (a) reactions the deleted user authored and (b) reactions left by others on the deleted user's memos are removed via hand-written SQL `DELETE` statements executed inside the `DeleteUser` transaction — no `ON DELETE CASCADE`/FK exists on the `reaction` table in any supported database.

**Evidence:**

- API entry: `server/router/api/v1/user_service.go:393` (`DeleteUser`) → `store/user.go` `Store.DeleteUser` → per-driver `DeleteUser`.
- Driver orchestration (identical pattern, all three DBs), function `deleteUserTargetsTx`:
  - Postgres: `store/db/postgres/user_delete.go:92-127`
  - MySQL: `store/db/mysql/user_delete.go:92-127`
  - SQLite: `store/db/sqlite/user_delete.go:92-127`
- Explicit reaction deletes inside that transaction:
  - `deleteReactionsByContentIDsTx` — deletes reactions on the deleted user's own memos: `DELETE FROM reaction WHERE content_id IN (...)` (Postgres: `store/db/postgres/user_delete.go:380-388`; MySQL: `store/db/mysql/user_delete.go:417-425`; SQLite: `store/db/sqlite/user_delete.go:380-388`)
  - `deleteReactionsByCreatorTx` — deletes reactions authored by the deleted user: `DELETE FROM reaction WHERE creator_id = $1` (Postgres: `store/db/postgres/user_delete.go:400-403`; MySQL lines 437-440; SQLite lines 400-403)
- All wrapped in one transaction (`tx.BeginTx`/`tx.Commit`, deferred `tx.Rollback()`), verified by `TestDeleteUserRollbackPreservesAllResources` in `server/router/api/v1/test/user_service_delete_test.go:328` and by selective-cleanup behavior in `store/test/user_delete_test.go` (`TestDeleteUserCleansRelatedData`, lines 97-113, 216-219).
- Schema check confirms no DB-level rule: `reaction` table definitions have no `FOREIGN KEY`/`REFERENCES` clause on `creator_id` or `content_id` in any dialect — `store/migration/postgres/LATEST.sql:90-98`, `store/migration/mysql/LATEST.sql:90-98`, `store/migration/sqlite/LATEST.sql:91-99` (and the original `0.20/00__reaction.sql`). `grep -rn "REFERENCES" store/migration | grep -i reaction` returns nothing. By contrast, `memo_share` in the same schema *does* declare `ON DELETE CASCADE` (e.g. postgres `LATEST.sql:108`), showing the omission on `reaction` is deliberate, not an oversight.
