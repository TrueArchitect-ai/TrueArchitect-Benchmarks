Premise correction: neither. This repository (usememos/memos, a Go app) has no NATS or RabbitMQ dependency anywhere (go.mod has no such client library, and no broker imports exist in the code).

Actual mechanism: webhook delivery is handled entirely in-process with a Go buffered channel, not an external message broker:

- `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` declares the "queue" as a buffered Go channel (capacity 128).
- `internal/webhook/webhook.go:42-55` — an `init()` spins up 4 goroutine workers (`for range 4 { go func() { for payload := range asyncPostQueue { ... Post(payload) ... } }() }`) that range over the channel and POST each webhook via `Post()`.
- `internal/webhook/webhook.go:184-196` — `PostAsync()` is the producer side; it does a non-blocking `select` send into `asyncPostQueue`, dropping (and logging) the payload if the channel is full.

So there's no external message broker or declared queue/exchange/subject at all — delivery is an in-memory, single-process fan-out over a Go channel with a fixed worker pool.
