**Premise correction:** Neither. This repo (usememos/memos) doesn't use an external message broker at all — there's no NATS or RabbitMQ dependency anywhere in the codebase (confirmed via grep across `.go`, `go.mod`, `package.json`, etc., and the graphify knowledge graph has no NATS/AMQP-related nodes).

**Actual mechanism:** Webhook delivery is handled by an in-process, in-memory Go channel, not a broker. In `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a buffered Go channel (capacity 128) declared as a package-level var. Four goroutine workers are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over `asyncPostQueue` and call `Post()` for each payload. `PostAsync()` (`internal/webhook/webhook.go:184-196`) enqueues into the channel via a non-blocking `select`/`default`, dropping (and logging a warning for) the payload if the queue is full — there's no persistence or redelivery, since it's purely in-memory.
