delivery function — `Post` in `internal/webhook/webhook.go:120` (invoked synchronously, or queued for async dispatch via `PostAsync` at `internal/webhook/webhook.go:184`, which is processed by worker goroutines calling `Post` at `internal/webhook/webhook.go:46`). The actual HTTP request happens via the shared `safeClient.Do(req)` call at `internal/webhook/webhook.go:152`.

protection mechanism — two layers in `internal/webhook/`:
1. `internal/webhook/validate.go:62` (`ValidateURL`) — checks the URL is http/https and resolves its hostname, rejecting it up front if any resolved IP falls in a reserved/private range (`isReservedIP`, `internal/webhook/validate.go:44`, checked against `reservedCIDRs`/`reservedNetworks` at `internal/webhook/validate.go:14-36`, covering loopback, RFC-1918, link-local/cloud metadata `169.254.169.254`, and IPv6 equivalents).
2. `internal/webhook/webhook.go:59` (`safeDialContext`) — installed as the `DialContext` on `safeClient`'s `http.Transport` (`internal/webhook/webhook.go:32-37`), it re-resolves the host at actual dial time and rejects reserved/private IPs using the same `isReservedIP` check, which also blocks DNS-rebinding attacks that could slip past the earlier `ValidateURL` check (since resolution happens fresh at connection time, not just at validation time).

Both can be disabled via the `AllowPrivateIPs` package var (`internal/webhook/validate.go:41`) for self-hosted deployments that need to target local-network webhook endpoints.
