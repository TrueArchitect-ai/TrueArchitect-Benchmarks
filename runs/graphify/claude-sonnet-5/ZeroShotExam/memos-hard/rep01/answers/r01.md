Actual mechanism: caching is done with a custom thread-safe in-memory cache implemented in `store/cache/cache.go` (a `sync.Map` with a background cleanup goroutine, size/eviction limits, and per-key TTL support via `Set`/`SetWithTTL`).

It's wired up in `store/store.go:38-61`, where `Store.New` builds a shared `cache.Config` and instantiates three separate in-memory caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29,51-53`).

The TTL for user entries comes from that shared config (`store/store.go:40-45`):
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
So `userCache` entries (populated in `store/user.go:151`) expire after **10 minutes** by default, with a background cleanup sweep every 5 minutes (`cache.DefaultConfig()` in `store/cache/cache.go:57-64` documents the same 10-minute default independently, though `store.go` doesn't call it — it builds the struct literal directly, with identical values).
