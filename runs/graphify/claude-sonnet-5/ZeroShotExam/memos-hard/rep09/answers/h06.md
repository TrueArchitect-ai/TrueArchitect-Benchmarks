h06.

RPC handlers whose execution path can transitively trigger an outbound HTTP request to a user-configured URL:

- `APIV1Service.CreateMemo` (`server/router/api/v1/memo_service.go:70`) → `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`)
- `APIV1Service.UpdateMemo` (`server/router/api/v1/memo_service.go:401`, dispatch at line 513) → `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`) → `DispatchMemoUpdatedWebhook` (`memo_service_webhooks.go:20`)
- `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`, dispatch at line 562) → `DispatchMemoDeletedWebhook` (`memo_service_webhooks.go:25`)
- `APIV1Service.CreateMemoComment` (`server/router/api/v1/memo_service_comments.go:20`, dispatch at line 119) → `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`)

Each of these calls a dispatch helper in `server/router/api/v1/memo_service_webhooks.go` that loads the memo owner's configured webhooks via `s.Store.GetUserWebhooks` (URLs created/managed by the user through `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`) and calls `webhook.PostAsync(payload)`.

Convergence function — `Post` in `internal/webhook/webhook.go:127` (the `PostAsync` queue at `webhook.go:37` is drained by worker goroutines started in `init()` that all call this same `Post` function, which builds the HTTP request and performs `safeClient.Do(req)` — the single place all these paths reach the network).

(A separate, unrelated convergence point also exists for link-preview fetching: `GetLinkMetadata`/`BatchGetLinkMetadata` in `server/router/api/v1/memo_service_link_metadata.go` converge on `httpgetter.GetHTMLMeta`, and SSO handlers `SignIn`/`CreateLinkedIdentity` converge on `oauth2.IdentityProvider.UserInfo`/`ExchangeToken` in `internal/idp/oauth2/oauth2.go` — but the webhook path above is the one where ≥3 handlers converge on a single delivery function.)
