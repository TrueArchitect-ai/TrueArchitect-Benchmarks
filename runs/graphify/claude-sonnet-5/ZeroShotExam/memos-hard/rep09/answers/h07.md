This is the `usememos/memos` codebase. A browser `GET /file/users/:identifier/avatar` request is served by `FileServerService.serveUserAvatar`, which loads the target user (by username, not by the request's authenticated user — hence "another user"'s image) and returns the `avatar_url` data-URI stored on that user row.

Additional detail:
- `serveUserAvatar` calls `s.parseDataURI(user.AvatarURL)` (fileserver.go:196) to decode the stored base64 data URI and returns it via `c.Blob(...)` (fileserver.go:209) — the image bytes themselves live inline in the `user.avatar_url` column (`store/migration/sqlite/.../*.sql:20`, `avatar_url TEXT NOT NULL DEFAULT ''`), not on disk/S3 like attachments.
- `Store.GetUser` (store/user.go:148-156) first checks an in-memory `userCache` before hitting `ListUsers`/the driver — so on a cache hit the request never reaches the DB layer at all.
- Access control: if the instance disallows anonymous access, `serveUserAvatar` first resolves the *requesting* browser's identity via `s.getCurrentUser()` → `s.authenticator.AuthenticateToUser()` (fileserver.go:174, 708-711) purely to check that *someone* is authenticated — it does not check that the viewer equals the target `identifier`, so any authenticated user can fetch any other user's avatar through this handler.
