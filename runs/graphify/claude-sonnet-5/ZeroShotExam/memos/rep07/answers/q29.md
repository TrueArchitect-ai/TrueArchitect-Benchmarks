Frontend API requests are authenticated via a Connect-RPC `Interceptor` named `authInterceptor` defined in `web/src/connect.ts` (lines 156–178), which attaches the token as a `Bearer` header and retries with a refreshed token on `401 Unauthenticated` errors (see `shouldHandleUnauthenticatedRetry()`, `web/src/connect.ts:102`).

- **Interceptor path:** `web/src/connect.ts` (the `authInterceptor` const, using token state from `web/src/auth-state.ts`)
- **Token kinds:** a short-lived JWT **access token** (sent as `Authorization: Bearer <token>`, managed via `getAccessToken`/`setAccessToken`/`isTokenExpired` in `web/src/auth-state.ts`) and an HttpOnly-cookie-based **refresh token** (exchanged via the `AuthService.refreshToken` RPC in `doRefreshAccessToken()`); the backend additionally supports long-lived **Personal Access Tokens (PAT)**.
- **Backend package that validates them:** `server/auth` (`server/auth/authenticator.go`) — the `Authenticator` type's `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, and `AuthenticateByPAT`/`resolveBearer` methods, invoked from the Connect interceptor chain in `server/router/api/v1/connect_interceptors.go`.
