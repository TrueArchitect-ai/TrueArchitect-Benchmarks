**Engine + path:** Google's [CEL (Common Expression Language)](https://github.com/google/cel-go) is used as the filter grammar, embedded via a custom compiler/renderer package at `internal/filter/` (`engine.go`, `schema.go`, `parser.go`, `render.go`).

**Mechanism:** `filter.NewEngine`/`DefaultEngine` (`internal/filter/engine.go:24,111`) wraps a `cel.Env` built from a field `Schema` (`internal/filter/schema.go`); `Engine.Compile` parses the filter string with `e.env.Compile` into a CEL AST and walks it via `buildCondition` (`internal/filter/parser.go:18`) into a dialect-agnostic `Condition` tree, which `Program.Render`/`CompileToStatement` then hands to a `renderer` (`internal/filter/render.go`) that walks the tree and emits a `Statement{SQL, Args}` — the renderer is parameterized by `RenderOptions.Dialect` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres` in `internal/filter/schema.go:11-16`), so the same condition tree produces dialect-specific SQL fragments (e.g. different JSON-extraction/placeholder syntax) via functions like `qualifyColumn()`, `jsonExtractExpr()`, `jsonArrayExpr()` in `render.go`. Each store backend (`store/db/sqlite/memo.go:51-61`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`) calls `filter.DefaultEngine()` then `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` (`internal/filter/helpers.go:9`) to compile+render the `ListMemos` filter and splice the resulting SQL/args into that dialect's `WHERE` clause and argument list.
