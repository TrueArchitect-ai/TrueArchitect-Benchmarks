q16. Based on `Store.DeleteMemo` in `/bench/home/work/store/memo.go` (lines 140–159), before deleting the memo row itself the store layer deletes:

- **Memo relations** — records in `memo_relation` where the memo is the source (`DeleteMemoRelation{MemoID: &delete.ID}`) and where it is the target (`DeleteMemoRelation{RelatedMemoID: &delete.ID}`) (`store/memo.go:142-147`).
- **Attachments** — all attachments linked to the memo, fetched via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and removed one-by-one through `Store.DeleteAttachment` (`store/memo.go:149-157`), which in turn also removes the underlying attachment storage/blob (`store/attachment.go:132-148`).

Only after these two cleanups does it call `s.driver.DeleteMemo(ctx, delete)` (`store/memo.go:158`), which issues the actual `DELETE FROM memo WHERE id = ?` (e.g. `store/db/sqlite/memo.go:237-248`).
