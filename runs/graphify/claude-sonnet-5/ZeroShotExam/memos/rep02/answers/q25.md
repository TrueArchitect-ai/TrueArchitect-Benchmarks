**Engine:** Google's CEL (`github.com/google/cel-go`), wrapped by a custom engine in `internal/filter/` (`engine.go`, `parser.go`, `schema.go`, `render.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-215`) validates `request.Filter` and stores it as a raw CEL string on `store.FindMemo.Filters`; each store dialect (e.g. `store/db/sqlite/memo.go:57-61`) calls `filter.DefaultEngine()` and `filter.AppendConditions`, which uses `Engine.Compile` (`internal/filter/engine.go:48`) to parse the string into a CEL AST via `cel.Env.Compile`, walks that AST in `parser.go` (`buildCondition`, `buildComparisonCondition`, etc.) into a dialect-agnostic `Condition` tree, and then `render.go`'s `renderer.Render` switches on `RenderOptions.Dialect` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`, defined in `schema.go`) to emit dialect-specific SQL fragments and placeholder args (e.g. `?` vs `$N`, `LIKE`/`ILIKE`, `json_each` vs `jsonb_array_elements_text` vs `JSON_TABLE`) as a `Statement{SQL, Args}` that gets appended to the query's WHERE clause.
