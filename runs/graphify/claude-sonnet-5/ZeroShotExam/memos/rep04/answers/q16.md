When the API's `DeleteMemo` handler calls `store.Store.DeleteMemo` (`server/router/api/v1/memo_service.go:580`, and again per-comment at line 574), the store layer's `DeleteMemo` (`store/memo.go:140-158`) deletes the following records before deleting the memo row itself:

- **Memo relation records** where the memo is the source (`DeleteMemoRelation` with `MemoID`) — `store/memo.go:142`
- **Memo relation records** where the memo is the target/related memo (`DeleteMemoRelation` with `RelatedMemoID`) — `store/memo.go:145`
- **Attachment records** linked to the memo, one at a time via `DeleteAttachment` (after listing them with `ListAttachments`) — `store/memo.go:149-157`

Only after those deletions does it call `s.driver.DeleteMemo(ctx, delete)` to delete the memo row itself (`store/memo.go:158`).

Note: memo comments (child memos linked via a `MemoRelationComment` relation) are deleted beforehand too, but that cleanup happens one level up, in the API handler (`server/router/api/v1/memo_service.go:567-577`), not inside the store's `DeleteMemo` method — it works by calling `store.DeleteMemo` recursively for each comment memo.
