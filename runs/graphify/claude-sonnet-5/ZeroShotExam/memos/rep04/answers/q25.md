q25. **Engine**: [google/cel-go](https://github.com/google/cel-go) (Google's Common Expression Language). It lives in `internal/filter/` — specifically `internal/filter/engine.go` (`Engine.Compile` builds a `cel.Env` and parses the filter string into a CEL AST), `internal/filter/parser.go` (walks the CEL parsed-expr AST into a dialect-agnostic `Condition` tree, e.g. `buildCondition`, `buildComparisonCondition`, `buildInCondition`, `buildTextMatchCondition`), and `internal/filter/render.go` (turns that IR into SQL).

**Mechanism**: `filter.DefaultEngine()` compiles the CEL filter string (used by `ListMemos` in `store/db/sqlite/memo.go:57` and `store/db/postgres/memo.go:54`) into a dialect-agnostic `Condition` tree, then `filter.AppendConditions(...)` calls the `render.go` renderer with a `DialectName` (`DialectSQLite`/`DialectPostgres`/`DialectMySQL`) so each `Condition` type (`ComparisonCondition`, `InCondition`, `TextMatchCondition`, `ListComprehensionCondition`, etc.) emits dialect-specific SQL fragments and placeholders (e.g. `?` for SQLite/MySQL vs `$N` for Postgres, `JSON_EXTRACT`/`JSON_TABLE` vs Postgres `->>`/`jsonb_array_elements_text`, `LIKE`/`ILIKE`/`REGEXP`/`~`) which are appended as a `WHERE` clause with bound args.
