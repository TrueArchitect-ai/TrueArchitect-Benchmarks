The frontend auth interceptor lives at `web/src/connect.ts:156` (`authInterceptor`, a Connect-RPC `Interceptor` installed on the shared `transport` at `web/src/connect.ts:184-188`); it works with helpers in `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken`/`isTokenExpired`) and `web/src/utils/auth-redirect.ts`.

- Interceptor path: `web/src/connect.ts` (function `authInterceptor`, `web/src/connect.ts:156`)
- Token kinds: it manages a short-lived JWT **access token**, attached as `Authorization: Bearer <token>` header (`setAuthorizationHeader`, `web/src/connect.ts:97`), and transparently triggers refresh via the long-lived **refresh token**, which is stored in an httpOnly cookie (`memos_refresh`) and sent automatically via `credentials: "include"` (`fetchWithCredentials`, `web/src/connect.ts:57`) rather than handled in JS. On a `401 Unauthenticated`, the interceptor calls `refreshAccessToken()` → `POST AuthService.refreshToken` on a separate interceptor-free transport, then retries once with the new access token (`web/src/connect.ts:161-177`).
- Backend package that validates them: `server/auth` (Go package `auth`, e.g. `github.com/usememos/memos/server/auth`), specifically `Authenticator.Authenticate` / `AuthenticateByAccessTokenV2` / `AuthenticateByRefreshToken` / `AuthenticateByPAT` in `server/auth/authenticator.go`, invoked from the Connect middleware `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go:217-231` via the shared `Authorizer` in `server/router/api/v1/authz.go`. This package also validates a third token kind, personal access tokens (`memos_pat_` prefix, checked in `server/auth/authenticator.go:102`), used for API access outside the browser session.
