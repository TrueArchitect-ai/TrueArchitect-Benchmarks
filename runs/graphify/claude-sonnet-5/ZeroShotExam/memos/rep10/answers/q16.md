Before deleting the memo row itself, the store layer (`Store.DeleteMemo` in `/bench/home/work/store/memo.go:140-157`) deletes:

1. **Memo relations** — rows in `memo_relation` where this memo is the source (`MemoID`) — via `driver.DeleteMemoRelation`.
2. **Memo relations** — rows in `memo_relation` where this memo is the target (`RelatedMemoID`) — via a second `driver.DeleteMemoRelation` call.
3. **Attachments** — all attachments linked to the memo (`ListAttachments` + `DeleteAttachment` for each) via `Store.DeleteAttachment`.

Only after these are cleaned up does it call `s.driver.DeleteMemo(ctx, delete)` to remove the `memo` row itself (see e.g. `/bench/home/work/store/db/sqlite/memo.go:237`).

Note: at the API layer (`/bench/home/work/server/router/api/v1/memo_service.go:518-591`), reactions and comment-type memo relations are also listed before deletion (for webhook dispatch and to recursively delete comment memos via `Store.DeleteMemo`), but reactions themselves aren't explicitly deleted by the store layer's `DeleteMemo` — only relations and attachments are.
