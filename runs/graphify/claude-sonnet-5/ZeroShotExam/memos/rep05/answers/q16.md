Before deleting the memo row, `Store.DeleteMemo` (store/memo.go:140-159) deletes:

1. **Memo relations** — where the memo is the source (`DeleteMemoRelation{MemoID: &delete.ID}`, store/memo.go:142) and where it is the target/related memo (`DeleteMemoRelation{RelatedMemoID: &delete.ID}`, store/memo.go:145).
2. **Attachments** linked to the memo — fetched via `ListAttachments(FindAttachment{MemoID: &delete.ID})` and then each one removed individually via `DeleteAttachment` (store/memo.go:149-157), which also deletes the attachment's backing storage (store/attachment.go:132-148).

Only after these does it call `s.driver.DeleteMemo(ctx, delete)` (store/memo.go:158) to delete the memo row itself. The underlying DB drivers (e.g. store/db/sqlite/memo.go:237-248) perform only a plain `DELETE FROM memo WHERE id = ?` with no further cascading, confirming the cascade logic lives entirely in the store layer.
