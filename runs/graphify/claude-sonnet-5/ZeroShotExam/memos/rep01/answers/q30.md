All four are thin wrappers: the first three route through the shared `dispatchMemoRelatedWebhook()` (memo_service_webhooks.go:48), while `DispatchMemoCommentCreatedWebhook` builds its payload inline — but every one of them ultimately calls `webhook.PostAsync()` (internal/webhook/webhook.go:184).

Delivery convergence: `webhook.PostAsync()` enqueues the payload onto the buffered `asyncPostQueue` channel (internal/webhook/webhook.go:39,190), which is drained by 4 worker goroutines started in `init()` (internal/webhook/webhook.go:42-55). Each worker calls `webhook.Post()` (internal/webhook/webhook.go:120), which performs the actual signed HTTP POST via the shared `safeClient` — this is the single point where all memo lifecycle webhooks are actually delivered.
