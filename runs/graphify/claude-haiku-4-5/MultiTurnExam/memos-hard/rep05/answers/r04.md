**Premise correction**: The webhook delivery system does not use NATS or RabbitMQ. Instead, it uses a simple in-memory Go channel.

**Actual mechanism**: Webhook delivery workers consume from an in-memory channel-based queue declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This channel has a buffer size of 128 messages. Four worker goroutines are spawned in the `init()` function (lines 42-54) that consume from this queue and dispatch webhooks. The `PostAsync` function (lines 184-196) enqueues webhook payloads to the queue, dropping messages if the queue is full rather than blocking.

This is a single-process, in-memory queue with no persistence or cross-process support.
