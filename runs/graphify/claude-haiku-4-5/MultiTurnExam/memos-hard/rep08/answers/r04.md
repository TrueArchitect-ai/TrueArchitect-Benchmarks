**Premise correction:** Neither NATS nor RabbitMQ is used for webhook delivery. 

**Actual mechanism:** Webhook delivery workers consume from a Go channel (not a message broker). The delivery queue is declared as a buffered Go channel at `/bench/home/work/internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This channel has a buffer capacity of 128 webhook payloads. Four worker goroutines are launched in the `init()` function (lines 42-55) that consume payloads from this channel and call `Post()` to deliver them. Webhooks are enqueued via `PostAsync()` (line 190) which attempts to send the payload to the channel, dropping it if the buffer is full. This is entirely in-process with no external message broker - it's a simple Go concurrency pattern using channels.
