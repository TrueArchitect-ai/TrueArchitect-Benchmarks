memo_relation, attachment, memo, memo_share

When DeleteMemo runs, explicit cascade deletion code deletes memo_relation records (both directions: memo as source and as target), then attachment records (and their storage), then the memo record itself. The memo_share table is also cleared via ON DELETE CASCADE foreign key constraints in all three database dialects. Comments (which are memos with memo_relation type='COMMENT') are deleted recursively before the main memo deletion. Note: reaction records are NOT cleaned up and remain orphaned.
