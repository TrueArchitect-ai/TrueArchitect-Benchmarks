**Premise correction:** This repository does not have per-user API rate-limiting middleware. Instead, it implements instance-level concurrency limiting for specific resource-intensive operations.

**Actual findings:**

**Location:** `/bench/home/work/server/router/api/v1/v1.go` (lines 59-60)

Two concurrency limiters are registered at the instance level:
1. **Thumbnail semaphore:** `semaphore.NewWeighted(3)` — limits to 3 concurrent thumbnail generations
2. **Image processing semaphore:** `semaphore.NewWeighted(2)` — limits to 2 concurrent image processing operations

**Where applied:** `/bench/home/work/server/router/api/v1/attachment_service_image.go` (lines 67-77)

The image processing limit is enforced via `acquireImageProcessingSlot()` method, which is called from `/bench/home/work/server/router/api/v1/attachment_service.go` (line 158) when processing attachments. It returns error code `ResourceExhausted` when the limit is reached.

These are **global instance limits** shared across all users, not per-user rate limits.
