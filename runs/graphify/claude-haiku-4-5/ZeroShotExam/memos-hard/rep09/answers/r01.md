**Premise correction**: There is no Redis connection for the cache layer. The repository does not use Redis.

**Actual mechanism**: The cache layer is implemented as an in-memory cache configured in `/bench/home/work/store/store.go:38-61`. The cache uses a Go-based thread-safe implementation (defined in `/bench/home/work/store/cache/cache.go`) with the following configuration for user entries:

- **Default TTL**: `10 * time.Minute` (10 minutes)
- **Cleanup Interval**: `5 * time.Minute`
- **Max Items**: 1000

Three separate in-memory caches are initialized at startup:
1. `userCache` - for caching users
2. `userSettingCache` - for caching user settings  
3. `instanceSettingCache` - for caching instance settings

All three use the same configuration, applying a **10-minute TTL** to user entries by default.
