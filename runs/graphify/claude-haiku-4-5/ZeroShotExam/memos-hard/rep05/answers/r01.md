**Premise correction:** This project does not use Redis. It implements an in-memory cache layer instead.

**Actual mechanism:** The cache layer is configured at `/bench/home/work/store/store.go` (lines 40-45) with the following settings:
- **User entries TTL**: 10 minutes (600 seconds) — applies to both `userCache` and `userSettingCache`
- **Implementation**: `/bench/home/work/store/cache/cache.go` provides a thread-safe, in-memory cache using `sync.Map` with TTL-based expiration
- **User data access**: User objects are cached in `/bench/home/work/store/user.go` and user-specific settings are cached in `/bench/home/work/store/user_setting.go`, both using the default 10-minute TTL

The cache includes automatic cleanup every 5 minutes and LRU eviction when the 1000-item limit per cache is exceeded.
