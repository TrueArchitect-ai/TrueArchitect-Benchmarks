**Computation site:** Metadata is computed across multiple client-side utilities and React components rather than a single central location:

- **Content parsing:** `/web/src/utils/markdown-manipulation.ts` (lines 15-201) extracts tasks, headings via mdast AST
- **Mentions & relations:** `/web/src/utils/remark-plugins/remark-mention.ts` (lines 47-52) and `/web/src/components/MemoMetadata/Relation/relationHelpers.ts` (lines 14-34)
- **Display metadata:** `/web/src/components/MemoView/MemoViewContext.tsx` (lines 36-66) derives timing and display state
- **Visual layout:** `/web/src/utils/media-item.ts` (lines 52-112) processes attachments; `/web/src/components/MemoMetadata/Attachment/visualGalleryLayout.ts` (lines 26-72) determines gallery layouts
- **Card rendering:** `/web/src/components/PagedMemoList/memoCardHeight.ts` (lines 40-110) estimates display height for virtualization

**Triggers:** Metadata recomputes on:
1. Content changes (task toggle, mentions/headings extracted from markdown edits)
2. Relation/comment additions
3. Tag/filter changes (affects blur content flag and statistics)
4. Attachment additions (triggers gallery layout resolution and height re-estimation)
5. Timestamp updates (create/update time and display time derivation)
6. Display context changes (timeBasis selection, filter changes affecting stats)

**Extracted properties:**
- Tasks: counts (total, complete, incomplete) and line numbers
- Headings: h1-h4 outline with slugified IDs
- Mentions: extracted @usernames
- Relations: buckets by referencing/referenced direction
- Comments: count via relation filtering
- Attachments: grouped motion/photo pairs, visual vs non-visual counts, optimal gallery layout (single/2-up/mosaic/2×2/2×3)
- Time: displayTime (create or update), relative format flag, is-updated-time flag
- Card metrics: estimated height including content, images, attachments, reactions, comments (clamped at 420px trigger)
- Statistics: activity by date, tag frequency counts
- Tags: blur-content flag via pattern matching
