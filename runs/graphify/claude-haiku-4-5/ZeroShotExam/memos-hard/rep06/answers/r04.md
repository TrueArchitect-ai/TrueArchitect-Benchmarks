**Premise correction:** The webhook delivery workers do not consume from either NATS or RabbitMQ.

**Actual mechanism:** The webhook delivery workers use **Go channels for in-process async task queueing**. 

**Queue declaration:** `/bench/home/work/internal/webhook/webhook.go` (lines 39-40) declares the queue as a bounded Go channel:
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The worker pool (lines 42-55 in the same file) consists of 4 concurrent goroutines that consume from this channel. Payloads are sent via the `PostAsync()` function with non-blocking semantics, dropping messages with a warning if the 128-item queue is full. This is a single-instance, in-process system with no external message broker integration.
