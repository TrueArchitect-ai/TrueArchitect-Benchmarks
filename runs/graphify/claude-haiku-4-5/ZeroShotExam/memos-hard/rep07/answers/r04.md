**Premise correction:** The webhook delivery workers do not consume from either NATS or RabbitMQ. 

**Actual mechanism:** The repository uses Go's built-in channel-based concurrency instead of an external message broker. The queue is declared in `/bench/home/work/internal/webhook/webhook.go` at line 39 as:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a buffered Go channel with a capacity of 128 messages. The workers are initialized via 4 goroutines (lines 42-55 in the same file) that continuously read from this channel and dispatch webhooks via the `Post()` function. Requests are enqueued by the `PostAsync()` function in the same file.
