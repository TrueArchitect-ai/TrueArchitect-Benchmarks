**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` in Go source returns nothing — the cache layer is **not** backed by Redis (or any external cache server). There is also no Redis connection/config to point to.

**Actual mechanism:** The cache is a process-local, in-memory TTL cache implemented in `store/cache/cache.go` — a `Cache` struct backed by an in-memory map of `item{value, expiration, size}` with a background cleanup goroutine (`store/cache/cache.go:1-60`, interface at `:11`, config at `:41-60`). It's not "connected" anywhere; it's just instantiated in-process.

The user cache is one of three such caches created in `store.New`:
- `userCache: cache.New(cacheConfig)` — `store/store.go:52`

with the shared `cacheConfig` defined at `store/store.go:40-45`:
- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

User entries are written via `Store.GetUser`/`ListUsers` using the plain `Set` (default TTL), e.g. `s.userCache.Set(...)` in `store/user.go:148` (`GetUser`) and `store/user.go:136` (`ListUsers`), so **user entries expire after the default 10-minute TTL** (matching the package default `DefaultConfig()` at `store/cache/cache.go:57-60`).

Answer: The question's premise is wrong — no Redis exists; caching is an in-memory TTL cache (`store/cache/cache.go`) configured inline in `store.New` (`store/store.go:40-52`), and user entries use the default 10-minute TTL.
