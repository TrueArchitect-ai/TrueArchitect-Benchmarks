**Premise correction:** There is no nightly database-cleanup job scheduled in the cron scheduler — so there is no run time to report.

What I found:
- A cron scheduler package does exist (`internal/scheduler/` — `scheduler.go`, `parser.go`, `job.go`, `middleware.go`), but it is **not wired into the running server at all**: the only files importing `internal/scheduler` are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). No production code constructs or registers jobs on it.
- Consequently there is no cron entry for a "nightly database cleanup" (no `@daily`/midnight/nightly schedule anywhere in the codebase).
- The only actual scheduled/periodic background work in the server is:
  - the S3 presign runner, on a fixed **12-hour** `time.Ticker` (not cron, not nightly) — `server/runner/s3presign/runner.go:26-41`, wired at `server/server.go:162-169`; and
  - the in-memory cache's expiry sweep, every **5 minutes** via `time.Ticker` — `store/cache/cache.go:199-210` (`CleanupInterval` set in `store/store.go:42`).
- Database-related "cleanup" is otherwise event-driven, not scheduled — e.g. attachment/relation cleanup during user or memo deletion (`server/router/api/v1/user_service.go:421-450`, `store/db/*/user_delete.go`), not a timed job.

So the question's premise (a nightly DB-cleanup cron job) does not match the code: the cron scheduler is unused in production, and no such job is defined.
