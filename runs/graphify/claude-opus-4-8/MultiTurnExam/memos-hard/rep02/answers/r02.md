**Premise correction:** There is no per-user API rate-limiting middleware in this codebase, so there is nothing to register and no request limits to report.

Evidence:
- A repo-wide search for rate-limiting (`rate.?limit`, `ratelimit`, `throttle`, `tollbooth`, `golang.org/x/time/rate`, `limiter`) turns up **no implementation** — the only hit is a prose bullet in a package doc comment (`internal/email/doc.go:86`, "Rate limit email sending to prevent abuse"), which is a general security recommendation, not code.
- `go.mod` contains no rate-limiting/throttling dependency.
- The actual middleware/interceptor chains contain no limiter:
  - Echo HTTP layer registers only `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`).
  - The Connect/gRPC API registers `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` — plus a request-size cap `connect.WithReadMaxBytes(maxAPIRequestBytes)` (`server/router/api/v1/v1.go:133-141`), and a gRPC-Gateway auth middleware (`server/router/api/v1/v1.go:69-97`). None of these throttle request rates.

So the request-per-user limits the question presumes do not exist. The nearest related control is a per-request body-size limit (`maxAPIRequestBytes` via `connect.WithReadMaxBytes` at `server/router/api/v1/v1.go:141`), which bounds payload size, not request rate.
