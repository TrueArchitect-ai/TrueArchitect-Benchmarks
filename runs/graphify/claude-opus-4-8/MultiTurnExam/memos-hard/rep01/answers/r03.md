**Premise correction:** There is no nightly database-cleanup job scheduled in this codebase, so there is no run time to report.

What I checked:
- An `internal/scheduler` package does exist — a generic, "GitHub Actions-inspired" cron scheduler library (`internal/scheduler/doc.go`, `scheduler.go`, `parser.go`, etc.). But it is **never imported or used** by the server: a search for `internal/scheduler`, `scheduler.New`, or `scheduler.Register` across `server/`, `cmd/`, and `store/` returns nothing. No `Job` with a cleanup function is ever registered anywhere.
- The only reference resembling a nightly cleanup — `Name: "daily-cleanup", Schedule: "0 2 * * *"` — is purely an illustrative example inside the package's doc comment (`internal/scheduler/doc.go:15-18`), not wired-up production code.
- The only actual "cleanup" mechanisms are unrelated:
  - **In-memory cache eviction**, which runs every 5 minutes via a ticker (`CleanupInterval: 5 * time.Minute` in `store/store.go:42` / `store/cache/cache.go:60`, loop at `store/cache/cache.go:199-210`). This is not a database cleanup, not nightly, and not cron-scheduled.
  - **Attachment/storage cleanup** that happens event-driven on user or memo deletion (`server/router/api/v1/user_service.go:421-450`, `server/router/api/v1/memo_service.go:579`, `store/attachment.go`), not on a schedule.
- The only real scheduled background jobs in the server are the S3-presign runner (every 12 hours) and, in principle, the memo-payload runner — neither of which is a nightly database cleanup (see `server/server.go:startBackgroundRunners`).

So no cron scheduler is running a nightly DB-cleanup job at any time.
