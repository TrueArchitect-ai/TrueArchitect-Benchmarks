**Premise correction:** Neither. The webhook delivery workers do not consume from NATS, RabbitMQ, or any external message broker. A repo-wide search for `nats`, `rabbitmq`, `amqp`, `kafka`, and `broker` returns nothing in the Go source, and `go.mod` declares no such dependency.

**Actual mechanism:** The "queue" is a plain in-process, buffered Go channel, entirely within the server process:
- It is declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel of capacity 128 — at `internal/webhook/webhook.go:39`.
- A package `init()` (`internal/webhook/webhook.go:42-56`) spawns **4 worker goroutines**, each ranging over `asyncPostQueue` and calling `webhook.Post` (`internal/webhook/webhook.go:120`) to perform the actual HTTP delivery.
- Producers enqueue via `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send into `asyncPostQueue` (dropping the payload if the buffer is full).

So there is no broker and no externally-declared queue — delivery is handled by an in-memory channel drained by four goroutines started at package initialization.
