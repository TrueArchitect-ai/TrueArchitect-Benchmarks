**Premise correction:** There is no per-user API rate-limiting middleware in this repository, so there is nothing to register and no request limits to report.

Evidence:
- A repo-wide search for rate-limiting terms (`rate limit`, `ratelimit`, `limiter`, `throttle`, `tollbooth`, `golang.org/x/time/rate`) returns no matches in the Go source (`grep` over the codebase, excluding `graphify-out`).
- `go.mod` declares no rate-limiting/throttling dependency (no `rate`, `limit`, or `throttle` module).
- The HTTP server only registers two Echo middlewares — `middleware.Recover()` and `newCORSMiddleware(profile)` — at `server/server.go:51-52` (CORS defined in `server/cors.go:13`). Neither performs rate limiting.
- The Connect/gRPC layer registers three interceptors — `MetadataInterceptor`, `LoggingInterceptor`, and `RecoveryInterceptor` (`server/router/api/v1/connect_interceptors.go`) — for header translation, logging, and panic recovery. None of them limits request rates, per user or otherwise.

If rate limiting is required, it isn't implemented in-process here; it would have to be added, or handled by an external reverse proxy/gateway in front of the server.
