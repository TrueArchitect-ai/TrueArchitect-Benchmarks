h02.

**Delivery function:** `webhook.Post` — `internal/webhook/webhook.go:120` (builds the `POST` request and executes it via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`). Delivery is normally invoked asynchronously through `PostAsync` (`internal/webhook/webhook.go:184`), which feeds a queue drained by worker goroutines that call `Post` (`internal/webhook/webhook.go:42-56`).

**Protection mechanism:** `safeDialContext` — `internal/webhook/webhook.go:59`. It is installed as the `DialContext` of the shared `safeClient`'s transport (`internal/webhook/webhook.go:32-37`), so at connection time it re-resolves the target hostname and refuses any address falling in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`), checking the CIDRs in `reservedCIDRs` (loopback, RFC-1918, link-local/cloud IMDS `169.254.169.254`, and IPv6 equivalents — `internal/webhook/validate.go:13-22`). Because the block happens at dial time on the actually-resolved IP, it also defeats DNS-rebinding.

Notes:
- There is a second, earlier check at configuration time: `webhook.ValidateURL` (`internal/webhook/validate.go:60`) validates the scheme and rejects URLs resolving to reserved IPs when a webhook is registered. But the guarantee that protects *delivery itself* is `safeDialContext`.
- Both checks can be disabled via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:39`) for self-hosted setups that intentionally target local services.
