**How I determined which candidate runs (there are three: sqlite, postgres, mysql):**

1. The API/store entry point `Store.CreateMemo` (`store/memo.go:109-113`) does not embed SQL — it delegates to the interface `s.driver.CreateMemo(...)`. So the concrete method depends on which `store.Driver` implementation is wired.

The driver is chosen by the factory `NewDBDriver` (`store/db/db.go`), which `switch`es on `profile.Driver`: `"sqlite"` → `sqlite.NewDB`, `"mysql"` → `mysql.NewDB`, `"postgres"` → `postgres.NewDB`, with `default` returning an error (`store/db/db.go:17-26`). So an empty driver value would fail — the value must be set upstream.
3. `profile.Driver` is populated from config at `cmd/memos/main.go:43` (`viper.GetString("driver")`), and the default when no flag/env is provided is `"sqlite"` — set both as the Viper default (`cmd/memos/main.go:122`) and as the persistent-flag default (`cmd/memos/main.go:130`).
4. Therefore, with no database flags, `profile.Driver == "sqlite"`, the factory constructs `sqlite.DB`, and `s.driver.CreateMemo` resolves to `store/db/sqlite/memo.go:16` — not the postgres (`store/db/postgres/memo.go`) or mysql (`store/db/mysql/memo.go`) counterparts.
