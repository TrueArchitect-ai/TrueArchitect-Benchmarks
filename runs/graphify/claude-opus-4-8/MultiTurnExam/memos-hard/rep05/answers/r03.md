**Premise correction: there is no nightly database-cleanup job, and in fact no cron-scheduled job of any kind is wired into the running server — so there is no scheduled time to report.**

Evidence:
- Although an `internal/scheduler` package exists (with `scheduler.New`, `ParseCronExpression`, cron middleware, etc.), **nothing in the production codebase imports or uses it**: a repo-wide search for `internal/scheduler` imports outside the package itself (excluding tests) returns zero hits, and there are no `scheduler.New` / `ParseCronExpression` call sites anywhere in production. It is effectively dead/unwired code, and it is not a "cron scheduler" driving any cleanup.
- There is no nightly database-cleanup job. The only background workers registered at startup (`Server.startBackgroundRunners`, `server/server.go:153`) are the S3 presign runner — and it is not cron-scheduled and not nightly: it runs on a plain `time.Ticker` every **12 hours** (`server/runner/s3presign/runner.go:26-30`), and it refreshes presigned attachment URLs, not database cleanup.
- The only recurring "cleanup" in the system is the in-memory cache eviction loop, which runs on a 5-minute interval (`store/cache/cache.go:47,60`; `CleanupInterval: 5 * time.Minute` in `store/store.go:42`) — again not a database job and not nightly.
- Other "cleanup" references (e.g. `server/router/api/v1/user_service.go:421-450`) are inline, on-demand attachment-storage cleanup triggered by user deletion, not scheduled jobs.
