Distinct server surfaces that enforce memo-view visibility:

- API v1 single-memo read gate (`checkMemoReadAccess`, used by `GetMemo`) — `server/router/api/v1/memo_service.go:39` (visibility check at lines 55-65)
- API v1 memo list filter (`ListMemos` restricts the query by viewer/visibility) — `server/router/api/v1/memo_service.go:219-225`, with the shared filter-builder at `server/router/api/v1/memo_service_converter.go:184-186`
- API v1 attachment service (serving/listing a memo's attachments gated by the parent memo's visibility) — `server/router/api/v1/attachment_service.go:445-451` and `server/router/api/v1/memo_attachment_service.go:214-222`
- Fileserver (raw attachment content serving gated by parent memo visibility) — `server/router/fileserver/fileserver.go:677` and `:699`
- RSS feed service (only `store.Public` memos are exposed) — `server/router/rss/rss.go:90` and `:141`
- SSE live-event delivery (`SSEClient.canReceive` filters broadcast memo events by visibility) — `server/router/api/v1/sse_hub.go:134-144`

(Related access gates keyed on the same visibility rules also appear in `server/router/api/v1/memo_service_comments.go:41`, `reaction_service.go:30-38`, and `memo_relation_service.go:109-111`, which govern commenting/reacting/relations rather than direct viewing.)
