**Premise correction:** There is no Redis in this codebase. A repository-wide search for `redis` finds zero references in any `.go` file and nothing in `go.mod` — the cache layer is not backed by Redis and has no Redis connection to configure.

**Actual mechanism:** The cache is a **thread-safe in-memory cache** implemented in `store/cache/cache.go` (`Cache`, "a thread-safe in-memory cache with TTL and memory management", `store/cache/cache.go:66`). It stores entries in a Go map with per-item expiration (`item.expiration = time.Now().Add(ttl)`, `store/cache/cache.go:112`) and a background cleanup goroutine.

The user cache is one of three in-process caches (`instanceSettingCache`, `userCache`, `userSettingCache`) constructed in `store.New` at `store/store.go:51-53` via `cache.New(cacheConfig)`. That config is defined inline at `store/store.go:40-45`:
- **DefaultTTL: 10 minutes** ← this is the TTL for user entries (they're written via `Store.GetUser`'s `s.userCache.Set(...)` at `store/user.go:167`, which uses the default TTL).
- CleanupInterval: 5 minutes, MaxItems: 1000.

(The same defaults are also encoded in `cache.DefaultConfig()`, `store/cache/cache.go:57-60`.)

Answer: **No Redis exists; the cache is an in-memory `Cache` (`store/cache/cache.go`) configured in `store.New` (`store/store.go:40-53`), and user entries use the default TTL of 10 minutes (`store/store.go:41`).**
