**Premise correction:** There is no GraphQL schema in this repository. The public API is not GraphQL — a codebase-wide search finds no `graphql`/`gqlgen` references in any `.go` file and no GraphQL dependency in `go.mod`. There is no `.graphql` schema to point to.

**Actual API surface:** The public API is defined with **Protocol Buffers** and served over **gRPC / Connect / gRPC-Gateway (REST+JSON)**. The service and message definitions live in `proto/api/v1/*.proto` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `instance_service.proto`, `ai_service.proto`, plus `common.proto` (store-side messages in `proto/store/`). Code is generated with **buf** (`proto/buf.yaml`, `proto/buf.gen.yaml`) into `proto/gen/`.

At runtime these protobuf services are exposed (not via GraphQL) through:
- **gRPC-Gateway** (REST/JSON) and **Connect** handlers, wired in `server/router/api/v1/v1.go` (`RegisterGateway` at `:64`, gRPC-Gateway mux at `:95`, Connect handlers via `NewConnectServiceHandler`/`RegisterConnectHandlers` at `:131-141`), using `connectrpc.com/connect` and `grpc-ecosystem/grpc-gateway/v2` (`server/router/api/v1/v1.go:7-8`).
- An **OpenAPI** description is generated/embedded (`proto/openapi_embed.go`) — reflecting the REST surface, again confirming it's protobuf/REST, not GraphQL.

Answer: **No GraphQL exists; the public API is a Protobuf-defined gRPC API in `proto/api/v1/*.proto` (built with buf → `proto/gen/`), exposed as REST via gRPC-Gateway and Connect in `server/router/api/v1/v1.go`.**
