Memo view-access (visibility) is enforced at multiple distinct server surfaces. Each distinct enforcement site, with file:

- **API v1 — direct memo read (`GetMemo`)** — `server/router/api/v1/memo_service.go:55-63` (non-public requires auth; `Private` → owner only)
- **API v1 — memo list query filtering (`ListMemos`)** — `server/router/api/v1/memo_service.go:219-225` (sets `VisibilityList` to `{Public}` or `{Public,Protected}` per viewer)
- **API v1 — user memo stats filtering** — `server/router/api/v1/user_service_stats.go:84-90,218-220` (restricts stats to `{Public}` / `{Public,Protected}`)
- **API v1 — attachment access for a memo** — `server/router/api/v1/memo_attachment_service.go:214-222` and `server/router/api/v1/attachment_service.go:445-451` (gates a memo's attachments by that memo's visibility)
- **API v1 — reactions** — `server/router/api/v1/reaction_service.go:30-38,83` (must be able to view the memo to list/add reactions)
- **API v1 — comments** — `server/router/api/v1/memo_service_comments.go:41` (private parent memo → owner/superuser only)
- **API v1 — SSE real-time delivery filter** — `server/router/api/v1/sse_hub.go:135-141` (`canReceive`: private events only to owner/admin)
- **RSS feed** — `server/router/rss/rss.go:90,141` (feed limited to `store.Public` memos)
- **File server (serving raw attachment/thumbnail blobs)** — `server/router/fileserver/fileserver.go:677,699` (public+anonymous allowed; private → owner/admin only)
- **Notification/email gating** — `server/router/api/v1/user_service_notifications.go:309-312` and `server/notification/email.go:313-316` (private/protected memos suppress cross-user notifications)

At minimum the three clearly distinct surfaces are: the **API v1 memo service** (`server/router/api/v1/memo_service.go`), the **RSS service** (`server/router/rss/rss.go`), and the **file server** (`server/router/fileserver/fileserver.go`) — with additional enforcement in the attachment, reaction, comment, SSE, and notification paths listed above.
