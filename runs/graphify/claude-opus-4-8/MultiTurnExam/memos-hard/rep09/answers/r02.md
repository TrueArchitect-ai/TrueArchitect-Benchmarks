**Premise correction:** The repository has no per-user API rate-limiting middleware — there is nothing to register and no request limits to report. The premise is false.

Evidence:
- A codebase-wide search for `rate limit` / `ratelimit` / `throttle` / `limiter` / `golang.org/x/time/rate` finds no rate-limiting implementation in any `.go` file, and `go.mod` pulls in no rate-limiting library (the only hit is a comment in `internal/email/doc.go:86` describing a *future* idea to rate-limit email sending — not implemented, and unrelated to API requests).
- The complete set of Connect/gRPC interceptors registered for the API is defined in `server/router/api/v1/v1.go:133-138`: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (all in `server/router/api/v1/connect_interceptors.go`). None of these performs rate limiting.
- The only per-request "limit" applied is a request **body size** cap (`connect.WithReadMaxBytes(maxAPIRequestBytes)` / `http.MaxBytesHandler`, `server/router/api/v1/v1.go:141,144`), which limits bytes per request, not request rate.

Answer: **No per-user (or any) API rate-limiting middleware exists; the API's registered interceptors are only Metadata, Logging, Recovery, and Auth (`server/router/api/v1/v1.go:133-138`), with the sole per-request cap being a max request-body size (`maxAPIRequestBytes`), not a rate limit.**
