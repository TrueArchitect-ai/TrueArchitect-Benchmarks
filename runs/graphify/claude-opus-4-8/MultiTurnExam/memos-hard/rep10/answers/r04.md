**Premise correction:** Neither. There is no external message broker in this codebase — no NATS and no RabbitMQ. A repo-wide search finds no `nats`, `amqp`, or `rabbitmq` imports/usage anywhere in the Go sources.

**Actual mechanism:** Webhook delivery uses a purely in-process Go channel as its work queue, all within a single package:

- The "queue" is a buffered channel declared at package scope: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39` (capacity 128).
- The workers are 4 goroutines spawned in `init()` that range over that channel and call `Post` for each payload — `internal/webhook/webhook.go:42-55`.
- Producers enqueue via `PostAsync`, a non-blocking `select` send that drops the payload (with a warning) if the buffer is full — `internal/webhook/webhook.go:184-196`.

So delivery is an in-memory channel + goroutine-pool pattern inside `internal/webhook/webhook.go`; there is no broker and no externally declared queue. (Consequence: because it is in-process and unbounded-drop, pending webhooks are lost on process restart or under sustained overflow.)
