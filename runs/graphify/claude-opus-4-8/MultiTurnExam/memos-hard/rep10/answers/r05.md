**Premise correction:** There is no GraphQL schema anywhere in this repository. The public API is not GraphQL. A repo-wide search finds no GraphQL usage at all — no `graphql`, `gqlgen`, or `graphql-go` imports, and no `.graphql`/schema files.

**Actual API surface:** The public API is defined with **Protocol Buffers**, served over **gRPC / Connect (RPC)** with a REST/HTTP mapping, plus a generated OpenAPI spec:

- The schema/IDL lives in `.proto` files under `proto/api/v1/` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus `common.proto`. Codegen is driven by `buf` (`proto/buf.yaml`, `proto/buf.gen.yaml`), with generated Go in `proto/gen/`.
- These services are implemented as `APIV1Service` handlers and registered on a Connect handler mux under the URL prefix `/memos.api.v1.*` (`server/router/api/v1/v1.go:133-144`, `connect_services.go`), behind the Connect interceptor chain (metadata/logging/recovery/auth).
- Machine-readable API description is an **OpenAPI** document, not a GraphQL schema — embedded via `proto/openapi_embed.go`.

So the correct answer is: the public API surface is protobuf-defined gRPC/Connect + REST (with OpenAPI), defined in `proto/api/v1/*.proto`; there is no GraphQL schema.
