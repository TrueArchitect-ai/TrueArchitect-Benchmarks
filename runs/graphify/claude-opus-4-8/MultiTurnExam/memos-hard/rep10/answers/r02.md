**Premise correction:** This repository has no per-user API rate-limiting middleware — there is nothing to register and no request limits to report. The premise is false.

Evidence:
- A repo-wide search for rate-limiting of any kind (`rate limit`, `ratelimit`, `golang.org/x/time/rate`, `tollbooth`, `limiter`, etc.) across the Go sources returns zero matches.
- The complete server middleware/interceptor stack contains no limiter:
  - Echo HTTP middleware: only `middleware.Recover()` and the CORS middleware — `server/server.go:51-52`, `server/cors.go:13`.
  - Connect/gRPC interceptor chain: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` — `server/router/api/v1/v1.go:133-138` (defined in `server/router/api/v1/connect_interceptors.go`). None of these throttle requests.

The only request-shaping guards that do exist are a maximum request body size (`connect.WithReadMaxBytes(maxAPIRequestBytes)` / `http.MaxBytesHandler`, `server/router/api/v1/v1.go:141-144`) and a couple of internal concurrency semaphores for thumbnail/image processing (`server/router/api/v1/v1.go:59-60`). Those cap payload size and in-flight work, not per-user request rates. There is no per-user (or global) rate limiter, so no configured limits exist.
