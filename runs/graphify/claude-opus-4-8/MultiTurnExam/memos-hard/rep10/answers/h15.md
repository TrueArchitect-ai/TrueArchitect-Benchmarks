Distinct memo-visibility (view) enforcement sites, by server surface:

- Connect/gRPC single-memo read gate — `checkMemoReadAccess` (Private → creator only; Protected/Public → must be authenticated) — server/router/api/v1/memo_service.go:54-68
- Connect/gRPC list filtering — `ListMemos` restricts `VisibilityList` to Public (or Public+Protected for authenticated non-owners) — server/router/api/v1/memo_service.go:219-225
- File server (serving a memo's attachment/raw content) — `FileServerService.checkAttachmentPermission` (Public served to anonymous only if allowed; Private → creator or admin) — server/router/fileserver/fileserver.go:674-699
- SSE real-time hub — `SSEClient.canReceive` decides which subscribers get a memo event by its visibility (Private vs Public/Protected) — server/router/api/v1/sse_hub.go:136-138
- RSS feed — feed queries force `VisibilityList: []store.Visibility{store.Public}` — server/router/rss/rss.go:90 and server/router/rss/rss.go:141
- Frontend SSR/metadata (sitemap/tags) — memo lookups constrained to `VisibilityList: []store.Visibility{store.Public}` — server/router/frontend/frontend.go:150

Related derived-access checks that reuse the same memo-visibility rules (viewing a memo's attachments/reactions) also exist at server/router/api/v1/attachment_service.go:445-451, server/router/api/v1/memo_attachment_service.go:214-222, server/router/api/v1/reaction_service.go:30-38, and server/router/api/v1/memo_service_comments.go:41.
