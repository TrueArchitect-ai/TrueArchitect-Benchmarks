**Premise correction:** There is no Redis anywhere in this codebase. A repo-wide search for `redis` in the Go sources returns zero matches. The cache layer is a self-contained, in-process, in-memory cache — there is no external cache server to "connect" to, so there is no Redis connection configuration.

**Actual mechanism:**

- The cache is a plain Go map guarded by a mutex, with per-item expiration and a background cleanup goroutine — `store/cache/cache.go` (interface + `item{value, expiration, size}` + `Config`). It offers `Set` (default TTL) and `SetWithTTL` (custom TTL).
- It is "configured" (not connected) in the store constructor `store/store.go:40-53`: one `cache.Config{ DefaultTTL: 10*time.Minute, CleanupInterval: 5*time.Minute, MaxItems: 1000 }` is created and used to instantiate three in-memory caches — `instanceSettingCache`, `userCache`, and `userSettingCache` (`cache.New(cacheConfig)`).
- **TTL for user entries:** user entries are written with `s.userCache.Set(...)` (e.g. `store/user.go:98, 122, 132, 143, 167`), i.e. the **default TTL of 10 minutes** (`store/store.go:41`); expired entries are swept every 5 minutes by the cleanup interval. There is no separate/custom TTL for users (no `SetWithTTL` calls in `store/user.go`). The package default is likewise 10 minutes (`cache.DefaultConfig`, `store/cache/cache.go`).
