**Premise correction:** There is no Redis in this codebase. A repo-wide search finds zero references to Redis (no `redis` in any `.go` file and none in `go.mod`). The cache layer is a self-contained **in-memory** cache, not a Redis client — so there is no "Redis connection" to configure anywhere.

**Actual mechanism:**
- The cache implementation is a custom in-process cache in `store/cache/cache.go` (`cache.Interface` / `cache.Cache`), storing items in memory with per-entry expiration and a background cleanup goroutine.
- The user cache is one of three caches created in `Store.New` at `store/store.go:38`. All three (`instanceSettingCache`, `userCache`, `userSettingCache`) are constructed from a single `cache.Config` (`store/store.go:40`–`45`) with:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
- The `userCache` is instantiated at `store/store.go:52` (`cache.New(cacheConfig)`).
- **TTL for user entries: 10 minutes.** `Store.GetUser` populates the cache via `s.userCache.Set(...)` (`store/user.go:167`), and `Set` applies the cache's `DefaultTTL` (10 min) — see the `Set` vs `SetWithTTL` distinction in the `cache.Interface` (`store/cache/cache.go:12-15`). The library's own `DefaultConfig()` also uses the same 10-minute default (`store/cache/cache.go:57`).
