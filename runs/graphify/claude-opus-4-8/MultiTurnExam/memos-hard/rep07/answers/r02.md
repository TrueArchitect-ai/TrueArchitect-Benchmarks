**Premise correction:** There is no per-user API rate-limiting middleware in this repository — so there is nothing registered and no request limits to report.

Evidence:
- No rate-limiting dependency exists: `go.mod` has no `golang.org/x/time/rate` or any limiter/throttle library, and a repo-wide `.go` search for `ratelimit`/`limiter`/`throttle`/`rate` finds no rate-limiting code. The only hit is a comment in a doc file (`internal/email/doc.go:86`, "Rate limit email sending to prevent abuse") — an aspirational note about SMTP, not an implemented API rate limiter.
- The complete server middleware/interceptor chain contains no rate limiter:
  - Echo HTTP middleware (`server/server.go:51-52`): `middleware.Recover()` and a CORS middleware; plus static/SPA middleware in `server/router/frontend/frontend.go:54,59`.

The closest existing controls are request-size limits (`connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`) and concurrency semaphores for thumbnail/image processing (`server/router/api/v1/v1.go:60-61`) — but these are not per-user request-rate limits.
