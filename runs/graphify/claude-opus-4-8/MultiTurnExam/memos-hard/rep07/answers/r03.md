**Premise correction:** There is no nightly database-cleanup job scheduled in a cron scheduler — so there is no scheduled run time to report.

Evidence:
- A cron scheduler package does exist (`internal/scheduler/`, with `ParseCronExpression`, `Scheduler.Register`, `Scheduler.Start`, etc.), but it is **not used by any production code**. The only importers of `github.com/usememos/memos/internal/scheduler` are its own tests (`internal/scheduler/integration_test.go`, `internal/scheduler/example_test.go`). No non-test code calls `scheduler.New`, `Register`, or `Start`, so no cron jobs — nightly or otherwise — are registered.
- The server's actual background jobs live under `server/runner/` and are just two ticker/one-shot runners, neither of which is a cron-scheduled database cleanup:
  - `s3presign` — re-presigns S3 attachment URLs on a 12-hour `time.Ticker` (`server/runner/s3presign/runner.go`, wired at `server/server.go:162-169`), not a nightly cron and not a cleanup.
  - `memopayload` — rebuilds memo payloads (`server/runner/memopayload/runner.go`), and isn't even wired into server startup.
- Searching the backend for `cleanup`/`nightly`/`cron`/`purge`/`vacuum` finds only inline deletion helpers (e.g. attachment cleanup during memo/user deletion in `server/router/api/v1/user_service.go`, `memo_service.go`) — all triggered synchronously by API operations, not by a scheduled cron job.

So the described "nightly database-cleanup cron job" does not exist in this codebase.
