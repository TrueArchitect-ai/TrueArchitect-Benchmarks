Distinct memo-visibility enforcement sites across server surfaces:

- `checkMemoReadAccess` (single-memo reads — GetMemo and callers): denies non-public memos to anonymous users and private memos to non-owners — `server/router/api/v1/memo_service.go:39` (checks at `:55`, `:63`)
- `ListMemos` visibility filtering (list/search surface): constrains the query to `PUBLIC` for anonymous users, and to `creator_id == me || visibility in ["PUBLIC","PROTECTED"]` for authenticated users — `server/router/api/v1/memo_service.go:217`–`227`
- `checkAttachmentPermission` (file server serving attachments/thumbnails): gates attachment bytes on the parent memo's visibility (public+anonymous allowed, share-token fallback, else private→owner/admin only) — `server/router/fileserver/fileserver.go:650` (checks at `:677`, `:699`)
- RSS feed generation: restricts feed items to `store.Public` only via `VisibilityList` — `server/router/rss/rss.go:90` and `:141`
- SSE real-time event delivery filter `SSEClient.canReceive`: only delivers private-memo events to the owner/admin — `server/router/api/v1/sse_hub.go:134` (event visibility populated in `server/router/api/v1/sse_event_helpers.go:29`)
