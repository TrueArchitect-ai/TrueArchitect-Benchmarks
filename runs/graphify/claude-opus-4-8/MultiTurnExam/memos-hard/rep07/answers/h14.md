**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`. It calls `markdownService.ExtractAll([]byte(memo.Content))` (the goldmark-based `ExtractAll`, `internal/markdown/markdown.go:356`) in a single parse pass and writes the result into `memo.Payload.Tags` and `memo.Payload.Property` (`runner.go:85-86`). So the derived metadata lives on the memo's `Payload` and is recomputed from `Content`, never taken from user input.

**Triggers (operations that force recomputation):**
- `CreateMemo` — every memo creation: `server/router/api/v1/memo_service.go:108`.
- `UpdateMemo`, but only when the `content` field is actually changed (inside the update-mask `content` branch, right after `memo.Content = request.Memo.Content`): `server/router/api/v1/memo_service.go:447`.
- Bulk backfill loop `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:52`), which rebuilds every memo's payload in batches — though, as established earlier, this `Runner`/`RunOnce` is not wired into production server startup, so in practice recomputation happens on the create/update paths.

**Extracted properties** (what `ExtractAll` derives and what gets persisted):
- `Tags` — the list of `#tags` found in the content (deduplicated, case preserved) → stored in `Payload.Tags`.
- `Property` (`storepb.MemoPayload_Property`) → stored in `Payload.Property`:
  - `Title` — text of a leading H1 heading (`markdown.go:387`)
  - `HasLink` — content contains a link (`:394`)
  - `HasCode` — content contains a code block/span (`:397`)
  - `HasTaskList` — content contains a task checkbox (`:400`)
  - `HasIncompleteTasks` — an unchecked task exists (`:403`)

Note: `ExtractAll` also computes `Mentions` (`@user`, `markdown.go:379-380`), but `RebuildMemoPayload` only persists `Tags` and `Property` into the memo payload — mentions are not stored via this path.
