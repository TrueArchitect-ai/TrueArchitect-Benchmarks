**Premise correction: there is no Redis anywhere in the cache layer.** A repo-wide search for `redis` in the Go sources returns nothing — no Redis client, no connection config. The cache is not backed by Redis at all.

**Actual mechanism:** The cache is a **thread-safe in-memory cache** (a `sync.Map` with per-item TTL and a background cleanup goroutine), defined in `store/cache/cache.go` (`Cache` struct backed by `sync.Map`, TTL/`CleanupInterval`/`MaxItems` config; interface at cache.go:10-31). There is no external connection to configure — it lives in-process.

The user cache specifically:
- `Store.userCache *cache.Cache` is declared at store/store.go:28 and constructed in `store.New` at store/store.go:52 via `cache.New(cacheConfig)`.
- All three caches (instance-setting, user, user-setting) share one config built inline in `store.New` at store/store.go:40-45: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`.

**TTL for user entries: 10 minutes** (the `DefaultTTL` of the shared cache config, store/store.go:41; matching `cache.DefaultConfig()` at store/cache/cache.go:58). Entries are written via `Store.GetUser` → `s.userCache.Set(...)` (store/user.go), which uses the default TTL; expired entries are swept every 5 minutes by the cache's cleanup interval.
