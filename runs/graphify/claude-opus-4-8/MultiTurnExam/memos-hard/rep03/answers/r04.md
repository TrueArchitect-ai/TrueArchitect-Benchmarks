**Premise correction: the webhook delivery workers consume from neither NATS nor RabbitMQ — there is no external message broker in this codebase at all.** A search of the Go sources and `go.mod` for NATS, RabbitMQ/AMQP, Kafka, etc. returns nothing; no broker client is imported or declared.

**Actual mechanism:** Webhook delivery is entirely in-process, backed by a plain buffered **Go channel**, in `internal/webhook/webhook.go`:

- The "queue" is a buffered channel of capacity 128, declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`.
- The workers are **4 goroutines** started in the package `init()` (`internal/webhook/webhook.go:42-54`), each looping `for payload := range asyncPostQueue` (`webhook.go:45`) and calling `Post` to perform the outbound HTTP delivery.
- Producers enqueue via `PostAsync`, which does a non-blocking send `case asyncPostQueue <- requestPayload:` (`webhook.go:190`) — dropping the event if the buffer is full rather than handing it to any broker.

So there is no queue "declared" in a broker; the analog is the buffered channel at `internal/webhook/webhook.go:39`, consumed by the four in-process worker goroutines defined in the same file.
