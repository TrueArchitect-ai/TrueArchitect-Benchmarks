How I determined which of the three candidates (`sqlite`, `mysql`, `postgres` — each has its own `CreateMemo` with an INSERT) actually runs on a default install:

1. **Default driver value.** The CLI registers the DB driver flag with a default of `"sqlite"`: `rootCmd.PersistentFlags().String("driver", "sqlite", ...)` and `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:130` and `:122`), read into the profile at `cmd/memos/main.go:43`. So with no flags, `profile.Driver == "sqlite"`.
2. **Factory selection.** `NewDBDriver` switches on `profile.Driver`; the `"sqlite"` case calls `sqlite.NewDB(profile)` (`store/db/db.go:20`), and unknown values return an error (`store/db/db.go:24`) — confirming sqlite is the only driver instantiated by default.
3. **Concrete INSERT.** The `store.Store.CreateMemo` call dispatches through the `store.Driver` interface to the selected driver's implementation — here `(*DB).CreateMemo` at `store/db/sqlite/memo.go:16`, which builds and executes `INSERT INTO memo (...) VALUES (...) RETURNING ...` via `d.db.QueryRowContext` (`store/db/sqlite/memo.go:41-49`).

The MySQL (`store/db/mysql/memo.go`) and Postgres (`store/db/postgres/memo.go`) `CreateMemo` methods exist but are never constructed on a default install, since the factory only builds the sqlite driver.
