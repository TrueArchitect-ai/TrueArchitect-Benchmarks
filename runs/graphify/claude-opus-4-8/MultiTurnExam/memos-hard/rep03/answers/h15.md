h15. Memo visibility is enforced independently across many server surfaces. The distinct enforcement sites:

Memo API — single-memo read (`GetMemo`): permission check on Private/Protected — server/router/api/v1/memo_service.go:50-64
Memo API — list scoping (`ListMemos`): visibility filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` — server/router/api/v1/memo_service.go:222
SSE live-event hub — per-connection delivery filter (`canReceive`) — server/router/api/v1/sse_hub.go:135-141
RSS feed — restricted to `store.Public` only — server/router/rss/rss.go:90 and :141
Frontend SSR (sitemap / server-rendered pages) — restricted to `store.Public` only — server/router/frontend/frontend.go:150
File server (serving memo-linked attachments/resources) — Private/anonymous gating — server/router/fileserver/fileserver.go:677 and :699
Attachment API — access gated by parent memo visibility — server/router/api/v1/attachment_service.go:445-451 and server/router/api/v1/memo_attachment_service.go:214-222
Reaction API — access gated by parent memo visibility — server/router/api/v1/reaction_service.go:30-38 and :83
Comment API — single check + list filter — server/router/api/v1/memo_service_comments.go:41 and :158-160
Related-memos / user-stats list filters — server/router/api/v1/memo_relation_service.go:109-111 and server/router/api/v1/user_service_stats.go:87
Notification/mention path (whether a user is notified about a memo) — server/notification/email.go:313-316, server/router/api/v1/user_service_notifications.go:309-312, server/router/api/v1/memo_mention_helpers.go:62-84

The three primary "who may view" surfaces are the **Memo API** (memo_service.go), the **RSS feed** (rss.go), and the **file server** (fileserver.go); the SSE hub and frontend SSR are two further independent view surfaces, and the attachment/reaction/comment/notification paths re-enforce the same rule on memo-derived content. Each site implements the check separately (there is no single shared guard — the API list surfaces repeat the same `creator_id == N || visibility in [...]` filter string in four places).
