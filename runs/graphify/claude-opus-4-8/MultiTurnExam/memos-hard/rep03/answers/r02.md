**Premise correction: there is no per-user API rate-limiting middleware in this codebase — so there is no registration site and no request limits to report.**

Evidence:

- A repo-wide search for any rate-limiting construct (`rate`, `ratelimit`, `limiter`, `throttle`, `quota`, `golang.org/x/time/rate`, tollbooth, etc.) in the Go sources turns up nothing related to request limiting. There is no rate-limiter dependency, type, or config anywhere.
- The full Connect/gRPC interceptor chain is registered in `server/router/api/v1/v1.go:133-137` and consists only of: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`). None of these limit request rate.
- The Echo-level middleware registered in `server/server.go:51-52` is only `middleware.Recover()` and `newCORSMiddleware(profile)` — again, no rate limiter.

The only request-size-related guard that exists is a byte-size cap on request bodies, not a rate limit: `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`. That bounds how large a single request may be, not how many requests a user may make. So the feature the question assumes (per-user API rate limiting with configured request limits) is simply not present.
