h14.

**Computation site: `memopayload.RebuildMemoPayload` — server/runner/memopayload/runner.go:74, which delegates to the markdown service's `ExtractAll` (internal/markdown/markdown.go:356) in a single pass and writes the result into `memo.Payload`.**

**Triggers (operations that recompute):**
- **Create** — `CreateMemo` calls `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` at server/router/api/v1/memo_service.go:108.
- **Update (content change)** — `UpdateMemo`, in the `content` field branch, sets `memo.Content = request.Memo.Content` and then rebuilds at server/router/api/v1/memo_service.go:447 (only when content is being updated).
- (There is also a bulk rebuild loop `Runner.RunOnce` at server/runner/memopayload/runner.go:52, but that `Runner` is never constructed in production — see the memopayload runner having no non-test `NewRunner` caller — so it does not run at runtime.)

**What the computation extracts** (from `ExtractAll` → `ExtractedData`, internal/markdown/markdown.go:21-24, stored on `memo.Payload`):
- **`Tags`** — all `#tags` found in the content → `memo.Payload.Tags` (runner.go:85).
- **`Property`** (`storepb.MemoPayload_Property`, proto/gen/store/memo.pb.go:87-92) → `memo.Payload.Property` (runner.go:86), containing the derived flags/title:
  - `HasLink`
  - `HasTaskList`
  - `HasCode`
  - `HasIncompleteTasks`
  - `Title` (extracted heading/title text)

So each memo's list/preview metadata (tags + the has-link / has-task-list / has-code / has-incomplete-tasks flags and title) is derived from its markdown content by `RebuildMemoPayload` on create and on content-updating updates, never set directly by the user.
