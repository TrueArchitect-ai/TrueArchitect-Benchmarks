**Premise correction:** The webhook delivery workers consume from **neither NATS nor RabbitMQ** — there is no external message broker in this codebase at all. A repository-wide search for `nats`, `rabbitmq`, `amqp`, `kafka`, etc. (in code and `go.mod`) returns zero hits. So there is no broker-declared queue to point to.

**Actual mechanism:** Webhook dispatch uses a bounded **in-process Go channel** as the queue, entirely within the `internal/webhook` package:
- The "queue" is declared as a buffered channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`.
- The "workers" are 4 goroutines started in `init()` that range over that channel and call `Post` for each payload — `internal/webhook/webhook.go:42-55`.
- Producers enqueue via `PostAsync`, which does a non-blocking send onto the channel and drops the delivery (with a warning) if the buffer is full — `internal/webhook/webhook.go:184-196`.
- Each worker's `Post` performs the actual outbound HTTP POST via the SSRF-guarded `safeClient.Do` — `internal/webhook/webhook.go:120,152`.

So delivery is a single-process, in-memory producer/consumer pattern (128-slot channel + 4 goroutine consumers); it is not backed by any external message broker, and the queue "declaration" is the channel at `internal/webhook/webhook.go:39`.
