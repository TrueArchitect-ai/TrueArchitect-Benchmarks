Memo visibility (PUBLIC / PROTECTED / PRIVATE) governs "who may view" and is enforced at these distinct server surfaces:

- Single-memo read access guard (`GetMemo`) — `server/router/api/v1/memo_service.go:55-65`
- Memo-list visibility filtering (`ListMemos`, anonymous → PUBLIC only, authed → own + PUBLIC/PROTECTED) — `server/router/api/v1/memo_service.go:219-225`
- Memo comments (visibility check before commenting + comment listing filter) — `server/router/api/v1/memo_service_comments.go:41` and `:158-160`
- Memo relations listing filter — `server/router/api/v1/memo_relation_service.go:109-111`
- Reactions (upsert/list gated on the memo's visibility) — `server/router/api/v1/reaction_service.go:30-38` and `:83`
- Attachment access via API (linked-attachment access follows memo visibility) — `server/router/api/v1/attachment_service.go:445-451` and `server/router/api/v1/memo_attachment_service.go:214-222`
- User stats visibility filter — `server/router/api/v1/user_service_stats.go:84-90` (and `:218-220`)
- File server attachment binary serving (`checkAttachmentPermission`) — `server/router/fileserver/fileserver.go:677` and `:699`
- SSE real-time event delivery filtering (`canReceive`) — `server/router/api/v1/sse_hub.go:135-141`
- Email notifications (skip private/protected recipients) — `server/notification/email.go:313-316`
- RSS feeds (public memos only) — `server/router/rss/rss.go:90` and `:141`
- Frontend SSR metadata (public memos only) — `server/router/frontend/frontend.go:150`

The two conceptually different mechanisms across these sites are (1) per-memo permission checks that return NotFound/PermissionDenied for a specific memo (e.g. `memo_service.go:55-65`, `fileserver.go:699`, `reaction_service.go`), and (2) query-time `VisibilityList`/CEL-filter narrowing so non-viewable memos never appear in lists/feeds (e.g. `memo_service.go:219-225`, `rss.go`, `frontend.go`, `user_service_stats.go`).
