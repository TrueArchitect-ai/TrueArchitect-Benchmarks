**No.** The MySQL store driver (`mysql.NewDB`, defined in `store/db/mysql/mysql.go`) is constructed in exactly one place: the driver-selection factory `NewDBDriver` at `store/db/db.go:22`. A codebase-wide search (`grep -rniE "mysql\.NewDB"`) returns only that single call site.

The other MySQL references are not constructions of the store driver:
- `store/test/store.go` and `store/test/containers.go` only build DSN strings and spin up test containers; they route through the same factory (`store/test/store.go:88-89` selects the driver by name, then defers to `NewDBDriver`). Where they touch MySQL directly it's via the standard library `sql.Open("mysql", dsn)` (`store/test/containers.go:145`) and DSN parsing with `go-sql-driver/mysql` (`store/test/containers.go:363`) — infrastructure, not the app's `store.Driver` implementation.
- The remaining `store/db/mysql/*.go` files are the driver's own internals (they live inside the package that the factory instantiates).

So outside `NewDBDriver`, the MySQL driver is never constructed directly.
