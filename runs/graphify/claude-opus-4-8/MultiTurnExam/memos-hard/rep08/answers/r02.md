**Premise correction:** There is no per-user API rate-limiting middleware in this codebase, so there is nothing to register and no request limits to report. A repository-wide search for rate-limiting (`rate.?limit`, `ratelimit`, `throttle`, `limiter`, `golang.org/x/time/rate`, `tollbooth`) turns up **zero implementation** — the only match is an aspirational comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which describes a not-yet-implemented idea, not actual code.

What the server *does* register instead:
- **Connect/gRPC interceptors** (`server/router/api/v1/connect_interceptors.go`): `MetadataInterceptor` (line 22), `LoggingInterceptor` (line 98), `RecoveryInterceptor` (line 165, panic recovery), and `AuthInterceptor` (line 208, authentication/authorization) — none of which perform rate limiting.
- **Echo HTTP middleware** (`server/server.go:51-52`): `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`) — again, no rate limiter.

So the request-throttling/rate-limiting layer the question presumes does not exist anywhere in the server; request admission is gated only by authentication (`AuthInterceptor`) and authorization (ACL/authz), not by any per-user request-count or per-second limit.
