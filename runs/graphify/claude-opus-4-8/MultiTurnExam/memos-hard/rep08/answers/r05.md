**Premise correction:** There is no GraphQL schema anywhere in this repository. A codebase-wide search for `graphql`, `gqlgen`, `graph-gophers`, etc. (in code and `go.mod`) returns zero hits — the project does not expose a GraphQL API, so there is no schema file to point to.

**Actual API surface:** The public API is defined with **Protocol Buffers** and served over **gRPC / Connect (with a REST/HTTP gateway and OpenAPI)**:
- The schema/service definitions are `.proto` files under `proto/api/v1/`: `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus `common.proto` (managed via buf — `proto/buf.yaml`, `proto/buf.gen.yaml`).
- Generated Go code lives in `proto/gen/api/v1/` (message/service types, gRPC stubs, the grpc-gateway `*.pb.gw.go` for REST mapping, and Connect handlers under `proto/gen/api/v1/apiv1connect/`).
- These services are implemented in `server/router/api/v1/` (e.g. `memo_service.go`, `user_service.go`) and wired through Connect interceptors (`server/router/api/v1/connect_interceptors.go`, `connect_services.go`).
- An OpenAPI spec is embedded via `proto/openapi_embed.go`.

So the "public API" is a Protobuf-defined gRPC/Connect + REST(gateway) surface, not GraphQL.
