**Mechanism: explicit Go code.** When a user is deleted, their emoji reactions are removed by hand-written `DELETE FROM reaction` statements inside the delete-user transaction — in all three DB drivers — not by any database-level cascade rule.

Evidence checked:
- **MySQL driver** (`store/db/mysql/user_delete.go`): the transaction orchestrator `deleteUserTargetsTx` explicitly calls `deleteReactionsByContentIDsTx` (line 96) and `deleteReactionsByCreatorTx` (line 102). Those functions run raw `DELETE FROM reaction WHERE content_id IN (...)` (line ~410) and `DELETE FROM reaction WHERE creator_id = ?` (line ~424). This covers both reactions *made by* the user (`creator_id`) and reactions *on the user's memos* (`content_id` = `memos/<uid>`, built by `memoContentIDsFromRefs`).
- **Postgres driver** (`store/db/postgres/user_delete.go:96,102` calling the same two functions defined at lines 380 and 400).
- **SQLite driver** (`store/db/sqlite/user_delete.go:96,102`, functions at lines 380 and 400).

All of these are explicit `tx.ExecContext(... DELETE FROM reaction ...)` calls within the user-deletion transaction, so removal is done by application Go code rather than a foreign-key `ON DELETE CASCADE` or trigger.
