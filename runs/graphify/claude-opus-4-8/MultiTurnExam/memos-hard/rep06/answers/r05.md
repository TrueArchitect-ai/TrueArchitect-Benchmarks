**Premise correction:** There is no GraphQL schema in this repository. A search for `graphql`, `gqlgen`, `schema.graphql`, etc. across the Go source and `go.mod` returns zero hits — the project does not expose a GraphQL API.

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC services**, served over Connect and gRPC-Gateway (JSON/HTTP), not GraphQL.

- The schema/service contracts live in `.proto` files under `proto/api/v1/` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, plus shared types in `common.proto`.
- Generated Go/TS bindings are in `proto/gen/` (e.g. `proto/gen/api/v1/...`), and the web client types in `web/src/types/proto/...`.
- The server wires these up in `server/router/api/v1/v1.go`: it builds a Connect handler with interceptors and registers it (`RegisterConnectHandlers`, `server/router/api/v1/v1.go:141`), and also uses a gRPC-Gateway mux (`server/router/api/v1/v1.go:95`) to expose the same services as RESTful HTTP/JSON endpoints. The `APIV1Service` methods in `server/router/api/v1/*.go` (e.g. `memo_service.go`, `user_service.go`) implement the proto-defined RPCs.

So the "schema for the public API" is the protobuf definitions in `proto/api/v1/`, surfaced as gRPC/Connect + REST — there is no GraphQL layer.
