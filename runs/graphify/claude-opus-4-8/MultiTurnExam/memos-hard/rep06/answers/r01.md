**Premise correction:** There is no Redis in this codebase — the cache layer is not backed by Redis (or any external cache server). A repo-wide search for `redis` in Go source returns zero hits. So there is no Redis connection to configure.

**Actual mechanism:** The cache is an in-process, in-memory cache implemented in `store/cache/cache.go` (a map-backed store with per-item expiration and a background cleanup goroutine; interface defined at `store/cache/cache.go:10`). The `Store` holds three such caches — `instanceSettingCache`, `userCache`, `userSettingCache` — declared at `store/store.go:27-29`.

They are "configured" in `store.New` at `store/store.go:40-45`, where a single `cache.Config` is built and passed to `cache.New(...)` for each cache (`store/store.go:51-53`):
- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

**TTL for user entries:** User records are cached via `userCache.Set(...)` (e.g. `store/user.go:98, 122, 132, 143, 167`). `Set` uses the cache's default TTL (per the interface contract at `store/cache/cache.go:12`), so user entries expire **10 minutes** after being written (`DefaultTTL` at `store/store.go:41`; the package default is likewise 10 min at `store/cache/cache.go` `DefaultConfig`). No `SetWithTTL` override is used for users.
