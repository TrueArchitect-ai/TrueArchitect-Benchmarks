**Handlers (RPC methods on `APIV1Service`) that can transitively trigger an outbound webhook HTTP request to a user-configured URL:**

1. `CreateMemo` — `server/router/api/v1/memo_service.go:157` (calls `DispatchMemoCreatedWebhook`)
2. `DeleteMemo` — `server/router/api/v1/memo_service.go:562` (calls `DispatchMemoDeletedWebhook`)
3. `UpdateMemo` — `server/router/api/v1/memo_service.go:513` (via `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`)
4. `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:119` (calls `DispatchMemoCommentCreatedWebhook`)
5. `SetMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:48` (via `dispatchMemoUpdatedSideEffects`)
6. `SetMemoRelations` — `server/router/api/v1/memo_relation_service.go:48` (via `dispatchMemoUpdatedSideEffects`)

All of these go through the `Dispatch*Webhook` methods in `server/router/api/v1/memo_service_webhooks.go`, which look up the user's configured webhook URLs (`GetUserWebhooks`) and call `webhook.PostAsync` (enqueue).

**Convergence function — path:** `webhook.Post` — `internal/webhook/webhook.go:120` (the single function where every path converges to build and actually send the request via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`). The async workers draining `PostAsync`'s queue also call `Post`, so it is the common funnel just before delivery.
