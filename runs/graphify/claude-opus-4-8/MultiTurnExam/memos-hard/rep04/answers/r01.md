**Premise correction:** There is no Redis anywhere in this codebase. A repo-wide search for `redis` (case-insensitive) in Go source returns nothing — the cache layer is not backed by Redis and there is no Redis connection to configure.

**Actual mechanism:** The cache is a thread-safe, **in-process in-memory TTL cache** implemented in `store/cache/cache.go` (`cache.Cache`, implementing `cache.Interface`; entries are plain Go values with an `expiration time.Time`, swept by a background cleanup goroutine). It is not shared across processes and requires no external service or connection string.

- **Where it's "configured":** in `store.New(...)`, which builds a single `cache.Config` and instantiates three caches — including the user cache — via `cache.New(cacheConfig)` (`store/store.go:38-53`). The user cache field is `Store.userCache` (`store/store.go:28`). There's also a `DefaultConfig()` in `store/cache/cache.go:56-63` with identical values, but the store constructs its own config literal.

- **TTL for user entries:** **10 minutes.** User rows are cached with the default TTL: `Store.GetUser`/`ListUsers` call `s.userCache.Set(ctx, key, user)` (`store/user.go`), and `Set` applies `DefaultTTL` (`SetWithTTL` uses a custom value, but the user path uses `Set`). That `DefaultTTL` is `10 * time.Minute`, set in `store/store.go:41` (with a `CleanupInterval` of 5 minutes and `MaxItems` of 1000). No per-user override is applied, so user entries expire 10 minutes after they're cached.
