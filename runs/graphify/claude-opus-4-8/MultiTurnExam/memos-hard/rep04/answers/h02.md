**Delivery function — `Post` at `internal/webhook/webhook.go:120` (the actual `safeClient.Do(req)` call executes at `internal/webhook/webhook.go:152`); protection mechanism — SSRF guard via `safeDialContext` at `internal/webhook/webhook.go:59`, which rejects reserved/private targets using `isReservedIP` at `internal/webhook/validate.go:44`**

How it fits together:

- When a memo/content change fires a webhook, `Post` (`internal/webhook/webhook.go:120`) marshals the payload, optionally HMAC-signs it, and performs the outbound HTTP POST via `safeClient.Do(req)` (`internal/webhook/webhook.go:152`). Async triggers route through `PostAsync` → a bounded worker pool that also calls `Post` (`internal/webhook/webhook.go:184`, `webhook.go:46`).
- The outbound request uses `safeClient`, a shared `http.Client` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`).
- `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the target hostname at dial time and rejects the connection if any resolved IP satisfies `isReservedIP` (`internal/webhook/webhook.go:65-74`). Because the check happens at dial time on the actually-resolved address, it also defeats DNS-rebinding attempts to reach internal addresses.
- `isReservedIP` (`internal/webhook/validate.go:44`) is what classifies an address as reserved/private (loopback, link-local, private ranges, etc.), blocking the webhook from being pointed at internal network addresses.
