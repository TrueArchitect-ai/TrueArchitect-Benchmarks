Memo visibility (`Public` / `Protected` / `Private`) is enforced at multiple independent server surfaces:

- `checkMemoReadAccess` — single-memo read guard used by GetMemo and related reads — server/router/api/v1/memo_service.go:39 (visibility check at memo_service.go:55-63)
- `ListMemos` — restricts the query by building `VisibilityList` from the viewer (anonymous → Public only; authenticated → Public+Protected) — server/router/api/v1/memo_service.go:219-225
- `ListAllUserStats` / user-stats listing — same viewer-based `VisibilityList` filtering — server/router/api/v1/user_service_stats.go:84-90 and user_service_stats.go:218-220
- RSS feed generation — forces `VisibilityList = [Public]` — server/router/rss/rss.go:90 and rss.go:141
- Frontend SSR/metadata endpoint — forces `VisibilityList = [Public]` — server/router/frontend/frontend.go:150
- `checkAttachmentPermission` — HTTP file/media server guard for serving a memo's attachments (with share-token fallback) — server/router/fileserver/fileserver.go:677-699
- `checkAttachmentAccess` — gRPC/Connect attachment API access guard — server/router/api/v1/attachment_service.go:445-451
- Memo-attachment service guard (setting/listing a memo's attachments) — server/router/api/v1/memo_attachment_service.go:214-222
- Reaction service guards (create/list reactions on a memo) — server/router/api/v1/reaction_service.go:30-38 and reaction_service.go:83
- Comment creation guard (may not comment on a private memo you don't own) — server/router/api/v1/memo_service_comments.go:41

(Related visibility checks also gate side-effects rather than viewing — e.g. notification/mention fan-out in server/router/api/v1/memo_mention_helpers.go:62-84, server/router/api/v1/user_service_notifications.go:309-312, and server/notification/email.go:313-316 — which suppress notifications for Private/Protected memos.)
