**Premise correction:** There is no nightly database-cleanup cron job in this codebase, so it has no scheduled run time.

Evidence:

- The repo does contain a cron package, `internal/scheduler` (with `ParseCronExpression`, `Schedule`, `Scheduler.Start`, etc.), but it is **not used anywhere in production**: a search for `scheduler.` outside `internal/scheduler/` and its tests returns nothing. Nothing constructs a `Scheduler` or registers a job with it, so no cron expression is ever scheduled — nightly or otherwise.
- The only background work actually wired into server startup is the S3 presign runner, started in `Server.startBackgroundRunners` (`server/server.go:153-171`). It runs on a fixed `time.Ticker` every 12 hours (`server/runner/s3presign/runner.go:26`), not on a cron schedule and not at a fixed wall-clock time, and it refreshes S3 presigned URLs — it is not a database-cleanup job.
- The "cleanup" that does exist is unrelated to a nightly cron DB job:
  - In-memory cache cleanup: a goroutine loop that sweeps expired entries every `CleanupInterval` = 5 minutes (`store/cache/cache.go:46-47`, `cache.go:60`, `cache.go:83`; configured in `store/store.go:42`).
  - Attachment/S3 storage cleanup performed inline when a memo or user is deleted (`store/attachment.go:171`, `server/router/api/v1/user_service.go:421-450`) — event-driven, not scheduled.
  - Test-teardown helpers named `Cleanup` (`server/router/api/v1/test/test_helper.go:65`).

So the premise is mistaken: no cron-scheduled nightly database-cleanup job exists, and the cron scheduler package, though present, is entirely unwired.
