**Premise correction:** This repository has no per-user API rate-limiting middleware — there is nothing to register and no request limits to report.

Evidence:

- A whole-repo search (Go sources and `go.mod`) for any rate-limiting construct — `rate.limit`, `throttle`, `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, `StatusTooManyRequests`/HTTP 429 — returns no implementation. The only textual hit is an aspirational comment in a package doc file, `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which describes email-sending behavior, not an HTTP/API rate limiter, and is not backed by any code.
- The middleware/interceptors actually registered on the server are: `middleware.Recover()` and the CORS middleware (`server/server.go:51-52`, `server/cors.go`), the static-file/SPA-fallback middleware for the frontend (`server/router/frontend/frontend.go:54-59`), the gRPC-Gateway auth middleware (`server/router/api/v1/v1.go:69-97`), and the Connect/gRPC interceptor chain — Metadata, Logging, Recovery, and Auth (`server/router/api/v1/v1.go:133-137`). None of these throttle requests by user or impose per-user request-count limits.
- The closest thing to a "limit" on the API is a per-request **body size** cap, not a rate limit: `connect.WithReadMaxBytes(maxAPIRequestBytes)` (`server/router/api/v1/v1.go:141`). That bounds request payload size, not request frequency, and is not per-user.

So the premise is mistaken: authentication/authorization is enforced (via the auth interceptor and ACL config in `server/router/api/v1/`), but no per-user rate limiting exists anywhere in the codebase.
