**Engine:** Google CEL (Common Expression Language, via `github.com/google/cel-go`), wrapped in the project's own filter engine at **`internal/filter/`** (env/types in `internal/filter/schema.go` & `engine.go`; parsing to an intermediate representation in `parser.go`/`ir.go`; SQL rendering in `render.go`).

**Mechanism:** The filter string is compiled by the CEL environment into an intermediate representation, then rendered into a dialect-specific SQL `WHERE` clause plus bound arguments via `filter.AppendConditions(ctx, engine, filters, DialectSQLite|DialectPostgres|DialectMySQL, &where, &args)` — called from each dialect's `ListMemos` (`store/db/sqlite/memo.go:61`, `store/db/postgres/memo.go:58`, `store/db/mysql/memo.go:69`), so the same CEL expression emits per-dialect SQL (e.g. `LENGTH(` vs `CHAR_LENGTH(`, `strftime` vs `EXTRACT` vs `YEAR(`).
