**Tables deleted by explicit cascade code in `store.DeleteMemo` (`store/memo.go:140-158`):**
- `memo_relation` — rows where the memo is source (`MemoID`) or target (`RelatedMemoID`)
- `attachment` — rows linked via `MemoID` (each removed with `DeleteAttachment`)
- `memo` — the memo row itself; and, because the API handler recurses over comment relations (`server/router/api/v1/memo_service.go:573-577`), each comment **memo** row plus its own `memo_relation`/`attachment` rows

**Also affected by a DB-level `ON DELETE CASCADE` (schema, not code):**
- `memo_share` — FK `memo_id REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`)

Note: `reaction` rows (keyed by the memo's resource name) are **not** deleted in this path — the handler only lists reactions for the webhook payload, with no corresponding `DeleteReaction` call.
