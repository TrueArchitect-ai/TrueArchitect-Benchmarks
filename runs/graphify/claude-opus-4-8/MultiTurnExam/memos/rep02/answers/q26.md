**memo, memo_relation, attachment**

`Store.DeleteMemo` (`store/memo.go:140-158`) explicitly deletes:
- `memo_relation` (both `MemoID` and `RelatedMemoID` directions) → `DELETE FROM memo_relation` (`store/db/sqlite/memo_relation.go`)
- `attachment` via `DeleteAttachment` → `DELETE FROM attachment` (`store/db/sqlite/attachment.go:212`)
- `memo` itself → `DELETE FROM memo` (`store/db/sqlite/memo.go`)

Comment memos are handled by recursive `Store.DeleteMemo` calls (`server/router/api/v1/memo_service.go:573-577`), which just cascade the same three tables. Note: `reaction` and `memo_share` rows are **not** deleted by this path (reactions are only listed to build the webhook payload), and the schemas define no DB-level `ON DELETE CASCADE`.
