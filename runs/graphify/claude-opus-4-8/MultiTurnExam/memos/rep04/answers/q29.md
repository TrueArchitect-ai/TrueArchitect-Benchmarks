**Interceptor path:** `web/src/connect.ts` (`authInterceptor`, line 156, registered in the transport's `interceptors` at line 188; token/refresh helpers in the same file plus `web/src/auth-state.ts`).

**Token kinds it manages:**
- Short-lived **JWT access token** — sent in the `Authorization: Bearer <token>` header; refreshed proactively (before expiry) and reactively (on 401).
- **Refresh token** — held server-side/in an HTTP-only cookie and exchanged for a new access token via `AuthService.refreshToken` (`refreshAuthClient.refreshToken({})`, line 75).
- (The backend also accepts **Personal Access Tokens (PAT)** on the same Authorization header.)

**Backend validation package:** `server/auth/` (the `Authenticator` in `server/auth/authenticator.go` — `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`, with token parsing in `server/auth/token.go`).
