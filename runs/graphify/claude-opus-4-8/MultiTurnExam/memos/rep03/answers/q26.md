**memo, memo_relation, attachment**

The explicit cascade lives in `Store.DeleteMemo` (`store/memo.go:140-159`), which deletes:
- `memo_relation` rows where the memo is the source (`MemoID`) and where it is the target (`RelatedMemoID`)
- `attachment` rows linked to the memo (via `DeleteAttachment`, `store/attachment.go:132` — which also removes the underlying blob/file storage, not a table)
- the `memo` row itself (`s.driver.DeleteMemo`)

The API handler (`server/router/api/v1/memo_service.go:518`) additionally recurses into comment memos via `DeleteMemo`, but those touch the same three tables. Reactions are only *listed* (for the webhook payload, line 545), not deleted, so the `reaction` table is not affected by this code path.
