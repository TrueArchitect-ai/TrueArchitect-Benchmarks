memo, memo_relation, attachment

Per `Store.DeleteMemo` (`store/memo.go:140-159`) and its dialect drivers, deleting a memo explicitly touches:
- **memo_relation** — deleted where the memo is source and where it is target (lines 142-147)
- **attachment** — each attachment linked to the memo is deleted (lines 148-157; `Store.DeleteAttachment` in `store/attachment.go:132` removes only the `attachment` row, no further DB cascade)
- **memo** — the memo row itself (line 158); the API handler also recursively deletes comment memos, hitting the same three tables (`server/router/api/v1/memo_service.go:573-577`)

Note: reactions are listed in the handler only for the webhook payload (`server/router/api/v1/memo_service.go:545`) and are **not** deleted by explicit cascade code, so the `reaction` table is not touched by this path.
