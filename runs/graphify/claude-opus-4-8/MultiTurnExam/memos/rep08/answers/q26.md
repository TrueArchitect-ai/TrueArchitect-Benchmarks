When `DeleteMemo` runs (API handler `server/router/api/v1/memo_service.go:518` → store `store/memo.go:140`), the tables affected by explicit code are:

- **memo** — the memo row itself, plus recursively its comment memos (the API handler deletes each comment memo, `memo_service.go:573-577`)
- **memo_relation** — rows where the memo is source (`MemoID`) or target (`RelatedMemoID`) (`store/memo.go:142-147`)
- **attachment** — rows linked to the memo, via `DeleteAttachment` per attachment (`store/memo.go:148-157`; also removes backing storage, not a table)

Not touched by explicit cascade code: `reaction` (the handler lists reactions only to build the webhook payload, it does not delete them). Any deletion of reaction rows would rely on DB-level constraints, not the Go delete path.
