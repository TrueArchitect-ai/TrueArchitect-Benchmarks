Memo view-visibility is enforced independently across several server surfaces (not routed through one shared helper). The distinct enforcement sites:

1. Single-memo read check (`checkMemoReadAccess` — used by `GetMemo` and comment listing): rejects non-public memos for anonymous users and Private memos for non-owners — `server/router/api/v1/memo_service.go:38-67`
2. List filtering (`ListMemos`): sets `VisibilityList`/CEL filter so anonymous callers see only PUBLIC and other-user results are limited to PUBLIC/PROTECTED — `server/router/api/v1/memo_service.go:183-225`
3. Comment creation (`CreateMemoComment`): blocks commenting on a Private memo you don't own — `server/router/api/v1/memo_service_comments.go:41-42`
4. Memo attachment listing (`ListMemoAttachments`): re-implements the read check on the parent memo's visibility — `server/router/api/v1/memo_attachment_service.go:214-223`
5. RSS feeds: query restricted to `store.Public` only — `server/router/rss/rss.go:90,141`
6. Frontend sitemap: query restricted to `store.Public` only — `server/router/frontend/frontend.go:150`
7. Fileserver attachment serving (`checkAttachmentAccess`): gates by parent memo visibility (public+anonymous, share token, or owner/admin) — `server/router/fileserver/fileserver.go:674-701`

Answer (enforcement site — path):

checkMemoReadAccess (GetMemo single-memo read) — server/router/api/v1/memo_service.go
