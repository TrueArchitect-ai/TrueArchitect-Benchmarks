**Premise correction:** The question assumes webhook delivery flows through an external message broker (NATS or RabbitMQ). Neither is used — in fact, this repository (Memos) contains no message broker at all. A search for `nats`, `rabbitmq`, `amqp`, `jetstream`, and `streadway` across the codebase (excluding generated/locale files) returns zero matches.

**Actual mechanism:** Webhook delivery uses an **in-process Go buffered channel with a pool of goroutine workers** — no broker, no external queue, no network hop between producer and consumer.

The "queue" is declared as a package-level buffered channel in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

It is drained by **4 worker goroutines** started in the package `init()` at `internal/webhook/webhook.go:42-55`, each ranging over the channel and calling `Post()` (an HTTP POST to the webhook URL):

```go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil { ... }
			}
		}()
	}
}
```

Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184`), which does a non-blocking send and drops the payload (with a warning) if the 128-slot buffer is full. The actual delivery in `Post()` (`internal/webhook/webhook.go:120`) is a plain `net/http` request via a shared SSRF-guarded client.

So the answer to "NATS or RabbitMQ" is: neither — it's an internal buffered channel (`asyncPostQueue`) consumed by in-process goroutines, all within `internal/webhook/webhook.go`.
