**Mechanism: explicit Go code** — not a database rule, and not "not at all."

When a user is permanently deleted in this `usememos/memos` repo, their emoji reactions are removed by two explicit `DELETE FROM reaction` statements executed inside the `DeleteUser` transaction. Reactions are cleaned up on two axes: reactions the user *authored*, and reactions *on the deleted user's memos*.

**Evidence (verified directly):**

- `store/db/postgres/user_delete.go:92-127` — `deleteUserTargetsTx` orchestrates the deletion. It calls:
  - Line 96: `deleteReactionsByContentIDsTx` — reactions on the user's memos.
  - Line 102: `deleteReactionsByCreatorTx` — reactions the user created.
- `store/db/postgres/user_delete.go:380-388` — `deleteReactionsByContentIDsTx`: `DELETE FROM reaction WHERE content_id IN (...)` (line 383).
- `store/db/postgres/user_delete.go:400-403` — `deleteReactionsByCreatorTx`: `DELETE FROM reaction WHERE creator_id = $1` (line 401).
- Reached from `store/user.go:171` (`Store.DeleteUser` → driver) and the service layer at `server/router/api/v1/user_service.go:414`, which does no reaction handling itself.
- Mirrored identically in the sqlite and mysql drivers: `store/db/sqlite/user_delete.go` (~:383, :401) and `store/db/mysql/user_delete.go` (~:420, :438).

**Negative evidence (checked — no DB-level rule):**

- The `reaction` table DDL in `store/migration/{postgres,sqlite,mysql}/LATEST.sql` has **no foreign keys and no `ON DELETE CASCADE`** — only a `UNIQUE(creator_id, content_id, reaction_type)` constraint. So the DB provides no automatic cleanup.
- The only cascade in the schema is `memo_share.memo_id REFERENCES memo(id) ON DELETE CASCADE` (postgres `LATEST.sql:108`), which is unrelated to reactions.
- The public reaction store (`store/reaction.go`) exposes only single-row `DeleteReaction`; there is no delete-by-user method — the by-user deletes live inline in `user_delete.go`.

Note: this covers *permanent* user deletion; the reaction cleanup depends entirely on the application code above, since the database won't do it.
