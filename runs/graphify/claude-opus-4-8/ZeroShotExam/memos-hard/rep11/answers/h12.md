**Determination method (how I ruled out the other candidates):**

The store layer is driver-indirected, so there are three sibling `CreateMemo` implementations that all satisfy the same interface — `store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, and `store/db/postgres/memo.go`. I traced which one is actually wired up on a default install:

1. **The call path is a delegation, not the SQL.** `Store.CreateMemo` (store/memo.go:109) just calls `s.driver.CreateMemo(...)` (store/memo.go:113); `driver` is the `store.Driver` interface (store/driver.go:29). So the real INSERT lives in whichever concrete driver was injected.

2. **Driver selection is a switch on `profile.Driver`.** `db.NewDBDriver` (store/db/db.go:14) switches on `profile.Driver`: `"sqlite"` → `sqlite.NewDB`, `"mysql"` → `mysql.NewDB`, `"postgres"` → `postgres.NewDB`, else error (store/db/db.go:18-27).

3. **The default value of that field is `sqlite`.** `profile.Driver` is set from `viper.GetString("driver")` (cmd/memos/main.go:43), and with no database flags the default resolves to `"sqlite"` — set both via `viper.SetDefault("driver", "sqlite")` (cmd/memos/main.go:122) and the persistent flag default `String("driver", "sqlite", ...)` (cmd/memos/main.go:130).

So the switch takes the `case "sqlite"` branch, the injected driver is `*sqlite.DB`, and its `CreateMemo` is the code that runs the INSERT — the mysql/postgres versions exist but are dead paths unless a non-default driver flag is passed.
