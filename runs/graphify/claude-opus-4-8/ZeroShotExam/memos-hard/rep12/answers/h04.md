**No.** Outside the driver-selection factory, the MySQL driver (`mysql.DB` / `mysql.NewDB`) is never constructed directly in production code.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:14`, which is the sole place that calls `mysql.NewDB(profile)` (`store/db/db.go:22`).
- `store/db/db.go:8` is the **only** file in the entire codebase that imports the driver package `github.com/usememos/memos/store/db/mysql` (verified by grepping every `.go` file for that import path — one hit). Since no other file imports the package, no other file can call `mysql.NewDB` or build a `mysql.DB{}`.
- `mysql.NewDB` (`store/db/mysql/mysql.go:20`) and the `DB` struct literal `DB{profile: profile}` (`store/db/mysql/mysql.go:29`) live inside the driver package itself, and the only other direct `&DB{}` literal is in an in-package test, `store/db/mysql/auth_config_test.go:12` — not outside-factory production code.
- The `mysql` references in `store/test/containers.go` are unrelated: they resolve to `github.com/testcontainers/testcontainers-go/modules/mysql` and `github.com/go-sql-driver/mysql` (`store/test/containers.go:16,20`), not the project's driver package.

So all driver construction flows through the factory; the one direct struct instantiation elsewhere is a unit test within the driver package.
