Memo view-visibility is enforced independently on several server surfaces (each re-checks the memo's `Visibility` rather than trusting a single gatekeeper). Distinct enforcement sites:

Connect/gRPC single-memo access check (`checkMemoVisibility`, used by GetMemo/GetMemoByUID) — server/router/api/v1/memo_service.go:55-66
Connect/gRPC ListMemos visibility filtering (anonymous → PUBLIC only; others → own OR PUBLIC/PROTECTED) — server/router/api/v1/memo_service.go:218-227
File/blob HTTP server serving a memo's attachments (anonymous-public, share-token, private-creator/admin checks) — server/router/fileserver/fileserver.go:677-701
Attachment API binary access (GetAttachmentBinary visibility gate) — server/router/api/v1/attachment_service.go:445-453
Reaction service visibility gate before listing/creating reactions — server/router/api/v1/reaction_service.go:30-38, 83
RSS feed restricted to PUBLIC memos — server/router/rss/rss.go:90, 141
Frontend sitemap SSR restricted to PUBLIC memos — server/router/frontend/frontend.go:150

The first three (core API single-memo check, the file server, and the ListMemos filter) are the primary "who may view a memo" surfaces; the remainder enforce the same visibility rules for memo-derived resources (attachments, reactions) and public listing surfaces (RSS, sitemap).
