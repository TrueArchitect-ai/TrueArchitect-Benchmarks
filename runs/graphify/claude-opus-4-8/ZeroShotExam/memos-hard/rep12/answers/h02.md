**Delivery function** — `Post` in `internal/webhook/webhook.go:120` (it marshals the payload, signs it, and calls `safeClient.Do(req)` at line 152 to actually send the outbound HTTP POST). Async dispatch is queued via `PostAsync` (line 184) and drained by worker goroutines started in `init` (lines 42–55), which all funnel into `Post`.

**Protection mechanism** — `safeDialContext` in `internal/webhook/webhook.go:59`, wired into the shared `safeClient`'s `Transport.DialContext` (lines 32–37). At dial time it resolves the target host and rejects any address in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`), which checks against `reservedCIDRs` (loopback, RFC-1918, link-local/cloud IMDS `169.254.169.254`, and IPv6 equivalents — `internal/webhook/validate.go:14`). Because the check runs on the *dialed* IP rather than a pre-flight lookup, it also defeats DNS-rebinding.

Notes:
- A second, earlier-stage guard exists: `ValidateURL` (`internal/webhook/validate.go:62`) validates the scheme and resolved IP when a webhook URL is *configured*. But that is TOCTOU-vulnerable to rebinding; the dial-time `safeDialContext` is what actually protects the delivery itself.
- Both guards can be disabled by the operator via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`), intended for self-hosted deployments targeting local-network services.
