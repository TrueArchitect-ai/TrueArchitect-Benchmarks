**Premise correction:** Neither. The webhook delivery workers don't consume from any external message broker — there is no NATS, RabbitMQ, or AMQP dependency in the project at all. A grep for `nats|rabbitmq|amqp|kafka` across `go.mod`/`go.sum` returns nothing, and the only textual match anywhere in the tree is an incidental substring in `web/src/locales/ca.json`.

**Actual mechanism:** Webhook delivery is handled entirely in-process using a buffered Go channel, not a broker queue.

- The "queue" is an in-memory Go channel declared as a package-level variable in `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  It's a bounded channel with capacity 128.

- The workers are 4 goroutines spawned in the package `init()` at `internal/webhook/webhook.go:42-55`. Each ranges over `asyncPostQueue` and calls `Post()` to dispatch the HTTP request.

- Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send onto the channel and drops the payload (with a warning log) if the buffer is full.

So the "broker" is a single-process, bounded `chan` with a fixed pool of 4 consumer goroutines — the queue lives and dies with the memos server process; nothing is declared in or consumed from NATS or RabbitMQ.
