**Premise correction:** There is no Redis in this repository. A codebase-wide search for `redis` across Go, YAML, and TOML files returns nothing, and there is no external cache server, client, or connection string anywhere. The cache layer is a thread-safe **in-process, in-memory cache** — no network connection is configured at all.

**Actual mechanism:**

- **Cache implementation:** `store/cache/cache.go` defines a `Cache` struct backed by a `sync.Map` with a background `cleanupLoop` goroutine (`store/cache/cache.go:65`, `:76`). It is instantiated in-process, not connected to any server.
- **Where it's "configured":** In `store/store.go:39-45`, the `New(...)` store constructor builds a `cache.Config` literal and creates the user cache with `userCache: cache.New(cacheConfig)` (`store/store.go:52`). This is the closest analog to "connection configuration" — there is no host/port/DSN because the store owns the cache directly.
- **TTL for user entries:** User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g., `CreateUser` `:97`, `UpdateUser`, `ListUsers`, `GetUser`). `Set` applies the cache's `DefaultTTL` (`store/cache/cache.go:91-92`). That default is **10 minutes**, set explicitly in `store/store.go:40` (`DefaultTTL: 10 * time.Minute`), which matches `DefaultConfig()` in `store/cache/cache.go:58`. Expired entries are swept every 5 minutes (`CleanupInterval`), with a `MaxItems: 1000` cap that triggers oldest-entry eviction.

So: user cache entries live for **10 minutes** in an in-memory cache configured inline in `store/store.go` — not a Redis TTL.
