## Answer

**RPC handler methods that can transitively trigger an outbound HTTP POST to a user-configured (webhook) URL:**

The mechanism is user webhooks. Each user configures webhook URLs (stored via `CreateUserWebhook`), and various memo-mutating RPC handlers dispatch activity payloads to those URLs. Handlers (all on `APIV1Service`):

1. **`CreateMemo`** — `server/router/api/v1/memo_service.go:70`, dispatches at `:157` via `DispatchMemoCreatedWebhook`.
2. **`DeleteMemo`** — `server/router/api/v1/memo_service.go:518`, dispatches at `:562` via `DispatchMemoDeletedWebhook`.
3. **`UpdateMemo`** — `server/router/api/v1/memo_service.go:401`, dispatches at `:513` via `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`.
4. **`CreateMemoComment`** — `server/router/api/v1/memo_service_comments.go:20`, dispatches at `:119` via `DispatchMemoCommentCreatedWebhook`.
5. **`SetMemoAttachments`** — `server/router/api/v1/memo_attachment_service.go:16`, dispatches at `:48` (`dispatchMemoUpdatedSideEffects`).
6. **`SetMemoRelations`** — `server/router/api/v1/memo_relation_service.go:16`, dispatches at `:48` (`dispatchMemoUpdatedSideEffects`).

**Convergence point — where all paths meet before delivery:**

All of the above call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go`), which enqueues onto `asyncPostQueue`. That queue is drained by worker goroutines (`internal/webhook/webhook.go:44`), and every payload — sync or async — is delivered by the single function:

- **`Post`** — `internal/webhook/webhook.go:118` (`func Post(requestPayload *WebhookRequestPayload) error`). This is where the request is marshaled, HMAC-signed, and sent via `safeClient.Do(req)` to `requestPayload.URL` (the user-configured webhook URL).

**convergence function — `webhook.Post` at `internal/webhook/webhook.go:118`**

(Note: `Post` routes through `safeClient`, whose `safeDialContext` blocks reserved/private IPs as an SSRF guard — but it is still the single delivery chokepoint for all webhook-triggering handlers.)
