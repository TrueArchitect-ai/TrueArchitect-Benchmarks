**Mechanism: removed by explicit Go code** (in the per-backend `DeleteUser` transaction) — there is no database-level cascade.

When a user is deleted, `DeleteUser` runs `deleteUserTargetsTx`, which explicitly removes reactions in two directions inside the transaction:
1. `deleteReactionsByContentIDsTx` — `DELETE FROM reaction WHERE content_id IN (...)`, covering reactions *on the deleted user's memos* (and their comment-tree descendants).
2. `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?`, covering reactions *authored by the deleted user* on anyone's content.

I confirmed the reaction table has **no** foreign key / `ON DELETE CASCADE` on either `creator_id` or `content_id`, so nothing happens automatically at the DB level — the Go deletes are the only mechanism. All three DB backends implement it identically.
