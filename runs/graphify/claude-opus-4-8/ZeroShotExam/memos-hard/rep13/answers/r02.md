**Premise correction:** There is no per-user API rate-limiting middleware in this repository. The question presupposes something that does not exist in the codebase, so there is no registration site and no request limits to report.

What I verified:

- **The complete middleware/interceptor stack contains no rate limiter.** The Echo HTTP server registers only two middlewares — `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/server.go:51-52`). The Connect/gRPC API stack registers four interceptors — `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (`server/router/api/v1/v1.go:133-137`) — plus a `gatewayAuthMiddleware` for the gRPC-Gateway path (`server/router/api/v1/v1.go:69, 97`). None of these throttle or count requests per user.

- **No rate-limiting dependency exists.** `go.mod` has no `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, or similar throttling library.

- **The only match for "rate limit" in the whole codebase is an aspirational comment, not code.** `internal/email/doc.go:86` lists `// - Rate limit email sending to prevent abuse` as a future consideration for email sending — unrelated to per-user API request limits, and not implemented.

The closest existing per-request cross-cutting controls are size/auth limits, not rate limits: a max request-body cap via `connect.WithReadMaxBytes(maxAPIRequestBytes)` (`server/router/api/v1/v1.go:141`) and authentication via `AuthInterceptor` / `gatewayAuthMiddleware`.

If you're looking to *add* per-user rate limiting, the natural home would be a new Connect interceptor added to the list at `server/router/api/v1/v1.go:133-137`.
