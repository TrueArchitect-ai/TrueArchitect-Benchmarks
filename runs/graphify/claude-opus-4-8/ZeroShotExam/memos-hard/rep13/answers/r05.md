**Premise correction:** This repository (the `memos` project) does **not** define a GraphQL schema anywhere. There is no `.graphql`/`.gql` schema, no GraphQL SDL, and no GraphQL server — a repo-wide search for "graphql" returns zero hits in source, docs, or proto files. The README confirms the design: it advertises "full **REST and gRPC** APIs" (`README.md:22`), not GraphQL.

**Actual API surface:** The public API is defined with **Protocol Buffers (gRPC)**, with a REST/HTTP layer generated from the same definitions:

- **Canonical schema — `.proto` files** in `proto/api/v1/`:
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/common.proto`
  - (Store-layer messages live in `proto/store/*.proto`.)
- **Generated Go code** (gRPC servers + REST gateway) in `proto/gen/api/v1/` — e.g. `*_grpc.pb.go` (gRPC) and `*.pb.gw.go` (grpc-gateway REST bindings). Codegen is driven by `proto/buf.yaml` / `proto/buf.gen.yaml`.
- **REST/OpenAPI surface:** a generated OpenAPI spec at `proto/gen/openapi.yaml`, embedded via `proto/openapi_embed.go`.
- **Serving/wiring:** the API router lives in `server/router/api/`; there is also an MCP router (`server/router/mcp/`) and RSS (`server/router/rss/`), but no GraphQL endpoint.

So the correct answer to "where the GraphQL schema is defined" is: nowhere — the public API is a gRPC + REST API whose source of truth is `proto/api/v1/*.proto`, with OpenAPI generated at `proto/gen/openapi.yaml`.
