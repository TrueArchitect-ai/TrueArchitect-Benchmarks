Memo visibility (who may view a memo) is enforced at several distinct server surfaces:

Single-memo read access (Connect/gRPC GetMemo) — `checkMemoReadAccess`, server/router/api/v1/memo_service.go:39-68 (blocks non-creator on Private, requires auth on non-Public, hides Archived from non-creators)
Memo listing (ListMemos) — visibility filter injection, server/router/api/v1/memo_service.go:218-227 (`creator_id == N || visibility in ["PUBLIC","PROTECTED"]`; anonymous → PUBLIC only)
RSS feed — server/router/rss/rss.go:90,141 (`VisibilityList: []store.Visibility{store.Public}`, public-only)
Attachment/file serving — `checkAttachmentPermission`, server/router/fileserver/fileserver.go:649-703 (re-checks the parent memo's visibility, plus share-token/anonymous fallbacks, before serving a file)
Reactions on a memo — server/router/api/v1/reaction_service.go:38-39,83-84 (Private memo → only creator/superuser may list or add reactions)
Attachment listing/linking tied to a memo — server/router/api/v1/attachment_service.go:451-452 and server/router/api/v1/memo_attachment_service.go:222-223 (Private memo gate before exposing its attachments)

The three core memo-view surfaces are the API single-read (`checkMemoReadAccess`), the API list filter (`ListMemos`), and the non-gRPC surfaces RSS (rss.go) and the file server (fileserver.go); reaction and attachment services re-enforce the same visibility rule on related content.
