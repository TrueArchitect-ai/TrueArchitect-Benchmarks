**Premise correction:** This repository (the `memos` Go backend) has **no Redis** and no Redis-backed cache layer at all. A `grep` for `redis` across the Go, TypeScript, and module files returns nothing. There is no "Redis connection" to configure. The premise that user entries are cached in Redis is false.

**Actual mechanism:** The cache is a **thread-safe in-memory cache** implemented in pure Go (`sync.Map` + a background cleanup goroutine), defined in `store/cache/cache.go`. It has no network/connection configuration — it's instantiated in-process.

- The user cache is created in `store/store.go:52` (`userCache: cache.New(cacheConfig)`), one of three in-memory caches (instance settings, users, user settings) all built from the same `cacheConfig`.
- That config is defined inline in `Store.New` at `store/store.go:40-45`: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`. (`store/cache/cache.go:57-64` `DefaultConfig()` sets identical defaults.)
- User entries are written via `s.userCache.Set(...)` in `store/user.go` (lines 98, 122, 132, 143, 167). `Set` uses the default TTL (`store/cache/cache.go:93-95`), so **user entries get a 10-minute TTL**. None of the user-cache writes call `SetWithTTL`, so there is no custom per-user override.

**TTL applying to user entries: 10 minutes** (the store's `DefaultTTL`), with lazy expiry on `Get` (`cache.go:135`) plus a sweep every 5 minutes (`cache.go:200-215`).
