Memo visibility is enforced across several server surfaces. The distinct enforcement sites:

**GetMemo (single-memo API read) — `server/router/api/v1/memo_service.go`**
`checkMemoReadAccess` (lines 38–67): archived memos only visible to creator; non-public memos require an authenticated user, and `Private` memos require `CreatorID == user.ID`. Called from `GetMemo`.

**ListMemos (list API read) — `server/router/api/v1/memo_service.go`**
Query-level visibility filtering (lines 218–227): anonymous → `VisibilityList = [Public]`; authenticated → filter `creator_id == <id> || visibility in ["PUBLIC","PROTECTED"]`, or `[Public, Protected]` when listing another user's memos.

**Attachment/file server — `server/router/fileserver/fileserver.go`**
`checkMemoAttachmentAccess` (lines 674–703): Public served only if anonymous allowed; otherwise a valid non-expired share token, or an authenticated user, and `Private` denied unless creator or admin.

**RSS feed — `server/router/rss/rss.go`**
Feeds restrict the store query to `VisibilityList = [store.Public]` (lines 90 and 141), so only public memos ever appear.

**Frontend SSR/metadata — `server/router/frontend/frontend.go`**
Server-rendered memo listing restricted to `VisibilityList = [store.Public]` (line 150).

Additional related in-service enforcement reuses the same visibility rules for memo-adjacent reads: comments (`server/router/api/v1/memo_service_comments.go:41`), reactions (`server/router/api/v1/reaction_service.go:38,83`), and attachment listing (`server/router/api/v1/memo_attachment_service.go:214,222`).
