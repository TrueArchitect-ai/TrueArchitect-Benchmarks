**Premise correction:** This repository (`usememos/memos`) has **no GraphQL schema** — there is no GraphQL API surface anywhere in the codebase. The question's premise is incorrect. Searching the entire tree for `graphql` returns zero matches.

**Actual API surface:** The public API is defined with **Protocol Buffers (gRPC)**, served over **Connect** and gRPC-compatible HTTP/REST. The schema lives in `.proto` files, not a `.graphql` schema:

- **Service/API definitions:** `proto/api/v1/*.proto` — the public API surface, one file per service:
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/common.proto`
- **Storage-layer messages:** `proto/store/*.proto`
- **Generated Go bindings:** `proto/gen/api/v1/` with Connect handlers under `proto/gen/api/v1/apiv1connect/*.connect.go`
- **Server-side implementations:** `server/router/api/v1/*.go` (e.g. `connect_services.go` wires up the Connect services)

The `README.md:22` confirms this: *"full REST and gRPC APIs for integration."* There is no GraphQL layer.
