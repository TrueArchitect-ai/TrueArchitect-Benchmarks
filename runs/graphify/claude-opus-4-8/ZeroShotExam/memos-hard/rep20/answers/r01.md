**Premise correction:** There is no Redis in this repository, and no external/networked cache layer of any kind. A full search for "redis" returns zero matches across the Go source, `go.mod`, and configs. This is the **memos** project, and its cache layer is a **thread-safe in-memory cache** (backed by `sync.Map`), not Redis — so there is no "Redis connection" to configure.

**Actual mechanism:**

- **Cache implementation:** `store/cache/cache.go` — a `Cache` struct using `sync.Map` with per-item `expiration` timestamps, a background `cleanupLoop` goroutine for eviction, and a `MaxItems` cap. It implements a local `Interface` (`store/cache/cache.go:11`); there is no connection string, host, or port anywhere.

- **Where it's "configured":** `store/store.go:38-61`. The `Store.New` constructor builds a `cache.Config` inline and instantiates three separate in-memory caches, including `userCache: cache.New(cacheConfig)` (`store/store.go:52`). The config is:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  
  (The same defaults also live in `cache.DefaultConfig()` at `store/cache/cache.go:57-64`.)

- **TTL for user entries:** All writes to the user cache in `store/user.go` (lines 98, 122, 132, 143, 167) call `s.userCache.Set(...)`, never `SetWithTTL(...)`. `Set` applies the cache's `DefaultTTL` (`store/cache/cache.go:92-95`). Therefore **user entries expire 10 minutes after they are written** (with lazy expiry on `Get` plus the 5-minute background cleanup sweep). There is no user-specific TTL override.

Cache keys for users are produced by `userCacheKey(userID int32)` at `store/user.go:88`.
