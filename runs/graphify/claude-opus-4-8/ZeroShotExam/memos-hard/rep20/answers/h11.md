**1st: User** (~7 packages); **2nd: Memo** (~6 packages)

The data layer is the `store/` package (`/bench/home/work/store/*.go`), where persistent entity types are defined as Go structs — `User` (`store/user.go`), `Memo` (`store/memo.go`), `Attachment`, `Inbox`, `Reaction`, `IdentityProvider`, `MemoRelation`, `MemoShare`, `UserIdentity`, `UserSetting`, `InstanceSetting`.

Counting distinct Go packages **outside** the `store/` tree that reference each type (via `store.<Type>`), the ranking is:

**1st — `store.User` (7 packages):**
- `server/auth`
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/fileserver`
- `server/router/frontend`
- `server/router/rss`

**2nd — `store.Memo` (6 packages):**
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/frontend`
- `server/router/rss`
- `server/runner/memopayload`

(Next closest is `store.Attachment` at 4 packages.) User edges out Memo mainly because it's also referenced by `server/auth` and `server/router/fileserver`, which don't touch `store.Memo`.
