**Premise correction:** The webhook delivery workers consume from *neither* NATS nor RabbitMQ. This repository (Memos) uses **no external message broker at all** — there is no NATS, RabbitMQ, or AMQP dependency anywhere in the codebase (confirmed: no matching imports in any `.go` file, and nothing in `go.mod`).

**Actual mechanism:** Webhook delivery is handled entirely **in-process using a buffered Go channel** as the "queue."

- The queue is declared in `internal/webhook/webhook.go:39` as a package-level variable:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  It's an in-memory channel with a fixed buffer of 128 payloads.

- The delivery workers are 4 goroutines spawned in `init()` at `internal/webhook/webhook.go:42-55`. Each ranges over `asyncPostQueue` and calls `Post()` (`webhook.go:120`), which does a plain `net/http` POST to the target URL via the shared SSRF-guarded `safeClient`.

- Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184`), a non-blocking `select` send that **drops the payload if the buffer is full** (`webhook.go:189-195`) — there is no durable broker, no persistence, and no redelivery.

So the "message broker" is really just a bounded in-process channel + a pool of 4 goroutines; the queue is declared at `internal/webhook/webhook.go:39`.
