**Premise correction:** This repository (the *memos* Go project) has **no per-user API rate-limiting middleware**, so there is no registration site or request-limit values to report. The question's premise is false.

What actually exists:

- **The API interceptor chain** is registered in `server/router/api/v1/v1.go:133-138` via `connect.WithInterceptors(...)`, and consists of exactly four interceptors — `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`). None of them throttle or count requests per user.
- **Echo-level middleware** is registered in `server/server.go:51-52` — only `middleware.Recover()` and `newCORSMiddleware(...)` (`server/cors.go`). No limiter here either.
- No rate-limiting library is present as a dependency (no `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, `throttled`, etc. in `go.mod`/`go.sum`).

The only things that resemble "limits" are unrelated:

- A **request byte-size cap**, `maxAPIRequestBytes`, applied at `server/router/api/v1/v1.go:141` and `:144` (`connect.WithReadMaxBytes` / `http.MaxBytesHandler`). This limits payload *size*, not request *rate*, and is not per-user.
- `internal/scheduler/middleware.go` defines middleware named `Recovery`, `Logging`, and `Timeout` — but these wrap background **job handlers** (the scheduler), not API requests, and none do rate limiting.
- A single aspirational comment at `internal/email/doc.go:86` (`Rate limit email sending to prevent abuse`) — a doc note, with no implementation.

So: the middleware you're describing does not exist in this codebase.
