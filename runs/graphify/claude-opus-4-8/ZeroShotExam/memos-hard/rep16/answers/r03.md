**Premise correction:** There is no nightly database-cleanup job scheduled anywhere in this repository, so there is no scheduled time to report.

What actually exists:

- `internal/scheduler/` is a **generic, GitHub-Actions-inspired cron scheduler library** (`internal/scheduler/doc.go:1`, `scheduler.go`, `job.go`, `parser.go`). It provides the machinery (`scheduler.New()`, `Register(&Job{...})`, cron-expression parsing), but it does not itself define or run any application job.
- This package is **never imported or used** by the actual server. Grepping for `internal/scheduler` across the codebase returns no importers outside the package itself, and there are no `scheduler.Job{...}` literals or `scheduler.Register(...)` calls in `server/`, `cmd/`, `store/`, or elsewhere.
- The only "cleanup" job tied to a schedule is an **illustrative documentation example**, not a wired-up job: `internal/scheduler/README.md:33-37` shows a job named `daily-cleanup`, and `internal/scheduler/doc.go:16` shows `Schedule: "0 2 * * *", // 2 AM daily`. These are usage samples for the library, not a running database-cleanup task.

The only real background cleanup in the app is the in-memory cache eviction goroutine in the store (`store/store.go:42`, `CleanupInterval: 5 * time.Minute`) — an interval-based ticker, not a cron-scheduled nightly database job.

So: no such cron-scheduled nightly database-cleanup job exists; the closest thing (`2 AM daily`) is only an example in the scheduler library's docs.
