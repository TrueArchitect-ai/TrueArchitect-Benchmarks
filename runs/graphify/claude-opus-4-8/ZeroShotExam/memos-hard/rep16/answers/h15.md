h15.

Memo view-visibility (who may view a memo) is enforced at multiple distinct server surfaces, each independently applying or re-implementing the PUBLIC / PROTECTED / PRIVATE + creator rules:

GetMemo single-read gate (`checkMemoReadAccess`, called by GetMemo) — server/router/api/v1/memo_service.go:39-68
ListMemos query-level visibility filter (VisibilityList / CEL `creator_id == X || visibility in [...]`) — server/router/api/v1/memo_service.go:218-227
Store/query layer that turns VisibilityList into a SQL `visibility IN (...)` clause (per-dialect copies) — store/db/sqlite/memo.go:96-102 (mirrored in store/db/mysql/memo.go, store/db/postgres/memo.go)
Memo comments — list guards parent memo + filters comments — server/router/api/v1/memo_service_comments.go:41-43 (create) and :148-161 (list)
Memo relations — inherit parent memo visibility filter — server/router/api/v1/memo_relation_service.go:107-112 and server/router/api/v1/memo_service_converter.go:182-187
Reactions — inherit memo visibility — server/router/api/v1/reaction_service.go:30-38 (list) and :83 (upsert)
Memo attachments (gRPC/Connect API) — server/router/api/v1/memo_attachment_service.go:214-222 and server/router/api/v1/attachment_service.go:422-451
Raw attachment/blob HTTP serving (separate echo fileserver, with share-token fallback) — server/router/fileserver/fileserver.go:650-704
RSS feeds — hard-restricted to PUBLIC — server/router/rss/rss.go:90,141
Frontend SSR metadata — hard-restricted to PUBLIC — server/router/frontend/frontend.go:150
User stats (list + get) — same anon/authed visibility filtering — server/router/api/v1/user_service_stats.go:83-91,217-221
SSE real-time delivery filtering (`SSEClient.canReceive`) — server/router/api/v1/sse_hub.go:134-144

The three core "who may view a memo" sites are the first three (GetMemo gate, ListMemos filter, and the store-layer SQL that enforces them). The remaining surfaces — comments, relations, reactions, attachments (both the API and the separate raw fileserver path), RSS, SSR, user stats, and SSE delivery — each independently re-enforce the same visibility rules on their own surface.
