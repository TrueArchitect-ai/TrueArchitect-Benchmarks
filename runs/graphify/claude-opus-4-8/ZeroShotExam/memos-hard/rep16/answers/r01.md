**Premise correction:** There is no Redis anywhere in this codebase. The cache layer is not backed by Redis (or any external cache server) — `grep -i redis` over the Go sources and `go.mod`/`go.sum` returns nothing. The premise of a "Redis connection" for the cache is incorrect.

**Actual mechanism:**

The cache is a custom, thread-safe **in-process in-memory cache** implemented in `store/cache/cache.go` (package `cache`). It stores entries in a `sync.Map`, tracks per-item expiration timestamps, and runs a background `cleanupLoop` goroutine to evict expired items. There is no network connection to configure — it lives entirely inside the server process.

**Where it's "configured":** in `store/store.go:40-53`, inside `store.New(...)`. A single `cache.Config` literal is built there and used to instantiate three separate caches, including `userCache`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
...
userCache: cache.New(cacheConfig),
```

(An identical default is also defined in `cache.DefaultConfig()` at `store/cache/cache.go:57-64`.)

**TTL for user entries:** **10 minutes.** User records are written via `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`), and `Set` delegates to `SetWithTTL` using `c.config.DefaultTTL` (`store/cache/cache.go:93-95`), which is the `10 * time.Minute` configured above. User cache keys are produced by `userCacheKey` (`store/user.go:88`), and entries are also explicitly removed on user deletion via `deleteUserCache` (`store/user_delete.go:39-40`). Expired user entries are additionally swept every 5 minutes by the `CleanupInterval` cleanup loop, and the cache is capped at 1000 items with oldest-item eviction.
