**Premise correction:** Neither. The webhook delivery workers do not consume from an external message broker at all — there is no NATS or RabbitMQ (nor any AMQP) in this codebase. A repo-wide search for `nats`/`rabbitmq`/`amqp` turns up nothing but an unrelated substring in a locale file.

**Actual mechanism:** Delivery is handled entirely in-process using a **Go buffered channel** as the queue. In `internal/webhook/webhook.go`:

- The "queue" is declared at package level as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel of capacity 128 (`internal/webhook/webhook.go:39`).
- A pool of **4 worker goroutines** is started in `func init()` (`internal/webhook/webhook.go:42-55`); each ranges over `asyncPostQueue` and calls `Post(payload)` to perform the actual HTTP delivery.
- Producers enqueue via `PostAsync`, which does a non-blocking `select` send onto the channel and drops the payload (logging a warning) if the buffer is full (`internal/webhook/webhook.go:184-196`).

So the "message broker" is just an in-memory bounded channel local to the running `memos` process — nothing is consumed from a broker, and no queue is declared in any broker infrastructure.
