Memo visibility (who may *view* a memo) is enforced at several distinct server surfaces:

- gRPC single-memo read — `checkMemoReadAccess` gates `GetMemo` (private → creator only; non-public → must be authenticated) — server/router/api/v1/memo_service.go (lines 39–68)
- gRPC list filtering — `ListMemos` restricts the query's `VisibilityList`/filter by caller (anon → PUBLIC only; other user → PUBLIC+PROTECTED; own → all) — server/router/api/v1/memo_service.go (lines 218–227)
- Comment listing — `ListMemoComments` blocks viewing comments of a private memo you don't own — server/router/api/v1/memo_service_comments.go (lines 41–42)
- Attachment/file serving — attachment access check honors the parent memo's visibility (public+anonymous allowed, private → creator/admin/share-token only) — server/router/fileserver/fileserver.go (lines 677–701)
- RSS feed — user and all-user RSS feeds hard-restrict to PUBLIC memos — server/router/rss/rss.go (lines 90, 141)
- Frontend sitemap — sitemap.xml lists only PUBLIC memos — server/router/frontend/frontend.go (lines 149–151)

The three primary read-authorization sites are the API `GetMemo` (`checkMemoReadAccess`), the API `ListMemos` visibility filter, and the fileserver attachment check; RSS, comments, and the sitemap enforce it on additional surfaces.
