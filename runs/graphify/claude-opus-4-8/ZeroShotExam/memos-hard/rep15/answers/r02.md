**Premise correction:** This repository (Memos, a Go application) has **no per-user API rate-limiting middleware** — the premise is false. There is nothing to register and no request limits to report, because such middleware does not exist in the codebase.

What actually exists:

- **The Connect/gRPC interceptor chain** is registered in `server/router/api/v1/v1.go:133-137` via `connect.WithInterceptors(...)`. It contains exactly four interceptors, none of which is a rate limiter:
  - `NewMetadataInterceptor()` — HTTP headers → gRPC metadata
  - `NewLoggingInterceptor(...)`
  - `NewRecoveryInterceptor(...)` — panic recovery
  - `NewAuthInterceptor(authorizer)` — authentication/anonymous-access policy

  (All defined in `server/router/api/v1/connect_interceptors.go`.)

- The only request *size* limit is `connect.WithReadMaxBytes(maxAPIRequestBytes)` in `server/router/api/v1/v1.go:141` — that caps request **body size**, not request **rate**, and is not per-user.

- The only occurrence of the phrase "rate limit" in the entire Go codebase is a non-normative documentation comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), listed under "Security Considerations." It is advice about *email sending*, not an implemented per-user API limiter, and no corresponding code exists.

A repo-wide search for rate-limiting libraries/patterns (`golang.org/x/time/rate`, `limiter`, `throttl`, `429`/`TooManyRequests`, "requests per…") returned no implementation, and `go.mod` declares no rate-limiting dependency.

So: if you're looking to add per-user API rate limiting, the natural place to register it would be the interceptor chain at `server/router/api/v1/v1.go:133`, but today no such middleware or limits are configured.
