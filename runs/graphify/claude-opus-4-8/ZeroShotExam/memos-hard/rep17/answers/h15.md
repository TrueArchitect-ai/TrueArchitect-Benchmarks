h15.

Memo visibility (who may view a memo) is enforced across several independent server surfaces in the `usememos/memos` codebase. The distinct enforcement sites:

- Single-memo read-access check (`checkMemoReadAccess`: archived → creator only; non-public requires auth; PRIVATE → creator only) — used by `GetMemo` and the parent/root-memo lookups — `server/router/api/v1/memo_service.go` (func at line 39; callers at 356, 367)
- Comment listing reuses that same check before returning a memo's comments — `server/router/api/v1/memo_service_comments.go` (line 148)
- `ListMemos` visibility filter injection (anonymous → PUBLIC only; authenticated → own memos OR PUBLIC/PROTECTED) — `server/router/api/v1/memo_service.go` (lines 218–227)
- User stats aggregation applies the same visibility filtering so hidden memos don't leak via stats — `server/router/api/v1/user_service_stats.go` (lines 82–92, 216–220)
- RSS feeds restrict to `store.Public` only — `server/router/rss/rss.go` (lines 90, 141)
- Frontend sitemap restricts to `store.Public` only — `server/router/frontend/frontend.go` (line 150)
- Attachment/media file serving enforces the parent memo's visibility (public+anonymous allowed, share-link exception, PRIVATE → creator/admin only) — `server/router/fileserver/fileserver.go` (lines 666–700)

The three core ones for "who may view a memo" are `checkMemoReadAccess` (memo_service.go), the `ListMemos` filter (memo_service.go), and the RSS/frontend/fileserver public-only surfaces; the attachment fileserver and user-stats paths are additional distinct enforcement sites.
