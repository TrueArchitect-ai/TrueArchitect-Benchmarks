**Handlers (all reach the same webhook‑delivery sink):**

- `CreateMemo` — `server/router/api/v1/memo_service.go:157` calls `DispatchMemoCreatedWebhook`
- `UpdateMemo` — `server/router/api/v1/memo_service.go:513` → `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:67` → `DispatchMemoUpdatedWebhook`)
- `DeleteMemo` — `server/router/api/v1/memo_service.go:562` calls `DispatchMemoDeletedWebhook`
- `SetMemoRelations` — `server/router/api/v1/memo_relation_service.go:48` → `dispatchMemoUpdatedSideEffects`
- `SetMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:48` → `dispatchMemoUpdatedSideEffects`

Each of these dispatch helpers (`DispatchMemo{Created,Updated,Deleted}Webhook`) funnels through `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which builds a payload targeting the user's configured webhook URL and calls `webhook.PostAsync`. The async queue workers, and the synchronous path, both end at one function.

**Convergence function — `Post` at `internal/webhook/webhook.go:120`**

`PostAsync` (webhook.go:184) merely enqueues; the four worker goroutines started in `init()` each call `Post`, and `Post` is the single place that constructs the `http.NewRequest("POST", requestPayload.URL, …)`, signs it, and issues the actual outbound request via `safeClient.Do(req)` (webhook.go:151) to the user‑configured URL.

Note: there's a *separate* outbound‑HTTP path — `GetLinkMetadata` / `BatchGetLinkMetadata` (`memo_service_link_metadata.go`) converging on `getLinkMetadata` — but that fetches a URL supplied in the request rather than a stored user‑configured webhook URL, so the webhook family above is the set that "converges before delivery."
