**Premise correction:** There is no Redis in this codebase. The question assumes a Redis-backed cache layer, but this project (memos) uses a **thread-safe in-memory cache** — no Redis connection is configured anywhere. The cache is a Go `sync.Map` with a background TTL-cleanup goroutine, not an external cache server.

**Actual mechanism:**

- **Cache implementation** — `store/cache/cache.go`. `Cache` is an in-memory store built on `sync.Map` (`store/cache/cache.go:66-73`), with expiration tracked per item (`item.expiration`, line 37) and a `cleanupLoop` goroutine that evicts expired entries on a ticker (`store/cache/cache.go:200-250`). There is no network client, connection string, host/port, or Redis import.

- **Where user caching is "configured"** — `store/store.go:38-53`. In `Store.New`, a single `cache.Config` is built inline with `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:40-45`), and the user cache is instantiated from it: `userCache: cache.New(cacheConfig)` (`store/store.go:52`). This same config also seeds `instanceSettingCache` and `userSettingCache`.

- **TTL for user entries** — **10 minutes.** User entries are written with plain `Set()` (e.g. `store/user.go:98, 122, 132, 143`), and `Set` delegates to `SetWithTTL` using the cache's `DefaultTTL` (`store/cache/cache.go:93-95`), which is `10 * time.Minute` from the config above. Keys are the stringified user ID via `userCacheKey()` (`store/user.go:88-90`). The same 10-minute default is also hardcoded in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), though the store passes its own explicit copy. Nothing in the user paths ever calls `SetWithTTL` with a custom TTL, so every user entry gets the 10-minute default.
