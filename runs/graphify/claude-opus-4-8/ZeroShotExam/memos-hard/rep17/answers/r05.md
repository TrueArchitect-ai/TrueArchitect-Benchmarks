**Premise correction:** This repository has **no GraphQL API** — there is no GraphQL schema anywhere in the codebase. A repo-wide search for `graphql` returns zero matches in Go, TypeScript, `.proto`, or config files. The question's premise is false.

**Actual API surface:** The public API is a **gRPC / Protocol Buffers** API, with a REST/HTTP layer generated on top of it via grpc-gateway. The "schema" is defined in Protobuf:

- **Source-of-truth schema** — `.proto` service and message definitions in `proto/api/v1/`:
  - `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `common.proto`
- **Build config** for the schema — `proto/buf.yaml`, `proto/buf.gen.yaml`, `proto/buf.lock`
- **Generated code** — `proto/gen/api/v1/*.pb.go` (messages), `*_grpc.pb.go` (gRPC servers), and `*.pb.gw.go` (REST gateway handlers). E.g. `proto/gen/api/v1/memo_service_grpc.pb.go`, `proto/gen/api/v1/memo_service.pb.gw.go`.
- **Service wiring** — the API server registers these services and their REST gateway in `server/router/api/v1/v1.go` (`APIV1Service` at L22, `NewAPIV1Service()` at L47, `.RegisterGateway()` at L65).

Note: the `Schema` symbol that showed up in the graph is unrelated — it's `internal/filter/schema.go:60`, a schema for the CEL-style **filter/query expression language** (used for memo filtering), not an API transport schema.
