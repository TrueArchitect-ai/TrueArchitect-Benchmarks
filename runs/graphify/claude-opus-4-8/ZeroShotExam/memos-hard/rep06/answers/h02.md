**Delivery function** — `Post` in `internal/webhook/webhook.go:120` executes the actual outbound HTTP POST via `safeClient.Do(req)` (line 152). (It runs synchronously there; `PostAsync`/the queue workers at lines 42-55 and 184 just call `Post`.)

**Protection mechanism** — The delivery is protected at dial time by `safeDialContext` in `internal/webhook/webhook.go:59`, wired into the shared `safeClient`'s `Transport` (lines 32-37). It resolves the hostname and rejects any address in a reserved/private range via `isReservedIP` — the ranges (loopback, RFC-1918, link-local incl. cloud IMDS `169.254.169.254`, and IPv6 equivalents) are defined in `internal/webhook/validate.go:14-54`. Because the check happens at connection time on the resolved IP, it also defeats DNS-rebinding. A separate up-front check, `ValidateURL` in `internal/webhook/validate.go:62`, validates the URL scheme and resolved IP when the webhook is configured. Both are bypassable only via the `AllowPrivateIPs` opt-out flag (`internal/webhook/validate.go:41`).

So concisely:
- delivery function — `Post`, `internal/webhook/webhook.go` (line 120, dispatch at 152); protection mechanism — `safeDialContext` on `safeClient.Transport`, `internal/webhook/webhook.go` (line 59), using reserved-range checks in `internal/webhook/validate.go` (`isReservedIP`, line 44), with configuration-time `ValidateURL`, `internal/webhook/validate.go` (line 62).
