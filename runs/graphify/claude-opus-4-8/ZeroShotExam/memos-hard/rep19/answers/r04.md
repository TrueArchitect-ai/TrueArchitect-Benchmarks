**Premise correction:** Neither. The webhook delivery workers don't consume from NATS *or* RabbitMQ — memos uses no external message broker for webhooks at all. The question's framing is false.

**Actual mechanism:** Delivery is handled entirely in-process by a buffered Go channel and a fixed pool of goroutines, all in `internal/webhook/webhook.go`:

- The "queue" is a package-level buffered channel, capacity 128:
  `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`
- It is "declared"/created in the `var` block, not by any broker. Consumers are 4 worker goroutines spawned in `init()` that range over the channel and call `Post()` for each payload — `internal/webhook/webhook.go:42-55`.
- Producers enqueue via `PostAsync()`, which does a non-blocking `select` send and drops the payload (with a warning log) if the channel is full — `internal/webhook/webhook.go:184-196`.

So it's an internal, bounded in-memory work queue (channel + goroutine pool), with no AMQP, no NATS, and no separate broker process. A grep across the Go sources for `nats|rabbitmq|amqp|broker` returns nothing in the webhook code (or anywhere relevant).
