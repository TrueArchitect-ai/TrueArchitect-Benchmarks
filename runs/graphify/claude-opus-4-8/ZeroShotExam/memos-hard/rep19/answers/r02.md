**Premise correction: this repository (Memos) has no per-user API rate-limiting middleware.** There is nothing to register, so it has no request limits. The premise of the question does not hold.

What actually exists:

- **HTTP (Echo) middleware** is registered in `server/server.go:51-52` — only `middleware.Recover()` and `newCORSMiddleware(profile)`. Frontend static serving adds `middleware.StaticWithConfig` and an SPA fallback in `server/router/frontend/frontend.go:54-59`. None of these throttle requests.
- **API interceptor chain** (Connect/gRPC) is assembled in `server/router/api/v1/v1.go:133-137`: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor`. There is no rate-limiting interceptor in that chain (see the interceptor definitions in `server/router/api/v1/connect_interceptors.go`).

Corroborating evidence that no such feature is present:
- A repo-wide search for `ratelimit`/`throttle`/`limiter` in `.go` files returns only one hit — a comment in `internal/email/doc.go:86` (`Rate limit email sending to prevent abuse`), which is an aspirational design note about *email sending*, not an HTTP/API middleware, and is not wired up anywhere.
- `go.mod` pulls in no rate-limiting dependency (e.g. no `golang.org/x/time/rate`, `tollbooth`, or `ulule/limiter`).

So there is no per-user rate limiter and no configured request limits to report. If you're looking to add one, the natural insertion points would be the Echo `.Use(...)` chain in `server/server.go` (for all HTTP traffic) or the interceptor list in `server/router/api/v1/v1.go` (for the typed API, where per-user identity is already available after `NewAuthInterceptor`).
