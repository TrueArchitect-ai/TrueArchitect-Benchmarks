**Premise correction:** There is no Redis anywhere in this codebase. A repo-wide search for `redis`/`go-redis`/`rueidis` (in `.go` and `go.mod`) returns nothing. The cache layer is a **thread-safe in-memory cache** — there is no external cache server and therefore no Redis connection to configure.

**Actual mechanism:**

- The cache implementation is `store/cache/cache.go` — a `Cache` struct backed by a `sync.Map` with per-item expiration, a background `cleanupLoop()` goroutine, and size/`MaxItems` eviction (`store/cache/cache.go:66`). No network client, no connection string.
- Configuration lives in `store/store.go:40-45`, inside `Store.New()`. It builds one `cache.Config` and instantiates three separate in-memory caches from it — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`). There is no connection to configure — just a `cache.Config` literal (there's also a `cache.DefaultConfig()` with identical values at `store/cache/cache.go:57`).

**TTL for user entries:** User entries have no dedicated TTL. They are written with `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. `store/user.go:98`, `:122`, `:132`, `:143`, `:167`), and `Set` applies the cache's **`DefaultTTL`** (`store/cache/cache.go:93-95`). That default is **10 minutes** (`store/store.go:41`), with expired entries swept by the cleanup loop every 5 minutes (`CleanupInterval`, `store/store.go:42`). The `SetWithTTL` method exists (`store/cache/cache.go:98`) but is not used for user entries, so the effective user-entry TTL is the default 10 minutes.
