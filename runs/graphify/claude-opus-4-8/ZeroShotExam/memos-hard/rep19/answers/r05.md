**Premise correction:** This repository (memos) has **no GraphQL schema and no GraphQL API**. A `grep` for `graphql` across `.go`, `.ts`, `.proto`, and `.graphql` files returns zero matches, and the node named `Schema` that the graph surfaces (`internal/filter/schema.go:60`) is a CEL/filter-expression schema for query filtering — unrelated to any public API.

**Actual API surface:** The public API is defined with **Protocol Buffers (gRPC + gRPC-gateway REST)**, not GraphQL:

- **Schema/source of truth** — `.proto` service definitions in `proto/api/v1/`:
  - `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, plus `common.proto`
  - Build config: `proto/buf.yaml`, `proto/buf.gen.yaml`, `proto/buf.lock`
- **Generated code** — `proto/gen/api/v1/` (e.g. `memo_service_grpc.pb.go`, `memo_service.pb.gw.go`, `user_service_grpc.pb.go`, etc.), containing both the gRPC servers and the gRPC-gateway REST handlers (`RegisterMemoServiceHandlerServer()` in `memo_service.pb.gw.go:961`, `RegisterUserServiceHandlerServer()` in `user_service.pb.gw.go:1295`).
- **HTTP/REST exposure** — the gateway is wired up in `server/router/api/v1/v1.go` via `APIV1Service` (`v1.go:22`), `NewAPIV1Service()` (`v1.go:47`), and `.RegisterGateway()` (`v1.go:65`); service method implementations live alongside it in `server/router/api/v1/`.
- **OpenAPI** — a generated OpenAPI/Swagger spec is embedded via `proto/openapi_embed.go` (there is `proto/gen/` output for it), which is the closest thing to a "public API schema" document.

So the correct answer to "where is the public API schema defined" is the **Protobuf `.proto` files under `proto/api/v1/`** (served over gRPC and a gRPC-gateway REST layer registered in `server/router/api/v1/v1.go`), not a GraphQL schema.
