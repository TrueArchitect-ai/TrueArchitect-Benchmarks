**Premise correction:** This repository (the Memos note-taking app) has **no per-user API rate-limiting middleware**. That component does not exist, so there is nothing registered and no per-user request limits to report.

What actually exists in the API middleware/interceptor chain, registered in `server/router/api/v1/v1.go`:

- **Connect interceptors** (`v1.go:133-138`): `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — none of which rate-limit.
- **gRPC-Gateway middleware** (`v1.go:69`, wired at `v1.go:97` via `runtime.WithMiddlewares`): a single `gatewayAuthMiddleware` for auth.
- **Echo-level middleware**: CORS (`server/cors.go:13`) and SPA fallback (`server/router/frontend/frontend.go:63`).

The only request "limit" enforced is a **request body size limit**, not a request-rate limit and not per-user:
- `maxAPIRequestBytes = 256 << 20` (256 MiB), defined at `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` (`v1.go:126,141,144`).

The only mentions of "rate limit" anywhere in the tree are **documentation, not code**:
- `internal/email/doc.go:86` — a comment recommending that SMTP email sending *should* be rate-limited.
- `internal/email/README.md:286-295` — an illustrative example ("10 emails per second" using `golang.org/x/time/rate`).

Both concern hypothetical email-sending throttling and are neither implemented nor registered as middleware, and neither is per-user API rate limiting.
