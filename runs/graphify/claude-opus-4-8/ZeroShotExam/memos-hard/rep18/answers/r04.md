**Premise correction:** The webhook delivery workers don't consume from NATS *or* RabbitMQ — this project (a Memos instance) has no external message broker at all. There is no NATS, RabbitMQ, or AMQP dependency anywhere in the codebase (`go.mod` and the Go sources contain no such imports).

**Actual mechanism:** Webhook delivery is handled entirely in-process using a **buffered Go channel** drained by a pool of goroutine workers.

- The "queue" is a buffered channel declared in `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- The workers are 4 goroutines started in the package `init()` at `internal/webhook/webhook.go:42-55`, each ranging over `asyncPostQueue` and calling `Post(payload)` to make the outbound HTTP request.
- Payloads are enqueued via `webhook.PostAsync(...)` (`internal/webhook/webhook.go:184`), which is called from the memo/comment dispatch paths in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

So the "message broker + queue declaration" framing doesn't apply: the queue is an in-memory `chan *WebhookRequestPayload` of capacity 128 declared at `internal/webhook/webhook.go:39`, consumed by goroutine workers spawned at `internal/webhook/webhook.go:42-55`.
