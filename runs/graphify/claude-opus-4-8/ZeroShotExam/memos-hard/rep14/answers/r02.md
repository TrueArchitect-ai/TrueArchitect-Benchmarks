**Premise correction: this repository has no per-user API rate-limiting middleware — it doesn't exist, so there are no request limits to report.**

The question assumes a rate-limiting middleware is registered somewhere. It isn't. I verified this across every layer where such a thing would live:

- **API interceptor chain** (`server/router/api/v1/v1.go:132-137`) — the Connect/gRPC interceptors registered via `connect.WithInterceptors(...)` are exactly four, none of which is a limiter: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor`. Their definitions are all in `server/router/api/v1/connect_interceptors.go` — again, no rate/throttle interceptor.
- **HTTP (Echo) middleware** (`server/server.go:51-52`) — only `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`) are registered. No throttling.
- **Scheduler middleware** (`internal/scheduler/middleware.go`) — this is background-job middleware (`Recovery`, chaining, etc.), not API request rate limiting, and it is not applied to HTTP/API requests.
- **Dependencies** — `go.mod`/`go.sum` pull in no rate-limiting library (`golang.org/x/time/rate`, tollbooth, throttled, ulule/limiter, etc.), and there is no use of `rate.Limiter`, `NewLimiter`, or an `Allow()` gate anywhere in the Go source.

The only match for "rate limit" in the codebase is an aspirational comment, not an implementation: `internal/email/doc.go:86` (`// - Rate limit email sending to prevent abuse`), and it concerns email sending, not per-user API requests.

So there is nothing registered and no configured request limits. If you're looking for the request-gating layer that *does* exist, it's the `AuthInterceptor` (authentication/anonymous-access policy) at `server/router/api/v1/v1.go:136` and `server/router/api/v1/connect_interceptors.go:205-237` — but that enforces auth, not rate limits.
