The question's premise is mistaken: **this repository has no cron scheduler, and no nightly database-cleanup job exists.** So there is no scheduled time to report.

What the codebase actually contains:
- The only background/scheduled runner is the S3 presign refresher in `server/runner/s3presign/runner.go`. It does not use a cron scheduler — it uses a Go `time.NewTicker` (`server/runner/s3presign/runner.go:30`) on a fixed interval described as "every 12 hours" (`server/runner/s3presign/runner.go:26`). It re-signs S3 attachment URLs; it does not clean up a database.
- The runner package (`server/runner/`) contains only `s3presign` and `memopayload` — no cleanup runner.
- `go.mod` pulls in no cron library (e.g. `robfig/cron`, `gocron`), and a search of `server/` for any database-cleanup job returns nothing.

The only other time-based scheduling is a GitHub Actions workflow (`.github/workflows/stale.yml`), which marks stale issues/PRs — unrelated to a database and not part of the application's runtime.

So: there is no nightly database-cleanup cron job to have a scheduled time.
