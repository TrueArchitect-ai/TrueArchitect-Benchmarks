Notes:
- The serving handler is `serveUserAvatar`, not the attachment path — profile images are user avatars, not attachments.
- The stored data is the `user.avatar_url` column, a `data:<mime>;base64,...` URI. `serveUserAvatar` decodes it via `(*FileServerService).parseDataURI()` (fileserver.go:641) and writes the bytes with `c.Blob(...)`; there is no separate blob/file hop for avatars.
- `GetUser` first checks `s.userCache` (only by ID; the username lookup here misses cache and always hits `ListUsers` → driver).
- Concrete driver shown is SQLite; equivalents exist at `store/db/postgres/user.go` and `store/db/mysql/user.go`.
