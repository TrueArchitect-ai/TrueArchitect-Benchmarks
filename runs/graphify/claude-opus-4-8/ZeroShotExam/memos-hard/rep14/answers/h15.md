Memo visibility (who may view a memo) is enforced at several distinct server surfaces. The distinct enforcement sites:

Single-memo read access (`checkMemoReadAccess`: public→open, protected→any authed user, private→creator only) — `server/router/api/v1/memo_service.go:39` (called by GetMemo at :356 and comment reads at :148/:367)

List query visibility filter (injects `creator_id == me || visibility in ["PUBLIC","PROTECTED"]`, or PUBLIC-only for anonymous) in `ListMemos` — `server/router/api/v1/memo_service.go:218`

Comment creation gate (blocks commenting on a private memo you don't own) in `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:41`

Attachment/file serving gate (checks the parent memo's visibility, plus share-token fallback, before serving a file) in `checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650` (visibility checks at :677 and :699)

SSE real-time delivery filter (`canReceive`: private events go only to creator/admin) — `server/router/api/v1/sse_hub.go:134`

RSS feed (restricts the feed to `store.Public` memos only) in `getSubscription` — `server/router/rss/rss.go:90` (and per-user feed at :141)

Frontend embed/metadata (fetches only `store.Public` memos for prerendered metadata) — `server/router/frontend/frontend.go:150`

The three core "who may view this memo" surfaces are the API single read (`memo_service.go`), the attachment/file server (`fileserver.go`), and the SSE broadcast filter (`sse_hub.go`); the list-query filter, RSS, and frontend paths enforce the same visibility rules on their respective surfaces.
