## What the shape tells you

`User` is the widest-reaching entity because it crosses **concern boundaries**, not just call volume: it's the only entity that reaches the authentication layer (`server/auth`) alongside the API, notification, RSS, and file-serving packages. It's an ambient identity type — nearly every request path needs it.

`Memo` is second and has the heaviest single-package concentration in `server/router/api/v1` (22 refs), but its spread is narrower and stays within content-handling concerns (API, notification, RSS, payload runner).

`Attachment` is worth noting as the near-miss: only 2 outside packages, but 15 references in `server/router/fileserver` — high coupling depth, low coupling breadth. If you're asking about blast radius rather than package spread, `Attachment`'s concentration in the file server makes it the more fragile of the two relationships.

Everything else funnels exclusively through `server/router/api/v1`, which is the healthy pattern — those entities are properly contained behind the API boundary.
