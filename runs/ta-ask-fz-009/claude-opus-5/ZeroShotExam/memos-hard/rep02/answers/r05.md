**The actual API surface: Protobuf/gRPC service definitions, exposed as a REST API via grpc-gateway.**

Where the contract is defined — `proto/api/v1/`:
- `memo_service.proto` — `MemoService`
- `user_service.proto` — `UserService`
- `auth_service.proto` — `AuthService`
- `attachment_service.proto` — `AttachmentService`
- `instance_service.proto` — `InstanceService`
- `shortcut_service.proto` — `ShortcutService`
- `idp_service.proto` — `IdentityProviderService`
- `ai_service.proto` — `AIService`
- `common.proto` — shared types

Each RPC carries a `google.api.http` annotation that is the REST binding. For example, `proto/api/v1/memo_service.proto:21-27` declares `CreateMemo` bound to `post: "/api/v1/memos"` with `body: "memo"`, and line 35 binds `GetMemo` to `get: "/api/v1/{name=memos/*}"`.

How it becomes HTTP:
- Generated gateway code lives in `proto/gen/api/v1/*.pb.gw.go` — e.g. the full `MemoService` route table at `proto/gen/api/v1/memo_service.pb.gw.go:1745`, `UserService` at `proto/gen/api/v1/user_service.pb.gw.go:2301`.
- Registration happens in `server/router/api/v1/v1.go`, which wires the service implementations into a grpc-gateway `runtime.ServeMux` (`RegisterMemoServiceHandlerServer` at `server/router/api/v1/v1.go:108`).

Non-gateway HTTP doors that also exist:
- SSE stream — `GET /api/v1/sse`, `server/router/api/v1/sse_handler.go:25`
- File serving — `GET /attachments/:uid/:filename` and `GET /users/:identifier/avatar`, `server/router/fileserver/fileserver.go:132` and `:168`
- RSS — `GET /explore/rss.xml` and `GET /u/:username/rss.xml`, `server/router/rss/rss.go:72` and `:111`
- Frontend meta — `GET /robots.txt`, `GET /sitemap.xml`, `server/router/frontend/frontend.go:128` and `:143`
- Health — `GET /healthz`, `server/server.go:44`

So if you're looking for the place to change the public API contract, edit the `.proto` files in `proto/api/v1/` and regenerate — the resource-oriented URL style (`{name=memos/*}`, `:batchGet`, `:getStats`) is Google AIP convention, not a GraphQL surface.
