**Premise correction: there is no nightly database-cleanup job in this repository, and the cron scheduler isn't wired into the running server at all.** So there's no scheduled time to report.

What actually exists:

- `internal/scheduler/` is a standalone, general-purpose cron library (5- and 6-field expressions, timezone option, Recovery/Logging/Timeout middleware) — `internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`. It registers nothing on its own.
- The code graph reports a **certified zero** for callers of `scheduler.New` — no production code constructs a scheduler. Every use is in docs or tests: `internal/scheduler/doc.go:12`, `example_test.go`, `integration_test.go`.
- The `"0 2 * * *"` ("2 AM daily", named `daily-cleanup`/`cleanup`) that likely prompted the question is **documentation/example text only**: `internal/scheduler/README.md:34-35`, `internal/scheduler/doc.go:15-16`, and `internal/scheduler/example_test.go:97-100`. It registers a `fmt.Println`-style stub, not a database operation.

The server's actual background work is interval-based, not cron-based:

- `server/server.go:153-174` (`startBackgroundRunners`) starts exactly one runner: the S3 presign runner.
- `server/runner/s3presign/runner.go:26-30` — a `time.NewTicker` every 12 hours, not a wall-clock time.
- The only other recurring cleanup is in-memory, not database: the cache expiry loop at `store/cache/cache.go:199-201`, default `CleanupInterval: 5 * time.Minute` (`store/cache/cache.go:60`).

If you want a nightly DB cleanup, the library is there but the wiring is missing — it would need a `scheduler.New(...)` plus `Register` call inside `startBackgroundRunners` in `server/server.go`.
