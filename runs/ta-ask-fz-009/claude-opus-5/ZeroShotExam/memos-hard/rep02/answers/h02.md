**h02.**

**Delivery function — `internal/webhook/webhook.go`:** `webhook.Post` (`internal/webhook/webhook.go:120`) is where the outbound HTTP POST actually executes — it marshals the payload, optionally attaches Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`, lines 133–150), and fires `safeClient.Do(req)` at line 152. Call sites reach it via `webhook.PostAsync` (line 184), which enqueues onto a bounded 128-slot channel drained by 4 worker goroutines started in `init()` (lines 39–55).

**Protection mechanism — two layers:**

1. **Dial-time SSRF guard (the real enforcement)** — `safeDialContext` in `internal/webhook/webhook.go:59`, wired as the `DialContext` of the shared `safeClient` transport (lines 32–37). It re-resolves the host and refuses the connection if *any* resolved address falls in a reserved range, which is what defeats DNS rebinding (resolve-then-connect races).
2. **Admission-time URL validation** — `webhook.ValidateURL` in `internal/webhook/validate.go:62`: absolute-URL parse, http/https scheme only, and reserved-IP rejection. It is called when webhooks are configured, from `APIV1Service.CreateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53`) and `UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:106`).

Both layers share the same predicate, `isReservedIP` (`internal/webhook/validate.go:44`), over the CIDR list at `internal/webhook/validate.go:14-23` — IPv4 loopback, RFC-1918 A/B/C, link-local incl. cloud IMDS `169.254.0.0/16`, plus IPv6 loopback/ULA/link-local.

**Escape hatch:** the package-level `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers at once. It is set from the `--allow-private-webhooks` flag in `cmd/memos/main.go:49` (declared at `cmd/memos/main.go:133`), default `false`.
