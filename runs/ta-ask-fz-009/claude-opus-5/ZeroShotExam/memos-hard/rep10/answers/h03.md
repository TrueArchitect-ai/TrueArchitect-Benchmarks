**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- `internal/idp/idp.go:1-8` is the shared abstraction package: it declares only the provider-neutral contract type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) — the normalized user identity that any provider type must produce. It has no imports, so it's the dependency sink both the concrete provider and the API layer point at.
- `internal/idp/oauth2/oauth2.go` is the only concrete protocol implementation shipped. Its package doc says "implements the OAuth2 identity provider integration" (line 1), and it supplies `IdentityProvider` (line 20) plus `NewIdentityProvider` (line 27), driven by `storepb.OAuth2Config` and `golang.org/x/oauth2`, with token exchange at line 47 (including PKCE support).

Corroborating scope: `internal/idp` contains exactly two Go source files plus one test — `idp.go` and `oauth2/oauth2.go` — so no SAML/LDAP/OIDC-specific sibling exists. The design docs agree that OAuth2 is the only supported type: `docs/configuration-provisioning.md:152` ("Initial validation supports only OAuth2 providers") and `docs/plans/2026-04-21-sso-user-identity-linkage/definition.md:47` explicitly puts "IdP types other than `OAUTH2`" out of scope.

The wire/API surface for managing providers is separate from this pair: `proto/gen/api/v1/apiv1connect/idp_service.connect.go:55` (`IdentityProviderServiceClient`/`Handler`) is the CRUD service for provider configuration, not the authentication protocol abstraction.
