r03. **Premise correction: there is no nightly database-cleanup job in this repository, and no cron scheduler wired into the running server at all.**

What actually exists:

**1. A cron scheduler library that no production code uses.** `internal/scheduler/` is a self-contained cron-job package (`scheduler.Register` at `internal/scheduler/scheduler.go:70`, cron parsing at `internal/scheduler/parser.go:30`). The only Go files importing it are its own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. `[ArchMap query]` returns a certified zero — nothing in `server/` or `cmd/` constructs a scheduler.

**2. The "2 AM daily cleanup" you're likely remembering is documentation, not a registered job.** It appears as illustrative snippets only:
- `internal/scheduler/README.md:34-35` — `Name: "daily-cleanup", Schedule: "0 2 * * *"`
- `internal/scheduler/doc.go:15` — same example in the package doc comment
- `internal/scheduler/example_test.go:97-99` — "Cleanup old data every night at 2 AM"
- `internal/scheduler/README.md:241-244` — a `"stale-session-cleanup"` example at `0 3 * * *`

None of these are real jobs; they are the package's usage examples, and one of them is a runnable `Example` test.

**3. The server's actual background work is interval-based, not cron-scheduled.** `Server.startBackgroundRunners` (`server/server.go:153-174`) starts exactly one runner: the S3 presign refresher, which runs once at boot and then every 12 hours (`server/runner/s3presign/runner.go:26-30`). There is no scheduled DB-maintenance runner alongside it.

The nearest thing to a periodic "cleanup" touching storage is the in-memory cache's expiry sweep — every 5 minutes by default (`store/cache/cache.go:60`, loop at `store/cache/cache.go:199-201`) — but that evicts cache entries, not database rows, and it is a ticker inside the cache, not a cron job.
