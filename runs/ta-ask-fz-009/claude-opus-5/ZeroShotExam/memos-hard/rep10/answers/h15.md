h15.

Memo read-visibility is enforced at **eight distinct server-side sites** across four surfaces (gRPC/API v1, file server, frontend/RSS public renderers, and the store query layer):

**Central API guard**
1. `checkMemoReadAccess` — canonical read gate (archived → creator only; non-public → auth required; private → creator only) — `server/router/api/v1/memo_service.go:39-68`; called from `GetMemo` (`:356`), parent-memo resolution (`:367`), and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)

**Per-RPC inline checks that duplicate the same rule instead of calling the guard**
2. `ListMemos` visibility scoping — anonymous → `PUBLIC` only; authenticated → `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` — `server/router/api/v1/memo_service.go:218-227`
3. `ListMemoAttachments` — inline visibility check before listing a memo's attachments — `server/router/api/v1/memo_attachment_service.go:213-225`
4. Reactions — inline check in list (`server/router/api/v1/reaction_service.go:29-41`) and in the upsert path (`:83`)
5. `checkAttachmentAccess` — attachment access derived from the owning memo's visibility — `server/router/api/v1/attachment_service.go:419-455` (used by `:256`)
6. Comment creation — refuses commenting on a private memo owned by someone else — `server/router/api/v1/memo_service_comments.go:41`
7. User stats — visibility list narrowing per viewer — `server/router/api/v1/user_service_stats.go:84-90`, `:218-220`

**Non-gRPC HTTP surfaces**
8. File server attachment streaming — public+anonymous allowed, share-token fallback, then private → creator/admin only — `server/router/fileserver/fileserver.go:677-701`
9. Public renderers hard-scope to `PUBLIC`: sitemap — `server/router/frontend/frontend.go:149-151`; RSS feeds — `server/router/rss/rss.go:90`, `:141`

**SSE delivery filter (push-side enforcement, distinct from request-side)**
10. `SSEClient.canReceive` — private events only to creator or admin, unknown visibility denied — `server/router/api/v1/sse_hub.go:134-144`, applied in `Broadcast` at `:123`; event visibility is stamped in `server/router/api/v1/sse_event_helpers.go:29-37`

**Where it bottoms out**
11. `FindMemo.VisibilityList` (`store/memo.go:69`) is translated to a SQL `visibility IN (...)` predicate independently per dialect — `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`

Architectural note: only sites 1 and 11 are shared mechanisms; sites 3, 4, 6 and 8 re-implement the "non-public ⇒ authenticated, private ⇒ creator" predicate by hand, and they don't agree — `checkMemoReadAccess` (`memo_service.go:63`) omits the `!isSuperUser(user)` escape hatch that the attachment/reaction paths include, so admins can read a private memo's attachments and reactions but not the memo itself through `GetMemo`. That divergence is the drift risk in this invariant.
