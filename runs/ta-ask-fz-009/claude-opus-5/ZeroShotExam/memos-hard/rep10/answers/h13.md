**Single concrete implementation:** the unexported `markdown.service` struct (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown` instance and satisfies the `markdown.Service` interface (`internal/markdown/markdown.go:31`). There is no second production implementation and no mock/fake in the graph — the interface exists for boundary/injection hygiene, not for polymorphism. Rendering back to markdown text delegates to a helper type, `renderer.MarkdownRenderer` (`internal/markdown/renderer/markdown_renderer.go:15`), constructed per call at `internal/markdown/markdown.go:250` — that's a collaborator, not an alternative `Service`.

**Construction:** only via the factory `markdown.NewService(opts...)` (`internal/markdown/markdown.go:85`), which applies `WithTagExtension` / `WithMentionExtension` on top of GFM and returns `&service{md}`. Runtime call sites:
- `NewAPIV1Service` — `server/router/api/v1/v1.go:48-51`, with both tag and mention extensions enabled. This is the **only production construction**; it's the single owner of the instance.
- Test-only: `server/router/api/v1/test/test_helper.go:44`, `server/router/fileserver/fileserver_test.go:427`, `server/router/rss/rss_test.go:54`.

The one instance is then handed to RSS by reference rather than re-created: `rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)` at `server/server.go:85`.

**Holders of the interface (struct fields typed `markdown.Service`):**

- `memopayload.Runner.MarkdownService` — `server/runner/memopayload/runner.go:16`, injected via `NewRunner` (`:19`). **Caveat:** `[ArchMap query]` returns a certified zero — this runner is never wired up anywhere; the live path into `memopayload` is the package-level function `RebuildMemoPayload(ctx, memo, markdownService)` (`server/runner/memopayload/runner.go:74`), which takes the interface as a parameter from the API layer.

One boundary note: this Go service is not the primary renderer for user-visible content. The doc comment at `internal/markdown/markdown.go:29-30` states HTML rendering happens mainly on the frontend (`web/src/components/MemoContent/MemoMarkdownRenderer.tsx:56` and its render-context in `web/src/components/MemoContent/MarkdownRenderContext.tsx`), with the Go `RenderHTML` reserved for RSS and other server-side output — which matches the call sites above.
