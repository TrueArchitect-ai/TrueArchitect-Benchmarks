**protection mechanism** — `internal/webhook/validate.go`, in two layers:

1. **Dial-time SSRF guard (the one that actually protects delivery):** the shared `safeClient` uses a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`, `:59-77`). Every dial resolves the host and rejects the connection if any resolved IP falls in a reserved range — this is what defeats DNS rebinding, since validation-at-write time can't. The range set is `reservedCIDRs` / `isReservedIP` in `internal/webhook/validate.go:14-54` (IPv4 loopback, RFC-1918, link-local incl. `169.254.169.254` IMDS, plus IPv6 `::1`, `fc00::/7`, `fe80::/10`).

2. **Admission-time validation:** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) enforces http/https scheme and non-reserved resolution when a webhook is created or edited — called from `APIV1Service.CreateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53`) and `UpdateUserWebhook` (`:106`), returning gRPC `InvalidArgument`.

**Escape hatch:** both layers consult the same `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`, short-circuited in `isReservedIP`), set from the `--allow-private-webhooks` CLI flag at `cmd/memos/main.go:49` (declared `:133`, bound `:160`). When true, SSRF protection is fully disabled for self-hosted deployments targeting local services.
