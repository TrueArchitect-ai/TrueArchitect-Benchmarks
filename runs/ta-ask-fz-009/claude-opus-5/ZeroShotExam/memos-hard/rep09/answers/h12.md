### The three candidates and why SQLite is the live one

`store.Driver` has exactly three concrete implementations — `sqlite.DB` (`store/db/sqlite/sqlite.go:16`), `mysql.DB` (`store/db/mysql/mysql.go:14`), `postgres.DB` (`store/db/postgres/postgres.go:16`) — each with its own `CreateMemo` and its own dialect-specific INSERT (e.g. the Postgres variant with `$n` placeholders at `store/db/postgres/memo.go:38`). Interface dispatch is decided once, at startup, by configuration:

- `store/db/db.go:14-27` — `NewDBDriver` switches on `profile.Driver`: `"sqlite"` → `sqlite.NewDB`, `"mysql"`, `"postgres"`, else error.
- `cmd/memos/main.go:122` — `viper.SetDefault("driver", "sqlite")`, and the flag itself also defaults to `sqlite` (`cmd/memos/main.go:130`). With no flags/env, `profile.Driver == "sqlite"`.
- `internal/profile/profile.go:110-116` — confirms the default path is a file DSN `memos_prod.db` under the data dir when driver is sqlite and no `--dsn` is given.
- The chosen driver is injected once into the store: `dbDriver, err := db.NewDBDriver(instanceProfile)` then `store.New(dbDriver, instanceProfile)` (`cmd/memos/main.go:57,64`), so every later call resolves to that one instance.

### Determination method

Map first, source to confirm: `[ArchMap query]` enumerated the three concrete drivers (so I knew the count of candidates rather than guessing); a text search for `INSERT INTO memo` located the actual SQL sites; then I read the *dispatch* decision rather than the call graph, because Go interface dispatch is invisible to static call edges — the deciding facts are the `switch profile.Driver` in `store/db/db.go` and the `sqlite` default in `cmd/memos/main.go`. `[ArchMap query]` was deliberately not used as the tiebreaker: it reported a name collision across 15 symbols (store, three drivers, gRPC/Connect stubs), which is exactly the ambiguity that only the config-time switch resolves.

Caveat on "default installation": the default holds for the `memos` binary with no flags, no env (`MEMOS_DRIVER`), and no config file — viper binds the flag, so any of those overriding to `mysql`/`postgres` moves execution to the corresponding `store/db/<driver>/memo.go`.
