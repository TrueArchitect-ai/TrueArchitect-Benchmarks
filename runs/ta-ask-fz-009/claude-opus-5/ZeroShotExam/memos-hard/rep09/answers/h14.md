**Computation site**

- `RebuildMemoPayload(ctx, memo, markdownService)` — `server/runner/memopayload/runner.go:74`. It delegates the actual parse to the markdown service: `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`runner.go:80-86`).
- The extraction itself is `internal/markdown/markdown.go:356` (`service.ExtractAll`) — one goldmark AST walk. The standalone equivalent for properties only is `service.ExtractProperties` (`internal/markdown/markdown.go:193`).
- Persisted shape is `MemoPayload.Property`, documented in the schema as "The calculated properties from the memo content" (`proto/store/memo.proto:14-22`, generated Go at `proto/gen/store/memo.pb.go:85`), stored in the memo row's `payload` column (`store/migration/sqlite/LATEST.sql:33` et al.) and surfaced on the API as `Memo.property` via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:49,315`).
- Separately, `Memo.snippet` is *not* persisted — it is derived per response at conversion time: `s.getMemoContentSnippet(memo.Content)` → `MarkdownService.GenerateSnippet([]byte(content), 64)` (`server/router/api/v1/memo_service_converter.go:76-80`, `server/router/api/v1/memo_service_webhooks.go:83-85`, generator at `internal/markdown/markdown.go:264`).

**Triggers**

Only three call sites for `RebuildMemoPayload` exist in the repo:
- `APIV1Service.CreateMemo` — before the store insert (`server/router/api/v1/memo_service.go:108`); this also covers comment creation, which routes through `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
- `APIV1Service.UpdateMemo` — only inside the `path == "content"` branch of the update mask, then written via `update.Payload = memo.Payload` (`server/router/api/v1/memo_service.go:436-451`). Visibility/pinned/state updates do not recompute.
- `memopayload.Runner.RunOnce` — batch backfill that walks all memos 100 at a time and re-saves each payload (`server/runner/memopayload/runner.go:27-72`). The graph reports a certified zero for callers of `RunOnce`, so this rebuilder is currently not wired into server startup — it exists as an on-demand/maintenance path.

Snippet recomputes implicitly on every read that converts a memo to the API type (get/list/etc.), since it's computed in the converter rather than stored.

**Extracted properties**

From the single AST walk (`internal/markdown/markdown.go:371-419`):
- `Property.Title` — text of the first block-level child if it is an H1 heading (`:384-388`, via `extractHeadingText`).
- `Property.HasLink` — any `KindLink` node (`:393-394`).
- `Property.HasCode` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan` (`:396-397`).
- `Property.HasTaskList` — any GFM task checkbox (`:399-400`).
- `Property.HasIncompleteTasks` — a task checkbox with `IsChecked == false` (`:401-405`).
- Alongside properties, the same pass collects `Tags` (from `#tag` nodes) and `Mentions`, deduplicated preserving case (`:376-381, 417-419`); `RebuildMemoPayload` persists `Tags` and `Property` but drops `Mentions`.

These properties are consumed for filtering/aggregation too — e.g. user stats counts memos with links/code/task lists/incomplete tasks off `memo.Payload.Property` (`server/router/api/v1/user_service_stats.go:141-152`).
