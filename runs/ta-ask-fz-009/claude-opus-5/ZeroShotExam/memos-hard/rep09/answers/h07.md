Two notes on the boundary: the frontend `UserAvatar` component renders whatever `avatarUrl` the API returned (web/src/components/UserAvatar.tsx:14) — I found no client code constructing `/file/users/.../avatar` (searched 433 files under web/src), so that endpoint is consumed by direct URL references (e.g. RSS/OG markup or stored avatar URLs) rather than by the avatar component. Also, unlike `serveAttachmentFile`, this handler has no per-user visibility check beyond the anonymous gate — any authenticated viewer (or anyone, on a public instance) can fetch any username's avatar.
