**delivery function — `webhook.Post` in `internal/webhook/webhook.go:120`** (the actual `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); **protection mechanism — dial-time SSRF guard `safeDialContext` in `internal/webhook/webhook.go:59`, backed by the reserved-CIDR check `isReservedIP` / `ValidateURL` in `internal/webhook/validate.go:44,62`**

How it fits together:

- **Execution path.** Callers enqueue via `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which drops the payload onto a bounded 128-slot channel `asyncPostQueue` (line 39) drained by 4 worker goroutines started in `init()` (lines 42–55). Each worker calls `Post`, which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`, lines 133–150), and performs the POST through the shared `safeClient` (line 152). Response reading is capped at 1 MiB (line 158) and the client has a 30 s timeout (lines 27, 33).

- **Two-layer SSRF defense.**
  1. *Admission time:* `ValidateURL` (`internal/webhook/validate.go:62`) requires an absolute URL, an `http`/`https` scheme, and that every resolved address for the hostname is outside the reserved ranges — returning gRPC `InvalidArgument` so create/update handlers reject bad URLs before storage.
  2. *Connect time:* `safeClient`'s transport uses `safeDialContext` (`internal/webhook/webhook.go:59`), which re-resolves the host and refuses to dial if any resolved IP is reserved. This is the load-bearing control — it closes the TOCTOU/DNS-rebinding hole that URL-only validation leaves open (noted in the comment at lines 29–31).

- **Blocked ranges and escape hatch.** `reservedCIDRs` (`internal/webhook/validate.go:14–23`) covers IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (cloud IMDS), plus IPv6 loopback, unique-local, and link-local. The check is globally bypassable via `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`), set from the `--allow-private-webhooks` flag in `cmd/memos/main.go:49,133` for self-hosted deployments targeting LAN services.

One caveat worth flagging: neither layer disables HTTP redirect following, so a permitted public host that 3xx-redirects is still re-dialed through `safeDialContext` — the dial guard holds, but the redirect itself isn't rejected earlier.
