## Why the ranking looks this way

`User` is the identity anchor, so it crosses boundaries that no other entity touches: authentication (`server/auth`), file serving (`server/router/fileserver`), and feed generation (`server/router/rss`) all need a user independent of any memo. `Memo` is the core domain object but its consumers are narrower — the API surface, notifications, the RSS feed, and the payload-rebuild runner. `Attachment` has more raw references in `fileserver` than `Memo` does anywhere outside the API layer, but they concentrate in two packages, so it loses on breadth.

Two caveats on precision: the graph notes that `~writes`/`~reads` edges are a **lower bound** because SQL assembled by string concatenation isn't captured, and that this IR set carries no `overrides`/`event`/`route` edges. Both gaps would only add references, and they'd apply fairly evenly across entities, so the User → Memo ordering is safe; treat the counts as approximate rather than exact.
