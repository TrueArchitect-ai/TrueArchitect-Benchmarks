**Premise correction: there is no nightly database-cleanup job in this repository, and the cron scheduler isn't wired into the running server at all.** So there is no scheduled time to report.

What actually exists:

1. **A standalone cron scheduler library, unused by the app.** `internal/scheduler/` implements a full cron engine — `ParseCronExpression` (`internal/scheduler/parser.go:30`), `Scheduler.Register` (`internal/scheduler/scheduler.go:70`), middleware (Recovery/Logging/Timeout per `internal/scheduler/README.md`). But `Register` has **zero callers** anywhere in the codebase (certified zero from the code graph), and the only files importing `github.com/usememos/memos/internal/scheduler` are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No job of any kind is registered by production code.

2. **The "2 AM daily-cleanup" string you may be thinking of is documentation, not a job.** `internal/scheduler/README.md:34-37` and `internal/scheduler/doc.go:14-16` show an illustrative snippet:
   ```go
   Name:     "daily-cleanup",
   Schedule: "0 2 * * *", // 2 AM daily
   ```
   That's an API usage example in the package docs — it never executes and touches no database.

3. **Real background work uses tickers, not cron, and neither cleans the database.** `Server.startBackgroundRunners` (`server/server.go:153-174`) starts exactly one runner: the S3 presign refresher, on a 12-hour `time.Ticker` (`server/runner/s3presign/runner.go:26-30`). The only other runner package, `server/runner/memopayload/runner.go`, is a payload rebuild helper. There is no vacuum/purge/retention job scheduled anywhere.

If you were expecting a nightly cleanup, the closest thing to build on is the unused `internal/scheduler` package plus the `startBackgroundRunners` hook in `server/server.go` — that's where a registration would have to go.
