h15.

Memo visibility is enforced in **thirteen** distinct places across five server surfaces (Connect/gRPC API, SSE hub, file server, RSS/sitemap HTTP routers, notification pipeline). There is no single choke point — each site re-implements the PUBLIC / PROTECTED / PRIVATE rule.

**Connect/gRPC API — per-memo read guard**
`checkMemoReadAccess` (archived → creator only; non-public → authenticated; private → creator) — server/router/api/v1/memo_service.go:39-68 (callers: `GetMemo` memo_service.go:341, `ListMemoComments` memo_service_comments.go:136)

**Connect/gRPC API — query-level visibility filters (list paths)**
ListMemos visibility scoping (`VisibilityList` / `creator_id == N || visibility in [...]`) — server/router/api/v1/memo_service.go:218-227
ListMemoRelations relation filter — server/router/api/v1/memo_relation_service.go:107-112
Batch relation conversion filter — server/router/api/v1/memo_service_converter.go:182-187
ListMemoComments comment filter — server/router/api/v1/memo_service_comments.go:156-160

**Connect/gRPC API — write/interaction guards**
Comment creation guard (private parent → creator/admin only) — server/router/api/v1/memo_service_comments.go:33-41
Reaction guards (list + upsert) — server/router/api/v1/reaction_service.go:29-38, :82-83
Memo-attachment access guard — server/router/api/v1/memo_attachment_service.go:213-222
Attachment access via memo visibility — server/router/api/v1/attachment_service.go:422-455 (`checkAttachmentAccess`)

**SSE delivery filter**
`SSEClient.canReceive` (private events only to creator/admin; unknown visibility denied) — server/router/api/v1/sse_hub.go:134-144, event visibility populated at server/router/api/v1/sse_event_helpers.go:29-37

**File server (non-API HTTP surface)**
`checkAttachmentPermission` (public + AllowAnonymous, share-token fallback, private → creator/admin) — server/router/fileserver/fileserver.go:650-704

**Public HTTP feeds**
RSS feeds restricted to `store.Public` — server/router/rss/rss.go:90, :141
Sitemap restricted to `store.Public` — server/router/frontend/frontend.go:149-151

**Notification pipeline**
`canViewerAccessMemo` (admin bypass; private → creator; protected → any authenticated) — server/notification/email.go:306-320
Mention-notification eligibility checks — server/router/api/v1/memo_mention_helpers.go:62-84

One deliberate bypass worth flagging: `GetMemoByShare` resolves a memo by opaque share token **without** a visibility check — only archived/missing is rejected (server/router/api/v1/memo_share_service.go:153-192), with the matching share-token exception in the file server at fileserver.go:684-689.
