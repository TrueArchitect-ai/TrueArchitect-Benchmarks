**The path shape**

1. Each handler's service method fires a dispatch helper in `server/router/api/v1/memo_service_webhooks.go`: `DispatchMemoCreatedWebhook` (:15), `DispatchMemoUpdatedWebhook` (:20), `DispatchMemoDeletedWebhook` (:25), `DispatchMemoCommentCreatedWebhook` (:30). The update-side handlers (`UpdateMemo`, `SetMemoAttachments`, `SetMemoRelations`) route through `dispatchMemoUpdatedSideEffects` at `server/router/api/v1/memo_update_helpers.go:66`.
2. Both `DispatchMemoCommentCreatedWebhook` and the shared `dispatchMemoRelatedWebhook` (memo_service_webhooks.go:48) load the target from user settings via `s.Store.GetUserWebhooks`, set `payload.URL = hook.Url` (:41, :67) — that's the user-configured URL — and call `webhook.PostAsync`.
3. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto the bounded `asyncPostQueue` (cap 128, drops on full). Four worker goroutines started in `init()` (:42–55) drain the queue and call `Post`. So `Post` is the single funnel: the RPC boundary never performs the request itself, and delivery is asynchronous and best-effort.

**Worth knowing about the boundary:** the shared `safeClient` (:32) installs `safeDialContext` (:59), which resolves the hostname and refuses any address in a reserved/private range — SSRF/DNS-rebinding guard sits at dial time, inside the convergence point, so every one of the handlers above inherits it.
