**Details worth noting:**

- **Two branches, one store call.** The authentication hop (`getCurrentUser` → `AuthenticateToUser`) fires only on private instances (`s.Profile.AllowAnonymous()` false, `fileserver.go:173`). On a public instance another user's avatar is served anonymously. Either way there is no per-user authorization check on the avatar itself — any resolvable username's avatar is served.
- **Lookup is username-only.** `getUserByUsername` passes `store.FindUser{Username: &identifier}` (`fileserver.go:716`), so the `:identifier` path segment must be the username, not the numeric ID.
- **The user cache is bypassed on this path.** `Store.GetUser` only consults `s.userCache` when `find.ID != nil` (`store/user.go:149`); a username lookup always falls through to `ListUsers` → SQL. The row is written *into* cache afterward (`store/user.go:143`), but every avatar request costs a query.
- **Data-layer fan-out is a three-dialect interface.** `store/driver.go:47` is the contract; sqlite/postgres/mysql each implement `ListUsers` with the same column list including `avatar_url`.
- **Type allowlist is enforced at serve time, not just upload.** `avatarAllowedTypes` (`fileserver.go:75`) re-checks the decoded MIME type after `parseDataURI`, mirroring the upload-side check in `server/router/api/v1/user_service.go:343` — defense in depth against rows written before validation existed.
