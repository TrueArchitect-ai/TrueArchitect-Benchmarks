## How the candidate was resolved

The interface has exactly three implementors — `sqlite.DB` (`store/db/sqlite/sqlite.go:16`), `mysql.DB` (`store/db/mysql/mysql.go:14`), `postgres.DB` (`store/db/postgres/postgres.go:16`) — so `s.driver.CreateMemo` is a dispatch, not a static call. Static call-graph analysis cannot pick the winner; the selection is a runtime config value. I resolved it by following the configuration back to its default:

- **Selection point:** `NewDBDriver` switches on `profile.Driver` — `store/db/db.go:18-24`; `case "sqlite"` → `sqlite.NewDB(profile)` (`store/db/db.go:20`). `default` returns `errors.New("unknown db driver")` (`store/db/db.go:26`), so the field must hold one of the three literals.
- **Value source:** the profile field is populated from config — `Driver: viper.GetString("driver")` at `cmd/memos/main.go:43`.
- **Default with no flags:** `viper.SetDefault("driver", "sqlite")` — `cmd/memos/main.go:122`, and the flag itself declares the same default: `rootCmd.PersistentFlags().String("driver", "sqlite", "database driver")` — `cmd/memos/main.go:130`.

So with no `--driver` flag (and no `MEMOS_DRIVER` env var — `viper.AutomaticEnv()` with prefix `memos` at `cmd/memos/main.go:167-169` can override it), the switch takes the sqlite branch, `s.driver` is `*sqlite.DB`, and the sqlite variant of the INSERT executes.
