**Computation site** — `memopayload.RebuildMemoPayload` at `server/runner/memopayload/runner.go:74-88`. It's a thin wrapper: it delegates the actual work to the markdown service's single-pass AST walk, `(*service).ExtractAll` in `internal/markdown/markdown.go:356-422`, then writes the result onto the memo's stored payload (`memo.Payload.Tags = data.Tags`, `memo.Payload.Property = data.Property`, runner.go:85-86). The equivalent property-only walk exists standalone as `ExtractProperties` (`internal/markdown/markdown.go:193-241`).

**Triggers** — three call sites, all confirmed:
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after content-length validation, before the store insert.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `content` update-mask branch; the rebuilt payload is carried into the update via `update.Payload = memo.Payload` (line 451). Other mask paths (e.g. `visibility`, line 452) do not recompute.
- The backfill runner `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:27-72`, which pages all memos in batches of 100 and re-derives + persists each payload. Note: the graph reports a **certified zero** on callers of `RunOnce`, and `grep` for `memopayload` finds no reference in `server/server.go` — so this runner is currently not wired into startup; it exists as a rebuild path without an invoker.

**Extracted properties** — stored on `MemoPayload.Property` (`storepb.MemoPayload_Property`), surfaced to the API as `Memo.property` via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:49`):
- `Title` — text of the document's **first block-level child only if it is an H1 heading** (`markdown.go:384-388`, via `extractHeadingText`).
- `HasLink` — any `KindLink` node.
- `HasCode` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- `HasTaskList` — any `TaskCheckBox` node.
- `HasIncompleteTasks` — a `TaskCheckBox` with `IsChecked == false`.

The same pass also derives `Payload.Tags` (deduped, original case preserved — `markdown.go:376-378`, `418`) and `Mentions` (lowercased, `379-381`); mentions are consumed separately by `server/router/api/v1/memo_mention_helpers.go:32` rather than stored on the payload.

One adjacent piece worth distinguishing: the list **snippet** is *not* part of this stored payload. It is computed per-response at convert time by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-88`, called from `memo_service_converter.go:76`), so it needs no recomputation trigger.
