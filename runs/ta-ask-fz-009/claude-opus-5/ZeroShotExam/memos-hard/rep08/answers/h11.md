## Why `User` wins

It's the identity type, so it crosses every boundary rather than just the API surface: `server/auth` needs it for session/credential handling, `server/notification` for recipients, `server/router/fileserver` and `server/router/rss` for per-user access decisions. `store.Memo` is the highest-volume type by *reference count* inside the API layer (22 direct hits in `server/router/api/v1`), but its fan-out is narrower — it doesn't reach the auth or fileserver packages.

By raw reference count the order is the same: `store.User` at 72 direct edges vs. `store.Memo` at 44.

## Caveats worth knowing

- The `store` package itself and `store/db/{mysql,postgres,sqlite}` are excluded as in-layer; including them would add 4 to every count uniformly and not change the ranking.
- `store.UserSetting` collides with a generated protobuf type of the same name (`proto/gen/store/user_setting.pb.go`), so its count merges two symbols — it's low enough not to affect the top two either way.
- The graph reports `~writes`/`~reads` edges as a **lower bound**: SQL assembled by string concatenation isn't captured. That affects raw edge counts, not the package fan-out I ranked on, since the fan-out comes from Go type references.
- `apiv1.User` and `apiv1.Reaction` also map to the `user`/`reaction` tables by name convention, but those are API-layer DTOs, not data-layer entities, so I left them out of the ranking.
