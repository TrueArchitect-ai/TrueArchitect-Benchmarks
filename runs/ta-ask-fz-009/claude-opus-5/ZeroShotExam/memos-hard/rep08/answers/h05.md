**Mechanism: explicit Go code**, inside the driver-level `DeleteUser` transaction — not a DB cascade, and not left orphaned.

## What happens

`store.DeleteUser` delegates to the per-dialect driver (`store/user.go:171`), and each driver runs one transaction that explicitly wipes reactions in two passes before the user row is removed:

- `deleteUserTargetsTx` — `store/db/sqlite/user_delete.go:92-127`:
  - line 96 `deleteReactionsByContentIDsTx` → `DELETE FROM reaction WHERE content_id IN (...)` (`store/db/sqlite/user_delete.go:380-388`) — removes *everyone's* reactions on the deleted user's memo tree.
  - line 102 `deleteReactionsByCreatorTx` → `DELETE FROM reaction WHERE creator_id = ?` (`store/db/sqlite/user_delete.go:400-403`) — removes the deleted user's own reactions on other people's memos.
- Identical structure in the other two dialects: `store/db/postgres/user_delete.go:96,102,380-401` and `store/db/mysql/user_delete.go:96,102,417-438`.

Both deletes are inside the same `BeginTx`/`Commit` as the user row removal (`store/db/sqlite/user_delete.go:29-59`), so the cleanup is atomic with the deletion.

## Why it is not database-level

The `reaction` table carries no foreign key at all — `creator_id INTEGER NOT NULL` with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint:

- `store/migration/sqlite/LATEST.sql:92-99`
- `store/migration/postgres/LATEST.sql:91-98`
- `store/migration/mysql/LATEST.sql:91-98`
- original creation: `store/migration/{sqlite,postgres,mysql}/0.20/00__reaction.sql`

Scanning the migration tree for `FOREIGN KEY|REFERENCES|ON DELETE|TRIGGER`, the only recent cascade is `memo_share.memo_id → memo(id) ON DELETE CASCADE` (`store/migration/*/0.27/04__memo_share.sql:11`); no rule touches `reaction`. So without the Go code the rows would simply be orphaned.

## Confirming coverage

`store/test/user_delete_test.go` (`TestDeleteUserCleansRelatedData`) seeds three reactions — a peer reacting to the doomed user's memo (:97), the doomed user reacting to a peer memo (:103), and a peer→peer-memo reaction that must survive (:109) — then asserts only the third remains (`:217-220`). That pins both delete passes and the non-over-deletion boundary.
