**Premise correction: there is no nightly database-cleanup job in this repository.** No cron job of any kind is registered at runtime.

What actually exists:

1. **`internal/scheduler/` is an unwired library, not an active scheduler.** It's a standalone cron-job package (`internal/scheduler/scheduler.go:70` defines `Register`, `internal/scheduler/parser.go:30` defines `ParseCronExpression`), described in `internal/scheduler/README.md:3` as "a production-ready, GitHub Actions-inspired cron job scheduler for Go." The code graph returns a **certified zero** for callers of `Scheduler.Register` — every `Register`/`scheduler.New` call site is inside the package's own tests and docs (`internal/scheduler/example_test.go`, `integration_test.go`, `job_test.go`, `doc.go`). A grep of the entire `server/` tree (126 files) for `scheduler.` returns no matches, so the server never constructs a scheduler.

2. **The "2 AM cleanup" you may be thinking of is illustrative example text.** The `0 2 * * *` schedule appears only in documentation and examples: `internal/scheduler/README.md:34-35` (`"daily-cleanup"`, `// 2 AM daily`), `internal/scheduler/doc.go:14-16`, and `internal/scheduler/example_test.go:98-106` (a job named `"cleanup"` that prints "Cleaning up old data..."). None of these touch the database — the example handler just writes to stdout.

3. **The only real background job is not cron-driven.** `server/server.go:153-174` (`startBackgroundRunners`) starts exactly one runner: the S3 presign runner (`server/runner/s3presign/runner.go`). It runs on a plain ticker interval of 12 hours, not a cron expression (`server/runner/s3presign/runner.go:26-30`), plus one immediate `RunOnce` at startup.

So if you're looking for scheduled database maintenance, it isn't implemented — you'd be adding the first real consumer of `internal/scheduler`, wiring it into `startBackgroundRunners` in `server/server.go`.
