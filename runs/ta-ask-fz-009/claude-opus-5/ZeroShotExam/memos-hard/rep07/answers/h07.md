**Two side-hops worth knowing, since this is "another user's" profile image:**

1. **Authorization is instance-wide, not per-user.** There is no ownership or visibility check on the target user. The only gate is anonymity: if `Profile.AllowAnonymous()` (`internal/profile/profile.go:46`) is false — i.e. no `InstanceURL` configured — the handler requires *any* authenticated viewer via `getCurrentUser` (`fileserver.go:708`) → `Authenticator.AuthenticateToUser` (`server/auth/authenticator.go:190`) → its own `Store.GetUser`. Once any valid session exists, every user's avatar is readable. On a public instance the endpoint is fully anonymous.
2. **Lookup is by username, and it bypasses the cache.** `getUserByUsername` passes `FindUser{Username: &identifier}`, but the `userCache` fast path in `Store.GetUser` (`store/user.go:149-156`) only triggers when `find.ID != nil`. So every avatar request falls through to a real `ListUsers` SQL query, then populates the cache by ID on the way out (`store/user.go:167`) — a cache that this route can never subsequently hit.
