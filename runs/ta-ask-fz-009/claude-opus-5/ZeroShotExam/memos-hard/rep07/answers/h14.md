**Computation site** — `memopayload.RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`, which delegates the actual parsing to the goldmark markdown service: `(*service).ExtractAll` in `internal/markdown/markdown.go:356-422`. `RebuildMemoPayload` writes the result onto the memo's stored payload (`memo.Payload.Tags`, `memo.Payload.Property`, runner.go:85-86) — the payload is persisted in the memo row (`store.UpdateMemo.Payload`, `store/memo.go:102`), not recomputed per read.

**Triggers** (all three callers, verified via the call graph):
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check, before the store write.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but **only** when the update mask contains `content` (the `path == "content"` branch, lines 436-451); other mask paths (`visibility`, `pinned`, `location`, `attachments`, `relations`) do not recompute it. The rebuilt payload is attached via `update.Payload = memo.Payload` (line 451).
- `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:27-72`, a batched (100 at a time) full-table backfill that rebuilds every memo's payload. Note: the graph reports a **certified zero** for callers of `RunOnce`, and grepping all Go sources for `memopayload` finds only `memo_service.go` and the runner file itself — so this backfill path is currently not wired into server startup; it's dormant migration machinery.

**Extracted properties** (one AST walk, `internal/markdown/markdown.go:371-421`):
- `Tags` — every `#tag` node, deduplicated with case preserved (`uniquePreserveCase`, line 418).
- `Property.Title` — text of the first block-level child of the document if it is an H1 heading (lines 384-389; declared in `proto/store/memo.proto:20-21`).
- `Property.HasLink` — any link node (line 394).
- `Property.HasCode` — code block, fenced code block, or inline code span (lines 396-397).
- `Property.HasTaskList` — any task checkbox (line 400).
- `Property.HasIncompleteTasks` — any unchecked task checkbox (lines 401-405).
- `Mentions` are also extracted by `ExtractAll` (line 380) but are *not* copied into the payload — `RebuildMemoPayload` only takes `Tags` and `Property`; mentions are consumed separately at `server/router/api/v1/memo_mention_helpers.go:32`.

These derived fields surface to clients through `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315-325`) and `memoMessage.Tags` (line 48), and back the CEL filter schema (`has_link` / `has_task_list` / `has_code` / `has_incomplete_tasks`, `internal/filter/schema.go:219-245`) plus the user stats rollups (`server/router/api/v1/user_service_stats.go:137-152`).

One adjacent derivation worth distinguishing: the memo **snippet** (`Memo.snippet`, output-only) is *not* stored — it is generated on every read by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-88`, called from `memo_service_converter.go:76-80` and for relation previews at lines 224-252).
