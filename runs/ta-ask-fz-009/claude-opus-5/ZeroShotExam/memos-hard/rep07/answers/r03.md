A search for `internal/scheduler` across all Go files returns no production import, and the code graph reports a **certified zero** callers for `Register` — nothing in the server wires this package up.

That is a usage sample in a README's `main()` snippet — it registers a handler that prints `"Running cleanup..."`, not a database job.

3. **The real background work is interval-based, not cron-based, and none of it is a nightly DB cleanup.** `server/server.go:153-174` (`startBackgroundRunners`) starts exactly one runner: the S3 presign refresher, on a plain ticker every 12 hours (`server/runner/s3presign/runner.go:26-30`). The only other recurring sweep is the in-memory cache janitor at a 5-minute interval (`store/cache/cache.go:201`, configured at `store/store.go:42`) — that evicts cache entries, not database rows.

So if you were expecting a nightly DB-cleanup cron entry, the closest thing is a README example. Adding one would mean instantiating `scheduler.New()` inside `startBackgroundRunners` in `server/server.go`, which currently has no scheduler at all.
