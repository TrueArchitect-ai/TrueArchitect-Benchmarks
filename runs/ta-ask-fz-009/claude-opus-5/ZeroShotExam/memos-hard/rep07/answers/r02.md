**Premise correction: there is no per-user API rate-limiting middleware in this repo.** Nothing registers one, so there are no per-user request limits to report.

What I verified:

- The graph's fuzzy search for `rate limit` and `ratelimit` returned a **certified miss** across all 7,293 indexed symbols (identifier, qname, abbreviation and doc-text tiers all probed), and `[ArchMap query]` returned only unrelated markdown-editor `delimiter` symbols.
- The Echo middleware stack is only two entries: `middleware.Recover()` and `newCORSMiddleware(profile)` — `server/server.go:51-52`.
- The Connect interceptor chain is four entries, none of them a limiter: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` — `server/router/api/v1/v1.go:133-138`, defined in `server/router/api/v1/connect_interceptors.go`.
- `golang.org/x/time` (the usual `rate.Limiter` source) is present in `go.mod:151` only as an **indirect** dependency — nothing in the tree imports it.

What does exist, and is probably what the question is reaching for — all of it **global, not per-user**:

| Control | Value | Location |
|---|---|---|
| Request body size cap (gateway + Connect) | `256 << 20` bytes | `server/router/api/v1/v1.go:20`, applied at `:126`, `:141`, `:144` |
| Concurrent image/EXIF processing slots | 2 | `server/router/api/v1/v1.go:60`, acquired in `attachment_service_image.go:67` |
| Concurrent thumbnail generations (API service) | 3 | `server/router/api/v1/v1.go:59` |
| Concurrent thumbnail generations (file server) | 3 | `server/router/fileserver/fileserver.go:46`, `:116` |

These are **concurrency semaphores**, not rate limits: they bound how many requests are in flight simultaneously, with no per-caller identity and no time window. When the image semaphore can't be acquired the caller gets `ResourceExhausted` ("too many image processing requests", `server/router/api/v1/attachment_service.go:158-161`), which is the only limit-shaped rejection in the API surface.

One more place the phrase appears, to rule it out: `internal/email/README.md:286-295` and `internal/email/doc.go:86` discuss rate-limiting email sends as a **suggested future enhancement** with example `rate.NewLimiter` code — documentation, not registered middleware.
