**Premise correction: there is no GraphQL schema in this repository.** A fuzzy search over all 7,293 indexed symbols returned a certified miss for "graphql," a content grep for the string matched nothing across 1,042 files, and there are no `.graphql`/`.gql`/`.graphqls` files anywhere in the tree. Memos does not expose a GraphQL API.

**The actual API surface: gRPC + Protobuf, with a REST/JSON gateway.**

The contract of record is the `.proto` service definitions in `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto`

These are the hand-written source of truth. Generated Go lands in `proto/gen/api/v1/`, including grpc-gateway shims (`*.pb.gw.go`) that project each RPC onto an HTTP verb + path via `google.api.http` annotations. The resulting public HTTP surface is `/api/v1/...` in Google AIP resource style, e.g.:

- `GET /api/v1/memos`, `POST /api/v1/memos`, `GET|PATCH|DELETE /api/v1/{name=memos/*}` — `proto/gen/api/v1/memo_service.pb.gw.go:1745`
- `GET /api/v1/users`, `PATCH /api/v1/{user.name=users/*}`, `POST /api/v1/users:batchGet` — `proto/gen/api/v1/user_service.pb.gw.go:2301`
- `POST /api/v1/auth/signin`, `GET /api/v1/auth/me` — `proto/gen/api/v1/auth_service.pb.gw.go:331`
- Plus custom-method suffixes (`:batchGet`, `:getStats`, `:transcribe`) rather than GraphQL-style single-endpoint querying.

Hand-written HTTP routes outside the gateway are the non-RPC edges:

- `GET /api/v1/sse` — `server/router/api/v1/sse_handler.go:25`
- File serving: `GET /attachments/:uid/:filename`, `GET /users/:identifier/avatar` — `server/router/fileserver/fileserver.go:132,168`
- RSS: `GET /explore/rss.xml`, `GET /u/:username/rss.xml` — `server/router/rss/rss.go:72,111`
- Frontend/meta: `/robots.txt`, `/sitemap.xml` — `server/router/frontend/frontend.go:128,143`; `GET /healthz` — `server/server.go:44`

So if you're looking for "the schema" — the place to edit when changing the public API — it's the `.proto` files in `proto/api/v1/`, then regenerate into `proto/gen/api/v1/`. The frontend consumes the same protos via generated TypeScript clients rather than issuing GraphQL documents.
