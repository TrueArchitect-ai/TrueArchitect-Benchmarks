I'll start by locating the identity-provider abstraction in the code graph.

h03. `internal/idp` (abstraction); `internal/idp/oauth2` (implementation)

**Abstraction — `internal/idp/idp.go`**
The package is deliberately thin: it defines only the provider-neutral contract type `IdentityProviderUserInfo` with `Identifier`, `DisplayName`, `Email`, `AvatarURL` (`internal/idp/idp.go:3-8`). That struct is the boundary — the normalized shape any provider must produce, decoupling user provisioning from whatever wire protocol the IdP speaks.

**Implementation — `internal/idp/oauth2/oauth2.go`**
OAuth2 is the only concrete protocol that ships. `internal/idp` contains exactly one subpackage (`oauth2`), no others:
- `oauth2.IdentityProvider` wraps a `storepb.OAuth2Config` (`internal/idp/oauth2/oauth2.go:20-22`)
- `NewIdentityProvider` validates required config fields — `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, `fieldMapping.identifier` (`internal/idp/oauth2/oauth2.go:27-43`)
- `ExchangeToken` does the authorization-code exchange via `golang.org/x/oauth2`, with optional PKCE `code_verifier` (`internal/idp/oauth2/oauth2.go:47-80`)
- `UserInfo` calls the userinfo endpoint and maps raw claims into `idp.IdentityProviderUserInfo` through the configured `FieldMapping` (`internal/idp/oauth2/oauth2.go:83-142`)

**Note on the shape of the abstraction:** there is no Go `interface` for providers — the seam is the shared user-info struct plus a per-provider package, and the store enum drives selection. The scope docs confirm OAuth2 is the only supported type: provisioning validation "supports only OAuth2 providers" (`docs/configuration-provisioning.md:152`), with `"type": "OAUTH2"` in the config example (`docs/configuration-provisioning.md:131`), and the SSO plan explicitly lists "Supporting IdP types other than `OAUTH2`" as a non-goal (`docs/plans/2026-04-21-sso-user-identity-linkage/definition.md:47`). So adding SAML or native OIDC would mean a new sibling package under `internal/idp/`, not a new implementation of an existing interface.
