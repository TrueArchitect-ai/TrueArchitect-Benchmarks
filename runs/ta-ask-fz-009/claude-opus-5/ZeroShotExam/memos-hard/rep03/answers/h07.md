h07.

The browser never fetches raw avatar bytes from the user API — the API returns a URL (`/file/{user.name}/avatar`), and the browser then hits the Echo fileserver route, which reads the avatar out of the `user` row.

**Hop chain (avatar image request):**

1. `FileServerService.RegisterRoutes` (`GET /file/users/:identifier/avatar`) — `server/router/fileserver/fileserver.go:121-125`
2. `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168` (serving handler; ends with `c.Blob(...)` at :209)
3. `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715`
4. `Store.GetUser` (checks `userCache`, else delegates) — `store/user.go:148`
5. `Store.ListUsers` — `store/user.go:136`
6. `Driver.ListUsers` (interface) — `store/driver.go`; implementations: `store/db/sqlite/user.go:88`, `store/db/postgres/user.go`, `store/db/mysql/user.go`
7. `user` table — column `avatar_url`, scanned at `store/db/sqlite/user.go:76`; schema in `store/migration/{sqlite,postgres,mysql}`

**Supporting hops:**

- Where the URL comes from: `convertUserFromStore` — `server/router/api/v1/user_service_converters.go:16`, which rewrites `AvatarUrl` to `/file/users/{username}/avatar` when the stored value is a base64 data URI (`:32-39`). So the stored data is a data URI in the `user.avatar_url` column, not a blob in the attachment store; `parseDataURI` decodes it at `fileserver.go:196` and the MIME type is allow-listed via `avatarAllowedTypes` (`:201`).
- Auth side-branch: on a private instance (`!s.Profile.AllowAnonymous()`), `serveUserAvatar` calls `FileServerService.getCurrentUser` (`fileserver.go:708`) → `auth.Authenticator.AuthenticateToUser` (`server/auth/authenticator.go:190`) → `Store.GetUser` / `Store.GetUserByPATHash` (`store/user.go:148`, `store/user_setting.go:128`). Note this is only an authentication gate — there is no per-user authorization check on *whose* avatar you read, so any authenticated viewer (or anyone, on a public instance) can fetch another user's avatar.
- Wiring: the service is constructed and mounted before the gRPC-Gateway in `server/server.go:81-82`.
