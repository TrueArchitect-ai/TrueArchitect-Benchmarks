Memo visibility is enforced at these distinct server-side sites (no single chokepoint — each surface re-implements the rule):

**Core gRPC/Connect API**

- `checkMemoReadAccess` — the shared per-memo read gate (GetMemo, comment/parent lookups) — `server/router/api/v1/memo_service.go:39-68` (callers at `memo_service.go:356`, `:367`, `memo_service_comments.go:148`)
- `ListMemos` query-scoping — anonymous ⇒ `VisibilityList = [PUBLIC]`; authenticated ⇒ CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`, or `[PUBLIC, PROTECTED]` for another creator's list — `server/router/api/v1/memo_service.go:218-227`
- `ListMemoReactions` inline visibility check — `server/router/api/v1/reaction_service.go:29-41`; `UpsertMemoReaction` at `:83` and `DeleteMemoReaction` path at `:38` reuse the same predicate
- `ListMemoAttachments` inline visibility check — `server/router/api/v1/memo_attachment_service.go:213-225`
- `checkAttachmentAccess` (attachment reads inherit the linked memo's visibility) — `server/router/api/v1/attachment_service.go:422-455`
- `ListMemoComments` / comment creation: private-parent gate — `server/router/api/v1/memo_service_comments.go:41`, and comment-visibility rule at `:100`
- Share-token bypass surface: `GetMemoByShare` deliberately grants read on a valid, non-expired token regardless of visibility (archived treated as not found) — `server/router/api/v1/memo_share_service.go:151-192`

**Non-gRPC HTTP surfaces**

- File server attachment permission check (public + anonymous allowed ⇒ open; else share token or authenticated user; private ⇒ creator/admin only) — `server/router/fileserver/fileserver.go:650-703` (visibility branches at `:677`, `:699`)
- RSS feeds — hard-scoped to `VisibilityList = [store.Public]` — `server/router/rss/rss.go:90` (instance feed) and `:141` (user feed)
- Sitemap generation in the frontend router — `VisibilityList = [store.Public]` — `server/router/frontend/frontend.go:150`

**Push / notification delivery**

- SSE fan-out filter `SSEClient.canReceive` — private events only to creator or admin; unknown visibility denied — `server/router/api/v1/sse_hub.go:134-144` (event's visibility stamped in `server/router/api/v1/sse_event_helpers.go:29-37`)
- Email notification gate `canViewerAccessMemo` — private ⇒ creator, protected ⇒ any authenticated viewer, admin bypass — `server/notification/email.go:306-320`
- Mention-notification eligibility (private memos don't notify non-creators) — `server/router/api/v1/memo_mention_helpers.go:62`, `:67`, `:84`

Note the divergence worth flagging: `checkMemoReadAccess` (`memo_service.go:63`) does **not** grant admins access to private memos, while the reaction, attachment, file-server, SSE and email paths all include an admin/super-user bypass (`isSuperUser(user)` / `store.RoleAdmin`). Same invariant, four different admin semantics.
