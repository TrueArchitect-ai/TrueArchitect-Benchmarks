How it works:

- **What it keeps fresh.** S3-backed attachments store their public link as a presigned URL in `attachment.reference`, which expires — the presign is issued with a 5-day expiration (`internal/storage/s3/s3.go:77`). Without periodic renewal those references would go stale.
- **The component.** `Runner` holds only a `*store.Store` (`server/runner/s3presign/runner.go:16-24`). `CheckAndPresign` pages through attachments filtered to `AttachmentStorageType_S3` in batches of 100 (`runner.go:55-65`), and for each one re-presigns via `s3Client.PresignGetObject` (`runner.go:108`), then writes back both the new `Reference` and an updated `LastPresignedTime` in the payload (`runner.go:114-120`).
- **The schedule.** `const runnerInterval = time.Hour * 12` (`runner.go:27`), driven by a `time.Ticker` in `Run`, which exits on `ctx.Done()` (`runner.go:29-41`). There's a second, finer-grained guard inside the loop: an attachment is skipped if its last presign was under 4 days ago, leaving a 1-day safety margin against the 5-day expiry (`runner.go:85-91`). So the 12-hour tick is the polling cadence; the effective renewal cadence per attachment is ~4 days.
- **The wiring.** `Server.Start` calls `s.startBackgroundRunners(ctx)` (`server/server.go:129`). That function builds the runner (`server.go:162`), does an immediate blocking `RunOnce(ctx)` so links are valid right after boot (`server.go:163`), then launches `Run(s3Context)` on a goroutine tracked by `backgroundRunnerWG` (`server.go:166-171`). The runner gets its own cancelable child context whose cancel func is registered in `s.backgroundRunnerCancels` (`server.go:156-159`), so `Shutdown` can stop it via `stopBackgroundRunners` and then join it with `waitBackgroundRunners` (`server.go:140-143`).
