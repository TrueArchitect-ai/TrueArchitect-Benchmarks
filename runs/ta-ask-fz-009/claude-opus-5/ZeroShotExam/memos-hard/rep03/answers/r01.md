**r01.**

**Premise correction:** there is no Redis anywhere in this repository — no client dependency in `go.mod`, and a full-tree text search for "redis" (case-insensitive, 1042 files) returns zero matches. There is no external cache server, no connection string, no cache host/port config knob.

**Actual mechanism — in-process, in-memory cache:**

- **Implementation:** `store/cache/cache.go` — `cache.Cache` (line 67) is a thread-safe in-memory cache built on `sync.Map` plus an `atomic.Int64` item counter, satisfying `cache.Interface` (line 11). Expiry is per-entry (`item.expiration`, line 37), enforced lazily on `Get` (line 135) and by a background `cleanupLoop` goroutine (line 200) on a ticker.
- **Where it's "configured":** `store.New` in `store/store.go:40-45` constructs a single `cache.Config` literal and hands the same config to three separate cache instances: `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`, declared at lines 27-29). The values are `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, `OnEviction: nil`. These are hardcoded literals — not read from env, flags, or profile. `cache.DefaultConfig()` (`store/cache/cache.go:57`) carries the identical values but is a separate path.
- **TTL for user entries:** **10 minutes**, inherited from that `DefaultTTL`. All user writes go through `s.userCache.Set(...)` (`store/user.go:98, 122, 132, 143, 167`), which delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). No user-specific TTL override exists — `SetWithTTL` is only called directly in tests (`store/cache/cache_test.go:26`). Reads hit the cache only in `GetUser` when looked up by ID (`store/user.go:150`); other find predicates bypass it.
- **Secondary eviction pressure:** entries can die before 10 minutes. Once `itemCount` exceeds `MaxItems` (1000), `cleanupOldest` (`store/cache/cache.go:253`) drops roughly 20% of capacity, so a busy instance evicts users on capacity, not just TTL. Invalidation on delete is explicit via `deleteUserCache` (`store/user_delete.go:39-40`).

Practical consequence for architecture: because the cache lives in the process (goroutine + `sync.Map`, torn down in `Store.Close` at `store/store.go:72-76`), it is **not** shared across replicas. Two memos instances behind a load balancer would each hold their own user entries with independent 10-minute windows, and a delete on one node does not invalidate the other.
