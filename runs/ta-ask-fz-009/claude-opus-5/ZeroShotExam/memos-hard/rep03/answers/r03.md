r03. **Premise correction: there is no nightly database-cleanup job in this repo, and no cron scheduler is wired into the running server at all.**

What actually exists:

- `internal/scheduler/` is a **standalone, unused library** — a cron engine (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) with a README describing itself as "a production-ready, GitHub Actions-inspired cron job scheduler for Go" (`internal/scheduler/README.md:1-3`). The only files importing `github.com/usememos/memos/internal/scheduler` are its own tests and its README (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). The code graph returns a **certified zero for callers of `Register`**, i.e. nothing in the app ever registers a job.

- The `"0 2 * * *"` / "2 AM daily" schedule you may be thinking of is **documentation and example code only**, not a live job:
  - `internal/scheduler/README.md:34-37` — `Name: "daily-cleanup"`, `Schedule: "0 2 * * *"`, handler prints `"Running cleanup..."`
  - `internal/scheduler/doc.go:14-16` — same snippet in the package doc
  - `internal/scheduler/example_test.go:97-106` — `Example_multipleJobs`, job named `"cleanup"` at `"0 2 * * *"`, handler prints `"Cleaning up old data..."`

- Actual background work in the server uses plain tickers, not cron, and none of it is database cleanup:
  - `server/server.go:153-174` — `startBackgroundRunners` starts exactly one long-running runner, the S3 presign runner.
  - `server/runner/s3presign/runner.go:27-30` — `runnerInterval = time.Hour * 12`, driven by `time.NewTicker`, refreshing presigned S3 URLs.
  - `server/runner/memopayload/runner.go:27` — `RunOnce` only, rebuilds memo payloads; no schedule.
  - The nearest thing to periodic pruning is the in-memory store cache, `CleanupInterval: 5 * time.Minute` (`store/cache/cache.go:46-60`, `store/store.go:42`) — cache eviction, not a database job.

So the honest answer is: nothing is scheduled to run nightly. If you need that behavior, `internal/scheduler` is the ready-made mechanism, but it would have to be instantiated and registered from `startBackgroundRunners` in `server/server.go:153`.
