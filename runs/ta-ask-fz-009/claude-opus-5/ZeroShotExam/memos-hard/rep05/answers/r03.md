**Premise correction: there is no nightly database-cleanup job in this repo, and no cron scheduler running in production — so there is no scheduled time to report.**

What actually exists:

1. **A cron scheduler *library*, wired to nothing.** `internal/scheduler/` is a self-contained cron package (`scheduler.New`, `Scheduler.Register` at `internal/scheduler/scheduler.go:70`, cron parsing at `internal/scheduler/parser.go:30`). Every caller of `scheduler.New()` / `Register()` lives inside the package's own tests and docs — `internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`, `internal/scheduler/doc.go`. Searching Go sources for `internal/scheduler` imports finds only those in-package files; the code graph returns a certified zero for callers of `scheduler.New` on the server side.

2. **The "2 AM cleanup" you may be remembering is documentation sample code, not a job.** `internal/scheduler/README.md:34-37` and `internal/scheduler/doc.go:14-16` show `Name: "daily-cleanup", Schedule: "0 2 * * *" // 2 AM daily` as the package's usage example, and `internal/scheduler/example_test.go:97-106` registers a `"cleanup"` job with `"0 2 * * *"` inside `Example_multipleJobs`. None of those touch the database — the example handler just prints.

3. **Real background work uses plain goroutines, not cron.** `server/server.go:153-174` (`startBackgroundRunners`) starts exactly one recurring runner: `s3presign.NewRunner(s.Store)` (`server/runner/s3presign/runner.go:16-47`), a loop-based S3 URL re-presigner. The other runner, `server/runner/memopayload/runner.go:27`, exposes only `RunOnce`. Neither is a cleanup job, and neither is cron-scheduled.

If you want a nightly DB cleanup, the pieces are there — you'd register a job against `internal/scheduler` from `startBackgroundRunners` in `server/server.go`, which is currently the only place background work is started.
