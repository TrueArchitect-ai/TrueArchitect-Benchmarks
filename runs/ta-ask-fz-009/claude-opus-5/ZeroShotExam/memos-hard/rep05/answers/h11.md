## What the shape means

`User` is the identity spine — it's the only entity that crosses into the authentication boundary (`server/auth`), which is why its breadth matches `Memo` while its coupling weight is roughly double. `Memo` compensates with reach into presentation and background processing (`server/router/frontend`, `server/runner/memopayload`) that `User` doesn't touch. In both cases `server/router/api/v1` dominates, so the API layer is where store entities leak outward most.

Two caveats on the numbers: the graph flags `~writes/~reads` edges as a **lower bound** because SQL assembled by string concatenation isn't captured, and it carries no `overrides`/`event`/`route` edges — so these counts are floors, not exact totals. The `store/db/{mysql,postgres,sqlite}` hits I excluded are dialect drivers inside the data layer, and table rows are triplicated across the three schema files by design.
