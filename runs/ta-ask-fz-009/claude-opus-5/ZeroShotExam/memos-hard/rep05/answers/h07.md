h07.

The avatar is not a file on disk or in object storage — it's a base64 data URI stored in the `user.avatar_url` column, and the fileserver decodes it on each request.

**Where the browser gets the URL** (not a serving hop, but the origin of the request): `convertUserFromStore` rewrites base64 avatars into a proxy URL `/file/{users/username}/avatar` — `server/router/api/v1/user_service_converters.go:33-38`.

**The serving chain (GET /file/users/:identifier/avatar):**

- `FileServerService.RegisterRoutes` (route binding) — `server/router/fileserver/fileserver.go:124`
- `FileServerService.serveUserAvatar` (handler) — `server/router/fileserver/fileserver.go:168`
- `FileServerService.getCurrentUser` → `auth.Authenticator.AuthenticateToUser` (only when `!s.Profile.AllowAnonymous()`) — `server/router/fileserver/fileserver.go:708` → `server/auth/authenticator.go:190`
- `FileServerService.getUserByUsername` (builds `store.FindUser{Username}`) — `server/router/fileserver/fileserver.go:715`
- `store.Store.GetUser` (user cache checked only for ID lookups, so a username lookup falls through) — `store/user.go:148`
- `store.Store.ListUsers` (populates `userCache`) — `store/user.go:136`
- `store.Driver.ListUsers` (interface, dialect dispatch) — `store/driver.go:47`
- `DB.ListUsers` — `store/db/sqlite/user.go:88` (`SELECT … avatar_url … FROM user`, columns at :159-164); parallel impls at `store/db/mysql/user.go` and `store/db/postgres/user.go`

**Back out through the handler:** `FileServerService.parseDataURI` decodes `user.AvatarURL` into MIME type + bytes (`server/router/fileserver/fileserver.go:737`), the type is checked against `avatarAllowedTypes`, then `setSecurityHeaders` + `Cache-Control` and `c.Blob(...)` write the bytes (`fileserver.go:196-209`).

Two notes on the boundary: another user's avatar is readable by anyone when the instance allows anonymous access (`s.Profile.AllowAnonymous()`, `fileserver.go:173`) — there is no per-user authorization beyond that gate, unlike attachments which go through `checkAttachmentPermission` (`fileserver.go:149`). And lookup is username-only now (`getUserByUsername`, `fileserver.go:715`), matching the migration described in `docs/plans/2026-03-24-user-resource-identifiers/plan.md:66`.
