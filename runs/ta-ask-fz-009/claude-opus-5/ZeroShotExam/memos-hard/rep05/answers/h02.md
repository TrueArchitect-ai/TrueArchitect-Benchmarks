Details that matter:

- **Execution path.** Callers don't call `Post` directly on the request path — they enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which pushes onto a bounded 128-slot channel (`asyncPostQueue`, line 39) drained by 4 goroutines started in `init()` (lines 42-55). Each worker calls `Post`, so the network write happens off-request, and overflow is dropped with a warning rather than blocking (lines 189-195).

- **Two layers of SSRF defense.**
  1. *Admission-time:* `ValidateURL` (`internal/webhook/validate.go:62-83`) rejects non-absolute URLs, non-http/https schemes, unresolvable hostnames, and hostnames resolving into reserved ranges — used when webhooks are created/updated.
  2. *Dial-time:* `safeDialContext` is installed as the shared client's `Transport.DialContext` (`internal/webhook/webhook.go:32-37`). It re-resolves the host at connect time and refuses the dial if any returned address is reserved. This is the load-bearing one — the code comment notes it "also defeats DNS rebinding attacks," which the admission-time check alone cannot, since a hostname can point elsewhere between validation and delivery.

- **Blocked ranges:** IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (explicitly covering cloud IMDS at 169.254.169.254), plus IPv6 loopback, unique-local, and link-local (`internal/webhook/validate.go:14-23`), parsed once at startup.

- **Documented escape hatch.** `AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers at once. It's wired to the `--allow-private-webhooks` CLI flag in `cmd/memos/main.go:133`, bound through viper at `cmd/memos/main.go:160` and assigned at `cmd/memos/main.go:49` — intended for self-hosted setups targeting LAN services.
