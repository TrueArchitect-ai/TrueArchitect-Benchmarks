**Computation site** — `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`. It delegates the actual work to the markdown service's single-pass AST walk, `(*service).ExtractAll` in `internal/markdown/markdown.go:355-422`, and writes the result onto the memo's stored payload:

```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```
(`runner.go:85-86`)

The payload shape it fills is `storepb.MemoPayload_Property` — commented in the generated code as "The calculated properties from the memo content" (`proto/gen/store/memo.pb.go:84-95`); the API mirror is `OUTPUT_ONLY` (`proto/api/v1/memo_service.proto:255-256, 271-277`).

**Triggers** — three call sites, all confirmed:
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before `Store.CreateMemo` (so comments get it too, since `CreateMemoComment` routes through `CreateMemo` at `server/router/api/v1/memo_service_comments.go:56`).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `path == "content"` branch of the update-mask loop; the recomputed payload is then attached via `update.Payload = memo.Payload` (`:450-451`). Other mask paths (visibility, location, attachments) do not recompute — `location` mutates the existing payload in place (`:482-484`).
- `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:27-72`, a backfill that pages all memos in batches of 100 and rewrites each payload. Note: the code graph returns a certified zero for callers of both `RunOnce` and `NewRunner`, and `grep` for `memopayload` finds only `memo_service.go` and the runner file itself — so this backfill path is currently not wired into server startup (contrast `s3presign.NewRunner(...)` / `RunOnce(ctx)` at `server/server.go:162-163`).

**Extracted properties** — from one `gast.Walk` over the parsed AST (`internal/markdown/markdown.go:371-411`):
- `Tags` — every memo-tag node, deduplicated preserving case (`:376-378, 418`)
- `Property.Title` — text of the first block-level child of the document if it is an H1 heading (`:383-389`)
- `Property.HasLink` — any `KindLink` node (`:393-394`)
- `Property.HasCode` — any code block, fenced code block, or inline code span (`:396-397`)
- `Property.HasTaskList` — any task checkbox (`:399-400`)
- `Property.HasIncompleteTasks` — any unchecked task checkbox (`:401-405`)

`ExtractedData.Mentions` is also produced in the same pass (`:379-381`) but is **not** persisted into the payload — it's consumed separately for mention notifications (`server/router/api/v1/memo_mention_helpers.go:32`).

One derived field worth separating: the list/preview **snippet** is *not* stored in the payload. It's computed per-response at conversion time via `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-89`), called from `convertMemoFromStore` (`server/router/api/v1/memo_service_converter.go:76-80`) and for relation previews in `batchConvertMemoRelations` (`:225, 248`). `GenerateSnippet` (`internal/markdown/markdown.go:264+`) flattens the AST to plain text, skipping fenced/indented code blocks.
