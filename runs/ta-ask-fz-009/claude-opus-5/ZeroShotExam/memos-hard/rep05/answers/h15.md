I'll map memo visibility enforcement across the server surfaces.

h15.

Memo visibility is enforced at many separate points — there is no single chokepoint. Distinct enforcement sites:

**Core gRPC read gate**
- `checkMemoReadAccess` (single-memo read: GetMemo, parent memo, ListMemoComments) — `server/router/api/v1/memo_service.go:39-68` (call sites :356, :367 and `server/router/api/v1/memo_service_comments.go:148`)
- ListMemos query-level filtering (`VisibilityList` / `visibility in ["PUBLIC","PROTECTED"]` filter) — `server/router/api/v1/memo_service.go:218-227`
- User-stats memo listing (same visibility narrowing, two places) — `server/router/api/v1/user_service_stats.go:83-92` and `:218-220`

**Sibling gRPC services that re-implement the rule inline instead of calling the gate**
- Attachment read access derived from memo visibility — `server/router/api/v1/attachment_service.go:422-455` (`checkAttachmentAccess`)
- ListMemoAttachments own inline check — `server/router/api/v1/memo_attachment_service.go:213-225`
- Reaction list/create — `server/router/api/v1/reaction_service.go:30-40` and `:83`
- Comment creation against parent memo — `server/router/api/v1/memo_service_comments.go:41`

**Non-gRPC HTTP surfaces**
- File server attachment serving (echo handler, plus anonymous-instance and share-token branches) — `server/router/fileserver/fileserver.go:650-700`
- RSS feeds (public-only find) — `server/router/rss/rss.go:90` and `:141`
- Sitemap XML (public-only find) — `server/router/frontend/frontend.go:149-151`

**Push / notification surfaces**
- SSE delivery filtering per connected client — `server/router/api/v1/sse_hub.go:134-144` (`canReceive`, applied in `Broadcast` :123)
- Inbox/notification viewer check — `canViewerAccessMemo`, `server/router/api/v1/user_service_notifications.go:302-316`
- Email notification viewer check (duplicate of the above, admin test differs: raw `RoleAdmin` vs `isSuperUser`) — `server/notification/email.go:306-320`
- Mention target eligibility — `canUserAccessMentionContext`, `server/router/api/v1/memo_mention_helpers.go:56-72` (used by `shouldSkipMentionInbox` :74-89)

**Deliberate bypass, worth knowing when reasoning about the invariant**
- Share tokens grant read access without any visibility test; only expiry/archived state is checked — `server/router/api/v1/memo_share_service.go:153-197` (`GetMemoByShare`, `getActiveMemoShare`), mirrored in the file server at `server/router/fileserver/fileserver.go:684-689`

The predicate itself (`Private` → creator only, `Protected` → any authenticated user, `Public` → anyone) is copied by hand at each site; `store.Visibility` and its constants are defined in `store/memo.go:13-24`, and the SQL-level `VisibilityList` filter lands in `store/db/{sqlite,mysql,postgres}/memo.go`.
