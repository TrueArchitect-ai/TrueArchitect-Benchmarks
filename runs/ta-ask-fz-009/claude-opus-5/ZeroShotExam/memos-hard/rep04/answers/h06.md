**Convergence function — `webhook.Post`, `internal/webhook/webhook.go:120`.**

Every dispatcher above funnels through `dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook`, which load the per-user rows via `Store.GetUserWebhooks` and set `payload.URL = hook.Url` (memo_service_webhooks.go:41, :67) — that's the user-configured URL. They then call `webhook.PostAsync` (webhook.go:184), which only enqueues onto `asyncPostQueue`; the four worker goroutines started in `init` (webhook.go:42–55) call `Post`, and `Post` is the sole place the outbound request is built and issued: `http.NewRequest("POST", requestPayload.URL, …)` at webhook.go:126 and `safeClient.Do(req)` at webhook.go:152.

Two things worth noting at that chokepoint: HMAC signing (Standard Webhooks `webhook-id`/`-timestamp`/`-signature`) is applied there when a signing secret is set (webhook.go:133–150), and SSRF protection is enforced below it by `safeDialContext` (webhook.go:59), which rejects reserved/private IPs at dial time — so it also covers DNS rebinding. `webhook.Post` is exported, but the map reports its only in-repo caller is that `init` worker loop, so it is effectively the single delivery gate.
