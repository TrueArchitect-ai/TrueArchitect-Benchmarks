**Computation site** — `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`. It ensures `memo.Payload` exists, then delegates the actual parsing to the markdown service: `markdownService.ExtractAll([]byte(memo.Content))` (`internal/markdown/markdown.go:356-422`), and writes back exactly two fields — `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (runner.go:85-86). Everything else in the payload (e.g. `Location`) is user-set and left untouched.

**Triggers** — three call sites, all of them content-write paths:
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`; user-supplied `Location` is layered on afterwards at :112. (Comment creation goes through here too — `CreateMemoComment` calls `s.CreateMemo`, `server/router/api/v1/memo_service_comments.go:56`.)
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `content` field-mask branch; the recomputed payload is assigned to `update.Payload` at :451. Other mask paths (`visibility`, `pinned`, `location`, …) do not recompute — the `location` branch at :482-484 reuses the existing payload as-is.
- Bulk backfill — `memopayload.Runner.RunOnce` (runner.go:27-72) walks all memos in batches of 100 and rebuilds + persists each payload. Note: the code graph reports a **certified zero** callers for `Runner.RunOnce`, and grep for `memopayload` finds no reference in `server/server.go` (only `s3presign.NewRunner`/`RunOnce` is wired there, `server/server.go:162-163`). So the backfill runner exists but is not currently invoked at startup.

**Extracted properties** — from a single AST walk in `ExtractAll`:
- `Tags` — every memo-tag node's text, deduplicated with original case preserved (`markdown.go:376-378, 418`).
- `Property.Title` — text of the document's first block-level child *only if* it is an H1 heading (`markdown.go:384-389`; `proto/store/memo.proto:20-21`).
- `Property.HasLink` — any link node (`markdown.go:393-394`).
- `Property.HasCode` — any code block, fenced code block, or code span (`markdown.go:396-397`).
- `Property.HasTaskList` — any task checkbox present (`markdown.go:399-400`).
- `Property.HasIncompleteTasks` — at least one unchecked checkbox (`markdown.go:401-404`).

`ExtractAll` also returns `Mentions` (`markdown.go:379-381`), but `RebuildMemoPayload` discards it — mentions are resolved separately in `server/router/api/v1/memo_mention_helpers.go:32`. Schema mirrors: `proto/store/memo.proto:12-22`, wire type `MemoPayload_Property` (`proto/gen/store/memo.pb.go:85`), surfaced to the API as `Memo.Property` via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:49`).

One related but distinct derived field: the list `Snippet` is *not* stored in the payload — it's computed per-response by `s.getMemoContentSnippet(memo.Content)` at conversion time (`server/router/api/v1/memo_service_converter.go:76-80`).
