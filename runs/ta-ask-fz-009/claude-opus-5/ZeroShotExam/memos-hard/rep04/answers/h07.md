Two things worth knowing about this path:

- **The image is not a file.** The avatar lives in the `user.avatar_url` column as a base64 data URI; `parseDataURI` (fileserver.go:737) splits MIME type from payload and the handler returns it via `c.Blob` (fileserver.go:209). No attachment/S3/local-disk hop is involved, unlike `serveAttachmentFile` (fileserver.go:132).
- **Authorization is instance-wide, not per-user.** The only gate is `Profile.AllowAnonymous()` (`internal/profile/profile.go:46`) at fileserver.go:173 — on an open instance any browser can fetch any user's avatar; on a private instance any authenticated viewer can fetch any other user's avatar. There is no check relating `viewer` to `user`. MIME type is then constrained by the `avatarAllowedTypes` allowlist (fileserver.go:75) plus `setSecurityHeaders` (fileserver.go:758).
