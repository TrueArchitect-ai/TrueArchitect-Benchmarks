**How the candidate was resolved**

The interface has exactly three implementations — `mysql.DB` (`store/db/mysql/mysql.go:14`), `postgres.DB` (`store/db/postgres/postgres.go:16`), `sqlite.DB` (`store/db/sqlite/sqlite.go:16`) — each with its own `CreateMemo` (`store/db/mysql/memo.go`, `store/db/postgres/memo.go`, `store/db/sqlite/memo.go`). So the call at `store/memo.go:113` is ambiguous on structure alone; the winner is decided by configuration, not by code shape:

- The only place the interface is bound to a concrete type is the factory `NewDBDriver` (`store/db/db.go:14-27`), a `switch profile.Driver` over `"sqlite" | "mysql" | "postgres"`, with `errors.New("unknown db driver")` as the default — i.e. driver selection is entirely data-driven from `profile.Driver`.
- `profile.Driver` is populated from viper at `cmd/memos/main.go:43`, and the default for that key is `"sqlite"` in two places: `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the flag default `rootCmd.PersistentFlags().String("driver", "sqlite", ...)` (`cmd/memos/main.go:130`).
- With no flags, `--dsn` is also empty, and `internal/profile/profile.go:110` fills in the sqlite file DSN under the data dir — confirming the sqlite branch is the one that actually opens a connection.
- The single production wiring site is `db.NewDBDriver(instanceProfile)` → `store.New(dbDriver, instanceProfile)` at `cmd/memos/main.go:57-64`; the other callers of `NewDBDriver` are tests (`store/test/store.go:28`, `server/router/api/v1/test/memo_service_benchmark_test.go:70`), so they don't affect a default install.

Method in short: enumerate implementors of `store.Driver` via the code graph, then follow the one binding site (the factory switch) back to the config key and its default value in `main.go`. The dispatch is invisible at the call site — it resolves only through `profile.Driver == "sqlite"`.
