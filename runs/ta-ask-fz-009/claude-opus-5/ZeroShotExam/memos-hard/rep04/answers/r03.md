**Premise correction: there is no nightly database-cleanup job in this repository, so it has no scheduled time.**

What actually exists:

**1. A cron scheduler library, with zero production jobs registered.** `internal/scheduler/` is a self-contained cron engine (`internal/scheduler/scheduler.go:70` — `Register(job *Job)`, `internal/scheduler/parser.go:30` — `ParseCronExpression`). The map returns a **certified zero** for callers of `Scheduler.Register`, and the only importers of the package are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). Nothing in `server/` or `cmd/` wires it up.

**2. The "0 2 * * *" / "2 AM daily" cleanup you may be thinking of is documentation and example code, not a job:**
- `internal/scheduler/README.md:34-37` — `Name: "daily-cleanup", Schedule: "0 2 * * *", // 2 AM daily`
- `internal/scheduler/doc.go:15-16` — the same snippet in the package doc comment
- `internal/scheduler/example_test.go:97-106` — `Name: "cleanup", Schedule: "0 2 * * *"` inside a runnable `Example_` function whose handler just prints `"Cleaning up old data..."`

None of these touch the database; they're illustrations of the scheduler API.

**3. The real background work is ticker-based, not cron-based, and it isn't cleanup.** `Server.startBackgroundRunners` (`server/server.go:153-174`) starts exactly one recurring runner: the S3 presign runner, on a `time.Ticker` at a fixed 12-hour interval (`server/runner/s3presign/runner.go:26-40`). It re-signs S3 object URLs (`CheckAndPresign`, `server/runner/s3presign/runner.go:47`) — no deletion or pruning. The other runner, `server/runner/memopayload/runner.go:27`, is a one-shot payload rebuild with no schedule at all.

One documentation inconsistency worth flagging: `AGENTS.md:69` lists `internal/` as containing "scheduler, cron, …", but there is no `internal/cron` directory — the scheduler package is the only thing there.
