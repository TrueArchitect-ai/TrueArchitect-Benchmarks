**The actual public API surface is gRPC + protobuf, exposed over HTTP via grpc-gateway.**

Where the contract is defined — the hand-written source of truth:

- `proto/api/v1/*.proto` — nine service definitions: `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `ai_service.proto`, plus shared types in `common.proto`.

Where the HTTP surface is generated from it:

- `proto/gen/api/v1/*.pb.gw.go` — grpc-gateway transcoding. Route patterns live here, e.g. `GET /api/v1/memos` and `POST /api/v1/{name=memos/*}/comments` at `proto/gen/api/v1/memo_service.pb.gw.go:1745`; the user surface at `proto/gen/api/v1/user_service.pb.gw.go:2301`; auth at `proto/gen/api/v1/auth_service.pb.gw.go:331`.

Shape of the surface: **Google AIP-style resource-oriented REST** under `/api/v1`, with resource names as path segments (`memos/*`, `users/*/shortcuts/*`) and custom methods via the colon verb convention (`POST /api/v1/attachments:batchDelete`, `GET /api/v1/{name=users/*}:getStats`, `POST /api/v1/instance/settings:batchGet`). That colon-verb idiom is what people sometimes mistake for a non-REST/graph-style API, but it's plain protobuf `google.api.http` annotation.

Non-generated handlers rounding out the surface:

- `server/router/api/v1/sse_handler.go:25` — `GET /api/v1/sse` (server-sent events, registered manually rather than through the gateway).
- `server/router/fileserver/fileserver.go:132,168` — attachment and avatar serving.
- `server/router/rss/rss.go:72,111` — RSS feeds.
- `server/router/frontend/frontend.go:128,143` — `robots.txt`, `sitemap.xml`.
- `server/server.go:44` — `GET /healthz`.

If you're looking for the file to edit when changing the API, it's the `.proto` under `proto/api/v1/` — the `proto/gen/` tree is generated output and shouldn't be hand-edited.
