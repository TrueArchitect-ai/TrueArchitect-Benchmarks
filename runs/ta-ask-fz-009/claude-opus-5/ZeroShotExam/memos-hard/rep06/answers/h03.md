h03. `internal/idp`; `internal/idp/oauth2`

- `internal/idp/idp.go` is the abstraction package: it declares the provider-neutral `IdentityProviderUserInfo` contract (identifier, display name, email, avatar URL) that any IdP integration must produce — `internal/idp/idp.go:3-8`.
- `internal/idp/oauth2` is the only concrete protocol implementation shipped: `IdentityProvider` wrapping `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (PKCE-capable) and `UserInfo` — `internal/idp/oauth2/oauth2.go:20`, `:27`, `:47`, `:83`. The package doc states it plainly: "Package oauth2 implements the OAuth2 identity provider integration" (`internal/idp/oauth2/oauth2.go:1`).
- Corroborating the single-protocol surface: the stored/API enum for provider type carries only `IdentityProvider_OAUTH2` (`proto/gen/store/idp.pb.go:26`, `proto/gen/api/v1/idp_service.pb.go:29`), and `internal/idp` contains no other implementation subpackage (`internal/idp/` holds only `idp.go` and `oauth2/`).
