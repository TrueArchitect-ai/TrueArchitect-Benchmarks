**Premise correction: neither.** There is no message broker in this repository at all. `go.mod` contains no NATS, RabbitMQ/AMQP, Kafka, Redis, or task-queue client — a grep for `nats|rabbitmq|amqp|streadway|kafka|redis|asynq|machinery` across the module manifests returns zero matches. So there is no queue *declaration* to point at, because there is no broker-managed queue.

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool.**

Everything lives in `internal/webhook/webhook.go`:

- **The "queue"** is a package-level buffered channel, capacity 128:
  `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`
- **The "workers"** are 4 goroutines started in `init()`, each ranging over that channel and calling `Post` — `internal/webhook/webhook.go:42-55`. Failures are logged via `slog.Warn` and dropped; there is no retry, no ack, no dead-letter.
- **The producer** is `PostAsync` — `internal/webhook/webhook.go:184-196`. Note it uses a `select` with a `default` branch: when the buffer is full the payload is **discarded** with a "Dropped webhook dispatch because the async queue is full" warning. Delivery is best-effort, not at-least-once.
- **Actual delivery** is a plain `http.Client.Do` in `Post` — `internal/webhook/webhook.go:120-180`, using a shared `safeClient` whose `DialContext` rejects reserved/private IPs to block SSRF and DNS rebinding (`internal/webhook/webhook.go:32-37`, `safeDialContext` at `:59`).

**Callers** (the only two enqueue sites, per the call graph): `APIV1Service.DispatchMemoCommentCreatedWebhook` at `server/router/api/v1/memo_service_webhooks.go:30` and `APIV1Service.dispatchMemoRelatedWebhook` at `server/router/api/v1/memo_service_webhooks.go:48`.

**Architectural consequence worth flagging:** because the queue is an in-memory channel scoped to the process, it is neither durable nor shared. A restart loses up to 128 in-flight webhooks, and horizontally scaling the server gives each replica its own independent queue and its own 4 workers. The same pattern is used for email (`email.asyncEmailQueue`, `internal/email/email.go:14`), so this is a deliberate house style for fire-and-forget side effects rather than an oversight — but it does mean "webhook delivery" here carries no delivery guarantee.
