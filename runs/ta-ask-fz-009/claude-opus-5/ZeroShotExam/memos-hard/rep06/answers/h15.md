h15.

Memo visibility is enforced at **eight distinct server-side sites** across four surfaces (Connect/gRPC API, static file server, RSS, SSE fan-out), plus the SQL predicate in the store:

**1. Single-memo read gate (`checkMemoReadAccess`) — `server/router/api/v1/memo_service.go:39-68`** — used by `GetMemo` (`memo_service.go:341`) and `ListMemoComments` (`memo_service_comments.go:136`); PUBLIC open, PROTECTED requires any authenticated user, PRIVATE requires the creator.

**2. List query scoping (`ListMemos`) — `server/router/api/v1/memo_service.go:218-227`** — anonymous ⇒ `VisibilityList = [PUBLIC]`; authenticated ⇒ CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`, or `[PUBLIC, PROTECTED]` when listing another user's memos.

**3. Attachment access via memo visibility — `server/router/api/v1/attachment_service.go:422-455`** (`checkAttachmentAccess`).

**4. Memo-attachment listing — `server/router/api/v1/memo_attachment_service.go:214-225`** (`ListMemoAttachments`, its own inline copy of the same rule).

**5. Reactions — `server/router/api/v1/reaction_service.go:30-41` (list) and `:83` (upsert)** — inline visibility check again.

**6. Comment creation on a parent memo — `server/router/api/v1/memo_service_comments.go:41`** — PRIVATE parent blocks non-creator non-superuser.

**7. File server (non-gRPC HTTP surface) — `server/router/fileserver/fileserver.go:650-704`** (`checkAttachmentPermission`) — independent implementation with an extra `share_token` bypass and `AllowAnonymous()` condition on PUBLIC.

**8. RSS feeds — `server/router/rss/rss.go:90` and `:141`** — hardcoded `VisibilityList: []store.Visibility{store.Public}`.

**9. SSE event fan-out — `server/router/api/v1/sse_hub.go:134-144`** (`SSEClient.canReceive`) — PRIVATE events only to creator or admin; unknown visibility denied.

**10. Notification recipient filtering — `server/notification/email.go:306-320`** (`canViewerAccessMemo`) and `server/router/api/v1/memo_mention_helpers.go:62,67,84` — decides whether a mention/comment notification may expose a memo to a target user.

The shared primitive underneath: `store.Visibility` and `FindMemo.VisibilityList` (`store/memo.go:13-21,69`), translated to SQL per dialect in `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`.

Note the duplication risk: sites 1, 3, 4, 5, 6 and 7 each re-implement the same PUBLIC/PROTECTED/PRIVATE ladder inline rather than delegating to `checkMemoReadAccess`, and they don't agree — `checkMemoReadAccess` has no superuser escape hatch (`memo_service.go:63`), while the attachment/reaction/comment paths all grant `isSuperUser(user)`.
