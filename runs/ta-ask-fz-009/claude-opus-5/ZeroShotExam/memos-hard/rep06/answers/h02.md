### How the two layers fit

**Delivery.** `Post` marshals the `WebhookRequestPayload`, sets `Content-Type`, and — when a signing secret is present — adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature: v1,…`, `internal/webhook/webhook.go:133-150`) before issuing the POST via the package-level `safeClient` (`internal/webhook/webhook.go:32-37`). Response reading is bounded to 1 MiB (`webhook.go:158`) and a non-2xx or non-zero body `code` is an error.

Callers normally go through `PostAsync` (`internal/webhook/webhook.go:184`), which drops the payload onto a bounded 128-slot channel (`webhook.go:39`) drained by 4 goroutines started in `init` (`webhook.go:42-55`); each worker calls `Post`. So the network egress always happens in `Post`, off the request goroutine.

**SSRF protection — two independent chokepoints:**

1. **Dial-time enforcement (the load-bearing one).** `safeClient`'s `http.Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:59-77`): it splits host/port, resolves the host itself via `net.DefaultResolver.LookupHost`, and refuses the connection if *any* resolved address is reserved. Because the check happens at dial time rather than at URL-save time, it also defeats DNS rebinding — the comment at `webhook.go:29-31` states this intent explicitly.
2. **Admission-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-absolute URLs, non-`http`/`https` schemes, and hostnames resolving into reserved space, returning a gRPC `InvalidArgument` so the API layer can surface it directly when a webhook is created/updated.

Both funnel through `isReservedIP` (`internal/webhook/validate.go:44`), matching against `reservedCIDRs` — loopback, RFC-1918, link-local incl. the cloud IMDS `169.254.0.0/16`, and IPv6 equivalents (`internal/webhook/validate.go:14-23`), parsed once at startup.

**The documented escape hatch.** `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers at once. It is wired from the `--allow-private-webhooks` flag in `cmd/memos/main.go:133`, bound through viper (`cmd/memos/main.go:160`) and assigned at `cmd/memos/main.go:49` — intended for self-hosted deployments targeting LAN services.

One structural note worth flagging: `AllowPrivateIPs` is a plain package-level `bool` written during startup and read from the four dispatch goroutines, so the safety posture is a process-wide global rather than per-webhook policy — there's no way to allow private targets for one webhook while blocking them for another.
