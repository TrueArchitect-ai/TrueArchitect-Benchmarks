**How the candidate was disambiguated**

Three concrete `store.Driver` implementations exist — `sqlite.DB` (`store/db/sqlite/sqlite.go:16`), `mysql.DB` (`store/db/mysql/mysql.go:14`), `postgres.DB` (`store/db/postgres/postgres.go:16`) — and each has its own memo INSERT (`store/db/mysql/memo.go:41`, `store/db/postgres/memo.go:38`). Interface dispatch alone can't pick one, so selection was resolved through the call chain plus the runtime wiring:

1. **Chain (structure):** `ConnectServiceHandler.CreateMemo` (`server/router/api/v1/connect_services.go:306`) → `APIV1Service.CreateMemo` (`server/router/api/v1/memo_service.go:70`) → `Store.CreateMemo` (`store/memo.go:109`), which does UID validation then delegates to the interface: `s.driver.CreateMemo(ctx, create)` (`store/memo.go:113`).
2. **The dispatch point:** `NewDBDriver` switches on `profile.Driver` — `case "sqlite": sqlite.NewDB(profile)` (`store/db/db.go:14-24`). So the concrete type is fixed by one config value.
3. **The default value of that config:** `viper.SetDefault("driver", "sqlite")` and the flag default `String("driver", "sqlite", "database driver")` in `cmd/memos/main.go:122,130`, bound into `Profile.Driver` at `cmd/memos/main.go:43`. Corroborating: `internal/profile/profile.go:110-116` only synthesizes a default DSN (`memos_prod.db` under the data dir) for the `sqlite` branch, i.e. sqlite is the only driver that works with no flags at all.

With no flags, `profile.Driver == "sqlite"`, so the sqlite branch is taken and the SQLite `CreateMemo` is the code that runs. The MySQL and Postgres variants are reachable only when `--driver`/`MEMOS_DRIVER` is set (and they also require an explicit DSN).
