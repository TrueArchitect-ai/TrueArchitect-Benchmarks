`(*Store).DeleteMemo` in **store/memo.go:140–159** does two clean-up passes before delegating the row delete to the driver (`store/memo.go:158` → e.g. `store/db/sqlite/memo.go:237`):

1. **`memo_relation` rows where this memo is the source** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (store/memo.go:142)
2. **`memo_relation` rows where this memo is the target** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})` (store/memo.go:145)
3. **Attachments linked to the memo** — `ListAttachments(FindAttachment{MemoID: …})` then `DeleteAttachment` per row (store/memo.go:149–157); `(*Store).DeleteAttachment` (store/attachment.go:132) additionally removes the attachment's backing blob/file via `DeleteAttachmentStorage` (store/attachment.go:193)

Only after these does it run `DELETE FROM memo WHERE id = ?`. Reactions are *not* deleted here — the API handler only reads them (`ListReactions`) for the webhook/SSE payload, and the store's memo delete path leaves reaction rows to the DB schema.
