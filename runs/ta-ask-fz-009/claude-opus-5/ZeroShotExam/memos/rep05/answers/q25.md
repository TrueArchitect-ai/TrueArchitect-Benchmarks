**Engine: Google CEL (`github.com/google/cel-go`), wrapped by the in-repo `filter` package at `internal/filter/`** — `engine.go` (compile), `schema.go` (CEL env + field/dialect metadata), `parser.go` (AST → IR), `ir.go` (condition tree), `render.go` (IR → SQL).

**Mechanism (one sentence):** `Engine.Compile` type-checks the filter string against a CEL environment whose variables *are* the allowed filter fields (`internal/filter/schema.go:232-249` — `content`, `creator_id`, `created_ts`, `pinned`, `tags`, `visibility`, `has_link`, `now`, …), lowers the CEL AST into a dialect-agnostic condition tree (`buildCondition`, `internal/filter/engine.go:62`; node types in `internal/filter/ir.go`), and then a per-dialect renderer walks that tree emitting a parameterized `WHERE` fragment plus args (`Program.Render` → `newRenderer`, `internal/filter/engine.go:96-99`, `internal/filter/render.go:32`).

**How it reaches ListMemos and each dialect:**

- API layer: `APIV1Service.ListMemos` validates `request.Filter` via `s.validateFilter` (`server/router/api/v1/memo_service.go:211-215`; implementation at `server/router/api/v1/shortcut_service.go:336-341`, which just compiles it with `filter.DefaultEngine()`), then appends it to `memoFind.Filters` — and appends a second synthesized CEL filter for visibility (`creator_id == %d || visibility in ["PUBLIC", "PROTECTED"]`, `memo_service.go:222`).
- Store layer: each driver calls `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` with its own dialect constant — `store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`. `AppendConditions` (`internal/filter/helpers.go:9-25`) compiles each filter to a `Statement` and ANDs the fragments in, threading `PlaceholderOffset: len(*args)`.
- Dialect divergence lives entirely in the renderer, keyed on `DialectName` (`internal/filter/schema.go:10-17`): placeholders (`$N` for Postgres vs `?`, `render.go:842-849`), tag containment (`LIKE` on JSON text / `JSON_CONTAINS` / `@> jsonb_build_array`, `render.go:451-510`), timestamp accessors (`strftime` / `EXTRACT` / `MONTH()`, `render.go:229-239`), case-insensitive match (`memos_unicode_lower ... LIKE` / `ILIKE` / MySQL collation, `render.go:578-586`), regex (`~` vs `REGEXP`, `render.go:564-570`), comprehensions (`json_each` vs `JSON_TABLE`, `render.go:652-660`), plus per-field column overrides via `Field.Expressions[dialect]` (`schema.go:319-323`, e.g. MySQL `UNIX_TIMESTAMP(%s)` at `schema.go:282-287`).

Notable detail: constant folding happens at compile time — a filter that's always true renders to empty SQL and is skipped, always-false renders to `1 = 0` (`render.go:42-58`), and `now` is frozen to one instant per compile (`engine.go:17-20`).
