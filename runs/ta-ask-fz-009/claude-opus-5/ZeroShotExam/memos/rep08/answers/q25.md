**Engine: Google CEL (`github.com/google/cel-go`), wrapped by the in-house filter package at `internal/filter/` — `engine.go` (compile), `schema.go` (CEL env + field metadata), `parser.go` (AST → condition IR), `ir.go` (IR types), `render.go` (IR → dialect SQL).**

**Mechanism:** `ListMemos` validates the CEL string and passes it through as `FindMemo.Filters` (`server/router/api/v1/memo_service.go:211-215`), then each store driver calls `filter.DefaultEngine()` + `filter.AppendConditions(..., filter.DialectSQLite|Postgres|MySQL, &where, &args)` (`store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`), which compiles the CEL AST once into a dialect-agnostic `Condition` tree and then renders that tree per dialect into a parameterized `WHERE` fragment.

Details worth knowing:

- **Compile path** — `Engine.Compile` runs `cel.Env.Compile` then `cel.AstToParsedExpr`, and hands the expr to `buildCondition` to produce the IR (`internal/filter/engine.go:48-71`). `now` is frozen once per compile so one filter sees one instant (`engine.go:17-20`).
- **Exposed syntax** — the CEL env declares the filterable identifiers (`content`, `creator`, `creator_id`, …) as `cel.Variable`s plus `ext` macros (`internal/filter/schema.go:232-235`), with per-field metadata (`FieldKind` scalar / bool column / JSON bool / JSON list / virtual alias, `schema.go:32-57`) driving what operators and column expressions are legal. Supported forms include `contains`/`matches`, `in`, comprehensions (`exists`, `all`, `filter`) and timestamp accessors like `created_ts.getFullYear()` (`internal/filter/ir.go:68,146`, `parser.go:633,803`).
- **Dialect divergence lives in the renderer** — `newRenderer(schema, opts)` carries `dialect DialectName` and switches on it per construct (`internal/filter/render.go:10-32`): regex → `~` on Postgres vs `REGEXP` on MySQL/SQLite (`render.go:566-570`); case folding → `memos_unicode_lower(...) ... ESCAPE '\'` on SQLite vs `ILIKE` on Postgres (`render.go:578-582`); JSON lists → `json_each` / `JSON_TABLE` / `jsonb_array_elements_text` (`render.go:652-683`); timestamp parts → `strftime(..., 'unixepoch')` vs `EXTRACT(... AT TIME ZONE 'UTC')` vs `YEAR()` (`render.go:229-233`, `accessorSpec` at `render.go:177-178`).
- **Args are placeholder-safe** — `RenderOptions.PlaceholderOffset` lets a fragment be spliced into an already-built arg list (Postgres `$N` numbering); `AppendConditions` passes `len(*args)` and wraps each fragment in parens (`internal/filter/helpers.go:9-24`).
- Same machinery serves attachments via a second schema/engine (`filter.DefaultAttachmentEngine()`, `engine.go:119-124`), and memo-relation queries reuse `CompileToStatement` to build `memo_id IN (SELECT id FROM memo WHERE …)` subqueries (`store/db/postgres/memo_relation.go:87-101`).
