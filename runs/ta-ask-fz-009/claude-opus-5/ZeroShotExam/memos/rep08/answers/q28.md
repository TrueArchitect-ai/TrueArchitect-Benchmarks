**Runners/goroutines the server actually starts**

- **s3presign runner** — `RunOnce` synchronously at startup, then a `time.NewTicker` loop every 12 h in a tracked goroutine (`server/server.go:162-171`; interval + loop at `server/runner/s3presign/runner.go:27-41`). This is the *only* thing `startBackgroundRunners` launches, and the only one registered in `backgroundRunnerCancels` / `backgroundRunnerWG` for graceful shutdown.
- **3 × cache cleanup loops** — one goroutine per cache (`instanceSettingCache`, `userCache`, `userSettingCache`), started implicitly by `cache.New` at `store/cache/cache.go:83`, driven by a `CleanupInterval` ticker set to 5 min (`store/store.go:40-53`, loop at `store/cache/cache.go:199-201`). Started from `store.New` in `cmd/memos/main.go:64` — i.e. before/outside the server's runner machinery — and stopped via `Store.Close()` (`store/store.go:72-79`).
- **Async email workers (2)** — started by package `init()` at `internal/email/email.go:16-36`; driven by sends on the buffered `asyncEmailQueue` channel (cap 128), not by a clock.
- **Async webhook dispatch workers (4)** — started by package `init()` at `internal/webhook/webhook.go:42-55`; driven by payloads pushed onto `asyncPostQueue` (cap 128).
- **SSE heartbeat ticker** — per-connection, 30 s ticker created inside the SSE request handler (`server/router/api/v1/sse_handler.go:17`, `:64`); lifetime = the HTTP request, hub closed on shutdown via `sseHub.Close()` (`server/server.go:203-208`).
- **PAT last-used writer** — fire-and-forget goroutine per authenticated PAT request, no schedule, no tracking (`server/auth/authenticator.go:179-185`).

So the batch payload-rebuild pass exists but is never scheduled or invoked.
