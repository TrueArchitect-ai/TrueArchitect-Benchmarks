**Server-Sent Events (SSE) over a single `GET /api/v1/sse` stream; hub at `server/router/api/v1/sse_hub.go`; broadcasting handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `UpsertMemoReaction`, `DeleteMemoReaction` (plus `SetMemoAttachments` / `SetMemoRelations` via the shared update path).**

## Mechanism

SSE, not WebSockets. The endpoint is `GET /api/v1/sse`, registered by `RegisterSSERoutes` (`server/router/api/v1/sse_handler.go:25`) and served by `handleSSE` (`sse_handler.go:34`), with a heartbeat governed by `sseHeartbeatInterval` (`sse_handler.go:15`).

## Hub

`server/router/api/v1/sse_hub.go` — `SSEHub` (line 56) is a mutex-guarded `map[*SSEClient]struct{}` created by `NewSSEHub` (line 63), with the lifecycle contract `Subscribe` (71) / `Unsubscribe` (89) / `Close` (99) and fan-out via `Broadcast` (115).

Two invariants worth knowing:
- **Non-blocking fan-out.** Each client has a 32-event buffer (line 74); a full buffer means the event is *dropped*, not queued (lines 126–130). Delivery is best-effort, so the web client cannot treat the stream as a complete change log.
- **Authorization at the edge of delivery.** `canReceive` (line 134) filters per-client: `Private` memos reach only the creator or an admin; public/protected/empty visibility go to everyone. That's why `SSEEvent` carries `Visibility` and `CreatorID` as `json:"-"` (lines 32–33) — server-side routing fields that never cross the wire.

The last one is a shared side-effect dispatcher rather than an RPC; it is called by `UpdateMemo` (`memo_service.go:401`), `SetMemoAttachments` (`memo_attachment_service.go:16`), and `SetMemoRelations` (`memo_relation_service.go:16`), so all three emit update events through one funnel.

Event types are the six constants at `sse_hub.go:14-21` (`memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`), mirrored client-side by `SSE_EVENT_TYPES` in `web/src/hooks/useLiveMemoRefresh.ts:15`.

One notable escape hatch: `withSuppressSSE` / `isSSESuppressed` (`memo_service.go:24-34`) let a request context turn broadcasting off, so a handler on that list won't always emit.
