**MySQL, PostgreSQL, SQLite**

Migrations live under `store/migration/`, one directory per dialect, each with versioned subdirectories plus a `LATEST.sql` baseline schema:

- `store/migration/mysql/` — `0.17` … `0.30`, plus `store/migration/mysql/LATEST.sql`
- `store/migration/postgres/` — `0.19` … `0.30`, plus `store/migration/postgres/LATEST.sql`
- `store/migration/sqlite/` — `0.2` … `0.30` (the longest history), plus `store/migration/sqlite/LATEST.sql`

The code graph confirms the same three-way split at table grain: 11 tables declared per dialect module (`store/migration/mysql`, `store/migration/postgres`, `store/migration/sqlite`), i.e. the schemas are kept in parity across all three.
