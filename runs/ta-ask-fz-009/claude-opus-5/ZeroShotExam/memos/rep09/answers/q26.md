**Tables written by `DeleteMemo`:** `memo`, `memo_relation`, `attachment` — plus `memo_share` on MySQL/Postgres only, via a DB-level FK cascade.

### The delete path

`APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) does permission checks and a webhook dispatch, then performs exactly two kinds of writes, both through `store.Store.DeleteMemo`:

1. It lists comment relations and calls `s.Store.DeleteMemo` for each comment memo (`memo_service.go:568-577`).
2. It calls `s.Store.DeleteMemo` for the memo itself (`memo_service.go:580`).

`store.Store.DeleteMemo` (`store/memo.go:140-159`) is the cascade layer, in order:

| Step | Table | Code |
|---|---|---|
| Delete relations where memo is source | `memo_relation` | `store/memo.go:142` |
| Delete relations where memo is target | `memo_relation` | `store/memo.go:145` |
| List + delete each linked attachment | `attachment` | `store/memo.go:149-157` → `store/attachment.go:132-148` |
| Delete the row itself | `memo` | `store/memo.go:158` → e.g. `store/db/sqlite/memo.go:237` (`DELETE FROM memo WHERE id = ?`) |

Because the comment loop re-enters `store.Store.DeleteMemo`, comment memos get the same three-table treatment — no extra tables.

### `memo_share` — cascade only on two of three drivers

`memo_share` has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in all three schemas (`store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`, `store/migration/sqlite/LATEST.sql:109`). On MySQL/Postgres the engine enforces it, so share rows disappear with the memo. **On SQLite it does not fire** — the driver opens the DB with foreign keys off: `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`). There is no application-level `DeleteMemoShare` call in the delete path, so SQLite deployments leave orphaned `memo_share` rows.

### Not touched: `reaction`

`ListReactions` is called at `memo_service.go:545`, but only to build the webhook payload — it is a read. No reaction delete appears anywhere in the path (`[ArchMap query]` shows `ListReactions` with no corresponding delete), and `reaction` keys off a `content_id` text field (`store/migration/sqlite/LATEST.sql:96`) with no FK to `memo`. Reactions on a deleted memo are orphaned on every driver.
