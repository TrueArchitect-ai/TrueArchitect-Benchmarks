All four then converge on the same delivery path: `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded 128-slot channel `asyncPostQueue` (:39) drained by 4 worker goroutines started in `init()` (:42–55), each calling `webhook.Post` (`internal/webhook/webhook.go:120`) — the single function that marshals the payload, adds Standard Webhooks HMAC-SHA256 headers when a signing secret is set (:133–150), and POSTs via the SSRF-guarded `safeClient` (:32–37).

Two behavioral notes worth knowing: dispatch failures are best-effort — callers only log warnings (e.g. `memo_service.go:158`), never fail the RPC; and if the queue is full, payloads are silently dropped with a warning (`webhook.go:192`), so delivery is not guaranteed.
