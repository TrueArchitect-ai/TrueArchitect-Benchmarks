**Engine:** Google CEL (Common Expression Language, `github.com/google/cel-go`), wrapped by the in-repo filter engine at **`internal/filter/`** — `engine.go` (compile), `schema.go` (CEL env + field metadata), `parser.go` (AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL).

**Mechanism (one sentence):** `ListMemos` validates `request.Filter` and pushes it into `memoFind.Filters` (`server/router/api/v1/memo_service.go:211-215`, via `validateFilter` at `server/router/api/v1/shortcut_service.go:336`); each store driver then calls `filter.DefaultEngine()` + `filter.AppendConditions(..., find.Filters, filter.Dialect<X>, &where, &args)` (`store/db/sqlite/memo.go:61`, `store/db/postgres/memo.go:58`, `store/db/mysql/memo.go:69`), which runs `Engine.CompileToStatement` — CEL compiles the expression to an AST (`internal/filter/engine.go:53-60`), `buildCondition` lowers that AST into a dialect-neutral `Condition` tree (`internal/filter/engine.go:62`, `internal/filter/ir.go`), and the `renderer` emits a parameterized `WHERE` fragment for the requested dialect (`internal/filter/render.go:32`).

**How dialect differences are absorbed:**
- Per-field SQL templates keyed by dialect in the schema, e.g. `creator` → `('users/' || %s)` for SQLite/Postgres vs `CONCAT('users/', %s)` for MySQL, and `created_ts`/`updated_ts` → `UNIX_TIMESTAMP(%s)` on MySQL vs pass-through `%s` on Postgres/SQLite (`internal/filter/schema.go:99-150`).
- Dialect-specific expression builders in the renderer for string length, JSON extraction/array handling, timestamp accessors, and column qualification (`internal/filter/render.go:177-219`, `:295-297`, `:919-956`).
- Placeholder style: `$N` (offset-aware) for Postgres, `?` otherwise (`internal/filter/render.go:842-849`), with `PlaceholderOffset` fed from the caller's existing arg count so fragments compose into a larger query (`internal/filter/helpers.go:11-22`).

Two edge results are folded at render time rather than pushed to SQL: an unsatisfiable filter becomes `1 = 0` and a trivially-true one becomes an empty fragment that the caller skips (`internal/filter/render.go:42-52`, `internal/filter/helpers.go:18-20`). The same machinery serves attachments through a second schema/engine (`filter.DefaultAttachmentEngine()`, `internal/filter/engine.go:119`; used in `store/db/*/attachment.go`).
