q26.

**Tables affected: `memo`, `memo_relation`, `attachment`, and `memo_share`** (the last only via FK cascade, and only on MySQL/Postgres — see caveat).

How each one is reached:

| Table | Mechanism | Anchor |
|---|---|---|
| `memo_relation` | Explicit cascade code in the store layer — deleted twice, once as `MemoID` and once as `RelatedMemoID` | `store/memo.go:141-147` → `store/db/sqlite/memo_relation.go:149` (`DELETE FROM memo_relation`) |
| `attachment` | Explicit cascade — lists attachments by `MemoID`, deletes each (plus the blob/file in storage) | `store/memo.go:148-157` → `store/attachment.go:132-149` → `store/db/sqlite/attachment.go:212` |
| `memo` | The target row itself | `store/memo.go:158` → `store/db/sqlite/memo.go:237-248` (`DELETE FROM memo WHERE id = ?`) |
| `memo_share` | DB-level `ON DELETE CASCADE` FK, no Go code | `store/migration/sqlite/LATEST.sql:109`, `store/migration/mysql/LATEST.sql:108`, `store/migration/postgres/LATEST.sql:108` |

Two things worth flagging:

**1. The `memo_share` cascade does not fire on SQLite.** The SQLite driver opens the database with foreign keys disabled: `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`). `memo_share` is the only table with an FK to `memo`, and there is no Go-side `DeleteMemoShare` call in the delete path — so on SQLite deployments those rows are orphaned, while MySQL/Postgres clean them up. That is a real divergence in behavior across the three backends.

**2. `reaction` is read but never written.** The API handler at `server/router/api/v1/memo_service.go:545-550` lists reactions for the memo — but only to build the webhook payload (`:560-565`). No delete follows, and `reaction.content_id` is a free-text column with no FK (`store/migration/sqlite/LATEST.sql:92-99`), so reaction rows survive memo deletion on all three databases.

Scope note: the API-level handler (`memo_service.go:518`) also recursively calls `store.DeleteMemo` for each comment memo (`:569-577`), so a delete of a parent memo touches the same four tables once per comment plus once for itself. It does not add new tables to the list.
