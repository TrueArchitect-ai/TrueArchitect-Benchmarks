**Mechanism:** Server-Sent Events (SSE) over a long-lived HTTP GET — `GET /api/v1/sse`, `Content-Type: text/event-stream`, Bearer-token auth in the `Authorization` header, 30s heartbeat comments, `X-Accel-Buffering: no` to defeat proxy buffering (`server/router/api/v1/sse_handler.go:25-110`).

**Hub path:** `server/router/api/v1/sse_hub.go` — `SSEHub` (line 56) is an in-process, mutex-guarded set of `*SSEClient`, each with a 32-event buffered channel; `Broadcast` (line 115) fans out JSON payloads and *drops* events for clients whose buffer is full rather than blocking. Per-client filtering happens in `canReceive` (line 134): private memos only reach the creator or an admin. `Close` (line 99) drains all clients on shutdown. The connection handler `handleSSE` subscribes/unsubscribes (`sse_handler.go:60-61`).
