**Engine: Google CEL (`github.com/google/cel-go`), wrapped by the in-repo filter engine at `internal/filter/` — `engine.go` (compile), `schema.go` (CEL env + exposed fields/dialects), `parser.go` (AST → condition IR), `ir.go`, `render.go` (IR → SQL).**

**Mechanism:** the filter string is compiled by a CEL environment whose variables/functions are declared in `internal/filter/schema.go` (`NewSchema`, `cel.Variable("content", ...)` etc., plus `ext` macros), the CEL AST is lowered into a dialect-agnostic `Condition` tree by `buildCondition` (`internal/filter/engine.go:53-65`, `internal/filter/parser.go`), and then a dialect-specific renderer (`newRenderer`/`Render`, `internal/filter/render.go`, switching on `DialectSQLite`/`DialectMySQL`/`DialectPostgres` from `internal/filter/schema.go:10-16`) emits a parameterized SQL fragment + args.

Path through ListMemos:
- `server/router/api/v1/memo_service.go:212-215` — validates the request filter (`validateFilter`, defined at `server/router/api/v1/shortcut_service.go:336`, which just compiles it via `filter.DefaultEngine()`) and appends it to `memoFind.Filters`; the visibility guard is itself injected as a CEL string (`creator_id == %d || visibility in ["PUBLIC","PROTECTED"]`, line 222).
- `store.Store.ListMemos` (`store/memo.go:116`) → driver methods `store/db/sqlite/memo.go:54`, `store/db/mysql/memo.go:62`, `store/db/postgres/memo.go:51`. Each calls `filter.DefaultEngine()` and `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)`.
- `filter.AppendConditions` (`internal/filter/helpers.go:9-25`) calls `engine.CompileToStatement` per filter with `RenderOptions{Dialect, PlaceholderOffset: len(args)}` — the offset is what keeps Postgres `$n` placeholders correctly numbered — and appends each fragment as `(...)` to the WHERE list plus its args.

Dialect differences live entirely in the renderer, not the parser: e.g. timestamp accessors (`internal/filter/render.go:219-241`), string length (`stringLengthExpr`, `render.go:297` — MySQL needs `CHAR_LENGTH` to match CEL's code-point `size()`), and JSON containment (`render.go:363-408`, `451-460`: SQLite `LIKE` on the JSON array, MySQL `JSON_CONTAINS`, Postgres its own form). Attachments use a separate schema via `filter.DefaultAttachmentEngine()` (`internal/filter/engine.go:119`), and memo-relation subqueries call `engine.CompileToStatement` directly (e.g. `store/db/postgres/memo_relation.go:87`).
