**Runners the server actually starts** (all wiring in `server/server.go:153-174`, `startBackgroundRunners`):

- **`s3presign.Runner`** — started twice-over: one synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a goroutine running `Run(s3Context)` which is driven by a **fixed `time.Ticker` at 12 h** (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). Per-cycle work is self-throttled: an attachment is re-presigned only if its `LastPresignedTime` is older than 4 days (`server/runner/s3presign/runner.go:85-91`). Cancelled via a stored `context.CancelFunc` on shutdown (`server/server.go:156-159`, `176-182`).
- **`store/cache` cleanup loop (×3)** — not registered as a "background runner," but three long-lived goroutines are started implicitly when the store is constructed: `cache.New` spawns `go c.cleanupLoop()` (`store/cache/cache.go:83`) for `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`). Driven by a **`time.Ticker` on `CleanupInterval = 5 min`** (`store/cache/cache.go:201`, config at `store/store.go:42`). Stopped via `Close()`/`stopChan` (`store/cache/cache.go:187-197`).

That is the whole set. Everything else async in the server is **request-scoped, not scheduled**:
- SSE heartbeat ticker lives inside the per-connection handler (`server/router/api/v1/sse_handler.go:64`), one per client, ends with the request.
- PAT last-used write is a fire-and-forget goroutine per authentication (`server/auth/authenticator.go:180`).
