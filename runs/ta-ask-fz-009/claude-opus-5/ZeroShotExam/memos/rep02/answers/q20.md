**Server-Sent Events (SSE) over HTTP; `server/router/api/v1/sse_hub.go` (endpoint handler in `server/router/api/v1/sse_handler.go`); `CreateMemo`, `UpdateMemo` (via `dispatchMemoUpdatedSideEffects`), `DeleteMemo`, `CreateMemoComment`, `UpsertMemoReaction`, `DeleteMemoReaction` — plus `SetMemoAttachments` and `SetMemoRelations`, which broadcast indirectly through the same helper.**

**Mechanism.** Plain SSE, not WebSockets (`gorilla/websocket` in `go.mod:79` is an indirect dep, unused here). The endpoint is `GET /api/v1/sse`, registered by `RegisterSSERoutes` (`server/router/api/v1/sse_handler.go:25-30`), setting `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no` and flushing via `http.Flusher` (`sse_handler.go:48-56`), with a 30s heartbeat (`sse_handler.go:17`). Auth is a Bearer token checked before the stream opens (`sse_handler.go:36-44`) — note that means the browser cannot use native `EventSource`; the client uses a fetch-based reader (`web/src/hooks/useLiveMemoRefresh.ts:205`).

**Hub.** `SSEHub` (`sse_hub.go:56-60`) is an in-process, mutex-guarded registry of `*SSEClient`, each holding a 32-buffered `chan []byte` plus `userID`/`role` (`sse_hub.go:48-52`, `71-86`). Two invariants worth knowing:

- **Non-blocking fan-out**: `Broadcast` drops events for clients whose buffer is full rather than blocking the writer (`sse_hub.go:126-130`) — delivery is best-effort, so the client treats events as refresh hints, not a reliable log.
- **Visibility filtering at the edge**: `canReceive` (`sse_hub.go:134-144`) gates `Private` memos to the creator or an admin; `Visibility`/`CreatorID` are `json:"-"` (`sse_hub.go:32-33`), so they inform routing without leaking to the wire.

Because the hub is process-local state, this is single-instance-only — it won't fan out across replicas without an external bus.
