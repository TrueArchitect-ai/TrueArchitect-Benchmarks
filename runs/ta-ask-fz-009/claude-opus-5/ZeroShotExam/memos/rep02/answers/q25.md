**Engine: Google CEL (`cel-go`), wrapped by the in-repo filter engine at `internal/filter/`** — entry point `filter.DefaultEngine()` in `internal/filter/engine.go:111`, which builds an `Engine` over the memo schema (`internal/filter/schema.go`, via `NewSchema()`).

**Mechanism (one sentence):** the CEL string is compiled by `cel-go` against the memo-specific CEL environment and normalized into a dialect-agnostic condition tree IR, then the renderer walks that IR and emits a dialect-specific SQL `WHERE` fragment plus bound args, which each store driver appends to its own query.

Path through the layers:

1. **RPC** — `v1.APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:178`) validates the expression (`validateFilter`, `server/router/api/v1/shortcut_service.go:336`) and passes it down as `FindMemo.Filters`; it does not build SQL itself.
2. **Compile** — `Engine.Compile` (`internal/filter/engine.go:48`) calls `env.Compile` (cel-go) then `cel.AstToParsedExpr`, and `buildCondition` (`internal/filter/parser.go`) converts the CEL AST into the IR defined in `internal/filter/ir.go`, enforcing schema field/type/operator rules.
3. **Render** — `Program.Render` / `Engine.CompileToStatement` (`internal/filter/engine.go:96`, `:74`) takes `RenderOptions{Dialect, PlaceholderOffset, DisableNullChecks}` (`engine.go:83`) and returns `Statement{SQL, Args}` (`engine.go:90`). `internal/filter/render.go` switches on `DialectSQLite` / `DialectMySQL` / `DialectPostgres` for every dialect-sensitive construct — placeholders (`?` vs `$n`, with offset tracking), JSON payload access (`json_each` / `JSON_TABLE` / `jsonb_array_elements_text`), `LIKE` vs `ILIKE`, `REGEXP` vs `~`, `LENGTH` vs `CHAR_LENGTH`, date-part extraction (`strftime` / `YEAR()` / `EXTRACT`) — e.g. `render.go:231`, `:365`, `:452`, `:565`, `:654`.
4. **Store binding** — each driver calls the same engine with its own dialect constant via the `AppendConditions` helper (`internal/filter/helpers.go`): `store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo.go:65-69`, `store/db/postgres/memo.go:54-58`. Postgres passes `PlaceholderOffset: len(args)` so `$n` numbering composes with pre-existing args (see `store/db/postgres/memo_relation.go:87-100`).

Two engine instances exist: `DefaultEngine()` for memos and `DefaultAttachmentEngine()` for attachments (`internal/filter/engine.go:111`, `:119`), both `sync.Once`-cached process-wide.

The design and supported surface are documented in `internal/filter/README.md` (three-phase pipeline: parse → normalize to IR → render), with maintenance notes in `internal/filter/MAINTENANCE.md`. One caveat that file states explicitly: regex *syntax* is not portable across dialects (Go RE2 on SQLite via a registered function in `store/db/sqlite/functions.go`, POSIX ERE on Postgres, ICU on MySQL), so the SQL is dialect-neutral in structure but not in regex semantics.
