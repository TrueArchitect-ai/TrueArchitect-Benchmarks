**Engine: Google CEL (`github.com/google/cel-go`), wrapped by the in-house filter engine at `internal/filter/`** — `engine.go` (`Engine`, `DefaultEngine`), `schema.go` (CEL env + field/dialect mapping), `parser.go` → `ir.go` (condition tree), `render.go` (SQL emission), `helpers.go` (`AppendConditions`).

**Mechanism:** `ListMemos` validates the CEL string and pushes it onto `MemoFind.Filters` (`server/router/api/v1/memo_service.go:211-215`); each dialect driver then calls `filter.DefaultEngine()` + `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect{SQLite,MySQL,Postgres}, &where, &args)` (`store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo.go:65-69`, `store/db/postgres/memo.go:54-58`), which compiles the CEL AST into a **dialect-agnostic condition tree** and then renders it per-dialect into a parameterized `WHERE` fragment plus args.

Details worth knowing:

- **Two-stage, not string-templating.** `Engine.Compile` runs `cel.Env.Compile` → `cel.AstToParsedExpr` → `buildCondition(...)` producing a `Condition` IR (`internal/filter/engine.go:48-71`). Dialect enters only at render time via `RenderOptions{Dialect, PlaceholderOffset}` (`engine.go:82-99`), so parsing/validation is shared and only emission diverges.
- **Vocabulary is a declared schema, not free-form.** `NewSchema()` registers the allowed variables — `content`, `creator_id`, `created_ts`, `pinned`, `tags`, `visibility`, `has_task_list`, `has_link`, `now`, etc. (`internal/filter/schema.go:233-246`), each `Field` carrying a `Column` plus optional per-dialect `Expressions map[DialectName]string` (`schema.go:55, 104-167`).
- **Dialect divergence lives in `render.go` switches** on `r.dialect`: regex → `~` on Postgres vs `REGEXP` on MySQL/SQLite (`render.go:564-570`); case-insensitive contains → `memos_unicode_lower(...) LIKE ... ESCAPE '\'` on SQLite vs `ILIKE` on Postgres vs `LIKE` on MySQL (`render.go:579-583`); JSON payload access → `JSON_EXTRACT` on SQLite/MySQL vs Postgres `->>`/`->` accessors (`render.go:932-950`); array comprehensions → `json_each` / `JSON_TABLE` / `jsonb_array_elements_text` (`render.go:653-684`); `size()` → `LENGTH` vs MySQL `CHAR_LENGTH` (`render.go:297-300`); time accessors → `strftime` vs `EXTRACT(... to_timestamp)` vs `YEAR()/MONTH()` (`render.go:230-234`).
- **Placeholders and safety.** Values always go through `r.addArg`, so fragments are bound parameters (`?` for SQLite/MySQL, `$N` for Postgres), and `PlaceholderOffset: len(*args)` keeps numbering correct when a filter is appended after existing conditions (`internal/filter/helpers.go:11-22`).
- **Constant folding is part of the contract.** `now`-only predicates fold at compile time to either empty SQL (matches everything) or `1 = 0` (unsatisfiable), per `internal/filter/functions_test.go:264-274`.
- Access control reuses the same path: the visibility guard is itself injected as a CEL string, `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` (`server/router/api/v1/memo_service.go:222`).

A sibling engine instance, `DefaultAttachmentEngine()` with `NewAttachmentSchema()`, serves attachment filters through the identical pipeline (`internal/filter/engine.go:119-124`).
