The path in detail:

1. **Handler** — `CreateMemo` calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)` after converting the stored memo, logging a warning on failure rather than failing the RPC (`server/router/api/v1/memo_service.go:156-159`).
2. **Dispatcher** — `DispatchMemoCreatedWebhook` is a thin wrapper that delegates to `dispatchMemoRelatedWebhook` with activity type `"memos.memo.created"` (`server/router/api/v1/memo_service_webhooks.go:15-17`). That function resolves the memo creator, loads their hooks via `s.Store.GetUserWebhooks(ctx, creatorID)`, and per hook builds a payload with the hook's `Url` and `SigningSecret`, then calls `webhook.PostAsync(payload)` (lines 48-72).
3. **Delivery package** — `internal/webhook`. `PostAsync` only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:184-196`, queue at :39); a background worker drains it and the actual HTTP POST happens in `Post` using the shared `safeClient` (`internal/webhook/webhook.go:120-180`). The client's dialer rejects reserved/private IPs unless `AllowPrivateIPs` is set (`internal/webhook/webhook.go:62-73`, flag wired in `cmd/memos/main.go:49`).
4. **Signing** — only when the hook has a `SigningSecret`. The key is derived by `resolveSigningKey`, which base64-decodes the Standard Webhooks `whsec_<base64>` form and otherwise uses the secret bytes raw (`internal/webhook/webhook.go:97-106`). Signature = HMAC-SHA256 over `msgID + "." + timestamp + "."` concatenated with the JSON body, base64-encoded (`internal/webhook/webhook.go:142-149`). Secrets are minted as 32 random bytes in `whsec_` form by `GenerateSigningSecret` (:111-117).

Two design details worth noting: dispatch is fire-and-forget, so a full queue silently drops notifications (only a `slog.Warn`), and an unsigned hook sends no signature headers at all — asserted by the tests at `internal/webhook/webhook_test.go:139-154`.
