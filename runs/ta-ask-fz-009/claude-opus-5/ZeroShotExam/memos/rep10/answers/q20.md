**Mechanism.** Plain HTTP SSE, not WebSockets — `handleSSE` sets `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive` and `X-Accel-Buffering: no` to defeat nginx buffering (`server/router/api/v1/sse_handler.go:48-51`), flushes headers immediately, and keeps the connection alive with a 30s heartbeat ticker (`sse_handler.go:17,64`). Auth is a Bearer token validated up front by `auth.NewAuthenticator`, rejecting with 401 before any streaming (`sse_handler.go:34-44`). `gorilla/websocket` is present in `go.mod:79` but only as an indirect dependency — it isn't this path.

**Hub.** `SSEHub` (`sse_hub.go:56`) is a mutex-guarded set of `*SSEClient`, each holding a buffered `events chan []byte` plus the `userID` and `role` (`sse_hub.go:48-52`). Connections join/leave via `hub.Subscribe(userID, role)` / `hub.Unsubscribe(client)` (`sse_handler.go:60-61`), and `SSEHub.Broadcast` (`sse_hub.go:115`) fans an `*SSEEvent` out to clients. A `closed` flag (`sse_hub.go:59`) supports shutting clients down during server shutdown. The event contract is six typed events (`sse_hub.go:14-21`): `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`. Note the deliberate boundary in `SSEEvent` (`sse_hub.go:24-34`): `Visibility` and `CreatorID` are `json:"-"` — they exist for **server-side delivery filtering** only and never reach the browser.
