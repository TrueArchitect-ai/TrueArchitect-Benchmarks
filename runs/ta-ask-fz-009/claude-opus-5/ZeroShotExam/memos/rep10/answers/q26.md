q26.

**Tables affected: `memo`, `memo_relation`, `attachment` — plus `memo_share` via an FK `ON DELETE CASCADE` (only where FKs are enforced).**

### Path of effects

`v1.APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) does permission checks, fires the webhook, then:

1. Lists child comment relations and calls `Store.DeleteMemo` for each comment memo (`memo_service.go:567-577`) — so every effect below happens recursively for comments too.
2. Calls `Store.DeleteMemo` for the memo itself (`memo_service.go:580`).

`store.Store.DeleteMemo` (`store/memo.go:140-159`) is where the explicit cascade lives:

| Table | How | Anchor |
|---|---|---|
| `memo_relation` | two explicit `DeleteMemoRelation` calls — rows where the memo is `memo_id` *and* where it is `related_memo_id` | `store/memo.go:142-147`; SQL at `store/db/sqlite/memo_relation.go:149` |
| `attachment` | `ListAttachments(MemoID)` then `DeleteAttachment` per row (also deletes the backing blob/file via `DeleteAttachmentStorage`) | `store/memo.go:149-157`, `store/attachment.go:132-148`, SQL at `store/db/sqlite/attachment.go:212` |
| `memo` | the driver `DELETE FROM memo WHERE id = ?` | `store/memo.go:158`, `store/db/sqlite/memo.go:237-248` |
| `memo_share` | **no application code** — relies on `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` | `store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108` |

### Two caveats worth flagging

- **`memo_share` cascade does not fire on SQLite.** The connection is opened with foreign keys disabled: `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`). On MySQL/Postgres the FK cascades; on SQLite the `memo_share` rows are orphaned. Note the user-deletion path *does* clean it explicitly (`store/db/sqlite/user_delete.go:411`), so the gap is specific to memo deletion.
- **`reaction` is read but never deleted.** `DeleteMemo` lists reactions only to build the webhook payload (`memo_service.go:545-550`); `reaction` has no FK to `memo` (`store/migration/sqlite/LATEST.sql:92-99`, it keys on a `content_id` string), so reaction rows for a deleted memo are left behind. The user-deletion path deletes them explicitly (`store/db/sqlite/user_delete.go:383`), which makes the omission here look unintentional rather than by design.
