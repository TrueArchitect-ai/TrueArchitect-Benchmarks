**APIV1Service.SignIn — `server/router/api/v1/auth_service.go:51`**

That's where the actual authentication logic lives: password credentials are resolved via `s.Store.GetUser` and verified with `bcrypt.CompareHashAndPassword` (`auth_service.go:55-68`), or SSO credentials are exchanged; session issuance is delegated to `APIV1Service.doSignIn` (`server/router/api/v1/auth_service_session.go:24`).

Two things sit in front of it, worth knowing so you don't mistake either for the handler:

- `ConnectServiceHandler.SignIn` — `server/router/api/v1/connect_services.go:78` — the Connect protocol adapter. It only unwraps `req.Msg` and wraps the call in `connectWithHeaderCarrier` so the service can set response headers (e.g. session cookies) protocol-agnostically, then delegates to `APIV1Service.SignIn`.
- `apiv1connect.AuthServiceHandler.SignIn` — `proto/gen/api/v1/apiv1connect/auth_service.connect.go:143` — the generated interface contract that `ConnectServiceHandler` satisfies. Generated code, not business logic.
