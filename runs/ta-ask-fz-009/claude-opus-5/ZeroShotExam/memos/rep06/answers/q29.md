### How the flow works

**Frontend interceptor** — `web/src/connect.ts`
- `authInterceptor` (`connect.ts:156`) is registered on the single Connect-Web transport (`connect.ts:184-189`) that backs every service client (memo, user, attachment, AI, etc., `connect.ts:192-203`). All RPCs go through it.
- Per request it calls `getRequestToken()` (`connect.ts:124`), sets `Authorization: Bearer <token>` (`connect.ts:97-100`), and on a `Code.Unauthenticated` response refreshes once and replays the request with an `X-Retry: true` marker to prevent loops (`connect.ts:157-177`); if refresh fails it calls `redirectOnAuthFailure()`.
- Refresh uses a **separate transport with no interceptors** to avoid recursion (`connect.ts:64-72`), and `fetch` is wrapped with `credentials: "include"` (`connect.ts:57-62`) so the refresh cookie rides along. Concurrent refreshes are deduplicated by `tokenRefreshManager` (`connect.ts:30-51`).

**Tokens managed** — `web/src/auth-state.ts`
- **Access token (JWT)**: held in-memory and in `localStorage` under `memos_access_token` / `memos_token_expires_at` (`auth-state.ts:6-7`); proactively refreshed when within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry (`auth-state.ts:18`, `connect.ts:140`), and shared across tabs via a `BroadcastChannel` named `memos_token_sync` (`auth-state.ts:13-50`).
- **Refresh token**: never touched by JS — it's a cookie (`memos_refresh`, `server/auth/token.go:49`, built at `server/router/api/v1/auth_service_session.go:224`) exchanged via `AuthService.RefreshToken` (`connect.ts:74-83`).

**Backend validation** — `server/auth`
- The Connect `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:208-231`) reads the `Authorization` header, delegates to `Authorizer.Authenticate` (`server/router/api/v1/authz.go:44`) → `auth.Authenticator.Authenticate` (`server/auth/authenticator.go:213`), then enforces policy with `CheckAccess` and returns `CodeUnauthenticated` on failure.
- `server/auth` handles three credential kinds: **access tokens** validated stateless by signature (`authenticator.go:41`, `token.go:71` `AccessTokenClaims`, 15 min — `token.go:40`); **refresh tokens** validated against the DB for revocation/expiry (`authenticator.go:61-99`, 30 days — `token.go:43`); **Personal Access Tokens** prefixed `memos_pat_`, looked up by hash (`authenticator.go:102-124`, `token.go:52`).
