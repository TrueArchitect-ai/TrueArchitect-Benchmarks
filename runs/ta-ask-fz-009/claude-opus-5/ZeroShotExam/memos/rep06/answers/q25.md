**Engine:** Google CEL (`cel-go`), wrapped by the in-house filter package at **`internal/filter/`** — `engine.go` (compile), `schema.go` (CEL env + field metadata), `parser.go` (CEL AST → condition IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → dialect SQL). **Mechanism (one sentence):** `Engine.Compile` type-checks the filter string against a CEL environment declaring the allowed memo fields (`internal/filter/schema.go:232+`, e.g. `content`, `creator_id`, `visibility`, `tags`, `created_ts`) and lowers the CEL AST into a dialect-agnostic `Condition` tree (`buildCondition`, `internal/filter/engine.go:62`), which `Program.Render` then emits as a parameterized SQL `WHERE` fragment plus args for the requested dialect (`internal/filter/engine.go:96` → `newRenderer`, `internal/filter/render.go:24`, switching on `DialectSQLite | DialectMySQL | DialectPostgres` from `internal/filter/schema.go:13-17`).

**Path through ListMemos:**
- `APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:178`) validates `request.Filter` via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`, which picks the dialect from `s.Profile.Driver`) and appends it to `store.FindMemo.Filters` (line 215) — plus a synthesized visibility/ownership CEL filter at line 222.
- Each store driver compiles those filter strings at query time with the process-wide singleton `filter.DefaultEngine()` and `filter.AppendConditions(..., dialect, &where, &args)` (`internal/filter/helpers.go:9`): `store/db/sqlite/memo.go:57-61` (`DialectSQLite`), `store/db/postgres/memo.go:54-58` (`DialectPostgres`), and the MySQL equivalent in `store/db/mysql/memo.go`.
- `AppendConditions` passes `PlaceholderOffset: len(*args)` so Postgres `$n` numbering stays consistent with the hand-built conditions appended after it; the rendered fragment is wrapped in parens and its args appended in order.
