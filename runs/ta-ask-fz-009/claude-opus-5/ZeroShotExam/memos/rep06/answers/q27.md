**Mechanism:** Go `embed.FS` — the Vite build output is compiled into the server binary and served by Echo's static middleware plus an SPA `index.html` fallback; **Path:** `server/router/frontend/frontend.go`

How the pieces line up:

- **Build step writes into the Go package.** `web/package.json:11` — `"release": "vite build --mode release --outDir=../server/router/frontend/dist --emptyOutDir"`. The compiled bundle lands in `server/router/frontend/dist`, not a separately deployed static host.
- **Embed directive.** `server/router/frontend/frontend.go:20-21` — `//go:embed dist/*` into `var embeddedFiles embed.FS`, unwrapped via `fs.Sub(embeddedFiles, "dist")` in `getFileSystem` (`frontend.go:115-118`). So the assets ship inside the single `memos` binary.
- **Serving.** `FrontendService.Serve` (`frontend.go:41-61`) registers `middleware.StaticWithConfig` over that embedded FS, then `spaFallbackMiddleware` (`frontend.go:63-80`), which converts a 404 on a non-API path into `c.FileFS("index.html", frontendFS)` — the client-side-routing fallback. A skipper (`frontend.go:82-90`) excludes `/api`, `/file`, `/memos.api.v1*`, `robots.txt`, `sitemap.xml`, and `*/rss.xml` so backend routes are never shadowed by the static handler.
- **Wired into the server.** `server/server.go:72` — `frontend.NewFrontendService(profile, store).Serve(ctx, echoServer)`, mounted before the API route groups.
- **Production packaging confirms it.** `scripts/Dockerfile` copies only the built binary into the runtime image (`Dockerfile:39`), with the comment at `Dockerfile:15-16` noting the frontend must be built first "so that the static files are available" — there is no nginx or static-file volume in the image.

Cache policy is also handled here rather than by a proxy: `no-cache` for HTML, `max-age=3600` for static assets, and `immutable` for hash-named assets (`frontend.go:23-27`).
