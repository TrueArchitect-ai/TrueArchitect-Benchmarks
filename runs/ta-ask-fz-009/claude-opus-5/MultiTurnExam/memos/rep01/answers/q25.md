q25. **CEL (Google's Common Expression Language, via `github.com/google/cel-go`) + internal/filter; the engine compiles the CEL AST into a dialect-agnostic condition tree (IR), which a per-dialect renderer then emits as a parameterized SQL fragment plus bound args.**

The pipeline, three stages in one package:

1. **Parse/type-check** — `Engine.Compile` runs `cel.NewEnv(schema.EnvOptions...)` and `env.Compile(filter)`, then converts to a parsed expr (`internal/filter/engine.go:25`, `:53-57`). The allowed fields, types, and functions come from `Schema` (`internal/filter/schema.go`), so unknown fields or bad operand types are rejected at compile time — e.g. `pinned && 1` and a non-boolean top-level expression both error (`internal/filter/engine_test.go:20-38`).
2. **Lower to IR** — `buildCondition` walks the CEL AST into a dialect-neutral `Condition` tree (`internal/filter/engine.go:62`, types in `internal/filter/ir.go`, walker in `internal/filter/parser.go`). Constants are folded here, with `now` frozen once per compile so a single filter sees one instant (`internal/filter/engine.go:17-20`; folding tests at `internal/filter/functions_test.go:15-42`).
3. **Render per dialect** — `Program.Render(RenderOptions{Dialect: ...})` (or the one-shot `Engine.CompileToStatement`, `internal/filter/engine.go:74`) emits a `Statement{SQL, Args}` from `internal/filter/render.go`, switching on `DialectSQLite` / `DialectPostgres` / `DialectMySQL`.

The dialect divergence is real, not cosmetic — visible in the test matrix:

| construct | SQLite | Postgres | MySQL |
|---|---|---|---|
| `content.matches(re)` | `` `memo`.`content` REGEXP ? `` | `memo.content ~ $1` | `` REGEXP ? `` |
| `startsWith` | `memos_unicode_lower(...)` + `ESCAPE '\'` | `ILIKE $1` | `LIKE ?` |
| `size(content)` | `LENGTH(` | `LENGTH(` | `CHAR_LENGTH(` |
| `tags.all(...)` | `json_each(` | `jsonb_array_elements_text(` | `JSON_TABLE(` |

(`internal/filter/engine_test.go:103-105`, `:140-142`, `:162-164`; `internal/filter/functions_test.go:58-60`)

Two properties worth flagging: values always travel as **bound arguments**, never interpolated — `content.contains("50%_off")` yields args `%50\%\_off%` with LIKE wildcards escaped (`internal/filter/engine_test.go:80-85`), so the filter surface isn't an injection vector. And the drivers consume the rendered fragment: `store/db/sqlite/memo.go` imports `internal/filter` (`:11`) and splices the `Statement.SQL` into its WHERE clause, with siblings doing the same in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`. Package docs live at `internal/filter/README.md` and `internal/filter/MAINTENANCE.md`.
