q20. **Server-Sent Events (SSE); server/router/api/v1/sse_hub.go; CreateMemo, CreateMemoComment, DeleteMemo, UpsertMemoReaction, DeleteMemoReaction (plus the shared helper dispatchMemoUpdatedSideEffects, which covers UpdateMemo)**

The pieces:

- **Transport**: SSE over a single long-lived GET — `RegisterSSERoutes` mounts `GET /api/v1/sse` (`server/router/api/v1/sse_handler.go:25`). That's the only streaming door in the HTTP surface; the rest is Connect/REST request-response.
- **Hub**: `server/router/api/v1/sse_hub.go` holds the client registry and fan-out (`SSEHub.Broadcast`), with the per-request connection handling in `server/router/api/v1/sse_handler.go` and event construction helpers in `server/router/api/v1/sse_event_helpers.go`. Covered by `sse_hub_test.go` / `sse_service_test.go`.
- **Broadcasters** (direct callers of `SSEHub.Broadcast`):

| handler | file |
|---|---|
| `APIV1Service.CreateMemo` | `server/router/api/v1/memo_service.go:70` |
| `APIV1Service.DeleteMemo` | `server/router/api/v1/memo_service.go:518` |
| `APIV1Service.CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:20` |
| `APIV1Service.UpsertMemoReaction` | `server/router/api/v1/reaction_service.go:60` |
| `APIV1Service.DeleteMemoReaction` | `server/router/api/v1/reaction_service.go:111` |
| `APIV1Service.dispatchMemoUpdatedSideEffects` | `server/router/api/v1/memo_update_helpers.go:66` |

The last row is the indirection worth knowing: `UpdateMemo` doesn't call the hub itself — it routes through `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_service.go:513`), which bundles the SSE broadcast with the other post-update side effects. Concretely, `DeleteMemo` emits `SSEEventMemoDeleted` with the memo name, visibility, and creator ID (`server/router/api/v1/memo_service.go:585-590`) — visibility and creator travel with the event so the hub can scope delivery rather than blindly fanning out to every connected client.
