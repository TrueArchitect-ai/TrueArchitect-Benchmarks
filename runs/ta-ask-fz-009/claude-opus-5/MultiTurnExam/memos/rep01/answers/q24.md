The seams worth naming:

- **Frontend → server** is a protocol boundary, not a resolved call edge. The browser speaks Connect (generated schema `web/src/types/proto/api/v1/memo_service_pb.ts`), so requests land at `ConnectServiceHandler.CreateMemo` (`server/router/api/v1/connect_services.go`), which unwraps the envelope and delegates to `APIV1Service.CreateMemo`. The `POST /api/v1/memos` REST form is the grpc-gateway alternative into the same handler (`proto/gen/api/v1/memo_service.pb.gw.go:1745`).
- **`Store.CreateMemo` is a guard, not a query** — it validates the UID against `base.UIDMatcher` and then dispatches through the `store.Driver` interface (`store/driver.go:10`), so the dialect hop is chosen at startup by `NewDBDriver` (`store/db/db.go:14`). Swap SQLite for `store/db/postgres/memo.go` or `store/db/mysql/memo.go` and the chain is otherwise identical.
- The SQL itself is assembled by string concatenation over `fields`/`placeholder` slices (`store/db/sqlite/memo.go:17-18`), inserting `uid`, `creator_id`, `content`, `visibility`, `payload`.

Also note the handler does more than persist: after the store write it dispatches the created-memo webhook (`server/router/api/v1/memo_service.go:156`) and broadcasts an SSE event (`:161`) — side effects on the same call, both best-effort.
