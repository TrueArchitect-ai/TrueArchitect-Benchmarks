q25. **CEL (Common Expression Language) via `github.com/google/cel-go` v0.28.1, wrapped by the in-house engine at `internal/filter/` (entry point `internal/filter/engine.go`); mechanism: cel-go parses the filter string into an AST which the engine walks into a dialect-agnostic condition IR, then renders per-dialect SQL `WHERE` fragments with bound placeholder args — cel-go never evaluates anything.**

The three-stage pipeline inside `internal/filter/`:

1. **Parse** — `NewEngine(schema)` builds a `cel.NewEnv` from the schema's env options (`internal/filter/engine.go:24-28`); the filterable field vocabulary and dialect enum live in `internal/filter/schema.go` (`DialectName` at :10).
2. **Lower to IR** — `internal/filter/parser.go` walks the CEL AST into the dialect-neutral condition types in `internal/filter/ir.go` (`LogicalCondition`, `ComparisonCondition`, `InCondition`, `TextMatchCondition`, `RegexCondition`, …).
3. **Render** — `internal/filter/render.go` switches on `DialectName` per node to emit dialect-correct SQL. The dialect divergence is real and concentrated here: JSON boolean access (`:365` SQLite / `:394` MySQL / `:402` Postgres), tag-list containment (`:452`/`:458`/`:464`), timestamp accessors (`:231`/`:234`/`:237`), string length (`stringLengthExpr` :297), and regex — Postgres uses its native operator while MySQL and SQLite share a branch (`:565`, `:568`); SQLite has no built-in `REGEXP`, so a Go-backed function is registered for it.

**Where drivers plug in:** each dialect's `ListMemos` obtains the shared engine and appends conditions with its own dialect constant — `store/db/sqlite/memo.go:57-61` (`filter.DialectSQLite`), `store/db/postgres/memo.go:54-58` (`DialectPostgres`), `store/db/mysql/memo.go:65-69` (`DialectMySQL`). `filter.AppendConditions` merges the rendered fragment into the driver's `where`/`args` slices, so filters stay parameterized rather than interpolated. `CompileToStatement` with a `PlaceholderOffset` (`store/db/postgres/memo_relation.go:87-89`) handles Postgres's positional `$N` numbering when a filter is embedded mid-query.

Same engine also serves attachments via `filter.DefaultAttachmentEngine()` (`store/db/sqlite/attachment.go:81`), and shortcuts are stored CEL strings validated by `APIV1Service.validateFilter` (`server/router/api/v1/shortcut_service.go:336`). Separately, `server/router/api/v1/user_service_filter.go:29` spins up its own small CEL env for username filtering rather than going through `internal/filter`.
