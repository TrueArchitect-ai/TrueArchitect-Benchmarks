q20. **Server-Sent Events (SSE); server/router/api/v1/sse_hub.go; CreateMemo, UpdateMemo (via dispatchMemoUpdatedSideEffects), DeleteMemo, CreateMemoComment, UpsertMemoReaction, DeleteMemoReaction**

**Mechanism** — SSE over the existing HTTP surface, not WebSockets. The endpoint is registered alongside the rest of `/api/v1` via `RegisterSSERoutes` (`server/router/api/v1/v1.go:125`), with the streaming handler in `server/router/api/v1/sse_handler.go`.

**Hub** — `SSEHub` (`server/router/api/v1/sse_hub.go:56`) is an in-process fan-out registry: a `map[*SSEClient]struct{}` behind a `sync.RWMutex`, with `Subscribe` (:71), `Unsubscribe` (:89), `Close` (:99), and `Broadcast` (:115). Each client gets a 32-slot buffered channel (:74), and `Broadcast` **drops** events for clients whose buffer is full rather than blocking (:112-114) — so SSE is a best-effort refresh hint, not a guaranteed event log. Per-client authorization happens at delivery time in `canReceive` (:134), which filters by memo visibility, creator, and admin role.

**Broadcast sites:**

| Handler | Broadcast site | Event type |
|---|---|---|
| `CreateMemo` (`memo_service.go:70`) | `memo_service.go:163` | `memo.created` |
| `UpdateMemo` → `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`) | `memo_update_helpers.go:71` | `memo.updated` |
| `DeleteMemo` (`memo_service.go:518`) | `memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` (`memo_service_comments.go:20`) | `memo_service_comments.go:126` | `memo.comment.created` |

| `DeleteMemoReaction` (`reaction_service.go:111`) | `reaction_service.go:161` | reaction deleted |

One design detail worth knowing: because `CreateMemoComment` delegates to `CreateMemo` internally, it would emit two events. It suppresses the inner one through a context flag — `CreateMemo` guards its broadcast with `if !isSSESuppressed(ctx)` (`memo_service.go:162`) — and emits `memo.comment.created` against the *parent* instead. That invariant is pinned by `TestCreateMemoComment_NoDuplicateSSEBroadcast` (`server/router/api/v1/sse_service_test.go:71`).
