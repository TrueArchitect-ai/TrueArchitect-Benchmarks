Three review priorities worth calling out:

- **`memo_service_converter.go`** is the proto↔store boundary — a field added to `store.Memo` that should surface in the API must be handled here, or it silently never reaches clients.
- **The three dialect files** must move together; the `store.Driver` interface (`store/driver.go`) enumerates each memo operation explicitly, so a signature change is a four-file edit minimum.
- **`server/runner/memopayload/runner.go`** rewrites memo payloads in a background job — payload/schema changes need a migration story here, not just a code change.

Two caveats on completeness: the graph flags that SQL built by string concatenation isn't captured, so column-level reads/writes in the dialect files are a lower bound — verify at the driver call sites.
