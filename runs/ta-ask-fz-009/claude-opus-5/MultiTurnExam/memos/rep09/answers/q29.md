q29. **web/src/connect.ts (`authInterceptor`, :156); short-lived JWT access tokens + HTTP-only cookie refresh tokens (backend also accepts Personal Access Tokens); server/auth**

**Frontend interceptor** — `authInterceptor` (`web/src/connect.ts:156-178`) is installed on the shared Connect transport (:188) and does three things:

1. **Attach** — resolves a token via `getRequestToken()` (:124) and sets `Authorization: Bearer <token>` (:97-100).
2. **Preflight refresh** — if the cached access token is expired within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` it refreshes *before* sending (:140-147). The comment at :136-139 names the reason: a stale token on a public endpoint like `ListMemos` would otherwise be silently treated as anonymous and return guest-scoped data.
3. **Reactive retry** — on `Code.Unauthenticated`, refresh once, re-send with an `X-Retry: true` marker to prevent loops (:164-172); if refresh fails, `redirectOnAuthFailure()` (:174).

**Token kinds:**
- *Access token* — short-lived JWT held in memory/`auth-state`, sent as a bearer header. Backend doc puts it at 15 minutes (`server/auth/authenticator.go:22`).
- *Refresh token* — never touched by JS; it rides as an HTTP-only cookie, which is why every fetch uses `credentials: "include"` (`web/src/connect.ts:57-62`). Exchanged via `refreshAuthClient.refreshToken({})` (:75).
- *PAT* — long-lived tokens for programmatic clients (`server/auth/authenticator.go:23`), validated server-side but not managed by the browser interceptor.

A notable detail: refresh goes through a **separate transport with no interceptors** (`refreshTransport`, :65-70) to avoid recursion, and concurrent refreshes are deduplicated by `tokenRefreshManager` (:30-51) so proactive focus-refresh and reactive 401-refresh can't race against server-side token rotation.

**Backend validation** — the `server/auth` package, centered on `Authenticator` (`server/auth/authenticator.go:26`), deliberately shared by the gRPC interceptor, Connect interceptor, and file server so all three agree (:17-19). Access tokens validate statelessly via `AuthenticateByAccessTokenV2` → `ParseAccessTokenV2` (:41-58); refresh tokens are checked against the DB for revocation and expiry in `AuthenticateByRefreshToken` (:61-99). The gateway path wires this in through `gatewayAuthMiddleware` (`server/router/api/v1/v1.go:97`).
