q26. **`memo_relation`, `attachment`, `memo`** — those are the only tables written by the DeleteMemo path.

Traced from the API handler down:

**Handler — `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`)**
1. Lists comment relations (`RelatedMemoID = memo.ID`, `Type = MemoRelationComment`) and calls `Store.DeleteMemo` on each comment memo (`memo_service.go:567-577`) — recursive, so every affected table is hit once per comment too.
2. Calls `Store.DeleteMemo` for the memo itself (`memo_service.go:580`).

**Store — `Store.DeleteMemo` (`store/memo.go:140-159`)**
- `memo_relation` — two deletes, both directions: `MemoID` then `RelatedMemoID` (`store/memo.go:142,145`) → `DELETE FROM memo_relation …` (`store/db/mysql/memo_relation.go:137` and dialect peers)
- `attachment` — lists by `MemoID`, then `DeleteAttachment` per row (`store/memo.go:149-157`) → `DELETE FROM attachment WHERE id = …` (`store/db/postgres/attachment.go:212`, `store/db/mysql/attachment.go:231`)
- `memo` — the row itself, last (`store/memo.go:158`) → `DELETE FROM memo WHERE …` (`store/db/sqlite/memo.go:239`, `store/db/mysql/memo.go:261`, `store/db/postgres/memo.go:246`)

**Two tables that are notably *not* touched — likely orphan rows:**

- **`reaction`** — the handler *reads* reactions (`memo_service.go:545-550`) but only to build the webhook payload (`memo_service.go:560-565`). `DeleteReaction` exists (`store/reaction.go:39`) and is never called on this path. Reactions key off `content_id`, and there's no FK cascade in the schema.
- **`memo_share`** — `DeleteMemoShare` exists (`store/memo_share.go:45`) but isn't invoked here either.

Both *are* cleaned up on user deletion (`DELETE FROM reaction …`, `DELETE FROM memo_share WHERE memo_id IN …` at `store/db/mysql/user_delete.go:420,448`), which confirms the cleanup is expected in principle — it's just absent from the single-memo path.

**Side effect beyond SQL:** `Store.DeleteAttachment` also removes the backing blob — local file `os.Remove` or object-storage delete — before the row delete (`store/attachment.go:141-148`, `store/attachment.go:202-216`), and a failed local-file delete aborts the whole operation.
