q04. **APIV1Service.SignIn — server/router/api/v1/auth_service.go**

The real implementation is at `server/router/api/v1/auth_service.go:51`. It handles two credential paths: password-based (bcrypt compare against `user.PasswordHash`, plus a `DisallowPasswordAuth` instance-setting check) and SSO via OAuth2 authorization code (`server/router/api/v1/auth_service.go:45-74`).

One wiring detail worth knowing: requests arriving over Connect land first on the thin delegating wrapper `ConnectServiceHandler.SignIn` at `server/router/api/v1/connect_services.go:78`, which wraps the call in `connectWithHeaderCarrier` (so the handler can set response headers — the auth cookie) and then forwards to `APIV1Service.SignIn`. The wrapper carries no business logic.
