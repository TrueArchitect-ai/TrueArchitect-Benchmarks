q10. **store/migration/sqlite/LATEST.sql**

The migrator applies it as the whole-schema bootstrap for uninitialized databases rather than replaying the incremental migration chain. From `store/migrator.go`:

- `LatestSchemaFileName = "LATEST.sql"` — "used to initialize fresh installations with the current schema" (`store/migrator.go:54-56`)
- Migration flow step 1: "preMigrate: Check if DB is initialized. If not, apply LATEST.sql" (`store/migrator.go:27`)
- "LATEST.sql: Full schema for new installations (faster than incremental migrations)" (`store/migrator.go:42`)

The dialect is selected by path — files are laid out as `store/migration/{driver}/...` (`store/migrator.go:39`) and embedded via `//go:embed migration` (`store/migrator.go:44`), so the SQLite backend resolves to `store/migration/sqlite/LATEST.sql`. That file carries the current table definitions, e.g. `memo` and `memo_relation` at `store/migration/sqlite/LATEST.sql:47`. `store/test/migrator_test.go:18-26` exercises exactly this fresh-install path.
