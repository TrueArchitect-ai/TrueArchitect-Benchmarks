**`web/src/connect.ts` (the `authInterceptor`, line 156); access token in memory + refresh token in an HTTP-only cookie, plus personal access tokens on the server side; validated by `server/auth/`.**

How it works:

**Interceptor** — `authInterceptor` (`web/src/connect.ts:156-178`) is installed on the single shared transport (`:188`), so every service client inherits it. Per request it resolves a token via `getRequestToken()` and sets `Authorization: Bearer <token>` (`:97-100`).

**Token kinds and lifecycle:**
- **Access token** — short-lived, held in `web/src/auth-state` (`getAccessToken`/`setAccessToken`, imported at `:4`), sent as the Bearer header.
- **Refresh token** — never touched by JS; it rides as a cookie because every fetch is `credentials: "include"` (`fetchWithCredentials`, `:57-62`). Exchanged via `AuthService.refreshToken` (`:75`).
- **Personal access tokens** — the other bearer credential the backend accepts, resolved by PAT hash (`store.Store.GetUserByPATHash`, `store/user_setting.go:128`).

Two refresh paths, deliberately separated:
- *Preflight* — if the stored token is expired within `REQUEST_TOKEN_EXPIRY_BUFFER_MS`, refresh before sending (`:140-147`). The comment at `:136-139` explains why: on public endpoints like `ListMemos` an expired token would silently downgrade to guest-scoped data rather than 401.
- *Reactive* — on `Code.Unauthenticated`, refresh once, stamp `X-Retry: true`, and replay; a second failure triggers `redirectOnAuthFailure()` (`:164-176`). The `X-Retry` guard bounds it to one attempt.
- Concurrent refreshes are deduplicated through `tokenRefreshManager` (`:30-51`, `:89-91`) — required because tab-focus refresh and 401 refresh would otherwise race against server-side token rotation.
- The refresh call itself uses a **separate transport with no interceptors** (`refreshTransport`, `:65-70`) specifically to prevent recursion.

**Backend validation: `server/auth/`** — `Authenticator.resolveBearer` (`server/auth/authenticator.go:149`) and `AuthenticateByRefreshToken` (`:61`) resolve the credential to a user via `Store.GetUser`; token minting/parsing lives in `server/auth/token.go`, request-header extraction in `server/auth/extract.go`, and identity propagation in `server/auth/context.go`. Which routes may skip authentication is declared separately in `server/router/api/v1/acl_config.go` (per `AGENTS.md:21`).
