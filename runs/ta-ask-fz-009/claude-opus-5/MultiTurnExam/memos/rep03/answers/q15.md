The convention holds throughout the store layer: one file per table, struct named as the singular CamelCase form of the table name, no ORM tags — column mapping is done explicitly in the hand-written SQL in each `store/db/{mysql,postgres,sqlite}/` counterpart file.

One historical wrinkle worth flagging on `attachment`: the table was renamed from `resource`, so migrations carry both names — `store/migration/sqlite/0.26/00__rename_resource_to_attachment.sql` (and the mysql/postgres equivalents). If you grep for `resource` in older migrations you're looking at the same entity as `store.Attachment`.
