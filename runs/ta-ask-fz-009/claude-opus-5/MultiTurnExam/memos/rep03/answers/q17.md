**web/src/hooks/useMemoQueries.ts; memoServiceClient**

The module is a TanStack Query wrapper around the generated Connect client (`memoServiceClient`, created at `web/src/connect.ts:197`), exporting the full CRUD surface:

- Reads — `useMemos` (:112) and `useInfiniteMemos` (:122) → `listMemos`; `useMemo` (:142) → `getMemo`; `useMemoComments` (:272) / `useInfiniteMemoComments` (:291) → `listMemoComments`; `useLinkMetadata` (:163) → `getLinkMetadata`
- Writes — `useCreateMemo` (:178) → `createMemo`; `useUpdateMemo` (:197) → `updateMemo` (sends a `FieldMask` from the caller's `updateMask`, :204); `useDeleteMemo` (:253) → `deleteMemo`

Two design points that matter if you touch this file:

- **Cache identity is centralized** in the `memoKeys` factory (`:15` for lists, plus `detail`/`comments`/`linkMetadata`), so invalidation after mutations is keyed consistently rather than ad hoc.
- **There are local cache-patching helpers** — `patchMemoListResponse` (:33), `findMemoInListResponse` (:72), and the type guards `isMemoListResponse` (:25) / `isInfiniteMemoListData` (:29) — which exist because a memo can be cached either as a flat `ListMemosResponse` or as `InfiniteData<ListMemosResponse>`. Any new mutation needs to handle both shapes or optimistic updates will silently miss the infinite lists.

One caveat: this is the canonical module, but not the only call site of the client — `web/src/components/MemoEditor/hooks/useLinkMemo.ts:55` calls `memoServiceClient.listMemos` directly, bypassing these hooks.
