**store/migration/sqlite/LATEST.sql**

The migrator resolves it by convention: `LatestSchemaFileName = "LATEST.sql"` (`store/migrator.go:56`) under the path layout `store/migration/{driver}/...` (`store/migrator.go:39`), so the sqlite driver reads `store/migration/sqlite/LATEST.sql`.

The flow that consumes it is documented at `store/migrator.go:27` — "preMigrate: Check if DB is initialized. If not, apply LATEST.sql" — and line 42 states the rationale: "Full schema for new installations (faster than incremental migrations)." A fresh install therefore never replays the `0.2`…`0.30` incremental files; it gets the whole schema in one shot (e.g. `memo_relation` at `store/migration/sqlite/LATEST.sql:47`).

The files are compiled into the binary via `//go:embed migration` (`store/migrator.go:44`), so this is read from the embedded FS, not from disk at runtime.
