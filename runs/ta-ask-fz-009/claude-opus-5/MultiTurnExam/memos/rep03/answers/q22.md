4. **Signing.** When `SigningSecret` is non-empty (`webhook.go:133`), `Post` computes `HMAC-SHA256` over `msgID + "." + timestamp + "." + body` (:142-144) and sets three headers: `webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<base64>` (:147-149). Secrets are stored in `whsec_<base64>` form and base64-decoded to raw key bytes by `resolveSigningKey` (:97-106); `GenerateSigningSecret` (:111) mints 32 random bytes. That header triple and the `v1,` prefix are the Standard Webhooks convention.

Two security properties worth noting, since they're deliberate and easy to regress:

- **SSRF hardening at dial time.** `safeDialContext` (`webhook.go:59-77`) resolves the hostname and rejects any reserved/private IP before connecting — which, as the comment at :30-31 states, also defeats DNS rebinding. Webhook URLs are user-supplied, so this is the boundary control.
- **Signing failures are loud, not silent.** A `whsec_`-prefixed secret that isn't valid base64 returns an error rather than signing with the wrong key (:100-102), because a silently-wrong signature would be unverifiable at the receiver.
