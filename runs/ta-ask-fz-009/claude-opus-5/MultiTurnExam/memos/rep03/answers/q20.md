Two architectural details that matter here:

- **Delivery is authorization-filtered, not a blind fan-out.** Each `SSEEvent` carries `Visibility` and `CreatorID` (`sse_hub.go:24-25`), and `SSEClient.canReceive(event)` (`sse_hub.go:134`) decides per-subscriber whether an event is visible — that's why clients subscribe with `(userID, role)`.
- **Comment events are re-scoped to the parent owner.** `resolveSSECreatorID` (`sse_event_helpers.go:12-20`) substitutes the *parent* memo's `CreatorID` when the memo is a comment, so a private parent's activity doesn't leak to the commenter's audience. Same helper backs the reaction events via `buildMemoReactionSSEEvent` (:24).
