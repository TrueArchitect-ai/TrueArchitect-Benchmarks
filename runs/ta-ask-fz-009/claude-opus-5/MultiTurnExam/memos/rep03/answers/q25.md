**Engine: Google CEL (cel-go) — `internal/filter/` (entry point `filter.DefaultEngine()` at `internal/filter/engine.go:111`)**

**Mechanism:** the CEL string is compiled against a typed schema into a dialect-agnostic condition tree (IR), which a per-dialect renderer then emits as a parameterized SQL fragment plus an args slice that each driver splices into its `WHERE` clause.

The three stages:

1. **Parse/compile.** `Engine.Compile` runs `e.env.Compile(filter)` and `cel.AstToParsedExpr` (`internal/filter/engine.go:53-57`), then `buildCondition` converts the CEL AST into the IR (`:62`; IR types in `internal/filter/ir.go`, conversion in `internal/filter/parser.go`). The CEL environment is defined by `NewSchema()` in `internal/filter/schema.go:232-249`, which whitelists the filterable variables — `content`, `creator`, `creator_id`, `created_ts`, `updated_ts`, `pinned`, `tag`, `tags`, `visibility`, `has_task_list`, `has_link`, `has_code`, `has_incomplete_tasks`, `now` — plus `ext.Sets()` and `cel.ValidateRegexLiterals()`. Unknown fields are rejected at render time too (`render.go:131`).
2. **Render per dialect.** `internal/filter/render.go` holds a `renderer` carrying a `DialectName` (`:12`) and switching on it: `DialectSQLite` / `DialectPostgres` / `DialectMySQL` (`:231-241`). Dialect divergence is explicit — timestamp extraction uses `strftime(..., 'unixepoch')` vs `EXTRACT(... FROM to_timestamp(...) AT TIME ZONE 'UTC')` vs the native MySQL function (`:232-238`), and `size()` maps to `CHAR_LENGTH` on MySQL but `LENGTH` elsewhere so it matches CEL's code-point semantics (`:297-301`).
3. **Consume in the driver.** Each `ListMemos` obtains the engine via `filter.DefaultEngine()` — `store/db/sqlite/memo.go:57`, `store/db/postgres/memo.go:54`, `store/db/mysql/memo.go:65` — and appends the rendered fragment to its `where`/`args` accumulators (seeded with `1 = 1`). MySQL additionally splits into `where` and `having` (`store/db/mysql/memo.go:63`).

Two properties worth relying on:

- **Injection safety is structural.** The renderer allocates numbered placeholders (`placeholderOffset`/`placeholderCounter`, `render.go:13-14`) and collects literals into `args` — user text never lands in the SQL string, only in bound parameters.
- **`now` is frozen per compile.** `nowFunc` is evaluated once (`engine.go:62`, comment at `:17-19`) so a single filter sees one instant, and tests can inject a deterministic clock.

There's also a second schema for attachments (`defaultAttachmentInst`, `engine.go:105-107`), so this engine is shared beyond memos. Design notes live in `internal/filter/README.md` and `internal/filter/MAINTENANCE.md`.
