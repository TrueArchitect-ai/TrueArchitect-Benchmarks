Two things about this chain:

- **The SQL layer is dialect-multiplied** — the same table is declared three times: `store/migration/sqlite/LATEST.sql:33`, `store/migration/mysql/LATEST.sql`, `store/migration/postgres/LATEST.sql`. A column change means editing all three plus adding a versioned migration under each `store/migration/{dialect}/{version}/`.
- **Two of the four are generated, one is not.** `memo_service_pb.ts` and the Go `proto/gen/api/v1/memo_service.pb.go` both derive from the proto, so the proto is the single edit point for the API contract. The store model (`store/memo.go:35`) and the SQL are hand-maintained and independent — the seam between them and the proto is `convertMemoFromStore` in `server/router/api/v1/memo_service_converter.go`, which is where a field added at one layer must be explicitly plumbed to reach the other.
