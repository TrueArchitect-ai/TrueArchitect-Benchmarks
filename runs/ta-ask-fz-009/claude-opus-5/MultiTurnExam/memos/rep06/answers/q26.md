Scope notes that matter for reasoning about this operation:

- **Comment memos multiply the same set.** The API handler deletes each child comment via `Store.DeleteMemo` before the parent (`server/router/api/v1/memo_service.go:567-577`), so these three tables are hit once per comment as well — but no additional tables enter the picture.
- **`reaction` is NOT touched.** Reactions are only read to build the deleted-webhook payload (`server/router/api/v1/memo_service.go:545-550`); nothing deletes them. Since they key off the memo's resource name (`ContentID`), rows are left orphaned in the `reaction` table.
- **Side effect beyond the DB:** deleting an attachment also removes the backing blob — local file `os.Remove` or object-storage delete (`store/attachment.go:141`, `deleteAttachmentStorageImpl` at `:202-218`). For `LOCAL` storage a failure is fatal to the operation; for remote it's only logged.
- No transaction wraps any of this (`store/memo.go:140-158`), so a mid-sequence failure leaves partial deletions committed.
