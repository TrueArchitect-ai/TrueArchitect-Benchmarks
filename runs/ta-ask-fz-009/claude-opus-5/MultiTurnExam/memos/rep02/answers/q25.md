q25. **Engine: Google CEL (`cel-go`), wrapped by the in-house `filter` package at `internal/filter/` — `engine.go` (CEL env + compile), `schema.go` (allowed variables), `parser.go` (AST → IR), `render.go` (IR → SQL); mechanism: the CEL expression compiles once into a dialect-agnostic condition tree, which `render.go` then emits as a parameterized `WHERE` fragment specialized per dialect, and each driver's `ListMemos` splices that fragment plus its args into its own query.**

How the hops line up:

- **Parse/validate** — `Engine` holds a `*cel.Env` built from a `Schema` (`internal/filter/engine.go:14-16`, `NewEngine` line 24); `Compile` runs `env.Compile` then `cel.AstToParsedExpr` (`engine.go:53-57`). The memo grammar is a closed vocabulary declared in `NewSchema()` — `content`, `creator`, `creator_id`, `created_ts`, `updated_ts`, `pinned`, `tag`, `tags`, `visibility`, `has_task_list`, `has_link`, `has_code`, `has_incomplete_tasks`, `now` (`internal/filter/schema.go:233-246`), with `ext.Sets()` and `ValidateRegexLiterals()` enabled (lines 247-248). Unknown identifiers fail at compile time rather than reaching SQL. `timestamp()`/`duration()` literals are folded in `parser.go:601`, `:626`, and `now` is frozen once per compile so one filter sees one instant (`engine.go:17-20`).
- **Dialect-agnostic IR** — the condition tree lives in `internal/filter/ir.go`; dialects are enumerated as `DialectName` (`internal/filter/schema.go:10-11`).
- **SQL generation** — `AppendConditions(ctx, engine, filters, dialect, &where, &args)` (`internal/filter/helpers.go:9`) calls `engine.CompileToStatement` with `RenderOptions{Dialect, PlaceholderOffset}` (lines 11-14) — the offset is what keeps placeholder numbering correct when merging into a query that already has args, and the rendering itself is in `internal/filter/render.go`.
- **Driver call site** — `sqlite.DB.ListMemos` grabs the process-wide engine via `filter.DefaultEngine()` (`store/db/sqlite/memo.go:57`, memoized by `sync.Once` at `internal/filter/engine.go:111-115`) and appends conditions with `filter.DialectSQLite` (`store/db/sqlite/memo.go:61`). Postgres and MySQL do the same with their own dialect constants in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`.

There's a parallel schema for attachments — `NewAttachmentSchema()` / `DefaultAttachmentEngine()` (`internal/filter/schema.go:259`, `engine.go:119`) — so the same engine serves `ListAttachments` filters. Design notes for the package are in `internal/filter/README.md` and `internal/filter/MAINTENANCE.md`.
