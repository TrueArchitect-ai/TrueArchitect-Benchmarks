q29. **Interceptor: `web/src/connect.ts` (`authInterceptor`, line 156); tokens: short-lived JWT access token in the `Authorization: Bearer` header + long-lived refresh token in an HttpOnly cookie (and PATs as an alternative bearer credential for API clients); backend validator: `server/auth/`**

**Frontend interceptor.** `authInterceptor` (`web/src/connect.ts:156-178`) is installed on the single shared Connect transport (`:188`) that backs every service client. Per request it:

1. Resolves a token via `getRequestToken()` (`:124-150`) and sets `Authorization: Bearer <token>` (`:97-100`).
2. **Preflight refresh** — if the stored token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` of expiry it refreshes *before* sending (`:140-147`). The comment at `:136-139` explains why: on a public endpoint like `ListMemos`, an expired token would otherwise be silently treated as anonymous and return guest-scoped data instead of 401.
3. **Reactive retry** — on `Code.Unauthenticated` it refreshes, re-signs, marks the request with `X-Retry: true`, and retries exactly once (`:164-172`); a second failure triggers `redirectOnAuthFailure()` (`:174`).

Refresh itself goes through `refreshAccessToken` → `tokenRefreshManager` (`:89-91`, `:30-51`), which deduplicates concurrent refreshes so the focus-based proactive refresh and the 401 path can't race server-side token rotation. It rides a **separate interceptor-free transport** (`refreshTransport`, `:65-70`) to avoid recursion, and uses `credentials: "include"` (`:57-62`) so the HttpOnly refresh cookie is sent — the refresh token is never touched by JS, only the access token is (`setAccessToken`, `web/src/auth-state.ts`).

**Backend validation — `server/auth/`:**

- `AuthenticateByAccessTokenV2` — stateless JWT verify, no DB hit (`server/auth/authenticator.go:41-42`; access tokens are 15 min per the doc comment at `:22`)
- `AuthenticateByRefreshToken` — parses, then checks the token row in the DB so revocation works (`:61`, `:73`)
- `AuthenticateByPAT` — requires the `PersonalAccessTokenPrefix`, looks up by hash via `GetUserByPATHash`, enforces expiry, and records last-used asynchronously (`:102-123`, `:179-184`)
- `resolveBearer` dispatches between access token and PAT by prefix (`:149-174`); `AuthenticateToUser` tries the header first and falls back to the refresh cookie (`:190-204`). Header extraction helpers are in `server/auth/extract.go`, token minting/parsing in `server/auth/token.go`, and request-scoped identity keys in `server/auth/context.go`.
