q22. **`APIV1Service.DispatchMemoCreatedWebhook` — `server/router/api/v1/memo_service_webhooks.go:15`; delivery package `internal/webhook`; HMAC-SHA256 per the Standard Webhooks spec**

**Dispatch path.** `CreateMemo` calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)` (`server/router/api/v1/memo_service.go:157`), and a failure is logged, not returned — webhook delivery is best-effort and never fails memo creation. The dispatcher is a thin wrapper that stamps the activity type `"memos.memo.created"` and delegates to `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:16`, `:48`), which resolves the memo's creator, loads that user's hooks via `Store.GetUserWebhooks` (`:57`), and per hook builds a payload carrying the hook's URL and `SigningSecret` (`:66-68`).

**Delivery.** `internal/webhook` — enqueued via `webhook.PostAsync` (`memo_service_webhooks.go:71`; implementation `internal/webhook/webhook.go:184`). It's a bounded fire-and-forget design: a 128-slot channel drained by 4 worker goroutines (`internal/webhook/webhook.go:39`, `:42-45`), each calling `Post` (`:120`), which JSON-POSTs the payload through a shared `safeClient` (`:32`, `:152`). That client's `DialContext` (`safeDialContext`, `:59`) rejects reserved/private IPs at dial time — SSRF and DNS-rebinding protection.

**Signing.** When the hook has a secret, `Post` computes HMAC-SHA256 over `msgID + "." + timestamp + "." + body` (`internal/webhook/webhook.go:142-145`) and sets the Standard Webhooks headers `webhook-id`, `webhook-timestamp`, and `webhook-signature: v1,<base64>` (`:147-149`). Secrets are `whsec_<base64>`-prefixed and base64-decoded to raw key bytes by `resolveSigningKey` (`:97-99`); a malformed prefix errors out rather than silently signing with the wrong key. New secrets come from `GenerateSigningSecret` (32 random bytes, `:111`).

Comments take a sibling path — `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`) notifies the *parent* memo's owner with activity type `"memos.memo.comment.created"`.
