**s3presign.Runner — `time.Ticker`, every 12 hours, plus one eager pass at startup.** Started in `Server.startBackgroundRunners` (`server/server.go:153-174`): `RunOnce(ctx)` fires immediately at line 163, then `Run(s3Context)` loops on a ticker with `runnerInterval = 12h` (`server/runner/s3presign/runner.go:27`, `:29-41`). Each pass re-presigns S3 attachment URLs in batches of 100, skipping any whose presigned URL is still valid for 4+ more days (`s3presign/runner.go:85-91`). It has its own cancelable context and is tracked in a `WaitGroup` so shutdown is orderly (`server/server.go:156-171`, `stopBackgroundRunners`/`waitBackgroundRunners`).

**SSE hub — not a scheduled runner; event-driven.** `SSEHub` is created in `NewAPIV1Service` and held by the server (`server/server.go:77`); its goroutines are per-connection, driven by `Broadcast` calls from handlers, and torn down via `sseHub.Close()` on shutdown (`server/server.go:203-208`).

**Unused-infra note — `server/runner/memopayload` is never started as a runner.** The package defines a `Runner` with `NewRunner` and a batching `RunOnce` that rewalks every memo and rebuilds its payload (`server/runner/memopayload/runner.go:14-72`), but the server never constructs it: `startBackgroundRunners` only wires s3presign, `server/server.go` doesn't import the package, and the map returns a **certified zero** for callers of `memopayload.Runner.RunOnce`. Only the package's free function `RebuildMemoPayload` is used, called synchronously on the write path in `CreateMemo` (`server/router/api/v1/memo_service.go:108`) and on update (`:447`). So the batch-backfill capability exists and compiles but is dead as scheduled infrastructure — presumably a one-off migration tool left in place.
