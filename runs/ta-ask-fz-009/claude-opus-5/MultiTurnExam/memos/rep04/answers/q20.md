q20. **Server-Sent Events (SSE); server/router/api/v1/sse_hub.go; CreateMemo, UpdateMemo (via updateMemoAndBroadcast helper), DeleteMemo, CreateMemoComment, UpsertMemoReaction, DeleteMemoReaction**

**Mechanism** — SSE. The hub is a subscribe/broadcast fan-out (`SSEHub.Broadcast`, `SSEHub.Subscribe`/`Unsubscribe`), with the HTTP streaming endpoint in `server/router/api/v1/sse_handler.go` and event construction helpers in `server/router/api/v1/sse_event_helpers.go`.

**Broadcast sites, all through `s.SSEHub.Broadcast`:**

| Handler | Event type | Anchor |
|---|---|---|
| `CreateMemo` | `SSEEventMemoCreated` | `server/router/api/v1/memo_service.go:163` |
| `DeleteMemo` | `SSEEventMemoDeleted` | `server/router/api/v1/memo_service.go:585` |
| memo update path | `SSEEventMemoUpdated` | `server/router/api/v1/memo_update_helpers.go:71` (shared helper called by `UpdateMemo`, `server/router/api/v1/memo_service.go:401`) |
| `CreateMemoComment` | `SSEEventMemoCommentCreated` | `server/router/api/v1/memo_service_comments.go:126` |
| `UpsertMemoReaction` | `SSEEventReactionUpserted` | `server/router/api/v1/reaction_service.go:106` |
| `DeleteMemoReaction` | `SSEEventReactionDeleted` | `server/router/api/v1/reaction_service.go:161` |

Two design details worth knowing: events carry `Visibility` (`memo_service.go:166`) so the hub can filter delivery by what each subscriber is allowed to see — the visibility-vs-creator logic is exercised in `server/router/api/v1/sse_hub_test.go:188-236`. And comment creation deliberately suppresses the generic `memo.created` event via `withSuppressSSE(ctx)` / `isSSESuppressed` (`memo_service.go:162`, `memo_service_comments.go:55`), emitting `memo.comment.created` against the *parent* memo instead, so subscribers get one meaningful event rather than two.
