q29. **web/src/connect.ts; short-lived JWT access token (in-memory, `Authorization: Bearer`) + long-lived refresh token (HTTP-only cookie), with Personal Access Tokens as a third accepted kind server-side; server/auth**

**Interceptor.** `authInterceptor` at `web/src/connect.ts:156`, installed on the shared transport at `:188` — so every service client (lines 192-203) is authenticated by construction. Per request it resolves a token via `getRequestToken()` and sets `Authorization: Bearer <token>` (`:158-159`, helper at `:97`).

**Tokens it manages:**

- **Access token** — short-lived JWT held in module state (`./auth-state`: `getAccessToken`/`setAccessToken`, `web/src/connect.ts:4`), attached as a Bearer header. Backend comment confirms a 15-minute lifetime (`server/auth/authenticator.go:22`).
- **Refresh token** — never touched by JS; carried as a credentialed cookie via `fetchWithCredentials` (`credentials: "include"`, `web/src/connect.ts:57-62`) and exchanged through `AuthService.refreshToken` (`:75`).

Two refresh paths guard the seam: a **preflight** refresh when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` of expiry (`:140-147`) — explicitly to stop public endpoints like `ListMemos` returning guest-scoped data on a stale token — and a **reactive** retry on `Code.Unauthenticated` that refreshes, marks the request with `X-Retry` to prevent loops, and replays once, redirecting on failure (`:164-176`). Concurrent refreshes are deduplicated by `tokenRefreshManager` (`:30-51`, rationale at `:85-88`), and refresh runs on a **separate transport with no interceptors** (`:65-72`) to avoid recursion.

**Backend validation.** `server/auth` — `Authenticator` (`server/auth/authenticator.go:26`), documented as the shared path for the gRPC interceptor, Connect interceptor, and file server (`:17-19`). `AuthenticateByAccessTokenV2` validates the JWT statelessly with no DB hit (`:41-58`); `AuthenticateByRefreshToken` parses then checks the token row for revocation (`:61-79`). It also accepts **Personal Access Tokens** for programmatic access (`:23`), resolved through `Store.GetUserByPATHash` (`store/user_setting.go:128`).
