**Engine: CEL (Google Common Expression Language, `github.com/google/cel-go`) — `internal/filter/`, entry point `filter.Engine` at `internal/filter/engine.go:14`**

**Mechanism:** the CEL expression is compiled once into a dialect-agnostic condition tree, then rendered per-dialect into a parameterized SQL `WHERE` fragment plus args, with dialect differences supplied by per-field expression templates in the schema.

The two-stage split is the load-bearing design:

- **Parse** — `Engine.Compile` (`internal/filter/engine.go:48`) runs `env.Compile(filter)` against a CEL env built from a field schema (`NewEngine`, :24–34), converts the AST, and hands it to `buildCondition` (:62) producing a `Condition` tree — no SQL yet. `now` is frozen once per compile (:17–20) so one filter sees one instant.
- **Render** — `Program.Render(RenderOptions{Dialect, PlaceholderOffset, DisableNullChecks})` (:96) emits a `Statement{SQL string; Args []any}` (:90–93) via `internal/filter/render.go`. `PlaceholderOffset` is what lets the fragment be spliced into a larger query whose args already occupy `$1..$n` (Postgres numbering vs. `?`).

Dialect handling is declarative, in `internal/filter/schema.go`: `DialectName` ∈ sqlite/mysql/postgres (:13–17), and each field carries `Expressions map[DialectName]string` (:55) — a `%s` template wrapped around the column. Concrete examples:

- `creator` → `('users/' || %s)` on SQLite/Postgres vs. `CONCAT('users/', %s)` on MySQL (:104–108)
- `created_ts`/`updated_ts` → `UNIX_TIMESTAMP(%s)` on MySQL because it stores a `TIMESTAMP`, bare `%s` on Postgres/SQLite which store BIGINT epochs (:130–136, :143–149)

The schema also constrains what's expressible per field — `AllowedComparisonOps` and `SupportsContains` (:54–56) — so an unsupported operator fails at compile time rather than producing bad SQL. JSON payload fields get their own accessor path (`buildPostgresJSONAccessor`, `internal/filter/render.go:970`).

Two engines are memoized process-wide: `DefaultEngine()` for memos and `DefaultAttachmentEngine()` for attachments (:111–124), each `sync.Once`-initialized from its own schema.
