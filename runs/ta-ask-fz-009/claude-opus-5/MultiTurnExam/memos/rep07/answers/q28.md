**s3presign — `time.Ticker`, every 12 hours, plus one eager pass at startup**

That is the *only* background runner the server starts. Wiring, all in `server/server.go`:

- `Server.Start` calls `s.startBackgroundRunners(ctx)` at `server/server.go:129`.
- `startBackgroundRunners` (`:153–174`) builds `s3presign.NewRunner(s.Store)` (`:162`), fires `RunOnce(ctx)` immediately (`:163`), then launches `Run(s3Context)` in a goroutine tracked by a `WaitGroup` (`:166–171`).
- Scheduling lives in the runner itself: `runnerInterval = 12h` and a `time.NewTicker` loop that exits on `ctx.Done()` (`server/runner/s3presign/runner.go:27–41`). The work is re-presigning S3 attachment URLs in batches of 100, skipping any whose presigned URL is still valid for 4+ more days (`:85–91`).
- Shutdown is cooperative: a per-runner `context.CancelFunc` is stored (`:156–159`) and invoked by `stopBackgroundRunners` (`:176`), with `waitBackgroundRunners` (`:184`) bounding the wait.

**Unused-infra note:** `server/runner/memopayload` is present and complete but **never started by the server**. `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) — which rebuilds every memo's payload (tags/properties) from Markdown — has a **certified zero callers** in the graph, and `server/server.go` imports only `server/runner/s3presign` (`:25`), not memopayload. It has no ticker or scheduling of its own; it's a one-shot batch backfill with no invoker in the running system. Its exported helper `RebuildMemoPayload` (`:74`) *is* used elsewhere (the memo write path), so the package isn't dead — only the runner's batch entry point is unscheduled.
