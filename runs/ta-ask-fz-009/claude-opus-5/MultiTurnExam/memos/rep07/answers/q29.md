**web/src/connect.ts (`authInterceptor`, :156); short-lived access token in memory (Bearer header) + refresh token in an HTTP-only cookie, plus Personal Access Tokens as an alternate credential; server/auth**

**Interceptor** — `authInterceptor` at `web/src/connect.ts:156` is installed on the single shared transport (`:188`), so every service client inherits it. Its contract:

- attaches `Authorization: Bearer <token>` (`setAuthorizationHeader`, :97–100)
- **preflight refresh**: `getRequestToken` (:124) refreshes when the token is expired within a buffer (`isTokenExpired(REQUEST_TOKEN_EXPIRY_BUFFER_MS)`, :140) — the comment at :136–139 explains why this matters: on a *public* method like `ListMemos`, an expired token would silently degrade to guest-scoped data rather than 401
- **reactive retry**: on `Code.Unauthenticated`, refresh once, set `X-Retry: true`, replay (:164–172); a second failure calls `redirectOnAuthFailure()` (:174)
- concurrent refreshes are deduplicated by `tokenRefreshManager` (:30–51, :89) to avoid racing server-side token rotation against the on-focus refresher
- the refresh call itself uses a **separate transport with no interceptors** (`:65–72`) explicitly to prevent recursion, and all requests go out with `credentials: "include"` (`:57–62`) so the refresh cookie rides along

**Tokens** — access token held client-side in `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken`, imported at :4) and sent as a Bearer header; the refresh token is never read by JS — `refreshToken({})` (:75) relies on the cookie, and the response carries `accessToken` + `expiresAt` (:81–82). PATs are the third credential kind, minted via the `personalAccessTokens` endpoints on UserService.

**Backend validation** — package `server/auth`: `Authenticator.resolveBearer` (`server/auth/authenticator.go:149`) and `Authenticator.AuthenticateByRefreshToken` (`:61`) resolve the caller to a user via `Store.GetUser`, with signing/claims logic in `server/auth/token.go` and request-context plumbing in `server/auth/context.go` / `extract.go`. The API-side entry is `APIV1Service.fetchCurrentUser` (`server/router/api/v1/auth_service_session.go:246`), which nearly every handler calls; PAT lookups go through `Store.GetUserByPATHash` (`store/user_setting.go:128`).
