Two clarifications that matter for a blast-radius read:

- **Comment memos** add more `memo`/`memo_relation`/`attachment` rows, not new tables — the API handler deletes each comment child through a recursive `Store.DeleteMemo` first (`server/router/api/v1/memo_service.go:567–577`).
- **Not touched:** `reaction` (only *read* at `memo_service.go:545` to build the webhook payload) and `memo_share`. Since the schemas declare no foreign keys for these relationships (`store/migration/sqlite/LATEST.sql:47–52`), nothing deletes them implicitly either — those rows are orphaned.

One side effect outside the database: `Store.DeleteAttachment` also removes the backing blob (local file or object storage) via `deleteAttachmentStorageImpl` (`store/attachment.go:141`, :202–218) before issuing the row delete. And none of this runs in a transaction, so a failure partway leaves the memo present with relations or attachments already gone.
