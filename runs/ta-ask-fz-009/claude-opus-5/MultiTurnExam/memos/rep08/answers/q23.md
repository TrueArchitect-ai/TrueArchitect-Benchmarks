Two things about this stack that matter when changing a field:

- **There's a fifth layer you'd otherwise miss:** `proto/store/memo.proto` defines the protobuf shape for the memo's `payload` column — the `payload TEXT NOT NULL DEFAULT '{}'` field in the schema (`store/migration/sqlite/LATEST.sql:43`) is serialized `storepb` data, not relational columns. Location, tags, and similar nested attributes live there rather than in the SQL table or `proto/api/v1/`.
- **The store↔API translation is manual**, in `server/router/api/v1/memo_service_converter.go` — adding a field to both `store.Memo` and `message Memo` still leaves it unpopulated until the converter is updated. The Go and TypeScript generated files (`proto/gen/api/v1/memo_service.pb.go`, `web/src/types/proto/api/v1/memo_service_pb.ts`) regenerate from the proto and shouldn't be hand-edited.
