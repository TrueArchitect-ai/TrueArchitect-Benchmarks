**Two caveats on the numbers**

The counts are edge counts, not distinct-symbol counts, so "~53 references" is an upper-ish proxy for coupling weight; the package counts are the exact figures. Also, every envelope carried the same disclosure: `~writes`/`~reads` edges are a **lower bound** because SQL built by string concatenation isn't captured, and the IR set lacks `k:overrides`/`~event`/`~route` edges. Since the store drivers build queries by concatenation (as seen in the user-delete code), the true reference counts could be somewhat higher — but that gap falls inside the data layer, which I've excluded, so it doesn't disturb the ranking.
