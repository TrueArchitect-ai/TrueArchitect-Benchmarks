**How the hops work**

The route is registered on the `/file` Echo group at `server/router/fileserver/fileserver.go:122-124`, mapping `GET /file/users/:identifier/avatar` to `serveUserAvatar`. Note this URL is what the API itself hands the browser: `user_service_converters.go:36` rewrites `AvatarUrl` to `/file/%s/avatar` whenever the stored value is a base64 data URI, specifically to keep raw image bytes out of JSON responses (`server/router/api/v1/user_service_converters.go:31-38`).

`serveUserAvatar` (`:168`) does three things before touching data:
1. **Anonymous gate** — if `!s.Profile.AllowAnonymous()`, it resolves a viewer via `getCurrentUser` and 401s when absent (`:173-181`). On a public instance this branch is skipped entirely.
2. **Lookup** — `identifier` from the path goes to `getUserByUsername` (`:185`).
3. **Decode and guard** — `parseDataURI(user.AvatarURL)` (`:196`) extracts type and bytes, then `avatarAllowedTypes` (`:75`, checked at `:201`) restricts the MIME type before `c.Blob` writes the response with security headers and cache-control (`:205-209`).

`getUserByUsername` (`:715-717`) is a one-liner: `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`.

`Store.GetUser` (`store/user.go:148`) checks the `userCache` **only when `find.ID` is set** (`:149-156`). Since this path queries by username, the cache is bypassed on read; it delegates to `Store.ListUsers` (`:158`), takes the first row, and populates the cache keyed by ID (`:167`). `ListUsers` dispatches to the dialect driver selected by `store/db/db.go:14`.

**The key data-layer fact:** the avatar is not a file. It's stored inline on the user row as a base64 data URI in `user.AvatarURL` — which is why the trace terminates at the user table rather than at attachment storage or the filesystem.

**One caveat on the auth branch**

The map's `p2`–`p5` chains show `getCurrentUser` (`:708`) reaching the store independently through `auth.Authenticator.AuthenticateToUser` (`server/auth/authenticator.go:190`) via three credential routes — refresh-token cookie (`GetUserRefreshTokenByID`, `store/user_setting.go:210`), bearer access token (`resolveBearer` → `Store.GetUser`), and PAT (`AuthenticateByPAT` → `GetUserByPATHash`, `store/user_setting.go:128`). Those are the *viewer* lookups on private instances, a separate branch from the profile-owner lookup above.
