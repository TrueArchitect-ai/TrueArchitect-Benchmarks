**Where delivery executes**

`Post` marshals the payload, builds the `POST`, optionally signs it (Standard Webhooks HMAC-SHA256 → `webhook-id`/`webhook-timestamp`/`webhook-signature` headers, `webhook.go:133-150`), and fires the actual request at `webhook.go:152` via `safeClient.Do(req)`.

Callers never invoke it inline. `PostAsync` (`webhook.go:184`) enqueues onto a bounded 128-slot channel (`webhook.go:39`), drained by 4 worker goroutines started in `init()` (`webhook.go:42-55`) — so the real execution happens on those workers, decoupled from the request path. Overflow is dropped with a warning, not blocked (`webhook.go:191-195`). Triggers are in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

**The protection — two layers, one shared predicate**

1. **Dial-time enforcement (the load-bearing one).** The shared `safeClient` installs `DialContext: safeDialContext` (`webhook.go:32-37`). `safeDialContext` resolves the hostname itself and rejects the connection if *any* returned address is reserved, before dialing (`webhook.go:59-77`). Because the check happens at dial time on the resolved IPs, it also defeats DNS rebinding — the comment at `webhook.go:30-31` states this intent, and the code structure backs it.

2. **Admission-time validation.** `ValidateURL` (`validate.go:62`) rejects bad webhook URLs at registration: absolute-URL parse, http/https scheme only, and no reserved resolved IP — returning a gRPC `InvalidArgument` directly. Wired into create and update in `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

The blocklist is 8 CIDRs parsed once at startup (`validate.go:14-36`): IPv4 loopback, all three RFC-1918 ranges, `169.254.0.0/16` (explicitly covering cloud IMDS at 169.254.169.254), plus IPv6 loopback, unique-local, and link-local.

**Escape hatch worth knowing about**

`webhook.AllowPrivateIPs` (`validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers at once. It's set from the `allow-private-webhooks` config flag at `cmd/memos/main.go:49`. Two caveats visible in the code: it's a plain global `bool` mutated after startup and read by the dialer goroutines with no synchronization, and being a single toggle it's all-or-nothing — there's no per-webhook or per-range allowance.

Two gaps in the guard as written: `safeDialContext` validates the resolved set but then re-dials by *hostname* (`net.JoinHostPort(host, port)`, `webhook.go:76`), causing a second independent resolution — so the check is not strictly TOCTOU-free despite the rebinding claim. And there's no redirect policy on `safeClient`, though the custom `DialContext` still applies to redirect hops, so a redirect to `localhost` is caught at dial.
