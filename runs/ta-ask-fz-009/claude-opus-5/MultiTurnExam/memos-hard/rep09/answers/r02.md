**Adjacent protections that are not rate limits**

Two mechanisms limit *size* rather than *frequency*, and could be mistaken for throttling:

- `connect.WithReadMaxBytes(maxAPIRequestBytes)` caps request body size (`server/router/api/v1/v1.go:141`).
- Concurrency semaphores bound in-flight work — `semaphore.NewWeighted(3)` for thumbnail generation (`server/router/api/v1/v1.go:59`) and `thumbnailSemaphore` in the file server (`server/router/fileserver/fileserver.go:107`).

Neither counts requests per user or per window. If you need abuse protection on the API, it would have to be added — the natural insertion point is the Echo global chain at `server/server.go:51-52` for HTTP-wide coverage, or the Connect interceptor list at `v1.go:133` if you want per-RPC granularity with authenticated identity already resolved.
