**Two distinct enforcement *styles*, which is the architectural point**

**1. Post-fetch object gates** — load the memo, then decide. The canonical one is `checkMemoReadAccess` (`memo_service.go:39-68`): archived memos are creator-only (`:45-52`), then anything non-`Public` requires authentication (`:55-62`), and `Private` requires being the creator (`:63-65`). Note the asymmetry — `Protected` is satisfied by *any* signed-in user, matching the proto's documented semantics (`proto/gen/api/v1/memo_service.pb.go:35`).

**2. Pre-query filters** — never fetch what the viewer can't see. `ListMemos` sets `VisibilityList = [Public]` for anonymous callers (`memo_service.go:219`) and for signed-in callers injects a CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` (`:222-225`). That same filter string is repeated verbatim in three other places — `memo_relation_service.go:111`, `memo_service_comments.go:160`, `memo_service_converter.go:186` — which is duplicated policy worth consolidating.

**The non-gRPC surfaces**

`FileServerService.checkAttachmentPermission` (`fileserver.go:650-704`) is the most nuanced site, and it's a separate implementation from the API's — different error vocabulary (HTTP codes, not gRPC status) and extra branches: unlinked attachments are creator-or-admin only (`:652-663`); `Public` short-circuits **only if** `AllowAnonymous()` (`:677`); a valid non-expired `share_token` scoped to that memo bypasses the check entirely (`:684-689`); otherwise `Private` requires creator-or-admin (`:699`).

RSS enforces by construction rather than by check — both feed handlers hardcode `VisibilityList: []store.Visibility{store.Public}` (`rss.go:90`, `:141`), so protected memos never enter a feed even for authenticated users.

`server/notification/email.go:313-316` gates outbound *notifications* on visibility — arguably enforcement of a different kind (preventing content leakage via email) but the same invariant.

**Caveat:** these are read-path sites. Mutation authorization (`memo.CreatorID != user.ID && !isSuperUser(user)`) at `memo_service.go:426`, `:541`, `memo_share_service.go:43`, etc. is ownership enforcement, not visibility, so I've excluded it.
