**The computation**

`RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) is deliberately thin: ensure a non-nil `MemoPayload`, call `markdownService.ExtractAll([]byte(memo.Content))`, then assign exactly two fields:

```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property   // :85-86
```

It mutates the in-memory `*store.Memo` and does **not** persist — callers are responsible for writing `Payload` through. It also ignores its `context` parameter (`_ context.Context`), since the work is pure CPU over the content string.

The extraction itself is a **single goldmark AST walk** (`internal/markdown/markdown.go:371-411`), explicitly structured that way for efficiency rather than one pass per property:

| Derived value | Source condition | Line |
|---|---|---|
| `Tags` | `#tag` nodes, via `asMemoTagNode` | `:376-377` |
| `Property.Title` | first block-level child of the document, only if it's an H1 | `:383-389` |
| `Property.HasLink` | any `KindLink` node | `:393-394` |
| `Property.HasCode` | code block, fenced code block, or code span | `:396-397` |
| `Property.HasTaskList` | any GFM task checkbox | `:399-400` |
| `Property.HasIncompleteTasks` | a checkbox with `!IsChecked` | `:401-405` |

Tags are deduplicated with case preserved (`:418`). `ExtractAll` also collects `Mentions` (lowercased, `:379-380`), but `RebuildMemoPayload` discards them — mentions are consumed separately by `memo_mention_helpers.go:32` for notification targeting, not stored in the payload.

The `Title`/H1 rule is the subtle one: only the *first* block-level node is examined (`firstBlockChecked` latch at `:385`), so an H1 further down the document yields no title.

**One correction to a plausible assumption**

The earlier-noted `dispatchMemoUpdatedSideEffects` helper (`memo_update_helpers.go`) does **not** rebuild the payload — I grepped it for `RebuildMemoPayload|Payload` and got no matches. So `SetMemoAttachments` and `SetMemoRelations` fire *webhooks* but do not recompute derived metadata, which is correct behavior since neither alters memo content.

Also worth flagging: `Runner.RunOnce` is the only trigger that writes the recomputed payload itself, and as established earlier it is never constructed in production — `server/server.go` imports only `server/runner/s3presign`. So the backfill path exists but is currently unreachable at runtime; in practice metadata is only recomputed on create/update.
