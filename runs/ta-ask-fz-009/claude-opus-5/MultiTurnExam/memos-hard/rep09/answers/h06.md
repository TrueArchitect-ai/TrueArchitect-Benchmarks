**The two-stage fan-in**

All six handlers funnel through four thin dispatchers in `server/router/api/v1/memo_service_webhooks.go` — `DispatchMemoCreatedWebhook` (:15), `DispatchMemoUpdatedWebhook` (:20), `DispatchMemoDeletedWebhook` (:25), all delegating to `dispatchMemoRelatedWebhook` (:48), plus `DispatchMemoCommentCreatedWebhook` (:30) which is separate because it targets the *related memo owner's* hooks rather than the actor's.

Both direct callers load the URL from user configuration — `s.Store.GetUserWebhooks(...)`, then `payload.URL = hook.Url` (`:41` and `:67`) — and converge on the single call `webhook.PostAsync(payload)` (`:43`, `:71`).

**One distinction in the wording**

`PostAsync` (`internal/webhook/webhook.go:184`) is the convergence point, but it does not deliver: it enqueues onto a bounded 128-slot channel (`webhook.go:39`), dropping on overflow (`webhook.go:191-195`). The actual outbound request executes in `webhook.Post` (`internal/webhook/webhook.go:120`, firing at `:152`) on one of four worker goroutines started in `init()` (`webhook.go:42-55`). So if you want the last function *on the handler's own stack*, it's `PostAsync`; the delivery itself happens off-stack in `Post`.
