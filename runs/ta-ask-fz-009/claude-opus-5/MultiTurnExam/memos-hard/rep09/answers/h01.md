How it works:

- **What goes stale:** S3-backed attachments are served as presigned URLs stored in the attachment's `reference` column. Presigned URLs are minted with a 5-day expiry (`internal/storage/s3/s3.go:77`), so the stored link would eventually die.
- **The refresh loop:** `Runner.Run` ticks on `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27`, `29-41`), calling `RunOnce` → `CheckAndPresign`.
- **The work:** `CheckAndPresign` (`runner.go:47`) pages `store.ListAttachments` filtered to `AttachmentStorageType_S3` in batches of 100, skips any object whose `LastPresignedTime` is under 4 days old (`runner.go:85-91` — a 1-day safety margin against the 5-day expiry), otherwise re-presigns via `s3Client.PresignGetObject` and writes back both the new `Reference` and a fresh `LastPresignedTime` (`runner.go:108-123`).
- **Startup wiring detail:** line 163 calls `RunOnce(ctx)` synchronously on the parent context so stale links are repaired before serving; the recurring loop then runs in a goroutine on a dedicated cancellable `s3Context` (`server/server.go:156-159`) registered in `backgroundRunnerCancels` for clean shutdown via `stopBackgroundRunners` (`server/server.go:176`).

The consuming side is `FileServerService.getS3PresignedURL` (`server/router/fileserver/fileserver.go:408-409`), which serves S3 files by redirect rather than downloading — see also `server/router/fileserver/README.md:277`.
