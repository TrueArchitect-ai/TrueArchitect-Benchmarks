**The abstraction (`internal/idp/idp.go`)**

Thinner than "abstraction" usually implies. The package contains exactly one declaration — the `IdentityProviderUserInfo` struct (`internal/idp/idp.go:3-8`) with four fields: `Identifier`, `DisplayName`, `Email`, `AvatarURL`. There is **no Go interface** here. The shared contract is the normalized user-info *data type*, not a set of methods; the abstraction is structural (every provider must produce this struct) rather than a polymorphic dispatch point. The directory holds only `idp.go` plus the `oauth2` subpackage.

**The implementation (`internal/idp/oauth2`)**

OAuth2 is the only concrete protocol that ships — `internal/idp/oauth2/oauth2.go`, self-described at line 1 as "the OAuth2 identity provider integration." It provides `IdentityProvider` (line 20) wrapping a `storepb.OAuth2Config`, with two operations:

- `ExchangeToken` (line 47) — authorization-code exchange via `golang.org/x/oauth2`, with optional PKCE by injecting `code_verifier` (lines 63-66).
- `UserInfo` (line 83) — bearer-token GET against `UserInfoUrl`, then maps arbitrary JSON claims into `idp.IdentityProviderUserInfo` through the provider's configured `FieldMapping` (lines 115-140).

`NewIdentityProvider` (line 27) validates five required config fields up front — `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, `fieldMapping.identifier`.

**Corroboration that OAuth2 is the only kind**

The enum backing provider type has a single real member: `store.IdentityProvider_OAUTH2` alongside `TYPE_UNSPECIFIED` (`proto/gen/store/idp.pb.go:26`), mirrored on the API side at `proto/gen/api/v1/idp_service.pb.go:29`. The config wrapper likewise carries one variant, `IdentityProviderConfig_Oauth2Config` (`proto/gen/store/idp.pb.go:214`). So the schema, not just the filesystem, constrains this to one protocol — adding SAML or LDAP would require a proto change, not just a new package.

One naming caveat: `IdentityProvider` is a heavily overloaded name in this repo — the OAuth2 client type, the store row (`store/idp.go:12`), and both proto messages all share it. The `internal/idp` types are the plugin-side ones.
