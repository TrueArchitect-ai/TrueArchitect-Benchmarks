**Two separate premise failures.**

**1. No cleanup job exists.** Searching the whole repo for `cleanup|vacuum|purge|prune|nightly|cron` turns up no such job. Every cleanup-flavored hit is either a Go test helper (`t.Cleanup(...)`), an inline comment about deleting related rows (`server/router/api/v1/memo_service.go:579`, `server/router/api/v1/auth_service_sso.go:76`), or the scheduler package's own docs and tests.

**2. The scheduler itself is entirely unwired.** `[ArchMap query]` returns a **certified zero** — no caller at any depth. Corroborating by import: the only files that import `github.com/usememos/memos/internal/scheduler` are `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. Both are tests inside the package's own directory. No production file imports it, so `scheduler.New()` is never called outside tests and no job is ever registered.

**Where "2 AM" actually comes from.** The `0 2 * * *` expression appears in exactly two non-production places:
- `internal/scheduler/doc.go:15-16` — a package doc example registering a job literally named `"daily-cleanup"` with `Schedule: "0 2 * * *", // 2 AM daily`. This is illustrative prose, not code that runs.
- `internal/scheduler/example_test.go:97-99` — a runnable example with the comment "Cleanup old data every night at 2 AM" and `Name: "cleanup"`.

It's easy to mistake the first for real wiring, since a package doc reads like a description of the system. It describes the library's API, not this server's configuration.

**What the package genuinely is:** a general-purpose, dependency-free cron library (`internal/scheduler/doc.go:1-8`) with expression parsing (`ParseCronExpression`, `internal/scheduler/parser.go:30`), job validation (`internal/scheduler/job.go:48-50`), timezone support, and middleware (`Recovery`, `Logging`). It's complete and tested but currently shelf-ware.

**What actually runs on a schedule** is the one background runner from h01: the S3 presign refresh, on a **12-hour ticker interval** (`server/runner/s3presign/runner.go:27`), started in `Server.startBackgroundRunners` (`server/server.go:162-171`). That's interval-based, not wall-clock cron — it has no fixed time of day, and it refreshes presigned URLs rather than cleaning the database.
