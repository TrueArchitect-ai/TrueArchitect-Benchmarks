**Extracted properties.** `RebuildMemoPayload` writes exactly two fields onto `memo.Payload` (`runner.go:85-86`) — `Tags` and `Property` — from a single `ExtractAll` parse (`:80`). What `ExtractAll` produces (`internal/markdown/markdown.go:356-422`):

- **`Tags`** — every `#tag` node, lowercase-preserved and deduplicated (`:376-378`, `:418`), skipping tags nested inside links/images via `asMemoTagNode` (`:134-140`)
- **`Property.Title`** — text of the first block-level `H1`, only if it's the document's first block (`:384-389`)
- **`Property.HasLink`** — any link node (`:393-394`)
- **`Property.HasCode`** — fenced/indented code blocks or inline code spans (`:396-397`)
- **`Property.HasTaskList`** — any GFM task checkbox (`:399-400`)
- **`Property.HasIncompleteTasks`** — true if any checkbox is unchecked (`:401-405`)

`ExtractAll` also collects `Mentions` (`:379-381`), but note that `RebuildMemoPayload` **discards them** — only `Tags` and `Property` are persisted. Mentions are consumed elsewhere (notifications), not stored in the payload.

**Why this shape.** The properties are precomputed booleans and a title, persisted into the memo's `payload` JSON column, so list and preview queries can filter and render without re-parsing markdown per row — the filter engine reads them as indexed fields rather than parsing content at query time. The single-pass `ExtractAll` (versus calling `ExtractTags` + `ExtractProperties` separately) exists for the same reason: one AST walk per write. The tradeoff is that the derived data is only as fresh as the last create/update, and since the backfill runner is unwired, a change to extraction logic would not retroactively apply to existing memos.
