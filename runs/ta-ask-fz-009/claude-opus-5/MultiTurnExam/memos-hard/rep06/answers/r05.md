**Premise correction: there is no GraphQL. No schema file, no server, no resolvers. The public API is defined in Protocol Buffers and exposed as REST (gRPC-Gateway) + Connect RPC.**

**Why the premise fails.** A search for `graphql|gqlgen|\.graphql|resolver|apollo` finds **no GraphQL anything**. A glob for `**/*.{graphql,graphqls,gql}` returns **zero files**. The only `resolver` hits are unrelated: Go's DNS `net.DefaultResolver` (`internal/webhook/webhook.go:65`, `internal/httpgetter/html_meta.go:23`) and design-doc prose about a "user-token resolver" (`docs/plans/2026-03-24-user-resource-identifiers/design.md:53`). `go.mod` has no GraphQL library.

**Where the API contract actually lives: `proto/api/v1/*.proto`** — nine service definitions, the hand-authored source of truth:

`ai_service.proto`, `attachment_service.proto`, `auth_service.proto`, `common.proto`, `idp_service.proto`, `instance_service.proto`, `memo_service.proto`, `shortcut_service.proto`, `user_service.proto`

Everything else is generated from these into `proto/gen/`.

**The surface it produces — 81 HTTP doors**, in three tiers:

1. **REST via gRPC-Gateway (74 endpoints)** — AIP-style resource paths generated from `google.api.http` annotations in the protos, e.g. `GET /api/v1/memos`, `POST /api/v1/memos`, `PATCH /api/v1/{memo.name=memos/*}`, `DELETE /api/v1/{name=memos/*/reactions/*}` (`proto/gen/api/v1/memo_service.pb.gw.go:1745`); `GET /api/v1/users`, `GET /api/v1/{name=users/*}:getStats` (`user_service.pb.gw.go:2301`); auth at `POST /api/v1/auth/signin`, `GET /api/v1/auth/me` (`auth_service.pb.gw.go:331`). Note the AIP conventions GraphQL would have replaced: `name`/`parent` resource paths, custom methods with `:verb` suffixes, and `:batchGet` collection calls.

2. **Connect RPC** — the same services over the Connect protocol via `proto/gen/api/v1/apiv1connect/*.connect.go`, wired through the interceptor stack from r02 (`server/router/api/v1/connect_services.go`). This is the transport the web client uses; it and the gateway share one `Authorizer` so both enforce identical rules (`server/router/api/v1/authz.go:18-22`).

3. **Non-proto HTTP routes (7)** — hand-registered Echo handlers outside the protobuf contract: SSE streaming `GET /api/v1/sse` (`server/router/api/v1/sse_handler.go:25`), file serving `GET /attachments/:uid/:filename` and `GET /users/:identifier/avatar` (`server/router/fileserver/fileserver.go:132,168`), RSS `GET /explore/rss.xml` and `GET /u/:username/rss.xml` (`server/router/rss/rss.go:72,111`), SEO `GET /robots.txt`, `GET /sitemap.xml` (`server/router/frontend/frontend.go:128,143`), and `GET /healthz` (`server/server.go:44`).

**Practical upshot:** to change the public API you edit a `.proto` in `proto/api/v1/` and regenerate — the `proto/gen/` tree is build output, not a place to hand-edit. Frontend types come from the same source (`web/src/types/proto/api/v1/*_pb.ts`), which is how client and server stay in contract without a schema-introspection layer.
