**Premise correction: neither. There is no message broker at all — no NATS, no RabbitMQ, no queue declaration to point to. Webhook delivery uses an in-process buffered Go channel.**

**Why the premise fails.** A case-insensitive search for `nats|rabbitmq|amqp|kafka|pubsub|message.?broker|celery` across the repo returns **zero Go matches**. The only hits are unrelated noise: Google API proto comments mentioning Cloud Pub/Sub URLs in generated TypeScript (`web/src/types/proto/google/api/client_pb.ts:246`, `resource_pb.ts:45`) and Catalan locale strings that happen to contain the substring "nats" inside words like *predeterminats* (`web/src/locales/ca.json:393`). `go.mod` (read in r01) carries no broker client. There is no broker dependency, connection string, or queue/exchange declaration anywhere.

**The actual mechanism** — a bounded worker pool over a channel, all in `internal/webhook/webhook.go`:

- **The "queue"** is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`) — a plain Go channel with a 128-slot buffer. That line *is* the declaration; there is no external topic or exchange.
- **The consumers** are 4 goroutines started in `init()` (`:42-55`), each looping `for payload := range asyncPostQueue` and calling `Post(payload)` (`:46`), logging a warning on failure (`:47-50`).
- **The producer** is `PostAsync` (`:184`), which non-blockingly enqueues via `select` with a `default:` branch (`:189-195`).
- **Delivery** happens in `webhook.Post` (`:120`) — the convergence point from h06 — via `safeClient.Do(req)` (`:152`).

**Consequences that a broker would have changed, and are worth knowing:**

1. **Overflow drops silently-ish.** When the 128-slot buffer is full, `PostAsync` takes the `default:` branch and *discards* the event with a warning (`:191-195`). No blocking, no backpressure to the caller, no dead-letter queue.
2. **No durability.** The queue lives in process memory. A restart or crash loses every pending webhook — there is no redelivery, no ack/nack, no persistence.
3. **No retries.** `Post` returns an error that the worker only logs (`:47`). A failed delivery is not requeued.
4. **Per-process, not per-cluster.** Like the cache in r01, each replica has its own independent queue and 4 workers; concurrency is 4 per process, not 4 cluster-wide.

A sibling pattern exists for email — `email.asyncEmailQueue` (`internal/email/email.go:14`) — so this channel-plus-workers idiom is the codebase's general approach to async fire-and-forget work, deliberately avoiding external infrastructure.
