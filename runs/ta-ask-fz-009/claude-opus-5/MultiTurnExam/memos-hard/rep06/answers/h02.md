**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

**Where delivery executes.** `Post` (`internal/webhook/webhook.go:120`) marshals the payload, builds the POST, optionally attaches Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`, lines 133–150), and fires it with `safeClient.Do(req)` at line 152. Callers don't invoke it directly — memo events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43,71`), which enqueues onto a bounded 128-slot channel (line 39) drained by 4 worker goroutines started in `init()` (lines 42–55); each worker calls `Post`. Overflow is dropped with a warning rather than blocking the request path (lines 189–195).

**What protects it.** Two layers, sharing one predicate:

1. **Dial-time enforcement — the real protection.** `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`, defined at line 59). It re-resolves the host itself and rejects the connection if *any* returned address is reserved (lines 65–74). Because the check happens at dial time on every request, it also defeats DNS rebinding — the comment at lines 30–31 states this explicitly, and it's the reason the guard can't be bypassed by a hostname that validated clean at save time and later flips to `127.0.0.1`.

2. **Admission-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a user registers or updates a webhook URL (`server/router/api/v1/user_service_webhooks.go:74,161,182`), enforcing http/https scheme and resolving the host, returning gRPC `InvalidArgument` for reserved targets. This is UX — fail fast with a clear error — not the security boundary.

**The blocklist and its escape hatch.** `reservedCIDRs` (`internal/webhook/validate.go:14-23`) covers IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` (explicitly called out as cloud IMDS — the `169.254.169.254` credential-theft target), and IPv6 loopback/ULA/link-local. Parsed once at startup (lines 28–36). Both layers funnel through `isReservedIP` (line 44), which short-circuits to `false` when the package-level `AllowPrivateIPs` is set — wired from the `--allow-private-webhooks` flag at `cmd/memos/main.go:49` (declared line 133, bound line 160, default `false`). So self-hosters pointing webhooks at LAN services can opt out, and flipping that one flag disables both layers at once.

One gap worth noting: the guard is IP-range based, checked against resolved addresses. It does not restrict non-reserved-but-sensitive targets (e.g. a public IP fronting an internal service), and `safeDialContext` validates the addresses it resolves but then dials by hostname (line 76), so resolution happens twice — a narrow TOCTOU window remains between the check and the dial.
