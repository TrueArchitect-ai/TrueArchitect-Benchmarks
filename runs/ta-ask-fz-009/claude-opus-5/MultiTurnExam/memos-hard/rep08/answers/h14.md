**h14.**

**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `service.ExtractAll` — `internal/markdown/markdown.go:356`; Triggers: `CreateMemo`, `UpdateMemo` (content field only), `CreateMemoComment`; Extracted: `Tags` + `Property{Title, HasLink, HasCode, HasTaskList, HasIncompleteTasks}`**

**The computation is a thin façade over one AST walk.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) ensures a payload exists, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns exactly two fields — `memo.Payload.Tags` and `memo.Payload.Property` (`:85-86`). Note it mutates the passed-in memo rather than persisting; the caller is responsible for writing.

The real extraction is `service.ExtractAll` (`internal/markdown/markdown.go:356-422`), a **single** `gast.Walk` over the parsed document (the comment at `:79` and `:370` both flag this as a deliberate one-pass optimization):

| Extracted | rule | anchor |
|---|---|---|
| `Tags` | `#tag` nodes, deduplicated preserving case | `:376-378`, `:418` |
| `Property.Title` | text of the first block-level child *only if* it's an H1 | `:383-388` |
| `Property.HasLink` | any `KindLink` node | `:393-394` |
| `Property.HasCode` | code block, fenced code block, or inline code span | `:396-397` |
| `Property.HasTaskList` | any task checkbox | `:399-400` |
| `Property.HasIncompleteTasks` | a checkbox with `!IsChecked` | `:401-405` |

`Mentions` is also collected (`:379-381`) but **discarded** by `RebuildMemoPayload` — it never reaches the payload. The persisted shape is `MemoPayload_Property`, documented in the schema as "The calculated properties from the memo content" (`proto/gen/store/memo.pb.go:84-92`).

**Triggers** — three live paths, per `[ArchMap query]`:

- `CreateMemo` — `server/router/api/v1/memo_service.go:70`, invoked at `:108` after the length check, before insert.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:401`, invoked at `:447` **inside the `content` field-mask branch**, so recomputation happens only when content actually changes; the result is carried into `update.Payload` at `:451`. Renaming a tag or flipping visibility alone does not re-derive.
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20` (indirect, via `CreateMemo`).
- The Connect wrappers `ConnectServiceHandler.CreateMemo`/`UpdateMemo` (`server/router/api/v1/connect_services.go:306, 330`) reach the same code.

**One backfill path that never runs.** `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) walks all memos in batches of 100, rebuilding and persisting each via `Store.UpdateMemo` — the bulk-recompute tool. As established earlier in this session, it has zero callers and is never constructed in `startBackgroundRunners`, so in a running server derived metadata is refreshed *only* on the write paths above. A change to the extraction rules would not retroactively apply to existing memos without manually invoking that runner.
