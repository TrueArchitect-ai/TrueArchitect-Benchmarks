**r01.**

**Premise correction: there is no Redis anywhere in this codebase.** A case-insensitive search for `redis` across 1042 files returns zero matches — no client dependency, no config key, no connection string. There is nothing to configure, because the cache is not a network cache.

**Actual mechanism: a process-local, in-memory cache.** `store/cache/cache.go` implements `Cache` as a `sync.Map` with atomic item counting (`store/cache/cache.go:66-73`) behind the `cache.Interface` contract (`:11-32`). It is created by `cache.New` (`:76-85`), which spawns a background `cleanupLoop` goroutine (`:200-215`) rather than dialing anything. State lives in the server process and dies with it — no external service, and no sharing across replicas.

**"Configuration" is a Go struct literal, not connection settings.** `Store.New` builds a `cache.Config` inline at `store/store.go:40-45` and hands the same config to three separate cache instances (`:51-53`):

- `instanceSettingCache`
- `userCache`
- `userSettingCache`

(declared at `store/store.go:27-29`).

**TTL for user entries: 10 minutes.** `DefaultTTL: 10 * time.Minute` at `store/store.go:41`, matching `cache.DefaultConfig()` (`store/cache/cache.go:59`). Note it is *not* user-specific — all three caches share identical settings: 10-minute TTL, 5-minute cleanup interval, 1000-item cap.

Two behavioral details that matter more than the TTL number:

- **Expiry is enforced lazily on read as well as by the sweeper.** `Get` checks `time.Now().After(itm.expiration)` and deletes on the spot (`store/cache/cache.go:135-144`); the 5-minute `cleanup` pass (`:218-250`) is just reclamation. So a user entry is never served past 10 minutes even if the sweeper hasn't run.
- **Entries can be evicted well before 10 minutes.** Exceeding `MaxItems: 1000` triggers `cleanupOldest` (`:117-119`, `:253-313`), which drops ~20% of capacity. Under load, user entries expire by pressure, not age.

Relevant to correctness: `Store.GetUser` only consults `userCache` for lookups **by ID** (`store/user.go:149-156`) — username lookups always hit the database — and cache shutdown is wired into `Store.Close`, which calls `Close()` on all three caches before closing the driver (`store/store.go:72-79`).
