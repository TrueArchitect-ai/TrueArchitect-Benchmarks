**r05.**

**There is no GraphQL in this codebase.** No `.graphql`/`.gql`/`.graphqls` files exist anywhere (glob returns nothing), and a case-insensitive search for `graphql|gqlgen|apollo|resolver` finds only unrelated hits — Go's `net.DefaultResolver` in `internal/httpgetter/html_meta.go:23` and `internal/webhook/webhook.go:65`, plus the word "resolver" in design docs describing an AI provider lookup. No schema, no resolvers, no GraphQL dependency.

**Actual API surface: Protobuf-defined RPC, exposed three ways.** The schema of record is the `.proto` files under `proto/api/v1/` (e.g. `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`). `buf generate` produces the Go/TS bindings — and per `AGENTS.md:19`, generated proto output must never be hand-edited.

From those definitions, three transports are served:

1. **gRPC** — service interfaces in `proto/gen/api/v1/*_grpc.pb.go`.
2. **Connect** — handlers in `proto/gen/api/v1/apiv1connect/*.connect.go`, wired through `server/router/api/v1/connect_services.go`.
3. **REST/JSON via grpc-gateway** — 76 HTTP routes generated into `proto/gen/api/v1/*.pb.gw.go`, all under `/api/v1`, following Google AIP resource-name conventions (`memos/*`, `users/*`, `attachments/*`).

Note that the closest analogue to GraphQL's field selection here is not a query language over a graph but two orthogonal mechanisms: `google.protobuf.FieldMask` for partial updates (the `PATCH` routes) and a **CEL filter expression** for list queries — `ListMemos` accepts filters like `pinned == true && visibility == "PUBLIC"` compiled by `internal/filter/` against the schema in `internal/filter/schema.go`. New public endpoints must also be registered in `server/router/api/v1/acl_config.go` (`AGENTS.md:21`).
