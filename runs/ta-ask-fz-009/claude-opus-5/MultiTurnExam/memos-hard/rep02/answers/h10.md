### Why it's the hub

`addArg` (`internal/filter/render.go:842–849`) is the SQL placeholder allocator for the filter-expression renderer. Each call appends one value to `r.args`, bumps `r.placeholderCounter`, and returns the dialect-correct token — `$N` for Postgres (line 846), `?` otherwise (line 848).

That makes it the single chokepoint every filter clause must pass through to bind a parameter, which is exactly why the degree is so high: each comparison, predicate, and JSON-array construct in the renderer calls it once or twice. It's also the reason the codebase gets parameterized queries rather than string interpolation, and where the one dialect difference in placeholder syntax is isolated — the same role `postgres.placeholder` (`store/db/postgres/common.go:16`, in=105) plays at the store layer, which is the repo-wide Go leader per `[ArchMap query]` but sits outside `internal/`.
