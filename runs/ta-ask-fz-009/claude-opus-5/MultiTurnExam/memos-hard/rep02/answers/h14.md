### Computation site

Two layers:

- **`RebuildMemoPayload`** (`server/runner/memopayload/runner.go:74–88`) is the assignment point. It ensures `memo.Payload` is non-nil (lines 75–77), calls `ExtractAll` on `memo.Content` (line 80), then writes back exactly two fields: `memo.Payload.Tags` and `memo.Payload.Property` (lines 85–86).
- **`ExtractAll`** (`internal/markdown/markdown.go:356–422`) does the work: one goldmark parse (line 357) followed by a **single AST walk** (`gast.Walk`, line 371) that collects everything at once — the comment at line 79 and line 355 both flag this as a deliberate efficiency choice over multiple passes.

The third call site, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:52`), never executes in production — per h08 that method has zero callers (certified zero). So only the two API paths matter at runtime.

### What gets extracted

**Tags** — from custom tag nodes (`markdown.go:376–378`), deduplicated with case preserved via `uniquePreserveCase` (line 418).

**`Property`** (`storepb.MemoPayload_Property`), five fields:
- `Title` — text of the first block-level child *only if* it is an H1 heading (lines 384–389); the `firstBlockChecked` latch means a later H1 is ignored.
- `HasLink` — any `KindLink` node (lines 393–394).
- `HasCode` — code block, fenced code block, or inline code span (lines 396–397).
- `HasTaskList` — any task checkbox (lines 399–400).
- `HasIncompleteTasks` — set additionally when a checkbox is unchecked (lines 401–405).

**Also computed but discarded:** `ExtractAll` populates `data.Mentions` (lines 379–381, lowercased and deduped at line 419), yet `RebuildMemoPayload` never copies it into the payload. Mentions are consumed on a separate path — `s.MarkdownService.ExtractAll` in `server/router/api/v1/memo_mention_helpers.go:32` — for notification purposes rather than persisted preview metadata.

### Consequence

Because recomputation is bound to the two write paths, the stored payload is only as current as the last content write. If extraction logic changes (a new property, different title rule), existing rows keep stale metadata — there is no live backfill, since the one component built for that job (`memopayload.Runner`) is unwired.
