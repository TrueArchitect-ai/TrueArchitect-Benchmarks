### The abstraction: `internal/idp`

Deliberately minimal — the package contains exactly one file, `internal/idp/idp.go`, defining a single struct `IdentityProviderUserInfo` (line 3) with four fields: `Identifier`, `DisplayName`, `Email`, `AvatarURL`.

Worth being precise about what kind of abstraction this is: **there is no Go interface here.** The boundary is a shared *data contract*, not a polymorphic dispatch point. `internal/idp` is the normalized user-identity shape that any provider must produce; it owns no behavior and imports nothing. Concrete providers depend on it (one-directional), which is why the dependency arrow runs `oauth2 → idp` and never back (`internal/idp/oauth2/oauth2.go:15`).

### The implementation: `internal/idp/oauth2`

`internal/idp/oauth2/oauth2.go`, self-described at line 1 as "Package oauth2 implements the OAuth2 identity provider integration." It provides `IdentityProvider` (line 20), wrapping a `*storepb.OAuth2Config`, with three entry points:

- `NewIdentityProvider` (line 27) — fail-fast construction requiring `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier`.
- `ExchangeToken` (line 47) — authorization-code exchange via `golang.org/x/oauth2`, with optional PKCE by passing `code_verifier` (lines 63–66).
- `UserInfo` (line 83) — fetches the userinfo endpoint and maps arbitrary provider claims into `idp.IdentityProviderUserInfo` (line 114).

That claim mapping is where the abstraction earns its keep: because provider JSON shapes differ, the config carries a `FieldMapping` and `UserInfo` projects those configured claim names onto the fixed struct. `Identifier` is mandatory and errors if absent or empty (lines 118–120); the optional fields are best-effort, with `DisplayName` falling back to `Identifier` (lines 128–130).

### OAuth2 is the only implementation

Confirmed at two levels, not just by directory listing:

- **Filesystem**: `internal/idp/` contains only `idp.go` and the `oauth2/` subpackage.
- **Schema**: `proto/api/v1/idp_service.proto:83` defines `IdentityProviderConfig` as a `oneof config` with exactly one member, `OAuth2Config oauth2_config = 1` (line 85), and the `Type` enum has a single non-zero value `OAUTH2 = 1` (line 79).

The `oneof` plus single-valued enum is the extension point — the schema is shaped to admit additional provider types (SAML, LDAP) without breaking wire compatibility, but only the OAuth2 arm is populated today.
