### Why the two-part structure matters

Ordering is deliberate: both reaction deletes run *before* `deleteMemosTx` (`store/db/sqlite/user_delete.go:120`) and `deleteUserRowTx` (line 123). Since no FK cascade exists, removing the memo or user rows first would orphan reaction rows permanently — nothing in the schema would clean them up. The Go code is the *only* mechanism, so its sequencing is load-bearing rather than incidental.

The `memo_share` contrast is instructive: that table does get a real `ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`), yet `deleteMemoSharesTx` is still called explicitly (line 105). So this codebase does not uniformly delegate to the database — reactions are purely application-enforced, and all three dialects must be kept in lockstep by hand.
