**Premise correction: there is no Redis in this codebase.** A case-insensitive search for `redis` across all 1042 files returns **zero matches**, and `go.mod`'s 142 dependencies contain no Redis client (no `go-redis`, no `redigo`). There is no Redis connection to configure — no host, port, DSN, or pool setting exists.

**Actual mechanism: a process-local, in-memory cache.** `store/cache/cache.go` implements `Cache` as a `sync.Map` of `item{value, expiration, size}` (`cache.go:35-39, 67-73`) with a background sweeper goroutine started in `New` (`cache.go:83`). No network client, no serialization — cached values are live Go pointers.

**Configuration site and the user TTL.** Config is set in code, not in any config file, at `store.New` — `store/store.go:40-45`:

```
DefaultTTL:      10 * time.Minute
CleanupInterval: 5 * time.Minute
MaxItems:        1000
```

**So user entries live 10 minutes.** The same `cacheConfig` value is passed to all three caches — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`) — so there is no user-specific TTL; users, user settings, and instance settings share identical parameters. `Cache.Set` stamps `expiration: time.Now().Add(ttl)` using `DefaultTTL` (`cache.go:93-94`, `:112`). `cache.DefaultConfig()` (`store/cache/cache.go:57-64`) declares the same three values, but note `store.New` **duplicates them literally** rather than calling it — two independent copies of the same numbers, so changing `DefaultConfig` would silently not affect the running store.

**Two consequences of it being in-process rather than Redis, worth stating plainly:**

1. **Expiry is lazy plus swept.** `Get` evicts on read if expired (`cache.go:135-144`); the `cleanupLoop` ticker sweeps every 5 minutes (`cache.go:200-215`). So a stale user can persist in the map past 10 minutes but will never be *returned* past it.
2. **No cross-instance coherence.** Nothing shares this cache. Running two memos instances against one database means each has its own `userCache`, and an update on node A leaves node B serving a stale user for up to 10 minutes — `Store.UpdateUser` only refreshes its own local map (`store/user.go:132`). That's the real architectural implication of the missing Redis: this design assumes single-instance deployment.

Bounding is by count, not bytes — `MaxItems: 1000` triggers `cleanupOldest`, which evicts roughly 20% (`cache.go:253-255`). The `size` field and `estimateSize` (`cache.go:316`) are computed but never actually used for eviction decisions.
