**Premise correction: there is no GraphQL anywhere in this codebase.** A case-insensitive search for `graphql|gqlgen|\.graphql|apollo` returns zero code matches (only coincidental "resolver" hits in unrelated design docs and Go's `net.DefaultResolver`), and a glob for `**/*.{graphql,gql,graphqls}` finds no schema files. No schema, no resolvers, no GraphQL endpoint.

**Actual API surface: Protobuf/gRPC service definitions, exposed three ways.** The contract is declared in nine `.proto` files under `proto/api/v1/` — `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto`. Those are the schema you're looking for; everything under `proto/gen/` is generated from them.

Each service is reachable over three transports simultaneously:
1. **gRPC** — from the generated `*_grpc.pb.go` service descriptors
2. **Connect RPC** — `proto/gen/api/v1/apiv1connect/*.connect.go`, wired at `server/router/api/v1/connect_services.go`
3. **REST/JSON via grpc-gateway** — HTTP annotations in the `.proto` files produce the `*.pb.gw.go` route tables, registered by `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`)

**The REST surface is 81 endpoints**, all AIP-style resource-oriented rather than query-language driven — e.g. `GET /api/v1/memos`, `POST /api/v1/memos`, `PATCH /api/v1/{memo.name=memos/*}`, `DELETE /api/v1/{name=memos/*}`, `GET /api/v1/{parent=users/*}/webhooks`, `POST /api/v1/users:batchGet`.

**Where the GraphQL-shaped needs are met instead**, since that's usually the reason for the question:
- **Field selection** → grpc-gateway/Connect field masks (`update_mask` on PATCH methods)
- **Arbitrary filtering** → a **CEL expression** `filter` parameter compiled to SQL by `internal/filter/` — that's the closest thing to a query language here, e.g. `pinned == true && visibility == "PUBLIC"` (documented at `proto/gen/api/v1/memo_service.pb.go:550-558`)
- **Batch fetching** → explicit `:batchGet` custom methods rather than a query graph
- **Subscriptions** → Server-Sent Events at `GET /api/v1/sse` (`server/router/api/v1/sse_handler.go:25`)

Non-RPC HTTP doors also exist outside `/api/v1`: the fileserver (`/attachments/:uid/:filename`, `/users/:identifier/avatar`), RSS feeds (`/explore/rss.xml`, `/u/:username/rss.xml`), `/robots.txt`, `/sitemap.xml`, and `/healthz`.
