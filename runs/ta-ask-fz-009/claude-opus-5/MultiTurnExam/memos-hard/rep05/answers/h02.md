**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual `safeClient.Do(req)` at line 152); protection is `safeDialContext` wired as the shared client's `Transport.DialContext` — `internal/webhook/webhook.go:59` (+ the reserved-CIDR list and `isReservedIP` in `internal/webhook/validate.go:14-54`).**

**Delivery path.** Memo mutations call `DispatchMemoCommentCreatedWebhook` / `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:30`, `:48`), which hand off to `webhook.PostAsync` (`internal/webhook/webhook.go:184`). `PostAsync` only enqueues onto a buffered channel (`asyncPostQueue`, cap 128, `:39`); four worker goroutines started in `init()` (`:42-55`) drain it and call `Post`. So `Post` is where the HTTP request is built, signed, and executed — nothing on the request path blocks on the network.

**The protection is layered, and the layers differ in strength:**

1. **Dial-time enforcement (the real guard).** All dispatches share one `http.Client` whose transport dials through `safeDialContext` (`internal/webhook/webhook.go:32-37, 59-77`). It re-resolves the host at connect time and refuses if *any* returned IP is reserved. Because the check happens at the moment of connection rather than at save time, this defeats **DNS rebinding** — a hostname that validated as public when the webhook was created but later resolves to `169.254.169.254` still fails to dial. The blocked ranges cover loopback, all three RFC-1918 blocks, link-local/cloud IMDS, and IPv6 loopback/ULA/link-local (`internal/webhook/validate.go:14-23`).

2. **Admission-time validation (defense in depth / good errors).** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a webhook is registered or edited — `CreateUserWebhook` and `UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53`, `:106`) — enforcing absolute URL, http/https scheme only, and non-reserved resolution. This rejects bad config with a gRPC `InvalidArgument` instead of failing silently later, but it is *not* the security boundary on its own; it's TOCTOU-prone by nature.

**Both layers share one kill switch.** `isReservedIP` returns `false` unconditionally when `webhook.AllowPrivateIPs` is set (`internal/webhook/validate.go:44-47`), and that flag is bound from the `--allow-private-webhooks` CLI flag / config key in `cmd/memos/main.go:49` (declared at `:133`, default `false`). Set it and SSRF protection is off at *both* validation and dial time — deliberate, for self-hosters pointing webhooks at LAN services, but worth knowing it's a single global with no per-webhook granularity.

Two adjacent hardening details in `Post` worth noting: the response body is read through `io.LimitReader(resp.Body, 1<<20)` (`:158`) so a hostile receiver can't exhaust memory, and the client carries a 30s timeout (`:27`). Requests are signed per the Standard Webhooks scheme — `webhook-id` / `webhook-timestamp` / `webhook-signature` HMAC-SHA256 over `msgID.timestamp.body` (`:139-149`).
