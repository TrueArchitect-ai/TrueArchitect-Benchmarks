**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating the parse to `markdown.service.ExtractAll` — `internal/markdown/markdown.go:356`.**

**Triggers (three production call sites):**

- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, unconditionally on every new memo, before `Store.CreateMemo` at `:115`
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, **only** when the field mask contains `content` (`:436`); the recomputed payload is attached to the update at `:451`
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20`, indirectly, because comments are memos created through `CreateMemo`

Both API entry points are also reachable via their Connect wrappers (`server/router/api/v1/connect_services.go:306`, `:330`) — same handler, second transport. A fourth potential trigger, the batch backfill `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), exists but is never invoked from production code — it isn't wired into `startBackgroundRunners`.

**What the computation extracts** — `RebuildMemoPayload` writes exactly two fields onto `memo.Payload` (`server/runner/memopayload/runner.go:85-86`):

1. **`Tags`** — deduplicated `#tag` list, case preserved, from AST `TagNode`s; tags inside links or images are deliberately excluded (`internal/markdown/markdown.go:376`, filter at `:134-140`, dedup at `:418`)
2. **`Property`** (a `storepb.MemoPayload_Property`) with five derived flags/values, all from a single AST walk (`internal/markdown/markdown.go:384-405`):
   - `Title` — text of an H1 only if it is the document's first block (`:386-388`)
   - `HasLink` — any link node (`:393`)
   - `HasCode` — code block, fenced code block, or inline code span (`:396`)
   - `HasTaskList` — any task checkbox (`:400`)
   - `HasIncompleteTasks` — at least one unchecked checkbox (`:401-403`)

Two design points worth flagging. `ExtractAll` also returns `Mentions` (`internal/markdown/markdown.go:379-381`), but `RebuildMemoPayload` ignores that field — mentions are consumed separately on the notification path (`server/router/api/v1/memo_mention_helpers.go:32`). And the payload is *derived cache*, not user input: `CreateMemo` overwrites it wholesale before persisting, then layers user-set `Location` on top afterwards (`memo_service.go:111-113`), so any client-supplied tags or properties are discarded. The consequence is that a change to the extraction rules leaves existing rows stale — which is presumably what the dormant `RunOnce` backfill was for.
