**Premise correction: there is no nightly database-cleanup job, and nothing at all is registered with the cron scheduler. The question has two false premises — the job doesn't exist, and the scheduler isn't wired into the running server.**

What I established:

- **No cleanup job exists.** A case-insensitive search for `cron|nightly|cleanup.*job|vacuum` across the Go sources returns hits only inside `internal/scheduler` itself (its own parser/docs) plus one unrelated user-agent string in a test (`store/test/user_setting_test.go:982`). No `VACUUM`, no purge/prune/retention job.
- **The scheduler is a library with zero production consumers.** `[ArchMap query]` returns a **certified zero** — no callers at any depth, including after widening probes. Every `scheduler.New(...)` / `s.Register(...)` occurrence in the repo is in the package's own docs and tests: `internal/scheduler/doc.go:12-28`, `example_test.go`, `integration_test.go`. So `internal/scheduler` (`scheduler.go:12`, `Register` at `:70`, `Start` at `:91`) is built and tested but never instantiated by the server.
- **The server's actual background machinery is not cron-based.** `Server.startBackgroundRunners` (`server/server.go:153-174`) registers exactly one periodic task, and it uses a plain `time.Ticker`, not a cron expression: the S3 presign runner on a 12-hour interval (`server/runner/s3presign/runner.go:27`, ticker loop at `:29-41`, wiring at `server/server.go:162-171`). That's URL refresh, not cleanup.

Where deletion/cleanup logic *does* live, for contrast — it's all request-driven, not scheduled:

- Cascading user deletion inside a transaction — `store/db/sqlite/user_delete.go:29` (and the mysql/postgres peers), invoked from the API on demand.
- In-memory cache expiry sweeps every 5 minutes — `store/cache/cache.go:200-215` — a per-cache goroutine, unrelated to the scheduler.

So if you need a nightly cleanup, the pieces exist but are unconnected: you'd instantiate `scheduler.New()` and `Register` a job in `startBackgroundRunners` (`server/server.go:153`), which is currently the only place background work is started.
