**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`) — OAuth2 is the only concrete protocol that ships.**

Details:

- **The abstraction is deliberately thin.** `internal/idp/idp.go` contains exactly one type — `IdentityProviderUserInfo` with `Identifier`, `DisplayName`, `Email`, `AvatarURL` (`internal/idp/idp.go:3-8`). There is no Go `interface` for providers; the shared contract is the normalized user-info struct that every implementation must produce. Polymorphism, such as it is, lives in the protobuf discriminator instead.
- **The implementation** is `internal/idp/oauth2/oauth2.go`, whose `IdentityProvider` struct wraps a `storepb.OAuth2Config` (`:20-22`) and exposes the two-step flow: `ExchangeToken` (`:47`, code→access token, with optional PKCE `code_verifier` at `:64-66`) and `UserInfo` (`:83`, Bearer call to `UserInfoUrl`, returning the shared `idp.IdentityProviderUserInfo` at `:114`). `NewIdentityProvider` (`:27`) enforces required config — `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, `fieldMapping.identifier`.
- **Provider-agnostic claim mapping** is what lets one OAuth2 implementation cover many vendors: claims are pulled out of the userinfo JSON by configured field names rather than fixed keys (`:115-140`), with `DisplayName` falling back to `Identifier` (`:128-130`).
- **The type system confirms OAuth2 is the sole variant.** The enums carry only `TYPE_UNSPECIFIED` and `OAUTH2` (`proto/gen/store/idp.pb.go:26`, `proto/gen/api/v1/idp_service.pb.go:29`), and the config oneof has a single arm, `IdentityProviderConfig_Oauth2Config` (`proto/gen/store/idp.pb.go:214`). So adding SAML or OIDC-native would require a new proto variant, not just a new package.
