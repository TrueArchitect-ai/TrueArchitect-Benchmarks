Enforcement is spread across nine distinct surfaces. Grouped by kind, since the mechanism differs:

**Direct per-memo access checks (deny an individual memo)**
- `APIV1Service.GetMemo` visibility gate — `server/router/api/v1/memo_service.go:55-63` (non-public requires a viewer; `Private` requires creator)
- `FileServerService.checkAttachmentPermission` — `server/router/fileserver/fileserver.go:677`, `:699` (attachment inherits its memo's visibility; share-token fallback at `:684-689`)
- `APIV1Service.checkAttachmentAccess` — `server/router/api/v1/attachment_service.go:445`, `:451`
- `SSEClient.canReceive` — `server/router/api/v1/sse_hub.go:135-141` (real-time delivery filter; unknown visibility denied by default)

**Query-scoping (visibility folded into the SQL/filter predicate so invisible memos never load)**
- `APIV1Service.ListMemos` — `server/router/api/v1/memo_service.go:219-225` (`VisibilityList` = `{Public}` anonymous, `{Public, Protected}` + own-creator filter authenticated)
- `user_service_stats` — `server/router/api/v1/user_service_stats.go:84-90`, `:218-220`
- Comment and relation listing filters — `server/router/api/v1/memo_service_comments.go:158-160`, `server/router/api/v1/memo_relation_service.go:109-111`, `server/router/api/v1/memo_service_converter.go:184-186`
- Public-only unauthenticated surfaces: RSS — `server/router/rss/rss.go:90`, `:141`; frontend SSR/sitemap — `server/router/frontend/frontend.go:150`

**Write/interaction gates (visibility governs who may act on a memo)**
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:41`
- `UpsertMemoReaction` / `DeleteMemoReaction` — `server/router/api/v1/reaction_service.go:30-38`, `:83`
- `SetMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-222`

**Notification/leak prevention (visibility limits what is disclosed outward)**
- Mention notification eligibility — `server/router/api/v1/memo_mention_helpers.go:62`, `:67`, `:84`
- Email notification content redaction — `server/notification/email.go:313-316` and `server/router/api/v1/user_service_notifications.go:309-312`

Two observations about this shape. There is **no central authorization helper** — each site re-implements the same predicate inline, and the recurring idiom `memo.Visibility == store.Private && memo.CreatorID != user.ID && !isSuperUser(user)` appears verbatim in at least four files (`attachment_service.go:451`, `memo_attachment_service.go:222`, `memo_service_comments.go:41`, `reaction_service.go:38`). Notably `memo_service.go:63` omits the `isSuperUser` clause, so `GetMemo` is stricter for admins than the interaction paths. Second, the ACL config explicitly delegates: `server/router/api/v1/acl_config.go:32` marks memo endpoints public with the comment that "visibility filtering [is] done in service layer" — so the middleware is deliberately *not* an enforcement point, which is why the invariant must hold at every one of the sites above.
