**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at line 152); protection is a two-layer SSRF guard: dial-time IP blocking via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`, plus admission-time `webhook.ValidateURL` — `internal/webhook/validate.go:62`.**

The delivery path:

- Callers never dial directly — they call `webhook.PostAsync` (`internal/webhook/webhook.go:184`) from `dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:71`, `:43`). That enqueues onto a bounded 128-slot channel (`webhook.go:39`), drained by 4 worker goroutines started in `init()` (`webhook.go:42-55`), each calling `Post`. Overflow is dropped with a warning rather than blocking the request (`webhook.go:191-195`).
- `Post` marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, `webhook.go:139-149`), then issues the request through the shared `safeClient` (`webhook.go:32-37`, 30s timeout).

Why the protection holds:

- **Enforcement point is the dialer, not the URL string.** `safeClient`'s `Transport.DialContext` is `safeDialContext` (`webhook.go:35`), which resolves the host itself and rejects the connection if *any* resolved address is reserved (`webhook.go:65-74`). Because the check happens at connect time on every request, it also defeats DNS rebinding — a hostname that validated as public at registration cannot later resolve to `127.0.0.1` and get through.
- **Blocked ranges** are the parsed `reservedCIDRs` list (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (explicitly covering cloud IMDS at 169.254.169.254), plus IPv6 loopback, unique-local, and link-local.
- **Second, earlier layer**: `ValidateURL` (`validate.go:62`) runs at webhook registration — `CreateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53`) and `UpdateUserWebhook` (`:106`) — requiring an absolute `http`/`https` URL that resolves off the reserved ranges, returning gRPC `InvalidArgument`. This is UX/fail-fast; the dialer is the real boundary.
- **Escape hatch**: both layers share `isReservedIP`, which short-circuits to `false` when the global `webhook.AllowPrivateIPs` is set (`validate.go:45-47`). That flag is bound from the `allow-private-webhooks` config at `cmd/memos/main.go:49` — so self-hosters can deliberately disable SSRF protection instance-wide.

Secondary hardening in the same path: the response body is capped at 1 MiB via `io.LimitReader` (`webhook.go:158`), and signing secrets are validated for control characters that would corrupt signature headers (`ValidateSigningSecret`, `validate.go:90`).
