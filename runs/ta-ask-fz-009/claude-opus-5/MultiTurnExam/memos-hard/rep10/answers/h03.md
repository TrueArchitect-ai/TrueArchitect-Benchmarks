### What the abstraction actually is

Worth being precise here, because it's thinner than the name suggests: `internal/idp` defines **no interface**. The whole package is one shared DTO — `IdentityProviderUserInfo` with `Identifier`, `DisplayName`, `Email`, `AvatarURL` (`internal/idp/idp.go:3-8`).

So the boundary is a **common return type**, not a polymorphic contract. `internal/idp` is the shared vocabulary; the provider "interface" is implicit in the method set of `oauth2.IdentityProvider` (`internal/idp/oauth2/oauth2.go:20`):

- `ExchangeToken(ctx, redirectURL, code, codeVerifier)` — line 47
- `UserInfo(ctx, token)` — line 83, returning `*idp.IdentityProviderUserInfo`

Dependency direction is correct — `oauth2` imports `idp` (line 15), never the reverse — so adding a second provider wouldn't require touching the shared package. But since nothing is programmed against an interface, callers hold the concrete `*oauth2.IdentityProvider`; a second protocol would mean extracting an interface first. This is a reasonable YAGNI position given one implementation ships, just not the plug-in architecture the package layout hints at.

### Implementation notes

`NewIdentityProvider` (line 27) validates five required config fields up front — `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier`. It leans on `golang.org/x/oauth2` for the exchange with `AuthStyleAutoDetect` (line 56), and **supports PKCE** by passing `code_verifier` when supplied (lines 64–66).

The genericity that makes it work with arbitrary providers lives in `FieldMapping`: `UserInfo` unmarshals the userinfo response into `map[string]any` and pulls claims by configured key name (lines 110–140). `Identifier` is mandatory — empty means hard failure (line 118) — while display name, email, and avatar are best-effort, with display name falling back to the identifier (lines 128–130).

One asymmetry to flag: this outbound userinfo call uses a plain `http.Client` with a 10s timeout (line 84) and **no SSRF guard** — unlike the webhook path, which routes through `safeDialContext`. IdP config is admin-only, so the exposure is narrower, but the protection is not shared between the two outbound-HTTP surfaces.
