### Notable details along the path

**The image is not a file on disk.** The avatar is stored as a **base64 data URI in the user row's `avatar_url` column**. `serveUserAvatar` reads `user.AvatarURL` and decodes it with `s.parseDataURI` (`fileserver.go:196`), then writes bytes via `c.Blob` (line 209). So "stored data" here means the user table, not the attachment/S3 subsystem — this endpoint never touches `store.Attachment`.

That also explains why the route exists at all: `convertUserToProto` rewrites the API response field to `/file/{user}/avatar` instead of inlining the base64 blob (`server/router/api/v1/user_service_converters.go:32-36`), specifically "to reduce the response size." The browser then follows that URL here.

**Two gates before the data hop:**

1. *Anonymous access* — if `!s.Profile.AllowAnonymous()` (a private instance with no InstanceURL), the handler requires a valid session/PAT via `getCurrentUser` → `authenticator.AuthenticateToUser` (`fileserver.go:173-181`, helper at `:708-712`) and returns 401 otherwise. On a public instance, any browser can fetch any user's avatar — which is the intended behavior for a public profile image.
2. *MIME allowlist* — `avatarAllowedTypes` (`fileserver.go:75`) is checked **after** decode (line 201), rejecting anything outside PNG/JPEG/GIF/WebP with a 400. Paired with `setSecurityHeaders` (line 205), this is the XSS defense against a stored SVG/HTML data URI; there's a matching upload-time check in `server/router/api/v1/user_service.go:337-351`.

**The lookup is cache-fronted.** `Store.GetUser` calls `cache.Cache.Get`/`Set` (`store/cache/cache.go:123`, `:93`) keyed by `store.userCacheKey` (`store/user.go:88`), and only falls through to `Store.ListUsers` → `Driver.ListUsers` on a miss. So a warm avatar request may resolve with **no database query at all**.

One inefficiency worth flagging: the lookup goes through `ListUsers` — a list query narrowed by `store.FindUser{Username: &identifier}` (`fileserver.go:716`) — rather than a dedicated single-row fetch. That's the general shape of the store layer, not specific to avatars.
