### What it does

The stale-link problem is real because S3 presigned URLs are generated with a **5-day expiry** (`internal/storage/s3/s3.go:77`, `PresignGetObject` at line 71). The `reference` column stored on each attachment holds that presigned URL, so without maintenance every S3-backed attachment link would break after five days.

`CheckAndPresign` (`server/runner/s3presign/runner.go:47`) handles this:

- Lists attachments filtered to `AttachmentStorageType_S3` in batches of 100 (`batchSize`, line 55), paging by offset — blobs excluded via `GetBlob: false`.
- Skips any object whose `LastPresignedTime` is still within 4 days (line 88), giving a **1-day safety margin** against the 5-day expiry.
- Re-presigns the rest and writes back both the new `Reference` and a fresh `LastPresignedTime` via `UpdateAttachment` (lines 108–120).
- Per-attachment S3 config wins over the instance-level setting (lines 93–96), so attachments uploaded under an older bucket config still get signed correctly.

### Schedule

`runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27`). `Run` is a plain `time.Ticker` loop with a `ctx.Done()` escape (lines 29–41). Note the ticker fires only *after* the first 12 hours — that's why startup calls `RunOnce` directly first.

### Wiring

In `startBackgroundRunners` (`server/server.go:153`):

1. A dedicated cancellable context is created and its cancel func registered on `s.backgroundRunnerCancels` (lines 156–159), so this runner shuts down independently of other subsystems.
2. `RunOnce(ctx)` at line 163 runs **synchronously on the startup path** — any URLs that expired while the server was down are refreshed before it starts serving.
3. `Run(s3Context)` is launched on a goroutine tracked by `s.backgroundRunnerWG` (lines 166–171), which `stopBackgroundRunners` (line 176) and `waitBackgroundRunners` (called at line 143) drain during graceful shutdown.

One architectural note: the boot-time `RunOnce` is synchronous and pages through *all* S3 attachments 100 at a time, creating a fresh `s3.NewClient` per attachment (line 102). On a large instance that's startup latency proportional to attachment count — a candidate for moving into the goroutine or hoisting client construction out of the loop.
