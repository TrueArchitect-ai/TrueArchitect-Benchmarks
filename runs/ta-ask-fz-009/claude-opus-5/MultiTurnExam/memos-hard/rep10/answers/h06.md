### Where paths converge

There are two layers of convergence, worth distinguishing:

**Intermediate — `dispatchMemoRelatedWebhook`** (`server/router/api/v1/memo_service_webhooks.go:48`). The three thin wrappers `DispatchMemoCreatedWebhook` (:15), `DispatchMemoUpdatedWebhook` (:20), and `DispatchMemoDeletedWebhook` (:25) all delegate here, differing only in the activity-type string. It resolves the memo creator via `ResolveUserByName` (:49), loads that user's webhooks with `GetUserWebhooks` (:57), and per hook stamps `payload.URL = hook.Url` and `payload.SigningSecret = hook.SigningSecret` (:67-68) — **this is where the user-configured URL enters the payload**.

`DispatchMemoCommentCreatedWebhook` (:30) deliberately bypasses this helper because it targets the *related memo owner* rather than the comment author — it takes `relatedMemoCreatorID` directly (:31). So it is a second, parallel producer.

**Final — `webhook.Post`** (`internal/webhook/webhook.go:120`). Both producers call `webhook.PostAsync` (:43 and :71), which only enqueues onto the bounded 128-slot `asyncPostQueue`. The four `init()` worker goroutines (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, where the actual request is issued at `safeClient.Do(req)` (:152). Every path — all six handlers, both dispatch producers — funnels through that single line.

### Why the convergence matters

Because delivery is one function, the SSRF control is also one control: `safeClient` uses `safeDialContext` (`internal/webhook/webhook.go:59`) to reject reserved/private IPs at dial time. A handler cannot accidentally opt out.

Two consequences of the async hop: the webhook fires on worker goroutines *after* the RPC has returned, so a full queue silently drops the notification (`internal/webhook/webhook.go:191-195`), and handler error returns reflect only enqueue-time failures like creator resolution — never delivery outcome.
