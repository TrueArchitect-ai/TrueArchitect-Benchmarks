### Where delivery executes

`Post` (`internal/webhook/webhook.go:120`) marshals the payload, builds the `POST`, optionally attaches Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`, lines 147–149), then fires it via `safeClient.Do` (line 152).

Most callers don't invoke `Post` directly — they use `PostAsync` (line 184), which enqueues onto a **bounded** channel `asyncPostQueue` of capacity 128 (line 39). A pool of **4 goroutines** started in `init()` (lines 42–55) drains that queue and calls `Post`. So the outbound request physically executes on one of those four background workers. The `select` with a `default` branch (lines 189–195) means an overflowing queue **drops** the webhook with a warning rather than blocking the caller — delivery is best-effort, not guaranteed, and there's no retry.

### What protects it

The primary control is at **dial time**, which is the architecturally important choice:

- `safeDialContext` (line 59) is installed as the `Transport.DialContext` of the shared `safeClient` (lines 32–37). It splits host/port, resolves via `net.DefaultResolver.LookupHost`, and rejects the connection if **any** returned address is reserved (lines 70–74).
- Because the check happens on the resolution that immediately precedes the connection, it **defeats DNS rebinding** — the comment at lines 30–31 states this intent explicitly. A validate-then-fetch design would be bypassable by a TTL-0 record that flips to `169.254.169.254` between admission and dispatch.
- `reservedCIDRs` (`internal/webhook/validate.go:14-23`) covers IPv4 loopback, all three RFC-1918 ranges, link-local **including cloud IMDS at 169.254.169.254**, and the IPv6 equivalents (`::1/128`, `fc00::/7`, `fe80::/10`). Parsed once in `init()` (lines 28–36), panicking on a malformed constant.

The secondary layer is admission-time: `ValidateURL` (line 62) enforces absolute-URL parsing, an http/https scheme allowlist, and the same reserved-IP check, returning a gRPC `InvalidArgument` so the API layer can reject a bad webhook URL at configuration time instead of failing silently later.

### The documented escape hatch

`AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false` (lines 45–47), disabling **both** layers at once since they share that predicate. It's wired from the `allow-private-webhooks` flag in `cmd/memos/main.go:49`, intended for self-hosted deployments targeting LAN services. Note it's a plain package-level `bool` mutated at startup and toggled by tests (`internal/webhook/webhook_test.go:90-92`) — fine in practice given it's set once before serving, though it is unsynchronized global state.
