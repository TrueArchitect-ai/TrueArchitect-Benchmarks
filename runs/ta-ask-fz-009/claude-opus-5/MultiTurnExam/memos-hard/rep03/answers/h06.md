### Why `Post`, not `PostAsync`, is the convergence point
`PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto `asyncPostQueue`, a 128-slot buffered channel (line 39), dropping on overflow (lines 191-195). It performs no I/O. The queue is drained by four worker goroutines started in `init()` (lines 42-55), each calling **`Post`** (line 120) — the sole place an outbound request is actually issued, via `safeClient.Do(req)` at line 152.

So `Post` is the single funnel where every path converges before delivery, and that's what makes the SSRF guard tractable: `safeClient`'s transport uses `safeDialContext` (line 59), which re-resolves the host and rejects reserved/private IPs at dial time. One chokepoint, one guard, covering all six handlers.

Also worth noting: because delivery is queued, none of these six handlers block on the HTTP call, and a full queue means webhooks are silently dropped rather than retried.
