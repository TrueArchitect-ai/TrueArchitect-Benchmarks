### Where delivery executes
`Post` (`internal/webhook/webhook.go:120-180`) marshals the payload, builds the POST, optionally signs it, and issues the request via `safeClient.Do(req)` at line 152. Everything else is a feeder into it:

- `PostAsync` (line 184) doesn't send anything — it enqueues onto `asyncPostQueue`, a buffered channel of 128 (line 39), dropping with a warning when full (lines 191-195).
- Four worker goroutines started in `init()` (lines 42-55) drain that queue and call `Post`.
- The trigger side is `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, which call `PostAsync` on memo changes — so request handlers never block on outbound delivery.

### What protects it
The guard is deliberately split, because URL-time validation alone is bypassable:

**1. Dial-time enforcement — the real protection.** `safeDialContext` (`internal/webhook/webhook.go:59-77`) is installed as the `Transport.DialContext` of the shared `safeClient` (lines 32-37). Every dispatch resolves the hostname itself (line 65) and rejects the connection if *any* returned IP is reserved (lines 70-74). Because this runs at connect time rather than at save time, it also defeats **DNS rebinding** — a hostname that validated as public when the webhook was created but later resolves to `169.254.169.254` still fails to dial. This is the layer that cannot be skipped, since it sits under the only HTTP client used for webhooks.

**2. Create/update-time validation — early, friendly rejection.** `ValidateURL` (`internal/webhook/validate.go:62-83`) requires an absolute URL, restricts the scheme to http/https (line 67), and resolves the host to screen reserved IPs. It returns a gRPC `InvalidArgument`, so bad URLs are refused at the API boundary — called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`.

**The blocklist** (`internal/webhook/validate.go:14-23`) is parsed once at startup into `reservedNetworks` (lines 28-36, panicking on a malformed CIDR): IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` — explicitly noted as covering the cloud IMDS endpoint — and the IPv6 equivalents `::1/128`, `fc00::/7`, `fe80::/10`.

### Escape hatch
`AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false` (lines 45-47), disabling **both** layers at once since they share that predicate. It's set from the `allow-private-webhooks` flag at `cmd/memos/main.go:49`, intended for self-hosted deployments targeting LAN services.

Two secondary hardening details in `Post`: the response body is read through `io.LimitReader(resp.Body, 1<<20)` (line 158), capping a malicious receiver at 1 MiB, and the client carries a 30-second timeout (lines 27, 33).
