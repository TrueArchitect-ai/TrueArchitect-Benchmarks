### Where it's computed
`RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) is a thin wrapper: it ensures `memo.Payload` is non-nil (lines 75-77), calls `markdownService.ExtractAll([]byte(memo.Content))` (line 80), then writes back exactly two fields — `memo.Payload.Tags` and `memo.Payload.Property` (lines 85-86). It deliberately does **not** touch `Location`, the other `MemoPayload` field (`proto/store/memo.proto:10`), since that is user-set rather than derived.

The real work is `service.ExtractAll` (`internal/markdown/markdown.go:356-422`), which parses the content once and does a **single AST walk** (line 371) collecting everything — the docstring at line 355 and the comment at line 79 both flag this as an efficiency choice over calling `ExtractTags`/`ExtractProperties` separately.

The batch runner would rebuild all memos in 100-row pages (lines 29-71), but as established earlier nothing constructs `memopayload.Runner`, so recomputation happens only on the create/update request path.

Consequence worth noting: because the only live triggers are content writes, metadata for existing memos is never refreshed retroactively. If extraction logic changes, stored payloads stay stale until each memo is edited — and the batch runner that would have fixed that is dead code.

### What gets extracted
From the walk in `ExtractAll`:
- **`Tags`** — from tag nodes (line 377), deduplicated with original case preserved via `uniquePreserveCase` (line 418).
- **`Property.Title`** — the text of the first block-level child *only if* it's an H1 heading (lines 384-389). The `firstBlockChecked` latch means an H1 later in the document does not set the title.
- **`Property.HasLink`** — any `KindLink` node (lines 393-394).
- **`Property.HasCode`** — any code block, fenced code block, or inline code span (lines 396-397).
- **`Property.HasTaskList`** — any task checkbox (lines 399-400).
- **`Property.HasIncompleteTasks`** — set when a checkbox is present and unchecked (lines 401-405), which is what powers "has open tasks" filtering.

The schema matches exactly: `MemoPayload.Property` at `proto/store/memo.proto:15-22`, commented "The calculated properties from the memo content," with `tags` at line 12.

One asymmetry: `ExtractAll` also collects `Mentions` (line 380, lower-cased and deduped), but `RebuildMemoPayload` discards them — `data.Mentions` is never assigned to the payload. Mentions are consumed elsewhere, not persisted as derived memo metadata.
