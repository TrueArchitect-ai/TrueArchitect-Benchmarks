### The six surfaces

**1. `checkMemoReadAccess`** (`server/router/api/v1/memo_service.go:39-68`) — the canonical rule for reading one memo. Archived memos are creator-only (lines 45-53); then for non-public memos it requires authentication (`Unauthenticated`, line 61) and rejects non-creators on `Private` (`PermissionDenied`, line 64). Note `Protected` passes for any authenticated user.

**2. `ListMemos` scoping** (`server/router/api/v1/memo_service.go:218-227`) — enforcement by *query construction*, not post-filtering. Anonymous callers get `VisibilityList = [Public]` (line 219); an authenticated caller browsing broadly gets the CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` (line 222); querying another user's memos narrows to `[Public, Protected]` (line 225). This is a distinct site because a bug here leaks rows the single-memo gate would have blocked.

**3. `checkAttachmentPermission`** (`server/router/fileserver/fileserver.go:650`) — guards attachment *bytes* over plain HTTP, outside gRPC. Unlinked attachments are creator-or-admin only (lines 652-664); otherwise it loads the parent memo (line 666) and derives access from `memo.Visibility`. Two rules unique to this surface: public attachments are served anonymously **only if** `s.Profile.AllowAnonymous()` (line 677), and there's a `share_token` fallback (line 684) letting private/protected memo attachments load from a share page.

**4. `SSEClient.canReceive`** (`server/router/api/v1/sse_hub.go:134-144`) — outbound delivery filter for live events. `Private` reaches only the creator or an admin (line 137); `Public`, `Protected`, and empty pass (line 138); anything unrecognized is **denied with a warning** (lines 140-142) — fail-closed, the only site with that posture. The `Visibility` field exists purely for this (`sse_hub.go:31-32`, marked `json:"-"` so it never ships to clients).

**5. RSS feeds** (`server/router/rss/rss.go:90`, `:141`) — both the instance-wide and per-user feeds hardcode `VisibilityList: []store.Visibility{store.Public}`. Feeds are unauthenticated, so this is the whole enforcement.

**6. Notification email** (`server/notification/email.go:313-316`) — suppresses/adjusts mail based on `Private` and `Protected`, preventing memo content leaking via email to recipients who couldn't view it in-app.

So the invariant is enforced in at least ten places with at least three distinct formulations; there is no single chokepoint.
