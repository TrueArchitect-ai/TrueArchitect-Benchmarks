### What happens at each hop

**Route** — `fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)` on the `/file` group (`fileserver.go:122-124`). Browsers land here because `convertUserToProto` rewrites the avatar field to `/file/{user}/avatar` rather than inlining base64 (`server/router/api/v1/user_service_converters.go:32-38`) — a deliberate response-size reduction.

**Handler** (`fileserver.go:168-210`), in order:
1. **Anonymity gate** — if `!s.Profile.AllowAnonymous()`, it calls `getCurrentUser` (line 174, defined line 708) and rejects a nil viewer with 401 (lines 178-180). On a public instance this is skipped entirely, so avatars are unauthenticated there.
2. `identifier := c.Param("identifier")` (line 183) → the lookup hop.
3. Guards: nil user → 404 (line 190); empty `AvatarURL` → 404 (line 193).
4. `parseDataURI(user.AvatarURL)` (line 196, defined line 737) — the avatar is **not** a file on disk or in S3; it's a base64 data URI stored in the user row, decoded via `dataURIRegex`.
5. MIME allow-list check against `avatarAllowedTypes` (line 201, defined line 75), then `setSecurityHeaders` (line 205) and `c.Blob(...)` (line 209).

**Lookup** — `getUserByUsername` is a one-line pass-through: `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})` (`fileserver.go:716`). Note it filters by `Username` only, not ID.

**Store** — `Store.GetUser` (`store/user.go:148`) consults `userCache` **only when `find.ID != nil`** (lines 149-156). This request filters by username, so the cache is bypassed and it always falls through to `Store.ListUsers` (line 158). `ListUsers` (line 136) delegates to `s.driver.ListUsers` and populates the cache keyed by ID on the way back (lines 142-144).

**Driver** — `DB.ListUsers` builds the `WHERE` clause and issues the SQL (`store/db/sqlite/user.go:88`); the MySQL and Postgres drivers implement the same `store.Driver` method, selected by the factory at `store/db/db.go:14`.

### The notable consequence
Every avatar request for another user reaches the database — the ID-keyed cache can't serve a username-keyed lookup — so avatar traffic scales with page renders unless the `Cache-Control` header set at line 207 keeps browsers from re-asking.
