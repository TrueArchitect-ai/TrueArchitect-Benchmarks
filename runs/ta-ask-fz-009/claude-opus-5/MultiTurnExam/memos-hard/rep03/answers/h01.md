**`s3presign.Runner` — every 12 hours (plus one synchronous pass at startup) — wired in `server/server.go:162-171` (inside `startBackgroundRunners`)**

### The component
`server/runner/s3presign/runner.go` — `Runner` struct (line 16), constructed by `NewRunner(store)` (line 20). It exists because S3 presigned URLs are time-limited: `internal/storage/s3/s3.go:77` sets a 5-day expiry on each presigned GET URL, and the attachment's `reference` column holds that URL. Without a refresher, links to S3-stored attachment content go dead after 5 days.

### The schedule
- `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27`), driven by a `time.Ticker` in `Run` (lines 29–41), exiting on `ctx.Done()`.
- Refresh is **not** unconditional every tick. `CheckAndPresign` skips any attachment whose `LastPresignedTime` is under 4 days old (`runner.go:85-91`), so each URL is actually re-signed roughly once per 4 days against a 5-day expiry — a 1-day safety margin, checked twice a day.

### Mechanics worth knowing
- Scope: only `AttachmentStorageType_S3` attachments, paged 100 at a time (`runner.go:53-65`).
- Per-attachment S3 config wins over the instance-wide setting (`runner.go:93-96`), so attachments uploaded under an older bucket config keep re-signing against that config.
- On success it writes both the new `Reference` URL and a bumped `LastPresignedTime` into a cloned payload (`runner.go:114-120`); the clone via `cloneAttachmentPayload` (line 134) avoids mutating shared proto state — the fix noted in `CHANGELOG.md:77`.
- Failures are logged and skipped per attachment, never fatal — one bad bucket doesn't stall the sweep.

Note: `EXTERNAL` storage-type attachments are not touched by this runner; it handles S3 only.
