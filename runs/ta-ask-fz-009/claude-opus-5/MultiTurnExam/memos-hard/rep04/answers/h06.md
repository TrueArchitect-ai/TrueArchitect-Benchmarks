**Chain B — comments → `DispatchMemoCommentCreatedWebhook`** (`server/router/api/v1/memo_service_webhooks.go:30`, `PostAsync` at `:43`):
- `APIV1Service.CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20`

Notice this one targets the *related memo owner's* webhooks (`GetUserWebhooks(ctx, relatedMemoCreatorID)`, `:31`), not the commenter's — so a comment can trigger an outbound request to a URL configured by a different user than the caller.

Each of these is exposed at the wire boundary by a `ConnectServiceHandler` shim that delegates to the `APIV1Service` method: `CreateMemo` `connect_services.go:306`, `UpdateMemo` `:330`, `DeleteMemo` `:338`, `SetMemoAttachments` `:346`, `SetMemoRelations` `:362`, `CreateMemoComment` `:378`.

**Where the URL comes from**: `payload.URL = hook.Url`, loaded from `Store.GetUserWebhooks` (`memo_service_webhooks.go:57,67` and `:31,41`) — user-configured, hence the SSRF guard on the dial path in `internal/webhook/webhook.go:59`.

**Convergence detail**: every path terminates at `PostAsync`, which only enqueues onto a bounded 128-slot channel; four worker goroutines drain it into `Post` (`internal/webhook/webhook.go:39-55`). So `PostAsync` is the last synchronous point shared by all handlers, and `Post` is the single place the HTTP request actually leaves the process.
