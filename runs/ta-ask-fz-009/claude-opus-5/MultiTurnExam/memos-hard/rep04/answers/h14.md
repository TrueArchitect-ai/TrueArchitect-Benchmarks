**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `markdown.service.ExtractAll` — `internal/markdown/markdown.go:356`; Triggers: memo create, memo content-field update, and comment creation; Extracted: `Payload.Tags` (all `#tags`) and `Payload.Property` (content-shape booleans, incl. first-block-H1 detection).**

**Where it runs.** `RebuildMemoPayload` mutates the memo in place — ensures a `MemoPayload` exists, runs one markdown parse, and assigns exactly two fields:
```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```
`server/runner/memopayload/runner.go:85-86`. Note it deliberately does *not* persist `data.Mentions`, even though `ExtractAll` collects them (`internal/markdown/markdown.go:379-381`) — mentions are consumed separately on the notification path (`server/router/api/v1/memo_mention_helpers.go:32`).

The Connect wire handlers `CreateMemo`/`UpdateMemo` (`server/router/api/v1/connect_services.go:306,330`) are the external entry points. Recomputation is content-gated: updating only `visibility` or other fields skips it entirely (`memo_service.go:452` onward), which is correct since the derived data depends solely on `Content`.

**What `ExtractAll` extracts** — a single goldmark AST walk (`internal/markdown/markdown.go:357-386`) collecting three things, of which two are persisted:
- **Tags** — every memo tag node, appended in document order (`:376-378`).
- **Mentions** — usernames lowercased (`:379-381`) — returned but dropped by `RebuildMemoPayload`.
- **Property** — a `storepb.MemoPayload_Property`, including the "first block-level child of the document is an H1 heading" check (`:383-386`), which is what drives list/preview title rendering.

The single-pass design is explicit in both comments (`runner.go:79`, `markdown.go:355`) — the properties are recomputed from content rather than stored per-field, so the memo row's `payload` column is always derivable from `content`.
