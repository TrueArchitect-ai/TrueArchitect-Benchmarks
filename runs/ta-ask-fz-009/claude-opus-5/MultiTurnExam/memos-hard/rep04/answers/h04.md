**No — `store/db/mysql` is constructed only inside the factory.**

Evidence:

- The code graph certifies exactly one caller of `mysql.NewDB`: `db.NewDBDriver` at `store/db/db.go:14` (the construction site is `store/db/db.go:22`, in the `case "mysql"` arm).
- The package is imported exactly once repo-wide: `"github.com/usememos/memos/store/db/mysql"` at `store/db/db.go:8`. Since Go requires an import to reference a package's constructor, a single import site means a single possible construction site — no other file can build the driver.
- Every entry point goes through the factory rather than around it: `cmd/memos/main.go:57`, `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver`.
- The MySQL package's own tests don't construct it either — no `NewDB` or `Driver{` literal in `store/db/mysql/*_test.go` (searched both test files: `auth_config_test.go`, `user_delete_test.go`).
- Contrast: SQLite *is* built directly outside the factory, at `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416`. So the discipline isn't universal across drivers — MySQL specifically stays behind the boundary.

The remaining `mysql.` references are unrelated: `store/db/mysql/mysql.go:17,30,73` are the upstream `go-sql-driver/mysql` DSN types, and `store/test/containers.go:101-105` is the Testcontainers MySQL module — both different packages that merely share the name.
