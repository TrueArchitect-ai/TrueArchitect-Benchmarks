Visibility is enforced in **six distinct surfaces**, split between per-memo permission checks and query-level scoping:

```
APIV1Service memo read gate (checkMemoVisibility-style guard) — server/router/api/v1/memo_service.go:55-65
ListMemos query scoping (VisibilityList / CEL filter by viewer) — server/router/api/v1/memo_service.go:218-226
SSE event fan-out filter — SSEClient.canReceive — server/router/api/v1/sse_hub.go:134-144
File server attachment gate — checkAttachmentPermission — server/router/fileserver/fileserver.go:677, :699
RSS feed scoping (public only) — server/router/rss/rss.go:90, :141
Frontend SSR/sitemap scoping (public only) — server/router/frontend/frontend.go:150
```

Plus these secondary API-surface checks that re-apply the same rule on related resources:

```
Attachment service — server/router/api/v1/attachment_service.go:445, :451
Memo-attachment service — server/router/api/v1/memo_attachment_service.go:222
Comments (parent memo readable? comment creation) — server/router/api/v1/memo_service_comments.go:41, :100
Reactions (list + upsert) — server/router/api/v1/reaction_service.go:38, :83
User stats scoping — server/router/api/v1/user_service_stats.go:84, :90, :218
Notification/mention suppression — server/router/api/v1/memo_mention_helpers.go:62, :67, :84; server/router/api/v1/user_service_notifications.go:309-312; server/notification/email.go:313-316
```

Two enforcement *styles* worth distinguishing architecturally:

- **Post-fetch permission checks** — load the memo, then deny: `PRIVATE && creator != viewer && !admin` → `PermissionDenied`/403. Seen at `memo_service.go:63`, `fileserver.go:699`, `reaction_service.go:38,83`, `attachment_service.go:451`, `memo_attachment_service.go:222`, `memo_service_comments.go:41`.
- **Pre-query scoping** — never fetch what the viewer can't see, by setting `FindMemo.VisibilityList` (`store/memo.go:69`) or appending a CEL filter. Anonymous gets `[PUBLIC]`; a viewer browsing someone else's memos gets `[PUBLIC, PROTECTED]`; a viewer with no creator filter gets `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` (`memo_service.go:218-226`). This is translated to SQL per dialect at `store/db/sqlite/memo.go:96`, `store/db/mysql/memo.go:104`, `store/db/postgres/memo.go:89`.

Two surfaces have extra conditions beyond the memo's own visibility: the file server also honors instance-level anonymous access (`fileserver.go:677`, gated on `Profile.AllowAnonymous()`) and a share-token fallback (`fileserver.go:681`); the SSE hub grants admins visibility of private events (`sse_hub.go:137`) and fails closed on unknown visibility values (`sse_hub.go:141-142`).
