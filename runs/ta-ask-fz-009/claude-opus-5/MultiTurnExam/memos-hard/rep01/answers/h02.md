**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard via `safeDialContext` on the shared `safeClient` transport — `internal/webhook/webhook.go:59` (with `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go:44`)**

**Delivery.** `Post` marshals the `WebhookRequestPayload`, builds a `POST`, optionally signs it, and executes it at `safeClient.Do(req)` (`webhook.go:152`) — that line is the actual outbound call. Everything else routes through it: `PostAsync` (`webhook.go:184`) only enqueues onto a 128-slot buffered channel (`webhook.go:39`), drained by 4 goroutines started in `init` that each call `Post` (`webhook.go:42-55`). Dispatch is fire-and-forget with backpressure by dropping — a full queue logs a warning and discards the event (`webhook.go:191-195`).

**Protection — two layers, one predicate.**

1. **Admission time**: `ValidateURL` (`validate.go:62`) rejects non-absolute URLs, any scheme other than http/https, and hostnames resolving into a reserved range, returning a gRPC `InvalidArgument` so API handlers can surface it directly.
2. **Dial time**: the real enforcement point. `safeDialContext` re-resolves the host on every connection and refuses if any returned address is reserved (`webhook.go:65-74`). Because the check happens at dial rather than at save, it also defeats **DNS rebinding** — a hostname that passed validation but later resolves to `127.0.0.1` still fails to connect. The comment at `webhook.go:30-31` states this intent explicitly.

Both layers share `isReservedIP` (`validate.go:44`), tested against CIDRs parsed once at startup (`validate.go:14-36`): IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` — which specifically covers the cloud instance-metadata endpoint `169.254.169.254` — plus IPv6 loopback, unique-local, and link-local.

**Escape hatch.** `AllowPrivateIPs` (`validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers at once. It is off by default and set from the `--allow-private-webhooks` flag at `cmd/memos/main.go:49` (declared `cmd/memos/main.go:133`), for self-hosters targeting LAN services.

**Gaps worth noting.** The guard is address-based only — it does not restrict ports, and it does not follow-check redirects: `safeClient` uses the default redirect policy, but since redirects are dialed through the same `safeDialContext`, a redirect to an internal address is still blocked at connect. Two things the CIDR list omits: `0.0.0.0/8` (`ip.IsUnspecified()`) and IPv4-mapped IPv6 forms like `::ffff:127.0.0.1` — note that the separate URL-preview fetcher at `internal/httpgetter/html_meta.go:105` uses Go's stdlib predicates (`IsLoopback/IsPrivate/IsLinkLocalUnicast/IsUnspecified`) instead, which do cover the unspecified case.
