**Actual API surface: Protobuf-defined gRPC, exposed three ways.** The schema of record is **`.proto` files**, not SDL:

```
proto/api/v1/memo_service.proto        proto/api/v1/user_service.proto
proto/api/v1/auth_service.proto        proto/api/v1/attachment_service.proto
```

Those nine definitions generate three transports over the same service contracts:
1. **gRPC** — `proto/gen/api/v1/*_grpc.pb.go`
2. **Connect** — `proto/gen/api/v1/apiv1connect/*.connect.go`, with procedure constants like `/memos.api.v1.MemoService/CreateMemo`
3. **REST/JSON via grpc-gateway** — HTTP annotations in the protos become the `*.pb.gw.go` route tables, registered by `apiV1Service.RegisterGateway` (`server/server.go:88`)

**81 HTTP doors total**, per the map's surface listing. The REST shape is Google-AIP resource-oriented, not query-based — e.g. `GET /api/v1/memos`, `POST /api/v1/memos`, `PATCH /api/v1/{memo.name=memos/*}`, `DELETE /api/v1/{name=memos/*}`, sub-collections like `GET /api/v1/{name=memos/*}/comments` and `/reactions`, and custom verbs via colon suffix (`POST /api/v1/users:batchGet`, `GET /api/v1/{name=users/*}:getStats`, `POST /api/v1/ai:transcribe`).
