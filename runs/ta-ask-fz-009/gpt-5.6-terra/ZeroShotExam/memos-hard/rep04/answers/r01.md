**Premise correction:** this repository does not configure a Redis connection for the cache layer—there are no Redis references in the codebase. The cache boundary is process-local in-memory storage.

**Actual mechanism:** `store.New` configures a shared `cache.Config` in [`store/store.go:40-44`](store/store.go#L40-L44) and constructs `userCache` with it at [`store/store.go:51-53`](store/store.go#L51-L53). User reads and list results populate that cache through `userCache.Set` in [`store/user.go:142-144`](store/user.go#L142-L144) and [`store/user.go:148-168`](store/user.go#L148-L168).

User entries therefore receive the default TTL of **10 minutes**. `Set` delegates to `SetWithTTL` using the configured default ([`store/cache/cache.go:92-95`](store/cache/cache.go#L92-L95)); the entry expiry is calculated locally as `time.Now().Add(ttl)` ([`store/cache/cache.go:110-113`](store/cache/cache.go#L110-L113)).
