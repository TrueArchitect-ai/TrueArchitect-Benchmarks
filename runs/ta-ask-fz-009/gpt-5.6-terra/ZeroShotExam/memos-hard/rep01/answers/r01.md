**Premise correction:** this repository does **not** configure a Redis connection for its cache layer. There is no Redis dependency or Redis client configuration; the cache boundary is an in-process Go cache.

**Actual mechanism:** `store.New` hard-codes the cache configuration and creates `userCache` with `cache.New(cacheConfig)` in `store/store.go:37-53`. The cache implementation is a `sync.Map`-backed, thread-safe memory cache (`store/cache/cache.go:66-73`), not a networked store. User records are stored and read through that cache in `store/user.go:98`, `store/user.go:150-153`, and `store/user.go:167`.

User cache entries have a **10-minute TTL**, configured as `DefaultTTL: 10 * time.Minute` in `store/store.go:40-45`; ordinary `Set` calls use that default TTL (`store/cache/cache.go:92-95`) and set expiration to `time.Now().Add(ttl)` (`store/cache/cache.go:98-114`).
