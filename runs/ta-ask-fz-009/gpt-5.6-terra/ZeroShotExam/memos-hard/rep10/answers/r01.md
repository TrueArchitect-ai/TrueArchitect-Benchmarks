**Premise correction:** this repository does not configure a Redis connection for its cache layer. The cache is process-local, in-memory Go storage (`sync.Map`), not a Redis-backed service; `go.mod` also has no Redis client dependency.

**Actual mechanism:** `store.New` creates the user cache with `cache.New(cacheConfig)` in `store/store.go:37-60`. Its configuration is hard-coded there: default TTL **10 minutes**, cleanup interval **5 minutes**, and maximum **1,000** entries (`store/store.go:40-45`). User records are inserted through `s.userCache.Set(...)` (for example, `store/user.go:92-99`, `126-144`, and `148-168`), and `Set` applies that configured default TTL (`store/cache/cache.go:92-95`). Expiration is enforced on reads and by the cleanup loop (`store/cache/cache.go:110-146`).
