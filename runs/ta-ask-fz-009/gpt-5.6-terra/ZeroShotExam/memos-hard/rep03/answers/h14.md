`server/runner/memopayload.RebuildMemoPayload` computes and persists the derived payload metadata: it calls `MarkdownService.ExtractAll` on `memo.Content`, then assigns the resulting `Property` (and tags) to `memo.Payload` (`server/runner/memopayload/runner.go:74-87`). The Markdown implementation performs one AST walk in `ExtractAll` (`internal/markdown/markdown.go:355-421`).

Triggers: memo creation calls the rebuild before persistence (`server/router/api/v1/memo_service.go:84-115`); an `UpdateMemo` whose update mask includes `content` rebuilds it (`server/router/api/v1/memo_service.go:430-451`); and the payload runner can batch-rebuild every memo, updating each stored payload (`server/runner/memopayload/runner.go:26-72`).

Extracted properties: whether the Markdown contains a link, any code block/fenced block/inline code span, a task list, and an incomplete task; plus a title from the document’s first block only when it is an H1 (`internal/markdown/markdown.go:383-405`). These are the output-only `Memo.Property` fields `has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, and `title` (`proto/gen/api/v1/memo_service.pb.go:2179-2187`).
