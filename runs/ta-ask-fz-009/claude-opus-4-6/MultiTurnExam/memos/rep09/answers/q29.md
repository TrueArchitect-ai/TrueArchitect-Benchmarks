**Interceptor:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` attached to the shared transport. It injects an `Authorization: Bearer <accessToken>` header on every outbound request and handles transparent token refresh on `Unauthenticated` (401) errors. Token state is managed in `web/src/auth-state.ts`.

**Token kinds managed:**
- **Access token** (short-lived JWT) — stored in-memory and `localStorage`, sent as a `Bearer` token in the `Authorization` header.
- **Refresh token** — sent as an HTTP-only cookie (`credentials: "include"`) to the `AuthService.RefreshToken` RPC to obtain a new access token.
- The backend also supports **Personal Access Tokens (PATs)** as an alternative bearer credential.

**Backend validation package:** `server/auth` (`server/auth/authenticator.go`) — the `Authenticator` struct provides `AuthenticateByAccessTokenV2` (validates access token JWTs), `AuthenticateByRefreshToken` (validates refresh tokens via the store), and `AuthenticateByPAT` (validates personal access tokens). The top-level `Authenticate` method resolves the bearer token from the `Authorization` header and dispatches to the appropriate method.
