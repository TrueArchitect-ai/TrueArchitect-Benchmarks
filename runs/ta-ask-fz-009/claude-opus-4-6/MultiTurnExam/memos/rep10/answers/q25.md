**Engine:** CEL (Common Expression Language) parsed by `cel-go`, implemented in the `internal/filter` package (`internal/filter/engine.go`).

**Mechanism:** Filter expressions use standard CEL syntax. The engine follows a three-phase pipeline: (1) the CEL expression is parsed and validated against a memo-specific schema (`internal/filter/schema.go`) using `cel-go`, (2) the CEL AST is normalized into a dialect-agnostic intermediate representation (`internal/filter/ir.go` via `internal/filter/parser.go`), and (3) the renderer (`internal/filter/render.go`) walks the IR and emits a SQL `WHERE` fragment with placeholder arguments tailored to the target dialect (`DialectSQLite`, `DialectMySQL`, or `DialectPostgres`), handling dialect differences such as JSON access operators, placeholder style (`?` vs `$n`), `LIKE` vs `ILIKE`, boolean coercion, etc. Each database driver calls `filter.DefaultEngine()` and `filter.AppendConditions()` with its dialect constant to inject the generated SQL into its query (e.g., `store/db/sqlite/memo.go:57–61`).
