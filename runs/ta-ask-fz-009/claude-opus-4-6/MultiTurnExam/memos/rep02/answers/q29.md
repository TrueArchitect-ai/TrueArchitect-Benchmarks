**Interceptor:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` access token to every request's `Authorization` header. Token state is managed in `web/src/auth-state.ts`.

**Token kinds managed:**
- **Access token** (short-lived JWT, ~15 min) — stored in-memory and localStorage, attached as `Authorization: Bearer <token>` on every request.
- **Refresh token** — sent as an HTTP cookie (`credentials: "include"`), used to obtain new access tokens via `AuthService.RefreshToken` when the access token expires or a 401 is received.
- The interceptor also handles **Personal Access Tokens (PATs)**, which are validated through the same `Bearer` header path on the backend.

**Backend validation package:** `server/auth` (`server/auth/authenticator.go`) — the `Authenticator` struct provides `AuthenticateByAccessTokenV2` (validates JWT access tokens), `AuthenticateByRefreshToken` (validates refresh tokens against the database), `AuthenticateByPAT` (validates personal access tokens), and the unified `AuthenticateToUser` entry point that tries the `Authorization` header first, then falls back to the refresh token cookie.
