**Engine:** CEL (Common Expression Language) via `google/cel-go`, implemented in the `internal/filter` package (`internal/filter/engine.go`, `internal/filter/parser.go`, `internal/filter/render.go`, etc.).

**Mechanism:** The filter string is parsed and type-checked by a CEL environment (`cel.NewEnv` in `internal/filter/engine.go`), which produces an AST that is lowered into a dialect-agnostic condition tree (`internal/filter/parser.go`). Each database driver then calls `filter.AppendConditions()` (`internal/filter/helpers.go`) passing a dialect constant (`filter.DialectMySQL`, `filter.DialectPostgres`, or `filter.DialectSQLite`), which invokes the renderer (`internal/filter/render.go`) to emit dialect-appropriate SQL `WHERE` fragments with parameterized placeholders—so the same CEL filter expression is compiled once into an IR and then rendered into the correct SQL syntax per dialect.
