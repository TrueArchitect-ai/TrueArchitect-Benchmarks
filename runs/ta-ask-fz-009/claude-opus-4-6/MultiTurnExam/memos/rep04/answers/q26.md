The following tables are affected when `DeleteMemo` runs:

1. **memo_relation** — `Store.DeleteMemo` (`store/memo.go:142–146`) explicitly deletes relations where the memo is source or target
2. **attachment** — `Store.DeleteMemo` (`store/memo.go:149–157`) lists and deletes all attachments linked to the memo
3. **memo** — the memo row itself is deleted last (`store/memo.go:158`, e.g. `store/db/sqlite/memo.go:239`)

Additionally, at the API handler level (`server/router/api/v1/memo_service.go:567–577`), comment memos (child memos linked via `memo_relation` with type `Comment`) are recursively deleted via `Store.DeleteMemo`, which cascades the same cleanup (memo_relation, attachment, memo) for each comment.

So the directly affected tables are: **memo**, **memo_relation**, **attachment**
