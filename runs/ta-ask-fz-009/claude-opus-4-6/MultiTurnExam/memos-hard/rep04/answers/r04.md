The premise is incorrect — **there is no message broker (neither NATS nor RabbitMQ)**. The webhook delivery workers consume from a plain **in-process Go buffered channel**, not an external message broker.

The "queue" is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the package `init()` function (`internal/webhook/webhook.go:42–55`) to consume from this channel and call `webhook.Post` for each payload. Producers enqueue via `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send and drops the message if the channel is full. Everything is in-memory within the single server process — no external messaging infrastructure is involved.
