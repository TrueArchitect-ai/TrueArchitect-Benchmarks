The `safeClient` HTTP client (`webhook.go:32`) uses a custom `Transport` whose `DialContext` is `safeDialContext`. Before dialing, it DNS-resolves the target hostname and checks every returned IP against a list of reserved/private CIDR ranges (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents — parsed at init from `reservedCIDRs` in `validate.go:14–23`). Any match is rejected, which also defeats DNS-rebinding attacks since the check happens at dial time, after resolution. A second layer, `ValidateURL` (`validate.go:62`), performs the same IP check at webhook **creation** time so users get an immediate error. An escape hatch `AllowPrivateIPs` (`validate.go:41`) exists for self-hosted deployments that intentionally target LAN services.
