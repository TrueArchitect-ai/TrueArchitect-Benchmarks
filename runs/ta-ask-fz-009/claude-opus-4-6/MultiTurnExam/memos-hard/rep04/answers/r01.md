The premise is incorrect — **there is no Redis connection**. The cache layer does not use Redis at all. The codebase has zero references to Redis anywhere (confirmed by grep across all 343 `.go` files and a graph-wide symbol search).

The cache is a **pure in-process, in-memory implementation** defined in `store/cache/cache.go`. It is a `sync.Map`-backed structure with per-entry TTLs, periodic cleanup, and max-item eviction — no external infrastructure. User entries are cached via `Store.userCache` (`store/user.go`), which is a `cache.Cache` instance. The TTL for user entries is whatever `DefaultTTL` is set to during construction. Looking at `store/store.go`, each cache (including `userCache`) is created with a `cache.Config` whose `DefaultTTL` is configured at store initialization — there is no special Redis TTL, just the in-memory cache's configured duration.
