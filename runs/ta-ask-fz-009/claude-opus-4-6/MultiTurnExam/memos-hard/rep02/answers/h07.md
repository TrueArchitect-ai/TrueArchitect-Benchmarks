The browser hits `GET /file/users/:identifier/avatar`. Here is the call chain hop by hop:

1. **Route registration:** `FileServerService.RegisterRoutes` — `server/router/fileserver/fileserver.go:124`
2. **HTTP handler:** `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
3. **Username lookup:** `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715`
4. **Store layer:** `Store.GetUser` — `store/user.go:148`
5. **Store delegation:** `Store.ListUsers` — `store/user.go:136` (called by `GetUser` when no cache hit)
6. **Driver (data layer):** `Driver.ListUsers` (e.g. `sqlite.DB.ListUsers`) — `store/db/sqlite/user.go:88` (or the equivalent MySQL/Postgres driver)

The avatar data itself is stored as a base64 data URI in the user's `AvatarURL` field. Back in the handler (`fileserver.go:196`), `parseDataURI` (`fileserver.go:737`) decodes it and the raw image bytes are returned via `c.Blob()` (`fileserver.go:209`). No attachment/blob storage is involved — the avatar is inline in the user row.
