**The premise is incorrect — there is no Redis connection.** The cache layer is entirely **in-memory**, implemented as `cache.Cache` (`store/cache/cache.go:67`), a thread-safe struct backed by a `sync.Map` with TTL-based expiration and a periodic cleanup goroutine. There is no Redis dependency anywhere in the codebase.

User entries (and all cache entries) use the **default TTL of 10 minutes** (`DefaultConfig()` at `store/cache/cache.go:59`), with a cleanup interval of 5 minutes and a max of 1000 items. The `Store` creates its caches via `cache.NewDefault()`, which applies this default configuration. There is no external cache service involved — the `cache.Cache` struct lives in-process and is instantiated per `Store` instance (`store/store.go`).
