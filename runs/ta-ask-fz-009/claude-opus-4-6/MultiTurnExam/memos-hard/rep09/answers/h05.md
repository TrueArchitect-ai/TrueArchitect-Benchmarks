**Mechanism: explicit Go code.**

When a user is deleted, their reactions are removed by explicit SQL `DELETE` statements executed within the user-deletion transaction in Go. There are two complementary deletions:

1. **Reactions the user created** — `DELETE FROM reaction WHERE creator_id = ?`
   - `store/db/sqlite/user_delete.go:401`
   - `store/db/mysql/user_delete.go:438`
   - `store/db/postgres/user_delete.go:401`

2. **Reactions on the user's memos** (by any user) — `DELETE FROM reaction WHERE content_id IN (…)` (the content IDs are the user's memo resource names)
   - `store/db/sqlite/user_delete.go:383`
   - `store/db/mysql/user_delete.go:420`
   - `store/db/postgres/user_delete.go:383`

There is **no database-level cascade**: the `reaction` table schema has no `FOREIGN KEY … ON DELETE CASCADE` constraint on `creator_id` (confirmed in `store/migration/sqlite/LATEST.sql:92–99`, `store/migration/mysql/LATEST.sql:91–98`, `store/migration/postgres/LATEST.sql:91–98`). The cleanup is entirely application-driven.
