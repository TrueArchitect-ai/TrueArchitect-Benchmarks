**Protection mechanism — `safeDialContext` + `isReservedIP`** (`internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`). SSRF is prevented at two layers:

1. **At dial time (runtime):** The `safeClient` HTTP client uses a custom `Transport` whose `DialContext` is `safeDialContext` (`webhook.go:34–36`). Before opening a TCP connection, it resolves the target hostname via DNS and checks every resulting IP against `isReservedIP` (`webhook.go:70–73`), which rejects any IP in loopback, RFC-1918, link-local/cloud-IMDS, and IPv6 private ranges (`validate.go:14–23`). This also defeats DNS rebinding, since the check happens on the resolved address, not the hostname.

2. **At URL registration time:** `ValidateURL` (`validate.go:62`) performs the same DNS-resolve-then-`isReservedIP` check when a user creates or updates a webhook, rejecting private-targeting URLs before they're ever stored.
