h15.

Memo visibility is enforced at these distinct sites:

1. **`GetMemo` (single-memo retrieval)** — `server/router/api/v1/memo_service.go:55–64` — checks visibility after fetching: anonymous users are rejected for non-PUBLIC memos; PRIVATE memos are restricted to the creator.

2. **`ListMemos` (query-time filtering)** — `server/router/api/v1/memo_service.go:218–227` — applies visibility constraints to the query: anonymous callers see only PUBLIC; authenticated callers viewing others' memos see PUBLIC + PROTECTED; own memos are unfiltered.

3. **`CreateMemoComment` (comment creation)** — `server/router/api/v1/memo_service_comments.go:33–42` — blocks commenting on PRIVATE memos by non-creators.

4. **`checkAttachmentAccess` (RPC attachment access)** — `server/router/api/v1/attachment_service.go:422–451` — linked attachments inherit the memo's visibility: PUBLIC is open, PRIVATE is creator-only.

5. **`checkAttachmentPermission` (file-server attachment serving)** — `server/router/fileserver/fileserver.go:650–699` — enforces the same memo-visibility rules when serving attachment files over HTTP (distinct code path from the RPC surface).

6. **`convertMemoRelationsFromStore` (relation filtering)** — `server/router/api/v1/memo_service_converter.go:182–187` — when loading related memos for a response, filters them by visibility so a relation edge never leaks a PRIVATE/PROTECTED memo to an unauthorized viewer.

7. **RSS feed generation** — `server/router/rss/rss.go:90` and `:141` — hardcodes `VisibilityList: []store.Visibility{store.Public}` so only PUBLIC memos appear in RSS feeds.

8. **Email notification suppression** — `server/notification/email.go:306–319` (`canViewerAccessMemo`) — prevents sending email notifications about memos the recipient cannot see (PRIVATE → creator only, PROTECTED → authenticated only).
