The browser hits `GET /users/:identifier/avatar`, which is routed by the Echo file server. Here is each hop from HTTP handler to data layer:

1. **`FileServerService.serveUserAvatar`** — `server/router/fileserver/fileserver.go:168`
2. **`FileServerService.getUserByUsername`** — `server/router/fileserver/fileserver.go:715` (resolves the `:identifier` path param to a user)
3. **`Store.GetUser`** — `store/user.go:148` (checks the in-memory user cache; on miss delegates down)
4. **`Store.ListUsers`** — `store/user.go:136` (calls through the `Driver` interface to the active DB backend)
5. **`Driver.ListUsers`** — e.g. `sqlite.DB.ListUsers` at `store/db/sqlite/user.go:88` (executes the SQL query; equivalent implementations exist in `store/db/mysql/` and `store/db/postgres/`)

The avatar data itself is stored as a data-URI in the user's `AvatarURL` column; `serveUserAvatar` decodes it with `parseDataURI` (line 196) and writes the raw bytes back to the response.
