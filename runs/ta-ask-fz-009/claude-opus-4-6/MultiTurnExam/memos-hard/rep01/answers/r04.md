The premise is incorrect — there is no message broker (neither NATS nor RabbitMQ). The webhook delivery workers consume from a plain **in-process Go buffered channel** declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutines are spawned in an `init()` function (`internal/webhook/webhook.go:42–55`) that range over this channel and call `webhook.Post` for each payload. Callers enqueue via `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which performs a non-blocking send on the channel (dropping the payload with a warning if the buffer is full). There is no external queue or broker involved.
