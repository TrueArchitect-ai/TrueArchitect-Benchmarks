Memo visibility is enforced at these distinct sites:

1. **`APIV1Service.checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:39` — Guards individual memo reads (GetMemo, and other single-memo RPCs). Blocks unauthenticated users from non-PUBLIC memos, and non-creators from PRIVATE memos.

2. **`APIV1Service.ListMemos` visibility filtering** — `server/router/api/v1/memo_service.go:218–226` — Pre-filters the query: anonymous users see only PUBLIC; authenticated users viewing others' memos see PUBLIC+PROTECTED; own memos are unfiltered. Visibility predicates are injected into `memoFind.VisibilityList` / `memoFind.Filters`.

3. **`FileServerService.checkAttachmentPermission`** — `server/router/fileserver/fileserver.go:650` — Enforces visibility when serving attachment binary content. Checks the owning memo's visibility: PUBLIC memos' attachments are served freely (on public instances), PRIVATE memos' attachments are restricted to the creator (or admin), and PROTECTED memos require authentication.

4. **`SSEClient.canReceive`** — `server/router/api/v1/sse_hub.go:134` — Filters SSE (Server-Sent Events) live-update delivery per subscriber. PRIVATE events are delivered only to the creator or admins; unknown visibility is denied by default.

5. **`canViewerAccessMemo` (notifications API)** — `server/router/api/v1/user_service_notifications.go:302` — Filters which notifications are returned to a user when listing/converting inbox items, suppressing references to memos the viewer cannot see.

6. **`canViewerAccessMemo` (email notifications)** — `server/notification/email.go:306` — Independently enforces the same visibility rules before including memo references in outbound notification emails.

7. **RSS feed visibility filtering** — `server/router/rss/rss.go:90,141` — Only PUBLIC memos are included in RSS feeds (`VisibilityList: []store.Visibility{store.Public}`), both for the instance-wide feed and per-user feeds.
