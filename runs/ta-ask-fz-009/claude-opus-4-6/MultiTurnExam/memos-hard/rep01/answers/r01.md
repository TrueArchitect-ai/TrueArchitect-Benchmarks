The premise is incorrect — there is no Redis connection. The cache layer is entirely **in-process / in-memory**, implemented as a `sync.Map`-based cache with TTL-based expiration and periodic cleanup (`store/cache/cache.go`). There is zero Redis (or any external cache store) usage anywhere in the codebase — a grep for "redis" across all 343 Go files returns no matches, and the code graph confirms no such symbol exists.

User cache entries use whatever `DefaultTTL` is configured when the `cache.Cache` is constructed. The cache is instantiated in `store.NewStore` (`store/store.go`) — the TTL is set per-cache instance via `cache.Config.DefaultTTL`, not via any Redis configuration.
