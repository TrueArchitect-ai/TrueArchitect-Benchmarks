**Premise correction:** There is no Redis connection anywhere in this codebase. The cache layer does not use Redis.

**Actual mechanism:** The cache is a purely **in-process, in-memory implementation** (`store/cache/cache.go`). The `Cache` struct holds a `sync.Map` of items with TTL-based expiration and periodic cleanup. It is constructed in `store.New` (`store/store.go:40–52`) with a shared `cache.Config` that applies to all caches, including the `userCache`:

- **Default TTL:** 10 minutes (`store/store.go:41`)
- **Cleanup interval:** 5 minutes (`store/store.go:42`)
- **Max items:** 1000 (`store/store.go:43`)

User entries use this same default TTL of 10 minutes — there is no Redis, no external cache service, and no separate TTL override for user entries.
