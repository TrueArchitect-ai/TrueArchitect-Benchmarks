**Protection mechanism** — `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`

The shared `safeClient` (`internal/webhook/webhook.go:32`) uses a custom `http.Transport` whose `DialContext` is `safeDialContext` (line 59). Before opening any TCP connection, `safeDialContext` resolves the target hostname via `net.DefaultResolver.LookupHost`, then checks every resolved IP against a blocklist of reserved/private CIDR ranges (`reservedCIDRs` in `internal/webhook/validate.go:14–23`: loopback, RFC-1918, link-local/cloud IMDS, and IPv6 equivalents). If any IP matches, the dial is rejected. Because the check happens at dial time (after DNS resolution, before connection), it also defeats DNS-rebinding attacks.

There is additionally a registration-time check: `ValidateURL` (`internal/webhook/validate.go:62`) performs the same DNS-resolve-and-block check when a webhook URL is first created/updated.

The SSRF guard can be opted out via the `--allow-private-webhooks` CLI flag (`cmd/memos/main.go:133`), which sets `webhook.AllowPrivateIPs = true` (`cmd/memos/main.go:49`) for self-hosted deployments targeting local-network services.
