Memo visibility is enforced at these distinct sites:

1. **`APIV1Service.checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:39` — Central gRPC-layer guard used by `GetMemo` (line 356), `UpdateMemo` (line 367), and `ListMemoComments` (line 148 in `memo_service_comments.go`). Blocks unauthenticated access to non-public memos and denies private memos to non-creators.

2. **`APIV1Service.ListMemos` visibility filtering** — `server/router/api/v1/memo_service.go:218–227` — Applies query-level visibility constraints: anonymous users see only `PUBLIC`; authenticated users viewing others' memos see `PUBLIC`+`PROTECTED`; own memos are unfiltered.

3. **`APIV1Service.CreateMemoComment` visibility check** — `server/router/api/v1/memo_service_comments.go:41` — Blocks commenting on a private memo unless the user is the creator or a super-user.

4. **`APIV1Service.checkAttachmentAccess`** — `server/router/api/v1/attachment_service.go:422` — For linked attachments, enforces the parent memo's visibility (public = open, private = creator/admin only).

5. **`APIV1Service.ListMemoAttachments` visibility check** — `server/router/api/v1/memo_attachment_service.go:213–224` — Checks memo visibility before returning its attachment list; denies private memos to non-creators.

6. **`APIV1Service.ListMemoRelations` visibility filtering** — `server/router/api/v1/memo_relation_service.go:108–112` — Filters related memos by visibility based on authentication state (anonymous → PUBLIC only; authenticated → own + PUBLIC + PROTECTED).

7. **`FileServerService.checkAttachmentAccess`** — `server/router/fileserver/fileserver.go:674–701` — HTTP file-serving layer: checks parent memo visibility, supports share-token fallback, and blocks private memos from non-creators/non-admins.

8. **RSS feed generation** — `server/router/rss/rss.go:90` and `:141` — Both the system-wide and per-user RSS feeds hardcode `VisibilityList: []store.Visibility{store.Public}`, ensuring only public memos appear in feeds.
