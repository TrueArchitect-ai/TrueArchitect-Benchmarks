MemoService is served over two protocols:

1. **gRPC-Gateway (REST / HTTP+JSON)** — `server/router/api/v1/v1.go` (line 108: `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)`), with the generated gateway glue in `proto/gen/api/v1/memo_service.pb.gw.go`

2. **Connect (ConnectRPC)** — `server/router/api/v1/connect_handler.go` (line 40: `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))`), registered into the Connect mux which is wired at `server/router/api/v1/v1.go` line 141 (`connectHandler.RegisterConnectHandlers(connectMux, …)`)

Both protocols delegate to the same `APIV1Service` struct (`server/router/api/v1/v1.go:22`), which implements the business logic once. The gRPC-Gateway path exposes it as RESTful JSON under `/api/v1/*`, while Connect exposes it under `/memos.api.v1.*` for browser clients (replacing the older grpc-web approach).
