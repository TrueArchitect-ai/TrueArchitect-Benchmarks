**Engine:** [CEL (Common Expression Language)](https://github.com/google/cel-go) via `google/cel-go`, wrapped in a custom `filter.Engine` at **`internal/filter/engine.go`**.

**Mechanism:** `Engine.Compile` parses the CEL filter string through a `cel.Env` into a CEL AST, then `buildCondition` (`internal/filter/parser.go`) converts that AST into a dialect-agnostic IR condition tree (`internal/filter/ir.go`), and `Render` (`internal/filter/render.go`) walks the condition tree and emits dialect-specific SQL fragments by switching on `DialectSQLite`/`DialectPostgres`/`DialectMySQL`—these fragments are injected into each store driver's query via `filter.AppendConditions` (`internal/filter/helpers.go`), which each dialect driver (e.g. `store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`) calls with its own `filter.Dialect*` constant.

In one sentence: the filter is a **CEL expression** parsed by `google/cel-go` inside `internal/filter/`, compiled to a dialect-neutral condition IR, then rendered to per-dialect SQL by a `renderer` that switches on `DialectSQLite`/`DialectPostgres`/`DialectMySQL` and appended as WHERE clauses through `filter.AppendConditions`.
