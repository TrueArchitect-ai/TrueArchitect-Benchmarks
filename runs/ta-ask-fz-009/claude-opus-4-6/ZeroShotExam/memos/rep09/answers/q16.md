When a memo is deleted via `Store.DeleteMemo` (`store/memo.go:140–159`), the store layer deletes these kinds of records before the memo row itself:

1. **Memo relations** (where the memo is the *source*) — `DeleteMemoRelation` with `MemoID` (`store/memo.go:142`)
2. **Memo relations** (where the memo is the *target*) — `DeleteMemoRelation` with `RelatedMemoID` (`store/memo.go:145`)
3. **Attachments** — lists all attachments linked to the memo, then deletes each one via `DeleteAttachment` (`store/memo.go:149–156`)

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567–577`), **comment memos** (child memos linked by a `Comment`-type relation) are recursively deleted via `Store.DeleteMemo` *before* the parent memo's own `Store.DeleteMemo` call, so each of those also triggers the same relation + attachment cleanup.
