Four memo lifecycle events dispatch webhooks, each with a dedicated dispatch function on `APIV1Service`:

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

All four are defined in `server/router/api/v1/memo_service_webhooks.go`.

The first three converge through the private method `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator's webhooks and calls `webhook.PostAsync`. `DispatchMemoCommentCreatedWebhook` (line 30) does its own webhook lookup (against the *related memo* owner rather than the comment author) but also calls `webhook.PostAsync`.

**All paths converge for delivery at `webhook.PostAsync`** (`internal/webhook/webhook.go:184`), which enqueues the payload onto a buffered channel (`asyncPostQueue`). Four background goroutines (spawned in `init()`, line 42) drain that channel and call **`webhook.Post`** (`internal/webhook/webhook.go:120`), which performs the actual HTTP POST with optional HMAC-SHA256 signing.
