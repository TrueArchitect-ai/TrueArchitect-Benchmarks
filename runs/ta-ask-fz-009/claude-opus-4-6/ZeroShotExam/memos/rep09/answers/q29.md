**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` wired into the shared transport at line 188.

**Token kinds managed (three):**

1. **Access token (JWT, short-lived, 15 min)** — stored in-memory and localStorage (`web/src/auth-state.ts`); attached as a `Bearer` token in the `Authorization` header (line 99 of `connect.ts`). Validated statelessly by signature on the backend.
2. **Refresh token (JWT, long-lived, 30 days)** — carried in an HTTP-only cookie (`memos_refresh`, per `server/auth/token.go:49`). The frontend interceptor calls `refreshToken()` via a dedicated `refreshTransport` (no interceptor, to avoid recursion) when it gets a 401 or detects the access token is about to expire. Validated against the database (revocation check) on the backend.
3. **Personal Access Token (PAT)** — prefixed `memos_pat_` (server/auth/token.go:52); sent as a `Bearer` token in the same `Authorization` header. Validated by SHA-256 hash lookup in the database.

**Backend validation package:** `server/auth` (package `auth`, rooted at `server/auth/`). Specifically:
- `server/auth/authenticator.go` — `Authenticator.Authenticate()` dispatches to `resolveBearer()`, which tries access-token-v2 parsing then PAT lookup.
- `server/auth/token.go` — defines token constants, generation, and parsing (`ParseAccessTokenV2`, `ParseRefreshToken`).
- The `Authorizer` in `server/router/api/v1/authz.go` wraps `auth.Authenticator` and adds method-level access policy (public vs. protected endpoints), and the `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go:208` calls `Authorizer.Authenticate()` + `Authorizer.CheckAccess()` for every unary RPC.
