Four memo lifecycle events dispatch webhooks:

- **memo created**: `DispatchMemoCreatedWebhook` — called at `server/router/api/v1/memo_service.go:157`
- **memo updated**: `DispatchMemoUpdatedWebhook` — called at `server/router/api/v1/memo_update_helpers.go:67`
- **memo deleted**: `DispatchMemoDeletedWebhook` — called at `server/router/api/v1/memo_service.go:562`
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` — called at `server/router/api/v1/memo_service_comments.go:119`

All four are defined in `server/router/api/v1/memo_service_webhooks.go`. The first three (`created`, `updated`, `deleted`) converge into the private helper `dispatchMemoRelatedWebhook` (line 48 of that file), which resolves the memo creator's webhooks and enqueues each one. `DispatchMemoCommentCreatedWebhook` does its own lookup (using the *related* memo's creator ID) but follows the same pattern.

Every dispatch path ultimately calls **`webhook.PostAsync`** (`internal/webhook/webhook.go:184`), which enqueues the payload into a bounded channel (`asyncPostQueue`). Four background goroutines (started in `init()`, line 42) drain that channel and each call **`webhook.Post`** (`internal/webhook/webhook.go:120`) — the single synchronous delivery function where all webhooks converge for actual HTTP POST delivery.
