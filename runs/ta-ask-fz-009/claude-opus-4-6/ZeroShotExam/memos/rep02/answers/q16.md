When a memo is deleted, the store layer (`store/memo.go:140–158`) deletes these kinds of records before the memo row itself:

1. **Memo relations** (where the memo is the *source*) — `DeleteMemoRelation` with `MemoID` (`store/memo.go:142`)
2. **Memo relations** (where the memo is the *target*) — `DeleteMemoRelation` with `RelatedMemoID` (`store/memo.go:145`)
3. **Attachments** — lists all attachments linked to the memo, then deletes each one via `DeleteAttachment` (`store/memo.go:149–156`)

Note: at the API layer (`server/router/api/v1/memo_service.go:568–577`), **comment memos** (related via `MemoRelationComment`) are also recursively deleted before the parent memo's own `Store.DeleteMemo` call, but that happens in the service layer, not the store layer itself.
