**Engine:** [CEL (Common Expression Language)](https://github.com/google/cel-go) via `github.com/google/cel-go`, wrapped in a custom `filter.Engine` struct at `internal/filter/engine.go`.

**Path:** `internal/filter/` — the key files are `engine.go` (CEL env + compile), `parser.go` (AST → dialect-agnostic IR `Condition` tree), `render.go` (IR → SQL), `ir.go` (condition IR types), and `helpers.go` (convenience `AppendConditions`).

**Mechanism in one sentence:** The `filter.Engine` parses the filter string into a CEL AST via `cel.NewEnv` / `env.Parse`, walks it into a dialect-agnostic `Condition` IR tree (`internal/filter/parser.go`), then `render.go` renders that tree to SQL fragments using a `DialectName` discriminator (`filter.DialectMySQL`, `filter.DialectPostgres`, `filter.DialectSQLite`) that controls placeholder style and dialect-specific SQL expressions (e.g. timestamp accessors), with each DB driver (e.g. `store/db/mysql/memo.go:69`, `store/db/postgres/memo.go:58`, `store/db/sqlite/memo.go:61`) calling `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` to splice the result into its query's `WHERE` clause.
