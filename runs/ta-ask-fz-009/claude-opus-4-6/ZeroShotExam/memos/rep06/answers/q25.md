**Engine:** [CEL (Common Expression Language)](https://github.com/google/cel-go) via `github.com/google/cel-go/cel`, wrapped in a custom `filter.Engine` at `internal/filter/engine.go`.

**Mechanism:** The `Engine.Compile` method parses the CEL filter string into a CEL AST, then `buildCondition` (`internal/filter/parser.go`) converts that AST into a dialect-agnostic intermediate `Condition` tree (`internal/filter/ir.go`); `Program.Render` (`internal/filter/engine.go:96`) then passes that tree to a `renderer` (`internal/filter/render.go`) which walks the `Condition` nodes and emits dialect-specific SQL fragments (parameterized `WHERE` clauses) by switching on `RenderOptions.Dialect` — one of `DialectSQLite`, `DialectPostgres`, or `DialectMySQL` — to produce the correct column expressions, placeholders, JSON accessors, and timestamp functions for each database.

**In one sentence:** A `cel-go`-based `filter.Engine` (`internal/filter/engine.go`) compiles the CEL filter string into a dialect-neutral condition IR (`internal/filter/ir.go`), then a `renderer` (`internal/filter/render.go`) walks that IR and emits dialect-specific SQL (SQLite/Postgres/MySQL) by branching on `DialectName` for placeholders, JSON operators, and date-part functions.
