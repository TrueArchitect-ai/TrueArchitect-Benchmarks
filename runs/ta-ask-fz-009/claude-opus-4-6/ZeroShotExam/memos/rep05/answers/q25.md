

Let me trace the filter parsing mechanism for `ListMemos`.

q25.

**Engine:** [CEL (Common Expression Language)](https://github.com/google/cel-go) via `cel-go`, wrapped in a custom `filter.Engine`.  
**Path:** `internal/filter/` (core files: `engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`).

**Mechanism in one sentence:** The engine parses the filter string as a CEL expression using `cel-go` (`engine.go`), converts the CEL AST into a dialect-agnostic intermediate representation of conditions (`parser.go` → `ir.go`), then a renderer (`render.go`) walks that IR and emits a SQL fragment with placeholders and arguments tailored to the target dialect (`DialectSQLite`, `DialectMySQL`, or `DialectPostgres`), which each store driver (e.g. `store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`) appends to its `WHERE` clause via `filter.AppendConditions`.
