**Engine:** [CEL (Common Expression Language)](https://github.com/google/cel-go) via `cel-go`, parsed by `filter.Engine` in **`internal/filter/engine.go`**.

**Mechanism:** `Engine.Compile()` uses `cel.Env.Compile()` to parse the filter string into a CEL AST, then `buildCondition()` (`internal/filter/parser.go`) converts that AST into a dialect-agnostic `Condition` IR tree (`internal/filter/ir.go`), and `Program.Render()` walks that tree through a `renderer` (`internal/filter/render.go`) that switches on a `DialectName` (`DialectSQLite`, `DialectPostgres`, `DialectMySQL`) to emit dialect-specific SQL fragments (e.g., `ILIKE` vs `LIKE`, `json_each` vs `jsonb_array_elements_text` vs `JSON_TABLE`, placeholder style `?` vs `$N`).

In one sentence: the CEL engine at `internal/filter/` compiles filter strings into a CEL AST, lowers them to a dialect-neutral condition tree, and a per-dialect renderer emits SQL with dialect-specific operators, functions, and placeholder styles.
