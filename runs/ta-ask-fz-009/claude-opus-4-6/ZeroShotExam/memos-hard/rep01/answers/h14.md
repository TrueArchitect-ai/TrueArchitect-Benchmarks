h14.

The derived metadata has **two tiers** — a **persisted payload** (tags + property) and a **per-response snippet** — computed at different points:

---

### 1. Persisted payload: `RebuildMemoPayload`

**Computation site:** `memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`), which delegates to `markdown.Service.ExtractAll` (`internal/markdown/markdown.go:356`).

**Triggers (three operations):**

| Operation | File:Line |
|---|---|
| **CreateMemo** | `server/router/api/v1/memo_service.go:108` |
| **UpdateMemo** (when `content` is in the update mask) | `server/router/api/v1/memo_service.go:447` |
| **Runner.RunOnce** (batch rebuild of all memos) | `server/runner/memopayload/runner.go:52` |

**Extracted properties** (stored in `MemoPayload`, defined in `proto/store/memo.proto:8–22`):

- **`tags`** — all `#tag` tokens found in the markdown content (deduplicated, case-preserving).
- **`property.has_link`** — whether the content contains any markdown link.
- **`property.has_task_list`** — whether the content contains any task checkbox.
- **`property.has_code`** — whether the content contains a code block, fenced code block, or code span.
- **`property.has_incomplete_tasks`** — whether any task checkbox is unchecked.
- **`property.title`** — the text of the first block-level H1 heading, if present.

Additionally, `ExtractAll` also collects **`mentions`** (usernames from `@mention` nodes), but these are returned in `ExtractedData.Mentions` (`internal/markdown/markdown.go:23`) and used for notification/mention logic rather than persisted into the payload.

---

### 2. Per-response snippet: `getMemoContentSnippet`

**Computation site:** `APIV1Service.getMemoContentSnippet` (`server/router/api/v1/memo_service_webhooks.go:83`), which calls `markdown.Service.GenerateSnippet` (`internal/markdown/markdown.go:264`).

**Triggers:** Every API response that converts a store memo to the wire `Memo` message — `convertMemoFromStoreWithCreators` (`server/router/api/v1/memo_service_converter.go:76`) and `batchConvertMemoRelations` (`server/router/api/v1/memo_service_converter.go:225, 248`). This means **every `Get`, `List`, `Create`, `Update`, and `Delete` response** that returns a memo computes the snippet on the fly. It is **not persisted** in the database.

**What it extracts:** a **plain-text summary** of the memo content, truncated to 64 characters at a word boundary (skipping code blocks), set on the API `Memo.snippet` field (marked `OUTPUT_ONLY` in `proto/api/v1/memo_service.proto:256`). This is used for list/preview display and also for relation sub-objects (`MemoRelation_Memo.snippet`).
