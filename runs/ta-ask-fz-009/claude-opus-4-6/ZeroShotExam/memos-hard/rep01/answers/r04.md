**Premise correction:** The webhook delivery workers consume from neither NATS nor RabbitMQ. There is no external message broker involved at all.

**Actual mechanism:** Webhook delivery uses an **in-process Go buffered channel** as its queue. The channel is declared at package level in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the package's `init()` function (`internal/webhook/webhook.go:42-55`), each reading from this channel in a `for … range` loop and calling `Post()` to perform the HTTP delivery synchronously within that goroutine.

The public entry point `PostAsync()` (`internal/webhook/webhook.go:184`) does a non-blocking `select` send into the channel — if the 128-slot buffer is full, the webhook is dropped with a warning log rather than blocking the caller.

In short: no broker, no NATS, no RabbitMQ — just a plain `chan *WebhookRequestPayload` with fixed-size fan-out goroutines, all in-process.
