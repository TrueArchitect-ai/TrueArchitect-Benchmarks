**Premise correction:** The question presupposes a message broker (NATS or RabbitMQ), but neither is used. There are no webhook delivery workers consuming from an external message broker.

**Actual mechanism:** Webhook delivery uses a plain **in-process Go buffered channel** as its queue, not any external broker. The queue is declared at package scope in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the package's `init()` function (lines 42–55) and consume from that channel with a simple `for payload := range asyncPostQueue` loop. The `PostAsync` function (line 184) enqueues payloads via a non-blocking `select` send, dropping the dispatch with a warning log if the 128-slot buffer is full. Delivery itself is a direct `http.Client.Do` POST — no broker, no external queue infrastructure at all.
