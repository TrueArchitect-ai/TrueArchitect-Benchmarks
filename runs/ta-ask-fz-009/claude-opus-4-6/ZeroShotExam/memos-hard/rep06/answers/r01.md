**The premise is wrong — there is no Redis connection.** This project does not use Redis at all. A grep across all 1,042 source files for `redis`/`Redis`/`REDIS` returned zero matches.

The cache layer is a **pure in-memory, in-process cache** implemented from scratch in `store/cache/cache.go`. It is backed by a `sync.Map` with per-item TTL expiration and a periodic cleanup goroutine — no external service, no network connection.

**How it's configured for user entries:**

The `Store` constructor in `store/store.go:38–61` creates the user cache (line 52):

```go
userCache: cache.New(cacheConfig),
```

where `cacheConfig` is hardcoded at `store/store.go:40–45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

User entries are stored via `s.userCache.Set(ctx, ...)` (e.g., `store/user.go:98`), which delegates to `Cache.Set` → `Cache.SetWithTTL` using the default TTL (`store/cache/cache.go:93–94`).

**The TTL for user entries is 10 minutes**, with expired items reaped every 5 minutes and a cap of 1,000 items across all cache instances (users, user settings, instance settings each get their own 1,000-item cache).
