**Delivery function** — `Post` in `internal/webhook/webhook.go` (line 120). It JSON-marshals a `WebhookRequestPayload`, builds an HTTP POST request to the configured URL, optionally HMAC-signs it (Standard Webhooks style), and sends it via the `safeClient`. An async variant, `PostAsync` (line 184), enqueues payloads into a bounded channel drained by 4 goroutine workers that each call `Post`.

**Protection mechanism** — SSRF guard via `safeDialContext` + `isReservedIP`, spanning two files in `internal/webhook/`:

1. **Dial-time enforcement** (`internal/webhook/webhook.go`, lines 59–77): The `safeClient` HTTP client uses a custom `Transport` whose `DialContext` is `safeDialContext`. This function DNS-resolves the target hostname and checks every resolved IP against `isReservedIP` *before* opening a connection, which also defeats DNS-rebinding attacks.

2. **Reserved-IP list** (`internal/webhook/validate.go`, lines 14–54): `reservedCIDRs` enumerates blocked ranges — IPv4 loopback (`127.0.0.0/8`), all three RFC-1918 private ranges, link-local/cloud IMDS (`169.254.0.0/16`), plus IPv6 equivalents (`::1/128`, `fc00::/7`, `fe80::/10`). These are parsed into `reservedNetworks` at init and checked by `isReservedIP`. An `AllowPrivateIPs` flag (line 41) can disable this for self-hosted deployments.

3. **Registration-time validation** (`internal/webhook/validate.go`, lines 62–83): `ValidateURL` also resolves the hostname and checks against the same reserved-IP list at webhook *creation* time, rejecting bad URLs with a gRPC `InvalidArgument` error before they're ever stored.
