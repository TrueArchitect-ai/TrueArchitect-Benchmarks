**Premise correction: neither NATS nor RabbitMQ.** The webhook delivery workers do not consume from any external message broker at all.

The actual mechanism is a **plain Go buffered channel** declared as a package-level variable in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four in-process goroutine workers are spawned in the package's `init()` function (`internal/webhook/webhook.go:42–55`). Each goroutine simply ranges over `asyncPostQueue` and calls `Post()` to deliver the webhook via HTTP:

```go
func init() {
    for range 4 {
        go func() {
            for payload := range asyncPostQueue {
                if err := Post(payload); err != nil { … }
            }
        }()
    }
}
```

Callers enqueue work via `PostAsync()` (`internal/webhook/webhook.go:184–196`), which does a non-blocking send on the channel; if the 128-slot buffer is full, the dispatch is silently dropped with a warning log.

There is **no dependency on NATS, RabbitMQ, or any other external message broker** anywhere in the codebase (a repo-wide search for `nats`, `rabbitmq`, and `amqp` returned zero results). The "queue" is purely an in-memory Go channel with a fixed pool of goroutine consumers.
