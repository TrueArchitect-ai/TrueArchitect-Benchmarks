**Explicit Go code; no database-level cascade.**

When a user is deleted, their emoji reactions are removed by **explicit Go code** via two separate DELETE operations executed within the same transaction. There is **no** database-level `ON DELETE CASCADE` or foreign key constraint on the `reaction` table — the `creator_id` column has no FK at all.

### What gets deleted

The `deleteUserTargetsTx` function (identical logic across all three DB drivers) issues two reaction-cleanup steps:

1. **`deleteReactionsByContentIDsTx`** — deletes all reactions *on* the user's memos (by matching `content_id` to `"memos/<uid>"` for every memo in the user's memo tree):
   - `DELETE FROM reaction WHERE content_id IN (…)`
   - This removes reactions that *anyone* left on the deleted user's memos.

2. **`deleteReactionsByCreatorTx`** — deletes all reactions *by* the user (on anyone's memos):
   - `DELETE FROM reaction WHERE creator_id = ?`
   - This removes reactions the deleted user left on other people's memos.
