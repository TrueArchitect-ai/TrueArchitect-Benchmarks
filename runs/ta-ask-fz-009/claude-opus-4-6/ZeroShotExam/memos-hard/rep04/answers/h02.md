**Delivery function** — `Post` in `internal/webhook/webhook.go` (line 120). It JSON-marshals the payload, constructs an HTTP POST request, optionally signs it with HMAC-SHA256 (Standard Webhooks format), and sends it via `safeClient`. **Protection mechanism** — SSRF guard in `internal/webhook/validate.go`, enforced at **two layers**:

1. **At dial time** (`safeDialContext`, `internal/webhook/webhook.go:59`): The `safeClient` HTTP client uses a custom `Transport` whose `DialContext` resolves the target hostname, then calls `isReservedIP` (`internal/webhook/validate.go:44`) against every resolved IP. Any IP falling within the `reservedCIDRs` blocklist (loopback, RFC-1918 private, link-local/cloud IMDS `169.254.0.0/16`, and IPv6 equivalents — `internal/webhook/validate.go:14-23`) is rejected before a TCP connection is opened. This also defeats DNS-rebinding attacks because the check happens after resolution, at connection time.

2. **At URL registration time** (`ValidateURL`, `internal/webhook/validate.go:62`): When a user creates or updates a webhook, the URL is eagerly resolved and checked against the same `isReservedIP` blocklist, returning a gRPC `InvalidArgument` error upfront.

A toggle `AllowPrivateIPs` (`internal/webhook/validate.go:41`) exists to disable the SSRF protection for self-hosted deployments that intentionally target local-network services.
