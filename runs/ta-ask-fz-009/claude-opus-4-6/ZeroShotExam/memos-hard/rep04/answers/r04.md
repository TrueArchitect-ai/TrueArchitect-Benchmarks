**Premise correction:** The question's premise is wrong — webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

**Actual mechanism:** Webhook delivery uses a plain **Go buffered channel** as an in-process async queue:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

declared at **`internal/webhook/webhook.go:39`**.

Four goroutine workers are spawned in an `init()` function (`internal/webhook/webhook.go:42–55`) that each `range` over the channel and call `Post()` synchronously per payload. Callers enqueue work via `PostAsync()` (`internal/webhook/webhook.go:184`), which does a non-blocking send on the channel and drops the payload with a warning log if the 128-slot buffer is full.

There is no NATS client, no RabbitMQ/AMQP dependency, and no external queue infrastructure anywhere in the webhook delivery path — it is entirely in-process, bounded, and fire-and-forget.
