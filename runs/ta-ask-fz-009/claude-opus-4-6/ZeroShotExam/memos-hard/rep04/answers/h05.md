Emoji reactions are removed by **explicit Go `DELETE` statements** executed within the user-deletion transaction. There are **no foreign keys** on the `reaction` table in any of the three database schemas (SQLite, PostgreSQL, MySQL) — `creator_id` and `content_id` are plain columns with no `REFERENCES` or `ON DELETE CASCADE` constraints.

The Go code performs **two** reaction-cleanup steps inside `deleteUserTargetsTx`:

1. **`deleteReactionsByContentIDsTx`** — deletes all reactions whose `content_id` matches the deleted user's memos (i.e., reactions *on* the user's content, regardless of who created them).

   - `store/db/postgres/user_delete.go:96` / `:380`
   - `store/db/sqlite/user_delete.go:96` / `:380`

2. **`deleteReactionsByCreatorTx`** — deletes all reactions where `creator_id` matches the deleted user (i.e., reactions the user placed on *other people's* content).
   - `store/db/mysql/user_delete.go:102` / `store/db/mysql/user_delete.go:437–439`
   - `store/db/postgres/user_delete.go:102` / `:400`

Both run inside the same transaction as the rest of the user deletion (`store/db/mysql/user_delete.go:29–59`; same pattern in postgres/sqlite).
