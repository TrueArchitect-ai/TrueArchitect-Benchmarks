The outbound HTTP request to a user-configured webhook URL is made by **`webhook.Post`** (`internal/webhook/webhook.go:120`), which POSTs to `requestPayload.URL`. All RPC handler paths converge into **`dispatchMemoRelatedWebhook`** (`server/router/api/v1/memo_service_webhooks.go:48`) before delivery — this is the single function where those paths meet before calling `webhook.PostAsync` → `webhook.Post`.

**Call chains:**

- `UpdateMemo` / `SetMemoRelations` / `SetMemoAttachments` → `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` → **`dispatchMemoRelatedWebhook`** → `webhook.PostAsync` → `webhook.Post`

**Convergence function:** **`dispatchMemoRelatedWebhook`** — `server/router/api/v1/memo_service_webhooks.go:48`

This function looks up the memo creator's configured webhooks via `Store.GetUserWebhooks`, builds a `WebhookRequestPayload` (with the user-configured `hook.Url`), and enqueues it via `webhook.PostAsync`. The actual HTTP POST happens in `webhook.Post` (`internal/webhook/webhook.go:120`) using a hardened `safeClient` that blocks private/reserved IPs.

Note: `CreateMemoComment`'s path through `DispatchMemoCommentCreatedWebhook` (line 30) is a slight variant — it calls `PostAsync` directly rather than going through `dispatchMemoRelatedWebhook`, because it dispatches to the *related memo owner's* webhooks, not the comment author's. So strictly, **five of the six** handlers converge through `dispatchMemoRelatedWebhook`; the `CreateMemoComment` path converges at the next level down: `webhook.PostAsync`.
