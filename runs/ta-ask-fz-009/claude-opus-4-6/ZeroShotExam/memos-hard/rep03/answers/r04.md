**Premise correction: the webhook delivery system uses neither NATS nor RabbitMQ.** There is no external message broker involved at all.

The actual mechanism is a **plain Go buffered channel** acting as an in-process async queue:

- **Queue declaration:** `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`
- **Workers:** `internal/webhook/webhook.go:42–55` — an `init()` function spawns **4 goroutines** that range over the channel (`for payload := range asyncPostQueue`), each calling `Post()` to deliver the webhook via HTTP.
- **Enqueue path:** `internal/webhook/webhook.go:184` — `PostAsync()` performs a non-blocking send into the channel; if the 128-slot buffer is full, the webhook is dropped with a warning log (line 192).

This is a purely in-process, single-binary design — no broker dependency, no durable queue, no consumer group protocol. Delivery is best-effort with bounded back-pressure via the channel capacity.
