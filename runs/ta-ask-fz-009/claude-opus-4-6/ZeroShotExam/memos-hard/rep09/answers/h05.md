Instead, the Go code in `deleteUserTargetsTx` (`store/db/mysql/user_delete.go:92–127`) explicitly deletes reactions in two passes within the same transaction:

1. **By content ID** (line 96–98) — `deleteReactionsByContentIDsTx` issues `DELETE FROM reaction WHERE content_id IN (...)` using the UIDs of all the user's memos (lines 417–425). This removes all reactions (by anyone) on the deleted user's memos.

Both of these run inside the `BeginTx`/`Commit` block in `DB.DeleteUser` (lines 29–59), so they are atomic with the rest of the user deletion. The same pattern exists in the sqlite and postgres store drivers (same file names under `store/db/sqlite/` and `store/db/postgres/`).
