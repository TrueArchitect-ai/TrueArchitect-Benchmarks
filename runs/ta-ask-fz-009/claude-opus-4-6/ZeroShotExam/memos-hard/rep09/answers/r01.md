**The premise is wrong — there is no Redis connection.** The cache layer is a pure **in-memory, in-process cache** with no external backing store like Redis.

**Actual mechanism:**

The cache is implemented as a Go `sync.Map`-based in-memory store at `store/cache/cache.go`. The `Cache` struct (line 67) holds data in a `sync.Map` field, with TTL-based expiration and a background cleanup goroutine.

The `userCache` is instantiated in `store/store.go:52` via:

```go
userCache: cache.New(cacheConfig),
```

where `cacheConfig` is defined at `store/store.go:40–45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

**TTL for user entries: 10 minutes** (the `DefaultTTL`). User entries are stored via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g., `store/user.go:98`), which calls `Set` → `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93–94`). No user-specific custom TTL override is used — all user cache entries use the default 10-minute TTL.

The cache has a **cleanup goroutine** that sweeps expired entries every 5 minutes (`CleanupInterval`), and an eviction policy that removes the oldest 20% of entries when the 1,000-item cap is exceeded (`store/cache/cache.go:253`).
