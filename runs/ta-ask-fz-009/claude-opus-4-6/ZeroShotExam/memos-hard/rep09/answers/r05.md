**Premise correction:** This repository has no GraphQL schema. The question's premise is incorrect — Memos does not use GraphQL at all. Zero `.graphql` or `.gql` files exist, and the term "GraphQL" appears nowhere in the codebase (confirmed by text search across 1,042 files and a certified miss across 7,293 symbols in the code graph).

**Actual API surface:** The public API is a **gRPC + REST (gRPC-Gateway)** API, defined by **Protocol Buffer (`.proto`) files** in `proto/api/v1/`:

| Proto definition | Domain |
|---|---|
| `proto/api/v1/memo_service.proto` | Memos (CRUD, comments, reactions, shares, relations) |
| `proto/api/v1/user_service.proto` | Users (CRUD, settings, webhooks, tokens, notifications, linked identities) |
| `proto/api/v1/auth_service.proto` | Auth (sign-in, sign-out, refresh, current user) |
| `proto/api/v1/attachment_service.proto` | Attachments |
| `proto/api/v1/instance_service.proto` | Instance profile, settings, stats |
| `proto/api/v1/idp_service.proto` | Identity providers |
| `proto/api/v1/shortcut_service.proto` | User shortcuts |
| `proto/api/v1/ai_service.proto` | AI (transcription) |
| `proto/api/v1/common.proto` | Shared message types |

These `.proto` files are code-generated into Go gRPC stubs and gRPC-Gateway HTTP reverse-proxy handlers under `proto/gen/api/v1/` (e.g., `*.pb.gw.go` files). All REST endpoints are served under the `/api/v1/` prefix. A handful of additional non-gRPC routes exist for file serving (`/attachments/`, `/users/:identifier/avatar`), RSS (`/explore/rss.xml`, `/u/:username/rss.xml`), SEO (`/robots.txt`, `/sitemap.xml`), SSE (`/api/v1/sse`), and health checks (`/healthz`).
