**Delivery function — `Post`** in `internal/webhook/webhook.go` (line 120). It JSON-marshals a `WebhookRequestPayload`, constructs an HTTP POST with optional HMAC-SHA256 signing, and sends it via `safeClient.Do()`. **Protection mechanism — SSRF guard via `safeDialContext` + `isReservedIP`**, spanning two files:

1. **`internal/webhook/webhook.go:59–77`** — `safeDialContext` replaces the default dialer on the shared `safeClient`'s transport. It resolves the target hostname via DNS and then checks every resolved IP against `isReservedIP` *before* connecting, which also defeats DNS-rebinding attacks.

2. **`internal/webhook/validate.go:14–54`** — `reservedCIDRs` / `reservedNetworks` define the blocked ranges (IPv4 loopback, all three RFC-1918 blocks, link-local/cloud IMDS `169.254.0.0/16`, plus IPv6 loopback, unique-local, and link-local). `isReservedIP` checks any IP against these parsed CIDRs. An `AllowPrivateIPs` toggle (line 41) can disable the guard for self-hosted deployments.

3. **`internal/webhook/validate.go:62–83`** — `ValidateURL` provides a *second* layer: at webhook-creation time it resolves the URL's hostname and rejects it if it points at a reserved IP, enforcing the policy before the webhook is even stored (scheme is also restricted to `http`/`https`).

So there are two enforcement points: **registration-time validation** (`ValidateURL`) and **dispatch-time dial guard** (`safeDialContext`), both in `internal/webhook/`.
