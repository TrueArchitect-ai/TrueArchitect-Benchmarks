**Premise correction: neither NATS nor RabbitMQ is involved.** There is no external message broker at all.

Webhook delivery uses a **plain Go buffered channel** as its in-process queue, not a message broker. The queue is declared at:

- **`internal/webhook/webhook.go:39`** — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`

Four goroutine workers are spun up in the package's `init()` function (`internal/webhook/webhook.go:42–55`). Each worker loops over `asyncPostQueue`, calling `Post()` to make the outbound HTTP request synchronously.

Callers enqueue work via `PostAsync()` (`internal/webhook/webhook.go:184`), which does a non-blocking send on the channel and drops the payload with a warning log if the 128-slot buffer is full.

There is no dependency on NATS, RabbitMQ, or any other message broker anywhere in the webhook delivery path.
