Memo visibility is enforced at these distinct server surfaces:

1. **GetMemo guard** — `server/router/api/v1/memo_service.go` (lines 55–66, the `checkGetMemoPermission` helper; blocks non-public access for unauthenticated users and private access for non-owners)

2. **CreateMemoComment** — `server/router/api/v1/memo_service_comments.go` (line 41; denies commenting on a private memo the user doesn't own)

3. **Reaction service (list + upsert + delete)** — `server/router/api/v1/reaction_service.go` (lines 30–41 for listing, line 83 for upsert/delete; checks memo visibility before allowing reactions)

4. **Attachment service (GetAttachment / linked-attachment access)** — `server/router/api/v1/attachment_service.go` (lines 421–455, `checkAttachmentAccess`; delegates to memo visibility for linked attachments)

5. **ListMemoAttachments** — `server/router/api/v1/memo_attachment_service.go` (lines 213–225; checks memo visibility before listing a memo's attachments)

6. **Mention notification dispatch** — `server/router/api/v1/memo_mention_helpers.go` (lines 56–71, `canUserAccessMentionContext`; suppresses mention inbox items when the target user can't see the private memo)

7. **User notification conversion** — `server/router/api/v1/user_service_notifications.go` (lines 302–316, `canViewerAccessMemo`; filters notifications so viewers only see memos matching their visibility level)

8. **Email notification** — `server/notification/email.go` (lines 306–320, its own `canViewerAccessMemo`; skips sending email about private/protected memos to unauthorized recipients)

9. **File server (attachment file serving)** — `server/router/fileserver/fileserver.go` (lines 677–701; enforces memo visibility + share-token fallback when serving raw attachment files over HTTP)
