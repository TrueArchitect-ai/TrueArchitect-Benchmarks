**Actual mechanism:**

The cache is defined in `store/cache/cache.go` as a `Cache` struct built on `sync.Map` with TTL-based expiration. It implements the `cache.Interface` interface (`:11`), exposing `Set`, `SetWithTTL`, `Get`, `Delete`, `Clear`, `Close`, and `Size`.

The user cache is one of three `*cache.Cache` instances created in `store/store.go:52`:

All three caches (user, user-setting, instance-setting) share the same `cache.Config` constructed at `store/store.go:40–45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,

```

**The TTL for user entries is 10 minutes** (the `DefaultTTL`). User entries are cached via `Set()` (not `SetWithTTL`), so they always use this default — confirmed at `store/user.go:98` (`s.userCache.Set(ctx, userCacheKey(user.ID), user)`) and several other call sites in that file. A background goroutine (`cleanupLoop`, `store/cache/cache.go:200`) sweeps expired entries every 5 minutes, and an LRU-style eviction (`cleanupOldest`, `:253`) removes the oldest 20% when the 1000-item cap is exceeded.
