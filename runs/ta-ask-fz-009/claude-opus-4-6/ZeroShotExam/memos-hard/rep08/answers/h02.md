**Protection mechanism — SSRF guard via `safeDialContext` + `isReservedIP`**, spanning two files:

1. **`internal/webhook/webhook.go:59–77`** — `safeDialContext` replaces the default dialer on the shared `safeClient` HTTP transport. It resolves the target hostname to IPs *before* connecting, then calls `isReservedIP` on every resolved address; if any falls in a blocked range, the dial is refused. This also defeats DNS-rebinding since the check happens at connection time after resolution.

2. **`internal/webhook/validate.go:14–54`** — `reservedCIDRs` (line 14) defines the blocked ranges: IPv4 loopback (`127.0.0.0/8`), all three RFC-1918 private ranges, link-local/cloud IMDS (`169.254.0.0/16`), plus IPv6 loopback, unique-local, and link-local. These are parsed into `reservedNetworks` at startup. `isReservedIP` (line 44) checks against them. A separate `ValidateURL` function (line 62) performs the same DNS-resolve-and-check at webhook *registration* time, so invalid targets are rejected early as well.

There is also an escape hatch: `AllowPrivateIPs` (validate.go:41) can be set to `true` to disable the SSRF protection for self-hosted deployments that intentionally target local-network services.
