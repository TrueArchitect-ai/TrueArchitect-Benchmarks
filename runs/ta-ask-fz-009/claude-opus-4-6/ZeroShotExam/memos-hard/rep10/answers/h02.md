**Delivery function — `Post` in `internal/webhook/webhook.go` (line 120).** This is the synchronous send path; it marshals the payload to JSON, signs it (if a secret is configured), and sends an HTTP POST via `safeClient`. An async variant, `PostAsync` (line 184), enqueues into a buffered channel consumed by 4 background goroutines that each call `Post`.

**Protection mechanism — SSRF guard in `internal/webhook/validate.go` and `internal/webhook/webhook.go`**, implemented as a two-layer defense:

1. **At registration time** (`ValidateURL`, `internal/webhook/validate.go:62`): when a webhook URL is created/updated, the URL's hostname is DNS-resolved and every returned IP is checked against `reservedCIDRs` (line 14) — a blocklist covering loopback, RFC-1918 private ranges, link-local/cloud IMDS (`169.254.0.0/16`), and their IPv6 equivalents. Requests with URLs resolving to any of those are rejected with a gRPC `InvalidArgument` error.

2. **At dial time** (`safeDialContext`, `internal/webhook/webhook.go:59`): the `safeClient` HTTP client uses a custom `Transport` whose `DialContext` re-resolves the hostname and calls `isReservedIP` on every resolved address *before opening a connection*. This defeats DNS-rebinding attacks where a hostname passes validation initially but resolves to a private IP when the actual request is made.

Both layers delegate to `isReservedIP` (`internal/webhook/validate.go:44`), which checks against the parsed `reservedNetworks` list. A toggle `AllowPrivateIPs` (`validate.go:41`) can disable the protection for self-hosted deployments that intentionally target local-network services.
