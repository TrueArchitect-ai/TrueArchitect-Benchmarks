**Premise correction: neither NATS nor RabbitMQ.** This codebase uses no external message broker at all for webhook delivery.

The webhook delivery workers consume from a **plain Go buffered channel**, not from any message broker. The mechanism is declared in `internal/webhook/webhook.go`:

- **Line 39** — the "queue" is a package-level buffered channel:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- **Lines 42–55** — the `init()` function spawns **4 goroutines** that range over that channel, each calling `Post()` (a synchronous HTTP POST) for every payload received.
- **Lines 183–196** — `PostAsync()` does a non-blocking send into `asyncPostQueue`; if the 128-slot buffer is full, the webhook is dropped with a warning log.

There is no NATS client, no RabbitMQ/AMQP dependency, and no external queue anywhere in the project (confirmed: grep for `nats` and `rabbitmq`/`amqp` returned zero relevant hits). The entire dispatch pipeline is in-process: a bounded channel with a small worker pool, all within a single Go binary.
