**Explicit Go code; no database-level cascade.**

Reactions are removed by two explicit `DELETE` statements in Go, executed within the same transaction that deletes the user. There are **no foreign key constraints** on the `reaction` table (no `REFERENCES`, no `ON DELETE CASCADE`) in any of the three database schemas.

The two deletion paths cover both directions:

1. **Reactions on the user's memos** — `deleteReactionsByContentIDsTx()` deletes all reactions (by anyone) whose `content_id` matches the deleted user's memo UIDs.
   - MySQL: `store/db/mysql/user_delete.go:96,417–425`
   - SQLite: `store/db/sqlite/user_delete.go:96`
   - Postgres: `store/db/postgres/user_delete.go:96`

2. **Reactions the user placed on other people's memos** — `deleteReactionsByCreatorTx()` deletes all reactions where `creator_id` matches the deleted user.
   - MySQL: `store/db/mysql/user_delete.go:102,437–439`
   - SQLite: `store/db/sqlite/user_delete.go:102`
   - Postgres: `store/db/postgres/user_delete.go:102`

Both calls happen inside `deleteUserTargetsTx()` (lines 92–127 in each driver file), which runs in the same DB transaction as the user row deletion.
