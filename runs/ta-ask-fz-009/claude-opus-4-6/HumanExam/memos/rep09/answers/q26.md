Tables affected when DeleteMemo runs:
- `memo_relation` (both directions: source and target, cleaned in store.Store.DeleteMemo)
- `attachment` (linked attachments deleted in store.Store.DeleteMemo)
- `memo` (the row itself, via driver.DeleteMemo)
- Additionally, at the API layer (APIV1Service.DeleteMemo), child comment memos are deleted first, each triggering the same cascade — so their `memo`, `memo_relation`, and `attachment` rows are also affected.
- The API handler also lists `reaction` records before deletion (for webhook payload construction), but reactions are not explicitly deleted in the cascade code; they reference the memo by content_id string, not by FK.

Tables: `memo_relation`, `attachment`, `memo`
