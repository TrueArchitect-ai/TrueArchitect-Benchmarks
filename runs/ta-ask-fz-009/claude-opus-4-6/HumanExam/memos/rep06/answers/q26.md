Tables affected when DeleteMemo runs:
- `memo_relation` (store/memo.go:142–146 — deletes where MemoID or RelatedMemoID matches)
- `attachment` (store/memo.go:149–156 — deletes attachments linked to the memo)
- `memo` (store/memo.go:158 — the memo row itself)
- `memo_share` (ON DELETE CASCADE FK in schema, store/migration/sqlite/LATEST.sql:109)
- Additionally at the API layer, comment memos (child `memo` rows linked via COMMENT relation) are recursively deleted first (server/router/api/v1/memo_service.go:567–577), each triggering the same cascade on `memo_relation`, `attachment`, `memo_share`, and `memo`.
