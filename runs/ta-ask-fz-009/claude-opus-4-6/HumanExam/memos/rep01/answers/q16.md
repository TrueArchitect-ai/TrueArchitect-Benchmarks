Before deleting the memo row, `Store.DeleteMemo` (store/memo.go:140–158) explicitly deletes:
- memo_relation records (where memo is source)
- memo_relation records (where memo is related target)
- attachment records (linked to the memo, plus their storage files)

Additionally, memo_share records are cascade-deleted by the `ON DELETE CASCADE` foreign key (store/migration/sqlite/LATEST.sql:109).

At the API layer (`DeleteMemo` handler, memo_service.go:567–577), comment memos (child memos linked via COMMENT-type memo_relation) are recursively deleted before the parent memo.

So the kinds deleted before the memo row: **memo_relation**, **attachment** (with storage cleanup), and **comment memos** (which themselves cascade through the same logic). Additionally **memo_share** records via FK cascade.
