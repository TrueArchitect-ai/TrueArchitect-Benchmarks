Before deleting the memo row, the store layer deletes:
- memo_relation records (where memo is source)
- memo_relation records (where memo is target/related)
- attachment records linked to the memo

Additionally, at the API handler level (before calling Store.DeleteMemo), comment memos (child memos linked via COMMENT relation) are recursively deleted first (each triggering the same store-layer cleanup). The `memo_share` table has an `ON DELETE CASCADE` foreign key on `memo_id`, so those records are also deleted by the database.
