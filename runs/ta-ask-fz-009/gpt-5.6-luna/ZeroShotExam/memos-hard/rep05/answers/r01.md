**Premise correction:** The cache layer does **not** use Redis. Its connection is not configured because there is no Redis client or Redis-backed cache in this repository.

**Actual mechanism:** User entries use a **process-local, thread-safe in-memory cache**:

- `Store.New` creates `userCache` with `cache.New(cacheConfig)` in [`store/store.go:38-53`](store/store.go#L38-L53).
- The cache implementation stores entries in a `sync.Map` and tracks expiration timestamps in [`store/cache/cache.go:66-73`](store/cache/cache.go#L66-L73) and [`store/cache/cache.go:110-114`](store/cache/cache.go#L110-L114).
- The configured default TTL for user entries is **10 minutes**, set in [`store/store.go:39-45`](store/store.go#L39-L45).
- User reads and writes use `s.userCache` in [`store/user.go:92-99`](store/user.go#L92-L99) and [`store/user.go:148-168`](store/user.go#L148-L168).

The TTL is enforced on reads and by the cache cleanup loop; cleanup runs every **5 minutes** ([`store/cache/cache.go:56-64`](store/cache/cache.go#L56-L64), [`store/cache/cache.go:199-202`](store/cache/cache.go#L199-L202)).
