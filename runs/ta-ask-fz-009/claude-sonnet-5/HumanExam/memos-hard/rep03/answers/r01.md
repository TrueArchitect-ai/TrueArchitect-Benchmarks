— Premise correction: there is no Redis-backed cache in this codebase. The "cache layer" (`store/cache/cache.go`) is an in-process, thread-safe in-memory map (`sync.Map` + a background cleanup goroutine), not Redis — there is no Redis client, connection string, or config anywhere in the repo. Actual mechanism: `store.Store` holds three `*cache.Cache` instances (`instanceSettingCache`, `userCache`, `userSettingCache`, store/store.go:27-29), constructed via `cache.New(cacheConfig)` (store/store.go:51-53) using `cache.DefaultConfig()`-style values set inline: `DefaultTTL: 10 * time.Minute` (store/store.go:41) — that's the TTL applied to user cache entries (and the other two caches), with a 5-minute `CleanupInterval` and 1000-item cap.
