**Premise correction:** Neither. The webhook delivery workers don't consume from any external message broker — there is no NATS or RabbitMQ integration in this codebase (`go.mod` has no `nats-io` or `amqp`/`rabbitmq` client dependency).

**Actual mechanism:** Webhook delivery is handled entirely in-process with a buffered Go channel acting as the "queue." In `internal/webhook/webhook.go:39`, `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)`. On package `init()` (`internal/webhook/webhook.go:42-55`), 4 goroutines are spawned that range over this channel and call `Post(payload)` for each item — these are the "delivery workers." Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send (`select`/`default`) and drops the payload with a warning log if the channel is full. So the "broker" here is just an in-memory Go channel, not a networked message broker, and it's declared/consumed within the same file, not in any separate infra config.
