- **Delivery function:** `Post` in `internal/webhook/webhook.go:120` — it marshals the `WebhookRequestPayload`, optionally HMAC-signs it (Standard Webhooks style), and issues the actual `POST` via the shared `safeClient.Do(req)` (`internal/webhook/webhook.go:152`). `PostAsync` (`internal/webhook/webhook.go:184`) just enqueues onto `asyncPostQueue`, which a pool of 4 worker goroutines (started in `init()`, `internal/webhook/webhook.go:42-55`) drains by calling `Post`.

- **Protection mechanism:** SSRF/DNS-rebinding protection lives in two cooperating places, both in `internal/webhook/`:
  - `safeDialContext` (`internal/webhook/webhook.go:59`) is installed as the `DialContext` on `safeClient`'s `http.Transport` (`internal/webhook/webhook.go:32-37`). It resolves the target hostname itself at dial time and rejects the connection if any resolved IP falls in a reserved/private range — this is what defeats DNS rebinding, since it checks the IP actually being dialed, not just the IP checked earlier.
  - `isReservedIP` / `reservedNetworks` / `ValidateURL` in `internal/webhook/validate.go` (lines 14-83) define the blocked CIDR ranges (loopback, RFC-1918 private space, link-local/cloud IMDS `169.254.0.0/16`, and IPv6 equivalents) and provide the pre-flight validation used when a webhook URL is created/updated (`ValidateURL`, `validate.go:62`), plus the shared `isReservedIP` check reused by `safeDialContext`. An `AllowPrivateIPs` flag (`validate.go:41`) can disable the guard for self-hosted deployments that intentionally target LAN services.
