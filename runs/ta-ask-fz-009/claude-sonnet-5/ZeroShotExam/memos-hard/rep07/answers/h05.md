Evidence:
- Schema: `reaction` table (`store/migration/mysql/LATEST.sql:91-98`, mirrored in the postgres/sqlite LATEST.sql equivalents) declares only an `id` primary key and a `UNIQUE(creator_id, content_id, reaction_type)` constraint — no `FOREIGN KEY ... So reactions are removed — both reactions the user made and reactions left on their content — but by hand-written Go transaction logic in the store layer, not by an `ON DELETE CASCADE` foreign key.
