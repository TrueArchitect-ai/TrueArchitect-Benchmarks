**Premise correction:** There is no Redis in this codebase — go.mod (`go.mod`) has no Redis client dependency, and `store/cache/cache.go` is a pure in-process cache with no network backend. `find`/`grep` for "redis" turned up zero hits across the whole repo (1042 files searched), and the module's dependency list confirms no `go-redis`/`redis` package is imported anywhere.

**Actual mechanism:** The cache layer is an in-memory, thread-safe TTL cache implemented in `store/cache/cache.go` (uses `sync.Map` + `sync/atomic`, no external connection to configure). It's instantiated per `Store` in `store/store.go:38-58`: `New()` builds a shared `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000}` (store/store.go:40-45) and uses it to construct three separate `*cache.Cache` instances — `instanceSettingCache`, `userCache`, and `userSettingCache` (store/store.go:51-53).

For user entries specifically, `userCache` is populated/read via `userCacheKey(userID)` in `store/user.go` (e.g. `store/user.go:98,122,132,143,150,167`) and invalidated on delete in `store/user_delete.go:39-40`. Since it uses `Set` (not `SetWithTTL`), it inherits the shared config's `DefaultTTL` — **10 minutes** — as set in `store/store.go:41`.
