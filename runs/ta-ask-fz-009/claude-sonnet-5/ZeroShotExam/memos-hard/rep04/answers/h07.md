That driver method runs the actual SQL `SELECT` against the `user` table, returning the row (including `avatar_url`) for the requested user regardless of who the viewer is. Back in the handler, `user.AvatarURL` is fed to `FileServerService.parseDataURI` (`server/router/fileserver/fileserver.go:737`) to decode the stored data-URI into image bytes, which are then written via `c.Blob(...)` (`server/router/fileserver/fileserver.go:209`).

Note on access control: the only gate is `s.Profile.AllowAnonymous()` (`internal/profile/profile.go:46`) plus, when anonymous access is disallowed, a check that *some* authenticated user (`getCurrentUser`, line 174) is making the request — there is no check that the viewer equals the `identifier` being requested, so any authenticated (or, on public instances, any anonymous) caller can fetch another user's avatar via this path.
