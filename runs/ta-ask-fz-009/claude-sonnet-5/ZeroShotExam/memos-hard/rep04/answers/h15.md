This is one distinct enforcement site: fileserver's attachment permission check. Now let's check memo_share_service.go (share tokens) and the frontend router for the SPA memo detail page, plus sse_hub.go for broadcast filtering.

h15.

Memo visibility (`PUBLIC` / `PROTECTED` / `PRIVATE`, gated additionally by row-status/archived and creator/admin override) is **not** enforced through one shared gate — it's independently re-implemented at each of the following server surfaces:

1. **Core memo read API (gRPC/Connect `MemoService.GetMemo`)** — `checkMemoReadAccess` in `server/router/api/v1/memo_service.go:39-68` (archived→creator-only, private→creator-only, protected/public→any authenticated/public reader). Reused by `ListMemoComments`.
2. **Memo comment creation surface** — a separate inline check (not routed through `checkMemoReadAccess`) in `server/router/api/v1/memo_service_comments.go:33-43` (`CreateMemoComment`), gating who may even comment on a memo based on its visibility.
3. **Reaction service** — its own inline visibility checks in `server/router/api/v1/reaction_service.go:29-41` (`ListMemoReactions`) and `:82-85` (`UpsertMemoReaction`).
4. **Attachment service (API v1, `GetAttachment`/download by attachment resource)** — `checkAttachmentAccess` in `server/router/api/v1/attachment_service.go:422-455`, and a duplicate inline version in `server/router/api/v1/memo_attachment_service.go:210-224`.
5. **Raw file-serving HTTP surface (non-gRPC)** — `checkAttachmentPermission` in `server/router/fileserver/fileserver.go:650-704`, which additionally accounts for anonymous access and share-token fallback.
6. **Real-time SSE event broadcast** — `SSEClient.canReceive` in `server/router/api/v1/sse_hub.go:134-144`, filtering which connected clients receive a memo-related event by its visibility.
7. **Email notification dispatch** — `canViewerAccessMemo` in `server/notification/email.go:306-320`.
8. **In-app inbox/notification surface** — a separately-defined `canViewerAccessMemo` in `server/router/api/v1/user_service_notifications.go:302-316`.
9. **Mention-notification dispatch** — visibility checks in `server/router/api/v1/memo_mention_helpers.go:62-84` deciding whether a mentioned user may be notified about a memo/comment they mention-referenced.
10. **Memo relation listing** — creator/visibility filter in `server/router/api/v1/memo_relation_service.go:35` and the CEL filter construction at `:109-111`.

That's at least ten distinct sites across four different protocols/entry points (gRPC API, raw HTTP file server, SSE stream, background notification dispatch) — each maintains its own copy of the private/protected/public + creator/admin logic rather than calling a single shared authorization function.
