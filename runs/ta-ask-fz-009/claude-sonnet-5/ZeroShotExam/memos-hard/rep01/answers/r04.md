**Premise correction:** Neither. This codebase (usememos/memos) has no message broker at all — no NATS or RabbitMQ dependency exists, and there is no queue declaration anywhere in the repo (`grep` for `nats|rabbitmq|amqp` across the whole tree returned zero matches, and the code graph search for `webhook` surfaces only the webhook API/proto symbols, not any broker client).

**Actual mechanism:** Webhook delivery is handled entirely in-process with a bounded Go channel, not a broker. In `internal/webhook/webhook.go:39`, `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` — a 128-slot buffered channel that serves as the "queue." `init()` (webhook.go:42-55) spawns 4 fixed worker goroutines that range over `asyncPostQueue` and call `Post(payload)` (webhook.go:120) to actually deliver the HTTP POST to the configured webhook URL. Producers enqueue via `PostAsync` (webhook.go:184-196), which does a non-blocking send (`select`/`default`) and logs+drops the payload if the channel is full, rather than retrying against any broker.

So there's no NATS/RabbitMQ topology to point to — the "queue" is the in-memory Go channel `asyncPostQueue`, declared and consumed entirely within `internal/webhook/webhook.go`.
