**Premise correction:** There is no GraphQL schema for the public API in this repository — it's a false premise. This project (usememos/memos) exposes its public API as **gRPC services with a REST/JSON gateway**, not GraphQL. A repo-wide grep for `graphql`/`schema.graphql`/`type Query`/`type Mutation` returned zero matches across 1042 searched files, and the code-graph's API surface extraction (`[ArchMap query]`) shows the same thing: no GraphQL routes anywhere.

**Actual API surface:**
- The API is defined via **Protobuf service definitions** (e.g. `MemoService`, `UserService`, `AttachmentService`, `AuthService`, `InstanceService`, `IdentityProviderService`, `ShortcutService`), compiled into generated Go code under `proto/gen/api/v1/` (e.g. `proto/gen/api/v1/memo_service.pb.gw.go`, `user_service.pb.gw.go`, `auth_service.pb.gw.go`, etc.).
- These generate a **grpc-gateway** REST surface mounted under `/api/v1/...` — e.g. `GET /api/v1/memos`, `POST /api/v1/memos`, `PATCH /api/v1/{memo.name=memos/*}`, `GET /api/v1/auth/me`, `POST /api/v1/users:batchGet`, and similar CRUD/RPC-style routes for each service (full list in the query output above, all anchored to their respective `*_service.pb.gw.go` files).
- Additional non-gRPC public routes exist alongside it: SSE at `server/router/api/v1/sse_handler.go:25`, file/avatar serving at `server/router/fileserver/fileserver.go`, RSS feeds at `server/router/rss/rss.go`, frontend static routes (`robots.txt`, `sitemap.xml`) at `server/router/frontend/frontend.go`, and a health check at `server/server.go:44`.

So the schema-equivalent artifact here is the `.proto` files that generate `proto/gen/api/v1/*.pb.gw.go` (the actual `.proto` source definitions would live under a `proto/api/v1/` or similar source tree — worth checking `proto/` directly if you want the hand-written service/message definitions rather than the generated gateway code).
