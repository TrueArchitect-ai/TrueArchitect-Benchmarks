Memo visibility enforcement is duplicated across many independent server surfaces, each re-implementing its own visibility/ownership check rather than sharing one gate. Distinct enforcement sites found:

1. Memo Service (gRPC/Connect `GetMemo`) — `server/router/api/v1/memo_service.go:44-67` (checks archived-status + `store.Public`/`store.Private` + creator match)
2. Memo Comment Service (`CreateMemoComment`) — `server/router/api/v1/memo_service_comments.go:33-43` (blocks commenting on a private memo you don't own)
3. Memo Reaction Service (`ListMemoReactions`, reaction create/delete) — `server/router/api/v1/reaction_service.go:29-41` and `:83`
4. Memo Attachment Service (`ListMemoAttachments`) — `server/router/api/v1/memo_attachment_service.go:213-225`
5. Attachment Service (direct attachment/blob access, `GetAttachment`-style check) — `server/router/api/v1/attachment_service.go:436-454`
6. File Server (raw resource/attachment HTTP endpoint, `AllowAnonymous`/share-token/creator checks) — `server/router/fileserver/fileserver.go:674-701`
7. Notification eligibility (`canViewerAccessMemo`, gates in-app inbox/mention notifications) — `server/router/api/v1/user_service_notifications.go:302-320,337-385`
8. Email notification dispatch (separate, near-duplicate `canViewerAccessMemo`) — `server/notification/email.go:155,187,306-320`
9. RSS feed generation (visibility-filtered listing, public only) — `server/router/rss/rss.go:88-93,138-144`
10. Sitemap generation (visibility-filtered listing, public only) — `server/router/frontend/frontend.go:149-151`
