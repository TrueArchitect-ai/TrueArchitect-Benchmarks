Memo-visibility enforcement is duplicated across many independent server surfaces rather than centralized in one gate. Distinct sites found:

1. Core memo read-access gate (gRPC/Connect API, `GetMemo` / comment listing) — `server/router/api/v1/common.go:39` (`checkMemoReadAccess`), invoked from `server/router/api/v1/memo_service.go:356,367` and `server/router/api/v1/memo_service_comments.go:148`
2. Memo list query-time visibility filter (`ListMemos`) — `server/router/api/v1/memo_service.go:218-227`
3. Comment-creation visibility check (must be able to read the parent to comment) — `server/router/api/v1/memo_service_comments.go:41`
4. Reaction service (list/create reactions requires read access to memo) — `server/router/api/v1/reaction_service.go:30-40,83-86`
5. Attachment service (standalone `GetAttachment`/linked attachment access) — `server/router/api/v1/attachment_service.go:445-453`
6. Memo-attachment service (per-memo attachment listing) — `server/router/api/v1/memo_attachment_service.go:214-224`
7. Raw file-serving HTTP surface (separate from the gRPC/Connect API, its own auth+visibility check) — `server/router/fileserver/fileserver.go:677-701`
8. SSE real-time event hub (`canReceive` gates which connected clients get a pushed memo event) — `server/router/api/v1/sse_hub.go:134-144`
9. Frontend/sitemap generator (restricts to public memos only) — `server/router/frontend/frontend.go:149-151`
10. Email notification dispatch (`canViewerAccessMemo`, one implementation) — `server/notification/email.go:306-320`
11. In-app/inbox notification service (`canViewerAccessMemo`, a second, separately-defined implementation) — `server/router/api/v1/user_service_notifications.go:302-316`
12. Mention-notification helper (visibility check before notifying a mentioned user) — `server/router/api/v1/memo_mention_helpers.go:62-84`

Notable detail: `canViewerAccessMemo` is defined twice, independently, in `server/notification/email.go:306` and `server/router/api/v1/user_service_notifications.go:302` — same logic, not shared code, so it's two separate enforcement sites that must be kept in sync by hand.
