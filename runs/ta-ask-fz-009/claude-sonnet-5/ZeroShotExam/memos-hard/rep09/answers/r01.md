**Premise correction:** There is no Redis connection in this codebase — I searched for `redis` across all 1042 tracked files (`grep_content`) and the code graph (`ArchMap query [ArchMap query]`) and found zero matches. The cache layer is not backed by an external cache server at all; it's a pure in-process, in-memory cache.

**Actual mechanism:** The cache is implemented at `store/cache/cache.go:67` as `cache.Cache`, a thread-safe in-memory store built on `sync.Map` with a background cleanup goroutine (`cleanupLoop`, `store/cache/cache.go:200`) — no network connection, no Redis client, no config for host/port/auth.

It's wired into the `Store` at `store/store.go:38-61`:
- `Store.New` builds a `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000, OnEviction: nil}` (`store/store.go:40-45`) — this matches `cache.DefaultConfig()` in `store/cache/cache.go:57-64`.
- Three separate `*cache.Cache` instances are created from that same config: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29, 51-53`).

**TTL for user entries:** `userCache` uses the shared `cacheConfig.DefaultTTL`, i.e. **10 minutes** (`store/store.go:41`). User records are written into it via `store.Store.CreateUser`, `UpdateUser`, etc., through `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. `store/user.go:98, 122, 132, 143, 167`), all of which use `Cache.Set` → `SetWithTTL(ctx, key, value, c.config.DefaultTTL)` (`store/cache/cache.go:93-95`), so every user cache entry expires 10 minutes after being set unless the key is refreshed or explicitly deleted (`store/user_delete.go:40`).
