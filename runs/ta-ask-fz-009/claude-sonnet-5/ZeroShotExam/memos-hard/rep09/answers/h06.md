**RPC handlers that can transitively trigger an outbound HTTP request to a user‑configured webhook URL:**

1. `v1.ConnectServiceHandler.CreateMemo` — `server/router/api/v1/connect_services.go:306` → `APIV1Service.CreateMemo` (`memo_service.go:70`) → `DispatchMemoCreatedWebhook` → `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:15,48`)

3. `v1.ConnectServiceHandler.UpdateMemo` — `server/router/api/v1/connect_services.go:330` → `APIV1Service.UpdateMemo` (`memo_service.go:401`) → `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`) → `DispatchMemoUpdatedWebhook` → `dispatchMemoRelatedWebhook`

5. `v1.ConnectServiceHandler.CreateMemoComment` — `connect_services.go:378` → `APIV1Service.CreateMemoComment` (`memo_service_comments.go:20`) → `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`)

Each of these dispatch paths loads the target's registered webhooks (`s.Store.GetUserWebhooks`, a user‑configured URL) and hands off a `webhook.WebhookRequestPayload` (with `payload.URL = hook.Url`) to `webhook.PostAsync` (`internal/webhook/webhook.go:184`).

`PostAsync` only enqueues onto `asyncPostQueue`; the four worker goroutines started in `webhook.init` (`internal/webhook/webhook.go:42-54`) all drain that queue by calling the same function.

**Convergence function — path:** `webhook.Post` — `internal/webhook/webhook.go:120`

This is the single point where every one of these RPC-triggered paths (sync or async) actually builds and issues the outbound `http.Request` via `safeClient.Do(req)` (`webhook.go:152`) to the user-supplied `requestPayload.URL`.
