Actual mechanism: webhook dispatch uses an in-process, in-memory Go channel as the "queue," not an external message broker. In `internal/webhook/webhook.go:39`, `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` — a buffered channel of capacity 128. Four worker goroutines are spawned in the package `init()` (webhook.go:42-54) that range over this channel and call `Post()` (webhook.go:120) to actually deliver the HTTP webhook request. `PostAsync()` (webhook.go:184-196) enqueues payloads into the channel with a non-blocking `select`, dropping and logging a warning if the buffer is full (webhook.go:189-195).

So there's no broker/queue infrastructure (NATS, RabbitMQ, or otherwise) anywhere in this repo for webhooks — delivery is fire-and-forget via an in-memory bounded channel consumed by a fixed pool of 4 goroutines within the same process.
