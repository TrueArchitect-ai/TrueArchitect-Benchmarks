**Handlers (RPC methods on `v1.APIV1Service`, the Connect/gRPC service for MemoService) that transitively trigger an outbound webhook POST to a user-configured URL:**

1. `APIV1Service.CreateMemo` — `server/router/api/v1/memo_service.go:70` → calls `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`)
2. `APIV1Service.UpdateMemo` — `server/router/api/v1/memo_service.go:401` → via `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`) → `DispatchMemoUpdatedWebhook` (`memo_service_webhooks.go:20`)
3. `APIV1Service.DeleteMemo` — `server/router/api/v1/memo_service.go:518` → `DispatchMemoDeletedWebhook` (`memo_service_webhooks.go:25`)
4. `APIV1Service.CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20` → `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`)

(Two more RPC handlers, `SetMemoAttachments` and `SetMemoRelations`, also reach the same webhook path indirectly since they call `dispatchMemoUpdatedSideEffects` too.)

Each of these dispatch methods loads the target user's configured webhook URLs (`s.Store.GetUserWebhooks`), builds a `webhook.WebhookRequestPayload{URL: hook.Url, ...}`, and calls `webhook.PostAsync(payload)` (`memo_service_webhooks.go:43,71`), which enqueues onto `asyncPostQueue`.

**Convergence function:** `webhook.Post` — `internal/webhook/webhook.go:120`

All four dispatch paths funnel through `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which only enqueues work; the actual outbound HTTP delivery — marshaling the payload, optionally HMAC-signing it, and issuing `safeClient.Do(req)` against `requestPayload.URL` — happens exclusively inside `Post` at `internal/webhook/webhook.go:120` (the `safeClient.Do` call itself is at line 152). Every RPC-triggered webhook, sync or async, terminates in this single function before hitting the network.
