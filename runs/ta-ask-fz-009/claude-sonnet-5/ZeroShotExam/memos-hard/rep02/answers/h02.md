**Delivery function** — `Post` (with `PostAsync` as the async wrapper feeding a bounded worker queue) in `internal/webhook/webhook.go:120` (async path `:184`). `Post` marshals the `WebhookRequestPayload`, optionally HMAC-signs it, and issues the actual `http.Client.Do(req)` call over `safeClient` (`internal/webhook/webhook.go:152`).

**Protection mechanism** — SSRF/private-network guarding happens at dial time, not just at input validation, so it also defeats DNS-rebinding:
- `safeClient`'s `http.Transport.DialContext` is overridden to `safeDialContext` (`internal/webhook/webhook.go:32-37, 59-77`), which resolves the target host and rejects the connection if any resolved IP is reserved/private (`isReservedIP`, `internal/webhook/validate.go:44-54`).
- The reserved-range check (`internal/webhook/validate.go:14-23`) blocks IPv4/IPv6 loopback, RFC-1918 private ranges, and link-local addresses including the `169.254.169.254` cloud metadata endpoint.
- A second check, `ValidateURL` (`internal/webhook/validate.go:62-83`), performs the same reserved-IP lookup at webhook-creation/update time so obviously bad URLs are rejected up front — belt-and-suspenders with the dial-time guard.
- Both checks can be disabled via the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41,45-47`) for self-hosted deployments that intentionally target internal services.
