**Premise correction:** There is no GraphQL schema in this repository — the premise that the public API is GraphQL doesn't hold. This is the `usememos/memos` codebase, and its public API is defined via **Protocol Buffers + gRPC-Gateway (REST)**, not GraphQL. A repo-wide search for `graphql` (case-insensitive, 1042 files scanned) returned zero matches, and the API-surface extraction shows only REST/gRPC-gateway routes.

**Actual API surface:**
- The service contracts are defined as `.proto` files (e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`) and compiled into Go bindings under `proto/gen/api/v1/`.
- Each service exposes its REST surface through generated gRPC-Gateway files, e.g. `proto/gen/api/v1/memo_service.pb.gw.go:1745`, `proto/gen/api/v1/user_service.pb.gw.go:2301`, `proto/gen/api/v1/attachment_service.pb.gw.go:571`, `proto/gen/api/v1/auth_service.pb.gw.go:331`, `proto/gen/api/v1/instance_service.pb.gw.go:525`, `proto/gen/api/v1/idp_service.pb.gw.go:493`, `proto/gen/api/v1/shortcut_service.pb.gw.go:529` — these translate incoming HTTP calls (`/api/v1/...`) to gRPC service methods.
- Additional non-gRPC public routes are hand-registered in `server/router/`: SSE at `server/router/api/v1/sse_handler.go:25`, file/attachment serving in `server/router/fileserver/fileserver.go`, frontend static routes in `server/router/frontend/frontend.go`, and RSS feeds in `server/router/rss/rss.go`.

So if you're looking for "the schema" in this codebase, the equivalent artifact is the proto definitions (source of truth for request/response types and RPCs), not a `.graphql` SDL file — none exists here.
