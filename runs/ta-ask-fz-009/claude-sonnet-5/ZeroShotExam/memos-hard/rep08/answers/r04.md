r04. Premise correction: neither NATS nor RabbitMQ is used — there is no external message broker in this codebase.

Actual mechanism: webhook delivery is handled entirely in-process via a buffered Go channel. In `internal/webhook/webhook.go`:
- `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (line 39) is the "queue" — an in-memory Go channel with capacity 128, not a broker-backed queue.
- `init()` (lines 42-55) spawns 4 goroutine workers that range over `asyncPostQueue` and call `Post(payload)` to deliver each webhook via HTTP.
- `PostAsync()` (lines 184-196) enqueues a payload into that channel (non-blocking, dropping and logging a warning if the channel is full).

So delivery is fire-and-forget, single-process, bounded-channel fan-out — no NATS/RabbitMQ dependency, and no persistence or cross-process durability for the queue.
