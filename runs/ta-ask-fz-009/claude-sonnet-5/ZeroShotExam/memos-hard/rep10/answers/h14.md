Derived memo metadata (used for lists/previews) is computed in the `MemoPayload.Property` block (plus `Tags`) attached to each memo, via `markdown.Service.ExtractAll` in `internal/markdown/markdown.go:356-420`, invoked through `memopayload.RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`.

**Computation site:**
- `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`) calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns the result into `memo.Payload.Tags` and `memo.Payload.Property` (`storepb.MemoPayload_Property`, defined `proto/gen/store/memo.pb.go:85-95`).
- `ExtractAll` (`internal/markdown/markdown.go:356`) parses the memo's markdown into a goldmark AST and does a single walk (`internal/markdown/markdown.go:371-411`) to collect everything.

**Triggers (recomputation happens only when content is set/changed):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` calls `memopayload.RebuildMemoPayload` right after building the new `store.Memo` from request content.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the branch handling the `content` update-mask path (`server/router/api/v1/memo_service.go:436-451`); changing visibility/pinned/etc. does not retrigger it.
- There is also a batch backfill path, `Runner.RunOnce` in `server/runner/memopayload/runner.go:27-72`, which pages through all memos and calls `RebuildMemoPayload` for each — but this `Runner` is never instantiated/started from `server/server.go` (only the `s3presign` runner is wired into `startBackgroundRunners`, `server/server.go:153-174`), so in the current codebase it's dead/unused infrastructure rather than an active trigger.

**Extracted properties** (from `ExtractedData`/`Property`, `internal/markdown/markdown.go:20-25` and `356-420`):
- `Tags` — all `#tag` nodes found in the AST, deduplicated case-preserving.
- `Mentions` — all `@username` mention nodes, lowercased and deduplicated.
- `Property.Title` — text of the first H1 heading if it's the document's first block-level child.
- `Property.HasLink` — set if any Markdown link node is present.
- `Property.HasCode` — set if any code block, fenced code block, or code span is present.
- `Property.HasTaskList` — set if any task checkbox node is present.
- `Property.HasIncompleteTasks` — set if any task checkbox is unchecked.

These computed fields live in `storepb.MemoPayload_Property` and mirror to the API's `Memo_Property` (`proto/gen/api/v1/memo_service.pb.go:2180-2189`), which is what list/preview UI consumes — none of these fields are user-settable; they're always derived from `memo.Content`.
