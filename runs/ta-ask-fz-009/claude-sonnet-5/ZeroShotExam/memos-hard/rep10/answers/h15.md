Memo-visibility enforcement is duplicated across at least these distinct server surfaces (each independently decides who may see a memo — none of them share a single shared authorizer):

- gRPC/Connect Memo API (single-memo reads) — `checkMemoReadAccess` in `server/router/api/v1/memo_service.go:39` (used by `GetMemo` and parent-memo lookups; also invoked from `server/router/api/v1/memo_service_comments.go:148`)
- Memo comment creation (inline duplicate check, not routed through `checkMemoReadAccess`) — `server/router/api/v1/memo_service_comments.go:41`
- Memo attachment listing — `server/router/api/v1/memo_attachment_service.go:213-224`
- Attachment service, linked-attachment access check — `checkAttachmentAccess` in `server/router/api/v1/attachment_service.go:422-454`
- Raw file-serving HTTP surface (separate from the gRPC/Connect API, includes share-token bypass) — `checkAttachmentPermission` in `server/router/fileserver/fileserver.go:650-704`
- Reaction service (list/create reactions) — `server/router/api/v1/reaction_service.go:29-41` and `server/router/api/v1/reaction_service.go:83`
- SSE real-time event push — `canReceive` in `server/router/api/v1/sse_hub.go:134-144`
- User notification construction (in-app) — `canViewerAccessMemo` in `server/router/api/v1/user_service_notifications.go:302-315`
- Email notification dispatch — `canViewerAccessMemo` in `server/notification/email.go:306-319`
- List/query-level filtering (CEL filter strings baked into store queries for non-owners) — repeated in `server/router/api/v1/memo_service.go:222`, `server/router/api/v1/memo_service_comments.go:158-160`, `server/router/api/v1/memo_service_converter.go:184-186`, `server/router/api/v1/memo_relation_service.go:109-111`, and `server/router/api/v1/user_service_stats.go:87-89`

Note: `canViewerAccessMemo` (notifications) and `checkMemoReadAccess`/inline checks (API/attachments/reactions) each reimplement the same PUBLIC/PROTECTED/PRIVATE + creator/admin logic independently rather than calling one shared function — this is why visibility rules appear duplicated rather than centralized.
