- **Delivery function**: `Post` in `internal/webhook/webhook.go:120` performs the actual outbound HTTP dispatch (marshals the payload, signs it with HMAC-SHA256, and sends it via the shared `safeClient`). It's invoked synchronously or queued asynchronously through `PostAsync` (`internal/webhook/webhook.go:184`), which feeds a bounded worker pool (`asyncPostQueue`, `internal/webhook/webhook.go:39-54`) that also calls `Post`.

- **Protection mechanism**: SSRF/private-network protection is enforced at dial time by `safeDialContext` (`internal/webhook/webhook.go:59`), installed as the `DialContext` of the shared `http.Transport` used by `safeClient` (`internal/webhook/webhook.go:32-37`). It resolves the hostname and rejects any resolved IP falling in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`), which checks against `reservedCIDRs`/`reservedNetworks` covering loopback, RFC-1918 private ranges, link-local/cloud-IMDS (169.254.169.254), and their IPv6 equivalents (`internal/webhook/validate.go:14-36`). This resolve-then-check-at-dial-time approach also defends against DNS rebinding. A separate pre-flight check, `ValidateURL` (`internal/webhook/validate.go:62`), performs the same reserved-IP check at webhook-registration time so invalid URLs are rejected up front. Both checks can be disabled for self-hosted/local-network use via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`).
