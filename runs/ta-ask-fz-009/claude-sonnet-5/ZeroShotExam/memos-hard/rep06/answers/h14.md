h14. Computation site; triggers; extracted properties

- **Where it's computed:** `server/runner/memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`), which delegates the actual content parsing to the markdown service's `ExtractAll` — implemented at `internal/markdown/markdown.go:356` (`(*service).ExtractAll`), a single-pass goldmark AST walk. It writes the result into `memo.Payload.Tags` and `memo.Payload.Property` (a `storepb.MemoPayload_Property`, defined at `proto/gen/store/memo.pb.go:85`).

- **Triggers (what recomputes it):**
  - Memo creation — `CreateMemo` calls `memopayload.RebuildMemoPayload` unconditionally (`server/router/api/v1/memo_service.go:108`).
  - Memo update, but *only when the content field is part of the update mask* — `UpdateMemo` calls it inside the `path == "content"` branch (`server/router/api/v1/memo_service.go:447`), so editing visibility/pinned/etc. alone does not recompute it.
  - A one-off backfill/maintenance runner — `Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) batches through `store.ListMemos` and calls `RebuildMemoPayload` for every memo, then persists via `Store.UpdateMemo`, used to backfill/repair payloads for existing memos (e.g. after a migration).

- **What the computation extracts** (all derived purely from `memo.Content`, via the single goldmark AST walk in `ExtractAll`, which itself invokes the same logic as `ExtractProperties` at `internal/markdown/markdown.go:193`):
  - `Tags` — `#tag` nodes found by walking the AST (`asMemoTagNode`), deduplicated.
  - `Mentions` — `@username` tokens (`mast.MentionNode`), lowercased (used separately for notification targeting, not stored as list metadata but computed in the same pass).
  - `Property.Title` — text of the first block-level child if it's an H1 heading.
  - `Property.HasLink` — set if any `Link` AST node is present.
  - `Property.HasCode` — set if any code block/fenced code block/code span node is present.
  - `Property.HasTaskList` / `Property.HasIncompleteTasks` — set from `TaskCheckBox` nodes, with the latter true if any checkbox is unchecked.

This metadata (tags + boolean/title properties) is what memo list/preview views consume, distinct from user-set fields like content, visibility, or pinned state.
