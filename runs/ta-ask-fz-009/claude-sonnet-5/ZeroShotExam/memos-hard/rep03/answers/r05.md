**Premise correction:** There is no GraphQL schema in this repository — this is the Memos codebase, and its public API is built entirely on **gRPC + gRPC-Gateway (REST/JSON)**, not GraphQL. A grep for GraphQL/schema/type-Query patterns turns up nothing GraphQL-related; the only "schema" hits are unrelated (filter schema builders in `internal/filter/schema.go`, and JSON-schema helpers for the MCP/OpenAPI tool catalog in `server/router/mcp/catalog.go` and `server/router/mcp/openapi.go`).

**Actual API surface** (per `[ArchMap query]`):
- Service contracts are defined as Protobuf in `proto/` and compiled to Go bindings/gateway handlers under `proto/gen/api/v1/*.pb.gw.go` (e.g. `memo_service.pb.gw.go:1745`, `user_service.pb.gw.go:2301`, `attachment_service.pb.gw.go:571`, `auth_service.pb.gw.go:331`, `idp_service.pb.gw.go:493`, `instance_service.pb.gw.go:525`, `shortcut_service.pb.gw.go:529`).
- These generate the REST-style JSON gateway routes under `/api/v1/...` (e.g. `POST /api/v1/memos`, `GET /api/v1/users`, etc.), all resolved back to the gateway files above.
- Additional non-gRPC public routes exist alongside it: SSE (`server/router/api/v1/sse_handler.go:25`), file/avatar serving (`server/router/fileserver/fileserver.go`), frontend static routes (`server/router/frontend/frontend.go`), RSS feeds (`server/router/rss/rss.go`), and a health check (`server/server.go:44`).
- There's also an OpenAPI/MCP tool catalog (`server/router/mcp/openapi.go`, `server/router/mcp/catalog.go`) that describes the REST surface for MCP tooling, but that's OpenAPI-derived from the same proto services, not a separate GraphQL layer.

So: the schema you're looking for lives in **`proto/`** (protobuf `.proto` service/message definitions), not any `.graphql`/`.gql` file — this project has no GraphQL API.
