h05. Explicit Go application code, not a database-level rule.

**Mechanism:** The `reaction` table has no foreign key or `ON DELETE CASCADE` on `creator_id` (or on `content_id`, which isn't even a schema-level FK since it's a polymorphic string reference to memo/comment resource names). It's declared plainly in all three dialect schemas as `CREATE TABLE reaction (... creator_id INT NOT NULL, content_id VARCHAR(256) NOT NULL, ...)` with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint — no cascade rule (`store/migration/mysql/LATEST.sql:91-98`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/sqlite/LATEST.sql:92-99`). Compare this to `memo_share`, which *does* declare `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (e.g. `store/migration/sqlite/LATEST.sql:109`) — reaction has no equivalent.

Instead, deletion is done by explicit application code inside the `DeleteUser` transaction:
- `server/router/api/v1/user_service.go:414` calls `s.Store.DeleteUser(ctx, &store.DeleteUser{ID: user.ID})`
- `store/user.go:171` (`Store.DeleteUser`) delegates to the SQL-driver implementation (`s.driver.DeleteUser`)
- The sqlite driver (`store/db/sqlite/user_delete.go:92-127`, `deleteUserTargetsTx`) explicitly issues, in order:
  - `deleteReactionsByContentIDsTx` (`store/db/sqlite/user_delete.go:380-388`) — `DELETE FROM reaction WHERE content_id IN (...)` for every memo/comment the user owned (removes reactions *left by others* on the deleted user's content)
  - `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:400-403`) — `DELETE FROM reaction WHERE creator_id = ?` (removes reactions *the deleted user made* on any content)
- The MySQL and Postgres drivers (`store/db/mysql/user_delete.go:29`, `store/db/postgres/user_delete.go:29`) implement the analogous transactional logic (same pattern, confirmed via `go_to_definition` for `DeleteUser`).

So both directions of emoji-reaction ownership (reactions the user authored, and reactions on the user's own memos/comments) are cleaned up by hand-written Go/SQL inside a single transaction, not by a database cascade rule.
