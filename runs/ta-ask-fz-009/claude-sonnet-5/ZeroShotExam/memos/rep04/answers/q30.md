**Memo lifecycle events → dispatch functions** (all in `server/router/api/v1/memo_service_webhooks.go`):

- memo created: `DispatchMemoCreatedWebhook` (memo_service_webhooks.go:15) → activity type `memos.memo.created`
- memo updated: `DispatchMemoUpdatedWebhook` (memo_service_webhooks.go:20) → activity type `memos.memo.updated`
- memo deleted: `DispatchMemoDeletedWebhook` (memo_service_webhooks.go:25) → activity type `memos.memo.deleted`
- memo comment created: `DispatchMemoCommentCreatedWebhook` (memo_service_webhooks.go:30) → activity type `memos.memo.comment.created`

The first three funnel through the shared helper `dispatchMemoRelatedWebhook` (memo_service_webhooks.go:48), which looks up the memo creator's registered webhooks (`s.Store.GetUserWebhooks`) and builds a `webhook.WebhookRequestPayload` per hook via `convertMemoToWebhookPayload` (memo_service_webhooks.go:76). `DispatchMemoCommentCreatedWebhook` builds its payload inline the same way but targets the related memo owner's webhooks instead of the memo creator's.

**Convergence point for delivery:**
All four dispatch paths call `webhook.PostAsync` (`internal/webhook/webhook.go:184`) — memo_service_webhooks.go:43 and :71. `PostAsync` enqueues the payload onto `asyncPostQueue`, a buffered channel drained by 4 worker goroutines started in `init()` (internal/webhook/webhook.go:39-55), each of which calls `Post` (`internal/webhook/webhook.go:120`) — the single function that actually marshals the payload, signs it (Standard Webhooks HMAC signature), and performs the outbound HTTP POST via the shared `safeClient`.

So: `internal/webhook/webhook.go`'s `Post` function is the ultimate delivery point that every memo-lifecycle webhook converges on.
