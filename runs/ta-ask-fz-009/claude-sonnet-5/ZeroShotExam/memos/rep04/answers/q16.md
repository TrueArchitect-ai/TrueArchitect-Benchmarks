In `store.Store.DeleteMemo` (store/memo.go:140-159), before deleting the memo row itself (`s.driver.DeleteMemo`, line 158), the store layer deletes:

1. **Memo relations** where the memo is the source (`DeleteMemoRelation{MemoID: &delete.ID}`, store/memo.go:142) — e.g. comment/reference links originating from this memo.
2. **Memo relations** where the memo is the target (`DeleteMemoRelation{RelatedMemoID: &delete.ID}`, store/memo.go:145) — links pointing at this memo.
3. **Attachments** linked to the memo — first listed via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` then deleted one-by-one via `DeleteAttachment` (store/memo.go:149-157).

Note: reactions and memo shares are not deleted inside `store.DeleteMemo` itself — reactions/attachments are gathered upstream in the API handler (`server/router/api/v1/memo_service.go:545-557`) only for webhook payload construction, and comment-type child memos are deleted recursively by the handler calling `store.DeleteMemo` again per comment (`server/router/api/v1/memo_service.go:567-577`) before the parent memo delete — but that recursion happens at the API/service layer, not inside the store's `DeleteMemo` function.
