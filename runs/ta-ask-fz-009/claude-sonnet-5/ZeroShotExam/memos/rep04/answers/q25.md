**Engine:** a hand-built CEL (Common Expression Language) filter engine in `internal/filter/` (using `github.com/google/cel-go/cel`), exposed as `filter.Engine`/`filter.DefaultEngine()` — core files `internal/filter/engine.go`, `internal/filter/schema.go`, `internal/filter/parser.go`, `internal/filter/render.go`.

**Where it enters ListMemos:** `server/router/api/v1/memo_service.go:178` (`APIV1Service.ListMemos`) validates `request.Filter` via `s.validateFilter` and appends it to `store.FindMemo.Filters`.

**Mechanism (CEL → SQL):** `filter.NewEngine` builds a CEL `*cel.Env` from a schema of declared variables/types (`internal/filter/schema.go:232-248`, e.g. `content`, `creator_id`, `tag`, `visibility`, `has_task_list`, etc.); `Engine.Compile` (`internal/filter/engine.go:48-70`) compiles the filter string to a CEL AST and walks it (`parser.go`) into a dialect-agnostic `Condition` tree; each dialect's store driver (`store/db/sqlite/memo.go:57-63`, `store/db/mysql/memo.go:65`, `store/db/postgres/memo.go:54`) then calls `filter.AppendConditions`/`engine.CompileToStatement(ctx, filterStr, filter.RenderOptions{Dialect: ...})`, which invokes the `renderer` in `internal/filter/render.go` to turn that condition tree into a `WHERE` fragment and args using dialect-specific SQL idioms (e.g. SQLite `strftime`, Postgres `EXTRACT ... AT TIME ZONE`/`->>`, MySQL `JSON_LENGTH`) selected via `DialectName` in `render.go` (lines ~222-244, 928-976).
