q25.

**Engine:** Google's CEL (Common Expression Language), via `github.com/google/cel-go`, wrapped in a custom package at `internal/filter/` (files `engine.go`, `schema.go`, `ir.go`, `render.go`, `helpers.go`).

**Mechanism:** `MemoService.ListMemos` (`server/router/api/v1/memo_service.go:211-215`) takes the request's `filter` string, validates it, and appends it to `store.FindMemo.Filters` (`store/memo.go:72`); at the storage layer each dialect's `memo.go` (`store/db/{mysql,postgres,sqlite}/memo.go`) calls `filter.AppendConditions` (`internal/filter/helpers.go:9`), which uses a shared `filter.Engine` (`internal/filter/engine.go`) to `cel.NewEnv(...).Compile(filter)` the CEL expression, convert the resulting CEL AST into an internal dialect-agnostic `Condition` tree (`internal/filter/ir.go`), and then render that tree through a `renderer` (`internal/filter/render.go`) that switches on `DialectName` (`DialectSQLite`/`DialectPostgres`/`DialectMySQL`, `render.go:231-237`) to emit dialect-specific SQL fragments and positional args (e.g. backtick-quoted `LIKE`/`REGEXP` for SQLite/MySQL vs. `ILIKE`/`~` with `$N` placeholders for Postgres, per `internal/filter/engine_test.go`).
