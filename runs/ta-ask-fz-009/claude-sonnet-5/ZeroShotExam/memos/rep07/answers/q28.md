**Background workers/runners actually started by the server**

- **S3 presign runner** (`server/runner/s3presign`) — started in `server.Start()` → `startBackgroundRunners()` (`server/server.go:153-174`). It runs an initial `RunOnce` synchronously, then a goroutine calls `Run(ctx)` which loops on a `time.NewTicker(runnerInterval)` with `runnerInterval = 12h` (`server/runner/s3presign/runner.go:27-40`). Trigger: **fixed 12-hour interval ticker**, cancelled via its own `context.CancelFunc` on shutdown.

That is the *only* runner wired into `startBackgroundRunners` — no other entry in `server/server.go` starts a goroutine loop.

**Present but not started as a background worker**

- **Memo payload runner** (`server/runner/memopayload`, `RunOnce`) — exists with the same batch-processing shape as the s3presign runner, but the server never calls `memopayload.NewRunner(...)` or its `RunOnce` in a loop. Its only caller is `memopayload.RebuildMemoPayload`, invoked synchronously and inline inside request handling in `server/router/api/v1/memo_service.go:108` and `:447` (on memo create/update) — not as a scheduled/background job.

**Unused scheduling infrastructure**

- `internal/scheduler` (`internal/scheduler/scheduler.go`) is a fully built cron-style scheduler (cron expression parsing, `Register`/`Start`/`Stop`, middleware like `Recovery`/`Logging`/`Timeout`, timezone support — see `internal/scheduler/doc.go`). Searching the codebase shows it is imported **only from its own test files** (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`) — no production code (`server/server.go`, `cmd/memos/main.go`, or any router) references `internal/scheduler`. This package is dead/unused infrastructure as far as the running server is concerned.

**Not a "runner" but worth noting**: the in-memory `store/cache` package (`store/cache/cache.go:200`) spins up its own `cleanupLoop()` goroutine on a ticker whenever `cache.New(...)` is called, and `store.New` creates three such caches (`instanceSettingCache`, `userCache`, `userSettingCache` in `store/store.go:51-53`). This is a background goroutine that does start as a side effect of store initialization, but it's a cache-TTL sweep, not a job/task runner analogous to s3presign/memopayload.
