I have enough to answer. The store layer's `Store.DeleteMemo` (store/memo.go:140-159) deletes these before removing the memo row itself (via `driver.DeleteMemo`):

q16.
- **Memo relations** (`memo_relation` records) — deleted twice: once where the memo is the source (`MemoID`) and once where it is the target (`RelatedMemoID`), via `driver.DeleteMemoRelation` (store/memo.go:142-147).
- **Attachments** linked to the memo — fetched with `ListAttachments` and removed one by one via `s.DeleteAttachment` (store/memo.go:149-157).

Only after these two cleanup steps does it call `s.driver.DeleteMemo(ctx, delete)` to delete the memo row itself (store/memo.go:158; concrete SQL in store/db/mysql/memo.go:259-270).

(Note: at the API layer, `APIV1Service.DeleteMemo` in server/router/api/v1/memo_service.go:518-582 also separately lists reactions/attachments for webhook purposes and recursively deletes "comment" memos first — but the actual store-layer cascade performed by `Store.DeleteMemo` itself only touches memo relations and attachments as listed above.)
