**Interceptor path:** `web/src/connect.ts` (the `authInterceptor` defined at `connect.ts:156`, wired into the Connect transport at `connect.ts:188`). It attaches the bearer token to each request (`setAuthorizationHeader`, `connect.ts:97`), does a preflight refresh if the access token is expiring (`getRequestToken`, `connect.ts:124`), and reactively refreshes-and-retries once on a `Code.Unauthenticated` (401) response before redirecting on repeated failure (`connect.ts:156-178`).

**Tokens it manages:** an in-memory/localStorage **access token** (short-lived JWT, managed via `web/src/auth-state.ts` — `getAccessToken`/`setAccessToken`, key `memos_access_token`, shared across tabs via `BroadcastChannel`), plus a **refresh token** held in an httponly cookie and exchanged via `refreshAuthClient.refreshToken({})` (`connect.ts:75`) to mint new access tokens.

**Backend validation package:** `server/auth` (package `auth`), specifically `server/auth/authenticator.go`'s `Authenticator` type, which validates the bearer access token (`AuthenticateByAccessTokenV2`, `authenticator.go:41`), the refresh-token cookie (`AuthenticateByRefreshToken`, `authenticator.go:61`), and personal access tokens (`AuthenticateByPAT`, `authenticator.go:102`), unified through `Authenticate`/`AuthenticateToUser` (`authenticator.go:190,213`). This is invoked by the request-layer `Authorizer` in `server/router/api/v1/authz.go:44` (`Authorizer.Authenticate`), which is what `NewAuthInterceptor` (`server/router/api/v1/connect_interceptors.go:213`) wraps into the actual Connect RPC interceptor on the Go server side.
