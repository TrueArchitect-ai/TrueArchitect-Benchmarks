**Engine:** Google's CEL (Common Expression Language), via `github.com/google/cel-go`, wrapped in a custom package at **`internal/filter/`** (`engine.go`, `schema.go`, `ir.go`, `render.go`). The `ListMemosRequest.filter` string uses CEL syntax (e.g. `creator_id == 123 || visibility in ["PUBLIC","PROTECTED"]`, as seen fabricated in `server/router/api/v1/memo_service.go:222`).

**Mechanism (filter → SQL):**
1. `filter.NewEngine`/`DefaultEngine()` builds a `cel.Env` from the memo schema's variable declarations (`internal/filter/schema.go:232-244`, e.g. `content`, `creator_id`, `tags`, `visibility`, `pinned`, etc.).
2. `Engine.Compile` (`internal/filter/engine.go:48`) parses the filter string with `cel.Env.Compile` → CEL AST → `cel.AstToParsedExpr`, then `buildCondition` walks that expr tree into this package's own dialect-agnostic IR (`Condition`/`ValueExpr` types in `internal/filter/ir.go`), producing a `Program`.
3. `Program.Render(RenderOptions{Dialect: ...})` (`internal/filter/engine.go:96`) hands the `Condition` tree to a `renderer` (`internal/filter/render.go`), whose `renderCondition`/`renderComparison`/`renderFieldPredicate`/etc. methods switch on `RenderOptions.Dialect` (`DialectSQLite`, `DialectPostgres`, `DialectMySQL`) to emit dialect-specific SQL fragments and placeholder args — e.g. different timestamp casts (`strftime` for SQLite, `EXTRACT...AT TIME ZONE` for Postgres, MySQL date functions) and JSON accessor syntax (`render.go:928-976`), producing a `Statement{SQL, Args}`.
4. Each store backend calls this per-dialect: `store/db/sqlite/memo.go:57` (`filter.DialectSQLite`), `store/db/postgres/memo.go:54` (`filter.DialectPostgres`), `store/db/mysql/memo.go:65` (`filter.DialectMySQL`), typically via `filter.AppendConditions(...)` to fold the rendered fragment into the `WHERE` clause and args slice.
