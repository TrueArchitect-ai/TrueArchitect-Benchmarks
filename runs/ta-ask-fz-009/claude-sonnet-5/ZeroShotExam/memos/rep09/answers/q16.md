Also checking whether reactions get cleaned up (DeleteMemo trace showed ListReactions call from API layer, not store). Let me verify.

q16. Before deleting the memo row itself, `store.Store.DeleteMemo` (store/memo.go:140-158) deletes:

1. **Memo relations** — all `memo_relation` rows where the memo is the source (`DeleteMemoRelation{MemoID: &delete.ID}`) and where it is the target (`DeleteMemoRelation{RelatedMemoID: &delete.ID}`), store/memo.go:142-147.
2. **Attachments** — it lists all attachments linked to the memo (`ListAttachments`, store/memo.go:149) and calls `s.DeleteAttachment` for each one, store/memo.go:153-156; `DeleteAttachment` (store/attachment.go:132-149) in turn removes the attachment's backing storage (`DeleteAttachmentStorage`) before deleting the attachment row itself.

Only after both of these cleanups does it call `s.driver.DeleteMemo(ctx, delete)` (store/memo.go:158) to delete the memo row.

Note: reactions (`ListReactions`) are only read/listed at the API layer (server/router/api/v1/memo_service.go:545) for building the response — they are not deleted by the store layer during memo deletion.
