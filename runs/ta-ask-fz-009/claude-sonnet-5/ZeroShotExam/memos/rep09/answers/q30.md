Memo lifecycle events that dispatch webhooks, and their dispatch functions — all defined in `server/router/api/v1/memo_service_webhooks.go`:

The first three all funnel through a shared helper, `dispatchMemoRelatedWebhook` (memo_service_webhooks.go:48), which looks up the memo creator's registered webhooks and builds the payload; `DispatchMemoCommentCreatedWebhook` does the same lookup/build inline for the related memo's creator instead.

**Convergence point for delivery:** every path ends by calling `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload onto a bounded async queue (`asyncPostQueue`, webhook.go:39) consumed by a pool of worker goroutines started in `init()` (webhook.go:42-55). Each worker calls `webhook.Post` (`internal/webhook/webhook.go:120`), the single function that actually marshals the payload, signs it (Standard Webhooks HMAC-SHA256), and performs the HTTP POST to the target URL via the SSRF-guarded `safeClient`.
