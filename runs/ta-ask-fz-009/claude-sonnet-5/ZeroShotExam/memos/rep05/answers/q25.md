**Engine:** `github.com/google/cel-go` (Common Expression Language), wrapped by a custom package at `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`).

**Mechanism:** the filter string on `ListMemosRequest` (consumed in `server/router/api/v1/memo_service.go:213`, e.g. `memoFind.Filters`) is parsed and schema-validated as CEL via `cel-go` (`internal/filter/schema.go` declares the memo field environment, `internal/filter/engine.go` builds the `cel.Env` and produces the parsed AST), then `internal/filter/parser.go` walks that CEL AST into a dialect-agnostic intermediate representation (`internal/filter/ir.go`), and finally `internal/filter/render.go` walks the IR to emit dialect-specific SQL fragments + placeholder args (branching on `DialectSqlite`/`DialectMysql`/`DialectPostgres`) — cel-go itself is only used for parsing/type-checking, never for evaluation (per `internal/filter/README.md:1-20`).
