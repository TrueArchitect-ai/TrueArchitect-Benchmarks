Memo lifecycle events and their dispatch functions (all in `server/router/api/v1/memo_service_webhooks.go`):

- `memos.memo.created`: `(*APIV1Service).DispatchMemoCreatedWebhook` (memo_service_webhooks.go:15) — called from `memo_service.go:157` on memo creation
- `memos.memo.updated`: `(*APIV1Service).DispatchMemoUpdatedWebhook` (memo_service_webhooks.go:20) — called from `memo_update_helpers.go:67` on memo update
- `memos.memo.deleted`: `(*APIV1Service).DispatchMemoDeletedWebhook` (memo_service_webhooks.go:25) — called from `memo_service.go:562` on memo deletion
- `memos.memo.comment.created`: `(*APIV1Service).DispatchMemoCommentCreatedWebhook` (memo_service_webhooks.go:30) — called from `memo_service_comments.go:119` when a comment is created

All four of these are thin wrappers: the three memo-level events (`created`/`updated`/`deleted`) funnel through a shared helper, `(*APIV1Service).dispatchMemoRelatedWebhook` (memo_service_webhooks.go:48), which loads the creator's webhooks, builds the payload via `convertMemoToWebhookPayload` (memo_service_webhooks.go:76), and hands off delivery. The comment-created path builds its payload inline but hands off the same way.

**Convergence point for actual delivery:** `webhook.PostAsync` in `internal/webhook/webhook.go:184`, which enqueues the `*WebhookRequestPayload` onto the bounded `asyncPostQueue`; the queue's worker(s) ultimately invoke `webhook.Post` (`internal/webhook/webhook.go:120`), which marshals the payload, optionally HMAC-signs it (Standard Webhooks scheme), and performs the actual `POST` over HTTP to the webhook's URL.
