q29. The frontend attaches a bearer token to every RPC via a Connect-RPC interceptor, and the backend validates it through a dedicated `auth` package.

- **Interceptor**: `authInterceptor` in `web/src/connect.ts:156` (registered on the Connect transport at `web/src/connect.ts:184-189`). It reads the current token via `getRequestToken()` (`web/src/connect.ts:124`), sets `Authorization: Bearer <token>` on outgoing requests (`setAuthorizationHeader`, `web/src/connect.ts:97`), and on a `Code.Unauthenticated` response triggers a one-shot refresh-and-retry (`shouldHandleUnauthenticatedRetry` / `refreshAndGetAccessToken`, `web/src/connect.ts:102-122`), redirecting the user out on failure (`redirectOnAuthFailure`).

- **Tokens managed**: an **access token** (short-lived, kept in memory + `localStorage` under `memos_access_token`, tracked with an expiry `memos_token_expires_at`, and synced across tabs via a `BroadcastChannel` — `web/src/auth-state.ts:1-40`) and a **refresh token** (handled server-side via cookies; the frontend calls `AuthService.RefreshToken` through a separate, interceptor-free `refreshTransport`/`refreshAuthClient` to avoid recursive auth loops, `web/src/connect.ts:64-83`).

- **Backend validation**: on the server, `v1.AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:208-239`) extracts the `Authorization` header and delegates to an `Authorizer` (`server/router/api/v1/authz.go:26`), which wraps an `*auth.Authenticator` from the **`server/auth`** package (imported at `server/router/api/v1/connect_interceptors.go:14` as `"github.com/usememos/memos/server/auth"`). `Authorizer.Authenticate` validates the bearer token and the result is applied to the request context (`auth.ApplyToContext`) before the call proceeds; failures return `connect.CodeUnauthenticated`.

**Answer format:** `web/src/connect.ts` (authInterceptor, line 156); access token + refresh token; `server/auth` (validated via `server/router/api/v1/authz.go`'s `Authorizer`/`AuthInterceptor`)
