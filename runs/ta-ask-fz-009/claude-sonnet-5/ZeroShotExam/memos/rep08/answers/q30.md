**Memo lifecycle events that dispatch webhooks** (all in `server/router/api/v1/memo_service_webhooks.go`):

- `memos.memo.created`: `DispatchMemoCreatedWebhook` (memo_service_webhooks.go:15) → calls `dispatchMemoRelatedWebhook`
- `memos.memo.updated`: `DispatchMemoUpdatedWebhook` (memo_service_webhooks.go:20) → calls `dispatchMemoRelatedWebhook`
- `memos.memo.deleted`: `DispatchMemoDeletedWebhook` (memo_service_webhooks.go:25) → calls `dispatchMemoRelatedWebhook`
- `memos.memo.comment.created`: `DispatchMemoCommentCreatedWebhook` (memo_service_webhooks.go:30) — dispatches directly, not through `dispatchMemoRelatedWebhook`

The first three route through the shared helper `dispatchMemoRelatedWebhook` (memo_service_webhooks.go:48), which sets `activityType` and does the actual per-hook posting; `DispatchMemoCommentCreatedWebhook` duplicates the same posting logic inline (using `convertMemoToWebhookPayload`) rather than calling the helper.

**Where all of them converge for delivery:**

Every dispatch path ends up building a `webhook.WebhookRequestPayload` via `convertMemoToWebhookPayload` (memo_service_webhooks.go:76) and calling `webhook.PostAsync` (internal/webhook/webhook.go:184). `PostAsync` enqueues the payload onto `asyncPostQueue`, which is drained by worker goroutines that all call `Post` (internal/webhook/webhook.go:120) — the single function that actually performs the signed HTTP delivery over `safeClient`. So the true convergence point for all memo-related webhook delivery is `Post` in `internal/webhook/webhook.go`.
