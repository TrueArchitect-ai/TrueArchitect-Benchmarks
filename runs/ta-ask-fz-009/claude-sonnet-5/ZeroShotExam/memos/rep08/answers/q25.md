**Engine:** Google's CEL (Common Expression Language), via `github.com/google/cel-go`, wrapped by a custom filter engine in **`internal/filter/`** (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`).

**Where it lives / how it's wired:**
- `ListMemos` (server/router/api/v1/memo_service.go:178) takes `request.Filter` (a CEL-style boolean expression string, e.g. `creator_id == 100 || visibility in ["PUBLIC","PROTECTED"]`), validates it via `s.validateFilter`, and appends it to `store.FindMemo.Filters` (memo_service.go:211-227).
- `internal/filter.NewEngine(schema)` (`internal/filter/engine.go:24`) builds a `cel.Env` from a `Schema` (`internal/filter/schema.go`) describing the allowed fields/functions (e.g. `creator_id`, `visibility`, `content`, `tags`, `created_ts`, plus CEL `ext` helpers).
- `Engine.Compile` (`internal/filter/engine.go:48`) parses/type-checks the CEL text into a CEL AST, then `internal/filter/parser.go` walks that AST into a dialect-agnostic `Condition` tree (`internal/filter/ir.go`) wrapped in a `Program`.

**How it becomes SQL per dialect:**
- `Program.Render(opts RenderOptions)` (`internal/filter/engine.go:96`) / `Engine.CompileToStatement` (`internal/filter/engine.go:74`) walk that `Condition` IR and emit a `Statement{SQL, Args}`, branching on `RenderOptions.Dialect` (`DialectSQLite` / `DialectPostgres` / `DialectMySQL`, switched in `internal/filter/render.go:231-238`) to produce dialect-specific fragments — e.g. SQLite uses `json_each(...)`/custom `memos_unicode_lower(...)`/`?` placeholders, Postgres uses `jsonb_array_elements_text(...)`/`ILIKE`/`$N` placeholders, MySQL uses `JSON_TABLE(...)`/backtick-quoted columns/`?` placeholders (per `internal/filter/engine_test.go`).
- Each store driver calls this through `internal/filter.AppendConditions` (`internal/filter/helpers.go:9`), which loops over `find.Filters`, calls `engine.CompileToStatement` for the driver's dialect, and appends the resulting `(sql)` fragment and args — invoked from `store/db/sqlite/memo.go:61`, `store/db/postgres/memo.go:58`, and `store/db/mysql/memo.go:69` inside their respective `ListMemos` implementations.

**One-sentence mechanism:** The filter string is parsed as a CEL expression into a CEL AST by `cel-go`, compiled by `internal/filter.Engine` into a dialect-agnostic `Condition` IR (`internal/filter/ir.go`, `parser.go`), and then rendered to dialect-specific SQL/args by `Program.Render`/`render.go`, which each of `store/db/{sqlite,postgres,mysql}/memo.go` invokes via `filter.AppendConditions` with its own `DialectName`.
