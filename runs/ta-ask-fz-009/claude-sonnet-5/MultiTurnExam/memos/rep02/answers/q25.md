q25. Engine: CEL (Common Expression Language, via `github.com/google/cel-go`), living in the `internal/filter` package — parsing/environment setup in internal/filter/engine.go and internal/filter/schema.go, condition-tree IR in internal/filter/ir.go, and SQL rendering in internal/filter/render.go.

Mechanism: the `Filter` string from `ListMemosRequest` is parsed by a CEL `cel.Env` (built with memo-specific field variables such as `creator_id`, `tag`, `visibility`, etc., in internal/filter/schema.go) into a CEL AST, which `internal/filter/parser.go` converts into a dialect-agnostic `Condition` tree (internal/filter/ir.go), and `internal/filter/render.go`'s `renderer.Render` then walks that tree emitting dialect-specific SQL fragments (branching on `DialectName` — `DialectSQLite`/`DialectMySQL`/`DialectPostgres` — for things like JSON extraction, string length, and timestamp arithmetic) that get appended into the `WHERE` clause built by the store/driver layer.
