**Unused scheduling infrastructure:**

1. **`internal/scheduler` package** (a full "GitHub Actions-inspired cron job scheduler" per its doc comment at `internal/scheduler/doc.go:1`, with `scheduler.New()`, `Job`, cron-expression parsing, middleware, etc.) is never imported outside its own tests — `grep` for `internal/scheduler"` only matches `example_test.go` and `integration_test.go` inside the package itself. It is not wired into `server/server.go` or `cmd/memos/main.go` at all.

2. **`server/runner/memopayload` Runner** — this package defines a `Runner` struct with `RunOnce` (a full batch-rebuild-all-memos loop, memopayload/runner.go:14-72) intended to be scheduled, but `NewRunner`/`Run`/`RunOnce` on that struct are never called anywhere in the codebase. Only the standalone `RebuildMemoPayload` function (not the `Runner`) is used, and it's called synchronously inline from the request-handling path in `server/router/api/v1/memo_service.go:108` and `:447` (CreateMemo/UpdateMemo), not as a background job.

So the server actually starts only **one** background worker (s3presign), driven by a manual ticker; the generic `internal/scheduler` cron engine and the `memopayload.Runner` batch job exist in the codebase but are not started by the server.
