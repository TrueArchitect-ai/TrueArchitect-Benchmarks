q29. **Interceptor path: `web/src/connect.ts`** (`authInterceptor`, lines 156-178); **token kinds: access token (short-lived, held in memory/JS state via `auth-state.ts`, sent as `Authorization: Bearer <token>` header) + refresh token (long-lived, sent as an HTTP cookie via `credentials: "include"`, exchanged through `AuthService.RefreshToken`)**; **backend package: `server/auth`** (server/auth/authenticator.go, token.go, context.go, extract.go)

Details:
- `authInterceptor` (web/src/connect.ts:156) attaches the access token to each request's `Authorization` header via `setAuthorizationHeader`, and on a `Code.Unauthenticated` response transparently calls `refreshAndGetAccessToken()` (which hits `AuthService.RefreshToken` through a separate, interceptor-free `refreshTransport`, using the browser's HTTP-only refresh-token cookie via `credentials: "include"`) before retrying once.
- Backend validation of these tokens (parsing/verifying the JWT-style access token, resolving bearer credentials, refresh-token handling) lives in `server/auth` — see `authenticator.go` (`Authenticator.resolveBearer`, `AuthenticateByRefreshToken`, per q21) and `token.go`.
