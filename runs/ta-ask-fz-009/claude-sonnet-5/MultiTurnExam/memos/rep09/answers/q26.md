q26. **memo_relation, attachment, memo**

Per `Store.DeleteMemo` (store/memo.go:140-158):
1. `memo_relation` — rows deleted where the memo is either the source (`memo_id`) or target (`related_memo_id`)
2. `attachment` — each attachment linked to the memo is deleted via `Store.DeleteAttachment` (store/attachment.go:132), which also removes the underlying file storage
3. `memo` — the memo row itself is deleted last via the driver's `DeleteMemo` (e.g. store/db/sqlite/memo.go:237)

Note: `reaction` and `memo_share` rows referencing the memo are **not** explicitly cascaded by `DeleteMemo` — that broader cascade (covering `reaction`, `memo_share`, `memo_relation`, `memo`, etc.) only happens in the separate user-deletion flow (`store/db/sqlite/user_delete.go:383-462`), not in single-memo deletion.
