**Runners actually started by the server:**
- s3presign.Runner — triggered by a `time.NewTicker` set to a 12-hour interval (`runnerInterval = time.Hour * 12`, server/runner/s3presign/runner.go:27,30), started in `Server.startBackgroundRunners` (server/server.go:153-173), which also runs it once immediately via `RunOnce(ctx)` (server/server.go:163) before entering the ticker loop (`s3presignRunner.Run(s3Context)`, server/server.go:169).

**Unused scheduling infrastructure:**
- `memopayload.Runner` (server/runner/memopayload/runner.go:14) defines a `RunOnce` method that batch-rebuilds the payload of *all* memos in the store, but this `Runner` type is never constructed or started anywhere in `server/server.go` — `NewRunner`/`RunOnce` on this type have no callers outside the package itself. Only the standalone helper function `memopayload.RebuildMemoPayload` (not the `Runner`) is called synchronously, inline, from `APIV1Service.CreateMemo` and `APIV1Service.UpdateMemo` (server/router/api/v1/memo_service.go:108, 447) — i.e. it runs per-request, not as a scheduled background job. So the `memopayload.Runner`'s batch-scheduling machinery exists in the codebase but is dead/unused by the running server.
