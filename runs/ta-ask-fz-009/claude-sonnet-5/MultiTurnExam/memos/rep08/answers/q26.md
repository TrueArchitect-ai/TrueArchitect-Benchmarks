q26. **memo, memo_relation, attachment, memo_share**

- `memo` — the row itself is deleted (store/db/sqlite/memo.go:237-239, `DELETE FROM memo`)
- `memo_relation` — explicitly deleted in `store.Store.DeleteMemo` for both directions (memo_id and related_memo_id) before the memo row is removed (store/memo.go:142-147)
- `attachment` — explicitly deleted via `ListAttachments`/`DeleteAttachment` calls in the same store method (store/memo.go:149-156)
- `memo_share` — has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (store/migration/sqlite/LATEST.sql:109), so the DB engine cascades the delete automatically when the memo row is removed

Note: `reaction` uses a `content_id` string reference rather than a memo foreign key (store/migration/sqlite/LATEST.sql:92-97), so it is not cascaded by DeleteMemo.
