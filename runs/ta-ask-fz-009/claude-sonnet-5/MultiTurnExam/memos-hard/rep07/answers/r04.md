r04. Premise correction: neither — there is no message broker in this codebase. A repo-wide search would turn up no NATS or RabbitMQ client/dependency (confirmed indirectly: `internal/webhook/webhook.go` imports only `net/http`, `crypto/hmac`, standard library packages, `github.com/google/uuid`, and `github.com/pkg/errors` — no broker client).

Actual mechanism: webhook delivery workers consume from an in-process, in-memory bounded Go channel, not a broker queue. It's declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39`. Four worker goroutines are spawned in the package `init()` function (`internal/webhook/webhook.go:42-55`), each running `for payload := range asyncPostQueue { ... Post(payload) ... }`. Producers enqueue via `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send (`select` with a `default` branch that drops and logs a warning if the channel is full at 128 items) — so there's no persistence, no broker, and no cross-process queue; it's purely an in-memory buffered channel scoped to a single server process.
