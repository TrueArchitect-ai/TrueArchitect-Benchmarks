h02. **Delivery function**: `webhook.Post` — `internal/webhook/webhook.go:120` (invoked synchronously, or queued for background dispatch via `webhook.PostAsync`, `internal/webhook/webhook.go:184`, which is drained by worker goroutines calling `Post` at `internal/webhook/webhook.go:46`). It builds the HTTP request and sends it via the shared `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

**Protection mechanism**: two layers, both in `internal/webhook`:
- Dial-time guard — `safeDialContext` (`internal/webhook/webhook.go:59-77`), installed as the `Transport.DialContext` of `safeClient` (`internal/webhook/webhook.go:32-37`), resolves the hostname at connection time and rejects any resolved IP that is reserved/private via `isReservedIP` (`internal/webhook/validate.go:44-54`) — this also defeats DNS-rebinding since it checks the IP actually being dialed, not just the one seen at validation time.
- Input-validation guard — `webhook.ValidateURL` (`internal/webhook/validate.go:62-83`), called when a webhook URL is created/updated in `server/router/api/v1/user_service_webhooks.go:74,161,182`, which resolves the hostname and rejects reserved/private IPs up front (covering loopback, RFC-1918 ranges, link-local/cloud IMDS `169.254.0.0/16`, and IPv6 equivalents, per `reservedCIDRs` at `internal/webhook/validate.go:14-23`).

Both checks can be disabled via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for self-hosted deployments targeting local-network services.
