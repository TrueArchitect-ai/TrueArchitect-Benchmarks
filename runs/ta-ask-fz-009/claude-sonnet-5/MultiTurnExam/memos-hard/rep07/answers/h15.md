h15. At least six distinct enforcement sites:

- **`v1.APIV1Service.checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:39-64` — the core gate used by memo read/comment retrieval paths (invoked from `GetMemo`/`ListMemos` at `memo_service.go:356,367` and comment listing at `memo_service_comments.go:148`); rejects private memos for non-owners and unauthenticated viewers.
- **`v1.APIV1Service.checkAttachmentAccess`** — `server/router/api/v1/attachment_service.go:422-451` — enforces the parent memo's visibility (public/protected/private) before serving an attachment via the Attachment API.
- **`memo_attachment_service.go`** attachment-listing check — `server/router/api/v1/memo_attachment_service.go:214-222` — separately enforces the same private/creator rule when listing a memo's attachments.
- **`reaction_service.go`** reaction access checks — `server/router/api/v1/reaction_service.go:30-38,83` — enforce visibility before allowing reaction creation/listing on a memo.
- **`memo_mention_helpers.go`** mention/notification gating — `server/router/api/v1/memo_mention_helpers.go:62-84` — filters out private memos from mention notifications unless the target is the creator.
- **`user_service_notifications.go`** notification payload gating — `server/router/api/v1/user_service_notifications.go:309-312` — hides/redacts memo content in notification payloads for private/protected memos.
- **`v1.SSEHub` broadcast filtering** — `server/router/api/v1/sse_hub.go:136-138` — decides which connected SSE subscribers receive a live memo event based on `store.Private`/`store.Public`/`store.Protected`.
- **`server/router/rss/rss.go`** RSS feed query — `server/router/rss/rss.go:90,141` — restricts the feed to `VisibilityList: []store.Visibility{store.Public}`, so private/protected memos never appear in RSS output.
- **`server/router/fileserver/fileserver.go`** static file/attachment serving — `server/router/fileserver/fileserver.go:677,699` — enforces public+anonymous-allowed or private+owner/admin rules before streaming attachment bytes over the file server route.
