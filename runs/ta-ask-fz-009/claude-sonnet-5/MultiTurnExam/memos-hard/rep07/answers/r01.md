r01. Premise correction: there is no Redis anywhere in this codebase — a repo-wide case-insensitive search for "redis" across all 1042 files returns zero matches. The cache layer is entirely in-process.

Actual mechanism: `store.Store`'s `userCache` is an in-memory `cache.Cache` (`store/cache/cache.go:67`, backed by a `sync.Map` with a background cleanup goroutine, no external connection at all). It's constructed in `store.New` at `store/store.go:51-53` via `cache.New(cacheConfig)`, where `cacheConfig` is set inline at `store/store.go:40-45`:

```
DefaultTTL:      10 * time.Minute,
CleanupInterval: 5 * time.Minute,
MaxItems:        1000,
```

So user entries cached under `userCacheKey(userID)` (`store/user.go:88`, set at `store/user.go:98,122,132,143,167`, read at `store/user.go:150`) get a **10-minute TTL**, with a background sweep every 5 minutes evicting expired entries (`cache.go:200-215`), and the whole cache is capped at 1000 items with LRU-ish eviction of the oldest 20% when exceeded (`cache.go:253-313`). It's closed cleanly on shutdown via `Store.Close` → `s.userCache.Close()` (`store/store.go:75`), which is itself called from `Server.Shutdown` (`server/server.go:146`).
