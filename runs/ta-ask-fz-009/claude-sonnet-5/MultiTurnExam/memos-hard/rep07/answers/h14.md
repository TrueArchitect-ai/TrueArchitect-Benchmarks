h14. **Computation site**: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74-88`. It calls `markdownService.ExtractAll([]byte(memo.Content))` (backed by `markdown.service.ExtractAll`, `internal/markdown/markdown.go:356-422`), then writes the result into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers (recomputation)**:
- Memo creation — `v1.APIV1Service.CreateMemo` calls `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` at `server/router/api/v1/memo_service.go:108`, right after content-length validation and before `s.Store.CreateMemo`.
- Memo update, but only when the `content` field is in the update mask — `v1.APIV1Service.UpdateMemo` calls `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)` at `server/router/api/v1/memo_service.go:447`, inside the `path == "content"` branch of the update-mask loop (`server/router/api/v1/memo_service.go:435-451`); updates to other fields (visibility, etc.) don't recompute it.
- Bulk background rebuild — `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) batches through all memos via `Store.ListMemos`, calls `RebuildMemoPayload` on each, and persists via `Store.UpdateMemo`. Per h08, however, this `Runner` is never constructed/invoked anywhere in production code — it's dead code, so in practice only the create/update-content paths trigger recomputation.

**Extracted properties** (from `markdown.Service.ExtractAll`, `internal/markdown/markdown.go:355-422`, single AST walk over the content):
- `Tags` — all `#tag` occurrences (deduplicated, case preserved)
- `Mentions` — all `@username` mentions (lowercased, deduplicated) — extracted by `ExtractAll` but note `RebuildMemoPayload` only copies `Tags` and `Property` into the memo payload, not `Mentions`
- `Property` (`storepb.MemoPayload_Property`): `Title` (text of a leading H1 heading), `HasLink`, `HasCode` (from code blocks/spans), `HasTaskList`, `HasIncompleteTasks` (from unchecked task checkboxes)
