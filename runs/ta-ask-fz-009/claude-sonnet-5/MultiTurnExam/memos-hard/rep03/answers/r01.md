**Premise correction:** there is no Redis connection in this codebase — a case-insensitive search for "redis" across 1042 files returned zero matches. The cache layer is not backed by Redis at all.

**Actual mechanism:** the cache is a self-contained, in-process, thread-safe in-memory cache — `Cache` (`store/cache/cache.go:67`), built on a `sync.Map` with a background cleanup goroutine (`cleanupLoop`, `cache.go:200-215`). It's created via `New(config Config)` (`cache.go:76`) or `NewDefault()` (`cache.go:88`), which uses `DefaultConfig()` (`cache.go:57-64`).

**TTL for user entries:** user cache entries use the cache's default TTL, since `Store.userCache` calls the plain `Set` (not `SetWithTTL`), e.g. in `store/user.go:143,167`. `DefaultConfig()` sets `DefaultTTL: 10 * time.Minute` (`store/cache/cache.go:59`), with a `CleanupInterval` of 5 minutes (`cache.go:60`) sweeping expired entries. So user entries live for 10 minutes in-process before expiring (or until explicitly invalidated, e.g. via `deleteUserCache` in `store/user_delete.go`).
