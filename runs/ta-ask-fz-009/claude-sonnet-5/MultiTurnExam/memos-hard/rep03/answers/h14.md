**Computation site:** `RebuildMemoPayload` — `server/runner/memopayload/runner.go:74` — which calls `markdownService.ExtractAll(...)` (the `markdown.Service` implementation in `internal/markdown/markdown.go`, whose `ExtractProperties` logic at `internal/markdown/markdown.go:193-241` walks the goldmark AST). The result is written into `memo.Payload.Tags` and `memo.Payload.Property` (`runner.go:85-86`).

**Triggers (operations that cause recomputation):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, called on every new memo creation.
- `UpdateMemo`, specifically when the `content` field is part of the update mask — `server/router/api/v1/memo_service.go:447` (only recomputed if `path == "content"`, i.e. content actually changed).
- The background `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) also calls it for every memo in batches — though as established earlier, this runner is never wired into server startup, so in practice only the create/update-content code paths trigger it.

**Extracted properties** (via `ExtractAll`, backed by `ExtractedData`/`ExtractProperties`):
- `Tags` — markdown tag tokens found in content
- `Property.Title` — text of a leading H1 heading, if the first block is one
- `Property.HasLink` — whether the content contains a link
- `Property.HasCode` — whether it contains a code block/span
- `Property.HasTaskList` / `Property.HasIncompleteTasks` — presence of task-list checkboxes and any unchecked ones

All computed purely from `memo.Content`, not user-supplied, and used to populate list/preview metadata (`storepb.MemoPayload` / `MemoPayload_Property`, `internal/markdown/markdown.go:20-25,192-241`).
