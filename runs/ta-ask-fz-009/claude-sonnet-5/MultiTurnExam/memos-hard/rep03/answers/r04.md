**Premise correction:** neither — there is no message broker involved in webhook delivery. There is no NATS or RabbitMQ (or any external broker) dependency in this codebase; `list_dependencies`-worthy imports and a repo-wide search show no such client library, and no queue is "declared" against an external broker.

**Actual mechanism:** webhook delivery uses an in-process, in-memory Go channel as its queue. `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` in `internal/webhook/webhook.go:39` — a bounded buffered channel, not a broker-backed queue. Four worker goroutines are started in the package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post(payload)` (`webhook.go:120`) for every dequeued item. Producers enqueue via `PostAsync` (`webhook.go:184-196`), which does a non-blocking channel send and drops (with a logged warning) if the channel is full — there's no persistence, acknowledgement, or cross-process broker semantics at all; it's purely an in-memory worker pool within the single server process.
