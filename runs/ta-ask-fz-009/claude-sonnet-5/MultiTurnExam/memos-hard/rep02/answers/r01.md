**Premise correction:** there is no Redis anywhere in this codebase — `grep` for "redis" across all `.go` files and `go.mod` returns zero matches. The cache layer isn't backed by an external cache server at all.

**Actual mechanism:** the cache is an in-process, in-memory, thread-safe cache implemented in `store/cache/cache.go` (type `Cache`, `store/cache/cache.go:66`), with no network connection or configuration file — it's constructed directly in Go via `cache.New(cacheConfig)`.

The user cache specifically (`userCache`) is one of three such in-memory caches instantiated in `store.New` (`store/store.go:47-58`), sharing a single default config:
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
(`store/store.go:40-45`)

So the **TTL for user entries is 10 minutes**, set as the `DefaultTTL` in this hardcoded config — there's no Redis connection to configure because the cache never leaves process memory.
