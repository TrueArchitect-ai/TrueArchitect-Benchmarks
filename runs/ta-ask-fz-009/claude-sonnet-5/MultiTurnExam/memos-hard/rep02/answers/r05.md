**Premise correction:** there is no GraphQL schema in this codebase — grep for `graphql`/`gqlgen`/`schema.graphql` across all `.go` files and `go.mod` finds nothing, and no `.graphql` file exists anywhere in the repository.

**Actual API surface:** the public API is defined via Protocol Buffers and exposed through a dual gRPC/REST surface (using grpc-gateway and Connect):
- The API contract is declared in `.proto` files under `proto/api/v1/` (e.g. `memo_service.proto`, `user_service.proto`, `attachment_service.proto`, etc.), compiled into generated Go code under `proto/gen/api/v1/`.
- REST-style HTTP routes are generated by grpc-gateway into `*.pb.gw.go` files (e.g. `proto/gen/api/v1/memo_service.pb.gw.go:1745`, `user_service.pb.gw.go:2301`, `attachment_service.pb.gw.go:571`, `instance_service.pb.gw.go:525`, `idp_service.pb.gw.go:493`, `shortcut_service.pb.gw.go:529`, `ai_service.pb.gw.go:151`, `auth_service.pb.gw.go:331`), covering roughly 70+ REST endpoints under `/api/v1/...` (memos, users, attachments, shortcuts, identity providers, instance settings, auth, AI).
- Additional non-gRPC HTTP surfaces sit alongside it: SSE at `GET /api/v1/sse` (`server/router/api/v1/sse_handler.go:25`), attachment/avatar file serving (`server/router/fileserver/fileserver.go:132,168`), RSS feeds (`server/router/rss/rss.go:72,111`), frontend static endpoints (`server/router/frontend/frontend.go:128,143`), and a health check (`server/server.go:44`).

So the schema equivalent for this API is the Protobuf service definitions in `proto/api/v1/`, not a GraphQL SDL file.
