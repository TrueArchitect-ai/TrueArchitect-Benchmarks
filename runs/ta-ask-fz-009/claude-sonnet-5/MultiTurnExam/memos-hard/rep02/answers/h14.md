**Computation site:** `memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`), which calls `markdownService.ExtractAll(memo.Content)` — the actual extraction logic lives in `(*service).ExtractAll` in `internal/markdown/markdown.go:356` (a single-pass goldmark AST walk). `RebuildMemoPayload` writes the results into `memo.Payload.Tags` and `memo.Payload.Property` (`server/runner/memopayload/runner.go:85-86`).

**Triggers (recomputation):**

- `APIV1Service.UpdateMemo`, specifically the `content` field-mask path — `server/router/api/v1/memo_service.go:447`, recomputed only when the memo's `content` is actually being updated (guarded by `path == "content"` at `:436`).
- `memopayload.Runner.RunOnce`/`CheckAndPresign`... actually the batch backfill path: `server/runner/memopayload/runner.go:52`, inside `Runner.RunOnce`, which walks all memos in batches and rebuilds every one's payload — though (per earlier finding) this `Runner` is never constructed/wired into server startup, so this trigger exists in code but is not reachable at runtime.

**Extracted properties** (via `ExtractAll` → `ExtractProperties`/tag+mention extraction in one AST walk, `internal/markdown/markdown.go`):
- `Tags` — all `#tag` occurrences (`ExtractedData.Tags`)
- `Mentions` — `@mention` occurrences (`ExtractedData.Mentions`)
- `Property.Title` — text of the document's first H1 heading, if present
- `Property.HasLink` — whether any Markdown link node exists
- `Property.HasCode` — whether any code block/fenced code block/code span exists
- `Property.HasTaskList` — whether any task checkbox exists
- `Property.HasIncompleteTasks` — whether any task checkbox is unchecked

These are all derived, read-only-to-the-user fields used to power previews/list rendering (title, snippet cues, link/code/task badges), computed fresh from `memo.Content` rather than supplied directly by the client.
