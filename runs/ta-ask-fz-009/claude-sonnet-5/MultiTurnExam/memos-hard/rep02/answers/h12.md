**Determination method:**
1. `store.Driver` is an interface (`store/driver.go`) implemented separately by `mysql.DB`, `postgres.DB`, `sqlite.DB` — so `CreateMemo` has three concrete candidates, one per backend, and the question is which one is wired up for a default install.
2. The concrete driver is selected in `db.NewDBDriver` (`store/db/db.go:14-32`), which switches on `profile.Driver` — `"sqlite"` → `sqlite.NewDB`, `"mysql"` → `mysql.NewDB`, `"postgres"` → `postgres.NewDB`.
3. `profile.Driver` comes from the CLI/viper config, and its default is set explicitly in `cmd/memos/main.go`: `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the persistent flag default `rootCmd.PersistentFlags().String("driver", "sqlite", ...)` (`cmd/memos/main.go:130`). With no database flags supplied, `profile.Driver == "sqlite"`.
4. `internal/profile/profile.go:110-117` (`Profile.Validate`) further confirms sqlite is the "no DSN specified" default path: it fills in a default DSN (`memos_prod.db`/`memos_demo.db` under the data dir) specifically when `p.Driver == "sqlite" && p.DSN == ""`.
5. `store.Store.CreateMemo` (`store/memo.go:109`) is the store-layer entry point called by the API handlers, and it simply delegates to `s.driver.CreateMemo(...)`, which — given the default driver selection above — resolves at runtime to `sqlite.DB.CreateMemo`.

So for a default install (no `--driver`/`--dsn` flags), the actual SQL INSERT executes in `sqlite.DB.CreateMemo` at `store/db/sqlite/memo.go:16`, reached via the `store.Driver` interface dispatch originating from `db.NewDBDriver`'s `"sqlite"` case (`store/db/db.go:20`).
