**Premise correction:** neither NATS nor RabbitMQ is used anywhere in this codebase — grep for `nats`/`rabbitmq`/`amqp`/"message broker" across all `.go` files and `go.mod` returns zero matches. There is no external message broker at all.

**Actual mechanism:** webhook delivery is handled entirely in-process via a buffered Go channel, not a broker queue. In `internal/webhook/webhook.go:39`:
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```
This is a bounded (capacity 128) in-memory channel declared as a package-level variable. Four worker goroutines are spawned in the package `init()` (`internal/webhook/webhook.go:42-55`) that range over `asyncPostQueue`, popping payloads and calling `Post` on each. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send (`select`/`default`) and drops the payload with a warning log if the channel is full — there's no persistence, no cross-process queue, and no durability guarantee: if the process restarts, any payload still in the channel is lost.
