r01. **Premise correction:** there is no Redis in this codebase — a repo-wide search for `redis` across all 343 scanned Go files returns zero matches, so there's no Redis connection to configure.

**Actual mechanism:** the cache layer is a self-contained in-process cache, not an external store. `store.Store` holds three `*cache.Cache` instances — `instanceSettingCache`, `userCache`, `userSettingCache` (store/store.go:27-29) — each backed by `store/cache/cache.go`'s `Cache` type, which is a thread-safe in-memory `sync.Map` with TTL expiry and a background cleanup goroutine (`store/cache/cache.go:66-90, 199-215`). No network connection or config file is involved.

**TTL for user entries:** `userCache` is constructed in `store.New` (store/store.go:38-61) with `cacheConfig := cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000}` (store/store.go:40-45), so user cache entries live for **10 minutes** by default before expiring, with an expired-entry sweep running every 5 minutes and a 1000-item cap.
