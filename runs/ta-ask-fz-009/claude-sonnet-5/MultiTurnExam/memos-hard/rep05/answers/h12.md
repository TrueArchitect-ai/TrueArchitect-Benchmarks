**Determination method:**

1. `store.Memo` creation flows through `Store.CreateMemo` → `s.driver.CreateMemo(...)`, dispatched via the `store.Driver` interface (`store/driver.go`), so at compile time there are three candidate implementations: `mysql.DB.CreateMemo`, `postgres.DB.CreateMemo`, `sqlite.DB.CreateMemo`.
2. Which one actually runs is decided entirely by `profile.Driver`, set from the `driver` config value. In `cmd/memos/main.go:122`, `viper.SetDefault("driver", "sqlite")` establishes the default when no `--driver`/`MEMOS_DRIVER` flag or env var is supplied.
3. `Profile.Validate` (`internal/profile/profile.go:70-120`) confirms sqlite is the assumed default path: it special-cases `p.Driver == "sqlite" && p.DSN == ""` (line 110) to compute a default DSN (`memos_prod.db`/`memos_demo.db` under the data dir) — no such default-DSN logic exists for mysql/postgres, i.e. the profile machinery is built around sqlite being the out-of-the-box driver.
4. The factory `db.NewDBDriver` (`store/db/db.go:14-32`) switches on `profile.Driver` and picks `sqlite.NewDB(profile)` for `case "sqlite"`, wiring the store's `driver` field to a `*sqlite.DB`.
5. Therefore, with no database flags at all, `profile.Driver == "sqlite"` (the viper default), the factory selects the sqlite driver, and `store.CreateMemo` calls resolve to `sqlite.DB.CreateMemo` at `store/db/sqlite/memo.go:16`.
