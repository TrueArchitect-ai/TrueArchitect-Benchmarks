**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74-88`. It delegates the actual parsing to `markdownService.ExtractAll` (`internal/markdown/markdown.go:356`, the goldmark-based `Service` implementation), which walks the markdown AST in a single pass and populates `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers (operations that call `RebuildMemoPayload`):**
- Memo creation — `APIV1Service.CreateMemo`, `server/router/api/v1/memo_service.go:108`, run on every new memo's content before it's persisted.
- Memo content update — inside `APIV1Service.UpdateMemo`'s field-mask handling, specifically when the `content` path is present in the update mask — `server/router/api/v1/memo_service.go:447`. Payload is only rebuilt if the content itself changed, not for other field updates (visibility, pinned, etc.).
- (Also, though not wired into production startup per h08, the standalone `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:27-72` — would batch-rebuild the payload for every memo in the store if invoked.)

**Extracted properties** (per `markdown.ExtractedData`, `internal/markdown/markdown.go:20-25`, all captured in one AST walk by `Service.ExtractAll`):
- `Tags` — all `#tag` occurrences in the content (excluding tags inside links/images).
- `Property` (`storepb.MemoPayload_Property`) — derived booleans/text: `Title` (first-child H1 heading text), `HasLink`, `HasCode` (code blocks/spans), `HasTaskList`, `HasIncompleteTasks`.
- (`Mentions` is also extracted by `ExtractAll` but is not copied into `memo.Payload` by `RebuildMemoPayload` — only `Tags` and `Property` are assigned at runner.go:85-86.)
