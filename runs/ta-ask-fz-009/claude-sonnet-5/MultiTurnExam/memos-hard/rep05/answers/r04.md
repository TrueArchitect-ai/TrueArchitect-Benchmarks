Premise correction: neither. There is no NATS or RabbitMQ (or any external message broker) in this codebase — webhook delivery doesn't consume from a queueing system at all.

Actual mechanism: the "queue" is a plain in-process buffered Go channel, `asyncPostQueue`, declared in `internal/webhook/webhook.go:39` (`asyncPostQueue = make(chan *WebhookRequestPayload, 128)`). A fixed pool of 4 worker goroutines is spun up in `init()` at `internal/webhook/webhook.go:42-55`, each ranging over `asyncPostQueue` and calling `Post` for every payload it receives. Producers enqueue via `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send (`select`/`default`) and simply drops the payload with a log warning if the channel is full — there's no persistence, no broker connection, and no durable queue backing this; it's entirely in-memory and scoped to the single server process's lifetime.
