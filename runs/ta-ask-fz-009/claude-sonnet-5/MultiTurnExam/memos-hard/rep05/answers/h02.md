**Delivery function:** `webhook.Post` — `internal/webhook/webhook.go:120` (does the actual `safeClient.Do(req)` HTTP POST; called both synchronously and, via the worker pool draining `asyncPostQueue`, asynchronously from `webhook.PostAsync`, same file, lines 42-55 and 184-196).

**Protection mechanism:** the SSRF guard is enforced at dial time by `safeDialContext` — `internal/webhook/webhook.go:59` — which is installed as the `DialContext` of the shared `safeClient`'s `http.Transport` (`internal/webhook/webhook.go:32-37`). `safeDialContext` resolves the target hostname and rejects any resolved IP that `isReservedIP` (`internal/webhook/validate.go:44`) flags as loopback/RFC-1918/link-local/cloud-IMDS/IPv6-equivalent (CIDR list at `internal/webhook/validate.go:14-23`), which defeats DNS-rebinding since the check happens against the actual dial address, not just the URL string. A second, earlier check (`webhook.ValidateURL`, `internal/webhook/validate.go:62`) performs the same reserved-IP resolution check up front when a webhook URL is created/updated, but the dial-time guard in `safeDialContext` is what actually protects delivery. Both honor the `AllowPrivateIPs` escape hatch (`internal/webhook/validate.go:41`), settable via the `--allow-private-webhooks` CLI flag wired in `cmd/memos/main.go:49`.
