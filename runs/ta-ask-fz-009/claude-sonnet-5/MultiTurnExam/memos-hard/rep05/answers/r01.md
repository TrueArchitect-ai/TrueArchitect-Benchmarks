Premise correction: there is no Redis in this codebase — a repo-wide search for "redis" returns zero matches across all 1042 files searched. The cache layer isn't backed by an external store at all.

Actual mechanism: the cache is an in-process, in-memory implementation, `Cache` in `store/cache/cache.go` (a `sync.Map`-backed structure with a background cleanup goroutine, no network client, no connection config of any kind — see `store/cache/cache.go:67-90`). It's constructed directly in Go via `cache.New(cacheConfig)`, not "connected to."

For user entries specifically: `Store.userCache` is created in `store.New` at `store/store.go:52`, using the `cacheConfig` built at `store/store.go:40-45`. That config sets `DefaultTTL: 10 * time.Minute` (`store/store.go:41`), and since `userCache.Set(...)` calls (e.g. `store/user.go:167`) use the default-TTL `Set` method rather than `SetWithTTL`, user cache entries expire after **10 minutes**, with a background sweep (`CleanupInterval: 5 * time.Minute`) evicting expired items in the meantime.
