**Computation site**: `memopayload.RebuildMemoPayload(ctx, memo, markdownService)` — `server/runner/memopayload/runner.go:74`. It calls `markdownService.ExtractAll([]byte(memo.Content))` (`internal/markdown/markdown.go:356`, implementing `markdown.Service.ExtractAll`), which parses the memo's markdown content once via goldmark and populates `memo.Payload.Tags` and `memo.Payload.Property` (`server/runner/memopayload/runner.go:85-86`) — this `Payload` is the derived-metadata blob attached to the `store.Memo`, used for tag filtering, list rendering, and previews rather than being user-supplied.

**Triggers** (recomputation call sites, both in `server/router/api/v1/memo_service.go`):
- **Memo creation** — `APIV1Service.CreateMemo`, `memo_service.go:108`: `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` runs on the newly created memo's content before it's persisted.
- **Memo update, only when `content` is in the update mask** — `APIV1Service.UpdateMemo`, `memo_service.go:436-449`: when `path == "content"`, the handler replaces `memo.Content` and calls `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)` again (`memo_service.go:447`), so the payload is only recomputed when content actually changes, not on every update.

**Extracted properties** (per `internal.markdown.ExtractedData`, `internal/markdown/markdown.go:21-25`, and what `RebuildMemoPayload` copies into the memo's stored payload, `server/runner/memopayload/runner.go:74-87`):
- `Tags` — `#tag` occurrences parsed from the content (excluding tags inside links/images)
- `Property` — a `MemoPayload_Property` of boolean flags computed from content (e.g. has-link/has-code/has-task-list-style markers, per `ExtractProperties`)
- (`ExtractedData` also carries `Mentions`, but `RebuildMemoPayload`'s current implementation only assigns `Tags` and `Property` into the memo payload — `server/runner/memopayload/runner.go:85-86`.)
