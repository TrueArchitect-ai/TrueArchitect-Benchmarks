**Premise correction**: There is no Redis connection anywhere in this codebase — a search for "redis" (case-insensitive) across all 1042 files in the repo returns zero matches. The cache layer is not backed by an external cache server at all.

**Actual mechanism**: `store/cache/cache.go` implements a self-contained in-process cache (`cache.Cache`, backed by an in-memory map with a background cleanup goroutine, per `store/cache/cache.go:10-32`+). It's instantiated directly in Go via `cache.New(cacheConfig)` inside `store.New` (`store/store.go:38-53`), which creates three separate in-memory caches — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:27-29, 51-53`) — all sharing one `cache.Config`.

**TTL for user entries**: `userCache` uses the same default `cacheConfig` as the others: `DefaultTTL: 10 * time.Minute` (`store/store.go:41`), with a `CleanupInterval` of 5 minutes and a cap of `MaxItems: 1000` (`store/store.go:42-43`). No per-cache override TTL is set for `userCache`, so user entries expire after 10 minutes by default (unless written with `SetWithTTL` using a custom duration, per the `cache.Interface` contract at `store/cache/cache.go:15-16`).
