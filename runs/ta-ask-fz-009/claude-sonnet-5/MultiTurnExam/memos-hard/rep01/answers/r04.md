**Premise correction**: Neither. There is no NATS or RabbitMQ (or any external message broker) in this codebase — no client library import for either exists anywhere in the dependency tree or source.

**Actual mechanism**: The webhook delivery workers consume from a plain in-process, in-memory Go channel — `asyncPostQueue`, a `chan *WebhookRequestPayload` with a buffer of 128, declared at `internal/webhook/webhook.go:39`. Four worker goroutines are spawned in the package `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post(payload)` for every item. Producers enqueue via `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send (`select`/`default`) and drops (with a warning log) if the queue is full. There's no external broker, no persistent queue, and no durability across process restarts — it's entirely an in-process buffered channel.
