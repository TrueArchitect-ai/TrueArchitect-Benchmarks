**Concrete method: `sqlite.DB.CreateMemo` — `store/db/sqlite/memo.go:16`**

This is the code that actually builds and issues `INSERT INTO `memo` (...) VALUES (...) RETURNING ...` (`store/db/sqlite/memo.go:41-47`) when a memo is saved on a default install.

**Determination method:**

1. **Default driver value.** `cmd/memos/main.go:122` sets `viper.SetDefault("driver", "sqlite")`, and the `--driver` CLI flag also defaults to `"sqlite"` (`cmd/memos/main.go:130`). With no database flags supplied, `viper.GetString("driver")` resolves to `"sqlite"`, which is assigned into `Profile.Driver` at `cmd/memos/main.go:43`.
2. **Driver-selection factory.** `main.go:57` calls `db.NewDBDriver(instanceProfile)`, which is the switch statement in `store/db/db.go:14-32` — for `profile.Driver == "sqlite"` it calls `sqlite.NewDB(profile)` (`store/db/db.go:20`), returning a `store.Driver` backed by the `sqlite.DB` concrete type.
3. **Store wiring.** That driver is passed into `store.New(dbDriver, instanceProfile)` (`main.go:64`), so all `store.Store` calls dispatch through the `store.Driver` interface to whichever concrete implementation was selected — here, `sqlite.DB`.
4. **Call path to the INSERT.** `store.Store.CreateMemo` (in `store/memo.go`, the store-layer wrapper) forwards to `s.driver.CreateMemo(...)`, which — because the driver is `*sqlite.DB` — resolves at runtime to `sqlite.DB.CreateMemo` at `store/db/sqlite/memo.go:16`, the method that contains the literal `INSERT INTO` SQL statement.

The other two candidates, `mysql.DB.CreateMemo` and `postgres.DB.CreateMemo`, exist in the codebase but are unreachable under a default install because `NewDBDriver`'s switch only ever instantiates one driver per process, chosen by `Profile.Driver`, and that value defaults to `"sqlite"` unless overridden by a `--driver` flag or `MEMOS_DRIVER` env var/config.
