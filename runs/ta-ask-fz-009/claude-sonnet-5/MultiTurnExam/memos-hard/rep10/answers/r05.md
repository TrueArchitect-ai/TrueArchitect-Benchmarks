**Premise correction:** there is no GraphQL schema anywhere in this repository — a repo-wide search for "graphql", ".graphqls", or "gqlgen" returns zero matches across all 1042 tracked files. This is not a GraphQL API.

**Actual API surface:** the public API is defined via **Protocol Buffers** and exposed as **gRPC + Connect RPC + a gRPC-Gateway REST façade**:

- The service/message contracts are declared in `.proto` sources (compiled into `proto/gen/api/v1/*.pb.go` and `proto/gen/api/v1/apiv1connect/*.connect.go`) — e.g. `MemoService`, `UserService`, `AttachmentService`, `IdentityProviderService`, `InstanceService`, `ShortcutService`, `AIService`, `AuthService`.
- Those proto definitions are simultaneously served three ways: native gRPC, Connect-protocol (browser-friendly RPC over HTTP), and a REST/JSON mapping generated by grpc-gateway — the REST routes are declared via `google.api.http` annotations baked into the generated `*.pb.gw.go` files (e.g. `proto/gen/api/v1/memo_service.pb.gw.go:1745`, `proto/gen/api/v1/user_service.pb.gw.go:2301`, etc.), giving endpoints like `GET /api/v1/memos`, `POST /api/v1/memos`, `PATCH /api/v1/{memo.name=memos/*}`, and so on across all services.
- On top of that, a handful of plain Echo HTTP handlers serve non-RPC concerns: SSE (`v1.RegisterSSERoutes`, `server/router/api/v1/sse_handler.go:25`), file/attachment/avatar serving (`server/router/fileserver/fileserver.go:132,168`), frontend static assets/robots/sitemap (`server/router/frontend/frontend.go:128,143`), RSS feeds (`server/router/rss/rss.go:72,111`), and a health check (`server/server.go:44`).

So the "public API schema" equivalent here is the proto IDL (not checked into the excerpt above by full path, but compiled to `proto/gen/api/v1/*.pb.go`), not a GraphQL SDL file.
