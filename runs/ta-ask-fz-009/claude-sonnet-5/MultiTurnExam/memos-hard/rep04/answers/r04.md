r04. **Premise correction:** There is no NATS or RabbitMQ (or any external message broker) involved in webhook delivery — a repo-wide search found no references to either technology in this codebase, and webhook dispatch doesn't cross a network message-broker boundary at all.

**Actual mechanism:** Webhook delivery workers consume from a plain **in-process, in-memory Go channel**, not a broker queue. It's declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `webhook.Post` for each payload dequeued. Producers enqueue onto it via `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send (`select` with a `default` branch that drops and logs a warning if the queue of 128 is full — there's no persistence or redelivery). This is a bounded, best-effort, single-process fan-out queue local to the server binary, entirely unrelated to NATS/RabbitMQ or any durable broker.
