r01. **Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search for "redis" (case-insensitive) returns zero matches across all 1042 files. The cache layer isn't backed by an external store at all.

**Actual mechanism:** The cache is a self-contained in-process cache, `cache.Cache` (`store/cache/cache.go:67`), implemented as a `sync.Map` with TTL-based expiration and a background cleanup goroutine — no network connection, no configuration for host/port/auth.

User entries specifically go through `Store.userCache`, one of three `*cache.Cache` instances constructed in `Store.New` (`store/store.go:38-60`), each configured with the same hardcoded `cacheConfig`:
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
(`store/store.go:40-45`, instantiated as `userCache: cache.New(cacheConfig)` at `store/store.go:52`).

**TTL for user entries:** 10 minutes (`DefaultTTL`), used implicitly by every `s.userCache.Set(...)` call (e.g. `store/user.go:98, 122, 132, 143, 167`) since none of them pass a custom TTL — they all go through `Cache.Set`, which applies `c.config.DefaultTTL` (`store/cache/cache.go:92-95`). Expired/evicted entries are swept every 5 minutes by `cleanupLoop` (`store/cache/cache.go:200-215`), and entries are also explicitly invalidated on user deletion (`store/user_delete.go:40`).
