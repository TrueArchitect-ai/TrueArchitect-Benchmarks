h15. Memo visibility is checked independently in each of these server surfaces:

- **`server/router/api/v1/memo_service.go:55-67`** — gRPC `MemoService.GetMemo` (and related read paths): blocks non-public memos for unauthenticated/non-owner viewers.
- **`server/router/api/v1/attachment_service.go:445-455`** — `AttachmentService` memo-attachment access check.
- **`server/router/api/v1/memo_attachment_service.go:222`** — `SetMemoAttachments`/related attachment-listing check on the owning memo.
- **`server/router/api/v1/reaction_service.go:38` and `:83`** — `ReactionService` (list/upsert reactions) checks on the target memo's visibility.
- **`server/router/api/v1/memo_service_comments.go:41`** — `CreateMemoComment` checks visibility of the memo being commented on.
- **`server/router/api/v1/memo_mention_helpers.go:62,67,84`** — mention-notification dispatch logic gating on memo/related-memo visibility before notifying mentioned users.
- **`server/router/api/v1/user_service_notifications.go:309`** — notification listing/serving, gated on memo visibility.
- **`server/router/fileserver/fileserver.go:693-704`** — HTTP file-serving handler (e.g. attachment/static file download) enforcing memo visibility for non-owner/non-admin viewers.
- **`server/notification/email.go:313`** — email notification sender, gating whether a private memo's content is included/sent.

At minimum three independent enforcement layers are represented here: the gRPC/Connect API layer (`server/router/api/v1/*.go`), the raw HTTP file-serving layer (`server/router/fileserver/fileserver.go`), and the notification/email layer (`server/router/api/v1/memo_mention_helpers.go`, `server/router/api/v1/user_service_notifications.go`, `server/notification/email.go`) — each with its own independent `Visibility == store.Private` check rather than a shared central authorization function.
