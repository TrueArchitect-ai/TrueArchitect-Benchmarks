**Premise correction:** Neither. There is no NATS, RabbitMQ, or any external message broker in this codebase — no such dependency appears in the Go module, and nothing imports a broker client library.

**Actual mechanism:** Webhook delivery uses a simple in-process, in-memory Go channel as its "queue," not a broker. In `internal/webhook/webhook.go`:

- `asyncPostQueue` is declared as a buffered Go channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`).
- On package `init()` (`internal/webhook/webhook.go:42-55`), 4 worker goroutines are spawned, each looping `for payload := range asyncPostQueue { ... webhook.Post(payload) ... }`.
- Producers enqueue via `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send into `asyncPostQueue`, dropping (and logging a warning) if the channel's 128-slot buffer is full.

So "the queue" is the bounded Go channel at `internal/webhook/webhook.go:39`, consumed by the 4 goroutines started in `init()` at `internal/webhook/webhook.go:42-55`, delivering via `webhook.Post` at `internal/webhook/webhook.go:120`. There's no broker, no persistence, and no cross-process queueing involved.
