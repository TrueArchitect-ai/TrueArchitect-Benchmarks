**Premise correction:** There is no Redis connection in this codebase. The "cache layer" (`store/cache`) is a plain in-process, in-memory cache — no external Redis client, config, or connection is configured anywhere. A search for `redis` across the repo would come back empty (nothing imports a Redis client library; `list_dependencies` territory and `store/cache/cache.go` confirm this is a self-contained Go struct-based cache).

**Actual mechanism:** `store.Store` holds three `*cache.Cache` instances — `instanceSettingCache`, `userCache`, `userSettingCache` — declared in `store/store.go:27-29` and constructed in `store.New` (`store/store.go:38-53`) using a shared `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So **user cache entries get a 10-minute TTL** (`DefaultTTL`), with a background cleanup sweep every 5 minutes and a 1000-item cap, all defined at `store/store.go:40-45`. The cache implementation itself lives in `store/cache/cache.go` (`cache.Cache`, `cache.Config` types), with `Set`/`Get`/`Close` methods used by `store.Store.GetUser`/`CreateUser`/`UpdateUser`/`ListUsers` (e.g. `store/user.go:98,122,132,143,150,167`) and closed via `store/store.go:74-76`.
