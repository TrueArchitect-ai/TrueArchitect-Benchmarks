Premise correction: neither NATS nor RabbitMQ is used anywhere in this codebase. A case-insensitive search for `nats|rabbitmq|amqp` across all tracked files returns no real hits (the only incidental substring matches are inside unrelated Catalan translation strings in `web/src/locales/ca.json`, not actual broker references) — there is no message-broker dependency, client, or connection config in the repo.

Actual mechanism: webhook delivery uses an **in-process, in-memory Go channel**, not an external broker. In `internal/webhook/webhook.go`:
- `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`) — a buffered channel acting as the "queue."
- A fixed pool of 4 worker goroutines is started in the package's `init()` function (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post(payload)` (`webhook.go:46`) to perform the actual outbound HTTP delivery.
- Producers enqueue via `PostAsync(requestPayload)` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send onto `asyncPostQueue`, dropping (and logging a warning for) the payload if the channel is full rather than blocking.

So there's no broker or declared external queue at all — the "queue" is a bounded Go channel living entirely within the server process, drained by goroutines spawned at package initialization.
