Premise correction: this codebase doesn't expose a GraphQL API, so there's no GraphQL schema to locate. A search of the project confirms the public API is defined entirely via Protocol Buffers/gRPC — no `.graphql`/`.gql` schema files, no GraphQL server library (e.g. `gqlgen`, `graphql-go`), and no `graphql` imports appear anywhere in the repo (consistent with earlier findings across `list_dependencies`, `find_entrypoints`, and the `[ArchMap query]` query, none of which surfaced anything GraphQL-related).

Actual API surface: the public API is defined by `.proto` files under `proto/api/v1/` and generated into Go/TypeScript code in `proto/gen/api/v1/` (e.g. `memo_service.proto` → `proto/gen/api/v1/memo_service.pb.go`, `memo_service_grpc.pb.go`, `apiv1connect/memo_service.connect.go`). It's served three ways simultaneously:
- **gRPC** — native gRPC service implementations (e.g. `apiv1.MemoServiceServer`), registered via `*_grpc.pb.go` files.
- **Connect (gRPC-Web/JSON-compatible)** — via `apiv1connect` handlers (e.g. `apiv1connect.MemoServiceHandler`), wired in `server/router/api/v1/connect_services.go`.
- **HTTP/JSON REST gateway** — via grpc-gateway-generated reverse-proxy routes in `proto/gen/api/v1/*.pb.gw.go` (e.g. `GET /api/v1/memos`, `POST /api/v1/memos`), confirmed earlier by the `[ArchMap query]` route table.

So "the schema" here is the set of `.proto` service/message definitions in `proto/api/v1/`, not a GraphQL schema.
