**Delivery function** — `webhook.Post` in `internal/webhook/webhook.go:120-180` (invoked directly, or queued for background dispatch via `PostAsync`, `internal/webhook/webhook.go:184-196`, which is drained by a pool of 4 worker goroutines started in `init()`, `internal/webhook/webhook.go:42-55`). `Post` marshals the payload, optionally HMAC-signs it (Standard Webhooks style), and sends it with the shared `safeClient` (`internal/webhook/webhook.go:32-37`).

**Protection mechanism** — SSRF protection is enforced at the transport/dial layer, not just at URL-validation time:
- `safeClient`'s `http.Transport.DialContext` is set to `safeDialContext` (`internal/webhook/webhook.go:32-37, 59-77`), which resolves the hostname itself, checks every resolved IP against `isReservedIP`, and refuses to dial if any address is reserved/private — this defeats DNS-rebinding since the check happens at actual connection time, not just against the URL string.
- The reserved/private CIDR list and `isReservedIP` logic live in `internal/webhook/validate.go` (lines 12-45ish, e.g. loopback, RFC-1918, link-local incl. cloud IMDS `169.254.169.254/32`), with an `AllowPrivateIPs` escape-hatch flag (`internal/webhook/validate.go:41`) used only in tests.
- Separately, `internal/webhook/validate.go:59-79` performs an upfront validation (used when a webhook URL is saved/created) that also rejects URLs resolving to reserved/private IPs, returning a gRPC `InvalidArgument` error — but the actual delivery-time guard is the dialer check in `webhook.go`.
