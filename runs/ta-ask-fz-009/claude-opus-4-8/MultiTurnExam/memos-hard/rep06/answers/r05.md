**Premise correction:** There is no GraphQL API in this repository — no GraphQL schema exists to point to. A search across all 1,042 files for `graphql`, `gqlgen`, `schema.graphql`, `type Query`, and `type Mutation` returns zero matches, and a glob for any `*.graphql` file finds none. There is no GraphQL server, resolver, or schema anywhere.

**Actual API surface:** The public API is defined with **Protocol Buffers + Connect/gRPC**, with an auto-generated gRPC-gateway providing a REST/HTTP surface. The schema lives in the `.proto` files under `proto/api/v1/`:
- `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, and `common.proto`.

These compile to Go (`proto/gen/api/v1/*.pb.go`, `*_grpc.pb.go`, the Connect bindings in `proto/gen/api/v1/apiv1connect/`, and the HTTP-gateway route tables in `*.pb.gw.go`). The resulting HTTP door set is a conventional RESTful `/api/v1/...` surface — e.g. `POST /api/v1/memos`, `GET /api/v1/memos`, `GET /api/v1/{name=memos/*}`, `POST /api/v1/auth/signin`, `GET /api/v1/users`, etc. (81 endpoints total, per `[ArchMap query]`), plus a few hand-written HTTP handlers outside the proto surface: SSE (`GET /api/v1/sse`, `server/router/api/v1/sse_handler.go:25`), the file server (`server/router/fileserver/fileserver.go`), RSS feeds (`server/router/rss/rss.go`), sitemap/robots (`server/router/frontend/frontend.go`), and `GET /healthz` (`server/server.go:44`).

So the "public API" is Protobuf-defined gRPC/Connect with a generated REST gateway under `/api/v1`, defined in `proto/api/v1/*.proto` — not GraphQL.
