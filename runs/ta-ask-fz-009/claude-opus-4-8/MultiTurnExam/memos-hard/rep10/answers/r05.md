**Premise correction: There is no GraphQL schema — the public API is not GraphQL.** No `.graphql`/`.graphqls` schema files exist anywhere in the repo, and no GraphQL library (`graphql`, `gqlgen`, `graph-gophers`, etc.) is imported in any of the 343 Go files. So there is no GraphQL schema to point to.

**Actual API surface: a Protocol-Buffers-defined API exposed over both Connect/gRPC and a REST (gRPC-Gateway) HTTP surface under `/api/v1`.** The schema of record is the set of `.proto` files:

- **Schema definitions:** `proto/api/v1/*.proto` — one service per file: `auth_service.proto`, `user_service.proto`, `memo_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus shared `common.proto`. These are the authoritative API definitions (messages + RPCs + HTTP annotations).
- **Generated code:** the proto compiler emits Go into `proto/gen/api/v1/` — the gRPC service stubs (`*_grpc.pb.go`), the Connect handlers (`proto/gen/api/v1/apiv1connect/*.connect.go`), and the gRPC-Gateway REST bindings (`*.pb.gw.go`) that carry the `verb + path` route table.
- **HTTP surface:** the REST routes are all under `/api/v1/...` — e.g. `POST /api/v1/memos`, `GET /api/v1/{name=memos/*}`, `GET /api/v1/users`, `POST /api/v1/auth/signin` (see the gateway pattern vars in `proto/gen/api/v1/*.pb.gw.go`). Browser clients use the Connect handlers wired at `server/router/api/v1/v1.go:133` (with the metadata/logging/recovery/auth interceptors). Non-proto HTTP endpoints exist too — SSE (`GET /api/v1/sse`, `server/router/api/v1/sse_handler.go:25`), the file server (`/attachments/...`, `/users/:identifier/avatar`), RSS feeds, and `/healthz` — but these are plain REST/echo handlers, not GraphQL.

So the "public API" is defined by the v1 `.proto` files under `proto/api/v1/`, surfaced as REST + Connect/gRPC, with no GraphQL layer involved.
