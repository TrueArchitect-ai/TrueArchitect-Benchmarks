**Premise correction: neither — the webhook delivery workers do not consume from any message broker. There is no NATS, no RabbitMQ, and no AMQP in this codebase** (a case-insensitive search for `nats`/`rabbitmq`/`amqp`/`streadway` yields only incidental substrings inside a Catalan locale file, `web/src/locales/ca.json` — no broker dependency or client anywhere).

**Actual mechanism:** webhook delivery is entirely in-process, using a bounded Go channel as the queue — declared in `internal/webhook/webhook.go`:

- The "queue" is a buffered channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`).
- The "workers" are four goroutines started in the package `init` (`internal/webhook/webhook.go:42-55`), each ranging over that channel and calling `Post` to perform the outbound HTTP delivery.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send onto `asyncPostQueue` and drops the payload (with a warning) if the buffer of 128 is full.

So the "queue" is a single 128-slot in-memory channel local to the running process, not a durable external broker — messages are lost on restart or buffer overflow, and there is nothing to declare in a broker.
