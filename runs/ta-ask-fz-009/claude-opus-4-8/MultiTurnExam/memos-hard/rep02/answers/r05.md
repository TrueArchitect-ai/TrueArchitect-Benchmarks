**Premise correction: there is no GraphQL schema — this project exposes no GraphQL API at all.** No `.graphql`/`.gqls` files exist, and there is no GraphQL library or generated resolver code (a repo-wide case-insensitive search for `graphql`/`gqlgen`/`schema.graphql`/`resolver` turns up only unrelated things: an AI-provider "resolver" and DNS `net.DefaultResolver`, plus a couple of design-doc mentions). So there is no schema file to point to.

**Actual API surface:** the public API is a **Protobuf-defined, Connect/gRPC service** exposed over HTTP via a gRPC-Gateway. The contract is declared in `.proto` files under `proto/` and compiled to Go in `proto/gen/api/v1/`. Concretely:

- The HTTP surface is a set of RPC services under `/api/v1/...` — `MemoService`, `UserService`, `AttachmentService`, `AuthService`, `InstanceService`, `IdentityProviderService`, `ShortcutService`, `AIService` — with REST-style verb+path mappings generated into `proto/gen/api/v1/*_service.pb.gw.go` (e.g. `POST /api/v1/memos`, `GET /api/v1/{name=memos/*}`, `GET /api/v1/users`, `POST /api/v1/auth/signin`).
- These are wired at runtime in `server/router/api/v1/v1.go` (Connect interceptor + gRPC-Gateway mux sharing one `Authorizer`).
- Non-RPC HTTP endpoints round out the surface: SSE at `GET /api/v1/sse` (`server/router/api/v1/sse_handler.go:25`), the file server (`GET /attachments/:uid/:filename`, `GET /users/:identifier/avatar`, `server/router/fileserver/fileserver.go`), RSS (`server/router/rss/rss.go`), frontend/sitemap/robots (`server/router/frontend/frontend.go`), and `GET /healthz` (`server/server.go:44`).

In short: query the API through the Connect/gRPC + REST-gateway endpoints defined in protobuf (`proto/` → `proto/gen/api/v1/`), not through a GraphQL schema.
