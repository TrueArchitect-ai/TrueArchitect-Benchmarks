**Actual API surface:** The public API is a **Protobuf-defined, Connect/gRPC + gRPC-Gateway (REST) service**. The "schema" is the set of `.proto` files under `proto/api/v1/`:

- `proto/api/v1/ai_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/common.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/memo_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/user_service.proto`

These compile to Go under `proto/gen/api/v1/` (message/service stubs in `*.pb.go`, Connect handlers in `apiv1connect/*.connect.go`, and the REST gateway bindings in `*.pb.gw.go`). Requests are served as RPC (Connect/gRPC) and as JSON/REST via the gateway — e.g. `POST /api/v1/memos`, `GET /api/v1/{name=memos/*}`, `POST /api/v1/auth/signin`, `GET /api/v1/users` — 74 gateway-mapped HTTP routes across the eight services, all under the `/api/v1/…` prefix (see the `pattern_*` route tables, e.g. `proto/gen/api/v1/memo_service.pb.gw.go`, `user_service.pb.gw.go`).

Alongside the RPC/REST surface there are a few plain HTTP endpoints (not GraphQL either): SSE streaming (`GET /api/v1/sse`, `server/router/api/v1/sse_handler.go:25`), file serving (`/attachments/...`, `/users/:identifier/avatar`, `server/router/fileserver/fileserver.go`), RSS feeds (`server/router/rss/rss.go`), sitemap/robots (`server/router/frontend/frontend.go`), and `GET /healthz` (`server/server.go:44`).

So if you're looking for the API contract, it lives in the `proto/api/v1/*.proto` definitions (generated into `proto/gen/api/v1/`), not in any GraphQL schema.
