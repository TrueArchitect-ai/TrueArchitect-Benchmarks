**Premise correction:** Neither. There is no external message broker — no NATS and no RabbitMQ (nor any AMQP/broker client) anywhere in the codebase. A full-text search for `nats`, `rabbitmq`, `amqp`, `streadway`, and `message broker` across all 343 Go files returns zero matches. So there is no broker to consume from and no external queue to declare.

**Actual mechanism:** Webhook delivery uses an **in-process, in-memory Go channel** as its work queue — everything runs inside the memos server process. In `internal/webhook/webhook.go`:
- The "queue" is a buffered channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — declared at `internal/webhook/webhook.go:39` (capacity 128).
- The "workers" are 4 goroutines started in `init()` that range over that channel and call `Post` for each payload — `internal/webhook/webhook.go:42–55`.
- Producers enqueue via `PostAsync`, which does a non-blocking send onto the channel and drops the payload if the buffer is full (`internal/webhook/webhook.go:184–193`).

So it's an internal fan-out over a bounded channel, not a broker-backed queue. This is process-local: the buffer is not durable and does not survive a restart, and it isn't shared across multiple server instances.
