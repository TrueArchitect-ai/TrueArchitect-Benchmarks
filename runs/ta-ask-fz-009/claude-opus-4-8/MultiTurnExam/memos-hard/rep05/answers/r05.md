**Premise correction: there is no GraphQL schema in this project. The public API is not GraphQL at all** — a repository-wide search for `graphql`/`gqlgen` across all 343 Go files returns zero matches, and there are no `.graphql`/`.gql` schema files anywhere. So there's no GraphQL schema location to cite.

**Actual API surface:** the public API is defined as **Protocol Buffers services**, from which gRPC, Connect (Buf Connect RPC), and a REST/HTTP gateway are generated. The schema of record is the `.proto` files under `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto`

These generate the served surface: the gRPC-gateway REST routes under `/api/v1/...` (81 endpoints, e.g. `POST /api/v1/memos`, `GET /api/v1/{name=memos/*}`, `GET /api/v1/users` — see the generated `proto/gen/api/v1/*.pb.gw.go` route tables), plus Connect handlers in `proto/gen/api/v1/apiv1connect/`. Alongside the proto-driven API there are a few hand-written non-RPC HTTP routes: SSE at `GET /api/v1/sse` (server/router/api/v1/sse_handler.go:25), file/avatar serving (server/router/fileserver/fileserver.go), RSS feeds (server/router/rss/rss.go), a healthcheck `GET /healthz` (server/server.go:44), and frontend static/SEO routes.

In short: the "schema" is Protobuf (`proto/api/v1/*.proto`), and the transport is gRPC/Connect + a REST gateway — not GraphQL.
