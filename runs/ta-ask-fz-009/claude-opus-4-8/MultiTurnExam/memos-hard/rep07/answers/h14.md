**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`. It runs the memo's `Content` through the markdown service's single-pass extractor `service.ExtractAll` (`internal/markdown/markdown.go:356`) and writes the results onto `memo.Payload` (a `storepb.MemoPayload`), which is what lists/previews read. This is derived server-side, not set by the user.

**Triggers (operations that recompute the payload):**
- **Memo create** — `APIV1Service.CreateMemo` calls `RebuildMemoPayload` at `server/router/api/v1/memo_service.go:108`.
- **Memo update** — `APIV1Service.UpdateMemo` calls `RebuildMemoPayload` at `server/router/api/v1/memo_service.go:447` (recomputes when content changes).
- **Bulk backfill/rebuild** — the `memopayload.Runner.RunOnce` batch job re-derives the payload for every memo, calling `RebuildMemoPayload` at `server/runner/memopayload/runner.go:52` then persisting via `Store.UpdateMemo`.

**Extracted properties:** `RebuildMemoPayload` copies two fields off the `ExtractedData` returned by `ExtractAll` onto the payload (runner.go:85–86):
- `Payload.Tags` — the list of `#tags` found in the content (`ExtractedData.Tags`).
- `Payload.Property` — a `MemoPayload_Property` computed from the content structure, including flags derived from the first block such as whether the memo has a link, a code block, a task list, and incomplete tasks (populated by `service.ExtractProperties` / the `ExtractAll` walk, `internal/markdown/markdown.go:193`, `:356`).

(Note: `ExtractedData` also carries `Mentions`, `internal/markdown/markdown.go:23`, but `RebuildMemoPayload` does not persist mentions into the payload — only `Tags` and `Property` become the memo's stored derived metadata.)
