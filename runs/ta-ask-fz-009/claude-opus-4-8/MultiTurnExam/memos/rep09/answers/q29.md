Interceptor path: web/src/connect.ts — `authInterceptor` (line 156), which sets the `Authorization: Bearer <token>` header (line 99) and is registered on the main transport (line 188).

Token kinds it manages:
- **JWT access token** — short-lived, held in memory and attached as the Bearer header; refreshed on 401 via `refreshToken()` (`web/src/connect.ts:74, 156-172`).
- **JWT refresh token** — long-lived, carried in an HTTP-only cookie (`credentials: "include"`, line 60) and used by the separate `refreshTransport` to mint new access tokens.
- (Personal Access Tokens are also accepted by the backend as Bearer credentials, though the browser flow uses the JWT pair.)

Backend package path: server/auth — the `Authenticator` validates them: `AuthenticateByAccessTokenV2` / `ParseAccessTokenV2` for the JWT access token, `AuthenticateByRefreshToken` for the refresh cookie, and `AuthenticateByPAT` for personal access tokens (`server/auth/authenticator.go:41, 61, 102`).
