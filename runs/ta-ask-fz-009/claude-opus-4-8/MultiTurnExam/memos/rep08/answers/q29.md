Interceptor path: web/src/connect.ts (the `authInterceptor`, line 156)

Token kinds: JWT **access token** (short-lived, sent as `Authorization: Bearer <token>`), JWT **refresh token** (HttpOnly cookie, used by `refreshToken()` to mint new access tokens), and **Personal Access Tokens (PAT)** validated server-side

Backend package path: server/auth (the `Authenticator` in `server/auth/authenticator.go`, token parsing in `server/auth/token.go`)

How it works:
- The Connect `authInterceptor` (`web/src/connect.ts:156`) fetches a valid access token via `getRequestToken()` and sets `Authorization: Bearer <token>` (line 99). On a `Code.Unauthenticated` (401) response it calls `refreshAccessToken()` — which POSTs to `AuthService.RefreshToken` over a separate transport sending the refresh-token cookie (`credentials: "include"`) — then retries once; if refresh fails it redirects to sign-in.
- The refresh token lives in an HttpOnly cookie (never touched directly by JS); the access token is held in `auth-state` and is preflight-refreshed near expiry.
- Backend validation is in **`server/auth`**: `Authenticator.AuthenticateByAccessTokenV2` (access JWT), `AuthenticateByRefreshToken` (refresh JWT), and `AuthenticateByPAT` (personal access tokens), with the JWT parsing/verification in `server/auth/token.go` (`ParseAccessTokenV2`, `ParseRefreshToken`).
