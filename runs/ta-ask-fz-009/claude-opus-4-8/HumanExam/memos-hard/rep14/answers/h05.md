**Explicit Go code**, not a DB cascade. On user delete, reactions are removed by two explicit statements per dialect: `deleteReactionsByContentIDsTx` and `deleteReactionsByCreatorTx`, orchestrated in `deleteUserTargetsTx` (e.g. `store/db/sqlite/user_delete.go:96,102`; also mysql `store/db/mysql/user_delete.go:96,102,417,437`, and postgres). Evidence there is no DB rule: the `reaction` table has no foreign key on `creator_id` (only a `UNIQUE` constraint) — `store/migration/sqlite/LATEST.sql:92-99`, `mysql/LATEST.sql:91-97`, `postgres/LATEST.sql:91-97`. The only `ON DELETE CASCADE` there is on `memo_reference.memo_id`, not reactions.
