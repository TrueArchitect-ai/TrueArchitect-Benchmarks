**Computation site.** The derived metadata lives on `MemoPayload.Property` (`store.MemoPayload_Property`, `proto/gen/store/memo.pb.go:85`). It's computed by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual extraction to the markdown service's `ExtractAll` — `internal/markdown/markdown.go:356`. `RebuildMemoPayload` parses the memo's `Content` and assigns `memo.Payload.Tags` and `memo.Payload.Property` (`runner.go:85-86`); it never reads user-supplied metadata.

**Triggers (recomputation).** Three call sites invoke `RebuildMemoPayload`:
- **Create** — `CreateMemo`, `server/router/api/v1/memo_service.go:108`.
- **Update** — `UpdateMemo`, `server/router/api/v1/memo_service.go:447`, fired specifically in the `content` field branch (only when the content mask path is updated; `memo_service.go:446-451`).
- **Backfill** — the batch `Runner.RunOnce`, `server/runner/memopayload/runner.go:52`, which walks all memos in batches of 100 and rebuilds each payload (used to rebuild existing memos after logic changes).

**Extracted properties.** `ExtractAll` does a single AST walk over the parsed markdown and derives (`internal/markdown/markdown.go:383-408`):
- `Title` — text of the document's first block-level child if it's an H1 heading.
- `HasLink` — a link node is present.
- `HasCode` — any code block, fenced code block, or inline code span is present.
- `HasTaskList` — a task checkbox is present.
- `HasIncompleteTasks` — a task checkbox that is unchecked is present.

(It also collects `Tags` and `Mentions` in the same pass, though only `Tags` and `Property` are written back to the payload in `RebuildMemoPayload`.) These `Property` fields are what the API surfaces via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315`) for list/preview rendering.
