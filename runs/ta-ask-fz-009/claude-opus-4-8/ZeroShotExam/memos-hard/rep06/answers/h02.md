**Delivery function** — `internal/webhook/webhook.go`: outbound delivery executes in `webhook.Post` (`internal/webhook/webhook.go:120`), specifically at the `safeClient.Do(req)` call (`internal/webhook/webhook.go:152`). It's driven either synchronously via `Post` or asynchronously via `PostAsync`, which enqueues onto a bounded channel drained by four worker goroutines that all call `Post` (`internal/webhook/webhook.go:42-55`, `184-196`).

**Protection mechanism** — `internal/webhook/webhook.go`: the shared `safeClient` (`internal/webhook/webhook.go:32-37`) uses a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:59-77`). At dial time `safeDialContext` resolves the target hostname (`net.DefaultResolver.LookupHost`) and rejects the connection if any resolved IP satisfies `isReservedIP` — i.e., a reserved/private address. Because the check happens on the *resolved* IPs at dial time rather than on the URL string, it also defeats DNS-rebinding, per the comment at lines 29-31.

One thing to note: the SSRF guard lives entirely in the reserved-IP check inside `safeDialContext`.
