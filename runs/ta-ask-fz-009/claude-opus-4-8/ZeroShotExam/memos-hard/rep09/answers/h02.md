**Where delivery executes:** `Post` at `internal/webhook/webhook.go:120` does the actual outbound HTTP call — it marshals the payload, builds the `POST` request (optionally HMAC-SHA256 signed per Standard Webhooks), and fires it via `safeClient.Do(req)` at `webhook.go:152`. `PostAsync` (`webhook.go:184`) just enqueues onto a bounded channel; four worker goroutines started in `init()` (`webhook.go:42`) drain the queue and call `Post` for the async path.

**What protects it from internal addresses (two layers):**

1. **Dial-time guard — the enforcing layer.** The shared `safeClient` is wired with a custom transport whose `DialContext` is `safeDialContext` (`webhook.go:32`–`77`). On every connection it resolves the target host and rejects the dial if any resolved IP falls in a reserved/private range (`webhook.go:70`–`73`). Because the check happens at dial time against the *resolved* IPs, it also defeats DNS-rebinding — a hostname that passed an earlier check but re-resolves to `169.254.169.254` etc. still gets blocked. This is the protection that actually covers the delivery call.

2. **Range logic + admission check.** `isReservedIP` (`internal/webhook/validate.go:44`) tests an IP against a parsed CIDR set — IPv4/IPv6 loopback, RFC-1918 private ranges, link-local/cloud IMDS (`169.254.0.0/16`), IPv6 ULA and link-local (`validate.go:14`–`23`). `ValidateURL` (`validate.go:62`) applies the same check up front when a webhook URL is created/updated (scheme must be http/https, hostname must not resolve to a reserved IP).

One caveat worth flagging: both layers honor `AllowPrivateIPs` (`validate.go:41`, checked at `validate.go:45`). When that flag is set, `isReservedIP` returns `false` unconditionally and the SSRF protection is disabled — intended for self-hosted setups targeting local services.
