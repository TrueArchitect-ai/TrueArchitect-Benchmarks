**Premise correction:** This repository (memos, `github.com/usememos/memos`) does not expose a GraphQL API, so there is no GraphQL schema to point at. There's no `.graphql`/`.gql` schema, no resolver layer, and no GraphQL server registered in the router.

**Actual API surface:** The public API is **gRPC with a REST/HTTP gateway, defined by Protocol Buffers** — not GraphQL.

- The contract is defined in `.proto` files, and the generated gateway/server code lives under `proto/gen/api/v1/` (e.g. `memo_service.pb.gw.go`, `user_service.pb.gw.go`, `auth_service.pb.gw.go`). These are grpc-gateway–generated REST bindings.
- The surface is a set of resource-oriented REST endpoints under `/api/v1/...`, backed by services: `MemoService`, `UserService`, `AuthService`, `AttachmentService`, `InstanceService`, `IdentityProviderService`, `ShortcutService`, `AIService`. Examples:
  - `GET /api/v1/memos`, `POST /api/v1/memos`, `PATCH /api/v1/{memo.name=memos/*}` (`proto/gen/api/v1/memo_service.pb.gw.go:1745`)
  - `POST /api/v1/auth/signin`, `GET /api/v1/auth/me` (`proto/gen/api/v1/auth_service.pb.gw.go:331`)
  - `GET /api/v1/users`, `POST /api/v1/users` (`proto/gen/api/v1/user_service.pb.gw.go:2301`)
- Non-gateway HTTP routes are hand-registered handlers, also REST/plain-HTTP: SSE (`server/router/api/v1/sse_handler.go:25`), file serving (`server/router/fileserver/fileserver.go`), RSS/sitemap/robots (`server/router/rss/rss.go`, `server/router/frontend/frontend.go`), and `GET /healthz` (`server/server.go:44`).

So if you're looking for the "schema," the equivalent artifact is the Protobuf service definitions (the `.proto` sources whose output is in `proto/gen/api/v1/`), which is the authoritative contract for this REST-over-gRPC API.
