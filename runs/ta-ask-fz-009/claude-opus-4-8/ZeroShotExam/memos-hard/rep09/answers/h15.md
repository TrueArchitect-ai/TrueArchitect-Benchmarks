Memo visibility (who may *view* a memo) is enforced at these distinct server surfaces, each with its own visibility logic:

Single-memo read access (GetMemo / ListMemoComments), via `checkMemoReadAccess` — server/router/api/v1/memo_service.go:39-67
List query pre-filter (ListMemos restricts the result set by visibility) — server/router/api/v1/memo_service.go:217-226
Attachment blob serving follows the linked memo's visibility, via `checkAttachmentAccess` / `checkMemoAccess` — server/router/api/v1/attachment_service.go:422-455
Memo-attachment listing/serving re-checks memo visibility — server/router/api/v1/memo_attachment_service.go:213-225
Email notification viewer gate, via `canViewerAccessMemo` — server/notification/email.go:306-320

The first two are the primary API viewing surfaces (per-item and query-level); the two attachment paths and the notification path each re-implement the same private/protected/public rule independently rather than delegating to a single helper — so visibility is enforced in five separate places, well above the "at least three" the question expects.
