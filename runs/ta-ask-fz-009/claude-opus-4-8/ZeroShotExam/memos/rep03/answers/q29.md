**Interceptor path:** `web/src/connect.ts` — `authInterceptor` (defined at line 156). It sets `Authorization: Bearer <token>` on every request via `setAuthorizationHeader` (line 97), and on a `Code.Unauthenticated` response it triggers a one-shot refresh + retry, redirecting to login if the refresh fails. Token state (in-memory access token, expiry, stored-token check) lives alongside it in `web/src/auth-state.ts`.

**Token kinds managed:**
- **Access Token V2** — short-lived, stateless JWT held in memory (`accessToken` in `auth-state.ts`), sent as the `Bearer` credential.
- **Refresh Token** — exchanged for a new access token via `RefreshToken` (`doRefreshAccessToken`, `connect.ts:74`). On the backend it lives in a cookie, not the header (`server/auth/authenticator.go:201`, `ExtractRefreshTokenFromCookie`).
- **Personal Access Token (PAT)** — also accepted as a `Bearer` credential, distinguished by `PersonalAccessTokenPrefix` (`authenticator.go:154`).

**Backend validation package:** `server/auth` — the `Authenticator` in `server/auth/authenticator.go` validates the bearer credential. `resolveBearer` (line 149) routes: no-prefix tokens go to `AuthenticateByAccessTokenV2` → `ParseAccessTokenV2` (stateless JWT verification against the shared secret), prefixed tokens go to `AuthenticateByPAT` (DB-backed), and the refresh-token cookie falls through to `AuthenticateByRefreshToken`. Header/cookie extraction helpers are in `server/auth/extract.go`.
