**Interceptor path:** `web/src/connect.ts` — `authInterceptor` (defined at line 156, wired into the Connect transport at line 188). On each request it fetches a token, sets the `Authorization: Bearer <token>` header (`setAuthorizationHeader`, line 97–99), and on an `Unauthenticated` error refreshes the token once and retries. Token state lives in `web/src/auth-state.ts`.

**Token kinds:** three, all carried as `Bearer` credentials except the refresh token:
- **Access Token V2** — the short-lived stateless JWT the interceptor sends on every request (`web/src/auth-state.ts`, `memos_access_token`).
- **Refresh Token** — the long-lived credential used to mint new access tokens (frontend refreshes via `refreshToken({})` in `connect.ts`; backend reads it from a cookie, `server/auth/authenticator.go:199–201`).
- **Personal Access Token (PAT)** — also accepted in the `Authorization` header, distinguished by a `PersonalAccessTokenPrefix` (`authenticator.go:154`).

**Backend validation package:** `server/auth/` — `server/auth/authenticator.go`. `resolveBearer` (line 149) validates a Bearer token as either an Access Token V2 (`AuthenticateByAccessTokenV2`) or a PAT (`AuthenticateByPAT`), and `AuthenticateToUser` (line 190) falls back to the refresh-token cookie.

**Summary:** `web/src/connect.ts` (with token state in `web/src/auth-state.ts`); Access Token V2 (JWT) / Refresh Token / Personal Access Token; `server/auth/` (`server/auth/authenticator.go`).
