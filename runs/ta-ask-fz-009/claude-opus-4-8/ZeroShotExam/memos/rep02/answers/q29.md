**interceptor path:** `web/src/connect.ts` — `authInterceptor` (defined at line 156), registered on the Connect-RPC transport at line 188. It sets `Authorization: Bearer <token>` on every request (`setAuthorizationHeader`, line 97), and on a `401/Unauthenticated` response it refreshes and retries once (lines 156–184).

**token kinds:** two, managed on the frontend by `web/src/auth-state.ts`:
- **Access token** — a short-lived JWT held in memory and mirrored to `localStorage` (`memos_access_token`, `auth-state.ts:6`), sent as the `Bearer` header. Cross-tab sync via `BroadcastChannel`.
- **Refresh token** — an HTTP-only cookie, never touched by JS. The interceptor's refresh path calls the `AuthService.refreshToken` RPC over a separate transport that sends `credentials: "include"` (`connect.ts:65–83`) to swap the cookie for a new access token.

(The backend also recognizes Personal Access Tokens on the same `Bearer` header, but the frontend browser flow uses the access/refresh pair above.)

**backend package path:** `server/auth`. It validates the JWTs (HS256) — `ParseAccessTokenV2` (`server/auth/token.go:220`) and `ParseRefreshToken` (`token.go:236`), both via `jwt.ParseWithClaims` with issuer/audience checks. The request-level entry points are `Authenticator.Authenticate` and `Authenticator.AuthenticateToUser` in `server/auth/authenticator.go` (lines 190, 213), which pull the token out of the header with `ExtractBearerToken` (`server/auth/extract.go:11`) and fall back to the refresh cookie.
