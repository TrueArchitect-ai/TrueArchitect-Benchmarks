When a memo is deleted through the API, the store layer (`store/memo.go:140`, `Store.DeleteMemo`) deletes the following before the memo row itself:

- **`memo_relation` records where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
- **`memo_relation` records where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
- **Attachments linked to the memo** — each `store.Attachment` found for the memo is deleted via `DeleteAttachment` (`store/memo.go:149-157`)

Then the memo row itself is deleted via `s.driver.DeleteMemo` (`store/memo.go:158`, e.g. `store/db/mysql/memo.go:259`).

Note: comments (child memos) are handled one level up in the service, not the store — `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:567-577`) deletes comment memos by calling `Store.DeleteMemo` for each, which recursively performs the same relation/attachment cleanup.
