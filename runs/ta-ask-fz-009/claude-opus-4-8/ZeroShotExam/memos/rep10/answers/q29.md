**Interceptor path:** `web/src/connect.ts` — `authInterceptor` (defined at line 156, wired into the main Connect transport at line 188). Its helpers live in the same file; token state is held in `web/src/auth-state.ts`.

**Token kinds:**
- **Access token (JWT, "Access Token V2")** — short-lived (15 min). The interceptor reads it via `getRequestToken()`, attaches it as `Authorization: Bearer <token>` (`setAuthorizationHeader`, line 97–99), and manages it in `web/src/auth-state.ts` (in-memory `accessToken` + localStorage key `memos_access_token`).
- **Refresh token** — not held by the interceptor as a value; it rides as an httpOnly cookie (`credentials: "include"`, line 60). On a `401 Unauthenticated` the interceptor calls `refreshAccessToken()` → `AuthService.refreshToken` over a separate no-interceptor transport (lines 64–91) to mint a new access token and retries the request once.
- (Personal Access Tokens exist for programmatic access but are not managed by this frontend interceptor.)

**Backend validation package:** `server/auth` — the `Authenticator` in `server/auth/authenticator.go`. Its doc comment states it's the shared logic used by "the gRPC interceptor, Connect interceptor, and file server" (lines 17–19).
