MemoService is exposed over two protocols, both registered in `server/router/api/v1/`:

1. **Connect (ConnectRPC)** — `server/router/api/v1/connect_handler.go` (line 40: `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` inside `RegisterConnectHandlers`, which mounts the handler on the HTTP mux for browser clients — the file's comment notes it "replaces grpc-web").

2. **HTTP/JSON REST via gRPC-Gateway** — `server/router/api/v1/v1.go` (line 108: `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` on the gateway `runtime.NewServeMux`, served under `/api/v1/*` at line 128).

Both registrations wrap the same `APIV1Service` implementation — `ConnectServiceHandler` (connect_handler.go:21) embeds `*APIV1Service` so the business logic has a single source of truth. Note there is no native gRPC server registration: the generated `RegisterMemoServiceServer` in `proto/gen/api/v1/memo_service_grpc.pb.go:439` has no call site in the server code.
