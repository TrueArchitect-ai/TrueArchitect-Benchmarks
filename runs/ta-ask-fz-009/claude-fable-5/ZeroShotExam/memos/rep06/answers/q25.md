**Engine:** CEL (Common Expression Language), via `github.com/google/cel-go` (go.mod:13). The in-house engine wrapping it lives in `internal/filter/` (engine.go, parser.go, ir.go, render.go, schema.go).

**Mechanism:** `ListMemos` passes the filter string through `validateFilter` into `memoFind.Filters` (server/router/api/v1/memo_service.go:211–215); each store driver then compiles it — e.g. `filter.DefaultEngine()` + `filter.AppendConditions(..., filter.DialectMySQL/DialectPostgres, ...)` in store/db/mysql/memo.go:65–69 and store/db/postgres/memo.go:54–58 — where `Engine.Compile` (internal/filter/engine.go:48) uses `cel.Env.Compile` on the CEL expression, converts the CEL AST into a dialect-agnostic condition tree via `buildCondition` (parser.go / ir.go), and the `renderer` (internal/filter/render.go) walks that tree emitting dialect-specific SQL WHERE fragments plus bind args, branching per `DialectName` for SQLite/MySQL/Postgres differences (e.g. `strftime` vs `EXTRACT(... FROM to_timestamp(...))` vs MySQL date functions at render.go:222–244, and different JSON accessors/placeholder styles).
