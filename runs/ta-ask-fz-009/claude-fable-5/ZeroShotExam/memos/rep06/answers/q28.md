**s3presign runner** (`server/runner/s3presign/runner.go`) — the only background runner the server starts. `Server.startBackgroundRunners` (server/server.go:153-174) creates it, runs it once immediately at startup (`RunOnce`, server/server.go:163), then launches `Run` in a goroutine. Scheduling is a plain `time.NewTicker` with a hard-coded 12-hour interval (`runnerInterval = time.Hour * 12`, server/runner/s3presign/runner.go:27-30), cancelled via a per-runner context and tracked with a WaitGroup for shutdown (server/server.go:176-199).

That's it — no other runner is started:

- **memopayload runner** (`server/runner/memopayload/runner.go`) defines a `Runner` with `RunOnce`, but `NewRunner`/`RunOnce` have zero callers (certified zero from the code graph). Only its stateless helper `RebuildMemoPayload` is used, invoked synchronously inside request handling (`server/router/api/v1/memo_service.go:108, 447`) — it is not a scheduled background worker.

**Unused scheduling infrastructure:** the codebase contains a full cron-style scheduler package, `internal/scheduler/` (cron-expression parser, job registration, timezone/middleware options — `internal/scheduler/scheduler.go`, `parser.go`, `job.go`). It is referenced only by its own tests (`internal/scheduler/example_test.go`, `integration_test.go`); the server never imports or starts it. The actual background scheduling bypasses it entirely in favor of the raw ticker.
