The server starts exactly **one** background runner. `Server.Start` (server/server.go:101) calls `startBackgroundRunners` (server/server.go:153), which:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — runs `RunOnce` immediately at startup, then loops via `Run()`, driven by a `time.NewTicker(runnerInterval)` with `runnerInterval = 12 hours` (runner.go:27–41). It re-signs S3 presigned URLs (`CheckAndPresign`, runner.go:47). Shutdown is via per-runner `context.CancelFunc` + `sync.WaitGroup` (server.go:156–199).

**Not started by the server:**

- **memopayload runner** (`server/runner/memopayload/runner.go`) — a `Runner` struct with `NewRunner`/`RunOnce` exists, but `NewRunner` has zero callers (graph-certified zero). Only its package-level helper `RebuildMemoPayload` is used, synchronously inside the memo API service (server/router/api/v1/memo_service.go:108, 447). It is never scheduled as a background worker.

**Unused scheduling infrastructure:**

- **`internal/scheduler/`** — a full cron-style scheduler (`Scheduler`, `Job`, cron-expression parser in `internal/scheduler/scheduler.go`, `parser.go`, plus middleware: `Logging`, `Recovery`, `Timeout` in `middleware.go`) is present but **not used by the server at all**. `scheduler.New` and `Scheduler.Start` have zero callers outside the package's own tests (`internal/scheduler/example_test.go`, `integration_test.go`) — both certified zeros in the code graph. The only actual scheduling mechanism in production is the plain `time.Ticker` in the s3presign runner.
