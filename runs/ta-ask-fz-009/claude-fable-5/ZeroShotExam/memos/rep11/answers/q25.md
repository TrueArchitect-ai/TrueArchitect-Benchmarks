**Engine:** Google CEL (Common Expression Language) via `github.com/google/cel-go`, wrapped in the project's own filter package at **`internal/filter/`** (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`, `helpers.go`).

**Mechanism (one sentence):** The RPC handler (`server/router/api/v1/memo_service.go:178`) passes the filter strings down to the store, where each dialect driver (`store/db/sqlite/memo.go:57`, `store/db/mysql/memo.go:65`, `store/db/postgres/memo.go:54`) calls `filter.DefaultEngine()` and `filter.AppendConditions(...)` with its `DialectName`; the engine compiles the CEL expression against a typed schema of memo variables (`content`, `tag`, `pinned`, etc. in `internal/filter/schema.go`), converts the CEL AST into a dialect-agnostic condition tree (`buildCondition` in `internal/filter/parser.go`, IR in `ir.go`), and a per-dialect renderer (`internal/filter/render.go`) turns that tree into a parameterized SQL WHERE fragment + args (`Statement`), which the driver appends to its query (`internal/filter/engine.go:48–99`).
