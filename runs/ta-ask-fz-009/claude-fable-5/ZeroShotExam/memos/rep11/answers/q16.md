The store layer's `Store.DeleteMemo` (store/memo.go:140-159), invoked from the API handler `APIV1Service.DeleteMemo` (server/router/api/v1/memo_service.go:518), deletes these record kinds before calling `s.driver.DeleteMemo` for the memo row itself:

- **Memo relation records (`memo_relation`)** — deleted twice, covering rows where the memo is the source (`MemoID`, store/memo.go:142) and rows where it is the target (`RelatedMemoID`, store/memo.go:145)
- **Attachment records** — all attachments linked to the memo are listed and deleted one by one (store/memo.go:149-157)

Only after those cleanups does it delete the memo row via the driver (store/memo.go:158, e.g. `DELETE FROM memo` in store/db/sqlite/memo.go:237-248).

(Note: comment memos are also deleted, but that happens in the API layer at server/router/api/v1/memo_service.go:567-577, each going through the same store-layer cleanup — not inside `Store.DeleteMemo` itself.)
