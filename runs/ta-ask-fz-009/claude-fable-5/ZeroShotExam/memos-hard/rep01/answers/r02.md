**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** A repo-wide search for `rate limit` / `limiter` / `throttle` turns up no such middleware anywhere.

What actually exists:

- **Middleware/interceptors that ARE registered** on the API path: a CORS middleware (`server/cors.go:13`, `newCORSMiddleware`), plus Connect RPC interceptors for metadata conversion and logging (`server/router/api/v1/connect_interceptors.go` — `MetadataInterceptor`, `LoggingInterceptor`) and auth/ACL enforcement (`server/router/api/v1/authz.go`, `server/router/api/v1/acl_config.go`). None of these implement rate limiting.
- **The only mentions of rate limiting** in the repo are documentation *suggestions*, not implementations: `internal/email/README.md:286-295` shows an example of how a caller *could* wrap email sending with `golang.org/x/time/rate` ("Implement Rate Limiting"), and `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a security consideration. Even these are about email sending, not per-user API requests.
- `golang.org/x/time v0.15.0` appears in `go.mod:151` only as an **indirect** dependency — no first-party code imports its `rate` package.

So there is no registration point and no request limits to report, because the middleware the question presupposes doesn't exist.
