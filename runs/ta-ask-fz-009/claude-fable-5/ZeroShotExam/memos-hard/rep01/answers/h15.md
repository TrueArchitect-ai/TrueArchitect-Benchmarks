Memo visibility is enforced independently in each server surface that can leak a memo — the gRPC API, the raw file server, the SSE event stream, and the public sitemap:

- gRPC API read access (`checkMemoReadAccess`, gates GetMemo etc.; private ⇒ creator only, non-public ⇒ auth required) — server/router/api/v1/memo_service.go:39–68 (plus list-side filtering via `VisibilityList` at lines 219–225)
- gRPC attachment access (`checkAttachmentAccess`, linked attachments follow the memo's visibility) — server/router/api/v1/attachment_service.go:422–455 (same rule repeated for memo-attachment listing in server/router/api/v1/memo_attachment_service.go:214–222)
- Raw file/attachment serving over HTTP (public + anonymous allowed, share-token fallback, private ⇒ creator or admin only) — server/router/fileserver/fileserver.go:677–701
- SSE real-time event fan-out (`SSEClient.canReceive`: private events delivered only to creator or admin) — server/router/api/v1/sse_hub.go:134–144
- Public sitemap generation (only `store.Public` memos are listed) — server/router/frontend/frontend.go:149–151

Related but secondary sites that also consult visibility: reaction endpoints (server/router/api/v1/reaction_service.go:30, 83), comment creation (server/router/api/v1/memo_service_comments.go:41), mention-notification suppression (server/router/api/v1/memo_mention_helpers.go:62–84), user stats filtering (server/router/api/v1/user_service_stats.go:84–90, 218–220), and email content redaction (server/notification/email.go:313–316).
