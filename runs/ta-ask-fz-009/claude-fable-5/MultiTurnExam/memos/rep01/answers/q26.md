**Tables affected: `memo`, `memo_relation`, `attachment`**

- **memo_relation** — `Store.DeleteMemo` (`store/memo.go:140-147`) explicitly deletes relation rows where the memo is either source (`MemoID`) or target (`RelatedMemoID`).
- **attachment** — same function lists and deletes each attachment linked to the memo (`store/memo.go:148-157`), each delete hitting the `attachment` table (e.g. `store/db/sqlite/attachment.go:212`) plus its blob storage.
- **memo** — finally the driver deletes the memo row itself (`store/db/sqlite/memo.go:237-239`).

Additionally, the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:567-577`) first deletes all *comment* memos (relations of type `COMMENT`), each via the same `Store.DeleteMemo` cascade — so those hits touch the same three tables again.

Note: `reaction` rows are listed only to build the webhook payload (`memo_service.go:545`), not deleted; no explicit cascade for `reaction` or `memo_share` appears in this path.
