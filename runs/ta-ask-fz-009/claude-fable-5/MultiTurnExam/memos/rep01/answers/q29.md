**Interceptor:** `web/src/connect.ts` — the auth interceptor attaches `Authorization: Bearer <token>` to every request (`setAuthorizationHeader`, line 97-100), proactively refreshes when the token is near expiry, and on 401 does a deduplicated refresh-and-retry via `tokenRefreshManager` (lines 30–91), using a separate interceptor-free `refreshTransport` (lines 65–72) to avoid recursion; token state lives in `web/src/auth-state.ts`.

**Token kinds:** short-lived **access tokens** (bearer, held in frontend memory via `auth-state`) and a **refresh token** carried as an HTTP cookie (`credentials: "include"`, line 57-62) used against the `RefreshToken` RPC for rotation. The backend additionally accepts **personal access tokens** on the same bearer path.

**Backend package:** `server/auth` — `server/auth/authenticator.go` validates them: `AuthenticateByAccessTokenV2` (line 41), `AuthenticateByRefreshToken` (line 61), `AuthenticateByPAT` (line 102), unified through `resolveBearer`/`Authenticate` (lines 149, 213).
