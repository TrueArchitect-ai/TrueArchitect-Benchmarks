**Interceptor:** `web/src/connect.ts` — `authInterceptor` (lines 156–178), attached to the shared Connect transport (line 188). It injects `Authorization: Bearer <token>` on every request, does preflight refresh of near-expiry tokens (`getRequestToken`, lines 124–150), and on a 401 refreshes once and retries (guarded by an `X-Retry` header), redirecting to sign-in on failure. Token state helpers live in `web/src/auth-state.ts`.

**Token kinds:**
- **Access token** (short-lived bearer JWT, held in memory / auth-state, sent as `Authorization: Bearer`)
- **Refresh token** (cookie-based — the refresh transport sends `credentials: "include"` with no auth interceptor, lines 57–72, calling `AuthService.RefreshToken`)
- The backend additionally accepts **personal access tokens (PATs)** on the same bearer path, though the web interceptor itself only manages access+refresh tokens.

**Backend package:** `server/auth` — `Authenticator` in `server/auth/authenticator.go` validates them: `AuthenticateByAccessTokenV2` (line 41), `AuthenticateByRefreshToken` (line 61), `AuthenticateByPAT` (line 102), with `resolveBearer`/`Authenticate` dispatching between token kinds.
