**Engine:** CEL (Common Expression Language, via `github.com/google/cel-go`) — the engine lives in **`internal/filter/`** (`engine.go` builds the `cel.Env` from a schema of memo variables like `content`, `tag`, `pinned` defined in `schema.go:232+`; expression parsing in `parser.go`).

**Mechanism:** the filter string is parsed by CEL into an AST, compiled into a dialect-agnostic condition tree (an internal IR, `internal/filter/ir.go` — "Engine parses CEL filters into a dialect-agnostic condition tree", `internal/filter/engine.go:13`), which is then rendered to dialect-specific SQL WHERE clauses by `internal/filter/render.go`, switching on `DialectName` (`DialectSQLite`/`DialectPostgres`/`DialectMySQL`, e.g. lines 231–240, 365–402) to emit the right placeholders, JSON accessors (e.g. `buildPostgresJSONAccessor`, `render.go:970`), and string functions per backend.
