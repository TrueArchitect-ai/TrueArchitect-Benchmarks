**Interceptor: web/src/connect.ts** — `authInterceptor` (line 156), attached to the shared Connect transport (line 188). It attaches `Authorization: Bearer <token>` to every request, does preflight refresh of near-expired tokens (`getRequestToken`, line 124), and on a 401 refreshes once and retries (dedup'd via `tokenRefreshManager`; refresh uses a separate interceptor-free transport, lines 65-72, to avoid recursion).

**Token kinds:**
- **Access token** — short-lived bearer JWT, held in memory (`web/src/auth-state.ts`), sent in the `Authorization` header
- **Refresh token** — cookie-based (requests use `credentials: "include"`, line 57-62), exchanged via `AuthService.RefreshToken` for new access tokens
- The backend additionally validates **personal access tokens (PATs)** on the same bearer path (`AuthenticateByPAT`)

**Backend package: server/auth** — `Authenticator` in `server/auth/authenticator.go` validates them: `AuthenticateByAccessTokenV2` (line 41), `AuthenticateByRefreshToken` (line 61), `AuthenticateByPAT` (line 102), unified through `resolveBearer`/`Authenticate` (lines 149, 213).
