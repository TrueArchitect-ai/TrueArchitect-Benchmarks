**Interceptor: web/src/connect.ts; tokens: short-lived access token (Bearer, in-memory via `web/src/auth-state.ts`) + refresh token (HTTP-only cookie) + backend also accepts personal access tokens; backend package: server/auth**

- The auth interceptor lives in `web/src/connect.ts`: it sets `Authorization: Bearer <accessToken>` on every request (`setAuthorizationHeader`, line 97), and on a `Code.Unauthenticated` response it refreshes once and retries (`shouldHandleUnauthenticatedRetry`, line 102).
- Token management: the **access token** (with expiry) is held via `getAccessToken`/`setAccessToken` from `web/src/auth-state.ts`; the **refresh token** rides as a cookie — refresh calls go through a separate interceptor-free transport with `credentials: "include"` (`refreshTransport`/`refreshAuthClient`, lines 65-72), deduplicated by `tokenRefreshManager` to survive server-side token rotation.
- Backend validation: package **server/auth** (`server/auth/authenticator.go`) — `Authenticator` validates access tokens (`AuthenticateByAccessTokenV2`, line 41, JWT with a server secret), refresh tokens (`AuthenticateByRefreshToken`, line 61), and personal access tokens (`AuthenticateByPAT`, line 102), unified in `Authenticate`/`AuthenticateToUser` (lines 190-213).
