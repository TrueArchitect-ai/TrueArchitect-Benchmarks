**Premise correction:** This project does not have a GraphQL schema for its public API. Instead, it uses **gRPC with a gRPC-Gateway** (HTTP/REST bridge).

**Actual API surface:**

The public API is defined using **Protocol Buffers (protobuf)** service definitions located in:
- **`proto/api/v1/`** — contains the service definitions:
  - `proto/api/v1/memo_service.proto` — Memo operations (create, read, update, delete, comments, reactions, shares)
  - `proto/api/v1/user_service.proto` — User management and settings
  - `proto/api/v1/auth_service.proto` — Authentication (sign in, sign out, refresh token)
  - `proto/api/v1/attachment_service.proto` — File attachments
  - `proto/api/v1/instance_service.proto` — Instance settings and statistics
  - `proto/api/v1/idp_service.proto` — Identity provider configuration
  - `proto/api/v1/shortcut_service.proto` — User shortcuts
  - `proto/api/v1/ai_service.proto` — AI features (transcription)
  - `proto/api/v1/common.proto` — Shared type definitions

These `.proto` files define gRPC services that are transpiled via **gRPC-Gateway** (using `google/api/annotations.proto`) into HTTP REST endpoints exposed at `/api/v1/`. The generated Go code lives in `proto/gen/api/v1/` (e.g., `proto/gen/api/v1/memo_service.pb.gw.go`).

The frontend (web/) uses **TanStack React Query** for HTTP client communication, not GraphQL.
