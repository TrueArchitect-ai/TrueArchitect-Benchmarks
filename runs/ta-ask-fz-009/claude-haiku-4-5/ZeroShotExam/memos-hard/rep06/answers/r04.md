**Premise correction:** The premise assumes webhook delivery workers consume from an external message broker, but they don't.

**Actual mechanism:** Webhook delivery uses an in-process buffered Go channel. The queue is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

When webhooks are triggered (via `webhook.PostAsync()` called from `server/router/api/v1/memo_service_webhooks.go`), payloads are enqueued to this channel. Four worker goroutines are spawned at package init time (`internal/webhook/webhook.go:42–55`) that consume from this queue and dispatch the HTTP POST requests. If the queue reaches capacity (128 items), new dispatches are dropped with a warning logged.
