**Premise correction:** This is not a GraphQL API. The project uses Protocol Buffers (protobuf) with gRPC-Gateway to define its public API, not GraphQL.

**Actual API surface location:**

The public API schema is defined as **Protocol Buffer (.proto) files** in the `proto/api/v1/` directory:

- `proto/api/v1/ai_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/common.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/memo_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/user_service.proto`

These protobuf definitions define both the **gRPC service interfaces** and the **HTTP/REST API endpoints** (via `google.api.http` annotations). The build process (configured in `proto/buf.gen.yaml` via [buf](https://buf.build/)) generates:

1. Go code (in `proto/gen/api/v1/`)
2. gRPC-Gateway handlers for HTTP/REST routing
3. OpenAPI/Swagger schema (generated at `proto/gen/openapi.yaml`)
4. TypeScript types for the frontend (in `web/src/types/proto/`)

The HTTP API endpoints follow REST conventions (e.g., `POST /api/v1/memos`, `GET /api/v1/memos/{id}`) derived from the protobuf service definitions.
