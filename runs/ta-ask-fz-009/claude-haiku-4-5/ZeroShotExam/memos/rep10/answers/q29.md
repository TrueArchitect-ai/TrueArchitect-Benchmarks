**Interceptor Path:** `web/src/connect.ts` (lines 156–178, the `authInterceptor` const)

**Token Kinds:** 
- Access Token V2 (short-lived JWT, 15 minutes)
- Personal Access Token / PAT (long-lived programmatic tokens)
- Refresh Token (stored in httpOnly cookie, 30 days)

**Backend Package Path:** `server/auth`

### How it works:

The frontend auth interceptor in `web/src/connect.ts` intercepts all API requests and:
1. Extracts the access token from `auth-state.ts` (via `getRequestToken()`)
2. Sets the `Authorization: Bearer {token}` header
3. On 401 Unauthenticated errors, calls refresh via `AuthService.refreshToken()` and retries

The backend `server/auth` package validates these tokens:
- **Access Token V2:** Validated stateless via `Authenticator.AuthenticateByAccessTokenV2()` — extracted by `ExtractBearerToken()` and parsed with the shared secret
- **PAT:** Validated via `Authenticator.AuthenticateByPAT()` — checked against database for revocation and expiry
- **Refresh Token:** Validated via `Authenticator.AuthenticateByRefreshToken()` — checked in database for revocation, expiry, and user status

The `Authenticator.Authenticate()` method (line 213 of `server/auth/authenticator.go`) is the entry point that resolves a Bearer token to an authenticated user or claims.
