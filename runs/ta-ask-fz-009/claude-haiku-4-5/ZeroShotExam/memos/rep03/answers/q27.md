The mechanism is **Go's `embed` directive** combined with **Echo's `StaticWithConfig` middleware** and an **SPA fallback middleware**.

Here's how it works:

1. **Embedding** (line 20 of `server/router/frontend/frontend.go`): The compiled React frontend is embedded into the Go binary at build time:
   ```go
   //go:embed dist/*
   var embeddedFiles embed.FS
   ```

2. **Serving** (lines 41–61 of `server/router/frontend/frontend.go`): The `FrontendService.Serve()` method:
   - Extracts the filesystem from the embedded dist folder
   - Uses Echo's `StaticWithConfig` middleware to serve static assets, skipping API and file routes
   - Registers an SPA fallback middleware (lines 63–79) that serves `index.html` for client-side routing (routes without file extensions fallback to `index.html`)
   - Sets cache headers appropriately (HTML: no-cache; versioned assets in `/assets/`: immutable)

3. **Wiring** (line 72 of `server/server.go`): In the main server initialization, the frontend is registered first before API routes:
   ```go
   frontend.NewFrontendService(profile, store).Serve(ctx, echoServer)
   ```

The compiled React output (from Vite build) is placed in `web/` directory and embedded into `server/router/frontend/dist/` at build time, then served as part of the single Go binary with no external file dependencies.
