**Interceptor path:** `web/src/connect.ts` (lines 156–178)

**Token kinds managed:**
- **Access Token (Bearer)** — short-lived JWT (15 minutes), sent in Authorization header as `Bearer <token>`
- **Refresh Token** — long-lived JWT (30 days), stored in HTTP-only cookie, used to obtain new access tokens when access token expires

**Backend package path:** `server/auth`

The frontend's `authInterceptor` (defined at line 156 in `web/src/connect.ts`) intercepts all Connect RPC requests. It calls `getRequestToken()` to obtain a valid access token from `web/src/auth-state.ts`, attaches it to the Authorization header as a Bearer token, and on 401 response, automatically refreshes the token and retries. The refresh token lives in a secure HTTP-only cookie and is exchanged for a new access token via `AuthService.refreshToken()`.

On the backend, the `server/auth` package's `Authenticator` type validates both token types:
- **Access Token V2**: Stateless JWT validation via `AuthenticateByAccessTokenV2()` — checks signature and claims only
- **Personal Access Token (PAT)**: Database-backed validation via `AuthenticateByPAT()` — checks hash, expiry, and revocation status

The `Authorizer` type in `server/router/api/v1/authz.go` wraps the `Authenticator` and sits in the Connect interceptor (line 222 in `server/router/api/v1/connect_interceptors.go`), calling `Authenticate()` to resolve credentials and `CheckAccess()` to enforce method-level policy.
