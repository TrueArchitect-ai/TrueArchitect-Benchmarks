Frontend API requests are authenticated via:

1. **Interceptor location**: `web/src/connect.ts` — the `authInterceptor` (line 156) is applied to the Connect transport (line 188)

2. **Token types managed**:
   - **Access tokens** — Short-lived JWT tokens (15 minutes) sent as `Authorization: Bearer <token>` headers
   - **Refresh tokens** — Long-lived tokens stored in cookies (with `credentials: "include"`) and managed via `BroadcastChannel` for cross-tab synchronization

3. **Backend validation package**: `server/auth` — the `Authenticator` struct (server/auth/authenticator.go) validates tokens via:
   - `AuthenticateByAccessTokenV2()` for JWT access tokens (stateless, no database query)
   - `AuthenticateByRefreshToken()` for refresh tokens (checks database for revocation)

The frontend stores the access token in `localStorage` with expiry tracking, and the interceptor handles preflight refresh (via `REQUEST_TOKEN_EXPIRY_BUFFER_MS`), reactive refresh on 401 errors, and concurrent request deduplication through the token refresh manager.
