CEL (Common Expression Language) — internal/filter/engine.go; The filter engine parses CEL expressions into a dialect-agnostic condition tree (IR), then renders that tree to dialect-specific SQL via `AppendConditions`, which each database driver calls with its dialect parameter to generate correctly-formatted WHERE clauses with placeholder styles (?, $n) for MySQL, PostgreSQL, and SQLite respectively.

The architecture works as follows:

1. **Engine + Path**: CEL (Common Expression Language) engine implemented in `internal/filter/engine.go`

2. **Mechanism**: Three-phase pipeline:
   - **Parsing** (parser.go): CEL expressions parsed with `cel-go` library and validated against memo schema
   - **Normalization** (ir.go): Raw CEL AST converted to dialect-agnostic intermediate representation (IR)
   - **Rendering** (render.go): IR rendered to dialect-specific SQL with appropriate placeholder styles (?, $n for Postgres) and handling of JSON fields in `memo.payload`

3. **Integration**: Each dialect driver (store/db/mysql/memo.go, store/db/postgres/memo.go, store/db/sqlite/memo.go) calls `filter.AppendConditions()` (internal/filter/helpers.go) with its DialectName parameter, which compiles filters and appends the resulting SQL fragments and arguments to the WHERE clause with correct placeholder offsets.
