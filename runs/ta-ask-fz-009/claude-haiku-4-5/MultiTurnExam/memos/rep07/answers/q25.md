CEL (Common Expression Language) — internal/filter/engine.go; filters are parsed by the CEL engine into a dialect-agnostic intermediate representation (IR), then rendered to SQL fragments and placeholder arguments by the renderer which handles dialect-specific syntax (JSON access patterns, placeholder formats, boolean semantics) for each database (SQLite, MySQL, PostgreSQL).

**Explanation:**

1. **Engine**: **CEL (Common Expression Language)** using the `cel-go` library, implemented in `internal/filter/engine.go`. The Engine parses CEL expressions and stores the schema configuration.

2. **How filters become SQL for each dialect**: The three-phase pipeline (documented in `internal/filter/README.md`):
   - **Parsing** (`parser.go`): CEL expressions validated against the memo schema
   - **Normalization** (`ir.go`): Converted to a dialect-agnostic intermediate representation (condition tree)
   - **Rendering** (`render.go`): The `renderer` walks the IR and produces SQL fragments tailored to the target dialect, handling dialect-specific differences:
     - **SQLite**: `?` placeholders, `JSON_EXTRACT()`, `LIKE` for tags
     - **MySQL**: `$n` placeholders, `JSON_CONTAINS()`, `JSON_TABLE()`
     - **PostgreSQL**: `$n` placeholders, `->` and `->>` operators, `@>` for JSON arrays, `REGEXP` operator

3. **Integration point**: `AppendConditions()` in `internal/filter/helpers.go` compiles filters and appends SQL fragments to WHERE clauses in each database driver (`store/db/sqlite/memo.go:61`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`).
