q29. web/src/connect.ts; Access Token V2 (JWT) and Personal Access Tokens (PAT); server/auth

Frontend API request authentication is handled by:

1. **Interceptor location**: `web/src/connect.ts` (lines 156-178) defines the `authInterceptor` which:
   - Gets the current access token via `getRequestToken()`
   - Sets the `Authorization: Bearer <token>` header on requests
   - Handles 401 responses by triggering a token refresh via `refreshAccessToken()`
   - Manages token storage via `web/src/auth-state.ts`

2. **Token kinds managed**:
   - **Access Token V2** (JWT): Short-lived tokens (~15 minutes) for API access
   - **Personal Access Tokens (PAT)**: Long-lived tokens for programmatic access
   - **Refresh tokens**: Stored in cookies for refreshing expired access tokens

3. **Backend validation package**: `server/auth/` package (files: `authenticator.go`, `token.go`, `extract.go`) which provides:
   - `Authenticator.AuthenticateByAccessTokenV2()` — validates JWT access tokens
   - `Authenticator.AuthenticateByPAT()` — validates Personal Access Tokens
   - `Authenticator.resolveBearer()` — handles Bearer token extraction and validation
   - `Authenticator.Authenticate()` — the main entry point for Connect/gRPC-Gateway requests
