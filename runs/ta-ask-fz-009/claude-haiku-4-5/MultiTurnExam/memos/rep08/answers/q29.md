Frontend API requests are authenticated through:

**Interceptor location**: `web/src/connect.ts` (lines 156-178) — The `authInterceptor` function that:
- Extracts stored access tokens from localStorage
- Sets the `Authorization: Bearer <token>` header
- Handles 401 responses by refreshing the token
- Retries failed requests with new tokens

**Token kinds managed**:
1. **Access Token V2** (JWT) — Short-lived tokens (15 minutes) for stateless API access
2. **Personal Access Token (PAT)** — Long-lived tokens for programmatic access (prefix-based)
3. **Refresh Token** — Stored in httpOnly cookies, used to obtain new access tokens

**Backend validation package**: `server/auth` (server/auth/authenticator.go, server/auth/token.go) which:
- `AuthenticateByAccessTokenV2()` — Validates JWT access tokens
- `AuthenticateByPAT()` — Validates Personal Access Tokens via hash lookup
- `AuthenticateByRefreshToken()` — Validates refresh tokens and checks revocation status
- `resolveBearer()` — Routes Bearer token validation to appropriate handler
