**Premise correction:** There is NO external message broker (NATS or RabbitMQ) for webhook delivery workers. 

**Actual mechanism:**

The webhook delivery system uses an **in-process Go channel** for async message queuing, NOT an external message broker.

**Implementation details:**

1. **Queue declaration/initialization**: `internal/webhook/webhook.go:39`

2. **Worker pool**: `internal/webhook/webhook.go:42-55` (in the `init()` function)
   - 4 goroutines spawned at package initialization
   - Each worker consumes from the `asyncPostQueue` channel
   - Each message consumed by a worker is posted synchronously via `Post(payload)`

3. **Enqueueing**: `internal/webhook/webhook.go:184-196` in `PostAsync()`

This is a lightweight in-memory queue that will be lost on server restart. There is no external message broker involvement—webhook delivery is entirely in-process with 4 concurrent workers pulling from a buffered channel.
