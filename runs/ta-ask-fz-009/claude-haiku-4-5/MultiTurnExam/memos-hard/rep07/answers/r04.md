**Premise correction:** The webhook delivery system does **not use NATS or RabbitMQ**. There is no external message broker at all.

**Actual mechanism:**

Webhook delivery uses a **simple in-memory Go channel queue** with spawned goroutine workers:

- **Queue declaration:** `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`
  - Bounded queue with capacity of 128 payloads
  - Any payloads beyond the capacity are silently dropped (logged as warning)

- **Worker pool:** 4 goroutine workers are spawned in `init()` — `internal/webhook/webhook.go:42-54`
  - Each worker consumes from the shared `asyncPostQueue` channel
  - Calls `Post(payload)` to deliver each webhook
  - Logs delivery failures asynchronously

- **Enqueueing:** Triggered by `PostAsync(requestPayload)` — `internal/webhook/webhook.go:184-196`
  - Called from memo/comment creation and update handlers

This is a lightweight, in-process solution with no external dependencies, no persistence, and no distributed delivery guarantees.
