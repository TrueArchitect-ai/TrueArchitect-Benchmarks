**Premise correction:** The question assumes the public API has a GraphQL schema, but the codebase defines **no GraphQL schema**. There is no GraphQL API at all.

**Actual API surface:** The public API is defined through:

1. **Protocol Buffers** — `proto/api/v1/*.proto` files (service definitions, request/response messages)
2. **Connect RPC** — Generated from `.proto` files, provides binary RPC protocol with browser support
3. **gRPC-Gateway** — Translates the same `.proto` definitions into REST/JSON APIs
4. **OpenAPI** — Auto-generated from `.proto` definitions at `proto/gen/openapi.yaml`

The README explicitly states "full REST and gRPC APIs for integration" — both REST and gRPC are generated from a single Protocol Buffer source. No GraphQL surface exists.

Service definitions are in `proto/api/v1/` (e.g., `memo_service.proto`, `user_service.proto`, `attachment_service.proto`), and handlers are implemented in `server/router/api/v1/` (e.g., `memo_service.go`, `user_service.go`). The gRPC-Gateway translator and Connect RPC handlers are registered together in `server/router/api/v1/v1.go:65-147`.
