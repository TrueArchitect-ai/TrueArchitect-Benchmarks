**Premise correction:** This repository (`github.com/usememos/memos`) does **not** use GraphQL at all — there is no GraphQL schema. There are no `*.graphql`/`*.gql` files, no `graphql`/`apollo`/`urql`/`relay`/`trpc` dependencies in `web/package.json`, and no `type Query`, `gql\``, `buildSchema`, or Apollo usage anywhere in the Go or TypeScript sources.

**Actual API surface:** The public API is a **schema-first Protobuf/gRPC API**, exposed three ways — native gRPC, Connect (used by the web client), and a REST/JSON gRPC-Gateway — served over an Echo HTTP server. The `.proto` files are the single source of truth; Go stubs, Connect handlers, the REST gateway, and an OpenAPI spec are all generated from them.

- **Authoritative "schema" (service contracts)** — `proto/api/v1/`:
  - `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `ai_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `common.proto`
  - Design notes (follows Google AIPs): `proto/api/v1/README.md`
  - Codegen config: `proto/buf.yaml`, `proto/buf.gen.yaml`
- **Generated code** — `proto/gen/`:
  - gRPC/message stubs `proto/gen/api/v1/*.pb.go`, REST gateway `*.pb.gw.go`, Connect handlers `proto/gen/api/v1/apiv1connect/*.connect.go`
  - **REST/HTTP schema (OpenAPI):** `proto/gen/openapi.yaml` (embedded via `proto/openapi_embed.go`)
- **Server wiring:**
  - `server/server.go` — builds the Echo v5 HTTP server
  - `server/router/api/v1/v1.go` — `RegisterGateway()` mounts the REST gateway (`/api/v1/...`) and Connect handlers (`/memos.api.v1.*`)
  - `server/router/api/v1/connect_services.go` and `server/router/api/v1/*_service.go` — service implementations

So the closest analog to "the schema for the public API" is the Protobuf definitions in `proto/api/v1/`, with the REST surface documented in the generated `proto/gen/openapi.yaml` — not GraphQL.
