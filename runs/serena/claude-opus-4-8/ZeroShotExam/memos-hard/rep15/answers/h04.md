**No.** Outside the driver-selection factory, the MySQL driver is never constructed directly anywhere in the codebase.

Evidence:

- **The factory** is `NewDBDriver` in `store/db/db.go:14-32`, whose `case "mysql"` arm (`store/db/db.go:22`) calls `mysql.NewDB(profile)`. This is the *only* call to `mysql.NewDB` in the entire repository.

- **The MySQL driver type** is `mysql.DB` with constructor `mysql.NewDB`, defined in `store/db/mysql/mysql.go`. The struct literal `DB{profile: profile}` is built at `store/db/mysql/mysql.go:29` — but that line is *inside* `NewDB` itself, i.e. the constructor, not an external direct construction.

- **Every consumer** (including tests) obtains the MySQL driver through the factory `NewDBDriver`, never by calling `mysql.NewDB` or building `mysql.DB{}` directly. Factory callers include `store/test/store.go:28,50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70`.

- Other MySQL references (e.g. `store/test/containers.go` using `sql.Open("mysql", dsn)` and the third-party `go-sql-driver/mysql` package) open raw connections or parse DSNs for test containers — they do **not** construct the memos `mysql.DB` store driver.

So the `mysql.DB` driver is reached exclusively through the factory; there are zero direct (non-factory) construction sites, in production code or tests.
