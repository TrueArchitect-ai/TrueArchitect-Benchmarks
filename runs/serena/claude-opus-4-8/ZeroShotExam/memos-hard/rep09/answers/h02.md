**delivery function — `internal/webhook/webhook.go`; protection mechanism — `internal/webhook/webhook.go` + `internal/webhook/validate.go`**

**Where delivery executes:** The `Post` function in `internal/webhook/webhook.go:120` performs the actual outbound HTTP call — it marshals the payload, builds the request (optionally adding an HMAC-SHA256 Standard-Webhooks signature), and fires it at line 152 via `safeClient.Do(req)`. Dispatch is queued/async through `PostAsync` (`webhook.go:184`) feeding a worker pool that calls `Post`.

**What protects it from internal addresses:** Two layers, both keyed on `isReservedIP` (`validate.go:44`) which checks the target against a list of reserved/private CIDRs (loopback, RFC-1918, `169.254.0.0/16` link-local/cloud IMDS, and IPv6 equivalents — `validate.go:14-23`):

1. **Dial-time guard (the real enforcement):** `safeClient` uses a custom transport whose `safeDialContext` (`webhook.go:59`) resolves the hostname and rejects any address in a reserved range *at connection time* (`webhook.go:71-73`). Because the check happens at dial, it also defeats DNS-rebinding/TOCTOU attacks.

2. **Up-front validation:** `ValidateURL` in `internal/webhook/validate.go:62` is called when a webhook is configured — it requires an absolute http/https URL and rejects hostnames resolving to reserved IPs (`validate.go:76-81`).

Note both layers can be disabled by the `AllowPrivateIPs` toggle (`validate.go:41,45`), intended for self-hosted deployments targeting local-network services.
