**1st: `User`; 2nd: `Memo`** (User ≈ 7 external packages; Memo ≈ 6).

The data layer is the `store` package (`store/*.go`), where persistent entity structs are defined — `Memo`, `User`, `Attachment`, `Reaction`, `Inbox`, `MemoRelation`, `MemoShare`, `IdentityProvider`, `UserSetting`, etc. (see `store/user.go:` `type User struct`, `store/memo.go:` `type Memo struct`).

Counting distinct packages **outside** the `store/` tree (excluding `store/db/*` drivers and `store/test`, which are part of the data layer) that reference each type as `store.<Type>`:

- **`store.User` — 7 packages:** `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- **`store.Memo` — 6 packages:** `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`

Every other entity trails behind (Attachment 4; Inbox/MemoRelation/MemoShare 3 each; the rest ≤2). `User` edges out `Memo` mainly because it's additionally consumed by `server/auth` and `server/router/fileserver`. The ranking holds even if you collapse the `api/v1/test` package into `api/v1` (User 6 vs. Memo 5).
