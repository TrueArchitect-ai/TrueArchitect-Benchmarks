**Premise correction:** The webhook delivery workers consume from *neither* NATS nor RabbitMQ. This repository (memos) uses no external message broker at all for webhook delivery. The question's framing assumes a broker that doesn't exist in this codebase — a `grep` for NATS returns nothing (the only "nats" hit is a substring inside Catalan locale strings in `web/src/locales/ca.json`), and RabbitMQ/AMQP appear nowhere in the code.

**Actual mechanism:** Webhook dispatch is handled entirely in-process using a buffered **Go channel** with a pool of goroutine workers, all in `internal/webhook/webhook.go`:

- The "queue" is a plain in-memory channel, declared at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- The workers are started in `init()` at `internal/webhook/webhook.go:42-55` — **4 goroutines** each ranging over the channel and calling `Post()` to deliver the webhook via HTTP:
  ```go
  for range 4 {
      go func() {
          for payload := range asyncPostQueue {
              if err := Post(payload); err != nil { ... }
          }
      }()
  }
  ```
- Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send onto `asyncPostQueue` and drops the payload (with a warning) if the buffer of 128 is full.

So the "message broker" is a bounded in-process channel and the "queue declaration" is `make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39`; delivery itself is a plain HTTP POST in `Post()` (`internal/webhook/webhook.go:120`).
