**RPC handlers that can transitively trigger an outbound HTTP request to a user-configured webhook URL:**

Each of these gRPC handlers in `server/router/api/v1/` dispatches to a user's configured webhook (URL comes from `s.Store.GetUserWebhooks(...)` → `hook.Url`):

- **`CreateMemo`** — `server/router/api/v1/memo_service.go:157` → `DispatchMemoCreatedWebhook`
- **`UpdateMemo`** — `server/router/api/v1/memo_service.go:401` → `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:67`) → `DispatchMemoUpdatedWebhook`
- **`DeleteMemo`** — `server/router/api/v1/memo_service.go:562` → `DispatchMemoDeletedWebhook`
- **`CreateMemoComment`** — `server/router/api/v1/memo_service_comments.go:119` → `DispatchMemoCommentCreatedWebhook`

All four `Dispatch*` helpers live in `server/router/api/v1/memo_service_webhooks.go`; the memo-lifecycle ones funnel through the shared helper `dispatchMemoRelatedWebhook`, and every one of them calls `webhook.PostAsync(payload)`.

**Convergence function before delivery:** `webhook.Post` — `internal/webhook/webhook.go:120`

`PostAsync` merely enqueues onto a bounded async queue; the queue worker (and any synchronous caller) ultimately invokes `Post`, which is the single function that builds the `POST` request to `requestPayload.URL` and issues it via `safeClient.Do(req)` (`internal/webhook/webhook.go:151`). This is the one point where all webhook paths converge before the HTTP request actually leaves the process.
