**Premise correction:** There is no Redis in this repository. The cache layer is not backed by Redis (or Memcached) at all — there are zero references to Redis/ioredis/`REDIS_URL` anywhere, and `go.mod` pulls in no external cache library.

**Actual mechanism:** The cache is a custom, hand-rolled thread-safe **in-memory TTL cache** written in Go, backed by `sync.Map` with a background cleanup goroutine and a max-items eviction policy.

- **Cache implementation:** `store/cache/cache.go` — the `Cache` struct at `store/cache/cache.go:66-73`, with lazy TTL expiry on `Get` and a background `cleanupLoop`/`cleanup`.
- **Where it's configured (the connection/config equivalent):** the store constructor `store/store.go:40-45`:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  This same config builds three caches at `store/store.go:51-53`, including `userCache`.

**TTL for user entries:** There is **no user-specific TTL**. The `userCache` (`store/store.go:52`) uses the shared `cacheConfig`, so user entries expire under the **default TTL of 10 minutes** (`store/store.go:41`). User cache writes go through `Set`, which always applies `c.config.DefaultTTL` (`store/cache/cache.go:93-95`); the write sites are in `store/user.go:98,122,132,143,167`. A `SetWithTTL` for per-entry TTLs exists (`store/cache/cache.go:98`) but is never used for users. Background cleanup runs every 5 minutes, with lazy expiry on read (`store/user.go:150-155`), and entries are invalidated on update/delete via `deleteUserCache` (`store/user_delete.go:39-40`).
