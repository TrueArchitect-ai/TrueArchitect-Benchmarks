A browser requesting another user's profile image hits `GET /file/users/:identifier/avatar`. The avatar is not a file on disk — it's stored as a base64 data-URI in the `user.avatar_url` column and decoded at serve time. Hops from HTTP handler to stored data:

- `serveUserAvatar` — `server/router/fileserver/fileserver.go:168` (serving handler for `GET /file/users/:identifier/avatar`, registered at `fileserver.go:124`)
- `getUserByUsername` — `server/router/fileserver/fileserver.go:715` (looks up the target user by the `:identifier` path param)
- `Store.GetUser` — `store/user.go:148` (checks user cache, then delegates to list)
- `Store.ListUsers` — `store/user.go:136` (calls the DB driver, populates cache)
- `(*DB).ListUsers` — `store/db/sqlite/user.go:88` (builds `WHERE username = ?`, runs `SELECT ... avatar_url ... FROM user` via `QueryContext` at `store/db/sqlite/user.go:173`; equivalent drivers at `store/db/postgres/user.go:87` and `store/db/mysql/user.go:84`)

The stored data is the `avatar_url` column of the `user` table. Back in the handler, `parseDataURI` (`fileserver.go:737`) decodes that data-URI to the image bytes, which are validated against `avatarAllowedTypes` and written with `c.Blob` (`fileserver.go:209`).
