**Premise correction:** The question assumes webhook delivery workers consume from an external message broker (NATS or RabbitMQ). Neither is used — in fact, this repository (Memos) contains no message broker at all. There is no NATS, no RabbitMQ, no AMQP client, and no broker library in `go.mod`/`go.sum`.

**Actual mechanism:** Webhook delivery is handled entirely in-process using a buffered Go channel drained by a pool of goroutine workers, all self-contained in `internal/webhook/webhook.go`:

- **The "queue" is declared** at `internal/webhook/webhook.go:39` as a buffered channel with capacity 128:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- **The workers** are started in `init()` at `internal/webhook/webhook.go:42-55` — a fixed pool of 4 goroutines, each ranging over `asyncPostQueue` and calling `Post()` to deliver each webhook over HTTP.
- **The producer** is `PostAsync()` (`internal/webhook/webhook.go:184-196`), which non-blockingly enqueues onto the channel and drops the payload with a warning if the buffer is full.
- **The caller** is `dispatchMemoRelatedWebhook` in `server/router/api/v1/memo_service_webhooks.go:71`, which invokes `webhook.PostAsync(payload)`.

So the correct answer is: neither broker — delivery uses an in-memory buffered channel (`asyncPostQueue`) declared at `internal/webhook/webhook.go:39`, consumed by 4 in-process goroutine workers.
