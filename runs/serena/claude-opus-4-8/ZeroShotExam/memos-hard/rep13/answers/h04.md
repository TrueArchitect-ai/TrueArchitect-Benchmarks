**yes** — but only in test code, not in production.

The driver-selection factory is `NewDBDriver` in `store/db/db.go:14–32`, whose MySQL branch calls `mysql.NewDB(profile)` (`store/db/db.go:22`). That factory function `mysql.NewDB` (`store/db/mysql/mysql.go:20`) is the intended construction entry point; internally it builds the struct at `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`).

Outside the factory, the MySQL driver struct is constructed directly in exactly one place — a unit test:
- `store/db/mysql/auth_config_test.go:12` — `db := &DB{}`, a zero-value `mysql.DB` built directly (bypassing `NewDB`) just to invoke `db.IsRetryableAuthenticationMutationError(...)`.

Evidence for "no production site outside the factory": every other path reaches the driver through the factory. All callers of `db.NewDBDriver` are test/benchmark harnesses (`store/test/store.go:28`, `:50`; `server/router/api/v1/test/memo_service_benchmark_test.go:70`), and `store/test/containers.go` only opens a raw `sql.Open("mysql", dsn)` connection (line ~145) rather than constructing the `mysql.DB` driver struct. There are no direct `mysql.NewDB(...)` calls outside `store/db/db.go`.

So: the MySQL driver is constructed directly outside the factory only in test code (`store/db/mysql/auth_config_test.go:12`); no production code constructs it outside the factory.
