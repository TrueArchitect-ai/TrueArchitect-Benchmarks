The question's premise is incorrect: **there is no nightly database-cleanup job scheduled in the cron scheduler.**

The repository does contain a standalone cron scheduler *library* at `internal/scheduler/`, but it is never wired into the running application — a search for its import path (`usememos/memos/internal/scheduler`) turns up only its own test files (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). No production code under `server/`, `store/`, or `main` ever registers a job with it.

What likely inspired the question is an **example**, not a real job:
- `internal/scheduler/example_test.go:97-105` — inside `Example_multipleJobs()`, a sample job named `"cleanup"` with schedule `"0 2 * * *"` (2:00 AM daily) and the comment "Cleanup old data every night at 2 AM." The same `0 2 * * *` daily-cleanup string appears as documentation in `internal/scheduler/doc.go` and `internal/scheduler/README.md`.

This example only demonstrates the library's API — it never registers or executes in the server, and it cleans up "old data" conceptually rather than the database.

For completeness, the only periodic background task the server actually runs is the S3 presigned-URL refresher (`server/runner/s3presign/runner.go`), which fires every 12 hours off a `time.Ticker` — not cron-scheduled, not nightly, and unrelated to database cleanup.

So there is no scheduled time to report, because the job doesn't exist.
