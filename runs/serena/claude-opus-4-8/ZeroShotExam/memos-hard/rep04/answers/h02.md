**Delivery function** — `Post` in `internal/webhook/webhook.go` is where the outbound HTTP request actually executes (`safeClient.Do(req)` at line 152). Deliveries are enqueued via `PostAsync` and the goroutine workers in `init()` call `Post`, which builds the POST request and sends it through the shared `safeClient`.

**Protection mechanism** — SSRF protection is enforced at dial time by `safeDialContext` in `internal/webhook/webhook.go` (lines 59–77), which is wired into `safeClient`'s `Transport.DialContext`. It resolves the target hostname and rejects any address matching `isReservedIP`. The reserved ranges and check live in `internal/webhook/validate.go` — `reservedCIDRs`/`isReservedIP` (loopback, RFC-1918 private, link-local incl. 169.254.169.254 IMDS, and IPv6 equivalents). Because the check happens at dial time after DNS resolution, it also defeats DNS-rebinding. There is a secondary up-front check, `ValidateURL` in `internal/webhook/validate.go` (lines 62–83), run when a webhook URL is configured. Both can be disabled via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`).

So:

delivery function — `Post` at `internal/webhook/webhook.go` (executes at `safeClient.Do`, line 152); protection mechanism — dial-time reserved-IP blocking via `safeDialContext` (`internal/webhook/webhook.go:59`) using `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go` (with an up-front `ValidateURL` check in the same file).
