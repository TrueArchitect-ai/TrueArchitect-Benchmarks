**`s3presign.Runner` (its `CheckAndPresign` logic) — every 12 hours — wired at `server/server.go:169` (inside `startBackgroundRunners`)**

Details:

- **Component:** The `Runner` in package `s3presign`, defined in `server/runner/s3presign/runner.go:16`. Its `CheckAndPresign` method (`runner.go:47`) walks all S3-backed attachments and re-generates their presigned S3 URLs before they expire, writing the fresh URL back via `Store.UpdateAttachment`. Because externally-stored (S3) attachments are served through time-limited presigned URLs, without this refresh the stored links would eventually go stale.

- **Schedule:** A Go `time.Ticker` on a **12-hour interval** — `const runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27`), used in the loop in `Run` (`runner.go:29-30`). Internally each URL is presigned with a ~5-day expiration and skipped while still valid for another 4 days, so it refreshes roughly a day before expiry.

- **Wiring into startup:** In `server/server.go`, inside `startBackgroundRunners`. The runner is constructed at `server/server.go:162` (`s3presignRunner := s3presign.NewRunner(s.Store)`), run once immediately at `server/server.go:163` (`RunOnce`), and its continuous background loop is launched in a goroutine at **`server/server.go:169`** (`s3presignRunner.Run(s3Context)`). `startBackgroundRunners` is itself called during server start at `server/server.go:129`.

Note: although the repo has an `internal/scheduler` package, this runner is not wired through it — it manages its own ticker goroutine tracked by `backgroundRunnerWG`.
