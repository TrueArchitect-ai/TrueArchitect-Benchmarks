**Delivery function** — `internal/webhook/webhook.go`. The outbound HTTP delivery actually executes in `Post()` (`internal/webhook/webhook.go:120`), specifically at the `safeClient.Do(req)` call on line 152. In production this runs asynchronously: `PostAsync()` (line 184) enqueues payloads onto `asyncPostQueue`, and four worker goroutines started in `init()` (lines 42–55) drain the queue and call `Post()`.

**Protection mechanism** — `internal/webhook/webhook.go` + `internal/webhook/validate.go`. The primary, dial-time SSRF guard is `safeDialContext` (`internal/webhook/webhook.go:59`), installed as the `DialContext` of the shared `safeClient` transport (lines 32–37). On every connection it resolves the hostname and rejects any address in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`), which checks against `reservedCIDRs`/`reservedNetworks` (loopback, RFC-1918, link-local/cloud IMDS `169.254.169.254`, and IPv6 equivalents — `internal/webhook/validate.go:14`). Because it resolves and checks at dial time, it also defeats DNS-rebinding. A secondary up-front check, `ValidateURL` (`internal/webhook/validate.go:62`), enforces http/https scheme and the same reserved-IP rejection when a webhook URL is configured. Both can be disabled by the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for local-network deployments.
