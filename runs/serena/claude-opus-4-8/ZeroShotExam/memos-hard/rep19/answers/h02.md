**delivery function** — `Post` in `internal/webhook/webhook.go` (the actual outbound HTTP request executes at `safeClient.Do(req)`, line 152; `PostAsync` enqueues onto a queue whose workers call `Post`).

**protection mechanism** — `internal/webhook/webhook.go`, via `safeDialContext` (lines 59–77), the `DialContext` of the shared `safeClient` transport. At dial time it resolves the target hostname and rejects any address in a reserved/private range using `isReservedIP` — defined in `internal/webhook/validate.go` (lines 44–54) against the `reservedCIDRs`/`reservedNetworks` blocklist (loopback, RFC-1918, link-local incl. cloud IMDS `169.254.169.254`, and IPv6 equivalents). Because the check happens on the resolved IP at dial time, it also defeats DNS-rebinding.

Notes worth calling out:
- There is a second, earlier layer: `ValidateURL` in `internal/webhook/validate.go` (lines 62–83) validates a webhook URL when it is configured (scheme must be http/https and must not resolve to a reserved IP). But this is validation-at-config-time only; the dial-time `safeDialContext` guard is what actually protects the outbound delivery itself.
- The protection can be globally disabled by the `AllowPrivateIPs` flag in `internal/webhook/validate.go:41`, intended for self-hosted deployments targeting local-network services.

So the delivery-time protection is `safeDialContext` (backed by `isReservedIP`), summarized in short form below:

delivery function — `Post` / `safeClient.Do` at `internal/webhook/webhook.go`; protection mechanism — `safeDialContext` calling `isReservedIP` at `internal/webhook/webhook.go` and `internal/webhook/validate.go`.
