h15.

Memo visibility is enforced across several distinct server surfaces. The verified enforcement sites:

Central single-memo read gate (`checkMemoReadAccess`, called by GetMemo / parent-comment reads) — server/router/api/v1/memo_service.go (lines 39–68; `if memo.Visibility == store.Private && memo.CreatorID != user.ID { PermissionDenied }`)

ListMemos query scoping (anonymous → PUBLIC only; authed → own + PUBLIC/PROTECTED) — server/router/api/v1/memo_service.go (lines 219–225; `visibility in ["PUBLIC","PROTECTED"]`)

Store/SQL-level visibility filtering (translates `FindMemo.VisibilityList` into a `visibility IN (...)` WHERE clause, per dialect) — store/db/sqlite/memo.go (line 102), store/db/postgres/memo.go, store/db/mysql/memo.go

Comment listing + creation gate — server/router/api/v1/memo_service_comments.go (ListMemoComments calls checkMemoReadAccess at line 148 and re-scopes comment visibility; CreateMemoComment blocks commenting on a private memo you don't own)

Reactions — server/router/api/v1/reaction_service.go (ListMemoReactions / UpsertMemoReaction gate on parent memo visibility)

Memo attachment listing — server/router/api/v1/memo_attachment_service.go (ListMemoAttachments checks parent memo visibility)

Generic attachment access (gRPC/REST) — server/router/api/v1/attachment_service.go (`checkAttachmentAccess`, resolves parent memo visibility)

Raw file download HTTP surface (with anonymous + share-token logic) — server/router/fileserver/fileserver.go (`checkAttachmentPermission`, lines 650–702)

SSE real-time streaming delivery filter — server/router/api/v1/sse_hub.go (`SSEClient.canReceive`, lines 134–144; `case store.Private: return c.userID == event.CreatorID || c.role == store.RoleAdmin`)

RSS feed (hardcoded PUBLIC-only) — server/router/rss/rss.go (lines 90, 141; `VisibilityList: []store.Visibility{store.Public}`)

Frontend server-side render/metadata (PUBLIC-only) — server/router/frontend/frontend.go (line 150; `VisibilityList: []store.Visibility{store.Public}`)

The three primary/independent surfaces are the API read gate (memo_service.go `checkMemoReadAccess`), the store-level SQL `visibility IN (...)` filter (store/db/*/memo.go), and the SSE streaming filter (sse_hub.go `canReceive`); the RSS and frontend PUBLIC-only queries, attachment/fileserver checks, comments, and reactions are additional distinct sites.
