The question's premise is mistaken: there is **no nightly database-cleanup job** wired into any cron scheduler in this repository.

What actually exists:

- The repo contains a homegrown cron scheduler *library* at `internal/scheduler/` (`scheduler.go`, `job.go`, `parser.go`, etc.), but it is never imported, instantiated, or given any jobs by the running application. No production code registers any scheduled job against it.
- The only "cleanup" job that resembles the premise lives in **example/test code**: `internal/scheduler/example_test.go:97-106` defines a job named `"cleanup"` with schedule `"0 2 * * *"` (daily at 2:00 AM). However, its handler merely prints `"Cleaning up old data..."` — it performs **no database work**, and it is never wired into the app.
- The only genuinely active cron in the repo is a GitHub Actions workflow, `.github/workflows/stale.yml:4-5` (`cron: "0 */8 * * *"`, every 8 hours), which marks stale issues/PRs — unrelated to database cleanup.
- The store layer does have an in-memory cache eviction loop (`store/cache/cache.go`, `CleanupInterval: 5 * time.Minute`), but that is a `time.Ticker` goroutine, not a cron job, and it evicts in-memory cache entries rather than cleaning a database.

So the answer to "what time is the nightly database-cleanup job scheduled to run" is that no such job is scheduled. If you're thinking of the example-only `"cleanup"` job (2:00 AM daily, `0 2 * * *`), note it is illustrative test code that does no database cleanup and is not registered anywhere in the app.
