**Premise correction:** The question assumes this repository has per-user API rate-limiting middleware. It does not. No API rate limiting of any kind — per-user, per-IP, per-endpoint, global, or login-attempt — exists anywhere in the codebase, and no rate-limiting library is imported (confirmed absent from `go.mod`/`go.sum`).

This is the **memos** project: a Go backend (Connect/gRPC + Echo v5) with a React frontend. The complete server middleware/interceptor chain contains no limiter:

- **Echo HTTP middleware** (`server/server.go:51-52`): only `middleware.Recover()` and `newCORSMiddleware(profile)`.
- **Connect RPC interceptors** (`server/router/api/v1/v1.go:133-137`): `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` — metadata conversion, logging, panic recovery, and authentication only. Defined in `server/router/api/v1/connect_interceptors.go`.
- **Auth/login** (`server/router/api/v1/auth_service.go`, `server/auth/*.go`): no failed-login throttling, lockout, or attempt counting.

**The only "limits" that exist are in-process concurrency semaphores, not request-rate limits:**

- `imageProcessingSemaphore = semaphore.NewWeighted(2)` (`server/router/api/v1/v1.go:59-60`) — caps **image processing (EXIF stripping) at 2 concurrent operations process-wide**, across all users combined. Acquired in `attachment_service_image.go:67-77` and invoked from `attachment_service.go:158-160`; on exhaustion it returns `codes.ResourceExhausted, "too many image processing requests"`.
- `thumbnailSemaphore = semaphore.NewWeighted(3)` (`v1.go:39-41`) — declared for 3 concurrent thumbnail generations but **never actually acquired anywhere** (effectively dead code).

These are global concurrency caps meant to prevent memory exhaustion — they are not per-user, not per-IP, and not rate (requests-per-time) limits. There is also no `429`/`StatusTooManyRequests` handling and no deployment-level throttling (no nginx `limit_req`, no Caddy config) in the repo.

So: there is no per-user rate-limiting middleware to point to. The closest thing is a global cap of 2 concurrent image-processing operations.
