**Premise correction:** The premise is mistaken — this repository (`usememos/memos`) has **no per-user API rate-limiting middleware**, nor rate limiting of any other kind (per-IP, global, etc.). There is nothing registered, so there are no request limits to report.

What I verified:

- The API server uses Connect/gRPC interceptors as its middleware chain, registered in `server/router/api/v1/v1.go:133-137`:
  ```go
  connectInterceptors := connect.WithInterceptors(
      NewMetadataInterceptor(),   // HTTP headers → gRPC metadata
      NewLoggingInterceptor(logStacktraces),
      NewRecoveryInterceptor(logStacktraces),
      NewAuthInterceptor(authorizer),
  )
  ```
  These four interceptors (defined in `server/router/api/v1/connect_interceptors.go`) handle metadata conversion, logging, panic recovery, and authentication/authorization — none of them rate-limit.

- No rate-limiting dependency exists: `go.mod`/`go.sum` contain no `golang.org/x/time/rate`, `tollbooth`, or similar library.

- A repo-wide search for `rate.?limit`, `throttle`, `429`, `TooManyRequests`, `quota`, etc. across all Go files returns only a single hit — and it's just a documentation recommendation, not an implementation: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" under "Security Considerations" for the email package.

So there is no rate-limiting middleware to locate and no limits to cite. If you're looking to add one, the natural insertion point would be a new interceptor in the chain at `server/router/api/v1/v1.go:133`.
