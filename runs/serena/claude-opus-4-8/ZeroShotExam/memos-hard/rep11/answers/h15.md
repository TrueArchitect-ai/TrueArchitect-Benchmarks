Memo visibility (who may view a memo) is enforced at several distinct server surfaces:

Single-memo read gate (`checkMemoReadAccess`, used by `GetMemo` and comment lookups): private memos require creator == current user, protected requires any authenticated user — server/router/api/v1/memo_service.go
List query visibility injection (`ListMemos` sets `VisibilityList`/CEL filter based on caller identity) — server/router/api/v1/memo_service.go
Store SQL `visibility IN (...)` clause builders, one per DB dialect:
 - store/db/sqlite/memo.go
 - store/db/postgres/memo.go
 - store/db/mysql/memo.go
Comment surface (`ListMemoComments` visibility filter + `CreateMemoComment` private-memo gate) — server/router/api/v1/memo_service_comments.go
RSS feed list (restricts to PUBLIC only) — server/router/rss/rss.go

The three core sites are `checkMemoReadAccess` + `ListMemos` in memo_service.go, and the store-level `visibility IN` filters in the sqlite/postgres/mysql memo.go files; the comment service and RSS handler are additional surfaces that enforce the same rules.
