**Yes** — the MySQL driver is constructed directly outside the driver-selection factory, in a test file.

Evidence:

- **Driver-selection factory:** `store/db/db.go` — `NewDBDriver` switches on `profile.Driver` and calls `mysql.NewDB(profile)` for the `"mysql"` case (`store/db/db.go:22`). This is the intended construction path.

- **The MySQL driver type** is the struct `DB` in package `mysql` (`store/db/mysql/mysql.go:14`), whose constructor is `mysql.NewDB`. Note there is no `mysql.New`/`NewMySQLDriver`; the type is `mysql.DB`.

- **Direct construction outside the factory:** `store/db/mysql/auth_config_test.go:12` builds a bare driver with `db := &DB{}` to exercise the method `IsRetryableAuthenticationMutationError` in isolation, without going through `NewDB` or the factory.

  (The struct literal `DB{profile: profile}` at `store/db/mysql/mysql.go:29` is *inside* the `NewDB` constructor itself, i.e. the factory's delegate, so it isn't an independent construction site. Third-party `mysqldriver.MySQLError{}` / `ParseDSN` uses are the `go-sql-driver/mysql` library's types, not the memos driver.)

So the only direct construction outside the factory path is the unit test at `store/db/mysql/auth_config_test.go:12`.
