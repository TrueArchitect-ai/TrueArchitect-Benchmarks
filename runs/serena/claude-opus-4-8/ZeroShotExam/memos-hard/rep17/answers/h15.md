Memo view-visibility is enforced at multiple distinct server surfaces. The rules are the standard three-tier: PUBLIC → anyone; PROTECTED → any authenticated user; PRIVATE → creator (or admin) only. Distinct enforcement sites:

1. Single‑memo read gate `checkMemoReadAccess` (used by GetMemo, and re‑used for comments) — `server/router/api/v1/memo_service.go:39` (check at lines 55–66; GetMemo call at `memo_service.go:356`)
2. List query visibility filtering in `ListMemos` — `server/router/api/v1/memo_service.go:218` (sets `VisibilityList`/adds `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` filter)
3. Store/SQL layer that applies the `VisibilityList`/visibility filter for every FindMemo — `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`
4. Comment surface: parent‑memo check in `CreateMemoComment` and the read gate + filter in `ListMemoComments` — `server/router/api/v1/memo_service_comments.go:41` and `memo_service_comments.go:148,157-161`
5. Memo attachment listing `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-224`
6. Raw attachment/file serving `checkAttachmentPermission` — `server/router/fileserver/fileserver.go:677,699`
7. RSS feed (public-only) — `server/router/rss/rss.go:90,141`
8. Server-side rendered frontend/meta (public-only) — `server/router/frontend/frontend.go:150`

Answer format (enforcement site — path):

checkMemoReadAccess single-memo read gate (GetMemo, GetMemo parent) — server/router/api/v1/memo_service.go

The three core "who may view a memo" sites are #1 (`checkMemoReadAccess`), #2 (`ListMemos`), and #3 (the store SQL filter); the remaining sites enforce the same visibility rules on adjacent surfaces (comments, attachments, file serving, RSS, SSR).
