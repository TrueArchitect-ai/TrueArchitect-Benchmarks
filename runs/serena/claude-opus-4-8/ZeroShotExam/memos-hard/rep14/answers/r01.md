**Premise correction:** There is no Redis connection anywhere in this repository. The premise that the cache layer uses Redis is false — `redis`/`ioredis`/any Redis client appears nowhere in `go.mod` or the Go source. This is the *memos* project, and its cache layer is a **thread-safe in-memory cache** (a custom `sync.Map`-based implementation), not a networked cache store.

**Actual mechanism:**

- The cache implementation lives in `store/cache/cache.go` — a `Cache` struct backed by `sync.Map` with per-item TTL expiration and a background cleanup goroutine (`cleanupLoop`, `store/cache/cache.go:200`).
- The cache is "configured" (constructed) in `store/store.go:40-53`, not via any connection string. Three separate in-memory cache instances are created with a shared `cacheConfig`:
  - `store/store.go:40-45` defines the config: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`.
  - `store/store.go:52` creates `userCache: cache.New(cacheConfig)` (alongside `instanceSettingCache` and `userSettingCache`).

- **TTL for user entries:** User entries are written via `s.userCache.Set(...)` (`store/user.go:98, 122, 132, 143, 167`). `Set` applies the cache's `DefaultTTL` (`store/cache/cache.go:93-95`), and no `SetWithTTL` override is used for users. So **user entries expire after 10 minutes** — the default TTL from `store/store.go:41`. There is no user-specific TTL; users get the same 10-minute default as instance settings and user settings.

Note the default-config helper in `store/cache/cache.go:57-64` also specifies 10 minutes, but the live values come from the explicit `cacheConfig` literal in `store/store.go:40`.
