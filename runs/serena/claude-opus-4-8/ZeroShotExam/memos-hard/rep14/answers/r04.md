**Premise correction:** The question's premise is false — the webhook delivery workers consume from *neither* NATS nor RabbitMQ. This repository (`usememos/memos`) has no external message broker at all; `go.mod`/`go.sum` contain no NATS, RabbitMQ, or AMQP client dependency.

**Actual mechanism:** Webhook delivery is entirely in-process, using a Go buffered channel drained by a fixed goroutine pool.

- The "queue" is a package-level buffered channel declared at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- The "delivery workers" are 4 goroutines spawned in `init()` (`internal/webhook/webhook.go:42-55`) that `range` over that channel and dispatch each payload via a plain HTTP `POST` (in `Post()`, lines ~120-180).
- Producers enqueue non-blockingly via `PostAsync()` (`internal/webhook/webhook.go:184-196`), dropping the payload if the channel is full. Call sites are in `server/router/api/v1/memo_service_webhooks.go` (e.g. lines 43 and 71) when memos change.

So the declaration you'd be looking for is the channel `asyncPostQueue` at `internal/webhook/webhook.go:39` — there is no broker subject/exchange because no broker is involved.
