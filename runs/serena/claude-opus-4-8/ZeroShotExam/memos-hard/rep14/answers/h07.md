This is Memos. A user's profile image (avatar) is stored inline as a base64 data URI in the `avatar_url` column of the `user` table — not as a separate file/blob. A browser hits `GET /file/users/:identifier/avatar`, and the chain from serving handler to stored data is:

- `serveUserAvatar` — server/router/fileserver/fileserver.go:168 (route registered at fileserver.go:124; parses the stored data URI at line 196 and writes bytes at line 209)
- `getUserByUsername` — server/router/fileserver/fileserver.go:715 (calls `s.Store.GetUser`)
- `Store.GetUser` — store/user.go:148 (delegates to `ListUsers`)
- `Store.ListUsers` — store/user.go:136 (calls `s.driver.ListUsers`)
- `DB.ListUsers` — store/db/sqlite/user.go:88 (builds `SELECT ... avatar_url ... FROM user`, runs `QueryContext` at line 173, scans `AvatarURL` at line 189)

The final data-layer hop is driver-specific; the same method exists for the other backends: store/db/postgres/user.go:87 and store/db/mysql/user.go:84.

So the stored data reached is the `user.avatar_url` column (a `data:` URI), fetched via the SQL query in the DB driver.
