**Premise correction:** This repository (`github.com/usememos/memos`, a Go project) has **no GraphQL schema at all** — there is no `.graphql` file, no `typeDefs`/`buildSchema`, and no GraphQL server anywhere in the tree. The premise that the public API is defined via a GraphQL schema is incorrect.

**Actual API surface:** The public API is a **Protocol Buffers / gRPC API** (with gRPC-gateway REST + Connect bindings). The schema is defined in the `.proto` files under `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto`

Supporting details:
- Codegen is driven by `proto/buf.gen.yaml` / `proto/buf.yaml`, producing Go stubs in `proto/gen/api/v1/` (gRPC `*_grpc.pb.go`, REST gateway `*.pb.gw.go`, and Connect `proto/gen/api/v1/apiv1connect/*.connect.go`).
- An OpenAPI document is embedded via `proto/openapi_embed.go`, and the HTTP/gRPC surface is wired up in `server/router/` and `server/server.go`.

So the public API is gRPC + REST(gateway)/Connect generated from protobuf definitions in `proto/api/v1/`, not GraphQL.
