Memo view-visibility (PUBLIC/PROTECTED/PRIVATE) is enforced at multiple independent server surfaces. The distinct enforcement sites:

Single-memo read gate (gRPC v1 `GetMemo` / comment `GetMemo` / `ListMemoComments`) — `server/router/api/v1/memo_service.go` (`checkMemoReadAccess`, lines 39–68; the visibility checks at lines 55 and 63; invoked at lines 356, 367, and `memo_service_comments.go:148`)
ListMemos visibility filtering (gRPC v1 list surface) — `server/router/api/v1/memo_service.go` (lines 218–227, injecting `VisibilityList` / the `creator_id ... || visibility in ["PUBLIC","PROTECTED"]` filter)
RSS feed (public web feed surface) — `server/router/rss/rss.go` (restricts results to `store.Public` at line 90, and the per-user feed at line 141)
File-server attachment access (raw file/attachment HTTP surface) — `server/router/fileserver/fileserver.go` (`checkAttachmentPermission`, visibility checks at lines 677 and 699)

Additional surfaces that enforce the same memo-visibility rule when serving memo-derived content:

gRPC v1 attachment-binary access — `server/router/api/v1/attachment_service.go` (lines 445–451) and `server/router/api/v1/memo_attachment_service.go` (lines 214–222)
User-stats listing (visibility-scoped memo stats) — `server/router/api/v1/user_service_stats.go` (lines 82–90 and 218–220)
Reaction access (view/react gated on memo visibility) — `server/router/api/v1/reaction_service.go` (lines 30–38, 83)

The first four are the core "who may view a memo" enforcement sites across distinct surfaces (single-memo RPC, list RPC, RSS, and the file server).
