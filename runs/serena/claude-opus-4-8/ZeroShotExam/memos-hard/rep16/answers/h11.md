Based on my analysis of the `store` package (the data layer) in this memos repository:

h11.

**1st: User (~6 packages); 2nd: Memo (~4 packages)**

The persistent entity types are the DB-backed structs defined in the `store/` package (e.g. `User` in `store/user.go`, `Memo` in `store/memo.go`, `Attachment` in `store/attachment.go`, `Inbox`, `MemoRelation`, `Reaction`, `IdentityProvider`, `UserSetting`, etc.).

Counting distinct packages **outside** `store/` that reference each type:

- **`store.User`** — referenced from ~6 packages: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/rss`.
- **`store.Memo`** — referenced from ~4 packages: `server/notification`, `server/router/api/v1`, `server/router/rss`, `server/runner/memopayload`.
- (Next: `store.Attachment` at ~3 packages — `server/router/api/v1`, `server/router/fileserver`, `server/router/rss`.)

So `User` (`store/user.go`) has the widest cross-package reach, followed by `Memo` (`store/memo.go`).
