**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is not even running in this application — so there is no scheduled time to report.**

Evidence:
- A repo-wide search for any scheduled cleanup/nightly/cron job (`cleanup`, `nightly`, `purge`, `cron`, `midnight`, `@daily`, `0 0`) finds **no database-cleanup job**. The only `cleanup` hits are inline, request-time attachment/user cleanup in handlers (e.g. `server/router/api/v1/user_service.go:421-450`, `memo_service.go:579`) and test teardown — none is a scheduled background job.
- A cron scheduler implementation does exist as a library package (`internal/scheduler/scheduler.go`, `internal/scheduler/parser.go` with `ParseCronExpression`), but it is **never instantiated or used** by production code: searching for `scheduler.New`, `.Register(`, or imports of `internal/scheduler` outside the package itself returns nothing. No jobs are registered and `Scheduler.Start` is never called from the server.
- The actual background work in this server is done by plain `time.Ticker` runners, not the cron scheduler — specifically the S3 presign runner on a fixed 12-hour interval (`server/runner/s3presign/runner.go:27`, wired at `server/server.go:169`). There is no daily/nightly DB-cleanup runner among them.

So no nightly DB-cleanup job is scheduled at any time; both the job and its use of the cron scheduler are absent.
