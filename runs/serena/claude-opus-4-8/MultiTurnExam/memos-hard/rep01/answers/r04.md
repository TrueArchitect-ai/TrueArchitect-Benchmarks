**Premise correction: neither. The webhook delivery workers do not consume from any external message broker — there is no NATS, no RabbitMQ, and no AMQP anywhere in the codebase.** A repo-wide search for `nats`, `rabbitmq`, `amqp`, `streadway` (etc.) returns no matches in the Go source, and `go.mod` declares no such dependency.

**Actual mechanism:** Webhook delivery is queued through an **in-process buffered Go channel**, entirely within the single server process:
- The queue is declared as a package-level buffered channel `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39`.
- Four worker goroutines are started in the package `init()` (`internal/webhook/webhook.go:42-55`); each ranges over `asyncPostQueue` and calls `Post` to perform the actual outbound HTTP delivery.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), a non-blocking send that drops the payload (with a warning) if the channel's 128-slot buffer is full.

So the "broker" is just an in-memory channel with a fixed buffer and a fixed pool of 4 consumer goroutines — nothing is declared on or consumed from NATS or RabbitMQ.
