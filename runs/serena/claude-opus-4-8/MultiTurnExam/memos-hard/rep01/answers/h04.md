**Yes** — but only in a test, and only as a bare struct literal (not via the `NewDB` constructor).

Evidence:
- The exported constructor `mysql.NewDB` is referenced in exactly one place in the whole codebase: the driver-selection factory `NewDBDriver` at `/bench/repo/store/db/db.go:22`. A repo-wide `grep "mysql.NewDB"` returns only that line. So the *production* driver is never constructed outside the factory.
- However, the MySQL driver type itself (`DB`) is constructed directly via a struct literal outside the factory in a test: `/bench/repo/store/db/mysql/auth_config_test.go:12` — `db := &DB{}` (used to exercise `IsRetryableAuthenticationMutationError` without opening a real connection). This lives inside the `mysql` package, so it can build the unexported-field struct directly.
- The only other `DB{...}` literal is inside `NewDB` itself (`/bench/repo/store/db/mysql/mysql.go:29`), which is the factory-invoked constructor, not a separate site.

So: no direct construction in non-test/production code; the single exception is the `&DB{}` literal in `auth_config_test.go`.
