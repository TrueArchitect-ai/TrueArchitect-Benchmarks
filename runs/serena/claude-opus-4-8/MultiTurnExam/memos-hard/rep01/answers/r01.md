**Premise correction:** There is no Redis anywhere in this codebase. A repo-wide search for `redis` returns nothing in the Go source and nothing in `go.mod`. The cache layer is **not** backed by Redis (or any external store) — it's a purely **in-process, in-memory cache** implemented in `store/cache/cache.go` (a map guarded by a mutex, with background cleanup goroutines). So there is no Redis connection to configure.

**Actual mechanism:**
- The cache is configured in `Store.New` at `store/store.go:40-45`, where a single `cache.Config` is built with `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`.
- Three in-memory caches are created from that config — `instanceSettingCache`, **`userCache`**, and `userSettingCache` — via `cache.New(cacheConfig)` (`store/store.go:51-53`).
- User entries are written through `s.userCache.Set(...)` in `Store.GetUser`/`Store.ListUsers` (`store/user.go:167`, `store/user.go:143`). `Set` uses the cache's default TTL (see the interface contract in `store/cache/cache.go:12-14` and `DefaultConfig` at `store/cache/cache.go:57`), so **user entries expire after 10 minutes**, with expired items reaped every 5 minutes by the cleanup goroutine.

In short: user cache TTL = **10 minutes**, held in an in-memory cache configured in `store/store.go:40`, not Redis.
