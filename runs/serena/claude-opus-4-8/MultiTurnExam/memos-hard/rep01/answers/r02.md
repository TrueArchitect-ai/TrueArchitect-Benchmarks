**Premise correction: there is no per-user API rate-limiting middleware in this codebase — it does not exist, so there is nothing registered and no request limits to report.**

Evidence:
- A repo-wide search for any rate-limiting terminology (`ratelimit`, `rate limit`, `limiter`, `throttle`, `tollbooth`, `golang.org/x/time/rate`) returns **no matches** in the Go source, and `go.mod` declares no rate-limiting dependency.
- The actual middleware/interceptor stack contains no limiter. The Echo HTTP server registers only `middleware.Recover()` and the CORS middleware (`server/server.go:51-52`, `server/cors.go:13-14`), plus a static-file/SPA-fallback handler for the frontend (`server/router/frontend/frontend.go:54-59`).
- The API layer (Connect/gRPC) registers these interceptors only: metadata, logging, recovery, and auth — `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` (`server/router/api/v1/v1.go:133-138`), with the gRPC-gateway using an auth-only middleware (`v1.go:69,97`). The only request-size guard present is `connect.WithReadMaxBytes(maxAPIRequestBytes)` (`v1.go:141`), which is a payload-size cap, not a per-user request-rate limit.

So no per-user rate limiter is registered anywhere, and no request-count/window limits are defined.
