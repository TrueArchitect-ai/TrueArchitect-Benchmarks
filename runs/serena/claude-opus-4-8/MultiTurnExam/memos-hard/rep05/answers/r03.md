**Premise correction:** There is no nightly database-cleanup job in the cron scheduler — so there is no scheduled time to report. The premise is false on two counts.

Evidence:
- **No such job exists.** There is no scheduled database-cleanup task anywhere. The only recurring background work wired into startup is the S3 presign runner (a `time.Ticker` every 12 hours, `server/server.go:162-169`), which re-signs attachment URLs — not a DB cleanup. Searches for `cleanup`/`nightly`/`midnight`/`prune`/`vacuum` in production code turn up only inline cleanup during memo/user deletion (`server/router/api/v1/memo_service.go:579`, `user_service.go:421+`), not a scheduled job.
- **The cron scheduler isn't even in use.** A generic cron scheduler package does exist at `internal/scheduler/` (its `job.go`/`doc.go` mention cron expressions like `"0 0 * * *"` and an example named `"daily-cleanup"`), but it is never imported or instantiated in production: `grep` for `usememos/memos/internal/scheduler` outside the package itself returns nothing, and there are no `NewScheduler`/`AddJob`/`.Start()` callers. The `"daily-cleanup"` string appears only inside a documentation example comment in `internal/scheduler/doc.go:15`, not as an actual registered job.

So there is neither a cron scheduler running nor a nightly cleanup job scheduled at any time.
