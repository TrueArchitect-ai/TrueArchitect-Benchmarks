**Computation site:** `RebuildMemoPayload` at `server/runner/memopayload/runner.go:74`, which calls the markdown service's `ExtractAll` (`internal/markdown/markdown.go:356`) to parse the memo's content and writes the results into `memo.Payload.Tags` and `memo.Payload.Property` (a `storepb.MemoPayload`). The extraction logic itself lives in `ExtractAll` (`internal/markdown/markdown.go:356-420`), which does a single goldmark AST walk.

**Triggers (recomputation happens on content changes):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (always, when a memo is created).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the `content` update-mask branch, i.e. when the memo's content actually changes.
- (A bulk-rebuild path also exists in `memopayload.Runner.RunOnce`/`Run` at `runner.go:52`, which re-derives payloads for all memos in batches — but as noted, that `Runner` isn't wired into production startup.)

**Extracted (derived) properties** (`internal/markdown/markdown.go:378-419`, stored on `MemoPayload`):
- `Tags` — deduplicated list of `#tags` found in the content.
- `Property.Title` — text of the document's first block if it's an H1 heading.
- `Property.HasLink` — true if any link node is present.
- `Property.HasCode` — true if any code block / fenced code / inline code span is present.
- `Property.HasTaskList` — true if any task-list checkbox is present.
- `Property.HasIncompleteTasks` — true if any task checkbox is unchecked.

(`ExtractAll` also collects `@mentions` into `ExtractedData.Mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property` onto the memo — mentions are used elsewhere, e.g. notifications.)
