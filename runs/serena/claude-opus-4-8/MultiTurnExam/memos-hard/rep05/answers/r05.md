**Premise correction:** There is no GraphQL schema in this project — the public API is not GraphQL. A search for `graphql`/`gqlgen`/`.graphql` across the sources returns nothing, so there is no schema file to point to. The premise is false.

**Actual API surface:** The public API is defined with **Protocol Buffers** and served over **gRPC / Connect + a gRPC-gateway REST bridge**:
- The API contract lives in `.proto` files under `proto/api/v1/` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus `common.proto`. Generated Go/TypeScript bindings are under `proto/gen/` (and `web/src/types/proto/`).
- These services are wired up in `server/router/api/v1/v1.go`: Connect handlers are registered via `connectHandler.RegisterConnectHandlers(...)` (`v1.go:141`), and an HTTP/JSON REST surface is exposed through the grpc-gateway `runtime.NewServeMux` (`v1.go:96`, using `github.com/grpc-ecosystem/grpc-gateway/v2/runtime`). Connect/gRPC support comes from `connectrpc.com/connect` (`v1.go:7`).

So the "schema" for the public API is the set of `.proto` definitions in `proto/api/v1/`, consumed via gRPC/Connect and a RESTful gRPC-gateway — not GraphQL.
