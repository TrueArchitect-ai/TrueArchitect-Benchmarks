**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — so there is nothing to register and no request limits to report. The premise is false.

Evidence:
- The API (Connect/gRPC) request pipeline is assembled in `server/router/api/v1/v1.go:133-137`, and its interceptor chain contains only: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (`connect_interceptors.go`). None of these performs rate limiting or throttling.
- The Echo middleware registered on the server (`server/router/frontend/frontend.go:54-59`) is static-file serving and SPA fallback — no rate limiter.
- A repo-wide search for `rate limit` / `ratelimit` / `throttle` / `limiter` / `quota` / `429` / `too many requests` across the Go sources yields no rate-limiting implementation. The only match is an aspirational comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which describes a possible future feature, not implemented code, and concerns outbound email rather than inbound API requests.
- No rate-limiting library (e.g. `golang.org/x/time/rate`, `tollbooth`) is imported anywhere.

If you need this, it would have to be added — e.g. as an additional Connect interceptor in the chain at `server/router/api/v1/v1.go:133`.
