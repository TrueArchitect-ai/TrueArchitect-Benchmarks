**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` in the Go sources returns nothing — the cache layer is not backed by Redis (or any external cache server). So there is no "Redis connection" to configure.

**Actual mechanism:** The cache is a thread-safe, in-process, in-memory cache implemented in `store/cache/cache.go` (`Cache` struct backed by a `sync.Map`, with TTL expiry and a background cleanup goroutine). The `Store` creates three of these — including the user cache — in `store.New` at `store/store.go:38-53`, all built with the same `cache.Config`:

```
DefaultTTL:      10 * time.Minute
CleanupInterval: 5 * time.Minute
MaxItems:        1000
```
(`store/store.go:40-45`; identical to `cache.DefaultConfig()` at `store/cache/cache.go:56`.)

**TTL for user entries:** 10 minutes. User records are cached via `s.userCache.Set(...)` (`store/user.go:98, 122, 132, 143, 167`), and `Cache.Set` applies the configured `DefaultTTL` (`store/cache/cache.go:93-94` → `SetWithTTL(..., c.config.DefaultTTL)`), which is `10 * time.Minute`. Expired entries are lazily skipped on `Get` and swept every 5 minutes by the cleanup interval. There's no per-user custom TTL override.
