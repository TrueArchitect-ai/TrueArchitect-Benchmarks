**Delivery function: `Post` — `internal/webhook/webhook.go` (the actual outbound `safeClient.Do(req)` call at `webhook.go:158`; invoked synchronously by `Post` and via the async worker pool feeding from `PostAsync`).**

**Protection mechanism: `safeDialContext` (installed as the `DialContext` on the shared `safeClient` transport) — `internal/webhook/webhook.go:57`, backed by `isReservedIP` / `reservedCIDRs` in `internal/webhook/validate.go`.**

How it works:
- Outbound delivery executes in `Post` (`internal/webhook/webhook.go:119`), which builds the request, optionally HMAC-signs it, and fires it with the shared `safeClient` (`webhook.go:158`). `PostAsync` just enqueues onto a bounded channel drained by four goroutines that also call `Post` (`webhook.go:41-53`, `176`).
- SSRF protection is enforced at dial time: `safeClient`'s `Transport.DialContext` is `safeDialContext` (`webhook.go:31-36`, `57`). It resolves the target host and rejects the connection if any resolved IP is in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`), which checks against `reservedCIDRs` — loopback, RFC-1918, IPv6 ULA/link-local, and the cloud IMDS range `169.254.0.0/16` (`validate.go:14-22`). Because the check happens at dial time on the resolved IP, it also defeats DNS-rebinding. There's additionally an up-front `ValidateURL` check (`validate.go:64`) when webhooks are configured, and an `AllowPrivateIPs` escape hatch (`validate.go:40`) that disables the guard for LAN-targeted self-hosted setups.
