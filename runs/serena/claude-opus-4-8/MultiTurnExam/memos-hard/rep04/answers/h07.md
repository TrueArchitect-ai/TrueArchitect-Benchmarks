A browser requests another user's profile image at `GET /file/users/:identifier/avatar`. The hops from handler to stored data:

route registration `fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)` — server/router/fileserver/fileserver.go:124
serveUserAvatar (serving handler) — server/router/fileserver/fileserver.go:168
getUserByUsername — server/router/fileserver/fileserver.go:715
Store.GetUser — store/user.go:148
Store.ListUsers — store/user.go:136
driver.ListUsers (Driver interface) — store/driver.go
DB.ListUsers (concrete SQL query on the `user` table, incl. `avatar_url`) — store/db/sqlite/user.go:88 (also store/db/postgres/user.go:87, store/db/mysql/user.go:84)

The avatar bytes themselves live in the `user` row's `avatar_url` column as a base64 data URI; back in the handler `serveUserAvatar` decodes it via `parseDataURI` (server/router/fileserver/fileserver.go:196, 737) and writes the blob to the response (fileserver.go:209).
