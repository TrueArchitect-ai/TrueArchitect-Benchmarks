**Premise correction:** There is no Redis connection anywhere in this codebase — a repo-wide search for `redis` in Go source returns nothing. The cache layer is not backed by Redis; it is a custom, process-local **in-memory** cache (`store/cache/cache.go`, `type Cache is a thread-safe in-memory cache with TTL`, store/cache/cache.go:66-67). Nothing is "configured" to connect to an external cache server.

**Actual mechanism:** The store creates three in-memory caches in `store.New` using one shared `cache.Config` (store/store.go:40-53): `instanceSettingCache`, `userCache`, and `userSettingCache`, each via `cache.New(cacheConfig)`. That config sets `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (store/store.go:40-45).

User entries live in `userCache` and are written with the plain `Set` method (store/user.go:98, 122, 132, 143, 167), which applies the cache's default TTL (`Set` → `SetWithTTL(..., c.config.DefaultTTL)`, store/cache/cache.go:93-94). So **user entries expire 10 minutes after they are cached** (the `cache.DefaultConfig()` also defaults to 10 minutes, store/cache/cache.go:57-59). Expired entries are reclaimed by a background cleanup loop running every 5 minutes (store/cache/cache.go:200-218), and the cache is capped at 1000 items with oldest-eviction.
