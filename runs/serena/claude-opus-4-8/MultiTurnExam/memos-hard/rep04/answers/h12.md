With a default install and no `--driver` flag, the database driver defaults to **sqlite**, so the concrete code that runs the memo INSERT is:

**Concrete method: `(*sqlite.DB).CreateMemo` — store/db/sqlite/memo.go:16**, which builds and executes `INSERT INTO \`memo\` (...) VALUES (...) RETURNING ...` at store/db/sqlite/memo.go:41-42.

How I determined which of the three candidates (`sqlite`, `postgres`, `mysql` each declare `DB.CreateMemo`) actually runs:

1. Driver selection is a runtime switch on `profile.Driver` in the factory `NewDBDriver` — `store/db/db.go:14-27` (`case "sqlite": sqlite.NewDB(profile)`, etc.).
2. The default value of that field with no flags is `"sqlite"`, set two ways in `cmd/memos/main.go`: `viper.SetDefault("driver", "sqlite")` (cmd/memos/main.go:122) and the persistent flag default `rootCmd.PersistentFlags().String("driver", "sqlite", ...)` (cmd/memos/main.go:130); the profile reads it via `viper.GetString("driver")` (cmd/memos/main.go:43).
3. Therefore `NewDBDriver` constructs the sqlite driver, and the store-level `Store.CreateMemo` delegates to `s.driver.CreateMemo` (the `Driver` interface, store/driver.go), which resolves to the sqlite implementation above. The postgres (`store/db/postgres/memo.go`) and mysql (`store/db/mysql/memo.go`) `CreateMemo` methods exist but are never reached without an explicit non-default `--driver`.
