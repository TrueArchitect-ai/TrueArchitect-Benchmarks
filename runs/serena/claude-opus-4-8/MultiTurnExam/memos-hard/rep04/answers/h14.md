The derived metadata is the memo's **`Payload`** (its `Tags` list and `Property` flags), computed from the memo content by parsing markdown — not set by the user.

**Computation site** — `RebuildMemoPayload` at server/runner/memopayload/runner.go:74, which runs the content through the markdown service in a single pass: `markdownService.ExtractAll([]byte(memo.Content))` (runner.go:80) and assigns `memo.Payload.Tags` and `memo.Payload.Property` (runner.go:85-86). The actual extraction lives in the markdown implementation `service.ExtractAll` (internal/markdown/markdown.go, property flags set around internal/markdown/markdown.go:394-403).

**Triggers (recomputation)** — the two mutating RPC handlers call it in production:
- `CreateMemo` — server/router/api/v1/memo_service.go:108 (`memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)`).
- `UpdateMemo` — server/router/api/v1/memo_service.go:447 (on content change).

There is also a batch `memopayload.Runner.RunOnce` that rebuilds all memos' payloads (server/runner/memopayload/runner.go:27, calling `RebuildMemoPayload` at :52), but that runner is not wired into server startup, so at runtime recomputation is driven by create/update.

**Extracted properties** — `ExtractAll` returns `ExtractedData{Tags, Mentions, Property}` (internal/markdown/markdown.go:20-25), and `RebuildMemoPayload` persists two of them into the payload:
- `Tags` — the list of `#tags` in the content.
- `Property` (`storepb.MemoPayload_Property`, proto/gen/store/memo.pb.go:85) with booleans: `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks` (set in internal/markdown/markdown.go:394-403).

(`Mentions` is also extracted by `ExtractAll` but is not stored into the payload here.)
