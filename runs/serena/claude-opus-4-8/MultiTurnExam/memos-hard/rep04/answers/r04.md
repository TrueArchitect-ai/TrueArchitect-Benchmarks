**Premise correction:** Neither. There is no external message broker in this codebase — no NATS, no RabbitMQ (and no AMQP/Kafka either). A repo-wide search of Go source and `go.mod` for `nats`, `rabbitmq`, `amqp`, `kafka` returns nothing. The webhook "workers" do not consume from any broker.

**Actual mechanism:** Webhook delivery is fully in-process, using a **buffered Go channel** as the queue. In `internal/webhook/webhook.go`:
- The queue is a package-level buffered channel declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (capacity 128).
- A package `init()` starts **4 worker goroutines** that range over that channel and call `Post` for each payload (`internal/webhook/webhook.go:42-55`).
- Producers enqueue via `PostAsync`, which does a non-blocking send onto the channel and drops the payload (with a warning) if the buffer is full (`internal/webhook/webhook.go:184-196`).

So the "broker" is an in-memory channel local to the process; nothing is declared on or consumed from NATS or RabbitMQ.
