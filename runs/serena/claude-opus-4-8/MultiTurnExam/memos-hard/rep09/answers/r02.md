**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — so there is nothing to register and no request limits to report. A repo-wide search for rate limiting (`rate.limit`, `ratelimit`, `throttle`, `golang.org/x/time/rate`, `Limiter`, `tollbooth`, etc.) in the Go source returns zero matches.

The server's actual middleware/interceptor stack contains no rate limiter:
- Echo HTTP middleware: `middleware.Recover()` and `newCORSMiddleware` — `server/server.go:51-52`; plus static-file and SPA-fallback middleware for the frontend — `server/router/frontend/frontend.go:54,59`.
- Connect/gRPC interceptors: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — `server/router/api/v1/v1.go:133-138` (plus a gRPC-Gateway auth middleware at `v1.go:69,97`).

The closest thing to a request bound is a per-request **payload size** cap, `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141` — but that limits body size, not request rate, and is not per-user. No component enforces a per-user request-per-time-window limit anywhere in the server.
