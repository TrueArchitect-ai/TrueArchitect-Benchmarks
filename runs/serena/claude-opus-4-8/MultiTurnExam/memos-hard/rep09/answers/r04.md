**Premise correction:** Neither — there is no external message broker. A repo-wide search finds no NATS, RabbitMQ/AMQP, Kafka, or any broker client in the Go code. The webhook workers do not consume from a broker at all.

**Actual mechanism:** Delivery is handled entirely in-process via a buffered Go channel plus a fixed goroutine pool, all in `internal/webhook/webhook.go`:
- The "queue" is a package-level buffered channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39` (capacity 128).
- Four worker goroutines are spawned in the package `init()` (`for range 4 { go func() { for payload := range asyncPostQueue { ... Post(payload) } }() }`) — `internal/webhook/webhook.go:42-55`. They range over the channel and call `Post` to perform the outbound HTTP POST (`webhook.go:120`, sent via `safeClient.Do` at `:152`).
- Enqueue is `PostAsync`, which does a non-blocking send: `case asyncPostQueue <- requestPayload:` with a `default:` that drops the event if the buffer is full — `internal/webhook/webhook.go:184-190`.

So the "queue" is an in-memory Go channel declared at `internal/webhook/webhook.go:39`, not a broker-managed queue, and it is process-local (not durable, not shared across instances).
