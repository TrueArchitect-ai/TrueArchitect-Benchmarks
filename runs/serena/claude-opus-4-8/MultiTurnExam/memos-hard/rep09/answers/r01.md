**Premise correction:** There is no Redis anywhere in the cache layer — a repo-wide search for "redis" in Go code returns nothing. The cache is not backed by Redis (or any external store), so there is no Redis connection to configure.

**Actual mechanism:** The cache is a thread-safe **in-memory** cache built on `sync.Map`, defined in `store/cache/cache.go` (type `Cache`, `data sync.Map` at `store/cache/cache.go:69`; entries carry an `expiration` timestamp, expired lazily on read and swept by a background `cleanupLoop`).

- **Where it's configured:** in `store/store.go:40-53`. `NewStore` builds one `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute}` (`store/store.go:41-42`) and creates three in-process caches from it — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`) — each via `cache.New(cacheConfig)`. (The config default `DefaultTTL = 10 * time.Minute` also appears in the cache package's own default at `store/cache/cache.go:59`.)

- **TTL for user entries:** **10 minutes.** User rows are cached with `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`), and `Set` applies the configured `DefaultTTL` (`store/cache/cache.go:92-94`), which the store sets to `10 * time.Minute`. No per-user `SetWithTTL` override is used, so user entries expire 10 minutes after being cached, with a background cleanup sweep every 5 minutes.
