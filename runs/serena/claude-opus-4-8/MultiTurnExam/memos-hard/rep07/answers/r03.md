Evidence:
- A generic cron `scheduler` package exists at `internal/scheduler/` (with `ParseCronExpression`, `Job.Schedule`, etc.), but it is **never used in production** — searching the whole repo, the only callers of `scheduler.New`/`scheduler.*` are in the package's own tests and doc comments (`internal/scheduler/example_test.go`, `integration_test.go`, `doc.go`). No server startup code registers any job with it. The cron-string comments like `"0 0 * * *" (daily at midnight)` at `internal/scheduler/job.go:21-22` are just documentation examples, not a scheduled job.
- The only actual background jobs wired into server startup are runners driven by `time.Ticker`, not the cron scheduler, and none of them is a nightly DB cleanup:

So: no cron-scheduled nightly cleanup exists — the premise's job and its "time" don't exist. The nearest real scheduled maintenance is the 12-hour S3 presign refresh runner.
