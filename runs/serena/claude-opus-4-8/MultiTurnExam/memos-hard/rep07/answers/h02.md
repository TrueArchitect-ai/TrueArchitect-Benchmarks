**Delivery function** — `Post` in `internal/webhook/webhook.go:120` is where the outbound HTTP request actually executes: it marshals the payload, builds the `POST` request (optionally adding HMAC-SHA256 Standard-Webhooks signature headers), and fires it via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. Dispatch is normally driven asynchronously through `PostAsync` → a bounded queue whose worker goroutines call `Post` (`internal/webhook/webhook.go:42-55`, `184-196`).

**Protection mechanism** — SSRF protection is enforced at *dial time* by `safeDialContext`, installed as the `DialContext` of the shared `safeClient`'s transport (`internal/webhook/webhook.go:32-37`, `59-77`). Before connecting, it resolves the target host and rejects any address in a reserved/private range via `isReservedIP`, which checks the parsed `reservedCIDRs`/`reservedNetworks` list (loopback, RFC-1918, link-local/IMDS `169.254.0.0/16`, and IPv6 equivalents) in `internal/webhook/validate.go:14-54`. Because the check happens at dial time against the freshly-resolved IP, it also defeats DNS-rebinding. There's an additional up-front check, `ValidateURL` (`internal/webhook/validate.go:62-83`), run when a webhook URL is configured. Both can be bypassed by the `AllowPrivateIPs` opt-out flag (`internal/webhook/validate.go:41-47`).

So:
- delivery function — `Post` (`internal/webhook/webhook.go:120`, actual send at `:152`)
- protection mechanism — `safeDialContext` dial-time reserved-IP block via `isReservedIP` (`internal/webhook/webhook.go:59-77`; ranges/logic in `internal/webhook/validate.go:14-54`), plus config-time `ValidateURL` (`internal/webhook/validate.go:62-83`)
