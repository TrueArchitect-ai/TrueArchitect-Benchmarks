**Premise correction:** There is no Redis anywhere in the cache layer — the repo has zero Redis references in Go code. The cache is not backed by an external store and has no "connection" to configure.

**Actual mechanism:** The cache layer is a thread-safe, in-process, in-memory cache built on `sync.Map` — `store/cache/cache.go` (type `Cache` at `store/cache/cache.go:65`, backed by a `sync.Map` and a background `cleanupLoop`). It is not configured with a connection string; it's instantiated directly in `store.New` with a `cache.Config` literal (`store/store.go:40-46`), which creates three separate in-memory caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`).

**TTL for user entries:** User entries go into `userCache`, whose writes use `Set` (e.g. `store/user.go:98,122,132,143,167`). `Set` applies the cache's default TTL (`store/cache/cache.go:12`), and that default is **10 minutes** — configured via `DefaultTTL: 10 * time.Minute` in the `cacheConfig` passed to `cache.New` in `store.New` (`store/store.go:41`). The same value is the library default in `cache.DefaultConfig()` (`store/cache/cache.go:57`). Entries are also bounded by `MaxItems: 1000` and swept by a `CleanupInterval` of 5 minutes.
