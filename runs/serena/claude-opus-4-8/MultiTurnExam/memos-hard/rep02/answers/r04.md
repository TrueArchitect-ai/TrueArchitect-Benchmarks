**Premise correction:** Neither. The webhook delivery workers do not consume from a message broker at all — there is no NATS, RabbitMQ, AMQP, Kafka, or any broker in the codebase (no such imports in the Go source and nothing in `go.mod`). So there is no externally-declared queue.

**Actual mechanism:** Webhook delivery is entirely in-process. The "queue" is a buffered Go channel declared in the webhook package:
- `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:37` (capacity 128).
- A `package init()` starts 4 background goroutine workers that range over that channel and call `Post` for each payload — `internal/webhook/webhook.go:40-53`.
- Producers enqueue via `PostAsync`, a non-blocking send onto the channel that drops the payload (with a warning log) if the buffer is full — `internal/webhook/webhook.go:184`.
- Each worker's `Post` performs the actual outbound HTTP delivery via the SSRF-guarded `safeClient` — `internal/webhook/webhook.go:120` (send at `:152`).

So the whole path is a bounded in-memory channel with a fixed pool of goroutine consumers, not a broker-backed queue.
