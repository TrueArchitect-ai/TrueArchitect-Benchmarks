**Premise correction: there is no per-user API rate-limiting middleware in this codebase — it does not exist, so there is nothing to register and no request limits to report.**

Evidence:

- A repo-wide search for rate-limiting terms (`rate limit`, `ratelimit`, `Limiter`, `throttle`, `tollbooth`, `golang.org/x/time/rate`, `StatusTooManyRequests`, `429`, "too many requests", "requests per") in non-test Go code returns nothing.
- `go.mod` pulls in no rate-limiting / throttling dependency (no `golang.org/x/time/rate`, `tollbooth`, etc.).
- The Connect/gRPC interceptor chain that wraps every API request is assembled in `server/router/api/v1/v1.go:133-137` and consists of exactly four interceptors — `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go` and `authz.go`). None of them enforces rate limits; they handle header/metadata translation, logging, panic recovery, and authentication/authorization respectively.

So the middleware described in the question isn't present anywhere in the server; there is no per-user request limit configured.
