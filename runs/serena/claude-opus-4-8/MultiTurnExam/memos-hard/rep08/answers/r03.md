**Premise correction: there is no nightly database-cleanup job (and the cron scheduler is never wired into the running server), so there is no scheduled run time to report.**

Evidence:

- A generic cron scheduler package does exist at `internal/scheduler/` (`scheduler.go`, `job.go`, `parser.go`, etc.), but it is **not used anywhere outside its own package** — grepping for `internal/scheduler`, `scheduler.New`, `AddJob`, `RegisterJob`, etc. across the rest of the codebase (`server/`, `cmd/`) returns nothing. It's a self-contained, currently-unused library with only its own tests/examples.
- The only occurrences of a "cleanup" cron job are illustrative comments/examples, not registered jobs: `internal/scheduler/doc.go:15-18` shows a hypothetical `"daily-cleanup"` job, and `internal/scheduler/job.go:21` gives `"0 0 * * *"` merely as an example of a "daily at midnight" expression in a doc comment. Neither registers a real job.
- No database-cleanup handler is defined or scheduled anywhere. The server's actual background work is the S3-presign runner (`server/runner/s3presign`, every 12 hours) wired in `server/server.go`, which is a plain `time.Ticker`, not the cron scheduler, and does no database cleanup.

So the described nightly DB-cleanup cron job does not exist in this repository.
