**Premise correction:** There is no Redis. The cache layer is **not** backed by Redis — a repo-wide search for "redis" in Go code returns nothing. The cache is a self-contained, in-process, in-memory implementation defined in `store/cache/cache.go` (a `Cache` type with a background cleanup goroutine, keyed map + TTL per item). So there is no Redis connection to configure anywhere.

**Actual mechanism:** The `Store` holds three in-memory caches — `instanceSettingCache`, `userCache`, `userSettingCache` — all constructed in `store.New` (`store/store.go:38-54`) from a single `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
...
userCache: cache.New(cacheConfig),
```

So the **TTL applying to user entries is 10 minutes** (`DefaultTTL: 10 * time.Minute`, `store/store.go:41`), with expired entries swept every 5 minutes (`CleanupInterval`). `Store.GetUser`/`ListUsers` populate `userCache` via `Set`, which uses this default TTL (`store/user.go`; `store/cache/cache.go` `Set` → default TTL). The same 10-minute default is also defined in `cache.DefaultConfig()` (`store/cache/cache.go`), though `store.New` supplies its own equivalent config literal rather than calling `DefaultConfig()`.
