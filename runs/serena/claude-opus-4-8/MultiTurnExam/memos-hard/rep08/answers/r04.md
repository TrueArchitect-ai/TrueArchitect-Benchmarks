**Premise correction: neither. The webhook delivery workers do not consume from any message broker — there is no NATS, RabbitMQ, AMQP, or Kafka in this codebase.** A repo-wide search of the Go sources and `go.mod` for `nats`, `rabbitmq`, `amqp`, `kafka`, `broker`, etc. returns nothing.

**Actual mechanism:** Webhook dispatch is entirely in-process, using a bounded Go channel — not an external queue. In `internal/webhook/webhook.go`:

- The "queue" is a package-level buffered channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`.
- A `func init()` starts **4 worker goroutines**, each ranging over `asyncPostQueue` and calling `Post` (the function that performs the actual outbound HTTP request via `safeClient.Do`).
- Producers enqueue with `PostAsync`, which does a non-blocking send onto `asyncPostQueue` (dropping the event with a warning if the buffer of 128 is full).

So the "workers" are goroutines draining an in-memory channel declared at `internal/webhook/webhook.go` (the `asyncPostQueue` var), with no broker and no externally declared queue.
