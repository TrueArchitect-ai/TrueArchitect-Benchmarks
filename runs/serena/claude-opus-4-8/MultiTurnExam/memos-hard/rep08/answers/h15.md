Distinct server surfaces that enforce memo visibility for viewing:

- **`GetMemo` — single-memo API read guard** — `server/router/api/v1/memo_service.go:55-64` (non-public requires auth; `Private` → only creator, else `PermissionDenied`).
- **`ListMemos` — API listing visibility filter** — `server/router/api/v1/memo_service.go:219-225` (anonymous → `PUBLIC` only; authed → `creator_id == me || visibility in ["PUBLIC","PROTECTED"]`).
- **Memo-relation / stats listing filter** — `server/router/api/v1/memo_service_converter.go:184-186` and `server/router/api/v1/user_service_stats.go:84-90,218-220` (same visibility filter applied when resolving related memos and stats).
- **Comments listing** — `server/router/api/v1/memo_service_comments.go:41` (view-guard on the related memo) and `:158-160` (visibility filter for listing comments).
- **RSS feed** — `server/router/rss/rss.go:90,141` (restricts to `store.Public` only).
- **Frontend SSR / metadata (OG tags)** — `server/router/frontend/frontend.go:150` (restricts to `store.Public`).
- **File server (attachment blobs)** — `server/router/fileserver/fileserver.go:677,699` (serves attachment only if parent memo visibility permits; `Private` → creator/admin only).
- **Attachment API service** — `server/router/api/v1/attachment_service.go:445-451` and `server/router/api/v1/memo_attachment_service.go:214-222` (visibility gate before returning attachment data).
- **Reaction service** — `server/router/api/v1/reaction_service.go:30-38,83` (visibility gate on the memo before listing/upserting reactions).
- **SSE realtime delivery filtering** — `server/router/api/v1/sse_hub.go:135-141` (`canReceive`: `Private` events delivered only to creator or admin).

(At minimum the three clearest read surfaces are `GetMemo` — `server/router/api/v1/memo_service.go`, the RSS feed — `server/router/rss/rss.go`, and the file/attachment server — `server/router/fileserver/fileserver.go`.)
