Memo visibility (`PUBLIC` / `PROTECTED` / `PRIVATE`) is enforced across these distinct server surfaces:

- Memo API — single-memo read access check (`GetMemo`/`checkMemoReadAccess`): rejects non-public memos for non-owners/anonymous — server/router/api/v1/memo_service.go:55–65
- Memo API — list query visibility filter (`ListMemos`): anonymous → `PUBLIC` only; authenticated → own memos or `PUBLIC`/`PROTECTED` — server/router/api/v1/memo_service.go:219–228
- RSS feed service — restricts feed to `PUBLIC` memos — server/router/rss/rss.go:90, server/router/rss/rss.go:141
- Frontend SSR / sitemap — restricts to `PUBLIC` memos — server/router/frontend/frontend.go:150
- File server — serving attachment blobs gated by the linked memo's visibility — server/router/fileserver/fileserver.go:677 and server/router/fileserver/fileserver.go:699
- Attachment API service — attachment access follows linked memo visibility — server/router/api/v1/attachment_service.go:445–451
- SSE hub — real-time event delivery filtered per client by memo visibility (`SSEClient.canReceive`) — server/router/api/v1/sse_hub.go:135
- Reaction service — blocks reacting to / reading reactions on memos the user can't view — server/router/api/v1/reaction_service.go:30,38 and server/router/api/v1/reaction_service.go:83
