**Premise correction:** There is no per-user API rate-limiting middleware in this repository, so there is nothing to register and no request limits to report.

Evidence:
- The Connect/gRPC API registers exactly four interceptors, none of which does rate limiting: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — wired at `server/router/api/v1/v1.go:133–137` (defined in `server/router/api/v1/connect_interceptors.go`).
- A repo-wide search for rate-limiting constructs (`rate limit`, `ratelimit`, `throttle`, `limiter`, `golang.org/x/time/rate`, `StatusTooManyRequests`/429) turns up no implementation — the only hit is an aspirational comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which is documentation, not code.

The closest thing to per-user request control is the `AuthInterceptor` (authentication/authorization, `server/router/api/v1/connect_interceptors.go:208`) plus a request *size* cap (`connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`) — neither of which limits request *rate/count* per user.
