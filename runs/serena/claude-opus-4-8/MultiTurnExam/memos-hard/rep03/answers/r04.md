**Premise correction:** Neither. The webhook delivery workers do not consume from any external message broker — there is no NATS, RabbitMQ, AMQP, or Kafka in the codebase (a repo-wide search for `nats`/`rabbitmq`/`amqp`/`kafka`/`broker` finds nothing in Go source). So there is no broker "queue" declared anywhere.

**Actual mechanism:** The "queue" is a plain in-process, buffered Go channel local to the webhook package:
- Declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39` (buffer of 128).
- An `init()` starts **4 worker goroutines**, each ranging over that channel and calling `Post` to deliver — `internal/webhook/webhook.go:42–54`.
- Producers enqueue via `PostAsync`, a non-blocking `select` send that **drops** the payload (logs a warning) if the buffer is full — `internal/webhook/webhook.go:184–199`.

Everything lives inside a single server process; there is no broker, no durable queue, and no cross-process consumption. If the process restarts, any in-buffer webhooks are lost.
