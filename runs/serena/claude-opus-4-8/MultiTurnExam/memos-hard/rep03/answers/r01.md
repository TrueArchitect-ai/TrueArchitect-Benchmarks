**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` in Go source returns nothing — the cache layer is **not** backed by Redis and there is no Redis connection to configure. The cache is a process-local, in-memory implementation.

**Actual mechanism:**
- The cache is defined in `store/cache/cache.go` — an in-memory `Cache` (a `map` of `item{value, expiration, size}` guarded by a mutex, with a background cleanup goroutine). Its `Interface` (`store/cache/cache.go:11`) exposes `Set`/`SetWithTTL`/`Get`/etc.; construction is `cache.New(config)` (`store/cache/cache.go:76`). No network/connection config exists — nothing to point at a server.
- The user cache is one of three in-memory caches created in `Store.New` (`store/store.go:52`, `userCache`). All three are built from a single `cacheConfig` with `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:40–45`).
- User entries are inserted via plain `s.userCache.Set(...)` (e.g. in `Store.GetUser`/`Store.ListUsers` in `store/user.go`), which uses the **default TTL**. So a cached user entry lives for **10 minutes** (evicted earlier if the 1000-item cap is hit, and swept by the 5-minute cleanup pass once expired).
