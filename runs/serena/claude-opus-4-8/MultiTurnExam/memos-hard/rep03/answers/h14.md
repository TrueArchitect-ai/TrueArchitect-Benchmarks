**Triggers (recomputation)** — the derived metadata is recomputed from content whenever content is created or changed:
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`
- `UpdateMemo`, on the `content` field update — `server/router/api/v1/memo_service.go:447` (right after `memo.Content = request.Memo.Content`)
- Bulk backfill: `memopayload.Runner.RunOnce` re-derives it for all memos in batches (`server/runner/memopayload/runner.go:52`), though that runner isn't wired into production startup — the live triggers are the two RPCs above.

**Extracted properties** — from `ExtractAll` (`internal/markdown/markdown.go:362–408`), stored into the payload:
- `Tags` — deduplicated `#tag` values (case preserved) — `runner.go:85`
- `Property` (`storepb.MemoPayload_Property`) — `runner.go:86`:
  - `Title` — text of a leading H1 heading (`markdown.go:387`)
  - `HasLink` — content contains a link (`:394`)
  - `HasCode` — contains a code block/fenced code/inline code span (`:397`)
  - `HasTaskList` — contains a task checkbox (`:400`)
  - `HasIncompleteTasks` — has at least one unchecked task (`:403`)

(`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property`; mentions are used separately for notifications.)
