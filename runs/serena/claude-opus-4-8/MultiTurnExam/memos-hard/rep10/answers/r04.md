**Premise correction:** Neither. There is no external message broker at all — no NATS, no RabbitMQ (nor AMQP). A repo-wide search finds no `nats`/`rabbitmq`/`amqp`/`streadway` references in any `.go` file and no such dependency in `go.mod`. So there is no broker to consume from and no queue "declared" in a broker.

**Actual mechanism:** Webhook delivery is dispatched through an **in-process buffered Go channel**, defined in `internal/webhook/webhook.go`:
- The queue is a package-level channel `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39` (capacity 128, in-memory only).
- Four worker goroutines are started in `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post(payload)` (line 46) to perform the actual HTTP delivery.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking `select` send onto `asyncPostQueue` and **drops the event if the buffer is full** (line 191-195) — behavior specific to an in-memory channel, not a durable broker.

Because the queue lives entirely in process memory, it is not persistent and not shared across instances.
