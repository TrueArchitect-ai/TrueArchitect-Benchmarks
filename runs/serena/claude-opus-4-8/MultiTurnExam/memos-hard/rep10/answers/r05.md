**Premise correction:** There is no GraphQL schema in this project. A repo-wide search finds no GraphQL references at all — no `graphql`/`gqlgen` imports in any `.go` file, no `.graphql`/`schema.graphql` files, and no such dependency in `go.mod`. So there is no GraphQL public API to define.

**Actual API surface:** The public API is defined with **Protocol Buffers (gRPC)**, exposed over both the Connect protocol and a REST/JSON gRPC-Gateway:
- Schema (source of truth) lives in `.proto` files under `proto/api/v1/` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `ai_service.proto`, `idp_service.proto`, `shortcut_service.proto`, plus `common.proto`.
- Generated Go bindings are in `proto/gen/api/v1/` — gRPC-Gateway REST stubs (`*_service.pb.gw.go`) and Connect handlers (`proto/gen/api/v1/apiv1connect/`).
- The server wires these up in `server/router/api/v1/`: `ConnectServiceHandler` (`connect_handler.go:21`) adapts the `APIV1Service` implementations to serve both native gRPC/Connect and, via `RegisterGateway`, REST/JSON (`server/router/api/v1/v1.go:65`). Access-control per RPC procedure is configured in `acl_config.go`.

So the API is proto/gRPC + Connect + gRPC-Gateway, not GraphQL.
