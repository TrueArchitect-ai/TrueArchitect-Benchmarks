**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`. It calls `markdownService.ExtractAll([]byte(memo.Content))` (the goldmark `service.ExtractAll` at `internal/markdown/markdown.go:356`) and writes the results into `memo.Payload.Tags` and `memo.Payload.Property` (`runner.go:85-86`). This derived data lives in the memo's `Payload` (stored as JSON), separate from user-set fields.

**Triggers (recomputation):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (recomputed on every create).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the branch that actually changes `content` (i.e. when the `content` field mask updates `memo.Content`; see `memo_service.go:446-448`). Metadata-only updates don't recompute.
- Bulk backfill via `memopayload.Runner` (`server/runner/memopayload/runner.go:52`, iterating all memos) — this path exists but the `Runner` is not wired into production startup, so in practice only Create/Update trigger it.

**Extracted properties** (via `ExtractAll`, walking the parsed markdown AST once):
- `Tags` — all `#tags` in the content (`internal/markdown/markdown.go:378`).
- `Property.Title` — text of a leading level-1 (`# `) heading, if the first block is an H1 (`markdown.go:387`).
- `Property.HasLink` — content contains a link (`markdown.go:394`).
- `Property.HasCode` — content contains a code block/fenced code/inline code span (`markdown.go:397`).
- `Property.HasTaskList` — content contains a task checkbox (`markdown.go:400`).
- `Property.HasIncompleteTasks` — content contains an unchecked task item (`markdown.go:403`).

(The `Property` shape is defined by `storepb.MemoPayload_Property` in `proto/gen/store/memo.pb.go:85`. Note `ExtractAll` also gathers `Mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property`.)
