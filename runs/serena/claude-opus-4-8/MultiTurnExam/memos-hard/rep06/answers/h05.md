**Mechanism: explicit Go code.** When a user is deleted, their emoji reactions are removed by explicit `DELETE FROM reaction` statements inside the delete-user transaction — in two ways: reactions the user *authored* (`WHERE creator_id = ?`) and reactions on the user's *content* (`WHERE content_id IN (...)`). This is done identically across all three DB drivers, not via a DB cascade.

Evidence locations:
- **MySQL** — `store/db/mysql/user_delete.go:96` (call `deleteReactionsByContentIDsTx`) and `:102` (call `deleteReactionsByCreatorTx`); implementations at `:417-420` (`DELETE FROM reaction WHERE content_id IN ...`) and `:437-438` (`DELETE FROM reaction WHERE creator_id = ...`).
- **SQLite** — `store/db/sqlite/user_delete.go:96` and `:102`; implementations at `:380-383` and `:400-401`.
- **Postgres** — `store/db/postgres/user_delete.go:96` and `:102`; implementations at `:380-383` and `:400-401`.

All run within the `DeleteUser` transaction (e.g. `store/db/mysql/user_delete.go`, `DeleteUser` → `deleteUserTargetsTx`), so removal is done by application code rather than left to a database-level cascade rule.
