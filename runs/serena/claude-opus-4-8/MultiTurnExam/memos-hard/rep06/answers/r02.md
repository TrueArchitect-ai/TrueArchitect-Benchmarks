**Premise correction: there is no per-user API rate-limiting middleware in this codebase — so there is no registration site and no request limits to report.**

Evidence:
- A repo-wide search of the Go sources for `rate limit` / `ratelimit` / `limiter` / `throttle` / `tollbooth` / `golang.org/x/time/rate` returns nothing. No rate-limiting library is imported and no rate-limiter is implemented.
- The actual API middleware/interceptor chain contains no rate limiter. For the Connect/gRPC API (`server/router/api/v1/v1.go:133-137`) the interceptors are only: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (defined in `server/router/api/v1/connect_interceptors.go` and `authz.go`). The gRPC-Gateway path adds only an auth middleware (`server/router/api/v1/v1.go:69,97`), and the frontend uses only static-file/SPA-fallback middleware (`server/router/frontend/frontend.go:54,59`).
- The only request-size-related guard is a byte cap, not a rate limit: `connect.WithReadMaxBytes(maxAPIRequestBytes)` (`server/router/api/v1/v1.go:141`) — a max request body size, which limits payload size per request, not request frequency per user.

So the closest existing controls are authentication/authorization (`AuthInterceptor`) and a max-request-body-bytes limit; neither is a per-user rate limiter. If per-user rate limiting is required, it would need to be added (e.g., a new Connect interceptor in `server/router/api/v1/connect_interceptors.go` wired into the interceptor list at `v1.go:133`).
