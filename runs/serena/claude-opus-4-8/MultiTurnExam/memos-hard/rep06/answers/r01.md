**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` in Go sources returns nothing — the cache layer is **not** backed by Redis. It's a process-local, in-memory cache implemented in `store/cache/cache.go` (a `*cache.Cache` with a background cleanup goroutine and a `sync`-guarded map). So there is no "Redis connection" to configure — no host/port/DSN, no external store.

**Actual mechanism:**
- The cache type and its `Interface` are defined in `store/cache/cache.go` (in-memory; entries are `item{value, expiration, size}`).
- The Store constructs three of these caches — including the user cache — in `store.New` at `store/store.go:47-53`, all sharing one `cache.Config` built at `store/store.go:40-45`:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
- **TTL for user entries: 10 minutes.** User records are cached via `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`), and `Set` applies the cache's `DefaultTTL` (`store/cache/cache.go` `Set` → default TTL). No `SetWithTTL` override is used for users, so they inherit the 10-minute default TTL (with expired entries reaped every 5 minutes by the cleanup interval). The default TTL constant lives in `store/cache/cache.go` `DefaultConfig` (also `10 * time.Minute`), but the value actually in effect is the one set in `store/store.go:41`.
