memo, memo_relation, attachment

When `DeleteMemo` runs (`store.DeleteMemo` in `store/memo.go:140-159`) it deletes `memo_relation` rows (both `memo_id` and `related_memo_id` directions), then the linked `attachment` rows, then the `memo` row itself. The API handler (`server/router/api/v1/memo_service.go:518`) additionally recurses into comment memos, but that touches the same three tables. Note: `reaction` rows are *not* removed by this path.
