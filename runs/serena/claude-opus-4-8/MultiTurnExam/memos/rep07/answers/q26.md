When `Store.DeleteMemo` (`store/memo.go:140`) runs, the tables affected by explicit code are:

- **memo_relation** — deleted where this memo is the source (`MemoID`) and where it's the target (`RelatedMemoID`)
- **attachment** — each attachment linked to the memo is deleted (via `DeleteAttachment`; also removes underlying file storage, not a DB table)
- **memo** — the memo row itself is deleted last (`driver.DeleteMemo`)

`DeleteAttachment` (`store/attachment.go`) does not cascade to further tables. (Any additional cleanup of tables like `reaction` or `memo_share` would depend on SQL-level FK `ON DELETE CASCADE`, not explicit Go cascade code.)
