**Premise correction:** Neither NATS nor RabbitMQ is used anywhere in this codebase. A repo-wide search for `nats`, `rabbitmq`, and `amqp` (across all `.go` files and `go.mod`) returns zero hits — there's no message-broker dependency at all.

**Actual mechanism:** Webhook delivery is queued in-process using a plain buffered Go channel, not an external broker. `asyncPostQueue := make(chan *WebhookRequestPayload, 128)` is declared in `internal/webhook/webhook.go` (in the package-level `var` block). Four worker goroutines are spawned in that same file's `init()` to range over the channel and call `Post(payload)` for each queued item. RPC handlers enqueue work via `webhook.PostAsync`, which does a non-blocking send (`select`/`default`) onto `asyncPostQueue`, dropping and logging a warning if the buffer of 128 is full (`internal/webhook/webhook.go`). This is entirely in-memory and local to the server process — there is no persistent queue, no broker connection, and nothing survives a process restart.
