**Premise correction:** There is no nightly database-cleanup job scheduled anywhere in this codebase, and no cron scheduler is actually running in production.

The repo does contain a generic cron-style job scheduler package, `internal/scheduler` (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`), which supports cron expressions and job registration via `(*Scheduler).Register`/`Start`. However, a repo-wide search shows it is never imported or instantiated anywhere outside its own package/tests — `grep -rln "internal/scheduler"` outside `internal/scheduler/` returns nothing, and there is no call to `scheduler.New(...)` in `server/` or `cmd/`. It's unused, undocumented-as-wired-up scaffolding, not an active job runner.

The only genuinely-running periodic/background work is:
- `s3presign.Runner`, which re-signs S3 attachment URLs every 12 hours (see h01) — unrelated to "database cleanup."
- The in-memory cache's `CleanupInterval: 5 * time.Minute` (`store/store.go:42`), which evicts expired cache entries, not database rows.
- Ad-hoc, request-triggered cleanup (e.g. attachment/relation deletion inside `DeleteMemo`/`DeleteUser`) — synchronous, not scheduled.

No component in this repository performs a scheduled/nightly database cleanup at any specific time.
