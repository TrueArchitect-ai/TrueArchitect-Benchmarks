**Premise correction:** This codebase does not use Redis at all — a repo-wide search (`grep -rli "redis"` over all `.go` files) turns up zero results. There is no Redis client, connection config, or dependency anywhere in `go.mod`/`go.sum` either.

**Actual mechanism:** The cache layer is an in-process, in-memory cache (`store/cache/cache.go`), backed by a `sync.Map` with TTL-based expiration and a background cleanup goroutine — not an external Redis instance.

- User entries are cached in `userCache *cache.Cache`, a field on `store.Store` (`store/store.go:28`), constructed in `store.New` (`store/store.go:38-60`).
- **TTL:** 10 minutes (`DefaultTTL: 10 * time.Minute`, `store/store.go:41`), with a 5-minute background cleanup interval (`CleanupInterval: 5 * time.Minute`, `store/store.go:42`) and a 1000-item cap (`MaxItems: 1000`, `store/store.go:43`). This same `cacheConfig` is reused for `instanceSettingCache` and `userSettingCache` as well.
- User cache reads/writes happen in `(*Store).GetUser` and `(*Store).ListUsers` (`store/user.go:148-169`, `:136-146`), keyed by `userCacheKey(user.ID)`.
