**Delivery function:** `Post` — `internal/webhook/webhook.go:120-180` (executes the actual outbound call via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`). It's invoked without blocking request handling through `PostAsync` (`internal/webhook/webhook.go:184-196`), which enqueues onto `asyncPostQueue` and is drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`).

**Protection mechanism:** SSRF is blocked at actual dial time by `safeDialContext` — `internal/webhook/webhook.go:59-77` — installed as the `DialContext` of the custom `http.Transport` backing `safeClient` (`internal/webhook/webhook.go:32-37`). It resolves the target host and rejects the connection if any resolved IP is reserved via `isReservedIP` (`internal/webhook/validate.go:44-54`, checking `reservedNetworks`/`reservedCIDRs` at `internal/webhook/validate.go:14-23`: loopback, RFC-1918 private ranges, link-local/cloud IMDS, and IPv6 equivalents). A companion pre-registration check, `ValidateURL` (`internal/webhook/validate.go:62-83`), applies the same `isReservedIP` logic via `net.LookupHost` when a webhook URL is first saved — but the dial-time check in `safeDialContext` is what actually protects each delivery, since it re-resolves DNS at connection time (defeating TOCTOU/DNS-rebinding bypasses of the earlier validation). Note there is a global escape hatch, `AllowPrivateIPs` (`internal/webhook/validate.go:41`), which disables both checks when set true.
