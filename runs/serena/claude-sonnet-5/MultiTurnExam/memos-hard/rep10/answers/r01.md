**Premise correction:** There is no Redis anywhere in this codebase — a full search for `redis`/`Redis` across all Go files turns up zero matches. The cache layer is a self-contained, in-process, in-memory cache, not backed by an external Redis connection.

**Actual mechanism:** `store/cache/cache.go` defines an in-memory `Cache` type (`Interface`) with expiration/eviction logic. The `Store` (`store/store.go:13-30`) holds three such caches — `instanceSettingCache`, `userCache`, `userSettingCache` — all constructed via `cache.New(cacheConfig)` in `Store.New` (`store/store.go:38-61`), using a shared `Config` set at `store/store.go:40-45`:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

So user entries in `userCache` (`store/store.go:28,52`) get a **10-minute TTL**, with a background sweep every 5 minutes evicting expired/excess entries — there is no Redis connection to configure.
