**Premise correction:** Neither. This repository has no message-broker dependency at all — `go.mod` contains no NATS or RabbitMQ (or AMQP) client library, and a repo-wide search for those terms in Go source returns nothing.

**Actual mechanism:** Webhook delivery workers consume from an in-process, buffered Go channel, not any external broker. It's declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39`. Four worker goroutines are started in `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post(payload)` for each item. Producers enqueue onto this same channel via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select`/`default` send and drops the payload (logging a warning) if the channel is full — all entirely within a single process, with no persistence or external queueing involved.
