**Handlers that transitively trigger an outbound HTTP request to a user-configured URL (webhook URL):**

1. `CreateMemo` — `server/router/api/v1/memo_service.go:70` → dispatch at `:157` → `DispatchMemoCreatedWebhook` (`memo_service_webhooks.go:15`) → `dispatchMemoRelatedWebhook` (`:47`) → `webhook.PostAsync` (`:71`)
2. `UpdateMemo` — `memo_service.go:401` → `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`) → `DispatchMemoUpdatedWebhook` (`memo_service_webhooks.go:20`) → `dispatchMemoRelatedWebhook` → `webhook.PostAsync`
3. `DeleteMemo` — `memo_service.go:518` → `DispatchMemoDeletedWebhook` (`memo_service_webhooks.go:25`) → `dispatchMemoRelatedWebhook` → `webhook.PostAsync`
4. `CreateMemoComment` — `memo_service_comments.go:20` → `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`) → `webhook.PostAsync` directly
   (also `SetMemoAttachments` and `SetMemoRelations` reach the same webhook path via `dispatchMemoUpdatedSideEffects`)

**Convergence function:** `Post` — `internal/webhook/webhook.go:120` (all `PostAsync`-queued deliveries are consumed by worker goroutines that call `Post`, which executes the actual outbound request via `safeClient.Do(req)` at line 152).

Note: separately, `SignIn`/`CreateLinkedIdentity` (SSO) and `Transcribe` (AI) also hit user/admin-configured URLs (IdP endpoints, AI provider endpoint), but each uses its own distinct HTTP client and does **not** converge with the webhook path — `internal/webhook.Post` is the convergence point only for the memo-webhook family of handlers.
