**Premise correction:** Neither — there is no NATS or RabbitMQ (or any external message broker) involved in webhook delivery. The premise is false.

**Actual mechanism:** Webhook delivery workers consume from an in-process, bounded Go channel, not an external broker. In `internal/webhook/webhook.go`, `PostAsync` (lines 184-196) pushes payloads onto `asyncPostQueue` (a buffered `chan` declared at line 39), which is consumed by a fixed pool of worker goroutines started in the package's `init()` (lines 42-55). Each worker calls `Post` (line 120), which performs the actual outbound HTTP delivery via `safeClient.Do(req)` (line 152). This queue lives entirely within the server process's memory — it is not backed by NATS, RabbitMQ, Redis, or any other broker, and disappears on restart (undelivered items are lost, not persisted).
