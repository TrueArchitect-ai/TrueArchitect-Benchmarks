**Premise correction:** There is no nightly database-cleanup job scheduled via a cron scheduler in this codebase — the premise is false.

**What actually exists:** `internal/scheduler/scheduler.go` implements a generic cron-style scheduler, but it's never instantiated in production — `scheduler.New(` is called only from its own tests (`internal/scheduler/example_test.go`, `integration_test.go`) and doc example (`internal/scheduler/doc.go`); there's no call under `server/`, `cmd/`, or `store/`. `go.mod` has no cron library either.

The only actual recurring background job in the running server is the S3 presigned-URL refresher (`server/runner/s3presign`), which uses a plain `time.Ticker` at a fixed 12-hour interval (`server/runner/s3presign/runner.go:26-30`), wired up in `server/server.go`'s `startBackgroundRunners` (~line 153-173) — not a cron/time-of-day schedule, and unrelated to database cleanup. A broad search for cleanup/vacuum/prune/purge database logic found only request-triggered helpers (e.g. attachment cleanup on user deletion in `server/router/api/v1/user_service.go`, provisional-user cleanup on SSO failure in `auth_service_sso.go`) — none of them scheduled or nightly.
