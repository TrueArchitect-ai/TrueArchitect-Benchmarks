**Premise correction:** There is no Redis anywhere in this codebase — no import, dependency, or config option (`grep -ri "redis"` across the repo, `go.mod`, and `go.sum` returns nothing). The cache layer is not backed by Redis or any external store.

**Actual mechanism:** It's a custom in-memory, thread-safe cache built on `sync.Map`, defined in `store/cache/cache.go:67-73` (`Cache` struct), with `New(config Config)` at `store/cache/cache.go:75-85` starting a background cleanup goroutine. It's instantiated as three separate in-process caches on `*store.Store` — `instanceSettingCache`, `userCache`, `userSettingCache` — at `store/store.go:27-29`.

The `userCache` is constructed at `store/store.go:52` using the config defined at `store/store.go:40-45`:
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```
User entries (set via `s.userCache.Set(...)` in `store/user.go:98,122,132,143,167`) use the default TTL, so **user cache entries expire after 10 minutes**, with expired entries swept every 5 minutes by the cache's internal cleanup loop (`store/cache/cache.go:200-215`). Everything lives in process memory and is lost on restart.
