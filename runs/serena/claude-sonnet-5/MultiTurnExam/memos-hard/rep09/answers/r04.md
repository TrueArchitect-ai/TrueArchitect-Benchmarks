**Premise correction:** Neither. There is no message broker (NATS, RabbitMQ, or otherwise) anywhere in this codebase — I checked `go.mod` and grepped the whole repo for `nats`/`rabbitmq`/`amqp` with no hits.

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel, not an external broker. It's declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:44`. A fixed pool of 4 goroutines, spawned in the package `init()` (`internal/webhook/webhook.go:42-51`), range over that channel and call `Post` for each payload. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send (`select`/`default`) and drops the payload with a warning log if the buffered channel is full — there's no persistence, durability, or acknowledgement semantics you'd get from an actual broker.
