**Premise correction:** There is no Redis in this codebase — I searched the whole repo (`.go`, `.md`, `.yaml`/`.yml`) for any mention of "redis" and found none. There's no external cache server, connection string, or client dependency for one.

**Actual mechanism:** The cache layer is a self-contained in-process cache, `store/cache/cache.go` (`Cache` struct backed by a `sync.Map`/mutex-protected map, not a network service). It's instantiated in `store.New` at `store/store.go:38-53`, which builds three separate in-memory `*cache.Cache` instances — `instanceSettingCache`, `userCache`, `userSettingCache` — all sharing the same `cache.Config` (`store/store.go:40-45`):

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user entries (`userCache`, `store/store.go:52`) get a **10-minute TTL**, with a background sweep every 5 minutes (`Cache`'s cleanup loop) evicting expired entries, and a 1000-item cap per cache — all in-process, with no Redis or other external store involved.
