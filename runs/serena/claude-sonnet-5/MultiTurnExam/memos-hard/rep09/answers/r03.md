**Premise correction:** There is no nightly database-cleanup job, and there's no wired-up "cron scheduler" in the running server at all. This repo does contain a generic cron-style scheduler library at `internal/scheduler/scheduler.go` (with `Register`, `Start`, `ParseCronExpression`, etc.), but it is only referenced from its own tests — `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. Neither `server/` nor `cmd/memos` ever imports `internal/scheduler`, so no job — nightly or otherwise — is registered or scheduled through it in production.

The only two things that resemble "cleanup" in the codebase are unrelated and not cron-scheduled:
- The in-memory cache's eviction ticker, `cleanupLoop` in `store/cache/cache.go:200-216`, which runs every `CleanupInterval` (5 minutes, `store/store.go:42`) to purge expired cache entries — not a database job.
- Attachment/storage cleanup performed synchronously inline during requests (e.g. `user_service.go:421-450` during user deletion, `store/attachment.go:171` during attachment deletion) — triggered by user actions, not a nightly timer.

The recurring background job that actually does exist and runs on a fixed interval is the S3 presign refresher (`server/runner/s3presign/runner.go`, every 12 hours — see prior answer h01), which is unrelated to "database cleanup."
