**Premise correction:** Neither. There is no external message broker (NATS, RabbitMQ, or otherwise) in this repository — a search of `go.mod`/`go.sum` and all `.go` files turns up no NATS or RabbitMQ client dependency, and none is imported anywhere.

**Actual mechanism:** Webhook delivery workers consume from an in-process, in-memory Go channel, not a broker. It's declared as a package-level buffered channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`. Four worker goroutines are spawned in the package's `init()` to range over that channel and call `Post` for each payload — `internal/webhook/webhook.go:42-55`. Producers enqueue via `PostAsync`, which does a non-blocking send (`select`/`default`) and drops the payload with a warning log if the channel is full — `internal/webhook/webhook.go:184-196`. Everything is local to the single server process; there's no persistence or cross-process queue.
