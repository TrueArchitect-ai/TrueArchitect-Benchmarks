computation site — `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`, which calls `markdownService.ExtractAll(content)` (interface method implemented at `internal/markdown/markdown.go:356-422`) and assigns the results to `memo.Payload.Tags` and `memo.Payload.Property` (the persisted `MemoPayload` on the memo row).

triggers — recomputation happens whenever a memo's content is (re)parsed:
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`
- `UpdateMemo`, specifically when the `content` field is in the update mask — `server/router/api/v1/memo_service.go:447`
(the package-level `RebuildMemoPayload` function is called directly; the `memopayload.Runner.RunOnce` batch job that would recompute it for all existing memos exists but, per the earlier finding, is never actually invoked in production — so recomputation is currently limited to memo create/update.)

extracted properties — from `ExtractAll` (`internal/markdown/markdown.go:356`): `Tags` (all `#tag` occurrences, deduplicated), `Mentions` (all `@username` mentions, lowercased/deduplicated — not persisted onto `Payload`, only `Tags`/`Property` are), and `Property`, a struct with `Title` (text of a leading H1 heading, if the first block is one), `HasLink`, `HasCode` (from code blocks/spans), `HasTaskList`, and `HasIncompleteTasks` (from unchecked task-list items) — these flags are what list/preview UI uses to show badges without re-parsing content each time.
