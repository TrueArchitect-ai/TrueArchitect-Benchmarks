Premise correction — there is no per-user API rate-limiting middleware anywhere in this codebase. A repo-wide search for "rate limit" / "ratelimit" / "throttle" turns up exactly one hit, a comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") that is purely aspirational documentation — it doesn't correspond to any implemented code. There's no Echo `middleware.RateLimiter` (or any custom rate-limiter) registered in `server/server.go` or elsewhere, and no middleware directory implements request throttling.

Actual mechanism — request-level protection that does exist is limited to: the SSE client-count guard in `server/router/api/v1/sse_hub.go`, concurrency semaphores for thumbnail/image processing (`thumbnailSemaphore`, `imageProcessingSemaphore` in `server/router/api/v1/v1.go:40-41`), and the bounded async webhook queue (`internal/webhook/webhook.go:39`) — none of which are per-user API rate limits.
