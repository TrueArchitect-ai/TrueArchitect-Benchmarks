Premise correction — there is no Redis anywhere in this codebase; a repo-wide search for "redis" (case-insensitive, all `.go` files) returns zero matches. The cache layer is an in-process, in-memory implementation, not a networked cache, so there's no "connection" to configure.

Actual mechanism — the cache is `store/cache/cache.go`'s `Cache` type (an in-memory map with TTL/eviction, `store/cache/cache.go:1-60+`). The `Store` holds three such caches, including `userCache` (`store/store.go:28`), all constructed in `store.New` (`store/store.go:38-53`) using a shared `cache.Config` with `DefaultTTL: 10 * time.Minute` (`store/store.go:41`, also `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`). So user entries cached via `s.userCache` (set/read in `Store.GetUser`/`ListUsers`, `store/user.go:136-169`) expire after **10 minutes**, with a background cleanup sweep every 5 minutes.
