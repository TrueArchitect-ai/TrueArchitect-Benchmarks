**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search for "redis" (case-insensitive) across all Go files returns zero results. The cache layer is not backed by an external cache server at all.

**Actual mechanism:** The cache is a self-contained in-process, in-memory implementation: `store/cache/cache.go` defines a `Cache` type (implementing `cache.Interface`) built on a plain `sync`-guarded map with expiration timestamps, no network client. It's instantiated in `store.New` (`store/store.go:38-58`): `userCache = cache.New(cacheConfig)` at `store/store.go:52`, using `cacheConfig.DefaultTTL = 10 * time.Minute` (`store/store.go:41`, with `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000`). User entries are written with `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`), which uses that 10-minute default TTL since no per-entry TTL override (`SetWithTTL`) is used for users.
