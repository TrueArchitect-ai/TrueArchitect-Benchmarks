**Premise correction:** Neither. There is no NATS or RabbitMQ (or any external message broker) in this codebase — `go.mod`/`go.sum` contain no such dependency, and a repo-wide search for "nats", "rabbitmq", or "amqp" returns nothing.

**Actual mechanism:** Webhook delivery workers consume from an in-process, in-memory Go channel, not a broker. `internal/webhook/webhook.go:39` declares `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`. `PostAsync` (`internal/webhook/webhook.go:184-196`) enqueues payloads onto this channel, and 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) range over `asyncPostQueue`, calling `Post` for each payload. This queue lives only in the server process's memory and is not durable or distributed.
