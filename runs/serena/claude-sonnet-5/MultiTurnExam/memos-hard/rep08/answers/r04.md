**Premise correction:** Neither. This codebase has no message broker at all — no NATS, RabbitMQ, or any other external queueing system appears in `go.mod`/`go.sum` or anywhere in the Go source.

**Actual mechanism:** Webhook delivery uses a bounded, in-process Go channel as the "queue," not an external broker. It's declared in `internal/webhook/webhook.go:39`:
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```
Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) to drain this channel and call `Post` for each payload. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send and drops (with a warning log) if the channel is full — there's no persistence, retry, or cross-process delivery; everything lives in a single server process's memory.
