q25. Engine: CEL (Common Expression Language, via `google/cel-go`) — implemented in `internal/filter/` (`engine.go` for compiling the CEL expression, `ir.go` for the dialect-agnostic condition tree, `schema.go` for per-field metadata, `render.go` for SQL rendering).

Mechanism: `Engine.Compile` (internal/filter/engine.go) parses the CEL filter string into a dialect-agnostic `Condition` tree, and `renderer.Render` (internal/filter/render.go) walks that tree to emit dialect-specific SQL/args, substituting per-field/per-dialect expression templates from `Schema.Expressions` (internal/filter/schema.go, e.g. `UNIX_TIMESTAMP(%s)` for MySQL vs. the raw column for Postgres/SQLite) so the same filter compiles to correct SQL for each of the three supported dialects.
