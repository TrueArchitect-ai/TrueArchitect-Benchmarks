q26. **memo**, **memo_relation**, **attachment**

Details (from `server/router/api/v1/memo_service.go:518-593` and `store/memo.go:140-159`):
- `store.DeleteMemo` deletes `memo_relation` rows where the memo is either `memo_id` or `related_memo_id`, then deletes each linked `attachment` row (via `DeleteAttachment`), then deletes the `memo` row itself.
- The API handler `APIV1Service.DeleteMemo` first finds and deletes any comment memos (rows in `memo` linked via `memo_relation` of type comment) by recursively calling `Store.DeleteMemo` on each — cascading the same `memo_relation`/`attachment`/`memo` deletions for each comment.
- `reaction` rows tied to the memo are only *read* (for the webhook payload) — they are not deleted, and there's no DB-level cascade for them (`reaction.content_id` is a plain TEXT column, not a foreign key). `memo_share` is likewise untouched by this path.
