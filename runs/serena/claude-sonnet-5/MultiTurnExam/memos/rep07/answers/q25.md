q25. Engine: CEL (Common Expression Language, via `google/cel-go`), living in `internal/filter/` (`engine.go`, `schema.go`, `ir.go`, `render.go`, `parser.go`).

Mechanism: the CEL filter string is compiled by `Engine` (`internal/filter/engine.go`) into a dialect-agnostic `Condition`/IR tree (`internal/filter/ir.go`), which `render.go`'s renderer then converts into a SQL WHERE fragment per `DialectName` (`sqlite`/`mysql`/`postgres`, defined in `internal/filter/schema.go`), substituting dialect-specific column expressions (e.g. `UNIX_TIMESTAMP(%s)` for MySQL vs. raw epoch columns for Postgres/SQLite) before the fragment is appended to the store layer's query via `AppendConditions` in `internal/filter/helpers.go`.
