In `store/memo.go` (`Store.DeleteMemo`, store/memo.go:140-159), before deleting the memo row itself, the store layer deletes:

1. **Memo relation records** (`memo_relation` table) — via two calls to `s.driver.DeleteMemoRelation`, once where the memo is the source (`MemoID`) and once where it's the target (`RelatedMemoID`) (store/memo.go:142-147).
2. **Attachment records** linked to the memo — it lists all attachments via `s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})` and deletes each one individually with `s.DeleteAttachment` (store/memo.go:148-157).

Only after these cleanups does it call `s.driver.DeleteMemo(ctx, delete)` (store/memo.go:158), which issues the actual `DELETE FROM memo WHERE id = ?` (e.g., store/db/sqlite/memo.go:237-248).
