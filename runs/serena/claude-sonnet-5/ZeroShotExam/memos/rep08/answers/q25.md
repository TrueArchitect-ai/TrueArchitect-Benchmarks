q25.

**Engine + path:** Google's CEL (Common Expression Language, `github.com/google/cel-go`) is used to parse the `filter` string. The engine lives in `internal/filter/` (`engine.go`, `schema.go`, `ir.go`, `render.go`, `helpers.go`).

**Mechanism:** `Engine.Compile` (`internal/filter/engine.go`) compiles the filter text with a CEL `cel.Env` built from a memo `Schema` (`internal/filter/schema.go`), converts the resulting CEL AST into a dialect-agnostic `Condition` tree (`ir.go`), and then `Program.Render`/`renderer.Render` (`internal/filter/render.go`) walks that tree to emit parameterized SQL fragments, branching per `DialectName` (`DialectSQLite`, `DialectMySQL`, `DialectPostgres`) for things like string functions, JSON array access, regex, and date extraction; the store layer (e.g. `store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`) calls `filter.DefaultEngine()` + `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` to turn `ListMemos`' `FindMemo.Filters` (populated from the RPC's `request.Filter` in `server/router/api/v1/memo_service.go`) into `WHERE` clause fragments and args for that database's query.
