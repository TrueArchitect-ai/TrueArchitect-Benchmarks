**Engine + path:** The `filter` field on `ListMemos` is parsed as a **CEL (Common Expression Language)** expression using Google's `cel-go` (`github.com/google/cel-go/cel`), wrapped by a custom package at `internal/filter/` — key files: `engine.go` (CEL env/compile), `parser.go` (CEL AST → internal IR), `ir.go` (IR types), `schema.go` (field/variable definitions), `render.go` (SQL rendering), `helpers.go` (`AppendConditions` glue).

**Mechanism:** `Engine.Compile` (`internal/filter/engine.go`) parses the filter string with `cel.Env.Compile` into a CEL AST, `buildCondition` (`internal/filter/parser.go`) walks that AST into a dialect-agnostic IR (`internal/filter/ir.go`), and then a per-call `renderer` (`internal/filter/render.go`) walks the IR and emits dialect-specific SQL fragments/placeholders — invoked separately by each store driver (`store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`) with `filter.DialectSQLite`/`DialectMySQL`/`DialectPostgres`, producing different SQL idioms per backend (e.g. `JSON_EXTRACT` vs Postgres `->`/`->>`, `LIKE`/`REGEXP` vs `~`, `?` vs `$N` placeholders) for the same parsed filter.
