The background research agent confirmed and added a bit more detail worth flagging — a small correction to my earlier answer:

- **Attachment deletion is deeper than I described**: `store/attachment.go:132-149`'s `DeleteAttachment` also removes the underlying blob/file/S3 object via `DeleteAttachmentStorage` before deleting the DB row — so it's not just a DB record but also storage cleanup.
- **Reactions are NOT deleted** by this flow at all (store or API layer) — they're only read (`ListReactions`) for the webhook payload, and there's no FK cascade for `reaction → memo`, so they become orphaned.
- **`memo_share`** is cleaned up via a DB-level `ON DELETE CASCADE` foreign key (`store/migration/postgres/LATEST.sql:108`), not by explicit store-layer code.
- **`memo_organizer`** no longer exists — dropped in migration `store/migration/postgres/0.26/01__drop_memo_organizer.sql`.

My original answer to q16 stands as the list of record kinds the **store layer explicitly deletes**: memo relations (both directions) and attachments (including their storage blobs), plus comment memos deleted recursively by the API handler before it reaches the store layer.
