**Engine + path:** CEL (Common Expression Language, `github.com/google/cel-go/cel`), wrapped by a custom `Engine` in `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `schema.go`, `render.go`, `helpers.go`).

**Mechanism:** The `filter` string from `ListMemos` (`server/router/api/v1/memo_service.go`, forwarded via `store.ListMemos` in `store/memo.go`) is compiled by `filter.Engine` (built over `cel.NewEnv` with a `Schema` of allowed memo fields in `schema.go`) into a CEL AST, which `parser.go` converts into a dialect-agnostic `Condition`/`Statement` IR (`ir.go`); a single `renderer` in `render.go` then walks that IR and switches on a `DialectName` (`sqlite`/`mysql`/`postgres`) to emit dialect-specific SQL fragments (e.g. regex ops, LIKE escaping, JSON extraction, `LENGTH` vs `CHAR_LENGTH`), which each backend's store code (`store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`) obtains via the shared `filter.AppendConditions(ctx, engine, filters, dialect, &where, &args)` helper and appends into its own query builder.
