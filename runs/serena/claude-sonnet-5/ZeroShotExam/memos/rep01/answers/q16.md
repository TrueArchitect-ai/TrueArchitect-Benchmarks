Reactions aren't cleaned up by `DeleteMemo` in the store layer. So the store-layer `DeleteMemo` only handles memo_relation and attachments. This confirms the answer.

q16.
When `Store.DeleteMemo` (store/memo.go:140-159) deletes a memo, before deleting the memo row itself it deletes:

1. **`memo_relation` records where the memo is the source** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (store/memo.go:142)
2. **`memo_relation` records where the memo is the target** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})` (store/memo.go:145)
3. **Attachments linked to the memo** — lists via `s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})` and deletes each one with `s.DeleteAttachment(...)` (store/memo.go:149-157)

Only after these does it call `s.driver.DeleteMemo(ctx, delete)` (store/memo.go:158), which issues `DELETE FROM memo WHERE id = ?` (e.g. store/db/sqlite/memo.go:237-248).

Note: `memo_share` rows are removed automatically via a DB-level `ON DELETE CASCADE` foreign key (store/migration/sqlite/*.sql:109), not by explicit store-layer code, and `reaction` rows are not cleaned up by `DeleteMemo` at all.
