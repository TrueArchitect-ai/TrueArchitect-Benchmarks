In `Store.DeleteMemo` (store/memo.go:140-159), before deleting the memo row itself, the store layer deletes:

1. **Memo relation records** — via `driver.DeleteMemoRelation`, called twice: once for relations where the memo is the source (`MemoID`) and once where it's the target (`RelatedMemoID`) (store/memo.go:142-147).
2. **Attachment records** — it lists all attachments linked to the memo (`ListAttachments`) and deletes each one via `DeleteAttachment` (store/memo.go:149-157).

Only after these two cleanup steps does it call `s.driver.DeleteMemo(ctx, delete)` to remove the memo row (store/memo.go:158).

Note: at the API layer (server/router/api/v1/memo_service.go:567-577), `DeleteMemo` also first deletes any child "comment" memos (memos related via a `MemoRelationComment` relation) by recursively calling `Store.DeleteMemo` on each — which in turn goes through the same relation/attachment cleanup for each comment memo.
