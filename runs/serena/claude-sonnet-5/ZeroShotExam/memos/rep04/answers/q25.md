**Engine + path**: The `internal/filter` package (`/bench/repo/internal/filter/`) — specifically `engine.go` (CEL compilation via `github.com/google/cel-go`), `parser.go`/`ir.go` (building a dialect-agnostic `Condition` tree from the CEL AST), `schema.go` (field/column definitions), and `render.go` (SQL rendering per dialect).

**Mechanism**: `ListMemos` (`server/router/api/v1/memo_service.go:211-216`) validates the filter via `validateFilter` and appends `request.Filter` to `store.FindMemo.Filters`; the store layer then calls `filter.AppendConditions` (`internal/filter/helpers.go`), which uses the package's `Engine.CompileToStatement` (`internal/filter/engine.go`) to CEL-parse the filter string into an AST, convert that AST into a dialect-agnostic `Condition` tree (`internal/filter/parser.go`/`ir.go`), and then have a `renderer` (`internal/filter/render.go`) walk that tree emitting parameterized SQL fragments and args tailored to whichever `DialectName` (sqlite/mysql/postgres) is passed in, which get appended into the `WHERE` clause built by the store's driver-specific `ListMemos` implementation (`store/db/{sqlite,mysql,postgres}/memo.go`).
