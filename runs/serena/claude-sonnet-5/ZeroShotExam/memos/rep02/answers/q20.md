**Mechanism:** Server-Sent Events (SSE) over an HTTP streaming endpoint (`text/event-stream`), not WebSockets.

**Hub implementation:** `server/router/api/v1/sse_hub.go` — the `SSEHub` type manages subscribed `SSEClient` connections and exposes `Broadcast(event *SSEEvent)` to fan out events (with per-client visibility filtering via `canReceive`). It's registered/wired up in `server/router/api/v1/v1.go` (`SSEHub: NewSSEHub()`, `RegisterSSERoutes`), and the actual streaming connection is served by `server/router/api/v1/sse_handler.go` (`handleSSE`).

**Handlers that broadcast through it** (all in `server/router/api/v1/`, calling `s.SSEHub.Broadcast(...)`):
- `CreateMemo` (memo_service.go) — `SSEEventMemoCreated`
- `DeleteMemo` (memo_service.go) — `SSEEventMemoDeleted`
- `dispatchMemoUpdatedSideEffects` (memo_update_helpers.go) — `SSEEventMemoUpdated`, invoked from `UpdateMemo` (memo_service.go) as well as attachment/relation update paths (`memo_attachment_service.go`, `memo_relation_service.go`)
- `CreateMemoComment` (memo_service_comments.go) — `SSEEventMemoCommentCreated`
- `UpsertMemoReaction` (reaction_service.go) — `SSEEventReactionUpserted`
- `DeleteMemoReaction` (reaction_service.go) — `SSEEventReactionDeleted`
