r04. Premise correction: this repo (usememos/memos) doesn't use either NATS or RabbitMQ for webhook delivery — there is no external message broker at all.

Actual mechanism: webhook dispatch is done with an in-process, in-memory Go channel that acts as a bounded worker queue. It's declared in `/bench/repo/internal/webhook/webhook.go:39` as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, and consumed by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each ranging over the channel and calling `Post()` to deliver the HTTP webhook. `PostAsync()` (`internal/webhook/webhook.go:184-196`) enqueues payloads with a non-blocking `select`/`default`, dropping (and logging) the webhook if the channel is full — there's no persistence, retry, or external broker involved.
