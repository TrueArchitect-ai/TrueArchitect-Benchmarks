**Actual mechanism:** The cache layer is a custom in-process, thread-safe in-memory cache implemented in `store/cache/cache.go` (backed by `sync.Map` with atomic counters, TTL expiration, and periodic cleanup — no external service involved).

For user entries specifically, the store maintains a dedicated `userCache` (`*cache.Cache`) declared in `store/store.go:28` and used in `store/user.go` (e.g., lines 98, 122, 132, 143, 150, 167) via `s.userCache.Set(...)` / `.Get(...)`, keyed by `userCacheKey(userID int32)` (`store/user.go:88`).

The TTL applied to user entries is the default TTL from the shared `cacheConfig` set in `store/store.go:40-45`:
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
So user cache entries expire **10 minutes** after being set, with a background cleanup sweep every 5 minutes (`store/cache/cache.go:56-64`, `DefaultConfig()`, mirrored inline in `store.go`).
