**Premise correction:** Neither NATS nor RabbitMQ is used. The repo (usememos/memos) has no message-broker dependency anywhere in the codebase — a search for `rabbitmq`/`amqp`/`nats` across Go/JS/config files turns up nothing relevant (the one hit, `web/src/locales/ca.json`, is an unrelated Catalan translation string).

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel as the "queue," not an external broker:

- `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel declared in `internal/webhook/webhook.go:39`.
- Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over `asyncPostQueue` and call `Post()` to deliver each webhook via `safeClient` (an SSRF-guarded `http.Client`).
- Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send and drops (with a warning log) if the queue is full — there's no persistence or redelivery, since it's purely in-memory.

So delivery is entirely process-local; there is no external broker or persistent queue declaration to point to.
