**Handlers (gRPC/Connect RPCs that transitively fire an HTTP request to a user-configured URL):**

1. `APIV1Service.CreateMemo` — `server/router/api/v1/memo_service.go:157` calls `s.DispatchMemoCreatedWebhook`
2. `APIV1Service.UpdateMemo` — via `dispatchMemoUpdatedSideEffects` at `server/router/api/v1/memo_update_helpers.go:67` calls `s.DispatchMemoUpdatedWebhook`
3. `APIV1Service.DeleteMemo` — `server/router/api/v1/memo_service.go:562` calls `s.DispatchMemoDeletedWebhook`
4. `APIV1Service.CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:119` calls `s.DispatchMemoCommentCreatedWebhook`

Each of these `Dispatch*Webhook` helpers (defined in `server/router/api/v1/memo_service_webhooks.go`) loads the caller's registered webhooks (`hook.Url`, set earlier by the user via `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`) and calls `webhook.PostAsync(payload)`, which enqueues onto `asyncPostQueue` (`internal/webhook/webhook.go:39/190`).

**Convergence function:** `Post` — `internal/webhook/webhook.go:120`

All four handlers' payloads are eventually drained from `asyncPostQueue` by the worker goroutines started in `init()` (`internal/webhook/webhook.go:42-53`), each of which calls `Post(payload)`. `Post` is the single place that actually builds the `http.NewRequest` and executes it via the SSRF-guarded `safeClient.Do(req)` (`internal/webhook/webhook.go:151`) against the user-configured `requestPayload.URL`.

(Note: a separate, unrelated convergence point exists for link previews — `GetLinkMetadata`/`BatchGetLinkMetadata` in `server/router/api/v1/memo_service_link_metadata.go` funnel into `httpgetter.GetHTMLMeta`, `internal/httpgetter/html_meta.go` — but that path uses a request-supplied URL rather than a stored user setting, and is a distinct package/function from the webhook convergence point above.)
