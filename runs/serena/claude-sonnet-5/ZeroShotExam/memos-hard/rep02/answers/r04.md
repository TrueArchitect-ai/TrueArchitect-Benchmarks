Premise correction: this repository (usememos/memos) does not use either NATS or RabbitMQ for webhook delivery — there is no external message broker involved at all.

Actual mechanism: webhook dispatch is handled entirely in-process via a buffered Go channel. In `internal/webhook/webhook.go:39`, `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` — an in-memory, capacity-128 channel (not a durable/broker-backed queue). Four goroutines are spun up in `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post()` for each payload. `PostAsync()` (`internal/webhook/webhook.go:184-196`) enqueues payloads with a non-blocking `select`/`default`, dropping and logging a warning if the queue is full. There's no AMQP/NATS client dependency anywhere in the repo (confirmed via grep for `rabbit`/`amqp`/`nats`/`jetstream`), so delivery is entirely local to the server process with no persistence across restarts.
