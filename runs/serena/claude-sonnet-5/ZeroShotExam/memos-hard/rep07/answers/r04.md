Premise correction: this repo (usememos/memos) does not use NATS or RabbitMQ for webhook delivery — there is no external message broker involved at all.

Actual mechanism: webhook delivery is handled entirely in-process via a buffered Go channel. In `internal/webhook/webhook.go:39`, `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` — a 128-capacity in-memory channel, not a broker-backed queue. Four worker goroutines are spawned in the package `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post()` for each payload. Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send and drops (with a logged warning) if the channel is full. There's no AMQP/NATS client, connection config, or queue/exchange declaration anywhere in the codebase (confirmed via repo-wide search for "rabbitmq", "amqp", "nats" — no matches).
