**Premise correction:** Neither. This repository (`usememos/memos`) does not use an external message broker for webhook delivery — there is no NATS or RabbitMQ dependency anywhere in the codebase (a grep across the repo turns up no `nats`/`rabbitmq`/`amqp` references outside an unrelated Catalan locale string).

**Actual mechanism:** Webhook delivery is handled entirely in-process via a buffered Go channel, not a message broker. In `internal/webhook/webhook.go:39`, `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` — an in-memory channel with capacity 128. An `init()` function (`internal/webhook/webhook.go:42-55`) spins up 4 goroutine workers that range over this channel and call `Post()` for each payload, logging a warning on failure. `PostAsync()` (`internal/webhook/webhook.go:184-196`) enqueues payloads with a non-blocking `select`/`default`, dropping and logging a warning if the queue is full rather than blocking. This is a purely in-process, non-durable worker pool — there's no external broker, no persistence across restarts, and no queue declaration on any broker system.
