Premise correction: neither. This repository (usememos/memos) has no NATS or RabbitMQ integration anywhere in the codebase (no `amqp`/`rabbitmq`/`nats` imports or config found via repo-wide search).

Actual mechanism: webhook delivery workers consume from an in-process Go buffered channel, not an external message broker. The "queue" is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

It's populated by `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send (drops and logs a warning if the channel is full). Four goroutine workers are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over `asyncPostQueue` and call `Post()` to actually deliver each webhook via HTTP. So delivery is entirely in-memory/in-process — there's no external broker, and consequently no persistence/redelivery across restarts.
