- delivery function — `Post` in `internal/webhook/webhook.go:120` (invoked synchronously, or asynchronously via `PostAsync` at `internal/webhook/webhook.go:184`, which feeds a worker pool that also calls `Post`). The actual outbound request executes via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.
- protection mechanism — SSRF protection is enforced at two layers in the same package:
  - `safeDialContext` (`internal/webhook/webhook.go:59`), installed as the `DialContext` on the shared `safeClient`'s `http.Transport` (`internal/webhook/webhook.go:32-37`), resolves the hostname at dial time and rejects any resolved IP in a reserved/private range — this is what actually blocks the connection (and defeats DNS rebinding, since it checks the IP that's about to be dialed, not just the URL's literal host).
  - `isReservedIP` / `reservedNetworks` and `ValidateURL` in `internal/webhook/validate.go:44` and `internal/webhook/validate.go:62` do an upfront check against reserved CIDR ranges (loopback, RFC-1918, link-local/cloud IMDS, and IPv6 equivalents) when a webhook URL is first configured/saved (called from the webhook API handlers, e.g. `server/router/api/v1/user_service_webhooks.go` / `memo_service_webhooks.go`), rejecting private-IP targets before they're ever stored.

Both share the same `isReservedIP` gate in `internal/webhook/validate.go:44`, which can be disabled via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for self-hosted deployments.
