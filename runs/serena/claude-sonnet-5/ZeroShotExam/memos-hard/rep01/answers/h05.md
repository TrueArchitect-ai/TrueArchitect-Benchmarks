h05. Mechanism: explicit Go application code (no DB-level cascade/trigger exists).

Evidence locations:

- **No FK/cascade in schema**: `reaction` table has no foreign key to `user` in any driver, e.g. `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98` — `creator_id` is a plain integer column, no `REFERENCES`/`ON DELETE CASCADE`, and no `CREATE TRIGGER` on `reaction` anywhere in `store/migration`.
- **Explicit deletion in Go**: within the `DeleteUser` transaction, e.g. `store/db/sqlite/user_delete.go:92-127` (`deleteUserTargetsTx`) calls:
  - `deleteReactionsByContentIDsTx` (`store/db/sqlite/user_delete.go:380-388`) — removes reactions on the user's own memos before those memos are hard-deleted.
  - `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:400-403`) — `DELETE FROM reaction WHERE creator_id = ?`, removing reactions the user made on others' memos.
  - Identical logic in `store/db/postgres/user_delete.go:96-102,380-403` and `store/db/mysql/user_delete.go:96-102,417-440`.
- **Call path**: `Store.DeleteUser` (`store/user.go:171-172`) is invoked from the user-deletion API (`server/router/api/v1/user_service.go:414`).
- **Test confirming behavior**: `server/router/api/v1/test/reaction_service_test.go` (`TestListMemoReactionsSkipsMissingCreators`, ~lines 198-233) creates a reaction, calls `Store.DeleteUser`, and asserts the reaction list is empty afterward.

Since there's no FK constraint, if this application-level cleanup were ever skipped, reactions would be orphaned rather than cascade-deleted by the database.
