**Computation site:** `internal/markdown/markdown.go` — two functions in the `markdown.Service`:
- `ExtractAll(content []byte)` (lines 356–422): single-pass goldmark AST walk extracting tags, mentions, and a `Property` struct (title, has_link, has_code, has_task_list, has_incomplete_tasks). Title comes only from a leading H1 heading (`extractHeadingText`, line 173).
- `GenerateSnippet(content []byte, maxLength int)` (lines 264–346): walks the AST to build a plain-text excerpt, stripping code blocks and truncating at a word boundary (`truncateAtWord`, line 472).

These are orchestrated/persisted via `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which calls `ExtractAll` and writes results into `memo.Payload.Tags` / `memo.Payload.Property` (proto defined in `proto/store/memo.proto:7-29`).

**Triggers:**
- Memo creation: `server/router/api/v1/memo_service.go:108` (`CreateMemo` calls `memopayload.RebuildMemoPayload` before `s.Store.CreateMemo`).
- Memo update — only when content changes: `server/router/api/v1/memo_service.go:436-451` (`UpdateMemo`'s field-mask loop, `if path == "content"` branch); if the update mask doesn't touch content, tags/title/flags are left untouched.
- Manual batch backfill: `Runner.RunOnce` in `server/runner/memopayload/runner.go:27` pages through all memos and rebuilds their payload, but this runner isn't wired into `server/server.go`'s startup/cron flow (unlike its sibling `s3presign` runner) — it appears to be for administrative/migration use only, not an automatic trigger.
- Separately, the **snippet** used for previews is *not* persisted — it's recomputed on every read via `getMemoContentSnippet` (`server/router/api/v1/memo_service_webhooks.go:83`, calling `GenerateSnippet(content, 64)`), invoked from `convertMemoFromStoreWithCreators` and `batchConvertMemoRelations` (`memo_service_converter.go`) each time a memo is converted to an API response for list/get calls, as well as in notification snippets (`user_service_notifications.go:318`).

**Extracted properties:**

- Not persisted (recomputed on each read): `snippet` — a ≤64-character, word-boundary-truncated plain-text excerpt of the content, used for list/preview display.
- No word count or reading-time field exists in the codebase.
