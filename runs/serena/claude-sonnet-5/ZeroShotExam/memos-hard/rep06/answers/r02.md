I could not find any per-user API rate-limiting middleware in this repository — there isn't one. This is the `usememos/memos` codebase (Go backend in `server/`, React frontend in `web/`). I checked:

- The Connect RPC interceptor chain registered in `/bench/repo/server/router/api/v1/connect_interceptors.go` and wired up in `/bench/repo/server/router/api/v1/v1.go` — it only contains `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor`. No rate-limiting interceptor.
- CORS middleware in `/bench/repo/server/cors.go` and general middleware in `/bench/repo/server/server.go` — no rate limiting there either.
- `golang.org/x/time` (which provides Go's token-bucket rate limiter) appears in `go.mod` only as an **indirect** dependency (line 151), meaning it's pulled in transitively by some other module, not used directly by this codebase's own code.
- No hits for `rate-limit`/`throttle`/`ratelimit` anywhere in the repo outside of unrelated pagination "limit" parameters (e.g., `memo_service.go`, `user_service.go` list/query size limits, which are unrelated to request-rate throttling).

So the premise that per-user API rate-limiting middleware exists and is registered somewhere is incorrect for this codebase as it currently stands — no such middleware or limits are implemented.
