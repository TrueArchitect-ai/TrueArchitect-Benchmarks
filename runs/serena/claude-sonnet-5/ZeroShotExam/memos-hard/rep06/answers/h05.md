**Mechanism: explicit Go application code** (within a single DB transaction), not a database-level cascade/trigger.

**Evidence:**

1. **User deletion entry point** — `server/router/api/v1/user_service.go:393-457`, `APIV1Service.DeleteUser` calls `s.Store.DeleteUser(ctx, &store.DeleteUser{ID: user.ID})`.
2. **Store wrapper** — `store/user.go:171-181`, `Store.DeleteUser` delegates to the per-driver `driver.DeleteUser`.
3. **Reaction model** — `store/reaction.go:7-14`: `Reaction{ID, CreatedTs, CreatorID, ContentID, ReactionType}`.
4. **No DB-level cascade/trigger**: the `reaction` table definitions in `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, and `store/migration/mysql/LATEST.sql:91-98` have no `FOREIGN KEY`/`ON DELETE CASCADE` clause referencing `user` (or `memo`). By contrast, `memo_share` in the same files does declare `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (e.g. `store/migration/mysql/LATEST.sql:108`), confirming the schema author's pattern for cascades is absent here. A repo-wide grep for `trigger` in `store/migration/*/LATEST.sql` found none.
5. **Explicit Go cleanup** — each DB driver's `DeleteUser` transaction (`store/db/sqlite/user_delete.go`, `store/db/postgres/user_delete.go`, `store/db/mysql/user_delete.go`, structurally identical) calls, inside `deleteUserTargetsTx`:
   - `deleteReactionsByContentIDsTx` (sqlite: lines 96, 380-388) — `DELETE FROM reaction WHERE content_id IN (...)`, removing reactions on all memos owned by the deleted user (including comment-tree descendants).
   - `deleteReactionsByCreatorTx` (sqlite: lines 102, 400-403) — `DELETE FROM reaction WHERE creator_id = ?`, removing reactions the deleted user made on any memo.
   - Both run before the memo rows and the `user` row itself are deleted (`deleteUserRowTx`, sqlite line 123). Equivalent code exists at `store/db/postgres/user_delete.go:380-403` and `store/db/mysql/user_delete.go:417-440`.

Conclusion: reactions are not orphaned — the application explicitly deletes both reactions authored by the deleted user and reactions on the deleted user's memos, in the same transaction as the user deletion, for all three supported backends.
