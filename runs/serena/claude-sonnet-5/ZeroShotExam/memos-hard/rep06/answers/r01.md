**Premise correction:** There is no Redis-backed cache layer in this repository. A search for "redis" across the entire codebase (excluding `node_modules`/`.git`) returns zero matches, and there's no `redis` dependency in `/bench/repo/go.mod` or `/bench/repo/web/pnpm-lock.yaml`.

**Actual mechanism:** Caching in this repo is done in-process/client-side, not via Redis:
- Frontend TanStack Query cache config: `web/src/lib/query-client.ts`
- A local memo editor draft cache: `web/src/components/MemoEditor/services/cacheService.ts` (tested in `web/tests/memo-editor-cache.test.ts`)
- Various `useXQueries.ts` hooks (`useMemoQueries.ts`, `useInstanceQueries.ts`, `useAttachmentQueries.ts`, `useMemoShareQueries.ts`) that layer query caching on top of the API, again via TanStack Query, not Redis.

There's no dedicated "user entries" TTL tied to a Redis store — any TTL-like behavior would be TanStack Query's `staleTime`/`gcTime` settings in `query-client.ts`, not a Redis expiry.
