**How the URL gets into the browser:** the API converter rewrites a base64 avatar into a relative URL — `convertUserFromStore` → `userpb.AvatarUrl = fmt.Sprintf("/file/%s/avatar", userpb.Name)` where `Name` is `users/{username}` (`server/router/api/v1/user_service_converters.go:16-40`). The React `<img src>` comes from that field (`web/src/components/UserAvatar.tsx`).

**Request path `GET /file/users/{username}/avatar` → stored data:**

- `FileServerService.RegisterRoutes` (route `GET /file/users/:identifier/avatar`) — server/router/fileserver/fileserver.go:120-125 (wired up in server/server.go:81-82)
- `FileServerService.serveUserAvatar` — server/router/fileserver/fileserver.go:159-205 (handler; anonymous gate via `getCurrentUser` → `auth.Authenticator.AuthenticateToUser` when the instance disallows anonymous)
- `FileServerService.getUserByUsername` — server/router/fileserver/fileserver.go:640-643
- `Store.GetUser` (with `store.FindUser{Username: &identifier}`; user cache is keyed by ID only, so a username lookup always falls through) — store/user.go:148-169
- `Store.ListUsers` — store/user.go:136-146
- `Driver.ListUsers` (interface) — store/driver.go:47
- `DB.ListUsers` — `SELECT ... avatar_url ... FROM user WHERE username = ?` — store/db/sqlite/user.go:88-203 (parallel impls: store/db/postgres/user.go, store/db/mysql/user.go)

**Back out:** the returned `user.AvatarURL` is a `data:<mime>;base64,...` string stored in the `user.avatar_url` column; `parseDataURI` (fileserver.go:661-675) decodes it, `avatarAllowedTypes` (fileserver.go:72-80) restricts the MIME type, and the bytes are written with `c.Blob` plus `setSecurityHeaders` and `Cache-Control: public, max-age=3600`.

Note there is no per-user authorization beyond the anonymous check — any authenticated viewer (or anyone, on an instance with `InstanceURL` set) can fetch any user's avatar by username.
