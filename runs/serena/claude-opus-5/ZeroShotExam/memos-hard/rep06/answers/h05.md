**Mechanism: explicit Go code** — two `DELETE FROM reaction` statements inside the transactional `DeleteUser` implementation of every DB driver. There is no FK/cascade on the `reaction` table.

**What I checked**

1. **Driver-level delete path.** `store.Store.DeleteUser` (`store/user.go:171`) delegates to `driver.DeleteUser`, implemented per-driver in `store/db/{sqlite,postgres,mysql}/user_delete.go`. Each runs everything in one transaction and calls, in `deleteUserTargetsTx` (`store/db/sqlite/user_delete.go:92-105`, same shape in postgres/mysql at line 96 and 102):
   - `deleteReactionsByContentIDsTx` — `DELETE FROM reaction WHERE content_id IN (...)` over the deleted user's memo content IDs (`memos/<uid>`), i.e. *other people's* reactions on this user's memos. sqlite `:380-387`, postgres `:380-387`, mysql `:417-427`.
   - `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?`, i.e. the user's own reactions anywhere. sqlite `:400-403`, postgres `:400-403`, mysql `:437-440`.

   Both are batched (`deleteUserBatchSize = 500`) and run before the `DELETE FROM user` at the end of the same tx.

2. **Schema — no database rule.** The `reaction` table has no foreign key or cascade in any dialect: `store/migration/sqlite/LATEST.sql:91-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98`, and the original `0.20/00__reaction.sql` for each dialect. Grepping `FOREIGN KEY|REFERENCES|ON DELETE` across `store/migration/` shows the only cascade in the current schema is `memo_share.memo_id → memo(id)` (`LATEST.sql:108-109`); the `user`-referencing cascades appear only in superseded 0.3–0.5 migrations, never on `reaction`.

3. **Test confirmation.** `store/test/user_delete_test.go:97-113, 216-220` seeds three reactions (peer→user's memo, user→peer's memo, peer→peer's memo) and asserts only the third survives — confirming both deletion rules and that unrelated reactions are untouched. Also exercised at API level in `server/router/api/v1/test/user_service_delete_test.go`; the API entrypoint is `APIV1Service.DeleteUser` (`server/router/api/v1/user_service.go:393-414`), which adds no reaction handling of its own.
