**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package: `internal/idp`** — `internal/idp/idp.go` defines the provider-agnostic contract, the `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any IdP implementation must produce.
- **Implementation package: `internal/idp/oauth2`** — `internal/idp/oauth2/oauth2.go` is the only concrete protocol implementation ("Package oauth2 implements the OAuth2 identity provider integration"). It wraps `storepb.OAuth2Config`, exposes `NewIdentityProvider`, `ExchangeToken` (with optional PKCE `code_verifier`), and a user-info fetch that maps provider fields via `config.FieldMapping` into `idp.IdentityProviderUserInfo`.

Consumer side: `server/router/api/v1/auth_service_sso.go:12-13` imports both packages and dispatches on the stored provider config, resolving/provisioning the local user in `resolveSSOUser`. Provider configuration types live in the generated store protos (`storepb.IdentityProvider`, `storepb.OAuth2Config`).

No SAML, OIDC-specific, or LDAP package exists in the tree — OAuth2 is the sole shipped protocol implementation.
