h15.

Memo visibility is enforced in many places — there is no single chokepoint. The distinct enforcement sites:

**Core API (Connect/gRPC, `server/router/api/v1/`)**

- Single-memo read gate `checkMemoReadAccess` (public → open; protected → any authed user; private → creator only) — `server/router/api/v1/memo_service.go:39-68` (callers: `GetMemo` :356, parent-memo resolution :367, `ListMemoComments` :148)
- List-query visibility injection in `ListMemos` (anonymous → `VisibilityList=[PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:217-227`, translated to SQL in `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`
- Comment list filter (`MemoFilter` on relations) — `server/router/api/v1/memo_service_comments.go:156-161`
- Comment creation gate + forced inheritance of parent visibility — `server/router/api/v1/memo_service_comments.go:33-52`
- Memo-relation listing filter — `server/router/api/v1/memo_relation_service.go:107-131`
- Relation expansion during memo conversion (`batchConvertMemoRelations`) — `server/router/api/v1/memo_service_converter.go:182-206`
- Reactions: list and upsert — `server/router/api/v1/reaction_service.go:29-41` and `:83`
- Attachment access via memo (`checkAttachmentAccess`) — `server/router/api/v1/attachment_service.go:422-454`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:213-226`
- User stats (`ListAllUserStats`, `GetUserStats`) — `server/router/api/v1/user_service_stats.go:77-92` and `:216-221`

**Raw file HTTP surface**

- `checkAttachmentPermission` (public + anonymous-allowed → open; share-token fallback; else authed and private ⇒ creator/admin) — `server/router/fileserver/fileserver.go:650-703`

**Realtime SSE fan-out**

- Per-client delivery filter `SSEClient.canReceive` (private events only to creator/admin; unknown visibility denied) — `server/router/api/v1/sse_hub.go:134-144`, with visibility stamped onto events in `server/router/api/v1/sse_event_helpers.go:29-37` and carried in `sse_hub.go:31-32`

**Notification / inbox / email delivery**

- Inbox notification gating `canViewerAccessMemo` — `server/router/api/v1/user_service_notifications.go:302-317` (used at :337, :342, :370, :385)
- Email notification gating, separate copy of `canViewerAccessMemo` — `server/notification/email.go:306-321` (used at :155, :187)
- Mention notification gating `canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-90`

**Anonymous public surfaces (hardcoded PUBLIC-only)**

- RSS feeds (instance + per-user) — `server/router/rss/rss.go:90` and `:141`
- Sitemap XML — `server/router/frontend/frontend.go:149-151`

**Deliberate bypass (token-gated instead of visibility-gated)**

- `GetMemoByShare` skips the visibility check entirely; the gate is share-token validity + expiry + non-archived — `server/router/api/v1/memo_share_service.go:153-207`

Note: the MCP surface is not a separate enforcement site — `server/router/mcp/catalog.go:12-14` exposes `MemoService_ListMemos`/`GetMemo`, which route through the same API handlers above.
