**delivery function — `webhook.Post` at `internal/webhook/webhook.go:120` (executed off the request path by background workers draining `asyncPostQueue`, started in `init()` at `internal/webhook/webhook.go:42-55`; callers enqueue via `webhook.PostAsync`, `internal/webhook/webhook.go:184`); protection mechanism — `safeDialContext` at `internal/webhook/webhook.go:59`, backed by `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go:14-54`**

How it fits together:

- **Trigger:** memo create/update/delete and comment-created call `webhook.PostAsync` for each of the creator's stored webhooks (`server/router/api/v1/memo_service_webhooks.go:43,71`). `PostAsync` pushes onto a 128-slot buffered channel and drops (with a warning) if full.
- **Execution:** four goroutines started in `init()` consume that channel and call `Post`, which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and issues the POST through the shared `safeClient` (`internal/webhook/webhook.go:152`).
- **SSRF protection (the enforcing layer):** `safeClient`'s `http.Transport` uses `safeDialContext`, which resolves the hostname at *dial* time and refuses to connect if any resolved IP falls in a reserved range — loopback, RFC-1918, link-local/169.254.169.254 (cloud IMDS), and the IPv6 equivalents (`internal/webhook/validate.go:14-23`). Because the check happens at dial time on the addresses actually being connected to, it also defeats DNS rebinding.
- **Second layer (validation, not enforcement):** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is applied when a user creates/updates a webhook (`server/router/api/v1/user_service_webhooks.go:74,161,182`) — it requires an absolute http/https URL and rejects hostnames resolving to reserved IPs. This is a UX-level early rejection; it's TOCTOU-prone on its own, which is why the dial-time check exists.
- **Escape hatch:** both checks share `isReservedIP`, which short-circuits to `false` when `webhook.AllowPrivateIPs` is set — wired to the `--allow-private-webhooks` flag / viper key in `cmd/memos/main.go:49,133,160` (default `false`) for self-hosters targeting LAN services.

One thing worth flagging: `AllowPrivateIPs` is a plain package-level `bool` read by dispatch goroutines while `main.go:49` writes it at startup — fine in practice given the write precedes serving, but it's an unsynchronized global if anything ever sets it later.
