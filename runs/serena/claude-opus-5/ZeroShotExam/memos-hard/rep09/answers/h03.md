**`internal/idp`; `internal/idp/oauth2`**

**Abstraction — `internal/idp`** (`internal/idp/idp.go`): defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any IdP implementation must produce. This is the only type in the package — the abstraction is the normalized user-info contract, not a Go interface.

**Implementation — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the sole concrete protocol, documented as "Package oauth2 implements the OAuth2 identity provider integration." It exposes `IdentityProvider` backed by `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (including PKCE `codeVerifier` support), and `UserInfo`, which maps remote claims through the configured `FieldMapping` into `idp.IdentityProviderUserInfo`.

Supporting evidence that OAuth2 is the only shipped protocol:
- `proto/api/v1/idp_service.proto:76-87` — the `Type` enum has just `TYPE_UNSPECIFIED` and `OAUTH2`, and `IdentityProviderConfig` is a `oneof` with a single member, `OAuth2Config`.
- `server/router/api/v1/auth_service_sso.go:119-134` — SSO login branches on `storepb.IdentityProvider_OAUTH2` alone, constructing the provider via `oauth2.NewIdentityProvider(...)` and returning `*idp.IdentityProviderUserInfo`.
- `internal/idp/` contains only `idp.go` and the `oauth2/` subdirectory; no other protocol (OIDC, SAML, LDAP) package exists.
