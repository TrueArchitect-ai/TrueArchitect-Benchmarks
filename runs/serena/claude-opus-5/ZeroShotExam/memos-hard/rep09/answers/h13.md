**`*markdown.service` (the sole goldmark-backed impl) — built once in `NewAPIV1Service`, then shared — held by `APIV1Service`, `RSSService`, and `memopayload.Runner`.**

### The interface
`markdown.Service` — `internal/markdown/markdown.go:31-55` — declares `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

### Concrete implementation
Exactly one: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:57-60`), returned as the interface from `NewService(opts ...Option)` (`markdown.go:85-113`). There are no alternative impls, mocks, or fakes anywhere in the repo — `ExtractAll` has a single method definition (`markdown.go:356`). Internally it delegates markdown-out rendering to `renderer.NewMarkdownRenderer()` (`internal/markdown/renderer/markdown_renderer.go`, used at `markdown.go:250` and `markdown.go:451`) and gets `#tag`/`@mention` parsing from `internal/markdown/extensions/{tag,mention}.go`.

### Who constructs it
- **Runtime, the only production construction:** `NewAPIV1Service` at `server/router/api/v1/v1.go:47-56`, configured with `WithTagExtension()` + `WithMentionExtension()`. `server/server.go:76` calls it, then passes the *same* instance to RSS at `server/server.go:85` (`rss.NewRSSService(..., apiV1Service.MarkdownService)`) — so one shared instance serves the whole process.
- **Tests only:** `server/router/api/v1/test/test_helper.go:44`, `server/router/fileserver/fileserver_test.go:427` (tags only), `server/router/rss/rss_test.go:54` (`markdown.NewService()` with no extensions).

One caveat worth flagging: `memopayload.Runner` holds the interface but is effectively dormant — `memopayload.NewRunner` (`runner.go:19`) has no callers anywhere in the repo, and `server.go` only wires up `s3presign.NewRunner` (`server.go:162`). At runtime the payload rebuild path is the free function `RebuildMemoPayload(ctx, memo, s.MarkdownService)` called directly from the memo service, which takes the interface as a parameter rather than via the struct.

The frontend is a separate, non-interfaced path: `web/src/components/MemoContent/MemoMarkdownRenderer.tsx` renders with `react-markdown` + remark/rehype plugins directly. Note the interface's doc comment (`markdown.go:29`) says the frontend uses "markdown-it" — that's stale.
