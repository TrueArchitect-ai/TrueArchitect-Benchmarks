**Premise correction: there is no per-user API rate-limiting middleware in this repository.** Memos has no rate limiter — no per-user request quotas, no token buckets, no 429/`ResourceExhausted` rate-limit responses, and no rate-limiting library dependency (`golang.org/x/time` appears in `go.mod:151` only as an indirect transitive dependency, not used by any first-party code).

**What is actually registered as middleware:**

- `server/server.go:51-52` — the only Echo-level middleware: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go`).
- `server/router/api/v1/v1.go:133-137` — the Connect RPC interceptor chain, in order: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor`. All four are defined in `server/router/api/v1/connect_interceptors.go`; none does rate limiting. `AuthInterceptor` (line 205 onward) enforces authentication and anonymous-access policy only.

**The "limits" that do exist are size caps and concurrency semaphores, not per-user request rates:**

| Limit | Location | Value |
|---|---|---|
| Max API request body | `server/router/api/v1/v1.go:20`, applied at lines 126, 141, 144 | 256 MiB (`256 << 20`) |
| Attachment upload size | `server/router/api/v1/attachment_service.go:120-125` | instance-configured `UploadSizeLimitMb`; falls back to `MaxUploadBufferSizeBytes` = 32 MiB (`attachment_service.go:27`) |
| Audio transcription size | `server/router/api/v1/ai_service.go:24` | 25 MiB |
| Concurrent image (EXIF) processing | `server/router/api/v1/v1.go:60`, acquired in `attachment_service_image.go:67-78` | 2 slots, server-wide |
| Concurrent thumbnail generation | `server/router/api/v1/v1.go:59` and `server/router/fileserver/fileserver.go:46,116,448` | 3 slots, server-wide |

Two clarifications about things that look like rate limiting but aren't:

- `server/router/api/v1/attachment_service.go:160` returns `codes.ResourceExhausted, "too many image processing requests"` — this fires when the **global** 2-slot `imageProcessingSemaphore` can't be acquired (context cancellation/deadline). It's a shared concurrency gate, not a per-user quota; one user's uploads contend with everyone's.
- `internal/scheduler/middleware.go` defines a `Middleware` type, but it wraps background **job handlers** (`Recovery`, `Logging`, `Timeout`), not HTTP/RPC requests.

The only mentions of rate limiting in the codebase are aspirational notes about email sending: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") and `internal/email/README.md:286-295`, which sketch an unimplemented `RateLimiter` as a suggested integration.
