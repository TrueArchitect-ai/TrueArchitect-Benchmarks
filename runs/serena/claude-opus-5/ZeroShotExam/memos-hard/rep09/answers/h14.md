**Computation site**: `memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`), which delegates the actual parsing to the markdown service's single-pass AST walk `(*service).ExtractAll` (`internal/markdown/markdown.go:356-420`). The result is stored on `memo.Payload.Property` (schema: `proto/store/memo.proto:14-21`) and surfaced to the API via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315`).

**Triggers (recomputation)**:
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before the memo is inserted.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only when `content` is in the update mask; the rebuilt payload is written along with the new content (`update.Payload = memo.Payload`).
- Bulk backfill — `Runner.RunOnce` in `server/runner/memopayload/runner.go:26-72` re-derives the payload for all memos in batches of 100 and persists each via `Store.UpdateMemo`. Note this runner is defined but not currently invoked from `server/server.go` (only `s3presign.NewRunner(...).RunOnce` is wired there at `server/server.go:162-163`).

**Extracted properties** (`storepb.MemoPayload_Property`):
- `has_link` — a `gast.KindLink` node exists (`markdown.go:393-394`)
- `has_code` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan` (`markdown.go:396-397`)
- `has_task_list` — any `east.KindTaskCheckBox` (`markdown.go:399-400`)
- `has_incomplete_tasks` — at least one task checkbox with `IsChecked == false` (`markdown.go:401-404`)
- `title` — text of the first block-level child of the document if it's an H1 heading, via `extractHeadingText` (`markdown.go:384-388`, `markdown.go:173`)

The same `ExtractAll` pass also fills `memo.Payload.Tags` (deduped, case-preserving) alongside `Property`. These four booleans plus `title` are what the filter layer exposes as `has_link` / `has_code` / `has_task_list` / `has_incomplete_tasks` (`internal/filter/schema.go:197-243`) and what user stats aggregate (`server/router/api/v1/user_service_stats.go:141-151`). Separately, the list/preview `snippet` is *not* stored — it's computed per-response by `GenerateSnippet` during conversion (`memo_service_converter.go:76`, `internal/markdown/markdown.go:264`).
