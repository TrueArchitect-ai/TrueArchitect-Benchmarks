**No** — outside the driver-selection factory, the MySQL driver is never constructed. The only near-exception is a zero-value struct literal in an in-package unit test, which creates no connection.

Evidence:

1. **The factory is the sole caller of `mysql.NewDB`.** `store/db/db.go:14-30` — `NewDBDriver(profile)` switches on `profile.Driver` and calls `mysql.NewDB(profile)` for the `"mysql"` case (`store/db/db.go:22`). `mysql.NewDB` is defined at `store/db/mysql/mysql.go:20` and is the only constructor exported by the package.

2. **No other file in the repo imports the mysql driver package.** `grep -rn "usememos/memos/store/db/mysql"` across all `*.go` returns exactly one hit outside the package itself: `store/db/db.go:8`. Since Go requires an import to reference `mysql.NewDB`/`mysql.DB`, that single import proves no external construction site exists.

3. **Callers go through the factory.** `store/test/store.go:28` and `store/test/store.go:50` obtain drivers via `db.NewDBDriver(profile)`; the test harness in `store/test/containers.go` only spins up a MySQL *container* and builds DSN strings (it imports `go-sql-driver/mysql` and `testcontainers/.../mysql`, not the internal driver package).

4. **The one direct literal is an in-package test stub, not a driver construction.** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — a zero-value struct inside `package mysql` used solely to call the pure helper `IsRetryableAuthenticationMutationError`. It opens no `*sql.DB` and is not reachable from outside the package (`DB`'s fields `db`, `profile`, `config` are unexported, `store/db/mysql/mysql.go:14-18`, so external packages couldn't meaningfully build one anyway).

Note that other packages referencing "mysql" (e.g. `internal/profile/profile.go`, `store/db/db.go` dialect switches, `server/router/api/v1/*.go`) only branch on the driver *name string* or use the upstream `go-sql-driver/mysql` package for DSN parsing/error codes — none construct the internal driver.
