**Premise correction:** There is no GraphQL schema anywhere in this repository. Memos does not expose a GraphQL API — a search for `graphql` across the codebase (Go, TS, JSON, Markdown) returns zero hits. The public API is defined in **Protocol Buffers**, served as gRPC, Connect, and REST (via gRPC-Gateway).

**Actual API surface**

*Schema definitions* — `proto/api/v1/`, one `.proto` file per service, each with `google.api.http` annotations that map RPCs to REST paths:

| File | RPCs |
|---|---|
| `proto/api/v1/user_service.proto` | 26 |
| `proto/api/v1/memo_service.proto` | 20 |
| `proto/api/v1/instance_service.proto` | 6 |
| `proto/api/v1/attachment_service.proto` | 6 |
| `proto/api/v1/shortcut_service.proto` | 5 |
| `proto/api/v1/idp_service.proto` | 5 |
| `proto/api/v1/auth_service.proto` | 4 |
| `proto/api/v1/ai_service.proto` | 1 |
| `proto/api/v1/common.proto` | shared types only |

Example of the REST mapping, `proto/api/v1/memo_service.proto:29`:
```proto
rpc ListMemos(ListMemosRequest) returns (ListMemosResponse) {
  option (google.api.http) = {get: "/api/v1/memos"};
}
```

*Code generation* — `proto/buf.gen.yaml` drives it, emitting Go message/gRPC/Connect/gateway stubs into `proto/gen/api/v1/`, an OpenAPI spec via the gnostic plugin, and TypeScript clients into `web/src/types/proto` for the frontend.

*Serving* — `server/router/api/v1/v1.go:65` (`RegisterGateway`) wires everything onto Echo:
- `/api/v1/*` and `/file/*` → gRPC-Gateway REST handler (`v1.go:128-129`)
- `/memos.api.v1.*` → Connect RPC handler (`v1.go:144`)
- plus a native gRPC server, registered from `server/server.go:88`

*Implementations* live alongside in `server/router/api/v1/` (`memo_service.go`, `user_service.go`, etc.).

*OpenAPI spec* — generated to `proto/gen/openapi.yaml` and embedded into the binary by `proto/openapi_embed.go`.

The design convention is documented in `proto/api/v1/README.md`: the API follows [Google's API Improvement Proposals](https://google.aip.dev/) (resource names like `memos/*`, `users/*`, standard List/Get/Create/Update/Delete verbs) — which is also why the README advertises "full REST and gRPC APIs" and never mentions GraphQL.
