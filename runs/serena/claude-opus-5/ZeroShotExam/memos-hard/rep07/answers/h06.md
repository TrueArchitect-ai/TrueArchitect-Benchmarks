All six load the creator's (or, for comments, the parent memo owner's) webhook rows via `s.Store.GetUserWebhooks`, set `payload.URL = hook.Url`, and call `webhook.PostAsync` — `server/router/api/v1/memo_service_webhooks.go:43,71`.

**Convergence function:** `webhook.Post` — `internal/webhook/webhook.go:120`.

`PostAsync` (`webhook.go:184`) only enqueues onto `asyncPostQueue`; the four worker goroutines started in `init()` (`webhook.go:42-55`) call `Post`, so every path — sync or async — builds the `POST` request, signs it (HMAC-SHA256, Standard Webhooks headers) and issues it through the shared `safeClient` at `webhook.go:152`. That client's transport uses `safeDialContext` (`webhook.go:59`) to reject reserved/private IPs at dial time.

The URL is user-configured through `CreateUserWebhook`/`UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:71-94, 159-185`), validated by `webhook.ValidateURL`.

Note: there are other outbound-HTTP paths in the codebase that do *not* pass through `webhook.Post` — link-metadata fetching (`internal/httpgetter/html_meta.go`), OIDC user-info (`internal/idp/oauth2/oauth2.go:84`), and the AI STT/audio-LLM clients (`internal/ai/stt`, `internal/ai/audiollm`). Those use their own clients and have no SSRF dial guard.
