**No** — in production code the MySQL driver is only ever constructed through the factory. The one exception is a zero-value struct literal in an in-package unit test.

Evidence:

- `store/db/db.go:22` — `NewDBDriver` is the sole caller of `mysql.NewDB(profile)`, inside the `switch profile.Driver` dispatch alongside `sqlite.NewDB` and `postgres.NewDB`.
- `store/db/db.go:8` is the **only** import of `github.com/usememos/memos/store/db/mysql` anywhere in the repo. Grepping for that import path and for `mysql.New` across all `*.go` files returns no other hits, so no package outside `store/db` can call the constructor. (By contrast, `sqlite.NewDB` *is* called directly in tests — `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416` — which shows the grep would have surfaced equivalent MySQL usage had it existed.)
- All other test/bootstrap paths go through the factory: `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(...)`; `store/test/containers.go` only sets up a MySQL testcontainer and DSN string (`store/test/containers.go:101-131`), leaving driver creation to the factory.
- Direct construction of the `DB` struct: grepping `DB{` under `store/db/mysql/` yields exactly two sites — `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`, inside `NewDB` itself) and `store/db/mysql/auth_config_test.go:12` (`db := &DB{}`). The latter is an in-package test that builds an empty struct purely to invoke the pure method `IsRetryableAuthenticationMutationError`; it never opens a connection and no `*sql.DB` is set.

Other references to "mysql" outside the package are to the third-party `github.com/go-sql-driver/mysql` library or the testcontainers module, not to the memos MySQL driver.
