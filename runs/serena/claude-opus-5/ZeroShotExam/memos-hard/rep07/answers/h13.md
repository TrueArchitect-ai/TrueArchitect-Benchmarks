**`*markdown.service` (the only concrete impl) — built by `markdown.NewService(...)`, called once at runtime in `NewAPIV1Service` — held by `APIV1Service`, `RSSService`, and (unwired) `memopayload.Runner`.**

Details:

**The interface** — `markdown.Service` (`internal/markdown/markdown.go:31`), a goldmark-backed facade with `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

**Implementation** — exactly one: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:57-59`). There is no mock, fake, or decorator implementing `Service` anywhere in the tree (verified by grep across `*.go`, including tests). Variation comes from options, not types: `WithTagExtension()` / `WithMentionExtension()` (`markdown.go:70-83`) change which goldmark extenders are registered on the same `*service`.

**Construction** — `markdown.NewService(...)` (`internal/markdown/markdown.go:86`) is the sole constructor. In production it's called exactly once, in `NewAPIV1Service` with both tag and mention extensions enabled (`server/router/api/v1/v1.go:48-50`); that single instance is then handed to the RSS router by `server/server.go:85` (`rss.NewRSSService(..., apiV1Service.MarkdownService)`). Other calls are test-only: `server/router/api/v1/test/test_helper.go:44`, `server/router/rss/rss_test.go:54`, `server/router/fileserver/fileserver_test.go:427` (the last with tags only, no mentions).

**Holders of the interface type**
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — used for `GenerateSnippet` in webhook payloads (`memo_service_webhooks.go:85`), `ExtractAll` for mentions (`memo_mention_helpers.go:32`), and passed into `memopayload.RebuildMemoPayload` on memo create/update (`memo_service.go:108`, `:447`).
- `RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — server-side `RenderHTML` for feed item content (`rss.go:339`).
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) — holds the interface, but `NewRunner` has no caller outside its own package, so this holder does not execute at runtime; the live path into that package is the free function `RebuildMemoPayload(ctx, memo, markdownService)` (`runner.go:74`), which takes the interface as a parameter rather than holding it.

Note: this interface is backend-only. The web client does its own markdown work via react-markdown/remark plugins (`web/src/components/MemoContent/MemoMarkdownRenderer.tsx`, `web/src/utils/remark-plugins/`), unrelated to `markdown.Service` — the Go side exists for metadata extraction, snippets, and RSS HTML, as the interface's doc comment states.
