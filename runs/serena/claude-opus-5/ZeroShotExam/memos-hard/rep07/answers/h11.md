**1st: `store.User` (~7 packages outside the store layer); 2nd: `store.Memo` (~6 packages).**

The data layer is the `store` package (`store/store.go`, with entity types declared in `store/user.go`, `store/memo.go`, `store/attachment.go`, etc.). Counting distinct Go packages *outside* `store/...` that reference each entity type:

|---|---|---|
| `User` | `store/user.go:29` | 7 — `server/auth` (`authenticator.go`, `context.go`), `server/notification` (`email.go`), `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss` |
| `Memo` | `store/memo.go:35` | 6 — `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload` (`runner.go`) |

Notes on scope: I excluded `store/db/{sqlite,mysql,postgres}` and `store/test` as part of the data layer itself; they reference nearly every entity. If test packages are also excluded, the ranking is unchanged (`User` 6, `Memo` 5). `User` also leads by raw reference count (~110 vs ~60 references outside `store/`), largely because it is threaded through auth (`server/auth/authenticator.go`) and every API converter (`server/router/api/v1/user_service.go`, `memo_service_converter.go`).
