**delivery function — `Post` in `internal/webhook/webhook.go:120`** (the actual outbound HTTP POST is at `internal/webhook/webhook.go:152`, `safeClient.Do(req)`); **protection mechanism — `safeDialContext` / `isReservedIP` in `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

Details:

**Where delivery executes**
- `server/router/api/v1/memo_service_webhooks.go` builds the payload on memo create/update/delete and comment-created events, then calls `webhook.PostAsync` (lines 43, 71).
- `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel `asyncPostQueue`, dropping with a warning if full.
- Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`. So the real network call happens in `Post` on a background worker, not on the request goroutine.
- `Post` marshals the JSON body, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and issues `safeClient.Do(req)` with a 30s timeout, reading at most 1 MiB of the response.

**What protects it from internal addresses (two layers)**
1. **Dial-time block (the one that actually protects delivery):** `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37, 59-77`). It splits host/port, resolves the host, and refuses to dial if any resolved IP is reserved. Because the check happens at dial time on every request, it also defeats DNS rebinding — a hostname that validated as public at registration time can't later point at loopback.
2. **Registration-time validation:** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates/updates a webhook (`server/router/api/v1/user_service_webhooks.go:74, 161, 182`). It requires an absolute http/https URL and rejects hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument`.

Both layers share `isReservedIP` (`internal/webhook/validate.go:44`), which tests against `reservedCIDRs` parsed once at startup: IPv4 loopback, the three RFC-1918 ranges, `169.254.0.0/16` (link-local, covering the cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, and `fe80::/10`.

One caveat worth flagging: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) disables both layers when true, for self-hosted deployments targeting LAN services. It has no setter or wiring anywhere in the repo — grep finds references only within `validate.go` — so it is effectively always `false` unless code elsewhere is added to set it.
