**Premise correction: this repository (Memos) has no per-user API rate-limiting middleware.** Nothing registers one, so there are no request limits to report.

What I verified:

- **Repo-wide search** for `rate limit` / `ratelimit` / `limiter` / `throttle` / `quota` / `burst` in Go sources returns no implementation. The only two hits are aspirational docs: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse", in a future-work list) and `internal/email/README.md:286` ("### 5. Implement Rate Limiting", a suggested pattern for consumers). No rate-limiting library (`golang.org/x/time/rate`, tollbooth, ulule/limiter) appears in `go.mod`/`go.sum`.
- **The actual HTTP middleware chain** is in `server/server.go:51-52` — only `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go`).
- **The actual RPC interceptor chain** is `server/router/api/v1/v1.go:133-138`: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` (defined in `server/router/api/v1/connect_interceptors.go`). No rate-limit interceptor.
- No 429 / `StatusTooManyRequests` path exists anywhere; there is no login-attempt throttling in `server/router/api/v1/auth_service.go` or `auth_service_session.go`.

The two limits that do exist are unrelated to per-user rate limiting:

| Limit | Location | Value | Scope |
|---|---|---|---|
| Max API request body size | `server/router/api/v1/v1.go:20`, applied at `:126`, `:141`, `:144` | `maxAPIRequestBytes = 256 << 20` (256 MiB) | Per request, all clients |
| Concurrent image (EXIF-strip) processing | `server/router/api/v1/v1.go:41,60`; acquired in `attachment_service_image.go:67-77` | `semaphore.NewWeighted(2)` — 2 concurrent slots | Process-wide, not per user |

That semaphore is the only thing that ever returns `ResourceExhausted` (`server/router/api/v1/attachment_service.go:160`, "too many image processing requests"), but it's a global concurrency gate that blocks rather than a rate limit, and it isn't keyed by user — one user's uploads can saturate both slots for everyone.
