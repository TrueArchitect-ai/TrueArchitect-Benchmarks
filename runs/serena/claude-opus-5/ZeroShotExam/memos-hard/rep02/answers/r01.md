**Premise correction:** There is no Redis (or any external cache server) in this repo. `grep -ri redis` across all Go, config, docs, and frontend files returns nothing, and `go.mod` has no Redis client dependency. Memos is a single-binary app — the cache layer is purely in-process.

**Actual mechanism**

- **Implementation:** `store/cache/cache.go` — a thread-safe in-memory cache built on `sync.Map` plus an `atomic.Int64` item counter, with a background cleanup goroutine (`cleanupLoop`, `store/cache/cache.go:200`). No network connection is involved; nothing is configured via env vars or connection strings.

- **Where it's "configured":** `store.New()` in `store/store.go:36-58` hardcodes a single `cache.Config` shared by all three caches:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  - `OnEviction: nil`

  The same values are duplicated in `cache.DefaultConfig()` (`store/cache/cache.go:59`). There's no way to override them at runtime — no flag, env var, or setting reads these.

- **User entries specifically:** users live in `Store.userCache` (`store/store.go:28`), keyed by the stringified user ID (`userCacheKey`, `store/user.go:88`). Writes go through `Set` (`store/user.go:98,122,132,143,167`), which delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). So **user entries get the same 10-minute TTL** — there is no user-specific TTL anywhere; `SetWithTTL` is never called with a custom duration outside the cache package's own tests.

Two caveats on that 10 minutes being an upper bound, not a guarantee:
- Entries can be evicted early when the cache exceeds `MaxItems: 1000` — `cleanupOldest` (`store/cache/cache.go:257`) drops ~20% of entries regardless of expiry.
- Explicit invalidation happens on user deletion (`store/user_delete.go:40`); updates overwrite the entry and reset its expiry.

Expiry itself is enforced lazily on `Get` (`store/cache/cache.go:132`) as well as by the 5-minute sweep, so a stale entry is never returned even between sweeps.

The sibling caches — `instanceSettingCache` and `userSettingCache` (`store/store.go:27,29`) — share the identical config.
