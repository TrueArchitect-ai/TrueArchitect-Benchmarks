**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider implementation normalizes its user data into. The type taxonomy lives alongside it in `proto/store/idp.proto:11-24` — `IdentityProvider.Type` enum plus a `IdentityProviderConfig` oneof, which is the extension point for additional protocols.

- **Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol shipped. `NewIdentityProvider(*storepb.OAuth2Config)` validates required config fields, `ExchangeToken` performs the code-for-token exchange (with optional PKCE `code_verifier`), and `UserInfo` fetches and field-maps the profile into `idp.IdentityProviderUserInfo`.

Wiring: `server/router/api/v1/auth_service_sso.go:119-133` branches on `storepb.IdentityProvider_OAUTH2` — the single case in that switch — and calls into the oauth2 package. The enum in `proto/store/idp.proto` has exactly one non-unspecified value (`OAUTH2 = 1`), and `internal/idp/` contains only the `oauth2` subdirectory, confirming no OIDC or SAML implementation ships.
