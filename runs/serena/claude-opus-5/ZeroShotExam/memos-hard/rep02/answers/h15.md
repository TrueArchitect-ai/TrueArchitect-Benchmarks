Memo-visibility enforcement is spread across several independent server surfaces (there is no single chokepoint — each surface re-implements the PUBLIC/PROTECTED/PRIVATE rule):

**Single-memo read gate (gRPC/Connect API)**
- `checkMemoReadAccess` — the canonical per-memo gate (archived → creator only; non-public → must be authenticated; private → creator only) — `server/router/api/v1/memo_service.go:39-67`, called from `GetMemo`/parent-memo lookup (`server/router/api/v1/memo_service.go:356`, `:367`) and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)

**Query-level (list) filtering — visibility pushed into the store query**
- `ListMemos` visibility list / CEL filter — `server/router/api/v1/memo_service.go:217-227`
- `ListMemoComments` child-comment filter (`visibility == "PUBLIC"` / `creator_id == N || visibility in [...]`) — `server/router/api/v1/memo_service_comments.go:156-161`
- User stats (`ListAllUserStats`, `GetUserStats`) — `server/router/api/v1/user_service_stats.go:84-92`, `:217-221`
- Store-side translation of `FindMemo.VisibilityList` into SQL — `store/memo.go:69`, `store/db/sqlite/memo.go:96`, `store/db/mysql/memo.go:104`, `store/db/postgres/memo.go:89`

**Attachment / file serving (separate HTTP surface, own copy of the rule)**
- `FileServerService.checkAttachmentPermission` — memo-derived visibility plus anonymous-instance and `share_token` fallbacks — `server/router/fileserver/fileserver.go:650-703`
- Attachment gRPC API `attachment_service.go` visibility check — `server/router/api/v1/attachment_service.go:436-455`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:207-226`

**Reactions**
- `ListMemoReactions` / `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:22-41`, `:74-85`

**Comment creation (write gate on a private parent)**
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:29-43`

**SSE realtime broadcast filtering**
- `SSEClient.canReceive` (private events only to creator/admin; unknown visibility denied) — `server/router/api/v1/sse_hub.go:134-144`, event visibility populated in `server/router/api/v1/sse_event_helpers.go:29-37`

**Anonymous/public feed surfaces (hard-coded PUBLIC only)**
- RSS feeds (instance + per-user) — `server/router/rss/rss.go:90`, `:141`
- Sitemap XML — `server/router/frontend/frontend.go:150`

**Notification / inbox / email content redaction**
- `canViewerAccessMemo` for in-app notifications — `server/router/api/v1/user_service_notifications.go:302-316` (used at `:337`, `:342`, `:370`, `:385`)
- `canViewerAccessMemo` for email notifications — `server/notification/email.go:306-320` (used at `:155`, `:187`)
- Mention inbox/notification gating — `server/router/api/v1/memo_mention_helpers.go:56-89`

**Deliberate bypass (share links)** — worth noting because it is the one path that intentionally skips the visibility check, substituting a token check: `GetMemoByShare` / `getActiveMemoShare` — `server/router/api/v1/memo_share_service.go:153-208` (mirrored by the `share_token` branch in `server/router/fileserver/fileserver.go:683-689`).
