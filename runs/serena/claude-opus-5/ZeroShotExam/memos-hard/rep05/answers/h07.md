**Where the URL comes from:** the gRPC/REST `User` proto never returns the raw base64 avatar. `convertUserFromStore` rewrites it to a relative file URL `/file/users/{username}/avatar` (`server/router/api/v1/user_service_converters.go:32-40`, using `BuildUserName` in `server/router/api/v1/user_resource_name.go:13`). The React `<img src>` is just that string (`web/src/components/UserAvatar.tsx`), so the browser issues a plain GET to `/file/users/{username}/avatar`.

**Hops from that GET to stored data:**

- `FileServerService.RegisterRoutes` (route `GET /file/users/:identifier/avatar`) — `server/router/fileserver/fileserver.go:121-125` (wired in `server/server.go:81-82`)
- `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
- `FileServerService.getCurrentUser` → `auth.Authenticator.AuthenticateToUser` — `server/router/fileserver/fileserver.go:708`, `server/auth/authenticator.go:190` *(only when `Profile.AllowAnonymous()` is false; gate for anonymous viewers, not the data path)*
- `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715`
- `Store.GetUser(ctx, &store.FindUser{Username: &identifier})` — `store/user.go:148` (ID-keyed `userCache` is skipped for a username lookup, so this always falls through)
- `Store.ListUsers` — `store/user.go:136` (delegates to `s.driver`, then populates `userCache`)
- `Driver.ListUsers` interface — `store/driver.go:47`
- `DB.ListUsers` — dialect impl, e.g. `store/db/sqlite/user.go:88` (`SELECT … avatar_url … FROM user WHERE username = ?`, scanned into `store.User.AvatarURL` at `store/db/sqlite/user.go:151-201`); same shape in `store/db/postgres/user.go` and `store/db/mysql/user.go`

**Back out:** the stored `avatar_url` is a base64 data URI in the `user` table; `serveUserAvatar` decodes it via `FileServerService.parseDataURI` (`server/router/fileserver/fileserver.go:737`), rejects types outside `avatarAllowedTypes` (`fileserver.go:75`), sets nosniff/DENY/CSP headers plus `Cache-Control: public, max-age=3600`, and writes the bytes with `c.Blob` (`fileserver.go:205-209`).

Note there is no per-user authorization on this route — any authenticated viewer (or anyone at all, on an instance with `InstanceURL` set) can fetch any username's avatar; the only check is the instance-level anonymous gate at `fileserver.go:173-181`.
