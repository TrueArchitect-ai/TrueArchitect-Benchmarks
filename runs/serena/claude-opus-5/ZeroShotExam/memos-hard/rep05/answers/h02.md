## Where delivery executes

`webhook.Post` (`internal/webhook/webhook.go:120`) is the single function that actually issues the outbound HTTP request. It marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), calls `safeClient.Do(req)` at `internal/webhook/webhook.go:152`, and validates the response (2xx status, `code == 0` in the JSON body, body read capped at 1 MiB).

Callers never invoke `Post` directly. `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a buffered channel (`asyncPostQueue`, capacity 128), drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`); a full queue drops the dispatch with a warning. The API layer fans out to each of the creator's registered hooks in `server/router/api/v1/memo_service_webhooks.go` — `dispatchMemoRelatedWebhook` (line 48) for memo created/updated/deleted, and `DispatchMemoCommentCreatedWebhook` (line 30) for comments.

## What protects it from internal addresses

Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`):

1. **Dial-time enforcement (the real guard).** `safeClient` uses a `Transport` with `DialContext: safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (line 59) resolves the hostname itself and rejects the connection if *any* resolved IP is reserved. Because the check happens at dial time on the same resolution path as the connection, it also defeats DNS rebinding — a TOCTOU attack that a validate-once-at-registration check alone would miss.

2. **Registration-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) requires an absolute `http`/`https` URL that doesn't resolve to a reserved IP, returning a gRPC `InvalidArgument`. It's called when webhooks are created or updated in `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. This is UX-level fail-fast, not the security boundary.

The blocklist is `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` (explicitly covering the cloud IMDS endpoint `169.254.169.254`), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`. Parsed once at startup into `reservedNetworks`.

**Escape hatch:** the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers. It's set from the `--allow-private-webhooks` CLI flag (default `false`) at `cmd/memos/main.go:49`, `:133`, `:160` — intended for self-hosted deployments targeting LAN services.

**Gaps worth noting:** the CIDR list omits `0.0.0.0/8` (`0.0.0.0` and `0.x.y.z` reach loopback on Linux), carrier-grade NAT `100.64.0.0/10`, IPv4-mapped IPv6 (`::ffff:127.0.0.1` parses as a 16-byte IP that `fc00::/7` and friends won't match), and `::/128`. Redirects are also unrestricted at the `http.Client` level — though since `safeDialContext` runs on every dial including redirect targets, a redirect to an internal host still fails at connect time.
