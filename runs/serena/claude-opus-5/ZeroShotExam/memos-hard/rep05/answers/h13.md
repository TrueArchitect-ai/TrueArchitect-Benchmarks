## The interface

`internal/markdown/markdown.go:31` — `markdown.Service`, with `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

## Implementation

There is exactly **one** implementation: the unexported struct `service` (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown`. No mocks, fakes, or alternate implementations exist anywhere in the repo — tests use the real one. Behavior varies only by construction options (`WithTagExtension`, `WithMentionExtension`, `internal/markdown/markdown.go:71-84`), which add the custom `extensions.TagExtension` / `extensions.MentionExtension` on top of `extension.GFM`.

## Construction

`markdown.NewService` (`internal/markdown/markdown.go:87`) is the only constructor. In production it is called **exactly once**, in `NewAPIV1Service` (`server/router/api/v1/v1.go:48-51`), with both tag and mention extensions enabled. That single instance is then threaded outward:

- `server/server.go:76` builds the `APIV1Service`.
- `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService` — the RSS service does not build its own.

Test-only constructions (different option sets, so not runtime paths): `server/router/api/v1/test/test_helper.go:44` (tags + mentions), `server/router/fileserver/fileserver_test.go:427` (tags only), `server/router/rss/rss_test.go:54` (no extensions).
