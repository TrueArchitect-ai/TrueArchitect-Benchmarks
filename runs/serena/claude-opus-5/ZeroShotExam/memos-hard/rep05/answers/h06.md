**Convergence function — `webhook.Post` at `internal/webhook/webhook.go:120`.**

The chain: every `Dispatch*Webhook` funnels into `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`; the comment variant inlines the same loop at `:30`), which loads the creator's stored webhook rows via `Store.GetUserWebhooks`, copies `hook.Url` / `hook.SigningSecret` onto the payload, and calls `webhook.PostAsync` (`webhook.go:184`). `PostAsync` only enqueues onto a 128-slot buffered channel; four worker goroutines started in `init()` (`webhook.go:42-55`) drain it and call `Post`, which is the single place the `POST` to the user-configured URL is actually built and sent (`http.NewRequest` at `:126`, `safeClient.Do` at `:152`).

The URLs are user-configured through `CreateUserWebhook` / `UpdateUserWebhook` (`user_service_webhooks.go:53,106`), validated by `webhook.ValidateURL` at write time; at delivery time `safeClient`'s `safeDialContext` (`webhook.go:59`) re-resolves the host and rejects reserved/private IPs, which is the DNS-rebinding guard.

Two other outbound-to-configured-URL paths exist but do **not** pass through `Post`: OAuth2 IdP `UserInfoUrl` fetched in `internal/idp/oauth2/oauth2.go:85` (reached from SSO sign-in, `auth_service_sso.go`), and the AI provider base URL in `internal/ai/`. Link-metadata fetching (`internal/httpgetter/`) uses a per-request URL rather than a configured one.
