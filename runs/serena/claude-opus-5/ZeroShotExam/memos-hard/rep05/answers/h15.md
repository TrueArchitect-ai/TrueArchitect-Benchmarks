Memo visibility is enforced independently in many places — there is no single chokepoint. Distinct enforcement sites:

Single-memo read gate `checkMemoReadAccess` (archived → creator only; PRIVATE → creator only; PROTECTED → any authenticated user) — `server/router/api/v1/memo_service.go:39` (callers: `GetMemo` :356, parent memo :367, `ListMemoComments` in `server/router/api/v1/memo_service_comments.go:148`)
`ListMemos` query-scoping (anonymous → `VisibilityList=[PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:218-227`
Comment listing memo filter (applied to the related-memo join) — `server/router/api/v1/memo_service_comments.go:157-162`
Memo relation listing memo filter — `server/router/api/v1/memo_relation_service.go:103-117`
Reactions read/write gate — `server/router/api/v1/reaction_service.go:29-41` (list), `:83` (upsert)
Attachment access over gRPC/Connect (`checkAttachmentAccess`, derives permission from the linked memo) — `server/router/api/v1/attachment_service.go:422-454`
`ListMemoAttachments` gate — `server/router/api/v1/memo_attachment_service.go:213-225`
Raw file/attachment HTTP serving (`checkAttachmentPermission`, incl. anonymous-instance rule and `share_token` fallback) — `server/router/fileserver/fileserver.go:650-703`
SSE broadcast delivery filter (`SSEClient.canReceive`; PRIVATE → creator or admin, unknown visibility denied) — `server/router/api/v1/sse_hub.go:134-143`, with the event's visibility populated in `server/router/api/v1/sse_event_helpers.go:29-37`
RSS feeds (explore + per-user, PUBLIC only) — `server/router/rss/rss.go:90`, `server/router/rss/rss.go:141`
Sitemap generation (PUBLIC only) — `server/router/frontend/frontend.go:149-152`
User stats aggregation (`ListAllUserStats`, `GetUserStats`) — `server/router/api/v1/user_service_stats.go:79-92`, `:214-221`
Share-token path — an intentional bypass of the visibility rules, gated only on a valid non-expired token — `server/router/api/v1/memo_share_service.go:152-208` (`GetMemoByShare`), registered unauthenticated in `server/router/api/v1/acl_config.go:40,71`
Notification/inbox content gating (`canViewerAccessMemo` — two independent copies) — `server/router/api/v1/user_service_notifications.go:302`, `server/notification/email.go:306`
Mention-notification gating (`canUserAccessMentionContext`) — `server/router/api/v1/memo_mention_helpers.go:56-72`
Store/SQL layer that actually applies `VisibilityList` and the CEL `visibility` field — `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`, `internal/filter/schema.go:162`

Not a separate site: the MCP surface (`server/router/mcp/adapter.go`) replays tool calls as HTTP requests against the same Echo server with the caller's `Authorization` header, so it inherits the API v1 checks rather than implementing its own.
