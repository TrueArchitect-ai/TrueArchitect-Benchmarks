**Premise correction:** There is no GraphQL schema in this repository. Memos does not expose a GraphQL API. A case-insensitive grep for `graphql` across all Go, TypeScript, Markdown, JSON, and YAML files returns zero matches, and there are no `.graphql`/`.gql`/`.graphqls` files anywhere in the tree.

**Actual API surface: Protocol Buffers → gRPC + Connect + REST gateway**

The schema of record is a set of `.proto` files in `proto/api/v1/`:

- `proto/api/v1/memo_service.proto` — memos, comments, reactions, relations, attachments, shares
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto` — shared enums/messages

The design follows Google's AIP guidelines, as stated in `proto/api/v1/README.md`. A separate `proto/store/*.proto` set (e.g. `proto/store/memo.proto`) defines internal persistence payloads, not the public API.

**REST surface** is derived from the same protos rather than defined separately: each RPC carries a `google.api.http` annotation that maps it to a REST route. For example, in `proto/api/v1/memo_service.proto`:

- `ListMemos` → `GET /api/v1/memos` (line 30)
- `CreateMemo` → `POST /api/v1/memos` (lines 22–23)
- `GetMemo` → `GET /api/v1/{name=memos/*}` (line 35)
- `DeleteMemoReaction` → `DELETE /api/v1/{name=memos/*/reactions/*}` (line 110)

**Code generation** is configured in `proto/buf.gen.yaml`, which runs five plugins over the protos: protobuf-go, gRPC-Go, Connect-Go, grpc-gateway, and gnostic-openapi — plus `bufbuild/es` emitting TypeScript clients into `web/src/types/proto`. Generated Go lands in `proto/gen/api/v1/`.

**The closest thing to a queryable schema document** is `proto/gen/openapi.yaml` — a 4,057-line OpenAPI 3.0.3 spec generated from the protos, embedded into the binary via `proto/openapi_embed.go`.

**Wiring at runtime:** `server/server.go:88` calls `apiV1Service.RegisterGateway(ctx, echoServer)` to mount the gRPC-gateway REST routes; handler implementations live in `server/router/api/v1/` (e.g. `memo_service.go`, `connect_handler.go`, `connect_services.go`).

Note that the repo also ships an MCP server (`server/router/mcp/`) that adapts the OpenAPI spec into tool definitions — that's an additional protocol surface, but still no GraphQL.
