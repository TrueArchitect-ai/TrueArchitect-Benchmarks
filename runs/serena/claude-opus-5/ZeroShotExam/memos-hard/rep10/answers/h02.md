### How it works

**Dispatch path.** Memo create/update/delete and comment-created events call `s.dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15-74`), which build a `WebhookRequestPayload` and hand it to `webhook.PostAsync` (`internal/webhook/webhook.go:184`). That only enqueues onto a buffered channel (`asyncPostQueue`, capacity 128, dropping with a warning when full). Four goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post`, so the outbound HTTP request actually executes in `Post` on a background worker, not on the request goroutine.

`Post` marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and issues the request through the shared `safeClient`.

**SSRF protection — two layers:**

1. **Dial-time (the enforcing layer)** — `safeClient`'s `http.Transport` uses `safeDialContext` (`internal/webhook/webhook.go:59-77`). It resolves the host itself and rejects the connection if *any* resolved address is reserved, before dialing. Because this runs at connection time rather than at save time, it also defeats DNS rebinding and redirect-based bypasses.
2. **Validation-time (fail-fast UX)** — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74,161,182`). It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument`.

Both share `isReservedIP` (`internal/webhook/validate.go:44`), checking against `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, the three RFC-1918 ranges, `169.254.0.0/16` (link-local, covering cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, and `fe80::/10`.

**Escape hatch:** the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) disables both layers for self-hosted setups targeting LAN services. It defaults to `false` and — worth noting — nothing in the production code wires it to a config or env var; the only assignments are in `internal/webhook/webhook_test.go:91,142`.

Secondary hardening in `Post`: a 30s client timeout (`internal/webhook/webhook.go:27`) and a 1 MiB `io.LimitReader` cap on the response body (`internal/webhook/webhook.go:158`).
