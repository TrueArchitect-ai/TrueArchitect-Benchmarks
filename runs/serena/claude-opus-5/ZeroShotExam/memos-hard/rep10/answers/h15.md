Memo visibility is enforced independently in several places — the store never applies a default visibility filter itself (`store/memo.go:69` only exposes `FindMemo.VisibilityList`, translated to SQL at `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`), so every caller re-implements the rule.

Central API read gate (`checkMemoReadAccess`: archived→creator-only, non-public→auth required, private→creator only) — server/router/api/v1/memo_service.go:39, called from GetMemo (:356) and the parent-memo check (:367), and from ListMemoComments (server/router/api/v1/memo_service_comments.go:148)
API list-query visibility filter (ListMemos: anonymous→PUBLIC only; authed→`creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — server/router/api/v1/memo_service.go:217-227
Raw file/attachment HTTP surface (`checkAttachmentPermission`, incl. anonymous-instance rule and share-token fallback) — server/router/fileserver/fileserver.go:669-703
SSE broadcast delivery filter (`SSEClient.canReceive`: private events only to creator or admin) — server/router/api/v1/sse_hub.go:134-143, with visibility/creator stamped in server/router/api/v1/sse_event_helpers.go:29-37
Reactions (list + upsert re-check visibility inline rather than calling the central gate) — server/router/api/v1/reaction_service.go:29-40 and :82-85
Attachment API access check (`checkAttachmentAccess`) — server/router/api/v1/attachment_service.go:436-453
Memo attachment listing — server/router/api/v1/memo_attachment_service.go:213-225
Comment creation gate — server/router/api/v1/memo_service_comments.go:41, plus the per-comment CEL filter at :156-161
Memo relation listing filter — server/router/api/v1/memo_relation_service.go:103-112
User stats surfaces (ListAllUserStats / GetUserStats) — server/router/api/v1/user_service_stats.go:83-92 and :217-221
Share-token surface: deliberately bypasses visibility, gated only on token validity/expiry and non-archived state — server/router/api/v1/memo_share_service.go:153-166 (and the matching token path in fileserver.go:681-688)
Public-only anonymous feeds: RSS — server/router/rss/rss.go:90 and :141; sitemap.xml — server/router/frontend/frontend.go:150
Notification content redaction (`canViewerAccessMemo`, duplicated in two packages) — server/router/api/v1/user_service_notifications.go:302-316 and server/notification/email.go:306-320
Mention notification targeting (`canUserAccessMentionContext` / `shouldSkipMentionInbox`) — server/router/api/v1/memo_mention_helpers.go:56-89

The MCP surface is not a separate site: it replays requests through the Echo HTTP server (server/router/mcp/adapter.go:27-42), so it inherits the API checks above.
