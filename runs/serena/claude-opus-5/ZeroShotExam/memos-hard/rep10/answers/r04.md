**Premise correction:** Neither. Memos uses no external message broker at all — there is no NATS, RabbitMQ/AMQP, Kafka, or Redis dependency anywhere in the project. `go.mod` (`/bench/repo/go.mod`) contains no broker client library, and a repo-wide grep for `nats|rabbitmq|amqp` across the Go sources returns zero hits (the only match in the whole tree is the Catalan word "amb" false-positive in `web/src/locales/ca.json`). Memos is deliberately a single self-contained Go binary, so a broker would contradict its deployment model.

**Actual mechanism — an in-process buffered Go channel with a fixed worker pool:**

- **The "queue" is declared** at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  A package-level buffered channel holding at most 128 pending payloads. It lives in process memory only — nothing is persisted, so anything still queued is lost on restart.

- **The "workers"** are 4 goroutines started in `init()` at `internal/webhook/webhook.go:42-55`. Each ranges over `asyncPostQueue` and calls `Post()`, logging a warning on failure. There is no retry or dead-letter path — a failed delivery is logged and dropped.

- **Enqueue** happens in `PostAsync()` at `internal/webhook/webhook.go:184-196`, which does a non-blocking `select` send. If the buffer is full, the payload is **dropped** with a warning rather than blocking the caller (`webhook.go:191-195`).

- **Producers** are the API service methods in `server/router/api/v1/memo_service_webhooks.go` — `dispatchMemoRelatedWebhook` (`:71`) and `DispatchMemoCommentCreatedWebhook` (`:43`) — which look up the user's webhooks via `s.Store.GetUserWebhooks` and call `webhook.PostAsync` per hook, for activity types `memos.memo.created` / `.updated` / `.deleted` / `.comment.created`.

- **Delivery itself** (`Post`, `internal/webhook/webhook.go:120-180`) is a plain HTTP POST via a shared `safeClient` with a 30s timeout and an SSRF-guarding dialer (`safeDialContext`, `:59`, backed by `internal/webhook/validate.go`), optionally signed with Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`).
