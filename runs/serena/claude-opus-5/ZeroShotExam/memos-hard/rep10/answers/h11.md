**1st: `store.User`; 2nd: `store.Memo`**

**Data layer** = the `store/` package tree (`store/*.go` plus its drivers in `store/db/*` and helpers in `store/test/`). The persistent entity types defined there are `User`, `Memo`, `Attachment`, `Reaction`, `Inbox`, `MemoRelation`, `MemoShare`, `UserSetting`, `UserIdentity`, `IdentityProvider`, `InstanceSetting`.

Counting distinct Go packages **outside** `store/` that reference each type:

| Type (definition) | Packages outside `store/` | Refs |
|---|---|---|
| `User` — `store/user.go:29` | **7** | ~99 |
| `Memo` — `store/memo.go:35` | **6** | ~73 |
| `Attachment` — `store/attachment.go:16` | 4 | ~43 |
| `Inbox` / `MemoRelation` / `MemoShare` | 3 each | — |
| `Reaction`, `UserIdentity` | 2 each | — |

**`store.User` (1st, 7 packages):**
- `server/auth` — `server/auth/authenticator.go`, `server/auth/context.go`
- `server/notification` — `server/notification/email.go`
- `server/router/api/v1` — ~19 files, e.g. `server/router/api/v1/user_service.go`, `auth_service.go`, `memo_service_converter.go`
- `server/router/api/v1/test` — `test_helper.go` and service tests
- `server/router/fileserver` — `server/router/fileserver/fileserver.go`
- `server/router/frontend` — `frontend_test.go`
- `server/router/rss` — `server/router/rss/rss.go`

**`store.Memo` (2nd, 6 packages):** `server/router/api/v1` (13 files), `server/router/api/v1/test`, `server/router/rss`, `server/router/frontend`, `server/notification`, `server/runner/memopayload` (`server/runner/memopayload/runner.go`).

Two notes on method: `store.User` uniquely dominates because it's the only entity the auth/session layer (`server/auth`) and the file-serving layer touch, giving it two packages `Memo` doesn't reach; `Memo` in turn is the only one used by `server/runner/memopayload`. Also, matches for `IdentityProvider`/`UserSetting`/`InstanceSetting` under `proto/gen/store` are generated-protobuf self-references (that package is also named `store`), not real references to the data-layer types, so I excluded them.
