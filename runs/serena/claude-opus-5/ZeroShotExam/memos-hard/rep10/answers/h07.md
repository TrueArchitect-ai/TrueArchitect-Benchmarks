The URL the browser hits is `/file/users/{username}/avatar`, minted server-side by the user converter (`AvatarUrl` is rewritten from the stored base64 data URI to that path) and rendered by `UserAvatar`'s `<img src>`. The request path from that GET to stored bytes:

**Hop chain (request → data)**

- `FileServerService.RegisterRoutes` (route `GET /file/users/:identifier/avatar`) — server/router/fileserver/fileserver.go:121-124
- `FileServerService.serveUserAvatar` (serving handler) — server/router/fileserver/fileserver.go:168
- `FileServerService.getCurrentUser` → `auth.Authenticator.AuthenticateToUser` (only when `Profile.AllowAnonymous()` is false) — server/router/fileserver/fileserver.go:611-616, server/auth/
- `FileServerService.getUserByUsername` — server/router/fileserver/fileserver.go:619-621
- `Store.GetUser` (with `store.FindUser{Username: &identifier}`; checks `userCache` only when finding by ID) — store/user.go:148
- `Store.ListUsers` (populates `userCache`) — store/user.go:136
- `Driver.ListUsers` (interface) — store/driver.go:47
- `DB.ListUsers` — SQL `SELECT ... avatar_url ... FROM user WHERE username = ?` — store/db/sqlite/user.go:88 (equivalents: store/db/postgres/user.go, store/db/mysql/user.go)
- `FileServerService.parseDataURI` — decodes the `data:<mime>;base64,...` value in `user.AvatarURL` into bytes — server/router/fileserver/fileserver.go:663
- `c.Blob(http.StatusOK, imageType, imageData)` after `avatarAllowedTypes` check + security/cache headers — server/router/fileserver/fileserver.go:195-206

**Where the data actually lives:** the avatar is not an attachment file or S3 object — it is stored inline in the `user.avatar_url` column as a base64 data URI (`store.User.AvatarURL`, store/user.go), which is why the last hop is a decode rather than a filesystem/S3 read.

**Note on "another user's":** `serveUserAvatar` does no per-user authorization — the only gate is instance-level: if `Profile.AllowAnonymous()` is false, any authenticated viewer suffices; otherwise anyone can fetch any user's avatar by username (server/router/fileserver/fileserver.go:171-180). That's unlike `serveAttachmentFile`, which runs `checkAttachmentPermission`.
