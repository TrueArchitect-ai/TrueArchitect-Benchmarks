**Mechanism: explicit Go code** — reactions are deleted by hand-written `DELETE FROM reaction` statements inside the driver-level user-deletion transaction, in all three DB drivers. There is no database-level cascade for them.

**Two separate deletions happen** (in `deleteUserTargetsTx`):
1. Reactions *on* the deleted user's memos, regardless of who reacted — `deleteReactionsByContentIDsTx`, batched by `content_id` (built as `"memos/"+memo.UID`, `store/db/sqlite/user_delete.go:512-518`).
2. Reactions *by* the deleted user on anyone's content — `deleteReactionsByCreatorTx` (`DELETE FROM reaction WHERE creator_id = ?`).

Evidence locations:

- `store/db/sqlite/user_delete.go:96` and `:102` (call sites), `:380-388` and `:400-403` (the two delete helpers)
- `store/db/postgres/user_delete.go:96`, `:102`, `:380`, `:400` — identical structure
- `store/db/mysql/user_delete.go:96`, `:102`, `:417`, `:437` — identical structure
- Wrapped in a single transaction: `store/db/sqlite/user_delete.go:29-63` (`BeginTx` … `tx.Commit`), reached from `store/user.go:171-181` → `server/router/api/v1/user_service.go:414`

Why it is *not* a DB rule:

- The `reaction` table has **no foreign key at all** — `store/migration/{sqlite,postgres,mysql}/LATEST.sql` (sqlite line 91, postgres line 90, mysql line ~91) define only `id`, `created_ts`, `creator_id`, `content_id`, `reaction_type`, `UNIQUE(creator_id, content_id, reaction_type)`. Same in the original `store/migration/*/0.20/00__reaction.sql`. `creator_id` is a plain INTEGER, and `content_id` is a text resource name (`memos/<uid>`), which couldn't be an FK to `memo.id` anyway.
- Grepping `FOREIGN KEY|REFERENCES|ON DELETE` across `store/migration/` shows the only surviving cascades are `memo_share.memo_id → memo(id)` (`store/migration/*/0.27/04__memo_share.sql:11`); the old user cascades were dropped in `store/migration/sqlite/0.7/00__remove_fk.sql`.
- Even where FKs remain, SQLite opens with them disabled: `store/db/sqlite/sqlite.go:53` (`_pragma=foreign_keys(0)`).

Tests confirming the behavior: `store/test/user_delete_test.go:97-112, 217-220` and `server/router/api/v1/test/user_service_delete_test.go:188-209, 287-298` — reactions on the user's memos and the user's own reactions are gone, while a third party's reaction on someone else's memo survives; `:429-431` checks reactions are still present after a rolled-back deletion.
