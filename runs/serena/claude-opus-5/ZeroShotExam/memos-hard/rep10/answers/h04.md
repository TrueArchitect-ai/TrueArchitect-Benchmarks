**No** — outside `NewDBDriver`, the MySQL driver is never constructed in production code. The only other construction is a zero-value literal in a unit test inside the `mysql` package itself.

Evidence:

1. **The factory is the only caller of `mysql.NewDB`** — `store/db/db.go:22`, inside `NewDBDriver` (`store/db/db.go:14`), which switches on `profile.Driver`:
   ```go
   case "mysql":
       driver, err = mysql.NewDB(profile)
   ```

2. **`store/db/db.go:8` is the only import of the package.** A repo-wide grep for `github.com/usememos/memos/store/db/mysql` returns exactly one hit — that import line. No other file can reach `mysql.NewDB` or `mysql.DB` at all.

3. **Constructor internals:** `store/db/mysql/mysql.go:20-40` — `NewDB` is the sole exported constructor; `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`) is the only struct literal in non-test code, and it's inside `NewDB` itself.

4. **All callers go through the factory:** `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(profile)`, selecting MySQL only via `profile.Driver` (set from env in `store/test/store.go:88`).

The one exception, which is not a real driver construction:
- `store/db/mysql/auth_config_test.go:12` — `db := &DB{}`, an in-package (`package mysql`) zero-value literal with no `*sql.DB` or config, used purely to invoke the pure method `IsRetryableAuthenticationMutationError` on error values. It never opens a connection.

Also worth disambiguating: occurrences of `mysql.Config`, `mysql.ParseDSN`, and `sql.Open("mysql", dsn)` in `store/db/mysql/mysql.go` refer to the third-party `github.com/go-sql-driver/mysql` package, not this repo's store driver.
