**No** — outside `store/db/db.go`'s `NewDBDriver` factory, no production code constructs the MySQL driver.

Evidence:

- **The factory is the only production caller.** `store/db/db.go:22` (`driver, err = mysql.NewDB(profile)`) is the sole invocation of `mysql.NewDB`, inside the `switch profile.Driver` in `NewDBDriver`. It's also the only file outside `store/db/mysql/` that imports `github.com/usememos/memos/store/db/mysql` (`store/db/db.go:8`).
- **Grep confirms no other construction sites.** Searching for `NewDB` / `&DB{` across all `.go` files turns up MySQL only at `store/db/mysql/mysql.go:20` (the constructor itself) and `mysql.go:29` (`driver := DB{profile: profile}`, internal to that constructor).
- **All other entry points go through the factory.** Test and benchmark helpers use `db.NewDBDriver(profile)` with a driver string (`store/test/store.go:28` and `:50`, `server/router/api/v1/test/memo_service_benchmark_test.go:70`), never `mysql.NewDB` directly.

Two things worth flagging, neither of which is a real bypass:

- `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — a zero-value struct inside the mysql package itself, used only to call the pure helper `IsRetryableAuthenticationMutationError`. No connection is opened. (`store/db/postgres/auth_config_test.go:12` and `postgres/user_setting_test.go` do the same for Postgres.)
- The `mysql` identifiers in `store/test/containers.go` (lines 20, 101–105) are the *testcontainers* module `testcontainers-go/modules/mysql`, and `mysqldriver` there (line 16) is `go-sql-driver/mysql` — neither is the memos MySQL store driver.

For contrast, SQLite *is* constructed directly outside the factory in `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416` (`sqlite.NewDB(p)`), so the pattern isn't universally enforced — it just happens to hold for MySQL.
