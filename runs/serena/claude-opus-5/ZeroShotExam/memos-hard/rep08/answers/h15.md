h15.

Memo visibility is enforced independently in several places — there is no single chokepoint. The distinct enforcement sites:

**Connect/gRPC API — single-memo read gate (the closest thing to a canonical check)**
`checkMemoReadAccess` (public → open; non-public → must be authed; private → creator only) — `server/router/api/v1/memo_service.go:39-67`, called from `GetMemo` (and its parent memo) at `:356`/`:367` and from `ListMemoComments` at `server/router/api/v1/memo_service_comments.go:148`

**Connect/gRPC API — list query scoping (visibility pushed into the store filter, not a per-row check)**
`ListMemos` visibility scoping — `server/router/api/v1/memo_service.go:218-227`
`ListMemoComments` child-memo filter — `server/router/api/v1/memo_service_comments.go:157-161`
`ListAllUserStats` / `GetUserStats` scoping — `server/router/api/v1/user_service_stats.go:84-91` and `:217-221`

**Connect/gRPC API — per-feature re-checks that duplicate the rule inline**
`CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:41`
`ListMemoReactions` and `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:30-41` and `:83`
`ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:213-225`
`checkAttachmentAccess` (attachment inherits its memo's visibility) — `server/router/api/v1/attachment_service.go:419-455`

**Realtime SSE fan-out**
`SSEClient.canReceive` — private events only to creator or admin — `server/router/api/v1/sse_hub.go:135-144`, with the event's visibility stamped in `server/router/api/v1/sse_event_helpers.go:29-37`

**Raw file/blob HTTP surface (separate from the API, own auth path)**
`checkAttachmentPermission` — share-token fallback, anonymous-access rules, then private→creator/admin — `server/router/fileserver/fileserver.go:649-703`

**Unauthenticated public-content surfaces (hard-scoped to PUBLIC)**
RSS feeds — `server/router/rss/rss.go:90` and `:141`
Sitemap — `server/router/frontend/frontend.go:150`

**Share-token surface (deliberate bypass of the visibility rule, gated on token validity/expiry instead)**
`GetMemoByShare` — `server/router/api/v1/memo_share_service.go:153-192`, token validation in `getActiveMemoShare`/`isMemoShareExpired` at `:196-210`

**Notification / inbox fan-out (visibility decides who gets told a memo exists)**
`canViewerAccessMemo` — `server/router/api/v1/user_service_notifications.go:302-316` (used at `:337`, `:342`, `:370`, `:385`)
`canViewerAccessMemo` — a second, separate copy — `server/notification/email.go:306-320` (used at `:155`, `:187`)
`canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-89`

Two notes on scope: the store layer (`store/memo.go:69`, `store/db/{sqlite,postgres,mysql}/memo.go`) only translates `VisibilityList`/filters into SQL — it applies policy the callers supply, it doesn't decide it. And the MCP router is not a separate site: `server/router/mcp/adapter.go:27-42` replays requests through the same echo server, so it inherits the API checks above.
