h14.

**`memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`), which delegates the actual parsing to `markdown.Service.ExtractAll` (`internal/markdown/markdown.go:355`); triggered on memo create, on memo update when `content` is in the update mask, and by the bulk backfill runner; extracts tags plus the `MemoPayload.Property` fields `title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`.**

Details:

**Computation site**
- `RebuildMemoPayload(ctx, memo, markdownService)` — `server/runner/memopayload/runner.go:74`. It ensures `memo.Payload` is non-nil, calls `ExtractAll([]byte(memo.Content))`, and assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (runner.go:85-86). User-set payload fields (`Location`) are untouched.
- The parse itself is a single goldmark AST walk in `internal/markdown/markdown.go:355-421` (`ExtractAll`). A standalone `ExtractProperties` (markdown.go:193) does the property half only; the memo path uses `ExtractAll` for the single-pass version.

**Triggers**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before `Store.CreateMemo`.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `path == "content"` branch; the rebuilt payload is written via `update.Payload = memo.Payload` (memo_service.go:451). Other update paths (visibility, pinned, location, etc.) don't recompute it — `location` mutates the existing payload in place (memo_service.go:482-484).
- `Runner.RunOnce` — `server/runner/memopayload/runner.go:27`: batch backfill (100 at a time) that rebuilds and persists the payload for every memo. Note this runner is defined but not currently wired into startup — `grep RunOnce` shows only `s3presignRunner.RunOnce` called in `server/server.go:163`.

**What is extracted** (`storepb.MemoPayload_Property`, declared in `proto/store/memo.proto:15-22`)
- `title` — text of the first block-level child of the document if it is an H1 heading (markdown.go:381-388).
- `has_link` — any `KindLink` node.
- `has_code` — `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- `has_task_list` — any `TaskCheckBox`; `has_incomplete_tasks` — any unchecked one (markdown.go:390-406).
- Alongside these, `ExtractAll` also collects `Tags` (deduped, case preserved) and `Mentions`; only tags are persisted into the payload.

These surface on the API via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315`) and drive the user stats aggregation (`server/router/api/v1/user_service_stats.go:141-153`) and store-level filters (`store/memo.go:87-90`).

One related but distinct piece: the list/preview **snippet** is *not* stored in the payload — it's computed per-read at conversion time by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83`, called from `memo_service_converter.go:76`).
