**Premise correction:** There is no nightly database-cleanup job in this repository's cron scheduler. The scheduler exists as a standalone library, but nothing registers a database-cleanup job with it.

What's actually there:

- `internal/scheduler/` is a self-contained cron scheduler package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It has **zero non-test importers** — no code in `cmd/`, `server/`, or `store/` imports `internal/scheduler`, so no jobs of any kind are registered at runtime.
- The "2 AM daily cleanup" you may be thinking of appears only in documentation and example code, and it is a generic placeholder, not a database job:
  - `internal/scheduler/doc.go:15-19` — package doc example, `Name: "daily-cleanup"`, `Schedule: "0 2 * * *"`, handler body is a comment (`// Your cleanup logic here`).
  - `internal/scheduler/example_test.go:97-106` — `Example_multipleJobs`, `Name: "cleanup"`, `Schedule: "0 2 * * *"`, handler just prints `"Cleaning up old data..."`.
  - `internal/scheduler/README.md:34` — same illustrative `daily-cleanup` snippet; `README.md:241` shows a `stale-session-cleanup` naming example.

The only real periodic work in the codebase runs on plain tickers, not cron:

- `server/runner/s3presign/runner.go:30` — S3 presigned-link refresh on a fixed interval.
- `store/cache/cache.go:201` — in-memory cache expiry sweep on `CleanupInterval`.

So if you're looking for a scheduled database cleanup to modify or audit, it doesn't exist yet — it would need to be written and wired up.
