## Where delivery executes

`webhook.Post()` at `internal/webhook/webhook.go:120` is where the outbound HTTP POST actually happens (`safeClient.Do(req)` at `internal/webhook/webhook.go:152`). It marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), posts, and checks the status code and response body.

Callers never invoke `Post` directly on the request path. `webhook.PostAsync()` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel `asyncPostQueue`, drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each calling `Post`. Overflow is dropped with a warning rather than blocking.

Trigger points are `server/router/api/v1/memo_service_webhooks.go:43` and `:71` — memo created/updated/deleted and comment-created events, fanning out over the creator's registered webhooks from `s.Store.GetUserWebhooks`.

## What protects it from internal addresses

Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against a parsed CIDR list covering IPv4 loopback, RFC-1918 ranges, link-local/cloud IMDS `169.254.0.0/16`, and IPv6 loopback/ULA/link-local (`internal/webhook/validate.go:14-23`):

1. **Dial-time enforcement (the real guard)** — `safeClient` is built with a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59`) re-resolves the host at connect time and refuses the dial if any resolved address is reserved. Because it runs on every dial, it also defeats DNS rebinding, and it applies to redirect hops since Go's default redirect-following goes back through the same transport.

2. **Admission-time validation** — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and hostnames resolving to reserved IPs when a webhook is created or updated, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. This gives a clean `InvalidArgument` error to the user but is TOCTOU-vulnerable on its own — layer 1 is what holds.

An escape hatch exists: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted deployments targeting LAN services. Note it's declared but nothing in the non-test tree ever sets it, so it's effectively always `false` unless wired up by a caller.
