**1st: `store.User` (~7 packages outside the store layer); 2nd: `store.Memo` (~6 packages)**

**The data layer** is the `store` package tree (`store/`, with driver implementations in `store/db/{sqlite,mysql,postgres}` and tests in `store/test`). Persistent entity types are declared one per file:

- `store/user.go:29` — `User`
- `store/memo.go:35` — `Memo`
- `store/attachment.go:16` — `Attachment`
- plus `MemoRelation`, `MemoShare`, `Inbox`, `Reaction`, `UserIdentity`, `UserSetting`, `IdentityProvider`, `InstanceSetting`

Counting distinct Go packages outside `store/...` (and excluding the unrelated generated `proto/gen/store` package, which is a different `store` import alias) that reference each type:

| Type | Packages | Refs |
|---|---|---|
| `store.User` | **7** | 99 |
| `store.Memo` | **6** | 73 |
| `store.Attachment` | 4 | 43 |
| `store.MemoShare` / `store.MemoRelation` / `store.Inbox` | 3 | 10–14 |
| `store.Reaction` / `store.UserIdentity` | 2 | 9–14 |

**`store.User`** — `server/auth` (`authenticator.go`, `context.go`), `server/notification` (`email.go`), `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver` (`fileserver.go`), `server/router/frontend` (`frontend_test.go`), `server/router/rss` (`rss.go`).

**`store.Memo`** — same set minus `server/auth` and `server/router/fileserver`, plus `server/runner/memopayload` (`runner.go`).

The gap is the auth/identity path: `server/auth` and `fileserver` carry `*store.User` for the authenticated principal without touching memos, while memos add only the payload runner. Note `UserSetting`, `IdentityProvider`, and `InstanceSetting` score 0 outside the layer — callers work with the protobuf equivalents from `proto/gen/store` (`storepb.*`) instead of the store structs.
