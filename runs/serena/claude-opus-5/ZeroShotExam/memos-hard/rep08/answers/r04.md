**Premise correction:** Neither. This repo (Memos) has no external message broker at all — no NATS, no RabbitMQ, no Kafka or Redis queue. The `nats` grep hits are substrings of Catalan words in `web/src/locales/ca.json` (e.g. "elimi**nats**", "predetermi**nats**"), and `go.mod` contains no AMQP/NATS client. There is also no separate worker process or deployment unit: `scripts/Dockerfile` builds the single Go binary, and there's no compose file defining a broker service.

**Actual mechanism — an in-process buffered Go channel with a fixed goroutine pool:**

- **"Queue" declaration:** `internal/webhook/webhook.go:39` — a package-level buffered channel, capacity 128:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- **"Workers":** `internal/webhook/webhook.go:42-55` — an `init()` function spawns exactly 4 goroutines, each ranging over the channel and calling `Post(payload)`, logging failures via `slog.Warn`. These live inside the same process as the API server, so they die with it.
- **Enqueue:** `PostAsync` (`internal/webhook/webhook.go:184-196`) does a non-blocking `select` send. On a full buffer it hits the `default` branch and **drops the delivery** with a warning — no retry, no persistence, no dead-letter.
- **Producers:** `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, which fan out per user webhook for `memos.memo.created/updated/deleted` and `memos.memo.comment.created`.
- **Delivery itself:** `Post` at `internal/webhook/webhook.go:120-180` — a single HTTP POST via a shared `safeClient` (30s timeout, SSRF-guarded dialer at `:59`), optional Standard Webhooks HMAC-SHA256 signing (`webhook-id` / `webhook-timestamp` / `webhook-signature` headers).

Practical consequence of there being no broker: webhook delivery is at-most-once and entirely in-memory. Anything still buffered is lost on restart or crash, and bursts beyond 128 pending payloads are silently discarded.
