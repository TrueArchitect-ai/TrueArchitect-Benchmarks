**`internal/idp`; `internal/idp/oauth2`**

**Abstraction package — `internal/idp`** (`internal/idp/idp.go`): a small package holding the provider-neutral contract, the `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider normalizes its user data into.

**Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): "Package oauth2 implements the OAuth2 identity provider integration." It defines `IdentityProvider` wrapping a `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (including PKCE `code_verifier` support), and `UserInfo`, which maps remote claims via the configured `FieldMapping` into `idp.IdentityProviderUserInfo`.

OAuth2 is the only concrete protocol that ships — the store enum has exactly one non-unspecified value, `OAUTH2` (`proto/store/idp.proto:10-14`), and `IdentityProviderConfig` is a `oneof` with the single variant `oauth2_config`. The dispatch site confirms it: `server/router/api/v1/auth_service_sso.go:120-134` branches only on `storepb.IdentityProvider_OAUTH2`. No OIDC-specific or SAML implementation exists (OIDC providers are configured as generic OAuth2 with custom URLs and field mappings).
