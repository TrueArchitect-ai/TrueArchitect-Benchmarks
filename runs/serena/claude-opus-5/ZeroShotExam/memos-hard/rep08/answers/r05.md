**Premise correction:** There is no GraphQL schema in this repository. A case-insensitive search for `graphql` across the entire tree returns zero matches — no `.graphql`/`.gql` files, no schema-definition code, no GraphQL server dependency in `go.mod`. Memos does not expose a GraphQL API.

**The actual public API surface:** it's Protobuf/gRPC-first, defined in `.proto` files under `proto/api/v1/`:

- `proto/api/v1/memo_service.proto` — memos, comments, reactions, relations, attachments, shares, link metadata
- `proto/api/v1/user_service.proto` — users, settings, access tokens, webhooks, identities
- `proto/api/v1/auth_service.proto` — sessions/SSO
- `proto/api/v1/attachment_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `ai_service.proto`, `common.proto`

(`proto/store/*.proto` are internal persistence messages, not public API.)

Each RPC carries a `google.api.http` annotation that defines its REST mapping — e.g. `proto/api/v1/memo_service.proto:30` maps `ListMemos` to `GET /api/v1/memos`, and line 35 maps `GetMemo` to `GET /api/v1/{name=memos/*}`.

**Codegen and serving:**
- `proto/buf.gen.yaml` drives `buf generate`, producing Go protobuf/gRPC/Connect/grpc-gateway stubs into `proto/gen/`, an OpenAPI spec, and TypeScript clients into `web/src/types/proto`.
- `proto/gen/openapi.yaml` is the generated OpenAPI spec, embedded into the binary via `proto/openapi_embed.go`.
- Three transports are wired up in `server/server.go`: the REST gateway (`server/router/api/v1/v1.go:65`, `RegisterGateway`), Connect RPC at `/memos.api.v1.*` (`server/router/api/v1/v1.go:144`, handlers in `server/router/api/v1/connect_handler.go`), and an MCP endpoint driven by the embedded OpenAPI spec (`server/router/mcp/service.go:76`).

So the answer to "where is the schema defined" is `proto/api/v1/*.proto` — protobuf, not GraphQL.
