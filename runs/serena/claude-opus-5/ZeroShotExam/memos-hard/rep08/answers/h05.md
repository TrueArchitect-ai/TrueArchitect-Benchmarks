**Mechanism: explicit Go code** — reactions are deleted by hand-written `DELETE FROM reaction` statements inside the user-delete transaction, in all three DB drivers. There is no database-level cascade, because the `reaction` table has no foreign keys at all.

## Evidence

**1. Explicit deletion in the delete-user transaction (two separate sweeps)**

`store/db/sqlite/user_delete.go:92-104` — `deleteUserTargetsTx` calls, before deleting memos and the user row:
- `deleteReactionsByContentIDsTx` (line 96) → `store/db/sqlite/user_delete.go:380-388`: `DELETE FROM reaction WHERE content_id IN (...)`, batched at 500. The content IDs are `"memos/" + memo.UID` for every memo in the deleted user's memo tree (`memoContentIDsFromRefs`, line 512-518), so *other* people's reactions on the deleted user's memos also go away.
- `deleteReactionsByCreatorTx` (line 102) → `store/db/sqlite/user_delete.go:400-403`: `DELETE FROM reaction WHERE creator_id = ?`, removing the deleted user's own reactions on anyone's content.

The same two calls and helpers exist in the other drivers:
- `store/db/postgres/user_delete.go:96, 102, 380-403`
- `store/db/mysql/user_delete.go:96, 102, 417-440`

Everything runs in one `BeginTx`/`Commit` (`store/db/sqlite/user_delete.go:29-59`), reached via `store.DeleteUser` (`store/user.go:171-181`) from the API handler `APIV1Service.DeleteUser` (`server/router/api/v1/user_service.go:393-416`).

**2. No DB-level rule to rely on**

`CREATE TABLE reaction` has no `FOREIGN KEY` / `ON DELETE CASCADE` in any dialect:
- `store/migration/sqlite/LATEST.sql:92-99`
- `store/migration/postgres/LATEST.sql:91-98`
- `store/migration/mysql/LATEST.sql:91-98`

(Contrast `memo_share` right below each, which *does* declare `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` — yet `memo_share` is still also cleaned explicitly at `store/db/sqlite/user_delete.go:405-416`.) I also grepped the versioned reaction migrations (`store/migration/{sqlite,postgres,mysql}/0.20/00__reaction.sql`, `0.23/00__reactions.sql`) for `FOREIGN KEY`/`REFERENCES` — no hits.

**3. Test asserting the behavior**

`store/test/user_delete_test.go:97-114` seeds three reactions (a peer's reaction on the deleted user's memo, the user's reaction on a peer memo, a peer's reaction on a peer memo); after `DeleteUser` (line 184), lines 216-220 assert only `peerReactionToKeep` survives.
