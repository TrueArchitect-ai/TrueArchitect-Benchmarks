**Premise correction: there is no nightly database-cleanup job in this repository.** The question assumes a scheduled cleanup job exists; it doesn't.

What actually exists:

- `internal/scheduler/` is a **standalone, generic cron scheduler library** (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It contains no job registrations of its own — `Register` is an API for callers.
- **Nothing in the repo imports it.** A grep for `internal/scheduler` across all Go files outside the package itself returns zero hits, so no job — database cleanup or otherwise — is scheduled anywhere in the running server.
- The "2 AM" figure that likely prompted the question comes only from **documentation and test examples**, not production code:
  - `internal/scheduler/doc.go:15-16` — package doc example: `Name: "daily-cleanup", Schedule: "0 2 * * *", // 2 AM daily`
  - `internal/scheduler/README.md:34-36` — the same illustrative snippet
  - `internal/scheduler/example_test.go:97-99` — `Example_multipleJobs` registers a job literally named `"cleanup"` at `"0 2 * * *"` that just prints "Cleaning up old data..."
  - `internal/scheduler/README.md:241-245` — a different best-practices example, `"stale-session-cleanup"` at `"0 3 * * *"`

None of these touch a database; they're placeholder handlers.

The only real periodic background work in the server is `server/runner/s3presign/runner.go:26-31`, which is an interval ticker (every 12 hours), not a cron-scheduled nightly job, and it refreshes S3 presigned URLs rather than cleaning up the database.
