**Convergence function: `webhook.Post` — `internal/webhook/webhook.go:120`** (the outbound call is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`).

**The path:** every handler above funnels into `dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48` and `:30`), which reads the target from `s.Store.GetUserWebhooks(...)` and sets `payload.URL = hook.Url` — the URL a user configured via `CreateUserWebhook`/`UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:74`, `:161`). Each calls `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a 128-slot channel drained by 4 goroutines started in `init()` (`:42-55`), and each of those calls `Post`. So `PostAsync` is the synchronous convergence point, but `Post` is the single function that actually builds and delivers the request — HMAC signing (`webhook-id`/`webhook-timestamp`/`webhook-signature`) and the SSRF-guarded `safeClient` (`safeDialContext` at `:59` rejects reserved/private IPs at dial time) both live there.

**Two other user-configured-URL egress paths exist but do not converge here**, in case they matter for your question:
- `internal/idp/oauth2/oauth2.go:85` fetches an admin-configured `UserInfoUrl` (reached from SSO sign-in / identity-provider handlers).
- `internal/httpgetter/image.go:21` and `html_meta.go:31` fetch a caller-supplied URL (link-metadata / image fetching), not a stored config value.
