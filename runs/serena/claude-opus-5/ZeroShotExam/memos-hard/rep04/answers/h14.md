**Triggers:**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before the row is inserted (runs on the `create` struct, so `Payload.Location` is layered on afterwards at line 111).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only when `content` is in the update mask; the rebuilt payload is written via `update.Payload` (line 451). Other mask paths (visibility, pinned, state, times, location) do not recompute — the `location` path at line 481-483 mutates the existing payload in place and preserves the derived property.
- Bulk backfill — `Runner.RunOnce` in `server/runner/memopayload/runner.go:27-72` rebuilds every memo in batches of 100. Note it is not wired into `server/server.go` startup (only the s3presign runner is, at `server/server.go:163`), so it's a manually-invoked/migration path.

**Extracted properties** (`MemoPayload.Property`, `internal/markdown/markdown.go:383-408`):
- `has_link` — any `gast.KindLink` node.
- `has_code` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- `has_task_list` — any GFM `TaskCheckBox`.
- `has_incomplete_tasks` — any `TaskCheckBox` with `IsChecked == false`.
- `title` — text of the first block-level child of the document if it is an H1 heading (`extractHeadingText`, `internal/markdown/markdown.go:173-179`).

The same walk also fills `Payload.Tags` (deduped, case-preserving) and mentions. These surface to clients via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315-326`) alongside `Tags` (line 48).
