The browser never gets base64 avatar bytes in the user API response — `convertUserFromStore` rewrites the field to a `/file/users/{username}/avatar` path, and the `<img>` for that path is what hits the file server.

**Return path:** `serveUserAvatar` then calls `FileServerService.parseDataURI` (server/router/fileserver/fileserver.go:737) to split the stored `data:image/…;base64,…` string, checks the MIME type against `avatarAllowedTypes` (fileserver.go:75), sets security + `Cache-Control` headers, and writes the decoded bytes with `c.Blob`.
