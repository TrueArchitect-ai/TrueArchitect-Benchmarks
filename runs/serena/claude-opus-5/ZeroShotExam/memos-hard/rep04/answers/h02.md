**Delivery function — `Post` in `internal/webhook/webhook.go:120`; protection mechanism — `safeDialContext` / `isReservedIP` in `internal/webhook/webhook.go:59` backed by `internal/webhook/validate.go:44`.**

**Where delivery executes**

- `webhook.Post` (`internal/webhook/webhook.go:120`) does the real work: marshals the payload, builds the `POST`, adds Standard Webhooks HMAC headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`) when a signing secret is set, then issues the request via `safeClient.Do` (`internal/webhook/webhook.go:152`) and validates the response body/status.
- Callers never call `Post` directly. `webhook.PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a buffered channel (`asyncPostQueue`, cap 128, `webhook.go:39`), drained by 4 goroutines started in `init()` (`webhook.go:42-55`) that call `Post`. Overflow is dropped with a warning, not blocked.
- Trigger points are `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (memo created/updated/deleted and comment-created dispatchers), which fan out over each user's stored webhooks.

**What protects it from internal addresses** — two layers:

1. **Dial-time enforcement (the real guard).** `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`, defined at `:59`). It splits host/port, resolves the host itself, and rejects the connection if *any* resolved IP satisfies `isReservedIP`. Because the check happens at dial time on every connection, it also defeats DNS rebinding — a host that validated cleanly at save time can't later resolve to an internal address.
2. **Admission-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`). It requires an absolute `http`/`https` URL and rejects hostnames resolving into reserved ranges, returning a gRPC `InvalidArgument`.

The blocklist is `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 ranges, `169.254.0.0/16` (covers the cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`. Parsed once at startup into `reservedNetworks` (`validate.go:28-36`).

Two things worth flagging:

- `AllowPrivateIPs` (`internal/webhook/validate.go:41`) is a global kill switch — when true, `isReservedIP` returns false unconditionally and *both* layers go away. Grepping the tree, nothing ever assigns it outside its declaration, so it's currently dead-off (defaults to `false`); it's a hook for self-hosted deployments with no wiring to a flag or config yet.
- The CIDR list doesn't cover `0.0.0.0/8`, carrier-grade NAT `100.64.0.0/10`, or IPv4-mapped IPv6 (`::ffff:127.0.0.1`), so those aren't blocked by `isReservedIP` as written.
