## Where delivery executes

- `webhook.Post()` — `internal/webhook/webhook.go:120` — marshals the payload, builds the `POST`, optionally adds Standard-Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and performs the actual outbound call via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.
- `webhook.PostAsync()` — `internal/webhook/webhook.go:184` — the entry point callers use. It enqueues onto a bounded 128-slot channel (`asyncPostQueue`), drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each of which calls `Post`. Overflow is dropped with a warning.
- Callers: `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (`dispatchMemoRelatedWebhook` for memo created/updated/deleted, plus comment-created), which load the user's hooks via `s.Store.GetUserWebhooks`.

## What protects it from internal addresses

Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which checks against a parsed CIDR list covering IPv4 loopback, RFC-1918, link-local/cloud IMDS `169.254.0.0/16`, and the IPv6 equivalents (`::1/128`, `fc00::/7`, `fe80::/10`) — `internal/webhook/validate.go:14-23`.

1. **Dial-time enforcement (the real guard).** `safeClient` is a shared `http.Client` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59-77`) re-resolves the host at connect time and refuses if *any* resolved IP is reserved. Because the check happens at dial rather than at save time, it also defeats DNS rebinding.
2. **Admission-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) enforces http/https scheme and non-reserved resolution when a webhook is created or updated — called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. This returns a gRPC `InvalidArgument`, so it's UX/defense-in-depth, not the last line.

An escape hatch exists: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to disable both layers for self-hosted deployments targeting LAN services. Note that it is currently only ever set in tests (`internal/webhook/webhook_test.go:91`, `:142`) — no CLI flag, env var, or config path wires it up, so in production it is effectively always `false`.
