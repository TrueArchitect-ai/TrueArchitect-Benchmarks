**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any provider implementation returns.
- **Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol implementation that ships. Its `IdentityProvider` wraps a `storepb.OAuth2Config` and provides `NewIdentityProvider`, `ExchangeToken` (with optional PKCE code verifier), and user-info retrieval mapped through `FieldMapping` into `idp.IdentityProviderUserInfo`.

Supporting evidence:
- `proto/store/idp.proto` declares `IdentityProvider.Type` with only `TYPE_UNSPECIFIED` and `OAUTH2`, and `IdentityProviderConfig` is a `oneof` containing just `oauth2_config` — no SAML/OIDC-specific variant.
- `server/router/api/v1/auth_service_sso.go:12-13` is the sole consumer, importing both `internal/idp` and `internal/idp/oauth2` to drive the SSO sign-in flow.
