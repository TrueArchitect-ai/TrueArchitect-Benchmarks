h15.

Memo visibility is not enforced by a single chokepoint — each surface that can expose memo data re-implements the check. Distinct enforcement sites:

**Core Connect/gRPC memo API**
- `checkMemoReadAccess` (single-memo read guard: archived → creator only, PROTECTED → any authed user, PRIVATE → creator) — `server/router/api/v1/memo_service.go:39`; called from `GetMemo` (`:356`), its parent-memo hop (`:367`), and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)
- `ListMemos` query-level filter (`VisibilityList = [PUBLIC]` for anonymous, else `creator_id == me || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:219-227`
- `CreateMemoComment` pre-check on the parent memo — `server/router/api/v1/memo_service_comments.go:41`
- Comment/relation listing `MemoFilter` pushed into SQL — `server/router/api/v1/memo_service_comments.go:157-162` and `server/router/api/v1/memo_relation_service.go:107-112`
- User stats aggregation filters — `server/router/api/v1/user_service_stats.go:84-92` and `:217-221`

**Attachment surfaces (two separate implementations)**
- API attachment permission check via linked memo — `server/router/api/v1/attachment_service.go:436-455`, plus `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-225`
- Raw HTTP file server `checkAttachmentPermission` (own copy, including the anonymous-instance rule and a `share_token` bypass) — `server/router/fileserver/fileserver.go:650-703`

**Reactions**
- `ListMemoReactions` / `UpsertMemoReaction` / delete paths — `server/router/api/v1/reaction_service.go:29-42`, `:82-85`, `:151+`

**Real-time (SSE)**
- Per-client broadcast filter `SSEClient.canReceive` (PRIVATE → creator or admin) — `server/router/api/v1/sse_hub.go:134-143`, event visibility populated in `server/router/api/v1/sse_event_helpers.go:29-37`

**Share links (deliberate bypass surface)**
- `GetMemoByShare` returns a memo of any visibility for a valid, unexpired token, gated only on token validity + not archived — `server/router/api/v1/memo_share_service.go:153-192`

**Public/unauthenticated read surfaces (hard-coded PUBLIC only)**
- RSS explore and per-user feeds — `server/router/rss/rss.go:90` and `:141`
- Sitemap generation — `server/router/frontend/frontend.go:150`

**Notification surfaces (two independent `canViewerAccessMemo` copies)**
- In-app inbox/notification rendering — `server/router/api/v1/user_service_notifications.go:302` (used at `:337`, `:342`, `:370`, `:385`)
- Email notifications — `server/notification/email.go:306` (used at `:155`, `:187`)
- Mention notification targeting — `canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-89`

The MCP surface (`server/router/mcp/adapter.go`) is not a separate site — it proxies HTTP requests into the same v1 API and inherits its checks. The store layer (`store/db/{sqlite,postgres,mysql}/memo.go`) only translates `FindMemo.VisibilityList`/filters into SQL; it applies no policy of its own.
