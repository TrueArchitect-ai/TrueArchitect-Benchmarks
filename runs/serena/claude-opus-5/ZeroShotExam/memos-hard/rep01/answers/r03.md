**Premise correction: there is no nightly database-cleanup job in this repository.** The question assumes a scheduled DB-cleanup job exists; it doesn't.

What actually exists:

- `internal/scheduler/` is a **standalone, generic cron scheduler library** (`scheduler.New()`, `Register(*Job)`, cron parsing, middleware). Its package doc explicitly advertises zero external dependencies — it's infrastructure, not a job registry (`internal/scheduler/doc.go`).
- **Nothing in the application imports it.** The only importers are its own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No production code registers any job with it.
- The only "cleanup at 2 AM" references are **illustrative examples, not real jobs**:
  - `internal/scheduler/doc.go:15-16` — a doc-comment sample job named `daily-cleanup` with `Schedule: "0 2 * * *" // 2 AM daily`
  - `internal/scheduler/example_test.go:97-100` — a runnable Go example named `cleanup` with `Schedule: "0 2 * * *"`, alongside equally fictional `health-check` and `weekly-backup` jobs

  Neither touches the database; both are placeholder handlers that print a string or return `nil`.

The server's actual background work does not use the scheduler at all: `server/server.go:153-173` starts a single background runner — the S3 presign refresher (`server/runner/s3presign/runner.go`) — via a goroutine, not a cron schedule.

So if you saw `0 2 * * *` and read it as the app's nightly DB cleanup, that's a documentation example for the scheduler library. If you want a real nightly cleanup job, it would need to be written and wired into `startBackgroundRunners` in `server/server.go`.
