Notes on the hops:

- **The URL is server-generated.** The stored `avatar_url` column holds a base64 data URI, not a path. `convertUserFromStore` (`user_service_converters.go:33-36`) detects the data-URI form and substitutes `/file/{userpb.Name}/avatar`, where `Name` is `users/{username}` from `BuildUserName` (`server/router/api/v1/user_resource_name.go:13`). If the stored value isn't base64, it's passed through verbatim as an external URL and no hop below happens.
- **Auth gate.** `serveUserAvatar` only requires a viewer when the instance is private: `s.Profile.AllowAnonymous()` false → `getCurrentUser` (`fileserver.go:708`) → `Authenticator.AuthenticateToUser` (`server/auth/authenticator.go:190`), bearer/PAT then refresh-token cookie. On a public instance any user's avatar is anonymous-readable.
- **Lookup is by username only** — `store.FindUser{Username: &identifier}` (`fileserver.go:716`), so the `:identifier` param must be the bare username, not the `users/{id}` resource name.
- **Cache is bypassed here.** `Store.GetUser` only consults `userCache` when `find.ID` is set (`store/user.go:149-156`); a username lookup always falls through to `ListUsers` and hits the DB, then populates the cache keyed by ID.
- **Final decode happens in the handler**, not the store: `parseDataURI` regex-splits `data:<type>;base64,<payload>` and base64-decodes it (`fileserver.go:737-750`), the type is checked against `avatarAllowedTypes` (`fileserver.go:75-83`), and the bytes go out via `c.Blob` with `nosniff`/`DENY`/CSP headers and 1-hour caching.
