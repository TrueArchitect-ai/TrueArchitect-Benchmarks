**Premise correction:** There is no GraphQL schema in this repository. A case-insensitive grep for `graphql` across the whole tree (excluding `node_modules`) returns zero hits, and there are no `.graphql`/`.gql` files. Memos does not expose a GraphQL API at all.

**Actual API surface: Protocol Buffers (gRPC) with a REST gateway.**

The public API is defined as `.proto` service definitions in `proto/api/v1/`:

- `proto/api/v1/memo_service.proto` — `MemoService`
- `proto/api/v1/user_service.proto` — `UserService`
- `proto/api/v1/auth_service.proto` — `AuthService`
- `proto/api/v1/attachment_service.proto` — `AttachmentService`
- `proto/api/v1/instance_service.proto` — `InstanceService`
- `proto/api/v1/shortcut_service.proto` — `ShortcutService`
- `proto/api/v1/idp_service.proto` — `IdentityProviderService`
- `proto/api/v1/ai_service.proto` — `AIService`
- `proto/api/v1/common.proto` — shared types

Design conventions follow the Google API Improvement Proposals, per `proto/api/v1/README.md`.

**Code generation** is driven by buf (`proto/buf.gen.yaml`, `proto/buf.yaml`), which emits:
- Go message/gRPC/Connect/grpc-gateway stubs into `proto/gen/api/v1/` (`*.pb.go`, `*_grpc.pb.go`, `*.pb.gw.go`)
- An OpenAPI 3.0.3 document at `proto/gen/openapi.yaml` (via gnostic), embedded through `proto/openapi_embed.go` — this is the closest analogue to a "schema document" for the public API
- TypeScript client types into `web/src/types/proto` (via `bufbuild/es`) for the frontend

**How it's served:** `server/router/api/v1/v1.go` wires everything up. `RegisterGateway` (line 65) registers each service's grpc-gateway handler, exposing REST/JSON under `/api/v1` (e.g. `POST /api/v1/ai:transcribe`), plus Connect handlers under `/memos.api.v1.*` for browser clients (line 144).

A separate, non-proto surface also exists: `proto/store/*.proto` holds internal persistence types (not public API), and `server/router/mcp/` serves an MCP endpoint, with `server/router/rss/` and `server/router/fileserver/` providing RSS and file-serving routes.
