**delivery function — `Post` in `internal/webhook/webhook.go:120`; protection mechanism — `safeDialContext` / `isReservedIP` + `ValidateURL` in `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44,62`**

How it fits together:

**Outbound delivery**
- `webhook.Post` (`internal/webhook/webhook.go:120`) marshals the payload, optionally adds Standard-Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and issues the actual `POST` via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.
- Callers don't invoke it directly — `webhook.PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:39-55`), each of which calls `Post`. The enqueue points are `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (memo created/updated/deleted and comment-created events).

**SSRF protection — two layers**
1. *Dial-time (the one that actually protects delivery):* `safeClient` is built with a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the host itself and refuses the connection if **any** resolved address is reserved — this is what defeats DNS rebinding, since the check happens on the same resolution path as the connect.
2. *Config-time:* `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates/updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`). It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument`.

Both layers share `isReservedIP` (`internal/webhook/validate.go:44`), which tests against `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, the three RFC-1918 blocks, `169.254.0.0/16` (cloud IMDS), plus IPv6 loopback, ULA, and link-local. Note these are the only blocked ranges — e.g. `0.0.0.0/8`, CGNAT `100.64.0.0/10`, and IPv4-mapped IPv6 forms are not in the list.

One caveat worth flagging: the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` entirely, but nothing in the non-test codebase ever assigns it — only `internal/webhook/webhook_test.go:91,142` do. So there is currently no flag or env var exposing it to self-hosted operators, despite the doc comment describing that use case.
