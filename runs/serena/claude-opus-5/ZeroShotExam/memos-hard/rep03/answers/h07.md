The URL the browser hits is not a blob path — the API rewrites base64 avatars to `/file/users/{username}/avatar`, and the handler decodes the data URI out of the `user` row at request time. There is no avatar file on disk or in S3.

**Where the URL comes from (setup, not a hop):**
- `convertUserFromStore` — `server/router/api/v1/user_service_converters.go:36` sets `AvatarUrl = "/file/" + BuildUserName(username) + "/avatar"` (i.e. `/file/users/{username}/avatar`) when the stored value is a base64 data URI
- `UserAvatar` — `web/src/components/UserAvatar.tsx:14` renders `<img src={avatarUrl}>`, so the browser issues a plain GET

**Request path:**

- `FileServerService.RegisterRoutes` — `server/router/fileserver/fileserver.go:124` (`GET /file/users/:identifier/avatar`; wired up at `server/server.go:81`)
- `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
- `FileServerService.getCurrentUser` → `Authenticator.AuthenticateToUser` — `server/router/fileserver/fileserver.go:708` → `server/auth/authenticator.go:190` (only when `!s.Profile.AllowAnonymous()`; gate on the *viewer*, not on whose avatar it is)
- `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715`
- `Store.GetUser` — `store/user.go:148` (cache hit only when `find.ID` is set; a username lookup always falls through)
- `Store.ListUsers` — `store/user.go:136` → `s.driver.ListUsers` (`ListUsers` on the `Driver` interface, `store/driver.go:47`)
- `DB.ListUsers` — `store/db/sqlite/user.go:88` (`SELECT ... avatar_url ... FROM user WHERE username = ?`); same method in `store/db/postgres/user.go` and `store/db/mysql/user.go`
- `FileServerService.parseDataURI` — `server/router/fileserver/fileserver.go:737` base64-decodes `user.AvatarURL`, then MIME-checked against `avatarAllowedTypes` and returned via `c.Blob` (`fileserver.go:201-209`)

Two things worth noting: the avatar bytes live in the `user.avatar_url` column as a data URI, so this path never touches the attachment/local/S3 storage layer; and the authorization check is presence-of-any-session, so any authenticated user (or anyone at all on an instance with `InstanceURL` set) can fetch any other user's avatar by username.
