**Premise correction:** Neither. This repository (memos, a Go monolith) has no external message broker at all — `go.mod`/`go.sum` contain no NATS, AMQP/RabbitMQ, Kafka, or Redis dependencies (grep returns nothing). There are no "webhook delivery workers" as a separate consuming service either.

**Actual mechanism — an in-process buffered Go channel:**

- **Queue declaration:** `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, a package-level buffered channel holding 128 payloads.
- **Workers:** `internal/webhook/webhook.go:42-55` — a package `init()` spawns exactly 4 goroutines, each ranging over `asyncPostQueue` and calling `Post(payload)`. These live in the same process as the API server; they aren't separate worker processes.
- **Producer:** `webhook.PostAsync()` (`internal/webhook/webhook.go:184-196`) does a non-blocking `select` send. If the buffer is full, the payload is **dropped** with a `slog.Warn` — there is no persistence, retry, or dead-lettering. A process restart loses anything still queued.
- **Call sites:** `server/router/api/v1/memo_service_webhooks.go:43` and `:71` enqueue payloads for memo created/updated/deleted and comment-created events, one per registered user webhook (`Store.GetUserWebhooks`).

Delivery itself is a plain HTTP POST via a shared `http.Client` with a 30s timeout and an SSRF-guarding dialer that rejects reserved/private IPs (`internal/webhook/webhook.go:32-37`, `59-77`), optionally signed with Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`) at `internal/webhook/webhook.go:133-150`.
