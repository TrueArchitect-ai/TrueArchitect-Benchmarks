**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider implementation maps its claims into.
- **Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol implementation. It provides `IdentityProvider` backed by `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (with optional PKCE `code_verifier`, `internal/idp/oauth2/oauth2.go:47`) and `UserInfo` (`internal/idp/oauth2/oauth2.go:83`), which applies the configured field mapping to produce an `idp.IdentityProviderUserInfo`.

Supporting evidence that OAuth2 is the sole shipped protocol:
- `server/router/api/v1/auth_service_sso.go:12-13` is the only consumer, importing exactly those two packages.
- The proto enums list only `OAUTH2 = 1` as a provider type — `proto/store/idp.proto:13` and `proto/api/v1/idp_service.proto:79`. No SAML/LDAP implementation exists.
