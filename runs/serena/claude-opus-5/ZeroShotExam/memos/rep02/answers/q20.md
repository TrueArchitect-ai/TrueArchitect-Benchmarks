**Mechanism:** Server-Sent Events (SSE) over a plain HTTP `GET /api/v1/sse` endpoint (`Content-Type: text/event-stream`, 30s heartbeat comments, Bearer-token auth). Not WebSockets.

**Hub path:** `server/router/api/v1/sse_hub.go` — `SSEHub` (`NewSSEHub`, `Subscribe`, `Unsubscribe`, `Broadcast`, `Close`), with per-client visibility filtering in `SSEClient.canReceive` (private memos only go to the creator or an admin). Supporting files:
- `server/router/api/v1/sse_handler.go` — `RegisterSSERoutes` / `handleSSE` (the streaming endpoint)
- `server/router/api/v1/sse_event_helpers.go` — `buildMemoReactionSSEEvent`, `resolveSSECreatorID`
- wired up in `server/router/api/v1/v1.go:57` (`SSEHub: NewSSEHub()`) and `:125` (`RegisterSSERoutes`), held by `server/server.go:38`
- client consumer: `web/src/hooks/useLiveMemoRefresh.ts` (fetch-based SSE reader that invalidates React Query caches)

**Handlers that broadcast:**
- `CreateMemo` — `memo.created` (`server/router/api/v1/memo_service.go:163`, skipped when `isSSESuppressed`, i.e. when invoked from `CreateMemoComment`)
- `DeleteMemo` — `memo.deleted` (`server/router/api/v1/memo_service.go:585`)
- `CreateMemoComment` — `memo.comment.created` for the parent memo (`server/router/api/v1/memo_service_comments.go:126`)
- `UpsertMemoReaction` — `reaction.upserted` (`server/router/api/v1/reaction_service.go:106`)
- `DeleteMemoReaction` — `reaction.deleted` (`server/router/api/v1/reaction_service.go:161`)
- `memo.updated` is emitted indirectly through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:71`), called by `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`)
