**`web/src/connect.ts`; short-lived JWT access token (localStorage, in `Authorization: Bearer`) + long-lived HttpOnly refresh-token cookie (`memos_refresh`), with Personal Access Tokens as the alternate bearer credential; `server/auth`**

How it fits together:

**Interceptor** — `authInterceptor` in `web/src/connect.ts:145` is registered on the Connect-Web transport (`web/src/connect.ts:170`) that backs every service client (memo, user, attachment, etc.). On each request it calls `getRequestToken()`, sets `Authorization: Bearer <token>`, and on a `Code.Unauthenticated` reply refreshes once, replays with an `X-Retry: true` marker to prevent loops, and on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).

**Tokens**
- Access token — 15 min JWT, held in memory + `localStorage` (`memos_access_token` / `memos_token_expires_at`) by `web/src/auth-state.ts`, shared across tabs via a `BroadcastChannel` (`memos_token_sync`). Preflight refresh fires when it's within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`); `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus with a 2 min buffer.
- Refresh token — 30 day JWT in the HttpOnly `memos_refresh` cookie (`server/auth/token.go:49`, set at `server/router/api/v1/auth_service_session.go:226`). The frontend never reads it; it's sent because the transport uses `credentials: "include"`, and refresh goes through a *separate* transport with no interceptors to avoid recursion (`web/src/connect.ts:64`). Concurrent refreshes are deduped by `tokenRefreshManager`.
- Personal Access Tokens (`memos_pat_` prefix) — the other bearer credential the same header path accepts, for programmatic clients.

**Backend validation** — package `server/auth`: `token.go` mints/parses (`ParseAccessTokenV2`, `ParseRefreshToken`), `extract.go` pulls the bearer and the cookie, and `authenticator.go` resolves them — access tokens statelessly, refresh tokens against the DB for revocation/expiry (`server/auth/authenticator.go:61`), PATs by hash lookup. It's shared by the Connect/gRPC-Gateway `Authorizer` (`server/router/api/v1/authz.go:36`) and the file server (`server/router/fileserver/fileserver.go:115`), so all transports enforce the same rules.
