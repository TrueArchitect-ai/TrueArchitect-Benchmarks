**Engine:** Google CEL (`github.com/google/cel-go` v0.28.1, `go.mod:13`), wrapped by the in-repo memo filter engine at **`internal/filter/`** (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`, `helpers.go`).

**Mechanism (one sentence):** `ListMemos` (`server/router/api/v1/memo_service.go:211-216`) validates `request.Filter` via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`) and stashes it in `store.FindMemo.Filters`; each driver's `ListMemos` then calls `filter.DefaultEngine()` + `filter.AppendConditions(...)` with its own dialect constant (`store/db/sqlite/memo.go:57,61` → `DialectSQLite`; `store/db/mysql/memo.go:65,69` → `DialectMySQL`; `store/db/postgres/memo.go:54,58` → `DialectPostgres`), which runs the three-phase pipeline — `cel.Env.Compile` parses/type-checks the expression against the memo schema's declared variables (`internal/filter/engine.go:47-58`, `schema.go NewSchema()`), `buildCondition` (`internal/filter/parser.go`) normalizes the CEL AST into a dialect-agnostic IR (`internal/filter/ir.go`), and the renderer (`internal/filter/render.go`) walks that IR into a SQL fragment plus bind args, encoding all dialect differences (`?` vs `$n` placeholders at `render.go:843-846`, `LIKE` vs `ILIKE` at `render.go:584-586`, JSON access `json_extract`/`JSON_EXTRACT`/`->>`, tag membership as `LIKE` / `JSON_CONTAINS` / `@>`), which `AppendConditions` (`internal/filter/helpers.go`) appends to the query's `WHERE` list with a placeholder offset.

Details worth noting:
- Field-level dialect SQL can also be declared in the schema itself via `Field.Expressions` per `DialectName` (e.g. `creator` → `('users/' || %s)` for SQLite/Postgres, `CONCAT('users/', %s)` for MySQL — `internal/filter/schema.go`).
- The engine is a `sync.Once` singleton per schema (`DefaultEngine` / `DefaultAttachmentEngine`, `internal/filter/engine.go:110-124`) so the CEL environment is built once per process.
- Timestamps (`now`, `duration(...)`, `timestamp(...)`) fold to epoch seconds at compile time, with `now` frozen once per compile (`internal/filter/engine.go:16-21`, `README.md`).
- Trivially-true filters render to empty SQL (skipped) and unsatisfiable ones to `1 = 0` (`internal/filter/render.go:41-56`).
- The server also injects its own CEL filter string for visibility scoping (`creator_id == N || visibility in ["PUBLIC", "PROTECTED"]`, `server/router/api/v1/memo_service.go:222`), which flows through the same engine.
