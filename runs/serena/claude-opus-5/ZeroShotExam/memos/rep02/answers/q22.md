**`DispatchMemoCreatedWebhook` — `server/router/api/v1/memo_service_webhooks.go`; `internal/webhook` (Go stdlib `net/http` client); HMAC-SHA256 Standard Webhooks signature (`webhook-id`/`webhook-timestamp`/`webhook-signature: v1,<base64>`)**

Flow:

1. **Handler** — `CreateMemo` calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)` at `server/router/api/v1/memo_service.go:157`, best-effort (failures only logged via `slog.Warn`).
2. **Dispatcher** — `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`) delegates to `dispatchMemoRelatedWebhook` with activity type `"memos.memo.created"`. That resolves the memo creator, loads `s.Store.GetUserWebhooks(ctx, creatorID)`, and for each hook builds a `webhook.WebhookRequestPayload` (via `convertMemoToWebhookPayload`) carrying the hook's `Url` and `SigningSecret`, then calls `webhook.PostAsync(payload)`.
3. **Delivery** — `internal/webhook` (`internal/webhook/webhook.go`). `PostAsync` enqueues onto a bounded 128-slot channel drained by 4 worker goroutines started in `init()`; dropped with a warning if full. Workers call `Post`, which POSTs JSON over `safeClient`, a shared `net/http` client with a 30s timeout and a `safeDialContext` transport that rejects reserved/private IPs (SSRF / DNS-rebinding guard). Non-2xx, or a response body with a non-zero `code`, is treated as an error.
4. **Signing** — when the hook has a signing secret, `Post` derives the key with `resolveSigningKey` (a `whsec_`-prefixed secret is base64-decoded to raw bytes; anything else used verbatim), then HMAC-SHA256 over `msgID + "." + timestamp + "." + body`. Headers set: `webhook-id` (`msg_<uuid>`), `webhook-timestamp` (Unix seconds), and `webhook-signature` (`v1,<base64 mac>`) — the Standard Webhooks scheme. Secrets are generated by `GenerateSigningSecret` from 32 crypto-random bytes.
