There is no ORM/tag-based mapping in this repo — tables are bound to structs by hand-written SQL in the per-driver store layer (`store/db/sqlite`, `store/db/mysql`, `store/db/postgres`), which scans rows into the domain structs defined in `store/`.

- **user**: `User` — `store/user.go:29` (SQL binding it: `store/db/sqlite/user.go:17` `INSERT INTO user (...)`, `:164` `FROM user`; parallel files in `store/db/mysql/user.go`, `store/db/postgres/user.go`)
- **attachment**: `Attachment` — `store/attachment.go:16` (SQL: `store/db/sqlite/attachment.go:34` `INSERT INTO \`attachment\``, `:109` `FROM \`attachment\``; also `store/db/mysql/attachment.go`, `store/db/postgres/attachment.go`)
- **reaction**: `Reaction` — `store/reaction.go:7` (SQL: `store/db/sqlite/reaction.go:16` `INSERT INTO \`reaction\``, `:60`/`:113` `FROM reaction`; also `store/db/mysql/reaction.go`, `store/db/postgres/reaction.go`)

Note the `Find*`/`Update*`/`Delete*` structs alongside each (e.g. `FindUser`, `UpdateAttachment`, `DeleteReaction`) are query-parameter structs, not table rows.
