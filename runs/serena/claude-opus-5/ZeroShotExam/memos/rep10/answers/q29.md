**`web/src/connect.ts`; JWT access token (in-memory + localStorage) and refresh token (HttpOnly cookie), plus Personal Access Tokens for API clients; `server/auth`**

### Frontend interceptor
- `web/src/connect.ts` defines `authInterceptor` (a Connect-RPC `Interceptor`) which is attached to the shared `createConnectTransport` used by every service client (`memoServiceClient`, `userServiceClient`, etc.). It sets `Authorization: Bearer <token>` on each request, and on a `Code.Unauthenticated` error refreshes once and retries the request with an `X-Retry: true` header, redirecting via `web/src/utils/auth-redirect.ts` if the refresh fails.
- Refresh calls go through a *separate* transport with no interceptors (`refreshTransport`/`refreshAuthClient`) to avoid recursion, and are deduplicated by `tokenRefreshManager`. `fetchWithCredentials` sets `credentials: "include"` so the refresh cookie is sent.

### Tokens it manages
- **Access token** — short-lived JWT held in `web/src/auth-state.ts` (module variable + `localStorage` keys `memos_access_token` / `memos_token_expires_at`), with preflight refresh when within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) and cross-tab sync over a `BroadcastChannel` (`memos_token_sync`). `web/src/hooks/useTokenRefreshOnFocus.ts` proactively refreshes on tab focus using the 2-minute buffer.
- **Refresh token** — never touched by JS; it's an HttpOnly cookie (`memos_refresh`, `server/auth/token.go:49`) sent automatically and exchanged via `AuthService.RefreshToken`.

### Backend validation
- `server/auth` (`github.com/usememos/memos/server/auth`): `authenticator.go` (`Authenticator.AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken` — the latter also does a DB revocation check), `token.go` (JWT generation/parsing, `AccessTokenDuration` 15m, `RefreshTokenDuration` 30d, `PersonalAccessTokenPrefix = "memos_pat_"`), `extract.go` (`ExtractBearerToken`, `ExtractRefreshTokenFromCookie`), `context.go`.
- It's wired into requests by the Connect interceptor at `server/router/api/v1/connect_interceptors.go:220` (reads `Authorization`, calls `auth.ApplyToContext`), and reused by the gRPC path and `server/router/fileserver`.
