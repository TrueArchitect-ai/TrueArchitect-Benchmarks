**`APIV1Service.SignIn` — `server/router/api/v1/auth_service.go:51`**

This is the actual business-logic implementation of the `SignIn` RPC declared at `proto/api/v1/auth_service.proto:24`. It handles both password credentials (bcrypt comparison against `user.PasswordHash`, plus a `DisallowPasswordAuth` check) and SSO/OAuth2 credentials, then calls `s.doSignIn` to mint the access token.

Related plumbing:
- `ConnectServiceHandler.SignIn` — `server/router/api/v1/connect_services.go:78` is a thin Connect-protocol wrapper that unwraps the request and delegates to `APIV1Service.SignIn`, wrapped in `connectWithHeaderCarrier` so the handler can set response headers (e.g. the session cookie).
- Session/token helpers live in `server/router/api/v1/auth_service_session.go`, SSO identity resolution in `server/router/api/v1/auth_service_sso.go`.
