`Store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) deletes, in order, before the memo row itself:

1. **Memo relations where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relations where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments{MemoID: ...}` and removed one by one with `Store.DeleteAttachment` (`store/memo.go:148-157`), which also deletes the underlying stored file/blob (`store/attachment.go:132-148`)

Only then does it call the driver's `DeleteMemo`, which is a plain `DELETE FROM memo WHERE id = ?` (e.g. `store/db/sqlite/memo.go:237`).

Note the API layer does extra work around this, not inside it: `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-577`) first finds comment relations and calls `Store.DeleteMemo` for each comment memo, then deletes the memo itself. Reactions are only read for the webhook payload there — they aren't deleted in the store's `DeleteMemo` path.
