**Runners the server actually starts**

- **S3 presign runner** (`server/runner/s3presign/runner.go`) — the only thing `Server.startBackgroundRunners` launches (`server/server.go:153-174`). Triggered twice: one immediate synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a goroutine running `Run(s3Context)` driven by a `time.NewTicker(12h)` loop (`s3presign/runner.go:29-40`, `runnerInterval = time.Hour * 12`). It exits on its own `context.CancelFunc`, stored in `backgroundRunnerCancels` and fired by `stopBackgroundRunners` during shutdown; the WaitGroup is joined in `waitBackgroundRunners`.
- **HTTP server goroutine** (`server/server.go:124`) — `httpServer.Serve(listener)`; started by `Server.Start`, not ticker-driven.
- **Store cache cleanup loops ×3** (`store/cache/cache.go:83`, `cleanupLoop` at `cache.go:199-206`) — started implicitly by `cache.New` for `instanceSettingCache`, `userCache`, `userSettingCache` in `store.New` (`store/store.go:39-53`). Driven by `time.NewTicker(CleanupInterval)` = 5 min, TTL 10 min. Stopped via `Store.Close` → cache close channel.
- **Webhook dispatch workers ×4** (`internal/webhook/webhook.go:42-54`) — started by a package `init()`, not by the server. Queue-driven: they range over `asyncPostQueue` (buffered 128); trigger is a webhook event being enqueued, not a clock.
- **Email send workers ×2** (`internal/email/email.go:16-34`) — same shape: package `init()`, consuming `asyncEmailQueue` (buffered 128), event/queue-driven.
- **SSE heartbeat ticker** (`server/router/api/v1/sse_handler.go:64`) — per-connection, inside the request handler, `sseHeartbeatInterval = 30s`. Lives for the life of a client stream, not a server-level worker.
- **Signal handler goroutine** (`cmd/memos/main.go:99`) — waits on SIGINT/SIGTERM, calls `s.Shutdown`.

**Unused scheduling infrastructure**

- `internal/scheduler/` — a full cron scheduler (5/6-field cron parsing, timezone support, middleware for recovery/logging/timeout, graceful shutdown; `scheduler.go`, `job.go`, `parser.go`, `middleware.go`, plus `README.md`/`doc.go`) is **not wired into the server at all**. The only files importing `github.com/usememos/memos/internal/scheduler` are its own `example_test.go` and `integration_test.go`. No production code registers a job or calls `Start()`.
- `server/runner/memopayload` — the `Runner` type and its `RunOnce` batch rebuild (`memopayload/runner.go:27-71`) are never instantiated; nothing calls `memopayload.NewRunner`. Only the standalone helper `RebuildMemoPayload` is used, synchronously inside `server/router/api/v1/memo_service.go:108` and `:447`. So the package exists as a runner but is not run as one.
