**Mechanism:** Server-Sent Events (SSE) over a plain HTTP GET stream — not WebSockets. The endpoint is `GET /api/v1/sse`, registered in `server/router/api/v1/sse_handler.go:25-30` and wired up at `server/router/api/v1/v1.go:125`. It authenticates via a Bearer token, sets `Content-Type: text/event-stream` (plus `no-cache`, `keep-alive`, `X-Accel-Buffering: no`), writes an initial `: connected` comment, then flushes `data: {...}\n\n` frames with a `: heartbeat` comment every 30s (`sseHeartbeatInterval`). The browser side is `web/src/hooks/useLiveMemoRefresh.ts`, which consumes the stream and invalidates React Query caches with exponential-backoff reconnection.

**Hub:** `server/router/api/v1/sse_hub.go` — `SSEHub` (created by `NewSSEHub()` at `server/router/api/v1/v1.go:57`, closed by the server at `server/server.go:205-206`). It's a mutex-guarded `map[*SSEClient]struct{}`; `Subscribe`/`Unsubscribe` manage per-client 32-buffered channels, `Broadcast` marshals the event to JSON and does a non-blocking send (dropping events for slow clients). `SSEClient.canReceive` filters private-visibility events to the creator or admins.
