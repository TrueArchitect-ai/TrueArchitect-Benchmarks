**`web/src/connect.ts` (authInterceptor, with token storage in `web/src/auth-state.ts`); JWT access token (Bearer, in localStorage) + HttpOnly `memos_refresh` refresh-token cookie (backend also accepts PATs as bearer); `server/auth` (Go package, validated via `server/router/api/v1/connect_interceptors.go`)**

Details:

**Frontend interceptor** — `web/src/connect.ts:145` defines `authInterceptor`, attached to the Connect-RPC transport (`web/src/connect.ts:171`) that all service clients are built from. It:
- calls `getRequestToken()` and sets `Authorization: Bearer <token>` (`web/src/connect.ts:88`)
- preflight-refreshes if the access token is within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), so public endpoints don't silently return guest-scoped data
- on a `Code.Unauthenticated` error, refreshes once and retries with an `X-Retry: true` header guard; on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`)
- refreshes through `AuthService.RefreshToken` on a *separate* transport with no interceptors to avoid recursion (`web/src/connect.ts:64`), deduped by `tokenRefreshManager`
- all fetches use `credentials: "include"` so the refresh cookie rides along

**Token kinds:**
- Access token — JWT, kept in memory + `localStorage` (`memos_access_token` / `memos_token_expires_at`) in `web/src/auth-state.ts`, cross-tab synced via a `BroadcastChannel` (`memos_token_sync`). Proactively refreshed on tab focus by `web/src/hooks/useTokenRefreshOnFocus.ts` (2-minute buffer).
- Refresh token — HttpOnly cookie `memos_refresh` (`server/auth/token.go:49`), never touched by JS; set/rotated in `server/router/api/v1/auth_service_session.go:226`.
- The backend additionally accepts a personal access token as the bearer value (`Authenticator.AuthenticateByPAT`, `server/auth/authenticator.go:102`).

**Backend validation** — package `auth` at `server/auth/`: `extract.go` pulls the bearer token / refresh cookie, `token.go` does `ParseAccessTokenV2` / `ParseRefreshToken` (JWT signing-method + kid check in `verifyJWTKeyFunc`), `authenticator.go` resolves it to a user. It's invoked per-RPC from the Connect interceptor at `server/router/api/v1/connect_interceptors.go:222` (also `v1.go:78` for gRPC, `sse_handler.go`, and `server/router/fileserver/fileserver.go`), via the thin `Authorizer` wrapper in `server/router/api/v1/authz.go`.
