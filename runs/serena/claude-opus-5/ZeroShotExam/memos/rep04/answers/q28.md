**Workers the server actually starts** (all launched from `Server.startBackgroundRunners`, `server/server.go:153-174`):

- **s3presign runner (`RunOnce`, startup pass)** — triggered once, synchronously, at server start (`server/server.go:163`); re-presigns S3 attachment URLs immediately.
- **s3presign runner (`Run`, continuous loop)** — driven by a plain `time.NewTicker` with a hardcoded 12-hour interval (`server/runner/s3presign/runner.go:27-40`), running in a goroutine tracked by `backgroundRunnerWG` and stopped via its own `context.CancelFunc` on shutdown (`server/server.go:156-171`, `176-201`). Each tick calls `CheckAndPresign`, which pages attachments in batches of 100 and refreshes any presigned URL within 4 days of its 5-day expiry.

That is the entire set — `startBackgroundRunners` registers exactly one runner.

**Related goroutines that exist but aren't "runners" started by `startBackgroundRunners`:**

- **Store cache janitors (×3)** — started indirectly by `store.New` → `cache.New` → `go c.cleanupLoop()` (`store/cache/cache.go:76-85`, `183-213`), one each for the instance-setting, user, and user-setting caches, on a 5-minute `CleanupInterval` ticker (`store/store.go:40-53`). Created in `main` before the server, not by the server's runner machinery.
- **SSE heartbeat ticker** — per-connection, not a background worker; lives for the lifetime of one SSE request (`server/router/api/v1/sse_handler.go:64`).
- Fire-and-forget goroutines for PAT last-used updates (`server/auth/authenticator.go:180`), webhook dispatch (`internal/webhook/webhook.go:44`), and email sending (`internal/email/email.go:18`) — event-driven, one goroutine per call, no scheduling.

**Unused scheduling infrastructure:**

- **`internal/scheduler` is dead code from the server's perspective.** It's a full GitHub-Actions-style cron scheduler — cron expression parser (5- and 6-field), timezone-aware scheduling, middleware chain with `Recovery()`/`Logging()`, graceful shutdown (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`, `doc.go`, plus its own README) — but `grep` for `scheduler` across the repo returns hits only inside `internal/scheduler` itself (its tests, doc.go, example_test.go) and one passing mention in `AGENTS.md:69`. Nothing in `server/`, `cmd/`, or `store/` imports it, and `Scheduler.Start()` (`internal/scheduler/scheduler.go:91`) is never called outside the package's own tests. The one recurring job the server does have (s3presign) uses a raw ticker instead.
