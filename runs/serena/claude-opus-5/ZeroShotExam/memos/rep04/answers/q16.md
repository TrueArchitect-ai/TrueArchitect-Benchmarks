`Store.DeleteMemo` in `store/memo.go:140-159` performs this cleanup before deleting the memo row itself:

1. **Memo relation records where the memo is the source** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
2. **Memo relation records where the memo is the target/related memo** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and removed one-by-one with `s.DeleteAttachment` (`store/memo.go:149-157`). `Store.DeleteAttachment` (`store/attachment.go:132-149`) also removes the underlying stored blob/local file via `DeleteAttachmentStorage` before deleting the attachment row.

Only then does it call `s.driver.DeleteMemo(ctx, delete)` (`store/memo.go:158`), which issues the plain `DELETE FROM memo WHERE id = ?` (e.g. `store/db/sqlite/memo.go:237`).

For context, things done *outside* the store layer: the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-580`) first deletes the memo's comment memos (each via `Store.DeleteMemo`, so their own relations/attachments are cleaned up too). Reactions and memo shares are not deleted by the store's `DeleteMemo` — reactions are only listed for the webhook payload.
