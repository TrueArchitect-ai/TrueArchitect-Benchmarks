**Convergence for delivery:**

The first three funnel through the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator and loads their webhooks. `DispatchMemoCommentCreatedWebhook` bypasses that helper — it targets the *related* memo's owner (`relatedMemoCreatorID`) rather than the comment author — but builds the same payload inline.

All four then converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue` (capacity 128, dropped with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`) drain the queue and call `webhook.Post` (`internal/webhook/webhook.go:120`), which does the actual HTTP POST — HMAC-SHA256 Standard Webhooks signing when a signing secret is set, sent via `safeClient` whose `safeDialContext` blocks reserved/private IPs (SSRF guard).
