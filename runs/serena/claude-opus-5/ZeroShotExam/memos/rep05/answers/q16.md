The store-layer `Store.DeleteMemo` (`store/memo.go:140-159`) removes these before deleting the memo row via `s.driver.DeleteMemo`:

1. **`memo_relation` records where the memo is the source** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
2. **`memo_relation` records where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **`attachment` records linked to the memo** — listed via `ListAttachments(FindAttachment{MemoID: ...})` and deleted one by one with `s.DeleteAttachment` (`store/memo.go:149-157`). Each of those also removes the attachment's backing storage (local file / S3 object) via `DeleteAttachmentStorage` before the row is deleted (`store/attachment.go:132-149`).

Note on the surrounding API path: for a memo with comments, `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:567-580`) first calls `Store.DeleteMemo` for each comment memo (so each comment goes through the same relation/attachment cleanup), then deletes the memo itself. Reactions and memo shares are not deleted in `Store.DeleteMemo`.
