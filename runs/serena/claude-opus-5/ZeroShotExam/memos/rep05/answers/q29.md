**`web/src/connect.ts`; JWT access token (localStorage, 15 min) + HTTP-only `memos_refresh` refresh-token cookie (30 days), plus Personal Access Tokens on the server side; `server/auth`**

**Frontend interceptor** — `web/src/connect.ts:146` defines `authInterceptor`, which is attached to the single Connect-RPC transport (`web/src/connect.ts:170-176`) shared by every generated service client (memo, user, auth, attachment, etc.). It:
- calls `getRequestToken()` and sets `Authorization: Bearer <token>` on each request;
- pre-emptively refreshes when the token is within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`);
- on a `Code.Unauthenticated` response, refreshes once, re-sends with an `X-Retry: true` marker, and on failure calls `redirectOnAuthFailure()`.

Refresh calls go through a separate interceptor-free transport (`refreshTransport`, `web/src/connect.ts:62-72`) to avoid recursion, and through a dedup manager so concurrent refreshes collapse into one. Both transports use `credentials: "include"` so the refresh cookie rides along.

**Token storage** — `web/src/auth-state.ts` holds the access token in memory + `localStorage` (`memos_access_token` / `memos_token_expires_at`) and syncs freshly refreshed tokens across tabs over a `BroadcastChannel` (`memos_token_sync`). `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus with a 2-minute buffer. The refresh token itself is never visible to JS — it's the server-set cookie.

**Backend validation** — `server/auth` (`github.com/usememos/memos/server/auth`):
- `token.go` — JWT constants/claims: `AccessTokenDuration` 15 min, `RefreshTokenDuration` 30 days, `RefreshTokenCookieName = "memos_refresh"`, `PersonalAccessTokenPrefix = "memos_pat_"`.
- `extract.go` — `ExtractBearerToken` (Authorization header) and `ExtractRefreshTokenFromCookie`.
- `authenticator.go` — `AuthenticateByAccessTokenV2` (stateless signature check), `AuthenticateByRefreshToken` (DB-backed revocation/expiry check), `AuthenticateByPAT` (SHA-256 hash lookup).

It's wired into the API by `server/router/api/v1/authz.go:36` (`Authorizer` wrapping `auth.NewAuthenticator`) and applied per-request in `server/router/api/v1/connect_interceptors.go:227`; the same package also backs `server/router/fileserver` and the SSE handler (`server/router/api/v1/sse_handler.go:26`).
