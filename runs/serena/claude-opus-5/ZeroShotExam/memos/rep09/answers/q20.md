**Mechanism:** Server-Sent Events (SSE) over a plain HTTP GET at `/api/v1/sse` — `text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`, with a `: heartbeat` comment every 30s and an initial `: connected` comment. Auth is a Bearer token in the `Authorization` header (`server/router/api/v1/sse_handler.go:34-57`). The browser side is `web/src/hooks/useLiveMemoRefresh.ts` (fetch-based stream with `Accept: text/event-stream`).

**Hub:** `server/router/api/v1/sse_hub.go` — `SSEHub` (mutex-guarded `map[*SSEClient]struct{}`, per-client buffered channel of 32, drops events for slow clients rather than blocking). `SSEClient.canReceive` filters by visibility: private events go only to the creator or an admin. Wired up in `server/router/api/v1/v1.go:57` (`NewSSEHub()`) and `:125` (`RegisterSSERoutes`), closed on shutdown at `server/server.go:205-206`.

**Handlers that broadcast** (all `APIV1Service` methods):

| Handler | File | Event type |
|---|---|---|
| `CreateMemo` | `memo_service.go:163` (skipped when `isSSESuppressed`, i.e. called from comment creation) | `memo.created` |
| `UpdateMemo` | `memo_service.go:513` → `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:71`) | `memo.updated` |
| `DeleteMemo` | `memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `memo_service_comments.go:126` | `memo.comment.created` |
| `SetMemoAttachments` | `memo_attachment_service.go:48` → same helper | `memo.updated` |
| `SetMemoRelations` | `memo_relation_service.go:48` → same helper | `memo.updated` |
| `UpsertMemoReaction` | `reaction_service.go:106` | `reaction.upserted` |
| `DeleteMemoReaction` | `reaction_service.go:161` | `reaction.deleted` |

Event payloads carry `type`, `name`, and optional `parent`; `Visibility`/`CreatorID` are JSON-excluded and used only for server-side delivery filtering, with `resolveSSECreatorID` (`sse_event_helpers.go:12`) substituting the parent memo's creator for comments.
