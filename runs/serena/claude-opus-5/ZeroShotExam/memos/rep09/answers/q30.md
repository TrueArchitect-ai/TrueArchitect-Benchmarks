**Convergence for delivery:**

The first three funnel through the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator and loads their webhooks. The comment case is the exception — it builds its payload inline (`memo_service_webhooks.go:30-46`) because it targets the *parent* memo's owner (`relatedMemoCreatorID`) rather than the comment author, so it never touches that helper.

All four converge at `webhook.PostAsync` in `internal/webhook/webhook.go:184`, which enqueues onto the buffered `asyncPostQueue` (cap 128, dropping with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `webhook.Post` (`internal/webhook/webhook.go:120`), which does the actual HTTP POST — JSON body, optional Standard Webhooks HMAC-SHA256 signing headers, sent via `safeClient` whose `safeDialContext` blocks reserved/private IPs.

All call sites treat dispatch failures as non-fatal, logging via `slog.Warn` rather than failing the request.
