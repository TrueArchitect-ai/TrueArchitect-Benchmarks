**`web/src/connect.ts`; JWT access token (in-memory + localStorage, sent as `Authorization: Bearer`) plus an HTTP-only refresh-token cookie (`memos_refresh`) — the backend also accepts Personal Access Tokens on the same header; `server/auth`**

How it works:

**Frontend interceptor — `web/src/connect.ts`**
- `authInterceptor` (`web/src/connect.ts:145`) is attached to the Connect-Web transport (`web/src/connect.ts:172`) that backs every service client (memo, user, auth, attachment, etc.).
- On each request it calls `getRequestToken()`, which reads the cached access token, and preflight-refreshes when it is within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), then sets `Authorization: Bearer <token>`.
- On a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry: true` marker to prevent loops, and calls `redirectOnAuthFailure()` if the refresh fails.
- Refresh goes through a *separate* transport with no interceptors (`refreshTransport`, `web/src/connect.ts:63`) to avoid recursion, and uses `fetch` with `credentials: "include"` so the refresh cookie is sent.
- Concurrent refreshes are deduplicated by `tokenRefreshManager`; `web/src/hooks/useTokenRefreshOnFocus.ts` also refreshes proactively on tab focus (2-minute buffer).

**Token storage — `web/src/auth-state.ts`**
- Access token + expiry held in module state and mirrored to `localStorage` under `memos_access_token` / `memos_token_expires_at`; a `BroadcastChannel` (`memos_token_sync`) shares freshly refreshed tokens across tabs.
- The refresh token itself is never touched by JS — it's a server-set cookie.

**Backend validation — `server/auth`**
- `server/auth/token.go`: access tokens are 15-minute JWTs (audience `user.access-token`), refresh tokens 30 days (`memos_refresh` cookie), PATs prefixed `memos_pat_`.
- `server/auth/authenticator.go`: `Authenticate()` resolves the bearer token — stateless JWT signature check (`AuthenticateByAccessTokenV2`) or DB-backed PAT lookup; `AuthenticateByRefreshToken` additionally checks the DB for revocation/expiry. `server/auth/extract.go` pulls the token from the `Authorization` header and the cookie.
- It's wired into the RPC path via `server/router/api/v1/connect_interceptors.go` and `server/router/api/v1/authz.go`, and reused by `server/router/fileserver/fileserver.go`.
