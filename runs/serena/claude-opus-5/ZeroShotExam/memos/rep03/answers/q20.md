**Server-Sent Events (SSE); `server/router/api/v1/sse_hub.go`; CreateMemo, DeleteMemo, CreateMemoComment, UpdateMemo/SetMemoRelations/SetMemoAttachments (via `dispatchMemoUpdatedSideEffects`), UpsertMemoReaction, DeleteMemoReaction**

**Mechanism** — plain HTTP SSE (`text/event-stream`), not WebSockets. The endpoint is `GET /api/v1/sse`, registered in `server/router/api/v1/sse_handler.go:25` (`RegisterSSERoutes`, wired at `server/router/api/v1/v1.go:125`). `handleSSE` (`sse_handler.go:34`) authenticates via a Bearer token, sets `Cache-Control: no-cache` / `X-Accel-Buffering: no`, writes an initial `: connected` comment, and then loops writing `data: <json>\n\n` frames plus a `: heartbeat` comment every 30s (`sseHeartbeatInterval`). The browser side is `web/src/hooks/useLiveMemoRefresh.ts`, which consumes the stream and invalidates React Query caches, with exponential-backoff reconnect.

**Hub** — `server/router/api/v1/sse_hub.go`: `SSEHub` holds a mutex-guarded `map[*SSEClient]struct{}`; `Subscribe`/`Unsubscribe`/`Close`/`Broadcast`. Each client gets a 32-buffered channel and events are dropped (non-blocking `select` default) for slow clients. `Broadcast` filters per client via `SSEClient.canReceive`: private-visibility events go only to the creator or an admin. The hub is created in `v1.go:57` and closed on shutdown at `server/server.go:205`. Event types and the `SSEEvent` payload struct also live in `sse_hub.go`; helpers in `sse_event_helpers.go`.
