`Store.DeleteMemo` (`store/memo.go:140-159`) performs this cleanup, in order, before calling `s.driver.DeleteMemo` on the memo row itself:

1. **Memo relations where the memo is the source** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
2. **Memo relations where the memo is the target/related memo** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})` (`store/memo.go:145`)
3. **Attachments linked to the memo** — lists them via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and deletes each with `s.DeleteAttachment` (`store/memo.go:149-157`), which also removes the underlying stored file/blob before the attachment row (`store/attachment.go:132-149`)

Notes on what is *not* done at this layer: reactions and comment memos are handled above the store, in the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-591`) — it recursively calls `Store.DeleteMemo` for comment memos found via `MemoRelationComment` relations, while reactions are only listed for the webhook payload, not explicitly deleted there.
