**Runners the server actually starts** (all launched from `Server.startBackgroundRunners`, `server/server.go:153-174`, called by `Server.Start` at `server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — one synchronous `RunOnce` at startup (`server/server.go:163`), then a goroutine running `Run(ctx)` driven by a `time.Ticker` with a hardcoded 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:26-40`). Cancellation is via a per-runner `context.CancelFunc` stored for shutdown; the WaitGroup is drained in `Shutdown`. It is the *only* entry appended to `backgroundRunnerCancels`/`backgroundRunnerWG`.

Other long-lived goroutines the process starts, indirectly (not registered as "background runners"):

- **Store cache cleanup loops ×3** (`store/cache/cache.go:83`, `cleanupLoop` at `:199`) — a `time.Ticker` at `CleanupInterval = 5 * time.Minute`; started implicitly by `cache.New` for `instanceSettingCache`, `userCache`, `userSettingCache` in `store.New` (`store/store.go:39-53`).
- **Webhook dispatch workers ×4** (`internal/webhook/webhook.go:42-55`) — package `init()`; not scheduled, they block on the `asyncPostQueue` channel (capacity 128), so events drive them.
- **Email send workers ×2** (`internal/email/email.go:16-34`) — package `init()`; queue-driven off `asyncEmailQueue` (capacity 128).
- **Signal handler goroutine** (`cmd/memos/main.go:99`) — waits on SIGINT/SIGTERM to call `s.Shutdown`.
- **HTTP serve goroutine** (`server/server.go:124`) — not a worker, just `httpServer.Serve`.
- Per-connection/per-request goroutines and tickers: SSE heartbeat ticker per client (`server/router/api/v1/sse_handler.go:64`), and fire-and-forget PAT last-used updates (`server/auth/authenticator.go:178-185`).

**Unused scheduling infrastructure:**

- `internal/scheduler` — a full cron scheduler (5/6-field cron parsing, timezone handling, middleware, graceful shutdown; `internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`, documented in `internal/scheduler/README.md` and `doc.go`) is **never used by the server**. Its only non-test importers are its own `example_test.go` and `integration_test.go`; no production code calls `scheduler.New`/`Register`/`Start`.
- `server/runner/memopayload` `Runner` (`NewRunner`/`RunOnce`, `server/runner/memopayload/runner.go:19,27`) is **never instantiated or scheduled**. Only the standalone helper `RebuildMemoPayload` is used, and that is called inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447` — so despite living under `server/runner/`, there is no memopayload background job.
