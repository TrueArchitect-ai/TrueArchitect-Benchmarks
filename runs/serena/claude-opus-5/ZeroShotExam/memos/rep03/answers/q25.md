**Engine + path:** Google CEL (Common Expression Language) via `github.com/google/cel-go` (`go.mod:13`), wrapped by the in-repo memo filter engine at `internal/filter/` — `engine.go` (entry point `filter.DefaultEngine()` / `Compile` / `CompileToStatement`), `schema.go` (CEL env declarations + per-dialect field expressions), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL), `helpers.go` (`AppendConditions`). Documented in `internal/filter/README.md`.

**Mechanism (one sentence):** `ListMemos` validates the filter with `s.validateFilter` (`server/router/api/v1/memo_service.go:211-216` → `server/router/api/v1/shortcut_service.go:336`) and stashes the raw string in `memoFind.Filters`, and each store driver's `ListMemos` then calls `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` (`store/db/sqlite/memo.go:61`, `store/db/postgres/memo.go:58`, `store/db/mysql/memo.go:69`), which runs the three-phase pipeline — cel-go compiles/type-checks the expression against the memo schema env, `parser.go` normalizes the AST into an IR condition tree (folding `now`/`duration`/arithmetic to constants), and `render.go` walks that IR with the target `DialectName` to emit a parameterized SQL fragment plus args that is AND-ed into the query's `WHERE`.

Dialect differences (JSON access `json_extract` vs `->>` vs `JSON_EXTRACT`, tag containment `LIKE` vs `JSON_CONTAINS` vs `@>`, `LIKE` vs `ILIKE`, `?` vs `$n` placeholders with `PlaceholderOffset`, `REGEXP` vs `~`) are all confined to `internal/filter/render.go` and the per-dialect `Expressions` maps in `internal/filter/schema.go`.
