**Workers the server actually starts**

- **s3presign runner** — the only entry in `Server.startBackgroundRunners` (`server/server.go:153-174`). Runs once synchronously at startup (`s3presignRunner.RunOnce(ctx)`, line 163), then a goroutine loops on a fixed `time.NewTicker(12h)` (`server/runner/s3presign/runner.go:27-41`). Shutdown is via a per-runner `context.CancelFunc` + `backgroundRunnerWG` (`server/server.go:176-201`).
- **HTTP (Echo) serve goroutine** — `go s.httpServer.Serve(listener)` (`server/server.go:124`); event-driven by incoming connections, stopped by `httpServer.Shutdown`.
- **Store cache cleanup loops ×3** — started implicitly by `cache.New` (`go c.cleanupLoop()`, `store/cache/cache.go:83`), one each for `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:41-53`). Driven by `time.NewTicker(CleanupInterval)` = 5 minutes (`store/cache/cache.go:201`, config at `store/store.go:41-46`). Created at `store.New` in `cmd/memos/main.go:64`.
- **Webhook async dispatch pool (4 goroutines)** — package `init()` in `internal/webhook/webhook.go:41-53`. Not timed: each goroutine ranges over the buffered channel `asyncPostQueue` (cap 128), fed by `PostAsync` (`internal/webhook/webhook.go:184-190`) from memo events (`server/router/api/v1/memo_service_webhooks.go:43,71`).
- **Email async send pool (2 goroutines)** — package `init()` in `internal/email/email.go:16-35`. Channel-driven off `asyncEmailQueue` (cap 128) via `SendAsync`, wired in `server/notification/email.go:30`.
- **Shutdown signal goroutine** — `cmd/memos/main.go:99`; blocks on the `os.Interrupt`/`SIGTERM` channel, then calls `s.Shutdown`.

Per-request (not process-lifetime) tickers/goroutines, for completeness: the 30s SSE heartbeat ticker per connection (`server/router/api/v1/sse_handler.go:18,64`) and the fire-and-forget PAT last-used update (`server/auth/authenticator.go:180`).

**Unused scheduling infrastructure**

- **`internal/scheduler` is dead code from the server's perspective.** It's a complete cron scheduler — 5/6-field cron parser (`internal/scheduler/parser.go`), job registration/timezones (`scheduler.go`, `job.go`), `Recovery`/`Logging`/`Timeout` middleware (`middleware.go`), plus `README.md` and `doc.go`. Grepping non-test code, it is referenced only from inside its own package; nothing in `server/` or `cmd/` imports it. The one real periodic job (s3presign) uses a hand-rolled `time.Ticker` instead.
- **`server/runner/memopayload.Runner` is never started.** `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:20,27`) have no callers; only the standalone helper `RebuildMemoPayload` is used, inline on the request path (`server/router/api/v1/memo_service.go:108,447`).
