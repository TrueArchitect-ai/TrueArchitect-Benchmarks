`store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) cleans up two kinds of records before issuing the `DELETE FROM memo` on the row itself:

1. **`memo_relation` rows where the memo is the source** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
2. **`memo_relation` rows where the memo is the target/related memo** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})` (`store/memo.go:145`)
3. **`attachment` rows linked to the memo** — listed via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and removed one by one with `s.DeleteAttachment` (`store/memo.go:148-157`), which also deletes the backing blob/local file before the DB row (`store/attachment.go:132-148`)

Then `s.driver.DeleteMemo` runs the plain `DELETE FROM memo WHERE id = ?` (e.g. `store/db/sqlite/memo.go:237`).

Two related points, since they sit just outside the store call:

- **Comment memos** are not handled inside the store. The API layer deletes them first: `DeleteMemo` in `/bench/repo/server/router/api/v1/memo_service.go:567-577` lists `MemoRelationComment` relations pointing at the memo and calls `store.DeleteMemo` recursively for each comment memo (each of which then does its own relation/attachment cleanup).
- **Reactions are not deleted** by the store path — they're only read for the webhook payload (`memo_service.go:545-550`); no reaction cleanup happens in `store.DeleteMemo` or the driver `DeleteMemo`.
