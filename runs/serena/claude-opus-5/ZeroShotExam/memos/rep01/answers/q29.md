**Answer: `web/src/connect.ts` (`authInterceptor`, backed by `web/src/auth-state.ts`); short-lived JWT access token (Bearer header, localStorage) + long-lived refresh token (HttpOnly cookie `memos_refresh`), plus Personal Access Tokens for programmatic clients; `server/auth`**

Details:

**Frontend interceptor** — `web/src/connect.ts:150` defines `authInterceptor`, installed on the single Connect transport (`createConnectTransport`, `web/src/connect.ts:174`) that backs every service client (memo, user, auth, attachment, etc.). It:
- calls `getRequestToken()` and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, `web/src/connect.ts:97`),
- proactively refreshes when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry,
- on a `Code.Unauthenticated` response, refreshes once, replays the request with an `X-Retry: true` header, and calls `redirectOnAuthFailure()` if that fails (`web/src/utils/auth-redirect.ts`).

Refreshes go through a separate interceptor-free transport (`refreshTransport`, `web/src/connect.ts:66`) to avoid recursion, and are deduplicated by `tokenRefreshManager`. Transport `fetch` uses `credentials: "include"` so the refresh cookie is sent.

**Token storage** — `web/src/auth-state.ts` holds the access token in memory + `localStorage` (`memos_access_token` / `memos_token_expires_at`) and syncs freshly refreshed tokens across tabs via a `BroadcastChannel` (`memos_token_sync`). `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes on tab focus with a larger 2-minute buffer.

**Backend validation** — package `server/auth`:
- `server/auth/token.go` — JWT issuing/parsing; access tokens 15 min (audience `user.access-token`), refresh tokens 30 days (audience `user.refresh-token`, cookie `memos_refresh`), PAT prefix `memos_pat_`.
- `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie`.
- `server/auth/authenticator.go` — `Authenticator.AuthenticateByAccessTokenV2` (stateless), `AuthenticateByRefreshToken` (DB-checked), and PAT validation.

It's wired in via `server/router/api/v1/authz.go` (`Authorizer`, shared by the Connect interceptor at `server/router/api/v1/connect_interceptors.go:220` and the gRPC-Gateway middleware in `server/router/api/v1/v1.go:76`), and reused by `server/router/fileserver/fileserver.go` and the SSE handler.
