**Memo lifecycle events → dispatch functions** (all defined in `server/router/api/v1/memo_service_webhooks.go`):

- `memos.memo.deleted`: `APIV1Service.DispatchMemoDeletedWebhook` (`memo_service_webhooks.go:25`; called from `memo_service.go:562` in `DeleteMemo`)
- `memos.memo.comment.created`: `APIV1Service.DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`; called from `memo_service_comments.go:119`)

**Convergence for delivery:**

The first three are thin wrappers over the shared helper `APIV1Service.dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:47`), which resolves the memo creator, loads their webhooks via `Store.GetUserWebhooks`, builds a payload with `convertMemoToWebhookPayload`, and calls `webhook.PostAsync`. The comment-created function does its own lookup (against the *related* memo's owner, not the comment creator) but ends at the same call.

All four converge on `webhook.PostAsync` (`internal/webhook/webhook.go:180`), which enqueues onto the buffered `asyncPostQueue` (cap 128, dropping with a warning when full). Four goroutines started in `init()` drain that queue and perform the actual HTTP delivery in `webhook.Post` (`internal/webhook/webhook.go:118`) — JSON marshal, optional Standard Webhooks HMAC-SHA256 signing, then `safeClient.Do` with an SSRF-guarding dialer.
