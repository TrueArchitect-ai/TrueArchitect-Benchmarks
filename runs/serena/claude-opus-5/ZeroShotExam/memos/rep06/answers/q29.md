**`web/src/connect.ts`; JWT access token (in-memory + localStorage, sent as `Authorization: Bearer`) and an HTTP-only refresh-token cookie (`memos_refresh`), plus PATs accepted on the same header; `server/auth`**

How it fits together:

**Frontend interceptor — `web/src/connect.ts:156`** (`authInterceptor`, wired into the Connect transport at `web/src/connect.ts:184-189`, so every generated service client below it is authenticated).
- It calls `getRequestToken()` (`connect.ts:124`) and sets `Authorization: Bearer <token>` (`connect.ts:97`).
- Proactive refresh: if the token is expired within `REQUEST_TOKEN_EXPIRY_BUFFER_MS`, it refreshes before sending (`connect.ts:140`).
- Reactive refresh: on a `Code.Unauthenticated` response it refreshes once, marks the retry with an `X-Retry` header to prevent loops, and on failure calls `redirectOnAuthFailure()` (`connect.ts:163-177`).
- Refreshes go through a separate transport with **no** interceptors to avoid recursion (`connect.ts:65-72`) and are deduplicated by `tokenRefreshManager` (`connect.ts:30-51`). `web/src/hooks/useTokenRefreshOnFocus.ts` does the same refresh on tab focus.

**Token storage — `web/src/auth-state.ts`**: access token kept in memory and mirrored to `localStorage` (`memos_access_token` / `memos_token_expires_at`), synced across tabs via a `BroadcastChannel`. The refresh token itself is never in JS — it rides as a cookie, which is why the transport uses `credentials: "include"` (`connect.ts:57-62`).

**Backend validation — `server/auth`** (`server/auth/token.go`, `authenticator.go`, `extract.go`). It defines the token kinds: JWT access tokens (15 min, audience `user.access-token`), JWT refresh tokens (30 days, cookie `memos_refresh`), and Personal Access Tokens (prefix `memos_pat_`, DB-backed). `Authenticator.Authenticate` (`server/auth/authenticator.go:213`) is the entry point; access tokens validate statelessly (`AuthenticateByAccessTokenV2`, line 41) while refresh tokens and PATs hit the store.

The wiring on the server side is `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go:207-231`, which reads the `Authorization` header, delegates to the shared `Authorizer`, checks per-procedure access policy (`server/router/api/v1/acl_config.go`), and stashes the result in context via `auth.ApplyToContext`.
