**Both protocols are HTTP-served adapters over the same `APIV1Service` implementation** (there is no standalone gRPC server — no `grpc.NewServer`/`RegisterMemoServiceServer` call exists outside generated code).

1. **REST / HTTP+JSON via grpc-gateway** — `server/router/api/v1/v1.go:108` (`v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)`), with the mux mounted onto Echo at `server/router/api/v1/v1.go:127-129` (`/api/v1/*`, `/file/*`). Generated routing lives in `proto/gen/api/v1/memo_service.pb.gw.go`.

2. **Connect RPC (connectrpc.com/connect)** — `server/router/api/v1/connect_handler.go:40` (`wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` inside `RegisterConnectHandlers`), mounted at `server/router/api/v1/v1.go:141-144` under the `/memos.api.v1.*` path group. The per-method Connect↔gRPC wrapping of the MemoService RPCs is in `server/router/api/v1/connect_services.go`, and the generated handler constructor is in `proto/gen/api/v1/apiv1connect/memo_service.connect.go`.

Note: MemoService methods are also surfaced as MCP tools (`server/router/mcp/catalog.go:12-25`), but that's a tool catalog built on the same service, not a third transport registration of the proto service.
