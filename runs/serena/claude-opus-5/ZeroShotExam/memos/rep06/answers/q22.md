Flow:

1. `CreateMemo` (`server/router/api/v1/memo_service.go:157`) calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)`, logging a warning on failure rather than failing the RPC.
2. `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`) delegates to `dispatchMemoRelatedWebhook` with activity type `"memos.memo.created"`. That function resolves the memo creator, loads `s.Store.GetUserWebhooks(ctx, creatorID)`, and for each hook builds a `webhook.WebhookRequestPayload` (via `convertMemoToWebhookPayload`) carrying the hook's `Url` and `SigningSecret`, then calls `webhook.PostAsync(payload)`.
3. HTTP delivery is done by the `internal/webhook` package (`internal/webhook/webhook.go`). `PostAsync` enqueues onto a buffered channel (`asyncPostQueue`, cap 128, dropped with a warning when full) drained by 4 worker goroutines that call `Post`, which POSTs the JSON body with a shared `http.Client` (30s timeout) whose transport uses `safeDialContext` to reject reserved/private IPs (SSRF/DNS-rebinding guard).
4. Signing: when `SigningSecret` is non-empty, `Post` derives the key via `resolveSigningKey` (base64-decoding a `whsec_`-prefixed Standard Webhooks secret, else raw bytes), computes `HMAC-SHA256(msgID + "." + timestamp + "." + body)`, and sets the `webhook-id`, `webhook-timestamp`, and `webhook-signature: v1,<base64>` headers. Secrets are generated by `GenerateSigningSecret` as `whsec_<base64 of 32 random bytes>`.
