**Mechanism:** Server-Sent Events (SSE) — a plain HTTP `GET /api/v1/sse` streaming endpoint with `Content-Type: text/event-stream`, Bearer-token auth, 30s heartbeat pings, and `X-Accel-Buffering: no`. Not WebSockets, and not part of the Connect/gRPC API surface.

**Hub:** `server/router/api/v1/sse_hub.go` — `SSEHub` (mutex-guarded `map[*SSEClient]struct{}`) with `Subscribe`/`Unsubscribe`/`Broadcast`/`Close`. Each client gets a 32-event buffered channel; events are dropped rather than blocking a slow client. `SSEClient.canReceive` filters private memos to the creator or an admin. Related files:
- `server/router/api/v1/sse_handler.go` — `RegisterSSERoutes` / `handleSSE` (the endpoint itself)
- `server/router/api/v1/sse_event_helpers.go` — `buildMemoReactionSSEEvent`, `resolveSSECreatorID`
- Wired up in `server/router/api/v1/v1.go:57,125` and closed on shutdown in `server/server.go:205`
- Client side: `web/src/hooks/useLiveMemoRefresh.ts`
