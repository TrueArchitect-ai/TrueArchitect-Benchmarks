**Convergence for delivery:**

The first three funnel through the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which only differs by the `activityType` string it stamps on the payload. `DispatchMemoCommentCreatedWebhook` does not use that helper — it resolves webhooks against the *related memo's* creator ID rather than the comment creator — but it builds the same payload inline.

All four then converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload onto the buffered `asyncPostQueue` (cap 128, dropping with a warning if full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`) drain that queue and call `webhook.Post` (`internal/webhook/webhook.go:120`), which does the actual HTTP POST — HMAC-SHA256 Standard Webhooks signing when a signing secret is set, sent via the SSRF-guarded `safeClient`.
