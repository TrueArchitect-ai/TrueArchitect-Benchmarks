**Two caveats worth flagging**

- `memo_share` has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`, `store/migration/sqlite/LATEST.sql:109`), but SQLite opens the DB with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so on SQLite the cascade does not fire and share rows are orphaned. There is no explicit `DeleteMemoShare` call in the delete path.
- `reaction` is never deleted. Reactions key off `content_id` (a memo name string, no FK — `store/migration/*/LATEST.sql:91`), so reactions on a deleted memo are left behind on every driver.
