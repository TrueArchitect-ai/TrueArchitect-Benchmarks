**Runners the server explicitly starts** (`server/server.go:154-176`, `startBackgroundRunners`) — exactly one:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — two triggers: a synchronous `RunOnce(ctx)` at startup, then a goroutine running `Run(s3Context)`, a `time.NewTicker(12 * time.Hour)` loop (`runnerInterval`, runner.go:27-40). Each tick re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days (5-day expiry). Cancelled via its own `context.CancelFunc` stored in `backgroundRunnerCancels`, and awaited through `backgroundRunnerWG` on `Shutdown` (server.go:129-146, 178-206).

**Other long-lived goroutines started implicitly by the process (not via `startBackgroundRunners`):**

- **Store cache cleanup loops ×3** (`store/cache/cache.go:75-84, 199-212`) — `cache.New` spawns `cleanupLoop`, a `time.NewTicker(CleanupInterval)`; `store.New` creates three caches (instanceSetting, user, userSetting) with a hardcoded 5-minute interval (`store/store.go:39-53`). Stopped by `Store.Close()` (`store/store.go:72-79`).
- **Webhook dispatch workers ×4** (`internal/webhook/webhook.go:42-55`) — package `init()`; queue-driven, consuming a 128-buffered `asyncPostQueue` channel. No timer.
- **Email send workers ×2** (`internal/email/email.go:16-35`) — package `init()`; queue-driven off `asyncEmailQueue` (buffer 128).
- **SSE heartbeat ticker** (`server/router/api/v1/sse_handler.go:17, 64`) — per-connection, not a background worker: created inside the request handler, 30s interval, lives as long as the client stream.
- **PAT last-used update** (`server/auth/authenticator.go:178-185`) — a one-shot fire-and-forget goroutine per authenticated PAT request, not a scheduled runner.

**Unused scheduling infrastructure:**

- **`internal/scheduler`** — a full cron scheduler (5/6-field cron parser, timezone handling, middleware, graceful shutdown; `scheduler.go`, `parser.go`, `job.go`, `middleware.go`, plus a README documenting it as "production-ready") is **never wired into the server**. Grepping the repo, the only non-test importers of `github.com/usememos/memos/internal/scheduler` are its own `example_test.go` and `integration_test.go`. Nothing in `server/`, `cmd/`, or `store/` constructs a `Scheduler` or registers a `Job`. The one runner that does exist (s3presign) uses a raw `time.Ticker` instead.
- **`server/runner/memopayload`** — packaged as a "runner" with `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:15-27`), but `NewRunner`/`RunOnce` are never called anywhere. Only the plain helper `memopayload.RebuildMemoPayload` is used, inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447`. So the runner half of that package is dead code.
