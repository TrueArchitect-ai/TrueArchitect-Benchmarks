MemoService is implemented once on `APIV1Service` (embedding `v1pb.UnimplementedMemoServiceServer`, `server/router/api/v1/v1.go:26`) and exposed over two wire protocols:

**REST/JSON over HTTP (grpc-gateway) — `/bench/repo/server/router/api/v1/v1.go`**
- `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` at `server/router/api/v1/v1.go:108` registers the service directly on the grpc-gateway mux (in-process, no gRPC socket hop).
- That mux is mounted on Echo at `/api/v1/*` and `/file/*` (`server/router/api/v1/v1.go:126-129`); the generated gateway routing/transcoding code lives in `proto/gen/api/v1/memo_service.pb.gw.go`.

**Connect RPC (`memos.api.v1.MemoService/*`) — `/bench/repo/server/router/api/v1/connect_handler.go` (+ `connect_services.go`)**
- Registration: `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` at `server/router/api/v1/connect_handler.go:40`, mounted on Echo at `/memos.api.v1.*` in `server/router/api/v1/v1.go:139-144`.
- Wrapping: `ConnectServiceHandler` adapts each gRPC method to Connect request/response types — the MemoService block starts at `server/router/api/v1/connect_services.go:304` (`CreateMemo`, `ListMemos`, `GetMemo`, …), with generated client/handler stubs in `proto/gen/api/v1/apiv1connect/memo_service.connect.go`.

Note: there's a third, non-wire surface — the MCP router (`server/router/mcp/catalog.go:12-25`) exposes `MemoService_*` methods as MCP tools — but that's built on the same service, not a separate protocol registration of the gRPC service.
