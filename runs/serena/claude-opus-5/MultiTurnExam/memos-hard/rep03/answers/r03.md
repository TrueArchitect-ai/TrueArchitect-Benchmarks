**Premise correction: no nightly database-cleanup job exists, and the cron scheduler is never used by the server — so there is no scheduled time to report.**

Two separate corrections:

**1. The `"0 2 * * *"` daily-cleanup you may be thinking of is documentation, not a registered job.** `internal/scheduler/doc.go:14-21` shows a package-usage example:

```go
s.Register(&scheduler.Job{
    Name:     "daily-cleanup",
    Schedule: "0 2 * * *", // 2 AM daily
    ...
})
```

That's illustrative prose in a doc comment. The only other occurrences of `scheduler.Register` are in `internal/scheduler/example_test.go:17,40,67`.

**2. `internal/scheduler` has no production caller at all.** Grepping for `scheduler.` outside its own package returns only `doc.go` and `example_test.go` — nothing in `server/`, `store/`, or `cmd/` imports it. The package (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`) is fully implemented but currently dead code, so no cron expression of any kind is live.

**What actually runs on a schedule:**

- **S3 presign refresh** — the only background runner, started at `server/server.go:162-171`: one immediate `RunOnce` then a `time.Ticker` every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). It's a fixed interval from process start, not a wall-clock time, and it refreshes presigned URLs rather than cleaning up data.
- **In-memory cache eviction** — `cleanupLoop` every 5 minutes per cache instance (`store/cache/cache.go:83`, interval from `store/store.go:42`). This evicts expired cache entries in RAM; it touches no database rows.

Database cleanup in this codebase is event-driven, not scheduled: cascading deletes happen inline when a user or memo is deleted (`store/db/*/user_delete.go`, and `store/attachment.go:171` for attachment/S3 cleanup). There is also a `memopayload.Runner.RunOnce` batch job (`server/runner/memopayload/runner.go:27`) that has no caller — another implemented-but-unwired background task.
