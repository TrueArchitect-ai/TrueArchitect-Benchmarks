**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

Details:

- **Abstraction**: `internal/idp/idp.go` is a minimal package defining just the provider-neutral result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) — `internal/idp/idp.go:3-8`. Note this is a shared data contract, not a Go interface; there's no `IdentityProvider` interface to implement, so dispatch is done by explicit type switch rather than polymorphism.
- **Implementation**: `internal/idp/oauth2` is the only concrete protocol package. `oauth2.IdentityProvider` wraps a `storepb.OAuth2Config` (`internal/idp/oauth2/oauth2.go:20-22`) and provides `NewIdentityProvider` (validates required fields: clientId, clientSecret, tokenUrl, userInfoUrl, fieldMapping.identifier — `oauth2.go:27`), `ExchangeToken` with PKCE `code_verifier` support (`oauth2.go:47`), and `UserInfo` returning an `*idp.IdentityProviderUserInfo` via configured field mapping (`oauth2.go:83`).
- **Wiring**: `resolveSSOIdentity` branches on `storepb.IdentityProvider_OAUTH2` and constructs the OAuth2 provider — `server/router/api/v1/auth_service_sso.go:120-133`.
- **Single-implementation confirmation**: the store proto's `IdentityProviderConfig` oneof has exactly one variant, `oauth2_config` (`proto/gen/store/idp.pb.go:158-159, 214-218`), so OAuth2/OIDC-style flows are the only SSO protocol that ships.
