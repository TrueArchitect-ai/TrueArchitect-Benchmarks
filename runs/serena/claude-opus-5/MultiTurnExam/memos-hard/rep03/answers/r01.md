**Premise correction: there is no Redis in this repository.** A case-insensitive search for "redis" across the entire tree (Go files, `go.mod`, and every non-`.git`/`node_modules` file) returns zero hits — no client dependency, no connection config, no flag. The cache layer is a purely in-process, in-memory implementation.

**Actual mechanism.**

- **Implementation**: `store/cache/cache.go` — a thread-safe in-memory cache built on `sync.Map` plus an atomic item counter (`store/cache/cache.go:66-72`), constructed by `cache.New(config)` (`store/cache/cache.go:74`). It satisfies the `cache.Interface` declared at `store/cache/cache.go:10-32`. Nothing crosses a network boundary, so the cache is per-process and not shared between instances.
- **Where it's "configured"**: not by any connection string or flag, but by a `cache.Config` literal hardcoded in `store.New` (`store/store.go:37-43`). Three separate cache instances are created from that same config — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`, fields declared at `store/store.go:26-29`).

**TTL for user entries: 10 minutes.**

- `store.New` sets `DefaultTTL: 10 * time.Minute` (`store/store.go:39`), alongside `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000`. (`cache.DefaultConfig()` at `store/cache/cache.go:57-64` declares the same values, but the store doesn't call it — it duplicates the literal.)
- Every user write goes through `s.userCache.Set(...)` (`store/user.go:98,122,132,143,167`), and `Cache.Set` forwards to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). No caller uses `SetWithTTL` with a custom duration for users, so 10 minutes applies uniformly.

Two behavioral notes: the user cache is keyed by ID via `userCacheKey` (`store/user.go:88`), and `Store.GetUser` only consults it when the lookup is by ID (`store/user.go:149-156`) — username lookups always hit the database. Cache goroutines are shut down through `Store.Close` → `s.userCache.Close()` (`store/store.go:75`).
