**Premise correction: no per-user API rate-limiting middleware exists in this repository.** There is nothing to cite a registration site or request limits for.

Evidence:

- A case-insensitive grep for `ratelimit`, `rate_limit`, "rate limit", and `throttl` across all Go files returns exactly one hit, and it's a comment in unrelated documentation prose: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse" — a suggestion, not an implementation).
- `go.mod` contains no limiter dependency: no `golang.org/x/time/rate`, no `github.com/ulule/limiter`, no `didip/tollbooth`, and Echo's `middleware.RateLimiter` is never referenced.
- The complete middleware/interceptor registration is small and contains no limiter:
  - Echo middleware — `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/server.go:51-52`), plus static-file and SPA-fallback middleware in the frontend router (`server/router/frontend/frontend.go:54,59`).
  - Connect interceptors — `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` (`server/router/api/v1/v1.go:133-137`, all defined in `server/router/api/v1/connect_interceptors.go`). `AuthInterceptor` enforces authentication and anonymous-access policy, not request rates.

**What does exist, and is easy to mistake for rate limiting** — all are concurrency caps or size caps, none per-user and none time-windowed:

- `maxConcurrentThumbnails = 3` via `semaphore.NewWeighted` (`server/router/fileserver/fileserver.go:46,116`) — process-wide cap on simultaneous thumbnail generation.
- `thumbnailSemaphore` (3) and `imageProcessingSemaphore` (2) on the API service (`server/router/api/v1/v1.go:59-60`) — likewise process-wide.
- Request body size caps: `connect.WithReadMaxBytes(maxAPIRequestBytes)` and `http.MaxBytesHandler(...)` (`server/router/api/v1/v1.go:140,145`).
- A bounded outbound webhook queue of 128 with 4 workers, which drops overflow (`internal/webhook/webhook.go:39,42-55`) — backpressure on outgoing calls, not inbound requests.

So a client can issue unlimited requests per unit time; the only inbound protections are authentication, payload size, and internal concurrency limits.
