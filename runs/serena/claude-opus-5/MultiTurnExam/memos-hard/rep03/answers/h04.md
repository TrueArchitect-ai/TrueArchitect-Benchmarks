**No** — outside `NewDBDriver`, nothing in the codebase constructs the MySQL driver.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:14-32`; its MySQL branch is the sole call to `mysql.NewDB` (`store/db/db.go:22`).
- A repo-wide grep for the import path `github.com/usememos/memos/store/db/mysql` returns exactly one hit: `store/db/db.go:8`. Since `mysql.NewDB` (defined at `store/db/mysql/mysql.go:20`) and the unexported `DB` struct can only be reached by importing that package, no other package — production or test — can construct it.
- The only other `DB` literals are inside the `mysql` package itself, so they aren't external construction: `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`, the body of `NewDB`) and `store/db/mysql/auth_config_test.go:12` (`db := &DB{}`, a zero-value struct in a package-internal unit test that doesn't open a connection).

Contrast worth noting: SQLite *is* constructed outside the factory — `sqlite.NewDB` is called directly in `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416` for test fixtures. Postgres, like MySQL, is only reached via `store/db/db.go:9,24`.
