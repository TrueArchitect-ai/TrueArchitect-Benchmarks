**Explicit Go code — two `DELETE FROM reaction` statements inside each driver's `DeleteUser` transaction. There is no database-level cascade for reactions.**

What I checked:

**1. The Go path.** `store.DeleteUser` (`store/user.go:171`) delegates to `s.driver.DeleteUser`, defined per driver:

- `store/db/sqlite/user_delete.go:29`
- `store/db/mysql/user_delete.go:29`
- `store/db/postgres/user_delete.go:29`

All three open a transaction and call `deleteUserTargetsTx` (sqlite: `store/db/sqlite/user_delete.go:92`), which removes reactions in **two** separate steps:

- `deleteReactionsByContentIDsTx` — `DELETE FROM reaction WHERE content_id IN (...)` (sqlite `:383`, mysql `:420`, postgres `:383`). This clears reactions *other people* left on the deleted user's memos. The content IDs come from `memoContentIDsFromRefs`, which builds `"memos/" + memo.UID` (`store/db/sqlite/user_delete.go:512`) — reactions key off a string content ID, not a memo FK.
- `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?` (sqlite `:400`, mysql `:438`, postgres `:401`). This clears the reactions *the user themselves* left on anyone's memos.

Both run before `deleteMemosTx` and `deleteUserRowTx` (`store/db/sqlite/user_delete.go:96-125`), all in one transaction committed at line 51, so it's atomic. The memo set includes descendant comment memos, gathered by a recursive CTE over `memo_relation` (`store/db/sqlite/user_delete.go:133`).

**2. The schema.** The `reaction` table has no foreign keys at all — in any dialect:

- `store/migration/sqlite/LATEST.sql:92-99`
- `store/migration/postgres/LATEST.sql:91-98`
- `store/migration/mysql/LATEST.sql:91-98`

Its columns are `creator_id`, `content_id`, `reaction_type` with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint. Grepping the schemas for `FOREIGN KEY` / `ON DELETE CASCADE` finds exactly one match per dialect, and it belongs to `memo_share`, not `reaction` (`store/migration/sqlite/LATEST.sql:109`, `postgres:108`, `mysql:108`). Even that cascade is on `memo_id`, and it's why `memo_share` still gets an explicit delete too (`deleteMemoSharesTx`, sqlite `:405`).

So the DB could not clean reactions up on its own — and additionally `content_id` is a text `"memos/{uid}"` value, which no FK could reference anyway.
