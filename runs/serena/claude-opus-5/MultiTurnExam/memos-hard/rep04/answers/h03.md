Details:

- **Abstraction** — `internal/idp/idp.go` is a minimal package defining just the shared cross-provider type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`). It's the normalized shape every provider must produce; there is no Go `interface` here, so the "abstraction" is this common result type plus the enum discriminator.
- **Implementation** — `internal/idp/oauth2/oauth2.go` is the only concrete provider. Its `IdentityProvider` wraps a `storepb.OAuth2Config`; `NewIdentityProvider` (line 27) validates required fields (`clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, `fieldMapping.identifier`), `ExchangeToken` (line 47) does the authorization-code exchange via `golang.org/x/oauth2` with optional PKCE `code_verifier`, and `UserInfo` (line 83) fetches the userinfo endpoint and maps its JSON into `idp.IdentityProviderUserInfo` using the configured field mapping.
- **Only one protocol ships** — the store enum has exactly one non-unspecified value, `IdentityProvider_OAUTH2 = 1` (`proto/store/idp.proto`, generated as `proto/gen/store/idp.pb.go:28`). No OIDC/SAML/LDAP implementation exists in the tree.
- **Dispatch point** — `resolveSSOIdentity` in `server/router/api/v1/auth_service_sso.go:104` loads the stored provider and branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` (line 120) to construct the `oauth2.IdentityProvider`, exchange the token, and fetch user info; the result feeds `resolveSSOUser` (line 19) for account lookup/creation, with an optional `IdentifierFilter` regex gate at lines 136-145.
