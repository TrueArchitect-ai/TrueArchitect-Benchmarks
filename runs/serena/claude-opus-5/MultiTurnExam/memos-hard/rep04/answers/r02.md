**Premise correction: there is no rate-limiting middleware in this repository — per-user or otherwise — so there is no registration site and no request limits to report.**

What I checked:

- Repo-wide greps over Go sources for `rate.?limit`, `ratelimit`, `throttl`, `Limiter`, `golang.org/x/time/rate`, `429`, and `TooManyRequests` return no matches outside the web frontend. The only hit anywhere is a comment in `internal/email/doc.go:86` listing "Rate limit email sending to prevent abuse" as an unimplemented future consideration.
- `golang.org/x/time/rate` and echo's `middleware.RateLimiter` are not in `go.mod` / not imported.
- The complete Echo middleware stack is two entries, both global and neither rate-related: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/server.go:51-52`).
- The complete Connect interceptor chain is `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:22, 98, 165, 205`), wired in `RegisterGateway` (`server/router/api/v1/v1.go:64`). No throttling interceptor exists.

**What does exist, and may be what you're thinking of** — per-request limits that are *not* rate limits:

- **Concurrency caps** via weighted semaphores: 3 concurrent thumbnail generations and 2 concurrent image-processing operations (`server/router/api/v1/v1.go:57-58`), and a separate thumbnail semaphore in the file server (`server/router/fileserver/fileserver.go:116`). These bound parallelism, not request frequency — excess requests wait rather than being rejected.
- **Content size limits**: a per-instance memo content length limit enforced in `CreateMemo`/`UpdateMemo` (`server/router/api/v1/memo_service.go:100-106`, `:438-444`).
- **Bounded webhook dispatch queue**: 128 slots with drop-on-full (`internal/webhook/webhook.go:39`, `:189-195`) — backpressure on outbound deliveries, not inbound requests.
- **Authorization** (not throttling) per RPC: `AuthInterceptor` plus the ACL config at `server/router/api/v1/acl_config.go`.

If you want per-user API rate limiting, it would need to be added — the natural insertion points are a new Connect interceptor alongside those in `connect_interceptors.go`, or an Echo middleware at `server/server.go:51`.
