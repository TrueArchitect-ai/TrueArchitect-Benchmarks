**Premise correction: no nightly database-cleanup job exists, and the cron scheduler is never used by the server at all — so there is no scheduled time to report.**

Evidence:

- **The `2 AM daily` cleanup you may be recalling is documentation, not code.** `internal/scheduler/doc.go:14-21` shows an illustrative usage example: a job named `"daily-cleanup"` with `Schedule: "0 2 * * *", // 2 AM daily`. It's inside a package comment block — every line is prefixed with `//`. Nothing registers it.
- **The scheduler package has no production importer.** The only files importing `github.com/usememos/memos/internal/scheduler` are `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. Every call to `Scheduler.Register` (`internal/scheduler/scheduler.go:68`) and `Scheduler.Start` lives in those test files. The package — a self-contained cron implementation with `Job` (`internal/scheduler/job.go`), a cron expression parser (`internal/scheduler/parser.go`), and `Recovery`/`Logging` middleware (`internal/scheduler/middleware.go`) — is currently unused infrastructure.
- **No database-cleanup logic exists to schedule.** Grepping for `cleanup` outside the web frontend turns up only: the in-memory cache's `CleanupInterval` (`store/store.go:42`, a 5-minute sweep of expired cache entries — not a database job), attachment cleanup performed inline during user/memo deletion (`server/router/api/v1/user_service.go:421-450`, `server/router/api/v1/memo_service.go:579`), and the doc-comment example above.

**What actually runs on a schedule:** exactly one background job, and it doesn't use the scheduler package. `startBackgroundRunners` (`server/server.go:153`) launches the S3 presign runner, which uses a plain `time.Ticker` on a fixed 12-hour interval (`server/runner/s3presign/runner.go:27,29-42`) plus one immediate pass at boot (`server/server.go:163`). It's interval-based, not wall-clock-scheduled, so it has no fixed time of day — the first run happens at server start and every 12 hours thereafter.
