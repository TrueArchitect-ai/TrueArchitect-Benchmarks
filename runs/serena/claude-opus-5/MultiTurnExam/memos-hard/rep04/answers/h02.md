**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP POST is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection: dial-time reserved/private-IP blocking via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

How it fits together:

- **Trigger** — memo create/update/delete/comment events call `s.dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook`, which look up the user's webhooks and hand each payload to `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43,71`).
- **Queueing** — `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel `asyncPostQueue`, dropping with a warning when full. Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it, so **`Post` is where the delivery actually executes** — marshalling the body, adding Standard Webhooks HMAC headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`) when a signing secret is set, POSTing, and checking the status/response code.
- **SSRF protection (primary)** — all dispatches use the package-level `safeClient` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). At dial time it resolves the host and refuses the connection if *any* resolved address is reserved (`internal/webhook/webhook.go:59-77`). Because the check happens at dial rather than at config time, it also defeats DNS rebinding.
- **Blocked ranges** — `reservedCIDRs` in `internal/webhook/validate.go:14-23`: IPv4 loopback, all three RFC-1918 blocks, 169.254.0.0/16 (cloud IMDS), plus `::1/128`, `fc00::/7`, `fe80::/10`. Parsed once into `reservedNetworks` in `init()` (`validate.go:28-36`).
- **SSRF protection (secondary, at configuration time)** — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and hostnames resolving to reserved IPs when a user registers or updates a webhook: `server/router/api/v1/user_service_webhooks.go:74,161,182`.
- **Escape hatch** — the `AllowPrivateIPs` package var (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, for self-hosted setups targeting LAN services. Note: in the current tree nothing outside tests assigns it, so it is effectively always `false` at runtime — the `--allow-private-webhooks` flag mentioned in `CHANGELOG.md:121` has no remaining wiring I could find.

Other outbound-HTTP paths (`internal/httpgetter/html_meta.go` for link previews, `server/router/fileserver/fileserver.go`) are separate and don't go through this client.
