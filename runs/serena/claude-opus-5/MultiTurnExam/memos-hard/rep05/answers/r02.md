**Premise correction: there is no per-user API rate-limiting middleware in this repository, so there is no registration site and no request limits to report.**

What I checked:

- A case-insensitive grep for `rate limit` / `ratelimit` / `throttle` and for the usual dependency `golang.org/x/time/rate` across all Go sources and `go.mod` returns zero hits.
- The full set of registered Echo middleware is small and contains nothing of the kind: `middleware.Recover()` and `newCORSMiddleware(profile)` at `server/server.go:51-52`, static-file serving and an SPA fallback at `server/router/frontend/frontend.go:54,59`. The API v1 surface adds only auth middleware (`server/router/api/v1/v1.go:95` and the authorizer wired in `RegisterGateway`), plus Connect interceptors in `server/router/api/v1/connect_interceptors.go` — none of which count or bucket requests.
- No handler returns HTTP 429; `StatusTooManyRequests` appears nowhere.

**What does exist, and is easy to mistake for rate limiting:** concurrency caps, not request-rate limits. These are global semaphores, not per-user, and they make callers *wait* rather than rejecting them:

- `imageProcessingSemaphore` — `semaphore.NewWeighted(2)` (`server/router/api/v1/v1.go:60`). This is the one that can reject: when it can't be acquired, `server/router/api/v1/attachment_service.go:160` returns `codes.ResourceExhausted` with "too many image processing requests".
- `thumbnailSemaphore` — `semaphore.NewWeighted(3)` (`server/router/api/v1/v1.go:59`), and a separate one in the file server bounded by `maxConcurrentThumbnails` (`server/router/fileserver/fileserver.go:116`).

Two other bounded resources, also not rate limits: the webhook dispatch queue caps in-flight deliveries at 128 and drops overflow (`internal/webhook/webhook.go:39`), and per-request page sizes are clamped by `MaxPageSize` in the memo list path (`server/router/api/v1/memo_service.go`).

If per-user rate limiting is a requirement, it would need to be added — most naturally as an Echo middleware alongside the CORS registration at `server/server.go:52`, or as a Connect interceptor, since both sit upstream of every API surface.
