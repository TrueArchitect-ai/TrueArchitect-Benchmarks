**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive grep for `redis` across all Go sources, `go.mod`, YAML, and Markdown returns zero hits. The cache layer is not external and requires no connection configuration — there is nothing to point at a Redis host.

**Actual mechanism: a process-local in-memory cache with a 10-minute default TTL for user entries.**

- **Implementation** — `store/cache/cache.go`. `Cache` is a `sync.Map` guarded by an atomic item counter, with per-entry expiration timestamps and a background cleanup goroutine (`store/cache/cache.go:66-72`). It satisfies the `Interface` declared at `store/cache/cache.go:11-32`.

- **Configuration** — not via any config file, flag, or DSN. It's a hardcoded literal in `store.New` at `store/store.go:40-45`: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, `OnEviction: nil`. The identical values also appear in `cache.DefaultConfig()` (`store/cache/cache.go:57-63`), though `store.New` builds its own literal rather than calling it.

- **User TTL specifically** — the same 10 minutes. `Store` holds three separate `*cache.Cache` instances built from that one config — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:27-29`, constructed at `:51-53`) — so users get no distinct TTL. Every user write uses the plain `Set` (`store/user.go:98, 122, 132, 143, 167`), which forwards to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`), stamping `expiration: time.Now().Add(ttl)` at `:112`. Nothing in the repo calls `SetWithTTL` directly for users.

Two consequences worth noting: entries can also be evicted early when the 1000-item cap is exceeded (`cleanupOldest`, `store/cache/cache.go:116-118`), and because the cache lives in the process, a multi-replica deployment gets independent caches with no invalidation between them. Explicit invalidation is manual — e.g. `s.userCache.Delete` on user deletion (`store/user_delete.go:40`). Also note `Store.GetUser` only consults the cache when looking up by ID (`store/user.go:149-156`); username lookups always hit the database.
