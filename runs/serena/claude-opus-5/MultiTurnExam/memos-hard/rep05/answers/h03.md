**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- **Abstraction — `internal/idp/idp.go`.** The shared package is deliberately thin: it defines only the `IdentityProviderUserInfo` struct (`internal/idp/idp.go:3-8`) with `Identifier`, `DisplayName`, `Email`, and `AvatarURL`. This is the normalized shape every provider must produce, and it's what decouples the SSO login flow from any particular protocol. Note there is no Go `interface` here — the abstraction is the common return type plus the enum in the schema, not a polymorphic interface.

- **Implementation — `internal/idp/oauth2/oauth2.go`.** The only concrete protocol that ships. `oauth2.IdentityProvider` (`:20`) wraps a `storepb.OAuth2Config`; `NewIdentityProvider` (`:27`) validates that `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier` are all non-empty. `ExchangeToken` (`:47`) swaps the authorization code for an access token, supporting PKCE via an optional `codeVerifier`, and `UserInfo` (`:83`) calls the userinfo endpoint and maps the raw claims into `idp.IdentityProviderUserInfo` using the configured field mapping.

Corroborating that OAuth2 is the sole implementation: the stored provider type enum has exactly one real value, `IdentityProvider_OAUTH2 = 1` alongside `TYPE_UNSPECIFIED` (`proto/gen/store/idp.pb.go:27-28`), and the SSO sign-in path constructs providers through a single call site, `oauth2.NewIdentityProvider(identityProvider.Config.GetOauth2Config())` at `server/router/api/v1/auth_service_sso.go:121`. No SAML, LDAP, or standalone OIDC package exists in the tree — OIDC providers are configured as generic OAuth2 endpoints.
