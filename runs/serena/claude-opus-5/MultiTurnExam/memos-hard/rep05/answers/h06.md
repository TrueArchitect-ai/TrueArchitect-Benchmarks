The last three all funnel through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `:67` — so editing a memo, swapping its attachments, or changing its relations are each enough to trigger delivery.

**Convergence.** Every dispatcher in `server/router/api/v1/memo_service_webhooks.go` loads the memo owner's webhooks via `s.Store.GetUserWebhooks`, fills in `payload.URL = hook.Url` — the user-configured endpoint — and calls `webhook.PostAsync` (`:43` for comments, `:71` for the create/update/delete family). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a 128-slot buffered channel; the four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it, and each one calls **`webhook.Post`** (`internal/webhook/webhook.go:120`), which is where the request is signed and actually issued via `safeClient.Do` at `:152`.

Worth distinguishing: `GetLinkMetadata` / `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go:14,19`) also make outbound HTTP via `httpgetter.GetHTMLMeta`, but that fetches a URL passed in the request rather than one *configured* by a user, and it does not pass through `webhook.Post`.
