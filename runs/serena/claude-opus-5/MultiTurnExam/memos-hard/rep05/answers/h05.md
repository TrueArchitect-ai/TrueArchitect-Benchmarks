**Explicit Go code — a deliberate application-level delete inside the delete-user transaction, not a database cascade.**

Evidence locations:

**1. The explicit deletes.** Each driver's `DeleteUser` runs `deleteUserTargetsTx`, which issues two separate reaction deletes:
- `deleteReactionsByContentIDsTx` — removes reactions *on* the user's memos (and their comment subtree), keyed by `content_id` in `memos/{uid}` form: `store/db/sqlite/user_delete.go:380-388`, called at `:96`.
- `deleteReactionsByCreatorTx` — removes reactions the user *left* on anyone's content: `DELETE FROM reaction WHERE creator_id = ?` at `store/db/sqlite/user_delete.go:400-403`, called at `:102`.

Both run inside the transaction opened at `store/db/sqlite/user_delete.go:30` and committed at `:51`, so reaction cleanup is atomic with the user row delete (`deleteUserRowTx`, `:461`).

**2. All three drivers do this identically** — the logic is duplicated per driver rather than shared: `store/db/postgres/user_delete.go:96,102` (definitions at `:380`, `:400`) and `store/db/mysql/user_delete.go:96,102` (definitions at `:417`, `:437`).

**3. Ruling out a database-level rule.** The `reaction` table has no foreign keys at all — no `REFERENCES user(id)`, no `ON DELETE CASCADE`. See the current schema in `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, and `store/migration/mysql/LATEST.sql:91-98`; the table carries only an id, `created_ts`, `creator_id`, `content_id`, `reaction_type`, and a uniqueness constraint. Grepping `FOREIGN KEY|ON DELETE|REFERENCES` across `store/migration/` shows cascades exist for other tables (e.g. `memo_share` → `memo` at `store/migration/sqlite/LATEST.sql:109`, and older 0.5-era user cascades), but none on `reaction`. Grepping `CREATE TRIGGER` finds only modification-time triggers (`store/migration/sqlite/0.6/00__recreate_triggers.sql`), none touching reactions.

A structural reason the Go code is necessary: `reaction.content_id` is a *string* resource name (`"memos/" + uid`, built at `store/db/sqlite/user_delete.go:512-518`), not an integer FK — so a cascade from `memo` couldn't have been expressed as a constraint even if the schema wanted one.
