**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard via `safeDialContext` / `isReservedIP` on the shared `safeClient` transport — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path.** API handlers build the payload and call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`, for memo created/updated/deleted and comment-created events). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a buffered channel of 128, dropping with a warning when full. The actual HTTP work happens in `Post` (`internal/webhook/webhook.go:120`), run by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`). `Post` marshals the JSON body, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and issues the request via `safeClient.Do` at `internal/webhook/webhook.go:152`.

**Protection.** Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against a prebuilt list of reserved CIDRs — IPv4 loopback, RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), and the IPv6 loopback/ULA/link-local equivalents (`internal/webhook/validate.go:14-36`):

1. *At dial time* — the real enforcement. `safeClient` is constructed with `Transport.DialContext: safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59`) re-resolves the host and refuses the connection if any resolved address is reserved. Because this happens per-connection rather than at configuration time, it also defeats DNS rebinding, as the comment at `internal/webhook/webhook.go:30-31` notes.
2. *At configuration time* — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and private-resolving hostnames when a user saves a webhook, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. This is a UX/early-failure check; it can be raced, which is why the dial-time check exists.

**Escape hatch.** `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosters targeting LAN services. One thing worth flagging: in this tree the variable is only ever written by tests (`internal/webhook/webhook_test.go:91`, `:142`) — I found no production assignment, though `CHANGELOG.md:121` references an `--allow-private-webhooks` flag. So SSRF protection is currently always on at runtime, and the flag appears to have been dropped or not yet re-wired.
