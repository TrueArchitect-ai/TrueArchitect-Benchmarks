**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `markdown.service.ExtractAll` — `internal/markdown/markdown.go:356`; Triggers: `CreateMemo`, `UpdateMemo` (content path only), and transitively `CreateMemoComment`; Extracted: tags + the `MemoPayload.Property` struct (title, has_link, has_code, has_task_list, has_incomplete_tasks)**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) initializes `memo.Payload` if nil, runs a single `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`. The real work is `ExtractAll` (`internal/markdown/markdown.go:356-422`), which parses the content once with goldmark and does one AST walk — the comment at `:79` notes the single-pass design is deliberate over calling `ExtractTags`/`ExtractProperties` separately.

**Triggers (recomputation happens only on content change):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, guarded by `if path == "content"` in the update-mask loop (`:436`). The result is written to `update.Payload` at `:451`. Updating visibility, pinned state, etc. does not recompute.
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:55` calls `s.CreateMemo` internally, so comments get payloads through the create path.
- `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:52` rebuilds payloads for all memos in batches of 100, but nothing constructs that `Runner`, so it's currently unreachable.

**What's extracted** (per the walk at `internal/markdown/markdown.go:371-411`):
- **Tags** — `#tag` nodes, deduplicated case-preservingly (`:376-378`, `:418`); tags inside links/images are excluded via `asMemoTagNode` → `isTagNodeInLinkOrImage` (`:122-140`).
- **Mentions** — collected into `ExtractedData.Mentions` lowercased (`:379-381`), but note `RebuildMemoPayload` does *not* persist these; they're used elsewhere for notifications.
- **Property** (`storepb.MemoPayload_Property`, fields at `proto/gen/store/memo.pb.go:85-95`):
  - `Title` — text of a leading H1 heading, only when it's the document's first block child (`:384-389`)
  - `HasLink` — any link node (`:393-394`)
  - `HasCode` — code block, fenced code block, or inline code span (`:396-397`)
  - `HasTaskList` / `HasIncompleteTasks` — task checkboxes, with the latter set when any box is unchecked (`:399-405`)

**Related but distinct:** the memo `Snippet` shown in list views is *not* stored — it's generated per-response by `getMemoContentSnippet` during proto conversion (`server/router/api/v1/memo_service_converter.go:76`), backed by `markdown.service.GenerateSnippet` (`internal/markdown/markdown.go:264`).
