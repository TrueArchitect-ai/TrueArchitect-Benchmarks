Notes on the shapes these take — they are not all the same kind of check:

- **Per-object gates.** `checkMemoReadAccess` (`server/router/api/v1/memo_service.go:39`) is the canonical one: archived memos are creator-only, non-public memos require authentication, and `PRIVATE` requires being the creator. Only three call sites use it, which is why the other RPCs re-implement equivalent logic inline (reactions, attachments, comments) — those inline copies additionally honor `isSuperUser`, which `checkMemoReadAccess` does not.
- **Query scoping** rather than rejection. `ListMemos` never denies; it narrows the query — anonymous callers get `VisibilityList = [PUBLIC]`, authenticated callers get a CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` (`server/router/api/v1/memo_service.go:218-227`). RSS, the sitemap, and user stats do the same thing with fixed visibility lists.
- **A separate HTTP surface.** `checkAttachmentPermission` (`server/router/fileserver/fileserver.go:650`) enforces visibility for raw file bytes outside gRPC entirely, and is the only site with a share-token bypass (`:685-691`) plus an anonymous-instance condition (`:677`).
- **Push, not pull.** `SSEClient.canReceive` (`server/router/api/v1/sse_hub.go:133`) filters broadcast events so private-memo events reach only the creator or an admin — an enforcement point with no request to reject.
