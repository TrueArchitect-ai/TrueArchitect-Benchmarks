The last three share `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66-69`), which calls `DispatchMemoUpdatedWebhook`.

**Convergence.** All four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go` — three delegate to `dispatchMemoRelatedWebhook` (`:48`) and the comment one has its own loop (`:30`). Each loads the target user's webhooks from `GetUserWebhooks`, sets `payload.URL = hook.Url` (the user-configured URL), and calls `webhook.PostAsync` (`memo_service_webhooks.go:43,71`). `PostAsync` only enqueues onto a 128-slot channel (`internal/webhook/webhook.go:184`); the four worker goroutines started in `init()` (`webhook.go:42-55`) each call **`webhook.Post`**, which is the single function that builds the request, signs it, and issues `safeClient.Do` (`webhook.go:152`). So delivery is asynchronous — it happens after the RPC has already returned.

Worth noting a distinct second outbound path with a different convergence point: `GetLinkMetadata` and `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go:14,19`) fetch a caller-supplied URL through `getLinkMetadata` → `fetchHTMLMeta` → `httpgetter.GetHTMLMeta` (`server/router/api/v1/memo_service.go:28`). That's a per-request URL rather than a stored user-configured one, and it does not pass through `webhook.Post`.
