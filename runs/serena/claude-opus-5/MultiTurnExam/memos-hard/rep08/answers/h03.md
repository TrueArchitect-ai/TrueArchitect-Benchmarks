**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation).**

- **Abstraction**: `internal/idp/idp.go:1-8` defines package `idp`, whose sole contribution is the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`). Note this is a shared data type rather than a Go interface — there's no `Provider` interface, so the abstraction is the normalized user-info shape that any provider must produce.
- **Implementation**: `internal/idp/oauth2/oauth2.go` — "Package oauth2 implements the OAuth2 identity provider integration." Its `IdentityProvider` wraps a `storepb.OAuth2Config`, validates required fields in `NewIdentityProvider` (`oauth2.go:27`), exchanges the authorization code with optional PKCE `code_verifier` support in `ExchangeToken` (`oauth2.go:47`), and maps the provider's response onto `idp.IdentityProviderUserInfo` via the configured field mapping in `UserInfo` (`oauth2.go:83`).
- **Only one concrete protocol ships**: `oauth2.NewIdentityProvider` is the single construction site, in the SSO sign-in path at `server/router/api/v1/auth_service_sso.go:121`, and it's reached through `identityProvider.Config.GetOauth2Config()` — no SAML, LDAP, or separate OIDC package exists in the tree.
