**What actually runs on a schedule.** Background work is started by `Server.startBackgroundRunners` (`server/server.go:153-174`), which registers exactly one recurring task, and it does not use cron syntax:

- The S3 presign runner — `RunOnce` immediately at startup (`server/server.go:163`), then a `time.Ticker` loop every 12 hours (`server/runner/s3presign/runner.go:27,29-41`). It refreshes expiring presigned attachment URLs; it deletes nothing.

The only other periodic timer is the in-memory cache sweeper, one goroutine per cache on a 5-minute `CleanupInterval` (`store/cache/cache.go:200-215`, configured at `store/store.go:42`) — that evicts expired cache entries in RAM, not database rows.

Database deletion in this codebase is entirely event-driven rather than scheduled: e.g. `DeleteUser` cascades in a transaction (`store/db/sqlite/user_delete.go`) and memo deletion cleans up relations and attachments inline (`server/router/api/v1/memo_service.go:579`). There is no retention sweep, no soft-delete purge, and no orphan collector.
