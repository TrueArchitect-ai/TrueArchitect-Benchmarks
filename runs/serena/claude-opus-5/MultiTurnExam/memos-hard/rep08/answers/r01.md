**Premise correction: there is no Redis in this repository.** Grepping for `redis` (case-insensitive) across all Go sources, `go.mod`, `go.sum`, YAML/JSON config, and Markdown returns zero hits. The cache layer is a hand-rolled, process-local, in-memory cache — no external cache server, no network connection to configure, and consequently nothing shared across replicas.

**Actual mechanism:**

- **Implementation**: `store/cache/cache.go` — a `Cache` struct backed by a `sync.Map` plus an `atomic.Int64` item counter (`cache.go:66-73`), satisfying the `cache.Interface` at `cache.go:11-32`. Entries are `item{value, expiration, size}` (`cache.go:35-39`).
- **Configuration site**: `store.New` — `store/store.go:38-58`. It builds one `cache.Config` literal (`store/store.go:40-45`) and uses it for all three caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`, declared at `store/store.go:27-29`). The values are hardcoded — no flag, env var, or profile field feeds them. `cache.DefaultConfig()` (`store/cache/cache.go:57-64`) declares the identical values but isn't what the store uses.
- **TTL for user entries: 10 minutes**, from `DefaultTTL: 10 * time.Minute` (`store/store.go:41`). Every `userCache.Set` call — `store/user.go:98, 122, 132, 143, 167` — goes through `Cache.Set`, which forwards to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`); no user write path uses a custom TTL. Expiry is enforced lazily on read (`cache.go:135-144`) and by a sweeper goroutine ticking every `CleanupInterval` of 5 minutes (`cache.go:200-215`).
- **Other bounds**: `MaxItems: 1000` per cache; exceeding it triggers `cleanupOldest`, which drops roughly 20% of capacity (`cache.go:253-313`). `OnEviction` is nil.
- **Invalidation**: user deletion explicitly evicts by key at `store/user_delete.go:40`. Note the cache is keyed by user ID only (`userCacheKey`), and `Store.GetUser` consults it solely when the lookup is by `ID` (`store/user.go:149-156`) — lookups by username or email always hit the database.
