**gRPC/Connect API (`server/router/api/v1`)**

- `ListMemos` visibility narrowing — anonymous → `PUBLIC` only; authenticated → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` — `server/router/api/v1/memo_service.go:217-226`
- User stats visibility narrowing — same pattern applied to stats queries — `server/router/api/v1/user_service_stats.go:84-90` and `:218-220`
- `CreateMemoComment` gate on the parent memo — `server/router/api/v1/memo_service_comments.go:41` (plus comment-visibility rule at `:100`)
- Reaction access gates (list/upsert and delete) — `server/router/api/v1/reaction_service.go:30-38`, `:83`

Two structural notes:

- **Share tokens are the sanctioned bypass.** `server/router/fileserver/fileserver.go:684-689` accepts a `share_token` query param and, if it maps to a non-expired `MemoShare` for that exact memo, skips the visibility check. `server/router/api/v1/memo_share_service.go` contains no visibility checks at all — access there is proven by possession of the token.
- **MCP inherits rather than re-implements.** `server/router/mcp` has no visibility logic; `NewMCPService` builds an in-process adapter over the Echo server (`server/router/mcp/service.go:48`), so MCP tool calls re-enter the API v1 handlers and pick up the checks above.
