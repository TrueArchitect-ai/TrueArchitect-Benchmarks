Two things worth noting about this path:

- **The image is not a file.** `user.AvatarURL` holds a base64 data URI in the `user.avatar_url` column, so the "stored data" is the user row itself — there's no attachment record, no filesystem read, and no S3 fetch. `parseDataURI` decodes it and `avatarAllowedTypes` (`fileserver.go:75`) restricts the MIME type before it is served.
- **The cache doesn't help here.** `Store.GetUser` only consults `userCache` when the lookup is by `ID` (`store/user.go:149-156`); this path looks up by username, so every avatar request falls through to `ListUsers` and hits the database, then writes the result into the cache keyed by ID.
