**Premise correction: this project has no GraphQL — no `.graphql`/`.gql` files, no GraphQL server library in `go.mod`, and no case-insensitive match for "graphql" anywhere in the Go, TypeScript, JSON, or Markdown sources. The public API is defined by Protocol Buffers.**

**Actual API surface:**

- **Schema of record**: eight `.proto` service definitions in `proto/api/v1/` — `memo_service.proto` (20 RPCs), `user_service.proto` (26), `attachment_service.proto` (6), `instance_service.proto` (6), `idp_service.proto` (5), `shortcut_service.proto` (5), `auth_service.proto` (4), `ai_service.proto` (1), plus shared types in `common.proto`. That's ~73 RPCs total.
- **Code generation** is driven by buf (`proto/buf.gen.yaml`), which fans one schema out to five targets: Go protobuf types and gRPC stubs, Connect handlers (`proto/gen/api/v1/apiv1connect/`), grpc-gateway REST bindings (`*.pb.gw.go`), a gnostic-generated OpenAPI document, and TypeScript clients emitted directly into `web/src/types/proto`.
- **Wire protocols exposed to clients** — all from that same schema:
  - **Connect/gRPC** and **REST via grpc-gateway**, registered in `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65+`), wired at `server/server.go:87-89`.
  - **OpenAPI/REST**: the generated spec is embedded into the binary at `proto/openapi_embed.go` (`//go:embed gen/openapi.yaml`) and served via `proto.OpenAPIYAML()`.
  - **MCP**: `mcp.NewMCPService` (`server/router/mcp/service.go:26`) builds its tool catalog by parsing that same embedded OpenAPI spec and dispatching in-process back through the Echo routes.
- **Non-proto HTTP surfaces** that sit outside the generated API: the file server (`/file/attachments/...`, `/file/users/:identifier/avatar` — `server/router/fileserver/fileserver.go:123-124`), RSS feeds (`server/router/rss/rss.go:66-68`), and `/healthz` (`server/server.go:67`).

So the closest analogue to "the schema for the public API" is `proto/api/v1/*.proto`, with `proto/gen/openapi.yaml` as its generated, machine-readable description.
