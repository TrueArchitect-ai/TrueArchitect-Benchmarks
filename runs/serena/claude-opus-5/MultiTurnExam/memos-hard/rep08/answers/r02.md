**Premise correction: there is no per-user API rate-limiting middleware in this repository — so there is no registration site and no request limits to report.**

Evidence:

- A case-insensitive grep for `ratelimit` / `rate_limit` / `rate limit` / `throttl` across all `.go`, `.ts`, `.tsx`, and `.md` files returns only aspirational documentation in the email package: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") and a "5. Implement Rate Limiting" suggestion in `internal/email/README.md:286-295`. Neither describes shipped code, and neither concerns the API.
- The Echo server registers exactly two global middlewares — `middleware.Recover()` and `newCORSMiddleware(profile)` — at `server/server.go:51-52`. Echo's built-in `middleware.RateLimiter` is never used.
- The API v1 interceptor chain enforces authentication and access policy (`NewAuthorizer` / `CheckAccess`, `server/router/api/v1/v1.go:65-90`), not request rate.
- No rate-limiting dependency exists: `golang.org/x/time/rate` is absent from the imports and `go.mod`.
