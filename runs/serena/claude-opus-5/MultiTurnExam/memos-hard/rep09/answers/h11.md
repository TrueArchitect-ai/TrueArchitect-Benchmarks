Method and scope notes:

- I treated the data layer as the whole `store/` tree (`store/`, `store/db/{sqlite,postgres,mysql}`, `store/test`) and excluded it, plus generated `proto/gen/`. Counting only the `store` root package as "the layer" would add the three driver packages and `store/test` to every type's tally, but it wouldn't change the ranking.
- Runner-up outside the top two is `store.Attachment` (`store/attachment.go:16`) at 4 packages / ~43 refs — it loses to `Memo` mainly because `server/notification` and `server/runner/memopayload` don't touch it.
- The differentiator for `User` is that it crosses into the auth and file-serving layers (`server/auth`, `server/router/fileserver`) where `Memo` never appears — `store.User` is what `auth.Authenticator.AuthenticateToUser` returns and what avatar serving resolves.
- Some entity types that exist in the store have zero external references — `store.UserSetting` (`store/user_setting.go:13`), `store.InstanceSetting` (`store/instance_setting.go:14`), `store.IdentityProvider` (`store/idp.go:12`). Server code consumes their protobuf equivalents (`storepb.UserSetting`, etc.) rather than the store structs, so they don't compete here.
