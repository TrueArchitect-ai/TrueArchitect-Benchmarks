**Premise correction: no per-user API rate-limiting middleware exists in this repository — there is nothing to register and no limits to report.**

What I checked:

- A case-insensitive grep across all Go sources for `ratelimit`, `rate_limit`, `rate limit`, `throttl`, and `limiter` returns exactly one hit, and it's a comment in unrelated documentation: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a *future suggestion*, not an implementation. Similarly, `internal/email/README.md:286-295` sketches rate limiting under a "###5. Implement Rate Limiting" heading as example code a caller could write.
- `go.mod` contains no rate-limiting dependency — notably no `golang.org/x/time/rate`, and no token-bucket or leaky-bucket library of any kind.
- The full set of HTTP middleware registered on the Echo server is two entries: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/server.go:51-52`, with the CORS middleware defined at `server/cors.go:13`). Neither throttles.
- On the API side, the only interceptor layers are authentication and access control: `gatewayAuthMiddleware` wired via `runtime.WithMiddlewares` for the gRPC-Gateway (`server/router/api/v1/v1.go:69`, `:97`) and the matching Connect interceptor. Both call `authorizer.Authenticate` / `authorizer.CheckAccess` — identity and permission checks, not request-count limits.

Related but different mechanisms that do exist, in case one of them is what you had in mind:

- **Concurrency caps, not rate limits**: `semaphore.NewWeighted(3)` for thumbnail generation and `semaphore.NewWeighted(2)` for image processing on `APIV1Service` (`server/router/api/v1/v1.go:57-58`), plus `maxConcurrentThumbnails = 3` in the file server (`server/router/fileserver/fileserver.go:46`, `:116`). These bound simultaneous work, not requests per user per interval.
- **A bounded queue with drop-on-full** for outbound webhooks — 128 slots drained by 4 workers (`internal/webhook/webhook.go:39-55`, `:189-195`).
- **A content-length limit** per memo, enforced in create/update (`server/router/api/v1/memo_service.go:100-106`, `:438-444`).

If you want per-user rate limiting, it would need to be added — the natural insertion points are the Echo middleware chain at `server/server.go:51` for all HTTP traffic, or the authenticated interceptor at `server/router/api/v1/v1.go:69` where the caller's identity is already resolved.
