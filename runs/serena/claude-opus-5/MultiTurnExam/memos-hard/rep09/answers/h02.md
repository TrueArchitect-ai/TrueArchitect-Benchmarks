**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery.** `Post` (`internal/webhook/webhook.go:120-180`) marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and performs the actual `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. Memo events don't call it directly — they call `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a 128-slot buffered channel drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:39-55`); those goroutines are what invoke `Post`. Call sites are `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

**Protection.** Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against loopback, RFC-1918, link-local/IMDS `169.254.0.0/16`, and the IPv6 equivalents (`internal/webhook/validate.go:14-23`):

1. *Dial-time* — the shared `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`, defined at `:59-77`). It resolves the host itself and refuses the connection if any resolved IP is reserved. Because this runs on every dial rather than at save time, it also defeats DNS rebinding.
2. *Registration-time* — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-IP hostnames when a user creates or updates a webhook, at `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

One thing worth flagging: `AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both layers when true, but nothing in the repo ever assigns it — no flag, env binding, or config read. It's effectively a compile-time constant `false` today, so the documented "self-hosted deployments targeting local network services" escape hatch is not actually reachable.
