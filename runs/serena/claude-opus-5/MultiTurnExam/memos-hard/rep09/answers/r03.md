**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never started — so there is no scheduled time to report.**

Two separate parts of the premise fail:

**1. No cleanup job exists.** Nothing in the server registers or runs a periodic database-cleanup, vacuum, purge, or prune task. Grepping `server/`, `store/`, and `cmd/` for those terms turns up only unrelated things: per-request attachment-storage cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`), cascade cleanup inside `DeleteMemo` (`server/router/api/v1/memo_service.go:579`), and a best-effort rollback of a provisional SSO user row (`server/router/api/v1/auth_service_sso.go:76`). All are synchronous consequences of a user action, not scheduled work.

**2. The cron scheduler is dead code.** `internal/scheduler` is a complete cron implementation — a 5-field expression parser (`internal/scheduler/parser.go`), job registry (`internal/scheduler/job.go`, `scheduler.go:70`), timezone support (`scheduler.go:33`), and Recovery/Logging/Timeout middleware (`internal/scheduler/middleware.go`) — but **no production code imports it**. Every reference to `internal/scheduler` lives inside the package's own `_test.go` files and `doc.go` examples; a grep for the import path outside `internal/scheduler/` returns nothing. So no cron expression is ever evaluated at runtime.

**What actually runs on a schedule.** The server has exactly one background runner, started from `Server.startBackgroundRunners` (`server/server.go:153-174`): the S3 presign runner, which re-signs S3 attachment URLs. It doesn't use cron at all — it's a plain `time.Ticker` with `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:26-41`), plus one immediate pass at startup (`server/server.go:163`). Being an interval ticker anchored to process start, it has no fixed wall-clock time; it fires 12 and 24 hours after boot, whenever that was.

There's also a second runner package, `server/runner/memopayload`, that would rebuild memo payloads in batches — but nothing constructs it either (`server/runner/memopayload/runner.go:19`), so it never runs.
