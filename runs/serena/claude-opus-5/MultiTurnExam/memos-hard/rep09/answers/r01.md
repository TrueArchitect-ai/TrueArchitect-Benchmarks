**Premise correction: there is no Redis in this repository.** Nothing imports a Redis client, `go.mod` has no Redis (or memcached) dependency, and a case-insensitive grep for "redis" across the Go sources, config files, and manifests returns zero hits. The cache layer is entirely in-process.

**Actual mechanism.** The cache is a hand-rolled, thread-safe in-memory store: `store/cache/cache.go`. `Cache` holds entries in a `sync.Map` with an atomic item counter (`store/cache/cache.go:66-73`), each `item` carrying a value, an absolute `expiration`, and an estimated size (`:35-39`). There is no network connection to configure — `cache.New` just starts a background `cleanupLoop` goroutine (`:76-85`).

**Configuration site.** `Store.New` builds one `cache.Config` and hands it to three separate caches (`store/store.go:38-52`):

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

used for `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`, `:49-51`). The identical values are also the package defaults in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), though `Store` supplies its own literal rather than calling it.

**TTL for user entries: 10 minutes.** Every write to `userCache` uses the plain `Set` (`store/user.go:98, 122, 132, 143, 167`), which delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`) — no user-specific override of `SetWithTTL` exists anywhere.

Expiry is enforced two ways: lazily on read, where `Get` deletes and reports a miss once `time.Now().After(itm.expiration)` (`store/cache/cache.go:135-144`), and eagerly by the 5-minute `cleanupLoop` sweep (`:200-250`). Separately, exceeding `MaxItems: 1000` triggers `cleanupOldest`, which drops ~20% of capacity (`:117-119`, `:253-255`), so a user entry can be evicted before its 10 minutes elapse. Explicit invalidation happens on user deletion (`store/user_delete.go:40`).

One caveat about scope: because this is per-process memory, the cache is not shared across replicas — a multi-instance deployment gets independent caches with up to 10 minutes of divergence on user rows.
