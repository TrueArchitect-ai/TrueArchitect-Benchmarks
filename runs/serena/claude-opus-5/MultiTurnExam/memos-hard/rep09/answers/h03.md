**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- **Abstraction — `internal/idp/idp.go`**: the package is deliberately thin. It defines only `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) — the provider-neutral shape every backend must produce. Note there is no Go `interface` type here; the abstraction is the shared user-info struct plus the convention that each provider package exposes `NewIdentityProvider` / `ExchangeToken` / `UserInfo`.

- **Implementation — `internal/idp/oauth2/oauth2.go`**: the sole concrete protocol, OAuth2, built on `golang.org/x/oauth2`. `NewIdentityProvider` validates the required config fields (`internal/idp/oauth2/oauth2.go:27`), `ExchangeToken` swaps the auth code for an access token with optional PKCE `code_verifier` support (`:47`), and `UserInfo` calls the configured userinfo endpoint and maps raw JSON claims onto `idp.IdentityProviderUserInfo` using the configurable `FieldMapping` (`:83`).

Supporting evidence that OAuth2 is the only one shipped: the store enum has exactly one non-unspecified value, `IdentityProvider_OAUTH2 = 1` (`proto/gen/store/idp.pb.go:27-28`), and the single consumer is `server/router/api/v1/auth_service_sso.go:13`, which imports only the oauth2 package.
