Visibility is enforced in **nine** distinct places across five surfaces. Grouped by kind:

**Per-memo permission checks (gRPC/Connect API)**
```
checkMemoReadAccess (shared gate for GetMemo, parent-memo reads, ListMemoComments) — server/router/api/v1/memo_service.go:39 (callers :356, :367; server/router/api/v1/memo_service_comments.go:148)
CreateMemoComment — related-memo gate                                              — server/router/api/v1/memo_service_comments.go:41
Reaction service — UpsertMemoReaction / DeleteMemoReaction gates                   — server/router/api/v1/reaction_service.go:30, :38, :83
checkAttachmentAccess — attachment inherits its memo's visibility                  — server/router/api/v1/attachment_service.go:445, :451
ListMemoAttachments gate                                                           — server/router/api/v1/memo_attachment_service.go:214, :222
```

**Query-scoping (visibility pushed into the store filter, so private rows never load)**
```
ListMemos — anonymous → PUBLIC only; authed → own OR PUBLIC/PROTECTED               — server/router/api/v1/memo_service.go:219-227
User stats endpoints — PUBLIC, or PUBLIC+PROTECTED for other users                  — server/router/api/v1/user_service_stats.go:84, :90, :218, :220
RSS feeds (instance + per-user)                                                     — server/router/rss/rss.go:90, :141
Frontend sitemap.xml                                                                — server/router/frontend/frontend.go:150
```

**Binary/file serving (non-gRPC HTTP surface)**
```
checkAttachmentPermission — public+anonymous-allowed, share-token fallback, private→creator/admin — server/router/fileserver/fileserver.go:677, :684-689, :699
```

**Real-time push (SSE fan-out)**
```
SSEClient.canReceive — per-subscriber filter; PRIVATE events only to creator or admin — server/router/api/v1/sse_hub.go:134-143
```

**Notification suppression (prevents leaking content by email/inbox)**
```
Email notification gate         — server/notification/email.go:313, :316
Mention-notification targeting  — server/router/api/v1/memo_mention_helpers.go:62, :67, :84
Notification settings gate      — server/router/api/v1/user_service_notifications.go:309, :312
```

Two things worth calling out:

- **Share tokens are a deliberate bypass**, not a separate enforcement point: `GetMemoByShare` (`server/router/api/v1/memo_share_service.go:150`) resolves a token and returns the memo *without* consulting visibility — it only rejects archived/missing memos. The file server honors the same bypass via the `share_token` query param (`server/router/fileserver/fileserver.go:684-689`), requiring the token to be unexpired and bound to that exact memo.
- **The two styles differ in failure mode.** The per-memo checks return `PermissionDenied`/`Unauthenticated` after loading the row; the query-scoping sites never fetch non-visible rows at all. `checkMemoReadAccess` also layers an archived-memo rule (creator-only) on top of visibility (`memo_service.go:44-53`).
