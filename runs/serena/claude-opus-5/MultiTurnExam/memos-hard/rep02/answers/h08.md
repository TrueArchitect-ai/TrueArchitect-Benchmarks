**Two declarers, both named `Runner`, in sibling packages:**

| declarer | invoked from production code? | caller |
|---|---|---|
| `s3presign.Runner.RunOnce` — `server/runner/s3presign/runner.go:43` | **yes** | `Server.startBackgroundRunners` — `server/server.go:163`; also self-invoked on each tick by `s3presign.Runner.Run` — `server/runner/s3presign/runner.go:36` |
| `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:27` | **no** | none — no caller anywhere, production or test |

Evidence for the negative case: grepping `RunOnce` across all Go files in the repo yields exactly five hits — the two declarations above, the two call sites on the s3presign runner, and nothing else. Separately, grepping `memopayload` shows the package is imported in only one place, `server/router/api/v1/memo_service.go:18`, and that import is used solely for the free function `memopayload.RebuildMemoPayload` (`memo_service.go:108` in `CreateMemo`, `:447` in `UpdateMemo`). `memopayload.NewRunner` (`server/runner/memopayload/runner.go:19`) is never called, so no `memopayload.Runner` value is ever constructed — its `RunOnce`, which would batch-rebuild the payload of every memo, is unreachable dead code. There is also no `runner_test.go` in `server/runner/memopayload/` (the directory holds only `runner.go`), so it isn't exercised by tests either.

For contrast, the live one: `s3presign.Runner.RunOnce` is called synchronously once at startup (`server/server.go:163`) and then every 12 hours by the ticker loop in `Run` (`server/runner/s3presign/runner.go:29-41`), which is launched as a goroutine at `server/server.go:169`.

Note the `internal/scheduler` package is unrelated — it declares no `RunOnce` method.
