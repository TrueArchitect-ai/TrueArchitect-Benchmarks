The last three all funnel through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `:67` before broadcasting the SSE event.

**Convergence.** Every `Dispatch*Webhook` method (`server/router/api/v1/memo_service_webhooks.go:15-46`) loads the target user's webhooks via `s.Store.GetUserWebhooks`, fills in `payload.URL = hook.Url` — the user-configured URL — and calls `webhook.PostAsync` (`memo_service_webhooks.go:43` and `:71`). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a 128-slot channel; the actual outbound request is made by the four worker goroutines started in `init` (`internal/webhook/webhook.go:42-55`), each of which calls **`webhook.Post`** (`internal/webhook/webhook.go:120`). `Post` is the single function that builds the request and issues it via `safeClient.Do` at `internal/webhook/webhook.go:152`.

One nuance worth stating: because delivery is queued, the HTTP request happens on a worker goroutine after the handler has already returned — the handlers cause it transitively rather than performing it inline.

Separately, `GetLinkMetadata` also makes an outbound request to a user-supplied URL through `fetchHTMLMeta` / `httpgetter.GetHTMLMeta` (`server/router/api/v1/memo_service.go:28`), but that's a distinct path that does not pass through `webhook.Post` and isn't driven by stored webhook configuration.
