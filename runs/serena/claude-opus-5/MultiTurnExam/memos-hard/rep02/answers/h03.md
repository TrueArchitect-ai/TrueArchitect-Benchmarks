**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- **Abstraction** — `internal/idp/idp.go` is the whole package: a single `IdentityProviderUserInfo` struct with `Identifier`, `DisplayName`, `Email`, `AvatarURL`. It's a shared result type rather than a Go interface — there's no `IdentityProvider` interface declared, so the "abstraction" is the normalized user-info shape every provider must produce, plus the protobuf schema in `proto/store/idp.proto` (`IdentityProvider.Type` enum and the `IdentityProviderConfig` `oneof`).

- **Implementation** — `internal/idp/oauth2/oauth2.go` defines `oauth2.IdentityProvider` with `NewIdentityProvider` (validates required config fields, `oauth2.go:27`), `ExchangeToken` (authorization-code exchange with optional PKCE `code_verifier`, `oauth2.go:47`), and `UserInfo` (bearer-token call to `user_info_url`, mapping claims through `FieldMapping` into `idp.IdentityProviderUserInfo`, `oauth2.go:83`).

OAuth2 is the only protocol that ships. Both the proto `Type` enum (`proto/store/idp.proto:11-14`) and the config `oneof` (`proto/store/idp.proto:21-25`) have exactly one member, and the SSO dispatch is a single `if identityProvider.Type == storepb.IdentityProvider_OAUTH2` branch at `server/router/api/v1/auth_service_sso.go:120-134` — no OIDC-, SAML-, or LDAP-specific package exists. Note that if a provider's type were ever unset, `userInfo` would stay nil and be dereferenced at `auth_service_sso.go:142`; in practice the enum only permits OAUTH2.
