**Premise correction: neither. There is no message broker in this repository — no NATS, no RabbitMQ, no AMQP, Kafka, or SQS client. Consequently there is no queue declaration anywhere.**

Evidence: a case-insensitive grep for `nats`, `rabbitmq`, `amqp`, `kafka`, `streadway`, `pubsub`, and `sqs` across all Go sources plus `go.mod` and `go.sum` yields a single hit, and it's a coincidental substring inside a base64 checksum line in `go.sum:63` (the `cespare/xxhash` hash), not a dependency. No broker library is imported or vendored.

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool**, all in `internal/webhook/webhook.go`:

- **The "queue"** is a package-level channel, `asyncPostQueue`, with a buffer of 128 payloads — `internal/webhook/webhook.go:39`. It's declared in the same `var` block as the HTTP client, not by any broker API.
- **The workers** are 4 goroutines started in the package `init` function — `internal/webhook/webhook.go:42-55`. Each ranges over the channel and calls `Post(payload)` for every item, logging a warning on failure (`:46-51`).
- **The producer** is `PostAsync` — `internal/webhook/webhook.go:184-196` — which does a non-blocking `select` send: if the buffer is full, the payload is **dropped** with a warning rather than blocking or retrying (`:191-194`). It also drops a nil payload defensively (`:185-188`).
- **Callers** are the memo webhook dispatchers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

Three properties follow from this being a channel rather than a broker, worth being explicit about: delivery is **at-most-once** with no retry and no dead-letter path; the queue is **per-process and in-memory**, so anything pending is lost on restart and is not shared across replicas; and back-pressure is handled by discarding rather than blocking the RPC handler.
