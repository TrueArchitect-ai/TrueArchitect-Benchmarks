**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF-guarded dial (`safeDialContext` + `isReservedIP`) on the shared `safeClient` transport — `internal/webhook/webhook.go:59` / `internal/webhook/validate.go:44`**

How it fits together:

**Delivery.** `Post` (`internal/webhook/webhook.go:120`) marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`, lines 133–150), and performs the actual outbound call at `internal/webhook/webhook.go:152` via `safeClient.Do(req)`. Callers don't invoke it directly — `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel drained by 4 worker goroutines started in `init` (`internal/webhook/webhook.go:39-55`), and those workers are what call `Post`. The API-side triggers are `dispatchMemoRelatedWebhook` and `DispatchMemoCommentCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

**Protection.** Two layers, both routed through `isReservedIP` (`internal/webhook/validate.go:44`), which tests the address against a prebuilt list of reserved CIDRs — loopback, RFC-1918, link-local incl. `169.254.169.254` IMDS, and IPv6 equivalents (`internal/webhook/validate.go:14-23`):

1. *At dial time* — `safeDialContext` (`internal/webhook/webhook.go:59`) is installed as the `Transport.DialContext` of `safeClient` (`internal/webhook/webhook.go:32-37`). It re-resolves the host and rejects the connection if **any** returned IP is reserved. Because this runs at connect time rather than at config time, it also defeats DNS rebinding — the comment at `internal/webhook/webhook.go:29-31` says as much.
2. *At registration time* — `ValidateURL` (`internal/webhook/validate.go:62`) enforces absolute URL, http/https scheme only, and non-reserved resolution when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`).

One thing worth flagging: `AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both layers when true, but nothing in the repo ever assigns it — there's no flag, env var, or config wiring for it, so it's permanently `false` at runtime.
