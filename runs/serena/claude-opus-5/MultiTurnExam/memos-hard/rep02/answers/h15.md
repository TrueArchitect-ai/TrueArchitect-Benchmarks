Distinct visibility-enforcement sites across the server surfaces:

**Connect/gRPC API (`server/router/api/v1`)**
- `checkMemoReadAccess` (single-memo gate: private → creator only, non-public → authenticated) — `server/router/api/v1/memo_service.go:39-68`; called from `GetMemo` (`:356`), the parent-memo check (`:367`), and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)
- `ListMemos` query scoping (anonymous → `PUBLIC` only; authenticated → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:217-227`
- `checkAttachmentAccess` (derives access from the owning memo's visibility) — `server/router/api/v1/attachment_service.go:422-455`, called at `:256`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-224`
- `ListMemoReactions` — `server/router/api/v1/reaction_service.go:30-42`
- `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:83`
- `CreateMemoComment` (gate on the parent memo) — `server/router/api/v1/memo_service_comments.go:41`
- `ListAllUserStats` — `server/router/api/v1/user_service_stats.go:84-92`
- `GetUserStats` — `server/router/api/v1/user_service_stats.go:218-221`

**Static file serving (`server/router/fileserver`)**
- `checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650-704`; public+anonymous allowed at `:677`, private restricted at `:699`, with a share-token bypass at `:684-689`

**Server-sent events (`server/router/api/v1`)**
- `SSEClient.canReceive` (per-subscriber delivery filter; private events only to creator or admin, unknown visibility denied) — `server/router/api/v1/sse_hub.go:134-144`

**RSS feeds (`server/router/rss`)**
- `GetExploreRSS` — `server/router/rss/rss.go:90` (hard-coded `VisibilityList: []store.Visibility{store.Public}`)
- `GetUserRSS` — `server/router/rss/rss.go:141` (same)

**Frontend/SSR (`server/router/frontend`)**
- `getSitemapXML` — `server/router/frontend/frontend.go:150` (public memos only)

**Notification content (`server/notification`, `server/router/api/v1`)**
- Email notification redaction — `server/notification/email.go:313-316` (private/protected memo content withheld)
- In-app notification redaction — `server/router/api/v1/user_service_notifications.go:309-312`
- Mention-target filtering — `server/router/api/v1/memo_mention_helpers.go:62-84` (no mention notification to a user who couldn't see the private memo)

Two notes: the MCP surface (`server/router/mcp/`) contains no visibility logic of its own — its catalog exposes `MemoService_ListMemos` / `MemoService_GetMemo` (`server/router/mcp/catalog.go:12-14`) and inherits the API-layer checks. And share links are a deliberate bypass rather than a separate check: `getActiveMemoShare` (`server/router/api/v1/memo_share_service.go:199`) validates token existence and expiry only, granting access regardless of the memo's visibility.
