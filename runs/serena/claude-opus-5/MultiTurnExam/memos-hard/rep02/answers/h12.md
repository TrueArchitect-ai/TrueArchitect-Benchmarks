**`(*sqlite.DB).CreateMemo` — `store/db/sqlite/memo.go:16` (INSERT executed at `store/db/sqlite/memo.go:41-42`); determined by following the driver default through the factory's `switch`, since the call site is an interface dispatch**

**Why this is the one that runs.** Three concrete `CreateMemo` methods exist — `store/db/sqlite/memo.go:16`, `store/db/mysql/memo.go`, and `store/db/postgres/memo.go` — and the call site can't distinguish them: `Store.CreateMemo` (`store/memo.go:109`) validates the UID and then delegates through the `Driver` interface at `store/memo.go:113` (`s.driver.CreateMemo(ctx, create)`), where `driver` is the interface-typed field declared at `store/store.go:15`. Static reading of that line names no implementation, so the selection has to be resolved from configuration:

1. **Default value.** With no flags, `viper.GetString("driver")` yields `"sqlite"` — the default is registered twice, as a viper default (`cmd/memos/main.go:122`) and as the persistent flag's default (`cmd/memos/main.go:130`, bound at `:151`). Nothing in `Profile.Validate` (`internal/profile/profile.go:68`) overrides `Driver`.
2. **Injection.** That value lands in `instanceProfile.Driver` (`cmd/memos/main.go:43`) and is passed to `db.NewDBDriver(instanceProfile)` (`cmd/memos/main.go:57`); the returned driver is handed to `store.New(dbDriver, instanceProfile)` (`cmd/memos/main.go:64`), which stores it in the `driver` field (`store/store.go:38`).
3. **Factory branch.** `NewDBDriver` switches on `profile.Driver` and, for `"sqlite"`, returns `sqlite.NewDB(profile)` — `store/db/db.go:18-20`. That is the only place a driver is constructed in production code (the MySQL and Postgres branches at `store/db/db.go:22` and `:24` are unreachable without an explicit `--driver`).

So `s.driver` holds a `*sqlite.DB`, and the dispatch resolves to `(*sqlite.DB).CreateMemo`. That method assembles the column/placeholder lists, marshals `create.Payload` to protojson, and runs `INSERT INTO memo (...) VALUES (...) RETURNING id, created_ts, updated_ts, row_status` via `d.db.QueryRowContext` (`store/db/sqlite/memo.go:41-47`), scanning the generated values back into the passed-in `*store.Memo`.

The upstream entry point is the `CreateMemo` RPC handler (`server/router/api/v1/memo_service.go:70`), which calls `s.Store.CreateMemo`.
