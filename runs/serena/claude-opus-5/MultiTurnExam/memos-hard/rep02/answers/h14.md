**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`**

**What it computes.** `RebuildMemoPayload` lazily initializes `memo.Payload`, calls `markdownService.ExtractAll([]byte(memo.Content))`, and assigns exactly two fields (`runner.go:85-86`):

- `Payload.Tags` — every `#tag` found in the goldmark AST, deduplicated with original case preserved via `uniquePreserveCase` (`internal/markdown/markdown.go:418`). Tags inside links/images are skipped (`asMemoTagNode` / `isTagNodeInLinkOrImage`, `markdown.go:122`).
- `Payload.Property` — a `storepb.MemoPayload_Property` (`proto/store/memo.proto:15-22`) with five derived fields, all set during a single AST walk (`markdown.go:370-411`):
  - `has_link` — any `gast.KindLink` node
  - `has_code` — any code block, fenced code block, or code span
  - `has_task_list` — any `TaskCheckBox`
  - `has_incomplete_tasks` — any `TaskCheckBox` that is unchecked
  - `title` — text of the first H1 heading, only when it is the document's first block child

`ExtractAll` also returns `Mentions`, but `RebuildMemoPayload` deliberately does not persist those — mentions are consumed separately for notifications (`server/router/api/v1/memo_mention_helpers.go:32`).

**Triggers.** Two production paths, both in the memo service:

1. `CreateMemo` — `server/router/api/v1/memo_service.go:108` — recomputed before insert, after the content-length check. `CreateMemoComment` inherits this by delegating to `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:447` — only inside the `path == "content"` branch; the rebuilt payload is then written via `update.Payload = memo.Payload` (`:451`).

Nothing else recomputes it. Notably, the `location` update branch (`memo_service.go:481-484`) mutates `Payload.Location` and writes the payload back, but leaves `Tags`/`Property` as-is — location is user-set, not derived. There's also a batch backfill, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), which would page through every memo and rebuild each payload, but `NewRunner` is never called anywhere, so it doesn't run.

**Consumption.** `convertMemoFromStore` reads the stored payload straight onto the API message — `memoMessage.Tags` and `memoMessage.Property` at `server/router/api/v1/memo_service_converter.go:48-49` — and the tag lists feed user stats (`server/router/api/v1/user_service_stats.go:138`, `:254`). That's why it's persisted rather than recomputed per request.

One consequence worth flagging: because the only triggers are content create/update, a memo whose payload predates a change in extraction logic keeps the stale derived values until its content is edited — and the runner that exists to fix that is not wired up.
