The browser hits `GET /file/users/{username}/avatar`. Each hop:

**Route/URL origin (how the browser learns the URL)**
- `convertUserFromStore` — `server/router/api/v1/user_service_converters.go:15` — when `user.AvatarURL` is a base64 data URI, the API replaces it with `/file/{userpb.Name}/avatar` (i.e. `/file/users/{username}/avatar`) at `:36` rather than inlining the image; `UserAvatar` renders that into `<img src>` (`web/src/components/UserAvatar.tsx:14`).

**Request path**
- `FileServerService.RegisterRoutes` — `server/router/fileserver/fileserver.go:121` — binds `GET /file/users/:identifier/avatar` at `:124`; wired into startup at `server/server.go:81-82`.
- `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168` — the serving handler.
- `FileServerService.getCurrentUser` → `auth.Authenticator.AuthenticateToUser` — `server/router/fileserver/fileserver.go:708` — only invoked when `!s.Profile.AllowAnonymous()` (`:173-181`); on a public instance this hop is skipped entirely.
- `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715` — one-liner wrapping the store call with `&store.FindUser{Username: &identifier}`.
- `Store.GetUser` — `store/user.go:148` — checks `s.userCache` only when `find.ID` is set; a username lookup always falls through to the next hop.
- `Store.ListUsers` — `store/user.go:136` — delegates to the driver, then populates `userCache`.
- `(*DB).ListUsers` — `store/db/sqlite/user.go:88` (peers: `store/db/mysql/user.go`, `store/db/postgres/user.go`) — builds `username = ?` into the WHERE clause (`:128-130`) and runs the `SELECT ... avatar_url ... FROM user` query (`:151-166`) — the data layer.

**Response path**
- `FileServerService.parseDataURI` — `server/router/fileserver/fileserver.go:737` — regex-splits the stored `data:<type>;base64,<payload>` value and base64-decodes it.
- MIME allowlist check against `avatarAllowedTypes` — `server/router/fileserver/fileserver.go:75` / `:201` — rejects anything outside png/jpeg/gif/webp/heic/heif.
- `setSecurityHeaders` + `c.Blob` — `server/router/fileserver/fileserver.go:205-209` — sets `nosniff`, `X-Frame-Options: DENY`, a restrictive CSP, `Cache-Control: public, max-age=3600`, and writes the bytes.

Two things this trace makes clear: the avatar is stored inline in the `user.avatar_url` column as a base64 data URI, not as a file or attachment row — no filesystem or S3 hop exists. And the driver selection at each `store.Store` call goes through `s.driver`, resolved once by the factory `NewDBDriver` (`store/db/db.go:14`).
