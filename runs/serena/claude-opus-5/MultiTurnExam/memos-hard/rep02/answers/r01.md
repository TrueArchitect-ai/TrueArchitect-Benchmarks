**Premise correction: there is no Redis in this repository — no client library, no connection config, no `redis` reference of any kind.** Grepping case-insensitively for "redis" across all Go sources, `go.mod`, `go.sum`, and JSON/YAML config files returns zero hits. There is no external cache server to configure.

**Actual mechanism: a process-local in-memory cache.**

- Implementation: `store/cache/cache.go` — `Cache` is a `sync.Map` plus an atomic item counter (`store/cache/cache.go:65-72`), behind the `Interface` at `store/cache/cache.go:11-32`. Entries carry a value, an absolute `expiration`, and an estimated size (`:35-38`).
- Configuration site: `store.New` — `store/store.go:38-45` — builds a single `cache.Config` literal inline and passes it to three separate cache instances (`:51-53`): `instanceSettingCache`, `userCache`, `userSettingCache` (fields declared at `store/store.go:27-29`). The settings are hard-coded in Go, not read from any file, flag, or env var. `cache.DefaultConfig()` (`store/cache/cache.go:56-63`) holds the same values but isn't what `store.New` calls.

**TTL for user entries: 10 minutes**, with a 5-minute background sweep and a 1000-item cap:

| setting | value | path |
|---|---|---|
| `DefaultTTL` | `10 * time.Minute` | `store/store.go:40` |
| `CleanupInterval` | `5 * time.Minute` | `store/store.go:41` |
| `MaxItems` | `1000` | `store/store.go:42` |

All user writes go through `Set` (not `SetWithTTL`), so they take `DefaultTTL` — `store/user.go:98`, `:122`, `:132`, `:143`, `:167`, keyed by `userCacheKey(user.ID)` (`store/user.go:88`). Expiry is enforced lazily on read as well: `Get` deletes and reports a miss once `time.Now()` passes the entry's expiration (`store/cache/cache.go:134-143`). Entries are also evicted early on explicit invalidation (`store/user_delete.go:40`) and when the 1000-item ceiling triggers `cleanupOldest` (`store/cache/cache.go:116-118`).

Two consequences worth noting: the cache is per-process, so a multi-instance deployment gets no shared invalidation; and `Store.GetUser` only consults the cache when looking up by ID (`store/user.go:149-156`) — username lookups always hit the database.
