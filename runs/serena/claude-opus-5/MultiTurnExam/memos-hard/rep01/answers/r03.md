**Premise correction: there is no nightly database-cleanup job, and the cron scheduler isn't running at all — so there's no schedule to report.**

Two separate false premises:

**1. No database-cleanup job exists.** Nothing in the repo periodically prunes, vacuums, or compacts the database. The only "cleanup" code is event-driven, not scheduled:
- Attachment storage cleanup when memos/users are deleted — `store/attachment.go:171,262-275`, `server/router/api/v1/user_service.go:421-450`, `server/router/api/v1/memo_service.go:579`.
- Best-effort removal of a provisional SSO user row on failure — `server/router/api/v1/auth_service_sso.go:76`.
- The in-memory cache's expiry sweep, `CleanupInterval: 5 * time.Minute` (`store/store.go:42`) — that's the cache goroutine from r01, not the database.

**2. `internal/scheduler` is unused in production.** It's a complete, well-documented cron package — `New` (`internal/scheduler/scheduler.go:54`), `Register`, `ParseCronExpression` (`internal/scheduler/parser.go`), plus `Recovery`/`Logging`/`Timeout` middleware and timezone support — but every reference to it outside its own directory is a test. A grep for `scheduler.` across the repo returns hits only in `internal/scheduler/example_test.go` and `internal/scheduler/doc.go`. No cron expression is registered anywhere in `server/`, `cmd/`, or `store/`.

**What actually runs on a timer:** exactly one background job, and it's a plain `time.Ticker`, not cron — the S3 presign refresher, every 12 hours plus one pass at startup (`server/runner/s3presign/runner.go:27,29-41`, started at `server/server.go:162-171`). There's also a dormant `memopayload.Runner` whose `RunOnce` nothing calls (`server/runner/memopayload/runner.go:27`; see h08).
