**Computation site: `memopayload.RebuildMemoPayload` — `/bench/repo/server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `/bench/repo/internal/markdown/markdown.go:356`**

**Triggers (recomputation happens only where content changes):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before the row is inserted.
- `UpdateMemo`, but *only* on the `content` update path — `server/router/api/v1/memo_service.go:447`, inside the `if path == "content"` branch; the new payload is then written along with the content (`:450-451`). Updating `visibility`, pinned state, etc. leaves the stored payload untouched.
- `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:52`, a batched backfill over every memo (100 at a time) that rewrites each payload. It is dead code in the current tree: nothing constructs the runner (see h08).

**What the computation extracts** — one goldmark AST walk (`markdown.go:370-410`) fills `ExtractedData` (`markdown.go:21-25`), of which `RebuildMemoPayload` stores two fields onto `memo.Payload` (`runner.go:83-84`):

- `Payload.Tags` — every `#tag` node, deduplicated while preserving original case (`markdown.go:377-379, 417`).
- `Payload.Property` (`storepb.MemoPayload_Property`, `proto/gen/store/memo.pb.go:85-95`):
  - `Title` — text of the first block-level H1, if the document starts with one (`markdown.go:387-393`)
  - `HasLink` — any link node (`:396-397`)
  - `HasCode` — code block, fenced code block, or inline code span (`:399-400`)
  - `HasTaskList` — any task checkbox (`:402-403`)
  - `HasIncompleteTasks` — at least one unchecked checkbox (`:404-407`)

Two things deliberately *not* persisted here: `ExtractedData.Mentions` is computed in the same walk (`markdown.go:380-382`) but dropped by `RebuildMemoPayload`, which assigns only `Tags` and `Property` — mentions are handled separately by the notification path (`server/router/api/v1/memo_mention_helpers.go:32`). And the preview *snippet* is not stored at all; it's generated on demand at read time via `getMemoContentSnippet` → `GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-90`), used for relations (`memo_relation_service.go:154,162`) and notifications (`user_service_notifications.go:318-350`).

Note `RebuildMemoPayload` replaces `Payload.Property` wholesale but leaves sibling payload fields (e.g. `Location`) intact — which is why `CreateMemo` sets the location *after* calling it (`memo_service.go:110-112`).
