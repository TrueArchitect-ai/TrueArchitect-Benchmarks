Notes on the hops:

- **Wiring** — the service is constructed and its routes registered at `server/server.go:81-82`; the `/file` group is defined at `fileserver.go:122`.
- **Access control** — before any lookup, `serveUserAvatar` checks `s.Profile.AllowAnonymous()` (`fileserver.go:173`); on a private instance it requires a viewer via `getCurrentUser`, returning 401 otherwise (`fileserver.go:173-181`). On an open instance, any user's avatar is public.
- **Lookup key** — the `:identifier` path param is treated strictly as a username: `getUserByUsername` passes `&store.FindUser{Username: &identifier}` (`fileserver.go:716`).
- **Cache** — `Store.GetUser` only consults `userCache` when the find is by ID (`store/user.go:149-156`); a username lookup always falls through to `ListUsers` → driver → SQL, then populates the cache by ID (`store/user.go:142-144, 167`).
- **The "stored data" is a data URI, not a file** — avatars live in the `user.avatar_url` TEXT column (`store/migration/sqlite/LATEST.sql:20`, selected at `store/db/sqlite/user.go:158`). The handler decodes it with `parseDataURI` (`fileserver.go:196`), rejects MIME types outside `avatarAllowedTypes` (`fileserver.go:75, 201`), sets security + cache headers, and writes the bytes with `c.Blob` (`fileserver.go:205-209`). Empty `AvatarURL` yields 404 (`fileserver.go:192`).
