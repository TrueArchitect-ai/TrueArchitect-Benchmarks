**Premise correction: there is no rate-limiting middleware in this repository — per-user or otherwise. No registration site and no request limits exist to cite.**

What I checked:

- Case-insensitive greps for `rate.?limit`, `ratelimit`, `throttl`, and `burst` across the Go sources return no implementation. The only hits anywhere are aspirational documentation in the email package — a TODO-style bullet at `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") and an illustrative code sample under "### 5. Implement Rate Limiting" at `internal/email/README.md:286-295`. Neither corresponds to shipped code.
- `go.mod` has no rate-limiter dependency (no `golang.org/x/time/rate`, no `ulule/limiter`, etc.).
- The Echo middleware stack is two entries wide — `middleware.Recover()` and `newCORSMiddleware(profile)` at `server/server.go:51-52`. Echo's own `middleware.RateLimiter` is not among them.
- The API's per-request interceptor chain does authentication and authorization only (`NewAuthorizer` / gateway auth middleware, `server/router/api/v1/v1.go:64-70`), with the ACL policy in `server/router/api/v1/acl_config.go`. Nothing counts requests per user.

**What does exist, and is easy to mistake for rate limiting:** concurrency caps on expensive media work, implemented with `semaphore.Weighted`, not request budgets —

- `thumbnailSemaphore`: 3 concurrent thumbnail generations, in both the file server (`server/router/fileserver/fileserver.go:46,116`) and the API service (`server/router/api/v1/v1.go:59`)
- `imageProcessingSemaphore`: 2 concurrent image operations (`server/router/api/v1/v1.go:60`)

These are process-wide, not per-user, and they bound simultaneous in-flight work rather than requests per interval — a slow client is queued, never rejected with a 429. Related but also not rate limiting: the webhook dispatcher's bounded 128-slot queue, which drops events when full (`internal/webhook/webhook.go:39,189-195`).

If you need per-user API limits, they'd have to be added — the natural insertion points are the Echo middleware chain at `server/server.go:51-52` (HTTP-wide) or the shared authorizer/interceptor at `server/router/api/v1/v1.go:64-70`, which already resolves the calling user.
