**`internal/idp` (`/bench/repo/internal/idp/idp.go`); `internal/idp/oauth2` (`/bench/repo/internal/idp/oauth2/oauth2.go`)**

Details:

- **Abstraction** — `internal/idp` is deliberately thin: it defines only the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) at `internal/idp/idp.go:3-8`. That's the common currency every provider implementation must return; there is no Go interface type, so the "abstraction" is this normalized user-info shape plus the `IdentityProvider_Type` enum in the store proto (`proto/gen/store/idp.pb.go:28`, which currently has exactly one non-unspecified value, `OAUTH2 = 1`).
- **Implementation** — `internal/idp/oauth2` is the only concrete protocol package. `oauth2.IdentityProvider` (`internal/idp/oauth2/oauth2.go:20`) is built from a `storepb.OAuth2Config` via `NewIdentityProvider` (`oauth2.go:27`), and provides `ExchangeToken` (`oauth2.go:47`, supporting PKCE via `codeVerifier`) and `UserInfo` (`oauth2.go:83`), which maps the provider's response onto `idp.IdentityProviderUserInfo` using the configured field mapping.
- **Consumer** — the SSO sign-in path constructs it at `server/router/api/v1/auth_service_sso.go:121` (`oauth2.NewIdentityProvider(identityProvider.Config.GetOauth2Config())`), the sole non-test caller.

Since OIDC is expressible as OAuth2 config here, no separate OIDC/SAML package ships.
