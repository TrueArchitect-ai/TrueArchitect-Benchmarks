**`webhook.Post` — `/bench/repo/internal/webhook/webhook.go:120`; SSRF-blocking dialer `safeDialContext` on the shared `safeClient` transport — `/bench/repo/internal/webhook/webhook.go:59` (reserved-range table + `isReservedIP` in `/bench/repo/internal/webhook/validate.go:14-54`)**

How it fits together:

- **Trigger** — memo create/update/delete and comment-created call `DispatchMemo*Webhook` in `server/router/api/v1/memo_service_webhooks.go:15-46`, which builds a payload per user webhook and calls `webhook.PostAsync` (`memo_service_webhooks.go:43,71`).
- **Where delivery executes** — `PostAsync` (`webhook.go:184`) only enqueues onto a bounded 128-slot channel, dropping with a warning if full. The actual HTTP POST happens in `Post` (`webhook.go:120`), run by 4 worker goroutines started in `init()` (`webhook.go:42-55`). `Post` marshals the payload, adds Standard-Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`) when a signing secret is set (`webhook.go:133-150`), then issues `safeClient.Do(req)` (`webhook.go:152`) with a 30s timeout and a 1 MiB response read cap.
- **Primary protection (at dial time)** — `safeClient`'s `http.Transport` uses `DialContext: safeDialContext` (`webhook.go:32-37`). `safeDialContext` (`webhook.go:59-77`) resolves the host itself and refuses to dial if *any* resolved address is reserved. Because the check happens at connection time on the addresses actually used, it also defeats DNS rebinding — noted explicitly in the comment at `webhook.go:30-31`.
- **Secondary protection (at configuration time)** — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user creates/updates a webhook, called from `server/router/api/v1/user_service_webhooks.go:74,161,182`.
- **Blocked ranges** — `reservedCIDRs` (`validate.go:14-23`): IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), plus IPv6 loopback, unique-local, and link-local. Parsed once at init (`validate.go:28-36`).
- **Escape hatch** — the package-level `AllowPrivateIPs` flag (`validate.go:41`) disables both checks for self-hosted setups targeting LAN services. In non-test code it is never assigned anywhere in the repo, so it stays `false` — there's no config or env wiring for it; only the tests flip it (`internal/webhook/webhook_test.go:91,142`).
