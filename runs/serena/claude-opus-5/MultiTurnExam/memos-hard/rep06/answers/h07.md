Notes on the hops:

- **Auth gate before any lookup:** on a private instance (`!s.Profile.AllowAnonymous()`), `serveUserAvatar` requires a viewer via `s.getCurrentUser` and returns 401 otherwise (`server/router/fileserver/fileserver.go:173-181`). On an open instance avatars are anonymously readable — covered by `TestServeUserAvatar_PrivateInstanceRequiresAuth` (`server/router/fileserver/fileserver_test.go:506`).
- **The image bytes never leave the user row.** There is no attachment/blob hop: the avatar is stored inline in `user.avatar_url` as a data URI, and the handler decodes it with `s.parseDataURI(user.AvatarURL)` (`fileserver.go:196`), enforces an allowlist of image MIME types (`avatarAllowedTypes`, `fileserver.go:75`), then writes it with `c.Blob` plus security and cache headers (`fileserver.go:205-209`).
- **Cache layer:** `Store.GetUser` only consults `userCache` when looking up by ID; a username lookup always falls through to `ListUsers` and the DB, then populates the cache keyed by the resulting ID (`store/user.go:148-168`, `:136-146`).
- **Wiring:** the service is constructed and its routes registered at `server/server.go:81-82`.
