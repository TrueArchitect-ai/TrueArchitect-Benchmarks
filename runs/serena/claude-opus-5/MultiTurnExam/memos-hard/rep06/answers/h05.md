**Explicit Go code — two SQL `DELETE` statements per driver inside the delete-user transaction. No database-level rule exists for this.**

Evidence locations:

**1. The explicit deletes.** Each driver's `deleteUserTargetsTx` issues two reaction deletions:

- `deleteReactionsByContentIDsTx` — removes reactions *on* the user's memos (content IDs built as `"memos/"+uid` from the recursive memo tree, including descendant comments): sqlite `store/db/sqlite/user_delete.go:378`, mysql `store/db/mysql/user_delete.go:417`, postgres `store/db/postgres/user_delete.go:380`. Batched at 500 IDs (`deleteUserBatchSize`).
- `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?`, the reactions the user *made* on anyone's content: sqlite `store/db/sqlite/user_delete.go:397`, mysql `store/db/mysql/user_delete.go:437`, postgres `store/db/postgres/user_delete.go:400`.

Both are called at the top of `deleteUserTargetsTx` (sqlite `store/db/sqlite/user_delete.go:95` and `:101`; same lines 96/102 in the mysql and postgres files), before memos and the user row are removed, all inside the single `BeginTx`/`Commit` in `DeleteUser` (`store/db/sqlite/user_delete.go:29-58`). Entry point is `Store.DeleteUser` → `s.driver.DeleteUser` (`store/user.go:171-172`).

**2. Why it can't be a DB rule.** The `reaction` table has no foreign key at all — `creator_id` is a bare `INTEGER NOT NULL` and `content_id` a plain text column, in all three schemas: `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98`, and identically in the original `store/migration/{sqlite,postgres,mysql}/0.20/00__reaction.sql`. A grep for `FOREIGN KEY`/`ON DELETE` across `store/migration/` returns cascades only for `memo_share.memo_id` and for legacy pre-0.5 tables — none referencing `reaction`. `content_id` is a string like `memos/<uid>`, not a numeric FK, so a cascade on it isn't even expressible.

So if the Go code were removed, reactions would be orphaned rather than cleaned up — the correctness burden sits entirely in `user_delete.go`, duplicated across the three drivers.
