**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`; triggers: memo creation and any content update; extracted: `tags` plus the `Property` set — `title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`.**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) ensures `memo.Payload` is non-nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns exactly two things:

```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```

The real work is one goldmark AST walk in `ExtractAll` (`internal/markdown/markdown.go:356-421`). The payload is persisted as JSON on the memo row, so it's stored derived data, not recomputed per read.

**Triggers (production):** only two call sites, both in the memo service —

- `CreateMemo` — `server/router/api/v1/memo_service.go:107-109`, run before `Store.CreateMemo` and before any explicit `Location` is merged in at `:110-112`. This also covers `CreateMemoComment`, which delegates to `s.CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:446-448`, but *only* inside the `if path == "content"` branch of the update mask, so a visibility-only or pinned-only update does not recompute. The refreshed payload is written through via `update.Payload = memo.Payload` (`:451`).

A third, batch recomputation path exists — `(*memopayload.Runner).RunOnce` (`server/runner/memopayload/runner.go:27`), which rebuilds every memo in batches of 100 — but it is dead code: neither it nor `memopayload.NewRunner` has any caller (consistent with h08).

**What gets extracted** (`internal/markdown/markdown.go:379-408`, mirroring `proto/store/memo.proto:7-22`):

- **`tags`** — every `#tag` node, deduplicated with original case preserved via `uniquePreserveCase` (`:417`).
- **`property.title`** — text of the document's first block-level child when it is an H1 heading (`:383-389`).
- **`property.has_link`** — any `KindLink` node.
- **`property.has_code`** — any code block, fenced code block, or code span.
- **`property.has_task_list`** — any task checkbox; **`property.has_incomplete_tasks`** — set additionally when a checkbox is unchecked (`:400-405`).

`ExtractAll` also collects `Mentions` into `ExtractedData` (`internal/markdown/markdown.go:23`), but `RebuildMemoPayload` discards them — mentions are handled separately for notifications rather than stored on the payload.

**Consumers (the "lists/previews" use):** `convertMemoFromStore` copies `memo.Payload.Tags` to the API message and maps the property block through `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:48-49`, `:315`); user tag stats read `memo.Payload.Tags` (`server/router/api/v1/user_service_stats.go:138`, `:254`). Note the list preview `Snippet` is *not* part of this payload — it's computed on the fly per response by `getMemoContentSnippet` (`memo_service_converter.go:76`).
