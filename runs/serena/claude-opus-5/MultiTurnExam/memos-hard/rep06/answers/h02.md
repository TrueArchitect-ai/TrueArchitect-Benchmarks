**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF-blocking dialer `safeDialContext` on the shared `safeClient` transport — `internal/webhook/webhook.go:59` (reserved-range table + `isReservedIP` in `internal/webhook/validate.go:14-54`)**

How it fits together:

**Delivery path.** Memo create/update/delete/comment events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which only enqueues onto a bounded 128-slot channel and drops with a warning when full (`internal/webhook/webhook.go:184-196`). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue, and each calls `Post`. So the actual HTTP request — JSON body, optional Standard Webhooks HMAC-SHA256 signature headers, `safeClient.Do(req)` at `internal/webhook/webhook.go:152` — executes in `Post`, on a worker goroutine, not on the request goroutine.

**Protection.** Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against loopback, RFC-1918, link-local/IMDS `169.254.0.0/16`, and the IPv6 equivalents (`internal/webhook/validate.go:14-23`):

1. *Dial-time* (the one guarding delivery): `safeDialContext` resolves the host and refuses the connection if any resolved address is reserved (`internal/webhook/webhook.go:59-77`). Because this runs per-dial rather than at save time, it also defeats DNS rebinding.
2. *Config-time*: `webhook.ValidateURL` rejects non-http(s) schemes and reserved-resolving hosts when a webhook is created or updated (`internal/webhook/validate.go:62`), called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

One thing worth flagging: the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both layers, but nothing outside `internal/webhook/webhook_test.go` ever assigns it — there's no flag or setting wiring it up, so in a running server it is always `false`.
