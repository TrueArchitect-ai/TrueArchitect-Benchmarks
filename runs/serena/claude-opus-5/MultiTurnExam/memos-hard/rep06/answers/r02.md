**Premise correction: there is no per-user API rate-limiting middleware in this repository. Nothing registers one, and there are no request limits to report.**

What I checked:

- **No rate-limiting code.** A case-insensitive grep for `ratelimit`, `rate limit`, `rate_limit`, `throttle`, and `limiter` across all Go files returns exactly one hit, and it's a prose bullet in a doc comment — "Rate limit email sending to prevent abuse" (`internal/email/doc.go:86`), a suggestion in the package's "Security Considerations" section, not an implementation. Repo-wide (including non-Go files) the only matches are that file and `internal/email/README.md`.
- **No dependency for it.** `go.mod` has no `golang.org/x/time/rate`, no `ulule/limiter`, no `tollbooth`, nor any similar package. Echo's own `middleware.RateLimiter` is never referenced.
- **The middleware chain is two entries long.** `server/server.go:51-52` registers only `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go`). Everything after that is route/service registration — frontend static files (`:72`), the file server (`:81-82`), RSS (`:85`), the gRPC-gateway + Connect handlers (`:88`), and MCP (`:92-95`).
- **The interceptor chain has no limiter either.** The Connect/gateway path installs an authorizer for authentication and anonymous-access policy (`server/router/api/v1/v1.go:66-70`, `server/router/api/v1/connect_interceptors.go`), plus the ACL config in `server/router/api/v1/acl_config.go` — authorization, not throttling.

The closest things that exist are **concurrency caps, not rate limits** — they bound simultaneous in-flight work globally, not requests-per-user-per-interval, and they queue rather than reject:

- `semaphore.NewWeighted(3)` for thumbnail generation and `semaphore.NewWeighted(2)` for image processing on the API service (`server/router/api/v1/v1.go:59-60`).
- `semaphore.NewWeighted(maxConcurrentThumbnails)` on the file server (`server/router/fileserver/fileserver.go:116`).

Also adjacent but distinct: the webhook dispatch queue drops events when its 128-slot buffer is full (`internal/webhook/webhook.go:189-195`) — backpressure on outbound deliveries, unrelated to inbound API requests.
