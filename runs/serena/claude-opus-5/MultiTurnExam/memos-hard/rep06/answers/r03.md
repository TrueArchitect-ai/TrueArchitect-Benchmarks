**Premise correction: there is no nightly database-cleanup job, and nothing at all is scheduled in the cron scheduler — so there is no time to report.**

Two separate corrections are folded into that:

**1. The cron scheduler exists but is entirely unused by the server.** `internal/scheduler` is a complete, self-contained cron implementation — 5-field expression parsing (`internal/scheduler/parser.go`), job registration (`Scheduler.Register`, `internal/scheduler/scheduler.go:70`), lifecycle (`Start`/`Stop`, `scheduler.go:169`), and middleware like `Recovery`, `Logging`, `Timeout` (`internal/scheduler/middleware.go`). But the package is imported from exactly two places, both tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No file under `server/`, `cmd/`, or `store/` imports it, so `scheduler.New` is never called in production and no cron expression is ever registered. `cmd/memos/main.go:89` calls `s.Start(ctx)` on the HTTP `Server`, not on a scheduler.

**2. No database-cleanup job exists in any form.** There's no vacuum, purge, prune, or retention sweep anywhere. Grepping those terms across `server/`, `store/`, and `cmd/` turns up only unrelated matches — attachment-storage cleanup performed inline during user deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`) and cache-eviction naming (`store/store.go:42`, `:73`). Cleanup here is event-driven, done in the request transaction (e.g. `store/db/sqlite/user_delete.go`), not scheduled.

What *is* actually scheduled in this server, for completeness:

- **The S3 presign runner** — the only recurring background job. It uses a plain `time.Ticker` at a fixed 12-hour interval (`server/runner/s3presign/runner.go:27`, loop at `:29`), not a cron expression, so it has no wall-clock time — it fires 12 hours after boot and every 12 hours thereafter, plus one immediate run at startup (`server/server.go:163`). It refreshes presigned attachment URLs; it deletes nothing.
- **Cache cleanup goroutines** — a 5-minute ticker per cache sweeping expired in-memory entries (`store/cache/cache.go:200-215`, interval from `store/store.go:42`). In-process only, no database involvement.
