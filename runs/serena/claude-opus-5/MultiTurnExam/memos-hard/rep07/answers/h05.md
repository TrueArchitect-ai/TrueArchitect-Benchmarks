**Explicit Go code — two `DELETE FROM reaction` statements inside the per-driver `DeleteUser` transaction. There is no database-level rule (no foreign key, no cascade, no trigger) on the `reaction` table.**

What I checked:

**1. The Go delete path.** Each driver implements `DeleteUser` as one transaction whose steps are listed in `deleteUserTargetsTx`. Reactions are removed by two distinct statements:

- `deleteReactionsByContentIDsTx` — `DELETE FROM reaction WHERE content_id IN (...)`, batched at 500 (`store/db/sqlite/user_delete.go:380-388`). This removes reactions *other people* left on the deleted user's memos. Content IDs are built as `"memos/" + memo.UID` (`store/db/sqlite/user_delete.go:512-518`), matching how reactions key off memo resource names.
- `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?` (`store/db/sqlite/user_delete.go:400-403`). This removes reactions the deleted user left on *anyone's* content.

Both are invoked at `store/db/sqlite/user_delete.go:96` and `:102`, before the memo and user rows are deleted (`:120`, `:123`). The memo set they operate on comes from a recursive CTE that also pulls in comment descendants (`store/db/sqlite/user_delete.go:134-147`).

**2. All three drivers do the same thing** — this is not sqlite-only: `store/db/postgres/user_delete.go:96`, `:102`, `:380-403` and `store/db/mysql/user_delete.go:96`, `:102`, `:417-439`.

**3. No database-level rule exists.** The `reaction` table is declared with no foreign keys and no cascade in any dialect: `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98` — each has just `id`, `created_ts`, `creator_id`, `content_id`, `reaction_type`, and a `UNIQUE(creator_id, content_id, reaction_type)`. Grepping `REFERENCES|ON DELETE|FOREIGN KEY|TRIGGER` across `store/migration/` finds cascades only on older/other tables (e.g. `memo_share` at `store/migration/sqlite/LATEST.sql:109`, and historical migrations under `sqlite/0.5/`), never on `reaction`. Even if one existed, SQLite opens with FK enforcement off: `_pragma=foreign_keys(0)` at `store/db/sqlite/sqlite.go:53`.

**4. Test confirmation of the scoping.** `store/test/user_delete_test.go` seeds reactions at `:97-112` and asserts at `:217-220` that a peer's reaction on a *peer's* memo survives — i.e. the deletion is scoped to the user's own reactions plus reactions on the user's own memo tree, not a blanket wipe.
