**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoRelations`, `SetMemoAttachments`; convergence function — `webhook.Post` at `internal/webhook/webhook.go:120` (the actual send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`).**

The six RPC handlers and how each reaches the network:

| Handler | Definition | Dispatch call |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:70` | `DispatchMemoCreatedWebhook` at `memo_service.go:157` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:401` | `dispatchMemoUpdatedSideEffects` at `memo_service.go:513` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:518` | `DispatchMemoDeletedWebhook` at `memo_service.go:562` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` at `memo_service_comments.go:119` |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:16` | `dispatchMemoUpdatedSideEffects` at `memo_relation_service.go:48` |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:16` | `dispatchMemoUpdatedSideEffects` at `memo_attachment_service.go:48` |

The last three of those "update" paths share a helper: `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`) calls `DispatchMemoUpdatedWebhook` at `memo_update_helpers.go:67` — so `SetMemoRelations` and `SetMemoAttachments` fire memo-updated webhooks even though neither is named "update."

Path to the wire: the create/update/delete variants all funnel through `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which loads the creator's configured webhooks via `s.Store.GetUserWebhooks` and sets `payload.URL = hook.Url` (`:57-68`). The comment variant does the same but targets the *related memo owner's* webhooks (`memo_service_webhooks.go:30-44`) — a user's configured URL can be hit by another user's action. Both then call `webhook.PostAsync` (`:43`, `:71`), which enqueues onto a 128-slot channel drained by four goroutines started in `init()` (`internal/webhook/webhook.go:39-55`). Those workers call **`webhook.Post`** — the single function where every path converges before delivery, and where the request is built, optionally HMAC-signed, and executed.

Two notes on scope: the URL is user-configured through `CreateWebhook`/`UpdateWebhook` (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`), but those handlers only validate — they perform a DNS lookup, not an HTTP request, so they're not on this list. Separately, `GetLinkMetadata` and `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go:14`, `:19`) do make outbound HTTP calls via `fetchHTMLMeta` → `httpgetter.GetHTMLMeta` (`memo_service.go:28`), but to a URL supplied per-request rather than a stored/configured one, and they don't touch `webhook.Post`.
