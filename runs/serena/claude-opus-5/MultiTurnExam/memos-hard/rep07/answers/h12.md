**Determination method, step by step:**

1. **Establish the default.** With no flags, `Driver` comes from viper: `viper.SetDefault("driver", "sqlite")` at `cmd/memos/main.go:122` and the flag default `rootCmd.PersistentFlags().String("driver", "sqlite", …)` at `cmd/memos/main.go:130`. It's read into the profile at `cmd/memos/main.go:43`. (Env override `MEMOS_DRIVER` is possible via `SetEnvPrefix("memos")`/`AutomaticEnv` at `cmd/memos/main.go:167-169`, but that's not a default install.) `Profile.Validate` then derives the sqlite DSN `memos_prod.db` under the data dir — `internal/profile/profile.go:110-117` — which only fires for `Driver == "sqlite"`, corroborating the default.

2. **Resolve the one candidate the factory selects.** `db.NewDBDriver` is called once at `cmd/memos/main.go:57`; its `switch profile.Driver` (`store/db/db.go:18-27`) picks `sqlite.NewDB(profile)` for `"sqlite"`. This is the only place a driver is constructed, so exactly one of the three implementations is live per process — the mysql/postgres `CreateMemo` methods are compiled but never reached.

3. **Follow the write path to the interface boundary.** The API handler calls `s.Store.CreateMemo` at `server/router/api/v1/memo_service.go:115` (the only non-test caller). `Store.CreateMemo` validates the UID and delegates to `s.driver.CreateMemo` at `store/memo.go:113`. `driver` is the `store.Driver` interface (`store/driver.go:10`), holding the concrete value chosen in step 2.

4. **Land on the concrete method.** For sqlite that's `store/db/sqlite/memo.go:16`, which builds the column/placeholder lists, marshals the payload to JSON, and executes the statement via `QueryRowContext` with `RETURNING id, created_ts, updated_ts, row_status` (`store/db/sqlite/memo.go:41-47`). The parallel implementations that do *not* run are `store/db/postgres/memo.go` and `store/db/mysql/memo.go` (the MySQL one differs materially — no `RETURNING` support, so it uses `LastInsertId`).
