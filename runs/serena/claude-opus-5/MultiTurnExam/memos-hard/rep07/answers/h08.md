Two types declare `RunOnce`, both in `server/runner/`:

```
*s3presign.Runner.RunOnce  — server/runner/s3presign/runner.go:43  — YES — server/server.go:163 (and self-call from Run, server/runner/s3presign/runner.go:36)
*memopayload.Runner.RunOnce — server/runner/memopayload/runner.go:27 — NO  — no caller anywhere (production or test)
```

Evidence:

- `grep -rn "RunOnce" --include=*.go .` returns exactly five lines repo-wide: the two declarations above, plus three call sites — `server/server.go:163`, `server/runner/s3presign/runner.go:36`, and the s3presign declaration itself. No `_test.go` file references `RunOnce` at all.

- **s3presign — invoked.** `startBackgroundRunners` constructs the runner and calls `RunOnce(ctx)` synchronously at `server/server.go:163`, then launches the ticker loop (`server/server.go:166-171`), whose `Run` re-enters `RunOnce` every 12 hours at `server/runner/s3presign/runner.go:36`.

- **memopayload — not invoked.** Beyond `RunOnce` having no callers, the whole runner is unreachable: `memopayload.NewRunner` (`server/runner/memopayload/runner.go:19`) has zero call sites, and the only thing the package is imported for is the package-level helper `RebuildMemoPayload`, used at `server/router/api/v1/memo_service.go:108` and `:447`. So the `Runner` struct, its constructor, and `RunOnce` are dead code — the payload-rebuild logic they'd batch over all memos is instead applied per-memo inline on create/update. There is also no interface in the repo requiring a `RunOnce` method that would make it reachable indirectly.
