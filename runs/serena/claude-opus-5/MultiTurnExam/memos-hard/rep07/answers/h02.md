**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); SSRF protection via a dial-time reserved-IP block, `safeDialContext` — `internal/webhook/webhook.go:59`, backed by `isReservedIP`/`reservedCIDRs` — `internal/webhook/validate.go:14-54`.**

How it fits together:

- **Delivery path**: memo create/update/delete builds a payload and calls `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`). That enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:39`, dropping with a warning if full, `:189-195`); four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it and call `Post`. So `Post` is where the outbound HTTP request is built, optionally HMAC-signed per Standard Webhooks (`:133-150`), and executed.

- **Primary protection**: all dispatches go through the shared `safeClient` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). At dial time it re-resolves the host and refuses the connection if *any* returned IP is in a reserved range (`:65-74`). Because the check happens at dial rather than at URL-registration time, it also defeats DNS rebinding. Blocked ranges cover IPv4 loopback, RFC-1918, link-local incl. `169.254.169.254` (cloud IMDS), and the IPv6 equivalents (`internal/webhook/validate.go:14-23`).

- **Secondary check**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a user registers/updates a webhook URL — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182` — enforcing http/https scheme and rejecting hostnames resolving to reserved IPs. This is defense-in-depth for good error messages; it's TOCTOU-prone on its own, which is why the dial-time check exists.

One thing worth flagging: the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both checks when true, but I found no code that ever sets it — no flag, env var, or config wiring anywhere in the repo. It's effectively hardcoded `false` today.
