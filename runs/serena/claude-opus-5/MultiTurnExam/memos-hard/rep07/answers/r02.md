**Premise correction: there is no per-user API rate-limiting middleware in this repository, so there is no registration site and no request limits to report.**

Evidence:

- A case-insensitive search for `ratelimit`, `rate_limit`, `rate limit`, `limiter`, and `throttl` across all Go sources returns exactly one hit, and it's a comment in unrelated documentation: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") — an aspirational security note, not an implementation. The same search over TS/TSX/Markdown/config finds only `internal/email/README.md:286-295`, a suggested code snippet in a "things you could implement" section.

- The actual Echo middleware stack is short and contains no limiter: `middleware.Recover()` and the CORS middleware at `server/server.go:51-52`, static-file and SPA-fallback middleware at `server/router/frontend/frontend.go:54-59`. The API layer adds authentication/authorization only — the gateway auth middleware and Connect interceptor built around `NewAuthorizer` in `server/router/api/v1/v1.go:95` and following. Nothing counts requests per user, per IP, or per token.

- No rate-limiting dependency is present either; `go.mod` has no `golang.org/x/time/rate`, `ulule/limiter`, or similar, and Echo's own `middleware.RateLimiter` is never referenced.

What does exist, and may be what the question is reaching for, are **concurrency caps** — not rate limits. These bound how many operations run *simultaneously*, with no per-user dimension and no request rejection (callers block until a slot frees):

- `thumbnailSemaphore` — 3 concurrent thumbnail generations, `server/router/api/v1/v1.go:59` and `server/router/fileserver/fileserver.go:116` (`maxConcurrentThumbnails = 3`, `fileserver.go:46`).
- `imageProcessingSemaphore` — 2 concurrent image operations, `server/router/api/v1/v1.go:60`.

There are also unrelated bounded queues, such as the 128-slot webhook dispatch channel drained by four workers (`internal/webhook/webhook.go:39-55`), which drops overflow rather than throttling callers. None of these constitute API rate limiting.
