**`internal/idp` (abstraction); `internal/idp/oauth2` (the one concrete implementation).**

Details:

- **Abstraction**: `internal/idp/idp.go` — the package is deliberately minimal. It defines only the shared result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) at `internal/idp/idp.go:3-8`. There is no Go interface here; the "abstraction" is this common user-info struct plus the protobuf-level provider model in `proto/store/idp.proto` (`IdentityProvider.Type` enum and a `oneof config`, `proto/store/idp.proto:11-22`), which is what makes room for future provider types.

- **Implementation**: `internal/idp/oauth2/oauth2.go` — OAuth2, with `NewIdentityProvider` validating required config (`:27-43`), `ExchangeToken` doing the code-for-token exchange including optional PKCE `code_verifier` (`:47-80`), and `UserInfo` fetching the userinfo endpoint and mapping claims onto `idp.IdentityProviderUserInfo` via the configured field mapping (`:83-141`).

- **Dispatch**: `server/router/api/v1/auth_service_sso.go:119-133` switches on the stored provider type; the only branch is `storepb.IdentityProvider_OAUTH2`. Correspondingly, the enum has just one non-unspecified value, `OAUTH2 = 1` (`proto/store/idp.proto:13`, generated at `proto/gen/store/idp.pb.go:28`). Note that because the type check is an `if` rather than an exhaustive switch with a default, an unknown provider type would leave `userInfo` nil and then be dereferenced downstream at `auth_service_sso.go:141` — unreachable today since OAUTH2 is the only writable type.
