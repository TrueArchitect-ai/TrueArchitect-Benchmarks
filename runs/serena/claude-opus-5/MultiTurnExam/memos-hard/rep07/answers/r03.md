**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never started by the server — so there is no scheduled time to report.**

Two separate corrections are folded into that:

**1. No database-cleanup job exists.** Searching for `nightly`, `cleanup job`, `vacuum`, and `purge` across the Go sources turns up nothing resembling a scheduled database maintenance task. The only `cleanup` machinery in the backend is the in-memory cache's expiry sweep — `Cache.cleanupLoop`/`cleanup` at `store/cache/cache.go:200-215` and `:218` — which runs on a 5-minute `time.Ticker`, not cron, and evicts map entries rather than touching the database.

**2. The cron scheduler is unused code.** `internal/scheduler` is a complete, well-tested cron implementation — `Scheduler.Register` (`internal/scheduler/scheduler.go:70`), `Job.Schedule` cron strings (`internal/scheduler/job.go:21`), a 5-field parser (`internal/scheduler/parser.go`), and middleware (`internal/scheduler/middleware.go`) — but nothing outside the package imports it. `grep -rn "internal/scheduler"` matches only the package's own `example_test.go:10` and `integration_test.go:13`. No production file constructs a `Scheduler` or registers a job.

If a cron string caught your eye, the two in the tree are illustrative only: `"0 * * * *" (hourly), "0 0 * * *" (daily at midnight)` as doc-comment examples at `internal/scheduler/job.go:21`, and `Schedule: "0 2 * * *", // 2 AM daily` inside a commented-out usage example at `internal/scheduler/doc.go:16`. That "2 AM daily" line is documentation of the API, not a registered job.

For completeness, the one background job the server actually runs is not cron-driven: the S3 presign runner, started at `server/server.go:162-171`, which does an immediate pass at startup and then re-signs on a fixed 12-hour `time.Ticker` (`server/runner/s3presign/runner.go:27`, `:29-41`).
