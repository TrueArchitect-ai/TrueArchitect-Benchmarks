**Delivery function: `webhook.Post` — `internal/webhook/webhook.go:120` (invoked off the async queue by `PostAsync` → the 4 worker goroutines in `init`, `internal/webhook/webhook.go:42-55`, 184-196); protection: SSRF guard at dial time via `safeDialContext` on the shared `safeClient` transport — `internal/webhook/webhook.go:59-77` (with `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go:14-54`)**

How it fits together:

- **Trigger**: memo create/update/delete paths call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which enqueues onto a bounded 128-slot channel and drops with a warning if full (`internal/webhook/webhook.go:189-195`). Four background workers drain that queue and call `Post`.
- **Actual outbound HTTP**: `Post` marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, `webhook.go:133-150`), and executes the request with `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. The response body is read through a 1 MiB `io.LimitReader` (`webhook.go:158`) and the client has a 30s timeout (`webhook.go:27`, `:33`).
- **The protection**: `safeClient`'s `http.Transport` uses `safeDialContext` (`webhook.go:32-37`), which resolves the host itself and refuses to dial if *any* resolved IP falls in a reserved range (`webhook.go:59-77`). Because the check happens at dial time rather than at URL-parse time, it also covers redirects and DNS-rebinding, where the name resolves benignly during validation and to an internal address later.
- **Blocked ranges**: loopback, RFC-1918, link-local incl. the cloud IMDS address `169.254.169.254`, plus IPv6 loopback/ULA/link-local — `internal/webhook/validate.go:14-23`, parsed once at init (`validate.go:28-36`).
- **Second, earlier layer**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-IP targets when a webhook is created or updated, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. This is an up-front UX check; the dial-time guard is what actually protects delivery.
- **Escape hatch**: `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted setups. Note that nothing in the repo currently assigns it — it has no flag or config wiring, so it stays at its `false` zero value in practice.
