**Premise correction: there is no GraphQL in this repository.** No `graphql`/`gqlgen` dependency in `go.mod` or the frontend `package.json`, and no `.graphql`/`.gql` schema files anywhere. Nothing to point at.

**Actual API surface: Protocol Buffers.** The schema of record is the set of `.proto` files under `proto/api/v1/`:

`ai_service.proto`, `attachment_service.proto`, `auth_service.proto`, `common.proto`, `idp_service.proto`, `instance_service.proto`, `memo_service.proto`, `shortcut_service.proto`, `user_service.proto` — with persistence-side messages in `proto/store/`. Code generation is driven by buf (`proto/buf.gen.yaml`, `proto/buf.yaml`) into `proto/gen/`.

Those definitions are exposed over three HTTP surfaces, all registered in `server/router/api/v1/v1.go`:

1. **REST/JSON via grpc-gateway** — eight `Register<X>ServiceHandlerServer` calls onto a `runtime.ServeMux` (`server/router/api/v1/v1.go:95-119`), mounted at `/api/v1/*` and `/file/*` (`:126-128`), with auth applied by `gatewayAuthMiddleware` (`:69`, `:96`).
2. **Connect RPC** (the browser client's transport, replacing grpc-web) — mounted at `/memos.api.v1.*` (`server/router/api/v1/v1.go:144`) behind the metadata/logging/recovery/auth interceptor chain (`:133-137`).
3. **SSE** for live updates — `RegisterSSERoutes` (`server/router/api/v1/v1.go:124`).

For machine-readable docs, an **OpenAPI** spec is generated from the protos and embedded in the binary: `proto/gen/openapi.yaml`, exposed via `proto.OpenAPIYAML()` (`proto/openapi_embed.go:5-12`). The MCP router also consumes it (`server/router/mcp/openapi.go`) to describe a subset of tools (`server/router/mcp/catalog.go`).

Non-proto HTTP surfaces exist alongside these but aren't part of the RPC API: the file server (`server/router/fileserver/`), RSS feeds (`server/router/rss/`), and frontend/sitemap routes (`server/router/frontend/`).
