**Premise correction: there is no per-user API rate-limiting middleware in this repository — nothing to register and no request limits to report.**

Evidence:

- A case-insensitive grep for `ratelimit` / `rate_limit` / `rate limit` / `throttl` / `limiter` across all Go sources (excluding generated code) returns exactly one hit, and it's aspirational prose in a doc comment: "Rate limit email sending to prevent abuse" — `internal/email/doc.go:86`.
- `go.mod` has no rate-limiting dependency (no `golang.org/x/time/rate`, no `echo` middleware limiter, no token-bucket library).
- The full middleware/interceptor stack is short and contains no limiter: Echo registers only `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/server.go:51-52`); the Connect stack is `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` (`server/router/api/v1/v1.go:133-137`); the grpc-gateway path adds only `gatewayAuthMiddleware` for auth (`server/router/api/v1/v1.go:69`, `:97`).
- There's also no login-attempt lockout or failed-attempt counter anywhere in `server/` or `internal/`.

What does exist — related but categorically different, since none of it is per-user or time-windowed:

| Control | Value | Path |
|---|---|---|
| Max request body size | 256 MiB | `server/router/api/v1/v1.go:20`, enforced at `:126`, `:141`, `:144` |
| Concurrent thumbnail generation (global semaphore) | 3 | `server/router/fileserver/fileserver.go:45-46`, `:116`; also `server/router/api/v1/v1.go:59` |
| Concurrent image processing (global semaphore) | 2 | `server/router/api/v1/v1.go:60` — returns `ResourceExhausted` "too many image processing requests" at `server/router/api/v1/attachment_service.go:160` |
| Per-request batch-size caps | e.g. `maxBatchDeleteAttachments`, `maxBatchGetUsers`, `maxBatchGetLinkMetadata` | `attachment_service.go:355`, `user_service.go:145`, `memo_service_link_metadata.go:24`, `instance_service.go:78` |
| Webhook dispatch queue | 128 slots, 4 workers, drops when full | `internal/webhook/webhook.go:39`, `:42-55`, `:189-195` |

The semaphores bound *simultaneous* work process-wide to protect memory; they don't limit request rate and don't distinguish users. If per-user rate limiting is a requirement, it would need to be added — the natural insertion point is a new Connect interceptor in the list at `server/router/api/v1/v1.go:133-137`, plus the Echo/gateway paths, since not all traffic flows through Connect.
