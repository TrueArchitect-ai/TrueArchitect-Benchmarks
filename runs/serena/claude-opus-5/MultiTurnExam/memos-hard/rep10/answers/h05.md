**Explicit Go code — two `DELETE FROM reaction` statements inside the `DeleteUser` transaction, implemented identically in all three drivers. There is no database-level cascade for reactions.**

What I checked:

**1. The delete path.** `DB.DeleteUser` opens a transaction, collects targets, and runs `deleteUserTargetsTx` (`store/db/sqlite/user_delete.go:29-59`). That function issues two separate reaction deletes:
- `deleteReactionsByContentIDsTx` (`store/db/sqlite/user_delete.go:96`, defined at `:380-383`) — `DELETE FROM reaction WHERE content_id IN (...)`, removing *everyone's* reactions on the deleted user's memos (content IDs come from the memo tree collected at `:64-67`).
- `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:102`, defined at `:400-401`) — `DELETE FROM reaction WHERE creator_id = ?`, removing the deleted user's own reactions on *other* people's memos.

Both run before the commit at `store/db/sqlite/user_delete.go:51`, so the cleanup is atomic with the user removal.

**2. All three drivers do the same thing**, at matching line numbers:
- MySQL — `store/db/mysql/user_delete.go:96`, `:102`, definitions at `:417-420` and `:437-438`
- Postgres — `store/db/postgres/user_delete.go:96`, `:102`, definitions at `:380-383` and `:400-401`

**3. The schema has no cascade to lean on.** The `reaction` table declares `creator_id INTEGER NOT NULL` and `content_id` with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint — no foreign key at all: `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98`.

**4. Confirmed by grepping the whole migration tree** for `FOREIGN KEY` / `ON DELETE CASCADE`: the only cascades in the current schema are `memo_share.memo_id → memo(id)` (`store/migration/sqlite/LATEST.sql:109` and the postgres/mysql equivalents at `:108`). Older `user`-referencing cascades exist only in historical migrations (e.g. `store/migration/sqlite/0.5/00__regenerate_foreign_keys.sql`), and none of them covered `reaction`. Note also that `content_id` is a memo *UID* string, not an integer FK, so a cascade on it isn't possible as modeled.
