**Premise correction: there is no Redis in this repo.** Grepping for `redis` (case-insensitive) across `go.mod`, `go.sum`, all Go/TS sources, and YAML configs returns zero hits — no client dependency, no connection settings, no compose service. The cache layer is entirely in-process.

**Actual mechanism.** Caching is a hand-rolled, thread-safe in-memory cache in `store/cache/cache.go`:

- `Interface` (`store/cache/cache.go:11-32`) defines `Set` / `SetWithTTL` / `Get` / `Delete` / `Clear` / `Size` / `Close`; `Cache` (`:66`) implements it over a `sync.Map` plus an atomic item counter — process-local, so nothing is shared between instances.
- Three separate cache instances live on the `Store`: `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:27-29`), all constructed in `store.New` (`store/store.go:50-53`).

**TTL for user entries: 10 minutes.** The config built in `store.New` (`store/store.go:40-45`) sets `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`. Every user write goes through `Cache.Set` (`store/user.go:98, 122, 132, 143, 167`), and `Set` delegates to `SetWithTTL` using exactly that default (`store/cache/cache.go:93-95`), stamping `expiration: time.Now().Add(ttl)` (`:110-114`). Nothing calls `SetWithTTL` with a custom duration for users, so 10 minutes applies uniformly. The same values are duplicated in `cache.DefaultConfig()` (`store/cache/cache.go:56-63`), though `store.New` builds its own literal rather than calling it.

Two behaviors worth knowing:

- Entries can be evicted **before** the TTL: when the count exceeds `MaxItems` (1000), `cleanupOldest` drops the oldest entries (`store/cache/cache.go:117-118`). A background `cleanupLoop` also sweeps expired items every 5 minutes (`store/cache/cache.go:199`).
- The user cache is keyed by ID only — `userCacheKey(userID)` (`store/user.go:88`) — so `Store.GetUser` consults it only when `find.ID != nil` (`store/user.go:149-156`); username/email lookups always hit the database. Deletion invalidates explicitly at `store/user_delete.go:40`, and all three caches are closed on shutdown via `Store.Close` (`store/store.go:74-76`).
