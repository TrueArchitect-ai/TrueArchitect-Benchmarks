**`internal/idp` (abstraction); `internal/idp/oauth2` (the one concrete implementation)**

- **Abstraction**: `internal/idp/idp.go` defines package `idp`, whose entire surface is the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) — the common shape every provider must produce. It's a shared data contract rather than a Go `interface`; there is no `IdentityProvider` interface type in the package.
- **Implementation**: `internal/idp/oauth2/oauth2.go` — package `oauth2`, "implements the OAuth2 identity provider integration". Its `IdentityProvider` wraps a `storepb.OAuth2Config`, and `NewIdentityProvider` (line 26) requires `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier`. It exposes `ExchangeToken` (with optional PKCE `code_verifier`, line ~45) and `UserInfo`, the latter mapping the provider's JSON response into `idp.IdentityProviderUserInfo` via the configured field mapping.
- **It's the only one**: the stored provider type enum has exactly one non-unspecified value, `IdentityProvider_OAUTH2` (`proto/gen/store/idp.pb.go:26-29`), and the SSO login path branches on just that single case — `server/router/api/v1/auth_service_sso.go:120-133` constructs an `oauth2.NewIdentityProvider` and no other kind. OIDC-style providers are configured through the same generic OAuth2 config (auth/token/userinfo URLs plus field mapping) rather than a separate package.
