**1st: `store.User` — ~7 packages outside `store/`; 2nd: `store.Memo` — ~6 packages**

Method: I listed the struct types declared in `store/*.go`, then for each entity counted the distinct packages (directories) outside the whole `store/` tree that reference `store.<Type>` (word-boundary matched, so `store.User` doesn't absorb `store.UserSetting`/`store.FindUser`; generated `proto/gen` excluded).

**`store.User`** (declared `store/user.go:43`) — 7 packages:
`server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`. It's the widest because authentication (`server/auth`), file serving (`server/router/fileserver/fileserver.go:715`), SSR/meta rendering, and RSS all need the user record independently of the API service.

**`store.Memo`** (declared `store/memo.go`) — 6 packages:
`server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`. It reaches one package `User` doesn't (`server/runner/memopayload`) but misses `server/auth` and `server/router/fileserver`.

Third is `store.Attachment` at 4 (`server/router/api/v1`, `.../v1/test`, `server/router/fileserver`, `server/router/rss`).

Two caveats on the counting:

- If you exclude the test package `server/router/api/v1/test`, the ranking is unchanged: `User` 6, `Memo` 5.
- If "outside that layer" means only outside the `store` package proper (counting the driver packages `store/db/{sqlite,mysql,postgres}` and `store/test` as consumers), every count rises by 4 and the order still holds: `User` 11, `Memo` 10, `Attachment` 8.
- `UserSetting`, `InstanceSetting`, and `IdentityProvider` score 0 outside the layer — not because they're unused, but because callers consume the protobuf forms (`storepb.UserSetting`, etc.) rather than the store structs.
