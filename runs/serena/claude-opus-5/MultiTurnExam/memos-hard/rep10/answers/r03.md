**Premise correction: there is no nightly database-cleanup job, and the cron scheduler isn't wired into the running server at all — so there's no scheduled time to report.**

Two separate parts of the premise fail:

**1. No cleanup job exists.** Grepping `server/`, `store/`, and `internal/` for `cleanup` / `vacuum` / `purge` / `prune` turns up nothing resembling a scheduled DB maintenance task. The hits are all unrelated:
- In-memory cache expiry — `store/cache/cache.go:201-210` (`cleanupLoop`, a 5-minute ticker per cache instance, `CleanupInterval` set at `store/store.go:42`). That's process memory, not the database.
- Synchronous, request-triggered deletion inside handlers — attachment storage cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`), relation/attachment cleanup on memo delete (`server/router/api/v1/memo_service.go:579`), and best-effort SSO row removal (`server/router/api/v1/auth_service_sso.go:76`).

**2. The cron scheduler is dead code in production.** `internal/scheduler` does implement cron-expression parsing and scheduling (`internal/scheduler/parser.go`, `internal/scheduler/scheduler.go`, `internal/scheduler/job.go`), but the only files importing it are its own tests — `internal/scheduler/integration_test.go` and `internal/scheduler/example_test.go`. No production file constructs a scheduler or registers a job, so no cron expression is ever evaluated at runtime.

**What actually runs on a schedule.** Exactly one background job, and it isn't cleanup: the S3 presign runner. It's started in `Server.startBackgroundRunners` (`server/server.go:162-171`) — one immediate `RunOnce` at startup, then a `time.Ticker` every **12 hours** (`runnerInterval`, `server/runner/s3presign/runner.go:27`). It refreshes expiring presigned attachment URLs; it deletes nothing. There is also a `memopayload.Runner.RunOnce` batch job (`server/runner/memopayload/runner.go:27`) that rebuilds memo payloads, but nothing constructs it, so it never executes either.
