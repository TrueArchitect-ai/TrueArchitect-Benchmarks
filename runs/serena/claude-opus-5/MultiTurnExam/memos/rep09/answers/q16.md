`Store.DeleteMemo` (`store/memo.go:140-159`) removes, in order, before calling `s.driver.DeleteMemo`:

1. **`memo_relation` rows where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **`memo_relation` rows where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **`attachment` rows linked to the memo** — listed then deleted one by one (`store/memo.go:148-157`); each `Store.DeleteAttachment` (`store/attachment.go:132-149`) also removes the underlying stored file/blob via `DeleteAttachmentStorage` before the DB row.

Two things happen at the API layer rather than in the store, worth noting: `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) first deletes all **comment memos** by recursing into `Store.DeleteMemo` for each `MemoRelationComment` relation (lines 567–577), and it only *reads* reactions (lines 545–550) for the webhook payload — reaction rows are not deleted on this path.
