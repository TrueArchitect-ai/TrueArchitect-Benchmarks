**Engine: CEL (Google Common Expression Language) via `github.com/google/cel-go`, wrapped by the in-repo memo filter engine at `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go:111`)**

**Mechanism:** a three-phase pipeline — cel-go parses the expression against the memo-specific CEL environment declared in `internal/filter/schema.go` (only schema-declared fields are allowed), `internal/filter/parser.go` normalizes the CEL AST into a dialect-agnostic IR (`internal/filter/ir.go`), and `internal/filter/render.go` walks that IR to emit a dialect-specific SQL fragment plus placeholder args, which the driver splices into its `WHERE` clause.

Supporting detail:
- Drivers call it through the helper `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect…, &where, &args)` — e.g. `store/db/sqlite/memo.go:57-61`, with the same pattern in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`.
- Dialect differences are encapsulated in the renderer's `DialectSQLite` / `DialectMySQL` / `DialectPostgres` switches (`internal/filter/render.go`, e.g. lines 231–237, 452–464): `?` vs `$n` placeholders, `JSON_EXTRACT`/`->>` JSON access, `LIKE` vs `ILIKE`, and tag membership as `LIKE` (SQLite) / `JSON_CONTAINS` (MySQL) / `@>` (Postgres).
- Package overview and examples: `internal/filter/README.md`.
