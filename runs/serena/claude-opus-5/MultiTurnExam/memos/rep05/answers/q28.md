**Runners the server actually starts** (`Server.startBackgroundRunners`, `/bench/repo/server/server.go:152-173`):

s3presign.Runner — time.Ticker every 12h, plus one immediate RunOnce at startup; cancelled via per-runner context on shutdown — server/runner/s3presign/runner.go:27-45, server/server.go:161-171

email async dispatch pool — 2 goroutines started in package init(), draining a buffered channel (cap 128); event-driven — internal/email/email.go:14-22

SSE per-connection heartbeat — time.Ticker per open stream, lives for the request — server/router/api/v1/sse_handler.go:64

The only entry in `startBackgroundRunners` is s3presign; the others are started implicitly (package `init()`, constructors, per-request) rather than by the server's runner wiring. Ad-hoc one-shot goroutines also exist, e.g. `recordPATUsage` (`server/auth/authenticator.go:180`).

**Unused infrastructure:**
- `internal/scheduler/` — a full cron-style scheduler (parser, jobs, middleware, README) with zero non-test importers anywhere in the repo; nothing in the server constructs or runs it.
- `server/runner/memopayload/` — the `Runner`/`RunOnce` type is never instantiated (`memopayload.NewRunner` has no callers). Only its standalone helper `RebuildMemoPayload` is used, called inline from `APIV1Service.CreateMemo` and `UpdateMemo` (`server/router/api/v1/memo_service.go:108,447`). So the package's *runner* half is dead scheduling infra, while the payload-rebuild function is live.
