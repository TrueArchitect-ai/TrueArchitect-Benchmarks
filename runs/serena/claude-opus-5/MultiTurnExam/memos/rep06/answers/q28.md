Runners the server actually starts (all from `Server.startBackgroundRunners`, `server/server.go:153-174`):

```
s3presign.Runner — RunOnce at startup, then a 12h time.Ticker loop in a goroutine
in-memory cache cleanup loop — periodic time.Ticker (CleanupInterval), started per Cache instance
SSE heartbeat ticker — per connected SSE client, sseHeartbeatInterval
```

- **s3presign** — `s3presign.NewRunner(s.Store)` is called at `server/server.go:161`; `RunOnce(ctx)` runs it immediately (:162), then `Run(s3Context)` loops on `time.NewTicker(runnerInterval)` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27-30`). It re-presigns S3 attachment URLs whose last presign is older than ~4 days (:88). Cancelled via the stored cancel func on shutdown (`server/server.go:175-`).
- **cache cleanup** — `cleanupLoop` at `store/cache/cache.go:200-201`, a goroutine per `Cache` created by the store; drives TTL eviction, not application work.
- **SSE heartbeat** — `server/router/api/v1/sse_handler.go:64`, one ticker per live client connection to keep the stream open.

**Unused infrastructure note:** `server/runner/memopayload` has a full `Runner` type with `NewRunner` and `RunOnce` (`server/runner/memopayload/runner.go:19,27`) for backfilling memo payloads, but nothing ever constructs it — `server/server.go` never imports the package, and the only import anywhere (`server/router/api/v1/memo_service.go:18`) uses just the standalone helper `RebuildMemoPayload` (:74) inline during Create/Update. So that runner is dead scheduling infrastructure as far as the running server is concerned.

Also worth noting: there is no cron/scheduler library in the project (no `robfig/cron` or similar in `go.mod`) — everything is plain `time.Ticker` plus goroutines.
