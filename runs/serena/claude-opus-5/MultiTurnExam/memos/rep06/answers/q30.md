- updated — `dispatchMemoUpdatedSideEffects`, `server/router/api/v1/memo_update_helpers.go:67` (reached from `UpdateMemo`, `SetMemoRelations`, `SetMemoAttachments`)
- deleted — `APIV1Service.DeleteMemo`, `server/router/api/v1/memo_service.go:562` (dispatched *before* the row is removed, so the payload is still complete)
- comment.created — `APIV1Service.CreateMemoComment`, `server/router/api/v1/memo_service_comments.go:119`, targeting the parent memo owner's hooks

**Convergence:** the first three share the helper `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:47`), which differs only by activity-type string; the comment variant duplicates that loop against the parent creator's hooks. All four then enqueue via **`webhook.PostAsync` (`internal/webhook/webhook.go:184`)**, which hands the payload to a bounded async queue (dropping with a warning if full) whose workers call **`webhook.Post` (`internal/webhook/webhook.go:118`)** — the single place that marshals the JSON, applies the HMAC-SHA256 Standard Webhooks signature headers, and performs the HTTP POST.
