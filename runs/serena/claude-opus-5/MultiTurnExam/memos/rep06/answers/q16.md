In `Store.DeleteMemo` (`store/memo.go:140-159`), before the final `driver.DeleteMemo` (the `DELETE FROM memo` at e.g. `store/db/sqlite/memo.go:237`):

2. **memo_relation rows where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **attachment rows linked to the memo** — listed via `FindAttachment{MemoID}` and deleted one by one (`store/memo.go:149-157`); each `Store.DeleteAttachment` also removes the backing blob from storage (local file or S3) before the row (`store/attachment.go:132-148`)

The API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) additionally deletes **child comment memos** first — it lists `memo_relation` rows of type comment pointing at this memo and calls `Store.DeleteMemo` on each (lines 567-577), which recursively applies the same relation/attachment cleanup.

Note: reactions and memo_share rows are only *read* here (for the webhook payload); no explicit delete of those is done in this path.
