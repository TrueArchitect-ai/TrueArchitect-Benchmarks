**CEL (Common Expression Language) via `github.com/google/cel-go`, wrapped by the in-repo engine at `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`); each dialect driver calls `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)`, which parses the CEL expression against the memo schema, normalizes it into a dialect-agnostic IR, and renders that IR into a dialect-specific SQL fragment plus bound args that are appended to the query's WHERE clause.**

The three phases (documented in `internal/filter/README.md:1-21`):
1. **Parse** — `Engine.Compile` runs `cel-go`'s `env.Compile` (`internal/filter/engine.go:52`) against the memo-specific environment declared in `internal/filter/schema.go`, so only schema-known fields are accepted.
2. **Normalize** — `internal/filter/parser.go` converts the CEL AST into the IR defined in `internal/filter/ir.go`, enforcing type/operator rules.
3. **Render** — `internal/filter/render.go` walks the IR per `DialectName` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`, e.g. lines 231-237, 365-402), handling `?` vs `$n` placeholders, JSON payload access (`json_extract` vs `->>`), `LIKE` vs `ILIKE`, and tag containment (`LIKE` / `JSON_CONTAINS` / `@>`).

Call site: `store/db/sqlite/memo.go:57-61` inside `ListMemos`, with the same two lines in `store/db/postgres/memo.go` and `store/db/mysql/memo.go` using their own dialect constants; the glue helper is `AppendConditions` at `internal/filter/helpers.go:9`. The filter string arrives from `ListMemosRequest.filter` (`proto/api/v1/memo_service.proto`) via `APIV1Service.ListMemos`. A separate, simpler filter path exists for users at `server/router/api/v1/user_service_filter.go`.
