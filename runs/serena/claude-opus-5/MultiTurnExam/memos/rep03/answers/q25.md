**CEL (Common Expression Language) via `cel-go` — engine in `internal/filter/` (entry point `internal/filter/engine.go`)**

**Mechanism:** the filter string is parsed and type-checked by `cel-go` against a memo-specific CEL environment (`internal/filter/schema.go`, used at `engine.go:25`), normalized into a dialect-agnostic IR (`internal/filter/parser.go` → `internal/filter/ir.go`), then rendered into a SQL fragment plus placeholder args for the target dialect by `internal/filter/render.go`, which each driver splices into its `WHERE` clause — e.g. `store/db/sqlite/memo.go:57-61` calls `filter.DefaultEngine()` and `filter.AppendConditions(..., filter.DialectSQLite, &where, &args)`, with `filter.DialectPostgres` / `filter.DialectMySQL` used in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`.

Dialect differences handled in the renderer (documented in `internal/filter/README.md`): `?` vs `$n` placeholders, JSON access on `memo.payload` (`json_extract` vs `->>`), tag membership (SQLite `LIKE`, MySQL `JSON_CONTAINS`, Postgres `@>`), and `LIKE` vs `ILIKE`. The API-layer glue that collects filter strings for `ListMemos` is `server/router/api/v1/memo_service_filter.go`; note `UserService` filters use a separate, smaller inline CEL env (`server/router/api/v1/user_service_filter.go:29`).
