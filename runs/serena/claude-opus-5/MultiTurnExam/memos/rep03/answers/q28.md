```
s3presign.Runner — one immediate RunOnce at startup, then a 12-hour time.Ticker loop until its context is cancelled
```

That is the only background runner the server starts. `Server.startBackgroundRunners` (`server/server.go:153`) constructs it at `:162`, calls `RunOnce(ctx)` synchronously at `:163`, then runs `Run(s3Context)` in a goroutine (`:167-171`) tracked by a `WaitGroup` and stopped via a stored cancel func (`stopBackgroundRunners`, `:176`). The loop itself is `time.NewTicker(runnerInterval)` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27-40`); it refreshes S3 presigned URLs whose `LastPresignedTime` is older than 4 days (`runner.go:88`).

**Unused scheduling infrastructure:** `server/runner/memopayload/runner.go` defines a full `Runner` with `NewRunner` (`:19`) and `RunOnce` (`:27`), but nothing ever constructs it — the only references to the package anywhere in the repo are `RebuildMemoPayload`, called inline from the request path in `server/router/api/v1/memo_service.go:108` (create) and `:447` (update). So the memopayload runner is dead scheduling infrastructure; its payload-rebuild logic is used, but only synchronously.

Two other background goroutines exist but aren't runners in this sense: the Echo HTTP server goroutine (`server/server.go:124`) and the fire-and-forget webhook delivery goroutine in `webhook.PostAsync` (`internal/webhook/webhook.go:44`).
