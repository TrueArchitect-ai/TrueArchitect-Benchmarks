`Store.DeleteMemo` (`store/memo.go:140-159`) deletes, in order, before the memo row:

1. **memo_relation rows where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **memo_relation rows where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **attachment rows linked to the memo** — listed via `ListAttachments{MemoID}` then deleted one by one (`store/memo.go:149-157`)
4. **the attachments' stored blobs** — `Store.DeleteAttachment` calls `DeleteAttachmentStorage` first, removing the local file or S3 object (`store/attachment.go:141-146`, `store/attachment.go:202+`)

Then `s.driver.DeleteMemo` issues the plain `DELETE FROM memo WHERE id = ?` (e.g. `store/db/sqlite/memo.go:237`).

Two things happen outside this store call: **comment memos** are deleted first by the API handler, which lists `MemoRelationComment` relations and calls `Store.DeleteMemo` on each child (`server/router/api/v1/memo_service.go:567-577`); and **reactions** are only read for the webhook payload (`memo_service.go:545`), not explicitly deleted on this path.
