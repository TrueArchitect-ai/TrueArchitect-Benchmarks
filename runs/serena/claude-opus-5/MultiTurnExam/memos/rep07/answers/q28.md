**Runners the server actually starts** — all in `Server.startBackgroundRunners` (`server/server.go:152-173`):

```
s3presign.Runner (RunOnce) — fired once, synchronously, at startup — server/server.go:163
s3presign.Runner (Run) — time.Ticker every 12 hours — server/runner/s3presign/runner.go:26-30
```

That is the only long-lived scheduled worker. Other background goroutines exist but are event-driven, not scheduled:

```
SSE heartbeat — per-connection ticker while a client is subscribed — server/router/api/v1/sse_handler.go:64
webhook.PostAsync — one goroutine per outgoing webhook, fired by the dispatch call — internal/webhook/webhook.go:44
email send — one goroutine per outgoing message — internal/email/email.go:18
auth token cleanup goroutine — triggered from the authenticator — server/auth/authenticator.go:180
```

**Unused infrastructure note:** `internal/scheduler` — a complete GitHub-Actions-style cron scheduler (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`, plus `README.md` and `doc.go`) — is **not wired into the server at all**. Grepping for imports of `internal/scheduler` outside the package itself returns nothing; its only callers are its own tests (`scheduler_test.go`, `integration_test.go`, `example_test.go`). The s3presign runner rolls its own `time.Ticker` rather than registering a job with it.

Also note `server/runner/memopayload` is a package under `runner/` but is not a runner — it exposes `RebuildMemoPayload`, called inline from the memo handlers (`server/router/api/v1/memo_service.go:108`, `:447`).
