**web/src/connect.ts; JWT access token + refresh token (HTTP-only cookie) + personal access tokens (PAT); server/auth**

- **Interceptor:** `authInterceptor` at `web/src/connect.ts:155`, installed on the shared Connect transport (:186). It fetches a token via `getRequestToken()` (:124), sets `Authorization: Bearer <token>`, and on a `Code.Unauthenticated` response refreshes once and retries, tagging the retry with an `X-Retry` header to prevent loops; if refresh fails it calls `redirectOnAuthFailure()`. A second, interceptor-free transport (`refreshTransport`, :64) exists solely for `refreshToken` calls so refresh can't recurse.

- **Token kinds:**
  - **Access token** — short-lived JWT held in memory and mirrored to `localStorage`, managed by `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken`, cross-tab sync via `BroadcastChannel`). Backend lifetime 15 min, audience `user.access-token` (`server/auth/token.go:37-40`). The interceptor does a proactive refresh when it's near expiry (`isTokenExpired(REQUEST_TOKEN_EXPIRY_BUFFER_MS)`, `web/src/connect.ts:140`) plus reactive refresh on 401.
  - **Refresh token** — HTTP-only cookie `memos_refresh` (`server/auth/token.go:49`), 30-day lifetime (:43), never touched by JS; sent because both transports use `fetch` with `credentials: "include"` (`web/src/connect.ts:57`).
  - **Personal access tokens (PAT)** — also accepted in the `Authorization: Bearer` header for API clients (`server/auth/token.go:51`, validated by `Authenticator.AuthenticateByPAT`).

- **Backend validation package: `server/auth/`** — `Authenticator` (`server/auth/authenticator.go:32`) with `AuthenticateByAccessTokenV2` (:41), `AuthenticateByRefreshToken` (:61), `AuthenticateByPAT` (:102), and the `resolveBearer` dispatcher (:149). It's wired into the gRPC-Gateway middleware in `server/router/api/v1/v1.go` and into the SSE endpoint via `RegisterSSERoutes` (`server/router/api/v1/sse_handler.go:26`); context plumbing is in `server/auth/context.go`, header/cookie extraction in `server/auth/extract.go`.
