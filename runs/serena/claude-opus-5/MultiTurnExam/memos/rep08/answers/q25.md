**Engine: CEL (Google's `cel-go`), wrapped by the project's own filter engine in `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`)**

**Mechanism:** each dialect's `ListMemos` builds its WHERE clause by calling `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` (e.g. `store/db/sqlite/memo.go:57-61`, with MySQL/Postgres equivalents in `store/db/mysql/memo.go` and `store/db/postgres/memo.go`), which runs a three-phase pipeline — parse the CEL expression against the memo-specific environment (`internal/filter/schema.go`, `internal/filter/parser.go`), normalize it into a dialect-agnostic IR (`internal/filter/ir.go`), then render that IR into a dialect-specific SQL fragment plus placeholder args (`internal/filter/render.go`) — so dialect differences like `?` vs `$n` placeholders, JSON access (`json_extract` / `->>`), `LIKE` vs `ILIKE`, tag containment (`LIKE` / `JSON_CONTAINS` / `@>`), and regex (`REGEXP` / `~`) are handled in one place.

The API side passes the raw filter string down from `APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:178`, with filter handling in `server/router/api/v1/memo_service_filter.go` and `memo_service_query.go`) into `store.FindMemo.Filters`. Design docs: `internal/filter/README.md` and `internal/filter/MAINTENANCE.md`.
