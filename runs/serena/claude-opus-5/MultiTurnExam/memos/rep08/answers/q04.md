**APIV1Service.SignIn — server/router/api/v1/auth_service.go**

Defined at `server/router/api/v1/auth_service.go:51`. It handles both password credentials and SSO authorization-code sign-in, then delegates token issuance to `APIV1Service.doSignIn` (`server/router/api/v1/auth_service_session.go:24`), which sets the refresh-token cookie.

Note there's a thin Connect-protocol wrapper, `ConnectServiceHandler.SignIn` at `server/router/api/v1/connect_services.go:78`, but it just forwards to `APIV1Service.SignIn` inside a header carrier so response headers/cookies can be set.
