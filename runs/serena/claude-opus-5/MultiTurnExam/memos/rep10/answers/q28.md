**Runners the server actually starts** — all from `Server.startBackgroundRunners` (`server/server.go:152-172`):

```
s3presign.Runner — RunOnce at startup, then a 12h time.Ticker loop (server/runner/s3presign/runner.go:27,30), cancelled via its own context on shutdown
store/cache cleanup loops (×3: instanceSettingCache, userCache, userSettingCache) — time.Ticker at cache.Config.CleanupInterval (store/cache/cache.go:201; created in store/store.go:51-53)
SSE client heartbeat — per-connection time.Ticker at sseHeartbeatInterval (server/router/api/v1/sse_handler.go:64), lifetime = the SSE request
```

The s3presign runner is the only entry in `startBackgroundRunners`; it re-presigns S3 attachment URLs whose last presign is older than ~4 days (`runner.go:88`). The cache loops and SSE heartbeat are goroutines owned by their components rather than registered runners, but they are the other things genuinely ticking in a running server.

Fire-and-forget goroutines, not scheduled work: webhook delivery `PostAsync` (`internal/webhook/webhook.go:44`), email send (`internal/email/email.go:18`), and PAT last-used recording (`server/auth/authenticator.go:180`).

**Unused infrastructure:**

- `internal/scheduler/` — a full cron-style scheduler package (parser, job, middleware, `scheduler.go`, README, doc.go, tests) with **zero importers outside itself**; `grep` for `usememos/memos/internal/scheduler` finds no hits in `server/`, `store/`, or `cmd/`. Nothing in the server schedules jobs through it.
- `server/runner/memopayload` has a `Runner` type with `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19,27`) that is **never instantiated or started**. Only its package-level `RebuildMemoPayload` function is used, called inline from the API handlers on memo create/update (`server/router/api/v1/memo_service.go:108`, `:447`) — so the backfill runner itself is dead scheduling infrastructure.
