**CEL (Google Common Expression Language, via `github.com/google/cel-go`) + internal/filter (engine.go, parser.go, ir.go, render.go, schema.go, helpers.go)**

The filter string is compiled by `Engine.Compile` into a CEL AST (`cel.NewEnv` at `internal/filter/engine.go:25`, `cel.AstToParsedExpr` at :57) against a declared variable schema (`content`, `creator`, `creator_id`, `created_ts`, `updated_ts`, `pinned`, `tag`, `tags`, … — `internal/filter/schema.go:232+`), lowered into a dialect-independent condition IR (`ir.go`/`parser.go`), and then rendered to a parameterized SQL fragment plus args by `render.go` for the target `DialectName` (`sqlite` | `mysql` | `postgres`, `schema.go:14-16`), with per-dialect templates in the schema (e.g. `('users/' || %s)` for SQLite/Postgres vs `CONCAT('users/', %s)` for MySQL, `UNIX_TIMESTAMP(%s)` only for MySQL) and dialect-specific placeholder styles (`render.go:231-238`); each driver calls `filter.DefaultEngine()` then `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` — e.g. `store/db/postgres/memo.go:54-58`, with the sqlite and mysql counterparts in `store/db/sqlite/memo.go` and `store/db/mysql/memo.go` — so the compiled fragments are appended as `AND`-ed `WHERE` clauses with bound arguments rather than interpolated SQL.

The same engine backs shortcuts, whose saved `filter` strings use the identical grammar (`proto/api/v1/shortcut_service.proto:70`), and attachments via `DefaultAttachmentEngine` (`engine.go:119`). Package docs: `internal/filter/README.md` and `internal/filter/MAINTENANCE.md`.
