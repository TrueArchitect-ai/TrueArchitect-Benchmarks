**CEL (Google Common Expression Language, `github.com/google/cel-go`) + `internal/filter`; the CEL AST is compiled once into a dialect-agnostic condition tree, then each driver renders that tree into a parameterized SQL `WHERE` fragment for its own dialect.**

Details:
- **Engine:** `filter.Engine` wraps a `cel.Env` (`internal/filter/engine.go:14-33`). `Compile` runs `env.Compile(filter)` and converts the AST into the IR (`internal/filter/engine.go:48`); the IR node types are in `internal/filter/ir.go`, the AST→IR walk in `internal/filter/parser.go`, and the allowed variables/functions per entity in `internal/filter/schema.go` (`DefaultEngine` for memos, `DefaultAttachmentEngine` for attachments — `internal/filter/engine.go:111`, `:119`). The dependency is pinned at `go.mod:13`.
- **Dialect rendering:** `Program.Render` / `Engine.CompileToStatement` take `RenderOptions{Dialect: DialectName}` (`internal/filter/engine.go:74-96`); dialect constants `DialectSQLite`/`DialectMySQL`/`DialectPostgres` are in `internal/filter/schema.go:11-16`, and `internal/filter/render.go` switches on them throughout (placeholders `?` vs `$n`, JSON extraction, `LENGTH` vs `CHAR_LENGTH`, etc.), emitting a SQL string plus bound args — so values are parameterized, not interpolated.
- **Wiring:** each driver's `ListMemos` calls `filter.DefaultEngine()` then `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` — `store/db/sqlite/memo.go:56-62` (`DialectSQLite`), `store/db/postgres/memo.go:54` (`DialectPostgres`), `store/db/mysql/memo.go:65` (`DialectMySQL`). The filter string arrives from the API handler `APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:178`) via `store.FindMemo.Filters`.

Background docs for the package live at `internal/filter/README.md` and `internal/filter/MAINTENANCE.md`.
