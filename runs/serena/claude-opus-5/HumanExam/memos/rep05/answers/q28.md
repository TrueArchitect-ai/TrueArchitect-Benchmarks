- s3presign runner — one immediate `RunOnce` at startup, then a `time.Ticker` every 12h (server/server.go:161-172; server/runner/s3presign/runner.go:26-40). It is the only runner the server explicitly starts.
- webhook delivery workers — 4 goroutines started by `internal/webhook` package `init()`, driven by a buffered channel (`asyncPostQueue`, cap 128) fed by `PostAsync` (internal/webhook/webhook.go:39-54,184)
- store cache janitors — 3 caches created in store/store.go:51-53, each running a `CleanupInterval` ticker loop (store/cache/cache.go:199-214)
- SSE heartbeat — per-connection 30s ticker, only while a client is subscribed (server/router/api/v1/sse_handler.go:17,64)

Unused infra: `internal/scheduler` (a full cron-style scheduler with parser/middleware, internal/scheduler/) is not referenced by the server at all — only by its own tests (internal/scheduler/example_test.go, integration_test.go). Also `server/runner/memopayload` despite its "runner" location is not a background runner; it is called inline from the memo handlers (server/router/api/v1/memo_service.go:107,447).
