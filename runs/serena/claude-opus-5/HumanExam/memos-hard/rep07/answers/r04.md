Premise is wrong: there is no message broker at all — no NATS, RabbitMQ, AMQP, or Kafka in the code or `go.mod`, and no queue is declared anywhere externally. Webhook delivery uses an in-process buffered Go channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`), drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) calling `Post` (`:120`). Producers call `PostAsync` (`:184`), which drops the payload with a warning when the buffer is full. It is not durable — pending payloads are lost on restart.
