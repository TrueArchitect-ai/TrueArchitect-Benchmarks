The premise is incorrect — the webhook delivery workers do not consume from either NATS or RabbitMQ. There is no external message broker involved at all.

The actual mechanism is a **plain Go in-memory buffered channel**. In `internal/webhook/webhook.go:39`, the queue is declared as:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in an `init()` function in the same file (lines ~42–55), each running a `for payload := range asyncPostQueue` loop that calls `Post()` to perform a synchronous HTTP POST. The enqueue side is `PostAsync()` (lines ~184–196), which does a non-blocking channel send and silently drops the webhook with a warning log if the channel is full. There is no persistence, no retry logic, and no external dependency — it is entirely in-process.
