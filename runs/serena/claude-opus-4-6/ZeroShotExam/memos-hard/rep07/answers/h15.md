Every distinct server-side enforcement site for memo visibility:

1. **GetMemo / single-memo read gate** — `server/router/api/v1/memo_service.go` (`checkMemoReadAccess`)
2. **ListMemos query-level filtering** — `server/router/api/v1/memo_service.go` (visibility list / CEL filter injected into query)
3. **ListMemoComments visibility filter** — `server/router/api/v1/memo_service_comments.go` (calls `checkMemoReadAccess` on parent + CEL filter on comments)
4. **CreateMemoComment private-memo guard** — `server/router/api/v1/memo_service_comments.go` (blocks non-creator comment on private memo; forces comment visibility to match parent)
5. **ListMemoRelations visibility filter** — `server/router/api/v1/memo_relation_service.go` (CEL visibility subquery on both sides of the relation)
6. **Batch relation conversion filter** — `server/router/api/v1/memo_service_converter.go` (`batchConvertMemoRelations` applies same CEL filter)
7. **Attachment access via API** — `server/router/api/v1/attachment_service.go` (`checkAttachmentAccess` enforces memo visibility on linked attachments)
8. **ListMemoAttachments inline check** — `server/router/api/v1/memo_attachment_service.go` (inline visibility gate before listing)
9. **File server attachment permission** — `server/router/fileserver/fileserver.go` (`checkAttachmentPermission` — independent implementation on the Echo HTTP file-serving path, includes share-token fallback)
10. **Reaction service** — `server/router/api/v1/reaction_service.go` (visibility checks in both `ListMemoReactions` and `UpsertMemoReaction`)
11. **SSE event delivery** — `server/router/api/v1/sse_hub.go` (`canReceive` filters broadcast events by memo visibility per connected client)
12. **User stats queries** — `server/router/api/v1/user_service_stats.go` (visibility list / CEL filter applied in `ListAllUserStats` and `GetUserStats`)
13. **API notification payloads** — `server/router/api/v1/user_service_notifications.go` (`canViewerAccessMemo` suppresses comment/mention notification payloads the viewer cannot access)
14. **Email notification dispatching** — `server/notification/email.go` (independent `canViewerAccessMemo` copy gates email delivery)
15. **Mention notification gating** — `server/router/api/v1/memo_mention_helpers.go` (`canUserAccessMentionContext` / `shouldSkipMentionInbox` prevents inbox items for inaccessible memos)
16. **Share-token access bypass** — `server/router/api/v1/memo_share_service.go` (`GetMemoByShare` grants read access via valid token, bypassing normal visibility — but still excludes archived memos)
17. **Visibility update constraint** — `server/router/api/v1/memo_service.go` (on `UpdateMemo`, comment visibility is forced to match parent memo)
18. **Database-layer SQL filtering (SQLite)** — `store/db/sqlite/memo.go` and `store/db/sqlite/memo_relation.go` (WHERE clauses on `visibility IN (...)` and CEL-compiled subqueries)
19. **Database-layer SQL filtering (Postgres)** — `store/db/postgres/memo.go` and `store/db/postgres/memo_relation.go` (same patterns for PostgreSQL)
