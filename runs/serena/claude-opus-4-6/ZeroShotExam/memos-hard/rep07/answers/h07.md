`serveUserAvatar` — `server/router/fileserver/fileserver.go`
`getUserByUsername` — `server/router/fileserver/fileserver.go`
`Store.GetUser` — `store/user.go`
`Store.ListUsers` — `store/user.go`
`Driver.ListUsers` — `store/db/sqlite/user.go` (or `store/db/postgres/user.go`, `store/db/mysql/user.go`)
`parseDataURI` — `server/router/fileserver/fileserver.go`

**Detail:**

1. **`serveUserAvatar`** — `server/router/fileserver/fileserver.go` — The Echo HTTP handler registered at `GET /file/users/:identifier/avatar`. Extracts the username from the URL path, retrieves the user, parses the stored data-URI avatar, validates the MIME type, and returns the raw image bytes.

2. **`getUserByUsername`** — `server/router/fileserver/fileserver.go` — Helper called by the handler; wraps a call to `s.Store.GetUser` with a `FindUser{Username: &identifier}` filter.

3. **`Store.GetUser`** — `store/user.go` — Checks an in-memory user cache (by ID; bypassed here since the lookup is by username), then falls through to `s.ListUsers(ctx, find)`.

4. **`Store.ListUsers`** — `store/user.go` — Delegates to `s.driver.ListUsers(ctx, find)`, the database-driver interface method.

5. **`Driver.ListUsers`** — `store/db/sqlite/user.go` (or postgres/mysql equivalents) — Builds and executes `SELECT … avatar_url … FROM user WHERE username = ?`, scanning the `avatar_url` column (a base64 data-URI string) into `User.AvatarURL`.

6. **`parseDataURI`** — `server/router/fileserver/fileserver.go` — Back in the handler, extracts the MIME type and base64 payload from the data-URI via regex, decodes the base64, and returns the raw bytes that the handler streams to the browser.

The avatar is stored **inline in the database** as a `data:image/<type>;base64,…` string in the `avatar_url` column — there is no separate filesystem or object-store hop.
