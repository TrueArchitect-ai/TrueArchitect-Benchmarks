The premise is incorrect — there is no Redis connection in this repository. The cache layer is a **custom in-process, in-memory cache** built on Go's `sync.Map`, not Redis.

The implementation lives in:

- **`store/cache/cache.go`** — defines the `Cache` struct backed by `sync.Map` with TTL-based expiration and a background cleanup goroutine.
- **`store/store.go:40-45`** — configures the cache with a hardcoded `Config` struct (no external connection or Redis client).

The `userCache` is instantiated at `store/store.go:52` via `cache.New(cacheConfig)`, where `cacheConfig` sets:

- **`DefaultTTL: 10 * time.Minute`** — user entries expire after 10 minutes.
- **`CleanupInterval: 5 * time.Minute`** — a background goroutine sweeps expired entries every 5 minutes.
- **`MaxItems: 1000`** — when exceeded, the oldest 20% of entries are evicted.

All three caches (`userCache`, `userSettingCache`, `instanceSettingCache`) share this same configuration. The cache keys for users are simply the user ID converted to a string (`store/user.go:88-89`).
