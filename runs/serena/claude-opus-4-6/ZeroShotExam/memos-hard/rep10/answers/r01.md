The premise is incorrect: there is no Redis connection in this repository. The cache layer is a **pure in-memory Go cache**, not Redis-backed.

The cache is implemented in `store/cache/cache.go` as a thread-safe in-memory store using `sync.Map` with TTL-based expiration. It is configured and instantiated in `store/store.go:38-53`, where the `Store.New()` constructor creates three cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing the same `cache.Config`.

The TTL that applies to user entries is **10 minutes** (`DefaultTTL: 10 * time.Minute`), set at `store/store.go:41`. This same default TTL applies to all three caches. User entries are cached via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` calls throughout `store/user.go`, which use the `Set` method (not `SetWithTTL`), so they inherit the default 10-minute TTL.

The cache also has a cleanup interval of 5 minutes and a max capacity of 1,000 items per cache instance (`store/store.go:42-43`). When the item limit is exceeded, the oldest 20% of entries are evicted (`store/cache/cache.go:253-313`).
