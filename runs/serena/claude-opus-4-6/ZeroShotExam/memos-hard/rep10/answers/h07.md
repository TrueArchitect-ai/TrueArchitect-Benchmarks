**Detail:** A browser hits `GET /file/users/:identifier/avatar`. The route is registered in `server/router/fileserver/fileserver.go` (line 124). The handler `serveUserAvatar` (line 168) authenticates the caller, then calls `getUserByUsername` (line 715 in the same file), which delegates to `s.Store.GetUser` in `store/user.go` (line 148). `GetUser` checks a 10-minute in-memory cache; on a miss it calls `s.ListUsers`, which calls `s.driver.ListUsers` (the `Driver` interface at `store/driver.go`, line 47). The concrete implementation (e.g. SQLite at `store/db/sqlite/user.go`, line 88) runs a SQL query selecting `avatar_url` from the `user` table. The avatar is stored as a base64 data URI directly in that column. Back in the handler, `parseDataURI` (line 737) decodes the base64 payload and the raw image bytes are returned via `c.Blob`.
