**Concrete method:** `(*DB).CreateMemo` in `store/db/sqlite/memo.go` — this is the method that executes the SQL `INSERT INTO memo ...` when a memo is saved under a default installation.

**Determination method:** The default driver is established by tracing the configuration chain:

1. In `cmd/memos/main.go` (lines ~122, 130), the `--driver` CLI flag defaults to `"sqlite"`:
   ```go
   viper.SetDefault("driver", "sqlite")
   rootCmd.PersistentFlags().String("driver", "sqlite", "database driver")
   ```
2. This value flows into `profile.Profile.Driver`, which is consumed by the factory function `NewDBDriver` in `store/db/db.go`. That function switches on `profile.Driver` and, for `"sqlite"`, instantiates `sqlite.NewDB(profile)`.
3. The resulting driver is wrapped by `store.New(dbDriver, profile)` in `store/store.go`. The `Store.CreateMemo` method in `store/memo.go` validates inputs and then delegates to `s.driver.CreateMemo(ctx, create)` — which resolves to the SQLite implementation.

There are three candidate implementations — `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, and `store/db/mysql/memo.go` — all satisfying the `Driver` interface defined in `store/driver.go`. The SQLite one is the one that actually runs because `"sqlite"` is the hardcoded default for the `--driver` flag, and no database flags means that default is never overridden.
