With a default installation (no database flags), the concrete code that executes the SQL INSERT when a memo is saved is:

**`(*DB).CreateMemo` — `store/db/sqlite/memo.go` (line 16)**

This method builds and executes an `INSERT INTO memo ... RETURNING id, created_ts, updated_ts, row_status` statement using `?` placeholders against the SQLite database.

**Determination method:** The driver selection is governed by a factory function `NewDBDriver` in `store/db/db.go` (line 14), which switches on `profile.Driver`. The default value for this field is hardcoded to `"sqlite"` in two places in `cmd/memos/main.go`:

- `viper.SetDefault("driver", "sqlite")` (line 124)
- `rootCmd.PersistentFlags().String("driver", "sqlite", ...)` (line 130)

Since the default driver is `"sqlite"`, the factory returns a `sqlite.DB` instance (`store/db/sqlite/sqlite.go`), which means the `CreateMemo` implementation in `store/db/sqlite/memo.go` is the one wired into the `Store` via the `Driver` interface (`store/driver.go`, line 29). The other two candidates — `store/db/postgres/memo.go` and `store/db/mysql/memo.go` — are only reachable when the `--driver` flag (or `MEMOS_DRIVER` env var) is explicitly set to `"postgres"` or `"mysql"`.

**Answer:** `(*DB).CreateMemo` — `store/db/sqlite/memo.go`; determined by tracing the `Driver` interface dispatch through the `NewDBDriver` factory in `store/db/db.go`, which selects the SQLite implementation based on the hardcoded default `"sqlite"` in `cmd/memos/main.go`.
