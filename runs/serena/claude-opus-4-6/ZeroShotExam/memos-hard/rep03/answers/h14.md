The derived metadata is computed in two places, both in `internal/markdown/markdown.go`:

1. **`MemoPayload.Property`** — extracted by `ExtractProperties()` (lines 192–241), or more commonly via the combined single-pass `ExtractAll()` (lines 355–422), which walks the goldmark AST and populates:
   - `has_link` (bool) — whether the content contains any links
   - `has_task_list` (bool) — whether the content contains task checkboxes
   - `has_code` (bool) — whether the content contains code blocks or code spans
   - `has_incomplete_tasks` (bool) — whether any task checkboxes are unchecked
   - `title` (string) — text of the first H1 heading, if the first block-level child is one

2. **`snippet`** — generated by `GenerateSnippet()` (lines 263–346), which parses the markdown AST, extracts plain text (skipping code blocks, collapsing block elements), and truncates to 64 characters at a word boundary (appending ` ...`). The entry point is `getMemoContentSnippet()` in `server/router/api/v1/memo_service_webhooks.go:83–90`.

**Computation site:** `internal/markdown/markdown.go` — functions `ExtractAll()`/`ExtractProperties()` for the property, and `GenerateSnippet()` for the snippet. The payload rebuild is orchestrated by `RebuildMemoPayload()` in `server/runner/memopayload/runner.go:74–88`.

**Triggers:** Recomputation is triggered on **memo creation** (`server/router/api/v1/memo_service.go:108`) and **memo content update** (`server/router/api/v1/memo_service.go:447`). A batch rebuild path (`RunOnce()` in `server/runner/memopayload/runner.go:27–72`) recomputes for all memos (used for migration/reindexing). The snippet is additionally computed at conversion time in `memo_service_converter.go:76` and for relation/notification payloads.

**Extracted properties:** `has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, `title` (first H1 heading text), and `snippet` (plain-text preview truncated to 64 chars). The property schema is defined in `proto/store/memo.proto:15–23` and the snippet field in `proto/api/v1/memo_service.proto:265–266`, both marked `OUTPUT_ONLY`.
