The premise is incorrect — there is no Redis connection in this project. The cache layer is an **in-process, in-memory cache**, not Redis.

The cache is implemented in `store/cache/cache.go` as a Go struct backed by a `sync.Map` with TTL-based expiration. It is configured and instantiated in `store/store.go:38-45`, where the `Store.userCache` field (line 28) is created with the shared `cacheConfig`.

The **TTL that applies to user entries is 10 minutes** (`DefaultTTL: 10 * time.Minute`, `store/store.go:41`). All three caches (instance settings, users, user settings) share this same default configuration — there is no per-cache TTL override. The user cache calls `Set()` without a custom TTL (e.g., `store/user.go:98`), so it falls through to the default 10-minute TTL via `cache/cache.go:93-94`.

Cleanup of expired entries runs every 5 minutes (`CleanupInterval: 5 * time.Minute`), and the cache is capped at 1,000 items (`MaxItems: 1000`).
