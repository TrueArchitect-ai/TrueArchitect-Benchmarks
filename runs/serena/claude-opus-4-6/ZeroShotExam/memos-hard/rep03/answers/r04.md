The premise is incorrect — webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is an **in-process Go buffered channel** declared at package level in `internal/webhook/webhook.go`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the `init()` function of that same file, each ranging over the channel to consume and dispatch payloads via HTTP POST. Work is enqueued through the `PostAsync()` function using a non-blocking `select` — if the 128-slot buffer is full, the payload is silently dropped with a warning log. There is no persistence, no retry logic, and no external broker dependency.
