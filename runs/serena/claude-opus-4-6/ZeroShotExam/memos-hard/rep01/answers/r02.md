The premise of the question is incorrect. This repository (usememos/memos) does not have per-user API rate-limiting middleware. The server's middleware stack — registered in `server/server.go` and `server/router/api/v1/connect_interceptors.go` — consists of:

- **Echo-level middleware** (`server/server.go`): `middleware.Recover()` (panic recovery) and a CORS middleware (`newCORSMiddleware`).
- **Connect RPC interceptors** (`server/router/api/v1/connect_interceptors.go`): `MetadataInterceptor` (header-to-gRPC-metadata conversion), `LoggingInterceptor` (request logging), `RecoveryInterceptor` (panic recovery), and `AuthInterceptor` (authentication/authorization).

There is also an internal `scheduler` middleware package (`internal/scheduler/middleware.go`) with `Recovery`, `Logging`, and `Timeout` middleware, but these are for background job scheduling, not API request handling.

None of these implement rate limiting of any kind — there are no request counters, token buckets, sliding windows, or per-user quota checks anywhere in the codebase.
