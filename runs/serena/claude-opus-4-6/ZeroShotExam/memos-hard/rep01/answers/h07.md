`GET /file/users/:identifier/avatar` — the browser requests another user's profile image at this path (constructed from the `avatar_url` field returned by the user API). Here is each hop:

1. `RegisterRoutes` — `server/router/fileserver/fileserver.go` (line 121): registers the Echo route `fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)`
2. `serveUserAvatar` — `server/router/fileserver/fileserver.go` (line 168): HTTP handler; authenticates if private, extracts `:identifier`, calls `getUserByUsername`
3. `getUserByUsername` — `server/router/fileserver/fileserver.go` (line 715): thin wrapper that calls `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`
4. `(*Store).GetUser` — `store/user.go` (line 148): checks the in-memory `userCache`; on miss calls `s.ListUsers`
5. `(*Store).ListUsers` — `store/user.go` (line 136): delegates to `s.driver.ListUsers(ctx, find)` (the `Driver` interface at `store/driver.go` line 47)
6. `(*DB).ListUsers` — `store/db/sqlite/user.go` (line 88) (or `store/db/postgres/user.go` / `store/db/mysql/user.go`): builds a SQL query against the `user` table, filtering by `username = ?`, and scans the `avatar_url` column into `user.AvatarURL`
7. `parseDataURI` — `server/router/fileserver/fileserver.go` (line 737): back in the handler, decodes the base64 data-URI stored in `AvatarURL` and returns the raw image bytes via `c.Blob`
