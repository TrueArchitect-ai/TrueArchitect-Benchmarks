The premise is incorrect — the webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain Go buffered channel**. In `internal/webhook/webhook.go:39`, the queue is declared as:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a package-level buffered channel with a capacity of 128. In the `init()` function at `internal/webhook/webhook.go:42-55`, **4 goroutine workers** are spawned that consume from this channel in a `for payload := range asyncPostQueue` loop, calling `Post(payload)` to deliver each webhook via HTTP.

Producers enqueue work via the `PostAsync` function (`internal/webhook/webhook.go:183-196`), which performs a non-blocking send on the channel and drops the payload with a warning log if the channel is full.

This is entirely in-process — no external message broker, no queue server, just a Go channel with goroutine consumers.
