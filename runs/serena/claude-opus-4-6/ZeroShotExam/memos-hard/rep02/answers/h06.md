The RPC handler methods that can transitively cause an outbound HTTP request to a user-configured webhook URL are:

1. **`CreateMemo`** — calls `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service.go:157`)
2. **`UpdateMemo`** — calls `dispatchMemoUpdatedSideEffects` which calls `DispatchMemoUpdatedWebhook` (`server/router/api/v1/memo_service.go:513` → `memo_update_helpers.go:67`)
3. **`DeleteMemo`** — calls `DispatchMemoDeletedWebhook` (`server/router/api/v1/memo_service.go:562`)
4. **`CreateMemoComment`** — calls both `CreateMemo` (which dispatches `memos.memo.created`) and then explicitly calls `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_comments.go:56,119`)

All four dispatch helpers (`DispatchMemoCreatedWebhook`, `DispatchMemoUpdatedWebhook`, `DispatchMemoDeletedWebhook`, `DispatchMemoCommentCreatedWebhook`) call **`webhook.PostAsync`** (`internal/webhook/webhook.go:184`), which enqueues the payload onto `asyncPostQueue`. The goroutine workers then drain that queue by calling the single convergence function:

**`webhook.Post`** — `internal/webhook/webhook.go:120`

This is where all paths converge: `Post` serializes the payload to JSON, constructs the HTTP request to the user-configured `URL`, optionally signs it with HMAC-SHA256, and sends it via `safeClient.Do()`.

**Handlers:** `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment` (≥3); **convergence function** — `webhook.Post` (`internal/webhook/webhook.go:120`)
