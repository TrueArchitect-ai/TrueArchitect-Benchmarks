The premise of the question is incorrect — this repository (Memos) does **not** use GraphQL. Its public API is defined using **Protocol Buffers (gRPC)** with an auto-generated **REST/HTTP gateway** and **OpenAPI spec**.

The actual API surface is defined by `.proto` files in `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/common.proto` (shared types)

These proto definitions are used to generate:
1. **gRPC server stubs** (Go code in `proto/gen/api/v1/`, e.g. `*_grpc.pb.go`)
2. **gRPC-Gateway reverse proxies** (e.g. `*_service.pb.gw.go`) that expose the gRPC services as REST endpoints
3. An **OpenAPI 3.0 spec** at `proto/gen/openapi.yaml`, generated via `protoc-gen-openapi`

The build toolchain uses **Buf** (`proto/buf.yaml`, `proto/buf.gen.yaml`) to orchestrate protobuf code generation. As the README states, the project provides "full REST and gRPC APIs" — no GraphQL layer exists.
