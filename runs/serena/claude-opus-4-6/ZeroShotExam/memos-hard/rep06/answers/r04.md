The premise is incorrect — webhook delivery uses **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain Go buffered channel** serving as an in-memory queue, declared in **`internal/webhook/webhook.go`** (line 39):

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

In the same file's `init()` function, **4 goroutine workers** are spawned at process startup. Each goroutine reads from this channel in an infinite loop and calls `Post()` to deliver the webhook via HTTP. The `PostAsync()` function (also in `webhook.go`) performs a non-blocking send onto the channel; if the 128-slot buffer is full, the webhook is silently dropped with a warning log — there is no retry, no persistence, and no dead-letter queue. If the process crashes, all queued webhooks are lost. The entire dispatch-and-delivery pipeline is in-process with no external dependencies.
