The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is a **custom in-memory cache**, not Redis-backed.

The cache is implemented as a pure Go in-process store using `sync.Map` in `store/cache/cache.go`. It is instantiated in `store/store.go:38-45` where the `Store.New()` constructor creates three separate `cache.Cache` instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing the same `cache.Config`.

The **TTL for user entries is 10 minutes** (`DefaultTTL: 10 * time.Minute`), set in `store/store.go:41`. This is the `DefaultTTL` from the `cache.Config` struct defined in `store/cache/cache.go:42-54`. The cleanup goroutine runs every 5 minutes (`CleanupInterval: 5 * time.Minute`), and the cache is capped at 1000 items (`MaxItems: 1000`).

User entries are cached by user ID (converted to string via `userCacheKey()` in `store/user.go:88-90`) and populated on create, update, get, and list operations (`store/user.go:92-169`).
