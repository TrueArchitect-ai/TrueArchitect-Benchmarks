The premise is incorrect — the webhook delivery workers consume from **neither NATS nor RabbitMQ**. The project uses no external message broker at all.

The actual mechanism is a **plain in-memory Go buffered channel** serving as the queue, declared at `internal/webhook/webhook.go` line 39:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

A pool of **4 goroutines** is spun up in the package's `init()` function (same file, lines 42–55), each ranging over that channel and calling `Post()` to perform a synchronous HTTP POST to the webhook URL. The non-blocking entry point `PostAsync` sends payloads into the channel and silently drops them (with a warning log) if the buffer is full.

There are no NATS, RabbitMQ, AMQP, Kafka, or Redis dependencies anywhere in the codebase or `go.mod`. The "queue" is entirely in-process with no persistence, retry, or dead-letter mechanism.
