The premise of the question is incorrect — this repository does not use Redis at all. There is no Redis connection, no Redis configuration, and no Redis-based cache layer anywhere in the codebase.

The actual caching mechanisms are:

1. **Frontend editor draft cache** (`web/src/components/MemoEditor/services/cacheService.ts`): Uses the browser's **`localStorage`** API to persist unsaved memo editor drafts. It is keyed by username and has **no TTL** — entries persist indefinitely until explicitly cleared (via `cacheService.clear()` or `cacheService.clearAll()`). Writes are debounced by 500ms (`CACHE_DEBOUNCE_DELAY`).

2. **Frontend query cache** (`web/src/lib/query-client.ts`): Uses **TanStack React Query's in-memory cache**. The default `staleTime` is **30 seconds** and `gcTime` (garbage collection / eviction) is **5 minutes**. These apply uniformly to all queries (including user-related ones) unless individually overridden.

3. **Frontend static asset HTTP cache** (`server/router/frontend/frontend.go`): The Go server sets HTTP `Cache-Control` headers — `no-cache, no-store, must-revalidate` for HTML pages, `public, max-age=3600` for static assets, and `public, max-age=3600, immutable` for hashed assets.

There is no server-side application-level cache layer (Redis or otherwise) and no concept of a "user entry TTL" distinct from the general React Query defaults.
