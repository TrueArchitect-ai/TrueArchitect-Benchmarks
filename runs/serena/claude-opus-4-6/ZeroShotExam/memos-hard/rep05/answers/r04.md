The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain Go in-process buffered channel** with a small goroutine worker pool. The queue is declared in **`internal/webhook/webhook.go`** as a package-level variable:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in an `init()` function in the same file, each reading from this channel in a `for payload := range asyncPostQueue` loop and calling `Post()` to make synchronous HTTP POST requests. The codebase has no dependencies on NATS, RabbitMQ, AMQP, Kafka, or any other external message broker (none appear in `go.mod`).

Payloads are enqueued via `PostAsync()` using a non-blocking channel send — if the 128-slot buffer is full, the webhook is silently dropped with a warning log. There is no retry logic and no persistence; if the process crashes, buffered payloads are lost. It is a fire-and-forget, in-process design.
