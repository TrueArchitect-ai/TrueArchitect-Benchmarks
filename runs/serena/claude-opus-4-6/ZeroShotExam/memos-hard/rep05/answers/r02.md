The premise of the question is incorrect. This repository does not have per-user API rate-limiting middleware. No such middleware is registered anywhere in the codebase.

The server (`server/server.go`) registers only `middleware.Recover()` and a CORS middleware. The API router's Connect/gRPC interceptors (`server/router/api/v1/v1.go`) are limited to metadata conversion, logging, recovery, and authentication — none perform rate limiting. No rate-limiting libraries are imported (though `golang.org/x/time` appears as an indirect dependency, its `rate` package is never used). There are no HTTP 429 responses anywhere in the code.

The closest related constructs are concurrency semaphores in `server/router/api/v1/v1.go` that cap concurrent thumbnail and image processing operations (3 and 2 respectively), but these are resource-protection semaphores, not per-user request rate limiters. The only mention of rate limiting is in documentation (`internal/email/README.md`) as a recommended best practice for email sending, with no actual implementation.
