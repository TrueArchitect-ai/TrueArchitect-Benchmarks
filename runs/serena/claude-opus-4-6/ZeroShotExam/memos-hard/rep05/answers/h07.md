The browser requests `GET /file/users/:identifier/avatar` (the URL is constructed by the API converter when it detects a base64 avatar). Each hop from HTTP handler to stored data:

`serveUserAvatar` — `server/router/fileserver/fileserver.go`
`getUserByUsername` — `server/router/fileserver/fileserver.go`
`Store.GetUser` — `store/user.go`
`Store.ListUsers` — `store/user.go`
`Driver.ListUsers` — `store/driver.go` (interface)
`DB.ListUsers` — `store/db/sqlite/user.go` (or `store/db/postgres/user.go` or `store/db/mysql/user.go`)

In detail:

1. **`serveUserAvatar`** — `server/router/fileserver/fileserver.go` — The Echo HTTP handler registered at `GET /file/users/:identifier/avatar` (line 124). Extracts the `:identifier` param, optionally checks authentication, then calls `getUserByUsername`.
2. **`getUserByUsername`** — `server/router/fileserver/fileserver.go` — Wraps `s.Store.GetUser` with a `FindUser{Username: &identifier}` filter (line 716).
3. **`Store.GetUser`** — `store/user.go` — Checks the in-memory user cache by ID; on miss delegates to `s.ListUsers` (line 158).
4. **`Store.ListUsers`** — `store/user.go` — Calls `s.driver.ListUsers` on the database driver interface (line 137).
5. **`Driver.ListUsers`** — `store/driver.go` — The `Driver` interface method (line 47) implemented by each DB backend.
6. **`DB.ListUsers`** — `store/db/sqlite/user.go` (or postgres/mysql equivalents) — Builds a SQL query with `WHERE username = ?`, executes it, and scans rows including the `avatar_url` column into `store.User`.

The returned `User.AvatarURL` (a `data:` URI with base64-encoded image bytes) is then decoded in `serveUserAvatar` via `parseDataURI` (`server/router/fileserver/fileserver.go` line 196) and served as the raw image blob.
