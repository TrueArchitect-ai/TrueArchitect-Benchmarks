The question's premise is incorrect: there is no Redis connection in this project. The cache layer is a **pure in-memory Go cache**, not Redis-backed.

The cache is implemented in `store/cache/cache.go` as a thread-safe in-memory store using `sync.Map` with TTL-based expiration and a background cleanup goroutine. It is instantiated in `store/store.go:38-61`, where the `Store` constructor creates three `cache.Cache` instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing the same `cache.Config`.

The **TTL for user entries is 10 minutes** (`10 * time.Minute`), set as the `DefaultTTL` in the shared config at `store/store.go:41`. The cleanup interval is 5 minutes, and the max item count is 1000. There is no per-entity TTL override for users — every `userCache.Set()` call (e.g., `store/user.go:98,122,132,143,167`) uses the default `Set` method, which applies the `DefaultTTL`.
