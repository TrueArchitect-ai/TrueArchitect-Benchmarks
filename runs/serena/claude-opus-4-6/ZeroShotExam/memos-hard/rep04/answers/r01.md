The premise is incorrect: there is no Redis connection in this repository. The cache layer is a **pure in-memory Go implementation**, not backed by Redis.

The cache is defined in `store/cache/cache.go` as a thread-safe in-memory store built on Go's `sync.Map` with TTL-based expiration and a background cleanup goroutine.

The `userCache` is instantiated in `store/store.go:52` via `cache.New(cacheConfig)`, using the same default `cache.Config` defined at `store/store.go:40–45`:

- **DefaultTTL: 10 minutes** (`10 * time.Minute`)
- CleanupInterval: 5 minutes
- MaxItems: 1000

This same configuration (and thus the same 10-minute TTL) applies to all three caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51–53`). There is no per-entity TTL override for user entries — they use the shared default of 10 minutes.
