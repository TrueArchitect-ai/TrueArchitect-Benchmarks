The premise is incorrect — this repository does **not** have a GraphQL API. The public API is defined using **Protocol Buffers (protobuf)** with **gRPC**, and an auto-generated **REST/OpenAPI** layer via gRPC-Gateway.

The API surface is defined by `.proto` files in `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto` (shared types)

From these proto definitions, the toolchain (configured in `proto/buf.gen.yaml`) generates:

1. **gRPC Go stubs** (e.g., `proto/gen/api/v1/*_grpc.pb.go`)
2. **gRPC-Gateway reverse proxies** (e.g., `proto/gen/api/v1/*_service.pb.gw.go`) that expose the gRPC services as RESTful HTTP/JSON endpoints under `/api/v1/`
3. **An OpenAPI 3.0 spec** at `proto/gen/openapi.yaml`

The README confirms this: the project advertises "full REST and gRPC APIs for integration" (`README.md`). There is no GraphQL schema anywhere in the codebase.
