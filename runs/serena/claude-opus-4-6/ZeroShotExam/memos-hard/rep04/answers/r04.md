The premise is incorrect — the webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain Go buffered channel** used as an in-process async queue. It is declared in `internal/webhook/webhook.go` at line 39:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

A pool of **4 goroutines** is spawned in the `init()` function (same file, lines 42–55), each consuming from this channel via `for payload := range asyncPostQueue`. The `PostAsync()` function (lines 184–196) enqueues payloads with a non-blocking `select` — if the buffer is full, the webhook is silently dropped with a warning log.

There are no NATS, RabbitMQ, AMQP, Kafka, or Redis dependencies anywhere in `go.mod`, and `scripts/compose.yaml` defines only a single `memos` service with no broker containers. The buffer size (128) and worker count (4) are hardcoded constants with no external configuration.
