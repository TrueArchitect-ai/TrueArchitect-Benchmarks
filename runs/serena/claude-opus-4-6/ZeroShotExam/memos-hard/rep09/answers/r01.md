The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is an **in-memory cache**, not a Redis-backed one.

The cache is implemented as a pure Go in-process `sync.Map`-based store in `store/cache/cache.go`. It is configured and instantiated in `store/store.go:38-45` inside the `New()` function:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

The `userCache` (along with `instanceSettingCache` and `userSettingCache`) is created at `store/store.go:52` with this same config, so user entries get a **default TTL of 10 minutes**. There is no external cache server involved — no Redis, Memcached, or any network-based cache. The `cache.Cache` struct (`store/cache/cache.go:67-73`) holds items in a `sync.Map` within the application process, with a background goroutine running cleanup every 5 minutes to evict expired entries.
