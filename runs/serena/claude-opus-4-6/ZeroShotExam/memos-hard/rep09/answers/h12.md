**Concrete method — path:** `DB.CreateMemo` — `store/db/sqlite/memo.go`

This method dynamically builds and executes:
```sql
INSERT INTO `memo` (`uid`, `creator_id`, `content`, `visibility`, `payload`)
VALUES (?, ?, ?, ?, ?)
RETURNING `id`, `created_ts`, `updated_ts`, `row_status`
```
via `d.db.QueryRowContext(ctx, stmt, args...).Scan(...)`.

**Determination method:** The default driver is resolved by tracing the config chain:

1. `cmd/memos/main.go` sets `viper.SetDefault("driver", "sqlite")` and the CLI flag also defaults to `"sqlite"`.
2. This value populates `profile.Driver`, which is passed to the factory in `store/db/db.go` (`NewDBDriver`). That factory switches on `profile.Driver` and for `"sqlite"` instantiates `sqlite.NewDB(profile)`.
3. The `Store` struct (`store/store.go`) holds this driver via the `Driver` interface (`store/driver.go`), and `Store.CreateMemo` (`store/memo.go`) delegates directly to `s.driver.CreateMemo(ctx, create)`.
4. Since the interface has three implementations — `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, and `store/db/mysql/memo.go` — the default `"sqlite"` driver value in the Viper/flag config is what selects the SQLite implementation as the one that actually runs.
