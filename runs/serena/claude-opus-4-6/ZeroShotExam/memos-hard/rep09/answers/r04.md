The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain in-process Go buffered channel** acting as an internal work queue. It is declared in `internal/webhook/webhook.go` at line 39:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

In the same file's `init()` function (lines 42–55), **4 goroutine workers** are spawned, each consuming from that channel in a `for payload := range asyncPostQueue` loop and calling `Post(payload)` to make the outbound HTTP request.

Producers enqueue work via `PostAsync()` (lines 184–196), which does a non-blocking send on the channel — if the 128-slot buffer is full, the webhook is silently dropped with a warning log. There is no external broker, no persistence, and no retry on failure.
