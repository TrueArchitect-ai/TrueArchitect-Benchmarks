The premise of the question is incorrect. This repository (usememos/memos) does **not** have any per-user API rate-limiting middleware. No such middleware is registered anywhere, and no request-per-time-window limits exist.

The codebase has no rate-limiting libraries in its direct dependencies (`golang.org/x/time` is only an indirect/transitive dependency and is never imported in application code). The only middleware registered on the server (`server/server.go:51-52`) is panic recovery (`middleware.Recover()`) and CORS handling (`newCORSMiddleware()`).

What the codebase *does* have — which is distinct from rate limiting — are:

- **Concurrency semaphores** in `server/router/api/v1/v1.go:39-41` (3 concurrent thumbnail generations, 2 concurrent image processing operations) and `server/router/fileserver/fileserver.go:45-46` (3 concurrent thumbnails). These cap simultaneous operations, not requests per time window.
- **Request body size limits** (`maxAPIRequestBytes = 256 MiB` in `server/router/api/v1/v1.go:20`).
- **Batch/page size limits** (e.g., `MaxPageSize = 1000` in `server/router/api/v1/common.go:15`).
