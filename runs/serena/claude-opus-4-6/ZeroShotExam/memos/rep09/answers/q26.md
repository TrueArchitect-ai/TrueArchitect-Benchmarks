The following database tables are affected when `DeleteMemo` runs:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
2. **`memo_relation`** — relations where the memo is source (`memo_id`) or target (`related_memo_id`) are explicitly deleted in `store/memo.go:142-146`, via `DeleteMemoRelation` (`store/db/sqlite/memo_relation.go:148-150`)
3. **`attachment`** — attachments linked to the memo are explicitly deleted in `store/memo.go:149-156`, via `DeleteAttachment` (`store/db/sqlite/attachment.go:212`)
4. **`memo_share`** — rows are deleted via `ON DELETE CASCADE` foreign key on `memo_id` referencing `memo(id)`, defined in all three database schemas (`store/migration/sqlite/LATEST.sql`, `store/migration/postgres/LATEST.sql`, `store/migration/mysql/LATEST.sql`)

Additionally, the service layer (`server/router/api/v1/memo_service.go:567-577`) recursively deletes **comment memos** (memos related via `MemoRelationComment`), which triggers the same cascade on `memo`, `memo_relation`, `attachment`, and `memo_share` for each comment.
