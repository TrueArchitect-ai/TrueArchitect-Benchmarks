**Interceptor path:** `web/src/connect.ts` — defines `authInterceptor`, a ConnectRPC `Interceptor` that calls `getRequestToken()` before each request and sets the `Authorization: Bearer <token>` header via `setAuthorizationHeader()`. On a 401 response it refreshes the token and retries once.

**Token kinds managed:**
1. **Access token (JWT, short-lived, 15 min)** — stored in-memory and in `localStorage` (`memos_access_token`); attached as `Bearer` in the `Authorization` header. State managed in `web/src/auth-state.ts`.
2. **Refresh token (JWT, long-lived, 30 days)** — stored as an HTTP-only cookie (`memos_refresh`); sent automatically via `credentials: "include"` on `fetch` calls. Never touched by JavaScript directly.
3. **Personal Access Token (PAT)** — prefixed `memos_pat_`, also sent as a `Bearer` token; validated server-side by SHA-256 hash lookup.

**Backend validation package:** `server/auth` (Go import path `github.com/usememos/memos/server/auth`). Key files:
- `server/auth/token.go` — JWT generation/parsing (`ParseAccessTokenV2`, `ParseRefreshToken`) using `golang-jwt/jwt/v5` with HS256 signing.
- `server/auth/authenticator.go` — `Authenticate(ctx, authHeader)` entry point that tries access-token JWT first, then falls back to PAT lookup.
- `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie` helpers.

The backend interceptor that invokes this package is `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`), which calls `Authenticator.Authenticate()` on every unary RPC.
