**Background workers the server actually starts:**

- **S3 Presign Runner** — 12-hour `time.Ticker` interval; explicitly launched by `server.startBackgroundRunners()` in `server/server.go:153-174` (also runs once synchronously at startup). Re-presigns expiring S3 attachment URLs (`server/runner/s3presign/runner.go`).
- **Webhook Async Queue Workers** — 4 goroutines consuming from a buffered channel (capacity 128), started via package `init()` in `internal/webhook/webhook.go:39-55`. Driven by `PostAsync()` calls from memo CRUD webhook dispatchers in `server/router/api/v1/memo_service_webhooks.go`.
- **Cache Cleanup Goroutines** — 3 instances (one per cache: `instanceSettingCache`, `userCache`, `userSettingCache`), each on a 5-minute `time.Ticker`; started when `store.New()` creates the caches (`store/cache/cache.go:82-84`, `store/store.go:51-53`). Evicts expired entries.
- **SSE Heartbeat Tickers** — per-connection 30-second `time.Ticker` in each SSE handler (`server/router/api/v1/sse_handler.go`); sends keepalive pings to connected clients.

**Unused scheduling infrastructure:**

- The `internal/scheduler/` package is a fully-implemented cron job framework (cron expression parser, timezone support, middleware chain with Recovery/Logging/Timeout, graceful shutdown) that is **never imported or used by any production code** — only its own test files reference it.
- The `server/runner/memopayload/` package defines a `Runner` type with a `RunOnce()` method for bulk memo payload rebuilds, but the **`Runner` is never instantiated by the server**. Only the standalone `RebuildMemoPayload()` function from that package is called, inline in API handlers for individual memo create/update operations.
