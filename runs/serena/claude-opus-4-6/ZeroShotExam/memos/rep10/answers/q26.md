The following database tables are affected when `DeleteMemo` runs:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
2. **`memo_relation`** — relations where the memo is either source (`memo_id`) or target (`related_memo_id`) are explicitly deleted (`store/memo.go:142-146`, `store/db/sqlite/memo_relation.go:148-150`)
3. **`attachment`** — all attachments linked to the memo are deleted (`store/memo.go:149-156`, `store/db/sqlite/attachment.go:212`)
4. **`memo_share`** — deleted via `ON DELETE CASCADE` foreign key on `memo_id` referencing `memo(id)` (`store/migration/sqlite/LATEST.sql:109`)

Additionally, the service-level `DeleteMemo` (`server/router/api/v1/memo_service.go:567-577`) first finds comment memos (via `memo_relation` with type `Comment`) and recursively calls `store.DeleteMemo` for each comment, so the same four tables are affected for each child comment memo as well.
