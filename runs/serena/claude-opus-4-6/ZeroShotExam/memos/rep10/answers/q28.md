**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (`server/runner/s3presign/runner.go`); started by `server.startBackgroundRunners()` in `server/server.go:153-174`, re-signs expiring S3 presigned URLs for attachments
- **Cache Cleanup (×3 instances)** — `time.NewTicker` every 5 minutes (`store/cache/cache.go`); one goroutine per cache (instanceSettingCache, userCache, userSettingCache), started implicitly via `cache.New()` during store initialization in `store/store.go:51-53`
- **Webhook Dispatch Workers (×4)** — event-driven channel consumers (`internal/webhook/webhook.go`); started in package `init()`, consuming from a buffered channel (`asyncPostQueue`, cap 128) fed by `PostAsync()` on memo create/update/delete/comment
- **Email Dispatch Workers (×2)** — event-driven channel consumers (`internal/email/email.go`); started in package `init()`, consuming from a buffered channel (`asyncEmailQueue`, cap 128) fed by `SendAsync()` for notification emails

**Unused scheduling infrastructure:**

The `internal/scheduler/` package is a fully implemented cron job scheduler (with cron expression parser, middleware support, `Register()`/`Start()`/`Stop()` lifecycle) that is **never imported or used** anywhere outside its own directory. No code in the server references `"internal/scheduler"`.

Additionally, `server/runner/memopayload/runner.go` exists in the runner directory but is **not started as a background runner** — its `RebuildMemoPayload()` is only called inline during memo create/update in `server/router/api/v1/memo_service.go`, not on a schedule.
