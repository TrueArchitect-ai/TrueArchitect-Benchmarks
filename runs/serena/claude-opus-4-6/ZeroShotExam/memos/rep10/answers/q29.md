**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` function attaches a `Bearer` access token via the `Authorization` header on every ConnectRPC request, handles 401 responses by refreshing and retrying once, with token state managed in `web/src/auth-state.ts`.

**Token kinds:** The interceptor manages two token types:
1. **Access token** (short-lived JWT, 15 min) — stored in-memory and in `localStorage` (`memos_access_token`), sent as `Bearer` in the `Authorization` header.
2. **Refresh token** (long-lived JWT, 30 days) — managed as an **HTTP-only cookie**, sent implicitly via `credentials: "include"` on refresh calls. The frontend never reads it directly; it issues a `refreshToken` RPC and the cookie is sent automatically.

**Backend validation package:** `server/auth/` (Go package `github.com/usememos/memos/server/auth`). Key file `server/auth/token.go` validates JWTs (HS256-signed, issuer `"memos"`) for both access tokens (audience `user.access-token`) and refresh tokens (audience `user.refresh-token`), plus **personal access tokens** (PATs, prefix `memos_pat_`, validated via SHA-256 hash lookup). The `Authenticator` in `server/auth/authenticator.go` is wired into the request pipeline via the Connect interceptor at `server/router/api/v1/connect_interceptors.go`.
