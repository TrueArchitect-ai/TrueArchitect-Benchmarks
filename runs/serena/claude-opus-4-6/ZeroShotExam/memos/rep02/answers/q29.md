**Interceptor path:** `web/src/connect.ts` — defines `authInterceptor` (a ConnectRPC `Interceptor`) that is attached to the main `createConnectTransport`. It calls `getRequestToken()` before each request and sets the `Authorization: Bearer <token>` header, with reactive retry on `Unauthenticated` errors.

**Token kinds:**
1. **Access token** (short-lived JWT, 15 min) — stored in-memory and in `localStorage` (`memos_access_token`), managed in `web/src/auth-state.ts`.
2. **Refresh token** (long-lived JWT, 30 days) — stored as an HTTP-only cookie, never touched by JavaScript; sent automatically via `credentials: "include"` on the dedicated refresh transport.

The interceptor also supports **Personal Access Tokens (PAT)** on the backend side (random strings prefixed `memos_pat_`, stored as SHA-256 hashes), which are passed as Bearer tokens through the same header.

**Backend validation package:** `server/auth` — specifically `server/auth/authenticator.go` (the `Authenticator` struct with methods `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`) and `server/auth/token.go` (JWT parsing/verification using `github.com/golang-jwt/jwt/v5`). This package is consumed by the server-side ConnectRPC interceptor at `server/router/api/v1/connect_interceptors.go`.
