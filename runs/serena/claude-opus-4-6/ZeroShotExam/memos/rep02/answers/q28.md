**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — 12-hour `time.NewTicker` interval (runs once immediately at startup, then every 12h); refreshes expiring presigned URLs for S3-stored attachments. Started in `server/server.go:153–173`, defined in `server/runner/s3presign/runner.go`.
- **Webhook Async Dispatch Workers (×4)** — event-driven via a buffered channel (`asyncPostQueue`, cap 128); started by package `init()` in `internal/webhook/webhook.go:42–55`, imported through `server/router/api/v1/memo_service_webhooks.go`.
- **Email Async Dispatch Workers (×2)** — event-driven via a buffered channel (`asyncEmailQueue`, cap 128); started by package `init()` in `internal/email/email.go:16–36`, imported through `server/notification/email.go`.
- **Cache Cleanup Workers (×3)** — 5-minute `time.NewTicker` interval; one per in-memory cache (`instanceSettingCache`, `userCache`, `userSettingCache`), started by `cache.New()` calls in `store/store.go:51–53`, cleanup loop in `store/cache/cache.go:200–215`.

**Unused scheduling infrastructure:**

The `internal/scheduler/` package is a fully-featured cron-expression-based job scheduler (with cron parsing, middleware support for recovery/logging/timeout, and graceful shutdown). It is **never imported by any production code** — no file outside the `internal/scheduler/` directory itself references it. It is tested but completely unwired from the server.

Additionally, the `server/runner/memopayload/` package defines a `Runner` struct with a `RunOnce()` method for bulk memo-payload rebuilds, but that `Runner` is **never instantiated or started** as a background worker. Only the standalone `RebuildMemoPayload()` function from the same package is used, and it is called synchronously per-request in `server/router/api/v1/memo_service.go`, not as a background task.
