When `DeleteMemo` runs, the following database tables are affected:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
2. **`memo_relation`** — all relation rows where the memo is either `memo_id` or `related_memo_id` are explicitly deleted (`store/memo.go:142-146`, via driver at `store/db/sqlite/memo_relation.go`)
3. **`attachment`** — all attachments linked to the memo are explicitly deleted (`store/memo.go:149-156`, via driver at `store/db/sqlite/attachment.go`)
4. **`memo_share`** — rows are removed via `ON DELETE CASCADE` foreign key constraint on `memo_id` referencing `memo(id)` (`store/migration/sqlite/LATEST.sql:109`)

Additionally, the service-layer `DeleteMemo` in `server/router/api/v1/memo_service.go:567-577` recursively deletes comment memos (other `memo` rows linked via `memo_relation` with type `Comment`), which triggers the same cascade for each comment.
