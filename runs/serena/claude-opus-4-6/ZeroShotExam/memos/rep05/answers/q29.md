**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (a Connect-protocol interceptor, not Axios) attaches an `Authorization: Bearer <token>` header to every outgoing RPC request and handles 401-based token refresh with retry logic.

**Token kinds managed:**
1. **Access token** — a short-lived JWT stored in-memory and persisted to `localStorage` (keys `memos_access_token` / `memos_token_expires_at`, defined in `web/src/auth-state.ts`). Attached as a Bearer header.
2. **Refresh token** — an HTTP-only cookie (`memos_refresh`) managed by the browser; never directly accessed by JavaScript. Used via `credentials: "include"` on a dedicated `refreshTransport` to obtain new access tokens.
3. **Personal Access Token (PAT)** — prefixed `memos_pat_`, resolved server-side alongside regular access tokens.

**Backend validation package:** `server/auth/` (Go package `github.com/usememos/memos/server/auth`). Key files:
- `server/auth/token.go` — JWT generation and parsing (`ParseAccessTokenV2`, `ParseRefreshToken`) using `golang-jwt/jwt/v5` with HS256 signing.
- `server/auth/authenticator.go` — the `Authenticator` struct that dispatches validation: stateless JWT check for access tokens, DB revocation check for refresh tokens, SHA-256 hash lookup for PATs.
- `server/auth/extract.go` — extracts bearer tokens from the `Authorization` header and refresh tokens from cookies.

The backend interceptor that invokes this package is at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`), which calls `Authenticator.Authenticate()` and then applies user claims to the request context.
