When a memo is deleted through the API, the store layer (`store/memo.go`) deletes the following kinds of records before the memo row itself:

1. **Memo relations** (where the memo is the *source*) — calls `DeleteMemoRelation` with `MemoID` set to the memo's ID
2. **Memo relations** (where the memo is the *target*) — calls `DeleteMemoRelation` with `RelatedMemoID` set to the memo's ID
3. **Attachments** — lists all attachments for the memo via `ListAttachments`, then for each one calls `DeleteAttachment`, which in turn deletes:
   - The attachment's backing **storage** (local file or S3 object, via `DeleteAttachmentStorage`)
   - Derived **cache files** (thumbnail `.jpeg` and motion `.mp4`)
   - The attachment **database row**

Additionally, at the API layer (`server/router/api/v1/memo_service.go`), **comment memos** (memos related via a `COMMENT` relation) are recursively deleted before the parent memo, each triggering the same store-level cleanup above.
