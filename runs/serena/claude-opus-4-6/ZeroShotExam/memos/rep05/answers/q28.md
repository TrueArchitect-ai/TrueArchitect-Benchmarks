**Background workers the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (`server/runner/s3presign/runner.go`); started in `server.go:startBackgroundRunners` to re-presign expiring S3 attachment URLs
- **Webhook dispatch workers (×4)** — channel-drain / demand-driven (`internal/webhook/webhook.go`); started via package `init()`, consume from a buffered channel fed by `PostAsync()`
- **Email dispatch workers (×2)** — channel-drain / demand-driven (`internal/email/email.go`); started via package `init()`, consume from a buffered channel fed by `SendAsync()`
- **Cache cleanup goroutines (×3)** — `time.NewTicker` every 5 minutes (`store/cache/cache.go`); one per cache instance created in `store/store.go` (instanceSettingCache, userCache, userSettingCache)

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — a complete cron-expression-based job scheduler with middleware support (recovery, logging, timeout). It is **never imported outside its own package**; no production code instantiates it or registers any jobs. Only its own unit/example tests exercise it.
- **`server/runner/memopayload/runner.go`** — defines a `Runner` struct with `RunOnce()` for bulk memo-payload rebuilding, but the server **never instantiates this runner**. Only the standalone function `memopayload.RebuildMemoPayload()` is used, and it's called inline during individual memo create/update operations in `memo_service.go`, not as a background worker.
