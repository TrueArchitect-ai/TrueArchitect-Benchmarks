**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (defined around line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` access token via the `Authorization` header on every outgoing RPC call, and handles 401 (`Unauthenticated`) errors by refreshing the token and retrying once.

**Token kinds managed:**
1. **Access tokens** (short-lived JWTs, stored in-memory and `localStorage` under `memos_access_token` — managed by `web/src/auth-state.ts`).
2. **Refresh tokens** (long-lived JWTs, stored server-side in an HttpOnly cookie named `memos_refresh`; the frontend never reads them directly but sends them via `credentials: "include"`).
3. **Personal Access Tokens (PATs)** (opaque tokens prefixed `memos_pat_`, not JWTs — validated by SHA-256 hash lookup in the database).

**Backend validation package:** `server/auth/` (Go package `github.com/usememos/memos/server/auth`). Key files: `token.go` (JWT parsing/validation with `golang-jwt/jwt/v5`, HS256), `authenticator.go` (central `Authenticator` struct dispatching to JWT or PAT validation), and `extract.go` (extracts Bearer tokens from headers and refresh tokens from cookies). The `Authenticator` is consumed by the authorizer middleware at `server/router/api/v1/authz.go`.
