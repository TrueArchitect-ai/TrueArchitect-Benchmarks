**Workers the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (plus one immediate `RunOnce` at startup); refreshes expiring S3 presigned URLs. Started in `server/server.go:startBackgroundRunners` via `server/runner/s3presign/runner.go`.
- **Webhook Dispatch Workers (x4)** — event-driven via buffered channel (`asyncPostQueue`, cap 128); started at package `init()` time in `internal/webhook/webhook.go`. Fire when `PostAsync()` is called on memo CRUD events.
- **Email Dispatch Workers (x2)** — event-driven via buffered channel (`asyncEmailQueue`, cap 128); started at package `init()` time in `internal/email/email.go`. Fire when `SendAsync()` is called for inbox notification emails.
- **Cache Cleanup Goroutines (x3)** — `time.NewTicker` every 5 minutes; one per cache instance (`instanceSettingCache`, `userCache`, `userSettingCache`) created in `store/store.go`, cleanup loop in `store/cache/cache.go`.

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — a fully-featured cron-based job scheduler (cron expression parsing, middleware chain with recovery/logging/timeout, graceful shutdown) that is **never imported by any production code**. It is only referenced in its own test files (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). No server code uses it.
- **`server/runner/memopayload/` Runner struct** — defines a `Runner` with `RunOnce()` for batch-rebuilding all memo payloads, but the `Runner`/`NewRunner()` are **never instantiated**. Only the standalone `RebuildMemoPayload()` function is called inline during individual memo create/update in `server/router/api/v1/memo_service.go`. The runner is not wired into `startBackgroundRunners()`.
