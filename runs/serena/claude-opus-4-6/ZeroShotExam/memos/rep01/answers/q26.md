When `DeleteMemo` runs, the following database tables are affected:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`, `store/db/postgres/memo.go:246`)
2. **`memo_relation`** — explicit cascade code deletes all `memo_relation` rows where the memo is either the source (`memo_id`) or target (`related_memo_id`) (`store/memo.go:142–146`, `store/db/sqlite/memo_relation.go:149`)
3. **`attachment`** — explicit cascade code lists and deletes all attachments linked to the memo (`store/memo.go:149–156`, `store/db/sqlite/attachment.go:212`)
4. **`memo_share`** — cleaned up via `ON DELETE CASCADE` foreign key on `memo_id` referencing `memo(id)` (`store/migration/sqlite/LATEST.sql:109`)

Additionally, at the service layer (`server/router/api/v1/memo_service.go:567–577`), comment memos (related via `memo_relation` with type `Comment`) are recursively deleted by calling `DeleteMemo` for each comment, which triggers the same cascade on those child memos.

**Table list: `memo`, `memo_relation`, `attachment`, `memo_share`**
