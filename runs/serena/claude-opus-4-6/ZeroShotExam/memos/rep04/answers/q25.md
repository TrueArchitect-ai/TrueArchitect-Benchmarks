**Engine:** Google CEL (Common Expression Language) via the `cel-go` library; the engine lives at `internal/filter/engine.go` (with schema in `internal/filter/schema.go`, parser in `internal/filter/parser.go`, IR types in `internal/filter/ir.go`, and renderer in `internal/filter/render.go`).

**Mechanism:** The CEL filter string is compiled and type-checked by `cel-go`, then `buildCondition()` (`internal/filter/parser.go`) walks the CEL AST to produce an intermediate-representation condition tree (`internal/filter/ir.go`), which a dialect-aware renderer (`internal/filter/render.go`) converts to SQL fragments (with dialect-specific placeholder syntax, JSON operators, text-matching, and timestamp functions for SQLite, PostgreSQL, and MySQL), appended to the query's WHERE clause via `filter.AppendConditions()` (`internal/filter/helpers.go`) called by each store driver (`store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`).
