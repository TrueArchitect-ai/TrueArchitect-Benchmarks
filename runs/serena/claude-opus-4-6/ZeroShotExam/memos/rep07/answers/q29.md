**Interceptor path:** `web/src/connect.ts` — defines a Connect RPC `Interceptor` (the `authInterceptor`) that attaches a `Bearer` token to the `Authorization` header of every outgoing request and handles transparent refresh/retry on 401.

**Token kinds managed:**
1. **Access token** (short-lived, 15 min) — stored in-memory and in `localStorage` (`"memos_access_token"`), sent as `Authorization: Bearer <token>`. Proactively refreshed when expired or within 30 s of expiry. Cross-tab synced via a `BroadcastChannel` (`web/src/auth-state.ts`).
2. **Refresh token** (long-lived, 30 days) — an `HttpOnly` cookie named `"memos_refresh"`, never touched by JS directly; sent automatically via `credentials: "include"`. Used by calling `AuthService.RefreshToken` over a separate non-intercepted transport to avoid recursion.
3. **Personal Access Token (PAT)** — long-lived tokens prefixed `"memos_pat_"`, validated on the backend but not generated/stored by the frontend.

**Backend validation package:** `server/auth/` — specifically:
- `server/auth/authenticator.go` — `Authenticator` with methods `AuthenticateByAccessTokenV2` (stateless JWT), `AuthenticateByRefreshToken` (DB-checked for revocation), and `AuthenticateByPAT` (SHA-256 hash lookup).
- `server/auth/token.go` — JWT generation/parsing using `golang-jwt/jwt/v5` (HS256).
- `server/auth/extract.go` — extracts the bearer token from the `Authorization` header and the refresh token from the cookie.

The server-side Connect RPC interceptor that invokes this package is at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`), which calls into the `Authorizer` (`server/router/api/v1/authz.go`) wrapping the `auth.Authenticator`.
