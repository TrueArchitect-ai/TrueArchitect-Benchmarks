Four memo lifecycle events dispatch webhooks, all with dispatch functions defined in `server/router/api/v1/memo_service_webhooks.go`:

- **created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

The first three (`Created`, `Updated`, `Deleted`) funnel through a shared private helper `dispatchMemoRelatedWebhook` in the same file. All four ultimately call **`webhook.PostAsync`** (`internal/webhook/webhook.go`), which enqueues the payload onto a buffered channel. A pool of goroutine workers drains that channel and calls the single synchronous delivery function **`Post`** in `internal/webhook/webhook.go` — this is where all webhook dispatches converge. `Post` serializes the payload to JSON, computes HMAC-SHA256 signatures (Standard Webhooks format) if a signing secret is configured, and sends the HTTP POST request via an SSRF-safe HTTP client.
