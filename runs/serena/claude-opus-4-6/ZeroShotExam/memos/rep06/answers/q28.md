**Runner actually started by the server:**

- **s3presign runner** — scheduled by a `time.Ticker` with a 12-hour interval (plus one immediate `RunOnce` call at startup). It refreshes pre-signed S3 URLs for attachments. Started in `server/server.go:153-174` via `startBackgroundRunners`, which launches `s3presign.NewRunner(s.Store)`.

**Unused scheduling infrastructure:**

- **memopayload runner** (`server/runner/memopayload/runner.go`) — has a `Runner` struct with a `RunOnce` method that rebuilds all memo payloads, but the server **never instantiates or starts it** as a background runner. Its `Runner` type is never constructed anywhere; only the standalone function `memopayload.RebuildMemoPayload` is called inline from `server/router/api/v1/memo_service.go:108` and `:447` during individual memo create/update API requests. The runner infrastructure (batch-processing all memos) exists in the codebase but is dead code — not wired into `startBackgroundRunners` or invoked from any entry point.
