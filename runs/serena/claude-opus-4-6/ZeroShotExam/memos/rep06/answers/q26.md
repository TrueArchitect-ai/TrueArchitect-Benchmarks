The following database tables are affected when `DeleteMemo` runs:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`, `store/db/postgres/memo.go:246`, `store/db/mysql/memo.go:261`)
2. **`memo_relation`** — all relations where the memo is either `memo_id` or `related_memo_id` are explicitly deleted before the memo (`store/memo.go:142-147`, executing `DELETE FROM memo_relation`)
3. **`attachment`** — all attachments linked to the memo are explicitly deleted (`store/memo.go:149-157`, executing `DELETE FROM attachment`)
4. **`memo_share`** — rows are deleted via `ON DELETE CASCADE` foreign key on `memo_id` referencing `memo(id)` (defined in `store/migration/sqlite/LATEST.sql`)

Additionally, the service layer at `server/router/api/v1/memo_service.go:567-577` recursively deletes **comment memos** (memos related via `MemoRelationComment`) by calling `Store.DeleteMemo` for each comment, which in turn cascades the same cleanup (memo_relation, attachment, memo_share) for those child memos.

**Table list:** `memo`, `memo_relation`, `attachment`, `memo_share`
