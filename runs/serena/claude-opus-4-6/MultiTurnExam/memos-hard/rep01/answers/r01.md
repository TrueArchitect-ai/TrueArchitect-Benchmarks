The question's premise is incorrect. There is no Redis connection in this codebase. The cache layer is entirely **in-memory**, implemented as a `sync.Map`-backed cache in `store/cache/cache.go`. It uses no external store like Redis.

User entries are cached using the default `cache.Config` (constructed via `cache.DefaultConfig()` at `store/cache/cache.go:57-64`), which sets a **`DefaultTTL` of 10 minutes** and a cleanup interval of 5 minutes. The `Store` struct creates its `userCache` (along with `userSettingCache` and `instanceSettingCache`) as `cache.NewDefault()` instances in `store/store.go`. Cache entries are invalidated eagerly on writes (e.g., `Store.UpdateUser` deletes the cache entry), and expire passively via the TTL and periodic cleanup goroutine.
