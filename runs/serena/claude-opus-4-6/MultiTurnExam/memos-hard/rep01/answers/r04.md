The question's premise is incorrect. There is no message broker (neither NATS nor RabbitMQ) involved in webhook delivery. The webhook delivery workers consume from a plain **in-memory Go buffered channel**.

The channel is declared as `asyncPostQueue` at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutines are started in `init()` (same file, lines 42–55) to drain this channel, each calling the `Post` function to execute the outbound HTTP request. Payloads are enqueued via `PostAsync` (line ~184), which simply sends the payload into the channel. There is no external queue or broker — the mechanism is entirely in-process.
