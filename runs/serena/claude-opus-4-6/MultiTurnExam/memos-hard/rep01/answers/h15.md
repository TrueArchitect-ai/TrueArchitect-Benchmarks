Memo visibility is enforced at these distinct sites:

1. **`APIV1Service.checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:39` — gate for `GetMemo` (line 356), `ListMemoComments` (line 148 of `memo_service_comments.go`)

2. **`APIV1Service.ListMemos` query-level filtering** — `server/router/api/v1/memo_service.go:218-227` — restricts which memos are returned based on the caller's identity (anonymous sees only `Public`; authenticated non-creator sees `Public`+`Protected`)

3. **`APIV1Service.CreateMemoComment` inline check** — `server/router/api/v1/memo_service_comments.go:41` — blocks commenting on `Private` memos by non-creators

4. **`APIV1Service.ListMemoReactions` / `UpsertMemoReaction` inline checks** — `server/router/api/v1/reaction_service.go:30` and `:83` — enforces visibility before listing or adding reactions

5. **`APIV1Service.ListMemoAttachments` inline check** — `server/router/api/v1/memo_attachment_service.go:213` — enforces visibility before listing a memo's attachments

6. **`APIV1Service.checkAttachmentAccess`** — `server/router/api/v1/attachment_service.go:422` — enforces memo visibility when accessing a linked attachment via the gRPC `GetAttachment` endpoint

7. **`FileServerService.checkAttachmentPermission`** — `server/router/fileserver/fileserver.go:650` — enforces memo visibility when serving attachment files over native HTTP

8. **`SSEClient.canReceive`** — `server/router/api/v1/sse_hub.go:134` — filters SSE live-update events so `Private` memo events are only delivered to their creator (or admin)

9. **`RSSService` query-level filtering** — `server/router/rss/rss.go:90,141` — RSS feeds only query `Public` memos via `VisibilityList`
