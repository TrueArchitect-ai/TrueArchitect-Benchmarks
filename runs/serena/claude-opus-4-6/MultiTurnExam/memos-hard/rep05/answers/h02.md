**Delivery function** — `Post` in `internal/webhook/webhook.go` (line ~120). It builds a JSON payload, signs it with HMAC-SHA256, and executes the outbound HTTP POST via `safeClient.Do(req)`. Callers go through `PostAsync` (line ~184), which queues work to a buffered channel drained by background goroutines.

**Protection mechanism** — A two-layer SSRF guard, both in `internal/webhook/webhook.go` and `internal/webhook/validate.go`:

1. **Registration-time validation** — `ValidateURL` (`internal/webhook/validate.go:62`). When a webhook is created or updated, it DNS-resolves the hostname and rejects any IP in a reserved CIDR range (loopback, RFC-1918, link-local/IMDS, IPv6 ULA/link-local — defined at `validate.go:14-23`). Called from `server/router/api/v1/user_service_webhooks.go` at lines 74, 161, and 182.

2. **Delivery-time dial guard** — `safeDialContext` (`internal/webhook/webhook.go:59`). A custom `DialContext` on the `safeClient` HTTP transport re-resolves the hostname at connection time and blocks connections to reserved IPs, defeating DNS-rebinding attacks where a hostname changes from a public to a private IP between registration and delivery.

Both layers check against the same `reservedCIDRs` list and can be toggled off via `AllowPrivateIPs` for self-hosted setups.
