By explicit Go code; reactions are removed in two ways within the `DeleteUser` transaction:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions on the user's memos by their content IDs (`DELETE FROM reaction WHERE content_id IN ...`). See `store/db/sqlite/user_delete.go:96,380-388` and `store/db/mysql/user_delete.go:96,417-425`.

2. **`deleteReactionsByCreatorTx`** — deletes reactions the user themselves created (`DELETE FROM reaction WHERE creator_id = ...`). See `store/db/sqlite/user_delete.go:102,400-403` and `store/db/mysql/user_delete.go:102,437-439`.

Both are called from `deleteUserTargetsTx` (lines 92–127 in each driver) inside a single transaction. I also checked the migration/schema files for `ON DELETE CASCADE` on the `reaction` table and found none — the cleanup is handled entirely by explicit Go code in the DB driver's user-deletion logic.
