By **explicit Go code**; reactions are removed in two ways within the `deleteUserTargetsTx` function during user deletion:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions on the user's memos (by `content_id`), e.g. `store/db/sqlite/user_delete.go:96` and `:380–388` (`DELETE FROM reaction WHERE content_id IN ...`).
2. **`deleteReactionsByCreatorTx`** — deletes reactions the user themselves created (by `creator_id`), e.g. `store/db/sqlite/user_delete.go:102` and `:400–402` (`DELETE FROM reaction WHERE creator_id = ?`).

The same logic is replicated in all three database drivers:
- `store/db/sqlite/user_delete.go:96,102` (calls), `:380–402` (implementations)
- `store/db/mysql/user_delete.go:96,102` (calls), `:417–439` (implementations)
- `store/db/postgres/user_delete.go:96,102` (calls), `:380–402` (implementations)

There are no foreign-key `ON DELETE CASCADE` rules handling this — the deletion is done entirely through explicit `DELETE FROM reaction` SQL statements in Go code, executed within the same transaction that removes the user.
