Neither — the premise is incorrect. There is no message broker (NATS, RabbitMQ, or otherwise) involved in webhook delivery.

The webhook workers consume from a plain **Go buffered channel** declared at `internal/webhook/webhook.go:39`:

```go
var asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutines are started in an `init()` function (lines 42–55 of the same file) that drain this channel and call `Post()` for each payload. `PostAsync()` (line 184) enqueues payloads into this channel with a non-blocking send, dropping the message if the buffer is full. The entire mechanism is in-process with no external broker.
