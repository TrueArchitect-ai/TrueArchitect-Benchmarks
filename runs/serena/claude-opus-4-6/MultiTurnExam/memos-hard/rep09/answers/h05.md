**Mechanism: explicit Go code** in the database driver's `DeleteUser` transaction.

**Evidence:**

1. **No database-level CASCADE rule** — The `reaction` table schema has no foreign key constraints at all (no `REFERENCES`, no `ON DELETE CASCADE`):
   - `store/migration/sqlite/LATEST.sql:92–98`
   - `store/migration/postgres/LATEST.sql:91–97`
   - `store/migration/mysql/LATEST.sql:91–97`

2. **Explicit Go deletion in the `DeleteUser` transaction** — Each driver's `user_delete.go` file performs two reaction cleanup steps within the delete-user transaction:
   - Deletes reactions on the user's content via `deleteReactionsByContentIDsTx` (e.g., `store/db/sqlite/user_delete.go:96`, line 380–383: `DELETE FROM reaction WHERE content_id IN ...`)
   - Deletes reactions created by the user via `deleteReactionsByCreatorTx` (e.g., `store/db/sqlite/user_delete.go:102`, line 400–401: `DELETE FROM reaction WHERE creator_id = ...`)
   - Same pattern in `store/db/postgres/user_delete.go:96,102` and `store/db/mysql/user_delete.go:96`

3. **The Go-level `DeleteUser` handler** in `server/router/api/v1/user_service.go:414` calls `s.Store.DeleteUser()`, which delegates to the driver, where the transactional cleanup above runs.
