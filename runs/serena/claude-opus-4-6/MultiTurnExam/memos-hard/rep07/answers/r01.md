The premise is incorrect — there is no Redis connection in this codebase. The cache layer uses an **in-memory cache**, not Redis.

The cache is implemented in `store/cache/cache.go` as a generic `Cache[K, V]` struct backed by a `sync.Map`. User entries are cached in `store/store.go` where the `userCache` is constructed via `cache.New[int32, *User]()`. The `Cache` type does not apply any TTL — entries persist in memory until explicitly invalidated via `Delete()` or `Invalidate()`, which happens in operations like `Store.UpdateUser` and `Store.DeleteUser` (`store/user.go`).
