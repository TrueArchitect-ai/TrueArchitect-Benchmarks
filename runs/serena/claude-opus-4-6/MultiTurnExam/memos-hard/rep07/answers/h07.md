1. `serveUserAvatar` — `server/router/fileserver/fileserver.go`
2. `getUserByUsername` — `server/router/fileserver/fileserver.go`
3. `Store.GetUser` — `store/user.go`
4. `Store.ListUsers` — `store/user.go`
5. `driver.ListUsers` — `store/db/sqlite/user.go` (or postgres/mysql equivalents)

The browser hits `GET /file/users/:identifier/avatar` (route registered in `fileserver.go`). The handler `serveUserAvatar` extracts the username, calls `getUserByUsername` (a thin wrapper in the same file), which calls `Store.GetUser` (`store/user.go`), which calls `Store.ListUsers`, which delegates to the concrete driver's `ListUsers` (e.g. `store/db/sqlite/user.go`) to `SELECT … avatar_url … FROM user WHERE username = ?`. The returned `AvatarURL` — a base64 data URI stored inline in the database — is decoded by `parseDataURI` back in the handler, validated against an allowed-type list, and written to the response as raw image bytes.
