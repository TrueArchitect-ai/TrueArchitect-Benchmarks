The premise is incorrect — there is no message broker (neither NATS nor RabbitMQ) in this codebase. Webhook delivery uses a simple in-process Go channel, not an external message queue.

In `internal/webhook/webhook.go`, `asyncPostQueue` is declared as a buffered channel (`chan WebhookRequestPayload`) with capacity 128. Four goroutines are started in `init()` (same file, lines ~42–55) to drain the channel and call `webhook.Post()` for each payload. Callers enqueue webhooks via `webhook.PostAsync()` (line ~184), which writes directly to this channel. The entire mechanism is in-memory within a single process — no external broker is involved.
