**Delivery function** — `Post` in `internal/webhook/webhook.go` (line ~120). In practice, callers use `PostAsync` (line ~184), which enqueues payloads into a buffered channel drained by background goroutines that each call `Post`. The memo service triggers this via dispatch helpers in `server/router/api/v1/memo_service_webhooks.go`.

**Protection mechanism** — SSRF guard implemented in two layers, both in the `internal/webhook/` package:

1. **Registration-time validation**: `ValidateURL` in `internal/webhook/validate.go` (line ~62) resolves the hostname and checks every resulting IP against `reservedCIDRs` (RFC-1918 private ranges, loopback, link-local/IMDS `169.254.0.0/16`, IPv6 ULA and link-local) defined at `internal/webhook/validate.go:14–23`, using the `isReservedIP` helper (line ~44).

2. **Connection-time re-check** (defeats DNS rebinding): `safeDialContext` in `internal/webhook/webhook.go` (line ~59) re-resolves the hostname and re-checks against the same reserved ranges *at dial time*, before allowing the TCP connection. The `Post` function uses a custom `http.Client` (`safeClient`, line ~32) whose transport is wired to this safe dialer.
