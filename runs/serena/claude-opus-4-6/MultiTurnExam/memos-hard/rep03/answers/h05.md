**Mechanism: explicit Go code.**

When a user is deleted, reactions are removed in two explicit SQL `DELETE` statements executed within a transaction — there are no `FOREIGN KEY … ON DELETE CASCADE` constraints on the `reaction` table to handle this automatically.

**Evidence locations:**

1. **Schema** — `store/migration/sqlite/LATEST.sql:92–98`: The `reaction` table has no foreign key with a cascade rule; it only has a `UNIQUE` constraint on `(creator_id, content_id, reaction_type)`.

2. **Explicit Go deletion** — `store/db/sqlite/user_delete.go`:
   - Line 96: `deleteReactionsByContentIDsTx` removes reactions on the deleted user's memos (by `content_id`).
   - Line 102: `deleteReactionsByCreatorTx` removes reactions the deleted user placed on other people's memos (by `creator_id`).
   - Lines 380–383: The actual `DELETE FROM reaction WHERE content_id IN …` SQL.
   - Lines 400–401: The actual `DELETE FROM reaction WHERE creator_id = …` SQL.

3. The same pattern exists in the Postgres and MySQL drivers (`store/db/postgres/user_delete.go`, `store/db/mysql/user_delete.go`).
