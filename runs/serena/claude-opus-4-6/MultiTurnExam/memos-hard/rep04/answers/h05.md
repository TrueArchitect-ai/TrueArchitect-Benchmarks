**Explicit Go code**; reactions are removed by two dedicated functions within the user-deletion transaction, covering both dimensions:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions whose `content_id` matches the user's memos (i.e., reactions by anyone on the deleted user's content). Called at e.g. `store/db/sqlite/user_delete.go:96`, `store/db/mysql/user_delete.go:96`.

2. **`deleteReactionsByCreatorTx`** — deletes reactions where `creator_id` matches the deleted user (i.e., reactions the user placed on others' content). Called at e.g. `store/db/sqlite/user_delete.go:102`, `store/db/mysql/user_delete.go:102`.

Both are invoked from `deleteUserTargetsTx` inside a database transaction, present in all three driver implementations:
- `store/db/sqlite/user_delete.go:92–104`
- `store/db/mysql/user_delete.go:92–104`
- `store/db/postgres/user_delete.go` (same structure)

There are no foreign-key `ON DELETE CASCADE` rules handling this — the Go code explicitly issues `DELETE FROM reaction` statements.
