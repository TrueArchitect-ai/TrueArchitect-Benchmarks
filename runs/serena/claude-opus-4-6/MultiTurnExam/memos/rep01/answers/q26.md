The following database tables are affected when DeleteMemo runs:

- **memo_relation** — explicitly deleted by store-layer cascade code (`store/memo.go`)
- **attachment** — explicitly deleted by store-layer cascade code (`store/memo.go`)
- **memo** — the memo row itself is deleted (`store/db/sqlite/memo.go`)
- **memo_share** — deleted via SQL `ON DELETE CASCADE` foreign key on `memo_id` (`store/migration/sqlite/LATEST.sql`)

Additionally, at the API layer (`server/router/api/v1/memo_service.go`), comment memos (child memos linked via `memo_relation`) are recursively deleted first, which triggers the same cascades on their own `memo`, `memo_relation`, `attachment`, and `memo_share` rows.
