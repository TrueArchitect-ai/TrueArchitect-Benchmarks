The following tables are affected when `DeleteMemo` runs:

1. **memo_relation** — explicitly deleted in `store/memo.go` (both `memo_id` and `related_memo_id` sides)
2. **attachment** — explicitly deleted in `store/memo.go` via `DeleteAttachment`
3. **memo** — the memo row itself, deleted in the dialect driver (e.g. `store/db/sqlite/memo.go`)
4. **memo_share** — cascaded via `ON DELETE CASCADE` foreign key on `memo_id` in the schema (`store/migration/sqlite/LATEST.sql`)

Additionally, when the memo has comments, the API handler (`server/router/api/v1/memo_service.go:567-577`) recursively calls `Store.DeleteMemo` for each comment memo, so their **memo_relation**, **attachment**, **memo**, and **memo_share** rows are also deleted.
