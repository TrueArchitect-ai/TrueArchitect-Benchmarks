Tables affected when DeleteMemo runs:

- **`memo`** — the memo row itself (and comment memos, which the API handler deletes first via recursive `Store.DeleteMemo` calls; `server/router/api/v1/memo_service.go:569-578`)
- **`memo_relation`** — explicitly deleted in both directions (as source and as target) in `Store.DeleteMemo` (`store/memo.go:142-147`)
- **`attachment`** — attachments linked to the memo are explicitly deleted (`store/memo.go:148-157`, via `Store.DeleteAttachment` in `store/attachment.go:132`, which also removes the stored file)
- **`memo_share`** — removed by a database-level `ON DELETE CASCADE` foreign key on `memo_id` (`store/migration/sqlite/LATEST.sql:108`)

Note: `reaction` rows are listed in the API handler only to build the webhook payload — there is no explicit reaction cleanup code and the `reaction` table has no FK cascade, so it is not affected.
