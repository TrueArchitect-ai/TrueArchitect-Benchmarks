**Interceptor:** `web/src/connect.ts` — the `authInterceptor` (line 156) attaches `Authorization: Bearer <accessToken>` to every ConnectRPC request, does a preflight refresh when the access token is expired, and reactively refreshes-and-retries on 401, deduplicating concurrent refreshes via a token-refresh manager. Token state itself lives in `web/src/auth-state.ts`.

**Token kinds managed:** a short-lived **access token** (JWT sent as a Bearer header, held in memory via `auth-state.ts`) and a **refresh token** (HTTP-only cookie, sent automatically and exchanged via `AuthService.RefreshToken` on a dedicated `refreshTransport`).

**Backend validation package:** `server/auth` — `authenticator.go` validates bearer access tokens and refresh tokens (`AuthenticateByRefreshToken`, checking the DB for revocation/expiry), with JWT parsing in `token.go` and header/cookie extraction in `extract.go`.
