**memo, memo_relation, attachment**

`Store.DeleteMemo` (`store/memo.go:140-159`) explicitly cascades before deleting the memo row:

- **memo_relation** — two `DeleteMemoRelation` calls remove rows where the memo is the source or the target (lines 142–147).
- **attachment** — attachments linked to the memo are listed and deleted via `Store.DeleteAttachment` → driver `DELETE FROM attachment` (`store/memo.go:149-157`, `store/db/sqlite/attachment.go:211`); this also removes the underlying file/blob from storage, which isn't a table.
- **memo** — finally the driver deletes the memo row itself (`store/db/sqlite/memo.go:237`; the postgres and mysql drivers are identical single-row deletes).

Additionally, the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go`) first deletes all comment memos by calling `Store.DeleteMemo` for each COMMENT relation — those hit the same three tables. Reaction rows are listed only to build the webhook payload; they are not deleted by this path.
