**Tables: memo, memo_relation, attachment**

`Store.DeleteMemo` (`store/memo.go:140-159`) explicitly cascades before deleting the memo row:

- **memo_relation** — deleted for both directions (`MemoID` and `RelatedMemoID`) via `driver.DeleteMemoRelation` (store/memo.go:142-147)
- **attachment** — every attachment linked to the memo is deleted via `Store.DeleteAttachment` (store/memo.go:148-157; this also removes the underlying file from local/S3 storage per store/attachment.go:132-149, though that's filesystem/object storage, not a table)
- **memo** — the memo row itself via `driver.DeleteMemo` (e.g. `DELETE FROM memo` in store/db/sqlite/memo.go:237)

Note the API handler `APIV1Service.DeleteMemo` (server/router/api/v1/memo_service.go) additionally deletes comment memos first — each comment goes through the same `Store.DeleteMemo` cascade, so the same three tables are hit for each comment as well.
