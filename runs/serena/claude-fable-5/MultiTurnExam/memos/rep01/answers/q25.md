**Engine:** CEL (Common Expression Language) via `cel-go`, implemented in `internal/filter/` — entry point `filter.DefaultEngine()` in internal/filter/engine.go, with schema.go, parser.go, ir.go, and render.go making up the pipeline (documented in internal/filter/README.md).

**Mechanism:** The filter string is parsed with cel-go against a memo-specific schema (internal/filter/schema.go), normalized into a dialect-agnostic intermediate representation (internal/filter/ir.go via parser.go), and then rendered by internal/filter/render.go into a SQL WHERE fragment plus placeholder args tailored to the target dialect (`DialectSQLite`, `DialectMySQL`, or `DialectPostgres` — handling differences like `?` vs `$n` placeholders, JSON access syntax, and LIKE/ILIKE); each dialect driver's `ListMemos` invokes this via `filter.AppendConditions` with its own dialect constant (e.g. store/db/sqlite/memo.go:57-61).
