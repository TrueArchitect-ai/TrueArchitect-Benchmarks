**Engine:** CEL (Common Expression Language), parsed with `cel-go` — the filter engine lives in **`internal/filter/`** (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`; parsing in `parser.go`, schema validation in `schema.go`).

**Mechanism:** The engine runs a three-phase pipeline (documented in `internal/filter/README.md`): the CEL expression is parsed with cel-go and validated against a memo-specific schema, normalized into a dialect-agnostic intermediate representation (`internal/filter/ir.go`), and then rendered by `internal/filter/render.go` into a parameterized SQL fragment tailored to the target dialect (`filter.DialectSQLite`, `DialectMySQL`, or `DialectPostgres` — handling differences like JSON access, placeholders, and LIKE vs ILIKE); each dialect driver invokes it when building the query, e.g. `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args)` in `store/db/sqlite/memo.go:57-61` (and equivalents in `store/db/mysql/memo.go` and `store/db/postgres/memo.go`).
