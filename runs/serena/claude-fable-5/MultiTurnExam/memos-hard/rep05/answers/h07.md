The browser requests `GET /file/users/{identifier}/avatar` (route registered at `server/router/fileserver/fileserver.go:124`). The avatar itself is stored as a data URI in the user row's `avatar_url` column, so "stored data" is reached through the user lookup path:

- `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168` (handler; checks anonymous access policy, then looks up the target user, decodes `user.AvatarURL` via `parseDataURI` at `fileserver.go:196`, and writes the image bytes)
- `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715` (wraps the store call with `store.FindUser{Username: ...}`)
- `Store.GetUser` — `store/user.go:148` (checks the user cache, then delegates)
- `Store.ListUsers` — `store/user.go:136` (calls into the pluggable driver and populates the cache)
- `store.Driver.ListUsers` implementation — `store/db/sqlite/user.go:88` (or `store/db/mysql/user.go:84` / `store/db/postgres/user.go:87`, depending on the configured driver), which runs the SQL `SELECT` against the `user` table and scans the row — including the `avatar_url` column holding the image data URI.
