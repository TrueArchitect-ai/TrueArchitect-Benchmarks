**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide grep for "redis" in the Go sources returns nothing — the cache layer is a purely in-process, thread-safe in-memory cache (`sync.Map`-based) defined in `store/cache/cache.go`, with no external connection to configure.

**Actual mechanism:** the `Cache` type (`store/cache/cache.go:67`) stores items in memory with per-entry expiration and a background cleanup loop. The store constructs three of these caches — including `userCache` — in `store.New` at `store/store.go:38-53`, using an inline config at `store/store.go:40-45`: **`DefaultTTL: 10 * time.Minute`**, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`. User entries are written with `Set` (e.g. `store/user.go:132,143,167`), which applies the default TTL — so **user cache entries live for 10 minutes** (in memory, per process), matching the package's own `DefaultConfig()` at `store/cache/cache.go:56-63`.
