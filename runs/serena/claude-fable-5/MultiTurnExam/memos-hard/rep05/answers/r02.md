**Premise correction: there is no per-user API rate-limiting middleware in this codebase — none is registered anywhere, so it has no request limits.**

What I checked:

- A repo-wide grep for `rate limit`, `ratelimit`, `throttle`, and `limiter` in the Go sources finds only a documentation comment suggesting rate limiting as a future hardening idea for email sending (`internal/email/doc.go:86`) — no implementation.
- The HTTP middleware stack registered on the Echo server consists only of `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`); the gRPC/Connect side adds auth/ACL interceptors (`server/router/api/v1/connect_interceptors.go`, `acl_config.go`), none of which do rate limiting.
- The closest things to request limiting are not per-user rate limits: weighted semaphores capping *concurrent* thumbnail generation (3) and image processing (2) server-wide (`server/router/api/v1/v1.go:40-41,60-61`), a bounded webhook dispatch queue (`internal/webhook/webhook.go:39`), and memo content-length limits — all resource/concurrency controls, not request-rate quotas.
