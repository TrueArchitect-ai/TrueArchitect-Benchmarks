**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74` — which calls `markdownService.ExtractAll` (`internal/markdown/markdown.go:356`) to parse the memo's markdown in a single goldmark AST walk, then stores the results into `memo.Payload.Tags` and `memo.Payload.Property` (the `MemoPayload` proto persisted with the memo).

**Triggers (operations that recompute it):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (also covers `CreateMemoComment`, which creates the comment through `s.CreateMemo` at `server/router/api/v1/memo_service_comments.go:56`)
- `UpdateMemo`, when the `content` field is in the update mask — `server/router/api/v1/memo_service.go:447`
- A bulk rebuild path exists — `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) rebuilds payloads for all memos in batches — but nothing in production code currently constructs or invokes that runner.

**Extracted properties** (from `ExtractAll`, `internal/markdown/markdown.go:356`):
- **Tags** — every `#tag` node in the content
- **Mentions** — every `@username` (lowercased; returned to callers for notifications, not stored in the payload)
- **Property.Title** — the text of a leading H1 heading, if the document's first block is one
- **Property.HasLink** — presence of any link node
- **Property.HasCode** — presence of code blocks, fenced code blocks, or code spans
- **Property.HasTaskList / Property.HasIncompleteTasks** — presence of task checkboxes, and whether any are unchecked

These payload fields are what list views, previews, and filters consume (e.g. tag filtering and the `has_link`/`has_task_list` style filter conditions in the store layer).
