Memo visibility is enforced independently on five server surfaces:

- **gRPC/Connect API (memo reads)** — `APIV1Service.checkMemoReadAccess` at `server/router/api/v1/memo_service.go:39` (public → anonymous OK if allowed; protected → any authenticated user; private → creator or superuser). Used by `GetMemo` (`memo_service.go:356`), parent memos (`memo_service.go:367`), and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`). List-shaped endpoints enforce the same policy at query time by constraining `FindMemo.VisibilityList` (`memo_service.go:219-225`, and `server/router/api/v1/user_service_stats.go:84-90,218-220`); per-resource checks are repeated in `reaction_service.go:30-83`, `attachment_service.go:445-451`, and `memo_attachment_service.go:214-222`.
- **File server (attachment/thumbnail downloads)** — `FileServerService.checkAttachmentPermission` at `server/router/fileserver/fileserver.go:650` (public + anonymous-allowed passes; otherwise a valid share token or an authenticated user, with private restricted to creator/admin at `fileserver.go:699`).
- **RSS feeds** — the feed queries only public memos: `VisibilityList: []store.Visibility{store.Public}` at `server/router/rss/rss.go:90` and `rss.go:141`.
- **Frontend router (sitemap/SEO)** — `getSitemapXML` lists only public memos: `server/router/frontend/frontend.go:150`.
- **SSE event stream** — `SSEClient.canReceive` at `server/router/api/v1/sse_hub.go:134` filters broadcast events by memo visibility (private events only to the creator or an admin).
