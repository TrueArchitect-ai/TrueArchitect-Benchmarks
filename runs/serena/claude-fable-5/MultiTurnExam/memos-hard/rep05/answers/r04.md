**Premise correction: neither — there is no message broker in this codebase.** A grep for NATS, RabbitMQ, AMQP, or any broker client turns up nothing; webhook delivery uses a plain in-process Go channel.

**Actual mechanism:** the "queue" is a buffered channel declared in `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`. The package's `init()` (`internal/webhook/webhook.go:42-55`) starts four worker goroutines that range over this channel and call `Post` (`webhook.go:120`) to perform the actual HTTP delivery. Producers enqueue via `PostAsync` (`webhook.go:184-196`), which does a non-blocking send and logs-and-drops the payload if the 128-slot buffer is full. Everything is in-memory within the single server process — no external broker, no persistence, no redelivery.
