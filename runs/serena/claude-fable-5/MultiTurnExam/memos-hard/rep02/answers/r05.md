**Premise correction: there is no GraphQL schema — this project doesn't have a GraphQL API at all.** No `.graphql` files, no GraphQL library imports, and no schema definitions exist anywhere in the repo.

**Actual API surface:** the public API is defined as **Protocol Buffers / gRPC service definitions** under `proto/api/v1/` (e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus shared types in `common.proto`). Generated code lives in `proto/gen/`. It is exposed over HTTP two ways, both wired in `server/router/api/v1/v1.go`:

1. **Connect protocol** handlers for browser/RPC clients (`RegisterConnectHandlers` at `server/router/api/v1/v1.go:141`, generated stubs in `proto/gen/api/v1/apiv1connect/`) — this replaces grpc-web; the frontend consumes it via generated TypeScript clients (`web/src/types/proto/api/v1/`, `web/src/connect.ts`).
2. **REST via grpc-gateway** (`github.com/grpc-ecosystem/grpc-gateway/v2`, wired around `server/router/api/v1/v1.go:69-97`), which maps the same proto services to JSON/HTTP endpoints.

So the schema-equivalent artifacts are the `.proto` files in `proto/api/v1/`, not a GraphQL SDL.
