**Premise correction: neither.** There is no message broker in this codebase at all — a repo-wide grep for NATS, RabbitMQ/AMQP (or Kafka) across Go sources and `go.mod` finds nothing.

**Actual mechanism:** webhook delivery uses a plain in-process Go channel as its queue. The "queue" is declared as a package-level buffered channel in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are started in the package's `init()` (`internal/webhook/webhook.go:42-55`); each ranges over `asyncPostQueue` and calls `Post` to perform the HTTP delivery. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send — if the 128-slot buffer is full, the event is dropped with a warning log rather than blocking the request path. There is no persistence, external broker, or redelivery: undelivered webhooks are lost on process restart or queue overflow.
