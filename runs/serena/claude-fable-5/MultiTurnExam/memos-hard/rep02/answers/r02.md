**Premise correction: there is no per-user API rate-limiting middleware in this codebase — nothing to register and no request limits exist.**

What I checked:

- A repo-wide search for rate-limit/throttle/limiter terms in Go code turns up nothing (no `golang.org/x/time/rate`, no Echo `RateLimiter` middleware, no custom limiter).
- The Echo server registers only two middlewares: `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`).
- The Connect/gRPC API stack's interceptor chain is metadata, logging, recovery, and auth only (`server/router/api/v1/v1.go:133-137`) — no rate limiting.

The closest things that do exist are not per-user request rate limits:

- Concurrency semaphores capping thumbnail generation to 3 and image processing to 2 simultaneous operations server-wide (`server/router/api/v1/v1.go:59-60`).
- A request body size cap on the API (`connect.WithReadMaxBytes(maxAPIRequestBytes)`, `server/router/api/v1/v1.go:141`).
- A bounded async webhook queue that drops when full (`internal/webhook/webhook.go`).

So if you were looking to add per-user rate limiting, it would have to be introduced — e.g., as an Echo middleware at `server/server.go` or an interceptor in `server/router/api/v1/v1.go`.
