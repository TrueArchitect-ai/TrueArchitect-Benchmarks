**Premise correction:** there is no Redis anywhere in this codebase — a repo-wide grep for "redis" in Go code finds nothing, and no Redis client is imported in `go.mod`. The cache layer is a purely in-process, in-memory cache.

**Actual mechanism:** the cache is the thread-safe in-memory `Cache` type built on `sync.Map` in `store/cache/cache.go` (struct at line ~66, `New` starts a background `cleanupLoop` goroutine). The `Store` constructs three instances of it — `instanceSettingCache`, `userCache`, and `userSettingCache` — in `store.New` at `store/store.go:51-53`, using the config literal at `store/store.go:40-45`.

**TTL for user entries:** user cache entries get the `DefaultTTL` of **10 minutes** (`store/store.go:41`; same value in `cache.DefaultConfig()` at `store/cache/cache.go:55`). Entries are set via `Set`, which applies the default TTL (`store/cache/cache.go:92-94`), e.g. from `Store.GetUser`/`ListUsers` in `store/user.go`. Expired items are swept by the cleanup loop every 5 minutes (`CleanupInterval`), and the cache is bounded at 1000 items (`MaxItems`).
