The derived metadata is the memo's `MemoPayload` — tags plus a `Property` message "calculated from the memo content" (`proto/store/memo.proto:7-22`).

**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual parsing to the goldmark-backed `markdown.Service.ExtractAll` (`internal/markdown/markdown.go:356`) — a single AST walk over the memo content — and writes the results into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers (recomputation happens when):**

1. **Memo creation** — `CreateMemo` calls it before persisting (`server/router/api/v1/memo_service.go:108`); this also covers comments, since `CreateMemoComment` routes through `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
2. **Content update** — `UpdateMemo` calls it when the `content` field is in the update mask (`server/router/api/v1/memo_service.go:447`).
3. **Bulk rebuild** — the `memopayload.Runner.RunOnce` batch job re-derives payloads for all memos (`server/runner/memopayload/runner.go:27,52`), though nothing in production currently invokes that runner.

**Extracted properties:**

- **Tags** — every `#tag` node, deduplicated case-preservingly (also mentions, returned separately for notifications, not stored in the payload).
- **`title`** — text of the first H1 heading if it's the document's first block (`markdown.go:387`).
- **`has_link`** — any link node (`markdown.go:394`).
- **`has_code`** — code block, fenced code block, or inline code span (`markdown.go:397`).
- **`has_task_list`** and **`has_incomplete_tasks`** — task checkboxes, and whether any are unchecked (`markdown.go:400-404`).

These stored fields power list views/previews and filtering without reparsing content on read.
