**Delivery function: `Post` (dispatched asynchronously via `PostAsync` and a worker-pool queue) — `internal/webhook/webhook.go`; protection mechanism: SSRF guard via `safeDialContext` (dial-time IP check backed by `isReservedIP`/`ValidateURL`) — `internal/webhook/webhook.go` and `internal/webhook/validate.go`**

Details:

- **Delivery:** `Post` at `internal/webhook/webhook.go:120` marshals the payload, optionally adds a Standard-Webhooks-style HMAC-SHA256 signature, and sends the HTTP POST through `safeClient.Do(req)`. Callers normally use `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto `asyncPostQueue`; four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`) drain the queue and call `Post`.
- **Protection:** the HTTP client's dialer is replaced with `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the target hostname at connection time and refuses to dial if any resolved IP is in a reserved range — this blocks DNS-rebinding as well as direct internal targets. The reserved ranges (IPv4/IPv6 loopback, RFC-1918 private, link-local including the cloud IMDS address 169.254.169.254) are defined in `reservedCIDRs` with the check in `isReservedIP` at `internal/webhook/validate.go:44`. There's also an up-front `ValidateURL` (`internal/webhook/validate.go:62`) enforcing http/https scheme and non-reserved resolution when webhook URLs are registered, and an `AllowPrivateIPs` escape hatch for self-hosted deployments that intentionally target LAN services.
