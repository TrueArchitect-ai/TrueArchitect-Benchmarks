**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual parsing to the markdown service's single-pass AST walk `ExtractAll` (`internal/markdown/markdown.go:356`). Results are stored on the memo as `memo.Payload.Tags` and `memo.Payload.Property` (the protobuf `MemoPayload` in `proto/gen/store/memo.pb.go`).

**Triggers:**
1. **Memo creation** — `CreateMemo` calls `memopayload.RebuildMemoPayload` at `server/router/api/v1/memo_service.go:108` before persisting.
2. **Content update** — `UpdateMemo` recomputes it whenever the update mask includes the `content` path (`server/router/api/v1/memo_service.go:447`), writing the new payload alongside the new content.
3. **Bulk rebuild** — the `memopayload.Runner.RunOnce` batch job (`server/runner/memopayload/runner.go:52`) can rebuild payloads for all memos, though as established earlier, nothing in production currently invokes that runner.

**Extracted properties:** from one goldmark parse of the memo content, `ExtractAll` collects:
- **Tags** — every `#tag` node, deduplicated case-preservingly (`markdown.go:377,418`)
- **Mentions** — every `@username`, lowercased and deduplicated (`markdown.go:380`) — returned in `ExtractedData`, though only Tags and Property are persisted to the payload
- **Property.Title** — the text of a leading H1 heading if it's the document's first block (`markdown.go:384-389`)
- **Property.HasLink** — any link node (`markdown.go:394`)
- **Property.HasCode** — code blocks, fenced code blocks, or inline code spans (`markdown.go:396-397`)
- **Property.HasTaskList** and **Property.HasIncompleteTasks** — task checkboxes, with the latter set when any checkbox is unchecked (`markdown.go:399-404`)

These power list views and previews (e.g., filtering by tag, "has incomplete tasks," showing titles/snippets) without users setting any of it explicitly.
