Distinct memo-visibility enforcement sites across the server:

1. **gRPC/Connect API — single-memo read guard**: `APIV1Service.checkMemoReadAccess` — `server/router/api/v1/memo_service.go:39` (public passes; otherwise requires auth, and Private requires creator).
2. **gRPC/Connect API — list filtering**: `ListMemos` injects visibility constraints into the query (`VisibilityList = [Public]` for anonymous; `creator_id == X || visibility in ["PUBLIC","PROTECTED"]` filter for signed-in users) — `server/router/api/v1/memo_service.go:218-227` (same pattern for comment listing at `server/router/api/v1/memo_service_comments.go:158-160`).
3. **Comment creation**: private memos can't be commented on by non-creators/non-admins — `server/router/api/v1/memo_service_comments.go:41`.
4. **Reactions**: visibility checked before listing/creating reactions — `server/router/api/v1/reaction_service.go:30-38,83`.
5. **SSE real-time events**: `SSEClient.canReceive` filters server-sent memo events so Private events reach only the creator or an admin — `server/router/api/v1/sse_hub.go:134`.
6. **File server (attachments)**: attachment downloads check the owning memo's visibility — anonymous access only for Public (on instances allowing it), share-token fallback, and Private restricted to creator/admin — `server/router/fileserver/fileserver.go:674-703`.
7. **RSS feeds**: feed queries fetch only `store.Public` memos — `server/router/rss/rss.go:90,141`.
8. **Frontend router (sitemap/static)**: only Public memos listed — `server/router/frontend/frontend.go:149-151`.
9. **Mention notifications**: mentioned users aren't notified about memos they can't view (Private + not creator) — `server/router/api/v1/memo_mention_helpers.go:62-67`.
10. **Notification emails**: Private memo content is withheld/handled specially before emailing — `server/notification/email.go:313-316`.
