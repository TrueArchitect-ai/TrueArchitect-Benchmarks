**Premise correction:** there is no Redis anywhere in this codebase — a repo-wide grep for "redis" turns up nothing. The cache layer is a purely **in-process, in-memory cache** implemented in `store/cache/cache.go` (`Cache` is described there as "a thread-safe in-memory cache with TTL and memory management").

**Actual mechanism:** the store constructs three cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — in `store/store.go:40-53` using a shared `cache.Config`. User entries use the default TTL from that config: **10 minutes** (`DefaultTTL: 10 * time.Minute`, `store/store.go:41`), with a cleanup sweep every 5 minutes and a 1000-item cap. User entries are written via `Store.ListUsers`/`GetUser` (`store/user.go:143,150`) with plain `Set`, which applies that 10-minute default (`store/cache/cache.go:92-94`); the caches are torn down in `Store.Close` (`store/store.go:74-76`).
