**Yes** — but only in one place, a unit test inside the driver's own package.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:14`, which calls `mysql.NewDB(profile)` at `store/db/db.go:22`. That file is the **only** place in the entire codebase that imports `github.com/usememos/memos/store/db/mysql` (verified by grepping for the import path — the sole hit outside the package itself is `store/db/db.go:8`).
- However, within the mysql package itself, `store/db/mysql/auth_config_test.go:12` constructs the driver struct directly with `db := &DB{}`, bypassing `NewDB` (fine there, since a package-internal test doesn't need a real connection).
- All other consumers go through the factory: production code reaches it via the store setup, and the integration test harness calls `db.NewDBDriver(profile)` at `store/test/store.go:28` and `store/test/store.go:50`. The mysql references in `store/test/containers.go` are the `go-sql-driver/mysql` SQL driver and testcontainers module for spinning up a MySQL container — not the repo's driver package.

So: outside the driver-selection factory, no external package ever constructs the MySQL driver; the only direct construction is the in-package test's `&DB{}` literal. If the question counts only code outside the `store/db/mysql` package itself, the answer is strictly **no**.
