**Premise correction:** this project has no GraphQL API — there is no GraphQL schema, resolver, or library anywhere in the backend or frontend code.

**Actual API surface:** the public API is **gRPC-style, defined in Protocol Buffers** and exposed over HTTP two ways:

- **Schema definitions:** protobuf files under `proto/api/v1/` — `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `common.proto` — with generated code in `proto/gen/`.
- **Transport:** the services are served both via **gRPC-Gateway** (REST/JSON mapping) and **Connect RPC**, registered in `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:64` onward, using `connectrpc.com/connect` and `grpc-ecosystem/grpc-gateway`), mounted on the Echo server.
- An **OpenAPI description** of the REST surface is generated at `proto/gen/openapi.yaml` (also consumed by the MCP router's curated tool catalog in `server/router/mcp/`).

So if you're looking for the API contract, the protobuf files in `proto/api/v1/` are the source of truth — the role a GraphQL schema would play elsewhere.
