**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in the Go source returns nothing — the cache layer is a purely in-process, in-memory cache, so there is no Redis connection to configure.

**Actual mechanism:** the cache is a hand-rolled thread-safe in-memory cache in `store/cache/cache.go` (`Cache` type backed by `sync.Map`, with TTL expiration, periodic cleanup, and a max-item cap). The store constructs three instances of it — including the user cache — in `store.New` at `store/store.go:40-53`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
userCache: cache.New(cacheConfig),
```

**TTL for user entries: 10 minutes** (the `DefaultTTL` above; user entries are written via `Set`, which uses the default TTL — e.g., `s.userCache.Set(...)` in `store/user.go:132,143,167`). Entries are also subject to the 5-minute cleanup sweep and eviction once the cache exceeds 1000 items. The same defaults appear in `cache.DefaultConfig()` at `store/cache/cache.go:57-63`.
