**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** A repo-wide search for rate-limit/throttle/limiter code finds none, and the only middleware registered on the Echo server is `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`), plus per-route auth in the API layer. Nothing tracks request counts per user, so there are no request limits to report.

The closest things that do exist are resource-bounding mechanisms, not rate limits:

- Concurrency semaphores in the file server — max 3 concurrent thumbnail generations (`server/router/fileserver/fileserver.go:45-46,107,116`) and similar semaphores in the API service (`server/router/api/v1/v1.go`, thumbnail weight 3, image-processing weight 2).
- A bounded async webhook queue (128 entries, 4 workers) that drops on overflow — `internal/webhook/webhook.go:39-55`.
- Content-length limits on memo content checked per request (`server/router/api/v1/memo_service.go:100-106`).

None of these are per-user, and none limit requests per time window.
