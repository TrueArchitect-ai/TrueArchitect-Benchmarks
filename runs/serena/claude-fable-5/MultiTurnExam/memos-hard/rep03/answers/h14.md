**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`. It calls `markdownService.ExtractAll` (implemented in `internal/markdown/markdown.go:356`), which does a single goldmark AST walk over the memo's content and writes the results into `memo.Payload.Tags` and `memo.Payload.Property` (the `MemoPayload` proto, `proto/store/memo.proto`).

**Triggers (operations that recompute it):**
- **Memo creation** — `CreateMemo` calls `RebuildMemoPayload` before persisting (`server/router/api/v1/memo_service.go:108`). Comment creation also flows through this path.
- **Content update** — `UpdateMemo` recomputes whenever the update mask includes the `content` path (`server/router/api/v1/memo_service.go:447`).
- A bulk-rebuild runner exists (`memopayload.Runner.RunOnce`, `server/runner/memopayload/runner.go:27`) that would recompute payloads for all memos in batches, but it is never invoked from production code — the two API paths above are the live triggers.

**Extracted properties:**
- `tags` — deduplicated list of `#tags` found in the content (case-preserving dedup).
- `property.title` — text of the first H1 heading if it's the document's first block.
- `property.has_link` — any link node present.
- `property.has_code` — any code block, fenced code block, or code span.
- `property.has_task_list` — any task checkbox; `property.has_incomplete_tasks` — any unchecked checkbox.
- The walk also collects `@mentions`, but those are used for notifications rather than stored in the payload (`RebuildMemoPayload` keeps only `Tags` and `Property`).

These fields (`proto/store/memo.proto:15-22`) are exactly what list views/previews filter and render without reparsing the markdown.
