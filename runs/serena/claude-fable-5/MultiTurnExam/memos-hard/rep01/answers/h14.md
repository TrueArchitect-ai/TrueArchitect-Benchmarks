**Derived metadata:** each memo's `Payload` — the tag list plus the "calculated properties" (`MemoPayload_Property`), which power list filtering and previews.

**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`. It calls `markdownService.ExtractAll` (implemented at `internal/markdown/markdown.go:356`), a single goldmark AST walk over the memo content, and writes the results into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers:**
- **Memo creation** — `CreateMemo` handler at `server/router/api/v1/memo_service.go:107`.
- **Content update** — `UpdateMemo` handler, when the `content` field is in the update mask, at `server/router/api/v1/memo_service.go:447`.
- **Comment creation** — indirectly, since `CreateMemoComment` creates the comment via `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
- **Bulk rebuild** — `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) can recompute payloads for all memos in batches, though this runner is not wired into server startup in current production code.

**Extracted properties:** from the single parse, `ExtractAll` produces tags (`#tag` nodes), mentions (`@mention` nodes), and the `MemoPayload_Property` fields defined in `proto/gen/store/memo.pb.go:85`: `HasLink`, `HasTaskList`, `HasCode`, `HasIncompleteTasks`, and `Title` (taken from a leading H1 heading). Tags and the property message are persisted to the payload (`server/runner/memopayload/runner.go:85-86`).
