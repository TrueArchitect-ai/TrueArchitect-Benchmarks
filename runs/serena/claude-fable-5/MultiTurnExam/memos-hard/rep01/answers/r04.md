**Premise correction:** neither — there is no message broker in this codebase. No NATS, RabbitMQ, Kafka, or any external queueing system is imported or configured (nothing in `go.mod` references one, and I verified this when tracing the webhook path earlier).

**Actual mechanism:** webhook delivery uses a plain in-process Go channel as a bounded queue. The "queue" is declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`. The package's `init()` (`internal/webhook/webhook.go:42-55`) starts 4 worker goroutines that range over this channel and call `Post` (`internal/webhook/webhook.go:120`) to perform the actual HTTP delivery. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send — if the 128-slot buffer is full, the dispatch is dropped with a warning log rather than blocking the request path. Everything lives and dies with the server process; there is no persistence or external broker involved.
