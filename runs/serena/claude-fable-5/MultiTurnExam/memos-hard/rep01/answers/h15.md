Five distinct enforcement sites, across five server surfaces:

- **gRPC/API v1 read access check** — `checkMemoReadAccess` at `server/router/api/v1/memo_service.go:39` (public passes; otherwise requires sign-in, and Private requires creator). Applied in `GetMemo` (`memo_service.go:356,367`) and reused by related handlers (e.g. `server/router/api/v1/reaction_service.go`, `server/router/api/v1/attachment_service.go`). List queries enforce it at query-build time: anonymous callers are restricted to `VisibilityList{Public}` and signed-in non-creators to Public/Protected via a CEL filter (`server/router/api/v1/memo_service.go:219-225`).
- **File server (attachment serving)** — `checkAttachmentPermission` at `server/router/fileserver/fileserver.go:649`: loads the owning memo and gates on `memo.Visibility` (public + anonymous-allowed passes; otherwise requires an authenticated user or a valid, unexpired per-memo share token, `fileserver.go:674-690`).
- **RSS feeds** — `server/router/rss/rss.go:90` and `:141`: feed queries hard-code `VisibilityList: []store.Visibility{store.Public}`, so only public memos ever appear.
- **Frontend sitemap** — `server/router/frontend/frontend.go:150`: `getSitemapXML` lists only `store.Public` memos.
- **SSE event delivery** — `SSEClient.canReceive` at `server/router/api/v1/sse_hub.go:134`: server-side filtering of realtime events by `event.Visibility` (Private events only to the creator or an admin; unknown visibility denied), with the visibility attached in `server/router/api/v1/sse_event_helpers.go:29-37`.
