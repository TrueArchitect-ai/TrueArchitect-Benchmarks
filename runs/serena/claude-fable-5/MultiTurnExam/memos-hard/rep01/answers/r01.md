**Premise correction:** there is no Redis anywhere in this codebase — a repo-wide grep for "redis" returns nothing. The cache layer is a purely in-process, in-memory cache implemented in `store/cache/cache.go` (a `sync.Map`-style store with per-item expiration, a background cleanup loop, and a max-item cap). No external cache service is configured.

**Actual mechanism:** the caches are constructed in `store.New` at `store/store.go:38-53`, which builds three `cache.Cache` instances (`instanceSettingCache`, `userCache`, `userSettingCache`) from an inline `cache.Config`. User entries go into `userCache` via `Store.GetUser`/`ListUsers` (`store/user.go:143,167`) using `Set`, which applies the **default TTL of 10 minutes** (`DefaultTTL: 10 * time.Minute`, `store/store.go:41`; applied in `SetWithTTL` via `cache.go:94`), with cleanup every 5 minutes and a 1000-item cap (`store/store.go:42-43`).
