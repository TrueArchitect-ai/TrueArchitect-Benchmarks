**Premise correction:** there is no per-user API rate-limiting middleware in this codebase. Nothing registers a rate limiter on the Echo server or the gRPC/Connect stack — the only middleware installed at the HTTP layer is `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`), and the API v1 layer wires only auth interceptors (`server/router/api/v1/v1.go:67,95`). A repo-wide search for rate-limit/throttle/limiter code (including Echo's `RateLimiter` middleware and `golang.org/x/time/rate`, which appears in `go.mod:151` only as an indirect dependency) finds no usage.

The closest things that exist are **global concurrency caps, not per-user rate limits**: two weighted semaphores in the API service — `imageProcessingSemaphore` limited to 2 concurrent EXIF-stripping operations and `thumbnailSemaphore` limited to 3 concurrent thumbnail generations (`server/router/api/v1/v1.go:40-41,59-60`). When the image-processing slot can't be acquired, the handler returns `ResourceExhausted: "too many image processing requests"` (`server/router/api/v1/attachment_service.go:158-160`). These are server-wide and independent of which user is calling, so there are no per-user request limits to report.
