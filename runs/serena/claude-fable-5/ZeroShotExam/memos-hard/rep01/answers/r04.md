Neither. This repository has no message broker at all — there is no NATS or RabbitMQ client, config, or dependency anywhere in the codebase (the only grep hit for "nats" is an unrelated word in a Catalan locale file, `web/src/locales/ca.json`).

The actual mechanism is an in-process, in-memory queue: webhook deliveries go through a buffered Go channel, `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared in `internal/webhook/webhook.go:39`. The "workers" are 4 goroutines started in that package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over the channel and calling `Post()` to deliver the HTTP request. Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send and logs-and-drops the payload if the 128-slot buffer is full. So there's no external broker, no durable queue, and no cross-process consumption — everything lives inside the single server process.
