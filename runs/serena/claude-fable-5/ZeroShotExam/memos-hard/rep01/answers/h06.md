Four RPC handler methods in `server/router/api/v1/` can transitively trigger an outbound HTTP POST to a user-configured webhook URL. Each fetches the memo creator's webhooks from the store (`GetUserWebhooks`) and dispatches a payload whose `URL` is set from `hook.Url`:

- **`CreateMemo`** — `server/router/api/v1/memo_service.go:70` → `DispatchMemoCreatedWebhook` (called at `:157`)
- **`UpdateMemo`** — `server/router/api/v1/memo_service.go:401` → `dispatchMemoUpdatedSideEffects` (`:513`) → `DispatchMemoUpdatedWebhook` (`memo_update_helpers.go:67`)
- **`DeleteMemo`** — `server/router/api/v1/memo_service.go:518` → `DispatchMemoDeletedWebhook` (called at `:562`)
- **`CreateMemoComment`** — `server/router/api/v1/memo_service_comments.go:20` → `DispatchMemoCommentCreatedWebhook` (called at `:119`)

The first three route through `dispatchMemoRelatedWebhook`; the comment path has its own dispatcher. All four call `webhook.PostAsync`, which enqueues onto `asyncPostQueue`, and the pool of worker goroutines drains that queue into the actual delivery function.

**Convergence function — delivery:** `webhook.Post` — `internal/webhook/webhook.go` (the single point where every path issues the outbound HTTP request via `safeClient.Do(req)`). `PostAsync` in the same file is the shared enqueue funnel just upstream of it.
