The premise is incorrect: this repository has no per-user API rate-limiting middleware at all.

What actually exists in the middleware/interceptor stack:

- The Echo server registers only `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`, `server/cors.go`).
- The API layer (`server/router/api/v1/v1.go:133-141`) registers Connect interceptors for metadata conversion, logging, panic recovery, and authentication (`NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor`), plus a gRPC-Gateway auth middleware (`v1.go:69-97`). The only request "limit" there is a max request body size (`connect.WithReadMaxBytes(maxAPIRequestBytes)` at `v1.go:141`), which is a payload-size cap, not a rate limit.
- The frontend router adds only static-file serving and an SPA fallback middleware (`server/router/frontend/frontend.go:54-59`).

The sole mention of rate limiting anywhere in the codebase is a documentation note suggesting that email sending *should* be rate limited to prevent abuse (`internal/email/doc.go:86`) — it is not implemented. No rate-limiting library (e.g., `golang.org/x/time/rate`, Echo's `RateLimiter`) appears in `go.mod` or the code. So there is no registration point and no request limits to report.
