**Premise correction:** There is no Redis in this repository. The cache layer is not Redis-backed at all — a repo-wide search finds no Redis client, connection string, or dependency anywhere (nothing in `go.mod`, no `redis`/`ioredis` references). So there is no Redis connection configuration to point to.

**Actual mechanism:** The cache layer is a custom in-process, thread-safe in-memory cache implemented in `store/cache/cache.go` (a `sync.Map` with per-item expiration, a background cleanup goroutine, and oldest-item eviction when over `MaxItems`). It is wired up in `store/store.go`, where `New()` creates three cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing this config (`store/store.go:40-45`):

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

**TTL for user entries:** User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 143, 167). `Set` applies the default TTL (`store/cache/cache.go:93-95`), so user cache entries live for **10 minutes**, with expired items swept every 5 minutes by the cleanup loop.
