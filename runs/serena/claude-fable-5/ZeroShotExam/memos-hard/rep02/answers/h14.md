The derived metadata is the memo's `Payload` — its `tags` list and the `Property` message (`proto/store/memo.proto:7-22`), which the proto itself describes as "the calculated properties from the memo content."

**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`. It delegates the actual extraction to the markdown service's single-pass AST walk, `ExtractAll` in `internal/markdown/markdown.go:355-419`, then writes the results into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers:**
- **Memo creation** — `CreateMemo` calls `memopayload.RebuildMemoPayload` before persisting (`server/router/api/v1/memo_service.go:108`).
- **Content update** — `UpdateMemo` calls it whenever the update mask includes the `content` path (`server/router/api/v1/memo_service.go:447`).
- **Bulk rebuild** — `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) rebuilds payloads for all memos in batches of 100; the runner type exists but I found no call site wiring it up in `server/server.go` (only the `s3presign` runner is invoked there), so it's currently an available-but-unscheduled maintenance path.

**Extracted properties** (from the goldmark AST walk in `ExtractAll`):
- `tags` — all `#tag` nodes, deduplicated case-preservingly.
- `Property.title` — the text of the document's first block-level child if it is an H1 heading (`markdown.go:383-389`).
- `Property.has_link` — any link node.
- `Property.has_code` — any code block, fenced code block, or inline code span.
- `Property.has_task_list` — any task checkbox; `Property.has_incomplete_tasks` — any unchecked checkbox (`markdown.go:391-408`).

(The same walk also collects `@mentions`, but those feed the mention helpers in `server/router/api/v1/memo_mention_helpers.go`, not the stored payload.)
