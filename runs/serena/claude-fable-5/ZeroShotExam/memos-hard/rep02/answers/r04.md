**Premise correction:** Neither. This repository (memos) uses no message broker at all — a repo-wide search for `nats`, `rabbitmq`, and `amqp` turns up nothing in the Go code (the only hit is an unrelated Catalan word in `web/src/locales/ca.json`), and there are no NATS/AMQP client dependencies.

**Actual mechanism:** Webhook delivery is handled entirely in-process with a buffered Go channel. The "queue" is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The "workers" are four goroutines started in the package `init()` (`internal/webhook/webhook.go:42-55`) that range over that channel and call `Post()` to deliver each webhook via HTTP (with HMAC signing and an SSRF-guarded client). Producers enqueue through `PostAsync()` (`internal/webhook/webhook.go:184`), which does a non-blocking send and logs a drop warning if the 128-slot buffer is full.
