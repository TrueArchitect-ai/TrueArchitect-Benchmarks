**Premise correction:** There is no Redis in this repository. Nothing in the codebase references Redis — no client library in `go.mod`/`go.sum`, no connection configuration anywhere. So there is no "Redis connection for the cache layer" to point to.

**Actual mechanism:** The cache layer is a custom thread-safe **in-memory** cache implemented in `store/cache/cache.go` (a `sync.Map`-based `Cache` type with TTL expiration, a periodic cleanup goroutine, and max-item eviction).

For user entries specifically:

- The `Store` creates a dedicated `userCache` (alongside `instanceSettingCache` and `userSettingCache`) in `store/store.go:38-53`, all built with the same config: **`DefaultTTL: 10 * time.Minute`**, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:40-45`).
- User entries are written with `s.userCache.Set(...)` (e.g. `store/user.go:98`), which delegates to `SetWithTTL` using the default TTL (`store/cache/cache.go:93-95`).

So the TTL that applies to cached user entries is **10 minutes**, with expired entries also swept every 5 minutes by the cleanup loop.
