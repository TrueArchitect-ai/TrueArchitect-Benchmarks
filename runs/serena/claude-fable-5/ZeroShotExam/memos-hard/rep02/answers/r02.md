**The premise is incorrect — this repository has no per-user API rate-limiting middleware.** There is nothing registered anywhere, so there are no request limits to report.

What actually exists:

- The full middleware/interceptor chain for the API is registered in `server/router/api/v1/v1.go:133-141`, and it consists only of `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, and `NewAuthInterceptor()` (implementations in `server/router/api/v1/connect_interceptors.go`), plus a gateway auth middleware at `server/router/api/v1/v1.go:69` and CORS handling in `server/cors.go`. None of these do rate limiting.
- The closest thing to a request limit is a request **size** cap, `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141` — a payload limit, not a rate limit.
- The only mentions of "rate limit" in the codebase are aspirational: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a *suggested* practice for email, not implemented middleware.

So if documentation or an assumption led you to expect throttling (e.g., N requests per minute per user), that protection currently does not exist in this codebase.
