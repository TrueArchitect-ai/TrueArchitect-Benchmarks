There is no GraphQL schema in this repository — the premise doesn't hold. Searching the entire repo for "graphql" turns up zero matches; the project (Memos) does not expose a GraphQL API at all.

The actual public API surface is a **gRPC / Connect RPC API defined in Protocol Buffers**, with an HTTP/REST layer generated on top:

- **Schema definitions:** `proto/api/v1/*.proto` — one file per service, e.g. `proto/api/v1/memo_service.proto`, `proto/api/v1/user_service.proto`, `proto/api/v1/auth_service.proto`, `proto/api/v1/attachment_service.proto`, `proto/api/v1/idp_service.proto`, `proto/api/v1/instance_service.proto`, `proto/api/v1/shortcut_service.proto`, `proto/api/v1/ai_service.proto`, plus shared types in `proto/api/v1/common.proto`. (Internal storage-layer messages live separately in `proto/store/*.proto`.)
- **Code generation:** configured in `proto/buf.gen.yaml` via buf, which generates Go gRPC stubs, Connect RPC handlers, a grpc-gateway REST transcoding layer, an OpenAPI spec (embedded via `proto/openapi_embed.go`), and TypeScript client types into `web/src/types/proto`. Generated code lands in `proto/gen/`.
- **Serving:** the API routes are wired up under `server/router/api/`.

So if you were looking for the schema-first source of truth for the public API, it's the protobuf files under `proto/api/v1/`, not a GraphQL schema.
