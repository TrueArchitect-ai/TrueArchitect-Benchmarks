**Yes** — in exactly one place: the MySQL driver's own package test constructs the `DB` struct directly.

Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14`, which calls `mysql.NewDB(profile)` at `store/db/db.go:22`. That is the only place in the entire codebase that imports the `store/db/mysql` package (a grep for imports of `db/mysql` matches only `store/db/db.go`), so no external code constructs the driver.
- However, inside the package itself, `store/db/mysql/auth_config_test.go:12` builds the driver struct directly with `db := &DB{}` (zero-value, no DB connection) to unit-test `IsRetryableAuthenticationMutationError`.
- The only other construction is the constructor itself: `driver := DB{profile: profile}` at `store/db/mysql/mysql.go:29`, which is part of `NewDB` and thus part of the factory path, not a separate direct construction.

For comparison, the integration tests in `store/test/store.go:28,50` go through the factory (`db.NewDBDriver`), not direct construction. So the answer is yes, but only in an in-package unit test (`auth_config_test.go`); all production code reaches the MySQL driver exclusively through the factory.
