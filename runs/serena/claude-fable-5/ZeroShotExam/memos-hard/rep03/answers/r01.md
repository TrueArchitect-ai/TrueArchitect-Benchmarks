**Premise correction:** There is no Redis anywhere in this repository — a repo-wide search for "redis" returns zero hits (no client dependency in `go.mod`/`go.sum`, no connection config). The cache layer is not Redis-backed.

**Actual mechanism:** Caching is done by a custom thread-safe **in-memory** cache implemented in `store/cache/cache.go` (a `sync.Map`-based `Cache` with TTL expiration, a periodic cleanup goroutine, and a max-item eviction policy). The caches are wired up in `store/store.go:38-58`, where `New()` creates three instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing one config:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

**TTL for user entries:** User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167), which uses the default TTL — so **10 minutes**, with expired items swept every 5 minutes by the cleanup loop (and also lazily evicted on `Get`). There is no external connection to configure; everything lives in process memory.
