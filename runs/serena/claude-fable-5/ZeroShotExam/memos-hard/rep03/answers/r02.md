**Premise correction: there is no per-user API rate-limiting middleware in this repository.** Nothing is registered anywhere, so it has no request limits.

What actually exists:

- The Echo server registers only `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`, with CORS in `server/cors.go`).
- The Connect/gRPC API stack registers interceptors for metadata, logging, panic recovery, and auth — but no rate limiting (`server/router/api/v1/v1.go:133-141`). The closest thing to a request limit there is a request **size** cap, `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`, which bounds bytes per request, not requests per user.
- The only mentions of rate limiting in the whole repo are documentation suggestions in the email package — `internal/email/doc.go:86` lists it as a best practice, and `internal/email/README.md:286` shows an example `RateLimitedSender` wrapper — neither of which is implemented or wired into the server.
