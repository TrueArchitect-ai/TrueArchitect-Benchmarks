The premise is incorrect — there is no nightly database-cleanup job registered in the cron scheduler, so it has no scheduled run time.

What actually exists in the repo:

- `internal/scheduler/` is a self-contained cron scheduler library (`scheduler.go`, `job.go`, `parser.go`), but nothing in the codebase registers jobs with it — grepping for imports of `internal/scheduler` outside the package itself (its tests, docs, README) finds no usages, so no production jobs of any kind are scheduled through it.
- The only "cleanup" jobs mentioned are illustrative examples in documentation: `internal/scheduler/doc.go:14-16` and `internal/scheduler/README.md:34` show a hypothetical `"daily-cleanup"` job with schedule `"0 2 * * *"` (2 AM daily), and `README.md:241` shows a `"stale-session-cleanup"` example. These are sample code, not real registered jobs.
- The server's actual background workers live in `server/runner/` (`memopayload`, `s3presign`), and neither is a database-cleanup job.

So if you've seen "2 AM" associated with cleanup in this repo, that's from the doc example — not a configured job.
