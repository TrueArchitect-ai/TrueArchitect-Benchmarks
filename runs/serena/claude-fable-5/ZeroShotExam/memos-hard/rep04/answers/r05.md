**Premise correction:** This repository has no GraphQL API at all — there are no `.graphql`/`.gql` files, no GraphQL schema, and no GraphQL dependencies anywhere in the codebase, so there is no GraphQL schema to point to.

**Actual API surface:** The public API is defined as Protocol Buffers and served as gRPC plus a REST/JSON interface via grpc-gateway:

- **Schema definitions:** `proto/api/v1/*.proto` — e.g. `proto/api/v1/memo_service.proto`, `proto/api/v1/user_service.proto`, `proto/api/v1/auth_service.proto`, `proto/api/v1/attachment_service.proto`, etc. (Internal storage-level messages live separately in `proto/store/*.proto`.)
- **Code generation:** managed with `buf` (`proto/buf.yaml`, `proto/buf.gen.yaml`; see `proto/README.md`), with generated Go stubs, grpc-gateway handlers, and an OpenAPI spec under `proto/gen/` (including `proto/gen/openapi.yaml`, embedded via `proto/openapi_embed.go`).
- **Server implementation:** the services are implemented and mounted in `server/router/api/v1/` — registration of the gRPC-gateway handlers happens in `server/router/api/v1/v1.go` (e.g. `RegisterMemoServiceHandlerServer` at `server/router/api/v1/v1.go:108`). The `go.mod` confirms the stack: `github.com/grpc-ecosystem/grpc-gateway/v2` and `connectrpc.com/connect`.

So if you're looking for the API contract, the `.proto` files in `proto/api/v1/` are the equivalent of what a GraphQL schema would be in a GraphQL project.
