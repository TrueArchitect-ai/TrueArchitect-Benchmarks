**Premise correction:** This repository does not use Redis at all — a repo-wide search turns up no Redis client, connection string, or configuration anywhere. The cache layer is a custom **in-memory** cache built into the Go backend.

**Actual mechanism:**

- The cache implementation is `store/cache/cache.go` — a thread-safe in-process cache (`sync.Map` + TTL expiration and a background cleanup goroutine), no external cache server involved.
- It is wired up in `store/store.go` (`New()`, lines 38–61), which creates three caches: `instanceSettingCache`, `userCache`, and `userSettingCache`, all sharing one `cache.Config`:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
- **User entries get the default TTL of 10 minutes.** `store/user.go` populates the user cache via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. lines 98, 122, 132, 167), and `Set` applies the config's `DefaultTTL` (as opposed to `SetWithTTL`, which would allow a custom one). The same 10-minute default is also mirrored in `cache.DefaultConfig()` in `store/cache/cache.go`.

So: no Redis connection exists to configure; user entries live in the in-memory `userCache` with a 10-minute TTL, cleaned up every 5 minutes.
