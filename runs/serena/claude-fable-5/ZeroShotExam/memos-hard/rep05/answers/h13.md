**impl** — The interface is `markdown.Service` (`internal/markdown/markdown.go:31`). The only concrete implementation is the unexported `service` struct in the same file (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown` instance (goldmark + GFM plus custom tag/mention extensions from `internal/markdown/extensions/`). That single implementation is what executes at runtime.

**construction** — Exactly one runtime construction site: `NewAPIV1Service` calls `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())` in `server/router/api/v1/v1.go:47-51`. That factory (`internal/markdown/markdown.go:85`) returns the `*service`. `NewAPIV1Service` is invoked from `server/server.go:76`, and the same instance is then reused — `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService`. (A second construction in `server/router/api/v1/test/test_helper.go:44` is test-only.)

**holders** — Three components declare a `markdown.Service` field:
- `APIV1Service.MarkdownService` — `server/router/api/v1/v1.go:35` (used by memo service handlers, e.g. via `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)` in `server/router/api/v1/memo_service.go:108,447`)
- `RSSService.MarkdownService` — `server/router/rss/rss.go:45,58` (server-side HTML rendering for RSS feeds)
- `memopayload.Runner.MarkdownService` — `server/runner/memopayload/runner.go:16,19` (holds the interface, though at runtime the memo handlers call the package's free function directly and `NewRunner` has no production call site)

(The frontend renders markdown separately with its own pipeline; the Go interface covers extraction, snippets, and RSS HTML.)
