Delivery function — `Post` in `internal/webhook/webhook.go` (line 120), which marshals the payload, optionally adds a Standard Webhooks HMAC-SHA256 signature, and sends the POST via the shared `safeClient`. Asynchronous dispatch goes through `PostAsync`/a bounded worker queue in the same file, but the actual HTTP call happens in `Post`.

Protection mechanism — SSRF guarding split across two layers in `internal/webhook/`:
- At dial time, `safeClient`'s transport uses `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the target hostname and refuses to connect if any resolved IP is in a reserved/private range (this also defeats DNS rebinding).
- The reserved-range logic itself — `reservedCIDRs` / `isReservedIP` — lives in `internal/webhook/validate.go`, covering loopback, RFC-1918, link-local (including the cloud metadata address 169.254.169.254), and IPv6 equivalents. `ValidateURL` in that same file additionally rejects such URLs up front when a webhook is created or updated (used by the API handlers, e.g. `server/router/api/v1/user_service_webhooks.go`). An `AllowPrivateIPs` flag in `validate.go` can disable the check for self-hosted deployments.

So: delivery function — `Post`, `internal/webhook/webhook.go`; protection mechanism — dial-time reserved-IP blocking (`safeDialContext` + `isReservedIP`/`ValidateURL`), `internal/webhook/webhook.go` and `internal/webhook/validate.go`.
