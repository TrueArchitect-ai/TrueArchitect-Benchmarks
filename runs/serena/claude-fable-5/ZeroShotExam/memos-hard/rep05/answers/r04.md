Neither — the premise is wrong. This repo (memos) uses no external message broker at all: a grep for NATS/RabbitMQ/AMQP turns up nothing outside an unrelated locale-file coincidence, and there is no broker client dependency.

Webhook delivery is handled entirely in-process. The "queue" is a buffered Go channel, `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared at `internal/webhook/webhook.go:39`. The "workers" are 4 goroutines started in that package's `init()` (`internal/webhook/webhook.go:42-55`), which range over the channel and call `Post()` to deliver each payload via a plain HTTP POST (with an SSRF-guarded client and optional Standard Webhooks HMAC signing). Producers enqueue through `PostAsync()` (`internal/webhook/webhook.go:184`), which does a non-blocking send and drops the payload with a warning if the channel is full — so delivery is best-effort and in-memory, with no broker, persistence, or retry.
