**Computation site:** The derived metadata is the memo payload's `Property` (plus tags), rebuilt by `memopayload.RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates to the goldmark-based markdown service's single-pass `ExtractAll` in `internal/markdown/markdown.go:356`. The resulting fields are defined in `proto/store/memo.proto` (`MemoPayload.Property`, commented "The calculated properties from the memo content").

**Triggers:**
- **Memo creation** — `CreateMemo` calls `RebuildMemoPayload` before storing (`server/router/api/v1/memo_service.go:108`).
- **Content update** — `UpdateMemo` calls it whenever the update mask includes the `content` path (`server/router/api/v1/memo_service.go:447`).
- **Bulk rebuild** — `Runner.RunOnce` in `server/runner/memopayload/runner.go:27` re-derives the payload for all memos in batches of 100 (a maintenance/migration runner; note it isn't currently wired into `server/server.go`, which only starts the s3presign runner).

**Extracted properties:** From a single AST walk of the markdown content, `ExtractAll` populates:
- `tags` — all hashtag nodes (`memo.Payload.Tags`)
- `Property.title` — text of the first block if it's an H1 heading
- `Property.has_link` — any link node
- `Property.has_code` — code blocks, fenced code blocks, or inline code spans
- `Property.has_task_list` — any task checkbox
- `Property.has_incomplete_tasks` — any unchecked task checkbox

(It also collects `@mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property` — `runner.go:85-86`.) A related but separate derivation, `GenerateSnippet` (`internal/markdown/markdown.go:264`), produces a 64-char plain-text summary, but only for webhook payloads (`server/router/api/v1/memo_service_webhooks.go:85`), not stored metadata.
