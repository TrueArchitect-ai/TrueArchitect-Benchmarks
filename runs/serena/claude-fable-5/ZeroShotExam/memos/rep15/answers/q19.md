MemoService is served over **REST (HTTP/JSON via gRPC-Gateway)** and **Connect RPC** — there is no native gRPC server (no `RegisterMemoServiceServer`/`grpc.NewServer` call exists in `server/`).

- **REST / gRPC-Gateway** — `server/router/api/v1/v1.go:108`, where `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` registers the service on the gateway mux, which is then mounted under `/api/v1/*` (generated gateway code in `proto/gen/api/v1/memo_service.pb.gw.go`).
- **Connect RPC** — `server/router/api/v1/connect_handler.go:40`, where `apiv1connect.NewMemoServiceHandler(s, opts...)` is mounted on the Connect mux inside `RegisterConnectHandlers`; the per-method wrapping of the gRPC-style implementations into Connect request/response types lives in `server/router/api/v1/connect_services.go` (MemoService section starts around line 304; generated handler in `proto/gen/api/v1/apiv1connect/memo_service.connect.go`).

Both protocols share the same underlying `APIV1Service` business logic — the `ConnectServiceHandler` struct just adapts it to Connect's wrapper types.
