Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook`
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook`
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook`
- comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook`

The first three are thin wrappers around the shared helper `dispatchMemoRelatedWebhook` (same file, `server/router/api/v1/memo_service_webhooks.go:48`), which looks up the creator's webhooks and sets the activity type; the comment dispatcher does its own lookup against the related memo owner's webhooks.

Delivery convergence: every path ends by calling `webhook.PostAsync(payload)` in `internal/webhook/webhook.go:184`, which enqueues the payload onto a bounded channel (`asyncPostQueue`); four worker goroutines started in `init()` drain the queue and perform the actual HTTP POST via `webhook.Post` (`internal/webhook/webhook.go:120`), which signs the request (Standard Webhooks HMAC headers when a signing secret is set) and sends it through an SSRF-guarded HTTP client.
