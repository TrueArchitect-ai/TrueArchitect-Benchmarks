Frontend API requests are authenticated by a Connect RPC interceptor: `authInterceptor` in `web/src/connect.ts` (line 156). For every request it obtains an access token via `getRequestToken()` and sets an `Authorization: Bearer <token>` header. It manages two token kinds:

- **Access token** — a short-lived JWT (15 minutes) kept in memory via `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken`). The interceptor proactively refreshes it when it's near expiry, and reactively refreshes-and-retries once on an `Unauthenticated` (401) error, redirecting to login if that fails.
- **Refresh token** — a long-lived (30 days) HttpOnly cookie sent automatically because the transport uses `credentials: "include"`. Refreshes go through a dedicated interceptor-free transport calling `AuthService.refreshToken`, with concurrent refreshes deduplicated by a token-refresh manager.

On the backend, these tokens are validated by the `server/auth` package: `server/auth/authenticator.go` defines `Authenticator` with `AuthenticateByAccessTokenV2` (stateless JWT validation of access tokens, plus PAT support) and `AuthenticateByRefreshToken` (validated against the database), with JWT claims/generation in `server/auth/token.go`.

Answer format summary: `web/src/connect.ts`; JWT access tokens (in-memory, Bearer header) + refresh tokens (HttpOnly cookie); `server/auth`.
