**s3presign runner** — the only background runner the server starts (`server/server.go:153` `startBackgroundRunners`, called from `Start` at `server/server.go:129`). It's driven by a plain `time.Ticker`: one immediate `RunOnce(ctx)` at startup, then `Run` loops on a 12-hour ticker (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). Shutdown is via per-runner `context.CancelFunc` plus a `sync.WaitGroup` (`server/server.go:176-201`).

That's it — no other worker is launched. Two pieces of infrastructure exist but are **not** started by the server:

- **`internal/scheduler`** — a full cron scheduler package (5/6-field cron expressions, timezones, middleware; `internal/scheduler/scheduler.go`, `doc.go`). It is imported by nothing outside its own package and tests; the server never instantiates it. The s3presign runner uses a raw `time.Ticker` instead.
- **`server/runner/memopayload`** — has a `Runner` with `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go`), but the runner is never constructed or started anywhere. Only its standalone `RebuildMemoPayload` function is called, synchronously, from the memo API handlers (`server/router/api/v1/memo_service.go:108,447`) — it's not a background worker in practice.
