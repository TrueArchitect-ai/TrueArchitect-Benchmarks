`web/src/connect.ts`; JWT access tokens (short-lived, ~15 min, sent as `Authorization: Bearer`) plus cookie-based refresh tokens used to obtain new access tokens; `server/auth`

Details:

- **Interceptor**: The Connect RPC `authInterceptor` is defined in `web/src/connect.ts` (line 156) and installed on the transport used by all frontend service clients. It attaches the access token via `Authorization: Bearer <token>` and, on an `Unauthenticated` error, refreshes the token once and retries (marked with an `X-Retry` header).
- **Tokens managed**: A short-lived **access token** kept in memory/state (`web/src/auth-state.ts`, with cross-tab sharing via BroadcastChannel and expiry-buffer preflight refresh) and a long-lived **refresh token** held in an HTTP-only cookie — the refresh call goes through a separate, interceptor-free transport (`refreshAuthClient` in `connect.ts`) with `credentials: "include"`.
- **Backend validation**: The Go package `server/auth` (`authenticator.go`, `token.go`, `extract.go`) validates them — JWT access tokens (15-minute, stateless validation via `AuthenticateByAccessTokenV2`/`ParseAccessTokenV2`), JWT refresh tokens (30 days, checked against the database), and also Personal Access Tokens for programmatic access. It's consumed by the gRPC/Connect interceptors in `server/router/api/v1` and the file server.
