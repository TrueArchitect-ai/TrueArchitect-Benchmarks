The server starts exactly one background runner, in `startBackgroundRunners` (`server/server.go:155-176`), called from `Server.Start`:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — triggered two ways: an immediate `RunOnce(ctx)` at server startup, then a continuous `Run()` goroutine driven by a `time.Ticker` firing every 12 hours (`const runnerInterval = time.Hour * 12`, `runner.go:27-40`), cancelled via a per-runner `context.CancelFunc` on shutdown. It re-presigns S3 attachment URLs.

Unused scheduling infrastructure:

- **memopayload runner** (`server/runner/memopayload/runner.go`) — this package defines a full `Runner` type with `NewRunner` and `RunOnce` (batch-rebuilds the payload of all memos), but the server never instantiates or starts it; `NewRunner`/`RunOnce` have no callers outside the package. Only its package-level helper `memopayload.RebuildMemoPayload` is used, called synchronously per-memo from the API layer (`server/router/api/v1/memo_service.go:108` and `:447`) — not as a scheduled/background job. Note it also has no ticker-based `Run` loop of its own; it's a one-shot batch runner that is simply never wired up.

There is no cron library or other scheduler in the codebase (nothing like `robfig/cron` in `go.mod`); all scheduling is the single `time.Ticker` inside the s3presign runner.
