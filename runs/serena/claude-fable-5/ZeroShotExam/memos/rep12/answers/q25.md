**Engine:** CEL (Common Expression Language) via `github.com/google/cel-go`, wrapped in the repo's own filter engine at `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:210-215`) validates the filter and passes it to the store as a string in `FindMemo.Filters`; each dialect's `ListMemos` (`store/db/sqlite/memo.go:61`, `store/db/mysql/memo.go:69`, `store/db/postgres/memo.go:58`) calls `filter.AppendConditions(...)` with its `DialectName`, which compiles the CEL expression against the memo schema's typed variables (`content`, `tags`, `pinned`, etc.) into a dialect-agnostic condition tree (IR in `internal/filter/ir.go`), then a `renderer` (`internal/filter/render.go`) walks that tree to emit parameterized SQL for the target dialect, with per-dialect column expressions supplied by the schema's `Expressions[DialectName]` map in `internal/filter/schema.go` (e.g. `UNIX_TIMESTAMP(%s)` on MySQL, `CONCAT(...)` vs `||` for string concat).
