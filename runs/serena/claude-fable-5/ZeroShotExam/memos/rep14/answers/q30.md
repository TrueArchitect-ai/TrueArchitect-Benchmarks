Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook` (called from `CreateMemo` in `server/router/api/v1/memo_service.go:157`)
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook` (called via `dispatchMemoUpdatedSideEffects` in `server/router/api/v1/memo_update_helpers.go:67`, which is invoked from memo update, relation, and attachment changes)
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook` (called from `DeleteMemo` in `server/router/api/v1/memo_service.go:562`)
- memo comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook` (called from `server/router/api/v1/memo_service_comments.go:119`)

The created/updated/deleted dispatchers are thin wrappers around the shared helper `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`); the comment dispatcher builds its payload itself because it targets the parent memo owner's webhooks. All four converge on the same delivery path: each per-hook payload is handed to `webhook.PostAsync` in `internal/webhook/webhook.go:184`, which enqueues it on the bounded `asyncPostQueue`; background workers drain that queue and perform the actual HTTP delivery via `webhook.Post` (`internal/webhook/webhook.go:120`), which signs (Standard Webhooks HMAC) and POSTs the JSON payload.
