q29.

`web/src/connect.ts`; short-lived JWT access tokens (sent as `Authorization: Bearer`) plus long-lived refresh tokens (HTTP-only cookie); `server/auth`

Details:

- **Interceptor**: `authInterceptor` is defined in `web/src/connect.ts:156` as a Connect RPC `Interceptor` and installed on the transport at `web/src/connect.ts:184-189`. It attaches the access token as a `Bearer` header, does a preflight refresh when the token is near expiry (`getRequestToken`, `web/src/connect.ts:124`), and on a `Code.Unauthenticated` error refreshes and retries once (marked with an `X-Retry` header) before redirecting to login.
- **Tokens managed**: a short-lived access token (15 min JWT), stored in localStorage and synced across tabs via BroadcastChannel in `web/src/auth-state.ts`, and a long-lived refresh token (30-day JWT) kept in an HTTP-only cookie — the transport uses `credentials: "include"` so the cookie rides along, and `refreshAccessToken` calls `AuthService.refreshToken` over a separate interceptor-free transport to avoid recursion (`web/src/connect.ts:64-91`).
- **Backend validation**: the `server/auth` package — `Authenticator` in `server/auth/authenticator.go` validates JWT access tokens statelessly (`AuthenticateByAccessTokenV2` via `ParseAccessTokenV2` in `server/auth/token.go`), validates refresh tokens against the database (cookie extraction in `server/auth/extract.go`), and also supports Personal Access Tokens for programmatic access. It's shared by the gRPC interceptor, Connect interceptor, and file server.
