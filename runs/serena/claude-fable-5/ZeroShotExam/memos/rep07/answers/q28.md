**Runners the server actually starts** (all wiring is in `server/server.go`, `startBackgroundRunners`, lines 153–174):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — the only background runner started. It runs once immediately at startup (`RunOnce(ctx)` at `server/server.go:163`), then runs continuously in a goroutine via `Run(s3Context)`, driven by a plain `time.NewTicker` with a hard-coded 12-hour interval (`const runnerInterval = time.Hour * 12` in `server/runner/s3presign/runner.go`). Shutdown is via per-runner `context.CancelFunc` plus a `sync.WaitGroup`.

**Present but NOT started as a background worker:**

- **memopayload runner** (`server/runner/memopayload/runner.go`) — it has `NewRunner`/`RunOnce` methods shaped like a runner, but the server never constructs or schedules it. Only its standalone helper `RebuildMemoPayload` is called synchronously from the API layer (`server/router/api/v1/memo_service.go:108` and `:447`) when memos are created/updated.

**Unused scheduling infrastructure:**

- **`internal/scheduler`** — a full cron-style scheduling package (with `scheduler.go`, `parser.go`, `job.go`, `middleware.go`, docs, and tests) that is not imported anywhere outside its own directory. The server does no cron-based scheduling at all; the one live runner uses a raw `time.Ticker` instead of this package.
