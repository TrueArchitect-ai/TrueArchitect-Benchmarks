**Engine + path:** CEL (Google Common Expression Language, via `github.com/google/cel-go`), living in the shared filter package at `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:178`) passes the request's filter string into the store's `MemoFind`; each DB driver builds a schema-aware CEL engine (`filter.DefaultEngine()`), which type-checks and compiles the CEL expression into a dialect-agnostic condition tree/IR (`engine.go`'s `Compile` walks the CEL AST in `parser.go`, folding `now` to a constant), and a renderer (`render.go`) then converts that tree into a parameterized SQL WHERE clause per dialect — `filter.DialectSQLite`, `filter.DialectMySQL`, or `filter.DialectPostgres` — using per-dialect column expressions from `schema.go` (e.g. `('users/' || %s)` for SQLite vs `CONCAT('users/', %s)` for MySQL). The drivers invoke it via `filter.AppendConditions(...)` / `engine.CompileToStatement(...)` in `store/db/sqlite/memo.go:57`, `store/db/mysql/memo.go:65`, and `store/db/postgres/memo.go:54`.
