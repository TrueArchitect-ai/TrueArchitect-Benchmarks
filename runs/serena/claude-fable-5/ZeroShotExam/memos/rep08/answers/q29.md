Frontend requests are authenticated by a ConnectRPC interceptor defined in `web/src/connect.ts` (`authInterceptor`, `web/src/connect.ts:156`). It manages two token kinds: a short-lived **JWT access token** (kept in memory via `web/src/auth-state.ts`, sent as an `Authorization: Bearer ...` header) and a long-lived **refresh token** (stored in the `memos_refresh` HTTP-only cookie, sent via `credentials: "include"`). The interceptor attaches the access token to each request, proactively refreshes it if expired, and on a 401 (`Code.Unauthenticated`) calls `AuthService.refreshToken` through a separate interceptor-free transport, then retries once (marked with an `X-Retry` header) before redirecting to login.

On the backend, tokens are validated by the **`server/auth`** package (`github.com/usememos/memos/server/auth`): `server/auth/authenticator.go` provides the shared `Authenticator` (stateless JWT access-token validation via `AuthenticateByAccessTokenV2`, DB-backed refresh-token validation, and Personal Access Token support), with JWT generation/parsing constants in `server/auth/token.go`. It's consumed by the gRPC/Connect interceptors in `server/router/api/v1` and the file server.

Answer format summary: `web/src/connect.ts`; JWT access tokens (in-memory, Bearer header) + refresh tokens (`memos_refresh` cookie) — backend additionally accepts Personal Access Tokens (`memos_pat_...`); `server/auth`.
