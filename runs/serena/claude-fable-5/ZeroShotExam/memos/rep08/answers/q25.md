**Engine:** CEL (Common Expression Language), via `github.com/google/cel-go`, wrapped in the repo's own filter package at `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-215`) validates the filter string and appends it to `memoFind.Filters`; the filter `Engine.Compile` (`internal/filter/engine.go`) compiles the string against a CEL environment built from a schema, converts the CEL AST to a parsed expression, and the parser (`internal/filter/parser.go`) lowers it into a dialect-agnostic `Condition` IR tree (`internal/filter/ir.go`); then each database driver calls `filter.AppendConditions` with its dialect — `filter.DialectSQLite` in `store/db/sqlite/memo.go:61`, `filter.DialectMySQL` in `store/db/mysql/memo.go:69`, `filter.DialectPostgres` in `store/db/postgres/memo.go:58` — which runs the renderer (`internal/filter/render.go`) to walk the condition tree and emit dialect-specific parameterized SQL (switching on `DialectName` for things like JSON access, string functions, and placeholder style) that gets appended to the query's WHERE clause and args.
