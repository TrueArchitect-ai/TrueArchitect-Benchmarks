**Engine:** CEL (Common Expression Language, via `github.com/google/cel-go`) — the parsing/translation engine lives in `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

**Mechanism:** `MemoService.ListMemos` (`server/router/api/v1/memo_service.go:211-223`) validates the filter and puts it on `memoFind.Filters`; each store driver (e.g. `store/db/sqlite/memo.go:57-61`, plus the `mysql` and `postgres` counterparts) calls `filter.DefaultEngine()` and `filter.AppendConditions(...)` with its `DialectName`. The engine compiles the CEL expression against a memo schema into a dialect-agnostic condition tree (IR in `internal/filter/ir.go`), and a per-dialect `renderer` (`internal/filter/render.go`) walks that tree emitting parameterized SQL fragments with dialect-specific constructs (e.g. `strftime` on SQLite vs `EXTRACT`/date functions on Postgres/MySQL, dialect-aware JSON and placeholder handling), which `AppendConditions` (`internal/filter/helpers.go`) appends to the query's WHERE clause and args.
