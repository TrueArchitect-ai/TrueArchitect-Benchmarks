`web/src/connect.ts`; short-lived JWT access tokens (Bearer, ~15 min, kept via `web/src/auth-state.ts`) plus the long-lived refresh token sent as the `memos_refresh` cookie (`credentials: "include"`) to `AuthService.refreshToken`; validated by `server/auth/` (`github.com/usememos/memos/server/auth`).

Details:

- **Interceptor** — `authInterceptor` in `web/src/connect.ts:156` is a Connect RPC `Interceptor` attached to the transport (`web/src/connect.ts:184-189`). Before each request it fetches the access token (with proactive refresh when near expiry, `getRequestToken` at `web/src/connect.ts:124`) and sets `Authorization: Bearer <token>`. On an `Unauthenticated` error it refreshes once via a dedicated interceptor-free transport (`refreshTransport`, `web/src/connect.ts:65`) and retries, redirecting to login if refresh fails.
- **Tokens** — a short-lived JWT **access token** held in memory (`web/src/auth-state.ts`) and a **refresh token** stored as an HTTP-only cookie (`memos_refresh`), which is why all fetches use `credentials: "include"`. Refresh is deduplicated between the interceptor and the tab-focus hook (`web/src/hooks/useTokenRefreshOnFocus.ts`).
- **Backend validation** — the `server/auth` package (`server/auth/authenticator.go`, `server/auth/token.go`): `Authenticator.AuthenticateByAccessTokenV2` does stateless JWT validation (15-min access tokens, audience `user.access-token`), refresh tokens (30-day, audience `user.refresh-token`) are checked against the DB, and it also supports `memos_pat_`-prefixed personal access tokens. It's consumed by the gRPC/Connect interceptors in `server/router/api/v1` and the file server in `server/router/fileserver`.
