The server starts exactly **one** background runner:

- **S3 presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:153-174`). It runs `RunOnce(ctx)` immediately at startup, then a goroutine runs `Run(ctx)`, whose scheduling is driven by a plain `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:26-41`). It is stopped via a per-runner `context.CancelFunc` on shutdown.

Not started as a background worker, for the record:

- **Memo payload runner** (`server/runner/memopayload/runner.go`) — it has `NewRunner`/`RunOnce` (no continuous `Run` loop), but `NewRunner` is never called anywhere. Only its standalone helper `RebuildMemoPayload` is invoked synchronously during memo create/update in `server/router/api/v1/memo_service.go:108,447`, so it's a library function, not a scheduled worker.

Unused scheduling infrastructure:

- **`internal/scheduler`** — a full cron-style scheduler package (5/6-field cron parsing, timezones, middleware, graceful shutdown; see `internal/scheduler/README.md` and `scheduler.go`) is present in the codebase but is **not imported or used anywhere outside its own package** (its only references are its own tests and examples). The server's sole runner uses a raw `time.Ticker` instead of this scheduler.
