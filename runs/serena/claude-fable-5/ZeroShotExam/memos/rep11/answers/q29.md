**`web/src/connect.ts`; short-lived JWT access tokens (Bearer header) plus HTTP-only refresh-token cookie; `server/auth`**

Details:

- **Interceptor**: `web/src/connect.ts` defines `authInterceptor` (line 156), a ConnectRPC `Interceptor` attached to the `createConnectTransport` used by all service clients (`memoServiceClient`, `userServiceClient`, etc.). It sets the `Authorization: Bearer <token>` header on every request, does a preflight refresh if the access token is near expiry, and on a `Code.Unauthenticated` error performs one refresh-and-retry (marked with an `X-Retry` header) before redirecting to login. A dedicated `refreshTransport` with no interceptors calls `AuthService.refreshToken` to avoid recursion, deduplicated via a token-refresh manager (also used by `web/src/hooks/useTokenRefreshOnFocus.ts`). Access-token storage helpers live in `web/src/auth-state.ts`.

- **Tokens managed**: two kinds — a short-lived JWT **access token** (15-minute lifetime) kept in frontend state and sent as a Bearer header, and a long-lived **refresh token** (30 days) held in the HTTP-only cookie `memos_refresh`, which is sent automatically because all fetches use `credentials: "include"`; the interceptor uses it (via the refresh endpoint) to mint new access tokens.

- **Backend validation**: the `server/auth` package (`server/auth/authenticator.go`, `token.go`, `extract.go`). Its `Authenticator` does stateless JWT validation of access tokens (`AuthenticateByAccessTokenV2` / `ParseAccessTokenV2`), validates refresh tokens against the database, and also supports Personal Access Tokens (`memos_pat_` prefix). It's shared by the gRPC/Connect interceptors in `server/router/api/v1` and the file server.
