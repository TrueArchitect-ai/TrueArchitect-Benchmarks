The server starts exactly one background runner, and it does so in `startBackgroundRunners` at `server/server.go:153-174`:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — triggered once immediately at startup via `RunOnce(ctx)` (`server/server.go:163`), then continuously by a plain `time.NewTicker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`), in a goroutine cancelled via a per-runner context on shutdown.

Not started by the server:

- **memopayload runner** (`server/runner/memopayload/runner.go`) — the `Runner` type and its `NewRunner`/`RunOnce` are never instantiated or scheduled anywhere. Only the package-level helper `memopayload.RebuildMemoPayload` is called synchronously from request handlers in `server/router/api/v1/memo_service.go` (lines 108, 447), which is not a background worker.

Unused scheduling infrastructure:

- **`internal/scheduler`** — a full cron-style job scheduler (5/6-field cron parsing, timezones, middleware, graceful shutdown; see `internal/scheduler/README.md` and `scheduler.go`) is present in the codebase but is imported by nothing outside its own package. Neither `server/` nor `cmd/` references it; the one real periodic job (s3presign) uses a raw `time.Ticker` instead. (The only other ticker in the server, `server/router/api/v1/sse_handler.go:64`, is a per-connection SSE heartbeat, not a background worker.)
