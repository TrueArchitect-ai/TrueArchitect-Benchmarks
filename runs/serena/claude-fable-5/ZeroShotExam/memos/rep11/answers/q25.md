**Engine:** Google's CEL (Common Expression Language), parsed via the `cel-go` library, wrapped in a custom filter engine at `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`).

**Mechanism:** The `ListMemos` handler (`server/router/api/v1/memo_service.go`) passes the filter strings into `MemoFind.Filters`; each store driver then compiles them through a three-phase pipeline — cel-go parses/validates the expression against a memo-specific schema (`internal/filter/schema.go`), `internal/filter/parser.go` normalizes the CEL AST into a dialect-agnostic IR (`internal/filter/ir.go`), and `internal/filter/render.go` walks that IR to emit a SQL fragment plus args for the target dialect, encapsulating differences like `?` vs `$n` placeholders, `JSON_EXTRACT` vs `->`/`->>` JSON access, and tag containment (`LIKE` on SQLite, `JSON_CONTAINS` on MySQL, `@>` on Postgres).

Each dialect wires it in via `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` (helper in `internal/filter/helpers.go`), e.g. `store/db/sqlite/memo.go:61`, `store/db/postgres/memo.go:58`, and the equivalent in `store/db/mysql/memo.go`. The pipeline is documented in `internal/filter/README.md`.
