**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (a `@connectrpc/connect` `Interceptor`, lines 156–178) is attached to the Connect transport that all frontend service clients use.

**Token kinds:** It manages short-lived JWT **access tokens**, attached as `Authorization: Bearer <token>` headers (from in-memory auth state in `web/src/auth-state.ts`), and cookie-based **refresh tokens** (sent via `credentials: "include"` to `AuthService.RefreshToken` on a dedicated interceptor-free transport). The interceptor does a preflight refresh when the access token is near expiry and a reactive refresh-and-retry on `Unauthenticated` (401) errors, redirecting to login if refresh fails.

**Backend validation package:** `server/auth/` (`github.com/usememos/memos/server/auth`) — `server/auth/authenticator.go` and `server/auth/token.go` define the `Authenticator` that validates JWT access tokens (15-minute lifetime, audience `user.access-token`), refresh tokens (30 days, `memos_refresh` cookie), and personal access tokens (`memos_pat_` prefix). It's used by the gRPC/Connect API interceptors in `server/router/api/v1` and the file server in `server/router/fileserver`.
