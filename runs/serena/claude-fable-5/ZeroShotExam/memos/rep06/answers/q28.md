**Runners the server actually starts** (see `server/server.go:153` `startBackgroundRunners`, called from `Server.Start` at `server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — the only background runner started. Trigger: `RunOnce` is executed immediately at startup (`server/server.go:163`), then a goroutine runs `Run`, which loops on a plain `time.Ticker` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:26-40`), refreshing S3 presigned URLs until its per-runner context is cancelled on shutdown.

**Present but NOT started by the server:**

- **memopayload runner** (`server/runner/memopayload/runner.go`) — has `NewRunner`/`RunOnce`, but the server never constructs or schedules it. Only its standalone helper `RebuildMemoPayload` is called synchronously from the API layer during memo create/update (`server/router/api/v1/memo_service.go:108,447`).
- **`internal/scheduler` cron package** (`internal/scheduler/`) — a full GitHub-Actions-style cron scheduler (cron expressions, timezones, middleware; see `internal/scheduler/doc.go`) that is **not imported anywhere outside its own package and tests**. The server does not use it; the one real runner is scheduled with a bare `time.Ticker` instead.
