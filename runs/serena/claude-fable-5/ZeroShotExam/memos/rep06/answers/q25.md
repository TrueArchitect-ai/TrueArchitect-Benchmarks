**Engine:** CEL (Common Expression Language), parsed with `github.com/google/cel-go`. **Path:** the filter engine lives in `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`).

**Mechanism:** The RPC handler (`server/router/api/v1/memo_service.go:211-223`) validates the filter and stores it on `memoFind.Filters`; the engine then runs a three-phase pipeline — cel-go parses/validates the expression against the memo-specific CEL environment in `internal/filter/schema.go`, `internal/filter/parser.go` normalizes the CEL AST into a dialect-agnostic IR (`internal/filter/ir.go`), and `internal/filter/render.go` walks the IR to emit a SQL fragment plus placeholder args per dialect (SQLite/MySQL/Postgres), encapsulating differences like `?` vs `$n` placeholders, JSON access (`JSON_EXTRACT` vs `->>`), boolean coercion, and tag-array predicates (`LIKE` / `JSON_CONTAINS` / `@>`).

Each store driver (`store/db/sqlite/memo.go:57`, `store/db/mysql/memo.go:65`, `store/db/postgres/memo.go:54`) calls `filter.AppendConditions` (`internal/filter/helpers.go`) with its own dialect constant to compile the filter strings into WHERE-clause fragments and bound args for the query it builds.
