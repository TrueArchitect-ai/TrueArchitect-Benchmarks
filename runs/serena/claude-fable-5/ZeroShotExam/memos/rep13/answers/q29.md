**Answer:** `web/src/connect.ts`; short-lived JWT access tokens (sent as `Authorization: Bearer …`) plus HTTP-only refresh-token cookies used to obtain new access tokens; `server/auth`.

Details:

- **Interceptor:** The `authInterceptor` (a ConnectRPC `Interceptor`) is defined in `web/src/connect.ts:156` and installed on the transport at `web/src/connect.ts:184-189` for all service clients (memo, user, auth, etc.).
- **Tokens it manages:** It attaches the in-memory **access token** as a `Bearer` header (`web/src/connect.ts:97-100`, with state kept in `web/src/auth-state.ts`), and when the token is missing/expired or a request comes back `Unauthenticated`, it calls `refreshAccessToken()` (`web/src/connect.ts:74-91`), which hits the `AuthService.RefreshToken` RPC over a cookie-credentialed transport — the **refresh token** itself lives in a cookie sent via `credentials: "include"` (`web/src/connect.ts:57-70`). It retries the failed request once (guarded by an `X-Retry` header) and redirects on auth failure.
- **Backend validation:** The `server/auth` package validates them — `AuthenticateByAccessTokenV2` parses/verifies the short-lived JWT access token, `AuthenticateByRefreshToken` checks refresh tokens against the store (revocation/expiry), and `AuthenticateByPAT` handles personal access tokens (`server/auth/authenticator.go:39-107`, with header extraction helpers in `server/auth/extract.go`).
