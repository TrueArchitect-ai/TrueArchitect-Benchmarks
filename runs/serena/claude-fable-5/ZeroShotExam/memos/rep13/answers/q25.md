**Engine:** CEL (Common Expression Language), parsed with the `cel-go` library. **Path:** the filter engine lives in `/bench/repo/internal/filter/` (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`, documented in `internal/filter/README.md`).

**Mechanism:** the `ListMemos` handler (`server/router/api/v1/memo_service.go`) puts the filter string(s) onto `memoFind.Filters`; each store driver (`store/db/sqlite/memo.go:57`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go:54`) calls `filter.DefaultEngine()` and `filter.AppendConditions(...)` with its dialect, and the engine runs a three-phase pipeline — cel-go parses/validates the expression against the memo schema (`schema.go`), `parser.go` normalizes the CEL AST into a dialect-agnostic IR (`ir.go`), and `render.go` walks the IR to emit a SQL fragment plus placeholder args per dialect (`filter.DialectSQLite`/`DialectMySQL`/`DialectPostgres`), encapsulating differences like `?` vs `$n` placeholders, `JSON_EXTRACT` vs `->>` JSON access, and tag matching via `LIKE` / `JSON_CONTAINS` / `@>` — which `AppendConditions` (`internal/filter/helpers.go`) then appends to the query's `WHERE` clause.
