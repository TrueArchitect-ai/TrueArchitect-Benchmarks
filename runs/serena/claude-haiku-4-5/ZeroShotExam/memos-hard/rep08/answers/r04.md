**Premise correction:** The webhook delivery workers do not consume from either NATS or RabbitMQ.

**Actual mechanism:** The webhook delivery system uses Go channels as an in-memory queue, not an external message broker. The queue is declared in `internal/webhook/webhook.go` at lines 39-40:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

A fixed pool of 4 goroutine workers initialized in the `init()` function (lines 42-55) consume from this channel. Webhooks are enqueued via the `PostAsync()` function when triggered from various endpoints like `server/router/api/v1/memo_service_webhooks.go`. This is a lightweight, single-process async pattern with no external broker dependency.
