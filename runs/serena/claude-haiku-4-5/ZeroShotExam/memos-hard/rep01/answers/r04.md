**r04.**

The webhook delivery system does **not** use NATS or RabbitMQ. The premise of the question is incorrect.

**Actual mechanism:** Webhook delivery workers consume from an **in-memory Go channel queue**, not a message broker. The queue is declared and initialized in `/bench/repo/internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the `init()` function (lines 42-55) that consume from this unbuffered channel and dispatch webhooks synchronously via HTTP POST. Webhook requests are enqueued through the `PostAsync()` function (line 184), which writes to this same channel. If the channel buffer is full, requests are dropped with a warning.
