**Premise correction:** The webhook delivery workers do not consume from NATS or RabbitMQ.

**Actual mechanism:** The webhook delivery workers consume from an **in-memory Go channel** named `asyncPostQueue`. The queue is declared at `/bench/repo/internal/webhook/webhook.go:39` as:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four concurrent worker goroutines are launched in the `init()` function (lines 42-55 in the same file) that range over this channel and process webhook payloads. The queue has a fixed buffer size of 128 messages. If the buffer fills, new webhook enqueue attempts fail silently. This is an in-process, non-persistent implementation suitable only for single-instance deployments.
