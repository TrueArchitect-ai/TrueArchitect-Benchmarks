h05. **Explicit Go code**; evidence locations:

**Mechanism**: When a user is deleted, emoji reactions are removed by **explicit Go code** through two DELETE statements executed in database transactions:

1. **Reactions created by the deleted user** are removed via `deleteReactionsByCreatorTx()` — deletes all rows where `creator_id` matches the deleted user.

2. **Reactions on memos created by the deleted user** are removed via `deleteReactionsByContentIDsTx()` — deletes all reactions where `content_id` matches any of the deleted user's memos.

**Evidence locations**:
- `/bench/repo/store/db/sqlite/user_delete.go`, `/bench/repo/store/db/postgres/user_delete.go`, `/bench/repo/store/db/mysql/user_delete.go` (lines ~400-403 and ~380-388 respectively for the two deletion functions)
- The `reaction` table schema has **no foreign key constraints** on `creator_id`, confirming that cleanup is not handled by database-level CASCADE rules
- Deletion flow orchestrated in `deleteUserTargetsTx()` (line 92 in each driver), which calls both functions within a single transaction for atomicity
