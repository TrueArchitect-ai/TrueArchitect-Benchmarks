The following database tables are affected when DeleteMemo runs:

1. **memo** - directly deleted via explicit code (`store.DeleteMemo()`)
2. **memo_relation** - directly deleted via explicit code (DeleteMemoRelation is called for both MemoID and RelatedMemoID)
3. **attachment** - directly deleted via explicit code (DeleteAttachment is called for each attachment)
4. **memo_share** - deleted via ON DELETE CASCADE foreign key constraint (all database backends: SQLite, PostgreSQL, MySQL)

**Evidence:**
- `/bench/repo/store/memo.go` (DeleteMemo function) - explicit deletions of memo_relation, attachments, and memo
- `/bench/repo/store/migration/sqlite/LATEST.sql` - memo_share has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE`
- `/bench/repo/store/migration/postgres/LATEST.sql` - same cascade constraint
- `/bench/repo/store/migration/mysql/LATEST.sql` - same cascade constraint
