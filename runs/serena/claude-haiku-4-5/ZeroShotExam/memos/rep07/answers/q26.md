Now let me summarize the flow:

1. **DeleteMemo** (memo_service.go:518-593):
   - Lists reactions on the memo (but doesn't delete them - they're just loaded for webhook)
   - Deletes memo comments (which themselves are memos - calls DeleteMemo recursively)
   - Calls store.DeleteMemo()

2. **store.DeleteMemo** (memo.go:140-159):
   - Calls DeleteMemoRelation with MemoID (deletes rows from **memo_relation**)
   - Calls DeleteMemoRelation with RelatedMemoID (deletes rows from **memo_relation**)  
   - Calls DeleteAttachment for each attachment (deletes rows from **attachment**)
   - Calls driver.DeleteMemo() to delete from **memo** table

3. **Cascade**:
   - memo_share has ON DELETE CASCADE foreign key to memo, so **memo_share** rows are automatically deleted by the database

The tables affected are:
- **memo** (explicitly deleted)
- **memo_relation** (explicitly deleted via DeleteMemoRelation)
- **attachment** (explicitly deleted via DeleteAttachment)
- **memo_share** (deleted via cascade)

Reactions are not deleted - they reference memos via content_id which is a string like "memos/abc123", not an integer foreign key, so there's no cascade.
