When DeleteMemo runs, the following database tables are affected (directly or by explicit cascade code):

1. **memo** - directly deleted (explicit DELETE statement)
2. **memo_relation** - deleted explicitly in two operations (one for memo_id, one for related_memo_id)
3. **attachment** - deleted explicitly (all attachments linked to the memo)
4. **memo_share** - cascade deleted via foreign key constraint `ON DELETE CASCADE`

**Note on reactions table:** The `reaction` table stores reactions with a `content_id` field that references the memo name, but there is NO foreign key constraint defined. Therefore, reactions are NOT automatically deleted when a memo is deleted—they are orphaned in the database. This appears to be an oversight as DeleteMemo does not include explicit deletion of reactions despite loading them for the webhook dispatch.
