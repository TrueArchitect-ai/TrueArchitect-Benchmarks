Frontend API requests get authenticated through the following pipeline:

**Interceptor path:** `web/src/connect.ts` (lines 156-178)

**Token kinds:** The interceptor manages two token types:
1. **Access Token** - short-lived JWT (15 minutes) used for API requests, sent in Authorization header as Bearer token
2. **Refresh Token** - long-lived JWT (30 days) stored as HTTP-only cookie, automatically used to refresh access tokens when expired

**Backend validation package:** `server/auth` (located at `/bench/repo/server/auth/`)

The authentication flow:
1. Frontend's `authInterceptor` in `connect.ts` adds the access token to the Authorization header via `setAuthorizationHeader()` 
2. On 401 response, it calls `refreshAccessToken()` which hits the AuthService via a token-refresh client
3. Backend's `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` (lines 205-240) validates tokens using the `Authorizer.Authenticate()` method
4. Validation is delegated to `server/auth/authenticator.go`, which calls `ParseAccessTokenV2()` from `server/auth/token.go` (lines 219-233) for stateless JWT validation or checks PAT tokens against the database
