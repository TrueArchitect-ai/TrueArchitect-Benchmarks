q26. **memo, memo_share**

When DeleteMemo runs in the store layer, it directly deletes from the **memo** table. The **memo_share** table is cascaded through database-level foreign key constraints (ON DELETE CASCADE) defined in all three dialects (PostgreSQL, MySQL, SQLite).

Note: While the API layer code comment suggests that relations and attachments are handled by DeleteMemo, the actual store implementation only deletes the memo row itself. The memo_relation and attachment tables are NOT explicitly deleted or cascaded - this appears to be a comment that doesn't match the implementation.
