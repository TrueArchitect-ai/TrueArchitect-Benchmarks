q26. memo, memo_relation, attachment, memo_share, reaction

When DeleteMemo runs, the following tables are affected:

1. **memo** — the memo row is deleted directly via `driver.DeleteMemo`
2. **memo_relation** — explicitly deleted via `DeleteMemoRelation` (both as source `MemoID` and target `RelatedMemoID`)
3. **attachment** — explicitly deleted via `DeleteAttachment` for all attachments linked to the memo
4. **memo_share** — implicitly deleted via `ON DELETE CASCADE` foreign key constraint (defined in schema line 109)
5. **reaction** — implicitly affected, as reactions reference the memo via `content_id` field (though no explicit cascade defined, reactions with `content_id` matching the memo are orphaned or cleaned up by the API layer at line 545)
