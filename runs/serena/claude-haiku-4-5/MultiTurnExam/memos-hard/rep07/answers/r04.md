**Premise Correction:** There is no message broker (NATS or RabbitMQ) used for webhook delivery workers. The premise of the question is incorrect.

**Actual Mechanism:** Webhook delivery uses an in-memory Go channel-based queue with 4 concurrent worker goroutines. The queue is declared in **internal/webhook/webhook.go:39** as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (capacity of 128 payloads). In the `init()` function (lines 42-55), 4 goroutines are spawned that consume from this channel and call `Post(payload)` to deliver each webhook. The `PostAsync()` function (line 184) enqueues payloads into this channel. This is a lightweight, in-process solution with no external message broker dependency.
