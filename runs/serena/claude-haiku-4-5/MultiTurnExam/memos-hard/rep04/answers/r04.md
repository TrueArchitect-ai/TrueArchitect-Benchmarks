**Premise correction:** The webhook delivery workers do NOT consume from NATS or RabbitMQ. Neither message broker is used.

**Actual mechanism:** Webhook delivery uses a simple in-memory Go channel-based queue. The queue is declared as a package-level variable in `/bench/repo/internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This queue has a capacity of 128 messages. In the `init()` function (lines 42-54), 4 concurrent worker goroutines are spawned that consume from this channel and execute webhook delivery by calling the `Post()` function. When `PostAsync()` is called, it enqueues the payload to this channel (line 190 in the same file). If the queue is full, the message is dropped with a warning log.
