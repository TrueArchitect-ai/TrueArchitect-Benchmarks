**Premise correction:** The codebase does not use Redis. The assumption about a Redis connection is incorrect.

**Actual mechanism:** Memo uses an in-memory cache layer implemented entirely in Go. The cache is configured at store/store.go:40-45, where:

- Cache type: In-memory `cache.Cache` (store/cache/cache.go:66-85)
- User cache instantiation: store/store.go:52 (`userCache: cache.New(cacheConfig)`)
- User entry TTL: **10 minutes** (store/store.go:41: `DefaultTTL: 10 * time.Minute`)
- Cleanup interval: 5 minutes (store/store.go:42)
- Max items: 1000 (store/store.go:43)

The cache is thread-safe using sync.Map and atomic operations, with background cleanup goroutines that expire entries after their TTL. There is no external Redis dependency; all caching is local to the server process.
