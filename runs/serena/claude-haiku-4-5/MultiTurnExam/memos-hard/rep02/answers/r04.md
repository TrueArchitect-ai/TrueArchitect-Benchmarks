**Premise correction:** The webhook delivery system does not use either NATS or RabbitMQ. The premise is incorrect.

**Actual mechanism:** Webhook delivery uses an **in-memory Go channel** for job queueing, not an external message broker.

**Queue declaration:** internal/webhook/webhook.go:39
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

**Workers:** internal/webhook/webhook.go:42-54 — An `init()` function spawns 4 goroutine workers that consume from the channel:
```go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously", ...)
				}
			}
		}()
	}
}
```

The queue has a bounded capacity of **128 payloads**. When full, new webhook dispatches are dropped with a warning (internal/webhook/webhook.go:192: "Dropped webhook dispatch because the async queue is full").

This is a simple in-process queue using Go channels, not a distributed message broker like NATS or RabbitMQ.
