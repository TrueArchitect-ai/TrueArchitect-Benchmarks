The premise is off: **there is no nightly database-cleanup job in this repository.** The cron scheduler exists as a standalone library that nothing in the application actually uses.

What's actually there:

- `internal/scheduler/` is a self-contained cron scheduler package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). Grepping for imports of `github.com/usememos/memos/internal/scheduler` turns up only `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13` — no production code registers any job with it.
- `"0 2 * * *"` (2 AM daily) does appear next to a job named `daily-cleanup`, but only in documentation snippets: `internal/scheduler/doc.go:15-16` and `internal/scheduler/README.md:34-35` (repeated at `README.md:321`). The README also shows a `stale-session-cleanup` example at `"0 3 * * *"` (`README.md:241-245`). These are illustrative examples of the API, not registered jobs — and the README even advises against `0 2 * * *` in favor of an offset like `"5 2 * * *"` (`README.md:267-268`).

The only real recurring background work runs on plain tickers, not cron, and isn't database cleanup:

- `server/runner/s3presign/runner.go:27,30` — refreshes S3 presigned links every 12 hours (`runnerInterval = time.Hour * 12`).
- `server/runner/memopayload/` — started alongside it in `server/server.go:153-173`; a one-pass rebuild of memo payloads, no interval.

So if you were looking for a scheduled DB cleanup to modify or to change the time on, it would need to be written first — the scheduler package is ready to use, but is currently unwired.
