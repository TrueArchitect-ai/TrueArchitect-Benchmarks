**Premise correction:** Neither. This repo (Memos) has no external message broker at all — there's no NATS, RabbitMQ, or AMQP dependency anywhere. `go.mod` contains no broker client library, and the only case-insensitive match for "nats"/"rabbitmq"/"amqp" in the whole tree is an unrelated string in `web/src/locales/ca.json`. There are also no separate "delivery worker" processes; Memos ships as a single Go binary.

**Actual mechanism — an in-process buffered Go channel with a fixed goroutine pool:**

- **The "queue" is declared** at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  a package-level buffered channel holding at most 128 pending payloads.

- **The "workers"** are 4 goroutines started in `init()` at `internal/webhook/webhook.go:42-55`. Each ranges over `asyncPostQueue` and calls `Post(payload)`; failures are only logged via `slog.Warn` — there is no retry, no dead-letter, and no persistence, so anything in flight is lost on restart.

- **Enqueue** happens in `PostAsync` (`internal/webhook/webhook.go:184-196`) via a `select` with a `default` branch: if the buffer is full, the payload is **dropped** with a warning rather than blocking the caller.

- **Producers** are the API handlers, not a broker publisher: `server/router/api/v1/memo_service_webhooks.go:43` and `:71` call `webhook.PostAsync(payload)` for `memos.memo.created/updated/deleted` and `memos.memo.comment.created`, after loading the user's registered endpoints with `s.Store.GetUserWebhooks`.

- **Delivery itself** is a plain HTTP POST in `Post` (`internal/webhook/webhook.go:120-180`), using a shared `safeClient` (`:32-37`) with a 30s timeout and an SSRF-guarding `safeDialContext` (`:59-77`) that rejects reserved/private IPs. Requests are optionally signed per the Standard Webhooks spec (`webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<HMAC-SHA256>`, `:133-150`).

So the closest thing to a "queue declaration" is that single `make(chan ..., 128)` line — it lives in the same process as the API server, not in any broker.
