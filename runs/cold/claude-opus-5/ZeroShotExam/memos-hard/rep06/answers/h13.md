## The interface

`markdown.Service` — `internal/markdown/markdown.go:31-55`. Eight methods: `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

## Concrete implementation(s)

**Exactly one:** the unexported `service` struct at `internal/markdown/markdown.go:57-60`, which wraps a `goldmark.Markdown` instance. There are no mocks, fakes, or alternate implementations anywhere in the repo — tests use the real `NewService(...)` (e.g. `internal/markdown/markdown_test.go:11`, `server/router/rss/rss_test.go:54`). So `*markdown.service` is the only thing that ever executes at runtime; the interface exists for seam/documentation rather than polymorphism.

Behavior is varied by functional options rather than by type: `WithTagExtension()` and `WithMentionExtension()` (`internal/markdown/markdown.go:67-81`) toggle the custom goldmark extenders in `internal/markdown/extensions/`, on top of `extension.GFM` and `parser.WithAutoHeadingID()`.

## Construction

- **Production (the only live instance):** `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())` inside `NewAPIV1Service` at `server/router/api/v1/v1.go:48-51`, called from `server/server.go:76`. That single instance is then shared — `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService(...)`.
- **Tests:** `server/router/api/v1/test/test_helper.go:44` (tags + mentions), `server/router/fileserver/fileserver_test.go:427` (tags only), `server/router/rss/rss_test.go:54` (no options).

Note on that third holder: `memopayload.NewRunner` (`runner.go:19`) is never called anywhere in the repo — `server/server.go` only wires `s3presign.NewRunner`. So the `Runner` struct field holds the interface but doesn't execute in production; the live path into that package is the free function `RebuildMemoPayload(ctx, memo, markdownService)` (`runner.go:74`), which takes `markdown.Service` as a parameter from `APIV1Service`.

The frontend does **not** go through this interface — `web/src/components/MemoContent/MemoMarkdownRenderer.tsx` uses `react-markdown` with remark/rehype plugins directly, which is why the Go interface doc comment says HTML rendering is "primarily done on frontend" and backend `RenderHTML` exists for RSS.
