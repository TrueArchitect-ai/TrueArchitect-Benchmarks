**Premise correction: this repository (Memos) has no per-user API rate-limiting middleware. There is nothing registered, and therefore no request limits to report.**

Evidence from the actual middleware chains:

**Connect/gRPC interceptor chain** — `server/router/api/v1/v1.go:133-140` registers exactly four interceptors, none of them a limiter:
- `NewMetadataInterceptor()`
- `NewLoggingInterceptor(logStacktraces)`
- `NewRecoveryInterceptor(logStacktraces)`
- `NewAuthInterceptor(authorizer)`

Those four are the complete set defined in `server/router/api/v1/connect_interceptors.go` (types at lines 22, 98, 165, 208) — there is no fifth.

**Echo HTTP middleware chain** — `server/server.go:51-52` registers only `middleware.Recover()` and `newCORSMiddleware(profile)`.

Corroborating checks:
- No 429 / `TooManyRequests` response is produced anywhere in `server/` or `internal/`.
- No rate-limiting dependency is used. `golang.org/x/time` (which provides `rate.Limiter`) is present in `go.mod:151` but marked `// indirect`, i.e. pulled in transitively and not imported by this codebase.
- The only textual mention of rate limiting is an aspirational note in `internal/email/doc.go:86` — `"- Rate limit email sending to prevent abuse"` — a future-work comment, not an implementation.

**What likely prompted the question** — the API does enforce limits, but they are *size* limits, not *rate* limits, and they are global rather than per-user:

- `maxAPIRequestBytes = 256 << 20` (256 MiB) at `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` to the gateway and Connect routes (lines 126, 144) and via `connect.WithReadMaxBytes` (line 141).
- A per-memo content length limit (`contentLengthLimit`, an instance setting) enforced in `server/router/api/v1/memo_service.go:106` and `:444`.
- An `UploadSizeLimitMb` instance setting (`server/router/api/v1/instance_service_converters.go:138`).

The `Limit` fields scattered through `server/router/rss/rss.go`, `server/runner/*`, and the service files are pagination/query bounds on store lookups, not throttling.

If you need per-user throttling, it would have to be added — the natural insertion point is a new interceptor in the `connect.WithInterceptors(...)` list at `server/router/api/v1/v1.go:133`, placed after `NewAuthInterceptor` so the authenticated user identity is available on the context.
