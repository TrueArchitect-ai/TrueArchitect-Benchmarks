**`*markdown.service` (the single unexported goldmark-backed impl) — constructed once by `apiv1.NewAPIV1Service` via `markdown.NewService(WithTagExtension(), WithMentionExtension())` — held by `APIV1Service`, `rss.RSSService`, and `memopayload.Runner`, plus passed as a parameter to `memopayload.RebuildMemoPayload`.**

Details:

**The interface** — `markdown.Service` at `internal/markdown/markdown.go:31-57` (ExtractAll, ExtractTags, ExtractProperties, RenderMarkdown, RenderHTML, GenerateSnippet, ValidateContent, RenameTag).

**Implementations** — exactly one: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:60-62`; methods at lines 118, 199, 252, 262, 271, 349, 358, 439). No mocks or fakes implement the interface anywhere — tests use the real `NewService(...)`. So `*service` is the only thing that ever executes at runtime.

**Construction** — `markdown.NewService(opts ...Option) Service` (`internal/markdown/markdown.go:85`) always builds `goldmark.New` with `extension.GFM` + `parser.WithAutoHeadingID()`, plus the tag/mention extensions when enabled.

There is exactly one runtime construction site: `NewAPIV1Service` at `server/router/api/v1/v1.go:48-51`, enabling both `WithTagExtension()` and `WithMentionExtension()`. That instance is stored on `APIV1Service.MarkdownService` and shared onward — `server/server.go:76` builds the API service, then line 85 hands `apiV1Service.MarkdownService` to `rss.NewRSSService`. (`server/router/api/v1/test/test_helper.go:44-46` is the only other construction, mirroring the same options for tests.)

**Holders of the interface type**
- `APIV1Service.MarkdownService` — `server/router/api/v1/v1.go:35`; used for `ExtractAll` (`memo_mention_helpers.go:32`), `GenerateSnippet` for webhooks (`memo_service_webhooks.go:85`), and passed into `memopayload.RebuildMemoPayload` (`memo_service.go:108`, `:447`).
- `RSSService.MarkdownService` — `server/router/rss/rss.go:45`, set in `NewRSSService` (`:58`); used for server-side `RenderHTML` in feeds (`rss.go:339`).
- `memopayload.Runner.MarkdownService` — `server/runner/memopayload/runner.go:16`, set by `NewRunner` (`:19`). Note: `NewRunner` has **no caller** in the repo — `server.go:162` only wires `s3presign.NewRunner`. So the Runner field holds the interface structurally, but at runtime the payload rebuild path goes through the free function `RebuildMemoPayload(ctx, memo, markdownService)` (`runner.go:74`), which takes `markdown.Service` as a parameter from `APIV1Service`.

One caveat worth flagging: this interface covers **backend** markdown only. HTML rendering for the UI is done in the frontend with `markdown-it` (per the doc comment at `internal/markdown/markdown.go:26-29`, and `web/src/components/MemoContent/MemoMarkdownRenderer.tsx`); the backend `RenderHTML` exists for RSS and other server-side needs.
