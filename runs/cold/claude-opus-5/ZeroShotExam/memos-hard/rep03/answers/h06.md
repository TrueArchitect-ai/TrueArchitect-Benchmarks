The four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go`; each loads the creator's webhooks via `Store.GetUserWebhooks` and calls `webhook.PostAsync(payload)` with `payload.URL = hook.Url` (lines 43 and 71). The URLs themselves are user-configured through the `CreateUserWebhook` / `UpdateUserWebhook` handlers in `server/router/api/v1/user_service_webhooks.go` (validated by `webhook.ValidateURL`, `internal/webhook/validate.go`).

**Convergence function — `webhook.Post` at `internal/webhook/webhook.go:120`**, which issues the actual `POST` via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

Every handler path reaches it through the single shared enqueue point `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which pushes onto a 128-slot `asyncPostQueue` drained by four goroutines started in `init()` (lines 42–55) that call `Post`. So `PostAsync` is the common call-graph funnel; `Post` is the single function that performs delivery (signing with HMAC-SHA256 and dialing through `safeDialContext`, which blocks reserved/private IPs for SSRF protection).

Note: other outbound HTTP to user-configured URLs exists but does *not* pass through this function — the OAuth2 IdP `UserInfoUrl` fetch (`internal/idp/oauth2/oauth2.go:84`), STT/AudioLLM provider endpoints (`internal/ai/stt`, `internal/ai/audiollm`), and link-preview fetching (`internal/httpgetter/html_meta.go`). Those are separate paths with no shared convergence point.
