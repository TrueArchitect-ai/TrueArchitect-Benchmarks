Two notes on the edges of this map:
- `GetMemoByShare` (`server/router/api/v1/memo_share_service.go:154-190`) deliberately **bypasses** visibility — a valid, unexpired share token grants read access regardless of PRIVATE/PROTECTED; it only enforces token validity/expiry and archived state. The file server honors the same token via the `share_token` query param (`fileserver.go:683-689`).
- The MCP endpoint (`server/router/mcp/`) is not a separate enforcement site — it proxies in-process through the same HTTP API routes (`server/router/mcp/adapter.go`), so it inherits the API v1 checks.
