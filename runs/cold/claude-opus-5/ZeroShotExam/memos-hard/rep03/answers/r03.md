**Premise correction: this repository has no nightly database-cleanup job scheduled in the cron scheduler.** There is nothing to report a run time for, because no such job is registered anywhere in the running application.

What actually exists:

- `internal/scheduler/` is a standalone, self-contained cron scheduler library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It is never imported by application code — the only importers are its own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. The scheduler is never instantiated or started by the server, so no cron job of any kind runs in Memos.
- Every `"0 2 * * *"` ("2 AM daily") cleanup you may have seen is **illustrative documentation/example code**, not a registered job:
  - `internal/scheduler/README.md:34` — quick-start snippet, `Name: "daily-cleanup"`
  - `internal/scheduler/doc.go:15` — same snippet in the package doc comment
  - `internal/scheduler/example_test.go:97-99` — `Example_multipleJobs`, `Name: "cleanup"`
  - `internal/scheduler/README.md:241-245` — a *different* hypothetical example, `"stale-session-cleanup"` at `"0 3 * * *"`, and the README elsewhere advises against on-the-hour scheduling (`"5 2 * * *"` over `"0 2 * * *"`).

The only real periodic cleanup in the codebase is not cron-based and not database-related: the in-memory cache sweeps expired entries on a ticker every 5 minutes by default (`store/cache/cache.go:60`, loop at `store/cache/cache.go:199-201`). The other background loops are the S3 presign refresher (`server/runner/s3presign/runner.go:30`) and the SSE heartbeat (`server/router/api/v1/sse_handler.go:64`).
