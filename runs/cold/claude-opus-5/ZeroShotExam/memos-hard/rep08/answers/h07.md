The avatar bytes are **not** files on disk or in S3 — they're stored inline as a base64 data URI in the `user.avatar_url` column, so the "data layer" hop ends at a `SELECT` on the `user` table.

**Hops:**

1. `UserAvatar` (`<img src={avatarUrl}>`) — `web/src/components/UserAvatar.tsx:12-14`
2. `convertUserFromStore` (rewrites base64 avatars to the URL `/file/users/{username}/avatar`) — `server/router/api/v1/user_service_converters.go:32-40`
3. `FileServerService.RegisterRoutes` (`GET /file/users/:identifier/avatar`) — `server/router/fileserver/fileserver.go:124`, wired at `server/server.go:81-82`
4. `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
5. `FileServerService.getCurrentUser` → `Authenticator.AuthenticateToUser` (only on private instances, i.e. `!Profile.AllowAnonymous()`) — `server/router/fileserver/fileserver.go:708` → `server/auth/authenticator.go:190`
6. `FileServerService.getUserByUsername` (`store.FindUser{Username: &identifier}`) — `server/router/fileserver/fileserver.go:715`
7. `Store.GetUser` (ID-keyed cache only; a username lookup always falls through) — `store/user.go:148`
8. `Store.ListUsers` → `s.driver.ListUsers` — `store/user.go:136`, interface at `store/driver.go:47`
9. `DB.ListUsers` — `store/db/sqlite/user.go:88` (peers: `store/db/postgres/user.go:87`, `store/db/mysql/user.go:84`); driver picked in `store/db/db.go:14`
10. `SELECT ... avatar_url ... FROM user WHERE username = ?` → `rows.Scan(&user.AvatarURL)` — `store/db/sqlite/user.go:151-198`

**Return path:** `parseDataURI` decodes the `data:image/...;base64,...` value (`fileserver.go:737`), the MIME type is checked against `avatarAllowedTypes` (`fileserver.go:75`, `:201`), security + cache headers are set, and the bytes go out via `c.Blob` (`fileserver.go:205-209`).
