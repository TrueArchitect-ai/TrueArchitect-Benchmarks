**Premise correction:** Neither. This repo (usememos/memos) has no message broker at all — no NATS, no RabbitMQ, no Kafka, no Redis. `go.mod` contains no broker client dependency, and a grep for `nats|rabbit|amqp|kafka|redis` across the Go sources returns zero hits (the only match anywhere is an unrelated Catalan word in `web/src/locales/ca.json`). There are also no "webhook delivery workers" as a separate service/deployment — delivery happens inside the single `memos` server process.

**Actual mechanism — an in-process buffered Go channel:**

`internal/webhook/webhook.go`
- **Queue declaration:** `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, a package-level buffered channel with capacity 128. This is the closest thing to a "queue," and it's purely in-memory.
- **Workers:** `internal/webhook/webhook.go:42-55` — an `init()` function spawns exactly 4 goroutines, each ranging over `asyncPostQueue` and calling `Post(payload)`. Failures are only logged via `slog.Warn`; there is no retry and no dead-letter path.
- **Enqueue:** `PostAsync` at `internal/webhook/webhook.go:184-196` does a non-blocking `select` send. If the buffer is full, the payload is **dropped** with a warning ("Dropped webhook dispatch because the async queue is full") — so delivery is best-effort and does not survive process restart.
- **Delivery:** `Post` at `internal/webhook/webhook.go:120` does a plain `http.POST` through `safeClient` (`webhook.go:32-37`), a 30s-timeout client whose `DialContext` (`safeDialContext`, `webhook.go:59`) rejects reserved/private IPs to block SSRF/DNS-rebinding. Optional Standard Webhooks HMAC-SHA256 signing adds `webhook-id` / `webhook-timestamp` / `webhook-signature` headers (`webhook.go:133-150`).

**Producers:** `server/router/api/v1/memo_service_webhooks.go` — `DispatchMemoCreatedWebhook` / `Updated` / `Deleted` (via `dispatchMemoRelatedWebhook`, line 48) and `DispatchMemoCommentCreatedWebhook` (line 30). Each loads the user's endpoints with `s.Store.GetUserWebhooks(...)` and calls `webhook.PostAsync(payload)` per hook.

Webhook endpoints themselves are no longer a dedicated table — `store/migration/{sqlite,mysql,postgres}/0.25/00__remove_webhook.sql` dropped it (it was added in 0.18); they now live in user settings, read via `server/router/api/v1/user_service_webhooks.go`.
