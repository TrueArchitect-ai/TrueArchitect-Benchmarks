### How it works

**Delivery path.** Memo create/update/delete and comment-created events call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43,71`. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel (`asyncPostQueue`, line 39), dropping with a warning if full. Four goroutines started in `init()` (lines 42–55) drain the queue and call `Post`, which is where the actual `http.Client.Do` happens (line 152). `Post` marshals the payload, adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`) when a signing secret is configured, and caps the response read at 1 MiB.

**SSRF protection.** Two layers:

1. **Dial-time (the real guard).** `Post` uses the shared `safeClient` (`internal/webhook/webhook.go:32`) whose `Transport.DialContext` is `safeDialContext`. It splits the address, resolves the host itself via `net.DefaultResolver.LookupHost`, and refuses to dial if *any* resolved IP is reserved. Because the check happens at connection time rather than at save time, it also defeats DNS rebinding — the comment at lines 30–31 says so explicitly.
2. **Admission-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a user registers or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74,161,182`): requires an absolute URL, an `http`/`https` scheme, and no resolved reserved IP, returning gRPC `InvalidArgument`.

The blocklist (`internal/webhook/validate.go:14-23`) covers IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` (cloud IMDS), plus IPv6 `::1/128`, `fc00::/7`, and `fe80::/10`, parsed once into `reservedNetworks` at startup.

**Escape hatch.** `AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` and thus disables *both* layers. It's set from the `--allow-private-webhooks` flag in `cmd/memos/main.go:49` (default `false`, registered at line 133) for self-hosted setups targeting LAN services.

One gap worth noting: `safeDialContext` resolves the host and checks those IPs, then dials by hostname again via `net.JoinHostPort(host, port)` (line 76) rather than dialing the specific IP it validated — a second resolution the checks don't cover.
