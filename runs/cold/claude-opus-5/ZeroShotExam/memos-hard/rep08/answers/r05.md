**Premise correction:** This repository (Memos) has no GraphQL schema at all. A case-insensitive grep for `graphql` across the entire tree (excluding `node_modules`) returns zero hits, and there are no `.graphql`/`.gql` files. There is no GraphQL server, resolver layer, or schema definition anywhere.

**Actual API surface — Protobuf/gRPC, defined in `proto/api/v1/`:**

The public API is defined as Protocol Buffers service definitions:

- `proto/api/v1/memo_service.proto` — core memo CRUD, comments, relations
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto`

Internal storage-layer messages (not the public API) live separately in `proto/store/*.proto`.

**How it's exposed:**

Each RPC carries a `google.api.http` annotation that maps it onto a REST path — e.g. in `proto/api/v1/memo_service.proto:18-24`, `CreateMemo` maps to `POST /api/v1/memos`, and `ListMemos` to `GET /api/v1/memos`. So the REST API is generated from the same proto definitions rather than being hand-written.

**Code generation** is driven by `proto/buf.gen.yaml`, which runs buf plugins for:
- Go structs + gRPC + ConnectRPC + grpc-gateway → `proto/gen/`
- OpenAPI spec (gnostic) → `proto/gen/openapi.yaml`, embedded into the binary via `proto/openapi_embed.go`
- TypeScript clients → `web/src/types/proto`

**Server handlers** implementing these services are in `server/router/api/v1/` (e.g. `memo_service.go`, `auth_service.go`, with ConnectRPC wiring in `connect_services.go` and `connect_handler.go`).

So if you were looking for a schema to introspect or query: the equivalent artifacts here are the `.proto` files in `proto/api/v1/` and the generated `proto/gen/openapi.yaml`.
