## How it works

**Trigger → enqueue.** Memo create/update/delete/comment events call `webhook.PostAsync(payload)` from `server/router/api/v1/memo_service_webhooks.go` (`dispatchMemoRelatedWebhook`, `DispatchMemoCommentCreatedWebhook`). `PostAsync` (`internal/webhook/webhook.go:177`) drops the payload onto a buffered channel `asyncPostQueue` (cap 128), dropping with a warning if full.

**Actual delivery.** Four goroutines started in `init()` (`internal/webhook/webhook.go:44`) drain that queue and call `Post()` — that's where the outbound HTTP request actually executes. `Post` marshals the payload to JSON, POSTs it, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and sends it via the shared `safeClient` (`resp, err := safeClient.Do(req)`).

## SSRF protection — two layers

1. **Dial-time blocking (the real enforcement).** `safeClient` is configured with a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32`). `safeDialContext` (`internal/webhook/webhook.go:59`) splits the host/port, resolves the hostname itself, and refuses to dial if *any* returned IP is reserved. Because the check happens at dial time on the resolved address, it also defeats DNS rebinding — a hostname that passed validation at registration but later resolves to an internal IP still gets blocked.

2. **Registration-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates/updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`). It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument` — this is UX/early rejection, not the last line of defense.

Both layers share `isReservedIP` (`internal/webhook/validate.go:49`), which tests against `reservedNetworks` parsed from `reservedCIDRs` (`internal/webhook/validate.go:15`): IPv4 loopback, RFC-1918 private (10/8, 172.16/12, 192.168/16), link-local `169.254.0.0/16` (covers cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`.

**Escape hatch.** The package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling both layers. It's wired to the `--allow-private-webhooks` CLI flag / viper config in `cmd/memos/main.go:49` (flag declared at `:133`, bound at `:160`), defaulting to `false` — intended for self-hosters targeting LAN services.

**Gap worth noting:** the CIDR list omits `0.0.0.0/8` (`0.0.0.0` and `127.x` aliases like `0177.0.0.1` resolve fine, but plain `0.0.0.0` routes to localhost on Linux), IPv4-mapped IPv6 (`::ffff:127.0.0.1` parses as a 16-byte IP that `127.0.0.0/8` may not match depending on `net.IP` normalization), and carrier-grade NAT `100.64.0.0/10`. Also, `Post` follows redirects by default — though the custom dialer still runs on each redirect hop, so redirect-based SSRF is covered.
