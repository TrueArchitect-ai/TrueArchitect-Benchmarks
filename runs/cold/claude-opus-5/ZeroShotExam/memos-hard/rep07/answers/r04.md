**Premise correction:** Neither. This repo (Memos, a single-binary Go app) has no message broker at all — no NATS, no RabbitMQ/AMQP, no Kafka or Redis queue. `go.mod`/`go.sum` contain no broker client dependency, and `scripts/compose.yaml` defines no broker service. (The only repo-wide grep hits for "nats" are Catalan words like `eliminats` in `web/src/locales/ca.json`.)

**Actual mechanism:** webhook delivery is an in-process worker pool over a buffered Go channel, entirely inside `internal/webhook/webhook.go`.

- **"Queue" declaration** — `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  A package-level buffered channel with capacity 128. It is process-local: nothing is persisted, and it does not survive a restart.

- **Workers** — `internal/webhook/webhook.go:42-55`: a package `init()` starts exactly 4 goroutines, each ranging over `asyncPostQueue` and calling `Post(payload)`. Failures are logged with `slog.Warn` and dropped; there is no retry or dead-letter path.

- **Producer** — `PostAsync` (`internal/webhook/webhook.go:184-196`) does a non-blocking `select` send. If the buffer is full, the payload is **dropped** with a "Dropped webhook dispatch because the async queue is full" warning — at-most-once delivery, by design.

- **Callers** — `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, which fan out over the user's registered webhooks (`s.Store.GetUserWebhooks`, stored in user settings) for `memos.memo.created/updated/deleted` and `memos.memo.comment.created`.

- **Delivery itself** — `Post` (`internal/webhook/webhook.go:120`) does a plain `http.POST` of the JSON payload via a shared 30s-timeout client whose dialer blocks reserved/private IPs (`safeDialContext`, line 59), optionally signing with Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`).
