**Premise correction: this repository has no per-user API rate-limiting middleware.** There is nothing to cite as "registered," and therefore no request limits to report.

What I checked and found:

- **No rate-limit code anywhere.** A repo-wide search for `rate.?limit`, `throttl`, `limiter`, `429`/`TooManyRequests` across Go, TS, proto, and config files returns only three hits, all documentation prose in the email package: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse", a security-considerations bullet) and `internal/email/README.md:286-296` (a "### 5. Implement Rate Limiting" section showing a hypothetical `rate.NewLimiter` snippet). Neither is implemented — no code in the repo constructs a limiter.
- **No rate-limiting dependency.** `golang.org/x/time v0.15.0` appears in `go.mod:151` but is marked `// indirect` (pulled in transitively), and `rate.NewLimiter` is never called in first-party code. No `tollbooth`, `ulule/limiter`, or similar.

The actual middleware/interceptor chains, for reference:

- **Echo HTTP middleware** — `server/server.go:51-52`: only `middleware.Recover()` and `newCORSMiddleware(profile)`. The frontend adds a static-file handler and SPA fallback (`server/router/frontend/frontend.go:54,59`).
- **Connect/gRPC interceptors** — `server/router/api/v1/v1.go:133-137`, in order: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor`. All four are defined in `server/router/api/v1/connect_interceptors.go`; the auth one enforces authentication/anonymous-access policy, not any request quota.

The one request limit that does exist is a size limit, not a rate limit: `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`, which caps request body bytes per call.
