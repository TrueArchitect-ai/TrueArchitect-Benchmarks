**Premise correction:** There is no Redis in this repository. No `redis` string appears anywhere in the Go sources, and there is no Redis dependency in `go.mod`/`go.sum` (or `web/package.json`). There is no connection string, host/port setting, or env var for an external cache — nothing in `internal/profile` or `cmd` configures a cache at all. Memos ships as a single Go binary with SQLite/MySQL/Postgres; its cache layer is entirely in-process.

**Actual mechanism:**

The cache is a hand-rolled, thread-safe in-memory cache backed by `sync.Map`, defined in `store/cache/cache.go`:
- `Cache` struct (`store/cache/cache.go:67`) with an `Interface` at `store/cache/cache.go:11`.
- Each entry is an `item` holding the value, an absolute `expiration` time, and an approximate size (`store/cache/cache.go:35`).
- Expiry is lazy on read (`Get` deletes and misses if `time.Now().After(itm.expiration)`, `store/cache/cache.go:135`) plus a background `cleanupLoop` goroutine on a ticker (`store/cache/cache.go:200`), with a `MaxItems` overflow eviction path (`cleanupOldest`, `store/cache/cache.go:253`).

Configuration happens in the store constructor, not in any config file or env var — `store.New` in `store/store.go:38-58`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

Three separate cache instances are created from that same config (`store/store.go:51-53`): `instanceSettingCache`, `userCache`, and `userSettingCache`. `cache.DefaultConfig()` (`store/cache/cache.go:57`) duplicates the same values, but the store uses its own literal.

**TTL for user entries: 10 minutes.** `userCache` is only ever written via `Set` — `store/user.go:98, 122, 132, 143, 167` — and `Set` delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). Nothing outside the cache package calls `SetWithTTL`, so no per-entry override exists; user entries inherit the 10-minute default, keyed by user ID as a string (`userCacheKey`, `store/user.go:88`). Staleness is bounded further by explicit invalidation: writes refresh the entry, and `deleteUserCache` (`store/user_delete.go:39-47`) removes the user plus its settings entries on delete.

One consequence worth noting: because this cache is per-process with no shared backing store, a multi-replica deployment gives each replica its own copy, and a user updated on one replica can be served stale by another for up to 10 minutes.

Unrelated caches also exist and are not part of this layer: an instance-stats memo cache with a 60-second TTL (`server/router/api/v1/instance_stats.go:21`) and an RSS feed cache (`server/router/rss/rss.go:346`).
