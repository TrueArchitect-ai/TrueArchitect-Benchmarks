**No** — in production code the MySQL driver is only ever constructed through the factory. The one direct construction outside it is in a test, and it's an empty struct, not a real driver.

Evidence:

- **Factory:** `store/db/mysql.NewDB(profile)` is called exactly once, from the driver-selection switch in `store/db/db.go:22` (`NewDBDriver`, case `"mysql"`). That is the sole call site of `mysql.NewDB` anywhere.
- **Package import graph:** `store/db/db.go:8` is the only file in the repo that imports `github.com/usememos/memos/store/db/mysql`. No server, store, cmd, or test code imports the package directly, so nothing else *can* construct it from outside.
- **All entry points go through the factory:** `db.NewDBDriver` is the only path used by callers — `store/test/store.go:28,50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70`.
- **Internal construction:** the `DB` struct literal is built in `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`) inside `NewDB` itself.
- **The one exception, and it's a test:** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — an in-package unit test that constructs a zero-value `DB` purely to call the pure method `IsRetryableAuthenticationMutationError`. It has no `*sql.DB` and never connects. (The same pattern exists on the Postgres side: `store/db/postgres/auth_config_test.go:12`, `user_setting_test.go:36,194,257`.)
- **Not a counterexample:** `store/test/containers.go:101-105` uses `mysql.Run`/`mysql.WithDatabase` from `testcontainers-go`, i.e. spinning up a MySQL *container*, not constructing the memos MySQL driver.
