**Method:** the data layer is the Go package `github.com/usememos/memos/store` (`store/*.go`). Its persistent entity types are `Attachment`, `IdentityProvider`, `Inbox`, `InstanceSetting`, `Memo`, `MemoRelation`, `MemoShare`, `Reaction`, `User`, `UserIdentity`, `UserSetting`. I counted distinct Go packages outside the `store/` tree (so excluding `store/db/{sqlite,postgres,mysql}` and `store/test`, which are part of the layer itself) that textually reference each type.

**`store.User` — 7 packages**
- `server/auth` (`authenticator.go`, `context.go`)
- `server/notification` (`email.go`)
- `server/router/api/v1` (`user_service.go`, `auth_service_sso.go`, `memo_service_converter.go`, …)
- `server/router/api/v1/test` (`test_helper.go`)
- `server/router/fileserver` (`fileserver.go`)
- `server/router/frontend` (`frontend_test.go`)
- `server/router/rss` (`rss.go`)

**`store.Memo` — 6 packages**
- `server/notification` (`email.go`)
- `server/router/api/v1` (`memo_service.go`, `memo_update_helpers.go`, `sse_event_helpers.go`, …)
- `server/router/api/v1/test` (`memo_service_test.go`, …)
- `server/router/frontend` (`frontend_test.go`)
- `server/router/rss` (`rss.go`)
- `server/runner/memopayload` (`runner.go`)

Third place is `store.Attachment` at ~4 packages (`server/router/api/v1`, `.../api/v1/test`, `server/router/fileserver`, `server/router/rss`).

Two notes on the counting: `store.IdentityProvider`, `store.InstanceSetting`, and `store.UserSetting` appear to have hits in `proto/gen/store`, but those are proto descriptor strings (`memos.store.IdentityProvider`) in a package that never imports the store package — false positives, so those entity types have no consumers outside the layer under their `store.` name. If you instead count the whole `store/` tree, the ranking is unchanged: `User` 11 vs `Memo` 10.
