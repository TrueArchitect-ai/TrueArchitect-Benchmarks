**`*markdown.service` (the single unexported goldmark-backed impl) — constructed once in `NewAPIV1Service` (plus a test helper) — held by `APIV1Service`, `RSSService`, and `memopayload.Runner`.**

**The interface** — `markdown.Service` in `internal/markdown/markdown.go:31-56` (ExtractAll, ExtractTags, ExtractProperties, RenderMarkdown, RenderHTML, GenerateSnippet, ValidateContent, RenameTag).

**Concrete implementation** — exactly one: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:58-61`). There are no alternate impls, mocks, or fakes anywhere in the tree — tests use the real one. Internally it delegates markdown-to-markdown rendering to `renderer.NewMarkdownRenderer()` (`internal/markdown/renderer/markdown_renderer.go:19`), a concrete struct, not another impl of `Service`; HTML output goes through goldmark's own renderer via `s.md.Convert` (`markdown.go:255-261`).

**Construction** — `markdown.NewService(opts ...Option)` (`internal/markdown/markdown.go:85`) always returns `&service{}`; options only toggle which goldmark extenders are registered (GFM always, plus `extensions.TagExtension` / `extensions.MentionExtension`).

Runtime call sites:
- `server/router/api/v1/v1.go:48-51` — `NewAPIV1Service` builds the one production instance with **both** `WithTagExtension()` and `WithMentionExtension()`. This is the only production construction; `server/server.go:76` invokes it.
- `server/server.go:85` — no second construction; the RSS service is handed `apiV1Service.MarkdownService`, so RSS shares the same instance.

Test-only constructions: `server/router/api/v1/test/test_helper.go:44`, `server/router/rss/rss_test.go:54` (no extensions), `server/router/fileserver/fileserver_test.go:427` (tags only).

One caveat worth flagging: `memopayload.NewRunner` (`runner.go:19`) is never called anywhere in the repo — `server/server.go:162` only wires `s3presign.NewRunner`. So the `Runner` holder is dead at runtime; the memopayload path actually executes through the free function `RebuildMemoPayload(ctx, memo, markdownService)` (`runner.go:74`), which takes `markdown.Service` as a parameter rather than a field.

Separately, the frontend does its own markdown rendering with `markdown-it` (`web/src/components/MemoContent/MemoMarkdownRenderer.tsx` and friends) — that is a parallel, unrelated pipeline, not an implementation of the Go `Service` interface, as the interface's own doc comment notes.
