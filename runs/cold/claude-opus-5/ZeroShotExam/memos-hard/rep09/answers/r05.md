**Premise correction:** There is no GraphQL in this repository. Memos does not expose a GraphQL API — no `.graphql`/`.gql` schema files, no GraphQL server library in `go.mod`, and no GraphQL client in `web/`. A repo-wide case-insensitive search for "graphql" returns zero hits.

**Actual API surface: Protocol Buffers (`.proto`), served three ways from one definition.**

**Schema source of truth — `proto/api/v1/*.proto`:**
- `proto/api/v1/memo_service.proto` (656 lines)
- `proto/api/v1/user_service.proto` (880 lines)
- `proto/api/v1/instance_service.proto` (360 lines)
- `proto/api/v1/attachment_service.proto`, `auth_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto`

These follow the [Google AIP](https://google.aip.dev/) resource-oriented style (`proto/api/v1/README.md`), and REST routes are declared inline as `google.api.http` annotations — e.g. `proto/api/v1/memo_service.proto:23` maps `CreateMemo` to `POST /api/v1/memos`, and line 35 maps `GetMemo` to `GET /api/v1/{name=memos/*}`.

A separate, internal-only set lives in `proto/store/*.proto` — these are storage payload types (JSON/proto blobs persisted in DB columns), not part of the public API.

**Codegen — `proto/buf.gen.yaml`** runs `buf generate` (see `proto/README.md`) and emits:
- Go message/gRPC/Connect/grpc-gateway stubs → `proto/gen/api/v1/`
- An OpenAPI 3.0.3 spec → `proto/gen/openapi.yaml` (4057 lines, via gnostic) — this is the closest thing to a "schema document" for the HTTP API
- TypeScript client types → `web/src/types/proto/`

**Serving — `server/router/api/v1/v1.go`:**
1. **REST/JSON** via grpc-gateway: services registered onto `gwMux` at `server/router/api/v1/v1.go:96-122`, mounted at `/api/v1/*` and `/file/*` (line 130-131).
2. **Connect RPC** (browser clients, replacing grpc-web): `server/router/api/v1/connect_handler.go:31`, mounted at `/memos.api.v1.*` (`v1.go:143`).
3. **Native gRPC** via the generated `*_grpc.pb.go` service interfaces implemented in `server/router/api/v1/*.go`.

The generated OpenAPI spec is also embedded into the binary (`proto/openapi_embed.go:5`) and reused to drive the MCP endpoint (`server/router/mcp/service.go:76-82`).

This matches the README's own claim: "full REST and gRPC APIs for integration."
