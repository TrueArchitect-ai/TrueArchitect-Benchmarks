Return trip: the row's `avatar_url` (a `data:<mime>;base64,...` URI) comes back as `store.User.AvatarURL`, is decoded by `FileServerService.parseDataURI` (`server/router/fileserver/fileserver.go:737`), MIME-checked against `avatarAllowedTypes` (line 75), and written with `c.Blob` plus `setSecurityHeaders` (line 758).

Two things worth noting about "another user's": the avatar bytes live in the `user` table, not in attachment/S3/local file storage — so no `store/attachment.go` or `internal/storage` hop is involved. And the handler applies no per-user authorization: on a public instance (`InstanceURL` set, `Profile.AllowAnonymous()` true) any avatar is served anonymously; on a private instance any authenticated viewer can fetch any other user's avatar (`server/router/fileserver/fileserver.go:171-181`).
