**How I resolved it**

1. **Call path to the interface.** `APIV1Service.CreateMemo` (`server/router/api/v1/memo_service.go:70`) calls `s.Store.CreateMemo` (line 115). That is `(*Store).CreateMemo` (`store/memo.go:109`), which only validates the UID and delegates: `return s.driver.CreateMemo(ctx, create)` (`store/memo.go:113`). No caching or wrapping layer intervenes — `Store` caches only instance settings, users, and user settings (`store/store.go:26-29`), not memos.

2. **Where `s.driver` comes from.** `main.go` builds it once: `dbDriver, err := db.NewDBDriver(instanceProfile)` then `store.New(dbDriver, instanceProfile)` (`cmd/memos/main.go:57,64`). `NewDBDriver` is a plain switch on `profile.Driver` returning `sqlite.NewDB`, `mysql.NewDB`, or `postgres.NewDB`, with `default: errors.New("unknown db driver")` (`store/db/db.go:16-27`).

3. **What `profile.Driver` is by default.** `Profile.Driver` is read from `viper.GetString("driver")` (`cmd/memos/main.go:43`), and both the viper default and the flag default are `"sqlite"` (`cmd/memos/main.go:122` and `:130`). With no `--driver`/`MEMOS_DRIVER` set, the switch takes the `"sqlite"` branch. Corroborating: `Profile.Validate()` has a sqlite-specific branch that auto-derives the DSN as `<data>/memos_prod.db` when `Driver == "sqlite" && DSN == ""` (`internal/profile/profile.go:110-118`) — the only driver that works with zero database flags, since mysql/postgres would fail without a DSN.

So the concrete receiver is `*sqlite.DB` (`store/db/sqlite/sqlite.go:16`, opened via `sql.Open("sqlite", ...)` with the `modernc.org/sqlite` driver at `sqlite.go:53`), and its `CreateMemo` is what issues the INSERT. The MySQL and Postgres versions differ in ways that confirm they're not the one running: MySQL uses `?` placeholders with a separate `LastInsertId` + re-select (no `RETURNING`), while Postgres uses `$1`-style placeholders.
