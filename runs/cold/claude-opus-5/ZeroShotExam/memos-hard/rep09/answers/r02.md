**Premise correction:** there is no per-user API rate-limiting middleware in this repository. Nothing registers a rate limiter, and no rate-limiting dependency is vendored — `go.mod` contains no `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, or similar.

What actually exists on the request path:

- **Echo HTTP middleware** — `server/server.go:51-52` registers exactly two: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go`). No throttling.
- **Connect RPC interceptors** — `server/router/api/v1/v1.go:133-138` registers four, in order: `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, `NewAuthInterceptor()`. All are defined in `server/router/api/v1/connect_interceptors.go`; none counts or limits requests. `AuthInterceptor` (`connect_interceptors.go:205`) enforces authentication and anonymous-access policy per call, but it is not quota-based.
- No gRPC `UnaryInterceptor`/`ChainUnaryInterceptor` chain is registered anywhere.

The only per-request *limit* in the codebase is a **payload size** cap, not a request-rate cap: `maxAPIRequestBytes = 256 << 20` (256 MiB) at `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` to the `/api/v1/*` and `/file/*` gateway routes and the `/memos.api.v1.*` Connect routes, plus `connect.WithReadMaxBytes` (`server/router/api/v1/v1.go:126-144`).

The only mentions of "rate limit" in the repo are aspirational documentation for SMTP sending, not implemented code: `internal/email/README.md:286-296` ("### 5. Implement Rate Limiting", with an illustrative `rate.NewLimiter(rate.Every(time.Second), 10)` snippet) and `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse" under Security Considerations). Neither is wired into `internal/email`'s actual sending path.

If you were told a specific limit (e.g. "N requests/minute per user"), it may come from a reverse proxy or deployment config outside this repo — I found no such configuration here either.
