**delivery function — `internal/webhook/webhook.go:120` (`Post`); protection mechanism — `safeDialContext` / `isReservedIP` in `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

**Where delivery executes**

- `webhook.Post()` — `internal/webhook/webhook.go:120` — marshals the payload, builds the `POST`, optionally adds Standard-Webhooks HMAC headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and does the actual `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.
- Callers don't invoke it directly: `webhook.PostAsync()` (`internal/webhook/webhook.go:184`) enqueues onto a 128-slot buffered channel, drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each of which calls `Post`. Overflow is dropped with a warning.
- Trigger points are `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (memo created/updated/deleted and comment-created dispatch).

**What protects it from internal addresses**

Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against the CIDR list at `internal/webhook/validate.go:14-23` (IPv4 loopback, RFC-1918, 169.254.0.0/16 incl. cloud IMDS, plus `::1/128`, `fc00::/7`, `fe80::/10`):

1. **Dial-time** (the real enforcement): `safeClient`'s transport uses `safeDialContext` — `internal/webhook/webhook.go:59-77`. It resolves the host via `net.DefaultResolver.LookupHost` and refuses the connection if any resolved IP is reserved.
2. **Registration-time**: `webhook.ValidateURL` — `internal/webhook/validate.go:62` — enforces http/https scheme and rejects hostnames resolving to reserved IPs when a user saves a webhook, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

There's also an escape hatch, `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`), which short-circuits `isReservedIP` and disables both layers for self-hosted setups.

Two caveats worth flagging, since you asked what actually protects it:

- `AllowPrivateIPs` is declared but never assigned anywhere in the tree (grep for it hits only `validate.go`), so there is currently no config/flag that turns it on — it's dead as a user-facing option.
- The comment at `internal/webhook/webhook.go:30-31` claims the dial-time check "defeats DNS rebinding," but `safeDialContext` checks the resolved IPs and then dials by *hostname* again (`internal/webhook/webhook.go:76`), causing a second resolution. The connection is not pinned to the vetted IP, so the check-to-connect gap remains.
