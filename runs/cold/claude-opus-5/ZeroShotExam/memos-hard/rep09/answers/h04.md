**No** — outside `NewDBDriver`, `mysql.NewDB` is never called anywhere in the codebase.

Evidence:

- **The factory is the sole caller.** `store/db/db.go:22` (`driver, err = mysql.NewDB(profile)`) inside `NewDBDriver`. A repo-wide grep for `mysql.NewDB` / imports of `github.com/usememos/memos/store/db/mysql` returns exactly two hits, both in that file: the import at `store/db/db.go:8` and the call at line 22. No other package imports `store/db/mysql` at all.

- **Everything else goes through the factory.** The only driver-construction sites elsewhere are `db.NewDBDriver(...)` calls: `cmd/memos/main.go:57`, `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70`. (By contrast, `sqlite.NewDB` *is* called directly in tests — `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416` — so the pattern isn't universal, it's specific to MySQL.)

- **One in-package nuance, not a real construction:** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — a zero-value struct literal in a same-package unit test for `IsRetryableAuthenticationMutationError`. It bypasses `NewDB`, but opens no connection and parses no DSN (`d.db` and `d.config` are nil), so it isn't a constructed driver. The only other `DB{...}` literal is inside `NewDB` itself (`store/db/mysql/mysql.go:29`).
