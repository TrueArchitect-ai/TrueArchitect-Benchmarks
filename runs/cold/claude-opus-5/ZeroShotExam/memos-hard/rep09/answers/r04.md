**Premise correction:** Neither. This repo (Memos, a Go note-taking server) has no external message broker at all — no NATS, no RabbitMQ/AMQP. A repo-wide grep for `rabbitmq|amqp|nats` returns only one hit, `web/src/locales/ca.json`, which is a Catalan-language false positive (the substring "nats" inside ordinary words). `go.mod` lists no broker client library.

**Actual mechanism:** Webhook delivery is handled entirely in-process by a buffered Go channel plus a fixed pool of goroutines.

- **The "queue" is declared** at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  A package-level buffered channel with capacity 128.

- **The "workers"** are 4 goroutines started in the package `init()` at `internal/webhook/webhook.go:42-55`, each ranging over `asyncPostQueue` and calling `Post(payload)`, logging a warning on failure.

- **Enqueue** happens in `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send. If the buffer is full, the payload is **dropped** with a warning — there is no persistence, no retry, and no redelivery, which is the main functional difference from a real broker.

- **Producers** are the API layer: `server/router/api/v1/memo_service_webhooks.go:43` and `:71` call `webhook.PostAsync(payload)` for the `memos.memo.created/updated/deleted` and `memos.memo.comment.created` activity types, after looking up the user's registered webhooks via `s.Store.GetUserWebhooks`.

- **Delivery itself** is a plain HTTP POST in `Post()` (`internal/webhook/webhook.go:120`), using a shared `safeClient` with a 30s timeout and an SSRF-guarding `DialContext` (`internal/webhook/webhook.go:59`), optionally signed per the Standard Webhooks spec (`webhook-id` / `webhook-timestamp` / `webhook-signature` headers).

Since state dies with the process, queued-but-undelivered webhooks are lost on restart.
