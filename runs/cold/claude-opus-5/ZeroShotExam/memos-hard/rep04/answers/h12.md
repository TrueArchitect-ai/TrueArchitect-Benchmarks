### How I determined which candidate runs

There are three implementations of `Driver.CreateMemo`, each with its own INSERT:
- `store/db/sqlite/memo.go:41` (backtick-quoted, `RETURNING`)
- `store/db/mysql/memo.go:41` (backtick-quoted, no `RETURNING` — uses `LastInsertId`)
- `store/db/postgres/memo.go:38` (unquoted, `$n` placeholders via `placeholders()`)

Selection is purely runtime, by `profile.Driver`:

1. `store/db/db.go` — `NewDBDriver` switches on `profile.Driver` over `"sqlite" | "mysql" | "postgres"`, erroring on anything else.
2. `cmd/memos/main.go:122` sets `viper.SetDefault("driver", "sqlite")` and `main.go:130` declares the flag with default `"sqlite"`; `main.go:43` reads `viper.GetString("driver")` into the profile. So with no `--driver` flag and no `MEMOS_DRIVER` env/config override, the value is `sqlite`.
3. Corroborating: `internal/profile/profile.go:110` special-cases `p.Driver == "sqlite" && p.DSN == ""` to synthesize `<data>/memos_prod.db` — i.e. sqlite is the only driver that works with zero additional flags, since mysql/postgres would require a `--dsn`.

Note this covers memo *creation*. Editing an existing memo takes `(*Store).UpdateMemo` → `(*sqlite.DB).UpdateMemo` in the same file, which issues an `UPDATE`, not an `INSERT`.
