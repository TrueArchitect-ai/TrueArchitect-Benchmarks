h15.

Memo visibility is **not** funneled through one shared authorizer — the rule (`PUBLIC` → anyone; `PROTECTED` → any authenticated user; `PRIVATE` → creator, plus admin/super-user on most paths) is re-implemented at each surface below.

**Core Connect/gRPC API (single-memo reads)**
- `checkMemoReadAccess` (archived + visibility gate; used by `GetMemo` :356, its parent memo :367, and `ListMemoComments`) — server/router/api/v1/memo_service.go:39-66
- `ListMemos` query scoping (`VisibilityList` for anonymous, CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` for authed) — server/router/api/v1/memo_service.go:217-227
- `ListMemoComments` parent gate + child-memo filter — server/router/api/v1/memo_service_comments.go:148-161
- `CreateMemoComment` parent-memo gate — server/router/api/v1/memo_service_comments.go:33-43
- `ListMemoReactions` / `UpsertMemoReaction` — server/router/api/v1/reaction_service.go:29-41 and :82-85
- `ListMemoAttachments` — server/router/api/v1/memo_attachment_service.go:213-226
- `checkAttachmentAccess` (attachment inherits its memo's visibility; used by `GetAttachment`) — server/router/api/v1/attachment_service.go:422-455
- `GetUserStats` / `ListAllUserStats` memo-find scoping — server/router/api/v1/user_service_stats.go:83-92 and :217-221
- `GetMemoByShare` — the deliberate bypass: share token + expiry + non-archived replace the visibility check — server/router/api/v1/memo_share_service.go:153-192 (helper `getActiveMemoShare` :199)

**HTTP file server (raw attachment/blob serving, separate from the API)**
- `checkAttachmentPermission` (anonymous-public, `share_token` fallback, then private/creator/admin) — server/router/fileserver/fileserver.go:650-703

**RSS feeds**
- Explore feed and per-user feed, both hard-pinned to `store.Public` — server/router/rss/rss.go:90 and :141

**Frontend SSR**
- `getSitemapXML`, public-only memo listing — server/router/frontend/frontend.go:149-151

**SSE broadcast fan-out**
- `SSEClient.canReceive` (per-connection filter on event visibility/creator/admin), fed by the visibility stamped on events in server/router/api/v1/sse_event_helpers.go:29-37 — server/router/api/v1/sse_hub.go:133-143

**Notification / mention fan-out (who may see memo content in an inbox or email)**
- `canViewerAccessMemo` — server/router/api/v1/user_service_notifications.go:302-315
- `canViewerAccessMemo` (duplicated for email, uses `RoleAdmin` instead of `isSuperUser`) — server/notification/email.go:306-319
- `canUserAccessMentionContext` / `shouldSkipMentionInbox` — server/router/api/v1/memo_mention_helpers.go:55-90

Underneath all of these, `VisibilityList`/filter translation to SQL happens in store/memo.go:69 and store/db/{sqlite,postgres,mysql}/memo.go — that's the mechanism, not an enforcement decision; the store applies whatever scoping the caller supplied.

Note the MCP router (server/router/mcp/) adds no check of its own — it forwards the caller's `Authorization` header to the v1 API (server/router/mcp/service.go:99-103), so it inherits the API's gates.
