### The interface
`markdown.Service` — `internal/markdown/markdown.go:31-56` — declares `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

### Implementation
Exactly one implementation exists in the repo: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:58-60`). There are no mocks or alternate implementations — `grep` for `func (…) ExtractAll(` yields only `markdown.go:356`. The factory `NewService(opts ...Option) Service` (`internal/markdown/markdown.go:85`) always returns `&service{}`; options only vary which goldmark extenders are registered (`extension.GFM` always, plus `extensions.TagExtension` / `extensions.MentionExtension`).

### Construction
- **Production:** `apiv1.NewAPIV1Service` (`server/router/api/v1/v1.go:47-52`) is the sole runtime construction site, calling `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())`. It is reached from `server.go:76`, and the same instance is then handed to RSS at `server/server.go:85`: `rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)` — so one shared instance serves both.
- **Tests:** `server/router/api/v1/test/test_helper.go:44` (tags + mentions), `server/router/fileserver/fileserver_test.go:427` (tags only), `server/router/rss/rss_test.go:54` (no extensions).
