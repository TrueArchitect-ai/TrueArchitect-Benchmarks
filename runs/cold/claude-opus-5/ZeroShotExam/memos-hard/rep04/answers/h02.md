**delivery function — `internal/webhook/webhook.go` (`Post`, line 120; async wrapper `PostAsync`, line 184); protection mechanism — `internal/webhook/webhook.go` (`safeDialContext`, line 59, wired into `safeClient`'s `http.Transport`, lines 32–37) backed by the reserved-CIDR check in `internal/webhook/validate.go` (`isReservedIP` / `reservedCIDRs`, lines 14–54)**

Details:

**Where delivery executes**
- `webhook.Post` (`internal/webhook/webhook.go:120`) marshals the payload, builds the POST, optionally adds Standard-Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and calls `safeClient.Do`.
- Callers don't call `Post` directly — `PostAsync` (`:184`) enqueues onto a bounded 128-slot channel drained by 4 goroutines started in `init()` (`:42-55`), which is where `Post` actually runs. Dispatch is triggered from `server/router/api/v1/memo_service_webhooks.go:43,71` for `memos.memo.created/updated/deleted` and `memos.memo.comment.created`.

**What protects it**

Two layers:

1. **Dial-time enforcement (the real defense).** The shared `safeClient` (`internal/webhook/webhook.go:32`) installs `safeDialContext` (`:59`) as its transport's `DialContext`. It resolves the host and rejects the connection if *any* returned IP is reserved. Because the check happens at dial time on the same resolution path as the connection, it also defeats DNS rebinding — a hostname that passed validation at save time but later resolves to `127.0.0.1` still fails here.
2. **Save-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-IP resolutions when a user creates/updates a webhook, called from `server/router/api/v1/user_service_webhooks.go:74,161,182`. This is UX-level rejection, not the security boundary.

Both share `isReservedIP` (`internal/webhook/validate.go:44`) against `reservedCIDRs` (`:14`): IPv4 loopback, RFC-1918 ranges, link-local `169.254.0.0/16` (cloud IMDS), plus `::1/128`, `fc00::/7`, `fe80::/10`.

**Escape hatch:** the global `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers. It's set from the `--allow-private-webhooks` flag (default `false`) in `cmd/memos/main.go:49,133,160` for self-hosted deployments targeting LAN services.

Two gaps worth noting: `safeDialContext` resolves the host and then re-dials by hostname (`:76`), so the resolver is consulted twice — a narrow TOCTOU window remains, unlike dialing the already-validated IP. And the CIDR list omits `0.0.0.0/8`, IPv4-mapped IPv6 (`::ffff:127.0.0.1`), and carrier-grade NAT `100.64.0.0/10`.
