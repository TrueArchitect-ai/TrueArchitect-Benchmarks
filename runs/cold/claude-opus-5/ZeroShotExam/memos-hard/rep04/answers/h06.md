**Convergence function — `webhook.Post`, `internal/webhook/webhook.go:120`**

The chain: each handler calls a `Dispatch*Webhook` wrapper in `server/router/api/v1/memo_service_webhooks.go`, which loads the memo creator's rows via `s.Store.GetUserWebhooks(...)`, copies `hook.Url` / `hook.SigningSecret` into a `WebhookRequestPayload`, and calls `webhook.PostAsync` (`memo_service_webhooks.go:43` and `:71`). `PostAsync` only enqueues onto `asyncPostQueue`; the four worker goroutines started in `internal/webhook/webhook.go:47-58` are what call `Post`. `Post` is the sole place `safeClient.Do(req)` is invoked (`webhook.go:152`) — it builds the POST, JSON-marshals the payload, and adds the Standard Webhooks `webhook-id`/`webhook-timestamp`/`webhook-signature` HMAC headers when a signing secret is set.

The URLs themselves are configured through `CreateUserWebhook` / `UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53`, `:106`), which gate them with `webhook.ValidateURL` (`internal/webhook/validate.go`); the SSRF guard is re-applied at dial time by `safeDialContext` (`internal/webhook/webhook.go:62`) on the shared `safeClient`, so DNS rebinding between validation and delivery is also blocked — unless `webhook.AllowPrivateIPs` is set.

Note: `GetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go`, via `internal/httpgetter`) also makes outbound HTTP to a user-supplied URL, but that URL is a per-request argument rather than stored configuration, and it does not route through `webhook.Post`.
