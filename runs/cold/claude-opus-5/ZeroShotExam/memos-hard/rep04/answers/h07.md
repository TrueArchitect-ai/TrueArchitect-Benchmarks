The browser never fetches a raw avatar blob from the user API — `convertUserFromStore` rewrites any base64 avatar into the URL `/file/users/{username}/avatar`, and the `<img>` in `UserAvatar` requests that path.

getUserByUsername — server/router/fileserver/fileserver.go:715

DB.ListUsers (`SELECT ... avatar_url ... FROM user WHERE username = ?`) — store/db/sqlite/user.go:88 (siblings: store/db/postgres/user.go, store/db/mysql/user.go)

Back in the handler, the stored `user.AvatarURL` is a data URI held in the `user.avatar_url` column: `parseDataURI` (server/router/fileserver/fileserver.go:737) base64-decodes it, the MIME type is checked against `avatarAllowedTypes` (line 75), and the bytes are written with `c.Blob` (line 209). No filesystem or S3 hop is involved for avatars — unlike attachments, the image lives entirely in the user row.
