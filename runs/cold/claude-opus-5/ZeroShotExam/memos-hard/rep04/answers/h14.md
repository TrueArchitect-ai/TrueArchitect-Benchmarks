**Computation site**

- `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74` — is the single entry point. It ensures `memo.Payload` exists, then delegates to the markdown service.
- The actual extraction is `(*service).ExtractAll` in `internal/markdown/markdown.go:356` (goldmark AST walk, single pass). `RebuildMemoPayload` assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`runner.go:85-86`).
- There is an equivalent standalone `ExtractProperties` (`internal/markdown/markdown.go:193`) declared on the `Service` interface (`markdown.go:39`), but the write path uses `ExtractAll` for efficiency.

**Triggers (recomputation)**

- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before the store write.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `path == "content"` branch of the update mask; the result is written via `update.Payload = memo.Payload`. Other mask paths (visibility, pinned, state, …) don't recompute.
- Batch backfill: `(*Runner).RunOnce` — `server/runner/memopayload/runner.go:27` — pages all memos 100 at a time, rebuilds each payload and persists via `store.UpdateMemo`. Note this runner is not currently wired up in `server/server.go` (only `s3presign.NewRunner` is constructed there), so it's a dormant/migration path.

**Extracted properties**

From `ExtractAll` (`markdown.go:362-408`):

- `Property.Title` — text of the first block-level child of the document if it is an H1 heading (`markdown.go:384-388`, via `extractHeadingText`).
- `Property.HasLink` — any `gast.KindLink` node.
- `Property.HasCode` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- `Property.HasTaskList` — any `east.KindTaskCheckBox`.
- `Property.HasIncompleteTasks` — a task checkbox with `IsChecked == false`.
- Alongside the property struct, the same pass collects `Tags` (and `Mentions`), deduplicated case-preserving (`markdown.go:417-419`); tags land in `Payload.Tags`.

These are surfaced to clients as output-only `Memo.Property` (`proto/api/v1/memo_service.proto:256,272-278`) via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315`), are used for filtering (`store.FindMemoPayload`, `store/memo.go:84-91`) and for user stats counters (`server/router/api/v1/user_service_stats.go:141-152`).

One clarification, in case you meant the list-preview text specifically: `Memo.snippet` is a *different* derived field — it is not stored in the payload, but computed per-response in `getMemoContentSnippet` at convert time (`server/router/api/v1/memo_service_converter.go:76-80`, `:225`, `:248`).
