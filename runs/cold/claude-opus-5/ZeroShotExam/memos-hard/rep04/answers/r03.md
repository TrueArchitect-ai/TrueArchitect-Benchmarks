**Premise correction: there is no nightly database-cleanup job registered in this repository.**

The repo does contain a cron scheduler package (`internal/scheduler/` — `scheduler.go`, `job.go`, `parser.go`, `middleware.go`), but it is never imported by any application code. Grepping for `internal/scheduler` outside the package itself returns hits only in its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`); nothing in `server/`, `cmd/`, or `store/` calls `scheduler.New()` or `Register(...)`. So no job of any kind — cleanup or otherwise — is actually scheduled at runtime.

What likely prompted the question is the `0 2 * * *` (2:00 AM daily) cleanup schedule that appears repeatedly, but only as **documentation and test fixtures**:

- `internal/scheduler/README.md:34-35` — quick-start snippet, `Name: "daily-cleanup", Schedule: "0 2 * * *", // 2 AM daily`
- `internal/scheduler/doc.go:15-16` — the same snippet in the package doc comment
- `internal/scheduler/example_test.go:98-101` — `Example_multipleJobs`, "Cleanup old data every night at 2 AM"
- `internal/scheduler/parser_test.go:82` — `0 2 * * *` as a parser test case
- `internal/scheduler/README.md:268` — notably advises *against* that exact expression ("2:00 AM (often overloaded)"), recommending staggering to `5 2 * * *`

The only real periodic work in the running server uses plain tickers, not cron: `server/runner/s3presign/runner.go:30` (S3 presign refresh) and `store/cache/cache.go:201` (in-memory cache expiry, 5-minute `CleanupInterval` per `store/store.go:42`) — neither is a nightly database cleanup.
