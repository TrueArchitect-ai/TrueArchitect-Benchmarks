Memo visibility is not centralized — it is re-implemented independently in each surface that can expose memo content. Every distinct enforcement site:

**Core gRPC/Connect API (`server/router/api/v1/`)**

`checkMemoReadAccess` — single-memo read gate (archived → creator only; non-public → auth required; private → creator only). Called by `GetMemo` (also on the parent memo) and `ListMemoComments` — `server/router/api/v1/memo_service.go:39` (callers at `:356`, `:367`, `memo_service_comments.go:148`)
`ListMemos` query-level visibility filter — anonymous → `VisibilityList=[PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` — `server/router/api/v1/memo_service.go:218-227`
`ListMemoComments` child-memo filter (separate from the parent gate above) — `server/router/api/v1/memo_service_comments.go:155-161`
`CreateMemoComment` gate — cannot comment on a private memo you don't own — `server/router/api/v1/memo_service_comments.go:41`
`ListMemoRelations` relation filter (`MemoFilter`) — `server/router/api/v1/memo_relation_service.go:107-112`
`batchConvertMemoRelations` — same filter, batch path used when converting memos for list responses — `server/router/api/v1/memo_service_converter.go:183-187`
`ListMemoAttachments` — inline visibility check before listing a memo's attachments — `server/router/api/v1/memo_attachment_service.go:213-224`
`checkAttachmentAccess` — attachment read via the API, derived from the linked memo's visibility — `server/router/api/v1/attachment_service.go:422-453`
Reaction service — `UpsertMemoReaction` / `DeleteMemoReaction` / list re-check visibility of the target memo — `server/router/api/v1/reaction_service.go:30-40`, `:83`
`ListAllUserStats` / user stats — visibility-scoped memo aggregation — `server/router/api/v1/user_service_stats.go:84-90`, `:218-220`
`SSEClient.canReceive` — server-side delivery filter so private memo events only reach creator/admin — `server/router/api/v1/sse_hub.go:134-143` (event visibility populated at `sse_event_helpers.go:29-37`)
`GetMemoByShare` — the deliberate bypass: an unexpired share token grants read regardless of visibility (only archived/missing are rejected) — `server/router/api/v1/memo_share_service.go:153-190`

**Non-gRPC HTTP surfaces**

`FileServerService.checkAttachmentPermission` — raw attachment/blob serving; own implementation including an anonymous-access gate and a `share_token` query-param fallback — `server/router/fileserver/fileserver.go:650-703`
RSS feeds (explore + per-user) — hard-restricted to `VisibilityList=[PUBLIC]` — `server/router/rss/rss.go:90`, `:141`
Sitemap XML — public memos only — `server/router/frontend/frontend.go:149-151`

**Notification/mention paths (visibility gating what content reaches a user)**

`canViewerAccessMemo` — gates memo content in user notifications/inbox — `server/router/api/v1/user_service_notifications.go:302-317`
`canViewerAccessMemo` — a separate duplicate in the email dispatcher — `server/notification/email.go:306-320`
`canUserAccessMentionContext` / `shouldSkipMentionInbox` — mention notifications suppressed when the target can't see the memo or its parent — `server/router/api/v1/memo_mention_helpers.go:56-88`

Not a distinct site: the MCP router proxies tool calls back through the same Echo server into the v1 API (`server/router/mcp/adapter.go:27-42`), so it inherits the checks above rather than adding its own.
