**Premise correction: there is no per-user API rate-limiting middleware in this repository.** No such middleware/interceptor is registered anywhere, so there are no request limits to report.

**What I checked**

The full server-side middleware/interceptor chain is short and fully enumerable:

- Echo-level middleware — `server/server.go:51-52`: only `middleware.Recover()` and `newCORSMiddleware(profile)`.
- Connect RPC interceptors — `server/router/api/v1/v1.go:133-138`: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor`. All four are defined in `server/router/api/v1/connect_interceptors.go`; none tracks request counts or per-user state.

There is also no rate-limiting dependency in `go.mod` (no `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`), and nothing in the codebase returns HTTP 429.

**Related-but-different limits that exist** (none is per-user, and none is a rate limit — they're per-request or process-global):

- **Request body size cap**: `maxAPIRequestBytes = 256 << 20` (256 MiB) at `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` to the gateway and Connect routes (`v1.go:136`, `:141`, `:144`).
- **Global concurrency semaphores** (process-wide, shared across all users — a cap on simultaneous work, not on requests per time window): `thumbnailSemaphore` = 3 and `imageProcessingSemaphore` = 2, at `server/router/api/v1/v1.go:59-60`. Exceeding the image one returns `ResourceExhausted` "too many image processing requests" (`server/router/api/v1/attachment_service.go:160`). A separate `maxConcurrentThumbnails = 3` semaphore exists in `server/router/fileserver/fileserver.go:45-46`.
- **Per-request batch size caps**: 100 for attachment batch-delete (`attachment_service.go:35`), instance settings (`instance_service.go:22`), and users (`user_service.go:23`); 10 for link metadata (`memo_service.go:26`).

**One likely source of the premise**: `internal/email/README.md:286-296` has a section titled "Implement Rate Limiting" showing a `rate.NewLimiter(rate.Every(time.Second), 10)` example ("10 emails per second"). This is aspirational guidance in prose, not wired into any code path — `golang.org/x/time/rate` is not imported anywhere. Similarly, `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a future consideration. Note that even as written, these concern outbound email, not per-user API requests.
