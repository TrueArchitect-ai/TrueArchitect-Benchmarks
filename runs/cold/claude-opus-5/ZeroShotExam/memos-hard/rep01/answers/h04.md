**No** — in non-test code the MySQL driver is only ever constructed through the factory. The one exception is a single in-package unit test that builds a zero-value struct.

Evidence:

- **The factory is the sole constructor call site.** `store/db/db.go:22` calls `mysql.NewDB(profile)` inside `NewDBDriver`, alongside the sqlite/postgres cases.
- **No other package imports the driver package.** A repo-wide grep for `store/db/mysql` (and for `mysql.New*`) returns exactly two hits, both in `store/db/db.go` — the import at line 8 and the call at line 22. Nothing in `cmd/`, `server/`, or `store/` reaches the package directly.
- **All other entry points go through the factory.** `store/test/store.go:28,50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70` call `db.NewDBDriver(...)`, not the driver constructor. `store/test/containers.go` touches MySQL only via the testcontainers module and `go-sql-driver/mysql` DSN parsing (lines 101–105, 362–368) — it spins up a server and builds a DSN, it doesn't build the store driver.
- **The one direct struct construction is a test.** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — legal because the test is in `package mysql`. It's a zero-value struct used only to invoke the pure helper `IsRetryableAuthenticationMutationError` on MySQL error codes; no connection, config, or profile is involved.
- The only other `DB{...}` literal in the package is `store/db/mysql/mysql.go:29`, inside `NewDB` itself.
