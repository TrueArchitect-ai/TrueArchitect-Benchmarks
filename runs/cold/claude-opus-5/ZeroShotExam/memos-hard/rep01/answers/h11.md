**1st: `store.User` (~7 packages outside the store layer); 2nd: `store.Memo` (~6 packages)**

**Data layer** = the `store` package (`/bench/repo/store/`), which defines the persistent entity types: `Memo` (`store/memo.go:35`), `User` (`store/user.go:29`), `Attachment` (`store/attachment.go:16`), `Inbox` (`store/inbox.go:24`), `MemoRelation` (`store/memo_relation.go:16`), `MemoShare` (`store/memo_share.go:6`), `Reaction` (`store/reaction.go:7`), `UserIdentity` (`store/user_identity.go:8`), `UserSetting` (`store/user_setting.go:13`), `IdentityProvider` (`store/idp.go:12`), `InstanceSetting` (`store/instance_setting.go:14`).

Counting distinct Go packages outside the `store/` tree (i.e. excluding `store/db/{sqlite,mysql,postgres}` and `store/test`, which are part of the data layer itself):

| Type | Packages | Where |

| `User` | **7** (~30 files) | `server/auth/`, `server/notification/`, `server/router/api/v1/`, `server/router/api/v1/test/`, `server/router/fileserver/`, `server/router/frontend/`, `server/router/rss/` |
| `Memo` | **6** (~21 files) | `server/notification/`, `server/router/api/v1/`, `server/router/api/v1/test/`, `server/router/frontend/`, `server/router/rss/`, `server/runner/memopayload/` |

The tiebreaker between the top two is `server/auth/` — `store.User` is the only entity referenced by the auth layer (`server/auth/authenticator.go`, `server/auth/context.go`), whereas `store.Memo`'s extra package is the payload runner (`server/runner/memopayload/runner.go`). Both are used in the API, RSS, notification, and frontend-test packages.

The ranking is stable under a stricter reading too: if you count the driver sub-packages as "outside," it's `User` 11 vs `Memo` 10; by file count it's 36 vs 31 repo-wide.
