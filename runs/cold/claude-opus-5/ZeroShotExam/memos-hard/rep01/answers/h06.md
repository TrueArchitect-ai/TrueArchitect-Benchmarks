**Convergence function — `webhook.Post`, `internal/webhook/webhook.go:120`**

Every path above funnels through `dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48` and `:30`), which loads the user's configured endpoints via `s.Store.GetUserWebhooks` and calls `webhook.PostAsync` (`internal/webhook/webhook.go:184`). `PostAsync` only enqueues onto `asyncPostQueue`; the four worker goroutines started in `init()` (`:42-55`) drain it into `Post`, which builds the `POST`, adds the Standard-Webhooks HMAC headers, and issues the actual request via `safeClient.Do` at `:152`.

So `PostAsync` is the enqueue funnel and `Post` is the single function where delivery happens.

Notes:
- The URL is user-configured through `CreateUserWebhook` / `UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`, validated by `webhook.ValidateURL` (`internal/webhook/validate.go`). SSRF is guarded twice: at config time by `ValidateURL`, and at dial time by `safeDialContext` (`internal/webhook/webhook.go:59`), which re-resolves the host to defeat DNS rebinding. Both are bypassable by the operator flag `webhook.AllowPrivateIPs`.
- Two other outbound-HTTP paths exist but do **not** converge here: `GetLinkMetadata` → `fetchHTMLMeta`/`httpgetter.GetHTMLMeta` (`server/router/api/v1/memo_service_link_metadata.go:46`), where the URL is per-request rather than configured, and the OAuth2 IdP `UserInfoUrl` fetch (`internal/idp/oauth2/oauth2.go:85`).
