**`*markdown.service` (the only implementation) — constructed once in `NewAPIV1Service` — held by `APIV1Service`, `RSSService`, and `memopayload.Runner`/`RebuildMemoPayload`.**

### The interface
`markdown.Service` — `internal/markdown/markdown.go:31-56` — declares `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

### Concrete implementation
Exactly one type satisfies it: the unexported `service` struct (`internal/markdown/markdown.go:59-61`), wrapping a `goldmark.Markdown`. There are no mocks, fakes, or alternate implementations anywhere in the repo — tests use the real one. (`renderer.MarkdownRenderer` at `internal/markdown/renderer/markdown_renderer.go:15` is a concrete helper the service instantiates inside `RenderMarkdown`/`RenameTag`, not a second `Service` impl.)

### Construction
- **Runtime (single instance):** `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())` in `NewAPIV1Service` — `server/router/api/v1/v1.go:48-51`. This is the only production call site; it's reached from `server/server.go:76`. Both custom extensions are enabled here, so `#tag` and `@mention` parsing are live in the server.
- **Tests only:** `server/router/api/v1/test/test_helper.go:44` (tags + mentions), `server/router/rss/rss_test.go:54` (no options), `server/router/fileserver/fileserver_test.go:427` (tags only).

`NewService` (`internal/markdown/markdown.go:81`) builds goldmark with GFM plus the optional `extensions.TagExtension` / `extensions.MentionExtension` and `parser.WithAutoHeadingID()`.

### Holders of the interface
1. `APIV1Service.MarkdownService` — `server/router/api/v1/v1.go:35`. Used for mention extraction (`memo_mention_helpers.go:32`), webhook snippets (`memo_service_webhooks.go:85`), and payload rebuilds on create/update (`memo_service.go:108`, `memo_service.go:447`).
2. `RSSService.MarkdownService` — `server/router/rss/rss.go:45`, injected via `NewRSSService` at `server/server.go:85`, which deliberately passes `apiV1Service.MarkdownService` so the RSS feed shares the same instance. Used for `RenderHTML` at `rss.go:339` — this is the one server-side HTML rendering path (frontend rendering is `react-markdown`, see `web/src/components/MemoContent/MemoMarkdownRenderer.tsx`).
3. `memopayload.Runner.MarkdownService` — `server/runner/memopayload/runner.go:16`, plus the package-level `RebuildMemoPayload(ctx, memo, markdownService)` at `runner.go:74`, which calls `ExtractAll`.

One caveat worth flagging: `memopayload.NewRunner` (`runner.go:19`) has **no call sites** — nothing in `cmd/` or `server/` constructs the `Runner`, so `RunOnce`'s batch backfill never executes at runtime. Only the free function `RebuildMemoPayload` is live, called from the API service with `APIV1Service.MarkdownService`. So at runtime there is effectively one `*service` value shared by two holders.
