**Premise correction: there is no nightly database-cleanup job in this repository's cron scheduler.** No cleanup job is scheduled at any time, because nothing is scheduled at all.

What actually exists:

- `internal/scheduler/` is a **standalone, unused library** — a "GitHub Actions-inspired cron job scheduler" (`internal/scheduler/doc.go:1`) with cron parsing (`parser.go`), job registration (`job.go`, `scheduler.go`), and middleware (`middleware.go`). It has zero external importers: `grep` for `internal/scheduler` across all Go files returns only its own `example_test.go:10` and `integration_test.go:13`. No server or `cmd` code ever calls `scheduler.New()` or `Register()`.
- The `"daily-cleanup"` / `"0 2 * * *"` (2 AM) strings that look like a real job are **documentation and test fixtures only** — `internal/scheduler/doc.go:15-16`, `internal/scheduler/README.md:34-35`, and `internal/scheduler/example_test.go:97-100`. The README also shows an unrelated `"stale-session-cleanup"` at `"0 3 * * *"` as a naming-convention example (`README.md:241-245`), which is itself illustrative.

The closest thing to real background work in this codebase is not cron-scheduled and not database cleanup:

- `server/runner/s3presign/runner.go:26-30` — a `time.Ticker` re-signing S3 URLs every 12 hours.
- `store/cache/cache.go:199-218` — an in-memory cache eviction goroutine on a 5-minute `CleanupInterval` (`store/store.go:42`).

So if you're looking for a scheduled DB cleanup to modify or audit, it would have to be written first; the scheduler package is available but not wired into the server.
