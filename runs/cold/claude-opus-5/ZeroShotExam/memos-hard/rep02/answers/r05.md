**Premise correction:** There is no GraphQL schema in this repository. A case-insensitive grep for `graphql` across the entire tree (excluding `.git`/`node_modules`) returns zero hits — no `.graphql`/`.gql` files, no schema-definition code, no GraphQL server or client dependency in `go.mod` or `web/package.json`. Memos is a Go backend that never had a GraphQL layer; the README describes it as offering "full REST and gRPC APIs" (`README.md:23`).

**The actual public API surface — Protocol Buffers:**

The API contract is defined in `.proto` files under `proto/api/v1/`, one file per service:

| Service | Definition |
|---|---|
| `MemoService` | `proto/api/v1/memo_service.proto:17` |
| `UserService` | `proto/api/v1/user_service.proto:17` |
| `AuthService` | `proto/api/v1/auth_service.proto:13` |
| `AttachmentService` | `proto/api/v1/attachment_service.proto:15` |
| `InstanceService` | `proto/api/v1/instance_service.proto:17` |
| `ShortcutService` | `proto/api/v1/shortcut_service.proto:14` |
| `IdentityProviderService` | `proto/api/v1/idp_service.proto:14` |
| `AIService` | `proto/api/v1/ai_service.proto:11` |

Shared messages live in `proto/api/v1/common.proto`. Internal storage schemas (not public API) are separate, in `proto/store/`.

**How the surface is exposed.** Each RPC carries a `google.api.http` annotation that maps it to a REST route — e.g. `CreateMemo` → `POST /api/v1/memos`, `GetMemo` → `GET /api/v1/{name=memos/*}` (`proto/api/v1/memo_service.proto:18-34`). The design follows Google's AIP guidelines (`proto/api/v1/README.md`).

`buf generate`, configured in `proto/buf.gen.yaml`, fans the protos out into four surfaces:
- **gRPC** — `proto/gen/api/v1/*_grpc.pb.go`
- **Connect RPC** — `proto/gen/api/v1/apiv1connect/*.connect.go`
- **REST via gRPC-Gateway** — `proto/gen/api/v1/*.pb.gw.go`
- **OpenAPI spec** — `proto/gen/openapi.yaml` (4,057 lines; this is the closest analogue to the "schema document" you were probably picturing)
- **TypeScript client types** — emitted to `web/src/types/proto/` for the frontend

Server-side handlers implementing these services are in `server/router/api/v1/`, registered on `APIV1Service` (`server/router/api/v1/v1.go:22-40`), with gateway and Connect handlers wired up in `RegisterGateway` (`server/router/api/v1/v1.go:64`).
