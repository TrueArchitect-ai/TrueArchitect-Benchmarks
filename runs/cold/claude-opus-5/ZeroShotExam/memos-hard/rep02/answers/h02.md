**delivery function — `Post()` in `internal/webhook/webhook.go:120` (invoked off a queue by the async dispatch workers in `init()`, `internal/webhook/webhook.go:42-55`, fed by `PostAsync`, `internal/webhook/webhook.go:184`); protection mechanism — `safeDialContext` / `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`, plus `ValidateURL` at `internal/webhook/validate.go:62`**

How it fits together:

- **Trigger:** memo create/update/delete and comment-created events call `webhook.PostAsync(payload)` from `server/router/api/v1/memo_service_webhooks.go:43,71`, iterating the creator's registered hooks.
- **Execution:** `PostAsync` only enqueues onto a buffered channel (`asyncPostQueue`, cap 128, `webhook.go:39`); it drops the event with a warning if full. Four goroutines started in `init()` drain the queue and call `Post`, which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), sends via `safeClient.Do`, and caps the response read at 1 MiB.
- **SSRF protection (two layers):**
  1. *Dial-time* — `safeClient` (`webhook.go:32`) uses a `Transport` with `DialContext: safeDialContext`. That resolves the hostname itself and refuses the connection if **any** resolved IP is in a reserved range. Because the check happens at dial time rather than at save time, it also defeats DNS rebinding.
  2. *Config-time* — `webhook.ValidateURL` is called when a user creates/updates a webhook (`server/router/api/v1/user_service_webhooks.go:74,161,182`), enforcing absolute URL, http/https scheme only, and non-reserved resolution.
- **Blocked ranges** (`reservedCIDRs`, `internal/webhook/validate.go:14-23`): 127.0.0.0/8, 10/8, 172.16/12, 192.168/16, 169.254/16 (cloud IMDS), ::1/128, fc00::/7, fe80::/10 — parsed once at startup.

One caveat worth flagging: `AllowPrivateIPs` (`internal/webhook/validate.go:41`) is an escape hatch that disables both layers when true, but grep shows it is never assigned anywhere outside its declaration and tests — there's no flag or env wiring for it, so in practice it's always `false` in production builds.
