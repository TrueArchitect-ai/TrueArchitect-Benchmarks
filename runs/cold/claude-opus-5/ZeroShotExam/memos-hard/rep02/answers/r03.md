**Premise correction: there is no nightly database-cleanup job in this repository.** The cron scheduler exists, but nothing registers a database-cleanup job with it — so there is no scheduled time to report.

What actually exists:

- `internal/scheduler/` is a standalone, self-contained cron scheduler library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). Nothing outside that package imports it — the only importers are its own `example_test.go` and `integration_test.go`. It is not wired into the server at all (`server/server.go`, `server/runner/` don't reference it).
- Every "cleanup at 2 AM" reference is illustrative documentation, not a registered job:
  - `internal/scheduler/doc.go:15-16` — package doc example: `Name: "daily-cleanup", Schedule: "0 2 * * *", // 2 AM daily`
  - `internal/scheduler/README.md:34-36` — the same snippet in the quick-start
  - `internal/scheduler/example_test.go:97-99` — `Example_multipleJobs` registers a job named `cleanup` on `0 2 * * *` whose handler just prints "Cleaning up old data..."

  None of these touch the database; they're doc/test fixtures.
- The only real background workers in the codebase are ticker-based, not cron-based, and none does database cleanup: `server/runner/s3presign/runner.go:30` (re-signs S3 URLs) and `server/router/api/v1/sse_handler.go:64` (SSE heartbeat). The nearest thing to a "cleanup" loop is the in-memory cache eviction ticker at `store/cache/cache.go:201`, driven by a `CleanupInterval` duration — not a cron schedule, and not a database job.

If the intent is to know what the docs suggest as a convention, that's 2:00 AM daily (`0 2 * * *`) — but that's an example in prose, not a job this system runs.
