**Premise correction: there is no nightly database-cleanup job in this repository.** The cron scheduler is a standalone, unused library — nothing in the running server registers any job with it, cleanup or otherwise.

What actually exists:

- `internal/scheduler/` is a self-contained cron scheduler package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). Grepping for imports of `github.com/usememos/memos/internal/scheduler` turns up only its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`) — no production call site in `server/`, `cmd/`, or `store/`.
- The only background runners the server actually wires up are `server/runner/memopayload/runner.go` and `server/runner/s3presign/runner.go`, and neither is a database-cleanup job driven by cron.

The "nightly cleanup at 2 AM" that the premise likely refers to appears only in **documentation and example code**, never as a registered job:

- `internal/scheduler/doc.go:15-16` — package doc example: `Name: "daily-cleanup"`, `Schedule: "0 2 * * *", // 2 AM daily`
- `internal/scheduler/README.md:34-36` — same quick-start snippet
- `internal/scheduler/example_test.go:97-106` — `Example_multipleJobs` registers a job named `"cleanup"` on `"0 2 * * *"` whose handler just prints `"Cleaning up old data..."`
- `internal/scheduler/README.md:241-245` — a *different* illustrative example, `"stale-session-cleanup"` at `"0 3 * * *"` (3 AM), which is why "the" cleanup time is ambiguous even within the docs

So if the question is "what does the sample cleanup job use," the answer is 2 AM daily (`0 2 * * *`) — but that is example code with a `fmt.Println` body, not a scheduled database cleanup that runs in this application.
