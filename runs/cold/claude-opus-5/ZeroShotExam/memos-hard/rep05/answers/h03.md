**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any provider implementation must produce. The SSO flow in `server/router/api/v1/auth_service_sso.go:19,104` is typed against this abstraction rather than a concrete provider.

- **Concrete implementation — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only shipped protocol implementation. Its package doc reads "implements the OAuth2 identity provider integration"; it provides `IdentityProvider` backed by `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (including PKCE via `codeVerifier`), and user-info retrieval with field mapping.

This is corroborated by the schema: `proto/store/idp.proto` declares a single enum value `OAUTH2 = 1` and a one-of config with only `OAuth2Config` (`proto/api/v1/idp_service.proto:83-96`), and `auth_service_sso.go:121` dispatches solely to `oauth2.NewIdentityProvider(...)`. No SAML/OIDC-specific package exists.
