Notable: the avatar image is not on disk or S3 — it lives inline in the `user.avatar_url` column as a base64 data URI, so the "data layer" terminates at that column rather than at a blob store. Also, `getUserByUsername` matches on `username` only (not user ID), so `/file/users/5/avatar` resolves only if a user is literally named `5`.
