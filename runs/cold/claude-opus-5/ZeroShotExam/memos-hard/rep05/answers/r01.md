**Premise correction:** There is no Redis in this repository, and no external cache service of any kind. Grepping the whole tree (excluding `node_modules`) for `redis` returns zero hits — there is no Redis client in `go.mod`, no connection string, no host/port/password config. Memos ships as a single Go binary; its only external datastore is the SQL database (SQLite/MySQL/Postgres). So there is nothing to configure a Redis connection *in*.

**Actual mechanism:** The cache layer is a hand-rolled, in-process, in-memory cache.

- **Implementation:** `store/cache/cache.go` — a `Cache` struct backed by a `sync.Map`, with an atomic item counter and a background `cleanupLoop()` goroutine. Each entry is an `item{value, expiration, size}`; `Get` (`store/cache/cache.go:122`) checks `time.Now().After(itm.expiration)` and evicts lazily on read, in addition to the periodic sweep.
- **Where it's wired up:** `store/store.go:38-53`. `store.New()` builds one `cache.Config` literal and hands the *same* config to three separate `cache.New(...)` instances held on the `Store`: `instanceSettingCache`, `userCache`, and `userSettingCache`. `Store.Close()` (`store/store.go:73-76`) stops all three cleanup goroutines.

**TTL for user entries: 10 minutes.**

It comes from the shared `DefaultTTL` in `store/store.go:40-44`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

Two details worth noting:

1. **The TTL is not user-specific.** Every write in `store/user.go` (`CreateUser`, `CreateUserIfNoUsers`, `UpdateUser`, `ListUsers`, `GetUser` — lines 98, 122, 132, 143, 167) calls plain `s.userCache.Set(...)`, which delegates to `SetWithTTL(..., c.config.DefaultTTL)` at `store/cache/cache.go:92-94`. `SetWithTTL` exists but is never used for users, so the 10-minute default is the only TTL that applies. The same 10 minutes therefore also applies to instance settings and user settings.
2. **TTL isn't the only eviction path.** `MaxItems: 1000` is a shared per-cache cap; exceeding it triggers `cleanupOldest()` (`store/cache/cache.go:116-118`), so user entries can be dropped before 10 minutes under load. Writes also actively refresh the cache rather than only invalidating it, and deletes go through `s.deleteUserCache(...)` (`store/user.go:179`).

Since the cache lives in process memory, it is per-instance and not shared across replicas — the closest thing to a "connection" is `cache.New()` spawning a goroutine, configured entirely in code at `store/store.go:38`, with no env var or config-file knob to tune the TTL.
