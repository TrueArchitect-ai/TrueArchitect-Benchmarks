**Runners the server actually starts**

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:153-173`). Driven by a `time.Ticker` with a fixed 12-hour interval (`runnerInterval = time.Hour * 12`, `runner.go:27-41`), plus one synchronous `RunOnce(ctx)` at startup before the loop goroutine begins. Stops via its own `context.CancelFunc` stored in `backgroundRunnerCancels`, awaited through `backgroundRunnerWG` on shutdown. This is the *only* entry in `startBackgroundRunners`.
- **Cache cleanup loops ×3** (`store/cache/cache.go:83`, `cleanupLoop` at `:200-215`) — one goroutine per cache created in `store.New` (`store/store.go:51-53`: instanceSetting, user, userSetting caches). Driven by a `time.Ticker` at `CleanupInterval: 5 * time.Minute` (`store/store.go:40-44`); terminated by `stopChan` via `Store.Close()` (`store/store.go:71-79`).
- **Webhook dispatch pool (4 goroutines)** (`internal/webhook/webhook.go:42-56`) — started in `init()` at package import, so they exist as soon as `server/router/api/v1/*_webhooks.go` is linked in. Not scheduled at all: each goroutine blocks on `range asyncPostQueue`, a buffered channel (cap 128) fed per-event by request handlers (`webhook.go:190`). Queue-driven, not time-driven; no shutdown path.
- **Email send pool (2 goroutines)** (`internal/email/email.go:14-20`) — same pattern: `init()`-started workers draining `asyncEmailQueue` (cap 128), fed per-event (`email.go:57`) from `server/notification/email.go`. Queue-driven; no shutdown path.
- **Signal-handler goroutine** (`cmd/memos/main.go:99-103`) — triggered by SIGINT/SIGTERM on channel `c`, calls `s.Shutdown(ctx)`.

Per-request, not background: the SSE heartbeat ticker (`server/router/api/v1/sse_handler.go:64`) lives inside a single client's handler goroutine, and `Authenticator.recordPATUsage` (`server/auth/authenticator.go:180`) spawns a fire-and-forget goroutine per authenticated PAT request.

**Unused scheduling infrastructure**

- **`internal/scheduler`** — a complete cron scheduler (5- and 6-field parser, timezone support, middleware, graceful `Stop`; `scheduler.go`, `parser.go`, `job.go`, `middleware.go`, README + `doc.go`) is **not used by the server at all**. The only importers of `github.com/usememos/memos/internal/scheduler` are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No production code registers a job or calls `scheduler.New()`.
- **`server/runner/memopayload`** — lives under `server/runner/` and defines a `Runner` with `RunOnce` (`server/runner/memopayload/runner.go:14-27`), but it is never started as a background runner. Only the free function `memopayload.RebuildMemoPayload` is called, synchronously inside request handlers (`server/router/api/v1/memo_service.go:108` and `:447`). The `Runner` type/`RunOnce` themselves have no callers in non-test code.
