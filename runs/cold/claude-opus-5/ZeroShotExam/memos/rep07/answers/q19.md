**MemoService is served over two protocols:**

**1. HTTP/JSON REST via gRPC-Gateway** — `server/router/api/v1/v1.go`
- Registration: `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` at `server/router/api/v1/v1.go:108`, registering the in-process `APIV1Service` (which embeds `v1pb.UnimplementedMemoServiceServer`, `v1.go:26`) onto the grpc-gateway `runtime.ServeMux`. The mux is mounted on Echo at `/api/v1/*` and `/file/*` (`v1.go:126-129`), with auth applied via `gatewayAuthMiddleware` (`v1.go:69-98`). The generated gateway code is `proto/gen/api/v1/memo_service.pb.gw.go`.

**2. Connect RPC (Connect/gRPC/gRPC-Web over HTTP)** — `server/router/api/v1/connect_handler.go` (+ `connect_services.go`)
- Registration: `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` at `server/router/api/v1/connect_handler.go:40`, registered on an `http.ServeMux` mounted at `/memos.api.v1.*` (`v1.go:139-144`) with the Connect interceptor chain (`v1.go:133-138`).
- Wrapping: `ConnectServiceHandler` (`connect_handler.go:21-28`) embeds `*APIV1Service`; the per-method `connect.Request`/`connect.Response` adapters for MemoService are in `server/router/api/v1/connect_services.go:304` onward (`// MemoService` section — `CreateMemo`, `ListMemos`, `GetMemo`, `UpdateMemo`, …), each delegating to the same gRPC implementation and translating errors via `convertGRPCError` (`connect_handler.go:65-73`). Generated handler code: `proto/gen/api/v1/apiv1connect/memo_service.connect.go`.

Both paths share one implementation — `APIV1Service` — so the business logic has a single source of truth (as documented in the comment at `connect_handler.go:13-20`). Note there is no native gRPC socket server: `grep` finds no `grpc.NewServer` or `RegisterMemoServiceServer` call outside `proto/gen`.

(Separately, the MCP router at `server/router/mcp/catalog.go:12-25` exposes MemoService methods as MCP tools, but it dispatches through the same service rather than being a third transport registration of the proto service.)
