**Convergence for delivery:**

The three memo lifecycle events (created/updated/deleted) are thin wrappers over the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo's creator, loads their webhooks via `s.Store.GetUserWebhooks`, and builds the payload with `convertMemoToWebhookPayload`. `DispatchMemoCommentCreatedWebhook` does not go through that helper — it looks up webhooks for the *related* memo's owner instead of the comment creator — but it builds the same payload type.

All four converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue` (128 slots, dropping with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`) drain that queue and call `webhook.Post` (`internal/webhook/webhook.go:120`), which does the actual HTTP POST — JSON body, optional Standard-Webhooks HMAC-SHA256 signing headers, sent via the SSRF-guarded `safeClient`.

Call sites: `memo_service.go:157` (create), `memo_update_helpers.go:67` (update), `memo_service.go:562` (delete), `memo_service_comments.go:119` (comment).
