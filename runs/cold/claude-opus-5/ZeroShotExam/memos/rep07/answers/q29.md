q29.

**Answer:** `web/src/connect.ts` (with token storage in `web/src/auth-state.ts`); short-lived JWT access token (Bearer header) + long-lived refresh token (HttpOnly cookie `memos_refresh`), plus PATs for programmatic clients; validated by `server/auth`.

**Details:**

**Interceptor — `web/src/connect.ts`**
- `authInterceptor` (`web/src/connect.ts:145`) is registered on the Connect-RPC transport (`createConnectTransport`, `interceptors: [authInterceptor]`) used by every service client (memo, user, auth, attachment, etc.).
- On each request it calls `getRequestToken()` and sets `Authorization: Bearer <token>`. The transport's `fetch` wrapper uses `credentials: "include"` so the refresh cookie rides along.
- On a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry: true` marker to prevent loops, and calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`) if refresh fails.
- A separate `refreshTransport` with **no** interceptors is used for `AuthService.refreshToken` to avoid recursion; `tokenRefreshManager` de-dupes concurrent refreshes.

**Tokens managed**
- **Access token** — JWT, 15 min (`AccessTokenDuration`, `server/auth/token.go:41`), audience `user.access-token`. Cached in memory and `localStorage` under `memos_access_token` / `memos_token_expires_at` (`web/src/auth-state.ts`), broadcast across tabs via a `memos_token_sync` `BroadcastChannel`. Preflight-refreshed within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`) and proactively on tab focus within 2 min (`web/src/hooks/useTokenRefreshOnFocus.ts`).
- **Refresh token** — 30 days (`RefreshTokenDuration`), HttpOnly cookie `memos_refresh` (`server/auth/token.go:49`); never touched by JS, only sent via `credentials: "include"`.
- **Personal Access Tokens** — prefix `memos_pat_` (`server/auth/token.go:53`), same `Authorization: Bearer` path for programmatic/API clients.

**Backend validation — `server/auth/`**
- `Authenticator` (`server/auth/authenticator.go:26`) is the shared validator for the Connect interceptor, gRPC interceptor, and file server.
- `AuthenticateByAccessTokenV2` does stateless signature validation; `AuthenticateByRefreshToken` additionally checks the DB (`store.GetUserRefreshTokenByID`) for revocation.
- `server/auth/extract.go` pulls the bearer token from the header and the refresh token from the cookie.
- Wired in at `server/router/api/v1/connect_interceptors.go:222` (`in.authorizer.Authenticate(ctx, authHeader)` → `auth.ApplyToContext`), with per-method permission rules in `server/router/api/v1/authz.go`.
