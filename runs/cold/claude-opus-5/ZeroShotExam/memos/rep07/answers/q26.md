**Tables affected: `memo`, `memo_relation`, `attachment`, and `memo_share`** (the last only on Postgres/MySQL — see caveat).

**How each is reached**

1. **`memo`** — the row itself, plus one row per comment memo.
   - `server/router/api/v1/memo_service.go:569-577` lists `MemoRelationComment` relations pointing at the memo and calls `Store.DeleteMemo` for each comment memo, then `:580` deletes the memo itself.
   - Driver SQL: `DELETE FROM memo WHERE id = ?` — `store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`.

2. **`memo_relation`** — explicit cascade code in `store/memo.go:141-147`: two `DeleteMemoRelation` calls, one matching `memo_id`, one matching `related_memo_id`, so relations in both directions are removed (for the memo and for each deleted comment).

3. **`attachment`** — explicit cascade code in `store/memo.go:148-157`: lists attachments with `MemoID = delete.ID` and calls `Store.DeleteAttachment` per attachment, which also removes the backing local/S3 file before the row (`store/attachment.go:132-149`).

4. **`memo_share`** — *not* touched by Go code; removed by a DB-level FK cascade declared on the table: `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in `store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`.
   - Caveat: the SQLite driver opens the DB with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so on SQLite that cascade does not fire and `memo_share` rows are left orphaned. It does fire on Postgres and MySQL.

**Explicitly *not* affected** (rows are read but never deleted, so they orphan):
- **`reaction`** — read at `server/router/api/v1/memo_service.go:545-550` only to build the webhook payload; there is no `DeleteReaction` call on this path, and `reaction.content_id` is a plain text column with no FK (`store/migration/sqlite/LATEST.sql:92-100`).
- **`inbox`** — memo-mention/comment notifications are never cleaned up on memo deletion; `Store.DeleteInbox` is only called from `server/router/api/v1/user_service_notifications.go:195`.
