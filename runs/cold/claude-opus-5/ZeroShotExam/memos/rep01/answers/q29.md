**`web/src/connect.ts`; JWT access token (in-memory/localStorage) + refresh token (HttpOnly cookie), plus PATs server-side; `server/auth`**

**Frontend interceptor — `web/src/connect.ts:156` (`authInterceptor`)**
- It's a Connect-RPC `Interceptor` registered on the single shared transport (`web/src/connect.ts:184-189`), so every generated service client (`memoServiceClient`, `userServiceClient`, etc., lines 192-203) goes through it.
- On each request it calls `getRequestToken()` (line 124) and sets `Authorization: Bearer <token>` (line 97). It does a *preflight* refresh when the access token is within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), and a *reactive* refresh on a `Code.Unauthenticated` error, replaying the request once with an `X-Retry: true` guard; if that fails it calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- Refreshes go through a separate transport with **no** interceptors (`web/src/connect.ts:65-72`) to avoid recursion, and through a dedup manager (line 30) so concurrent refreshes collapse into one. `fetch` is wrapped with `credentials: "include"` so the refresh cookie is sent.

**Tokens managed — `web/src/auth-state.ts`**
- **Access token**: short-lived JWT held in a module variable, persisted to `localStorage` under `memos_access_token` / `memos_token_expires_at`, and synced across tabs via a `BroadcastChannel` named `memos_token_sync`.
- **Refresh token**: never touched by JS — it's an HttpOnly cookie (`memos_refresh`) sent automatically; the frontend only calls `AuthService.RefreshToken` (`web/src/connect.ts:74-83`). Proactive refresh on tab focus lives in `web/src/hooks/useTokenRefreshOnFocus.ts` (2-minute buffer).

**Backend validator — `server/auth`** (package doc at `server/auth/token.go:1-11`)
- `server/auth/extract.go:11` pulls the bearer token from the header; `server/auth/authenticator.go` validates it: `AuthenticateByAccessTokenV2` (line 41) does stateless JWT signature validation, `AuthenticateByRefreshToken` (line 61) parses *and* checks the DB for revocation/expiry, and tokens prefixed `memos_pat_` (`server/auth/token.go:52`) are validated as Personal Access Tokens against the store.
- It's wired in via `AuthInterceptor` at `server/router/api/v1/connect_interceptors.go:208-230`, which reads the `Authorization` header, delegates to the `Authorizer`, and stores the result on the context with `auth.ApplyToContext`. The same package also backs `server/router/fileserver` and `server/router/mcp`.
