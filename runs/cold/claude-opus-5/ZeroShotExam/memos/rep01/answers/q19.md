**1. HTTP/JSON REST via gRPC-Gateway** — `server/router/api/v1/v1.go`
`RegisterGateway` builds a `runtime.NewServeMux` and registers the memo service in-process with `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` (`server/router/api/v1/v1.go:108`), then mounts it on Echo at `/api/v1/*` and `/file/*` (`v1.go:126-129`). The generated gateway glue lives in `proto/gen/api/v1/memo_service.pb.gw.go`.

**2. Connect RPC (connectrpc, the browser/gRPC-compatible protocol)** — `server/router/api/v1/connect_handler.go`
`ConnectServiceHandler` wraps `*APIV1Service` and registers `apiv1connect.NewMemoServiceHandler(s, opts...)` on a `http.ServeMux` (`server/router/api/v1/connect_handler.go:40`, via `RegisterConnectHandlers`). That mux is created and mounted at `/memos.api.v1.*` in `server/router/api/v1/v1.go:139-144`. Generated code: `proto/gen/api/v1/apiv1connect/memo_service.connect.go`.

Both share one implementation — `APIV1Service` (which embeds `v1pb.UnimplementedMemoServiceServer`, `v1.go:26`); the Connect side is a thin wrapper that also translates gRPC status codes to Connect codes (`connect_handler.go:63-80`).

Note: MemoService methods are additionally exposed as MCP tools (`server/router/mcp/catalog.go:12-25`), but that is not a third registration of the service — the MCP adapter replays requests through the Echo server against the same REST gateway routes (`server/router/mcp/adapter.go:26-42`).
