**`web/src/connect.ts`; JWT access token (Bearer, in-memory/localStorage) + `memos_refresh` HttpOnly refresh-token cookie (and Personal Access Tokens on the same Bearer header); `server/auth`**

**Frontend — `web/src/connect.ts`**
- `authInterceptor` (`web/src/connect.ts:145`) is registered on the single `createConnectTransport` (`web/src/connect.ts:170`) that backs every Connect-RPC service client (`memoServiceClient`, `userServiceClient`, etc.), so all API calls pass through it.
- On each request it calls `getRequestToken()` and sets `Authorization: Bearer <token>`. On a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry: true` marker to prevent loops, and on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- Token state lives in `web/src/auth-state.ts`: access token cached in memory + `localStorage` (`memos_access_token` / `memos_token_expires_at`), with a `BroadcastChannel` (`memos_token_sync`) so tabs share refreshes. Preflight refresh fires when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s); `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus (2min buffer).
- Refresh goes through a separate transport with **no** auth interceptor (`web/src/connect.ts:66`) calling `AuthService.RefreshToken`; `fetch` uses `credentials: "include"` so the HttpOnly refresh cookie is sent. Concurrent refreshes are deduped by `tokenRefreshManager`.

**Tokens managed**
1. Short-lived JWT access token ("Access Token V2", 15 min) — sent as `Authorization: Bearer`.
2. Long-lived refresh token (30 days) — HttpOnly cookie `memos_refresh` (`server/auth/token.go:43-49`), never touched by JS.
3. Personal Access Tokens — same `Bearer` header path, used for programmatic clients.

**Backend — `server/auth`**
- `Authenticator` (`server/auth/authenticator.go`) validates all three: `AuthenticateByAccessTokenV2` (stateless JWT parse), `AuthenticateByPAT` (store lookup, prefix-detected in `resolveBearer`), `AuthenticateByRefreshToken` (DB-validated).
- Token generation/parsing in `server/auth/token.go`; header/cookie extraction in `server/auth/extract.go`.
- It's invoked per-request by `AuthInterceptor.WrapUnary` (`server/router/api/v1/connect_interceptors.go:217-231`), which delegates to the `Authorizer` in `server/router/api/v1/authz.go` for anonymous-access policy (`acl_config.go`) and stashes the result via `auth.ApplyToContext`.
