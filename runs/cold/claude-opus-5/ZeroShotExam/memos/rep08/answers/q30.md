Convergence for delivery:

The first three are thin wrappers over the shared helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which only differs by the `activityType` string. The comment event doesn't go through that helper — it resolves webhooks by the *related* memo's creator ID rather than the comment creator — but all four converge one level lower: each looks up `s.Store.GetUserWebhooks`, builds a payload via `convertMemoToWebhookPayload` (`memo_service_webhooks.go:76`), sets `ActivityType`/`URL`/`SigningSecret`, and calls **`webhook.PostAsync`** (`internal/webhook/webhook.go:184`).

`PostAsync` enqueues onto the bounded `asyncPostQueue` (cap 128, dropped with a warning if full), drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each calling **`webhook.Post`** (`internal/webhook/webhook.go:120`) — the single actual delivery point, which JSON-marshals the payload, adds Standard Webhooks HMAC-SHA256 headers when a signing secret is set, and POSTs via the SSRF-guarded `safeClient`.
