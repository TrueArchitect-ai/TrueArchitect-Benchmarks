**`web/src/connect.ts`; short-lived JWT access token (in-memory/localStorage, Bearer header) + long-lived refresh token (httpOnly `memos_refresh` cookie), plus PAT support server-side; `server/auth`**

**Frontend interceptor — `web/src/connect.ts`**
- `authInterceptor` (`web/src/connect.ts:145`) is attached to the Connect-RPC transport (`createConnectTransport`, `web/src/connect.ts:170`) that backs every service client (memo, user, auth, attachment, etc.). It sets `Authorization: Bearer <token>` on each request.
- On a `Code.Unauthenticated` error it refreshes once and replays the request with an `X-Retry: true` header to prevent loops; if the refresh fails it calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- Refresh goes through a separate transport with **no** interceptors (`refreshTransport`, `web/src/connect.ts:64`) to avoid recursion, and all callers funnel through `tokenRefreshManager` so concurrent refreshes are deduplicated. `fetch` is wrapped with `credentials: "include"` so the refresh cookie is sent.

**Tokens managed**
- **Access token** — short-lived JWT (15 min, `AccessTokenDuration` in `server/auth/token.go:39`). Stored by `web/src/auth-state.ts` (in-memory + `localStorage` keys `memos_access_token` / `memos_token_expires_at`), shared between tabs over a `BroadcastChannel` (`memos_token_sync`). `getRequestToken()` does a preflight refresh when within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30 s); `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus with a 2 min buffer.
- **Refresh token** — long-lived (30 days), delivered as the httpOnly cookie `memos_refresh` (`server/auth/token.go:49`); the frontend never reads it, it just calls `AuthService.RefreshToken` with credentials included.
- **Personal Access Tokens** (`memos_pat_` prefix) exist for programmatic clients but aren't used by the web interceptor.

**Backend validation — `server/auth`**
- `Authenticator` (`server/auth/authenticator.go`) does stateless JWT validation via `AuthenticateByAccessTokenV2`, DB-backed `AuthenticateByRefreshToken`, and PAT lookup; header/cookie parsing lives in `server/auth/extract.go`, token minting/parsing in `server/auth/token.go`.
- It's wired into the API via the Connect interceptors in `server/router/api/v1/connect_interceptors.go` (and `server/router/fileserver/fileserver.go` for file requests), with authorization rules in `server/router/api/v1/authz.go`.
