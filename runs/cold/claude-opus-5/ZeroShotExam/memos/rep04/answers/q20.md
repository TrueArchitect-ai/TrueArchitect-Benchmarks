**q20.**

**Server-Sent Events (SSE) over `GET /api/v1/sse`; `server/router/api/v1/sse_hub.go` (`SSEHub`); `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `UpsertMemoReaction`, `DeleteMemoReaction`**

Details:

**Mechanism** — SSE, not WebSockets. `server/router/api/v1/sse_handler.go:34` sets `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`, flushes headers, and streams with a 30s heartbeat (`sseHeartbeatInterval`). The route is registered at `server/router/api/v1/sse_handler.go:25` (`RegisterSSERoutes` → `GET /api/v1/sse`), wired in `server/router/api/v1/v1.go:125`. Auth is a Bearer token via `auth.Authenticator`. The browser side is `web/src/hooks/useLiveMemoRefresh.ts`, which reconnects with exponential backoff (1s → 30s) and invalidates React Query caches.

**Hub** — `server/router/api/v1/sse_hub.go`. `SSEHub` holds a mutex-guarded `map[*SSEClient]struct{}`; `Subscribe` (32-event buffered channel per client), `Unsubscribe`, `Close`, and `Broadcast`. `Broadcast` drops events for slow clients rather than blocking, and filters per client via `canReceive`: `Private` memos go only to the creator or an admin. The hub instance lives on `APIV1Service.SSEHub` (`server/router/api/v1/v1.go:36,57`) and is closed on shutdown (`server/server.go:204-206`).

**Broadcasting handlers** (event types in `sse_hub.go:14-21`):
- `CreateMemo` — `memo_service.go:163`, `memo.created`, guarded by `isSSESuppressed(ctx)` so comment creation doesn't double-fire
- `UpdateMemo` — `memo_service.go:513` → `dispatchMemoUpdatedSideEffects` at `memo_update_helpers.go:71`, `memo.updated`
- `DeleteMemo` — `memo_service.go:585`, `memo.deleted`
- `CreateMemoComment` — `memo_service_comments.go:126`, `memo.comment.created`
- `UpsertMemoReaction` — `reaction_service.go:106`, `reaction.upserted`
- `DeleteMemoReaction` — `reaction_service.go:161`, `reaction.deleted`

The last two build their payload via `buildMemoReactionSSEEvent` in `server/router/api/v1/sse_event_helpers.go`.
