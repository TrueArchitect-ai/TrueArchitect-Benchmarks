**Convergence for delivery:**

The three non-comment events share the internal helper `dispatchMemoRelatedWebhook(ctx, memo, activityType)` (`memo_service_webhooks.go:47`), which resolves the memo creator and their webhooks. The comment variant instead resolves webhooks for the *related memo's* creator (`relatedMemoCreatorID`), so it bypasses that helper — but all four build the payload via `convertMemoToWebhookPayload` and then converge on:

- `webhook.PostAsync(payload)` — `internal/webhook/webhook.go:181`, which enqueues onto the bounded `asyncPostQueue` (128 slots, drops with a warning when full)
- 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:41`) drain the queue and call **`webhook.Post(payload)`** — `internal/webhook/webhook.go:118` — the single function that actually performs the HTTP POST (HMAC-SHA256 Standard Webhooks signing, SSRF-guarded `safeClient`).
