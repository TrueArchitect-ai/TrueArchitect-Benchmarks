`Store.DeleteMemo` (`store/memo.go:140-159`) removes two other kinds of records before calling `s.driver.DeleteMemo` (the actual `DELETE FROM memo` — `store/db/sqlite/memo.go:237`):

- **Memo relations, in both directions** — `DeleteMemoRelation{MemoID: &delete.ID}` and `DeleteMemoRelation{RelatedMemoID: &delete.ID}`, so rows where this memo is either the source or the target are cleaned up (`store/memo.go:141-147`).
- **Attachments linked to the memo** — it lists them via `ListAttachments(FindAttachment{MemoID:...})` and calls `DeleteAttachment` on each (`store/memo.go:148-157`). `Store.DeleteAttachment` (`store/attachment.go:132-149`) also deletes the underlying stored file/blob (`DeleteAttachmentStorage`) before removing the attachment row.

Notes on scope:
- Reactions and memo shares are **not** deleted by the store layer here.
- The API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-581`) additionally deletes the memo's comment memos first — each via its own `Store.DeleteMemo`, which recursively applies the relation/attachment cleanup above.
