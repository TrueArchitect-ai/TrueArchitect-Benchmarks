**MemoService is served over gRPC-Gateway REST/JSON and Connect RPC.** (There is no standalone gRPC listener — no `grpc.NewServer` anywhere outside generated code; the gRPC service impl is reused behind both HTTP surfaces.)

**1. REST / JSON (gRPC-Gateway) — `server/router/api/v1/v1.go`**
- `server/router/api/v1/v1.go:108` — `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` registers the service directly onto the grpc-gateway mux (in-process, no gRPC dialing), which is mounted at `/api/v1/*` and `/file/*` (`v1.go:128-129`).
- Generated routing/marshaling: `proto/gen/api/v1/memo_service.pb.gw.go`.

**2. Connect RPC — `server/router/api/v1/connect_handler.go`**
- `server/router/api/v1/connect_handler.go:40` — `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` inside `RegisterConnectHandlers`, mounted at `/memos.api.v1.*` from `v1.go:140-144`.
- Per-method wrapping of the gRPC impl into Connect request/response types lives in `server/router/api/v1/connect_services.go:304` onward (the `// MemoService` section: `CreateMemo`, `ListMemos`, `GetMemo`, …), each delegating to `s.APIV1Service.*` and translating errors via `convertGRPCError` (`connect_handler.go:65`).
- Generated Connect stubs: `proto/gen/api/v1/apiv1connect/memo_service.connect.go`.

Both surfaces share one implementation (`APIV1Service`, `server/router/api/v1/v1.go:22-45`) and one authorizer (`v1.go:68`), applied as gateway middleware for REST and as `NewAuthInterceptor` for Connect (`v1.go:137`).
