**Runners the server actually starts**

- **s3presign runner** — `server/server.go:153-174` (`startBackgroundRunners`). Runs `RunOnce(ctx)` synchronously once at startup, then a goroutine loops on a `time.NewTicker(12h)` (`server/runner/s3presign/runner.go:26-40`); stopped by its own `context.CancelFunc` on shutdown. This is the **only** entry in `startBackgroundRunners`.
- **HTTP serve goroutine** — `server/server.go:124`, driven by incoming connections on the TCP/unix listener (not a scheduled job).
- **Cache cleanup loops (×3)** — `store/cache/cache.go:81` (`go c.cleanupLoop()`), fired by a `time.NewTicker(CleanupInterval)` at `cache.go:201`. Started implicitly by `store.New` (`store/store.go:37-58`, `CleanupInterval: 5 * time.Minute`) for the instanceSetting/user/userSetting caches, i.e. at process startup from `cmd/memos/main.go:63`.
- **Webhook dispatch pool (4 goroutines)** — `internal/webhook/webhook.go:42-55`, started in `init()` on package import; driven by the `asyncPostQueue` channel (event-driven, one item per memo activity), not a timer.
- **Email send pool (2 goroutines)** — `internal/email/email.go:16-35`, also `init()`-time; driven by the `asyncEmailQueue` channel.
- **SSE heartbeat** — `server/router/api/v1/sse_handler.go:64`, a `time.NewTicker(30s)` per connected client; request-scoped, lives only for the SSE request, ends on `ctx.Done()`.
- **PAT last-used writer** — `server/auth/authenticator.go:178-184`, a fire-and-forget goroutine per authenticated PAT request.
- **Signal-handler goroutine** — `cmd/memos/main.go:99`, waits on SIGINT/SIGTERM to call `s.Shutdown`.

**Unused scheduling infrastructure**

- **`internal/scheduler/`** — a complete cron scheduler (cron parser, jobs, middleware, timezone support, README and `doc.go`) is **never used by the server**. The only imports of `github.com/usememos/memos/internal/scheduler` are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No production code registers a job; the one recurring runner uses a hand-rolled `time.Ticker` instead.
- **`server/runner/memopayload.Runner`** — `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19-27`) are never called anywhere; only the standalone `memopayload.RebuildMemoPayload` helper is used, inline on the request path (`server/router/api/v1/memo_service.go:108,447`). So this "runner" exists but is never scheduled or started.
