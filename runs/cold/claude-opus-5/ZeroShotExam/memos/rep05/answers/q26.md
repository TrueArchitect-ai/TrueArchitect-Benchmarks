**Tables affected: `memo`, `memo_relation`, `attachment`, and `memo_share` (DB-level FK cascade, MySQL/Postgres only).**

### Store-level cascade — `store/memo.go:140-159`
`(*Store).DeleteMemo` explicitly cascades before deleting the memo row:

1. **`memo_relation`** — two deletes, one matching `memo_id = ID` and one matching `related_memo_id = ID` (`store/memo.go:142-147` → e.g. `store/db/sqlite/memo_relation.go:137`).
2. **`attachment`** — lists attachments with `MemoID = ID` and calls `DeleteAttachment` per row (`store/memo.go:149-157` → `store/attachment.go:132-149`, `store/db/sqlite/attachment.go:211`). This also removes the underlying blob/local/S3 file, which is filesystem/object-storage, not a table.
3. **`memo`** — the row itself, `DELETE FROM memo WHERE id = ?` (`store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`).

### API-level cascade — `server/router/api/v1/memo_service.go:518-593`
`(*APIV1Service).DeleteMemo` first lists comment relations (`RelatedMemoID = memo.ID`, type `COMMENT`) and calls `Store.DeleteMemo` for each comment memo (lines 567-577), so the same three tables are hit again for every comment. It then deletes the memo itself (line 580). The reaction/attachment lookups at lines 545-557 are only for the webhook payload.

### `memo_share` — schema cascade, not code
`memo_share` has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in all three schemas (`store/migration/sqlite/LATEST.sql:109`, `postgres/LATEST.sql:108`, `mysql/LATEST.sql:108`). There is no Go code deleting shares on memo deletion. Note this cascade does **not** fire on SQLite: the connection is opened with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so share rows are orphaned on SQLite deployments.

### Not affected: `reaction`
Reactions are stored with a string `content_id` (the memo resource name) and no FK (`store/migration/sqlite/LATEST.sql:92-100`). Nothing in `DeleteMemo` deletes them — `DeleteReaction` is only called from `reaction_service.go:141`. Reaction rows for a deleted memo are left orphaned.
