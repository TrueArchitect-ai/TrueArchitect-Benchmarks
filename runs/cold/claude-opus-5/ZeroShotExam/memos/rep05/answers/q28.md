**Runners the server actually starts — and what drives each**

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started explicitly in `Server.startBackgroundRunners` (`server/server.go:153-174`). Two triggers: one synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a goroutine running `Run()` on a `time.NewTicker` fixed 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). Shutdown is via its own `context.CancelFunc` stored in `backgroundRunnerCancels` + `backgroundRunnerWG`.
- **HTTP serve goroutine** (`server/server.go:124-128`) — `httpServer.Serve(listener)`; driven by incoming connections, torn down by `httpServer.Shutdown`.
- **3× store cache cleanup loops** (`store/cache/cache.go:75-83`, `cleanupLoop` at :199) — started implicitly by `cache.New` inside `store.New` for `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`). Driven by a `time.NewTicker(CleanupInterval)` = 5 minutes (`store/store.go:42`); stopped via `stopChan` from `Store.Close()` (`store/store.go:72-79`).
- **Webhook dispatch pool — 4 goroutines** (`internal/webhook/webhook.go:42-55`) — started in package `init()`, so they exist whenever the binary runs. Not time-driven: they block on the buffered channel `asyncPostQueue` (cap 128), fed by `webhook.PostAsync` from memo activity (`server/router/api/v1/memo_service_webhooks.go:43,71`).
- **Email sender pool — 2 goroutines** (`internal/email/email.go:16-35`) — also package `init()`; driven by the `asyncEmailQueue` channel (cap 128) fed by `email.SendAsync`, wired in `server/notification/email.go:30`.

Per-request/per-connection goroutines (not long-lived workers, but the only other recurring timers): the SSE heartbeat `time.NewTicker(30s)` per connected client (`server/router/api/v1/sse_handler.go:17,64`), and the fire-and-forget PAT last-used update goroutine (`server/auth/authenticator.go:178-185`).

**Unused scheduling infrastructure**

- **`internal/scheduler` is entirely unused by the server.** It's a full cron scheduler — 6/5-field cron parser (`parser.go`), `Job` registration (`job.go`), middleware chain (`middleware.go`), timezone support and graceful shutdown (`scheduler.go`), plus a README and `doc.go` describing it as "included with Memos." Grepping for `internal/scheduler` across all Go files yields zero references outside the package itself (only its own `*_test.go` / `example_test.go`). Nothing in `server/server.go` or `cmd/memos/main.go` constructs a `scheduler.New()`; the only real periodic job uses a hand-rolled `time.Ticker` instead.
- **`memopayload.Runner` is also dead runner scaffolding** (`server/runner/memopayload/runner.go:16-24,26-90`) — `NewRunner`/`RunOnce` are never called; only the free function `RebuildMemoPayload` is used, inline on the request path (`server/router/api/v1/memo_service.go:108,447`).
