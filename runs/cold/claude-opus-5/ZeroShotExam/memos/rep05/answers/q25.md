**Engine:** Google CEL (`github.com/google/cel-go`, go.mod:13), wrapped by the in-repo memo filter engine at `internal/filter/` — `engine.go` (`Engine`, `Compile`, `CompileToStatement`, `DefaultEngine`), `schema.go` (CEL env + field metadata), `parser.go`, `ir.go`, `render.go`, `helpers.go`. **Mechanism (one sentence):** `ListMemos` (`server/router/api/v1/memo_service.go:211-224`) validates `request.Filter` via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`) and pushes it onto `store.FindMemo.Filters`; each dialect driver's `ListMemos` (`store/db/sqlite/memo.go:57-63`, `store/db/postgres/memo.go:54-59`, `store/db/mysql/memo.go:65-71`) calls `filter.AppendConditions(ctx, filter.DefaultEngine(), find.Filters, filter.Dialect{SQLite,Postgres,MySQL}, &where, &args)` (`internal/filter/helpers.go:9`), which compiles the CEL string through `cel-go` into a dialect-agnostic IR condition tree (`parser.go`/`ir.go`) and renders it into a parameterized SQL fragment plus args for the target dialect (`render.go`), appended as `(...)` to the WHERE clause.

Supporting details:
- The pipeline is explicitly three-phase — parse (CEL, schema-validated so only declared fields are usable), normalize to IR, render per dialect (`internal/filter/README.md`).
- Dialect differences live in the renderer and schema field `Expressions` maps (`internal/filter/schema.go:104-145`): `?` placeholders for SQLite/MySQL vs `$n` for Postgres, JSON access (`json_extract` vs `->>`), timestamps (`UNIX_TIMESTAMP` on MySQL), and tag membership (`LIKE` on SQLite, `JSON_CONTAINS` on MySQL, `@>` on Postgres).
- `RenderOptions.PlaceholderOffset` is set from `len(args)` so the fragment composes with pre-existing query args.
- Timestamp expressions (`now`, `duration(...)`, `timestamp(...)`) fold to epoch seconds at compile time, with `now` frozen once per compile via the engine's `nowFunc` (`internal/filter/engine.go:17-20`).
- Trivial filters render to empty SQL (skipped); unsatisfiable ones render to `1 = 0` (`internal/filter/engine.go:41-56` in `render.go`'s `Render`).
- The same engine is reused for shortcut filters and user stats; there's a separate `DefaultAttachmentEngine()` for attachments.
