**`web/src/connect.ts`; short-lived JWT access token (Bearer, localStorage) + long-lived refresh token (HttpOnly `memos_refresh` cookie) — plus PATs on the server side; `server/auth/`**

### Frontend interceptor — `web/src/connect.ts:156`
`authInterceptor` is a Connect-RPC `Interceptor` installed on the single `createConnectTransport` (`web/src/connect.ts:184-189`) that backs every service client (memo, user, attachment, auth, etc.). Per request it:
1. Calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, line 97).
2. Preflight-refreshes if the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30 s) of expiry.
3. On a `Code.Unauthenticated` response, refreshes once, replays the request with an `X-Retry: true` header to prevent loops, and on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).

Transport uses `credentials: "include"` (`fetchWithCredentials`, line 57) so the refresh cookie rides along. Refresh calls go through a *separate* interceptor-free transport (`refreshTransport`, line 65) to avoid recursion, and are deduplicated by `tokenRefreshManager` (line 30). Proactive refresh on tab focus lives in `web/src/hooks/useTokenRefreshOnFocus.ts`.

### Tokens managed — `web/src/auth-state.ts`
- **Access token**: JWT in memory + `localStorage` keys `memos_access_token` / `memos_token_expires_at`; 15 min lifetime; cross-tab sync via a `memos_token_sync` `BroadcastChannel`.
- **Refresh token**: not touched by JS — it's an HttpOnly cookie `memos_refresh` (`server/auth/token.go:47`), 30 day lifetime, exchanged via `AuthService.RefreshToken`.
- **PAT** (`memos_pat_` prefix): server-side auth method for programmatic clients, not issued by the web app.

### Backend validation — `server/auth/`
- `server/auth/token.go` — issuing/parsing JWTs (`Issuer = "memos"`, audiences `user.access-token` / `user.refresh-token`, PAT hashing).
- `server/auth/authenticator.go` — `Authenticator.AuthenticateByAccessTokenV2` (stateless signature check), `AuthenticateByRefreshToken` (DB revocation + expiry check), `AuthenticateByPAT` (hash lookup).
- `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie`.

It's wired in via `server/router/api/v1/authz.go:36` (`Authorizer` wrapping the authenticator), used by both the Connect interceptor and the gRPC-Gateway middleware in `server/router/api/v1/v1.go:78`, plus `sse_handler.go` and `server/router/fileserver/fileserver.go:115`.
