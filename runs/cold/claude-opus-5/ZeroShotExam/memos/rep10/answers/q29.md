**Answer: `web/src/connect.ts`; JWT access token (in-memory + localStorage, sent as `Authorization: Bearer`) and a refresh token (HttpOnly `memos_refresh` cookie), plus Personal Access Tokens for programmatic clients; `server/auth/`**

### Frontend interceptor — `web/src/connect.ts`

`authInterceptor` (`web/src/connect.ts:154`) is registered on the Connect-RPC transport (`interceptors: [authInterceptor]`, `web/src/connect.ts:180`), which backs every generated service client (`memoServiceClient`, `userServiceClient`, etc.). Per request it:

1. Calls `getRequestToken()` and sets `Authorization: Bearer <token>`.
2. Pre-emptively refreshes if the token expires within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) — this avoids public endpoints like `ListMemos` silently returning guest-scoped data.
3. On a `Code.Unauthenticated` error, refreshes once, marks the request with an `X-Retry: true` header to prevent loops, and retries; on failure calls `redirectOnAuthFailure()`.

Supporting pieces:
- `web/src/auth-state.ts` — token storage (`memos_access_token` / `memos_token_expires_at` in localStorage) and cross-tab sync via a `memos_token_sync` BroadcastChannel.
- Refresh goes through a separate transport with **no** interceptors (`refreshTransport`, `web/src/connect.ts:64`) to avoid recursion, and uses `credentials: "include"` so the refresh cookie is sent. A `tokenRefreshManager` dedupes concurrent refreshes.
- `web/src/hooks/useTokenRefreshOnFocus.ts` — proactive refresh on tab focus (2-minute buffer).

### Token kinds

From `server/auth/token.go`:
- **Access token** — JWT, 15 min (`AccessTokenDuration`), audience `user.access-token`, stateless validation.
- **Refresh token** — JWT, 30 days, audience `user.refresh-token`, stored in the `memos_refresh` cookie, and checked against the DB for revocation.
- **Personal Access Token** — prefix `memos_pat_`, SHA-256 hashed, for programmatic access.

### Backend validation — `server/auth/`

`Authenticator` (`server/auth/authenticator.go`) is the shared validator used by the Connect interceptor, gRPC interceptor, and file server:
- `AuthenticateByAccessTokenV2` (line 41) — stateless JWT parse.
- `AuthenticateByRefreshToken` (line 61) — parse + DB revocation/expiry check.
- `AuthenticateByPAT` (line 102) — hash lookup.
- `resolveBearer` (line 149) dispatches on the `memos_pat_` prefix; `server/auth/extract.go` pulls the bearer token from the header and the refresh token from the cookie.

The wiring point is `server/router/api/v1/connect_interceptors.go:222`, which calls `Authenticate(ctx, authHeader)` and stows the result on the context via `auth.ApplyToContext`.
