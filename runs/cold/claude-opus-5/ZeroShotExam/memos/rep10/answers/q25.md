**Engine:** Google CEL (`github.com/google/cel-go`, go.mod:13), wrapped by the in-repo memo filter engine at `internal/filter/` — `engine.go` (entry point `filter.DefaultEngine()`), `schema.go` (CEL env + field metadata), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL), `helpers.go` (store glue). Documented in `internal/filter/README.md`.

**Mechanism (one sentence):** `ListMemos` validates `request.Filter` via `s.validateFilter` (`server/router/api/v1/memo_service.go:211-215` → `server/router/api/v1/shortcut_service.go:336`) and appends it to `store.FindMemo.Filters`; each store driver then calls `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` (`store/db/sqlite/memo.go:57-62`, `store/db/postgres/memo.go:54-59`, `store/db/mysql/memo.go:65-70`), which runs the three-phase pipeline — `cel.Env.Compile` type-checks the expression against the memo schema, `buildCondition` normalizes the CEL AST into the IR, and `renderer.Render` walks the IR emitting a dialect-specific SQL fragment plus bound args that get AND-ed into the `WHERE` clause.

Dialect differences live entirely in `internal/filter/render.go` (switches on `DialectSQLite`/`DialectMySQL`/`DialectPostgres`): `?` vs `$n` placeholders, `json_extract`/`JSON_EXTRACT`/`->>` for `memo.payload`, tag containment via `LIKE` / `JSON_CONTAINS` / `@>`, `LIKE` vs `ILIKE`, `REGEXP` vs `~` (SQLite's `regexp` is a Go function registered in `store/db/sqlite/functions.go`), and `strftime` / date functions / `EXTRACT` for timestamp accessors. Server-side validation picks the dialect from `s.Profile.Driver` so a filter is rejected up front if it can't render for the active database.
