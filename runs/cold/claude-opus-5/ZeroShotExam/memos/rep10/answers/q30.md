Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

```
memos.memo.created: DispatchMemoCreatedWebhook
memos.memo.updated: DispatchMemoUpdatedWebhook
memos.memo.deleted: DispatchMemoDeletedWebhook
memos.memo.comment.created: DispatchMemoCommentCreatedWebhook
```

Delivery convergence: `webhook.PostAsync` → `webhook.Post` in `internal/webhook/webhook.go:184` / `internal/webhook/webhook.go:120`

Details:

- **Convergence in two steps.** The three plain lifecycle events are thin wrappers over the shared helper `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks via `s.Store.GetUserWebhooks`, stamps `payload.ActivityType`, and calls `webhook.PostAsync`. `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`) does *not* use that helper — it targets the *related memo owner* (`relatedMemoCreatorID`) rather than the comment's creator, so it builds the payload inline — but it still ends at the same `webhook.PostAsync` call (`memo_service_webhooks.go:43`).
- **Final delivery.** `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto the bounded `asyncPostQueue` (capacity 128, dropped with a warning when full); four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it into `webhook.Post` (`internal/webhook/webhook.go:120`), which does the HMAC-SHA256 Standard Webhooks signing and the actual POST through the SSRF-guarded `safeClient`.
