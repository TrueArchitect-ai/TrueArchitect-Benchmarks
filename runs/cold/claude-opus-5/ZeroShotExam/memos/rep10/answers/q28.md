**Runners the server actually starts** — all wiring is in `Server.startBackgroundRunners` (`server/server.go:153-174`), called from `Server.Start` (`server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — startup one-shot + fixed-interval `time.Ticker`. `RunOnce(ctx)` fires synchronously at boot (`server/server.go:163`), then a goroutine runs `Run(s3Context)`, which ticks every `runnerInterval = 12h` (`server/runner/s3presign/runner.go:27-41`). Each pass re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days. Shut down via its own `context.CancelFunc` + `WaitGroup` (`server/server.go:156-171`, `176-201`).

That is the **only** entry in `startBackgroundRunners`. Other long-lived goroutines exist but are not scheduled runners:

- **store cache cleanup loops ×3** (`store/cache/cache.go:76-85`, `199-213`) — implicitly started by `cache.New` inside `store.New` (`store/store.go:39-53`), one per cache (instance-setting, user, user-setting); ticker at `CleanupInterval = 5m`. Started by store construction, not by the server's runner wiring.
- **webhook dispatch pool** (`internal/webhook/webhook.go:42-55`) — 4 goroutines started in `init()`, driven by the `asyncPostQueue` channel (event-driven, not timed).
- **email send pool** (`internal/email/email.go:14-25`) — 2 goroutines started in `init()`, driven by `asyncEmailQueue` (event-driven).
- **SSE heartbeat ticker** (`server/router/api/v1/sse_handler.go:64`) — per-connection, lives for the request; not a background worker.

**Unused scheduling infrastructure:**

- **`internal/scheduler`** — a full cron scheduler (5/6-field parser, timezone support, middleware, graceful shutdown; `internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`, plus README/doc.go) is **not used by the server at all**. Its only importers in the repo are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`); no production file imports it. The s3presign runner uses a raw `time.Ticker` rather than this scheduler.
- **`server/runner/memopayload`** — despite living under `server/runner/`, its `Runner`/`NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:14-27`) are never instantiated or scheduled. Only the standalone `RebuildMemoPayload` function is used, and only synchronously inside request handlers (`server/router/api/v1/memo_service.go:108`, `:447`).
