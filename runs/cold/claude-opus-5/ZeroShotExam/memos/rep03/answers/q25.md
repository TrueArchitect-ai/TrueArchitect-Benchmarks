**Mechanism (one sentence):** `ListMemos` validates the filter up front via `s.validateFilter` (`server/router/api/v1/memo_service.go:211-215` → `shortcut_service.go:336`) and passes the raw string through `store.FindMemo.Filters`; each dialect store then calls `filter.DefaultEngine()` + `filter.AppendConditions(...)` (`store/db/sqlite/memo.go:57`, `store/db/mysql/memo.go:65`, `store/db/postgres/memo.go:54`), which runs the three-phase pipeline — `cel-go` compiles/type-checks the expression against the memo schema (`schema.go:89 NewSchema`), `parser.go` normalizes the AST into a dialect-agnostic IR (constant-folding `now`/`duration()`/`timestamp()` into epoch seconds), and `render.go` walks the IR emitting a dialect-specific `WHERE` fragment plus bound args that are appended to the query's existing `where`/`args`.

**Where dialect differences live:** all inside the renderer/schema —
- Placeholders: `$n` for Postgres vs `?` elsewhere, offset by pre-existing args (`render.go:842-849`, offset supplied by `helpers.go:12`).
- Column quoting: backticks for SQLite/MySQL, bare for Postgres (`render.go:919`).
- JSON/tag predicates: SQLite `LIKE`, MySQL `JSON_CONTAINS`, Postgres `@>`/`jsonb_build_array` (`render.go:451-471`, `501-512`).
- Timestamp part extraction, string length, case-insensitive match (`LIKE` vs `ILIKE`), and regex — per-dialect switches at `render.go:230-241`, `297`, `563-572`, `579+`.
- Per-field SQL templates keyed by dialect (`Field.Expressions` / `Field.columnExpr`, `schema.go:55`, `321-326`), e.g. `creator` rendering as `('users/' || …)` on SQLite/Postgres vs `CONCAT('users/', …)` on MySQL.

The same engine also serves shortcuts and user stats (`shortcut_service.go`, `user_service_stats.go:71`); attachments use a sibling schema via `DefaultAttachmentEngine` (`engine.go:119`).
