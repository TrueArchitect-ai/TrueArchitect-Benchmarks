**Runners the server actually starts — and what drives each**

- **S3 presign runner** (`server/runner/s3presign/runner.go`) — started in `server/server.go:153` (`startBackgroundRunners`): one synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a goroutine running `Run(s3Context)` driven by a plain `time.NewTicker(12h)` loop (`server/runner/s3presign/runner.go:27-41`). Trigger: fixed 12-hour interval + one-shot at boot; stopped by its own `context.CancelFunc` on `Shutdown` (`server/server.go:156-171`), waited on via `backgroundRunnerWG`.
- **Store cache cleanup loops ×3** (`store/cache/cache.go:83`, `cleanupLoop` at 199-213) — started implicitly by `cache.New` for `instanceSettingCache`, `userCache`, `userSettingCache` in `store.New` (`store/store.go:50-53`), which `cmd/memos/main.go:64` calls before the server is built. Trigger: `time.NewTicker(CleanupInterval)` = 5 minutes (`store/store.go:41-43`); stops on `Close()`.
- **Webhook async dispatch workers ×4** (`internal/webhook/webhook.go:42-54`) — spawned in the package's `init()`, so they start whenever the webhook package is linked in. Trigger: event-driven, not timed — they block on the `asyncPostQueue` channel (cap 128) fed by `webhook.PostAsync` from memo create/update/delete (`server/router/api/v1/memo_service_webhooks.go:43,71`).
- **HTTP serve goroutine** (`server/server.go:124`) — trigger: incoming connections; ends on `http.ErrServerClosed`.
- **Signal-handler goroutine** (`cmd/memos/main.go:99`) — trigger: SIGINT/SIGTERM → `s.Shutdown(ctx)`.

Per-request/per-connection goroutines (not global workers, listed for completeness): SSE heartbeat `time.NewTicker(30s)` per connected client (`server/router/api/v1/sse_handler.go:17,64`), and the fire-and-forget PAT last-used update per authenticated request (`server/auth/authenticator.go:178-184`).

**Unused scheduling infrastructure**

- `internal/scheduler` — a full cron scheduler (5/6-field parser, timezone support, middleware, graceful shutdown; `scheduler.go`, `parser.go`, `job.go`, `middleware.go`, `README.md`) is **never used by the server**. Grepping `internal/scheduler` across the repo yields only `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13` — no production importer. The one real periodic runner uses a raw `time.Ticker`, not this package.
- `server/runner/memopayload` — the `Runner`/`RunOnce` batch job (`server/runner/memopayload/runner.go:14-27`) is also never instantiated: `memopayload.NewRunner` has no callers, and only the package's inline `RebuildMemoPayload` helper is used, synchronously, from `server/router/api/v1/memo_service.go:108,447`.
