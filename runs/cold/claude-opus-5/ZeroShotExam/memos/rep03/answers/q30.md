**Events and dispatch functions** — all defined in `server/router/api/v1/memo_service_webhooks.go`:

**Convergence for delivery:**

The first three funnel through the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:47`), which resolves the memo creator and looks up their hooks. The comment event skips that helper (it targets the *related memo's* owner, not the comment creator's) and does its own `Store.GetUserWebhooks` lookup — but both paths build the same `webhook.WebhookRequestPayload` and call:

- `webhook.PostAsync` (`internal/webhook/webhook.go:191`) → enqueues onto the bounded `asyncPostQueue` (128 slots, drops with a warning when full) → drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:40`) → `webhook.Post` (`internal/webhook/webhook.go:117`), which does the actual HMAC-SHA256 signing and `POST` via the SSRF-guarded `safeClient`.

So the single convergence point for delivery is `internal/webhook/webhook.go`'s `Post`, reached asynchronously through `PostAsync`.
