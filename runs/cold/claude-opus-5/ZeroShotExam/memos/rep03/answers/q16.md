`store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) removes, in order, before deleting the memo row:

1. **Memo relation records where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relation records where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments{MemoID: &delete.ID}` and deleted one by one with `s.DeleteAttachment` (`store/memo.go:149-157`). Each of those also deletes the attachment's backing storage (local file or object-storage blob) before the attachment row — `store/attachment.go:132-149`.

Only after those does it call `s.driver.DeleteMemo`, which issues the plain `DELETE FROM memo WHERE id = ?` (e.g. `store/db/sqlite/memo.go:237`).

Note on scope: reactions and comment memos are *not* handled by the store layer. The API handler deletes child comment memos itself, by looking up `MemoRelationComment` relations and calling `store.DeleteMemo` on each (`server/router/api/v1/memo_service.go:566-577`); reactions are only read there for the webhook payload, not deleted.
