**`web/src/connect.ts`; JWT access token (in-memory + localStorage, `Authorization: Bearer`) + refresh token (HttpOnly `memos_refresh` cookie), with Personal Access Tokens as the programmatic alternative; `server/auth`**

**Frontend interceptor — `web/src/connect.ts:156`**
- `authInterceptor` is attached to the Connect-RPC transport (`web/src/connect.ts:184-189`) that backs every service client (memo, user, attachment, AI, etc.). The transport uses `fetch` with `credentials: "include"` (`connect.ts:57`) so the refresh cookie rides along.
- Per request it calls `getRequestToken()` (`connect.ts:124`) and sets `Authorization: Bearer <token>`. That does a *preflight* refresh when the access token is within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), and *reactively* on a `Code.Unauthenticated` response it refreshes once, marks the retry with an `X-Retry` header, and replays; if the refresh fails it calls `redirectOnAuthFailure()` (`connect.ts:161-177`).
- Refresh goes through a separate transport with no interceptors to avoid recursion (`connect.ts:64-72`) calling `AuthService.RefreshToken`, and is deduped by `tokenRefreshManager` (`connect.ts:30-51`, `89`).

**Token storage — `web/src/auth-state.ts`**
- Access token + expiry kept in module memory and mirrored to `localStorage` under `memos_access_token` / `memos_token_expires_at`; a `BroadcastChannel` (`memos_token_sync`) shares freshly refreshed tokens between tabs. `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus using a larger 2-minute buffer.
- The refresh token itself is never in JS — it's a server-set cookie.

**Backend validation — `server/auth/`**
- `server/auth/token.go` defines the token model: access tokens (JWT, 15 min, audience `user.access-token`), refresh tokens (JWT, 30 days, cookie `memos_refresh`), and PATs (prefix `memos_pat_`).
- `server/auth/authenticator.go` — `Authenticator.Authenticate` / `AuthenticateToUser` extract the bearer token (`server/auth/extract.go`), validate access tokens statelessly by signature (`AuthenticateByAccessTokenV2`), route `memos_pat_`-prefixed tokens to `AuthenticateByPAT` (recording last-used asynchronously), and fall back to the refresh cookie, which *is* checked against the DB for revocation (`AuthenticateByRefreshToken`).
- Consumers: `server/router/api/v1/connect_interceptors.go:222`, plus `server/router/api/v1/authz.go`, `sse_handler.go`, and `server/router/fileserver/fileserver.go`.
