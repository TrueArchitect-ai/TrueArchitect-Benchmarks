**Runners/workers actually running in a live server**

- **s3presign runner** — explicit `RunOnce(ctx)` once at startup, then a `time.Ticker` every 12 h (`runnerInterval = time.Hour * 12`) until its context is cancelled. Started in `server/server.go:153-174` (`startBackgroundRunners`), loop at `server/runner/s3presign/runner.go:29-41`. This is the **only** runner registered in `backgroundRunnerCancels` / `backgroundRunnerWG`, i.e. the only one the server's own lifecycle tracks.
- **HTTP serve goroutine** — started once at `Start()`; runs until `Shutdown` (`server/server.go:124-128`).
- **Store cache cleanup loops (×3)** — one goroutine per cache (`instanceSettingCache`, `userCache`, `userSettingCache`), spawned implicitly by `cache.New` at `store/cache/cache.go:83`; driven by a `time.Ticker` on `CleanupInterval = 5 * time.Minute` set in `store/store.go:40-53`. Stops only via `Cache.Close`.
- **Email send workers (×2)** — package `init()` goroutines at `internal/email/email.go:16-34`; queue-driven, not timed: they block on the 128-buffered `asyncEmailQueue`, fed by `SendAsync` (`internal/email/email.go:55`), used by `server/notification/email.go:30`.
- **Webhook dispatch workers (×4)** — package `init()` goroutines at `internal/webhook/webhook.go:42-55`; queue-driven off the 128-buffered `asyncPostQueue`, fed by `PostAsync` on memo create/update/delete events (`server/router/api/v1/memo_service_webhooks.go:43,71`).
- **Shutdown signal watcher** — one goroutine blocking on the SIGINT/SIGTERM channel (`cmd/memos/main.go:99-103`).

Request-scoped, not background workers, but goroutine/ticker-driven: the fire-and-forget PAT last-used update per authenticated PAT request (`server/auth/authenticator.go:179-184`) and the 30 s SSE heartbeat ticker inside each live SSE connection handler (`server/router/api/v1/sse_handler.go:64`).

**Unused scheduling infrastructure**

- **`internal/scheduler` is dead code as far as the server is concerned.** It's a complete cron scheduler — 5/6-field cron parser (`internal/scheduler/parser.go`), job registration and per-job goroutines (`internal/scheduler/scheduler.go:104-120`), timezone support, middleware chain with recovery/logging (`internal/scheduler/middleware.go`), docs (`internal/scheduler/doc.go`, `README.md`) — but grepping for `usememos/memos/internal/scheduler` yields **no non-test importers anywhere** in `cmd/`, `server/`, or `store/`. Its only consumers are its own `*_test.go` / `example_test.go` / `integration_test.go`. No cron expression drives any real job; the sole recurring server job (s3presign) uses a plain ticker instead.
- Minor related note: `server/runner/memopayload` sits under `server/runner/` but is **not** a background runner — `RebuildMemoPayload` is called synchronously from request handlers (`server/router/api/v1/memo_service.go:108,447`).
