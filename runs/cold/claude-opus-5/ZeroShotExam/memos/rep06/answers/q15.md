There's no ORM here — the structs live in the `store` package and are mapped to tables by hand-written SQL in the per-driver implementations (`store/db/{sqlite,postgres,mysql}/`).

| Table | Struct — path |
|---|---|
| `user` | `User` — `store/user.go:29` |
| `attachment` | `Attachment` — `store/attachment.go:16` |
| `reaction` | `Reaction` — `store/reaction.go:7` |

Supporting evidence for the table mapping (SQL that binds each struct to its table):
- `store/db/sqlite/user.go:17` (`INSERT INTO user ...`), `store/db/postgres/user.go:155` (`FROM "user"`), `store/db/mysql/user.go:18`
- `store/db/*/attachment.go` and `store/db/*/reaction.go` do the same for the other two; schemas are in `store/migration/{sqlite,postgres,mysql}/LATEST.sql`.

Note the `attachment` table was renamed from `resource` in 0.26 (`store/migration/*/0.26/00__rename_resource_to_attachment.sql`).
