**Mechanism:** Server-Sent Events (SSE) over a plain HTTP streaming endpoint — `GET /api/v1/sse`, `Content-Type: text/event-stream`, with `: heartbeat` comments every 30s and Bearer-token auth (`server/router/api/v1/sse_handler.go`). The browser side does not use `EventSource`; it uses `fetch` + a `ReadableStream` reader so it can send the `Authorization` header, with exponential-backoff reconnect (`web/src/hooks/useLiveMemoRefresh.ts`).

**Hub path:** `server/router/api/v1/sse_hub.go` — `SSEHub` (mutex-guarded `map[*SSEClient]struct{}`, 32-event buffered channel per client, drops events for slow clients). Constructed in `server/router/api/v1/v1.go:57` (`NewSSEHub()`), route registered at `v1.go:125` via `RegisterSSERoutes`, and closed on shutdown in `server/server.go:205`. Event types/payload and the visibility filter (`SSEClient.canReceive`: private events only to the creator or an admin) live in the same file; helper builders are in `server/router/api/v1/sse_event_helpers.go`.
