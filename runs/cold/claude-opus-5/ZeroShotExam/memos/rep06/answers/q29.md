**`web/src/connect.ts`; short-lived JWT access token (Bearer, in localStorage/in-memory) + long-lived refresh token (HttpOnly `memos_refresh` cookie), with Personal Access Tokens as an alternate Bearer credential; `server/auth`**

**Frontend — `web/src/connect.ts`**
- `authInterceptor` (`web/src/connect.ts:156`) is registered on the Connect-Web transport (`web/src/connect.ts:184-189`) that backs every service client (memo, user, attachment, auth, etc.). It:
  - calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`web/src/connect.ts:97`);
  - proactively refreshes when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry;
  - reactively retries once on `Code.Unauthenticated`, tagging the retry with an `X-Retry` header, then calls `redirectOnAuthFailure()` if the refresh fails (`web/src/connect.ts:163-177`).
- Refresh goes through a *separate* transport with no interceptors to avoid recursion (`web/src/connect.ts:65-83`), calling `AuthService.RefreshToken`; concurrent refreshes are deduped by `tokenRefreshManager` (`web/src/connect.ts:30-51`). `fetch` uses `credentials: "include"` so the refresh cookie rides along.
- Token storage lives in `web/src/auth-state.ts`: access token + expiry in `localStorage` under `memos_access_token` / `memos_token_expires_at`, synced across tabs via a `memos_token_sync` BroadcastChannel. `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes on tab focus using the larger 2-minute buffer.

**Backend — `server/auth`**
- `server/auth/token.go` defines the token kinds: access token (15 min, audience `user.access-token`), refresh token (30 days, audience `user.refresh-token`, cookie `memos_refresh`), and PATs prefixed `memos_pat_`.
- `server/auth/authenticator.go` validates them: `AuthenticateByAccessTokenV2` (stateless JWT parse), `AuthenticateByRefreshToken` (JWT + DB revocation check), and `AuthenticateByPAT`; `server/auth/extract.go` pulls the bearer token from the header and the refresh token from the cookie.
- Consumers: `server/router/api/v1/authz.go:36` (`Authorizer`, shared by the Connect interceptor and gRPC-Gateway middleware, which also decides public vs. protected procedures), `server/router/fileserver/fileserver.go:115`, `server/router/api/v1/sse_handler.go:26`, and `server/router/api/v1/auth_service_session.go` for the refresh/session flow.
