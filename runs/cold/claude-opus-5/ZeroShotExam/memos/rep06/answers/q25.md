**Engine + path:** Google CEL (`github.com/google/cel-go` v0.28.1, `go.mod:13`), wrapped by the in-repo memo filter engine at `internal/filter/` — `engine.go` (entry point `filter.DefaultEngine()` / `Compile` / `CompileToStatement`), `schema.go` (CEL env + field metadata), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL), `helpers.go` (store glue).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-216`) validates the CEL string via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`) and pushes it into `store.FindMemo.Filters`; each store driver then calls `filter.DefaultEngine()` + `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect{SQLite,MySQL,Postgres}, &where, &args)` (`store/db/sqlite/memo.go:57-62`, `store/db/mysql/memo.go:65-70`, `store/db/postgres/memo.go:54-59`), which compiles the CEL AST into the IR and lets `render.go`'s dialect-aware renderer emit a parameterized `WHERE` fragment plus args appended to the query.

Details worth knowing:

- **Three-phase pipeline** (documented in `internal/filter/README.md`): parse/type-check with cel-go against the memo-specific env (`schema.NewSchema()`, so only declared fields like `content`, `creator_id`, `created_ts`, `tags`, `visibility`, `pinned`, `has_task_list` are allowed) → normalize to IR (`buildCondition` in `parser.go`, enforcing operator/type rules) → render to SQL.
- **Dialect handling lives entirely in `render.go`**: placeholders (`?` for SQLite/MySQL vs `$n` for Postgres, with `RenderOptions.PlaceholderOffset` so fragments compose with pre-existing args), JSON access (`json_extract` vs `JSON_EXTRACT` vs `->`/`->>`), tag membership (SQLite `LIKE`, MySQL `JSON_CONTAINS`, Postgres `@>` — `renderTagInList` at `render.go:434`), `LIKE` vs `ILIKE`, and regex (`~` on Postgres vs `REGEXP` on MySQL/SQLite, `render.go:558`).
- **Timestamps** (`now`, `duration(...)`, `timestamp(...)`) are constant-folded to epoch seconds at compile time, with `now` frozen once per `Compile` via the engine's injectable `nowFunc` (`engine.go:17-22`).
- The same engine also serves attachments (`filter.DefaultAttachmentEngine()`) and memo-relation subqueries, which call `engine.CompileToStatement` directly instead of `AppendConditions`.
