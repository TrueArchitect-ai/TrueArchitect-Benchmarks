**Convergence for delivery:**

The first three are thin wrappers over the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks, and builds a payload per hook. The comment-created one bypasses that helper (it targets the *related* memo's owner rather than the comment creator) and builds its payload inline.

All four converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload onto the bounded `asyncPostQueue` (capacity 128, dropped with a warning if full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `webhook.Post` (`internal/webhook/webhook.go:120`), which does the actual HTTP POST — JSON marshal, optional Standard Webhooks HMAC-SHA256 signing (`webhook-id`/`webhook-timestamp`/`webhook-signature` headers), and the request via the SSRF-guarded `safeClient`.
