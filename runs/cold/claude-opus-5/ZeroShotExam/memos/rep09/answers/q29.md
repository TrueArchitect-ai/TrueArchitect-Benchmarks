**`web/src/connect.ts` (the `authInterceptor`, wired into the Connect transport); JWT access token (localStorage, 15 min) + `memos_refresh` refresh-token cookie (HTTP-only, 30 days) — plus Personal Access Tokens as an alternate bearer credential; `server/auth`**

How it works:

**Frontend interceptor — `web/src/connect.ts:145`**
- `authInterceptor` is passed to `createConnectTransport` (`web/src/connect.ts:170`) and applies to every Connect RPC client exported from that file (memo, user, auth, attachment, etc.).
- On each request it calls `getRequestToken()`, which does a *preflight* refresh if the access token is within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), then sets `Authorization: Bearer <token>`.
- On a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry: true` marker to prevent loops, and calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`) if the refresh fails.
- Refreshes go through a separate transport with **no** interceptors (`web/src/connect.ts:60`) to avoid recursion, using `credentials: "include"` so the refresh cookie is sent; concurrent refreshes are deduped by `tokenRefreshManager`.

**Token storage — `web/src/auth-state.ts`**
- Access token + expiry in `localStorage` under `memos_access_token` / `memos_token_expires_at`, mirrored in memory.
- A `BroadcastChannel` (`memos_token_sync`) shares freshly refreshed tokens across tabs so only one tab hits the refresh endpoint.
- `web/src/hooks/useTokenRefreshOnFocus.ts` proactively refreshes on tab focus using the larger 2-minute buffer.

**Backend validation — `server/auth`**
- `server/auth/token.go` defines the JWT scheme: issuer `memos`, audiences `user.access-token` / `user.refresh-token`, 15 min access / 30 day refresh lifetimes, cookie name `memos_refresh`, and the `memos_pat_` PAT prefix.
- `server/auth/authenticator.go` validates them: `AuthenticateByAccessTokenV2` (stateless signature check), `AuthenticateByPAT`, and `AuthenticateByRefreshToken` (parses the JWT *and* checks the DB for revocation via `GetUserRefreshTokenByID`).
- Consumers: the Connect/gRPC interceptors in `server/router/api/v1/` (with public methods listed in `server/router/api/v1/acl_config.go`), the refresh/session flow in `server/router/api/v1/auth_service_session.go`, and `server/router/fileserver/`.
