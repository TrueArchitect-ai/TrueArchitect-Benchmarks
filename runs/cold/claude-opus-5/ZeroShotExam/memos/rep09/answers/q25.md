**Engine: Google CEL (`github.com/google/cel-go` v0.28.1), wrapped by the in-repo filter engine at `internal/filter/`** — `engine.go` (`Engine`, `DefaultEngine()`), `schema.go`, `parser.go`, `ir.go`, `render.go`, `helpers.go`. Docs: `internal/filter/README.md`.

**Mechanism (one sentence):** `ListMemos` passes `request.Filter` through `validateFilter` (`server/router/api/v1/shortcut_service.go:336`) into `store.FindMemo.Filters`, and each driver's `ListMemos` calls `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect{SQLite,MySQL,Postgres}, &where, &args)` — a three-phase pipeline that (1) compiles the CEL string against a memo-specific CEL env of declared variables (`content`, `tag`, `tags`, `visibility`, `pinned`, `created_ts`, `has_task_list`, …, plus `now`) in `schema.go:232`, (2) normalizes the CEL AST into a dialect-agnostic IR condition tree in `parser.go`/`ir.go` (folding `now`/`duration()`/`timestamp()` to epoch constants at compile time), and (3) walks that IR in `render.go` to emit a dialect-specific `WHERE` fragment plus bound args.

Details worth noting:

- Entry points: `server/router/api/v1/memo_service.go:211-215` (validate + append filter; also appends a synthesized visibility filter at line 223); store call sites `store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo.go:65-69`, `store/db/postgres/memo.go:54-58`.
- Dialect differences live entirely in the renderer + `Field.Expressions` map (`internal/filter/schema.go`):
  - Placeholders: `$n` for Postgres, `?` for SQLite/MySQL, with `PlaceholderOffset` so fragments compose with pre-existing args (`render.go:842`).
  - Tags/JSON arrays: SQLite `LIKE '%"tag"%'`, MySQL `JSON_CONTAINS`, Postgres `@> jsonb_build_array(...)` (`render.go:451-512`).
  - JSON booleans (`has_task_list` etc.) via `json_extract` / `JSON_EXTRACT` / `->`,`->>` + `IS TRUE` coercion (`render.go:363-408`).
  - Per-field SQL templates, e.g. `creator` → `('users/' || %s)` on SQLite/Postgres vs `CONCAT('users/', %s)` on MySQL (`schema.go:99-107`); attachment `create_time` → `UNIX_TIMESTAMP(%s)` on MySQL only.
  - Other per-dialect bits: `ILIKE` vs `LIKE`/`LOWER` for case-insensitive match (`render.go:579`), regex operator (`render.go:563`), `CHAR_LENGTH` vs `LENGTH` (`render.go:297`), timestamp part extraction (`render.go:219-241`).
- Constant folding shortcuts: an always-true filter renders to empty SQL (skipped), always-false renders to `1 = 0` (`render.go:32-57`).
- The same engine serves attachments via a separate schema (`NewAttachmentSchema` / `DefaultAttachmentEngine`); user filters use a separate, simpler CEL path in `server/router/api/v1/user_service_filter.go`.
