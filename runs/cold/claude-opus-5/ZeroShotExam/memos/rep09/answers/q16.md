`Store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) cleans up two kinds of records before calling `s.driver.DeleteMemo`:

1. **Memo relation rows** — deleted in two passes: once with `MemoID = <memo>` (relations where this memo is the source) and once with `RelatedMemoID = <memo>` (relations where it is the target), via `driver.DeleteMemoRelation` (`store/memo.go:141-147`, type defined in `store/memo_relation.go:37`).
2. **Attachments linked to the memo** — listed with `FindAttachment{MemoID: ...}` and removed one by one with `Store.DeleteAttachment` (`store/memo.go:148-157`). That call also removes the attachment's backing blob/file first via `DeleteAttachmentStorage` before deleting the attachment row (`store/attachment.go:132-149`).

Only then does it delete the memo row itself (`store/memo.go:158`).

Two related notes on scope: reactions and memo shares are *not* deleted by the store layer here. And comment memos are removed at the API layer before the store call — `APIV1Service.DeleteMemo` lists `MemoRelationComment` relations and calls `Store.DeleteMemo` on each comment first (`/bench/repo/server/router/api/v1/memo_service.go:567-581`).
