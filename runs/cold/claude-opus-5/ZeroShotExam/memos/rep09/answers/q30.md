Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

```
memos.memo.created: DispatchMemoCreatedWebhook          (memo_service_webhooks.go:15)
memos.memo.updated: DispatchMemoUpdatedWebhook          (memo_service_webhooks.go:20)
memos.memo.deleted: DispatchMemoDeletedWebhook          (memo_service_webhooks.go:25)
memos.memo.comment.created: DispatchMemoCommentCreatedWebhook (memo_service_webhooks.go:30)
```

Convergence for delivery:

- The three plain lifecycle events are thin wrappers over the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks, and builds a payload via `convertMemoToWebhookPayload`. `DispatchMemoCommentCreatedWebhook` bypasses that helper (it targets the *related* memo's owner, not the comment creator) but builds the same payload inline.
- All four then call `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue` (128 slots, drops with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`) drain the queue and call `webhook.Post` (`internal/webhook/webhook.go:120`) — the single place the HTTP POST, HMAC-SHA256 Standard Webhooks signing, and SSRF-guarded `safeClient` delivery actually happen.

Call sites: `memo_service.go:157` (create), `memo_update_helpers.go:67` (update), `memo_service.go:562` (delete), `memo_service_comments.go:119` (comment created).
