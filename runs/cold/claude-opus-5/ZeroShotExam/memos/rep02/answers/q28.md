**Other long-lived goroutines the process runs, started implicitly rather than by the runner wiring:**

- HTTP serve loop (`server/server.go:124-128`) — one goroutine per `Start`, driven by incoming connections
- 3× store cache cleanup loops (`instanceSettingCache`, `userCache`, `userSettingCache`) — `cache.New` unconditionally spawns `cleanupLoop` (`store/cache/cache.go:82`, `store/store.go:39-53`); `time.NewTicker(CleanupInterval)` = 5 min, stops on `Close()`
- Webhook async dispatch pool, 4 workers (`internal/webhook/webhook.go:42-55`) — started in package `init()`, driven by the `asyncPostQueue` channel (buffer 128), not by a timer
- Email async send pool, 2 workers (`internal/email/email.go:16-34`) — package `init()`, driven by `asyncEmailQueue` channel (buffer 128)
- SSE heartbeat (`server/router/api/v1/sse_handler.go:64`) — per-connection ticker at 30s, lives as long as the client stream
- PAT last-used writes (`server/auth/authenticator.go:178-184`) — fire-and-forget goroutine per authenticated PAT request, not a pooled worker

**Unused scheduling infrastructure:**

- `internal/scheduler/` is a full cron scheduler (5/6-field cron parsing, timezone support, middleware chain, graceful stop — `internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`, `doc.go`) and it is **never used by the server**. The only importers are its own tests (`internal/scheduler/example_test.go`, `integration_test.go`); no production file references it. The one real periodic job in the server (s3presign) uses a hand-rolled `time.Ticker` instead. Note also that `AGENTS.md` claims `internal/` contains a `cron` package — no such directory exists.
- `server/runner/memopayload` is also dead as a *runner*: `memopayload.NewRunner` / `Runner.RunOnce` (`server/runner/memopayload/runner.go:19,27`) have no callers. Only the standalone helper `RebuildMemoPayload` is used, inline on the request path in `server/router/api/v1/memo_service.go:108,447`.
