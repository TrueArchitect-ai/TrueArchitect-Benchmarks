**Server-Sent Events (SSE) over `GET /api/v1/sse`; `/bench/repo/server/router/api/v1/sse_hub.go`; CreateMemo, DeleteMemo, CreateMemoComment, UpsertMemoReaction, DeleteMemoReaction, and (via `dispatchMemoUpdatedSideEffects`) UpdateMemo / SetMemoAttachments / SetMemoRelations**

**Mechanism.** SSE, not WebSockets. `SSEHub` (`sse_hub.go:56`) keeps a set of subscribed clients with `Subscribe`/`Unsubscribe`/`Broadcast`/`Close` (lines 71, 89, 115, 99), and per-client filtering via `canReceive` (line 134) using the event's `Visibility` and `CreatorID`, which are marshal-excluded. Event types are `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted` (lines 14-21). The HTTP endpoint is registered by `RegisterSSERoutes` in `/bench/repo/server/router/api/v1/sse_handler.go:25` (Bearer-token authenticated), wired up from `/bench/repo/server/router/api/v1/v1.go`.

**Broadcasting handlers** (all `APIV1Service` methods):
- `CreateMemo` — `/bench/repo/server/router/api/v1/memo_service.go:163`
- `DeleteMemo` — `memo_service.go:585`
- `CreateMemoComment` — `/bench/repo/server/router/api/v1/memo_service_comments.go:126`
- `UpsertMemoReaction` — `/bench/repo/server/router/api/v1/reaction_service.go:106`
- `DeleteMemoReaction` — `reaction_service.go:161`
- `dispatchMemoUpdatedSideEffects` — `/bench/repo/server/router/api/v1/memo_update_helpers.go:71`, the shared `memo.updated` broadcast called from `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`)

Note that `CreateMemoComment` suppresses the inner `CreateMemo` broadcast (`withSuppressSSE`) so a comment emits only the `memo.comment.created` event.
