**Google CEL (cel-go) via the in-repo `internal/filter` engine — `/bench/repo/internal/filter/` (`engine.go`, `schema.go`, `ir.go`, `render.go`, `helpers.go`)**

**Mechanism:** `Engine.Compile` (`/bench/repo/internal/filter/engine.go:47`) type-checks the CEL expression against a per-resource schema of declared variables (`content`, `tag`, `pinned`, `visibility`, `created_ts`, `has_link`, … — `/bench/repo/internal/filter/schema.go:232`) and lowers it into a dialect-agnostic condition tree (`ir.go`), which the renderer (`render.go`) then emits as a parameterized SQL `WHERE` fragment plus args, substituting per-dialect column expressions from each field's `Expressions` map keyed by `DialectSQLite`/`DialectMySQL`/`DialectPostgres` (e.g. `('users/' || %s)` vs `CONCAT('users/', %s)`, `schema.go:104-107`) and dialect-appropriate placeholders.

Each driver calls it the same way: `filter.DefaultEngine()` then `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args)` — `/bench/repo/store/db/sqlite/memo.go:57-61`, with the postgres/mysql equivalents in `store/db/postgres/memo.go` and `store/db/mysql/memo.go` passing their own `DialectName`. The filter string reaches the store as `FindMemo.Filters` (`/bench/repo/store/memo.go:72`), populated by the handler-side helper `/bench/repo/server/router/api/v1/memo_service_filter.go`. Background notes live in `/bench/repo/internal/filter/README.md` and `MAINTENANCE.md`.
