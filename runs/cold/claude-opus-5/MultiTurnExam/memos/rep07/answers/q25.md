**CEL (Google Common Expression Language), parsed with `cel-go`; engine in `internal/filter/` — entry point `filter.DefaultEngine()` at `internal/filter/engine.go`**

**Mechanism:** each dialect driver's `ListMemos` calls `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` — `store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69` — which runs the engine's three-phase pipeline (CEL parse + schema validation in `internal/filter/parser.go` against the field declarations in `internal/filter/schema.go` → dialect-agnostic IR in `internal/filter/ir.go` → dialect-specific rendering in `internal/filter/render.go`) and appends the resulting SQL fragment and bound arguments to the query the driver is building.

The renderer is where the dialects diverge (`internal/filter/render.go`): `?` placeholders for SQLite/MySQL vs `$n` for Postgres, `json_extract`/`JSON_EXTRACT` vs `->`/`->>` for the `memo.payload` JSON column, `LIKE` vs `ILIKE`, and tag membership as `LIKE` patterns (SQLite) / `JSON_CONTAINS` (MySQL) / `@>` (Postgres). Background and the file-by-file responsibilities are documented in `internal/filter/README.md`.
