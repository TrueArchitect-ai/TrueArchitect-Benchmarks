**Runners actually started**

s3presign runner — `RunOnce` at startup, then a `time.Ticker` on a 12-hour interval
SSE heartbeat (per connection) — a `time.Ticker` per subscribed client, not a global worker

**Unused infrastructure note:** the `internal/scheduler` cron package is not wired into the server at all.

Details:

- **s3presign** is the only true background runner. `startBackgroundRunners` constructs it and calls `RunOnce(ctx)` synchronously, then launches `Run(s3Context)` in a goroutine — `server/server.go:153-173`. `Run` drives a `time.NewTicker(runnerInterval)` with `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27-30`); each tick calls `CheckAndPresign` (`:47`), which re-signs S3 objects whose last presign is older than 4 days (`:88`). It gets its own cancelable context and a `WaitGroup` slot so shutdown is graceful (`server/server.go:176-199`).

- **SSE heartbeat** is per-connection rather than a server-wide worker: `time.NewTicker(sseHeartbeatInterval)` inside the streaming handler at `server/router/api/v1/sse_handler.go:64`, keeping each open SSE response alive.

- **`server/runner/memopayload`** exists and defines `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19`, `:27`), but nothing constructs it — `s3presign.NewRunner` at `server/server.go:162` is the only `NewRunner` call in the tree. Only the package-level helper `memopayload.RebuildMemoPayload` (`:74`) is used, called inline from the API handlers at `server/router/api/v1/memo_service.go:108` and `:447`. So the payload rebuild happens synchronously on memo create/update, not on a schedule.

- **`internal/scheduler`** is a complete cron-job framework — parser, jobs, middleware, docs (`internal/scheduler/README.md`) — with zero importers outside its own package and tests. No production code registers a job with it.

Other goroutines in the codebase are fire-and-forget per-event work, not scheduled runners: async webhook POSTs (`internal/webhook/webhook.go:44`), async email sends (`internal/email/email.go:18`), and the PAT last-used timestamp update (`server/auth/authenticator.go:180`).
