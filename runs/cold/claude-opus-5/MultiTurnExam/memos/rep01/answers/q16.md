Before deleting the memo row, `Store.DeleteMemo` (`store/memo.go:140-159`) removes:

1. **memo_relation records where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **memo_relation records where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **attachments linked to the memo** — listed via `FindAttachment{MemoID:...}` and deleted one by one (`store/memo.go:149-157`)

Only then does it call `s.driver.DeleteMemo(ctx, delete)` (`store/memo.go:158`) to remove the memo row itself.

One level up, the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) additionally deletes **comment memos** first — it lists `memo_relation` rows of type `MemoRelationComment` pointing at this memo and calls `Store.DeleteMemo` on each (`memo_service.go:567-577`), so each comment goes through the same relation/attachment cleanup. Reactions and relations are only *read* there to build the webhook payload; the handler does not delete reaction rows.
