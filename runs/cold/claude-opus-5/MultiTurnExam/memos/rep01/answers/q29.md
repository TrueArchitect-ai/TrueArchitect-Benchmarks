**web/src/connect.ts; JWT access token (Bearer, 15 min) + refresh token (HttpOnly cookie, 30 days) — PATs also accepted server-side; server/auth**

- **Interceptor:** `authInterceptor` at `web/src/connect.ts:156` — attaches `Authorization: Bearer <token>` to every Connect request, and on a `Code.Unauthenticated` response refreshes once, retries with an `X-Retry` marker, and redirects to login if the refresh fails (`:163-177`). It's installed on the shared transport at `:188`.

- **Tokens it manages:**
  - *Access token* — short-lived JWT held in `web/src/auth-state.ts` (in-memory + `localStorage`, cross-tab sync via `BroadcastChannel`). `getRequestToken` (`web/src/connect.ts:124`) proactively refreshes when it's within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` of expiry so public endpoints don't silently degrade to anonymous.
  - *Refresh token* — never touched by JS; it rides as an HttpOnly cookie because every request uses `credentials: "include"` (`web/src/connect.ts:57-62`). Refresh goes through a separate interceptor-free transport and `refreshAuthClient` (`:65-72`) calling `AuthService.RefreshToken`, deduplicated by `tokenRefreshManager` (`:30-51`).

- **Backend validation:** `server/auth` — `Authenticator` in `server/auth/authenticator.go` (`AuthenticateByAccessTokenV2` `:41`, `AuthenticateByRefreshToken` `:61`, `AuthenticateByPAT` `:102`, `Authenticate` `:213`); JWT signing/claims and the `AccessTokenDuration = 15m` / `RefreshTokenDuration = 30d` / `RefreshTokenCookieName` constants in `server/auth/token.go:35-48`; header/cookie parsing in `server/auth/extract.go`; context plumbing in `server/auth/context.go`. It's hooked into the Connect path via `NewAuthInterceptor` (`server/router/api/v1/v1.go:134`) and into the REST gateway via the `gatewayAuthMiddleware` at `server/router/api/v1/v1.go:85-95`.
