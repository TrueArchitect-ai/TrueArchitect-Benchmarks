**Mechanism:** Server-Sent Events (SSE) over `GET /api/v1/sse`
**Hub path:** `server/router/api/v1/sse_hub.go`
**Handlers that broadcast:** `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoRelations`, `SetMemoAttachments`, `UpsertMemoReaction`, `DeleteMemoReaction`

Details:

- The hub is `SSEHub` (`server/router/api/v1/sse_hub.go:56`) with `Subscribe`/`Unsubscribe`/`Broadcast`/`Close` (lines 71, 89, 115, 99) and the event types `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted` (lines 14-21). `Broadcast` filters per subscriber using the event's `Visibility`/`CreatorID`. The HTTP endpoint is registered by `RegisterSSERoutes` in `server/router/api/v1/sse_handler.go:25` (mounted from `server/router/api/v1/v1.go:125`), authenticated by Bearer token.
- Direct `SSEHub.Broadcast` call sites: `CreateMemo` (`memo_service.go:163`), `DeleteMemo` (`memo_service.go:585`), `CreateMemoComment` (`memo_service_comments.go:126`), `UpsertMemoReaction` (`reaction_service.go:106`), `DeleteMemoReaction` (`reaction_service.go:161`).
- `UpdateMemo` (`memo_service.go:401`), `SetMemoRelations` (`memo_relation_service.go:16`), and `SetMemoAttachments` (`memo_attachment_service.go:16`) broadcast indirectly via the shared helper `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`, broadcast at line 71).

Note that `CreateMemo` can be called with SSE suppressed — `CreateMemoComment` wraps it in `withSuppressSSE` so the parent's `memo.comment.created` event fires instead of a generic `memo.created` (`memo_service_comments.go:56`); helpers for building these events live in `server/router/api/v1/sse_event_helpers.go`.
