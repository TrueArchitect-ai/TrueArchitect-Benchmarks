```
s3presign runner — one immediate RunOnce at startup, then a time.Ticker every 12h in its own goroutine (canceled via per-runner context on shutdown)
```

That is the only background runner the server starts. `Server.startBackgroundRunners` (`server/server.go:153-172`) constructs `s3presign.NewRunner(s.Store)`, calls `RunOnce(ctx)` synchronously, then spawns `Run(s3Context)` in a goroutine tracked by a `WaitGroup`. `Run` is a plain `time.Ticker` loop (`server/runner/s3presign/runner.go:29-41`) with `runnerInterval = 12h` (:27); its work is re-presigning expiring S3 attachment URLs (`CheckAndPresign`, :47). Shutdown cancels the context and waits (`server/server.go:174-198`).

**Unused scheduling infrastructure — two pieces:**

- **`internal/scheduler/`** — a full GitHub-Actions-style cron scheduler (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`, plus `README.md`/`doc.go`). `scheduler.New(` has zero call sites outside the package's own tests and doc examples, so nothing in the running server uses it.
- **`server/runner/memopayload`** — `NewRunner` (`server/runner/memopayload/runner.go:19`) and its `RunOnce` (:27) are never called anywhere; only the standalone helper `RebuildMemoPayload` (:74) is used, and that's called inline from the request path in `server/router/api/v1/memo_service.go:108` and `:447`, not from any background loop.

For completeness, other long-lived goroutines exist but aren't runners: the HTTP serve loop (`server/server.go:124`) and the SSE hub's per-client connections (`server/router/api/v1/sse_hub.go`), closed via `closeLongLivedConnections` at shutdown.
