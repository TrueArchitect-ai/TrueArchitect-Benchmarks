```
s3presign — one immediate RunOnce at startup, then a 12-hour time.Ticker in its own goroutine
```

That is the only background runner the server starts. `startBackgroundRunners` (`server/server.go:154`) creates the runner via `s3presign.NewRunner(s.Store)`, calls `RunOnce(ctx)` synchronously, then launches `Run(s3Context)` in a tracked goroutine. The interval is `runnerInterval = time.Hour * 12` at `server/runner/s3presign/runner.go:27`, driving a `time.NewTicker` loop (line 30) that exits on `ctx.Done()`. Shutdown cancels the per-runner context and waits on the `WaitGroup` (`server/server.go:171`, `:181`).

**Unused-infra note:** `server/runner/memopayload/` sits under the same `runner` tree but is **not** a scheduled runner — nothing starts it. It's a plain helper invoked inline from the request path: `memopayload.RebuildMemoPayload` at `server/router/api/v1/memo_service.go:108` (create) and `:447` (update). Its placement under `server/runner/` makes it look like a periodic job it never was; there is no ticker, goroutine, or backfill sweep for it.

Two adjacent long-lived components are also started but aren't runners in this sense: the HTTP server goroutine (`server/server.go:124`) and the SSE hub, whose per-client goroutines are created on connection and torn down via `sseHub.Close()` (`server/server.go:198`).
