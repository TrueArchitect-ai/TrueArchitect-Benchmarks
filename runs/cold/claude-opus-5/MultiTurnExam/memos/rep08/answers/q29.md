**web/src/connect.ts; short-lived JWT access tokens + long-lived refresh tokens (httpOnly cookie), with Personal Access Tokens as an alternative bearer credential; server/auth**

**Interceptor.** `authInterceptor` at `web/src/connect.ts:156`, attached to the shared Connect transport (line 188). Per request it calls `getRequestToken()` and sets `Authorization: Bearer <token>`. On a `Code.Unauthenticated` response it refreshes once, re-sends with an `X-Retry: true` marker to prevent loops, and on failure calls `redirectOnAuthFailure()` (lines 161-177). Transports use `fetch` with `credentials: "include"` (`fetchWithCredentials`, line 57) so the refresh cookie rides along.

**Tokens.**
- *Access token* — JWT, 15-minute lifetime (`AccessTokenDuration`, `server/auth/token.go:40`), audience `user.access-token`. Held only in memory on the client via `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken`). Refreshed proactively when within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`, line 18) and on tab focus at 2 min (`FOCUS_TOKEN_EXPIRY_BUFFER_MS`).
- *Refresh token* — 30-day lifetime (`server/auth/token.go:43`), audience `user.refresh-token`, delivered as the `memos_refresh` cookie (line 49). Exchanged by `refreshAuthClient.refreshToken({})` (`web/src/connect.ts:75`) over a **separate interceptor-free transport** (line 65) so refresh can't recurse into the 401 path; concurrent refreshes are deduplicated by `tokenRefreshManager` (line 51) to avoid racing server-side token rotation.
- *Personal Access Token* — prefix `memos_pat_` (`server/auth/token.go:52`), for programmatic clients rather than the web app.

**Backend validation.** `server/auth` — `Authenticator` in `server/auth/authenticator.go` dispatches by credential type: `AuthenticateByAccessTokenV2` (line 41), `AuthenticateByRefreshToken` (61), `AuthenticateByPAT` (102), with `resolveBearer` (149) picking between JWT and PAT and `AuthenticateToUser` (190) handling header+cookie. Cookie parsing is in `server/auth/extract.go`, context plumbing in `server/auth/context.go`. It's applied to REST traffic through `gatewayAuthMiddleware` in `server/router/api/v1/v1.go` and to Connect traffic via the handler options in `server/router/api/v1/connect_handler.go`.
