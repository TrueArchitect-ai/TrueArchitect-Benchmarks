**web/src/connect.ts (`authInterceptor`, line 156); short-lived JWT access tokens + long-lived refresh-token cookie (plus PATs on the backend); server/auth**

How it works:

- **Interceptor** — `authInterceptor` in `web/src/connect.ts:156-178` is attached to the Connect transport (:184-189). On every request it fetches a token via `getRequestToken()` and sets `Authorization: Bearer <token>`. On a `Code.Unauthenticated` response it refreshes once, re-sends with an `X-Retry` marker to prevent loops, and on failure calls `redirectOnAuthFailure()`.
- **Access token** — a JWT held in `localStorage` with its expiry (`web/src/auth-state.ts:52-95`). `getRequestToken` (`connect.ts:124-150`) also refreshes *preemptively* when the token is within 30s of expiry, so public endpoints like ListMemos don't silently return guest-scoped data.
- **Refresh token** — an HTTP-only cookie named `memos_refresh` (`server/auth/token.go:48-49`), 30-day lifetime (:42-43), audience `user.refresh-token` (:45-46). The frontend never reads it; it calls `authServiceClient.refreshToken({})` over a *separate* interceptor-free transport with `credentials: "include"` to avoid recursion (`connect.ts:57-83`), and concurrent refreshes are deduped by `tokenRefreshManager` (:30-51, :89-91).
- **Backend validation** — package **`server/auth`**: `Authenticator.Authenticate` / `resolveBearer` (`server/auth/authenticator.go:149`, :213) accept either an Access Token V2 or a **Personal Access Token**; `AuthenticateByRefreshToken` (:61) handles the cookie path. Token generation/parsing lives in `server/auth/token.go`, bearer extraction in `server/auth/extract.go`. Refresh tokens are also recorded server-side per user (`s.Store.AddUserRefreshToken`, `server/router/api/v1/auth_service_session.go:40`) enabling rotation/revocation.

The authenticator is invoked on the Connect path via the interceptors in `server/router/api/v1/connect_interceptors.go`, on the REST path via the gateway middleware in `server/router/api/v1/v1.go:69-97`, and for SSE in `server/router/api/v1/sse_handler.go:34-37`.
