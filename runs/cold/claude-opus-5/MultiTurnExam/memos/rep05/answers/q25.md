**Engine:** CEL (Common Expression Language) via `cel-go` — `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go:25`, which builds a `cel.NewEnv` from the memo schema).

**Mechanism:** A three-phase pipeline — `parser.go` converts the CEL AST into a dialect-agnostic IR (`ir.go`) validated against the memo field schema (`schema.go`), then `render.go` walks that IR to emit a dialect-specific SQL fragment plus placeholder args, which each driver splices into its `WHERE` clause via `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect…, &where, &args)` (e.g. `store/db/sqlite/memo.go:57-61`, with `DialectPostgres`/`DialectMySQL` equivalents in the postgres and mysql drivers).

Dialect differences handled in the renderer: `?` vs `$n` placeholders, `LIKE` vs `ILIKE`, JSON access (`json_extract` vs `->>`), and tag membership (`LIKE` patterns for SQLite, `JSON_CONTAINS` for MySQL, `@>` for Postgres) — documented in `internal/filter/README.md`. The API-side plumbing that passes user filters down is in `server/router/api/v1/memo_service_filter.go`, and the RPC field is `ListMemosRequest.filter` in `proto/api/v1/memo_service.proto`.
