**Convergence.** The first three funnel through the unexported helper `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator and loads their hooks; `DispatchMemoCommentCreatedWebhook` does the same lookup itself but against the *parent* memo's creator, since the notification targets the memo owner rather than the commenter. Both then build a payload via `convertMemoToWebhookPayload` and call `webhook.PostAsync(payload)`.

That is the single delivery point: `PostAsync` (`/bench/repo/internal/webhook/webhook.go:184`) enqueues onto a 128-slot channel drained by 4 worker goroutines started in `init()` (line 42), which invoke `Post` (line 119) — JSON body, HMAC-SHA256 Standard Webhooks signature headers, `safeClient` HTTP POST.

Note the separate `CreateUserWebhook` / `UpdateUserWebhook` / `DeleteUserWebhook` handlers in `/bench/repo/server/router/api/v1/user_service_webhooks.go` are CRUD for webhook *registrations*, not event dispatchers.
