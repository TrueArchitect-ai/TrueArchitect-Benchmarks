**CEL (Common Expression Language) via `github.com/google/cel-go` — `/bench/repo/internal/filter/`; the CEL AST is lowered into a dialect-agnostic condition tree (IR), which a per-dialect renderer turns into a parameterized SQL `WHERE` fragment plus bind args that each driver appends to its query.**

Where each piece lives:

- **Engine** — `filter.Engine` at `/bench/repo/internal/filter/engine.go:14`. `NewEngine` builds a `cel.Env` from a `Schema`; `Compile` (line 47) calls `env.Compile(filter)` and converts the AST via `cel.AstToParsedExpr`. The `now` variable is frozen once per compile so a filter sees a single instant. `cel-go v0.28.1` is pinned in `/bench/repo/go.mod:13`.
- **Schema / allowed fields and functions** — `/bench/repo/internal/filter/schema.go`; AST-to-IR lowering in `/bench/repo/internal/filter/parser.go`, with the condition-tree types in `/bench/repo/internal/filter/ir.go`.
- **SQL generation** — `/bench/repo/internal/filter/render.go`. The `renderer` (line 10) carries a `DialectName` and a placeholder counter/offset, and switches on `DialectSQLite` / `DialectPostgres` / `DialectMySQL` wherever the SQL differs (JSON extraction, string length — e.g. `stringLengthExpr` at line 297 — and placeholder style `?` vs `$N`). Degenerate cases render as `1 = 0` (unsatisfiable) or an empty string (trivially true).
- **Glue into queries** — `filter.AppendConditions` at `/bench/repo/internal/filter/helpers.go:9` compiles each filter string with the caller's dialect and current arg count, then appends `(<sql>)` to the `where` slice and the bind values to `args`. Callers are the per-dialect memo drivers, e.g. `/bench/repo/store/db/sqlite/memo.go:57-61` (`filter.DefaultEngine()` + `filter.DialectSQLite`), with peers in `/bench/repo/store/db/postgres/memo.go` and `/bench/repo/store/db/mysql/memo.go`.

Filters arrive from the API layer through `ListMemosRequest.filter` (`/bench/repo/proto/api/v1/memo_service.proto`), are put on `store.FindMemo.Filters` by `APIV1Service.ListMemos` (`/bench/repo/server/router/api/v1/memo_service.go:178`), and reach the driver via `Store.ListMemos`. Package notes and the supported filter grammar are documented in `/bench/repo/internal/filter/README.md` and `MAINTENANCE.md`. A parallel user-filter path exists at `/bench/repo/server/router/api/v1/user_service_filter.go`.
