**Interceptor.** `authInterceptor` at `/bench/repo/web/src/connect.ts:155` is attached to the shared Connect transport (line 187). Per request it resolves a token via `getRequestToken` (line 124), sets `Authorization: Bearer <token>`, and on a `Code.Unauthenticated` response refreshes once and retries — marking the retry with an `X-Retry` header so it can't loop (lines 160-177); if the refresh fails it calls `redirectOnAuthFailure()`. It also does a *preflight* refresh when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` of expiry, so public endpoints like `ListMemos` don't silently return guest-scoped data (lines 136-147).

**Tokens.**
- *Access token* — JWT held in `localStorage` (`/bench/repo/web/src/auth-state.ts`: `getAccessToken`, `setAccessToken`, `isTokenExpired`, plus cross-tab adoption).
- *Refresh token* — HttpOnly cookie `memos_refresh`, never read by JS; the browser sends it because both transports use `credentials: "include"` (`connect.ts:56`). Refresh goes through a dedicated `refreshTransport`/`refreshAuthClient` with **no** interceptor to avoid recursion (lines 64-71), and concurrent refreshes are deduplicated by `tokenRefreshManager` (line 50) so proactive on-focus refresh and reactive 401 refresh don't race with server-side rotation.
- *Personal Access Token* — `memos_pat_…`, for API clients rather than the web UI.
