**1st: `store.User` — ~5 non-test packages (7 counting test packages); 2nd: `store.Memo` — ~4 non-test packages (6 counting test packages)**

Both are declared in the data layer at `store/user.go` and `store/memo.go`. Counting packages *outside* `store/...` (so excluding the three drivers `store/db/{sqlite,postgres,mysql}` and `store/test`, which are part of the data layer):

**`store.User` — 5 non-test packages**
- `server/auth` — `server/auth/*.go` (7 references; authenticator resolves the current user)
- `server/notification` (5)
- `server/router/api/v1` (45 — by far the heaviest consumer)
- `server/router/fileserver` (2 — e.g. `getUserByUsername` in `server/router/fileserver/fileserver.go:715`)
- `server/router/rss` (2)

Plus two test-only packages: `server/router/api/v1/test` and `server/router/frontend` (the latter references it only from `_test.go` files), giving 7 packages if you count test code.

**`store.Memo` — 4 non-test packages**
- `server/notification` (10)
- `server/router/api/v1` (30)
- `server/router/rss` (1)
- `server/runner/memopayload` (1 — `RebuildMemoPayload` in `server/runner/memopayload/runner.go`)

Plus `server/router/api/v1/test` and `server/router/frontend` tests → 6 with test code.

The decisive difference is `server/auth`: `store.User` is the only entity threaded through the authentication layer, which no other entity touches.

Close third for context: **`store.Attachment`** at 3 non-test packages (`server/router/api/v1` 21, `server/router/fileserver` 15, `server/router/rss` 1) — note its raw reference count in `fileserver` is high, but it's spread across fewer packages. `store.MemoShare`, `store.Reaction`, `store.Inbox`, and `store.MemoRelation` all sit at 1–2 outside packages, and `store.IdentityProvider` / `store.UserSetting` appear only inside the data layer (the API layer works with the protobuf `storepb` variants instead).
