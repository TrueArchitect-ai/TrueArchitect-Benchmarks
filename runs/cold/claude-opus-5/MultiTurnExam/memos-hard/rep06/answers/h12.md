How I determined it — three candidates implement `CreateMemo` with identical signatures (`store/db/sqlite/memo.go:16`, `store/db/postgres/memo.go:16`, `store/db/mysql/memo.go:16`), so the call site alone can't tell you which runs:

1. **Found the dispatch point.** The handler calls `s.Store.CreateMemo` (`server/router/api/v1/memo_service.go:115`); `Store.CreateMemo` validates the UID then delegates to `s.driver.CreateMemo` (`store/memo.go:109-114`). `driver` is the `Driver` interface, which declares `CreateMemo` at `store/driver.go:29` — a dynamic dispatch, so the concrete type must be resolved from construction, not from the call.
2. **Found where the concrete type is chosen.** `db.NewDBDriver` switches on `profile.Driver` (`store/db/db.go:14-31`), returning `sqlite.NewDB`, `mysql.NewDB`, or `postgres.NewDB`. As established earlier, that factory is the only construction site for these drivers.
3. **Resolved `profile.Driver` for a default install.** `main.go` populates it from `viper.GetString("driver")` (`cmd/memos/main.go:43`), and the default is `"sqlite"` in both places it's set: `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the flag default (`cmd/memos/main.go:130`). With no flags, env, or config file overriding it, the `case "sqlite"` branch wins. `Profile.Validate` then also derives the DSN — `<data-dir>/memos_prod.db` (`internal/profile/profile.go:109-115`) — confirming a file-backed SQLite install is the default posture.
