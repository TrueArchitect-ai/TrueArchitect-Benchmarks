**Premise correction: there is no Redis anywhere in this repository — no `redis` import, dependency in `go.mod`, config flag, or reference in any Go/YAML/JSON file. The cache layer is a hand-rolled in-process in-memory cache, and user entries use the default TTL of 10 minutes.**

The actual mechanism:

- **Implementation**: `store/cache/cache.go` — a `Cache` backed by a `sync.Map` plus an `atomic.Int64` item counter (`store/cache/cache.go:66-72`), with a background `cleanupLoop` goroutine for expiry. It satisfies a local `Interface` (`store/cache/cache.go:11-32`) with `Set`/`SetWithTTL`/`Get`/`Delete`/`Clear`/`Size`/`Close`. Nothing is serialized or sent over a network; it lives in the server process and is lost on restart.

- **Configuration site**: `store.New` (`store/store.go:37-59`) builds one `cache.Config` literal and passes it to three separate cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:26-28`, constructed at `:50-52`). The settings are:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  - `OnEviction: nil`

  These are hardcoded — there is no flag, env var, or config file to tune them. `cache.DefaultConfig()` (`store/cache/cache.go:56-63`) declares the identical values but isn't what `store.New` calls; the literal is duplicated.

- **User entry TTL: 10 minutes.** Every user cache write goes through `Set` (`store/user.go:98, 122, 132, 143, 167`), and `Cache.Set` delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). No user code path calls `SetWithTTL` with a custom duration, so the 10-minute default is the effective TTL. Entries are keyed by user ID via `userCacheKey` (`store/user.go:88`).

- **Practical caveat**: the user cache is only *read* when the lookup is by ID — `Store.GetUser` consults it solely if `find.ID != nil` (`store/user.go:148-156`). Lookups by username or email always fall through to SQL regardless of TTL.

Because the cache is per-process and unshared, a multi-replica deployment would have independent caches with no cross-instance invalidation — which is presumably why the TTLs are kept short.
