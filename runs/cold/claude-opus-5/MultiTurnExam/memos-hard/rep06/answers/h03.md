h03.

**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`) — OAuth 2.0 is the only protocol implementation that ships**

Details:

- **Abstraction — `internal/idp`**: the package is deliberately thin. `internal/idp/idp.go` defines just the normalized `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider must produce. There's no Go `interface` type here — the shared contract is the user-info shape plus the protobuf schema. The provider *model* is defined in `proto/store/idp.proto`: `IdentityProvider` with a `Type` enum whose only non-unspecified value is `OAUTH2 = 1`, and an `IdentityProviderConfig` `oneof` currently holding a single `oauth2_config` variant (`proto/store/idp.proto:7-25`, generated as `proto/gen/store/idp.pb.go`).

- **Implementation — `internal/idp/oauth2`**: `internal/idp/oauth2/oauth2.go` implements the OAuth2 flow on top of `golang.org/x/oauth2`. `NewIdentityProvider` validates the required config fields (client ID/secret, token URL, user-info URL, identifier field mapping); `ExchangeToken` swaps the auth code for an access token and supports PKCE by passing `code_verifier` when supplied; `UserInfo` fetches the user-info endpoint (10s timeout, `userInfoRequestTimeout`) and maps raw claims into `idp.IdentityProviderUserInfo` via the configured `FieldMapping`.

- **Dispatch point**: `resolveSSOIdentity` in `server/router/api/v1/auth_service_sso.go:104-134` loads the stored provider and branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` to construct the OAuth2 provider — the single branch confirming OAuth2 is the only shipped protocol. Since OIDC providers are configured as generic OAuth2 (auth/token/user-info URLs plus field mapping), OIDC works in practice but there is no separate OIDC/SAML/LDAP package.
