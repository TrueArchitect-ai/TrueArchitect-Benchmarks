**Computation site: `memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`), which delegates to `(*markdown.service).ExtractAll` (`internal/markdown/markdown.go:356`); Triggers: `CreateMemo`, `CreateMemoComment` (via `CreateMemo`), and `UpdateMemo` only when `content` is in the update mask; Extracted: `tags` plus the `Property` set — `has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, `title`**

**Where it's computed.** `RebuildMemoPayload` ensures `memo.Payload` is non-nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`server/runner/memopayload/runner.go:74-86`). `ExtractAll` does a single goldmark AST walk (`internal/markdown/markdown.go:356-421`), which is why it's preferred over calling `ExtractTags`/`ExtractProperties` separately. The result is persisted in the memo's `payload` column as protojson (e.g. `store/db/sqlite/memo.go:19-26`).

**What's extracted** (schema: `proto/store/memo.proto:7-29`):

- `tags` — every `#tag` node, but *not* ones nested inside a link or image (`asMemoTagNode` → `isTagNodeInLinkOrImage`, `internal/markdown/markdown.go:114-135`), deduplicated with original case preserved.
- `property.has_link` — any `gast.KindLink` node.
- `property.has_code` — any code block, fenced code block, or inline code span.
- `property.has_task_list` — any GFM task checkbox; and `property.has_incomplete_tasks` — set when at least one checkbox is unchecked.
- `property.title` — the text of the first block-level child of the document *only if* it's an H1 heading (`internal/markdown/markdown.go:383-389`).

`ExtractAll` also returns `Mentions`, but `RebuildMemoPayload` does not store them — mentions are consumed live for notifications (`server/router/api/v1/memo_mention_helpers.go:32`).

**Triggers** — only two call sites of `RebuildMemoPayload` in production:

1. `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`.
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, inside the `if path == "content"` branch of the update-mask loop. Updates to visibility, pinned state, attachments, or relations therefore do **not** recompute the payload.
3. `CreateMemoComment` inherits trigger #1, since it delegates to `s.CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).

There is also a bulk backfill path, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-71`), which rebuilds every memo's payload in batches — but as established earlier, nothing constructs that runner, so it never executes.

Two related-but-distinct things worth separating: the memo **snippet** used in list previews is *not* part of this stored payload — it's generated per-response at conversion time via `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_converter.go:76-80`, `memo_relation_service.go:154,162`). And `markdown.Service.RenameTag` (`internal/markdown/markdown.go:425`) is declared and implemented but has no caller outside its own package, so no tag-rename operation currently triggers recomputation.
