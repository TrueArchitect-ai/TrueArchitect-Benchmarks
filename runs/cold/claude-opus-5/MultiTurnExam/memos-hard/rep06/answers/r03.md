**Premise correction: there is no nightly database-cleanup job — and in fact no scheduled jobs at all. The cron scheduler package exists but is never used by the running server, so nothing is registered with it and no schedule time exists to report.**

Evidence:

- **The scheduler has zero importers.** `internal/scheduler` is a complete, self-contained cron implementation — `Scheduler` with `Register`/`Start`/`Stop` (`internal/scheduler/scheduler.go:54,70,91,169`), a `Job` type carrying `Name`/`Schedule`/`Timezone`/`Handler` (`internal/scheduler/job.go:14-36`), a 5-field cron expression parser (`internal/scheduler/parser.go:30`), and middleware for recovery/logging/timeout (`internal/scheduler/middleware.go`). But searching every Go file outside the package for `"github.com/usememos/memos/internal/scheduler"` returns nothing. Its only consumers are its own tests (`example_test.go`, `integration_test.go`, etc.). `scheduler.New` is never called from production code, and `Scheduler.Register` is never called at all outside the package.

- **Nothing cleanup-shaped is scheduled.** Grepping `server/`, `store/`, and `cmd/` for cleanup work surfaces only: per-request cleanup during entity deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`), and the in-memory cache's expiry goroutine — `CleanupInterval: 5 * time.Minute` (`store/store.go:42`, `store/cache/cache.go:60`, loop at `cache.go:83`). None of these touch a cron schedule, and the cache one is a plain `time.Ticker` on a 5-minute period, not a nightly job.

- **The only genuinely scheduled background work is on a fixed interval, not a wall-clock time.** `startBackgroundRunners` (`server/server.go:153-174`) starts exactly one runner: `s3presign.Runner`, which runs once at boot and then every 12 hours via `time.NewTicker(runnerInterval)` where `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27-41`). Being interval-based from process start, its fire times drift with restarts — there is no "runs at 03:00" semantics anywhere in the server.

So `internal/scheduler` is currently dead code — infrastructure built for scheduled jobs that no job has yet been wired into.
