**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`; Triggers: memo create and memo update-with-content-change (plus a batch backfill runner that isn't wired up); Extracts: `tags` + the `Property` set (`title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`)**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-87`) ensures `memo.Payload` exists, runs a single-pass markdown parse via `markdownService.ExtractAll([]byte(memo.Content))`, then assigns:

```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```

The parse itself is `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356-422` — one goldmark AST walk that collects everything at once.

**Triggers (recomputation points):**

| Trigger | Site |
|---|---|
| `CreateMemo` — always, before the insert | `server/router/api/v1/memo_service.go:108` (the resulting payload is then persisted via `s.Store.CreateMemo` at `:115`) |
| `UpdateMemo` — only when the field mask contains `content` | `server/router/api/v1/memo_service.go:447`, inside the `if path == "content"` branch (`:436-452`); the rebuilt payload is written back through `update.Payload = memo.Payload` at `:452` |
| `memopayload.Runner.RunOnce` — batch backfill over all memos, 100 at a time | `server/runner/memopayload/runner.go:52` — **never invoked in production** (see h08: the `Runner` type is never constructed outside its own package) |

Note what does *not* trigger it: `SetMemoAttachments` and `SetMemoRelations` fire the "memo updated" side effects but don't touch content, so no recomputation. Same for a visibility-only update (`memo_service.go:452` onward).

**What's extracted** (persisted into `MemoPayload`, `proto/store/memo.proto:7-22`):

- `tags` — deduplicated `#tag` node values, case preserved; tag nodes nested inside links/images are excluded (`asMemoTagNode`, `internal/markdown/markdown.go:134`)
- `property.title` — text of the first H1 heading, only if it's the document's first block child (`markdown.go:384-389`)
- `property.has_link` — any `KindLink` node
- `property.has_code` — any code block, fenced code block, or inline code span
- `property.has_task_list` — any GFM task checkbox
- `property.has_incomplete_tasks` — any task checkbox that is unchecked (`markdown.go:399-405`)

Two adjacent details worth separating out:

- `ExtractAll` also returns **mentions** (lowercased `@username`), but `RebuildMemoPayload` deliberately does not store them in the payload — they're consumed separately for notifications via `server/router/api/v1/memo_mention_helpers.go:32`.
- The **snippet** shown in list views is *not* part of this stored payload. It's derived on read at conversion time — `getMemoContentSnippet` (`server/router/api/v1/memo_service_webhooks.go:83`) calling `GenerateSnippet(content, 64)`, used at `memo_service_converter.go:76-80` and in the batch path at `:225`.
- `payload.Location` is user-supplied, not derived, and is set separately after the rebuild (`memo_service.go:111-113`).
