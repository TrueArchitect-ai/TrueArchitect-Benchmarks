**No** — the MySQL driver is constructed in exactly one place, the factory.

Evidence:

1. **Single import of the package, repo-wide.** `grep -rn "store/db/mysql" --include=*.go .` returns exactly one Go hit: `store/db/db.go:8`. No other production file, test file, or command imports `github.com/usememos/memos/store/db/mysql`. (The only other matches anywhere in the repo are prose mentions of file paths in `docs/plans/…` markdown, not code.)

2. **Single call site of the constructor.** `mysql.NewDB` (defined at `store/db/mysql/mysql.go:20`) is invoked only at `store/db/db.go:22`, inside the `switch profile.Driver` in `NewDBDriver` — alongside the parallel `sqlite.NewDB` (`db.go:20`) and `postgres.NewDB` (`db.go:24`) cases.

3. **The struct itself is unexported-by-convention outside the factory.** `mysql.DB` (`store/db/mysql/mysql.go:14-18`) has only unexported fields (`db`, `profile`, `config`), so it cannot be usefully constructed as a literal from another package — a `mysql.DB{}` elsewhere would have a nil `*sql.DB`. The one composite-literal construction, `db := &DB{}`, is intra-package and in a test: `store/db/mysql/auth_config_test.go:12`.

So all MySQL driver instantiation flows through `store.Driver` returned by `NewDBDriver` in `store/db/db.go:14`.
