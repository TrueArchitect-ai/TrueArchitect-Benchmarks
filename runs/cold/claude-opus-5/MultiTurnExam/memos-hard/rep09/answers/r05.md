**Premise correction: this project has no GraphQL. There is no schema file, no resolver, no GraphQL library.** Searching every Go/TS/JSON source and `go.mod` for `graphql`, `gqlgen`, `apollo`, and `.graphql`/`.graphqls` files returns zero hits.

**The actual API surface: Protocol Buffers–defined RPC, exposed simultaneously as gRPC, Connect, and a REST/JSON gateway.**

**Schema of record** — `.proto` files in `proto/api/v1/`:
`memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto`. Store-side messages live in `proto/store/` (e.g. `proto/store/memo.proto`, referenced earlier for `MemoPayload`).

Each RPC carries its own HTTP mapping via `google.api.http` annotations, which is what produces the REST surface — e.g. in `proto/api/v1/memo_service.proto`: `CreateMemo` → `POST /api/v1/memos` (`:22-25`), `ListMemos` → `GET /api/v1/memos` (`:30`), `GetMemo` → `GET /api/v1/{name=memos/*}` (`:35`), `UpdateMemo` → `PATCH /api/v1/{memo.name=memos/*}` (`:40-43`).

**Code generation** — `proto/buf.gen.yaml` runs five plugins over those files: protobuf-go, gRPC-Go, **Connect-Go**, **grpc-gateway**, and **gnostic-openapi** (so the OpenAPI document is generated from the protos, not hand-written), plus `bufbuild/es` emitting TypeScript into `web/src/types/proto` for the frontend. Output lands in `proto/gen/api/v1/` (`*.pb.go`, `*_grpc.pb.go`, `*.pb.gw.go`, `apiv1connect/*.connect.go`).

**Server wiring** — handlers are the `APIV1Service` methods in `server/router/api/v1/`, registered through `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:64`), called from `server/server.go:88`. Alongside it the server exposes non-RPC HTTP surfaces: the file server (`server/router/fileserver/fileserver.go:121`), RSS (`server/router/rss/rss.go`), MCP (`server/router/mcp/`), and the frontend static handler.
