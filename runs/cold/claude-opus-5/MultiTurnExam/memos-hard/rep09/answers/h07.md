Details worth noting:

- **Auth gate first**: on a private instance (`!s.Profile.AllowAnonymous()`), the handler requires a session/access token/PAT via `getCurrentUser` before any lookup — `fileserver.go:173-181`.
- **The lookup key is the username**, taken from the `:identifier` path param and passed as `&store.FindUser{Username: &identifier}` (`fileserver.go:716`). Because `FindUser.ID` is nil, `GetUser`'s cache fast-path at `store/user.go:149-156` is skipped, so this always reaches the driver.
- **The data is not a file** — the avatar lives inline in the `user.avatar_url` column as a data URI. The handler decodes it with `parseDataURI` (`fileserver.go:737`, regex-based), enforces an allowlist of image MIME types via `avatarAllowedTypes` (`fileserver.go:75`, checked at `:201`), sets security headers plus `Cache-Control`, and writes the bytes with `c.Blob` (`fileserver.go:205-209`).
- **Why the browser requests this URL**: the API rewrites base64 avatars into `/file/{user.Name}/avatar` when converting users for API responses — `server/router/api/v1/user_service_converters.go:36`.
- Driver hop shown for SQLite; MySQL and Postgres have parallel `ListUsers` implementations in `store/db/mysql/user.go` and `store/db/postgres/user.go`.
