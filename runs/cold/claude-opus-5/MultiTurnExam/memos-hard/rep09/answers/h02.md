**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard via `safeDialContext` + `isReservedIP` (dial-time) — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path**
- Callers enqueue with `webhook.PostAsync` (`internal/webhook/webhook.go:184`) — a bounded 128-slot channel (`webhook.go:39`) drained by 4 worker goroutines started in `init()` (`webhook.go:42-55`). The workers call `Post`, so the actual HTTP request is built, HMAC-signed (Standard Webhooks `webhook-id`/`webhook-timestamp`/`webhook-signature` headers, `webhook.go:133-150`), and executed at `resp, err := safeClient.Do(req)` — `internal/webhook/webhook.go:152`.
- Trigger sites are the memo lifecycle dispatchers in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

**Protection**
- Primary (at delivery time): `safeClient` uses a custom `http.Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`webhook.go:59-77`) resolves the hostname itself and rejects the connection if *any* resolved IP is reserved. Because the check happens at dial time rather than only at configuration time, it also defeats DNS-rebinding (`webhook.go:29-31`).
- `isReservedIP` (`internal/webhook/validate.go:44`) matches against `reservedCIDRs` (`validate.go:14-23`): IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), and the IPv6 loopback/ULA/link-local equivalents, parsed once in `init()` (`validate.go:28-36`).
- Secondary (at configuration time): `webhook.ValidateURL` (`validate.go:62`) enforces http/https scheme and the same reserved-IP check when a webhook is created or updated — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.
- Escape hatch: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) disables both checks for self-hosted setups. Note it is currently only ever set from tests (`internal/webhook/webhook_test.go:91`, `:142`) — no CLI flag or env var wires it up, so in the shipped server the protection is always on.
