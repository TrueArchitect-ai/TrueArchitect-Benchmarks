**Premise correction: neither — there is no message broker in this repository at all.** Grepping every Go file and `go.mod` for `nats`, `rabbitmq`, `amqp`, `kafka`, `streadway`, `sqs`, `pubsub`, and `broker` yields zero real hits; no client library is a dependency. Consequently there is no queue declaration, no exchange/subject binding, and no connection config.

**The actual mechanism: an in-process buffered Go channel with a fixed worker pool, all in `internal/webhook/webhook.go`.**

- **The "queue"** is a package-level channel declared at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  Capacity 128, in memory, per process. It is not durable — anything buffered is lost on restart, and it is not shared between replicas.

- **The "workers"** are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over `asyncPostQueue` and calls `Post(payload)`, logging a warning on failure. There are no retries, no acks, no dead-letter path — a failed delivery is logged and dropped.

- **Producing** goes through `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send: if the buffer is full, the event is **dropped** with a warning rather than blocking the request (`:191-195`). Callers are the memo lifecycle dispatchers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

- **Consuming/delivery** ends at `webhook.Post` (`internal/webhook/webhook.go:120`), which marshals the payload, adds Standard Webhooks HMAC headers when a signing secret is set (`:133-150`), and issues the request via the SSRF-guarded `safeClient` at `:152`.

So the whole pipeline is a bounded, best-effort, single-process fan-out — closer to a fire-and-forget worker pool than to broker-backed delivery.
