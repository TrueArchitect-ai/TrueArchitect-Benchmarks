**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive search for `redis` across all Go sources, `go.mod`, and YAML/JSON config returns zero hits — no client dependency, no connection string, no config key. So there is nothing to point at for "where Redis is configured."

**The actual mechanism: a process-local, in-memory cache.**

- **Implementation**: `store/cache/cache.go` — a `sync.Map`-backed `Cache` type (`cache.go:65-72`) with per-item expiration, an atomic item counter, and a background cleanup goroutine. It satisfies the local `cache.Interface` (`cache.go:11-32`). Being in-process, it is not shared across instances — a multi-replica deployment gets independent caches.
- **Configuration site**: `store.New` in `store/store.go:38-53`, which builds one `cache.Config` literal and hands it to three separate cache instances: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`, fields declared at `store/store.go:27-29`).

**TTL applying to user entries: 10 minutes** (with 1000-item and cleanup bounds):

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
— `store/store.go:40-45`. The same values are duplicated in `cache.DefaultConfig()` (`store/cache/cache.go:56-63`), though `store.New` doesn't call it.

That 10 minutes is what user entries get because every user write goes through `Set`, which delegates to `SetWithTTL` using `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). There are no `SetWithTTL` callers outside the cache package, so no user entry ever receives a custom TTL. The user cache is populated at `store/user.go:98`, `:122`, `:132`, `:143`, and `:167`, keyed by `userCacheKey(userID)` (`store/user.go:88`), and read at `store/user.go:150` — note that read path only hits when `FindUser.ID` is set, so username-based lookups always bypass the cache.

Lifecycle: the cleanup goroutines are stopped by `Store.Close` calling `Close` on all three caches (`store/store.go:74-76`).
