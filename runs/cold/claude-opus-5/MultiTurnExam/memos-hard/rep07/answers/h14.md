**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `markdown.(*service).ExtractAll` — `internal/markdown/markdown.go:356`; Triggers: memo create and memo content-update (plus the never-invoked batch backfill runner); Extracted: `Tags` + the `Property` set — `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`, `title`.**

**Where it's computed.** `RebuildMemoPayload(_ context.Context, memo *store.Memo, markdownService markdown.Service)` (`server/runner/memopayload/runner.go:74-88`) lazily initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`:85-86`). The real work is one goldmark AST walk in `(*service).ExtractAll` (`internal/markdown/markdown.go:356-420`). The result is persisted as the `payload` JSON column on the memo row (marshaled in the driver, e.g. `store/db/sqlite/memo.go:21-26`).

Note what does *not* trigger it: `SetMemoAttachments`, `SetMemoRelations`, and non-content update paths (visibility, pinned, etc.) leave the stored payload untouched — correctly, since none of them change `memo.Content`.

**What's extracted** (`internal/markdown/markdown.go:356-420`, shape defined in `proto/store/memo.proto:7-22`):

- `tags` — every `#tag` node, but skipping tags nested inside a link or image (`isTagNodeInLinkOrImage`, `internal/markdown/markdown.go:122`), deduplicated case-preserving via `uniquePreserveCase`.
- `property.title` — text of the first H1 heading, only if that heading is the document's first block-level child (`:383-389`).
- `property.has_link` — any `KindLink` node.
- `property.has_code` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- `property.has_task_list` — any `TaskCheckBox`; and `property.has_incomplete_tasks` when at least one checkbox is unchecked (`:400-406`).

`ExtractAll` also returns `Mentions` (lowercased `@user` names), but `RebuildMemoPayload` does not store them — mentions are consumed separately at request time for notifications (`server/router/api/v1/memo_mention_helpers.go:32`).

**Related but distinct.** The list/preview `snippet` is *not* stored in the payload; it's derived per response by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-90`), called from the memo converter at `server/router/api/v1/memo_service_converter.go:76-80` and for relation previews at `server/router/api/v1/memo_relation_service.go:154-173`. The stored `Payload.Tags`, by contrast, is read straight back out in the converter (`memo_service_converter.go:48`) and aggregated for user tag stats (`server/router/api/v1/user_service_stats.go:138`, `:254`).
