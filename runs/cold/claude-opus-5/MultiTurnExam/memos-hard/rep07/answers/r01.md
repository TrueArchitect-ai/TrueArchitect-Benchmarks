**Premise correction: there is no Redis anywhere in this repository — no client library, no connection config, no dependency. A case-insensitive search for "redis" across all Go sources, `go.mod`, and YAML/JSON config files returns zero hits. The cache layer is a process-local, in-memory implementation.**

**Actual mechanism:**

- **Implementation**: `store/cache/cache.go` — a `sync.Map`-backed `Cache` type (`:66-73`) satisfying the `Interface` at `:11-32` (`Set`, `SetWithTTL`, `Get`, `Delete`, `Clear`, `Size`, `Close`). Each entry is an `item` holding the value, an absolute `expiration` time, and a rough size estimate (`:35-39`). It's per-process state, so in a multi-instance deployment each instance has its own copy with no invalidation between them.

- **Where it's "configured"**: `store.New` in `store/store.go:38-61`. The config is a hardcoded literal at `store/store.go:40-45` — `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, `OnEviction: nil` — and the same struct is passed to all three caches at `:51-53`: `instanceSettingCache`, `userCache`, `userSettingCache`. There is no flag, env var, or config-file key that changes any of these; `internal/profile/profile.go` carries no cache settings. `store/cache/cache.go:57-64` defines an identical `DefaultConfig()`, but `store.New` doesn't call it — it duplicates the values inline.

- **TTL for user entries: 10 minutes.** Every write to `userCache` uses the plain `Set` — `store/user.go:98`, `:122`, `:132`, `:143`, `:167` — and `Set` forwards to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`), stamping `expiration: time.Now().Add(ttl)` at `:112`. Nothing in the codebase calls `SetWithTTL` directly, so all three caches use the same 10-minute lifetime.

Two behavioral details worth knowing: the user cache is keyed by user ID only (`userCacheKey`), so `Store.GetUser` consults it only when the lookup is by ID — a lookup by username or email always falls through to SQL (`store/user.go:148-169`). And deletion invalidates explicitly at `store/user_delete.go:40`. Expired entries are swept by a background goroutine on the 5-minute `CleanupInterval`, stopped via `Cache.Close` (`store/cache/cache.go:187`), which `Store.Close` calls for all three caches (`store/store.go:74-76`).
