Notes worth flagging:

- The avatar is stored inline as a **data URI** in the `user.avatar_url` column (`store/db/sqlite/user.go:159`), not as a file or attachment row — so "reaching stored data" ends at the user table. `parseDataURI` splits the MIME type and base64 payload; the handler 404s if `AvatarURL` is empty (`fileserver.go:192-194`).
- Access control is coarse: on an instance where `Profile.AllowAnonymous()` is false, *any* authenticated viewer suffices (`fileserver.go:173-181`) — there's no per-user check, so one user may fetch another's avatar. On a public instance the endpoint is open.
- The frontend usually doesn't hit this route at all: `UserAvatar` (`web/src/components/UserAvatar.tsx`) renders `avatarUrl` straight into `<img src>`, and that value arrives as the data URI via the user API (`server/router/api/v1/user_service_converters.go`). This `/file/...` route is the URL-based path to the same stored bytes.
