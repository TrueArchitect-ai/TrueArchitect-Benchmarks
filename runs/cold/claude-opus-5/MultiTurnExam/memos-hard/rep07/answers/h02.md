**`webhook.Post` — `internal/webhook/webhook.go:120`; dial-time reserved-IP blocking via `safeDialContext` on the shared `safeClient` transport — `internal/webhook/webhook.go:59` (ranges in `internal/webhook/validate.go:14-54`)**

How it fits together:

- **Delivery path**: memo create/update/delete handlers call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:184-196`, dropping with a warning when full). The actual HTTP request is built, HMAC-signed (Standard Webhooks `webhook-id`/`webhook-timestamp`/`webhook-signature` headers), and executed in `Post` at `internal/webhook/webhook.go:120-180` — running on one of 4 worker goroutines started in `init()` at `internal/webhook/webhook.go:42-55`.

- **Primary protection**: `Post` sends through `safeClient` (`internal/webhook/webhook.go:32-37`), whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:59-77`). It splits host/port, resolves the host itself, and refuses to dial if *any* resolved address is reserved. Because the check happens at dial time rather than at URL-save time, it also defeats DNS rebinding — the comment at `webhook.go:30-31` states this explicitly.

- **Reserved ranges**: `isReservedIP` (`internal/webhook/validate.go:44-54`) tests against `reservedNetworks`, parsed once in `init()` from `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 blocks, 169.254.0.0/16 (cloud IMDS), plus IPv6 loopback, unique-local, and link-local.

- **Secondary, earlier check**: `webhook.ValidateURL` (`internal/webhook/validate.go:62-83`) runs when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`), rejecting non-http(s) schemes and hostnames resolving to reserved IPs with `InvalidArgument`.

- **Escape hatch**: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) disables both checks when true. Note it is never assigned anywhere in non-test code — only `internal/webhook/webhook_test.go:91` and `:142` set it — so in a running server it stays at its zero value `false` and protection is always on; there is currently no CLI flag or env var wired to it.
