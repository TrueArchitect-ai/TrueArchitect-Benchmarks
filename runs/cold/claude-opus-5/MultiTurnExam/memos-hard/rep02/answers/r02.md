**Premise correction: there is no rate-limiting middleware in this codebase — per-user or otherwise — so there is no registration site and no request limits.**

Evidence:

1. **No rate-limiting code or dependency.** A case-insensitive grep for `rate.?limit|ratelimit|throttl|token.?bucket|leaky` across all Go sources and `go.mod` returns exactly one hit, and it's an aspirational comment in package documentation: `internal/email/doc.go:86` — `//   - Rate limit email sending to prevent abuse`. Nothing implements it. `golang.org/x/time/rate` is not a dependency, and Echo's `middleware.RateLimiter` is never referenced.

2. **The full middleware chain is two entries.** `server/server.go:51-52` registers `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go:14`), and that's the entirety of `echoServer.Use(...)`. The remaining per-request interception is authentication: the gateway auth middleware and Connect interceptor built around `NewAuthorizer` in `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:95` and following). Authorization, not throttling.

What does exist — and may be what the question is reaching for — are **static caps and concurrency guards**, none of which track per-user request rates:

- **Batch-size caps** rejecting oversized single requests: `maxBatchDeleteAttachments = 100` (`server/router/api/v1/attachment_service.go:35,354`), `maxBatchGetInstanceSettings = 100` (`instance_service.go:22,77`), `maxBatchGetUsers = 100` (`user_service.go:23,144`), `maxBatchGetLinkMetadata = 10` (`memo_service.go:26`, enforced at `memo_service_link_metadata.go:23`).
- **Concurrency semaphores**, process-wide rather than per-user: `semaphore.NewWeighted(3)` for thumbnails and `(2)` for image processing (`server/router/api/v1/v1.go:59-60`), plus `maxConcurrentThumbnails` in the file server (`server/router/fileserver/fileserver.go:116`).
- **A bounded webhook dispatch queue** (128 slots, drops on overflow) at `internal/webhook/webhook.go:39,189-195`.
- **Content-length limits** on memos, read from instance settings (`server/router/api/v1/memo_service.go:595`).

These bound the size and concurrency of individual operations; none limits how many requests a user may issue over time. If rate limiting is needed, it would have to be added — the natural insertion point is alongside the existing `echoServer.Use(...)` calls at `server/server.go:51-52`, or in the Connect interceptor chain in `server/router/api/v1/v1.go`.
