**Premise correction: there is no Redis in this repository.** Grepping `redis` case-insensitively across all Go sources, `go.mod`, `go.sum`, and YAML/JSON config returns zero hits. The cache layer is entirely in-process — there is no external cache server, no connection string, and nothing to configure.

**Actual mechanism.** The cache is a hand-rolled in-memory implementation in `store/cache/cache.go`: a `sync.Map` of `item{value, expiration, size}` guarded by an atomic item counter, satisfying the local `cache.Interface` (`store/cache/cache.go:11-32`).

Three separate `*cache.Cache` instances hang off `Store` (`store/store.go:27-29`): `instanceSettingCache`, `userCache`, and `userSettingCache`. All three are built in `store.New` from one hardcoded `cache.Config` (`store/store.go:40-53`):

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`
- `OnEviction: nil`

**TTL for user entries: 10 minutes.** Every write goes through `Set` (`store/user.go:98,122,132,143,167`), and `Cache.Set` delegates to `SetWithTTL(ctx, key, value, c.config.DefaultTTL)` (`store/cache/cache.go:94`) — nothing in the user path calls `SetWithTTL` with a custom duration, so the 10-minute default is what applies. Keys are `userCacheKey(user.ID)`. The same 10 minutes applies to instance settings and user settings, since they share the config literal.

Two details that matter more than the TTL in practice: the cache is only consulted on ID-keyed lookups — `Store.GetUser` skips it entirely when finding by username or other fields (`store/user.go:149-156`) — and entries are invalidated eagerly on mutation and delete rather than being left to expire (`Store.DeleteUser` → `s.deleteUserCache`, `store/user.go:179`). Cleanup goroutines are stopped via `Store.Close` → `userCache.Close()` (`store/store.go:75`). Since the cache lives in the process, it is per-instance and not shared across replicas.

`DefaultConfig()` in `store/cache/cache.go:56-63` declares the identical values, but `store.New` builds its own literal rather than calling it.
