Notes on the path:

- **Wiring**: the service is constructed and its routes registered at `server/server.go:81-82`.
- **Access control** happens before any lookup: if `s.Profile.AllowAnonymous()` is false, `getCurrentUser` must resolve a session/access token/PAT or the handler returns 401 (`fileserver.go:170-179`). On a public instance, anyone may fetch any user's avatar.
- **Lookup key**: `getUserByUsername` passes the path segment as `store.FindUser{Username: &identifier}` — so the URL's `:identifier` is a username, not an ID.
- **Cache**: `Store.GetUser` only consults `userCache` when `find.ID` is set (`store/user.go:149-156`); a username lookup always falls through to `ListUsers` and the DB, though results are written back into the cache by ID (`store/user.go:142-144`, `167`).
- **The "stored data" is the row itself**, not a file: `avatar_url` holds a base64 data URI in the `user` table. `parseDataURI` regex-splits it and base64-decodes the payload (`fileserver.go:737-748`); the handler then rejects anything outside `avatarAllowedTypes` (PNG/JPEG/JPG/GIF/WebP, `fileserver.go:75-81`), sets security headers plus `Cache-Control: public, max-age=3600`, and writes the bytes via `c.Blob` (`fileserver.go:205-209`).
