**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard via `safeDialContext` / `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

**Where delivery executes.** Memo create/update/delete paths call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43,71`), which only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:39,184-196`) and drops the payload with a warning if the queue is full. Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, which is where the actual outbound HTTP POST happens: it marshals the payload, optionally attaches Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, lines 133-150), and issues `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

**What protects it.** Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44-54`), which tests against a set of CIDRs parsed once at startup — loopback, RFC-1918, link-local incl. `169.254.169.254` (cloud IMDS), and the IPv6 equivalents (`internal/webhook/validate.go:14-36`):

1. **Dial-time enforcement** — the shared `safeClient` uses a `Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). It resolves the host and refuses the connection if *any* resolved address is reserved (`internal/webhook/webhook.go:59-77`). Because the check runs at dial time rather than at configuration time, it also defeats DNS rebinding.
2. **Config-time validation** — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-`http(s)` schemes and reserved-resolving hostnames when a user saves a webhook, returning a gRPC `InvalidArgument` (`server/router/api/v1/user_service_webhooks.go:74,161,182`).

One caveat worth noting: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits both layers when true, for self-hosted setups targeting LAN services. I found no code in the repo that ever sets it, so it is effectively always `false` (protection on) unless something outside this tree assigns it.
