The first three `Dispatch*` methods all funnel through `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which loads the creator's configured hooks via `s.Store.GetUserWebhooks` and sets `payload.URL = hook.Url`. That plus the comment variant call `webhook.PostAsync` (`memo_service_webhooks.go:43,71`), which only enqueues onto a 128-slot channel; four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it. **`webhook.Post` (`internal/webhook/webhook.go:120`) is the single function every path converges on before the wire** — it marshals the body, optionally signs it, and issues `safeClient.Do(req)` at line 152.

One caveat on "single": there is a *second*, unrelated outbound family. `GetLinkMetadata` and `BatchGetLinkMetadata` (`memo_service_link_metadata.go:14,19`) fetch a URL supplied in the request itself, converging on `getLinkMetadata` → `fetchHTMLMeta` = `httpgetter.GetHTMLMeta` (`memo_service.go:28`). Both are in the unauthenticated allowlist (`acl_config.go:36-37`). That URL is per-request rather than user-*configured*, so I read it as outside the question's scope — but it does not pass through `webhook.Post` or its SSRF-guarded client.
