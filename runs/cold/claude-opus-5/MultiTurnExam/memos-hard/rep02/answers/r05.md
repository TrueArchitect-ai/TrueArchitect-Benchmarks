**Premise correction: there is no GraphQL in this repository.** A case-insensitive grep for `graphql|gqlgen|apollo|.graphql` across Go sources, `go.mod`, TypeScript/TSX, and JSON config returns zero hits — no schema file, no resolver layer, no client library on either the server or the web side.

**Actual API surface: Protocol Buffers / gRPC, exposed over three transports.**

The schema of record is the set of `.proto` service definitions in `proto/api/v1/` — `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus `common.proto`. A parallel `proto/store/` tree defines persisted payload messages (e.g. the `MemoPayload` used for derived metadata). API design follows Google's AIPs, per `proto/api/v1/README.md`.

Code generation is driven by buf (`proto/buf.gen.yaml`, `buf.yaml`, `buf.lock`) with five server-side plugins plus one for the frontend, all emitting into `proto/gen/` (and `web/src/types/proto` for TypeScript):

- `protocolbuffers/go` — message types
- `grpc/go` — gRPC service stubs
- `connectrpc/go` — Connect handlers (`proto/gen/api/v1/apiv1connect/`)
- `grpc-ecosystem/gateway` — REST/JSON transcoding (`*.pb.gw.go`)
- `community/google-gnostic-openapi` — an OpenAPI document, embedded via `proto/openapi_embed.go`
- `bufbuild/es` — TypeScript types for the web client

At runtime, `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`) mounts two of these onto Echo: the **gRPC-Gateway** mux for REST-style JSON calls (`v1.go:95`), and **Connect** handlers for browser clients — replacing grpc-web — served on the `/memos.api.v1.*` path group with a request-size cap (`v1.go:131-144`). Both share one authorizer so auth policy has a single source of truth (`v1.go:67`).

So the equivalent of "where the schema is defined" is `proto/api/v1/*.proto`; the closest analogue to a queryable public schema document is the generated OpenAPI spec rather than a GraphQL SDL.
