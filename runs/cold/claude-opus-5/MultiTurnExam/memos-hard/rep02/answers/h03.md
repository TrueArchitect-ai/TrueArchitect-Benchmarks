**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- **Abstraction — `internal/idp`**: the whole package is one file, `internal/idp/idp.go`, defining the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`). Note this is a shared *result type* rather than a Go interface — there is no `IdentityProvider` interface declared anywhere; the abstraction is the normalized user-info shape every provider must produce.

- **Implementation — `internal/idp/oauth2`**: `internal/idp/oauth2/oauth2.go` is the only concrete provider that ships. It defines `IdentityProvider` backed by `storepb.OAuth2Config` (line 20), with `NewIdentityProvider` validating required fields (line 27), `ExchangeToken` performing the authorization-code exchange with optional PKCE `code_verifier` (line 47), and `UserInfo` calling the userinfo endpoint and mapping arbitrary claims into `idp.IdentityProviderUserInfo` via the configured `FieldMapping` (line 83).

Wiring confirms it's the sole option: `resolveSSOIdentity` in `server/router/api/v1/auth_service_sso.go:119-134` branches only on `storepb.IdentityProvider_OAUTH2` and constructs `oauth2.NewIdentityProvider`. The store proto's provider-type enum has no other variant in use, so an unmatched type would leave `userInfo` nil.
