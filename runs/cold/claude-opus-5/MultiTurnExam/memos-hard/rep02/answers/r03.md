**Premise correction: there is no nightly database-cleanup job, and the cron scheduler has no registered jobs at all — so there is no time to report.**

Two separate corrections:

1. **The cron scheduler is never used in production.** `internal/scheduler` is a complete, working package — cron-expression parsing (`internal/scheduler/parser.go:30`), `Register`/`Start`/`Stop` (`internal/scheduler/scheduler.go:70,91,169`), timezone and middleware options (`Recovery`, `Logging`, `Timeout` in `internal/scheduler/middleware.go`) — but nothing imports it. Grepping for `internal/scheduler` across the tree yields exactly two importers, both inside the package's own test files: `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. `scheduler.New()` and `Register(&scheduler.Job{...})` are called only there. The server never constructs a `Scheduler`, so no cron expression is ever registered or evaluated at runtime.

2. **There is no database-cleanup job to schedule.** No vacuum, purge, prune, or retention routine exists. The only background work the server actually starts is the S3 presign refresher — `startBackgroundRunners` creates and runs `s3presign.Runner` (`server/server.go:162-171`), which is driven by a plain `time.Ticker` at a 12-hour interval (`server/runner/s3persign/runner.go` → `server/runner/s3presign/runner.go:26,29-40`), not by the cron scheduler and not at a wall-clock time.

Deletion cleanup in this codebase is **event-driven, not scheduled**: it happens inline in the request that triggers it — the transactional cascade in `DeleteUser` (`store/db/sqlite/user_delete.go`, and the Postgres/MySQL peers), memo deletion handling relations and attachments (`server/router/api/v1/memo_service.go:579`), and S3 object cleanup during attachment deletion (`store/attachment.go:171`).

The closest thing to a recurring "cleanup" is the in-memory cache's expiry sweep — `cleanupLoop` on a 5-minute `CleanupInterval` (`store/cache/cache.go:60,83`) — but that evicts cache entries, touches no database, and again uses a ticker rather than cron.
