**Premise correction: neither. There is no message broker in this repository — no NATS, no RabbitMQ, no AMQP, no Kafka.** A case-insensitive grep for `nats`, `rabbitmq`, `amqp`, `kafka`, and `streadway` across all Go sources, `go.mod`, and `go.sum` returns zero hits. There is no external queue, and therefore no queue declaration, exchange, subject, or connection config anywhere.

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool, entirely inside `internal/webhook/webhook.go`.**

- **The "queue"** is a package-level buffered channel holding 128 payloads:
  `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`.

- **The "workers"** are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over the channel and calls `Post` for every payload, logging a warning on failure:
  ```go
  for range 4 {
      go func() {
          for payload := range asyncPostQueue {
              if err := Post(payload); err != nil { slog.Warn(...) }
          }
      }()
  }
  ```

- **The "producer"** is `PostAsync` (`internal/webhook/webhook.go:184-196`), called from the memo dispatchers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

Consequences of it being a channel rather than a broker, all visible in the code:

1. **Overflow is dropped, not persisted.** `PostAsync` uses a non-blocking `select` with a `default` branch that logs `"Dropped webhook dispatch because the async queue is full"` (`internal/webhook/webhook.go:189-195`). A full queue silently loses events.
2. **No durability.** The queue lives in process memory; anything still buffered at shutdown is lost. Nothing drains `asyncPostQueue` during `Server.Shutdown` (`server/server.go:134-151`), and the workers are not tracked by `backgroundRunnerWG`.
3. **No retry or dead-lettering.** `Post` failures are logged and discarded (`internal/webhook/webhook.go:46-51`); there is no redelivery path.
4. **Per-process, not shared.** In a multi-replica deployment each instance has its own independent channel and workers — there is no cross-instance coordination.

Actual delivery happens in `Post` (`internal/webhook/webhook.go:120`), which sends via `safeClient.Do(req)` at `:152` over the SSRF-guarded transport.
