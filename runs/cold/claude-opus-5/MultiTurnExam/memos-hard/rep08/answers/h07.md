Notes on the hops:

- **The avatar is not a file on disk or in object storage.** It's stored inline on the `user` row as a base64 data URI in `avatar_url`; `parseDataURI` (`server/router/fileserver/fileserver.go:737-750`) splits it with `dataURIRegex` (`:98`) into MIME type + decoded bytes. So "the data layer" here is the `user` table, not the attachment/blob path used by `serveAttachmentFile` (`:132`).
- **Caching short-circuit.** `Store.GetUser` consults `userCache` only when the lookup is by `ID` (`store/user.go:149-156`). This route looks up by `Username`, so it always falls through to `ListUsers` and hits the driver — though `ListUsers` then populates the cache (`store/user.go:142-144`).
- **Auth hop is conditional.** Step 2 runs only on a private instance (no `InstanceURL`); on an open instance anonymous requests proceed straight to the user lookup (`server/router/fileserver/fileserver.go:171-181`).
- **Response guards after the data hop:** MIME allowlist check against `avatarAllowedTypes` (`server/router/fileserver/fileserver.go:201`, defined at `:75`), then `setSecurityHeaders` and `Cache-Control` (`:205-207`).
