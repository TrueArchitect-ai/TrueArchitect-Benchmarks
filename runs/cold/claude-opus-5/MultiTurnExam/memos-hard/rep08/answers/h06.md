**Handlers: `MemoService.CreateMemo`, `MemoService.UpdateMemo`, `MemoService.DeleteMemo`, `MemoService.CreateMemoComment`, `MemoService.SetMemoAttachments`, `MemoService.SetMemoRelations` — six in total; convergence: `webhook.PostAsync` — `internal/webhook/webhook.go:184` (which hands off to `webhook.Post`, `internal/webhook/webhook.go:120`, where the request is actually sent).**

The six paths, each ending in a user-configured `hook.Url` from `s.Store.GetUserWebhooks`:

| Handler | Definition | Dispatch call |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:70` | `DispatchMemoCreatedWebhook` at `memo_service.go:157` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:401` | `dispatchMemoUpdatedSideEffects` at `memo_service.go:513` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:518` | `DispatchMemoDeletedWebhook` at `memo_service.go:562` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` at `memo_service_comments.go:119` |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:16` | `dispatchMemoUpdatedSideEffects` at `memo_attachment_service.go:48` |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:16` | `dispatchMemoUpdatedSideEffects` at `memo_relation_service.go:48` |

The last three of those go through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `:67` — so `SetMemoAttachments` and `SetMemoRelations` emit `memos.memo.updated` webhooks even though neither is a "memo update" RPC by name.

**Convergence.** All six funnel into the dispatchers in `server/router/api/v1/memo_service_webhooks.go` — `DispatchMemoCreated/Updated/Deleted` all delegate to `dispatchMemoRelatedWebhook` (`:48`), while comments use `DispatchMemoCommentCreatedWebhook` (`:30`). Those two functions are the last distinct step; the single function they both reach is `webhook.PostAsync` (called at `memo_service_webhooks.go:71` and `:43`), defined at `internal/webhook/webhook.go:184`. `PostAsync` enqueues onto the 128-slot `asyncPostQueue` (`internal/webhook/webhook.go:39`), whose 4 worker goroutines (`internal/webhook/webhook.go:42-55`) call `webhook.Post` — where the actual `safeClient.Do(req)` happens (`internal/webhook/webhook.go:152`).

One note on scope: webhook URLs are validated at configuration time by `webhook.ValidateURL` in the `UserService` webhook handlers (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`), but that only performs a DNS lookup, not an outbound HTTP request, so those handlers aren't on this list.
