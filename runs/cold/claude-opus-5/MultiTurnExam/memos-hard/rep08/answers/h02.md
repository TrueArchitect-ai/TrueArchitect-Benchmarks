**`webhook.Post` — `/bench/repo/internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection is the `safeDialContext` dial-time SSRF guard on the shared client's Transport — `internal/webhook/webhook.go:59`, backed by the reserved-CIDR check `isReservedIP` in `internal/webhook/validate.go:44`.**

How it fits together:

- **Delivery path**: memo create/update/delete handlers call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:39`) drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`). Each worker calls `Post`, which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`, `internal/webhook/webhook.go:133-150`), and sends via `safeClient` with a 30s timeout (`internal/webhook/webhook.go:27,32-37`). Overflow is dropped with a warning rather than blocking (`internal/webhook/webhook.go:189-195`).

- **Protection (two layers)**:
  1. *At dial time* — `safeDialContext` (`internal/webhook/webhook.go:59-77`) resolves the host itself and refuses to connect if any resolved IP is reserved. Because this happens on every connection rather than at save time, it also defeats DNS rebinding (noted in the comment at `internal/webhook/webhook.go:30-31`).
  2. *At configuration time* — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) requires an absolute http/https URL and rejects hostnames resolving into reserved ranges; it's called when users create/update webhooks in `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

- **Blocked ranges**: `reservedCIDRs` in `internal/webhook/validate.go:14-23` — IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (explicitly covering cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`. Parsed once into `reservedNetworks` at init (`internal/webhook/validate.go:28-36`).

- **Escape hatch**: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` for self-hosted setups targeting LAN services. Note that nothing in non-test code currently sets it, so it stays `false` by default — I found no CLI flag or env binding for it in the repo.
