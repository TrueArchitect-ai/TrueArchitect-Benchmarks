**`github.com/usememos/memos/internal/idp` (`internal/idp/idp.go`); `github.com/usememos/memos/internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

Details:

- **Abstraction package** — `internal/idp/idp.go` is the whole package: it defines the single provider-neutral type `IdentityProviderUserInfo` (`internal/idp/idp.go:3-8`) with `Identifier`, `DisplayName`, `Email`, `AvatarURL`. Note it's a shared data contract, not a Go interface — there's no `IdentityProvider` interface for implementations to satisfy; concrete providers just return `*idp.IdentityProviderUserInfo`.

- **Implementation package** — `internal/idp/oauth2/oauth2.go` ("Package oauth2 implements the OAuth2 identity provider integration", line 1). It provides `IdentityProvider` wrapping `*storepb.OAuth2Config` (line 20), `NewIdentityProvider` with required-field validation (line 27), `ExchangeToken` with optional PKCE `code_verifier` (line 45), and `UserInfo`, which fetches the userinfo endpoint with a 10s timeout and maps claims onto `idp.IdentityProviderUserInfo` via the configured `FieldMapping` (line 83).

- **It's the only one that ships** — the store proto enumerates exactly one provider type, `OAUTH2` (`proto/store/idp.proto:9-14`), and the config oneof holds only `OAuth2Config` (`proto/store/idp.proto:21-25`). The SSO handler branches on that single type at `server/router/api/v1/auth_service_sso.go:120-134`, calling `oauth2.NewIdentityProvider` → `ExchangeToken` → `UserInfo`. (OIDC providers are supported only insofar as they're configured as generic OAuth2 endpoints; there's no separate OIDC/SAML/LDAP package.)
