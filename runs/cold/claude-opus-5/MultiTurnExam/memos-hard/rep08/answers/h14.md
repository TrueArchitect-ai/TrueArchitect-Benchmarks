**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: `CreateMemo` (`server/router/api/v1/memo_service.go:108`) and `UpdateMemo` when the update mask includes `content` (`server/router/api/v1/memo_service.go:447`). Extracted: `Tags` plus the five `MemoPayload.Property` fields — `title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`.**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns only two fields:
```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```
Note it deliberately leaves `Payload.Location` alone — that one *is* user-set (`proto/store/memo.proto:24-28`), and `CreateMemo` overlays it separately at `server/router/api/v1/memo_service.go:110-112`.

The actual extraction is a single goldmark AST walk in `ExtractAll` (`internal/markdown/markdown.go:356-420`), which is why it exists alongside the narrower `ExtractTags`/`ExtractProperties` — one parse instead of several.

**Triggers (all of them).**
1. `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before `s.Store.CreateMemo` at `:114`.
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, inside the `if path == "content"` branch of the update-mask loop (`:435-452`); the fresh payload is written to `update.Payload` at `:452`. Other mask paths (visibility, pinned, etc.) do **not** recompute, which is correct since they don't change content.
3. `CreateMemoComment` — indirectly, since it delegates to `s.CreateMemo` at `server/router/api/v1/memo_service_comments.go:56`.

`SetMemoAttachments` and `SetMemoRelations` don't recompute (they don't touch content). There is also a bulk backfill path, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), which would rebuild every memo's payload in batches of 100 — but nothing constructs or calls it, so it never runs.

**What's extracted** (per `internal/markdown/markdown.go:371-419`, written into `storepb.MemoPayload_Property`, declared `proto/store/memo.proto:15-22`):

| Field | Derivation |
|---|---|
| `tags` | `#tag` nodes collected during the walk (`:376-378`), deduplicated preserving original case via `uniquePreserveCase` (`:418`) |
| `title` | text of the first block-level child of the document if it's an H1 heading (`:383-389`) |
| `has_link` | any `gast.KindLink` node (`:392-393`) |
| `has_code` | any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan` (`:395-396`) |
| `has_task_list` | any `east.KindTaskCheckBox` (`:398-399`) |
| `has_incomplete_tasks` | a task checkbox with `IsChecked == false` (`:400-404`) |

`ExtractAll` also gathers `Mentions`, but `RebuildMemoPayload` discards them — mentions are consumed separately for notifications (`server/router/api/v1/memo_mention_helpers.go:32`).

**Consumers (the "lists/previews" use).** The payload is surfaced to the API at `server/router/api/v1/memo_service_converter.go:48-49` (`memoMessage.Tags`, `convertMemoPropertyFromStore`), and aggregated for user stats at `server/router/api/v1/user_service_stats.go:138-152` and `:254-268`.

One related-but-distinct piece: the memo **snippet** is also derived from content, but it's computed at read time in the converter (`getMemoContentSnippet` → `GenerateSnippet`, `server/router/api/v1/memo_service_converter.go:76` and `:225`/`:248`; helper at `server/router/api/v1/memo_service_webhooks.go:83`) rather than stored in the payload.
