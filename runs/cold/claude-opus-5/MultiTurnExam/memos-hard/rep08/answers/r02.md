**Premise correction: this repository has no rate-limiting middleware at all — per-user or otherwise — so there is no registration site and no request limits to report.**

What I checked:

1. **No rate-limiting code or dependency.** A case-insensitive grep across all Go sources for `ratelimit`, `rate_limit`, `rate limit`, `throttl`, `golang.org/x/time/rate`, and `Limiter` returns exactly one hit, and it's an aspirational comment in documentation, not code: `internal/email/doc.go:86` — `//   - Rate limit email sending to prevent abuse`. `go.mod` contains no rate-limiting library (no `golang.org/x/time`, no `echo` rate-limiter, no `tollbooth`/`ulule/limiter`).

2. **The Echo middleware stack has two entries, neither of them a limiter.** `server/server.go:51-52`:
   ```go
   echoServer.Use(middleware.Recover())
   echoServer.Use(newCORSMiddleware(profile))
   ```
   Those are the only `echoServer.Use(...)` calls in the codebase. Echo ships a `middleware.RateLimiter`, but it is never referenced here.

3. **The Connect/gRPC interceptor chain has three entries, none a limiter.** `server/router/api/v1/v1.go:133-138` registers `NewMetadataInterceptor()` (header→metadata), `NewLoggingInterceptor(logStacktraces)`, and `NewAuthInterceptor(authorizer)` — all defined in `server/router/api/v1/connect_interceptors.go` (`:25`, `:103`, `:213`). No throttling interceptor exists.

4. **Other route surfaces are unprotected too.** The file server (`server/router/fileserver/fileserver.go:121-125`), RSS (`server/router/rss/rss.go`), and MCP (`server/router/mcp`) register handlers directly with no limiter wrapper.

What does exist — and may be what the question is reaching for — are *concurrency* and *size* bounds, which are a different mechanism (they cap simultaneous work or payload size, not request frequency, and none are per-user):

- **Concurrency semaphores**: thumbnail generation capped at 3 and image processing at 2 in `server/router/api/v1/v1.go:57-58`; a separate `thumbnailSemaphore` in the file server (`server/router/fileserver/fileserver.go:107`, `:116`).
- **Webhook dispatch backpressure**: a 128-slot queue drained by 4 workers, dropping overflow (`internal/webhook/webhook.go:39-55`, `:189-195`).
- **Pagination and content caps**: `MaxPageSize` / `normalizePageSize` in the memo service, and the instance-level `ContentLengthLimit` enforced at `server/router/api/v1/memo_service.go:104` and `:443`.

If per-user API rate limiting is a requirement, it would need to be added — the natural insertion points would be a new interceptor in the chain at `server/router/api/v1/v1.go:133`, or an `echoServer.Use(...)` alongside `server/server.go:51-52` to also cover the file server, RSS, and MCP surfaces.
