**Premise correction: there is no nightly database-cleanup job. No cron job of any kind is registered anywhere in this codebase, and the cron scheduler package is never wired into the running server.**

The `"0 2 * * *"` ("2 AM daily") schedule that likely prompted the question appears only in illustrative material, never in executable production code:

- `internal/scheduler/doc.go:15-16` — a package doc comment showing a hypothetical job named `daily-cleanup` on `"0 2 * * *"`, with the body commented as `// Your cleanup logic here`. It's inside a `//` comment block, so it compiles to nothing.
- `internal/scheduler/example_test.go:99-100` — a test example with `Name: "cleanup"`, `Schedule: "0 2 * * *"`.
- `internal/scheduler/parser_test.go:82` — the same expression as a parser test case.

Evidence the scheduler is entirely unused in production:

1. **No production import.** `grep -rn "usememos/memos/internal/scheduler"` across all Go files returns two hits, both test files in the package's own directory: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. Nothing under `cmd/`, `server/`, or `store/` imports it.
2. **No registration.** `scheduler.New(...)` and `(*Scheduler).Register(...)` (`internal/scheduler/scheduler.go`) are never called outside the package's tests, so the job registry is always empty.
3. **The package is self-contained scaffolding** — `scheduler.go`, `job.go`, `parser.go`, `middleware.go` plus docs and tests — built but not adopted.

**What actually runs on a schedule instead.** The server's only recurring background work is the S3 presigned-URL refresh runner, which uses a plain `time.Ticker` rather than cron: `runnerInterval = time.Hour * 12` at `server/runner/s3presign/runner.go:27`, driven by the loop at `:29-41`, and wired at `server/server.go:162-171` (with one immediate pass at `:163`). Its work is re-signing S3 attachment URLs, not database cleanup, and its cadence is "every 12 hours from process start" — not a fixed wall-clock time.

The closest thing to periodic cleanup is the in-memory cache sweeper: `CleanupInterval: 5 * time.Minute` in `store/store.go:42`, which expires cache entries — it does not touch the database.

Deletion cleanup in this codebase is event-driven, not scheduled: e.g. attachment storage cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`) and the transactional cascade in `store/db/*/user_delete.go`.
