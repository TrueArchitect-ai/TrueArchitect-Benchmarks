**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive search for "redis" across all `.go`, `go.mod`, YAML, JSON, and Markdown files returns zero hits — no client dependency, no config key, no connection string. The cache layer is entirely in-process.

**Actual mechanism:**

- **Implementation**: `store/cache/cache.go` — a hand-rolled, thread-safe in-memory cache. `Cache` (line 66) is backed by a `sync.Map` plus an `atomic.Int64` item counter; each entry is an `item{value, expiration, size}` (line 34). No network layer, no serialization, no external process. It lives and dies with the server process.
- **Where it's configured**: `store.New` in `/bench/repo/store/store.go:39-45` builds one `cache.Config` and uses it for all three caches:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  Then instantiates `instanceSettingCache`, `userCache`, and `userSettingCache` via `cache.New(cacheConfig)` (`store.go:51-53`). These values are hard-coded — there is no flag, env var, or settings key to tune them. `cache.DefaultConfig()` (`cache/cache.go:56`) declares the same three values but isn't what the store uses.

**TTL for user entries: 10 minutes**, with these specifics:

- Every write goes through `Store` helpers that call `s.userCache.Set(ctx, userCacheKey(user.ID), user)` — `/bench/repo/store/user.go:98, 122, 132, 143, 167`. `Cache.Set` (`cache/cache.go:92`) always applies `c.config.DefaultTTL`; nothing in the user path calls `SetWithTTL` with a custom value, so 10 minutes applies uniformly.
- Keys are `userCacheKey(userID)` (`store/user.go:88`) — **ID-keyed only**. `Store.GetUser` (`store/user.go:148`) therefore only reads the cache when the lookup is by ID; lookups by username or email always hit the database (relevant to the avatar path in h07).
- Expiry is enforced two ways: lazily on read, where `Get` deletes an entry whose `expiration` has passed and returns a miss (`cache/cache.go:123-131`), and proactively by `cleanupLoop`, a goroutine started in `cache.New` (line 82) that sweeps every 5 minutes.
- A 1000-item ceiling triggers `cleanupOldest()` on insert (`cache/cache.go:117-119`), so entries can be evicted before their TTL expires.
- Invalidation on user deletion is explicit via `Store.deleteUserCache` (`/bench/repo/store/user_delete.go:39`), called from `Store.DeleteUser` (`store/user.go:178`).

One consequence worth noting: because this cache is per-process and non-shared, a multi-replica deployment would give each replica its own independent copy with no cross-instance invalidation.
