**Premise correction: neither. There is no message broker in this repository at all** — a case-insensitive grep across every Go file and `go.mod` for `nats`, `rabbit`, `amqp`, `kafka`, `pubsub`, and `sqs` returns zero hits. No broker client is a dependency, and no queue is declared anywhere.

**Actual mechanism — an in-process Go channel with a fixed worker pool, all in `/bench/repo/internal/webhook/webhook.go`:**

- **The "queue"** is a package-level buffered channel holding 128 payloads:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  declared at `internal/webhook/webhook.go:39`. It's process-local memory — no persistence, no network, no external service.
- **The "workers"** are 4 goroutines started in the package's `init()` (`webhook.go:42-55`). Each loops over `asyncPostQueue` and calls `Post(payload)` for every item, logging failures with `slog.Warn`. Because they're started in `init()`, they spin up on package import rather than by any explicit server-startup wiring.
- **Enqueue** happens in `PostAsync` (`webhook.go:184-196`) via a non-blocking `select` with a `default` arm. When the buffer is full the payload is **silently dropped** with a warning — there's no backpressure on the caller and no retry.
- **Producers** are the memo webhook dispatchers at `/bench/repo/server/router/api/v1/memo_service_webhooks.go:43` and `:71`, reached from the `CreateMemo`/`UpdateMemo`/`DeleteMemo`/`CreateMemoComment`/`SetMemoAttachments`/`SetMemoRelations` handlers.
- **Delivery** is a plain HTTP POST via the shared `safeClient` in `Post` (`webhook.go:152`), with a 30-second timeout (`webhook.go:27`) and the SSRF dial guard described earlier.

Practical consequences of this design, worth being aware of: undelivered webhooks are lost on process exit (nothing drains the channel at shutdown — `Server.Shutdown` doesn't touch it), each replica in a multi-instance deployment has its own independent queue, and there is no retry, dead-letter path, or delivery-attempt record anywhere in the code.
