Notes on each hop:

- **Route wiring**: `FileServerService.RegisterRoutes` puts the handler under the `/file` group (`fileserver.go:121-125`); the service itself is constructed and registered during server setup at `server/server.go:81-82`.
- **`serveUserAvatar`** (`fileserver.go:168`) first gates access: if `s.Profile.AllowAnonymous()` is false, it requires a resolvable viewer via `s.getCurrentUser` and returns 401 otherwise (lines 171–180). It then takes the `:identifier` path param as a **username**.
- **`getUserByUsername`** (`fileserver.go:715`) is a one-line adapter: `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`.
- **`Store.GetUser`** (`store/user.go:148`) consults `userCache` only when the find is by **ID**; since this lookup is by username, it always falls through to `ListUsers`, then warms the cache with the result (line 167).
- **`Store.ListUsers`** (`store/user.go:136`) delegates to `s.driver.ListUsers` and caches each row.
- **Driver layer**: the dialect implementation builds the `WHERE` clause and runs the query — `store/db/sqlite/user.go:88` (and the postgres/mysql equivalents). `avatar_url` is in both the SELECT list (line 158) and the `rows.Scan` into `user.AvatarURL` (line 188).
- **Back out**: the avatar is not a blob on disk or S3 — it's a **data URI stored in the `user.avatar_url` column**. `serveUserAvatar` decodes it with `parseDataURI` (`fileserver.go:737`), rejects any MIME type not in `avatarAllowedTypes` (`fileserver.go:75`, line 201), sets security headers plus `Cache-Control: public, max-age=3600`, and writes the bytes with `c.Blob` (line 207).
