**Explicit Go code — a per-driver `DELETE FROM reaction` inside the delete-user transaction. There is no database-level rule; the `reaction` table has no foreign key at all.**

What I checked:

**1. The delete path.** `Store.DeleteUser` (`/bench/repo/store/user.go:170`) just delegates to `s.driver.DeleteUser`. Each driver implements it as one transaction that collects targets then deletes them: `/bench/repo/store/db/sqlite/user_delete.go:29`, `/bench/repo/store/db/postgres/user_delete.go`, `/bench/repo/store/db/mysql/user_delete.go`.

**2. Two explicit reaction deletes** in `deleteUserTargetsTx` (`sqlite/user_delete.go:92-127`), both before the memo/user rows go:
- `deleteReactionsByContentIDsTx` (line 96 → defined line 380) — `DELETE FROM reaction WHERE content_id IN (...)`, batched at 500, removing *everyone's* reactions on the deleted user's memos. Content IDs are built as `"memos/" + memo.UID` (line 512), matching how reactions store `content_id`.
- `deleteReactionsByCreatorTx` (line 102 → defined line 400) — `DELETE FROM reaction WHERE creator_id = ?`, removing the user's own reactions on other people's memos.

Mirrored identically in the other drivers: `postgres/user_delete.go:102, 383, 400` and `mysql/user_delete.go:102, 420, 437`.

**3. No DB-level rule.** The `reaction` table DDL has no `REFERENCES`/`ON DELETE CASCADE` in any dialect — `/bench/repo/store/migration/sqlite/LATEST.sql:92-99`, `/bench/repo/store/migration/postgres/LATEST.sql:91-98`, `/bench/repo/store/migration/mysql/LATEST.sql:91-98`. Grepping all three `LATEST.sql` files for `FOREIGN KEY|REFERENCES` yields exactly one hit each, and it's on `memo_share.memo_id`, not `reaction`. Additionally the SQLite driver opens the DB with `_pragma=foreign_keys(0)` (`/bench/repo/store/db/sqlite/sqlite.go:53`), so even a declared FK wouldn't enforce there. No triggers exist for this either.

**4. Test confirmation.** `/bench/repo/store/test/user_delete_test.go` seeds reactions by the doomed user and by a peer (lines 97–112), then after deletion asserts only the unrelated peer reaction survives (lines 217–220) — verifying the Go-side deletion is what does the work.
