Details:

- **Abstraction package**: `internal/idp` (`/bench/repo/internal/idp/idp.go`) is deliberately thin — it defines only the shared result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`), the normalized shape every provider must produce. Note there is no Go `interface` here; the "abstraction" is this common user-info struct plus the proto-level `IdentityProvider` / `IdentityProviderConfig` types, where `IdentityProviderConfig` is a `oneof` with a single arm (`proto/proto/store/idp.proto`) and the `Type` enum has exactly one non-zero value, `OAUTH2`.
- **Implementation package**: `internal/idp/oauth2` (`/bench/repo/internal/idp/oauth2/oauth2.go`) — the only concrete provider that ships. `NewIdentityProvider` validates required config fields (line ~27), `ExchangeToken` performs the code exchange with optional PKCE `code_verifier` (line ~45), and `UserInfo` fetches the userinfo endpoint and maps fields via the configured `FieldMapping` into `idp.IdentityProviderUserInfo`.
- **Where they meet**: `resolveSSOIdentity` in `/bench/repo/server/router/api/v1/auth_service_sso.go:104` branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` (line 120) and constructs the OAuth2 provider — a single `if`, not a registry, because OAuth2 is the only case. Generic OIDC/SAML would require a new arm here plus a new proto config variant.
