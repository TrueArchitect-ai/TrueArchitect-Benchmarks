Two things worth flagging:

- **`canViewerAccessMemo` is duplicated verbatim in two packages** — `server/router/api/v1/user_service_notifications.go:302` and `server/notification/email.go:306`. The bodies are identical except that the API copy uses `isSuperUser(viewer)` while the email copy compares `viewer.Role == store.RoleAdmin` directly. Any rule change has to be made in both.
- **Two enforcement styles coexist.** Single-memo paths check an already-loaded `memo.Visibility` after the fetch (`checkMemoReadAccess`, `checkAttachmentPermission`, the reaction gates); list paths instead push the constraint down into the SQL query via `FindMemo.VisibilityList` or an appended CEL filter (`memo_service.go:221`, `user_service_stats.go`, RSS, sitemap). The share-token path at `memo_share_service.go:151` and `fileserver.go:684-690` is a deliberate third mode that grants access to PRIVATE/PROTECTED memos without a session.
