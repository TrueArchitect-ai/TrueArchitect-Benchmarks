**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

Details:

- **Abstraction — `internal/idp`**: `internal/idp/idp.go` is the whole package: it defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every implementation normalizes to. Note it's a shared data contract, not a Go `interface` — there is no `IdentityProvider` interface type. The provider *shape* (type enum + config oneof) is declared in the schema at `proto/store/idp.proto:7-25`, with `IdentityProvider.Type` currently having exactly one non-unspecified value, `OAUTH2`, and `IdentityProviderConfig.config` a oneof holding only `oauth2_config`.

- **Implementation — `internal/idp/oauth2`**: `internal/idp/oauth2/oauth2.go` is the only concrete protocol that ships. `NewIdentityProvider` (line 27) validates the required config fields (`clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, `fieldMapping.identifier`); `ExchangeToken` (line 47) runs the authorization-code exchange via `golang.org/x/oauth2`, with optional PKCE by passing `code_verifier`; `UserInfo` (line 83) fetches the userinfo endpoint under a 10s timeout and maps raw claims into `idp.IdentityProviderUserInfo` using the configured `FieldMapping`.

- **Dispatch site**: `server/router/api/v1/auth_service_sso.go:119-134` branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` and constructs the oauth2 provider — the single branch confirms OAuth2 is the only implementation wired in. An identifier-filter regex is then applied to the returned identifier (`auth_service_sso.go:136-146`).

No OIDC-, SAML-, or LDAP-specific package exists in the repo; OIDC providers are supported only insofar as they can be configured as generic OAuth2 with a userinfo URL.
