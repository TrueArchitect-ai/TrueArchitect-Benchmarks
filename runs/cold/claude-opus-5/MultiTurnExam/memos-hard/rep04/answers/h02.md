**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); SSRF protection is a dial-time reserved-IP check, `safeDialContext` — `internal/webhook/webhook.go:59`, backed by `isReservedIP`/`reservedCIDRs` — `internal/webhook/validate.go:14-54`**

How it fits together:

- **Trigger → delivery**: memo create/update/delete and comment-created call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43,71`), which enqueues onto a bounded 128-slot channel (`webhook.go:39`, drops with a warning when full). Four worker goroutines started in `init()` (`webhook.go:42-55`) drain the queue and call `Post`, which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook.go:133-150`), and performs the POST via the shared `safeClient` (`webhook.go:152`).

- **Primary protection (dial time)**: `safeClient`'s `Transport.DialContext` is `safeDialContext` (`webhook.go:32-37`). It splits host/port, resolves the hostname itself, and rejects the connection if *any* returned IP falls in a reserved range (`webhook.go:59-77`). Because the check happens at dial time on every request rather than only at save time, it also defeats DNS rebinding — the comment at `webhook.go:29-31` states this explicitly.

- **Secondary protection (save time)**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74,161,182`). It enforces an absolute URL, an http/https scheme, and that the hostname doesn't resolve to a reserved IP, returning gRPC `InvalidArgument`.

- **Blocked ranges** (`internal/webhook/validate.go:14-23`): IPv4 loopback `127/8`, RFC-1918 `10/8`, `172.16/12`, `192.168/16`, link-local `169.254/16` (explicitly covering cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`. Parsed once into `reservedNetworks` at init.

One thing worth flagging: the `AllowPrivateIPs` escape hatch (`internal/webhook/validate.go:41`) disables both checks when true, but nothing in the repo ever assigns it — no flag, env var, or config wires it up, so it is permanently `false` in the shipped binary. Also note `safeDialContext` resolves the host and then dials `host:port` by name rather than dialing a validated IP, so there is a small TOCTOU window between the check and the connection.
