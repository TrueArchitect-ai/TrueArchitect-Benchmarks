**Premise correction: this project has no GraphQL. There is no schema file, no resolver layer, and no GraphQL dependency** — a repo-wide grep for `graphql`, `gqlgen`, `.graphql`, and `.gql` (across Go, TypeScript, `go.mod`, and JSON, excluding `node_modules`) returns zero matches, and `find` turns up no `*.graphql`/`*.gql` files.

**Actual API surface — Protobuf/gRPC, exposed three ways from one set of `.proto` definitions:**

- **Schema source of truth** — `proto/api/v1/*.proto`: `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `ai_service.proto`, plus `common.proto`. Persistence-side messages live in `proto/store/*.proto`. Codegen is driven by buf (`proto/buf.gen.yaml`, `proto/buf.yaml`) into `proto/gen/`, and TypeScript client types into `web/src/types/proto`.

- **Three runtime surfaces**, all backed by the same `APIV1Service` implementation and wired in `RegisterGateway` (`server/router/api/v1/v1.go`):
  1. **REST/JSON via gRPC-Gateway** — `runtime.NewServeMux` with the eight `Register*ServiceHandlerServer` calls (`v1.go:96-121`), mounted on `/api/v1/*` and `/file/*` (`v1.go:127-128`), wrapped in a request-size limit.
  2. **Connect RPC** — for browser clients, replacing grpc-web, with metadata/logging/recovery/auth interceptors (`v1.go:132-140`); generated code in `proto/gen/api/v1/apiv1connect/`.
  3. **Server-Sent Events** — `RegisterSSERoutes` (`v1.go:124`), backed by `SSEHub` (`server/router/api/v1/sse_hub.go`).

- **Machine-readable spec** — an **OpenAPI** document, not a GraphQL SDL: generated by the gnostic-openapi buf plugin into `proto/gen/openapi.yaml` and embedded via `//go:embed` in `proto/openapi_embed.go`.

- **Non-RPC HTTP surfaces** that sit outside the proto definitions: the file server (`server/router/fileserver/fileserver.go`), RSS feeds (`server/router/rss/rss.go`), the frontend/SSR router (`server/router/frontend/frontend.go`), and an MCP server (`server/router/mcp/`).
