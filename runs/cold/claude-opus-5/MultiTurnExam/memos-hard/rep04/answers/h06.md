**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`; convergence function — `webhook.Post` at `internal/webhook/webhook.go:120` (actual send at `webhook.go:152`)**

The six RPC handlers, with their paths:

| Handler | Path to delivery |
|---|---|
| `CreateMemo` — `server/router/api/v1/memo_service.go:70` | → `DispatchMemoCreatedWebhook` (`memo_service.go:157`) |
| `UpdateMemo` — `memo_service.go:401` | → `dispatchMemoUpdatedSideEffects` (`memo_service.go:513`) → `DispatchMemoUpdatedWebhook` (`memo_update_helpers.go:67`) |
| `DeleteMemo` — `memo_service.go:518` | → `DispatchMemoDeletedWebhook` (`memo_service.go:562`) |
| `CreateMemoComment` — `memo_service_comments.go:20` | → `DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`) |
| `SetMemoAttachments` — `memo_attachment_service.go:16` | → `dispatchMemoUpdatedSideEffects` (`memo_attachment_service.go:48`) → `DispatchMemoUpdatedWebhook` |
| `SetMemoRelations` — `memo_relation_service.go:16` | → `dispatchMemoUpdatedSideEffects` (`memo_relation_service.go:48`) → `DispatchMemoUpdatedWebhook` |

All four `Dispatch*Webhook` methods (`server/router/api/v1/memo_service_webhooks.go:15,20,25,30`) load the creator's webhooks via `Store.GetUserWebhooks`, set `payload.URL = hook.Url`, and call `webhook.PostAsync` (`memo_service_webhooks.go:43,71`). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a 128-slot channel; the four worker goroutines started in `init()` (`webhook.go:42-55`) are what call **`webhook.Post`** — the single function where every path converges and where the request is built, optionally HMAC-signed, and sent via `safeClient.Do` (`webhook.go:152`). The URL is user-configured through `CreateUserWebhook`/`UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53,106`), which validate it with `webhook.ValidateURL`.

Two notes worth having:

- Because delivery is asynchronous, the outbound request happens on a worker goroutine after the RPC has already returned — the handler is the trigger, not the caller of `Post` on its own stack.
- There is a **second, unrelated** outbound-HTTP-to-user-URL path that does *not* converge on `webhook.Post`: `GetLinkMetadata` and `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go:14,19`) fetch a URL taken straight from the request via `getLinkMetadata` → `fetchHTMLMeta` → `httpgetter.GetHTMLMeta` (`memo_service_link_metadata.go:46`, `server/router/api/v1/memo_service.go:28`, `internal/httpgetter/html_meta.go`). That URL is request-supplied rather than stored configuration, which is why I've listed it separately — but if your definition of "user-configured URL" includes it, those two handlers belong on the list as well.
