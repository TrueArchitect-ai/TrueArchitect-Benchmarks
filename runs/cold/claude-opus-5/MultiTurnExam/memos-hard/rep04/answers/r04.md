**Premise correction: neither — there is no message broker in this repository. No NATS, RabbitMQ, AMQP, Kafka, or NSQ client appears in any Go source, `go.mod`, or `go.sum`** (a case-insensitive grep for all of those terms returns only one false positive: the substring "nSQ" inside `openMigrationSQLDB` in `store/test/migrator_upgrade_test.go`). There is no queue declaration, no exchange/subject binding, and no external queue infrastructure of any kind.

**Actual mechanism — an in-process buffered Go channel with a fixed worker pool, all in `internal/webhook/webhook.go`:**

- **The "queue"** is a package-level buffered channel with capacity 128: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`). It's declared in the same `var` block as the shared HTTP client — there's no separate declaration site or config.

- **The workers** are 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over the channel and calls `Post` (line 46), logging a warning on failure. They start when the package is first loaded, not from any explicit server-startup wiring.

- **Producing** happens via `PostAsync` (`internal/webhook/webhook.go:184-196`), called from the memo webhook dispatchers at `server/router/api/v1/memo_service_webhooks.go:43,71`. It does a **non-blocking** send: if the buffer is full, the `default` branch drops the payload and logs `"Dropped webhook dispatch because the async queue is full"` (lines 189-195).

- **Delivery** is `Post` (`internal/webhook/webhook.go:120`), which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers, and sends via `safeClient.Do` with a 30s timeout (lines 27, 152).

Operational consequences worth knowing, since they're exactly what a broker would otherwise give you: the queue is **per-process and in-memory**, so pending deliveries are lost on restart or crash; there is **no retry** — a failed `Post` is logged and discarded; there is **no dead-letter path**; overflow is **silently dropped** beyond a log line; and nothing is shared across instances in a multi-replica deployment.
