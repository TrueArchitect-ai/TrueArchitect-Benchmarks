**Premise correction: there is no nightly database-cleanup job, and the cron scheduler has no registered jobs at all — so there is no scheduled time to report.**

What I verified:

- **A cron scheduler package exists but is entirely unused in production.** `internal/scheduler` provides `New` (`internal/scheduler/scheduler.go:54`), `Register` (`:70`), `Start` (`:91`), `Stop` (`:169`), a 5-field cron parser (`internal/scheduler/parser.go`, `Schedule.Next` at `:92`), and job validation (`internal/scheduler/job.go:39`). Grepping for imports of `github.com/usememos/memos/internal/scheduler` outside the package returns only `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No production file imports it, and every `scheduler.New(...)`/`.Register(...)` call site is in that package's own tests or doc comments (`internal/scheduler/doc.go:12-28`, `example_test.go:15-17`, `scheduler_test.go:36-127`). So zero cron jobs are registered anywhere in the running server.

- **The only real background work is a fixed-interval ticker, not cron, and it isn't a cleanup job.** `startBackgroundRunners` (`server/server.go:153-174`) starts exactly one runner: the S3 presign runner, which re-signs attachment URLs immediately at startup and then every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27`, loop at `:29-41`). There's no wall-clock time associated with it — the schedule is relative to process start.

- **No cleanup/vacuum/purge job exists.** Grepping for `cleanup`/`vacuum`/`purge`/`prune` across the backend turns up only: the in-memory cache's cleanup goroutine, which runs every 5 minutes (`store/store.go:42`, `store/cache/cache.go:47`) and evicts expired cache entries — not database rows; and *synchronous, request-triggered* cleanup — cascading deletes when a memo is removed (`server/router/api/v1/memo_service.go:579`) and S3 object cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`). Also dormant is `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), a bulk memo-payload rebuild that is never constructed or called.

So: nothing in this codebase runs on a nightly (or any wall-clock) schedule. Expired sessions, soft-deleted rows, and orphaned data are not swept by a periodic job.
