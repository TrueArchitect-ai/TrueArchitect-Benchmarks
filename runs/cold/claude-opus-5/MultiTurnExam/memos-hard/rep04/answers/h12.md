How I determined it's the SQLite one and not Postgres/MySQL:

1. **The call chain ends at an interface, so static tracing alone is inconclusive.** `CreateMemo` (`server/router/api/v1/memo_service.go:115`) → `Store.CreateMemo` (`store/memo.go:109`), which validates the UID and then calls `s.driver.CreateMemo(ctx, create)` (`store/memo.go:113`). `driver` is the `store.Driver` interface, whose `CreateMemo` is declared at `store/driver.go:29` and implemented three times — `store/db/sqlite/memo.go:16`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`.

2. **Resolved the dynamic type via the factory's input.** The only place the interface value is constructed is `db.NewDBDriver` (`store/db/db.go:14`), which switches on `profile.Driver`: `"sqlite"` → `sqlite.NewDB`, `"mysql"` → `mysql.NewDB`, `"postgres"` → `postgres.NewDB`, else error (`store/db/db.go:18-27`). Confirmed via grep that `mysql.NewDB`/`postgres.NewDB`/`sqlite.NewDB` have no other call sites, so this switch is the sole binding point.

3. **Established the default value of `profile.Driver`.** In `cmd/memos/main.go`, the driver comes from viper (`main.go:43`), whose default is `"sqlite"` — set both as `viper.SetDefault("driver", "sqlite")` (`main.go:122`) and as the persistent flag default (`main.go:130`, bound at `main.go:151`). With no flags/env, `Driver == "sqlite"`.

4. **Checked that a default install doesn't fail the DSN requirement.** `sqlite.NewDB` errors out if `profile.DSN == ""` (`store/db/sqlite/sqlite.go:25-27`), but `Profile.Validate` (called at `cmd/memos/main.go:51`) fills it in for SQLite: `p.DSN = <dataDir>/memos_prod.db` (`internal/profile/profile.go:110-117`). So the default path constructs successfully.

That chain — default flag value → factory switch → single constructor → concrete receiver — is what pins the runtime type to `*sqlite.DB`.
