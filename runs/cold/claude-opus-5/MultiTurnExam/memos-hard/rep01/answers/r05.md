**Premise correction: this project has no GraphQL API.** A repo-wide search for `graphql`, `gqlgen`, `.graphql`, and `apollo` across Go sources, `go.mod`, TypeScript/TSX, and JSON returns zero hits. There is no schema file, no resolver layer, and no GraphQL dependency.

**Actual API surface — Protobuf/gRPC service definitions exposed over three HTTP transports:**

- **Schema of record:** `.proto` files in `proto/api/v1/` — `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto`. Persistence-layer messages live separately in `proto/store/`. Codegen is driven by `proto/buf.gen.yaml` into `proto/gen/`.
- **Transports**, all registered in `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`):
  - **gRPC-Gateway** — REST/JSON mapping via `runtime.NewServeMux`, with each service registered at `server/router/api/v1/v1.go:97-110`.
  - **Connect RPC** — handlers in `server/router/api/v1/connect_services.go`, generated into `proto/gen/api/v1/apiv1connect/`.
  - **MCP** — a Model Context Protocol surface that proxies a curated subset of the same RPCs (`server/router/mcp/catalog.go:12-14`), registered at `server/server.go:96`.
- **Machine-readable spec:** an OpenAPI document generated from the protos at `proto/gen/openapi.yaml`, embedded into the binary via `//go:embed` at `proto/openapi_embed.go:5`. That file is the closest analogue to the "schema for the public API" you're asking about.
- **Auth** is applied uniformly across transports by a shared `Authorizer` (`server/router/api/v1/v1.go:68`), with the per-method anonymous-access policy table in `server/router/api/v1/acl_config.go`.

Non-RPC HTTP surfaces exist alongside this but aren't part of the API proper: file serving at `/file/...` (`server/router/fileserver/fileserver.go:121`) and RSS feeds (`server/router/rss/rss.go`).
