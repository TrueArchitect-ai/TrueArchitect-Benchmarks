**Premise correction: there is no per-user API rate-limiting middleware in this repository — it doesn't exist, so there's no registration site and no request limits to report.**

Evidence:

- A case-insensitive search across all Go sources and `go.mod` for `ratelimit`, `rate_limit`, "rate limit", `golang.org/x/time/rate`, `Throttle`, and `limiter` produces exactly one hit, and it's a comment describing future work, not code: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"). Echo's `middleware.RateLimiter` is never imported or referenced.
- The complete middleware stack on the Echo server is two entries — `middleware.Recover()` and the CORS middleware (`server/server.go:51-52`) — plus static-file and SPA-fallback middleware on the frontend group (`server/router/frontend/frontend.go:54`, `:59`). The API surface adds an auth middleware for the gRPC-Gateway and a Connect interceptor (`server/router/api/v1/v1.go:95`), which authenticate and authorize but do not count or throttle requests.

What does exist, and may be what you're thinking of — these are **concurrency caps and size limits, not per-user rate limits**. None of them track a caller identity, none reset on a time window, and none return HTTP 429:

- `maxConcurrentThumbnails = 3` — a weighted semaphore bounding simultaneous thumbnail generation in the file server (`server/router/fileserver/fileserver.go:45-46`, `:116`).
- `thumbnailSemaphore` (3) and `imageProcessingSemaphore` (2) on the API service (`server/router/api/v1/v1.go:59-60`).
- A per-memo content-length limit enforced on create and update (`server/router/api/v1/memo_service.go:101`, `:439`, resolved by `getContentLengthLimit` at `:595`).

Excess requests queue on the semaphores rather than being rejected, so an authenticated client can issue unlimited API calls. If rate limiting is a requirement for your deployment, it would need to be added — either as new Echo middleware registered alongside the existing two at `server/server.go:51-52`, or at a reverse proxy in front of the server.
