**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`.**

**Triggers (recomputation happens on exactly three paths):**

1. `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`.
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but *only* when `"content"` appears in the request's `UpdateMask.Paths` (`memo_service.go:436`). Updating visibility, pinned state, etc. leaves the payload untouched.
3. `CreateMemoComment` — indirectly: it delegates to `s.CreateMemo` at `server/router/api/v1/memo_service_comments.go:56`, so comments get payloads through path 1.

There's also `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:52`), which rebuilds every memo in batches of 100 and persists via `Store.UpdateMemo` — but that runner is never constructed or invoked in production, so it's dead code.

**What's extracted** — a single goldmark AST walk (`internal/markdown/markdown.go:370`) populates two fields on `memo.Payload` (`server/runner/memopayload/runner.go:85-86`):

- **`Tags`** — every `#tag` node, deduplicated with original case preserved (`internal/markdown/markdown.go:417`).
- **`Property`** (`storepb.MemoPayload_Property`, defined at `proto/store/memo.proto:15-22`):
  - `title` — text of the first block-level child *only if* it's an H1 heading (`markdown.go:383-389`)
  - `has_link` — any `KindLink` node
  - `has_code` — any code block, fenced code block, or code span
  - `has_task_list` — any task checkbox
  - `has_incomplete_tasks` — any task checkbox that is unchecked (`markdown.go:400-405`)

`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` discards that field — mentions are consumed separately for notifications (`server/router/api/v1/memo_mention_helpers.go:32`).

**Consumption:** the derived data surfaces in list/preview responses via `memoMessage.Tags = memo.Payload.Tags` (`server/router/api/v1/memo_service_converter.go:48`) and drives user tag statistics (`server/router/api/v1/user_service_stats.go:138`, `:254`).

One consequence worth noting: because the payload is only rebuilt on content changes, there's no tag-rename path that rewrites stored payloads — no production caller of `Service.RenameTag` exists in this tree.
