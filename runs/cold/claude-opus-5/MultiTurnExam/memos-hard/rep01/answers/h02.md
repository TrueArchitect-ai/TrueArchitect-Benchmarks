**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual `safeClient.Do` at `internal/webhook/webhook.go:152`); protection: `safeDialContext` installed as the HTTP transport's `DialContext`, backed by the `isReservedIP` CIDR check — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

How it fits together:

- **Trigger path** — memo create/update/delete/comment events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43`, `:71`), which only enqueues onto a bounded 128-slot channel and drops on overflow (`internal/webhook/webhook.go:184-196`). Four worker goroutines started in `init()` drain that queue and call `Post` (`internal/webhook/webhook.go:42-55`), so delivery — JSON body, optional Standard Webhooks HMAC-SHA256 headers, 30s timeout, 1 MiB response read cap — executes in `Post`.
- **Primary protection (dial-time)** — all dispatches share `safeClient`, whose `http.Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). It resolves the hostname itself and refuses the connection if *any* returned address falls in a reserved range (`internal/webhook/webhook.go:59-77`). Because the check happens at dial time on the resolved IPs, it also defeats DNS rebinding, where a hostname passes validation and then re-resolves to an internal address.
- **Secondary protection (registration-time)** — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user saves a webhook, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.
- **Blocked ranges** — `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4/IPv6 loopback, RFC-1918, link-local incl. cloud IMDS `169.254.0.0/16`, and IPv6 ULA.

One thing worth flagging: the documented escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) is never assigned outside tests in this tree — the `--allow-private-webhooks` flag referenced in `CHANGELOG.md:121` has no remaining wiring, so the guard is currently always on in production builds.
