`store.User` leads on both breadth and raw reference count. Its edge in breadth comes from two packages that never touch `Memo`: `server/auth` (session and token validation) and `server/router/fileserver` (avatar serving and attachment permission checks). `store.Memo` is more concentrated — heavily used in `server/router/api/v1` but absent from the auth and file-serving layers.

Two caveats on the method:

- Counts are `grep`-based on the qualified type name with a trailing non-identifier boundary, so `store.User` excludes `store.UserSetting`/`store.UserIdentity`/`store.UpdateUser`, and `store.Memo` excludes `store.MemoRelation`/`store.MemoShare`. Companion query structs (`FindUser`, `UpdateMemo`, etc.) are counted separately, not folded in.
- Several entities defined in `store/` have **zero** references outside the data layer — `store.UserSetting` (`store/user_setting.go:13`), `store.InstanceSetting` (`store/instance_setting.go:14`), and `store.IdentityProvider` (`store/idp.go:12`). Callers in `server/` work with the protobuf `storepb` equivalents instead, so those entity structs never cross the layer boundary.

If you'd counted the `store/test` and `store/db/*` packages as "outside," `store.Memo` would rank first on raw references (141 vs 110) — driven by 71 references in `store/test` alone. Excluding the data layer as the question specifies, `store.User` is first.
