**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation).**

- **Abstraction** — `internal/idp/idp.go:3` defines the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider normalizes its user profile into. That's the whole package — it's a data contract rather than a Go interface, so provider implementations are selected by type switch rather than polymorphically.
- **Implementation** — `internal/idp/oauth2/oauth2.go` is the only concrete provider that ships. It defines `IdentityProvider` (`:20`), `NewIdentityProvider(config *storepb.OAuth2Config)` (`:27`), `ExchangeToken` with PKCE `codeVerifier` support (`:47`), and `UserInfo` returning `*idp.IdentityProviderUserInfo` (`:83`).
- **Consumer** — `server/router/api/v1/auth_service_sso.go:12-13` is the sole importer of both packages, driving the SSO sign-in flow.
- **Corroboration in the store layer** — `storepb.IdentityProvider_Type` has one branch handled, `IdentityProvider_OAUTH2` (`store/idp.go:223`, `:235`); there is no second provider directory under `internal/idp/`. OIDC-style providers are configured through the same OAuth2 config rather than a separate package.
