**No — `mysql.NewDB` is called from exactly one place, the driver-selection factory.**

Evidence:

1. **Single constructor, single call site.** `mysql.NewDB` is defined at `store/db/mysql/mysql.go:20`. A repo-wide grep for `NewDB(` across all `.go` files (excluding generated code) yields exactly one invocation of it: `store/db/db.go:22`, inside `NewDBDriver`'s `switch profile.Driver` — `case "mysql": driver, err = mysql.NewDB(profile)`.

2. **Single import of the package.** Grepping for the import path `store/db/mysql` returns one hit: `store/db/db.go:8`. No other package — not `cmd/`, not `server/`, not any test outside the driver package — imports `store/db/mysql` at all, so it has no way to construct the driver directly.

3. **No struct-literal back door.** The unexported `DB` struct (`store/db/mysql/mysql.go:14`) is constructed in only two places, both inside package `mysql` itself: the constructor (`mysql.go:29`) and an in-package unit test that builds an empty `&DB{}` for a pure-function check (`store/db/mysql/auth_config_test.go:12`). Being unexported, it can't be built from outside the package regardless.

4. **Contrast with SQLite.** `sqlite.NewDB` *is* constructed outside the factory — at `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416` — which shows the grep would surface such cases if they existed for MySQL. `postgres.NewDB` is likewise only called from `store/db/db.go:24`.

5. **Tests route through the factory too.** MySQL-backed tests go through `db.NewDBDriver` with a profile whose `Driver` is set to `"mysql"` (`store/test/store.go:28,50`, driver selected at `store/test/store.go:88`, plus `server/router/api/v1/test/memo_service_benchmark_test.go:70`), rather than calling the MySQL constructor directly.

Note that `github.com/go-sql-driver/mysql` (the third-party SQL driver, distinct from this repo's driver wrapper) *is* imported elsewhere — `store/test/containers.go:16` uses it alongside testcontainers to provision a MySQL 8 container. That's DSN/connection plumbing for test infrastructure, not construction of the repo's `store.Driver` implementation.
