**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `webhook.go:152`); protection is the SSRF-guarded dial hook `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path**
- Callers dispatch via `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded 128-slot channel (`webhook.go:39`) drained by 4 worker goroutines started in `init` (`webhook.go:42-55`). Overflow is dropped with a warning rather than blocking the request.
- Each worker calls `Post` (`webhook.go:120`), which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers `webhook-id`/`webhook-timestamp`/`webhook-signature` (`webhook.go:133-150`), then executes the request through the shared `safeClient` (`webhook.go:152`). Response reading is capped at 1 MiB (`webhook.go:158`) and the client has a 30s timeout (`webhook.go:27,33`).
- Trigger sites are `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, fed by `DispatchMemoCreated/Updated/Deleted/CommentCreatedWebhook` (`memo_service_webhooks.go:15-46`).

**SSRF protection**
- The shared client's `Transport.DialContext` is `safeDialContext` (`webhook.go:32-37`, defined at `webhook.go:59-77`). It resolves the hostname itself and refuses to dial if *any* resolved address is reserved/private. Because the check happens at dial time rather than at URL-save time, it also defeats DNS rebinding — a hostname that passed validation but later resolves to an internal IP is still blocked.
- `isReservedIP` (`internal/webhook/validate.go:44`) tests against `reservedCIDRs` (`validate.go:14-23`): IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), and the IPv6 equivalents `::1/128`, `fc00::/7`, `fe80::/10`, parsed once at startup (`validate.go:28-36`).
- A second, earlier layer validates URLs at configuration time: `webhook.ValidateURL` (`validate.go:62`) enforces http/https and the same IP check, called from `server/router/api/v1/user_service_webhooks.go:74,161,182`.
- Both layers share one escape hatch: the `AllowPrivateIPs` global (`validate.go:41`), which short-circuits `isReservedIP` (`validate.go:45-47`). It's set from the `--allow-private-webhooks` flag in `cmd/memos/main.go:49` (flag declared at `main.go:133`, bound to viper at `main.go:160`), defaulting to `false` — intended for self-hosted deployments targeting LAN services.

One gap worth flagging: the dial guard rejects a host if any resolved IP is reserved, but it then hands the *hostname* back to the dialer (`webhook.go:76`), which re-resolves independently. That's a narrow TOCTOU window rather than an open hole, since a rebinding attacker still has to win the race between the two lookups.
