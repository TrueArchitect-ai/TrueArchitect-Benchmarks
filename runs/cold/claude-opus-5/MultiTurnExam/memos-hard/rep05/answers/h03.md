**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation — OAuth2, the only protocol that ships)**

- **Abstraction**: `internal/idp/idp.go` — package `idp` defines the shared, protocol-neutral result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) at `idp.go:3-8`. It's a deliberately thin abstraction: a common user-info struct that every provider maps into, not a Go interface. The provider *type* enum lives alongside it in the store proto, `IdentityProvider_Type` (`proto/gen/store/idp.pb.go:24`), which currently has exactly two values — `TYPE_UNSPECIFIED` and `OAUTH2` (`idp.pb.go:27-28`).

- **Implementation**: `internal/idp/oauth2/oauth2.go` — package `oauth2`, "implements the OAuth2 identity provider integration" (`oauth2.go:1`). It exposes `IdentityProvider` (`oauth2.go:20`), `NewIdentityProvider` with required-field validation (`oauth2.go:27`), `ExchangeToken` with optional PKCE `code_verifier` support (`oauth2.go:47`), and `UserInfo` returning `*idp.IdentityProviderUserInfo` (`oauth2.go:83`), built on `golang.org/x/oauth2`.

- **Wiring**: `server/router/api/v1/auth_service_sso.go:120-131` branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2`, constructs the OAuth2 provider from `Config.GetOauth2Config()`, exchanges the code, and fetches user info; the config oneof `IdentityProviderConfig` likewise has only an `Oauth2Config` variant (`proto/gen/store/idp.pb.go:158`). Provider CRUD is in `server/router/api/v1/idp_service.go` and `store/idp.go`.

So no OIDC-discovery, SAML, or LDAP implementation exists in this tree — OIDC providers are supported only insofar as they can be configured as generic OAuth2 endpoints.
