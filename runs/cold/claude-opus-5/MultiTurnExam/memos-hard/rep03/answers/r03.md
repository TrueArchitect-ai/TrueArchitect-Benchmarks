**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never used by the server — so there is no scheduled time to report.**

Two separate corrections are folded into that:

**1. The cron scheduler exists but is dead code.** `internal/scheduler/` is a complete, tested cron package — `New` with options (`internal/scheduler/scheduler.go:54`), `ParseCronExpression` (`internal/scheduler/parser.go`), middleware like `Recovery`/`Logging`/`Timeout`, and example tests. But `grep -rn "internal/scheduler"` across the repo finds importers only inside the package's own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). Nothing in `cmd/`, `server/`, or `store/` imports it, so no cron job of any kind is registered or runs.

**2. No database-cleanup job exists anywhere**, cron-scheduled or otherwise. Searching the backend for `cleanup`/`vacuum`/`purge`/`prune`/`nightly` turns up only unrelated things: in-process cache expiry (`store/cache/cache.go:83`, `cleanupLoop`, at a 5-minute `CleanupInterval` — `store/store.go:42`), S3 blob cleanup performed inline during attachment/user deletion (`store/attachment.go:171`, `server/router/api/v1/user_service.go:421-450`), and test teardown helpers. There is no `VACUUM`, no expired-row sweep, no retention job.

**What actually runs on a schedule:** exactly one background task, and it isn't cleanup. `startBackgroundRunners` (`server/server.go:153-174`) starts the S3 presign runner — `RunOnce` synchronously at startup (`server/server.go:163`), then a `time.Ticker` loop every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:28`, loop at line 30). It refreshes presigned attachment URLs; it deletes nothing. Being interval-based from process start, it has no wall-clock time-of-day either.

Worth noting for anyone expecting expiry-based cleanup: `memo_share` rows carry an `expires_ts` (`store/migration/sqlite/LATEST.sql:108`), but expiration is enforced at read time via `isMemoShareExpired` rather than by a sweeper, so expired share rows persist in the table indefinitely.
