**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

Details:

- **Abstraction:** `internal/idp/idp.go` is the whole package — it defines the single shared type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`), the provider-neutral shape every implementation must produce. Note it's a data contract, not a Go interface; there's no `IdentityProvider` interface, so dispatch is done by an explicit type switch rather than polymorphism.
- **Implementation:** `internal/idp/oauth2/oauth2.go` — `NewIdentityProvider(*storepb.OAuth2Config)` validates required fields (clientId, clientSecret, tokenUrl, userInfoUrl, fieldMapping.identifier), `ExchangeToken` performs the code exchange with optional PKCE `code_verifier`, and `UserInfo` fetches and field-maps the profile into `idp.IdentityProviderUserInfo`.
- **Only one protocol ships.** The store enum in `proto/store/idp.proto:11-14` has just `TYPE_UNSPECIFIED = 0` and `OAUTH2 = 1`, and the call site branches on it at `server/router/api/v1/auth_service_sso.go:120` — `if identityProvider.Type == storepb.IdentityProvider_OAUTH2`. No SAML/LDAP/OIDC-specific package exists. (OIDC providers are supported only insofar as they're usable via the generic OAuth2 + userinfo-endpoint flow.)
