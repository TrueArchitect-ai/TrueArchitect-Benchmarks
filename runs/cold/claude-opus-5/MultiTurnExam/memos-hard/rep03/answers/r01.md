**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive search for `redis` across all Go sources, `go.mod`, and YAML/JSON config returns zero hits. The cache layer is a hand-rolled, in-process, in-memory cache — nothing is configured, because there's no external service to connect to.

**Actual mechanism:**

- **Implementation:** `store/cache/cache.go` — a `Cache` struct backed by `sync.Map` plus an `atomic.Int64` item counter (`store/cache/cache.go:66-72`), satisfying the `cache.Interface` declared at line 11. State lives in the server process and is lost on restart; a multi-replica deployment would have independent, unsynchronized caches.

- **Configuration site:** `store.New` — `store/store.go:39-44`. It builds one `cache.Config` literal and hands the *same* config to three separate cache instances (lines 50-52): `instanceSettingCache`, `userCache`, `userSettingCache`.
  ```go
  DefaultTTL:      10 * time.Minute
  CleanupInterval: 5 * time.Minute
  MaxItems:        1000
  OnEviction:      nil
  ```
  Note this literal duplicates `cache.DefaultConfig()` (`store/cache/cache.go:56-63`) rather than calling it — the values are identical today, so changing one won't change the other.

- **TTL for user entries: 10 minutes.** Every write to `userCache` uses the plain `Set` method — `store/user.go:98`, `:122`, `:132`, `:143`, `:167` — and `Set` forwards to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). No user write path calls `SetWithTTL` with an override, so the 10-minute default is the effective TTL.

Two details that matter in practice:

- **Entries can vanish sooner than 10 minutes.** The shared 1000-item cap applies per cache, and `deleteUserCache` (`store/user_delete.go:40`) explicitly evicts on user deletion. Keys are `userCacheKey(user.ID)`.
- **The cache only serves ID lookups.** `Store.GetUser` consults `userCache` solely when `find.ID != nil` (`store/user.go:149-156`); a lookup by username or email always falls through to `ListUsers` and the database, then repopulates the cache keyed by ID (line 167).

Cleanup goroutines started per cache are stopped via `Cache.Close` (`store/cache/cache.go:187`), called from `Store.Close` at `store/store.go:74-76`.
