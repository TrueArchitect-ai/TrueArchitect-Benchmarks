**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP POST is `safeClient.Do(req)` at line 152); SSRF guard via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

- **Delivery path.** API handlers call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`) for memo created/updated/deleted and comment-created events. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel (dropping with a warning if full); four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post`, which marshals the payload, adds Standard Webhooks HMAC-SHA256 headers when a signing secret is set, and issues the request through `safeClient` (30s timeout, response body capped at 1 MiB).

- **Protection at dial time.** `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`, defined at line 59). It splits host/port, resolves the hostname itself, and refuses to dial if *any* resolved address is reserved — this is what defeats DNS rebinding, since the check happens on the same resolution round as the connection rather than at save time.

- **The blocklist.** `isReservedIP` (`internal/webhook/validate.go:44`) tests against `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), and the IPv6 equivalents `::1/128`, `fc00::/7`, `fe80::/10`, parsed once in `init()`.

- **Second, weaker layer.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs at configuration time from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`, rejecting non-http(s) schemes and hostnames that resolve to reserved IPs. This is TOCTOU-prone on its own; the dial-time check is the real guarantee.

- **Escape hatch.** `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both checks for self-hosted deployments targeting LAN services. Note that nothing in the repo currently assigns it outside of tests — no CLI flag or env var wires it up — so in practice it stays `false` and the protection is always on.
