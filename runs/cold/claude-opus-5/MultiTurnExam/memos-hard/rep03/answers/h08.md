*s3presign.Runner — server/runner/s3presign/runner.go:43 — YES — server/server.go:163 (and internally server/runner/s3presign/runner.go:36)

Details:

- **`*s3presign.Runner.RunOnce`** (`server/runner/s3presign/runner.go:43`) is invoked from production code at `server/server.go:163`, inside `startBackgroundRunners` — a synchronous one-shot pass at startup. It's also called on every tick from the package's own `Run` loop at `server/runner/s3presign/runner.go:36`. It delegates to `CheckAndPresign`.

- **`*memopayload.Runner.RunOnce`** (`server/runner/memopayload/runner.go:27`) has no callers at all — production or test. `grep -rn "NewRunner("` finds only `s3presign.NewRunner` at `server/server.go:162`; `memopayload.NewRunner` (`server/runner/memopayload/runner.go:19`) is never called, so a `*memopayload.Runner` is never constructed. The package *is* imported (`server/router/api/v1/memo_service.go:18`), but only for the standalone function `RebuildMemoPayload`, used at `memo_service.go:108` and `:447` — not the `Runner` type. So the batch-rebuild-all-memos path is effectively dead code.

Neither type satisfies a shared interface; there's no `RunOnce` interface declaration in the repo, so the name collision is incidental.
