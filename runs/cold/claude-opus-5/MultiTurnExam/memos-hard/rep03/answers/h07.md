The browser hits `GET /file/users/{username}/avatar`. That URL isn't chosen by the client — the API rewrites base64 avatars to it when converting users for the wire (`server/router/api/v1/user_service_converters.go:36`, `fmt.Sprintf("/file/%s/avatar", userpb.Name)`).

Notes on the hops:

- **Registration.** `NewFileServerService` is constructed and its routes registered at `server/server.go:81-82`, so this is a plain Echo handler outside the gRPC/Connect API.
- **`serveUserAvatar`** (line 168) first gates access: if `s.Profile.AllowAnonymous()` is false, it requires a resolvable viewer via `getCurrentUser` and returns 401 otherwise (lines 173-181). There's no per-user authorization beyond that — any authenticated viewer (or anyone, on a public instance) can fetch any user's avatar.
- **`getUserByUsername`** (line 715) is a one-liner wrapping `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`, so the `:identifier` path param is matched against `username`.
- **`Store.GetUser`** (`store/user.go:148`) consults `s.userCache` only when the lookup is by `ID`; a username lookup always falls through to `ListUsers`. The result is then written into the cache keyed by ID (line 167).
- **`Store.ListUsers`** (`store/user.go:136`) delegates to `s.driver.ListUsers` and populates the cache for each row.
- **Driver.** Dialect-specific; the SQLite implementation is `store/db/sqlite/user.go:88`, with the `username = ?` predicate at line 128-130 and `avatar_url` selected at line 158 and scanned into `user.AvatarURL`. MySQL and Postgres have parallel implementations under `store/db/mysql/user.go` and `store/db/postgres/user.go`. The driver is chosen by the factory `NewDBDriver` (`store/db/db.go:14`).

Back in the handler, the stored value is a data URI, not a file: `parseDataURI` (`server/router/fileserver/fileserver.go:737`) splits it via `dataURIRegex` and base64-decodes the payload, the MIME type is checked against `avatarAllowedTypes` (line 75, gating to PNG/JPEG/GIF/WebP), and the bytes go out via `c.Blob` with security headers and `Cache-Control` (lines 205-209).
