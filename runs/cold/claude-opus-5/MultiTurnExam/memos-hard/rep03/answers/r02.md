**Premise correction: no per-user API rate-limiting middleware exists in this repository.** There is nothing to cite because nothing implements it — so there are no limits to report.

Evidence:

- A case-insensitive search across all Go sources and `go.mod` for `rate.?limit`, `ratelimit`, `throttl`, `golang.org/x/time/rate`, and Echo's `middleware.RateLimiter` returns **zero** hits in server code. The only matches anywhere in the repo are aspirational documentation in the email package — `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") and a suggested snippet under "### 5. Implement Rate Limiting" at `internal/email/README.md:286-295` — both describing work a *caller* might do, neither wired into anything.
- No `429` / `Too Many Requests` response is produced anywhere in the backend.
- Echo's global middleware stack is exactly two entries, registered at `server/server.go:51-52`: `middleware.Recover()` and `newCORSMiddleware(profile)` (defined at `server/cors.go:14`). No limiter is added there, nor on `rootGroup` (`server/server.go:74`), nor in the gRPC-Gateway/Connect setup in `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:64+`), which installs only authentication/authorization interceptors.

What does exist, and is easy to mistake for rate limiting, is **concurrency limiting** — semaphores that cap simultaneous expensive work process-wide, not per user and not per request rate:

- `thumbnailSemaphore`, weight 3 — `server/router/fileserver/fileserver.go:116` (constant `maxConcurrentThumbnails = 3` at line 46)
- `thumbnailSemaphore`, weight 3, and `imageProcessingSemaphore`, weight 2 — `server/router/api/v1/v1.go:59-60`

These make callers *wait* rather than rejecting them, and they're global to the process regardless of which user is calling.

Two other bounded resources, also not rate limits: the webhook dispatch queue is a 128-slot buffered channel drained by 4 workers, dropping overflow (`internal/webhook/webhook.go:39-55`, `:189-195`), and outbound webhook requests have a 30-second timeout (`internal/webhook/webhook.go:27`).
