**Premise correction: neither. There is no message broker in this repository at all** — no NATS, no RabbitMQ, and no Kafka/AMQP/Redis either. `go.mod` and `go.sum` contain zero broker dependencies, and a case-insensitive source search finds no broker client code. (The only apparent hits are false positives — `nsq` matching inside `openMigratio**nSQ**LDB` in `store/test/migrator_upgrade_test.go:157`.) Consequently there is no queue declaration to point at, in the AMQP/JetStream sense.

**Actual mechanism — an in-process Go channel with a fixed worker pool, all in `internal/webhook/webhook.go`:**

- **The "queue" is a package-level buffered channel**, declared at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  Capacity 128, holding pointers to `WebhookRequestPayload` (line 79). It lives in the server process's heap — nothing is persisted, nothing crosses a network, and the contents are lost on restart or crash.

- **Four workers, started in `init()`** — `internal/webhook/webhook.go:42-55`. A `for range 4` loop spawns goroutines that each `range` over the channel and call `Post(payload)`, logging a warning on failure. Because this is `init()`, the pool starts on package import rather than at explicit server startup, and there's no shutdown path — the goroutines are never drained or cancelled during `Server.Shutdown`.

- **Enqueue is non-blocking with drop-on-full** — `PostAsync` (`internal/webhook/webhook.go:184-196`) does a `select` with a `default` branch, so when all 128 slots are occupied the payload is discarded with a `slog.Warn` rather than applying backpressure. There is no retry, no dead-letter, and no delivery guarantee — a failed `Post` is logged and forgotten.

- **Delivery itself** is `Post` (`internal/webhook/webhook.go:120`), which signs the body when a secret is configured and issues the POST via the SSRF-guarded `safeClient` (line 152).

Producers are the memo API handlers, which call `webhook.PostAsync` at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.
