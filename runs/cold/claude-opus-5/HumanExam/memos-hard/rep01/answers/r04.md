— Premise is wrong on both counts: there is **no message broker** — neither NATS nor RabbitMQ/AMQP appears in `go.mod`, `go.sum`, or any Go file — and therefore no queue is declared anywhere. Actual mechanism: an in-process Go channel. `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:40`; four worker goroutines are started in the package `init()` (`internal/webhook/webhook.go:42-52`) and each drains the channel by calling `Post` (`:44`). Producers call `webhook.PostAsync` (`:184`), which does a non-blocking send and **drops** the payload with a warning when the buffer is full (`:190-196`). The queue is unpersisted and per-process: pending deliveries are lost on restart, and there is no retry.
