— Premise is wrong: there is no per-user (or any) rate-limiting middleware in this codebase. `grep -rniE "limiter|throttl|ratelimit|golang.org/x/time/rate"` over the Go sources returns nothing. The only Echo middleware registered is `middleware.Recover()` and the CORS middleware (server/server.go:51-52); the API v1 stack adds auth/authorization interceptors only (`NewAuthorizer`, server/router/api/v1/v1.go:65-70, server/router/api/v1/connect_interceptors.go). The nearest thing to a limit is concurrency capping, not rate limiting: `semaphore.NewWeighted(3)` / `NewWeighted(2)` for thumbnail and image processing (server/router/api/v1/v1.go:60-61, returning `ResourceExhausted` at server/router/api/v1/attachment_service.go:160) and `maxConcurrentThumbnails = 3` in the file server (server/router/fileserver/fileserver.go:44,114).
