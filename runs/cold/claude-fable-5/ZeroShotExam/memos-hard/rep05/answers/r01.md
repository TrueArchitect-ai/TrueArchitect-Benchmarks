**Premise correction:** There is no Redis in this repository. The cache layer is not Redis-backed at all — a repo-wide search finds no Redis client, connection config, or dependency. The cache is a custom **thread-safe in-memory Go cache** defined in `store/cache/cache.go`.

**Actual mechanism:**
- The `Cache` type (`store/cache/cache.go`) is an in-process map with per-entry TTL, a background cleanup goroutine, and memory management (`MaxItems`, eviction). Its built-in default config is `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute` (`store/cache/cache.go:59`).
- The store wires it up in `store/store.go:38-61` (`New()`), creating three caches from one `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000}`: `instanceSettingCache`, `userCache`, and `userSettingCache`.
- **TTL for user entries: 10 minutes.** User objects are inserted via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167), and `Set` applies the default TTL (`store/cache/cache.go:92-94`), i.e. the 10-minute `DefaultTTL` — no custom `SetWithTTL` is used for users.

(Separately, there's a small one-off memoization cache for instance stats with a 60-second TTL in `server/router/api/v1/instance_stats.go:21`, but that's unrelated to user entries.)
