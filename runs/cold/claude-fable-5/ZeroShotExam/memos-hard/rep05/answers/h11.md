**1st: `User`; 2nd: `Memo`** (User ≈ 7 packages, Memo ≈ 6 packages)

The data layer is the `store` package, which defines the persistent entities: `Memo` (store/memo.go:35), `User` (store/user.go:29), `Attachment` (store/attachment.go:16), `Inbox` (store/inbox.go:24), `Reaction` (store/reaction.go:7), `IdentityProvider` (store/idp.go:12), `MemoRelation` (store/memo_relation.go:16), `MemoShare` (store/memo_share.go:6), `UserIdentity` (store/user_identity.go:8), `UserSetting` (store/user_setting.go:13), and `InstanceSetting` (store/instance_setting.go:14).

Counting distinct Go packages outside the `store/` tree (i.e., excluding `store/db/*` and `store/test`, which are part of the data layer) that reference each `store.<Type>`:

- **`store.User` — 7 packages**: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- **`store.Memo` — 6 packages**: `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`
- Next closest is `store.Attachment` at 4 packages; everything else is 3 or fewer.

The ranking holds even if test packages are excluded (User 6, Memo 5): `User` is the most widely referenced entity because authentication (`server/auth`) and the file server need it in addition to the rendering/API paths, while `Memo` picks up the `memopayload` runner instead.
