**impl** — The interface is `markdown.Service` (`internal/markdown/markdown.go:31`). The only concrete implementation is the unexported `service` struct in the same file (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown` instance (GFM plus the repo's custom tag/mention extensions from `internal/markdown/extensions`). No other type implements the interface in production code.

**construction** — Constructed exactly once at runtime by the factory `markdown.NewService(...)` (`internal/markdown/markdown.go:85`), called from `NewAPIV1Service` in `server/router/api/v1/v1.go:48-51` with both `WithTagExtension()` and `WithMentionExtension()` options. That single instance is then shared: `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService(...)`. (Tests build their own instances in `server/router/api/v1/test/test_helper.go:44`, `server/router/rss/rss_test.go:54`, and `server/router/fileserver/fileserver_test.go:427`, but those don't run in production.)

**holders** — Three components declare a `MarkdownService markdown.Service` field:
- `APIV1Service` (`server/router/api/v1/v1.go:35`) — uses it for payload rebuilds (`memo_service.go:108,447`), mention extraction (`memo_mention_helpers.go:32`), and webhook snippets (`memo_service_webhooks.go:85`).
- `RSSService` (`server/router/rss/rss.go:45`) — uses `RenderHTML` for feeds (`rss.go:339`), holding the same instance handed over in `server.go:85`.
- `memopayload.Runner` (`server/runner/memopayload/runner.go:16`) also holds the interface, but `memopayload.NewRunner` has no non-test call sites — at runtime the package-level function `RebuildMemoPayload(ctx, memo, markdownService)` (`runner.go:74`) is invoked directly by the API service with its instance, so the Runner itself isn't wired into the running server.

One nuance worth noting: per the comment at `internal/markdown/markdown.go:29-30`, HTML rendering for display is mostly done client-side (the `web/` React app uses remark/rehype plugins); the Go interface exists for server-side needs — metadata extraction, snippets, tag renames, and RSS HTML.
