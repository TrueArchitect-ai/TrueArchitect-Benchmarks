**Premise correction:** There is no Redis in this repository. No Redis client, connection config, or dependency exists anywhere (no hits in `go.mod` or the source tree). The cache layer is a custom **in-process, in-memory cache** implemented in Go.

**Actual mechanism:** The cache is implemented in `store/cache/cache.go` — a `sync.Map`-based cache with per-item expiration, periodic cleanup, and a max-item cap. The store wires it up in `store/store.go:38-58`, where `New()` creates three cache instances (`instanceSettingCache`, `userCache`, `userSettingCache`) from a shared config:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

**TTL for user entries:** User entries go through `userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167). `Set` delegates to `SetWithTTL` using the default TTL (`store/cache/cache.go:93-94`), so user cache entries expire after **10 minutes**, with expired items swept every 5 minutes by the cleanup goroutine.
