**Computation site; triggers; extracted properties:**

**Computation site:** `memopayload.RebuildMemoPayload()` in `server/runner/memopayload/runner.go:74`, which delegates the actual parsing to the goldmark-based markdown service's `ExtractAll()` in `internal/markdown/markdown.go:356`. The result is stored on the memo as `memo.Payload.Tags` and `memo.Payload.Property` (a `MemoPayload.Property` message defined in `proto/store/memo.proto`, commented there as "The calculated properties from the memo content").

**Triggers:**
1. **Memo creation** — `CreateMemo` calls `RebuildMemoPayload` before persisting (`server/router/api/v1/memo_service.go:108`).
2. **Content update** — `UpdateMemo` calls it when the update mask includes the `content` path (`server/router/api/v1/memo_service.go:447`).
3. **Bulk rebuild** — the `memopayload.Runner.RunOnce()` maintenance runner (`server/runner/memopayload/runner.go:27`) recomputes the payload for all memos in batches of 100 (though I found no call site currently wiring this runner into server startup — `server/server.go` only invokes the `s3presign` runner — so it exists as a bulk-migration/rebuild utility).

**Extracted properties** (from a single AST walk of the markdown content in `ExtractAll`, `internal/markdown/markdown.go:356-420`):
- `tags` — all `#tag` nodes, deduplicated with original case preserved
- `property.title` — text of the first H1 heading, only if it's the document's first block
- `property.has_link` — presence of any link node
- `property.has_code` — presence of code blocks, fenced code blocks, or inline code spans
- `property.has_task_list` — presence of task checkboxes
- `property.has_incomplete_tasks` — any task checkbox that is unchecked

(`ExtractAll` also collects `@mentions`, but those aren't stored in the payload — only tags and the property struct are, per `runner.go:85-86`.)
