Delivery function — `Post` in `internal/webhook/webhook.go` (line 120; async dispatch goes through `PostAsync`/the worker queue in the same file, which just calls `Post`). This is where the outbound HTTP POST to the configured webhook URL actually executes, via the shared `safeClient`.

Protection mechanism — SSRF guarding at dial time: `safeClient`'s transport uses `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the target host and rejects any IP matching the reserved/private ranges defined in `reservedCIDRs` / `isReservedIP` in `internal/webhook/validate.go`. Because the check happens inside the dialer, it also defeats DNS-rebinding tricks. A secondary, earlier layer is `ValidateURL` in `internal/webhook/validate.go:62`, which rejects webhook URLs at registration time if they use a non-http(s) scheme or resolve to a reserved/private IP (the guard can be disabled for self-hosted setups via `AllowPrivateIPs` in that same file).
