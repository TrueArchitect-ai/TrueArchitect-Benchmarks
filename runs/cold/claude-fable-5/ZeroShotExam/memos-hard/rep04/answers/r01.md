**Premise correction:** There is no Redis in this repository. Nothing in the codebase references Redis or any external cache service — the cache layer is a custom, thread-safe **in-memory** cache implemented in Go.

**Actual mechanism:**

- The cache implementation lives in `store/cache/cache.go` — a generic in-process cache built on `sync.Map` with per-entry TTL expiration, a periodic cleanup goroutine, and a max-item cap.
- It is wired up in `store/store.go:38-58` (`store.New`), which creates three cache instances: `instanceSettingCache`, `userCache`, and `userSettingCache`, all sharing one `cache.Config`:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
- **User entries get the 10-minute default TTL.** All user cache writes go through `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`), and `Set` applies `config.DefaultTTL` (`store/cache/cache.go:92-94`); the `SetWithTTL` custom-TTL path is never used for users. Entries are also invalidated eagerly on user deletion (`store/user_delete.go:40`).

So: no Redis connection exists to configure — user entries live in an in-memory cache with a 10-minute TTL set in `store/store.go`.
