The outbound webhook delivery executes in `Post()` at `internal/webhook/webhook.go:120` (with an async path, `PostAsync()`/the worker queue in the same file, that just funnels into `Post`). The actual HTTP call goes through a shared `safeClient` (`internal/webhook/webhook.go:32`).

The SSRF protection has two layers:

- **At dial time (the real guard):** `safeClient`'s transport uses `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the target hostname and refuses to connect if any resolved address is in a reserved/private range — this also defeats DNS-rebinding, since the check happens at connection time, not just at registration.
- **The range check itself:** `isReservedIP` against `reservedCIDRs` in `internal/webhook/validate.go:14-54` (loopback, RFC-1918, link-local/cloud IMDS 169.254.0.0/16, and IPv6 equivalents; can be disabled via `AllowPrivateIPs` for self-hosted setups). `ValidateURL` in the same file additionally rejects such URLs up front when a webhook is created/updated.

- delivery function — `Post()` in `internal/webhook/webhook.go` (via `safeClient.Do`)
- protection mechanism — `safeDialContext` + `isReservedIP`/`reservedCIDRs` in `internal/webhook/webhook.go` / `internal/webhook/validate.go`
