**Computation site:** The derived metadata is the memo's payload "property" (defined as `MemoPayload.Property` in `proto/store/memo.proto`, commented "The calculated properties from the memo content"). It's computed by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual content analysis to the markdown service's single-pass AST walk in `ExtractAll` at `internal/markdown/markdown.go:356`.

**Triggers for recomputation:**
1. **Memo creation** — `CreateMemo` calls `memopayload.RebuildMemoPayload` before persisting (`server/router/api/v1/memo_service.go:108`).
2. **Memo update, when the `content` field is in the update mask** — `UpdateMemo` re-runs `RebuildMemoPayload` and writes the new payload alongside the content (`server/router/api/v1/memo_service.go:447`). Other update paths (visibility, pinned, etc.) do not recompute it.
3. **Bulk rebuild** — the `memopayload.Runner.RunOnce` maintenance runner iterates all memos in batches of 100 and rebuilds each payload (`server/runner/memopayload/runner.go:27`).

**Extracted properties:** `ExtractAll` parses the memo's markdown into an AST and, in one walk, extracts:
- `tags` — from `#tag` nodes, deduplicated case-preservingly (stored as `MemoPayload.tags`)
- `has_link` — presence of any link node
- `has_code` — presence of code blocks, fenced code blocks, or inline code spans
- `has_task_list` — presence of task checkboxes
- `has_incomplete_tasks` — any checkbox that is unchecked
- `title` — text of the first block-level element if it is an H1 heading

These fields back list/preview features (e.g., filtering memos by "has link/code/task list" and showing titles) without users setting them explicitly.
