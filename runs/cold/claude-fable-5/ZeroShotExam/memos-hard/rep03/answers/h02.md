Outbound webhook delivery executes in `Post()` in `internal/webhook/webhook.go` (with `PostAsync()` in the same file enqueueing payloads that worker goroutines drain through `Post()`). The dispatch happens via a shared `safeClient` HTTP client (`internal/webhook/webhook.go:32`).

The SSRF protection lives in two layers:

1. **Dial-time enforcement** — the `safeClient` transport uses `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the target hostname at connection time and refuses to dial any address matching a reserved/private range. Doing this at dial time also defeats DNS-rebinding attacks that would slip past a check done only at registration.
2. **Registration-time validation** — `ValidateURL` in `internal/webhook/validate.go:62` rejects webhook URLs up front if they aren't http/https or resolve to a reserved IP. The blocked ranges (loopback, RFC-1918, link-local including the 169.254.169.254 cloud metadata endpoint, and IPv6 equivalents) are defined in `reservedCIDRs` (`internal/webhook/validate.go:14`), checked by `isReservedIP` (`internal/webhook/validate.go:44`). An `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) can disable the protection for self-hosted deployments targeting local-network services.
