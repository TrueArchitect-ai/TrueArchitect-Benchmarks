The premise is incorrect — this repository has no per-user API rate-limiting middleware registered anywhere, so there are no request limits to report.

What actually exists:

- The HTTP server registers only `middleware.Recover()` and a CORS middleware in `server/server.go:51-52`.
- The API layer registers Connect RPC interceptors in `server/router/api/v1/v1.go:133-138`: metadata conversion, logging, recovery, and auth (implemented in `server/router/api/v1/connect_interceptors.go`). None of these do rate limiting or throttling.
- The only request-size-style constraint on the API is a max request body size (`connect.WithReadMaxBytes(maxAPIRequestBytes)` in `server/router/api/v1/v1.go:141`), which is a byte limit, not a request-rate limit.

The only mentions of "rate limit" in the codebase are documentation suggesting it as a *future* best practice for email sending — `internal/email/README.md:286-295` ("Implement Rate Limiting", with a sketch that returns "rate limit exceeded") and `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"). That code is illustrative only and is not implemented or registered anywhere.
