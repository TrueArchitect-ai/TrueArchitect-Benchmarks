**RPC handler methods that can transitively trigger an outbound HTTP request to a user-configured URL** (via the memo webhook system, whose target URL is set by the user through `CreateUserWebhook`/`UpdateUserWebhook`):

- `CreateMemo` — `server/router/api/v1/memo_service.go:70` → `DispatchMemoCreatedWebhook` (`memo_service.go:157`)
- `UpdateMemo` — `server/router/api/v1/memo_service.go:401` → `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` (`memo_service.go:513`, `memo_update_helpers.go:67`)
- `DeleteMemo` — `server/router/api/v1/memo_service.go:518` → `DispatchMemoDeletedWebhook` (`memo_service.go:562`)
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20` → `DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`)
- `SetMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:16` and `SetMemoRelations` — `memo_relation_service.go:16`, both via `dispatchMemoUpdatedSideEffects` (`:48` each)

These `Dispatch…Webhook` helpers all funnel into `dispatchMemoRelatedWebhook`/`DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go`), which call `webhook.PostAsync` to enqueue the payload. The four async queue workers then all invoke the single delivery function.

**Convergence function** — `Post` in `internal/webhook/webhook.go:119` (invoked by the `PostAsync` queue workers started in that file's `init`). This is the one place that marshals the payload and issues the actual `http.NewRequest("POST", requestPayload.URL, …)` / `safeClient.Do(req)` to the user-configured webhook URL.

(Note: other outbound-HTTP sinks exist — e.g. OAuth2 `UserInfoUrl` in `internal/idp/oauth2/oauth2.go` and link-preview fetching in `internal/httpgetter/` — but the webhook path is the one where multiple RPC handlers converge on a single delivery function as the question describes.)
