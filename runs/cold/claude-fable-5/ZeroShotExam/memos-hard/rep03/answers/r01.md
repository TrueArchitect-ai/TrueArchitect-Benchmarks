**Premise correction:** There is no Redis in this repository. The cache layer is not backed by Redis (or any external store) — I found no Redis client, connection config, or dependency anywhere in the codebase. Instead, the project uses a custom **thread-safe in-memory cache** implemented in Go.

**Actual mechanism:**

- The cache implementation lives in `store/cache/cache.go` — a `sync.Map`-based in-memory cache with TTL expiration, a periodic cleanup goroutine, and a max-item cap.
- It is wired up in `store/store.go:39-53` (`store.New`), which creates three cache instances: `instanceSettingCache`, `userCache`, and `userSettingCache`, all sharing this config:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
- **TTL for user entries: 10 minutes.** User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167), and `Set` applies the default TTL (`store/cache/cache.go:92-94`); no custom `SetWithTTL` is used for users. Entries are also invalidated eagerly on user deletion (`store/user_delete.go:40`).

So: no Redis connection exists to configure — the "cache layer" is process-local memory, and user cache entries expire after 10 minutes (with cleanup sweeps every 5 minutes).
