**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual extraction to the goldmark-based `ExtractAll` in `internal/markdown/markdown.go:356` (single AST walk over the memo's markdown). The result is stored on the memo's `Payload` (`MemoPayload` message defined in `proto/store/memo.proto`, whose `Property` sub-message is documented as "The calculated properties from the memo content").

**Triggers for recomputation:**
- **Memo creation** — `CreateMemo` calls `memopayload.RebuildMemoPayload` before persisting (`server/router/api/v1/memo_service.go:108`).
- **Memo content update** — `UpdateMemo` calls it whenever the update mask includes the `content` path, and persists the rebuilt payload alongside the new content (`server/router/api/v1/memo_service.go:447`).
- **Bulk rebuild** — `Runner.RunOnce` in `server/runner/memopayload/runner.go:27` re-derives the payload for all memos in batches of 100 (a maintenance/migration runner; I found no current call site wiring it into server startup, unlike e.g. the s3presign runner in `server/server.go`).

**Extracted properties** (`ExtractedData` → `memo.Payload`):
- `tags` — all `#tag` nodes, deduplicated case-preservingly.
- `Property.title` — text of the document's first block-level element if it is an H1 heading.
- `Property.has_link` — presence of any link node.
- `Property.has_code` — presence of code blocks, fenced code blocks, or inline code spans.
- `Property.has_task_list` / `Property.has_incomplete_tasks` — presence of task checkboxes, and of any unchecked ones.

One related but distinct detail: the `snippet` shown in list views is *not* stored in this payload — it's generated on the fly during API conversion via `GenerateSnippet` (`internal/markdown/markdown.go:264`, called from `server/router/api/v1/memo_service_converter.go:76`).
