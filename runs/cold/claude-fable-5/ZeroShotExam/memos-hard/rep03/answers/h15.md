Memo visibility is enforced independently at these server surfaces:

1. gRPC/API v1 single-memo read gate — `checkMemoReadAccess` at `server/router/api/v1/memo_service.go:39` (denies non-public memos to anonymous users and private memos to non-creators; used by GetMemo and related RPCs).
2. gRPC/API v1 list-time filtering — `ListMemos` at `server/router/api/v1/memo_service.go:218-227` (anonymous callers are restricted to `VisibilityList: [Public]`; authenticated callers get an injected `creator_id == X || visibility in ["PUBLIC","PROTECTED"]` filter).
3. Per-resource replicas of the same check in other API v1 services — `server/router/api/v1/reaction_service.go:30-38,83`, `server/router/api/v1/attachment_service.go:445-451`, `server/router/api/v1/memo_attachment_service.go:214-222`, and `server/router/api/v1/memo_service_comments.go:41` (each re-checks `memo.Visibility == store.Private && memo.CreatorID != user.ID` before acting on the memo).
4. File server (raw attachment/blob serving over HTTP) — `checkAttachmentPermission` at `server/router/fileserver/fileserver.go:650-704` (public + anonymous-allowed passes, share-token fallback, otherwise requires auth and blocks private memos for non-creator/non-admin).
5. SSE real-time event delivery — `canReceive` at `server/router/api/v1/sse_hub.go:134-143` (private-memo events are delivered only to the creator or an admin; unknown visibility is denied).
6. RSS feeds — `server/router/rss/rss.go:90,141` (both the explore feed and per-user feed query only `store.Public` memos).
7. Frontend router (sitemap generation) — `server/router/frontend/frontend.go:150` (`getSitemapXML` lists only `store.Public` memos).

The core "at least three" surfaces are the API v1 gRPC layer (items 1–3), the file server (item 4), and the SSE hub (item 5), with the RSS and frontend routers (items 6–7) enforcing public-only visibility at query time.
