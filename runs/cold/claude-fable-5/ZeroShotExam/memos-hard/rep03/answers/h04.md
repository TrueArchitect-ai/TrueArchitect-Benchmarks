**Yes** — in exactly one place, a unit test inside the mysql package itself.

The driver-selection factory is `NewDBDriver` in `store/db/db.go:14-32`, which calls `mysql.NewDB(profile)` for the `"mysql"` case (`store/db/db.go:22`). The MySQL driver type is the `DB` struct defined in `store/db/mysql/mysql.go:14`, normally constructed only by its own `NewDB` constructor (`store/db/mysql/mysql.go:20-41`).

Evidence from a repo-wide search:

- `mysql.NewDB` is called from exactly one location in the whole codebase: the factory at `store/db/db.go:22`. Everything else (production code and integration tests like `store/test/store.go:28,50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70`) goes through `db.NewDBDriver`.
- However, the struct is constructed directly once, bypassing both the factory and `NewDB`: `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — a zero-value MySQL driver built just to call the pure method `IsRetryableAuthenticationMutationError` (no real database connection involved).

For comparison, other direct `&DB{...}` constructions found by the search are for the *Postgres* driver (`store/db/postgres/postgres.go:33`, `store/db/postgres/user_setting_test.go`, `store/db/postgres/auth_config_test.go`), not MySQL. So outside the factory, the only direct construction of the MySQL driver is that single test-file instance at `store/db/mysql/auth_config_test.go:12`.
