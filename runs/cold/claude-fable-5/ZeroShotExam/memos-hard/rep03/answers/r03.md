**Premise correction: there is no nightly database-cleanup job scheduled in this repository.** The question presumes a registered job that doesn't exist.

What actually exists:

- **`internal/scheduler/`** is a cron scheduler *library* (parser, jobs, middleware), but no production code registers any jobs with it — nothing outside the package itself imports it. The only "cleanup" job references are illustrative examples in its docs: `internal/scheduler/README.md` (line ~34) and `internal/scheduler/doc.go` (line 15) show a hypothetical `"daily-cleanup"` job with schedule `"0 2 * * *"` (2 AM daily), but that's sample code in documentation, not a configured job.
- The real background work is done by plain runners started in `server/server.go`, not via the cron scheduler: `server/runner/s3presign/runner.go` runs on a 12-hour `time.Ticker` (S3 presign refresh, not database cleanup), and `server/runner/memopayload` exists as an on-demand rebuild runner.

So there is no scheduled time to report — no database-cleanup job is wired into the cron scheduler anywhere in the codebase.
