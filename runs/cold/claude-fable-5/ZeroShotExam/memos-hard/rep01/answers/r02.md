The premise is incorrect: this repository has no per-user API rate-limiting middleware registered anywhere, so there are no request limits to report.

What actually exists:

The closest thing to a "limit" there is a request body size cap (`connect.WithReadMaxBytes(maxAPIRequestBytes)`), which is a payload size limit, not a rate limit.

The only mentions of rate limiting in the codebase are aspirational documentation in the email package: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a best-practice suggestion, and `internal/email/README.md:286-295` shows an example snippet ("Implement Rate Limiting") for callers to write themselves — neither is implemented or registered as middleware.
