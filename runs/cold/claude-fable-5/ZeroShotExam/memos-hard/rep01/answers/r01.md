**Premise correction:** There is no Redis in this repository. Nothing in the codebase references Redis (or any external cache service) — the cache layer is a purely in-process, in-memory Go cache.

**Actual mechanism:** The cache is implemented in `store/cache/cache.go` — a thread-safe in-memory cache with per-entry TTL, a background cleanup loop, and an item cap. The store wires it up in `store/store.go:38-61`, where `New()` creates three cache instances (`instanceSettingCache`, `userCache`, `userSettingCache`) from a shared `cache.Config`.

**TTL for user entries:** User entries use the default TTL of **10 minutes**, set in `store/store.go:41` (`DefaultTTL: 10 * time.Minute`, with `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000`). The user store code in `store/user.go` populates the cache via `s.userCache.Set(...)` (e.g. lines 98, 122, 132, 167), which uses that default TTL rather than a custom one (`store/cache/cache.go:92-94`). The same 10-minute default also appears as the library's own fallback in `store/cache/cache.go:59`.
