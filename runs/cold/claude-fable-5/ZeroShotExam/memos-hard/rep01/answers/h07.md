A browser GET to `/file/users/:identifier/avatar` reaches the stored avatar (a base64 data URI held in the `user.avatar_url` column) through this chain:

`GET /file/users/:identifier/avatar` (route) — server/router/fileserver/fileserver.go:124
`serveUserAvatar` — server/router/fileserver/fileserver.go:168
`getUserByUsername` — server/router/fileserver/fileserver.go:715
`Store.GetUser` — store/user.go:148
`Store.ListUsers` — store/user.go:136
`driver.ListUsers` (SQL `SELECT ... avatar_url ... FROM user`) — store/db/sqlite/user.go:88 (Postgres: store/db/postgres/user.go:87; MySQL: store/db/mysql/user.go:84)

The handler then decodes `user.AvatarURL` via `parseDataURI` (server/router/fileserver/fileserver.go:196/737) and writes the bytes back with `c.Blob` — so the "stored data" is the `avatar_url` column value read by the driver's `ListUsers` query, not a file on disk.
