**Computation site.** The derived metadata is `MemoPayload.Property` (plus the tags list), defined as "the calculated properties from the memo content" in `proto/store/memo.proto` (lines 13–22). It is computed by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`, which delegates the actual content analysis to the markdown service's single-pass AST walk in `ExtractAll` (`internal/markdown/markdown.go:356` onward). `RebuildMemoPayload` writes the result into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers.** Recomputation happens on:
1. **Memo creation** — `CreateMemo` calls `memopayload.RebuildMemoPayload` before persisting (`server/router/api/v1/memo_service.go:108`).
2. **Memo update when the `content` field is in the update mask** — `UpdateMemo` recomputes the payload only for the `"content"` path and stores the new payload alongside the content (`server/router/api/v1/memo_service.go:447`).
3. **Bulk rebuild** — the `memopayload.Runner.RunOnce` background job re-derives the payload for all memos in batches of 100 (`server/runner/memopayload/runner.go:27-72`). Note this runner is defined but not currently wired into server startup (`server/server.go` only starts the `s3presign` runner), so in practice the API create/update paths are the live triggers.

**Extracted properties.** The single goldmark AST walk in `ExtractAll` extracts:
- `tags` — from memo tag nodes, deduplicated case-preservingly
- `property.title` — text of the first block-level H1 heading of the document
- `property.has_link` — any link node present
- `property.has_code` — any code block, fenced code block, or code span
- `property.has_task_list` — any task checkbox node
- `property.has_incomplete_tasks` — any unchecked task checkbox

(It also extracts `mentions`, but `RebuildMemoPayload` stores only tags and property.) These fields are surfaced to clients via the API converter at `server/router/api/v1/memo_service_converter.go:320` for list/preview rendering.
