Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook`
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook`
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook`
- memo comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook`

The first three are thin wrappers around the shared helper `dispatchMemoRelatedWebhook` (same file, line 48), which looks up the creator's webhooks; the comment event looks up the related memo owner's webhooks itself. All four converge on the same delivery path: each loops over the user's webhooks and calls `webhook.PostAsync(payload)` in `internal/webhook/webhook.go:184`, which enqueues the payload onto the bounded `asyncPostQueue` channel; background worker goroutines (started at `webhook.go:44`) drain the queue and perform the actual HTTP delivery via `webhook.Post` (`internal/webhook/webhook.go:120`), which marshals the JSON body, signs it (HMAC-SHA256 `webhook-signature` headers), and POSTs it to the configured URL.
