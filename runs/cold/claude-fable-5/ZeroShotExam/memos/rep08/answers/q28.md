**Runners the server actually starts** (all in `startBackgroundRunners`, `server/server.go:154-176`, called from `Server.Start`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started twice, in two modes:
  - `RunOnce(ctx)` — executed once immediately at server startup (server/server.go:163), synchronously.
  - `Run(ctx)` in a goroutine — driven by a `time.Ticker` with a fixed 12-hour interval (`const runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-40`); loops until its per-runner cancel context (created in `startBackgroundRunners`) is cancelled at shutdown.

That's the only background worker. There is no cron library in `go.mod`, and no other tickers besides the SSE heartbeat ticker in `server/router/api/v1/sse_handler.go` (which is per-connection keepalive, not a background worker).

**Unused infrastructure:** `server/runner/memopayload/runner.go` defines a second runner (`Runner` with `NewRunner` and `RunOnce`, which batch-rebuilds the payload of all memos). The server never instantiates or schedules it — `memopayload.NewRunner` has no call sites anywhere in the codebase. Only the package's standalone helper `RebuildMemoPayload` is used, called inline from the API layer when a memo is created or updated (`server/router/api/v1/memo_service.go:108` and `:447`). So the memopayload *runner* is dead scheduling infrastructure as far as the server is concerned.
