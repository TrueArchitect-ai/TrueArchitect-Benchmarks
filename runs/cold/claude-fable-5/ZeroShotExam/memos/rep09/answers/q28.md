The server starts exactly one background runner (in `startBackgroundRunners`, `server/server.go:153-174`, called from `Server.Start` at `server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — runs once immediately at startup via `RunOnce(ctx)` (`server/server.go:163`), then continuously in a goroutine via `Run()`, driven by a `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). It re-presigns S3 attachment URLs whose presigned links are nearing expiry. It is cancelled at shutdown via a per-runner `context.CancelFunc` and waited on with a `sync.WaitGroup`.

**Unused scheduling infrastructure:** the **memopayload runner** (`server/runner/memopayload/runner.go`) has the same runner shape — `NewRunner(...)` plus a batch-processing `RunOnce(ctx)` that rebuilds all memo payloads — but the server never instantiates or schedules it. `NewRunner`/`RunOnce` have no callers anywhere in the codebase; only the package's standalone helper `RebuildMemoPayload` is used, and only synchronously inside API request handling (`server/router/api/v1/memo_service.go:108` and `:447`), not as a background job. There is no cron library in `go.mod`; the only other ticker in the server is a per-connection SSE heartbeat (`server/router/api/v1/sse_handler.go:63-64`), which is request-scoped rather than a background worker.
