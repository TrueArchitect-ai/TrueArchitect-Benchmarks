**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (a ConnectRPC `Interceptor`, `web/src/connect.ts:156`) is attached to the Connect transport used by all service clients. On each request it calls `getRequestToken()` and sets an `Authorization: Bearer <token>` header; on a `Code.Unauthenticated` error it refreshes the token once (marking the retry with an `X-Retry` header) and retries, redirecting to login if that fails. Token state itself (get/set/expiry checks) lives in `web/src/auth-state.ts`.

**Token kinds it manages:**
- **JWT access token** — short-lived (15 minutes), held in frontend state and sent as the `Authorization: Bearer` header.
- **JWT refresh token** — long-lived (30 days), stored in the `memos_refresh` HTTP-only cookie (requests use `credentials: "include"`); the interceptor uses it via `AuthService.refreshToken` on a dedicated interceptor-free transport to obtain new access tokens, both proactively (preflight expiry check) and reactively on 401.

**Backend package that validates them:** `server/auth` — the `Authenticator` in `server/auth/authenticator.go` (with JWT parsing/constants in `server/auth/token.go`) validates access tokens statelessly, refresh tokens against the database, and also Personal Access Tokens (`memos_pat_` prefix). It's invoked by the Connect/gRPC interceptors in `server/router/api/v1` (e.g. `server/router/api/v1/connect_interceptors.go`) and by `server/router/fileserver`.
