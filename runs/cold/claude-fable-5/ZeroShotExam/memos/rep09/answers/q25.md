**Engine:** CEL (Google Common Expression Language, parsed with `cel-go`) — the memo filter engine lives in `internal/filter/` (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`).

**Mechanism:** The `ListMemos` filter string is compiled by `filter.DefaultEngine()` in a three-phase pipeline — (1) `cel-go` parses the expression and validates it against the memo-specific CEL environment declared in `internal/filter/schema.go`, (2) `internal/filter/parser.go` normalizes the CEL AST into a dialect-agnostic IR (`internal/filter/ir.go`), and (3) `internal/filter/render.go` walks the IR to emit a SQL fragment plus placeholder args tailored to the target dialect (`?` placeholders for SQLite/MySQL, `$n` for Postgres, plus dialect-specific JSON access like `JSON_EXTRACT` vs `->>`, tag matching via `LIKE` / `JSON_CONTAINS` / `@>`, and boolean coercion).

Each store driver invokes it with its own dialect via `filter.AppendConditions` (from `internal/filter/helpers.go`):
- `store/db/sqlite/memo.go:57-61` → `filter.DialectSQLite`
- `store/db/mysql/memo.go:65-69` → `filter.DialectMySQL`
- `store/db/postgres/memo.go:54-58` → `filter.DialectPostgres`

The pipeline is documented in `internal/filter/README.md`.
