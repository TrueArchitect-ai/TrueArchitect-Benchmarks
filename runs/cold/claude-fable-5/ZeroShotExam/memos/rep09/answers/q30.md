The memo lifecycle webhooks are all defined in `server/router/api/v1/memo_service_webhooks.go`:

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook`
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook`
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook`
- memo comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook`

The first three are thin wrappers around the shared helper `dispatchMemoRelatedWebhook` (same file, line 48), which looks up the creator's webhooks; the comment variant does its own lookup against the related memo owner's webhooks. All four converge on `webhook.PostAsync(payload)` in `internal/webhook/webhook.go:184`, which enqueues the payload onto a bounded channel (`asyncPostQueue`, capacity 128); four worker goroutines started in that package's `init()` drain the queue and perform the actual HTTP delivery via `webhook.Post` (`internal/webhook/webhook.go:120`), which signs (if a secret is set) and POSTs through the SSRF-guarded `safeClient`.
