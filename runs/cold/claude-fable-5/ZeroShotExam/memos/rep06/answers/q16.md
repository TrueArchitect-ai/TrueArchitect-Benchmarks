When the API's delete-memo handler calls `Store.DeleteMemo`, the store layer cleans up two kinds of related records before deleting the memo row itself (`store/memo.go:140-159`):

- **Memo relation records** (`memo_relation` rows) — deleted twice, once where the memo is the source (`MemoID`) and once where it is the target (`RelatedMemoID`), via `DeleteMemoRelation` (`store/memo_relation.go:51`)
- **Attachments** linked to the memo — listed with `ListAttachments` and each removed with `DeleteAttachment`

Only after those cleanups does it call the driver's `DeleteMemo`, which issues the `DELETE FROM memo` for the row itself (e.g. `store/db/sqlite/memo.go:237`).
