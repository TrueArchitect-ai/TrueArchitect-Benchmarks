**Interceptor:** `web/src/connect.ts` — the `authInterceptor` (a ConnectRPC `Interceptor`, line 156) is attached to the `createConnectTransport` used by all service clients.

**Tokens it manages:**
- **JWT access token** — short-lived (15 min), kept in memory via `web/src/auth-state.ts` and sent on every request as an `Authorization: Bearer <token>` header. The interceptor preflight-refreshes it when near expiry and reactively refreshes-and-retries once on an `Unauthenticated` (401) error, using an `X-Retry` header to avoid loops.
- **JWT refresh token** — long-lived (30 days), stored in the HTTP-only `memos_refresh` cookie (requests use `credentials: "include"`); the interceptor uses it indirectly through the `AuthService.RefreshToken` RPC on a separate interceptor-free transport to obtain new access tokens.

**Backend validation package:** `server/auth` — the `Authenticator` in `server/auth/authenticator.go` validates access tokens statelessly (`AuthenticateByAccessTokenV2` / `ParseAccessTokenV2`), validates refresh tokens against the database (`AuthenticateByRefreshToken`), and also handles Personal Access Tokens; token generation/parsing constants live in `server/auth/token.go`. It's shared by the gRPC/Connect API interceptors (`server/router/api/v1`) and the file server (`server/router/fileserver`).
