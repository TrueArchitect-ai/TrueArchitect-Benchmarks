Frontend requests are authenticated by a Connect RPC interceptor that attaches a `Authorization: Bearer <token>` header and transparently refreshes on expiry/401.

- **Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is installed on the Connect transport (line 188). It calls `getRequestToken()` to attach the token, preflight-refreshes near-expired tokens, and on a `Code.Unauthenticated` error refreshes once and retries (marked with an `X-Retry` header). Token state itself lives in `web/src/auth-state.ts`, and refreshes are deduplicated via `refreshAccessToken()` (also used by `web/src/hooks/useTokenRefreshOnFocus.ts`).

- **Token kinds:** a short-lived JWT **access token** (15 min, sent as the Bearer header, kept in client auth-state) and a long-lived **refresh token** (30 days, held in the `memos_refresh` cookie — the refresh call uses a separate interceptor-free transport with `credentials: "include"`). The backend additionally supports **personal access tokens** (`memos_pat_` prefix), though the web interceptor only manages the first two.

- **Backend package:** `server/auth` — `server/auth/token.go` defines the token generation/claims (access, refresh, PAT), and `server/auth/authenticator.go` / `server/auth/extract.go` extract and validate the Bearer token on incoming requests.

Answer format summary: `web/src/connect.ts`; access token (JWT Bearer) + refresh token (cookie), plus backend-side personal access tokens; `server/auth`.
