**Engine + path:** CEL (Common Expression Language), parsed with `cel-go`, in the dedicated filter package at `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`).

**Mechanism:** The `filter` field on `ListMemosRequest` (`proto/api/v1/memo_service.proto:326-339`) is a CEL expression that goes through a three-phase pipeline — cel-go parses and validates it against a memo-specific schema/environment (`internal/filter/schema.go`, `internal/filter/parser.go`), the CEL AST is normalized into a dialect-agnostic intermediate representation (`internal/filter/ir.go`), and a renderer (`internal/filter/render.go`) walks that IR to emit a SQL fragment plus placeholder args tailored to the target dialect (SQLite, MySQL, or Postgres), encapsulating differences like `?` vs `$n` placeholders, JSON access (`json_extract` / `JSON_EXTRACT` / `->>`), `LIKE` vs `ILIKE`, and tag membership (`LIKE` patterns on SQLite, `JSON_CONTAINS` on MySQL, `@>` on Postgres).

Each store driver invokes it via `filter.AppendConditions` with its dialect enum — e.g. `store/db/sqlite/memo.go:57-61` (and the analogous `store/db/mysql/memo.go`, `store/db/postgres/memo.go`) — appending the compiled fragment and args to the query's `WHERE` clause. The pipeline is documented in `internal/filter/README.md`.
