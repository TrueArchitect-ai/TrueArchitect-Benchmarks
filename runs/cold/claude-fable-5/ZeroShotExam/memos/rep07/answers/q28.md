The server starts exactly **one** background runner:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `startBackgroundRunners` (`server/server.go:153-174`). Trigger: an immediate `RunOnce(ctx)` at server startup, then a continuous `Run(ctx)` goroutine driven by a plain `time.NewTicker` with `runnerInterval = 12 hours` (`server/runner/s3presign/runner.go:27-36`), canceled via a per-runner `context.CancelFunc` on shutdown.

Not started by the server:

- **memopayload runner** (`server/runner/memopayload/runner.go`) — its `Runner`/`RunOnce` batch-rebuild loop is never instantiated or started anywhere. Only its package-level helper `memopayload.RebuildMemoPayload` is called synchronously during memo create/update in `server/router/api/v1/memo_service.go:108` and `:447`, so it runs inline with API requests, not as a background worker.

Unused scheduling infrastructure:

- **`internal/scheduler`** — a full cron-expression scheduler package (parser, jobs, middleware, e.g. `ParseCronExpression` in `internal/scheduler/scheduler.go`) is present with docs and tests, but it is imported by nothing outside its own package. Neither `server/server.go` nor `cmd/` uses it; the one real background runner (s3presign) schedules itself with a raw `time.Ticker` instead.
