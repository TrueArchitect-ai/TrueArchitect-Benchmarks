Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook`
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook`
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook`
- comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook`

The first three are thin wrappers over the shared helper `dispatchMemoRelatedWebhook` (same file, line 48), which looks up the creator's webhooks; the comment variant looks up the related memo owner's webhooks directly. All four converge on `webhook.PostAsync(payload)` in `internal/webhook/webhook.go:184`, which enqueues the payload on `asyncPostQueue` for bounded async delivery via `Post` (`internal/webhook/webhook.go:120`) — the function that actually performs the signed HTTP POST to the webhook URL.
