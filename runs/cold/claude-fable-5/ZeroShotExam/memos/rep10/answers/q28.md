The server starts exactly one background runner, in `startBackgroundRunners` at `server/server.go:153-174`:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — triggered once immediately at server startup via `RunOnce(ctx)` (`server/server.go:163`), then continuously in a goroutine via `Run(ctx)`, whose scheduling is a plain `time.NewTicker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:26-41`). It is stopped through a per-runner cancelable context and tracked with a `sync.WaitGroup` for graceful shutdown.

**Unused infrastructure:** the **memopayload runner** (`server/runner/memopayload/runner.go`) is a second runner package with a `Runner` type, `NewRunner` constructor, and a batch `RunOnce` method — but the server never instantiates or starts it. `NewRunner` has no call sites anywhere in the codebase; only the package-level helper `memopayload.RebuildMemoPayload` is used, called synchronously inside API request handling when memos are created/updated (`server/router/api/v1/memo_service.go:108,447`). Unlike s3presign, it also has no `Run`/ticker loop, so as a background runner it is entirely dormant. There is no cron library in `go.mod`; the only other ticker in the server is the per-connection SSE heartbeat (`server/router/api/v1/sse_handler.go:63-64`), which is part of request handling, not a background worker.
