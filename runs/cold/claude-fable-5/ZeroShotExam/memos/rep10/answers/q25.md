**Engine:** Google's CEL (Common Expression Language), parsed with `github.com/google/cel-go` — the filter engine lives in `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

**Mechanism:** The API layer (`server/router/api/v1/memo_service.go`) passes the filter string into `MemoFind.Filters`; the engine compiles it in a CEL environment (`filter.NewEngine`/`DefaultEngine` in `internal/filter/engine.go`), then `parser.go` walks the CEL AST (`exprv1.Expr`) into a dialect-agnostic `Condition` tree (IR, with `now` frozen to a single instant), and `render.go` renders that tree into parameterized SQL + args using per-dialect field templates defined in `schema.go` (`DialectSQLite`, `DialectMySQL`, `DialectPostgres` — e.g. MySQL uses `CONCAT('users/', %s)`/`UNIX_TIMESTAMP(...)` while SQLite/Postgres use `||`). Each store driver invokes it with its own dialect via `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args)` in `store/db/sqlite/memo.go:57-61`, with the analogous calls in `store/db/mysql/memo.go` and `store/db/postgres/memo.go`.
