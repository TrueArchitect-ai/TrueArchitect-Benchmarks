**No (with one package-internal test caveat); evidence below.**

- The factory is `NewDBDriver` in `store/db/db.go:14`, which calls `mysql.NewDB(profile)` at `store/db/db.go:22` based on the profile's driver setting.
- A repo-wide grep for importers of `github.com/usememos/memos/store/db/mysql` finds exactly one file: the factory itself (`store/db/db.go:8`). No other Go file in the codebase imports the mysql package, so no external code can call `mysql.NewDB` or build its `DB` type.
- A grep for all `NewDB` call sites confirms this: the only `mysql.NewDB` call is in the factory. (By contrast, the SQLite driver *is* constructed directly outside the factory, in `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416` — the MySQL driver has no such call sites.)

Caveat for completeness: inside the mysql package itself, the unit test `store/db/mysql/auth_config_test.go:12` constructs a bare `&DB{}` struct directly to test SQL-building logic. That's package-internal test code, not a use of the driver as a database connection; everywhere else, construction goes through the factory.
