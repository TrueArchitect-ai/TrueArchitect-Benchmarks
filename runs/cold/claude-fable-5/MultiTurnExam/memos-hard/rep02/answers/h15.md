Distinct enforcement sites for memo visibility:

- **gRPC/Connect API read gate `checkMemoReadAccess`** (used by `GetMemo`, comment listing, etc.) — `server/router/api/v1/memo_service.go:39` (call sites at `:356`, `:367`, and `server/router/api/v1/memo_service_comments.go:148`)
- **API list filtering** — `ListMemos` constrains `VisibilityList` to Public (anonymous) or Public+Protected (other signed-in users) — `server/router/api/v1/memo_service.go:219-225`
- **Per-handler API checks on related operations** — reactions (`server/router/api/v1/reaction_service.go:30-38,83`), attachment listing by memo filter (`server/router/api/v1/attachment_service.go:445-451`), memo-attachment listing (`server/router/api/v1/memo_attachment_service.go:214-222`), comment creation on private memos (`server/router/api/v1/memo_service_comments.go:41`)
- **File server (attachment/blob serving)** — before serving an attachment's bytes it checks the owning memo's visibility: public + anonymous allowed at `server/router/fileserver/fileserver.go:677`, private restricted to creator/admin at `:699`
- **RSS feeds** — explore and user feeds query only `store.Public` memos — `server/router/rss/rss.go:90` and `:141`
- **Frontend router (HTML meta/OpenGraph rendering)** — only renders memo metadata for public memos via `VisibilityList: []store.Visibility{store.Public}` — `server/router/frontend/frontend.go:150`
- **SSE event delivery** — the hub's `canReceive` filter decides per-subscriber whether a memo event may be delivered based on `event.Visibility` (public/protected/private rules, denying unknown values) — `server/router/api/v1/sse_hub.go:135-141` (visibility attached to events in `server/router/api/v1/sse_event_helpers.go:29-37`)
- **Notification emails** — comment/mention email content is redacted for private/protected memos — `server/notification/email.go:313-316` and `server/router/api/v1/user_service_notifications.go:309-312`
