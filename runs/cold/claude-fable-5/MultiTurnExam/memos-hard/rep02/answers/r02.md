**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** Searches for "rate limit", "throttle", and "limiter" across `server/`, `internal/`, and `cmd/` return nothing, and the Echo server registers only two middlewares at startup: `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`), plus per-route auth interceptors in the API layer — none of which count or limit requests per user.

The closest things that exist, for accuracy, are resource-concurrency guards rather than rate limits: `APIV1Service` holds weighted semaphores capping concurrent thumbnail generation at 3 and image processing at 2 across all users (`server/router/api/v1/v1.go:39-41,59-60`), and the webhook dispatcher uses a bounded queue of 128 with 4 workers (`internal/webhook/webhook.go:39-43`). But no middleware enforces request-count limits per user anywhere.
