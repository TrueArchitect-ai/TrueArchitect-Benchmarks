**Delivery function: `Post` (with `PostAsync` enqueueing onto a worker pool that calls it) — `internal/webhook/webhook.go`; protection mechanism: dial-time SSRF guard `safeDialContext`/`isReservedIP` (plus creation-time `ValidateURL`) — `internal/webhook/webhook.go` and `internal/webhook/validate.go`**

Details:

- **Where delivery executes:** `Post()` at `internal/webhook/webhook.go:120` builds the JSON payload, optionally adds Standard-Webhooks HMAC-SHA256 signature headers, and sends the HTTP POST via `safeClient.Do(req)` (`internal/webhook/webhook.go:152`). Asynchronous dispatch goes through `PostAsync()` (`internal/webhook/webhook.go:184`), which enqueues onto `asyncPostQueue`; four background goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post`. Callers live in e.g. `server/router/api/v1/memo_service_webhooks.go`.

- **SSRF protection:** all requests use the shared `safeClient`, whose transport replaces the dialer with `safeDialContext` (`internal/webhook/webhook.go:59-77`). At dial time it resolves the hostname and rejects any address matching the reserved/private ranges in `reservedCIDRs` (`internal/webhook/validate.go:14-23` — loopback, RFC-1918, link-local/cloud IMDS 169.254.169.254, and IPv6 equivalents) via `isReservedIP` (`internal/webhook/validate.go:44`). Checking at dial time also defeats DNS-rebinding attacks. A first line of defense, `ValidateURL` (`internal/webhook/validate.go:62`), applies the same reserved-IP check plus scheme validation when a webhook URL is registered. The guard can be deliberately disabled for self-hosted setups via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`).
