**Premise correction: neither — no message broker exists in this codebase.** There is no NATS or RabbitMQ (or any external queue) dependency; the webhook delivery workers consume from a plain in-process Go channel.

Actual mechanism (all in `internal/webhook/webhook.go`):

- The "queue" is a buffered channel declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`.
- Four worker goroutines are started in the package's `init()` (`internal/webhook/webhook.go:42-55`); each ranges over the channel and calls `Post(payload)` to perform the actual HTTP delivery.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send — if the 128-slot buffer is full, the dispatch is dropped and a warning is logged rather than blocking the request path.

So delivery is best-effort, in-memory, and process-local: nothing is persisted or brokered, and queued webhooks are lost if the process exits.
