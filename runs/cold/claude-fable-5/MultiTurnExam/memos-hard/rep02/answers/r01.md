**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" (Go, TS, config, docs) returns zero hits. The cache layer is a purpose-built, thread-safe **in-memory** cache (`sync.Map`-based) defined in `store/cache/cache.go` — no external connection is configured at all.

Actual mechanism:

- The `Cache` type (`store/cache/cache.go`) stores items in-process with per-item expiration, a background cleanup loop, and a max-item cap with eviction.
- The store constructor `New` in `store/store.go:37-53` builds three caches (instance settings, users, user settings) from a shared `cache.Config`.
- **TTL for user entries: 10 minutes** — `DefaultTTL: 10 * time.Minute` in `store/store.go:40` (matching the package default in `cache.DefaultConfig()`, `store/cache/cache.go:59`), with a 5-minute cleanup interval and a 1000-item cap. User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. `GetUser`/`ListUsers` cache warms), which uses that default TTL.
