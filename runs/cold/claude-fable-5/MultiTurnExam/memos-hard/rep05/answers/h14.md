**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`. It runs the memo's raw content through the goldmark-backed markdown service (`markdownService.ExtractAll`, implemented at `internal/markdown/markdown.go:355`) in a single parse and writes the results into the memo's `Payload` (`memo.Payload.Tags`, `memo.Payload.Property`).

**Triggers (production call sites):**
- **Memo creation** — `CreateMemo` at `server/router/api/v1/memo_service.go:108`, before the row is inserted. This also covers comment creation, since `CreateMemoComment` delegates to `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
- **Content update** — `UpdateMemo` at `server/router/api/v1/memo_service.go:447`, only when the update mask includes the `content` path; the rebuilt payload is persisted alongside the new content.
- There is also a batch rebuilder, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), that would recompute payloads for all memos in batches of 100, but nothing in production currently invokes it.

**Extracted properties:** the payload stored per memo (schema in `proto/store/memo.proto:8-22`) comprises:
- `Tags` — all `#tag` occurrences in the content
- `Property.has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks` — boolean content features
- `Property.title` — the text of the first H1 heading, if present

(`ExtractAll` also collects `@mentions`, but those are used for notification dispatch, not stored in the payload by `RebuildMemoPayload`.) This derived metadata is what list views and previews use — e.g. snippets/filters over tags and the task/link/code flags — without reparsing content on read.
