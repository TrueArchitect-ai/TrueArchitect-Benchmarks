**Delivery function:** `Post` — `internal/webhook/webhook.go:120` (with async dispatch via `PostAsync` and a 4-worker queue at `internal/webhook/webhook.go:39-55,184`). This is where the outbound HTTP POST actually executes (`safeClient.Do(req)` at line 152).

**Protection mechanism:** dial-time SSRF blocking of reserved/private IPs — `internal/webhook/webhook.go:59-77` (`safeDialContext`, installed as the shared client's `Transport.DialContext` at lines 32-37) together with the reserved-range list and check in `internal/webhook/validate.go:14-54` (`reservedCIDRs` / `isReservedIP`).

How it works: every webhook request goes through `safeClient`, whose custom `DialContext` resolves the target hostname and refuses to connect if any resolved address falls in a reserved range (loopback, RFC-1918 private ranges, link-local including the cloud IMDS address 169.254.169.254, and IPv6 equivalents). Doing the check at dial time also defeats DNS rebinding, since the address is validated on the same resolution used for the connection. There's an additional early check at registration time — `ValidateURL` in `internal/webhook/validate.go:62` rejects webhook URLs that resolve to reserved IPs (and non-http/https schemes) — plus an `AllowPrivateIPs` escape hatch (`validate.go:41`) for self-hosted deployments that intentionally target local-network services.
