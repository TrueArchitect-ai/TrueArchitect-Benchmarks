**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in the Go code turns up nothing — no client library, no connection config, no Redis-related settings.

**Actual mechanism:** The cache layer is a purely in-process, thread-safe in-memory cache implemented in `store/cache/cache.go` (a `sync.Map` with per-item expiration, periodic cleanup, and a max-item cap — see the `Cache` type and `Config` at `store/cache/cache.go:41-73`). No external service or connection is involved.

The user cache specifically is constructed in `Store.New` at `store/store.go:38-53`: `userCache: cache.New(cacheConfig)` with

- **DefaultTTL: 10 minutes** (`store/store.go:41`) — this is the TTL applied to user entries, since `Store.GetUser`/`ListUsers` populate the cache via plain `Set` (`store/user.go:143,167`), which uses the default TTL
- CleanupInterval: 5 minutes, MaxItems: 1000 (`store/store.go:42-43`)

So: user entries live in an in-memory cache with a 10-minute TTL, not in Redis.
