**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** Nothing registers one, and no rate-limiting library is in direct use — a repo-wide search for rate-limit/throttle/limiter terms, echo's `middleware.RateLimiter`, and `golang.org/x/time/rate` finds no hits in application code (`golang.org/x/time` appears only as an *indirect* dependency in `go.mod:151`).

The middleware actually registered on the Echo server is just `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`), plus auth/ACL interceptors in the API layer.

The closest things to request limiting that do exist are **server-wide concurrency caps, not per-user rate limits**:

- 3 concurrent thumbnail generations and 2 concurrent image-processing operations in the API service (`server/router/api/v1/v1.go:59-60`, acquired in `server/router/api/v1/attachment_service_image.go:71`)
- a thumbnail-generation semaphore in the file server (`server/router/fileserver/fileserver.go:116,448`)
- a bounded webhook dispatch queue of 128 with 4 workers (`internal/webhook/webhook.go:39-55`)

None of these track users or count requests per time window.
