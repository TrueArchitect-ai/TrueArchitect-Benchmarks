**Premise correction: neither — there is no message broker in this codebase at all.** No NATS, RabbitMQ, AMQP, Kafka, or any other broker client appears in the Go code or in `go.mod`.

**Actual mechanism:** Webhook delivery is handled entirely in-process with a plain Go channel, in `internal/webhook/webhook.go`:

- The "queue" is a buffered channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`).
- The "workers" are 4 goroutines started in the package's `init()`, which range over the channel and call `Post` for each payload (`internal/webhook/webhook.go:42-55`).
- Producers enqueue via `PostAsync`, which does a non-blocking send and drops the delivery (with a warning log) if the 128-slot buffer is full (`internal/webhook/webhook.go:184-196`).

So delivery is best-effort and in-memory only — nothing is persisted or brokered externally; a server restart loses any queued-but-undelivered webhooks.
