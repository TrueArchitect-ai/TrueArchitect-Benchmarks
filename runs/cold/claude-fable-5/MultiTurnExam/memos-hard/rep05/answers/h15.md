Distinct server surfaces that enforce memo visibility:

1. **gRPC/API v1 read access check** — `checkMemoReadAccess` in `server/router/api/v1/memo_service.go:39-68` (public/protected/private + archived rules for `GetMemo` etc.), plus query-level filtering for lists: `ListMemos` constrains `VisibilityList` to Public / Public+Protected depending on viewer (`server/router/api/v1/memo_service.go:219,225`; same pattern in `server/router/api/v1/user_service_stats.go:84,90,218,220`).

2. **API v1 sub-resources enforcing via the parent memo's visibility** — reactions: `server/router/api/v1/reaction_service.go:30,38,83`; comments: `server/router/api/v1/memo_service_comments.go:41`; attachment listing: `server/router/api/v1/attachment_service.go:445,451`.

3. **File server (raw attachment bytes over plain HTTP)** — `checkAttachmentPermission` in `server/router/fileserver/fileserver.go:649-704`: public memos served only when anonymous access is allowed, share-token fallback for private/protected, otherwise creator-or-admin required for private.

4. **SSE real-time event delivery** — `SSEClient.canReceive` in `server/router/api/v1/sse_hub.go:134-144`: private-memo events are delivered only to the creator or an admin, using the visibility stamped onto events in `server/router/api/v1/sse_event_helpers.go:29-38`.

5. **RSS feeds** — `server/router/rss/rss.go:90,141`: feed queries hard-restrict `VisibilityList` to `store.Public` only.

6. **Frontend router (sitemap/SEO)** — `server/router/frontend/frontend.go:149-151`: sitemap generation lists only `store.Public` memos.
