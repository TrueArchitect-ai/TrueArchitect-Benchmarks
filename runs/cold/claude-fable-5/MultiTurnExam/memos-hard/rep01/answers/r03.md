**Premise correction: there is no nightly database-cleanup job, and the cron scheduler isn't wired into the server at all.**

Specifically:

- A cron scheduler package does exist (`internal/scheduler/` — `scheduler.go`, `job.go`, `parser.go` with cron-expression parsing), but **nothing in production code imports it**. The only importers are its own test files (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). No jobs — cleanup or otherwise — are ever registered with it.
- No database-cleanup/vacuum/purge job exists anywhere in the server. The background work that does run is scheduled differently: the S3 presign refresh runner uses a plain `time.Ticker` every 12 hours (`server/runner/s3presign/runner.go:27`, started from `server/server.go:153-173`), and the in-memory caches run an expired-entry cleanup goroutine every 5 minutes (`store/cache/cache.go`, config at `store/store.go:42`) — neither touches the database for cleanup, and neither uses cron or a time-of-day schedule.

So there is no "time" to report: the premise of a cron-scheduled nightly DB cleanup doesn't match this codebase.
