**Premise correction: neither.** There is no message broker in this codebase — a repo-wide search for NATS, RabbitMQ, or AMQP in the Go source finds nothing.

**Actual mechanism:** webhook delivery is handled entirely in-process with a buffered Go channel, all in `internal/webhook/webhook.go`:

- The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a bounded channel declared at `internal/webhook/webhook.go:39`.
- The "workers" are 4 goroutines started in the package's `init()` (`webhook.go:42-55`), each ranging over the channel and calling `Post` to execute the outbound HTTP delivery.
- Producers enqueue via `PostAsync` (`webhook.go:184-197`), which does a non-blocking send; if the 128-slot buffer is full, the dispatch is dropped with a warning log rather than blocking the request path.

So there's no queue declaration in any broker — just a channel and worker goroutines living inside the server process, with no persistence or cross-process delivery.
