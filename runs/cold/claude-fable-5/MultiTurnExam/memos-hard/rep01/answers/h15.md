Memo visibility is enforced independently on each server surface that can expose memo content:

**gRPC/Connect API (api/v1)** — the main surface, with per-RPC checks:
- Memo reads: `GetMemo` rejects non-public memos for anonymous users and private memos for non-creators (`server/router/api/v1/memo_service.go:55-63`); `ListMemos` constrains queries to `Public`/`Protected` visibility lists or a creator filter (`memo_service.go:219-225`)
- Reactions: visibility checked before listing/creating reactions on a memo (`server/router/api/v1/reaction_service.go:30-38, 83`)
- Attachments via memo linkage: `server/router/api/v1/attachment_service.go:436-451` and `server/router/api/v1/memo_attachment_service.go:213-222`
- User stats built from memos: visibility-filtered queries (`server/router/api/v1/user_service_stats.go:84-90, 218-220`)
- Mention notifications: suppressed for private memos the mentioned user can't see (`server/router/api/v1/memo_mention_helpers.go:62-84`)

**Raw file serving (HTTP file server)** — when a browser fetches an attachment blob, the linked memo's visibility is re-checked: public requires anonymous access to be allowed, private requires creator or admin (`server/router/fileserver/fileserver.go:674-699`).

**RSS feeds** — feed queries are hard-limited to `store.Public` memos only (`server/router/rss/rss.go:90` and `:141`).

**Frontend/SEO router** — server-rendered/meta pages only load `store.Public` memos (`server/router/frontend/frontend.go:150`).

**Email notifications** — outbound notification emails redact content based on visibility (`server/notification/email.go:313-316`).
