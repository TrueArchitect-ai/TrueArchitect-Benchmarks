**Premise correction: there is no Redis in this codebase.** A repo-wide search for "redis" in the Go source finds nothing — the cache layer is a homegrown, thread-safe **in-memory cache** (a `sync.Map` with TTL expiration and background cleanup), defined in `store/cache/cache.go`. No external cache service or connection is configured anywhere.

**Actual mechanism:** the store constructor `store.New` builds three cache instances — including the user cache — from a hardcoded config at `store/store.go:40-45`:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

The user cache is created at `store/store.go:52` (`userCache: cache.New(cacheConfig)`), and user entries are written with the default TTL via `Set` (e.g. in `Store.GetUser`/`ListUsers`, `store/user.go:136-168`), since no custom `SetWithTTL` is used for users. The same 10-minute default also appears as the package default in `cache.DefaultConfig()` (`store/cache/cache.go:57-63`).

**So: user cache entries live in process memory with a 10-minute TTL**, cleaned up every 5 minutes — no Redis connection exists to configure.
