**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** I searched the Go source for rate-limiting in all its likely forms — "ratelimit"/"rate limit", "throttle", `golang.org/x/time/rate`, Echo's `middleware.RateLimiter`, and every registered middleware/interceptor — and none exists.

What actually is registered:

- **Echo HTTP middleware** (`server/server.go:51-52`): only `middleware.Recover()` and a CORS middleware — no rate limiter, and nothing user-scoped.
- **Connect RPC interceptors** (`server/router/api/v1/connect_interceptors.go`): a `MetadataInterceptor` (header→metadata conversion) and a `LoggingInterceptor` — again, no rate limiting.

The closest things to request limits are not per-user rate limits at all: concurrency semaphores capping expensive image work server-wide — 3 concurrent thumbnail generations and 2 concurrent image-processing operations (`server/router/api/v1/v1.go:59-61`, plus a thumbnail semaphore in `server/router/fileserver/fileserver.go:106`) — and a 1 MiB cap on webhook response bodies (`internal/webhook/webhook.go:158`). There are no per-user request-count limits anywhere, so no registration site or limit values can be cited.
