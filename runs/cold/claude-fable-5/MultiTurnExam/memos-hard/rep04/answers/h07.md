- `FileServerService.parseDataURI` (decodes the stored `user.AvatarURL` data URI into bytes) — back in `server/router/fileserver/fileserver.go:196`, then validated against `avatarAllowedTypes` and written with `c.Blob(...)` (`fileserver.go:201-209`)

Notes on the data's location: the profile image isn't a file on disk — it's stored inline as a data URI in the `avatar_url` column of the `user` table, so the "data layer" terminus is the user row fetched by the driver's `ListUsers`. Access control for other users' avatars is minimal by design: on instances allowing anonymous access no auth is required; on private instances any valid session/token suffices (`fileserver.go:171-181`).
