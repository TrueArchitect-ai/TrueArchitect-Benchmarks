Distinct enforcement sites for memo visibility:

- **gRPC/Connect API read check** — `APIV1Service.checkMemoReadAccess` — `server/router/api/v1/memo_service.go:39-68` (public → anyone; protected → any authenticated user; private → creator only). Used by memo reads, and echoed by per-operation checks in sibling handlers (`reaction_service.go:30-38,83`, `attachment_service.go:445-451`, `memo_service_comments.go:41`, `memo_attachment_service.go:214-222`).
- **API list filtering** — `ListMemos` constrains the store query's `VisibilityList` based on the caller (anonymous → public only; other users → public+protected) — `server/router/api/v1/memo_service.go:219-225`, with the same pattern for user stats at `server/router/api/v1/user_service_stats.go:84-90,218-220`.
- **File server (attachment binaries)** — `FileServerService.checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650-704`: resolves the owning memo and enforces its visibility before serving bytes (public + anonymous-allowed passes; share-token fallback; otherwise authenticated user, with private restricted to creator/admin).
- **RSS feeds** — queries are hard-limited to `VisibilityList: []store.Visibility{store.Public}` — `server/router/rss/rss.go:90,141`.
- **Frontend sitemap/SEO surface** — sitemap generation lists only public memos — `server/router/frontend/frontend.go:149-151`.
- **SSE event stream** — `SSEClient.canReceive` filters realtime events: private-memo events are delivered only to the creator or an admin — `server/router/api/v1/sse_hub.go:134-144`.
- **Notification surfaces** — mention/comment notifications and emails suppress or gate content for private/protected memos — `server/router/api/v1/memo_mention_helpers.go:62-84`, `server/router/api/v1/user_service_notifications.go:309-312`, `server/notification/email.go:313-316`.
