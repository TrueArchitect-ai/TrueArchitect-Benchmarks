**Delivery function: `Post` (with `PostAsync` enqueuing onto a worker pool that calls it) — `internal/webhook/webhook.go`; protection mechanism: dial-time SSRF guard `safeDialContext` / `isReservedIP` (plus registration-time `ValidateURL`) — `internal/webhook/webhook.go` and `internal/webhook/validate.go`**

Details:

- **Delivery:** `Post` at `internal/webhook/webhook.go:120` builds the JSON payload, optionally adds Standard Webhooks HMAC-SHA256 signature headers, and sends the POST via the shared `safeClient`. Asynchronous dispatch goes through `PostAsync` (`webhook.go:184`), which enqueues onto `asyncPostQueue`, drained by 4 worker goroutines started in `init()` (`webhook.go:42-55`) that each call `Post`.
- **Protection:** All requests use `safeClient`, whose `http.Transport` replaces the dialer with `safeDialContext` (`internal/webhook/webhook.go:59-77`). At dial time it resolves the hostname and rejects any address matching the reserved/private ranges in `reservedCIDRs` via `isReservedIP` (`internal/webhook/validate.go:14-54`) — loopback, RFC-1918, link-local/IMDS (169.254.169.254), and IPv6 equivalents. Checking at dial time also defeats DNS-rebinding. A first line of defense, `ValidateURL` (`internal/webhook/validate.go:62`), applies the same reserved-IP check plus scheme validation when a webhook URL is registered. The guard can be deliberately disabled for self-hosted setups via `AllowPrivateIPs` (`validate.go:41`).
