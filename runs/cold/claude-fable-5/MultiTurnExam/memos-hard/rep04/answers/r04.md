**Premise correction: neither — there is no message broker in this codebase.** No NATS, no RabbitMQ (or Kafka, etc.); searches for those terms and their client libraries turn up nothing in `go.mod` or the source.

Actual mechanism: webhook delivery is entirely in-process, built on a buffered Go channel:

- The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — declared at `internal/webhook/webhook.go:39`.
- The "workers" are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over the channel and calling `Post` to execute the HTTP delivery.
- Producers call `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send onto the channel; if the 128-slot buffer is full, the dispatch is **dropped** with a warning log rather than blocking or being persisted.

Consequently there is no durability or cross-process distribution: queued webhook deliveries live only in memory and are lost on server shutdown or when the buffer overflows.
