**Premise correction: there is no nightly database-cleanup job, and the cron scheduler isn't used for anything in the server at all.**

What I found:

- The repo does contain a cron-style scheduler package, `internal/scheduler/` (with `parser.go` supporting cron expressions, `scheduler.go`, jobs, middleware, examples). However, grepping for imports of `internal/scheduler` outside the package itself returns **zero production or test consumers** — it's a self-contained library that nothing in the server wires up.
- No database-cleanup job exists anywhere. Searches for cleanup/nightly/vacuum-style jobs turn up only inline cleanup logic that runs as part of request handling (e.g., attachment cleanup during user deletion in `server/router/api/v1/user_service.go:421-450`, relation/attachment cleanup in `DeleteMemo` at `server/router/api/v1/memo_service.go:579`).
- The only scheduled background work in the server is the S3 presign runner, started in `Server.startBackgroundRunners` (`server/server.go:162-171`) and ticking every 12 hours via a plain `time.Ticker` (`server/runner/s3presign/runner.go:27`) — it refreshes presigned URLs, not database cleanup, and doesn't use the cron scheduler or a clock time.
- The in-memory caches run expiry sweeps every 5 minutes (`store/store.go:42`), also via `time.Ticker` — again not a cron job and not database cleanup.

So there's no scheduled time to report: no such job exists.
