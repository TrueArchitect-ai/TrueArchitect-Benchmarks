**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" (Go, TypeScript, and docs) returns nothing — the cache layer is a purely in-process, thread-safe in-memory cache, not an external store.

Actual mechanism:

- The cache implementation is `Cache` in `store/cache/cache.go` — an in-memory map with per-entry TTL expiration, a background cleanup goroutine (`CleanupInterval`), and a `MaxItems` bound with eviction.
- User entries live in the `userCache` field of the store, constructed in `Store.New` at `store/store.go:38-53` alongside `instanceSettingCache` and `userSettingCache`, all sharing one config.
- **The TTL that applies to user entries is 10 minutes** — `DefaultTTL: 10 * time.Minute` in the `cacheConfig` at `store/store.go:41` (matching `cache.DefaultConfig()` in `store/cache/cache.go:57-64`), with cleanup sweeps every 5 minutes and a 1000-item cap. User entries are written via `Set` (default TTL) from `Store.GetUser`/`ListUsers` (`store/user.go:132,143,167`).

So there is no connection configuration at all — nothing external to connect to; caching is per-process and lost on restart.
