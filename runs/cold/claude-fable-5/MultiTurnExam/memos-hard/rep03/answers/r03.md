**Premise correction: no nightly database-cleanup job exists, and the cron scheduler isn't even wired into the server.**

Two parts to this:

1. **There is a cron scheduler package** — `internal/scheduler/` (a "GitHub Actions-inspired cron job scheduler" per `internal/scheduler/doc.go`, with cron-expression parsing in `parser.go` and job definitions in `job.go`) — but it is **never used by any production code**. A repo-wide grep shows no imports of it outside its own package's tests and examples; the only "daily-cleanup" mention is a hypothetical snippet in the package documentation (`internal/scheduler/doc.go:15`), not a real job.

2. **No database-cleanup job is scheduled anywhere else either.** The server's only background work is started in `Server.startBackgroundRunners` (`server/server.go:153-174`), which runs a single runner: the S3 presigned-URL refresher on a plain 12-hour `time.Ticker` (`server/runner/s3presign/runner.go:27`) — a URL-refresh task, not database cleanup, and not cron-based. The only "cleanup" resembling activity is the in-memory cache's expired-entry sweep every 5 minutes (`store/store.go:42`, `store/cache/cache.go`), which is in-process memory housekeeping, not a database job.

So there is no time to report: the premise (a scheduled nightly DB cleanup) doesn't match the codebase.
