**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`. It runs the memo's markdown content through `markdownService.ExtractAll` (implemented at `internal/markdown/markdown.go:356`) in a single AST pass and writes the results into the memo's `Payload` (`memo.Payload.Tags`, `memo.Payload.Property`), which is persisted as a JSON column on the memo row.

**Triggers (recomputation happens on):**
1. **Memo creation** — `CreateMemo` calls it before inserting, at `server/router/api/v1/memo_service.go:108`. This also covers comment creation, since `CreateMemoComment` delegates to `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
2. **Content update** — `UpdateMemo` calls it when the `content` field is in the update mask, at `server/router/api/v1/memo_service.go:447`, storing the fresh payload alongside the new content.
3. **Bulk rebuild** — `Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) can re-derive the payload for *all* memos in batches of 100; however, this runner is not wired into server startup, so in practice only the create/update paths fire.

**Extracted properties:** from `markdown.ExtractedData` (`internal/markdown/markdown.go:21-25`), the payload gets:
- `Tags` — deduplicated `#tag` occurrences (excluding tags inside links/images)
- `Property` (`storepb.MemoPayload_Property`): `Title` (text of a leading H1 heading), `HasLink`, `HasCode` (code blocks/spans), `HasTaskList`, and `HasIncompleteTasks` (unchecked checkboxes)

(`ExtractAll` also extracts `Mentions`, but `RebuildMemoPayload` doesn't store those in the payload — they drive mention notifications instead. The list/preview *snippet* is derived separately at render time via `getMemoContentSnippet`, `server/router/api/v1/memo_service_webhooks.go:83`.)
