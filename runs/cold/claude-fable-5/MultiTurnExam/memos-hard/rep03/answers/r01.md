**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" (Go sources, `go.mod`) returns nothing — the cache layer is a purely in-process, in-memory cache built on `sync.Map`, defined in `store/cache/cache.go` (the `Cache` type at `store/cache/cache.go:66`, with TTL, periodic cleanup, and max-item eviction). No external connection is configured because none exists.

**Actual mechanism and the user-entry TTL:** the store constructs three of these in-memory caches — instance settings, users, and user settings — in `store.New` at `store/store.go:47-53`, using a hard-coded config at `store/store.go:40-45`:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

User entries are written to `userCache` via plain `Set` (e.g., `store/user.go:143,167` after `ListUsers`/`GetUser`), which applies the default TTL (`Set` delegates to `SetWithTTL` with `config.DefaultTTL` in `store/cache/cache.go`). **So user cache entries live 10 minutes**, with expired items purged by a cleanup goroutine every 5 minutes, and the whole thing shut down in-process via `Store.Close` (`store/store.go:72-79`) — no Redis, no network configuration, no persistence.
