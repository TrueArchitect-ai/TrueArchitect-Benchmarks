**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** A repo-wide search for rate-limit/limiter/throttle terms in the Go sources finds nothing, and the actual middleware stack confirms it: the Echo server registers only `middleware.Recover()` (`server/server.go:51`), CORS (`server/cors.go:14`), and static-file serving for the frontend (`server/router/frontend/frontend.go:54`). The gRPC-Gateway/Connect layer adds only authentication/authorization middleware and interceptors (`server/router/api/v1/v1.go:65-95`, `server/router/api/v1/connect_interceptors.go`) — Echo's built-in `RateLimiter` middleware is never used.

The closest things that exist are not per-user rate limits but global concurrency caps on expensive operations:

- Thumbnail generation is limited to 3 concurrent operations via a weighted semaphore — `server/router/fileserver/fileserver.go:46,107,116,448`.
- The API service similarly holds `thumbnailSemaphore` (3) and `imageProcessingSemaphore` (2) — `server/router/api/v1/v1.go:59-60`.
- The webhook dispatcher bounds outbound work with a 128-entry queue and 4 workers — `internal/webhook/webhook.go:39-55`.

These protect server resources regardless of which user makes the request; no middleware counts or limits requests per user (or per IP) anywhere.
