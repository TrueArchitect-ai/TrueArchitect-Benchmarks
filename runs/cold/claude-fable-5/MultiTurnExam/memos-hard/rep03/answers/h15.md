Distinct places where memo visibility is enforced, one per server surface:

- **gRPC/Connect API v1 — single-memo read gate:** `APIV1Service.checkMemoReadAccess` — `server/router/api/v1/memo_service.go:39-68` (public open; protected requires any authenticated user; private requires creator), plus query-time list filtering in `ListMemos` — `server/router/api/v1/memo_service.go:219-225`. The same rules are re-applied by sibling RPCs guarding memo-adjacent data: reactions (`server/router/api/v1/reaction_service.go:30-38,83`), linked attachments (`server/router/api/v1/attachment_service.go:436-451`), and memo relations (`server/router/api/v1/memo_relation_service.go:109-111`).
- **HTTP file server — attachment downloads:** `FileServerService.checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650-704` (anonymous access only for public memos on public instances, share-token fallback, private restricted to creator/admin).
- **SSE real-time events — delivery filtering:** `SSEClient.canReceive` — `server/router/api/v1/sse_hub.go:134-144` (events for private memos are delivered only to the creator or admins).
- **RSS feeds:** queries are hard-restricted to `VisibilityList: []store.Visibility{store.Public}` — `server/router/rss/rss.go:90` and `:141`.
- **Frontend/SEO router — sitemap:** only public memos are listed — `server/router/frontend/frontend.go:150`.
- **Email notifications — content redaction:** `canViewerAccessMemo` and visibility-based content suppression — `server/notification/email.go:306-319` and `:313-316` (private/protected memo content is withheld from recipients who couldn't view the memo).
