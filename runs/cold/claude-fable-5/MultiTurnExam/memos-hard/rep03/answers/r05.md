**Premise correction: there is no GraphQL API in this project — no schema files, no GraphQL libraries in `go.mod`, no resolver code anywhere.**

**Actual API surface:** the public API is defined with **Protocol Buffers / gRPC**, served over HTTP two ways:

- **Schema definitions:** `.proto` files under `proto/api/v1/` — `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto` — with generated Go code in `proto/gen/` (build config in `proto/buf.yaml` / `proto/buf.gen.yaml`).
- **Serving stack:** `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`) mounts two transports on the Echo server: a **gRPC-Gateway** (`grpc-ecosystem/grpc-gateway/v2`) that exposes the services as a RESTful JSON HTTP API, and **ConnectRPC** handlers (`connectrpc.com/connect`, wired around `server/router/api/v1/v1.go:131-139` and `connect_services.go`) for browser clients, replacing grpc-web.
- A generated **OpenAPI** description of the REST surface also ships at `proto/gen/openapi.yaml`, embedded via `proto/openapi_embed.go`.

Beyond the RPC API, the remaining HTTP surfaces are plain Echo routes: file/avatar serving (`server/router/fileserver/fileserver.go`), RSS feeds (`server/router/rss/rss.go`), and the static frontend + SEO endpoints (`server/router/frontend/frontend.go`). No GraphQL anywhere.
