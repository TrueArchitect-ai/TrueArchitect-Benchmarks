**Runners the server actually starts:**

- s3presign runner (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:153-174`): one immediate `RunOnce(ctx)` at startup, then a goroutine running `Run(ctx)` driven by a plain `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-35`). It refreshes S3 presigned URLs.

That is the only background runner the server launches.

**Not started by the server:**

- memopayload runner (`server/runner/memopayload/runner.go`) — its `Runner`/`RunOnce` is never constructed or started by the server; only the standalone helper `memopayload.RebuildMemoPayload` is called inline from the memo handlers (`server/router/api/v1/memo_service.go:108,447`).

**Unused scheduling infrastructure:** the full cron-style scheduler package at `internal/scheduler/` (scheduler.go, job.go, parser.go, middleware.go) is referenced only by its own tests/examples — no server code imports it. The server's only actual scheduling mechanism is the raw `time.Ticker` in the s3presign runner.
