- **Interceptor:** `web/src/connect.ts` — the ConnectRPC auth interceptor attaches `Authorization: Bearer <token>` to every request (line 97–99), proactively refreshes near-expiry tokens, and on a 401 performs a deduplicated token refresh (via the manager and `refreshAccessToken`) and retries once, using token state from `web/src/auth-state.ts`.
- **Tokens managed:** short-lived **JWT access tokens** (~15 minutes, sent as Bearer headers) and a **refresh token** (obtained/rotated via `AuthService.RefreshToken` on a separate transport, stored server-side as a session and validated against the database). The backend additionally accepts long-lived **Personal Access Tokens (PATs)** for programmatic access, though the web app itself manages the access/refresh pair.
- **Backend validation package:** `server/auth` — `server/auth/authenticator.go` (`AuthenticateByAccessTokenV2` for stateless JWT validation, `AuthenticateByRefreshToken`, `AuthenticateByPAT`), used by the gRPC-gateway middleware, Connect interceptor, and file server.
