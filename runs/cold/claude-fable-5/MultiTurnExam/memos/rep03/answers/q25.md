**Engine: CEL (Common Expression Language), via `github.com/google/cel-go`, wrapped in the project's `internal/filter` package** (`internal/filter/engine.go` — `Engine` "parses CEL filters into a dialect-agnostic condition tree"; supporting files `parser.go`, `ir.go`, `schema.go`, `render.go`).

**Mechanism:** The filter string is compiled by the cel-go environment into an AST, translated into a dialect-agnostic condition IR (`internal/filter/parser.go` / `ir.go`), and then rendered to parameterized SQL per dialect by the renderer in `internal/filter/render.go`, which switches on `DialectSQLite` / `DialectMySQL` / `DialectPostgres` (e.g. `ILIKE $1` for Postgres vs `LIKE ?` for MySQL); each store driver invokes this via `filter.DefaultEngine()` + `filter.AppendConditions(...)` when building its WHERE clause (e.g. `store/db/sqlite/memo.go:57-61`).
