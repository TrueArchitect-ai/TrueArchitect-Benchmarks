**Interceptor:** `web/src/connect.ts` — the `authInterceptor` (lines 156–178) attached to the ConnectRPC transport. It attaches `Authorization: Bearer <token>` to every request, preflight-refreshes near-expired tokens (`getRequestToken`, line 124), and on a 401 (`Code.Unauthenticated`) performs one deduplicated token refresh and retry before redirecting to login.

**Tokens managed:** a short-lived JWT **access token** (kept in frontend auth state, `web/src/auth-state.ts`, sent as a Bearer header) and a **refresh token** (HTTP-only cookie, sent via `credentials: "include"` and exchanged through `AuthService.RefreshToken` on a separate interceptor-free transport, `web/src/connect.ts:65-91`). The backend additionally accepts long-lived **Personal Access Tokens (PATs)** as Bearer tokens for programmatic access, though the web interceptor itself only manages access/refresh tokens.

**Backend validation package:** `server/auth` — `server/auth/authenticator.go` (`AuthenticateByAccessTokenV2` for JWT access tokens, `AuthenticateByRefreshToken` for refresh tokens, `AuthenticateByPAT` for PATs, with `resolveBearer` distinguishing PAT-prefixed tokens from JWTs; JWT parsing lives in `server/auth/token.go`). It's invoked from the API middleware in `server/router/api/v1/` for both gateway and Connect requests.
