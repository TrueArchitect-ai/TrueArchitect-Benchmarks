**Interceptor:** `web/src/connect.ts` — the auth interceptor sets an `Authorization: Bearer <token>` header on every ConnectRPC request (line 97), proactively refreshes near-expiry tokens, and on a 401 reactively calls the AuthService `refreshToken` RPC (deduplicated via a token-refresh manager) before retrying. Token storage/expiry helpers live in `web/src/auth-state.ts`.

**Token kinds:** a short-lived **access token** (JWT, held in memory/browser state and sent as the Bearer header) and a **refresh token** (sent via cookie to the `RefreshToken` RPC to mint new access tokens). The backend additionally accepts long-lived **Personal Access Tokens (PATs)** as Bearer tokens for programmatic access.

**Backend package:** `server/auth` — `server/auth/authenticator.go` validates them (`resolveBearer` dispatches access tokens vs. PATs; `AuthenticateByRefreshToken` at line 61 checks refresh tokens against the database; `AuthenticateByPAT` at line 102 checks hashed PATs), with JWT parsing in `server/auth/token.go`.
