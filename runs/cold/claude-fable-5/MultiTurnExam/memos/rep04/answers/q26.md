Tables affected when `Store.DeleteMemo` runs (`store/memo.go:140-158`):

- **memo_relation** — explicitly deleted first, both where the memo is the source (`MemoID`) and the target (`RelatedMemoID`) (`store/memo.go:142-147`)
- **attachment** — all attachments linked to the memo are deleted via `Store.DeleteAttachment` (`store/memo.go:148-157`, which also removes the underlying file/blob storage, `store/attachment.go:132-149`)
- **memo** — the memo row itself, deleted last by the driver (`store/memo.go:158`, e.g. `store/db/sqlite/memo.go:237`)

Additionally, the API-level handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:568-577`) first deletes all comment memos (relations of type COMMENT pointing at this memo) by calling `Store.DeleteMemo` for each — so those comments' own `memo`, `memo_relation`, and `attachment` rows are cascaded through the same path. No other tables (e.g. `reaction`) are deleted in this flow — reactions are only listed for the webhook payload.
