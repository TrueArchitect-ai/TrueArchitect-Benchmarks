**Interceptor:** `web/src/connect.ts` — the `authInterceptor` (lines 156-178), installed on the Connect transport (line 188), with token state helpers in `web/src/auth-state.ts`.

**Token kinds it manages:**
- A short-lived **JWT access token**, attached as an `Authorization: Bearer <token>` header on every request (with proactive preflight refresh when near expiry, and reactive refresh-and-retry on a 401/`Unauthenticated` error).
- An HTTP-only **refresh token cookie**, sent automatically via `credentials: "include"` and used by a separate interceptor-free transport (`refreshAuthClient.refreshToken`, lines 65-83) to obtain new access tokens with server-side rotation.

**Backend validation package:** `server/auth` — `server/auth/authenticator.go` validates the bearer JWT (and also supports personal-access-token hashes via `GetUserByPATHash`), looking up the user with `store.GetUser`; the refresh/session flow lives in `server/router/api/v1/auth_service_session.go`.
