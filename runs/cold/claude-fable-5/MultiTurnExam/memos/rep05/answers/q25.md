**Engine: CEL (Common Expression Language) via `cel-go` — `internal/filter/`**

**Mechanism:** Filter strings are parsed as CEL expressions with `cel-go` and validated against the memo field schema (`internal/filter/schema.go`, `engine.go`), converted into a dialect-agnostic intermediate representation (`internal/filter/parser.go`, `ir.go`), and then the renderer (`internal/filter/render.go`) walks that IR to emit dialect-specific SQL WHERE clauses with placeholders — each driver calls `filter.AppendConditions(...)` with its own dialect constant, e.g. `filter.DialectSQLite` in `store/db/sqlite/memo.go:61` (with dialect divergences like `strftime` vs `EXTRACT` vs MySQL date functions handled in `render.go`, and SQLite's regex support backed by a Go function registered in `store/db/sqlite/functions.go`). The pipeline is documented in `internal/filter/README.md`.
