**Premise correction:** The question presupposes a message broker (NATS or RabbitMQ) — but the webhook delivery workers use **neither**. This repository (memos) has no external message broker at all; there is no NATS, RabbitMQ, Redis, or Kafka involved in webhook delivery.

**Actual mechanism:** Webhook delivery is handled entirely in-process using a **buffered Go channel** as the queue, drained by a fixed pool of goroutine workers.

- The queue is declared in `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel with capacity 128.
- The workers are started in the package `init()` at `internal/webhook/webhook.go:42-55`, which spawns **4 goroutines** (`for range 4`), each looping over `asyncPostQueue` and calling `Post()` to make the outbound HTTP request.
- Enqueue happens in `PostAsync()` at `internal/webhook/webhook.go:184-196`, which does a non-blocking `select` send onto the channel and drops the payload (with a warning log) if the buffer is full.

So the "broker" is just an in-memory Go channel bounded at 128 items, consumed by 4 worker goroutines — no NATS, no RabbitMQ.
