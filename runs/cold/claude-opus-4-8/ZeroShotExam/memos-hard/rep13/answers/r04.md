**Premise correction:** The webhook delivery workers in this repository (Memos, a Go project) do **not** consume from either NATS or RabbitMQ. Neither broker exists in the codebase — the only match for those terms anywhere is a stray string in a Catalan locale file (`web/src/locales/ca.json`), and `go.mod` declares no message-broker dependency at all.

**Actual mechanism:** Webhook delivery uses an **in-process Go channel with a fixed worker pool** — no external broker or persistent queue.

- The "queue" is declared as a buffered channel in `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  (capacity 128, in-memory only).

- The workers are 4 goroutines spawned in the package `init()` at `internal/webhook/webhook.go:42-55`, each ranging over that channel and calling `Post()` to make the outbound HTTP request.

- Enqueueing happens in `PostAsync()` at `internal/webhook/webhook.go:184-196`, which does a non-blocking `select` send onto `asyncPostQueue` and **drops the payload** (logging a warning) if the buffer is full — there is no broker-backed durability or retry.

So the delivery path is purely `PostAsync → buffered channel → 4 goroutine workers → HTTP POST`, all within a single process; nothing is consumed from an external message broker.
