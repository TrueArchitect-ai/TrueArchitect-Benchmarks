**Protection mechanism** — `safeDialContext` in `internal/webhook/webhook.go` (lines ~59–77). It is wired in as the `DialContext` of `safeClient`'s transport, so on every connection it re-resolves the target host and rejects any address in a reserved/private range (`isReservedIP`), which defeats DNS-rebinding since the check runs on the exact IP being dialed.

A second, earlier layer exists at config time: `ValidateURL` in `internal/webhook/validate.go`, which enforces http/https scheme and blocks URLs resolving to reserved IPs when a webhook is created/updated. Both layers delegate the range decision to `isReservedIP` (`internal/webhook/validate.go`), backed by the `reservedCIDRs` list (loopback, RFC-1918, link-local/IMDS `169.254.169.254`, IPv6 equivalents). Note the protection can be globally disabled via the `AllowPrivateIPs` toggle for self-hosted deployments.
