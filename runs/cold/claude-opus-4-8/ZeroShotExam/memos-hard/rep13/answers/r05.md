**Premise correction:** This repository (Memos, the self-hosted note-taking app) has **no GraphQL schema at all**. There are no `*.graphql`/`*.gql` files, and a case-insensitive search across the whole repo for `graphql`, `typeDefs`, `buildSchema`, `resolvers`, `apollo`, or `gqlgen` returns zero matches. No GraphQL libraries appear in `go.mod` or `web/package.json`. So there is no "GraphQL schema for the public API" to locate.

**Actual API surface:** The public API is **Protobuf-first**, exposed over gRPC, Connect RPC, and a RESTful JSON gateway.

- **Source of truth (schema):** `proto/api/v1/*.proto` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `shortcut_service.proto`, `instance_service.proto`, `idp_service.proto`, `ai_service.proto`, `common.proto`. Build config lives in `proto/buf.yaml`, `proto/buf.gen.yaml`, `proto/buf.lock`. (Internal storage messages, not the public API, are in `proto/store/`.)
- **Generated bindings:** `proto/gen/api/v1/` — `*.pb.go`, `*_grpc.pb.go`, gRPC-gateway REST handlers `*.pb.gw.go`, and Connect bindings under `apiv1connect/`.
- **REST/OpenAPI:** `proto/gen/openapi.yaml` (OpenAPI 3.0.3), embedded via `proto/openapi_embed.go`.
- **Server implementation/routing:** `server/router/api/v1/` (handlers plus Connect wiring in `connect_services.go`, `connect_handler.go`, `connect_interceptors.go`).
- **Frontend client:** `web/package.json` uses `@connectrpc/connect` / `@connectrpc/connect-web` — the web app talks to the backend over Connect RPC (protobuf), not GraphQL.

In short: the "schema" is the set of Protobuf service definitions in `proto/api/v1/`, not GraphQL.
