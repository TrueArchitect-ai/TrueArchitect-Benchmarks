The premise needs correcting: **there is no "database-cleanup" job in the cron scheduler.** No scheduled job in this repository cleans a database, so there's no scheduled time to report for one.

What actually exists:

- The cron scheduler is a standalone, self-contained library in `internal/scheduler/` (`scheduler.go`, `parser.go`, `job.go`, etc.). It is **not wired into the production application** — nothing outside the package imports it.
- The only jobs named "cleanup" are **illustrative examples**, and their handlers do not touch a database:
  - `internal/scheduler/example_test.go:97-106` — a job named `"cleanup"` with schedule `"0 2 * * *"` (2 AM daily). Its handler merely prints `"Cleaning up old data..."` — a placeholder in an example test.
  - `internal/scheduler/doc.go:14-20` — a doc-comment example named `"daily-cleanup"` at `"0 2 * * *"` (2 AM daily), with the comment `// Your cleanup logic here`.

So if the question was reaching for the `2 AM` (`0 2 * * *`) schedule, note that: (1) it belongs to a generically-named `"cleanup"`/`"daily-cleanup"` example, not a "database" job; and (2) it's example/documentation code that never runs in the app.

For completeness, the only genuinely active recurring schedule in the repo is the GitHub Actions stale-issue bot at `.github/workflows/stale.yml:5` (`cron: "0 */8 * * *"`, every 8 hours), which is unrelated to any database. Real "cleanup" activity in production is not scheduled: an in-memory cache eviction ticker every 5 minutes (`store/cache/cache.go:199-218`) and event-driven attachment-storage cleanup on deletion (`store/attachment.go`).
