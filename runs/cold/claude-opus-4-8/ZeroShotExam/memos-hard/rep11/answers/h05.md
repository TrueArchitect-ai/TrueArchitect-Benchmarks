**Mechanism: explicit Go code.** When a user is deleted, their emoji reactions are removed by explicit `DELETE FROM reaction` statements in the store's delete-user transaction — not by a database FK cascade and not left orphaned.

## What I checked

This is the `usememos/memos` project. User deletion is handled per-backend in `DeleteUser`, which runs all deletes in one transaction via `deleteUserTargetsTx`. That function makes two explicit calls that remove reactions:

- `deleteReactionsByContentIDsTx` — removes reactions **on the deleted user's memos** (matched by `content_id IN (...)`, where content IDs are `"memos/"+uid`).
- `deleteReactionsByCreatorTx` — removes reactions **authored by the deleted user** (`DELETE FROM reaction WHERE creator_id = ?`).

Both cases are covered, and it's done identically across all three DB drivers:

**Postgres** — `store/db/postgres/user_delete.go`:
- Orchestration: `deleteUserTargetsTx`, lines 92–99 (`deleteReactionsByContentIDsTx` then `deleteReactionsByCreatorTx`).
- `deleteReactionsByContentIDsTx` (line ~360): `DELETE FROM reaction WHERE content_id IN <clause>`.
- `deleteReactionsByCreatorTx` (line ~377): `DELETE FROM reaction WHERE creator_id = $1`.

**SQLite** — `store/db/sqlite/user_delete.go`:
- Calls at lines 96 and 102.
- `deleteReactionsByContentIDsTx` line 380–383, `deleteReactionsByCreatorTx` line 400–401.

**MySQL** — `store/db/mysql/user_delete.go`:
- Calls at lines 96 and 102.
- `deleteReactionsByContentIDsTx` line 417–420, `deleteReactionsByCreatorTx` line 437–438.

Shared scaffolding (`store/db/postgres/user_delete.go`): `memoContentIDsFromRefs` builds the `content_id` values as `"memos/"+memo.UID`, and reaction deletes run before the memos/user rows are deleted, all inside the transaction opened in `DeleteUser`.

Because the removal is driven by these explicit statements (rather than a `content_id`→memo FK cascade or a `creator_id`→user FK cascade), it does not rely on any database-level `ON DELETE CASCADE`. The `store/reaction.go` store also has no separate cleanup job invoked here — deletion happens solely through the delete-user transaction above.
