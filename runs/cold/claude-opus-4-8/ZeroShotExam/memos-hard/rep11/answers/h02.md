**Delivery function — `internal/webhook/webhook.go`:** The outbound HTTP delivery actually executes in `Post` (`internal/webhook/webhook.go:120`), specifically at the `safeClient.Do(req)` call on line 152. `Post` marshals the payload, builds the `POST` request, optionally attaches an HMAC-SHA256 signature, and sends it. It's invoked either synchronously or asynchronously via `PostAsync` (line 184), which feeds a worker pool that calls `Post` (lines 42–55).

**Protection mechanism — `internal/webhook/webhook.go` + `internal/webhook/validate.go`:** The request is protected against being pointed at internal addresses by an SSRF guard enforced at **dial time**. `Post` uses a shared `safeClient` (`webhook.go:32`) whose `Transport.DialContext` is `safeDialContext` (`webhook.go:59`). `safeDialContext` resolves the target hostname via DNS and rejects the connection if any resolved IP falls in a reserved/private range — checked by `isReservedIP` (`internal/webhook/validate.go:44`) against the `reservedCIDRs` list (loopback, RFC-1918, link-local/IMDS `169.254.169.254`, and IPv6 equivalents; `validate.go:14`). Because the check happens at dial after re-resolving the host, it also defeats DNS-rebinding/TOCTOU attacks.

There is also a secondary/earlier check, `ValidateURL` (`internal/webhook/validate.go:62`), applied when a webhook URL is registered (scheme must be http/https and the hostname must not resolve to a reserved IP), but the authoritative runtime protection is `safeDialContext`. Note both can be disabled by the `AllowPrivateIPs` flag (`validate.go:41`) for local-network deployments.
