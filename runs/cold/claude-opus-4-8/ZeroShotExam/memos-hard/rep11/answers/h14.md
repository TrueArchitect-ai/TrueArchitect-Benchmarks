**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual extraction to the Goldmark markdown service — `(*service).ExtractAll` in `internal/markdown/markdown.go:356` (a single AST walk). `RebuildMemoPayload` writes the results into `memo.Payload.Property` (and `.Tags`) at `runner.go:85-86`. The stored shape is `storepb.MemoPayload_Property`.

**Triggers (what causes recomputation):**
- **Create memo:** `server/router/api/v1/memo_service.go:108` calls `RebuildMemoPayload` when a memo is created.
- **Update memo — content change only:** `server/router/api/v1/memo_service.go:447`, inside the `path == "content"` branch of the update mask (`memo_service.go:436-451`). Editing visibility, pinned state, etc. does not recompute it — only a content update does.
- **Batch rebuild:** `Runner.RunOnce` (`runner.go:27`) re-derives the payload for *all* memos in batches of 100, run as a maintenance/migration pass over existing memos.

**Extracted properties** (`internal/markdown/markdown.go:383-408`, into `MemoPayload_Property`):
- `Title` — text of the document's first block-level child if it is an H1 heading (`markdown.go:384-388`).
- `HasLink` — true if any link node is present (`KindLink`).
- `HasCode` — true if any code block, fenced code block, or inline code span is present.
- `HasTaskList` — true if any task checkbox is present.
- `HasIncompleteTasks` — true if any task checkbox is unchecked.

(Tags are extracted in the same pass but are collected content references, not the derived `Property` metadata.) These `property.*` fields are also what the filter layer queries for list views (`internal/filter/schema.go:191-224`).
