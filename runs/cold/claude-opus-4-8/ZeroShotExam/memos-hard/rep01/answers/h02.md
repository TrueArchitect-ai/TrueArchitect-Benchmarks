**Delivery function** — `Post` in `internal/webhook/webhook.go` (the outbound request fires at `webhook.go:152` via `resp, err := safeClient.Do(req)`). All deliveries funnel through this: `PostAsync`/the async worker goroutines (`webhook.go:42-55`) also call `Post`.

**Protection mechanism** — `safeDialContext`, the `DialContext` hook on the shared `safeClient`'s transport, in `internal/webhook/webhook.go:59-77`. It resolves the target host and rejects the connection if any resolved IP is reserved/private (via `isReservedIP` in `internal/webhook/validate.go:44-54`, backed by the `reservedCIDRs` table at `validate.go:14-23` covering loopback, RFC-1918, link-local/IMDS, and IPv6 equivalents).

Details worth noting:
- The check runs **at dial time on the resolved IPs**, so it also defeats DNS-rebinding (TOCTOU) attacks — the exact address being connected to is validated, not just a pre-checked string.
- There is a second, up-front layer: `ValidateURL` (`validate.go:62-83`) applies the same `isReservedIP` test when a webhook URL is registered, returning a gRPC `InvalidArgument` error. But the dial-time hook in the transport is the load-bearing guarantee.
- An escape hatch exists: the package-level `AllowPrivateIPs` bool (`validate.go:38-47`) short-circuits `isReservedIP` to disable protection for self-hosted LAN deployments; it defaults to `false` (protection on).
