**Premise correction:** There is no Redis in this repository. The question presumes a Redis-backed cache layer, but there are zero references to Redis anywhere — no Redis client dependency in `go.mod`, no connection string, no config. The cache is a custom **in-process, in-memory** implementation, so there is no "Redis connection" to configure.

**Actual mechanism:**

- **Cache implementation:** `store/cache/cache.go` — a thread-safe in-memory cache backed by Go's `sync.Map` (`Cache` struct at `store/cache/cache.go:66-73`), with a background `cleanupLoop` goroutine for TTL-based eviction.

- **Where it's "configured" (the equivalent of connection setup):** `store/store.go:40-53`. A single `cache.Config` is defined inline and passed to three separate in-memory caches:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  // ...
  instanceSettingCache: cache.New(cacheConfig),
  userCache:            cache.New(cacheConfig),
  userSettingCache:     cache.New(cacheConfig),
  ```

- **TTL for user entries:** **10 minutes.** User records are written via `s.userCache.Set(...)` (e.g. `store/user.go:167`), which delegates to `SetWithTTL` using `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). That default is `DefaultTTL: 10 * time.Minute` at `store/store.go:41`. No user-specific TTL override exists anywhere, so user and user-setting entries uniformly expire after 10 minutes. Eviction is by soonest-expiration plus a 1000-item cap — not strict LRU.

(For completeness, other unrelated caches exist — browser-side React Query in `web/src/lib/query-client.ts` and an in-memory RSS feed cache in `server/router/rss/rss.go` — but none use Redis and none is the user-record cache layer.)
