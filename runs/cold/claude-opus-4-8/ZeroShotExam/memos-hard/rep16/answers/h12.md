**Determination method:**

There are three candidate `CreateMemo` implementations that all issue the SQL INSERT — one per driver:
- `store/db/sqlite/memo.go:16`
- `store/db/mysql/memo.go` (`func (d *DB) CreateMemo`)
- `store/db/postgres/memo.go` (`func (d *DB) CreateMemo`)

They are dispatched through an interface, not called directly. The path is:

1. `Store.CreateMemo` (`store/memo.go:109-113`) validates the UID and delegates to `s.driver.CreateMemo(...)` — `s.driver` is the `store.Driver` interface, so the concrete implementation depends on which driver was constructed.
2. The driver is selected by `db.NewDBDriver` (`store/db/db.go`) via a `switch profile.Driver` over `"sqlite"` / `"mysql"` / `"postgres"`.
3. `profile.Driver` comes from `viper.GetString("driver")` in `cmd/memos/main.go:43`. Its default is set to `"sqlite"` in two places — `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the flag default `rootCmd.PersistentFlags().String("driver", "sqlite", ...)` (`cmd/memos/main.go:130`).

So with **no database flags**, `profile.Driver == "sqlite"`, the switch constructs `sqlite.NewDB`, and `s.driver.CreateMemo` binds to `(*sqlite.DB).CreateMemo`. That is the concrete code running the INSERT; the MySQL and Postgres versions are dead paths under a default install.
