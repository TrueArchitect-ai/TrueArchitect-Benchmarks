**Premise correction:** The webhook delivery workers consume from *neither* NATS nor RabbitMQ. This repository (memos) uses no external message broker at all for webhook delivery — there is no NATS, RabbitMQ, AMQP, Kafka, or Redis in the webhook path (a grep for `nats|rabbitmq|amqp` across the Go sources returns nothing outside generated proto noise).

**Actual mechanism:** Webhook delivery is handled entirely in-process using a buffered Go channel and a small pool of goroutine workers.

- The "queue" is a package-level buffered channel declared at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- The delivery workers are 4 goroutines spun up in `init()` at `internal/webhook/webhook.go:42-55`, each ranging over that channel and calling `Post(payload)` (the actual HTTP dispatch) for every item.
- Producers enqueue via `PostAsync` at `internal/webhook/webhook.go:184-196`, which does a non-blocking `select` send into `asyncPostQueue` and drops the payload (with a warning) if the buffer of 128 is full.

So it's an in-memory, bounded channel-backed worker pool local to the server process — not a message-broker consumer. The queue is declared as the `asyncPostQueue` channel at `internal/webhook/webhook.go:39`, and the consuming workers are started in the `init()` function just below it.
