**Which RPC handlers can transitively cause an outbound HTTP request to a user-configured URL**

Memos lets each user configure webhook URLs (`Store.GetUserWebhooks`), and several gRPC (RPC) handlers in `server/router/api/v1` fire webhooks to those URLs on memo-related activity. The handlers are:

1. **`CreateMemo`** — `server/router/api/v1/memo_service.go:157` → `DispatchMemoCreatedWebhook`
2. **`UpdateMemo`** — `server/router/api/v1/memo_service.go:513` → `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` (`memo_update_helpers.go:67`)
3. **`DeleteMemo`** — `server/router/api/v1/memo_service.go:562` → `DispatchMemoDeletedWebhook`
4. **`CreateMemoComment`** — `server/router/api/v1/memo_service_comments.go:119` → `DispatchMemoCommentCreatedWebhook`
5. **`SetMemoAttachments`** — `server/router/api/v1/memo_attachment_service.go:48` → `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`
6. **`SetMemoRelations`** — `server/router/api/v1/memo_relation_service.go:48` → `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`

**Convergence function.** All four `DispatchMemo*Webhook` wrappers funnel into a single function that resolves the creator's configured webhook URLs and hands each off for delivery:

- **`(*APIV1Service).dispatchMemoRelatedWebhook`** — `server/router/api/v1/memo_service_webhooks.go:48`. It calls `GetUserWebhooks`, sets `payload.URL = hook.Url`, and enqueues via `webhook.PostAsync`.

The actual outbound HTTP send then occurs in **`webhook.Post`** — `internal/webhook/webhook.go:120` (the `safeClient.Do(req)` call), which `PostAsync` drains its queue into. So the paths converge at `dispatchMemoRelatedWebhook` in the handler layer, and delivery itself is performed by `webhook.Post`.

(Note: outbound HTTP to user URLs also exists in `internal/httpgetter` for link-preview fetching and in `internal/idp/oauth2` for OAuth, but those are not reached from the memo RPC handlers above; the webhook path is the one where multiple RPC handlers converge on one delivery function.)
