The question's premise is mistaken: there is **no nightly database-cleanup job** scheduled in the cron scheduler in this repository.

The repo does contain a complete, self-contained cron scheduler package at `internal/scheduler/` (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`, `doc.go`), but it is **dead code — imported by nothing** outside its own tests. It is never instantiated by the application (`cmd/memos/main.go` → `server/server.go`).

What likely inspired the question is a **documentation example**, not a real job. In `internal/scheduler/doc.go:14-21` (and echoed in `internal/scheduler/job.go:20-21`), there's an illustrative snippet:

```go
//	s.Register(&scheduler.Job{
//		Name:     "daily-cleanup",
//		Schedule: "0 2 * * *", // 2 AM daily
```

This `"daily-cleanup"` at 2 AM is only a sample in the package docs — no such job is implemented or registered anywhere.

The only real recurring background work in the running app is:
- **S3 URL re-presigning**, every 12 hours (`server/runner/s3presign/runner.go:27`) — not a DB cleanup.
- An **in-memory cache eviction loop**, every 5 minutes (`store/cache/cache.go:199-217`) — memory only, not the database.
- A CI stale-bot cron, every 8 hours (`.github/workflows/stale.yml:4-5`) — unrelated to the database.

So there is no scheduled time to report, because the job does not exist.
