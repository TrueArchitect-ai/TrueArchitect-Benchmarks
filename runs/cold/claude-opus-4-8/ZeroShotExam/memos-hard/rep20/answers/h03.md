h03. `internal/idp`; `internal/idp/oauth2`

- **Abstraction package:** `internal/idp` (`internal/idp/idp.go`) defines the provider abstraction — the shared `IdentityProviderUserInfo` contract every concrete provider returns. The provider-type enum lives at the proto/store layer (`proto/gen/store/idp.pb.go`, `store/idp.go`).
- **Concrete implementation package:** `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`), whose package doc reads "Package oauth2 implements the OAuth2 identity provider integration" — providing the OAuth2 `IdentityProvider` (`ExchangeToken`/`UserInfo`) that maps claims into `idp.IdentityProviderUserInfo`. It is the only concrete protocol implementation (no SAML/OIDC/LDAP packages exist; OIDC-style flows are handled generically via the configurable OAuth2 endpoints).

Wiring: `server/router/api/v1/auth_service_sso.go` instantiates it via `oauth2.NewIdentityProvider(...)` when the provider type is `storepb.IdentityProvider_OAUTH2`.
