A browser requests another user's profile image via `GET /file/users/:identifier/avatar`. The avatar bytes are stored as a base64 data URI in the `user.avatar_url` column, so the path to stored data runs through the user store, not the attachment store.

Route registration:
- `RegisterRoutes` — server/router/fileserver/fileserver.go:124 (`fileGroup.GET("/file/users/:identifier/avatar", s.serveUserAvatar)`)

Hops from serving handler to data layer:
- `FileServerService.serveUserAvatar` — server/router/fileserver/fileserver.go:168 (serving handler; reads `user.AvatarURL`, decodes via `parseDataURI`, returns `c.Blob`)
- `FileServerService.getUserByUsername` — server/router/fileserver/fileserver.go:715
- `Store.GetUser` — store/user.go:148
- `Store.ListUsers` — store/user.go:136
- `DB.ListUsers` — store/db/sqlite/user.go:88 (`SELECT ... avatar_url ... FROM user WHERE username = ?` — reads the stored avatar data)

Note: the SQLite driver is shown; equivalent implementations exist at `store/db/mysql/user.go` and `store/db/postgres/user.go`, dispatched through the `store.Driver.ListUsers` interface.
