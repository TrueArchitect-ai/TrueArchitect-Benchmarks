**Premise correction:** There is no GraphQL schema anywhere in this repository. A repo-wide search for "graphql" returns zero matches, and the project (this is `usememos/memos`, a Go codebase) does not expose a GraphQL API at all. The `README.md` states the project offers "full REST and gRPC APIs" (`README.md:22`) — no GraphQL.

**Actual API surface:** The public API is defined with **Protocol Buffers (gRPC)**, not GraphQL. The schema lives in:

- `proto/api/v1/*.proto` — the public v1 service definitions, one file per service:
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/common.proto`
- `proto/store/*.proto` — internal storage/persistence message definitions (not the public surface).
- `proto/buf.yaml` / `proto/buf.gen.yaml` — the buf build/codegen config; run via `buf generate` (`proto/README.md`).
- `proto/gen/openapi.yaml` — a generated **OpenAPI** spec, which provides the REST view of the same services (embedded via `proto/openapi_embed.go`).

So the API is authored as gRPC/protobuf under `proto/api/v1/`, and REST access is offered through the generated OpenAPI/gRPC-gateway layer — there is no GraphQL schema to point to.
