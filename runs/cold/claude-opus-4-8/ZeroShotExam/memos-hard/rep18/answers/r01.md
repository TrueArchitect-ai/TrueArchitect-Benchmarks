**Premise correction:** There is no Redis in this repository. The cache layer for `usememos/memos` uses no external cache server at all — a `grep` for `redis` across the Go source returns nothing (the only `redis` hits are unrelated transitive entries in `go.sum`/`web/pnpm-lock.yaml`), and `go.mod` declares no Redis/memcached dependency. So there is no "Redis connection" to configure.

**Actual mechanism:** Caching is a hand-rolled, thread-safe, in-process in-memory cache.

- Implementation: `store/cache/cache.go` — a `Cache` struct backed by `sync.Map` with an `atomic.Int64` item counter, per-item `expiration time.Time`, lazy eviction on read, a background `cleanupLoop`, and bulk `cleanupOldest` eviction when `MaxItems` is exceeded (TTL-based, not strictly LRU).
- Configuration (code-level, no connection string): `store/store.go:40-45` sets one `cache.Config` shared by all three caches (`instanceSettingCache`, `userCache`, `userSettingCache`), instantiated via `cache.New(...)` at `store/store.go:51-53`:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```

**TTL for user entries:** 10 minutes. The user cache in `store/user.go` writes exclusively via `s.userCache.Set(...)` (e.g. lines 98, 122, 132, 143, 167), and `Set` delegates to `SetWithTTL(..., c.config.DefaultTTL)` (`store/cache/cache.go`). There is no user-specific TTL override anywhere (no `SetWithTTL` callers exist outside the cache implementation itself), so user entries expire after the shared 10-minute `DefaultTTL`.
