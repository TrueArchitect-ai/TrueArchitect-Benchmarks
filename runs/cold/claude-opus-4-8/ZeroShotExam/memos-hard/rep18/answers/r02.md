The question's premise is mistaken: **there is no per-user API rate-limiting middleware in this repository**, so there is no registration site or set of request limits to report.

I searched the codebase exhaustively for `rate limit`, `rateLimit`, `throttle`, `limiter`, `429`, `too many requests`, and `quota`. No rate-limiting library is imported (no `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, etc., in `go.mod`), and none of the registered middleware does request-rate counting.

**What is actually registered** (and does *not* rate-limit):

- The Connect/gRPC interceptor chain — `server/router/api/v1/v1.go:133-138` — is just `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` (defined in `server/router/api/v1/connect_interceptors.go`): metadata, logging, panic recovery, and auth only.
- The Echo HTTP middleware stack — `server/server.go:51-52` — is only `middleware.Recover()` and `newCORSMiddleware(profile)` (plus SPA/static handling in `server/router/frontend/frontend.go`). Echo's built-in `RateLimiter` is available but is not used.

**What exists instead** — these are concurrency and size caps, not per-user request-rate limits:

- **Global image-processing concurrency semaphores** (process-wide, shared across all users), `server/router/api/v1/v1.go:39-41,59-60`: `thumbnailSemaphore = semaphore.NewWeighted(3)` and `imageProcessingSemaphore = semaphore.NewWeighted(2)`. When exhausted, `attachment_service.go:158-160` returns `codes.ResourceExhausted, "too many image processing requests"` — the only "too many requests"-style error in the code, but it's a global concurrency guard, not throttling.
- **Request/upload size caps**: `maxAPIRequestBytes = 256 << 20` (256 MiB) at `server/router/api/v1/v1.go:20`, and `MaxUploadBufferSizeBytes = 32 << 20` (32 MiB default, configurable via the `UploadSizeLimitMb` setting) at `server/router/api/v1/attachment_service.go:27,120-125`.

There is also no login-attempt throttling in `server/auth/`. Genuine per-user request-rate limiting would need to be added, either as a new interceptor/middleware or at a reverse proxy.
