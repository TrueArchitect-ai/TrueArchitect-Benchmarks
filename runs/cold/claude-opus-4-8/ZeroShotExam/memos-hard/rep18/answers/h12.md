**How I determined it's this candidate (and not the MySQL or PostgreSQL versions):**

The store layer only dispatches to the active driver — `Store.CreateMemo` at `store/memo.go:109-113` just calls `s.driver.CreateMemo(ctx, create)`. So the question is which `store.Driver` implementation is wired in.

1. Driver selection: `store/db/db.go` (`NewDBDriver`) switches on `profile.Driver`, mapping `"sqlite"` → `sqlite.NewDB`, `"mysql"` → `mysql.NewDB`, `"postgres"` → `postgres.NewDB` (lines 19-24). There are three concrete `CreateMemo` implementations (one per subpackage under `store/db/`), which is the multiple-candidates situation.

2. Default with no flags: in `cmd/memos/main.go`, the driver defaults to `"sqlite"` in two places — `viper.SetDefault("driver", "sqlite")` (line 122) and the flag definition `rootCmd.PersistentFlags().String("driver", "sqlite", …)` (line 130). The profile reads it via `viper.GetString("driver")` (line 43). Confirmed further by `internal/profile/profile.go:110`, which special-cases `Driver == "sqlite"` with an empty DSN to fall back to a local sqlite file — so a default install with no DB flags runs SQLite.

Therefore the `switch` lands on the `"sqlite"` case, `sqlite.NewDB` is the driver installed into the store, and its `CreateMemo` (the code above) is what actually executes the INSERT. The MySQL/PostgreSQL `CreateMemo` methods exist but are unreachable without an explicit `--driver` flag.
