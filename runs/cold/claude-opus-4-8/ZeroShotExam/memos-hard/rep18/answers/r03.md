The question's premise is incorrect: there is **no nightly database-cleanup job** scheduled in this repository's cron scheduler, so it has no scheduled run time.

What actually exists:

- The repo has a home-grown cron library at `internal/scheduler/`, but it is **not imported by any application code** — only by its own tests. It schedules nothing in production.
- The "cleanup" jobs that mention a time are **example/documentation code**, not real jobs:
  - `internal/scheduler/example_test.go:98-106` — an example job named `"cleanup"` with schedule `"0 2 * * *"` (2:00 AM daily) that merely prints `"Cleaning up old data..."`.
  - `internal/scheduler/README.md:33-40` — a `daily-cleanup` example at `0 2 * * *` (2 AM).
  - `internal/scheduler/README.md:240-246` — a `stale-session-cleanup` example at `0 3 * * *`.
  - `internal/scheduler/doc.go:16` — a comment example `0 2 * * *`.

  None of these run, and none is a *database* cleanup — the example handlers do no DB work.

The only things that actually run on a schedule use Go `time.Ticker` intervals, not cron, and none is a nightly DB cleanup:
- `store/cache/cache.go:201` — evicts expired **in-memory cache** entries every 5 minutes (the only thing literally named "cleanup").
- `server/runner/s3presign/runner.go:27` — re-presigns S3 URLs every 12 hours (a refresh, not a purge).
- `server/router/api/v1/sse_handler.go:17` — SSE heartbeat every 30 seconds.

So if you saw "2:00 AM" for a cleanup job, that came from example code in the unused `internal/scheduler` package (`0 2 * * *`), not from an actual scheduled database-cleanup job.
