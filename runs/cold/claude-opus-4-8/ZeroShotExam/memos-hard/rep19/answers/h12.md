**How I determined which of the three candidates runs:**

There are three concrete `CreateMemo` implementations — sqlite, mysql, and postgres (`store/db/{sqlite,mysql,postgres}/memo.go`). Selection is by database driver, resolved at startup:

1. **Default driver is `sqlite`.** In `cmd/memos/main.go:122` (`viper.SetDefault("driver", "sqlite")`) and the flag default at `main.go:130` (`rootCmd.PersistentFlags().String("driver", "sqlite", ...)`), so with no database flags the profile's `Driver` field is `"sqlite"`.

2. **The driver string selects the concrete implementation.** `db.NewDBDriver` (`store/db/db.go:14-32`) switches on `profile.Driver`; the `"sqlite"` case calls `sqlite.NewDB(profile)`, returning a `*sqlite.DB` as the `store.Driver` interface. `main.go:57-64` wires this into the store via `store.New(dbDriver, ...)`.

3. **The save path dispatches through that interface.** `store.Store` holds the driver as an interface field (`store/store.go:15` `driver Driver`, assigned at `store.go:48`). The public `(*Store).CreateMemo` (`store/memo.go:109-114`) validates the UID then delegates to `s.driver.CreateMemo(ctx, create)` — a virtual call resolving to the sqlite implementation because that is the concrete type stored. The mysql/postgres versions are only reachable when `--driver` is set to those values.

So the interface dispatch plus the `"sqlite"` default is how I confirmed the sqlite method — not the mysql/postgres ones — is what actually executes the INSERT in a default installation.
