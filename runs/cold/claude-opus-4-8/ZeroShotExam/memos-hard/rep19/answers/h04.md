**No.** The MySQL driver is only ever constructed inside the driver-selection factory.

Evidence:

- The MySQL driver package is `store/db/mysql`, whose constructor is `func NewDB(profile *profile.Profile) (store.Driver, error)` at `store/db/mysql/mysql.go:20` (returning a `*DB`, defined at `store/db/mysql/mysql.go:14`).

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14`, a `switch` on the DB driver string. The MySQL branch constructs it at `store/db/db.go:21-22`:
  ```go
  case "mysql":
      driver, err = mysql.NewDB(profile)
  ```

- Searching the entire codebase, `mysql.NewDB(` appears exactly once — that factory line at `store/db/db.go:22`. There are no other calls.

- The memos MySQL package (`github.com/usememos/memos/store/db/mysql`) is imported by exactly one file, `store/db/db.go:8`. Since no other file imports the package, nothing else can construct its `DB` type (directly or via `NewDB`).

Note on look-alikes that are *not* the memos MySQL driver: `store/db/mysql/mysql.go` uses `mysql.Config` / `mysql.ParseDSN` (lines 17, 30, 73) — these reference the external `go-sql-driver/mysql` package, not the memos driver. And `store/test/containers.go:101-105` uses `mysql.Run` / `mysql.WithDatabase` etc. — the testcontainers `mysql` module, again not the memos driver. Test setup obtains a MySQL driver through the factory (`db.NewDBDriver`), e.g. `store/test/store.go:28,50`, not by constructing `mysql.NewDB` directly.
