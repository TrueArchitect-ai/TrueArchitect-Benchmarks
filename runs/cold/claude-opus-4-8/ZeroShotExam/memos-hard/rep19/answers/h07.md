A browser requests another user's avatar at `GET /file/users/:identifier/avatar`. The avatar image is stored as a base64 data-URI in the user row's `avatar_url` column; the handler loads that user row through the store and decodes the data-URI into the response body.

Hops from serving handler to the data layer:

`serveUserAvatar` — server/router/fileserver/fileserver.go:168 (route registered at server/router/fileserver/fileserver.go:124)
`(*FileServerService).getUserByUsername` — server/router/fileserver/fileserver.go:715
`(*Store).GetUser` — store/user.go:148
`(*Store).ListUsers` — store/user.go:136
`(*DB).ListUsers` — store/db/sqlite/user.go:88 (selects `avatar_url` at store/db/sqlite/user.go:159)

The returned `user.AvatarURL` is then decoded back in the handler by `(*FileServerService).parseDataURI` (server/router/fileserver/fileserver.go:737) and written to the response via `c.Blob` (server/router/fileserver/fileserver.go:209).

Note: the SQLite driver is shown above; the same `ListUsers` interface method is implemented per backend in `store/db/mysql/user.go` and `store/db/postgres/user.go`, selected at runtime via `s.driver`.
