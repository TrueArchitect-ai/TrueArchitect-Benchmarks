**Premise correction:** There is no Redis in this repository, and no external cache store of any kind. This is the `usememos/memos` project (Go backend), and its cache layer is a hand-rolled **in-memory** cache backed by a Go `sync.Map` — not Redis. There is no Redis connection to configure: no `redis`/`ioredis`/`node-redis` dependency (`go.mod`, `web/package.json`), no connection string, and no docker-compose/env wiring for one. (The only `createClient` calls in the tree are ConnectRPC clients in `web/src/connect.ts`, unrelated to caching.)

**Actual mechanism:**

- **Cache implementation:** `store/cache/cache.go` — a thread-safe in-process `Cache` struct over `sync.Map`, with per-item expiration timestamps, lazy eviction on `Get`, and a background `cleanupLoop` goroutine.
- **Where it's configured:** `store/store.go:41-43` builds the cache config with `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, and creates three caches — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:27-29`, `:51-53`).
- **TTL for user entries:** **10 minutes.** The user cache is populated only via `s.userCache.Set(...)` in `store/user.go` (lines 98, 122, 132, 143, 167). `Set` delegates to `SetWithTTL(..., c.config.DefaultTTL)` (`store/cache/cache.go:93-95`), so there is **no user-specific TTL** — user entries inherit the store-wide default of 10 minutes. Entries are invalidated explicitly on user delete via `deleteUserCache` → `userCache.Delete` (`store/user_delete.go:40`).
