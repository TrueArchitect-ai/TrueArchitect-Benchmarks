Based on my analysis of the repository (the `usememos/memos` Go codebase), the data layer is the `store` package (`store/*.go`), where persistent entity types like `Memo`, `User`, `Attachment`, etc. are defined.

I counted, for each persistent entity type, the number of **distinct packages outside the store layer** (excluding `store/`, its DB drivers in `store/db/*`, and `store/test`) that reference `store.<Type>`:

| Type | Outside packages |
|------|-----|
| User | 7 |
| Memo | 6 |
| Attachment | 4 |
| Inbox / MemoRelation / MemoShare | 3 |

**h11.**

1st: **User** (~7 packages); 2nd: **Memo** (~6 packages)

- `store.User` (defined in `store/user.go`) is referenced from 7 non-store packages: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`.
- `store.Memo` (defined in `store/memo.go`) is referenced from 6 non-store packages: `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`.

(The counts are close — `User` edges out `Memo` mainly via `server/auth` and `server/router/fileserver`. If the store's own DB-driver subpackages were counted as "outside," both would rise by ~4 but the ranking would be unchanged: User 11, Memo 10.)
