Memo visibility is enforced across many distinct server surfaces. The grep confirms each of the sites below. The core view-gating sites:

GetMemo read-access gate (`checkMemoReadAccess`, shared by GetMemo) — server/router/api/v1/memo_service.go:63
ListMemos query-level visibility filter — server/router/api/v1/memo_service.go:219,225
Memo comments (Create/ListMemoComments) — server/router/api/v1/memo_service_comments.go:41
Memo reactions (List/Upsert) — server/router/api/v1/reaction_service.go:38,83
ListMemoAttachments — server/router/api/v1/memo_attachment_service.go:222
Attachment binary access via gRPC (`checkAttachmentAccess`) — server/router/api/v1/attachment_service.go:451
Raw file server HTTP endpoint (`checkAttachmentPermission`) — server/router/fileserver/fileserver.go:699
RSS feeds (explore + user, restricted to Public) — server/router/rss/rss.go:90,141
SSE streaming delivery filter (`canReceive`) — server/router/api/v1/sse_hub.go:135
User stats endpoints (ListAllUserStats/GetUserStats) — server/router/api/v1/user_service_stats.go:84,90,218,220
Sitemap generation (Public only) — server/router/frontend/frontend.go:150

Visibility-driven content redaction (related, not strictly view-gating): mention-notification suppression (server/router/api/v1/memo_mention_helpers.go:62,67), email/notification content redaction (server/notification/email.go:313, server/router/api/v1/user_service_notifications.go:309).

The primary/central enforcement is the `checkMemoReadAccess` helper (memo_service.go:63) used by GetMemo and comment listing, plus the store-query `VisibilityList` filter in ListMemos (memo_service.go:219). The remaining surfaces each re-implement the `Visibility == Private && CreatorID != user.ID` check independently.
