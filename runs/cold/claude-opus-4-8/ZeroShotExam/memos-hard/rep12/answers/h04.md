h04.

**Yes** — the MySQL driver struct is constructed directly outside the driver-selection factory, in a test.

Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14-32`. For the `"mysql"` case it calls `mysql.NewDB(profile)` (`store/db/db.go:22`), which is the intended constructor. That factory is the **only** caller of `mysql.NewDB` in the codebase (`grep` for `mysql.NewDB` returns just `store/db/db.go:22`).

- However, the MySQL driver type `DB` (defined at `store/db/mysql/mysql.go:13-17`) is also instantiated directly via a struct literal — bypassing `NewDB`/the factory — in `store/db/mysql/auth_config_test.go:12`:
  ```go
  db := &DB{}
  ```
  This constructs a `mysql.DB` directly (in-package, so the unexported struct is accessible) to unit-test its methods, without going through `NewDBDriver` or `mysql.NewDB`.

- The other `DB{...}` literal, `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`), is *inside* `NewDB` itself, so it is part of the factory path, not a separate direct construction.

So: the constructor function `mysql.NewDB` is only ever invoked from the factory, but the driver struct itself is directly built once in the test file `store/db/mysql/auth_config_test.go:12`.
