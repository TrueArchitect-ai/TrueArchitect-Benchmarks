**Delivery function — `internal/webhook/webhook.go`:** The outbound HTTP delivery actually executes in the `Post` function (`internal/webhook/webhook.go:120`), specifically at the `safeClient.Do(req)` call on line 152. `Post` marshals the payload, builds the `POST` request (optionally adding HMAC-SHA256 signature headers), and sends it. It's driven asynchronously via `PostAsync` → an `asyncPostQueue` consumed by worker goroutines started in `init()`.

**Protection mechanism — two layers:**

1. **Dial-time IP guard (primary defense) — `internal/webhook/webhook.go`:** The request is sent through a shared `safeClient` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:59`). Before connecting, it resolves the target hostname and rejects any address in a reserved/private range via `isReservedIP`. Because the check happens at dial time on the actually-resolved IPs, it also defeats DNS-rebinding attacks.

2. **URL validation + reserved-range definitions — `internal/webhook/validate.go`:** `ValidateURL` (`internal/webhook/validate.go:62`) is called when a webhook is configured, checking the scheme (http/https) and that the hostname doesn't resolve to a reserved IP. Both layers rely on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against `reservedCIDRs` (loopback, RFC-1918 private ranges, link-local incl. `169.254.169.254` cloud IMDS, and IPv6 equivalents). Note the guard can be disabled by the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for local-network deployments.

So: delivery function — `Post` (`safeClient.Do`) in `internal/webhook/webhook.go`; protection mechanism — `safeDialContext`/`isReservedIP` reserved-IP blocking (with `ValidateURL` at config time) in `internal/webhook/webhook.go` and `internal/webhook/validate.go`.
