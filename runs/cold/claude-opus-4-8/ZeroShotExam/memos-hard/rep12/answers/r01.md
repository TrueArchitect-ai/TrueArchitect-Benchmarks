**Premise correction:** There is no Redis in this repository. There is no Redis, ioredis, Memcached, or any external cache dependency anywhere — neither in the Go backend (`go.mod`) nor the frontend (`web/package.json`). The `createClient` calls in `web/src/connect.ts` are Connect RPC clients, not a Redis client. So there is no "Redis connection for the cache layer" to configure.

**Actual mechanism:** Server-side caching is a homegrown, thread-safe **in-memory** cache with TTL, implemented in `store/cache/cache.go` (a `sync.Map`-backed store with a background cleanup goroutine and max-item eviction — see the type comment at `store/cache/cache.go:66`).

The store creates three instances in `store/store.go:27-29`, including a dedicated `userCache` "cache for users". Its config is built explicitly in `store/store.go:40-46`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

**TTL for user entries:** There is no user-specific TTL. User entries get the shared default of **10 minutes**. Writes to the user cache in `store/user.go` (e.g. `store/user.go:98`) all call `.Set(...)`, which delegates to `DefaultTTL` via `store/cache/cache.go:93-95`. The per-entry `SetWithTTL` is never used in production code (only in `store/cache/cache_test.go`), so users inherit the flat 10-minute default — the same TTL applied to user settings and instance settings.

Sources: `store/cache/cache.go`, `store/store.go:27-53`, `store/user.go:88-167`, `go.mod`, `web/package.json`, `web/src/connect.ts`.
