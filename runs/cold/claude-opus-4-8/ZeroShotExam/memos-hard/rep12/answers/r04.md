**Premise correction:** The webhook delivery workers consume from **neither NATS nor RabbitMQ.** The question assumes an external message broker is involved; there isn't one. Memos has no NATS or AMQP/RabbitMQ dependency for webhook delivery.

**Actual mechanism:** Webhook dispatch is handled entirely in-process by a buffered Go channel and a fixed pool of goroutines — no external broker.

- The "queue" is a plain buffered channel, declared in `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- The worker pool is started in the package `init()` at `internal/webhook/webhook.go:42-55`, spawning 4 goroutines that range over `asyncPostQueue` and call `Post()` for each payload.
- Enqueue happens in `PostAsync` at `internal/webhook/webhook.go:184-196`, which does a non-blocking `select` send onto the channel (dropping the payload with a warning if the buffer of 128 is full).
- Actual delivery (`internal/webhook/webhook.go:120-180`, `Post`) is a direct HTTP POST via a shared SSRF-guarded `http.Client`.

So the "workers" are in-memory goroutines draining a bounded Go channel — there is no message-broker-declared queue at all.
