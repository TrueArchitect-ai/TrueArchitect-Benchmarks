**Delivery function — `internal/webhook/webhook.go`**
The outbound HTTP request executes in `Post(requestPayload *WebhookRequestPayload)`. The request is built with `http.NewRequest("POST", ...)` and fired via `safeClient.Do(req)` (around line 152). Delivery is invoked directly or asynchronously through `PostAsync`, whose buffered queue is drained by four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each calling `Post`.

**Protection mechanism — `internal/webhook/webhook.go` (dial-time) + `internal/webhook/validate.go` (predicate + up-front check)**
The `safeClient` is a shared `http.Client` whose `http.Transport` uses a custom `DialContext: safeDialContext` (`webhook.go:32-37`). `safeDialContext` (`webhook.go:59-77`) resolves the target host at dial time via `net.DefaultResolver.LookupHost` and rejects the connection if any resolved IP is reserved/private — doing the check on the actually-resolved IP also defeats DNS-rebinding. The blocking predicate is `isReservedIP` (`internal/webhook/validate.go:44-54`), which tests the IP against `reservedNetworks`, the parsed `reservedCIDRs` list covering loopback, RFC-1918 ranges, `169.254.0.0/16` (link-local / cloud IMDS), and IPv6 equivalents (`validate.go:14-23`). The same predicate backs an up-front `ValidateURL` check at registration time (`validate.go:62-83`). An `AllowPrivateIPs` flag (`validate.go:41`) can disable the protection for self-hosted deployments.

So the core answer: **delivery function — `Post` in `internal/webhook/webhook.go`; protection mechanism — `safeDialContext`/`safeClient` reserved-IP dial-time block (backed by `isReservedIP`) in `internal/webhook/webhook.go` and `internal/webhook/validate.go`.**
