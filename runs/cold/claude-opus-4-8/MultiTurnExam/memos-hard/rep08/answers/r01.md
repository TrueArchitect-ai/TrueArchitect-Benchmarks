**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` returns zero matches — the cache layer is **not** backed by Redis (or any external cache server). There is no Redis connection to configure.

**Actual mechanism:** The cache is an in-process, in-memory implementation defined in `store/cache/cache.go` (a `*cache.Cache` with a `map`-based store, background cleanup goroutine, and per-item expiration; see the `Interface`/`Config` at `store/cache/cache.go:10-53`). The `Store` holds three of these caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — all constructed in `store.New` with the same config at `store/store.go:38-53`.

**TTL for user entries:** User entries live in `userCache`, created with the default config `DefaultTTL: 10 * time.Minute` (`store/store.go:41`; the package default is likewise 10 minutes at `store/cache/cache.go` `DefaultConfig`). Entries are written via `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,167`), which uses that default TTL, and expired items are swept by the cache's cleanup loop (`CleanupInterval: 5 * time.Minute`). So user cache entries expire **10 minutes** after they're set (or sooner, on explicit invalidation via `deleteUserCache`).
