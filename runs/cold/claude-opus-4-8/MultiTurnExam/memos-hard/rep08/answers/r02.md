**Premise correction:** There is no per-user API rate-limiting middleware in this codebase, so there is nothing to register and no request limits to report.

Evidence:
- A repo-wide search for rate-limiting terms (`rate limit`, `ratelimit`, `throttle`, `golang.org/x/time/rate`, `Limiter`, `tollbooth`, "requests per") returns no matches in the server code or dependencies.
- The full set of registered middleware/interceptors is: `middleware.Recover()` and the CORS middleware (`server/server.go:51-52`, `server/cors.go`), static-file + SPA-fallback middleware for the frontend (`server/router/frontend/frontend.go:54-59`), and the shared auth/authorization interceptor used by the Connect handler and gRPC-Gateway (`server/router/api/v1/v1.go:67-97`, `server/router/api/v1/authz.go`). None of these enforce a request-rate limit.
- The only "limits" present are **concurrency** caps, not rate limits: `golang.org/x/sync/semaphore` gates concurrent thumbnail/image processing (`server/router/api/v1/v1.go:40-41`, `server/router/fileserver/fileserver.go:107-116`), and the webhook dispatcher uses a bounded async queue (`internal/webhook/webhook.go:39`). These bound simultaneous work, not per-user request frequency.

If you need per-user API rate limiting, it would have to be added (e.g., an Echo middleware registered alongside the others in `server/server.go`); it does not exist today.
