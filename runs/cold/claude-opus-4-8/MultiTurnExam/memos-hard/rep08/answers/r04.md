**Premise correction:** Neither. The webhook delivery workers do **not** consume from any external message broker — there is no NATS, RabbitMQ, AMQP, or Kafka anywhere in the codebase (a repo-wide search for those, and in `go.mod`, returns zero matches). So there is no broker "queue" declared.

**Actual mechanism:** Delivery is handled entirely in-process via a bounded Go channel. In `internal/webhook/webhook.go`:
- The queue is a buffered channel declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (capacity 128).
- The "workers" are 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each looping over `asyncPostQueue` and calling `Post` to perform the outbound HTTP delivery.
- Producers enqueue with `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send onto the channel and drops the event with a warning if the buffer is full.

So it's an in-memory channel-backed worker pool inside the single server process, not a message-broker consumer.
