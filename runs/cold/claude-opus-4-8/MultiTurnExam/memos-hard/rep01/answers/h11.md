**1st: `store.User` (referenced from ~6 packages outside the data layer); 2nd: `store.Memo` (~4 packages).**

Method: I took the core persistent entity types declared in the `store` package (`User`, `Memo`, `Attachment`, `Reaction`, `MemoRelation`, `MemoShare`, `UserSetting`, `Inbox`, `InstanceSetting`, `IdentityProvider`, `UserIdentity` — e.g. `store/user.go:29`, `store/memo.go:35`) and counted the distinct packages that reference `store.<Type>`, excluding the entire data layer itself (everything under `store/`, including the `store/db/{sqlite,postgres,mysql}` driver subpackages) and test files.

- **`store.User` — ~6 packages:** `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/rss`.
- **`store.Memo` — ~4 packages:** `server/notification`, `server/router/api/v1`, `server/router/rss`, `server/runner/memopayload`.

Everything else trails: `store.Attachment` ≈ 3, then `store.MemoShare`/`store.Inbox` ≈ 2, and the rest ≈ 1. So `User` is the most widely referenced entity type outside the data layer, with `Memo` second.

(Rough counts: grep-based static reference counting by package directory, so a package is counted once regardless of how many times it uses the type; the `store\.User\b` word-boundary match excludes distinct types like `store.UserSetting`/`store.UserIdentity`.)
