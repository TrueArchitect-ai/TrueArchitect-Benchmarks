**Delivery function — `webhook.Post` at `internal/webhook/webhook.go:120` (line 152, `safeClient.Do(req)` is the actual outbound HTTP call). Protection mechanism — `safeDialContext`, installed as the `DialContext` of the shared `safeClient` transport, at `internal/webhook/webhook.go:59` (client wiring at lines 32-37), which rejects any target resolving to a reserved/private IP via `isReservedIP` in `internal/webhook/validate.go:44` (CIDR list at `validate.go:14`).**

Details:

- **Where delivery executes:** `Post` (`internal/webhook/webhook.go:120`) marshals the payload, optionally HMAC-signs it (Standard Webhooks headers), and performs the POST via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. Async triggers go through `PostAsync` → a bounded queue → worker goroutines that call `Post` (`webhook.go:42-55`, `webhook.go:184`).

- **What protects it against internal/SSRF targets:** The outbound request uses `safeClient`, whose `http.Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:34-35`, `webhook.go:59-77`). At dial time it resolves the hostname and refuses to connect if any resolved IP is in a reserved/private range — this is the enforcement that matters because it runs on the actual connection and therefore also defeats DNS-rebinding (a URL that passed validation but re-resolves to an internal IP is still blocked). The reserved ranges (loopback, RFC-1918, link-local incl. cloud IMDS `169.254.169.254`, IPv6 equivalents) and the `isReservedIP` check live in `internal/webhook/validate.go:14-54`.

- Secondary/earlier layer: `ValidateURL` (`internal/webhook/validate.go:62`) runs at webhook *registration* time — checks scheme and that the hostname doesn't resolve to a reserved IP — but the dial-time guard in `webhook.go` is what protects the delivery itself. Both can be disabled via the `AllowPrivateIPs` flag (`validate.go:41-47`) for self-hosted local-network use.
