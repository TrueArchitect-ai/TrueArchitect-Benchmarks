**Premise correction: there is no GraphQL schema — this project exposes no GraphQL API at all.** A repo-wide search finds zero references to `graphql`/`gqlgen`, no `.graphql`/`.gql` schema files, and no GraphQL library in `go.mod`. So there is no GraphQL schema location to point to.

**Actual API surface — Protocol Buffers (gRPC) defined in `proto/api/v1/`, exposed over three transports.** The public API "schema" is the set of `.proto` service definitions:

- **Schema definitions:** `proto/api/v1/*.proto`, declaring 8 services — `MemoService`, `UserService`, `AttachmentService`, `AuthService`, `AIService`, `InstanceService`, `ShortcutService`, `IdentityProviderService` (e.g. `proto/api/v1/memo_service.proto`, `proto/api/v1/user_service.proto`). The REST/HTTP shape of each RPC is declared inline via `google.api.http` annotations (e.g. `GET /api/v1/memos`, `proto/api/v1/memo_service.proto:30`). Generated Go code lives under `proto/gen/api/v1/`.

- **How it's served** (wired in `server/router/api/v1/v1.go`):
  - **gRPC-Gateway** — a `runtime.NewServeMux` (`v1.go:96`) with handlers registered per service (e.g. `RegisterMemoServiceHandlerServer`, `v1.go:108`), exposing a RESTful JSON API under `/api/v1/...` derived from the proto HTTP annotations.
  - **Connect (connectrpc.com/connect)** — Connect handlers for browser clients (`v1.go:131`), replacing grpc-web.
  - The underlying gRPC service implementations are the `APIV1Service` methods (e.g. `MemoService`, `UserService`).

So the API is proto/gRPC + REST (gRPC-Gateway) + Connect, not GraphQL; the canonical schema is `proto/api/v1/*.proto`.
