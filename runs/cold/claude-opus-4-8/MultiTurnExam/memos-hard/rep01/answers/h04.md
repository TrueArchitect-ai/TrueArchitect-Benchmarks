**Yes — but only in a unit test.**

Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14`, whose `switch` constructs the MySQL driver via `mysql.NewDB(profile)` at `store/db/db.go:22`. That is the only production call site — a repo-wide grep for `mysql.NewDB` returns just the factory (`store/db/db.go:22`) and the definition itself (`store/db/mysql/mysql.go:20`).

- However, the MySQL driver's concrete type (`DB`, which implements `store.Driver`) *is* constructed directly outside the factory in a test: `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` to unit-test `IsRetryableAuthenticationMutationError` without opening a real connection.

So the answer depends on scope: no production/non-test code constructs it outside the factory (the only paths go through `mysql.NewDB` called from `NewDBDriver`), but the `DB` struct is instantiated directly in `store/db/mysql/auth_config_test.go:12`. Note that's a zero-value struct literal rather than a call to the package constructor `mysql.NewDB` (`store/db/mysql/mysql.go:20`), which is the function the factory invokes.
