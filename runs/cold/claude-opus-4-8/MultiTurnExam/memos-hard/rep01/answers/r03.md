**Premise correction: there is no nightly database-cleanup job, and no cron scheduler runs one — so there is no scheduled time to report.**

Evidence:

- **No cron scheduler is wired into the running server.** An `internal/scheduler` package exists (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`) and can parse cron expressions, but it is **imported by nothing in production** — the only files referencing it are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). It is dead/unused code from the app's perspective; no `Job` or nightly schedule is ever registered.

- **No database-cleanup job exists at all.** Searching for cleanup/nightly/cron/purge/vacuum-style scheduled work turns up nothing of the sort. The `cleanup` hits are unrelated: per-request attachment-storage cleanup on user deletion (`server/router/api/v1/user_service.go:421`), memo relation/attachment cleanup done inline on delete (`server/router/api/v1/memo_service.go:579`), and the in-memory cache's `CleanupInterval` sweep (`store/store.go:42`, `store/cache/cache.go:83`) — none are database cleanup, and none are cron-scheduled.

- **The only background jobs actually started** (in `server/server.go`) are: the HTTP server goroutine (`server.go:124`), the graceful-shutdown watcher (`server.go:186`), and the **S3 presign runner** — an immediate `RunOnce` plus a `time.Ticker` loop firing **every 12 hours** (`server/server.go:163`/`:169`; interval at `server/runner/s3presign/runner.go:27`). That runner refreshes expiring S3 presigned URLs; it is not a database cleanup, not nightly, and not driven by a cron scheduler (it's a fixed-interval ticker, not a wall-clock time).

So the question's premise is mistaken on two counts: there's no nightly DB-cleanup job, and the cron scheduler package that exists is not actually used to schedule anything.
