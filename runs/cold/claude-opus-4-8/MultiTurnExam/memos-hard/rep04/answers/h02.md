The server delivers webhook notifications when memo content changes. The outbound HTTP request actually executes inside the webhook `Post` function.

**Delivery function** — `webhook.Post` in `internal/webhook/webhook.go`; the request is actually sent at `internal/webhook/webhook.go:152` (`safeClient.Do(req)`). (`Post` runs either synchronously or via the async worker pool fed by `PostAsync`/`asyncPostQueue`, `internal/webhook/webhook.go:184-196` and `42-55`.)

**Protection mechanism** — SSRF/DNS-rebinding guard at dial time via `safeDialContext`, which resolves the target host and rejects any address in a reserved/private range. It's installed as the `safeClient` transport's `DialContext` (`internal/webhook/webhook.go:32-37`, function `safeDialContext` at `internal/webhook/webhook.go:59-77`), and the range check is `isReservedIP` against the parsed reserved CIDR list (loopback, RFC-1918, link-local/IMDS 169.254.0.0/16, IPv6 equivalents) in `internal/webhook/validate.go:44-54` (CIDRs at `internal/webhook/validate.go:14-23`).

Because the check runs at dial time on the resolved IPs (not just the URL string), it also defeats DNS rebinding. There is additionally an up-front `webhook.ValidateURL` check when a webhook URL is registered (`internal/webhook/validate.go:62-83`), but the enforcement that protects the actual delivery is the transport dialer. Note both are bypassable via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41-47`).

Answer line:
`webhook.Post — internal/webhook/webhook.go:152 (safeClient.Do); protection: safeDialContext dial-time reserved-IP block via isReservedIP — internal/webhook/webhook.go:59-77 + internal/webhook/validate.go:44-54`
