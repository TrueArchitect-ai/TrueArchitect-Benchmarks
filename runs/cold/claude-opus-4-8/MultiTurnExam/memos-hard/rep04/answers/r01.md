**Premise correction:** There is no Redis. The cache layer is not backed by Redis (or any external/network cache) — a repo-wide search for "redis" finds zero references in code or `go.mod`. The cache is a custom, process-local in-memory TTL cache implemented in `store/cache/cache.go` (a `map`/`sync`-based store of `item{value, expiration, size}` with a background cleanup goroutine). So there is no "Redis connection to configure."

**Actual mechanism:** The cache is configured in `store.New` at `store/store.go:38-53`. A single `cache.Config` is built there —
```
DefaultTTL: 10 * time.Minute
CleanupInterval: 5 * time.Minute
MaxItems: 1000
```
(`store/store.go:40-45`) — and used to construct three separate in-memory caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`), each via `cache.New(cacheConfig)`.

**TTL for user entries:** User entries are written with `userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`). `Set` applies the cache's default TTL (`store/cache/cache.go` `Interface.Set` — "adds a value with the default TTL"), and no `SetWithTTL` override is used for users. Therefore user cache entries expire after the **default TTL of 10 minutes** (`store/store.go:41`), with expired entries reclaimed by the 5-minute cleanup sweep. Note the `DefaultConfig()` in `store/cache/cache.go:56` also happens to specify 10 minutes, but the store constructs its caches with its own inline config, not `DefaultConfig()`.

Answer line:
`No Redis exists — the cache is an in-memory TTL cache (store/cache/cache.go) configured in store.New (store/store.go:38-53); user entries use the default TTL = 10 minutes (store/store.go:41), since userCache.Set uses DefaultTTL (store/user.go:98).`
