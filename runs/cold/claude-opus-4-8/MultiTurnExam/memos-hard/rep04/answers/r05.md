**Premise correction:** There is no GraphQL schema — this project does not expose a GraphQL API. A repo-wide search finds no `graphql`/`gqlgen` references, no `.graphql` schema files, and no GraphQL dependency in the code.

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC services**, served over Connect and gRPC-Gateway (REST/JSON). The schema (service and message definitions) lives in the `.proto` files under `proto/api/v1/`, e.g.:
- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, and shared types in `proto/api/v1/common.proto`.

These compile to Go in `proto/gen/api/v1/` (including Connect stubs under `proto/gen/api/v1/apiv1connect/` and gRPC-Gateway REST bindings `*.pb.gw.go`). The handlers are registered and served in `server/router/api/v1/v1.go` (Connect interceptors/handlers and the gRPC-Gateway mux). So the API is proto-defined gRPC + REST, not GraphQL.

Answer line:
`No GraphQL exists; the public API is gRPC/Protobuf defined in proto/api/v1/*.proto (e.g. memo_service.proto, user_service.proto), generated into proto/gen/api/v1/ and served via Connect + gRPC-Gateway in server/router/api/v1/v1.go.`
