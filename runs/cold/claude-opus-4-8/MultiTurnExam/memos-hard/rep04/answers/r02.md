**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — it does not exist, so there is nothing registered and no request limits to report.

Evidence:
- A repo-wide search for rate limiting (`rate limit`, `ratelimit`, `throttle`, `limiter`, `golang.org/x/time/rate`) returns no matches in the Go source, and `go.mod` pulls in no rate-limiting/throttling library (e.g., no `golang.org/x/time`, `tollbooth`, etc.).
- The middleware/interceptors actually registered on the API surface are, for the Connect/gRPC handlers (`server/router/api/v1/v1.go:133-137`): `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` — plus the gRPC-Gateway auth middleware (`server/router/api/v1/v1.go:69,97`). For the HTTP server (`server/server.go:51-52`): `middleware.Recover()` and `newCORSMiddleware(profile)`. None of these performs rate limiting.
- The only request "limit" present is a body-size cap, `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141` — a maximum request byte size, not a per-user request-rate limit.

So there is no per-user rate limiter, no registration site, and no configured request-per-window limits.
