**Premise correction:** There is no nightly database-cleanup job, and nothing is scheduled through the cron scheduler — so there is no run time to report.

Evidence:
- A cron scheduler package does exist (`internal/scheduler/`: `scheduler.go`, `job.go`, `parser.go` with `ParseCronExpression`, etc.), but it is a standalone/library package that is **not used anywhere** in the server. Searching for any use of it outside its own package (`scheduler.`, `NewScheduler`, `AddJob`) returns only its own in-package tests — no production wiring.
- The only background jobs actually started at server startup are registered in `startBackgroundRunners` (`server/server.go:153-173`), and there are exactly two runners (`server/runner/`): `s3presign` and `memopayload`. Neither is a database-cleanup job:
  - `s3presign` refreshes S3 presigned URLs on a **12-hour `time.Ticker`** (`server/runner/s3presign/runner.go:26-41`), not a cron time-of-day and not cleanup.
  - `memopayload` rebuilds memo payloads and isn't even wired into startup (not constructed anywhere in production).
- No `@daily`/`@midnight`/cron-scheduled cleanup job is registered anywhere, and the `internal/scheduler` cron engine has no jobs added to it.

So there is no scheduled nightly cleanup task; the premise that one runs at a particular cron time is unfounded.
