**Computation site — `RebuildMemoPayload` in `server/runner/memopayload/runner.go:73`, which calls `markdown.Service.ExtractAll` (`internal/markdown/markdown.go:356`) and writes the result into `memo.Payload.Tags` / `memo.Payload.Property`.**

**Triggers (recomputation call sites):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (on every new memo, after content validation).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447` (in the `content` field-update branch, i.e. whenever a memo's content changes).
- Batch rebuild `(*Runner).RunOnce` — `server/runner/memopayload/runner.go:52`, which walks all memos in batches of 100 and re-derives + persists each payload (used to backfill/migrate payloads; note this `Runner` is defined but not wired into normal startup).

**Extracted properties** (`ExtractedData` → `MemoPayload`): from a single goldmark parse walk of the content, `ExtractAll` produces:
- `Tags` — the list of `#tag` hashtags (`memo.Payload.Tags`).
- `Property` (`storepb.MemoPayload_Property`, `proto/gen/store/memo.pb.go:85`), containing:
  - `Title` — text of a leading H1 heading, when the document's first block is `# ...`.
  - `HasLink` — true if any link node is present.
  - `HasCode` — true for any code block / fenced code / inline code span.
  - `HasTaskList` — true if any task-list checkbox exists.
  - `HasIncompleteTasks` — true if any unchecked task checkbox exists.

(The `ExtractedData` also gathers `Mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property` into the payload.) This payload is the derived, content-computed metadata used for list/preview rendering rather than anything the user sets directly.
