h05.

**Mechanism: explicit Go code** — a user's emoji reactions are removed by application code inside the `DeleteUser` store transaction, not by any database rule. No foreign key or `ON DELETE CASCADE` exists on the `reaction` table in any backend, and no triggers touch it.

**Evidence locations:**

1. **User delete path:** `server/router/api/v1/user_service.go:393` (`DeleteUser` handler) → `store/user.go:171` (store dispatch) → per-backend driver `DeleteUser`.

2. **Explicit reaction deletion (all three backends), covering both reactions the user authored and reactions others left on the user's memos:**
   - SQLite — `store/db/sqlite/user_delete.go:96` (`deleteReactionsByContentIDsTx`, `DELETE FROM reaction WHERE content_id IN ...`) and `:102` (`deleteReactionsByCreatorTx`, `DELETE FROM reaction WHERE creator_id = ...`), orchestrated in `deleteUserTargetsTx` (lines 92–127), all within one transaction.
   - MySQL — `store/db/mysql/user_delete.go:420` (by content_id) and `:438` (by creator_id).
   - Postgres — `store/db/postgres/user_delete.go:383` (by content_id) and `:401` (by creator_id).

3. **Schema confirms no DB-level rule:** the `reaction` table's `creator_id` is a plain `INTEGER/INT NOT NULL` with no `REFERENCES user(id)` / `ON DELETE CASCADE` in `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/mysql/LATEST.sql:91-98`, and `store/migration/postgres/LATEST.sql:91-98`. (By contrast the `memo` table does use `ON DELETE CASCADE`, so the reaction table's omission is deliberate.)

4. **No triggers:** the only historical triggers (SQLite modification-time triggers) were removed in `store/migration/sqlite/0.7/01__remove_triggers.sql`; none ever referenced `reaction`.

5. **Test confirming intent:** `store/test/user_delete_test.go` (`TestDeleteUserCleansRelatedData`).
