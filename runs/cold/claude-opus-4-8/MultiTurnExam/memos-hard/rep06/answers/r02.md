**Premise correction:** This repository has no per-user API rate-limiting middleware — there is nothing to register and no request limits to report.

Evidence:
- A repo-wide grep for `rate limit`/`ratelimit`/`throttle`/`limiter`/`tollbooth`/`golang.org/x/time/rate` across all Go sources finds only a single aspirational comment in unrelated documentation (`internal/email/doc.go:86`: "Rate limit email sending to prevent abuse"), not any implementation.
- `go.mod`/`go.sum` pull in no rate-limiting library (no tollbooth, ulule/limiter, `x/time/rate`, etc.).
- The server's actual middleware/interceptor stack contains no limiter. The Echo middleware registered is only static-file serving and SPA fallback (`server/router/frontend/frontend.go:54,59`). The API v1 surface registers an auth middleware for the gRPC-Gateway and Connect interceptors that do metadata conversion, logging, and authorization (`server/router/api/v1/v1.go:69,97`; `server/router/api/v1/connect_interceptors.go`; `server/router/api/v1/authz.go`) — none of which enforce request-count/rate limits.

The only request-bounding mechanisms present are unrelated to rate limiting: content-length caps on memos, and concurrency semaphores for thumbnail/image processing (`server/router/api/v1/v1.go`). If rate limiting is required, it would need to be added (e.g. as a new Connect interceptor or Echo middleware); it does not currently exist.
