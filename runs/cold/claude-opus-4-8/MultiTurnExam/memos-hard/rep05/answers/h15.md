Memo view-visibility (PUBLIC / PROTECTED / PRIVATE) is enforced across several distinct server surfaces. The core "who may view a memo" enforcement sites:

- **v1 API single-memo read** — `checkMemoReadAccess` (denies non-public memos to anonymous users, and private memos to non-creators) — `server/router/api/v1/memo_service.go:44-67` (invoked by `GetMemo`)
- **v1 API list** — `ListMemos` visibility filtering (anonymous → PUBLIC only; authenticated non-owner → PUBLIC+PROTECTED, plus own via SQL filter) — `server/router/api/v1/memo_service.go:217-226`
- **File server (attachment serving)** — `checkAttachmentPermission` (PUBLIC served only if anonymous allowed; else requires share token, or authenticated creator/admin for private) — `server/router/fileserver/fileserver.go:677-701`
- **RSS feeds** — `GetExploreRSS` and `GetUserRSS` restrict feeds to `store.Public` — `server/router/rss/rss.go:90` and `server/router/rss/rss.go:141`
- **Frontend sitemap (SSR)** — `getSitemapXML` restricts to `store.Public` — `server/router/frontend/frontend.go:150`
- **User stats API** — `ListAllUserStats` / `ListUserStats` filter memos by visibility based on viewer — `server/router/api/v1/user_service_stats.go:84-90` and `server/router/api/v1/user_service_stats.go:218-220`

Additional action-gating surfaces that enforce the same view-visibility rule before allowing interaction:

- **Reactions** — `server/router/api/v1/reaction_service.go:30,38,83`
- **Attachment listing/metadata** — `server/router/api/v1/attachment_service.go:445-451`
- **Memo attachment access** — `server/router/api/v1/memo_attachment_service.go:214-222`
- **Comments** — `server/router/api/v1/memo_service_comments.go:41`

(The first three — v1 read `checkMemoReadAccess`, RSS, and the file server — are three clearly distinct surfaces; the others above are the remaining enforcement points.)
