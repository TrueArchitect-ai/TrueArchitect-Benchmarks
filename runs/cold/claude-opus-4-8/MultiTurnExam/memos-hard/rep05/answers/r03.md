**Premise correction:** There is no nightly database-cleanup cron job in this codebase, so there is no scheduled time to report. The premise assumes a job that doesn't exist.

Evidence:

- A generic cron scheduler library does exist as a self-contained package, `internal/scheduler/` (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, etc.), and its doc comment even uses a hypothetical `"daily-cleanup"` job as an *illustrative example* (`internal/scheduler/doc.go:15-18`). But that is only example/documentation text, not a registered job.
- The scheduler package is **never imported or used anywhere outside its own directory**: grepping the whole tree for `internal/scheduler`/`scheduler.` usages outside `internal/scheduler/` returns nothing, and there are no `scheduler.New(...)` or `.Register(...)` calls in `server/` or `cmd/`. So no job — cleanup or otherwise — is ever registered with it in production.
- The only actual background jobs wired into server startup are the two runners in `server/runner/` (see `server/server.go`): the S3 presign runner (every 12 hours — `server/runner/s3presign/runner.go:27`) and the memo-payload rebuild runner (which isn't even instantiated). Neither is a "nightly database cleanup," and neither is time-of-day/cron scheduled — they run on fixed intervals via `time.Ticker`, not clock times.

If you're thinking of periodic data maintenance, the closest thing is that per-user deletions cascade cleanup synchronously in Go (`store/db/*/user_delete.go`), and the S3 presign runner refreshes URLs on a 12-hour interval — but there is no nightly cron cleanup job and thus no scheduled run time.
