**Route:** `GET /file/users/:identifier/avatar` (registered at `server/router/fileserver/fileserver.go:124`). The avatar image itself is stored as a base64 data-URI in the user record's `avatar_url` column, so the "stored data" is the user row.

Hops:

1. `serveUserAvatar` — `server/router/fileserver/fileserver.go:168` (handler; extracts `:identifier`, then decodes `user.AvatarURL` via `parseDataURI` and writes the bytes with `c.Blob`)
2. `(*FileServerService).getUserByUsername` — `server/router/fileserver/fileserver.go:715` (builds `store.FindUser{Username: &identifier}`)
3. `(*Store).GetUser` — `store/user.go:148` (cache check, then delegates to `ListUsers`)
4. `(*Store).ListUsers` — `store/user.go:136` (delegates to the driver)
5. `(*DB).ListUsers` — `store/db/sqlite/user.go:88` (builds `WHERE username = ?` and runs the SELECT that reads `avatar_url` from the `user` table — the data layer; postgres/mysql drivers have the equivalent `store/db/postgres/user.go` and `store/db/mysql/user.go`)

The returned `store.User.AvatarURL` (`store/user.go:43`) carries the stored image data back up to `serveUserAvatar`, which parses the data URI (`parseDataURI`, `server/router/fileserver/fileserver.go:196`) and serves the raw image bytes.
