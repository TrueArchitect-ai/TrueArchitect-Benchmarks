**delivery function — `Post` in `internal/webhook/webhook.go` (line 120, actual HTTP send at `webhook.go:152` via `safeClient.Do(req)`); protection mechanism — `safeDialContext` in `internal/webhook/webhook.go` (line 59), backed by `isReservedIP` / `reservedNetworks` in `internal/webhook/validate.go` (lines 43–54)**

Details:

- **Where outbound delivery executes**: `webhook.Post` (`internal/webhook/webhook.go:120`) marshals the payload, builds the request, optionally adds the HMAC-SHA256 signature headers, and performs the actual network send at `internal/webhook/webhook.go:152` (`safeClient.Do(req)`). Deliveries are queued and run on background workers via `PostAsync` → `asyncPostQueue` → `Post` (`webhook.go:184`, `webhook.go:42-55`).

- **What protects it from internal/private addresses (SSRF/DNS-rebinding protection)**: The shared `safeClient` uses a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the target host at dial time and rejects any resolved IP that `isReservedIP` matches (`internal/webhook/validate.go:44`), where `isReservedIP` checks against `reservedNetworks`/`reservedCIDRs` covering loopback, RFC-1918 private ranges, link-local/cloud IMDS (169.254.0.0/16), and IPv6 equivalents (`internal/webhook/validate.go:14-23`). Because the check happens at dial time on the resolved IP, it also defeats DNS-rebinding. There is a separate up-front `ValidateURL` check (`internal/webhook/validate.go:62`) used when webhooks are configured, but the enforced-at-delivery guard is `safeDialContext`. (Note: both can be disabled via the `AllowPrivateIPs` flag, `validate.go:41`.)
