**Premise correction:** There is no Redis in this project. The premise is false — the cache layer is not backed by Redis (there are zero `redis` references in the Go sources or `go.mod`), so there is no Redis connection to configure. The cache is a **process-local, in-memory** implementation.

**Actual mechanism:**

- The cache is a custom in-memory `Cache` defined in `store/cache/cache.go` (a `map[string]*item` guarded by a mutex, with a background cleanup goroutine — `store/cache/cache.go:34-76`). It stores plain Go values in the server's own heap; nothing is serialized to or connected to an external store.
- The user cache is one of three such caches created in `store.New`, all built from the same `cacheConfig` (`store/store.go:40-53`): `userCache = cache.New(cacheConfig)` at `store/store.go:52`. Reads/writes go through it in `store/user.go` (e.g. `GetUser` checks `s.userCache.Get` at `store/user.go:150` and populates via `s.userCache.Set` at `:167`, keyed by `userCacheKey(userID)` — `store/user.go:88`).
- **TTL for user entries: 10 minutes.** User entries are stored with `Set` (not `SetWithTTL`), so they use the cache's `DefaultTTL`, configured to `10 * time.Minute` at `store/store.go:41` (matching the package default in `store/cache/cache.go` `DefaultConfig`). A cleanup pass runs every 5 minutes (`CleanupInterval`, `store/store.go:42`), and the cache holds at most 1000 items (`MaxItems`, `store/store.go:43`).
