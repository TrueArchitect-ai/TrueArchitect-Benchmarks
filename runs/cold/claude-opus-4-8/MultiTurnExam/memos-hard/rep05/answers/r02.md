**Premise correction:** This repository has **no per-user API rate-limiting middleware** — it is not registered anywhere because it does not exist. The premise assumes a component that isn't present, so there are no request limits to report.

Evidence:

- A repo-wide search for rate-limiting turns up nothing in code: no `rate.Limiter`, `ratelimit`, `throttle`, `limiter`, `golang.org/x/time/rate`, or `tollbooth` references in any `.go` file, and `go.mod` declares no rate-limiting dependency. The only textual match for "rate limit" is an aspirational comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") — a doc note, not an implementation.
- The complete set of registered request-path middleware/interceptors is:
  - Echo HTTP middleware: `middleware.Recover()` and CORS (`server/server.go:51-52`), plus static-file and SPA-fallback middleware on the frontend (`server/router/frontend/frontend.go:54,59`).
  - Connect/gRPC interceptors: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` (`server/router/api/v1/v1.go:133-137`, defined in `server/router/api/v1/connect_interceptors.go`).

None of these enforce request-count limits per user (or otherwise). The closest request-bounding control is a *payload size* cap, not a rate limit: `connect.WithReadMaxBytes(maxAPIRequestBytes)` (`server/router/api/v1/v1.go:141`) and webhook read limits — but these bound request/response byte sizes, not request frequency. So there is no per-user rate-limiting registration site or limit values to cite.
