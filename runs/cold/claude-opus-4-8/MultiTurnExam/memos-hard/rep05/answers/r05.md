**Premise correction:** There is no GraphQL schema in this project. The premise is false — the public API is not GraphQL, so there is no GraphQL schema file to point to. A repo-wide search finds zero references to `graphql`/`gqlgen`, no `.graphql`/`.gql` schema files, and no such dependency in `go.mod`.

**Actual API surface:** The public API is a **Protocol Buffers / gRPC API**, defined as `.proto` service definitions and exposed over both Connect-RPC and a gRPC-Gateway HTTP/JSON transport.

- **Schema/IDL location:** the service and message definitions live in `proto/api/v1/*.proto` — e.g. `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, and shared types in `common.proto`. Generated Go code lives under `proto/gen/api/v1/`.
- **How it's served:** `NewAPIV1Service` / registration in `server/router/api/v1/v1.go`:
  - Connect-RPC handlers registered at `server/router/api/v1/v1.go:141` (`RegisterConnectHandlers(connectMux, connectInterceptors, ...)`), with interceptors set up at `:133-137`.
  - A grpc-gateway HTTP/JSON mux via `RegisterGateway` (`server/router/api/v1/v1.go:65`), using `github.com/grpc-ecosystem/grpc-gateway/v2/runtime` (`v1.go:8`), mounted on the Echo server (`v1.go:123,143`).

So the API surface is proto-defined gRPC/Connect (plus a REST/JSON gateway), not GraphQL.
