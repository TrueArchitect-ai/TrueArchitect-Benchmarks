**Concrete method — `(*DB).CreateMemo` in the SQLite driver — `store/db/sqlite/memo.go:16` (the `INSERT INTO \`memo\` ... RETURNING ...` executes at `store/db/sqlite/memo.go:41-42`).**

**Determination method:**

1. There are three candidate `CreateMemo` implementations, one per driver: `store/db/sqlite/memo.go:16`, `store/db/postgres/memo.go`, and `store/db/mysql/memo.go`. All satisfy the `store.Driver` interface, and `Store.CreateMemo` (`store/memo.go:109`) just delegates to `s.driver.CreateMemo` (`store/memo.go:113`) — so the concrete one that runs is whichever driver the factory selected.

2. The driver is chosen in the factory `NewDBDriver` (`store/db/db.go:14-27`) by a `switch profile.Driver`: `"sqlite"` → `sqlite.NewDB` (`store/db/db.go:20-22`).

3. `profile.Driver`'s default is `sqlite` with no flags set: `cmd/memos/main.go:122` (`viper.SetDefault("driver", "sqlite")`) and the flag's default at `cmd/memos/main.go:130` (`String("driver", "sqlite", ...)`). Confirmed also by `internal/profile/profile.go:110`, which special-cases `Driver == "sqlite"` when no DSN is given.

So on a default install the `Store` holds a `*sqlite.DB`, and saving a memo dispatches through `Store.CreateMemo` → `(*sqlite.DB).CreateMemo`, which builds and executes the SQL INSERT at `store/db/sqlite/memo.go:41`.
