**Premise correction:** There is no per-user API rate-limiting middleware in this repository, so there is nowhere it is registered and there are no request limits to report.

Evidence:
- A repo-wide search for rate-limiting (`rate.limit`, `ratelimit`, `throttle`, `limiter`, `golang.org/x/time/rate`, `tollbooth`) turns up **no** implementation in non-test code. The only hit is an aspirational comment in a doc file — `internal/email/doc.go:86` (`- Rate limit email sending to prevent abuse`) — which describes a suggestion, not an implemented feature, and concerns email sending rather than API requests.
- `go.mod` contains no rate-limiting dependency.
- The actual middleware/interceptor stack that *is* registered contains no limiter: the Echo server registers only `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`), and the API layer's Connect/gRPC interceptors are `MetadataInterceptor`, `LoggingInterceptor` (`server/router/api/v1/connect_interceptors.go:17,93`) and an authorization interceptor (`server/router/api/v1/authz.go`) — authentication/authorization and logging, not rate limiting.

So the server enforces auth/ACL (per-method allow-list in `server/router/api/v1/acl_config.go`) but does not implement per-user API request rate limiting anywhere.
