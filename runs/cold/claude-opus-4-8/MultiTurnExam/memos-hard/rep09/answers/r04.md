**Premise correction:** The webhook delivery workers do not consume from any external message broker — neither NATS nor RabbitMQ. Neither is present: a repo-wide search finds no `nats`, `rabbitmq`, `amqp`, or `kafka` references in the code, and `go.mod` declares no such dependency. There is no external queue to "declare."

**Actual mechanism:** Webhook delivery uses an in-process buffered Go channel as the queue, with a fixed pool of goroutine workers — all inside `internal/webhook/webhook.go`:

- The queue is a package-level buffered channel with capacity 128: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`.
- The workers are 4 goroutines started in `init()` that range over that channel and call `Post` for each payload — `internal/webhook/webhook.go:42-55`.
- Producers enqueue via `PostAsync`, a non-blocking send with a `default` case that drops the payload (and logs a warning) if the buffer is full — `internal/webhook/webhook.go:184-196`.
- Each worker then performs the actual outbound HTTP POST in `Post` via the SSRF-guarded `safeClient.Do` — `internal/webhook/webhook.go:120,152`.

So the "queue" is a bounded in-memory channel local to the process (`webhook.go:39`), consumed by in-process worker goroutines (`webhook.go:42-55`); nothing is brokered externally, and the queue does not survive a process restart.
