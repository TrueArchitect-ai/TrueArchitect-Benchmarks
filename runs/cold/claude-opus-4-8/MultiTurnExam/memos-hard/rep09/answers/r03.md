**Premise correction:** There is no nightly database-cleanup job in a cron scheduler, so there is no scheduled time to report.

Evidence:
- A cron-style scheduler package does exist (`internal/scheduler/` — `parser.go`, `job.go`, `scheduler.go`, `doc.go`), and it can parse cron expressions and run registered jobs. But it is **never used in production**: no non-test file anywhere imports `usememos/memos/internal/scheduler`, and the only references to `Register`/`Start` are inside the package's own documentation example (`internal/scheduler/doc.go:14,23`). The scheduler is unwired dead/library code — nothing constructs it or registers a job with it.
- There is no database-cleanup job of any kind: a search for `cleanup`/`nightly`/`vacuum`/`purge`/`midnight` finds no such scheduled task. The only `cleanup` in the codebase is the in-memory cache's expiry sweep (`store/cache/cache.go`, on a 5-minute interval), which is unrelated to the database and is a `time.Ticker` loop, not a cron job.
- The actual background work that runs on startup is the S3 presign runner (12-hour ticker, `server/runner/s3presign/runner.go`), wired in `server/server.go:162-169` — again a `time.Ticker`, not the cron scheduler, and not a database-cleanup task.

So neither a "nightly" schedule nor a "database-cleanup" job exists to have a scheduled time.
