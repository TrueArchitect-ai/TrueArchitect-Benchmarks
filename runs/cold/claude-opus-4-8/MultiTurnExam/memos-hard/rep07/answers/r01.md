**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` finds zero references in Go code and no Redis dependency in `go.mod`. The cache layer is not backed by Redis (or any external store) — it's a purely in-process, in-memory TTL cache.

**Actual mechanism:**
- The cache implementation is `store/cache/cache.go` — an in-memory `Cache` (map + `sync` + background cleanup goroutine) implementing the `cache.Interface`. There is no connection to configure; nothing is dialed or connected.
- The user cache is one of three in-memory caches created in `store.New` — `userCache: cache.New(cacheConfig)` at `store/store.go:52` (alongside `instanceSettingCache` and `userSettingCache`).
- The TTL for user entries comes from that shared `cacheConfig`: `DefaultTTL: 10 * time.Minute` (`store/store.go:41`), with `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000`. So user cache entries expire **10 minutes** after they're set (via `Set`/`SetWithTTL` in `store/cache/cache.go`; the package's own `DefaultConfig` in `store/cache/cache.go:57` also defaults to 10 minutes, but the Store explicitly supplies its own config).

Users are cached/evicted by `Store.GetUser`/`ListUsers` (`store/user.go`), keyed by user ID.
