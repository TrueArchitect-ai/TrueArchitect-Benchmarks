Memo view-visibility (PUBLIC / PROTECTED / PRIVATE, plus archived-only-to-creator) is enforced across several distinct server surfaces:

- Single-memo read on the v1 API — `checkMemoReadAccess` (Public served to all; Protected requires auth; Private only creator; archived only creator) — `server/router/api/v1/memo_service.go:39-67` (called from `GetMemo`)
- Memo listing on the v1 API — visibility filtering in `ListMemos` (anon → PUBLIC only; authed → own + PUBLIC/PROTECTED) — `server/router/api/v1/memo_service.go:217-227`
- Attachment file serving (fileserver) — `checkAttachmentPermission` gates attachment content by the parent memo's visibility (+ share-token / admin fallback) — `server/router/fileserver/fileserver.go:650-703` (checks at 677, 699)
- Attachment access on the v1 API — parent-memo visibility check before returning attachment data — `server/router/api/v1/attachment_service.go:445-451` (and `memo_attachment_service.go:222`)
- RSS feed — only PUBLIC memos are selected — `server/router/rss/rss.go:90` and `rss.go:141`
- Frontend server-side render / prerender metadata — only PUBLIC memos — `server/router/frontend/frontend.go:150`
- User stats listing — visibility filter by viewer — `server/router/api/v1/user_service_stats.go:84-90` and `:218-220`
- Reactions on a memo — gated by memo visibility (Private → only creator/superuser) — `server/router/api/v1/reaction_service.go:38` and `:83`
