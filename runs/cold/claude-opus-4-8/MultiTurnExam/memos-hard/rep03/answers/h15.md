Distinct memo-visibility (view-access) enforcement sites across server surfaces:

- gRPC/REST API — `GetMemo` single-memo read check (denies protected to anon, private to non-owner) — server/router/api/v1/memo_service.go:55-63
- gRPC/REST API — `ListMemos` visibility filtering (anon → PUBLIC only; authed → own + PUBLIC/PROTECTED) — server/router/api/v1/memo_service.go:219-225
- gRPC/REST API — user memo stats visibility filtering — server/router/api/v1/user_service_stats.go:84-90 (and :218-220)
- gRPC/REST API — memo comments/relations list filter — server/router/api/v1/memo_service_comments.go:158-160 and server/router/api/v1/memo_relation_service.go:109-111
- Realtime SSE delivery — per-client `canReceive` gates events by memo visibility/creator — server/router/api/v1/sse_hub.go:134-141
- RSS feed — restricts to PUBLIC memos only — server/router/rss/rss.go:90 and :141
- Frontend SSR/meta rendering — restricts to PUBLIC memos only — server/router/frontend/frontend.go:150
- Attachment file serving (fileserver) — access gated by the linked memo's visibility — server/router/fileserver/fileserver.go:677 and :699
- Attachment API (`GetAttachment` / blob) — access follows linked memo visibility — server/router/api/v1/attachment_service.go:445-451 (and the SetMemoAttachments path, server/router/api/v1/memo_attachment_service.go:214-222)
- Reaction API — reacting/viewing gated by memo visibility — server/router/api/v1/reaction_service.go:30-38 and :83
