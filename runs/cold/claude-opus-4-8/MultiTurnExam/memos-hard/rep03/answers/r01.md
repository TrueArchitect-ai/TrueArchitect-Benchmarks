**Premise correction:** There is no Redis anywhere in this codebase. `grep` for `redis` across all Go source and `go.mod` returns zero hits — the cache layer is not backed by Redis (or any external cache server). So there is no "Redis connection" to configure.

**Actual mechanism:** The cache is a purely in-process, in-memory cache implemented in Go, with a background cleanup goroutine — `store/cache/cache.go` (the `cache.Interface`/`cache.Cache` type). It stores plain `any` values in a map guarded by a mutex, with per-item expiration times.

Three such caches are constructed by the store, all with the same config, in `Store.New` — `store/store.go:38-53`:
- `instanceSettingCache`, `userCache`, `userSettingCache`, each `cache.New(cacheConfig)`.

**TTL for user entries:** The `userCache` (`store/store.go:52`) uses the default config `DefaultTTL: 10 * time.Minute` (`store/store.go:41`; also the package default in `cache.DefaultConfig`, `store/cache/cache.go`). User rows are inserted into it via `s.userCache.Set(...)` in `GetUser` (`store/user.go:167`), which uses the default TTL — so **user entries expire after 10 minutes** (with cleanup sweeps every 5 minutes, `store/store.go:42`, and a 1000-item cap).
