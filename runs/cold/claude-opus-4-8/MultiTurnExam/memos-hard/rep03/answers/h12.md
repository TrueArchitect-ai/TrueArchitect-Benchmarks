**Concrete method — `(*DB).CreateMemo` in the SQLite driver — `store/db/sqlite/memo.go:16`.** The actual SQL INSERT is built and executed there: `INSERT INTO memo (...) VALUES (...) RETURNING ...` via `d.db.QueryRowContext` (`store/db/sqlite/memo.go:41-47`).

**How I determined which of the three driver implementations (sqlite/postgres/mysql) actually runs:**

1. There are three `CreateMemo` implementations — `store/db/sqlite/memo.go:16`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go` — all satisfying the `store.Driver` interface. The store-level `Store.CreateMemo` (`store/memo.go`) just delegates to `s.driver.CreateMemo`, so the concrete one is whichever driver was constructed at startup.

2. The driver is chosen in the factory `NewDBDriver` by `switch profile.Driver` (`store/db/db.go:22` for the `"mysql"` case, `sqlite.NewDB` for `"sqlite"`).

3. `profile.Driver` comes from the `driver` config value, whose default — with no flags/env set — is `"sqlite"`: `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the flag default `rootCmd.PersistentFlags().String("driver", "sqlite", ...)` (`cmd/memos/main.go:130`). The profile also confirms SQLite is the default path by auto-filling a SQLite DSN when `Driver == "sqlite"` and DSN is empty (`internal/profile/profile.go:110`).

So on a default install the factory takes the `"sqlite"` branch → `sqlite.NewDB` → `sqlite.(*DB).CreateMemo` executes the INSERT; the postgres and mysql `CreateMemo` methods are compiled in but never reached.
