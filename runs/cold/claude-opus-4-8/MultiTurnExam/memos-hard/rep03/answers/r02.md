**Premise correction:** There is no per-user API rate-limiting middleware in this codebase, so there is nothing to register and no request limits to report.

Evidence:
- Searching the Go source for any rate-limiting concept — `rate limit`, `ratelimit`, `limiter`, `throttle`, `golang.org/x/time/rate`, `tollbooth`, `StatusTooManyRequests`/`429` — yields no implementation (the only match is a comment aspiration in `internal/email/doc.go:86` about rate-limiting *email sending*, not API requests). `go.mod` pulls in no rate-limiting library.
- The middleware chain that *is* registered contains no limiter. On the Echo HTTP server, only `middleware.Recover()` and the CORS middleware are installed (`server/server.go:51-52`, `server/cors.go`). On the API layer, the Connect/gRPC interceptor chain is Metadata → Logging → Recovery → Auth (`server/router/api/v1/v1.go:133-137`), plus the gRPC-Gateway auth middleware (`server/router/api/v1/v1.go:69,97`). None of these enforces per-user request limits.

The only request-size guard present is a byte cap on request bodies (`connect.WithReadMaxBytes(maxAPIRequestBytes)`, `server/router/api/v1/v1.go:141`), which limits payload size — not request rate. So the described component does not exist.
