**Delivery function: `Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection mechanism: `safeDialContext` — `internal/webhook/webhook.go:59`**

Details:

- **Where outbound delivery executes**: `Post` in `internal/webhook/webhook.go:120` marshals the payload, builds the `POST` request (and optional Standard-Webhooks HMAC signature), and fires it via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. Delivery is normally driven asynchronously: `PostAsync` enqueues onto a bounded channel, and 4 worker goroutines started in `init()` call `Post` (`internal/webhook/webhook.go:41-53`).

- **What protects it from internal addresses (SSRF guard)**: All dispatches go through the shared `safeClient`, whose `Transport.DialContext` is set to `safeDialContext` (`internal/webhook/webhook.go:31-36`). `safeDialContext` (`internal/webhook/webhook.go:59`) re-resolves the target hostname at *dial time* and rejects any address in a reserved/private range, which also defeats DNS-rebinding (the check happens on the IP actually being connected to, not just a pre-validated hostname). The range test is `isReservedIP` (`internal/webhook/validate.go:44`), backed by the `reservedCIDRs` list — loopback, RFC-1918, link-local/cloud IMDS `169.254.0.0/16`, and IPv6 equivalents (`internal/webhook/validate.go:13-23`). It can be disabled via the `AllowPrivateIPs` flag for local-network self-hosting.

Supporting (defense-in-depth, not the delivery-time guard): `ValidateURL` at `internal/webhook/validate.go:62` validates scheme and resolved IPs when a webhook URL is first configured.
