**Premise correction: There is no nightly database-cleanup job — and in fact no scheduled job at all is registered anywhere in this codebase — so there is no scheduled run time to report.**

Evidence:
- A generic cron-style scheduler package exists at `internal/scheduler/` (`scheduler.go`, `job.go`, `parser.go`), but it is **never used by production code**: grepping `server/` and `cmd/` for `internal/scheduler` / `scheduler.New` / `.Register(` returns nothing outside the package's own tests. Nothing calls `scheduler.New(...)` or registers a `Job`.
- The only mention of a "daily-cleanup" job is illustrative documentation, not a real registration: `internal/scheduler/doc.go:15-18` shows an *example* `Name: "daily-cleanup", Schedule: "0 2 * * *"`, and `job.go:21` gives `"0 0 * * *"` as an example comment. These are docstrings, not scheduled jobs.
- The actual background work in the server is not cron-driven and includes no DB cleanup: the only runners are the S3 presign runner (a 12-hour `time.Ticker`, `server/runner/s3presign/runner.go:25`) started in `server/server.go:162-169`, and the (unwired) memopayload runner. Neither is a nightly database cleanup.

So the premise is mistaken: no nightly cleanup job is scheduled; the scheduler library ships unused.
