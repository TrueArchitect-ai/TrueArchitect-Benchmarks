Memo view-access (visibility) is enforced at these distinct server surfaces:

Single-memo read (gRPC GetMemo path) — `checkMemoReadAccess`, gate at store.Public/Private checks — server/router/api/v1/memo_service.go:39 (logic at :55-65)
Memo listing (gRPC ListMemos) — visibility restriction of the query for the requesting user (`VisibilityList` / CEL `visibility in ["PUBLIC","PROTECTED"]` filter) — server/router/api/v1/memo_service.go:217-227
Attachment/raw file serving (file server) — `checkAttachmentPermission`, gates blob delivery by the owning memo's visibility — server/router/fileserver/fileserver.go:650 (logic at :677 and :699)
RSS feed generation — feeds restricted to `VisibilityList: {store.Public}` — server/router/rss/rss.go:90 and server/router/rss/rss.go:141
Real-time SSE event delivery — `SSEClient.canReceive` filters events by `event.Visibility` before pushing to a subscriber — server/router/api/v1/sse_hub.go:134 (switch at :135)

Notes / related (not "view a memo" itself but visibility-gated access to memo-adjacent actions, so listed separately): reaction read/access checks at server/router/api/v1/reaction_service.go:30-38, attachment-listing checks at server/router/api/v1/attachment_service.go:445-451 and server/router/api/v1/memo_attachment_service.go:214-222, and comment access at server/router/api/v1/memo_service_comments.go:41.
