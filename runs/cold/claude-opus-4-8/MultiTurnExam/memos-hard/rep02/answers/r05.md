**Premise correction: There is no GraphQL schema — this project exposes no GraphQL API.** A repo-wide search finds no GraphQL: no `.graphql`/`.graphqls` schema files, no `gqlgen`/`graphql-go` dependency, and no resolvers. (The only `grep` hits for "resolver" are `net.DefaultResolver.LookupHost` DNS calls in `internal/webhook/webhook.go:65` and `internal/httpgetter/html_meta.go:23` — unrelated.)

**Actual API surface:** The public API is defined as **Protocol Buffers (gRPC), served over Connect and gRPC-Gateway (REST/JSON)**. The schema lives in `.proto` files under `proto/api/v1/`:
- `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus `common.proto`.

These generate the Go stubs in `proto/gen/api/v1/` (including the gRPC-Gateway `*.pb.gw.go` REST handlers). At runtime the services are wired up in `server/router/api/v1/v1.go` — a Connect handler with interceptors (`v1.go:133-141`) and a gRPC-Gateway mux (`v1.go:95-97`). So the "public API" is gRPC/Connect + a REST gateway defined by protobuf, not GraphQL.
