**Premise correction: Neither — there is no external message broker (no NATS, no RabbitMQ, no AMQP/Kafka) anywhere in this codebase.** A repo-wide search over the Go sources for `nats`, `rabbitmq`, `amqp`, `kafka`, `broker` returns nothing, and `go.mod` declares no such dependency.

**Actual mechanism:** Webhook delivery uses an **in-process, buffered Go channel** as its work queue, drained by goroutine workers within the same server process — all in `internal/webhook/webhook.go`:

- The "queue" is a buffered channel declared at package level: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`) — capacity 128, in-memory only.
- Workers: an `init()` spawns **4 goroutines**, each ranging over the channel and calling `Post` for every payload (`internal/webhook/webhook.go:43-53`).
- Producers enqueue via `PostAsync`, which does a non-blocking send `case asyncPostQueue <- requestPayload:` and drops the event (with a warning) if the buffer is full (`internal/webhook/webhook.go:190`).

So there is no broker to consume from and no queue "declared" in any messaging system — the queue is a Go channel local to the process, and delivery is handled by in-process worker goroutines. (Note this means queued webhooks are not durable and are lost on restart.)
