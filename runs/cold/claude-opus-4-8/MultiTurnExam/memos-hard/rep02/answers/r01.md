**Premise correction:** There is no Redis anywhere in this codebase — the cache layer is not backed by Redis (a repo-wide `grep -i redis` over the Go sources returns nothing). So there is no "Redis connection" to configure.

**Actual mechanism:** The cache is a custom **in-process, in-memory TTL cache** implemented in `store/cache/cache.go` (a `map`-backed store with a background cleanup goroutine; interface at `store/cache/cache.go:10`, config at `:40`). There is no external connection or DSN — it lives inside the server process.

- **Where it's configured:** `store.New` builds a single `cache.Config` and instantiates the caches with it — `store/store.go:40-53`. The user cache is `userCache: cache.New(cacheConfig)` (`store/store.go:52`).
- **TTL for user entries:** **10 minutes.** The config sets `DefaultTTL: 10 * time.Minute` (`store/store.go:41`), and user entries are written via `s.userCache.Set(...)` (`store/user.go:167`), which applies the default TTL (the interface's `Set` = "default TTL", `store/cache/cache.go:12`). Supporting defaults: `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:42-43`); the same 10-minute default also appears in `cache.DefaultConfig()` at `store/cache/cache.go:58`.

So: no Redis; user cache entries expire after a 10-minute TTL in an in-memory cache configured in `store/store.go`.
