- **Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (defined at line 156, wired into the main transport at line 188). It attaches `Authorization: Bearer <token>` headers and, on a 401, transparently refreshes and retries. Supporting token state lives in `web/src/auth-state.ts` (in-memory access token, persisted under `localStorage` key `memos_access_token`, shared across tabs via `BroadcastChannel`), and `refreshAccessToken`/`refreshAuthClient` call `AuthService.refreshToken`.

- **Token kinds:** a short-lived **access token** (JWT, sent as a `Bearer` header, held in memory/localStorage) and a **refresh token** (managed server-side via the `AuthService.RefreshToken` RPC / cookie, used to mint new access tokens). The backend also validates **personal access tokens (PAT)**.

- **Backend validation package:** `server/auth/` (package `auth`) — the `Authenticator` in `server/auth/authenticator.go` validates access tokens (`AuthenticateByAccessTokenV2`), refresh tokens (`AuthenticateByRefreshToken`), and PATs (`AuthenticateByPAT`), with JWT logic in `server/auth/token.go`.
