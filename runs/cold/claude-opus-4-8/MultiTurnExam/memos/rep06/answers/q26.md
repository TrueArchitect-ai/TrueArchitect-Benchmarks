**memo, memo_relation, attachment**

When `DeleteMemo` runs, the explicit cascade code in `store/memo.go` (`Store.DeleteMemo`) deletes:
- `memo_relation` rows (both where the memo is source `MemoID` and target `RelatedMemoID`)
- `attachment` rows linked to the memo (via `DeleteAttachment`)
- the `memo` row itself (via `driver.DeleteMemo`)

The API handler (`server/router/api/v1/memo_service.go:518`) additionally deletes comment memos, but those go through the same `Store.DeleteMemo`, hitting the same three tables.

Note: `reaction` rows are only *listed* (for the webhook payload) in the delete handler, not deleted — so the reaction table is not affected by explicit cascade code.
