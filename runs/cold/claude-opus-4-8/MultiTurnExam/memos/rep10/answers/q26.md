When `DeleteMemo` runs, these tables are affected:

- **memo** — the memo row itself (and, at the API layer, any comment memos which are deleted the same way) — `store/memo.go:158`, `server/router/api/v1/memo_service.go:573-577`
- **memo_relation** — rows where the memo is source or target — `store/memo.go:142,145`
- **attachment** — attachments linked to the memo — `store/memo.go:149-157` (via `Store.DeleteAttachment`, which also removes the underlying storage file, not a table)
- **memo_share** — deleted by DB-level FK cascade `ON DELETE CASCADE` on `memo_id` — `store/migration/sqlite/LATEST.sql:109`

(Reactions are listed for the webhook payload but are **not** deleted, and the `reaction` table has no cascade referencing `memo`.)
