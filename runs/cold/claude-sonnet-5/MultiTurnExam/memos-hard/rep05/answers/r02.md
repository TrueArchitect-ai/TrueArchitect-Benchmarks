r02. **Premise correction**: There is no per-user API rate-limiting middleware in this codebase. A repo-wide search for rate-limiting/throttling logic (`rate.?limit|ratelimit|throttle`) turns up only a single aspirational doc comment — `// - Rate limit email sending to prevent abuse` in `internal/email/doc.go:86` — which is not backed by any implementation. `golang.org/x/time` (the package that would typically provide a token-bucket limiter) appears only as an *indirect* transitive dependency in `go.mod:151`, never imported or used directly anywhere.

The only middleware registered on the Echo server (`server/server.go:51-52`) is `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`); the frontend router additionally registers static-file and SPA-fallback middleware (`server/router/frontend/frontend.go:54,59`). None of these enforce request limits.

The closest things to "limits" in the codebase are concurrency-bounding semaphores — `thumbnailSemaphore`/`imageProcessingSemaphore` in `server/router/api/v1/v1.go:40-41,59-60` and `thumbnailSemaphore` in `server/router/fileserver/fileserver.go:107,116` — but these cap concurrent in-flight thumbnail/image-processing work process-wide, not per-user request rates over time, and aren't wired as HTTP middleware.
