r04. **Premise correction**: Neither — this codebase has no message broker at all. There's no NATS or RabbitMQ dependency in `go.mod`/`go.sum`, and no AMQP/NATS client code anywhere.

**Actual mechanism**: Webhook delivery is handled entirely in-process. `internal/webhook/webhook.go` declares a buffered Go channel, `asyncPostQueue := make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`), which functions as the "queue." Four worker goroutines are spawned in the package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post(payload)` (line 46) to deliver the webhook. Producers enqueue work via `PostAsync`, which does a non-blocking `select` send on `asyncPostQueue` and drops the payload (logging a warning) if the channel is full (`internal/webhook/webhook.go:184-196`). There's no external broker, persistence, or cross-process queue — it's all in-memory within the single server process.
