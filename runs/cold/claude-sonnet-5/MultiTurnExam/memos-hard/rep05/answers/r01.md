r01. **Premise correction**: This repository has no Redis dependency at all — no `redis` import, client, or config exists anywhere in the codebase (checked `go.mod`/`go.sum` and all `.go` sources). There is no Redis-backed cache layer to configure.

**Actual mechanism**: The cache layer is a custom, thread-safe **in-memory** cache — `Cache` in `store/cache/cache.go` (backed by `sync.Map` with a background `cleanupLoop` goroutine, `store/cache/cache.go:66-90,199-215`). It is instantiated per `Store` (not via any external connection) in `New` at `store/store.go:38-58`, which creates three separate in-process cache instances: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29,51-53`).

**TTL for user entries**: The `userCache` uses the same default `cache.Config` as the others — `DefaultTTL: 10 * time.Minute` (`store/store.go:41`, mirrored as the package default in `store/cache/cache.go:59`), with expired entries swept by a `CleanupInterval` of `5 * time.Minute` (`store/store.go:42`).
