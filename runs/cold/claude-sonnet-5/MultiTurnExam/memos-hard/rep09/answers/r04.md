**Premise correction:** Neither. There is no message broker (NATS, RabbitMQ, or otherwise) involved in webhook delivery anywhere in this codebase — no imports of any NATS/RabbitMQ/AMQP/Kafka client library exist in the repo.

**Actual mechanism:** Webhook dispatch uses a plain in-process Go channel as a bounded work queue, not an external broker. It's declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four long-running goroutines are started in `init()` (`internal/webhook/webhook.go:42-55`) that range over `asyncPostQueue` and call `Post` (`internal/webhook/webhook.go:120`) for each payload — these are the "delivery workers." Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send (`select`/`default`) and drops the payload with a log warning if the channel's 128-item buffer is full. This queue lives entirely in the memory of a single server process — it isn't durable, isn't shared across instances, and has no external broker or persistent queue declaration behind it.
