**Premise correction:** There is no Redis anywhere in this repository — a repo-wide search of Go source and `go.mod` turns up zero references to Redis. The cache layer is not backed by an external cache store at all.

**Actual mechanism:** Caching is implemented as an in-process, thread-safe in-memory cache: `store/cache/cache.go` (`Cache` type, built on `sync.Map` with a background `cleanupLoop` goroutine for expiry, `store/cache/cache.go:66-90,199-215`). The store package instantiates three separate instances of it — `instanceSettingCache`, `userCache`, and `userSettingCache` — in `store/store.go:27-29`, constructed in `store.New` at `store/store.go:38-55`.

**TTL for user entries:** `userCache` is created with the same `cacheConfig` as the others, set in `store/store.go:40-45`: `DefaultTTL: 10 * time.Minute` (with `CleanupInterval: 5 * time.Minute` sweeping expired entries and `MaxItems: 1000` as an eviction cap). This default TTL is applied whenever a user is cached via `Cache.Set` (`store/cache/cache.go:92-95`, which calls `SetWithTTL` with `c.config.DefaultTTL`).
