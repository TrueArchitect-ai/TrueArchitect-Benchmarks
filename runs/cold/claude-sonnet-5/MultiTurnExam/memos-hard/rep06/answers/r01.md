**Premise correction:** There is no Redis in this codebase — no import, dependency, or connection config for Redis exists anywhere (`go.mod` has no Redis client, and a repo-wide search for "redis" returns nothing). The cache layer is a self-contained, in-memory Go cache, not a Redis-backed one.

**Actual mechanism:** The cache is implemented in `store/cache/cache.go` — a thread-safe in-memory cache (`sync.Map` + atomic counters, `cache.Cache`) with a background goroutine (`cleanupLoop`, `cache.go:200-215`) that periodically evicts expired entries. It's instantiated per `Store` in `store/store.go:38-58`, which creates three separate cache instances — `instanceSettingCache`, `userCache`, `userSettingCache` — all using the same default `cache.Config` (`store/store.go:40-45`).

**TTL for user entries:** The `userCache` uses `DefaultTTL: 10 * time.Minute` (`store/store.go:41`, matching `cache.DefaultConfig()` at `store/cache/cache.go:57-64`), with a cleanup sweep every 5 minutes (`CleanupInterval: 5 * time.Minute`) and a cap of 1000 items (`MaxItems: 1000`).
