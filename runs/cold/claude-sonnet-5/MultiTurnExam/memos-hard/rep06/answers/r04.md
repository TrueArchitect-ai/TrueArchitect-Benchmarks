**Premise correction:** Neither. There is no message broker (NATS, RabbitMQ, or any other) in this codebase — no such dependency exists in `go.mod`, and a repo-wide search for "nats", "rabbitmq", "amqp", "broker", or "queue" (as a broker concept) turns up nothing of that kind.

**Actual mechanism:** As established earlier, webhook delivery uses an in-process, in-memory Go channel as its "queue" — `asyncPostQueue := make(chan *WebhookRequestPayload, 128)`, declared in `internal/webhook/webhook.go:39`. It's a buffered channel (capacity 128), not backed by any external broker. Four worker goroutines consume from it, started in `init()` at `internal/webhook/webhook.go:42-55`, each looping `for payload := range asyncPostQueue { Post(payload) ... }`. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send (`select`/`default`) and drops the payload with a warning log if the channel is full — there's no persistence or durability beyond process memory.
