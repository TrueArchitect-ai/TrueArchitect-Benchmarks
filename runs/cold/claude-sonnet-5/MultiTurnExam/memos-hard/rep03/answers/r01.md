**Premise correction**: There is no Redis anywhere in this codebase — a repo-wide search for "redis"/"Redis"/"go-redis" (including `go.mod`/`go.sum`) returns zero hits. The cache layer is a self-contained in-memory cache, not a Redis client.

**Actual mechanism**: `store/cache/cache.go` implements a thread-safe in-memory cache (`Cache` struct backed by `sync.Map` with atomic item counting, a background `cleanupLoop` goroutine, and size-based eviction). It is instantiated in `store/store.go:38-58` — `Store.New` builds a `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000}` (lines 40-45) and creates three separate in-process cache instances from it: `instanceSettingCache`, `userCache`, and `userSettingCache` (lines 51-53).

**User entry TTL**: 10 minutes — `userCache.Set` (e.g. `store/user.go:98,122,132,143,167`) uses the default `Set` method (`store/cache/cache.go:93-95`), which applies `cacheConfig.DefaultTTL`, i.e. the 10-minute value set at `store/store.go:41`. Entries are also proactively purged by the periodic `cleanupLoop` every 5 minutes (`CleanupInterval`, `store/store.go:42`).
