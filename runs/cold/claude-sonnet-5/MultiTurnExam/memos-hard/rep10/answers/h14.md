h14.

**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74-88`. It calls `markdownService.ExtractAll(memo.Content)` (the `*service` implementation at `internal/markdown/markdown.go:356`, which internally walks the parsed goldmark AST via `ExtractTags`/`ExtractProperties`, e.g. `internal/markdown/markdown.go:143` and `:193`), then stores the result into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers (recomputation):**
- `APIV1Service.CreateMemo` on every new memo — `server/router/api/v1/memo_service.go:108`.
- `APIV1Service.UpdateMemo`, but only when the update mask includes the `content` field path — `server/router/api/v1/memo_service.go:447`.
(There's also a dormant `memopayload.Runner.RunOnce` batch job that rebuilds the payload for every memo, but per prior analysis it's never wired up/called from production code — `server/runner/memopayload/runner.go:27`.)

**Extracted properties** (via `internal/markdown.ExtractedData`, `internal/markdown/markdown.go:21-25`):
- `Tags` — all `#tag` occurrences in the content (`ExtractTags`, `internal/markdown/markdown.go:143`).
- `Property` (`storepb.MemoPayload_Property`, built by `ExtractProperties`, `internal/markdown/markdown.go:193-241`) — a first-H1 `Title`, `HasLink`, `HasCode` (code blocks/spans), `HasTaskList`, and `HasIncompleteTasks` (unchecked task items).

Mentions are also parsed by the markdown service but are not persisted into `MemoPayload` by `RebuildMemoPayload` — only `Tags` and `Property` are written back.
