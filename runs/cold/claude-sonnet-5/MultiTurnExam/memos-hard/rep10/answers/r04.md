**Premise correction:** This codebase uses neither NATS nor RabbitMQ (nor any message broker at all) — `go.mod` and a full-source grep for "nats"/"rabbitmq"/"amqp" return zero hits.

**Actual mechanism:** Webhook delivery is handled entirely in-process with a Go buffered channel. `internal/webhook/webhook.go:39` declares `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a 128-item in-memory queue, not a broker-backed one. Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over `asyncPostQueue` and call `Post` for each payload. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send and drops (with a logged warning) if the queue is full. Everything lives within the single server process — there's no external broker, connection, or queue declaration to point to.
