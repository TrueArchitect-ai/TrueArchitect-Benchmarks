**Computation site:** `RebuildMemoPayload` — `server/runner/memopayload/runner.go:74-88`. It calls `markdownService.ExtractAll([]byte(memo.Content))` (line 80), then sets `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (lines 85-86). The actual parsing/extraction happens in `(*service).ExtractAll` in `internal/markdown/markdown.go` (single-pass goldmark AST walk), backed by `ExtractTags` and `ExtractProperties` (`internal/markdown/markdown.go:193-241`).

**Triggers (what causes recomputation):**
- `CreateMemo` RPC handler — `server/router/api/v1/memo_service.go:108` — every new memo.
- `UpdateMemo` RPC handler, only when the `content` field is present in the update mask — `server/router/api/v1/memo_service.go:447` (inside the `if path == "content"` branch, `server/router/api/v1/memo_service.go:436-449`); editing other fields (visibility, pinned, etc.) does not recompute it.
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:56` — internally calls `s.CreateMemo`, so comments (which are stored as memos) get the same treatment.
- Also reachable via the (currently unwired) `memopayload.Runner.RunOnce` batch job (`server/runner/memopayload/runner.go:27-72`), which would recompute payloads for all memos if ever run — see h08.

**Extracted properties** (`internal/markdown.ExtractedData`, `internal/markdown/markdown.go:21-25`, of which `RebuildMemoPayload` persists `Tags` and `Property`):
- `Tags []string` — all `#tag` occurrences in the content.
- `Property *storepb.MemoPayload_Property` — derived booleans/metadata from the AST walk: `Title` (text of a leading H1 heading), `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks`.
- (`Mentions []string` is also part of `ExtractedData` but is not copied into `memo.Payload` by `RebuildMemoPayload` — only `Tags` and `Property` are persisted.)
