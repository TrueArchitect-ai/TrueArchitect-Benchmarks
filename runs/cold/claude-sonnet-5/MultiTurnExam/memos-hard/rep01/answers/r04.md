**Premise correction:** Neither. There is no message broker (NATS, RabbitMQ, or any other) in this codebase — a search of `go.mod` and all `.go` files for "nats", "rabbitmq", or "amqp" turns up nothing.

**Actual mechanism:** Webhook delivery is queued via a plain in-process Go buffered channel, not an external broker. It's declared in `internal/webhook/webhook.go:38`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

`PostAsync` (`internal/webhook/webhook.go:184`) enqueues payloads onto this channel (non-blocking — it drops and logs a warning if the channel is full). Four worker goroutines, spawned in the package `init()` (`internal/webhook/webhook.go:42-49`), range over `asyncPostQueue` and call `Post` (`internal/webhook/webhook.go:120`) to actually deliver each webhook over HTTP. This lives entirely in the server's own process memory — nothing is persisted or shared across processes, so it doesn't survive a restart.
