Confirmed — `DeleteReaction` is never invoked from the memo-deletion path, so reactions are not cascaded.

q26. `memo`, `memo_relation`, `attachment`

- `memo` — the memo row itself (`store/db/sqlite/memo.go:237`, `Store.DeleteMemo`), plus recursively for each comment memo found via `memo_relation` (handler `server/router/api/v1/memo_service.go:566-577`)
- `memo_relation` — deleted for the memo as both source and target (`store/memo.go:142-147`)
- `attachment` — deleted for each attachment linked to the memo (`store/memo.go:148-157`, via `Store.DeleteAttachment`)

Note: `reaction` rows referencing the memo are listed (for the webhook payload) but are **not** deleted — there's no explicit `DeleteReaction` call in the delete path and no DB-level cascade (`reaction.content_id` in `store/migration/sqlite/LATEST.sql:96` is a plain `TEXT` column, not a foreign key), so they become orphaned.
