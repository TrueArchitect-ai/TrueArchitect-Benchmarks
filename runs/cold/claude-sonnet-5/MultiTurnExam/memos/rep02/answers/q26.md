q26. Tables affected when `Store.DeleteMemo` runs (`store/memo.go:140-159`):

- **`memo`** — the row itself is deleted (direct)
- **`memo_relation`** — explicit cascade in Go: rows where the memo is `memo_id` or `related_memo_id` are deleted before the memo row
- **`attachment`** — explicit cascade in Go: attachments linked via `memo_id` are deleted (row removed, plus underlying storage) via `Store.DeleteAttachment`
- **`memo_share`** — cascaded at the SQL schema level via `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`)

Note: other memo-referencing tables like `reaction` (keyed by `content_id`, no FK) are not covered by any cascade found in the schema or `DeleteMemo` code.
