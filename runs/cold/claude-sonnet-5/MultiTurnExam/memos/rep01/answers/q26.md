q26. Tables affected when `Store.DeleteMemo` runs (store/memo.go:140-158):

- **memo** — the row itself is deleted (direct)
- **memo_relation** — explicitly deleted for both directions (memo as source and as related/target) before the memo row is removed (direct, explicit cascade code)
- **attachment** — explicitly looked up via `ListAttachments` and deleted one-by-one via `DeleteAttachment` before the memo row is removed (direct, explicit cascade code)
- **memo_share** — has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (store/migration/postgres/LATEST.sql:108), so rows are removed automatically by the database when the memo is deleted (DB-level cascade, not explicit Go code)

Note: `reaction` rows reference memos via a generic `content_id` (no foreign key to `memo`), so they are not automatically cascaded or explicitly cleaned up in `DeleteMemo`.
