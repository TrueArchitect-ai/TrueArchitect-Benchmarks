q25. CEL (Common Expression Language) engine at internal/filter/engine.go (Engine, using google/cel-go); mechanism: internal/filter/render.go

`Engine.Compile` (`internal/filter/engine.go`) parses the CEL filter string into a dialect-agnostic `Condition` tree via `cel-go`. Each store dialect driver (e.g. `store/db/postgres/memo.go:54-58`) obtains the default engine via `filter.DefaultEngine()` and calls `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectPostgres/...MySQL/...SQLite, &where, &args)`, which in turn uses `internal/filter/render.go` to render that condition tree into dialect-specific SQL fragments (switching on `DialectSQLite`/`DialectMySQL`/`DialectPostgres` for things like `ILIKE` vs `LIKE`, `jsonb_array_elements_text` vs `json_each` vs `JSON_TABLE`, date functions, etc.) plus parameterized args appended to the query's WHERE clause.
