**RPC handlers** (in `server/router/api/v1/`, part of the Connect-RPC/gRPC `MemoService` implementation) that transitively trigger an outbound HTTP request to a user-configured webhook URL:

1. `CreateMemo` — `server/router/api/v1/memo_service.go:70` → calls `s.DispatchMemoCreatedWebhook` (`memo_service.go:157`)
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:401` → via `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66-67`) → calls `s.DispatchMemoUpdatedWebhook`
3. `DeleteMemo` — `server/router/api/v1/memo_service.go:518` → calls `s.DispatchMemoDeletedWebhook` (`memo_service.go:562`)
4. `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20` → calls `s.DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`)

(`SetMemoAttachments`/`SetMemoRelations` also reach the same path indirectly via `dispatchMemoUpdatedSideEffects`.)

**Call chain:** each handler → its `Dispatch*Webhook` method → `dispatchMemoRelatedWebhook`/inline logic in `server/router/api/v1/memo_service_webhooks.go` (fetches the user's stored webhook URLs via `s.Store.GetUserWebhooks`) → `webhook.PostAsync` (`internal/webhook/webhook.go:184`, enqueues onto `asyncPostQueue`) → worker goroutine (`internal/webhook/webhook.go:42-55`) invokes the same function that a synchronous call would use.

**Convergence function — path:** `Post` — `internal/webhook/webhook.go:120` (`func Post(requestPayload *WebhookRequestPayload) error`). This is the single point where all paths (direct or via `PostAsync`'s queue) funnel through immediately before the actual outbound call, `safeClient.Do(req)`, at `internal/webhook/webhook.go:152`.

(Note: the user-supplied webhook URL is persisted via `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`, which validates but does not itself dispatch — the four handlers above are what cause delivery to that URL.)
