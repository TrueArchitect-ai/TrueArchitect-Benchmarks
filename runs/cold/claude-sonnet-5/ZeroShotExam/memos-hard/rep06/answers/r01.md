**Premise correction:** There is no Redis anywhere in this codebase (`memos`, a Go application). A repo-wide search for "redis" returns zero hits, and there is no Redis client dependency, connection config, or Docker/Compose service for it.

**Actual mechanism:** The cache layer is an in-process, thread-safe in-memory cache implemented in `store/cache/cache.go`, not Redis. It's a simple `map`-backed store with TTL expiration and a background cleanup goroutine (no external service or network connection at all).

User entries specifically go through `userCache`, one of three caches instantiated in `store/store.go:27-53`. It's constructed via `cache.New(cacheConfig)` with `cacheConfig.DefaultTTL: 10 * time.Minute` (`store/store.go:41`). Calls in `store/user.go` (lines 98, 122, 132, 143, 167) use `s.userCache.Set(ctx, userCacheKey(user.ID), user)` — the plain `Set` method, which per `store/cache/cache.go:92-94` applies the cache's `DefaultTTL` rather than a custom `SetWithTTL` duration.

So: user entries are cached in-memory for **10 minutes**, configured at `store/store.go:41`, with the cache mechanics defined in `store/cache/cache.go`.
