r02. Premise correction: this repository has no per-user API rate-limiting middleware to point to.

This is the "memos" Go backend, which uses Connect RPC interceptors (not Express/Koa-style middleware) as its request-handling chain. That chain is registered in `server/router/api/v1/v1.go` (~lines 133-141) via `connect.WithInterceptors(...)`, and consists of exactly four interceptors defined in `server/router/api/v1/connect_interceptors.go`:

- `MetadataInterceptor` — converts HTTP headers to gRPC metadata
- `LoggingInterceptor` — request logging
- `RecoveryInterceptor` — panic recovery
- `AuthInterceptor` — authentication/authorization

None of these throttle or limit request rates, and there's no per-user, per-IP, or global rate limiter elsewhere in the codebase (checked auth/session handling, and any reverse-proxy config — there is none). The only "rate limit" mentions in the repo are unrelated: an illustrative code snippet and a comment in `internal/email/README.md` and `internal/email/doc.go` about rate-limiting *outbound email*, not API requests — and that's documentation only, not implemented code. `golang.org/x/time` appears in `go.mod` but only as an unused indirect dependency, so it isn't backing any limiter either.

So there's no answer to "where is it registered / what are its limits" because the feature doesn't exist in this codebase.
