**Delivery function** — `Post` (and its async wrapper `PostAsync`) in `internal/webhook/webhook.go:120` (dispatch loop calling it: `internal/webhook/webhook.go:42-55`). It builds the HTTP request and sends it via a shared `safeClient` (`internal/webhook/webhook.go:32`).

**Protection mechanism** — SSRF protection happens at two layers, both in `internal/webhook/`:
- `safeDialContext` (`internal/webhook/webhook.go:59`), installed as the `DialContext` on `safeClient`'s `http.Transport` (`internal/webhook/webhook.go:32-37`). At actual dial time it resolves the target hostname and rejects the connection if any resolved IP is reserved/private — this is what defeats DNS-rebinding (a hostname that resolves safely at validation-time but to an internal IP at request-time).
- `ValidateURL` / `isReservedIP` in `internal/webhook/validate.go:44` and `:62`, which pre-validate a webhook URL (scheme + hostname resolution against `reservedCIDRs`: loopback, RFC-1918 private ranges, link-local/cloud IMDS `169.254.169.254`, and IPv6 equivalents) when a webhook is created/updated.

Both checks can be disabled via the `AllowPrivateIPs` package variable (`internal/webhook/validate.go:41`) for self-hosted deployments that intentionally target local-network services.
