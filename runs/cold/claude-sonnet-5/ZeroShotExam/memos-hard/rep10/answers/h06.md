In each case the dispatch helper pulls the destination from `hook.Url`, the user-configured webhook URL stored per-user (`GetUserWebhooks`).

**Convergence function** — `Post(requestPayload *WebhookRequestPayload) error` at `internal/webhook/webhook.go:120`.

All the above paths funnel through the async wrapper `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a worker pool that ultimately calls `Post`. `Post` is where `http.NewRequest("POST", requestPayload.URL, …)` (webhook.go:126) and `safeClient.Do(req)` (webhook.go:152) actually issue the outbound request to the user-supplied URL — using the package-level `safeClient` (webhook.go:32, explicitly commented as "the shared HTTP client used for all webhook dispatches") with an SSRF-guarded dialer.

(Note: there's a second, separate user-URL path — the SSO/OAuth2 identity-provider flow, e.g. `SignIn` in `auth_service.go:80` and `CreateUserAccessBinding` in `user_service_identities.go:56`, both via `resolveSSOIdentity` in `auth_service_sso.go:104` — but that uses its own inline `http.Client` in `internal/idp/oauth2/oauth2.go:84`, not the webhook convergence point.)
