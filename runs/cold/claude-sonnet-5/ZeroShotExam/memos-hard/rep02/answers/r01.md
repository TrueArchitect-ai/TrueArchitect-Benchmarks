Premise correction: this repository (Memos) has no Redis integration at all — there is no `redis` reference anywhere in the codebase (checked via `grep -ril "redis"` across the full repo, zero hits), no Redis client dependency in `go.mod`/`web/package.json`, and no Redis service in any Docker/compose config.

Actual mechanism: the "cache layer" that exists is client-side only, not Redis-backed:
- `web/src/components/MemoEditor/services/cacheService.ts` — an in-browser cache for the memo editor (draft/edit state), tested by `web/tests/memo-editor-cache.test.ts`.
- `web/src/lib/query-client.ts` — a TanStack Query client configuring in-memory query caching/staleness for API responses (this is the closest thing to a "TTL for user entries," but it governs client-side query freshness, not server-side Redis key expiry).

There is no server-side Redis connection configuration file, no `REDIS_URL`/`REDIS_ADDR` env var usage, and no TTL applied to "user entries" in a Redis sense anywhere in this repo.
