**Premise correction:** There is no Redis anywhere in this repository (usememos/memos). A repo-wide search for "redis" turns up zero matches, and there's no Redis client dependency, connection string, or config option.

**Actual mechanism:** The "cache layer" is an in-process, thread-safe in-memory Go cache, not an external Redis instance:

- Implementation: `store/cache/cache.go` — a `sync.Map`-backed cache with per-item expiration and a background cleanup goroutine (`cleanupLoop`).
- Instantiation/config: `store/store.go:38-53` — `Store.New()` builds a `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000, OnEviction: nil}` and creates three separate `*cache.Cache` instances from it: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`).
- User entries specifically: `store/user.go` calls `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. lines 98, 122, 132, 143, 167) — the plain `Set` method, not `SetWithTTL`, so it inherits the store's default TTL of **10 minutes** (`store/cache/cache.go:46-63`, `Set` → `SetWithTTL(ctx, key, value, c.config.DefaultTTL)`). Entries are also explicitly invalidated on delete via `s.userCache.Delete(...)` in `store/user_delete.go:40`.
