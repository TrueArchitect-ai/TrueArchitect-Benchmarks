delivery function — `Post` (dispatched synchronously) and `PostAsync` (queues to `asyncPostQueue`, drained by workers calling `Post`), both in `internal/webhook/webhook.go` (`Post` at internal/webhook/webhook.go:120, `PostAsync` at internal/webhook/webhook.go:184); the actual outbound HTTP call happens via `safeClient.Do(req)` at internal/webhook/webhook.go:152.

protection mechanism — SSRF protection is enforced at two layers in `internal/webhook/`:
- Dial-time guard: `safeDialContext` (internal/webhook/webhook.go:59-77), installed as the `DialContext` of the shared `safeClient`'s `http.Transport` (internal/webhook/webhook.go:32-37). It resolves the target host and rejects the connection if any resolved IP is reserved/private, which also prevents DNS-rebinding bypasses.
- Pre-flight validation: `ValidateURL` (internal/webhook/validate.go:62-83), called when a webhook URL is registered/updated, which resolves the hostname and rejects reserved/private IPs before the URL is ever saved.

Both rely on `isReservedIP` (internal/webhook/validate.go:44-54) checking against `reservedNetworks`/`reservedCIDRs` (internal/webhook/validate.go:14-26), covering loopback, RFC-1918 private ranges, link-local/cloud IMDS (169.254.0.0/16), and their IPv6 equivalents. Note there's an escape hatch: package-level var `AllowPrivateIPs` (internal/webhook/validate.go:41) disables this protection entirely when set to `true`.
