**1st: User; 2nd: Memo** (rough package counts: User ~7 packages, Memo ~6 packages outside `store`)

The data layer is the `store` package (`store/*.go`), which defines the persistent entity types `User`, `Memo`, `Attachment`, `Reaction`, `Inbox`, `IdentityProvider`, `MemoRelation`, `MemoShare`, `UserSetting`, `UserIdentity`, and `InstanceSetting` (see e.g. `store/user.go:29`, `store/memo.go:35`, `store/attachment.go:16`, `store/reaction.go:7`, `store/inbox.go:24`, `store/idp.go:12`, `store/memo_relation.go:16`, `store/memo_share.go:6`, `store/user_setting.go:13`, `store/user_identity.go:8`, `store/instance_setting.go:14`).

Searching all Go source for `store.<Type>` and grouping matches by importing package/directory (excluding `store`'s own sub-packages `store/db/*`, `store/test`, `store/cache`, `store/seed`, `store/migration`, which implement the data layer itself), `store.User` is used from the most distinct packages:

- `server/auth`
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/fileserver`
- `server/router/frontend`
- `server/router/rss`

(7 packages)

`store.Memo` comes next, used from:

- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/frontend`
- `server/router/rss`
- `server/runner/memopayload`

(6 packages)

All other entity types (`Attachment`, `Inbox`, `MemoShare`, `MemoRelation`, `Reaction`, `UserIdentity`, `IdentityProvider`, `UserSetting`, `InstanceSetting`) are referenced from fewer outside packages (mostly just `server/router/api/v1` plus one or two others), so `User` and `Memo` are clearly the top two — consistent with `User` and `Memo` being the two most fundamental domain entities (auth, notifications, RSS, fileserver, frontend routing, and API all touch users; memos are touched by fewer but still several subsystems).
