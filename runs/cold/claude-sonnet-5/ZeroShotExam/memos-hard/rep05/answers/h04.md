Yes; evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14-32`, which switches on `profile.Driver` and calls `mysql.NewDB(profile)` for the `"mysql"` case (store/db/db.go:21-22). This is the only production call site of `mysql.NewDB` — no other file imports `store/db/mysql` for production use.
- However, the MySQL driver is constructed directly outside that factory in test code:
  - `store/db/mysql/auth_config_test.go:12` — `db := &DB{}`, directly instantiating the `mysql.DB` struct, bypassing `NewDB` entirely.
  - `store/test/containers.go:145` — `sql.Open("mysql", dsn)`, a raw `database/sql` MySQL connection (driver registered via `mysqldriver "github.com/go-sql-driver/mysql"`, containers.go:16) used to spin up per-test databases in a MySQL testcontainer, also independent of `mysql.NewDB`/`NewDBDriver`.

So while no production code path constructs the MySQL driver directly outside the factory, test/test-infrastructure code does construct it (or the underlying `go-sql-driver/mysql`) directly in two places.
