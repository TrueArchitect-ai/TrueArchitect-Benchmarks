**Delivery function** — `Post` (and its async wrapper `PostAsync`) in `internal/webhook/webhook.go:120` (dispatch loop that calls it: `internal/webhook/webhook.go:42-55`). It builds the HTTP request and sends it via a shared `safeClient` (`internal/webhook/webhook.go:32`).

**Protection mechanism** — SSRF protection is enforced at two layers, both in the `internal/webhook` package:
- `safeDialContext` — `internal/webhook/webhook.go:59` — a custom `net.Dialer.DialContext` installed as the `http.Client`'s `Transport.DialContext` (`webhook.go:35`), which resolves the hostname at *dial time* and rejects any resolved IP that falls in a reserved/private range (this closes the DNS-rebinding gap that a pre-request-only check would miss).
- `isReservedIP` / `ValidateURL` — `internal/webhook/validate.go:44` and `internal/webhook/validate.go:62` — check resolved IPs against `reservedNetworks` (loopback, RFC-1918 private ranges, link-local incl. cloud IMDS `169.254.169.254`, and IPv6 equivalents), defined in `internal/webhook/validate.go:14-23`. `ValidateURL` is used for upfront validation when a webhook URL is registered/updated (e.g. from `server/router/api/v1/user_service_webhooks.go`), while `safeDialContext` re-enforces the same `isReservedIP` check on every actual outbound connection.

Note: this protection can be disabled via the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for self-hosted deployments targeting local-network services.
