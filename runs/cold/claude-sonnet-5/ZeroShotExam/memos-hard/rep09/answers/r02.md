Premise correction: there is no per-user API rate-limiting middleware in this repository (`usememos/memos`), so it cannot be located or its limits described.

What actually exists, confirmed by grepping the whole codebase (`server/`, `internal/`, `web/`, `proto/`, `go.mod`) for `rate limit`, `throttle`, `RateLimiter`, `limiter`, etc.:

- `server/server.go` — the Echo HTTP server only registers `middleware.Recover()` (panic recovery) and a custom CORS middleware (`server/cors.go`). No rate limiter.
- `server/router/api/v1/v1.go` — the Connect RPC handler chain wires exactly four interceptors: `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, and `NewAuthInterceptor()` (auth only, no throttling).
- The gRPC-Gateway REST routes apply `http.MaxBytesHandler` with `maxAPIRequestBytes` — that's a request **body size** cap, not a request-count/time-window rate limit.
- The only other mention is illustrative, non-functional example code in `internal/email/README.md` suggesting a developer *could* rate-limit email sending with `golang.org/x/time/rate` — that package isn't even imported in `go.mod`, and it concerns outbound email, not inbound API requests.

So there's no per-user (or any other) request-count/time-window rate-limiting middleware registered anywhere in this codebase, and no configured limits to report.
