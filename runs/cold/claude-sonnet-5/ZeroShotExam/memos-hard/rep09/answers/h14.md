**Computation site:**
- Persisted metadata (tags + property flags): `internal/markdown/markdown.go:356` — `(*service).ExtractAll()`, invoked via `RebuildMemoPayload()` in `server/runner/memopayload/runner.go:74`, which writes results onto `memo.Payload.Tags` and `memo.Payload.Property`. - Non-persisted preview text (snippet): `internal/markdown/markdown.go:264` — `GenerateSnippet()`, wrapped by `getMemoContentSnippet()` in `server/router/api/v1/memo_service_webhooks.go:83`, and applied when converting a store memo to its API representation in `server/router/api/v1/memo_service_converter.go:76` (also used at lines 225/248 for relation previews).

**Triggers:**
- `CreateMemo` (`server/router/api/v1/memo_service.go:108`) calls `memopayload.RebuildMemoPayload` before the memo is persisted.
- `UpdateMemo` (`server/router/api/v1/memo_service.go:447`) calls it again, but **only** when `content` is among the paths in the request's `update_mask` — editing other fields (visibility, pinned, etc.) does not retrigger extraction.
- A batch maintenance job, `Runner.RunOnce()` (`server/runner/memopayload/runner.go:27`), pages through all memos and rebuilds each payload — useful for backfilling after logic changes (note: this runner isn't currently wired into `server.go` startup, so it's dead/available code rather than an active cron trigger).
- The snippet is not stored at all — it's recomputed on every read, i.e. every time `convertMemoFromStoreWithCreators` (list/get responses), memo-relation lookups, or notification/webhook payload builders serialize a memo from `store.Memo` to the API model.

**Extracted properties:**
- `Title` — text of the memo's first block-level H1 heading, if present (`extractHeadingText`).
- `Tags` — all `#tag` occurrences in the content, deduplicated (case-preserving).
- `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks` — booleans derived from AST node kinds (links, code blocks/spans, GFM task-list checkboxes).
- `Snippet` — a plain-text excerpt (default max 64 chars, truncated at a word boundary) built by walking the AST and concatenating text nodes while skipping code blocks — used for list/preview rendering in the web UI.
- (Transient, not persisted) `Mentions` — lowercased `@username` mentions, extracted the same way for notification purposes.

These map to the proto `Memo.Property` message (`proto/api/v1/memo_service.proto:272-278`): `has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, `title`.
