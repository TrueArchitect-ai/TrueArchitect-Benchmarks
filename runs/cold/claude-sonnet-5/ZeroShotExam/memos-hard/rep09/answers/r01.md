**Premise correction:** There is no Redis connection in this repository. This is the `usememos/memos` codebase, and a search across the entire tree (`grep -ril "redis"`) turns up zero matches — no Redis client, config option, or connection string exists anywhere in `internal/`, `server/`, `store/`, or `cmd/`.

**Actual mechanism:** The cache layer is a pure in-process, in-memory cache, implemented in `store/cache/cache.go` (a `sync.Map`-backed store with TTL expiration and a background cleanup goroutine — no external service involved).

It's wired up in `store/store.go:38-53`: `Store.New()` builds a `cache.Config` and creates three separate in-memory caches (`instanceSettingCache`, `userCache`, `userSettingCache`) all sharing the same config:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user entries (`userCache`) get a **10-minute TTL** (`DefaultTTL`), with a background sweep every 5 minutes (`CleanupInterval`) evicting expired entries, and a cap of 1000 items per cache (`MaxItems`), enforced via LRU-ish eviction of the oldest 20% when exceeded (`store/cache/cache.go:117-119, 253-313`). This TTL can be overridden per-entry via `SetWithTTL`, but nothing in `store/user.go` calls it with a custom value — user cache entries use the default 10-minute TTL from `Set()` (`store/cache/cache.go:92-95`).
