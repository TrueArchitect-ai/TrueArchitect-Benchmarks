Delivery function — `Post` in `/bench/repo/internal/webhook/webhook.go:120` (also queued/dispatched asynchronously via `PostAsync` and the worker loop in `init()`, lines 42-55 and 184-196), which performs the actual `safeClient.Do(req)` HTTP POST.

Protection mechanism — `safeDialContext` in `/bench/repo/internal/webhook/webhook.go:59`, installed as the `DialContext` on the shared `safeClient`'s `http.Transport` (webhook.go:32-37). It resolves the target host via `net.DefaultResolver.LookupHost` and rejects any resolved IP that is "reserved" (checked via `isReservedIP` in `/bench/repo/internal/webhook/validate.go:44`, against the `reservedCIDRs`/`reservedNetworks` list defined at validate.go:14-36 — loopback, RFC-1918 private ranges, link-local/cloud IMDS `169.254.0.0/16`, and IPv6 equivalents). Because the check happens at dial time (post-DNS-resolution, per-connection) rather than only on the URL string, it also defeats DNS-rebinding attacks. There's a matching pre-flight check, `ValidateURL` (validate.go:62), used when webhook URLs are created/updated (e.g. in `server/router/api/v1/user_service_webhooks.go` / `memo_service_webhooks.go`), using the same `isReservedIP` logic. An `AllowPrivateIPs` flag (validate.go:41) can disable this protection for self-hosted deployments that intentionally target internal services.
