**Premise correction:** There is no Redis anywhere in this repository (this is the `usememos/memos` codebase) — a repo-wide case-insensitive search for `redis` returns zero hits. There's no separate "cache layer" backed by an external service either.

**Actual mechanism:** User entries are cached in-process using a custom thread-safe in-memory cache (`store/cache/cache.go`), not Redis. It's a `sync.Map`-backed cache with per-item expiration and a periodic cleanup goroutine.

- The `Store` struct holds a dedicated `userCache *cache.Cache` field, constructed in `store.New()` at `/bench/repo/store/store.go:52`.
- The cache config used for `userCache` (and `instanceSettingCache`, `userSettingCache`) is defined at `/bench/repo/store/store.go:40-45`:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  So **user entries get a 10-minute TTL**, with a background cleanup sweep every 5 minutes and a 1000-item cap (oldest 20% evicted when exceeded, per `cleanupOldest` in `/bench/repo/store/cache/cache.go:253`).
- User cache reads/writes go through `store/user.go` (e.g. `s.userCache.Set(ctx, userCacheKey(user.ID), user)` at lines 98, 122, 132, 143, 167, and `s.userCache.Get(...)` at line 150), keyed by `userCacheKey(userID int32)` (`/bench/repo/store/user.go:88`). Deletion on user removal happens via `s.deleteUserCache` in `/bench/repo/store/user_delete.go:39-41`.
- This same `cache.Cache` type (`/bench/repo/store/cache/cache.go`) is generic and reused for `instanceSettingCache` and `userSettingCache` too — all three currently share the same `DefaultTTL` of 10 minutes since they're all built from the one `cacheConfig`, though `SetWithTTL` allows a per-call override if needed.
