**Engine + path:** A custom CEL (Common Expression Language, via `google/cel-go`) filter engine that lives entirely in `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`). `ListMemos` (`server/router/api/v1/memo_service.go:211-215`) appends the raw `request.Filter` string to `store.FindMemo.Filters`, and validates it via `s.validateFilter` (`server/router/api/v1/shortcut_service.go:336`), which calls `filter.DefaultEngine()` and `engine.CompileToStatement`.

**Mechanism:** Each store driver (e.g. `store/db/sqlite/memo.go:57-63`, and the mysql/postgres equivalents) calls `filter.AppendConditions` (`internal/filter/helpers.go:9`), which uses the shared `Engine` to CEL-compile the filter string into an AST, convert it into a dialect-agnostic `Condition` tree (`engine.go` `buildCondition`), and then run it through a `renderer` (`internal/filter/render.go`) that walks that IR and emits dialect-specific SQL fragments/placeholders (e.g. `qualifyColumn`, `JSON_EXTRACT` vs `->>`/`jsonb_array_elements_text`, `LIKE`/`ILIKE`/`memos_unicode_lower`, MySQL `JSON_TABLE` vs SQLite `json_each` vs Postgres `jsonb_array_elements_text` for tag comprehensions) chosen by the `DialectName` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`) passed in from `s.Profile.Driver`.
