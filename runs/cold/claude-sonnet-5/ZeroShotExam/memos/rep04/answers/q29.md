**Interceptor:** `web/src/connect.ts` — a Connect-RPC `Interceptor` (`authInterceptor`) attached to the shared `createConnectTransport`; it sets the `Authorization: Bearer <token>` header on each request and, on an auth failure, refreshes and retries once. Token lifecycle helpers live in `web/src/auth-state.ts`, with `web/src/utils/auth-redirect.ts` handling redirect-to-sign-in on unrecoverable failure.

**Token kinds:**
- Access token (JWT, short-lived ~15 min) — kept in memory / `localStorage` (`memos_access_token`, expiry in `memos_token_expires_at`), sent as `Authorization: Bearer`.
- Refresh token (JWT, ~30 days, rotated on use) — HttpOnly cookie `memos_refresh`, sent via `credentials: "include"`.
- Personal Access Token (PAT, prefixed `memos_pat_`) — Bearer token for programmatic API access, validated by the same backend path.

**Backend validation package:** `server/auth/` — specifically `server/auth/token.go` (JWT/PAT generation & parsing), `server/auth/authenticator.go` (`Authenticator.Authenticate`/`AuthenticateByAccessTokenV2`/`AuthenticateByRefreshToken`/`AuthenticateByPAT`), and `server/auth/extract.go` (extracts bearer header / refresh cookie). It's wired into every RPC via `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor.WrapUnary`), with issuance/rotation in `server/router/api/v1/auth_service_session.go`.
