**Engine**: [CEL](https://github.com/google/cel-go) (`github.com/google/cel-go` v0.28.1, Google's Common Expression Language), wrapped by a custom package at `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `schema.go`, `render.go`, `helpers.go`).

The `filter` field on `ListMemosRequest` (`proto/api/v1/memo_service.proto:339`) is documented as "a CEL expression"; `APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:178`) validates it and passes it into the store layer.

**Mechanism**: `internal/filter/engine.go` compiles the raw string via `cel.Env.Compile` into a CEL AST; `internal/filter/parser.go` walks that AST into a dialect-agnostic `Condition`/`ValueExpr` intermediate representation (`internal/filter/ir.go`); then `internal/filter/render.go`'s `renderer` visitor walks that IR and string-builds SQL, branching per node on a `DialectName` enum (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`) rather than using separate per-dialect files — e.g. `strftime` vs `EXTRACT(...to_timestamp)` vs `YEAR()/MONTH()` for timestamp accessors, `JSON_EXTRACT`/`json_each` vs `JSON_TABLE`/`JSON_CONTAINS` vs `jsonb_array_elements_text`/`@>` for tag/JSON handling, and `?` vs `$N` placeholders. Each dialect's memo store (`store/db/{sqlite,mysql,postgres}/memo.go`) just calls the shared `filter.AppendConditions(...)` with its own `DialectName` constant to get back SQL + args.
