**Runners actually started by the server** (boot path: `cmd/memos/main.go` → `store.New()` → `server.NewServer()` → `server.Start()`):

- S3 presign runner — 12-hour `time.NewTicker`, run once immediately then on the ticker; started in `server.startBackgroundRunners` (`server/server.go:153-171`), called from `Server.Start` (`server/server.go:129`); ticker defined in `server/runner/s3presign/runner.go:27,29-41`.
- Store cache cleanup loop ×3 (instance-setting cache, user cache, user-setting cache) — 5-minute `time.NewTicker` per instance (`store/cache/cache.go:200-215`, goroutine spawned in `cache.New` at `store/cache/cache.go:83`); the three caches are constructed in `store.New()` (`store/store.go:41,51-53`), invoked from `cmd/memos/main.go:64`.
- Webhook async dispatch pool (4 goroutines) — not time-based; each worker blocks on `for payload := range asyncPostQueue` and fires when a webhook event is enqueued; spawned via `package init()` (`internal/webhook/webhook.go:38,41-52`), so it starts at process load, not explicitly from `server.Start()`.
- Email async dispatch pool (2 goroutines) — same pattern, driven by `for request := range asyncEmailQueue`; spawned via `package init()` (`internal/email/email.go:14,16-36`).

Not boot-scheduled background workers, but tickers worth noting: SSE heartbeat (`server/router/api/v1/sse_handler.go:17,64`, 30s) is created/destroyed per SSE HTTP connection, not at server startup.

**Unused scheduling infrastructure:**
- `internal/scheduler` — a full cron-style job scheduler (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`, with cron-expression parsing, timezones, `Register`/`Start`/`Stop`). Grep for its import path across the repo shows it's only referenced from its own test files (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`) — no production code imports or wires it in.
- `memopayload.Runner` — a batch runner (`server/runner/memopayload/runner.go:14-72`, `NewRunner`/`RunOnce`) built with the same shape as the S3 presign runner, meant to rebuild all memo payloads. It's never instantiated anywhere (`grep` for `memopayload.NewRunner`/`memopayload.Runner` finds nothing outside its own file). Only the plain helper function `memopayload.RebuildMemoPayload` (not the `Runner` type) is used, called synchronously per-memo from `server/router/api/v1/memo_service.go:108` and `:447`.
