q16. In `Store.DeleteMemo` (`store/memo.go:140-159`), before deleting the memo row itself, the store layer deletes:

1. **`memo_relation` records where this memo is the source** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
2. **`memo_relation` records where this memo is the target/related memo** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})` (`store/memo.go:145`)
3. **`attachment` records linked to the memo** — listed via `s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})` and each deleted with `s.DeleteAttachment(...)`, which also removes the underlying stored file (`store/memo.go:149-156`, `store/attachment.go:132-149`)

Only after these does it call `s.driver.DeleteMemo(ctx, delete)` (`store/memo.go:158`) to delete the memo row itself.

(Not handled here: `memo_share` rows cascade via a DB-level `ON DELETE CASCADE` FK rather than explicit Go code, and `reaction` rows are not cleaned up at all since the `reaction` table has no FK tie to `memo`.)
