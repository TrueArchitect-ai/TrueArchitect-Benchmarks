s3presign runner — `time.Ticker` firing every 12h (`runnerInterval = time.Hour * 12`), started in `server/server.go:153-174` via `s3presignRunner := s3presign.NewRunner(s.Store)`, an immediate `RunOnce(ctx)` call, then `go func() { s3presignRunner.Run(s3Context) }()`; the ticker/interval loop itself lives in `server/runner/s3presign/runner.go:27-41`, shut down via context cancellation in `stopBackgroundRunners` (`server/server.go:176-182`). This is the only scheduled background worker the server starts (the Echo HTTP listener goroutine at `server/server.go:124-128` is the web server itself, and the 30s `time.NewTicker` heartbeat in `server/router/api/v1/sse_handler.go:64` is per-SSE-connection, not a global boot-time worker).

**Unused scheduling infrastructure:**
- `internal/scheduler` — a full cron-expression scheduler package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) with its own README describing `New()`/`Register(&Job{...})`/`Start()` usage. It is imported nowhere in production code (`cmd/memos`, `server/`, `store/`) — only by its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). No job is ever registered with it in the running app.
- `server/runner/memopayload.Runner` (`NewRunner`/`RunOnce`, `server/runner/memopayload/runner.go:14-72`) — a batch job designed to mirror the `s3presign.Runner` pattern (rebuild payloads for all memos), but `NewRunner` is never called anywhere in the repo. Only the separate, non-runner helper `memopayload.RebuildMemoPayload` (`runner.go:74-88`) is used, and it's invoked synchronously inline during memo create/update requests (`server/router/api/v1/memo_service.go:108` and `:447`), not as a scheduled background job.
