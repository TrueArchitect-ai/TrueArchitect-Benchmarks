q29. Frontend API requests are authenticated via a Connect-RPC interceptor (this repo uses `@connectrpc/connect`, not axios/fetch directly).

- **Interceptor path:** `web/src/connect.ts` — the `authInterceptor` function attaches `Authorization: Bearer <token>` to every request, catches `Unauthenticated` (401) errors, refreshes the token, and retries once before redirecting to login. Token state/refresh logic lives alongside it in `web/src/auth-state.ts` (with `web/src/hooks/useTokenRefreshOnFocus.ts` doing proactive refresh-on-focus).
- **Token kinds:** two JWTs —
  - **Access token** (short-lived): stored in `localStorage` (`memos_access_token`), sent as `Authorization: Bearer <token>` header, synced across tabs via a `BroadcastChannel`.
  - **Refresh token** (long-lived): stored as an HttpOnly cookie (`memos_refresh`, defined server-side in `server/auth/token.go:49`), sent automatically via `credentials: "include"`, used only by the `RefreshToken` RPC.
- **Backend package path:** `server/auth/` (core validation: `authenticator.go` for `AuthenticateByAccessTokenV2`/`AuthenticateByRefreshToken`/`AuthenticateByPAT`; `token.go` for JWT claims/cookie constants; `extract.go` for pulling the header/cookie), invoked per-request by the Connect middleware in `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor.WrapUnary`), wired in `server/router/api/v1/v1.go:133`.
