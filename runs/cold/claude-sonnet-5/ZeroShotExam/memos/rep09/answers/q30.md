The background research agent I'd launched earlier finished and confirms my answer, with one useful addition: there's no separate "archived" webhook event — archiving a memo goes through `UpdateMemo` with `update_mask` path `"state"` (`memo_service.go:467-469`), which still dispatches via `DispatchMemoUpdatedWebhook` as `"memos.memo.updated"`. Also, `DispatchMemoUpdatedWebhook` is invoked from a shared helper (`memo_update_helpers.go:67`) that's called not just from `UpdateMemo` but also from attachment changes (`memo_attachment_service.go:48`) and relation changes (`memo_relation_service.go:48`) — so any of those trigger the same "updated" webhook.
