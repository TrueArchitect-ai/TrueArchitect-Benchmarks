The background research agent confirmed my findings and added a few more entry points I hadn't traced. Here's the complete picture:

q30.
event: memo created → `DispatchMemoCreatedWebhook` (server/router/api/v1/memo_service_webhooks.go:15), invoked from `CreateMemo` (memo_service.go:157)
event: memo updated (content/visibility/pinned/state/etc. via `UpdateMemo`) → `DispatchMemoUpdatedWebhook` (memo_service_webhooks.go:20), invoked from `dispatchMemoUpdatedSideEffects` (memo_update_helpers.go:67), which `UpdateMemo` calls (memo_service.go:513)
event: memo deleted → `DispatchMemoDeletedWebhook` (memo_service_webhooks.go:25), invoked from `DeleteMemo` (memo_service.go:562)
event: memo comment created → `DispatchMemoCommentCreatedWebhook` (memo_service_webhooks.go:30), invoked from `CreateMemoComment` (memo_service_comments.go:119)
event: memo attachments set (also fires an "updated" webhook) → same `DispatchMemoUpdatedWebhook`, via `dispatchMemoUpdatedSideEffects` called from `SetMemoAttachments` (memo_attachment_service.go:48)
event: memo relations set (also fires an "updated" webhook) → same `DispatchMemoUpdatedWebhook`, via `dispatchMemoUpdatedSideEffects` called from `SetMemoRelations` (memo_relation_service.go:48)

Activity-type strings sent: `memos.memo.created`, `memos.memo.updated`, `memos.memo.deleted`, `memos.memo.comment.created` (memo_service_webhooks.go:16,21,26,40).

Convergence: created/updated/deleted share the private helper `dispatchMemoRelatedWebhook` (memo_service_webhooks.go:48), which looks up the creator's webhooks and builds the payload; the comment-created path builds its payload inline (memo_service_webhooks.go:30-46). All four then call `webhook.PostAsync` (internal/webhook/webhook.go:184), which enqueues onto a bounded channel drained by a pool of worker goroutines (started in `init()`, webhook.go:42-55) that call the actual HTTP-delivery function:

**Delivery function: `webhook.Post` — internal/webhook/webhook.go:120** (marshals payload, optionally HMAC-signs it, and POSTs via the SSRF-guarded `safeClient` at webhook.go:152).
