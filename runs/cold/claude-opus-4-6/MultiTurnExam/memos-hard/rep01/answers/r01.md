The premise is incorrect — there is no Redis connection. The cache layer is purely **in-memory**, implemented as a `sync.Map` with TTL-based expiration in `store/cache/cache.go`. There is no Redis dependency anywhere in the codebase.

User entries use the **default cache configuration** (`store/cache/cache.go:57–64`): a **10-minute TTL**, with cleanup every 5 minutes and a max of 1000 items. The user cache is created via `cache.NewDefault()` in `store/store.go` and entries are set with `Set()` (line 93 of `cache.go`), which applies the default TTL. No custom TTL is specified for user entries.
