**Mechanism:** explicit Go code.

When a user is deleted, reactions are removed by two explicit SQL `DELETE` statements executed within the same transaction, in all three database drivers:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions whose `content_id` matches any of the user's memos (reactions *on* the user's content).
   - `store/db/sqlite/user_delete.go:380–387` (called at line 96)
   - `store/db/postgres/user_delete.go:380–387` (called at line 96)
   - `store/db/mysql/user_delete.go:417–435` (called at line 96)

2. **`deleteReactionsByCreatorTx`** — deletes reactions where `creator_id` matches the deleted user (reactions *by* the user on others' content).
   - `store/db/sqlite/user_delete.go:400–403` (called at line 102)
   - `store/db/postgres/user_delete.go:400–403` (called at line 102)
   - `store/db/mysql/user_delete.go:437–439` (called at line 102)

There are no `CASCADE` foreign-key constraints on the `reaction` table handling this — both directions (reactions on the user's memos, and reactions created by the user) are cleaned up by explicit Go code within the `DeleteUser` transaction.
