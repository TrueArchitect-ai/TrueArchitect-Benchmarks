Reactions are removed by **explicit Go code**, not by a database-level CASCADE rule. The `reaction` table has no foreign key constraints at all (`store/migration/sqlite/LATEST.sql:92-99`; same for MySQL and Postgres variants).

When a user is deleted, the `deleteUserTargetsTx` function handles reaction cleanup in two steps:

1. **Reactions on the user's memos** — `deleteReactionsByContentIDsTx` deletes all reactions whose `content_id` matches the user's memo content IDs (`store/db/sqlite/user_delete.go:96`, `:380-387`).
2. **Reactions by the user on other content** — `deleteReactionsByCreatorTx` deletes all reactions where `creator_id` matches the deleted user (`store/db/sqlite/user_delete.go:102`, `:400-403`).

The same pattern exists in all three drivers:
- `store/db/sqlite/user_delete.go:96,102,380-403`
- `store/db/mysql/user_delete.go:420,438`
- `store/db/postgres/user_delete.go:383,401`
