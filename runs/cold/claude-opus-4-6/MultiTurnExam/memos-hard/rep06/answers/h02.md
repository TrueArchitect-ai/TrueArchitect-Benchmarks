**Delivery function** — `Post` in `internal/webhook/webhook.go` (lines ~120-179). It builds an HTTP POST with the JSON payload, optionally signs it with HMAC-SHA256 (Standard Webhooks headers), and sends it via a `safeClient`. The async path used by the server is `PostAsync` (same file, lines ~184-196), which enqueues work onto a buffered channel drained by background goroutines that each call `Post`.

**Protection mechanism** — A two-layer SSRF guard in the same package:

1. **Registration-time validation**: `ValidateURL` in `internal/webhook/validate.go` (lines ~62-83) resolves the hostname and checks every resulting IP against a blocklist of reserved CIDRs (loopback, RFC-1918 private, link-local/IMDS, IPv6 ULA/link-local — defined at lines ~14-36 of the same file via `isReservedIP`).

2. **Connection-time re-check**: `safeDialContext` in `internal/webhook/webhook.go` (lines ~59-77) re-resolves the hostname at dial time and runs the same `isReservedIP` check again before allowing the TCP connection, defeating DNS-rebinding attacks that could change resolution between validation and delivery.
