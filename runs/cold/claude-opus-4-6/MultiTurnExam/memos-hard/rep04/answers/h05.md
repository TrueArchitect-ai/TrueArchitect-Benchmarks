**Mechanism: explicit Go code** — reactions are removed by two explicit SQL `DELETE` statements within the user-deletion transaction, not by any database-level cascade or foreign key rule.

**Evidence locations:**

1. `deleteReactionsByContentIDsTx` — deletes reactions on the user's memos by `content_id` (`DELETE FROM reaction WHERE content_id IN ...`):
   - `store/db/sqlite/user_delete.go:380–388`
   - `store/db/postgres/user_delete.go:380–388`
   - `store/db/mysql/user_delete.go` (same pattern)

2. `deleteReactionsByCreatorTx` — deletes reactions the user themselves created by `creator_id` (`DELETE FROM reaction WHERE creator_id = ...`):
   - `store/db/sqlite/user_delete.go:400–403`
   - `store/db/postgres/user_delete.go:400–403`

Both are called from `deleteUserTargetsTx` (e.g., `store/db/sqlite/user_delete.go:96` and `:102`) inside the same transaction that deletes the user row. There are no `ON DELETE CASCADE` foreign key constraints involved — the cleanup is entirely in application-level Go code.
