Memo visibility is enforced in at least these distinct sites:

1. **`checkMemoReadAccess`** (single-memo gRPC guard) — `server/router/api/v1/memo_service.go:39` — used by `GetMemo` (line 356) and `ListMemoComments` (line 148 of `memo_service_comments.go`). Blocks unauthenticated access to non-public memos; blocks non-owners from private memos.

2. **`ListMemos` query-level filtering** — `server/router/api/v1/memo_service.go:218–227` — restricts the DB query itself: anonymous users see only `PUBLIC`; authenticated users see `PUBLIC + PROTECTED + own`, via `VisibilityList` and CEL filter injection.

3. **`CreateMemoComment` visibility gate** — `server/router/api/v1/memo_service_comments.go:33–43` — checks the parent memo's visibility before allowing a comment; blocks non-owners from commenting on private memos.

4. **`ListMemoReactions` / `UpsertMemoReaction` visibility checks** — `server/router/api/v1/reaction_service.go:30–41` and `:82–85` — inline visibility checks before listing or upserting reactions on a memo.

5. **`checkAttachmentAccess`** (gRPC attachment access) — `server/router/api/v1/attachment_service.go:422–455` — for linked attachments, enforces the parent memo's visibility rules.

6. **`ListMemoAttachments` visibility check** — `server/router/api/v1/memo_attachment_service.go:213–225` — checks memo visibility before listing its attachments.

7. **File server attachment serving** — `server/router/fileserver/fileserver.go:666–701` — enforces memo visibility when serving attachment files over HTTP, with share-token fallback.

8. **SSE event delivery filter** — `server/router/api/v1/sse_hub.go:134–144` (`canReceive`) — private memo events are only delivered to the creator or admins.

9. **RSS feed** — `server/router/rss/rss.go:90,141` — queries restrict to `store.Public` visibility only.

10. **Frontend Open Graph metadata** — `server/router/frontend/frontend.go:150` — restricts to `store.Public` when rendering `<meta>` tags for link previews.
