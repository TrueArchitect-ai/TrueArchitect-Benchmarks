The premise is incorrect — there is no Redis connection in this codebase. The cache layer is an in-memory implementation, not Redis-backed.

The cache is defined as `store/cache/cache.go`, which implements a generic in-memory cache with expiration and cleanup. User entries are cached in `Store.userCache` (constructed in `store/store.go`) using this in-memory cache. The TTL for all cache entries is governed by the `expiration` parameter passed to `cache.New()` at construction time — there is no Redis, no external cache store, and no Redis configuration anywhere in the repository.
