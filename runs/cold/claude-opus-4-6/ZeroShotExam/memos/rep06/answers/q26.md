When `DeleteMemo` runs, the following database tables are affected:

1. **`memo_relation`** — Rows are deleted where the memo is either the source (`memo_id`) or the target (`related_memo_id`). This is done explicitly in `store/memo.go:142-146` via two calls to `DeleteMemoRelation`, which executes `DELETE FROM memo_relation` in the driver (e.g., `store/db/sqlite/memo_relation.go:149`).

2. **`attachment`** — All attachments linked to the memo are deleted. Done explicitly in `store/memo.go:149-156` by listing attachments for the memo and calling `DeleteAttachment` for each, which executes `DELETE FROM attachment` (`store/db/sqlite/attachment.go:212`).

3. **`memo`** — The memo row itself is deleted last via `s.driver.DeleteMemo` at `store/memo.go:158`, which executes `DELETE FROM memo` (`store/db/sqlite/memo.go:239`).

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (found via `memo_relation` with type `Comment`) are recursively deleted by calling `Store.DeleteMemo` for each comment — so each comment triggers the same cascade on all three tables above.

**Tables affected: `memo`, `memo_relation`, `attachment`**
