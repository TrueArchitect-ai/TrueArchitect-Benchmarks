Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

The first three delegate to the private helper `dispatchMemoRelatedWebhook` (same file), which looks up the memo creator's webhooks and posts each one. `DispatchMemoCommentCreatedWebhook` does its own lookup but follows the same delivery path.

All four converge on **`webhook.Post`** (via **`webhook.PostAsync`**) in `internal/webhook/webhook.go`. `PostAsync` enqueues payloads onto a buffered channel (`asyncPostQueue`), drained by a pool of worker goroutines that each call `Post` to perform the actual HTTP POST delivery (with optional HMAC-SHA256 signing and an SSRF-safe client).
