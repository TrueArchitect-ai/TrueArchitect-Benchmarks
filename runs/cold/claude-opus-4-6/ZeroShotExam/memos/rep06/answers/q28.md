**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (`server/runner/s3presign/runner.go:27`); started in `server.go:153` via `startBackgroundRunners`, re-presigns S3 attachment URLs nearing expiry
- **Cache Cleanup (×3)** — `time.NewTicker` every 5 minutes (`store/cache/cache.go:62`); one goroutine per cache instance (instanceSettingCache, userCache, userSettingCache), started when `store.New()` is called, evicts expired entries
- **Webhook Async Dispatch (×4)** — channel-driven (`internal/webhook/webhook.go:39-55`); 4 worker goroutines started in `init()`, consuming from a buffered channel (cap 128) fed by `PostAsync`

**Unused scheduling infrastructure:**

The `internal/scheduler/` package is a fully-featured cron-based job scheduler (cron expression parser, middleware with recovery/logging/timeout, timezone support, graceful shutdown) that is **never imported or used** by the server or any other production code. The server's only periodic runner (S3 presign) uses a hand-rolled `time.NewTicker` loop instead.

Additionally, `server/runner/memopayload/runner.go` defines a `Runner` struct with a `RunOnce()` method, but its constructor `NewRunner()` is never called anywhere in production code — only the standalone `RebuildMemoPayload` function from that package is used (synchronously, inline in `memo_service.go`).
