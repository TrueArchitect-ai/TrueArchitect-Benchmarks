The frontend auth interceptor lives at **`web/src/connect.ts`** (the `authInterceptor` function, ~line 156). It is a Connect RPC interceptor that sets the `Authorization: Bearer <token>` header on every outgoing request and handles automatic retry with token refresh on `Unauthenticated` responses.

**Tokens managed:**

| Token | Frontend handling |
|---|---|
| **Access token** | Stored in memory and `localStorage` (`memos_access_token`); 15-minute lifetime; refreshed proactively on tab focus and reactively on 401. Managed in `web/src/auth-state.ts`. |
| **Refresh token** | HttpOnly cookie (`memos_refresh`); 30-day sliding window; never touched by JS — sent implicitly via `credentials: "include"`. |

The interceptor also coexists with **Personal Access Tokens (PATs)**, which are opaque `memos_pat_*` strings validated server-side by SHA-256 hash lookup.

**Backend validation package:** **`server/auth/`** (Go package `auth`). Key files:

- `server/auth/authenticator.go` — `Authenticate()` dispatches to `AuthenticateByAccessTokenV2()` (stateless JWT/HS256 check) or `AuthenticateByPAT()` (database hash lookup); `AuthenticateByRefreshToken()` does JWT + DB revocation check.
- `server/auth/token.go` — JWT generation/parsing (`GenerateAccessTokenV2`, `ParseAccessTokenV2`, `GenerateRefreshToken`, etc.).
- `server/router/api/v1/connect_interceptors.go` — server-side `AuthInterceptor` that calls into the `auth` package and applies the result to the request context.

**Summary:** `web/src/connect.ts`; access token + refresh token (+ PATs); `server/auth/`.
