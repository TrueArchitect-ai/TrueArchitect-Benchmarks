When `DeleteMemo` runs, the following database tables are affected:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
2. **`memo_relation`** — relations where the memo is either `memo_id` or `related_memo_id` are deleted (`store/memo.go:142-146`)
3. **`attachment`** — all attachments linked to the memo are deleted (`store/memo.go:149-156`)

Additionally, the service-level `DeleteMemo` in `server/router/api/v1/memo_service.go:567-577` first deletes comment memos (by looking up `memo_relation` rows of type `Comment` where the memo is the `related_memo_id`), and for each comment it recursively calls `store.DeleteMemo`, which cascades the same cleanup (memo_relation, attachment, memo) for each comment.

**Table list: `memo`, `memo_relation`, `attachment`**
