**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (a Connect RPC `Interceptor`) attaches a `Bearer` token via the `Authorization` header to every outgoing request and handles transparent retry on 401.

**Token kinds:**
1. **Access token** — a short-lived JWT (15 min, audience `user.access-token`), stored in localStorage (`memos_access_token`) and managed in `web/src/auth-state.ts`.
2. **Refresh token** — a long-lived JWT (30 days, audience `user.refresh-token`), stored as an HttpOnly cookie (`memos_refresh`), used with refresh-token rotation.
3. **Personal access token (PAT)** — long-lived, prefixed `memos_pat_`, stored as a SHA-256 hash in the database, for programmatic API access.

**Backend validation package:** `server/auth/` — contains `authenticator.go` (validates all three credential types: `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`), `token.go` (HS256 JWT generation/parsing via `golang-jwt/jwt/v5`), and `extract.go` (extracts tokens from headers/cookies). The server-side Connect RPC `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` calls into this package for every inbound request.
