**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line ~156) is a ConnectRPC `Interceptor` that sets `Authorization: Bearer <token>` on every request, handles 401 responses by refreshing the access token, and proactively refreshes tokens nearing expiry (within 30 seconds).

**Token kinds:**
1. **Access token** — a short-lived (15 min) HS256 JWT stored in `localStorage` (key `memos_access_token`), sent as a `Bearer` token in the `Authorization` header. Token state managed in `web/src/auth-state.ts`.
2. **Refresh token** — a long-lived (30 day) HS256 JWT stored in an HTTP-only cookie named `memos_refresh`, sent automatically via `credentials: "include"`. Rotated on each refresh.
3. **Personal access token (PAT)** — a random string prefixed with `memos_pat_`, validated by SHA-256 hash lookup in the database. Also sent as a `Bearer` token.

**Backend validation package:** `server/auth/` — specifically `server/auth/authenticator.go` (the `Authenticator` struct with `Authenticate()` entry point), `server/auth/token.go` (JWT parsing/generation via `golang-jwt/jwt/v5`), and `server/auth/extract.go` (header/cookie extraction). The server-side ConnectRPC interceptor that invokes this package lives at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`).
