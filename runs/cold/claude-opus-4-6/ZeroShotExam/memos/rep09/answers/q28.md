**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (plus once at startup); refreshes pre-signed S3 attachment URLs. Started explicitly in `Server.startBackgroundRunners()` (`server/server.go:162-167`, runner at `server/runner/s3presign/runner.go`)
- **Webhook Async Workers (×4)** — channel-driven (`asyncPostQueue`, buffered 128); started via package-level `init()` on import (`internal/webhook/webhook.go:42-55`)
- **Email Async Workers (×2)** — channel-driven (`asyncEmailQueue`, buffered 128); started via package-level `init()` on import (`internal/email/email.go:16-36`)

**Scheduling infrastructure present but NOT used by the server:**

- **`internal/scheduler/` package** — A full cron-expression scheduler with timezone support, middleware (`Recovery`, `Logging`, `Timeout`), and graceful shutdown (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It is **never imported outside its own test files** — no production code instantiates a `Scheduler` or registers any `Job`. The S3 presign runner uses a hand-rolled `time.NewTicker` loop instead.
- **`server/runner/memopayload/` Runner** — A batch runner (`memopayload.Runner`) that rebuilds payload for all memos (`server/runner/memopayload/runner.go`). Its `NewRunner()` is **never called** by the server; `startBackgroundRunners()` only starts the S3 presign runner. The standalone function `RebuildMemoPayload()` is used inline during individual memo create/update in `memo_service.go`, but the batch `Runner` itself is dead code.
