When `DeleteMemo` runs, the following database tables are affected:

1. **`memo_relation`** — Rows are deleted where the memo is either the source (`memo_id`) or target (`related_memo_id`). This is done explicitly in `store/memo.go:142-147` via two calls to `driver.DeleteMemoRelation`.

2. **`attachment`** — All attachments linked to the memo are deleted. Done in `store/memo.go:149-156` by listing attachments for the memo and calling `DeleteAttachment` for each, which issues `DELETE FROM attachment` (`store/db/sqlite/attachment.go:212`).

3. **`memo`** — The memo row itself is deleted last via `driver.DeleteMemo` (`store/memo.go:158`), which issues `DELETE FROM memo` (`store/db/sqlite/memo.go:239`).

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (related via `memo_relation` with type `Comment`) are recursively deleted by calling `Store.DeleteMemo` for each comment — so for those child memos, the same three tables (`memo_relation`, `attachment`, `memo`) are affected again.

**Table list: `memo`, `memo_relation`, `attachment`**
