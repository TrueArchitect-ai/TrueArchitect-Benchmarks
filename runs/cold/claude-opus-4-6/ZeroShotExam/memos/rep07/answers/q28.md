**Runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (plus one synchronous `RunOnce` at startup). Started by `server.startBackgroundRunners()` in `server/server.go:153–173`; defined in `server/runner/s3presign/runner.go:27`.
- **Webhook Dispatch Workers (×4)** — channel-driven (`asyncPostQueue`, buffered 128). Workers consume payloads on demand when `PostAsync()` is called from request handlers. Started via Go `init()` in `internal/webhook/webhook.go:42–55`.
- **Email Dispatch Workers (×2)** — channel-driven (`asyncEmailQueue`, buffered 128). Workers consume requests on demand when `SendAsync()` is called. Started via Go `init()` in `internal/email/email.go:16–35`.
- **Cache Cleanup Goroutines (×3)** — `time.NewTicker` every 5 minutes. One per cache instance (`instanceSettingCache`, `userCache`, `userSettingCache`), spawned by `cache.New()` in `store/cache/cache.go:82–84`, triggered from `store.New()` in `store/store.go:51–53`.

**Scheduling infrastructure present but NOT used by the server:**

- **`internal/scheduler/` package** — a full-featured cron-expression-based job scheduler (with 5/6-field cron parsing, middleware, timezone support, graceful shutdown) spread across `scheduler.go`, `parser.go`, `job.go`, `middleware.go`, and `doc.go`. It is **never imported by any production code**; the only imports are from its own test files (`example_test.go`, `integration_test.go`).
- **`server/runner/memopayload/` Runner** — has a `Runner` struct with a `RunOnce()` batch method (`server/runner/memopayload/runner.go:14–72`), but the server never instantiates or schedules it. Its core function `RebuildMemoPayload` is called inline during memo create/update in `server/router/api/v1/memo_service.go`, not as a background runner.
