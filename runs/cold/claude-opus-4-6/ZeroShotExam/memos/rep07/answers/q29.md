**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches an `Authorization: Bearer <token>` header to every outgoing request and handles automatic retry with token refresh on `Unauthenticated` errors.

**Token kinds managed:**
1. **Access token** — a short-lived JWT (15 min), stored in-memory and in `localStorage` (`memos_access_token`); managed in `web/src/auth-state.ts`.
2. **Refresh token** — a long-lived JWT (30 days), stored as an `HttpOnly` cookie named `memos_refresh` (set by the server, not accessible to JS); sent automatically via `credentials: "include"` on fetch requests.
3. **Personal Access Token (PAT)** — long-lived tokens prefixed `memos_pat_`, validated by SHA-256 hash lookup in the database.

**Backend package that validates them:** `server/auth/` — specifically:
- `server/auth/authenticator.go` provides `AuthenticateByAccessTokenV2` (stateless JWT/HS256 validation), `AuthenticateByRefreshToken` (DB-backed revocation check), and `AuthenticateByPAT` (hash lookup).
- `server/auth/token.go` handles JWT generation and parsing (`ParseAccessTokenV2`, `ParseRefreshToken`).
- `server/auth/extract.go` extracts the Bearer token from the `Authorization` header and the refresh token from the cookie.

The backend wires this into the request pipeline via `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`, which delegates to an `Authorizer` (`server/router/api/v1/authz.go`) wrapping the `auth.Authenticator`.
