Four memo lifecycle events dispatch webhooks, with these dispatch function names (all defined in `server/router/api/v1/memo_service_webhooks.go`):

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

The first three delegate to a shared private helper `dispatchMemoRelatedWebhook` (same file, line 48), while `DispatchMemoCommentCreatedWebhook` (line 30) handles its own loop but follows the same pattern.

All four converge for delivery through **`webhook.PostAsync`** (`internal/webhook/webhook.go:184`), which enqueues payloads onto a buffered channel. Four goroutines (spawned in `init()`, line 42) drain that channel and call **`webhook.Post`** (`internal/webhook/webhook.go:120`) — the single synchronous HTTP delivery function where all webhook dispatches ultimately converge.
