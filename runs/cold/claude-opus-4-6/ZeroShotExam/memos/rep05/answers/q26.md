The following database tables are affected when `DeleteMemo` runs:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
2. **`memo_relation`** — all relation records where the memo is either `memo_id` or `related_memo_id` are explicitly deleted in `store/memo.go:142-147` (via `DeleteMemoRelation` at `store/db/sqlite/memo_relation.go:148-150`)
3. **`attachment`** — all attachments linked to the memo are explicitly deleted in `store/memo.go:149-156` (via `DeleteAttachment` at `store/db/sqlite/attachment.go:212`)
4. **`memo_share`** — rows referencing the memo are removed via `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` defined in the schema (`store/migration/sqlite/LATEST.sql:109`)

Additionally, the API-level `DeleteMemo` (`server/router/api/v1/memo_service.go:567-577`) first recursively deletes comment memos (found via `memo_relation` with type `Comment`), which triggers the same cascade on `memo`, `memo_relation`, `attachment`, and `memo_share` for each comment.
