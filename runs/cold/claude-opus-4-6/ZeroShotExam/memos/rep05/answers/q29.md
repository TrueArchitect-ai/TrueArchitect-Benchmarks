**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line ~156) is a ConnectRPC `Interceptor` that attaches a `Bearer` access token via `setAuthorizationHeader()` on every outgoing request and handles automatic refresh-and-retry on `Unauthenticated` errors.

**Token kinds:**
1. **Access token** — short-lived JWT (15 min), stored in-memory and `localStorage` (`memos_access_token`), sent as `Authorization: Bearer <token>`. State managed in `web/src/auth-state.ts`.
2. **Refresh token** — long-lived JWT (30 days), stored as an `HttpOnly` cookie (`memos_refresh`), sent implicitly via `credentials: "include"`. The server performs rotation on each refresh.
3. **Personal access token (PAT)** — long-lived random string prefixed `memos_pat_`, also sent as a `Bearer` token and validated by SHA-256 hash lookup in the database.

**Backend validation package:** `server/auth/` — specifically:
- `server/auth/authenticator.go` — `Authenticator` with `AuthenticateByAccessTokenV2()`, `AuthenticateByRefreshToken()`, and `AuthenticateByPAT()`.
- `server/auth/token.go` — JWT generation/parsing (`ParseAccessTokenV2`, `ParseRefreshToken`) using `HS256` via `golang-jwt/jwt/v5`.
- `server/auth/extract.go` — extracts bearer tokens from headers and refresh tokens from cookies.

The server-side ConnectRPC interceptor that calls into this package lives at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`).
