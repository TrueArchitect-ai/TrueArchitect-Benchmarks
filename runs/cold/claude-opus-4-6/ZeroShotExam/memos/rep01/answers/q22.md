**`DispatchMemoCreatedWebhook`** — `server/router/api/v1/memo_service_webhooks.go`; delivery package: **`internal/webhook`** (which uses Go's standard `net/http` client via `webhook.Post`/`webhook.PostAsync`); signing mechanism: **HMAC-SHA256 following the Standard Webhooks spec** (message ID + timestamp + body signed with the webhook's secret, output sent as `v1,<base64>` in a `webhook-signature` header).

The flow: `CreateMemo` in `server/router/api/v1/memo_service.go` calls `DispatchMemoCreatedWebhook`, which delegates to the private `dispatchMemoRelatedWebhook` (same file). That method fetches the creator's webhooks from the store, builds a `WebhookRequestPayload` (including the `"memos.memo.created"` activity type and the per-webhook signing secret), and enqueues it via `webhook.PostAsync` (`internal/webhook/webhook.go`). The `Post` function resolves the signing key (stripping a `whsec_` prefix and base64-decoding if present), computes HMAC-SHA256 over `msgID.timestamp.body`, and sets the `webhook-id`, `webhook-timestamp`, and `webhook-signature` headers on the outgoing HTTP request.
