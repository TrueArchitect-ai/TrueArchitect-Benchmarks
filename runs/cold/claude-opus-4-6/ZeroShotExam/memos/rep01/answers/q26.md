When `DeleteMemo` runs, the following database tables are affected:

1. **`memo_relation`** — `store.DeleteMemo` explicitly deletes rows where the memo is the source (`MemoID`) and where the memo is the target (`RelatedMemoID`) (`store/memo.go:142-147`)
2. **`attachment`** — `store.DeleteMemo` lists attachments for the memo and deletes each one (`store/memo.go:149-157`, SQL in e.g. `store/db/sqlite/attachment.go:212`)
3. **`memo`** — the memo row itself is deleted (`store/memo.go:158`, SQL in e.g. `store/db/sqlite/memo.go:239`)

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (found via `memo_relation` with type `Comment`) are recursively deleted through the same `store.DeleteMemo` path, so for each comment the same three tables (`memo_relation`, `attachment`, `memo`) are affected.

**Tables: `memo`, `memo_relation`, `attachment`**
