**Background workers the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (plus once immediately at startup); re-signs expiring S3 presigned URLs (`server/runner/s3presign/runner.go`, started in `server/server.go:153-173`)
- **Cache Cleanup (×3 instances)** — `time.NewTicker` every 5 minutes; evicts expired entries from `instanceSettingCache`, `userCache`, `userSettingCache` (`store/cache/cache.go:200-215`, created in `store/store.go:51-53`)
- **Webhook Dispatch Workers (×4)** — channel-driven (`asyncPostQueue`, capacity 128); fire on memo create/update/delete/comment events (`internal/webhook/webhook.go:42-55`, started via `init()`)
- **Email Dispatch Workers (×2)** — channel-driven (`asyncEmailQueue`, capacity 128); fire when notifications trigger email sends (`internal/email/email.go:14-36`, started via `init()`)

**Unused scheduling infrastructure:**

- The `internal/scheduler/` package is a **fully-featured cron scheduler** (supports 5- and 6-field cron expressions, timezones, middleware for recovery/logging/timeout) that is **never imported by any production code** — only by its own test files (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`).
- The `server/runner/memopayload/` runner struct exists with `NewRunner()` and `RunOnce()` but is **never wired into `startBackgroundRunners()`**; only its static `RebuildMemoPayload` function is called inline from memo API handlers (`server/router/api/v1/memo_service.go:108,447`).
