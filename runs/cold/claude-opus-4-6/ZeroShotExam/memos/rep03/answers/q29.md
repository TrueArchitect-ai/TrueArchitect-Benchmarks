**Interceptor path:** `web/src/connect.ts` — defines `const authInterceptor: Interceptor` (around line 156) using ConnectRPC's interceptor mechanism. It attaches an `Authorization: Bearer <token>` header to every outgoing request, handles 401 retries with token refresh, and redirects to sign-in on persistent auth failure. Supporting token state (in-memory + `localStorage`) is managed in `web/src/auth-state.ts`.

**Token kinds:**
1. **JWT access tokens** (short-lived, 15 min) — audience `user.access-token`, sent as `Bearer` header, validated statelessly via signature.
2. **JWT refresh tokens** (long-lived, 30 days) — audience `user.refresh-token`, stored as an `HttpOnly` cookie (`memos_refresh`), validated against the database with rotation on each use.
3. **Personal access tokens (PAT)** — prefixed `memos_pat_`, stored as SHA-256 hashes in the database, used for programmatic/API access.

**Backend validation package:** `server/auth/` (Go package `auth`). Key files: `token.go` (JWT generation/parsing via `golang-jwt/jwt/v5`), `authenticator.go` (`Authenticate()` dispatches to access-token, refresh-token, or PAT validation), and `extract.go` (extracts bearer tokens from headers and refresh tokens from cookies). The server-side interceptor that calls into this package lives at `server/router/api/v1/connect_interceptors.go`.
