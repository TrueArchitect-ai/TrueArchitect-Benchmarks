**Interceptor path:** `web/src/connect.ts` — defines `authInterceptor` (an `Interceptor` for ConnectRPC) that attaches `Authorization: Bearer <token>` to every outgoing request, handles `Unauthenticated` responses by refreshing and retrying once, and redirects on final failure.

**Token kinds managed (three):**

1. **Access token** — a short-lived HS256 JWT (audience `user.access-token`). Stored in-memory and in `localStorage` (`memos_access_token`), synced across tabs via `BroadcastChannel`. Managed in `web/src/auth-state.ts`.
2. **Refresh token** — a long-lived HS256 JWT (audience `user.refresh-token`). Delivered as an `HttpOnly` cookie named `memos_refresh`; never touched by JS directly. Subject to rotation on each use.
3. **Personal Access Token (PAT)** — a random string prefixed `memos_pat_`, stored as a SHA-256 hash in the database. Also sent as a `Bearer` token.

**Backend validation package:** `server/auth/` — specifically:
- `server/auth/authenticator.go` — `Authenticate()` resolves the `Bearer` header, trying access-token JWT validation (`AuthenticateByAccessTokenV2`) then PAT hash lookup (`AuthenticateByPAT`); refresh tokens are validated separately via `AuthenticateByRefreshToken`.
- `server/auth/token.go` — JWT parsing/signing with `github.com/golang-jwt/jwt/v5`.
- `server/auth/extract.go` — extracts bearer tokens from headers and refresh tokens from cookies.

The server-side ConnectRPC interceptor that calls into this package is `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`.
