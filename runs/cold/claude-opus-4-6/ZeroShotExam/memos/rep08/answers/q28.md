**Workers/runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (with an eager `RunOnce` at startup); re-signs expiring S3 attachment URLs. Started explicitly in `server/server.go:153-173` via `startBackgroundRunners()`.
- **Cache Cleanup (×3 goroutines)** — `time.NewTicker` every 5 minutes per cache instance; evicts expired entries from in-memory caches (`instanceSettingCache`, `userCache`, `userSettingCache`). Started implicitly when the store is created in `store/store.go:51-53`, each calling `cleanupLoop()` in `store/cache/cache.go:83`.
- **Webhook Dispatch Workers (×4 goroutines)** — event-driven via a buffered channel (cap 128); drain and POST webhook payloads. Started via `init()` in `internal/webhook/webhook.go:42`.
- **Email Dispatch Workers (×2 goroutines)** — event-driven via a buffered channel (cap 128); drain and send emails. Started via `init()` in `internal/email/email.go:16`.

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — A full-featured cron-expression-based job scheduler (with parser, middleware for recovery/logging/timeout, timezone support, graceful shutdown). It is **never imported** by any production code outside its own package and tests. None of the active runners use it; they all rely on simple `time.NewTicker` loops or channel-based dispatch instead.
- **`server/runner/memopayload.Runner`** — Has a `NewRunner()` constructor and a `RunOnce()` batch method (`server/runner/memopayload/runner.go:19-27`), but the `Runner` struct is **never instantiated** and has no scheduling loop. Only the standalone `RebuildMemoPayload()` function from the same package is called synchronously during memo create/update in `server/router/api/v1/memo_service.go:108,447`.
