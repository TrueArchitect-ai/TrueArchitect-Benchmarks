The following database tables are affected when `DeleteMemo` runs:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
2. **`memo_relation`** — explicit cascade in `store/memo.go:142-146` deletes rows where the memo is either `memo_id` or `related_memo_id`
3. **`attachment`** — explicit cascade in `store/memo.go:149-156` lists and deletes all attachments linked to the memo
4. **`memo_share`** — DB-level `ON DELETE CASCADE` foreign key on `memo_id` references `memo(id)` (`store/migration/sqlite/LATEST.sql:109`), so rows are automatically removed when the memo is deleted

Additionally, the service layer (`server/router/api/v1/memo_service.go:567-577`) recursively deletes comment memos (via `memo_relation` with type `Comment`), which triggers the same `store.DeleteMemo` cascade for each comment — hitting `memo`, `memo_relation`, and `attachment` again for those child memos.

**Table list: `memo`, `memo_relation`, `attachment`, `memo_share`**
