**Interceptor path:** `web/src/connect.ts` — defines a ConnectRPC `Interceptor` (the `authInterceptor` function) that attaches an `Authorization: Bearer <token>` header to every outgoing RPC request, handles `Unauthenticated` errors with a single retry after refreshing, and redirects to the auth page on final failure.

**Token kinds managed:**
1. **JWT Access Token** (short-lived, ~15 min) — stored in-memory and in `localStorage` (`memos_access_token`), managed by `web/src/auth-state.ts`, sent as `Bearer <token>` on every request.
2. **JWT Refresh Token** (long-lived, ~30 days) — stored as an HttpOnly cookie (`memos_refresh`), sent automatically by the browser; used exclusively by the `RefreshToken` RPC endpoint with rotation (server issues a new one each time).
3. **Personal Access Token (PAT)** — prefixed `memos_pat_`, used for programmatic API access, validated server-side via SHA-256 hash lookup.

**Backend validation package:** `server/auth/` — contains `token.go` (JWT generation/parsing via `golang-jwt/jwt/v5`, HS256), `authenticator.go` (the `Authenticator` struct with `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`), and `extract.go` (bearer/cookie extraction). The server-side interceptor that calls into this package is `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`.
