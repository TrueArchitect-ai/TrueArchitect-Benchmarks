When `DeleteMemo` runs, the following database tables are affected:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`, `store/db/postgres/memo.go:246`)
2. **`memo_relation`** — relations where the memo is either source (`MemoID`) or target (`RelatedMemoID`) are explicitly deleted (`store/memo.go:142-146`)
3. **`attachment`** — all attachments linked to the memo are explicitly deleted (`store/memo.go:149-156`)
4. **`memo_share`** — rows referencing the memo are deleted via `ON DELETE CASCADE` foreign key on `memo_id` (`store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`)

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (related via `memo_relation` with type `Comment`) are recursively deleted by calling `DeleteMemo` on each comment, which cascades the same set of table operations for each comment memo.
