The premise is incorrect — this repository does not use Redis at all. There is no Redis connection anywhere in the codebase.

The cache layer is a **custom in-process, in-memory cache** implemented in pure Go at `store/cache/cache.go`. It uses a `sync.Map` for thread-safe storage with TTL-based expiration and a background cleanup goroutine — no external cache server is involved.

The user cache is configured in `store/store.go:38-45`, where a `cache.Config` is created with a **`DefaultTTL` of 10 minutes**. This same config is passed to `cache.New(cacheConfig)` to create the `userCache` field (`store/store.go:52`). Since user entries are stored via `s.userCache.Set(ctx, key, user)` (e.g., `store/user.go:98`), which calls `SetWithTTL` with the default TTL (`store/cache/cache.go:93-94`), **user entries expire after 10 minutes**.

Other cache parameters: cleanup runs every 5 minutes, and the maximum item count is 1,000 per cache instance (`store/store.go:42-43`).
