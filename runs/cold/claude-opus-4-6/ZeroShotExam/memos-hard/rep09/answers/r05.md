The premise is incorrect — there is no GraphQL schema. Memos does not use GraphQL at all.

The public API is defined using **Protocol Buffers (protobuf)**. The source-of-truth service definitions live in `proto/api/v1/*.proto` (e.g., `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, etc.). Each `.proto` file declares gRPC services with `google.api.http` annotations that map RPCs to REST routes.

From those proto definitions, the build pipeline (configured in `proto/buf.gen.yaml`) generates:

1. **REST/JSON endpoints** via gRPC-Gateway, mounted at `/api/v1/*` in `server/router/api/v1/v1.go`
2. **Connect protocol handlers** (for browser clients) at `/memos.api.v1.*`, registered in `server/router/api/v1/connect_services.go`
3. **An OpenAPI 3.0.3 spec** at `proto/gen/openapi.yaml` (~4,000 lines), produced by `protoc-gen-openapi`
4. **TypeScript types** for the web frontend in `web/src/types/proto/`

So the actual API surface is protobuf-defined gRPC exposed over three transports (gRPC, gRPC-Gateway REST, and Connect), not GraphQL.
