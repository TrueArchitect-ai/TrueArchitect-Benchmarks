The premise is incorrect — webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain Go buffered channel** (`chan *WebhookRequestPayload`) with capacity 128, declared at package level in `internal/webhook/webhook.go` (line 39):

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the `init()` function of that same file (lines 41–55), each ranging over the channel and calling `Post()` to make the HTTP request. Work is enqueued via the `PostAsync` function (line 184), which does a non-blocking send — if the channel is full, the webhook is dropped with a warning log.

This is an entirely in-process, non-durable, fire-and-forget delivery system with no external broker, no persistence, and no retry logic.
