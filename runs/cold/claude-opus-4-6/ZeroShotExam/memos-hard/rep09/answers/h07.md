`GET /file/users/:identifier/avatar` — each hop from handler to data:

1. `serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
2. `getUserByUsername` — `server/router/fileserver/fileserver.go:715`
3. `(*Store).GetUser` — `store/user.go:148`
4. `(*Store).ListUsers` — `store/user.go:136`
5. `(*DB).ListUsers` (driver) — `store/db/sqlite/user.go:88` (or `store/db/postgres/user.go` / `store/db/mysql/user.go`)
6. `parseDataURI` — `server/router/fileserver/fileserver.go:737`

The route is registered at `fileserver.go:124`. The handler `serveUserAvatar` optionally authenticates via `getCurrentUser` (`fileserver.go:708`) → `Authenticator.AuthenticateToUser` (`server/auth/authenticator.go`), then calls `getUserByUsername` which delegates to `Store.GetUser`. `GetUser` checks an in-memory cache (by ID only, so misses on username lookups) then calls `Store.ListUsers`, which calls `driver.ListUsers` — the SQL driver builds a `SELECT … avatar_url … FROM user WHERE username = ?` query. The `avatar_url` column stores a base64 data URI (`data:image/png;base64,…`). Back in the handler, `parseDataURI` decodes the base64 payload and the raw image bytes are returned via `c.Blob()`.
