The premise of the question is incorrect. This repository does not have per-user API rate-limiting middleware. No such middleware is registered anywhere, and no per-user request limits are enforced.

The server's middleware stack (`server/server.go:51-52`) consists only of panic recovery and CORS. The API v1 interceptor chain (`server/router/api/v1/v1.go:132-136`) includes metadata conversion, logging, recovery, and authentication — none of which perform rate limiting.

The closest things to request limiting in the codebase are **global concurrency semaphores** (not per-user, not rate limits): a thumbnail semaphore capped at 3 concurrent operations and an image-processing semaphore capped at 2 (`server/router/api/v1/v1.go:39-41`). These guard resource-intensive operations against overload, but they are not per-user and do not count requests over time.

Rate limiting is mentioned only in documentation (`internal/email/doc.go:86`, `internal/email/README.md:286-297`) as a recommended practice with illustrative sample code, but it is never implemented.
