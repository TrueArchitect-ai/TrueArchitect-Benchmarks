A browser `<img>` tag hits `/file/users/:identifier/avatar`. Here is each hop from handler to stored data:

1. `serveUserAvatar` — `server/router/fileserver/fileserver.go`
2. `getUserByUsername` — `server/router/fileserver/fileserver.go`
3. `Store.GetUser` — `store/user.go`
4. `Store.ListUsers` — `store/user.go`
5. `driver.ListUsers` — `store/db/sqlite/user.go` (or `store/db/postgres/user.go` / `store/db/mysql/user.go`)
6. `parseDataURI` — `server/router/fileserver/fileserver.go`

**Details:**

- The Echo router dispatches `GET /file/users/:identifier/avatar` to `serveUserAvatar` (`server/router/fileserver/fileserver.go:167`), registered in `RegisterRoutes` at line ~121.
- `serveUserAvatar` extracts the `:identifier` param (the username) and calls `getUserByUsername` (`server/router/fileserver/fileserver.go:715`), which calls `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`.
- `Store.GetUser` (`store/user.go:148`) checks an in-memory user cache (keyed by ID, so a username lookup misses), then delegates to `Store.ListUsers` (`store/user.go:136`).
- `ListUsers` calls `s.driver.ListUsers(ctx, find)`, dispatching to the concrete DB driver — e.g. the SQLite implementation in `store/db/sqlite/user.go`, which runs `SELECT … avatar_url … FROM user WHERE username = ?` and scans `avatar_url` into the `User.AvatarURL` field.
- Back in `serveUserAvatar`, `parseDataURI` (`server/router/fileserver/fileserver.go:737`) extracts the MIME type and base64-decodes the raw image bytes from the `data:image/…;base64,…` string stored in the column.
- The handler validates the MIME type against `avatarAllowedTypes` (line 75) and returns the decoded bytes via `c.Blob()`.

The avatar is stored as a base64 data URI directly in the `avatar_url` TEXT column of the `user` table (schema: `store/migration/sqlite/LATEST.sql:20`).
