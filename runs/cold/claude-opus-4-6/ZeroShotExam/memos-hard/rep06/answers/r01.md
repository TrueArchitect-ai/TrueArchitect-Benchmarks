The premise is incorrect — this repository (usememos/memos) does **not use Redis** at all. There is no Redis connection anywhere in the codebase.

The cache layer is a **custom in-memory Go cache** implemented in `store/cache/cache.go`. It uses a `sync.Map` for thread-safe storage with TTL-based expiration and a background cleanup goroutine — no external cache service is involved.

The user cache is created in `store/store.go:51` via `cache.New(cacheConfig)` using the same default `cache.Config` defined at `store/store.go:40-45`:

- **Default TTL: 10 minutes** (`10 * time.Minute`) — this applies uniformly to all cache entries including user entries, since `userCache.Set()` calls (e.g., `store/user.go:98`, `:122`, `:132`, `:143`, `:167`) use the no-custom-TTL `Set` method, which delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`).
- **Cleanup interval: 5 minutes** (expired entries are swept every 5 minutes).
- **Max items: 1,000** (with LRU-style eviction of the oldest 20% when exceeded).

There is no per-type TTL override for user entries — they share the same 10-minute default TTL as instance settings and user settings caches, all instantiated with the identical `cacheConfig` in `store/store.go:50-52`.
