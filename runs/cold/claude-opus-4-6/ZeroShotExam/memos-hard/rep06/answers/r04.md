The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is an **in-process Go buffered channel**. In `internal/webhook/webhook.go`, a package-level channel is declared:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the `init()` function of the same file, each consuming from that channel in a `for payload := range asyncPostQueue` loop. `PostAsync()` performs a non-blocking send into the channel; if the 128-slot buffer is full, the webhook is silently dropped with a warning log.

There are no dependencies on NATS, RabbitMQ, Redis, Kafka, or any other external broker in `go.mod`. The "queue" is purely in-memory within the single process.
