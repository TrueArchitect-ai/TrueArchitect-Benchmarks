The premise of the question is incorrect — this repository does not have per-user API rate-limiting middleware. No such middleware is registered anywhere in the codebase.

The server's middleware stack (`server/server.go:50-53`) applies only `middleware.Recover()` and a custom CORS middleware. The Connect RPC interceptor chain (`server/router/api/v1/v1.go:133-138`) consists of `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` — none of which perform rate limiting. There are no rate-limiting library dependencies in `go.mod` (no `golang.org/x/time/rate`, `httprate`, `tollbooth`, etc.), and no HTTP 429 responses anywhere in the server code.

The closest things to throttling are global concurrency semaphores in `server/router/api/v1/v1.go:39-41` that cap concurrent thumbnail generation (3) and image processing (2), but these are not per-user rate limits — they are system-wide concurrency caps on specific operations.
