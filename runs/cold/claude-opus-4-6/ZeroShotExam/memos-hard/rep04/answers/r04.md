The premise is incorrect — the webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all. The entire mechanism is an in-process Go buffered channel with a fixed pool of goroutine consumers.

**The "queue" declaration** is at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

**The workers** are four goroutines spawned in `init()` at `internal/webhook/webhook.go:42–55` — each one range-loops over the channel, calling `Post()` (a synchronous HTTP request) for each payload.

**The producer** is `PostAsync()` at `internal/webhook/webhook.go:184–196`, which does a non-blocking send into the channel; if the channel is full (128 items), the webhook is dropped with a warning log.

There are no external broker dependencies anywhere: `go.mod` contains no NATS, AMQP, or Kafka client libraries, and `scripts/compose.yaml` defines only a single `memos` container with no sidecar broker services.
