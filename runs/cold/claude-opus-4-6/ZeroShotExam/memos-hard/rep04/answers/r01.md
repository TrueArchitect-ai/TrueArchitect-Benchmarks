The premise is incorrect — there is no Redis connection in this repository. The cache layer is a **custom in-memory cache** implemented in pure Go, not backed by Redis.

The cache is implemented at `store/cache/cache.go` as a thread-safe in-memory `Cache` struct with TTL-based expiration and a cleanup goroutine. It is configured in `store/store.go:40-41`, where the default TTL is set to **10 minutes**:

```go
cacheConfig := cache.Config{
    DefaultTTL: 10 * time.Minute,
}
```

This same config is used to create all three cache instances (`store/store.go:51-53`):

- `instanceSettingCache` — for instance settings
- `userCache` — for users
- `userSettingCache` — for user settings

So the TTL that applies to user entries is **10 minutes**, which is the `DefaultTTL` from the shared `cache.Config`. There is no per-cache TTL override for the user cache — all three caches share the same configuration.

The cache itself (`store/cache/cache.go`) supports per-entry TTL overrides via `SetWithTTL()`, but user entries are always stored via `Set()` (`store/user.go`), which uses the default 10-minute TTL.
