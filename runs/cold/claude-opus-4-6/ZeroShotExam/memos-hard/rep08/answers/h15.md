Every distinct server-side enforcement site for memo visibility:

1. `checkMemoReadAccess` (reusable gate for GetMemo, ListMemoComments) — `server/router/api/v1/memo_service.go`
2. `ListMemos` query-level visibility filtering — `server/router/api/v1/memo_service.go`
3. `CreateMemoComment` private-memo check before allowing comment — `server/router/api/v1/memo_service_comments.go`
4. `ListMemoComments` CEL memo filter on comment visibility — `server/router/api/v1/memo_service_comments.go`
5. `ListMemoReactions` inline visibility check — `server/router/api/v1/reaction_service.go`
6. `UpsertMemoReaction` private-memo check before allowing reaction — `server/router/api/v1/reaction_service.go`
7. `ListMemoRelations` CEL visibility filter on related memos — `server/router/api/v1/memo_relation_service.go`
8. `batchConvertMemoRelations` CEL visibility filter during batch relation loading — `server/router/api/v1/memo_service_converter.go`
9. `ListMemoAttachments` inline visibility check — `server/router/api/v1/memo_attachment_service.go`
10. `checkAttachmentAccess` (API/gRPC layer attachment access via memo visibility) — `server/router/api/v1/attachment_service.go`
11. `checkAttachmentPermission` (HTTP file-server layer, includes share-token and private-instance logic) — `server/router/fileserver/fileserver.go`
12. `canReceive` SSE event delivery filtering by visibility — `server/router/api/v1/sse_hub.go`
13. `ListAllUserStats` / `GetUserStats` visibility filtering on stats queries — `server/router/api/v1/user_service_stats.go`
