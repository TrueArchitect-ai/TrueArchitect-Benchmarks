**Explicit Go code**; reactions are deleted by direct SQL `DELETE` statements within the user-deletion transaction — not by any database-level cascade rule.

**Evidence:**

1. **No foreign key / CASCADE on the `reaction` table.** The schema defines `creator_id INTEGER NOT NULL` with no `REFERENCES` or `ON DELETE CASCADE`:
   - `store/migration/sqlite/LATEST.sql:92-99`
   - `store/migration/postgres/LATEST.sql:91-98`
   - `store/migration/mysql/LATEST.sql:91-98`

2. **Go code explicitly deletes reactions in two directions** inside `deleteUserTargetsTx`, within a single transaction:

   - **Reactions on the user's memos** (by `content_id`): `store/db/sqlite/user_delete.go:96-98` calls `deleteReactionsByContentIDsTx` (lines 380–388), which runs `DELETE FROM reaction WHERE content_id IN (...)`.
   - **Reactions the user placed on others' content** (by `creator_id`): `store/db/sqlite/user_delete.go:102-104` calls `deleteReactionsByCreatorTx` (lines 400–403), which runs `DELETE FROM reaction WHERE creator_id = ?`.

   Postgres and MySQL drivers are structurally identical (`store/db/postgres/user_delete.go`, `store/db/mysql/user_delete.go`).

3. **Test coverage confirms both directions**: `store/test/user_delete_test.go:97-114, 216-220` — verifies that a peer's reaction on the deleted user's memo is removed, the deleted user's reaction on a peer's memo is removed, and an unrelated peer-to-peer reaction survives.

**Mechanism: explicit Go code; evidence: `store/db/*/user_delete.go` (delete functions), `store/migration/*/LATEST.sql` (no CASCADE), `store/test/user_delete_test.go` (test verification).**
