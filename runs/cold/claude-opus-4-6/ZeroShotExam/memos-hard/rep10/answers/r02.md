The premise of the question is incorrect. This repository does not have any per-user API rate-limiting middleware. There is no mechanism anywhere in the codebase that tracks or throttles API requests on a per-user basis.

The server registers only recovery and CORS middleware (`server/server.go`), and the Connect RPC interceptor chain (`server/router/api/v1/v1.go:133-137`) uses only metadata, logging, recovery, and auth interceptors — none of which implement rate limiting. No rate-limiting libraries (e.g., `golang.org/x/time/rate`, `tollbooth`) appear in `go.mod`, no HTTP 429 status codes or `X-RateLimit-*` headers exist in the codebase, and no per-user request counters or token-bucket/sliding-window logic is present.

The closest things to resource controls are concurrency semaphores for thumbnail/image processing (`server/router/api/v1/v1.go:59-60`) and a 256 MiB request body size limit (`server/router/api/v1/v1.go:20`), but these are not per-user rate limits.
