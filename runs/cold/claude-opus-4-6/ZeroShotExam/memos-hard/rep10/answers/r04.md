The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all.

The queue is a **plain Go buffered channel** declared as a package-level variable in `internal/webhook/webhook.go:39`:

```go
var asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the `init()` function of the same file (~line 41–55), each draining the channel with `for payload := range asyncPostQueue` and calling `Post(payload)` to make an HTTP POST to the webhook URL.

Work is enqueued via `PostAsync()` (`internal/webhook/webhook.go:184–196`), which does a non-blocking send on the channel — if the buffer (capacity 128) is full, the payload is silently dropped with a warning log. There is no retry, no persistence, and no durability: everything is in-process memory, lost on restart.
