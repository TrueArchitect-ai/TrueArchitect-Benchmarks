The premise is incorrect — this repository does **not** use GraphQL at all. There are zero `.graphql`/`.gql` files, zero GraphQL dependencies, and no GraphQL server or client code anywhere in the codebase.

The public API is defined using **Protocol Buffers (protobuf)**, not GraphQL. The proto service definitions live in `proto/api/v1/` (e.g., `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`). From these proto files, three transport layers are code-generated via the pipeline configured in `proto/buf.gen.yaml`:

1. **gRPC** — generated stubs in `proto/gen/api/v1/*_grpc.pb.go`
2. **REST via gRPC-Gateway** — generated reverse-proxy handlers in `proto/gen/api/v1/*.pb.gw.go`, with an auto-generated OpenAPI 3.0.3 spec at `proto/gen/openapi.yaml`
3. **ConnectRPC** — used by the web frontend (`@connectrpc/connect` and `@connectrpc/connect-web` in `web/package.json`), with TypeScript types generated into `web/src/types/proto/`

The README (`README.md`, line 23) confirms: *"Open & Extensible — MIT-licensed with full REST and gRPC APIs for integration."*
