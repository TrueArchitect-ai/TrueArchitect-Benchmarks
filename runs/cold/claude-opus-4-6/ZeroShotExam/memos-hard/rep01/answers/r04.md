The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all.

The actual mechanism is a **plain in-process Go buffered channel** acting as a bounded queue with a fixed pool of goroutine workers. The entire setup is in `internal/webhook/webhook.go`:

- **Line 39**: A buffered channel of capacity 128 is declared as the queue:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- **Lines 42–55**: An `init()` function spawns **4 goroutine workers**, each consuming from the channel in a loop and calling `Post()` to deliver via HTTP.
- **Lines 184–196**: `PostAsync()` enqueues a payload with a non-blocking send; if the channel is full, the webhook is **silently dropped** with a warning log.

There are no external broker dependencies in the project (`go.mod` contains no NATS, AMQP, or Redis queue libraries). The design is entirely in-process — no persistence, no retries, no dead-letter queue. If the process restarts, in-flight webhooks are lost.
