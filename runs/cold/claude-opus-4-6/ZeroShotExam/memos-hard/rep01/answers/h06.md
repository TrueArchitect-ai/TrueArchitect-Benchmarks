The outbound-HTTP-to-user-configured-URL mechanism in this repo is the **webhook system**. User-configured webhook URLs are stored per user and delivered via `webhook.Post()` (`internal/webhook/webhook.go:120`), which issues an `http.NewRequest("POST", requestPayload.URL, ...)` through an SSRF-guarded `safeClient`.

**RPC handlers that transitively trigger outbound HTTP requests:**

1. **`CreateMemo`** — `server/router/api/v1/memo_service.go` → calls `DispatchMemoCreatedWebhook`
2. **`UpdateMemo`** — `server/router/api/v1/memo_service.go` → calls `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`
3. **`DeleteMemo`** — `server/router/api/v1/memo_service.go` → calls `DispatchMemoDeletedWebhook`
4. **`CreateMemoComment`** — `server/router/api/v1/memo_service_comments.go` → calls `DispatchMemoCommentCreatedWebhook` (and internally `CreateMemo`, which also fires the created webhook)
5. **`SetMemoRelations`** — `server/router/api/v1/memo_relation_service.go` → calls `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`
6. **`SetMemoAttachments`** — `server/router/api/v1/memo_attachment_service.go` → calls `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`

**Convergence function:** `dispatchMemoRelatedWebhook` — `server/router/api/v1/memo_service_webhooks.go:48`

This single private method is where the created/updated/deleted handler paths all converge. It resolves the memo creator, fetches their webhooks from the store, builds the payload, and calls `webhook.PostAsync()` for each configured URL. (The comment-created path at line 30 of the same file is structurally parallel but targets the *parent memo owner's* webhooks rather than the comment creator's; both feed into the same `webhook.PostAsync` → `webhook.Post` delivery pipeline.)
