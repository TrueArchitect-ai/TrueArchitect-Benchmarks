The premise of the question is incorrect — this repository does not have per-user API rate-limiting middleware. No such middleware is registered anywhere, and no request limits (per user, per IP, or otherwise) are enforced.

The closest things in the codebase are:

- **Global concurrency semaphores** (not per-user rate limits) in `server/router/api/v1/v1.go:39-41` that cap concurrent thumbnail generation (3) and image processing (2). These return `codes.ResourceExhausted` when full (`server/router/api/v1/attachment_service.go:160`), but they are not time-windowed or per-user.
- **Documentation-only mentions** in `internal/email/doc.go:86` and `internal/email/README.md:286-297` that recommend implementing rate limiting for email sending, but no actual implementation exists.

The actual middleware/interceptor chains registered in `server/server.go:51-52` (Recover, CORS) and `server/router/api/v1/v1.go:132-138` (Metadata, Logging, Recovery, Auth interceptors) contain no rate limiter.
