The premise is incorrect — there is no Redis connection in this repository. The cache layer is an **in-memory Go cache**, not Redis-backed.

The cache is implemented in `store/cache/cache.go` as a thread-safe in-memory store using `sync.Map` with TTL-based expiration. It is instantiated in `store/store.go:38-45`, where `Store.New()` creates a `cache.Config` with a **default TTL of 10 minutes** (`10 * time.Minute`) for all cache entries, including user entries. The `userCache` field (`store/store.go:28`) is created with this same config at `store/store.go:52`.

User entries are cached by user ID (key derived via `userCacheKey()` in `store/user.go:88-90`) using the default `Set()` method (`store/user.go:98, 122, 132, 143, 167`), which applies the default 10-minute TTL. There is no per-type TTL override for user entries — they use the same `DefaultTTL` as all other cached data. Expired entries are cleaned up by a background goroutine running every 5 minutes (`CleanupInterval: 5 * time.Minute` at `store/cache/cache.go:61`).
