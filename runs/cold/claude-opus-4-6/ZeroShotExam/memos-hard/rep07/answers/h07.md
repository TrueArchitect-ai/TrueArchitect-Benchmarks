`GET /file/users/:identifier/avatar` — each hop from route to data:

1. `FileServerService.RegisterRoutes` — `server/router/fileserver/fileserver.go:121`
2. `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
3. `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715`
4. `Store.GetUser` — `store/user.go:148`
5. `Store.ListUsers` — `store/user.go:136`
6. `Driver.ListUsers` (interface) — `store/driver.go:47`

8. `FileServerService.parseDataURI` — `server/router/fileserver/fileserver.go:737`

The route dispatches to `serveUserAvatar`, which calls `getUserByUsername` with the URL's `:identifier` param. That calls `Store.GetUser` with a `FindUser{Username}`, which delegates to `Store.ListUsers`, which calls the `Driver.ListUsers` interface method (implemented e.g. by SQLite's `DB.ListUsers` querying `SELECT ... avatar_url ... FROM user WHERE username = ?`). The returned `User.AvatarURL` field holds a base64-encoded data URI; `parseDataURI` decodes it and the raw image bytes are sent back via `c.Blob`.
