The premise is incorrect — there is no GraphQL schema. The public API is defined using **Protocol Buffers (protobuf)** with **gRPC-Gateway**, not GraphQL.

The API surface is defined by `.proto` files in `proto/api/v1/`:

- `memo_service.proto`
- `user_service.proto`
- `auth_service.proto`
- `attachment_service.proto`
- `idp_service.proto`
- `instance_service.proto`
- `ai_service.proto`
- `shortcut_service.proto`
- `common.proto`

These protobuf definitions are used to generate:

1. **gRPC stubs** (Go) — in `proto/gen/api/v1/` (e.g., `*_grpc.pb.go`)
2. **gRPC-Gateway REST handlers** (Go) — in `proto/gen/api/v1/` (e.g., `*.pb.gw.go`)
3. **OpenAPI spec** — at `proto/gen/openapi.yaml`

Code generation is configured via `proto/buf.gen.yaml` using the Buf toolchain. The result is a dual REST + gRPC API, not a GraphQL one.
