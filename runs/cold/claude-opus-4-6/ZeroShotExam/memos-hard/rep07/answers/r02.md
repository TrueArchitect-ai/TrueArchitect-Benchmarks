The premise of the question is incorrect — this repository does not contain any per-user API rate-limiting middleware. No such middleware is registered anywhere, and no rate-limiting libraries are imported.

The server's middleware stack in `server/server.go` consists only of `middleware.Recover()` and a CORS middleware. The API layer in `server/router/api/v1/v1.go` registers Connect interceptors for metadata, logging, recovery, and authentication — but none for rate limiting. No HTTP 429 responses, `Retry-After` headers, or rate-limiting packages (e.g., `golang.org/x/time/rate`, `httprate`, `tollbooth`) appear in the codebase.

The closest constructs are global concurrency semaphores (e.g., `thumbnailSemaphore` capped at 3, `imageProcessingSemaphore` capped at 2) in `server/router/api/v1/v1.go` and `server/router/fileserver/fileserver.go`, but these limit concurrent CPU-heavy operations globally, not per-user request rates.
