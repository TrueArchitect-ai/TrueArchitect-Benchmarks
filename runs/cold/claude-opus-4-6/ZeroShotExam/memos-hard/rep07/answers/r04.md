The premise is incorrect — the webhook delivery workers do not consume from either NATS or RabbitMQ. There is no external message broker involved at all.

The actual mechanism is an **in-process Go buffered channel**. The queue is declared at package level in `internal/webhook/webhook.go` (line 39):

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the package's `init()` function (same file, lines 42–55), each running `for payload := range asyncPostQueue` to consume payloads and call `Post()` to make the HTTP request. The producer side (`PostAsync`) uses a non-blocking send with a `select`/`default` — if the 128-slot buffer is full, the webhook is silently dropped with a warning log rather than blocking the caller.
