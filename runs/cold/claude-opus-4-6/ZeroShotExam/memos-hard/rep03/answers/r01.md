The premise is incorrect — this repository does **not** use Redis. There is no Redis connection anywhere in the codebase.

The cache layer is a **custom in-memory cache** (not Redis) implemented in pure Go at `store/cache/cache.go`. It uses a `sync.Map` for thread-safe storage with TTL-based expiration and a background cleanup goroutine.

The cache is configured in `store/store.go:40-45` when the `Store` is created, with these settings applied uniformly to **all** caches (including the user cache):

- **DefaultTTL**: 10 minutes
- **CleanupInterval**: 5 minutes
- **MaxItems**: 1000

The `userCache` field (`store/store.go:28`) is instantiated at `store/store.go:52` using `cache.New(cacheConfig)` with the same 10-minute TTL as every other cache (instance settings, user settings). There is no per-entity TTL override for user entries — they all use the shared `DefaultTTL` of 10 minutes, unless a caller explicitly uses `SetWithTTL` (`store/cache/cache.go:98`) to specify a different duration.
