The premise of the question is incorrect — this repository does not have per-user API rate-limiting middleware. No such middleware is registered anywhere in the codebase.

The server's middleware/interceptor chains contain no rate limiter:

- **Echo middleware** (`server/server.go:51-52`): only `Recover()` and CORS.
- **Connect interceptors** (`server/router/api/v1/v1.go:133-137`): only `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor`.
- **gRPC-Gateway middleware** (`server/router/api/v1/v1.go:97`): only `gatewayAuthMiddleware`.

No rate-limiting libraries (e.g. `golang.org/x/time/rate`, `tollbooth`, `httprate`) are imported in application code, and no files or directories relate to rate limiting.

The closest mechanisms are **global concurrency semaphores** for image/thumbnail processing (`server/router/api/v1/v1.go:39-41` — 3 concurrent thumbnails, 2 concurrent image-processing requests) and a **request body size cap** of 256 MiB (`server/router/api/v1/v1.go:20`), but neither is per-user rate limiting.
