The premise of the question is incorrect. This repository does not have any per-user API rate-limiting middleware. No such middleware is registered anywhere, and no request limits are configured.

The server's middleware/interceptor stacks are defined in two places:

- **`server/server.go`** (lines 51–52): Registers only `Recover()` and CORS middleware on the Echo router.
- **`server/router/api/v1/v1.go`** (lines 133–138): Registers four gRPC interceptors — `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` — none of which perform rate limiting.

There are no rate-limiting libraries in `go.mod` or `web/package.json` (no `golang.org/x/time/rate`, `tollbooth`, `express-rate-limit`, etc.).

The closest thing to request limiting is **global concurrency semaphores** for image processing in `server/router/api/v1/v1.go` (lines 39–41, 59–60), which cap simultaneous thumbnail/image operations at 2–3 concurrently — but these are not per-user and do not enforce a request rate over time.
