The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all.

The actual mechanism is a **plain Go buffered channel** serving as an in-process queue. It is declared in `internal/webhook/webhook.go` (line 39):

```go
var asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in an `init()` function (lines 42–55 of the same file) that range over this channel and call `Post()` for each payload. Jobs are enqueued via the `PostAsync()` function (lines 184–196), which does a non-blocking send — if the channel's 128-slot buffer is full, the webhook is silently dropped with a log warning.

There is no external broker dependency (NATS, RabbitMQ, Redis, etc.) anywhere in the codebase, nor any PostgreSQL-based queue mechanism. The entire webhook delivery pipeline is in-process, fire-and-forget, with no persistence or retry logic.
