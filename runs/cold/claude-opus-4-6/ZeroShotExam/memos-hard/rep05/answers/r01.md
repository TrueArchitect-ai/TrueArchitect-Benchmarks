The premise is incorrect — this repository (usememos/memos) does not use Redis at all. There is no Redis connection configured anywhere in the codebase.

The cache layer is a **custom in-memory cache** implemented in pure Go, not backed by any external store. It is defined in `store/cache/cache.go` and uses a `sync.Map` with a background cleanup goroutine — no network connections, no Redis client, no external dependencies.

The `userCache` is created in `store/store.go:52` with the same shared `cache.Config` constructed at `store/store.go:40-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

So the **TTL for user entries is 10 minutes**, applied uniformly — the `userCache`, `userSettingCache`, and `instanceSettingCache` all share the identical configuration. All calls to cache users (e.g., `store/user.go:98`, `:122`, `:132`, `:143`, `:167`) use `s.userCache.Set(ctx, userCacheKey(user.ID), user)`, which delegates to the default TTL via `cache/cache.go:93-94`. No call site overrides the TTL with `SetWithTTL`.
