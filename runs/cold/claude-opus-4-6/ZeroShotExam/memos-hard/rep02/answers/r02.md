The premise of the question is incorrect. This repository does **not** have per-user API rate-limiting middleware. No middleware tracking or limiting the number of requests a user can make over time is registered anywhere.

The middleware chain registered in `server/server.go:51-52` consists only of panic recovery (`middleware.Recover()`) and CORS (`newCORSMiddleware(profile)`).

What the codebase does have — which is conceptually adjacent but distinct — are **concurrency-limiting semaphores** for resource-intensive operations, not time-windowed rate limits:

- `server/router/api/v1/v1.go:40-41` — `thumbnailSemaphore` (max 3 concurrent) and `imageProcessingSemaphore` (max 2 concurrent)
- `server/router/fileserver/fileserver.go:45-46` — a separate `thumbnailSemaphore` (max 3 concurrent)

There are also per-request **batch size caps** (e.g., 100 items for batch-get/delete endpoints in `attachment_service.go`, `user_service.go`, `instance_service.go`), but these limit payload size per call, not request frequency per user.
