The premise is incorrect — this repository (usememos/memos) does not use Redis at all. There is no Redis connection anywhere in the codebase.

The cache layer is a **custom in-memory cache** implemented in pure Go at `store/cache/cache.go`. It uses a `sync.Map` for thread-safe storage with TTL-based expiration and a background cleanup goroutine — no external cache service is involved.

The `userCache` is instantiated in `store/store.go:51` via `cache.New(cacheConfig)`, where `cacheConfig` is defined at lines 40–45 with a **`DefaultTTL` of 10 minutes**. This same configuration (10-minute TTL, 5-minute cleanup interval, max 1000 items) is shared across all three caches: `instanceSettingCache`, `userCache`, and `userSettingCache`.

User entries are cached on create, update, list, get, and delete operations in `store/user.go`, using a simple numeric user ID as the cache key (line 88–90: `strconv.Itoa(int(userID))`).
