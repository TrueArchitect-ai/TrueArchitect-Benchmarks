The premise is incorrect — webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **Go buffered channel** functioning as an in-process async queue, declared in `internal/webhook/webhook.go` at line 39:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the `init()` function (lines 42–55) of the same file, each consuming from this channel in an infinite loop and calling `Post()` to deliver the webhook. The `PostAsync()` function (line 184) enqueues payloads with a non-blocking send, silently dropping webhooks with a warning log if the 128-slot buffer is full. There is no external queue dependency, no broker configuration, and no retry logic — everything is in-process and ephemeral.
