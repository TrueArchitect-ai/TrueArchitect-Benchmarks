**Source:** Frontend API requests are authenticated as follows:

1. **Frontend interceptor** (`authInterceptor` at lines 156-178 in `/bench/repo/web/src/connect.ts`): Intercepts all requests made through the ConnectRPC transport, retrieves or refreshes the access token, and sets it in the Authorization header. On 401 response, automatically attempts to refresh the token via the `RefreshToken` RPC before retrying the request.

2. **Tokens managed** (defined in `/bench/repo/web/src/auth-state.ts`):
   - **Access Token**: Short-lived JWT token (managed in localStorage with `memos_access_token` key)
   - **Refresh Token**: Long-lived JWT token stored in HttpOnly cookies (name: `memos_refresh`)
   - Tokens are synced across browser tabs via BroadcastChannel to avoid duplicate refresh requests

3. **Backend validation** (`/bench/repo/server/auth` package): Validates tokens as documented at line 1-11 in `/bench/repo/server/auth/token.go`. The package supports:
   - JWT access tokens (15-minute lifetime, audience: "user.access-token")
   - JWT refresh tokens (30-day lifetime, audience: "user.refresh-token") 
   - Personal Access Tokens (PAT) for programmatic access
