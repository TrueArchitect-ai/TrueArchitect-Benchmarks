CEL (Common Expression Language) via google/cel-go — /bench/repo/internal/filter/engine.go; The filter engine parses CEL expressions into a dialect-agnostic condition tree, then renders that tree to dialect-specific SQL (SQLite, MySQL, PostgreSQL) during query execution in each driver's ListMemos method via AppendConditions helper.

**Source:** The filtering mechanism works as follows:
1. **Engine + Path**: CEL (Common Expression Language) using the `google/cel-go` library is parsed by the `Engine` struct in `/bench/repo/internal/filter/engine.go` (line 14). The engine is created with a schema and compiles CEL expressions via `Compile()` method (line 48).
2. **Mechanism**: The filter engine creates a dialect-agnostic condition tree from the CEL expression (lines 61-80 in `/bench/repo/internal/filter/render.go` show the `renderCondition` method that handles different condition types). When ListMemos is called with a filter string (as seen in `/bench/repo/server/router/api/v1/memo_service.go` line 215), it's stored in `FindMemo.Filters`. The filter is then validated using `validateFilter()` which compiles it to SQL using the detected dialect. During actual query execution in each dialect driver (e.g., `/bench/repo/store/db/sqlite/memo.go` line 61), the `AppendConditions()` helper from `/bench/repo/internal/filter/helpers.go` compiles each filter string to a dialect-specific SQL statement via `engine.CompileToStatement()`, passing the appropriate dialect (SQLite, MySQL, or PostgreSQL) to render the condition tree as native SQL for that dialect.
