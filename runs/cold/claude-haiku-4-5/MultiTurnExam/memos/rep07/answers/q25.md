CEL (Common Expression Language) — /bench/repo/internal/filter/engine.go; Filter expressions are compiled to a dialect-agnostic IR tree by `filter.DefaultEngine()`, then rendered to dialect-specific SQL via the `Render()` method which walks the tree and generates appropriate SQL syntax for SQLite, MySQL, or PostgreSQL including placeholder styles, JSON access patterns, and boolean semantics.

The ListMemos RPC filter mechanism works as follows:

1. **Engine + Location**: CEL (Common Expression Language) parsed by `filter.DefaultEngine()` at `/bench/repo/internal/filter/engine.go`

2. **Mechanism in one sentence**: Filter expressions are parsed as CEL expressions validated against the memo schema, converted to a dialect-agnostic intermediate representation (IR), then rendered by the `Render()` method into SQL fragments tailored to the target dialect (SQLite/MySQL/PostgreSQL) with appropriate placeholder styles, JSON access patterns, boolean coercions, and dialect-specific functions.

The pipeline (from `/bench/repo/internal/filter/README.md`):
- **Phase 1 (Parsing)**: CEL expressions validated by `cel-go` against the schema in `schema.go`
- **Phase 2 (Normalization)**: Raw CEL AST converted to dialect-agnostic IR in `parser.go`
- **Phase 3 (Rendering)**: IR translated to SQL by `render.go` using `AppendConditions()` helper in `helpers.go`, which appends each filter's SQL fragment and placeholder args to the store driver's WHERE clause
