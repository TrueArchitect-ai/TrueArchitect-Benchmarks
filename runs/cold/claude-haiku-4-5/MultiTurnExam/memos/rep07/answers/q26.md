When `DeleteMemo` runs in the store layer (`/bench/repo/store/memo.go` line 140), the following database tables are affected:

   - Deletes records where `memo_id = delete.ID` (line 142)
   - Deletes records where `related_memo_id = delete.ID` (line 145)

3. **attachment** — Explicitly deleted by store code before the memo is deleted (lines 149-156) via `s.DeleteAttachment()` calls for each attachment linked to the memo

4. **memo_share** — Deleted by database CASCADE constraint (`FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in `/bench/repo/store/migration/sqlite/LATEST.sql`)

Note: **reaction** records are NOT deleted when a memo is deleted. These orphaned records remain in the database with `content_id` pointing to the deleted memo's resource name.
