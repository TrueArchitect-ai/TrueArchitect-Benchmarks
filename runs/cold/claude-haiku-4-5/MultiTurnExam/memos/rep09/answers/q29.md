Frontend API requests are authenticated as follows:

1. **Auth interceptor location**: `/bench/repo/web/src/connect.ts` (line 156) — the `authInterceptor` intercepts all Connect RPC requests, manages token refresh, and handles retry logic

2. **Token kinds managed**:

   - **Refresh tokens** (long-lived JWT, 30-day duration) — stored in HttpOnly cookies, used to obtain new access tokens via `RefreshToken()` RPC (defined in `/bench/repo/web/src/auth-state.ts`)

3. **Backend validation package**: `/bench/repo/server/auth` — validates tokens via:
   - `Authenticator.AuthenticateByAccessTokenV2()` (line 41 in `/bench/repo/server/auth/authenticator.go`) for JWT access token validation
   - `Authenticator.AuthenticateByRefreshToken()` for refresh token validation
   - Both methods used by API interceptors (Connect and gRPC-Gateway) to authenticate incoming requests
