**Premise correction:** There is no external message broker (NATS or RabbitMQ) used for webhook delivery.

**Actual mechanism:** Webhook delivery workers consume from an in-memory Go channel declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The queue is declared with a buffer capacity of 128 messages. Four consumer goroutines are started in the `init()` function (internal/webhook/webhook.go:42-55) that continuously consume from this channel and call `Post()` to deliver webhooks. When `PostAsync()` is called (internal/webhook/webhook.go:184), payloads are sent to this channel for asynchronous delivery. If the channel buffer is full, the message is dropped with a warning log.

This is a simple in-process queue mechanism using Go channels, not an external message broker.
