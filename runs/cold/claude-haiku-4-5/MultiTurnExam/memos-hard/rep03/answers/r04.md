**Premise correction**: There is no external message broker (NATS or RabbitMQ) used for webhook delivery. The webhook delivery workers consume from an in-memory Go channel.

**Actual mechanism**: Webhook delivery is implemented as an in-memory async queue in `/bench/repo/internal/webhook/webhook.go:39`, where `asyncPostQueue` is declared as a buffered channel with capacity of 128:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned on initialization (`/bench/repo/internal/webhook/webhook.go:42-54`) to consume from this channel and execute the webhook delivery via `Post()`. When `PostAsync()` is called (`/bench/repo/internal/webhook/webhook.go:184`), it enqueues payloads onto this channel for the workers to process asynchronously. There is no persistent queue, no message broker, and no resilience to process restarts—webhooks queued but not yet delivered when the server shuts down are lost.
