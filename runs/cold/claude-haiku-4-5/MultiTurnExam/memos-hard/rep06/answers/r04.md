**Premise correction:** The question assumes webhook delivery uses an external message broker (NATS or RabbitMQ), but this is not the case.

**Actual mechanism:** Webhook delivery uses an **in-memory Go channel** as the queue, not an external message broker. The queue is declared as:

- **Queue declaration:** `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `/bench/repo/internal/webhook/webhook.go:39`

- **Workers:** 4 goroutines are spawned in the `init()` function (lines 42-55) that consume from this channel and execute the webhook delivery via the `Post()` function — `/bench/repo/internal/webhook/webhook.go:42-55`

- **Delivery method:** `PostAsync()` enqueues webhook requests to this channel — `/bench/repo/internal/webhook/webhook.go:184-195`

This is an in-process, non-persistent queue with bounded capacity (128 items). Webhook requests exceeding this capacity are dropped with a warning log message.
