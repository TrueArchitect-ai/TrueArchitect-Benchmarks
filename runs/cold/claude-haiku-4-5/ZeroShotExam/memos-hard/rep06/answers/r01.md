**Premise Correction:** There is no Redis connection. The cache layer uses an in-memory cache implementation, not Redis.

**Actual Mechanism:**

The cache is configured in `/bench/repo/store/store.go` (lines 38-61), where three separate in-memory caches are initialized, including a `userCache`. The implementation is defined in `/bench/repo/store/cache/cache.go`.

**TTL for User Entries:** **10 minutes** (DefaultTTL)

User entries are cached using this default TTL when operations like `CreateUser()`, `UpdateUser()`, `ListUsers()`, and `GetUser()` are called in `/bench/repo/store/user.go`. The cache uses a background cleanup goroutine that runs every 5 minutes to evict expired entries. There is no external configuration of this TTL—it is hardcoded in the cache implementation.
