**Premise correction:** The webhook delivery workers do not use NATS or RabbitMQ. This is a false dichotomy in the question.

**Actual mechanism:** The webhook delivery system uses an **in-process buffered Go channel** as its queue implementation.

**Queue declaration location:** `/bench/repo/internal/webhook/webhook.go` (lines 39-55)

The queue is declared as:
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

A buffered channel with capacity of 128 webhook payloads. Four concurrent worker goroutines are initialized at package load time, each consuming from this channel in an infinite loop and calling `Post()` to send the HTTP request. Messages enqueued via `PostAsync()` are sent to this channel, with excess messages dropped if the queue is full (with a warning log).

No external message broker is involved—this is a lightweight, in-memory, single-process queue implementation.
