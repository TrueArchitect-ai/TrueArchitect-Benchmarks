**Premise correction:** There is no per-user API rate-limiting middleware registered in this codebase.

After exhaustive searching of the repository, including middleware registration, interceptors, and configuration, I found no implementation of per-user API rate-limiting. The only request limiting mechanisms in place are:

1. **Global request size limit** (`server/router/api/v1/v1.go:20`): 256 MB max request bytes via `http.MaxBytesHandler`
2. **Concurrency limits for specific operations** (not per-user API rate limiting):
   - Thumbnail generation: Limited to 3 concurrent operations (`server/router/fileserver/fileserver.go`)
   - Image processing: Limited to 2 concurrent operations (`server/router/api/v1/v1.go:60`)
3. **Content validation** (`server/router/api/v1/memo_service.go`): Content length limits per instance settings

The server registers only two middleware at initialization (`server/server.go:51-52`): panic recovery and CORS handling. The API layer uses Connect RPC interceptors for authentication/authorization, logging, and recovery—none implementing per-user rate limiting.
