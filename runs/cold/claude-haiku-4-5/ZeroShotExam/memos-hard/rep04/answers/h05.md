h05.

When a user is deleted, emoji reactions are removed by **explicit Go code**, not by database-level rules.

**Evidence locations:**

1. **Deletion logic**: `/bench/repo/store/db/mysql/user_delete.go` lines 417-440
   - `deleteReactionsByContentIDsTx()` removes reactions to the deleted user's memos
   - `deleteReactionsByCreatorTx()` removes reactions created by the deleted user

2. **No foreign key constraints**: All migration files (`/bench/repo/store/migration/mysql/0.20/00__reaction.sql`, etc.) define the `reaction` table with only a UNIQUE constraint on `(creator_id, content_id, reaction_type)` — no `FOREIGN KEY` on `creator_id` pointing to `user(id)`, and no `ON DELETE CASCADE` clauses.

3. **Deletion order in transaction**: `/bench/repo/store/db/mysql/user_delete.go` lines 92-127 in `deleteUserTargetsTx()` explicitly calls reaction cleanup at lines 96 and 102 before deleting the user row.

4. **Test verification**: `/bench/repo/store/test/user_delete_test.go` lines 97-220 confirm both types of reactions are cleaned up during user deletion.
