Based on my comprehensive search of the repository, **there is no per-user API rate-limiting middleware registered in this codebase.**

However, the application does implement several resource-limiting mechanisms:

**Concurrency-based limits (closest to rate-limiting):**
- `/bench/repo/server/router/api/v1/v1.go:39-60` — Image processing semaphores:
  - `thumbnailSemaphore`: Limited to 3 concurrent thumbnail generations
  - `imageProcessingSemaphore`: Limited to 2 concurrent image processing operations
  - Enforced in `/bench/repo/server/router/api/v1/attachment_service.go:160`

**Other resource limits:**
- `/bench/repo/server/router/api/v1/v1.go:20` — Global request body limit: 256 MiB (`maxAPIRequestBytes`)
- `/bench/repo/server/router/api/v1/attachment_service.go` — Configurable file upload size limit (default 32 MiB)
- `/bench/repo/server/router/api/v1/attachment_service.go:35` — Batch delete limit: 100 attachments

The middleware registered in `/bench/repo/server/server.go:51-52` includes only `Recover()` and CORS middleware. There are no per-user request-rate-limiting middleware (like token bucket, leaky bucket, or request-quota-based implementations).
