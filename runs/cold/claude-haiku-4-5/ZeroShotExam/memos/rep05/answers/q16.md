Based on the store layer implementation in `/bench/repo/store/memo.go`, when a memo is deleted through the API, the store layer deletes the following records **before** the memo row itself:

1. **memo_relation** - All relations where the memo is the source (MemoID) or target (RelatedMemoID)
2. **attachment** - All attachments linked to the memo (including physical storage cleanup)

Note: The API layer in `/bench/repo/server/router/api/v1/memo_service.go` also recursively deletes any comment memos before calling the store layer's `DeleteMemo`, but the store layer itself handles the memo_relation and attachment deletions as the final cascading steps before the memo row is removed from the database.
