To summarize for clarity:

**q25.**

**Engine + path:** Google's CEL (cel-go library), wrapped in a custom `Engine` at `internal/filter/engine.go`.

**Mechanism:** CEL expression is parsed by `Engine.Compile()` via `cel.Env.Compile()` into an AST, then converted to a dialect-agnostic condition tree by `buildCondition()` in `internal/filter/parser.go`.

**SQL conversion:** The condition tree is rendered to dialect-specific SQL via `renderer.renderCondition()` in `internal/filter/render.go`, using dialect-specific SQL templates from the schema (e.g., MySQL CONCAT vs SQLite || for concatenation). Each DB driver calls `filter.AppendConditions()` to compile filters into `Statement` objects with SQL and parameters for that dialect (SQLite, MySQL, PostgreSQL).
