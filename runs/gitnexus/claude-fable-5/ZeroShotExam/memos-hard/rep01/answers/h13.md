- **Impl:** The unexported `service` struct in `internal/markdown/markdown.go:58` is the only concrete implementation of the `markdown.Service` interface (defined at `internal/markdown/markdown.go:31`). It wraps a `goldmark.Markdown` engine and is the sole runtime implementation — there are no alternates (the interface's methods delegate to goldmark parsing plus a `MarkdownRenderer` from `internal/markdown/renderer/markdown_renderer.go` for AST-to-markdown output).

- **Construction:** `markdown.NewService(...)` (`internal/markdown/markdown.go:85`) is the only factory. At runtime it is called exactly once, in `NewAPIV1Service` at `server/router/api/v1/v1.go:48`, with `markdown.WithTagExtension()` and `markdown.WithMentionExtension()` enabled. (A second call exists only in test code: `server/router/api/v1/test/test_helper.go:44`.)

- **Holders:** Two components hold the interface at runtime:
  1. `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — used for snippets, mention/tag extraction, and payload rebuilds (e.g., `server/router/api/v1/memo_service_webhooks.go:85`, `memo_mention_helpers.go:32`).
  2. `RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — injected in `server/server.go:85`, where `rss.NewRSSService(...)` receives the same instance from `apiV1Service.MarkdownService`; used for server-side HTML rendering of RSS feeds (`rss.go:339`).

  A third struct, `memopayload.Runner` (`server/runner/memopayload/runner.go:16`), also declares a `MarkdownService markdown.Service` field, but its constructor `NewRunner` has no callers in the codebase — production code instead passes the interface directly to the free function `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)` (`server/router/api/v1/memo_service.go:108`), so the Runner holder never materializes at runtime.

So both runtime holders share one `*service` instance created in `NewAPIV1Service`.
