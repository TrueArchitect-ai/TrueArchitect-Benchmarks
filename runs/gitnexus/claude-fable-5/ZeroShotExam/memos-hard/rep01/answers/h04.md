**Yes** — but only in a unit test inside the driver's own package; all production code goes through the factory.

Evidence:

- **The factory** is `NewDBDriver` in `store/db/db.go`, which calls `mysql.NewDB(profile)` at `store/db/db.go:22`. A repo-wide grep shows this is the *only* call to `mysql.NewDB`, and `store/db/db.go:8` is the only file anywhere that imports `github.com/usememos/memos/store/db/mysql`.
- **The one direct construction** is in `store/db/mysql/auth_config_test.go:12`, where the test builds the driver struct literally (`db := &DB{}`) — bypassing `NewDB` entirely — to unit-test `IsRetryableAuthenticationMutationError` without a real database connection. Being in package `mysql` itself, it doesn't need the import.
- The integration tests in `store/test/` do **not** construct it directly: `store/test/store.go:28` and `:50` obtain drivers via `db.NewDBDriver(profile)`. The `mysql` imports in `store/test/containers.go` are the `go-sql-driver/mysql` client library and the testcontainers MySQL module, not the memos MySQL driver package.

So: no direct construction anywhere in production code; one direct struct-literal instantiation in the driver package's own unit test (`store/db/mysql/auth_config_test.go:12`).
