Delivery function — `Post()` in `internal/webhook/webhook.go` (line 120), which marshals the payload and sends the POST via a shared `safeClient`; asynchronous dispatch goes through `PostAsync()`/the worker queue in the same file, which ultimately calls `Post()`. Callers trigger this from the memo webhook dispatch code in `server/router/api/v1/memo_service_webhooks.go`.

Protection mechanism — SSRF guarding split across two layers, both in the `internal/webhook` package:

1. **Dial-time blocking (the real enforcement):** `safeClient`'s transport uses `safeDialContext()` (`internal/webhook/webhook.go:59`), which re-resolves the target hostname at connect time and refuses any address matching a reserved/private range via `isReservedIP()`. Doing this at dial time also defeats DNS-rebinding tricks.
2. **Registration-time validation:** `ValidateURL()` in `internal/webhook/validate.go` rejects webhook URLs whose scheme isn't http/https or whose hostname resolves to a reserved IP when the webhook is created/updated.

The blocked ranges (`reservedCIDRs` in `internal/webhook/validate.go:14`) cover IPv4/IPv6 loopback, RFC-1918 private ranges, unique-local, and link-local — including the cloud metadata address 169.254.169.254. An escape hatch, `AllowPrivateIPs` (`internal/webhook/validate.go:41`), can disable the check for self-hosted deployments that intentionally target LAN services.
