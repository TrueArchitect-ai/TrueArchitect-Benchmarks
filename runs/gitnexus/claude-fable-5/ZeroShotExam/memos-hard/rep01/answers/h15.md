Memo visibility is enforced independently in several server surfaces. The distinct enforcement sites are:

1. **gRPC Memo API — read access check** — `checkMemoReadAccess` in `server/router/api/v1/memo_service.go` (lines 39–68): non-public memos require authentication, and private memos are viewable only by their creator. Used by `GetMemo`. The same file also scopes `ListMemos` (lines ~218–228) by injecting a visibility filter (`PUBLIC` only for anonymous users; `creator_id == me || visibility in ["PUBLIC","PROTECTED"]` for authenticated users).

2. **Attachment API — access via linked memo** — `checkAttachmentAccess` in `server/router/api/v1/attachment_service.go` (~lines 435–455): `GetAttachment`/attachment reads resolve the linked memo and deny access if it's private and the requester isn't the creator or a superuser.

3. **Raw file server (HTTP blob route)** — `server/router/fileserver/fileserver.go` (~lines 680–705): before serving attachment bytes it checks the owning memo's visibility (private → creator or admin only), with a share-token fallback that grants access when a valid, unexpired `share_token` for that specific memo is presented.

4. **Memo attachments listing** — `server/router/api/v1/memo_attachment_service.go` (lines ~210–225): `ListMemoAttachments` re-checks memo visibility (unauthenticated denied for non-public; private restricted to creator/superuser).

5. **Reactions API** — `server/router/api/v1/reaction_service.go` (lines 30–90): both `ListMemoReactions` and `UpsertMemoReaction` deny access to private memos for non-creators/non-superusers.

6. **Comments API** — `server/router/api/v1/memo_service_comments.go` (line 41): creating a comment checks the parent memo's visibility (private → creator/superuser only).

7. **SSE real-time event hub** — `SSEClient.canReceive` in `server/router/api/v1/sse_hub.go` (lines 134–144): broadcast events for private memos are delivered only to the creator or an admin; unknown visibility values are denied by default.

Secondary/related surfaces (visibility-aware but about disclosure rather than direct view authorization): mention-notification gating in `server/router/api/v1/memo_mention_helpers.go` (skips notifying users who can't see the memo), content redaction for private/protected memos in `server/notification/email.go` and `server/router/api/v1/user_service_notifications.go`, and the SSR sitemap in `server/router/frontend/frontend.go` (line ~150) which lists only public memos.
