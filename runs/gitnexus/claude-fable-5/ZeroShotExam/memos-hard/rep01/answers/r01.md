**Premise correction:** There is no Redis in this repository. A grep for "redis" across the entire codebase (Go, TypeScript, config, docs) returns zero matches — memos has no external cache service and no Redis connection to configure.

**Actual mechanism:** The cache layer is a homegrown, thread-safe **in-memory** cache defined in `store/cache/cache.go`. The store wires it up in `store/store.go`: the `Store` struct holds `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:26-28`), all created in `New()` with a shared `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```
(`store/store.go:39-44`)

**TTL for user entries:** User objects are written with `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167), and `Set` applies the config's default TTL (`store/cache/cache.go:92-94`) — so user cache entries live for **10 minutes**, with an expired-entry cleanup sweep every 5 minutes and a 1000-item cap. The cache is per-process and dies with the server; nothing is persisted or shared over a network connection.
