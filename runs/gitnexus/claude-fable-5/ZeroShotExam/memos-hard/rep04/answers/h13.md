**impl** — The interface is `markdown.Service` (`internal/markdown/markdown.go:31`). Exactly one concrete implementation executes at runtime: the unexported `*service` struct (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown` instance configured with GFM plus the custom tag and mention extensions (`internal/markdown/extensions/tag.go`, `internal/markdown/extensions/mention.go`). (HTML rendering for the UI happens on the frontend with markdown-it; this backend service is used for extraction, snippet generation, tag rename, and RSS HTML.)

**construction** — `markdown.NewService(...)` (`internal/markdown/markdown.go:85`) is the only factory. In production it is called exactly once, inside `NewAPIV1Service` at `server/router/api/v1/v1.go:48`, with `WithTagExtension()` and `WithMentionExtension()`. That single instance is then shared: `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService(...)`. (A test helper also constructs one at `server/router/api/v1/test/test_helper.go:44`, but that's test-only.)

**holders** — Three components hold the `markdown.Service` interface as a field or parameter:
1. `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — used across the API handlers (e.g. memo create/update paths in `server/router/api/v1/memo_service.go`).
2. `RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — receives the API service's instance for server-side HTML rendering of feeds.
3. `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`); the package-level `RebuildMemoPayload` also takes the interface as a parameter (`runner.go:74`) and is invoked at runtime from `server/router/api/v1/memo_service.go:108` and `:447` with `s.MarkdownService`.

One side note: `internal/markdown/renderer/markdown_renderer.go` (`NewMarkdownRenderer`) is a concrete AST→markdown renderer, but it sits *behind* the `service` implementation (constructed inside `RenderMarkdown` and `RenameTag`), not behind the interface itself.
