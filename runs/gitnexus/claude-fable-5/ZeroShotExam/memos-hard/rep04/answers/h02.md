**Delivery function** — `Post` in `internal/webhook/webhook.go:120` (specifically the `safeClient.Do(req)` call at `internal/webhook/webhook.go:152`). This is where the outbound HTTP POST actually goes to the wire. Async triggers (`PostAsync`, line 184) enqueue onto a channel whose worker goroutines all call `Post`.

**Protection mechanism** — `safeDialContext` in `internal/webhook/webhook.go:59`, wired into the shared `safeClient`'s transport (`internal/webhook/webhook.go:32-37`). It resolves the target host at *dial time* and refuses to connect if any resolved address is a reserved/private IP (`isReservedIP` / `reservedCIDRs` in `internal/webhook/validate.go:14-54`). Because the check happens at connect time on the actual resolved IPs, it also defeats DNS-rebinding bypasses.

Supporting detail:
- There is also a pre-flight guard, `ValidateURL` in `internal/webhook/validate.go:62`, run when the webhook URL is registered — it rejects non-http(s) schemes and hostnames resolving to reserved IPs. But this is a check-time validation; the load-bearing protection at delivery time is `safeDialContext`.
- Both guards can be globally disabled via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`, consulted in `isReservedIP`), intended for self-hosted deployments targeting local-network services.
