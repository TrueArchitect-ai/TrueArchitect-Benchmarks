The premise is incorrect: this repository (memos) has no per-user API rate-limiting middleware at all, so there is nowhere it's registered and no request limits to report.

What is actually registered on the API surface:

- Echo-level middleware in `server/server.go:51-52`: `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`, defined in `server/cors.go`).
- Connect/gRPC interceptors in `server/router/api/v1/v1.go:133-141`: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor`, plus a gateway auth middleware at `server/router/api/v1/v1.go:69`.

The only request "limit" in the API stack is a maximum request body size (`connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`), and page-size normalization for list endpoints (`normalizePageSize` in `server/router/api/v1/common.go:46`) — neither of which is rate limiting. A repo-wide search for rate-limit/throttle/limiter terms in the Go code turns up nothing.
