Memo visibility ("who may view") is enforced at these distinct server surfaces:

1. Memo API read-access check (shared helper used by GetMemo etc.: public → anyone, protected → any signed-in user, private → creator only) — `server/router/api/v1/memo_service.go` (~lines 55–66); the same file also enforces it on listing by constraining `VisibilityList`/CEL filter for anonymous vs. authenticated callers (~lines 219–225).
2. Memo comments (visibility check before creating a comment, and visibility-filtered comment listing) — `server/router/api/v1/memo_service_comments.go` (lines 33–41, 158–160).
3. Reactions API (checks parent memo visibility before listing/upserting reactions) — `server/router/api/v1/reaction_service.go` (lines 29–38, 82–83).
4. Attachment API (access to an attachment gated by the linked memo's visibility) — `server/router/api/v1/attachment_service.go` (lines 255, 436–451).
5. Memo-attachment API (checks memo visibility before exposing its attachments) — `server/router/api/v1/memo_attachment_service.go` (lines 213–222).
6. Raw file serving (attachment bytes served only if the linked memo's visibility permits: public+anonymous-allowed, private → creator or admin) — `server/router/fileserver/fileserver.go` (lines 674–699).
7. SSE realtime delivery filtering (`SSEClient.canReceive` drops private-memo events for non-creator, non-admin clients) — `server/router/api/v1/sse_hub.go` (lines 134–143, with visibility attached in `server/router/api/v1/sse_event_helpers.go`).
8. RSS feeds (queries hard-limited to `store.Public` memos) — `server/router/rss/rss.go` (lines 90, 141).
9. User memo stats (visibility list restricted per requesting user) — `server/router/api/v1/user_service_stats.go` (lines 84–90, 218–220); similarly, the frontend meta/OG renderer only loads public memos — `server/router/frontend/frontend.go` (line 150).

The core three surfaces are the memo API itself (`memo_service.go`), the attachment/file-serving paths (`attachment_service.go` / `memo_attachment_service.go` / `fileserver.go`), and the ancillary read surfaces (comments, reactions, SSE, RSS, stats) — each re-implements the public/protected/private rule independently.
