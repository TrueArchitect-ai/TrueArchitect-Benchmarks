**Yes — but only in one place, a unit test inside the MySQL package itself.**

Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14-32`, which calls `mysql.NewDB(profile)` at `store/db/db.go:22` inside a `switch profile.Driver` statement. This is the only file in the entire codebase that imports `github.com/usememos/memos/store/db/mysql` (verified by grepping all `.go` files for the import path), so no external package can construct the MySQL driver any other way.
- However, within the mysql package's own tests, `store/db/mysql/auth_config_test.go:12` constructs the driver struct directly with a bare literal: `db := &DB{}`, in order to unit-test `IsRetryableAuthenticationMutationError` without a real database connection. This bypasses both the factory and the package's `NewDB` constructor.
- For completeness: the only other `DB{...}` literal in the package is at `store/db/mysql/mysql.go:29`, inside `mysql.NewDB` itself — that's the constructor's own implementation, not an independent construction site. (The postgres package has the same pattern, with direct `&DB{...}` literals in `store/db/postgres/user_setting_test.go` and `store/db/postgres/auth_config_test.go`.)

So in production code the MySQL driver is only ever created through the factory in `store/db/db.go`; the sole direct construction outside it is the test-only `&DB{}` literal in `store/db/mysql/auth_config_test.go`.
