**Premise correction:** There is no Redis in this repository. Nothing in the codebase (Go, TypeScript, or config) references Redis — the cache layer is not an external service at all.

**Actual mechanism:** The cache is a thread-safe **in-process, in-memory cache** implemented in `store/cache/cache.go` (a `Cache` struct with TTL expiration, a cleanup goroutine, and a max-item cap). The connection/configuration point is `store.New()` in `store/store.go:38-61`, which builds a `cache.Config` and creates three caches: `instanceSettingCache`, `userCache`, and `userSettingCache`.

**TTL for user entries:** User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167), which uses the default TTL. That default is **10 minutes** (`DefaultTTL: 10 * time.Minute`, set in `store/store.go:41`, with the same fallback default in `store/cache/cache.go:59`), alongside a 5-minute cleanup interval and a 1000-item cap. Entries are also explicitly invalidated on user deletion (`store/user_delete.go:40`).
