The premise is incorrect — this repository (memos) has no per-user API rate-limiting middleware. Nothing of the kind is registered anywhere, so there are no request limits to report.

What actually exists:

- The Echo HTTP server registers only `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`).
- The Connect/gRPC API stack registers four interceptors — metadata, logging, recovery, and auth — in `server/router/api/v1/v1.go:133-137`, plus an auth middleware for the gRPC-Gateway (`server/router/api/v1/v1.go:69`). None of these do rate limiting; the only request-size constraint is `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`, which caps request body size, not request rate.
- The only "rate limit" mentions in the codebase are documentation suggestions, not implementations: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a best-practice recommendation, and `internal/email/README.md:291-294` shows an example using `golang.org/x/time/rate` (10 emails per second) that callers could add themselves. `golang.org/x/time` appears in `go.mod` only as an indirect dependency and is not used for API throttling.
