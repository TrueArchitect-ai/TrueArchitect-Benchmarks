**1st: User (~7 packages); 2nd: Memo (~6 packages)**

The data layer is the `store` package, whose persistent entity structs are defined in files like `store/user.go`, `store/memo.go`, `store/attachment.go`, `store/inbox.go`, `store/reaction.go`, etc. Counting the distinct Go packages outside `store/` that reference each type (`store.User`, `store.Memo`, …):

- **`store.User`** (`store/user.go:29`) — 7 packages: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- **`store.Memo`** (`store/memo.go:35`) — 6 packages: `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`

For comparison, the next tier is `store.Attachment` at 4 packages, then `MemoRelation`/`MemoShare`/`Inbox` at 3 each. The ranking holds even if you exclude the test package (`User` 6 vs `Memo` 5): User is touched everywhere authentication or ownership matters, while Memo references are concentrated in the routers and the memo-payload runner.
