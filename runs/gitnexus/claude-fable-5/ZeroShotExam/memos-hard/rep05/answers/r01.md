**Premise correction:** There is no Redis in this repository. A grep across the entire codebase finds zero Redis references — no client library, no connection config, no env var. The cache layer is a purely in-process, in-memory cache implemented in Go.

**Actual mechanism:** The store's caches are created in `store/store.go:38-61` (`New`), which builds three instances of the custom cache from `store/cache/cache.go`: `instanceSettingCache`, `userCache`, and `userSettingCache`. The shared config is:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute` (background eviction goroutine)
- `MaxItems: 1000`

User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167). `Cache.Set` (`store/cache/cache.go:93-94`) delegates to `SetWithTTL` using the configured default, so **user cache entries live for 10 minutes** (unless invalidated earlier by update/delete, or evicted by the cleanup cycle / item cap). The caches are per-process only — they're torn down in `Store.Close` (`store/store.go:72-79`) and share nothing across instances, so there's no external connection to configure.
