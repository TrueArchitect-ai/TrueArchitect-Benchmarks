The provider abstraction lives in `internal/idp`; the shipped concrete protocol implementation is OAuth2 in `internal/idp/oauth2`.

- `internal/idp/idp.go` (package `idp`) defines the provider-agnostic abstraction — the `IdentityProviderUserInfo` struct (identifier, display name, email, avatar) that any provider must map into.
- `internal/idp/oauth2/oauth2.go` (package `oauth2`) is the only concrete implementation shipped: an `IdentityProvider` built from a `storepb.OAuth2Config`, with `ExchangeToken` (including PKCE support) and user-info fetching that maps provider responses to `idp.IdentityProviderUserInfo`. Tests are in `internal/idp/oauth2/oauth2_test.go`, and it's consumed by the SSO login path in `server/router/api/v1/auth_service_sso.go`.

Answer: `internal/idp`; `internal/idp/oauth2`
