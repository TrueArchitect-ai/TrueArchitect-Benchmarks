The premise is incorrect — this repository has no per-user API rate-limiting middleware. Nothing registers a rate limiter, and there are no request-count limits to report.

What the server actually registers:

- `server/server.go:51-52` — the Echo server uses only `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`).
- `server/router/api/v1/v1.go:133-141` — the Connect RPC handler chain consists of `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, and `NewAuthInterceptor()` (plus a gateway auth middleware at `v1.go:69`). No throttling/limiter interceptor exists.

The only limits that do exist are of a different kind: a request **size** cap (`connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`) and pagination caps (`normalizePageSize` in `server/router/api/v1/common.go:46`). The sole mention of rate limiting anywhere is an aspirational doc comment — `internal/email/doc.go:86` says "Rate limit email sending to prevent abuse" as guidance, not implemented code. A codebase-wide search for rate-limit/throttle/limiter terms turns up nothing else in Go or TypeScript source.
