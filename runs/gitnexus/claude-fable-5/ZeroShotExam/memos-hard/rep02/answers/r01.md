**Premise correction:** There is no Redis in this repository. Nothing in the codebase references Redis — the cache layer is a purely in-memory, in-process cache, so there's no Redis connection to configure.

**Actual mechanism:** The cache is a custom in-memory implementation in `store/cache/cache.go`, backed by a `sync.Map` with a background cleanup goroutine. The store wires it up in `store/store.go:38-61` (`New()`), which creates three caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing one `cache.Config`:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

**TTL for user entries:** 10 minutes. User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 143, 167), and `Cache.Set` (`store/cache/cache.go:93-94`) delegates to `SetWithTTL` using `config.DefaultTTL` — the 10-minute default set in `store/store.go:41`. No custom TTL is applied to user entries.
