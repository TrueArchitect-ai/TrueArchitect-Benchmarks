Memo view-visibility is enforced independently in each of these server surfaces:

gRPC/API memo read access (`checkMemoReadAccess`, used by GetMemo etc.; private → creator only, non-public → authenticated) — `server/router/api/v1/memo_service.go` (lines 39–68), plus list-time filtering via `VisibilityList`/CEL filter in ListMemos (lines 219–225)

API attachment access (`checkAttachmentAccess`: memo-linked attachments follow the memo's visibility) — `server/router/api/v1/attachment_service.go` (lines ~422–455)

Memo-attachment listing (ListMemoAttachments re-checks memo visibility before returning attachments) — `server/router/api/v1/memo_attachment_service.go` (lines ~214–225)

HTTP file server serving attachment binaries (`checkAttachmentPermission`: public+anonymous allowed, share-token fallback, private → creator/admin) — `server/router/fileserver/fileserver.go` (lines 650–704)

SSE real-time event delivery (`canReceive` filters broadcast memo events so private-memo events reach only the creator/admin) — `server/router/api/v1/sse_hub.go` (lines 134–143, event visibility set in `server/router/api/v1/sse_event_helpers.go`)

Reactions on memos (list/upsert reaction handlers check the target memo's visibility) — `server/router/api/v1/reaction_service.go` (lines 38, 83)

Comment creation (checks visibility of the related/parent memo before allowing a comment) — `server/router/api/v1/memo_service_comments.go` (line 41)

RSS/Atom feeds (query is hard-restricted to `store.Public` memos only) — `server/router/rss/rss.go` (lines 90, 141)

User memo stats (visibility filtering per viewer before aggregating) — `server/router/api/v1/user_service_stats.go` (lines 84–90, 218–220)

Notification snippets (`canViewerAccessMemo`: memo content only included if the recipient may view the memo) — `server/router/api/v1/user_service_notifications.go` (lines ~302–316), with a parallel copy for email notifications in `server/notification/email.go` (lines ~306–320) and mention-notification gating in `server/router/api/v1/memo_mention_helpers.go` (lines 62–67)

The three headline surfaces the question is likely after are the API v1 gRPC handlers (`memo_service.go` and the attachment/reaction/comment handlers), the HTTP fileserver (`fileserver.go`), and the SSE broadcast hub (`sse_hub.go`) — with RSS and notification rendering as additional independent sites. Note that memo-share and relation endpoints (`memo_share_service.go`, `memo_relation_service.go`) check creator ownership rather than visibility, so I excluded them.
