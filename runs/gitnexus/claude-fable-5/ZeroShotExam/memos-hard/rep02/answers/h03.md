The provider abstraction lives in the `internal/idp` package, and the one concrete protocol implementation that ships is OAuth 2.0 in the `internal/idp/oauth2` package.

- `internal/idp/idp.go` defines the shared abstraction — the `IdentityProviderUserInfo` struct (identifier, display name, email, avatar URL) that any provider implementation must map its claims into.
- `internal/idp/oauth2/oauth2.go` implements the OAuth 2.0 flow (with tests in `internal/idp/oauth2/oauth2_test.go`); it's consumed by the sign-in path in `server/router/api/v1/auth_service.go`.

Answer: `internal/idp`; `internal/idp/oauth2`
