**Premise correction: this repository has no per-user API rate-limiting middleware.** There is nothing to point to for request limits, because no rate limiter (per-user or otherwise) is registered anywhere in the server.

What is actually registered on the API path:

- Global Echo middleware: only `middleware.Recover()` and a CORS middleware, at `server/server.go:51-52`.
- Connect RPC interceptors: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor`, registered at `server/router/api/v1/v1.go:133-138` and defined in `server/router/api/v1/connect_interceptors.go`. None of these do rate limiting.
- The only "limit" applied to API requests is a request **size** cap, not a rate cap: `maxAPIRequestBytes = 256 << 20` (256 MiB), enforced via `http.MaxBytesHandler` / `connect.WithReadMaxBytes` at `server/router/api/v1/v1.go:20,126,141`.

A repo-wide search for rate-limiting terms (`ratelimit`, `limiter`, `throttle`, `tollbooth`, `golang.org/x/time/rate`) finds only a documentation comment in `internal/email/doc.go:86` suggesting operators rate-limit email sending — advice about the SMTP feature, not implemented middleware.
