Frontend requests are authenticated by a Connect RPC client interceptor that attaches a Bearer access token and transparently refreshes it, and the backend validates that token in its own Connect interceptor chain.

- **Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is installed on the shared Connect transport used by all service clients. It calls `getRequestToken()` and sets `Authorization: Bearer <token>` on each request (with token state kept in `web/src/auth-state.ts`).
- **Token kinds:** two — a short-lived **access token** (held in memory, sent as a `Bearer` Authorization header, proactively refreshed before expiry and reactively refreshed on a 401/Unauthenticated error with one retry) and a **refresh token** (an HttpOnly **cookie**, sent because the transport uses `credentials: "include"`, exchanged via `AuthService.RefreshToken` on a separate interceptor-free transport to avoid recursion).
- **Backend package:** `server/router/api/v1` — `server/router/api/v1/connect_interceptors.go` reads the `Authorization` header (and forwards the Cookie header for the RefreshToken method), with the authorization rules in `server/router/api/v1/authz.go` and `server/router/api/v1/acl_config.go`, and the auth/refresh endpoints in `server/router/api/v1/auth_service.go`.

Answer format: `web/src/connect.ts`; access token (Bearer header) + refresh token (HttpOnly cookie); `server/router/api/v1`
