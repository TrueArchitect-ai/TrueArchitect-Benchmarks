The server starts exactly one background runner, and the codebase contains a full cron scheduler package that nothing uses.

**Runners the server actually starts** (all wiring in `Server.startBackgroundRunners`, `server/server.go:153-174`, called from `Server.Start` at `server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — triggered once immediately at startup via `RunOnce(ctx)` (`server/server.go:163`), then continuously in a goroutine via `Run(ctx)`, which is driven by a `time.NewTicker` with a hard-coded 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:26-40`). It stops via context cancellation on shutdown. Each tick calls `CheckAndPresign` to refresh expiring S3 presigned URLs.

That's the only entry in `startBackgroundRunners` — no other worker goroutines are launched there.

**Not started by the server:**

- **memopayload runner** (`server/runner/memopayload/runner.go`) — has the same `NewRunner`/`RunOnce` runner shape, but the server never constructs or starts it as a background worker. Only its `RebuildMemoPayload` helper function is called, synchronously in the request path when memos are created/updated (`server/router/api/v1/memo_service.go:108`, `:447`).
- **`internal/scheduler` (cron scheduler) — unused infrastructure.** This is a complete GitHub-Actions-style cron package (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `doc.go`) with cron-expression parsing, timezones, and middleware, but no code outside the package itself imports it. Neither runner is registered with it; the s3presign runner uses its own raw `time.Ticker` instead.

For completeness (background goroutines, but not server-managed "runners"): the in-memory cache spawns its own cleanup loop on construction (`go c.cleanupLoop()` with a ticker, `store/cache/cache.go:83`, `:201`), and each SSE connection runs a per-connection heartbeat ticker (`server/router/api/v1/sse_handler.go:64`). These are started by their own components, not by `startBackgroundRunners`.
