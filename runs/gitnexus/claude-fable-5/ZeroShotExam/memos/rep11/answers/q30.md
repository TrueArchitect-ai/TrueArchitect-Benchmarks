Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook` — called from `CreateMemo` in `server/router/api/v1/memo_service.go:157`
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook` — called from `server/router/api/v1/memo_update_helpers.go:67`
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook` — called from `DeleteMemo` in `server/router/api/v1/memo_service.go:562`
- memo comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook` — called from `server/router/api/v1/memo_service_comments.go:119`

Delivery convergence: the created/updated/deleted dispatchers all route through the shared helper `dispatchMemoRelatedWebhook` (memo_service_webhooks.go:48), and that helper plus the comment dispatcher both enqueue via `webhook.PostAsync` in `internal/webhook/webhook.go:184`. `PostAsync` pushes the payload onto a bounded `asyncPostQueue` channel, and four worker goroutines started in the package's `init()` drain the queue by calling `webhook.Post` (`internal/webhook/webhook.go:120`), which performs the actual HTTP POST (with HMAC signing headers and an SSRF-safe HTTP client). So the single point of delivery for all four events is `Post` in `internal/webhook/webhook.go`.
