The server starts exactly one background runner, and one other "runner" package exists but is never run in the background:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:153-174`), which is called from `Server.Start` (`server/server.go:129`). It runs `RunOnce` immediately at startup, then `Run` loops on a plain `time.NewTicker` with a hardcoded 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27`), stopping on context cancellation during shutdown.
- **memopayload runner** (`server/runner/memopayload/runner.go`) — NOT started as a background worker. Although it has a `Runner` type with `RunOnce`, the server never spawns it; only its `RebuildMemoPayload` helper is called synchronously from the API layer during memo create/update (`server/router/api/v1/memo_service.go:108` and `:447`).

Unused scheduling infrastructure: the cron-style scheduler package at `internal/scheduler/` (`scheduler.go` with `Register`/`Start`, plus a cron-expression `parser.go`) is not imported by the server or any production code at all — the only files importing `github.com/usememos/memos/internal/scheduler` are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). The single live background runner uses a raw `time.Ticker` instead.
