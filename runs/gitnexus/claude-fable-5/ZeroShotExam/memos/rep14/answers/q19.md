MemoService is exposed over two protocols, both mounted onto the same Echo HTTP server in `RegisterGateway`:

1. **HTTP/REST (JSON) via gRPC-Gateway** — `server/router/api/v1/v1.go` (line 108: `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)`, served under `/api/v1/*`).
2. **Connect RPC (Connect protocol, replacing grpc-web for browser clients)** — `server/router/api/v1/connect_handler.go` (line 40: wraps `apiv1connect.NewMemoServiceHandler(s, ...)`, registered via `RegisterConnectHandlers` and mounted at `/memos.api.v1.*` in `server/router/api/v1/v1.go`).

Notably, plain gRPC is not one of the two: the generated `RegisterMemoServiceServer` in `proto/gen/api/v1/memo_service_grpc.pb.go` is never called by the server — the gateway registration in `v1.go` invokes the service implementation (`APIV1Service`, defined for MemoService in `server/router/api/v1/memo_service.go`) in-process rather than through a gRPC listener.
