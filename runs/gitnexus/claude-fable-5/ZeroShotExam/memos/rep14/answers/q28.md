The server starts exactly one background runner, and two pieces of scheduling-capable infrastructure in the repo are never wired into it.

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `startBackgroundRunners` (`server/server.go:153-174`), which is called from `Server.Start` (`server/server.go:129`). Scheduling is two-part: an immediate `RunOnce(ctx)` at startup, then a goroutine running `Run(ctx)`, which loops on a `time.NewTicker` with a hard-coded 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:26-41`), stopping on context cancellation at shutdown. That is the entirety of the server's background work.

Unused infrastructure:

- **`internal/scheduler/`** — a complete GitHub-Actions-style cron scheduler (5/6-field cron expressions, timezones, middleware, graceful shutdown; see `internal/scheduler/doc.go`, `scheduler.go`, `job.go`, `parser.go`) is **not used by the server at all**. Grepping for imports of `internal/scheduler` finds no references outside the package and its own tests. The s3presign runner uses a plain `time.Ticker` instead of this scheduler.
- **memopayload runner** (`server/runner/memopayload/runner.go`) — has the same `Runner`/`RunOnce` background-runner shape (batch-rebuilds all memo payloads), but the server never constructs or starts it as a background worker. Only the package's standalone helper `RebuildMemoPayload` is called synchronously from the API layer (`server/router/api/v1/memo_service.go:108,447`) when memos are created/updated.
