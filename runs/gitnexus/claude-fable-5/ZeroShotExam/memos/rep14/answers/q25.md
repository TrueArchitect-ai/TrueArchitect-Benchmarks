**Engine:** CEL (Common Expression Language) via `github.com/google/cel-go` (declared in `go.mod`). **Path:** the filter subsystem lives in `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-223`) validates the filter and appends it to `memoFind.Filters`; each store dialect (e.g. `store/db/mysql/memo.go:65-69`, with equivalents in `store/db/sqlite/` and `store/db/postgres/`) calls `filter.DefaultEngine()` and `filter.AppendConditions(..., filter.DialectMySQL, &where, &args)`. Inside `internal/filter`, the `Engine` (`engine.go`) compiles the string against a CEL environment built from the memo schema (`schema.go`'s `NewSchema`), converts the CEL AST into a dialect-agnostic condition tree / IR (`parser.go`, `ir.go`), and then a renderer (`render.go`) walks that tree emitting dialect-specific SQL — switching on `DialectSQLite` / `DialectMySQL` / `DialectPostgres` for things like placeholders, JSON extraction, and boolean casts — producing WHERE fragments plus bound args that the store appends to its query.
