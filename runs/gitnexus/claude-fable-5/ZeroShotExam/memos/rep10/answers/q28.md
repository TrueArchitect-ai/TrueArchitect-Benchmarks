The server starts exactly **one** background runner:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:153-174`), which is called from `Server.Start` (`server/server.go:129`). Scheduling: an immediate `RunOnce(ctx)` at startup, then a goroutine running `Run(ctx)` which uses a plain `time.NewTicker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). It is stopped via a per-runner `context.CancelFunc` and awaited with a `sync.WaitGroup` on shutdown.

Not background runners despite appearances:

- **memopayload runner** (`server/runner/memopayload/runner.go`) — lives in the `runner/` directory and has a `RunOnce` method, but the server never starts it as a background worker. Its `RebuildMemoPayload` function is only called synchronously from the API layer on memo create/update (`server/router/api/v1/memo_service.go:108,447`).

Unused scheduling infrastructure:

- **`internal/scheduler`** (`internal/scheduler/scheduler.go`, `parser.go`) — a full cron-style job scheduler with registration, timezone support, and middleware. It is **not imported by any production code**; its only references are its own tests and examples (`internal/scheduler/*_test.go`). The server's sole runner uses a raw `time.Ticker` instead of this scheduler.
