The server starts exactly one dedicated background runner, plus an incidental cache-cleanup goroutine:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `startBackgroundRunners` (`server/server.go:153-174`): it runs `RunOnce` immediately at startup, then a goroutine runs `Run`, driven by a plain `time.NewTicker` with a hard-coded 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27`). It re-presigns S3 attachment URLs in batches.
- **Cache cleanup goroutine** (`store/cache/cache.go:83,200`) — not part of the server's runner list, but each `cache.New()` spawns a `cleanupLoop` goroutine driven by a `time.NewTicker` on `CleanupInterval` to evict expired entries. (Per-SSE-connection heartbeat tickers in `server/router/api/v1/sse_handler.go` are connection-scoped, not background workers.)

Notably NOT a background worker despite living in the runner package: the **memopayload runner** (`server/runner/memopayload/runner.go`). Its `RunOnce` (rebuild all memo payloads) is never scheduled or invoked by the server; only its standalone `RebuildMemoPayload` function is called synchronously from the memo API handlers (`server/router/api/v1/memo_service.go:108,447`).

Unused scheduling infrastructure: **`internal/scheduler`** — a complete GitHub-Actions-style cron scheduler (5/6-field cron expressions, timezones, middleware, graceful shutdown; see `internal/scheduler/doc.go`) — is imported by nothing outside its own package and tests. The server never uses it; its background scheduling is done with raw `time.Ticker` loops instead.
