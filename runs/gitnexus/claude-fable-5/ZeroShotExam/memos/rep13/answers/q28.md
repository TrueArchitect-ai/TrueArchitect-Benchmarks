The server starts exactly one background runner:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `startBackgroundRunners` (`server/server.go:153-174`). Trigger: an immediate `RunOnce(ctx)` at server startup, then a continuous goroutine whose `Run` loop is driven by a `time.NewTicker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-40`), stopping on context cancellation at shutdown.

Unused scheduling infrastructure:

- The **memopayload runner** (`server/runner/memopayload/runner.go`) has the same runner shape — `NewRunner` and a `RunOnce` that rebuilds payloads for all memos — but the server never constructs or starts it; `NewRunner`/`RunOnce` have no callers anywhere in the codebase. Only its standalone helper function `RebuildMemoPayload` is used, called synchronously from the API layer when memos are created/updated (`server/router/api/v1/memo_service.go:108, 447`). So it exists as background-runner infrastructure but is not scheduled or run in the background.

There is no cron/scheduler library in `go.mod`; the only scheduling mechanism actually in use is the s3presign ticker.
