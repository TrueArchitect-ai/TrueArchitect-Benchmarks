When the API's `DeleteMemo` handler calls into the store, `Store.DeleteMemo` in `store/memo.go` (lines 140–159) cleans up the following before deleting the memo row itself:

- **Memo relation records where the memo is the source** — `DeleteMemoRelation` with `MemoID` set to the memo's ID (`store/memo.go:142`)
- **Memo relation records where the memo is the target** — `DeleteMemoRelation` with `RelatedMemoID` set to the memo's ID (`store/memo.go:145`)
- **Attachments linked to the memo** — it lists them with `ListAttachments({MemoID})` and deletes each via `DeleteAttachment` (`store/memo.go:149-157`)

Only after that does it call the driver's `DeleteMemo`, which just deletes the `memo` row (e.g. `store/db/sqlite/memo.go:237`) — the drivers do no additional cascading themselves.
