Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- `memos.memo.created`: `DispatchMemoCreatedWebhook` (line 15)
- `memos.memo.updated`: `DispatchMemoUpdatedWebhook` (line 20)
- `memos.memo.deleted`: `DispatchMemoDeletedWebhook` (line 25)
- `memos.memo.comment.created`: `DispatchMemoCommentCreatedWebhook` (line 30)

Delivery convergence: the created/updated/deleted dispatchers are thin wrappers over the shared helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which looks up the memo creator's webhooks and enqueues each payload via `webhook.PostAsync`. The comment-created dispatcher skips that helper (it targets the related memo owner's webhooks instead of the memo creator's) but calls `webhook.PostAsync` directly. So all four ultimately converge on `PostAsync` in `internal/webhook/webhook.go:184`, which enqueues onto a bounded async queue whose workers (started in `init`, `internal/webhook/webhook.go:41`) perform the actual HTTP POST — with Standard Webhooks HMAC signing — in `Post` (`internal/webhook/webhook.go:120`).
