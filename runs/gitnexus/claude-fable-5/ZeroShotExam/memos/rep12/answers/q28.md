The server starts exactly one background runner:

**s3presign runner — started once at server startup, then driven by a 12-hour `time.Ticker`.** In `Server.Start` → `startBackgroundRunners` (`server/server.go:129`, `server/server.go:153-174`), the server creates `s3presign.NewRunner(s.Store)`, calls `RunOnce(ctx)` immediately (one initial pass), then launches `Run(ctx)` in a goroutine. `Run` loops on `time.NewTicker(runnerInterval)` with `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:26-41`), re-presigning S3 attachment URLs each tick. Shutdown is handled via per-runner `context.CancelFunc` plus a `sync.WaitGroup` (`server/server.go:176-201`).

Not a background runner despite living in `server/runner/`:

- **memopayload (`server/runner/memopayload/runner.go`)** — never started by the server and has no ticker/loop (only `NewRunner`, `RunOnce`, and `RebuildMemoPayload`). Its only production use is synchronous calls to `memopayload.RebuildMemoPayload` from the memo API handlers (`server/router/api/v1/memo_service.go:108, 447`); `NewRunner`/`RunOnce` aren't invoked anywhere outside the package.

Unused scheduling infrastructure:

- **`internal/scheduler/` (a full cron-style scheduler with `Register`, `Start`, and a cron-expression parser in `scheduler.go`/`parser.go`) is NOT used by the server at all.** The only imports of `github.com/usememos/memos/internal/scheduler` are its own test/example files (`internal/scheduler/example_test.go`, `integration_test.go`, `scheduler_test.go`). The actual runner scheduling uses a plain `time.Ticker`, not this package.
