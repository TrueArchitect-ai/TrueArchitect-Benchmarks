**Engine:** CEL (Common Expression Language, via `github.com/google/cel-go`), living in the `internal/filter` package (`internal/filter/engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-223`) validates the filter and appends it to `memoFind.Filters`; each store driver then calls `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` — the `Engine` compiles the CEL expression against a schema-defined CEL environment into a dialect-agnostic condition tree (IR), and a `renderer` (`internal/filter/render.go`) walks that tree emitting parameterized SQL with per-dialect branches (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`, e.g. `strftime` vs `EXTRACT` vs MySQL date functions) from `store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo.go:69`, and `store/db/postgres/memo.go:58`.
