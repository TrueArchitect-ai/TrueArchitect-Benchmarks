**Answer:** `DispatchMemoCreatedWebhook` — `server/router/api/v1/memo_service_webhooks.go`; delivery package `github.com/usememos/memos/internal/webhook` (using Go's standard `net/http` client); signing mechanism: Standard Webhooks-style HMAC-SHA256 signature.

Details:

- **Dispatcher:** When a memo is created, `CreateMemo` in `server/router/api/v1/memo_service.go:157` calls `DispatchMemoCreatedWebhook` (defined in `server/router/api/v1/memo_service_webhooks.go:15`). That delegates to the internal helper `dispatchMemoRelatedWebhook` with activity type `"memos.memo.created"`, which looks up the creator's webhooks via `s.Store.GetUserWebhooks` and enqueues each payload with `webhook.PostAsync(payload)`.
- **Delivery package:** `internal/webhook` (`internal/webhook/webhook.go`). `PostAsync` puts the payload on a bounded queue drained by 4 worker goroutines that call `Post`, which sends a JSON POST using a shared `net/http` client (`safeClient`) with a 30s timeout and an SSRF-guarding dialer that blocks reserved/private IPs. No third-party HTTP library is used.
- **Signing mechanism:** HMAC-SHA256 per the Standard Webhooks convention. If the hook has a `SigningSecret` (a `whsec_<base64>` secret is base64-decoded to raw key bytes), `Post` computes `HMAC-SHA256(key, "<msgID>.<timestamp>." + body)`, base64-encodes it, and sets the headers `webhook-id` (`msg_<uuid>`), `webhook-timestamp` (Unix seconds), and `webhook-signature` (`v1,<base64 signature>`) — see `internal/webhook/webhook.go:133-150`. Unsigned hooks (no secret) send no signature headers.
