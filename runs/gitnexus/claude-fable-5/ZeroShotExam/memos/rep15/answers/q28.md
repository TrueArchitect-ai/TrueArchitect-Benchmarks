The server starts exactly **one** background runner:

- **`s3presign` runner** (`server/runner/s3presign/runner.go`) — started in `startBackgroundRunners` (`server/server.go:153-174`), which is called from `Server.Start` (`server/server.go:129`). It runs `RunOnce(ctx)` immediately at startup, then `Run(ctx)` in a goroutine driven by a plain `time.NewTicker` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27-41`). It re-presigns S3 attachment URLs, and is stopped via a per-runner `context.CancelFunc` plus a `sync.WaitGroup` on shutdown.

Not actually started as workers:

- **`memopayload` runner** (`server/runner/memopayload/runner.go`) — it has a `Runner` type with `RunOnce`, but the server never constructs or schedules it. Only its standalone helper `RebuildMemoPayload` is called synchronously from the memo API handlers (`server/router/api/v1/memo_service.go:108,447`). It is not a background worker in practice.

Unused scheduling infrastructure:

- **`internal/scheduler/`** — a complete GitHub-Actions-style cron scheduler (cron-expression parser, `Job`, `Scheduler` with middleware/timezone support, plus tests and a README) is present, but nothing outside the package imports it. Neither `server/server.go` nor any runner uses it; the only real scheduling in the server is the raw 12-hour ticker inside the s3presign runner. (Other tickers in the codebase — the SSE heartbeat in `server/router/api/v1/sse_handler.go` and the cache cleanup loop in `store/cache/cache.go` — are per-connection/internal-cache housekeeping, not server-started runners.)
