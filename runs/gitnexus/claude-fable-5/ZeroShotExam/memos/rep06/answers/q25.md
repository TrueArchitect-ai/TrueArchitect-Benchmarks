**Engine:** CEL (Common Expression Language, via `github.com/google/cel-go`), living in the `internal/filter` package (`internal/filter/engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-223`) validates the filter string and puts it on `memoFind.Filters`; each store driver then calls `filter.DefaultEngine()` + `filter.AppendConditions(...)` with its own dialect constant — `store/db/sqlite/memo.go:57-61` (`DialectSQLite`), `store/db/mysql/memo.go:65-69` (`DialectMySQL`), `store/db/postgres/memo.go:54-58` (`DialectPostgres`). Inside the engine, `Engine.Compile` (`internal/filter/engine.go:48`) type-checks the expression against a CEL environment built from a field schema (`schema.go`), converts the CEL AST into a dialect-agnostic condition tree IR (`buildCondition` in `parser.go`, node types in `ir.go`, with the `now` variable frozen to one instant per compile), and then `Program.Render` walks that tree with a per-dialect renderer (`render.go`, which switches on `DialectName` for placeholder style, JSON access, string-length functions, etc.) to emit a parameterized SQL WHERE fragment plus args via `CompileToStatement`. `filter.AppendConditions` (`internal/filter/helpers.go:9`) wraps each rendered fragment in parentheses and appends it to the query's WHERE list with a placeholder offset.

So in one sentence: the filter is a CEL expression compiled by cel-go in `internal/filter`, lowered from the CEL AST into an internal condition-tree IR, and rendered per dialect (SQLite/MySQL/Postgres) into parameterized SQL WHERE fragments that the three store drivers append to their memo queries.
