**Interceptor:** `web/src/connect.ts` — the auth interceptor attaches `Authorization: Bearer <accessToken>` to every request (line 99), does a preflight refresh when the access token is near expiry (line 136), and reactively refreshes-and-retries once on a 401, deduplicating concurrent refreshes via a token-refresh manager. Token state itself (in-memory + `localStorage` + cross-tab `BroadcastChannel` sharing) lives in `web/src/auth-state.ts`.

**Token kinds:** short-lived **JWT access tokens** (~15 min, sent as Bearer header), a long-lived **refresh token** held in an HTTP-only cookie set by the backend (`server/router/api/v1/auth_service_session.go:44-47`) and exchanged via the `AuthService.RefreshToken` RPC, and — for programmatic clients rather than the browser flow — **Personal Access Tokens (PATs)**.

**Backend validation package:** `server/auth` — `server/auth/authenticator.go` implements `AuthenticateByAccessTokenV2` (JWT), `AuthenticateByRefreshToken` (checked against the database for revocation/expiry), and `AuthenticateByPAT` (hash lookup), with JWT parsing helpers in `server/auth/token.go`.
