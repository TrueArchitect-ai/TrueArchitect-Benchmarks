**Interceptor:** `web/src/connect.ts` — the `authInterceptor` (around line 154) is attached to the Connect transport; token state helpers live in `web/src/auth-state.ts`.

**Token kinds managed:** two —
1. A short-lived **access token**, sent as an `Authorization: Bearer <token>` header; the interceptor attaches it, proactively refreshes it before expiry (`isTokenExpired` preflight), and reactively refreshes-and-retries once on a 401.
2. A **refresh token**, held in an HTTP-only cookie (all requests use `credentials: "include"`); it is exchanged for new access tokens via `AuthService.RefreshToken` on a separate interceptor-free transport (`refreshTransport`, `web/src/connect.ts:64-72`) to avoid recursion, with concurrent refreshes deduplicated by `createTokenRefreshManager`.

**Backend validation package:** `server/auth` — the `Authenticator` in `server/auth/authenticator.go` validates bearer access tokens (`resolveBearer`, line 159) and refresh tokens (`AuthenticateByRefreshToken`, line 87), loading the user from the store.
