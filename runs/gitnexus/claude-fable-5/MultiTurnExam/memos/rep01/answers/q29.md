Interceptor: `web/src/connect.ts` — the `authInterceptor` (line 156) attaches `Authorization: Bearer <token>` headers to every ConnectRPC request, and on expiry/401 transparently calls the `refreshToken` RPC (with single-flight dedup via the token-refresh manager) and retries. Token storage helpers live in `web/src/auth-state.ts` (imported at the top of connect.ts).

Token kinds: short-lived JWT access tokens (~15 minutes) kept by the frontend, refreshed via a refresh token (held server-side as an HTTP cookie/database record and validated against the store); the backend additionally accepts long-lived Personal Access Tokens (PATs) for programmatic access.

Backend package: `server/auth` — `server/auth/authenticator.go` validates all of them: `AuthenticateByAccessTokenV2` (JWT parse/verify), `AuthenticateByRefreshToken` (JWT parse plus revocation/expiry check against the database), and `AuthenticateByPAT` (hash lookup via `Store.GetUserByPATHash`). It's wired into both protocols through the gateway auth middleware in `server/router/api/v1/v1.go`.
