Interceptor: web/src/connect.ts (the `authInterceptor` at `web/src/connect.ts:156`, applied to the transport at line 188); token kinds: a short-lived **access token** (JWT sent as `Authorization: Bearer ...`, stored via `web/src/auth-state.ts`) and a long-lived **refresh token** (~30 days, kept in an HTTP-only cookie); backend package: server/auth

How it works: the interceptor attaches the current access token to every request, does a preflight refresh if the token is expired, and on a 401 reactively calls the `RefreshToken` RPC (through a dedicated `refreshAuthClient` and a dedup manager so concurrent requests/tabs trigger only one refresh — tabs share fresh tokens via a BroadcastChannel in `web/src/auth-state.ts`). On the backend, the `server/auth` package validates credentials: `Authenticator` (`server/auth/authenticator.go`) parses the bearer access token, falls back to the refresh-token cookie (`AuthenticateByRefreshToken`, which checks the JWT and the stored token record in the DB), with JWT creation/parsing in `server/auth/token.go` and cookie/header extraction in `server/auth/extract.go`. (The same bearer path also accepts personal access tokens, resolved against the store via `GetUserByPATHash`.)
