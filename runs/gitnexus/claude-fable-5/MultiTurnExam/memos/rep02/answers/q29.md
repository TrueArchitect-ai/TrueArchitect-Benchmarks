**Interceptor:** `web/src/connect.ts` — the `authInterceptor` (line 156) sets an `Authorization: Bearer <token>` header on every ConnectRPC request, and on a 401/expiry transparently calls the `refreshToken` RPC and retries; in-memory access-token state and cross-tab sharing live in `web/src/auth-state.ts`.

**Token kinds managed:** a short-lived **access token** (kept in memory/localStorage, sent as the Bearer header) and a **refresh token** (held in an HTTP-only cookie set by the backend — `server/router/api/v1/auth_service_session.go:44-47` — which the frontend uses implicitly via the refresh RPC). The backend additionally accepts **personal access tokens (PATs)** over the same Bearer header.

**Backend validation package:** `server/auth` — the `Authenticator` in `server/auth/authenticator.go` validates access tokens (`AuthenticateByAccessTokenV2`), refresh tokens (`AuthenticateByRefreshToken`), and PATs (`AuthenticateByPAT`), with `resolveBearer` dispatching between them.
