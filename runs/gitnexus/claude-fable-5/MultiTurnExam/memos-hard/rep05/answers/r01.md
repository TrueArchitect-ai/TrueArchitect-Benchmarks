**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in Go code returns nothing — the cache layer is a purely in-process, in-memory cache.

**Actual mechanism:** the cache is implemented in `store/cache/cache.go` — a `Cache` type backed by a `sync.Map` (`store/cache/cache.go:69`), with per-entry expiration timestamps and a background cleanup goroutine that sweeps expired items on a `CleanupInterval` ticker (`store/cache/cache.go:201`).

The caches are configured in `store.New` at `store/store.go:38-52`: three instances are created (`instanceSettingCache`, `userCache`, `userSettingCache`), all with the same hard-coded config — `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`.

So the TTL that applies to user entries is **10 minutes**: `Store.GetUser`/`ListUsers` populate `userCache` via `Set` (`store/user.go:167`, `store/user.go:143`), and `Set` applies the config's `DefaultTTL` (`store/cache/cache.go:94`). There is no external cache server and no per-user TTL override.
