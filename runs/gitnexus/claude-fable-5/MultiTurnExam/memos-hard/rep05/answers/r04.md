**Premise correction: neither.** There is no message broker in this codebase at all — no NATS, RabbitMQ, AMQP, or Kafka client appears anywhere in the Go code (a repo-wide search returns nothing).

**Actual mechanism:** webhook delivery is asynchronous but entirely in-process, built on a buffered Go channel:

- The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — declared at `internal/webhook/webhook.go:39`.
- The "workers" are four goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`); each ranges over the channel and calls `Post` to perform the HTTP delivery.
- Producers call `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send: if the 128-slot buffer is full, the event is **dropped** with a warning log rather than blocking the request path (`internal/webhook/webhook.go:189-194`).

Consequences of this design worth knowing: delivery is best-effort with no persistence, no retries, and no cross-restart durability — anything queued is lost if the process exits, which is exactly the trade-off a broker would change.
