The derived metadata is the memo's **payload** (`memo.Payload` — tags plus content-derived boolean properties), rebuilt from the markdown content whenever the content changes.

**Computation site** — `memopayload.RebuildMemoPayload` at `server/runner/memopayload/runner.go:74`. It calls `markdownService.ExtractAll` (`internal/markdown/markdown.go:356`), which parses the content once with goldmark and fills `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers** —
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (payload computed before the memo is inserted)
- `UpdateMemo` (when the `content` field is updated) — `server/router/api/v1/memo_service.go:447`, inside the handler declared at line 401
- A backfill path: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) rebuilds payloads for *all* memos in batches of 100 — though no production code currently invokes this runner (it's available as a maintenance/migration mechanism).

**Extracted properties** — from a single goldmark parse (`ExtractedData`, `internal/markdown/markdown.go:21`):
- `Tags` — all `#tag` occurrences in the content
- `Property` (`storepb.MemoPayload_Property`), four booleans set while walking the AST (`internal/markdown/markdown.go:394-404`): `HasLink`, `HasCode`, `HasTaskList`, and `HasIncompleteTasks` (a task-list item that isn't checked)
- (`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` stores only `Tags` and `Property` into the payload.)

These payload fields are what list views and filters use (e.g. tag filtering and the "has link / has task list" properties) without re-parsing memo content on every read.
