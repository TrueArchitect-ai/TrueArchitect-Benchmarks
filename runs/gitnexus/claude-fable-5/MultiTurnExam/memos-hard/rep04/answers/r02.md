**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** A repo-wide search for rate-limiting terms (`rate limit`, `ratelimit`, `throttle`, `limiter`, `x/time/rate`) finds nothing in Go code except a doc comment suggesting email rate limiting as a *future* consideration (`internal/email/doc.go:86`). No rate-limiter dependency exists in `go.mod`, and nothing tracks per-user request counts.

What actually gets registered as HTTP middleware is only `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`), plus auth/ACL interceptors on the gRPC/Connect side — none of them do rate limiting.

The closest things to request throttling in the code are **concurrency** limits, not per-user rate limits:
- Thumbnail generation is capped by a weighted semaphore (`maxConcurrentThumbnails`) in `server/router/fileserver/fileserver.go:106-116,447-451`.
- The API service caps concurrent thumbnail/image processing with semaphores of weight 3 and 2 (`server/router/api/v1/v1.go`, `NewAPIV1Service`).
- Webhook dispatch uses a bounded queue (128) with 4 workers (`internal/webhook/webhook.go:39-55`), dropping on overflow.

These are global resource-protection caps, not per-user request limits — so there is no registration site or request-per-time limit to cite.
