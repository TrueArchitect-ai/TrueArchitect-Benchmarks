**Premise correction: there is no nightly database-cleanup job in this codebase.** 

Two facts behind that:

1. The repo does contain a cron scheduler package — `internal/scheduler/` (`scheduler.go`, `parser.go`, `job.go`, with 5/6-field cron expression support). However, it is **never used by production code**: no file outside `internal/scheduler/` itself imports it (only its own tests and examples reference it). It's a self-contained library ("Scheduler Plugin", per `internal/scheduler/README.md`) with no registered jobs, so no job — cleanup or otherwise — is scheduled through it at any time of day.

2. The background work the server actually runs is not cron-based and not database cleanup: the only wired background runner is the S3 presigned-URL refresher, driven by a plain 12-hour `time.Ticker` (`server/runner/s3presign/runner.go:26-41`, started in `server/server.go:153-170`). The other runner (`server/runner/memopayload`) isn't wired in at all. Database cleanup of related rows happens inline/transactionally when entities are deleted (e.g. user deletion in `store/db/*/user_delete.go`), and the only periodic "cleanup" anywhere is the in-memory cache's expired-entry sweep every 5 minutes (`store/store.go:42`, `store/cache/cache.go`) — in-process memory, not the database.

So there is no scheduled time to report: no nightly database-cleanup cron job exists.
