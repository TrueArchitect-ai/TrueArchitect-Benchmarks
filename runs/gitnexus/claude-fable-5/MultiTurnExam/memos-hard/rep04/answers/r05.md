**Premise correction: this project has no GraphQL API.** There is no GraphQL schema file (`.graphql`/`.gql`), no GraphQL server library in the Go code, and no resolver code anywhere in the repository.

**Actual API surface:** The public API is **gRPC-based, defined in Protocol Buffers**, and exposed over HTTP in several forms:

- **Schema definition:** the proto files under `proto/api/v1/` — `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto` — managed with `buf` (`proto/buf.yaml`). Generated code lands in `proto/gen/api/v1/` (plain protobuf, gRPC stubs, grpc-gateway `.pb.gw.go`, and Connect handlers under `proto/gen/api/v1/apiv1connect/`).
- **Serving:** `APIV1Service` implements the services (`server/router/api/v1/`), registered in `server/server.go:76-88` — including a REST-style HTTP mapping via the grpc-gateway (`apiV1Service.RegisterGateway`, `server/server.go:88`) and Connect-RPC handlers (`server/router/api/v1/connect_services.go`).
- Additional non-gRPC surfaces are plain Echo HTTP routes: the file server (`server/router/fileserver/`), RSS feeds (`server/router/rss/`), and an MCP endpoint (`server/router/mcp/`, registered at `server/server.go:96`).

So there is no GraphQL schema location to cite — the equivalent "schema" is the protobuf service definitions in `proto/api/v1/*.proto`.
