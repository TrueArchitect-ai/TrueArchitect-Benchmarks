**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in the Go code returns zero hits — no client library, no connection config, no env var. The cache layer is a purely **in-process, in-memory cache** built on `sync.Map`.

**Actual mechanism:** The cache is implemented in `store/cache/cache.go` — a thread-safe in-memory `Cache` type with per-entry TTL, periodic cleanup, and a max-item cap (`Config` with `DefaultTTL`, `CleanupInterval`, `MaxItems`). The store constructs three separate instances of it in `store.New` at `store/store.go:38-53`: `instanceSettingCache`, `userCache`, and `userSettingCache`.

**TTL for user entries:** 10 minutes. The `cacheConfig` built in `store/store.go:40-44` sets `DefaultTTL: 10 * time.Minute` (with cleanup every 5 minutes and a 1000-item cap), and user entries are written via plain `Set` (e.g. `s.userCache.Set(...)` in `store/user.go:143,167`), which uses that default TTL — matching `cache.DefaultConfig()` in `store/cache/cache.go:57-63`.

So: nothing to configure for Redis — user cache entries live in process memory and expire after 10 minutes (or on eviction/explicit invalidation, e.g. on user update/delete).
