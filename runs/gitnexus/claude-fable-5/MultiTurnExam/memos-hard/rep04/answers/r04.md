**Premise correction: neither.** There is no message broker in this codebase — no NATS, RabbitMQ, Kafka, or AMQP client appears in `go.mod` or anywhere in the Go source (a repo-wide search returns zero hits).

**Actual mechanism:** Webhook delivery is asynchronous but entirely in-process, using a buffered Go channel as the "queue":

- The queue is declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel holding up to 128 pending payloads.
- The "workers" are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`); each ranges over the channel and calls `Post` to perform the actual HTTP delivery, logging a warning on failure.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send: if the channel buffer is full, the dispatch is **dropped** with a warning rather than blocking the request path.

Consequences of this design worth knowing: there is no persistence, no retry, and no cross-process distribution — queued webhooks are lost on server shutdown or queue overflow, which is exactly the trade-off a broker would otherwise cover.
