**Delivery function:** `Post` in `internal/webhook/webhook.go` (line 120) is where the outbound HTTP POST actually executes — it marshals the payload, optionally adds Standard-Webhooks HMAC-SHA256 signature headers, and sends via `safeClient.Do(req)`. `PostAsync` (line 184) is the async entry point that queues payloads for a pool of worker goroutines, which still call `Post`. It's triggered from the API layer, e.g. `server/router/api/v1/memo_service_webhooks.go`.

**Protection mechanism:** dial-time SSRF blocking of reserved/private IPs. The shared `safeClient` uses a custom transport whose `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the target hostname at connection time and rejects any address matching `isReservedIP`. The reserved ranges and the check live in `internal/webhook/validate.go` — `reservedCIDRs` (loopback, RFC-1918, link-local/cloud IMDS 169.254.0.0/16, and IPv6 equivalents, lines 14–23) and `isReservedIP` (line 44). Because the check happens inside the dialer (not just once at registration), it also defeats DNS-rebinding attacks. Two supporting pieces: `ValidateURL` (`validate.go:62`) rejects bad schemes and private-resolving hostnames when a webhook is registered, and the `AllowPrivateIPs` flag (`validate.go:41`) lets self-hosted deployments opt out.

In the requested format: `webhook.Post` (dispatched via `PostAsync` worker queue) — `internal/webhook/webhook.go`; dial-time reserved/private-IP blocking via `safeDialContext` + `isReservedIP`/`reservedCIDRs` — `internal/webhook/webhook.go` and `internal/webhook/validate.go`.
