**1st: `store.User` — 2nd: `store.Memo`.**

I counted distinct Go packages (non-test files) outside the data layer (`store/` and its `store/db/*` drivers) that reference each persistent entity struct defined in the `store` package (`store/user.go`, `store/memo.go`, `store/attachment.go`, etc.):

- **`store.User`** — ~6 outside packages: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/rss`. (9 if you also count the three `store/db/{sqlite,mysql,postgres}` driver packages, which I treat as part of the data layer.)
- **`store.Memo`** — ~4 outside packages: `server/notification`, `server/router/api/v1`, `server/router/rss`, `server/runner/memopayload`. (7 counting drivers.)

Runner-up behind those: `store.Attachment` with 3 outside packages (`server/router/api/v1`, `server/router/fileserver`, `server/router/rss`); the rest (`Reaction`, `Inbox`, `IdentityProvider`, `UserSetting`, `InstanceSetting`, `MemoRelation`) each appear in only 1–2 packages outside the layer, and `Activity`/`Webhook` in none.

So the ranking is: **1st `User` (~6 packages), 2nd `Memo` (~4 packages)** — and the ordering is the same under either counting convention.
