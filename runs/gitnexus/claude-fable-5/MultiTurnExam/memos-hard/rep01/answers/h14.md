**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`. It runs a single goldmark parse via `markdownService.ExtractAll` (`internal/markdown/markdown.go:356`) and writes the results into the memo's `Payload` (`storepb.MemoPayload`, defined in `proto/store/memo.proto`), which is persisted alongside the memo and used to drive list filtering/previews without re-parsing content.

**Triggers (operations that recompute it):**
- Memo creation — `APIV1Service.CreateMemo` calls it before insert (`server/router/api/v1/memo_service.go:108`).
- Memo update, specifically when the `content` field is changed — inside `UpdateMemo`'s content branch (`server/router/api/v1/memo_service.go:447`).
- Bulk backfill — `memopayload.Runner.RunOnce` iterates all memos in batches of 100 and rebuilds each payload (`server/runner/memopayload/runner.go:27-72`), intended for migration/repair (though nothing currently wires this runner into server startup).

**Extracted properties** (from `ExtractAll`, `internal/markdown/markdown.go:356-422`):
- `Tags` — all `#tag` occurrences, deduplicated case-preservingly (stored in `MemoPayload.Tags`).
- `Property.Title` — text of the first block-level H1 heading, if the document starts with one.
- `Property.HasLink` — any markdown link present.
- `Property.HasCode` — any code block, fenced code block, or inline code span.
- `Property.HasTaskList` / `Property.HasIncompleteTasks` — task checkboxes present / any unchecked.

(`ExtractAll` also collects `@mention` usernames into `ExtractedData.Mentions`, but `RebuildMemoPayload` only persists the tags and the property struct — mentions are used elsewhere for notifications, not stored in the payload.)
