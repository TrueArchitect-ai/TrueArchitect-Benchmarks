**Implementation:** the single concrete type is the unexported `service` struct (`internal/markdown/markdown.go:58`), which wraps a goldmark parser/renderer. It is the only implementation of the `markdown.Service` interface (`internal/markdown/markdown.go:31`) in the codebase, so it is what executes at runtime.

**Construction:** the factory `markdown.NewService` (`internal/markdown/markdown.go:85`) builds it, assembling goldmark with GFM plus optional custom tag/mention extensions. In production it is constructed in exactly one place: `NewAPIV1Service` (`server/router/api/v1/v1.go:48`), with `WithTagExtension()` and `WithMentionExtension()` enabled. (Tests construct their own via `server/router/api/v1/test/test_helper.go:44`.)

**Holders of the interface:**
- `APIV1Service.MarkdownService` — `server/router/api/v1/v1.go:35` (used for snippets, tag extraction, payload rebuilds in the gRPC API layer).
- `RSSService.MarkdownService` — `server/router/rss/rss.go:45`; the same instance is passed along from the API service at server wiring time (`server/server.go:85`) and used for server-side HTML rendering of feeds (`server/router/rss/rss.go:339`).
- `memopayload.Runner.MarkdownService` — `server/runner/memopayload/runner.go:16`; the runner type accepts the interface via `NewRunner`, though nothing in production currently constructs that runner — the package's `RebuildMemoPayload` function is instead called directly with the API service's instance (`server/router/api/v1/memo_service.go:108`, `:447`).

So at runtime there is effectively one goldmark-backed `service` instance, created by the API v1 service and shared with the RSS service.
