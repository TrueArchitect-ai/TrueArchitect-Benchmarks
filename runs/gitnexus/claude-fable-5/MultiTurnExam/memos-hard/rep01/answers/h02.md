**Delivery function: `Post` (with `PostAsync` enqueuing onto a bounded worker queue that calls it) — `internal/webhook/webhook.go`; protection mechanism: dial-time SSRF guard `safeDialContext`/`isReservedIP`, backed by the `reservedCIDRs` blocklist and the URL-time check `ValidateURL` — `internal/webhook/webhook.go` and `internal/webhook/validate.go`**

Details:

- The actual outbound HTTP POST executes in `Post` (`internal/webhook/webhook.go:120`), which marshals the payload, optionally signs it (Standard Webhooks HMAC-SHA256 headers), and sends it via the shared `safeClient`. Content-change paths call `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto `asyncPostQueue`; four goroutines started in `init()` drain the queue and invoke `Post`.
- The SSRF protection lives in the client's transport: `safeClient` uses `safeDialContext` (`internal/webhook/webhook.go:59`) as its `DialContext`, which resolves the target hostname and refuses to connect if any resolved IP is in a reserved/private range per `isReservedIP` (`internal/webhook/validate.go:44`). The blocklist `reservedCIDRs` (`internal/webhook/validate.go:14`) covers loopback, RFC-1918 ranges, link-local (including the cloud metadata address 169.254.169.254), and IPv6 equivalents. Because the check happens at dial time, it also defeats DNS-rebinding attacks, not just bad URLs at registration.
- There's a second, earlier layer: `ValidateURL` (`internal/webhook/validate.go:62`) rejects webhook URLs that aren't http/https or that resolve to reserved IPs when webhooks are created/updated via the API. The `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) can disable the guard for self-hosted deployments targeting local-network services.
