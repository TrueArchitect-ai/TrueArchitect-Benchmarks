**Premise correction: there is no per-user API rate-limiting middleware in this codebase — nothing to register, and no request limits exist.** A repo-wide search for rate-limit/throttle/limiter terms in the Go sources finds only a documentation comment suggesting operators rate-limit email sending (`internal/email/doc.go:86`); no implementation exists.

What the server actually registers as middleware is just `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`), plus auth/logging interceptors on the gRPC side — none of them count or limit requests per user.

The closest things to throttling in the code are concurrency caps, not rate limits: semaphores bounding concurrent thumbnail generation and image processing (`server/router/api/v1/v1.go:59-60`, `server/router/fileserver/fileserver.go:116`), and the bounded webhook dispatch queue of 128 entries drained by 4 workers (`internal/webhook/webhook.go:39-55`). These protect server resources but impose no per-user request quota. If you need API rate limiting for a deployment, it would have to be added (or handled by a reverse proxy in front of memos).
