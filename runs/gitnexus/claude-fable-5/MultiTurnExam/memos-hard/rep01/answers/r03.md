**Premise correction: there is no nightly database-cleanup job, and no cron job is scheduled at all.** Two things make the premise wrong:

1. The repo does contain a cron scheduler package — `internal/scheduler` (`internal/scheduler/scheduler.go`, with a cron-expression parser in `internal/scheduler/parser.go`) — but nothing outside the package imports it. It is used only by its own tests and examples (`internal/scheduler/example_test.go`, etc.), so no job of any kind is registered with it in production code.
2. No database-cleanup logic exists to schedule. The only background jobs the server runs are started in `Server.startBackgroundRunners` (`server/server.go:153`), which launches a single runner: the S3 presign refresher (`server/runner/s3presign/runner.go`), on a 12-hour ticker — not a cron time, and not database cleanup. The "cleanup" hits in the codebase are unrelated: in-memory cache cleanup intervals (`store/cache/cache.go`) and best-effort attachment/storage cleanup performed inline during user deletion (`server/router/api/v1/user_service.go:421-450`).

So there is no time to report — neither the job nor its scheduling exists.
