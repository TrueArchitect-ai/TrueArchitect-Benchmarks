**1st: `store.User` (~6 outside packages); 2nd: `store.Memo` (~4 outside packages)**

The persistent entity types live in the `store` package (`store/user.go`, `store/memo.go`, `store/attachment.go`, `store/inbox.go`, `store/reaction.go`, etc.), with per-database driver implementations under `store/db/{sqlite,mysql,postgres}`. Counting distinct packages *outside* that data layer (excluding `store/`, `store/db/*`, and generated `proto/gen/store`, and excluding `_test.go` files) that reference each type:

1. **`store.User` — 6 packages**: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test` (test-helper package), `server/router/fileserver`, `server/router/rss`. (5 if you discount the test-helper package.)
2. **`store.Memo` — 4 packages**: `server/notification`, `server/router/api/v1`, `server/router/rss`, `server/runner/memopayload`.

Runners-up for context: `store.Attachment` is next with 3 (`server/router/api/v1`, `server/router/fileserver`, `server/router/rss`), then `store.Inbox` with 2. `User` leads because authentication (`server/auth`), notifications, the gRPC API layer, the file server (avatar serving), and RSS all need the user record, whereas most other entities are only touched by the API layer.
