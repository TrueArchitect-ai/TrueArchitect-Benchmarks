**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in the Go sources finds nothing — the cache layer is a purely in-process, thread-safe in-memory cache, so there is no Redis connection to configure.

**Actual mechanism:** the cache is implemented in `store/cache/cache.go` — a `Cache` struct built on `sync.Map` with per-item TTL expiration, a background cleanup goroutine, and a max-item cap. The `Store` creates three separate instances of it in `store.New` (`store/store.go:37-53`): `instanceSettingCache`, `userCache`, and `userSettingCache`, all with the same hardcoded config.

**TTL for user entries: 10 minutes.** The `userCache` is constructed with `DefaultTTL: 10 * time.Minute` (plus `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`) at `store/store.go:39-44`; user objects are inserted with that default TTL via `Set` in `Store.GetUser`/`ListUsers` (`store/user.go:132, 143, 167`). These values are compile-time defaults (matching `cache.DefaultConfig()` in `store/cache/cache.go:57`) — they are not configurable via flags or environment.
