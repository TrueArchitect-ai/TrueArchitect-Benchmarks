**Premise correction: neither — there is no message broker in this codebase.** No NATS, RabbitMQ, or any other external queueing system appears anywhere in the Go sources or dependencies.

**Actual mechanism:** webhook delivery is queued entirely in-process using a buffered Go channel. The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared at `internal/webhook/webhook.go:39`. The "workers" are four goroutines started in that package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over the channel and calling `Post` (`internal/webhook/webhook.go:120`) to perform the actual HTTP delivery. Producers (the memo webhook dispatchers in `server/router/api/v1/memo_service_webhooks.go`) enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send — if the 128-slot buffer is full, the event is dropped with a warning log rather than blocking the request path. Consequently there is no persistence, retry, or cross-process delivery: pending webhooks are lost if the server exits.
