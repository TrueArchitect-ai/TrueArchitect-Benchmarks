Distinct server surfaces that enforce memo visibility:

- **gRPC/Connect API — single-memo read guard** `checkMemoReadAccess` — `server/router/api/v1/memo_service.go:39-68` (public allowed anonymously only if the instance allows it; private restricted to creator; also list queries constrain `VisibilityList` at `memo_service.go:219-225`). Related per-RPC checks in the same surface reuse the pattern for sub-resources: comments (`server/router/api/v1/memo_service_comments.go:41`), reactions (`server/router/api/v1/reaction_service.go:30-38`), memo attachments listing (`server/router/api/v1/memo_attachment_service.go:214-222`), attachment service (`server/router/api/v1/attachment_service.go:445-451`), and user stats (`server/router/api/v1/user_service_stats.go:84-90, 218-220`).
- **File server (raw attachment bytes)** — `checkAttachmentPermission` in `server/router/fileserver/fileserver.go:660-705`: serves public-memo attachments anonymously only when allowed, honors share tokens, otherwise requires an authenticated user and blocks private memos' attachments from non-creators/non-admins.
- **SSE real-time event delivery** — `SSEClient.canReceive` in `server/router/api/v1/sse_hub.go:134-143`: private-memo events are delivered only to the creator or an admin, using the `Visibility`/`CreatorID` fields carried on each event (`sse_hub.go:31-33`).
- **RSS feeds** — `server/router/rss/rss.go:90` and `:141`: feed queries hard-restrict to `VisibilityList: []store.Visibility{store.Public}`.
- **Frontend sitemap** — `server/router/frontend/frontend.go:150`: sitemap generation lists only `store.Public` memos.
- **Notification/email surface** — recipients are filtered by memo visibility before notifying: `server/router/api/v1/user_service_notifications.go:309-312`, `server/notification/email.go:313-316`, and mention notifications in `server/router/api/v1/memo_mention_helpers.go:62-84` (no private-memo notifications to non-creators).

So visibility is enforced independently in at least six surfaces: the v1 API handlers, the file server, the SSE hub, RSS, the frontend sitemap, and the notification path.
