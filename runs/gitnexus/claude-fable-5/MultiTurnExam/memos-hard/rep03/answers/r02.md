**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** A repo-wide search for rate-limit/throttle/limiter code finds nothing but a documentation aside (`internal/email/doc.go:86`, a comment suggesting email sending "should" be rate-limited — not implemented as middleware).

What the server actually registers as global middleware is only `middleware.Recover()` and a CORS middleware, at `server/server.go:51-52`; the API surface adds authentication/authorization interceptors (`server/router/api/v1/v1.go`, `acl_config.go`) but no request-rate accounting per user.

The closest mechanisms that exist are concurrency caps, not rate limits, and they're not per-user:

- Semaphores limiting concurrent thumbnail generation (3) and image processing (2) in the API service — `server/router/api/v1/v1.go:59-60` — and `maxConcurrentThumbnails` in the file server — `server/router/fileserver/fileserver.go:107-116`.
- A bounded webhook dispatch queue (drops when full) — `internal/webhook/webhook.go:39, 184-196`.
- Content-length limits on memo content (checked in `server/router/api/v1/memo_service.go:105-107`).

So there is no registration site and no request-per-time-window limits to cite; per-user API rate limiting simply isn't implemented.
