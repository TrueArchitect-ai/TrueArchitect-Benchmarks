**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in the Go sources returns nothing — no client library, no connection config, no environment variable. The cache layer is a purely **in-process, in-memory cache**.

Actual mechanism: the cache is a thread-safe `sync.Map`-based implementation in `store/cache/cache.go` (the `Cache` type, with TTL expiration, a background cleanup goroutine, and a max-item cap). The user cache is constructed in `Store.New` at `store/store.go:38-53`: three caches (`instanceSettingCache`, `userCache`, `userSettingCache`) are all created with the same inline config at `store/store.go:40-45`:

- **DefaultTTL: 10 minutes** — this is the TTL applied to user entries, since `Store.GetUser`/`ListUsers` populate `userCache` via plain `Set` (`store/user.go:143`, `:167`), which uses the default TTL.
- CleanupInterval: 5 minutes; MaxItems: 1000.

So: user entries live in an in-memory cache with a 10-minute TTL, configured at `store/store.go:40-45` and implemented in `store/cache/cache.go`; nothing is ever configured for, or connected to, Redis.
