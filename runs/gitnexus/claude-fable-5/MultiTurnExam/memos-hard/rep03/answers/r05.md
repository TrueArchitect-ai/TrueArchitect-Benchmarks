**Premise correction: this project has no GraphQL API — no schema files, no GraphQL libraries, no resolvers anywhere in the codebase** (a repo-wide search for "graphql" matches nothing in Go, TypeScript, or proto sources).

Actual API surface: the public API is **gRPC-style, defined in Protocol Buffers**:

- Schema definitions live in `proto/api/v1/*.proto` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus `common.proto`.
- Generated Go stubs are under `proto/gen/api/v1/` (including Connect-RPC handlers in `proto/gen/api/v1/apiv1connect/`).
- The services are implemented by `APIV1Service` in `server/router/api/v1/` and exposed over HTTP two ways from `RegisterGateway` (`server/router/api/v1/v1.go`): a gRPC-Gateway that maps the RPCs to RESTful JSON endpoints (with auth middleware), and Connect protocol handlers — both mounted on the Echo server in `server/server.go`.

So instead of a GraphQL schema, the contract is the protobuf schema in `proto/api/v1/`, served as REST (via gRPC-Gateway annotations) and Connect/gRPC.
