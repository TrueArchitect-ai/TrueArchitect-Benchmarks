**Premise correction: there is no nightly database-cleanup job — and the cron scheduler isn't even wired into the server.**

Two things are wrong with the premise:

1. A cron scheduler package does exist (`internal/scheduler/` — a GitHub-Actions-inspired cron job scheduler with `ParseCronExpression`, `Job`, `Register`, etc.), but it is **never used by production code**. The only files importing `internal/scheduler` are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). No server code registers any job with it. The "daily-cleanup" string that might suggest otherwise is just an illustrative example in the package documentation (`internal/scheduler/doc.go:15`).
2. No database-cleanup task exists anywhere else either. The background work the server actually runs is limited to the S3 presign refresher, started in `Server.startBackgroundRunners` (`server/server.go:153-174`), which ticks every 12 hours (`server/runner/s3presign/runner.go:27`) — it refreshes presigned URLs and doesn't clean the database. The only "cleanup" in the codebase is the in-memory cache's expired-entry sweep every 5 minutes (`store/cache/cache.go`, configured at `store/store.go:42`), which is unrelated to the database.

So there is no scheduled time to report: no such job is registered, and the cron scheduler runs nothing at all in production.
