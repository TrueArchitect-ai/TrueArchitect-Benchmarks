**Abstraction package: `internal/idp` (`internal/idp/idp.go`); implementation package: `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`).**

The `internal/idp` package defines the provider-agnostic abstraction — the `IdentityProviderUserInfo` struct (identifier, display name, email, avatar) that any provider must produce. The only concrete protocol implementation shipped is OAuth 2.0, in `internal/idp/oauth2`: its `IdentityProvider` type wraps a `storepb.OAuth2Config` and implements `ExchangeToken` (with PKCE support) and user-info retrieval, mapping provider responses into `idp.IdentityProviderUserInfo`. (The proto definitions in `proto/gen/store/idp.pb.go` and `proto/gen/api/v1/idp_service.pb.go` also only define an OAuth2 config variant — no SAML/LDAP implementations exist.)
