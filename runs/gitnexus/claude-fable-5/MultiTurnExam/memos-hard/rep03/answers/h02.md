**Delivery function: `webhook.Post` — `internal/webhook/webhook.go` (line 120); protection mechanism: dial-time SSRF guard `safeDialContext` / `isReservedIP` — `internal/webhook/webhook.go` (lines 57-77) with the reserved-range logic in `internal/webhook/validate.go`.**

How it fits together:

- When memos or comments change, the API layer (e.g. `dispatchMemoRelatedWebhook` in `server/router/api/v1/memo_service_webhooks.go`) enqueues payloads via `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which feeds a bounded queue drained by 4 worker goroutines. The actual outbound HTTP POST — JSON body, optional Standard Webhooks HMAC-SHA256 signing, response check — executes in `Post` at `internal/webhook/webhook.go:120-180`.
- `Post` sends through a shared `safeClient` whose `http.Transport` uses `safeDialContext` (`internal/webhook/webhook.go:59-77`). At dial time it resolves the hostname and rejects any address matching `isReservedIP` (`internal/webhook/validate.go:44-54`), which covers loopback, RFC-1918 private ranges, link-local (including the cloud metadata address 169.254.169.254), and the IPv6 equivalents listed in `reservedCIDRs` (`internal/webhook/validate.go:14-23`). Enforcing this at dial time rather than only at URL-save time also defeats DNS-rebinding tricks.
- There's a second, earlier layer: `ValidateURL` (`internal/webhook/validate.go:62-83`) applies the same reserved-IP check when a webhook URL is registered. The `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) can disable the guard for self-hosted deployments that intentionally target LAN services.
