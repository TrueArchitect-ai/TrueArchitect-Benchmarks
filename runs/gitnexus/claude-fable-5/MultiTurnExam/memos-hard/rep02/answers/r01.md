**Premise correction: there is no Redis anywhere in this codebase — the cache layer is a purely in-memory, in-process cache.** A case-insensitive grep for "redis" across all Go files returns nothing; no Redis client library is imported and no connection is configured.

Actual mechanism: the cache is a hand-rolled, thread-safe in-memory cache with TTL, size cap, and periodic cleanup, implemented in `store/cache/cache.go`. The `Store` constructor creates three instances of it — `instanceSettingCache`, `userCache`, and `userSettingCache` — in `store/store.go:38-53`, using an inline config:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

User entries are written via `s.userCache.Set(...)` (e.g. `store/user.go:143,167`), and `Set` applies the default TTL (`store/cache/cache.go:92-94`), so **user cache entries live for 10 minutes**, with expired items swept every 5 minutes by `cleanupLoop` (`cache.go:199`) and an LRU-ish eviction when the 1000-item cap is hit. The caches are shut down via `Store.Close` (`store/store.go:74-76`), not by closing any network connection.
