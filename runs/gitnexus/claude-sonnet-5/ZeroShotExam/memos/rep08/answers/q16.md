Reactions and comment-relations are handled at the API/service layer, but the question specifically asks about the **store layer**, so the answer is based on `store/memo.go`.

Before deleting the memo row itself, the store layer's `Store.DeleteMemo` (store/memo.go:140-159) deletes:

- **Memo relations** where the memo is the source (`memo_relation` rows with `memo_id = <deleted memo>`)
- **Memo relations** where the memo is the target/related memo (`memo_relation` rows with `related_memo_id = <deleted memo>`)
- **Attachments** linked to the memo (fetched via `ListAttachments` and removed one-by-one via `DeleteAttachment`)

Only after these cleanups does it call `s.driver.DeleteMemo(ctx, delete)` to remove the memo row itself.

(Note: at a layer above the store — `APIV1Service.DeleteMemo` in `server/router/api/v1/memo_service.go:518-582` — reactions are listed and comment memos are recursively deleted via `Store.DeleteMemo` before the parent memo's deletion, but that orchestration happens in the service/router layer, not inside the store's `DeleteMemo` function itself.)
