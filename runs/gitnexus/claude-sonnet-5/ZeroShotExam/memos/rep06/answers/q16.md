The driver-level `DeleteMemo` just deletes the memo row itself — all cascading cleanup happens in the store layer's `Store.DeleteMemo` wrapper (`store/memo.go:140-159`), which runs before calling `s.driver.DeleteMemo`.

q16.
Before deleting the memo row, `Store.DeleteMemo` (store/memo.go:140-159) deletes:
- **Memo relations** where the memo is the source (`memo_relation` rows via `DeleteMemoRelation{MemoID: &delete.ID}`)
- **Memo relations** where the memo is the target (`memo_relation` rows via `DeleteMemoRelation{RelatedMemoID: &delete.ID}`)
- **Attachments** linked to the memo (each fetched via `ListAttachments{MemoID: &delete.ID}` and removed individually with `DeleteAttachment`)
