Memo lifecycle events that dispatch webhooks, and their dispatch functions (all in `server/router/api/v1/memo_service_webhooks.go`):

- memo created: `DispatchMemoCreatedWebhook` (called from `server/router/api/v1/memo_service.go:157`)
- memo updated: `DispatchMemoUpdatedWebhook` (called from `server/router/api/v1/memo_update_helpers.go:67`)
- memo deleted: `DispatchMemoDeletedWebhook` (called from `server/router/api/v1/memo_service.go:562`)
- memo comment created: `DispatchMemoCommentCreatedWebhook` (called from `server/router/api/v1/memo_service_comments.go:119`)

All four route through `dispatchMemoRelatedWebhook` (used by the created/updated/deleted trio; the comment-created variant builds its payload inline) which both build a `webhook.WebhookRequestPayload` and hand it to `webhook.PostAsync` (`internal/webhook/webhook.go:184`). `PostAsync` enqueues onto `asyncPostQueue`, a bounded channel drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each of which calls the actual delivery function `Post` (`internal/webhook/webhook.go:120`) — this is where the final convergence point is: `Post` in `internal/webhook/webhook.go` performs the signed HTTP POST to the webhook URL via the SSRF-guarded `safeClient`.
