Before deleting the memo row itself, `Store.DeleteMemo` (store/memo.go:140-159) deletes:

1. **Memo relation records** — via `driver.DeleteMemoRelation`, called twice: once where the memo is the source (`MemoID`) and once where it's the target (`RelatedMemoID`) (store/memo.go:142-147)
2. **Attachment records** — lists all attachments linked to the memo via `ListAttachments`, then deletes each one individually with `DeleteAttachment` (store/memo.go:149-157)

Only after both of these complete does it call `s.driver.DeleteMemo(ctx, delete)` to remove the memo row (store/memo.go:158).

Note: the API handler (`server/router/api/v1/memo_service.go:567-577`) also deletes memo *comments* (child memos linked via a `MemoRelationComment` relation) before calling `Store.DeleteMemo` on the memo itself, but that cleanup happens at the API/service layer, not inside the store layer's `DeleteMemo`.
