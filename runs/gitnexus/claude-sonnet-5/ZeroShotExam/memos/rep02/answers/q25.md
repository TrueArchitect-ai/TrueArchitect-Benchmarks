The filter is CEL (Common Expression Language) — parsed via the `cel-go` library (`github.com/google/cel-go`). The engine lives in `internal/filter/` (`engine.go`, `parser.go`/`ir.go`, `render.go`, `schema.go`), and is invoked from `server/router/api/v1/memo_service.go:178` (`ListMemos`), which validates `request.Filter` via `validateFilter` (defined in `server/router/api/v1/shortcut_service.go:336`) and appends it to `store.FindMemo.Filters`.

Mechanism: `Engine.Compile` (`internal/filter/engine.go`) compiles the CEL string into an AST via `cel.NewEnv`/`env.Compile`, walks the parsed expression into a dialect-agnostic `Condition` tree (`buildCondition`, in `ir.go`), and then `Program.Render` (`internal/filter/render.go`) walks that tree with a `renderer` that emits dialect-specific SQL fragments + args (switching on `DialectSQLite`/`DialectPostgres`/`DialectMySQL` for things like column qualification, timestamp extraction, JSON containment, and string length semantics) to produce the final `Statement{SQL, Args}` used in the store layer's query.
