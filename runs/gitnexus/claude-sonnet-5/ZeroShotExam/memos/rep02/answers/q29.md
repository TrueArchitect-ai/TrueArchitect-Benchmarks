- **Interceptor**: `web/src/connect.ts` — the `authInterceptor` const (`web/src/connect.ts:156-178`), a Connect-RPC `Interceptor` attached to the shared transport (`web/src/connect.ts:184-189`). It reads the token via `getRequestToken()`, sets `Authorization: Bearer <token>`, and on a `401 Unauthenticated` retries once after refreshing via `refreshAccessToken()`/`doRefreshAccessToken()` (which calls `AuthService.refreshToken`), falling back to `redirectOnAuthFailure()` if refresh fails.
- **Token kinds**: short-lived JWT **access tokens** (managed client-side via `web/src/auth-state.ts`: `getAccessToken`, `setAccessToken`, `isTokenExpired`) sent as a `Bearer` header, plus an HttpOnly **refresh token** cookie (sent automatically via `credentials: "include"` in `fetchWithCredentials`) used to mint new access tokens.
- **Backend validation package**: `server/auth` (specifically `server/auth/authenticator.go`'s `Authenticator` type), which validates JWT access tokens (`AuthenticateByAccessTokenV2`/`ParseAccessTokenV2`), refresh tokens (`AuthenticateByRefreshToken`), and Personal Access Tokens (`AuthenticateByPAT`), used consistently by the gRPC/Connect interceptors and file server.
