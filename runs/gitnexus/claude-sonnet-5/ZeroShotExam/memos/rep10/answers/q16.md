Before deleting the memo row itself, `Store.DeleteMemo` (store/memo.go:140-159) deletes:

- **Memo relations where the memo is the source** — `driver.DeleteMemoRelation(&DeleteMemoRelation{MemoID: &delete.ID})` (store/memo.go:142)
- **Memo relations where the memo is the related/target memo** — `driver.DeleteMemoRelation(&DeleteMemoRelation{RelatedMemoID: &delete.ID})` (store/memo.go:145) — this covers comment relations and any other memo-to-memo relations
- **Attachments linked to the memo** — listed via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and deleted one-by-one via `DeleteAttachment` (store/memo.go:149-157)

Only after these does it call `driver.DeleteMemo(ctx, delete)` to remove the memo row itself (store/memo.go:158, e.g. store/db/postgres/memo.go:244-255).

Note: at the API-handler layer (server/router/api/v1/memo_service.go:518-591), memo *comments* (child memos linked via a `MemoRelationComment` relation) are deleted first by recursively calling `Store.DeleteMemo` on each comment's memo ID before deleting the parent memo — but that recursion itself goes through the same store-layer cleanup above. Reactions are listed (for the webhook payload) but are not explicitly deleted by this code path.
