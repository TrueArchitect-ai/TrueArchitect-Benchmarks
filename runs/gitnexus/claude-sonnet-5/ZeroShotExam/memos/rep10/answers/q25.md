Engine: Google's CEL (`github.com/google/cel-go`), wrapped by memos' own `internal/filter` package (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

Mechanism: `ListMemos` (server/router/api/v1/memo_service.go:211) passes `request.Filter` to `filter.DefaultEngine()`, which compiles the CEL expression via `cel.Env.Compile` into a CEL AST, converts it into a dialect-agnostic `Condition` tree (`buildCondition` in `internal/filter/ir.go`/`parser.go`), and then `Program.Render(RenderOptions{Dialect: ...})` in `internal/filter/render.go` walks that tree emitting SQL fragments with `switch` statements on `DialectName` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`) so each node (string ops, time functions, casts, etc.) is rendered with the correct dialect-specific SQL syntax and placeholders.
