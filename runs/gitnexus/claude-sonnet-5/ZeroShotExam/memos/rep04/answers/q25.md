q25. The filter expression is parsed with **CEL (Common Expression Language) via `cel-go`**, implemented in Anthropic-adjacent internal package `internal/filter/` (specifically `internal/filter/parser.go` for CEL→IR conversion, `internal/filter/schema.go` for the memo-specific CEL environment/field declarations, `internal/filter/ir.go` for the intermediate representation, `internal/filter/render.go` for SQL generation, and `internal/filter/engine.go` as the glue exposing `filter.DefaultEngine()`/`Engine.Compile`/`CompileToStatement`).

Mechanism: the engine parses the filter string as a CEL expression validated against the memo schema, normalizes the resulting CEL AST into a dialect-agnostic IR tree of conditions (`ir.go`), and then `render.go` walks that IR to emit a SQL fragment plus placeholder args customized per target dialect (SQLite, MySQL, Postgres) — handling differences like `?` vs `$n` placeholders, JSON payload access, boolean coercion, `LIKE`/`ILIKE`/`REGEXP`/`~`, and tag/array predicates for each engine.
