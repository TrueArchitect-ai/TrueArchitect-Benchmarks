**Runner — trigger**

- S3 presign runner (`server/runner/s3presign`) — runs once synchronously at startup, then every 12h via `time.NewTicker(runnerInterval)` (`server/runner/s3presign/runner.go:27,30`). Started from `Server.Start()` → `startBackgroundRunners()` in `server/server.go:129,151-171`.
- Store cache cleanup loops (instance-setting cache, user cache, user-setting cache) — `time.NewTicker(c.config.CleanupInterval)`, default 5 min (`store/cache/cache.go:83,200-213`). Created by `store.New()` (`store/store.go:44,51-53`), which runs before the HTTP server starts, from `cmd/memos/main.go:62`.
- Webhook dispatch pool (4 goroutines) — `internal/webhook/webhook.go:38-49`, started in package `init()`; each goroutine blocks on `range asyncPostQueue` (a channel), so it's request/event-triggered, not time-scheduled.
- Email dispatch pool (2 goroutines) — `internal/email/email.go:17-33`, same pattern: package `init()` spawns goroutines draining `asyncEmailQueue`, triggered by enqueued sends, not a timer.

**Unused scheduling infra:** `internal/scheduler` is a full cron-style scheduler package (cron parsing, `Job`, middleware, `Scheduler.Start()`/`Stop()`) with its own README describing it as the job-scheduling mechanism, but `grep -rln "usememos/memos/internal/scheduler"` shows the only importers are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). Nothing in `server/`, `cmd/`, or `store/` imports it — it's never started by the running server. Similarly, `server/runner/memopayload/runner.go` defines a `Runner`/`RunOnce` that's never constructed anywhere; only the sibling free function `RebuildMemoPayload` is used, and it's called synchronously per-request from `server/router/api/v1/memo_service.go:108,447`, not as a background job.
