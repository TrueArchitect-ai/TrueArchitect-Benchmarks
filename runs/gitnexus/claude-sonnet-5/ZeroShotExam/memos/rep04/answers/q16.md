When the memo API handler (`DeleteMemo` in `server/router/api/v1/memo_service.go:518-582`) deletes a memo, it first deletes each memo-comment (a memo linked via a `MemoRelationComment` relation) by recursively calling `store.DeleteMemo` on it. Then the store layer's `Store.DeleteMemo` (`store/memo.go:140-159`) does the following before deleting the memo row itself:

1. **Memo relations** — deletes `memo_relation` rows where the memo is the source (`DeleteMemoRelation{MemoID: &delete.ID}`) and where it is the target (`DeleteMemoRelation{RelatedMemoID: &delete.ID}`) (`store/memo.go:142-147`).
2. **Attachments** — lists attachments linked to the memo (`ListAttachments`) and deletes each one via `s.DeleteAttachment` (`store/memo.go:149-157`).

Only after these are removed does it call the driver's `DeleteMemo`, which issues `DELETE FROM memo WHERE id = ?` (e.g. `store/db/sqlite/memo.go:237-239`).

Note: reactions (`ListReactions`) are looked up in the API handler for the webhook payload, but they are not deleted by `store.DeleteMemo` itself — I did not find a corresponding reaction-deletion call in the store layer's delete path, so reactions may rely on a DB foreign-key cascade rather than explicit store-layer deletion (not confirmed from the code I inspected).
