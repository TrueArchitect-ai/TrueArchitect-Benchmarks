**Engine + path**: Google's CEL (Common Expression Language, via `github.com/google/cel-go`), wrapped by a custom filter engine in `internal/filter/` (`engine.go` defines `Engine`/`Program`, `parser.go` walks the CEL AST into a dialect-agnostic `Condition` IR, `render.go` turns that IR into SQL).

**Mechanism**: `ListMemos` (`server/router/api/v1/memo_service.go:178`) takes `request.Filter`, validates it via `validateFilter`, and stores it in `store.FindMemo.Filters`; each dialect-specific store (e.g. `store/db/sqlite/memo.go:57-61`) then calls `filter.DefaultEngine()` to CEL-compile the string into a `Program`/`Condition` tree (`internal/filter/engine.go` + `parser.go`, using `google.golang.org/genproto/.../expr/v1alpha1` AST nodes) and `filter.AppendConditions(..., filter.DialectSQLite, ...)` invokes the `render.go` renderer, which walks that `Condition` tree and emits dialect-specific SQL (parameterized WHERE-clause fragments + args) for SQLite, MySQL, or Postgres depending on the `DialectName` passed in.
