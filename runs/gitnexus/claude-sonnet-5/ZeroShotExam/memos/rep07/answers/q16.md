The driver-level `DeleteMemo` only deletes the memo row itself — all cascade cleanup happens in `store.Store.DeleteMemo` (store/memo.go:140-159) before calling the driver.

q16.
Before deleting the memo row itself, `Store.DeleteMemo` (`store/memo.go:140-159`) deletes:

- **Memo relations** — twice, once where the memo is the source (`DeleteMemoRelation{MemoID: &delete.ID}`) and once where it's the related/target memo (`DeleteMemoRelation{RelatedMemoID: &delete.ID}`) (store/memo.go:142-147)
- **Attachments** linked to the memo — lists them via `ListAttachments` and deletes each individually via `DeleteAttachment` (store/memo.go:149-157)

Note: at the API layer (`server/router/api/v1/memo_service.go:567-577`), `DeleteMemo` handler also first deletes any child "comment" memos (memos related via `MemoRelationComment`) by recursively calling `Store.DeleteMemo` on each — so their relations/attachments are cleaned up the same way before the parent memo is deleted.
