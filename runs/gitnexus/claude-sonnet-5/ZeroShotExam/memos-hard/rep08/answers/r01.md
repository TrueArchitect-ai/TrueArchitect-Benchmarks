**Premise correction:** memos does not use Redis for its cache layer. There's no Redis client, connection config, or dependency (checked `go.mod`, all `.go`/`.ts` sources, and the GitNexus index — zero hits).

**Actual mechanism:** Caching is done via a custom in-process, thread-safe in-memory cache implemented in `store/cache/cache.go`. `Store` (defined in `store/store.go:13-30`) holds three instances of it — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`) — all created in `store.New()` (`store/store.go:38-60`) from one shared `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So **user entries (`userCache`) get the `DefaultTTL` of 10 minutes**, with a background cleanup sweep every 5 minutes and a 1000-item cap (LRU-style eviction beyond that). The cache also supports a per-entry override via `SetWithTTL` (`store/cache/cache.go:97-98`), but `userCache`'s callers use the plain `Set` path, so they inherit the 10-minute default.
