Memo-visibility access control is re-implemented independently in several places rather than funneled through one gate:

enforcement site — server/router/api/v1/memo_service.go (`checkMemoReadAccess`, used by `GetMemo`; plus separate inline `VisibilityList`/filter-string scoping in `ListMemos`)
enforcement site — server/router/api/v1/memo_service_comments.go (inline visibility check on the parent memo in `CreateMemoComment`, line ~41, independent of `checkMemoReadAccess`)
enforcement site — server/router/api/v1/attachment_service.go (`checkAttachmentAccess`, gates `GetAttachment`/raw attachment download by the linked memo's visibility)
enforcement site — server/router/api/v1/memo_attachment_service.go (inline visibility check in `ListMemoAttachments`)
enforcement site — server/router/api/v1/reaction_service.go (inline visibility checks in `ListMemoReactions` and `UpsertMemoReaction`)
enforcement site — server/router/api/v1/sse_hub.go (`SSEClient.canReceive`, filters real-time broadcast events by a memo's visibility/creator)
enforcement site — server/router/api/v1/user_service_notifications.go (`canViewerAccessMemo`, gates whether a memo's content is included in a user notification payload)
enforcement site — server/router/api/v1/user_service_stats.go (inline `VisibilityList` scoping in `ListAllUserStats` and `GetUserMemosStats`)
enforcement site — server/router/rss/rss.go (`GetExploreRSS`/`GetUserRSS` hard-restrict feeds to `store.Public`)
enforcement site — server/router/frontend/frontend.go (`getSitemapXML` hard-restricts sitemap entries to `store.Public`)
enforcement site — server/router/fileserver/fileserver.go (`checkAttachmentPermission`, gates raw blob file serving by memo visibility, with an added share-token bypass path)
