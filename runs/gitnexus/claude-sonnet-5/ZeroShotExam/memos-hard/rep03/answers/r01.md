**Premise correction:** there is no Redis in this codebase — a repo-wide search for `redis` turns up nothing, and no dependency/config references it. The "cache layer" is an in-process (non-distributed) Go cache, not an external Redis connection.

**Actual mechanism:** it's implemented in `store/cache/cache.go` as a thread-safe in-memory cache (`sync.Map` + TTL + background cleanup goroutine), not a network service — so there's no "connection" to configure at all.

- The `Store` struct (`store/store.go:26-29`) holds three of these in-process caches: `instanceSettingCache`, `userCache`, `userSettingCache`.
- They're constructed in `store.New()` (`store/store.go:38-46`) with a shared `cache.Config`:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
- So the TTL for user entries (`userCache`) is **10 minutes**, applied via the default `Config.DefaultTTL` when `Set()` is called (e.g. `store/user.go:98,122,132,143,167`) — no per-call TTL override is used for user entries, though the cache type also exposes `SetWithTTL` for custom durations.
