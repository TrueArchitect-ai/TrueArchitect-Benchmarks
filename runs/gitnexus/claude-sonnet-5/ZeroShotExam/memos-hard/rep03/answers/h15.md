Memo visibility (PUBLIC/PROTECTED/PRIVATE) is checked independently in each of these places — none of them delegate to a single shared authorization function, so each is a distinct enforcement site:

- gRPC memo read gate (`checkMemoReadAccess`, used by `GetMemo` and comment lookups) — server/router/api/v1/memo_service.go
- gRPC `ListMemos` / stats listing visibility scoping (VisibilityList / CEL filter) — server/router/api/v1/memo_service.go, server/router/api/v1/user_service_stats.go
- gRPC comment creation visibility check (`CreateMemoComment`) — server/router/api/v1/memo_service_comments.go
- gRPC reaction service checks (`ListMemoReactions`, `UpsertMemoReaction`) — server/router/api/v1/reaction_service.go
- gRPC attachment access check (`checkAttachmentAccess`) — server/router/api/v1/attachment_service.go
- gRPC memo-attachment listing check (`ListMemoAttachments`) — server/router/api/v1/memo_attachment_service.go
- Memo-share bypass path (`GetMemoByShare`, authorizes via share token instead of visibility) — server/router/api/v1/memo_share_service.go
- HTTP file-serving permission check (`checkAttachmentPermission`) — server/router/fileserver/fileserver.go
- SSE live-update broadcast filter (`canReceive`) — server/router/api/v1/sse_hub.go
- Notification/email content-access guard (`canViewerAccessMemo`, duplicated) — server/router/api/v1/user_service_notifications.go and server/notification/email.go
- Mention-notification visibility gating (`canUserAccessMentionContext`, `shouldSkipMentionInbox`) — server/router/api/v1/memo_mention_helpers.go
- RSS feed hard filter (Public-only) — server/router/rss/rss.go
- Frontend sitemap hard filter (Public-only) — server/router/frontend/frontend.go
- Store-layer SQL `WHERE visibility IN (...)` construction (per DB driver) — store/db/sqlite/memo.go, store/db/mysql/memo.go, store/db/postgres/memo.go

The first two (memo_service.go, user_service_stats.go) plus the fileserver check are the clearest "at least three" distinct surfaces (gRPC API, listing/stats, and raw HTTP file serving), but visibility is actually re-implemented across at least a dozen call sites rather than centralized.
