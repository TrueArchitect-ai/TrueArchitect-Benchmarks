Premise correction: this codebase (the "memos" note-taking app) doesn't use either NATS or RabbitMQ for webhook delivery — a repo-wide search for `nats`/`rabbitmq`/`amqp` turns up nothing, and neither appears in `go.mod`.

Actual mechanism: webhook delivery is an in-process Go channel, not an external message broker. `internal/webhook/webhook.go:39` declares `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, a buffered channel of capacity 128. Four goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post()` (`internal/webhook/webhook.go:119`) to actually deliver each webhook via `net/http`. Producers enqueue work with `PostAsync()` (`internal/webhook/webhook.go:183-196`), which does a non-blocking `select` send and drops (with a warning log) if the channel is full — there's no persistence or redelivery, so this is a best-effort in-memory worker pool, not a durable broker-backed queue.
