**h11.**

Persistent entity types are defined in the `store` package (memos' data layer): `store.User`, `store.Memo`, `store.Attachment`, `store.Reaction`, `store.Inbox`, `store.MemoShare`, `store.MemoRelation`, `store.IdentityProvider`, `store.InstanceSetting`, `store.UserSetting`, `store.UserIdentity` (defined in `store/*.go`, e.g. `store/user.go`, `store/memo.go`, `store/attachment.go`, etc.). I counted, for each type, how many distinct Go packages outside `store/**` (i.e. `server/**`, `internal/**`, `cmd/**`) reference it via `store.<Type>`.

Results (packages outside the data layer referencing the type):

- `store.User` → 7 packages: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- `store.Memo` → 6 packages: `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`
- `store.Attachment` → 4 packages
- `store.MemoRelation` / `store.MemoShare` → 3 packages each
- Others (`Inbox`, `Reaction`, `IdentityProvider`, `InstanceSetting`, `UserSetting`, `UserIdentity`) → 1–3 packages

**Answer: 1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages)**

`User` edges out `Memo` because it's also consumed directly in `server/auth` (authentication/session context), a package that doesn't need the `Memo` entity at all.
