Based on the persistent entity types (Go structs) defined in the `store` package (memos' data layer — `store/*.go`: `User`, `Memo`, `Attachment`, `Inbox`, `Reaction`, `MemoRelation`, `MemoShare`, `UserIdentity`, `UserSetting`, `IdentityProvider`, `InstanceSetting`), I searched for `store.<Type>` usages across the repo and grouped by importing package, excluding the `store` package's own subpackages (`store/db/*`, `store/test`).

**1st: `store.User`** — referenced from ~7 outside packages: `server/auth`, `server/notification`, `server/router/api/v1` (+ its `test` subpackage), `server/router/fileserver`, `server/router/frontend`, `server/router/rss`.

**2nd: `store.Memo`** — referenced from ~6 outside packages: `server/notification`, `server/router/api/v1` (+ `test`), `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`.

For comparison, the next widest were `store.Attachment` (~4 packages) and `store.Inbox`/`store.MemoRelation`/`store.MemoShare` (~3 packages each).

`User` edges out `Memo` mainly because of `server/auth` (session/auth middleware) and `server/router/fileserver`, both of which need user identity/permission checks but don't otherwise touch memo data directly.
