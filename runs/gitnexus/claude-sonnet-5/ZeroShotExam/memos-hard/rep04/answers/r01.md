**Premise correction:** There is no Redis connection in this codebase — memos does not use Redis (or any external cache service) at all. No Redis client, config, or connection string exists anywhere in the repo.

**Actual mechanism:** The cache layer is an in-process, thread-safe in-memory cache implemented in `store/cache/cache.go` (backed by `sync.Map` with atomic item counting and a background cleanup goroutine). It's wired up in `store/store.go:38-58`, where `Store.New()` creates three separate cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`) — all using the same `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So for user entries (`userCache`), the TTL is **10 minutes** by default (`DefaultTTL`), with a background sweep every 5 minutes (`CleanupInterval`) evicting expired entries, and a 1000-item cap that triggers eviction of the oldest 20% when exceeded (`store/cache/cache.go:253-313`). Individual entries can also be set with a custom TTL via `SetWithTTL` (`store/cache/cache.go:98-120`) instead of the 10-minute default.
