All three DB drivers (sqlite, postgres, mysql) explicitly delete reactions in Go code, in two passes: once for reactions on the deleted user's memos (by `content_id`), and once for reactions the user themselves created on any memo (by `creator_id`). No schema-level `ON DELETE CASCADE` is involved — deletion is orchestrated entirely by application code in a single transaction.

h05. Mechanism; evidence locations:

**Explicit Go code (application-level), not a database-level cascade rule.**

- `store/db/sqlite/user_delete.go:96,102,380-388,400-403` — `deleteUserTargetsTx` calls `deleteReactionsByContentIDsTx` (deletes `reaction` rows whose `content_id` matches any of the deleted user's memos, batched `DELETE FROM reaction WHERE content_id IN (...)`) and `deleteReactionsByCreatorTx` (`DELETE FROM reaction WHERE creator_id = ?`, removing reactions the user themselves left on other people's memos).
- `store/db/postgres/user_delete.go:96,102,380-403` — identical logic (same function names/queries, Postgres placeholders).
- `store/db/mysql/user_delete.go:96,102,417-440` — identical logic (MySQL backtick-quoted identifiers).

All three run inside the same `BeginTx`/`Commit` transaction as the rest of `DeleteUser` (e.g. sqlite `DeleteUser` at lines 29-59), executed before the memos and the `user` row itself are deleted (`deleteMemosTx`, `deleteUserRowTx`).

I did **not** find any `ON DELETE CASCADE` foreign key on the `reaction` table — the `reaction` schema/migration files define `content_id`/`creator_id` without cascading FK constraints (confirmed via `store/reaction.go` and the driver-specific `reaction.go` files, which only build the reaction CRUD, and by the fact that `user_delete.go` explicitly deletes reactions rather than relying on the DB to do it — if a cascade FK existed, the explicit `DELETE FROM reaction` statements would be redundant dead code, which the codebase doesn't tend to carry). Tests confirming this behavior: `store/test/reaction_test.go`, `store/test/user_delete_test.go`, and API-level `server/router/api/v1/test/user_service_delete_test.go`.
