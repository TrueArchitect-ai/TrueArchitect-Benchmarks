**Premise correction:** Neither. The memos codebase doesn't use NATS or RabbitMQ (repo-wide search for `nats`/`rabbitmq`/`amqp` returns zero hits) — there's no message broker in this project at all.

**Actual mechanism:** Webhook delivery is handled in-process via a buffered Go channel that acts as an in-memory work queue, consumed by a small fixed pool of goroutines:

- Queue declaration: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39`
- Workers: 4 goroutines spawned in `init()` at `internal/webhook/webhook.go:42-54`, each ranging over `asyncPostQueue` and calling `Post(payload)` (defined at `internal/webhook/webhook.go:120`) to perform the actual HTTP delivery via the shared `safeClient` (`internal/webhook/webhook.go:32-37`).
- If the channel is full, dispatch is dropped with a warning (`internal/webhook/webhook.go:192`), rather than backing off to an external broker.

So delivery is bounded, asynchronous, and entirely local to the Go process — there's no persistence, no cross-process consumer, and no broker to declare a queue in.
