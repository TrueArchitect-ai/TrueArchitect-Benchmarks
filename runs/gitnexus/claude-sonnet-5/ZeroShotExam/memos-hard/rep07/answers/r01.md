**Premise correction:** There is no Redis in this codebase — a full-text search for "redis" across the repo (memos, a Go app) returns zero matches, and there is no Redis client, connection URL, or config anywhere.

**Actual mechanism:** The cache layer is an in-process, in-memory LRU/TTL cache implemented at `store/cache/cache.go` (type `cache.Cache`, `cache.Config`), not a networked store. It's wired up in `store/store.go`:

- `store/store.go:24-29` — `Store` holds a `cacheConfig cache.Config` plus three in-memory caches: `instanceSettingCache`, `userCache`, `userSettingCache`.
- `store/store.go:38-53` (`store.New`) — constructs a single shared `cache.Config` and passes it to `cache.New(...)` for each cache instance.

The TTL applied to user entries (via `userCache`) is the default TTL set at construction:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So **user cache entries expire after 10 minutes** (`store/store.go:41`), with a background cleanup sweep every 5 minutes and a 1000-item cap — all defined in `store/cache/cache.go` (`Config.DefaultTTL`, `DefaultConfig()` at line ~56 shows the same 10m/5m defaults) and instantiated per-cache in `store/store.go`.
