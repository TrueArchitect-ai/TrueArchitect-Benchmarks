h11.

Based on grepping Go source for usages of each `store.<Type>` persistent entity (defined in `/store/*.go`: `Memo`, `User`, `Attachment`, `Reaction`, `Inbox`, `MemoRelation`, `MemoShare`, `UserSetting`, `UserIdentity`, `InstanceSetting`, `IdentityProvider`), and counting distinct packages that reference each type **outside the data layer** (excluding `store/` itself and its DB-driver subpackages `store/db/{mysql,postgres,sqlite}`, which implement the persistence layer rather than consume it):

- **`store.User`** — referenced from **~6 packages**: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/rss`
- **`store.Memo`** — referenced from **~4 packages**: `server/notification`, `server/router/api/v1`, `server/router/rss`, `server/runner/memopayload`

(Next closest is `store.Attachment` at ~3 packages: `server/router/api/v1`, `server/router/fileserver`, `server/router/rss`.)

**1st: User (~6 packages); 2nd: Memo (~4 packages)**

`User` is the most widely referenced entity because it's needed almost everywhere for auth/identity context (`server/auth`), notifications, RSS rendering, file serving, and the main API layer, whereas `Memo` is mostly consumed within the core API service, notifications, RSS, and the memo-payload runner.
