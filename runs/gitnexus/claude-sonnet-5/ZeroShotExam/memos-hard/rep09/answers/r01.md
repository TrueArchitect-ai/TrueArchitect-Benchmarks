**Premise correction:** There is no Redis connection in this codebase — memos does not use Redis (or any external cache backend) for its cache layer. There is no `redis` import, client, connection string, or config anywhere in the repo.

**Actual mechanism:** The cache layer is an in-process, in-memory cache implemented in `store/cache/cache.go` (a `sync.Map`-backed `Cache` struct with a background cleanup goroutine). It's instantiated per-`Store` in `store/store.go:37-77`:

- `Store.userCache` (`store/store.go:27`) holds cached `User` objects.
- It's created via `cache.New(cacheConfig)` at `store/store.go:52`, where `cacheConfig` (`store/store.go:39-45`) sets:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`

So user cache entries expire after **10 minutes** (the same `DefaultTTL` used by all three in-process caches — `instanceSettingCache`, `userCache`, `userSettingCache`), enforced lazily on `Get` (`store/cache/cache.go` `Get` method checks `time.Now().After(itm.expiration)`) and via a periodic cleanup loop, not by any Redis expiry mechanism.
