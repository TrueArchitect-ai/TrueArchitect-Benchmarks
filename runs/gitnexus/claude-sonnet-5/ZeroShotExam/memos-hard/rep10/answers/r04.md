**Premise correction:** Neither. There is no NATS or RabbitMQ broker in this codebase (memos, the `usememos/memos` note-taking app). Webhook delivery is not backed by an external message broker at all.

**Actual mechanism:** Webhook dispatch uses an in-process, in-memory Go channel as the "queue" — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared in `internal/webhook/webhook.go:39`. A fixed pool of 4 goroutines, spawned in the package `init()` (`internal/webhook/webhook.go:42-55`), range over this channel and call `Post()` (`internal/webhook/webhook.go:120`) to deliver each webhook via HTTP. Enqueuing is done by `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send and drops (with a warning log) if the buffer of 128 is full — there's no persistence, retry-on-restart, or external broker involved.
