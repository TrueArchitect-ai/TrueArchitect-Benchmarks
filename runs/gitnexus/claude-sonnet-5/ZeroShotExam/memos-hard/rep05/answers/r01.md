**Premise correction:** There is no Redis connection in this codebase — Redis isn't a dependency anywhere (no mention in `go.mod`/`go.sum`, no import, no config), so nothing "configures a Redis connection" for caching.

**Actual mechanism:** Caching is done with a custom in-process, in-memory TTL cache implemented in `store/cache/cache.go` (a `sync.Map`-backed store with a background cleanup goroutine — see `cache.New`/`cache.DefaultConfig`, `store/cache/cache.go:57-64`). The `Store` struct wires up an instance of this cache specifically for users:

- `store/store.go:28` — `userCache *cache.Cache // cache for users` field on `Store`
- `store/store.go:41,52` — constructed via `cache.New(cacheConfig)` using `DefaultConfig()`, whose `DefaultTTL` is `10 * time.Minute` (`store/cache/cache.go:59`)
- `store/user.go:88-167` — `userCacheKey(userID)` and the `Set`/`Get` calls on `s.userCache` when creating/updating/looking up users, all using the default (no `SetWithTTL` override), so user cache entries expire after **10 minutes**.

So: the "Redis connection" doesn't exist — it's an in-memory `sync.Map`-based cache local to each server process, and user entries get a 10-minute TTL from `cache.DefaultConfig()`.
