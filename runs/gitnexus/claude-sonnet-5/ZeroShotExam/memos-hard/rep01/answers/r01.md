r01. Premise correction: there is no Redis connection in this codebase — this project (memos) has no Redis dependency at all (confirmed via a repo-wide grep for "redis", which returns zero hits, and there's no Redis client, config field, or connection string anywhere).

Actual mechanism: caching is done with a custom in-process, thread-safe memory cache (`sync.Map`-backed) defined in `store/cache/cache.go`. The `Store` struct wires up three separate instances of it — `instanceSettingCache`, `userCache`, and `userSettingCache` — in `store/store.go:38-58`, all built with the same `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000}`.

So user entries cached via `userCache` (populated/read in `store/user.go:88-167`, keyed by `userCacheKey(userID)`, and invalidated on delete in `store/user_delete.go:39-40`) get a **10-minute TTL**, with a background cleanup sweep every 5 minutes and a 1000-item cap per cache — all in-memory, no Redis or external cache server involved.
