**Premise correction:** There is no Redis anywhere in this codebase (confirmed via repo-wide grep and the GitNexus index — no `redis` references at all, and no external cache service is wired in). This is `usememos/memos`, whose "cache layer" is an in-process, in-memory Go cache, not Redis.

**Actual mechanism:** The cache is implemented in `store/cache/cache.go` — a custom in-memory `Cache` type (map-backed, with a mutex, atomic counters, background cleanup goroutine, and an LRU-style max-item eviction), not backed by any external store/connection.

It's configured and instantiated in `store/store.go:24,40-53`:
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
...
userCache: cache.New(cacheConfig),
```
The `Store` struct holds three separate in-memory caches — `instanceSettingCache`, `userCache`, `userSettingCache` — all built from this one `cacheConfig`.

**TTL for user entries:** `userCache` uses the shared `DefaultTTL` of **10 minutes** (`store/store.go:41`). Individual entries can override this via `SetWithTTL` (per the `cache.Interface` in `store/cache/cache.go`), but nothing in `store/store.go` does so for user entries — they all get the default 10-minute TTL, with expired/excess entries reaped by the 5-minute cleanup interval or the 1000-item cap.
