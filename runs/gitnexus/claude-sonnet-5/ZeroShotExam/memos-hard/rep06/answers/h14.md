It's invoked through `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`, which writes the results onto `memo.Payload.Tags` and `memo.Payload.Property` (`storepb.MemoPayload`).

**Triggers (recomputation):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` calls `memopayload.RebuildMemoPayload` on every new memo before it's persisted.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only when the update mask includes the `content` field (i.e., the memo body actually changed); other field updates (visibility, pinned, state, etc.) don't retrigger it.
- `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) — a batch job that pages through all memos (100 at a time) and calls `RebuildMemoPayload` on each, used for bulk backfill/rebuild. Note: in the current codebase this runner isn't wired into `server/server.go`'s startup (only the `s3presign` runner is registered there), so it exists as a standalone rebuild utility rather than an active background trigger.

**Extracted properties** (goldmark AST walk over the memo's markdown content, `internal/markdown/markdown.go:356-421`):
- `Tags` — all `#tag` nodes (deduplicated, case preserved) — `ExtractedData.Tags` / `MemoPayload.Tags`.
- `Mentions` — all `@mention` nodes, lower-cased and deduplicated — `ExtractedData.Mentions` (used separately, e.g. by `memo_mention_helpers.go`, not persisted onto `Payload`).
- `Property` (`storepb.MemoPayload_Property`), derived from AST node kinds:
  - `Title` — text of the first block-level child if it's an H1 heading.
  - `HasLink` — a `Link` node is present.
  - `HasCode` — a code block, fenced code block, or code span is present.
  - `HasTaskList` — a task checkbox node is present.
  - `HasIncompleteTasks` — any task checkbox is unchecked.
