**Premise correction:** Neither. There is no NATS or RabbitMQ (or any external message broker) in this codebase — a repo-wide grep for `nats`/`rabbitmq`/`amqp` in Go source and config turns up nothing relevant (the one JSON hit is an unrelated locale-string coincidence in `web/src/locales/ca.json`).

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel as a bounded work queue, not a broker. In `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post()` for each payload:

```go
for range 4 {
    go func() {
        for payload := range asyncPostQueue {
            if err := Post(payload); err != nil { ... }
        }
    }()
}
```

`PostAsync()` (`internal/webhook/webhook.go:184-196`) is the producer side — it does a non-blocking `select` send into `asyncPostQueue`, dropping (and logging a warning for) the request if the channel is full. So "the queue" is declared as a buffered Go channel at `internal/webhook/webhook.go:39`, consumed by the goroutine pool started in that same file's `init()` — entirely intra-process, with no external broker involved.
