**Premise correction:** There is no Redis connection in this codebase's cache layer. `memos` doesn't use Redis (or any external cache service) anywhere — the grep for "redis" across the repo returns nothing.

**Actual mechanism:** The cache layer is a custom in-process, in-memory cache implemented in `store/cache/cache.go` (a `sync.Map`-backed struct with TTL expiration and a background cleanup goroutine — no network connection at all).

The `Store` struct in `store/store.go:13-30` instantiates three separate in-memory caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — each built with the same shared config defined at `store/store.go:40-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So the `userCache` (which holds user entries, `store/store.go:28`) uses a **10-minute default TTL**, with a background sweep every 5 minutes (`store/cache/cache.go:200-215`) evicting expired entries, and a max of 1000 items per cache before an LRU-ish eviction of the oldest 20% kicks in (`store/cache/cache.go:253-313`). Entries can also be set with a custom TTL via `SetWithTTL` (`store/cache/cache.go:97-120`), but the default path used for user entries is the 10-minute TTL above.
