q25. Engine: **CEL (Common Expression Language)** via `google/cel-go`, implemented in `internal/filter/engine.go` (`Engine.Compile` compiles the filter string into a CEL AST/`Program`).

Mechanism: The CEL AST is converted into a dialect-agnostic `Condition` tree (per a `Schema`, e.g. `internal/filter/schema.go`), and `internal/filter/render.go` renders that tree into SQL `WHERE` fragments + args by switching on `DialectName` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`) at each rendering point, so the same parsed filter produces dialect-specific SQL (e.g. different JSON-extraction, timestamp, and string-concat expressions per dialect) which store layer callers append via `internal/filter/helpers.go`'s `AppendConditions`.
