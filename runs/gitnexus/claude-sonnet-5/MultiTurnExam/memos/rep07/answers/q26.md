q26. `memo`, `memo_relation`, `attachment`, `memo_share`

- `memo` — the row itself is deleted (`store/db/postgres/memo.go:244-254`).
- `memo_relation` — explicitly cleared for both `memo_id` and `related_memo_id` in `store/memo.go:142-147` (`Store.DeleteMemo`).
- `attachment` — attachments linked via `memo_id` are explicitly listed and deleted one by one (`store/memo.go:149-157`, calling `Store.DeleteAttachment`, which also removes the underlying storage blob).
- `memo_share` — declared with `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/postgres/LATEST.sql:108`), so it cascades automatically at the DB level.

Note: `reaction.content_id` is a plain `TEXT` column with no foreign key, so reactions on a deleted memo are not cascaded by the schema, and `Store.DeleteMemo` doesn't clean them up explicitly either.
