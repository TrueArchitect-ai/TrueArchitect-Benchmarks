**Engine:** CEL (Common Expression Language, `google/cel-go`), wrapped by an in-house engine at `internal/filter/` (schema/env in `internal/filter/schema.go`, parsing in `internal/filter/parser.go`/`engine.go`, SQL rendering in `internal/filter/render.go`).

**Mechanism:** The filter string from the RPC is parsed and type-checked into a CEL AST via `Engine.CompileToStatement` (`internal/filter/engine.go`), then `internal/filter/render.go` walks that AST and emits a parameterized SQL `WHERE` fragment, switching on a `DialectName` (`DialectSQLite`/`DialectPostgres`/`DialectMySQL`) at each rendering branch to produce dialect-specific SQL (e.g. different string/date functions per database).
