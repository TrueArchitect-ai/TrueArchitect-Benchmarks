**Delivery function** — `Post` in `internal/webhook/webhook.go:120-180` (invoked synchronously or queued via `PostAsync`, `internal/webhook/webhook.go:184-196`) sends the outbound POST using the package-level `safeClient` (`internal/webhook/webhook.go:32-37`).

**Protection mechanism** — SSRF protection happens at two layers, both in the `internal/webhook` package:
- Dial-time enforcement: `safeClient`'s `Transport.DialContext` is set to `safeDialContext` (`internal/webhook/webhook.go:59-77`), which resolves the hostname and rejects any resulting IP that falls in a reserved/private range — this also defeats DNS-rebinding, since the check runs against the actual IP used to dial, not just the IP resolved at validation time.
- Pre-flight validation: `ValidateURL` in `internal/webhook/validate.go:62-83` (used when a webhook URL is registered/updated) checks scheme and resolves the hostname against `reservedNetworks`/`isReservedIP` (`internal/webhook/validate.go:14-54`), covering loopback, RFC-1918 private ranges, link-local/cloud IMDS (169.254.169.254), and their IPv6 equivalents — bypassable per-deployment via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`).
