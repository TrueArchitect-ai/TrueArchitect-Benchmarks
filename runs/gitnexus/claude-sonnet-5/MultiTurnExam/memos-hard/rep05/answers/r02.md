**Premise correction:** There is no per-user API rate-limiting middleware in this codebase. A repo-wide search for rate-limiting (`golang.org/x/time/rate`, Echo's rate-limiter middleware, or any hand-rolled "rate limit"/"throttle" logic) turns up nothing implemented — the only hit is a doc comment in `internal/email/doc.go:86` that lists "Rate limit email sending to prevent abuse" as an *aspirational* design note, not actual code.

**What actually exists instead:** The server uses bounded *concurrency* semaphores in a few places (not per-user request-rate limits) — e.g. `thumbnailSemaphore := semaphore.NewWeighted(3)` and `imageProcessingSemaphore := semaphore.NewWeighted(2)` in `server/router/api/v1/v1.go:59-60`, and a separate thumbnail semaphore in `server/router/fileserver/fileserver.go:116` — these cap concurrent thumbnail/image-processing work server-wide, not per-user request counts, and aren't "rate-limiting middleware" registered on the request path.
