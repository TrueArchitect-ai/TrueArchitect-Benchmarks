Memo visibility (`store.Private`/`Protected`/`Public`) is checked independently in each of these server surfaces:

- **gRPC `GetMemo`** (single-memo read) — `server/router/api/v1/memo_service.go:63`
- **gRPC memo attachment access** (`memo_attachment_service.go` / `attachment_service.go`) — `server/router/api/v1/memo_attachment_service.go:222`, `server/router/api/v1/attachment_service.go:451`
- **gRPC reaction service** (viewing/adding reactions on a memo) — `server/router/api/v1/reaction_service.go:38,83`
- **gRPC memo comments service** — `server/router/api/v1/memo_service_comments.go:41`
- **Mention-notification dispatch helpers** — `server/router/api/v1/memo_mention_helpers.go:62,67,84`
- **In-app inbox/notification delivery** (`canViewerAccessMemo`) — `server/router/api/v1/user_service_notifications.go:302-385`
- **Email notification delivery** (separate `canViewerAccessMemo`) — `server/notification/email.go:155,187,306-313`
- **File server** (binary attachment download, `checkAttachmentPermission`) — `server/router/fileserver/fileserver.go:649-703`
- **RSS feed generation** (restricted to `store.Public` only via `VisibilityList`) — `server/router/rss/rss.go:90,141`
- **SSE live-update hub** (`SSEClient.canReceive`, per-connection event filtering) — `server/router/api/v1/sse_hub.go:134-144`

Note that the two `canViewerAccessMemo` implementations (notifications vs. email) are separately declared, duplicated functions in different packages, not a shared helper — each is its own independent enforcement site.
