**Premise correction:** Neither — there is no external message broker (NATS, RabbitMQ, or any other) involved in webhook delivery. A repo-wide check confirms no NATS/AMQP/RabbitMQ client library is imported anywhere in the codebase.

**Actual mechanism:** Webhook dispatch uses a simple in-process Go channel as a bounded queue: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared in `internal/webhook/webhook.go:39`. Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post` for each payload. `PostAsync` (`internal/webhook/webhook.go:184-196`) enqueues onto it with a non-blocking `select`/`default`, dropping (and logging) the dispatch if the channel is full — there's no persistence, no broker, no cross-process queue; it's entirely in-memory and scoped to a single server process.
