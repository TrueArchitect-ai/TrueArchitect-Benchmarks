**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search finds zero references to Redis (no client library, no connection string, no config flag). The "cache layer" isn't backed by an external store at all.

**Actual mechanism:** User entries (and instance settings, user settings) are cached in an in-process, in-memory cache implemented in `store/cache/cache.go` (a custom `Interface`/`Cache` type with expiration + LRU-style eviction, no network connection of any kind). It's instantiated in `store.New` at `store/store.go:38-58`, which creates three separate `*cache.Cache` instances (`instanceSettingCache`, `userCache`, `userSettingCache`) all sharing one `cache.Config`.

**TTL for user entries:** `10 * time.Minute` — the `DefaultTTL` set in the `cache.Config` literal at `store/store.go:41`, applied to `userCache` via `cache.New(cacheConfig)` at `store/store.go:52`. (Cleanup of expired entries runs every 5 minutes, `store/store.go:42`, and the cache is capped at 1000 items, `store/store.go:43`.)
