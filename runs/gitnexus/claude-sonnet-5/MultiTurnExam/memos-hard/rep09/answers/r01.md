**Premise correction** — There is no Redis anywhere in this codebase (a repo-wide search for `redis`/`Redis` in Go source returns zero hits). The cache layer is not backed by an external cache server at all.

**Actual mechanism** — The cache layer is an in-process, thread-safe in-memory cache implemented in `store/cache/cache.go` (`type Cache struct` at line 66). Three separate `*cache.Cache` instances are created for the `Store` — `instanceSettingCache`, `userCache`, and `userSettingCache` — all constructed with the same `cache.Config` in `store/store.go:38-53` (`New` function).

**TTL for user entries** — `userCache` uses the default TTL from that shared config: `DefaultTTL: 10 * time.Minute` (`store/store.go:41`), with a background cleanup sweep every `CleanupInterval: 5 * time.Minute` (`store/store.go:42`) and a `MaxItems: 1000` cap. Individual `Set` calls can override this with `SetWithTTL` (`store/cache/cache.go:97`), but `Store`'s user cache writes (e.g. in `store/user.go`) use the plain `Set`, so they get the 10-minute default.
