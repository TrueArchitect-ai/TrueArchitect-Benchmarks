**Premise correction** — Neither. There is no NATS or RabbitMQ (or any external message broker) anywhere in this codebase — a repo-wide search for `nats`, `NATS`, `rabbitmq`, `amqp` in `go.mod`/source turns up nothing.

**Actual mechanism** — Webhook delivery uses an in-process, in-memory Go channel as its queue, defined in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

It's a buffered channel (capacity 128), not a declared queue on any broker. Four long-lived worker goroutines are spawned in that same file's `init()` (`internal/webhook/webhook.go:42-55`) to drain the channel and call `Post` for each payload. `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto this channel with a non-blocking `select`/`default` — if the channel is full, the webhook dispatch is simply dropped and logged (`internal/webhook/webhook.go:189-195`), rather than being queued externally or retried via a broker.
