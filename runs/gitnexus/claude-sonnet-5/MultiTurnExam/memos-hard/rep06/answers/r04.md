**Premise correction** — Neither. This repo has no message-broker dependency at all — `go.mod` contains no NATS or RabbitMQ/AMQP client library (confirmed by grepping `go.mod` for both, zero hits).

**Actual mechanism** — Webhook delivery workers consume from an in-process, in-memory Go channel, not an external broker. `internal/webhook/webhook.go:39` declares `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (a buffered channel of capacity 128). Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post` for every payload. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send — if the channel is full, the dispatch is dropped and logged rather than blocking. All of this lives entirely within the single server process; there's no queue "declared" anywhere outside this Go channel.
