**Premise correction** — There is no Redis anywhere in this codebase. A repo-wide search (`grep -rli redis` over all `.go` files, plus `go.mod`/`go.sum`) turns up zero hits — no Redis client dependency, no Redis config, nothing.

**Actual mechanism** — The cache layer is a self-contained, in-process, in-memory cache (`store/cache/cache.go`), backed by `sync.Map` with atomic item counting — not an external store. It's constructed in `store.New` (`store/store.go:38-60`), which builds three `*cache.Cache` instances (`instanceSettingCache`, `userCache`, `userSettingCache`, lines 51-53) all sharing the same `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user entries (`userCache`) get the default **10-minute TTL**, with a background cleanup sweep every 5 minutes (`store/cache/cache.go:56-62` `DefaultConfig`, mirrored in `store/store.go:40-45`). Nothing here talks to a network service — it lives and dies with the process, and is torn down via `Store.Close` (`store/store.go:72-79`).
