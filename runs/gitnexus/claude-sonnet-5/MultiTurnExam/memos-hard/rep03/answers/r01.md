**Premise correction:** There is no Redis in this codebase — a repo-wide search for "redis" (source, go.mod/go.sum) returns nothing. The cache layer is an in-process, in-memory cache, not an external Redis connection.

**Actual mechanism:** `store/cache/cache.go` implements a thread-safe in-memory cache (`Cache`, backed by `sync.Map`, with TTL expiry and a background `cleanupLoop` goroutine — no network connection is configured because there is none). It's constructed in `store/store.go:51-53` via `cache.New(cacheConfig)`, producing three separate cache instances (`instanceSettingCache`, `userCache`, `userSettingCache`) all sharing one config.

**TTL for user entries:** `userCache`'s entries use the shared `cacheConfig.DefaultTTL`, set to **10 minutes** at `store/store.go:41` (`DefaultTTL: 10 * time.Minute`) — matching `cache.DefaultConfig()`'s own default in `store/cache/cache.go:59`.
