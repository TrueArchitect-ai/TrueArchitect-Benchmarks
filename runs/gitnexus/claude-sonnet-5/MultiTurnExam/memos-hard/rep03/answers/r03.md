**Premise correction:** There is no nightly database-cleanup job scheduled anywhere in this codebase.

The repo does contain a general-purpose cron-style scheduler package at `internal/scheduler/scheduler.go`, but it is never imported or wired up by any production code — a repo-wide search for `usememos/memos/internal/scheduler` shows it's referenced only from its own test files (`internal/scheduler/integration_test.go`, `internal/scheduler/example_test.go`). No job is registered on it in `server/` or `cmd/`.

The only actual scheduled background jobs in the server are the two `time.Ticker`-based runners in `server/runner/`: `s3presign.Runner` (12-hour interval, `server/runner/s3presign/runner.go:27`) and the unwired `memopayload.Runner`. Neither is a "database cleanup" job, and neither runs at a specific "nightly" time — they're interval-based, not clock-based. The "cleanup" hits found elsewhere in the code (`server/router/api/v1/user_service.go`, `auth_service_sso.go`, `memo_service.go`) are all inline, request-triggered cleanup logic (e.g. deleting a user's attachments during account deletion), not scheduled jobs.
