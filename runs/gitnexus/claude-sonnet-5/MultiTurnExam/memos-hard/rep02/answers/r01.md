**Premise correction:** there is no Redis in this codebase — a repo-wide search for `redis` (Go source, docs, `go.mod`) turns up nothing. The "cache layer" is an in-process, in-memory cache, not a Redis connection.

**Actual mechanism:** `store/cache/cache.go` implements a thread-safe in-memory `Cache` backed by `sync.Map` with a background TTL-eviction goroutine (`cleanupLoop`, `cache.go:200-215`) — no network connection or external config exists to "configure."

The user cache is constructed in `Store.New` at `store/store.go:47-58`, using a `cache.Config` built inline (lines 40-45) with:
- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

`userCache` is instantiated at `store/store.go:52` (`cache.New(cacheConfig)`), so **user entries get a 10-minute TTL** (`DefaultTTL`), swept by a cleanup pass every 5 minutes — all local to the process, nothing Redis-backed.
