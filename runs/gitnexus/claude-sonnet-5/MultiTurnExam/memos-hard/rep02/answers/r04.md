**Premise correction:** neither. There is no external message broker in this codebase — no NATS, no RabbitMQ (a search of `go.mod` and the `internal`/`server` trees for `nats`, `rabbitmq`, `amqp` returns nothing).

**Actual mechanism:** webhook delivery uses an in-process Go buffered channel, not a broker. `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` in `internal/webhook/webhook.go:39`. `PostAsync` (`internal/webhook/webhook.go:184-196`) enqueues payloads onto this channel (non-blocking `select`/`default`, dropping and logging a warning if the buffer of 128 is full). Four worker goroutines, spawned in the package's `init()` (`internal/webhook/webhook.go:42-55`), range over `asyncPostQueue` and call `Post` for each payload — all within the same server process, with no external queueing system involved.
