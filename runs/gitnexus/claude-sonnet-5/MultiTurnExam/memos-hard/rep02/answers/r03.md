**Premise correction:** there is no nightly database-cleanup job in this codebase, and no cron scheduler wired into the running server.

The repo does have an `internal/scheduler` package (`internal/scheduler/scheduler.go`, `internal/scheduler/job.go`) that implements a generic cron-style job scheduler — but a repo-wide search for its import (`usememos/memos/internal/scheduler`) shows it is referenced **only** from its own package's test files (`internal/scheduler/integration_test.go`, `internal/scheduler/example_test.go`). No production code (`server/`, `store/`, `cmd/`) ever imports or registers a job with it, so it isn't wired into server startup at all.

The only background jobs actually started by the server (`Server.startBackgroundRunners`, `server/server.go:153-174`) are:
- `s3presign.Runner` — runs on a fixed 12-hour ticker (`server/runner/s3presign/runner.go:27`) to re-presign S3 attachment URLs, not a database cleanup.
- `memopayload.Runner` — exists but is never constructed or started in production (confirmed dead code, per earlier analysis).

Neither is a "database-cleanup" job, and neither runs on a "nightly" (fixed clock-time) schedule — the s3presign runner is interval-based (every 12 hours from process start), not time-of-day based. There's no cron expression anywhere in this codebase specifying a nightly run time.
