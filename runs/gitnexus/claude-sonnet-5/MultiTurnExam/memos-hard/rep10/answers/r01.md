**Premise correction:** There is no Redis in this codebase — no Redis client, driver, or dependency exists anywhere (no hits in `go.mod`, no imports referencing redis). The cache layer is a pure in-process, in-memory implementation.

**Actual mechanism:** The cache is `store/cache/cache.go` (`cache.Interface` / `cache.Cache`, an in-memory map with expiration timestamps and a background cleanup goroutine — no external service involved). The user cache (`userCache`) is constructed in `store/store.go:52` via `cache.New(cacheConfig)`, using the shared `cacheConfig` defined at `store/store.go:40-45`:
- `DefaultTTL: 10 * time.Minute` — so user entries expire after **10 minutes**
- `CleanupInterval: 5 * time.Minute` (periodic sweep of expired entries)
- `MaxItems: 1000`

This same in-memory cache type also backs `instanceSettingCache` and `userSettingCache` (`store/store.go:27-29, 51, 53`), all with identical default TTL/config.
