**Delivery function:** `Post` — `internal/webhook/webhook.go:120-180` (marshals the payload, optionally HMAC-signs it, and sends it via `safeClient.Do(req)`). It's invoked synchronously or queued via `PostAsync` (webhook.go:184-196), which feeds a bounded channel drained by 4 worker goroutines started in `init()` (webhook.go:42-55) that call `Post`.

**Protection mechanism:** SSRF is blocked at the transport-dial level, not just at input validation:
- `safeDialContext` — `internal/webhook/webhook.go:59-77` — the custom `DialContext` used by the shared `safeClient` HTTP client (webhook.go:32-37). It resolves the target hostname itself and rejects any resolved IP that is reserved/private *at dial time*, which also defeats DNS-rebinding TOCTOU attacks (a check-then-connect on a stale hostname resolution can't be exploited since dial-time resolution is what's checked).
- Backed by `isReservedIP` / `reservedCIDRs` — `internal/webhook/validate.go:14-54` — blocking loopback, RFC-1918 private ranges, and link-local/cloud IMDS (`169.254.0.0/16`) addresses, plus IPv6 equivalents (unless `AllowPrivateIPs` is set for self-hosted deployments).
- There's also an upfront input-validation pass, `ValidateURL` — `internal/webhook/validate.go:62-83` — called when a webhook is created/updated, which performs the same reserved-IP check via DNS lookup before the URL is even saved. This is a defense-in-depth/early-rejection check; the authoritative protection against SSRF (including rebinding) is `safeDialContext`.
