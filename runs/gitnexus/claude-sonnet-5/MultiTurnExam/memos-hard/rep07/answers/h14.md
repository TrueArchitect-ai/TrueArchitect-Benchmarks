**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74-84`. It calls `markdownService.ExtractAll([]byte(memo.Content))` (backed by `internal/markdown/markdown.go:356-422`, a single goldmark AST walk) and stores the result into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers (call sites in production code):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, run unconditionally whenever a new memo is created (right after content-length validation, before the memo is persisted).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, run only when the update mask includes the `content` path (`server/router/api/v1/memo_service.go:436-451`) — i.e. recomputed only when the memo's content itself changes, not on visibility/pin/other field updates.

(There is also a batch/backfill path, `memopayload.Runner.RunOnce` at `server/runner/memopayload/runner.go:27-52`, which calls the same function over all memos in the store — but per earlier analysis this `Runner` type is never constructed in production code, so it isn't a live trigger today.)

**Extracted properties** (`storepb.MemoPayload_Property`, computed in the same AST walk):
- `Tags` — `#tag` occurrences (deduplicated, case-preserved)
- `Property.Title` — text of a leading H1 heading, if the first block is one
- `Property.HasLink` — presence of any Markdown link
- `Property.HasCode` — presence of code blocks/fenced code/inline code spans
- `Property.HasTaskList` — presence of task-list checkboxes
- `Property.HasIncompleteTasks` — presence of at least one unchecked task-list item

(`ExtractAll` also collects `@mention` references into `data.Mentions`, but per `RebuildMemoPayload`'s implementation only `Tags` and `Property` are written into `memo.Payload` — mentions aren't persisted there.)
