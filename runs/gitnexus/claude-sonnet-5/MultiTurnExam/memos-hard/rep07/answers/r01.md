**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search for "redis" (case-insensitive, all `.go` files) returns zero hits, and there's no Redis client dependency, config field, or connection string. The cache layer is a self-contained in-process cache, not backed by an external store.

**Actual mechanism:** The cache implementation lives in `store/cache/cache.go` — an in-memory, TTL/size-bounded cache (`cache.Cache`, with `Set`/`SetWithTTL`/`Get`/`Delete`/`Clear`/background cleanup via `CleanupInterval`, no network client involved). The user cache specifically is `Store.userCache` — constructed in `store/store.go:52` (`cache.New(cacheConfig)`) as one of three caches (`instanceSettingCache`, `userCache`, `userSettingCache`) built with the same shared config, `cacheConfig`, defined at `store/store.go:40-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user entries get a **10-minute default TTL**, with a background cleanup sweep every 5 minutes and a 1000-item cap, all managed in-process (populated/read by `Store.GetUser`/`Store.ListUsers` in `store/user.go`).
