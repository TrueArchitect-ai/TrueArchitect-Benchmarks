**Premise correction:** Neither — there is no message broker involved. A search for `nats`/`rabbitmq`/`amqp` across the repo returns no matches, and there's no broker client dependency in `go.mod`.

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel as its queue: `asyncPostQueue := make(chan *WebhookRequestPayload, 128)` in `internal/webhook/webhook.go:33` (buffered, capacity 128). `webhook.PostAsync` (`internal/webhook/webhook.go:186-198`) enqueues onto this channel (non-blocking — it drops and logs a warning if the buffer is full, `webhook.go:194-197`). A fixed pool of 4 worker goroutines, started in the package `init()` (`internal/webhook/webhook.go:38-49`), range over `asyncPostQueue` and call `Post` for each dequeued payload. This is entirely local to the running server process — nothing is persisted or shared across instances.
