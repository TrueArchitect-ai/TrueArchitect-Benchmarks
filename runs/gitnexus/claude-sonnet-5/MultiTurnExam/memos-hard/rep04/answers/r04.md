**Premise correction:** Neither. There is no message broker in this codebase — no NATS or RabbitMQ dependency exists anywhere (`grep` for "nats"/"rabbitmq"/"amqp" across the repo returns nothing).

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel as the queue: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared in `internal/webhook/webhook.go:39`. Four worker goroutines are spun up in that package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post` to deliver the HTTP request. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send and drops (with a warning log) if the buffer of 128 is full. This is entirely local to the server process — it does not persist across restarts and has no external broker involved.
