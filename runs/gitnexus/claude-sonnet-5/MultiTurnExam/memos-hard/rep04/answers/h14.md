**Computation site:** `RebuildMemoPayload` — `server/runner/memopayload/runner.go:74-88`. It calls `markdownService.ExtractAll([]byte(memo.Content))` (the goldmark-backed `internal/markdown` service) and writes the result into `memo.Payload.Tags` / `memo.Payload.Property`.

**Triggers (recomputation call sites):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, runs on every new memo.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only when the update mask includes the `content` path (`server/router/api/v1/memo_service.go:435-449`); other field-only updates (visibility, pinned, etc.) don't recompute it.

**Extracted properties** (per `Service.ExtractAll`, `internal/markdown/markdown.go:356-422`, itself built from `ExtractTags`/`ExtractProperties` logic):
- `Tags` — all `#tag` occurrences found in the content (deduplicated, case-preserving), skipping tags inside links/images.
- `Property.Title` — text of a leading H1 heading, if the first block in the document is one.
- `Property.HasLink`, `Property.HasCode`, `Property.HasTaskList`, `Property.HasIncompleteTasks` — booleans derived from presence of links, code blocks/spans, and task-list checkboxes (including whether any are unchecked).

These derived fields (`memo.Payload.Tags`/`Property`) power memo lists/previews and filtering, distinct from user-set fields like visibility or pinned state.
