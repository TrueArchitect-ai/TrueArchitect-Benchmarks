- Deletion logic in `DeleteUser`, present identically in each driver:
  - `store/db/sqlite/user_delete.go:96` and `:102` (call sites in `deleteUserTargetsTx`), with implementations `deleteReactionsByContentIDsTx` (line 380/`store/db/sqlite/user_delete.go:380`... actually sqlite file lines 380-388) deleting reactions on the user's own memos (`DELETE FROM reaction WHERE content_id IN (...)`, matched via `memo.uid` → `content_id`), and `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:400-403`) deleting reactions the user made on others' memos (`DELETE FROM reaction WHERE creator_id = ?`).
  - Same two functions duplicated in `store/db/mysql/user_delete.go:417-438` and `store/db/postgres/user_delete.go:380-401`, called from each driver's `deleteUserTargetsTx` at lines 96/102.

So reactions are cleaned up two ways in code: reactions attached to the deleted user's own memos (via `content_id`) and reactions the deleted user left on any memo (via `creator_id`), both inside the same transaction as the rest of the user-deletion cascade.
