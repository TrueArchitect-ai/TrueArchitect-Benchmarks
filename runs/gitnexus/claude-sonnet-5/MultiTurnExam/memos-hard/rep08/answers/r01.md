**Premise correction**: There is no Redis anywhere in this codebase — `grep -ri redis` across all Go source, docs, `go.mod`/`go.sum` returns zero hits. This project has no Redis dependency at all.

**Actual mechanism**: The cache layer is a pure in-memory cache, implemented in `store/cache/cache.go` (`type Cache`, with `New`, `Get`, `Set`, `Delete`, `Close`). It's constructed in `store/store.go:38-61` (`func New`), where `Store` holds three instances — `instanceSettingCache`, `userCache`, `userSettingCache` — all built from a shared `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user entries (`userCache`) get a **10-minute default TTL**, with a background cleanup sweep every 5 minutes and a 1000-item cap — all in-process, nothing external like Redis is configured or connected.
