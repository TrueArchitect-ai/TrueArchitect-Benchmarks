— Premise is wrong: neither. There is no message broker — no NATS, RabbitMQ, AMQP, or Kafka dependency in `go.mod`/`go.sum`. Webhook delivery is in-process: a package-level buffered Go channel `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`) drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each calling `Post` (:120). Producers call `PostAsync` (:184), which drops the payload with a warning when the buffer is full — so the "queue" is unbounded-loss, non-durable, and dies with the process.
