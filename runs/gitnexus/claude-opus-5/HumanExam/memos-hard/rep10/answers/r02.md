— Premise is wrong: there is no rate-limiting middleware in this codebase, per-user or otherwise. A repo-wide grep for `ratelimit`/`rate_limit`/"rate limit" in Go sources yields one hit, and it is a doc comment listing a *future* idea: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"). The Echo middleware chain registers only `middleware.Recover()` and the CORS middleware (`server/server.go:51-53`); the API v1 stack adds auth/authorization interceptors (`server/router/api/v1/v1.go:65-70`, `server/router/api/v1/authz.go`), not throttling. The only request-concurrency limits are semaphores for thumbnail/image work (`server/router/api/v1/v1.go:59-60`, `server/router/fileserver/fileserver.go:116`), which are not rate limits.
