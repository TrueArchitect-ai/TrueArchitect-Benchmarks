— Premise is wrong: there is no message broker at all — no NATS, RabbitMQ/AMQP, Kafka, or Redis anywhere in the Go code or `go.mod`, and no queue is declared. Webhook delivery is in-process: a buffered Go channel `asyncPostQueue` of capacity 128 (`internal/webhook/webhook.go:39`) drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each calling `Post` (`internal/webhook/webhook.go:120`). Producers use `PostAsync` (`internal/webhook/webhook.go:184`), which drops the event with a warning if the buffer is full (`:191-195`). Consequences: no durability across restarts, no retries.
