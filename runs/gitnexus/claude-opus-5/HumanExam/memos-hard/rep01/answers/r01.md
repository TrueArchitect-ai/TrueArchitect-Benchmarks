— Premise is wrong: there is no Redis and no external cache layer. The cache is an in-process, TTL'd `sync.Map` implementation — `store/cache/cache.go:66-90` (`Cache`, `New`, background `cleanupLoop` at `:200`). Three instances are created in `store.New`: `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:47-58`). The config is hard-coded in Go, not configured anywhere: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:40-45`; identical defaults at `store/cache/cache.go:57-64`). So user entries live 10 minutes; there is no per-entity TTL override (`SetWithTTL` exists at `store/cache/cache.go:98` but no production caller passes a custom TTL). Explicit invalidation happens on user delete (`store/user_delete.go:38-46`).
