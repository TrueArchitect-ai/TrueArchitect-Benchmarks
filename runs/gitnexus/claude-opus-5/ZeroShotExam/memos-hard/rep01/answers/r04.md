**Premise correction:** Neither. There is no message broker in this repository at all — no NATS, no RabbitMQ, no Kafka/Redis/AMQP client. `go.mod` contains no broker dependency of any kind, and there is no queue *declaration* in the broker sense (no exchange/subject/durable-consumer setup anywhere in the tree). The only "queue" is an in-process Go channel.

**Actual mechanism** — an in-memory buffered channel with a fixed goroutine worker pool, all inside the single Memos server process:

- **The "queue" is declared** at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  A package-level buffered channel with capacity 128.

- **The "workers"** are 4 goroutines started in the package `init()` at `internal/webhook/webhook.go:42-55`. Each ranges over `asyncPostQueue` and calls `Post(payload)`; failures are only logged via `slog.Warn` — there is no retry, no dead-letter, and no persistence.

- **Producers** enqueue via `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`). It does a non-blocking `select` send: if the buffer is full, the payload is **dropped** with a warning (`internal/webhook/webhook.go:191-195`). Nil payloads are also dropped.

- **Call sites** are in `server/router/api/v1/memo_service_webhooks.go` — `DispatchMemoCreatedWebhook` / `Updated` / `Deleted` route through `dispatchMemoRelatedWebhook` (line 71), and `DispatchMemoCommentCreatedWebhook` calls `PostAsync` directly (line 43). Subscriber URLs come from per-user settings via `s.Store.GetUserWebhooks` (see `store/user_setting.go`, `server/router/api/v1/user_service_webhooks.go`).

- **Delivery itself** is a plain HTTP POST in `Post` (`internal/webhook/webhook.go:120-180`), signed per the Standard Webhooks spec (`webhook-id` / `webhook-timestamp` / `webhook-signature`, HMAC-SHA256), using a shared client whose dialer blocks reserved/private IPs for SSRF protection (`internal/webhook/webhook.go:59-77`).

Practical consequence of there being no broker: webhook deliveries are best-effort and process-local — anything still buffered is lost on restart, and bursts beyond 128 queued items are silently dropped rather than backpressured.
