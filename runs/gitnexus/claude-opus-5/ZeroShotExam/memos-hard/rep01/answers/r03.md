**Premise correction: there is no nightly database-cleanup job in this repo's cron scheduler.** The scheduler exists, but it is a standalone library with *zero* registered jobs anywhere in production code — so there is no scheduled time to report.

What's actually there:

- `internal/scheduler/` is a self-contained cron-job library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). Its package doc describes it as "a GitHub Actions-inspired cron job scheduler" (`internal/scheduler/doc.go:1`).
- Nothing outside the package imports it. The only importers of `github.com/usememos/memos/internal/scheduler` are its own test files (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No server, cmd, or store code registers a job.
- The package contains no database code at all — the only `db` reference in the whole package is a `db.Exec("INSERT IGNORE INTO processed_items ...")` snippet inside a README prose example (`internal/scheduler/README.md:278`).

The likely source of the premise is that "cleanup at 2 AM" appears repeatedly in **documentation and example code**, not in a wired-up job:

- `internal/scheduler/doc.go:15-16` — a doc comment showing `Name: "daily-cleanup"`, `Schedule: "0 2 * * *"` ("2 AM daily").
- `internal/scheduler/example_test.go:97-106` — a runnable `Example_multipleJobs` registering a `"cleanup"` job at `"0 2 * * *"`, alongside a health check (`*/5 * * * *`) and weekly backup (`0 1 * * 0`).
- `internal/scheduler/README.md:34-37` — the same `"daily-cleanup"` quick-start snippet.
- `internal/scheduler/README.md:241-245` — a best-practices snippet for a `"stale-session-cleanup"` job at `"0 3 * * *"` (3 AM), which removes sessions rather than doing database cleanup.

So if a specific time is wanted from those illustrations, the closest is **2 AM daily (`0 2 * * *`)** — but that's example/doc code, not a job this application actually schedules or runs.
