**No** — outside `NewDBDriver`, the MySQL driver is never constructed in application code. There is exactly one in-package test exception (a zero-value struct, not a real driver).

**Evidence:**

1. **Only one call site for the constructor.** `mysql.NewDB` (`store/db/mysql/mysql.go:20`) is called exactly once in the whole repo: `store/db/db.go:22`, inside the `switch profile.Driver` factory. Grepping `NewDB\b` across all `*.go` returns only the three definitions (sqlite/mysql/postgres), the three factory call sites in `store/db/db.go:20-24`, and two direct `sqlite.NewDB` calls in tests (`store/demo_seed_test.go:24`, `store/deployment_config_test.go:416`) — no direct `mysql.NewDB` anywhere.

2. **Only one importer of the package.** `grep -rn "usememos/memos/store/db/mysql"` matches a single line: `store/db/db.go:8`. No other package can construct `mysql.DB` at all, since nothing else imports it.

3. **Everything funnels through the factory.** `NewDBDriver` callers are `store/test/store.go:28` and `:50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70`; each passes a `profile.Driver` string, so even the MySQL test path goes through the factory.

**The one exception, and why it doesn't count as constructing the driver:** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — an in-package zero-value literal with nil `db`/`profile`/`config`, used purely to call the pure method `IsRetryableAuthenticationMutationError` on MySQL error codes. It opens no connection.

**A near-miss worth naming:** `store/test/containers.go:145` calls `sql.Open("mysql", dsn)` (and imports `go-sql-driver/mysql` at line 16, plus the testcontainers `mysql.Run` at line 101). That is a raw `database/sql` handle for container bootstrapping/readiness, not the `store.Driver` implementation — it never produces a `mysql.DB`.
