### Where delivery executes

- `webhook.Post` (`internal/webhook/webhook.go:120`) is the only place an outbound request is actually made: it marshals the payload, builds the POST, optionally adds Standard Webhooks HMAC headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and fires `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.
- Callers never invoke `Post` directly. `webhook.PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a buffered channel (`asyncPostQueue`, cap 128, dropping with a warning when full); four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it and call `Post`.
- The API layer feeds that queue from `dispatchMemoRelatedWebhook` and `DispatchMemoCommentCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, reached via the `DispatchMemoCreated/Updated/DeletedWebhook` wrappers (`server/router/api/v1/memo_service_webhooks.go:15-27`).

### What protects it from internal addresses

Two layers, both bottoming out in `isReservedIP` (`internal/webhook/validate.go:44`), which tests against the CIDR list at `internal/webhook/validate.go:14-23` — IPv4 loopback, RFC-1918 ranges, `169.254.0.0/16` (cloud IMDS), plus IPv6 loopback/ULA/link-local.

1. **Dial-time enforcement (the real guard).** `safeClient` (`internal/webhook/webhook.go:32-37`) uses a `http.Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:59-77`). It splits host/port, resolves the host itself, rejects the connection if *any* returned IP is reserved, and only then dials. Because the check happens on the resolved address at connect time rather than on the stored URL, it also defeats DNS rebinding — which the comment at `internal/webhook/webhook.go:30-31` calls out explicitly.
2. **Write-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62-83`) runs when a user creates or updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument`. This is UX/early-rejection; it's TOCTOU-vulnerable on its own, which is why layer 1 exists.

One thing worth flagging: `AllowPrivateIPs` (`internal/webhook/validate.go:41`) is a global kill switch that disables *both* layers when true. `CHANGELOG.md:121` documents an `--allow-private-webhooks` flag for it, but I found no non-test assignment in the current tree — only `internal/webhook/webhook_test.go:91` and `:142`. So the escape hatch is presently unreachable from configuration; the flag appears to have been dropped or not yet re-wired.
