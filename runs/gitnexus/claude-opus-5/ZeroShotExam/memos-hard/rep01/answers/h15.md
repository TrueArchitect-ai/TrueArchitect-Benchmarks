h15.

Memo visibility is enforced at **eleven distinct sites** across four server surfaces (Connect/gRPC API, raw HTTP file server, feed/sitemap routes, SSE broadcast) plus the store query layer.

**Connect/gRPC API (`server/router/api/v1/`)**

1. `checkMemoReadAccess` — single-memo read gate (archived→creator-only; non-public→must be authed; private→creator only) — `server/router/api/v1/memo_service.go:39-67`. Called by `GetMemo` (memo at `:356`, and again on the *parent* memo at `:367`) and by `ListMemoComments` at `server/router/api/v1/memo_service_comments.go:148`.
2. `ListMemos` — list-query scoping: anonymous ⇒ `VisibilityList = [PUBLIC]`; authed ⇒ CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`, or `[PUBLIC, PROTECTED]` when listing another user — `server/router/api/v1/memo_service.go:217-227`.
3. `ListMemoComments` — second, list-level filter on the comment set itself (`visibility == "PUBLIC"` for anonymous, else creator-or-public/protected) — `server/router/api/v1/memo_service_comments.go:152-161`; plus `CreateMemoComment`'s private-parent check at `:41`.
4. `ListAllUserStats` / `GetUserStats` — same visibility scoping applied to the stats aggregation query — `server/router/api/v1/user_service_stats.go:83-92` and `:217-221`.
5. `ListMemoReactions` / `UpsertMemoReaction` — visibility checked before exposing or writing reactions — `server/router/api/v1/reaction_service.go:29-40` and `:83`.
6. `ListMemoAttachments` — visibility of the owning memo gates the attachment list — `server/router/api/v1/memo_attachment_service.go:213-225`.
7. `checkAttachmentAccess` — an attachment linked to a memo inherits that memo's visibility — `server/router/api/v1/attachment_service.go:434-453`.
8. `GetMemoByShare` — the deliberate *bypass* path: an unexpired share token grants read regardless of visibility; only archived/missing is refused — `server/router/api/v1/memo_share_service.go:151-191` (token validity in `getActiveMemoShare` / `isMemoShareExpired`, `:194-213`).

**Raw HTTP file server**

9. `checkAttachmentPermission` — serving attachment bytes: public+anonymous-allowed ⇒ open; else `share_token` query-param fallback; else must be authed, and private ⇒ creator or admin — `server/router/fileserver/fileserver.go:666-703`.

**Feeds / crawler surfaces**

10. RSS feeds — hard-pinned to `VisibilityList: [PUBLIC]` for both explore and per-user feeds — `server/router/rss/rss.go:90` and `:141`; sitemap likewise at `server/router/frontend/frontend.go:150`.

**SSE live broadcast**

11. `SSEClient.canReceive` — per-connection delivery filter: private events only to creator or admin — `server/router/api/v1/sse_hub.go:134-144`, with the event's visibility/creator stamped by `buildMemoSSEEvent`/`resolveSSECreatorID` (comments inherit the *parent* memo's creator) — `server/router/api/v1/sse_event_helpers.go:9-38`.

**Supporting layers (not independent gates, but where the decision is realized/reused)**

- Store SQL translation of `VisibilityList` into a `visibility IN (...)` predicate — `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`.
- Notification/mention fan-out suppresses delivery based on memo visibility — `server/router/api/v1/memo_mention_helpers.go:62-84`, `server/router/api/v1/user_service_notifications.go:309-312`, `server/notification/email.go:313-316`.

The notable asymmetry: `GetMemo` uses an imperative post-fetch check, while `ListMemos`/stats/comments push the rule into the query as a CEL filter — so the same policy is expressed twice in two different forms, and share tokens bypass both by design.
