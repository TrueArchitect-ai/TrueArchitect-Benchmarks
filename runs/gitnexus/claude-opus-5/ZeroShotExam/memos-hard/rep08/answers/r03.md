**Premise correction: there is no nightly database-cleanup job in this repository.** No cron job of any kind is registered in production code.

What actually exists:

- `internal/scheduler/` is a **standalone, self-contained cron library** (parser, job registry, middleware, graceful shutdown, zero external dependencies) — see `internal/scheduler/doc.go:1-35`. It has no production callers: the only files importing `github.com/usememos/memos/internal/scheduler` are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). Nothing in `cmd/` or `server/` constructs a scheduler or registers a job.
- There is no database-cleanup handler anywhere — no vacuum/purge/retention job in `store/` or `server/`.

The `0 2 * * *` (2 AM daily) expression you may be thinking of appears **only in documentation and test fixtures**, and never as a *database* cleanup:

- `internal/scheduler/doc.go:15-16` — package doc example, job named `"daily-cleanup"`, handler body is the comment `// Your cleanup logic here`
- `internal/scheduler/example_test.go:98-106` — `Example_multipleJobs`, job `"cleanup"` that prints `"Cleaning up old data..."`
- `internal/scheduler/README.md:34-35` and `:321`
- `internal/scheduler/parser_test.go:82` — a parser test case

Worth noting: the library's own README argues *against* that time. `internal/scheduler/README.md:261-269` recommends staggering off the hour, giving `"5 2 * * *"` as good and calling `"0 2 * * *"` "often overloaded" — so 2:00 AM is the doc example the README itself advises replacing, not a configured job.

If you're looking for scheduled maintenance in memos, it isn't wired up through this package; the scheduler is currently dead code awaiting a first consumer.
