**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider must produce. This is the type the SSO flow consumes regardless of protocol.

- **Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol implementation that ships. It provides `IdentityProvider` with `NewIdentityProvider(*storepb.OAuth2Config)`, `ExchangeToken` (with optional PKCE code verifier), and `UserInfo`, built on `golang.org/x/oauth2`.

Corroborating details:
- `proto/store/idp.proto` declares `IdentityProvider.Type` with exactly one non-unspecified value, `OAUTH2`, and `IdentityProviderConfig` is a `oneof` containing only `OAuth2Config` — so OAuth2 is the sole supported protocol at the schema level too.
- `server/router/api/v1/auth_service_sso.go:104-130` (`resolveSSOIdentity`) is the wiring point: it imports both packages, constructs `oauth2.NewIdentityProvider(...)` from the stored config, exchanges the code for a token, and returns an `*idp.IdentityProviderUserInfo`.
