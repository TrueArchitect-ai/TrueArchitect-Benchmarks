Memo visibility is enforced at many independent points — there is no single chokepoint. The distinct enforcement sites:

**Core read gate (single-memo fetch)**
- `checkMemoReadAccess` (GetMemo, parent-memo resolution, ListMemoComments) — `server/router/api/v1/memo_service.go:39-67`

**List/query scoping (visibility pushed into the store query)**
- `ListMemos` visibility scoping (`VisibilityList` for anonymous, CEL `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` for authed) — `server/router/api/v1/memo_service.go:218-227`
- `ListMemoComments` comment filter (`visibility == "PUBLIC"` vs. creator-or-public/protected) — `server/router/api/v1/memo_service_comments.go:152-180`
- User stats aggregation (`ListAllUserStats` and per-user stats) — `server/router/api/v1/user_service_stats.go:84-92` and `:217-221`
- RSS feeds (explore + per-user), public-only — `server/router/rss/rss.go:90` and `:141`
- Sitemap XML, public-only — `server/router/frontend/frontend.go:149-151`
- Storage-layer application of `VisibilityList` — `store/memo.go:69`, `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`

**Sub-resource gates (reached via a memo)**
- Reactions: `ListMemoReactions` (`:29-42`) and `UpsertMemoReaction` (`:83-84`) — `server/router/api/v1/reaction_service.go`
- Comment creation gate — `server/router/api/v1/memo_service_comments.go:33-43`
- Attachment access over gRPC/Connect: `checkAttachmentAccess` — `server/router/api/v1/attachment_service.go:419-454`
- Attachment blobs over plain HTTP: `checkAttachmentPermission` (separate implementation, adds share-token and anonymous-instance handling) — `server/router/fileserver/fileserver.go:650-703`

**Push/notification surfaces**
- SSE broadcast filtering: `SSEClient.canReceive` — `server/router/api/v1/sse_hub.go:134-143`
- Notification payload redaction: `canViewerAccessMemo` — `server/router/api/v1/user_service_notifications.go:302-317`
- Mention-notification eligibility — `server/router/api/v1/memo_mention_helpers.go:62-84`

**Deliberate bypass path**
- `GetMemoByShare` resolves an opaque share token and returns the memo *without* any visibility check (only archived/expired are rejected) — `server/router/api/v1/memo_share_service.go:151-191`; the matching token fallback in the file server is `server/router/fileserver/fileserver.go:684-690`

Two notes on scope: the MCP surface (`server/router/mcp/adapter.go:27-42`) replays tool calls through the same echo/Connect handlers, so it inherits the v1 checks rather than adding its own; and the store/db files above apply the filter but don't decide policy — the policy lives in the callers listed under list scoping.
