**Premise correction:** There is no GraphQL schema in this repository. There is no `.graphql`/`.gql` file, no GraphQL server library, and no `graphql` dependency in `go.mod`, `go.sum`, or `web/package.json`. The public API is not GraphQL.

**Actual API surface: Protobuf/gRPC, defined in `proto/api/v1/`**

The schema of record is the set of `.proto` files:

- `proto/api/v1/memo_service.proto` — `MemoService` (memos, attachments, relations, comments, reactions, shares, link metadata)
- `proto/api/v1/user_service.proto` — `UserService` (users, stats, user settings, linked identities)
- `proto/api/v1/auth_service.proto` — `AuthService` (`GetCurrentUser`, `SignIn`, `SignOut`, `RefreshToken`)
- `proto/api/v1/attachment_service.proto` — `AttachmentService`
- `proto/api/v1/instance_service.proto` — `InstanceService`
- `proto/api/v1/shortcut_service.proto` — `ShortcutService`
- `proto/api/v1/idp_service.proto` — `IdentityProviderService`
- `proto/api/v1/ai_service.proto` — `AIService` (`Transcribe`)
- `proto/api/v1/common.proto` — shared types
- Persistence-layer messages live separately in `proto/store/*.proto`

**How it's exposed.** Each RPC carries a `google.api.http` annotation that defines its REST binding, e.g. `proto/api/v1/memo_service.proto:23` (`post: "/api/v1/memos"`), `:30` (`get: "/api/v1/memos"`), `:35` (`get: "/api/v1/{name=memos/*}"`). So clients get a REST/JSON API under `/api/v1/...` — that is the closest analogue to what the question was reaching for, but it is resource-oriented REST, not a single GraphQL endpoint.

**Codegen and serving:**
- `proto/buf.gen.yaml` drives generation via `buf`: Go structs, gRPC, ConnectRPC, grpc-gateway, and an OpenAPI spec into `proto/gen/`, plus TypeScript client types into `web/src/types/proto`.
- `proto/gen/openapi.yaml` is the generated OpenAPI description, embedded into the binary by `proto/openapi_embed.go` and consumed by the MCP router (`server/router/mcp/service.go:78`).
- Handlers are registered in `server/router/api/v1/v1.go` — `RegisterGateway` (`v1.go:65`) wires each service into a grpc-gateway mux, mounts it at `/api/v1/*` and `/file/*`, and also sets up ConnectRPC handlers for browser clients (replacing grpc-web).
- Server implementations are the Go files alongside `server/router/api/v1/v1.go`; `APIV1Service` embeds each generated `Unimplemented*Server`.

To change the API surface, edit the `.proto` files and regenerate with `buf generate` from `proto/` (see `proto/README.md`).
