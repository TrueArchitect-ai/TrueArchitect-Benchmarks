## Where delivery executes

`Post` at `internal/webhook/webhook.go:120` is where the outbound HTTP request actually happens — it marshals the payload, optionally attaches Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and issues `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

Callers never invoke `Post` directly. `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a buffered channel (`asyncPostQueue`, cap 128, drops with a warning when full); four goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post`. The API layer feeds it from `dispatchMemoRelatedWebhook` and `DispatchMemoCommentCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, which fan out to each of the memo creator's registered webhooks.

## What protects it

Two layers, both keyed on `isReservedIP` in `internal/webhook/validate.go:44`:

1. **Dial-time block (the real defense).** `safeClient` (`internal/webhook/webhook.go:32-37`) uses a `Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:59-77`). It splits host/port, resolves the hostname itself via `net.DefaultResolver.LookupHost`, and refuses the connection if *any* resolved address is reserved. Because this runs per-dial rather than at registration, it also defeats DNS rebinding — the comment at `internal/webhook/webhook.go:30-31` says as much.

2. **Registration-time validation.** `ValidateURL` (`internal/webhook/validate.go:62-83`) requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved ranges. It's called when a user creates or updates a webhook, at `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`, returning a gRPC `InvalidArgument`. This is a fail-fast UX check, not the security boundary — it's TOCTOU-vulnerable on its own.

The blocked ranges are `reservedCIDRs` at `internal/webhook/validate.go:14-23`: IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (explicitly covering the cloud IMDS endpoint `169.254.169.254`), plus IPv6 loopback, ULA, and link-local. They're parsed once in `init()`, which panics on a malformed entry rather than silently shipping a gap.

One caveat worth flagging: `AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling **both** layers at once. It's declared as an exported package var for self-hosted setups targeting LAN services, but I found no code anywhere in the repo that sets it — no flag, env var, or config binding — so it is unconditionally `false` in the shipped server and can only be flipped by an external importer of the package.
