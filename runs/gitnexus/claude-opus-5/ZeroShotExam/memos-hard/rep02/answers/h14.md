**Computation site; triggers; extracted properties**

**Computation site**

- Persisted derived metadata lives in the memo's stored payload (`MemoPayload.property` + `MemoPayload.tags`, defined in `proto/store/memo.proto:7-22` — the proto comment literally says "The calculated properties from the memo content").
- It is computed by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`, which delegates to the goldmark-based markdown service: `markdown.(*service).ExtractAll` in `internal/markdown/markdown.go:356-422` (single AST walk; the equivalent standalone extractors are `ExtractTags` at `internal/markdown/markdown.go:143` and `ExtractProperties` at `internal/markdown/markdown.go:193-241`).
- On read, the store payload is mapped to the API shape by `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315-326`), assigned in `convertMemoFromStoreWithCreators` (`memo_service_converter.go:47-51`).

**Triggers**

1. `CreateMemo` — `server/router/api/v1/memo_service.go:108` (rebuild before `Store.CreateMemo`). Comments inherit this: `CreateMemoComment` calls `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:436-451`: only when the update mask contains `content`; the rebuilt payload is written via `update.Payload`. Other mask paths (visibility, pinned, state, timestamps) do not recompute it.
3. Batch backfill — `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) rebuilds every memo in batches of 100 and persists via `Store.UpdateMemo`. Note: this runner is not currently wired into startup — `server/server.go:153-173` only starts the `s3presign` runner, and `memopayload` is imported nowhere but `memo_service.go`.

**Extracted properties**

From `ExtractAll` / `ExtractProperties` (`internal/markdown/markdown.go:376-408`):

- `tags` — all `#tag` nodes, excluding tags nested inside links/images (`asMemoTagNode`, `markdown.go:134-140`), deduplicated preserving case.
- `property.title` — text of the first block-level child if it is an H1 heading (`extractHeadingText`, `markdown.go:173-179`).
- `property.has_link` — any `KindLink` node.
- `property.has_code` — any code block, fenced code block, or inline code span.
- `property.has_task_list` — any GFM task checkbox.
- `property.has_incomplete_tasks` — any task checkbox with `IsChecked == false`.
- (`ExtractAll` also returns `Mentions`, but `RebuildMemoPayload` doesn't store them; mentions are consumed separately in `server/router/api/v1/memo_mention_helpers.go:32`.)

These fields drive list/filter behavior and user stats (`server/router/api/v1/user_service_stats.go:138-168`).

One related but distinct field: `Memo.snippet` is also derived from content, but it is computed on the fly per response rather than stored — `getMemoContentSnippet` → `GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-90`, `internal/markdown/markdown.go:264-346`), called from `memo_service_converter.go:76` and `memo_relation_service.go:154-162`.
