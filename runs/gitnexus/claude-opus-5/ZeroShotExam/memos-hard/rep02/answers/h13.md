**`*markdown.service` (the single unexported struct) — built only by `markdown.NewService(...)` — held by `APIV1Service`, `RSSService`, and `memopayload.Runner`.**

### The interface
`markdown.Service` (`internal/markdown/markdown.go:31-55`) declares 8 methods: `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

### Concrete implementation — exactly one
`type service struct { md goldmark.Markdown }` (`internal/markdown/markdown.go:57-60`) is the only type implementing it — there is no mock or alternate impl anywhere in the repo (a grep for other `ExtractAll`/`RenderHTML` method receivers returns only `internal/markdown/markdown.go:356` and `:255`). Tests use the real service.

Behaviour is varied by options rather than by a second type: `WithTagExtension()` / `WithMentionExtension()` (`markdown.go:71-82`) toggle which goldmark extenders are added on top of `extension.GFM` in `NewService` (`markdown.go:85-113`). Nested behind it, `RenderMarkdown` and `RenameTag` delegate to a concrete `*renderer.MarkdownRenderer` (`internal/markdown/renderer/markdown_renderer.go:15-30`), which is *not* behind an interface.

### Construction
Production construction happens in exactly one place:
- `server/router/api/v1/v1.go:48-51` — `NewAPIV1Service` builds it with **both** tag and mention extensions enabled.

Test-only constructions (different option sets, so not the runtime config):
- `server/router/api/v1/test/test_helper.go:44-46` — tags + mentions
- `server/router/fileserver/fileserver_test.go:427` — tags only
- `server/router/rss/rss_test.go:54` — no extensions

At runtime there is a **single instance**: `server/server.go:76` creates the `APIV1Service`, and `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService`, so RSS shares the same object rather than making its own.
