## Where delivery executes

`webhook.Post` (`internal/webhook/webhook.go:120-180`) is the function that actually performs the outbound HTTP POST — it marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 signature headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and issues `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

It is reached asynchronously, not inline with the request:
- `webhook.PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel `asyncPostQueue`, dropping with a warning when full.
- Four goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`.
- Callers are the memo dispatchers in `server/router/api/v1/memo_service_webhooks.go` — `dispatchMemoRelatedWebhook` (line 48, for created/updated/deleted) and `DispatchMemoCommentCreatedWebhook` (line 30), which look up per-user webhooks via `s.Store.GetUserWebhooks` and call `PostAsync` at lines 43 and 71.

## What protects it from internal addresses

Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests an IP against `reservedNetworks` — parsed at startup from `reservedCIDRs` (`internal/webhook/validate.go:14-23`): 127.0.0.0/8, the three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), ::1/128, fc00::/7, fe80::/10.

1. **Dial-time enforcement — the real protection.** `safeClient` (`internal/webhook/webhook.go:32-37`) is an `http.Client` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:59-77`). On every connection it re-resolves the host via `net.DefaultResolver.LookupHost` and refuses the dial if *any* returned address is reserved. Because this runs at connect time rather than at save time, it also defeats DNS rebinding.

2. **Admission-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62-83`) rejects non-absolute URLs, non-http/https schemes, unresolvable hostnames, and hostnames resolving into a reserved range, returning a gRPC `InvalidArgument`. It is called when webhooks are created/updated in `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`.

**Escape hatch:** the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers at once. It defaults to `false`; per `CHANGELOG.md:121` it's exposed as the `--allow-private-webhooks` CLI flag for self-hosted deployments targeting LAN services. Note that in the current tree the flag variable is only assigned in `internal/webhook/webhook_test.go` — I did not find a non-test assignment wiring the CLI flag to it, so that binding may have been lost or moved since the changelog entry.
