## How I determined it runs (rather than the MySQL/Postgres twins)

Three types implement `CreateMemo(ctx, *store.Memo)` — `store/db/sqlite/memo.go:16`, `store/db/mysql/memo.go:16`, `store/db/postgres/memo.go:16` — so the answer depends on which one the `store.Driver` interface value holds at runtime. I resolved that by walking the chain in both directions:

1. **Down from the API entry point.** `APIV1Service.CreateMemo` (`server/router/api/v1/memo_service.go:70`) calls `s.Store.CreateMemo` at line 115. That wrapper (`store/memo.go:109-114`) only validates the UID against `base.UIDMatcher`, then delegates: `return s.driver.CreateMemo(ctx, create)`. No caching or decorating layer sits in between — `Store.driver` is the plain interface field assigned once in `store.New` (`store/store.go:15,38,48`). The Connect RPC handler (`server/router/api/v1/connect_services.go:306`) funnels into the same `APIV1Service.CreateMemo`, so both transports converge here.

2. **Up from the driver construction.** `db.NewDBDriver` (`store/db/db.go`) is a single `switch profile.Driver` over `"sqlite" | "mysql" | "postgres"`, defaulting to an `"unknown db driver"` error — the string value is the only thing that decides the implementation.

3. **Pinning the default value.** In `cmd/memos/main.go`, both the Viper default and the persistent flag default are `"sqlite"` (lines 122 and 130), bound together at line 151, and read into the profile at line 43. `Profile.Validate` corroborates this by filling in a SQLite-specific DSN when none is given: `if p.Driver == "sqlite" && p.DSN == ""` → `<dataDir>/memos_prod.db` (`internal/profile/profile.go:109-116`). So with no database flags set, `profile.Driver == "sqlite"` and the switch selects `sqlite.NewDB`.

The MySQL and Postgres versions are only reachable with an explicit `--driver` (or env/config equivalent); note the Postgres one is textually different — `INSERT INTO memo (...)` unquoted with `$n` placeholders (`store/db/postgres/memo.go:38`) — which is why a plain grep for `INSERT INTO memo` finds Postgres but not the SQLite path that actually runs.
