## The interface

`markdown.Service` — `internal/markdown/markdown.go:31-55`: `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

## Implementation

Exactly one concrete type: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:57-60`), with all eight methods on `*service` (lines 143, 193, 244, 255, 264, 349, 356, 425). A repo-wide grep turns up **no mock, fake, or stub implementation** — even the tests (`internal/markdown/markdown_test.go`, `server/router/rss/rss_test.go`, `server/router/api/v1/test/test_helper.go`, `server/router/fileserver/fileserver_test.go`) construct the real one via `NewService`. So the interface is a seam for configuration/testability, not for polymorphism.

Configuration varies via functional options rather than type: `WithTagExtension()` / `WithMentionExtension()` (`markdown.go:71-82`) append the custom `extensions.TagExtension` / `extensions.MentionExtension` on top of `extension.GFM` (`markdown.go:91-108`).

## Construction

Single production construction site — `NewAPIV1Service` (`server/router/api/v1/v1.go:48-51`), with both tag and mention extensions enabled. `server/server.go:76` builds the API service, then line 85 passes `apiV1Service.MarkdownService` into `rss.NewRSSService`, so the RSS feed shares the same instance rather than making its own.

Test construction sites: `server/router/api/v1/test/test_helper.go:44-52` (same two options), `server/router/fileserver/fileserver_test.go:427` (tags only), `server/router/rss/rss_test.go:54` (no options).

One caveat on the third holder: `memopayload.NewRunner` (`runner.go:19`) is never called anywhere in the repo — `server.go` only wires `s3presign.NewRunner` (`server.go:162`). The runtime path into that package is the free function `RebuildMemoPayload(ctx, memo, markdownService)` (`runner.go:74`), which `APIV1Service` calls directly with its own instance. So `Runner` holds the interface in code but is currently dead; at runtime exactly one `*service` value exists, created in `NewAPIV1Service` and shared with RSS.

Separately, `renderer.NewMarkdownRenderer()` (`internal/markdown/renderer/markdown_renderer.go`) is a concrete AST→markdown renderer constructed inline by `RenderMarkdown` and `RenameTag` (`markdown.go:250, 451`) — it sits behind `Service`, not alongside it.
