**Premise correction:** There is no GraphQL schema in this repository. A case-insensitive grep for `graphql` across the entire tree (excluding `node_modules`) returns zero matches — no `.graphql`/`.gql` files, no schema-first SDL, no resolver layer, no GraphQL server dependency in `go.mod`. Memos' public API is **Protobuf/gRPC-defined**, exposed as gRPC, Connect, and a REST/JSON gateway.

**Actual API surface — where the schema lives:**

- **Source of truth: `proto/api/v1/*.proto`** — the public v1 API is defined here as Protobuf services with `google.api.http` annotations mapping each RPC to a REST route. The eight services are:
  - `proto/api/v1/memo_service.proto` (e.g. `MemoService.CreateMemo` → `POST /api/v1/memos`, `GetMemo` → `GET /api/v1/{name=memos/*}`)
  - `proto/api/v1/user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `ai_service.proto`
  - `proto/api/v1/common.proto` — shared enums/messages
  - `proto/api/v1/README.md` states the design follows Google's AIP resource-oriented guidelines (hence the `name=memos/*` resource naming).
- **Internal storage schemas** (not public API): `proto/store/*.proto`.
- **Codegen: `proto/buf.gen.yaml`** — buf generates Go protobuf/gRPC/Connect/grpc-gateway stubs into `proto/gen/`, an OpenAPI 3.0 spec into `proto/gen/openapi.yaml` (via gnostic), and TypeScript clients into `web/src/types/proto/api/v1/*_pb.ts`.
- **The generated OpenAPI spec is the closest thing to a "public API schema document"**: `proto/gen/openapi.yaml`, embedded into the binary by `proto/openapi_embed.go` (`OpenAPIYAML()`).
- **Serving:**
  - Connect/gRPC handlers registered in `server/router/api/v1/connect_handler.go:31` (`RegisterConnectHandlers`), with per-RPC implementations wired in `server/router/api/v1/connect_services.go` and business logic in `server/router/api/v1/*_service.go`.
  - REST/JSON gateway registered via `server/router/api/v1/v1.go:65` (`RegisterGateway`), invoked from `server/server.go:87`.
  - Additional non-gRPC surfaces: `server/router/rss`, `server/router/fileserver`, and an MCP endpoint at `server/router/mcp` (which itself consumes the OpenAPI spec — `server/router/mcp/openapi.go`).

`README.md:22` confirms the intended surface: "full REST and gRPC APIs for integration."
