**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package: `internal/idp`** — `internal/idp/idp.go:3` defines the provider-agnostic `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any IdP implementation normalizes its user data into.
- **Implementation package: `internal/idp/oauth2`** — `internal/idp/oauth2/oauth2.go:1` ("Package oauth2 implements the OAuth2 identity provider integration") provides `IdentityProvider` with `NewIdentityProvider(*storepb.OAuth2Config)`, `ExchangeToken` (with PKCE support), and user-info fetching.

OAuth2 is the only concrete protocol that ships: `proto/store/idp.proto` declares `IdentityProvider.Type` with just `TYPE_UNSPECIFIED` and `OAUTH2`, and `IdentityProviderConfig`'s oneof has a single `oauth2_config` variant. The only non-test consumer is `server/router/api/v1/auth_service_sso.go:12-13`, which imports both packages to run the SSO login flow, with storage in `store/idp.go` and the driver-specific files under `store/db/{sqlite,mysql,postgres}/idp.go`.
