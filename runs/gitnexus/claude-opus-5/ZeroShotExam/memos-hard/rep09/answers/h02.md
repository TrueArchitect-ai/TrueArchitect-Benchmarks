**delivery function — `Post` in `internal/webhook/webhook.go:120`** (the actual outbound `POST`, executing at `internal/webhook/webhook.go:152` via `safeClient.Do(req)`); **protection mechanism — `safeDialContext` (`internal/webhook/webhook.go:59`) backed by `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go:14-54`**.

How it fits together:

- **Trigger:** memo create/update/delete and comment-created call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43` and `:71`. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel; four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post`. So delivery executes on those background workers, not the request goroutine.
- **Primary SSRF guard (dial time):** `Post` uses the shared `safeClient` (`internal/webhook/webhook.go:32-37`) whose `Transport.DialContext` is `safeDialContext`. That resolves the host itself and refuses the connection if *any* resolved address is in a reserved range. Because the check happens at dial time on the resolved IPs, it also defeats DNS rebinding — a TOCTOU attack that a validate-then-fetch scheme would miss.
- **Secondary guard (registration time):** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a user creates or updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. It enforces http/https scheme and rejects hostnames resolving to reserved IPs, giving an immediate `InvalidArgument` instead of a silent later failure.
- **Blocked ranges** (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (covers cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`.
- **Escape hatch:** the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted deployments targeting LAN services. Note it is declared but never assigned anywhere in non-test code, so it is effectively always `false` at runtime — there's currently no config or CLI flag wired to it.

One gap worth flagging: the blocklist omits `0.0.0.0/8` (`0.0.0.0` and `127.x` aliases like `0` reach localhost on Linux), IPv4-mapped IPv6 forms such as `::ffff:127.0.0.1`, and carrier-grade NAT `100.64.0.0/10`. `net.ParseIP("::ffff:127.0.0.1")` yields a 4-in-6 address that `net.IPNet.Contains` does normalize to 4 bytes, so that case is actually covered — but `0.0.0.0/8` is not.
