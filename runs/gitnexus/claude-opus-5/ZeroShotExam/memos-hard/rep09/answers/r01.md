**Premise correction:** There is no Redis in this repository. `go.mod` has no Redis (or any external cache) dependency, and a case-insensitive search for `redis` across Go, TypeScript, YAML, JSON, and Markdown files returns zero hits. There is no connection string, host/port setting, or client to configure — nothing to point at a Redis server.

**Actual mechanism:** The cache layer is a hand-rolled, in-process, in-memory cache backed by `sync.Map`.

- **Implementation:** `store/cache/cache.go` — a `Cache` struct holding a `sync.Map` plus an atomic item counter (`store/cache/cache.go:66-73`). Entries are `item{value, expiration, size}` (`store/cache/cache.go:35-39`). A background goroutine (`cleanupLoop`, `store/cache/cache.go:200`) sweeps expired entries on a ticker, and `cleanupOldest` (`store/cache/cache.go:253`) evicts roughly 20% of `MaxItems` when the cache overflows. Expiry is also checked lazily on read (`Get`, `store/cache/cache.go:135`).
- **Where it's "configured":** `store/store.go:39-45`, inside `store.New()`. The config is a Go literal — not env vars, not a config file:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  - `OnEviction: nil`

  The same `cacheConfig` value is passed to all three caches — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`). An identical default also exists as `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), but `store.New` does not call it; it duplicates the values inline. Caches are shut down in `Store.Close` (`store/store.go:72-79`).

**TTL for user entries: 10 minutes.** The user cache is populated only via `s.userCache.Set(...)` — `store/user.go:98`, `:122`, `:132`, `:143`, `:167` — and `Set` delegates to `SetWithTTL` using `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). No call site anywhere in the codebase uses `SetWithTTL` directly, so users inherit the shared 10-minute default with no per-entry override. Cache keys are the stringified user ID (`userCacheKey`, `store/user.go:88-90`); entries are invalidated explicitly on delete (`store/user_delete.go:40`) and overwritten on update.

One consequence worth noting: because this is per-process memory, the cache is not shared across replicas. Running multiple memos instances against one database means each has its own copy, and a user updated on instance A can be served stale by instance B for up to 10 minutes — the invalidation at `store/user_delete.go:40` only affects the local process.
