Memo visibility is **not** funnelled through one guard — it is re-implemented at each surface that can expose memo data. Distinct enforcement sites:

Single-memo read gate (`checkMemoReadAccess`, used by GetMemo, its parent memo, ListMemoComments) — `server/router/api/v1/memo_service.go:39-76` (callers at `:356`, `:367`, `server/router/api/v1/memo_service_comments.go:148`)
List query scoping (ListMemos injects `VisibilityList`/CEL `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:217-227`
Memo sub-resource RPCs, inline duplicated checks — `server/router/api/v1/memo_attachment_service.go:213-224` (ListMemoAttachments), `server/router/api/v1/reaction_service.go:29-41` and `:82-85` (ListMemoReactions, UpsertMemoReaction), `server/router/api/v1/memo_service_comments.go:41-43` (CreateMemoComment)
Attachment RPC access check (linked attachment inherits its memo's visibility) — `server/router/api/v1/attachment_service.go:424-454`
Memo-relation scoping filter (hides related/comment memos the viewer can't see) — `server/router/api/v1/memo_relation_service.go:107-112`, `server/router/api/v1/memo_service_converter.go:182-187`, applied in SQL at `store/db/{sqlite,mysql,postgres}/memo_relation.go`
User stats aggregation — `server/router/api/v1/user_service_stats.go:78-92` (ListAllUserStats), `:217-221` (GetUserStats)
SSE broadcast delivery filter (per-client, private events only to creator/admin) — `server/router/api/v1/sse_hub.go:134-144`, event visibility stamped in `server/router/api/v1/sse_event_helpers.go:29-37`
File server HTTP attachment/blob serving (independent Echo path, own auth) — `server/router/fileserver/fileserver.go:650-703`
Share-token grant path (bypasses visibility by design; token is the authority, creator/admin-only to mint) — `server/router/api/v1/memo_share_service.go:42-44`, `:152-170`; honoured by the file server at `server/router/fileserver/fileserver.go:683-690`
RSS feeds (public-only) — `server/router/rss/rss.go:90`, `:141`
Sitemap XML (public-only) — `server/router/frontend/frontend.go:150`
In-app notification payload redaction (`canViewerAccessMemo`) — `server/router/api/v1/user_service_notifications.go:302-322` (used at `:337`, `:342`, `:370`, `:385`)
Email notification dispatch (second, separate copy of `canViewerAccessMemo`) — `server/notification/email.go:306-326` (used at `:155`, `:187`)
Mention notification gating (`canUserAccessMentionContext`) — `server/router/api/v1/memo_mention_helpers.go:56-88`

Two notes: the MCP surface (`server/router/mcp/catalog.go:12-14`) exposes `MemoService_ListMemos`/`GetMemo` but adds no check of its own — it inherits sites 1–2. And the store layer (`store/db/{sqlite,mysql,postgres}/memo.go:~90-105`) is where `VisibilityList` becomes SQL; it's the mechanism, not a decision point — it enforces whatever the caller passed, so a surface that forgets to set it leaks.
