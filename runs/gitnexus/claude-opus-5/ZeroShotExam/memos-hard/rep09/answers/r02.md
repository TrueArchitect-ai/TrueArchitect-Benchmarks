**Premise correction: this repository has no per-user API rate-limiting middleware.** There is nothing to register and no request limits to report.

Evidence:

- A repo-wide search for `rate limit` / `ratelimit` / `throttle` (and common Go limiter libs: `tollbooth`, `ulule/limiter`, `didip`) matches only prose, never code — `internal/email/doc.go:86` (`// - Rate limit email sending to prevent abuse`, an aspirational note) and `internal/email/README.md`.
- `golang.org/x/time` (which provides `rate.Limiter`) appears in `go.mod:151` marked `// indirect`, and no `.go` file imports it.

What actually is registered on the request path:

- Echo-level middleware — `server/server.go:51-52`: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go`). That's all.
- Connect/gRPC interceptors — `server/router/api/v1/v1.go:133-137`: `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, `NewAuthInterceptor(authorizer)`, all defined in `server/router/api/v1/connect_interceptors.go`. None of these count requests or enforce a per-user quota; `AuthInterceptor` only resolves identity and delegates to `Authorizer` (`server/router/api/v1/authz.go`).

The limits that do exist are size/pagination caps, not rate limits:

- `maxAPIRequestBytes = 256 << 20` (256 MiB) — `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` at lines 126, 141, 144.
- `DefaultPageSize = 50`, `MaxPageSize = 1000` — `server/router/api/v1/common.go:13-18`.
- Per-request content/upload caps: memo content length limit from instance settings (`server/router/api/v1/memo_service.go:101-106`) and upload size limit (`server/router/api/v1/attachment_service.go:120-124`).

If you want per-user rate limiting, the natural insertion point is a new interceptor in `server/router/api/v1/connect_interceptors.go` added to the `connect.WithInterceptors(...)` list at `server/router/api/v1/v1.go:133`, keyed on the user resolved by `AuthInterceptor` — but note the REST/gateway path at line 126 and the non-API routers (`server/router/rss`, `server/router/mcp`, `server/router/fileserver`) bypass those interceptors and would need separate coverage.
