**Answer: `Memo.payload` — the `MemoPayload.Property` block plus `tags` (`proto/store/memo.proto:7-23`, commented "The calculated properties from the memo content").**

**Computation site**
- `RebuildMemoPayload` — `server/runner/memopayload/runner.go:74-88`. It ensures `memo.Payload` exists, calls the markdown service, and assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`.
- The actual extraction is `service.ExtractAll` — `internal/markdown/markdown.go:356-422`: one goldmark parse plus a single `gast.Walk` over the AST (there are also single-purpose `ExtractTags` at :143 and `ExtractProperties` at :193 with the same logic, kept for callers that need only one).

**Triggers (recomputation)**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before `Store.CreateMemo`.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:436-452`, only when the update mask contains the `content` path; the rebuilt payload is written via `update.Payload = memo.Payload`.
- A batch backfill exists — `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) pages through all memos 100 at a time, rebuilds, and persists via `Store.UpdateMemo`. Note it is not currently wired into startup: `server/server.go:162-163` only constructs and runs the `s3presign` runner, and nothing else references `memopayload.NewRunner`.

Nothing else recomputes it — e.g. `memo_mention_helpers.go:32` calls `ExtractAll` too, but only to resolve @mentions for notifications, not to persist payload.

**What the computation extracts** (`internal/markdown/markdown.go:376-408`)
- `Tags` — `#tag` nodes, skipping tags nested inside links/images (`asMemoTagNode`/`isTagNodeInLinkOrImage`, :122-140), deduplicated case-preserving (`uniquePreserveCase`, :456).
- `Mentions` — `@username` nodes, lowercased and deduplicated (used for notifications, not stored on the payload).
- `Property.Title` — text of the document's first block-level child if it is an H1 heading (`extractHeadingText`, :173).
- `Property.HasLink` — any `KindLink` node.
- `Property.HasCode` — any code block, fenced code block, or inline code span.
- `Property.HasTaskList` — any GFM task checkbox; `Property.HasIncompleteTasks` — any unchecked checkbox.

These reach the API in `convertMemoFromStore` (`server/router/api/v1/memo_service_converter.go:48-49` via `convertMemoPropertyFromStore` at :315), which is what list/preview rendering consumes. Separately, the `snippet` field shown in previews is *not* stored — it's generated per-response by `getMemoContentSnippet` (`memo_service_webhooks.go:83`) calling `GenerateSnippet(content, 64)` (`internal/markdown/markdown.go:264`).
