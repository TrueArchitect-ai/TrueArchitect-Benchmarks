## Where delivery executes

`webhook.Post()` — `internal/webhook/webhook.go:120` — is the function that actually performs the outbound HTTP request. It marshals the payload to JSON, builds a `POST`, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and issues the call at `internal/webhook/webhook.go:152` via `safeClient.Do(req)`.

Delivery is normally reached asynchronously: `PostAsync()` (`internal/webhook/webhook.go:184`) enqueues onto a buffered channel (`asyncPostQueue`, cap 128, dropping with a warning when full), and 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) call `Post` off that queue. Callers are `dispatchMemoRelatedWebhook` and `DispatchMemoCommentCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, covering memo created/updated/deleted and comment-created events.

## What protects it

Two layers, both keyed on `isReservedIP` in `internal/webhook/validate.go:44`:

1. **Dial-time enforcement (the real protection).** `safeClient` (`internal/webhook/webhook.go:32`) uses a `Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:59`). On every connection it re-resolves the host and refuses to dial if *any* resolved address falls in a reserved range. Because the check happens at dial time rather than at URL-registration time, it also defeats DNS rebinding — a hostname that validated as public earlier but later resolves to a private address still gets blocked.

2. **Registration-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates or updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument`. This is fail-fast UX; it is not sufficient alone, since resolution can change between validation and delivery.

The blocked ranges are `reservedCIDRs` at `internal/webhook/validate.go:14-23`: IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (which covers the cloud IMDS endpoint `169.254.169.254`), plus IPv6 loopback, unique-local, and link-local. They are parsed once at startup in `init()` (`internal/webhook/validate.go:28`), panicking on a malformed entry.

Two things worth flagging:

- **`AllowPrivateIPs`** (`internal/webhook/validate.go:41`) is a global kill switch that makes `isReservedIP` always return false, disabling both layers. Grepping the non-test tree, nothing ever sets it — there's no flag or config wiring, so it's effectively `false` in production and only settable from tests.
- The reserved list does **not** include `0.0.0.0/8`, `100.64.0.0/10` (CGNAT), IPv4-mapped IPv6 (`::ffff:127.0.0.1`), or `192.0.0.0/24`. `net.ParseIP` on an IPv4-mapped form yields a 16-byte IP that `Contains` will still match against the IPv4 `127.0.0.0/8` net (Go normalizes), so that specific case is covered, but `0.0.0.0` and CGNAT ranges are not.
