**Premise correction: this repository has no per-user API rate-limiting middleware.** There is no rate limiter of any kind — per-user, per-IP, or global — registered anywhere in the request path, so there are no request limits to report.

What's actually registered:

- **HTTP middleware** (`server/server.go:51-52`): only `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go:14`). Static-file/SPA middleware is added separately in `server/router/frontend/frontend.go:54,59`.
- **Connect/gRPC interceptor chain** (`server/router/api/v1/v1.go:133-138`): `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — defined in `server/router/api/v1/connect_interceptors.go`. Auth/authz only, no throttling.

Nearby things that might be mistaken for it:

- `maxAPIRequestBytes = 256 << 20` (256 MiB) in `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` at lines 126, 141, and 144. That's a per-request **body size** cap, not a request-rate limit.
- `internal/scheduler/middleware.go` defines a `Middleware`/`Chain` abstraction, but it wraps background **job handlers** (`Recovery`, `Logging`), not HTTP requests.

The only mention of rate limiting in the Go tree is aspirational documentation: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" under security recommendations — not implemented. `golang.org/x/time` appears in `go.mod:151` but is marked `// indirect` and is not used for limiting here.
