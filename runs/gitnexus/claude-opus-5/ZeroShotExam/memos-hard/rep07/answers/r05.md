**Premise correction:** There is no GraphQL schema in this repository. The memos public API is not GraphQL — searching for `graphql`/`gqlgen`/`apollo` across Go, TS, config, and schema files returns zero hits, and `go.mod` contains no GraphQL library.

**Actual API surface — Protobuf/gRPC, defined in `proto/api/v1/`:**

The single source of truth is the `.proto` files:

- `proto/api/v1/memo_service.proto` — `MemoService`
- `proto/api/v1/user_service.proto` — `UserService`
- `proto/api/v1/auth_service.proto` — `AuthService`
- `proto/api/v1/attachment_service.proto` — `AttachmentService`
- `proto/api/v1/instance_service.proto` — `InstanceService`
- `proto/api/v1/shortcut_service.proto` — `ShortcutService`
- `proto/api/v1/idp_service.proto` — `IdentityProviderService`
- `proto/api/v1/ai_service.proto` — `AIService`
- `proto/api/v1/common.proto` — shared types

All under package `memos.api.v1`.

**How that schema becomes the public surface** (`proto/buf.gen.yaml`, run via `buf generate`):

- **gRPC + Connect handlers** → `proto/gen/api/v1/` (Go)
- **REST/JSON** via grpc-gateway, from `google.api.http` annotations written inline in each RPC. E.g. `memo_service.proto:22-27` maps `CreateMemo` to `POST /api/v1/memos`; `ListMemos` → `GET /api/v1/memos`; `GetMemo` → `GET /api/v1/{name=memos/*}`.
- **OpenAPI spec** → `proto/gen/openapi.yaml`, embedded into the binary by `proto/openapi_embed.go` and consumed by the MCP router (`server/router/mcp/`).
- **TypeScript client types** → `web/src/types/proto/` for the frontend.

Server-side implementations live in `server/router/api/v1/` (e.g. `memo_service.go`, `auth_service.go`), with Connect wiring in `server/router/api/v1/connect_services.go` and `connect_handler.go`.

So the closest analogue to "the schema for the public API" is `proto/api/v1/*.proto`, with the generated `proto/gen/openapi.yaml` as the published API description.
