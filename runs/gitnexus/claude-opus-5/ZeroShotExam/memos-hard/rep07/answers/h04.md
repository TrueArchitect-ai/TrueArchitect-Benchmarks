**No** — outside `NewDBDriver`, the MySQL driver is never constructed in production code. The only other construction is a zero-value struct literal in an in-package unit test.

Evidence:

1. **The factory is the sole production construction site.** `store/db/db.go:22` calls `mysql.NewDB(profile)` inside `NewDBDriver` (`store/db/db.go:14`), and `store/db/db.go:8` is the *only* Go import of `github.com/usememos/memos/store/db/mysql` anywhere in the repo (grep for `store/db/mysql` in `*.go` returns only that line; other hits are docs under `docs/plans/`). Since `DB` and `NewDB` are only reachable from outside via that import path, no other package can construct the driver.

2. **`mysql.NewDB` has exactly one caller.** `store/db/mysql/mysql.go:20` defines it; the only call is `store/db/db.go:22`. The struct literal at `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`) is inside `NewDB` itself.

3. **All other consumers go through the factory.** `db.NewDBDriver` is called from `store/test/store.go:28`, `store/test/store.go:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` — driver selection is always by `profile.Driver` string, never by direct package reference.

4. **One in-package test exception.** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — a zero-value struct with no `*sql.DB`, used only to invoke the pure method `IsRetryableAuthenticationMutationError`. This is same-package (`package mysql`) test scaffolding, not a driver instantiation, and it's the only `&DB{}` in the mysql package. (By contrast, the postgres driver *does* have a non-factory literal path plus test literals at `store/db/postgres/user_setting_test.go:36,194,257`.)

5. **Beware the naming collision.** Many files import `github.com/go-sql-driver/mysql` (e.g. `store/db/mysql/mysql.go:7`, `store/test/containers.go:16`, `store/db/mysql/auth_config_test.go:6`) and `testcontainers .../modules/mysql` (`store/test/containers.go:20`, used at `containers.go:101`). Those are the upstream SQL driver and the test-container helper — not the memos `store.Driver` implementation.
