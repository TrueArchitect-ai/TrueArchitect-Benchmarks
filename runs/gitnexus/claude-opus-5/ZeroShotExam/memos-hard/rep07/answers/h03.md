**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package: `internal/idp`** — `internal/idp/idp.go` defines the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any provider must produce, decoupling the SSO login flow from any specific protocol.
- **Implementation package: `internal/idp/oauth2`** — `internal/idp/oauth2/oauth2.go` ("Package oauth2 implements the OAuth2 identity provider integration") provides the only concrete provider: `IdentityProvider` built from `storepb.OAuth2Config` via `NewIdentityProvider`, with `ExchangeToken` (including PKCE support) and user-info retrieval mapped through the configured `FieldMapping`.

Supporting evidence that OAuth2 is the sole shipped protocol:

- `proto/store/idp.proto:21` — `IdentityProviderConfig` is a oneof whose only member is `oauth2_config` (`OAuth2Config`); same in `proto/api/v1/idp_service.proto`.
- `server/router/api/v1/auth_service_sso.go:12-13` is the only non-test consumer, importing both `internal/idp` and `internal/idp/oauth2` to drive the SSO sign-in path.
- Storage/CRUD for provider records lives in `store/idp.go` with per-driver implementations in `store/db/{sqlite,mysql,postgres}/idp.go`, and the gRPC surface in `server/router/api/v1/idp_service.go`.

No SAML, OIDC-specific, or LDAP implementation exists in the tree.
