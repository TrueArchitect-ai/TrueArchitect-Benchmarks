## Convergence

All six funnel through `server/router/api/v1/memo_service_webhooks.go` — the three memo verbs share the private `dispatchMemoRelatedWebhook` (`:48`), comments use `DispatchMemoCommentCreatedWebhook` (`:30`). Both read the target from the user's stored config (`s.Store.GetUserWebhooks` → `hook.Url`, `hook.SigningSecret`) and call `webhook.PostAsync`.

`PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto `asyncPostQueue`; four worker goroutines started in `init` (`:42`) drain it. The single function where every path converges and the outbound request is actually built and sent is:

**`Post` — `internal/webhook/webhook.go:120`**, which does `http.NewRequest("POST", requestPayload.URL, …)` and `safeClient.Do(req)` at `:152`.

If you want the last *synchronous* chokepoint in handler context instead, that's `PostAsync` at `internal/webhook/webhook.go:184` — but delivery itself happens only in `Post`.

Two notes on the URL being user-controlled: it's validated at write time by `webhook.ValidateURL` (`internal/webhook/validate.go:61`, called from `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`), and re-checked at dial time by `safeDialContext` (`internal/webhook/webhook.go:59`), which rejects reserved/private IPs. Those two user-webhook CRUD handlers do a DNS lookup but no outbound HTTP, so I've excluded them.
