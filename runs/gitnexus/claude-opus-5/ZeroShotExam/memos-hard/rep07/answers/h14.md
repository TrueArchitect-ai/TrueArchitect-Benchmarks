**Answer (computation site; triggers; extracted properties)**

**Computation site.** `memopayload.RebuildMemoPayload` at `server/runner/memopayload/runner.go:74-88`, which delegates the actual parsing to the markdown service's single-pass AST walk `(*service).ExtractAll` at `internal/markdown/markdown.go:356-422` (goldmark AST walk; the equivalent standalone walk is `ExtractProperties`, `internal/markdown/markdown.go:193-241`). The result is stored on the memo's payload blob (`memo.Payload.Tags`, `memo.Payload.Property`) — shape defined in `proto/store/memo.proto:7-23` (`MemoPayload.Property`, commented "The calculated properties from the memo content").

**Triggers (recomputation).**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before the row is inserted.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `path == "content"` branch of the update mask, so payload is rebuilt exactly when content changes (visibility/pinned/state updates don't recompute).
- Bulk backfill — `Runner.RunOnce` at `server/runner/memopayload/runner.go:27-72` walks all memos in batches of 100 and rebuilds each payload. Note: `memopayload.NewRunner` has no production caller (`server/server.go` only wires the `s3presign` runner), so this path is currently a migration/backfill utility rather than a scheduled job.

**Extracted properties.** `ExtractAll` returns tags, mentions, and the property struct; `RebuildMemoPayload` persists tags + property:
- `tags` — deduped `#tag` nodes, original case preserved, skipping tags nested inside links/images (`asMemoTagNode`, `internal/markdown/markdown.go:134-140`)
- `has_link` — any `KindLink` node
- `has_code` — any code block, fenced code block, or inline code span
- `has_task_list` — any GFM task checkbox
- `has_incomplete_tasks` — any task checkbox with `IsChecked == false`
- `title` — plain text of the first block child of the document when it is an H1 heading (`extractHeadingText`, `internal/markdown/markdown.go:173-179`)

(Mentions from `ExtractAll` are not persisted here; they're consumed separately in `server/router/api/v1/memo_mention_helpers.go:32`.)

Surfacing: `convertMemoPropertyFromStore` maps the stored property onto the `OUTPUT_ONLY` `Memo.property` API field (`server/router/api/v1/memo_service_converter.go:49,315-326`; `proto/api/v1/memo_service.proto:255-279`). The related preview `snippet` field is *not* part of this payload — it's derived per-request via `GenerateSnippet(content, 64)` at `server/router/api/v1/memo_service_converter.go:76-80` → `server/router/api/v1/memo_service_webhooks.go:83-85`.
