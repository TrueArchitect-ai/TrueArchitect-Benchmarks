**Convergence function — `webhook.Post` at `internal/webhook/webhook.go:120`**

The full chain:

1. Handlers call one of the four dispatchers in `server/router/api/v1/memo_service_webhooks.go` (`DispatchMemoCreatedWebhook`/`Updated`/`Deleted` → the shared private `dispatchMemoRelatedWebhook` at :48, plus `DispatchMemoCommentCreatedWebhook` at :30).
2. Each loads the target user's rows via `s.Store.GetUserWebhooks(...)` and sets `payload.URL = hook.Url` — the user-configured URL (`memo_service_webhooks.go:41,67`).
3. Both call `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue` channel (cap 128, drops with a warning when full).
4. Four worker goroutines started in `init()` (`webhook.go:42-55`) drain that queue and call **`Post`**, which builds the `http.POST`, optionally HMAC-signs it (Standard Webhooks `webhook-id`/`-timestamp`/`-signature`), and issues the request via `safeClient.Do(req)` at `webhook.go:152`.

Two notes on how you'd read the graph here: the channel hop in step 3–4 breaks the static call edge, so `Post`'s only non-test caller is the `init()` worker goroutine — the handler→`Post` reachability is not visible as a direct call chain. And the URL is guarded twice against SSRF: `ValidateURL` at write time (`internal/webhook/validate.go:62`) and `safeDialContext` at dial time (`webhook.go:59`), the latter also defeating DNS rebinding. Both are bypassable by design when the operator sets `AllowPrivateIPs` (`validate.go:41`).
