**`internal/idp`; `internal/idp/oauth2`**

- `internal/idp/idp.go` — the abstraction package. It's deliberately minimal: it defines only the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider implementation normalizes remote user data into.
- `internal/idp/oauth2/oauth2.go` — the only concrete protocol implementation ("Package oauth2 implements the OAuth2 identity provider integration"). It provides `IdentityProvider` wrapping a `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (supports PKCE via `codeVerifier`), and `UserInfo` returning `*idp.IdentityProviderUserInfo`.

Corroborating evidence:

- `server/router/api/v1/auth_service_sso.go:12-13` is the sole non-test consumer, importing both `internal/idp` and `internal/idp/oauth2`.
- The proto confirms OAuth2 is the only shipped protocol: `proto/api/v1/idp_service.proto:76-87` declares `enum Type { TYPE_UNSPECIFIED = 0; OAUTH2 = 1; }` and an `IdentityProviderConfig` oneof with a single member, `oauth2_config`.

Note that OIDC isn't a separate implementation here — it's covered by configuring the generic OAuth2 provider's `auth_url`/`token_url`/`user_info_url` plus `FieldMapping` (`proto/api/v1/idp_service.proto:89-96`).
