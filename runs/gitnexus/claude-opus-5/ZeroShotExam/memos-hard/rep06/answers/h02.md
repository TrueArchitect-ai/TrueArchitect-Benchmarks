### Where delivery executes

`webhook.Post` (`internal/webhook/webhook.go:120-180`) is the function that actually builds the POST, signs it, and calls `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

Callers never invoke it directly. The API layer calls `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload onto a bounded 128-slot channel (`asyncPostQueue`, line 39); four goroutines started in `init()` (lines 42-55) drain that queue and call `Post`. Entry points are `dispatchMemoRelatedWebhook` and `DispatchMemoCommentCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, fed by the created/updated/deleted dispatchers at lines 15-27.

### What protects it from internal addresses

Two layers:

1. **Dial-time enforcement (the real protection).** All dispatches share `safeClient` (`internal/webhook/webhook.go:32-37`), whose `http.Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:59-77`). It resolves the host itself via `net.DefaultResolver.LookupHost` and refuses the connection if *any* resolved address is reserved. Because this runs at connect time rather than at save time, it also defeats DNS rebinding — the comment at lines 29-31 states this explicitly.

2. **Admission-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62-83`) rejects non-`http(s)` schemes and reserved-resolving hostnames when a webhook is created or updated, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`. This returns a gRPC `InvalidArgument` for good UX but is TOCTOU-prone on its own; layer 1 is what actually holds.

Both layers share `isReservedIP` (`internal/webhook/validate.go:44-54`), which tests against `reservedNetworks` — parsed once at startup from `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` (explicitly covering the cloud IMDS endpoint `169.254.169.254`), plus IPv6 loopback, unique-local, and link-local.

### One caveat worth flagging

`AllowPrivateIPs` (`internal/webhook/validate.go:41`) is a global kill switch that disables **both** layers at once when true. It defaults to `false` and has no config, flag, or env wiring anywhere in the codebase — the only assignments are in `internal/webhook/webhook_test.go:91` and `:142`. So the documented "useful for self-hosted deployments" escape hatch is currently unreachable in production; SSRF protection is always on.
