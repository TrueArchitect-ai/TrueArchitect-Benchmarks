**Premise correction:** There is no GraphQL schema in this repository. A search for `graphql` across all Go, TypeScript, JSON, YAML, and proto sources returns zero hits. Memos has no GraphQL API — no schema file, no resolvers, no GraphQL server dependency.

**Actual API surface: Protocol Buffers (gRPC/Connect) + generated REST + OpenAPI**

The schema of record is a set of `.proto` files:

- `proto/api/v1/` — the public API definitions, one file per service:
  - `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto`
- `proto/store/` — internal persistence-layer messages (`memo.proto`, `idp.proto`, `user_setting.proto`, `instance_setting.proto`, `attachment.proto`, `inbox.proto`). These are storage types, not part of the public API.

Each RPC carries a `google.api.http` annotation that defines its REST binding. E.g. `proto/api/v1/memo_service.proto:17` declares `service MemoService`, with `ListMemos` mapped to `GET /api/v1/memos` (line 30), `GetMemo` to `GET /api/v1/{name=memos/*}` (line 35), `DeleteMemo` to `DELETE /api/v1/{name=memos/*}` (line 48), etc.

**Code generation** is driven by `proto/buf.gen.yaml`, which runs five plugins: protobuf-go, gRPC-go, ConnectRPC-go, grpc-gateway, and gnostic-openapi (Go output into `proto/gen/`), plus `bufbuild/es` emitting TypeScript clients into `web/src/types/proto` for the frontend.

**Derived artifacts:**
- `proto/gen/api/` and `proto/gen/store/` — generated Go bindings
- `proto/gen/openapi.yaml` — generated OpenAPI 3.0.3 spec; this is the closest thing to a browsable "public API schema" document. It is embedded into the binary via `proto/openapi_embed.go` and served at runtime through `proto.OpenAPIYAML()`.

**Server wiring:**
- `server/router/api/v1/` holds the hand-written service implementations (`memo_service.go`, `user_service.go`, `auth_service.go`, …), with `connect_handler.go` / `connect_services.go` exposing them over ConnectRPC and `connect_interceptors.go` handling auth/authz.
- `server/server.go:88` calls `apiV1Service.RegisterGateway(ctx, echoServer)` to mount the gRPC-gateway REST surface under `/api/v1`.
- Additional non-proto surfaces exist alongside it: `server/router/rss` (RSS feeds), `server/router/fileserver` (attachment serving), and `server/router/mcp` (MCP endpoint).

Design conventions are documented in `proto/api/v1/README.md`, which states the API follows the Google API Improvement Proposals (AIPs) — hence the resource-name style (`memos/*`, `users/*`) rather than a graph query model.
