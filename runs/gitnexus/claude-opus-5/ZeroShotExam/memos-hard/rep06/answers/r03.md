**Premise correction: there is no nightly database-cleanup job in this repo's cron scheduler.** No job is scheduled at any time, because the scheduler is never wired into the application.

What actually exists:

- `internal/scheduler/` is a standalone, self-contained cron scheduler package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It is imported **only** by its own tests — `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No `cmd/`, `server/`, or `store/` code registers a job with it, so no cron job of any kind runs in memos today.
- The "daily-cleanup" you may have seen is illustrative documentation, not a registration: `internal/scheduler/doc.go:15-19` shows a `Name: "daily-cleanup"` job with `Schedule: "0 2 * * *"` (2 AM daily) as the package's usage example, and `internal/scheduler/README.md:34` repeats it. Other cleanup names in `README.md:233,241` (`user-cleanup-job`, `stale-session-cleanup`) are likewise naming-convention examples with no handler behind them.

The real periodic background work in the app is interval-based (`time.Ticker`), not cron-scheduled and not nightly:

- `store/cache/cache.go:201` — in-memory cache expiry sweep, every 5 minutes by default (`store/cache/cache.go:60`). This touches the cache, not the database.
- `server/runner/s3presign/runner.go:30` — S3 presigned-link refresh, every 12 hours (`runner.go:27`).
- `server/router/api/v1/sse_handler.go:64` — SSE connection heartbeat.

So if you're looking for where to add a nightly DB cleanup, it would be new work: the scheduler package is ready to use but has no wiring point yet.
