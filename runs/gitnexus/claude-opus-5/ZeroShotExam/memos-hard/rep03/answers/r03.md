**Premise correction: there is no nightly database-cleanup job in this repository.** The `internal/scheduler` package is a standalone, self-contained cron scheduler *library* with no callers anywhere in the application — `grep` for `scheduler.` outside `internal/scheduler/` returns zero hits in `server/`, `cmd/`, or `store/`. Nothing in memos registers a cleanup job, and no job touches the database.

What does exist is a "2 AM daily cleanup" that appears only in **documentation and example code**:

- `internal/scheduler/doc.go:14-20` — package doc example: `Name: "daily-cleanup"`, `Schedule: "0 2 * * *", // 2 AM daily`, with the body being a `// Your cleanup logic here` placeholder.
- `internal/scheduler/README.md:34-35` — same `daily-cleanup` / `"0 2 * * *"` snippet in the quick-start; the handler just prints `"Running cleanup..."`.
- `internal/scheduler/example_test.go:97-106` — `Example_multipleJobs` registers a job named `cleanup` at `"0 2 * * *"` tagged `maintenance`, whose handler prints `"Cleaning up old data..."`.
- `internal/scheduler/README.md:241-245` — a best-practices snippet showing a `stale-session-cleanup` job at `"0 3 * * *"` (3 AM), calling an undefined `cleanupSessions`. This is the one place a different hour appears, so "2 AM" isn't even consistent across the docs.

So if the "2 AM" figure came from reading `doc.go` or the README, it describes a hypothetical job in an illustration, not a scheduled task memos runs. Related example jobs in the same file are likewise fictional: `health-check` at `*/5 * * * *` and `weekly-backup` at `0 1 * * 0` (`internal/scheduler/example_test.go:109-127`).
