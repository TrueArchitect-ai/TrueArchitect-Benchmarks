**Delivery function — `Post` in `internal/webhook/webhook.go:120`; protection mechanism — `safeDialContext` + `isReservedIP` in `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

### Where delivery executes

`webhook.Post` (`internal/webhook/webhook.go:120`) is the only place the outbound HTTP request is actually made — it marshals the `WebhookRequestPayload` to JSON, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and calls `safeClient.Do(req)` at `webhook.go:152`.

Callers never invoke it directly. The API layer calls `webhook.PostAsync` (`webhook.go:184`), which enqueues onto a buffered channel (`asyncPostQueue`, cap 128, dropping with a warning when full); four goroutines started in `init()` (`webhook.go:42-55`) drain that queue and call `Post`. The enqueue sites are `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

### What protects it

Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests an IP against `reservedNetworks` — the parsed form of `reservedCIDRs` (`validate.go:14-23`): IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` (covering cloud IMDS at 169.254.169.254), plus IPv6 loopback, unique-local, and link-local.

1. **Dial-time enforcement (the real guard).** `safeClient` (`webhook.go:32-37`) is a shared `http.Client` whose `Transport.DialContext` is `safeDialContext` (`webhook.go:59`). On every connection it re-resolves the host and refuses to dial if *any* returned address is reserved. Because this runs at dial time rather than at save time, it also defeats DNS rebinding — the comment at `webhook.go:30-31` states this explicitly.

2. **Admission-time validation.** `webhook.ValidateURL` (`validate.go:62`) is called when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`). It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument`. This is UX-level rejection only; layer 1 is what makes it sound.

**Escape hatch:** the package-level `webhook.AllowPrivateIPs` flag (`validate.go:41`) short-circuits `isReservedIP` to `false`, disabling *both* layers, for self-hosted deployments targeting LAN services. Worth noting: nothing in the non-test source wires this flag to a CLI flag, env var, or config field — grep finds writes only inside `internal/webhook`, so it is currently reachable only from tests.
