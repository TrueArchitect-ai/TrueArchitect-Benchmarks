**Mechanism: explicit Go code** — reactions are deleted by hand-written `DELETE FROM reaction` statements inside the `DeleteUser` transaction of each store driver. There is no database-level cascade for them.

## What the Go code does

`store/db/sqlite/user_delete.go` (and identical logic in the postgres/mysql drivers) runs two separate reaction deletes inside `deleteUserTargetsTx`:

- `store/db/sqlite/user_delete.go:96` → `deleteReactionsByContentIDsTx` — deletes reactions *on* the deleted user's memos (keyed by memo UID, since `reaction.content_id` stores the memo resource name). Implementation at `store/db/sqlite/user_delete.go:380-383`, batched via `deleteUserBatchSize` (500).
- `store/db/sqlite/user_delete.go:102` → `deleteReactionsByCreatorTx` — deletes reactions *made by* the deleted user on anyone's content: `DELETE FROM reaction WHERE creator_id = ?` at `store/db/sqlite/user_delete.go:400-401`.

Same two calls, same order, in:
- `store/db/postgres/user_delete.go:96,102` (impls at `:380`, `:400`)
- `store/db/mysql/user_delete.go:96,102` (impls at `:417`, `:437`)

Entry point: `store/user.go:171` `(*Store).DeleteUser` → `store/driver.go:48` driver interface → the per-driver implementations above. All deletes run in one transaction (there's a test-only rollback failpoint at `store/user_delete.go:9-27`).

## Why it is *not* database-level

The `reaction` table is declared with no foreign key and no `ON DELETE` clause in any dialect:
- `store/migration/sqlite/LATEST.sql:92-99`
- `store/migration/postgres/LATEST.sql:91-98`
- `store/migration/mysql/LATEST.sql:91-98`

Grepping all three `LATEST.sql` files, the only `FOREIGN KEY` / `ON DELETE` in the whole schema is `memo_share.memo_id → memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`, postgres `:108`, mysql `:108`). No `CREATE TRIGGER` exists in any current schema either — FK/trigger machinery was stripped out historically (`store/migration/sqlite/0.7/00__remove_fk.sql`, `store/migration/sqlite/0.7/01__remove_triggers.sql`).

## Test confirmation

`server/router/api/v1/test/user_service_delete_test.go` seeds four reactions (`:188-209`) and asserts after deletion that reactions on the user's own memo and on their comment are gone (`:287-293`), while a third party's reaction on a foreign memo survives (`:295-298`). The rollback test confirms a reaction is still present when the transaction aborts (`:366-369`, `:429-431`) — which is only meaningful because the delete is transactional Go code, not a DB cascade.
