**Convergence function — `webhook.Post`, `internal/webhook/webhook.go:120`**

All four `Dispatch*Webhook` functions (`server/router/api/v1/memo_service_webhooks.go:15-46`) do the same thing: load the memo owner's webhooks via `s.Store.GetUserWebhooks` (`store/user_setting.go:312`), set `payload.URL = hook.Url`, and call `webhook.PostAsync` (`internal/webhook/webhook.go:184`). `PostAsync` only enqueues onto `asyncPostQueue`; the four worker goroutines started in `init` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, which is the single place the outbound request is built and issued (`safeClient.Do(req)` at `internal/webhook/webhook.go:152`).

Notes on the URL being user-controlled and the guardrails already in place:
- The URL originates from `CreateUserWebhook` / `UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53`, `:106`), stored as a user setting.
- Write-time validation is `webhook.ValidateURL` (`internal/webhook/validate.go:61`).
- Dial-time SSRF defense is `safeDialContext` (`internal/webhook/webhook.go:59`), wired into `safeClient`'s transport; it re-resolves the host and rejects reserved/private IPs, which also covers DNS rebinding between validation and dispatch.

If you're picking one choke point to instrument or harden, `Post` is it — every handler above reaches the network only through it.
