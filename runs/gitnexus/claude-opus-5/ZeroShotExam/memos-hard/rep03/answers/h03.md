**`internal/idp`; `internal/idp/oauth2`**

**The abstraction package — `internal/idp`** (`internal/idp/idp.go`)
It defines the single provider-neutral type all SSO paths converge on:

```go
type IdentityProviderUserInfo struct {
    Identifier, DisplayName, Email, AvatarURL string
}
```

This is a deliberately thin abstraction — a normalized user-info struct rather than a Go interface. There is no `IdentityProvider` interface in the package; the polymorphism lives in the protobuf type enum instead (`proto/store/idp.proto`), where `IdentityProvider.Type` and the `IdentityProviderConfig` oneof are the extension points.

**The concrete implementation — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`)
Package doc: "implements the OAuth2 identity provider integration." It provides `NewIdentityProvider(*storepb.OAuth2Config)`, `ExchangeToken` (authorization-code exchange with optional PKCE `code_verifier`), and `UserInfo`, which fetches the userinfo endpoint and maps arbitrary claims onto `idp.IdentityProviderUserInfo` via the configurable `FieldMapping`.

**It is the only implementation that ships.** Both the proto enum and the dispatch site confirm this:

- `proto/store/idp.proto` — `enum Type { TYPE_UNSPECIFIED = 0; OAUTH2 = 1; }`, and the config oneof has exactly one arm, `OAuth2Config oauth2_config = 1`. No OIDC or SAML variant exists.
- `server/router/api/v1/auth_service_sso.go:104` — `resolveSSOIdentity` branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` and constructs `oauth2.NewIdentityProvider(...)`. There is no `else`, so any other type would fall through with `userInfo` nil.

One thing worth flagging since you're looking at this path: because that `if` has no fallback, a stored provider row with an unexpected type reaches the `identifierFilter` block at `auth_service_sso.go:137` with `userInfo == nil` and nil-derefs on `userInfo.Identifier`. Today the proto admits only `OAUTH2`, so it isn't reachable in practice — but it's the failure mode to fix when a second provider type is added.

`internal/idp/oauth2/oauth2_test.go` is the only test file under the tree, which matches the single-implementation picture.
