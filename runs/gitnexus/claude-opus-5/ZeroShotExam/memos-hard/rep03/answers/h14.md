**Answer: `RebuildMemoPayload` → `markdown.Service.ExtractAll`; triggered on memo create and on content-updating updates (plus a batch backfill); extracts tags + the five calculated `Property` fields.**

## Computation site

- `server/runner/memopayload/runner.go:74` — `RebuildMemoPayload(ctx, memo, markdownService)` lazily initializes `memo.Payload`, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`runner.go:80-86`).
- The actual extraction is a single goldmark AST walk in `internal/markdown/markdown.go:356` (`service.ExtractAll`). `service.ExtractProperties` (`markdown.go:193`) is the same property logic standalone, but the payload path uses `ExtractAll` for the one-pass version.

## Triggers

1. **CreateMemo** — `server/router/api/v1/memo_service.go:108`, before `Store.CreateMemo` (user-set fields like `Location` are applied after, at `:111-113`).
2. **UpdateMemo** — `server/router/api/v1/memo_service.go:447`, only inside the `path == "content"` branch of the update mask; the rebuilt payload is written via `update.Payload = memo.Payload` (`:451`). Other mask paths (visibility, pinned, state, timestamps) do not recompute it.
3. **Batch rebuild** — `Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) pages all memos in batches of 100 and rebuilds + persists each payload. Note: this runner is not currently wired into startup — `server/server.go:163` only starts the `s3presign` runner, and no code outside the `memopayload` package constructs `NewRunner`. So in practice recomputation happens only on create and content update.

## What it extracts

Into `MemoPayload.Property` (proto: `proto/store/memo.proto:15-22`, comment "The calculated properties from the memo content"):

- `title` — text of the first H1 heading, only if it is the document's first block child (`markdown.go:376-382`)
- `has_link` — any `KindLink` node
- `has_code` — `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`
- `has_task_list` — any GFM `TaskCheckBox`
- `has_incomplete_tasks` — any task checkbox with `IsChecked == false`

The same pass also fills `MemoPayload.Tags` (deduped `#tags`, case preserved, ignoring tags inside links/images — `markdown.go:120-135`) and returns `Mentions`, which the payload rebuild discards (mentions are consumed separately at `server/router/api/v1/memo_mention_helpers.go:32`).

Consumers: `convertMemoPropertyFromStore` (`memo_service_converter.go:315`) exposes it on the API `Memo.property` for list rendering, and user stats aggregate it at `server/router/api/v1/user_service_stats.go:141-151,257-267`. The list `snippet` field is *not* part of this payload — it is computed per-response from content at `memo_service_converter.go:76` via `GenerateSnippet`.
