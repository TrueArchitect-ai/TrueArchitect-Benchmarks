**`s3presign.Runner` (`server/runner/s3presign/runner.go`) — every 12 hours, plus one immediate synchronous pass at startup — wired in `server/server.go:162-171` (started from `startBackgroundRunners`, itself called at `server/server.go:129`).**

Details:

- **What it does** — `CheckAndPresign` (`server/runner/s3presign/runner.go:47`) pages through all attachments with storage type `S3` in batches of 100 (`store.ListAttachments` with `GetBlob: false`), and for each one regenerates a presigned GET URL via `s3.Client.PresignGetObject` (`internal/storage/s3/s3.go:70`). It writes the new URL back as the attachment's `Reference` and stamps `LastPresignedTime` in the payload (`runner.go:114-123`). Presigned URLs are minted with a 5-day expiry, so an attachment is skipped if its last presign is still valid for at least the next 4 days (`runner.go:85-91`) — that 1-day margin is what keeps links from ever going stale between ticks.
- **Schedule** — `runnerInterval = time.Hour * 12` (`runner.go:27`), driven by a `time.Ticker` in `Run` (`runner.go:29-41`), which exits on context cancellation.
- **Wiring** — `Server.startBackgroundRunners` (`server/server.go:153`) constructs the runner with `s3presign.NewRunner(s.Store)` (`server/server.go:162`), calls `RunOnce(ctx)` inline so a refresh happens immediately at boot (`server/server.go:163`), then launches `Run(s3Context)` in a tracked goroutine (`server/server.go:166-171`). The cancel func is registered at `server/server.go:159` so `Shutdown` → `stopBackgroundRunners`/`waitBackgroundRunners` (`server/server.go:140`, `143`) can stop and drain it. Import at `server/server.go:25`.

One caveat worth flagging: the startup `RunOnce` at `server/server.go:163` runs on the parent `ctx`, not the cancellable `s3Context`, so it isn't interrupted by `stopBackgroundRunners`.
