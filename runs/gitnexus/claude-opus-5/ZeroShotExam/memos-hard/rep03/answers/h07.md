Notes on the data layer:
- The stored data is **not** a file on disk or in S3 — the avatar lives in the `user.avatar_url` column as a `data:<mime>;base64,...` URI (`dataURIRegex`, server/router/fileserver/fileserver.go:98). The attachment/S3/thumbnail machinery in the same file is not on this path.
- `Store.GetUser` only hits `userCache` when the lookup is by ID; the avatar path looks up by `Username`, so it always falls through to `ListUsers` → driver → SQL (store/user.go:148-158).
- Service wiring: `fileserver.NewFileServerService(...)` + `RegisterRoutes` at server/server.go:81-82.
- Authorization for *another* user's avatar: there is no per-user check — any resolvable username's avatar is served, gated only by the instance-level anonymous check above.
