**Premise correction:** Neither. There is no message broker in this repository at all — `go.mod`/`go.sum` contain no NATS, AMQP/RabbitMQ, Kafka, Redis, or task-queue dependency (grep for `nats|amqp|rabbit|kafka|pulsar|asynq|redis` returns nothing). There are also no "webhook delivery workers" as a separate service or process.

**Actual mechanism:** webhook delivery is an in-process Go channel with a fixed pool of goroutines, all inside a single binary.

- **Queue declaration** — `internal/webhook/webhook.go:39`: a buffered Go channel, `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`.
- **Workers** — `internal/webhook/webhook.go:42-55`: a package `init()` starts 4 goroutines, each ranging over `asyncPostQueue` and calling `Post(payload)`; failures are only logged via `slog.Warn` (no retry, no dead-letter).
- **Producer** — `PostAsync` (`internal/webhook/webhook.go:184-196`) does a non-blocking `select` send; when the 128-slot buffer is full the payload is **dropped** with a warning. Because the queue lives in memory, anything still enqueued is lost on restart.
- **Delivery** — `Post` (`internal/webhook/webhook.go:120`) POSTs JSON over `safeClient`, an `http.Client` with a 30s timeout and an SSRF-guarding `DialContext` (`safeDialContext`, line 59) that rejects reserved/private IPs. Optional Standard-Webhooks HMAC-SHA256 signing sets `webhook-id` / `webhook-timestamp` / `webhook-signature`.
- **Call sites** — `server/router/api/v1/memo_service_webhooks.go:43` and `:71` enqueue per user-registered webhook (`s.Store.GetUserWebhooks`) for `memos.memo.created/updated/deleted` and `memos.memo.comment.created`.
