**Premise correction: there is no nightly database-cleanup job in this repo's cron scheduler.** The scheduler package exists, but nothing in the application ever registers a job with it — the only "daily-cleanup at 2 AM" is documentation/test example text.

What's actually there:

- `internal/scheduler/` is a self-contained, GitHub-Actions-inspired cron library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). `Scheduler.Register` is at `internal/scheduler/scheduler.go:70`.
- No production code calls `scheduler.New()` or `.Register(...)`. Every reference to the package outside `internal/scheduler/` is zero — the only callers are its own tests. So no job of any kind is scheduled through it, cleanup or otherwise.
- The `"0 2 * * *"` ("2 AM daily") value that looks like an answer appears only as illustrative sample code: `internal/scheduler/doc.go:15-17`, the Quick Start block in `internal/scheduler/README.md`, and `internal/scheduler/example_test.go:99-100`. Those are docs/examples, not a wired-up job.

The background work that *is* actually wired up doesn't use cron at all — it uses tickers:

- `server/runner/s3presign/runner.go:26` — S3 presign refresh, `runnerInterval = time.Hour * 12` (every 12 hours, plus one `RunOnce` at startup), started in `server/server.go:153-171`.
- `store/cache/cache.go:46-60,199-218` — in-memory cache expiry sweep, `CleanupInterval` defaulting to 5 minutes (`store/store.go:42`). This is cache eviction, not database cleanup.

There is also no cron entry in Docker/deployment config for a DB cleanup; the only cron-scheduled thing in the repo is the GitHub stale-issue workflow (`.github/workflows/stale.yml`), which is CI, not the app's scheduler.
