**1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages)**

The data layer is the `store` package (`/bench/home/work/store/`), which defines the persistent entity types: `Attachment`, `IdentityProvider`, `Inbox`, `InstanceSetting`, `Memo` (`store/memo.go:35`), `MemoRelation`, `MemoShare`, `Reaction`, `User` (`store/user.go:29`), `UserIdentity`, `UserSetting`.

Counting distinct Go packages outside the `store/...` tree (so excluding the driver packages `store/db/{sqlite,postgres,mysql}` and `store/test`, which are part of the layer itself):

| Type | External packages | Where |
|---|---|---|
| `User` | **7** | `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss` |
| `Memo` | **6** | `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload` |
| `Attachment` | 4 | `server/router/api/v1` (+ its `test`), `server/router/fileserver`, `server/router/rss` |
| `MemoShare` / `MemoRelation` / `Inbox` | 3 each | — |
| `Reaction`, `UserIdentity` | 2 each | — |
| `IdentityProvider`, `InstanceSetting`, `UserSetting` | 1 (`proto/gen/store` only, for their payload protos) | — |

Notes on the ranking:

- `User` edges out `Memo` because it is the only entity reaching `server/auth` (`server/auth/auth.go` and friends) and `server/router/fileserver`, in addition to the API, RSS, frontend, and notification packages.
- `Memo` is unique to `server/runner/memopayload`, which rebuilds memo payloads.
- If you rank by raw reference count instead of package count, the order flips: `store.Memo` has ~150 references outside `store/` vs. ~119 for `store.User`. By the asked metric (breadth of packages), `User` is first.
