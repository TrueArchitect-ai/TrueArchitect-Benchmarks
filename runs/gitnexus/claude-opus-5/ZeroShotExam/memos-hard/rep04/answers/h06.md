### Convergence

`webhook.PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto the bounded `asyncPostQueue` (drops with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call **`webhook.Post`** (`internal/webhook/webhook.go:120`) — the single function that marshals the payload, builds the `POST` to `requestPayload.URL`, attaches the Standard Webhooks HMAC headers, and issues the actual request via `safeClient.Do` (`internal/webhook/webhook.go:152`).

If you want the last synchronous point inside the RPC call itself, that's `PostAsync`; the outbound HTTP request is only ever issued from `Post`.

SSRF at that convergence point is guarded two ways: `webhook.ValidateURL` at configuration time (`user_service_webhooks.go:74,161,182`) and `safeDialContext` (`internal/webhook/webhook.go:59`), which re-resolves the host at dial time and rejects reserved/private IPs, defeating DNS rebinding.

Two other outbound-HTTP paths exist but do **not** converge on `webhook.Post`: `internal/httpgetter/html_meta.go` (link-preview fetch of a caller-supplied URL) and `internal/idp/oauth2/oauth2.go:84-91` (fetch of an admin-configured identity-provider `UserInfoUrl`).
