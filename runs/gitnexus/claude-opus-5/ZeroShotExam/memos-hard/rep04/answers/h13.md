## Concrete implementation

Exactly **one**: the unexported `service` struct (`internal/markdown/markdown.go:58-60`), wrapping a `goldmark.Markdown`. There are no mocks, fakes, or alternate impls anywhere in the tree — tests use the real one. Behavior varies only by construction options, not by type:

- `markdown.NewService(opts...)` (`internal/markdown/markdown.go:85-113`) always enables `extension.GFM`; `WithTagExtension()` / `WithMentionExtension()` conditionally add `extensions.TagExtension` and `extensions.MentionExtension` (`internal/markdown/extensions/tag.go`, `mention.go`).
- `RenderMarkdown` and `RenameTag` delegate AST→markdown output to `renderer.NewMarkdownRenderer()` (`internal/markdown/renderer/markdown_renderer.go`), constructed per call at `markdown.go:250` and `markdown.go:451`.

## Construction at runtime

A **single instance**, created inside `NewAPIV1Service` (`server/router/api/v1/v1.go:47-62`) with both tag and mention extensions enabled. `server/server.go:76` builds the API service, then `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService` — so RSS shares the same instance rather than making its own.

Test-only constructions: `server/router/api/v1/test/test_helper.go:44` (tags + mentions), `server/router/fileserver/fileserver_test.go:427` (tags only), `server/router/rss/rss_test.go:54` (bare `NewService()` — no tag/mention extensions).
