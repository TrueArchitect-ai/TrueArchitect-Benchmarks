**Premise correction:** There is no Redis in this repository. A case-insensitive grep for `redis` across the entire repo (excluding `.git`/`node_modules`) returns zero hits — no client dependency in `go.mod`, no connection string, no config key, no docker-compose service. There is no external cache server of any kind; caching is entirely in-process.

**Actual mechanism**

The cache layer is a hand-rolled, thread-safe in-memory cache in `store/cache/cache.go`:
- `Cache` struct (`store/cache/cache.go:67`) backed by a `sync.Map` plus an atomic item counter.
- Each entry (`item`, `store/cache/cache.go:35`) stores an absolute `expiration` timestamp set at write time (`store/cache/cache.go:112`). Expiry is enforced both lazily on `Get` (`store/cache/cache.go:135`) and by a background `cleanupLoop` goroutine (`store/cache/cache.go:200`).
- Overflow eviction: when `MaxItems` is exceeded, `cleanupOldest` drops ~20% of the cap (`store/cache/cache.go:253`).

**Where it's "configured":** in `store.New` (`store/store.go:38-61`), not in any config file or env var — the values are hardcoded literals:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

That single config is shared by three independent cache instances (`store/store.go:51-53`): `instanceSettingCache`, `userCache`, and `userSettingCache`. All are closed in `Store.Close` (`store/store.go:72`).

**TTL for user entries:** **10 minutes**, with a 1000-item cap per cache. `userCache` is written via `Set` (not `SetWithTTL`) at `store/user.go:98, 122, 132, 143, 167`, so it always takes `DefaultTTL`. In fact `SetWithTTL` has no non-test callers anywhere in the codebase — every cached entry, user or otherwise, uses the same 10-minute TTL. Keys are the plain user ID (`userCacheKey`, `store/user.go:88`); `GetUser` only hits the cache when looking up by ID (`store/user.go:150`), and staleness is mitigated by write-through on create/update (`store/user.go:98/132`) and explicit invalidation in `deleteUserCache` (`store/user.go:179`).

Two unrelated caches also exist and are separate from this layer: an RSS feed cache with its own `cacheEntry`/`cacheMutex` in `server/router/rss/rss.go`, and a frontend draft cache in `web/src/components/MemoEditor/services/cacheService.ts`.
