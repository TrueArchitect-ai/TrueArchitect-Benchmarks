**Computation site.** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74` is the single place the derived payload is (re)built. It delegates the actual extraction to the goldmark-backed markdown service: `(*service).ExtractAll` in `internal/markdown/markdown.go:356` (interface declared at `internal/markdown/markdown.go:33`), then assigns `memo.Payload.Tags` and `memo.Payload.Property` (`runner.go:85-86`). `ExtractAll` does one parse + one AST walk for efficiency; `ExtractTags` (`markdown.go:143`) and `ExtractProperties` (`markdown.go:193`) are the equivalent single-purpose variants.

**Triggers (recomputation).**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before the store write.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only when `content` is in the update mask; the result is written via `update.Payload = memo.Payload`.
- Batch backfill: `Runner.RunOnce` in `server/runner/memopayload/runner.go:27` rebuilds every memo in batches of 100 and persists via `Store.UpdateMemo`. Note this runner is not currently wired into startup — `server/server.go` only calls `s3presignRunner.RunOnce`; only the exported `RebuildMemoPayload` function is used in the live request paths.

Note the payload is derived from content only — it is not recomputed on visibility/pin/relation updates, and there is no rebuild hook on a content rewrite that bypasses `UpdateMemo`'s content path.

**Extracted properties.** Stored in `MemoPayload` (`proto/store/memo.proto:7-27`), surfaced on the API `Memo` as `property` (`proto/gen/api/v1/memo_service.pb.go:251`, converted by `convertMemoPropertyFromStore` at `server/router/api/v1/memo_service_converter.go:314`):
- `tags` — all `#tag` nodes, skipping tags inside links/images (`asMemoTagNode`, `markdown.go:134`), deduplicated case-preserving (`uniquePreserveCase`, `markdown.go:456`).
- `property.title` — text of the first block-level child if it's an H1 heading (`markdown.go:384-389`, via `extractHeadingText`).
- `property.hasLink` — any `KindLink` node.
- `property.hasCode` — any code block, fenced code block, or code span.
- `property.hasTaskList` — any GFM task checkbox; `property.hasIncompleteTasks` — any unchecked checkbox.

`ExtractAll` also returns `Mentions` (lowercased `@user` nodes), but that field is *not* persisted into the payload — it's consumed separately for mention notifications (`server/router/api/v1/memo_mention_helpers.go:32`).

These fields back list filtering (`property.hasLink` / `hasTaskList` / `hasCode` in `web/src/contexts/MemoFilterContext.tsx:11-13` and `store/test/memo_filter_test.go`). The list *preview text* is a separate derivation: `Snippet` is computed per-request at conversion time via `getMemoContentSnippet` → `GenerateSnippet` (`server/router/api/v1/memo_service_converter.go:76-80`, `internal/markdown/markdown.go:264`) and is never stored in the payload.
