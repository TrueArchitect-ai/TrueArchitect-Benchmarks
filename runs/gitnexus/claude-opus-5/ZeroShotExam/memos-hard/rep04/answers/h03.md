**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider must produce. The protobuf side of the abstraction lives in `proto/proto/store/idp.proto` — `IdentityProvider` with a `Type` enum and an `IdentityProviderConfig` oneof, both designed for multiple provider kinds.

- **Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol shipped. `NewIdentityProvider(*storepb.OAuth2Config)` validates required config, `ExchangeToken` performs the code→token exchange (with optional PKCE `code_verifier`), and `UserInfo` fetches and field-maps the profile into `idp.IdentityProviderUserInfo`.

The dispatch point confirming OAuth2 is the sole implementation is `server/router/api/v1/auth_service_sso.go:120`, where `resolveSSOIdentity` branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` with no other case — matching the proto enum, which has only `TYPE_UNSPECIFIED = 0` and `OAUTH2 = 1`, and the config oneof, which has only `oauth2_config`. Persistence for provider records is in `store/idp.go` with per-dialect implementations under `store/db/{sqlite,mysql,postgres}/idp.go`.
