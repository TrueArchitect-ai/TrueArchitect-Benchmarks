The premise doesn't hold: **there is no nightly database-cleanup job registered anywhere in this codebase.** Nothing schedules one, so it has no run time.

What actually exists:

- `internal/scheduler/` is a standalone, self-contained cron scheduler package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). Nothing outside the package ever imports it — no call to `scheduler.New()` or `Register(...)` exists in `cmd/`, `server/`, or `store/`. It's library code with zero production wiring.
- The `"0 2 * * *"` (2 AM daily) cleanup you may be thinking of appears only in **documentation and example code**, never in a running path:
  - `internal/scheduler/doc.go:15-18` — package doc sample job named `"daily-cleanup"`
  - `internal/scheduler/README.md:34-37` — the same sample in the Quick Start
  - `internal/scheduler/example_test.go:97-100` — `Example_multipleJobs`, a job named `"cleanup"` on `"0 2 * * *"` that just prints "Cleaning up old data..."
  - `internal/scheduler/README.md:241-245` — a `"stale-session-cleanup"` naming-convention example

  None of these touch the database; the handlers are `fmt.Println` / no-ops.

The only real background work in the server is interval-based, not cron-based, and does no cleanup:

- `server/runner/s3presign/runner.go:27-35` — re-signs S3 URLs on a `time.NewTicker` every 12 hours (`runnerInterval = time.Hour * 12`), starting from process boot rather than a wall-clock time.
- `server/runner/memopayload/runner.go` — a one-shot payload rebuild.

If you're after a scheduled DB cleanup, it would need to be written and wired up — the scheduler package is available for that but currently unused.
