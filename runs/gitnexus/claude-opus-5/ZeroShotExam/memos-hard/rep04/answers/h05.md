**Mechanism: explicit Go code** — reactions are deleted by hand-written `DELETE FROM reaction` statements inside the user-delete transaction, in all three DB drivers. There is no database-level rule (no foreign key, no `ON DELETE CASCADE`, no trigger) on the `reaction` table.

**What I checked and found**

1. **Schema — no DB-level rule.** `reaction` is declared with a bare `creator_id INTEGER NOT NULL` and no FK in every dialect:
   - `store/migration/sqlite/LATEST.sql:92-99`
   - `store/migration/postgres/LATEST.sql:91-98`
   - `store/migration/mysql/LATEST.sql:91-98`
   
   Grepping all of `store/migration/` for `reaction` lines containing `FOREIGN`/`REFERENCES`/`CASCADE`/`TRIGGER` returns nothing. The only `ON DELETE CASCADE` in the current schema is `memo_share.memo_id → memo(id)` (`store/migration/sqlite/LATEST.sql:109` and the postgres/mysql equivalents at line 108). The 0.20/0.23 reaction migrations (`store/migration/*/0.20/00__reaction.sql`, `*/0.23/00__reactions.sql`) only create the table and rewrite `reaction_type` values to emoji — they add no constraints.

2. **Go code — two explicit deletes, both wired into the delete transaction.** In `store/db/sqlite/user_delete.go` (mirrored line-for-line in `store/db/postgres/user_delete.go` and `store/db/mysql/user_delete.go`):
   - `deleteReactionsByContentIDsTx` — `DELETE FROM reaction WHERE content_id IN (...)`, batched at 500 (`sqlite/user_delete.go:380-388`; postgres `:383`; mysql `:420`). This removes reactions *on* the deleted user's memos (content IDs are `memos/<uid>`, including comment memos pulled in by the recursive memo tree at `sqlite/user_delete.go:133-147`).
   - `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?` (`sqlite/user_delete.go:400-403`; postgres `:401`; mysql `:438`). This removes reactions the deleted user *left on other people's* memos.
   
   Both are called from `deleteUserTargetsTx` (`store/db/sqlite/user_delete.go:92-127`, calls at lines 96 and 102), which runs inside the single transaction opened by `DB.DeleteUser` (`store/db/sqlite/user_delete.go:29-59`) before the user row itself is deleted.

3. **Call path.** `store.Store.DeleteUser` (`store/user.go:171-172`) → driver `DeleteUser` (`store/driver.go:48`), reached from the API at `server/router/api/v1/user_service.go:393,414` and from SSO cleanup at `server/router/api/v1/auth_service_sso.go:77`.

4. **Test confirms the behavior.** `store/test/user_delete_test.go` seeds three reactions (`:97-114`): one by the peer on the deleted user's memo, one by the deleted user on the peer's memo, and one by the peer on the peer's own memo. After deletion it asserts only the last survives (`:216-220`) — i.e. both the user's own reactions and the reactions on the user's memos are gone.
