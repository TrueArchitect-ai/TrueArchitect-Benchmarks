`Store.DeleteMemo` (`store/memo.go:140-159`) performs this cleanup before calling the driver's `DELETE FROM memo` (`store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go`):

1. **Memo relations where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relations where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments{MemoID: ...}` and deleted one by one with `DeleteAttachment` (`store/memo.go:149-157`), which also removes the underlying stored file/blob (`store/attachment.go:132-149`, via `DeleteAttachmentStorage`)

Only then does it call `s.driver.DeleteMemo(ctx, delete)` for the memo row itself (`store/memo.go:158`).

Two things that happen outside the store layer, for contrast: comment memos are deleted by the API handler, which lists `MemoRelationComment` relations pointing at the memo and calls `Store.DeleteMemo` on each child memo first (`server/router/api/v1/memo_service.go:567-577`); and reactions are only read for the webhook payload (`memo_service.go:545`), not deleted by `Store.DeleteMemo`.
