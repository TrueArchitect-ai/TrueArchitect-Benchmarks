**Runners the server actually starts**

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:153-174`). Driven by a plain `time.Ticker` of 12 h (`runnerInterval = time.Hour * 12`, `runner.go:27-41`), plus one synchronous `RunOnce(ctx)` at startup before the loop goroutine begins (`server/server.go:163`). Each pass re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days, in batches of 100. Stopped via a per-runner `context.CancelFunc` collected in `backgroundRunnerCancels`, waited on with `backgroundRunnerWG` during `Shutdown` (`server/server.go:134-201`).

That is the **only** entry in `startBackgroundRunners` — no other worker is registered there.

**Other long-lived goroutines started implicitly (not via the runner registry)**

- **Store cache janitors ×3** (`store/cache/cache.go:76-85, 199-213`) — `cache.New` unconditionally does `go c.cleanupLoop()`, ticking every `CleanupInterval = 5 min` (`store/store.go:39-53`); three instances (`instanceSettingCache`, `userCache`, `userSettingCache`). Stopped by `Cache.Close()`, reached through `Store.Close()` in `Server.Shutdown`.
- **SSE heartbeat** (`server/router/api/v1/sse_handler.go:63-65`) — a 30 s ticker (`sseHeartbeatInterval`), but per-connection inside the request handler, not a server-wide worker; connections are torn down by `sseHub.Close()` (`server/server.go:203-208`).
- Fire-and-forget one-shot goroutines, event-triggered rather than scheduled: PAT last-used writeback (`server/auth/authenticator.go:178-184`), webhook dispatch (`internal/webhook/webhook.go:44`), email send (`internal/email/email.go:18`), and the signal-handler shutdown goroutine (`cmd/memos/main.go:99`).

**Unused scheduling infrastructure**

- **`internal/scheduler` — a full cron scheduler that the server never uses.** It implements 5/6-field cron parsing, timezone handling, middleware (recovery/logging/timeout), and graceful shutdown (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`, documented in `doc.go` and `README.md`), but `scheduler.New(` appears only in `internal/scheduler/example_test.go` and `integration_test.go` — no production file imports the package. The one real periodic job in the server (s3presign) uses a hand-rolled `time.Ticker` instead of a registered cron job.
- **`server/runner/memopayload` `Runner` is dead as a runner** (`server/runner/memopayload/runner.go:14-72`) — `memopayload.NewRunner` is never called anywhere, so its batch `RunOnce` (rebuild payloads for all memos) never executes. Only the free function `RebuildMemoPayload` is used, inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447`.
