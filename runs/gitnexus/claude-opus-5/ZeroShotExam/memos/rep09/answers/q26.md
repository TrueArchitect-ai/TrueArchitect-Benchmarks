**Tables written by `DeleteMemo`: `memo_relation`, `attachment`, `memo` — plus `memo_share` only via DB-level FK cascade (MySQL/Postgres, not SQLite).**

### The call chain

`APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) does read-only lookups for the webhook payload (reactions, attachments, relations), then:
1. Lists COMMENT relations pointing at the memo and calls `Store.DeleteMemo` for each comment memo (`memo_service.go:567-577`) — recursion into the same three tables.
2. Calls `Store.DeleteMemo` for the memo itself (`memo_service.go:580`).

`Store.DeleteMemo` (`store/memo.go:140-159`) is where the explicit cascade lives:

| Table | How | Code |
|---|---|---|
| `memo_relation` | Two explicit deletes: `MemoID = id` and `RelatedMemoID = id` | `store/memo.go:142-147` → `store/db/sqlite/memo_relation.go:149`, `postgres/memo_relation.go:164`, `mysql/memo_relation.go:137` |
| `attachment` | Lists attachments with `MemoID = id`, deletes each via `Store.DeleteAttachment` (which also removes the blob/local file) | `store/memo.go:149-157`, `store/attachment.go:132-149` → `sqlite/attachment.go:212`, `postgres/attachment.go:212`, `mysql/attachment.go:231` |
| `memo` | The row itself, last | `store/memo.go:158` → `sqlite/memo.go:237`, `postgres/memo.go:246`, `mysql/memo.go:261` |

### `memo_share` — driver-dependent

`memo_share` has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in all three schemas (`store/migration/sqlite/LATEST.sql:109`, `postgres/LATEST.sql:108`, `mysql/LATEST.sql:108`). There is no Go-side deletion of shares in the memo-delete path. On SQLite the connection is opened with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so the cascade does **not** fire there and share rows are orphaned; on Postgres/MySQL it does.

### Not touched

- `reaction` — `APIV1Service.DeleteMemo` only *reads* reactions for the webhook payload (`memo_service.go:545-550`). The table keys on a string `content_id` with no FK (`LATEST.sql:92-99`), so reaction rows for a deleted memo are left behind on every driver.
- `inbox` — memo-mention notifications are never cleaned up on delete.
