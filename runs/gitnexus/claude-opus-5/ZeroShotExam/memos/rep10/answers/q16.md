`Store.DeleteMemo` (`store/memo.go:140-159`) performs this cleanup before calling `s.driver.DeleteMemo`:

1. **Memo relations where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relations where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments{MemoID: &delete.ID}` and deleted one by one with `DeleteAttachment` (`store/memo.go:149-157`), which also removes the underlying stored file/blob via `DeleteAttachmentStorage` (`store/attachment.go:132-148`)

Then the memo row itself: `s.driver.DeleteMemo(ctx, delete)` (`store/memo.go:158`).

Note on the layer above: the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-582`) first deletes the memo's **comment memos** (child memos found via `MemoRelationComment` relations, `memo_service.go:567-577`), each of which recursively runs the same store-level cleanup, before deleting the target memo. Reactions are only *read* there (for the webhook payload) — the store's `DeleteMemo` does not delete reaction rows.
