**Answer: Go `embed` (`//go:embed dist/*`) compiled into the server binary and served by an Echo static-file middleware with SPA fallback; `server/router/frontend/frontend.go`**

How the pieces fit together:

1. **Build step** — `web/package.json:11` defines `"release": "vite build --mode release --outDir=../server/router/frontend/dist --emptyOutDir"`, so the compiled React bundle lands directly in `server/router/frontend/dist`. CI runs this before compiling Go (`.github/workflows/release.yml:99-108`).

2. **Embedding** — `server/router/frontend/frontend.go:20-21`:
   ```go
   //go:embed dist/*
   var embeddedFiles embed.FS
   ```
   The whole `dist` tree is baked into the binary at compile time; `getFileSystem("dist")` (`frontend.go:115-121`) does `fs.Sub` to get the sub-filesystem rooted at `dist`.

3. **Serving** — `FrontendService.Serve` (`frontend.go:41-61`) registers `middleware.StaticWithConfig` over that embedded FS, plus `spaFallbackMiddleware` (`frontend.go:63-80`) which catches 404s on extension-less paths and returns `index.html` so client-side routing works. A skipper (`frontend.go:82-90`) excludes `/api`, `/file`, gRPC paths (`/memos.api.v1.*`), `robots.txt`, `sitemap.xml`, and `rss.xml`. Cache headers are set per asset type (`frontend.go:92-105`): no-cache for HTML, `max-age=3600, immutable` for hashed `/assets/`.

4. **Wiring into the server** — `server/server.go:72`: `frontend.NewFrontendService(profile, store).Serve(ctx, echoServer)`.

Net effect: production ships a single self-contained Go binary — no separate web server or static-file directory needed.
