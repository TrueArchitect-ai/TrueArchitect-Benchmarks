**Runners the server actually starts** (`server/server.go:153` `startBackgroundRunners`, called from `Server.Start` at `server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — **fixed-interval `time.Ticker`, every 12 hours** (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27`, loop at `:29-41`). It also does one immediate synchronous `RunOnce(ctx)` at startup (`server/server.go:163`) before the goroutine loop begins, so the first pass happens at boot, not 12h later. Work: re-presigns S3 attachment URLs whose presign is within 4 days of its 5-day expiry (`s3presign/runner.go:85-91`). Shutdown is via a dedicated `context.CancelFunc` stored in `Server.backgroundRunnerCancels` (`server/server.go:156-159`, cancelled in `stopBackgroundRunners`, awaited in `waitBackgroundRunners`). Note the startup `RunOnce` is passed the parent `ctx`, not the cancellable `s3Context`.

- **store cache cleanup loops ×3** (`store/cache/cache.go:83` `go c.cleanupLoop()`) — **fixed-interval `time.Ticker`, every 5 minutes** (`CleanupInterval: 5 * time.Minute`, `store/store.go:42`; ticker at `store/cache/cache.go:201`). These aren't registered as "background runners" — they start implicitly inside `cache.New` when `store.New` builds `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`), and stop when `Store.Close()` runs during shutdown.

That's the complete set of long-lived server-owned loops. The only other tickers are per-request/per-connection, not workers: the SSE heartbeat ticker lives inside each SSE handler invocation (`server/router/api/v1/sse_handler.go:64`, 30s). `internal/email` and `internal/webhook` spawn fire-and-forget goroutines per event, not scheduled workers.

**Unused scheduling infrastructure:**

- **`internal/scheduler/` is entirely unused by the server.** It's a full cron implementation — expression parser (`internal/scheduler/parser.go`), job registry and run loop (`internal/scheduler/scheduler.go`), middleware chain (`internal/scheduler/middleware.go`), plus README and docs. Grepping every non-test Go file, the only importers of `github.com/usememos/memos/internal/scheduler` are its own `example_test.go:10` and `integration_test.go:13`. Nothing in `cmd/memos/main.go` or `server/` registers a job or calls `Scheduler.Start`. The one real periodic job (s3presign) uses a hand-rolled `time.Ticker` instead.

- **`server/runner/memopayload`** (`server/runner/memopayload/runner.go`) lives under `server/runner/` alongside s3presign, but its `Runner`/`RunOnce` backfill is never started or constructed — `NewRunner` has no callers. Only the standalone `RebuildMemoPayload` function is used, called inline on the request path from `server/router/api/v1/memo_service.go:108` and `:447`. So the memopayload *runner* is dead scheduling-adjacent code; the payload rebuild itself is request-triggered, not scheduled.
