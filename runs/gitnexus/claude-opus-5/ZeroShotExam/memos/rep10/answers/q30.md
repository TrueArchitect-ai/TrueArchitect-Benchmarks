**Convergence for delivery:**

1. The three lifecycle dispatchers (created/updated/deleted) are one-line wrappers over the shared helper `APIV1Service.dispatchMemoRelatedWebhook(ctx, memo, activityType)` — `server/router/api/v1/memo_service_webhooks.go:48`. It resolves the memo creator, loads that user's webhooks via `s.Store.GetUserWebhooks`, builds the payload with `convertMemoToWebhookPayload`, and stamps `ActivityType`/`URL`/`SigningSecret`.

3. Four worker goroutines started in `internal/webhook/webhook.go:42` (`init`) drain the queue and call `webhook.Post` — `internal/webhook/webhook.go:120` — the actual HTTP delivery: JSON marshal, optional HMAC-SHA256 signing headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), POST via the SSRF-guarded `safeClient`, then status/response-code validation.
