**Frontend interceptor — `web/src/connect.ts:156`**
- `authInterceptor` is registered on the Connect-RPC transport at `web/src/connect.ts:184-189`; every service client (memo, user, attachment, AI, shortcut, IdP, instance, auth) is created from that transport, so all API calls flow through it.
- Per request it calls `getRequestToken()` (`connect.ts:124`) and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, line 97).
- Reactive path: on a `Code.Unauthenticated` error it refreshes once, marks the retry with an `X-Retry` header to prevent loops, and on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- Proactive path: `getRequestToken` pre-refreshes when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s), and `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes on tab focus (2 min buffer). Concurrent refreshes are deduped by `tokenRefreshManager` (`connect.ts:30-51`), and the refresh call goes over a separate interceptor-free transport (`connect.ts:65`) to avoid recursion.

**Tokens it manages**
- **Access token** — short-lived JWT held in memory + `localStorage` (`memos_access_token` / `memos_token_expires_at`), managed in `web/src/auth-state.ts`; shared across tabs via a `BroadcastChannel` (`memos_token_sync`).
- **Refresh token** — never touched by JS: it's an HttpOnly cookie (`memos_refresh`), which is why the transport uses `fetch` with `credentials: "include"` (`connect.ts:57-62`) and calls `AuthService.RefreshToken`.

**Backend validation — `server/auth/`**
- `server/auth/token.go` — JWT generation/parsing: `ParseAccessTokenV2` (audience `user.access-token`, 15 min), `ParseRefreshToken` (audience `user.refresh-token`, 30 days), HS256 with `kid: v1`, plus PAT hashing (`memos_pat_` prefix, SHA-256).
- `server/auth/authenticator.go` — `Authenticator.Authenticate` / `AuthenticateToUser`: bearer token → access token V2 (stateless) or PAT (DB lookup), falling back to the refresh cookie; `AuthenticateByRefreshToken` additionally checks the DB for revocation/expiry.
- `server/auth/extract.go` — `ExtractBearerToken`, `ExtractRefreshTokenFromCookie`.
- Wired in at `server/router/api/v1/authz.go:36` (gRPC/Connect authz interceptor, with `connect_interceptors.go` and `acl_config.go` defining public methods), plus `server/router/api/v1/sse_handler.go` and `server/router/fileserver/fileserver.go`.
