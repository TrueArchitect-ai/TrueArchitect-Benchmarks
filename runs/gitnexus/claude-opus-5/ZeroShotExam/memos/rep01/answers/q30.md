**Convergence for delivery**

The three lifecycle events (created/updated/deleted) are one-line wrappers over the shared helper `APIV1Service.dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks via `Store.GetUserWebhooks`, builds a payload with `convertMemoToWebhookPayload`, and calls `webhook.PostAsync`.

The comment variant does *not* go through `dispatchMemoRelatedWebhook` — it resolves the *related memo owner's* webhooks itself (`memo_service_webhooks.go:31`) — but it also ends at `webhook.PostAsync`.

So the true common delivery point for all four is:

- `webhook.PostAsync` — `internal/webhook/webhook.go:184` — enqueues onto the buffered `asyncPostQueue` (cap 128, dropped with a warning if full)
- drained by 4 worker goroutines started in `init()` at `internal/webhook/webhook.go:42-55`, each calling `webhook.Post` — `internal/webhook/webhook.go:120` — which does the actual HTTP POST (Standard Webhooks HMAC-SHA256 signing, SSRF-guarded `safeClient`).
