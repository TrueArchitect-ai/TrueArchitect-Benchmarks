**Runners the server actually starts** (`Server.startBackgroundRunners`, `server/server.go:148-172` — this is the *entire* registry, exactly one runner):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — two triggers: a synchronous `RunOnce(ctx)` at startup (`server/server.go:158`), then a goroutine looping on a fixed `time.NewTicker(12 * time.Hour)` (`runnerInterval`, `runner.go:27-40`). Each tick re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days. Stopped by its own `context.CancelFunc` registered in `backgroundRunnerCancels`, awaited via `backgroundRunnerWG` on shutdown.

**Other long-lived goroutines that exist but are not part of the runner registry** (for completeness — none are scheduled by the server):

- **Cache cleanup loops ×3** (`store/cache/cache.go:82` `go c.cleanupLoop()`) — started by `cache.New` inside `store.New` (`store/store.go:51-53`), i.e. by `cmd/memos/main.go:64` before the server exists. Driven by `time.NewTicker(CleanupInterval)` = 5 minutes (`store/store.go:40-44`). Shut down via `Store.Close()` (`store/store.go:72-79`).
- **Webhook dispatch pool, 4 goroutines** (`internal/webhook/webhook.go:41-53`) — started in `init()`, driven by the `asyncPostQueue` channel. Event-driven, not scheduled; never shut down.
- **Email dispatch pool, 2 goroutines** (`internal/email/email.go:16-34`) — same pattern, `asyncEmailQueue` channel.
- **SSE heartbeat** (`server/router/api/v1/sse_handler.go:64`) — a 30 s ticker created *per connected client* inside the request handler, not a background worker.
- **PAT last-used write** (`server/auth/authenticator.go:180`) — a fire-and-forget goroutine per authenticated request.

**Unused scheduling infrastructure — two pieces:**

- **`internal/scheduler/`** is a complete, documented cron scheduler (5/6-field cron expression parser, timezone support, middleware chain with `Recovery()`/`Logging()`, graceful `Stop`) — `internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `doc.go`. **Nothing in production imports it**: the only references outside the package are its own `example_test.go:10` and `integration_test.go:13`. The one real periodic job in the server (s3presign) uses a hand-rolled `time.Ticker` instead.
- **`memopayload.Runner`** (`server/runner/memopayload/runner.go`) — lives under `server/runner/` alongside s3presign and has a batched `RunOnce` that rebuilds every memo's tags/properties, but `memopayload.NewRunner` is **never called**. `server/router/api/v1/memo_service.go` imports the package only for the package-level `RebuildMemoPayload` helper, invoked inline on memo create (`memo_service.go:108`) and update (`memo_service.go:447`). So there is no scheduled or startup memo-payload rebuild; the `Runner` type is dead code.
