**Background workers the server actually starts**

- **s3presign runner (`server/runner/s3presign/runner.go`)** — started in `Server.startBackgroundRunners` (`server/server.go:153-174`). Trigger: one immediate synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a `time.NewTicker` loop on `runnerInterval = 12h` (`server/runner/s3presign/runner.go:27-41`). It's the only entry in `backgroundRunnerCancels`/`backgroundRunnerWG`, cancelled via `stopBackgroundRunners` and awaited in `waitBackgroundRunners` on shutdown (`server/server.go:176-201`).
- **3 × store cache janitors (`store/cache/cache.go:83`)** — `cache.New` unconditionally spawns `cleanupLoop()`; `store.New` creates three caches (`instanceSettingCache`, `userCache`, `userSettingCache`, `store/store.go:51-53`). Trigger: `time.NewTicker(CleanupInterval)` = 5 minutes (`store/store.go:40-45`, `store/cache/cache.go:201`). Stopped by `Store.Close()` (`store/store.go:72-79`), which the server calls at the end of `Shutdown`. These are started implicitly by store construction in `cmd/memos/main.go`, not by `startBackgroundRunners`.
- **HTTP serve goroutine (`server/server.go:124-128`)** — not a scheduled job; driven by incoming connections.

Not periodic workers (per-request/per-connection goroutines, listed only to be explicit): the SSE heartbeat ticker lives inside each SSE request handler (`server/router/api/v1/sse_handler.go:64`), and PAT last-used updates (`server/auth/authenticator.go:180`), webhook dispatch (`internal/webhook/webhook.go:44`), and email sending (`internal/email/email.go:18`) are fire-and-forget goroutines per event.

**Unused scheduling infrastructure**

- **`internal/scheduler/` is entirely unused by the server.** It's a full cron implementation (`scheduler.go` with `Register`/`Start`/`Stop`, `parser.go` with 5- and 6-field `ParseCronExpression`, `job.go`, `middleware.go`, plus a README and doc.go), but the only importers in the repo are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). No production code imports it; the one real periodic job (s3presign) uses a hand-rolled `time.Ticker` instead.
- **`server/runner/memopayload`'s runner shell is also unused as a runner.** `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19-72`) have no callers; only the plain helper `RebuildMemoPayload` is used, inline from request paths in `server/router/api/v1/memo_service.go:108` and `:447`. So the memopayload backfill never runs in the background.
