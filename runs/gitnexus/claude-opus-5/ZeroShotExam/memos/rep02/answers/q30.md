**Convergence for delivery:**

The three core lifecycle events (created/updated/deleted) are one-line wrappers that converge on the unexported helper `(*APIV1Service).dispatchMemoRelatedWebhook(ctx, memo, activityType)` — `server/router/api/v1/memo_service_webhooks.go:48`. It resolves the memo creator, loads their webhooks via `s.Store.GetUserWebhooks`, builds a payload per hook with `convertMemoToWebhookPayload`, and stamps the `ActivityType`, URL, and signing secret.

`DispatchMemoCommentCreatedWebhook` does *not* go through that helper — it takes the *related* memo's creator ID directly rather than resolving the comment memo's own creator, so it inlines the same loop (`memo_service_webhooks.go:31-45`).

All four converge one level lower, at `webhook.PostAsync` — `internal/webhook/webhook.go:184` (called at `memo_service_webhooks.go:43` and `:71`). `PostAsync` enqueues onto the bounded `asyncPostQueue` (capacity 128, dropped with a warning when full); four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it and call `webhook.Post` (`internal/webhook/webhook.go:120`), which does the actual JSON POST with optional Standard Webhooks HMAC-SHA256 signing via the SSRF-guarded `safeClient`.

Call sites, for completeness: created — `server/router/api/v1/memo_service.go:157`; deleted — `memo_service.go:562`; updated — `memo_update_helpers.go:67` (in `dispatchMemoUpdatedSideEffects`); comment created — `memo_service_comments.go:119`. All four log-and-continue on error.
