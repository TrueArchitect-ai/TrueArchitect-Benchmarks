**Engine:** Google CEL (`github.com/google/cel-go v0.28.1`, `go.mod:13`) — the filter string is a standard CEL expression, parsed by the in-repo filter engine at `internal/filter/` (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`, `helpers.go`).

**Mechanism (one sentence):** A three-phase pipeline — `Engine.Compile` compiles the CEL string against a schema-declared `cel.Env` (`internal/filter/engine.go:46`), `buildCondition` in `parser.go` normalizes the CEL AST into a dialect-agnostic condition-tree IR (`ir.go`) while enforcing schema rules, and `Program.Render` (`engine.go:92`) walks that IR through `newRenderer` in `render.go` to emit a dialect-specific SQL fragment plus bound args.

**Path through the RPC:**
- `ListMemos` validates the expression via `s.validateFilter` (defined at `server/router/api/v1/shortcut_service.go:336`) and appends it to `memoFind.Filters` — `server/router/api/v1/memo_service.go:211-215`. Visibility/ACL constraints are appended as *additional* CEL filter strings (e.g. `creator_id == %d || visibility in ["PUBLIC", "PROTECTED"]`, `memo_service.go:221`).
- Each store driver calls `filter.DefaultEngine()` then `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` with its own dialect constant: `store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo.go:65-69`, `store/db/postgres/memo.go:54-58`.
- `AppendConditions` (`internal/filter/helpers.go`) compiles each filter with a `PlaceholderOffset` equal to the current arg count and wraps each fragment in parens as an AND-ed `WHERE` clause.

**Dialect differences** live entirely in `render.go`, keyed on `DialectName` (`schema.go:13-17`: `sqlite`/`mysql`/`postgres`):
- Placeholders: `$N` for Postgres (offset-aware), `?` otherwise — `render.go:842-849`.
- JSON access: `JSON_EXTRACT(col, '$.path')` for SQLite/MySQL vs `buildPostgresJSONAccessor` (`->`/`->>` chains, cast to `::boolean`) for Postgres — `render.go:932-944`.
- Booleans: SQLite gets `1`/`0` ints via `addBoolArg` (`render.go:851+`); plus per-dialect handling of string length, `LIKE` vs `ILIKE`, and JSON array length (`JSON_ARRAY_LENGTH` vs equivalents).

Field vocabulary exposed to CEL is declared in `internal/filter/schema.go` (`content`, `creator`, `creator_id`, `created_ts`, `updated_ts`, `pinned`, `visibility`, `tags`/`tag`, `has_task_list`, `has_link`, `has_code`, `has_incomplete_tasks`); anything not in that map is rejected at compile time. `internal/filter/README.md` documents the same three-phase design.
