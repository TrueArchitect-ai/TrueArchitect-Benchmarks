`web/src/connect.ts`; JWT access token (in-memory + localStorage) and HttpOnly refresh-token cookie (plus PATs accepted by the same backend path); `server/auth`

**How it works**

- **Interceptor** — `authInterceptor` in `web/src/connect.ts:156` is attached to the single Connect-Web transport (`web/src/connect.ts:184-189`) that backs every service client (memo, user, auth, attachment, etc.). It calls `getRequestToken()` and sets `Authorization: Bearer <token>` on each request. On a `Code.Unauthenticated` reply it refreshes once, re-sends with an `X-Retry: true` header to prevent loops, and on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).

- **Tokens managed**
  - *Access token* — short-lived JWT held in memory and mirrored to `localStorage` under `memos_access_token` / `memos_token_expires_at` (`web/src/auth-state.ts:6-7`). Preflight refresh fires when it is within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), and `useTokenRefreshOnFocus` (`web/src/hooks/useTokenRefreshOnFocus.ts`) refreshes proactively on tab focus with a 2-minute buffer.
  - *Refresh token* — never touched by JS; it rides as an HttpOnly cookie, which is why all fetches use `credentials: "include"` (`web/src/connect.ts:57-62`). `refreshAccessToken()` calls `AuthService.RefreshToken` over a **separate transport with no interceptors** (`web/src/connect.ts:65-72`) to avoid recursion, and a `createTokenRefreshManager` singleton plus a `BroadcastChannel` (`memos_token_sync`, `web/src/auth-state.ts:13`) dedupes concurrent refreshes across tabs.

- **Backend validation** — package `server/auth` (`server/auth/token.go`, `extract.go`, `authenticator.go`). It defines issuer `memos`, key id `v1`, access tokens at 15 min with audience `user.access-token`, refresh tokens at 30 days with audience `user.refresh-token` in cookie `memos_refresh`, and Personal Access Tokens prefixed `memos_pat_` (`server/auth/token.go:26-52`). `ExtractBearerToken` parses the `Authorization` header and `ExtractRefreshTokenFromCookie` reads the cookie. The Connect/gRPC interceptors in `server/router/api/v1/connect_interceptors.go` (`auth.ApplyToContext`, line 227) and `server/router/fileserver` consume it.
