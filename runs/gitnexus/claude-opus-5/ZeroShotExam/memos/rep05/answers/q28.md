**Started by `Server.Start` → `startBackgroundRunners` (`server/server.go:129`, `server/server.go:153-174`) — exactly one runner:**

- **s3presign runner** (`server/runner/s3presign/runner.go`) — two triggers: one synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a goroutine with a `time.Ticker` firing every `runnerInterval = 12h` (`server/runner/s3presign/runner.go:27,30-41`). It re-presigns S3 attachment URLs whose 5-day presign is within 4 days of expiry. Its cancel func is registered in `backgroundRunnerCancels` and it is waited on via `backgroundRunnerWG` at shutdown (`server/server.go:176-201`).

**Other long-lived goroutines that exist in a running process, but are not started by `startBackgroundRunners`:**

- **store cache cleanup loops ×3** (`store/cache/cache.go:83`, `cleanupLoop` at `:199`) — ticker every `CleanupInterval = 5m`; started implicitly by `cache.New` inside `store.New` (`store/store.go:44,51-53`), i.e. by `cmd/memos/main.go:68` before the server is constructed.
- **email async workers ×2** (`internal/email/email.go:16-35`) — `init()`-spawned, queue-driven (`asyncEmailQueue`, buffered 128), not timed.
- **webhook async dispatchers ×4** (`internal/webhook/webhook.go:42-55`) — `init()`-spawned, queue-driven (`asyncPostQueue`, buffered 128), not timed.
- **HTTP serve goroutine** (`server/server.go:124`) and **signal-handler goroutine** (`cmd/memos/main.go:99`) — request/signal driven, not schedulers.
- **SSE heartbeat ticker** (`server/router/api/v1/sse_handler.go:64`) — per-connection, lives only for the request; the `SSEHub` itself has no background goroutine (`server/router/api/v1/sse_hub.go:63-67`).
- **PAT last-used update** (`server/auth/authenticator.go:180`) — fire-and-forget per authenticated request.

**Unused scheduling infrastructure:**

- **`internal/scheduler` — a complete cron scheduler (5/6-field cron parsing, timezone support, middleware, graceful shutdown: `scheduler.go`, `parser.go`, `job.go`, `middleware.go`) is NEVER used by the server.** The only non-test importers are its own `example_test.go` and `integration_test.go`; `scheduler.New`/`Start` appear nowhere in production code. The s3presign runner uses a hand-rolled `time.Ticker` instead of this package.
- **`server/runner/memopayload` is not run as a runner.** `memopayload.NewRunner` and `Runner.RunOnce` (`server/runner/memopayload/runner.go:19,27`) have zero callers; only the standalone `RebuildMemoPayload` helper is used, synchronously inside memo create/update (`server/router/api/v1/memo_service.go:108,447`). So the batch memo-payload rebuild worker exists but is never scheduled or invoked.
