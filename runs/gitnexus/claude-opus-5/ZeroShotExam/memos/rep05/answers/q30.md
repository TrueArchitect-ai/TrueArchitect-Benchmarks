**Convergence for delivery:**

The three plain lifecycle events (created/updated/deleted) are thin wrappers that all funnel into the unexported helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks via `s.Store.GetUserWebhooks`, builds a payload with `convertMemoToWebhookPayload`, and calls `webhook.PostAsync`.

`DispatchMemoCommentCreatedWebhook` bypasses that helper (it targets the *related* memo's owner, not the comment creator) but ends at the same call — `webhook.PostAsync` (`memo_service_webhooks.go:43`).

So the true common delivery point for all four is **`webhook.PostAsync` → `webhook.Post`** in `internal/webhook/webhook.go`:
- `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot `asyncPostQueue`, dropping with a warning if full.
- Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post` (`internal/webhook/webhook.go:120`), which marshals JSON, adds Standard Webhooks HMAC headers when a signing secret is set, and sends via the SSRF-guarded `safeClient`.

**Call sites:**

All four call sites only log a warning on failure, so a webhook error never fails the API request.
