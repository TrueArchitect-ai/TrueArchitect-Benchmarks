## Frontend interceptor — `web/src/connect.ts:145`

`authInterceptor` is a `@connectrpc/connect` `Interceptor` wired into the single `createConnectTransport` (`web/src/connect.ts:170`) that backs every service client (memo, user, auth, attachment, AI, shortcut, IdP, instance). Its flow:

1. Calls `getRequestToken()` (`connect.ts:117`) and sets `Authorization: Bearer <token>`.
2. **Preflight refresh** — if the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30 s) of expiry, refresh first, so public endpoints like `ListMemos` don't silently return guest-scoped data.
3. **Reactive retry** — on `Code.Unauthenticated`, refresh once, re-set the header, mark the request with `X-Retry: true` to prevent loops, and replay. If refresh fails → `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).

Refresh itself goes through a **separate transport with no interceptors** (`connect.ts:63`) to avoid recursion, and through `tokenRefreshManager` (`connect.ts:31`) which dedupes concurrent refreshes.

## Tokens it manages — `web/src/auth-state.ts`

| Token | Storage | Notes |
|---|---|---|
| **Access token** (JWT, 15 min) | in-memory + `localStorage["memos_access_token"]` / `memos_token_expires_at` | sent as `Authorization: Bearer` |
| **Refresh token** (JWT, 30 days) | HttpOnly cookie `memos_refresh` — never touched by JS; sent because the transport uses `fetch` with `credentials: "include"` (`connect.ts:56`) | exchanged via `AuthService.refreshToken` |

Cross-tab coordination uses a `BroadcastChannel` (`memos_token_sync`, `auth-state.ts:12`) so one tab's refresh is adopted by the others, plus `useTokenRefreshOnFocus` (`web/src/hooks/useTokenRefreshOnFocus.ts`) which proactively refreshes on tab visibility with a 2-minute buffer.

## Backend validation — `server/auth/`

- `server/auth/token.go` — claims, audiences (`user.access-token`, `user.refresh-token`), durations, `RefreshTokenCookieName = "memos_refresh"`, PAT prefix `memos_pat_`.
- `server/auth/authenticator.go` — `Authenticator.Authenticate()` (`:213`) dispatches: `AuthenticateByAccessTokenV2` (stateless signature check), `AuthenticateByPAT` (`:102`, DB-backed), `AuthenticateByRefreshToken` (`:60`, DB-checked for revocation).
- `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie`.

It's invoked from the Connect-side interceptor at `server/router/api/v1/connect_interceptors.go:222` (`in.authorizer.Authenticate(ctx, authHeader)` → `auth.ApplyToContext`), and the same package is reused by `server/router/fileserver`.
