**Runners the server actually starts** (`Server.Start` → `startBackgroundRunners`, `server/server.go:129`, `:153-174`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — the only entry in `startBackgroundRunners`. Two triggers: one synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a goroutine running `Run` on a plain `time.NewTicker` at a hard-coded `runnerInterval = 12h` (`server/runner/s3presign/runner.go:27,29-41`). Its context comes from a per-runner `context.WithCancel` whose cancel is stashed in `backgroundRunnerCancels` and fired by `stopBackgroundRunners`, with `backgroundRunnerWG` awaited in `waitBackgroundRunners` (`server/server.go:156-171,176-201`).
- **HTTP serve loop** — `go s.httpServer.Serve(listener)` (`server/server.go:124`); driven by inbound connections, stopped by `shutdownHTTPServer`.
- **Store cache cleanup goroutines ×3** — started implicitly, not by the server's runner wiring: `cache.New` spawns `cleanupLoop` (`store/cache/cache.go:83,199-212`) for `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`), each on a 5-minute `CleanupInterval` ticker (`store/store.go:42`); stopped by `Store.Close` (`store/store.go:72-79`).
- **Signal-handler goroutine** — `cmd/memos/main.go:99`; triggered by SIGINT/SIGTERM, calls `s.Shutdown`.

Not background runners, for completeness: the SSE heartbeat ticker (`server/router/api/v1/sse_handler.go:64`) is per-connection inside the request handler, and `recordPATUsage` (`server/auth/authenticator.go:180`) is a fire-and-forget per-request goroutine.

**Unused scheduling infrastructure:**

- **`internal/scheduler/`** — a complete cron scheduler (5/6-field parser, timezone support, middleware, graceful shutdown, README, docs) is **never used by the server**. Its only importers are its own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No production code imports the package; the one real periodic job (s3presign) uses a raw ticker instead.
- **`server/runner/memopayload.Runner`** — `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19,27`) are never called anywhere in the repo, including tests. Only the free function `RebuildMemoPayload` is used, and only inline on the request path (`server/router/api/v1/memo_service.go:108,447`). So the `runner/` directory holds two runners but the server starts only one.
