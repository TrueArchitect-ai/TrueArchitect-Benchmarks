**Engine:** Google **CEL** (`github.com/google/cel-go v0.28.1`, `go.mod:13`), wrapped by the in-repo filter engine at **`internal/filter/`** — `engine.go` (compile/render entry points, `DefaultEngine()`), `schema.go` (CEL env + field metadata), `parser.go` (AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL), `helpers.go` (`AppendConditions`).

**Mechanism (one sentence):** `Engine.Compile` type-checks the CEL string against a memo-specific env whose only declared variables are the filterable fields (`schema.go:233-247`: `content`, `creator`, `created_ts`, `pinned`, `tags`, `visibility`, `has_*`, `now`, plus `ext.Sets()`), `parser.go`'s `buildCondition` normalizes the CEL AST into a dialect-agnostic IR condition tree while enforcing schema rules (allowed operators, JSON-list vs bool-column kinds, constant folding of `now`/durations), and `render.go`'s `renderer` walks that IR emitting a SQL fragment + bound args for the requested `DialectName` (`sqlite`/`mysql`/`postgres`), switching per dialect on JSON access (`json_each` vs `JSON_TABLE` vs `jsonb_array_elements_text`), timestamp columns (`UNIX_TIMESTAMP(%s)` on MySQL vs raw epoch BIGINT elsewhere), string concat (`||` vs `CONCAT`), LIKE/ILIKE, and placeholders (`$N` for Postgres, `?` otherwise — `render.go:842-849`).

**Call path for ListMemos:**
- `server/router/api/v1/memo_service.go:211-215` — `request.Filter` is validated (`validateFilter`, defined at `server/router/api/v1/shortcut_service.go:336`, which compiles it against the driver's dialect) and appended to `memoFind.Filters`.
- Each driver then calls `filter.DefaultEngine()` + `filter.AppendConditions(...)` with its dialect: `store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`.
- `internal/filter/helpers.go` compiles each filter to a `Statement` and appends `(SQL)` to the WHERE list with a `PlaceholderOffset` equal to the current arg count, so Postgres `$N` numbering stays correct.
