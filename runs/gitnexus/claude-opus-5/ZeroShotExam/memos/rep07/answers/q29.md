**`web/src/connect.ts` (the `authInterceptor`, lines 156–178); access token (in-memory + `localStorage`, sent as `Authorization: Bearer`) and refresh token (HTTP-only `memos_refresh` cookie, sent via `credentials: "include"`) — plus PATs on the same Bearer header; validated by `server/auth` (Go package `github.com/usememos/memos/auth`).**

### Frontend

- **`web/src/connect.ts:156`** — `authInterceptor` is a Connect-RPC `Interceptor` installed on the single `createConnectTransport` at `web/src/connect.ts:184-189`. Every service client (memo, user, attachment, AI, shortcut, IdP, instance, auth) is created from that transport, so all RPCs go through it.
- Per request it calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, line 97). Two refresh paths:
  - **Proactive/preflight** — if `isTokenExpired(REQUEST_TOKEN_EXPIRY_BUFFER_MS)` (30s buffer), refresh before sending; important so public endpoints like ListMemos don't return guest-scoped data.
  - **Reactive** — on `Code.Unauthenticated`, refresh once, re-set the header, mark `X-Retry: true`, and retry; on failure `redirectOnAuthFailure()`.
- Refresh itself uses a **separate transport with no interceptors** (`refreshTransport`, line 65) to avoid recursion, and all callers funnel through `tokenRefreshManager` (line 30) to dedupe concurrent refreshes. `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus with a larger 2-minute buffer.

### Token storage

`web/src/auth-state.ts` — access token + expiry in memory and `localStorage` (`memos_access_token`, `memos_token_expires_at`), synced across tabs via a `BroadcastChannel` (`memos_token_sync`). The refresh token is never in JS: it's the `memos_refresh` cookie sent because `fetchWithCredentials` sets `credentials: "include"` (`web/src/connect.ts:57`).

### Backend

**`server/auth/`** (package doc at `server/auth/token.go:1-11`):
- `server/auth/token.go` — HS256 JWTs, issuer `memos`, `kid: v1`. `ParseAccessTokenV2` (audience `user.access-token`, 15 min, stateless) and `ParseRefreshToken` (audience `user.refresh-token`, 30 days).
- `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie`.
- `server/auth/authenticator.go` — `Authenticator.Authenticate` (Bearer only, records PAT last-used) and `AuthenticateToUser` (Bearer, then refresh-cookie fallback). Access tokens validate by signature alone; refresh tokens are checked against the DB for revocation/expiry; PATs (`memos_pat_` prefix) resolve by SHA-256 hash.

Consumed by the API interceptor at `server/router/api/v1/authz.go` (`Authorizer.Authenticate`) and by the file server; token rotation on refresh lives in `server/router/api/v1/auth_service_session.go:112` (`APIV1Service.RefreshToken`).
