**Convergence for delivery:**

The three lifecycle dispatchers are thin wrappers over `APIV1Service.dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which differs only by the `activityType` string. The comment variant does not go through that helper (it resolves the *related* memo's owner instead of the memo creator, via `relatedMemoCreatorID`), but it duplicates the same body inline.

All four converge on **`webhook.PostAsync`** (`internal/webhook/webhook.go:184`), called at `memo_service_webhooks.go:43` and `:71` after building the payload with `convertMemoToWebhookPayload` and stamping `ActivityType`, `URL`, and `SigningSecret` from each of the creator's `GetUserWebhooks` rows.

`PostAsync` only enqueues onto the buffered channel `asyncPostQueue` (cap 128, `webhook.go:39`), dropping with a warning if full. Four worker goroutines started in `init()` (`webhook.go:42-55`) drain the channel and call the real delivery function **`webhook.Post`** (`internal/webhook/webhook.go:120`), which marshals the JSON body, adds Standard Webhooks HMAC headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`) when a signing secret is set, and sends it via the SSRF-guarded `safeClient` (`webhook.go:32`, blocks reserved/private IPs at dial time).
