Two notes on where breakage will actually land:

- The three driver files under `store/db/` are the only places that map struct fields to SQL columns (`CreateMemo` builds the column list, `ListMemos` scans row → `store.Memo`). A field add/remove/rename must be mirrored in all three, plus a migration under `store/migration/`.
- `store/driver.go:29-32` is the interface all three drivers satisfy, so a signature-level change there fans out to every driver at compile time.

Not included: `proto/gen/api/v1/memo_service.pb.go` defines a separate generated `v1pb.Memo` — it's only coupled to `store.Memo` through `server/router/api/v1/memo_service_converter.go`, which is already listed.
