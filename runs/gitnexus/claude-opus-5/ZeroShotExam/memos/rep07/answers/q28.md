**Runners the server explicitly starts** (`Server.Start` → `startBackgroundRunners`, `server/server.go:129`, `server/server.go:153-174`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — one synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a goroutine running `Run` on a `time.NewTicker` fixed 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). Shutdown is via its own `context.CancelFunc` stored in `backgroundRunnerCancels` plus a `sync.WaitGroup` join (`server/server.go:156-171`, `176-201`). That is the **only** entry in `startBackgroundRunners`.

**Background goroutines started indirectly (not via the runner wiring):**

- **store cache cleanup loops ×3** (instanceSetting, user, userSetting) — `cache.New` spawns `cleanupLoop` (`store/cache/cache.go:82`), driven by a `CleanupInterval` ticker set to 5 minutes (`store/store.go:39-53`, `store/cache/cache.go:199-201`); stopped by `Store.Close` (`store/store.go:72-78`).
- **SSE heartbeat ticker** — per-connection, not server-wide: 30s ticker created inside the SSE handler for each client (`server/router/api/v1/sse_handler.go:17,64`), ends when the request context ends.
- **Event-triggered fire-and-forget goroutines** (no schedule at all): PAT last-used timestamp update (`server/auth/authenticator.go:180`), email send (`internal/email/email.go:18`), webhook dispatch (`internal/webhook/webhook.go:44`).
- **Signal handler goroutine** — waits on SIGINT/SIGTERM to call `s.Shutdown` (`cmd/memos/main.go:99`).

**Unused scheduling infrastructure:**

- **`internal/scheduler/` is entirely unused in production.** It's a full cron scheduler (5/6-field cron parser `internal/scheduler/parser.go`, `Job`/`Register`/`Start` in `internal/scheduler/scheduler.go:69-117`, middleware in `internal/scheduler/middleware.go`, README + `doc.go`), but `scheduler.New(` appears only in `internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`, and doc comments — no non-test caller anywhere in `cmd/`, `server/`, or `store/`. Nothing the server runs, including the s3presign 12h loop, goes through it; that loop uses a raw ticker.
- **`server/runner/memopayload.Runner` is never instantiated.** `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19,27`) have no callers; only the package-level function `RebuildMemoPayload` is used, synchronously inside memo create/update paths (`server/router/api/v1/memo_service.go:108,447`). So despite living under `server/runner/`, it is not a scheduled background runner.
