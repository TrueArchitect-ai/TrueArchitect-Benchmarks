**MemoService is served over gRPC-Gateway REST/JSON and Connect RPC** — both wired up from the same `APIV1Service` implementation in `RegisterGateway`.

1. **gRPC-Gateway REST/JSON (HTTP transcoding, `/api/v1/*`)** — `server/router/api/v1/v1.go:108` (`v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)`), with the generated transcoding code in `proto/gen/api/v1/memo_service.pb.gw.go`. The mux is mounted on Echo at `server/router/api/v1/v1.go:128`.

2. **Connect RPC (`/memos.api.v1.*`)** — `server/router/api/v1/connect_handler.go:40` (`wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` inside `RegisterConnectHandlers`), where `ConnectServiceHandler` embeds `*APIV1Service` so the same gRPC-style methods back both protocols. Generated handler: `proto/gen/api/v1/apiv1connect/memo_service.connect.go`; mounted at `server/router/api/v1/v1.go:144`.

Two notes on things that look like a third protocol but aren't:

- `proto/gen/api/v1/memo_service_grpc.pb.go` defines `RegisterMemoServiceServer`, but nothing in the repo calls it (no `grpc.NewServer()` anywhere outside generated code) — there's no native gRPC listener. `APIV1Service` only embeds `v1pb.UnimplementedMemoServiceServer` (`server/router/api/v1/v1.go:26`) to satisfy the generated interface.
- The MCP surface (`server/router/mcp/catalog.go:12-25` lists `MemoService_*` tools) is not a separate registration of the service — `server/router/mcp/service.go` builds tools from the OpenAPI spec and dispatches through the REST gateway via the adapter in `server/router/mcp/adapter.go`.
