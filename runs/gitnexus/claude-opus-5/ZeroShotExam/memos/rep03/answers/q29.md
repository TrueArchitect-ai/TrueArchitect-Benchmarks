## How it works

**Frontend interceptor — `web/src/connect.ts:156`**
`authInterceptor` is a ConnectRPC `Interceptor` wired into the single `createConnectTransport` at `web/src/connect.ts:184-189`; every generated service client (memo, user, attachment, AI, shortcut, IdP, instance, auth) is created from that transport, so all API calls flow through it. On each request it:
1. Calls `getRequestToken()` (`connect.ts:124`) and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, line 97).
2. Preflight-refreshes if the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry.
3. On a `Code.Unauthenticated` error, refreshes once, marks the retry with the `X-Retry` header, and replays; if refresh fails it calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).

Refresh itself goes through a *separate* transport with no interceptors (`refreshTransport`, line 65) to avoid recursion, and all refreshes are deduplicated by `tokenRefreshManager` (line 30) so the reactive 401 path and the proactive `useTokenRefreshOnFocus` hook (`web/src/hooks/useTokenRefreshOnFocus.ts`) can't race.

**Tokens managed**
- **Access token** — short-lived JWT (15 min, `AccessTokenDuration`), held in memory + `localStorage` under `memos_access_token` / `memos_token_expires_at`, synced across tabs via a `BroadcastChannel` (`web/src/auth-state.ts`). This is what the interceptor puts in the `Authorization` header.
- **Refresh token** — long-lived JWT (30 days), never touched by JS: it rides the `memos_refresh` HttpOnly cookie, which is why `fetchWithCredentials` sets `credentials: "include"` (`connect.ts:57`). Exchanged for a new access token via `AuthService.RefreshToken`.
- (The backend also accepts **Personal Access Tokens** with the `memos_pat_` prefix on the same Bearer header, but the web client doesn't issue them.)

**Backend validation — `server/auth`**
`server/auth/token.go` defines the claim types and parsers (`ParseAccessTokenV2`, `ParseRefreshToken`, HS256 with `kid: v1`, issuer `memos`, audience `user.access-token` / `user.refresh-token`). `server/auth/authenticator.go` (`Authenticator.Authenticate` / `resolveBearer`) does the actual per-request validation: access tokens are stateless signature checks, refresh tokens are additionally checked against the DB for revocation, PATs by SHA-256 hash lookup. `server/auth/extract.go` pulls the token out of the `Authorization` header and the `memos_refresh` cookie.

It's invoked from the Connect interceptor at `server/router/api/v1/connect_interceptors.go:222` and the gRPC path at `server/router/api/v1/v1.go:78` (both via `server/router/api/v1/authz.go`), with public/bootstrap method exemptions listed in `server/router/api/v1/acl_config.go`.
