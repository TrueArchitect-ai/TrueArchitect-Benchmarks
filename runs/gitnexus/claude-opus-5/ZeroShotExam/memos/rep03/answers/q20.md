**Mechanism:** Server-Sent Events (SSE) over a plain HTTP `GET /api/v1/sse` endpoint — `Content-Type: text/event-stream`, Bearer-token auth, 30 s heartbeat comments, `X-Accel-Buffering: no`. The browser side is an `EventSource`-style consumer in `web/src/hooks/useLiveMemoRefresh.ts` (with exponential reconnect backoff), which invalidates React Query caches on each event.

**Hub:** `server/router/api/v1/sse_hub.go` — `SSEHub` (mutex-guarded `map[*SSEClient]struct{}`, `Subscribe`/`Unsubscribe`/`Broadcast`/`Close`; 32-event buffer per client, events dropped for slow clients). Per-client visibility filtering lives in `SSEClient.canReceive` (private memos only to the creator or an admin). Wired up in `server/router/api/v1/v1.go:57` (`NewSSEHub()`) and `:125` (`RegisterSSERoutes`), the endpoint itself in `server/router/api/v1/sse_handler.go`, and shut down in `server/server.go:205`.

**Handlers that broadcast:**

| Handler | File | Event type |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:163` | `memo.created` (skipped when `isSSESuppressed`, i.e. called from `CreateMemoComment`) |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:126` | `memo.comment.created` |
| `UpsertMemoReaction` | `server/router/api/v1/reaction_service.go:106` | `reaction.upserted` |
| `DeleteMemoReaction` | `server/router/api/v1/reaction_service.go:161` | `reaction.deleted` |
| `dispatchMemoUpdatedSideEffects` (shared helper) | `server/router/api/v1/memo_update_helpers.go:71` | `memo.updated` |

The `memo.updated` event isn't broadcast inline by its callers — `UpdateMemo` (`memo_service.go:513`), `SetMemoRelations` (`memo_relation_service.go:48`), and `SetMemoAttachments` (`memo_attachment_service.go:48`) all route through `dispatchMemoUpdatedSideEffects`, which fires the webhook and the SSE event together.
