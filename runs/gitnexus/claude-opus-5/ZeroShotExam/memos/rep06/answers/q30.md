**Convergence for delivery:**

The three memo-lifecycle dispatchers are thin wrappers over the shared helper `dispatchMemoRelatedWebhook(ctx, memo, activityType)` (`memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks via `s.Store.GetUserWebhooks`, builds a payload with `convertMemoToWebhookPayload`, and calls `webhook.PostAsync`.

`DispatchMemoCommentCreatedWebhook` does **not** go through that helper — it resolves webhooks for the *related memo's* creator instead of the comment author, and calls `webhook.PostAsync` directly (`memo_service_webhooks.go:43`).

All four converge at `webhook.PostAsync` → `internal/webhook/webhook.go:184`, which enqueues onto the bounded `asyncPostQueue` (capacity 128, dropping with a warning when full). Four worker goroutines started in `init()` (`webhook.go:42-55`) drain the queue and perform the actual HTTP delivery in `webhook.Post` (`internal/webhook/webhook.go:120`), which marshals the JSON body, adds the Standard Webhooks HMAC-SHA256 signature headers when a signing secret is set, and POSTs via the SSRF-guarded `safeClient`.
