**Mechanism:** Server-Sent Events (SSE) over a plain HTTP GET — `text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no`, flushed per event via `http.Flusher`. The endpoint is `GET /api/v1/sse` (`server/router/api/v1/sse_handler.go:24-46`), registered in `server/router/api/v1/v1.go:125`, authenticated by Bearer token in the `Authorization` header. Browser side consumes it in `web/src/hooks/useLiveMemoRefresh.ts`. No WebSockets anywhere.

**Hub path:** `server/router/api/v1/sse_hub.go` — `SSEHub` (a mutex-guarded `map[*SSEClient]struct{}`) with `NewSSEHub`/`Subscribe`/`Unsubscribe`/`Broadcast`/`Close`. Each client gets a 32-slot buffered channel; events for slow clients are dropped rather than blocking the broadcaster, and `canReceive` filters `Private` memos to the creator or an admin. The hub is constructed in `server/router/api/v1/v1.go:57`, held on `APIV1Service.SSEHub`, and closed on shutdown via `server/server.go:202-207`.

**Handlers that broadcast:**

| Handler | Location | Event |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:163` | `memo.created` (suppressed when called from `CreateMemoComment`, via `suppressSSEKey`) |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:126` | `memo.comment.created` |
| `UpsertMemoReaction` | `server/router/api/v1/reaction_service.go:106` | `reaction.upserted` |
| `DeleteMemoReaction` | `server/router/api/v1/reaction_service.go:161` | `reaction.deleted` |
| `UpdateMemo`, `SetMemoAttachments`, `SetMemoRelations` | indirectly, all three call `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:71`) | `memo.updated` |

So the direct `SSEHub.Broadcast` call sites are five service methods plus the shared `dispatchMemoUpdatedSideEffects` helper, which three more handlers (`memo_service.go:513`, `memo_attachment_service.go:48`, `memo_relation_service.go:48`) route through.
