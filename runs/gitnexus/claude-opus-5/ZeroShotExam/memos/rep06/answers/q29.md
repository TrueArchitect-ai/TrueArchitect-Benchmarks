**`web/src/connect.ts`; short-lived JWT access token (localStorage, `Authorization: Bearer`) + HTTP-only refresh-token cookie (`memos_refresh`), plus PATs accepted on the same header; `server/auth`**

**Interceptor** — `authInterceptor` at `web/src/connect.ts:156`, registered on the ConnectRPC transport (`web/src/connect.ts:184-189`) that backs every service client (memo, user, auth, attachment, AI, shortcut, IdP, instance). Per request it:
- calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, line 97)
- preflight-refreshes when the token is within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`)
- on a `Code.Unauthenticated` response, refreshes once, re-sends with an `X-Retry: true` marker to prevent loops, and calls `redirectOnAuthFailure()` if the refresh fails (lines 163-177)
- uses a separate interceptor-free `refreshTransport` (line 65) so the refresh call can't recurse, deduped through `tokenRefreshManager` (line 30)

**Tokens** — managed in `web/src/auth-state.ts`:
- *access token*: JWT held in memory + `localStorage` keys `memos_access_token` / `memos_token_expires_at`, synced across tabs over a `memos_token_sync` BroadcastChannel (lines 26-50)
- *refresh token*: never touched by JS — it's an HTTP-only cookie sent because `fetchWithCredentials` sets `credentials: "include"` (`web/src/connect.ts:57`); the frontend only invokes `AuthService.refreshToken` to swap it for a new access token
- `web/src/hooks/useTokenRefreshOnFocus.ts` proactively refreshes on tab focus with a 2-minute buffer

**Backend validation** — `server/auth` (`github.com/usememos/memos/server/auth`):
- `token.go` — `ParseAccessTokenV2`, `ParseRefreshToken`, constants `RefreshTokenCookieName = "memos_refresh"`, 30-day refresh lifetime
- `authenticator.go` — `AuthenticateByAccessTokenV2` (stateless JWT check), `AuthenticateByRefreshToken` (DB revocation + expiry check), `AuthenticateByPAT`
- `extract.go` — `ExtractBearerToken`, `ExtractRefreshTokenFromCookie`

It's driven by the server-side authorizer at `server/router/api/v1/authz.go` (with `acl_config.go` listing public methods), and reused by `server/router/fileserver/fileserver.go` and `sse_handler.go`.
