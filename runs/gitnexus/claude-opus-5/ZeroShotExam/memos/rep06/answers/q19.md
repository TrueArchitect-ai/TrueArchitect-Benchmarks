**REST / HTTP+JSON via gRPC-Gateway — `server/router/api/v1/v1.go`**
`APIV1Service` embeds `v1pb.UnimplementedMemoServiceServer` (`v1.go:26`) and registers the generated gateway handler in-process at `v1.go:108` (`v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)`). The mux is mounted on Echo at `/api/v1/*` (`v1.go:128`); generated routing/marshaling code lives in `proto/gen/api/v1/memo_service.pb.gw.go`.

**Connect RPC (connectrpc) — `server/router/api/v1/connect_handler.go` (+ `connect_services.go`)**
`apiv1connect.NewMemoServiceHandler(s, opts...)` is registered on the Connect mux at `connect_handler.go:40`, mounted on Echo under `/memos.api.v1.*` (`v1.go:144`). The per-method wrapping that adapts the gRPC implementations to Connect request/response types is in `server/router/api/v1/connect_services.go:304` onward ("// MemoService" section, e.g. `CreateMemo`, `ListMemos`, `GetMemo`), against the generated interface in `proto/gen/api/v1/apiv1connect/memo_service.connect.go`.

Note: there is no standalone native gRPC server — no `grpc.NewServer()`/`RegisterMemoServiceServer` call exists outside generated code, so the two live protocols are the gateway REST surface and Connect. (MCP in `server/router/mcp/catalog.go` re-exposes the same methods as tools, but it dispatches over these, it isn't a third protocol registration.)
