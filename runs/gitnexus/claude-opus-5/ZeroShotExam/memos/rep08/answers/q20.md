**Mechanism:** Server-Sent Events (SSE) over a plain HTTP `GET /api/v1/sse` stream (`text/event-stream`, Bearer-token auth, 30s heartbeat) — not WebSockets.

**Hub:** `server/router/api/v1/sse_hub.go` — `SSEHub` (`sync.RWMutex` + `map[*SSEClient]struct{}`) with `Subscribe`/`Unsubscribe`/`Broadcast`/`Close`. Events are dropped for slow clients (32-event buffer) and filtered per-client by `canReceive` (private memos only reach the creator or an admin). The endpoint handler is `handleSSE` in `server/router/api/v1/sse_handler.go:33`, registered by `RegisterSSERoutes` (wired in `server/router/api/v1/v1.go:125`; hub created at `v1.go:57`, closed on shutdown via `server/server.go:205`). Client side: `web/src/hooks/useLiveMemoRefresh.ts`.

**Handlers that broadcast:**

| Handler | File:line | Event |
|---|---|---|
| `CreateMemo` | `memo_service.go:163` | `memo.created` (suppressed when invoked from `CreateMemoComment` via the `suppressSSEKey` context flag) |
| `DeleteMemo` | `memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `memo_service_comments.go:126` | `memo.comment.created` (on the parent memo) |
| `UpdateMemo` | `memo_service.go:513` → `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:71`) | `memo.updated` |
| `SetMemoAttachments` | `memo_attachment_service.go:48` → same helper | `memo.updated` |
| `SetMemoRelations` | `memo_relation_service.go:48` → same helper | `memo.updated` |
| `UpsertMemoReaction` | `reaction_service.go:106` | `reaction.upserted` |
| `DeleteMemoReaction` | `reaction_service.go:161` | `reaction.deleted` |

The three `memo.updated` producers all funnel through the shared helper `dispatchMemoUpdatedSideEffects`, which is the only direct `Broadcast` call site for that event type.
