**`web/src/connect.ts`; JWT access token (localStorage, sent as `Authorization: Bearer`) + HTTP-only refresh-token cookie (`memos_refresh`), plus PAT support server-side; `server/auth/`**

**Interceptor** — `authInterceptor` at `web/src/connect.ts:156`, registered on the Connect-Web transport (`web/src/connect.ts:184-189`) that backs every service client (memo, user, auth, attachment, etc.). Per request it:
1. calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`web/src/connect.ts:97`);
2. on a `Code.Unauthenticated` error, refreshes once, marks the retry with an `X-Retry` header to prevent loops, and replays; if the refresh fails it calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).

**Tokens managed** — `web/src/auth-state.ts` holds the short-lived JWT access token in memory + `localStorage` (`memos_access_token`, `memos_token_expires_at`), with expiry buffers (`REQUEST_TOKEN_EXPIRY_BUFFER_MS` 30s, `FOCUS_TOKEN_EXPIRY_BUFFER_MS` 2min) and a `BroadcastChannel` (`memos_token_sync`) so tabs share a refreshed token. The refresh token itself is never in JS — it rides as an HTTP-only cookie, which is why the transports use `credentials: "include"` (`web/src/connect.ts:57`). Refresh goes through a separate interceptor-free transport (`web/src/connect.ts:65-72`) to avoid recursion, deduped by `tokenRefreshManager` (`web/src/connect.ts:30`); `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus.

**Backend validation** — package `server/auth/` (`github.com/usememos/memos/server/auth`):
- `server/auth/token.go` — claims, signing, constants: access token 15min, refresh token 30 days, cookie `memos_refresh`, PAT prefix `memos_pat_`.
- `server/auth/authenticator.go` — `Authenticator.AuthenticateByAccessTokenV2` (stateless signature check) and `AuthenticateByRefreshToken` (DB-checked for revocation against `UserSetting_REFRESH_TOKENS`).
- `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie`.

It's consumed by the API authorizer `server/router/api/v1/authz.go:36`, the SSE handler `server/router/api/v1/sse_handler.go:26`, the file server `server/router/fileserver/fileserver.go:115`, and the refresh RPC `server/router/api/v1/auth_service_session.go:112` (`RefreshToken`, which rotates the cookie).
