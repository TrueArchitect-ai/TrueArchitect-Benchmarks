**Runners the server actually starts** (all wiring is in `Server.startBackgroundRunners`, `server/server.go:152-173`, called from `Server.Start` at `server/server.go:126`):

- **s3presign runner (`RunOnce`, startup pass)** — triggered once, synchronously, at server start: `s3presignRunner.RunOnce(ctx)` (`server/server.go:161`, `server/runner/s3presign/runner.go:42`).
- **s3presign runner (`Run`, continuous loop)** — triggered by a fixed `time.NewTicker` on `runnerInterval = 12h` (`server/runner/s3presign/runner.go:26,29-40`), running in its own goroutine under a dedicated cancelable context whose cancel func is stored for shutdown (`server/server.go:154-170`, stopped via `stopBackgroundRunners`/`waitBackgroundRunners`, `server/server.go:175-200`).

That is the entire set registered as background runners — `startBackgroundRunners` starts only s3presign.

**Other periodic goroutines that exist but are not "background runners":**

- **Store cache cleanup loops (×3)** — started implicitly by `cache.New` (`store/cache/cache.go:75-83` spawns `cleanupLoop`), driven by a `CleanupInterval` ticker of 5 minutes (`store/cache/cache.go:200-213`); three instances are created in `store.New` for `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:39-53`). Not registered with `backgroundRunnerCancels`/`WaitGroup`; they stop when `Store.Close()` runs during shutdown.
- **SSE heartbeat ticker** — per-connection, not a server-wide worker: created inside the SSE handler on each client connection (`server/router/api/v1/sse_handler.go:64`).

**Unused scheduling infrastructure:**

- **`internal/scheduler/` is dead code as far as the server is concerned.** It's a full cron scheduler — `ParseCronExpression` (`internal/scheduler/parser.go:29`), `Schedule.Next` (`parser.go:91`), `Scheduler.Register`/`Start` (`internal/scheduler/scheduler.go:69,90`), jobs (`job.go`), middleware (`middleware.go`), plus a README advertising it as "production-ready". Grepping for imports of `github.com/usememos/memos/internal/scheduler` outside the package itself returns nothing: the only importers are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No cron expression drives any server behavior; the only real schedule is the hardcoded 12-hour ticker in s3presign.
- **`server/runner/memopayload`** is a runner package with a `Runner`/`NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:15-30`) that is never started as a background runner. Only its standalone helper `RebuildMemoPayload` is used, called inline on the request path from the memo service (`server/router/api/v1/memo_service.go:108,447`). So `memopayload.Runner`/`RunOnce` (the bulk rebuild-all-memos pass) has no trigger at all.
