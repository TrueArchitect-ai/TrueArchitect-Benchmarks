**Engine + path:** Google **CEL** (`github.com/google/cel-go`, plus `ext.Sets()`/other extensions), wrapped by the in-repo memo filter engine at **`internal/filter/`** — `engine.go` (entry point `filter.DefaultEngine()` / `CompileToStatement`), `schema.go` (allowed fields + CEL env), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL), `helpers.go` (`AppendConditions`). Design notes are in `internal/filter/README.md`.

**Mechanism (one sentence):** `ListMemos` validates `request.Filter` (`server/router/api/v1/memo_service.go:211-215`, via `validateFilter` in `server/router/api/v1/shortcut_service.go:336`) and passes it through as `MemoFind.Filters`; each store driver then calls `filter.DefaultEngine()` + `filter.AppendConditions(...)` with its own dialect constant — `store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69` — which runs the three-phase pipeline (cel-go `env.Compile` → schema-validated IR via `buildCondition` → `newRenderer(...).Render`) to emit a parameterized SQL fragment plus args that are appended to the query's `WHERE` clause.

**Where the dialects diverge** (all inside `internal/filter/render.go`, switching on `DialectSQLite`/`DialectMySQL`/`DialectPostgres` declared in `schema.go:12-17`):
- Placeholders: `?` for SQLite/MySQL vs `$n` for Postgres (`RenderOptions.PlaceholderOffset` keeps numbering aligned with pre-existing args).
- JSON payload access: `json_extract` vs `JSON_EXTRACT` vs `->`/`->>` with `::boolean` casts (`renderJSONBoolComparison`, render.go:357-411).
- Tag membership: SQLite `LIKE` patterns, MySQL `JSON_CONTAINS`, Postgres `@>` (`renderTagInList`, render.go:434-482).
- Regex: Postgres `~`, MySQL/SQLite `REGEXP` (SQLite backed by a Go-registered function in `store/db/sqlite/functions.go`) — `renderRegex`, render.go:558-577.
- Timestamp accessors and `size()`/`LENGTH`: `strftime` vs `EXTRACT` vs `YEAR`/`MONTH` (`timestampAccessorExpr`, render.go:222-248; `stringLengthExpr`, render.go:297).

Note `now` is frozen once per compile (`parseContext.now`, `parser.go:11-16`) so a filter observes a single instant, and time expressions constant-fold to epoch seconds.
