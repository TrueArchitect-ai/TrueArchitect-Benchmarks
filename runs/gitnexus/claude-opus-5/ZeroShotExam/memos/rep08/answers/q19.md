Both are backed by the same `APIV1Service` implementation — `ConnectServiceHandler` just embeds `*APIV1Service` and adapts gRPC errors (`convertGRPCError`), so business logic has a single source of truth.

Two related things that are *not* separate protocols here:
- `proto/gen/api/v1/memo_service_grpc.pb.go` defines the native gRPC server interface, but no `grpc.Server` registration exists in the codebase — `APIV1Service` only embeds `v1pb.UnimplementedMemoServiceServer` (`server/router/api/v1/v1.go:26`) to satisfy the interface used by the two handlers above.
- The MCP surface (`server/router/mcp/catalog.go`) exposes MemoService operations as tools, but it dispatches over the REST gateway's HTTP method/path rather than being its own registration of the service.
