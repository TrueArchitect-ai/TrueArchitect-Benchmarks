There's no ORM here — the mapping is hand-written SQL in the per-driver DB layer (`store/db/{sqlite,postgres,mysql}/`), which reads/writes the model structs defined in `store/`.

| table | Struct — path |
|---|---|
| `user` | `store.User` — `store/user.go:29` |
| `attachment` | `store.Attachment` — `store/attachment.go:16` |
| `reaction` | `store.Reaction` — `store/reaction.go:7` |

Evidence of the table binding (SQLite driver; Postgres/MySQL mirror it):
- `store/db/sqlite/user.go:17` — `INSERT INTO user (...)`, in `CreateUser(ctx, create *store.User)`
- `store/db/sqlite/attachment.go:34` — ``INSERT INTO `attachment` (...)``, in `CreateAttachment(ctx, create *store.Attachment)`
- `store/db/sqlite/reaction.go:16` — ``INSERT INTO `reaction` (...)``, in `UpsertReaction(ctx, upsert *store.Reaction)`

Each table also has companion parameter structs in the same file (e.g. `FindUser`/`UpdateUser`/`DeleteUser`), but those are query descriptors, not row models.
