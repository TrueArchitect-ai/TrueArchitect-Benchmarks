**web/src/connect.ts (`authInterceptor`, with token state in web/src/auth-state.ts); access token V2 (JWT, Bearer header) + refresh token (httpOnly cookie) + Personal Access Tokens (PATs); server/auth**

**Interceptor.** `authInterceptor` at `web/src/connect.ts:156` is installed on the Connect transport (`:188`). Per request it fetches a token via `getRequestToken` (`:124`) and sets `Authorization: Bearer <token>`. On a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry` marker to prevent loops, and calls `redirectOnAuthFailure` if the refresh also fails (`:163-177`). Refresh itself goes through a separate interceptor-free transport and `refreshAuthClient` (`:65-72`) so it can't recurse, and `tokenRefreshManager` (`:30`) dedupes concurrent refreshes. It also preemptively refreshes when the token is within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), which matters for public endpoints that would otherwise silently serve guest-scoped data.

**Tokens.**
- **Access token (V2)** — short-lived JWT held in memory and mirrored to `localStorage` under `memos_access_token` (`web/src/auth-state.ts:6`), sent as a Bearer header. Tabs share freshly-refreshed tokens over a `BroadcastChannel` (`auth-state.ts:13`).
- **Refresh token** — httpOnly cookie `memos_refresh` (`server/auth/token.go:49`), never touched by JS; the transport just sends `credentials: "include"` (`web/src/connect.ts:57-62`).
- **PAT** — long-lived tokens prefixed `memos_pat_` (`server/auth/token.go:52`) for programmatic clients; accepted in the same Bearer position.

**Backend validation.** The `server/auth` package. `Authenticator.resolveBearer` (`server/auth/authenticator.go:149`) tries `AuthenticateByAccessTokenV2` (`:41`) then falls back to `AuthenticateByPAT` (`:102`), which hashes the token, looks it up via `Store.GetUserByPATHash`, checks expiry, and records last-used asynchronously (`:179`). `AuthenticateByRefreshToken` (`:61`) backs the refresh endpoint; token generation lives in `server/auth/token.go`, header/cookie parsing in `server/auth/extract.go`. It's invoked from the Connect interceptors (`server/router/api/v1/connect_interceptors.go`) and the gateway auth middleware in `server/router/api/v1/v1.go:94-97`, with per-method rules in `server/router/api/v1/acl_config.go` and `authz.go`.
