```
s3presign.Runner — 12-hour time.Ticker, plus one immediate RunOnce at startup
internal/webhook async dispatch pool — 4 goroutines draining a buffered channel, triggered per webhook event (not scheduled)
SSE per-connection heartbeat — time.Ticker per connected client, for the life of the connection
```

**Details.**

- **`s3presign.Runner`** is the only runner started through the server's background-runner machinery. `startBackgroundRunners` (`server/server.go:150`) calls `s3presignRunner.RunOnce(ctx)` synchronously, then launches `Run(s3Context)` in a goroutine tracked by a `WaitGroup` with its own cancel func for shutdown. `Run` drives a `time.NewTicker(runnerInterval)` with `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27-30`); each tick calls `CheckAndPresign`, which re-signs S3 objects whose `LastPresignedTime` is older than 4 days (`runner.go:88`).

- **Webhook dispatch pool** — `internal/webhook/webhook.go:42` spawns 4 worker goroutines in `init()`, each consuming from `asyncPostQueue` (capacity 128, `:39`). Not time-scheduled: work arrives when a handler calls `webhook.PostAsync`, and the queue drops with a warning when full. Since it's an `init()`, it starts on package import rather than via `Server.Start`, and there's no shutdown hook for it.

- **SSE heartbeat** — `handleSSE` creates a `time.NewTicker(sseHeartbeatInterval)` per client connection (`server/router/api/v1/sse_handler.go:64`) to keep the stream alive. Connection-scoped, not a server-wide worker.

**Unused infrastructure:** `server/runner/memopayload` ships a full runner — `NewRunner(store, markdownService)` and `RunOnce` (`server/runner/memopayload/runner.go:19` and `:27`) — that **nothing ever starts**. `memopayload.NewRunner` has zero call sites anywhere in the repo, including tests; `server/server.go` doesn't even import the package. Only the package's standalone `RebuildMemoPayload` function (`runner.go:74`) is used, called inline from the API layer on create and update (`server/router/api/v1/memo_service.go:108` and `:447`). So the backfill/rebuild-all-payloads path exists but is dead code from the server's perspective.
