`Store.DeleteMemo` (`store/memo.go:140-159`) deletes, in order, before the memo row:

1. **`memo_relation` rows where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **`memo_relation` rows where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **`attachment` rows linked to the memo** — listed via `FindAttachment{MemoID}` and deleted one by one (`store/memo.go:149-157`); each `Store.DeleteAttachment` (`store/attachment.go:132`) also removes the **backing stored file/blob** (local disk or external storage) via `DeleteAttachmentStorage` before deleting the row
4. Finally `s.driver.DeleteMemo` deletes the **memo row** (`store/memo.go:158`)

Additionally, at the API layer `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) first deletes **child comment memos** — every memo related to this one with type `COMMENT` — by calling `Store.DeleteMemo` on each (lines 568-577), so their relations and attachments are cleaned up by the same cascade.

Note what is *not* deleted: reaction rows are only *read* (line 545) to build the webhook payload; nothing in this path deletes `reaction` records for the memo.
