**web/src/connect.ts (`authInterceptor`, with token state in web/src/auth-state.ts); short-lived JWT access token (V2), HttpOnly refresh-token cookie `memos_refresh`, and Personal Access Tokens for programmatic clients; server/auth (validated via `server/router/api/v1/connect_interceptors.go` for Connect and the gateway middleware in `server/router/api/v1/v1.go`)**

**Frontend.** `authInterceptor` (`web/src/connect.ts:156`) is installed on the Connect transport (line 188) and does three things per request:
1. Calls `getRequestToken()` (line 124), which reads the access token from `localStorage` via `getAccessToken` (`web/src/auth-state.ts:52`) and, if it's within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30 s) of expiry, refreshes preemptively (`connect.ts:140`) — important for public endpoints like `ListMemos`, where an expired token would otherwise return guest-scoped data.
2. Sets `Authorization: Bearer <token>` (line 159).
3. On a `Code.Unauthenticated` response, refreshes once, marks the retry with an `X-Retry` header, and replays; if the refresh fails it calls `redirectOnAuthFailure()` (lines 163-177).

Refresh itself goes through a *separate* interceptor-free transport and `refreshAuthClient` to avoid recursion (`connect.ts:65-72`); `refreshAccessToken` dedupes concurrent calls through a refresh manager (lines 30-91) so the focus-refresh hook and the 401 path can't race server-side token rotation. All transports use `credentials: "include"` (line 57-62) so the HttpOnly refresh cookie rides along.

**Backend.** `server/auth` is the validation package — `Authenticator` in `server/auth/authenticator.go`:
- `AuthenticateByAccessTokenV2` → `ParseAccessTokenV2` HMAC-verifies the JWT with the instance secret (line 41)
- `AuthenticateByRefreshToken` → parses the cookie token, then checks it against the DB record via `GetUserRefreshTokenByID` (line 61)
- `AuthenticateByPAT` → prefix check, `HashPersonalAccessToken`, DB lookup by hash, expiry check (line 102), with async last-used recording (line 179)
- `resolveBearer` (line 149) picks access-token vs PAT by prefix; `AuthenticateToUser` (line 190) tries the `Authorization` header first and falls back to the refresh cookie. Cookie extraction is in `server/auth/extract.go`, token minting/parsing in `server/auth/token.go`, and request-context plumbing in `server/auth/context.go`.

It's wired into both protocols: `NewAuthInterceptor(authorizer)` for ConnectRPC (`server/router/api/v1/connect_interceptors.go:213`, registered at `server/router/api/v1/v1.go:137`) and the gateway auth middleware on the REST mux (`server/router/api/v1/v1.go:95`). Cookie issuance/rotation/clearing lives in `server/router/api/v1/auth_service_session.go`.
