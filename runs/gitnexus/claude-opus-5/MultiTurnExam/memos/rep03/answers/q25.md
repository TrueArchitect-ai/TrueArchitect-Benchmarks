**Google CEL (cel-go) via the in-repo `internal/filter` package — `internal/filter/engine.go` (parse), `internal/filter/ir.go` + `parser.go` (condition tree), `internal/filter/render.go` (SQL), `internal/filter/schema.go` (allowed fields/functions); dialect enum `filter.DialectSQLite | DialectPostgres | DialectMySQL`**

**Mechanism:** `filter.Engine.Compile` runs the filter string through a `cel.Env` built from the memo `Schema` and lowers the CEL AST into a dialect-agnostic condition tree (`engine.go:47-69`), which `Program.Render` then walks with a dialect-parameterized renderer (`engine.go:93`, `render.go`) to emit a parameterized SQL `WHERE` fragment plus args — so each driver calls `filter.DefaultEngine()` and `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` (e.g. `store/db/sqlite/memo.go:57-61`, and the same two lines in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`), with the renderer switching on dialect for things like timestamp accessors, JSON/tag containment, and string length (`render.go:231-237, 297-302, 365-410, 452-464`).

Supporting detail: `cel-go v0.28.1` is the dependency (`go.mod:13`). Engines are process-wide singletons — `DefaultEngine()` for memos and `DefaultAttachmentEngine()` for attachments (`engine.go:111`, `:118`), the latter using `NewAttachmentSchema()`. `now` is frozen once per compile so one filter sees a single instant (`engine.go:17-20`). The same engine backs attachment filters (`server/router/api/v1/attachment_service.go`) and saved shortcuts (`server/router/api/v1/shortcut_service.go`, whose `Shortcut.filter` is documented in `proto/api/v1/shortcut_service.proto` as the same grammar as `ListMemos.filter`). Design notes live in `internal/filter/README.md` and `internal/filter/MAINTENANCE.md`.
