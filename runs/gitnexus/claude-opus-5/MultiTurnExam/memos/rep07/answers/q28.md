```
s3presign.Runner — 12-hour time.Ticker loop, plus one immediate RunOnce at startup
internal/webhook async dispatch pool — 4 goroutines draining a 128-slot channel, triggered per webhook event (package init)
SSE heartbeat (per connection) — 30-second ticker inside each live SSE request
```

Details:

- **s3presign** is the only runner started via `Server.startBackgroundRunners` (`server/server.go:152-170`): `s3presign.NewRunner(s.Store)`, an immediate `RunOnce(ctx)` at `:163`, then `Run(s3Context)` in a goroutine. `Run` drives a `time.NewTicker(runnerInterval)` with `runnerInterval = 12h` (`server/runner/s3presign/runner.go:27`, `:29-36`); each pass re-presigns S3 objects in batches of 100, skipping those presigned within the last 4 days (`:55`, `:88`). It has its own cancel func for graceful shutdown (`server/server.go:154-156`, `stopBackgroundRunners` at `:172`).
- **Webhook dispatch workers** aren't registered by the server but start on package init: 4 goroutines reading `asyncPostQueue` (`internal/webhook/webhook.go:39`, `:41-54`). Scheduling is event-driven — each `webhook.PostAsync` from a memo handler enqueues one job, dropped with a warning if the queue is full.
- **SSE heartbeats** run per connection, on a `sseHeartbeatInterval = 30 * time.Second` ticker (`server/router/api/v1/sse_handler.go:17`), for the lifetime of each client stream.

**Unused infrastructure:** `server/runner/memopayload` ships a full `Runner` type — `NewRunner(store, markdownService)` and `RunOnce(ctx)` that rebuilds the payload of *all* memos (`server/runner/memopayload/runner.go:19`, `:27`) — but nothing constructs it. `server/server.go` doesn't import the package, and the only references anywhere are to the standalone helper `memopayload.RebuildMemoPayload`, called inline by `CreateMemo` and `UpdateMemo` (`server/router/api/v1/memo_service.go:108`, `:447`). So the batch backfill runner is dead code as far as the running server is concerned.
