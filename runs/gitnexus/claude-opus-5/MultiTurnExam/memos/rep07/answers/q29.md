**web/src/connect.ts; short-lived JWT access token (Authorization: Bearer) + HttpOnly refresh-token cookie — backend also accepts Personal Access Tokens on the same header; server/auth**

**Interceptor:** `authInterceptor` at `web/src/connect.ts:156`, installed on the shared Connect transport (`:188`). Per request it fetches a token via `getRequestToken()` (`:124`) and sets `Authorization: Bearer …`; on a `Code.Unauthenticated` response it refreshes once, replays the request with an `X-Retry` marker, and redirects to login if the refresh fails (`:163-177`).

**Tokens:**
- *Access token* — JWT held in memory + `localStorage` (`web/src/auth-state.ts`, keys `memos_access_token` / `memos_token_expires_at`), pre-emptively refreshed when within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`) or 2min on tab focus (`FOCUS_TOKEN_EXPIRY_BUFFER_MS`, used by `web/src/hooks/useTokenRefreshOnFocus.ts`). Cross-tab sharing via a `BroadcastChannel` so only one tab refreshes.
- *Refresh token* — a cookie, never touched by JS; requests go out with `credentials: "include"` (`web/src/connect.ts:57`). `AuthService.refreshToken` is called through a separate interceptor-free transport (`refreshTransport` / `refreshAuthClient`, `:65-72`) to avoid recursion, with concurrent refreshes deduped by `tokenRefreshManager` (`:30`, `:89`).
- *Personal Access Token* — not used by the web client, but the backend accepts one on the same `Authorization: Bearer` header for programmatic access.

**Backend validation:** package `server/auth` — `Authenticator` in `server/auth/authenticator.go`: `AuthenticateByAccessTokenV2` (`:41`), `AuthenticateByRefreshToken` (`:61`, checks the DB via `GetUserRefreshTokenByID`), `AuthenticateByPAT` (`:102`, hash lookup + expiry check, records last-used). `resolveBearer` (`:149`) tries access token then PAT; `AuthenticateToUser` (`:190`) falls back to the refresh cookie. JWT parse/sign lives in `server/auth/token.go`, header/cookie extraction in `server/auth/extract.go`, context plumbing in `server/auth/context.go`. Server-side session/token issuance is in `server/router/api/v1/auth_service_session.go`.
