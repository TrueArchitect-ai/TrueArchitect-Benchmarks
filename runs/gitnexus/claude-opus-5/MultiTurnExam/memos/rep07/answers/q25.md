**Engine: Google CEL (`github.com/google/cel-go`), wrapped by the `filter` package at `internal/filter/` — `internal/filter/engine.go`**

**Mechanism:** `Engine.Compile` compiles the CEL expression against a typed environment (`internal/filter/engine.go:47`, env built from `internal/filter/schema.go`) into a dialect-agnostic condition tree (`internal/filter/ir.go`, built by `internal/filter/parser.go`), and then `Program.Render` walks that tree through a dialect-parameterized renderer (`internal/filter/render.go`, `RenderOptions{Dialect: …}` at `internal/filter/engine.go:84`) that emits per-dialect SQL plus bound args — which the memo drivers splice into their `WHERE` clause via `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite|DialectMySQL|DialectPostgres, &where, &args)` (`internal/filter/helpers.go:9`; call sites at `store/db/sqlite/memo.go:58-62`, and the mysql/postgres equivalents).

Concrete dialect divergence, from `internal/filter/engine_test.go:93-167`: `startsWith` renders as `memos_unicode_lower(...) LIKE ... ESCAPE '\'` on SQLite, `ILIKE $1` on Postgres, `LIKE ?` on MySQL; `matches` becomes `REGEXP ?` on SQLite/MySQL but `~ $1` on Postgres; tag predicates expand to `json_each` / `jsonb_array_elements_text` / `JSON_TABLE` respectively. Placeholder numbering is handled by `PlaceholderOffset` so Postgres `$n` markers stay consistent when conditions are appended.

The user-facing grammar is the same one exposed as `Shortcut.filter` (`proto/api/v1/shortcut_service.proto`); package docs are in `internal/filter/README.md` and `internal/filter/MAINTENANCE.md`.
