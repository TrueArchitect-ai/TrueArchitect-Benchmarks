**CEL (Google Common Expression Language, `github.com/google/cel-go`) + `internal/filter`**

**Mechanism:** `Engine.Compile` compiles the filter string into a CEL AST and lowers it to a dialect-agnostic condition tree (`internal/filter/engine.go:47`, IR in `internal/filter/ir.go`), which each driver then renders into a SQL `WHERE` fragment plus bound args by calling `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` with its own `DialectName` — `DialectSQLite` (`store/db/sqlite/memo.go:61`), `DialectPostgres` (`store/db/postgres/memo.go:58`), `DialectMySQL` (`store/db/mysql/memo.go:69`) — so the same expression yields per-dialect SQL from one parse.

Supporting detail:

- The CEL environment and the field→column mapping come from `internal/filter/schema.go`; per-field dialect differences are declared there as an `Expressions map[DialectName]string`, e.g. `('users/' || %s)` for SQLite/Postgres vs `CONCAT('users/', %s)` for MySQL (lines 104-107), and `UNIX_TIMESTAMP(%s)` only for MySQL (line 132).
- Rendering lives in `internal/filter/render.go`, which emits parameterized SQL (placeholder counter + `args`) and collapses degenerate cases to `1 = 0` (unsatisfiable) or an empty string (trivially true) at lines 41-52.
- `now` is frozen once per `Compile` so a single filter sees one instant (`internal/filter/engine.go:17-20`).
- Drivers obtain the shared engine via `filter.DefaultEngine()` (`internal/filter/engine.go:111`).
- The same CEL filter strings are what `ShortcutService` stores as saved views — see the `Shortcut.filter` comment at `proto/api/v1/shortcut_service.proto:15-17`.
