**web/src/connect.ts; short-lived JWT access token (in-memory) + refresh token (HTTP-only cookie), plus Personal Access Tokens for programmatic clients; server/auth**

**Interceptor** — `authInterceptor` at `web/src/connect.ts:156`, installed on the shared Connect transport (`web/src/connect.ts:188`). Per request it fetches a token via `getRequestToken()` (line 124) and sets `Authorization: Bearer <token>` (line 97). On a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry` marker to prevent loops, and on failure calls `redirectOnAuthFailure()` (lines 161-177).

**Tokens it manages:**
- **Access token** — short-lived JWT held in memory (`web/src/auth-state.ts`). The interceptor also refreshes *preemptively* when it's within the expiry buffer, so public endpoints like ListMemos don't silently fall back to guest-scoped data (`web/src/connect.ts:136-147`).
- **Refresh token** — HTTP-only cookie, sent implicitly by `fetchWithCredentials` (`credentials: "include"`, line 57). Refresh goes through a dedicated interceptor-free transport and `refreshAuthClient` to avoid recursion (lines 65-72), and concurrent refreshes are deduplicated by `tokenRefreshManager` (line 51) — important because tab-focus refresh and 401-triggered refresh can race against server-side token rotation.

**Backend validation** — `server/auth`, specifically `Authenticator` (`server/auth/authenticator.go:26`): `AuthenticateByAccessTokenV2` (line 41) for the JWT, `AuthenticateByRefreshToken` (line 61, checked against the DB), and `AuthenticateByPAT` (line 102, prefix + hash lookup, expiry check, last-used recording). `resolveBearer` (line 149) picks between JWT and PAT by prefix. Token parsing/hashing lives in `server/auth/token.go`, cookie extraction in `server/auth/extract.go`.

It's wired in at three call sites so all protocols share one policy: `NewAuthorizer` (`server/router/api/v1/authz.go:34`) backs both the gRPC-Gateway middleware and the Connect `NewAuthInterceptor` (`server/router/api/v1/v1.go:68`, 137-142); the SSE handler builds its own (`server/router/api/v1/sse_handler.go:26`); and the file server does too (`server/router/fileserver/fileserver.go:115`).
