All four are defined in `server/router/api/v1/memo_service_webhooks.go` (lines 15, 20, 25, 30). Their call sites:

- **Created** — `APIV1Service.CreateMemo`, `server/router/api/v1/memo_service.go:157`
- **Updated** — `dispatchMemoUpdatedSideEffects`, `server/router/api/v1/memo_update_helpers.go:67`, itself invoked from `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`)
- **Deleted** — `APIV1Service.DeleteMemo`, `server/router/api/v1/memo_service.go:562` (fired *before* the row is removed, so the payload still resolves)
- **Comment created** — `APIV1Service.CreateMemoComment`, `server/router/api/v1/memo_service_comments.go:119`, targeting the parent memo's creator rather than the comment author

**Convergence:** the first three are thin wrappers over the shared `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which differs only in the activity-type string. That helper resolves the creator, loads their hooks via `Store.GetUserWebhooks`, and calls `webhook.PostAsync(payload)` (line 71). `DispatchMemoCommentCreatedWebhook` skips the shared helper (it already knows the recipient user ID) but lands on the same `webhook.PostAsync` at line 43.

`PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded `asyncPostQueue`, dropping with a warning if full, and workers drain it into `Post` (`internal/webhook/webhook.go:119`) — which does the JSON POST and the Standard Webhooks HMAC-SHA256 signing.
