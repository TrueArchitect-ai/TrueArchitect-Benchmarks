Inside `Store.DeleteMemo` (`store/memo.go:140-159`), before the memo row is removed:

1. **memo_relation rows where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **memo_relation rows where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **attachments linked to the memo** — listed via `ListAttachments{MemoID}` and deleted one by one with `DeleteAttachment` (`store/memo.go:148-157`)

Then `s.driver.DeleteMemo` deletes the memo row itself (`store/memo.go:158`).

One level up, the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) additionally deletes **comment memos** first — it lists `memo_relation` rows of type `MemoRelationComment` pointing at this memo and calls `Store.DeleteMemo` on each (lines 567-577), so each comment goes through the same relation/attachment cleanup. Note the handler reads reactions (line 545) only to build the webhook payload; it does not delete them.
