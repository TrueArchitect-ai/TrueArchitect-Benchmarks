**CEL (Common Expression Language, via `cel-go`) — internal/filter/** (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`)

Mechanism: the engine runs a three-phase pipeline — `parser.go` parses the CEL expression and validates it against the memo field schema in `schema.go`, converting it into a dialect-agnostic IR (`ir.go`); then `render.go` walks that IR and emits a SQL fragment plus placeholder args specialized per dialect (`DialectSQLite`, `DialectPostgres`, `DialectMySQL` — handling JSON access, boolean casts, `?` vs `$n` placeholders, `LIKE` vs `ILIKE`, `LENGTH` vs `CHAR_LENGTH`), which each driver splices into its `WHERE` clause via `engine.CompileToStatement(ctx, *find.MemoFilter, filter.RenderOptions{Dialect: ...})` — see `store/db/sqlite/memo.go:57`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go:65`.

The design is documented in `internal/filter/README.md`; the filter arrives from the RPC field declared in `proto/api/v1/memo_service.proto` and is passed down as `store.FindMemo.MemoFilter` (`store/memo.go`). The same engine also compiles shortcut filters (`server/router/api/v1/shortcut_service.go:341`).
