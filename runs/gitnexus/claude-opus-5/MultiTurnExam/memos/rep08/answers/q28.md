**Runners the server actually starts (one):**

```
s3presign.Runner — one immediate RunOnce at startup, then a time.Ticker every 12 hours
```

Started in `Server.startBackgroundRunners` (`server/server.go:151`): `s3presignRunner.RunOnce(ctx)` fires synchronously, then `go s3presignRunner.Run(s3Context)` loops on `time.NewTicker(runnerInterval)` (`server/runner/s3presign/runner.go:30`) with `runnerInterval = time.Hour * 12` (line 27), calling `RunOnce` on each tick and returning on `ctx.Done()`. It gets its own cancellable context registered in `backgroundRunnerCancels` and is tracked by `backgroundRunnerWG` for graceful shutdown. Its work (`CheckAndPresign`, line 47) pages S3-backed attachments in batches of 100 and refreshes presigned URLs.

**Unused scheduling infrastructure:**

```
server/runner/memopayload — its Runner type and RunOnce loop are never started by the server
```

`memopayload` has the same runner shape as `s3presign` — `NewRunner(store, markdownService)` at `server/runner/memopayload/runner.go:19` and `RunOnce` at line 27, documented as "rebuilds the payload of all memos" — but nothing constructs it. `grep` for `memopayload` across the repo shows only two call sites, both to the standalone helper `RebuildMemoPayload` (line 74), invoked inline from the request path: `server/router/api/v1/memo_service.go:108` (in `CreateMemo`) and `:447` (in `UpdateMemo`). So payload rebuilding happens synchronously per memo write; the batch runner and its `RunOnce` sweep are dead scheduling infrastructure. Note there is no `Run`/ticker method on it at all — only `RunOnce` — so it was never a periodic runner, just an unwired one-shot backfill.

**Two other background goroutine sets, if you count them as workers** (neither is a `server/runner` and neither is scheduled by `startBackgroundRunners`):

- **Webhook dispatch pool** — `internal/webhook/webhook.go:42`: a package `init()` spawns 4 goroutines draining a 128-slot `asyncPostQueue`. Trigger is event-driven (`webhook.PostAsync` from memo create/update/delete/comment), not timed; a full queue drops the delivery with a warning.
- **SSE hub** — `server/router/api/v1/sse_hub.go`; per-client goroutines created on `Subscribe` when a browser connects to `GET /api/v1/sse`, driven by broadcasts rather than a schedule. Shut down via `sseHub.Close()` in `closeLongLivedConnections` (`server/server.go`), since long-lived SSE requests don't drain on `http.Server.Shutdown`.
