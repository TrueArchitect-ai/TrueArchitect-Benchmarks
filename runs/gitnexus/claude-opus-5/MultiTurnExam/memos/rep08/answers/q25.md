**Engine: CEL (Google Common Expression Language), via `cel-go` — `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`)**

**Mechanism:** A three-phase pipeline — `cel-go` parses the expression and type-checks it against the memo-specific CEL environment in `internal/filter/schema.go`, `internal/filter/parser.go` normalizes the CEL AST into a dialect-agnostic IR (`internal/filter/ir.go`), and `internal/filter/render.go` walks that IR to emit a SQL fragment plus bind args for the requested `DialectName`, which the dialect driver appends to its `WHERE` clause.

Supporting detail:

- **Where it's invoked.** Each dialect's `ListMemos` calls `filter.DefaultEngine()` then `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` — e.g. `store/db/postgres/memo.go:55-60` passes `filter.DialectPostgres`; the sqlite (`store/db/sqlite/memo.go:54`) and mysql (`store/db/mysql/memo.go:62`) versions pass their own constants. The helper is `internal/filter/helpers.go:9`.
- **Dialect constants.** `DialectSQLite`, `DialectMySQL`, `DialectPostgres` at `internal/filter/schema.go:14-16`.
- **How dialect differences are encoded.** `schema.go` maps each filter field to a backing column plus a per-dialect `Expressions` map — e.g. `creator` renders as `('users/' || %s)` for SQLite/Postgres but `CONCAT('users/', %s)` for MySQL (`schema.go:104-107`), and timestamp fields use `UNIX_TIMESTAMP(%s)` on MySQL vs. passthrough elsewhere (`schema.go:130-148`). The renderer handles the rest: `?` placeholders for SQLite/MySQL vs. `$n` for Postgres (offset-tracked so it composes with pre-existing args), `JSON_EXTRACT`/`->>` variants for the `memo.payload` JSON column, `LIKE` vs `ILIKE`, and tag membership as `LIKE` (SQLite) / `JSON_CONTAINS` (MySQL) / `@>` (Postgres).
- **Safety property.** Only fields declared in the schema can appear in a filter, and values always leave as bound placeholders rather than inlined literals — so user filter strings can't inject SQL.
- **Docs.** `internal/filter/README.md` describes the pipeline and per-file responsibilities; `internal/filter/MAINTENANCE.md` covers extending it. The CEL environment variables (`content`, `creator`, `creator_id`, `created_ts`, …) are declared at `internal/filter/schema.go:232+`.

The same filter syntax is what `ShortcutService` stores — a shortcut is a saved CEL filter string meant to be passed straight to `ListMemos` (`proto/api/v1/shortcut_service.proto:15-17`).
