**Convergence for delivery:** `webhook.PostAsync` in **`internal/webhook/webhook.go:184`**.

The first three funnel through the shared helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:49`), which resolves the memo's creator, loads `Store.GetUserWebhooks(creatorID)`, builds a payload via `convertMemoToWebhookPayload` (line 76), stamps `ActivityType`/`URL`/`SigningSecret`, and calls `PostAsync`. `DispatchMemoCommentCreatedWebhook` doesn't use that helper — it takes `relatedMemoCreatorID` explicitly so the notification goes to the *parent* memo's owner rather than the comment author — but it ends at the same `webhook.PostAsync`.

From there, `PostAsync` enqueues onto the bounded 128-slot `asyncPostQueue`, drained by 4 goroutines started in `internal/webhook/webhook.go:42`, each calling `webhook.Post` (line 120) for the actual signed HTTP POST. Deletion is worth noting for ordering: `DeleteMemo` dispatches the webhook *before* the rows are removed, so the payload still reflects the memo's state.
