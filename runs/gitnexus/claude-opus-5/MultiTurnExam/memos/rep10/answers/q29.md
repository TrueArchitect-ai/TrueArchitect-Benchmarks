**web/src/connect.ts (with token storage in web/src/auth-state.ts); short-lived JWT access tokens (Authorization: Bearer) + rotating refresh tokens in an HttpOnly cookie, plus personal access tokens for API clients; server/auth**

- **Interceptor:** `authInterceptor` at `web/src/connect.ts:156` — attaches `Authorization: Bearer <token>` to every Connect request, proactively refreshes when the token is near expiry (`getRequestToken`, line 121), and on a `Code.Unauthenticated` response refreshes once and retries with an `X-Retry` marker, redirecting to login if that fails. It's installed on the shared transport at line 187. A second, interceptor-free `refreshTransport`/`refreshAuthClient` (lines 64-72) exists to avoid recursion during refresh, and concurrent refreshes are deduped by `tokenRefreshManager` (line 30).
- **Tokens:** access tokens are held in `localStorage` via `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken`/`isTokenExpired`); the refresh token is issued as an HttpOnly cookie by `doSignIn` (`server/router/api/v1/auth_service_session.go:27-46`) and rotated on each `RefreshToken` call (line 113). Personal access tokens are the third kind, for non-browser clients.
- **Backend validation:** the `server/auth` package — `Authenticator.AuthenticateByAccessTokenV2` (`server/auth/authenticator.go:41`), `AuthenticateByRefreshToken` (line 61, checks the stored token record), `AuthenticateByPAT` (line 102), and the header/cookie entry points `AuthenticateToUser` / `Authenticate` (lines 190, 213); JWT generation and parsing live in `server/auth/token.go`, extraction helpers in `server/auth/extract.go`. It is invoked from the Connect interceptors (`server/router/api/v1/connect_interceptors.go`) and from the grpc-gateway middleware in `server/router/api/v1/v1.go`.
