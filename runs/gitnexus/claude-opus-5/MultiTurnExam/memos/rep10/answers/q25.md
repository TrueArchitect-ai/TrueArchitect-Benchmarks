**CEL (Common Expression Language, via `github.com/google/cel-go`) + `internal/filter/` (engine at `internal/filter/engine.go`, CEL env/schema at `internal/filter/schema.go`)**

**Mechanism:** the filter string is CEL-compiled into an AST (`Engine.Compile`, `internal/filter/engine.go:47`), lowered into a dialect-agnostic condition tree (`buildCondition` in `internal/filter/parser.go`, node types in `internal/filter/ir.go`), and then each dialect driver renders that same tree into its own SQL `WHERE` fragment plus bound args by calling `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect*, &where, &args)` — e.g. `store/db/sqlite/memo.go:57-61` with `filter.DialectSQLite`, and the equivalents in `store/db/postgres/memo.go` and `store/db/mysql/memo.go` — with the per-dialect differences (JSON extraction, `?`/`$n` placeholders, string-length function) handled in the `DialectName` switches in `internal/filter/render.go`.

The API layer passes the request's `filter` through to `store.FindMemo.Filters` in `APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:178`); background on the design is in `internal/filter/README.md` and `internal/filter/MAINTENANCE.md`.
