**Runners the server actually starts**

```
s3presign.Runner — RunOnce at startup, then a time.Ticker every 12h (server/server.go:161-172; interval at server/runner/s3presign/runner.go:27, loop at :29-41)
store/cache janitor goroutine — time.Ticker on the cache's CleanupInterval, started when each cache is constructed (store/cache/cache.go:201)
SSE heartbeat — per-connection time.Ticker, one goroutine per connected browser, not a global runner (server/router/api/v1/sse_handler.go:64)
```

`startBackgroundRunners` (`server/server.go:154-174`) starts exactly one entry in the background-runner group: the S3 presign runner, with its own cancellable context and a WaitGroup used by `Shutdown` (`server/server.go:133-151`). It refreshes expiring S3 presigned attachment URLs (`s3presign.Runner.CheckAndPresign`, `server/runner/s3presign/runner.go:47`).

**Unused / non-runner infrastructure**

- **`internal/scheduler` is entirely unused by the server.** It's a full cron-style scheduler package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go` plus a README and examples), but grep finds no import of `github.com/usememos/memos/internal/scheduler` anywhere outside its own package and tests. The one runner that does exist rolls its own `time.Ticker` instead.
- **`server/runner/memopayload` has a `Runner` with `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19`, `:27`) that is never instantiated.** Only the package-level helper `RebuildMemoPayload` is used, called synchronously from the memo create/update handlers (`server/router/api/v1/memo_service.go:108`, `:447`). So the backfill runner is dead code even though its package is imported.

Not a scheduled runner but worth noting: PAT last-used timestamps are written in a fire-and-forget goroutine per request (`server/auth/authenticator.go:180`).
