**Server-Sent Events (SSE) over `GET /api/v1/sse`; server/router/api/v1/sse_hub.go (endpoint in sse_handler.go); handlers below**

Mechanism — an in-process `SSEHub` fans events out to subscribed browser connections. Event types are `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted` (`server/router/api/v1/sse_hub.go:14-21`); each `SSEEvent` carries `Visibility`/`CreatorID` for server-side delivery filtering (lines 23-33). The HTTP endpoint is registered by `RegisterSSERoutes` and served by `handleSSE`, with Bearer-token auth and a 30s heartbeat (`server/router/api/v1/sse_handler.go:15-40`), mounted from `server/router/api/v1/v1.go:125`. Event construction helpers live in `server/router/api/v1/sse_event_helpers.go`.

Handlers that call `s.SSEHub.Broadcast`:
- `APIV1Service.CreateMemo` — `server/router/api/v1/memo_service.go:163`
- `APIV1Service.DeleteMemo` — `server/router/api/v1/memo_service.go:585`
- `APIV1Service.CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:126`
- `APIV1Service.UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:106`
- `APIV1Service.DeleteMemoReaction` — `server/router/api/v1/reaction_service.go:161`
- `APIV1Service.dispatchMemoUpdatedSideEffects` — `server/router/api/v1/memo_update_helpers.go:71`, the shared "memo.updated" path invoked by `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`)

Note `CreateMemoComment` also suppresses the inner `CreateMemo` broadcast via `withSuppressSSE` so a comment emits one `memo.comment.created` event rather than a duplicate `memo.created` (`server/router/api/v1/memo_service_comments.go:56`).
