**web/src/connect.ts (with token storage in web/src/auth-state.ts); JWT access token + refresh token (HTTP-only cookie) + Personal Access Tokens for programmatic clients; server/auth**

Frontend side — `authInterceptor` in `web/src/connect.ts:156-178` is attached to the Connect transport (line 188). Per request it fetches a token via `getRequestToken()` and sets `Authorization: Bearer <token>` (lines 97-100, 124-150); on a `Code.Unauthenticated` response it refreshes once, marks the retry with an `X-Retry` header to prevent loops, and redirects to login if the refresh fails. The refresh call itself goes through a separate interceptor-free client (`web/src/connect.ts:65-72`) to avoid recursion, and `createTokenRefreshManager` (line 30) dedupes concurrent refreshes. All fetches use `credentials: "include"` (line 57-62) so the refresh cookie is sent.

Tokens:
- **Access token** — JWT, 15-minute lifetime, audience `user.access-token`; held in memory + `localStorage` (`memos_access_token` / `memos_token_expires_at`) and shared across tabs over a `BroadcastChannel` (`web/src/auth-state.ts:1-50`); pre-emptively refreshed within a 30s buffer for requests and 2min on tab focus (lines 18-19). Constants at `server/auth/token.go:35-40`.
- **Refresh token** — 30-day JWT, audience `user.refresh-token`, delivered as the `memos_refresh` cookie (`server/auth/token.go:42-49`), exchanged via `AuthService.RefreshToken` (`web/src/connect.ts:74-83`).
- **Personal Access Token (PAT)** — long-lived, prefix `memos_pat_`, for programmatic access (`server/auth/token.go:10, 51-52`).

Backend validation — package **`server/auth`** (`authenticator.go`, `token.go`, `extract.go`, `context.go`). `Authenticator` is the single source of truth used by the Connect interceptor, the gRPC-gateway middleware, and the file server (`server/auth/authenticator.go:17-36`); `AuthenticateByAccessTokenV2` does stateless JWT validation (line 40), `AuthenticateByRefreshToken` validates against the DB (line 61), and PATs are looked up by hash (`Store.GetUserByPATHash`, `store/user_setting.go:128`). It's wired in at `server/router/api/v1/v1.go:68` (`NewAuthorizer`) for both protocols and at `server/router/api/v1/sse_handler.go:25` for SSE.
