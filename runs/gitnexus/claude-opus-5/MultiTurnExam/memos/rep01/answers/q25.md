**CEL (Google Common Expression Language) via `github.com/google/cel-go` — engine in `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`); go.mod:13**

Mechanism: the filter string from `ListMemosRequest` is compiled by `Engine.Compile` into a CEL AST (`internal/filter/engine.go:47-69`) and lowered by `buildCondition` into a dialect-agnostic `Condition` tree (`internal/filter/parser.go:18`), which the `renderer` then emits as a SQL `WHERE` fragment plus bound args for a specific `DialectName` — `sqlite` / `mysql` / `postgres` (`internal/filter/render.go:10-56`, dialect constants at `internal/filter/schema.go:14-16`); each driver's `ListMemos` calls `filter.DefaultEngine()` then `filter.AppendConditions(..., filter.DialectXxx, &where, &args)` to append the rendered fragment to its query (`store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:58`, `store/db/mysql/memo.go:69`; helper at `internal/filter/helpers.go:9-25`).

Per-dialect differences are data, not code paths: `Schema` fields carry an `Expressions map[DialectName]string` giving the dialect-specific SQL for a field (e.g. `CONCAT('users/', %s)` on MySQL vs `('users/' || %s)` on SQLite/Postgres, `UNIX_TIMESTAMP(%s)` on MySQL — `internal/filter/schema.go:104-148`), and the renderer also handles placeholder style/offset (`RenderOptions.PlaceholderOffset`). Trivially-true filters render to an empty string (skipped) and unsatisfiable ones to `1 = 0` (`internal/filter/render.go:41-50`). The API-side entry point is `server/router/api/v1/memo_service_filter.go`; a parallel `DefaultAttachmentEngine`/`NewAttachmentSchema` exists for attachment filters (`internal/filter/engine.go:119-123`).
