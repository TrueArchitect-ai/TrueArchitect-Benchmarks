**Engine: Google CEL (`github.com/google/cel-go`) — `internal/filter/`**

**Mechanism:** The filter string is parsed by a CEL environment whose variables/functions are declared in `internal/filter/schema.go` (`content`, `creator`, `creator_id`, `tag`, `visibility`, time helpers, …), compiled by `Engine.CompileToStatement` (`internal/filter/engine.go:25`, `:57`) into a dialect-neutral IR (`internal/filter/ir.go`), and then rendered to a parameterized SQL fragment plus args by `internal/filter/render.go`, which switches on `DialectSQLite` / `DialectPostgres` / `DialectMySQL` at every point the SQL differs (JSON extraction, placeholder style `?` vs `$N`, string ops, etc.).

Each dialect driver calls into it at query time — `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` (`internal/filter/helpers.go:9`), invoked from `store/db/sqlite/memo.go:61`, `store/db/postgres/memo.go:58`, and `store/db/mysql/memo.go:69` — appending each compiled fragment as a parenthesized `WHERE` clause with its bound arguments, so user input never reaches the SQL text.

Entry point on the API side is `server/router/api/v1/memo_service_filter.go`, which validates the `ListMemosRequest.filter` before it becomes `store.FindMemo.Filters`. `internal/filter/README.md` and `MAINTENANCE.md` document the supported surface.
