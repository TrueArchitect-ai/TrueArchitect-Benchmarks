**APIV1Service.SignIn — server/router/api/v1/auth_service.go**

That's where the actual RPC logic lives (`server/router/api/v1/auth_service.go:51`): it dispatches on the request's credential type (password vs. SSO), looks up/authenticates the user, and calls `doSignIn` to mint the session token.

Two related pieces in the same package, in case you're tracing the call path:
- `ConnectServiceHandler.SignIn` (`server/router/api/v1/connect_services.go:78-82`) is a thin Connect-protocol wrapper that unwraps `req.Msg` and delegates to `APIV1Service.SignIn`, wrapping it in `connectWithHeaderCarrier` so the handler can set response headers (the session cookie).
- `APIV1Service.doSignIn` (`server/router/api/v1/auth_service_session.go:24`) creates the session and returns the token and expiry.
