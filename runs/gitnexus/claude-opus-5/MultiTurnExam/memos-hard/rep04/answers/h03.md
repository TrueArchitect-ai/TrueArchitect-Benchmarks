**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- **Abstraction** — `internal/idp/idp.go`. It's a deliberately thin package: the only thing it defines is the `IdentityProviderUserInfo` struct (`internal/idp/idp.go:3-8`) with `Identifier`, `DisplayName`, `Email`, `AvatarURL`. That's the common shape every provider must normalize its user profile into. Note there is no Go `interface` here — the abstraction is the shared return type plus the provider-type enum, not a polymorphic contract.
- **Implementation** — `internal/idp/oauth2/oauth2.go`, "Package oauth2 implements the OAuth2 identity provider integration" (line 1). It defines `IdentityProvider` wrapping a `storepb.OAuth2Config` (`:20`), with `NewIdentityProvider` validating required fields (`:27`), `ExchangeToken` performing the code→token exchange with optional PKCE `code_verifier` (`:46`), and `UserInfo` fetching and field-mapping the profile into `idp.IdentityProviderUserInfo`.

OAuth2 is the only concrete protocol that ships. The store enum has exactly one non-zero member, `IdentityProvider_OAUTH2 = 1` (`proto/gen/store/idp.pb.go:28`), and the SSO dispatch in `server/router/api/v1/auth_service_sso.go:120-134` branches on that single type with no other arm — so a provider of any other type would fall through with a nil `userInfo`. Config is persisted through `store/idp.go` with per-dialect implementations in `store/db/{sqlite,postgres,mysql}/idp.go`, and exposed over the API by `server/router/api/v1/idp_service.go`.
