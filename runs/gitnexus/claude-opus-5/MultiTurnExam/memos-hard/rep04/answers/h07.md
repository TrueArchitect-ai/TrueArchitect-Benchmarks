Notes on each hop:

- **Route registration** — `FileServerService.RegisterRoutes` (`server/router/fileserver/fileserver.go:121`) mounts the `/file` group; the service itself is constructed and wired into Echo at `server/server.go:81-82`.
- **Where the browser gets the URL** — `convertUserFromStore` (`server/router/api/v1/user_service_converters.go:16`) rewrites the raw base64 avatar into `/file/{name}/avatar` at line 36 so the API response stays small; the actual bytes are fetched separately over this file route.
- **`serveUserAvatar`** (`:168`) does four things before returning bytes: gates anonymous access when `!s.Profile.AllowAnonymous()` (`:173-181`), reads `:identifier`, looks up the user, then decodes `user.AvatarURL` via `parseDataURI` (`:737`) and enforces `avatarAllowedTypes` (`:75`, checked at `:201`) before `c.Blob` (`:209`). So the "stored data" is the base64 data URI in the user row, not a file on disk or an attachment blob.
- **`getUserByUsername`** (`:715`) is a one-line adapter: `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`.
- **`Store.GetUser`** (`store/user.go:148`) consults `s.userCache` only when the lookup is by ID; a username lookup always falls through to `ListUsers`, then populates the cache keyed by ID (`:167`).
- **`Store.ListUsers`** (`store/user.go:136`) delegates to `s.driver.ListUsers` and warms the cache for each row.
- **Driver layer** — the concrete implementation is selected by `NewDBDriver` (`store/db/db.go:14`); each dialect builds the `SELECT` including `avatar_url`: sqlite `store/db/sqlite/user.go:88` (column list at `:159`), postgres `store/db/postgres/user.go:150`, mysql `store/db/mysql/user.go:147`.
