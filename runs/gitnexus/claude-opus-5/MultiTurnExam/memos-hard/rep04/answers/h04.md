**No.** The MySQL driver is constructed only inside the factory.

Evidence:

1. **Exactly one importer.** `grep -rn "store/db/mysql" --include=*.go .` across the whole repo returns a single hit: `store/db/db.go:8`. No other Go file — production or test — imports the package, so no other file can name `mysql.NewDB` or the `mysql.DB` type at all.
2. **Exactly one call site.** `mysql.NewDB(profile)` appears only at `store/db/db.go:22`, inside the `switch profile.Driver` in `NewDBDriver` (`store/db/db.go:14`), alongside the `sqlite` and `postgres` arms.
3. **The constructor itself is single-definition.** `store/db/mysql/mysql.go:20` is the only `func New*` in the package; it builds the value at `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`).

Two things that turn up in a naive grep but are *not* counterexamples:

- `store/db/mysql/auth_config_test.go:12` does `db := &DB{}`, but that's an in-package test (`package mysql`) constructing a zero-value struct to exercise a helper — no import, no factory bypass from outside.
- `store/test/containers.go:16` imports `github.com/go-sql-driver/mysql`, which is the upstream `database/sql` driver library, not this repo's `store/db/mysql` package. Same for `store/db/mysql/mysql.go:7` and `auth_config.go:7`.

All real construction routes go through the factory: `NewDBDriver` is called from `store/test/store.go:28`, `store/test/store.go:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` — the driver choice always resolves from `profile.Driver`.
