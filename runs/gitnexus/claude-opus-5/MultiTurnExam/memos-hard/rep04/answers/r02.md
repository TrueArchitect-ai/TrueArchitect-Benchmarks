**Premise correction: there is no per-user API rate-limiting middleware in this repository.** Nothing is registered, so there are no request limits to report.

Evidence:

- Grepping all Go sources for `ratelimit`, `rate_limit`, `rate limit`, `throttl`, and `golang.org/x/time/rate` yields exactly one hit, and it's an aspirational comment in unrelated docs: "Rate limit email sending to prevent abuse" — `internal/email/doc.go:86`. No implementation follows it.
- `go.mod` declares no rate-limiter or throttling dependency (no `golang.org/x/time`, no `echo` ratelimit middleware, no token-bucket library).
- The full set of registered Echo middleware is three entries: `middleware.Recover()` (`server/server.go:51`), `newCORSMiddleware(profile)` (`server/server.go:52`), and the static/SPA handlers for the frontend (`server/router/frontend/frontend.go:54`, `:59`). Echo's built-in `middleware.RateLimiter` is never used.
- The Connect/gRPC interceptor chain is likewise four entries, none of them a limiter: metadata, logging, recovery, auth — `server/router/api/v1/v1.go:133-138`.

**What does exist**, in case one of these is what you're after — all of them are global or per-request caps, not per-user rate limits:

| mechanism | value | path |
|---|---|---|
| Max API request body size | 256 MiB (`256 << 20`) | `server/router/api/v1/v1.go:20`, enforced at `:126`, `:141`, `:144` |
| Concurrent thumbnail generation | 3 (weighted semaphore) | `server/router/api/v1/v1.go:59`; fileserver copy at `fileserver.go:46`, `:116` |
| Concurrent image processing | 2 | `server/router/api/v1/v1.go:60` |
| Memo content length | instance setting, read per request | `server/router/api/v1/memo_service.go:595` (`getContentLengthLimit`), applied at `:104` and `:443` |
| Outbound webhook queue depth | 128, drops on overflow | `internal/webhook/webhook.go:39` |

The semaphores bound concurrency process-wide regardless of who is calling, and the byte/length caps are per-request. None of them tracks a per-user request count over time, so an authenticated client can issue unlimited requests as long as each one fits within these bounds. If you need per-user rate limiting, it would have to be added — the natural insertion point is the interceptor chain at `server/router/api/v1/v1.go:133`, after `NewAuthInterceptor` has resolved the caller identity.
