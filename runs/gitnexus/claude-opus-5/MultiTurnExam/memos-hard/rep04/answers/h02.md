**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path.** Memo mutations call `DispatchMemo*Webhook` in `server/router/api/v1/memo_service_webhooks.go:15-46`, which build a `WebhookRequestPayload` per registered user hook and hand it to `webhook.PostAsync` (`internal/webhook/webhook.go:184`). That only enqueues onto a bounded 128-slot channel (dropping with a warning when full). The actual HTTP request is executed by `webhook.Post` (`internal/webhook/webhook.go:120`), running on one of 4 worker goroutines started in `init` (`internal/webhook/webhook.go:42-55`). `Post` marshals the JSON body, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and issues `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

**Protection.** Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against the parsed `reservedCIDRs` list — loopback, RFC-1918, link-local incl. `169.254.169.254` IMDS, and IPv6 equivalents (`internal/webhook/validate.go:14-23`):

1. **Dial-time** (the one that actually protects delivery): `safeClient` is built with a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`:59`) resolves the host itself and refuses the connection if *any* resolved address is reserved. Because it checks at dial time rather than at save time, it also defeats DNS rebinding — the comment at `:29-31` says so explicitly.
2. **Admission-time**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a webhook is created or updated, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

One caveat worth flagging: the `AllowPrivateIPs` escape hatch (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to always return false, disabling both layers. The changelog records it as an `--allow-private-webhooks` flag (`CHANGELOG.md:121`), but I find no assignment to that variable anywhere in the current tree outside its declaration and tests — so in this checkout it is effectively always `false` and the guard is always on. If that flag is meant to still exist, its wiring is missing.
