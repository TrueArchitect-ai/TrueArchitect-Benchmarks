**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never used by the server.** No such schedule exists to report a time for.

Two separate false premises:

**1. The cron scheduler runs nothing.** `internal/scheduler` is a complete, working "GitHub Actions-inspired cron job scheduler" (`internal/scheduler/doc.go:1`) with a cron expression parser (`internal/scheduler/parser.go`), job type (`internal/scheduler/job.go`), and Recovery/Logging/Timeout middleware (`internal/scheduler/middleware.go`). But the only files importing `github.com/usememos/memos/internal/scheduler` are its own tests — `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No production code constructs a scheduler or registers a job; every `Register(&scheduler.Job{...})` call site in the repo is a test or a doc example. The package is dead weight from the server's perspective.

Cron strings you may have seen, like `ParseCronExpression("0 9 * * *") // 9 AM` (`internal/scheduler/integration_test.go:183`), are test fixtures exercising the parser, not registered schedules.

**2. There is no database-cleanup job anywhere**, scheduled or otherwise — no vacuum, prune, purge, or retention sweep. Deletion is entirely event-driven and synchronous: memo deletion cascades relations and attachments inside `store.DeleteMemo` (`server/router/api/v1/memo_service.go:579`), and user deletion runs its explicit multi-table transaction in `store/db/{sqlite,postgres,mysql}/user_delete.go` (see h05), with S3 blob cleanup handled inline at `server/router/api/v1/user_service.go:421-450`.

**What the server actually schedules on a timer** is one job, and it isn't cleanup: the S3 presign refresher (h01), which uses a plain `time.Ticker` at a 12-hour interval rather than a cron expression — `server/runner/s3presign/runner.go:27` (`runnerInterval = time.Hour * 12`), started at `server/server.go:162-171`. There is no wall-clock time associated with it; the first run happens at process startup and every 12 hours thereafter, so it drifts with restarts.

The only other recurring background work is the in-memory cache sweep every 5 minutes (`store/store.go:42`, loop at `store/cache/cache.go:83`) — that expires cached objects in RAM, not database rows.
