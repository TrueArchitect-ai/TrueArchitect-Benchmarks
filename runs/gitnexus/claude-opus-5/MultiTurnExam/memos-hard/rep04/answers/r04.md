**Premise correction: neither. There is no message broker in this repository** — no NATS, no RabbitMQ, no AMQP, Kafka, SQS, or Redis pub/sub. A repo-wide grep across all Go sources, `go.mod`, and `go.sum` for those names returns nothing (the single `go.sum` line that matches is a coincidental substring inside an `xxhash` base64 hash). Consequently there is no queue *declared* anywhere in the infrastructure sense — no exchange, subject, topic, or binding.

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool, entirely inside `internal/webhook`.**

- **The "queue"** is a package-level channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`. Capacity 128, values are `*WebhookRequestPayload` (`:79`), and it lives in the same process as the API server.
- **The "workers"** are 4 goroutines started in the package `init()` — `internal/webhook/webhook.go:42-55`. Each ranges over the channel and calls `Post(payload)` (`:46`), logging a warning on failure. They start when the package is first linked in, not via explicit server wiring, and they're never shut down.
- **The producer** is `PostAsync` (`internal/webhook/webhook.go:184`), called from the memo webhook dispatchers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

Three consequences that a real broker would change, worth stating plainly:

1. **Overflow drops silently-ish.** `PostAsync` uses a non-blocking `select` with a `default` branch (`internal/webhook/webhook.go:189-195`): if all 128 slots are full, the payload is discarded with a `slog.Warn` and never retried.
2. **No persistence, no redelivery.** The channel is memory-only, so a restart or crash loses everything queued. `Post` returns an error on non-2xx (`:163`) but nothing re-enqueues it — delivery is strictly at-most-once, single-attempt.
3. **No cross-instance coordination.** Each replica has its own channel and its own 4 workers; there is no shared queue, so nothing is load-balanced or deduplicated across instances.

Actual delivery is performed by `Post` (`internal/webhook/webhook.go:120`) over the SSRF-guarded `safeClient` with a 30-second timeout (`:27`, `:32-37`).
