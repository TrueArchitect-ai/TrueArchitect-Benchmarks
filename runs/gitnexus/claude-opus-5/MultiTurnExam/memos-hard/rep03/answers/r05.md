**Premise correction: this project has no GraphQL API. There is no `.graphql`/`.gql`/`.graphqls` schema file anywhere, no gqlgen or graphql-go dependency in `go.mod`, and no Apollo/urql/Relay client in `web/package.json` — a case-insensitive search for `graphql` across Go sources, module files, and the frontend manifest returns zero matches.**

**Actual API surface: Protocol Buffers / gRPC, exposed over three transports plus a generated OpenAPI document.**

**Schema definitions** — `proto/api/v1/`, nine `.proto` files:

| File | Service |
|---|---|
| `proto/api/v1/memo_service.proto` | `MemoService` (declared at `:17`) |
| `proto/api/v1/user_service.proto` | `UserService` |
| `proto/api/v1/auth_service.proto` | `AuthService` |
| `proto/api/v1/attachment_service.proto` | `AttachmentService` |
| `proto/api/v1/instance_service.proto` | `InstanceService` |
| `proto/api/v1/idp_service.proto` | `IdentityProviderService` |
| `proto/api/v1/shortcut_service.proto` | `ShortcutService` |
| `proto/api/v1/ai_service.proto` | `AIService` |
| `proto/api/v1/common.proto` | shared messages |

Internal persistence schemas live separately under `proto/store/` (e.g. `memo.proto`, `idp.proto`, `attachment.proto`).

**Code generation** is driven by buf (`proto/buf.gen.yaml`), which runs five plugins: protobuf-go and grpc-go (Go types + gRPC stubs → `proto/gen`), connectrpc-go (Connect handlers), grpc-gateway (JSON/REST transcoding), gnostic-openapi (an OpenAPI spec), and buf/es targeting TypeScript into `web/src/types/proto` — which is how the frontend gets its typed client, with no GraphQL layer in between.

**Runtime surfaces**, all implemented by `APIV1Service` and registered in `RegisterGateway` (`server/router/api/v1/v1.go:95`):

- **Connect RPC** — handlers in `proto/gen/api/v1/apiv1connect/`, wired in `server/router/api/v1/connect_services.go`, with metadata/logging/recovery interceptors (`server/router/api/v1/connect_interceptors.go`).
- **gRPC-Gateway REST/JSON** — HTTP mappings declared per-RPC via `google.api.http` annotations in the `.proto` files.
- **Plain HTTP side-routes** outside the proto surface: the file server (`server/router/fileserver/fileserver.go:121-124`), RSS feeds (`server/router/rss/rss.go:67`), and frontend/sitemap (`server/router/frontend/frontend.go`).

**The closest thing to a "public API schema document"** is the generated OpenAPI spec at `proto/gen/openapi.yaml`, embedded into the binary via `//go:embed` and served through `proto.OpenAPIYAML()` (`proto/openapi_embed.go:5-11`).
