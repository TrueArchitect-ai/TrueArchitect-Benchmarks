**`webhook.Post` — `internal/webhook/webhook.go:120` (async wrapper `PostAsync` at `internal/webhook/webhook.go:184`); SSRF guard via `safeDialContext` / `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path.** Memo create/update/delete events call `webhook.PostAsync(payload)` from `server/router/api/v1/memo_service_webhooks.go:43` and `:71`. `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel (`webhook.go:39`), dropping with a warning when full. Four worker goroutines started in `init()` (`webhook.go:42-55`) drain the queue and call `Post`, which is where the actual HTTP request executes: it marshals the payload, optionally attaches Standard Webhooks HMAC-SHA256 headers (`webhook.go:133-150`), and issues `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

**Protection — two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`):**

1. *Dial-time (the one that actually protects delivery).* `safeClient` is built with a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`webhook.go:59-77`) resolves the host itself and refuses the connection if **any** resolved IP falls in a reserved range. Because the check happens at dial time on every request, it also defeats DNS rebinding and redirect-based bypasses.
2. *Registration-time.* `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and hostnames resolving to reserved IPs when a user saves a webhook — called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

The blocked ranges are the `reservedCIDRs` list at `internal/webhook/validate.go:14-23`: IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (covers cloud IMDS at 169.254.169.254), plus IPv6 loopback, unique-local, and link-local. They're parsed once into `reservedNetworks` in `init()` (`validate.go:28-36`).

Two things worth flagging:

- There's an escape hatch, `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`), which short-circuits `isReservedIP` and disables *both* layers. Grepping the repo, nothing outside the package ever assigns it — no flag, env var, or profile field — so in the shipped binary it is always `false`. It's a test/embedder hook, not a user-facing setting.
- `safeDialContext` resolves via `net.DefaultResolver.LookupHost` and then dials `net.JoinHostPort(host, port)`, i.e. it re-resolves rather than dialing the exact IP it vetted. That's a narrow TOCTOU window, though a rebind would have to land between the two resolutions in the same dial.
