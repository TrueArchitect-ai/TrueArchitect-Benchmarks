**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never instantiated by the running server — so there is no scheduled time to report.**

Two separate corrections, both load-bearing:

**1. The cron scheduler is dead code in production.** `internal/scheduler` is a complete, self-contained cron implementation (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`, with a README and doc comments). But grepping for imports of `github.com/usememos/memos/internal/scheduler` outside the package itself yields only two files — `internal/scheduler/integration_test.go:13` and `internal/scheduler/example_test.go:10`. Nothing in `cmd/`, `server/`, or `store/` imports it. Likewise, the only `.Register(` call anywhere in non-test code is inside a doc comment (`internal/scheduler/doc.go:14`). `scheduler.New` is never called by the server, so no cron expression is ever parsed or fired at runtime.

**2. The "daily cleanup at 2 AM" that looks like an answer is illustrative documentation, not configuration.** `internal/scheduler/doc.go:14-21` contains:

```go
s.Register(&scheduler.Job{
    Name:     "daily-cleanup",
    Schedule: "0 2 * * *", // 2 AM daily
    Handler: func(ctx context.Context) error {
        // Your cleanup logic here
        return nil
    },
})
```

That's a usage example in a package doc comment with an empty handler body — there's no such job registered anywhere, and no database-cleanup logic behind it.

**What actually runs on a schedule:** exactly one background job, the S3 presign refresher — `s3presign.Runner`, ticking every 12 hours via `time.Ticker` (`server/runner/s3presign/runner.go:27`, `:29-41`), started at `server/server.go:162-171`. It uses a plain ticker, not the cron package.

**Database cleanup that exists, but is event-driven rather than scheduled:** deletions cascade synchronously inside the triggering request — e.g. `DeleteUser` removes reactions, attachments, memos, and inboxes in one transaction (`store/db/sqlite/user_delete.go:92`), and memo deletion cleans up relations and attachments (`server/router/api/v1/memo_service.go:579`). The only recurring cleanup in the process is the in-memory cache sweeper, every 5 minutes (`store/store.go:42`, `store/cache/cache.go:200`) — which touches no database.
