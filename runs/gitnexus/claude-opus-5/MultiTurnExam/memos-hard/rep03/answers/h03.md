**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation — OAuth2, the only concrete protocol that ships)**

Details:

- **Abstraction — `internal/idp`**, whose sole file `internal/idp/idp.go:1-8` defines the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`). Note it's a data-contract abstraction, not a Go `interface` — there is no `IdentityProvider` interface type; providers converge on this common user-info shape rather than on a method set.
- **Implementation — `internal/idp/oauth2`**, in `internal/idp/oauth2/oauth2.go`. Its `IdentityProvider` type (`oauth2.go:20`) wraps a `storepb.OAuth2Config`, and provides `NewIdentityProvider` (`oauth2.go:27`, validating required fields), `ExchangeToken` (`oauth2.go:47`, with PKCE `code_verifier` support), and `UserInfo` (`oauth2.go:83`, mapping arbitrary claims onto `idp.IdentityProviderUserInfo` via the configured `FieldMapping`).

Supporting evidence that OAuth2 is the only one:

- The stored provider-type enum has exactly two values — `TYPE_UNSPECIFIED` and `OAUTH2` (`proto/gen/store/idp.pb.go:27-28`, from `proto/store/idp.proto`).
- The only consumer outside the package is `server/router/api/v1/auth_service_sso.go`, whose dispatch is a single `if identityProvider.Type == storepb.IdentityProvider_OAUTH2` branch constructing `oauth2.NewIdentityProvider` (`auth_service_sso.go:120-133`). There's no OIDC, SAML, or LDAP package.

One behavioral note on that dispatch: if a stored provider's type is not `OAUTH2`, the branch is skipped and `userInfo` stays nil, so a non-empty `IdentifierFilter` then dereferences nil at `auth_service_sso.go:142`. Unreachable today since `OAUTH2` is the only writable type, but it's what would break first if a second provider type were added.
