Visibility is enforced in **four distinct server surfaces** (gRPC/Connect API, HTTP file server, SSE hub, and the read-only HTTP feeds), across these sites:

**gRPC / Connect API — `server/router/api/v1/`**

- `APIV1Service.checkMemoReadAccess` (shared single-memo gate; also handles archived) — `server/router/api/v1/memo_service.go:39-68`
- `APIV1Service.ListMemos` — injects `VisibilityList`/CEL filter per viewer — `server/router/api/v1/memo_service.go:218-227`
- `APIV1Service.ListMemoComments` — `checkMemoReadAccess` on the parent plus a per-comment `memoFilter` — `server/router/api/v1/memo_service_comments.go:148`, `:156-161`
- `APIV1Service.CreateMemoComment` — blocks commenting on another user's private memo — `server/router/api/v1/memo_service_comments.go:41`
- `APIV1Service.ListMemoReactions` — `server/router/api/v1/reaction_service.go:29-41`
- `APIV1Service.UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:83`
- `APIV1Service.ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:213-225`
- `APIV1Service.checkAttachmentAccess` (attachment reached via its linked memo) — `server/router/api/v1/attachment_service.go:422`, checks at `:445-452`
- `APIV1Service.ListAllUserStats` — `server/router/api/v1/user_service_stats.go:84-90`
- `APIV1Service.GetUserStats` — `server/router/api/v1/user_service_stats.go:218-220`
- `APIV1Service.GetMemoByShare` — the deliberate *bypass*: a valid, unexpired share token returns a private/protected memo without any visibility check (only archived/missing are rejected) — `server/router/api/v1/memo_share_service.go:153-192`, token validity in `getActiveMemoShare` (`:199`)

**HTTP file server — `server/router/fileserver/`**

- `FileServerService.checkAttachmentPermission` — public+anonymous fast path (`:677`), share-token fallback (`:683-689`), then private-owner check (`:699`) — `server/router/fileserver/fileserver.go:650-703`

**SSE broadcast — `server/router/api/v1/`**

- `SSEClient.canReceive` — per-subscriber delivery filter; private events go only to creator or admin, unknown visibility denied — `server/router/api/v1/sse_hub.go:134-143` (called from `SSEHub.Broadcast`, `:123`)

**Read-only HTTP feeds**

- `RSSService.GetExploreRSS` — hard-restricted to `store.Public` — `server/router/rss/rss.go:90`
- `RSSService.GetUserRSS` — hard-restricted to `store.Public` — `server/router/rss/rss.go:141`
- `FrontendService.getSitemapXML` — hard-restricted to `store.Public` — `server/router/frontend/frontend.go:150`

**Related but not view enforcement** — these use visibility to suppress *notifications* rather than gate reads: `server/notification/email.go:313-316`, `server/router/api/v1/user_service_notifications.go:309-312`, and mention gating in `server/router/api/v1/memo_mention_helpers.go:62-84`.

Two observations from the sweep: the same three-branch idiom (`!= Public` → require user → `== Private && not owner && not admin` → deny) is copy-pasted across at least five API sites rather than routed through the shared `checkMemoReadAccess`, and the admin bypass is inconsistent — `checkMemoReadAccess` (`memo_service.go:63`) does **not** grant admins access to private memos, while the reaction, attachment, and fileserver paths do via `isSuperUser(user)` / `user.Role != store.RoleAdmin`.
