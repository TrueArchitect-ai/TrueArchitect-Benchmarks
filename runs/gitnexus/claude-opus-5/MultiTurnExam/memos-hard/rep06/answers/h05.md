**Explicit Go code — not a database rule.** Reactions are deleted by hand-written `DELETE FROM reaction` statements inside the `DeleteUser` transaction, in all three drivers.

What I checked:

**1. The delete path.** `store.DeleteUser` (`store/user.go:171`) delegates to the driver's `DeleteUser`, implemented per-backend at `store/db/sqlite/user_delete.go:29`, `store/db/postgres/user_delete.go:29`, `store/db/mysql/user_delete.go:29`. Each opens a transaction and calls `deleteUserTargetsTx`, which issues two separate reaction deletions (sqlite line numbers; the other two drivers are structurally identical):

- `deleteReactionsByContentIDsTx` (`store/db/sqlite/user_delete.go:380`, called at `:96`) — `DELETE FROM reaction WHERE content_id IN (…)`, removing *everyone's* reactions on the deleted user's memos. The content IDs are built as `"memos/"+uid` by `memoContentIDsFromRefs` (`:512`), matching how `reaction.content_id` is stored; the memo set comes from a recursive CTE that also pulls in comment descendants (`:133`).
- `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:400`, called at `:102`) — `DELETE FROM reaction WHERE creator_id = ?`, removing the user's own reactions on memos belonging to anyone.

Both are batched at 500 (`deleteUserBatchSize`, `:14`) and run before the `memo` and `user` rows are deleted, all inside one transaction committed at `:51`.

Same functions at `store/db/postgres/user_delete.go:380,400` (called `:96,:102`) and `store/db/mysql/user_delete.go:417,437` (called `:96,:102`).

**2. Why it can't be a database rule.** The `reaction` table has no foreign key at all — `creator_id` and `content_id` are plain columns with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint, in every schema: `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98`. The only `ON DELETE CASCADE` in the schemas is on `memo_share.memo_id` (`store/migration/sqlite/LATEST.sql:109` and peers), which doesn't touch reactions.

On SQLite it wouldn't fire even if declared: the connection is opened with `_pragma=foreign_keys(0)` and a comment stating constraints are deliberately disabled (`store/db/sqlite/sqlite.go:40,53`).
