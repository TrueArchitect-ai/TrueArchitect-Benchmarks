**Premise correction: neither. There is no message broker in this repository — no NATS, no RabbitMQ, and no queue declaration to point at.** Searching `go.mod`/`go.sum` and all Go sources for `nats`, `rabbit`, `amqp`, `kafka`, `nsq`, `pubsub`, and `streadway` returns zero hits. No broker client is a dependency, so nothing could be consumed from one.

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool** — entirely in `internal/webhook/webhook.go`.

- **The "queue"** is a package-level buffered channel holding 128 payloads: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`). It's declared in the same `var` block as the shared HTTP client, not in any broker topology or config.
- **The "workers"** are four goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) — a `for range 4` loop, each goroutine ranging over the channel and calling `Post(payload)`, logging a warning on failure. The count is a hardcoded literal, not configurable.
- **Producers** call `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking `select` send: if the buffer is full, the default branch **drops the event** with a warning (`:189-195`). There is no retry, no dead-letter path, and no acknowledgement.
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120`), which marshals the payload, optionally signs it with HMAC-SHA256 Standard Webhooks headers, and issues `safeClient.Do(req)` at `:152` under a 30-second timeout.

Consequences worth being explicit about, since they're exactly what a broker would change: the queue lives in the server process's memory, so **pending webhooks are lost on restart or crash**, they are not shared or load-balanced across replicas (each instance has its own 128-slot buffer and 4 workers), and a burst beyond 128 in-flight items silently sheds load rather than backing up.

Producers are the memo lifecycle handlers — `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` — reaching `PostAsync` via `server/router/api/v1/memo_service_webhooks.go:43,71`.
