**Premise correction: there is no per-user API rate-limiting middleware in this repository.** Nothing is registered, so there are no request limits to report.

Evidence:

- A case-insensitive search across all Go sources for `ratelimit`, `rate_limit`, `rate limit`, `throttle`, and `RateLimiter` returns exactly one hit, and it's an unimplemented aspiration in a doc comment: `internal/email/doc.go:86` — `//   - Rate limit email sending to prevent abuse`.
- Echo's middleware chain is two entries, neither of which limits requests: `middleware.Recover()` and `newCORSMiddleware(profile)` at `server/server.go:51-52`. The only other `e.Use(...)` calls are static-file and SPA-fallback handlers in `server/router/frontend/frontend.go:54,59`.
- The Connect/gRPC interceptor chain is three entries — metadata, logging, recovery — registered at `server/router/api/v1/v1.go:133-136`. No limiter among them.
- Echo v5 ships a `middleware.RateLimiter`, and `golang.org/x/time` (which provides `rate.Limiter`) is present in `go.mod:151` — but marked `// indirect`, i.e. pulled in transitively and not imported by this codebase.

What does exist, and is easy to mistake for rate limiting, is **concurrency limiting** — bounded parallelism, not requests-per-interval, and global rather than per-user:

- `APIV1Service.thumbnailSemaphore` — `semaphore.NewWeighted(3)` and `imageProcessingSemaphore` — `semaphore.NewWeighted(2)`, both at `server/router/api/v1/v1.go:59-60`.
- `FileServerService.thumbnailSemaphore` — `semaphore.NewWeighted(maxConcurrentThumbnails)` at `server/router/fileserver/fileserver.go:116`.
- The webhook dispatch queue: a 128-slot buffered channel drained by 4 worker goroutines, which *drops* overflow rather than throttling callers (`internal/webhook/webhook.go:39-55`, `:189-195`).

Adjacent protections that bound abuse without being rate limits: the per-memo content length cap enforced in `CreateMemo`/`UpdateMemo` (`server/router/api/v1/memo_service.go:105`, `:443`) and the 30-second webhook HTTP timeout (`internal/webhook/webhook.go:27`).

If per-user API rate limiting is a requirement, it would need to be added — the natural insertion points being the Echo chain at `server/server.go:51` or the Connect interceptor list at `server/router/api/v1/v1.go:133`.
