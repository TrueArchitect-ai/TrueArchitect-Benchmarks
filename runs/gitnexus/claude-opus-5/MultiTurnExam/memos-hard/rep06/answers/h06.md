The three `Set*`/`Update` handlers share an intermediate funnel, `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `:67`.

**Where they converge.** Every helper resolves the memo owner's configured hooks via `s.Store.GetUserWebhooks` and calls `webhook.PostAsync` — `server/router/api/v1/memo_service_webhooks.go:71` for the created/updated/deleted paths (all three route through `dispatchMemoRelatedWebhook` at `:48`), and `:43` for the comment path. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a 128-slot channel; the four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) then call **`webhook.Post`** (`internal/webhook/webhook.go:120`), which builds and issues the actual HTTP request at `:152`. So `Post` is the single function all paths pass through immediately before delivery — `PostAsync` is the in-request funnel, `Post` the delivery one.

The URL is user-configured per-user (`hook.Url`, set through the webhook CRUD handlers in `server/router/api/v1/user_service_webhooks.go`), validated at configuration time by `webhook.ValidateURL` and again at dial time by the SSRF guard on the shared client.

One adjacent path worth distinguishing: `GetLinkMetadata` also makes an outbound HTTP request, but to a URL passed in the request itself rather than a stored user-configured one, and it does **not** go through `webhook.Post`.
