**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF-blocking dial hook `safeDialContext` + `isReservedIP` on the shared `safeClient` transport — `internal/webhook/webhook.go:59` / `internal/webhook/validate.go:44`**

How it fits together:

- **Delivery path** — memo create/update/delete events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which enqueues onto a bounded 128-slot channel drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:39-55`). Each goroutine calls `Post`, which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and issues the actual `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. Overflow is dropped with a warning rather than blocking the request.

- **Primary protection (dial time)** — `safeClient` is built with a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the host itself and refuses the connection if *any* resolved address is reserved. Because the check runs at dial time on the resolved IP, it also defeats DNS rebinding — a hostname that passes validation but later resolves to `127.0.0.1` still fails at connect. The blocklist is loopback, RFC-1918, link-local (incl. the `169.254.169.254` cloud IMDS address), and IPv6 equivalents, parsed once in `init()` (`internal/webhook/validate.go:14-36`).

- **Secondary protection (config time)** — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`). This is a UX/early-rejection layer; the dial-time guard is what actually holds at delivery.

One thing worth flagging: the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` for both layers, but nothing in the non-test codebase ever assigns it — only `internal/webhook/webhook_test.go:91` and `:142`. So despite the doc comment describing it as an option for self-hosted deployments targeting local services, in production it is permanently `false` with no flag or env var wired to it.
