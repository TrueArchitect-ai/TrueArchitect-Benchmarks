**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

Details:

- **Abstraction** — `internal/idp/idp.go` is a single-file package defining `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`), the provider-neutral shape every implementation must produce. It's a shared struct rather than a Go `interface`; the contract is "return one of these," and there is no `IdentityProvider` interface type to satisfy.

- **Implementation** — `internal/idp/oauth2/oauth2.go` is the only concrete provider that ships. Its `IdentityProvider` wraps `storepb.OAuth2Config`, validates required fields in `NewIdentityProvider` (`:27`), exchanges the auth code via `golang.org/x/oauth2` with optional PKCE `code_verifier` in `ExchangeToken` (`:47`), and maps arbitrary userinfo JSON claims into `idp.IdentityProviderUserInfo` through the configured `FieldMapping` in `UserInfo` (`:83`).

- **Confirming it's the only one** — the store proto has a single config variant, `IdentityProviderConfig_Oauth2Config` (`proto/gen/store/idp.pb.go:214`), and the SSO sign-in path branches on exactly one type: `if identityProvider.Type == storepb.IdentityProvider_OAUTH2` in `resolveSSOIdentity` (`server/router/api/v1/auth_service_sso.go:120-134`). Any other type falls through with `userInfo` still nil. No SAML, LDAP, or OIDC-specific package exists.
