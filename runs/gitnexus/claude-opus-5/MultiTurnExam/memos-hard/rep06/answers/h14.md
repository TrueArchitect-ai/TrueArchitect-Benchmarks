**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`; triggers: `CreateMemo`, `UpdateMemo` (content in the update mask), `CreateMemoComment` (via `CreateMemo`); extracted: `Tags` + `Property{HasLink, HasTaskList, HasCode, HasIncompleteTasks, Title}`**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`) initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, and assigns exactly two fields: `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`. The real work is `ExtractAll` (`internal/markdown/markdown.go:356`), which parses once with goldmark and does a single `gast.Walk`, collecting everything in that one pass rather than re-parsing per property. The result is persisted as JSON in the memo row's `payload` column.

**Triggers.**

| Trigger | Call site |
|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:108` — before `Store.CreateMemo` at `:115` |
| `UpdateMemo`, only when `update_mask` contains `content` | `server/router/api/v1/memo_service.go:447`, inside the `if path == "content"` branch (`:436`); the fresh payload is assigned to `update.Payload` at `:451` |
| `CreateMemoComment` | indirectly — it delegates to `s.CreateMemo` at `server/router/api/v1/memo_service_comments.go:56` |

Note the asymmetry: updating `visibility`, pinning, relations, or attachments does **not** recompute, which is correct since none of them change content. There is also a bulk rebuild path, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), which would re-derive payloads for every memo in batches of 100 — but as established, `NewRunner` is never called in production, so that path never executes.

**What gets extracted** (`internal/markdown/markdown.go:371-419`):

- **`Tags`** — text of each `TagNode`, skipping tags nested inside links or images (`asMemoTagNode`, `:134`), then deduplicated with original casing preserved via `uniquePreserveCase` (`:418`).
- **`Property.Title`** — text of the first block-level child of the document *only if* it's an H1 heading (`:384-389`).
- **`Property.HasLink`** — any `KindLink` node (`:393`).
- **`Property.HasCode`** — any code block, fenced code block, or inline code span (`:396`).
- **`Property.HasTaskList`** — any GFM task checkbox; and **`Property.HasIncompleteTasks`** when at least one checkbox is unchecked (`:399-405`).

These five booleans/string match the proto definition at `proto/store/memo.proto:15-22` (generated: `proto/gen/store/memo.pb.go:87-92`).

Two clarifications on scope: `ExtractAll` also returns `Mentions` (lowercased `@username`s), but `RebuildMemoPayload` deliberately does *not* persist them — mentions are consumed separately for notifications (`server/router/api/v1/memo_mention_helpers.go:32`). And the memo **snippet** used in previews is *not* part of this stored payload; it's computed on read via `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-85`), called during conversion at `memo_service_converter.go:76`.
