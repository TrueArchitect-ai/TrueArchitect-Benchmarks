**Triggers — three call sites:**

- `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:52`, a batch backfill over all memos (100 at a time). Worth flagging: nothing in production constructs a `memopayload.Runner`, so this path never executes at runtime — it's dead code.

**What the computation extracts.** `RebuildMemoPayload` initializes `memo.Payload` if nil, calls `ExtractAll` once over the content, then writes two fields (`runner.go:84-85`):

- `Payload.Tags` — every `#tag`, deduplicated with original case preserved via `uniquePreserveCase`. Tags nested inside a link or image are skipped (`asMemoTagNode` → `isTagNodeInLinkOrImage`, `markdown.go:117`).
- `Payload.Property` (`storepb.MemoPayload_Property`, `proto/gen/store/memo.pb.go:85`) — five derived fields:
  - `Title` — text of the first H1, but only when that heading is the document's first block-level child (`markdown.go:383-389`).
  - `HasLink` — any `KindLink` node.
  - `HasCode` — any code block, fenced code block, or inline code span.
  - `HasTaskList` — any task checkbox.
  - `HasIncompleteTasks` — any task checkbox that is unchecked.

One asymmetry worth noting: `ExtractAll` also collects `Mentions` (lowercased `@username`s) in its `ExtractedData`, but `RebuildMemoPayload` discards them — only `Tags` and `Property` are persisted to the memo payload. All of it comes from a single `gast.Walk` over one parse, which is the stated reason `ExtractAll` exists rather than calling `ExtractTags`/`ExtractProperties` separately.
