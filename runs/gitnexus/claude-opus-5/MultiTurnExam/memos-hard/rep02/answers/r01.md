**Premise correction: there is no Redis in this repository — no Redis client, no connection string, no dependency.** Grepping every `.go` file for `redis` (case-insensitive) returns zero hits, and `go.mod`/`go.sum` contain no Redis driver. So there is nothing to configure.

**Actual mechanism: a process-local in-memory cache**, not a shared/external one.

- **Implementation**: `store/cache/cache.go` — a `Cache` struct built on `sync.Map` plus an atomic item counter, with TTL expiry and a background cleanup goroutine. It satisfies the `Interface` declared at `store/cache/cache.go:11`.
- **Configuration site**: `store.New` in `/bench/home/work/store/store.go:40-44`, which builds a `cache.Config` literal and passes it to three separate cache instances at lines 51-53: `instanceSettingCache`, `userCache`, and `userSettingCache`. (`cache.DefaultConfig()` at `store/cache/cache.go:57` declares identical values but isn't what the store uses — `store.New` inlines its own copy.)

**TTL for user entries: 10 minutes**, from `DefaultTTL: 10 * time.Minute` (`store/store.go:41`). Every user write goes through `Set` (`store/user.go:98`, `:122`, `:132`, `:143`, `:167`), which applies the default TTL — `SetWithTTL` is never called for users, so no per-entry override exists. The accompanying settings are `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000` (shared across all three caches, since they're constructed from the same config value).

Two consequences of it being in-process rather than Redis:

- Entries die with the process; `Store.Close` (`store/store.go:75`) stops each cache's cleanup goroutine.
- Nothing is shared between instances, so a multi-replica deployment would have independent caches with no cross-node invalidation. Explicit invalidation is local only — e.g. `s.userCache.Delete(...)` on user deletion at `store/user_delete.go:40`.

One nuance on read path: `Store.GetUser` only consults `userCache` when looking up by ID (`store/user.go:149-156`); lookups by username or email always hit the database and then populate the cache.
