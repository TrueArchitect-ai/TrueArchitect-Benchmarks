Notes worth flagging:

- The rule itself is duplicated, not centralized. The scoping filter string `creator_id == %d || visibility in ["PUBLIC", "PROTECTED"]` appears verbatim at six sites, and the gate predicate `Visibility == store.Private && CreatorID != user.ID && !isSuperUser(user)` appears at five. There is no shared helper — each surface reimplements it.
- `canViewerAccessMemo` is defined **twice** with the same name and identical logic, in two different packages (`server/router/api/v1/user_service_notifications.go:302` and `server/notification/email.go:306`) — genuinely separate copies, not one shared function.
- The file server is the surface most easily missed: `/file/attachments/...` serves bytes without passing through any gRPC handler, so `checkAttachmentPermission` is the only thing standing between an anonymous request and a private memo's attachment. It additionally gates on `s.Profile.AllowAnonymous()` (line 677), which the API-side check does not.
- The MCP router (`server/router/mcp/`) contains no visibility logic of its own — it reaches memos through the API service, so it inherits those checks rather than adding a site.
