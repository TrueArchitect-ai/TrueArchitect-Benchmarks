**Premise correction: there is no GraphQL in this repository.** A repo-wide grep for `graphql` / `gqlgen` / `.graphql` / `schema.gql` across Go, TypeScript, `go.mod`, and JSON files returns zero hits (excluding `node_modules`). There is no schema file, resolver layer, or GraphQL dependency.

**Actual API surface: Protobuf/gRPC definitions, exposed over three transports.**

**Schema definition** — `/bench/home/work/proto/api/v1/`, nine `.proto` files:
`ai_service.proto`, `attachment_service.proto`, `auth_service.proto`, `common.proto`, `idp_service.proto`, `instance_service.proto`, `memo_service.proto`, `shortcut_service.proto`, `user_service.proto`. Persistence-layer messages live separately in `proto/store/`.

**Code generation** — driven by buf (`proto/buf.gen.yaml`, `proto/buf.yaml`, `proto/buf.lock`), emitting:
- Go message/gRPC/Connect/grpc-gateway code into `proto/gen/api/v1/`
- an OpenAPI document via the gnostic plugin (embedded through `proto/openapi_embed.go`)
- TypeScript clients into `web/src/types/proto` for the frontend

**Runtime exposure** — wired in `APIV1Service.RegisterGateway` (`/bench/home/work/server/router/api/v1/v1.go:65`):
- **grpc-gateway** REST/JSON — the gateway mux is mounted on Echo at `v1.go:126`, with a shared authorizer middleware
- **Connect RPC** — mux built at `v1.go:139-141` and routed at `v1.go:144` under the path pattern `/memos.api.v1.*`
- both wrapped in `http.MaxBytesHandler(..., maxAPIRequestBytes)`

**Non-gRPC HTTP surfaces** also exist alongside it, under `server/router/`: `fileserver` (`/file/...` for attachment bytes and avatars), `rss` (feeds), `frontend` (SPA and sitemap), and `mcp` (Model Context Protocol endpoint). None of these is GraphQL either.
