**Delivery function: `webhook.Post` — `/bench/home/work/internal/webhook/webhook.go:120` (the actual HTTP POST fires at `webhook.go:152` via `safeClient.Do`); protection mechanism: `safeDialContext` / `isReservedIP` dial-time IP blocking — `/bench/home/work/internal/webhook/webhook.go:59` and `/bench/home/work/internal/webhook/validate.go:44`.**

How it fits together:

**Delivery path**
- Memo create/update/delete triggers call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which just enqueues onto a bounded 128-slot channel `asyncPostQueue` (`webhook.go:39`, `184-196`) and drops the payload with a warning if the queue is full.
- Four worker goroutines started in `init()` (`webhook.go:42-55`) drain that queue and call `Post`. So `Post` is where the outbound request is actually built, signed (Standard Webhooks HMAC-SHA256 `webhook-id`/`webhook-timestamp`/`webhook-signature` headers, `webhook.go:133-150`), and executed.

**SSRF protection — two layers**
1. *Dial-time (the real enforcement)*: `safeClient` (`webhook.go:32-37`) is an `http.Client` whose `Transport.DialContext` is `safeDialContext` (`webhook.go:59-77`). It resolves the host itself and refuses the connection if **any** returned IP is reserved. Because the check happens at dial time on every request, it also defeats DNS rebinding — a hostname that validated as public at save time still can't connect if it later resolves to a private address.
2. *Admission-time*: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user saves a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`), returning a gRPC `InvalidArgument`.

Both layers share `isReservedIP` (`validate.go:44`), which tests against the CIDR list at `validate.go:14-23`: IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` (covering the cloud IMDS endpoint `169.254.169.254`), plus IPv6 loopback, unique-local, and link-local.

One thing worth flagging: the `AllowPrivateIPs` escape hatch (`validate.go:41`) short-circuits `isReservedIP` for both layers, but nothing in the repo ever assigns it — there is no flag, env var, or config wiring, so it is permanently `false` in practice. Also note `safeDialContext` resolves the host and then re-dials by hostname (`webhook.go:76`) rather than pinning the verified IP, leaving a narrow TOCTOU window between the check and the connect.
