h15.

Memo visibility (`PUBLIC` / `PROTECTED` / `PRIVATE`, defined at `store/memo.go`) is enforced independently on **eleven** distinct sites across five server surfaces. They do not share a single chokepoint — each re-implements the rule.

**Core API v1 — single-memo read gate**
- `checkMemoReadAccess` — `server/router/api/v1/memo_service.go:39` (the closest thing to a shared helper; called from `GetMemo` at `:356` and for the parent memo at `:367`, and from `ListMemoComments` at `server/router/api/v1/memo_service_comments.go:148`)

**Core API v1 — list-query filter injection (visibility pushed into SQL, not checked post-hoc)**
- `ListMemos` — `server/router/api/v1/memo_service.go:217-227` (anonymous → `[PUBLIC]`; authenticated → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`)
- `ListAllUserStats` — `server/router/api/v1/user_service_stats.go:84-90`
- `GetUserStats` — `server/router/api/v1/user_service_stats.go:218-220`

**Core API v1 — related-resource gates (each checks the owning memo's visibility)**
- `checkAttachmentAccess` — `server/router/api/v1/attachment_service.go:445-453`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-224`
- `ListMemoReactions` — `server/router/api/v1/reaction_service.go:30-40`
- `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:83`
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:41`

**File-serving surface (plain HTTP, not gRPC)**
- `FileServerService.checkAttachmentPermission` — `server/router/fileserver/fileserver.go:677,699` — the only site that also honours a `share_token` query param as an access grant (`:683-690`)

**Real-time delivery**
- `SSEClient.canReceive` — `server/router/api/v1/sse_hub.go:134` — filters broadcast events per subscriber (called from `Broadcast`, `:123`); note it defaults to *deny* on an unknown visibility value

**Anonymous/public surfaces (hard-restricted to `PUBLIC`)**
- RSS feeds — `server/router/rss/rss.go:90` and `:141`
- Sitemap — `server/router/frontend/frontend.go:150`

**Notification suppression** — `canViewerAccessMemo` exists twice, once per package, with the same logic: `server/router/api/v1/user_service_notifications.go:309-312` and `server/notification/email.go:313-316`.

Two things worth flagging. First, `GetMemoByShare` (`server/router/api/v1/memo_share_service.go:153`) is a deliberate **bypass**, not an enforcement site — a valid, non-expired share token returns the memo regardless of visibility; the only checks are token match and expiry (`:137-143`, `getActiveMemoShare` at `:199`, `isMemoShareExpired` at `:195`). Second, the MCP surface (`server/router/mcp/`) contains no visibility code at all — it delegates to the API v1 handlers above and inherits their checks.
