**Premise correction: there is no per-user API rate-limiting middleware in this repository. None is registered, and no request limits exist to report.**

Evidence:

- A case-insensitive grep for `ratelimit` / `rate_limit` / `rate limit` / `throttl` across all Go source returns exactly one hit, and it's a comment describing future work: `internal/email/doc.go:86` — `"Rate limit email sending to prevent abuse"`.
- No rate-limiting library is a direct dependency. `golang.org/x/time` (the home of `rate.Limiter`) appears in `go.mod:151` but is marked `// indirect`, and grepping the source for `golang.org/x/time` returns no importers — nothing in this codebase uses it.
- The complete set of Echo middleware is four entries: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/server.go:51-52`), plus static-file serving and SPA fallback in the frontend router (`server/router/frontend/frontend.go:54,59`). None throttles.
- The complete set of Connect interceptors is four: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` (`server/router/api/v1/v1.go:133-138`). None throttles.

**What does exist, and is easy to mistake for rate limiting** — none of it is per-user, and none returns 429:

| Mechanism | Path | What it actually bounds |
|---|---|---|
| `http.MaxBytesHandler(…, maxAPIRequestBytes)` | `server/router/api/v1/v1.go:126,144` | request *body size*, not frequency |
| `connect.WithReadMaxBytes` | `server/router/api/v1/v1.go:141` | same, for Connect |
| `semaphore.NewWeighted(3)` / `(2)` | `server/router/api/v1/v1.go:59-60` | process-wide concurrent thumbnail / image-processing jobs |
| `semaphore.NewWeighted(maxConcurrentThumbnails)` | `server/router/fileserver/fileserver.go:116` | process-wide concurrent thumbnail generation |
| bounded webhook queue (128 slots, 4 workers) | `internal/webhook/webhook.go:39-55` | outbound webhook backlog; overflow is dropped with a log line |
| memo content length limit | `server/router/api/v1/memo_service.go:101-110` | per-request payload size |

These are concurrency and size caps that protect server resources globally. If you need per-user request-rate limiting, it would have to be added — the natural insertion points are the Echo chain at `server/server.go:51` or the interceptor list at `server/router/api/v1/v1.go:133`, and the already-vendored `golang.org/x/time/rate` would cover the token-bucket side.
