**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection is a dial-time SSRF guard, `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

How it fits together:

**Delivery path.** Memo events call `webhook.PostAsync` (`internal/webhook/webhook.go:184`) from `server/router/api/v1/memo_service_webhooks.go:43,71`, which enqueues onto a bounded 128-slot channel drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:39-55`). Each worker calls `Post`, which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and issues the POST via the shared `safeClient` with a 30s timeout. Overflow is dropped with a warning rather than blocking the request path.

**SSRF protection.** `safeClient`'s `http.Transport` uses `safeDialContext` instead of the default dialer (`internal/webhook/webhook.go:32-37`). At dial time it resolves the host itself and rejects the connection if *any* resolved address falls in a reserved range — because the check happens on the address actually being dialed, it also defeats DNS rebinding (a hostname that passes validation at registration but later resolves to 127.0.0.1). The blocked ranges are in `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (cloud IMDS), and the IPv6 equivalents.

**Second, earlier layer.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects bad URLs at registration time — non-absolute, non-http(s) scheme, or resolving to a reserved IP — called from `server/router/api/v1/user_service_webhooks.go:74,161,182`.

**Escape hatch.** Both layers consult the package-level `AllowPrivateIPs` (`internal/webhook/validate.go:41`), set from the `--allow-private-webhooks` flag at `cmd/memos/main.go:49` (flag declared at `cmd/memos/main.go:133`). When enabled, `isReservedIP` always returns false and the SSRF guard is fully disabled — intended for self-hosted setups whose webhook targets live on the LAN.
