**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoRelations`, `SetMemoAttachments` — all in `server/router/api/v1/`; convergence function: `webhook.Post` — `internal/webhook/webhook.go:120`.**

The six RPC handlers and their paths to delivery:

| Handler | Path to dispatch |
|---|---|
| `CreateMemo` (`memo_service.go:70`) | `DispatchMemoCreatedWebhook` at `memo_service.go:157` |
| `DeleteMemo` (`memo_service.go:518`) | `DispatchMemoDeletedWebhook` at `memo_service.go:562` |
| `UpdateMemo` (`memo_service.go:401`) | `dispatchMemoUpdatedSideEffects` at `memo_service.go:513` |
| `SetMemoRelations` (`memo_relation_service.go:16`) | `dispatchMemoUpdatedSideEffects` at `memo_relation_service.go:48` |
| `SetMemoAttachments` (`memo_attachment_service.go:16`) | `dispatchMemoUpdatedSideEffects` at `memo_attachment_service.go:48` |
| `CreateMemoComment` (`memo_service_comments.go:20`) | `DispatchMemoCommentCreatedWebhook` at `memo_service_comments.go:119` |

The three `SetMemo*`/`UpdateMemo` paths funnel through the shared helper `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `memo_update_helpers.go:67`.

**Convergence.** All four `Dispatch*Webhook` methods (`memo_service_webhooks.go:14-45`) look up the creator's registered webhooks via `Store.GetUserWebhooks`, build a payload per hook, and call `webhook.PostAsync` (`memo_service_webhooks.go:43,71`). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded channel; the worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it and call **`webhook.Post`** — the single function where every path converges. The actual socket write is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`, guarded by the SSRF dialer described in the earlier answer.

Two things worth distinguishing: the URL is user-configured through the `CreateUserWebhook` / `UpdateUserWebhook` handlers (`user_service_webhooks.go:53,106`), but those handlers only *store* the URL after `webhook.ValidateURL` — they don't themselves emit an outbound request, and there is no "test webhook" RPC. Separately, the SSO sign-in path also makes outbound HTTP to a configured URL (`internal/idp/oauth2/oauth2.go:91`), but that URL is set by instance admins via the IdP service, not by ordinary users, and it does not pass through `webhook.Post`.
