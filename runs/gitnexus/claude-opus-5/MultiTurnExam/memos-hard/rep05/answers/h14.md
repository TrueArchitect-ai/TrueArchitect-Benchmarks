**Computation site: `RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: `CreateMemo`, `CreateMemoComment` (via `CreateMemo`), and `UpdateMemo` when the `content` field is in the update mask. Extracted: deduplicated `#tags` plus the `Property` set — `has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, and `title`.**

**What's computed.** `RebuildMemoPayload` writes exactly two fields onto `memo.Payload` (`server/runner/memopayload/runner.go:85-86`): `Tags` and `Property`. Both come from a single goldmark AST walk in `ExtractAll` (`internal/markdown/markdown.go:356-421`):

- **Tags** — collected from `MemoTagNode`s produced by the custom tag extension, then deduplicated preserving original case (`markdown.go:417`).
- **`Property.Title`** — text of the document's first block-level child if it's an H1 (`markdown.go:383-388`).
- **`Property.HasLink`** — any `KindLink` node.
- **`Property.HasCode`** — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- **`Property.HasTaskList`** — any `east.KindTaskCheckBox`; and **`Property.HasIncompleteTasks`** when such a checkbox is unchecked (`markdown.go:398-403`).

The schema is `MemoPayload.Property` in `proto/store/memo.proto:15-22`, commented "The calculated properties from the memo content." Note `ExtractAll` also gathers `Mentions`, but `RebuildMemoPayload` does not persist them — they feed notifications, not the payload.

**Triggers (all live paths):**

| Trigger | Site | Condition |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:108` | every create, before the INSERT at `:115` |
| `CreateMemoComment` | indirect — calls `s.CreateMemo` at `server/router/api/v1/memo_service_comments.go:56` | every comment (comments are memos) |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:447` | only inside the `path == "content"` branch; the recomputed payload is assigned to `update.Payload` at `:451` |

Because recomputation is gated on the `content` mask path, updates to `visibility`, `pinned`, `state`, or `create_time` deliberately leave the derived metadata untouched — correct, since none of them change the content it's derived from. One caveat: `Payload.Location` is *not* derived — `CreateMemo` overwrites it from the request after the rebuild (`memo_service.go:111-113`), so it's user-set data living in the same payload.

There is a fourth, dead trigger: the batch backfill `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:52`) re-derives payloads for all memos in pages of 100, but as established earlier that `Runner` is never constructed anywhere, so it never runs.
