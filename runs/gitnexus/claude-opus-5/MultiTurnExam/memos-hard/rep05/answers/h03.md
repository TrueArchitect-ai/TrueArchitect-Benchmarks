**`internal/idp` (abstraction) — `internal/idp/idp.go`; `internal/idp/oauth2` (implementation) — `internal/idp/oauth2/oauth2.go`.**

Details:

- **Abstraction — `internal/idp`.** The package is deliberately thin: it defines only the provider-neutral result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) at `internal/idp/idp.go:3-8`. There is no Go `interface` here — the contract is the shared user-info struct that every concrete provider returns, plus the `IdentityProvider.Type` enum in the schema (`proto/api/v1/idp_service.proto:77-79`).
- **Implementation — `internal/idp/oauth2`.** OAuth2 is the only concrete protocol that ships. `oauth2.IdentityProvider` wraps a `storepb.OAuth2Config` (`internal/idp/oauth2/oauth2.go:20-22`), with `NewIdentityProvider` validating that `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier` are all non-empty (`oauth2.go:27-43`). `ExchangeToken` (`oauth2.go:47`) trades the auth code for an access token via `golang.org/x/oauth2`, supporting PKCE when a `code_verifier` is passed. `UserInfo` (`oauth2.go:83`) fetches the userinfo endpoint with a 10s timeout and maps raw JSON claims onto `idp.IdentityProviderUserInfo` using the configured field mapping.
- **Only one provider type exists.** The proto enum has just `TYPE_UNSPECIFIED = 0` and `OAUTH2 = 1` (`proto/api/v1/idp_service.proto:77-79`) — no OIDC/SAML/LDAP implementations. Both packages are consumed from a single place, the SSO sign-in path at `server/router/api/v1/auth_service_sso.go:12-13`.
