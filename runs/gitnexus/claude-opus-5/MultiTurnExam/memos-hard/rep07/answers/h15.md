Distinct visibility-enforcement sites across the server (grouped by surface):

**Connect/gRPC API — memo reads**
- `APIV1Service.checkMemoReadAccess` (single-memo gate: non-public requires auth; private requires creator) — `server/router/api/v1/memo_service.go:39-68`; invoked from `GetMemo` (`:356`, and for the parent memo at `:367`) and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)
- `APIV1Service.ListMemos` (query-scoping: anonymous → `VisibilityList = [PUBLIC]`; authenticated → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:217-227`

**Connect/gRPC API — memo sub-resources** (each re-derives the parent memo's visibility rather than calling `checkMemoReadAccess`)
- `APIV1Service.ListMemoReactions` — `server/router/api/v1/reaction_service.go:30-41`
- `APIV1Service.UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:83`
- `APIV1Service.ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-224`
- `APIV1Service.checkAttachmentAccess` (attachment linked to a memo) — `server/router/api/v1/attachment_service.go:437-453`
- `APIV1Service.CreateMemoComment` (commenting on a private memo you don't own) — `server/router/api/v1/memo_service_comments.go:41`
- `APIV1Service.ListAllUserStats` / `GetUserStats` (stats scoped to `[PUBLIC]` or `[PUBLIC, PROTECTED]`) — `server/router/api/v1/user_service_stats.go:84`, `:90`, `:218`, `:220`

**Raw HTTP file server**
- `FileServerService.checkAttachmentPermission` (public+anonymous-allowed short-circuit, share-token fallback, then private→creator/admin) — `server/router/fileserver/fileserver.go:677`, `:684-689`, `:699`

**Server-sent events**
- `SSEClient.canReceive`, applied per client in `SSEHub.Broadcast` (private events only to creator or admin) — `server/router/api/v1/sse_hub.go:134-143`, called at `:122`; event visibility is populated by `server/router/api/v1/sse_event_helpers.go:29-37`

**Public feeds / SSR**
- `RSSService` feed handlers (both instance-wide and per-user feeds hard-scope to `[PUBLIC]`) — `server/router/rss/rss.go:90` and `:141`
- `FrontendService.getSitemapXML` (sitemap lists only public memos) — `server/router/frontend/frontend.go:150`

**Notifications** (visibility limits who may be notified, not who may read)
- `server/router/api/v1/user_service_notifications.go:309-312`, `server/notification/email.go:313-316`, and mention targeting in `server/router/api/v1/memo_mention_helpers.go:62-84`

Two observations worth noting. The share-token path is a deliberate bypass: a valid, unexpired `share_token` matching the memo grants attachment access regardless of visibility (`server/router/fileserver/fileserver.go:684-689`, with expiry logic in `isMemoShareExpired`, `server/router/api/v1/memo_share_service.go:195`). And enforcement is duplicated rather than centralized — the sub-resource handlers each re-implement the `Public → allow / Private → creator-or-superuser` test inline instead of routing through `checkMemoReadAccess`, so the rules must be kept in sync by hand. `server/router/mcp` contains no visibility checks of its own.
