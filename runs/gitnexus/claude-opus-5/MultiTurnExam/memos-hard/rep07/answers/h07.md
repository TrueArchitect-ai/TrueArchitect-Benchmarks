Route: `GET /file/users/:identifier/avatar`. Hops from browser to stored bytes:

- `FileServerService.RegisterRoutes` (route registration: `fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)`) — `server/router/fileserver/fileserver.go:121` (registered into Echo at `server/server.go:81-82`)
- `FileServerService.serveUserAvatar` (the serving handler) — `server/router/fileserver/fileserver.go:168`
- `FileServerService.getCurrentUser` (only on a private instance — `!s.Profile.AllowAnonymous()`; anonymous is rejected 401) — `server/router/fileserver/fileserver.go:174`
- `FileServerService.getUserByUsername` (thin wrapper: `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`) — `server/router/fileserver/fileserver.go:715`
- `Store.GetUser` (cache layer — the `userCache` hit only applies when looking up by ID, so a username lookup always falls through) — `store/user.go:148`
- `Store.ListUsers` (calls the driver, then populates `userCache`) — `store/user.go:136`
- `Store.driver.ListUsers` → e.g. `(*DB).ListUsers` for SQLite (builds `WHERE username = ?` and selects the `avatar_url` column) — `store/db/sqlite/user.go:88`, column list at `store/db/sqlite/user.go:159`; MySQL/Postgres equivalents in `store/db/mysql/user.go`, `store/db/postgres/user.go`
- `FileServerService.parseDataURI` (back in the handler: the avatar is stored as a `data:` URI string in `user.avatar_url`, so this regex-matches and base64-decodes it into raw image bytes) — `server/router/fileserver/fileserver.go:737`
- `c.Blob(http.StatusOK, imageType, imageData)` (response written, after `setSecurityHeaders` and `Cache-Control`) — `server/router/fileserver/fileserver.go:209`

Two things worth flagging about this path: the image is **not** in blob storage or on disk — it lives inline in the `user.avatar_url` column as a base64 data URI, which is why the "data layer" hop is an ordinary user row read rather than an attachment fetch. And the only authorization check is the instance-level anonymous gate at `fileserver.go:173-181`; once a viewer is allowed in (or the instance is public), any user's avatar is readable by username, with MIME restricted to the `avatarAllowedTypes` allowlist at `server/router/fileserver/fileserver.go:75`.
