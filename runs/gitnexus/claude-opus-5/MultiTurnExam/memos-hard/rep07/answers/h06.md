**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoRelations`, `SetMemoAttachments` (all `APIV1Service`, `MemoService` RPCs); convergence — `webhook.PostAsync` — `internal/webhook/webhook.go:184` (which hands off to `webhook.Post`, `internal/webhook/webhook.go:120`, where the HTTP request is actually issued).**

The six handlers and how each reaches the webhook layer:

| RPC handler | Declared at | Dispatch call |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:70` | `DispatchMemoCreatedWebhook` at `:157` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:401` | `dispatchMemoUpdatedSideEffects` at `:513` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:518` | `DispatchMemoDeletedWebhook` at `:562` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` at `:119` |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:16` | `dispatchMemoUpdatedSideEffects` at `:48` |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:16` | `dispatchMemoUpdatedSideEffects` at `:48` |

The last three of those go through a shared helper rather than calling the webhook package directly: `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`) calls `DispatchMemoUpdatedWebhook` at `:67` before broadcasting the SSE event — so any RPC that mutates a memo's attachments or relations also fires an "updated" webhook, not just `UpdateMemo`.

**Convergence.** All four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go`; each loads the target user's webhooks via `s.Store.GetUserWebhooks`, sets `payload.URL = hook.Url` (the user-configured URL), and calls `webhook.PostAsync` — `memo_service_webhooks.go:43` for the comment path and `:71` for the create/update/delete path (`DispatchMemoCreated/Updated/Deleted` at `:15`, `:20`, `:25` all delegate to `dispatchMemoRelatedWebhook` at `:48`). `PostAsync` is therefore the single funnel: it enqueues onto the bounded 128-slot `asyncPostQueue` (`internal/webhook/webhook.go:39`), and four worker goroutines started in `init()` (`webhook.go:42-55`) call `Post`, which signs the body and issues the request via `safeClient.Do` (`webhook.go:152`).

Two notes on scope: memo *reaction* RPCs do not dispatch webhooks — `Dispatch*Webhook` has no other callers in `server/`. And if "user-configured URL" is read to include admin-configured SSO endpoints, the auth RPCs reaching `resolveSSOIdentity` (`server/router/api/v1/auth_service_sso.go:104`) also make outbound calls to the IdP's token/userinfo URLs, but those go through `golang.org/x/oauth2` and a plain `http.Client`, not through `PostAsync`.
