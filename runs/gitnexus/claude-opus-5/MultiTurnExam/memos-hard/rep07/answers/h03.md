**`internal/idp` (abstraction); `internal/idp/oauth2` (the only concrete implementation — OAuth 2.0).**

Details:

- **Abstraction — `internal/idp/idp.go`**: this package is deliberately thin. It defines just `IdentityProviderUserInfo` (`internal/idp/idp.go:3-8`) — the normalized `Identifier` / `DisplayName` / `Email` / `AvatarURL` shape every provider must produce. Note there is no Go `interface` type here; the "abstraction" is the shared result struct plus the by-convention method set (`ExchangeToken`, `UserInfo`) that a provider package implements, with dispatch done by a type switch on the stored enum rather than through an interface value.

- **Implementation — `internal/idp/oauth2/oauth2.go`**: `IdentityProvider` wrapping a `storepb.OAuth2Config` (`:20-22`), constructed by `NewIdentityProvider` which requires `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier` (`:27-43`). It provides `ExchangeToken` — authorization-code exchange via `golang.org/x/oauth2`, with optional PKCE `code_verifier` (`:47-80`) — and `UserInfo`, which calls the userinfo endpoint with a bearer token and maps claims onto `idp.IdentityProviderUserInfo` using the configured field mapping (`:83-142`).

- **Where they meet**: `server/router/api/v1/auth_service_sso.go` imports both packages (`:12-13`). `resolveSSOIdentity` loads the stored provider and branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` (`:120`) before calling `oauth2.NewIdentityProvider(...)`, `ExchangeToken`, and `UserInfo` (`:121-130`).

Confirming that OAuth2 is the only one that ships: `proto/store/idp.proto` declares a single non-unspecified enum value `OAUTH2 = 1` (line 13), and the config `oneof` has exactly one variant, `IdentityProviderConfig_Oauth2Config` (`proto/gen/store/idp.pb.go:214`). There is no OIDC/SAML/LDAP provider package in the tree.
