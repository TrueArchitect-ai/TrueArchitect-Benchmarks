**Premise correction: there is no nightly database-cleanup job, and nothing is scheduled in the cron scheduler at all — so there is no time to report.**

Two separate corrections are involved:

**1. No cleanup job exists.** Searching for `cleanup|vacuum|prune` across `server/` and `store/` turns up only inline, request-scoped cleanup — attachment-storage cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`), best-effort rollback of a provisional SSO user row (`server/router/api/v1/auth_service_sso.go:76`), and memo relation/attachment cleanup inside `DeleteMemo` (`server/router/api/v1/memo_service.go:579`). None of it is periodic or database-wide. There is no `VACUUM`, no old-row purge, and no retention sweep anywhere.

**2. The cron scheduler is never used in production.** `internal/scheduler` is a complete, tested cron package — `Schedule`/`matches` parsing at `internal/scheduler/parser.go:121`, `Register`/`Start`/`Stop` at `internal/scheduler/scheduler.go`, jobs at `internal/scheduler/job.go`, plus middleware and a README. But `grep -rn "internal/scheduler"` shows it is imported by exactly two files, both its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No server code constructs a scheduler or registers a job, so the cron engine never runs.

**What actually runs on a timer.** Background periodic work in this server is done with plain `time.Ticker` goroutines, not cron, and there is exactly one live instance:

- **`s3presign.Runner`** — refreshes S3 presigned attachment URLs. Interval `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27`), ticker loop at `:29-41`, wired in `Server.startBackgroundRunners` at `server/server.go:162-171` with an immediate `RunOnce(ctx)` at `:163`. It runs every 12 hours from process start — an offset from boot time, not a wall-clock time of day, so there is no "3 AM"-style schedule anywhere in the codebase.
- **Cache expiry sweeps** — `CleanupInterval: 5 * time.Minute` (`store/store.go:42`) drives the in-memory `store/cache` eviction goroutines. This is in-process cache housekeeping, not database cleanup.
- **`memopayload.Runner`** exists (`server/runner/memopayload/runner.go`) but is dead code — `NewRunner` has no callers and it has no ticker at all.
