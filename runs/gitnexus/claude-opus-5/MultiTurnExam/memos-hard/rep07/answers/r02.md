**Premise correction: there is no per-user API rate-limiting middleware in this repository — it is not registered anywhere because it does not exist.**

Evidence:
- `grep -rni "ratelimit|rate_limit|rate limit|throttl"` across all Go sources returns exactly one hit, and it is aspirational prose in a doc comment: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"). Repo-wide (non-Go) the only other hit is a "5. Implement Rate Limiting" suggestion section in `internal/email/README.md:286-295`.
- `go.mod` contains no rate-limiter dependency (no `tollbooth`, `golang.org/x/time/rate`, `ulule/limiter`, etc.).
- The actual Echo middleware stack is two entries: `middleware.Recover()` and `newCORSMiddleware(profile)` — `server/server.go:51-52`.
- The Connect/gRPC interceptor chain is four entries, none of them a limiter: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` — `server/router/api/v1/v1.go:133-137`. The gateway path adds only the auth middleware (`server/router/api/v1/v1.go:66-80`).

What does exist are unrelated caps that are sometimes mistaken for rate limits — all global, none per-user, and none rejecting requests based on request frequency:

- **Request body size**: `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` on the gateway (`server/router/api/v1/v1.go:126`) and `connect.WithReadMaxBytes` on Connect handlers (`:141`), declared at `server/router/api/v1/v1.go:20`.
- **Concurrency semaphores**: thumbnail generation capped at 3 (`server/router/fileserver/fileserver.go:46`, `:116`; also `server/router/api/v1/v1.go:59`) and image processing at 2 (`server/router/api/v1/v1.go:60`). These make callers wait, not fail.
- **Webhook dispatch queue**: a bounded 128-slot channel with 4 workers, which drops (with a warning) when full — `internal/webhook/webhook.go:39`, `:42-55`, `:189-195`.
- **Memo content length**: an instance setting enforced per request in `CreateMemo`/`UpdateMemo` (`server/router/api/v1/memo_service.go:105`, `:443`).

If you need per-user rate limiting, it would have to be added — the natural insertion points are the Echo middleware stack at `server/server.go:51` (covers `/file/*` and the gateway) and the Connect interceptor list at `server/router/api/v1/v1.go:133`, where `NewAuthInterceptor` already resolves the caller's identity that a per-user limiter would key on.
