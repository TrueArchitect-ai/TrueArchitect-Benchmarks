**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); SSRF protection is `safeDialContext` → `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

How it fits together:

**Delivery path**
- API handlers build the payload and call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` for comment-created, `:71` for the create/update/delete flow via `dispatchMemoRelatedWebhook`).
- `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel `asyncPostQueue` (`webhook.go:39`), dropping with a warning if full.
- Four worker goroutines started in `init()` (`webhook.go:42-55`) drain that queue and call `Post`, which is where the request is actually marshalled, HMAC-signed (Standard Webhooks `webhook-id`/`webhook-timestamp`/`webhook-signature` headers, `webhook.go:133-150`), and sent via `safeClient.Do` (`webhook.go:152`).

**Protection against internal addresses** — two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against `reservedNetworks` parsed from `reservedCIDRs` (`validate.go:14-23`: IPv4 loopback, all three RFC-1918 ranges, `169.254.0.0/16` link-local incl. cloud IMDS, plus `::1/128`, `fc00::/7`, `fe80::/10`):

1. **Dial-time (the one that guards delivery itself)**: `safeClient`'s `Transport.DialContext` is `safeDialContext` (`webhook.go:32-37`, `59-77`). It re-resolves the host and refuses to dial if *any* returned IP is reserved. Because this runs at connection time rather than at save time, it also defeats DNS rebinding — noted in the comment at `webhook.go:29-31`.
2. **Config-time**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-`http(s)` schemes and reserved-resolving hostnames when a user creates or updates a webhook — called at `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

One caveat worth flagging: the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` for both layers, but grepping the tree shows it is only ever assigned in tests — no CLI flag, env var, or config path sets it in production code, so the guard is effectively always on for self-hosted deployments targeting LAN services.
