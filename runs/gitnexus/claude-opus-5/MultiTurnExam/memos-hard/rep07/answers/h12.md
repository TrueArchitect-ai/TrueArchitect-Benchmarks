How I determined it:

The call site is polymorphic, so the source alone is ambiguous — `Store.CreateMemo` (`store/memo.go:109`) validates the UID and then calls `s.driver.CreateMemo(ctx, create)` at `store/memo.go:113`, where `driver` is the `store.Driver` interface. There are exactly three implementations of that method: `store/db/sqlite/memo.go:16`, `store/db/postgres/memo.go:16`, and `store/db/mysql/memo.go:16`.

Resolving which one is bound at runtime took three steps:

1. **Where the interface value is assigned** — `db.NewDBDriver` (`store/db/db.go:14`) switches on `profile.Driver`: `"sqlite"` → `sqlite.NewDB`, `"mysql"` → `mysql.NewDB`, `"postgres"` → `postgres.NewDB` (`store/db/db.go:19-26`). So the concrete type is decided entirely by that one string.

2. **What that string is with no flags** — `cmd/memos/main.go` sets the default twice, consistently: `viper.SetDefault("driver", "sqlite")` at `cmd/memos/main.go:122` and the persistent flag default `rootCmd.PersistentFlags().String("driver", "sqlite", "database driver")` at `:130`, bound together at `:151`. The profile then reads `Driver: viper.GetString("driver")` at `cmd/memos/main.go:43`. With no flag and no `MEMOS_DRIVER` env override, the value is `"sqlite"`.

3. **Corroboration in the profile itself** — `internal/profile/profile.go:110` special-cases `p.Driver == "sqlite" && p.DSN == ""` to synthesize a default DSN of `<data>/memos_prod.db`, which only makes sense if sqlite is the no-configuration path.

So the chain for a default install is: RPC handler `CreateMemo` (`server/router/api/v1/memo_service.go:70`) → `Store.CreateMemo` (`store/memo.go:109`) → interface dispatch → `(*sqlite.DB).CreateMemo` (`store/db/sqlite/memo.go:16`).

RETURNING id, created_ts, updated_ts, row_status` with `QueryRowContext` rather than `ExecContext` + `LastInsertId`, so the generated ID and timestamps are scanned straight back into the passed-in `*store.Memo` (`store/db/sqlite/memo.go:42-49`).
