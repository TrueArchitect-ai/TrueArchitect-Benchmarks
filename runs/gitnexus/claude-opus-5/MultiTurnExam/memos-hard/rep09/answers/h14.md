## Where it's computed

`RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`) is a small wrapper: it ensures `memo.Payload` is non-nil, calls `markdownService.ExtractAll([]byte(memo.Content))` in a single pass (`:80`), and assigns the two derived fields:

```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```
— `server/runner/memopayload/runner.go:85-86`

The real work is `ExtractAll` (`internal/markdown/markdown.go:356`), which parses the content into a goldmark AST and does **one** `gast.Walk` collecting everything at once (`:371-411`). The payload rides along on the memo row as the `payload` JSON column — see the INSERT in `store/db/sqlite/memo.go:41`.

## Triggers

Recomputation is content-driven and happens at exactly two production call sites:

1. **`CreateMemo`** — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `s.Store.CreateMemo` at `:115`. Note the ordering: `Payload.Location` is set *after* the rebuild (`:110-112`), because location is user-supplied and must not be clobbered.
2. **`UpdateMemo`** — `server/router/api/v1/memo_service.go:447`, inside the `if path == "content"` branch of the update-mask loop (`:435-436`). The rebuilt payload is then attached to the update via `update.Payload = memo.Payload` (`:452`). Changing visibility, pinned state, or location does **not** re-derive metadata, which is correct since none of them affect content.

There's also a dormant bulk path: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) batch-rebuilds every memo 100 at a time and calls `RebuildMemoPayload` at `:52` — but `NewRunner` has no callers, so it never runs in production.

## What's extracted

From the single AST walk in `ExtractAll`:

| Output | Source | Line |
|---|---|---|
| `Tags []string` | `#tag` nodes, deduplicated preserving original case | `markdown.go:377`, dedup at `:418` |
| `Property.Title` | text of the first block-level child *only if* it's an H1 heading | `markdown.go:384-389` |
| `Property.HasLink` | any `KindLink` node | `markdown.go:393-394` |
| `Property.HasCode` | fenced/indented code block or inline code span | `markdown.go:396-397` |
| `Property.HasTaskList` | any task checkbox | `markdown.go:399-400` |
| `Property.HasIncompleteTasks` | a checkbox with `IsChecked == false` | `markdown.go:401-405` |

These land in the proto as `MemoPayload.Tags`/`MemoPayload.Property` (`proto/gen/store/memo.pb.go:26-28`) and `MemoPayload_Property.{HasLink,HasTaskList,HasCode,HasIncompleteTasks,Title}` (`memo.pb.go:87-92`).

One asymmetry worth noting: `ExtractAll` also collects `Mentions` (lowercased `@username` nodes, `markdown.go:379-381`) into its `ExtractedData`, but `RebuildMemoPayload` discards that field — mentions aren't persisted on the payload. They're consumed separately for notifications via a direct `ExtractAll` call in `server/router/api/v1/memo_mention_helpers.go:32`.
