## The determination

The call site itself doesn't tell you which code runs. `Store.CreateMemo` (`store/memo.go:109`) validates the UID and then calls `s.driver.CreateMemo(ctx, create)` at `store/memo.go:113` — `driver` is of interface type `store.Driver`, which declares `CreateMemo` at `store/driver.go:29`. Three types satisfy it, each with its own INSERT: `store/db/sqlite/memo.go:16`, `store/db/mysql/memo.go`, and `store/db/postgres/memo.go`. Static reading of the API handler (`server/router/api/v1/memo_service.go:115`) can't disambiguate them.

So I resolved the interface by following the value that populates it at startup:

1. **Flag default.** `cmd/memos/main.go:130` registers `--driver` with default `"sqlite"`, and `cmd/memos/main.go:122` sets the same via `viper.SetDefault("driver", "sqlite")`. With no flags, no `MEMOS_DRIVER` env var (`viper.AutomaticEnv()` with prefix `memos`, `main.go:167-169`), and no config override, the resolved value is `sqlite`.
2. **Into the profile.** `main.go:43` builds the profile with `Driver: viper.GetString("driver")`. `Profile.Validate` (`internal/profile/profile.go:110-118`) confirms this is the default-install path: when `Driver == "sqlite"` and `DSN == ""`, it synthesizes `memos_prod.db` under the data dir.
3. **Through the factory.** `main.go:57` calls `db.NewDBDriver(instanceProfile)`, which switches on `profile.Driver` (`store/db/db.go:17-26`) and returns `sqlite.NewDB(profile)` for the `"sqlite"` case (`store/db/db.go:20`).
4. **Bound into the store.** `main.go:64` passes that driver to `store.New(dbDriver, instanceProfile)`, so `s.driver` in `Store.CreateMemo` is a `*sqlite.DB` for the whole process lifetime — the binding happens once at startup and never changes.
