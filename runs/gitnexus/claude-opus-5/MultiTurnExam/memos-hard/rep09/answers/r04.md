## The actual mechanism: an in-process buffered Go channel

Everything lives inside the server process, in `internal/webhook/webhook.go`.

**The "queue"** is a package-level buffered channel with a fixed capacity of 128:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```
— `internal/webhook/webhook.go:39`

**The "workers"** are four goroutines started by the package's `init()` function — so they spin up on first import of the package, not via any explicit server wiring:

```go
func init() {
    for range 4 {
        go func() {
            for payload := range asyncPostQueue {
                if err := Post(payload); err != nil { slog.Warn(...) }
            }
        }()
    }
}
```
— `internal/webhook/webhook.go:42-55`

**Producing** goes through `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send via `select` with a `default` branch (`:189-195`). When the buffer is full the payload is **dropped** with a `slog.Warn` — there is no retry, no persistence, and no dead-letter path. Callers are the memo webhook dispatchers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

**Consuming** ends in `Post` (`internal/webhook/webhook.go:120`), which marshals the JSON body, optionally adds Standard Webhooks HMAC-SHA256 headers (`:133-150`), and issues the HTTP request via `safeClient.Do` at `:152` with a 30-second timeout (`:27`).

## Consequences of this design worth knowing

Because the queue is an in-memory channel rather than a broker:

- **Deliveries do not survive restart.** Anything buffered when the process exits is lost; there's no durable store backing it.
- **No cross-replica coordination.** Each server instance has its own channel and its own four workers.
- **Bounded, lossy backpressure.** Under a burst above 128 pending payloads, new events are discarded rather than queued or blocking the RPC handler — a deliberate trade to keep memo create/update latency unaffected.
- **No retry semantics.** A failed `Post` is logged and abandoned; a broker's redelivery guarantees don't exist here.
