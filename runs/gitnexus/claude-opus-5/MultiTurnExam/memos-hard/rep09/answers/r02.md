**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** It isn't registered anywhere, so there are no request limits to report.

## What I checked

- **Code search.** `grep -rni "ratelimit|rate_limit|rate limit|throttle|limiter"` across all Go files returns exactly one hit, and it's a to-do-style comment in documentation, not an implementation: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse").
- **Dependencies.** `go.mod` contains no rate-limiting module (no `tollbooth`, `ulule/limiter`, `golang.org/x/time/rate`, etc.).
- **HTTP middleware chain.** The Echo server registers only two global middlewares — `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/server.go:51-52`). The frontend router adds static-file and SPA-fallback middleware (`server/router/frontend/frontend.go:54`, `:59`). That's the complete set.
- **RPC interceptors.** Exactly four exist, all in `server/router/api/v1/connect_interceptors.go`: `MetadataInterceptor` (`:22`), `LoggingInterceptor` (`:98`), `RecoveryInterceptor` (`:165`), and `AuthInterceptor` (`:208`). None does counting or throttling.
- **No 429 path.** No handler returns `http.StatusTooManyRequests`. The single `connect.CodeResourceExhausted` reference (`connect_interceptors.go:153`) is in `LoggingInterceptor.classifyError`, which merely maps error codes to log levels.

## What exists instead (adjacent, but not rate limiting)

There are **concurrency** limits — caps on simultaneous in-flight work, global to the process rather than per-user, and they make callers wait rather than rejecting them:

- `thumbnailSemaphore = semaphore.NewWeighted(3)` and `imageProcessingSemaphore = semaphore.NewWeighted(2)` on `APIV1Service` (`server/router/api/v1/v1.go:59-60`), acquired in `attachment_service_image.go:71`.
- A separate thumbnail semaphore on the file server (`server/router/fileserver/fileserver.go:107`, `:116`), acquired at `:448`.

Also request-shaping but not rate limiting: a per-instance memo content-length cap (`getContentLengthLimit`, enforced at `server/router/api/v1/memo_service.go:104` and `:443`), a 128-slot bounded webhook dispatch queue that drops overflow (`internal/webhook/webhook.go:39`, `:189-195`), and a 1 MiB cap on webhook response bodies (`internal/webhook/webhook.go:158`).

If you need per-user rate limiting, it would have to be added — the natural insertion points are a new Echo middleware alongside `server/server.go:51-52`, or a fifth Connect interceptor in `connect_interceptors.go` (which already has authenticated-user context available via `AuthInterceptor`).
