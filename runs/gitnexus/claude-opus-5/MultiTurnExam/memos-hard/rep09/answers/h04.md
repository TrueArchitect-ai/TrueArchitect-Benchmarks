## Evidence

**1. Import graph.** `store/db/mysql` is imported by exactly one file in the entire repo:

```
store/db/db.go:8:  "github.com/usememos/memos/store/db/mysql"
```

A grep for that import path across all `*.go` files, excluding the package's own directory, returns that single line. Since `NewDB` is only reachable through the package qualifier from outside, one importer means one possible external call site.

**2. Call site.** That importer is the factory itself — `NewDBDriver` in `store/db/db.go:14-30`, which switches on `profile.Driver` and calls `mysql.NewDB(profile)` at `store/db/db.go:22`. No other `mysql.NewDB(` or `&mysql.DB{}` occurrence exists anywhere.

**3. Graph confirmation.** `context({name: "NewDB", file_path: "store/db/mysql/mysql.go"})` reports exactly one incoming CALLS edge, from `NewDBDriver` in `store/db/db.go`, matching the grep.

## The one caveat

Within the package itself, `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — a zero-value struct literal (no `*sql.DB` connection, no profile) used to exercise auth-config methods that don't touch the database. It's legal only because the test lives in the same package, it bypasses `NewDB` rather than calling it, and it's test-only. That's the sole direct construction of the `DB` type outside `NewDB`, and it doesn't represent a production path around the factory.
