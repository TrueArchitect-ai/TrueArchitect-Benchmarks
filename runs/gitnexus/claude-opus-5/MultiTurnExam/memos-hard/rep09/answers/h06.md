## The six handler entry points

All are gRPC/Connect handlers on `APIV1Service`, and all reach a user-registered webhook URL (registered per-user and stored via `GetUserWebhooks`):

| Handler | Declared at | Reaches webhooks via |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:70` | `DispatchMemoCreatedWebhook` at `:157` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:401` | `dispatchMemoUpdatedSideEffects` at `:513` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:518` | `DispatchMemoDeletedWebhook` at `:562` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` at `:119` |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:16` | `dispatchMemoUpdatedSideEffects` at `:48` |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:16` | `dispatchMemoUpdatedSideEffects` at `:48` |

The last three of those funnel through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `:67` — so editing a memo, re-attaching files, or changing relations all emit `memos.memo.updated`.

## Where they converge

The four `Dispatch*Webhook` functions in `server/router/api/v1/memo_service_webhooks.go` are thin: three of them delegate to `dispatchMemoRelatedWebhook` (`:48`) and the comment one is standalone (`:30`). Both loop over the target user's webhooks and end at the same call:

- `webhook.PostAsync(payload)` — `server/router/api/v1/memo_service_webhooks.go:71` (memo created/updated/deleted) and `:43` (comment created)

`PostAsync` (`internal/webhook/webhook.go:184`) is the single convergence point before delivery — every webhook-emitting path in the codebase goes through it. It enqueues onto the 128-slot `asyncPostQueue` (`webhook.go:39`), dropping with a warning if full, and four worker goroutines started in `init()` (`webhook.go:42-55`) call `Post` (`webhook.go:120`), where the actual HTTP request goes out via `safeClient.Do` at `webhook.go:152`.

So if you want the last point common to all six handlers, it's `PostAsync`; if you want the last point common to all *deliveries*, it's `Post`. `PostAsync` is the narrower answer since it's on the synchronous handler path.

One scoping note: I read "user-configured URL" as the webhook feature. There is other outbound HTTP in the server — the OAuth2 SSO token/userinfo exchange in `internal/idp/oauth2/oauth2.go:47,83`, reached from the auth SSO handler — but those endpoints are configured by an instance admin as part of an identity provider, not by ordinary users, and they don't pass through `PostAsync`.
