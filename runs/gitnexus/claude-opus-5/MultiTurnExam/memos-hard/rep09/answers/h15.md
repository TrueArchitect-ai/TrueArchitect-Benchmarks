## How they group

**Two enforcement styles.** Most sites are *post-fetch gates* — load the memo, then reject: `checkMemoReadAccess` returns `Unauthenticated` for anonymous users on non-public memos and `PermissionDenied` when a non-owner hits a `Private` one (`memo_service.go:55-66`). The list-shaped surfaces instead do *pre-filtering*, pushing visibility into the query so restricted rows never load: `ListMemos` sets `VisibilityList = [PUBLIC]` for anonymous callers, and for authenticated ones appends a CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` (`memo_service.go:218-227`).

**Non-gRPC surfaces enforce independently.** These don't route through `checkMemoReadAccess` and each re-implement the rule:
- `fileserver.checkAttachmentPermission` (`fileserver.go:650`) is the most elaborate — public memos pass only when `Profile.AllowAnonymous()` (`:677`), then a `share_token` query-param fallback validates a non-expired `MemoShare` bound to that exact memo (`:685-691`), then falls back to the authenticated-user check at `:699` (admins allowed).
- `SSEClient.canReceive` (`sse_hub.go:134`) filters outbound events: `Private` reaches only the creator or an admin; `Public`/`Protected`/empty pass; unknown values are logged and **denied** — a fail-closed default.
- RSS (`rss.go:90`, `:141`) and the sitemap (`frontend.go:150`) hard-code `VisibilityList: []store.Visibility{store.Public}` — `Protected` never appears in feeds or the sitemap even for signed-in users.

**Notification fan-out** has two independent copies of the same predicate, both named `canViewerAccessMemo` in different packages (`user_service_notifications.go:302` and `notification/email.go:306`) — duplicated logic that would need to be changed in both places.

**Adjacent but distinct:** `memo_mention_helpers.go:62-84` filters mention *targets* by visibility, and `checkMemoReadAccess` also gates archived memos to their creator (`memo_service.go:45-53`) — a separate `RowStatus` rule layered alongside visibility. The share-token path (`memo_share_service.go:151`, `GetMemoByShare`) is a deliberate bypass: a valid token grants access regardless of visibility.
