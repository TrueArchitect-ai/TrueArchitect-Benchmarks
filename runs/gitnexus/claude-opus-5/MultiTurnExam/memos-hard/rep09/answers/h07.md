## Details per hop

**Route registration.** `FileServerService.RegisterRoutes` (`server/router/fileserver/fileserver.go:121`) mounts an Echo group at `/file` and binds `GET /users/:identifier/avatar` to `serveUserAvatar` at `:124`. The service is constructed and registered during server setup at `server/server.go:80-81`, deliberately before the gRPC-gateway.

**Handler.** `serveUserAvatar` (`fileserver.go:168`):
1. If the instance isn't anonymous-readable (`!s.Profile.AllowAnonymous()`), it requires a viewer via `getCurrentUser` (`:715` → `authenticator.AuthenticateToUser`) and 401s if absent (`:173-181`). Note the gate is on *being logged in*, not on any relationship to the target user — any authenticated user can fetch any other user's avatar.
2. Reads the path param `identifier` (`:183`) and looks the user up (`:185`).
3. 404s when the user is missing or `AvatarURL == ""` (`:189-194`).

**Store lookup.** `getUserByUsername` (`fileserver.go:715`) is a one-liner: `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`. Despite the param being named `identifier`, only the username field is populated — no ID or email fallback.

**Cache + store layer.** `Store.GetUser` (`store/user.go:148`) consults `userCache` only when `find.ID` is set (`:149-156`); since this path filters by username, it always falls through to `Store.ListUsers` (`store/user.go:136`), which delegates to the driver and back-fills the cache keyed by user ID (`:142-144`).

**Data layer.** `DB.ListUsers` builds `username = ?` into the WHERE clause (`store/db/sqlite/user.go:128-130`) and selects `avatar_url` among the columns from the `user` table (`:151-166`), then scans rows into `store.User`. Parallel implementations exist in `store/db/mysql/user.go` and `store/db/postgres/user.go`.

**Response.** Back in the handler, the avatar is not a file on disk or in object storage — `user.AvatarURL` holds a data URI. `parseDataURI` (`fileserver.go:737`) regex-matches it and base64-decodes the payload; the MIME type is checked against the `avatarAllowedTypes` allowlist (`:75`, enforced at `:201`), security headers are set (`setSecurityHeaders`, `:758`), `Cache-Control` is applied, and the bytes go out via `c.Blob` (`:209`).
