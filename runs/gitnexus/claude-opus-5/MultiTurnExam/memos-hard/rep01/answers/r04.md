**Premise correction: neither. There is no message broker in this repository — no NATS, no RabbitMQ, no AMQP, Kafka, or SQS — and therefore no queue declaration.** A case-insensitive search across all Go sources for `nats`, `rabbitmq`, `amqp`, `kafka`, `streadway`, `pubsub`, and `sqs` returns zero hits, and `go.mod` lists no broker client library. Webhook delivery never leaves the process boundary until the outbound HTTP request itself.

**Actual mechanism: an unexported, in-process buffered Go channel with a fixed pool of goroutines**, all in `internal/webhook/webhook.go`.

- **The "queue" is a package-level channel**: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`). That 128-slot buffer is the entire queue declaration — no exchange, topic, subject, or durable binding.
- **The "workers" are four goroutines started in `init`**: `for range 4 { go func() { for payload := range asyncPostQueue { ... } }() }` (`internal/webhook/webhook.go:42-55`). They start at package initialization, not from any server wiring, and each pulls a payload and calls `Post` (`:46`), logging a warning on failure (`:47-51`).
- **Producer side**: `PostAsync` (`internal/webhook/webhook.go:184`) does a non-blocking send with a `default` branch — when the buffer is full the event is **dropped** with a warning (`:189-195`), rather than blocking the caller or persisting for retry. Producers are the memo RPC handlers, via `webhook.PostAsync` at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.
- **Delivery**: `Post` (`internal/webhook/webhook.go:120`) marshals the payload, optionally adds Standard-Webhooks HMAC headers, and sends via the shared `safeClient` (`:152`), which blocks reserved/private IPs at dial time (`:59`).

The practical consequences of this being a channel rather than a broker are worth stating plainly, since they're the properties someone asking about NATS/RabbitMQ usually cares about:

- **No durability** — queued payloads live only in memory; a restart or crash loses everything in flight.
- **No retries or dead-lettering** — a failed `Post` is logged once and discarded; there's no redelivery, backoff, or DLQ.
- **No cross-process fan-out** — each server replica has its own independent 128-slot queue and 4 workers; nothing is shared or coordinated between instances.
- **Silent overflow** — under burst load the `default` case drops events, and the only trace is a `slog.Warn`.
