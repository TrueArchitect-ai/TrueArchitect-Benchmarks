Three observations worth separating from the list:

The two `canViewerAccessMemo` functions are **duplicated implementations**, not one shared helper — near-identical logic living in two packages, so a policy change needs both edited.

`GetMemoByShare` (`server/router/api/v1/memo_share_service.go:153`) deliberately **does not** consult visibility; a valid unexpired share token substitutes for it, and only archived/missing memos are rejected (`:163-166`). The matching bypass exists in the file server at `fileserver.go:684-689`.

The MCP router has no visibility code of its own (`server/router/mcp/` has zero `Visibility` references) — it allowlists `MemoService_ListMemos` / `MemoService_GetMemo` (`server/router/mcp/catalog.go:12-14`) and inherits the API-layer checks. Likewise `store/db/{sqlite,mysql,postgres}/memo.go` translate `FindMemo.VisibilityList` into SQL but make no policy decision; they're the mechanism the scoping sites rely on.
