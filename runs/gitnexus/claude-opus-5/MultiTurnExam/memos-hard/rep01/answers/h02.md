**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard at dial time via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path.** Memo create/update/delete handlers call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43`, `:71`), which only enqueues onto a bounded 128-slot channel and drops with a warning if full (`internal/webhook/webhook.go:184-196`). The actual HTTP send happens in `Post` (`internal/webhook/webhook.go:120`), run by four worker goroutines started in `init` (`internal/webhook/webhook.go:42-55`). `Post` marshals the payload, optionally adds Standard-Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, lines 133-150), and issues the request through `safeClient.Do` (line 152), with a 30s timeout and a 1 MiB cap on the response body read (lines 27, 158).

**Protection.** Two layers, both keyed on the same reserved-range list:

1. *Dial-time* (the real enforcement): `safeClient`'s Transport uses `safeDialContext` (`internal/webhook/webhook.go:35`, defined at `:59`). It resolves the host itself and refuses the connection if any resolved address is reserved (lines 65-74). The comment at `internal/webhook/webhook.go:29-31` notes this placement is deliberate — checking at dial time rather than at URL-parse time also defeats DNS rebinding.
2. *Admission-time*: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http/https schemes and reserved-resolving hostnames when a user registers or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`), returning a gRPC `InvalidArgument`.

The blocked ranges are `reservedCIDRs` in `internal/webhook/validate.go:14-23` — IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (explicitly covering cloud IMDS at 169.254.169.254), plus IPv6 loopback, ULA, and link-local; parsed once in `init` (`validate.go:28-36`).

One thing worth flagging: there's an escape hatch, `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`), which short-circuits `isReservedIP` to `false` and thereby disables *both* layers. Grepping the non-test tree, nothing ever assigns it — no flag, env var, or config wires it up — so in the shipped binary it stays `false` and the protection is always on.
