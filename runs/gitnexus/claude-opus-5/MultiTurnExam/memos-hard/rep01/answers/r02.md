**Premise correction: there is no per-user API rate-limiting middleware in this repository — so there is no registration site and no request limits to report.**

Evidence:

- A case-insensitive search across all Go files for `ratelimit`, `rate_limit`, "rate limit", and `throttl` yields exactly one hit, and it's an aspirational comment in package docs, not code: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" under future considerations.
- No rate-limiting dependency exists. `go.mod` has no `golang.org/x/time/rate`, no `ulule/limiter`, no `didip/tollbooth`, and Echo's `middleware.RateLimiter` is never referenced.
- The complete set of Echo middleware registered on the server is three entries: `middleware.Recover()` (`server/server.go:51`), `newCORSMiddleware(profile)` (`server/server.go:52`, config at `server/cors.go:14`), and — on the frontend router only — static-file serving plus an SPA fallback (`server/router/frontend/frontend.go:54`, `:59`). None of these limit request rates.
- The gRPC-Gateway/Connect stack installs an auth interceptor rather than a limiter (`server/router/api/v1/v1.go:95` and the `NewAuthorizer` wiring at `v1.go:68`), so authenticated request volume is unbounded per user.

**What does exist, and is easy to mistake for rate limiting:** concurrency caps, not request-rate caps. These bound how many operations run *simultaneously*, with excess callers blocking rather than being rejected:

- `thumbnailSemaphore` — `semaphore.NewWeighted(3)` in `server/router/api/v1/v1.go:59`, and a parallel one in the file server, `maxConcurrentThumbnails = 3` (`server/router/fileserver/fileserver.go:46`, acquired at `:448`)
- `imageProcessingSemaphore` — `semaphore.NewWeighted(2)` (`server/router/api/v1/v1.go:60`)

They're process-wide and content-type-specific, not per-user, and they return no 429.

Two other bounds worth distinguishing, since they also aren't rate limits: `MaxPageSize` clamps result-set size in `ListMemos` (`server/router/api/v1/memo_service.go:241`), and the webhook dispatcher drops events when its 128-slot queue is full (`internal/webhook/webhook.go:39`, `:189-195`) — a backpressure valve on outbound deliveries, not on inbound API calls.
