## Where it's computed

`RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`. The real work is `ExtractAll` (`internal/markdown/markdown.go:356`), which parses the content once into a goldmark AST and does a **single `gast.Walk`** (`:370-411`) collecting everything in one pass — the comment at `:355` calls out efficiency as the reason for the combined API.

The result is persisted on the memo row as the protojson-encoded `payload` column (schema: `MemoPayload` in `proto/store/memo.proto:7-23`, with `Property` at `:15-22` labeled "The calculated properties from the memo content").

## What it extracts

From the walk in `internal/markdown/markdown.go:376-408`:

| Field | How it's derived |
|---|---|
| `Tags` | every `MemoTagNode` (`:376-378`), deduplicated preserving original case via `uniquePreserveCase` (`:417`) |
| `Property.Title` | text of the document's **first block-level child only if it's an H1** — guarded by `firstBlockChecked` and a `Parent().Kind() == KindDocument` check (`:384-390`) |
| `Property.HasLink` | any `gast.KindLink` node (`:394`) |
| `Property.HasCode` | any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan` (`:397`) |
| `Property.HasTaskList` | any `east.KindTaskCheckBox` (`:400`) |
| `Property.HasIncompleteTasks` | a task checkbox with `!IsChecked` (`:402-404`) |

`ExtractAll` also collects `Mentions` (lowercased, `:379-381`), but `RebuildMemoPayload` deliberately drops them — only `Tags` and `Property` are stored (`runner.go:85-86`). Mentions are consumed separately for notifications at `server/router/api/v1/memo_mention_helpers.go:32`.

## What triggers recomputation

Exactly two call sites in production, both in the memo service:

1. **`CreateMemo`** — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `s.Store.CreateMemo` (`:114`). Note `Payload.Location` is set *after* the rebuild (`:110-112`), since location is user-supplied and would otherwise be clobbered.
2. **`UpdateMemo`** — `server/router/api/v1/memo_service.go:447`, and only inside the `if path == "content"` branch of the update-mask loop (`:440-453`). Updates that change visibility, pinned state, etc. leave the payload untouched — recomputation is content-gated.
3. **`CreateMemoComment`** — inherits it transitively: it calls `s.CreateMemo(...)` at `server/router/api/v1/memo_service_comments.go:56`, so a comment's payload is built by the same path.

One dead trigger worth flagging: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) exists to rebuild payloads for *all* memos in batches of 100, but nothing constructs the `Runner` — `memopayload.NewRunner` (`:19`) has no callers, and only `s3presign.NewRunner` is wired into startup (`server/server.go:162`). So there is no bulk-backfill path running today.

Separately: the memo **snippet** used in list views is *not* part of this stored payload — it's generated on demand at conversion time via `s.MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:85`), so it never needs invalidation.
