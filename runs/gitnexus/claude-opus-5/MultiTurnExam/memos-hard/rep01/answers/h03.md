**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- **Abstraction — `internal/idp/idp.go`**: the package is deliberately thin. It defines a single provider-neutral type, `IdentityProviderUserInfo` (`internal/idp/idp.go:3-8`), with `Identifier`, `DisplayName`, `Email`, and `AvatarURL`. That struct is the contract every provider normalizes to; there is no Go `interface` here — the seam is the shared result type, not a method set.

- **Implementation — `internal/idp/oauth2/oauth2.go`**: OAuth2 is the only concrete protocol that ships. `IdentityProvider` (`oauth2.go:20`) wraps a `storepb.OAuth2Config`; `NewIdentityProvider` (`oauth2.go:27`) requires `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier`. `ExchangeToken` (`oauth2.go:47`) swaps the auth code for an access token via `golang.org/x/oauth2`, passing `code_verifier` when PKCE is in play. `UserInfo` (`oauth2.go:83`) calls the userinfo endpoint with a bearer token (10s timeout, `oauth2.go:24`) and maps raw claims onto `idp.IdentityProviderUserInfo` using the configured field mapping — identifier is required, the rest are best-effort with display name falling back to the identifier (`oauth2.go:115-140`).

Two corroborating signals that OAuth2 is the sole implementation: the stored provider type enum has exactly one real value, `IdentityProvider_OAUTH2 = 1` alongside `TYPE_UNSPECIFIED` (`proto/gen/store/idp.pb.go:27-28`), and the SSO sign-in path constructs providers unconditionally through `oauth2.NewIdentityProvider(identityProvider.Config.GetOauth2Config())` (`server/router/api/v1/auth_service_sso.go:121`, imports at `:12-13`) — no branch on provider type.
