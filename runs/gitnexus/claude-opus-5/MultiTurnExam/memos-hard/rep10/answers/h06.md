Path to convergence: the three `Dispatch*Webhook` wrappers (`server/router/api/v1/memo_service_webhooks.go:15,20,25`) all funnel into `dispatchMemoRelatedWebhook` (`:48`); the comment variant is `DispatchMemoCommentCreatedWebhook` (`:30`). Both load the target user's webhooks via `s.Store.GetUserWebhooks` and set `payload.URL = hook.Url` — that's the user-configured URL — then call `webhook.PostAsync` (`:71` and `:43`). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded channel; the four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) call **`webhook.Post`**, which is where the request is actually built, signed, and sent via `safeClient.Do` (`internal/webhook/webhook.go:152`).

Two notes:
- `SetMemoRelations` and `SetMemoAttachments` reach delivery indirectly, through the shared `dispatchMemoUpdatedSideEffects` helper (`server/router/api/v1/memo_update_helpers.go:66`), which fires the `memos.memo.updated` webhook at `:67`.
- The `CreateUserWebhook` / `UpdateUserWebhook` handlers (`server/router/api/v1/user_service_webhooks.go:53,106`) touch user-configured URLs too, but only to resolve and validate them via `webhook.ValidateURL` — they don't deliver a payload.
