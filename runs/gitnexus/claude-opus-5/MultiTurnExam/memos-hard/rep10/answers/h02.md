**Delivery function: `webhook.Post` — `internal/webhook/webhook.go:120` (dispatched asynchronously via `webhook.PostAsync` → a 4-worker queue, `internal/webhook/webhook.go:184` / `:42-55`); protection: a dial-time SSRF guard, `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

How it fits together:

- **Trigger**: memo create/update/delete paths call `webhook.PostAsync` at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`. `PostAsync` enqueues onto a bounded 128-slot channel (dropping with a warning if full), and four goroutines started in `init()` call `Post` for each payload.
- **Actual outbound HTTP**: `Post` marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and issues the request via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. The response body is read through `io.LimitReader(..., 1<<20)`.
- **Primary protection (at dial time)**: `safeClient` is an `http.Client` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` resolves the host itself and refuses to dial if *any* resolved address is reserved — because the check happens on the resolved IPs at connection time, it also defeats DNS rebinding, per the comment at `internal/webhook/webhook.go:30-31`.
- **Blocklist**: `isReservedIP` (`internal/webhook/validate.go:44`) tests against `reservedCIDRs` (`internal/webhook/validate.go:14-23`): 127.0.0.0/8, 10/8, 172.16/12, 192.168/16, 169.254/16 (cloud IMDS), ::1/128, fc00::/7, fe80::/10 — parsed once in `init()`.
- **Secondary, at configuration time**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user saves a webhook, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.
- **Escape hatch**: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted deployments. Note that in the current tree nothing outside tests assigns it — the `--allow-private-webhooks` flag mentioned in `CHANGELOG.md:121` has no remaining wiring in `cmd/`, so the guard is effectively always on at runtime.
