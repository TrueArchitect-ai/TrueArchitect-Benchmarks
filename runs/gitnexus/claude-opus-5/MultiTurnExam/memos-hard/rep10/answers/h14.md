**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `markdown.(*service).ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: `CreateMemo` and `UpdateMemo` (only when the `content` field is in the update mask). Extracts: `Tags` plus the five `Property` fields — `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks`, `Title`.**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`. The actual work is a single goldmark AST walk in `internal/markdown/markdown.go:371-411` — deliberately one pass, per the interface comment "extracts tags, properties, and references in a single parse (most efficient)". Tags are deduplicated preserving case (`internal/markdown/markdown.go:418`).

**Triggers (both in `server/router/api/v1/memo_service.go`):**
1. `CreateMemo` — `memo_service.go:108`, after the content-length check and before `s.Store.CreateMemo`.
2. `UpdateMemo` — `memo_service.go:447`, inside the `if path == "content"` branch of the update-mask loop; the result is written through `update.Payload = memo.Payload` (`:451`).

Notably, no other mutation recomputes it: the `location` branch (`:481-484`) mutates `Payload.Location` without re-deriving tags/properties, and `SetMemoAttachments` / `SetMemoRelations` don't touch the payload. There is also a bulk backfill path, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), which would rebuild every memo in batches of 100 — but it has no call site anywhere, so it never runs.

**What's extracted** (`ExtractedData` → `storepb.MemoPayload`, fields defined at `proto/gen/store/memo.pb.go:85-95`):

| Field | Source in the AST walk |
|---|---|
| `Tags []string` | custom `MemoTagNode` (`internal/markdown/markdown.go:376-378`), deduped |
| `Property.Title` | text of the first block-level child if it's an H1 heading (`:383-389`) |
| `Property.HasLink` | any `gast.KindLink` node (`:393-394`) |
| `Property.HasCode` | `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan` (`:396-397`) |
| `Property.HasTaskList` | any `east.KindTaskCheckBox` (`:399-400`) |
| `Property.HasIncompleteTasks` | a task checkbox with `!IsChecked` (`:401-404`) |

`ExtractAll` also returns `Mentions`, but `RebuildMemoPayload` doesn't persist those — mentions are consumed separately for inbox notifications (`server/router/api/v1/memo_mention_helpers.go:32`).
