**Premise correction: there is no nightly database-cleanup job, and the cron scheduler has no registered jobs at all — so there's no scheduled time to report.**

Two separate corrections are needed:

**1. No such job exists.** Grepping for `cleanup`/`vacuum`/`purge`/`prune` across `server/`, `store/`, and `cmd/` turns up no scheduled database maintenance. The only "cleanup" work is event-driven, not time-driven: attachment/relation cleanup inside `DeleteMemo` (`server/router/api/v1/memo_service.go:579`), S3 object cleanup when a user is deleted (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`), and the in-memory cache's 5-minute expiry sweep (`store/store.go:42` → `store/cache/cache.go:200`), which touches no database.

**2. The cron scheduler isn't wired into the server at all.** `internal/scheduler` is a complete, working package — `Scheduler` with `Register`/`Start`/`Stop` (`internal/scheduler/scheduler.go:70`, `:91`, `:169`), a `Job` type (`internal/scheduler/job.go`), and a 5-field cron expression parser (`internal/scheduler/parser.go`) — but nothing outside the package imports it. `grep -rln "internal/scheduler"` returns only two files, both tests: `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. Likewise, every one of the ~20 `Register(...)` call sites lives in `_test.go` files or the doc comment at `internal/scheduler/doc.go:14`. No `scheduler.New(...)` appears in `cmd/memos/main.go` or `server/server.go`.

**What actually runs on a schedule** is one hand-rolled ticker loop, not a cron job: the S3 presign runner, every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27`), started at `server/server.go:162-171`. It refreshes presigned attachment URLs; it does not clean up the database.
