**Premise correction: this project has no GraphQL API.** A case-insensitive grep for `graphql|gqlgen|apollo` across all Go, TypeScript, JSON, and proto sources returns zero hits; there are no `.graphql`/`.gql` schema files anywhere, and no GraphQL dependency in `go.mod` or the web `package.json`. There is no GraphQL schema to point at.

**Actual API surface: Protocol Buffers / gRPC, exposed over Connect and gRPC-Gateway, with a generated OpenAPI spec.**

- **Schema of record — `.proto` files in `proto/api/v1/`:** `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, and shared `common.proto`. Internal persistence messages live alongside in `proto/store/`. Codegen is driven by Buf (`proto/buf.yaml`, `proto/buf.gen.yaml`).
- **Generated Go code — `proto/gen/`:** message and gRPC stubs (e.g. `proto/gen/api/v1/memo_service_grpc.pb.go`), Connect handlers (`proto/gen/api/v1/apiv1connect/memo_service.connect.go`), and gRPC-Gateway REST bindings (`proto/gen/api/v1/*.pb.gw.go`).
- **Server wiring:** `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`) mounts both the gRPC-Gateway and the Connect handlers onto the Echo server; the Connect handler adapters are in `server/router/api/v1/connect_services.go`.
- **The closest thing to a published schema document** is the generated OpenAPI spec, embedded into the binary at `proto/openapi_embed.go:4-5` (`//go:embed gen/openapi.yaml`) and served via `OpenAPIYAML()`. That's the REST-facing contract clients would consult.

Two adjacent surfaces that aren't GraphQL either, in case one of them is what you had in mind: raw HTTP file serving under `/file/...` (`server/router/fileserver/fileserver.go:121-125`), and an MCP (Model Context Protocol) endpoint in `server/router/mcp/`, which re-exposes the same v1 RPCs as tools (`server/router/mcp/catalog.go`) rather than defining its own schema.
