**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- **Abstraction — `internal/idp/idp.go`**: the package is deliberately thin. It defines only `IdentityProviderUserInfo` (`internal/idp/idp.go:3-8`) with `Identifier`, `DisplayName`, `Email`, `AvatarURL` — the normalized shape every provider must produce. Note there's no Go `interface` type here; the abstraction is this shared return struct plus the `NewIdentityProvider` / `ExchangeToken` / `UserInfo` method shape that implementations follow by convention.

- **Implementation — `internal/idp/oauth2/oauth2.go`**: `IdentityProvider` (`:20`) wrapping a `storepb.OAuth2Config`, with `NewIdentityProvider` (`:27`, validating required config fields), `ExchangeToken` (`:47`, authorization-code exchange with optional PKCE `code_verifier`), and `UserInfo` (`:83`, bearer-token call to `UserInfoUrl` mapping raw claims onto `idp.IdentityProviderUserInfo` via the configured `FieldMapping`).

OAuth2 is the only concrete implementation that ships — it's the only subpackage under `internal/idp/`, and the stored provider enum has just two values, `TYPE_UNSPECIFIED` and `OAUTH2` (`proto/gen/store/idp.pb.go:27-28`). The single dispatch site reflects that: `resolveSSOIdentity` branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` and constructs `oauth2.NewIdentityProvider` (`server/router/api/v1/auth_service_sso.go:120-121`), with no other provider branch.
