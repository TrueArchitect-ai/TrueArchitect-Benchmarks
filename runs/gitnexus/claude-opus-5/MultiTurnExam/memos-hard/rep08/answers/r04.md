**Premise correction: neither. There is no message broker in this codebase — no NATS, no RabbitMQ, and no queue is declared anywhere.** A case-insensitive grep across all Go sources plus `go.mod`/`go.sum` for `nats|rabbitmq|amqp|kafka|streadway|pubsub|sqs` returns a single hit, and it's coincidental base64 noise inside an unrelated `xxhash` checksum line (`go.sum:63`). No broker client is a dependency; nothing connects to one.

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool, entirely inside `internal/webhook/webhook.go`.**

- **The "queue"** is a package-level buffered channel of 128 payloads: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`). It's declared in the same `var` block as the HTTP client — there is no external declaration, no durable storage, and no separate process.
- **The "workers"** are four goroutines started in the package `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over `asyncPostQueue` and calls `Post(payload)` for every item, logging a warning on failure (`:46-51`).
- **Producers** call `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send. This is important: **on a full queue the payload is silently dropped**, with only a `slog.Warn` (`:191-195`) — there's no retry, no dead-letter, no backpressure onto the caller. Producers are the memo lifecycle handlers via `dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:71`, `:43`).
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120`): JSON-marshal, optional Standard Webhooks HMAC-SHA256 signing (`:133-150`), then `safeClient.Do(req)` at `:152` with a 30-second timeout and SSRF-guarded dialer.

Practical consequences of this being a channel rather than a broker: the queue is process-local (each replica has its own), it's purely in-memory so anything pending is lost on restart or crash, a single delivery failure is logged and abandoned rather than requeued, and concurrency is capped at exactly 4 in-flight deliveries per process. Since `init()` runs on package import, the workers start automatically with no wiring in `server/server.go` — which is why you won't find a startup registration site for them.
