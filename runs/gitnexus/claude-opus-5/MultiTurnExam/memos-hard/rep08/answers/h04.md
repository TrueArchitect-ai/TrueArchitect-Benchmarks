**No — in production code the MySQL driver is only ever constructed inside the factory. (One test constructs the struct literal directly; see below.)**

Evidence:

1. **The factory is the sole caller of the constructor.** `mysql.NewDB` is defined at `store/db/mysql/mysql.go:20` and invoked exactly once in the whole repo: `store/db/db.go:22`, inside `NewDBDriver`'s `switch profile.Driver` (`store/db/db.go:14-27`).

2. **The package is imported exactly once.** A repo-wide grep for the import path `github.com/usememos/memos/store/db/mysql` (excluding the package's own files) returns a single hit — `store/db/db.go:8`. No other package can construct it, since `DB` and `NewDB` are only reachable through that import.

3. **All driver acquisition funnels through the factory.** The only `NewDBDriver` callers are test helpers — `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` — each passing a profile rather than picking a driver themselves. Direct `sqlite.NewDB` calls do exist in two tests (`store/deployment_config_test.go:416`, `store/demo_seed_test.go:24`), but there is no MySQL equivalent.

**One caveat:** an in-package unit test builds the struct directly rather than through the constructor — `db := &DB{}` at `store/db/mysql/auth_config_test.go:12`. That's a zero-value `DB` (no `*sql.DB` connection) used only to call the pure error-classification method `IsRetryableAuthenticationMutationError`; it's in-package Go so it needs no import, and it isn't a real driver instantiation. Aside from that, and the factory's own `driver := DB{profile: profile}` at `store/db/mysql/mysql.go:29` (inside `NewDB` itself), nothing constructs it.
