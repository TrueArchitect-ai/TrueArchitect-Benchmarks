**`s3presign.Runner` (S3 presigned-URL refresh runner, `server/runner/s3presign/runner.go`) — once at startup, then every 12 hours — `server/server.go:162-171` (inside `startBackgroundRunners`, itself called from `Server.Start` at `server/server.go:129`)**

How it works:

- **Component**: `Runner` in `server/runner/s3presign/runner.go:16`. `CheckAndPresign` (`runner.go:47`) pages through attachments with `StorageType == AttachmentStorageType_S3` in batches of 100 (`runner.go:55-65`), calls `s3Client.PresignGetObject` (`runner.go:108`, implemented at `internal/storage/s3/s3.go:70`), and writes the fresh URL back via `UpdateAttachment` along with an updated `LastPresignedTime` (`runner.go:114-120`). So the stale-link problem it solves is expiring S3 presigned URLs stored in `Attachment.Reference`.
- **Schedule**: `runnerInterval = time.Hour * 12` (`runner.go:27`), driven by a `time.Ticker` in `Run` (`runner.go:29-41`). Per-attachment it skips any object whose presigned URL is still valid for the next 4 days — URLs are issued with a 5-day expiry (`runner.go:85-91`), so each object is effectively re-signed about once every 4 days.
- **Wiring**: `server/server.go:162` constructs it, `:163` does an immediate `RunOnce(ctx)` pass at startup, and `:166-171` launches `Run` in a tracked goroutine under a dedicated cancellable `s3Context` (`:156-159`) so `Shutdown` → `stopBackgroundRunners` (`server.go:176`) can stop it cleanly.
