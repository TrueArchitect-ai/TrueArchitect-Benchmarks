**Premise correction: there is no per-user API rate-limiting middleware in this repository. It isn't registered anywhere, and there are no request limits to report.**

Evidence:

- A case-insensitive grep across all Go files for `rate.?limit|ratelimit|throttl|golang.org/x/time/rate|StatusTooManyRequests|429` returns exactly one hit, and it's a doc comment listing future ideas — `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"). No implementation accompanies it.
- `go.mod` declares no rate-limiting dependency (no `golang.org/x/time`, no `ulule/limiter`, no `echo` rate-limiter module). Echo's built-in `middleware.RateLimiter` is never imported or used.
- **Every HTTP middleware actually registered** is: `middleware.Recover()` (`server/server.go:51`), `newCORSMiddleware(profile)` (`server/server.go:52`), and, on the frontend surface, `middleware.StaticWithConfig` and `spaFallbackMiddleware` (`server/router/frontend/frontend.go:54`, `:59`). None of these limit request rates.
- **Every Connect/gRPC interceptor** in `server/router/api/v1/connect_interceptors.go` is likewise unrelated: `MetadataInterceptor` (`:22`), `LoggingInterceptor` (`:98`), and `RecoveryInterceptor` (`:164`). Authentication and authorization are handled separately by `NewAuthorizer` in `server/router/api/v1/v1.go:69`, which gates *who* may call an RPC, not *how often*.
- The only other mention repo-wide is aspirational documentation — `internal/email/README.md:286-295` sketches a rate-limiting example for email sending that isn't wired into anything.

**Concurrency limits that exist but are not rate limits.** A few semaphores bound *simultaneous* expensive work, and are easy to mistake for throttling: `thumbnailSemaphore` and `imageProcessingSemaphore` in `APIV1Service` (`server/router/api/v1/v1.go:58-59`, weights 3 and 2), and `thumbnailSemaphore` in the file server (`server/router/fileserver/fileserver.go:107`). These cap in-flight operations globally, not per user, and excess requests wait rather than being rejected with 429.

If you need per-user rate limiting, it would have to be added — the natural insertion points are an Echo middleware alongside `server/server.go:51-52` for the raw HTTP surfaces, or a new Connect interceptor registered next to the existing three in `server/router/api/v1/v1.go`, keyed off the authenticated user resolved by the authorizer.
