**Explicit Go code — there is no database-level rule that could do it; evidence below.**

**What I checked, and what it showed:**

**1. The explicit Go deletion.** `DeleteUser` runs everything in one transaction (`store/db/sqlite/user_delete.go:29-59`), and its target-deletion step removes reactions in two distinct passes (`deleteUserTargetsTx`, `store/db/sqlite/user_delete.go:92-127`):

- `deleteReactionsByContentIDsTx` (`store/db/sqlite/user_delete.go:380`) — `DELETE FROM reaction WHERE content_id IN (…)`, batched at 500, covering reactions *on* the deleted user's memos (including comment descendants, gathered by the recursive memo-tree query at `:134-147`; content IDs are built as `"memos/"+uid` at `:512-518`).
- `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:400`) — `DELETE FROM reaction WHERE creator_id = ?`, i.e. the user's own reactions left on *other people's* memos. This is the one that directly answers the question.

Both run before `deleteMemosTx` (`:451`) and `deleteUserRowTx` (`:461`), so the cleanup is not relying on any later cascade.

**2. All three drivers do the same thing.** The identical pair exists in `store/db/postgres/user_delete.go:380` / `:400` and `store/db/mysql/user_delete.go:417` / `:437`, both invoked at `:96` and `:102` of their respective files.

**3. No database-level rule exists.** The `reaction` table carries no foreign key in any dialect — `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98` declare only `creator_id INTEGER NOT NULL` with a `UNIQUE(creator_id, content_id, reaction_type)` constraint. Grepping every `CREATE TABLE reaction` across migration history (`store/migration/{sqlite,postgres,mysql}/0.20/00__reaction.sql` plus the three `LATEST.sql`) for `FOREIGN KEY`/`REFERENCES` returns nothing, so it never had one. Other tables do use cascades (e.g. `memo_share` → `memo` at `store/migration/sqlite/LATEST.sql:109`), which confirms the absence on `reaction` is a real gap, not a grep artifact.

**4. Even if an FK existed, SQLite wouldn't enforce it.** The connection is opened with foreign keys explicitly disabled: `_pragma=foreign_keys(0)` in `store/db/sqlite/sqlite.go:53`.
