The following tables are directly affected when `DeleteMemo` runs:

1. **`memo_relation`** — deleted by `Store.DeleteMemo` in `store/memo.go:142–146` (both as source and target)
2. **`attachment`** — deleted by `Store.DeleteAttachment` called from `store/memo.go:153–156`
3. **`memo`** — the memo row itself, deleted last at `store/memo.go:158`

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567–577`), comment memos are deleted first via recursive `Store.DeleteMemo` calls, which in turn cascade through the same three tables for each comment. The reactions and attachments are also loaded before deletion for webhook dispatch (`memo_service.go:545–554`), but no explicit `DELETE` on the `reaction` table is performed in the delete path.

So the directly affected tables are: `memo_relation`, `attachment`, `memo`.
