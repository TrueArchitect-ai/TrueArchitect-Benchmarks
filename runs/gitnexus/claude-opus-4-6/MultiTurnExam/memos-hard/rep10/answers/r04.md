The premise is incorrect — there is no message broker (neither NATS nor RabbitMQ) involved in webhook delivery. The webhook workers consume from a plain **in-memory Go buffered channel** declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutines are spawned in the package `init()` function (`internal/webhook/webhook.go:42–55`) to read from this channel and call `Post()` for each payload. Callers enqueue work via `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send to the channel and drops the event if the buffer is full. There is no external queue or broker.
