The premise is incorrect — there is no Redis connection. The cache layer is entirely **in-memory**, implemented as a `sync.Map`-backed cache in `store/cache/cache.go`. There is no Redis dependency anywhere in the codebase.

User entries are cached by `Store.userCache` (created in `store/store.go`) using the default configuration (`cache.DefaultConfig()` at `store/cache/cache.go:57–64`), which sets a **10-minute TTL** (`DefaultTTL: 10 * time.Minute`). Entries are actively evicted on access if expired (`cache.go:135–143`) and also cleaned up in the background every 5 minutes (`CleanupInterval: 5 * time.Minute`).
