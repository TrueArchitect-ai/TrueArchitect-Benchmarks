Explicit Go code; reactions are removed by two dedicated functions called within the `deleteUserTargetsTx` transaction in every database driver:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions on the user's memos (by `content_id` matching the memo UIDs):
   - `store/db/sqlite/user_delete.go:380`
   - `store/db/mysql/user_delete.go:417`
   - `store/db/postgres/user_delete.go:380`

2. **`deleteReactionsByCreatorTx`** — deletes reactions the user themselves created (by `creator_id`):
   - `store/db/sqlite/user_delete.go:400`
   - `store/db/mysql/user_delete.go:437`
   - `store/db/postgres/user_delete.go:400`

Both are called from `deleteUserTargetsTx` (e.g., `store/db/sqlite/user_delete.go:96–103`) inside the same transaction that deletes the user row, ensuring reactions are cleaned up before the user and their memos are removed. There are no database-level foreign key cascades handling this — it is all done in application-level Go code with explicit `DELETE FROM reaction` SQL statements.
