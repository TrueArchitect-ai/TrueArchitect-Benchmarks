The premise is incorrect — there is no Redis connection anywhere in this codebase. The cache layer is a purely **in-process, in-memory implementation** (`store/cache/cache.go`) using a `sync.Map`-style structure with TTL-based expiration and periodic cleanup.

User entries are cached by `userCache` (`store/store.go:28`), which is constructed with the default `cacheConfig` at `store/store.go:52`. That config sets a **10-minute TTL** (`DefaultTTL: 10 * time.Minute`) and a 5-minute cleanup interval, with a max of 1000 items (`store/store.go:40–44`). No external cache service (Redis or otherwise) is involved.
