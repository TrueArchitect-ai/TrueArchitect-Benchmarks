Explicit Go code; the `deleteUserTargetsTx` function in each database driver handles reaction removal via two dedicated functions:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions on the user's memos (by `content_id`), e.g. `store/db/mysql/user_delete.go:417-425`, `store/db/sqlite/user_delete.go:380-388`, `store/db/postgres/user_delete.go:380-388`

2. **`deleteReactionsByCreatorTx`** — deletes reactions the user themselves created (by `creator_id`), e.g. `store/db/mysql/user_delete.go:437-439`, `store/db/sqlite/user_delete.go:400-402`, `store/db/postgres/user_delete.go:400-402`

Both are called from `deleteUserTargetsTx` within the delete-user transaction (e.g. `store/db/mysql/user_delete.go:96` and `:102`). There are no database-level foreign key cascades involved — these are explicit `DELETE FROM reaction WHERE ...` statements in Go code, executed in batches within the same transaction that removes the user.
