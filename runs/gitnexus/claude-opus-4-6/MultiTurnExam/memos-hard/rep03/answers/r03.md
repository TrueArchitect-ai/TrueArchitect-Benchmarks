The premise is incorrect — there is no nightly database-cleanup cron job in this codebase. While an `internal/scheduler` package exists, it is never instantiated or used by the server at runtime (no imports of it in `server/`). The only "cleanup" in the system is the in-memory cache eviction loop in `store/cache/cache.go`, which runs every 5 minutes to remove expired cache entries — this is not a database cleanup job. The background runners that do exist (`s3presign` and `memopayload`) are interval-based Go goroutines using `time.Ticker`, not cron-scheduled database cleanup tasks.
