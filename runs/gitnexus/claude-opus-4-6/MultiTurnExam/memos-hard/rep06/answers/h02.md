**Delivery function** — `Post` — `internal/webhook/webhook.go:120`

The `Post` function marshals a `WebhookRequestPayload` to JSON, constructs an HTTP POST request (optionally HMAC-SHA256 signed per Standard Webhooks), and sends it via a shared `safeClient`. Async dispatch goes through `PostAsync` (line 184), which enqueues payloads onto a buffered channel consumed by 4 background goroutines (initialized in `init()`, line 42).

**Protection mechanism** — `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`

SSRF protection is two-layered:

1. **At dial time** (`safeDialContext`, `internal/webhook/webhook.go:59`): The custom `http.Transport` on `safeClient` resolves the target hostname via DNS and checks every returned IP against reserved/private CIDR ranges before opening the connection. This also defeats DNS rebinding attacks.

2. **At URL registration time** (`ValidateURL`, `internal/webhook/validate.go:62`): When a webhook URL is first configured, the URL is parsed, its scheme is restricted to `http`/`https`, the hostname is resolved, and every resulting IP is checked against the same `isReservedIP` blocklist.

The blocked ranges (defined in `internal/webhook/validate.go:14`) cover IPv4 loopback, RFC-1918 private, link-local (including cloud IMDS 169.254.x.x), and their IPv6 equivalents.
