Explicit Go code; reactions are removed by two dedicated functions called within the user-deletion transaction:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions on all of the user's memos (by `content_id`).
   - SQLite: `store/db/sqlite/user_delete.go:380–388`
   - MySQL: `store/db/mysql/user_delete.go:417–425`

2. **`deleteReactionsByCreatorTx`** — deletes reactions the user themselves created (by `creator_id`).
   - SQLite: `store/db/sqlite/user_delete.go:400–403`
   - MySQL: `store/db/mysql/user_delete.go:437–440`

Both are called from `deleteUserTargetsTx` in each driver (SQLite: `store/db/sqlite/user_delete.go:96,102`; MySQL: `store/db/mysql/user_delete.go:96,102`), which runs inside a single transaction. There are no foreign-key `ON DELETE CASCADE` rules doing this — the `reaction` table schema (e.g. `store/migration/sqlite/LATEST.sql`, `store/migration/mysql/LATEST.sql`) does not define cascading deletes from the `user` table. The cleanup is entirely application-level Go code.
