The premise is incorrect — there is no message broker (neither NATS nor RabbitMQ) involved in webhook delivery. The webhook workers consume from a plain **in-memory Go buffered channel**.

The queue is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the package's `init()` function (`internal/webhook/webhook.go:42–55`) that range over this channel and call `Post()` for each payload. Callers enqueue work via `PostAsync()` (`internal/webhook/webhook.go:184`), which performs a non-blocking send and drops the payload with a warning if the channel is full. There is no external message broker, no persistence, and no retry queue — everything is in-process.
