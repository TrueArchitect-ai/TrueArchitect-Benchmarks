**Delivery function** — `Post` — `internal/webhook/webhook.go:120`

This function marshals the payload to JSON, constructs an HTTP POST request, optionally signs it with HMAC-SHA256, and sends it via `safeClient`. An async variant `PostAsync` (line 184) enqueues payloads onto a buffered channel drained by 4 worker goroutines (lines 42–55).

**Protection mechanism** — SSRF guard via `safeDialContext` + `ValidateURL` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:62`

Two layers prevent targeting internal network addresses:

1. **At dial time** (`safeDialContext`, `internal/webhook/webhook.go:59`): The `safeClient` HTTP client uses a custom `Transport` whose `DialContext` resolves the target hostname and rejects any IP that falls within reserved/private CIDR ranges (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents). This also defeats DNS rebinding attacks since the check happens at connection time, after DNS resolution.

2. **At registration time** (`ValidateURL`, `internal/webhook/validate.go:62`): When a webhook URL is first configured, it is validated to ensure it parses correctly, uses `http`/`https` scheme, and does not resolve to a reserved/private IP.

The blocked CIDR ranges are defined in `reservedCIDRs` (`internal/webhook/validate.go:14`) and checked by `isReservedIP` (`internal/webhook/validate.go:44`), with an opt-out flag `AllowPrivateIPs` for self-hosted deployments that need to target local-network services.
