Reactions are removed by **explicit Go code**, not by a database-level rule (no foreign key cascades). The `deleteUserTargetsTx` function in each driver performs two reaction-deletion steps within the user-delete transaction:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions on the user's memos (by `content_id`):
   - `store/db/sqlite/user_delete.go:380`
   - `store/db/mysql/user_delete.go:417`
   - `store/db/postgres/user_delete.go:380`

2. **`deleteReactionsByCreatorTx`** — deletes reactions the user themselves created (by `creator_id`):
   - `store/db/sqlite/user_delete.go:400`
   - `store/db/mysql/user_delete.go:437`
   - `store/db/postgres/user_delete.go:400`

Both are called from `deleteUserTargetsTx` in each driver (e.g., `store/db/sqlite/user_delete.go:96–103`). I also checked the schema migrations (`store/migration/sqlite/LATEST.sql`, `store/migration/mysql/LATEST.sql`, `store/migration/postgres/LATEST.sql`) — the `reaction` table has no `ON DELETE CASCADE` foreign key constraints that would handle this automatically.
