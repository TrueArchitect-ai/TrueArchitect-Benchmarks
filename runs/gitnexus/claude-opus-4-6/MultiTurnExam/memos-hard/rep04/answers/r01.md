The question's premise is incorrect — there is no Redis connection. The cache layer is entirely **in-memory**, implemented as a `sync.Map`-backed store in `store/cache/cache.go`. There is no Redis dependency anywhere in the codebase.

The user cache is configured in `store/store.go:51–53`, where all three caches (`instanceSettingCache`, `userCache`, `userSettingCache`) are created with the same `cacheConfig`. That config uses `cache.DefaultConfig()` (`store/cache/cache.go:57–64`), which sets a **default TTL of 10 minutes**, a cleanup interval of 5 minutes, and a max of 1000 items. There is no per-type TTL override for user entries — they use the same 10-minute default.
