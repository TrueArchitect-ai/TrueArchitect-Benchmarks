Here are the distinct memo visibility enforcement sites:

1. **`checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:39` — per-memo guard used by `GetMemo` (line 356) and `ListMemoComments` (line 148 in `memo_service_comments.go`). Blocks unauthenticated access to non-PUBLIC memos; blocks PRIVATE memos from non-owners.

2. **`ListMemos` / `ListMemoComments` / `ListMemoRelations` visibility filter injection** — `server/router/api/v1/memo_service_converter.go:182–187`, `memo_service_comments.go:158–160`, `memo_relation_service.go:108–112` — injects a filter predicate into the database query: anonymous users see only `PUBLIC`; authenticated users see `PUBLIC`, `PROTECTED`, and their own memos. This is the bulk-listing enforcement path.

3. **`CreateMemoComment` visibility check** — `server/router/api/v1/memo_service_comments.go:41` — prevents commenting on a PRIVATE memo unless the user is its creator or a super-user.

4. **`ListMemoAttachments` visibility check** — `server/router/api/v1/memo_attachment_service.go:213–225` — enforces visibility when listing a memo's attachments; blocks unauthenticated and non-owner access to PRIVATE memo attachments.

5. **File server attachment access control** — `server/router/fileserver/fileserver.go:674–701` — enforces visibility when serving attachment files over HTTP; allows anonymous access only for PUBLIC memos on public instances, checks share tokens, and blocks PRIVATE memo attachments from non-owners/non-admins.

6. **SSE event delivery filtering (`canReceive`)** — `server/router/api/v1/sse_hub.go:134–144` — filters real-time server-sent events so PRIVATE memo events are only delivered to the creator or admins.

7. **RSS feed** — `server/router/rss/rss.go:90` — only fetches `PUBLIC` memos for the RSS feed.

8. **Sitemap generation** — `server/router/frontend/frontend.go:150` — only includes `PUBLIC` memos in the sitemap.
