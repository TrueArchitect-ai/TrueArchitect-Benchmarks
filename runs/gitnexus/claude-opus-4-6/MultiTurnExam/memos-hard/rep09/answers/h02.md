**Delivery function** — `Post` (synchronous) and `PostAsync` (enqueues to a buffered channel for background workers) — `internal/webhook/webhook.go:120` and `internal/webhook/webhook.go:184`.

**Protection mechanism** — SSRF guard via `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the target hostname and rejects any IP in a reserved/private range using `isReservedIP` (`internal/webhook/validate.go:44`). The blocked ranges (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents) are defined in `reservedCIDRs` at `internal/webhook/validate.go:14`. This check is applied in two places:

1. **At dial time** — the `safeClient` HTTP client uses a custom `Transport` whose `DialContext` is `safeDialContext`, which resolves DNS and blocks reserved IPs before any connection is established (`internal/webhook/webhook.go:32-37`). This also defeats DNS rebinding.
2. **At URL registration time** — `ValidateURL` (`internal/webhook/validate.go:62`) performs the same DNS-resolve-and-check when a user saves a webhook URL, rejecting it early with a gRPC `InvalidArgument` error.
