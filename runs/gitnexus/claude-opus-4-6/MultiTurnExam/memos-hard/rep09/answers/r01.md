The question's premise is incorrect — there is no Redis connection. The cache layer is a **pure in-memory implementation** using Go's `sync.Map`, defined in `store/cache/cache.go`. There is no Redis dependency anywhere in the codebase.

User entries use the **default cache configuration** (`store/cache/cache.go:57-64`): a **10-minute TTL**, 5-minute cleanup interval, and a max of 1000 items. The user cache is created via `cache.NewDefault()` in the `Store` constructor (`store/store.go`), which applies these defaults. There is no per-entry-type TTL override — user cache entries are stored with `Set()` (`store/user.go:167`), which uses the default TTL.
