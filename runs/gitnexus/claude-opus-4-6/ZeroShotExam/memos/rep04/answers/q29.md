**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` token to the `Authorization` header of every outgoing request, handles 401 retries by refreshing the token, and redirects on auth failure.

**Token kinds managed:**
1. **Access tokens** (short-lived JWTs, 15 minutes) — stored/retrieved via `getAccessToken()`/`setAccessToken()` from `web/src/auth-state.ts`, attached as `Bearer <token>` in the `Authorization` header.
2. **Refresh tokens** — sent as an HTTP cookie (`credentials: "include"`); used to obtain new access tokens via `refreshAuthClient.refreshToken()`.
3. **Personal Access Tokens (PAT)** — long-lived tokens for programmatic access, also sent as `Bearer` tokens and distinguished server-side by a `memos_pat_` prefix.

**Backend validation package:** `server/auth` (specifically `server/auth/authenticator.go`). The `Authenticator` struct validates all three token types: `AuthenticateByAccessTokenV2` for JWTs (stateless), `AuthenticateByRefreshToken` for refresh tokens (checked against the database), and `AuthenticateByPAT` for personal access tokens (hash lookup). The server-side Connect interceptor at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`, line 208) delegates to this package via the `Authorizer`.
