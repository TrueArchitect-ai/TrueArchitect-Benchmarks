The following database tables are affected when `DeleteMemo` runs:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
2. **`memo_relation`** — all relation rows where the memo is either `memo_id` or `related_memo_id` are deleted (`store/memo.go:142-146`, `store/db/sqlite/memo_relation.go:148-150`)
3. **`attachment`** — all attachments linked to the memo are deleted (`store/memo.go:149-156`, `store/db/sqlite/attachment.go:212`)

The cascade path in `store/memo.go:140-158` (`Store.DeleteMemo`) is:
1. Delete from `memo_relation` where `memo_id` = target
2. Delete from `memo_relation` where `related_memo_id` = target
3. List and delete each row from `attachment` where `memo_id` = target
4. Delete from `memo` where `id` = target

Additionally, the service layer (`server/router/api/v1/memo_service.go:567-577`) first finds comment memos (via `memo_relation` with type `Comment`) and recursively calls `Store.DeleteMemo` for each comment, so the same three tables (`memo`, `memo_relation`, `attachment`) are cascaded for comment memos as well.

**Table list: `memo`, `memo_relation`, `attachment`**
