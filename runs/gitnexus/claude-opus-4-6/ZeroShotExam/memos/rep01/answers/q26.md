The following database tables are affected when `DeleteMemo` runs:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
2. **`memo_relation`** — relations where the memo is either source (`memo_id`) or target (`related_memo_id`) are explicitly deleted in `store/memo.go:142-146`
3. **`attachment`** — attachments linked to the memo are listed and individually deleted in `store/memo.go:149-156` (SQL at `store/db/sqlite/attachment.go:212`)
4. **`memo_share`** — deleted via `ON DELETE CASCADE` foreign key on `memo_id` referencing `memo(id)` (`store/migration/sqlite/LATEST.sql:109`)

Additionally, for comment memos: the service handler at `server/router/api/v1/memo_service.go:568-577` finds all `memo_relation` rows of type `Comment` pointing at the memo and recursively calls `DeleteMemo` on each comment memo, which cascades the same set of table deletions for each comment.

**Table list: `memo`, `memo_relation`, `attachment`, `memo_share`**
