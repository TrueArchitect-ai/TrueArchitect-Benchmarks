**Runner actually started by the server:**

- **s3presign runner** — driven by a `time.Ticker` set to a 12-hour interval (`server/runner/s3presign/runner.go:27`). The server calls `s3presignRunner.RunOnce(ctx)` for an immediate first run, then launches `s3presignRunner.Run(s3Context)` in a goroutine which loops on the ticker (`server/server.go:153–171`). It refreshes pre-signed S3 URLs for attachments.

**Runner that exists but is NOT started by the server:**

- **memopayload runner** (`server/runner/memopayload/runner.go`) — has a `Runner` struct with a `RunOnce` method that rebuilds memo payloads, but the server never instantiates or starts it. The only usage of this package is calling its `RebuildMemoPayload` function directly (as a plain function, not as a runner) in the memo gRPC service during create/update operations (`server/router/api/v1/memo_service.go:108,447`).

**Scheduling infrastructure NOT used by the server:**

- The `internal/scheduler` package (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`) is a fully-featured cron-expression-based job scheduler supporting named jobs, cron parsing, timezone configuration, and middleware. It is **never imported outside its own test files** — only `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go` reference it. No production code uses it. The s3presign runner uses a simple `time.Ticker` loop instead.
