Four memo lifecycle events dispatch webhooks, each with its own dispatch function in `server/router/api/v1/memo_service_webhooks.go`:

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

The first three delegate to the private helper `dispatchMemoRelatedWebhook` (same file, line 48), which builds the payload and calls `webhook.PostAsync`. `DispatchMemoCommentCreatedWebhook` (line 30) builds its payload inline but also calls `webhook.PostAsync`.

All four converge on `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload into the buffered `asyncPostQueue` channel. Four goroutines (started in `init()`, line 42) drain that channel and call `Post` (`internal/webhook/webhook.go:120`) — the single synchronous delivery function that marshals the JSON, signs it (if a secret is configured), and sends the HTTP POST via `safeClient`.
