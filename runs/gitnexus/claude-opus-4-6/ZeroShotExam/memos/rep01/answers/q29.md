**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` token to every outgoing request via the `Authorization` header, handles 401 retries by refreshing the token, and redirects on auth failure.

**Token kinds:** Three token types are managed:
1. **Access tokens** (short-lived JWT, 15-minute TTL) — sent as `Bearer` in the `Authorization` header; validated statelessly by signature.
2. **Refresh tokens** (long-lived JWT, 30-day TTL) — stored in an HTTP cookie named `memos_refresh`; used to obtain new access tokens.
3. **Personal Access Tokens (PAT)** — prefixed `memos_pat_`, long-lived, SHA-256–hashed and looked up in the database.

**Backend package path:** `server/auth` — the `Authenticator` struct (`server/auth/authenticator.go`) validates all three token types, and `server/auth/token.go` contains the JWT generation/parsing logic (HS256 signing, claims structures, PAT hashing).
