**Runners the server actually starts:**

- **S3 presign runner** — `time.Ticker` every 12 hours (`server/runner/s3presign/runner.go:27,29`). Launched explicitly in `server.Server.startBackgroundRunners()` (`server/server.go:153–171`) as a managed goroutine with cancellation and WaitGroup tracking. Regenerates expiring S3 presigned URLs for attachments.

- **Webhook dispatch workers (x4)** — channel-driven (`asyncPostQueue`, buffered 128). Started via package-level `init()` in `internal/webhook/webhook.go:42–55`. Each goroutine reads payloads from the channel and POSTs them. Triggered by `PostAsync()` calls from memo creation/update handlers.

- **Email dispatch workers (x2)** — channel-driven (`asyncEmailQueue`, buffered 128). Started via package-level `init()` in `internal/email/email.go:16–36`. Each goroutine reads email requests from the channel and sends via SMTP. Triggered by `SendAsync()`.

- **Cache cleanup goroutines (x3)** — `time.Ticker` every 5 minutes (`store/cache/cache.go:83`). One per cache instance created in `store/store.go:51–53` (`instanceSettingCache`, `userCache`, `userSettingCache`). Evicts expired entries.

**Unused scheduling infrastructure:**

The `internal/scheduler/` package is a fully-featured cron-style job scheduler (cron expression parsing in `parser.go`, job lifecycle in `job.go`, middleware support in `middleware.go`, graceful shutdown in `scheduler.go`). It is **never imported outside its own package and test files** — zero references to `scheduler.New()` or `scheduler.Register()` from any server or application code. The S3 presign runner uses a simple `time.Ticker` loop instead.
