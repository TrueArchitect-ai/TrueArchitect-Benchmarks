**Interceptor path:** `web/src/connect.ts` — defines `authInterceptor`, a ConnectRPC `Interceptor` that attaches a `Bearer` token via the `Authorization` header on every outgoing request and handles automatic retry with token refresh on `Unauthenticated` responses.

**Token kinds managed:**
1. **Access token** — a short-lived JWT stored in-memory and persisted to `localStorage` (key `memos_access_token`). Attached as `Bearer <token>` on each request.
2. **Refresh token** — a long-lived JWT sent as an HTTP-only cookie (`memos_refresh`). Used to obtain new access tokens via a dedicated `refreshTransport` (same file, line ~65) that has no interceptors to avoid recursion.
3. **Personal Access Token (PAT)** — long-lived tokens (prefixed `memos_pat_`) also sent as `Bearer` tokens for programmatic API access.

Frontend token state (read/write/sync across tabs) lives in `web/src/auth-state.ts`, with a proactive refresh hook at `web/src/hooks/useTokenRefreshOnFocus.ts`.

**Backend validation package:** `server/auth/` (Go `package auth`). Key files:
- `server/auth/token.go` — JWT generation and parsing (`ParseAccessTokenV2`, `ParseRefreshToken`, `GeneratePersonalAccessToken`) using `golang-jwt/jwt/v5` with HS256.
- `server/auth/authenticator.go` — `Authenticator` struct with methods `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`.
- `server/auth/extract.go` — `ExtractBearerToken` (parses `Authorization` header) and `ExtractRefreshTokenFromCookie`.

The server-side ConnectRPC interceptor at `server/router/api/v1/connect_interceptors.go` calls into this package to validate tokens on every inbound request.
