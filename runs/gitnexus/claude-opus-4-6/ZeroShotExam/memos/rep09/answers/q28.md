The server starts **one** background worker/runner:

- **S3 presign runner** — driven by a `time.Ticker` set to every 12 hours (`runnerInterval = 12h`). It is launched as a goroutine in `server/server.go:153-174` (`startBackgroundRunners`), which calls `s3presign.NewRunner` and runs it via `s3presignRunner.Run(ctx)`. The runner also executes once synchronously at startup via `RunOnce(ctx)` (line 163). The ticker-based loop lives in `server/runner/s3presign/runner.go:29-41`.

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — A full cron-expression-based job scheduler (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) with support for cron expressions, per-job timezones, middleware chains, and graceful shutdown. It is **never imported or used** by the server or any production code — no file outside `internal/scheduler/` imports it (only its own `_test.go` files reference it). The server's sole background runner uses a simple `time.Ticker` instead.

- **`server/runner/memopayload/` runner** — Defines a `Runner` struct with a `RunOnce` method that batch-rebuilds all memo payloads, but the server **never instantiates or starts** this runner. Only the standalone `RebuildMemoPayload` function from this package is called inline by `server/router/api/v1/memo_service.go` (lines 108, 447) during individual memo create/update operations — not as a background job.
