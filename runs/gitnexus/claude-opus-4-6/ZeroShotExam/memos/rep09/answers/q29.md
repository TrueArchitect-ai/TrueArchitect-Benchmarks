**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` token to every outgoing request's `Authorization` header, handles 401 retries by refreshing the token, and redirects on auth failure.

**Token kinds managed:**

1. **Access tokens (JWT, short-lived ~15 min)** — stored in-memory and localStorage by `web/src/auth-state.ts`; set on the `Authorization: Bearer <token>` header. The interceptor proactively refreshes them before expiry and reactively refreshes on `Unauthenticated` errors.
2. **Refresh tokens** — carried as an HTTP cookie (`credentials: "include"` on fetch); used by `refreshAuthClient.refreshToken()` to obtain new access tokens. The interceptor itself never reads the cookie directly — the browser sends it automatically.
3. **Personal Access Tokens (PAT)** — long-lived tokens with a `memos_` prefix, also sent as `Bearer` tokens; handled on the backend side (the frontend interceptor treats them identically to access tokens).

**Backend validation package:** `server/auth` (specifically `server/auth/authenticator.go`). The `Authenticator` struct validates all three token kinds: `AuthenticateByAccessTokenV2` for JWTs (stateless), `AuthenticateByRefreshToken` for refresh tokens (database-checked), and `AuthenticateByPAT` for personal access tokens (hash-based database lookup).
