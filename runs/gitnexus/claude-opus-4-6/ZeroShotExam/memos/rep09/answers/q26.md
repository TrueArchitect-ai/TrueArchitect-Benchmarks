The following database tables are affected when `DeleteMemo` runs:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
2. **`memo_relation`** — all relation rows where the memo is either `memo_id` or `related_memo_id` are deleted (`store/memo.go:142–146`, `store/db/sqlite/memo_relation.go:148–150`)
3. **`attachment`** — all attachments linked to the memo are deleted (`store/memo.go:149–157`, `store/db/sqlite/attachment.go:212`)

The cascade is explicit in `store/memo.go:140–158`: `Store.DeleteMemo` first deletes `memo_relation` rows (both directions), then deletes associated `attachment` rows, then deletes the `memo` row itself.

Additionally, at the service layer (`server/router/api/v1/memo_service.go:567–577`), comment memos (child memos linked via `MemoRelationComment`) are recursively deleted by calling `Store.DeleteMemo` for each comment, which triggers the same three-table cascade for each comment memo.
