**Interceptor path:** `web/src/connect.ts` — defines `authInterceptor` (an `@connectrpc/connect` `Interceptor`) that attaches an `Authorization: Bearer <token>` header to every outgoing request, handles `Unauthenticated` errors with a single-retry refresh, and redirects to login on failure.

**Token kinds managed:**
1. **Access token** — short-lived JWT (15 min, audience `user.access-token`), stored in-memory and `localStorage` under `memos_access_token`, sent as `Bearer` header. Token state is managed in `web/src/auth-state.ts` with cross-tab sync via `BroadcastChannel`.
2. **Refresh token** — long-lived JWT (30 days, audience `user.refresh-token`), stored as an HTTP-only cookie named `memos_refresh`, sent automatically via `credentials: "include"`. Used by a dedicated `refreshTransport` (no auth interceptor, to avoid recursion) to obtain new access tokens.
3. **Personal access token (PAT)** — long-lived, prefixed `memos_pat_`, also sent as `Bearer` header for programmatic API access.

**Backend validation package:** `server/auth/` — the `Authenticator` struct in `server/auth/authenticator.go` provides `AuthenticateByAccessTokenV2` (stateless JWT validation), `AuthenticateByRefreshToken` (validates against DB for revocation), and `AuthenticateByPAT` (hash-based DB lookup). Token extraction lives in `server/auth/extract.go` (`ExtractBearerToken`, `ExtractRefreshTokenFromCookie`). The server-side ConnectRPC interceptor that calls into this package is `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`.
