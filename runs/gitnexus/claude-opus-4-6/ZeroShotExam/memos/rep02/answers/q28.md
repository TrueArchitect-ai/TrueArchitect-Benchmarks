**Runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (`server/runner/s3presign/runner.go:27`). Started in `server/server.go:162-171` via `startBackgroundRunners`. Runs once immediately at startup, then every 12h re-signs expiring S3 presigned URLs for attachments.

- **Cache cleanup goroutines (×3)** — `time.NewTicker` every 5 minutes (`store/cache/cache.go:83,201`). Three instances are launched automatically when the `Store` is created (`store/store.go:51-53`) for `instanceSettingCache`, `userCache`, and `userSettingCache`. Each evicts expired entries from its in-memory cache.

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — A fully-featured cron scheduler with cron expression parsing (5-field and 6-field), timezone support, middleware (recovery, logging, timeout), and graceful shutdown (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It is **never imported outside its own test files** — zero production usage anywhere in the server.

- **`server/runner/memopayload/runner.go`** — Defines a `Runner` struct with `NewRunner()` and `RunOnce()` methods, but neither is called anywhere. Only the standalone `RebuildMemoPayload` function from that package is used (inline during memo create/update in `server/router/api/v1/memo_service.go`). The runner scaffolding is dead code.
