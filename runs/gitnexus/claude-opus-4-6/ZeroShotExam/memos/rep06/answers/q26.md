When `DeleteMemo` runs, the following database tables are affected:

1. **`memo_relation`** — The store-level `DeleteMemo` (`store/memo.go:140-158`) explicitly deletes relations where the memo is either the source (`MemoID`) or target (`RelatedMemoID`) via two calls to `DeleteMemoRelation`, which issues `DELETE FROM memo_relation` (`store/db/sqlite/memo_relation.go:149`).

2. **`attachment`** — The store-level `DeleteMemo` lists all attachments for the memo and deletes each one via `DeleteAttachment`, which issues `DELETE FROM attachment` (`store/db/sqlite/attachment.go:212`).

3. **`memo`** — Finally, the driver-level `DeleteMemo` deletes the memo row itself with `DELETE FROM memo` (`store/db/sqlite/memo.go:239`).

Additionally, at the service level (`server/router/api/v1/memo_service.go:567-577`), before deleting the memo itself, the code finds all **comment** relations pointing to this memo and recursively calls `Store.DeleteMemo` for each comment memo — which in turn cascades through the same `memo_relation`, `attachment`, and `memo` deletions for those comments.
