**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` token to every outgoing request via the `Authorization` header, handles 401 retries by refreshing the token, and redirects on auth failure.

**Token kinds:** The system manages three token types:
1. **Access tokens (JWT)** — short-lived (15 min) tokens stored client-side and set as `Bearer` in the `Authorization` header. Validated statelessly on the backend.
2. **Refresh tokens** — longer-lived tokens stored as HTTP-only cookies (`credentials: "include"`), used to obtain new access tokens via `AuthService.RefreshToken`.
3. **Personal Access Tokens (PAT)** — long-lived tokens for programmatic access, also sent as `Bearer` tokens (distinguished by a prefix on the backend).

**Backend package:** `server/auth` (specifically `server/auth/authenticator.go`) — the `Authenticator` struct validates all three token types: `AuthenticateByAccessTokenV2` for JWTs, `AuthenticateByRefreshToken` for refresh tokens, and `AuthenticateByPAT` for personal access tokens. The server-side Connect interceptor lives at `server/router/api/v1/connect_interceptors.go` (`AuthInterceptor`, line 208), which delegates to the `Authorizer` (in `server/router/api/v1/authz.go`), which in turn calls `Authenticator.Authenticate`.
