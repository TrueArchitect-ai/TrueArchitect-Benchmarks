**Runners the server actually starts:**

- **S3 presign runner** — `time.Ticker` every 12 hours (plus one synchronous `RunOnce` at startup). Started as a background goroutine in `server/server.go:153-173`, runner defined in `server/runner/s3presign/runner.go:27-41`. Refreshes expiring presigned URLs for S3-stored attachments.

- **Webhook dispatch workers (x4)** — channel-consumer goroutines launched in `init()` at `internal/webhook/webhook.go:42-55`. Driven by a buffered channel (`asyncPostQueue`, capacity 128); payloads enqueued via `PostAsync()` from memo CRUD/comment handlers.

- **Email dispatch workers (x2)** — channel-consumer goroutines launched in `init()` at `internal/email/email.go:16-35`. Driven by a buffered channel (`asyncEmailQueue`, capacity 128); messages enqueued via `SendAsync()` from notification handlers.

- **Cache cleanup goroutines (x3)** — `time.Ticker` every 5 minutes. One per cache instance (`instanceSettingCache`, `userCache`, `userSettingCache`), spawned in `store/cache/cache.go:83` via `cache.New()`, created at `store/store.go:51-53`.

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — a fully-featured cron job scheduler (cron expression parser, timezone support, middleware chain with recovery/logging/timeout, graceful shutdown) with comprehensive tests across `scheduler.go`, `job.go`, `parser.go`, `middleware.go`, and four test files. It is **not imported by any production code** — only its own test files reference it. It appears built for future use but is never wired into the server.

- **`server/runner/memopayload/` Runner** — has a `NewRunner` / `RunOnce` pattern like the S3 presign runner, but the server **never instantiates or starts it** as a background worker. Only the standalone `RebuildMemoPayload` function from this package is called synchronously during individual memo create/update API calls (`server/router/api/v1/memo_service.go`). The `Runner` struct itself is dead code.
