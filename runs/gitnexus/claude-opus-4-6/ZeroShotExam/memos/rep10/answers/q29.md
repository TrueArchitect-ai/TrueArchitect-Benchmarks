**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` token to every outgoing request via the `Authorization` header, handles 401 retries by refreshing the token, and redirects on auth failure. Token state (get/set/clear/expiry) is managed in `web/src/auth-state.ts`.

**Token kinds:** Three token types are managed:
1. **JWT access tokens** — short-lived (15 min), stored in-memory and localStorage, attached as `Bearer` tokens by the interceptor, validated statelessly on the backend.
2. **Refresh tokens** — delivered via HTTP cookie (`credentials: "include"`), used to obtain new access tokens when they expire (via `AuthService.RefreshToken`), validated against the database for revocation.
3. **Personal Access Tokens (PAT)** — long-lived tokens prefixed with a distinguishing string, also sent as `Bearer` tokens, validated by hash lookup in the database.

**Backend package path:** `server/auth` — specifically `server/auth/authenticator.go`, which contains the `Authenticator` struct. It exposes `AuthenticateByAccessTokenV2` (stateless JWT validation), `AuthenticateByRefreshToken` (cookie-based, DB-checked), `AuthenticateByPAT` (hash-based DB lookup), and the unified `Authenticate`/`AuthenticateToUser` methods used by the gRPC/Connect interceptors.
