**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` access token to every outgoing request's `Authorization` header, and on a 401 (`Code.Unauthenticated`) automatically refreshes the token and retries once.

**Token kinds managed:**
1. **Access tokens** (short-lived JWTs, 15 minutes) — stored/retrieved via `getAccessToken()`/`setAccessToken()` from `web/src/auth-state.ts`, sent as `Bearer` in the `Authorization` header.
2. **Refresh tokens** — sent as an HTTP-only cookie (`credentials: "include"`); used by the interceptor's retry path to obtain a fresh access token via `AuthService.RefreshToken`.
3. **Personal Access Tokens (PAT)** — long-lived tokens for programmatic access, also sent as `Bearer` tokens and validated server-side.

**Backend package that validates them:** `server/auth` (specifically `server/auth/authenticator.go`). The `Authenticator` struct provides `AuthenticateByAccessTokenV2` (stateless JWT validation), `AuthenticateByRefreshToken` (database-backed revocation check), and `AuthenticateByPAT` (hash-based lookup + expiry check). The unified entry point `Authenticate()` (line 213) resolves a Bearer token to an `AuthResult` covering both access tokens and PATs.
