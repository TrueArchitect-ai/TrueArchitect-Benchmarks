Four memo lifecycle events dispatch webhooks, defined in `server/router/api/v1/memo_service_webhooks.go`:

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

The first three converge through the private helper `dispatchMemoRelatedWebhook` (same file, line 48), while `DispatchMemoCommentCreatedWebhook` builds its payload inline — but all four ultimately call `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload onto `asyncPostQueue`. Worker goroutines (spawned in `init()` at `internal/webhook/webhook.go:42`) drain that channel and call `Post` (`internal/webhook/webhook.go:120`), which is the single delivery function where all webhook dispatches converge for actual HTTP delivery.
