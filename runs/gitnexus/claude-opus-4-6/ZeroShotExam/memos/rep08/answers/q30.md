Four memo lifecycle events dispatch webhooks, each with its own dispatch function in `server/router/api/v1/memo_service_webhooks.go`:

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

The first three converge through the private helper `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator's webhooks and calls `webhook.PostAsync`. `DispatchMemoCommentCreatedWebhook` (line 30) builds the payload itself but also calls `webhook.PostAsync`.

All four ultimately converge on `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload into `asyncPostQueue`. Worker goroutines (spawned in `init()`, line 42) drain that channel and call `Post` (`internal/webhook/webhook.go:120`) — the single delivery function that performs the HTTP POST to the webhook endpoint.
