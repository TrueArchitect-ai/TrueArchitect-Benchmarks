When `DeleteMemo` runs, the following database tables are directly affected:

1. **`memo_relation`** — deleted explicitly in `store/memo.go:142-146` via two `DeleteMemoRelation` calls (once where memo is the source via `MemoID`, once where memo is the target via `RelatedMemoID`)
2. **`attachment`** — deleted explicitly in `store/memo.go:149-156` by iterating over attachments linked to the memo and calling `DeleteAttachment` for each
3. **`memo`** — the memo row itself is deleted in `store/memo.go:158` via `s.driver.DeleteMemo`

Additionally, at the service layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (related via `MemoRelationComment`) are recursively deleted by calling `Store.DeleteMemo` for each comment, which triggers the same cascade on `memo_relation`, `attachment`, and `memo` for those child memos.
