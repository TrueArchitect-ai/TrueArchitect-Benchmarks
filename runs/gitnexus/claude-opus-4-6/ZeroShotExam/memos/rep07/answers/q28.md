**Background workers the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (`server/runner/s3presign/runner.go:27,30`). Started by `server.go:162–171` via `startBackgroundRunners()`. Refreshes expiring S3 presigned URLs for attachments. Also runs once synchronously at startup before the ticker loop begins.
- **Webhook dispatch workers (4 goroutines)** — channel-driven (`internal/webhook/webhook.go:42–54`). Started in `init()`, consuming from a buffered channel (`asyncPostQueue`, cap 128). Triggered on-demand when `PostAsync()` enqueues a webhook payload.
- **Email send workers (2 goroutines)** — channel-driven (`internal/email/email.go:16–36`). Started in `init()`, consuming from a buffered channel (`asyncEmailQueue`, cap 128). Triggered on-demand when `SendAsync()` enqueues an email request.

**Unused scheduling infrastructure:**

The `internal/scheduler/` package is a fully-featured cron job scheduler (cron expression parsing, timezone-aware scheduling, middleware support, graceful shutdown) that is **never imported by any production code**. It has only test files exercising it. No production code calls `scheduler.New()`, registers jobs, or calls `scheduler.Start()`. The S3 presign runner — the only periodic background worker — uses a plain `time.NewTicker` loop instead.

Additionally, `server/runner/memopayload/` defines a `Runner` struct with a `RunOnce()` method for bulk-rebuilding memo payloads, but its `NewRunner()` is never called by production code and it is not started as a background worker. (The `RebuildMemoPayload` utility function from that package is used inline by the memo service at `server/router/api/v1/memo_service.go`, but the runner itself is unused.)
