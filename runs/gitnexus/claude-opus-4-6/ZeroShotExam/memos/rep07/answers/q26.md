The following database tables are affected when `DeleteMemo` runs:

1. **`memo_relation`** — explicitly deleted in `store/memo.go:142-146` via two `DeleteMemoRelation` calls (once for `MemoID`, once for `RelatedMemoID`)
2. **`attachment`** — explicitly deleted in `store/memo.go:149-156` by listing attachments for the memo and calling `DeleteAttachment` for each
3. **`memo`** — the memo row itself is deleted in `store/memo.go:158` (and at the DB driver level, e.g., `store/db/sqlite/memo.go:239`)
4. **`memo_share`** — deleted via `ON DELETE CASCADE` foreign key constraint on `memo_id` referencing `memo(id)` (`store/migration/sqlite/LATEST.sql:109`, same in postgres and mysql)
5. **`memo`** (comment rows) — the service layer at `server/router/api/v1/memo_service.go:569-577` first finds all comment relations (`MemoRelationComment`) pointing to the memo and recursively calls `Store.DeleteMemo` for each comment memo, which in turn triggers the same cascade (memo_relation, attachment, memo_share) for those comments

In summary, the affected tables are: **`memo`**, **`memo_relation`**, **`attachment`**, **`memo_share`**.
