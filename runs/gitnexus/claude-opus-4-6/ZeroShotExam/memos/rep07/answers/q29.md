The frontend auth interceptor lives in **`web/src/connect.ts`** (the `authInterceptor` constant, line 156). It is a ConnectRPC `Interceptor` that attaches a `Bearer` token to every outgoing request's `Authorization` header and handles 401 retries.

**Token kinds it manages:**
1. **Access tokens** (short-lived JWTs, ~15 min) — stored in memory and localStorage via `web/src/auth-state.ts`; attached as `Bearer <token>` on each request.
2. **Refresh tokens** — sent as an HTTP cookie (`credentials: "include"`); used to obtain new access tokens when the access token expires or a 401 is received (via `refreshAuthClient.refreshToken()`).

The interceptor does not directly handle Personal Access Tokens (PATs), but the backend accepts them through the same `Authorization: Bearer` header.

**Backend validation package:** **`server/auth`** (`server/auth/authenticator.go`). The `Authenticator` struct validates all three credential types: `AuthenticateByAccessTokenV2` for short-lived JWTs, `AuthenticateByRefreshToken` for refresh tokens, and `AuthenticateByPAT` for Personal Access Tokens.

**Summary:** `web/src/connect.ts`; access tokens (JWT) + refresh tokens (cookie); `server/auth`
