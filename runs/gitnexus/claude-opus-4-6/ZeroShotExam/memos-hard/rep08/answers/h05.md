**Explicit Go code**; reactions are removed in two ways during user deletion, both via explicit `DELETE` statements in a transaction.

**Evidence:**

1. **`deleteReactionsByCreatorTx`** (`store/db/mysql/user_delete.go:~line 97`) — deletes all reactions the user created:
   ```go
   DELETE FROM reaction WHERE creator_id = ?
   ```

2. **`deleteReactionsByContentIDsTx`** (`store/db/mysql/user_delete.go:~line 85`) — deletes all reactions on the user's memos (by content ID):
   ```go
   DELETE FROM reaction WHERE content_id IN (...)
   ```

   Both are called from `deleteUserTargetsTx` (same file, lines ~72–76), which runs inside a transaction in `DeleteUser`.

3. **No database-level CASCADE** — the `reaction` table schema in all three database backends (`store/migration/sqlite/LATEST.sql`, `store/migration/mysql/LATEST.sql`, `store/migration/postgres/LATEST.sql`) defines `creator_id` and `content_id` as plain columns with no `REFERENCES` or `ON DELETE CASCADE` constraints.

So both the user's own reactions (by `creator_id`) **and** other users' reactions on the deleted user's memos (by `content_id`) are explicitly removed in Go code within the delete-user transaction.
