The premise is incorrect — webhook delivery uses **neither NATS nor RabbitMQ**. There is no external message broker at all.

The actual mechanism is a **buffered Go channel with an in-process goroutine worker pool**, declared in `internal/webhook/webhook.go`:

- **Line 39**: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel of capacity 128 serves as the "queue."
- **Lines 42–55**: A package `init()` function spawns **4 goroutines** that range over the channel and call `Post()` to deliver each webhook via HTTP.
- **Lines 184–196**: `PostAsync()` performs a non-blocking send into the channel; if the buffer is full, the webhook is **dropped** with a warning log.

There are no external messaging dependencies (NATS, RabbitMQ, Redis, etc.) anywhere in `go.mod` or the source. The entire dispatch is in-memory, fire-and-forget, with no persistence, retries, or dead-letter handling.
