The premise of the question is incorrect. This repository (Memos) does not have a per-user API rate-limiting middleware. There is no rate-limiter registered anywhere in the server routing or middleware stack.

The server middleware setup in `server/server.go` registers only `middleware.Recover()` (line 51) and a CORS middleware via `server/cors.go`. The gRPC/Connect layer in `server/router/api/v1/v1.go` uses authorization middleware (authentication and policy checks via `server/router/api/v1/authz.go`), but no rate limiting. The `internal/scheduler/middleware.go` file contains a `Recovery` middleware and a `Chain` helper for the internal task scheduler, not for API request throttling.

The only mention of "rate limit" in the entire codebase is a comment in `internal/email/doc.go` (line 86) describing a future aspiration to "rate limit email sending to prevent abuse," but no such logic is implemented.
