**Premise correction:** There is no Redis connection in this codebase. The cache layer does not use Redis at all.

**Actual mechanism:** The cache is a custom **in-memory Go cache** built on `sync.Map`, implemented in `store/cache/cache.go`. It is configured and instantiated in `store/store.go:38-51` inside the `New()` constructor. Three separate cache instances are created — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing the same `cache.Config`.

The **TTL for user entries is 10 minutes** (`10 * time.Minute`), set as the `DefaultTTL` in `store/store.go:41`. This is the same default returned by `cache.DefaultConfig()` at `store/cache/cache.go:57-63`. The user cache is populated via `s.userCache.Set(ctx, key, user)` calls throughout `store/user.go` (e.g., lines 98, 122, 132, 143, 155, 167), which use `Set()` — which in turn delegates to `SetWithTTL` with the configured `DefaultTTL` (`store/cache/cache.go:93-94`).

Additional cache parameters: cleanup interval is 5 minutes, max items is 1000 (`store/store.go:42-43`). Eviction of expired items happens both lazily on read (`cache.go:135-136`) and proactively via a background goroutine (`cache.go:200-215`).
