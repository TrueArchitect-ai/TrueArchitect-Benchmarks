Memo visibility is enforced at many distinct sites across the server. Here are all the enforcement locations:

1. **`checkMemoReadAccess` (single-memo gate)** — `server/router/api/v1/memo_service.go` — Central per-memo check: rejects non-owners on private memos, requires auth on non-public memos, hides archived memos from non-creators. Called by `GetMemo` and `ListMemoComments`.

2. **`ListMemos` query-level filter** — `server/router/api/v1/memo_service.go` — Injects `VisibilityList` or CEL filter expressions before the DB query (e.g., unauthenticated callers only see `PUBLIC`; authenticated callers see own + `PUBLIC`/`PROTECTED`).

3. **`ListMemoComments` visibility filter** — `server/router/api/v1/memo_service_comments.go` — Checks parent memo via `checkMemoReadAccess`, then applies a `MemoFilter` on comment visibility (`PUBLIC` only for anon, `PUBLIC`/`PROTECTED` + own for authenticated).

4. **`CreateMemoComment` visibility gate** — `server/router/api/v1/memo_service_comments.go` — Blocks commenting on private memos by non-owners/non-admins.

5. **`batchConvertMemoRelations` visibility filter** — `server/router/api/v1/memo_service_converter.go` — Applies a `memoFilter` when batch-loading related memos, excluding those the viewer cannot see.

6. **`ListMemoRelations` visibility filter** — `server/router/api/v1/memo_relation_service.go` — Builds its own `memoFilter` to restrict both outgoing and incoming relation queries by visibility.

7. **`ListMemoReactions` visibility check** — `server/router/api/v1/reaction_service.go` — Inline check: non-public memos require auth; private memos restricted to creator/admin.

8. **`UpsertMemoReaction` visibility check** — `server/router/api/v1/reaction_service.go` — Blocks reactions on private memos by non-owners/non-admins.

9. **`ListMemoAttachments` visibility check** — `server/router/api/v1/memo_attachment_service.go` — Inline check mirroring the reaction pattern for listing attachments.

10. **`checkAttachmentAccess` (API attachment gate)** — `server/router/api/v1/attachment_service.go` — For attachments linked to a memo, enforces the memo's visibility before serving via the API.

11. **`checkAttachmentPermission` (file server gate)** — `server/router/fileserver/fileserver.go` — Enforces memo visibility for HTTP file downloads at `/file/attachments/`, including share-token fallback.

12. **`GetUserStats` visibility filter** — `server/router/api/v1/user_service_stats.go` — Restricts which memos count in stats by `VisibilityList` (public-only for anon, public+protected for other users).

13. **`ListAllUserStats` visibility filter** — `server/router/api/v1/user_service_stats.go` — Same pattern applied to the aggregated stats endpoint.

14. **Database-level `VisibilityList` SQL filter** — `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go` — Adds `WHERE memo.visibility IN (...)` clause when `VisibilityList` is set.

15. **Database-level `MemoFilter` sub-select on relations** — `store/db/sqlite/memo_relation.go`, `store/db/postgres/memo_relation.go`, `store/db/mysql/memo_relation.go` — Adds `memo_id IN (SELECT id FROM memo WHERE ...)` sub-selects compiled from CEL filters.

16. **RSS feeds (explore + per-user)** — `server/router/rss/rss.go` — Both `GetExploreRSS` and `GetUserRSS` set `VisibilityList` to `[Public]` only.

17. **Sitemap generation** — `server/router/frontend/frontend.go` — `getSitemapXML` queries with `VisibilityList: [Public]` only.

18. **SSE event delivery (`canReceive`)** — `server/router/api/v1/sse_hub.go` — Filters real-time push events: private memo events delivered only to creator/admin.

19. **Instance-wide anonymous gate (`CheckAccess`)** — `server/router/api/v1/authz.go` — On private instances, blocks unauthenticated access to all memo endpoints except bootstrap methods.
