The browser hits `GET /file/users/:identifier/avatar`. Here is each hop from the HTTP handler to stored data:

`RegisterRoutes` — `server/router/fileserver/fileserver.go` (line 124, registers the route)
`serveUserAvatar` — `server/router/fileserver/fileserver.go` (line 167, HTTP handler; extracts `:identifier`, reads `user.AvatarURL`, parses the data URI, returns the image blob)
`getUserByUsername` — `server/router/fileserver/fileserver.go` (line 714, builds a `FindUser{Username: &identifier}` and delegates to the store)
`Store.GetUser` — `store/user.go` (line 147, checks the in-memory `userCache`, falls through to `ListUsers`)
`Store.ListUsers` — `store/user.go` (line 135, calls `s.driver.ListUsers` on the database driver interface)
`Driver.ListUsers` — `store/driver.go` (line 47, interface method; concrete implementations in `store/db/sqlite/user.go:88`, `store/db/postgres/user.go:87`, `store/db/mysql/user.go:84` — each runs a SQL query against the `user` table)

The avatar data itself is stored inline in the `avatar_url` column as a data-URI; `serveUserAvatar` calls `parseDataURI` to decode it and streams the raw image bytes back to the browser.
