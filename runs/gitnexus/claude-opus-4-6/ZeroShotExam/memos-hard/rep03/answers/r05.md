The premise is incorrect — this project does **not** use GraphQL. The public API is defined using **Protocol Buffers (gRPC) with HTTP/JSON transcoding**, not GraphQL.

The API surface is defined in `.proto` files under `proto/api/v1/`:

- `proto/api/v1/memo_service.proto` — Memo CRUD operations
- `proto/api/v1/auth_service.proto` — Authentication
- `proto/api/v1/user_service.proto` — User management
- `proto/api/v1/attachment_service.proto` — Attachments
- `proto/api/v1/instance_service.proto` — Instance configuration
- `proto/api/v1/idp_service.proto` — Identity providers
- `proto/api/v1/shortcut_service.proto` — Shortcuts
- `proto/api/v1/ai_service.proto` — AI features (transcription)
- `proto/api/v1/common.proto` — Shared message types

These proto definitions use `google.api.http` annotations to expose REST endpoints (e.g., `GET /api/v1/memos`, `POST /api/v1/memos`). From these protos, an **OpenAPI 3.0 spec** is generated at `proto/gen/openapi.yaml`, and Go server/client code is generated into `proto/gen/api/` and `proto/gen/store/`. The HTTP routing is handled in `server/router/api/v1/`.
