The premise is incorrect — there is no Redis connection in this project. The cache layer is entirely **in-memory**, implemented as a custom Go cache in `store/cache/cache.go`.

The `Store` struct (`store/store.go:12-30`) holds three in-memory caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — all created via `cache.New(cacheConfig)` at `store/store.go:51-53`.

The `userCache` uses the shared default `cache.Config` defined at `store/store.go:40-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

So the TTL for user entries is **10 minutes**, with expired entries cleaned up every 5 minutes by a background goroutine (`store/cache/cache.go:200-215`). The cache is a `sync.Map`-backed structure with per-item expiration timestamps (`store/cache/cache.go:67-73`), not an external store like Redis.
