2. `serveUserAvatar` — `server/router/fileserver/fileserver.go` (line 168): HTTP handler; extracts `:identifier` param, calls `getUserByUsername`
3. `getUserByUsername` — `server/router/fileserver/fileserver.go` (line 715): wraps `s.Store.GetUser` with a `FindUser{Username: &identifier}` filter
4. `Store.GetUser` — `store/user.go` (line 148): checks user cache by ID, then delegates to `Store.ListUsers`
5. `Store.ListUsers` — `store/user.go` (line 136): calls `s.driver.ListUsers` on the `Driver` interface
6. `Driver.ListUsers` — `store/driver.go` (line 47): interface method implemented per DB backend
7. `DB.ListUsers` — `store/db/mysql/user.go` (line 84) / `store/db/sqlite/user.go` (line 88): builds and executes `SELECT ... FROM user WHERE username = ?`, scanning `avatar_url` from the row

The avatar data itself is stored inline in the `user` table's `avatar_url` column as a base64 data URI. Back in `serveUserAvatar` (line 196), `parseDataURI` decodes it and the raw image bytes are returned via `c.Blob()`.
