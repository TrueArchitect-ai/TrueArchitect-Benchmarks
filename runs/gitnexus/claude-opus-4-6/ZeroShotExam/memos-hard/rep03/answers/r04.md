The premise is incorrect — there is no external message broker (neither NATS nor RabbitMQ). The webhook delivery workers consume from a **plain Go buffered channel**, not a message broker.

The queue is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a package-level buffered channel with a capacity of 128 entries. In the same file's `init()` function (lines 42–55), **4 goroutines** are spawned as workers that range over the channel and call `Post()` for each payload. The `PostAsync()` function (lines 183–196) enqueues payloads into this channel with a non-blocking `select` — if the channel is full, the webhook is dropped with a warning log.

There is no external broker dependency anywhere in the codebase; the entire mechanism is in-process.
