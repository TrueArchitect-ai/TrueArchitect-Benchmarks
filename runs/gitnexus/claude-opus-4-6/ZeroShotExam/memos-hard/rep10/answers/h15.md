Every distinct server-side enforcement site for memo visibility:

1. **`checkMemoReadAccess` (central read gate)** — `server/router/api/v1/memo_service.go` (lines 39–67). Reusable function called by `GetMemo` and `ListMemoComments`.

2. **`ListMemos` query-time filtering** — `server/router/api/v1/memo_service.go` (lines 218–227). Restricts `VisibilityList`/`Filters` by auth state before the SQL query.

3. **`ListMemoComments` query-time filtering** — `server/router/api/v1/memo_service_comments.go` (lines 157–161). Filters comment memos by visibility (in addition to the `checkMemoReadAccess` call on the parent).

4. **`CreateMemoComment` visibility check** — `server/router/api/v1/memo_service_comments.go` (lines 33–43). Blocks commenting on private memos unless creator or admin.

5. **`ListMemoRelations` visibility filtering** — `server/router/api/v1/memo_relation_service.go` (lines 107–112). Applies a `MemoFilter` on related memos by visibility.

6. **`batchConvertMemoRelations` visibility filtering** — `server/router/api/v1/memo_service_converter.go` (lines 182–187). Same pattern applied when bulk-loading relations during memo conversion.

7. **`ListMemoReactions` visibility check** — `server/router/api/v1/reaction_service.go` (lines 29–41). Checks memo visibility before listing reactions.

8. **`UpsertMemoReaction` visibility check** — `server/router/api/v1/reaction_service.go` (lines 82–85). Blocks reactions on private memos for non-creator/non-admin.

9. **`ListMemoAttachments` visibility check** — `server/router/api/v1/memo_attachment_service.go` (lines 213–225). Inline visibility gate before listing a memo's attachments.

10. **`checkAttachmentAccess` (gRPC attachment service)** — `server/router/api/v1/attachment_service.go` (lines 420–455). Enforces memo visibility when accessing linked attachments via the gRPC API.

11. **`checkAttachmentPermission` (file server)** — `server/router/fileserver/fileserver.go` (lines 649–703). Separate enforcement path for direct file serving with share-token fallback.

12. **SSE `canReceive`** — `server/router/api/v1/sse_hub.go` (lines 134–144). Filters server-sent events by memo visibility per connected client.

13. **`canViewerAccessMemo` (API notifications)** — `server/router/api/v1/user_service_notifications.go` (lines 302–316). Gates notification payload construction.

14. **`canViewerAccessMemo` (email notifications)** — `server/notification/email.go` (lines 306–320). Parallel implementation gating email notification content.

15. **`ListAllUserStats` query-time filtering** — `server/router/api/v1/user_service_stats.go` (lines 77–91). Restricts stats queries by visibility.

16. **`GetUserStats` query-time filtering** — `server/router/api/v1/user_service_stats.go` (lines 217–221). Per-user stats restricted by visibility.

17. **RSS feed filtering** — `server/router/rss/rss.go` (line 90 and line 141). Both RSS endpoints restrict to `store.Public` only.

18. **Sitemap filtering** — `server/router/frontend/frontend.go` (line 150). Only public memos appear in the sitemap.
