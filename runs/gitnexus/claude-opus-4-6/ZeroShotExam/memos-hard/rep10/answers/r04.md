The premise is incorrect — there is no message broker at all. The webhook delivery system uses neither NATS nor RabbitMQ. Instead, it uses a plain **in-process Go buffered channel** as its dispatch queue.

The "queue" is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a buffered channel with a capacity of 128 payloads. Four goroutine workers are spawned in the `init()` function (`internal/webhook/webhook.go:42-55`) that drain this channel and call `Post()` to make synchronous HTTP requests for each payload. Callers enqueue work via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which performs a non-blocking send and drops the payload with a warning log if the channel is full.

There is no external message broker, no persistent queue, and no at-least-once delivery guarantee — everything is in-memory within the single process.
