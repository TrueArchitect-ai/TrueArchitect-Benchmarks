**Delivery function** — `Post` in `internal/webhook/webhook.go` (line 120). It marshals the payload to JSON, constructs an HTTP POST request, optionally signs it with HMAC-SHA256, and sends it via `safeClient`. Asynchronous callers use `PostAsync` (line 184), which enqueues onto a buffered channel consumed by 4 background goroutines that each call `Post`.

**Protection mechanism** — SSRF prevention via `safeDialContext` in `internal/webhook/webhook.go` (line 59) and `ValidateURL` in `internal/webhook/validate.go` (line 62). Two layers work together:

1. **At registration time**: `ValidateURL` (`internal/webhook/validate.go:62`) resolves the webhook URL's hostname and rejects it if any resolved IP falls within a reserved/private CIDR range (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents — listed in `reservedCIDRs` at `validate.go:14`).

2. **At dial time**: The `safeClient` HTTP client uses a custom `Transport` whose `DialContext` is `safeDialContext` (`webhook.go:59`). This re-resolves the hostname immediately before connecting and checks every resolved IP against `isReservedIP` (`validate.go:44`), blocking the connection if any address is private. This second check defeats DNS rebinding attacks where a hostname initially resolves to a public IP but later resolves to a private one.

The `AllowPrivateIPs` flag (`validate.go:41`) provides an opt-out for self-hosted deployments that legitimately need to reach local-network services.
