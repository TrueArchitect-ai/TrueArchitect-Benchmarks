The browser hits `GET /file/users/:identifier/avatar`. Here is each hop from the HTTP route to stored data:

`RegisterRoutes` — `server/router/fileserver/fileserver.go`
`serveUserAvatar` — `server/router/fileserver/fileserver.go`
`getUserByUsername` — `server/router/fileserver/fileserver.go`
`Store.GetUser` — `store/user.go`
`Store.ListUsers` — `store/user.go`
`DB.ListUsers` — `store/db/sqlite/user.go` (or `store/db/postgres/user.go`, `store/db/mysql/user.go`)

In detail:

1. **`RegisterRoutes`** — `server/router/fileserver/fileserver.go:120` — registers the Echo route `fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)` under the `/file` group.
2. **`serveUserAvatar`** — `server/router/fileserver/fileserver.go:167` — the HTTP handler. Checks anonymous access via `Profile.AllowAnonymous()`, extracts the `:identifier` path param, calls `getUserByUsername` to load the user, reads `user.AvatarURL`, parses the data URI with `parseDataURI`, and writes the image bytes back as a blob response.
3. **`getUserByUsername`** — `server/router/fileserver/fileserver.go:714` — thin wrapper that calls `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`.
4. **`Store.GetUser`** — `store/user.go:148` — checks the in-memory `userCache` first; on miss, delegates to `s.ListUsers()` and caches the result.
5. **`Store.ListUsers`** — `store/user.go:136` — delegates to `s.driver.ListUsers(ctx, find)`, the database driver interface.
6. **`DB.ListUsers`** — `store/db/sqlite/user.go:88` (or the postgres/mysql variant) — builds and executes the SQL query against the `user` table, scanning rows into `store.User` structs (including `AvatarURL`).

The avatar image data itself is stored inline in the `user` row's `avatar_url` column as a data URI. `parseDataURI` (`server/router/fileserver/fileserver.go`) decodes it into raw bytes for the HTTP response.
