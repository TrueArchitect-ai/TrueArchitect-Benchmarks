The premise is incorrect — the webhook delivery system uses **neither NATS nor RabbitMQ**. There is no external message broker at all.

Webhook dispatch uses an **in-process buffered Go channel** as its queue. The channel is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a package-level buffered channel with capacity 128. In the same file's `init()` function (`internal/webhook/webhook.go:42–55`), four goroutine workers are spawned that consume from this channel in a `for payload := range asyncPostQueue` loop, calling `Post(payload)` to make the outbound HTTP request.

Producers enqueue work via `PostAsync()` (`internal/webhook/webhook.go:184–196`), which does a non-blocking send (`select` with a `default` case that drops and logs a warning if the channel is full). The callers are in `server/router/api/v1/memo_service_webhooks.go`, where methods like `DispatchMemoCreatedWebhook`, `DispatchMemoUpdatedWebhook`, etc. call `webhook.PostAsync(payload)` for each matching user webhook.
