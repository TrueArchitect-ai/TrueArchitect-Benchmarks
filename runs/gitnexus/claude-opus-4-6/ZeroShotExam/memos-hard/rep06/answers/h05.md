**Explicit Go code** removes emoji reactions when a user is deleted — there are no database-level CASCADE rules.

The `reaction` table has no foreign key constraints at all (`store/migration/sqlite/LATEST.sql:92-99`, `mysql/LATEST.sql:91-98`, `postgres/LATEST.sql:91-98`). The cleanup is done via two raw SQL DELETEs inside `deleteUserTargetsTx()`, which runs in a transaction:

1. **`deleteReactionsByContentIDsTx`** — deletes all reactions *on* the user's memos (`DELETE FROM reaction WHERE content_id IN (...)`)
   - `store/db/sqlite/user_delete.go:380-388` (called at line 96)
   - `store/db/mysql/user_delete.go:417-425`
   - `store/db/postgres/user_delete.go:380-388`

2. **`deleteReactionsByCreatorTx`** — deletes all reactions *by* the user (`DELETE FROM reaction WHERE creator_id = ?`)
   - `store/db/sqlite/user_delete.go:400-403` (called at line 102)
   - `store/db/mysql/user_delete.go:437-439`
   - `store/db/postgres/user_delete.go:400-402`

Both steps execute before the memo and user rows are deleted, avoiding orphaned references.
