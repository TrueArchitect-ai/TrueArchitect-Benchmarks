The outbound webhook delivery executes in the `Post` function at `internal/webhook/webhook.go:120`, which serializes the payload as JSON and sends an HTTP POST via a shared `safeClient`. Asynchronous dispatch happens through `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues payloads onto a buffered channel consumed by 4 background goroutines (started in `init`, line 42).

Protection against SSRF (being pointed at internal network addresses) is implemented in two layers, both in the `internal/webhook` package:

1. **At dial time** — `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the target hostname via DNS and checks every returned IP against `isReservedIP` (`internal/webhook/validate.go:44`), which compares against a list of reserved/private CIDR blocks (`reservedCIDRs`, `internal/webhook/validate.go:14`) covering loopback, RFC-1918, link-local (including cloud IMDS 169.254.x.x), and IPv6 equivalents. This check runs inside the HTTP transport itself, defeating DNS rebinding.

2. **At URL registration time** — `ValidateURL` (`internal/webhook/validate.go:62`) performs an up-front DNS resolution and reserved-IP check before a webhook URL is ever persisted, also enforcing that only `http`/`https` schemes are accepted.

**Answer:** delivery function — `Post` in `internal/webhook/webhook.go`; protection mechanism — `safeDialContext` + `isReservedIP` in `internal/webhook/webhook.go` and CIDR blocklist + `ValidateURL` in `internal/webhook/validate.go`.
