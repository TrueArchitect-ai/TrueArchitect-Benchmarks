The premise is incorrect — there is no Redis connection in this project. The cache layer is an **in-memory Go cache**, not Redis-backed.

The cache is implemented in `store/cache/cache.go` as a `sync.Map`-based in-memory store with TTL expiration and periodic cleanup. It is configured in `store/store.go:40-48`, where a `cache.Config` is created with these defaults:

- **DefaultTTL**: `10 * time.Minute`
- **CleanupInterval**: `5 * time.Minute`
- **MaxItems**: `1000`

The user cache (`userCache`) is instantiated at `store/store.go:52` using this same shared config, so user entries have a **10-minute TTL**. There is no per-cache TTL override for users — all three caches (`instanceSettingCache`, `userCache`, `userSettingCache`) share the identical `cacheConfig`. Individual entries can use a custom TTL via `SetWithTTL()` (`store/cache/cache.go:98`), but no call site for user entries uses that — they all call `.Set()` (e.g., `store/user.go:98,122,132,143,167`), which applies the default 10-minute TTL.
