Here is the request trace from the browser to stored data, hop by hop:

```
RegisterRoutes (GET /file/users/:identifier/avatar) — server/router/fileserver/fileserver.go
serveUserAvatar — server/router/fileserver/fileserver.go
getUserByUsername — server/router/fileserver/fileserver.go
Store.GetUser — store/user.go
Store.ListUsers — store/user.go
Driver.ListUsers — store/driver.go (interface), store/db/sqlite/user.go (or postgres/mysql implementations)
```

**Detail:**

1. `RegisterRoutes` registers the route `GET /file/users/:identifier/avatar` bound to `serveUserAvatar` — `server/router/fileserver/fileserver.go:124`
2. `serveUserAvatar` extracts the `:identifier` path param and calls `getUserByUsername` — `server/router/fileserver/fileserver.go:167`
3. `getUserByUsername` calls `s.Store.GetUser` with a `FindUser{Username: &identifier}` — `server/router/fileserver/fileserver.go:716`
4. `Store.GetUser` checks the in-memory `userCache`, then delegates to `Store.ListUsers` — `store/user.go:148`
5. `Store.ListUsers` calls `s.driver.ListUsers` (the `Driver` interface) — `store/user.go:136`
6. `DB.ListUsers` (concrete driver, e.g. SQLite) builds and executes a `SELECT … FROM user WHERE username = ?` query against the database — `store/db/sqlite/user.go:88` (also `store/db/postgres/user.go:87`, `store/db/mysql/user.go:84`)

The avatar bytes themselves are stored inline in the `user` row as the `AvatarURL` column (a base64 data URI). Back in `serveUserAvatar`, the `user.AvatarURL` field is decoded via `parseDataURI` (line 196) and the raw image bytes are written to the HTTP response.
