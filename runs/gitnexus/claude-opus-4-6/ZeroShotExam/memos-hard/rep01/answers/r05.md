The premise is incorrect — this project does not use GraphQL. The public API is defined using **Protocol Buffers (protobuf)** with **gRPC** and **Connect** (an HTTP-compatible gRPC protocol).

The API schema is defined in `.proto` files under `proto/api/v1/`:

- `proto/api/v1/memo_service.proto` — Memo CRUD operations
- `proto/api/v1/auth_service.proto` — Authentication
- `proto/api/v1/user_service.proto` — User management
- `proto/api/v1/attachment_service.proto` — Attachments
- `proto/api/v1/instance_service.proto` — Instance settings
- `proto/api/v1/idp_service.proto` — Identity providers
- `proto/api/v1/ai_service.proto` — AI features
- `proto/api/v1/shortcut_service.proto` — Shortcuts
- `proto/api/v1/common.proto` — Shared types

These proto definitions generate both gRPC stubs (Go, in `proto/gen/api/v1/`) and TypeScript clients (in `web/src/types/proto/api/v1/`). The server exposes these services via **Connect RPC** (`connectrpc.com/connect`), as seen in `server/router/api/v1/connect_handler.go`, which wraps the gRPC service implementations to support both native gRPC and HTTP+JSON (Connect protocol) on REST-style paths like `/api/v1/memos`.
