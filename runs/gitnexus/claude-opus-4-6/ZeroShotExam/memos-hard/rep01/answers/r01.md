The premise is incorrect — there is no Redis in this repository. The cache layer uses a **custom in-process, in-memory cache** built on Go's `sync.Map`, not Redis.

**Cache implementation:** `store/cache/cache.go` defines a generic in-memory cache with per-item TTL expiration, periodic cleanup, and LRU-like eviction.

**Configuration:** `store/store.go` (lines 38–53) creates three cache instances — `userCache`, `userSettingCache`, and `instanceSettingCache` — all sharing the same hardcoded config:

- **DefaultTTL: 10 minutes**
- CleanupInterval: 5 minutes
- MaxItems: 1000

**User entry TTL is 10 minutes.** There is no per-user TTL override; all writes go through `Set()` which uses the default TTL. User entries are cached by numeric user ID (`store/user.go:88–89`), written on create/update/list/get-miss, and explicitly invalidated on delete (`store/user_delete.go:39–47`).

There is no Redis dependency in `go.mod`, no Redis client library, no external cache service of any kind. The entire cache layer is in-process memory that does not survive a restart.
