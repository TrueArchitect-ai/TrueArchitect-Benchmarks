Delivery function — `Post` at `internal/webhook/webhook.go:120`; it serializes the payload as JSON, signs it with HMAC-SHA256 if a secret is configured, and sends the HTTP POST via `safeClient`. Asynchronous dispatch goes through `PostAsync` (same file, line 184), which enqueues onto a buffered channel consumed by 4 goroutine workers that each call `Post`.

Protection mechanism — `safeDialContext` at `internal/webhook/webhook.go:58` and `isReservedIP`/`ValidateURL` at `internal/webhook/validate.go`. Two layers defend against SSRF:

1. **At registration time**: `ValidateURL` (`internal/webhook/validate.go:62`) resolves the hostname and rejects any URL whose IPs fall within reserved/private CIDR ranges (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents — defined in `reservedCIDRs` at line 14).
2. **At dial time**: The `safeClient` HTTP client uses a custom `Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:58`). This resolves the hostname again and checks every resolved IP against the same `isReservedIP` function (`internal/webhook/validate.go:44`), blocking connections to private/reserved addresses. This second check defeats DNS rebinding attacks where the hostname resolves to a public IP at validation time but a private IP at request time.

The protection can be toggled off via `AllowPrivateIPs` (`internal/webhook/validate.go:41`) for self-hosted deployments that intentionally target local-network services.
