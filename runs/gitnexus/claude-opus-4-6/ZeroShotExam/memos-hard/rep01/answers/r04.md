**Premise correction:** The webhook delivery system uses **neither NATS nor RabbitMQ**. There is no external message broker at all.

**Actual mechanism:** Webhook delivery uses a **plain Go buffered channel** as an in-process async queue. The queue is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in an `init()` function at `internal/webhook/webhook.go:42-55` that consume from this channel and call `Post()` to deliver each webhook via HTTP. Callers enqueue work by calling `PostAsync()` (`internal/webhook/webhook.go:184-196`), which performs a non-blocking send on the channel (dropping the payload with a warning if the buffer is full).

The dispatch call sites are in `server/router/api/v1/memo_service_webhooks.go`, where methods like `DispatchMemoCreatedWebhook` look up the user's configured webhook URLs from the store and call `webhook.PostAsync(payload)` for each one. There is no external broker dependency anywhere in the webhook pipeline.
