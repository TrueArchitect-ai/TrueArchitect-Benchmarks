The premise of the question is incorrect. This repository does **not** have per-user API rate-limiting middleware. No such middleware is registered anywhere in the codebase.

The HTTP server (`server/server.go`) registers only `middleware.Recover()` and a CORS middleware. The Connect RPC layer (`server/router/api/v1/connect_interceptors.go`) uses four interceptors — `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` — none of which perform rate limiting. No file in the codebase imports `golang.org/x/time/rate`, and HTTP 429 is never returned.

The closest things to "limits" are:

- **Concurrency semaphores** for image/thumbnail processing (not per-user rate limits): a weighted semaphore of 3 for thumbnails and 2 for image processing in `server/router/api/v1/v1.go:39-41`, and a similar `maxConcurrentThumbnails = 3` semaphore in `server/router/fileserver/fileserver.go:45-46`.
- **Request body size cap** of 256 MiB (`maxAPIRequestBytes` at `server/router/api/v1/v1.go:20`), applied via `http.MaxBytesHandler`.
