The premise is incorrect — there is no Redis connection in this codebase. The cache layer is entirely **in-memory**, implemented in pure Go with no external backing store.

**Actual cache mechanism:**

The cache is a custom in-memory implementation at `store/cache/cache.go`, built on Go's `sync.Map` with TTL-based expiration and a background cleanup goroutine. It is configured in `store/store.go:38-45`, where the `Store` constructor creates three cache instances (`userCache`, `instanceSettingCache`, `userSettingCache`) all sharing the same `cache.Config`.

**TTL for user entries:**

The `userCache` uses the default `cache.Config` defined at `store/store.go:40-45`:

- **DefaultTTL: 10 minutes** (`10 * time.Minute`)
- CleanupInterval: 5 minutes
- MaxItems: 1000

This same default is also codified in `store/cache/cache.go:57-64` (`DefaultConfig()`). There is no per-entry TTL override for users — all three caches (users, user settings, instance settings) share the identical 10-minute TTL.

Separately, the RSS feed layer (`server/router/rss/rss.go:24-27`) has its own unrelated in-memory `map[string]*cacheEntry` cache with a 1-hour TTL (`defaultCacheDuration`), but this caches rendered RSS XML, not user records.
