**Delivery function** — `Post` in `internal/webhook/webhook.go:120`. It serializes the payload to JSON, builds an HTTP POST request (optionally HMAC-signed), and sends it via `safeClient.Do()`. An async variant `PostAsync` (`internal/webhook/webhook.go:184`) enqueues payloads onto a buffered channel consumed by 4 goroutine workers that each call `Post`.

**Protection mechanism** — Two-layer SSRF defense, both in `internal/webhook/validate.go`:

1. **Registration-time validation**: `ValidateURL` (`internal/webhook/validate.go:62`) resolves the webhook hostname and checks every returned IP against `isReservedIP` (`validate.go:44`), which matches against a hardcoded list of reserved CIDRs (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents) parsed at startup (`validate.go:14–36`). This rejects webhook URLs pointing at internal addresses before they are ever stored.

2. **Dial-time validation**: `safeDialContext` (`internal/webhook/webhook.go:59`) is wired into the shared `safeClient`'s transport (`webhook.go:35`). It re-resolves the hostname at connection time and calls the same `isReservedIP` check on every resolved IP, blocking the connection if any falls in a reserved range. This defeats DNS rebinding attacks where a hostname resolves to a public IP at registration but to a private IP at delivery time.

An escape hatch exists: the package-level `AllowPrivateIPs` variable (`validate.go:41`) disables both checks for self-hosted deployments that need to target local-network services.

**Answer:** delivery function — `Post`, `internal/webhook/webhook.go`; protection mechanism — `safeDialContext` + `isReservedIP`/`ValidateURL`, `internal/webhook/validate.go`
