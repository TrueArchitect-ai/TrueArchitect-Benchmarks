```
RegisterRoutes — server/router/fileserver/fileserver.go
serveUserAvatar — server/router/fileserver/fileserver.go
getUserByUsername — server/router/fileserver/fileserver.go

```

**Details:** The browser hits `GET /file/users/:identifier/avatar`. `RegisterRoutes` (line 120) maps that path to `serveUserAvatar` (line 167), which extracts the `:identifier` param and calls `getUserByUsername` (line 714). That one-liner delegates to `Store.GetUser` (line 147, `store/user.go`), which first checks an in-memory user cache, then falls through to `Store.ListUsers` (line 136, `store/user.go`). `ListUsers` calls `s.driver.ListUsers` — the `Driver` interface (line 47, `store/driver.go`) — dispatching to the concrete DB implementation (SQLite, MySQL, or Postgres). The returned `User.AvatarURL` field (`store/user.go`) contains a data URI; `serveUserAvatar` parses it with `parseDataURI` and writes the raw image bytes back to the response.
