The premise is incorrect — there is no message broker at all. The webhook delivery system uses neither NATS nor RabbitMQ.

Webhook delivery is built on a **plain Go buffered channel** (`asyncPostQueue = make(chan *WebhookRequestPayload, 128)`) declared at `internal/webhook/webhook.go:39`. Four goroutine workers are started in an `init()` function at `internal/webhook/webhook.go:42-55`, each consuming payloads from this channel and calling `Post()` to make synchronous HTTP POST requests to the configured webhook URLs.

The dispatch entry point is `PostAsync()` (`internal/webhook/webhook.go:183-196`), which performs a non-blocking send into the channel (dropping the payload with a warning log if the 128-slot buffer is full). Callers like `DispatchMemoCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go` invoke `webhook.PostAsync(payload)` directly — there is no external message broker, queue service, or pub/sub system involved.
