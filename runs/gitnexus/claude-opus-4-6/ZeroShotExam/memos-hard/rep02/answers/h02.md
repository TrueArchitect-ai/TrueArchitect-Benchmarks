**Delivery function — `Post`; `internal/webhook/webhook.go`** (line 120). It JSON-marshals a `WebhookRequestPayload`, builds an HTTP POST request, and sends it via `safeClient` (line 152). Asynchronous callers use `PostAsync` (line 184), which enqueues the payload onto a buffered channel consumed by 4 goroutine workers that each call `Post`.

**Protection mechanism — `safeDialContext` + `isReservedIP` + `ValidateURL`; `internal/webhook/webhook.go` and `internal/webhook/validate.go`.**

Two layers of SSRF protection prevent webhooks from targeting internal network addresses:

1. **Registration-time validation** — `ValidateURL` (`internal/webhook/validate.go:62`) resolves the hostname and checks every resulting IP against `isReservedIP` (`validate.go:44`), which tests against a list of reserved CIDRs (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents) parsed at startup (`validate.go:14–36`). This blocks obviously-private URLs before they're even saved.

2. **Delivery-time enforcement** — `safeDialContext` (`internal/webhook/webhook.go:59`) is wired into the `safeClient`'s transport as a custom `DialContext`. It re-resolves the hostname at connection time and rejects any IP in a reserved range via the same `isReservedIP` check. This defeats DNS rebinding attacks where a hostname resolves to a public IP at registration but a private IP at delivery time.

Both checks can be bypassed for self-hosted deployments by setting `AllowPrivateIPs = true` (`validate.go:41`).
