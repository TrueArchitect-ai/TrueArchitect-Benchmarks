`GET /file/users/:identifier/avatar` — the browser hits this route, which is served by the following chain:

1. `RegisterRoutes` — `server/router/fileserver/fileserver.go` (registers the route on the Echo group, binding it to `serveUserAvatar`)
2. `serveUserAvatar` — `server/router/fileserver/fileserver.go` (HTTP handler; extracts `:identifier` param, calls `getUserByUsername`, reads `user.AvatarURL`, parses the data URI, returns the image blob)
3. `getUserByUsername` — `server/router/fileserver/fileserver.go` (thin wrapper; builds a `FindUser{Username: &identifier}` and calls `Store.GetUser`)
4. `Store.GetUser` — `store/user.go` (checks the in-memory `userCache`; on miss delegates to `Store.ListUsers`)
5. `Store.ListUsers` — `store/user.go` (delegates to `s.driver.ListUsers`, the DB driver interface)
6. `Driver.ListUsers` — `store/driver.go` (interface at line 47; implemented per database engine)
7. `DB.ListUsers` — `store/db/sqlite/user.go` (or `store/db/postgres/user.go`, or `store/db/mysql/user.go`) — executes the SQL query against the `user` table and scans rows including `avatar_url`
