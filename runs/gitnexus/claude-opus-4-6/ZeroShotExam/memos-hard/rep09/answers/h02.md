**Delivery function** — `Post` in `internal/webhook/webhook.go` (line 120). It marshals the payload to JSON, constructs an HTTP POST request, optionally signs it with HMAC-SHA256, and sends it via the `safeClient`. Asynchronous callers use `PostAsync` (line 184), which enqueues onto a buffered channel consumed by background goroutines that ultimately call `Post`.

**Protection mechanism** — SSRF protection via `safeDialContext` in `internal/webhook/webhook.go` (line 59) and `ValidateURL` / `isReservedIP` in `internal/webhook/validate.go` (line 44).

Two layers prevent webhooks from reaching internal network addresses:

1. **At dial time** (`safeDialContext`, `internal/webhook/webhook.go:59`): The custom `DialContext` on `safeClient`'s transport resolves the target hostname via DNS, then checks every resolved IP against `isReservedIP`. This blocks connections to loopback, RFC-1918 private, link-local (including cloud IMDS 169.254.x.x), and IPv6 equivalents — and defeats DNS rebinding because the check happens after resolution, right before dialing.

2. **At registration time** (`ValidateURL`, `internal/webhook/validate.go:62`): When a webhook URL is created/updated, `ValidateURL` parses the URL, enforces `http`/`https` scheme, resolves the hostname, and rejects any address in reserved CIDR ranges via the same `isReservedIP` check.

The reserved CIDR list is defined in `internal/webhook/validate.go:14–23` and parsed once at init. An escape hatch (`AllowPrivateIPs`, `internal/webhook/validate.go:41`) exists for self-hosted deployments that need to target local-network services.
