The premise is incorrect: there is no Redis connection in this codebase. The cache layer is an **in-memory Go cache**, not Redis-backed.

**Cache implementation:** `store/cache/cache.go` defines a thread-safe in-memory cache using `sync.Map` with TTL-based expiration and a background cleanup goroutine.

**Configuration:** The cache is configured in `store/store.go:39-45` when the `Store` is created via `New()`. The default `cache.Config` is:

- **DefaultTTL:** 10 minutes
- **CleanupInterval:** 5 minutes
- **MaxItems:** 1000

**User entries specifically:** The user cache is one of three cache instances created in `store/store.go:52`:

```go
userCache: cache.New(cacheConfig),
```

It uses the same shared `cacheConfig`, so user entries get the same **10-minute TTL** as all other cached data (instance settings, user settings). There is no per-cache TTL override for users.

The only other caching mechanism in the project is the RSS feed cache in `server/router/rss/rss.go:24-27`, which is a separate in-memory `map[string]*cacheEntry` with a **1-hour** TTL (`defaultCacheDuration = 1 * time.Hour`) and a max of 50 entries — but that caches rendered RSS XML, not user objects.
