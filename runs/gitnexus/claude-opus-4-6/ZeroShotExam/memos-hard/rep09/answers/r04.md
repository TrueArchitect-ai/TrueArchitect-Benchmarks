**Premise correction:** The webhook delivery workers consume from neither NATS nor RabbitMQ. There is no external message broker in this codebase.

**Actual mechanism:** Webhook delivery uses an **in-process buffered Go channel** as its queue. The channel `asyncPostQueue` is declared at `internal/webhook/webhook.go:39` as:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in an `init()` function (`internal/webhook/webhook.go:42-55`) that range over this channel, calling `Post()` for each payload. Callers enqueue work via `PostAsync()` (`internal/webhook/webhook.go:183-196`), which does a non-blocking send — if the 128-slot buffer is full, the webhook is dropped with a warning log. The dispatch functions in `server/router/api/v1/memo_service_webhooks.go` (e.g., `DispatchMemoCreatedWebhook`, line 15) call `webhook.PostAsync(payload)` to enqueue deliveries.

There is no external broker dependency anywhere in the project.
