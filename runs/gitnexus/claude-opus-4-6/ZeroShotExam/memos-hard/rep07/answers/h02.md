The outbound webhook delivery executes in the `Post` function, which serializes the payload as JSON, constructs an HTTP POST request, optionally signs it with HMAC-SHA256, and sends it via a shared `safeClient` — `internal/webhook/webhook.go`. Asynchronous dispatch uses `PostAsync` (same file), which enqueues payloads onto a buffered channel consumed by 4 background goroutines that each call `Post`.

SSRF protection is implemented at two layers in `internal/webhook/validate.go`:

1. **At dial time** (`safeDialContext` in `internal/webhook/webhook.go:59-77`): The custom `DialContext` on the HTTP transport resolves the target hostname and checks every returned IP against `isReservedIP` before opening a connection. This also defeats DNS-rebinding attacks because the check happens after resolution, right before dialing.

2. **At URL registration time** (`ValidateURL` in `internal/webhook/validate.go:62-83`): When a webhook URL is created or updated, the URL is resolved and checked against the same reserved IP ranges.

Both layers use `isReservedIP` (`internal/webhook/validate.go:44-54`), which checks the IP against a list of reserved CIDRs covering IPv4 loopback, RFC-1918 private ranges, link-local (including cloud IMDS 169.254.x.x), IPv6 loopback, unique-local, and link-local (`reservedCIDRs` at `validate.go:14-23`).

**Answer:** delivery function — `Post` in `internal/webhook/webhook.go`; protection mechanism — `safeDialContext` (dial-time IP check) in `internal/webhook/webhook.go` + `ValidateURL` / `isReservedIP` (reserved CIDR blocklist) in `internal/webhook/validate.go`.
