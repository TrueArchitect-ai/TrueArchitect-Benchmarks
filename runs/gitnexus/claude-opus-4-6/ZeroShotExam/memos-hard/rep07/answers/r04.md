The premise is incorrect — the webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain Go buffered channel** used as an in-process async queue. It is declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the package's `init()` function (`internal/webhook/webhook.go:42–55`) that consume from this channel:

```go
func init() {
    for range 4 {
        go func() {
            for payload := range asyncPostQueue {
                if err := Post(payload); err != nil { ... }
            }
        }()
    }
}
```

Payloads are enqueued via `PostAsync()` (`internal/webhook/webhook.go:184–196`), which performs a non-blocking send on the channel and drops the payload with a warning log if the 128-slot buffer is full. The workers then call `Post()` to make the outbound HTTP request synchronously. The entire dispatch pipeline is in-process with no external broker dependency.
