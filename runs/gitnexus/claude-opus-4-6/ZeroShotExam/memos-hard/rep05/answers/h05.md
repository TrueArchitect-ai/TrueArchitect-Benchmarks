**By explicit Go code**; reactions are removed in two ways during user deletion:

1. **Reactions on the user's memos** are deleted via `deleteReactionsByContentIDsTx()` — removes all reactions (by any user) whose `content_id` matches the deleted user's memo content IDs.
   - `store/db/sqlite/user_delete.go:96,380–387`
   - `store/db/postgres/user_delete.go:383`
   - `store/db/mysql/user_delete.go:420`

2. **Reactions created by the user** (on other people's memos) are deleted via `deleteReactionsByCreatorTx()` — removes all reactions where `creator_id` matches the deleted user.
   - `store/db/sqlite/user_delete.go:102,400–403`
   - `store/db/postgres/user_delete.go:401`
   - `store/db/mysql/user_delete.go:438`

Both are called inside `deleteUserTargetsTx()` (`store/db/sqlite/user_delete.go:92–104`) as part of the transactional user deletion flow.

The `reaction` table itself has **no foreign key on `creator_id`** — the schema only has a `UNIQUE(creator_id, content_id, reaction_type)` constraint and no `ON DELETE CASCADE` referencing the user table (`store/migration/sqlite/LATEST.sql:92–98`). So removal is entirely handled by explicit Go code, not a database-level rule.
