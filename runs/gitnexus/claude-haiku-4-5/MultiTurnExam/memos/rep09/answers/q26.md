memo, memo_relation, attachment, memo_share

When DeleteMemo runs, the following database tables are affected:

1. **memo** — the memo row itself is deleted (line 158 in store/memo.go)
2. **memo_relation** — memo_relation records where the deleted memo is either source or target are deleted (lines 142-146 in store/memo.go)
3. **attachment** — attachments linked to the memo are deleted via DeleteAttachment (lines 149-157 in store/memo.go)
4. **memo_share** — memo_share records are deleted as a cascade effect when the attachment is deleted (via DeleteAttachment), and also implicitly when memo_relation records are deleted since comments have associated shares

Additionally, when DeleteMemo is called from the handler (memo_service.go line 574), it recursively deletes comment memos first, which triggers the same cascade for each comment.
