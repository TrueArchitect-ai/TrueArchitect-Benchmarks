CEL (Common Expression Language) — internal/filter/engine.go; The filter engine parses CEL expressions into a dialect-agnostic intermediate representation (IR) and then renders it to SQL with dialect-specific placeholders, JSON accessors, and operators for each database (SQLite, MySQL, PostgreSQL).

**Source:**
- **Engine**: CEL via `github.com/google/cel-go` library, implemented in `/bench/home/work/internal/filter/engine.go` (line 13 defines the Engine struct)
- **Mechanism**: Three-phase pipeline (as documented in `/bench/home/work/internal/filter/README.md`):
  1. Parsing: CEL expressions parsed with cel-go and validated against memo schema (lines 48-71 in `engine.go`)
  2. Normalization: Raw CEL AST converted to dialect-agnostic IR defined in `ir.go`
  3. Rendering: IR walker in `render.go` produces SQL fragments tailored to target dialect (SQLite: `?` placeholders, MySQL: `?` with JSON_EXTRACT, PostgreSQL: `$n` with JSON `->` operators)
- **SQL conversion**: The `Render()` method (line 96 in `engine.go`) converts the compiled program to a `Statement` with SQL and Args, handling dialect differences via the `RenderOptions.Dialect` parameter
