**Premise correction:** The question assumes webhook delivery workers consume from either NATS or RabbitMQ, but neither message broker is used.

**Actual mechanism:** Webhook delivery uses a simple bounded Go channel queue. The queue is declared as a module-level variable in `internal/webhook/webhook.go:39`:

```go
var asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in `init()` (lines 42-54) at package initialization time. Each worker listens on this channel and processes incoming webhook payloads sequentially, calling `Post()` for each payload. If the queue fills beyond 128 items, new webhook requests are dropped with a warning log (line 192-193).

This is the same pattern used for async email sending: a simple buffered channel with worker goroutines, no external message broker.
