**Premise correction:** The repository does not use NATS or RabbitMQ for webhook delivery. There is no external message broker.

**Actual mechanism:** Webhook delivery workers consume from an in-memory Go channel (`asyncPostQueue`), declared at `internal/webhook/webhook.go:39` as:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The queue is a buffered channel with capacity 128. Four worker goroutines are spawned in the `init()` function (lines 42-55) at package initialization time, each consuming from this channel and calling `Post()` to deliver webhooks. When a webhook is dispatched via `PostAsync()` (line 184-196), the payload is sent to this channel. If the queue is full, the dispatch is dropped with a warning log message.

This is a simple in-process asynchronous delivery system, not a distributed message broker architecture.
