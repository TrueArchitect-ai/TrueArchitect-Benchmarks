**Premise correction:** There is no external message broker (NATS or RabbitMQ) used for webhook delivery. 

**Actual mechanism:** Webhook delivery uses an in-memory Go channel queue:
- **Queue implementation:** `asyncPostQueue` — a buffered Go channel with capacity of 128 — `internal/webhook/webhook.go:39`
- **Workers:** 4 goroutines spawned in the `init()` function — `internal/webhook/webhook.go:42-54` that consume from the `asyncPostQueue` channel and call `Post()` to deliver each webhook payload
- **Enqueue method:** `PostAsync()` function enqueues payloads to the channel — `internal/webhook/webhook.go:184-196`

This is not a persistent distributed queue system. It's an in-memory channel-based queue that loses any unprocessed webhooks on server shutdown. No external message broker infrastructure is configured.
