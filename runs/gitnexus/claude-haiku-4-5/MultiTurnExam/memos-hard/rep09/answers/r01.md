**Premise correction:** There is no Redis connection configured in this codebase. The cache layer is NOT Redis-backed.

**Actual mechanism:** The cache layer uses an in-memory cache implemented in `store/cache/cache.go:66-90`. User entries are cached using this in-memory implementation with the following configuration:

- **Cache type:** Thread-safe in-memory cache with TTL and memory management (`store/cache/cache.go`)
- **Configuration location:** `store/store.go:40-45` in the `New()` function
- **TTL for user entries:** **10 minutes** (`store/store.go:41`: `DefaultTTL: 10 * time.Minute`)
- **Cleanup interval:** 5 minutes
- **Max items:** 1000

The cache is implemented using Go's `sync.Map` for thread-safe operations and tracks expiration times per item, cleaning up expired entries periodically. All three cache types (instance settings, users, and user settings) use the same 10-minute default TTL.
