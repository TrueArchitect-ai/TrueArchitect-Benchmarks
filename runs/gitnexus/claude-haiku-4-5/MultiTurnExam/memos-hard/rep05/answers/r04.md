**Premise correction**: There is no external message broker (NATS or RabbitMQ) used for webhook delivery workers. No queue is declared in any external system.

**Actual mechanism**: Webhook delivery uses an in-memory Go channel queue:
- Queue implementation: internal/webhook/webhook.go:39 — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`
- Worker pool: internal/webhook/webhook.go:42-54 — 4 goroutine workers initialized at package load time via `init()` function
- Workers consume from the channel: internal/webhook/webhook.go:45 — `for payload := range asyncPostQueue`
- Delivery execution: internal/webhook/webhook.go:46 — each worker calls `Post(payload)` synchronously

The queue is not persisted, not backed by a message broker, and exists only during server runtime. If the server crashes, unprocessed webhooks in the queue are lost.
