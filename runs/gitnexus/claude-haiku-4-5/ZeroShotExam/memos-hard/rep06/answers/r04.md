r04. This question appears to contain a false premise. The webhook delivery in this codebase does **not** consume from either NATS or RabbitMQ.

**Actual mechanism:** The webhook delivery system uses an in-memory Go channel-based queue for asynchronous delivery. Specifically in `internal/webhook/webhook.go:39-55`:

- `asyncPostQueue` is a buffered Go channel with capacity 128 (`make(chan *WebhookRequestPayload, 128)`)
- During `init()`, 4 worker goroutines are spawned that consume from this channel and dispatch webhook requests via `Post()`
- `PostAsync()` enqueues webhook payloads to this channel for bounded asynchronous dispatch

This is a lightweight, in-process solution rather than an external message broker system. The queue is declared as a package-level variable in **internal/webhook/webhook.go:39**.
