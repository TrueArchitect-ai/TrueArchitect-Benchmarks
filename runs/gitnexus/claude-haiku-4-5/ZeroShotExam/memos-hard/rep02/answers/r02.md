**Premise correction:** Per-user API rate-limiting middleware does not exist in this codebase.

The repository has no registered rate-limiting middleware. The server initialization in `server/server.go:51-52` registers only:
- `middleware.Recover()` (panic recovery)
- `newCORSMiddleware(profile)` (CORS handling defined in `server/cors.go`)

The only request-limiting mechanisms are **resource-based concurrency controls** using semaphores for expensive operations:
- `thumbnailSemaphore`: 3 concurrent thumbnail generations (`server/router/api/v1/v1.go:59`)
- `imageProcessingSemaphore`: 2 concurrent image processing operations (`server/router/api/v1/v1.go:60`)

These are not per-user rate limits—they are global concurrency limits to prevent resource exhaustion.
