**Premise correction:** The question presupposes webhook delivery workers consume from either NATS or RabbitMQ, but this is incorrect.

**Actual mechanism:** The webhook delivery system uses neither NATS nor RabbitMQ. Instead, it uses an **in-memory unbuffered Go channel** (`asyncPostQueue`) declared at package initialization in **`internal/webhook/webhook.go:39`**.

The queue is a buffered channel with capacity 128:
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers consume from this queue in the `init()` function (lines 42–55), each reading payloads and dispatching them via the `Post()` function. When the queue fills, new webhook dispatch requests are dropped with a warning rather than blocked.
