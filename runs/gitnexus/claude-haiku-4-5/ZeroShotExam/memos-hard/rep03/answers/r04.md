**Answer:** The premise assumes an external message broker, but the actual mechanism is **in-process queuing**.

The webhook delivery workers do not consume from NATS or RabbitMQ. Instead, webhooks are delivered asynchronously using an **in-memory channel queue** declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The queue is initialized with a buffer size of 128 items and is consumed by 4 worker goroutines spawned in the `init()` function (`internal/webhook/webhook.go:42-55`). When a webhook needs to be dispatched asynchronously, the `PostAsync()` function (`internal/webhook/webhook.go:183-196`) sends the payload to this channel for the workers to consume.
