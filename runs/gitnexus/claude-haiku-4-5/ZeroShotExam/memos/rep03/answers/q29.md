**Interceptor path:** `web/src/connect.ts:156` (the `authInterceptor` constant)

**Token kinds:** The frontend manages three types of tokens:
1. **Access Token (JWT)** - Short-lived (15 minutes), validated stateless via JWT signature, contains user role/status/username claims
2. **Refresh Token (JWT)** - Long-lived (30 days), validated against database for revocation, stored as HTTP-only cookie
3. **Personal Access Token (PAT)** - Long-lived programmatic tokens with prefix `memos_pat_`, validated via SHA-256 hash lookup

**Backend package path:** `server/auth` (located at `server/auth/authenticator.go` and `server/auth/token.go`)

The auth interceptor (lines 156-178) handles token acquisition via `getRequestToken()`, sets the `Authorization: Bearer {token}` header, and implements retry logic on 401 responses to refresh expired access tokens via `refreshAccessToken()`. The backend `server/auth` package provides the `Authenticator` struct which validates tokens: `AuthenticateByAccessTokenV2()` for stateless JWT validation, `AuthenticateByRefreshToken()` for database-backed refresh tokens, and `AuthenticateByPAT()` for personal access tokens.
