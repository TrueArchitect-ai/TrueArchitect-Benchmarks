**Frontend auth interceptor:** `web/src/connect.ts` (lines 156-178, defined as `authInterceptor`)

**Token kinds managed:**
- Access tokens (short-lived, 15 minutes) — Bearer tokens sent in `Authorization` header
- Refresh tokens (long-lived, 30 days) — stored as HTTP-only cookie (`memos_refresh`), used to obtain new access tokens
- Personal Access Tokens (PAT) — long-lived tokens for programmatic access

**Backend validation package:** `server/auth/` (package `auth`)
- Core validation: `ParseAccessTokenV2()` and `ParseRefreshToken()` in `server/auth/token.go` (lines 219-249)
- Stateless JWT validation using HMACSHA256 with secret key
- Access tokens validated by signature only; refresh tokens also checked against database for revocation
- Backend interceptor uses `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` (lines 205-231) which delegates to `Authenticator` in `server/auth/authenticator.go`
