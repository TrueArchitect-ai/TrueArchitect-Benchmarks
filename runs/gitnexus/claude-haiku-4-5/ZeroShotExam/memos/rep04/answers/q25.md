**CEL-Go** (`github.com/google/cel-go/cel`); lives in `internal/filter/engine.go:Engine.Compile` → `internal/filter/parser.go:buildCondition` handles AST-to-IR conversion; the filter becomes SQL via `internal/filter/render.go:renderer.Render` which walks the condition tree and generates dialect-specific SQL (SQLite/Postgres/MySQL) with per-dialect template substitutions (timestamp extraction, JSON operators, placeholder syntax).

**Engine + path:** CEL-Go + `internal/filter/` (engine.go parses, parser.go builds IR, render.go generates SQL per dialect)

**Mechanism:** Filter string → CEL parses to AST → buildCondition recursively converts AST to dialect-agnostic IR condition tree → renderer walks IR and emits per-dialect SQL with placeholders and type-appropriate operators.
