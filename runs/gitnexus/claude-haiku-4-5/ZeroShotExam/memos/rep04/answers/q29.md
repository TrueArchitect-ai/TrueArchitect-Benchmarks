**Frontend API authentication interceptor:** `web/src/connect.ts` (line 156: `authInterceptor`)

**Token kinds managed:** 
- Access Token (JWT, stored in localStorage with expiry)
- Refresh Token (HTTP-only cookie, used via `refreshToken()` call to backend)

**Backend package:** `server/auth` (contains `authenticator.go` which validates tokens via methods like `AuthenticateByAccessTokenV2()`, `AuthenticateByRefreshToken()`, and `AuthenticateByPAT()`)

---

**How it works:**
The frontend interceptor in `web/src/connect.ts:authInterceptor` (1) prefetches the access token via `getRequestToken()` and adds it as a Bearer token in the Authorization header, (2) handles token refresh automatically when receiving a 401 response by calling the backend's `RefreshToken()` RPC with credentials via `refreshTransport`, and (3) manages token state via `web/src/auth-state.ts`. The backend `server/auth/authenticator.go` validates these tokens—access tokens are JWTs validated server-side, and refresh tokens are HTTP-only cookies.
