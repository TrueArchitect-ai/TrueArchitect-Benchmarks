**Interceptor path:** `web/src/connect.ts:156-178` (the `authInterceptor` function)

**Token kinds:** 
1. Access tokens (JWT) — short-lived (15 minutes), stateless validation via signature
2. Refresh tokens (JWT) — long-lived (30 days), stored in HTTP-only cookie, validated against database for revocation
3. Personal Access Tokens (PAT) — long-lived tokens with `memos_pat_` prefix for programmatic access

**Backend package:** `server/auth` — validates all tokens via the `Authenticator` struct defined in `server/auth/authenticator.go`

The frontend auth interceptor (web/src/connect.ts:156-178) attaches tokens to requests as Bearer tokens in the Authorization header, with logic to preflight-refresh expired tokens and reactive retry with refresh on 401 responses. The backend validates these three token types statelessly (access tokens) or via database lookup (refresh tokens, PAT) using methods like `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, and `AuthenticateByPAT`.
