**memo, memo_relation, attachment**

When `DeleteMemo` runs (`Store.DeleteMemo` at `store/memo.go:140`, invoked from the API handler at `server/router/api/v1/memo_service.go:518`):

- **memo_relation** — deleted directly for both directions (`MemoID` and `RelatedMemoID`), `store/memo.go:142-146`.
- **attachment** — attachments linked to the memo are deleted via `DeleteAttachment`, `store/memo.go:149-157` (also removes physical storage, not a DB table).
- **memo** — the memo row itself (`store/memo.go:158`); the API handler additionally recurses to delete comment memos (`server/router/api/v1/memo_service.go:573-577`), each of which repeats the same cascade.

Note: the `reaction` table is **not** touched by explicit cascade code in the delete path — reactions are only listed to build the deletion webhook payload (`server/router/api/v1/memo_service.go:545`), not deleted.
