**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156), which sets `Authorization: Bearer <token>` on every request (`setAuthorizationHeader`, line 97) and reactively refreshes on a 401; helper state lives in `web/src/auth-state.ts`, with the refresh RPC using `credentials: "include"` (line 60) so the refresh-token cookie is sent.

**Token kinds it manages:**
- Short-lived **JWT access token** (~15 min) — held in memory and attached as the `Authorization: Bearer` header.
- **Refresh token** — delivered via HTTP cookie (`credentials: "include"`); used by `AuthService.RefreshToken` to mint new access tokens.
- (The backend additionally accepts **Personal Access Tokens (PAT)** on the same header.)

**Backend validating package:** `server/auth` (`server/auth/authenticator.go` — `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`; token parsing in `server/auth/token.go`).
