**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156), attached to the main transport (line 188). It reads the access token via `web/src/auth-state.ts`, sets the `Authorization: Bearer <token>` header, and on a 401 reactively refreshes and retries. Refresh calls go to the `AuthService.refreshToken` RPC over a separate transport with `credentials: "include"` (cookie-based).

**Token kinds:**
- **Access token** — short-lived JWT (~15 min), stored in `localStorage` (`memos_access_token`), sent as `Authorization: Bearer`.
- **Refresh token** — sent/received via an HTTP-only cookie (`credentials: "include"`), used to mint new access tokens.
- (The same `Bearer` path also accepts **Personal Access Tokens (PAT)** on the backend.)

**Backend validation package:** `server/auth/` — the `Authenticator` (`server/auth/authenticator.go`) validates access tokens (`AuthenticateByAccessTokenV2`), refresh tokens (`AuthenticateByRefreshToken`), and PATs (`AuthenticateByPAT`); JWT parsing/creation lives in `server/auth/token.go`.
