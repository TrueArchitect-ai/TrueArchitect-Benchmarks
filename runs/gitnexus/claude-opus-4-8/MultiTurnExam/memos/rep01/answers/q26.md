Tables affected when `DeleteMemo` runs (`store/memo.go:140`, plus the API-layer cascade in `server/router/api/v1/memo_service.go:518`):

- **memo_relation** — deleted where the memo is source (`MemoID`) and where it's target (`RelatedMemoID`) (store/memo.go:142, 145)
- **attachment** — all attachments linked to the memo are deleted (store/memo.go:149-157 → `DeleteAttachment` in store/attachment.go:132, which also removes storage files, not a DB table)
- **memo** — the memo row itself (store/memo.go:158); comment memos are also deleted recursively via the API handler (server/router/api/v1/memo_service.go:573-577), each cascading through the same paths

Note: `reaction` rows are listed for the webhook payload but are **not** explicitly deleted by this code path — cleanup of reactions is not performed in `DeleteMemo`'s explicit cascade code (any removal would rely on DB-level constraints, not code here).
