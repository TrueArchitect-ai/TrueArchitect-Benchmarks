memo, memo_relation, attachment

The API `DeleteMemo` handler (`server/router/api/v1/memo_service.go:518`) recursively deletes comment memos and then the memo itself via `Store.DeleteMemo` (`store/memo.go:140`). That store method explicitly deletes: `memo_relation` rows (both `memo_id` and `related_memo_id` directions), linked `attachment` rows (via `DeleteAttachment`, which also removes the underlying storage/local file — not a table), and finally the `memo` row.

Note: `reaction` rows are read for the webhook payload but are **not** deleted by explicit cascade code in this path (they'd rely on DB-level foreign keys, not application code).
