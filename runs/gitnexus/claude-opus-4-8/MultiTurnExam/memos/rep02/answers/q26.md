q26.
`memo`, `memo_relation`, `attachment`

`Store.DeleteMemo` (`store/memo.go:140-159`) explicitly deletes rows from `memo_relation` (both source `memo_id` and target `related_memo_id`) and `attachment` (via `DeleteAttachment`), then the `memo` row itself. At the API layer (`server/router/api/v1/memo_service.go:567-580`) comment memos are removed first, but those recurse into the same three tables.

Note: `reaction` is **not** deleted by explicit cascade code — `DeleteMemo` only *lists* reactions to build the webhook payload (`memo_service.go:545`), it never deletes them.
