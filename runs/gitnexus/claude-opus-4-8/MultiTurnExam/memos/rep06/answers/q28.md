**Runners the server actually starts** (all wired in `server/server.go:startBackgroundRunners`, line 153):

- **s3presign runner** — one immediate `RunOnce` at boot (`server/server.go:163`), then a continuous goroutine driven by a **12-hour `time.Ticker`** (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). It re-presigns S3 attachment URLs.

That is the **only** background runner started.

**Not a background worker:** `server/runner/memopayload` lives under `server/runner/`, but it is **not** started as a runner — its `RebuildMemoPayload` is called **synchronously inline** during `CreateMemo`/`UpdateMemo` (`server/router/api/v1/memo_service.go:108,447`), with no scheduling of its own.

**Unused scheduling infrastructure:** `internal/scheduler/` is a full GitHub-Actions-style cron scheduler (cron parser, jobs, middleware — `internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `doc.go`), but it is **not imported or started anywhere** by the server — no production code outside the package references `internal/scheduler`. The server relies solely on the s3presign `time.Ticker`, not this cron engine.
