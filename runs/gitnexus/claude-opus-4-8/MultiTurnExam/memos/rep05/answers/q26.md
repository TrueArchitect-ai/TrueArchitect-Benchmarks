**memo, memo_relation, attachment**

When `APIV1Service.DeleteMemo` runs, it calls `Store.DeleteMemo` (`store/memo.go:140`), whose explicit cascade code:
- deletes rows from **memo_relation** (both `memo_id` and `related_memo_id` directions),
- deletes linked rows from **attachment** (via `DeleteAttachment`; also deletes blob storage for local files, which is not a DB table),
- deletes the **memo** row itself.

The handler also recursively deletes comment memos through the same `Store.DeleteMemo` path (hitting the same three tables). Note: reactions are only *listed* for the webhook payload — the delete path does **not** remove `reaction` rows, so that table is not affected by explicit cascade code here.
