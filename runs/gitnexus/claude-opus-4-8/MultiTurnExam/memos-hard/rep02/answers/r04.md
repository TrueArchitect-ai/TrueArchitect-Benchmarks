**Premise correction:** Neither — there is no external message broker at all. A repo-wide search finds no NATS, RabbitMQ/AMQP, Kafka, or any broker dependency in the Go sources or `go.mod`. Webhook delivery does not consume from an external queue.

**Actual mechanism:** The webhook workers consume from an **in-process buffered Go channel**, declared as a package-level variable in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

An `init()` function (`internal/webhook/webhook.go:42-54`) spawns **4 worker goroutines**, each ranging over that channel and calling `Post(payload)` to perform the actual HTTP delivery. Producers enqueue via `PostAsync` — `case asyncPostQueue <- requestPayload:` at `internal/webhook/webhook.go:190`. So it's a single-process, in-memory channel-plus-goroutine-pool (buffer size 128, 4 consumers), entirely within the server process — not a broker-backed queue, and it does not survive restarts.
