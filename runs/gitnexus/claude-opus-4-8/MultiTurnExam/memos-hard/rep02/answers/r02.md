**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — so there is no registration site and no request limits to report.

Evidence I checked:
- A repo-wide search for rate-limiting terms (`rate limit`, `ratelimit`, `throttle`, `limiter`, `tollbooth`, `golang.org/x/time/rate`) across the Go sources found **no implementation** — the only hit is a doc comment in `internal/email/doc.go:86` that merely *suggests* "Rate limit email sending to prevent abuse" as a future idea, not any actual code.
- `go.mod` declares no rate-limiting dependency.
- The middleware/interceptor surfaces contain nothing rate-related:
  - Echo middleware registered in `server/server.go:51-52` is only `Recover()` and a CORS middleware (`newCORSMiddleware`); the frontend adds static-file and SPA-fallback middleware (`server/router/frontend/frontend.go:54,59`).
  - The only Connect/gRPC interceptor is `MetadataInterceptor` (`server/router/api/v1/connect_interceptors.go`), which just converts HTTP headers to gRPC metadata — not rate limiting.

So the server enforces authentication/authorization and CORS, but ships no per-user (or global) API rate limiting.
