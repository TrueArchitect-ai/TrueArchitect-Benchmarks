**Premise correction:** There is no GraphQL schema in this project — no GraphQL API exists. A repo-wide search finds no `.graphql`/`.gqls` schema files, no `graphql`/`gqlgen` dependency in `go.mod`, and no resolver types. (The only grep hits were false positives on the word "Resolver" in DNS lookups: `internal/httpgetter/html_meta.go:23`, `internal/webhook/webhook.go:65`.)

**Actual API surface:** The public API is defined with **Protocol Buffers**, served over **Connect RPC / gRPC** (with gRPC-Web/HTTP compatibility), not GraphQL.
- The schema (service and message definitions) lives in `.proto` files under `proto/api/v1/` — e.g. `proto/api/v1/memo_service.proto`, `auth_service.proto`, `user_service.proto`, `attachment_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `ai_service.proto`, `instance_service.proto`, plus `common.proto` (store-layer messages are in `proto/store/*.proto`).
- Generated Go/Connect code is in `proto/gen/api/v1/` and `proto/gen/api/v1/apiv1connect/`.
- The services are registered in `RegisterConnectHandlers` — `server/router/api/v1/connect_handler.go:31` — which mounts the eight Connect service handlers (`apiv1connect.NewMemoServiceHandler`, `NewAuthServiceHandler`, `NewUserServiceHandler`, etc.) on the HTTP mux (`connect_handler.go:37-44`).
- Additionally there's an SSE endpoint for live memo refresh (`server/router/api/v1/sse_handler.go`), and RSS/fileserver/frontend HTTP surfaces — but none are GraphQL.

So the equivalent of a "schema for the public API" is the set of protobuf service definitions in `proto/api/v1/`, exposed via Connect RPC.
