**Premise correction:** There is no Redis. The codebase contains no Redis dependency or connection anywhere — `grep -rni "redis"` across the Go sources and `go.mod` returns nothing. The cache layer is a self-contained, thread-safe **in-memory** cache, not backed by any external store.

**Actual mechanism:**
- The cache implementation is `store/cache/cache.go` — a `Cache` struct holding items in an in-process map with per-item expiration (`item.expiration = time.Now().Add(ttl)`, `cache.go:112`) and a background `cleanupLoop` (`cache.go:199`) that evicts expired entries. It's constructed via `cache.New(config)` (`cache.go:76`).
- It is "configured" in `store.New` (`store/store.go:38-53`), not via any connection string. A single `cache.Config` (`store/store.go:40-45`) is used to build three caches, including `userCache` (`store/store.go:52`): `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`.
- **TTL for user entries: 10 minutes.** User records are written with `s.userCache.Set(...)` (`store/user.go:98,122,132,143,167`), and `Set` uses the cache's `DefaultTTL` (`cache.go:92-94`), which is the 10-minute value from the config above. (A `SetWithTTL` variant exists for custom TTLs, but user entries use the default path.)
