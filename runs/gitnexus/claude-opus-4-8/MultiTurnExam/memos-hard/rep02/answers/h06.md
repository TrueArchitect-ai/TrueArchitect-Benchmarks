**Convergence function — `webhook.PostAsync` — `internal/webhook/webhook.go:184`.** This is the single choke point where every one of those paths meets before delivery; it enqueues the payload, and a background worker drains the queue into `Post` (`internal/webhook/webhook.go:120`), which issues the actual HTTP request.

Note on the API layer: the create/update/delete handlers funnel through `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), but the comment path (`DispatchMemoCommentCreatedWebhook`) calls `webhook.PostAsync` directly and bypasses it — so `dispatchMemoRelatedWebhook` is *not* a universal choke point; `webhook.PostAsync` is. (Reaction handlers like `UpsertMemoReaction`/`DeleteMemoReaction` do **not** dispatch webhooks in this codebase.)
