**Concrete method: `(*DB).CreateMemo` in the SQLite driver — `store/db/sqlite/memo.go:16`** (it builds `INSERT INTO \`memo\` (...) VALUES (...) RETURNING ...` at `memo.go:41` and executes it via `d.db.QueryRowContext` at `memo.go:42`).

**How I determined which of the three candidate `CreateMemo` implementations (sqlite/mysql/postgres) actually runs:**

1. The store facade `(*Store).CreateMemo` (`store/memo.go:109`) doesn't do SQL itself — it dispatches through the `store.Driver` interface: `return s.driver.CreateMemo(ctx, create)` (`store/memo.go:113`). So the concrete method is whichever driver `s.driver` holds.
2. `s.driver` is chosen by the factory `NewDBDriver` (`store/db/db.go:14`), which switches on `profile.Driver`: `"sqlite" → sqlite.NewDB`, `"mysql" → mysql.NewDB`, `"postgres" → postgres.NewDB` (`store/db/db.go:18-27`).
3. With a **default installation (no flags)**, `profile.Driver` defaults to `"sqlite"` — set in `cmd/memos/main.go:122` (`viper.SetDefault("driver", "sqlite")`) and `cmd/memos/main.go:130` (`PersistentFlags().String("driver", "sqlite", ...)`). No `--driver` flag means the `"sqlite"` case is taken, so `s.driver` is the SQLite `*DB`.
4. Therefore the interface call resolves to the SQLite implementation `(*DB).CreateMemo` at `store/db/sqlite/memo.go:16`, which is the code that actually issues the INSERT. (The mysql/postgres `CreateMemo` methods exist but are unreachable without an explicit non-default `--driver`.)
