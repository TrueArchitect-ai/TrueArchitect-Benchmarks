**No** — the MySQL driver is never constructed directly outside the driver-selection factory in any production/external code.

Evidence:
- The MySQL constructor is `NewDB(profile *profile.Profile) (store.Driver, error)` in package `store/db/mysql` (`store/db/mysql/mysql.go:20`).
- The factory is `NewDBDriver` (`store/db/db.go:14`), whose `case "mysql"` calls `mysql.NewDB(profile)` at `store/db/db.go:22`.
- `mysql.NewDB` is called from exactly one place in the entire repo — that factory line. The `store/db/mysql` package is imported by only one file, `store/db/db.go:8` (the factory itself). No `main`, migration, tool, or other production code imports or constructs it.
- The one construction outside the factory is a bare struct literal `db := &DB{}` in `store/db/mysql/auth_config_test.go:12` — an in-package (white-box) unit test that allocates a zero-value `DB` to exercise a method. It does not call `NewDB` and does not go through the factory, but it is same-package test code, not a direct driver construction in the normal sense.

So the only "direct" instantiation anywhere outside the factory is that same-package test's struct literal; no other code constructs the MySQL driver except the factory.
