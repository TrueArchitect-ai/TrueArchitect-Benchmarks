**Premise correction:** No nightly database-cleanup job is scheduled anywhere in this codebase — so there is no scheduled run time to report.

Evidence:
- The `internal/scheduler` package (a general-purpose cron scheduler, `internal/scheduler/doc.go`) exists, but **nothing imports or uses it** — a non-test search for imports of `internal/scheduler` returns zero files, and there are no `scheduler.New()` / `Register(...)` / `Start()` calls anywhere outside the package's own code and tests. It is unwired library code.
- The only "daily-cleanup" with a `"0 2 * * *"` (2 AM daily) schedule is an **illustrative example in a doc comment** — `internal/scheduler/doc.go:15-18` — not an actual registered job.
- The real background jobs in the server are not cron-based and are not DB-cleanup: the s3presign runner (12-hour ticker, `server/runner/s3presign/runner.go`) wired at `server/server.go:162-169`, and cache-eviction goroutines inside the in-memory cache (`store/cache/cache.go`). Actual data cleanup (relations, attachments) happens inline within delete operations (e.g. `store.DeleteMemo`, `store.DeleteUser`), not on a nightly schedule.

If you'd expected a nightly cleanup, note that the scheduler machinery is present but never instantiated — so if that 2 AM job is what you're after, it would need to be registered and started (it currently is not).
