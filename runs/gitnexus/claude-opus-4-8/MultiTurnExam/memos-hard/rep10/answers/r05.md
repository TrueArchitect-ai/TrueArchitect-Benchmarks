**Premise correction: there is no GraphQL schema — memos does not expose a GraphQL API. There are no `.graphql`/`.gql` files, no `gqlgen`, and no GraphQL server anywhere (the two "resolver" grep hits are `net.DefaultResolver` DNS lookups, not GraphQL resolvers).**

Actual API surface — Protobuf-defined gRPC / Connect RPC services:

- The public API is defined as Protocol Buffers under `proto/api/v1/*.proto`. Eight services are declared there:
  - `AuthService` (`proto/api/v1/auth_service.proto:13`)
  - `UserService` (`proto/api/v1/user_service.proto:17`)
  - `MemoService` (`proto/api/v1/memo_service.proto:17`)
  - `AttachmentService` (`proto/api/v1/attachment_service.proto:15`)
  - `InstanceService` (`proto/api/v1/instance_service.proto:17`)
  - `IdentityProviderService` (`proto/api/v1/idp_service.proto:14`)
  - `ShortcutService` (`proto/api/v1/shortcut_service.proto:14`)
  - `AIService` (`proto/api/v1/ai_service.proto:11`)
- Generated Go code lives in `proto/gen/api/v1/` (including `*.pb.gw.go` HTTP-gateway stubs), and the handlers implementing these services are the `APIV1Service` methods in `server/router/api/v1/`. They're served over the Connect protocol (gRPC/gRPC-Web/HTTP+JSON), not GraphQL.

So the "schema" for the public API is the set of `.proto` definitions in `proto/api/v1/`, not a GraphQL schema.
