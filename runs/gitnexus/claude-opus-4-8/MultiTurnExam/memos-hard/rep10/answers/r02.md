**Premise correction: memos has no per-user API rate-limiting middleware. There is nothing to register and no request limits, because the feature does not exist in the codebase.**

Evidence:

- A whole-repo grep for `ratelimit` / `rate limit` / `throttle` / `quota` / the usual limiter libraries (`golang.org/x/time/rate`, `tollbooth`) and `limiter` returns no implementation. The only hit is a comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") — an unimplemented note, not middleware, and about email rather than the API.
- The actual middleware/interceptor chain that *is* registered contains no limiter:
  - Echo HTTP middleware in `server/server.go:51-52`: `middleware.Recover()` and `newCORSMiddleware` (`server/cors.go:13`).
  - Connect RPC interceptors in `server/router/api/v1/connect_interceptors.go`: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor` (plus auth). None enforce request counts or rates.

So there is no per-user (or global) API rate limiter in the server, and therefore no configured request limits to report. If rate limiting is required, it would need to be added (e.g. a new Connect interceptor) or handled by an upstream reverse proxy outside this repository.
