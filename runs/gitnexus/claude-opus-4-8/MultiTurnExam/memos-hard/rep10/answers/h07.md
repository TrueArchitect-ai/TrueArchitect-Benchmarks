How it fits together: the JSON API doesn't return raw avatar bytes — `user_service_converters.go:31-38` rewrites `AvatarUrl` to `/file/{name}/avatar`, so the browser fetches that route. `serveUserAvatar` reads the `:identifier` param, calls `getUserByUsername` (a thin wrapper over `Store.GetUser` with `FindUser{Username:...}`), which falls through to `Store.ListUsers` → the driver's `ListUsers` that issues `SELECT ... avatar_url ... FROM user WHERE username = ?` and scans it into `user.AvatarURL` (`store/db/sqlite/user.go:189`; equivalents at `postgres/user.go:150`, `mysql/user.go:147`).

The avatar is stored as a base64 `data:` URI in the `user.avatar_url` column (not `user_setting`, not a blob). The handler then decodes it via `parseDataURI` (`fileserver.go:737`) using `dataURIRegex` (`fileserver.go:98`), validates the MIME against `avatarAllowedTypes`, and writes the raw bytes with `c.Blob(...)`.
