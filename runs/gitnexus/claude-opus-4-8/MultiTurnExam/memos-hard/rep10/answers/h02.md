**Delivery function — `Post` in `internal/webhook/webhook.go` (the HTTP POST executes at `safeClient.Do(req)`, `webhook.go:152`); protection — a custom `http.Client` whose `Transport.DialContext` is `safeDialContext`, backed by the `isReservedIP`/`reservedCIDRs` blocklist in `internal/webhook/validate.go`**

Details:

- **Delivery** — `Post(requestPayload *WebhookRequestPayload)` at `internal/webhook/webhook.go:120` performs the outbound POST via the shared `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. (`PostAsync` just enqueues; background workers call `Post`.)

- **Protection** — the delivery client is wired with `DialContext: safeDialContext` (`internal/webhook/webhook.go:35`). `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the target host at dial time and rejects any resolved address matching `isReservedIP` (`internal/webhook/validate.go:44`), which checks against the `reservedCIDRs` blocklist (`internal/webhook/validate.go:14`) covering loopback, RFC1918 private ranges, and link-local `169.254.0.0/16` (the cloud IMDS range). Because the check runs at dial time on the resolved IP, it also defends against DNS rebinding.

Worth noting: there's a global `AllowPrivateIPs` opt-out flag (`internal/webhook/validate.go:41`, honored at `validate.go:45`) that disables this protection, and a create/update-time `ValidateURL` (`internal/webhook/validate.go:62`) that applies the same check as defense-in-depth.
