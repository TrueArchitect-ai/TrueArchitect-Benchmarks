**Premise correction: there is no Redis. The cache layer is a process-local, in-memory cache — a whole-repo grep for `redis` returns zero hits.**

Actual mechanism:

- The cache is `store/cache/cache.go` — a thread-safe in-memory cache built on `sync.Map` with per-item TTL and a background cleanup goroutine. There is no external cache server, no connection string, and no Redis configuration anywhere.
- It's configured in the `Store` constructor at `store/store.go:40-45`, where a single `cache.Config` is created (`DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`) and used to build three separate caches — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`). (`cache.DefaultConfig()` at `store/cache/cache.go` also defaults to the same 10-minute TTL.)
- **User-entry TTL: 10 minutes.** User rows are inserted via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. `store/user.go:98,122,132,143,167`). `Set` uses the cache's configured `DefaultTTL` (see the `Interface.Set` doc comment in `cache.go`), which for `userCache` is the 10 minutes set at `store/store.go:41`. Expired entries are swept by the cleanup goroutine every 5 minutes, and the cache is capped at 1000 items.

So: cache = in-memory (`store/cache`), configured in `store/store.go:40-53`; user entries live 10 minutes.
