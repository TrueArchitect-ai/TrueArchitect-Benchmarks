**Premise correction:** There is no per-user API rate-limiting middleware in this codebase, so there is nothing to register and no request limits to report. A repo-wide search for rate limiting turns up nothing functional — no `golang.org/x/time/rate`, no limiter/throttle library in `go.mod`, and the only textual hit is an unrelated documentation comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which is aspirational doc text, not implemented code.

What the server actually registers instead:
- Echo HTTP middleware in `server/server.go:51-52`: `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`, `server/cors.go`).
- Connect/gRPC interceptors in `server/router/api/v1/v1.go:133-138`: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (authentication/authorization) — none of which do rate limiting.

The only request-sizing guard present is a max request body size (`connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`), which caps payload bytes per request — not a per-user request-rate limit.
