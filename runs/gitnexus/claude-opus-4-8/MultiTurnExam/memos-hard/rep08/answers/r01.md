**Premise correction:** There is no Redis in this project. A repo-wide search finds zero `redis` references in any `.go` file and no redis dependency in `go.mod`/`go.sum`. The cache layer is not backed by Redis at all.

**Actual mechanism:** The cache is a thread-safe **in-memory** cache implemented in `store/cache/cache.go` (`type Cache`, constructed via `cache.New(config)`). It's configured in the store constructor, not via any connection string — `store/store.go:40-45` builds a `cache.Config` with `DefaultTTL: 10 * time.Minute` and `CleanupInterval: 5 * time.Minute`, then creates three caches from it: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`). A background `cleanupLoop` (`store/cache/cache.go:199`) evicts expired entries.

**TTL for user entries:** User records are cached via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (`store/user.go:143`). `Set` uses the cache's default TTL (`store/cache/cache.go:92-94`), which for `userCache` is the configured `DefaultTTL` of **10 minutes**. No per-user custom TTL is applied.
