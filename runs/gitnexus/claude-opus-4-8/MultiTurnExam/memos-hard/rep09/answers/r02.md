**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — so there is no registration site and no request limits to report.

- A full search for rate-limiting concepts (`ratelimit`, `limiter`, `throttle`, `golang.org/x/time/rate`, `tollbooth`, etc.) turns up **no implementation**. - A bounded async **webhook dispatch queue** (128 entries, 4 workers) — `internal/webhook/webhook.go:39-55`.

Answer: **Premise is incorrect — no per-user (or any) API rate-limiting middleware is registered anywhere in the codebase (only an aspirational comment at `internal/email/doc.go:86`). The nearest real safeguards are the 8 KB memo content-length limit (`store/instance_setting.go:211`), image-processing concurrency semaphores (`server/router/api/v1/v1.go:59-60`, `server/router/fileserver/fileserver.go:116`), and the bounded webhook queue (`internal/webhook/webhook.go:39`) — none of which are request-rate limits.**
