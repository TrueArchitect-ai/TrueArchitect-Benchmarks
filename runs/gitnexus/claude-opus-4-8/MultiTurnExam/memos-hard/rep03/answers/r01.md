**Premise correction:** There is no Redis anywhere in this codebase. A repo-wide search for `redis` finds zero matches in the Go source and in `go.mod`. The cache layer is **not** backed by Redis — it is a custom **in-process, in-memory cache** implemented in `store/cache/cache.go` (a `map`-based store guarded by a mutex, with a background cleanup goroutine and approximate size/`MaxItems` eviction). So there is no Redis connection to configure.

**Actual mechanism:**
- **Where configured:** The Store builds one `cache.Config` and instantiates the caches with it in `store/store.go:40-53`:
  ```
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ...
  userCache: cache.New(cacheConfig),
  ```
  (The same config also backs `instanceSettingCache` and `userSettingCache`.)
- **TTL for user entries:** **10 minutes.** User entries are written via `s.userCache.Set(...)` (e.g. `store/user.go:143`, `:167`), and `Cache.Set` applies the config's `DefaultTTL` (`store/cache/cache.go:94`, `SetWithTTL(..., c.config.DefaultTTL)`), which is `10 * time.Minute` per `store/store.go:41`. Expired entries are reaped by the cleanup loop every 5 minutes (`CleanupInterval`). No user entry is written with a custom per-entry TTL, so 10 minutes applies.
