**Premise correction:** There is no nightly database-cleanup job, and in fact the cron scheduler is not wired into the running server at all — so there is no schedule time to report.

Evidence:
- A cron scheduler package does exist (`internal/scheduler/` — `scheduler.go`, `job.go`, `parser.go` with `ParseCronExpression`), but it is **never used by production code**. Searching for any non-test import of `internal/scheduler` returns nothing, and `scheduler.New()` appears only in doc comments (`internal/scheduler/doc.go:12,28`) and tests. Nothing registers a job with it.
- There is no "database cleanup" job anywhere. The only cleanup work is (a) on-demand, inline during `DeleteUser`/`DeleteMemo` (e.g. attachment-storage cleanup in `store/attachment.go:171` and `server/router/api/v1/user_service.go:421-450`), not scheduled; and (b) the in-memory cache's expiry sweep, which runs every **5 minutes** via a `time.Ticker` (`store/cache/cache.go:200-210`, `CleanupInterval` at `store/store.go:42`) — not a cron job and not database-related.
- The server's actual background work is started in `Server.startBackgroundRunners` (`server/server.go:153`), which runs only the S3-presign runner on a fixed **12-hour** interval (`server/runner/s3presign/runner.go:27`). That is the only recurring scheduled task, and it re-presigns S3 attachment URLs — it is not a nightly job and not a database cleanup.

So the assumption of a nightly, cron-scheduled DB-cleanup job is incorrect: no such job (or cron time) exists.
