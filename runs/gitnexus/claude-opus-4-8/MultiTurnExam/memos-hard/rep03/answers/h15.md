Memo visibility (PUBLIC / PROTECTED / PRIVATE vs. viewer) is enforced at these distinct server surfaces:

1. Single-memo read access — `checkMemoReadAccess` — `server/router/api/v1/memo_service.go:39` (lines 55, 24-25 do the PUBLIC/PROTECTED/PRIVATE-vs-viewer check; called from `GetMemo` at :356 and for parent memos at :367).
2. Memo list filtering — `ListMemos` — `server/router/api/v1/memo_service.go:219-225` (anonymous → PUBLIC only; authed → own + PUBLIC/PROTECTED).
3. SSE event delivery filtering — `SSEHub.canReceive` — `server/router/api/v1/sse_hub.go:135-141` (per-subscriber visibility gate on streamed memo events).
4. Attachment/file serving — `FileServerService.checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650` (enforces the owning memo's visibility at lines 677, 699).
5. RSS feed — `server/router/rss/rss.go:90` and `:141` (`VisibilityList: []store.Visibility{store.Public}` — only public memos exposed).
6. Frontend SSR / sitemap — `server/router/frontend/frontend.go:150` (`VisibilityList: []store.Visibility{store.Public}`).

Additional API-v1 sites that re-apply the same viewer-based visibility filter (same surface as #2, distinct code locations):
- Comment listing — `server/router/api/v1/memo_service_comments.go:158-160`.
- Memo-relation listing — `server/router/api/v1/memo_relation_service.go:109-111`.
- User stats — `server/router/api/v1/user_service_stats.go:84-90` and `:218-220`.
