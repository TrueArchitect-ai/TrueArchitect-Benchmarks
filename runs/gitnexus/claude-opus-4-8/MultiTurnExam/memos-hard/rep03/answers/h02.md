**Delivery function:** `Post` in `internal/webhook/webhook.go:120-180` — it marshals the payload, builds the POST request (optionally HMAC-signs it), and the actual outbound HTTP call executes at `safeClient.Do(req)` (`internal/webhook/webhook.go:152`). `PostAsync` (line 184) just enqueues onto a bounded channel drained by worker goroutines that call `Post`.

**Protection mechanism:** The SSRF guard is baked into the shared `safeClient`'s transport via `safeDialContext` (`internal/webhook/webhook.go:32-37, 59-77`). At **dial time** it re-resolves the target hostname and rejects any address in a reserved/private range through `isReservedIP` (`internal/webhook/validate.go:44-54`), which checks against `reservedCIDRs`/`reservedNetworks` covering loopback, RFC-1918, IPv6 ULA/link-local, and cloud IMDS `169.254.169.254` (`internal/webhook/validate.go:11-36`). Because the check runs at connection time on the actually-resolved IP (not just the pre-parsed URL), it also defeats DNS-rebinding.

Supporting notes:
- There's an additional up-front validation, `ValidateURL` (`internal/webhook/validate.go:56-83`), used when webhooks are configured (scheme must be http/https; hostname must not resolve to a reserved IP), but that is a create-time check — the enforcement that protects the *delivery* itself is `safeDialContext`.
- The guard can be globally disabled by the `AllowPrivateIPs` flag (`internal/webhook/validate.go:38-47`), which short-circuits `isReservedIP` for self-hosted deployments targeting the local network.
