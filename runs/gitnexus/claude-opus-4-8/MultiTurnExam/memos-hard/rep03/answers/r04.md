**Premise correction:** Neither. There is no external message broker in this codebase — no NATS, no RabbitMQ (nor AMQP/Kafka). A repo-wide search for `nats`, `rabbitmq`, `amqp`, `kafka` finds zero matches in the Go source and in `go.mod`. So there is no broker to consume from and no external queue declared.

**Actual mechanism:** Webhook delivery is dispatched over an **in-process buffered Go channel**, entirely within the server process:
- The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — declared at `internal/webhook/webhook.go:39` (a channel with a 128-item buffer).
- The workers are **4 goroutines** started in the package `init()` (`internal/webhook/webhook.go:42-55`); each ranges over `asyncPostQueue` and calls `Post` (the actual HTTP delivery, `internal/webhook/webhook.go:120`).
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking `select` send onto `asyncPostQueue` and drops the payload (with a warning) if the buffer is full.

So the "broker" is just a bounded in-memory channel with a fixed pool of consumer goroutines — there is no NATS/RabbitMQ queue declaration anywhere.
