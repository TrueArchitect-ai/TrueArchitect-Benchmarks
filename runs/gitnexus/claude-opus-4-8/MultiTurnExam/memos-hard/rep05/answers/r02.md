**Premise correction:** The repository has **no per-user API rate-limiting middleware** — there is nothing to register and no request limits to report. The premise is mistaken.

Evidence:
- A repo-wide grep for `ratelimit` / `rate limit` / `limiter` / `throttle` / `golang.org/x/time/rate` across the Go sources yields no rate-limiting implementation. The only hit is a comment in `internal/email/doc.go:86` describing a possible future idea for email sending, not an implemented middleware.
- The complete Connect/gRPC interceptor chain is assembled at `server/router/api/v1/v1.go:133-138` and consists of exactly four interceptors: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`). None of them performs rate limiting.

What *does* exist near this area — and may be what the question conflates with rate limiting — is a **request body size limit**, not a request-frequency limit: `maxAPIRequestBytes` is enforced via `connect.WithReadMaxBytes(maxAPIRequestBytes)` and `http.MaxBytesHandler(...)` at `server/router/api/v1/v1.go:141,144`. That caps payload size per request, not the number of requests per user. There is also `AuthInterceptor` (`connect_interceptors.go:205`) for authentication/anonymous-access policy, but again no rate/quota enforcement.
