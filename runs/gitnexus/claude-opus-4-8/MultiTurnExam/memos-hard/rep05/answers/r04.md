**Premise correction:** Neither. The webhook delivery workers do **not** consume from an external message broker — there is no NATS, RabbitMQ, AMQP, or Kafka anywhere in the codebase (a repo-wide grep for `nats`/`rabbitmq`/`amqp`/`kafka` across the Go sources and `go.mod` returns nothing). There is no external queue to declare.

**Actual mechanism:** The "queue" is an **in-process buffered Go channel** with a fixed pool of goroutine workers, all inside `internal/webhook/webhook.go`:

- The queue is declared as a package-level buffered channel of capacity 128: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`.
- Four worker goroutines are spawned in `func init()` (`webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post` (`webhook.go:46`) to perform the actual HTTP delivery (`safeClient.Do` at `webhook.go:152`).
- Producers enqueue via `PostAsync` (`webhook.go:184`), which does a non-blocking send onto the channel and **drops** the payload with a warning if the buffer is full (`webhook.go:189-195`).

So delivery is handled entirely within the server process by a bounded channel + 4 workers, not by any message broker.
