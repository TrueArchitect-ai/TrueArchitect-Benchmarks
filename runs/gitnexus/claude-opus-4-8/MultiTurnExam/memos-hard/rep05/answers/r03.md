**Premise correction:** There is **no nightly database-cleanup job scheduled in the cron scheduler** — so there is no run time to report. The premise is mistaken on two counts:

1. **No such job is registered anywhere.** A cron `scheduler` package does exist (`internal/scheduler/`, with `Job.Schedule` cron expressions, `scheduler.New`, `Register`, etc.), but it is **never wired into production**: grepping for imports of `internal/scheduler` or calls to `scheduler.New` / `scheduler.Register` outside the package's own files and tests returns nothing, and no `Job` is registered anywhere under `server/`. The scheduler is effectively dead/unused infrastructure at runtime.

2. **The "2 AM daily cleanup" you may be thinking of is only example text.** The string `"0 2 * * *" // 2 AM daily` with a `daily-cleanup` job appears solely inside a documentation comment illustrating the API — `internal/scheduler/doc.go:14-19` — not in any real registration.

What actually runs on a schedule in this server is the **S3 presign runner**, and it is not cron-based and not a database cleanup: it re-signs S3 attachment URLs on a fixed **12-hour interval** via a `time.Ticker` (`server/runner/s3presign/runner.go:27`), wired in at `server/server.go:162-169`. The only "cleanup" timers are the in-memory cache's expiry sweeps every 5 minutes (`store/cache/cache.go:200-210`, `store/store.go:42`), which are also not a nightly cron job and not database-level.
