**Premise correction:** There is no Redis (or any external cache server) in this codebase — a repo-wide grep for `redis` in Go sources returns nothing. The cache layer is a self-contained, **in-process in-memory cache** implemented in `store/cache/cache.go` (a TTL map guarded by `sync`/`sync/atomic`, with a background cleanup goroutine). So there is no "Redis connection" to configure.

**Actual mechanism:**
- The cache is constructed in `store.New` at `store/store.go:38-58`, where a single `cache.Config` (`store/store.go:40-45`) is applied to three in-memory caches via `cache.New(cacheConfig)` — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`). No host/port/DSN is involved; it lives in the server process.
- **TTL for user entries:** `DefaultTTL = 10 * time.Minute` (`store/store.go:41`). User records are cached via `s.userCache.Set(...)` (e.g. `store/user.go:98,122,167`), which uses the cache's default TTL, so user entries expire after **10 minutes** (with cleanup sweeps every 5 minutes and a 1000-item cap, `store/store.go:42-43`). The default config values are also defined in `cache.DefaultConfig()` at `store/cache/cache.go:57` (10m TTL / 5m cleanup), though the store passes its own explicit config.
