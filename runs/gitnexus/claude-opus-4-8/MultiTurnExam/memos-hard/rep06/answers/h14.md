- **Where computed:** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`) writes the derived metadata into `memo.Payload`. It does a single-pass markdown walk via the injected `markdown.Service.ExtractAll` (`internal/markdown/markdown.go`), then sets `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`.
- **What triggers recomputation:** the graph confirms three callers of `RebuildMemoPayload`:
  - `CreateMemo` — `server/router/api/v1/memo_service.go:108` (on every memo creation).
  - `UpdateMemo` — `server/router/api/v1/memo_service.go:447` (when the memo's content is updated).
  - `Runner.RunOnce` — `server/runner/memopayload/runner.go:27/52` (a batch rebuild over all memos; note per earlier findings this runner has no production startup wiring, so it's effectively a maintenance/backfill path).
- **What the computation extracts** (from `ExtractAll`, `internal/markdown/markdown.go`): the memo's `#tags` (deduplicated, case-preserved) and a `MemoPayload_Property` (`proto/gen/store/memo.pb.go:85`) with:
  - `Title` — text of a leading H1 heading,
  - `HasLink` — content contains a link,
  - `HasCode` — content contains a code block/span,
  - `HasTaskList` — content contains a task checkbox,
  - `HasIncompleteTasks` — at least one unchecked task.

  (`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property` into the memo payload.)
