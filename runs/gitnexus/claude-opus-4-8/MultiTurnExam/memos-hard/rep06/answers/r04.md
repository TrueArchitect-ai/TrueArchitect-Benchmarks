**Premise correction: webhook delivery does not use NATS or RabbitMQ — there is no external message broker at all.** Searching `go.mod` and all `.go` files for `nats`, `rabbitmq`, and `amqp` returns zero matches, so neither broker is a dependency and no queue is "declared" in any broker.

**Actual mechanism:** The webhook workers consume from an in-process Go **buffered channel**. In `internal/webhook/webhook.go`:
- The queue is declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (line 39) — a channel with a 128-slot buffer, living entirely in the server process's memory.
- `init()` (line 42) launches **4 goroutine workers**, each ranging over `asyncPostQueue` (line 45) and calling `Post(payload)` (line 46) to perform the outbound HTTP delivery.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which sends the payload onto that same channel.

So delivery is a purely in-memory producer/consumer pipeline (channel + goroutine pool), not a durable broker-backed queue — the backlog is bounded at 128 and is lost if the process restarts.
