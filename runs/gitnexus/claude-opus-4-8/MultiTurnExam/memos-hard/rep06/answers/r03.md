**Premise correction: there is no nightly database-cleanup job in the cron scheduler — so there is no scheduled run time to report.**

Evidence:
- A cron `scheduler` package *does* exist (`internal/scheduler/` — "a GitHub Actions-inspired cron job scheduler" with cron-expression `Schedule` fields, `internal/scheduler/doc.go`, `job.go:19`), but it is **never wired into the running server**. Searching all non-test `.go` files outside the package itself for `scheduler.New`, `scheduler.Job`, or `.Register(` (a job) yields **zero** production call sites — nothing constructs the scheduler or registers any job with it at startup.
- There is likewise no cron expression for a nightly job anywhere in `server/` (no `Schedule:` cron strings, no `@daily`/`@midnight`/`"0 0 ..."`).
- No database-cleanup job of any kind is scheduled. The only recurring background work is the S3 presign refresh runner, and it runs on a **12-hour `time.Ticker`**, not a cron time (`server/runner/s3presign/runner.go:27`, wired at `server/server.go:169`) — see earlier findings. Attachment/storage cleanup happens **synchronously on user deletion** (`server/router/api/v1/user_service.go:421+`), not on a nightly schedule.

So the scheduler is present-but-unused, and no nightly DB-cleanup cron job (and no run time) exists.
