**Premise correction: there is no per-user (or any) API rate-limiting middleware in this codebase — so there's no registration site and no request limits to report.**

Evidence:
- A repo-wide search of all `.go` files for `rate limit` / `ratelimit` / `throttle` / `limiter` / `tollbooth` / `golang.org/x/time/rate` returns **zero** matches. `go.mod` likewise has no rate-limiting dependency.
- The actual API middleware/interceptor chains contain no limiter:
  - Connect/gRPC interceptors (`server/router/api/v1/v1.go:133-137`): `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` — nothing rate-related.
  - Echo middleware (`server/server.go:51-52`): `middleware.Recover()` and `newCORSMiddleware(profile)` only.

The closest related control is a **request body size cap**, not a rate limit: `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` at `server/router/api/v1/v1.go:20, 126, 141, 144`. That limits how large a single request may be, not how many requests a user may make.
