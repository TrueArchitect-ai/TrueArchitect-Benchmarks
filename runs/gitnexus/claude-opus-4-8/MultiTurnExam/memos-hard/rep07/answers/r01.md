**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` (case-insensitive, all Go files) returns zero hits. The cache layer is a purely in-process, in-memory implementation — no external cache server is configured or connected anywhere.

**Actual mechanism:**
- The cache is `store/cache/cache.go` — an in-memory, mutex-guarded store of `item{value, expiration, size}` with a background cleanup goroutine (implements the `cache.Interface`, cache.go:11).
- It's configured in `store.NewStore` at `store/store.go:40-45`: `cache.Config{ DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000 }`. Three caches are constructed from this same config — `instanceSettingCache`, `userCache`, `userSettingCache` (store.go:51-53).
- **TTL for user entries:** the `userCache` writes all go through plain `Set` (e.g. `s.userCache.Set(...)` at store/user.go:98, 122, 132, 143, 167), which applies the **default TTL of 10 minutes**. No `SetWithTTL` override is used for user entries, so user cache entries expire 10 minutes after they're written (with sweep every 5 minutes and a 1000-item cap).
