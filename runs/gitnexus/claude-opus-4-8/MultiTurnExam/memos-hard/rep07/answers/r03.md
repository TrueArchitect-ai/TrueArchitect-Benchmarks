**Premise correction:** There is no nightly database-cleanup job, and no cron scheduler drives one — so there is no scheduled time to report.

Evidence:
- An `internal/scheduler` package exists (with `New`, `Register`, `Start`, cron `parser.go`, etc.), but **nothing imports it**: a repo-wide search for imports of `internal/scheduler` and for `scheduler.New(` / `.Register(` outside the package itself returns zero production references. The cron scheduler is dead/unwired code — it never runs.
- The server's actual background work is not cron-based and contains no DB-cleanup job. `startBackgroundRunners` (`server/server.go:153`) starts only the S3 presign runner (a 12-hour `time.Ticker`, `server/runner/s3presign/runner.go:27`); the memo-payload runner exists but isn't invoked.
- The only recurring "cleanup" in the codebase is the **in-memory cache sweep** — `CleanupInterval: 5 * time.Minute` (`store/store.go:42`, `store/cache/cache.go:60`, loop at `cache.go:83`). That's an interval, not a nightly/clock-time cron, and it evicts expired cache entries, not database rows.
- Expired-record handling (refresh tokens, PATs, memo-share tokens, RSS cache entries) is done **lazily at access time** (e.g. `server/auth/authenticator.go:81-115`, `server/router/fileserver/fileserver.go:681-686`, `server/router/rss/rss.go:346-358`), not by any scheduled batch purge.

So the feature described in the question does not exist in this repository.
