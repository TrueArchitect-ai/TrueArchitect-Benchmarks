**Premise correction:** Neither NATS nor RabbitMQ (nor any external message broker) is involved. A repo-wide search for `nats`, `rabbitmq`, `amqp`, `kafka`, `streadway`, etc. across all Go files and `go.mod` returns zero matches. There is no broker and no externally-declared queue.

**Actual mechanism:** Webhook delivery uses an **in-process Go channel** as the queue, entirely within the server process — see `internal/webhook/webhook.go`:
- The "queue" is a buffered channel declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (capacity 128).
- The "workers" are 4 goroutines spawned in `init()` at `internal/webhook/webhook.go:42-55`, each ranging over `asyncPostQueue` and calling `Post` to perform the outbound HTTP delivery.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), a non-blocking `select` send that drops the payload (with a warning) if the buffer is full.

So it's a bounded, in-memory channel + goroutine-pool pattern, not a message-broker-backed queue. Nothing is persisted or consumed from an external broker; if the process restarts, in-flight queued webhooks are lost.
