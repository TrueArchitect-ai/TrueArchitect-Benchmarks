**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — so there is no registration site and no request limits to report.

Evidence:
- A repo-wide, case-insensitive search for rate-limiting terms (`rate limit`, `ratelimit`, `Limiter`, `throttle`, `tollbooth`, `golang.org/x/time/rate`) across all Go files returns **zero** matches.
- `go.mod` declares no rate-limiting/throttling dependency (no `x/time/rate`, tollbooth, ulule/limiter, etc.).
- The Connect/gRPC API stacks exactly four interceptors, none of them a limiter — `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` (`server/router/api/v1/v1.go:133-137`, defined in `server/router/api/v1/connect_interceptors.go`).
- The only "limit" tokens found are unrelated: a `WithReadMaxBytes(maxAPIRequestBytes)` request *size* cap (`server/router/api/v1/v1.go:141`) and a query `Limit` for a user lookup (`server/router/api/v1/authz.go:87-88`).

If per-user rate limiting is required, it would need to be added (e.g., as a new Connect interceptor registered alongside the existing four in `v1.go:133`); it does not exist today.
