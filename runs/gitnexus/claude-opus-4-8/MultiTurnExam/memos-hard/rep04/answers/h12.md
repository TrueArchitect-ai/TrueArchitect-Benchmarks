**How I determined it among the candidates:** There are three `CreateMemo` implementations — `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, and `store/db/mysql/memo.go` — each satisfying the `store.Driver` interface. Which one runs is fixed by the configured driver, resolved as follows:

1. **Default driver value** — the CLI sets the `driver` config default to `"sqlite"` in `cmd/memos/main.go:122` (`viper.SetDefault("driver", "sqlite")`), and the flag itself also defaults to `"sqlite"` (`cmd/memos/main.go:130`). With no DB flags, `Profile.Driver` is populated from this at `cmd/memos/main.go:43`.
2. **Driver selection** — `main.go:57` calls the factory `db.NewDBDriver(instanceProfile)` (`store/db/db.go:13`), whose `switch profile.Driver` picks `sqlite.NewDB(profile)` for `"sqlite"` (`store/db/db.go:19-20`). That concrete `*sqlite.DB` is stored as the `store.Driver` in `store.New(...)` (`main.go:64`).
3. **Dispatch to the INSERT** — a memo save goes through `Store.CreateMemo` (`store/memo.go`), which calls `s.driver.CreateMemo(...)` on the interface; since the driver instance is `*sqlite.DB`, the method that actually executes the SQL is the sqlite one at `store/db/sqlite/memo.go:16`. The postgres and mysql versions are never constructed in a default install (their `NewDB` is only reached for `driver == "postgres"`/`"mysql"`).
