A profile image (avatar) is stored **inline in the user row** as a base64 data-URI in the `avatar_url` column — not in file/S3/attachment storage — so the request stays in-process and resolves through the user store to the DB. Hops:

- serveUserAvatar (route `GET /file/users/:identifier/avatar`) — server/router/fileserver/fileserver.go:168 (registered at server/router/fileserver/fileserver.go:124)
- FileServerService.getUserByUsername — server/router/fileserver/fileserver.go:715
- Store.GetUser — store/user.go:148
- Store.ListUsers — store/user.go:136 (delegates to `s.driver.ListUsers`)
- (*DB).ListUsers — store/db/sqlite/user.go:88 (SQL `SELECT ... avatar_url ... FROM user`; Postgres/MySQL equivalents are the parallel `ListUsers` in store/db/postgres/user.go and store/db/mysql/user.go)

The row's `avatar_url` is returned back up the same chain, then decoded and written to the response in the handler: FileServerService.parseDataURI (server/router/fileserver/fileserver.go:196/737) → `c.Blob` (server/router/fileserver/fileserver.go:209).
