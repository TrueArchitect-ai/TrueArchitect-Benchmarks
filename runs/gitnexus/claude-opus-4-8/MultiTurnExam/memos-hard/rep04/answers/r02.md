**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — so there is no registration site and no request limits to report. A repository-wide search for any rate-limiting construct (`RateLimit`, `Throttle`, `limiter`, `golang.org/x/time/rate`, etc.) in the Go sources returns zero matches.

What the API middleware/interceptor chain actually contains (Connect/gRPC, registered in `server/router/api/v1/v1.go:133-137`) is:
- `NewMetadataInterceptor()` — copies HTTP headers into gRPC metadata (server/router/api/v1/connect_interceptors.go)
- `NewLoggingInterceptor(...)`
- `NewRecoveryInterceptor(...)` — panic recovery
- `NewAuthInterceptor(authorizer)` — authentication/authorization

None of these throttle by user or by request rate. The only request-volume controls present are unrelated to per-user rate limiting: a request **size** cap (`connect.WithReadMaxBytes(maxAPIRequestBytes)` at server/router/api/v1/v1.go:141), and in-process **concurrency semaphores** for expensive media work (`thumbnailSemaphore`/`imageProcessingSemaphore` in server/router/api/v1/v1.go:59-60, and the file server's thumbnail semaphore in server/router/fileserver/fileserver.go). There is no code that limits how many requests a given user may make per unit time.
