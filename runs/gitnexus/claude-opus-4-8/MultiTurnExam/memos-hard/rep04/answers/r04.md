**Premise correction:** Neither NATS nor RabbitMQ is used — there is no external message broker anywhere in the codebase. A repo-wide search for `nats`, `rabbitmq`, `amqp`, `kafka`, etc. (both in Go sources and in `go.mod`) returns nothing. So there is no broker-declared queue to point to.

**Actual mechanism:** Webhook delivery uses an **in-process buffered Go channel** with a fixed pool of goroutine workers, all inside `internal/webhook/webhook.go`:

- The "queue" is a package-level buffered channel declared at `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a bounded in-memory buffer of 128 pending payloads.
- The workers are 4 goroutines started in the package `init()` (`internal/webhook/webhook.go:42-45`), each looping `for payload := range asyncPostQueue` and calling `Post` to perform the HTTP delivery.
- Producers enqueue via `PostAsync`, which does a non-blocking send onto the channel (`internal/webhook/webhook.go:190`); if the buffer is full it drops the event with a warning (`webhook.go:191-195`) rather than blocking.

So the whole thing is local to the process (state is lost on restart, no persistence, no broker); there is no NATS/RabbitMQ queue declaration to cite.
