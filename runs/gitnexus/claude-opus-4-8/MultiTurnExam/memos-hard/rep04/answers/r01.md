**Premise correction:** There is no Redis anywhere in this codebase. A repo-wide search for `redis`/`Redis` in Go sources returns nothing — the cache layer is not backed by Redis (or any external cache server). So "where the Redis connection is configured" has no answer because no such connection exists.

**Actual mechanism:** The cache is a custom, process-local, thread-safe **in-memory** cache implemented in `store/cache/cache.go` (`type Cache` at store/cache/cache.go:67; entries expire via a per-item `expiration` timestamp and a background `cleanupLoop`).

- **Where it's "configured":** in `store.New(...)`, which builds one `cache.Config` and creates three in-memory `cache.Cache` instances — including the user cache — at `store/store.go:40-53`. (The package also exposes `DefaultConfig()` with the same values at store/cache/cache.go:57-64, but the store constructs its own literal config rather than calling it.)
- **TTL for user entries:** user entries live in `userCache` (`store/store.go:52`), which uses the shared config's `DefaultTTL` of **10 minutes** (`store/store.go:41`). There is no user-specific TTL override — `Store.GetUser` populates the cache via `s.userCache.Set(...)` (store/user.go:167), and `Set` applies the default TTL (store/cache/cache.go:92-94). The cache also runs cleanup every 5 minutes and caps at 1000 items (`store/store.go:42-43`).

So: no Redis; it's an in-memory `cache.Cache` configured in `store/store.go:40-53`, and user entries expire after 10 minutes.
