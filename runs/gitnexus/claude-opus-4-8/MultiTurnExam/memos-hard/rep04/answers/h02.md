**Delivery function** — `Post` in `internal/webhook/webhook.go` (the actual outbound HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`; `Post` is defined at line 120, and is invoked either synchronously or via the async worker pool feeding `PostAsync`/`asyncPostQueue`).

**Protection mechanism** — the shared `safeClient`'s custom `safeDialContext` transport in `internal/webhook/webhook.go:59` (wired at lines 32-37), which resolves the target host at dial time and rejects any address in a reserved/private range. That range check is `isReservedIP` backed by `reservedNetworks`/`reservedCIDRs` in `internal/webhook/validate.go:44` (CIDR list at lines 14-23, covering loopback, RFC-1918, IPv6 loopback/ULA/link-local, and the 169.254.169.254 cloud-IMDS link-local range). Because the guard runs at dial time after DNS resolution, it also defeats DNS-rebinding. There is an additional up-front check via `ValidateURL` (`validate.go:62`) when a webhook URL is created, but the enforced runtime protection on the delivery path is `safeDialContext` → `isReservedIP`.

Note: both checks can be globally disabled by the `AllowPrivateIPs` flag (`validate.go:41,45`) for self-hosted deployments that intentionally target local services.
