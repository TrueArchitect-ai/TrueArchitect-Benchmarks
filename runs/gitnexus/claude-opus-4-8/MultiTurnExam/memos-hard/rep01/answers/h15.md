Memo-visibility read enforcement is spread across these distinct server surfaces (all paths under `/bench/home/work`):

- GetMemo access check (`checkMemoVisibility`/inline gate) — server/router/api/v1/memo_service.go:55-65
- ListMemos visibility filtering (anonymous → PUBLIC only; authed non-owner → PUBLIC+PROTECTED) — server/router/api/v1/memo_service.go:219-227
- User stats memo filtering (same PUBLIC / PUBLIC+PROTECTED gating) — server/router/api/v1/user_service_stats.go:84-90, :218-220
- ListMemoComments — private parent viewable only by creator/superuser — server/router/api/v1/memo_service_comments.go:41
- Reaction viewing/listing gated by parent memo visibility — server/router/api/v1/reaction_service.go:30-38, :83
- Attachment binary API (`GetAttachmentBinary`) gated by parent memo visibility — server/router/api/v1/attachment_service.go:445-451
- Memo attachment listing gated by parent memo visibility — server/router/api/v1/memo_attachment_service.go:214-222
- File server attachment/media serving (`checkMemoVisibility`, incl. share-token fallback) — server/router/fileserver/fileserver.go:677, :699
- RSS feed restricted to PUBLIC memos — server/router/rss/rss.go:90, :141
- Frontend SSR/prerender restricted to PUBLIC memos — server/router/frontend/frontend.go:150
- SSE event delivery filter (`SSEClient.canReceive`) — server/router/api/v1/sse_hub.go:135-142
- Store query layer WHERE-clause on `visibility` (the `VisibilityList` filter that backs the above list queries) — store/db/sqlite/memo.go:96 (mirrored: store/db/postgres/memo.go:89, store/db/mysql/memo.go:104)

(Related visibility branches also exist in notification/mention paths — server/notification/email.go:313-316, server/router/api/v1/user_service_notifications.go:309-312, server/router/api/v1/memo_mention_helpers.go:62-84 — but those gate whether to notify/mention, not whether a requester may view a memo.)
