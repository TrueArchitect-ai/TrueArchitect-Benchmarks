**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` across all `.go` files returns zero matches — the cache layer is **not** backed by Redis and has no Redis connection to configure.

**Actual mechanism:** The cache is a process-local, in-memory implementation in `store/cache/cache.go` (a `*Cache` with an in-memory map, a size/`MaxItems` cap, and a background cleanup goroutine — no external store, no network connection). It's "configured" in Go code, not via a connection string:

- The store instantiates three of these caches (`instanceSettingCache`, `userCache`, `userSettingCache`) with a single `cache.Config` in `store.New` at `store/store.go:40-53`:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  (These defaults mirror `cache.DefaultConfig()` at `store/cache/cache.go:56`.)

**TTL for user entries:** User records are cached via `s.userCache.Set(...)` (e.g. `store/user.go:98, 122, 132, 143, 167`). `Set` applies the cache's default TTL — `Set → SetWithTTL(..., c.config.DefaultTTL)` at `store/cache/cache.go:93-95` — so user entries live for **10 minutes** (the `DefaultTTL` configured in `store/store.go:41`), with expired entries reaped by the cleanup pass every 5 minutes. No per-entry custom TTL is used for users.
