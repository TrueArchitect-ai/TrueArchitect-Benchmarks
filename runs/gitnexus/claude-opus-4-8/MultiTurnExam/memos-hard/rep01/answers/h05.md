**Mechanism: explicit Go code** (in the `DeleteUser` transaction), not a database-level cascade.

Evidence:

1. **No DB-level rule.** The `reaction` table declares `creator_id` as a plain `INTEGER/INT NOT NULL` with no foreign key and no `ON DELETE CASCADE` in any dialect:
   - `store/migration/sqlite/LATEST.sql:92-99`
   - `store/migration/postgres/LATEST.sql:91-98`
   - `store/migration/mysql/LATEST.sql:91-98`

2. **Explicit Go deletion.** Inside the user-deletion transaction, `deleteUserTargetsTx` explicitly runs `DELETE FROM reaction WHERE creator_id = ?` (removing reactions the user *authored*), and also deletes reactions *on the user's own memos* by content id:
   - `store/db/sqlite/user_delete.go:102` → `deleteReactionsByCreatorTx`, whose SQL is at `store/db/sqlite/user_delete.go:400-403` (`DELETE FROM reaction WHERE creator_id = ...`)
   - `store/db/sqlite/user_delete.go:96` → `deleteReactionsByContentIDsTx` (reactions on the deleted user's memos)
   - The same logic is mirrored for the other drivers in `store/db/postgres/user_delete.go` and `store/db/mysql/user_delete.go` (both define `deleteReactionsByCreatorTx` and are called from their `deleteUserTargetsTx`).

So a deleted user's emoji reactions are removed by explicit `DELETE` statements in the Go `DeleteUser` code path (per driver), all within the single delete-user transaction.
