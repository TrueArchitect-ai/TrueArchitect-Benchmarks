**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — nothing is registered, and there are no request limits to report.

Evidence:
- A repo-wide search for rate-limiting (`rate.?limit`, `ratelimit`, `throttle`, `limiter`, `golang.org/x/time/rate`, `tollbooth`) across all `.go` files finds no implementation. The only hit is an aspirational documentation comment, `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which describes a possible future enhancement for the email subsystem — not an HTTP/API middleware, and not per-user.
- The actual middleware/interceptor chain contains no rate limiter:
  - Echo HTTP server: only `middleware.Recover()` and `newCORSMiddleware(...)` are registered — `server/server.go:51-52` (CORS defined in `server/cors.go`).
  - Connect/gRPC API: the interceptor stack is Metadata → Logging → Recovery → Auth only — `server/router/api/v1/v1.go:133-137`; the gRPC-Gateway path adds only an auth middleware — `server/router/api/v1/v1.go:69, 97`.

The closest existing request-size/abuse control is a body-size cap (`connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`), but that is a per-request byte limit, not a per-user request-rate limit. So the described middleware and its "request limits" do not exist.
