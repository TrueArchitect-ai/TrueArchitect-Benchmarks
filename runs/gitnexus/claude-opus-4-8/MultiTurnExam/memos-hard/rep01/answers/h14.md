The UpdateMemo trigger fires only when `content` is in the update mask (`memo.Content = request.Memo.Content` immediately precedes it). I have the full picture.

h14.

**Computation site** — `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which calls the markdown service's single-pass extractor `(*service).ExtractAll` (`internal/markdown/markdown.go:356`) and writes the result onto `memo.Payload.Tags` and `memo.Payload.Property` (`server/runner/memopayload/runner.go:85-86`). The derived data lives in the memo's `Payload` (proto `storepb.MemoPayload`), not in any user-set field.

**Triggers (recomputation)** — the RPC handlers that create or change memo *content*:
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (on every create).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the branch that applies a new `content` value (`memo.Content = request.Memo.Content` at line 446, i.e. when `content` is in the update mask). Handlers that change only relations/attachments (`SetMemoRelations`, `SetMemoAttachments`) do **not** recompute it, since content is unchanged.
- A batch backfill path also exists — `memopayload.Runner.RunOnce` → `RebuildMemoPayload` (`server/runner/memopayload/runner.go:52`) — but that runner is not wired into production startup (it's unused; only the free function `RebuildMemoPayload` is called from the handlers).

**Extracted properties** — `ExtractAll` walks the goldmark AST once and derives:
- `Tags` — the list of `#tag` hashtags found in the content (`internal/markdown/markdown.go:377`).
- `Property` (`storepb.MemoPayload_Property`, fields at `proto/gen/store/memo.pb.go:87-90`):
  - `HasLink` — content contains a link (`markdown.go:394`)
  - `HasCode` — contains a code block/fenced block/inline code span (`markdown.go:396-397`)
  - `HasTaskList` — contains a task checkbox (`markdown.go:399-400`)
  - `HasIncompleteTasks` — contains at least one unchecked task checkbox (`markdown.go:401-404`)
  - `Title` — text of a leading H1 heading, if the first block is one (`markdown.go:387`)
  
  (It also collects `Mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property` onto the memo.)
