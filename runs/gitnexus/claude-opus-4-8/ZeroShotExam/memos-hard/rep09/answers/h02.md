**Delivery function** — `Post()` in `internal/webhook/webhook.go` (defined ~line 119; the request actually goes out at `safeClient.Do(req)`, `internal/webhook/webhook.go:152`). All dispatches — including the async worker path via `PostAsync` — funnel through this same `Post`/`safeClient`.

**Protection mechanism** — `internal/webhook/validate.go`

The core defense that guards the actual delivery is enforced at **dial time**: the shared `safeClient` uses `safeDialContext` as its transport `DialContext` (`internal/webhook/webhook.go:32-37`, `59-77`). On every connection it resolves the target host and rejects any IP that `isReservedIP` matches — which also defeats DNS-rebinding, since the check happens at connect time, not just at validation time.

The blocklist and predicate live in `internal/webhook/validate.go`:
- `reservedCIDRs` / `reservedNetworks` — the blocked ranges: loopback, RFC-1918 private, `169.254.0.0/16` (link-local + cloud IMDS), and IPv6 equivalents (`validate.go:14-36`)
- `isReservedIP()` — membership check, shared by both the dialer and the validator (`validate.go:44-54`)
- `ValidateURL()` — up-front create/update-time validator requiring an absolute http/https URL that doesn't resolve to a reserved IP (`validate.go:62-83`)
- `AllowPrivateIPs` — opt-out flag that disables the protection for self-hosted/local-network deployments (`validate.go:41`)

So there are two layers: `ValidateURL` rejects bad URLs when a webhook is configured, and `safeDialContext` re-checks at the moment of delivery.

**Answer:** delivery function — `Post` (via `safeClient.Do`) in `internal/webhook/webhook.go`; protection mechanism — dial-time `safeDialContext` in `internal/webhook/webhook.go` backed by `isReservedIP`/`reservedCIDRs` (and create-time `ValidateURL`) in `internal/webhook/validate.go`.
