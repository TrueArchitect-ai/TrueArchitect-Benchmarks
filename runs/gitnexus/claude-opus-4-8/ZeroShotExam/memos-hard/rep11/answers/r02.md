**Premise correction:** The question assumes this repository has per-user API rate-limiting middleware. It does not. There is **no request-rate-limiting middleware of any kind** — per-user or global — anywhere in the codebase. An exhaustive search for rate-limit / throttle / limiter / token-bucket patterns across all Go files turns up zero implementations. Consequently there is no registration site and no request limits to report.

What actually exists:

- **The only rate-limit references are non-code.** A doc comment at `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") and a *suggested future* snippet in `internal/email/README.md:286-295` (`rate.NewLimiter(...)`). Neither is wired into anything. `golang.org/x/time` appears in `go.mod:151` but only as an `// indirect` transitive dependency.

- **The only request guard is a size cap, not a rate limit:** `maxAPIRequestBytes = 256 << 20` (256 MB body cap) at `server/router/api/v1/v1.go:20`, applied at lines 126/141/144. That limits payload size, not request frequency.

- **The middleware/interceptors that *are* registered** (none rate-limiting):
  - Connect RPC interceptor chain — `server/router/api/v1/v1.go:133-138`: Metadata → Logging → Recovery → Auth (defined in `connect_interceptors.go`).
  - gRPC-Gateway middleware — `v1.go:96-98`: `gatewayAuthMiddleware` (auth only).
  - Echo HTTP middleware — `server/server.go:51-52`: `middleware.Recover()` and `newCORSMiddleware`.

If per-user rate limiting were to be added, the natural insertion point would be a new interceptor in the `connect.WithInterceptors(...)` chain at `v1.go:133-138`, keyed on the identity that the auth interceptor places in the context — but as of now, no such middleware and no such limits exist.
