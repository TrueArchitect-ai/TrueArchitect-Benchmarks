**Premise correction:** There is no Redis anywhere in this repository. A search for `redis` across all source and config files returns zero matches. The "memos" project (Go backend + React frontend) uses an **in-process, in-memory cache**, not a Redis-backed cache layer — there's no external cache server or connection string to configure.

**Actual mechanism:**

The cache layer is a thread-safe in-memory cache implemented in Go at `store/cache/cache.go` (`type Cache struct`, backed by a map with a background cleanup goroutine — no network connection of any kind).

It's configured in `store/store.go:39-53`, inside `Store.New()`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

That single config is shared by three separate cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`, `51-53`).

**TTL for user entries:** User records are stored via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 143, 167). `Set` applies the cache's `DefaultTTL` (it delegates to `SetWithTTL` with `c.config.DefaultTTL` at `store/cache/cache.go:92-95`), and no user code path uses a custom TTL. So **user entries expire after the default 10 minutes**, with stale entries reaped by the cleanup goroutine running every 5 minutes.
