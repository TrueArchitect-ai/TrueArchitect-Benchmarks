Notes:
- The stored avatar is a base64 data URI kept in the `user.avatar_url` column. After the DB read, the handler decodes it in-process via `parseDataURI` (fileserver.go:737) and writes the bytes with `c.Blob` (fileserver.go:209) — no separate blob/file store is involved for avatars.
- `GetUser` first checks `s.userCache` but only for lookups by ID; this path looks up by username, so it falls through to `ListUsers` → driver every time (though the row gets cached by ID afterward).
- Driver shown is SQLite; equivalent `ListUsers` implementations exist in `store/db/postgres/user.go` and `store/db/mysql/user.go` depending on configured backend.
