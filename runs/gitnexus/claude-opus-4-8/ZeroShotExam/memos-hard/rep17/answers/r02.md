**Premise correction:** The question assumes this repository has a per-user API rate-limiting middleware that is registered somewhere. It does not. Memos (this Go backend) has **no rate-limiting of any kind** — not per-user, not per-IP, not global.

The complete middleware/interceptor chain is:

- **Echo HTTP middleware** — `server/server.go:51-52`: only `middleware.Recover()` (panic recovery) and `newCORSMiddleware(profile)` (CORS).
- **Connect RPC interceptors** — `server/router/api/v1/v1.go:133-137`: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`). None of these count, throttle, or limit requests.

No rate-limiting library is even a dependency (no `golang.org/x/time/rate`, `tollbooth`, `throttled`, etc. in `go.mod`), and nothing returns HTTP 429 / `CodeResourceExhausted` for throttling.

Two things that might be mistaken for the premise but aren't:

- **A request-body size cap** (not a rate limit) at `server/router/api/v1/v1.go:20`: `const maxAPIRequestBytes = 256 << 20` (256 MB), enforced via `http.MaxBytesHandler` / `connect.WithReadMaxBytes` (`v1.go:126, 141, 144`). This limits the size of a single request, not request frequency.
- **Aspirational docs only** in the email package — `internal/email/doc.go:86` and `internal/email/README.md:286-295` mention/illustrate rate limiting, but no such code is implemented.

So there is no middleware to point to and no request limits to report; if per-user rate limiting is required, it would have to be built from scratch.
