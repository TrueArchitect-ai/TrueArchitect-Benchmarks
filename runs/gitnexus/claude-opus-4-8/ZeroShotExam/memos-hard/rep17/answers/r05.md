**Premise correction:** memos does not have a GraphQL API — there is no GraphQL schema anywhere in the repository. A recursive, case-insensitive search for `graphql` across the tree returns zero matches. The question's premise is mistaken.

**Actual API surface:** The public API is defined as **Protocol Buffers (gRPC / Connect-RPC, with a REST/JSON gateway)**, not GraphQL. The schema lives in:

- `proto/api/v1/` — the public v1 API service and message definitions, one `.proto` file per service:
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/common.proto`
- `proto/store/` — internal persistence/storage message schemas (not the public surface).

Code is generated from these via **buf** (`proto/buf.gen.yaml`, `proto/buf.yaml`), producing Go bindings under `proto/gen/` and TypeScript types under `web/src/types/proto`. The generated plugins (`protocolbuffers/go`, `grpc/go`, `connectrpc/go`, `grpc-ecosystem/gateway`, and `google-gnostic-openapi`) confirm the transport is gRPC/Connect plus a REST gateway with an OpenAPI description (`proto/openapi_embed.go`) — again, no GraphQL layer.

So the correct place to look for "the API schema" is `proto/api/v1/*.proto`.
