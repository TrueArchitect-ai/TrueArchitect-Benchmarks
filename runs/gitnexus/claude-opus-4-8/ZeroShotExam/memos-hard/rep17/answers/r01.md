**Premise correction:** There is no Redis anywhere in this project. A full search for `redis`/`go-redis`/`redigo`/`rueidis` across the `.go` sources, `go.mod`, and `go.sum` returns nothing, and `go.mod` pulls in no external cache library at all (no ristretto/groupcache/golang-lru/bigcache/memcache). So there is no "Redis connection for the cache layer" to configure — the question's premise is mistaken.

**Actual mechanism:** The cache is a hand-written, thread-safe, in-memory TTL cache.

- Implementation: `store/cache/cache.go` — backed by a `sync.Map` with an `atomic.Int64` item counter. Each entry is an `item{value, expiration time.Time, size}`. A background `cleanupLoop` goroutine evicts expired entries, `Get` also lazily evicts on access, and when `MaxItems` is exceeded `cleanupOldest` drops ~20% of the oldest entries (a rough expiration-ordered eviction, not a true LRU).
- Wiring: `store/store.go` creates three separate cache instances on the `Store` struct — `instanceSettingCache`, `userCache`, `userSettingCache` — each via `cache.New(cacheConfig)` (`store/store.go:51-53`), closed in `Store.Close()`.

**TTL for user entries:** There is no user-specific TTL. The user cache inherits the store-wide default config defined inline in `store/store.go:40-45`:
- `DefaultTTL: 10 * time.Minute` (`store/store.go:41`)
- `CleanupInterval: 5 * time.Minute` (line 42)
- `MaxItems: 1000` (line 43)

That config is passed to `userCache: cache.New(cacheConfig)` (`store/store.go:52`). All user writes in `store/user.go` (lines 98, 122, 132, 143, 167) use the plain `Set`, which delegates to `SetWithTTL` with the default TTL (`store/cache/cache.go:93-95`), stamping `expiration: time.Now().Add(ttl)` (`cache.go:112`). Invalidation on delete happens via `deleteUserCache` → `s.userCache.Delete` (`store/user_delete.go:39-40`).

**Bottom line:** User cache entries live in an in-process `sync.Map`-based cache and expire **10 minutes** after being set (`store/store.go:41`), enforced by lazy eviction in `Get` plus the 5-minute background cleanup loop — no Redis, and no per-user TTL override.
