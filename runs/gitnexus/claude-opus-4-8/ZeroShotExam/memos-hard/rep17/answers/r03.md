The premise is mistaken — there is **no nightly database-cleanup job scheduled in any cron scheduler** in this repository, so there is no scheduled run time to report.

What actually exists:

- A standalone cron scheduler **library** lives at `internal/scheduler/` (`scheduler.go`, `job.go`, `parser.go`, etc.), but it is **never imported or instantiated** anywhere in the application (`server/`, `cmd/`, `internal/`, `web/`). No jobs are registered against it — it is effectively unused library code exercised only by its own tests.

- The closest thing to a "database cleanup" schedule is an **illustrative doc-comment example**, not a real job: `internal/scheduler/doc.go:14-18` shows a hypothetical `"daily-cleanup"` job with cron `"0 2 * * *"` (2 AM daily). This is documentation, not a registered job.

- The only genuinely live scheduled task in the repo is a CI workflow — `.github/workflows/stale.yml:4-5` runs the stale-issues bot on `cron: "0 */8 * * *"` (every 8 hours). It has nothing to do with database cleanup.

- Actual "cleanup" logic in the app (`server/router/api/v1/user_service.go:421-450`, `memo_service.go:579`) is synchronous attachment/storage cleanup during deletion requests — not scheduled.

So if someone cited "2 AM," they were reading the `doc.go` example; that is not a running scheduled job.
