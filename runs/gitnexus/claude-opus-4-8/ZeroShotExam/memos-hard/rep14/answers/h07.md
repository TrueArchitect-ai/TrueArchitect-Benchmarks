**Where the data lives / final serve:** the avatar is stored inline as a base64 data URI in the `user.avatar_url` column, read into `store.User.AvatarURL`. Back in the handler, `FileServerService.parseDataURI` (server/router/fileserver/fileserver.go:737) decodes it and `c.Blob(...)` (fileserver.go:209) writes the bytes to the browser.

Note: for *another* user's image, permission is gated only by instance-level anonymity — on a private instance `getCurrentUser`/`authenticator.AuthenticateToUser` (fileserver.go:708) must resolve a viewer; there's no per-target authorization, so any authenticated (or, on a public instance, anonymous) request can fetch any username's avatar.
