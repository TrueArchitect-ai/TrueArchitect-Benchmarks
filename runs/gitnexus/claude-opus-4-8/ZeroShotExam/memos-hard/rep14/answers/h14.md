**Computation site**

The derived metadata is the memo's `Payload.Property` (a `MemoPayload_Property` proto: used for list/preview rendering — link/code/task badges, title). It's populated by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual content parsing to the markdown service's `ExtractAll` in `internal/markdown/markdown.go:356`. `RebuildMemoPayload` assigns both `memo.Payload.Property` and `memo.Payload.Tags` from the extracted data (`runner.go:85-86`).

**Triggers (recomputation)**

- **Create** — `CreateMemo` calls it before persisting (`server/router/api/v1/memo_service.go:108`).
- **Update** — `UpdateMemo` recomputes only when the `content` field is in the update mask (`server/router/api/v1/memo_service.go:447`).
- **Batch backfill** — the background `Runner.RunOnce` rebuilds the payload for every memo in 100-memo batches (`server/runner/memopayload/runner.go:27-72`).

**Extracted properties**

`ExtractAll` does a single AST walk (`internal/markdown/markdown.go:371-411`) and extracts into `MemoPayload_Property`:
- `HasLink` — any link node (`markdown.go:394`)
- `HasCode` — any code block/fenced code/code span (`markdown.go:397`)
- `HasTaskList` — any task-checkbox node (`markdown.go:400`)
- `HasIncompleteTasks` — a task checkbox that is unchecked (`markdown.go:402-403`)
- `Title` — text of the first block-level child if it's an H1 heading (`markdown.go:384-388`)

The same pass also fills `ExtractedData.Tags` (deduped, case-preserved) and `Mentions`, of which `RebuildMemoPayload` writes `Tags` onto the payload alongside `Property`.
