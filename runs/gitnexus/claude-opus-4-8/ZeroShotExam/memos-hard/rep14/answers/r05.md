**Premise correction:** memos does not expose a GraphQL API, so there is no GraphQL schema to point to. A repo-wide search for `graphql` turns up zero matches in Go, TypeScript, or proto sources (`proto/api/v1/README.md` is the only file naming it, and only to say the API is proto-defined). The question's premise is incorrect.

**Actual API surface — gRPC + gRPC-gateway (REST/JSON), defined in Protocol Buffers:**

The public API "schema" lives in the `.proto` service definitions under `proto/api/v1/`, including:
- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto`

Supporting pieces:
- `proto/buf.yaml` / `proto/buf.gen.yaml` — buf config that compiles these protos.
- `proto/gen/api/` — generated Go stubs; `web/src/types/proto/api/` — generated TypeScript types for the frontend client.
- REST access is provided via gRPC-gateway HTTP annotations on the same protos, with an **OpenAPI** document embedded through `proto/openapi_embed.go`.
- Server-side handlers implementing these services are in `server/router/api/`.

So the public API is proto-defined gRPC services (with a REST/OpenAPI gateway), not GraphQL.
