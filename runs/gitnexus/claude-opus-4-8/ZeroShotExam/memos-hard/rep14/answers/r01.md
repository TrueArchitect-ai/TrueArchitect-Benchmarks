**Premise correction:** There is no Redis anywhere in this repository. `memos` is a Go application (`go.mod`), and its cache layer is a **thread-safe in-memory cache**, not a Redis-backed one. `grep` for `redis` returns zero hits, and `go.mod` declares no Redis/cache client dependency. So "where is the Redis connection configured" has no answer because no such connection exists.

**Actual mechanism:**

- The cache implementation lives in `store/cache/cache.go` — a `sync.Map`-based store (`Cache` struct, `store/cache/cache.go:66-73`) with per-item expiration, a background cleanup goroutine (`cleanupLoop`, line 200), and a max-item eviction policy. No network connection, no external store.
- It is "configured" (not connected) in `store/store.go:38-58`. `Store.New` builds a single `cache.Config` and instantiates three separate in-memory caches, one of which is `userCache` (`store/store.go:28,52`):
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
  }
  ```
- **TTL for user entries: 10 minutes.** User records are written via `s.userCache.Set(...)` (store/user.go:98, 122, 132, 143, 167). `Set` applies `c.config.DefaultTTL` (`store/cache/cache.go:92-95`) — there is no `SetWithTTL` override for users — so user entries inherit the `DefaultTTL` of `10 * time.Minute` set in `store/store.go:41`. Expired entries are lazily dropped on `Get` and swept every 5 minutes by the cleanup loop.

The same default config is shared by `instanceSettingCache` and `userSettingCache`, so the 10-minute TTL applies to all three caches, not just users.
