h15.

Memo visibility enforcement for **viewing** a memo is spread across several distinct server surfaces. The canonical checks and the surfaces that independently gate read access are:

Single-memo read gate (`checkMemoReadAccess`: archived→creator only, non-PUBLIC→auth required, PRIVATE→creator only; used by GetMemo, comment parent lookup, ListMemoComments) — server/router/api/v1/memo_service.go
ListMemos visibility filter (anon→[PUBLIC]; self→creator filter; other user→[PUBLIC,PROTECTED] via CEL) — server/router/api/v1/memo_service.go
Store SQL WHERE builder (`VisibilityList` → `memo.visibility in (...)`, the actual DB-level filter) — store/db/sqlite/memo.go, store/db/postgres/memo.go, store/db/mysql/memo.go
RSS feed filter (hard-codes VisibilityList=[PUBLIC] for instance and per-user feeds) — server/router/rss/rss.go
File server blob authorization (`checkAttachmentPermission`: PUBLIC/anon-allowed, else share_token, else auth; PRIVATE→creator/admin) — server/router/fileserver/fileserver.go
ListMemoComments related-memo filter (`memoFilter` applied to ListMemoRelations) — server/router/api/v1/memo_service_comments.go
Reaction service read gate (ListMemoReactions/UpsertMemoReaction: non-PUBLIC→auth, PRIVATE→creator/super-user) — server/router/api/v1/reaction_service.go
Attachment service memo-visibility gate — server/router/api/v1/attachment_service.go
Memo-attachment list gate (SetMemoAttachments / list attachments) — server/router/api/v1/memo_attachment_service.go
Memo relations converter filter (`batchConvertMemoRelations` strips non-visible linked memos) — server/router/api/v1/memo_service_converter.go
AddMemoRelations relation-target filter — server/router/api/v1/memo_relation_service.go
User stats visibility filters (ListMemoStats / per-user stats) — server/router/api/v1/user_service_stats.go

The three primary/canonical sites are the first three (single-memo `checkMemoReadAccess`, `ListMemos` filter, and the store SQL `visibility in (...)` builder); the remaining rows are additional surfaces that independently apply the same visibility rules.

Note: `GetMemoByShare` in server/router/api/v1/memo_share_service.go **deliberately bypasses** visibility enforcement — a valid share token grants read access regardless of visibility.
