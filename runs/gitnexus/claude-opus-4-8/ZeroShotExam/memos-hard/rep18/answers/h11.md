**1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages)**

The data layer is the `store/` package (`/bench/home/work/store/`), where persistent entity types are defined as structs — `User` (`store/user.go`), `Memo` (`store/memo.go`), `Attachment`, `Inbox`, `Reaction`, `IdentityProvider`, `MemoRelation`, `MemoShare`, `UserSetting`, `UserIdentity`, `InstanceSetting`.

Counting distinct packages *outside* the `store/` tree that reference each type (via `store.<Type>`):

| Type | Outside packages |
|------|------|
| **User** | **7** |
| **Memo** | **6** |
| Attachment | 4 |
| Inbox / MemoRelation / MemoShare | 3 |
| Reaction / UserIdentity | 2 |

`store.User` is referenced from 7 non-data-layer packages: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`.

`store.Memo` follows with 6: `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`.

(Note: matches under `store/db/{sqlite,mysql,postgres}` and `store/test` were excluded as part of the data layer itself.)
