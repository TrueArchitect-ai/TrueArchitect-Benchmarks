**Computation site.** The derived metadata lives in each memo's `Payload.Property` (`storepb.MemoPayload_Property`, defined in `proto/gen/store/memo.pb.go:85`). It is populated by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which calls the goldmark-based `markdownService.ExtractAll` and assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (lines 85–86). The actual extraction happens in `service.ExtractAll` at `internal/markdown/markdown.go:356`, which parses the memo `Content` into an AST and walks it once to compute the property fields.

**Triggers (what causes recomputation).** Anything that (re)builds a memo's payload from its content:
- **Create** — `CreateMemo` calls `RebuildMemoPayload` at `server/router/api/v1/memo_service.go:108`.
- **Update** — `UpdateMemo` calls it at `server/router/api/v1/memo_service.go:447` (in the `content`-field branch, after setting `memo.Content = request.Memo.Content`), i.e. only when the memo's content is changed.
- **Batch backfill** — the `memopayload.Runner.RunOnce` job (`server/runner/memopayload/runner.go:27`) iterates all memos in batches of 100, rebuilds each payload, and persists via `UpdateMemo`.

**Extracted properties.** From the single AST walk in `ExtractAll` (`internal/markdown/markdown.go:371-421`), the `Property` message gets:
- `Title` — text of the document's first block-level child if it is an H1 heading (`markdown.go:384-388`).
- `HasLink` — true if any `KindLink` node exists (line 394).
- `HasCode` — true for any code block / fenced code block / code span (line 397).
- `HasTaskList` — true if any task-checkbox node exists (line 400).
- `HasIncompleteTasks` — true if any task checkbox is unchecked (lines 401-404).

(The same pass also fills `Payload.Tags` from `#tag` nodes and `Mentions`, but the derived preview/list metadata proper is the `Property` struct above.)
