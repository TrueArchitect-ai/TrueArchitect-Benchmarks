**Premise correction:** memos does not expose a GraphQL API — there is no GraphQL schema (SDL) anywhere in the repo (no `.graphql` files, no schema-first resolver setup). The premise that the public API is GraphQL is incorrect.

**Actual API surface:** The public API is defined **protobuf-first** as gRPC services under `proto/api/v1/`. Each service has its own `.proto` file:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto`

Codegen is driven by Buf (`proto/buf.gen.yaml`, `proto/buf.yaml`). From these `.proto` definitions Buf generates, into `proto/gen/`:
- Go gRPC + **Connect** stubs (`proto/gen/api/v1/apiv1connect/`)
- a **gRPC-Gateway** (REST/HTTP JSON transcoding) layer
- an **OpenAPI** document (via the gnostic-openapi plugin), embedded through `proto/openapi_embed.go`
- TypeScript client types for the web frontend (`web/src/types/proto/api/`)

The services are wired up server-side under `server/router/api/`.

So the "schema" for the public API is the set of protobuf service definitions in `proto/api/v1/*.proto`, surfaced at runtime over gRPC, Connect, and a REST/OpenAPI gateway — not GraphQL.
