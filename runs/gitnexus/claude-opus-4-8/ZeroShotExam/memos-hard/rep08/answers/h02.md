**Delivery function** — `Post` at `internal/webhook/webhook.go:119-180`. This is where the outbound HTTP POST actually executes: it marshals the payload, builds the request (optionally HMAC-signing it), and fires it via `safeClient.Do(req)` (line 152). It's driven asynchronously by a worker pool in `init()` pulling off `asyncPostQueue`, enqueued by `PostAsync` (same file).

**Protection mechanism** — `safeDialContext` at `internal/webhook/webhook.go:59-77`, installed as the `DialContext` of the shared `safeClient`'s transport (lines 32-37). At connection time it resolves the target host and rejects any address in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44-54`), which checks against the `reservedCIDRs` list — loopback, RFC-1918, link-local/cloud-IMDS `169.254.169.254`, and IPv6 equivalents (`internal/webhook/validate.go:14-23`). Because the check happens at *dial* time on the actually-resolved IP, it also defeats DNS-rebinding.

Two supporting notes:
- A second, earlier check `ValidateURL` (`internal/webhook/validate.go:62-83`) validates the URL scheme and rejects reserved-IP resolution when a webhook is *registered/configured* (returns a gRPC `InvalidArgument`). The dial-time guard in `Post` is the one that protects the actual delivery.
- Both checks can be disabled via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:38-41`), intended for self-hosted deployments targeting local-network services.
