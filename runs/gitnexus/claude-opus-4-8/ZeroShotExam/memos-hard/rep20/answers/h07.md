h07.

A browser `GET /file/users/:identifier/avatar` is routed and served entirely by the fileserver, which resolves the target user through the store and returns the avatar bytes decoded from that user's `avatar_url` column (stored as a data URI, not a separate file).

Route registered at `server/router/fileserver/fileserver.go:124` (`fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)`).

Hops from serving handler to stored data:

serveUserAvatar — server/router/fileserver/fileserver.go:168
getUserByUsername — server/router/fileserver/fileserver.go:714
Store.GetUser — store/user.go:148
Store.ListUsers — store/user.go:135
driver.ListUsers (interface) — store/driver.go:46
DB.ListUsers (SQL `SELECT … avatar_url … FROM user`) — store/db/sqlite/user.go:88 (equivalently store/db/postgres/user.go:86, store/db/mysql/user.go:83)

The stored value is `User.AvatarURL` (`store/user.go`), a `data:` URI. Back in the handler, `serveUserAvatar` calls `parseDataURI` (`server/router/fileserver/fileserver.go`) to split it into type + bytes and writes them via `c.Blob` (fileserver.go:196–209). Note: the identifier is looked up purely by username, so any user's avatar is reachable this way (subject only to the anonymous-access check at fileserver.go:173–181 on private instances).
