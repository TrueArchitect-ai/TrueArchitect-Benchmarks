**Computation site** — The content-derived metadata lives in a memo's `Payload.Property` field. It is populated by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`, which delegates the actual work to the markdown service's AST walk `(*service).ExtractAll` in `internal/markdown/markdown.go:355-420` (property switch at lines 391-408). `RebuildMemoPayload` calls `markdownService.ExtractAll([]byte(memo.Content))` and assigns `memo.Payload.Tags`/`memo.Payload.Property`.

**Triggers** — `RebuildMemoPayload` runs on:
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447` (only in the `content` update-mask branch, i.e. when content actually changes)
- The batch backfill runner `Runner.RunOnce` — `server/runner/memopayload/runner.go:52` (rebuilds all memos' payloads in batches and re-persists)

**Extracted properties** — By parsing the content into a goldmark AST and walking nodes, it derives (`MemoPayload_Property`, `proto/gen/store/memo.pb.go:84-95`):
- `HasLink` (from link nodes)
- `HasCode` (code block / fenced code block / code span)
- `HasTaskList` (task checkbox present)
- `HasIncompleteTasks` (an unchecked task checkbox)
- `Title` (text of the first block child if it is an H1 heading)

In the same AST pass `ExtractAll` also collects sibling payload fields `Tags` (`#tag`) and `Mentions` (`@user`), though `RebuildMemoPayload` only writes `Tags` and `Property` back into the payload.
