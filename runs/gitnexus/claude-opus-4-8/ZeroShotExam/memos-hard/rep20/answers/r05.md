**Premise correction:** memos does not expose a GraphQL API, so there is no GraphQL schema to point to. A search for `graphql` across the source (excluding `node_modules`/build output) returns nothing.

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC**, using Connect-Go (gRPC + gRPC-Web + REST/HTTP) rather than GraphQL.

- **Schema (source of truth):** `proto/api/v1/*.proto` — one file per service:
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/common.proto`
- **Build config:** `proto/buf.yaml`, `proto/buf.gen.yaml`, `proto/buf.lock`
- **Generated code:** `proto/gen/api/v1/` (Go types/service stubs)
- **Generated OpenAPI (the REST-facing spec):** embedded via `proto/openapi_embed.go`
- **Server-side implementations of the schema:** `server/router/api/v1/` (e.g. `connect_services.go`, `memo_service_comments.go`, `ai_service.go`), wired up in `server/server.go`.

So the closest analog to "the schema for the public API" is the protobuf definitions under `proto/api/v1/`, exposed at runtime over gRPC/Connect and REST — not GraphQL.
