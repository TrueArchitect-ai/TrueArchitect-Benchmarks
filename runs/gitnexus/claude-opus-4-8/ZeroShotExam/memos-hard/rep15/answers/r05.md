**Premise correction:** memos does not define — or use — a GraphQL schema. There is no GraphQL server, schema file, or resolver anywhere in the codebase (a repo-wide search for `graphql` returns zero matches in `.go`/`.proto`/`.ts` sources). So there is no "GraphQL schema for the public API" to point to.

**Actual API surface:** The public API is defined with **Protocol Buffers (gRPC + gRPC-gateway REST + OpenAPI)**, not GraphQL. The schema of record lives in:

- `proto/api/v1/` — the public API service/message definitions, one `.proto` per service:
  - `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `instance_service.proto`, `ai_service.proto`, and `common.proto`
- `proto/buf.yaml` / `proto/buf.gen.yaml` — the buf build/codegen config (deps include `buf.build/googleapis/googleapis`)
- `proto/gen/` — generated code (gRPC stubs, gateway, OpenAPI)
- `proto/openapi_embed.go` — embeds the generated OpenAPI spec
- `proto/store/` — internal storage-layer protobufs (not the public API surface)

REST endpoints are exposed via grpc-gateway annotations on those service definitions, so the `.proto` files under `proto/api/v1/` are the single source of truth for the public API.
