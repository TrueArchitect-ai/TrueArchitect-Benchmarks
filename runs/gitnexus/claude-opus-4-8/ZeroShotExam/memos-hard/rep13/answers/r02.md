**Premise correction: this repository (memos) has no per-user API rate-limiting middleware.** There is nothing to register and no configured request limits, so the question's premise is false.

What I verified:

- A strict search for rate-limiting terms (`rate-limit`, `ratelimit`, `throttl`, `golang.org/x/time/rate`, `tollbooth`, `limiter`) across the non-generated source turns up **zero** actual implementation. The only matches are aspirational docs, not code:
  - `internal/email/doc.go:86` — a doc comment listing "Rate limit email sending to prevent abuse" as a *suggestion*.
  - `internal/email/README.md:286-296` — a "### 5. Implement Rate Limiting" section with example `golang.org/x/time/rate` code (10 emails/sec) presented as a *future improvement*, not wired into anything.

- The actual server middleware/interceptor chain is registered in `server/router/api/v1/v1.go:133-138` via `connect.WithInterceptors(...)`, and it contains exactly four interceptors, none of them a rate limiter:
  1. `NewMetadataInterceptor()` — HTTP headers → gRPC metadata
  2. `NewLoggingInterceptor(...)` — request logging
  3. `NewRecoveryInterceptor(...)` — panic recovery
  4. `NewAuthInterceptor(authorizer)` — authentication / anonymous-access policy

  These are all defined in `server/router/api/v1/connect_interceptors.go`. The only other HTTP middleware is CORS (`server/cors.go`).

So there is no per-user (or global) request-rate limiting layer in this codebase, and consequently no request limits to report. If you were expecting one, it would need to be added — the email README sketch is the closest thing to a starting point, but it concerns outbound email, not the API.
