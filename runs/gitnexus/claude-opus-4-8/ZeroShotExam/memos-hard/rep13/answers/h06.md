**RPC handler methods** (all on `APIV1Service`, in `server/router/api/v1/`) that can transitively trigger an outbound HTTP request to a user-configured webhook URL:

1. **`CreateMemo`** — `memo_service.go:157` → `DispatchMemoCreatedWebhook`
2. **`DeleteMemo`** — `memo_service.go:562` → `DispatchMemoDeletedWebhook`
3. **`UpdateMemo`** — `memo_service.go:513` → `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:67`) → `DispatchMemoUpdatedWebhook`
4. **`CreateMemoComment`** — `memo_service_comments.go:119` → `DispatchMemoCommentCreatedWebhook`
5. **`SetMemoAttachments`** (`memo_attachment_service.go:48`) and **`SetMemoRelations`** (`memo_relation_service.go:48`) — both also route through `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`

Each `Dispatch*` method loads the creator's webhooks via `Store.GetUserWebhooks`, sets `payload.URL = hook.Url` (the user-configured URL), and calls `webhook.PostAsync`, which enqueues to a worker pool.

**Convergence function** — `Post` — `internal/webhook/webhook.go:120`

All paths funnel through `Post`: the async workers started in `init()` drain the queue and call `Post` (`webhook.go:46`), which is the single function that marshals the payload, builds the request to `requestPayload.URL`, and actually performs the network call via `safeClient.Do(req)` (`webhook.go:152`).
