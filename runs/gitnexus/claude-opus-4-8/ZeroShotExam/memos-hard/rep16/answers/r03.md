The question's premise is mistaken: there is **no nightly database-cleanup job scheduled in any cron scheduler** in this repository, so there is no scheduled time to report.

What actually exists:

- A general-purpose cron scheduler package lives at `internal/scheduler/` (`scheduler.go`, `job.go`, `parser.go`, etc.), but it is **dead code** — no production code (`cmd/`, `server/`) ever imports, instantiates, or registers a job on it. The only `scheduler.New`/`Register` calls are commented-out examples in `internal/scheduler/doc.go`.
- The closest textual match to your question is a **documentation example**, not a running job: a commented-out sample job named `"daily-cleanup"` with cron expression `"0 2 * * *"` (2 AM daily) in `internal/scheduler/doc.go:15`. This is illustrative sample code, not a scheduled task, and it is a cache/generic example — not a database cleanup.
- The only periodic cleanup that genuinely runs is **in-memory cache eviction every 5 minutes** via a `time.Ticker` in `store/cache/cache.go` (`cleanupLoop()` at line 200; default `CleanupInterval: 5 * time.Minute`). It is not cron-driven, not nightly, and does not touch the database.
- Other "cleanup" logic (attachment/storage cleanup in `store/attachment.go` and `server/router/api/v1/user_service.go`; provisional-user cleanup in `server/router/api/v1/auth_service_sso.go:76`) runs **on-demand** during delete operations, not on a schedule.

So: no nightly DB-cleanup cron job exists. The `"0 2 * * *"` you may have heard of is a commented-out doc example in `internal/scheduler/doc.go`, not a live scheduled job.
