When a user is deleted, `DeleteUser` runs a transaction whose `deleteUserTargetsTx` explicitly deletes reactions two ways:
- `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?` (reactions the deleted user made)
- `deleteReactionsByContentIDsTx` — `DELETE FROM reaction WHERE content_id IN (...)` (reactions others left on the deleted user's memos)

This is implemented identically across all three drivers. The `reaction` table has no foreign key / `ON DELETE CASCADE` on `creator_id` (it's a plain `INTEGER NOT NULL` column with only a `UNIQUE` constraint), so the database does nothing on its own — the Go code is what does the cleanup.
