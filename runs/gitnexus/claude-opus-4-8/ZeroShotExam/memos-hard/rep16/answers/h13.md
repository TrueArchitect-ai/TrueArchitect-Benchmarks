**Markdown processing sits behind the `markdown.Service` interface** (`internal/markdown/markdown.go:31-55`), which declares `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, and `RenameTag`.

**impl** — There is exactly one concrete implementation: the unexported struct `service` (`internal/markdown/markdown.go:58-60`), wrapping a `goldmark.Markdown`. All eight methods are `*service` receivers (lines 143, 193, 244, 255, 264, 349, 356, 425). No other implementer or mock exists in the codebase, so `*service` is what executes at runtime. (Internally, `RenderMarkdown`/`RenameTag` delegate to a `renderer.MarkdownRenderer` built via `renderer.NewMarkdownRenderer()` at `internal/markdown/markdown.go:250,451`, but that is a helper concrete type, not the interface in question.)

**construction** — Built only through `markdown.NewService(...)` (`internal/markdown/markdown.go:85`, returning `&service{...}` at line 110). The single production construction site is `NewAPIV1Service` (`server/router/api/v1/v1.go:48-51`), which calls `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())` and stores it. (Other `NewService` calls are test-only: `server/router/api/v1/test/test_helper.go:44`, `server/router/fileserver/fileserver_test.go:427`, `server/router/rss/rss_test.go:54`.) That one instance is then passed by reference — it is not reconstructed downstream.

**holders** — Components holding the `markdown.Service` interface as a field:
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — the owner/constructor; used e.g. in `server/router/api/v1/memo_service.go:108,447` via `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)`.
- `RSSService.MarkdownService` (`server/router/rss/rss.go:45`, ctor `NewRSSService` at line 58) — wired the *same* instance in `server/server.go:85` (`rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)`); used for `RenderHTML` at `server/router/rss/rss.go:339`.
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`, ctor `NewRunner` at line 19) — a holder in the type, but `NewRunner` is only invoked from tests; production code reaches the same logic through the standalone `RebuildMemoPayload(...)` function (line 74), which takes the interface as a parameter rather than holding it.

So: `*markdown.service` (goldmark-backed) — constructed once by `markdown.NewService(WithTag/WithMention)` in `NewAPIV1Service` — held by `APIV1Service`, `RSSService` (same shared instance), and `memopayload.Runner` (test construction only; prod uses it via the `RebuildMemoPayload` parameter).
