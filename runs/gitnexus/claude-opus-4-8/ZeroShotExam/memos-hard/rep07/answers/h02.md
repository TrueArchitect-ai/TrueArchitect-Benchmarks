**delivery function** — `Post` — `internal/webhook/webhook.go:120` (the actual `safeClient.Do(req)` outbound POST is at line 152; async workers call it via `PostAsync`/`asyncPostQueue` → `Post`).

**protection mechanism** — `safeDialContext` — `internal/webhook/webhook.go:59` (installed as the `DialContext` of the shared `safeClient` at lines 32–37). It resolves the target host and rejects any connection to a reserved/private IP via `isReservedIP` — `internal/webhook/validate.go:44` (ranges in `reservedCIDRs`, `internal/webhook/validate.go:14`). Because the check runs at dial time on the resolved IPs, it also defeats DNS-rebinding.

Notes:
- There's a second, earlier layer: `ValidateURL` — `internal/webhook/validate.go:62` validates the URL (scheme + resolves-to-reserved-IP) when a webhook is configured. The dial-time `safeDialContext` is what protects the actual delivery.
- Both checks can be disabled by the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`), intended for self-hosted deployments targeting local-network services.
