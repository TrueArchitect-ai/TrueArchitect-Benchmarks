**Premise correction:** There is no Redis connection anywhere in this codebase. `memos` (module `github.com/usememos/memos`, a Go project) has no Redis dependency in `go.mod`/`go.sum`, and no cache-layer client is configured against Redis. The premise that the cache is Redis-backed is incorrect.

**Actual mechanism:** The cache layer is a **thread-safe in-memory cache**, implemented in-process in `store/cache/cache.go` (`type Cache` — a mutex-guarded map with a background cleanup goroutine). It is not a network cache and requires no connection configuration.

- **Where it's "configured":** in `store/store.go:38-58`, inside `Store.New()`. A single `cache.Config` literal (`store/store.go:40-45`) is created and reused to instantiate three separate in-memory caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`). The config values are:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  - `OnEviction: nil`

- **TTL for user entries:** User records are written to `userCache` via plain `Set(...)` (e.g. `store/user.go:98,122,132,143,167`), which applies the cache's **default TTL of 10 minutes** (`store/store.go:41`). There is no per-user override — `SetWithTTL` is not used for user entries. Expired entries are swept by the cleanup goroutine every 5 minutes. `Store.Close()` (`store/store.go:73-76`) stops these goroutines.

The `Config` struct and defaults are defined in `store/cache/cache.go` (fields at lines ~42-54, `DefaultConfig()` mirroring the same 10-min/5-min values at ~57-60).

Note: an unrelated, separate ad-hoc cache exists for RSS (`server/router/rss/rss.go`) and a frontend `cacheService.ts` — neither is Redis nor the user cache.
