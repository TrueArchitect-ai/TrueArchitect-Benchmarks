All webhook-dispatch paths in this codebase converge on one delivery function, so multiple RPC handlers can transitively trigger an outbound HTTP POST to a user-configured webhook URL (URLs stored per-user via `Store.GetUserWebhooks`, `store/user_setting.go`).

**RPC handler methods (all on `APIV1Service`):**

1. `CreateMemo` — `server/router/api/v1/memo_service.go:70` → `DispatchMemoCreatedWebhook` (call at `:157`)
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:401` → `dispatchMemoUpdatedSideEffects` (`:513`) → `DispatchMemoUpdatedWebhook`
3. `DeleteMemo` — `server/router/api/v1/memo_service.go:518` → `DispatchMemoDeletedWebhook` (call at `:562`)
4. `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20` → `DispatchMemoCommentCreatedWebhook` (call at `:119`)
5. `SetMemoRelations` — `server/router/api/v1/memo_relation_service.go:16` → `dispatchMemoUpdatedSideEffects` (`:48`)
6. `SetMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:16` → `dispatchMemoUpdatedSideEffects` (`:48`)

**Path shape:** handlers 1–3, 5, 6 funnel through `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:47`); handler 4 through `DispatchMemoCommentCreatedWebhook` (`:29`). Both call `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto `asyncPostQueue`; the `init` worker goroutines (`:42`) drain that queue.

**Convergence function — delivery:** `webhook.Post` — `internal/webhook/webhook.go:120`. Every path (and the async worker) lands here, and this is the single function that performs the actual outbound request via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

(`webhook.PostAsync` at `internal/webhook/webhook.go:184` is the shared *enqueue* funnel the handlers call directly, if you want the convergence point one step before the goroutine hand-off rather than the `Do` call itself.)
