**Computation site**

The derived metadata is a memo's `Payload` (fields `Tags` and `Property`), computed by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`. It delegates the actual content parsing to the markdown service's single-pass `ExtractAll` — `internal/markdown/markdown.go:356` (goldmark AST walk). `RebuildMemoPayload` then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (runner.go:85-86).

**Triggers (recomputation)**

- **CreateMemo** — `server/router/api/v1/memo_service.go:108` (on the new memo's content).
- **UpdateMemo when the content field changes** — `server/router/api/v1/memo_service.go:447` (inside the `content` update branch, after `memo.Content` is reassigned).
- **Batch backfill** — `Runner.RunOnce` in `server/runner/memopayload/runner.go:27` rebuilds the payload of every memo in batches of 100 and persists via `UpdateMemo`. (This runner exposes `RebuildMemoPayload`/`RunOnce` but is not currently wired into `server/server.go` startup — it's a standalone migration utility.)

**Extracted properties**

`ExtractAll` walks the markdown AST and populates:
- `Payload.Tags` — all `#tags`, deduplicated while preserving original case (`markdown.go:377`, `418`).
- `Payload.Property` (`storepb.MemoPayload_Property`):
  - `Title` — text of the first block-level child if it's an H1 heading (`markdown.go:387`).
  - `HasLink` — a `KindLink` node exists (`394`).
  - `HasCode` — any code block / fenced code / inline code span (`397`).
  - `HasTaskList` — a task-checkbox node exists (`400`).
  - `HasIncompleteTasks` — any task checkbox is unchecked (`403`).

(`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` only copies `Tags` and `Property` into the payload — the metadata used for list/preview rendering.)
