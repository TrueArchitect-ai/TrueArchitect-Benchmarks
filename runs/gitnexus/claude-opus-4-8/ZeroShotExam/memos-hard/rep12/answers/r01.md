**Premise correction:** There is no Redis in this codebase (`usememos/memos`). A `grep` for `redis` across all Go source returns nothing. The cache layer is not backed by Redis or any external store — it is a **thread-safe, in-process, in-memory cache** implemented entirely in Go.

**Actual mechanism:**

- **Implementation:** `store/cache/cache.go` — a `Cache` struct built on `sync.Map` plus an `atomic.Int64` item counter, with a background `cleanupLoop` goroutine that evicts expired entries. There is no connection to configure (no host, port, or client) because it lives in the process's own memory.

- **Where it's configured / "connected":** `store/store.go:38-58`. The `Store` holds three separate in-memory cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`) — each created via `cache.New(cacheConfig)` (`store/store.go:51-53`). The shared config is defined inline at `store/store.go:40-45`:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  
  (The library's own `DefaultConfig()` at `store/cache/cache.go:57-64` uses the same values.)

- **TTL for user entries:** User records are cached in `userCache` via `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`). `Set` applies the cache's `DefaultTTL` (`store/cache/cache.go:92-95`), so **user entries expire after 10 minutes**. Cache keys are `userCacheKey(userID)` (`store/user.go:88`); user *settings* use `userSettingCache` with the same 10-minute default TTL. No user-specific TTL override is used anywhere — none of the user writes call `SetWithTTL`.

Expired entries are removed lazily on `Get` and proactively by the cleanup goroutine every 5 minutes; when the cache exceeds 1000 items it also sheds the oldest ~20% (`cleanupOldest`, `store/cache/cache.go:253`).
