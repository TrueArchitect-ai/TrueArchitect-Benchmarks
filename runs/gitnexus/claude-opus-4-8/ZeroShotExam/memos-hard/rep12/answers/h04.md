**No.** Outside the driver-selection factory, the MySQL driver is never constructed directly anywhere else in the application code.

Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14-32`. Its `switch profile.Driver` dispatches the `"mysql"` case to `mysql.NewDB(profile)` (`store/db/db.go:22`).
- `mysql.NewDB` (the exported constructor in `store/db/mysql/mysql.go:20`) is called from **exactly one place** — `store/db/db.go:22`. A repo-wide grep for `mysql.NewDB` returns only that line.
- The driver type is `mysql.DB` (`store/db/mysql/mysql.go:14`), and its fields (`db`, `profile`, `config`) are all **unexported**, so the struct literal cannot be built from any package other than `mysql` itself. Grepping for `mysql.DB{` outside the `mysql` package yields nothing.
- The only direct struct constructions of `DB{…}` are both *inside* the `mysql` package: `DB{profile: profile}` within `NewDB` itself (`store/db/mysql/mysql.go:29`), and `&DB{}` in the package's own test `store/db/mysql/auth_config_test.go:12`. Neither is "outside" the factory in the sense of another subsystem instantiating the driver — the test is same-package and doesn't open a real connection.

So the factory is the sole entry point through which the MySQL driver is instantiated in the running application.
