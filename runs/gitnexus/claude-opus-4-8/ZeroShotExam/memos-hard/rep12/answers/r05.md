**Premise correction:** memos has no GraphQL schema. There is no GraphQL server, no `.graphql`/SDL files, and no GraphQL resolver layer anywhere in the codebase — a repo-wide search for "graphql" turns up nothing in the Go, TypeScript, or proto sources. The question's assumption of a GraphQL public API is incorrect.

**Actual API surface:** memos defines its public API with **Protocol Buffers (gRPC)**, not GraphQL. The schema of record is the set of `.proto` service definitions in `proto/api/v1/`:

- `proto/api/v1/auth_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/memo_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto`

From these, `proto/buf.gen.yaml` drives code generation into multiple surfaces:
- **gRPC + Connect** Go stubs → `proto/gen/api/...`
- **REST/HTTP** via the grpc-gateway plugin (endpoints come from `google.api.http` annotations on the RPCs in the `.proto` files)
- **OpenAPI** spec via the gnostic-openapi plugin (embedded through `proto/openapi_embed.go`)
- **TypeScript** client types → `web/src/types/proto/`

The server wires these handlers under `server/router/api/`. So the "schema" you'd be looking for lives in `proto/api/v1/*.proto`, and the public API is gRPC/Connect + a REST gateway + OpenAPI — there is no GraphQL layer.
