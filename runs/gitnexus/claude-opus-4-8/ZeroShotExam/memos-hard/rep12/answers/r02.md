The premise is mistaken: **this repository (`usememos/memos`) has no per-user API rate-limiting middleware.** There is nothing to register and no limits to report.

Evidence:

- **The Connect RPC interceptor chain contains no rate limiter.** In `server/router/api/v1/connect_interceptors.go`, the only interceptors defined are `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` — authentication/logging/panic-recovery only, none of which throttle or count requests.
- **No rate-limiting dependency exists.** `go.mod` pulls in no limiter library (`golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, etc.), and a codebase-wide search for `rate limit`, `throttle`, `limiter`, and `429` across all Go source finds no implementation.
- **The single textual match is a documentation note, not code.** `internal/email/doc.go:86` reads `//   - Rate limit email sending to prevent abuse` — a security-considerations suggestion in a package doc comment about SMTP sending, with no corresponding implementation.
- `internal/filter/` (the only middleware-adjacent directory besides the interceptors) is a CEL expression filter for queries, unrelated to rate limiting.

So there is no location where per-user rate-limiting middleware is registered, and consequently no request limits to cite. If you need rate limiting, it would have to be added (e.g., a new Connect interceptor in `connect_interceptors.go`) or handled by an upstream reverse proxy outside this codebase.
