h02.

**Delivery function — `internal/webhook/webhook.go`** (`Post`, defined at line 120; the outbound POST is built at `webhook.go:126` and actually fired at `webhook.go:152` via `safeClient.Do(req)`). It's dispatched from the memo webhook handlers (`server/router/api/v1/memo_service_webhooks.go`) through `Post`/`PostAsync`.

**Protection mechanism — `internal/webhook/validate.go`** (`isReservedIP` at line 44, backed by the `reservedCIDRs` blocklist at lines 14–23). This is enforced in two layers:

- **Dial-time (the real SSRF defense):** `safeDialContext` in `internal/webhook/webhook.go:59` is wired in as the `DialContext` of the shared `safeClient`. It resolves the host at connect time and rejects any resolved address where `isReservedIP` is true (`webhook.go:71`) — so it also defeats DNS-rebinding.
- **Create/update-time:** `ValidateURL` in `internal/webhook/validate.go:62` enforces http/https scheme and rejects hostnames resolving to reserved IPs, called when webhooks are registered.

The blocklist covers IPv4 loopback, RFC-1918 private ranges, link-local/cloud-IMDS (`169.254.0.0/16`), and IPv6 loopback/ULA/link-local.

Two caveats worth noting: there's a package-level `AllowPrivateIPs` bypass flag (`validate.go:41`) that disables both layers when true (currently only set in tests, no production wiring), and the blocklist omits some ranges like `0.0.0.0/8`, CGNAT (`100.64.0.0/10`), and IPv4-mapped-IPv6, which could theoretically bypass the check.
