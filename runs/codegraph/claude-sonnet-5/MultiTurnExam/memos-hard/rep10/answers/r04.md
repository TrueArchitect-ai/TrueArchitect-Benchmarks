**Premise correction:** Neither. There's no NATS or RabbitMQ (or any external message broker) in this codebase — `go.mod` has no such dependency, and no `.go` file imports either.

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel, not a message broker. In `internal/webhook/webhook.go:39`:
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```
This is a buffered channel (capacity 128) declared as a package-level `var`. Four worker goroutines are started in `init()` (`internal/webhook/webhook.go:42-55`) that range over `asyncPostQueue` and call `Post(payload)` for each item. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send — dropping (and logging) the payload if the channel is full rather than blocking. All of this lives entirely within the single server process; there's no external queueing/broker infrastructure involved.
