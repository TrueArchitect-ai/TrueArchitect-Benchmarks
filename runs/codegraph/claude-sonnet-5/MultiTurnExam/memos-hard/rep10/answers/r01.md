**Premise correction:** This repository has no Redis integration at all — no `redis` import in `go.mod`, and no reference to Redis anywhere in the Go source (`grep -ri redis` across all `.go` files returns nothing).

**Actual mechanism:** The cache layer is an in-process, in-memory cache, not an external Redis connection. It's implemented in `store/cache/cache.go` (`Cache` struct backed by `sync.Map`, `store/cache/cache.go:67-90`) and wired up in `store.New` — `store/store.go:38-61` — which constructs three separate `*cache.Cache` instances (`instanceSettingCache`, `userCache`, `userSettingCache`) using a shared `cache.Config`.

For user entries specifically, `userCache` uses the default config built in `store/store.go:40-45`:
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
So user cache entries (set/read via `Store.GetUser`/`Store.ListUsers`/`Store.UpdateUser` in `store/user.go`) get a **10-minute TTL**, with a background cleanup sweep every 5 minutes (`(*Cache).cleanupLoop`, `store/cache/cache.go:200-215`).
