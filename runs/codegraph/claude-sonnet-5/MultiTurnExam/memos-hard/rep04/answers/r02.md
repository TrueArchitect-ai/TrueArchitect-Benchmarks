**Premise correction:** There is no per-user API rate-limiting middleware in this codebase. A repo-wide search for "rate limit", "ratelimit", "throttle", and "limiter" across all `.go` files (and `go.mod`) returns zero matches.

What does exist is unrelated to request rate-limiting:
- `thumbnailSemaphore` / `imageProcessingSemaphore` (`server/router/api/v1/v1.go:40-41`) — `golang.org/x/sync/semaphore.Weighted` used to cap *concurrent* thumbnail/image-processing work (3 and 2 slots respectively), not a per-user or per-time-window request limit.
- A bounded async queue for webhook/email dispatch (`internal/webhook/webhook.go:39`, `internal/email/email.go:14`) — backpressure via a fixed-size channel, again not user-facing rate limiting.

No middleware in `server/server.go` or any router registers request throttling, and there's no token-bucket/leaky-bucket implementation anywhere in the tree. If per-user API rate limiting is desired, it would need to be added — it isn't present today.
