**Premise correction:** Neither. There is no NATS or RabbitMQ (or any external message broker) in this codebase — a repo-wide search of `go.mod` and all `.go` files for "nats" and "rabbitmq"/"amqp" returns zero matches.

**Actual mechanism:** Webhook delivery uses a fixed-size, in-process Go channel as its "queue": `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`). Four worker goroutines are started in the package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over that channel and calling `Post(payload)` (`internal/webhook/webhook.go:120`) to deliver the HTTP request. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send and drops (with a logged warning) if the channel is full — there's no persistence, no broker, no durability across process restarts.
