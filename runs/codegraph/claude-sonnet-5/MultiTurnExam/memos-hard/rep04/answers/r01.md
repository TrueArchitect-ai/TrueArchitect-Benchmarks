**Premise correction:** There is no Redis anywhere in this codebase. A repo-wide search (`go.mod`, and every `.go` file) for "redis" returns zero matches — no Redis client dependency, no connection config.

**Actual mechanism:** The cache layer is a pure in-memory, in-process cache: `store/cache/cache.go` (`Cache` struct backed by `sync.Map`, `store/cache/cache.go:67-73`). It's constructed by `store.New` (`store/store.go:38-61`) with a default config (`store/store.go:40-45`):
```
DefaultTTL:      10 * time.Minute,
CleanupInterval: 5 * time.Minute,
MaxItems:        1000,
```
This single `cache.Config` backs three separate in-memory caches held on the `Store`: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`). So user entries (`userCache`, populated/read in `store/user.go`, e.g. `Store.GetUser`/`Store.CreateUser`) get the default **10-minute TTL**, expired lazily on `Get` and swept by a background `cleanupLoop` ticking every 5 minutes (`store/cache/cache.go:200-215`). There's no external cache service or connection to configure — it's entirely local process memory, lost on restart.
