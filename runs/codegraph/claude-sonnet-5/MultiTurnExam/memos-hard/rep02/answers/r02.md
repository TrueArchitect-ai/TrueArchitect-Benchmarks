**Premise correction:** There is no per-user API rate-limiting middleware in this codebase. `grep -rli "ratelimit\|rate.limit\|limiter" --include=*.go .` turns up only a single doc comment (`internal/email/doc.go:86`, "Rate limit email sending to prevent abuse") describing an aspirational/external concern for email sending — no actual implementation.

The only middleware registered on the Echo server (`server/server.go:44-99`, `NewServer`) is:
```go
echoServer.Use(middleware.Recover())      // server/server.go:51
echoServer.Use(newCORSMiddleware(profile)) // server/server.go:52
```
No rate-limiting middleware (echo's `middleware.RateLimiter` or a custom equivalent) is wired in anywhere. The closest bounded-concurrency mechanisms in the server are unrelated semaphores for expensive operations — `thumbnailSemaphore` and `imageProcessingSemaphore` in `server/router/api/v1/v1.go:40-41` — which cap concurrent thumbnail/image-processing work, not per-user request rates.
