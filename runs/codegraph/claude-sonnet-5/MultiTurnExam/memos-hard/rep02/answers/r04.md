**Premise correction:** Neither — there is no NATS or RabbitMQ (or any external message broker) in this codebase. `grep -rli "nats\|rabbitmq\|amqp"` across the repo turns up nothing; webhook delivery has no external queue dependency at all.

**Actual mechanism:** Webhook dispatch uses an in-process Go buffered channel as its "queue," defined in `internal/webhook/webhook.go`:
- `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39` — a 128-slot in-memory channel, not a declared broker queue.
- `PostAsync` (`internal/webhook/webhook.go:184-196`) enqueues onto it (non-blocking; drops and logs a warning if full).
- A package `init()` (`internal/webhook/webhook.go:42-55`) spawns 4 goroutines that range over `asyncPostQueue` and call `Post` for each payload — these are the "delivery workers," running entirely within the server process, consuming from this Go channel rather than any external message broker.
