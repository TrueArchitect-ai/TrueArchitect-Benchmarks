**Premise correction**: there is no Redis in this codebase — no `redis` import appears anywhere in `go.mod` or any `.go` file (checked repo-wide, zero matches). There is no external cache connection to configure.

**Actual mechanism**: the cache layer is an in-process, in-memory cache (`store/cache/cache.go`), not backed by any external store. `Store` (store/store.go:38-61) constructs three such caches — `instanceSettingCache`, `userCache`, `userSettingCache` — via `cache.New(cacheConfig)`, using a shared `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000, OnEviction: nil}` (store/store.go:39-45). Entries are stored via `Cache.Set`/`SetWithTTL` (store/cache/cache.go:92-120), which uses `config.DefaultTTL` unless a custom TTL is passed — user records go through `Store.CreateUser`/`UpdateUser`/`GetUser` (store/user.go:92-169), all calling `s.userCache.Set(ctx, userCacheKey(user.ID), user)` with no custom TTL, so **user entries expire after 10 minutes**, cleaned up by a background goroutine (`cleanupLoop`, store/cache/cache.go:200-215) ticking every 5 minutes.
