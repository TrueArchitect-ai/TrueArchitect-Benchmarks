**Premise correction**: neither. There is no NATS or RabbitMQ (or any external message broker) in this codebase — no such import appears in `go.mod` or anywhere in the Go source.

**Actual mechanism**: webhook delivery uses an in-process, in-memory Go channel as its "queue", defined in `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`. On package `init()` (internal/webhook/webhook.go:42-55), 4 goroutines range over this channel and call `Post(payload)` for each item. Producers enqueue via `PostAsync` (internal/webhook/webhook.go:184-196), which does a non-blocking `select` send to `asyncPostQueue`, dropping and logging a warning if the buffer (128 items) is full rather than blocking. This is purely local to the server process — nothing is persisted or shared across instances.
