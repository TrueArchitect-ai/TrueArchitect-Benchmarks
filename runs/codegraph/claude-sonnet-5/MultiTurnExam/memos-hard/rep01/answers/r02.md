**Premise correction:** There is no per-user API rate-limiting middleware in this codebase. `grep -rli "rate.?limit\|ratelimit\|throttle" --include="*.go" .` returns zero hits anywhere in the Go backend.

**Actual mechanism:** The only global Echo middleware registered in `server/server.go` (`NewServer`) is `middleware.Recover()` and a custom CORS middleware (`newCORSMiddleware`) — `server/server.go:51-52`. Neither implements request throttling or per-user limits. Some individual subsystems have their own local concurrency caps (not rate limits) — e.g. `thumbnailSemaphore`/`imageProcessingSemaphore` in `APIV1Service` (`server/router/api/v1/v1.go:39-41`) bound concurrent thumbnail/image work, and the webhook dispatch queue is a bounded channel (`internal/webhook/webhook.go:39`) — but none of these enforce a per-user request-rate limit on the API surface.
