**Premise correction:** There is no Redis anywhere in this codebase — `grep -rli "redis" --include="*.go" .` returns zero hits. The repo has no Redis client dependency (not in `go.mod`) and no Redis connection configuration exists.

**Actual mechanism:** Caching is done entirely in-process via `store/cache/cache.go` — a thread-safe in-memory `Cache` (backed by `sync.Map` with a background cleanup goroutine, `store/cache/cache.go:66-90`). `store.Store` constructs three of these in-memory caches in `store/store.go:38-61` (`instanceSettingCache`, `userCache`, `userSettingCache`), each configured with:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So the **user entries TTL is 10 minutes** (`DefaultTTL`, `store/store.go:41`), with expired entries swept by a cleanup goroutine every 5 minutes (`CleanupInterval`) and a 1000-item cap per cache (`MaxItems`) — all enforced by `store/cache/cache.go` (`SetWithTTL`/`cleanupLoop`/`cleanupOldest`), not by any external Redis instance.
