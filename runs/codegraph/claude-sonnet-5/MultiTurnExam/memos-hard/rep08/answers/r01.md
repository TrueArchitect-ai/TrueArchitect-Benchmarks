Premise correction — there's no Redis anywhere in this codebase. A repo-wide case-insensitive search for "redis" across Go source (excluding `web/`) turns up zero matches, and `go.mod` has no such dependency either.

Actual mechanism — the cache layer is an in-process, in-memory cache: `store/cache/cache.go`, a `sync.Map`-backed `Cache` type with a background goroutine (`cleanupLoop`, `store/cache/cache.go:200-215`) that periodically expires stale entries — no network connection, no external service.

User-entry TTL — `store.New` (`store/store.go:38-58`) constructs a shared `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000}` (`store/store.go:40-45`) and uses it to build `userCache` (among `instanceSettingCache` and `userSettingCache`), all at `store/store.go:51-53`. So user entries cached via `Store.userCache` (e.g. in `Store.GetUser`, `store/user.go:148-169`) get a 10-minute TTL by default (`cache.DefaultConfig()` in `store/cache/cache.go:57-64` also defaults to 10 minutes, consistent with this).
