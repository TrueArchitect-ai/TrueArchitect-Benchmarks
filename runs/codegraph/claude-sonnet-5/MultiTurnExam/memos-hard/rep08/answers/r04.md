Premise correction — neither. There is no NATS or RabbitMQ (or any external message broker) in this codebase. A search for "nats"/"rabbitmq"/"amqp" across Go source finds nothing, and `go.mod` has no such dependency.

Actual mechanism — webhook delivery uses an in-process, in-memory Go channel as its "queue": `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`), a bounded channel with 128 slots. It's drained by 4 fixed worker goroutines spawned in the package's `init()` (`internal/webhook/webhook.go:42-55`), each looping `for payload := range asyncPostQueue { ... Post(payload) ... }`. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send and drops (with a `slog.Warn`) if the channel is full — there's no persistence, retry, or cross-process delivery; it's purely an in-memory worker pool within the single server process.
