**Premise correction**: This repository has no Redis integration at all — a repo-wide search for `redis`/`Redis` across all Go files returns zero matches. There is no external cache server to "configure a connection" for.

**Actual mechanism**: The cache layer is a purely in-process, in-memory implementation at `store/cache/cache.go` (`Interface`/`Cache` with `Set`, `SetWithTTL`, `Get`, `Delete`, `Clear`, backed by a `sync.Map`-style structure with a background cleanup goroutine — no network client, no connection config).

It's instantiated in `(*Store).New` — `store/store.go:38-58` — which builds a `cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000}` (`store/store.go:40-45`) and creates three separate in-memory cache instances from it: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`).

**TTL for user entries**: `userCache` uses that same default config, so entries set via `Store.CreateUser`/`UpdateUser`/`GetUser` (`store/user.go`) expire after **10 minutes** (`cache.Config.DefaultTTL`, `store/store.go:41`), unless a caller uses `SetWithTTL` for a custom duration — no such override is used for the user cache in this codebase.
