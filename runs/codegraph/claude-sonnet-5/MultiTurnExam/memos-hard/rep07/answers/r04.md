**Premise correction**: Neither. This codebase has no NATS or RabbitMQ dependency — a repo-wide search for `nats`/`rabbitmq`/`amqp` across all Go files (including `go.mod`) turns up nothing. There is no message broker involved in webhook delivery at all.

**Actual mechanism**: Webhook delivery workers consume from an in-process, in-memory Go channel, not an external broker. In `internal/webhook/webhook.go:39`, `asyncPostQueue := make(chan *WebhookRequestPayload, 128)` declares a buffered channel (capacity 128) as the "queue." Four worker goroutines are spawned in the package `init()` (`internal/webhook/webhook.go:42-55`), each running `for payload := range asyncPostQueue { ... Post(payload) ... }`. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send (`select`/`default`) and drops the payload with a warning log if the channel is full — there's no persistence, acknowledgement, or redelivery semantics you'd expect from a real broker.
