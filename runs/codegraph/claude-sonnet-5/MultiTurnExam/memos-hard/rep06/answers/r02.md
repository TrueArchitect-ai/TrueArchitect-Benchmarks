**Premise correction:** There is no per-user API rate-limiting middleware in this codebase. A search for rate-limiting/throttling code across all Go and web source (`grep -rli "rate.?limit\|ratelimit\|throttle"`) returns nothing — no middleware, no dependency, no registration site.

What the server does have that's adjacent but distinct:
- `maxAPIRequestBytes = 256 << 20` in `server/router/api/v1/v1.go:20`, a request-body size cap (via `http.MaxBytesHandler`), not a rate limit.
- Concurrency caps like `thumbnailSemaphore`/`imageProcessingSemaphore` (`server/router/api/v1/v1.go:39-41`) and `internal/webhook/webhook.go`'s bounded async queue — these throttle concurrent work, not requests-per-user-per-time-window.
- The bounded queues in `internal/webhook/webhook.go` and `internal/email/email.go` drop/log on overflow, but again this isn't per-user API rate limiting.

So there's no such middleware to cite a registration site or limits for.
