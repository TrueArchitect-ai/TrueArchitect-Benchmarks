**Premise correction:** There is no nightly database-cleanup job in the cron scheduler — in fact the cron `internal/scheduler` package isn't used anywhere in production at all.

Evidence:
- `internal/scheduler` (the generic `Scheduler`/`Job`/`Register`/`Start` cron machinery, `internal/scheduler/scheduler.go`, `job.go`, `parser.go`) is imported only by its own tests — `internal/scheduler/integration_test.go:13` and `internal/scheduler/example_test.go:10`. No production file imports `"github.com/usememos/memos/internal/scheduler"` (verified via `grep -rn "usememos/memos/internal/scheduler" --include=*.go .`), so no job is ever registered or started through it at runtime.
- The only real recurring background job in the server is the S3 presign refresher (`server/runner/s3presign/runner.go`), which runs on its own `time.Ticker` every 12 hours (not via cron, not a database-cleanup job, and not a fixed clock time — see h01).
- The "cleanup"-named hits elsewhere (`store/cache/cache.go`'s in-memory cache eviction loop, `store/attachment.go`/`memo_service.go` attachment/user deletion helpers) are request-triggered or interval-ticker-driven in-process routines, not a cron-scheduled nightly database cleanup job.

So there's no scheduled time to report — the premise of a nightly DB-cleanup cron job doesn't hold in this codebase.
