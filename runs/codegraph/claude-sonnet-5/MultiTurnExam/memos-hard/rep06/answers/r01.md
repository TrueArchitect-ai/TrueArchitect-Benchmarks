**Premise correction:** There is no Redis anywhere in this codebase — no Redis client import, no Redis config, nothing in `go.mod` (`grep -rli redis --include=*.go .` and `grep -i redis go.mod` both return nothing). The cache layer is a pure in-process, in-memory cache, not backed by any external store.

**Actual mechanism:** `store/cache/cache.go` defines a thread-safe in-memory `Cache` (backed by a `sync.Map` with a background cleanup goroutine, `store/cache/cache.go:66-90,199-215`). `store.Store` (`store/store.go:38-61`) constructs three of these caches — `instanceSettingCache`, `userCache`, `userSettingCache` — using a shared `cache.Config` with `DefaultTTL: 10 * time.Minute` and `CleanupInterval: 5 * time.Minute` (`store/store.go:40-45`). User entries specifically are cached in `userCache` and go through this same 10-minute default TTL (set/refreshed in `Store.GetUser`/`CreateUser`/`UpdateUser`/`ListUsers`, `store/user.go`), not a Redis-managed expiry.
