**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search for `redis`/`Redis` in Go source returns zero hits. The cache layer is not backed by an external service at all.

**Actual mechanism:** Caching is done by an in-process, in-memory cache implemented in `store/cache/cache.go` (a `sync`-protected map with TTL expiration and periodic cleanup, `store/cache/cache.go:35-60`+). The user cache (`userCache *cache.Cache`, `store/store.go:28`) is constructed in `store.New` at `store/store.go:47-58`, using a shared `cache.Config` set at `store/store.go:40-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user entries (`userCache`) get a **10-minute default TTL**, with a background cleanup sweep every 5 minutes and a 1000-item cap — no Redis connection exists to configure.
