**Premise correction:** Neither NATS nor RabbitMQ (nor any external message broker) is used — a repo-wide search finds no imports or references to `nats`, `rabbitmq`, `amqp`, or any message-queue client library in the codebase.

**Actual mechanism:** Webhook delivery workers consume from an in-process, in-memory Go channel, not a broker. It's declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over `asyncPostQueue` and call `Post` for each payload. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send to `asyncPostQueue` and drops (logging a warning) if the buffered channel (capacity 128) is full — there's no persistence, acknowledgement, or external broker involved, just an in-memory bounded queue local to the running server process.
