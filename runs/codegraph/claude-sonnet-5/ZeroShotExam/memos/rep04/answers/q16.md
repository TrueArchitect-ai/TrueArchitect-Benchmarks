Within `Store.DeleteMemo` (store/memo.go:140-159), before deleting the memo row itself, the store layer deletes:

1. **Memo relations** where the memo is the source (`DeleteMemoRelation` with `MemoID: &delete.ID`)
2. **Memo relations** where the memo is the target/related memo (`DeleteMemoRelation` with `RelatedMemoID: &delete.ID`)
3. **Attachments** linked to the memo — first listed via `ListAttachments(MemoID: &delete.ID)`, then each is removed individually via `DeleteAttachment`

Only after these cleanups does it call `s.driver.DeleteMemo(ctx, delete)` to remove the memo row itself (store/memo.go:158).

(Note: at the API layer, `server/router/api/v1/memo_service.go:567-577` additionally deletes memo comments — which are themselves memos — before deleting the target memo, but that's orchestration above the store layer, not something `store.DeleteMemo` does internally.)
