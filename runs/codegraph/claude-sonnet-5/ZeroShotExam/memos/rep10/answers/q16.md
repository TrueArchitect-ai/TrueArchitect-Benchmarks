Before deleting the memo row itself, `store.Store.DeleteMemo` (store/memo.go:140-158) deletes:

1. **Memo relations** — via `DeleteMemoRelation` called twice: once where the memo is the source (`MemoID`) and once where it is the target (`RelatedMemoID`)
2. **Attachments** — lists attachments linked to the memo (`ListAttachments`) and deletes each one via `DeleteAttachment`

Only after these are removed does it call `s.driver.DeleteMemo(ctx, delete)` to delete the memo row (store/memo.go:158).

Additionally, at the API layer (`server/router/api/v1/memo_service.go:518-593`), before invoking `store.DeleteMemo` on the target memo, `APIV1Service.DeleteMemo` first deletes any **child memo comments** (memos related via the `MemoRelationComment` relation type), each via a recursive call to `s.Store.DeleteMemo` — which in turn triggers the same relation/attachment cleanup for each comment memo.
