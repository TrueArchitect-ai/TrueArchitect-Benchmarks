- **Interceptor path**: `web/src/connect.ts:156` — `authInterceptor` (a Connect-RPC `Interceptor`), attached to the shared `transport` at `web/src/connect.ts:184-189` and applied to all service clients (`instanceServiceClient`, `authServiceClient`, `userServiceClient`, `memoServiceClient`, etc.). It sets the `Authorization: Bearer <token>` header on each request (`setAuthorizationHeader`, connect.ts:97-100) and on a 401 (`Code.Unauthenticated`) transparently refreshes the access token once and retries (connect.ts:156-178), falling back to `redirectOnAuthFailure()` on failure.

- **Token kinds**: 
  - Short-lived JWT **access token** (managed in `web/src/auth-state.ts` via `getAccessToken`/`setAccessToken`/`isTokenExpired`), sent as a Bearer header.
  - **Refresh token**, stored as an HTTP-only cookie (sent via `credentials: "include"` in `fetchWithCredentials`, connect.ts:57-62) and exchanged for a new access token through `AuthService.refreshToken` (connect.ts:74-83).
  - Backend-side there's also a long-lived **Personal Access Token (PAT)**, which can be sent the same way (`Authorization: Bearer memos_pat_...`) for programmatic access.

- **Backend package that validates them**: `server/auth` (`server/auth/authenticator.go`), specifically `Authenticator.Authenticate`/`AuthenticateToUser` (validates access token JWTs via `AuthenticateByAccessTokenV2`, PATs via `AuthenticateByPAT`, and refresh tokens via `AuthenticateByRefreshToken`). This is wrapped by `server/router/api/v1/authz.go`'s `Authorizer` (`NewAuthorizer`, `Authenticate`, `CheckAccess`), which is invoked by the Connect interceptor `NewAuthInterceptor` in `server/router/api/v1/connect_interceptors.go:213`.
