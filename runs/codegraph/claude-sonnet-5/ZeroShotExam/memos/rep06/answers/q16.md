In `store/memo.go` (`Store.DeleteMemo`, lines 140-158), before deleting the memo row itself, the store layer deletes:

1. **Memo relation records** — where the memo is the source (`DeleteMemoRelation` with `MemoID`) and where it is the target (`DeleteMemoRelation` with `RelatedMemoID`)
2. **Attachment records** — all attachments linked to the memo (fetched via `ListAttachments` then removed one-by-one via `DeleteAttachment`)

Only after these are cleaned up does it call `s.driver.DeleteMemo(ctx, delete)` to delete the memo row (store/db/postgres/memo.go:244, store/db/mysql/memo.go:259).

Note: at the API layer (`server/router/api/v1/memo_service.go:518-582`), `DeleteMemo` additionally deletes child "comment" memos (via `MemoRelationComment` relations) before deleting the target memo, but each of those is itself just a recursive call into the same store-layer `DeleteMemo`.
