In `store/memo.go`, `Store.DeleteMemo` (store/memo.go:140-159) deletes these records before deleting the memo row itself:

- **Memo relations** (`memo_relation` table) — twice: once where the memo is the source (`DeleteMemoRelation{MemoID: &delete.ID}`) and once where it's the target/related memo (`DeleteMemoRelation{RelatedMemoID: &delete.ID}`)
- **Attachments** linked to the memo — listed via `ListAttachments{MemoID: &delete.ID}` and deleted one by one via `DeleteAttachment`

Additionally, at the API layer (`server/router/api/v1/memo_service.go:518-593`, `APIV1Service.DeleteMemo`), before calling `Store.DeleteMemo` on the memo itself, it also deletes **memo comments** (child memos linked via a `MemoRelationComment` relation) by recursively calling `Store.DeleteMemo` on each comment's memo ID — which in turn triggers the same relation/attachment cleanup for each comment.
