**Engine + path:** Google's [CEL (Common Expression Language)](https://github.com/google/cel-go) via `cel-go`, wrapped by a custom filter engine in `internal/filter/` (`engine.go`, `schema.go`, `ir.go`, `render.go`, `helpers.go`).

**Mechanism:** `store/db/{mysql,postgres,sqlite}/memo.go`'s `ListMemos` calls `filter.AppendConditions` (`internal/filter/helpers.go:9`), which for each filter string calls `Engine.CompileToStatement` (`internal/filter/engine.go:74`) — this uses a CEL `cel.Env` built from a `Schema` (`internal/filter/schema.go`, e.g. `NewSchema()` at line 89) to parse the CEL expression into an AST via `env.Compile`, converts it into a dialect-agnostic `Condition` tree (`internal/filter/ir.go`) via `buildCondition`, and then `Program.Render` (`engine.go:96`) invokes the dialect-aware renderer in `internal/filter/render.go` (`renderCondition`/`renderResult` etc.) to emit parameterized SQL fragments and args, using per-field `Expressions map[DialectName]string` in the `Schema` (e.g. `UNIX_TIMESTAMP(%s)` for MySQL vs. raw `%s` for Postgres/SQLite) to handle dialect-specific column expressions.
