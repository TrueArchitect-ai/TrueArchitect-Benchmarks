- s3presign runner (`server/runner/s3presign/runner.go`, wired in `server/server.go:153-174` `startBackgroundRunners`) — started via `Server.Start()` (`server/server.go:129`) on every server boot. It runs once immediately (`RunOnce` at server.go:163) and then loops on a `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, s3presign/runner.go:27,30), stopped via context cancellation in `stopBackgroundRunners`/`Shutdown`.

That is the only background runner actually started by the server. Two pieces of scheduling infrastructure exist in the codebase but are NOT used by the server:
- `server/runner/memopayload.Runner` (with its own `NewRunner`/`RunOnce` batch-rebuild-all-memos loop) is never instantiated by `server.go` — `server.go` only imports `s3presign`, not `memopayload`. The only live use of that package is the standalone `RebuildMemoPayload` function, called synchronously inline in request handlers (`server/router/api/v1/memo_service.go:108,447`), not as a scheduled/background job.
- `internal/scheduler` — a full generic cron-expression scheduler (`Scheduler`, `Job`, `Register`, `Start`, `ParseCronExpression`, etc. in `internal/scheduler/scheduler.go` and `parser.go`) — has no callers anywhere in the server/CLI code; `scheduler.New(...)` is only invoked from its own package's tests (`example_test.go`, `integration_test.go`) and doc comments (`doc.go`). It is not wired into `server/server.go` at all.
