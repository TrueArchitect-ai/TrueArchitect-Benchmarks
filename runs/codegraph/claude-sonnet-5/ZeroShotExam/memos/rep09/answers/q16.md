When `Store.DeleteMemo` (store/memo.go:140-158) runs, before deleting the memo row itself it deletes:

1. **Memo relations** — via two calls to `DeleteMemoRelation`, once with `MemoID: &delete.ID` (relations where this memo is the source) and once with `RelatedMemoID: &delete.ID` (relations where this memo is the target)
2. **Attachments** — it lists all attachments linked to the memo (`ListAttachments` with `MemoID: &delete.ID`) and deletes each one individually via `DeleteAttachment`

Only after these cleanups does it call `s.driver.DeleteMemo(ctx, delete)` to remove the memo row itself (store/db/postgres/memo.go:244 / store/db/mysql/memo.go:259).

(Note: at the API layer, `server/router/api/v1/memo_service.go:518-593` also deletes memo comments — themselves memos related via a `MemoRelationComment` relation — by calling `Store.DeleteMemo` recursively for each comment before deleting the parent memo, which triggers the same relation/attachment cleanup for each comment.)
