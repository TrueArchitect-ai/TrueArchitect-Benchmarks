**Engine + path:** Google's CEL (Common Expression Language), via `github.com/google/cel-go/cel`, wrapped by memos' own `internal/filter` package — specifically `internal/filter/engine.go` (`Engine.Compile`), `internal/filter/parser.go` (AST → dialect-agnostic `Condition` tree via `buildCondition`), `internal/filter/schema.go` (field/type metadata and CEL env vars), and `internal/filter/render.go` (condition tree → SQL).

**Mechanism:** `Engine.Compile` (internal/filter/engine.go:48) parses the `filter` string from `ListMemosRequest` with the CEL environment defined by `NewSchema()` (internal/filter/schema.go:89), converts the resulting CEL AST into a dialect-agnostic `Condition` tree via `buildCondition`, and then `Program.Render`/`renderer.Render` (internal/filter/render.go:32) walks that tree to emit dialect-specific SQL — choosing table/column syntax, JSON functions (`JSON_EXTRACT`/`JSON_TABLE` for SQLite/MySQL vs. `->`/`->>`/`jsonb_*` for Postgres), timestamp handling, and placeholder style (`?` vs `$N`) based on the `DialectName` (sqlite/mysql/postgres) passed in via `RenderOptions`; the call sites are `store/db/{sqlite,mysql}/memo.go`'s `ListMemos`, which invoke `filter.AppendConditions` (internal/filter/helpers.go:9) to compile+render each filter string into a `WHERE`-clause fragment and args.
