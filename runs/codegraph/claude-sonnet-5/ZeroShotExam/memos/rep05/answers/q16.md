In `store/memo.go` (`Store.DeleteMemo`, store/memo.go:140-158), before deleting the memo row the store layer deletes:

1. **Memo relations** where the memo is the source (`s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})`)
2. **Memo relations** where the memo is the target/related memo (`s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})`)
3. **Attachments** linked to the memo — it lists them via `s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})` and deletes each one individually via `s.DeleteAttachment(...)`

Only after these cleanups does it call `s.driver.DeleteMemo(ctx, delete)` to remove the memo row itself.

(Note: at the API layer, `server/router/api/v1/memo_service.go:518-593` also deletes memo *comments* — child memos linked via a `MemoRelationComment` relation — by calling `store.DeleteMemo` recursively for each comment before deleting the parent memo, but that recursive comment cleanup happens in the service layer, not inside the store's `DeleteMemo` itself.)
