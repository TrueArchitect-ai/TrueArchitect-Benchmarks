When `Store.DeleteMemo` (store/memo.go:140) deletes a memo row, it first deletes, in order:

1. **Memo relations** (`memo_relation` records) where the memo is the source (`DeleteMemoRelation` with `MemoID`) — store/memo.go:142
2. **Memo relations** where the memo is the target/related memo (`DeleteMemoRelation` with `RelatedMemoID`) — store/memo.go:145
3. **Attachments** linked to the memo — listed via `ListAttachments` then deleted one-by-one via `DeleteAttachment` — store/memo.go:149-157

Only after these are removed does it call `s.driver.DeleteMemo(ctx, delete)` to delete the memo row itself (store/memo.go:158).

Note: at the API layer (`server/router/api/v1/memo_service.go:518-582`), before calling `Store.DeleteMemo`, the handler also separately deletes any **memo comments** (child memos linked via a `MemoRelationComment` relation) by recursively calling `Store.DeleteMemo` on each comment's memo ID (memo_service.go:567-577) — each of those recursive calls goes through the same relation/attachment cleanup described above.
