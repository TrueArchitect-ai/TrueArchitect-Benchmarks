q25.

**Engine + path:** Filters use CEL (Common Expression Language, via `github.com/google/cel-go`), implemented in `internal/filter/` (`engine.go`, `parser.go`, `schema.go`, `render.go`, `helpers.go`).

**Mechanism:** `Engine.Compile` (internal/filter/engine.go:48) uses a CEL `cel.Env` (built from a `Schema` in schema.go) to parse the filter string into a CEL AST, which `buildCondition`/`buildCallCondition` (internal/filter/parser.go) walks into a dialect-agnostic `Condition` tree; `Program.Render` then hands that tree to a `renderer` (internal/filter/render.go) whose methods switch on `RenderOptions.Dialect` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`) to emit dialect-specific SQL fragments and args (e.g. different placeholder syntax, `JSON_CONTAINS` for MySQL vs `@>`/`jsonb_build_array` for Postgres vs `LIKE` against a JSON string for SQLite).

This is wired into `ListMemos` via `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)`, called from each dialect's store package: `store/db/sqlite/memo.go:57`, `store/db/mysql/memo.go:65`, `store/db/postgres/memo.go:54`. The raw filter string itself originates from the gRPC request in `server/router/api/v1/memo_service.go:211` (`ListMemos` reads `request.Filter`, validates it, and appends it to `memoFind.Filters`).
