Within `store.Store.DeleteMemo` (store/memo.go:140-158), before deleting the memo row itself, the store layer deletes:

1. **Memo relations** — via `DeleteMemoRelation`, once where this memo is the source (`MemoID: &delete.ID`) and once where it is the target (`RelatedMemoID: &delete.ID`) (store/memo.go:142-147)
2. **Attachments** — lists all attachments linked to the memo via `ListAttachments`, then deletes each one individually via `DeleteAttachment` (store/memo.go:149-157)

Only after these cleanups does it call `s.driver.DeleteMemo(ctx, delete)` to remove the memo row itself (store/memo.go:158).

Note: at the API layer (`server/router/api/v1/memo_service.go:518-593`), `DeleteMemo` additionally deletes child "comment" memos first (by finding `MemoRelationComment` relations and recursively calling `store.DeleteMemo` on each), but that recursion is orchestrated by the API handler, not the store layer itself.
