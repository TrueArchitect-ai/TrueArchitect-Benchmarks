Within `store.Store.DeleteMemo` (store/memo.go:140-158), before deleting the memo row itself, the store layer deletes:

1. **Memo relations** — `DeleteMemoRelation` called twice: once where this memo is the source (`MemoID`) and once where it's the target (`RelatedMemoID`) (store/memo.go:142-147).
2. **Attachments** — lists all attachments linked to the memo via `ListAttachments`, then deletes each one individually with `DeleteAttachment` (store/memo.go:148-157), which also cleans up associated attachment storage.

Only after these are removed does it call `s.driver.DeleteMemo(ctx, delete)` to delete the memo row (store/memo.go:158).

Note: at the API layer (server/router/api/v1/memo_service.go:567-577), memo comments (child memos linked via a `MemoRelationComment` relation) are deleted first by recursively calling `store.DeleteMemo` on each comment's memo ID — but that's a separate outer-layer step, not part of the store's internal `DeleteMemo` logic itself.
