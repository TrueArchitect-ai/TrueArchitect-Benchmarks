q29.
Frontend auth interceptor: `web/src/connect.ts` (`authInterceptor`, lines 156–178) — a Connect-RPC `Interceptor` attached to the shared `createConnectTransport` (line 184-189) that sets `Authorization: Bearer <token>` on every request (via `setAuthorizationHeader`) and, on a `Code.Unauthenticated` response, transparently calls `refreshAccessToken()` and retries once (falling back to `redirectOnAuthFailure()`); token state itself lives in `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken`/`isTokenExpired`).

Token kinds managed: short-lived JWT **access tokens** (kept in frontend memory/state, sent as `Authorization: Bearer`) and long-lived JWT **refresh tokens** (kept in an HTTP-only cookie, `memos_refresh`, sent automatically via `credentials: "include"` and exchanged via `AuthService.refreshToken`). A third kind, **Personal Access Tokens (PAT)**, exists for programmatic/API use but isn't managed by this interceptor.

Backend package that validates them: `server/auth` (see `server/auth/token.go` for JWT generation/parsing — `ParseAccessTokenV2`, `ParseRefreshToken` — and `server/auth/authenticator.go` for request-time validation), wired into the API via the `AuthInterceptor`/`Authorizer` in `server/router/api/v1/connect_interceptors.go` and `server/router/api/v1/authz.go`.
