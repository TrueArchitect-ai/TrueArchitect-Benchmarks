When `Store.DeleteMemo` (store/memo.go:140) runs for a memo, it deletes these related records before deleting the memo row itself:

- **Memo relations** — rows in `memo_relation` where the memo is the source (`DeleteMemoRelation` with `MemoID`) or the target (`DeleteMemoRelation` with `RelatedMemoID`)
- **Attachments** — all attachments linked to the memo, fetched via `ListAttachments` and removed one-by-one via `DeleteAttachment`

Only after these are cleaned up does it call `s.driver.DeleteMemo(ctx, delete)` to delete the memo row itself.

Additionally, at the API layer (`server/router/api/v1/memo_service.go:518` `DeleteMemo`), before invoking `Store.DeleteMemo` on the target memo, it first finds and deletes any **memo comments** (memos related via `store.MemoRelationComment`), each via a recursive call to `Store.DeleteMemo` (which in turn cascades their own relations/attachments as above).
