- **Interceptor path**: `web/src/connect.ts` — the `authInterceptor` (Connect-RPC `Interceptor`, `connect.ts:156`), attached to the `createConnectTransport` used by all frontend service clients.
- **Token kinds**: 
  - **Access token** (short-lived JWT, "Access Token V2") — attached as `Authorization: Bearer <token>` header via `setAuthorizationHeader`; managed in-memory/state via `getAccessToken`/`setAccessToken`/`isTokenExpired` (`web/src/auth-state.ts`), with proactive refresh before expiry and reactive refresh-and-retry on a `Code.Unauthenticated` (401) response.
  - **Refresh token** — an HTTP-only cookie (not touched directly by JS; sent via `credentials: "include"` in `fetchWithCredentials`), exchanged for a new access token via `AuthService.refreshToken` on a separate `refreshTransport` (no auth interceptor, to avoid recursion).
  - The backend additionally supports a **Personal Access Token (PAT)** (`memos_pat_...`-prefixed, long-lived) sent the same way as a Bearer token, though it's issued/managed via `web/src/components/Settings/AccessTokenSection.tsx`, not by the interceptor itself.

- **Backend package that validates them**: `server/auth` (`server/auth/authenticator.go`) — `Authenticator.Authenticate`/`AuthenticateByAccessTokenV2`/`AuthenticateByRefreshToken`/`AuthenticateByPAT`. It's invoked through `server/router/api/v1/authz.go`'s `Authorizer.Authenticate`/`CheckAccess`, which is wired into the Connect interceptor chain (`server/router/api/v1/connect_interceptors.go`) and gRPC-Gateway (`server/router/api/v1/v1.go`).
