**Backend (Go) — the real interface-behind-implementation:**

`markdown.Service` is the interface (`internal/markdown/markdown.go:31-55`), with a single concrete runtime implementation:

- impl — `*service` (unexported struct wrapping a `goldmark.Markdown`), `internal/markdown/markdown.go:58-113`
- construction — `markdown.NewService(opts ...Option)` at `internal/markdown/markdown.go:85`, called with `markdown.WithTagExtension(), markdown.WithMentionExtension()` in `NewAPIV1Service` (`server/router/api/v1/v1.go:47-51`); also called (with varying options) in `server/router/rss/rss.go` (`NewRSSService`) and `server/runner/memopayload/runner.go` (`NewRunner`), plus in test helpers (`internal/markdown/markdown_test.go`, `server/router/api/v1/test/test_helper.go`, `server/router/fileserver/fileserver_test.go`, `server/router/rss/rss_test.go`)
- holders — `APIV1Service.MarkdownService markdown.Service` field (`server/router/api/v1/v1.go:35`); an equivalent field/param on the RSS service (`server/router/rss/rss.go`) and on the memo-payload rebuild runner (`server/runner/memopayload/runner.go`)

**Frontend (React) note:** there is no analogous Go-style interface — `MemoMarkdownRenderer` (`web/src/components/MemoContent/MemoMarkdownRenderer.tsx:56`) uses `ReactMarkdown` directly (from `react-markdown`) with a fixed remark/rehype plugin pipeline; it's not constructed behind an abstraction, so it isn't part of this interface/impl pair.
