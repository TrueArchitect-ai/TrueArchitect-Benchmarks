Premise correction: there is no message broker in this codebase at all — neither NATS nor RabbitMQ is used or even referenced anywhere (`grep -ri "nats\|rabbitmq\|amqp"` across the repo returns nothing).

Actual mechanism: webhook delivery is done in-process via a goroutine, not a queue consumer. `webhook.PostAsync()` in `internal/webhook/webhook.go:184` spawns a `go func()` (webhook.go:44 inside `PostAsync`) that calls `Post()` (webhook.go:120) to perform the HTTP POST to the webhook URL. It's called directly from the API handlers in `server/router/api/v1/memo_service_webhooks.go` (e.g. `dispatchMemoRelatedWebhook` at line 71, and `DispatchMemoCommentCreatedWebhook` at line 43) — fire-and-forget per event, with no external broker, no persisted queue, and no separate worker process.
