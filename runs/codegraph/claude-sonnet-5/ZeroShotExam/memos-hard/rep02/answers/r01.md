Premise correction: there is no Redis anywhere in this repository — I searched (`grep -ri redis`) across the whole codebase and found zero matches. The "cache layer" referenced in the question is not backed by Redis at all; it's an in-process, in-memory cache implemented from scratch in Go.

Actual mechanism:
- The cache implementation lives in `store/cache/cache.go` — a thread-safe in-memory `sync.Map`-based cache with per-item expiration, background cleanup, and max-item eviction (no external service, no network connection to configure).
- It's wired up in `store/store.go:38-58`. `store.New()` builds a `cache.Config` with `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, and uses it to construct three separate in-memory caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`, `40-53`).
- Since user entries (`userCache`) are created with that same `cacheConfig` and no override, they get the default TTL of **10 minutes** (`store/store.go:41`), unless a specific call site uses `SetWithTTL` with a custom duration — I didn't find any such override for user entries in `store/user.go`.

So: no Redis connection exists to configure; the user-cache TTL is 10 minutes, set via the shared `cacheConfig` in `store/store.go`.
