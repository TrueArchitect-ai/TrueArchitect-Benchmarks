The data layer is the `store` package (`store/*.go`), which defines the persistent entity types (`store.User`, `store.Memo`, `store.Attachment`, `store.MemoRelation`, `store.Reaction`, `store.Inbox`, `store.MemoShare`, `store.UserSetting`, `store.UserIdentity`, `store.InstanceSetting`, `store.IdentityProvider`). I counted, for each type, the number of distinct non-store packages (`.go` files outside `store/`) that reference it via `store.<Type>`.

Ranking by number of distinct external packages:

1st: `store.User` (~7 packages: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`)

2nd: `store.Memo` (~6 packages: `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`)

Next closest was `store.Attachment` at 4 packages. `User` edges out `Memo` because it's also consumed directly by `server/auth` (session/token validation) and `server/router/fileserver`, in addition to the same request/response and notification paths that reference `Memo`.
