**Premise correction:** There is no Redis connection anywhere in this codebase — a repo-wide search for "redis"/"Redis" across Go, TS/TSX, YAML, and JSON files turns up zero matches. This project (usememos/memos) does not use Redis for caching.

**Actual mechanism:** The cache layer is a custom in-memory, thread-safe cache built on `sync.Map` with TTL-based expiration and periodic cleanup, defined in `store/cache/cache.go`. It's instantiated per-`Store` in `store/store.go:39-53`, which creates three separate cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing one `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    ...
}
```
(`store/store.go:40-41`)

So the `userCache` (used for user lookups, e.g. `store/user.go:150-151`) gets a **10-minute TTL** by default, same as the other stores' caches, since `SetWithTTL` falls back to `config.DefaultTTL` (`store/cache/cache.go:92-95`) unless a call site explicitly overrides it with `SetWithTTL`. Expired entries are lazily evicted on `Get` and also swept every `CleanupInterval` (5 minutes, per `cache.DefaultConfig()` in `store/cache/cache.go:56-64`, though the store's own config at `store/store.go:39-53` is what's actually wired in and should be checked for its own `CleanupInterval` value if a full picture is needed).
