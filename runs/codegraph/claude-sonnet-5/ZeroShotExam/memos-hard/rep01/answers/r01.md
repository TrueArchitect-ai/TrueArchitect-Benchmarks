Premise correction: there is no Redis anywhere in this codebase — a repo-wide search for "redis" returns zero matches. The "cache layer" is not backed by an external cache server at all; it's a custom in-process, in-memory cache implemented in Go.

Actual mechanism: `store/cache/cache.go` defines a thread-safe in-memory `Cache` (backed by `sync.Map`) with TTL expiration, periodic cleanup, and size-based eviction. It's instantiated in `store/store.go:38-61` (function `New`), which builds three separate in-memory caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — all using the same `cacheConfig`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user entries (cached via `userCache` in `store/user.go`, keyed by `userCacheKey(userID int32)` at store/user.go:88, e.g. lines 98/122/132/150/167) expire after the `DefaultTTL` of **10 minutes**, with a background cleanup sweep every 5 minutes (`CleanupInterval`) and a cap of 1000 items per cache (LRU-ish eviction of oldest entries when exceeded).
