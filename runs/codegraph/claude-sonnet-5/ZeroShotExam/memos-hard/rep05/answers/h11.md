I counted, per entity type, the number of distinct non-`store/*` Go packages that reference `store.<Type>` (`grep -rl 'store\.<Type>\b' --include='*.go' . | grep -vE '^(\./)?store/' | xargs -n1 dirname | sort -u`):

- `store.User`: 7 packages — `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- `store.Memo`: 6 packages — `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`
- `store.Attachment`: 4 packages
- `store.Inbox` / `store.MemoRelation` / `store.MemoShare`: 3 each
- `store.Reaction` / `store.UserIdentity`: 2 each
- `store.UserSetting` / `store.InstanceSetting` / `store.IdentityProvider`: 1 each

**Answer:** 1st: `User` (~7 packages, defined in `store/user.go`); 2nd: `Memo` (~6 packages, defined in `store/memo.go`) — both are used across nearly every consumer-facing layer (`server/router/api/v1`, `server/router/frontend`, `server/router/rss`, `server/notification`), reflecting that user and memo are the two central entities the rest of the app revolves around.
