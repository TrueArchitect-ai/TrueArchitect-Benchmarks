Premise correction: neither NATS nor RabbitMQ is used — there is no external message broker in this codebase at all.

Actual mechanism: webhook delivery uses an in-process, in-memory Go channel as a bounded work queue. It's declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

A fixed pool of 4 goroutines is started in `init()` (`internal/webhook/webhook.go:42-55`) to drain this channel and call `Post()` (the actual HTTP POST to the webhook URL, `internal/webhook/webhook.go:120`). Producers call `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send and drops (with a `slog.Warn` log) if the queue is full — there's no persistence or redelivery, just an in-memory buffered channel scoped to the process lifetime.

Note this is the same pattern used for async email sending in `internal/email/email.go:14` (`asyncEmailQueue`), confirming it's a repo-wide convention rather than something specific to webhooks.
