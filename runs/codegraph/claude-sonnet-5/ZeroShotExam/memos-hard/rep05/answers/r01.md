**Premise correction:** There is no Redis anywhere in this codebase. A repo-wide search for "redis" (Go, TS, YAML, env files) returns zero matches — this app (usememos/memos) doesn't use Redis for caching at all.

**Actual mechanism:** Caching is done with a hand-rolled in-process cache, `store/cache/cache.go` (`Cache` struct backed by `sync.Map` with a background `cleanupLoop` goroutine for expiry). It's configured and wired up in `store/store.go:38-61`: `Store.New` builds a `cache.Config{DefaultTTL: 10*time.Minute, CleanupInterval: 5*time.Minute, MaxItems: 1000}` and creates three separate cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` (store/store.go:27-29, 51-53).

For user entries specifically: `userSettingCache` and `userCache` both use that same default config, so **user entries get a 10-minute TTL** (`store/store.go:41`, mirrored in `store/cache/cache.go:59` as the package's own `DefaultConfig()`). Keys for user settings are built by `getUserSettingCacheKey` (store/cache.go:7-9), and populated/read in `store/user_setting.go` (`UpsertUserSetting`, `GetUserSetting`, etc., lines 59, 78, 106, 122).

Separately, there's an unrelated in-memory RSS feed cache (`server/router/rss/rss.go:23-27`, a plain `map[string]*cacheEntry` with its own 1-hour `defaultCacheDuration`), but that caches rendered RSS XML, not user entries.
