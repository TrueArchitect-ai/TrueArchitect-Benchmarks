**Premise correction:** There is no Redis connection in this codebase — no Redis client, driver, or connection string exists anywhere in the repo (confirmed via a repo-wide search for "redis", which returned zero matches).

**Actual mechanism:** The cache layer is a pure in-memory, process-local cache implemented in `store/cache/cache.go` (a `sync.Map`-backed struct with a background cleanup goroutine — no external service involved). It's instantiated in `store/store.go:38-58`, where `Store.New()` builds a shared `cache.Config` and creates three separate in-memory caches (`instanceSettingCache`, `userCache`, `userSettingCache`), all using the same config.

**TTL for user entries:** `userCache` uses the same `cacheConfig` as the others, set at `store/store.go:40-45`:
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
So user entries get a **10-minute default TTL**, with a background cleanup sweep every 5 minutes and a 1000-item cap per cache (least-recently-set eviction once exceeded, per `cleanupOldest` in `store/cache/cache.go:253-313`). This is the library's `DefaultConfig()` values (`store/cache/cache.go:57-64`) applied explicitly rather than inherited.
