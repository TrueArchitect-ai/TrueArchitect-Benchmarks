**Premise correction:** There is no Redis in this codebase — I grepped for "redis" across all Go/TS/config/markdown files and found zero matches. The cache layer is not backed by an external Redis instance at all.

**Actual mechanism:** Caching is implemented as an in-memory, process-local cache (`store/cache/cache.go`), using Go's `sync.Map` with TTL-based expiration and a background cleanup goroutine — no network connection or external service is involved.

- The `Store` struct (`store/store.go:13-30`) holds three such caches: `instanceSettingCache`, `userCache`, and `userSettingCache`.
- They're all constructed in `store.New()` (`store/store.go:38-61`) with a shared `cache.Config`:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
- So the **TTL for user entries (`userCache`) is 10 minutes** (`store/store.go:41`, applied via `cache.New(cacheConfig)` at `store/store.go:52`), with expired-entry cleanup running every 5 minutes.

Separately, there's an unrelated in-memory RSS feed cache in `server/router/rss/rss.go` (a hand-rolled `map[string]*cacheEntry` with its own TTL/ETag logic), but that's for RSS feed content, not user entries.
