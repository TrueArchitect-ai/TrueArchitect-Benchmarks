Each of these dispatch functions fetches the target user's configured webhooks via `s.Store.GetUserWebhooks` (URLs stored in `WebhooksUserSetting_Webhook.Url`, proto/gen/store/user_setting.pb.go:917 — set by the user through the `CreateUserWebhook`/`UpdateUserWebhook` RPCs in `server/router/api/v1/user_service_webhooks.go`), builds a `webhook.WebhookRequestPayload{URL: hook.Url, ...}`, and calls `webhook.PostAsync(payload)`.

**Convergence function:** `Post` — `internal/webhook/webhook.go:120`

`PostAsync` (webhook.go:184) just enqueues the payload onto `asyncPostQueue`; the worker goroutines started in `init()` (webhook.go:42-55) pull from that queue and call `Post`, which is where every one of these paths actually converges before the request leaves the process — it builds the `http.Request` for `requestPayload.URL` and performs the outbound call via `safeClient.Do(req)` (webhook.go:152).

(Note: `internal/httpgetter/html_meta.go`'s `GetHTMLMeta`, used by `GetLinkMetadata`/`BatchGetLinkMetadata`, is a separate outbound-HTTP path to an arbitrary URL, but that URL comes from request input rather than persisted user configuration, and it converges through a different client (`httpClient.Get`) — not the same convergence point as the webhook paths above.)
