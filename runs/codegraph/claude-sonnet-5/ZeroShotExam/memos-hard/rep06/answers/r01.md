**Premise correction:** There is no Redis anywhere in this codebase — I searched the full repo (`grep -ril redis`) and found zero matches, no Redis client dependency in `go.mod`, and no Redis config in any env/YAML files. This project (usememos/memos) doesn't use Redis for caching at all.

**Actual mechanism:** The cache layer is a custom in-process, thread-safe in-memory cache (`sync.Map`-backed) implemented in `store/cache/cache.go`. It's instantiated per `Store` in `store/store.go:38-58`, which creates three separate cache instances (`instanceSettingCache`, `userCache`, `userSettingCache`) all sharing one `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```
(`store/store.go:40-45`)

User entries are written via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` in `store/user.go` (lines 98, 122, 132, 143, 167), which uses `Set` (not `SetWithTTL`), so they get the **default TTL of 10 minutes** as defined in `cache.Config.DefaultTTL` / `cache.DefaultConfig()` (`store/cache/cache.go:57-64`). A background cleanup loop sweeps expired entries every 5 minutes (`CleanupInterval`), and entries are also lazily evicted on `Get` if expired (`store/cache/cache.go:135-144`).
