**impl** — The interface is `markdown.Service` (`internal/markdown/markdown.go:31`). At runtime the only concrete implementation is the unexported `*service` struct (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown` parser (with optional `TagExtension`/`MentionExtension`) and implements `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

**construction** — Built exclusively via `markdown.NewService(opts ...Option)` (`internal/markdown/markdown.go:85`). In production there is one call site: `NewAPIV1Service` (`server/router/api/v1/v1.go:47-51`) calls `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())`, producing a single shared instance. That same instance is then threaded into `rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)` in `server/server.go:85`. (Test-only construction also happens in `internal/markdown/markdown_test.go`, `server/router/api/v1/test/test_helper.go`, `server/router/fileserver/fileserver_test.go`, `server/router/rss/rss_test.go`.)

**holders** — Three structs hold the interface as a field typed `markdown.Service`:
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — the original owner, used directly by handlers like `RebuildMemoPayload` in `server/router/api/v1/memo_service.go`.
- `RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — reuses the APIV1Service's instance for `RenderHTML` in RSS item descriptions.
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`), populated via `NewRunner(store, markdownService)` — note this runner doesn't appear to be instantiated anywhere in `server/server.go`'s current wiring (only the unrelated `s3presign.Runner` is started there), so this holder looks unused in the live server path outside of its own package/tests.
