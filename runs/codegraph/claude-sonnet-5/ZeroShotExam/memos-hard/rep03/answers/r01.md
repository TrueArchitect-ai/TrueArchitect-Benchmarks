**Premise correction:** There is no Redis connection anywhere in this repository — I searched all `.go`/`.ts`/`.tsx`/config files for "redis" and found zero matches. This codebase (usememos/memos) does not use Redis for caching.

**Actual mechanism:** The cache layer is a custom in-process, thread-safe in-memory cache (`sync.Map`-backed) implemented in `store/cache/cache.go`. It's instantiated per-`Store` in `store/store.go:38-58`, which configures a shared `cache.Config` with:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

This same config backs three separate cache instances: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29, 51-53`).

For user entries specifically, `userCache` is used in `store/user.go` (e.g. `userCache.Set` at lines 98, 122, 132, 143, 167 and `userCache.Get` at line 150, keyed by `userCacheKey(userID)` at line 88) and invalidated on delete in `store/user_delete.go:40`. Since user cache writes call `Set` (not `SetWithTTL`), they use the cache's `DefaultTTL` — **10 minutes** — as defined in `store/cache/cache.go:59` (`DefaultConfig()`) and mirrored in the `Store`'s own `cacheConfig` in `store/store.go:41`.
