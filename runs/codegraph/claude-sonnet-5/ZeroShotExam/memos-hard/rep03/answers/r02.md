Premise correction: this repository (usememos/memos) has no per-user API rate-limiting middleware. There is no `RateLimit`/`Limiter`/throttle-style middleware registered anywhere in the Go server code.

What actually exists in the request pipeline (`server/router/api/v1/v1.go:64-146` and `server/router/api/v1/connect_interceptors.go`) is:
- `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — registered via `connect.WithInterceptors(...)` in `RegisterGateway` (`server/router/api/v1/v1.go:133-138`)
- A gRPC-Gateway auth middleware (`gatewayAuthMiddleware`, `server/router/api/v1/v1.go:69-93`)
- Concurrency limits unrelated to per-user rate limiting: `thumbnailSemaphore` (max 3 concurrent) and `imageProcessingSemaphore` (max 2 concurrent) in `NewAPIV1Service` (`server/router/api/v1/v1.go:59-60`), and a global `maxAPIRequestBytes = 256 << 20` request-size cap (`server/router/api/v1/v1.go:20`)

None of these implement per-user request-rate limiting (e.g., requests-per-minute per user). The only other hits for "limit/throttle" in the codebase are unrelated frontend editor utilities (`web/src/components/MemoEditor/Editor/formatting.ts`, `listIndent.ts`), not server middleware. If you're looking for rate limiting to add or expected it to already exist, it isn't present — this would need to be built from scratch, likely as another Connect interceptor alongside `AuthInterceptor`.
