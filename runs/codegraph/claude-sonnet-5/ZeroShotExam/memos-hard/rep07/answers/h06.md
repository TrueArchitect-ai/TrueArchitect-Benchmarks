**Handlers (RPC methods on `APIV1Service` implementing `MemoServiceServer`) whose paths transitively cause an outbound HTTP request to a user-configured URL:**

1. `CreateMemo` — `server/router/api/v1/memo_service.go:157` calls `s.DispatchMemoCreatedWebhook(...)`
2. `UpdateMemo` — via `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66-67`) calls `s.DispatchMemoUpdatedWebhook(...)`
3. `DeleteMemo` — `server/router/api/v1/memo_service.go:562` calls `s.DispatchMemoDeletedWebhook(...)`
4. `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:119` calls `s.DispatchMemoCommentCreatedWebhook(...)`

Each of these `Dispatch*Webhook` methods (`server/router/api/v1/memo_service_webhooks.go:15-46`) fetches the caller's configured webhook URLs via `s.Store.GetUserWebhooks` (user-configured `WebhooksUserSetting_Webhook.Url`, `proto/gen/store/user_setting.pb.go:917`) and calls `webhook.PostAsync(payload)`, which enqueues onto `asyncPostQueue`; four worker goroutines (`internal/webhook/webhook.go:42-55`) dequeue and call `Post`.

**Convergence function — path:**
`Post` — `internal/webhook/webhook.go:120` (issues the actual outbound request via `safeClient.Do(req)` at line 152, against `requestPayload.URL`, which originates from the user-configured webhook URL)

Note: a second, separate convergence point exists for link-preview fetching — `GetHTMLMeta` (`internal/httpgetter/html_meta.go:136`, using `httpClient.Get`) — reached from the `GetLinkMetadata`/`BatchGetLinkMetadata` RPCs, but there the URL is caller-supplied per-request rather than a persisted user *setting*, so I've treated the webhook path as the primary answer to "user-configured URL."
