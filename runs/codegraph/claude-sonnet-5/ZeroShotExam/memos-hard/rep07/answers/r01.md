Premise correction: this repository (usememos/memos) has no Redis connection anywhere — there's no Redis client, config, or dependency in the codebase (no `redis` references in `go.mod`/`go.sum`, no import of any Redis package). There is no "cache layer" backed by Redis, and no TTL applies to "user entries" in the sense implied.

Actual mechanism: caching in this codebase is done with in-process, in-memory maps guarded by mutexes, not an external Redis store:

- **RSS feed cache** — `server/router/rss/rss.go:35-49`: a `cacheEntry` struct held in a `map[string]*cacheEntry` (`RSSService.cache`) protected by `sync.RWMutex`. Entries expire after `defaultCacheDuration = 1 * time.Hour` (`server/router/rss/rss.go:26`), capped at `maxCacheSize = 50` entries (`server/router/rss/rss.go:27`). This caches rendered RSS/Atom feed XML per user/explore feed — not raw "user entries."
- **Instance stats cache** — `server/router/api/v1/instance_stats.go:21`: `instanceStatsCacheTTL = 60 * time.Second`, used to memoize `GetInstanceStats` results (`server/router/api/v1/v1.go:43`, `server/router/api/v1/instance_stats.go:67`). This is instance-wide statistics, not per-user data.

Neither cache involves Redis or a dedicated "user entries" TTL — both are local in-memory caches scoped to a single server process.
