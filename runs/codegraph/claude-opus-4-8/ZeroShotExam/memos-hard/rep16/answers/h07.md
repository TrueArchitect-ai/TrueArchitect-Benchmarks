The request path is `GET /file/users/:identifier/avatar`, served by the Echo file-server, resolving the avatar which is stored as a base64 data-URI in the user's `avatar_url` column.

Route registration — `FileServerService.RegisterRoutes` — server/router/fileserver/fileserver.go:121 (registers `GET /file/users/:identifier/avatar` → `serveUserAvatar`)
serveUserAvatar (serving handler) — server/router/fileserver/fileserver.go:168
getUserByUsername — server/router/fileserver/fileserver.go:715 (builds `store.FindUser{Username: &identifier}`)
Store.GetUser — store/user.go:148 (checks userCache, else lists)
Store.ListUsers — store/user.go:136 (delegates to the DB driver)
driver ListUsers (data layer, SELECTs `avatar_url` from the `user` table) — store/db/sqlite/user.go (and store/db/postgres/user.go, store/db/mysql/user.go:84)

Then the stored value is turned back into image bytes in the handler:
FileServerService.parseDataURI — server/router/fileserver/fileserver.go:737 (decodes the `data:<type>;base64,...` value from `user.AvatarURL` into raw image bytes, returned via `c.Blob`)

The stored data itself is the `avatar_url` column of the `user` table (struct field `User.AvatarURL`, store/user.go:43), holding a base64 data-URI.
