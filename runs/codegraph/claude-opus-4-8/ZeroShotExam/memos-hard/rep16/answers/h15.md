h15.

Memo visibility (who may view a memo / its content) is enforced independently on several server surfaces. The distinct enforcement sites:

gRPC/Connect API — single-memo read gate `checkMemoReadAccess` (Public served to all; non-public requires auth; Private requires creator) — server/router/api/v1/memo_service.go:39
gRPC/Connect API — `ListMemos` visibility filter (anonymous → PUBLIC only; other users → PUBLIC/PROTECTED unless own memos) — server/router/api/v1/memo_service.go:218
Memo comments — viewing comments on a Private parent memo requires creator/superuser — server/router/api/v1/memo_service_comments.go:41
File server — attachment download gated by parent memo visibility `checkAttachmentPermission` — server/router/fileserver/fileserver.go:649
Attachment service — `checkAttachmentAccess` gates GetAttachmentBinary by parent memo visibility — server/router/api/v1/attachment_service.go:451
SSE hub — live-event delivery filter `canReceive` (Private/Protected events only to creator/admin) — server/router/api/v1/sse_hub.go:135 (with helper server/router/api/v1/sse_event_helpers.go)
RSS feed — restricted to `store.Public` memos only — server/router/rss/rss.go:90
Frontend SSR permalink metadata — restricted to `store.Public` memos only — server/router/frontend/frontend.go:150

The store layer (`ListMemos` in store/db/mysql/memo.go, store/db/postgres/memo.go) only applies the `VisibilityList` filter it is handed; it does not itself decide who the viewer is — the authorization decisions live at the sites above.
