**Premise correction:** There is no nightly *database-cleanup* job actually registered or running anywhere in this repository. The premise assumes a live scheduled job exists; it does not.

What actually exists is a standalone, self-contained cron scheduler *library* under `internal/scheduler/` that is never imported or instantiated by the application. The only things that import it are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`) — no production code calls `scheduler.New()` or registers any job.

The "cleanup" job you're likely referring to appears only in illustrative example/doc code, not in a real schedule:

- `internal/scheduler/example_test.go:97-106` — an `Example_multipleJobs` demo registers a job named `"cleanup"` with schedule `"0 2 * * *"` and the comment "Cleanup old data every night at 2 AM". Its handler just prints `"Cleaning up old data..."` — there is no database interaction.
- `internal/scheduler/doc.go:14-16` — the package doc comment shows a sample `"daily-cleanup"` job with `Schedule: "0 2 * * *", // 2 AM daily`.

So the closest match is a *2 AM* example, but it is (a) not a database job — it touches no DB, and (b) not an actually-scheduled job — it lives only in documentation/example code. The only real cron in the repo is a GitHub Actions "stale" workflow (`.github/workflows/stale.yml:5`, `cron: "0 */8 * * *"`), which is unrelated to database cleanup.
