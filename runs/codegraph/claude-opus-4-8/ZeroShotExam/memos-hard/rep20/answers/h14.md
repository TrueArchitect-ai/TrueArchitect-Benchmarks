**Computation site.** The derived metadata is the memo's `Payload` — specifically `MemoPayload.Property` and `Payload.Tags` (defined in `proto/gen/store/memo.pb.go:84`, the `MemoPayload_Property` struct). It is (re)computed by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which calls `markdownService.ExtractAll(memo.Content)` and copies `data.Tags` and `data.Property` onto the memo. The actual extraction logic lives in the goldmark-based markdown service `ExtractAll` at `internal/markdown/markdown.go:356` (its single-pass equivalent of `ExtractProperties` at `internal/markdown/markdown.go:193`), which walks the parsed AST.

**Triggers (what causes recomputation).** `RebuildMemoPayload` is invoked on:
- **Memo creation** — `CreateMemo` in `server/router/api/v1/memo_service.go:108`.
- **Memo update** — `UpdateMemo` in `server/router/api/v1/memo_service.go` (calls `RebuildMemoPayload`, then persists the new `Payload`).
- **Bulk backfill** — the `Runner.RunOnce` job in `server/runner/memopayload/runner.go:27`, which iterates all memos in batches and rebuilds+persists each payload.

Recomputation is content-driven; the resulting `Payload` is then written to the `memo.payload` column by the DB layer (`store/db/{sqlite,postgres,mysql}/memo.go`).

**Extracted properties.** From walking the markdown AST (`internal/markdown/markdown.go:356`–421):
- `Tags` — deduplicated (case-preserving) list of `#tags` (excluding tags inside links/images); also `Mentions` collected in the same pass.
- `Property.Title` — text of the first block if it is an H1 heading.
- `Property.HasLink` — true if any link node exists.
- `Property.HasCode` — true for any code block, fenced code block, or inline code span.
- `Property.HasTaskList` — true if any task checkbox exists.
- `Property.HasIncompleteTasks` — true if any task checkbox is unchecked.
