**No.** The MySQL store driver (`mysql.NewDB`) is constructed only inside the driver-selection factory.

Evidence:
- The MySQL driver constructor is `NewDB` in `store/db/mysql/mysql.go:20`, returning a `store.Driver`.
- The only package that imports `github.com/usememos/memos/store/db/mysql` is `store/db/db.go` (grep for the import path returns exactly one file).
- The only call to `mysql.NewDB(...)` in the entire codebase is `store/db/db.go:22`, inside `NewDBDriver` — the factory that switches on `profile.Driver` (`store/db/db.go:14-32`). CodeGraph's blast radius confirms `NewDB (store/db/mysql/mysql.go:20)` has just **1 caller**, in `store/db/db.go`.
- The other `mysql.*` references in test code (`store/test/containers.go`, e.g. lines 101–105, 145) are calls into the third-party `testcontainers-go/modules/mysql` package and `sql.Open("mysql", ...)` with the `go-sql-driver/mysql` SQL driver — not the Memos MySQL store driver. Likewise, the various `case "mysql":` branches (e.g. `store/test/store.go:88`, `attachment_service.go:405`, `shortcut_service.go:348`) are string-based dialect switches, not driver construction.

So the MySQL store driver is never instantiated directly outside `NewDBDriver`.
