**Premise correction:** This repository (the [usememos/memos](https://github.com/usememos/memos) project) does **not** expose a GraphQL API, and there is no GraphQL schema anywhere in it. The public API is not GraphQL-based at all, so there is no `.graphql` schema file to point to. (A repo-wide search for "graphql" returns no matches in Go/TS/proto/JSON sources.)

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC services**, with the schema living in `.proto` files:

- **Public API schema** — `proto/api/v1/*.proto`, one file per service:
  - `auth_service.proto`, `memo_service.proto`, `user_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, plus shared `common.proto`
- **Storage-layer schema** — `proto/store/*.proto` (e.g. `memo.proto`, `user_setting.proto`, `attachment.proto`) — internal persistence types, not the public surface.

Code generation is driven by **buf** (`proto/buf.yaml`, `proto/buf.gen.yaml`). From those protos, buf generates:
- Go gRPC + **Connect** + **grpc-gateway** (REST/HTTP) bindings → `proto/gen/`
- An **OpenAPI** document (via the gnostic-openapi plugin) — so the HTTP surface is REST/OpenAPI, not GraphQL
- TypeScript client types (via `bufbuild/es`) → `web/src/types/proto`

So the answer to "where is the GraphQL schema" is: there isn't one — the public API is a gRPC/Connect + REST (grpc-gateway) API whose canonical schema is the Protobuf definitions in `proto/api/v1/`.
