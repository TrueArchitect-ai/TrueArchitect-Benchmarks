Memo view-visibility is enforced at multiple server surfaces (each independently decides who may see a memo based on `Visibility` + creator/current user):

`checkMemoReadAccess` (single-memo read gate for GetMemo) — server/router/api/v1/memo_service.go:34 (checks at lines 55–66)
`ListMemos` visibility scoping (list query restricted to PUBLIC / PUBLIC+PROTECTED / own) — server/router/api/v1/memo_service.go:218–227
`ListMemoAttachments` (attachment access gated by parent memo visibility) — server/router/api/v1/memo_attachment_service.go:214–222
`ListMemoReactions` / `UpsertMemoReaction` (reaction access gated by memo visibility) — server/router/api/v1/reaction_service.go:30–38, 83
Comment read access to parent memo — server/router/api/v1/memo_service_comments.go:41
RSS feeds (Explore/User RSS filtered to PUBLIC only) — server/router/rss/rss.go:90, 141
Frontend sitemap/SSR (public memos only) — server/router/frontend/frontend.go:150

The store layer (`store/db/mysql/memo.go`, `store/db/postgres/memo.go`, `store/memo.go`) only applies whatever `VisibilityList`/filters the callers set — it does not itself enforce who may view; enforcement lives in the router/API surfaces above.

Note: the store-layer `ListMemos`/`GetMemo` only apply the `VisibilityList`/filters they're handed — the actual "who may view" decisions are the router surfaces listed above.
