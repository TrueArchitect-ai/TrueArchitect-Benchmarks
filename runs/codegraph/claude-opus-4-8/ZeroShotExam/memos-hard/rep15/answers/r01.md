**Premise correction:** There is no Redis in this repository. The cache layer is not backed by Redis (or any external cache server) — there is no Redis connection to configure. The user cache is a process-local, in-memory cache.

**Actual mechanism:**

- The cache is a thread-safe in-memory implementation in `store/cache/cache.go` — a `Cache` struct built on `sync.Map` with atomic item counting and a background cleanup goroutine (`store/cache/cache.go:66-90`). No network client is involved.
- It is "configured" (instantiated, not connected) in `store/store.go`. `store.New` builds a `cache.Config` and creates three separate in-memory caches, including `userCache` (`store/store.go:38-58`):
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
  }
  ...
  userCache: cache.New(cacheConfig),
  ```
- User entries are written into this cache via `s.userCache.Set(...)` in `store/user.go` (e.g. `CreateUser`, `UpdateUser`, `ListUsers`, `GetUser` — `store/user.go:98,132,143,167`) and evicted on delete in `store/user_delete.go:40`. `Set` uses the default TTL (`store/cache/cache.go:92-95`).

**TTL for user entries:** **10 minutes** — the `DefaultTTL` set in `store/store.go:41` (matching `DefaultConfig()` in `store/cache/cache.go:59`). Since user entries are stored via the plain `Set` (not `SetWithTTL`), they inherit this default. Entries also expire lazily on read and via a cleanup loop that runs every 5 minutes, and the cache is capped at 1000 items with oldest-item eviction.

(For contrast, the RSS feed cache in `server/router/rss/rss.go` is a separate, unrelated in-memory `map[string]*cacheEntry` with a 1-hour duration — also not Redis.)
