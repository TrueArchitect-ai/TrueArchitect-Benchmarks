**Premise correction:** There is no nightly database-cleanup job in the cron scheduler — the premise doesn't hold for this repository.

What actually exists:

- `internal/scheduler/` is a **generic, reusable cron-scheduling library** (a `Scheduler`, `Job`, and a `ParseCronExpression` supporting 5/6-field cron). It defines no concrete jobs itself. Its docstring even gives `"0 0 * * *"` (daily at midnight) only as an *illustrative example* of the cron format (`internal/scheduler/job.go:21`), not as a registered job.
- Crucially, **nothing in production code registers any job with it.** Searches for `scheduler.Register(`, `scheduler.Job`, or imports of `internal/scheduler` outside the package itself return no hits — the package is exercised only by its own `_test.go` and example files. So there is no scheduled database-cleanup job (nightly or otherwise) and thus no configured time.
- The only "cleanup" that runs on a timer is an **in-memory cache** eviction loop in `store/cache/cache.go` (`cleanupLoop`, line 200), which fires on a `time.Ticker` set to `config.CleanupInterval`. This is not the cron scheduler, not the database, and not nightly — it's a periodic interval for evicting expired cache entries.

Since no such job is registered, no run time can be cited.

Sources: `internal/scheduler/job.go`, `internal/scheduler/scheduler.go`, `internal/scheduler/parser.go`, `store/cache/cache.go`.
