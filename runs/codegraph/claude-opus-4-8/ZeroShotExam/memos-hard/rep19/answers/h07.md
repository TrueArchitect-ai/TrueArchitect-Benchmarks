The image is served over Echo (not gRPC). A browser GETs `/file/users/:identifier/avatar`; the handler looks the user up by username and decodes the avatar, which is stored inline as a base64 data-URI in the `user.avatar_url` column.

Notes:
- The stored data itself is the `avatar_url` column of the `user` table (type `store.User.AvatarURL`, store/user.go:43), held as a `data:<type>;base64,...` URI rather than a file on disk — so the "data layer" terminus is that DB column, decoded in-process by `parseDataURI`.
- `Store.GetUser` first checks `userCache` only when looking up by ID; a username lookup always falls through to `ListUsers` → `driver.ListUsers` (the SQL query), so the DB is hit here.
- The DB driver is selected at runtime (sqlite/mysql/postgres); all three implement `ListUsers`/`GetUser` identically for this path.
