Memo view-visibility is enforced independently at these server sites:

Single-memo read gate (`checkMemoReadAccess`, applied on GetMemo / GetMemoByUID / ListMemoComments precheck) — server/router/api/v1/memo_service.go:39-68
ListMemos query filtering (anonymous → PUBLIC only; authed → own memos OR PUBLIC/PROTECTED) — server/router/api/v1/memo_service.go:218-226
ListMemoComments query filtering (anonymous → PUBLIC only; authed → own OR PUBLIC/PROTECTED) — server/router/api/v1/memo_service_comments.go:156-161
CreateMemoComment visibility gate (must be able to view the parent memo to comment on it) — server/router/api/v1/memo_service_comments.go:41-43
Attachment/file serving gate (`checkAttachmentPermission` — enforces the parent memo's visibility, share-token and anonymous-access exceptions) — server/router/fileserver/fileserver.go:649-704

The underlying `VisibilityList` SQL predicate that these API filters compile down to lives in the store drivers (store/db/sqlite/memo.go, store/db/postgres/memo.go, store/db/mysql/memo.go), but that's the mechanism the API-layer sites above drive, not an independent policy decision.
