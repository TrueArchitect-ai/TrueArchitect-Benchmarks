**Premise correction:** The repository does not contain any nightly database-cleanup job scheduled in the cron scheduler, so there is no scheduled time to report.

The premise assumes such a job exists and is wired up. It isn't:

- `internal/scheduler/` is a **standalone, generic cron library** (parser, `Scheduler`, `Job`, middleware). It defines no concrete jobs — callers register their own via `Scheduler.Register`. See `internal/scheduler/scheduler.go:70` and `internal/scheduler/job.go:14`.
- **Nothing in the application actually uses this scheduler.** Searching the server/store/cmd code for `internal/scheduler` or `scheduler.New`/`scheduler.Register` returns no non-test call sites — the library is never instantiated to register a database-cleanup (or any) job.
- The only thing resembling a "cleanup" job is a **documentation example**, not a real scheduled job: `internal/scheduler/doc.go:14-21` shows a sample `Job{Name: "daily-cleanup", Schedule: "0 2 * * *"}` (2 AM daily) purely to illustrate the API in a code comment.
- The actual periodic "cleanup" that runs in the app is unrelated to cron: an in-memory cache eviction loop on a 5-minute `time.Ticker`, not a cron-scheduled DB job — `store/cache/cache.go:60` / `cache.go:199-210` (`CleanupInterval: 5 * time.Minute`).

So there is no nightly database-cleanup cron entry to read a time from. If you're thinking of the `0 2 * * *` value, that's an illustrative snippet in `internal/scheduler/doc.go`, not a live scheduled job.
