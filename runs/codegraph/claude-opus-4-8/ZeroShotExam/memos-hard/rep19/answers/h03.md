The answer is clear from the source. The `internal/idp` package defines the abstraction (`IdentityProviderUserInfo`, and the provider interface referenced by `resolveSSOIdentity`), and `internal/idp/oauth2` ships the concrete OAuth2 implementation.

h03.
`internal/idp` (the provider abstraction — defines `IdentityProviderUserInfo` and the provider contract); implementation: `internal/idp/oauth2` (the concrete OAuth2 protocol implementation).

The wiring in `server/router/api/v1/auth_service_sso.go:104-134` (`resolveSSOIdentity`) imports both `github.com/usememos/memos/internal/idp` and `github.com/usememos/memos/internal/idp/oauth2`, and when a provider's type is `IdentityProvider_OAUTH2` it calls `oauth2.NewIdentityProvider(...)` then `ExchangeToken`/`UserInfo` (defined in `internal/idp/oauth2/oauth2.go:1-142`). OAuth2 is the only concrete protocol implementation that ships.
