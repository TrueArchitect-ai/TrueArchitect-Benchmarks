**Premise correction:** There is no Redis anywhere in this repository. A repo-wide search for "redis" (across Go, TS, YAML, TOML files) returns zero matches, and `go.mod` declares no Redis dependency. There is no Redis connection to configure — the cache layer is a **purely in-memory, in-process cache**. So the question's premise (a Redis-backed cache configured somewhere) does not hold.

**Actual mechanism:**

The cache is a hand-rolled thread-safe in-memory cache implemented in `store/cache/cache.go`. It stores entries in a `sync.Map` with per-item expiration timestamps and a background `cleanupLoop` goroutine — no external datastore, no network connection.

- **Cache implementation:** `store/cache/cache.go` — `Cache` struct built on `sync.Map`; `Set` uses the config's `DefaultTTL`, `SetWithTTL` allows a custom TTL, and a cleanup goroutine evicts expired items.
- **Where it's "configured":** `store/store.go:38-58` (`store.New`). The config is a literal `cache.Config` struct, not a connection string:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
- **User entries specifically:** The store creates three separate in-memory caches sharing that same config — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`). User and user-setting entries are written via `s.userSettingCache.Set(...)` (e.g. `store/user_setting.go:59,78,106`), and `Cache.Set` applies the default TTL. **So the TTL applying to user (and user-setting) entries is 10 minutes** (`store/cache/cache.go:98` `Set` → `SetWithTTL(..., c.config.DefaultTTL)`, with `DefaultTTL` = 10 minutes from `store/store.go:41`).

Note: there is a second, unrelated cache in `server/router/rss/rss.go` — a small map-based RSS feed cache (`cacheEntry`, `getFromCache`/`putInCache`) with its own `defaultCacheDuration = 1 * time.Hour` (`server/router/rss/rss.go:25`). It caches rendered RSS XML keyed by `"explore"` and `"user:<username>"`, but it is also in-memory (not Redis) and is not the user-record cache.
