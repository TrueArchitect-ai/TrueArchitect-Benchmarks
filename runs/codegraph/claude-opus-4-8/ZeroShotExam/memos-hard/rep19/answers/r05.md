**Premise correction:** This repository (memos) does **not** use GraphQL. There is no GraphQL schema, no `.graphql`/`.gql` files, no gqlgen/apollo dependency, and no GraphQL server — a repo-wide search for `graphql` returns zero matches in Go, TypeScript, proto, and config files. So there is no "GraphQL schema for the public API" to point to.

**Actual API surface:** The public API is defined as **gRPC services using Protocol Buffers**, with a REST/HTTP gateway generated on top.

- **Schema source of truth:** `.proto` files under `proto/api/v1/` — e.g. `proto/api/v1/memo_service.proto`, `auth_service.proto`, `user_service.proto`, `attachment_service.proto`, `ai_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, plus shared `common.proto`. Store-layer messages live in `proto/store/*.proto`.
- **Codegen config:** `proto/buf.yaml`, `proto/buf.gen.yaml`, `proto/buf.lock`; generated code lands in `proto/gen/`.
- **REST + OpenAPI:** HTTP endpoints are produced via grpc-gateway from these same protos, and an OpenAPI spec is embedded (`proto/openapi_embed.go`).
- **Additional surface:** an MCP server under `server/router/mcp/` (with its own `openapi.go`/JSON-schema tooling), which is JSON-Schema/OpenAPI-based — still not GraphQL.

In short: the public API contract is the protobuf definitions in `proto/api/v1/`, exposed over gRPC and REST(+OpenAPI) — not GraphQL.
