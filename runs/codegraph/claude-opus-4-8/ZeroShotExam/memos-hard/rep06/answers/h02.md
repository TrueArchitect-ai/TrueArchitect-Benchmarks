**Delivery function** — `Post` in `internal/webhook/webhook.go:120`. This is where the outbound HTTP POST actually executes: it marshals the payload, builds the request, adds the optional HMAC signature headers, and fires it via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. (`PostAsync` at `internal/webhook/webhook.go:184` just enqueues onto a bounded channel; four background workers started in `init` drain it and call `Post`.)

**Protection mechanism** — `safeDialContext` in `internal/webhook/webhook.go:59`, wired in as the `DialContext` of the shared `safeClient`'s `http.Transport` (`internal/webhook/webhook.go:32-37`). At dial time it splits host/port, resolves the hostname via `net.DefaultResolver.LookupHost`, and rejects the connection if any resolved IP satisfies `isReservedIP` — blocking reserved/private ranges. Because the check happens on the post-resolution IPs at dial time, it also defeats DNS-rebinding attempts. This is what stops the webhook from being pointed at internal/private network addresses (SSRF guard).

Note: this is a dial-time guard only — the target URL itself is stored as-supplied and not validated up front, so protection relies entirely on `safeDialContext` running for every dispatch through `safeClient`.
