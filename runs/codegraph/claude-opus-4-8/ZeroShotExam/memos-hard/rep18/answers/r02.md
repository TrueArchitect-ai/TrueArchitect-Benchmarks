**Premise correction: there is no per-user API rate-limiting middleware in this repository.** The question assumes one exists and is registered somewhere with configured request limits — but no such middleware is present.

What the API middleware/interceptor chain actually consists of, registered in `server/router/api/v1/v1.go` (`RegisterGateway`, lines 65–146):

- **Connect interceptors** (`connect.WithInterceptors`, lines 133–138): `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — defined in `server/router/api/v1/connect_interceptors.go`. None of these throttles or counts requests per user.
- **gRPC-Gateway middleware** (`gatewayAuthMiddleware`, lines 69–93): authentication/authorization only, delegating to the shared `Authorizer` in `server/router/api/v1/authz.go`.

None enforces a rate limit. The `AuthInterceptor`/`Authorizer` do per-request *authentication and access-policy* checks, not rate limiting.

The only "limits" in this area are unrelated to per-user request rate:
- **Request body size cap**: `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` / `connect.WithReadMaxBytes` (`server/router/api/v1/v1.go:20`, 126, 141, 144).
- **Concurrency semaphores** (global, not per-user): `thumbnailSemaphore` = 3, `imageProcessingSemaphore` = 2 (`server/router/api/v1/v1.go:59–60`).

Other apparent matches are not middleware: `internal/email/doc.go:86` only mentions rate-limiting email in a doc comment, and the `web/src/.../formatting.ts` hits are markdown "delimiter" tokens. `go.mod` pulls in no rate-limiting library (e.g. `golang.org/x/time/rate`, tollbooth, etc.).

So: no per-user rate-limiting middleware is registered, and there are no per-user request limits to report.
