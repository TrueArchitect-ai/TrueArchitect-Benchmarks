**Premise correction:** This repository (Memos) has **no GraphQL schema**. There is no `.graphql`/`.gql` schema, no schema-definition-language file, and no GraphQL server (no `graphql-go`, `gqlgen`, Apollo, etc.). A repo-wide case-insensitive search for `graphql` returns zero matches in any `.go`, `.ts`, or `.proto` file. So the premise that a GraphQL API exists is incorrect.

**Actual public API surface — Protocol Buffers / gRPC with a REST (JSON) gateway:**

The public API is defined in **Protobuf service definitions** under `proto/api/v1/`:
- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto`

Each `service`/`rpc` carries a `google.api.http` annotation (e.g. `post: "/api/v1/memos"`, `get: "/api/v1/memos"`), so the same definitions serve both **gRPC** and a **REST/JSON HTTP gateway** rooted at `/api/v1`.

**Code generation** is driven by `proto/buf.gen.yaml`, which emits:
- Go gRPC + grpc-gateway stubs into `proto/gen/`,
- **OpenAPI** (via the `google-gnostic-openapi` plugin) as the machine-readable public-API description — served/embedded through `server/router/api/openapi_embed.go`,
- TypeScript client types into `web/src/types/proto`.

The gateway/routers wiring these services lives under `server/router/api/`. (Separately, `server/router/mcp/` exposes an MCP + OpenAPI adapter — the `jsonSchema`/`okSchema` symbols from the CodeGraph context are JSON Schema for MCP tools, not GraphQL.)

So: the public API is **proto-defined gRPC + REST at `/api/v1`**, described by generated OpenAPI — not GraphQL.
