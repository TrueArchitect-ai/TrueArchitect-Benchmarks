The premise is mistaken on two counts: there is **no nightly _database_-cleanup job registered anywhere in this application**, and the only cleanup job that exists is illustrative example/doc code, not a wired-up production job.

What actually exists:

- `internal/scheduler/` is a **generic, standalone cron library** (`Scheduler`, `Job`, `ParseCronExpression`). A repo-wide search for `scheduler.New(...)` / `scheduler.Register(...)` outside the package and its tests returns nothing — no part of the application registers any job with it.
- The only "cleanup at night" references live in non-executing documentation/examples:
  - `internal/scheduler/doc.go:14-16` — a doc-comment example named `"daily-cleanup"` with `Schedule: "0 2 * * *"` (commented "2 AM daily"), handler is just a placeholder ("Your cleanup logic here").
  - `internal/scheduler/example_test.go:97-100` — an `Example_multipleJobs` test registering a job named `"cleanup"`, `Schedule: "0 2 * * *"` ("every night at 2 AM"), whose handler merely prints `"Cleaning up old data..."`. It cleans up "old data," not a database specifically.

Separately, there is an unrelated cache cleanup at `store/cache/cache.go:200` (`cleanupLoop`), but it runs on a `CleanupInterval` ticker, not a cron time, and evicts expired in-memory cache items — not a database.

So: if you're asking about the example cron cleanup job, its schedule is `0 2 * * *` (**02:00 / 2 AM**). But there is no real nightly database-cleanup job scheduled in this codebase — the 2 AM figure comes only from documentation/example code.
