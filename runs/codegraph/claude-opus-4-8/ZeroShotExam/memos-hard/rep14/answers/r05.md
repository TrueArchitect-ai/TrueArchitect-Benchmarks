**Premise correction:** There is no GraphQL schema in this repository. The public API is **not** GraphQL — a repo-wide search for `graphql` (across `.go`, `.ts`, `.tsx`, and `.proto` files) returns zero matches. The premise of the question is mistaken.

**Actual API surface:** The public API is defined with **Protocol Buffers (gRPC)**, exposed over HTTP via grpc-gateway and documented with OpenAPI. The schema lives in the `proto/` directory:

- **`proto/api/v1/*.proto`** — the public API v1 service definitions and messages, e.g. `proto/api/v1/memo_service.proto`, `proto/api/v1/user_service.proto`, `proto/api/v1/auth_service.proto`, `proto/api/v1/attachment_service.proto`, `proto/api/v1/instance_service.proto`, `proto/api/v1/shortcut_service.proto`, `proto/api/v1/ai_service.proto`, `proto/api/v1/idp_service.proto`, and `proto/api/v1/common.proto`.
- **`proto/store/*.proto`** — internal storage message definitions (not the public surface).
- **`proto/buf.yaml`** / **`proto/buf.gen.yaml`** — the Buf build/codegen configuration; generated code lands in `proto/gen/`.
- **`proto/openapi_embed.go`** — embeds the generated OpenAPI spec for the REST surface.

There is also an MCP/OpenAPI adapter layer under `server/router/mcp/` (e.g. `openapi.go`, `catalog.go`), but that builds JSON Schema for MCP tools over the same proto-defined services — it is not a GraphQL schema.
