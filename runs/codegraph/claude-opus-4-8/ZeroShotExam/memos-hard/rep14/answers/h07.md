The avatar bytes are stored inline in the user row's `avatar_url` column as a base64 data URI; a browser fetches them via `GET /file/users/:identifier/avatar`. The chain from serving handler to stored data:

RegisterRoutes (`fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)`) — server/router/fileserver/fileserver.go:124
serveUserAvatar — server/router/fileserver/fileserver.go:168
getUserByUsername (`s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`) — server/router/fileserver/fileserver.go:715
Store.GetUser — store/user.go:148
Store.ListUsers (`s.driver.ListUsers`) — store/user.go:136
driver.ListUsers (DB layer; reads the `avatar_url` column from the `user` table) — store/db/sqlite/user.go (and store/db/postgres/user.go, store/db/mysql/user.go)

Back in `serveUserAvatar`, the returned `user.AvatarURL` is decoded by `parseDataURI`, checked against `avatarAllowedTypes`, and written to the response with `c.Blob(...)` (server/router/fileserver/fileserver.go:196–209).

Note: `getUserByUsername` looks up by `Username` only, so the `:identifier` path segment must be the target user's username.
