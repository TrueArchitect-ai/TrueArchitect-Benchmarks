**Premise correction:** The question assumes this repository has a per-user API rate-limiting middleware. It does not. There is no rate-limiting middleware registered anywhere in the codebase, and therefore no per-user request limits to report.

What the codebase actually has:

- The API server (this is the **memos** project) registers its interceptor/middleware chain in `server/router/api/v1/v1.go:133-136` via `connect.WithInterceptors(...)`. The registered interceptors are exactly three, defined in `server/router/api/v1/connect_interceptors.go`:
  - `NewMetadataInterceptor()` — converts HTTP headers to gRPC metadata
  - `NewLoggingInterceptor(logStacktraces)` — request logging
  - `NewRecoveryInterceptor(logStacktraces)` — panic recovery

None of these performs rate limiting. There is no rate-limiter interceptor, no `golang.org/x/time/rate`/limiter dependency, and no `429 Too Many Requests` handling in the server code.

The only occurrence of the phrase "rate limit" in the entire repo is an aspirational security note in a doc comment — `internal/email/doc.go:86` (`- Rate limit email sending to prevent abuse`) — which describes a general best practice for SMTP, not an implemented feature, and is unrelated to per-user API request limiting.

So there is no location to cite for such middleware and no configured request limits, because the feature described in the premise doesn't exist in this repository.
