**Premise correction:** There is no "nightly database-cleanup job" in the cron scheduler. The `internal/scheduler` package is a **generic, general-purpose cron scheduler library** (a reusable engine), not a place where application jobs like a database cleanup are actually registered. Its core files (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`) define the machinery — `Job`, `Register`, `Start`, cron parsing — but register no concrete jobs. A repo-wide search finds no database-cleanup job wired into the scheduler anywhere in production code.

The question appears to conflate two unrelated things:

1. **Illustrative examples only** — the sole "cleanup at night" references are documentation/test snippets, not a real scheduled job:
   - `internal/scheduler/doc.go:15-16` — a package-doc example job named `"daily-cleanup"` with `Schedule: "0 2 * * *"` ("2 AM daily"), whose handler is just a `// Your cleanup logic here` placeholder.
   - `internal/scheduler/example_test.go:97-100` — an example job named `"cleanup"` ("Cleanup old data every night at 2 AM"), `Schedule: "0 2 * * *"`. This cleans "old data" generically, not a database, and exists only as a runnable doc example.

2. **The actual database/cache cleanup that exists** is not cron-scheduled and not nightly. In `store/cache/cache.go`, `Cache.cleanupLoop` (line 200) removes expired items on a `time.Ticker` at `config.CleanupInterval` — an interval-based background goroutine, not a clock-time cron job.

So: no nightly database-cleanup job is scheduled in the cron scheduler at all. The only "2 AM" cleanup you'll find is placeholder example code (`0 2 * * *`), and the real cache cleanup runs on a recurring interval rather than at a fixed nightly time.
