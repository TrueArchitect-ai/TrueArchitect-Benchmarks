**Premise correction: this repository has no per-user API rate-limiting middleware.** There is nothing to register and no request limits to report.

I verified the full middleware/interceptor stack:

- **Connect/gRPC interceptor chain** — registered in `server/router/api/v1/v1.go:133-137` via `connect.WithInterceptors(...)`. The complete chain is: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go` and `authz.go`). None of these throttle or rate-limit; the auth interceptor does authorization only.
- **Echo HTTP middleware** — registered in `server/server.go:51-52` (`middleware.Recover()`, `newCORSMiddleware`) and `server/router/frontend/frontend.go:54-59` (static file serving + SPA fallback). No rate limiter here either.

The only "rate limit" the codebase mentions is a *future design note*, not code: a comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") describing possible enhancements to the email subsystem — unrelated to API requests and not implemented.

The one request-size guard that does exist is a byte cap, not a rate limit: `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141` — this bounds request *body size*, not request *frequency* per user.

So there is no per-user (or global) request-count/rate limiting on the API, and consequently no request limits to cite.
