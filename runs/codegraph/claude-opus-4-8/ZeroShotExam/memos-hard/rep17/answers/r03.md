The question's premise is incorrect: there is **no nightly database-cleanup job scheduled in the cron scheduler**. The `internal/scheduler` package is a standalone, general-purpose cron library — it defines the machinery (`Scheduler`, `Job`, `ParseCronExpression`) but nothing in the codebase actually registers a database-cleanup job with it. A grep for `scheduler.New(` / `.Register(` across non-test code returns no callers, so no real jobs (nightly or otherwise) are ever wired up.

What likely inspired the question is a **documentation example**, not a live job:

- `internal/scheduler/doc.go:14-16` — a package-doc example registering a job named `"daily-cleanup"` with `Schedule: "0 2 * * *", // 2 AM daily`.
- `internal/scheduler/job.go:21` — a comment giving `"0 0 * * *"` as an example of "daily at midnight".

So the closest thing to your premise is an illustrative "daily-cleanup" example that runs at **2 AM** (`0 2 * * *`) — but it's sample code in a doc comment, not an actual scheduled database-cleanup job.

Separately, there is a real cleanup mechanism that is *not* cron-based: `store/cache/cache.go:200` (`cleanupLoop`) evicts expired in-memory cache items on a `CleanupInterval` ticker — but that's cache eviction, not a database cleanup, and it isn't scheduled via the cron scheduler or tied to any nightly time.
