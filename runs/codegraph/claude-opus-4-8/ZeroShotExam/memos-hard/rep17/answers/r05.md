**Premise correction:** There is no GraphQL schema anywhere in this repository. A case-insensitive search for `graphql` across all Go, TypeScript, `.proto`, and JSON files returns zero matches. This is the Memos project, whose public API is **gRPC/Protocol Buffers** with a REST + OpenAPI gateway generated from those definitions — not GraphQL.

**Actual public API surface:**

- **Schema source of truth — Protobuf service definitions** in `proto/api/v1/`:
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/common.proto`
- **Store-layer messages** (internal persistence, not the public surface) in `proto/store/*.proto`.
- **Generated code** lives under `proto/gen/`, and the build is driven by `proto/buf.yaml` / `proto/buf.gen.yaml` (Buf toolchain).
- **REST/OpenAPI** is derived from the protos via grpc-gateway; the OpenAPI document is wired through `proto/openapi_embed.go`.
- **Server routing** that mounts these APIs is in `server/router/api/` (plus `server/router/mcp`, `rss`, `fileserver`, `frontend` for non-core surfaces).

So the closest thing to a "public API schema" is the Protobuf/gRPC service set in `proto/api/v1/`, exposed additionally as REST via an OpenAPI spec — there is no GraphQL layer.
