**impl** — The Markdown `Service` interface (`internal/markdown/markdown.go:31`) has exactly one concrete implementation that runs at runtime: the unexported `service` struct (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown` engine. (Its `RenderMarkdown` method internally delegates to the `MarkdownRenderer` helper at `internal/markdown/renderer/markdown_renderer.go:15`, but that renderer is not itself behind the `Service` interface — it's a collaborator, not an implementation of it.)

**construction** — Built by the factory `markdown.NewService(...)` (`internal/markdown/markdown.go:85`), which returns `&service{md: goldmark.New(...)}`. In production there is a single construction site: inside `NewAPIV1Service` at `server/router/api/v1/v1.go:48`, configured with `WithTagExtension()`/`WithMentionExtension()`. That one instance is then shared — `server/server.go:76` creates the API service, and `server/server.go:85` passes `apiV1Service.MarkdownService` into the RSS service. (Additional `NewService` calls exist only in tests: `server/router/api/v1/test/test_helper.go:44`, `server/router/rss/rss_test.go:54`, `server/router/fileserver/fileserver_test.go:427`, `internal/markdown/markdown_test.go`.)
