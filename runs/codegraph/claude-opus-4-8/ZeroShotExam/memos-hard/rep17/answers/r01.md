**Premise correction:** There is no Redis anywhere in this repository. A search for `redis` across all Go, config, and dependency files returns zero matches. The cache layer is **not** backed by Redis (or any external/network cache) — it is a self-contained, thread-safe, in-process in-memory cache. There is no "Redis connection" to configure.

**Actual mechanism:**

- The cache implementation lives in `store/cache/cache.go` — a `Cache` struct built on `sync.Map` with an `atomic.Int64` item counter and a background `cleanupLoop` goroutine (`store/cache/cache.go:66-85`). It implements a local `Interface` (`store/cache/cache.go:10-32`), not a Redis client.

- The cache is "configured" — instantiated, not connected — in `store/store.go`. The `Store.New` constructor (`store/store.go:38-61`) builds a `cache.Config` inline and creates three separate in-memory caches: `instanceSettingCache`, `userCache`, and `userSettingCache`, each via `cache.New(cacheConfig)`. There is no host, port, or DSN — just Go struct construction.

**TTL for user entries:**

User entries are stored in `userCache` (`store/store.go:28,52`). Writes go through `s.userCache.Set(...)` in `store/user.go` (e.g. `CreateUser`, `UpdateUser`, `ListUsers`, `GetUser` at lines 98, 132, 143, 167). The `Set` method applies the cache's **default TTL** (`store/cache/cache.go:92-95`) — no per-user custom TTL is used.

That default TTL is **10 minutes**, set in the `cacheConfig` in `store/store.go:41` (`DefaultTTL: 10 * time.Minute`), matching `cache.DefaultConfig()` at `store/cache/cache.go:57-64`. A `CleanupInterval` of 5 minutes sweeps expired entries, and expired entries are also evicted lazily on `Get` (`store/cache/cache.go:135-144`).

So: **user cache entries live for 10 minutes** (the shared default TTL), stored in an in-memory `sync.Map`-backed cache — not Redis.
