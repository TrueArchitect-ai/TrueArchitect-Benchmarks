Memo view-visibility (who may read a memo/its content) is enforced independently at several server surfaces:

Single-memo read access (GetMemo + comment retrieval) — server/router/api/v1/memo_service.go (`checkMemoReadAccess`, lines 39–68; enforces private→creator-only, non-public→auth required)
ListMemos result filtering — server/router/api/v1/memo_service.go (lines ~217–227; narrows `VisibilityList`/filter to PUBLIC for anonymous, PUBLIC+PROTECTED + own for authed users)
Attachment binary access via API (respects parent memo visibility) — server/router/api/v1/attachment_service.go (lines ~436–454)
Static/raw file server for memo attachments — server/router/fileserver/fileserver.go (lines 677, 699)
RSS feed (public memos only) — server/router/rss/rss.go (lines 90, 141: `VisibilityList: [Public]`)
Frontend SSR/metadata embed (public memos only) — server/router/frontend/frontend.go (line 150: `VisibilityList: [Public]`)

The first three/four are the primary "who may view a memo" enforcement sites; RSS and frontend SSR additionally restrict served memos to `Public`.
