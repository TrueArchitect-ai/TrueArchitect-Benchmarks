**Delivery function** — `Post` at `internal/webhook/webhook.go:120`. This is where the outbound HTTP POST actually executes: it marshals the payload, builds the request, optionally adds the HMAC signature headers, and calls `safeClient.Do(req)` (line 152). `PostAsync` (line 184) just enqueues onto a bounded channel; four background workers started in `init` (line 42) drain the queue and each call `Post`, which is what dispatches on the wire. The webhook-related callers (e.g. `dispatchMemoRelatedWebhook`, `DispatchMemoCommentCreatedWebhook`) live in `server/router/api/v1/memo_service_webhooks.go`, but the network I/O happens in `Post`.

**Protection mechanism** — `safeDialContext` at `internal/webhook/webhook.go:59` (with its helper `isReservedIP`). All webhook requests go through the shared `safeClient` (line 32), whose `http.Transport.DialContext` is set to `safeDialContext`. At dial time it splits host/port, resolves the hostname via `net.DefaultResolver.LookupHost`, and rejects the connection if any resolved IP falls in a reserved/private range (`isReservedIP`), returning `"webhook: connection to reserved/private IP address is not allowed"`. Because the check runs against the *resolved* IPs at connection time rather than on the URL string, it also defeats DNS-rebinding attempts — this is the SSRF guard that prevents webhooks from being pointed at internal network addresses.
