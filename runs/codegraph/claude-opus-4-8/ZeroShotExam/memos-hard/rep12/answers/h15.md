h15.

Memo visibility (who may read a memo) is enforced at several distinct server surfaces, all in `server/router/api/v1/`. The core gate is the `checkMemoReadAccess` helper, and it is duplicated inline across the other read surfaces (list-query filters + per-object checks):

checkMemoReadAccess helper (single-memo read gate: PRIVATE→creator only, PROTECTED→signed-in) — server/router/api/v1/memo_service.go:39 (called by GetMemo at :356/:367)

ListMemos visibility filter (anonymous→PUBLIC only; signed-in→own OR PUBLIC/PROTECTED) — server/router/api/v1/memo_service.go:218

ListMemoComments read-access + visibility filter (checkMemoReadAccess at :148, comment filter at :160) and CreateMemoComment private check at :41 — server/router/api/v1/memo_service_comments.go

Reaction access checks (ListMemoReactions/UpsertMemoReaction: PRIVATE blocked unless creator/superuser) — server/router/api/v1/reaction_service.go:38 and :83

Memo attachment visibility check (PRIVATE blocked unless creator/superuser) — server/router/api/v1/memo_attachment_service.go:222

Attachment access check (getMemo-backed) — server/router/api/v1/attachment_service.go:451

Memo relations visibility filter (creator_id OR PUBLIC/PROTECTED) — server/router/api/v1/memo_relation_service.go:111

User memo-stats visibility filter — server/router/api/v1/user_service_stats.go:84 and :218

Converter relation/comment filter (creator_id OR PUBLIC/PROTECTED) — server/router/api/v1/memo_service_converter.go:186

The three primary, canonical enforcement sites are the first three: the `checkMemoReadAccess` helper (`memo_service.go:39`), the `ListMemos` query filter (`memo_service.go:218`), and the comment-read filter (`memo_service_comments.go`). The reaction, attachment, relation, and stats surfaces re-enforce the same PRIVATE/PROTECTED rules independently.
