The avatar is not a separate file on disk — it is stored inline in the `user.avatar_url` column as a base64 `data:` URI, so the "data layer" here is a `SELECT` against the `user` table.


Notes:
- `serveUserAvatar` reads `user.AvatarURL` (populated by the `avatar_url` DB column, scanned in `ListUsers` at `store/db/mysql/user.go:170`), then `parseDataURI` (fileserver.go:737) splits the `data:<type>;base64,<...>` string and base64-decodes it, and the handler returns the bytes via `c.Blob` (fileserver.go:209).
- `(*Store).GetUser` first checks an in-memory `userCache` only when looking up by ID; the avatar path looks up by `Username`, so it always falls through to `ListUsers` → the driver → the database.
- The concrete driver is chosen at runtime via the `Driver` interface (`store/driver.go:47`); MySQL, Postgres, and SQLite each implement `ListUsers`.
