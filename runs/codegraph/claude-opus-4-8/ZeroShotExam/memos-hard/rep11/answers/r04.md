**Premise correction:** The webhook delivery workers consume from *neither* NATS nor RabbitMQ. This repository (memos) uses no external message broker for webhooks at all — there is no queue "declared" in any broker.

**Actual mechanism:** Webhook delivery is handled entirely in-process using a buffered Go channel and a fixed pool of goroutine workers, all within `internal/webhook/webhook.go`:

- The "queue" is a plain buffered channel declared as a package-level variable:
  `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39` (capacity 128).
- The "workers" are 4 goroutines spawned in `init()` (`internal/webhook/webhook.go:42-55`). Each loops `for payload := range asyncPostQueue` and calls `Post(payload)` to perform the actual HTTP `POST` to the webhook URL (`internal/webhook/webhook.go:120`).
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send onto `asyncPostQueue`; if the channel/buffer is full it drops the dispatch and logs a warning rather than blocking.

So delivery is a bounded in-memory channel + 4-goroutine worker pool inside the Go process, not a message-broker-backed queue.
