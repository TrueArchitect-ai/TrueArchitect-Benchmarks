The premise is mistaken — there is no nightly database-cleanup job in this repository's cron scheduler, so it has no scheduled run time.

What actually exists:

- `internal/scheduler/` is a **generic, standalone cron-scheduler library** (`Scheduler`, `Job`, `ParseCronExpression`, middleware). A `Job` carries a `Name`, a cron `Schedule` string, and a `Handler` (`internal/scheduler/job.go:14`), and jobs are added via `Scheduler.Register` / run via `Start` (`internal/scheduler/scheduler.go:70`, `:91`). But no cron expressions or concrete jobs are defined here — the package only provides the machinery.
- Critically, this package is **never imported or used anywhere else in the codebase**. A repo-wide search for imports of `internal/scheduler` and for any `scheduler.New` / `scheduler.Register` / `&scheduler.Job{...}` calls outside the package itself returns nothing. So no database-cleanup job (nor any other job) is registered with the cron scheduler at all.

The only "cleanup" that runs on a timer is unrelated to both cron and the database: the **in-memory cache** in `store/cache/cache.go` runs a `cleanupLoop` (`store/cache/cache.go:200`) driven by a `time.Ticker` on `config.CleanupInterval` (an interval, not a cron time), evicting expired cache entries — not a nightly database cleanup.

So the correct statement is: there is no nightly database-cleanup cron job, and therefore no scheduled time to report.
