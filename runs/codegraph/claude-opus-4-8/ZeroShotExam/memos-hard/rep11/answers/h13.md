**impl** — The `markdown.Service` interface (`internal/markdown/markdown.go:31-55`) has exactly one concrete implementation: the unexported `service` struct (`internal/markdown/markdown.go:57-60`), which wraps a `goldmark.Markdown` parser. It is the only type that satisfies the interface at runtime (`implements: service → Service`). (Internally, `service.RenderMarkdown` delegates to the separate `renderer.MarkdownRenderer` helper — `internal/markdown/renderer/markdown_renderer.go` — but that is a private collaborator, not an implementation of the `Service` interface.)

**construction** — Built by `markdown.NewService(opts ...Option) Service` (`internal/markdown/markdown.go:85-113`), which returns `&service{md: ...}`. At runtime there is a single call site: `NewAPIV1Service` (`server/router/api/v1/v1.go:47-51`) calls `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())` and stores it in `APIV1Service.MarkdownService`. That one instance is then shared — `server.NewServer` passes `apiV1Service.MarkdownService` into the RSS service (`server/server.go:85`).

**holders** — Three components hold the `markdown.Service` interface as a field:
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — the primary owner; constructs it and shares it.
- `RSSService.MarkdownService` (`server/router/rss/rss.go:42-45`, injected via `NewRSSService`, `rss.go:58`) — uses it for `RenderHTML` when building feeds (`rss.go:339`).
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:14-17`, injected via `NewRunner`) — uses it via `RebuildMemoPayload` → `ExtractAll` (`runner.go:74-80`).

(Note: `server/server.go:startBackgroundRunners` currently only wires the `s3presign` runner; the `memopayload.Runner` type holds the interface but its `RebuildMemoPayload` helper is what executes at runtime, driven with the shared `markdown.Service`.)
