**Premise correction:** This repository (Memos) does **not** define a GraphQL schema, and there is no GraphQL API surface anywhere in it. I searched for GraphQL across Go, TypeScript, proto, and config files and found no schema, no resolvers, and no GraphQL server. The premise of the question is mistaken.

**Actual API surface:** The public API is a **Protocol Buffers / gRPC** API with a REST/JSON transcoding layer (gRPC-Gateway) — not GraphQL. It is defined in:

- **`proto/api/v1/*.proto`** — the canonical service and message definitions. The services are:
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/common.proto` (shared messages)

Supporting pieces:
- **`proto/buf.yaml`** / **`proto/buf.gen.yaml`** — the buf build config. `buf.gen.yaml` shows the plugins used: `grpc-ecosystem/gateway` (REST/JSON transcoding) and `community/google-gnostic-openapi` (OpenAPI/Swagger generation) — i.e. the API is exposed as gRPC + REST, and its interface docs are **OpenAPI**, not a GraphQL schema.
- **`proto/gen/api/`** — generated Go code from those protos.
- **`web/src/types/proto/api/`** — generated TypeScript client types.
- **`server/router/api/`** — the Go server-side implementations of these services.

So the correct answer is: there is no GraphQL schema; the public API contract lives in the `.proto` files under `proto/api/v1/`, served over gRPC and REST (gRPC-Gateway) with OpenAPI as the generated schema format.
