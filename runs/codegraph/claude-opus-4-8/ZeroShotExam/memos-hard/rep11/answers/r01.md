r01.

**Premise correction:** There is no Redis anywhere in the cache layer. The question presumes a Redis-backed cache with a configurable per-key TTL for user entries, but this codebase (memos) has no Redis connection at all — the cache is a purely in-process, in-memory implementation. There is also no user-specific TTL; user entries fall under the store's single default TTL.

**Actual mechanism:**

- **The cache implementation** is a thread-safe in-memory cache built on `sync.Map`, defined in `store/cache/cache.go`. The `Cache` struct (`store/cache/cache.go:67`) holds its data in a `sync.Map`, tracks item count with an atomic counter, and runs a background `cleanupLoop` goroutine to evict expired items. There is no external datastore or network connection — nothing to "connect" to.

- **Where it's "configured":** in `store.New` at `store/store.go:38-61`. The store constructs three independent in-memory caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — each via `cache.New(cacheConfig)`. The config is a literal `cache.Config` (`store/store.go:40-45`):
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  
  (The same values are also mirrored in `cache.DefaultConfig()` at `store/cache/cache.go:57-64`.)

- **TTL that applies to user entries:** User records live in `userCache`. They are written via `s.userCache.Set(...)` in `store/user.go` (e.g. `GetUser` at `store/user.go:167`, `ListUsers` at `store/user.go:143`, `CreateUser` at `store/user.go:98`). `Set` applies the cache's `DefaultTTL` (`store/cache/cache.go:93-95`), so **user entries expire 10 minutes after they are cached**. There is no per-user or user-specific TTL override; `SetWithTTL` exists (`store/cache/cache.go:98`) but is not used for users.

**Note on the separate "cache" you may find:** `server/router/rss/rss.go` has its own unrelated in-memory RSS feed cache (`cacheEntry`, `getFromCache`/`putInCache`) with a `defaultCacheDuration = 1 * time.Hour` (`server/router/rss/rss.go:25`). That caches rendered RSS XML by feed key (including `"user:<username>"` feed keys), not user records, and it is likewise not Redis.
