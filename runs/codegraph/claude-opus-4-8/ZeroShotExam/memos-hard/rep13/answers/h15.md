h15.
Memo visibility (who may view a memo) is enforced at several distinct server surfaces:

- Single-memo read access (`checkMemoReadAccess`, gates `GetMemo`/parent-memo and comment listing) — server/router/api/v1/memo_service.go:39
- List filtering by visibility (`ListMemos` builds `VisibilityList`/CEL filter from the current user: unauth → PUBLIC only; others → PUBLIC/PROTECTED or own) — server/router/api/v1/memo_service.go:218
- Comment listing on a memo (`ListMemoComments` blocks private memos for non-creator/non-superuser) — server/router/api/v1/memo_service_comments.go:41
- RSS feed (restricts the query to `store.Public` only) — server/router/rss/rss.go:90 (and rss.go:141)

The primary three are the single-memo `checkMemoReadAccess`, the `ListMemos` visibility filter, and the RSS feed's Public-only restriction; the comment-listing check is a fourth distinct site.

Note: `GetMemoByShare` (server/router/api/v1/memo_share_service.go:153) deliberately does *not* re-check visibility — an active share token itself is the authorization — so it is a bypass by design rather than an enforcement site.
