The answer is clear from the code. The `internal/idp` package defines the abstraction (the `IdentityProviderUserInfo` type and provider contract), and `internal/idp/oauth2` is the concrete protocol implementation.

h03.
The provider abstraction is defined in the **`internal/idp`** package (imported as `github.com/usememos/memos/internal/idp`), which declares the shared `IdentityProviderUserInfo` type and the provider contract used by the auth layer (see `server/router/api/v1/auth_service_sso.go:12-13` and `internal/idp/oauth2/oauth2.go:15`).

The one concrete protocol implementation that ships is **`internal/idp/oauth2`** — an OAuth2 provider. `internal/idp/oauth2/oauth2.go:1` opens with `// Package oauth2 implements the OAuth2 identity provider integration`, and `resolveSSOIdentity` only instantiates it for `storepb.IdentityProvider_OAUTH2` via `oauth2.NewIdentityProvider(...)` (`auth_service_sso.go:120-121`), then calls its `ExchangeToken`/`UserInfo` methods.

Answer: `internal/idp`; `internal/idp/oauth2`
