**Premise correction:** There is no Redis in this repository. A repo-wide search for `redis` across all Go files returns nothing — the cache layer is an in-process, in-memory cache backed by a `sync.Map`, not an external Redis connection. So there is no "Redis connection" to configure anywhere.

**Actual mechanism:**

- The cache implementation is a thread-safe in-memory cache in `store/cache/cache.go`. A `Cache` (`store/cache/cache.go:67`) stores entries in a `sync.Map`, each `item` carrying an `expiration` timestamp, with a background `cleanupLoop` goroutine that evicts expired/oldest entries. There is no network client, DSN, or connection string — construction is just `cache.New(config)` (`store/cache/cache.go:76`).

- The user cache is wired up in the store, not via any Redis config. `store/store.go:28` declares `userCache *cache.Cache`, and `store.New` instantiates it at `store/store.go:52` with the inline `cacheConfig` defined at `store/store.go:40-45`.

- **TTL for user entries:** user entries are written via `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`). `Set` uses the cache's configured `DefaultTTL` (`store/cache/cache.go:93-94`), which for the user cache is **10 minutes** (`DefaultTTL: 10 * time.Minute` at `store/store.go:41`; the package default in `DefaultConfig()` is likewise 10 minutes, `store/cache/cache.go:59`). Cleanup runs every 5 minutes, and the cache holds at most 1000 items. None of the `Set` calls for users use a custom `SetWithTTL`, so 10 minutes applies uniformly.

Note: there is a *separate*, unrelated cache for RSS feeds in `server/router/rss/rss.go` — a plain `map[string]*cacheEntry` with a 1-hour `defaultCacheDuration` (`server/router/rss/rss.go:25`). That is feed content, not user entries, and also not Redis.
