**Premise correction:** This repository (Memos) has **no GraphQL schema at all** — there is no GraphQL API, no `.graphql`/`.gql` files, and no GraphQL server/library dependency anywhere in the codebase (a case-insensitive search for "graphql" across Go and TS/TSX sources returns nothing). The question's premise is mistaken.

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC**, with a REST/HTTP transcoding layer and an MCP layer on top:

- **Schema (source of truth):** `.proto` files in `proto/api/v1/` — e.g. `proto/api/v1/memo_service.proto`, `auth_service.proto`, `user_service.proto`, `attachment_service.proto`, `ai_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, plus `common.proto`. Internal store schemas live in `proto/store/`.
- **Build config:** `proto/buf.yaml`, `proto/buf.gen.yaml`, `proto/buf.lock`; generated code lands in `proto/gen/`.
- **REST/OpenAPI:** exposed via gRPC-gateway with an embedded OpenAPI document (`proto/openapi_embed.go`).
- **Server routers:** `server/router/api` (gRPC/HTTP API services), `server/router/mcp` (MCP + OpenAPI adapter — `server/router/mcp/openapi.go`), and `server/router/rss`.

So the "GraphQL schema" doesn't exist; the equivalent artifact is the set of protobuf service definitions under `proto/api/v1/`.
