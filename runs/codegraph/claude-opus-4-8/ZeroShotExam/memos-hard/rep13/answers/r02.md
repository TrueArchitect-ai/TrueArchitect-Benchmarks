**Premise correction: there is no per-user (or any) API rate-limiting middleware in this repository.** The question assumes one exists; it does not.

I searched the codebase for rate-limiting constructs (`rate.limit`/`ratelimit`/`throttle`/`golang.org/x/time/rate`/`tollbooth`/`limiter`) and found no rate limiter — the only matches were unrelated (`web/src/components/MemoEditor/Editor/formatting.ts`, `listIndent.ts`, `internal/email/doc.go`).

The actual API middleware/interceptor chain is registered in `server/router/api/v1/v1.go` (`APIV1Service.RegisterGateway`), and none of the registered components limit request *rate*:

- **gRPC-Gateway path**: `gatewayAuthMiddleware` (authentication/access policy only) via `runtime.WithMiddlewares` — `server/router/api/v1/v1.go:69-98`.
- **Connect path interceptors** (`server/router/api/v1/v1.go:133-138`, defined in `server/router/api/v1/connect_interceptors.go`): `MetadataInterceptor` (header→metadata), `LoggingInterceptor`, `RecoveryInterceptor` (panic recovery), and `AuthInterceptor` (auth). No throttling.

What does exist are **non-rate resource limits**, which may be what the question is gesturing at:

- **Request body size limit**: `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` — `server/router/api/v1/v1.go:20`, `:126`, `:141`, `:144`. This is a per-request byte cap, not a per-user request-rate limit.
- **Concurrency semaphores** (global, not per-user): `thumbnailSemaphore = semaphore.NewWeighted(3)` and `imageProcessingSemaphore = semaphore.NewWeighted(2)` — `server/router/api/v1/v1.go:59-60`.

So the accurate statement is: this codebase enforces request-*size* and concurrency limits, but no per-user request-*rate* limiting middleware is registered anywhere.
