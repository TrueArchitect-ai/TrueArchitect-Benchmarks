**no** — outside the driver-selection factory, the MySQL store driver is never constructed directly.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:13-31`. It's the sole place that calls the MySQL driver's constructor: `mysql.NewDB(profile)` at `store/db/db.go:22`, inside the `switch profile.Driver` case `"mysql"`.
- The MySQL driver is constructed only through `mysql.NewDB` (`store/db/mysql/mysql.go:20`), which returns a `*mysql.DB` as a `store.Driver`. A repo-wide grep for any other invocation or direct struct literal — `mysql.NewDB`, `mysql.DB{`, `&mysql.DB` — yields exactly one hit: `store/db/db.go:22`. There are no `mysql.DB{...}` composite literals anywhere.
- The other `mysqldriver`-prefixed references are **not** the memos MySQL store driver. They import the upstream `github.com/go-sql-driver/mysql` package for unrelated purposes:
  - `store/db/mysql/auth_config.go:7,15-16` and `store/db/mysql/auth_config_test.go:6,13-15` use `mysqldriver.MySQLError` (error-type inspection).
  - `store/test/containers.go:16,363` uses `mysqldriver.ParseDSN` (DSN parsing for the test container).

So construction of the MySQL store driver happens exclusively inside the `NewDBDriver` factory; nowhere else in the codebase instantiates it directly.
