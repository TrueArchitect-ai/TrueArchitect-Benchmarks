Distinct server surfaces that enforce memo view-visibility:

Single-memo read (API v1 `GetMemo`) — `server/router/api/v1/memo_service.go:50` and `:63` (private memo returned only to its creator)
Memo listing filter (API v1 `ListMemos`) — `server/router/api/v1/memo_service.go:219-225` (viewer sees Public only when anonymous, Public+Protected for other users, all for owner)
RSS feed service — `server/router/rss/rss.go:90` and `:141` (feeds expose only Public memos)
Frontend SSR / sitemap / social-tag service — `server/router/frontend/frontend.go:150` (only Public memos)
File server (serving attachment file bytes) — `server/router/fileserver/fileserver.go:677` and `:699` (public+anonymous allowed; private only creator/admin)
API v1 attachment binary (`GetAttachmentBinary`) — `server/router/api/v1/attachment_service.go:451` (attachment of a private memo only to creator/admin)
User stats (API v1) — `server/router/api/v1/user_service_stats.go:84-90` and `:218-220` (stats filtered by the same Public / Public+Protected visibility rules)

Related access checks that piggyback on memo visibility (reading/writing sub-resources of a private memo): reactions — `server/router/api/v1/reaction_service.go:38,83`; comments — `server/router/api/v1/memo_service_comments.go:41`; memo attachments — `server/router/api/v1/memo_attachment_service.go:222`.

The three core "who may view a memo" surfaces are the **API v1 memo service** (`memo_service.go`), the **RSS service** (`rss.go`), and the **frontend SSR service** (`frontend.go`), with the **file server** (`fileserver.go`) enforcing the same rule when serving the underlying attachment bytes.
