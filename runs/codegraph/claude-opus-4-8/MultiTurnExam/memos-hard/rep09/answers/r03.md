**Premise correction:** There is **no nightly database-cleanup job**, and it is not scheduled in any cron scheduler — so there is no run time to report. The premise is false on two counts:

1. **No database-cleanup job exists.** Searches for cleanup/vacuum/purge/prune-style scheduled jobs turn up nothing. The only background runners started at server startup are the **S3 presign runner** (`server/server.go:161-170`, runs every 12h — not a DB cleanup) via `startBackgroundRunners`. No job deletes/vacuums/prunes database rows on a schedule.

2. **The cron scheduler isn't wired up at all.** A generic scheduler package does exist (`internal/scheduler/` — `Scheduler`, `Job`, cron `Schedule`/`parser.go`), but it is **never used in production**: no file outside `internal/scheduler/` (and its tests) imports it, and there are no `scheduler.New`/`Register` calls anywhere in `server/`, `cmd/`, or `store/`. It's effectively dead/unused code with no registered jobs.

So nothing schedules a nightly cleanup — background work is limited to the 12-hour S3 presign refresh, which runs off a plain `time.Ticker`, not the cron scheduler.
