**Premise correction:** There is **no per-user API rate-limiting middleware** in this codebase — so there is nothing registered and no request limits to report. The question's premise is false.

Evidence:
- A repo-wide search of the Go server/internal code for rate limiting (`rate limit`, `RateLimiter`, `golang.org/x/time/rate`, `throttle`, `limiter`, `quota`, `StatusTooManyRequests`/`429`) returns **zero** matches.
- The only middleware registered on the Echo server is `middleware.Recover()` and `newCORSMiddleware(profile)` — `server/server.go:51-52`. The frontend router additionally registers static-file and SPA-fallback middleware — `server/router/frontend/frontend.go:54,59`. None of these perform rate limiting.

So no per-user (or global) API rate limiter exists; requests are not throttled by any built-in middleware. (Any such limiting would have to be provided externally, e.g. a reverse proxy, which is outside this repository.)
