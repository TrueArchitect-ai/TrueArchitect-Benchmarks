**Premise correction:** There is **no GraphQL** anywhere in this project — no `.graphql`/`.graphqls` schema files, no `gqlgen`/`graphql-go` dependencies, and no GraphQL references in the Go sources or `go.mod`. So there is no GraphQL schema to point to; the premise is false.

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC services**, served over **Connect (connectrpc) + gRPC + a gRPC-gateway REST/JSON** interface, with an **OpenAPI** document generated from the protos.

- **Schema (source of truth):** `.proto` service definitions in `proto/api/v1/` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto`.
- **Generated code:** `proto/gen/api/v1/` (Go types + gRPC), including Connect handlers under `proto/gen/api/v1/apiv1connect/` (e.g. `idp_service.connect.go`, `ai_service.connect.go`) and REST gateway stubs (`*.pb.gw.go`).
- **OpenAPI:** an embedded OpenAPI spec is generated from the protos and consumed by the MCP service (`server/router/mcp/openapi.go`, `loadMCPServiceOpenAPISpec` reading `memosproto.OpenAPIYAML()`).
- **Wiring:** services are registered on the Echo/Connect server in `server/router/api/v1/` (e.g. `v1.go`, `connect_services.go`), and the frontend consumes them via generated TypeScript proto clients under `web/src/types/proto/`.

So the public API is proto-defined gRPC/Connect + REST-gateway (+ an MCP endpoint), not GraphQL.
