**Premise correction:** There is **no Redis** anywhere in this codebase. A repo-wide search for `redis` in Go sources (and `go.mod`) returns nothing — the cache layer is not backed by Redis and there is no Redis connection to configure. The premise that "the Redis connection for the cache layer" exists is false.

**Actual mechanism:** The cache is a **thread-safe in-process, in-memory cache** implemented in `store/cache/cache.go` (`Cache` — "a thread-safe in-memory cache with TTL and memory management", `store/cache/cache.go:66`; items expire via a `time.Now().Add(ttl)` expiration field and a periodic `cleanupLoop`). It's "configured" (not connected — it's just a struct) in `store.New` at `store/store.go:37-52`, which builds three `cache.New(cacheConfig)` instances, including `userCache`.

**TTL for user entries:** The default TTL — **10 minutes** — with a 5-minute cleanup interval and a 1000-item cap (`store/store.go:40-42`, matching `cache.DefaultConfig` at `store/cache/cache.go:59`). User entries are written via `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`), and `Set` applies the cache's `DefaultTTL` (`store/cache/cache.go:92-94`). No per-user custom TTL (`SetWithTTL`) is used, so user cache entries live 10 minutes.
