**Computation site:** `RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`. It calls the markdown service's single-pass `ExtractAll` (`internal/markdown/markdown.go:356`) on `memo.Content` and writes the results into `memo.Payload.Tags` and `memo.Payload.Property` (the derived metadata stored on the memo, distinct from user-set fields). Property computation itself lives in `(*service).ExtractProperties` — `internal/markdown/markdown.go:193`.

**Triggers (operations that recompute it):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (recomputes for the new memo before insert).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447` (recomputes when the memo's content is updated).
- Also the batch backfill path `memopayload.Runner.RunOnce`/`RebuildMemoPayload` loop (`server/runner/memopayload/runner.go:52`), which rebuilds payloads for all memos — though as established, that `Runner` isn't wired into production startup; the live triggers are the create/update RPC handlers.

**Extracted metadata (`ExtractAll` → stored):**
- **Tags** — the list of `#tags` in the content (`ExtractedData.Tags`, `internal/markdown/markdown.go:22`).
- **Property** (`storepb.MemoPayload_Property`), computed in `ExtractProperties`:
  - `Title` — text of a leading H1 heading, if the first block is one.
  - `HasLink` — content contains a link.
  - `HasCode` — content contains a code block/span.
  - `HasTaskList` — content contains a task-list checkbox.
  - `HasIncompleteTasks` — at least one unchecked task checkbox.

(Note: `ExtractAll` also computes `Mentions`, but `RebuildMemoPayload` persists only `Tags` and `Property` onto the memo payload.)
