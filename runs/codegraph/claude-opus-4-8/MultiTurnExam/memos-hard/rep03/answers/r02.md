**Premise correction:** The premise is false — there is **no per-user (or any) API rate-limiting middleware in this codebase**, so there is no registration site and no request limits to report.

Evidence:
- A repository-wide search for rate-limiting constructs (`ratelimit`, `RateLimiter`, `limiter`, `throttle`, `golang.org/x/time/rate`, "requests per", "per second/minute") across all `.go` files returns **no matches**. Notably, Echo's `middleware.RateLimiter` is not used.
- The Echo middleware chain registers only `middleware.Recover()` and the CORS middleware — `server/server.go:51`–`:52` (CORS defined in `server/cors.go:14`). No rate limiter is added.
- The API v1 request pipeline uses interceptors for metadata, logging, recovery, and **auth/authorization** only — `server/router/api/v1/v1.go:133`–`:137` (`NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor`); the gRPC-Gateway and Connect handlers share one `Authorizer` (`server/router/api/v1/authz.go`, `acl_config.go`). None of these throttle by user or rate.
- The only request "limits" present are unrelated size caps, not rate limits: a max request body size `maxAPIRequestBytes = 256 << 20` (256 MiB) enforced via `http.MaxBytesHandler` / `connect.WithReadMaxBytes` — `server/router/api/v1/v1.go:20`, `:126`, `:141`, `:144` — and pagination page-size caps (`MaxPageSize`, `server/router/api/v1/common.go:16`).

So: the correct statement is that memos does not implement per-user API rate limiting; access is gated by authentication/authorization interceptors and by request-size/page-size caps, not by request-rate limits.
