Memo view-access is enforced across several distinct server surfaces. Each distinct enforcement site:

- API v1 single-memo read gate (`checkMemoReadAccess`, used by `GetMemo`) — `server/router/api/v1/memo_service.go:38` (visibility checks at :55–:66; archived-only-to-creator at :44–:53)
- API v1 list query visibility filter (`ListMemos` restricts by current user) — `server/router/api/v1/memo_service.go:217`–`:227`, enforced in the SQL `WHERE` via `FindMemo.VisibilityList` — `store/db/sqlite/memo.go:96` (and `store/db/postgres/memo.go`, `store/db/mysql/memo.go`)
- HTTP file server attachment/blob permission (`checkAttachmentPermission`) — `server/router/fileserver/fileserver.go:650` (visibility checks at :677 and :699)
- API v1 attachment service access check — `server/router/api/v1/attachment_service.go:445`–`:451` and `server/router/api/v1/memo_attachment_service.go:214`–`:222`
- API v1 reaction service access check — `server/router/api/v1/reaction_service.go:30`–`:38` and `:83`
- API v1 memo comment access check — `server/router/api/v1/memo_service_comments.go:41`
- RSS feed (public-only memos) — `server/router/rss/rss.go:90` and `:141`
- Frontend SSR / sitemap (public-only memos) — `server/router/frontend/frontend.go:150`
- Memo share resolution (`GetMemoByShare` — share-token bypass path) — `server/router/api/v1/memo_share_service.go:153`

(The three primary "who may view a memo" surfaces are the first three: the `GetMemo` read gate, the `ListMemos` SQL visibility filter, and the file-server `checkAttachmentPermission`; the remaining API resource checks, RSS, and frontend SSR enforce the same visibility rules on their respective surfaces.)
