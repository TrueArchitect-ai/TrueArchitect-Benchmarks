**Premise correction:** Neither. The webhook delivery workers do not consume from any external message broker — there is no NATS, no RabbitMQ (nor AMQP/Kafka) anywhere in the codebase. A search for `nats`, `rabbitmq`, `amqp`, `streadway`, `kafka` across all `.go` files returns **no matches**, and there is no external queue declared.

**Actual mechanism:** delivery is dispatched through an **in-process, bounded Go channel** local to the `internal/webhook` package:
- The "queue" is a buffered channel `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39` (capacity 128, in-memory, lost on restart).
- A fixed pool of **4 worker goroutines** is started in `init()` and each ranges over that channel, calling `Post` for every payload — `internal/webhook/webhook.go:42`–`:55` (`for range 4 { go func() { for payload := range asyncPostQueue { Post(payload) } }() }`).
- Producers enqueue non-blockingly via `PostAsync`, which does a `select` send onto the channel and **drops** the payload (with a warning log) if the buffer is full — `internal/webhook/webhook.go:184`–`:195` (send at `:190`). Callers such as `DispatchMemoCreated/Updated/Deleted/CommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go`) feed it.

So the correct answer is: no broker at all — webhook workers consume from an in-memory buffered channel (`asyncPostQueue`) declared at `internal/webhook/webhook.go:39`, serviced by 4 goroutines started in `internal/webhook/webhook.go:42`.
