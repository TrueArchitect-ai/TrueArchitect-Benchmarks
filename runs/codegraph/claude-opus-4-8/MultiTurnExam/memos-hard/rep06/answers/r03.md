**Premise correction:** There is no nightly database-cleanup job scheduled anywhere, so it has no run time. The premise assumes two things that don't hold in this codebase:

1. **The cron scheduler isn't wired into the running server at all.** A cron scheduler package does exist (`internal/scheduler/scheduler.go`, with cron parsing in `internal/scheduler/parser.go`), but a repo-wide search shows the `internal/scheduler` package is never imported or used outside its own directory and tests — `scheduler.New` has zero production callers. Nothing registers any job with it, so no cron-scheduled work runs.

2. **No database-cleanup job exists.** There is no nightly/periodic cleanup task purging the database. The only background work the server actually starts is in `Server.startBackgroundRunners` (`server/server.go:153`), which launches exactly one runner: the **S3 presign runner** (`s3presign.NewRunner` → `Run`, `server/server.go:162-169`). That runner refreshes S3 attachment presigned URLs on a fixed **12-hour interval** (`server/runner/s3presign/runner.go:27`, `time.Hour * 12`) — it is not cron-based, not nightly, not a fixed clock time, and does not clean up the database.

Cleanup that does happen is inline/on-demand rather than scheduled — e.g. attachment/relation cleanup during memo deletion (`server/router/api/v1/memo_service.go:579`) and storage cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`). So there is no scheduled time to report.
