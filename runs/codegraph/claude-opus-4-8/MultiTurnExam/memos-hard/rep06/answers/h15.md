Distinct server surfaces that enforce memo visibility (who may view a memo/its content):

GetMemo single-read gate (private → creator/admin only; protected → authenticated) — server/router/api/v1/memo_service.go:55-63

ListMemos list-scoping filter (anonymous → PUBLIC only; authenticated non-owner → PUBLIC+PROTECTED) — server/router/api/v1/memo_service.go:219-225

User stats memo-scoping filter (same PUBLIC / PUBLIC+PROTECTED restriction) — server/router/api/v1/user_service_stats.go:84-90, 218-220

Attachment metadata/blob API (GetAttachment) visibility gate — server/router/api/v1/attachment_service.go:445-451

Memo-attachment listing gate — server/router/api/v1/memo_attachment_service.go:214-222

File server attachment-content access check (checkMemoAccess: public+anonymous, share-token fallback, private→creator/admin) — server/router/fileserver/fileserver.go:677, 699

Reaction service read/write gate (must be viewable: non-public requires auth; private → creator/admin) — server/router/api/v1/reaction_service.go:30-38, 83

SSE live-event delivery filter (private events delivered only to creator/admin) — server/router/api/v1/sse_hub.go:135-141

RSS feed (serves PUBLIC memos only) — server/router/rss/rss.go:90, 141

Frontend SSR/sitemap (PUBLIC memos only) — server/router/frontend/frontend.go:150

The core, database-enforced primitive underlying the list/stats/RSS/frontend surfaces is `FindMemo.VisibilityList`, translated to a SQL `visibility IN (...)` predicate in each driver (e.g. store/db/sqlite/memo.go:96, store/db/postgres/memo.go:89, store/db/mysql/memo.go:104). The per-memo checks (GetMemo, attachment, reaction, fileserver, SSE) enforce it in Go against the requesting user's identity/role.
