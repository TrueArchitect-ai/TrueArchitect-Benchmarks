**Premise correction:** The premise is false — there is **no per-user API rate-limiting middleware** in this repository, so there is nothing registered and no request limits to report.

Evidence:
- A repo-wide search for any rate-limiting facility (`rate limit`, `ratelimit`, `Limiter`, `throttle`, `tollbooth`, `golang.org/x/time/rate`) across all Go files returns **zero matches**.
- The actual middleware/interceptor stack that *is* registered contains no rate limiter:
  - Echo HTTP middleware (`server/server.go:51-52`): `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`).
  - Frontend static-serving middleware (`server/router/frontend/frontend.go:54,59`).
  - Connect/gRPC interceptors (`server/router/api/v1/v1.go:133-137`): `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` — i.e. metadata mapping, logging, panic recovery, and authentication only.
- The only request-shaping limit that exists is a payload **size** cap, not a rate cap: `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`. That bounds request body size, not requests per user or per unit time.

So there is no per-user (nor per-IP) rate limiting anywhere in the server; API abuse throttling would have to be added or handled by an external reverse proxy.
