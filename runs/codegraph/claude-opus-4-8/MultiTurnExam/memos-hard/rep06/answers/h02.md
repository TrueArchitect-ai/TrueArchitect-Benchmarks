**delivery function** — `Post` in `internal/webhook/webhook.go:120`. The outbound HTTP request is actually executed there by `safeClient.Do(req)` at `internal/webhook/webhook.go:152` (async callers go through `PostAsync` → the `asyncPostQueue` worker pool → `Post`, `internal/webhook/webhook.go:184` and `:42-55`).

**protection mechanism** — `internal/webhook/webhook.go`. The delivery uses a shared `safeClient` whose transport dials through `safeDialContext` (`internal/webhook/webhook.go:59`, wired at `:32-37`). At dial time `safeDialContext` resolves the target host and rejects any address in a reserved/private range via `isReservedIP`, which defeats both direct internal targeting and DNS-rebinding. The reserved-range check and its CIDR list live in `internal/webhook/validate.go` (`isReservedIP` at `:44`, `reservedCIDRs` at `:14`).

There is also a defense-in-depth check at webhook-registration time: `ValidateURL` (`internal/webhook/validate.go:62`) enforces http/https scheme and the same reserved-IP rejection when a user creates/updates a webhook (called from `server/router/api/v1/user_service_webhooks.go`). But the protection that guards the *actual delivery* is the `safeDialContext`/`safeClient` transport, since it re-checks at connection time.
