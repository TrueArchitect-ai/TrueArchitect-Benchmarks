The data layer is the `store` package (including its driver sub-packages `store/db/{sqlite,postgres,mysql}`). Counting distinct packages *outside* that layer that reference each persistent entity type (`store.<Type>` in non-test `.go`, web frontend and the whole `store/` tree excluded):

**1st — `store.User`** (`store/user.go:29`) — referenced from **6** external packages:
- `server/auth`
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/fileserver`
- `server/router/rss`

**2nd — `store.Memo`** (`store/memo.go:35`) — referenced from **4** external packages:
- `server/notification`
- `server/router/api/v1`
- `server/router/rss`
- `server/runner/memopayload`

Third is `store.Attachment` (`store/attachment.go`) at ~3 packages; every other entity (`MemoShare`, `Inbox`, `Reaction`, `MemoRelation`, `UserSetting`, `IdentityProvider`, `InstanceSetting`, `UserIdentity`) sits at 1–2.

Notes:
- Counts are rough (grep for `store.<Type>` with word boundaries, so `store.User` does not absorb `store.UserSetting`/`store.UserIdentity`). If you drop the test-support package `server/router/api/v1/test`, User is ~5 production packages and Memo ~4 — the ranking is unchanged.
- `User` leads because it's needed by auth (`server/auth`), avatar serving (`server/router/fileserver`), notifications, RSS, and the main API service, whereas `Memo` (despite heavy *use* inside the API layer) spreads across fewer distinct packages.
