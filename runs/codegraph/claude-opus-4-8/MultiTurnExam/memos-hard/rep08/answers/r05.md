**Premise correction:** There is no GraphQL API in this project, so there is no GraphQL schema defined anywhere. A repo-wide search for `graphql`, `gqlgen`, and `graph-gophers` in Go source and `go.mod` returns zero hits. The premise is false.

**Actual API surface:** The public API is a **Protocol Buffers–defined gRPC / Connect API**, not GraphQL.

- **Schema/IDL source:** `.proto` service definitions under `proto/api/v1/` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus `common.proto`. Build config lives at `proto/buf.yaml` / `proto/buf.gen.yaml`.
- **Generated code:** Go bindings in `proto/gen/api/v1/` (including `*_grpc.pb.go`, gRPC-gateway `*.pb.gw.go`, and Connect handlers under `proto/gen/api/v1/apiv1connect/`), and a TypeScript client under `web/src/types/proto/`.
- **How it's served:** the API is registered as Connect/gRPC/gRPC-Web + a gRPC-gateway (HTTP+JSON) in `server/router/api/v1/v1.go` and wired in `server/server.go:76-90` (`RegisterGateway`).
- **OpenAPI (not GraphQL):** an OpenAPI spec is embedded via `proto/openapi_embed.go` and consumed by the MCP endpoint (`server/router/mcp/`) — this is the closest thing to a "schema document," but it is OpenAPI over the gRPC/Connect surface, still not GraphQL.

So the public API is defined by protobuf service schemas in `proto/api/v1/*.proto` and exposed over gRPC/Connect/gRPC-gateway; there is no GraphQL schema.
