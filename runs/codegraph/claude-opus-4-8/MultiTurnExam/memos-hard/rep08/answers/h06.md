**Convergence function — `webhook.Post`, `internal/webhook/webhook.go:120`**

Reasoning / evidence trail:

- Each dispatcher pulls the *user-configured* webhook URLs from the store (`s.Store.GetUserWebhooks`) and sets `payload.URL = hook.Url` before dispatching — `server/router/api/v1/memo_service_webhooks.go:41,67`. So the outbound target is user-controlled.
- The memo-create/update/delete dispatchers all funnel through the shared helper `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), while the comment path (`DispatchMemoCommentCreatedWebhook`, `:30`) has its own loop; **both** end by calling `webhook.PostAsync(payload)` (`:71` and `:43`) — the single enqueue convergence point.
- `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded channel drained by worker goroutines started in `init` (`internal/webhook/webhook.go:42-55`), and every worker calls **`Post`** (`:46`). `Post` (`internal/webhook/webhook.go:120`) is where all paths converge immediately before the actual HTTP send `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

So every one of these RPC handlers, regardless of activity type or sync/async framing, ultimately delivers through the one `Post` function. (Its `safeClient` also enforces the SSRF guard from h02.)
