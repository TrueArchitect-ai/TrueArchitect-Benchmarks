How I determined which of the three candidate `CreateMemo` implementations actually runs:

1. **Entry point / interface dispatch.** Saving a memo calls `store.CreateMemo` (`store/memo.go:109`), which after a UID check delegates to `s.driver.CreateMemo(ctx, create)` (`store/memo.go:113`). `s.driver` is the `store.Driver` interface (`store/driver.go:29`), so the concrete implementation is chosen at construction time, not here. There are three implementers: `store/db/sqlite/memo.go:16`, `store/db/postgres/memo.go`, and `store/db/mysql/memo.go`.

2. **Which implementer is wired in.** The concrete driver is built once by the factory `NewDBDriver`, which switches on `profile.Driver` and returns `sqlite.NewDB` / `postgres.NewDB` / `mysql.NewDB` accordingly (`store/db/db.go:14-31`). The `store.Store` is created with that driver in `cmd/memos/main.go:57-64` (`db.NewDBDriver(instanceProfile)` → `store.New(dbDriver, …)`).

3. **What the default value is.** `profile.Driver` comes from the `driver` config key (`cmd/memos/main.go:43`). With no flags/env set, its default is **`"sqlite"`** — set both via `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the persistent flag default `rootCmd.PersistentFlags().String("driver", "sqlite", …)` (`cmd/memos/main.go:130`). The profile also confirms sqlite is the assumed default by auto-deriving a DSN only when `p.Driver == "sqlite"` (`internal/profile/profile.go:110`).

So on a default install the factory's `case "sqlite"` branch runs, binding the `Driver` interface to `*sqlite.DB`, and the actual SQL INSERT is emitted by `(*sqlite.DB).CreateMemo` at `store/db/sqlite/memo.go:41`. The postgres and mysql `CreateMemo` methods exist but are never constructed unless `--driver` (or the `driver` env/config) is changed.
