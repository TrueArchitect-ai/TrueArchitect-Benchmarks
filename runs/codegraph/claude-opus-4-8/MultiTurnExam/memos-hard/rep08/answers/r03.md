**Premise correction:** There is no nightly database-cleanup job, and nothing is scheduled in "the cron scheduler" — so there is no run time to report. The premise is false on two independent counts.

Evidence:

1. **No database-cleanup job exists (nightly or otherwise).** There is no purge/vacuum/cleanup job anywhere in the server. Searching for cleanup-type work turns up only unrelated things: the in-memory cache's cleanup goroutine (`CleanupInterval: 5 * time.Minute`, `store/store.go:42` — a 5-minute in-memory eviction sweep, not a DB job) and inline attachment/memo cleanup performed synchronously during delete operations (`store/attachment.go`, `server/router/api/v1/memo_service.go:579`, `user_service.go:421`). None is a scheduled database-maintenance task.

2. **The cron scheduler is not wired into the running server at all.** A cron scheduler package does exist at `internal/scheduler/` (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`), but it has **no production callers**: searching for uses of the package outside `internal/scheduler` (and outside tests) returns nothing — `scheduler.New`, `Register`, etc. are referenced only from the package's own tests (`internal/scheduler/*_test.go`). So no jobs of any kind are registered with it in the actual server.

The only real scheduled background work in the server is the S3-presign refresh runner, and it does **not** use the cron scheduler — it is a plain `time.Ticker` firing every 12 hours (`server/runner/s3presign/runner.go:27`), started from `startBackgroundRunners` (`server/server.go:162-169`). There is no nightly (daily) job and no cron-scheduled database cleanup.
