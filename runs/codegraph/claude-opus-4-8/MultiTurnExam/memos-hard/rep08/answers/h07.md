Request: `GET /file/users/{identifier}/avatar` for another user's avatar. Trace from HTTP route to stored data:

```
RegisterRoutes (route GET /file/users/:identifier/avatar → serveUserAvatar) — server/router/fileserver/fileserver.go:121 (route decl :123)
serveUserAvatar (handler; auth-gates on private instances, then looks up the user) — server/router/fileserver/fileserver.go:165
getUserByUsername — server/router/fileserver/fileserver.go:715
Store.GetUser (cache check, else ListUsers) — store/user.go:148
Store.ListUsers (wraps driver) — store/user.go:136 (calls s.driver.ListUsers at :137)
Driver.ListUsers (interface) — store/driver.go:47
DB.ListUsers (concrete SQL query of the user row, incl. avatar_url column) — store/db/sqlite/user.go (and store/db/postgres/user.go, store/db/mysql/user.go)
```

Then back in the handler the stored data is decoded and written to the response:

```
serveUserAvatar reads user.AvatarURL (a data: URI held in the user row) — server/router/fileserver/fileserver.go (user.AvatarURL, ~:255)
parseDataURI (splits the stored data URI into MIME type + bytes) — server/router/fileserver/fileserver.go (~:259)
c.Blob(...) writes the image bytes — server/router/fileserver/fileserver.go (~:270)
```

Notes / evidence:
- The route group `/file` and the two GET routes are registered in `FileServerService.RegisterRoutes` (`server/router/fileserver/fileserver.go:120-124`), which is itself wired into startup by `NewServer` at `server/server.go:81-82` (`fileServerService.RegisterRoutes(echoServer)`). The frontend static handler explicitly *skips* `/file` (`server/router/frontend/frontend.go:87`), so these requests reach the fileserver, not the SPA.
- The avatar is **not** a separate blob/attachment — it is stored inline as a data-URI string in the `user` table's `avatar_url` column (`store.User.AvatarURL`, `store/user.go:43`), which is why the data layer hop is `GetUser`/`ListUsers` on the user row rather than an attachment lookup. `getUserByUsername` passes `FindUser{Username: &identifier}` (`server/router/fileserver/fileserver.go:715-716`).
- `Store.GetUser` short-circuits on an ID cache only; a username lookup falls through to `s.ListUsers` → `s.driver.ListUsers` (`store/user.go:148-169`), landing in the per-dialect driver implementations.
