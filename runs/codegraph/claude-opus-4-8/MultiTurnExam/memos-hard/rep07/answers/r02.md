**Premise correction:** The repository has no per-user API rate-limiting middleware — it does not exist, so there is nothing to register and no request limits to report. The only Echo middleware wired into the server is `middleware.Recover()` and `newCORSMiddleware(profile)`, both registered in `NewServer` at server/server.go:51-52 (plus per-route auth middleware in `RegisterGateway`). A repo-wide search for rate-limiting constructs (`ratelimit`, `RateLimiter`, `limiter`, `throttle`, `golang.org/x/time/rate`, Echo's `middleware.RateLimiter`) finds no implementation anywhere in the Go backend; the sole textual match is an aspirational comment about throttling *email* sending in internal/email/doc.go:86, which is documentation, not code.

The closest thing to any request bounding is the webhook async dispatch queue, which caps *concurrency/queue depth* (a 128-slot buffered channel with 4 workers) in internal/webhook/webhook.go:39-55 — but that is outbound webhook delivery back-pressure, not inbound per-user API rate limiting. So the answer is that the described middleware is not present in the codebase.
