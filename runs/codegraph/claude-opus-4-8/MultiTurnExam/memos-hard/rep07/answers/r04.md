**Premise correction:** Neither. The webhook delivery workers do not consume from any external message broker — there is no NATS and no RabbitMQ (nor AMQP) anywhere in the project. A search of `go.mod` and all Go sources for `nats`, `rabbitmq`, `amqp`, `streadway`, etc. returns nothing. There is no external queue to declare.

**Actual mechanism:** Delivery is dispatched over a plain **in-process Go buffered channel**, entirely within the single server process. In internal/webhook/webhook.go:39, the queue is declared as:
`asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel with capacity 128.

An `init()` function (internal/webhook/webhook.go:42-55) starts **4 goroutine workers** that range over that channel and call `Post` for each payload (the actual HTTP delivery). Producers enqueue via `PostAsync` (internal/webhook/webhook.go:184-196), which does a non-blocking `select` send onto `asyncPostQueue` and drops the payload with a warning if the buffer is full. So the "workers" are goroutines, the "queue" is a bounded in-memory channel, and everything lives in the memos process — no broker involved.
