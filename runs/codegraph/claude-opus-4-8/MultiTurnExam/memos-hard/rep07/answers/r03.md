**Premise correction:** There is no nightly database-cleanup job in the codebase, so it has no scheduled run time. The premise is false on two counts:

1. **No cleanup job exists.** No job that purges/cleans the database on a schedule is defined or registered anywhere in production code. (Deletion cleanup that does exist is inline and event-driven — e.g. relation/attachment cleanup during `DeleteMemo` at server/router/api/v1/memo_service.go:579 and user-deletion cleanup at server/router/api/v1/user_service.go:421-450 — none of it cron-scheduled.)

2. **The cron scheduler isn't even running.** A cron scheduler package exists at `internal/scheduler/` (`scheduler.New`, `Job`, `ParseCronExpression`, etc.), but it is never instantiated or wired into the server. `scheduler.New(...)` and `.Register(...)` are called only from tests (`internal/scheduler/*_test.go`); a search across production code (excluding the package itself and tests) finds zero usages, and neither server/server.go nor cmd/memos/main.go references the scheduler at all.

The only actual background work wired into startup is the S3 presign runner (`s3presign.Runner`, run every 12h via a `time.Ticker`, registered in `Server.startBackgroundRunners` at server/server.go:162-169) — which refreshes presigned attachment URLs, not a database cleanup, and it uses a plain ticker interval, not the cron scheduler. So there is no nightly DB-cleanup cron time to report.
