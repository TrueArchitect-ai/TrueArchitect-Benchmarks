h11.

The persistent entity types are the structs defined in the `store` package (the data layer — `store/*.go`, with drivers under `store/db/*`): `User`, `Memo`, `Attachment`, `Reaction`, `Inbox`, `MemoRelation`, `MemoShare`, `UserSetting`, `InstanceSetting`, `IdentityProvider`, `UserIdentity`, etc. Counting distinct packages *outside* `store/` (and excluding generated `proto/`) that reference each `store.<Type>`:

**1st: `User` — ~7 packages**
`server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`.

**2nd: `Memo` — ~6 packages**
`server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`.

Method: `grep -rln "store\.<Type>\b"` across `*.go`, dropping `store/` and `proto/`, then counting unique directories. The next tier trails clearly — `Attachment` ≈ 4 packages, then `MemoShare` / `MemoRelation` / `Inbox` ≈ 3 each. (If the test package `server/router/api/v1/test` is excluded as non-production, the counts become User ≈ 6 and Memo ≈ 5, but the ranking is unchanged.)

So `User` is referenced from the most external packages, with `Memo` a close second.
