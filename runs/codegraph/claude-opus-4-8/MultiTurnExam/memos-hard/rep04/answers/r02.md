**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — it does not exist, so there is nowhere it is "registered" and there are no request limits to report.

Evidence:
- The HTTP middleware stack registered on the Echo server is only `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/server.go:51-52`); the frontend router additionally adds static-file serving and an SPA-fallback (`server/router/frontend/frontend.go:54-59`). No rate limiter, throttle, or token-bucket middleware is wired anywhere.
- Searching the Go sources for `ratelimit`/`RateLimiter`/`limiter`/`golang.org/x/time/rate`/`tollbooth` yields no implementation — the only hit is an aspirational comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which is documentation, not code, and concerns SMTP sending rather than per-user API requests.
- There is no `429 / http.StatusTooManyRequests` response anywhere in non-generated code, which would be the expected signal of a rate limiter.

There *are* a few unrelated internal concurrency caps (e.g. `semaphore.NewWeighted(3)` / `NewWeighted(2)` for thumbnail and image processing in `server/router/api/v1/v1.go`, and bounded async queues of 128 for webhooks/email), but these are global in-process concurrency limits, not per-user request rate limiting on the API surface.

So the question's premise is mistaken: no per-user API rate-limiting middleware or configured request limits exist.
