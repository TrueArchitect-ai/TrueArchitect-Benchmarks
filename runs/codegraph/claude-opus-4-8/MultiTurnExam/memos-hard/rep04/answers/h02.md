The server delivers webhooks (fired when memos/content change) over HTTP, and the outbound request is protected against internal/SSRF targets primarily at dial time.

**Delivery function**: `webhook.Post` — `internal/webhook/webhook.go:120` (executes `safeClient.Do(req)` at `internal/webhook/webhook.go:152`; the async path `PostAsync` enqueues onto worker goroutines that also call `Post`).

**Protection mechanism**: `safeDialContext` — `internal/webhook/webhook.go:59`, installed as the `DialContext` of the shared `safeClient` transport (`internal/webhook/webhook.go:32-37`). On every dial it resolves the hostname and rejects any address in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`, backed by the `reservedCIDRs` list at `internal/webhook/validate.go:14`). Because the check happens at connection time on the resolved IP, it also defeats DNS-rebinding.

Notes:
- There's a second, earlier layer: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) validates scheme and blocks reserved IPs when a webhook URL is created/updated (called from `server/router/api/v1/user_service_webhooks.go`). But the guarantee at actual delivery is `safeDialContext`, since a URL that passed validation could later rebind to an internal IP.
- Both layers can be disabled by the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for self-hosted deployments targeting local networks.
