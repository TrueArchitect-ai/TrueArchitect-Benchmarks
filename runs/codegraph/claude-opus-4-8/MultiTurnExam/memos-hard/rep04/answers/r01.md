**Premise correction:** There is no Redis anywhere in this codebase. The cache layer is not backed by Redis (or any external cache server) — `grep -rni "redis"` over the Go sources and `go.mod` returns nothing. So there is no "Redis connection" to configure.

**Actual mechanism:** The cache is an in-process, in-memory cache implemented in `store/cache/cache.go` (`Cache` = a `sync.Map` with per-entry TTL, size accounting, and a background cleanup goroutine; `store/cache/cache.go:66-90`). It's not "connected" — it's just constructed with a `cache.Config`.

- **Where user caching is configured:** in `store.New` (`store/store.go:38-58`). A single `cacheConfig` is built with `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:40-45`), and the user cache is created from it: `userCache: cache.New(cacheConfig)` (`store/store.go:52`).
- **TTL for user entries:** User records are written via `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`). `Cache.Set` stores using the config's default TTL — `SetWithTTL(ctx, key, value, c.config.DefaultTTL)` (`store/cache/cache.go:93-94`). Therefore user cache entries expire after **10 minutes** (`store/store.go:41`), with expired entries reaped on read or by the 5-minute cleanup loop.

So: no Redis; user entries live in an in-memory `store/cache.Cache` configured in `store/store.go` with a 10-minute TTL.
