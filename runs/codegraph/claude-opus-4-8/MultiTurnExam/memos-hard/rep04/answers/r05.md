**Premise correction:** There is no GraphQL schema, and no GraphQL API at all. Searching the repo for `graphql`/`gqlgen`/`*.graphql` yields nothing (no dependency in `go.mod`, no schema files, no resolvers). So there is no GraphQL schema location to point to.

**Actual API surface:** The public API is defined with **Protocol Buffers** and served over **gRPC / gRPC-Gateway (REST) / Connect**:

- The schema (service and message definitions) lives in `.proto` files under `proto/api/v1/` — e.g. `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `shortcut_service.proto`, `instance_service.proto`, `idp_service.proto`, `ai_service.proto`, and `common.proto`.
- These generate Go code under `proto/gen/api/v1/` (gRPC stubs `*_grpc.pb.go`, gRPC-Gateway `*.pb.gw.go`, and Connect handlers under `proto/gen/api/v1/apiv1connect/`).
- The service implementation (`APIV1Service`) is wired in `server/router/api/v1/v1.go`: it mounts the gRPC-Gateway REST mux (`v1.go:126`) and the Connect handler (`NewConnectServiceHandler`, `v1.go:140`) under the `/memos.api.v1.*` route (`v1.go:144`).
- There is also an OpenAPI spec derived from the protos (embedded and used by the MCP endpoint, e.g. `server/router/mcp/openapi.go`), reinforcing that the public contract is proto/OpenAPI-based, not GraphQL.

So the "schema" for the public API is the Protobuf definitions in `proto/api/v1/*.proto`, exposed as gRPC + REST (gRPC-Gateway) + Connect — not GraphQL.
