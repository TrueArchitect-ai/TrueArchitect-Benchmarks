**Computation site** — `memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`). It calls the markdown service's single-pass `ExtractAll` (`internal/markdown/markdown.go:356`) and writes the result into the memo's `Payload`:
```
memo.Payload.Tags     = data.Tags
memo.Payload.Property = data.Property
```
This derived metadata is persisted in the `memo.payload` column and is what list/preview queries use (e.g. `FindMemoPayload`'s `TagSearch`, `HasLink`, `HasTaskList`, `HasCode`, `HasIncompleteTasks` in `store/memo.go`).

**Triggers (recomputation)** — the API service rebuilds the payload from content on:
- **Memo creation** — `APIV1Service.CreateMemo` → `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` at `server/router/api/v1/memo_service.go:108`.
- **Memo update, only when the `content` field is in the update mask** — `APIV1Service.UpdateMemo` → `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)` at `server/router/api/v1/memo_service.go:447` (inside the `path == "content"` branch).

(There is also `memopayload.Runner.RunOnce`, a bulk backfill that would rebuild all memos, but that `Runner` is never constructed in production, so it is not an active trigger.)

**Extracted properties** — `ExtractAll` walks the goldmark AST once and produces (`internal/markdown/markdown.go:356-420`):
- **`Tags`** — all `#tag` nodes, deduplicated preserving case.
- **`Property`** (`storepb.MemoPayload_Property`, fields at `proto/gen/store/memo.pb.go:85-90`):
  - `Title` — text of the document's first block if it's an H1 heading.
  - `HasLink` — a link node is present.
  - `HasCode` — any code block / fenced code / inline code span.
  - `HasTaskList` — a task-checkbox is present.
  - `HasIncompleteTasks` — at least one task checkbox is unchecked.

(`ExtractAll` also collects `Mentions` (`@user`), but `RebuildMemoPayload` does not store those in the payload — they feed mention notifications, not the derived list/preview metadata.)
