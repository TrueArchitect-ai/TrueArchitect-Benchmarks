Memo visibility is enforced at multiple independent server surfaces. Distinct enforcement sites:

- **Single-memo read access (gRPC/Connect `GetMemo`)** — `checkMemoReadAccess`, which requires auth for non-public memos and denies non-creators on private memos — `server/router/api/v1/memo_service.go:39` (checks at :55-64)
- **Memo list querying (`ListMemos`)** — constrains the query by `VisibilityList`/CEL filter: anonymous → `PUBLIC` only; authenticated non-owner → `PUBLIC`+`PROTECTED`; owner → own via `creator_id` — `server/router/api/v1/memo_service.go:219-225`
- **Attachment / file serving (fileserver)** — decides who may fetch a memo's attachment bytes based on the parent memo's visibility (public+anonymous allowed; private restricted to creator/admin; unlinked → creator only) — `server/router/fileserver/fileserver.go:651,677,699`
- **RSS feed** — restricts feeds to `PUBLIC` memos only — `server/router/rss/rss.go:90` and `:141`
- **SSE real-time delivery filtering** — `SSEClient.canReceive` drops private events for non-creator/non-admin subscribers — `server/router/api/v1/sse_hub.go:134` (switch at :135)
- **Frontend SSR / sitemap / meta tags** — only `PUBLIC` memos are exposed — `server/router/frontend/frontend.go:150`

Additional API surfaces that re-apply the same visibility rule when listing/embedding memos:
- **User stats** (`ListMemoTags`/stats) — `server/router/api/v1/user_service_stats.go:84-90` and `:218-220`
- **Memo comments listing** — `server/router/api/v1/memo_service_comments.go:158-160` (and comment-creation visibility rule at :100)
- **Memo relations listing** — `server/router/api/v1/memo_relation_service.go:109-111`
- **Reactions** (`UpsertMemoReaction`) — non-public memos require an authenticated viewer — `server/router/api/v1/reaction_service.go:30`
- **Memo attachment listing** — `server/router/api/v1/memo_attachment_service.go:214`

The core three surfaces are the gRPC single-memo check (`memo_service.go:39/55`), the list-query filter (`memo_service.go:219`), and the fileserver attachment check (`fileserver.go:677/699`), with RSS, SSE, and frontend as further distinct surfaces.
