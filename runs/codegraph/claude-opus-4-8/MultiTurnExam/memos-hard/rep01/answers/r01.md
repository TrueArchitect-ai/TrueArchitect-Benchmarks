**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` (in Go source) returns zero matches — the cache layer is **not** backed by Redis, and there is no Redis connection to configure anywhere. The cache is an in-process, in-memory implementation.

**Actual mechanism:**
- The cache is a thread-safe **in-memory** map with TTL and size-based eviction: `store/cache/cache.go` (`Cache` — "a thread-safe in-memory cache with TTL and memory management", `store/cache/cache.go:66`; `Interface` at `:10`). Entries expire via `expiration: time.Now().Add(ttl)` (`store/cache/cache.go:112`) and are reaped by a background cleanup goroutine, not by any external store.
- It is "configured" not with a connection string but with a `cache.Config` created in `Store.New` — `store/store.go:38-44`: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`. Three separate in-memory caches are instantiated from it (`instanceSettingCache`, `userCache`, `userSettingCache`) at `store/store.go:50-52` via `cache.New(cacheConfig)`.
- **User-entry TTL:** the `userCache` uses that shared config, and `Store.GetUser`/`ListUsers` populate it with plain `s.userCache.Set(...)` (no custom TTL), which applies the default TTL. So **user cache entries live 10 minutes** (`DefaultTTL: 10 * time.Minute`, `store/store.go:41`; applied via `Cache.Set` → `SetWithTTL(..., c.config.DefaultTTL)` at `store/cache/cache.go:92-94`).

Answer: **No Redis exists — the cache is an in-memory `cache.Cache` (`store/cache/cache.go`) configured in-code by `cache.Config` in `store/store.go:38-44`; user entries use the default 10-minute TTL (`store/store.go:41`).**
