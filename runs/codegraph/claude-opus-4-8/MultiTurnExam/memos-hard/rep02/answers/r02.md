**Premise correction: There is no per-user API rate-limiting middleware in this codebase — no such middleware is registered, and there are no request limits to report.**

Evidence:

- A repo-wide search for rate-limiting (`ratelimit`, `rate limit`, `limiter`, `throttle`, `golang.org/x/time/rate`) in Go source finds nothing functional — the only hit is an aspirational doc comment in an unrelated package: internal/email/doc.go:86 (`// - Rate limit email sending to prevent abuse`), which describes a suggestion, not implemented code.
- The actual middleware/interceptor stack registered on the server contains no limiter:
  - Echo-level middleware in `NewServer`: `middleware.Recover()` and `newCORSMiddleware(profile)` — server/server.go:51-52 (CORS defined in server/cors.go:13).
  - gRPC-Gateway: a single `gatewayAuthMiddleware` for auth — server/router/api/v1/v1.go:69, registered via `runtime.WithMiddlewares` at v1.go:97.
  - Connect interceptors: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — server/router/api/v1/v1.go:133-138 (defined in server/router/api/v1/connect_interceptors.go). None performs rate limiting.
- There is also a `maxAPIRequestBytes` (256 MiB) body-size cap (server/router/api/v1/v1.go:20, applied via `http.MaxBytesHandler`), but that limits request *size*, not request *rate*, and is not per-user.

So the question's premise is mistaken: no per-user (or global) API rate-limiting middleware is wired into server startup, and consequently no request-count limits exist.
