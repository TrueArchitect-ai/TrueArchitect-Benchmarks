**Determination method:**

There are three candidate implementations of the `Driver.CreateMemo` interface method — `store/db/sqlite/memo.go:16`, `store/db/mysql/memo.go`, and `store/db/postgres/memo.go` — all reachable dynamically through `store.Store.CreateMemo`, which delegates to `s.driver.CreateMemo` (store/memo.go:109-113). To decide which concrete one runs I resolved the driver selection, not the dispatch:

1. **Selection point:** `NewDBDriver` picks the driver with a `switch profile.Driver` (store/db/db.go:18-26): `"sqlite"` → `sqlite.NewDB`, `"mysql"` → `mysql.NewDB`, `"postgres"` → `postgres.NewDB`. So the concrete type of `s.driver` is fixed by `profile.Driver`.
2. **Default value with no flags:** `profile.Driver` defaults to `"sqlite"` — set in cmd/memos/main.go:122 (`viper.SetDefault("driver", "sqlite")`) and the flag default in cmd/memos/main.go:130 (`String("driver", "sqlite", ...)`). With no `--driver`/`MEMOS_DRIVER` override, this stays `"sqlite"`.
3. **Conclusion:** The factory therefore constructs the sqlite driver (per h04, that's the single construction site), so `s.driver` is `*sqlite.DB` and the interface call `s.driver.CreateMemo` binds to `(*sqlite.DB).CreateMemo`.

So on a default install the SQL INSERT for a saved memo is executed by `(*sqlite.DB).CreateMemo` (store/db/sqlite/memo.go:16). I determined it by tracing the compile-time driver **selection** (`NewDBDriver` switch) back to the default config value, rather than the interface dispatch alone — which by itself has three equally-valid candidates.
