Notes on what I checked:
- The route is registered in `RegisterRoutes` at server/router/fileserver/fileserver.go:124, wired into startup via `fileserver.NewFileServerService(...).RegisterRoutes(echoServer)` in `NewServer` (server/server.go:81-82).
- I ruled out a gRPC `UserService/GetUserAvatar` endpoint being the data path: `acl_config.go:25` references that method name for ACL allow-listing, but the browser image request is served by the Echo handler above. The avatar image itself is not a separate blob table — it is stored inline on the user row as a base64 data URI in `User.AvatarURL` (store/user.go:43), which the converter exposes to clients as the `/file/{user}/avatar` URL (server/router/api/v1/user_service_converters.go:36).
- `Store.GetUser` → `Store.ListUsers` → `s.driver.ListUsers` is the hop into the `Driver` interface (store/user.go:136-137, 148-168), whose concrete implementation runs the SQL `SELECT` in each database driver's `user.go`.
