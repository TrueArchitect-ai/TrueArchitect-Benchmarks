Memo visibility is enforced across many server surfaces. Each distinct enforcement site (function/location where a viewer is allowed or denied based on `memo.Visibility`):

- Memo read (single) — `checkMemoReadAccess` — server/router/api/v1/memo_service.go:39 (Private/Protected checks at :63)
- Memo list filtering — `ListMemos` sets `memoFind.VisibilityList` by viewer — server/router/api/v1/memo_service.go:219-225
- Attachment gRPC access — `checkAttachmentAccess` — server/router/api/v1/attachment_service.go:422 (:445, :451)
- File server (attachment blobs / avatars over HTTP) — `checkAttachmentPermission` — server/router/fileserver/fileserver.go:650 (:677, :699)
- Reaction service (upsert/list reactions) — server/router/api/v1/reaction_service.go:38 and :83
- Memo comments (create comment on a memo) — server/router/api/v1/memo_service_comments.go:41
- Memo attachment listing/setting — server/router/api/v1/memo_attachment_service.go:222
- User stats — `VisibilityList` filter by viewer — server/router/api/v1/user_service_stats.go:84-90 and :218-220
- SSE live broadcast delivery — visibility-gated fan-out — server/router/api/v1/sse_hub.go:136-138
- Mention notification access — `canUserAccessMentionContext` — server/router/api/v1/memo_mention_helpers.go:56 (:62, :67); and `canViewerAccessMemo` — server/router/api/v1/user_service_notifications.go:302 (:309, :312)
- RSS feeds (public-only) — server/router/rss/rss.go:90 and :141
- Frontend SSR / sitemap (public-only) — server/router/frontend/frontend.go:150

The three primary surfaces, if a minimal answer is wanted, are: the **Memo gRPC service** (`checkMemoReadAccess` + `ListMemos` visibility filter, server/router/api/v1/memo_service.go), the **file server** (`checkAttachmentPermission`, server/router/fileserver/fileserver.go:650), and the **RSS/frontend public feeds** (server/router/rss/rss.go, server/router/frontend/frontend.go) — with additional enforcement in the attachment, reaction, comment, stats, SSE, and notification surfaces listed above.

Note: I found these by grepping the `server/` tree for `Visibility`/`store.Public|Protected|Private` usage and permission-helper functions; each site independently re-checks visibility rather than sharing one central guard.
