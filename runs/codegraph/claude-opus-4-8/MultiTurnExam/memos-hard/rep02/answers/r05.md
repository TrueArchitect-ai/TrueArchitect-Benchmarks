**Premise correction: There is no GraphQL schema in this repository. A search for `graphql`/`gqlgen`/`.graphql` in the Go source returns nothing — the public API is not GraphQL.**

**Actual API surface:** The public API is defined with **Protocol Buffers / gRPC service definitions**, exposed over both REST (gRPC-Gateway) and Connect RPC, with an OpenAPI document as the schema artifact:

- **Schema source of truth — `.proto` files** in `proto/api/v1/`: `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `common.proto`. These declare the services and messages.
- **Generated code** in `proto/gen/api/v1/` (`*.pb.go`, `*_grpc.pb.go`, `*.pb.gw.go`, and Connect handlers under `apiv1connect/`), built via buf (`proto/buf.gen.yaml`, `proto/buf.yaml`).
- **HTTP exposure:** registered in `APIV1Service.RegisterGateway` (server/router/api/v1/v1.go:65) — a gRPC-Gateway mux serving REST at `/api/v1/*` (v1.go:99-128) plus Connect handlers at `/memos.api.v1.*` (v1.go:139-144).
- **OpenAPI (REST schema), not GraphQL:** an OpenAPI spec is embedded via `proto/openapi_embed.go` (`memosproto.OpenAPIYAML()`), consumed by the MCP service (`loadMCPServiceOpenAPISpec`, server/router/mcp/service.go:76-85) to build tools.

So the closest thing to a "public API schema" is the protobuf definitions in `proto/api/v1/*.proto` (with a generated OpenAPI/Swagger document) — the API is gRPC + REST (gRPC-Gateway) + Connect, and there is no GraphQL layer.
