**Handlers (RPC methods that can transitively trigger an outbound HTTP POST to a user-configured webhook URL):**

- **`MemoService.CreateMemo`** — dispatches `DispatchMemoCreatedWebhook` (via memo-created side effects; server/router/api/v1/memo_service.go, `CreateMemo`).
- **`MemoService.UpdateMemo`** (server/router/api/v1/memo_service.go:401) — calls `s.dispatchMemoUpdatedSideEffects` at server/router/api/v1/memo_service.go:513, which invokes `DispatchMemoUpdatedWebhook`.
- **`MemoService.DeleteMemo`** (server/router/api/v1/memo_service.go:518) — calls `s.DispatchMemoDeletedWebhook` at server/router/api/v1/memo_service.go:562.
- **`MemoService.CreateMemoComment`** (server/router/api/v1/memo_service_comments.go:20) — calls `DispatchMemoCommentCreatedWebhook`.

**Convergence function before delivery — `webhook.PostAsync` (internal/webhook/webhook.go:184).**

Why they converge there:

- The created/updated/deleted paths all route through the shared helper `dispatchMemoRelatedWebhook` (server/router/api/v1/memo_service_webhooks.go:48), which resolves the user's configured webhooks (`GetUserWebhooks`), builds the payload (`convertMemoToWebhookPayload`), and calls `PostAsync`.
- The comment path (`DispatchMemoCommentCreatedWebhook`) calls `PostAsync` directly.
- So the single point where every handler path meets before the request actually leaves the process is `PostAsync` (internal/webhook/webhook.go:184). It enqueues onto `asyncPostQueue`, and the worker goroutines then call `Post` (internal/webhook/webhook.go:120), where `safeClient.Do(req)` (internal/webhook/webhook.go:152) performs the actual outbound delivery — guarded at dial time by `safeDialContext` against internal addresses (per h02).

If you instead want the single function where delivery itself happens (rather than the pre-delivery convergence), that is `webhook.Post` (internal/webhook/webhook.go:120); but the point where all handler paths converge *before* delivery is `PostAsync`.
