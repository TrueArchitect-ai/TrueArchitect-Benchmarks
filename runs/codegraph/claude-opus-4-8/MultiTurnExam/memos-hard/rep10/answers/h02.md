**delivery function — `internal/webhook/webhook.go:120` (`Post`, which performs the actual outbound HTTP POST via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection mechanism — `internal/webhook/webhook.go:59` (`safeDialContext`), backed by `isReservedIP`/`reservedNetworks` at `internal/webhook/validate.go:44` / `:14-26`**

Details:
- The webhook payloads are dispatched via `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues to a bounded channel drained by worker goroutines started in `init` (`internal/webhook/webhook.go:42-55`); those workers call `Post`, where the real network delivery happens (`safeClient.Do`, line 152). Callers are in `server/router/api/v1/memo_service_webhooks.go` (e.g. `dispatchMemoRelatedWebhook`).
- SSRF protection is enforced at **dial time** by `safeDialContext` (`internal/webhook/webhook.go:57-77`), wired as the `DialContext` of the shared `safeClient.Transport` (`internal/webhook/webhook.go:32-37`). It resolves the target host and rejects any address in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44-54`) against the parsed `reservedNetworks` CIDR list (loopback, RFC-1918, link-local/IMDS `169.254.0.0/16`, IPv6 equivalents — `internal/webhook/validate.go:14-26`). Because the check happens after resolution at connect time, it also defeats DNS rebinding.
- There is additionally a create/update-time guard, `ValidateURL` (`internal/webhook/validate.go:62`), called from `server/router/api/v1/user_service_webhooks.go`, but the runtime protection that guards the actual delivery is `safeDialContext`. A `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) can disable the check for self-hosted local-network targets.
