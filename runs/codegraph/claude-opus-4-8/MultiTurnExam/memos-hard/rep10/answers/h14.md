**computation site — `RebuildMemoPayload` (server/runner/memopayload/runner.go:74), which calls `markdownService.ExtractAll(memo.Content)` and writes the result into `memo.Payload.Tags` and `memo.Payload.Property`; the actual extraction runs in the goldmark `service` (internal/markdown/markdown.go — property walk at internal/markdown/markdown.go:199-234). triggers — recomputed whenever a memo's content is created or edited: `CreateMemo` (server/router/api/v1/memo_service.go:108) and `UpdateMemo` (server/router/api/v1/memo_service.go:447); also a bulk backfill path `Runner.RunOnce` (server/runner/memopayload/runner.go:52) re-derives it for all memos. extracted properties — see below.**

What the computation extracts (from a single markdown parse of the content, stored in `storepb.MemoPayload`):
- **Tags** — all `#tags` found in the content (`memo.Payload.Tags`, from `ExtractedData.Tags`).
- **Property** (`memo.Payload.Property`, a `MemoPayload_Property`):
  - `Title` — text of the content's first block if it's an H1 heading (internal/markdown/markdown.go:210-212)
  - `HasLink` — true if any link node is present (:217)
  - `HasCode` — true for any code block/fenced code/inline code span (:219-220)
  - `HasTaskList` — true if any task checkbox exists (:222-223)
  - `HasIncompleteTasks` — true if any task checkbox is unchecked (:225-226)

This metadata is derived from content (not user-set) and is what lists/previews rely on. Note: the `Runner.RunOnce` bulk path exists but isn't wired into production startup (see h08); the live triggers are the `CreateMemo`/`UpdateMemo` handlers.
