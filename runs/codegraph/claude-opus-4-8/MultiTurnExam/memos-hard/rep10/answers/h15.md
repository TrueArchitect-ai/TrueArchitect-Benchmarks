Memo-view (read) visibility is enforced at several distinct server surfaces:

- gRPC/Connect API single-memo read — `checkMemoReadAccess` (gates `GetMemo` etc.: non-Public requires auth, Private requires owner) — server/router/api/v1/memo_service.go:54-65
- gRPC/Connect API list filtering — `ListMemos` restricts the query's `VisibilityList` (anonymous → Public only; authenticated → Public+Protected, plus own memos) — server/router/api/v1/memo_service.go:219-225
- File server (a memo's attachment/file bytes) — `checkAttachmentPermission` gates serving by the parent memo's visibility — server/router/fileserver/fileserver.go:677 and :699
- RSS feed — feed queries restrict to `VisibilityList: {Public}` — server/router/rss/rss.go:90 and :141
- Frontend SSR / sitemap / OG tags — restricts to `VisibilityList: {Public}` — server/router/frontend/frontend.go:150
- SSE realtime delivery filtering — `canReceive` only delivers Private events to the owner/admin (Public/Protected to any subscriber) — server/router/api/v1/sse_hub.go:135-141
- User stats aggregation — filters memos by `VisibilityList` based on viewer identity — server/router/api/v1/user_service_stats.go:84-90 and :218-220

(Related access checks that gate *interacting* with a memo rather than plain viewing also key off visibility: reactions — server/router/api/v1/reaction_service.go:30-38; comments — server/router/api/v1/memo_service_comments.go:41; attachment mutation — server/router/api/v1/memo_attachment_service.go:214-222.)
