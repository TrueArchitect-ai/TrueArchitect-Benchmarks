**Premise correction: neither — the webhook delivery workers do not consume from any external message broker. There is no NATS, no RabbitMQ, no AMQP/Kafka anywhere in the codebase** (repo-wide search of all Go source and `go.mod` for `nats`/`rabbitmq`/`amqp`/`kafka`/`broker` returns zero matches). So there is no broker-declared queue to point to.

**Actual mechanism:** delivery is dispatched through an in-process buffered Go channel, entirely inside `internal/webhook/webhook.go`:
- The "queue" is a package-level buffered channel declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (internal/webhook/webhook.go:39).
- The "workers" are 4 goroutines started in `init()` (internal/webhook/webhook.go:42-55), each ranging over `asyncPostQueue` and calling `Post` to perform the outbound HTTP delivery.
- Producers enqueue via `PostAsync` (internal/webhook/webhook.go:184), a non-blocking send that drops the payload with a warning if the channel is full.

This is a purely in-memory, single-process work queue — bounded at 128 pending payloads with 4 consumer goroutines — not a distributed broker. (The dispatch is triggered by memo RPC handlers via `DispatchMemo*Webhook` in `server/router/api/v1/memo_service_webhooks.go`.)
