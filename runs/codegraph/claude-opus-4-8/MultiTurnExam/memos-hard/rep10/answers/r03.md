**Premise correction: there is no nightly database-cleanup job — and in fact the cron scheduler is not wired into the running server at all — so there is no scheduled time to report.**

Findings:
- A cron scheduler package does exist (`internal/scheduler/` — `Scheduler`, `Job`, cron `Schedule`/`ParseCronExpression`), but it is a standalone library with **no production callers**. Searching all non-test Go for `NewScheduler`, `scheduler.`, or `.Register(` outside `internal/scheduler/` itself returns nothing — the only usages are the package's own tests (`internal/scheduler/*_test.go`). Nothing in `server/` or `cmd/` instantiates or registers jobs with it.
- There is **no database-cleanup job** registered anywhere. No `@daily`/`0 0 * * *`-style schedule, no "cleanup"/"prune"/"vacuum" cron job exists in the server. The `cleanup` references in the codebase are unrelated: per-request cascade deletes during memo/user deletion (e.g. server/router/api/v1/memo_service.go:579, server/router/api/v1/user_service.go:421-450) and the in-memory cache's expiry sweep (store/cache/cache.go).
- The actual scheduled background work in the server is not cron-based and not a DB cleanup: it's the S3-presign runner on a fixed 12-hour `time.Ticker` (server/runner/s3presign/runner.go), started from `server/server.go`.

So the question's premise (a nightly DB-cleanup job in the cron scheduler) does not hold: neither the job nor any use of the cron scheduler exists in the server.
