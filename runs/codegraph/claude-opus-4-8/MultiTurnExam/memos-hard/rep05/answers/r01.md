**Premise correction:** There is no Redis anywhere in this codebase. A repo-wide search for `redis` returns zero hits in Go source and no such dependency in `go.mod`. The cache layer is an **in-process, in-memory cache**, not Redis — so there is no Redis connection to configure.

**Actual mechanism:**
- The cache is implemented in `store/cache/cache.go` — a thread-safe in-memory store backed by a `sync.Map` with per-entry TTL and a background cleanup goroutine (`Cache` struct at `store/cache/cache.go:66`, `New` at `:76`).
- It is "configured" (no network — just Go config values) in `store.New` at `store/store.go:38-58`. The shared `cache.Config` is `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:40-45`). The user cache is instantiated at `store/store.go:52` (`userCache: cache.New(cacheConfig)`).
- **TTL for user entries:** user records are written with `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. `store/user.go:98`, `:122`, `:132`, `:143`, `:167`). `Cache.Set` delegates to `SetWithTTL(ctx, key, value, c.config.DefaultTTL)` (`store/cache/cache.go:93-94`), so user entries use the default TTL of **10 minutes**. A cleanup loop evicts expired entries every 5 minutes (`store/cache/cache.go:200-215`), and entries are also removed on user update/delete (`store/user_delete.go:40`).

**Answer:** No Redis exists — the cache is an in-memory `store/cache/cache.go` cache configured with plain Go values in `store.New` (`store/store.go:38-58`); user entries are stored via `Cache.Set`, which applies the config's `DefaultTTL` = **10 minutes** (`store/store.go:41`, `store/cache/cache.go:93-94`).
