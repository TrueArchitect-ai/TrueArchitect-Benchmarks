**Premise correction:** There is no per-user API rate-limiting middleware in this repository — so there is nothing to register and no request limits to report.

Evidence:
- A repo-wide search for any rate-limiting construct (`ratelimit`, `limiter`, `throttle`, `golang.org/x/time/rate`) finds **no** rate-limiter in the Go source. The only match is a documentation comment listing a hypothetical future idea ("Rate limit email sending to prevent abuse") in `internal/email/doc.go:86` — not an implementation, and about email, not the API.
- The global Echo middleware chain registered at server construction is only `middleware.Recover()` and `newCORSMiddleware(profile)` — `server/server.go:51-52`. The frontend router additionally registers static-file and SPA-fallback middleware (`server/router/frontend/frontend.go:54`, `:59`). None of these limit request rates.
- The request pipeline has authentication/authorization (e.g. the `auth.Authenticator`, per-endpoint permission checks) but no counter, token bucket, or window-based limiter keyed on user or IP anywhere.

So the question's premise is mistaken: memos does not implement per-user (or per-IP) API rate limiting. If such protection is needed, it would have to come from an external layer (reverse proxy / gateway), which is outside this codebase.
