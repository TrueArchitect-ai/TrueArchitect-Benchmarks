**Premise correction:** There is no nightly database-cleanup job scheduled in a cron scheduler — so there is no run time to report. The premise is doubly mistaken.

Evidence:
- A cron scheduler package does exist (`internal/scheduler`, with `Scheduler`, `Job`, and cron-expression parsing in `internal/scheduler/scheduler.go`, `internal/scheduler/parser.go`), **but it is not used anywhere in production.** The only files that import `github.com/usememos/memos/internal/scheduler` are `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go` — both tests. No server or startup code constructs `scheduler.New()` or registers any `Job` (the `New`/`Register`/`Start` calls exist only in doc-comment examples in `internal/scheduler/doc.go`).
- The background work that actually runs at startup is wired in `Server.startBackgroundRunners` (`server/server.go:153-173`), and the only runner registered there is the **S3 presign** runner (`s3presign.NewRunner`, `server/server.go:162`), which refreshes S3 URLs every 12 hours (`server/runner/s3presign/runner.go:27`). That is not a database-cleanup job and is not cron-scheduled — it uses a simple `time.Ticker`.
- There is no "nightly", `@daily`, or database-cleanup job anywhere: a search for `nightly` / `@daily` / `database.*cleanup` in Go source returns nothing.

So no nightly DB-cleanup cron job exists; the `internal/scheduler` cron package is present but wired to nothing in the running server.
