Third-party SSO login is built around a two-package structure under `internal/idp`:

- **Abstraction package** — `internal/idp` (Go import path `github.com/usememos/memos/internal/idp`). It defines the provider-neutral types, notably `idp.IdentityProviderUserInfo`, which the OAuth2 implementation imports and returns (`internal/idp/oauth2/oauth2.go:15` imports it; used at `:83`, `:114`).
- **Implementation package** — `internal/idp/oauth2`, whose package doc reads *"Package oauth2 implements the OAuth2 identity provider integration"* (`internal/idp/oauth2/oauth2.go:1-2`). It provides the concrete `IdentityProvider` struct with `NewIdentityProvider`, `ExchangeToken` (PKCE-capable), and `UserInfo` (`internal/idp/oauth2/oauth2.go:20-142`). OAuth2 is the only concrete protocol that ships — the store/proto config and service conversions only handle `IdentityProvider_OAUTH2` (`server/router/api/v1/idp_service.go:191`, `:226`).

**Answer:** abstraction package — `internal/idp`; implementation package — `internal/idp/oauth2`.
