Webhook delivery is triggered by memo-mutation RPC handlers on `APIV1Service`, all of which funnel through the async webhook dispatcher into the actual HTTP POST.

RPC handlers (each transitively POSTs to the user-configured webhook `Url`):
- **`UpdateMemo`** — `server/router/api/v1/memo_service.go:401`; calls `dispatchMemoUpdatedSideEffects` (`:513`) → `DispatchMemoUpdatedWebhook`.
- **`DeleteMemo`** — `server/router/api/v1/memo_service.go:518`; calls `DispatchMemoDeletedWebhook` directly (`:562`).
- **`CreateMemo`** — `server/router/api/v1/memo_service.go`; dispatches `DispatchMemoCreatedWebhook` ("memos.memo.created").
- **`CreateMemoComment`** — dispatches `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:30`), which posts to the parent memo owner's webhook.

Convergence: The created/updated/deleted paths first collapse into `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), and together with the comment path they all call `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the shared queue whose worker goroutines invoke the single delivery function **`webhook.Post`** — the one place where the outbound `safeClient.Do(req)` HTTP request actually executes (`internal/webhook/webhook.go:120`, network call at `:152`).

**Answer:** handlers — `APIV1Service.UpdateMemo`, `APIV1Service.DeleteMemo`, `APIV1Service.CreateMemo` (also `CreateMemoComment`), all in `server/router/api/v1/memo_service.go` / `memo_service_webhooks.go`; convergence function — `webhook.Post` (`internal/webhook/webhook.go:120`), reached via the shared `webhook.PostAsync` (`internal/webhook/webhook.go:184`).
