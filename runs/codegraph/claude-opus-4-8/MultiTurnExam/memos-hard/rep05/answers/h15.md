Memo visibility (`PUBLIC` / `PROTECTED` / `PRIVATE`) is enforced across several distinct server surfaces. The core "who may view a memo" enforcement sites:

- Single-memo read gate — `APIV1Service.checkMemoReadAccess` (public passes; protected requires auth; private requires creator) — `server/router/api/v1/memo_service.go:39` (checks at `:55-63`; archived-only-to-creator at `:46`)
- Memo listing filter — `APIV1Service.ListMemos` restricts results to `PUBLIC` (anonymous), or `PUBLIC`+`PROTECTED` / own memos (authenticated) — `server/router/api/v1/memo_service.go:213-227`
- Attachment/file HTTP server — `FileServerService.checkAttachmentPermission` gates attachment bytes by the owning memo's visibility (public+anonymous allowed; private only creator/admin; share-token fallback) — `server/router/fileserver/fileserver.go:650` (checks at `:677`, `:699`)
- RSS feed — only `store.Public` memos are ever included — `server/router/rss/rss.go:90` and `server/router/rss/rss.go:141`
- Frontend sitemap (server-side rendering) — only `store.Public` memos — `server/router/frontend/frontend.go:150`
- SSE realtime delivery filter — private memo events delivered only to their creator — `server/router/api/v1/sse_hub.go:136-138`

Additional surfaces that enforce the same memo-visibility rule when viewing memo-related resources:

- Reaction viewing/creation — `server/router/api/v1/reaction_service.go:30-38` (and `:83`)
- v1 attachment access — `server/router/api/v1/attachment_service.go:445-451` and `server/router/api/v1/memo_attachment_service.go:214-222`
- Comment access — `server/router/api/v1/memo_service_comments.go:41`
- User stats aggregation — `server/router/api/v1/user_service_stats.go:84-90` (and `:218-220`)
- Notification/email gating — `server/router/api/v1/user_service_notifications.go:309-312`, `server/notification/email.go:313-316`
