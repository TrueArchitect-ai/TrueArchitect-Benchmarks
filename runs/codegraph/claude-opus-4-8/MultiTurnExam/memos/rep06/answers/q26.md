memo, memo_relation, attachment

When `store.DeleteMemo` (`store/memo.go:140`) runs, it explicitly deletes:
- `memo_relation` rows (both where the memo is the source and where it's the target)
- `attachment` rows linked to the memo (via `DeleteAttachment`, which also removes the underlying storage file — not a DB table)
- the `memo` row itself

No other tables are touched by explicit cascade code (reactions are listed for the webhook payload in the API handler but not deleted here). At the API layer, comment memos are additionally deleted, but that recurses through the same `store.DeleteMemo` and so affects the same three tables.
