memo, memo_relation, attachment

When `DeleteMemo` runs, the explicit cascade in `Store.DeleteMemo` (`store/memo.go:140-158`) deletes:
- **memo_relation** rows (where the memo is either `memo_id` or `related_memo_id`)
- **attachment** rows linked to the memo (via `Store.DeleteAttachment`, which also removes the underlying storage blob — not a table)
- the **memo** row itself (and, at the API layer, comment memos recursively, each cascading the same way)

Note: reactions on the memo are *listed* (for the webhook payload) but not explicitly deleted by this path, so the `reaction` table is not affected by explicit cascade code.
