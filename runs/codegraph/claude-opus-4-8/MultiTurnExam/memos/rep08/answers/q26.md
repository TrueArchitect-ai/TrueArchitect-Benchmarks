memo, memo_relation, attachment

When `DeleteMemo` runs, the explicit cascade code (`Store.DeleteMemo`, store/memo.go:140-158) deletes rows from:
- **memo_relation** — where the memo is either source (`MemoID`) or target (`RelatedMemoID`)
- **attachment** — all attachments linked to the memo (via `DeleteAttachment`; this also removes the underlying file storage, not a DB table)
- **memo** — the memo row itself, plus comment memos deleted first at the API layer (server/router/api/v1/memo_service.go:568-580), each recursing through the same cascade

Note: `reaction` rows are listed only to build the webhook/SSE payload — they are **not** explicitly deleted in this path.
