Tables affected: **memo, memo_relation, attachment**

`Store.DeleteMemo` (store/memo.go:140) explicitly deletes:
- `memo_relation` rows where the memo is the source (`memo_id`) and where it is the target (`related_memo_id`)
- `attachment` rows linked to the memo (via `DeleteAttachment`)
- the `memo` row itself (`driver.DeleteMemo`)

The API handler (`server/router/api/v1/memo_service.go:518`) additionally deletes each comment memo, but that recurses through the same `Store.DeleteMemo`, so it touches the same three tables.

Note: there are no SQL-level `FOREIGN KEY ... ON DELETE CASCADE` constraints in the schema (e.g. `store/migration/sqlite/LATEST.sql`), and `reaction` rows are **not** removed by `DeleteMemo` (they are only listed for the webhook payload, not deleted).
