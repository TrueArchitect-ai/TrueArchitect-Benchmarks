Mechanism: The `Engine` (`internal/filter/engine.go:14`) uses a `cel.Env` to parse the CEL filter string into an AST, converts it into a dialect-agnostic `Condition` tree, and then a `renderer` (`internal/filter/render.go`) walks that tree emitting per-dialect SQL (a `WHERE` fragment plus bound args) by branching on `DialectName` — `DialectSQLite`, `DialectMySQL`, `DialectPostgres` — for things like timestamp accessors and string length, which the memo store then splices into its `ListMemos` query for the active driver.
