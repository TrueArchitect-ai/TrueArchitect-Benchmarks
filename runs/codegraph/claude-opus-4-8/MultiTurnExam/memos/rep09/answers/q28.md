**Runners the server actually starts** (in `Server.startBackgroundRunners`, `server/server.go:153`):

- s3presign runner — `RunOnce(ctx)` immediately at startup, then a continuous `Run` loop driven by a `time.Ticker` firing every 12 hours (`runnerInterval = 12h`, `server/runner/s3presign/runner.go:26-40`). It re-presigns S3 attachment URLs.

That is the only background runner started.

**Notes on infrastructure present but NOT started as a server background runner:**
- `server/runner/memopayload` — has a `Runner` type, but the server never calls `memopayload.NewRunner`/starts it as a background job. It is used only synchronously via the package function `memopayload.RebuildMemoPayload(...)`, invoked inline inside memo create/update handlers (`server/router/api/v1/memo_service.go:108,447`).
- `internal/scheduler` — a full cron-style scheduling framework (`scheduler.go`, `job.go`, `parser.go`, `Schedule`/field matchers) exists in the codebase, but **nothing outside the package imports it** (`grep` for `internal/scheduler` finds no importers). It is entirely unused by the server; the one real runner uses a plain `time.Ticker` instead.
