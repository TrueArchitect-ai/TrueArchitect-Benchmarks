**Interceptor path:** `web/src/connect.ts` — the ConnectRPC transport is configured with `credentials: "include"` (sends auth cookies) plus an auth `Interceptor` that reactively refreshes on a 401 and a `tokenRefreshManager`/`refreshAccessToken` that deduplicates refreshes (lines ~30-90; the interceptor is attached to the main `transport`).

**Token kinds it manages:** short-lived **access tokens** and **refresh tokens** (JWTs delivered via cookies); the interceptor also supports **personal access tokens (PATs)** as bearer credentials on the backend side. It reactively calls `refreshToken` to mint a new access token from the refresh token.

**Backend validation package:** `server/auth` — the `Authenticator` (`server/auth/authenticator.go`) validates access tokens (`AuthenticateByAccessTokenV2`), refresh tokens (`AuthenticateByRefreshToken`), and PATs (`AuthenticateByPAT`); it is invoked via the `Authorizer.Authenticate` wrapper in `server/router/api/v1/authz.go:44`, wired into the Connect/gateway interceptors (`server/router/api/v1/connect_interceptors.go`).
