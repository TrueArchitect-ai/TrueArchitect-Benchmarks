**Engine:** Google CEL (Common Expression Language, via `github.com/google/cel-go`) — the engine lives in `internal/filter/` (`engine.go` compiles the CEL filter; `parser.go` + `ir.go` build a dialect-agnostic condition/IR tree; `render.go` and `schema.go` handle SQL emission).

**Mechanism:** The filter string is compiled by the CEL `Engine` (`internal/filter/engine.go:14`) into a dialect-agnostic `Condition` tree, then a `renderer` (`internal/filter/render.go`) walks that tree and emits SQL for the target `DialectName` (`sqlite`, `mysql`, or `postgres` — `internal/filter/schema.go:14-16`), using per-dialect expression templates (e.g. `||` vs `CONCAT`) and placeholder styles to produce parameterized SQL passed to each store driver.
