**interceptor path**: `web/src/connect.ts` — the `authInterceptor` (line 156) attaches the access token as an `Authorization: Bearer <token>` header, and on a 401 or near-expiry it proactively/reactively refreshes via `refreshAccessToken` → `AuthService.refreshToken`.

**token kinds**: A short-lived **JWT access token** (held in memory client-side, sent as the `Authorization` Bearer header) and a **refresh token** (managed via cookie, exchanged at `refreshToken` to mint new access tokens). The backend additionally supports **Personal Access Tokens (PATs)**.

**backend package path**: `server/auth/` — the `Authenticator` (`server/auth/authenticator.go`) validates JWT access tokens (`AuthenticateByAccessTokenV2` / `ParseAccessTokenV2`) and PATs (`AuthenticateByPAT`); wired into request handling via `server/router/api/v1/authz.go` (`Authenticate`) and the Connect interceptors.
