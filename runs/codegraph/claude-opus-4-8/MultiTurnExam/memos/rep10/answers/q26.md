**memo, memo_relation, attachment**

When `DeleteMemo` runs (`store/memo.go:140` + API handler `server/router/api/v1/memo_service.go:518`), the explicit cascade code affects:

- **memo_relation** — rows where the memo is source (`MemoID`) or target (`RelatedMemoID`) are deleted (`store/memo.go:142-147`)
- **attachment** — rows linked to the memo are deleted via `DeleteAttachment` (`store/memo.go:149-157`; also removes backing storage/files, not a table)
- **memo** — the memo row itself, and additionally each comment memo is deleted (recursively through the same path) by the API handler (`memo_service.go:573-580`)

Note: the `reaction` table is **not** cleaned up by explicit cascade code — the delete handler only *reads* reactions to build the webhook payload; foreign-key cascades were removed by migration `store/migration/sqlite/0.7/00__remove_fk.sql`, so reaction rows are not deleted here.
