**Premise correction**: Neither NATS nor RabbitMQ is used. The codebase does not use a message broker for webhook delivery.

**Actual mechanism**: Webhook delivery uses an in-memory Go channel-based queue for asynchronous processing. Specifically:
- The queue is declared at `internal/webhook/webhook.go:39` as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — an unbuffered channel with capacity 128
- Four worker goroutines are spawned in `init()` (lines 42-54) that consume from this queue and execute the actual HTTP POST to the webhook endpoint via the `Post()` function
- Webhooks are enqueued asynchronously via `PostAsync()` which sends the payload to the queue (lines 184-196)

This is a simple in-process queue with no external message broker—all webhook delivery workers consume from the same in-memory Go channel.
