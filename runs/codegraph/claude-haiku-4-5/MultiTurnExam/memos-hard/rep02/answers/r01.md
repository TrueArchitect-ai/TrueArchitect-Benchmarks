**Premise correction:** There is no Redis connection configured for the cache layer. The question assumes Redis-backed caching, but the implementation uses a different approach.

**Actual mechanism:** The cache layer is an **in-memory cache** implemented at `store/cache/cache.go` with no Redis integration. User entries are cached using this in-memory cache with a **default TTL of 10 minutes** (configured at `store/cache/cache.go:59` via `DefaultConfig()` returning `DefaultTTL: 10 * time.Minute`). 

User entries are stored in `s.userCache` initialized in `store/store.go:52` as a `cache.Cache` instance with this default configuration. When users are retrieved or created (`store/user.go:98, 122, 132, 143, 167`), they are cached with the default TTL. The cache is managed locally within each server process with automatic expiration cleanup every 5 minutes.
