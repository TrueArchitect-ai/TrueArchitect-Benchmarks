**Premise correction:** Neither NATS nor RabbitMQ is used for webhook delivery. The question assumes an asynchronous message-broker-based worker pattern that does not exist in the codebase.

**Actual mechanism:** Webhook delivery is performed synchronously via HTTP POST. The dispatch happens directly in the RPC handlers through `internal/webhook/webhook.go:120` — the `Post()` method calls `safeDialContext()` to make a direct HTTP request to the webhook URL with SSRF protection. There is no message queue, no workers, and no broker integration.

Webhook dispatch is triggered at two points:
1. **Memo creation** — `server/router/api/v1/memo_service.go` calls `DispatchMemoCreatedWebhook()`
2. **Memo comment creation** — `server/router/api/v1/memo_service.go` calls `DispatchMemoCommentCreatedWebhook()`

Both converge at `server/router/api/v1/memo_service_webhooks.go:120` where `dispatchMemoRelatedWebhook()` calls `webhook.Post()` synchronously within the request context. No asynchronous job queue or message broker infrastructure exists.
