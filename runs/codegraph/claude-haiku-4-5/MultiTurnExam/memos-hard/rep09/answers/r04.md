**Premise correction:** This codebase does not use NATS or RabbitMQ for webhook delivery. It uses an in-memory channel.

**Actual mechanism:** Webhook delivery workers consume from a simple in-memory buffered channel declared in internal/webhook/webhook.go:

- **Queue declaration:** `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (line 39)
- **Worker initialization:** 4 worker goroutines are spawned in the init() function (lines 42-54) that range over the asyncPostQueue channel
- **Producer:** PostAsync() function (line 184) enqueues webhooks to the channel
- **Consumer:** Each of 4 worker goroutines calls Post() to dispatch the webhook (line 46)
- **Capacity:** 128 payload capacity (line 39); payloads are dropped with a warning if the queue is full (lines 189-195)

This is a bounded, in-process, synchronous webhook dispatcher with no external message broker.
