**Explicit Go code; Evidence locations:**

Emoji reactions are removed through **explicit Go code**, not database-level constraints. When a user is deleted, the Go implementation calls `deleteReactionsByCreatorTx()` which executes a SQL DELETE statement targeting all reactions where `creator_id` matches the deleted user ID.

**Checked:**
1. **MySQL implementation:** store/db/mysql/user_delete.go:102 calls `deleteReactionsByCreatorTx()`; line 437-439 shows the deletion: `DELETE FROM reaction WHERE creator_id = ?`
2. **PostgreSQL implementation:** store/db/postgres/user_delete.go:102 calls the same function with identical SQL logic
3. **SQLite implementation:** store/db/sqlite/user_delete.go follows the same pattern
4. **Schema verification:** store/migration/mysql/LATEST.sql shows the `reaction` table has NO foreign key constraints on `creator_id` — only a UNIQUE constraint on the combination of `(creator_id, content_id, reaction_type)`

There are TWO separate reaction deletion operations in the user delete flow:
- Line 96: `deleteReactionsByContentIDsTx()` — removes reactions on memos created by the user
- Line 102: `deleteReactionsByCreatorTx()` — removes reactions created by the user (emoji reactions they added to other memos)
