**Premise correction:** This codebase does not use Redis. It uses an in-memory cache layer.

**Actual mechanism:** User entries are cached in-memory using `store.userCache` (store/store.go:28, initialized at line 52). The cache is created with a default TTL of **10 minutes** (store/store.go:41) using the in-memory `cache.Cache` implementation (store/cache/cache.go). All cache instances (userCache, userSettingCache, instanceSettingCache) use the same configuration defined in store/store.go:40-45, which specifies:
- **DefaultTTL: 10 minutes** for all cache entries including users
- CleanupInterval: 5 minutes (how often expired entries are removed)
- MaxItems: 1000 (memory cap)

The cache is thread-safe, in-memory only, with no external Redis dependency. User cache entries expire and are cleaned up periodically based on their 10-minute TTL.
