**Premise correction:** The codebase does not use NATS or RabbitMQ or any external message broker. Instead, it uses an in-memory buffered Go channel for webhook delivery.

**Actual mechanism:** Webhook delivery workers consume from an in-memory channel queue declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a buffered channel with capacity 128. Four worker goroutines are spawned at initialization time (lines 42–55) via `init()` that continuously consume from this queue and dispatch webhooks synchronously via the `Post()` function (line 46). The `PostAsync()` function (lines 182–196) enqueues webhook payloads into this channel; if the channel is full, the request is dropped with a warning log (lines 191–194) rather than being queued to an external broker.
