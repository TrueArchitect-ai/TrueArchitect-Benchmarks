**Premise correction:** The codebase does not use GraphQL for the public API. Instead, it uses Protocol Buffers (gRPC) with gRPC-Gateway for HTTP/REST endpoints.

**Actual API surface:** The API is defined in Protocol Buffer service definitions located in `/bench/home/work/proto/api/v1/` with the following services:

- `memo_service.proto` — Memo CRUD, attachments, relations, comments, and reactions
- `auth_service.proto` — Authentication (signin, signout, signup)
- `user_service.proto` — User management, access tokens, webhooks
- `attachment_service.proto` — Attachment operations
- `instance_service.proto` — Instance settings and statistics
- `shortcut_service.proto` — User shortcuts
- `ai_service.proto` — AI operations
- `idp_service.proto` — Identity provider configuration
- `common.proto` — Shared types

Each `.proto` file uses `google.api.http` annotations to define REST endpoints. The service handlers are implemented in Go (`server/router/api/v1/`) and the proto definitions are compiled to gRPC service code (in `proto/gen/api/v1/`), then exposed via gRPC-Gateway (line 88 in `server/server.go`) which translates HTTP/JSON requests to gRPC calls, and via Connect RPC handlers (line 140 in `server/server.go`) for browser-compatible RPC.
