When DeleteMemo runs, the following database tables are affected:
1. **memo** — the memo row is deleted directly
2. **memo_relation** — all relations where the memo is either the source or target are deleted
3. **attachment** — all attachments linked to the memo are deleted (via DeleteAttachment)
4. **reaction** — implicitly affected as reactions reference memos (via ContentID in the memo_service.go DeleteMemo handler where reactions are listed)

Additionally, the API layer also deletes memo comments (which are themselves memos), so the recursion means multiple rows in the **memo** table can be deleted, and their associated **memo_relation** and **attachment** records are also cascaded.
