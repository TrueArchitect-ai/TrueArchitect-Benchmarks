**Premise correction:** The question assumes webhook delivery workers consume from a message broker (NATS or RabbitMQ), but this is not accurate.

**Actual mechanism:** Webhook delivery workers do not consume from NATS or RabbitMQ. Instead, webhooks are dispatched asynchronously using an in-process Go channel. In `internal/webhook/webhook.go:39`, a channel `asyncPostQueue` is declared with a buffer size of 128. On init (lines 42-55), 4 goroutines are spawned that continuously read from this channel and call the `Post()` function to deliver each webhook request. When `PostAsync()` is called (line 184), it enqueues the webhook payload onto this local channel; if the channel is full, the payload is dropped and logged.
