**Premise correction:** The premise that Redis is configured for the cache layer is incorrect.

**Actual mechanism:** The cache layer does NOT use Redis. Instead, the codebase implements an in-memory cache system.

**Configuration location and TTL details:**

1. **In-memory cache implementation** (`store/cache/cache.go:41-64`): The cache is a thread-safe in-memory store with:
   - **Default TTL for user entries: 10 minutes** (`store/store.go:41`)
   - Configuration: `DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000`

2. **User cache initialization** (`store/store.go:38-61`): The `Store` struct creates an in-memory cache using `cache.New(cacheConfig)` with the TTL configuration above. User entries are stored using `userCache.Set()` with the default 10-minute TTL (`store/user.go:98`, `store/user.go:132`, `store/user.go:143`).

3. **Cache implementation** (`store/cache/cache.go:76-90`): The `New()` function creates a thread-safe in-memory cache backed by `sync.Map`, not Redis. The cache runs a cleanup loop that removes expired items every 5 minutes.

The cache layer is entirely in-process memory with no external Redis dependency.
