Based on the codebase exploration, markdown processing operates behind two distinct interfaces:

**Backend Interface:**
- **Implementation:** `service` (internal/markdown/markdown.go:58) — a struct wrapping goldmark.Markdown
- **Construction:** `NewService()` (internal/markdown/markdown.go:85) — factory function that returns `Service` interface, creates goldmark instance with configurable extensions (GFM, tags, mentions)
- **Holders:** `NewRSSService` (server/router/rss/rss.go), `NewRunner` (server/runner/memopayload/runner.go) — hold references to the `Service` interface

**Frontend Interface:**
- **Implementation:** `ReactMarkdown` from react-markdown library (web/src/components/MemoContent/MemoMarkdownRenderer.tsx:4)
- **Construction:** Instantiated inline in `MemoMarkdownRenderer` component (web/src/components/MemoContent/MemoMarkdownRenderer.tsx:144-164) with plugins (remark-*, rehype-*) and custom component mappings
- **Holders:** `MemoMarkdownRenderer` component (web/src/components/MemoContent/MemoMarkdownRenderer.tsx:56) held in `MemoContent` (web/src/components/MemoContent/index.tsx)

The backend uses a goldmark-based Service interface for tag/mention extraction and HTML rendering; the frontend uses react-markdown with custom remark/rehype plugins for client-side markdown rendering.
