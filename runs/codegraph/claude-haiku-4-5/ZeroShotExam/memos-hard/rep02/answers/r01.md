**Premise correction:** There is no Redis connection for the cache layer. The cache implementation does not use Redis at all.

**Actual mechanism:** The cache layer is implemented as an in-memory cache (not Redis-backed). User entries have a **10-minute default TTL**.

**Details:**

1. **Cache Implementation** (store/cache/cache.go:66-90): The cache is a thread-safe in-memory cache using Go's `sync.Map` for storage. It is NOT Redis-based.

2. **Store Initialization** (store/store.go:38-61): When the Store is created, it initializes three in-memory caches using `cache.New()`:
   - `userCache` (line 52)
   - `instanceSettingCache` (line 51)
   - `userSettingCache` (line 53)

3. **User Cache Configuration** (store/store.go:40-45):
   ```go
   cacheConfig := cache.Config{
       DefaultTTL:      10 * time.Minute,
       CleanupInterval: 5 * time.Minute,
       MaxItems:        1000,
       OnEviction:      nil,
   }
   ```

4. **TTL for User Entries**: User entries use the default TTL of **10 minutes** (store/cache/cache.go:59 and store/store.go:41). This TTL is applied when calling `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g., store/user.go:98, 122, 132, 143, 167).
