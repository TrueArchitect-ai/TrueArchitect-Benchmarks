**Premise correction:** The question assumes a Redis connection, but the codebase does not use Redis. The cache layer is an in-process memory cache.

**Actual mechanism:**

1. **Cache interface:** Defined in `store/cache/cache.go` as a generic `Interface` with methods like `Set()`, `SetWithTTL()`, `Get()`, `Delete()`, and `Clear()`.

2. **User cache configuration:** In `store/user.go`, user entries are cached using `s.userCache.Set(ctx, userCacheKey(userID), user)` where the cache key is the user's ID converted to a string (`store/user.go:88-90`). The TTL for user cache is not explicitly set in the code shown — the `Set()` method uses a default TTL (defined in the `Cache` interface but not shown in the excerpt).

3. **RSS feed cache:** For RSS feeds, the cache TTL is explicitly defined as **1 hour** (`server/router/rss/rss.go:25`):
   ```go
   defaultCacheDuration = 1 * time.Hour
   ```
   This duration is checked in `getFromCache()` at line 357 (`server/router/rss/rss.go:357`) and applied when storing entries via `putInCache()`.

The cache is configured **in-memory** without Redis, using the interface-based abstraction in `store/cache/cache.go`.
