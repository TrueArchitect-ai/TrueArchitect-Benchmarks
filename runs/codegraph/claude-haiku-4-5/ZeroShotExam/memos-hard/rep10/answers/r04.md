**Premise correction:** The question assumes webhook delivery workers consume from an external message broker (NATS or RabbitMQ). This is incorrect.

**Actual mechanism:** The webhook delivery system uses neither NATS nor RabbitMQ. Instead, it uses an in-memory Go channel for asynchronous queueing:

- **Queue declaration location:** `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a bounded channel with capacity 128
- **Worker pool:** `internal/webhook/webhook.go:42-55` — the `init()` function spawns 4 goroutines that consume from `asyncPostQueue` and call `Post()` to dispatch each webhook payload
- **Payload enqueueing:** `internal/webhook/webhook.go:184-195` — the `PostAsync()` function enqueues payloads into the channel; if the queue is full, payloads are dropped with a warning log

This is a lightweight, in-process queue using Go's concurrency primitives, not an external message broker system.
