**Premise correction:** The repository does not use Redis for caching. Instead, it uses an in-process Go cache layer.

**Actual mechanism:** The cache is configured in `store/cache/cache.go` with a standard `Interface` type that defines `Set`, `SetWithTTL`, `Get`, `Delete`, `Clear`, and `Size` operations. For user entries specifically:

- **User cache key format** (store/user.go:88-90): User cache keys are generated via `userCacheKey()` which converts the user ID to a string: `strconv.Itoa(int(userID))`
- **User cache usage** (store/user.go:98, 122, 132, 143, 167): User entries are cached via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` using the default TTL
- **Default TTL** (store/cache/cache.go:12-16): The `Set` method adds values with a "default TTL" (the specific duration is defined in the `Config` struct), while `SetWithTTL` allows custom TTL specification
- **RSS service cache** (server/router/rss/rss.go:25): For reference, RSS feeds use an explicit TTL of `1 * time.Hour`

The user cache uses the in-process cache's default TTL, not a custom duration. The exact default TTL value would be found in the `Config` struct initialization in `store/cache/cache.go`.
