**Premise correction:** The question assumes webhook delivery workers consume from an external message broker (NATS or RabbitMQ), but this is incorrect.

**Actual mechanism:** Webhook delivery uses an in-memory buffered channel queue, not an external message broker.

**Details** (`internal/webhook/webhook.go:39-55`):
- An `asyncPostQueue` is a buffered Go channel with capacity of 128 (`make(chan *WebhookRequestPayload, 128)`)
- Four goroutine workers are spawned in the `init()` function that consume from this queue
- When `PostAsync()` is called, webhook payloads are enqueued to this channel (with a warning if the queue is full)
- If the queue is full, the webhook dispatch is dropped and a warning is logged

This is a simple in-process async queue with bounded capacity and multiple workers, similar to the email system in the same codebase (`internal/email/email.go:14-36`).
