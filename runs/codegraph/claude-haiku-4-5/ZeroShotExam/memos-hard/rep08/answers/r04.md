**Premise correction:** The question assumes webhook delivery workers consume from either NATS or RabbitMQ. This premise is incorrect.

**Actual mechanism:** Webhook delivery does not use an external message broker at all. Instead, webhooks are delivered asynchronously using an in-memory buffered Go channel (`asyncPostQueue`), declared in `internal/webhook/webhook.go:39`.

**Details:**
- The queue is declared as: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel with capacity 128
- The queue is initialized in the `init()` function (`internal/webhook/webhook.go:42-55`), which spawns 4 concurrent workers
- Each worker reads from `asyncPostQueue` and calls `Post()` to dispatch the webhook synchronously to its target URL
- `PostAsync()` (`internal/webhook/webhook.go:184-195`) enqueues webhook payloads to this channel; if the queue is full, payloads are dropped with a warning log
- This is similar to the email delivery pattern in `internal/email/email.go`, which uses an identical channel-based approach with a buffered queue
