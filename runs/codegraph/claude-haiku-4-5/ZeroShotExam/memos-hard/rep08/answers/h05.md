h05. **Explicit Go code removes emoji reactions (not database-level cascade).**

**Mechanism:** When a user is deleted, emoji reactions are removed through two explicit Go `DELETE FROM reaction` SQL statements in the `deleteUserTargetsTx` function:

1. **Reactions on the user's own memos** — removed via `deleteReactionsByContentIDsTx()` (store/db/mysql/user_delete.go:417-424, store/db/postgres/user_delete.go:380-387, store/db/sqlite/user_delete.go:380-387), which deletes reactions where `content_id` matches memo UIDs from the deleted user's memo tree.

2. **Reactions created by the user** — removed via `deleteReactionsByCreatorTx()` (store/db/mysql/user_delete.go:437-440, store/db/postgres/user_delete.go:400-403, store/db/sqlite/user_delete.go:400-403), which deletes reactions where `creator_id = userID`.

Both functions are called explicitly from `deleteUserTargetsTx` (store/db/mysql/user_delete.go:92-127) before cascading deletes of memos themselves. There is no evidence of database-level CASCADE constraints; the application code is responsible for the cleanup.

**Evidence locations:**
- `store/db/mysql/user_delete.go:96-97` (calls both deletion functions)
- `store/db/mysql/user_delete.go:417-424` (deleteReactionsByContentIDsTx – delete reactions on user's memos)
- `store/db/mysql/user_delete.go:437-440` (deleteReactionsByCreatorTx – delete user's reactions)
- Identical implementations in `store/db/postgres/user_delete.go:380-387, 400-403`
- Identical implementations in `store/db/sqlite/user_delete.go:380-387, 400-403`
