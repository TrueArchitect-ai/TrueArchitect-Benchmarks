The markdown processing stack uses **two distinct patterns**:

**Frontend (React):**
- **Implementation**: `ReactMarkdown` (from the `react-markdown` library)
- **Construction**: Instantiated directly in `MemoMarkdownRenderer` (web/src/components/MemoContent/MemoMarkdownRenderer.tsx:144)
- **Holders**: `MemoMarkdownRenderer` component wraps it and configures it with custom remark/rehype plugins and a `markdownComponents` object (lines 145–162)

**Backend (Go):**
- **Interface**: `Service` interface (internal/markdown/markdown.go:31–55) defining ExtractTags, ExtractProperties, RenderMarkdown, RenderHTML, etc.
- **Concrete Implementation**: `service` struct (internal/markdown/markdown.go:58–59) with a goldmark.Markdown instance
- **Construction**: `NewService()` factory function (internal/markdown/markdown.go:85–113) creates and configures the service with GFM extensions and optional tag/mention extensions
- **Holders**: Used by `NewRSSService` (server/router/rss/rss.go:58) and `RebuildMemoPayload` (server/runner/memopayload/runner.go:74)

The frontend delegates markdown rendering to the React library with custom component overrides; the backend abstracts markdown processing behind a Service interface using goldmark as the underlying parser.
