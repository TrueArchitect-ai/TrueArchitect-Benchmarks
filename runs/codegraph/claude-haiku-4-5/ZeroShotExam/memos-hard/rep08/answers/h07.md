The browser request for another user's profile image flows through the following handler and data layer hops:

**serveUserAvatar** — server/router/fileserver/fileserver.go:168
  ↓ (extracts identifier from URL path parameter)
**getUserByUsername** — server/router/fileserver/fileserver.go:715
  ↓ (calls Store.GetUser with FindUser filter)
**GetUser** — store/user.go:148
  ↓ (queries database for user record)
**User struct with AvatarURL field** — store/user.go

The serving handler (`serveUserAvatar` at server/router/fileserver/fileserver.go:168) receives the request at the `/file/users/:identifier/avatar` route (server/router/fileserver/fileserver.go:124), then calls `getUserByUsername` (server/router/fileserver/fileserver.go:715) to fetch the user by username. That function calls the Store's `GetUser` method (store/user.go:148) which queries the database. The user's avatar data is stored as a data URI in the `AvatarURL` field of the User struct, and `serveUserAvatar` parses and serves it directly as the image blob.
