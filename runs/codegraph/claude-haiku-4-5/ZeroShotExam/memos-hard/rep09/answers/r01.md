**Premise correction:** The cache layer is NOT configured to use Redis. Instead, it uses an in-memory cache implementation.

**Actual mechanism:**

The user cache is configured in `store/store.go:38-61` in the `New()` function. The cache is implemented as an in-memory cache (`*cache.Cache`) defined in `store/cache/cache.go`, not Redis.

**Configuration details:**

- **Cache type:** In-memory cache with thread-safe operations (using `sync.Map`)
- **TTL for user entries:** **10 minutes** (`DefaultTTL: 10 * time.Minute`)
- **Cleanup interval:** 5 minutes
- **Max items:** 1000

The user cache is initialized at `store/store.go:52` with these settings applied uniformly across all three caches (instanceSettingCache, userCache, and userSettingCache). When users are created, updated, or retrieved, they are stored in the cache using the `userCache.Set()` method which applies the default 10-minute TTL (as seen in `store/user.go:98`, `store/user.go:122`, `store/user.go:132`, etc.).
