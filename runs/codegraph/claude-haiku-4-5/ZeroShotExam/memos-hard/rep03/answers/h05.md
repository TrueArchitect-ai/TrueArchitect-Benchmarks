**Mechanism: Explicit Go code**

When a user is deleted, their emoji reactions are removed by **explicit Go code** that executes two separate DELETE statements:

1. **Reactions created by the deleted user** are deleted via `deleteReactionsByCreatorTx()` which executes: `DELETE FROM reaction WHERE creator_id = <userID>`

2. **Reactions on the deleted user's memos** are deleted via `deleteReactionsByContentIDsTx()` which executes: `DELETE FROM reaction WHERE content_id IN (...)` for each memo the user created.

  - Line 96: `deleteReactionsByContentIDsTx(ctx, tx, contentIDs)` — deletes reactions on the user's memo content
  - Line 102: `deleteReactionsByCreatorTx(ctx, tx, userID)` — deletes reactions the user created

- Implementation of `deleteReactionsByContentIDsTx()` in `store/db/mysql/user_delete.go:417-425` (same in postgres and sqlite versions)

- Implementation of `deleteReactionsByCreatorTx()` in `store/db/mysql/user_delete.go:437-440` (same in postgres and sqlite versions)

The reactions are not removed by database-level cascade rules — they are explicitly deleted in the application code within a database transaction before the user row itself is deleted.
