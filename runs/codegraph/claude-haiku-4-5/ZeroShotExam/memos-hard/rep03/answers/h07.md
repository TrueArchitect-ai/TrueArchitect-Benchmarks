**Profile Image Request Flow to Data Layer:**

1. HTTP Handler — `serveUserAvatar` — server/router/fileserver/fileserver.go:168
2. Get User by Username — `getUserByUsername` — server/router/fileserver/fileserver.go:715
3. Store Interface — `GetUser` — store/user.go:148
4. Database Query — `ListUsers` — store/db/mysql/user.go:84

The flow is: browser request → `serveUserAvatar` handler (checks auth if needed, extracts username from URL param) → `getUserByUsername` helper (calls store's `GetUser`) → `GetUser` method (checks cache, then calls driver's `ListUsers`) → `ListUsers` in MySQL driver (builds SQL query: `SELECT ... FROM user WHERE username = ?`, scans result into User struct, which includes `AvatarURL` field). The avatar data itself (a data URI) is already stored in the `avatar_url` column and returned by the database query.
