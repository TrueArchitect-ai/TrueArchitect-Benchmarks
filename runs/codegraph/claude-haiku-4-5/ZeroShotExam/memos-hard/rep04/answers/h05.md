**Mechanism:** Emoji reactions are removed by **explicit Go code**.

**Evidence locations:**

When a user is deleted, the `DeleteUser` function in `store/db/mysql/user_delete.go:29`, `store/db/postgres/user_delete.go:29`, and `store/db/sqlite/user_delete.go:29` orchestrates the deletion. The `deleteUserTargetsTx` function (lines 92-126 in mysql, postgres, sqlite) calls two functions in sequence:

1. **Line 96** in all three drivers: `deleteReactionsByContentIDsTx(ctx, tx, contentIDs)` — deletes all emoji reactions on memos created by the deleted user
2. **Line 102** in all three drivers: `deleteReactionsByCreatorTx(ctx, tx, userID)` — deletes all emoji reactions *created* by the deleted user

The implementations are:
- `deleteReactionsByContentIDsTx` (mysql:417-425, postgres:380-388, sqlite:380-388) — executes `DELETE FROM reaction WHERE content_id IN (...)` 
- `deleteReactionsByCreatorTx` (mysql:437-440, postgres:400-403, sqlite:400-403) — executes `DELETE FROM reaction WHERE creator_id = ?`

Both functions run as explicit SQL DELETE statements within the user deletion transaction, not as database-level cascade rules.
