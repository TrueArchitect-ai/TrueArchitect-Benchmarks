**Premise correction:** The codebase does not use Redis for caching. 

**Actual mechanism:** The cache layer is implemented as an in-memory cache (not Redis) configured in `store/store.go` and `store/cache/cache.go`:

1. **Cache Configuration** (`store/store.go:40-45`):
   - `DefaultTTL: 10 * time.Minute` — this is the default TTL that applies to user entries
   - `CleanupInterval: 5 * time.Minute`
   - `MaxItems: 1000`

2. **User Cache Usage** (`store/store.go:52`):
   - User entries are cached in `userCache` which is created with `cache.New(cacheConfig)`

3. **User Cache Key** (`store/user.go:88-90`):
   - User cache keys are generated by `userCacheKey(userID)` which converts the user ID to a string

The cache is thread-safe in-memory storage (`store/cache/cache.go:67-85`) using Go's `sync.Map`, not a Redis connection. All three caches (instanceSettingCache, userCache, userSettingCache) use the same 10-minute default TTL configuration.
