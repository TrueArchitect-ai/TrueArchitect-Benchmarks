h14.

**Computation site:** Memo metadata is computed on-demand at two layers:

1. **Server-side (Go)** — `server/router/api/v1/memo_service_link_metadata.go:41-56` (`getLinkMetadata` function) extracts link metadata from external URLs when memos contain links. The function calls `fetchHTMLMeta(url)` to extract title, description, and image from the HTML.

2. **Client-side (Web)** — Memo preview metadata is computed in React components dynamically from the memo object:
   - `web/src/components/MemoPreview/MemoPreview.tsx:104-164` derives preview text, attachment counts, and visual summaries from `content` and `attachments` props
   - `web/src/components/MemoActionMenu/memoShareImagePreviewModel.ts:30-57` (`buildMemoShareImagePreviewModel`) computes display metadata for social sharing images (display name, creation time, visual attachment summary)

**Triggers for recomputation:**

1. **Link metadata:** Computed on-demand when `GetLinkMetadata` or `BatchGetLinkMetadata` API methods are called (explicitly requested by client, not automatic on memo changes)
2. **Preview metadata:** Recomputed whenever the memo's `content` or `attachments` properties change (React dependency arrays), or when a memo is rendered in a list view

**Extracted properties:**

- **Link metadata:** url, title (page title), description (meta description), image (open graph image URL)
- **Preview summary:** truncated plain text, attachment count and thumbnail icons, creator name (optional), memo ID (optional)
- **Share preview:** formatted creation timestamp, creator avatar URL, visual attachment items (images/videos), non-visual attachment count badge

Notably, there is no server-side computation of memo snippets or preview text—that's derived on-the-fly from raw content by the client, allowing previews to reflect the latest content without database denormalization.
