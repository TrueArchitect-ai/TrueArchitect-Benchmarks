**Premise correction:** The question assumes webhook delivery workers consume from either NATS or RabbitMQ as external message brokers. This is **incorrect**.

**Actual mechanism:** The webhook delivery system uses an **in-process buffered Go channel** as its queue, not an external message broker.

**Location:** `internal/webhook/webhook.go:39-54`

The implementation:
- Declares a buffered channel queue: `var asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (line 39)
- Initializes 4 goroutine workers in `init()` (lines 42-54) that consume from this channel and dispatch webhooks synchronously via `Post()`
- When webhooks are triggered, `PostAsync()` (line 184) enqueues payloads to this channel with a non-blocking send that drops messages if the queue is full (lines 189-195)

This is an in-memory, single-process queue mechanism without any external message broker dependency.
