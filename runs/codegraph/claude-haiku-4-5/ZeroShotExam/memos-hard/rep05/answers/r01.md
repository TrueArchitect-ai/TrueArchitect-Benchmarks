**Premise correction:** The cache layer is NOT backed by Redis. The code uses an in-memory cache, not Redis.

**Actual mechanism:**

The cache for user entries is configured in **`store/store.go:38-61`** where the `New` function initializes the Store:

- **Default TTL for user entries:** `10 * time.Minute` (line 41)
- **Cache implementation:** In-memory cache (`store/cache/cache.go`) with cleanup interval of `5 * time.Minute` (line 42)
- **Max items:** `1000` (line 43)

User cache operations use the generic cache interface defined in **`store/cache/cache.go:10-32`**. When users are accessed, they're stored using **`s.userCache.Set(ctx, userCacheKey(user.ID), user)`** in **`store/user.go`** (lines 98, 122, 132, 143, 167), which applies the default TTL of 10 minutes.

The cache expiration check happens in **`store/cache/cache.go:135-144`** where expired items are automatically removed when accessed or during periodic cleanup runs every 5 minutes.
