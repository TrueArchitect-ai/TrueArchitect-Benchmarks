**Premise correction:** The question assumes webhook delivery workers consume from either NATS or RabbitMQ, but this is incorrect.

**Actual mechanism:** Webhook delivery does NOT use a message broker at all. Instead, webhooks are delivered using an **in-memory buffered channel** declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The queue is consumed by 4 goroutines spawned in the `init()` function (`internal/webhook/webhook.go:42-54`), which continuously read from this channel and dispatch webhooks synchronously via HTTP. When `PostAsync()` is called (`internal/webhook/webhook.go:184`), it enqueues payloads to this in-memory channel. If the queue fills up (128 capacity), new webhook dispatches are dropped with a warning logged.

This is a simple, single-process async queue design with no external message broker dependency.
