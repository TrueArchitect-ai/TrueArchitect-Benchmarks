**Premise correction:** There are no separate webhook delivery workers. The premise that webhook delivery workers consume from a message broker (NATS or RabbitMQ) is incorrect.

**Actual mechanism:** Webhooks are dispatched asynchronously using an in-memory channel-based queue, not a separate message broker. 

In `internal/webhook/webhook.go` (lines 39-55):
- Line 39: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — declares the queue as a buffered Go channel with capacity 128
- Lines 42-55: The `init()` function spawns 4 goroutines that each consume from this channel and dispatch the webhook via `Post()` 
- Line 184-195: `PostAsync()` enqueues payloads to the channel with a non-blocking send (drops if full)

The queue is declared as a package-level variable in `internal/webhook/webhook.go`, and webhook delivery is handled by goroutines running within the same process, not by separate workers consuming from NATS or RabbitMQ.
