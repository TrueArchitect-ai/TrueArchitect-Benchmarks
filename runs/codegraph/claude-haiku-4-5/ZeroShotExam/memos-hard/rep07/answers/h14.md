Based on my exploration of the codebase, memo content-derived metadata used for lists and previews is computed in the following manner:

**Computation site:** `internal/markdown/markdown.go` — the `Service` interface and its `service` implementation provide the core computation methods.

**Triggers:** The computation is triggered by three key operations:
1. `ExtractTags()` — called to extract all `#tags` from memo content
2. `ExtractProperties()` — called to compute derived boolean properties from content  
3. `GenerateSnippet()` — called to create a plain text summary of the content (used in lists/previews)

**Extracted properties:**
- **Tags**: All hashtags found in the markdown content (deduplicated while preserving case), extracted from tag nodes during AST walk (`internal/markdown/markdown.go:142-170`)
- **Properties**: Boolean metadata properties computed from content parsing (`ExtractProperties()` interface method, line 39)
- **Snippet**: Plain text summary of content up to a specified max length, generated via `GenerateSnippet()` (`internal/markdown/markdown.go:47-48`)

The frontend `MemoPreview` component (`web/src/components/MemoPreview/MemoPreview.tsx:104-164`) uses this derived data for display in lists, rendering the content via `MemoContent` component and truncating/summarizing as needed for preview contexts. The extraction is performed server-side via the markdown service using goldmark AST parsing with custom tag and mention extensions.
