**Mechanism: Explicit Go code**

Emoji reactions are removed by explicit Go code through two DELETE queries in the user deletion transaction, not by database-level rules or left orphaned.

**Evidence locations:**

1. **Reactions on user's deleted memos** — `store/db/mysql/user_delete.go:417-425`, `store/db/sqlite/user_delete.go:380-388`, `store/db/postgres/user_delete.go:380-388`:
   - `deleteReactionsByContentIDsTx()` deletes all reactions where `content_id IN (...)` with the user's memo content IDs
   - Called at line 96 in the deletion flow (`deleteUserTargetsTx`)

2. **Reactions created by the deleted user** — `store/db/mysql/user_delete.go:437-440`, `store/db/sqlite/user_delete.go:400-403`, `store/db/postgres/user_delete.go:400-403`:
   - `deleteReactionsByCreatorTx()` deletes all reactions where `creator_id = userID`
   - Called at line 102 in the deletion flow (`deleteUserTargetsTx`)

Both functions execute explicit SQL `DELETE` statements as part of the transactional user deletion process. There are no foreign key constraints or database-level CASCADE rules handling this cleanup.
