Frontend API requests get authenticated through the following:

**Interceptor path:** `web/src/connect.ts:156` (the `authInterceptor` function)

**Token kinds managed:** 
- Access Token V2 (short-lived JWT sent in Authorization header as Bearer token)
- Personal Access Token (PAT) (long-lived tokens for programmatic access, also sent in Authorization header)
- Refresh Token (stored in Cookie header for implicit refresh flow fallback)

**Backend package path:** `server/auth` (specifically `server/auth/authenticator.go`)

The flow works as follows:
1. Frontend's `authInterceptor` (`web/src/connect.ts:156`) intercepts all API requests
2. It retrieves the access token via `getRequestToken()` and sets it in the `Authorization` header as `Bearer ${token}` (`web/src/connect.ts:99`)
3. The backend's `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:208-230`) receives the request and extracts the Authorization header
4. It delegates to `Authorizer.Authenticate()` (`server/router/api/v1/authz.go:44`), which calls `Authenticator.Authenticate()` (`server/auth/authenticator.go:213`)
5. The authenticator validates the Bearer token via `resolveBearer()` (`server/auth/authenticator.go:149`), which routes to either `AuthenticateByAccessTokenV2()` or `AuthenticateByPAT()`
6. Access tokens are validated stateless via JWT signature verification (`AuthenticateByAccessTokenV2` → `ParseAccessTokenV2`), while PATs are checked against the database for revocation
