**Interceptor path:** `server/router/api/v1/connect_interceptors.go:208` (AuthInterceptor struct and NewAuthInterceptor function)

**Token kinds managed:** Access tokens (JWT access tokens, short-lived 15 minutes) and Personal Access Tokens (PAT, long-lived for programmatic access). The interceptor also manages refresh tokens via cookie fallback.

**Backend package that validates them:** `server/auth` package (`server/auth/authenticator.go:26` for the Authenticator struct and `server/auth/token.go` for token parsing and validation)

The authentication flow works as follows:
1. The AuthInterceptor at line 217-230 in `connect_interceptors.go` extracts the Authorization header and calls `authorizer.Authenticate()`
2. The Authorizer delegates to the Authenticator in `server/auth/authenticator.go:213` which resolves Bearer tokens (Access Token V2 or PAT)
3. Token validation happens in `server/auth/token.go` via ParseAccessTokenV2 (line 220) and ParseRefreshToken (line 236), using JWT signature verification with the shared secret
4. The Authorizer then applies the authentication result to the context and enforces method-level access control via CheckAccess
