**Interceptor path:** `server/router/api/v1/connect_interceptors.go` — The `AuthInterceptor` struct and its `NewAuthInterceptor` function (line 205-215) define the auth interceptor for frontend API requests.

**Token kinds:** The interceptor manages two types of tokens:
1. **JWT Access Tokens (Access Token V2)** — Short-lived tokens (15 minutes) using HS256 signature with audience `"user.access-token"`
2. **Personal Access Tokens (PAT)** — Long-lived tokens for programmatic access, prefixed with `"memos_pat_"`

Both are extracted from the `Authorization` header as Bearer tokens. The token types are defined in `server/auth/token.go` (lines 35-46 and 64-77).

**Backend package that validates them:** `server/auth` package — specifically:
- `Authenticator` struct in `server/auth/authenticator.go` performs the validation
- `ParseAccessTokenV2()` and `ParseRefreshToken()` in `server/auth/token.go` validate JWT signatures and claims
- The `Authorizer` struct in `server/router/api/v1/authz.go` delegates to the `Authenticator` for the actual credential validation
- The interceptor flow: `AuthInterceptor.WrapUnary()` → `Authorizer.Authenticate()` → `Authenticator.Authenticate()` → token parsing and validation
