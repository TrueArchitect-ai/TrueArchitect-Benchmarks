When a memo is deleted through the API, the store layer deletes the following records **before** the memo row itself (in order):

1. **Memo relations** (where the memo is the source) — via `DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})`
2. **Memo relations** (where the memo is the target) — via `DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})`
3. **Attachments** linked to the memo — via iterating through `ListAttachments` and calling `DeleteAttachment` for each

These cascading deletions are implemented in `store/memo.go:140-158` in the `Store.DeleteMemo` method, which performs cleanup before calling `s.driver.DeleteMemo(ctx, delete)` to delete the memo row itself.
