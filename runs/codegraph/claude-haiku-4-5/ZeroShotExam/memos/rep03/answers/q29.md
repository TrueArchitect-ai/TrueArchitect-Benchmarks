**Interceptor path**: `web/src/connect.ts:156` (the `authInterceptor` function)

**Token kinds**: 
- Access tokens (JWT, short-lived ~15 minutes)
- Personal Access Tokens (PATs, long-lived for programmatic access)
- Refresh tokens (via HttpOnly cookies)

**Backend validation package**: `server/auth/authenticator.go` (the `Authenticator` type)

The frontend auth interceptor (web/src/connect.ts:156-178) intercepts all Connect/gRPC requests and:
1. Extracts Bearer tokens from the Authorization header via `getRequestToken()`
2. Sets the Authorization header with `Bearer ${token}` format
3. Handles 401 responses by refreshing the access token via the refresh token cookie and retrying

On the backend, `server/auth/authenticator.go` provides the `Authenticator` struct which validates tokens:
- `AuthenticateByAccessTokenV2()` validates JWT access tokens (stateless)
- `AuthenticateByPAT()` validates Personal Access Tokens against the database
- `AuthenticateByRefreshToken()` validates refresh tokens against the database with revocation checks

The `Authorizer` type in `server/router/api/v1/authz.go` uses the `Authenticator` to enforce method-level access control across both Connect and gRPC-Gateway transports.
