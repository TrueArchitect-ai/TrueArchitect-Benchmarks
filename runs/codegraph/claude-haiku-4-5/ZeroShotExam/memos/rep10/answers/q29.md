**Token Kinds Managed:**
1. **Access Token V2** (short-lived JWT, 15 minutes) — stored in memory/localStorage, sent in `Authorization: Bearer <token>` header
2. **Refresh Token** (long-lived) — stored in HTTP-only cookie, used to obtain new access tokens
3. **Personal Access Token (PAT)** (programmatic access) — also sent as `Bearer <token>` in Authorization header

**Authentication Flow:**
- Frontend interceptor (`web/src/connect.ts:156-178`) extracts the access token via `getRequestToken()`, sets the `Authorization: Bearer <token>` header, and handles automatic refresh on 401 responses
- Backend `Authorizer.Authenticate()` (`server/router/api/v1/authz.go:44`) validates the Authorization header and returns an `AuthResult` containing either claims (for Access Token V2) or user + token (for PAT)
- Core validation happens in `Authenticator.AuthenticateByAccessTokenV2()` (stateless JWT validation) and `Authenticator.AuthenticateByPAT()` (database lookup for PAT revocation checks)
