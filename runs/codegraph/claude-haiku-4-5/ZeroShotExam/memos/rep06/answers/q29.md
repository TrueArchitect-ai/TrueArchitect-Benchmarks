**Interceptor path:** `server/router/api/v1/connect_interceptors.go:208` (AuthInterceptor struct)

**Token kinds:** 
1. **Access Token V2** — short-lived JWT tokens (15 minutes) for stateless API access
2. **Personal Access Tokens (PAT)** — long-lived tokens for programmatic access
3. **Refresh Token** — stored in HttpOnly cookie, exchanged for new access tokens

**Backend package that validates them:** `server/auth/authenticator.go` (Authenticator struct)

The authentication flow works as follows:

1. **Frontend** (`web/src/auth-state.ts`) stores the access token in `localStorage` (keys: `memos_access_token`, `memos_token_expires_at`) and manages token refresh via `BroadcastChannel` for multi-tab synchronization.

2. **Request authentication** (`server/router/api/v1/connect_interceptors.go:217-230`): The `AuthInterceptor.WrapUnary` method extracts the `Authorization` header from Connect RPC requests and calls `Authorizer.Authenticate()`.

3. **Token validation** (`server/auth/authenticator.go:213-224`): The `Authenticator.Authenticate()` method:
   - Extracts Bearer token from the Authorization header via `ExtractBearerToken()`
   - Validates Access Token V2 (stateless, via `AuthenticateByAccessTokenV2()`)
   - Or validates Personal Access Token (via `AuthenticateByPAT()`)
   - Returns an `AuthResult` containing either user claims or user identity

4. **Access control** (`server/router/api/v1/authz.go:58-69`): The `Authorizer.CheckAccess()` method enforces method-level policy based on the `AuthResult` and procedure name, returning `ErrUnauthenticated` for protected methods when unauthenticated.
