**Engine + path:** CEL (Common Expression Language) engine via `github.com/google/cel-go/cel` in `internal/filter/engine.go`.

**Mechanism in one sentence:** The Engine parses CEL filter strings into a dialect-agnostic Condition tree (lines 48–70 in `internal/filter/engine.go`), then a renderer walks that tree and generates dialect-specific SQL via `renderer.renderCondition()` which uses `qualifyColumn()` to handle per-dialect column syntax and `addArg()` to generate appropriate placeholders (e.g., `$N` for Postgres, `?` for MySQL/SQLite, see lines 32–99 and 842–849 in `internal/filter/render.go`).

**Where it flows:** ListMemos (e.g., `store/db/mysql/memo.go:62`) calls `filter.AppendConditions()` which invokes `engine.CompileToStatement()` (line 69), passing the filter string and `DialectName` (e.g., `DialectMySQL`); `CompileToStatement` compiles the filter and renders it with `Program.Render()` (lines 74–79), which constructs a `renderer` with the target dialect (line 97) and emits a `Statement` with dialect-specific SQL and args (lines 32–58).
