When DeleteMemo runs, the following database tables are affected (directly or by explicit cascade code):

1. **memo** — The main memo record is deleted directly (store/db/mysql/memo.go:261, store/db/postgres/memo.go:246)

2. **memo_relation** — All relations where the deleted memo is either the source or target are explicitly deleted via two separate calls to DeleteMemoRelation (store/memo.go:142-146):
   - Deletes rows where memo_id equals the deleted memo's ID
   - Deletes rows where related_memo_id equals the deleted memo's ID

3. **attachment** — All attachments linked to the memo are explicitly deleted via DeleteAttachment (store/memo.go:149-156). This cascades to delete the attachment records themselves.

4. **reaction** — Reactions on the memo being deleted (listed via ListReactions at server/router/api/v1/memo_service.go:545-549)

5. **memo** (comments) — Memo comments (which are memos with a comment relation) are explicitly deleted recursively (server/router/api/v1/memo_service.go:569-577), which then triggers DeleteMemo again for each comment, causing cascading deletion of their relations and attachments.

**Summary of affected tables:**
- memo
- memo_relation
- attachment
- reaction
