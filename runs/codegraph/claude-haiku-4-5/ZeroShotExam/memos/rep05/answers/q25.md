The syntax/engine is **CEL (Common Expression Language)** which lives in `internal/filter/engine.go`. The filter parsing and SQL rendering mechanism works as follows: CEL expressions are compiled by the `Engine` (which wraps `cel.Env`) into an intermediate condition tree via `Compile()`, then that tree is rendered into dialect-specific SQL (MySQL, SQLite, or PostgreSQL) by calling `Program.Render()` with the target dialect name, producing parameterized SQL fragments that are appended to the WHERE clause.

**Key files:**
- `internal/filter/engine.go:14` - Engine struct and Compile method
- `internal/filter/helpers.go:9` - AppendConditions function that orchestrates the flow
- `internal/filter/schema.go:14-16` - DialectName constants (DialectSQLite, DialectMySQL, DialectPostgres)
- `internal/filter/parser.go` - buildCondition that converts CEL AST to Condition tree
- `internal/filter/render.go` (referenced via newRenderer) - renders Condition tree to dialect-specific SQL
