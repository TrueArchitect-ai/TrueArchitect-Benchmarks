q26.

When `DeleteMemo` runs, the following database tables are directly affected:

1. **memo** — The memo record itself is deleted (store/db/mysql/memo.go:261, store/db/postgres/memo.go:246)

2. **memo_relation** — All relations where the memo is either the source (MemoID) or target (RelatedMemoID) are deleted (store/memo.go:142-147)

3. **attachment** — All attachments linked to the memo are deleted (store/memo.go:148-157)

These deletions occur through explicit cascade code in `Store.DeleteMemo()` at store/memo.go:140-158:
- First, memo_relation records are cleaned up for both directions
- Then, attachments are fetched and deleted via `DeleteAttachment` 
- Finally, the memo itself is deleted

Additionally, when memos have comments (which are themselves memos with a COMMENT relation), those comment memos are recursively deleted first via the same process (server/router/api/v1/memo_service.go:569-577), which applies the same cascade logic.

**Answer: memo, memo_relation, attachment**
