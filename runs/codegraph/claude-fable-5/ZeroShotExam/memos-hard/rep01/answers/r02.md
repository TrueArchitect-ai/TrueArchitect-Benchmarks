**Premise correction: this repository has no per-user API rate-limiting middleware.** There is nothing to register and no request limits to report.

What the server actually registers:

- Echo HTTP middleware in `server/server.go:51-52` — only `middleware.Recover()` and a CORS middleware. Echo's built-in `RateLimiter` middleware is not used.
- Connect RPC interceptors in `server/router/api/v1/v1.go:133-138` — `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, and `NewAuthInterceptor()` (implemented in `server/router/api/v1/connect_interceptors.go`). None of these do rate limiting.
- A gRPC-Gateway auth middleware at `server/router/api/v1/v1.go:69` — authentication only.

Searches across the Go server code and `go.mod` for `rate limit`, `throttle`, `Limiter`, `RateLimit`, and `golang.org/x/time/rate` turn up no rate-limiting implementation or dependency. The closest thing to a request constraint is a request *size* cap — `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141` — which limits request body size, not request frequency.
