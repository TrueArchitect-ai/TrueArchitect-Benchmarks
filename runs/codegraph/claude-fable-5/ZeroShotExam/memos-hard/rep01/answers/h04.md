**No** — the MySQL driver is constructed only inside the driver-selection factory.

Evidence:

- The MySQL driver's only constructor is `mysql.NewDB` in `store/db/mysql/mysql.go:20`, which builds the `mysql.DB` struct (`store/db/mysql/mysql.go:14`).
- The only call to `mysql.NewDB` in the entire codebase is in the factory `NewDBDriver`, at `store/db/db.go:22` (the `case "mysql":` branch of the driver switch). CodeGraph's index confirms `mysql.NewDB` has exactly 1 caller, in `store/db/db.go`.
- A repo-wide grep shows the package `github.com/usememos/memos/store/db/mysql` is imported in exactly one file: `store/db/db.go:8`. No other Go file imports it, so no other code can call `mysql.NewDB` or construct `mysql.DB` directly.
- A grep for direct struct construction (`mysql.DB{`) outside the package returns nothing; the struct's fields (`db`, `profile`, `config`) are unexported anyway, so a usable instance can't be built outside the package.

By contrast, the SQLite driver *is* constructed directly outside the factory (in tests like `store/demo_seed_test.go`), which underscores that MySQL is not.
