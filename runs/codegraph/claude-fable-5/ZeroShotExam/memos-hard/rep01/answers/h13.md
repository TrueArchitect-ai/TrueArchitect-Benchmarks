**impl** — The interface is `markdown.Service` (`internal/markdown/markdown.go:31`). The only concrete implementation that executes at runtime is the unexported `service` struct (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown` instance. Its helper pieces — the custom `tagParser` and `mentionParser` inline parsers (`internal/markdown/parser/tag.go`, `internal/markdown/parser/mention.go`) and the `MarkdownRenderer` (`internal/markdown/renderer/markdown_renderer.go`) — are internals behind that one implementation, not alternative implementations of the interface.

**construction** — `markdown.NewService(...)` (`internal/markdown/markdown.go:85`) is the factory; the production call site is `NewAPIV1Service` in `server/router/api/v1/v1.go:48`, which builds it with `markdown.WithTagExtension()` and `markdown.WithMentionExtension()`. That single instance is then shared: `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService`. (Tests construct their own instances via the same factory, e.g. `server/router/api/v1/test/test_helper.go:44`.)

**holders** — Components holding the `markdown.Service` interface:
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`)
- `RSSService.MarkdownService` (`server/router/rss/rss.go:45`), receiving the API service's instance
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) declares the field, but `NewRunner` has no production caller — at runtime the memopayload package is only used via the free function `RebuildMemoPayload(ctx, memo, s.MarkdownService)` from `server/router/api/v1/memo_service.go:108,447`, with the interface passed as an argument.

One caveat: the frontend renders markdown separately with `react-markdown` (`web/src/components/MemoContent/MemoMarkdownRenderer.tsx`), but that path is not behind this interface — the Go `markdown.Service` handles server-side concerns (tag/mention/property extraction, snippets, RSS HTML rendering).
