The outbound-notification path is the webhook system: when a memo changes, the API layer builds a `WebhookRequestPayload` (see `server/router/api/v1/memo_service_webhooks.go`) and hands it to the webhook package.

- **Delivery function** — `Post` in `internal/webhook/webhook.go` (line 120). This is where the HTTP POST actually executes, via the shared `safeClient` (`safeClient.Do(req)` at `internal/webhook/webhook.go:152`). Asynchronous dispatch goes through `PostAsync` (line 184), which enqueues onto `asyncPostQueue`; worker goroutines started in the package `init` (line 42) drain the queue and call the same `Post`.

- **Protection mechanism** — two layers of SSRF defense:
  1. **Dial-time enforcement** (the one that actually protects delivery): `safeDialContext` in `internal/webhook/webhook.go` (line 59) is installed as the `http.Transport.DialContext` of `safeClient`. It re-resolves the target host at connection time and rejects any IP matching `isReservedIP` — defined in `internal/webhook/validate.go` (line 44) against the `reservedCIDRs` list (loopback, RFC-1918 ranges, link-local/cloud-IMDS 169.254.0.0/16, and IPv6 equivalents). Because this runs at dial time, it also defeats DNS-rebinding tricks.
  2. **Registration-time validation**: `ValidateURL` in `internal/webhook/validate.go` (line 62) is called from `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`, rejecting non-http(s) schemes and hostnames that resolve to reserved/private IPs before a webhook can be saved.

An escape hatch exists for self-hosted setups: the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) disables the reserved-IP check when set.
