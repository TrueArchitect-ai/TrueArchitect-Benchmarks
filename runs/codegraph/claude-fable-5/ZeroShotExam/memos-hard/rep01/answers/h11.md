**1st: `User` (~7 packages); 2nd: `Memo` (~6 packages)**

The data layer is the `store` package, whose persistent entity structs are defined one per file at the top of `store/` (e.g. `store/user.go:29` `type User struct`, `store/memo.go:35` `type Memo struct`, plus `Attachment` in `store/attachment.go:16`, `MemoRelation`, `IdentityProvider`, `Inbox`, `InstanceSetting`, `UserSetting`, `Reaction`, `UserIdentity`, `MemoShare`).

Counting distinct Go packages outside the entire `store/` tree (i.e. excluding the `store/db/*` driver and `store/test` packages, which are part of the data layer) that reference each `store.<Type>`:

- **`store.User` — 7 packages:** `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- **`store.Memo` — 6 packages:** `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`
- Next tier: `Attachment` (4), then `MemoRelation`/`Inbox`/`MemoShare` (3 each); `IdentityProvider`, `InstanceSetting`, and `UserSetting` aren't referenced outside the store tree at all.

If you exclude the `_test` package (`server/router/api/v1/test`), the counts drop to 6 and 5 respectively, but the ranking is unchanged: `User` first, `Memo` second.
