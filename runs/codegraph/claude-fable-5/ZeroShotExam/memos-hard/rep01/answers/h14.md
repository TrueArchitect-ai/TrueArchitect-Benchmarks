**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual extraction to the markdown service's single-pass AST walk in `(*service).ExtractAll` at `internal/markdown/markdown.go:356` (interface defined at `internal/markdown/markdown.go:31`). The result is stored on the memo as `memo.Payload.Tags` and `memo.Payload.Property` (`storepb.MemoPayload_Property`), persisted as the JSON `payload` column by the store drivers (e.g. `store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`) and surfaced in the API as the "Output only" `tags`/`property` fields of `Memo` (`proto/gen/api/v1/memo_service.pb.go:241,252`).

**Triggers (recomputation happens whenever content is written):**
- **Memo creation** — `APIV1Service.CreateMemo` calls `memopayload.RebuildMemoPayload` before inserting (`server/router/api/v1/memo_service.go:108`).
- **Memo update with `content` in the update mask** — `APIV1Service.UpdateMemo` rebuilds the payload when the `"content"` path is present (`server/router/api/v1/memo_service.go:447`).
- **Server-wide background rebuild** — `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) re-lists all memos in batches of 100, rebuilds each payload, and writes it back; the runner is wired up in `startBackgroundRunners`.

**Extracted properties** (from the goldmark AST walk in `ExtractAll`, `internal/markdown/markdown.go:371-411`):
- `Tags` — all `#tag` nodes, deduplicated case-preservingly (also `Mentions`, used separately for mention notifications, not stored in the payload)
- `Property.Title` — text of the document's first block if it is an H1 heading
- `Property.HasLink` — any link node
- `Property.HasCode` — any code block, fenced code block, or code span
- `Property.HasTaskList` — any task checkbox
- `Property.HasIncompleteTasks` — any unchecked task checkbox
