**Premise correction: there is no per-user API rate-limiting middleware in this repository**, so it isn't registered anywhere and has no request limits.

What actually exists:

- **HTTP (Echo) middleware** is registered in `server/server.go:51-52`, and consists only of `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`). No rate limiter.
- **Connect/gRPC API interceptors** are defined in `server/router/api/v1/connect_interceptors.go`: `MetadataInterceptor` (header conversion), `LoggingInterceptor`, and `RecoveryInterceptor` (panic recovery). None of them do rate limiting.

The closest things to throttling in the codebase, neither of which is per-user request rate limiting:

- A concurrency semaphore (`thumbnailSemaphore`, created in `server/router/fileserver/fileserver.go:111-118`) that caps simultaneous thumbnail generation — a resource guard, not a per-user request limit.
- A documentation comment in `internal/email/doc.go:86` suggesting "Rate limit email sending to prevent abuse" as a best practice — advisory text only, with no implementation behind it.

A repo-wide search for `rate limit`, `ratelimit`, `throttle`, and `limiter` turns up nothing else (the remaining hits are all "delimiter" in the web editor code).
