Memo visibility is enforced independently at each server surface that can expose a memo (or memo-derived data). The distinct enforcement sites are:

- Memo gRPC/Connect API, single-memo reads — `checkMemoReadAccess` (public/protected/private + archived check, used by `GetMemo` and related handlers) — `server/router/api/v1/memo_service.go:39`
- Memo gRPC/Connect API, list queries — `ListMemos` narrows `VisibilityList`/filters based on the caller (anonymous → PUBLIC only; other users' memos → PUBLIC+PROTECTED) — `server/router/api/v1/memo_service.go:218`
- Comments API — parent memo's visibility checked before creating/reading comments — `server/router/api/v1/memo_service_comments.go:41`
- Reactions API — memo visibility checked before listing/upserting reactions on it — `server/router/api/v1/reaction_service.go:30` (and `:83`)
- Memo-attachment API — visibility check before listing a memo's attachments — `server/router/api/v1/memo_attachment_service.go:214`
- Attachment API — `checkAttachmentAccess` re-checks the linked memo's visibility before serving attachment data via gRPC — `server/router/api/v1/attachment_service.go:445`
- Raw HTTP file server — attachment blob downloads gated on the linked memo's visibility (with a share-token fallback for private/protected memos) — `server/router/fileserver/fileserver.go:677`
- SSE realtime hub — `canReceive` filters memo events per connected client by memo visibility (private only to creator/admin) — `server/router/api/v1/sse_hub.go:134`
- RSS feeds — feed queries hard-restricted to `store.Public` memos — `server/router/rss/rss.go:90` (and `:141`)
- Frontend sitemap — `getSitemapXML` includes only PUBLIC memos — `server/router/frontend/frontend.go:150`
- User stats API — stats queries restricted by viewer-appropriate visibility list — `server/router/api/v1/user_service_stats.go:84` (and `:218`)
- Notification/mention gating — `canViewerAccessMemo` prevents notifying users about memos they can't view — `server/router/api/v1/user_service_notifications.go:302`, with a parallel check in `server/router/api/v1/memo_mention_helpers.go:62`

The store layer (`store/memo.go`, `store/db/*/memo.go`) only applies whatever `VisibilityList`/filters the callers pass — it does not decide access itself, so the enforcement genuinely lives at the router-layer sites above.
