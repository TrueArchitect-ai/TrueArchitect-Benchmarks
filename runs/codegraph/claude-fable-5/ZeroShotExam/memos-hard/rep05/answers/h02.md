The webhook feature in this repo delivers memo-change notifications over HTTP, and both pieces live in `internal/webhook/`.

- **Delivery function** — `Post` in `internal/webhook/webhook.go:120` performs the actual outbound HTTP POST (signing the payload and sending via the shared `safeClient`). Asynchronous dispatch goes through `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded channel drained by worker goroutines in the package `init` that call `Post`.

- **Protection mechanism** — SSRF protection is enforced at connection time by `safeDialContext` in `internal/webhook/webhook.go:59`, installed as the `DialContext` on `safeClient`'s transport. It re-resolves the target host at dial time and rejects any address matching `isReservedIP` / `reservedNetworks` in `internal/webhook/validate.go:44` (loopback, RFC-1918, link-local/IMDS, and IPv6 equivalents). Doing the check at dial time also defeats DNS rebinding. As a first line of defense, `ValidateURL` (`internal/webhook/validate.go:62`) applies the same reserved-IP check when webhooks are created or updated via `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`. The guard can be intentionally disabled for self-hosted local-network use via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`).
