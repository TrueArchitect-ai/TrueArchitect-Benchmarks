`internal/idp`; `internal/idp/oauth2`

The abstraction lives in the `idp` package at `internal/idp/idp.go`, which defines the provider-neutral `IdentityProviderUserInfo` struct (identifier, display name, email, avatar URL) that any provider implementation must produce. The one concrete protocol implementation that ships is the OAuth2 package at `internal/idp/oauth2/oauth2.go` — its `IdentityProvider` type wraps a `storepb.OAuth2Config` and implements `ExchangeToken` (with PKCE support) and `UserInfo`, returning the shared `idp.IdentityProviderUserInfo`. It's wired into sign-in via `server/router/api/v1/auth_service_sso.go`, and the web UI offers only OAuth2 templates (GitHub, GitLab, Google, Custom) in `web/src/components/CreateIdentityProviderDialog.tsx`, confirming OAuth2 is the sole protocol implemented.
