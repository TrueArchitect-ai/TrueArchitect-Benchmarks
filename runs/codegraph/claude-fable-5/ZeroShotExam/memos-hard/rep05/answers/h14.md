**Computation site:** `memopayload.RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`. It delegates the actual parsing to the markdown service's `ExtractAll` (`internal/markdown/markdown.go:356`), which does a single goldmark AST walk over the memo's content, then stores the results on `memo.Payload` (the `MemoPayload` store message with `Tags` and `Property` fields, `proto/gen/store/memo.pb.go:24`).

**Triggers:**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, called on every memo creation after the content-length check.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, called only when the update mask includes the `content` path (so metadata is recomputed exactly when content changes).
- A batch rebuild path also exists: `Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) rebuilds the payload for all memos in batches of 100, though grep shows no current caller wires this runner up in the server.

**Extracted properties** (from `ExtractAll`, `internal/markdown/markdown.go:356-422`):
- `Tags` — all `#tag` nodes, deduplicated case-preservingly.
- `Property.Title` — text of the first block-level H1 heading, if the document starts with one.
- `Property.HasLink` — any link node.
- `Property.HasCode` — code block, fenced code block, or inline code span.
- `Property.HasTaskList` — any task checkbox, and `Property.HasIncompleteTasks` if any checkbox is unchecked.

(`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` persists only `Tags` and `Property` into the payload.) These payload properties surface in the API as `Memo.Property` (`proto/gen/api/v1/memo_service.pb.go`) for list/preview UI use.
