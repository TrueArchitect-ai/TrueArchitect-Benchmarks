**Premise correction:** This repository (Memos, a Go + React note-taking app) has no Redis at all — a repo-wide grep for "redis" returns zero hits in the Go, TypeScript, and config files. There is no Redis connection to configure, no connection string, and no external cache service. All caching is in-process, in-memory.

**Actual mechanism:** There are two separate in-memory caches:

1. **Store-layer cache** (`store/cache/cache.go`) — a thread-safe `sync.Map`-based cache with TTL and a background cleanup goroutine. The store creates three instances of it in `store/store.go:38-58` (`New`): `instanceSettingCache`, `userCache`, and `userSettingCache`, all configured inline with hard-coded values:
   - **`DefaultTTL: 10 * time.Minute`** — this is the TTL that applies to user entries. `Store.CreateUser`/`UpdateUser`/`ListUsers`/`GetUser` populate `userCache` via `Set()` (`store/user.go:98,132,143,167`), and `Set` applies the default TTL (`store/cache/cache.go:93-95`). So **user entries live for 10 minutes**, with a cleanup sweep every 5 minutes and a 1000-item cap. The same 10-minute default is also in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`). There is no external config file, env var, or flag for this — it's compiled in.

2. **RSS feed cache** (`server/router/rss/rss.go`) — a separate plain `map[string]*cacheEntry` guarded by a mutex, with `defaultCacheDuration = 1 * time.Hour` (`rss.go:25`) and a 50-feed LRU cap. Its `"user:"+username` keys are cached RSS feeds, not user records, and expire after 1 hour.

So: no Redis anywhere; the TTL on cached user entries is the hard-coded 10 minutes in `store/store.go:41`.
