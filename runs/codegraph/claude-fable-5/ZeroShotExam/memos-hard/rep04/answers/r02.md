The premise is incorrect: this repository has no per-user API rate-limiting middleware, so there is nowhere it is registered and no request limits to report.

What is actually registered:

- **Echo HTTP middleware** (`server/server.go:51-52`): only `middleware.Recover()` and a CORS middleware (`server/cors.go`).
- **Connect/gRPC API interceptors** (`server/router/api/v1/v1.go:133-137`): a logging interceptor, a recovery interceptor, and an auth interceptor (`NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor`) — no rate limiter among them.

A repo-wide search for `rate limit` / `ratelimit` / `throttle` / `limiter` turns up nothing rate-limiting-related in the server code. The closest things to "limits" that do exist are size/concurrency caps, not per-user request-rate limits: a max API request body size passed as `connect.WithReadMaxBytes(maxAPIRequestBytes)` (`server/router/api/v1/v1.go:141`), a cap of 100 users per `BatchGetUsers` call (`maxBatchGetUsers` in `server/router/api/v1/user_service.go:23`), and a semaphore limiting concurrent thumbnail generation (`server/router/fileserver/fileserver.go:448`).
