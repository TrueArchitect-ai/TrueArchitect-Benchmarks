Memo visibility is enforced independently in four (arguably five) server surfaces:

- gRPC/HTTP API v1 memo service — `server/router/api/v1/memo_service.go`. `checkMemoReadAccess` (line 39) denies private memos to non-creators and archived memos to anyone but the creator, called from `GetMemo` (line 356) and from the comment listing path (`server/router/api/v1/memo_service_comments.go:148`); `ListMemos` (lines 218–227) injects visibility constraints (`Public` only for anonymous users, `creator_id == me || visibility in [PUBLIC, PROTECTED]` for signed-in users) into the store query. The same API surface repeats the private-memo check in related RPCs: `server/router/api/v1/reaction_service.go` (lines 38, 83), `server/router/api/v1/memo_attachment_service.go:222`, and `server/router/api/v1/attachment_service.go:451`.
- File server (raw attachment/blob serving over HTTP) — `server/router/fileserver/fileserver.go`. `checkAttachmentPermission` (line 650) re-derives access from the owning memo: public memos are served anonymously only when the instance allows it, a valid non-expired share token grants access, otherwise the request must be authenticated and private memos are limited to the creator or an admin (line 699).
- SSE real-time event hub — `server/router/api/v1/sse_hub.go`. `canReceive` (line 134) filters broadcast events per connected client: private-memo events are delivered only to the memo's creator or an admin; unknown visibility values are denied.
- RSS feeds — `server/router/rss/rss.go`. Both the explore feed and per-user feeds hard-code `VisibilityList: []store.Visibility{store.Public}` (lines 90 and 141), so only public memos ever appear in RSS output.

A fifth, related site: the frontend router's sitemap generator also restricts itself to public memos (`server/router/frontend/frontend.go:150`), keeping non-public memo URLs out of `/sitemap.xml`.

(The MCP router in `server/router/mcp/` adapts calls onto the API v1 service, so it inherits the first site's enforcement rather than adding its own.)
