**No** — the MySQL driver is only constructed inside the driver-selection factory.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:14`, which calls `mysql.NewDB(profile)` at `store/db/db.go:22` inside a `switch profile.Driver` on `"sqlite"`/`"mysql"`/`"postgres"`.
- A repo-wide grep for `mysql.NewDB` finds exactly one call site — that factory line. The constructor itself is defined at `store/db/mysql/mysql.go:20`.
- `store/db/db.go` is the only Go file in the repo that imports the `github.com/usememos/memos/store/db/mysql` package, so no other file can construct the driver (its `DB` struct or `NewDB`) directly.
- Every other place that needs a driver goes through the factory: `store/test/store.go:28` and `store/test/store.go:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(...)`.
- The other `mysql` references are unrelated: `store/test/containers.go` imports `github.com/testcontainers/testcontainers-go/modules/mysql` (a test-container helper) and `github.com/go-sql-driver/mysql` (the low-level SQL driver for connection checks), not the store's MySQL driver; files like `server/router/api/v1/attachment_service.go:405` and `internal/filter/schema.go:15` only branch on the string `"mysql"`.
