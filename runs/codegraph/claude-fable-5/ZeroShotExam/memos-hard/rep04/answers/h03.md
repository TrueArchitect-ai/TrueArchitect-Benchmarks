**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package:** `internal/idp` — the package `idp` defines the provider-agnostic contract, notably the `IdentityProviderUserInfo` struct (`internal/idp/idp.go:3`) that any provider implementation returns after fetching user details.
- **Implementation package:** `internal/idp/oauth2` — the only concrete protocol implementation that ships, implementing the OAuth2 flow. `internal/idp/oauth2/oauth2.go` defines the `IdentityProvider` struct with `NewIdentityProvider`, `ExchangeToken` (authorization-code + PKCE exchange), and `UserInfo` (which maps claims into `idp.IdentityProviderUserInfo`).

Supporting evidence: the server's SSO auth path (`server/router/api/v1/auth_service_sso.go`) constructs providers via `oauth2.NewIdentityProvider`, and the web UI's provider templates (GitHub, GitLab, Google, Custom in `web/src/components/CreateIdentityProviderDialog.tsx`) all use `IdentityProvider_Type.OAUTH2` — no other protocol (e.g. SAML or LDAP) is implemented.
