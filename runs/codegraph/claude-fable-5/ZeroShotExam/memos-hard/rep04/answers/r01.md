**Premise correction:** There is no Redis in this repository. Nothing in the Go module, config, or code references Redis at all — the cache layer is entirely in-process, in-memory Go code, so there is no Redis connection to configure.

**Actual mechanism:** Caching is provided by a custom thread-safe in-memory cache implemented in `store/cache/cache.go` (a `sync.Map`-backed `Cache` type with TTL expiration, a background cleanup loop, and a max-item cap). The `Store` wires up three instances of it — `instanceSettingCache`, `userCache`, and `userSettingCache` — in `store/store.go:38-60`, all sharing the same config:

- **DefaultTTL: 10 minutes** — this is the TTL that applies to user entries, since user objects are cached with `s.userCache.Set(...)` (which uses the default TTL, see `Set` at `store/cache/cache.go:93`) from `CreateUser`, `UpdateUser`, `ListUsers`, and `GetUser` in `store/user.go:92-169`, keyed by user ID (`userCacheKey`, `store/user.go:88`).
- CleanupInterval: 5 minutes, MaxItems: 1000 (`store/store.go:40-45`; the same defaults exist in `DefaultConfig()` at `store/cache/cache.go:57-64`).

Separately, there's an unrelated per-service RSS feed cache in `server/router/rss/rss.go:23-50` — a plain map with a 1-hour expiration (`defaultCacheDuration`) whose keys happen to include `"user:"+username`, but that caches rendered RSS XML, not user records. Neither cache is Redis-backed or externally configurable.
