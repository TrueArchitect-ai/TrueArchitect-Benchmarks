**Premise correction: this repository has no per-user API rate-limiting middleware.** A repo-wide search for "rate limit", "ratelimit", "throttle", and "limiter" turns up nothing in the server code (the only textual matches are the word "delimiter" in unrelated frontend editor files, `web/src/components/MemoEditor/Editor/formatting.ts` and `listIndent.ts`).

What the server actually registers is:

- **Echo middleware** in `server/server.go:51-52` — `middleware.Recover()` and a CORS middleware (`newCORSMiddleware`, defined in `server/cors.go`). No rate limiter.
- **Connect RPC interceptors** in `server/router/api/v1/v1.go:133-137` — `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` (defined in `server/router/api/v1/connect_interceptors.go`). Again, no rate limiter among them.

The closest thing to a request limit is a **request-size** cap, not a request-rate cap: `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`. So there are no per-user request limits (e.g. requests per minute) to report — the premise of the question doesn't hold for this codebase.
