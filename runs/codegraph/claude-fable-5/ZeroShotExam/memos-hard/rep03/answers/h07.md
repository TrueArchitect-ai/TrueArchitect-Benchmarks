A browser requests `GET /file/users/:identifier/avatar`. The avatar isn't a file on disk or in object storage — it's stored inline as a base64 `data:` URI in the `avatar_url` column of the `user` table, so the "data layer" hop is the user store/DB read, and the handler decodes the stored data URI into image bytes.

The concrete DB driver (`sqlite`/`mysql`/`postgres`) is selected at store construction; all three implement `ListUsers` identically for this path, selecting the `avatar_url` column from the `user` table.
