**Premise correction:** There is no Redis anywhere in this repository. A repo-wide search for "redis" returns zero hits (no client library in `go.mod`, no config, no code). The cache layer is entirely in-process, in-memory Go code.

**Actual mechanism:**

- The cache implementation is `store/cache/cache.go` — a thread-safe in-memory `Cache` built on `sync.Map`, with per-item TTL expiration, a periodic cleanup goroutine, and a max-item cap with oldest-first eviction.
- The caches are constructed in `store/store.go:38-61` (`store.New`). It creates three instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing one config defined right there: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`. (The same defaults also appear in `DefaultConfig()` at `store/cache/cache.go:57-64`.) There is no external connection to configure; the caches die with the process.
- **TTL for user entries: 10 minutes.** User objects are written to `userCache` via `Set` (e.g. `store/user.go:98,132,143,167`), and `Set` applies the config's `DefaultTTL` (`store/cache/cache.go:93-95`). User settings in `userSettingCache` (`store/user_setting.go`) get the same 10-minute TTL. Nothing in the codebase uses `SetWithTTL` to override it for user data.

One caveat on wording: if "user entries" meant the per-user RSS feed cache (`"user:"+username` keys in `server/router/rss/rss.go`), that is a separate hand-rolled `map[string]*cacheEntry` in the same file, expiring after `defaultCacheDuration = 1 * time.Hour` (`server/router/rss/rss.go:25,357`) — also purely in-memory, not Redis.
