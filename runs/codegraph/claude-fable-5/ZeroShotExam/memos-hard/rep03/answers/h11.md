**1st: `User` (~7 packages); 2nd: `Memo` (~6 packages)**

The data layer is the `store` package, where the persistent entities are defined: `Memo` (`store/memo.go`), `User` (`store/user.go`), `Attachment` (`store/attachment.go`), `Inbox`, `Reaction`, `MemoRelation`, `MemoShare`, `IdentityProvider`, `UserIdentity`, `UserSetting`, `InstanceSetting` (ignoring the Find/Update/Delete request structs, which are query helpers rather than entities).

Counting distinct Go packages outside `store/` that reference each type (`store.<Type>` with a word boundary, so `store.Memo` doesn't absorb `store.MemoRelation`):

- **`store.User` — 7 packages**: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- **`store.Memo` — 6 packages**: `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`
- Next: `store.Attachment` with 4, then `MemoShare`/`MemoRelation`/`Inbox` with 3 each.

If you exclude the test package (`server/router/api/v1/test`), the counts drop to 6 and 5 respectively, but the ranking is unchanged: `User` first, `Memo` second.
