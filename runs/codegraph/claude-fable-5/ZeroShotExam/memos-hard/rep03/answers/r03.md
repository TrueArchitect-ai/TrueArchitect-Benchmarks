The premise is incorrect — there is no nightly database-cleanup job scheduled in this repository. The cron scheduler package at `internal/scheduler/` is a standalone library, and no application code actually registers any job with it: nothing in `cmd/`, `server/`, or `store/` imports or calls the scheduler.

The "cleanup" jobs that do appear are only illustrative examples, not real scheduled work:

- `internal/scheduler/doc.go:14-16` — a `"daily-cleanup"` job with schedule `"0 2 * * *"` (2 AM daily) in the package documentation's usage example.
- `internal/scheduler/example_test.go:97-99` — a `"cleanup"` example job, also at 2 AM.
- `internal/scheduler/README.md` — similar sample jobs (`"daily-cleanup"`, `"stale-session-cleanup"`).

The only real periodic cleanup in the codebase is the in-memory cache expiry loop in `store/cache/cache.go:199-218`, which runs on a 5-minute `time.Ticker` (`store/store.go:42`) — it's not a cron-scheduled job and doesn't clean the database.

So if a documentation example counts as "the" answer, the sample time is 2 AM daily (`0 2 * * *`), but no such job is actually wired up or scheduled anywhere in the application.
