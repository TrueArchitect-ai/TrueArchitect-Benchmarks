**No.** Outside the driver-selection factory, the MySQL driver is never constructed directly.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go`, which switches on the driver name and calls `sqlite.NewDB`, `mysql.NewDB` (`store/db/db.go:22`), or `postgres.NewDB`.
- A repo-wide grep for calls to `mysql.NewDB` finds exactly one call site: `store/db/db.go:22`. (By contrast, the SQLite driver *is* constructed directly outside the factory, in `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416` — MySQL has no equivalent.)
- The only file in the codebase that imports the `github.com/usememos/memos/store/db/mysql` package at all is `store/db/db.go:8`, so no other code could even reference the package's constructor or its `DB` type.
- A grep for direct struct instantiation (`mysql.DB{`, `&mysql.DB`) returns no hits anywhere. The only place the `mysql.DB` struct literal is built is inside the driver's own constructor `NewDB` at `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`), which is internal to the package, and CodeGraph's index likewise reports `NewDB` (`store/db/mysql/mysql.go:20`) as having exactly one caller, in `store/db/db.go`.

So all MySQL driver construction flows through the `NewDBDriver` factory in `store/db/db.go`.
