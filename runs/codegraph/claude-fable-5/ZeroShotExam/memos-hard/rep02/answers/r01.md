**Premise correction:** There is no Redis in this repository. A search across the whole codebase (Go sources, `go.mod`, configs) finds zero Redis references — no client library, no connection config, no environment variable. The cache layer is entirely **in-process, in-memory**.

**Actual mechanism:**

- The cache implementation is a custom thread-safe in-memory cache at `store/cache/cache.go` — a `sync.Map` of items with per-entry `expiration` timestamps, a background cleanup goroutine (`cleanupLoop`), and LRU-style eviction when `MaxItems` is exceeded. Nothing is networked or persisted.

- **User entries:** the store constructor `New` in `store/store.go:38-53` creates three caches (`userCache`, `userSettingCache`, `instanceSettingCache`) all with a hard-coded config of **`DefaultTTL: 10 * time.Minute`** (plus `CleanupInterval: 5m`, `MaxItems: 1000`). User objects are written to `userCache` via `Set(...)` (which applies that default 10-minute TTL, `store/cache/cache.go:93-95`) in `CreateUser`, `UpdateUser`, `ListUsers`, and `GetUser` in `store/user.go`, keyed by user ID (`userCacheKey`, `store/user.go:88`).

- A second, unrelated cache exists for RSS feeds in `server/router/rss/rss.go` — a plain mutex-guarded map. If "user entries" meant the per-user RSS feed cache (`"user:" + username` keys in `GetUserRSS`), those expire after **`defaultCacheDuration = 1 * time.Hour`** (`server/router/rss/rss.go:25`), checked in `getFromCache`.

So: nothing to configure for Redis — the TTL for cached user records is 10 minutes, set in code in `store/store.go`, not in any external configuration.
