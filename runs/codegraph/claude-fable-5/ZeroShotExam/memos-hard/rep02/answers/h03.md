**`internal/idp`; `internal/idp/oauth2`**

- The abstraction lives in `internal/idp/idp.go` (package `idp`), which defines the provider-neutral `IdentityProviderUserInfo` struct (identifier, display name, email, avatar URL) that any provider implementation returns.
- The single concrete protocol implementation that ships is OAuth 2.0, in `internal/idp/oauth2/oauth2.go` (package `oauth2` — "Package oauth2 implements the OAuth2 identity provider integration"). Its `IdentityProvider` type wraps a `storepb.OAuth2Config` and implements `ExchangeToken` and `UserInfo` (which returns the abstraction's `*idp.IdentityProviderUserInfo`).

Supporting evidence: the sign-in flow in `server/router/api/v1/auth_service_sso.go` calls `oauth2.NewIdentityProvider` and consumes `idp.IdentityProviderUserInfo`, and the proto config (`proto/gen/api/v1/idp_service.pb.go`, `proto/gen/store/idp.pb.go`) has a `oneof config` with only an `Oauth2Config` variant — confirming OAuth2 is the only shipped protocol.
