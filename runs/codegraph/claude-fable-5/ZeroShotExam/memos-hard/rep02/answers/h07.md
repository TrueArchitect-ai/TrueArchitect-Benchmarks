The avatar is stored as a base64 data URI in the `avatar_url` column of the `user` table; the browser hits `GET /file/users/:identifier/avatar` and the chain to that column is:

- `FileServerService.RegisterRoutes` (wires `GET /file/users/:identifier/avatar`) — server/router/fileserver/fileserver.go:121–125
- `serveUserAvatar` (serving handler: optional anonymous-access check, then fetches the target user, validates MIME against `avatarAllowedTypes`, decodes the data URI with `parseDataURI`, returns bytes via `c.Blob`) — server/router/fileserver/fileserver.go:168
- `getUserByUsername` (builds `store.FindUser{Username: &identifier}`) — server/router/fileserver/fileserver.go:715
- `Store.GetUser` (checks `userCache`, falls through to list) — store/user.go:148
- `Store.ListUsers` (delegates to the DB driver, populates cache) — store/user.go:136
- `Driver.ListUsers` (interface, dispatched to the configured backend) — store/driver.go:47
- `DB.ListUsers` (concrete impl: `SELECT ... avatar_url ... FROM user WHERE username = ?`, scans into `store.User.AvatarURL`) — store/db/sqlite/user.go / store/db/mysql/user.go:84 / store/db/postgres/user.go

The `store.User` struct carrying `AvatarURL` back up the chain is defined at store/user.go:29. (Client-side, the request originates from the `UserAvatar` component's `<img>` at web/src/components/UserAvatar.tsx:8, but the server-side path above is the trace from handler to data.)
