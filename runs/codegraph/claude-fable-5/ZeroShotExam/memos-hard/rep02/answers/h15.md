Memo visibility is enforced independently on five server surfaces (plus per-endpoint filters within the gRPC API). The distinct enforcement sites:

- gRPC/Connect API (memo service) — `server/router/api/v1/memo_service.go` — `checkMemoReadAccess` (line 39) gates `GetMemo` (and parent-memo access), and `ListMemos` injects visibility filters (`Public` only for anonymous, `Public/Protected` for other users' memos, lines 218–227). The same check is reused for comments in `server/router/api/v1/memo_service_comments.go` (line 148, plus a `Private`-memo guard at line 41), for reactions in `server/router/api/v1/reaction_service.go` (lines 30–83), and for per-user stats in `server/router/api/v1/user_service_stats.go` (lines 84–90, 218–220).
- File/attachment HTTP server — `server/router/fileserver/fileserver.go` — before serving attachment bytes it loads the owning memo and enforces visibility: anonymous access only for `Public` memos on instances allowing it, a share-token fallback, and a `Private` check (`user.ID != memo.CreatorID && user.Role != RoleAdmin` → 403) around lines 666–703.
- RSS feeds — `server/router/rss/rss.go` — both the explore feed and the per-user feed query with `VisibilityList: []store.Visibility{store.Public}` (lines 90 and 141), so only public memos are ever syndicated.
- Frontend sitemap — `server/router/frontend/frontend.go` — `getSitemapXML` lists memos with `VisibilityList: []store.Visibility{store.Public}` (line 150), so only public memos appear in `sitemap.xml`.
- SSE real-time event stream — `server/router/api/v1/sse_hub.go` — `canReceive` (lines 134–144) filters event delivery per connected client: `Private` events go only to the creator or an admin; unknown visibility is denied.

So the minimum-three answer is the API v1 memo service, the fileserver, and the RSS router; the frontend sitemap and the SSE hub are two further independent enforcement points.
