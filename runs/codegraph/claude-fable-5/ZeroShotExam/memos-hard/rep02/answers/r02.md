**Premise correction: this repository has no per-user API rate-limiting middleware.** Nothing registers a rate limiter, throttle, or request quota anywhere in the server, so there are no request limits to report.

What the API stack actually registers instead:

- **Echo HTTP middleware** (`server/server.go:51-52`): only `middleware.Recover()` and a CORS middleware (`server/cors.go`).
- **Connect RPC interceptors** (`server/router/api/v1/connect_interceptors.go`): `MetadataInterceptor` (header→metadata conversion), `LoggingInterceptor`, `RecoveryInterceptor` (panic recovery), and `AuthInterceptor` (authentication/anonymous-access policy, backed by `server/auth/`). None of these count or limit requests.

The only "rate limit" mention in the backend is an aspirational doc comment — `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as an operational recommendation for deployers, not implemented code. A grep for `rate limit`/`throttle`/`limiter` across Go and frontend sources turns up nothing else relevant (the frontend hits are unrelated markdown-editor "delimiter" strings).
