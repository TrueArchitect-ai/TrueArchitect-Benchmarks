When the API handler (`DeleteMemo` in `server/router/api/v1/memo_service.go:518`) calls `Store.DeleteMemo`, the store-layer method at `store/memo.go:140-158` deletes these records before issuing the final `DELETE FROM memo` (via the driver, e.g. `store/db/sqlite/memo.go:237`):

- **Memo relation records** (`memo_relation`) — deleted twice via `driver.DeleteMemoRelation`: once where the memo is the source (`MemoID`) and once where it is the target (`RelatedMemoID`) (`store/memo.go:142-147`).
- **Attachment records** linked to the memo — listed with `ListAttachments{MemoID}` and each removed via `s.DeleteAttachment` (`store/memo.go:149-157`), which per `store/attachment.go` also handles the attachment's storage/derived-cache cleanup.

(Note: comment memos are also deleted, but that happens in the API layer before calling `Store.DeleteMemo` for the parent — each comment deletion recursively goes through the same store-layer cleanup.
