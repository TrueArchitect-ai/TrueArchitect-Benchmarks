**Answer:** `DispatchMemoCreatedWebhook` — `server/router/api/v1/memo_service_webhooks.go`; delivery package `internal/webhook` (`github.com/usememos/memos/internal/webhook`); signing mechanism: Standard Webhooks-style HMAC-SHA256 signature.

Details of the flow:

- The `CreateMemo` handler calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)` right after persisting the memo (`server/router/api/v1/memo_service.go:157`).
- `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`) delegates to `dispatchMemoRelatedWebhook` with activity type `"memos.memo.created"`. That helper looks up the creator's webhooks via `Store.GetUserWebhooks` (`store/user_setting.go:312`), builds a `webhook.WebhookRequestPayload` per hook, and enqueues each with `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:71`).
- HTTP delivery is done by the `internal/webhook` package: `PostAsync` feeds a bounded queue drained by 4 workers that call `Post` (`internal/webhook/webhook.go:120`), which POSTs the JSON payload using a shared SSRF-guarded `http.Client`.
- Signing: if the webhook has a signing secret, `Post` computes an HMAC-SHA256 over `msgID + "." + timestamp + "." + body` and sets the Standard Webhooks headers `webhook-id`, `webhook-timestamp`, and `webhook-signature: v1,<base64 MAC>` (`internal/webhook/webhook.go:133-150`); `whsec_`-prefixed secrets are base64-decoded to the raw key by `resolveSigningKey` (`internal/webhook/webhook.go:97`).
