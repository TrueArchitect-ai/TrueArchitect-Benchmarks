The server starts exactly one background runner, in `startBackgroundRunners` (`server/server.go:153`, called from `Server.Start` at `server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — triggered once immediately at startup via `RunOnce(ctx)`, then continuously in a goroutine via `Run()`, driven by a plain `time.NewTicker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). It's stopped via per-runner `context.CancelFunc` on shutdown (`server/server.go:176`).

Not started by the server:

- **memopayload runner** (`server/runner/memopayload/runner.go`) — defines a `Runner` with `RunOnce`, but the server never constructs or schedules it. Only its standalone function `RebuildMemoPayload` is called synchronously from the API layer during memo create/update (`server/router/api/v1/memo_service.go:108` and `:447`). It is not a background worker in practice.

**Unused scheduling infrastructure:** the full cron scheduler package `internal/scheduler/` (cron-expression parser with 5/6-field support, `Schedule.Next`, job runner, middleware — `parser.go`, `scheduler.go`, `job.go`, `middleware.go`) is not imported anywhere outside its own package (only its own tests and `example_test.go`). The server's sole runner uses a bare `time.Ticker` instead, so this entire cron infrastructure is dead code from the server's perspective.
