In `store/memo.go` (the `Store.DeleteMemo` method, `store/memo.go:140`), before deleting the memo row via the driver, the store layer deletes:

- **Memo relation records** (`memo_relation`) — deleted twice, covering both directions: relations where this memo is the source (`MemoID`) and relations where it is the target (`RelatedMemoID`), via `driver.DeleteMemoRelation`.
- **Attachment records** linked to the memo — listed with `ListAttachments{MemoID}` and each deleted with `DeleteAttachment`.

Only after that does it call `s.driver.DeleteMemo` to remove the memo row itself (implemented as a plain `DELETE FROM memo` in e.g. `store/db/postgres/memo.go:244` and `store/db/mysql/memo.go:259`).

Note: comment memos are also deleted, but that happens one layer up in the API handler (`server/router/api/v1/memo_service.go:567-577`), which calls `store.DeleteMemo` recursively for each comment — it's not part of the store layer's own cleanup.
