**Engine:** Google CEL (Common Expression Language), via the `github.com/google/cel-go` library. The filter machinery lives in `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`).

**Mechanism:** `Engine.Compile` (`internal/filter/engine.go:48`) compiles the filter string in a CEL environment built from the schema's `EnvOptions`, converts the CEL AST into a dialect-agnostic `Condition` IR tree via `buildCondition` (`internal/filter/parser.go`, node types in `internal/filter/ir.go`), and then `Program.Render`/`renderer.Render` (`internal/filter/render.go:32`) walks that tree to emit a dialect-specific SQL fragment plus bound args, keyed by `DialectName` (`sqlite`/`mysql`/`postgres`, `internal/filter/schema.go:13-17`).

The flow end to end: `APIV1Service.ListMemos` validates the filter and appends it to `FindMemo.Filters` (`server/router/api/v1/memo_service.go:211-216`); each store driver then calls `filter.DefaultEngine()` and `filter.AppendConditions` with its own dialect constant to merge the rendered SQL into its WHERE clause — `store/db/sqlite/memo.go:57-63` (DialectSQLite), `store/db/mysql/memo.go:65-71` (DialectMySQL), and `store/db/postgres/memo.go:54-60` (DialectPostgres, with numbered `$n` placeholders via `PlaceholderOffset`).
