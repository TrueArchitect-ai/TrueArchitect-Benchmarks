When the API's `DeleteMemo` handler (`server/router/api/v1/memo_service.go:518`) calls `Store.DeleteMemo`, the store layer (`store/memo.go:140-158`) deletes these record types before running the final `DELETE FROM memo`:

- **Memo relation records where the memo is the source** — `driver.DeleteMemoRelation` with `MemoID` set (`store/memo.go:142`)
- **Memo relation records where the memo is the target/related memo** — `driver.DeleteMemoRelation` with `RelatedMemoID` set (`store/memo.go:145`)
- **Attachment records linked to the memo** — it lists them via `ListAttachments{MemoID}` and deletes each with `DeleteAttachment` (`store/memo.go:149-157`, implemented in `store/attachment.go`)

Only after those cleanups does it call `driver.DeleteMemo` to remove the memo row itself (`store/memo.go:158`; per-database implementations in `store/db/sqlite/memo.go:237`, `store/db/mysql/memo.go:259`, `store/db/postgres/memo.go:244`).

Note that reactions are *not* deleted by the store layer — the API handler lists them only to build the webhook payload — and comment memos are deleted by the API layer itself (looping over comment relations and calling `Store.DeleteMemo` per comment), not inside the store method.
