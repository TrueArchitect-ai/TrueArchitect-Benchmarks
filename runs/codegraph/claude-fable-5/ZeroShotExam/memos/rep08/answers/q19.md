MemoService is served over **HTTP/JSON REST via gRPC-Gateway** and **Connect RPC (connectrpc)**. Both are wired up in `APIV1Service.RegisterGateway`:

- **gRPC-Gateway (HTTP/JSON REST under `/api/v1/*`)** — `server/router/api/v1/v1.go:108` calls `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` on the gateway mux (the generated registration lives in `proto/gen/api/v1/memo_service.pb.gw.go:961`).
- **Connect RPC (under `/memos.api.v1.*`)** — `server/router/api/v1/connect_handler.go:40` wraps the service with `apiv1connect.NewMemoServiceHandler(s, opts...)` inside `RegisterConnectHandlers`, which `v1.go:139-144` mounts on the Connect mux.

Note it is *not* served over native gRPC: the generated `RegisterMemoServiceServer` (`proto/gen/api/v1/memo_service_grpc.pb.go:439`) has no callers in the server code. The comment in `connect_handler.go` even notes Connect replaced grpc-web, with both protocols sharing the same `APIV1Service` gRPC-style implementation.
