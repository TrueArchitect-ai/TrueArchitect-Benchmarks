In this repo (memos), the API handler `DeleteMemo` (server/router/api/v1/memo_service.go:518) calls `Store.DeleteMemo`, and the store layer method (store/memo.go:140-158) cleans up two other kinds of records before issuing the final `DELETE FROM memo`:

- **Memo relation records** (`memo_relation`) — deleted twice, once where the memo is the source (`MemoID`) and once where it is the target (`RelatedMemoID`), via `driver.DeleteMemoRelation` (store/memo.go:142-147, store/memo_relation.go)
- **Attachment records** linked to the memo — listed with `ListAttachments{MemoID}` and each removed via `DeleteAttachment` (store/memo.go:149-157, store/attachment.go)

Only after that does it call `s.driver.DeleteMemo`, which executes the plain `DELETE FROM memo WHERE id = ?` in each driver (store/db/sqlite/memo.go:237, store/db/mysql/memo.go:259, store/db/postgres/memo.go:244).

Note: comment memos are also deleted before the parent, but that recursion happens in the API layer (memo_service.go:567-577), not the store layer — and reactions are not deleted by `Store.DeleteMemo` at all.
