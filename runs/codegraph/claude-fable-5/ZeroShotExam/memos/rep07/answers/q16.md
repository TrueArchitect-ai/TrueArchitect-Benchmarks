When the API handler (`DeleteMemo` in `server/router/api/v1/memo_service.go:518`) calls `Store.DeleteMemo`, the store layer (`store/memo.go:140-158`) deletes these records before issuing the `DELETE FROM memo` for the memo row itself:

- **Memo relation records** (`memo_relation`) — two `DeleteMemoRelation` calls: one for relations where the memo is the source (`MemoID`), one where it is the target (`RelatedMemoID`) (`store/memo.go:142-147`)
- **Attachment records** linked to the memo — it lists attachments with `FindAttachment{MemoID}` and deletes each via `DeleteAttachment` (`store/memo.go:149-157`)

Only after that does it call `s.driver.DeleteMemo`, which runs the plain `DELETE FROM memo WHERE id = ?` in each driver (`store/db/sqlite/memo.go:237`, `store/db/mysql/memo.go:259`, `store/db/postgres/memo.go:244`).

Note that comment memos are deleted at the API layer (the handler loops over comment relations and calls `Store.DeleteMemo` for each child, `memo_service.go:567-577`), not inside the store method itself; reactions are only listed at the API layer for the webhook payload, not deleted by `Store.DeleteMemo`.
