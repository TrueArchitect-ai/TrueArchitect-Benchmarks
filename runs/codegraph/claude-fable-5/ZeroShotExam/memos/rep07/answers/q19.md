MemoService is served over two protocols, both mounted on the same Echo HTTP server (no standalone `grpc.NewServer` is created; the gRPC-generated `RegisterMemoServiceServer` in `proto/gen/api/v1/memo_service_grpc.pb.go` is unused for a native gRPC listener):

- **REST / HTTP-JSON via gRPC-Gateway** — `server/router/api/v1/v1.go` (`RegisterGateway` calls `v1pb.RegisterMemoServiceHandlerServer` at `server/router/api/v1/v1.go:108`, and mounts the gateway mux on `/api/v1/*`).
- **Connect RPC (connectrpc, which also speaks gRPC/gRPC-Web wire formats for browser clients)** — `server/router/api/v1/connect_handler.go` (the `ConnectServiceHandler` wrapper around `APIV1Service`; `RegisterConnectHandlers` calls `apiv1connect.NewMemoServiceHandler` at `server/router/api/v1/connect_handler.go:40`). The Connect mux is mounted on `/memos.api.v1.*` back in `server/router/api/v1/v1.go:139-144`.

So in the requested format:

- gRPC-Gateway (REST/JSON) — `server/router/api/v1/v1.go`
- Connect RPC — `server/router/api/v1/connect_handler.go` (wired into Echo in `server/router/api/v1/v1.go`)

Both share the single business-logic implementation in `APIV1Service`; the generated handlers live in `proto/gen/api/v1/memo_service.pb.gw.go` (gateway) and `proto/gen/api/v1/apiv1connect/memo_service.connect.go` (Connect).
