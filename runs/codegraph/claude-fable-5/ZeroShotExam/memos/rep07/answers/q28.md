The server starts exactly one background runner, in `startBackgroundRunners` (server/server.go:153), called from `Server.Start` (server/server.go:129):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — triggered by an immediate `RunOnce(ctx)` at startup, then a plain `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, server/runner/s3presign/runner.go:27-41), running in a goroutine until its context is canceled at shutdown (`stopBackgroundRunners`, server/server.go:176).

That's the only one. Two other pieces of infrastructure exist but are **not** started by the server:

- **`internal/scheduler`** — a full cron-style job scheduler (`Scheduler`, `Register`, `Start`, `ParseCronExpression` in `internal/scheduler/scheduler.go`) is present in the codebase but is imported by no code outside its own package; the server never creates or starts a `Scheduler`, so this scheduling infrastructure is entirely unused.
- **`server/runner/memopayload`** (`server/runner/memopayload/runner.go`) — despite living under `server/runner/` and having a `RunOnce` batch method, it is never started as a background runner. Only its standalone helper `RebuildMemoPayload` is called synchronously from the API request path (`server/router/api/v1/memo_service.go:108` and `:447`); the `Runner` itself has no scheduled or background invocation.
