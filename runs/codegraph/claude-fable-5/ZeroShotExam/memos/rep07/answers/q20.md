**Mechanism:** Server-Sent Events (SSE). The server maintains an SSE hub and streams JSON change events (`memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`) to connected browsers via `handleSSE` in `server/router/api/v1/sse_handler.go` (with a heartbeat interval and per-client visibility filtering).

**Hub path:** `server/router/api/v1/sse_hub.go` — the `SSEHub` struct with `Subscribe`, `Unsubscribe`, `Broadcast`, and `Close` methods; slow clients get events dropped rather than blocking the broadcaster, and private-memo events are filtered so only the creator or an admin receives them (`canReceive`).

**Handlers that broadcast:** Per the call graph, `SSEHub.Broadcast` is invoked from:
- `CreateMemo` — `server/router/api/v1/memo_service.go`
- `DeleteMemo` — `server/router/api/v1/memo_service.go`
- `dispatchMemoUpdatedSideEffects` (the update path used by `UpdateMemo`) — `server/router/api/v1/memo_update_helpers.go`
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go`
- `UpsertMemoReaction` and `DeleteMemoReaction` — `server/router/api/v1/reaction_service.go`

**Answer format:** Server-Sent Events (SSE); `server/router/api/v1/sse_hub.go`; CreateMemo, DeleteMemo, dispatchMemoUpdatedSideEffects (UpdateMemo), CreateMemoComment, UpsertMemoReaction, DeleteMemoReaction
