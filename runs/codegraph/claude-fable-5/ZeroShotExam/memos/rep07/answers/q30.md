Four memo lifecycle events dispatch webhooks, all defined in `server/router/api/v1/memo_service_webhooks.go`:

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`)
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:20`, called from `server/router/api/v1/memo_update_helpers.go`)
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook` (`server/router/api/v1/memo_service_webhooks.go:25`, called from `DeleteMemo` in `server/router/api/v1/memo_service.go`)
- memo comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:30`)

Convergence for delivery: the created/updated/deleted dispatchers all funnel through the shared helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which — like `DispatchMemoCommentCreatedWebhook` — ultimately calls `webhook.PostAsync` in `internal/webhook/webhook.go:184`. `PostAsync` enqueues the payload onto `asyncPostQueue`, and the actual HTTP delivery (JSON POST with HMAC `webhook-signature` headers) happens in `webhook.Post` (`internal/webhook/webhook.go:120`). So the single delivery path all events converge on is `webhook.PostAsync` → `asyncPostQueue` → `webhook.Post` in `internal/webhook/webhook.go`.
