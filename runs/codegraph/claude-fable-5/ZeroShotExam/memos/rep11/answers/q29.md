Frontend requests go through a Connect RPC interceptor that attaches a `Authorization: Bearer <token>` header and transparently refreshes expired tokens.

- **Interceptor path:** `web/src/connect.ts` — `authInterceptor` (registered on the Connect transport at `web/src/connect.ts:184-189`), with token storage helpers in `web/src/auth-state.ts`. It does a preflight refresh when the access token is near expiry (`getRequestToken`), and on a `Code.Unauthenticated` error it refreshes once and retries the request (marked with an `X-Retry` header), redirecting to sign-in if refresh fails.
- **Token kinds:** a short-lived JWT **access token** (kept in memory/auth-state, sent as the Bearer header) and a long-lived **refresh token** (sent as an HTTP-only cookie via `credentials: "include"` and the `AuthService.RefreshToken` RPC over a separate interceptor-free transport). The backend additionally supports **personal access tokens** (`memos_pat_*`, managed via `server/router/api/v1/user_service_access_tokens.go`) for external clients, though the web interceptor itself only manages the access/refresh pair.
- **Backend package:** `server/auth` — `server/auth/token.go` defines `ParseAccessTokenV2`/`ParseRefreshToken` (HS256 JWT validation with issuer/audience/type checks) and PAT hashing; the API layer wires this in through `Authenticate` in `server/router/api/v1/authz.go` and the connect interceptors in `server/router/api/v1/connect_interceptors.go`.

**Answer:** `web/src/connect.ts` (authInterceptor); JWT access tokens + refresh tokens (plus server-side personal access tokens); `server/auth`.
