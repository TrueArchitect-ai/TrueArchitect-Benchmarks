When `Store.DeleteMemo` runs (`store/memo.go:140-158`), it deletes these related records before issuing the `DELETE FROM memo` for the memo row itself (which happens in the drivers, e.g. `store/db/sqlite/memo.go:237`):

- **Memo relation records** — two `driver.DeleteMemoRelation` calls remove `memo_relation` rows where the memo is the source (`MemoID`) and where it is the target (`RelatedMemoID`) (`store/memo.go:142-147`).
- **Attachment records** — it lists attachments linked to the memo and deletes each one via `s.DeleteAttachment` (`store/memo.go:149-157`).

For context, the API handler (`server/router/api/v1/memo_service.go:518`) additionally deletes comment memos (child memos related by `MemoRelationComment`) before calling `Store.DeleteMemo` on the target memo, but within the store layer itself the cleanup is relations and attachments. Reactions are only listed there for the webhook payload, not deleted by the store's `DeleteMemo`.
