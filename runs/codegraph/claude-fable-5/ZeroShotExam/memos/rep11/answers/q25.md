**Engine:** Google CEL (Common Expression Language) via `github.com/google/cel-go`, wrapped by the repo's own filter engine in `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:178`) validates the filter string and passes it via `store.FindMemo.Filters` to the per-dialect store drivers; each driver (`store/db/sqlite/memo.go:54`, `store/db/mysql/memo.go:62`, `store/db/postgres/memo.go:51`) gets `filter.DefaultEngine()` and calls `filter.AppendConditions` with its dialect (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`). The engine (`internal/filter/engine.go`) compiles the string with `cel.Env.Compile`, converts the CEL AST into a dialect-agnostic condition IR (`buildCondition` in `internal/filter/parser.go`, node types in `internal/filter/ir.go`, folding `now` to a frozen constant), then a renderer (`internal/filter/render.go`) walks that condition tree and emits a dialect-specific parameterized SQL fragment plus args (handling per-dialect column quoting, placeholder styles, JSON extraction, and date-part accessors per the schema in `internal/filter/schema.go`), which the driver appends to its `WHERE` clause.

One-sentence summary: CEL syntax parsed by cel-go inside the custom engine at `internal/filter/`; the CEL AST is lowered to an intermediate `Condition` tree which a per-dialect renderer converts into a parameterized SQL `WHERE` fragment for SQLite, MySQL, or Postgres.
