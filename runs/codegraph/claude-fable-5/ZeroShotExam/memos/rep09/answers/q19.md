MemoService is served over two protocols, both wired up from `APIV1Service.RegisterGateway` in `server/router/api/v1/v1.go` (the comment there says it "registers the gRPC-Gateway and Connect handlers"):

- **HTTP/JSON REST (gRPC-Gateway)** — `server/router/api/v1/v1.go`: `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` at `server/router/api/v1/v1.go:108` registers the generated gateway handlers (from `proto/gen/api/v1/memo_service.pb.gw.go`) on a `runtime.ServeMux` mounted under `/api/v1/*`.
- **Connect RPC** — `server/router/api/v1/connect_handler.go`: `ConnectServiceHandler` wraps `APIV1Service`, and `RegisterConnectHandlers` calls `apiv1connect.NewMemoServiceHandler(s, opts...)` at `server/router/api/v1/connect_handler.go:40`, mounted under `/memos.api.v1.*` back in `server/router/api/v1/v1.go:139-144`.

Note that despite the generated `RegisterMemoServiceServer` in `proto/gen/api/v1/memo_service_grpc.pb.go`, the server does not register a native gRPC server for it — the two live protocols are the gRPC-Gateway REST API and Connect (which replaced grpc-web for browser clients, per the comment at `server/router/api/v1/v1.go:131`).
