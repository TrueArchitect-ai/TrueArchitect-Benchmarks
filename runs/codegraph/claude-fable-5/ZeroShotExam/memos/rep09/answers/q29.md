Frontend API requests go through a Connect-RPC client interceptor: `authInterceptor` in `web/src/connect.ts` (line 156), which is registered on the transport created by `createConnectTransport` (`web/src/connect.ts:184`). On every request it calls `getRequestToken()` to fetch the current access token (stored in localStorage and synced across tabs via `web/src/auth-state.ts`), sets it as an `Authorization: Bearer <token>` header, proactively refreshes it if it's within 30 seconds of expiry, and on a 401 (`Code.Unauthenticated`) reactively refreshes and retries the request once before redirecting to login.

The tokens it manages:
- **JWT access token** — short-lived (15 minutes), sent as the Bearer header, persisted in localStorage (`memos_access_token` in `web/src/auth-state.ts`).
- **JWT refresh token** — long-lived (30 days), held in the `memos_refresh` httpOnly cookie; the interceptor never reads it directly but triggers `AuthService.RefreshToken` over a separate interceptor-free transport with `credentials: "include"` to obtain new access tokens (`web/src/connect.ts:65-91`).

On the backend, these are validated by the **`server/auth`** package (`server/auth/token.go`): `ParseAccessTokenV2` and `ParseRefreshToken` verify the JWT signature, issuer, and audience claims (and it also handles Personal Access Tokens via `HashPersonalAccessToken`). The server-side `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` delegates to this package for each request.
