**Runners the server actually starts** (all wiring is in `server/server.go`, `startBackgroundRunners`, `server/server.go:153`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — the only background runner started. It's triggered two ways: an immediate `RunOnce(ctx)` at server startup (`server/server.go:163`), then a continuous goroutine whose scheduling is driven by a plain `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`), stopped via per-runner `context.CancelFunc` on shutdown.

**Present but NOT started as a background runner:**

- **memopayload runner** (`server/runner/memopayload/runner.go`) — the `Runner` type and `NewRunner` are never instantiated by the server; nothing calls its `RunOnce`. Only its standalone helper `RebuildMemoPayload` is invoked synchronously from the API request path (`server/router/api/v1/memo_service.go:108,447`), so it runs on demand, not on any schedule.

**Unused scheduling infrastructure:**

- `internal/scheduler/` — a full GitHub-Actions-inspired cron scheduler (cron expression parsing, timezones, middleware, graceful shutdown; see `internal/scheduler/doc.go`, `scheduler.go`, `parser.go`, `job.go`) is **not imported anywhere outside its own package** — the server does not use it. The only production scheduling actually in use is the raw `time.Ticker` inside the s3presign runner.
