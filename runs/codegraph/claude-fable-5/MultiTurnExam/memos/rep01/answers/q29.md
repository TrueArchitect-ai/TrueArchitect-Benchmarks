- **Interceptor:** `web/src/connect.ts` — the `authInterceptor` (a ConnectRPC `Interceptor`, around lines 155-180) attaches `Authorization: Bearer <token>` to every request, does a preflight refresh of near-expired tokens, and on an `Unauthenticated` error refreshes once via a separate no-interceptor transport (`refreshAuthClient.refreshToken`) and retries before redirecting to sign-in. Token state itself lives in `web/src/auth-state.ts`.
- **Token kinds:** short-lived JWT **access tokens** (~15 minutes, sent as Bearer header, refreshed by the interceptor) and a **refresh token** held in an HTTP-only cookie (sent with `credentials: "include"` to the RefreshToken RPC). The backend additionally accepts long-lived **personal access tokens (PATs)** on the same Bearer header, though the web interceptor only manages the access/refresh pair.
- **Backend package:** `server/auth` — `server/auth/authenticator.go` validates them (`AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `resolveBearer` for access token vs. PAT, and `AuthenticateToUser` which tries the Authorization header then falls back to the refresh-token cookie), wired into the API through `server/router/api/v1/authz.go` and `connect_interceptors.go`.
