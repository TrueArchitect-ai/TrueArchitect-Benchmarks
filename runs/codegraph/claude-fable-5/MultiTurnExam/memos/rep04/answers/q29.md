- **Interceptor:** `web/src/connect.ts` — the `authInterceptor` (line ~156) attached to the ConnectRPC transport. It attaches the token via `Authorization: Bearer ...`, does preflight refresh of near-expiry tokens, and on an `Unauthenticated` error refreshes once and retries (marking the retry with an `X-Retry` header), redirecting to sign-in if refresh fails. Token state itself lives in `web/src/auth-state.ts`.
- **Token kinds:** a short-lived **access token** (kept in frontend state, sent as a Bearer header) and a **refresh token** (HTTP-only cookie, sent via `credentials: "include"` and exchanged through `AuthService.RefreshToken` on a separate interceptor-free transport to avoid recursion, `web/src/connect.ts:65-92`).
- **Backend validation package:** `server/auth/` — the `Authenticator` (`server/auth/authenticator.go`, e.g. `resolveBearer` and `AuthenticateByRefreshToken`, with token logic in `server/auth/token.go`), invoked from the API layer's `Authenticate` in `server/router/api/v1/authz.go:44` via the Connect interceptors (`server/router/api/v1/connect_interceptors.go`) and the gateway auth middleware in `server/router/api/v1/v1.go`.
