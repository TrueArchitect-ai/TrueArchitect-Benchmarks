Runners the server actually starts (`Server.startBackgroundRunners`, `server/server.go:153-174`):

- s3presign runner (`server/runner/s3presign/runner.go`) — run once synchronously at startup (`RunOnce`, `server/server.go:163`), then continuously in a goroutine driven by a plain `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-40`), cancelled via per-runner context on shutdown.

That is the only background runner the server starts. Two other pieces of scheduling/worker infrastructure exist but are NOT used by the server:

- `internal/scheduler/` — a full cron-style scheduler package (`scheduler.go`, `parser.go`, `job.go`) that is imported by nothing outside its own package and tests; no server code wires it up.
- `server/runner/memopayload/runner.go` — a `Runner` with `RunOnce` to rebuild all memo payloads, but `memopayload.NewRunner` is never called anywhere (not in `server/server.go` or `cmd/memos/`); only the package's synchronous helper `RebuildMemoPayload` is used inline by the memo handlers (`server/router/api/v1/memo_service.go:108`, `:447`).
