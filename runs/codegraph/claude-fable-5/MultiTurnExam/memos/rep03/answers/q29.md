Interceptor: web/src/connect.ts; tokens: short-lived JWT access token (Bearer header, kept in memory via `web/src/auth-state.ts`) + HTTP-only cookie refresh token (and the backend also accepts personal access tokens); backend package: server/auth

Details: the auth interceptor in `web/src/connect.ts` attaches `Authorization: Bearer <accessToken>` to every request (`setAuthorizationHeader`, ~line 98), proactively refreshes tokens near expiry, and on a 401 calls `refreshAccessToken()` — which uses a separate interceptor-free transport (`refreshTransport`/`refreshAuthClient`, lines 65-72) hitting `AuthService.RefreshToken` with `credentials: "include"` so the cookie-stored refresh token is sent, then retries the original request once (`X-Retry` header). Access-token state lives in `web/src/auth-state.ts`. On the backend, the `server/auth` package validates everything: `Authenticator.AuthenticateByAccessTokenV2` parses the 15-minute JWT access token, `AuthenticateByRefreshToken` checks the refresh token against the database (revocation/expiry), and `AuthenticateByPAT` handles personal access tokens (`server/auth/authenticator.go`), wired into request handling via `Authenticate` in `server/router/api/v1/authz.go` and the Connect interceptors in `server/router/api/v1/connect_interceptors.go`.
