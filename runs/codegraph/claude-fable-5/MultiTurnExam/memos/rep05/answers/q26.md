Tables affected when DeleteMemo runs:

- **memo** — the row itself, deleted by the dialect driver (`store/db/sqlite/memo.go:237-248`, `DELETE FROM memo`); the API handler additionally deletes comment memos (also `memo` rows) first via repeated `Store.DeleteMemo` calls (`server/router/api/v1/memo_service.go:568-578`)
- **memo_relation** — explicit cascade in `Store.DeleteMemo` (`store/memo.go:142-147`), deleting rows where the memo is either `memo_id` or `related_memo_id`
- **attachment** — explicit cascade in `Store.DeleteMemo` (`store/memo.go:149-157`), which calls `Store.DeleteAttachment` (`store/attachment.go:132`) per attachment (this also removes the underlying file from local/S3 storage, which is not a table)

No explicit cascade code touches `reaction` or `memo_share` in this path — the API handler at `server/router/api/v1/memo_service.go:545` lists reactions only to build the deleted-webhook payload, and there is no `DeleteReaction`/`DeleteMemoShare` call in the delete flow.
