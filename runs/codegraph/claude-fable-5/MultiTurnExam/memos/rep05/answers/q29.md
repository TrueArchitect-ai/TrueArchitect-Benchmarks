Interceptor: web/src/connect.ts (the auth interceptor built around `setAuthorizationHeader` / `shouldHandleUnauthenticatedRetry`, with token storage in `web/src/auth-state.ts`); token kinds: short-lived JWT access tokens (sent as `Authorization: Bearer ...`, ~15 min) and refresh tokens (HTTP-only cookie, used by the interceptor's `refreshAccessToken` flow via the separate `refreshTransport`) — plus long-lived Personal Access Tokens for programmatic (non-browser) access; backend package: server/auth

How it works: the interceptor in `web/src/connect.ts` attaches the in-memory access token to every request, and on a `Code.Unauthenticated` error it deduplicates a call to `AuthService.RefreshToken` (over a credential-including transport so the refresh-token cookie is sent, `web/src/connect.ts:64-91`) and retries once. On the backend, `Authenticator.AuthenticateToUser` in `server/auth/authenticator.go:190` validates the Authorization header first (JWT access token via `AuthenticateByAccessTokenV2`, or PAT), then falls back to the refresh-token cookie (`AuthenticateByRefreshToken`, checked against the database); JWT parsing lives in `server/auth/token.go`.
