Memo visibility is enforced independently on each server surface that can expose memo content:

1. **gRPC/REST API v1 — direct memo access check** (`canAccessMemo`-style guard in `GetMemo`): public allowed anonymously, otherwise requires auth; Private requires creator — `server/router/api/v1/memo_service.go:55-63`; list endpoints additionally constrain queries to `Public`/`Protected` for non-owners — `server/router/api/v1/memo_service.go:219-225`.
2. **API v1 sub-resources replicate the check** for content reachable through related RPCs: attachments (`server/router/api/v1/attachment_service.go:445-451`, `server/router/api/v1/memo_attachment_service.go:214-222`), reactions (`server/router/api/v1/reaction_service.go:30-83`), and comments (`server/router/api/v1/memo_service_comments.go:41`).
3. **HTTP file server** (raw attachment/media downloads outside gRPC): re-checks memo visibility before serving file bytes — `server/router/fileserver/fileserver.go:677-699` (Public + anonymous allowed only if instance allows it; Private restricted to creator/admin).
4. **RSS feeds**: queries are hard-limited to `store.Public` memos — `server/router/rss/rss.go:90` (explore feed) and `:141` (user feed).
5. **Frontend/sitemap serving**: sitemap generation only lists Public memos — `server/router/frontend/frontend.go:150`.
6. **Notification/email surface**: before including memo content in mention notifications/emails, visibility is enforced (Private only to creator, Protected to signed-in users) — `server/notification/email.go:313-316`, `server/router/api/v1/user_service_notifications.go:309-312`, and `server/router/api/v1/memo_mention_helpers.go:62-84`.
