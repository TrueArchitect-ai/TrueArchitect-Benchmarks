**Premise correction: neither — there is no message broker.** The codebase uses no NATS, RabbitMQ, or any external queueing system (no such imports exist anywhere in the Go sources).

**Actual mechanism**: webhook delivery is queued entirely in-process with a buffered Go channel. `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39`. An `init()` function in the same file (`internal/webhook/webhook.go:42-55`) starts 4 worker goroutines that range over that channel and call `Post` (`webhook.go:120`) to perform the actual HTTP delivery. Producers enqueue via `PostAsync` (`webhook.go:184-196`), which does a non-blocking send and drops the dispatch with a warning log if the 128-slot buffer is full. So delivery is best-effort and in-memory only — no persistence, broker, or cross-process queue.
