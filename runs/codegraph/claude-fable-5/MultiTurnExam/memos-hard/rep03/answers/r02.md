**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** Nothing registers one, and no request-count limits exist.

What I checked:
- A repo-wide search of the Go sources for rate-limiting terms (`ratelimit`, `rate limit`, `throttle`, `limiter`) finds only a documentation comment suggesting email sending "should" be rate-limited (`internal/email/doc.go:86`) — no implementation.
- The Echo server registers only two middlewares: `Recover()` and CORS (`server/server.go:51-52`).
- The Connect/gRPC API pipeline registers four interceptors — metadata, logging, recovery, and auth (`server/router/api/v1/v1.go:133-137`) — none of which do rate limiting.

The closest things that do exist are resource guards, not per-user rate limits: a request-size cap on the API (`connect.WithReadMaxBytes(maxAPIRequestBytes)`, `server/router/api/v1/v1.go:141`) and concurrency semaphores limiting thumbnail generation to 3 and image processing to 2 concurrent operations (`server/router/api/v1/v1.go:59-60`) — instance-wide, not per user.
