This is the webhook system. When a memo changes, the server dispatches webhook payloads via `internal/webhook`.

**Delivery function** — `webhook.Post` at `internal/webhook/webhook.go:120` performs the actual outbound HTTP POST (signing the body with HMAC-SHA256 if a secret is set, then sending via the shared `safeClient`). Async dispatches go through `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded queue drained by worker goroutines that call `Post`.

**Protection mechanism** — two layers of SSRF defense:
1. **Dial-time blocking**: the shared HTTP client's transport uses `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the target host at connection time and refuses to dial any address in a reserved/private range — this also defeats DNS-rebinding, since the check happens on the addresses actually being dialed. The reserved ranges (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents) are defined in `reservedCIDRs`/`isReservedIP` at `internal/webhook/validate.go:14-54`.
2. **Registration-time validation**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects webhook URLs that aren't http/https or that resolve to a reserved/private IP, called from `server/router/api/v1/user_service_webhooks.go` when webhooks are created/updated.

An escape hatch, `AllowPrivateIPs` (`internal/webhook/validate.go:41`), can disable the check for self-hosted deployments targeting local-network services.
