**Premise correction: there is no Redis in this codebase.** A repo-wide search for "redis" in the Go sources finds nothing — the cache layer is a pure in-process, in-memory cache, not an external store.

**Actual mechanism**: the cache is implemented in `store/cache/cache.go` — a thread-safe in-memory map with per-entry TTL, periodic cleanup, and a max-item cap (`Cache` struct, `store/cache/cache.go:66`). The `Store` constructs three of them (instance-setting, user, and user-setting caches) in `store/store.go:40-53` with an inline `cache.Config`.

**TTL for user entries**: user cache entries use the `DefaultTTL` of **10 minutes** (`store/store.go:41`; same value as `DefaultConfig()` in `store/cache/cache.go:59`), with cleanup every 5 minutes and a 1000-item cap. Entries are written via `Set`, which applies the default TTL (`store/cache/cache.go:92-94`), e.g. from `Store.GetUser`/`ListUsers` in `store/user.go:143,167`.
