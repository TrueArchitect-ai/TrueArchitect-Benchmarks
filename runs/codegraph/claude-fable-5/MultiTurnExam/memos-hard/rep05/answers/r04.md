**Premise correction: neither.** There is no message broker in this codebase — no NATS, no RabbitMQ (no such imports exist in `go.mod` or anywhere in the Go source).

**Actual mechanism:** webhook delivery is queued entirely in-process using a buffered Go channel:

- The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — declared at `internal/webhook/webhook.go:39`.
- The "workers" are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over that channel and calling `Post` (`internal/webhook/webhook.go:120`) to perform the actual HTTP delivery.
- Producers (the memo webhook dispatchers in `server/router/api/v1/memo_service_webhooks.go`) enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send; if the 128-slot buffer is full the dispatch is **dropped** with a warning log rather than persisted or retried.

So delivery is best-effort and ephemeral: the queue lives only in server memory, has no durability across restarts, and involves no external broker.
