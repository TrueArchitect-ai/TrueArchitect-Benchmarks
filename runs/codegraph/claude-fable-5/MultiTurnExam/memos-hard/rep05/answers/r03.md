**Premise correction: there is no nightly database-cleanup job, and the cron scheduler isn't wired into the server at all.**

What the repo actually contains:

- A generic cron-capable scheduler package exists at `internal/scheduler/` (`scheduler.go`, `parser.go`, `job.go`), with cron-expression parsing, timezone support, and middleware. But **no production code imports it** — the only references outside the package itself are its own tests/examples (`internal/scheduler/doc.go`, `example_test.go`, etc.). No job — cleanup or otherwise — is registered with it anywhere.
- The only recurring background work the server actually runs is the **S3 presigned-URL refresh runner**, started from `Server.startBackgroundRunners` (`server/server.go:153-174`) on a 12-hour ticker (`server/runner/s3presign/runner.go:27`). That refreshes attachment URLs; it is not a database cleanup and doesn't use the cron scheduler.
- Database cleanup that does exist is **inline, not scheduled**: e.g. `store.DeleteMemo` removes related relations/attachments at delete time (`store/memo.go:140-159`), and user deletion cleans up dependent rows in a transaction (`store/db/*/user_delete.go`). Expired-data sweeps of cache entries happen in the in-memory cache's cleanup goroutine (`store/cache/cache.go`), also not cron-based.

So there is no scheduled time to report — the premise (a nightly DB-cleanup cron job) doesn't match the codebase.
