Distinct memo-visibility enforcement sites across the server's surfaces:

**API v1 (gRPC / Connect / HTTP gateway):**
- `GetMemo` per-memo check + `ListMemos` visibility filtering (anonymous → PUBLIC only; signed-in → PUBLIC+PROTECTED plus own) — `server/router/api/v1/memo_service.go:55-63`, `:219-225`
- Comment access/creation checks on the related memo — `server/router/api/v1/memo_service_comments.go:41`, `:100`
- Reaction list/upsert checks — `server/router/api/v1/reaction_service.go:30-38`, `:83`
- Memo-attachment operations check the memo's visibility — `server/router/api/v1/memo_attachment_service.go:214-222`
- Mention-notification suppression respects visibility (a mention in a PRIVATE memo doesn't notify non-creators) — `server/router/api/v1/memo_mention_helpers.go:62-84`
- User stats restrict which memos are counted by viewer (`VisibilityList`) — `server/router/api/v1/user_service_stats.go:84-90`, `:218-220`
- Notifications avoid leaking private/protected memo content — `server/router/api/v1/user_service_notifications.go:309-312`

**File server (raw attachment/media downloads):**
- `FileServerService.checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650-704`: PUBLIC memo attachments only for anonymous-allowed instances; share-token fallback; PRIVATE requires creator or admin.

**RSS feeds:**
- Explore and per-user feeds query only `store.Public` memos — `server/router/rss/rss.go:90`, `:141`

**Frontend/SEO surface:**
- Sitemap generation lists only PUBLIC memos — `server/router/frontend/frontend.go:150`

(The MCP endpoint reuses the in-process API v1 routes, so it inherits the API-layer enforcement rather than adding its own.)
