**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" finds no imports, clients, connection config, or environment variables — the cache layer is not backed by Redis at all.

**Actual mechanism:** the cache layer is a purely in-process, thread-safe in-memory cache implemented in `store/cache/cache.go` (the `Cache` struct, "thread-safe in-memory cache with TTL and memory management", `store/cache/cache.go:66`). The `Store` creates three instances of it — `instanceSettingCache`, `userCache`, and `userSettingCache` — in `store.New` (`store/store.go:38-52`), all sharing one config:

- **TTL for user entries: 10 minutes** (`DefaultTTL: 10 * time.Minute`, `store/store.go:41`), applied because `Store` code populates the user cache via plain `Set` (e.g. `store/user.go:98`, `:132`, `:143`), which uses the default TTL (`store/cache/cache.go:92-94`).
- Cleanup sweep every 5 minutes, max 1000 items per cache (`store/store.go:42-43`).

So nothing is configured for an external cache service; user entries live in process memory for up to 10 minutes (or until eviction/update).
