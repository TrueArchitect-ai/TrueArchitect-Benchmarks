**Premise correction: this project has no GraphQL API.** A repo-wide search for "graphql" across Go, TypeScript, proto, and config files finds nothing — no schema files (`.graphql`), no GraphQL libraries in `go.mod` or `web/package.json`, no resolvers.

**Actual API surface:** the public API is Protobuf/gRPC-based, defined in `.proto` files and exposed over several transports:

- **Schema definition:** the proto service definitions under `proto/api/v1/` — `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto` — with generated Go code in `proto/gen/api/v1/`.
- **Transports:** registered in `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`): native gRPC handlers, a **gRPC-Gateway** REST/JSON mapping, and **Connect protocol** handlers (`proto/gen/api/v1/apiv1connect/`), all mounted on the Echo server (`server/server.go`).
- **OpenAPI description:** a generated `openapi.yaml` embedded into the binary via `proto/openapi_embed.go` (`//go:embed gen/openapi.yaml`), which also drives the **MCP endpoint** (`server/router/mcp/service.go` builds its tool registry from that spec).
- Auxiliary read-only surfaces: RSS feeds (`server/router/rss/rss.go`) and the file server for attachments/avatars (`server/router/fileserver/fileserver.go`).

So the closest analog to "the schema for the public API" is the proto package `proto/api/v1/` (plus the generated OpenAPI spec), not a GraphQL schema.
