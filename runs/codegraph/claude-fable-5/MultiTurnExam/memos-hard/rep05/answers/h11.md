**1st: `store.User` (~7 outside packages); 2nd: `store.Memo` (~6 outside packages)**

The persistent entity types are the structs in the `store` package (`store/user.go`, `store/memo.go`, `store/attachment.go`, `store/reaction.go`, `store/memo_relation.go`, …). Counting distinct Go packages outside the data layer (i.e., excluding `store/`, `store/db/*`, `store/test`) that reference each type:

- **`store.User`** (`store/user.go:29`) — 7 packages: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- **`store.Memo`** (`store/memo.go:35`) — 6 packages: `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`

Runners-up for comparison: `store.Attachment` — 4 packages (`api/v1`, `api/v1/test`, `fileserver`, `rss`); `store.MemoRelation` — 3; `store.Reaction` — 2. So `User` edges out `Memo` for the widest reach, mainly because auth (`server/auth`) and avatar serving (`server/router/fileserver`) need users but not memos.
