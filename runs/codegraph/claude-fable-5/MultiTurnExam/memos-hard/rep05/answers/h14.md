**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`. It runs `markdownService.ExtractAll` (the goldmark-based single-pass extractor, `internal/markdown/markdown.go:356`) over the memo's content and writes the results into `memo.Payload` (`storepb.MemoPayload`), which is persisted alongside the memo and used for list filtering/previews.

**Triggers (recomputation happens on):**
- **Memo creation** — `APIV1Service.CreateMemo` calls `RebuildMemoPayload` before inserting (`server/router/api/v1/memo_service.go:108`); comment creation goes through the same creation path.
- **Content update** — `APIV1Service.UpdateMemo`, in the `content` update-mask branch, rebuilds the payload before saving (`server/router/api/v1/memo_service.go:447`).
- A batch rebuild-everything path exists in `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), but it has no production callers — it's dead code, not a live trigger.

**Extracted properties:** from `ExtractedData` (`internal/markdown/markdown.go:21`) the rebuild stores:
- `Tags` — all `#tags` found in the content
- `Property` (`MemoPayload_Property`, `proto/gen/store/memo.pb.go:85`): `HasLink`, `HasTaskList`, `HasCode`, `HasIncompleteTasks` (booleans derived from the markdown AST), and `Title` — the text of the first H1 heading, if any.

(`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property` — `server/runner/memopayload/runner.go:85-86`.)
