Distinct server surfaces that enforce memo visibility:

- **gRPC API v1 — read-access gate `checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:38` (used by GetMemo etc.; public passes, protected requires any authenticated user, private requires the creator). List queries enforce it at the query level via `VisibilityList` filters — `server/router/api/v1/memo_service.go:219,225`. Related sub-resources repeat the same check inline: comments `memo_service_comments.go:41`, reactions `reaction_service.go:38,83`, attachments `attachment_service.go:451` and `memo_attachment_service.go:222`, mention notifications `memo_mention_helpers.go:62-84`.
- **File server (attachment/binary downloads) — `checkAttachmentPermission`** — `server/router/fileserver/fileserver.go:650` (visibility comparison at line 699: private blocks non-creator/non-admin; also honors a per-memo `share_token` fallback at ~line 683).
- **SSE event stream — `SSEClient.canReceive`** — `server/router/api/v1/sse_hub.go:134` (private events are delivered only to the creator or an admin; public/protected go to all connected clients).
- **RSS feeds — query-level restriction to public memos only** — `server/router/rss/rss.go:90,141` (`VisibilityList: []store.Visibility{store.Public}`).
- **Notification email rendering — `canViewerAccessMemo`** — `server/notification/email.go:306` (with a private-memo content-redaction check at line 313), so email recipients don't receive memo content they couldn't view.
