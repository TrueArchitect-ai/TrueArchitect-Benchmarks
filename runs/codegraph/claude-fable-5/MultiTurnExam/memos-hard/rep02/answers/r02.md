**Premise correction: there is no per-user API rate-limiting middleware in this codebase, and therefore no request limits to report.** A repo-wide search for rate-limit/throttle/limiter terms across the backend finds only a documentation aspiration — a comment in `internal/email/doc.go:86` listing "Rate limit email sending" as a security consideration, with no implementation.

What is actually registered, for contrast:

- Echo HTTP middleware: only `Recover()` and a CORS middleware — `server/server.go:51-52`.
- Connect/gRPC interceptors: metadata conversion, logging, recovery, and authentication (`NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor`) — `server/router/api/v1/v1.go:133-137`. None of these count or limit requests per user.

The closest things to throttling that do exist are resource-concurrency caps, not rate limits: request-size limits (`connect.WithReadMaxBytes(maxAPIRequestBytes)`, `server/router/api/v1/v1.go:141`), semaphores bounding concurrent thumbnail (3) and image processing (2) work (`server/router/api/v1/v1.go:59-60`), and the bounded webhook dispatch queue (`internal/webhook/webhook.go:39`).
