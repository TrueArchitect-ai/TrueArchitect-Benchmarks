**Premise correction: neither — there is no message broker at all. No NATS, RabbitMQ, or any external queue appears anywhere in the codebase** (no such imports exist in `go.mod` or any Go file).

Actual mechanism: webhook delivery is entirely in-process. The "queue" is a buffered Go channel, `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared at `internal/webhook/webhook.go:39`. The package's `init` function (`webhook.go:42-55`) starts four worker goroutines that range over the channel and call `Post` (`webhook.go:120`) for each payload. Producers enqueue via `PostAsync` (`webhook.go:184`), which does a non-blocking send — if the 128-slot buffer is full, the dispatch is **dropped** with a warning log rather than persisted or retried. So delivery is best-effort and memory-only: nothing survives a process restart, which is the practical difference from a broker-backed design.
