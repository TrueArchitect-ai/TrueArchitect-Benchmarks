**Delivery function: `Post` — `internal/webhook/webhook.go:120`; protection mechanism: dial-time reserved-IP blocking via `safeDialContext`/`isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

Details:

- **Where delivery executes:** `webhook.Post` (`internal/webhook/webhook.go:120`) builds and sends the HTTP POST (with optional Standard Webhooks HMAC signing) through the shared `safeClient`. Dispatches are usually enqueued via `PostAsync` (`webhook.go:184`) and drained by four background workers started in the package `init` (`webhook.go:42`), which call `Post`. The API layer feeds these from `server/router/api/v1/memo_service_webhooks.go` (e.g. `dispatchMemoRelatedWebhook`).
- **SSRF protection:** Two layers, both in `internal/webhook`:
  1. `safeClient`'s transport uses `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the target host at dial time and refuses any address in a reserved/private range — this also defeats DNS-rebinding, since the check happens on the actual connection, not just at registration.
  2. The blocklist itself lives in `internal/webhook/validate.go`: `reservedCIDRs`/`isReservedIP` (`validate.go:14,44`) covers loopback, RFC-1918, link-local (including the cloud metadata address 169.254.169.254), and IPv6 equivalents. `ValidateURL` (`validate.go:62`) applies the same check when a webhook is created/updated (called from `server/router/api/v1/user_service_webhooks.go`), and the `AllowPrivateIPs` flag (`validate.go:41`) can disable the protection for self-hosted deployments.
