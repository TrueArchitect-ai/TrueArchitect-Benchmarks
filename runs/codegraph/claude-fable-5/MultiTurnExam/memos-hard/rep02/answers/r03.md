**Premise correction: there is no nightly database-cleanup job — nothing in this codebase schedules database cleanup at any time of day.**

What I checked:

- The repo does contain a cron-scheduler package, `internal/scheduler/` (`scheduler.go`, `parser.go`, `job.go`, with cron-expression parsing), but **no production code uses it**: grepping for `scheduler.` across `server/`, `cmd/`, and `store/` finds zero references outside the package's own files and tests. It's an unused library.
- The only recurring background job in the server is the S3 presigned-URL refresh runner, which runs on a simple 12-hour `time.Ticker`, not a cron schedule (`server/runner/s3presign/runner.go:27`, wired in `server/server.go:162-169`).
- The only "cleanup" that runs periodically is the in-memory cache's expired-entry sweep every 5 minutes (`store/cache/cache.go:83`, interval from `store/store.go:42`) — in-process memory, not the database.
- Database-side deletions (e.g. of a user's memos, reactions, attachments) happen synchronously inside request handling (`store/db/*/user_delete.go`, `server/router/api/v1/memo_service.go:579`), not as a scheduled job.
