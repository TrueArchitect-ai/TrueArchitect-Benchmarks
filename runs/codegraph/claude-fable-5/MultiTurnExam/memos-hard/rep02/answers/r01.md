**Premise correction: there is no Redis in this codebase — the cache layer is a purely in-process, in-memory cache.** A repo-wide case-insensitive grep for "redis" over all Go files returns nothing; no Redis client dependency or connection configuration exists.

Actual mechanism: the cache is a thread-safe in-memory implementation built on `sync.Map` — `Cache` in `store/cache/cache.go` (struct at line ~66, with TTL, periodic cleanup, and max-item eviction). The store constructs three separate instances of it in `Store.New` (`store/store.go:38-53`): `instanceSettingCache`, `userCache`, and `userSettingCache`.

TTL for user entries: user objects are cached via `s.userCache.Set(...)` (e.g. in `Store.ListUsers`, `store/user.go:143`), and `Set` applies the cache's `DefaultTTL`. The config built in `store/store.go:40-45` sets **`DefaultTTL: 10 * time.Minute`** (with a 5-minute cleanup interval and a 1000-item cap — the same defaults as `cache.DefaultConfig()` in `store/cache/cache.go`). So user entries live for 10 minutes in process memory, not in any external store.
