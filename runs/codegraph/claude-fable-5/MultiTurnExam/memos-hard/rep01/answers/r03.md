**Premise correction: there is no nightly database-cleanup job, and the cron scheduler isn't even wired into the server.**

Two parts to this:

1. **No database-cleanup job exists.** Searching the backend for cleanup/vacuum/purge-style jobs finds nothing scheduled against the database. The only background jobs the server starts are in `Server.startBackgroundRunners` (`server/server.go:153-174`), and the only one registered there is the S3 presign refresher (`server/runner/s3presign/runner.go`), which runs on a simple 12-hour `time.Ticker` — not a cron schedule, and not a cleanup task.

2. **The cron scheduler package is dead code.** The repo does contain a cron scheduler (`internal/scheduler/scheduler.go`, with a cron-expression parser in `internal/scheduler/parser.go` and job definitions in `internal/scheduler/job.go`), but no production code imports it — a repo-wide grep for imports of `internal/scheduler` outside the package itself returns nothing; it's exercised only by its own tests (`internal/scheduler/*_test.go`).

The only periodic "cleanup" that happens at all is in-process cache expiry sweeps every 5 minutes inside the in-memory cache (`CleanupInterval` in `store/store.go:42`, implemented in `store/cache/cache.go`) — which touches cached entries, not the database.
