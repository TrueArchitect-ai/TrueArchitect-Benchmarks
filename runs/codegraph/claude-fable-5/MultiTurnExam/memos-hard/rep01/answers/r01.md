**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide grep for "redis" across all Go files and `go.mod` returns nothing — no Redis client dependency, no connection configuration, no external cache service at all.

**Actual mechanism:** The cache layer is a purely in-memory, in-process cache implemented in `store/cache/cache.go` — a thread-safe `Cache` struct built on `sync.Map` with per-entry TTL, periodic cleanup, and a max-item cap (`Cache` at `store/cache/cache.go:66`, config at `store/cache/cache.go:41-54`).

The user cache is constructed in `store.New` at `store/store.go:38-53`: three caches (`instanceSettingCache`, `userCache`, `userSettingCache`) are created with a shared `cache.Config` of:

- **`DefaultTTL: 10 * time.Minute`** — this is the TTL that applies to user entries, since all user writes go through `Set` (which uses the default TTL), e.g. `s.userCache.Set(...)` in `store/user.go:98,122,132,143,167`
- `CleanupInterval: 5 * time.Minute` (background sweep of expired items)
- `MaxItems: 1000`

So: user entries live in an in-process memory cache with a 10-minute TTL, configured at `store/store.go:41` — nothing is externalized to Redis, and the cache dies with the process (goroutines are stopped via `Store.Close` → `userCache.Close()` at `store/store.go:75`).
