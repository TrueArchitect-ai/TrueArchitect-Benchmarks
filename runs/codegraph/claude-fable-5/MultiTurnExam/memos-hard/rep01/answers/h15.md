Distinct memo-visibility enforcement sites in the server:

1. **gRPC/API read-access gate `checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:39` (public → anonymous allowed only if `AllowAnonymous`; protected → any authenticated user; private → creator or admin). Applied in `GetMemo` (`memo_service.go:356,367`) and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`).

2. **List-query visibility filtering in `ListMemos`** — `server/router/api/v1/memo_service.go:219-225`: anonymous callers get `VisibilityList = [Public]`; authenticated non-owners get `[Public, Protected]` plus a CEL filter `creator_id == X || visibility in ["PUBLIC","PROTECTED"]`, pushed down into the SQL WHERE clause by the drivers (e.g., `store/db/sqlite/memo.go:96-102`).

3. **Inline checks on adjacent APIs** — reactions: `server/router/api/v1/reaction_service.go:30,38,83`; comments: `server/router/api/v1/memo_service_comments.go:41`; attachments listing: `server/router/api/v1/attachment_service.go:445-451` and `server/router/api/v1/memo_attachment_service.go:214-222` (all deny private memos to non-creator/non-admin).

4. **HTTP file server attachment permission check** — `server/router/fileserver/fileserver.go:677-699`: serving an attachment's binary re-checks the owning memo's visibility (public + anonymous-allowed serves; private restricted to creator/admin).

5. **RSS feeds** — `server/router/rss/rss.go:90,141`: feeds query only `VisibilityList: [store.Public]`.

6. **SSE event delivery filter `SSEClient.canReceive`** — `server/router/api/v1/sse_hub.go:134-144`: private memo events are delivered only to the creator or an admin; unknown visibility is denied.

7. **Notification/email side** — mention notifications and email digests skip private memos the target can't see: `server/router/api/v1/memo_mention_helpers.go:62-84` and `server/notification/email.go:313`.
