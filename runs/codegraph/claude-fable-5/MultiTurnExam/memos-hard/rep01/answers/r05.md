**Premise correction: there is no GraphQL API in this repository** — no GraphQL schema files, no GraphQL library in `go.mod`, and no reference to GraphQL anywhere in the backend or frontend source.

**Actual API surface:** The public API is a **gRPC/Protobuf-defined API exposed over HTTP** in several forms:

- **Schema source of truth:** Protobuf service definitions under `proto/api/v1/` — `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus `common.proto` (generated Go code lives in `proto/gen/api/v1/`).
- **Transports:** the services are served via Connect handlers (supporting Connect, gRPC, and gRPC-Web protocols; registered with interceptors in `server/router/api/v1/v1.go:133-141`) and as a RESTful JSON API via gRPC-Gateway under `/api/v1/...` (generated gateways like `proto/gen/api/v1/user_service.pb.gw.go`, wired in `RegisterGateway` from `server/server.go:88`).
- **Additional HTTP surfaces:** a native file-serving API (`server/router/fileserver/fileserver.go` — `/file/attachments/...`, `/file/users/.../avatar`), RSS feeds (`server/router/rss/rss.go`), an SSE event stream (`server/router/api/v1/sse_*.go`), and an MCP endpoint at `/mcp` driven by the embedded OpenAPI spec (`server/router/mcp/service.go`).

So an integrator consumes the API via REST/JSON, gRPC, or Connect against the proto-defined services — not via GraphQL queries.
