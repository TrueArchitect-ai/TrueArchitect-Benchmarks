**Delivery function: `Post` — `internal/webhook/webhook.go:120`; protection mechanism: dial-time SSRF guard `safeDialContext` (using `isReservedIP` in `internal/webhook/validate.go:44`) — `internal/webhook/webhook.go:59`**

How it works:

- Outbound delivery executes in `webhook.Post` (`internal/webhook/webhook.go:120`), which marshals the payload, optionally adds Standard-Webhooks HMAC signature headers, and sends the POST via the shared `safeClient`. Async dispatches go through `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded channel drained by four worker goroutines that each call `Post`.
- The SSRF protection lives in the HTTP client's transport: `safeClient` is built with `DialContext: safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the target hostname at dial time and refuses the connection if any resolved address falls in a reserved/private range — checked by `isReservedIP` against the CIDR list in `internal/webhook/validate.go:14-23` (loopback, RFC-1918, link-local/cloud IMDS, and IPv6 equivalents). Enforcing this at dial time also defeats DNS-rebinding attacks, since the check applies to the addresses actually being connected to.
- There's a complementary registration-time check: `ValidateURL` (`internal/webhook/validate.go:62`) rejects webhook URLs that resolve to reserved IPs when webhooks are created/updated (called from `server/router/api/v1/user_service_webhooks.go`), but the dial-time guard is what protects the actual delivery. An escape hatch `AllowPrivateIPs` (`internal/webhook/validate.go:41`) can disable the check for self-hosted deployments.
