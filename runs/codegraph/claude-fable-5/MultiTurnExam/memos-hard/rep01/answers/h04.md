**No.** Outside the driver-selection factory, the MySQL driver is never constructed directly.

Evidence:

- The MySQL driver's only constructor is `mysql.NewDB` in `store/db/mysql/mysql.go:20`, and a repo-wide grep for its call sites finds exactly one: the factory switch in `NewDBDriver` at `store/db/db.go:22` (`case "mysql": driver, err = mysql.NewDB(profile)`).
- A broader grep for any reference to the `store/db/mysql` package outside its own directory turns up only the factory's import and call in `store/db/db.go:8` and `store/db/db.go:22`. Every other match is either inside the `store/db/mysql` package itself, or refers to unrelated things named "mysql": the third-party `github.com/go-sql-driver/mysql` library (used inside the driver package and in `store/test/containers.go` for DSN parsing), the testcontainers `mysql` module that spins up a MySQL container for tests (`store/test/containers.go`), and MySQL SQL-dialect strings in `internal/filter`.
- By contrast, tests that need a concrete driver either go through the factory (`db.NewDBDriver` in `store/test/store.go:28,50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70`) or construct the SQLite driver directly (`sqlite.NewDB` in `store/deployment_config_test.go:416` and `store/demo_seed_test.go:24`) — no test or production code calls `mysql.NewDB` directly.
