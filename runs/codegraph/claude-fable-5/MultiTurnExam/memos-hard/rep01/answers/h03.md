**Abstraction package: `internal/idp`; implementation package: `internal/idp/oauth2`**

- `internal/idp` (`internal/idp/idp.go`) defines the provider-neutral abstraction — the `IdentityProviderUserInfo` struct (identifier, display name, email, avatar URL) that any provider implementation must produce.
- The one concrete protocol implementation that ships is OAuth2, in `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`). Its `IdentityProvider` type wraps a `storepb.OAuth2Config` and implements the flow: `ExchangeToken` (authorization-code exchange, with optional PKCE) and `UserInfo` (fetches the userinfo endpoint and maps claims into `idp.IdentityProviderUserInfo` via the configured field mapping).

The SSO sign-in path consumes it in `server/router/api/v1/auth_service_sso.go`, which constructs the provider with `oauth2.NewIdentityProvider(...)`. There is no other protocol implementation (e.g., no SAML/LDAP package) under `internal/idp` — `oauth2` is the only subpackage.
