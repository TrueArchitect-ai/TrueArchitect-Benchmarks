**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`. It calls `markdownService.ExtractAll` (the goldmark-based single-pass extractor in `internal/markdown/markdown.go`, ~line 355+) and writes the results into `memo.Payload.Tags` and `memo.Payload.Property`, which are persisted in the memo row's JSON `payload` column.

**Triggers (production call sites):**

- **Memo creation** — `APIV1Service.CreateMemo` at `server/router/api/v1/memo_service.go:108`, before the row is inserted. This also covers **comment creation**, since `CreateMemoComment` delegates to `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
- **Content update** — `APIV1Service.UpdateMemo` at `server/router/api/v1/memo_service.go:447`, when the update mask includes the `content` path; the recomputed payload is saved alongside the new content.
- There is also a batch rebuild-everything runner (`memopayload.Runner.RunOnce`, `server/runner/memopayload/runner.go:27`) that would recompute payloads for all memos, but it is never invoked in production code.

**What the computation extracts** (from `ExtractedData` at `internal/markdown/markdown.go:21` and the walk at `:355-420`):

- **Tags** — every `#tag` node, deduplicated case-preservingly.
- **Mentions** — every `@username`, lowercased and deduplicated (used for mention notifications rather than stored in the payload).
- **Property** (`storepb.MemoPayload_Property`), the list/preview metadata:
  - `Title` — text of an H1 heading when it's the document's first block (`:387`)
  - `HasLink` — any markdown link (`:394`)
  - `HasCode` — code block, fenced code block, or code span (`:397`)
  - `HasTaskList` — any task checkbox (`:400`)
  - `HasIncompleteTasks` — at least one unchecked checkbox (`:403`)

These properties are what the CEL filter schema exposes for list queries (`has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, `tags` in `internal/filter/schema.go`).
