**Premise correction: neither.** There is no message broker in this codebase — no NATS, no RabbitMQ, no AMQP client, and no such dependency in `go.mod`. Webhook delivery never leaves the server process.

**Actual mechanism:** the "queue" is a plain in-memory buffered Go channel, declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The "workers" are four goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`); each ranges over the channel and calls `Post` (`internal/webhook/webhook.go:120`) to make the outbound HTTP request. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`) with a non-blocking `select` — if the 128-slot buffer is full, the dispatch is **dropped** with a warning log rather than queued durably. So there is no persistence, no redelivery, and no broker: a webhook that fails or is dropped is simply lost (only a `slog.Warn` records it).
