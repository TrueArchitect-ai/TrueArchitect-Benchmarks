**Premise correction:** there is no Redis anywhere in this codebase. A repo-wide search for "redis" in Go sources returns zero hits, and there is no Redis client dependency. The cache layer is a purely **in-process, in-memory cache**.

**Actual mechanism:** the cache is the hand-rolled `Cache` type in `store/cache/cache.go` — a `sync.Map`-backed, thread-safe store with per-entry TTL, periodic cleanup, and a max-item cap (`Cache` struct at `store/cache/cache.go:66`, `New` at `:75`). The store layer creates three instances of it in `store.New` (`store/store.go:38-53`): `instanceSettingCache`, `userCache`, and `userSettingCache`.

**TTL for user entries:** 10 minutes. `store.New` builds the config with `DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000` (`store/store.go:40-45`, matching `DefaultConfig()` in `store/cache/cache.go:56-63`), and user entries are written with `Set` (e.g. `s.userCache.Set(...)` in `store/user.go:98,122,132,143,167`), which applies that default TTL. A background goroutine sweeps expired entries every 5 minutes, and the caches are torn down via `Cache.Close` when the store shuts down (`store/store.go:72-79`).
