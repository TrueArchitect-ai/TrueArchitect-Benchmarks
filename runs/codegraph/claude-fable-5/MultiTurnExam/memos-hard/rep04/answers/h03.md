**Abstraction package:** `internal/idp` — `internal/idp/idp.go` defines the provider-neutral abstraction, the `IdentityProviderUserInfo` struct (identifier, display name, email, avatar URL) that any provider implementation must produce.

**Implementation package:** `internal/idp/oauth2` — `internal/idp/oauth2/oauth2.go` is the one concrete protocol implementation that ships: an OAuth2 `IdentityProvider` built from a `storepb.OAuth2Config`, with `ExchangeToken` (authorization-code exchange, including PKCE support) and `UserInfo` (fetches the userinfo endpoint and maps claims into `idp.IdentityProviderUserInfo` via the configured field mapping).

The server consumes it in the SSO sign-in flow at `server/router/api/v1/auth_service_sso.go`, and OAuth2 is likewise the only provider type exposed in the admin UI (`IdentityProvider_Type.OAUTH2` in `web/src/components/CreateIdentityProviderDialog.tsx`).
