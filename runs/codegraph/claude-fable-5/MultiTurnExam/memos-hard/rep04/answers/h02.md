**Delivery function:** `webhook.Post` — `internal/webhook/webhook.go:120`. This is where the outbound HTTP POST actually executes (via the shared `safeClient` at `internal/webhook/webhook.go:152`). Memo create/update/delete/comment events reach it through `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded channel drained by four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`); the dispatch call sites are in `server/router/api/v1/memo_service_webhooks.go`.

**Protection mechanism:** SSRF guarding at dial time via `safeDialContext` — `internal/webhook/webhook.go:59`. The `safeClient`'s `http.Transport` uses this custom `DialContext`, which resolves the target hostname and refuses the connection if any resolved IP falls in a reserved/private range (checked by `isReservedIP` against loopback, RFC-1918, link-local/IMDS, and IPv6 equivalents in `internal/webhook/validate.go:14-54`). Because the check happens at connection time rather than only at configuration time, it also defeats DNS-rebinding attacks. There is additionally a first line of defense at webhook registration: `ValidateURL` (`internal/webhook/validate.go:62`) rejects URLs that resolve to reserved IPs when a webhook is created or updated (`server/router/api/v1/user_service_webhooks.go`). The escape hatch `AllowPrivateIPs` (`internal/webhook/validate.go:41`) can disable the check for self-hosted deployments.
