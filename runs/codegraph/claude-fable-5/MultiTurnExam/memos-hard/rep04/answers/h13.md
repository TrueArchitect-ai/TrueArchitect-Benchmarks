**Interface:** `markdown.Service` — `internal/markdown/markdown.go:31` (ExtractAll, RenderHTML, GenerateSnippet, RenameTag, etc.).

**Concrete implementation that executes at runtime:** the unexported `service` struct wrapping a goldmark instance — `internal/markdown/markdown.go:58` (`type service struct { md goldmark.Markdown }`). It is the only implementation of the interface in the codebase.

**Construction:** the factory `markdown.NewService(opts...)` (`internal/markdown/markdown.go:85`) builds the goldmark pipeline (GFM plus optional tag/mention extensions). In production it is called in exactly one place: `NewAPIV1Service` at `server/router/api/v1/v1.go:48`, with `WithTagExtension()` and `WithMentionExtension()` enabled. (The test helper `server/router/api/v1/test/test_helper.go:44` constructs another one for tests.)

**Holders of the interface:**

- `APIV1Service.MarkdownService` — `server/router/api/v1/v1.go:35` (used for memo payload rebuilds, snippets, tag renames across the API handlers).
- `RSSService.MarkdownService` — `server/router/rss/rss.go:45`; it doesn't construct its own — `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService`, so both share the single instance.
- `memopayload.Runner.MarkdownService` — `server/runner/memopayload/runner.go:16`; note this holder is never instantiated in production (`memopayload.NewRunner` has no production callers). The package's standalone `RebuildMemoPayload` function instead receives the service as a parameter (`server/runner/memopayload/runner.go:74`), called from `server/router/api/v1/memo_service.go` with the API service's instance.

So at runtime there is one goldmark-backed `service` instance, created once in `NewAPIV1Service` and shared by the API v1 handlers and the RSS router.
