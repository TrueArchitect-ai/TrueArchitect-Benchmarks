The following RPC handler methods can transitively cause an outbound HTTP request to a user-configured URL:

**Webhook path** (user configures a webhook URL via `CreateUserWebhook`; these handlers POST to it):
1. **`CreateMemo`** (`server/router/api/v1/memo_service.go:157`) — calls `DispatchMemoCreatedWebhook`
2. **`UpdateMemo`** (via `server/router/api/v1/memo_update_helpers.go:67`) — calls `DispatchMemoUpdatedWebhook`
3. **`DeleteMemo`** (`server/router/api/v1/memo_service.go:562`) — calls `DispatchMemoDeletedWebhook`
4. **`CreateMemoComment`** (`server/router/api/v1/memo_service_comments.go:119`) — calls `DispatchMemoCommentCreatedWebhook`

**Link metadata path** (user supplies an arbitrary URL to fetch):
5. **`GetLinkMetadata`** (`server/router/api/v1/memo_service_link_metadata.go:14`) — calls `getLinkMetadata` → `fetchHTMLMeta`
6. **`BatchGetLinkMetadata`** (`server/router/api/v1/memo_service_link_metadata.go:19`) — calls `getLinkMetadata` → `fetchHTMLMeta`

All four webhook-dispatching handlers converge through a single function before delivery: **`webhook.Post`** (`internal/webhook/webhook.go:120`). The three named dispatch helpers (`DispatchMemoCreatedWebhook`, `DispatchMemoUpdatedWebhook`, `DispatchMemoDeletedWebhook`) call `dispatchMemoRelatedWebhook` which calls `webhook.PostAsync`, and `DispatchMemoCommentCreatedWebhook` also calls `webhook.PostAsync`. `PostAsync` enqueues onto `asyncPostQueue`, which is consumed by goroutines that call `Post`. So `webhook.Post` at `internal/webhook/webhook.go:120` is the single convergence function where all webhook delivery paths meet before the outbound HTTP request is made.

**Handlers (≥3): `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`; convergence function: `webhook.Post`** (`internal/webhook/webhook.go:120`)
