Memo visibility is enforced at these distinct server-side sites:

1. `checkMemoReadAccess` (GetMemo / general memo read guard) — `server/router/api/v1/memo_service.go:39`
2. `ListMemos` visibility filter (query-time row filtering) — `server/router/api/v1/memo_service.go:218–227`
3. `ListMemoComments` visibility filter (comment listing) — `server/router/api/v1/memo_service_comments.go:33–42` (and comment-list query filter at line 158)
4. `ListMemoReactions` / `UpsertMemoReaction` visibility checks — `server/router/api/v1/reaction_service.go:29–41, 82–85`
5. `checkAttachmentAccess` (attachment download gated by linked memo visibility) — `server/router/api/v1/attachment_service.go:422–455`
6. `ListMemoAttachments` visibility check — `server/router/api/v1/memo_attachment_service.go:213–224`
7. SSE `canReceive` (real-time event delivery filtering) — `server/router/api/v1/sse_hub.go:134–144`
8. `canViewerAccessMemo` in notification service (filters notifications by memo visibility) — `server/router/api/v1/user_service_notifications.go:302–316`
9. `canViewerAccessMemo` in email notification (same logic, separate copy) — `server/notification/email.go:306–320`
10. `ListAllUserStats` visibility filter — `server/router/api/v1/user_service_stats.go:84–91`
11. Fileserver attachment access (memo visibility + share-token fallback) — `server/router/fileserver/fileserver.go:677–689`
12. Frontend sitemap (only public memos) — `server/router/frontend/frontend.go:149–151`
13. `buildMemoFindFilterByVisibility` in memo-service converter (shared filter for comment/relation queries) — `server/router/api/v1/memo_service_converter.go:183–187`
