The premise is incorrect — there are no message-broker-based webhook delivery workers. The codebase uses neither NATS nor RabbitMQ.

**Actual mechanism:** Webhooks are delivered via a simple in-process buffered Go channel + goroutine worker pool. The "queue" is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

At `init()` time (lines 42–55), 4 goroutines are spawned to consume from this channel. Each goroutine calls `Post()`, which makes a direct outbound HTTP POST to the webhook URL using a shared `http.Client`. Callers enqueue payloads via `PostAsync()` (line 184), which does a non-blocking send into the channel (dropping the payload with a warning if the buffer is full). There is no external message broker involved anywhere in the project.
