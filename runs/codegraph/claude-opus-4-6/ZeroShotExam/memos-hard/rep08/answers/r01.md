The premise is incorrect — this repository does not use Redis for caching. Based on the codebase, the cache layer uses an **in-memory Go struct**, not Redis.

The caching mechanism is defined in `server/router/rss/rss.go`. The `cacheEntry` struct (line 35) holds cached data with a `createdAt` timestamp, and the TTL is determined by the constant `maxCacheAge`, which is set to **5 minutes** (`5 * time.Minute`). Cache validity is checked by comparing `time.Since(entry.createdAt)` against `maxCacheAge`. This applies uniformly to all RSS cache entries (both explore and user feeds) — there is no separate TTL specifically for "user entries" versus other entry types.
