The premise is incorrect: this repository does not use Redis at all. There is no Redis connection, client, or dependency anywhere in the codebase.

The cache layer is a **custom in-memory cache** implemented in `store/cache/cache.go`. It is a thread-safe Go struct (`Cache`) backed by a `sync.Map` with TTL-based expiration and a background cleanup goroutine — no external cache service is involved.

**User entries** (user settings specifically) are cached via `s.userSettingCache`, which is a `*cache.Cache` instance created in `store/store.go:51` with the default `cache.Config`. The **TTL for all cache entries, including user settings, is 10 minutes** (`DefaultTTL: 10 * time.Minute`), set at `store/store.go:41` and echoed in `store/cache/cache.go:59`. The cache also enforces a max of 1000 items and runs cleanup every 5 minutes.

There is a separate RSS feed cache in `server/router/rss/rss.go` (a plain `map[string]*cacheEntry` with a 1-hour duration), but that is unrelated to user data and also not Redis-backed.
