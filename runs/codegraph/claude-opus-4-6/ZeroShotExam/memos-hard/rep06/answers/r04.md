The premise is incorrect — there are no "webhook delivery workers" consuming from NATS or RabbitMQ. This project uses neither message broker.

The actual mechanism is a **buffered Go channel** acting as an in-process async queue. In `internal/webhook/webhook.go:39`, a channel is declared:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in an `init()` function (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post()` to deliver each webhook via a direct HTTP POST. The `PostAsync` function (`internal/webhook/webhook.go:184-196`) enqueues payloads into this channel with a non-blocking send, dropping the payload if the buffer is full.

There is no external queue or broker — webhooks are dispatched in-process through a simple fan-out of 4 goroutines reading from a buffered channel of capacity 128.
