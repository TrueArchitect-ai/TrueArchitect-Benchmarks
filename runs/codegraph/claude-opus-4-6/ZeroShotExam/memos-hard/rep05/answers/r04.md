The premise is incorrect — there are no message broker consumers (neither NATS nor RabbitMQ) for webhook delivery. Webhooks are delivered synchronously via direct HTTP POST calls, not through a queue-based worker system.

The webhook delivery mechanism is implemented in `internal/webhook/webhook.go`. The function `Post` (around line 79) takes a `WebhookRequestPayload`, serializes it to JSON, signs it with HMAC-SHA256 if a secret is configured, and makes a direct `http.DefaultClient.Do()` call to the webhook URL. This is invoked inline — there is no queue declaration, no broker connection, and no asynchronous worker consuming from a message bus.
