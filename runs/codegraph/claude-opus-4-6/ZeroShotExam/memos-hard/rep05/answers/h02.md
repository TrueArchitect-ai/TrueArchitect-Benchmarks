**Delivery function** — `Post` in `internal/webhook/webhook.go` (line 120). It serializes the payload to JSON and sends an HTTP POST to the configured webhook URL using `safeClient`. Asynchronous dispatch goes through `PostAsync` (line 184), which enqueues onto `asyncPostQueue`; background goroutines (started in `init`, line 42) drain the queue by calling `Post`.

**Protection mechanism** — SSRF protection is implemented in two layers, both in the `internal/webhook/` package:

1. **At dial time** — `safeDialContext` (`internal/webhook/webhook.go:59`): The `safeClient` HTTP client uses a custom `DialContext` that resolves the target hostname and calls `isReservedIP` on every resolved address before connecting. This defeats DNS rebinding because the check happens at connection time, not just at URL registration.

2. **At URL registration time** — `ValidateURL` (`internal/webhook/validate.go:62`): When a webhook is created or updated, this function resolves the hostname and rejects any URL whose IP falls in a reserved range.

Both rely on `isReservedIP` (`internal/webhook/validate.go:44`), which checks resolved IPs against `reservedCIDRs` (`internal/webhook/validate.go:14`) — a blocklist covering IPv4 loopback, RFC-1918 private ranges, link-local (including cloud IMDS at 169.254.0.0/16), IPv6 loopback, unique-local, and link-local ranges.
