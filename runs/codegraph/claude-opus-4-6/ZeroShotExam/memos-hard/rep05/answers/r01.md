The premise is incorrect: this repository does not use Redis at all. There is no Redis connection, client, or dependency anywhere in the codebase.

The cache layer is a **custom in-memory Go cache** implemented in `store/cache/cache.go`. It uses a `sync.Map` for thread-safe storage with TTL-based expiration and a background cleanup goroutine — no external cache service is involved.

**User entries** (user settings, users, instance settings) are cached via three `*cache.Cache` instances created in `store/store.go:38-61`:

- `userCache`
- `userSettingCache`
- `instanceSettingCache`

All three are initialized with the same `cache.Config` (`store/store.go:40-45`), which sets `DefaultTTL` to **10 minutes**. This is also the value returned by `cache.DefaultConfig()` at `store/cache/cache.go:57-64`. When `userSettingCache.Set()` is called (e.g., `store/user_setting.go:59`), it delegates to `Cache.Set()` (`store/cache/cache.go:93`), which applies the configured `DefaultTTL` of 10 minutes.

Separately, the RSS feed layer in `server/router/rss/rss.go` has its own independent in-memory cache (a plain `map[string]*cacheEntry` with a mutex) using a **1-hour** TTL (`defaultCacheDuration` at line 25), but this is unrelated to user entries.

The database backends are SQLite, MySQL, and PostgreSQL — accessed via `database/sql` — with no Redis anywhere in the dependency tree.
