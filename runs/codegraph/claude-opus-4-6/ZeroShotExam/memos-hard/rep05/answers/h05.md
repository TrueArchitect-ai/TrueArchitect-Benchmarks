Emoji reactions are removed by **explicit Go code**, via two dedicated deletion functions called within the user-deletion transaction. No database-level cascading rules are relied upon.

The `deleteUserTargetsTx` function (e.g., `store/db/mysql/user_delete.go:92`) calls two reaction-cleanup steps in sequence:

1. **`deleteReactionsByContentIDsTx`** — deletes all reactions on the user's memos (by content ID). This removes reactions left by *any* user on content owned by the deleted user.
   - `store/db/mysql/user_delete.go:96`, `:420` (`DELETE FROM reaction WHERE content_id IN ...`)
   - `store/db/postgres/user_delete.go:383`
   - `store/db/sqlite/user_delete.go:383`

2. **`deleteReactionsByCreatorTx`** — deletes all reactions *created by* the deleted user (on anyone else's content).
   - `store/db/mysql/user_delete.go:102`, `:438` (`DELETE FROM reaction WHERE creator_id = ?`)
   - `store/db/postgres/user_delete.go:401`
   - `store/db/sqlite/user_delete.go:401`

Both are executed inside the same transaction before memo and user row deletion, across all three database drivers (MySQL, PostgreSQL, SQLite).
