Memo visibility is enforced at the following distinct server surfaces:

1. **GetMemo (single memo fetch)** — `server/router/api/v1/memo_service.go` (lines 55–63: checks `memo.Visibility` against the requesting user, denying PRIVATE memos to non-owners)
2. **ListMemos (memo listing filter)** — `server/router/api/v1/memo_service.go` (lines 219–225: restricts `VisibilityList` and appends visibility filter based on caller identity)
3. **CreateMemoComment / ListMemoComments** — `server/router/api/v1/memo_service_comments.go` (line 41: blocks commenting on PRIVATE memos by non-owners; lines 158–160: filters visible memos when listing comments)
4. **ListMemoReactions / UpsertMemoReaction** — `server/router/api/v1/reaction_service.go` (lines 29–38 and 82–84: checks memo visibility before allowing reaction listing or creation)
5. **Attachment service (checkAttachmentAccess)** — `server/router/api/v1/attachment_service.go` (lines 436–452: enforces linked memo visibility when accessing attachments via gRPC)
6. **SSE hub (canReceive)** — `server/router/api/v1/sse_hub.go` (lines 134–141: filters real-time SSE events by memo visibility before delivery to each client)
7. **File server (HTTP attachment serving)** — `server/router/fileserver/fileserver.go` (lines 674–699: enforces memo visibility when serving attachment files over HTTP)
8. **ListMemoRelations** — `server/router/api/v1/memo_relation_service.go` (lines 109–111: applies visibility filter when listing related memos)
9. **Memo reference resolution (converter)** — `server/router/api/v1/memo_service_converter.go` (lines 184–186: applies visibility filter when resolving referenced/related memos in responses)
10. **SetMemoAttachments** — `server/router/api/v1/memo_attachment_service.go` (lines 213–222: checks memo visibility before allowing attachment mutations)
11. **User stats** — `server/router/api/v1/user_service_stats.go` (lines 84–90: filters by visibility when computing another user's memo statistics)
