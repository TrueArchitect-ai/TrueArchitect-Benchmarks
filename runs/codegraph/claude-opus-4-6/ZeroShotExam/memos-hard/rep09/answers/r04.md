The premise is incorrect — there are no message broker consumers (neither NATS nor RabbitMQ) for webhook delivery. Webhooks are delivered synchronously via direct HTTP POST calls, not through any queue-based system.

The webhook delivery mechanism is implemented in `internal/webhook/webhook.go`. The function `Post` (line ~79+) constructs an HTTP request with the `WebhookRequestPayload` and sends it directly using Go's `http.Client`. When a webhook-triggering event occurs (e.g., memo creation/update), the code in `server/router/api/v1/memo_service_webhooks.go` iterates over configured webhooks and calls `webhook.Post()` for each one inline — there is no queue declaration, no broker connection, and no background worker consuming from a message queue.
