**Mechanism: explicit Go code** — reactions are removed by two dedicated SQL `DELETE` statements executed within the user-deletion transaction. There are no database-level `ON DELETE CASCADE` rules involved (no foreign key cascade references were found in the migration files for the `reaction` table).

**Two deletion paths cover all cases:**

1. **`deleteReactionsByContentIDsTx`** — deletes reactions on the user's memos (by `content_id`), called at `store/db/mysql/user_delete.go:96`, `store/db/postgres/user_delete.go:96`, `store/db/sqlite/user_delete.go:96`. The SQL is `DELETE FROM reaction WHERE content_id IN (...)` (e.g., `store/db/mysql/user_delete.go:420`).

2. **`deleteReactionsByCreatorTx`** — deletes reactions the user themselves created on any content (by `creator_id`), called at `store/db/mysql/user_delete.go:102`, `store/db/postgres/user_delete.go:102`, `store/db/sqlite/user_delete.go:102`. The SQL is `DELETE FROM reaction WHERE creator_id = ?` (e.g., `store/db/mysql/user_delete.go:438`).

Both are invoked from `deleteUserTargetsTx` within the same transaction that deletes the user row, across all three database drivers (MySQL, PostgreSQL, SQLite).
