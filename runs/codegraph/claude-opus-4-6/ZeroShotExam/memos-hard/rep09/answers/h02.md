**Delivery function** — `Post` in `internal/webhook/webhook.go:120`. It serializes the payload to JSON, constructs an HTTP POST request to the webhook URL, optionally signs it with HMAC-SHA256, and sends it via `safeClient`. Asynchronous dispatch goes through `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto `asyncPostQueue`; worker goroutines (started in `init()` at line 42) drain the queue by calling `Post`.

**Protection mechanism** — Two-layer SSRF guard, both in `internal/webhook/validate.go` and `internal/webhook/webhook.go`:

1. **At webhook creation/update time**: `ValidateURL` (`internal/webhook/validate.go:62`) resolves the URL's hostname and calls `isReservedIP` (`internal/webhook/validate.go:44`) against a list of reserved CIDRs (`reservedCIDRs`, `internal/webhook/validate.go:14`) covering loopback, RFC-1918 private ranges, link-local/cloud IMDS (`169.254.0.0/16`), and IPv6 equivalents. URLs resolving to any of these are rejected before the webhook is stored.

2. **At dial time (defeats DNS rebinding)**: The `safeClient` (`internal/webhook/webhook.go:32`) uses a custom transport with `safeDialContext` (`internal/webhook/webhook.go:59`), which re-resolves the hostname at connection time and again checks every resolved IP against `isReservedIP`. This prevents a DNS rebinding attack where a hostname passes validation but later resolves to an internal address when the actual HTTP request is made.
