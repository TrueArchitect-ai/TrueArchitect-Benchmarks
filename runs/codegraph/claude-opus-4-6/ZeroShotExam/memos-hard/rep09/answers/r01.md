The premise is incorrect — this repository does not use Redis at all. There is no Redis connection, client, or dependency anywhere in the codebase.

The cache layer is a **pure in-memory Go implementation** located at `store/cache/cache.go`. It uses a `sync.Map` for thread-safe storage with a background cleanup goroutine — no external services involved.

There is no user-entry-specific TTL. The cache uses a single **default TTL of 10 minutes** for all entries, configured in `DefaultConfig()` (`store/cache/cache.go:59`). Callers can override this per-entry via `SetWithTTL()`, but the default applies uniformly regardless of entry type. The cleanup interval is 5 minutes, and the max item count is 1000 (`store/cache/cache.go:57–63`).
