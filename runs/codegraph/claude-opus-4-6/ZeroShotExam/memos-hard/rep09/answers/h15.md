Memo visibility is enforced at these distinct server-side sites:

1. **GetMemo / checkMemoReadAccess** — `server/router/api/v1/memo_service.go` (line 39–68). Central guard used by `GetMemo`: rejects unauthenticated users for non-public memos; denies access to `PRIVATE` memos unless the caller is the creator.

2. **ListMemos** — `server/router/api/v1/memo_service.go` (line 218–227). Filters the query's `VisibilityList`/filter: anonymous users see only `PUBLIC`; authenticated users viewing another user's memos see only `PUBLIC` + `PROTECTED`; own memos are unfiltered.

3. **CreateMemoComment** — `server/router/api/v1/memo_service_comments.go` (line 41). Before allowing a comment on a memo, checks that a `PRIVATE` memo is only commentable by its creator (or a super-user).

4. **File server (attachment serving)** — `server/router/fileserver/fileserver.go` (lines 677, 699). Serves attachments for `PUBLIC` memos only when the instance allows anonymous access; denies `PRIVATE` memo attachments unless the requester is the creator or admin; also accepts a valid share token as a fallback.

5. **User stats (ListAllUserStats / GetUserStats)** — `server/router/api/v1/user_service_stats.go` (lines 84–91, 218–221). When listing memo statistics for users, applies the same visibility filter: anonymous sees only `PUBLIC`, other authenticated users see `PUBLIC` + `PROTECTED`.

6. **Frontend sitemap** — `server/router/frontend/frontend.go` (line 150). The sitemap endpoint only includes `PUBLIC` memos.

7. **Mention/inbox helpers** — `server/router/api/v1/memo_mention_helpers.go` (lines 62–68, `canUserAccessMentionContext`). Suppresses mention inbox items when the user cannot see a `PRIVATE` memo they were mentioned in.
