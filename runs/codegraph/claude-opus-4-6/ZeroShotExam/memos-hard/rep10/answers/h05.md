Emoji reactions are removed by **explicit Go code**, not by a database-level rule. Two dedicated functions handle this within the user-deletion transaction:

1. **`deleteReactionsByContentIDsTx`** — deletes all reactions on the user's memos (`DELETE FROM reaction WHERE content_id IN ...`), covering reactions by *any* user on content the deleted user owned.
2. **`deleteReactionsByCreatorTx`** — deletes all reactions *created by* the deleted user (`DELETE FROM reaction WHERE creator_id = ?`), covering reactions the user left on other people's memos.

Both are called from `deleteUserTargetsTx`, which orchestrates the full deletion inside a transaction. This logic is duplicated across all three database drivers:

- `store/db/mysql/user_delete.go:96–103` (calls), `:416–421` and `:436–439` (implementations)
- `store/db/postgres/user_delete.go:96–103` (calls), `:380–388` and `:400–403` (implementations)
- `store/db/sqlite/user_delete.go:96–103` (calls), `:380–388` and `:400–403` (implementations)

No foreign-key `ON DELETE CASCADE` or database triggers are involved — the Go code issues explicit `DELETE FROM reaction` SQL statements within the same transaction that removes the user.
