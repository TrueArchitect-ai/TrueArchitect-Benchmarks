The avatar is stored as a base64 data URI in the `avatar_url` column of the `user` table. When a browser requests `/file/users/:identifier/avatar`, the request flows through these hops:

1. `RegisterRoutes` — `server/router/fileserver/fileserver.go:124` (registers `GET /file/users/:identifier/avatar` route)
2. `serveUserAvatar` — `server/router/fileserver/fileserver.go:168` (HTTP handler; extracts the `:identifier` param, checks auth on private instances)
3. `getUserByUsername` — `server/router/fileserver/fileserver.go:715` (resolves the username string to a `store.User`)
4. `Store.GetUser` — `store/user.go:148` (checks the in-memory user cache by ID; if miss, delegates to `ListUsers`)
5. `Store.ListUsers` — `store/user.go:136` (delegates to the DB driver via `s.driver.ListUsers`)
6. `Driver.ListUsers` — `store/driver.go:47` (interface method dispatching to the concrete DB backend)
7. `DB.ListUsers` — `store/db/sqlite/user.go:88` (or `store/db/mysql/user.go:84` or `store/db/postgres/user.go:87`) (executes `SELECT ... avatar_url ... FROM user WHERE username = ?` and scans the `avatar_url` column into `store.User.AvatarURL`)
8. `parseDataURI` — `server/router/fileserver/fileserver.go` (back in `serveUserAvatar`, decodes the `data:<type>;base64,...` value from `user.AvatarURL` into raw bytes and serves them via `c.Blob`)
