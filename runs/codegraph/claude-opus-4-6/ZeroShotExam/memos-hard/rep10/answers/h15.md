Memo visibility is enforced at these distinct server surfaces:

1. **ListMemos (memo listing/search)** — `server/router/api/v1/memo_service.go` — filters by `creator_id == %d || visibility in ["PUBLIC", "PROTECTED"]` for authenticated non-owners, restricts to `PUBLIC` only for anonymous users
2. **ListMemoComments (comment listing)** — `server/router/api/v1/memo_service_comments.go` — same visibility filter pattern when listing comments, plus explicit `Private` check before allowing a new comment (line 41)
3. **ListReactions / UpsertReaction / DeleteReaction** — `server/router/api/v1/reaction_service.go` — checks `memo.Visibility` and denies access to private memos for non-owners (lines 30-39, 82-84)
4. **ListMemoRelations** — `server/router/api/v1/memo_relation_service.go` — applies the same visibility filter when listing related memos (lines 109-111)
5. **Attachment access (gRPC)** — `server/router/api/v1/attachment_service.go` — `checkAttachmentAccess` enforces memo visibility rules for linked attachments (lines 436-452)
6. **Memo-attachment operations** — `server/router/api/v1/memo_attachment_service.go` — checks memo visibility before allowing attachment operations (lines 213-223)
7. **SSE event delivery** — `server/router/api/v1/sse_hub.go` — `canReceive` filters events by visibility so subscribers only see events for memos they're allowed to view (lines 135-141)
8. **File server (HTTP)** — `server/router/fileserver/fileserver.go` — enforces visibility when serving attachment files: public memos served anonymously only if allowed, private memos restricted to creator/admin (lines 677, 699)
9. **User stats** — `server/router/api/v1/user_service_stats.go` — restricts memo counts by visibility when computing stats for other users (lines 84-90, 218-220)
10. **Memo list building (converter)** — `server/router/api/v1/memo_service_converter.go` — applies visibility filter when building memo lists in converter helpers (lines 184-186)
