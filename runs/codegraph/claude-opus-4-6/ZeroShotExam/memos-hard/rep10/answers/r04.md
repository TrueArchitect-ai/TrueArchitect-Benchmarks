The premise is incorrect — there are no message broker-based webhook delivery workers in this codebase. The project uses neither NATS nor RabbitMQ for webhook delivery.

The actual mechanism is a **buffered Go channel with in-process goroutine workers**. It is declared in `internal/webhook/webhook.go`:

- **Line 39**: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel of capacity 128 serves as the in-process queue.
- **Lines 42–55**: The `init()` function spawns 4 goroutine workers that consume from `asyncPostQueue` and call `Post()` for each payload.
- **Lines 184–196**: `PostAsync()` enqueues a payload onto the channel via a non-blocking `select`; if the channel is full, the webhook is dropped with a warning log.

Callers (e.g., `dispatchMemoRelatedWebhook` in `server/router/api/v1/memo_service_webhooks.go:71`) invoke `webhook.PostAsync(payload)`, which sends the payload into the channel. The goroutine workers then HTTP POST the JSON payload directly to the configured webhook URL. There is no external message broker involved.
