**Delivery function** — `Post` in `internal/webhook/webhook.go:120`. It marshals the payload to JSON, constructs an HTTP POST request, optionally signs it with HMAC-SHA256, and sends it via the `safeClient`. Asynchronous dispatch goes through `PostAsync` (same file, line 184), which enqueues onto a buffered channel consumed by 4 goroutines that each call `Post`.

**Protection mechanism** — `safeDialContext` in `internal/webhook/webhook.go:59` combined with `isReservedIP` and the `reservedNetworks` / `reservedCIDRs` blocklist in `internal/webhook/validate.go:14-54`. The `safeClient` HTTP client (line 32) uses a custom `Transport` whose `DialContext` is `safeDialContext`. Before connecting, `safeDialContext` resolves the target hostname via DNS and checks every resolved IP against `reservedNetworks` (loopback, RFC-1918, link-local/cloud IMDS, IPv6 ULA and link-local). Any match is rejected with an error, which defeats both direct private-IP URLs and DNS rebinding attacks. Additionally, `ValidateURL` (`internal/webhook/validate.go:62`) performs the same DNS-resolution-and-`isReservedIP` check at webhook creation/update time (`server/router/api/v1/user_service_webhooks.go:74,161,181`), providing defense-in-depth so that URLs pointing at internal addresses are rejected before they are even stored.
