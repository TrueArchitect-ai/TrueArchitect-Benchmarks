The premise is wrong — there is no Redis connection in this repository. A `grep -ri "redis"` across the codebase returns zero results.

The project uses **in-memory caching**, implemented in two separate layers:

1. **Server-side (Go):** `store/cache/cache.go` defines a generic in-memory cache behind an `Interface` with `Set`, `SetWithTTL`, `Get`, `Delete`, and `Clear` methods. There is no external datastore — items are held in-process with expiration tracked per-item via a `time.Time` field on the `item` struct (line 37). The RSS subsystem (`server/router/rss/rss.go`) uses its own `map[string]*cacheEntry` with a hardcoded `defaultCacheDuration` of **1 hour** (line 25) and a max cache size of 50 entries (line 26). User-specific RSS feeds are cached under the key `"user:<username>"` and share the same 1-hour TTL — there is no distinct TTL for "user entries."

2. **Client-side (TypeScript):** `web/src/components/MemoEditor/services/cacheService.ts` uses **browser `localStorage`** for editor draft caching, with a 500ms debounce delay. No TTL applies — entries persist until explicitly cleared.
