The premise is incorrect — there are no message broker consumers (neither NATS nor RabbitMQ) for webhook delivery. Webhooks are delivered synchronously via direct HTTP POST calls, not through any queue-based system.

The webhook dispatch mechanism is in `internal/webhook/webhook.go`. The function `Post` (around line 84) directly makes an HTTP POST request to the webhook URL using `http.DefaultClient.Do()`. When a webhook needs to fire, `convertMemoToWebhookPayload` builds the payload and `Post` sends it immediately — there is no queue declaration, no broker connection, and no worker consumer pattern.
