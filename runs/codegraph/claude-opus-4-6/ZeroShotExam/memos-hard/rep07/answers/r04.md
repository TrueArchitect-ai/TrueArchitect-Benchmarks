The premise is incorrect — there are no message broker-based webhook delivery workers in this codebase. The system uses neither NATS nor RabbitMQ for webhook delivery.

Webhooks are delivered via a simple **in-process Go channel + goroutine pool** pattern, declared in `internal/webhook/webhook.go`:

- **Queue**: a buffered Go channel `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (line 39).
- **Workers**: 4 goroutines spawned in `init()` (lines 42–55) that range over the channel and call `Post()` to make an HTTP POST to the webhook URL.
- **Enqueue**: `PostAsync()` (line 184) does a non-blocking send into the channel; if the buffer is full, the webhook is dropped with a warning log.

There is no external message broker dependency — `go.mod` contains no NATS or RabbitMQ/AMQP libraries. The entire dispatch mechanism is an in-memory fan-out within a single process.
