Emoji reactions are removed by **explicit Go code**, not by database-level rules (no foreign key `ON DELETE CASCADE` on the reaction table references the user).

Two explicit `DELETE` statements handle reactions in `deleteUserTargetsTx`:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions on the user's memos by content ID: `DELETE FROM reaction WHERE content_id IN (...)` (`store/db/sqlite/user_delete.go:280`, and equivalents in `store/db/mysql/user_delete.go`, `store/db/postgres/user_delete.go`).

2. **`deleteReactionsByCreatorTx`** — deletes reactions the user themselves created: `DELETE FROM reaction WHERE creator_id = ?` (`store/db/sqlite/user_delete.go:290`, and equivalents in mysql/postgres).

Both are called within the same transaction in `deleteUserTargetsTx` (`store/db/sqlite/user_delete.go:96–100`). I also checked the migration files for any `ON DELETE CASCADE` or foreign key referencing the user table on the reaction table and found none.

**Evidence locations:**
- `store/db/sqlite/user_delete.go` — functions `deleteReactionsByContentIDsTx` (line ~275) and `deleteReactionsByCreatorTx` (line ~286), called from `deleteUserTargetsTx` (lines 96–100)
- `store/db/mysql/user_delete.go` — same two functions
- `store/db/postgres/user_delete.go` — same two functions
- Migration directories (`store/db/sqlite/migration/`, `store/db/mysql/migration/`, `store/db/postgres/migration/`) — no `ON DELETE` rules referencing the reaction table
