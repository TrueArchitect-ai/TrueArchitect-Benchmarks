**`(*DB).CreateMemo`** — `store/db/sqlite/memo.go:16`

This is the concrete method that executes the SQL INSERT when a memo is saved in a default installation. It builds and executes an `INSERT INTO memo ...` statement at line 41–42 using `d.db.QueryRowContext`.

**Determination method:** The default database driver is established by tracing the configuration chain:

1. `cmd/memos/main.go:122` sets `viper.SetDefault("driver", "sqlite")` — so with no `--driver` flag, the driver is `"sqlite"`.
2. `cmd/memos/main.go:43` reads `Driver: viper.GetString("driver")` into the profile.
3. `cmd/memos/main.go:57` calls `db.NewDBDriver(instanceProfile)`.
4. `store/db/db.go:14–27` (`NewDBDriver`) switches on `profile.Driver` — the `"sqlite"` case calls `sqlite.NewDB(profile)`, returning a `*sqlite.DB` that implements the `store.Driver` interface.
5. The `store.Driver` interface (`store/driver.go:29`) declares `CreateMemo`, so when the store calls `driver.CreateMemo(...)`, it dispatches to `store/db/sqlite.(*DB).CreateMemo` — the SQLite implementation at `store/db/sqlite/memo.go:16`.

The MySQL (`store/db/mysql/memo.go:16`) and Postgres (`store/db/postgres/`) implementations exist as alternatives but are only selected when `--driver` is explicitly set to `"mysql"` or `"postgres"`.
