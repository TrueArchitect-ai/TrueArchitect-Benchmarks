Here are the distinct memo visibility enforcement sites on the server:

1. **GetMemo (`checkMemoReadAccess` helper)** — `server/router/api/v1/memo_service.go` (lines 39–68, called at line 356)
2. **ListMemos (query-level visibility filtering)** — `server/router/api/v1/memo_service.go` (lines 218–227: unauthenticated see only Public; authenticated see own + Public + Protected)
3. **CreateMemoComment (parent memo visibility check)** — `server/router/api/v1/memo_service_comments.go` (line 41: blocks commenting on Private memos)
4. **ListMemoComments (`checkMemoReadAccess` + query filter)** — `server/router/api/v1/memo_service_comments.go` (lines 148, 158–160)
5. **ListMemoRelations (visibility filter on related memos)** — `server/router/api/v1/memo_relation_service.go` (lines 109–111)
6. **CreateReaction / DeleteReaction (memo visibility check)** — `server/router/api/v1/reaction_service.go` (lines 30–38, 82–83)
7. **Memo attachment service (visibility check before linking)** — `server/router/api/v1/memo_attachment_service.go` (lines 213–222)
8. **File server (attachment download visibility gate)** — `server/router/fileserver/fileserver.go` (lines 674–699)
9. **RSS feed (only Public memos)** — `server/router/rss/rss.go` (lines 90, 141)
10. **SSE hub (event delivery filtering by visibility)** — `server/router/api/v1/sse_hub.go` (lines 135–141)
11. **Frontend service (SEO meta tags, Public only)** — `server/router/frontend/frontend.go` (line 150)
