`GET /file/users/:identifier/avatar` → serving handler and each hop to the database:

1. `FileServerService.RegisterRoutes` — `server/router/fileserver/fileserver.go:124` (registers the route)
2. `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168` (HTTP handler; extracts `:identifier` param, calls `getUserByUsername`)
3. `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715` (wraps `Store.GetUser` with a `FindUser{Username: &identifier}`)
4. `Store.GetUser` — `store/user.go:148` (checks the in-memory `userCache`; on miss delegates to `ListUsers`)
5. `Store.ListUsers` — `store/user.go:136` (calls `s.driver.ListUsers`, the DB driver)
6. `DB.ListUsers` — `store/db/mysql/user.go:84` (or `store/db/sqlite/user.go` / `store/db/postgres/user.go`; builds and executes `SELECT … avatar_url … FROM user WHERE username = ?`, scans the `AvatarURL` column into `store.User`)

Back in `serveUserAvatar`, the `user.AvatarURL` (a `data:` URI stored in the DB) is parsed with `parseDataURI`, and the decoded bytes are returned via `c.Blob()`.
