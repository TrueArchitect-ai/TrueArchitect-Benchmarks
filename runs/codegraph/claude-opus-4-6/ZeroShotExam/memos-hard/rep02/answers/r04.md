The premise is incorrect — there are no message broker-based webhook delivery workers in this codebase. The system uses **neither NATS nor RabbitMQ**.

The actual mechanism is a **buffered Go channel with in-process goroutine workers**. It is declared and initialized in `internal/webhook/webhook.go`:

- **Line 39**: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel of capacity 128 serves as the in-process "queue."
- **Lines 42–55**: The `init()` function spawns **4 goroutine workers** that each range over `asyncPostQueue` and call `Post()` to deliver the webhook via a direct **HTTP POST** (using a shared `safeClient` with SSRF protections).
- **Lines 184–196**: `PostAsync()` enqueues a payload onto the channel with a non-blocking `select`; if the channel is full, the webhook is dropped with a warning log.

There is no external message broker anywhere in the codebase — webhook delivery is entirely in-process, using Go's concurrency primitives (channels + goroutines) to decouple the API handler from the HTTP POST to the webhook endpoint.
