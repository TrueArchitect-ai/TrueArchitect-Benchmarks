`GET /file/users/:identifier/avatar` → stored avatar data:

1. `FileServerService.RegisterRoutes` — `server/router/fileserver/fileserver.go:121` (registers the route)
2. `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168` (HTTP handler; extracts `:identifier` param)
3. `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715` (looks up user by username)
4. `Store.GetUser` — `store/user.go:148` (checks in-memory cache, falls through to `ListUsers`)
5. `Store.ListUsers` — `store/user.go:136` (delegates to the DB driver)
6. `DB.ListUsers` — `store/db/mysql/user.go:84` (or `store/db/sqlite/user.go`, `store/db/postgres/user.go`; builds and executes `SELECT … avatar_url … FROM user WHERE username = ?`)

The avatar data itself is stored inline in the `user` table's `avatar_url` column as a `data:` URI. Back in `serveUserAvatar` (line 196), `parseDataURI` base64-decodes `user.AvatarURL` and the raw image bytes are returned via `c.Blob`.
