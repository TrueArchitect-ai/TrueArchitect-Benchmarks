The premise is incorrect: this repository does not use Redis at all. There is no Redis connection, dependency, or configuration anywhere in the codebase.

The cache layer is a **custom in-memory Go cache** implemented in `store/cache/cache.go`. It uses `sync.Map` for thread-safe storage and runs a background goroutine for periodic cleanup. The default configuration (`DefaultConfig()` at `store/cache/cache.go:57-63`) sets:

- **Default TTL**: 10 minutes
- **Cleanup interval**: 5 minutes
- **Max items**: 1,000

User setting entries (cached in `store/user_setting.go:59,78,106`) use `cache.Set()`, which applies the **default 10-minute TTL** — no custom TTL is specified for user entries.

There is also a separate, simpler RSS feed cache in `server/router/rss/rss.go:48` — a plain `map[string]*cacheEntry` protected by `sync.RWMutex` with a 1-hour TTL (`defaultCacheDuration` at line 25) and a 50-entry cap. This is unrelated to the user settings cache.
