**Delivery function** — `Post` in `internal/webhook/webhook.go:120`. This is where the outbound HTTP POST is constructed and executed (via `safeClient.Do`). Asynchronous callers use `PostAsync` (same file, line 184), which enqueues the payload onto `asyncPostQueue`; worker goroutines (started in `init`, line 42) drain the queue and call `Post`.

**Protection mechanism** — Two layers of SSRF defense, both in `internal/webhook/`:

1. **At webhook creation/update time**: `ValidateURL` (`internal/webhook/validate.go:62`) resolves the target hostname and checks every resolved IP against `isReservedIP` (`internal/webhook/validate.go:44`), which tests against a list of reserved CIDRs (`reservedCIDRs`, line 14) covering loopback, RFC-1918 private ranges, link-local/cloud IMDS (`169.254.0.0/16`), and IPv6 equivalents. URLs resolving to any of these are rejected before the webhook is stored.

2. **At delivery time (defeating DNS rebinding)**: The `safeClient` HTTP client (`internal/webhook/webhook.go:32`) uses a custom `Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:59`). This function re-resolves the hostname at connection time and again checks every resolved IP against `isReservedIP`, blocking the connection if any address falls within a reserved range. This ensures that even if a hostname resolves to an internal IP between creation and delivery, the request is still blocked.
