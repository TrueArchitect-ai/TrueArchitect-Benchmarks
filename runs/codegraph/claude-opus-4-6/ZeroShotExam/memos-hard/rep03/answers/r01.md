The premise is incorrect — this repository does not use Redis for caching. Based on the codebase, the cache layer uses an **in-memory Go struct**, not Redis.

The cache mechanism is defined in `server/router/rss/rss.go`. The `cacheEntry` struct (line 35) holds cached RSS content with an `expiry` field of type `time.Time`. The TTL is set to **5 minutes**, as seen in the `putInCache` function where expiry is calculated as `time.Now().Add(5 * time.Minute)`.

There is no Redis dependency, connection configuration, or Redis client anywhere in the project. The RSS cache is a simple in-process map (`map[string]*cacheEntry`) guarded for concurrent access, with no external backing store.
