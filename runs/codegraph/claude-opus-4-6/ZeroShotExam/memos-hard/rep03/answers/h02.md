**Delivery function** — `Post` in `internal/webhook/webhook.go` (line 120). This is where the outbound HTTP POST to the webhook endpoint actually executes. It serializes the payload, optionally signs it with HMAC-SHA256, and sends it via `safeClient.Do(req)`. Asynchronous callers use `PostAsync` (line 184), which enqueues payloads onto a buffered channel consumed by goroutines that call `Post`.

**Protection mechanism** — `safeDialContext` in `internal/webhook/webhook.go` (line 59) combined with `isReservedIP` and the `reservedNetworks` list in `internal/webhook/validate.go` (lines 14–54). Two layers enforce SSRF protection:

1. **At webhook creation/update time**: `ValidateURL` (`internal/webhook/validate.go:62`) resolves the hostname and rejects any URL whose IP falls in a reserved/private CIDR range (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents).
2. **At dial time** (defeating DNS rebinding): The `safeClient` HTTP client (`internal/webhook/webhook.go:32`) uses a custom `Transport` with `safeDialContext` as its `DialContext`. This function re-resolves the hostname at connection time and blocks the connection if any resolved IP is in the reserved ranges — so even if DNS returns a public IP at validation time but a private IP later, the connection is refused.

Both layers share the same `isReservedIP` function (`internal/webhook/validate.go:44`) and `reservedNetworks` CIDR list, which can be bypassed via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for self-hosted deployments that intentionally target local-network services.
