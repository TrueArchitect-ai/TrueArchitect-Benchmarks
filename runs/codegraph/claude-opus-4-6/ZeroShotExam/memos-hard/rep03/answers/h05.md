Emoji reactions are removed by **explicit Go code** via two dedicated deletion functions called during the user deletion transaction.

In `deleteUserTargetsTx` (e.g., `store/db/mysql/user_delete.go:92–127`), two reaction-deletion calls are made:

1. **`deleteReactionsByContentIDsTx`** (line 96) — deletes all reactions on the user's memos: `DELETE FROM reaction WHERE content_id IN (...)` using the memo content IDs. Evidence: `store/db/mysql/user_delete.go:420`, `store/db/sqlite/user_delete.go:383`, `store/db/postgres/user_delete.go:383`.

2. **`deleteReactionsByCreatorTx`** (line 102) — deletes all reactions *created by* the user on any content: `DELETE FROM reaction WHERE creator_id = ?`. Evidence: `store/db/mysql/user_delete.go:438`, `store/db/sqlite/user_delete.go:401`, `store/db/postgres/user_delete.go:401`.

Both are executed within the same transaction as the rest of the user deletion (`store/db/mysql/user_delete.go:29–59`), across all three database drivers (MySQL, PostgreSQL, SQLite). There is no reliance on database-level CASCADE rules for reactions.
