The premise of the question is incorrect. This repository does not implement per-user API rate-limiting middleware. The API layer (registered in `server/server.go` and `server/router/api/v1/v1.go`) uses Connect/gRPC interceptors for authentication (`server/auth/authenticator.go`) and authorization (`server/router/api/v1/acl_config.go`, `server/router/api/v1/authz.go`), but none of these implement request rate limiting. The only concurrency control present is a thumbnail-generation semaphore (`server/router/api/v1/v1.go:39`), which limits concurrent operations — not per-user request rates. The sole mention of "rate" in the codebase is a comment in `internal/email/doc.go`, unrelated to API middleware.
