The premise is incorrect — there are no message broker-based webhook delivery workers consuming from NATS or RabbitMQ. Webhooks in this repository are dispatched synchronously via direct HTTP calls, not through a message queue.

In `internal/webhook/webhook.go`, the function `Post` (which sends webhook HTTP requests) is called directly in-process whenever a webhook-triggering event occurs. The webhook runner (`runner.go` in the same package) uses a simple Go channel or direct invocation pattern — there is no external message broker involved.

The webhook payload is constructed in `internal/webhook/webhook.go` (the `WebhookRequestPayload` struct at line 79) and posted via standard `net/http` calls. Webhook dispatch is triggered from the memo service layer (e.g., `server/router/api/v1/memo_service_webhooks.go`), not consumed from any queue.
