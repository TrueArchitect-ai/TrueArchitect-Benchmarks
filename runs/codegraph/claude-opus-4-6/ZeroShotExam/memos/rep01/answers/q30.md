Four memo lifecycle events dispatch webhooks:

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

All four are defined in `server/router/api/v1/memo_service_webhooks.go`. The first three converge through the private method `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator's webhooks and calls `webhook.PostAsync` for each. `DispatchMemoCommentCreatedWebhook` (line 30) handles its own webhook lookup (using the *related* memo creator's ID rather than the comment creator) but also calls `webhook.PostAsync`.

All four ultimately converge for delivery at `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload onto `asyncPostQueue` (a buffered channel, line 39). Four goroutines (started in `init()`, line 42) drain that channel and call `webhook.Post` (`internal/webhook/webhook.go:120`), which performs the actual HTTP POST.
