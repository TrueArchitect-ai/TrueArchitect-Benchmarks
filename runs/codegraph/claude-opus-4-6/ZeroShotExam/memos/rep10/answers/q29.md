The auth interceptor lives at `server/router/api/v1/connect_interceptors.go` (the `AuthInterceptor` struct, line 208). Its `WrapUnary` method (line 217) extracts the `Authorization` header from each incoming Connect RPC request, delegates to the `Authorizer` (defined in `server/router/api/v1/authz.go`) which calls through to the core `Authenticator`.

**Token kinds managed:**
1. **JWT Access Tokens (Access Token V2)** — short-lived (15-minute) bearer tokens validated statelessly via `AuthenticateByAccessTokenV2` (`server/auth/authenticator.go:41`).
2. **Personal Access Tokens (PATs)** — long-lived tokens with a `PersonalAccessTokenPrefix`, validated by hash lookup via `AuthenticateByPAT` (`server/auth/authenticator.go:102`).
3. **Refresh Tokens** — used via cookie fallback in `AuthenticateToUser` (`server/auth/authenticator.go:61`), though the Connect interceptor path itself only handles Bearer tokens (access tokens and PATs).

**Backend package that validates them:** `server/auth` — specifically `server/auth/authenticator.go`, which contains the `Authenticator` struct and all token parsing/validation logic (`AuthenticateByAccessTokenV2`, `AuthenticateByPAT`, `AuthenticateByRefreshToken`, `resolveBearer`).

**Summary:** `server/router/api/v1/connect_interceptors.go`; access tokens (JWT), personal access tokens (PAT), refresh tokens (cookie); `server/auth`.
