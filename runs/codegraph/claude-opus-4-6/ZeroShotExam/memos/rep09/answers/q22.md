When a memo is created, the handler `CreateMemo` in `server/router/api/v1/memo_service.go` calls `DispatchMemoCreatedWebhook` — defined in `server/router/api/v1/memo_service_webhooks.go`. This function delegates to `dispatchMemoRelatedWebhook` (same file), which looks up the creator's webhooks, builds a `WebhookRequestPayload`, and calls `webhook.PostAsync` to enqueue delivery.

The HTTP delivery is performed by the `internal/webhook` package (`internal/webhook/webhook.go`). `PostAsync` enqueues the payload onto a buffered channel, and background goroutines drain it by calling `Post`, which uses `net/http` (via a custom `safeClient`) to make the POST request.

The request-signing mechanism is **HMAC-SHA256** following the **Standard Webhooks** convention. When a `SigningSecret` is present, `Post` generates a `webhook-id` (UUID), a `webhook-timestamp` (Unix seconds), computes `HMAC-SHA256(key, msgID + "." + timestamp + "." + body)`, and sets the `webhook-signature` header to `"v1," + base64(mac)`. Secrets in `whsec_<base64>` format are base64-decoded to derive the raw key; otherwise the secret string is used directly as the key.

**dispatcher** — `DispatchMemoCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go`; **delivery package** — `internal/webhook`; **signing mechanism** — HMAC-SHA256 (Standard Webhooks: `webhook-id` / `webhook-timestamp` / `webhook-signature` headers with `v1,<base64>` signature).
