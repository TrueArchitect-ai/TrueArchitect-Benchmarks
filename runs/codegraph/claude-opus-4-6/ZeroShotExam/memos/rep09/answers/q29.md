**Frontend auth interceptor:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a Connect-RPC `Interceptor` that attaches an `Authorization: Bearer <token>` header to every outgoing request, handles 401 retries by refreshing the token, and redirects on final auth failure.

**Tokens it manages:**
1. **Access tokens (JWT)** — short-lived (15-minute) tokens stored in memory via `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken`). Attached as `Bearer` tokens in the `Authorization` header.
2. **Refresh tokens** — long-lived tokens stored as HttpOnly cookies (sent via `credentials: "include"`). Used by `refreshAuthClient.refreshToken({})` to obtain new access tokens.
3. **Personal Access Tokens (PAT)** — long-lived tokens for programmatic access, also sent as `Bearer` tokens.

**Backend package that validates them:** `server/auth` (specifically `server/auth/authenticator.go`). The `Authenticator` struct provides `Authenticate()`, `AuthenticateByAccessTokenV2()`, `AuthenticateByRefreshToken()`, and `AuthenticateByPAT()`. It is consumed by the `Authorizer` in `server/router/api/v1/authz.go`, which is in turn used by the server-side `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` (line 208) to enforce authentication on incoming Connect-RPC requests.
