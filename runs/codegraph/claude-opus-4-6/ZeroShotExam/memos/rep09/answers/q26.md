The following database tables are affected when `DeleteMemo` runs:

1. **`memo_relation`** — Rows deleted explicitly in `store/memo.go:142-146` via two `DeleteMemoRelation` calls (once where memo is the source `MemoID`, once where it is the `RelatedMemoID`).

2. **`attachment`** — Rows deleted in `store/memo.go:149-157` by listing attachments for the memo and calling `DeleteAttachment` for each one (which issues `DELETE FROM attachment`).

3. **`memo`** — The memo row itself is deleted in `store/memo.go:158` via `driver.DeleteMemo`, which issues `DELETE FROM memo WHERE id = ?` (see `store/db/postgres/memo.go:246`, `store/db/mysql/memo.go:261`).

4. **`memo`** (comment memos) — At the service layer (`server/router/api/v1/memo_service.go:568-577`), comment memos are found via `memo_relation` (type `COMMENT`) and each comment is recursively deleted through `Store.DeleteMemo`, which in turn affects `memo_relation`, `attachment`, and `memo` again for each comment.

In summary, three tables are directly affected: **`memo`**, **`memo_relation`**, **`attachment`**.
