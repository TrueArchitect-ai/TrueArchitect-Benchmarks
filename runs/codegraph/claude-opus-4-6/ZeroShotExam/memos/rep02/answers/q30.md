Four memo lifecycle events dispatch webhooks:

- **memo created**: `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:20`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (`server/router/api/v1/memo_service_webhooks.go:25`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:30`)

All four converge for delivery through `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload onto `asyncPostQueue` (a buffered channel, line 39). Four goroutines started in `init()` (line 42) drain that channel and call `webhook.Post` (`internal/webhook/webhook.go:120`), which performs the actual HTTP POST via `safeClient`.

The first three (`Created`, `Updated`, `Deleted`) share a common intermediary — `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`) — which resolves the memo creator's webhooks and calls `webhook.PostAsync` for each. `DispatchMemoCommentCreatedWebhook` resolves webhooks for the *related memo's* creator directly (line 31) and also calls `webhook.PostAsync`.
