When a memo is deleted, the store layer (`store/memo.go:140-158`) deletes the following kinds of records before the memo row itself:

1. **Memo relations (as source)** — `DeleteMemoRelation` where the memo is the source (`MemoID` = memo's ID) (line 142)
2. **Memo relations (as target)** — `DeleteMemoRelation` where the memo is the related/target memo (`RelatedMemoID` = memo's ID) (line 145)
3. **Attachments** — lists all attachments linked to the memo, then deletes each one via `DeleteAttachment` (lines 149–157)

Note: at the API service layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (child memos linked via `MemoRelationComment`) are also recursively deleted before the parent memo, but each of those deletions goes through the same `Store.DeleteMemo` path, which performs the three cleanup steps above for each comment as well.
