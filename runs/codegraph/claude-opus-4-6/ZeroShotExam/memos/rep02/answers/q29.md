**Frontend auth interceptor:** `web/src/connect.ts` (lines 156–178). It is a Connect RPC `Interceptor` that runs on every API request. Before each call it retrieves a short-lived **access token** (JWT) via `getRequestToken()` and sets it as a `Bearer` token in the `Authorization` header. On a 401 (`Code.Unauthenticated`) response it transparently refreshes the token using an HTTP-only **refresh token** cookie (via `refreshAccessToken()` / the `AuthService.RefreshAccessToken` RPC) and retries the request. It also manages **Personal Access Tokens (PATs)** as an alternative bearer credential.

**Token kinds managed:**
1. **Access token (v2 JWT)** — short-lived, stored in-memory and `localStorage` (`web/src/auth-state.ts`), sent as `Authorization: Bearer <token>`.
2. **Refresh token (JWT)** — long-lived, stored as an HTTP-only cookie, used to obtain new access tokens.
3. **Personal Access Token (PAT)** — long-lived opaque token (prefixed `memos_`), also sent as a `Bearer` token.

**Backend validation package:** `server/auth` (`server/auth/authenticator.go`). The `Authenticator` struct validates all three credential types: `AuthenticateByAccessTokenV2` (stateless JWT validation), `AuthenticateByRefreshToken` (JWT + DB revocation check), and `AuthenticateByPAT` (hash lookup). The backend interceptor that invokes this is `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` (line 208), which delegates to `Authorizer` in `server/router/api/v1/authz.go` (line 26).
