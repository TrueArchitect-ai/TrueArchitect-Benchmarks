When `DeleteMemo` runs, the following database tables are affected (directly or by explicit cascade code):

1. **`memo_relation`** — Deleted first via two calls to `DeleteMemoRelation`: once where the memo is the source (`memo_id`), once where it is the target (`related_memo_id`) (`store/memo.go:142-147`).

2. **`attachment`** — Attachments linked to the memo are listed and each is deleted individually via `DeleteAttachment` (`store/memo.go:149-157`, which calls `driver.DeleteAttachment` issuing `DELETE FROM attachment`).

3. **`memo`** — The memo row itself is deleted last via `driver.DeleteMemo` (`store/memo.go:158`, issuing `DELETE FROM memo`).

Additionally, the API-layer handler in `server/router/api/v1/memo_service.go:567-577` recursively deletes **comment memos** before deleting the parent memo: it queries `memo_relation` for relations of type `Comment` where the memo is the `related_memo_id`, then calls `Store.DeleteMemo` for each comment. Each recursive `DeleteMemo` call cascades through the same three tables above (`memo_relation`, `attachment`, `memo`) for the comment memo.
