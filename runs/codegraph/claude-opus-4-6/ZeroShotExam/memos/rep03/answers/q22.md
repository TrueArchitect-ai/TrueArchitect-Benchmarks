When a memo is created, the handler `CreateMemo` in `server/router/api/v1/memo_service.go` calls `DispatchMemoCreatedWebhook` — defined in `server/router/api/v1/memo_service_webhooks.go`. This delegates to the private method `dispatchMemoRelatedWebhook` (same file), which looks up the creator's webhooks, builds a `WebhookRequestPayload`, and calls `webhook.PostAsync` to enqueue delivery.

The HTTP delivery is performed by the `internal/webhook` package (`internal/webhook/webhook.go`). `PostAsync` enqueues the payload onto a buffered channel; background goroutines drain it by calling `Post`, which uses a standard `net/http` client to POST the JSON payload.

Signing uses **HMAC-SHA256** following the **Standard Webhooks** convention. When a `SigningSecret` is present on the payload, `Post` generates a `webhook-id` (UUID), a `webhook-timestamp` (Unix seconds), computes `HMAC-SHA256(key, msgID + "." + timestamp + "." + body)`, and sets the `webhook-signature` header to `"v1," + base64(mac)`. The key is derived via `resolveSigningKey`: secrets prefixed with `whsec_` are base64-decoded; plain strings are used as-is.

**dispatcher** — `DispatchMemoCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go`; **delivery package** — `internal/webhook` (specifically `webhook.Post`/`webhook.PostAsync`); **signing mechanism** — HMAC-SHA256 with Standard Webhooks headers (`webhook-id`, `webhook-timestamp`, `webhook-signature` with `v1,<base64>` format).
