The frontend auth interceptor lives in `web/src/connect.ts` (the `authInterceptor` constant, line 156). It manages two token kinds: **short-lived JWT access tokens** (stored/retrieved via `getAccessToken`/`setAccessToken` from `web/src/auth-state.ts`) and **refresh tokens** (sent as HttpOnly cookies via `credentials: "include"`). The interceptor sets the `Authorization: Bearer <accessToken>` header on every request, and on a `Code.Unauthenticated` response it calls `refreshAccessToken()` to exchange the cookie-based refresh token for a new access token, then retries. Personal Access Tokens (PATs) are also accepted as Bearer tokens.

On the backend, validation is performed by the `server/auth` package (`server/auth/authenticator.go`). The `Authenticator` struct provides `Authenticate()`, `AuthenticateByAccessTokenV2()` (stateless JWT validation), `AuthenticateByPAT()` (database-backed PAT validation), and `AuthenticateByRefreshToken()` (database-backed refresh token validation). The `Authorizer` in `server/router/api/v1/authz.go` wraps `Authenticator` and is used by the Connect interceptor (`server/router/api/v1/connect_interceptors.go`) to enforce method-level access control on every RPC.
