When a memo is created, the handler `CreateMemo` in `server/router/api/v1/memo_service.go` calls `DispatchMemoCreatedWebhook` defined in `server/router/api/v1/memo_service_webhooks.go`. This method delegates to `dispatchMemoRelatedWebhook` (same file), which looks up the creator's webhooks and calls `webhook.PostAsync` for each one.

- **Dispatcher** — `DispatchMemoCreatedWebhook` (which calls `dispatchMemoRelatedWebhook`) in `server/router/api/v1/memo_service_webhooks.go`
- **Delivery package** — `internal/webhook` (specifically the `Post` function in `internal/webhook/webhook.go`, invoked asynchronously via `PostAsync` through a buffered channel with 4 worker goroutines)
- **Signing mechanism** — HMAC-SHA256 following the Standard Webhooks convention. The `Post` function computes `HMAC-SHA256(key, msgID + "." + timestamp + "." + body)`, base64-encodes the result, and sets three headers: `webhook-id` (a UUID), `webhook-timestamp` (Unix epoch), and `webhook-signature` (`v1,<base64-signature>`). The signing key is derived via `resolveSigningKey`: secrets with the `whsec_` prefix are base64-decoded to raw bytes; plain strings are used as-is.
