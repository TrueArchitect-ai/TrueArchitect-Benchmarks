The frontend auth interceptor lives at `web/src/connect.ts` (the `authInterceptor` function, line 156). It manages two token kinds: **JWT access tokens** (short-lived, stored in memory via `getAccessToken`/`setAccessToken` from `web/src/auth-state.ts`) and **refresh tokens** (HttpOnly cookies sent via `credentials: "include"`). On each request it attaches the access token as a `Bearer` header; on a 401 (`Code.Unauthenticated`) it calls `RefreshToken` to exchange the cookie-based refresh token for a new access token, then retries. It also does preflight refresh when the access token is near expiry. Personal Access Tokens (PATs) are a third credential type handled on the backend side.

The backend package that validates these tokens is `server/auth` (`server/auth/authenticator.go`). Its `Authenticator.Authenticate` method extracts the Bearer token, dispatches to `AuthenticateByAccessTokenV2` (stateless JWT validation) or `AuthenticateByPAT` (database lookup by token hash). The `Authorizer` in `server/router/api/v1/authz.go` wraps `Authenticator` and enforces method-level access policy; it is called by the Connect interceptor in `server/router/api/v1/connect_interceptors.go`.
