When `DeleteMemo` runs, the following database tables are affected:

1. **`memo_relation`** — Rows deleted where `memo_id` or `related_memo_id` matches the memo being deleted (`store/memo.go:142-146`, via `DeleteMemoRelation`). Also deleted for any comment memos recursively.

2. **`attachment`** — Rows deleted for all attachments linked to the memo (`store/memo.go:149-157`, via `DeleteAttachment`). Also deleted for any comment memos recursively.

3. **`memo`** — The memo row itself is deleted (`store/memo.go:158`, e.g. `store/db/postgres/memo.go:244-255`). Also, comment memos are deleted first (see below).

4. **`memo`** (comment memos) — Before deleting the target memo, the API layer in `server/router/api/v1/memo_service.go:568-577` finds all `COMMENT`-type relations where this memo is the parent (`related_memo_id`), and recursively calls `Store.DeleteMemo` for each comment. Each such recursive call in turn deletes from `memo_relation`, `attachment`, and `memo` for that comment.

**Summary table list:** `memo_relation`, `attachment`, `memo`
