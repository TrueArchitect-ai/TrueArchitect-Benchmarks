**Frontend auth interceptor:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that runs on every request. It calls `getRequestToken()` to obtain a JWT access token (from in-memory/localStorage state managed in `web/src/auth-state.ts`), then sets the `Authorization: Bearer <token>` header via `setAuthorizationHeader()` (line 97–99). On a 401 (`Code.Unauthenticated`) response, it transparently refreshes the token using the refresh-token cookie and retries once.

**Token kinds managed:**
1. **JWT access tokens** (short-lived, 15 min) — stored client-side in localStorage under `memos_access_token`, sent as `Authorization: Bearer` header.
2. **JWT refresh tokens** (long-lived, 30 days) — stored as an HTTP cookie named `memos_refresh`, sent with `credentials: "include"` to the `RefreshToken` RPC endpoint.
3. **Personal Access Tokens (PAT)** — prefixed `memos_pat_`, also sent as `Authorization: Bearer`, used for programmatic access.

**Backend validation package:** `server/auth` (`server/auth/authenticator.go`, `server/auth/token.go`). The `Authenticator` struct provides `Authenticate()`, `AuthenticateByAccessTokenV2()`, `AuthenticateByRefreshToken()`, and `AuthenticateByPAT()`. The server-side Connect interceptor that invokes it is `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` (line 208), which delegates to `Authorizer.Authenticate()` → `auth.Authenticator.Authenticate()`.
