The filter expression is parsed by a custom recursive-descent parser (a CEL-like syntax) implemented in `internal/filter/engine.go` and `internal/filter/parser.go`. The `Engine` struct's `Parse` method tokenizes and parses the filter string into an internal expression tree (`parseContext`), and then `Engine.Compile` renders that tree into a SQL `WHERE` clause by walking the expression and calling dialect-aware helpers in `internal/filter/render.go` that switch on `DialectName` (e.g., `DialectMySQL`, `DialectPostgres`, `DialectSQLite` defined in `internal/filter/schema.go`) to emit the correct SQL syntax for each database backend.

**Engine + path:** Custom recursive-descent CEL-like parser in `internal/filter/engine.go` + `internal/filter/parser.go`.

**Mechanism:** The parsed expression tree is compiled into a SQL `WHERE` clause by `internal/filter/render.go`, which switches on `DialectName` (`internal/filter/schema.go`) to produce dialect-specific SQL for MySQL, PostgreSQL, and SQLite.
