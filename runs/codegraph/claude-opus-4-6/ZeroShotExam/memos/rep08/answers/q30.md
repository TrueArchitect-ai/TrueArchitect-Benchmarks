Four memo lifecycle events dispatch webhooks:

- **memo created**: `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:20`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (`server/router/api/v1/memo_service_webhooks.go:25`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:30`)

The first three converge into the shared helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo creator's webhooks and calls `webhook.PostAsync` for each. `DispatchMemoCommentCreatedWebhook` handles its own webhook lookup (using the *related* memo's creator ID rather than the comment's creator) but also calls `webhook.PostAsync`.

All four ultimately converge for delivery at `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload into a buffered channel (`asyncPostQueue`). Four background goroutines (started in `init()` at `internal/webhook/webhook.go:42`) drain that channel and call `webhook.Post` (`internal/webhook/webhook.go:120`), which performs the actual HTTP POST to the webhook endpoint.
