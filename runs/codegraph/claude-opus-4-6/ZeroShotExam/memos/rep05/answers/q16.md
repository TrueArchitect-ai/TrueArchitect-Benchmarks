When a memo is deleted through the API, the store layer (`Store.DeleteMemo` in `store/memo.go:140–158`) deletes the following kinds of records before the memo row itself:

1. **Memo relations (as source)** — `DeleteMemoRelation` where the memo is the `MemoID` (line 142)
2. **Memo relations (as target)** — `DeleteMemoRelation` where the memo is the `RelatedMemoID` (line 145)
3. **Attachments** — lists all attachments linked to the memo, then deletes each one via `DeleteAttachment` (lines 149–157)

After all three of those are cleaned up, the store calls `driver.DeleteMemo` to delete the memo row itself (line 158).

Note: at the API service layer (`server/router/api/v1/memo_service.go:567–577`), **comment memos** (child memos linked via `MemoRelationComment`) are also recursively deleted before the parent memo, but each of those deletions goes through the same `Store.DeleteMemo` path, so the store-layer cleanup order above applies to each one.
