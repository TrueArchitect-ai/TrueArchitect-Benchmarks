The frontend auth interceptor lives at `web/src/connect.ts` (the `authInterceptor` function, line 156). It attaches a `Bearer` token to every outgoing Connect RPC request via the `Authorization` header. It manages two token kinds:

1. **Access tokens (JWT)** — short-lived (15-minute) tokens stored in memory, obtained/refreshed via the `RefreshToken` RPC using an HTTP-only refresh-token cookie.
2. **Personal Access Tokens (PAT)** — long-lived tokens for programmatic access, identified by a `memos_` prefix.

On the backend, these tokens are validated by the `server/auth` package (`server/auth/authenticator.go`). The `Authenticator` struct provides `AuthenticateByAccessTokenV2` (stateless JWT validation) and `AuthenticateByPAT` (hash-based database lookup). The Connect-layer enforcement is in `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:208`), which delegates to `Authorizer.Authenticate` (`server/router/api/v1/authz.go:44`), which in turn calls `auth.Authenticator.Authenticate`.

**Interceptor path:** `web/src/connect.ts` (frontend); `server/router/api/v1/connect_interceptors.go` (backend Connect interceptor)
**Token kinds:** JWT access tokens, refresh tokens (cookie), Personal Access Tokens (PAT)
**Backend validation package:** `server/auth` (`server/auth/authenticator.go`)
