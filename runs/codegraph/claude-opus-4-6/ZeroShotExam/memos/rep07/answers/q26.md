When `DeleteMemo` runs, the following database tables are affected:

1. **`memo_relation`** — `store/memo.go:142-146` explicitly deletes rows where the memo is either the source (`memo_id`) or the target (`related_memo_id`).

2. **`attachment`** — `store/memo.go:149-157` lists all attachments for the memo and deletes each one from the `attachment` table (via `s.driver.DeleteAttachment`).

3. **`memo`** — `store/memo.go:158` deletes the memo row itself (via `s.driver.DeleteMemo`, e.g. `store/db/postgres/memo.go:244-255`).

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), comment memos are deleted first: it queries `memo_relation` for relations of type `COMMENT` where `related_memo_id` is the target memo, then recursively calls `Store.DeleteMemo` for each comment. Each comment deletion cascades through the same three tables above (`memo_relation`, `attachment`, `memo`).

**Table list:** `memo`, `memo_relation`, `attachment`
