When a memo is deleted, the store layer (`store/memo.go:140-158`) deletes the following kinds of records before the memo row itself:

1. **Memo relations (source)** — `DeleteMemoRelation` where the memo is the source (`MemoID`) (`store/memo.go:142`)
2. **Memo relations (target)** — `DeleteMemoRelation` where the memo is the related/target memo (`RelatedMemoID`) (`store/memo.go:145`)
3. **Attachments** — lists all attachments linked to the memo, then deletes each one via `DeleteAttachment` (`store/memo.go:149-156`)

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), **comment memos** (child memos linked via `MemoRelationComment`) are recursively deleted via `Store.DeleteMemo` before the parent memo itself is deleted — and each of those recursive deletions triggers the same store-layer cleanup of memo relations and attachments.
