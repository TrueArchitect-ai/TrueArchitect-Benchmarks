Frontend API requests are authenticated via a Connect (ConnectRPC) interceptor defined at `web/src/connect.ts:156` (`authInterceptor`). Before each request it calls `getRequestToken()` which reads a short-lived **JWT access token** from in-memory/localStorage state (managed in `web/src/auth-state.ts`) and sets the `Authorization: Bearer <token>` header. On a 401 (`Code.Unauthenticated`), the interceptor transparently refreshes using a **refresh token** (an HttpOnly cookie read server-side) via `AuthService.RefreshToken`, then retries. The interceptor also supports **Personal Access Tokens (PATs)** which use the same Bearer header path.

The three token kinds managed are:
1. **JWT access tokens** (short-lived, 15 min) — carried in the `Authorization` header.
2. **Refresh tokens** (long-lived, 30 days) — stored as an HttpOnly cookie, used to obtain new access tokens.
3. **Personal Access Tokens (PATs)** — long-lived Bearer tokens for programmatic access.

On the backend, tokens are validated by the `server/auth` package (`server/auth/authenticator.go`). The `Authenticator` struct provides `AuthenticateByAccessTokenV2` (stateless JWT validation), `AuthenticateByRefreshToken` (database-checked), and `AuthenticateByPAT` (hash-based lookup). The `Authorizer` in `server/router/api/v1/authz.go` wraps `Authenticator` and is used by the Connect `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:208`) to enforce method-level access policy.

**Interceptor path:** `web/src/connect.ts` (frontend); `server/router/api/v1/connect_interceptors.go` (backend)
**Token kinds:** JWT access tokens, refresh tokens (HttpOnly cookie), Personal Access Tokens (PATs)
**Backend validation package:** `server/auth` (`server/auth/authenticator.go`)
