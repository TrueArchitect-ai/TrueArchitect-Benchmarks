**Memo lifecycle events and their dispatch functions:**

- memo created: `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`)
- memo updated: `DispatchMemoUpdatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:20`)
- memo deleted: `DispatchMemoDeletedWebhook` (`server/router/api/v1/memo_service_webhooks.go:25`)
- memo comment created: `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:30`)

All four converge for delivery through `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload onto `asyncPostQueue` (a buffered channel). Worker goroutines (spawned in `init()` at `internal/webhook/webhook.go:42`) drain the queue and call `webhook.Post` (`internal/webhook/webhook.go:120`) — the single function that performs the actual HTTP POST delivery.

The first three (`Created`, `Updated`, `Deleted`) share a common intermediate: `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo creator's webhooks and calls `webhook.PostAsync` per hook. `DispatchMemoCommentCreatedWebhook` bypasses that helper (it looks up the *related memo owner's* webhooks instead) but still calls `webhook.PostAsync` directly, converging at the same delivery path.
