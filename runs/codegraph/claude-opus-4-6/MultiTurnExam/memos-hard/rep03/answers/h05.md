Explicit Go code. Reactions are removed in two passes within the user-deletion transaction:

1. **`deleteReactionsByContentIDsTx`** — deletes all reactions attached to the user's memos (by `content_id`). Evidence: `store/db/sqlite/user_delete.go:380`, `store/db/postgres/user_delete.go:380`, `store/db/mysql/user_delete.go:417`.
2. **`deleteReactionsByCreatorTx`** — deletes all reactions the user themselves created (by `creator_id`). Evidence: `store/db/sqlite/user_delete.go:400`, `store/db/postgres/user_delete.go:400`, `store/db/mysql/user_delete.go:437`.

Both are called from the main delete transaction in each driver (e.g., `store/db/sqlite/user_delete.go:96,102`). There are no database-level foreign key cascades on the `reaction` table — the migration files contain no FK constraints for it.
