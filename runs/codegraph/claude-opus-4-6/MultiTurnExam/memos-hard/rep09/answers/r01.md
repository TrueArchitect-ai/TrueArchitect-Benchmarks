**Premise correction:** There is no Redis connection. The cache layer does not use Redis at all.

**Actual mechanism:** The cache is an in-process, in-memory implementation defined in `store/cache/cache.go`. It uses a `sync.Map` with no TTL — entries remain until explicitly deleted or the process restarts. The `Store` creates three `Cache` instances (for instance settings, users, and user settings) in `store/store.go`. User entries are cached by user ID via `Store.GetUser` / `Store.ListUsers` / `Store.CreateUser` / `Store.UpdateUser` (all in `store/user.go`) and invalidated on deletion via `Store.deleteUserCache` — but they never expire on their own.
