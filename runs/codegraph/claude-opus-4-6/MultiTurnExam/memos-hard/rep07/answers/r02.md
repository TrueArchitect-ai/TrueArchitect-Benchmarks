**Premise correction:** There is no per-user API rate-limiting middleware in this codebase. No rate limiter is registered, configured, or implemented anywhere in the server.

I verified by searching for rate-limiting patterns across the backend:

- No references to "rate limit", "ratelimit", "throttle", or "limiter" exist in the server or middleware code.
- The middleware stack (registered in `server/router/api/v1/v1.go` and `server/server.go`) consists of authentication/ACL interceptors, CORS handling, and gRPC gateway registration — no rate limiting.
- The `internal/scheduler/middleware.go` provides job-level middleware (logging, recovery, timeout) for the cron scheduler, not HTTP request throttling.

The server relies on external infrastructure (reverse proxy, load balancer) for any rate limiting, rather than implementing it at the application layer.
