Explicit Go code. When a user is deleted, reactions are removed in two passes within the same transaction:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions whose `content_id` matches the user's memos (reactions *on* their content). Found at `store/db/sqlite/user_delete.go:380`, `store/db/postgres/user_delete.go:380`, `store/db/mysql/user_delete.go:417`.
2. **`deleteReactionsByCreatorTx`** — deletes reactions where `creator_id` matches the deleted user (reactions *by* them). Found at `store/db/sqlite/user_delete.go:400`, `store/db/postgres/user_delete.go:400`, `store/db/mysql/user_delete.go:437`.

Both are called from the user-delete transaction in each driver (e.g. `store/db/sqlite/user_delete.go:96,102`). There are no `ON DELETE CASCADE` foreign-key rules on the `reaction` table in the migration files — the cleanup is entirely in Go code.
