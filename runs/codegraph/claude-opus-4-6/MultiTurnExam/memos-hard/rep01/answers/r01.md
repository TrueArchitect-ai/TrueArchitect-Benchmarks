**Premise correction:** There is no Redis connection anywhere in this codebase. The cache layer is a **pure in-process Go data structure** — not an external store.

**Actual mechanism:** The cache is implemented in `store/cache/cache.go` as a `Cache` struct backed by a `sync.Map` (line 69) with TTL-based expiration. It is constructed via `cache.NewDefault()` which calls `DefaultConfig()` (line 57), setting:

- **Default TTL: 10 minutes** (line 59) — this applies uniformly to all cached entries, including user objects
- **Cleanup interval: 5 minutes** (line 60) — a background goroutine sweeps expired items on this cadence
- **Max items: 1,000** (line 61) — with LRU-style eviction of the oldest 20% when exceeded

User entries are cached in `store/user.go` via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g., line 98), which calls `Set` → `SetWithTTL` with the default 10-minute TTL. The `userCache` field is a `cache.Interface` on the `Store` struct, initialized with `cache.NewDefault()` in `store/store.go`.

No custom TTL is used for user entries — they share the same 10-minute default as every other cache namespace (settings, etc.).
