Explicit Go code. Reactions are removed in two passes within the `deleteUserTargetsTx` function, which runs inside the user-deletion transaction in all three database drivers:

1. **`deleteReactionsByContentIDsTx`** — deletes all reactions whose `content_id` matches the deleted user's memos (i.e., reactions *on* their content). Evidence: `store/db/mysql/user_delete.go:96`, `store/db/postgres/user_delete.go:96`, `store/db/sqlite/user_delete.go:96`. The SQL is `DELETE FROM reaction WHERE content_id IN (...)` (e.g., `store/db/mysql/user_delete.go:420`).

2. **`deleteReactionsByCreatorTx`** — deletes all reactions *created by* the deleted user (reactions they left on anyone's content). Evidence: `store/db/mysql/user_delete.go:102`, `store/db/postgres/user_delete.go:102`, `store/db/sqlite/user_delete.go:102`. The SQL is `DELETE FROM reaction WHERE creator_id = ?` (e.g., `store/db/mysql/user_delete.go:438`).

Both are called before memo and user row deletion, within the same transaction. This is not relying on database-level CASCADE rules — it is explicit application-level cleanup in Go.
