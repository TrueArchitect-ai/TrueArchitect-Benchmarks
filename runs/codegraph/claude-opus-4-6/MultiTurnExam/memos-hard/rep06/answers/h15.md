Here are the distinct memo visibility enforcement sites:

1. **ListMemos query-level filter** — `server/router/api/v1/memo_service_converter.go:182-186`. Unauthenticated users see only `PUBLIC`; authenticated users see `PUBLIC`, `PROTECTED`, and their own memos. Applied via CEL filter injected into the DB query.

2. **SSE event delivery filter** — `server/router/api/v1/sse_hub.go:134-143`. `canReceive` blocks `PRIVATE` memo events from reaching clients who aren't the creator or an admin.

3. **RSS feed** — `server/router/rss/rss.go:90`. Hard-codes `VisibilityList: []store.Visibility{store.Public}`, so only public memos appear in the feed.

4. **File server (attachment download by memo path)** — `server/router/fileserver/fileserver.go:699`. Blocks non-creator, non-admin users from downloading attachments of `PRIVATE` memos.

5. **Attachment service (gRPC)** — `server/router/api/v1/attachment_service.go:422-455`. `checkAttachmentAccess` enforces memo visibility when fetching linked attachments via the API.

6. **Memo attachment listing** — `server/router/api/v1/memo_attachment_service.go:213-224`. Checks memo visibility before listing a memo's attachments.

7. **Comment creation** — `server/router/api/v1/memo_service_comments.go:33-42`. Blocks commenting on `PRIVATE` memos the user doesn't own.

8. **Reaction listing** — `server/router/api/v1/reaction_service.go:29-41`. Checks memo visibility before returning its reactions.

The core enforcement pattern is consistent: `PUBLIC` is open to everyone, `PROTECTED` requires authentication, `PRIVATE` requires being the creator or an admin. Sites 1 (query filter) and 3 (RSS) enforce at the data-fetch level; the rest enforce at the handler level after fetching the memo.
