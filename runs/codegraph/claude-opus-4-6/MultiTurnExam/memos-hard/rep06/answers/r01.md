The premise is incorrect — there is no Redis connection. The cache layer is purely in-memory, not backed by Redis or any external store.

The cache is implemented in `store/cache/cache.go`, where `Cache` is a generic in-memory structure using a sync.Map (line 187 shows its `Close` method). It is instantiated in `store/store.go:38` inside `New`, which creates caches like `userCache` directly in the `Store` struct.

User entries are cached in `store/user.go` via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g., lines 98, 122, 132, 143, 167). There is no TTL — entries persist in the map until explicitly overwritten (on update/re-fetch) or removed (on delete via `s.deleteUserCache` at line 179). The cache lives for the lifetime of the process and is cleared when `Store.Close` is called.
