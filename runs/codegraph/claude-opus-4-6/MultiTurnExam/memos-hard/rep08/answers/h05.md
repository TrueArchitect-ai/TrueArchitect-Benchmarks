**Mechanism:** Explicit Go code, executed within the same database transaction as the rest of the user deletion.

**Evidence locations:** Each database driver's `deleteUserTargetsTx` function calls two reaction-cleanup helpers:

1. `deleteReactionsByContentIDsTx` — deletes reactions whose `content_id` matches the user's deleted memos (`DELETE FROM reaction WHERE content_id IN ...`):
   - `store/db/sqlite/user_delete.go:96,380-383`
   - `store/db/postgres/user_delete.go:96,380-383`
   - `store/db/mysql/user_delete.go:96,417-420`

2. `deleteReactionsByCreatorTx` — deletes all reactions created by the user (`DELETE FROM reaction WHERE creator_id = ?`):
   - `store/db/sqlite/user_delete.go:102,400-401`
   - `store/db/postgres/user_delete.go:102,400-401`
   - `store/db/mysql/user_delete.go:102,437-438`

Both calls happen inside the transaction opened by `DeleteUser` in each driver, so reactions on the user's memos *and* reactions the user placed on other people's memos are all removed atomically. There is no database-level cascade rule involved — this is purely application-level SQL executed in Go.
