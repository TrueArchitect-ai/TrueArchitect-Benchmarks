**Premise correction:** There is no message broker. Neither NATS nor RabbitMQ is used.

**Actual mechanism:** The webhook delivery workers consume from a plain in-process Go buffered channel — `asyncPostQueue` declared at `internal/webhook/webhook.go:39` as `make(chan *WebhookRequestPayload, 128)`. Four goroutines are spawned in an `init()` function (line 42–55) that range over this channel and call `Post` for each payload. Producers enqueue via `PostAsync` (line 184), which does a non-blocking send and drops the payload with a warning if the channel is full.
