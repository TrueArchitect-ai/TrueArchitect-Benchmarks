**Premise correction:** There is no per-user API rate-limiting middleware in this codebase.

The server registers gRPC/Connect interceptors for authentication (`Authorizer` at `server/router/api/v1/authz.go`) and logging, but no rate-limiting middleware exists. There are no token-bucket, sliding-window, or rate-limit implementations anywhere in the server code. The only concurrency-limiting mechanism is a semaphore for thumbnail generation (`server/router/fileserver/fileserver.go:107`, capped at 3 concurrent operations) and the bounded webhook async queue (128 slots, `internal/webhook/webhook.go:39`), neither of which is per-user API rate limiting.
