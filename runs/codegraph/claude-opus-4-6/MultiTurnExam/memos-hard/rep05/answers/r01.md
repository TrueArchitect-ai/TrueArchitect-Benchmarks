**Premise correction:** There is no Redis connection. The cache layer does not use Redis.

**Actual mechanism:** The cache is an in-process, in-memory implementation — `store/cache/cache.go` — backed by a `sync.Map` with no external dependencies. It provides `Get`, `Set`, and `Delete` operations with no TTL; entries persist in memory until explicitly deleted or the process exits.

User entries are cached in `store/store.go` via `s.userCache` (a `*Cache` instance). They are added/updated on `CreateUser` (line 98), `UpdateUser` (line 132), `ListUsers` (line 142), and `GetUser` (line 167), and evicted on `DeleteUser` via `deleteUserCache`. There is no expiration — entries live for the lifetime of the process.
