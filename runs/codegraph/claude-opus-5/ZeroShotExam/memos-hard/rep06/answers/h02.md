How it fits together:

**Trigger → enqueue.** `server/router/api/v1/memo_service_webhooks.go` has `DispatchMemoCreatedWebhook` / `Updated` / `Deleted` (all funneling through `dispatchMemoRelatedWebhook`, line 48) plus `DispatchMemoCommentCreatedWebhook` (line 30). Each loads the creator's webhooks from the store, builds a `WebhookRequestPayload`, and calls `webhook.PostAsync` (lines 43, 71).

**Enqueue → execute.** `PostAsync` (`internal/webhook/webhook.go:184`) is non-blocking: it pushes onto a buffered `asyncPostQueue` (cap 128) and drops the event with a warn log if full. Four goroutines started in `init()` (line 42) drain the queue and call `Post` — so the actual outbound HTTP POST executes in `Post` at `internal/webhook/webhook.go:120`, on a background worker, not on the request goroutine. `Post` marshals the payload, optionally adds Standard Webhooks HMAC headers (`webhook-id`/`-timestamp`/`-signature`), and issues `safeClient.Do(req)` at line 152.

**SSRF protection — two layers:**

1. *Dial-time (the real guard).* `safeClient` (line 32) is an `http.Client` whose `Transport.DialContext` is `safeDialContext` (line 59). It splits the address, resolves the host via `net.DefaultResolver.LookupHost`, and rejects the connection if **any** resolved IP is reserved. Because this happens at dial time rather than at save time, it also defeats DNS rebinding and covers redirects.
2. *Save-time.* `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`); it requires an absolute http/https URL and rejects hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument`.

Both layers share `isReservedIP` (`internal/webhook/validate.go:44`), which tests against `reservedNetworks` — parsed once at startup from `reservedCIDRs` (lines 14-23): IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), and the IPv6 equivalents `::1/128`, `fc00::/7`, `fe80::/10`.

Two things worth flagging: the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` entirely, and per CHANGELOG.md:121 it was meant to be driven by a `--allow-private-webhooks` flag — but in the current tree nothing outside `internal/webhook/webhook_test.go` ever assigns it, so the flag wiring appears to be gone and it is effectively always `false`. Also, the CIDR list omits `0.0.0.0/8`, `100.64.0.0/10` (CGNAT), and IPv4-mapped IPv6 forms like `::ffff:127.0.0.1`, which `net.IPNet.Contains` would not match against the IPv6 entries.
