**Premise correction:** There is no Redis anywhere in this repository. `grep -ri redis` over the Go, TypeScript, YAML, and module files returns nothing — no `go-redis` dependency, no connection string, no `REDIS_*` env var. The cache layer is a purely in-process, in-memory implementation, so there is no connection to configure at all.

**Actual mechanism**

*Cache implementation* — `store/cache/cache.go`: a `Cache` struct backed by a `sync.Map` plus an atomic item counter (`store/cache/cache.go:66-73`). Each entry (`item`, line 35) carries a value, an absolute `expiration` timestamp, and an estimated size. `New(config)` (line 76) starts a background `cleanupLoop` goroutine that ticks on `CleanupInterval` and sweeps expired entries; `Close()` (line 187) stops it. Expiry is also checked lazily on read in `Get` (line 135). Over-capacity triggers `cleanupOldest`, which drops ~20% of `MaxItems` (line 253).

*Where it's "configured"* — `store.New` in `store/store.go:38-61`. One `cache.Config` literal is built inline and shared by three separate cache instances:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
...
instanceSettingCache: cache.New(cacheConfig),
userCache:            cache.New(cacheConfig),
userSettingCache:     cache.New(cacheConfig),
```

These values are hardcoded — not read from env, flags, or `internal/profile`. `cache.DefaultConfig()` (`store/cache/cache.go:57`) duplicates the same numbers for standalone use via `NewDefault()`.

**TTL for user entries: 10 minutes.** Every user write path calls `s.userCache.Set(...)` (`store/user.go:98`, `:122`, `:132`, `:143`, `:167`), and `Set` delegates to `SetWithTTL(..., c.config.DefaultTTL)` (`store/cache/cache.go:93-95`) — so users get the 10-minute default. Nothing in the user path calls `SetWithTTL` with a custom duration. Keys are the stringified user ID (`userCacheKey`, `store/user.go:88`); `GetUser` only consults the cache when looked up by ID (`store/user.go:149-156`). Invalidation on delete is explicit via `deleteUserCache` (`store/user_delete.go:39-47`), which also clears that user's setting-cache entries.

User *settings* share the same 10-minute TTL through `userSettingCache` (`store/user_setting.go:59`, `:78`, `:106`), keyed `"<userID>-<settingKey>"` (`store/cache.go:7`).

**Unrelated, separate cache:** the RSS feed cache in `server/router/rss/rss.go` is its own hand-rolled `map[string]*cacheEntry` guarded by a `sync.RWMutex` — it does not use `store/cache` and has a **1-hour** TTL (`defaultCacheDuration`, `server/router/rss/rss.go:25`) with a 50-entry cap. Its per-user feed entries (key `"user:"+username`, line 114) expire after 1 hour, which is the one place a "user entry" carries a different TTL.
