**No** — outside the factory, nothing in production code constructs the MySQL driver; the only direct construction is a zero-value struct in one of the driver package's own unit tests.

Evidence:

1. **Factory is the sole constructor call site.** `mysql.NewDB(profile)` is called exactly once in the repo, at `store/db/db.go:22`, inside `NewDBDriver` (the `switch profile.Driver` selector alongside `sqlite.NewDB` and `postgres.NewDB`).

2. **The package is imported exactly once.** A grep for the import path `github.com/usememos/memos/store/db/mysql` matches only `store/db/db.go:8`. Since `DB` and `NewDB` live in that package, no other package can construct it — including the server entrypoint `cmd/memos/main.go:57` and the test helpers `store/test/store.go:28,50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70`, all of which go through `db.NewDBDriver`.

3. **Direct struct literals.** `grep "DB{" store/db/mysql/*.go` yields two hits:
   - `store/db/mysql/mysql.go:29` — `driver := DB{profile: profile}`, i.e. inside `NewDB` itself.
   - `store/db/mysql/auth_config_test.go:12` — `db := &DB{}`, an in-package test that builds an empty, unconnected struct only to call the pure helper `IsRetryableAuthenticationMutationError`. This is the one construction outside the factory path, and it never opens a connection.

One thing not to confuse with the above: `store/test/containers.go:145` calls `sql.Open("mysql", dsn)` and `containers.go:363` calls `mysqldriver.ParseDSN`. Those use the third-party `go-sql-driver/mysql` package for testcontainer setup, not memos' own `store/db/mysql.DB` driver.
