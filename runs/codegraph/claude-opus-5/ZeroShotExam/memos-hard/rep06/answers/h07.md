The URL a browser loads for another user's avatar is `/file/users/{username}/avatar` (minted server-side when the user proto is built, because raw base64 avatars are stripped from API responses). The chain:

**URL origin (why the browser requests it)**
- `convertUserToProto` (sets `AvatarUrl = "/file/%s/avatar"` from `users/{username}`) — server/router/api/v1/user_service_converters.go:31-37
- `UserAvatar` (`<img src={avatarUrl}>`) — web/src/components/UserAvatar.tsx:9-14

**Request path to stored data**
- `shouldSkipFrontendStatic` (lets `/file/...` bypass the embedded-SPA static/fallback middleware) — server/router/frontend/frontend.go:82-90
- `FileServerService.RegisterRoutes` (`fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)`, registered from `NewServer` at server/server.go:81-82) — server/router/fileserver/fileserver.go:121-125
- `FileServerService.serveUserAvatar` (handler) — server/router/fileserver/fileserver.go:168-210
- `FileServerService.getCurrentUser` → `Authenticator.AuthenticateToUser` (only on a private instance, i.e. `!Profile.AllowAnonymous()`) — server/router/fileserver/fileserver.go:708-712 → server/auth/authenticator.go:190
- `FileServerService.getUserByUsername` (builds `store.FindUser{Username: &identifier}`) — server/router/fileserver/fileserver.go:715-717
- `Store.GetUser` (user cache is keyed by ID only, so a username lookup always falls through) — store/user.go:148-169
- `Store.ListUsers` → `s.driver.ListUsers` — store/user.go:136-146
- `Driver.ListUsers` (interface dispatch) — store/driver.go:47
- `DB.ListUsers` (`SELECT ... avatar_url ... FROM user WHERE username = ?`, `db.QueryContext` + `rows.Scan` into `user.AvatarURL`) — store/db/sqlite/user.go:88-198 (same shape in store/db/postgres/user.go:87 and store/db/mysql/user.go:84)

**Back out to the response**
- `FileServerService.parseDataURI` (decodes the stored `data:image/...;base64,...` value) — server/router/fileserver/fileserver.go:737-750
- `avatarAllowedTypes` gate + `setSecurityHeaders` + `c.Blob` — server/router/fileserver/fileserver.go:75-83, 758-763, 201-209

Note the data layer here is the `user.avatar_url` column itself — avatars are stored inline as base64 data URIs, not as attachment blobs on disk/S3.
