**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package:** `internal/idp` — `internal/idp/idp.go` is the whole package: it declares the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider implementation must produce, so callers depend on this type rather than on a protocol-specific shape.
- **Implementation package:** `internal/idp/oauth2` — `internal/idp/oauth2/oauth2.go` ("Package oauth2 implements the OAuth2 identity provider integration") defines the concrete `IdentityProvider` struct over `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (incl. PKCE `code_verifier`), and `UserInfo`, which maps provider claims into `idp.IdentityProviderUserInfo` via the configured field mapping.

OAuth2 is the only protocol that ships: the proto enum `IdentityProvider_Type` has just `TYPE_UNSPECIFIED` and `OAUTH2`, and `IdentityProviderConfig` is a oneof containing only `oauth2_config` (`proto/gen/api/v1/idp_service.pb.go`, `proto/gen/store/idp.pb.go`). The admin UI templates (GitHub, GitLab, Google, Custom) are all `IdentityProvider_Type.OAUTH2` in `web/src/components/CreateIdentityProviderDialog.tsx`; wiring into auth lives in `server/router/api/v1/idp_service.go`.
