Memo visibility is enforced independently in many places — there is no single chokepoint. The distinct sites, grouped by surface:

**Core memo API (Connect/gRPC v1)**
`APIV1Service.checkMemoReadAccess` — the single-memo read gate (used by GetMemo, parent-memo lookup, ListMemoComments) — `server/router/api/v1/memo_service.go:39-67` (callers at `:356`, `:367`, `server/router/api/v1/memo_service_comments.go:148`)
`APIV1Service.ListMemos` visibility/CEL filter injection (anonymous → PUBLIC; user → `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:217-227`
`APIV1Service.ListMemoComments` per-comment memo filter (separate from the parent gate above) — `server/router/api/v1/memo_service_comments.go:156-161`
`APIV1Service.CreateMemoComment` private-parent gate (and comment inherits parent visibility) — `server/router/api/v1/memo_service_comments.go:33-52`
`APIV1Service.ListMemoRelations` related-memo filter — `server/router/api/v1/memo_relation_service.go:107-112`
`APIV1Service.GetMemoByShare` — share-token path that deliberately bypasses visibility (only expiry/archived checked) — `server/router/api/v1/memo_share_service.go:152-190`

**Reactions**
`ListMemoReactions` visibility gate — `server/router/api/v1/reaction_service.go:29-41`
`UpsertMemoReaction` private-memo gate — `server/router/api/v1/reaction_service.go:82-85`

**Attachments**
`ListMemoAttachments` visibility gate — `server/router/api/v1/memo_attachment_service.go:213-226`
`APIV1Service.checkAttachmentAccess` — visibility of the linked memo governs the attachment — `server/router/api/v1/attachment_service.go:422-455`
`FileServerService.checkAttachmentPermission` — raw HTTP file serving (`/file/...`), including anonymous-instance and `share_token` fallbacks — `server/router/fileserver/fileserver.go:650-703`

**Stats**
`ListAllUserStats` visibility filter — `server/router/api/v1/user_service_stats.go:82-92`
`GetUserStats` visibility filter — `server/router/api/v1/user_service_stats.go:216-221`

**Realtime / notifications**
`SSEClient.canReceive` — server-side delivery filtering of broadcast memo events — `server/router/api/v1/sse_hub.go:134-142` (visibility carried on the event at `sse_hub.go:31-32`, `sse_event_helpers.go:29-37`)
`canViewerAccessMemo` for inbox/user notifications — `server/router/api/v1/user_service_notifications.go:302-316`
`canViewerAccessMemo` for email notifications (a second, duplicate copy) — `server/notification/email.go:306-319`
`canUserAccessMentionContext` / `shouldSkipMentionInbox` — mention fan-out — `server/router/api/v1/memo_mention_helpers.go:56-89`

**Public/unauthenticated surfaces (hardcoded PUBLIC-only)**
RSS feeds (instance and per-user) — `server/router/rss/rss.go:90`, `server/router/rss/rss.go:141`
Sitemap XML — `server/router/frontend/frontend.go:148-152`

The `VisibilityList`/`Filters` set at these call sites are ultimately translated to SQL in the store drivers (`store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`), but the store itself applies no default — it enforces only what a caller passes, so each site above is genuinely independent.
