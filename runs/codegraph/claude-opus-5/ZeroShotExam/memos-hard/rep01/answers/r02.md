**Premise correction: this repo has no per-user API rate-limiting middleware.** There is no requests-per-second/per-minute limiter of any kind — not per user, not per IP, not global. Nothing is registered anywhere in the middleware or interceptor chain, and there is no rate-limiting dependency in `go.mod` (no `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, etc.).

What actually exists in the request pipeline:

**Echo middleware** (`server/server.go:51-52`) — only two entries: `middleware.Recover()` and `newCORSMiddleware(profile)`.

**Connect RPC interceptors** (`server/router/api/v1/v1.go:133-138`) — four, in order:
- `NewMetadataInterceptor()` — copies HTTP headers into gRPC metadata
- `NewLoggingInterceptor(logStacktraces)`
- `NewRecoveryInterceptor(logStacktraces)`
- `NewAuthInterceptor(authorizer)` — authentication/anonymous-access policy only

All four are defined in `server/router/api/v1/connect_interceptors.go`; none tracks per-user request counts or time windows.

**The limits that do exist are different in kind** — request *size* caps and concurrency semaphores, all process-wide rather than per user:

| Limit | Value | Location |
|---|---|---|
| Max API request body | 256 MiB (`256 << 20`) | `server/router/api/v1/v1.go:20`, applied at `:126`, `:141`, `:144` |
| Concurrent EXIF-strip image processing | 2 | `server/router/api/v1/v1.go:60` |
| Concurrent thumbnail generation (API) | 3 | `server/router/api/v1/v1.go:59` |
| Concurrent thumbnail generation (file server) | 3 (`maxConcurrentThumbnails`) | `server/router/fileserver/fileserver.go:46`, `:116` |
| Max image pixel count | 50,000,000 | `server/router/api/v1/attachment_service.go:36` |

The one place a client can see a "too many requests"-style error is `server/router/api/v1/attachment_service.go:160`, which returns `codes.ResourceExhausted` with the message `"too many image processing requests"`. That fires when `acquireImageProcessingSlot` (`server/router/api/v1/attachment_service_image.go:67-77`) fails to acquire the shared 2-slot semaphore — a global concurrency backpressure signal during a single upload, not a per-user request quota. Two concurrent uploads from *any* users occupy both slots.
