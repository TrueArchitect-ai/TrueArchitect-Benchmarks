**1st: `User` (~7 packages); 2nd: `Memo` (~6 packages)**

The data layer is the `store/` package, where persistent entities are defined: `User` (`store/user.go:29`), `Memo` (`store/memo.go:35`), `Attachment` (`store/attachment.go:16`), plus `Inbox`, `Reaction`, `MemoRelation`, `MemoShare`, `UserIdentity`, `UserSetting`, `InstanceSetting`, `IdentityProvider`.

Counting distinct packages outside `store/...` that reference each type:

| Type | Packages outside `store/` | Refs |
|---|---|---|
| `store.User` | 7 — `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss` | ~99 |
| `store.Memo` | 6 — `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload` | ~73 |
| `store.Attachment` | 4 — `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/rss` | ~43 |

The ordering holds if you exclude the `server/router/api/v1/test` package as well (User: 6, Memo: 5, Attachment: 3). `User` leads because it's the only entity reaching the auth layer (`server/auth`) in addition to every route surface.

Two notes on scope:
- Packages *inside* the data layer (`store/db/{sqlite,postgres,mysql}`, `store/test`) were excluded; including them doesn't change the ranking.
- `UserSetting`, `InstanceSetting`, and `IdentityProvider` have zero references outside the data layer — server code consumes their protobuf counterparts (`proto/gen/store`) instead of the Go store structs.
