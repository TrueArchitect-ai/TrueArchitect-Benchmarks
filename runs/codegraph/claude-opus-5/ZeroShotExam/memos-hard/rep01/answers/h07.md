Key detail: an avatar is **not** an attachment — it is stored inline in the `user.avatar_url` column as a `data:<mime>;base64,...` URI (`store.User.AvatarURL`, `store/user.go:43`). So the data layer is a single user-row read; there is no local-disk or S3 hop, unlike `serveAttachmentFile` (`server/router/fileserver/fileserver.go:132`). The decoded MIME type is then checked against `avatarAllowedTypes` before the bytes are written.
