**Premise correction: there is no nightly database-cleanup job in this repository.** `internal/scheduler` is a standalone, generic cron-scheduler *library* — it defines the machinery (`Scheduler`, `Job`, cron parser, middleware) but registers no jobs of its own, and nothing outside the package imports it. The only callers of `Scheduler.Register` are the package's own tests and doc comments (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`, `internal/scheduler/doc.go`), so no cleanup job — database-related or otherwise — actually runs anywhere in the application.

What likely prompted the premise are cleanup jobs that appear only as illustrative examples:

- `internal/scheduler/doc.go:15-16` — `"daily-cleanup"` at `"0 2 * * *"` (2 AM), in a package doc comment
- `internal/scheduler/README.md:34-35` — the same `"daily-cleanup"` / `"0 2 * * *"` snippet
- `internal/scheduler/example_test.go:97-100` — a job named `"cleanup"` at `"0 2 * * *"`, commented "Cleanup old data every night at 2 AM"
- `internal/scheduler/README.md:241-244` — `"stale-session-cleanup"` at `"0 3 * * *"` (3 AM), a best-practices snippet

None of these touch a database; they print strings or reference an undefined `cleanupSessions` handler. If you're after real database maintenance, the scheduler package isn't wired into the server at all — the actual DB layer lives under `store/` with no scheduled-job entry point.
