**Premise correction:** There is no Redis anywhere in this repository — no `redis` import, dependency in `go.mod`/`go.sum`, config key, or docs mention (a case-insensitive grep across the whole tree returns nothing). There is no connection to configure, and therefore no Redis-side TTL on user entries.

**Actual mechanism**

Caching is entirely **in-process, in-memory**, implemented in `store/cache/cache.go`:

- `Cache` (store/cache/cache.go:67) is a thread-safe `sync.Map` with per-item `expiration` (`item`, store/cache/cache.go:35-39) and an atomic item counter. It satisfies the `Interface` at store/cache/cache.go:11 (`Set`, `SetWithTTL`, `Get`, `Delete`, `Clear`, `Size`, `Close`).
- Expiry is lazy-plus-sweep: `New` starts `cleanupLoop` (store/cache/cache.go:76-85, 200), which ticks on `CleanupInterval` and calls `cleanup` (store/cache/cache.go:218) to drop expired entries.

**Where it's "configured"** — `store.New` in `store/store.go:38-58`, not a connection string:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

Three separate caches share that one config: `instanceSettingCache`, `userCache`, `userSettingCache` (store/store.go:27-29, 51-53), each closed in `Store.Close` (store/store.go:73-76). `cache.DefaultConfig()` (store/cache/cache.go:57-64) holds identical values but is only used via `NewDefault`.

**TTL for user entries: 10 minutes.** `Store.CreateUser`, `CreateUserIfNoUsers`, `UpdateUser`, `ListUsers`, and `GetUser` all call `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (store/user.go:98, 122, 132, 143, 167), and `Set` delegates to `SetWithTTL` with `c.config.DefaultTTL` (store/cache/cache.go:93-95) — i.e. 10 minutes. No user-cache call site passes a custom TTL. Cache keys are just the stringified user ID (`userCacheKey`, store/user.go:88), so `GetUser` only hits cache when looked up by `ID`; lookups by username/email always fall through to the DB. Invalidation is explicit on delete via `deleteUserCache` (store/user_delete.go:39), and user settings use a separate key format `"<userID>-<key>"` (`getUserSettingCacheKey`, store/cache.go:7) in `userSettingCache` — also 10 minutes.

One unrelated cache worth distinguishing: the RSS feed cache in `server/router/rss/rss.go` is a hand-rolled `map[string]*cacheEntry` guarded by a mutex, with its own `defaultCacheDuration = 1 * time.Hour` and `maxCacheSize = 50` (server/router/rss/rss.go:23-27, 347-400). It does not use `store/cache` and is not Redis either.
