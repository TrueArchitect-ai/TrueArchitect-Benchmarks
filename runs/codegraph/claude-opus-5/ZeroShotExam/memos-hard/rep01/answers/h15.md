h15.

Memo visibility is **not** centralized — each server surface re-implements the PUBLIC / PROTECTED / PRIVATE rule independently. Distinct enforcement sites:

**Connect/gRPC API v1 — single-memo read gate**
`checkMemoReadAccess` (archived → creator-only; non-public → auth required; private → creator only) — `server/router/api/v1/memo_service.go:39-66`, called from `GetMemo` (+ parent memo) at `:355`/`:367` and `ListMemoComments` at `server/router/api/v1/memo_service_comments.go:148`

**Connect/gRPC API v1 — list/query-side filter**
`ListMemos` builds `VisibilityList` / a `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` CEL filter — `server/router/api/v1/memo_service.go:216-228`

**Related-memo / comment-relation filters (own copy of the same predicate)**
`server/router/api/v1/memo_relation_service.go:105-112`, `server/router/api/v1/memo_service_converter.go:180-190`, `server/router/api/v1/memo_service_comments.go:158-165`

**Reactions** — inline visibility check in `ListMemoReactions` and `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:29-41, 83`

**Comment creation** — parent-memo visibility check — `server/router/api/v1/memo_service_comments.go:34-42`

**Memo attachment listing** — inline check in `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:213-225`

**Attachment API access** — `checkAttachmentAccess` derives permission from the owning memo's visibility — `server/router/api/v1/attachment_service.go:422-455`

**Raw file server (`/file/...` binary serving)** — `checkAttachmentPermission`, including the anonymous-instance rule and the `share_token` bypass — `server/router/fileserver/fileserver.go:650-704`

**User stats** — visibility scoping for `GetUserStats` / `ListAllUserStats` — `server/router/api/v1/user_service_stats.go:82-92, 215-221`

**Share-token path (deliberate bypass of the above)** — `GetMemoByShare` returns any non-archived memo for a valid, unexpired token — `server/router/api/v1/memo_share_service.go:153-207`

**SSE broadcast fan-out** — `SSEClient.canReceive` decides which connected clients see a memo event — `server/router/api/v1/sse_hub.go:134-144`

**RSS feeds** — hard-restricted to `store.Public` — `server/router/rss/rss.go:90, 141`

**Sitemap** — public-only memo listing — `server/router/frontend/frontend.go:148-152`

**Notification rendering** — `canViewerAccessMemo` gates memo snippets in notifications — `server/router/api/v1/user_service_notifications.go:302-316`; email notifications repeat the rule at `server/notification/email.go:311-318`; mention-notification eligibility at `server/router/api/v1/memo_mention_helpers.go:62-84`

Note: the MCP surface (`server/router/mcp/catalog.go:12,14`) is not a separate site — it dispatches to the same `MemoService_ListMemos` / `MemoService_GetMemo` handlers. The store layer (`store/memo.go`, `store/db/*/memo.go`) only applies whatever `VisibilityList`/filters callers pass; it enforces nothing on its own.
