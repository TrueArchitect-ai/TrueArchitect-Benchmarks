h15.

Memo visibility is enforced in **fifteen** distinct places across five server surfaces (Connect/gRPC API, HTTP file server, RSS, sitemap, SSE broadcast, notifications). There is no single chokepoint — each site re-implements the PUBLIC / PROTECTED / PRIVATE rule.

**Connect/gRPC API — per-memo read gate**
`checkMemoReadAccess` (single-memo gate: archived → creator only; non-public → authed; private → creator) — `server/router/api/v1/memo_service.go:39-68`, called from `GetMemo` (self + parent memo) at `memo_service.go:356,367` and `ListMemoComments` at `server/router/api/v1/memo_service_comments.go:148`

**Connect/gRPC API — query scoping (store-level `VisibilityList` / CEL filter)**
`ListMemos` visibility scoping — `server/router/api/v1/memo_service.go:218-226`
`ListMemoComments` comment sub-query filter — `server/router/api/v1/memo_service_comments.go:157-161`
`batchConvertMemoRelations` relation-target filter — `server/router/api/v1/memo_service_converter.go:183-187`
`ListMemoRelations` filter — `server/router/api/v1/memo_relation_service.go:108-112`
`ListAllUserStats` / `GetUserStats` — `server/router/api/v1/user_service_stats.go:84-92` and `:217-221`

**Connect/gRPC API — inline re-implementations on memo-adjacent RPCs**
`ListMemoReactions` + `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:29-41` and `:83-85`
`CreateMemoComment` (private-parent gate; comment inherits parent visibility) — `server/router/api/v1/memo_service_comments.go:34-42`
`ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:213-225`
`checkAttachmentAccess` (attachment RPCs inherit linked memo's visibility) — `server/router/api/v1/attachment_service.go:422-455`
`GetMemoByShare` (share-token path deliberately *bypasses* visibility; only archived/missing are rejected) — `server/router/api/v1/memo_share_service.go:153-192`

**HTTP file server (raw attachment bytes, separate auth stack)**
`checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650-703` (public + `AllowAnonymous`, else share-token fallback at `:684`, else authed and private → creator/admin)

**SSE broadcast fan-out**
`SSEClient.canReceive` — `server/router/api/v1/sse_hub.go:134-143` (private events only to creator or admin)

**Unauthenticated HTTP feeds**
RSS `GetExploreRSS` / `GetUserRSS` — `server/router/rss/rss.go:90` and `:141` (`VisibilityList: {Public}`)
Sitemap `getSitemapXML` — `server/router/frontend/frontend.go:150` (`VisibilityList: {Public}`)

**Notification / mention delivery (controls who sees memo content in an inbox or email)**
`canViewerAccessMemo` — `server/router/api/v1/user_service_notifications.go:302-316`
`canViewerAccessMemo` (duplicate, email path) — `server/notification/email.go:306-320`
`canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-89`

Underlying mechanism (not policy): `store.FindMemo.VisibilityList` at `store/memo.go:69`, translated to SQL in `store/db/sqlite/memo.go`, `store/db/mysql/memo.go:104-111`, `store/db/postgres/memo.go:89-96`.

Two notes worth flagging: the notification rule is duplicated verbatim in two files (`user_service_notifications.go` uses `isSuperUser`, `email.go` inlines `Role == RoleAdmin`), and the API-level checks treat PROTECTED as "any authenticated user" while several inline copies omit the archived-memo check that `checkMemoReadAccess` performs.
