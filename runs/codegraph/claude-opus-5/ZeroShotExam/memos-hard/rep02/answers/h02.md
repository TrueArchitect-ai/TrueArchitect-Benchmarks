How it fits together:

**Delivery path**
- Memo create/update/delete and comment events build payloads and call `webhook.PostAsync` — `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.
- `PostAsync` (`internal/webhook/webhook.go:184`) is non-blocking: it enqueues onto a buffered channel (`asyncPostQueue`, cap 128) and drops with a warning if full.
- Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post`.
- `Post` (`internal/webhook/webhook.go:120`) is where the actual outbound HTTP request happens: marshals JSON, optionally adds Standard-Webhooks HMAC headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), then `safeClient.Do(req)` at `internal/webhook/webhook.go:152`, with a 1 MiB limited response read.

**SSRF protection — two layers**
1. *Dial-time (the real enforcement).* `safeClient` is an `http.Client` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`:59-77`) resolves the host itself and refuses to dial if **any** resolved IP falls in a reserved range. Because the check happens at dial time on the addresses actually used, it also defeats DNS rebinding — the comment at `:29-31` says so explicitly. This covers redirects too, since every connection the transport makes goes through it.
2. *Admission-time (fail-fast UX).* `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a user creates or updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. It requires an absolute http/https URL and rejects hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument`. This is TOCTOU-vulnerable on its own; layer 1 is what makes it safe.

The blocklist (`reservedCIDRs`, `internal/webhook/validate.go:14-23`) covers IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` (cloud IMDS at 169.254.169.254), and the IPv6 equivalents `::1/128`, `fc00::/7`, `fe80::/10`. Parsed once into `reservedNetworks` at startup.

**One thing worth flagging:** the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both layers when true — `isReservedIP` short-circuits to `false`. Its doc comment describes it as being for self-hosted deployments targeting local services, but grep shows no assignment anywhere in non-test code: no CLI flag, env var, or config wiring sets it. It is currently dead configuration that always stays at the zero value `false`, so protection is unconditionally on.

Gaps in coverage: `reservedCIDRs` omits some ranges an SSRF blocklist often includes — `0.0.0.0/8`, `100.64.0.0/10` (CGNAT), `192.0.0.0/24`, and IPv4-mapped IPv6 (`::ffff:127.0.0.1` parses to a 4-in-6 IP; `net.IPNet.Contains` does normalize that against IPv4 CIDRs, so that specific case is handled). Also, `ValidateURL` has no covering tests per the index, though `Post`'s signing behavior does (`internal/webhook/webhook_test.go`).
