**No** — the MySQL driver is never constructed outside the driver-selection factory (in non-test production code, the factory is its only construction site).

Evidence:

1. **The factory is the sole caller.** `store/db/db.go:22` — `NewDBDriver` switches on `profile.Driver` and calls `mysql.NewDB(profile)` for the `"mysql"` case (alongside `sqlite.NewDB` and `postgres.NewDB`).

2. **`store/db/db.go` is the only file in the repo that imports the mysql driver package.** A repo-wide grep for the import path `github.com/usememos/memos/store/db/mysql` across all `.go` files returns exactly one hit: `store/db/db.go:8`. Since `mysql.DB` and `mysql.NewDB` can only be referenced through that import, no other package can construct it.

3. **Only one external reference to the constructor exists.** Grepping for `mysql.NewDB`, `mysql.DB{`, `&mysql.DB`, and `new(mysql.DB)` yields a single match: `store/db/db.go:22`. CodeGraph agrees — `NewDB` at `store/db/mysql/mysql.go:20` has exactly 1 caller, in `store/db/db.go`.

4. **Inside the package**, the only real construction is `driver := DB{profile: profile}` at `store/db/mysql/mysql.go:29`, i.e. within `NewDB` itself.

One qualification worth noting: there is one in-package construction outside `NewDB`, in a unit test — `store/db/mysql/auth_config_test.go:12` does `db := &DB{}`. That is a zero-value struct with no `*sql.DB` and no config, used purely to invoke the pure method `IsRetryableAuthenticationMutationError` on MySQL error codes; it never opens a connection and is not reachable from production code.

Callers of the factory itself are `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` — all of which go through `NewDBDriver` rather than touching the MySQL driver directly.
