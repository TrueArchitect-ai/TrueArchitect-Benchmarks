**The premise is incorrect — there is no nightly database-cleanup job in this repository.**

What actually exists:

- `internal/scheduler/` is a standalone, generic cron-scheduler *library* (`doc.go:1`: "Package scheduler provides a GitHub Actions-inspired cron job scheduler"). It defines `Job`, `Scheduler`, and a cron parser (`internal/scheduler/job.go`, `scheduler.go`, `parser.go`, `middleware.go`).
- **Nothing in the application registers any job with it.** Outside of `internal/scheduler/` itself, the package is never imported — the only `scheduler.New(...)`/`Register(...)` calls in the tree are in `internal/scheduler/example_test.go` and the package's own tests. So the scheduler is never started, and there are zero real scheduled jobs — cleanup or otherwise.

The likely source of the "2 AM nightly cleanup" impression is documentation and test fixtures, not a live job:

- `internal/scheduler/doc.go:14-16` — a doc-comment usage example registering a job named `"daily-cleanup"` with `Schedule: "0 2 * * *", // 2 AM daily`.
- `internal/scheduler/example_test.go:100` — a runnable `Example` using the same `"0 2 * * *"` schedule, alongside other illustrative schedules (`0 9 * * *` at line 42, `0 1 * * 0` at line 122, etc.).

Both are illustrative examples with no-op handlers; neither touches the database. There is also no cron entry elsewhere (no crontab, no k8s CronJob, no scheduled GitHub workflow doing DB cleanup) — the only real background runners are `server/runner/memopayload` and `server/runner/s3presign`, which are not cron-scheduled through this package.

If you want an actual nightly DB-cleanup job, the library is ready to use but the wiring (registering the job and calling `Start()` during server bootstrap) would need to be added.
