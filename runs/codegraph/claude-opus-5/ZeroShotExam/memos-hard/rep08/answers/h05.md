**Mechanism: explicit Go code** — a per-driver `DELETE FROM reaction` inside the user-deletion transaction. There is no DB-level rule (no foreign key, no cascade, no trigger) on the `reaction` table.

**What I checked**

1. **The delete path.** `store.Store.DeleteUser` (`store/user.go:171`) delegates to the driver's `DeleteUser`, which opens a transaction and calls `deleteUserTargetsTx` — identical structure in all three drivers (`store/db/sqlite/user_delete.go:29,92`, `store/db/postgres/user_delete.go:29,92`, `store/db/mysql/user_delete.go:29,92`).

2. **Two explicit reaction deletes**, ordered first in `deleteUserTargetsTx` (lines 96 and 102 in each driver file):
   - `deleteReactionsByContentIDsTx` — `DELETE FROM reaction WHERE content_id IN (...)`, removing *all* reactions (including other users') on the deleted user's memo subtree. sqlite:380, postgres:380, mysql:417.
   - `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?`, removing the user's own reactions on anyone's memos. sqlite:400, postgres:400, mysql:437.

3. **Schema — no DB-level rule.** The `reaction` table in all three `LATEST.sql` files declares only `id`, `created_ts`, `creator_id`, `content_id`, `reaction_type` and a `UNIQUE(creator_id, content_id, reaction_type)` constraint — `creator_id` is a plain `INTEGER`/`INT` with no `REFERENCES user(id)`: `store/migration/sqlite/LATEST.sql:92`, `store/migration/mysql/LATEST.sql:91`, `store/migration/postgres/LATEST.sql` (same block). Same in the original `0.20/00__reaction.sql` migrations. A repo-wide grep for `REFERENCES|CASCADE|TRIGGER` in `store/migration/` shows cascades only on `memo_share`, `memo_resource`, and legacy tables — never `reaction`.

4. **Even existing FKs wouldn't fire on SQLite:** the connection is opened with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so cascade enforcement is off entirely. Reinforces that cleanup must be, and is, done in Go.

5. **Test coverage** confirms both behaviors: `store/test/user_delete_test.go` seeds reactions (lines 97–112) and asserts a peer's reaction on an unrelated memo survives while the rest are gone (lines 217–220). API-level tests also exercise the tolerance path for orphaned reactions (`server/router/api/v1/test/reaction_service_test.go`).
