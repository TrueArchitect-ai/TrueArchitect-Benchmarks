**1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages)**

The data layer is the `store/` package (Go), where persistent entity types are defined — `User` (`store/user.go:29`), `Memo` (`store/memo.go:35`), `Attachment` (`store/attachment.go:16`), `Inbox`, `Reaction`, `MemoRelation`, `MemoShare`, `UserIdentity`, `UserSetting`, `IdentityProvider`, `InstanceSetting`.

Counting distinct Go packages outside the `store/` tree (i.e., excluding the driver packages `store/db/{sqlite,postgres,mysql}` and `store/test`, which are part of the data layer itself) that reference each type:

| Type | Packages | Where |
|---|---|---|
| `store.User` | 7 | `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss` |
| `store.Memo` | 6 | `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload` |
| `store.Attachment` | 4 | `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/rss` |

The ranking is the same if you drop the `*/test` package from each count (User 6, Memo 5). By raw occurrence count the ordering also holds: `store.User` ~99 references vs `store.Memo` ~73, with `server/router/api/v1` (`server/router/api/v1/user_service.go`, `memo_service.go`, etc.) dominating both.

Note: `store.UserSetting`, `store.IdentityProvider`, and `store.InstanceSetting` show a match in `proto/gen/store` only because that generated package is itself named `store` (`proto/gen/store/*.pb.go`) — not a genuine cross-package reference to the data-layer type.
