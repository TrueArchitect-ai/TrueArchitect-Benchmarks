h15.

Memo visibility is enforced at **nine distinct server surfaces** (plus a share-token bypass). Grouped by the decision they make:

**Core gRPC/Connect memo service (`server/router/api/v1/`)**

`checkMemoReadAccess` — shared single-memo read gate (public→open, protected→any authed user, private→creator only; archived→creator only); called by `GetMemo` (+ its parent memo), `ListMemoComments` — server/router/api/v1/memo_service.go:39-66, 356, 367; server/router/api/v1/memo_service_comments.go:148
`ListMemos` query scoping — anonymous gets `VisibilityList = [PUBLIC]`; authed gets CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` — server/router/api/v1/memo_service.go:217-227
Sub-resource inline checks — duplicated `if memo.Visibility != Public { … Private && CreatorID != user.ID && !isSuperUser }` blocks, one per RPC:
  · `ListMemoReactions` / `UpsertMemoReaction` — server/router/api/v1/reaction_service.go:29-41, 83
  · `CreateMemoComment` (parent memo) — server/router/api/v1/memo_service_comments.go:33-43
  · `ListMemoAttachments` — server/router/api/v1/memo_attachment_service.go:213-226
  · `checkAttachmentReadAccess` (linked attachment) — server/router/api/v1/attachment_service.go:436-454
Relation/comment list SQL filter — `MemoFilter` string pushed into the store so private/protected relations are dropped in SQL — server/router/api/v1/memo_relation_service.go:107-112; server/router/api/v1/memo_service_comments.go:155-161
User stats scoping — same VisibilityList/CEL pattern for `GetUserStats` and `ListAllUserStats` — server/router/api/v1/user_service_stats.go:77-92, 217-222
SSE broadcast gate — `SSEClient.canReceive`: private events only to creator or admin — server/router/api/v1/sse_hub.go:133-143 (visibility stamped in server/router/api/v1/sse_event_helpers.go:29-37)
Notification visibility — `canViewerAccessMemo` gates notification content; `canUserAccessMentionContext` gates mention inbox/email delivery — server/router/api/v1/user_service_notifications.go:302-316; server/router/api/v1/memo_mention_helpers.go:56-89; and a **second independent copy** in server/notification/email.go:306-320

**Non-gRPC HTTP surfaces**

Raw file/attachment server (Echo) — its own check, independent of the API service, incl. anonymous-instance rule and admin bypass — server/router/fileserver/fileserver.go:666-703
RSS feeds — hard-scoped to `VisibilityList = [PUBLIC]` for both explore and per-user feeds — server/router/rss/rss.go:90, 141
Sitemap — hard-scoped to `VisibilityList = [PUBLIC]` — server/router/frontend/frontend.go:149-151

**Bypass (intentional)**

Share links — `GetMemoByShare` resolves an opaque token and skips visibility entirely (only archived/missing are rejected); the file server honors the same token via `?share_token=` — server/router/api/v1/memo_share_service.go:151-190; server/router/fileserver/fileserver.go:684-690

Note: the store layer (`store/db/{sqlite,mysql,postgres}/memo.go`) only *applies* `VisibilityList`/filters — it makes no authorization decision of its own, so it isn't an enforcement site. The MCP router (`server/router/mcp/`) proxies the v1 API and adds no check of its own.
