## The interface

`markdown.Service` — `internal/markdown/markdown.go:31-55`. Nine methods: `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

## Concrete implementation

Exactly one: the unexported `service` struct at `internal/markdown/markdown.go:58-60`, wrapping a `goldmark.Markdown`. There is no second impl and no mock/fake anywhere — tests construct the real thing. So every call through `markdown.Service` at runtime lands on `*service`.

Two supporting concretes sit *below* the interface, not behind it:
- `renderer.MarkdownRenderer` (`internal/markdown/renderer/markdown_renderer.go:15`) — constructed internally by `service.RenderMarkdown` (line 250) and `service.RenameTag` (line 451) to walk the AST back to markdown text.
- `parser.tagParser` / `parser.mentionParser` (`internal/markdown/parser/tag.go:19`, `parser/mention.go:19`) — goldmark `parser.InlineParser` impls, registered at priority 200 by `extensions.TagExtension` / `extensions.MentionExtension` (`internal/markdown/extensions/tag.go:17`, `mention.go:17`) only when the corresponding option is passed.

## Construction

One production site: `NewAPIV1Service` at `server/router/api/v1/v1.go:48-51`, with both `WithTagExtension()` and `WithMentionExtension()` — so the production instance has `#tag` and `@mention` parsing plus GFM. Nothing else calls `NewService` outside tests.

Test-only constructions (note the differing option sets, which change what parses):
- `server/router/api/v1/test/test_helper.go:44` — tag + mention
- `server/router/fileserver/fileserver_test.go:427` — tag only
- `server/router/rss/rss_test.go:54` — no options, so `#tag`/`@mention` are plain text in that test's RSS output

One thing worth flagging: `memopayload.Runner` and its `NewRunner` are dead code. The live path uses only the package-level `RebuildMemoPayload(ctx, memo, markdownService)`, which takes the interface as a parameter rather than reading the struct field, so `Runner.RunOnce` (`runner.go:52`) never executes.

Separately, the frontend does its own markdown rendering via `react-markdown` in `web/src/components/MemoContent/MemoMarkdownRenderer.tsx` — that's an unrelated pipeline (remark/rehype plugins), not an implementation of the Go `markdown.Service` interface. The interface doc comment at `markdown.go:29` still says the frontend uses `markdown-it`, which is stale.
