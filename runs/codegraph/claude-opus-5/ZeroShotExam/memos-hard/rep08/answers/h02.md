**delivery function — `internal/webhook/webhook.go`; protection mechanism — `internal/webhook/webhook.go` + `internal/webhook/validate.go`**

**Where delivery executes**

`Post(requestPayload *WebhookRequestPayload)` at `internal/webhook/webhook.go:120` is where the outbound HTTP request is actually built and sent (`safeClient.Do(req)` at `internal/webhook/webhook.go:152`). It marshals the payload to JSON, POSTs it, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and checks the response.

It is not called inline on the request path. `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel, and four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue calling `Post`. Callers are the memo dispatchers in `server/router/api/v1/memo_service_webhooks.go` (`dispatchMemoRelatedWebhook` line 48, `DispatchMemoCommentCreatedWebhook` line 30), which fan out to each of the creator's registered webhooks.

**What protects it from internal addresses**

Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against the CIDR list at `internal/webhook/validate.go:14-23` — IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), and the IPv6 equivalents (`::1/128`, `fc00::/7`, `fe80::/10`).

1. **Dial-time enforcement (the real guard).** `safeClient` (`internal/webhook/webhook.go:32-37`) uses a `Transport` with `DialContext: safeDialContext`. `safeDialContext` (`internal/webhook/webhook.go:59-77`) resolves the host at connection time and refuses if *any* returned IP is reserved. Because this happens per-dial rather than at save time, it also defeats DNS rebinding and redirect-based bypasses.

2. **Admission-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a user creates or updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. It requires an absolute http/https URL and rejects hostnames resolving to reserved ranges, giving a clean `InvalidArgument` error instead of a silent later failure.

**Escape hatch:** `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling both layers for self-hosted deployments targeting LAN services. Note that nothing in the non-test source sets it — there is no wiring from config or flags, so it is currently always `false` at runtime.
