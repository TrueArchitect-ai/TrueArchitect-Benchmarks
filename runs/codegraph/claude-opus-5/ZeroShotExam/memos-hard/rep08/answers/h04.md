**No** — in production code the MySQL driver is only ever constructed through the factory. The one exception is a zero-value struct literal in a same-package unit test.

Evidence:

- `store/db/mysql/mysql.go:20` defines the only constructor, `NewDB(profile *profile.Profile) (store.Driver, error)`, which builds `driver := DB{profile: profile}` at line 29 (inside the constructor itself).
- A repo-wide grep for `mysql.NewDB`, `mysql.DB{`, `&mysql.`, and imports of `store/db/mysql` returns exactly two hits, both in the factory file: `store/db/db.go:8` (the import) and `store/db/db.go:22` (`driver, err = mysql.NewDB(profile)` inside `NewDBDriver`'s `switch profile.Driver`). No other package imports `store/db/mysql` at all, so external direct construction is impossible.
- Test harnesses go through the factory too: `store/test/store.go:28` and `store/test/store.go:50` both call `db.NewDBDriver(profile)`; `store/test/containers.go` only touches the upstream `go-sql-driver/mysql` and testcontainers `mysql` packages (DSN parsing, container startup), not the memos driver type.
- The lone direct instantiation outside `NewDB` is `store/db/mysql/auth_config_test.go:12` — `db := &DB{}`, an empty in-package struct literal used to call the pure helper `IsRetryableAuthenticationMutationError`. It has no `*sql.DB` or profile, so it isn't a functioning driver instance.
