**The premise is incorrect: there is no nightly database-cleanup job in this repository.** No cron job of any kind is actually registered or run by the application.

What actually exists:

- `internal/scheduler/` is a **standalone, unwired cron library** (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It provides `New()`, `Register(*Job)`, `Start()`, `Stop()` and a cron-expression parser, but nothing outside the package imports it. The only importers are its own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. Nothing in `cmd/`, `server/`, or `store/` calls `scheduler.New()` or registers a job, so no schedule is live at runtime.

- The "cleanup at 2 AM" figure that likely prompted the question comes only from **documentation and example code**, not from a registered job:
  - `internal/scheduler/doc.go:15-17` — package doc example: `Name: "daily-cleanup"`, `Schedule: "0 2 * * *"` (comment: "2 AM daily")
  - `internal/scheduler/README.md:34-36` — same example
  - `internal/scheduler/README.md:241-244` — a different illustrative example, `"stale-session-cleanup"` at `0 3 * * *`
  - `internal/scheduler/example_test.go:97-100` — `Example_multipleJobs` registers a job named `cleanup` at `0 2 * * *` (alongside a `health-check` at `*/5 * * * *`), but this runs only as a Go example test

- Also note these examples are generic "old data" cleanup, not database cleanup specifically. The only real periodic maintenance in the codebase is the in-memory cache sweeper — a `time.Ticker` loop, not cron — at `store/cache/cache.go:199-215`, defaulting to a 5-minute `CleanupInterval` (`store/cache/cache.go:60`).

So if you're looking for a scheduled DB-cleanup task to inspect or modify, it doesn't exist yet; the scheduler package is available but not yet hooked into the server.
