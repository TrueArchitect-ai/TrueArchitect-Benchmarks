**Premise correction:** There is no Redis in this repository. A case-insensitive grep for `redis` across the whole tree (including `go.mod`/`go.sum`, Docker/compose files, and docs) returns zero hits. There is no external cache server, no connection string, and no cache-related environment variables — so there is nothing "configured" in the sense the question implies.

**Actual mechanism:** The cache layer is a hand-rolled, in-process, in-memory cache backed by `sync.Map`.

- **Implementation:** `store/cache/cache.go` — `Interface` (line 11) with `Set`/`SetWithTTL`/`Get`/`Delete`/`Clear`/`Size`/`Close`, and the `Cache` struct (line 67) storing `item{value, expiration, size}`. Expiry is enforced lazily on `Get` (line 135) and by a background `cleanupLoop` goroutine (line 200) ticking at `CleanupInterval`. `MaxItems` overflow triggers `cleanupOldest` (line 253), which evicts ~20% of `MaxItems`.
- **"Connection" / construction point:** `store.New` in `store/store.go:38-61`. It builds one `cache.Config` literal (lines 40-45: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, `OnEviction: nil`) and uses it for all three caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (lines 51-53). These are per-process fields on `Store`, so nothing is shared across instances. `Store.Close` (line 72) shuts down the three cleanup goroutines.
- **TTL for user entries: 10 minutes.** Every write to `userCache` goes through `Set`, not `SetWithTTL` — `store/user.go:98,122,132,143,167` — and `Cache.Set` (`store/cache/cache.go:93-95`) delegates to `SetWithTTL` with `c.config.DefaultTTL`, i.e. the 10 minutes from `store/store.go:41`. Cache keys come from `userCacheKey(userID)` (`store/user.go:88`); reads happen only in `GetUser` when looking up by ID (`store/user.go:150`), and deletes on user removal (`store/user_delete.go:40`). `SetWithTTL` is never called outside the cache package, so no user entry gets a custom TTL.

Note there's also a second, unrelated cache: the RSS feed cache in `server/router/rss/rss.go` — a plain `map[string]*cacheEntry` guarded by a `sync.RWMutex` (lines 48-49), with `defaultCacheDuration = 1 * time.Hour` (line 25) and `maxCacheSize = 50` (line 26). Per-user RSS feeds are keyed `"user:" + username` (line 114) and expire after 1 hour (`getFromCache`, line 357); that same duration is echoed in the `Cache-Control: public, max-age=3600` response header (line 405). This one does not use the `store/cache` package at all.
