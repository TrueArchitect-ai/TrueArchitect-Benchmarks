**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package:** `internal/idp` (`internal/idp/idp.go`) — defines the provider-agnostic `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any IdP implementation must produce.
- **Implementation package:** `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`) — the only concrete protocol implementation that ships. Its doc comment reads "Package oauth2 implements the OAuth2 identity provider integration." It provides `NewIdentityProvider(*storepb.OAuth2Config)`, `ExchangeToken` (with optional PKCE `code_verifier`), and `UserInfo`, which maps provider claims onto `idp.IdentityProviderUserInfo` via the configured `FieldMapping`.

Wiring: the API layer calls into it from `server/router/api/v1/auth_service_sso.go` (6 call sites to `oauth2.NewIdentityProvider`), config comes from `storepb.OAuth2Config`, and the frontend surfaces it in `web/src/components/IdentityProviderButtons.tsx` and `web/src/components/Settings/SSOSection.tsx`. No SAML/LDAP/OIDC-specific package exists.
