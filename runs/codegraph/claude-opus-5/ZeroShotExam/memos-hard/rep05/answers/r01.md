**Premise correction:** There is no Redis anywhere in this repository — no Redis client dependency, no connection string, no config knob. A `grep -rni redis` across Go, TS/TSX, YAML, JSON, Markdown and `go.mod` returns zero hits. The cache layer is a hand-rolled, in-process, in-memory cache; nothing is shared across server instances or survives a restart.

**Actual mechanism**

*The cache implementation* — `store/cache/cache.go`: a `Cache` struct backed by `sync.Map` plus an `atomic.Int64` item counter, implementing the `Interface` at `store/cache/cache.go:11`. Each entry is an `item{value, expiration, size}` (`store/cache/cache.go:35`); `Set` stamps `expiration = time.Now().Add(ttl)` (`store/cache/cache.go:112`). Expiry is enforced lazily on `Get` (`store/cache/cache.go:135`) and by a background `cleanupLoop` goroutine ticking on `CleanupInterval` (`store/cache/cache.go:200`). Over-capacity triggers `cleanupOldest`, which drops ~20% of `MaxItems` (`store/cache/cache.go:253`).

*Where it's "configured"* — `store/store.go:38`, in `New()`. The config is hard-coded in code, not read from env/flags:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

Three separate cache instances are built from that same config (`store/store.go:51-53`): `instanceSettingCache`, `userCache`, `userSettingCache`. `store/cache/cache.go:57` has an identical `DefaultConfig()`, but the store doesn't use it.

**TTL for user entries: 10 minutes.** `userCache` is keyed by stringified user ID (`userCacheKey`, `store/user.go:88`) and is only ever written via `Set` — `CreateUser` (`store/user.go:98`), `CreateUserIfNoUsers` (:122), `UpdateUser` (:132), `ListUsers` (:143), `GetUser` (:167). `Set` delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:94`), so every user entry gets the 10-minute default; no call site uses `SetWithTTL` with a custom duration. Note `GetUser` only consults the cache when looking up by `find.ID` (`store/user.go:149`) — username/email lookups always hit the driver. Invalidation on delete goes through `deleteUserCache` (`store/user_delete.go`), and user *settings* use a separate cache keyed `"<userID>-<settingKey>"` (`store/cache.go:7`) with the same 10-minute TTL.

**Unrelated cache you may be thinking of** — RSS feeds have their own independent, hand-rolled cache in `server/router/rss/rss.go`: a `map[string]*cacheEntry` guarded by a `sync.RWMutex` on `RSSService` (`server/router/rss/rss.go:48`), with `defaultCacheDuration = 1 * time.Hour` and `maxCacheSize = 50` (`server/router/rss/rss.go:25-26`). Its per-user feed entries are keyed `"user:"+username` (`server/router/rss/rss.go:114`) and expire after **1 hour** (`getFromCache`, `server/router/rss/rss.go:357`) — that same duration is echoed into the `Cache-Control: public, max-age=3600` header (`server/router/rss/rss.go:405`). This cache does not use `store/cache` at all.
