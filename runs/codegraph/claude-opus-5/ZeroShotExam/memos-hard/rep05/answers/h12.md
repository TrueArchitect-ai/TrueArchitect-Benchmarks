### The three candidates

`store.Driver` declares `CreateMemo` (`store/driver.go:29`), and exactly three types implement it — all with their own INSERT:
- `store/db/sqlite/memo.go:16` — `INSERT INTO \`memo\` ... RETURNING ...` (`QueryRowContext`)
- `store/db/mysql/memo.go:16` — backticked INSERT with `FROM_UNIXTIME(?)` timestamps, `ExecContext` + `LastInsertId`
- `store/db/postgres/memo.go:16` — unquoted INSERT with `$n` placeholders + `RETURNING`

Static call-graph alone can't disambiguate these: the save path is `APIV1Service.CreateMemo` (`server/router/api/v1/memo_service.go:115`) → `Store.CreateMemo` (`store/memo.go:109`), which does UID validation then calls `s.driver.CreateMemo(ctx, create)` — an interface call resolved at runtime.

### How the ambiguity was resolved

I followed the value bound to `Store.driver` back to its construction, rather than guessing from the interface:

1. **Dispatch site** — `store/memo.go:113` calls through the `driver Driver` field of `Store` (`store/store.go:15`). There is no caching/decorator wrapper: `store.New` (`store/store.go:38`) stores the driver verbatim; the caches it builds are only for instance settings, users, and user settings.
2. **Driver construction** — `store.New(dbDriver, ...)` is fed by `db.NewDBDriver(instanceProfile)` in `cmd/memos/main.go:57`. `NewDBDriver` (`store/db/db.go:14-27`) switches on the *string* `profile.Driver`: `"sqlite"` → `sqlite.NewDB`, `"mysql"` → `mysql.NewDB`, `"postgres"` → `postgres.NewDB`, anything else → error `"unknown db driver"`.
3. **Default value of that string** — `profile.Driver` comes from `viper.GetString("driver")` (`cmd/memos/main.go:43`), whose default is `"sqlite"` in both places it's set: `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the flag default `rootCmd.PersistentFlags().String("driver", "sqlite", ...)` (`cmd/memos/main.go:130`). With no flags, the switch takes the `sqlite` branch.
4. **Corroborating evidence that sqlite is the no-flag path** — `Profile.Validate` (`internal/profile/profile.go:109-116`) auto-fills a DSN *only* for sqlite (`<dataDir>/memos_prod.db`, or `memos_demo.db` in demo mode). MySQL and Postgres have no DSN default, and `sqlite.NewDB` errors with `"dsn required"` if empty (`store/db/sqlite/sqlite.go:26-28`) — so a flagless run is only viable on sqlite, since `--dsn` would be mandatory for the other two.

The `driver` key is also bound to viper's env handling, so `MEMOS_DRIVER` can override it — but that is not a default installation.
