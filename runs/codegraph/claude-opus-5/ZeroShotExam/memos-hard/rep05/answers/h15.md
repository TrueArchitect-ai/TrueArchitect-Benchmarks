**Primary enforcement sites (Connect/gRPC API v1):**

Single-memo read gate `checkMemoReadAccess` (archived → creator only; non-public → auth required; private → creator only); called by `GetMemo`, the parent-memo check, and `ListMemoComments` — `server/router/api/v1/memo_service.go:39-68` (call sites `:356`, `:367`)
List-level visibility filter in `ListMemos` (anonymous → `VisibilityList=[PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`; archived → creator only) — `server/router/api/v1/memo_service.go:188-227`
`ListMemoComments` parent gate + per-comment visibility filter passed to the store — `server/router/api/v1/memo_service_comments.go:148`, `:157-161`
`CreateMemoComment` private-parent gate (and comment inherits parent visibility) — `server/router/api/v1/memo_service_comments.go:34-42`, `:100`
`ListMemoRelations` — related-memo visibility filter — `server/router/api/v1/memo_relation_service.go:102-116`, `:128-131`
`batchConvertMemoRelations` — same filter applied when embedding relations in list responses — `server/router/api/v1/memo_service_converter.go:177-198`
`ListMemoReactions` / `UpsertMemoReaction` visibility checks — `server/router/api/v1/reaction_service.go:29-42`, `:83`
`ListMemoAttachments` visibility check — `server/router/api/v1/memo_attachment_service.go:212-225`
`checkAttachmentAccess` — attachment access follows its memo's visibility — `server/router/api/v1/attachment_service.go:422-454`
User stats (`ListAllUserStats`, `GetUserStats`) visibility filters — `server/router/api/v1/user_service_stats.go:77-92`, `:216-221`

**Non-gRPC HTTP surfaces:**

Raw file/blob server `checkAttachmentPermission` (public+anonymous-allowed, else share token, else auth; private → creator/admin) — `server/router/fileserver/fileserver.go:650-703`
RSS feeds (explore + per-user) restricted to `VisibilityList=[PUBLIC]` — `server/router/rss/rss.go:90`, `:141`
Sitemap XML restricted to public memos — `server/router/frontend/frontend.go:148-152`

**Push/side-channel surfaces:**

SSE live-update delivery filter `SSEClient.canReceive` (private events only to creator or admin; unknown visibility denied) — `server/router/api/v1/sse_hub.go:134-143` (event visibility stamped at `sse_event_helpers.go:29-37`)
Mention-notification eligibility — private memos only notify the creator — `server/router/api/v1/memo_mention_helpers.go:62-84`
Email/notification content gating by visibility — `server/router/api/v1/user_service_notifications.go:309-312` and `server/notification/email.go:313-316`

**Deliberate bypass (share links):** `GetMemoByShare` serves any non-archived memo to an unauthenticated caller holding a valid, unexpired token — `server/router/api/v1/memo_share_service.go:153-192`; the matching `share_token` fallback in the file server is at `server/router/fileserver/fileserver.go:683-689`.

The filters above are ultimately applied in SQL at `store/db/sqlite/memo.go:96`, `store/db/mysql/memo.go:104`, `store/db/postgres/memo.go:89` (`FindMemo.VisibilityList`, defined at `store/memo.go:69`) — that's the mechanism, not an independent policy decision.
