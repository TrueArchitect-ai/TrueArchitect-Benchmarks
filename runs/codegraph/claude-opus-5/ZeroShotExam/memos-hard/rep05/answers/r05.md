**Premise correction:** There is no GraphQL schema in this repository. A case-insensitive search for `graphql` across all Go, TypeScript, proto, JSON, and YAML sources returns zero hits, and there are no `.graphql`/`.gql` files or `gqlgen.yml`. Memos does not expose a GraphQL API.

**Actual API surface — Protobuf/gRPC is the single source of truth**

The public API is defined as protobuf service definitions in `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `ai_service.proto`, `common.proto`
- Store-internal messages (not part of the public API) live in `proto/store/`

REST routes are declared inline on each RPC via `google.api.http` annotations — e.g. `proto/api/v1/memo_service.proto:30` maps `ListMemos` to `GET /api/v1/memos`.

**Code generation** — `proto/buf.gen.yaml` runs `buf generate` with five plugins, producing:
- Go structs + gRPC + Connect + grpc-gateway stubs into `proto/gen/`
- An OpenAPI 3.0.3 spec at `proto/gen/openapi.yaml` (4057 lines, via gnostic) — this is the closest analogue to "the schema for the public API," and it's generated, not hand-written
- TypeScript client types into `web/src/types/proto/api/v1/`

**Runtime wiring** (`server/server.go:71-96`) mounts, in order: frontend static files, file server, RSS (`server/router/rss`), the gRPC-Gateway REST layer via `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`), and MCP (`server/router/mcp`). Connect-protocol handlers for all eight services are registered in `server/router/api/v1/connect_handler.go:31-49`; the web client talks to them through `web/src/connect.ts`.

Notably, the MCP server is driven by the generated OpenAPI spec — `server/router/mcp/service.go:78` unmarshals the embedded `proto.OpenAPIYAML()` (`proto/openapi_embed.go`) to derive its tool catalog, and `server/router/mcp/service_test.go:71-73` asserts the embedded copy matches the on-disk generated file.

So: three protocols (gRPC, Connect, REST-over-gateway) plus MCP and RSS, all derived from one set of `.proto` files. None of them is GraphQL.
