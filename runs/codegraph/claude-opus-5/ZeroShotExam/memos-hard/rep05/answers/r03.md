**Premise correction: there is no nightly database-cleanup job in this repository.** The `internal/scheduler` package is a standalone cron library — it defines the scheduler, job type, cron parser, and middleware, but no application code anywhere registers a job with it. The only cleanup jobs named "2 AM daily" exist in documentation and example code, not in a running schedule.

What actually exists:

- `internal/scheduler/scheduler.go` — `Scheduler.Register` / `Start` / `Stop`; the job set is entirely whatever the caller registers. No production caller: `grep` for `scheduler.` outside `internal/scheduler/` returns only that package's own files and doc.
- `internal/scheduler/doc.go:15-18` — a *doc comment* example: `Name: "daily-cleanup"`, `Schedule: "0 2 * * *", // 2 AM daily`, with the body commented as "Your cleanup logic here". This is illustrative package documentation, not a registration.
- `internal/scheduler/example_test.go:97-106` — `Example_multipleJobs` registers a job named `"cleanup"` on `"0 2 * * *"` whose handler just prints "Cleaning up old data...". It's a Go example test, and it isn't database-related.
- `internal/scheduler/parser_test.go:82` — `"0 2 * * *"` as a parser test fixture.

The repo's real background work doesn't use the cron scheduler at all, and none of it is a nightly database cleanup:

- `server/runner/s3presign/runner.go:29-31` — interval ticker (`time.NewTicker(runnerInterval)`), re-presigns S3 URLs.
- `server/runner/memopayload/runner.go:27` — `RunOnce`, a one-shot payload rebuild, not scheduled.

So if you're looking for where to change the cleanup time, there's nothing to change — the "2 AM" figure comes from an example. If you want such a job to exist, it would need to be created and registered against the scheduler at startup.
