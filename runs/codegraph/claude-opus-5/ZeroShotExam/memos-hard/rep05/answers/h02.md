**delivery function** — `webhook.Post` at `internal/webhook/webhook.go:120` (the actual `http.Request` build + `safeClient.Do` at line 152); **protection mechanism** — `safeDialContext` at `internal/webhook/webhook.go:59`, backed by `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go:14-54`.

How it fits together:

- **Trigger** — memo create/update/delete and comment-created call `s.dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go:15-74`, which build a `WebhookRequestPayload` per registered user webhook and hand it to `webhook.PostAsync` (`internal/webhook/webhook.go:184`).
- **Async hop** — `PostAsync` enqueues onto a bounded 128-slot channel (`asyncPostQueue`, line 39), drained by 4 goroutines started in `init()` (lines 42-55). Overflow is dropped with a warning, so delivery is best-effort. Each worker calls `Post`.
- **Delivery** — `Post` marshals the payload, optionally adds Standard-Webhooks HMAC headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, lines 133-150), and issues the POST via the package-level `safeClient` (line 152). Response body is read through a 1 MiB `io.LimitReader` (line 158).

Two layers of SSRF protection:

1. **At dial time (the real enforcement)** — `safeClient`'s `http.Transport` uses `DialContext: safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` splits host/port, resolves the host itself via `net.DefaultResolver.LookupHost`, and refuses the connection if *any* resolved address is reserved (`internal/webhook/webhook.go:59-77`). Because the check happens on the resolution used for the actual dial, it also defeats DNS-rebinding, which a URL-time check alone would miss.
2. **At registration time (early feedback)** — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved ranges; it's called from webhook create/update in `server/router/api/v1/user_service_webhooks.go:74,161,182`. This returns a gRPC `InvalidArgument` so users see the error when saving, but it is not the security boundary — TOCTOU means the dial-time check is what actually holds.

The blocked ranges are `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (covers cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`. They're parsed once at startup into `reservedNetworks`.

One thing worth flagging: the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both layers when true, but grep shows it is never assigned anywhere outside its declaration — no flag, env var, or profile field wires it up, so it is currently dead configuration that only tests can set.
