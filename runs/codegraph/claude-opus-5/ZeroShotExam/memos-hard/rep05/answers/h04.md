**No** — outside the factory, no production or test code constructs the MySQL driver.

Evidence:

- The only importer of the driver package in the whole repo is the factory itself: `grep -rn "store/db/mysql" --include=*.go` returns exactly one hit, `store/db/db.go:8`. Since `mysql.NewDB` / `mysql.DB` are only reachable via that import path, no other package *can* construct it.
- The single call to the constructor is `store/db/db.go:22` (`driver, err = mysql.NewDB(profile)`) inside `NewDBDriver`, alongside the sqlite and postgres cases.
- Everything else goes through the factory: `store/test/store.go:28,50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70` call `db.NewDBDriver(profile)`. By contrast, the sqlite driver *is* built directly in tests (`store/demo_seed_test.go:24`, `store/deployment_config_test.go:416` call `sqlite.NewDB(p)`), so the pattern exists but is not used for MySQL.

Two in-package uses of the struct literal, neither of which is an outside construction:
- `store/db/mysql/mysql.go:29` — `driver := DB{profile: profile}` inside `NewDB` itself.
- `store/db/mysql/auth_config_test.go:12` — `db := &DB{}`, a zero-value struct in a same-package unit test for `IsRetryableAuthenticationMutationError`; it never opens a connection.
