**Premise correction: there is no per-user API rate-limiting middleware in this repository.** No middleware, interceptor, or handler enforces a per-user (or per-IP) request-rate limit anywhere in the server, so there are no request limits to report.

**What the middleware/interceptor chain actually contains**

- Echo-level middleware, registered in `server/server.go:51-53`: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go:14`), plus the frontend static/SPA-fallback middleware in `server/router/frontend/frontend.go:54-59`. No limiter.
- Connect RPC interceptors, registered in `server/router/api/v1/v1.go:133-137`: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — all defined in `server/router/api/v1/connect_interceptors.go`. No limiter.
- gRPC-Gateway: a single auth middleware via `runtime.WithMiddlewares(gatewayAuthMiddleware)` (`server/router/api/v1/v1.go:95-97`). No limiter.

`golang.org/x/time/rate` appears in `go.mod:151` only as an **indirect** dependency, and the only mentions of rate limiting in the tree are aspirational docs about SMTP sending, not implemented code: `internal/email/README.md:286-297` (a "### 5. Implement Rate Limiting" best-practice example) and `internal/email/doc.go:86`.

**The limits that do exist** (none of them per-user rate limits)

- Request *size* cap: `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` — `server/router/api/v1/v1.go:20,126,141,144`.
- Global *concurrency* semaphores, process-wide and not per user: `thumbnailSemaphore` = 3 and `imageProcessingSemaphore` = 2 (`server/router/api/v1/v1.go:39-41,59-60`; acquired in `server/router/api/v1/attachment_service_image.go:68-75`). Exceeding image-processing concurrency yields `ResourceExhausted "too many image processing requests"` (`server/router/api/v1/attachment_service.go:160`) — a queue/backpressure signal, not a rate quota.
- Per-request batch-size caps, e.g. `maxBatchDeleteAttachments = 100` (`server/router/api/v1/attachment_service.go:355`), max users per batch get (`server/router/api/v1/user_service.go:145`), max URLs per link-metadata batch (`server/router/api/v1/memo_service_link_metadata.go:24`).

There is also no login-attempt throttling or lockout in the auth path.
