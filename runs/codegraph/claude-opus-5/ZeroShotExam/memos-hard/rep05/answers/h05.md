**Mechanism: explicit Go code** — the per-driver `DeleteUser` transaction issues `DELETE FROM reaction` statements. There is no FK/cascade on the `reaction` table in any of the three schemas.

**What the Go code does** (identical in all three drivers, inside one transaction):

- `store/db/sqlite/user_delete.go:92` `deleteUserTargetsTx` calls, in order:
  - `deleteReactionsByContentIDsTx` (line 96) → `store/db/sqlite/user_delete.go:380`: `DELETE FROM reaction WHERE content_id IN (...)`, batched at 500, over the content IDs (`memos/<uid>`) of the user's whole memo tree (memos + descendant comments). This removes *other people's* reactions on the deleted user's memos.
  - `deleteReactionsByCreatorTx` (line 102) → `store/db/sqlite/user_delete.go:400`: `DELETE FROM reaction WHERE creator_id = ?`. This removes the deleted user's own reactions, including ones left on memos that survive.
- Same code at the same lines in `store/db/mysql/user_delete.go:96,102,380,400` and `store/db/postgres/user_delete.go:96,102`.
- Entry points: `store/user.go:171` (`Store.DeleteUser` → driver) ← `server/router/api/v1/user_service.go:393` (`APIV1Service.DeleteUser`). The whole thing commits atomically at `store/db/*/user_delete.go:51`.

**What I checked to rule out a DB-level rule:**

- `reaction` table DDL in `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/mysql/LATEST.sql:91-98`, `store/migration/postgres/LATEST.sql:91-98` — columns only, a `UNIQUE(creator_id, content_id, reaction_type)` constraint, and **no FOREIGN KEY / ON DELETE clause**. Same in the original `store/migration/{mysql,postgres}/0.20/00__reaction.sql`.
- Grepped all of `store/migration/` for `FOREIGN KEY|REFERENCES|ON DELETE` — the cascades that exist are on `memo_share.memo_id` and on legacy sqlite ≤0.5 tables; `reaction` never appears.
- Even where sqlite FKs exist historically, they're inert: the DSN opens with `_pragma=foreign_keys(0)` at `store/db/sqlite/sqlite.go:53`.

**Test coverage confirming it:** `store/test/user_delete_test.go:97-113` creates three reactions (a peer's reaction on the deleted user's memo, the deleted user's reaction on a peer memo, and a peer's reaction on a peer memo), and `store/test/user_delete_test.go:216-220` asserts only the last survives.

Separately, the read path also defends against orphans — the API filters out reactions whose creator no longer exists (see `server/router/api/v1/test/reaction_service_test.go`, `TestListMemoReactionsSkipsMissingCreators`) — but the actual row removal is the explicit Go deletes above.
