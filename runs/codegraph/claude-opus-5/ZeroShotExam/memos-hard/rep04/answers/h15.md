Memo visibility is enforced independently in each of these server surfaces (no single chokepoint — each re-implements or re-applies the rule):

**Core API v1 (Connect/gRPC — also what the MCP surface calls through)**
1. Single-memo read gate `checkMemoReadAccess` (archived → creator only; non-PUBLIC → auth required; PRIVATE → creator only) — `server/router/api/v1/memo_service.go:39` (called from `GetMemo` and the parent-memo check at `memo_service.go:356,367`, and from `ListMemoComments` at `server/router/api/v1/memo_service_comments.go:148`)
2. List-query scoping in `ListMemos` (anonymous → `VisibilityList = [PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:216-227`
3. Comment surfaces: `CreateMemoComment` PRIVATE-parent check + inherited visibility — `server/router/api/v1/memo_service_comments.go:41,52`; and the child-comment visibility filter in `ListMemoComments` — `server/router/api/v1/memo_service_comments.go:155-160`
4. Reactions: `ListMemoReactions` (non-PUBLIC → auth; PRIVATE → creator/superuser) and `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:29-41, 83`
5. `ListMemoAttachments` visibility check — `server/router/api/v1/memo_attachment_service.go:213-226`
6. Attachment read gate `checkAttachmentAccess` (linked attachments inherit memo visibility) — `server/router/api/v1/attachment_service.go:419-455` (used by `GetAttachment`, line 256)
7. User stats: `ListAllUserStats` and `GetUserStats` apply their own visibility list/filter — `server/router/api/v1/user_service_stats.go:78-92, 217-221`
8. Notification rendering gate `canViewerAccessMemo` (redacts memo payloads in inbox items) — `server/router/api/v1/user_service_notifications.go:302-315` (applied at 337, 342, 370, 385)
9. Mention-notification targeting `canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-89`
10. Share-token path, which deliberately bypasses visibility when a valid, unexpired token resolves (archived still hidden) — `server/router/api/v1/memo_share_service.go:153-193`

**Non-gRPC HTTP surfaces**
11. SSE broadcast filtering `SSEClient.canReceive` (PRIVATE events only to creator/admin) — `server/router/api/v1/sse_hub.go:134-143` (event visibility stamped in `server/router/api/v1/sse_event_helpers.go:29-37`)
12. Raw file/attachment streaming `checkAttachmentPermission` (PUBLIC + anonymous-allowed, `share_token` fallback, else auth + PRIVATE→creator/admin) — `server/router/fileserver/fileserver.go:650-704`
13. RSS feeds — hardcoded `VisibilityList: [PUBLIC]` in `GetExploreRSS` and `GetUserRSS` — `server/router/rss/rss.go:88-90, 139-141`
14. Sitemap XML — hardcoded `VisibilityList: [PUBLIC]` — `server/router/frontend/frontend.go:149-151`

**Outside the HTTP routers**
15. Email notification dispatch, its own copy of `canViewerAccessMemo` — `server/notification/email.go:306-319` (applied at 155, 187)

The store layer itself does not enforce anything — `store.FindMemo.VisibilityList` / `Filters` are just query parameters (`store/memo.go:57-82`, `store/db/sqlite|mysql|postgres/memo.go`), so every caller above is responsible for setting them.
