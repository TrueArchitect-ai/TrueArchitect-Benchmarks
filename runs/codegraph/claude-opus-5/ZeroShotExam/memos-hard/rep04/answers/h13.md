**`*markdown.service` (the only concrete impl) — built by `markdown.NewService(...)`, in practice the single instance created in `NewAPIV1Service` — held by `APIV1Service`, `RSSService`, and `memopayload.Runner`.**

### The interface
`internal/markdown/markdown.go:31` — `markdown.Service` with `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`.

### Implementation
Exactly one implementation exists in the repo: the unexported `service struct{ md goldmark.Markdown }` (`internal/markdown/markdown.go:57`), a goldmark wrapper. There are no mocks/fakes implementing the interface — tests construct the real one. Its behavior varies by option rather than by type: `WithTagExtension()` / `WithMentionExtension()` add the custom inline parsers in `internal/markdown/parser/tag.go` and `internal/markdown/parser/mention.go` (wired via `internal/markdown/extensions/`), and `RenderMarkdown` delegates to `renderer.MarkdownRenderer` (`internal/markdown/renderer/markdown_renderer.go:15`), which is a plain struct, not behind the interface.

### Construction
- Production: `NewAPIV1Service` (`server/router/api/v1/v1.go:48`) calls `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())` and stores it on the service. This is the only non-test construction site, so at runtime one shared instance (tags + mentions enabled) serves the whole server.
- `server/server.go:85` passes that same instance into `rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)` — RSS does not build its own.
- Tests build their own: `server/router/api/v1/test/test_helper.go:44` (tags + mentions), `server/router/fileserver/fileserver_test.go:427` (tags only), `server/router/rss/rss_test.go:54` (no extensions).

### Holders
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — used at `memo_mention_helpers.go:32` (`ExtractAll`), `memo_service_webhooks.go:85` (`GenerateSnippet`), and passed to `memopayload.RebuildMemoPayload` at `memo_service.go:108` and `:447`.
- `RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — used at `rss.go:339` (`RenderHTML`) for feed content.
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`, set by `NewRunner`) — note `NewRunner` has no callers outside its own package, so this holder is currently unused in production; the live path is the package-level `RebuildMemoPayload(ctx, memo, markdownService)` (`runner.go:74`), which takes the interface as a parameter rather than holding it.

Frontend markdown is unrelated to this abstraction: `web/src/components/MemoContent/MemoMarkdownRenderer.tsx` uses `react-markdown` with remark/rehype plugins directly, with no equivalent interface indirection.
