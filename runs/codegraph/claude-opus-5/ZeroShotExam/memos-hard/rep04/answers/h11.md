**1st: `store.User` (~7 packages outside the data layer); 2nd: `store.Memo` (~6 packages)**

The data layer is the Go `store` package (`store/*.go`), where the persistent entity structs are defined — `User` (`store/user.go:29`), `Memo` (`store/memo.go:35`), `Attachment` (`store/attachment.go`), `Inbox`, `Reaction`, `MemoRelation`, `MemoShare`, `UserIdentity` (`store/user_identity.go:8`), `UserSetting`, `IdentityProvider`, `InstanceSetting`.

Counting distinct packages that reference each type, excluding the data layer itself (`store/`, `store/db/{sqlite,postgres,mysql}`, `store/test`):

| Type | Outside packages |
|---|---|
| `store.User` | 7 — `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss` |
| `store.Memo` | 6 — `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload` |
| `store.Attachment` | 4 — `server/router/api/v1`, `.../test`, `server/router/fileserver`, `server/router/rss` |
| `store.MemoShare` / `MemoRelation` / `Inbox` | 3 each |
| `store.Reaction` / `UserIdentity` | 2 each |

`User` leads because it's threaded through authentication (`server/auth`, e.g. `server/router/api/v1/user_resource_name.go:49` returning `*store.User`) in addition to every content-serving path; `Memo` appears everywhere `User` does except `server/auth`, but gains `server/runner/memopayload`.

If you exclude test packages, the ranking is unchanged (User 6, Memo 5). The remaining entity types (`UserSetting`, `IdentityProvider`, `InstanceSetting`) are referenced only from the DB drivers inside the data layer, with their payloads living in `proto/gen/store`.
