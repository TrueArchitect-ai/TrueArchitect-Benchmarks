**delivery function — `internal/webhook/webhook.go:120` (`Post`); protection mechanism — `internal/webhook/webhook.go:59` (`safeDialContext`) backed by `internal/webhook/validate.go` (`isReservedIP` / `reservedCIDRs`)**

Details:

- **Where delivery executes:** `Post` (`internal/webhook/webhook.go:120`) marshals the `WebhookRequestPayload`, optionally adds Standard-Webhooks HMAC headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and issues the POST via the package-level `safeClient` at line 152. `PostAsync` (`internal/webhook/webhook.go:184`) just enqueues onto a 128-slot buffered channel; four goroutines started in `init()` (line 42) drain it and call `Post`, so async dispatches also execute inside `Post`. Callers are in `server/router/api/v1/memo_service_webhooks.go`.

- **Protection (defense in depth, two layers):**
  1. *Dial-time block* — `safeClient` (`internal/webhook/webhook.go:32`) uses a custom `Transport.DialContext = safeDialContext` (line 59). It splits host/port, resolves the host itself, and rejects the connection if **any** resolved IP is in a reserved range. Because the check happens at dial time on every request, it also defeats DNS rebinding (TOCTOU between validation and connect).
  2. *Config-time validation* — `ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-IP-resolving hostnames when a user creates/updates a webhook; called from `server/router/api/v1/user_service_webhooks.go:74,161,182`.

  Both share `isReservedIP` (`internal/webhook/validate.go:44`) against `reservedCIDRs` (line 14): IPv4 loopback, RFC-1918 10/8, 172.16/12, 192.168/16, link-local 169.254/16 (cloud IMDS), plus `::1/128`, `fc00::/7`, `fe80::/10`.

- **Escape hatch:** the package var `AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling both layers for self-hosted setups targeting LAN services. Note it is declared but never assigned anywhere in the Go tree outside tests — no flag or config currently wires it up, so it is effectively always `false` in production.

Ancillary hardening in `Post`: 30s client timeout (line 27) and a 1 MiB `io.LimitReader` cap on the response body (line 158).
