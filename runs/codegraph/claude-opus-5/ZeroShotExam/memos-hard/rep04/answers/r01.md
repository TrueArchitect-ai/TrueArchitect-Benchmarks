**Premise correction:** There is no Redis anywhere in this repository. A case-insensitive search across the whole tree (excluding `.git`/`node_modules`) returns zero hits for "redis" — no client dependency in `go.mod`, no connection string, no env var, no docker-compose service. Nothing connects to an external cache server.

**Actual mechanism — a process-local in-memory cache**

*Implementation:* `store/cache/cache.go` — a `Cache` struct backed by `sync.Map` plus an `atomic.Int64` item counter, with a background `cleanupLoop()` goroutine. Each entry (`item`, `store/cache/cache.go:35`) stores the value, an absolute `expiration` time, and an estimated size. `Get` (line ~120) lazily evicts on read when `time.Now().After(itm.expiration)`.

*"Connection" configuration:* there is none to configure — the caches are constructed in-process in `store.New`, `store/store.go:38-54`, with a hardcoded `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

Three separate `*cache.Cache` instances are created from it (`store/store.go:26-28`): `instanceSettingCache`, `userCache`, `userSettingCache`. `cache.DefaultConfig()` (`store/cache/cache.go:56`) holds the same values. Nothing reads these from the environment or profile, so they can't be tuned without a code change.

**TTL for user entries: 10 minutes.** User objects are written via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` at `store/user.go:98, 122, 132, 143, 167`, and `Set` delegates to `SetWithTTL(..., c.config.DefaultTTL)` (`store/cache/cache.go:89-91`). No caller anywhere in the codebase invokes `SetWithTTL` with a custom duration, so users inherit the 10-minute default. Entries are also invalidated explicitly on delete (`store/user_delete.go:40`), and can be evicted early by `cleanupOldest()` if the cache exceeds `MaxItems: 1000`. User settings (`store/user_setting.go:59, 78, 106`, keyed by `getUserSettingCacheKey` in `store/cache.go:7`) use the same 10-minute TTL.

**Possible source of the confusion:** a second, unrelated cache exists for RSS feeds — `RSSService.cache`, a plain `map[string]*cacheEntry` guarded by a `sync.RWMutex` (`server/router/rss/rss.go:42-50`). Its per-user feed entries are keyed `"user:" + username` (line 114) and expire after `defaultCacheDuration = 1 * time.Hour` (line 25, enforced in `getFromCache`, line 357), with a 50-entry cap. That is the only place a "user" cache entry has a TTL other than 10 minutes — and it too is in-memory, not Redis.
