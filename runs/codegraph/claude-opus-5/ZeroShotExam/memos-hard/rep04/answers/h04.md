**No** — `mysql.NewDB` is never called outside the factory. (One caveat: the mysql package's own test constructs a zero-value `&DB{}` struct literal, which isn't a real driver construction.)

Evidence:

1. **The factory is the sole caller of `mysql.NewDB`.** A repo-wide grep for `mysql.NewDB(` returns exactly one hit: `store/db/db.go:22`, inside `NewDBDriver`'s `switch profile.Driver` (`store/db/db.go:14-32`). Codegraph agrees: `NewDB` at `store/db/mysql/mysql.go:20` has **1 caller**, `store/db/db.go`.

2. **Nothing else even imports the package.** `grep -rn "store/db/mysql" --include="*.go"` matches only `store/db/db.go:8`. Since `NewDB` is the package's only constructor and it's unexported-to-nobody-else, no other package can build a MySQL driver.

3. **Other call sites go through the factory.** The only non-factory driver constructions in the repo are SQLite: `store/deployment_config_test.go:416` and `store/demo_seed_test.go:24` call `sqlite.NewDB(p)` directly. The real consumers — `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` — all call `db.NewDBDriver(profile)`.

4. **The one struct literal is an in-package test stub, not a driver.** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` (package `mysql`, so it can reach the unexported fields). It's a zero-value struct with nil `db`, `profile`, and `config`, used only to invoke the pure method `IsRetryableAuthenticationMutationError` on MySQL error codes 1213/1205/1062. No connection is opened — `sql.Open("mysql", dsn)` happens only in `NewDB` at `store/db/mysql/mysql.go:35`.
