h03.
`internal/idp`; `internal/idp/oauth2`

**Abstraction — `internal/idp`** (`internal/idp/idp.go`): a single-file package defining the provider-agnostic contract, the `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider normalizes remote user data into. Note it is a shared data type, not a Go interface — there is no `IdentityProvider` interface, so dispatch is done by an explicit type switch rather than polymorphism.

**Implementation — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol that ships. Its header comment reads "Package oauth2 implements the OAuth2 identity provider integration." It wraps `golang.org/x/oauth2`, holds a `*storepb.OAuth2Config`, and exposes `NewIdentityProvider`, `ExchangeToken` (with PKCE `code_verifier` support), and `UserInfo`, which maps the userinfo endpoint's JSON onto `idp.IdentityProviderUserInfo` via the configured `FieldMapping`.

Supporting evidence that OAuth2 is the sole implementation:
- `server/router/api/v1/auth_service_sso.go:119-121` — the only consumer, gated on `if identityProvider.Type == storepb.IdentityProvider_OAUTH2`. There is no other branch, so a provider of any other type would fall through with a nil `userInfo`.
- `proto/store/idp.proto` — the `IdentityProvider.Type` enum has only `TYPE_UNSPECIFIED` and `OAUTH2`, and `IdentityProviderConfig`'s oneof has just `oauth2_config`. No SAML or dedicated OIDC type exists (OIDC providers are configured as generic OAuth2 endpoints).
