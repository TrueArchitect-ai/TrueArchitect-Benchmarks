**Computation site**

`memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:73`. It delegates the actual parse to the markdown service's `ExtractAll` (`internal/markdown/markdown.go:355`), then assigns the result onto the store model:

```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property   // runner.go:84-85
```

The payload is persisted as the memo's JSON `payload` column (`store/memo.go:51`, decoded per driver e.g. `store/db/sqlite/memo.go:180`) and surfaced on the API as the OUTPUT_ONLY `Memo.property` via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315`, proto message at `proto/api/v1/memo_service.proto:256,272`). A near-duplicate property-only walk exists as `service.ExtractProperties` (`internal/markdown/markdown.go:192`) but has no non-test callers.

**Triggers for recomputation**

- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only when `content` is in the `update_mask`; the rebuilt payload is then written along with the content (`update.Payload = memo.Payload`). Other mask paths (visibility, pinned, state, create_time…) do not recompute.
- Batch backfill: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) walks every memo in pages of 100 and rewrites each payload. Note that this runner is currently not wired into startup — `server/server.go:163` only calls the s3presign runner, and `memopayload` is imported nowhere but `memo_service.go`, so in practice recomputation happens only on memo create and content update.

**What the computation extracts**

One goldmark AST walk over the memo content produces, in `ExtractedData`:

- `Tags` — `#tag` nodes, deduplicated preserving case; and `Mentions` (`@user`, lowercased) which are used for mention resolution (`server/router/api/v1/memo_mention_helpers.go:32`), not stored on the payload.
- `Property` (`storepb.MemoPayload_Property`, `internal/markdown/markdown.go:390-408`):
  - `HasLink` — any `gast.KindLink` node
  - `HasCode` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`
  - `HasTaskList` — any `east.KindTaskCheckBox`
  - `HasIncompleteTasks` — a task checkbox with `IsChecked == false`
  - `Title` — text of the first block-level child of the document only if it is an H1 heading (`extractHeadingText`, first-block guard at markdown.go:382-388)

These booleans back the memo list filters (`store/memo.go:84` `FindMemoPayload`) and user stats (`server/router/api/v1/user_service_stats.go:141-151`).

Separately, `Memo.snippet` (used for previews/relation cards) is *not* stored — it's generated at conversion time by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83`, applied at `memo_service_converter.go:76-80`).
