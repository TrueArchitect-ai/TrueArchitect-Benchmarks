**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`internal/idp/idp.go`): defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any IdP implementation must produce. It has no imports and no protocol specifics — it's the shared contract.

- **Implementation package — `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`): the only concrete protocol shipped. Its doc comment reads *"Package oauth2 implements the OAuth2 identity provider integration."* It provides `IdentityProvider` (wrapping `storepb.OAuth2Config`), `NewIdentityProvider` (validates `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, `fieldMapping.identifier`), `ExchangeToken` (authorization-code exchange with optional PKCE `code_verifier`), and `UserInfo` (bearer-token call to the userinfo endpoint, mapping claims through `FieldMapping` into `idp.IdentityProviderUserInfo`).

Callers: `server/router/api/v1/auth_service_sso.go` invokes `oauth2.NewIdentityProvider` (6 call sites) during SSO sign-in. Tests live at `internal/idp/oauth2/oauth2_test.go`. No SAML/LDAP/OIDC-specific package exists — OAuth2 is the sole implementation.
