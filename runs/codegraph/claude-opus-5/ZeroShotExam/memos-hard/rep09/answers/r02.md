**Premise correction: there is no per-user API rate-limiting middleware in this repository.** No rate limiter is registered anywhere — not in the Echo middleware chain, not in the Connect interceptor stack, and not in the gRPC-Gateway middleware. There is therefore no per-user request limit to report.

Evidence:

- **Echo middleware chain** — `server/server.go:51-52` registers exactly two: `middleware.Recover()` and `newCORSMiddleware(profile)`.
- **Connect interceptor stack** — `server/router/api/v1/v1.go:133-137` registers four interceptors: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`). None is a rate limiter.
- **gRPC-Gateway middleware** — `server/router/api/v1/v1.go:69-95` installs a single `gatewayAuthMiddleware` doing authentication + access-policy checks only.
- **Dependencies** — `go.mod` contains no rate-limiting library (no `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, etc.).
- The only repo-wide matches for "rate limit" are aspirational docs for a different subsystem: `internal/email/doc.go:86` and `internal/email/README.md:286` list rate limiting as something a *caller* should implement for email sending.

What *does* exist, if you're looking for abuse/resource controls (none of which are per-user or time-windowed):

| Control | Location | Value |
|---|---|---|
| Max API request body (gateway + Connect) | `server/router/api/v1/v1.go:20`, applied at `:127` and `:141-144` | 256 MiB |
| Concurrent thumbnail generation | `server/router/api/v1/v1.go:59` | semaphore, 3 at a time |
| Concurrent image processing | `server/router/api/v1/v1.go:60` | semaphore, 2 at a time; excess returns `ResourceExhausted` "too many image processing requests" (`attachment_service.go:160`) |
| Upload size | `server/router/api/v1/attachment_service.go:120-124` | instance setting `UploadSizeLimitMb`, defaulting to 32 MiB (`MaxUploadBufferSizeBytes`, line 27) |
| Batch-request sizes | `user_service.go:23` (100 users), `instance_service.go:22` (100 settings), `attachment_service.go:35` (100 attachments), `memo_service.go:26` (10 link-metadata URLs) | per-call caps, not rate limits |
| Memo content length | `server/router/api/v1/memo_service.go:595-600` | instance setting `ContentLengthLimit` |

The semaphores are global concurrency gates shared across all users, not per-user quotas — a single user can saturate them, and there's no cap on requests-per-interval for any identity. Sign-in is also unthrottled: `server/router/api/v1/auth_service.go` has no attempt counter or lockout.
