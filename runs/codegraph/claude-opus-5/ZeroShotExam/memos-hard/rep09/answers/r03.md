**Premise correction: there is no nightly database-cleanup job in this repository.** The cron scheduler exists, but nothing registers a database-cleanup job with it — so there is no scheduled time to report.

What's actually there:

- `internal/scheduler/` is a standalone, general-purpose cron library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). It provides `New`, `Register`, `Start`, `Stop`, cron parsing (5- and 6-field), timezones, and middleware — but it defines no jobs of its own.
- Nothing in the application wires it up. The only non-test imports of `github.com/usememos/memos/internal/scheduler` are inside the package's own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No code under `server/`, `cmd/`, or `store/` imports it.
- The "2 AM cleanup" you may be thinking of appears only as illustrative sample code, not a live registration:
  - `internal/scheduler/doc.go:15-17` — package doc example: `Name: "daily-cleanup"`, `Schedule: "0 2 * * *"` with a `// Your cleanup logic here` stub.
  - `internal/scheduler/example_test.go:97-99` — runnable `Example_multipleJobs` with a `"cleanup"` job on `"0 2 * * *"` that just prints "Cleaning up old data..." (alongside example health-check and backup jobs).

The actual recurring background work in this codebase uses plain tickers, not the cron scheduler, and none of it is a nightly DB cleanup:

- `server/runner/s3presign/runner.go:30` — S3 presigned-URL refresh on a fixed `runnerInterval`.
- `store/cache/cache.go:201` — in-memory cache expiry sweep on `CleanupInterval` (memory only, not the database).
