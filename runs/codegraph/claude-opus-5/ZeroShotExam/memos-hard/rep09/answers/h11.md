**1st: `store.User`; 2nd: `store.Memo`**

The data layer is the `store` package (entity structs defined in `store/user.go:29`, `store/memo.go:35`, `store/attachment.go:16`, `store/inbox.go:24`, `store/memo_share.go:6`, `store/reaction.go:7`, `store/memo_relation.go:16`, `store/user_identity.go:8`, `store/user_setting.go:13`, `store/idp.go:12`, `store/instance_setting.go:14`).

Counting distinct Go packages *outside* `store/...` (so excluding the `store/db/{sqlite,postgres,mysql}` drivers and `store/test`) that mention each type:

| Type | Packages outside the store tree | Where |
|---|---|---|
| `store.User` | ~7 | `server/auth` (`authenticator.go`), `server/notification` (`email.go`), `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss` |
| `store.Memo` | ~6 | `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload` |
| `store.Attachment` | ~4 | `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/rss` |

Runners-up drop off quickly: `MemoShare` and `MemoRelation` ~3 packages, `Inbox`/`Reaction`/`UserIdentity` ~2, and `UserSetting`/`IdentityProvider`/`InstanceSetting` are referenced outside the store tree only via their generated proto payloads in `proto/gen/store`.

`User` edges out `Memo` mainly because it is also required by the auth layer (`server/auth/authenticator.go`) and the file server's ownership checks (`server/router/fileserver/fileserver.go`), which never need a `Memo` struct directly.
