**The premise is wrong: there is no nightly database-cleanup job in this repository.** The `internal/scheduler` package is a standalone, generic cron library — nothing in the application ever registers a job with it.

What the code actually shows:

- `internal/scheduler/scheduler.go:70` — `Register(job *Job)` is the only way a job enters the scheduler. Jobs are supplied by callers; the package hard-codes none.
- The only files importing `internal/scheduler` are its own tests: `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. No production code under `cmd/`, `server/`, or `store/` uses it at all, so the scheduler is never started with real jobs.

The "2 AM cleanup" the premise probably refers to comes from documentation and an example, not a live job:

- `internal/scheduler/doc.go:15-16` — a package-doc usage snippet (inside a comment) showing `Name: "daily-cleanup"`, `Schedule: "0 2 * * *", // 2 AM daily`.
- `internal/scheduler/example_test.go:97-101` — `Example_multipleJobs` registers a job named `"cleanup"` on `"0 2 * * *"` with the comment "Cleanup old data every night at 2 AM", alongside a health check (`*/5 * * * *`) and a weekly backup (`0 1 * * 0`).

Neither touches a database — the example handler just prints `"Cleaning up old data..."`.

One nearby thing that *is* real and might be the source of the confusion: `store/cache/cache.go:200` runs a `cleanupLoop()` goroutine that evicts expired entries on a `CleanupInterval` ticker. That's the in-memory cache, not the database, and it's an interval ticker rather than a cron schedule.
