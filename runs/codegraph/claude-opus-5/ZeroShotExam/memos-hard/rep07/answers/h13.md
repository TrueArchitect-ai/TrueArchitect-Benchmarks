### The interface
`markdown.Service` — `internal/markdown/markdown.go:31-55` (8 methods: `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`).

### Implementation
Exactly **one** concrete implementation exists in the repo: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:57-60`). There are no alternative impls, mocks, or fakes — `func (s *service) ExtractAll` is the only definition of any of these methods anywhere. So `*service` is what executes at runtime, always.

Its behavior is configured by `Option`s (`internal/markdown/markdown.go:62-113`): GFM is always on, plus `extensions.TagExtension` / `extensions.MentionExtension` gated by `WithTagExtension()` / `WithMentionExtension()`, and `parser.WithAutoHeadingID()`. Note this means the *same* interface can yield a #tag-blind instance if built without the option.

### Construction
- **Production:** the single instance is created in `NewAPIV1Service` — `server/router/api/v1/v1.go:48-51` — with both tag and mention extensions, and stored on the service (`v1.go:56`). This is the only production construction site.
- **Sharing:** `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService(...)`, so RSS reuses that same instance rather than making its own.
- **Tests** build their own: `server/router/api/v1/test/test_helper.go:44-47` (tag + mention), `server/router/fileserver/fileserver_test.go:427` (**tag only**), `server/router/rss/rss_test.go:54` (`markdown.NewService()` — **no extensions**, so tags/mentions are inert there).
