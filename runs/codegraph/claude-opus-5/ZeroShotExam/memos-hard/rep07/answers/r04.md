**Premise correction:** Neither. There is no message broker in this repository at all — no NATS, RabbitMQ, AMQP, Kafka, or Redis client appears anywhere in `go.mod`/`go.sum` or the source tree, and there is no queue "declaration" in the broker sense (no exchange/subject/binding).

**Actual mechanism — an in-process Go channel with a fixed goroutine pool:**

1. **The "queue" is a buffered channel**, declared in the package-level `var` block at `internal/webhook/webhook.go:39`:
   ```go
   asyncPostQueue = make(chan *WebhookRequestPayload, 128)
   ```
   Capacity 128, in-memory, per-process — so it is not durable and its contents are lost on restart.

2. **The "workers" are 4 goroutines** started in `init()` at `internal/webhook/webhook.go:42-55`. Each ranges over `asyncPostQueue` and calls `Post(payload)`, logging a warning on failure. There are no retries and no dead-letter path — a failed delivery is dropped after one attempt.

3. **Enqueue is non-blocking with drop-on-full.** `PostAsync` (`internal/webhook/webhook.go:184-196`) does a `select` with a `default` branch: if the buffer is full, the payload is discarded and a "Dropped webhook dispatch because the async queue is full" warning is logged.

4. **Delivery itself** is a plain HTTP POST in `Post` (`internal/webhook/webhook.go:120-180`) using a shared `http.Client` with a 30s timeout and an SSRF-guarding `DialContext` (`safeDialContext`, lines 59-77) that rejects reserved/private IPs. When the webhook has a signing secret, it adds Standard Webhooks `webhook-id` / `webhook-timestamp` / `webhook-signature` HMAC-SHA256 headers.

5. **Producers** are the memo webhook dispatchers in `server/router/api/v1/memo_service_webhooks.go` — `dispatchMemoRelatedWebhook` (line 48) and `DispatchMemoCommentCreatedWebhook` (line 30) look up the user's webhooks via `s.Store.GetUserWebhooks` and call `webhook.PostAsync(payload)` per hook. The webhook *endpoints* (URL + signing secret) are stored in the database and managed through `server/router/api/v1/user_service_webhooks.go`; that store row is the closest thing to a "queue declaration," but it's a subscription target, not a broker queue.
