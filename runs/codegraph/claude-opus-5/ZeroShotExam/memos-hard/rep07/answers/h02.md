**delivery function — `Post` in `internal/webhook/webhook.go:120`; protection mechanism — `safeDialContext` (dial-time reserved-IP block) in `internal/webhook/webhook.go:59`, backed by `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go:14-54`**

How it fits together:

- **Trigger:** `server/router/api/v1/memo_service_webhooks.go` — `DispatchMemoCreatedWebhook` / `Updated` / `Deleted` / `CommentCreated` load the creator's webhooks from the store, build a `WebhookRequestPayload`, and call `webhook.PostAsync` (`memo_service_webhooks.go:43`, `:71`).
- **Queueing:** `PostAsync` (`internal/webhook/webhook.go:184`) is non-blocking — it pushes onto a buffered channel `asyncPostQueue` (cap 128) and drops the event with a warning if full.
- **Actual outbound execution:** four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`. `Post` (`:120`) marshals the JSON body, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and issues the request via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

Protection against internal/private targets — two layers:

1. **Dial-time (the real guard), `internal/webhook/webhook.go:29-37, 59-77`:** the shared `safeClient`'s `http.Transport` uses `safeDialContext`, which resolves the host itself and refuses to dial if *any* resolved address is in a reserved range. Because the check happens at connect time rather than at save time, it also defeats DNS rebinding (the comment at `:30-31` says exactly this). Note it re-resolves and dials `host` by name, so the connection isn't pinned to the vetted IP.
2. **Admission-time, `internal/webhook/validate.go:62`:** `ValidateURL` runs when a user creates/updates a webhook (called from `server/router/api/v1/user_service_webhooks.go`) — requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument`.

The blocklist itself is `reservedCIDRs` in `internal/webhook/validate.go:14-23` (IPv4 loopback, RFC-1918 ×3, 169.254.0.0/16 for cloud IMDS, plus `::1/128`, `fc00::/7`, `fe80::/10`), parsed once at startup into `reservedNetworks` and consulted by `isReservedIP` (`:44`).

One thing worth flagging: the escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both layers when true, but grep shows it is only ever assigned in `internal/webhook/webhook_test.go` — there is no flag, env var, or config wiring for it, so in a real deployment it is always `false` and self-hosters cannot target LAN endpoints despite the doc comment saying that's its purpose.
