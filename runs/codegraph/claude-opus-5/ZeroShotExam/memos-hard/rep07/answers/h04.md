Evidence:

- **The factory is the sole caller.** `store/db/db.go:22` (`NewDBDriver`) is the only site calling `mysql.NewDB(profile)`. Grepping the whole repo for imports of the package returns exactly one hit: `store/db/db.go:8` imports `github.com/usememos/memos/store/db/mysql`. Since `DB` and `NewDB` are only reachable via that import path from outside, no other package can construct it. CodeGraph agrees: `NewDB` (store/db/mysql/mysql.go:20) — 1 caller, in `store/db/db.go`.
- **In-package construction** is limited to `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}` inside `NewDB` itself) and `store/db/mysql/auth_config_test.go:12` (`db := &DB{}`), a zero-value struct used only to exercise the pure method `IsRetryableAuthenticationMutationError` — it never opens a connection.
- **Test infrastructure goes through the factory too.** `store/test/store.go` / `store/test/main_test.go` call `NewDBDriver`, not `mysql.NewDB`. The one other MySQL-flavored `sql.Open("mysql", dsn)` in the tree, `store/test/containers.go:145`, opens a bare `*sql.DB` against the testcontainer to run `CREATE DATABASE` — it builds a raw connection, not a `store.Driver`.
