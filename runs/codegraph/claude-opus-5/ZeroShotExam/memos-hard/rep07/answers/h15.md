h15.

Memo visibility is enforced independently in ~10 places (no single chokepoint — the per-memo helper `checkMemoReadAccess` covers only the memo-read RPCs; every other surface re-implements the rule).

**Core gRPC/Connect API (`server/router/api/v1/`)**

1. Single-memo read guard `checkMemoReadAccess` (archived → creator only; non-PUBLIC → auth required; PRIVATE → creator only), called by `GetMemo` (incl. the parent memo of a comment) — `server/router/api/v1/memo_service.go:39-68`, callers at `:356`, `:367`
2. `ListMemos` query-level scoping (anon → `VisibilityList = [PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`; archived → own memos only) — `server/router/api/v1/memo_service.go:188-227`
3. `ListMemoComments` — `checkMemoReadAccess` on the parent plus a separate per-comment `MemoFilter` string applied to the relation query — `server/router/api/v1/memo_service_comments.go:148,155-161`; `CreateMemoComment` re-checks PRIVATE-parent access at `server/router/api/v1/memo_service_comments.go:34-42`
4. User stats surfaces — `GetUserStats` and `ListAllUserStats` each rebuild the same visibility scoping independently — `server/router/api/v1/user_service_stats.go:84-91` and `:207-222`
5. Attachment access — `server/router/api/v1/attachment_service.go:425-454` (per-attachment permission via owning memo) and `server/router/api/v1/memo_attachment_service.go:213-225` (`ListMemoAttachments`)
6. Reactions — `ListMemoReactions` at `server/router/api/v1/reaction_service.go:29-41`, `UpsertMemoReaction` at `:82-85`, and the delete path in the same file
7. SSE broadcast filtering — per-client `canReceive` drops PRIVATE events unless the subscriber is the creator or an admin — `server/router/api/v1/sse_hub.go:133-146`
8. Share-token bypass path — `GetMemoByShare` deliberately serves a memo of *any* visibility to an unauthenticated caller holding a valid, unexpired token (archived still hidden) — `server/router/api/v1/memo_share_service.go:151-192`; the file server honors the same token at `server/router/fileserver/fileserver.go:684-690`

**Non-gRPC HTTP surfaces**

9. File server attachment permission — anonymous access only for PUBLIC memos when the instance allows anonymous, else share token or authenticated user, PRIVATE restricted to creator/admin — `server/router/fileserver/fileserver.go:660-703`
10. RSS feeds — both explore and per-user feeds hard-scope to `VisibilityList = [PUBLIC]` — `server/router/rss/rss.go:90` and `:141`
11. Sitemap XML — `VisibilityList = [PUBLIC]` — `server/router/frontend/frontend.go:143-152`

**Notification/derived-content surfaces** (control who may see memo content echoed into notifications)

12. In-app notification payloads — `canViewerAccessMemo` (PRIVATE → creator, PROTECTED → any authed user, admin bypass) — `server/router/api/v1/user_service_notifications.go:302-321`, applied at `:337,342,370,385`
13. Email notifications — a duplicate `canViewerAccessMemo` implementation — `server/notification/email.go:306-325`, applied at `:155,187`
14. Mention notification targeting — `canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-89`

The store layer itself does not enforce anything: `store/db/{sqlite,mysql,postgres}/memo.go` only translates `FindMemo.VisibilityList` / `Filters` / `CreatorID` into SQL (e.g. `store/db/mysql/memo.go:98-111`), so correctness depends entirely on each caller above setting those fields.
