**Convergence function: `webhook.Post` — `internal/webhook/webhook.go:120`**

The chain: each handler → `DispatchMemo*Webhook` / `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:15-74`) → loads the target URLs from the user's stored `WebhooksUserSetting` (`s.Store.GetUserWebhooks`) → `webhook.PostAsync` (`webhook.go:184`, enqueues onto `asyncPostQueue`) → worker goroutines in `init()` (`webhook.go:42-55`) call `Post`, which is the sole place the outbound request is built and sent (`safeClient.Do(req)`, `webhook.go:152`).

So `PostAsync` is where the handler paths merge, but `Post` is the single function through which every dispatch — sync or async — actually delivers.

Two notes:
- The URL is user-configured through `CreateUserWebhook`/`UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53`, `:106`), which validate via `webhook.ValidateURL` (`internal/webhook/validate.go`); `Post`'s client additionally re-checks at dial time in `safeDialContext` (`webhook.go:59`) to defeat DNS rebinding.
- Separately, `GetLinkMetadata` / `BatchGetLinkMetadata` (`memo_service_link_metadata.go:14`, `:19`) make outbound HTTP requests via `httpgetter.GetHTMLMeta`, but to a URL passed in the request rather than a stored user setting, and they do not go through `webhook.Post`.
