**Premise correction:** Neither. This repo (memos) has no external message broker at all — there is no NATS, RabbitMQ, AMQP, Kafka, or Redis dependency anywhere in the Go code or `go.mod` (a repo-wide grep for `nats|rabbitmq|amqp|kafka|redis` across Go/mod/config files hits only `web/src/locales/ca.json`, an incidental substring in translated text). There are also no separate "delivery worker" processes — everything runs in the single memos server binary.

**Actual mechanism:** an in-process buffered Go channel with a fixed pool of goroutines, all declared in `internal/webhook/webhook.go`:

- **Queue declaration** — `internal/webhook/webhook.go:39`: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, a package-level buffered channel holding 128 payloads.
- **Workers** — `internal/webhook/webhook.go:42-55`: a package `init()` starts 4 goroutines, each ranging over `asyncPostQueue` and calling `Post(payload)`, logging a warning on failure. No retries.
- **Producer** — `PostAsync` (`internal/webhook/webhook.go:184-196`) does a non-blocking `select` send; if the buffer is full it takes the `default` branch and **drops** the webhook with a "Dropped webhook dispatch because the async queue is full" warning. Nil payloads are also dropped.
- **Delivery** — `Post` (`internal/webhook/webhook.go:120-180`) marshals the payload to JSON, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and POSTs via the shared `safeClient` (`webhook.go:32-37`), whose transport uses `safeDialContext` to block reserved/private IPs (SSRF/DNS-rebinding guard).
- **Callers** — `server/router/api/v1/memo_service_webhooks.go:43` and `:71` call `webhook.PostAsync(payload)` for `memos.memo.created/updated/deleted` and `memos.memo.comment.created` events, after fetching the user's registered webhook URLs from the store.

Note the persistence implication: since the queue is an in-memory channel, anything still buffered is lost on process restart.
