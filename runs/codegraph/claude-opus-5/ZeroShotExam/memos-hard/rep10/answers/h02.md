**delivery function — `Post` in `internal/webhook/webhook.go:120`** (with `PostAsync`, `internal/webhook/webhook.go:184`, enqueuing onto a 128-slot channel drained by 4 worker goroutines started in `init()`, `internal/webhook/webhook.go:42`); **protection mechanism — `safeDialContext` + `isReservedIP`, `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`** (plus `ValidateURL`, `internal/webhook/validate.go:62`).

Details:

- **Trigger path:** memo create/update/delete/comment-created call `dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15-74`), which look up the creator's webhooks and call `webhook.PostAsync`. The actual HTTP request — JSON marshal, optional Standard-Webhooks HMAC-SHA256 signing headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), `safeClient.Do`, response check — happens in `Post` (`internal/webhook/webhook.go:120-180`), executing on one of the async worker goroutines, not the request goroutine.

- **SSRF protection, two layers:**
  1. *Dial-time (authoritative):* the shared `safeClient` (`internal/webhook/webhook.go:32-37`) uses a `Transport` whose `DialContext` is `safeDialContext`. It resolves the host and refuses the connection if any resolved IP is reserved (`internal/webhook/webhook.go:59-77`). Because the check happens at dial time on the address actually being connected to, it also defeats DNS rebinding and redirect-to-internal.
  2. *Write-time:* `webhook.ValidateURL` runs when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`), rejecting non-http(s) schemes and hostnames resolving into reserved ranges with `InvalidArgument`.

- **The blocklist** is `reservedCIDRs` in `internal/webhook/validate.go:14-23`: IPv4 loopback, RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), and IPv6 loopback/ULA/link-local. Both layers funnel through `isReservedIP`.

- **Escape hatch:** the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) disables both layers for self-hosted deployments targeting LAN services. Note it defaults to `false` and — outside tests — nothing in the codebase ever sets it, so there is currently no CLI flag or config wiring to turn it on.
