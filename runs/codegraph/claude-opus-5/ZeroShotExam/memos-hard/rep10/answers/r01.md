**Premise correction:** There is no Redis in this repository. A case-insensitive search for `redis` across the whole tree (excluding `node_modules`/`.git`) returns zero hits — nothing in `go.mod`/`go.sum`, no client, no connection string, no config key. There is no external cache server or connection to configure at all.

**Actual mechanism**

Caching is entirely **in-process, in-memory**, in two independent places:

**1. Store-level cache (`store/cache/cache.go`)** — a hand-rolled thread-safe cache built on `sync.Map` + an `atomic.Int64` item counter, with per-item expiration timestamps and a background `cleanupLoop` goroutine (`store/cache/cache.go:66-215`). Each item stores `value`, `expiration`, and an estimated `size`.

Configuration is a plain Go struct literal, not connection settings — `cache.Config{DefaultTTL, CleanupInterval, MaxItems, OnEviction}` (`store/cache/cache.go:41-64`).

**Where user entries are configured and what TTL applies:** `store.New()` in `store/store.go:38-61` builds one shared `cacheConfig` and instantiates three separate caches with it:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
instanceSettingCache: cache.New(cacheConfig),
userCache:            cache.New(cacheConfig),
userSettingCache:     cache.New(cacheConfig),
```

So **user entries get a 10-minute TTL** — that's the only TTL applied to them. All writes go through `userCache.Set(...)` (`store/user.go:98, 122, 132, 143, 167`), and `Set` delegates to `SetWithTTL(..., c.config.DefaultTTL)` (`store/cache/cache.go:93-95`); no caller ever passes a custom TTL for users. Keys are just the stringified user ID (`userCacheKey`, `store/user.go:88-90`); user *settings* use `"<userID>-<key>"` (`store/cache.go:7-9`) and share the same 10-minute TTL.

Expiry is enforced lazily on `Get` (`store/cache/cache.go:135-144`) plus by the 5-minute sweep, and the cache is bounded at 1000 items with an approximate-oldest eviction pass. Entries are also invalidated explicitly on delete (`store/user_delete.go:39`, `DeleteUserSettings` at `store/user_setting.go:110-125`). Note this is per-process state — it is not shared across replicas, which is the practical consequence of there being no Redis.

**2. RSS feed cache (`server/router/rss/rss.go`)** — a completely separate `map[string]*cacheEntry` guarded by a `sync.RWMutex` on `RSSService` (`server/router/rss/rss.go:42-50`), with `defaultCacheDuration = 1 * time.Hour` and `maxCacheSize = 50` (`:23-27`). Per-user RSS feeds are keyed `"user:" + username` (`:114`) and expire after **1 hour** via `getFromCache` (`:346-366`); the same duration is echoed to clients as `Cache-Control: public, max-age=3600` (`:405`). This cache does not use `store/cache` at all.
