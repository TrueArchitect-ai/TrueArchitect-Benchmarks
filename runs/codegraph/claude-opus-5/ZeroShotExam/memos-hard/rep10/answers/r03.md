**Premise correction: there is no nightly database-cleanup job in this repository.** The cron scheduler here is a standalone, unused library — nothing in the application registers any job with it, so there is no scheduled cleanup time to report.

What actually exists:

- `internal/scheduler/` is a self-contained cron package (`scheduler.go`, `parser.go`, `job.go`). `Scheduler.Register` (`internal/scheduler/scheduler.go:70`) is only ever called from the package's own tests and examples (`example_test.go`, `integration_test.go`, `scheduler_test.go`). No code under `server/`, `cmd/`, or `store/` imports the package at all.
- The `"0 2 * * *"` (2 AM daily) cleanup schedule you may have seen is **documentation/example code only**:
  - `internal/scheduler/doc.go:14-16` — `"daily-cleanup"`, `// 2 AM daily`
  - `internal/scheduler/README.md:34-35` and `:321`
  - `internal/scheduler/example_test.go:97-100` — `Example_multipleJobs` registers a `"cleanup"` job at `"0 2 * * *"`
  - None of these touch a database; the handlers just print or are test stubs. The README (`:267-268`) even advises `"5 2 * * *"` over `"0 2 * * *"`.

The only real periodic cleanup in the codebase is in-memory, not database, and not cron-driven: `store/cache/cache.go:200` runs `cleanupLoop` on a `time.Ticker` every 5 minutes by default (`store/cache/cache.go:60`) to evict expired cache entries. The other background runner is `server/runner/s3presign/runner.go:30`, also interval-based.
