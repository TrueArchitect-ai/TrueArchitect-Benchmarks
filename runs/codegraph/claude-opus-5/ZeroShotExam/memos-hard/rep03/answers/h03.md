**`internal/idp`; `internal/idp/oauth2`**

- `internal/idp/idp.go` — package `idp` defines the provider-agnostic abstraction: the `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider implementation must produce.
- `internal/idp/oauth2/oauth2.go` — package `oauth2` is the only concrete protocol implementation ("Package oauth2 implements the OAuth2 identity provider integration"). It provides `IdentityProvider` wrapping `storepb.OAuth2Config`, plus `NewIdentityProvider`, `ExchangeToken` (with optional PKCE `code_verifier`), and `UserInfo`, which maps claims into `idp.IdentityProviderUserInfo` via the configured field mapping.

Supporting evidence that OAuth2 is the sole shipped protocol: the proto enum `IdentityProvider_Type` only has an `OAUTH2` case and the config oneof only has `oauth2Config` (`web/src/components/CreateIdentityProviderDialog.tsx:13-22, 341-350`), and `server/router/api/v1/auth_service_sso.go` constructs providers exclusively via `oauth2.NewIdentityProvider`. Frontend templates (GitHub, GitLab, Google, Custom) are just presets over that same OAuth2 config.
