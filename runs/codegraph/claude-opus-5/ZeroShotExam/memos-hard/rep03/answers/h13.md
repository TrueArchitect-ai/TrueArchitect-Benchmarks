### Implementation
There is exactly one concrete type: the unexported `service` struct (`internal/markdown/markdown.go:58-60`), which wraps a `goldmark.Markdown`. All 8 methods are on `*service` (lines 143, 193, 244, 255, 264, 349, 356, 425). No mock, fake, or alternate implementation exists anywhere in the repo — I grepped for other types with the `ExtractAll(content []byte)` signature and `internal/markdown/markdown.go` is the only hit; even the tests use the real `NewService()`.

Variation comes from functional options rather than from separate types — `NewService(opts ...Option)` (`internal/markdown/markdown.go:85-113`) conditionally appends `extensions.TagExtension` and `extensions.MentionExtension` on top of `extension.GFM`, so the same `*service` type behaves differently depending on `WithTagExtension()` / `WithMentionExtension()`.

### Construction
Production has a single construction site: `NewAPIV1Service` at `server/router/api/v1/v1.go:48-51`, built with **both** tag and mention extensions enabled, and stored on the `APIV1Service`. It is never constructed again — every other holder receives that same instance:

Test-only construction sites: `server/router/api/v1/test/test_helper.go:44` (tags + mentions), `server/router/fileserver/fileserver_test.go:427` (tags only), and `server/router/rss/rss_test.go:54` (no extensions).

### Holders
Three struct fields of type `markdown.Service`:

1. `APIV1Service.MarkdownService` — `server/router/api/v1/v1.go:35`. Used for mention extraction (`memo_mention_helpers.go:32`), webhook snippets (`memo_service_webhooks.go:85`), and passed into `memopayload.RebuildMemoPayload` at `memo_service.go:108` and `:447`.

3. `memopayload.Runner.MarkdownService` — `server/runner/memopayload/runner.go:16`, used at line 52.

One caveat worth flagging: `memopayload.NewRunner` (`server/runner/memopayload/runner.go:19`) is **never called** — `server.go:162` only constructs `s3presign.NewRunner`. So the `Runner` holder exists in code but doesn't execute at runtime; the memopayload path is reached only through the package-level `RebuildMemoPayload` function, which takes the interface as a parameter from `APIV1Service`.

Separately, the frontend does its own markdown work with `mdast-util-from-markdown`/`micromark` (`web/src/utils/markdown-task-actions.ts`) and markdown-it — that is not behind this interface and is a parallel implementation, as the comment at `internal/markdown/markdown.go:29-30` notes.
