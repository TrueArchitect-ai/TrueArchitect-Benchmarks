**1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages)**

The data layer is the `store` package (`/bench/home/work/store/*.go`), which defines the persistent entity types: `User`, `Memo`, `Attachment`, `Inbox`, `MemoRelation`, `MemoShare`, `Reaction`, `UserIdentity`, `UserSetting`, `InstanceSetting`, `IdentityProvider`.

Counting distinct Go packages outside `store/` (and its subpackages `store/db/*`, `store/test`) that reference each type:

| Type | Outside packages |
|---|---|
| `store.User` (`store/user.go:29`) | 7 |
| `store.Memo` (`store/memo.go:35`) | 6 |
| `store.Attachment` (`store/attachment.go:16`) | 4 |
| `store.MemoShare` / `store.MemoRelation` / `store.Inbox` | 3 each |
| `store.UserIdentity` / `store.Reaction` | 2 each |
| `store.UserSetting` / `store.InstanceSetting` / `store.IdentityProvider` | 1 each |

Where they're referenced:

- **`User`** — `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- **`Memo`** — `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`

The ordering holds if you drop the test packages too (User 6, Memo 5). `User` edges out `Memo` mainly because of `server/auth` (`store.User` in session/token handling) and `server/router/fileserver`, neither of which touches `store.Memo`; conversely `Memo`'s extra consumer is `server/runner/memopayload`.
