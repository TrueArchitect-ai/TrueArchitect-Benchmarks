**Premise correction:** There is no Redis anywhere in this repository — no `redis`/`go-redis`/`rueidis` dependency in `go.mod`, no connection string, no config option. A repo-wide search for those terms returns zero hits. The cache layer is a hand-rolled, in-process, in-memory cache, so there is no connection to configure at all.

**Actual mechanism:**

- **Implementation:** `store/cache/cache.go` — a thread-safe in-memory cache built on `sync.Map` plus an `atomic.Int64` item counter (`Cache` struct, `store/cache/cache.go:67`). Each entry stores its value, an absolute `expiration` time, and an estimated size (`item`, `store/cache/cache.go:35`). A background goroutine (`cleanupLoop`, `store/cache/cache.go:200`) sweeps expired entries on a ticker; expired entries are also evicted lazily on `Get` (`store/cache/cache.go:135`). Overflow past `MaxItems` triggers `cleanupOldest` (`store/cache/cache.go:253`).

- **Where it's "configured":** `store.New` in `store/store.go:36-58` builds a single `cache.Config` literal in code (not from env or a config file):
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  - `OnEviction: nil`

  That same config is passed to all three caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`). `cache.DefaultConfig()` (`store/cache/cache.go:57`) carries identical values but is not used by the store.

- **TTL for user entries:** **10 minutes**, inherited from that shared `DefaultTTL`. Every user write path calls `s.userCache.Set(...)` (`store/user.go:98,122,132,143,167`), and `Set` delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). `SetWithTTL` is never called with a custom duration anywhere in non-test code, so there is no per-entry or user-specific TTL override. The cache key is just the user ID as a string (`userCacheKey`, `store/user.go:88`); user settings use a separate `userSettingCache` keyed `"<userID>-<key>"` (`store/cache.go:7`), with the same 10-minute TTL.

- **Scope caveat:** because it's process-local, the cache is not shared across instances — invalidation is explicit (`s.userCache.Delete` / `deleteUserCache` in `store/user_delete.go`, called from `DeleteUser`, `store/user.go:179`), and `Store.Close` stops the cleanup goroutines (`store/store.go:70-75`).
