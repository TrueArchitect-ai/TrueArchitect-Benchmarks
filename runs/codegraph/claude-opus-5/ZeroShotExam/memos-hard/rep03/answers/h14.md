h14.

**`memopayload.RebuildMemoPayload` → `markdown.Service.ExtractAll`; on memo create and on content-updating memo update (plus the batch `Runner.RunOnce` backfill); extracts `tags` + the `property` booleans `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`, and `title` (first H1).**

**Computation site**
- `server/runner/memopayload/runner.go:74` — `RebuildMemoPayload(ctx, memo, markdownService)` ensures `memo.Payload` exists, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`.
- The actual extraction is `internal/markdown/markdown.go:356` (`(*service).ExtractAll`), a single goldmark AST walk. The interface is declared at `internal/markdown/markdown.go:31-55`.
- Shape of the stored data: `proto/store/memo.proto:8-22` (`MemoPayload.property/tags`, `MemoPayload.Property`), generated in `proto/gen/store/memo.pb.go:24`. It is surfaced on the API memo at `server/router/api/v1/memo_service_converter.go:47-51` (`memoMessage.Tags`, `memoMessage.Property`).

**Triggers (recomputation)**
- `CreateMemo` — `server/router/api/v1/memo_service.go:107`, before the store write.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `path == "content"` branch of the update mask; the rebuilt payload is written via `update.Payload`. Other mask paths (visibility, pinned, location, …) do not recompute it — location is set separately on the same payload (`memo_service.go:110-112`).
- Bulk backfill — `Runner.RunOnce` at `server/runner/memopayload/runner.go:27` re-derives the payload for every memo in batches of 100 and persists via `Store.UpdateMemo`. Note this runner is currently not wired up anywhere: `server/server.go` constructs only `s3presign.NewRunner` (`server/server.go:162`); there is no `memopayload.NewRunner` call in the tree, so today the only live triggers are create and content-update.

**What the walk extracts** (`internal/markdown/markdown.go:371-421`)
- `Tags` — every `MemoTag` node, deduplicated case-preserving (`uniquePreserveCase`); `Mentions` are collected in the same pass (lowercased) but are used for mention resolution, not stored in the payload.
- `Property.Title` — text of the first block-level child of the document if it is a level-1 heading (`extractHeadingText`), guarded by `firstBlockChecked`.
- `Property.HasLink` — any `gast.KindLink` node.
- `Property.HasCode` — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- `Property.HasTaskList` — any `east.KindTaskCheckBox`; and `Property.HasIncompleteTasks` when such a checkbox has `IsChecked == false`.

These properties back the list filters `property.hasLink` / `hasTaskList` / `hasCode` in the UI (`web/src/components/MemoFilters.tsx:45-56`, `web/src/hooks/useMemoFilters.ts:73-78`) and the CEL store filters `has_link` / `has_task_list` / `has_code` / `has_incomplete_tasks`.

Note that the preview `snippet` on the API memo is a *separate* derivation — it is computed per-response in `server/router/api/v1/memo_service_converter.go:76` via `getMemoContentSnippet`, not stored in the payload.
