**Premise correction: this repository has no per-user API rate-limiting middleware.** There is no rate limiter to register, and therefore no request limits to report.

What I checked:

- **Echo-level middleware** (`server/server.go:51-52`) — only `middleware.Recover()` and `newCORSMiddleware(profile)`. Echo's `middleware.RateLimiter` is never used.
- **Connect RPC interceptors** (`server/router/api/v1/v1.go:133-138`) — the complete chain is `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor`, all defined in `server/router/api/v1/connect_interceptors.go`. None does rate limiting.
- **gRPC-Gateway middleware** (`server/router/api/v1/v1.go:70-93`) — a single `gatewayAuthMiddleware` doing authentication/anonymous-access policy only.
- **Frontend middleware** (`server/router/frontend/frontend.go:54-60`) — static-file serving and SPA fallback.
- No rate-limiting dependency in `go.mod` (no `golang.org/x/time/rate`, tollbooth, ulule/limiter, etc.), and a repo-wide grep for `rate.?limit|throttl|limiter|quota|burst` returns only unrelated hits (markdown `delimiter` variables in `web/src/components/MemoEditor/Editor/formatting.ts`, and an aspirational comment in `internal/email/doc.go:86`: "Rate limit email sending to prevent abuse").

Adjacent limits that exist but are **not** per-user rate limits:

- `maxAPIRequestBytes = 256 << 20` (256 MiB) in `server/router/api/v1/v1.go:20` — a per-request *body size* cap applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` (lines 126, 141, 144).
- Global concurrency semaphores in `server/router/api/v1/v1.go:59-60` — `thumbnailSemaphore` (3 concurrent) and `imageProcessingSemaphore` (2 concurrent). These are process-wide, not per-user, and bound concurrency rather than request rate.
