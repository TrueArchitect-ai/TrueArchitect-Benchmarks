**Engine:** Google CEL (`github.com/google/cel-go`), wrapped by the in-repo filter engine at `internal/filter/` — `engine.go` (`Engine`/`Program`/`DefaultEngine`), `schema.go` (CEL env + field declarations), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL), `helpers.go` (`AppendConditions`).

**Mechanism (one sentence):** `Engine.Compile` (`internal/filter/engine.go:48`) type-checks the filter string against a memo-specific CEL environment and converts the CEL AST into a dialect-agnostic IR condition tree via `buildCondition` (`internal/filter/parser.go`), then `Program.Render` (`internal/filter/engine.go:96`) walks that IR with a dialect-parameterized renderer (`internal/filter/render.go`, `DialectSQLite`/`DialectMySQL`/`DialectPostgres` from `internal/filter/schema.go:11-16`) that emits a parameterized SQL fragment plus args — `?` vs `$n` placeholders, `json_extract` vs `JSON_EXTRACT` vs `->>`, `LIKE` vs `ILIKE`, `REGEXP` vs `~`, etc.

**Wiring:**
- `ListMemos` RPC validates the filter (`server/router/api/v1/memo_service.go:211-216` → `validateFilter` at `server/router/api/v1/shortcut_service.go:336`, which picks the dialect from `s.Profile.Driver`) and appends it to `store.FindMemo.Filters`.
- Each driver's `ListMemos` calls `filter.DefaultEngine()` then `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)`, which appends `(<fragment>)` to the WHERE list with a `PlaceholderOffset` equal to the current arg count: `store/db/sqlite/memo.go:57-63`, `store/db/mysql/memo.go:65-71`, `store/db/postgres/memo.go:54-60`.
- Design notes and per-dialect SQL specifics are documented in `internal/filter/README.md`.
