**Convergence for delivery:**

The three lifecycle dispatchers (created/updated/deleted) are one-line wrappers over the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo creator, loads that user's webhooks via `s.Store.GetUserWebhooks`, builds a payload with `convertMemoToWebhookPayload` (`:76`), and calls `webhook.PostAsync` per hook.

The comment-created dispatcher does **not** go through `dispatchMemoRelatedWebhook` — it inlines the same loop (targeting the *related* memo's owner rather than the comment creator) and also ends at `webhook.PostAsync`.

So the single convergence point for all four is `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue` channel (cap 128, dropping with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`) drain that queue and perform the actual HTTP delivery in `webhook.Post` (`internal/webhook/webhook.go:120`) — which does the HMAC-SHA256 Standard Webhooks signing and posts via the SSRF-guarded `safeClient`.
