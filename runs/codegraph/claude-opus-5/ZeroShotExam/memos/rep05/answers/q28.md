**Runners the server actually starts**

- **s3presign runner (the only true background runner)** — started in `Server.startBackgroundRunners` (`server/server.go:153-174`). Driven two ways: one synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a goroutine running `Run(s3Context)`, which is a `time.Ticker` loop with a hardcoded 12-hour interval (`server/runner/s3presign/runner.go:27-41`). Cancelled via its own `context.CancelFunc` stored in `backgroundRunnerCancels` and awaited through `backgroundRunnerWG` on shutdown (`server/server.go:176-201`).
- **HTTP server goroutine** — `s.httpServer.Serve(listener)` in a goroutine (`server/server.go:124-128`); event-driven by incoming connections, not scheduled.
- **Store cache cleanup loops (3 of them)** — `go c.cleanupLoop()` in `store/cache/cache.go:83`, started implicitly by `cache.New(...)` for `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`). Driven by a `time.Ticker` on `CleanupInterval = 5 * time.Minute` (`store/store.go:40-44`, `store/cache/cache.go:200-215`). Stopped only when `Store.Close()` runs at shutdown.
- **Async email workers (2)** — package `init()` spawns 2 goroutines draining `asyncEmailQueue` (`internal/email/email.go:14-30`). Queue-driven (fire-and-forget on send requests), not time-scheduled; started at package init, so they exist whenever the binary runs.
- **Async webhook dispatch workers (4)** — package `init()` spawns 4 goroutines draining `asyncPostQueue` (`internal/webhook/webhook.go:42-55`). Queue-driven.
- **Signal-handler goroutine** — `cmd/memos/main.go:99-103`; waits on SIGINT/SIGTERM, then calls `s.Shutdown`.
- **Per-request/per-connection goroutines** (not persistent workers): SSE heartbeat ticker at 30s per connected client (`server/router/api/v1/sse_handler.go:16-17,63-64`), and PAT last-used recording fired per authenticated request (`server/auth/authenticator.go:180`).

**Unused scheduling infrastructure**

`internal/scheduler/` — a full cron scheduler (cron expression parser supporting 5- and 6-field formats, `Job` registration, `Scheduler.Start/Stop`, timezone support, middleware chain: `internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`, plus a README and `doc.go`) is **never used by the server**. The only references to `github.com/usememos/memos/internal/scheduler` in the whole repo are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). Nothing in `server/`, `store/`, or `cmd/` imports it — the one real runner (s3presign) uses a plain `time.Ticker` instead.

Secondary note: `server/runner/memopayload` is a directory under `server/runner/`, but its `Runner`/`RunOnce` (`server/runner/memopayload/runner.go:14,26`) is never started by the server either — only its standalone `RebuildMemoPayload` function is called inline from request handlers (`server/router/api/v1/memo_service.go:108,447`).
