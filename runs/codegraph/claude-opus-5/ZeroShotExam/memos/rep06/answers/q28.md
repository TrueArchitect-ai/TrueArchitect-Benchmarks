**Runners the server actually starts**

- **s3presign runner (continuous loop)** — `server/server.go:162-171` creates `s3presign.NewRunner(s.Store)` and runs `Run(s3Context)` in a goroutine; driven by a fixed `time.NewTicker(runnerInterval)` where `runnerInterval = 12h` (`server/runner/s3presign/runner.go:27,29-41`). Cancelled via the stored `context.CancelFunc` in `stopBackgroundRunners` (`server/server.go:176`), waited on by `backgroundRunnerWG`.
- **s3presign one-shot pass** — `s3presignRunner.RunOnce(ctx)` at `server/server.go:163`, executed synchronously at server start (before the ticker loop), so presigning happens immediately on boot rather than after 12h.
- **Store cache janitors (3 instances)** — `cache.New(...)` launches `go c.cleanupLoop()` (`store/cache/cache.go:83,200`), driven by `CleanupInterval = 5 * time.Minute` set in `store.New` (`store/store.go:39-53`). Started indirectly for `instanceSettingCache`, `userCache`, `userSettingCache` when the store is created in `cmd/memos/main.go`.
- **SSE heartbeat** — `time.NewTicker(sseHeartbeatInterval)` with `sseHeartbeatInterval = 30 * time.Second` (`server/router/api/v1/sse_handler.go:17,64`); per-connection, started on each SSE stream request rather than at boot, and torn down by `sseHub.Close()` during shutdown (`server/server.go:203-208`).
- **Shutdown signal watcher** — `go func() { <-c; s.Shutdown(ctx) }()` in `cmd/memos/main.go:99`, triggered by SIGINT/SIGTERM (`signal.Notify`).

Fire-and-forget goroutines (not scheduled workers): webhook dispatch (`internal/webhook/webhook.go:44`), email send (`internal/email/email.go:18`), PAT last-used update (`server/auth/authenticator.go:180`) — each spawned per request/event.

**Unused scheduling infrastructure**

- `internal/scheduler/` — a full cron scheduler (`Scheduler.Register/Start/Stop`, `ParseCronExpression`, job middleware chain; `scheduler.go`, `job.go`, `parser.go`, `middleware.go`) is **never used by the server**. Its only importers are its own tests: `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. No production code imports the package, so no cron expression drives anything at runtime.
- `server/runner/memopayload.Runner` — `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19,27`) are never called by the server; only the package-level helper `memopayload.RebuildMemoPayload` is used, and it's invoked inline on memo create/update (`server/router/api/v1/memo_service.go:108,447`). So the memopayload backfill runner exists but is not started or scheduled.
