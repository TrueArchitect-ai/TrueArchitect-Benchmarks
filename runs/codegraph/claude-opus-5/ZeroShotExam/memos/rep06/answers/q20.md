**Server-Sent Events (SSE) over a long-lived HTTP `GET /api/v1/sse` stream; `server/router/api/v1/sse_hub.go`; CreateMemo, UpdateMemo (via `dispatchMemoUpdatedSideEffects`), DeleteMemo, CreateMemoComment, UpsertMemoReaction, DeleteMemoReaction**

Details:

**Mechanism** — SSE, not WebSockets. `handleSSE` (`server/router/api/v1/sse_handler.go:33`) sets `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`, writes `data: %s\n\n` frames, and sends a `: heartbeat` comment every 30s. Auth is a Bearer token on the request; the route is registered by `RegisterSSERoutes` (`sse_handler.go:24`) and mounted in `server/router/api/v1/v1.go:125`. The browser side consumes it with a `fetch` stream at `web/src/hooks/useLiveMemoRefresh.ts:203`.

**Hub** — `SSEHub` in `server/router/api/v1/sse_hub.go:56`: a mutex-guarded set of `SSEClient`s each with a 32-slot buffered channel. `Subscribe`/`Unsubscribe`/`Close`/`Broadcast` (line 115); `Broadcast` drops events for clients whose buffer is full rather than blocking, and filters per client via `canReceive` (line 134) so `PRIVATE` memos only reach the creator or an admin. Constructed once in `v1.go:57`, held by the server at `server/server.go:38`.

Reaction events are built by `buildMemoReactionSSEEvent` (`server/router/api/v1/sse_event_helpers.go:24`), which uses the parent memo's creator for visibility scoping when the target is a comment.
