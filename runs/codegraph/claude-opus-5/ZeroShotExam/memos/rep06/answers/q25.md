**Engine: Google CEL (`cel-go`), wrapped by the in-repo filter engine at `internal/filter/`** — entry point `filter.DefaultEngine()` in `internal/filter/engine.go:111`.

**Mechanism (one sentence):** `Engine.Compile` parses the filter with `cel-go` (`e.env.Compile` → `cel.AstToParsedExpr`, `internal/filter/engine.go:48-71`), `buildCondition` in `internal/filter/parser.go` normalizes the CEL AST into a dialect-agnostic IR condition tree (`internal/filter/ir.go`) while validating it against the memo schema, and `Program.Render` walks that IR through `internal/filter/render.go` with a `RenderOptions{Dialect, PlaceholderOffset}` to emit a dialect-specific SQL fragment plus bound args.

**Where the dialect differences live** (`internal/filter/schema.go`, `internal/filter/render.go`):
- Dialect constants `DialectSQLite`/`DialectMySQL`/`DialectPostgres` at `internal/filter/schema.go:13-17`.
- Per-field SQL overrides via `Field.Expressions map[DialectName]string`, applied by `Field.columnExpr` (`internal/filter/schema.go:321-327`) — e.g. `creator` renders `('users/' || %s)` on SQLite/Postgres vs `CONCAT('users/', %s)` on MySQL (`schema.go:104-108`).
- Placeholders: `renderer.addArg` emits `$n` (offset-adjusted) for Postgres and `?` otherwise (`internal/filter/render.go:842-849`).
- Per the package README (`internal/filter/README.md`), JSON access (`JSON_EXTRACT` / `json_extract` / `->` / `->>`), tag membership (SQLite `LIKE`, MySQL `JSON_CONTAINS`, Postgres `@>`), and `LIKE` vs `ILIKE` are likewise branched in the renderer helpers.

Constant folding also happens at compile time: `now` is frozen once per `Compile` via `Engine.nowFunc` (`engine.go:17-20,62`), and always-true/always-false conditions collapse to an empty fragment or `1 = 0` (`render.go:42-58`).
