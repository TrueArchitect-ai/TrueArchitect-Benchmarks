### How it works

**Frontend interceptor — `web/src/connect.ts:156`**
`authInterceptor` is a Connect‑RPC `Interceptor` registered on the single `createConnectTransport` (`web/src/connect.ts:184-189`) that backs every generated service client (`memoServiceClient`, `userServiceClient`, etc.). On each request it:
1. Calls `getRequestToken()` (`connect.ts:124`) and sets `Authorization: Bearer <token>` (`connect.ts:97`).
2. Preflight‑refreshes if the token is within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), so public endpoints like `ListMemos` don't silently return guest‑scoped data.
3. On a `Code.Unauthenticated` error, refreshes once, replays the request with an `X-Retry: true` header, and on failure calls `redirectOnAuthFailure()` (`connect.ts:161-177`).

Refresh goes through a *separate* transport with no interceptors to avoid recursion (`connect.ts:65-72`), and concurrent refreshes are deduped by `tokenRefreshManager` (`connect.ts:30-51`). The `fetch` wrapper uses `credentials: "include"` so the refresh cookie rides along.

**Token storage — `web/src/auth-state.ts`**
Holds the access token in memory + `localStorage` (`memos_access_token`, `memos_token_expires_at`) with `getAccessToken` / `setAccessToken` / `isTokenExpired` / `hasStoredToken` / `clearAccessToken`, and syncs freshly refreshed tokens across tabs via a `BroadcastChannel` (`memos_token_sync`).

**Token kinds**
- Access token: JWT, 15 min (`server/auth/token.go:38`), sent as `Authorization: Bearer`.
- Refresh token: JWT, 30 days, stored in the `memos_refresh` cookie (`server/auth/token.go:41-49`), used only by `AuthService.RefreshToken`.
- Personal Access Token: `memos_pat_`‑prefixed random string, SHA‑256 hashed in the DB — for CLI/mobile/third‑party, managed in `web/src/components/Settings/AccessTokenSection.tsx`.

**Backend validation — `server/auth`**
`Authenticator` (`server/auth/authenticator.go:26`) validates all three: `AuthenticateByAccessTokenV2` (stateless JWT parse), `AuthenticateByRefreshToken` (JWT + DB revocation/expiry check), `AuthenticateByPAT` (prefix check + hash lookup, async last‑used update). Header/cookie parsing lives in `server/auth/extract.go`. It's wired into the request path via `Authorizer` in `server/router/api/v1/authz.go:44`, which the Connect interceptor (`server/router/api/v1/connect_interceptors.go`) and gRPC‑Gateway middleware both share, so `ErrUnauthenticated` maps to the `Unauthenticated` code the frontend interceptor keys off.
