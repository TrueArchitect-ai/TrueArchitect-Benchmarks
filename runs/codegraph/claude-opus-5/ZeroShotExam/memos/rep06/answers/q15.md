The repo has no ORM — mapping is done by hand-written SQL in per-driver files (`store/db/sqlite`, `store/db/postgres`, `store/db/mysql`), each of which scans rows into the shared model structs in the `store` package.

| table | Struct — path |
|---|---|
| `user` | `User` — `store/user.go:29` |
| `attachment` | `Attachment` — `store/attachment.go:16` |
| `reaction` | `Reaction` — `store/reaction.go:7` |

Evidence of the table binding (SQL naming the table, scanning into the struct):
- `user` → `store/db/mysql/user.go:18` (`INSERT INTO user ...`), `:147` scans into `store.User`; also `store/db/sqlite/user.go:17`, `store/db/postgres/user.go`.
- `attachment` → `store/db/sqlite/attachment.go:34`, `store/db/mysql/attachment.go:34`, `store/db/postgres/attachment.go:33`.
- `reaction` → `store/db/sqlite/reaction.go:16`, `store/db/mysql/reaction.go:16`, `store/db/postgres/reaction.go:13`.

Each model file also carries its companion `Find*`/`Update*`/`Delete*` query structs (e.g. `FindUser`, `FindAttachment`, `FindReaction`), which are query descriptors rather than row mappings.
