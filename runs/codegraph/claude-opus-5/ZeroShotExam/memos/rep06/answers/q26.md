**Tables affected: `memo`, `memo_relation`, `attachment`, and `memo_share` (via DB-level FK cascade on Postgres/MySQL only).**

### Direct + explicit cascade code

`store/memo.go:140` — `Store.DeleteMemo` does the explicit cleanup, in order:

1. **`memo_relation`** — two deletes, once matching `memo_id` and once matching `related_memo_id` (`store/memo.go:142-147` → `store/db/{sqlite,postgres,mysql}/memo_relation.go`).
2. **`attachment`** — lists attachments with `MemoID = delete.ID` and calls `Store.DeleteAttachment` per row (`store/memo.go:149-157`); that also removes the underlying local/S3 blob before the row delete (`store/attachment.go:132-149`).
3. **`memo`** — the row itself, `DELETE FROM memo WHERE id = ?` (`store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`, `store/db/sqlite/memo.go:237`).

The API layer (`server/router/api/v1/memo_service.go:518`) adds recursion: before deleting the target memo it finds child memos via `memo_relation` of type `COMMENT` and calls `Store.DeleteMemo` on each (lines 567-577), so the same three tables are hit again for every comment.

### Cascade at the DB level

**`memo_share`** has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`, `store/migration/sqlite/LATEST.sql:109`). There is no Go code deleting shares on memo deletion, so this relies entirely on the database — and **on SQLite it does not fire**: the connection opens with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), leaving orphaned `memo_share` rows on that driver.

### Not affected

**`reaction`** is read but never deleted. `DeleteMemo` lists reactions only to build the webhook payload (`server/router/api/v1/memo_service.go:545-550`), and `reaction.content_id` is a plain `TEXT` column holding `memos/{uid}` with no foreign key (`store/migration/sqlite/LATEST.sql:92-98`). `Store.DeleteReaction` is called only from `DeleteMemoReaction` (`server/router/api/v1/reaction_service.go:141`). Reaction rows for a deleted memo are left orphaned.
