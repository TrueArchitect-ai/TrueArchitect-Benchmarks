**Memo lifecycle events that dispatch webhooks** — all defined in `server/router/api/v1/memo_service_webhooks.go`:

```
memos.memo.created: DispatchMemoCreatedWebhook (memo_service_webhooks.go:15)
memos.memo.updated: DispatchMemoUpdatedWebhook (memo_service_webhooks.go:20)
memos.memo.deleted: DispatchMemoDeletedWebhook (memo_service_webhooks.go:25)
memos.memo.comment.created: DispatchMemoCommentCreatedWebhook (memo_service_webhooks.go:30)
```

**Convergence for delivery:**

- The first three are thin wrappers over the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks via `Store.GetUserWebhooks`, builds a payload with `convertMemoToWebhookPayload`, and enqueues it. `DispatchMemoCommentCreatedWebhook` skips that helper (it targets the *related* memo's owner rather than the comment creator) but does the same payload construction inline.
- **All four converge on `webhook.PostAsync`** (`internal/webhook/webhook.go:184`), which pushes the payload onto the bounded `asyncPostQueue` (cap 128, dropping with a warning if full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call **`webhook.Post`** (`internal/webhook/webhook.go:120`) — the actual HTTP delivery: JSON marshal, optional Standard-Webhooks HMAC-SHA256 signing headers, and POST through the SSRF-guarded `safeClient`.

Call sites that trigger them: `memo_service.go:157` (create), `memo_update_helpers.go:67` via `dispatchMemoUpdatedSideEffects` (update — also reached from `memo_relation_service.go:48` and `memo_attachment_service.go:48`), `memo_service.go:562` (delete), and `memo_service_comments.go:119` (comment created).
