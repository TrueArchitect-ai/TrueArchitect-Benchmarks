**Tables written to (rows deleted) by `DeleteMemo`: `memo`, `memo_relation`, `attachment` — plus `memo_share` via DB-level `ON DELETE CASCADE` (Postgres/MySQL only).**

Trace:

**API layer — `server/router/api/v1/memo_service.go:518-593`**
1. Reads the memo (`memo`), its reactions (`reaction`) and attachments (`attachment`) only to build the webhook payload — no deletes there (`:545-565`).
2. Lists comment relations and calls `store.DeleteMemo` for each child comment memo (`:567-577`), so every table below is hit once per comment memo as well.
3. Calls `store.DeleteMemo` for the memo itself (`:580`).

**Store layer — `store/memo.go:140-159`** (the explicit cascade code)
- `memo_relation`: two deletes, one where the memo is the source (`MemoID`) and one where it's the target (`RelatedMemoID`) — `store/memo.go:142-147`, SQL at `store/db/sqlite/memo_relation.go` / mysql / postgres equivalents.
- `attachment`: lists attachments with `MemoID` and calls `Store.DeleteAttachment` per row (`store/memo.go:149-157`), which deletes the DB row (`store/db/mysql/attachment.go:230`, sqlite/postgres equivalents) and also removes the local/S3 file and thumbnail/motion caches (`store/attachment.go:132-148`, `:202-293`).
- `memo`: the row itself — `store/db/sqlite/memo.go`, `store/db/mysql/memo.go:259`, `store/db/postgres/memo.go:244`.

**`memo_share` — cascade only on Postgres/MySQL**
`memo_share.memo_id` has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`). There is no Go code deleting shares in this path, and SQLite opens its connection with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so on SQLite the cascade does **not** fire and `memo_share` rows are left orphaned. (`store/db/*/user_delete.go` deletes `memo_share` explicitly, but that's the user-deletion path, not `DeleteMemo`.)

**Not touched:** `reaction` — rows keyed by `content_id = "memos/{uid}"` are read for the webhook but never deleted; the only `DeleteReaction` caller is `server/router/api/v1/reaction_service.go:141`. Reaction rows for a deleted memo are orphaned on all three databases (no FK on `reaction.content_id`, `store/migration/sqlite/LATEST.sql:92-99`).
