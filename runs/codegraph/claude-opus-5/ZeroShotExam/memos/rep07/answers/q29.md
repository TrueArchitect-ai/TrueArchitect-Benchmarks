**`web/src/connect.ts`; short‑lived JWT access token (Bearer, in localStorage/memory) + HttpOnly `memos_refresh` refresh‑token cookie (and PAT `memos_pat_…` as an equivalent bearer credential); `server/auth`**

Details:

- **Interceptor** — `authInterceptor` in `web/src/connect.ts:156`, installed on the Connect transport (`web/src/connect.ts:184-189`, `useBinaryFormat`, `fetch` wrapper forcing `credentials: "include"` so the refresh cookie rides along). Every service client (memo, user, auth, attachment, AI, shortcut, IdP, instance) is created from that transport, so all frontend RPCs go through it.
- **What it does** — on each request it calls `getRequestToken()` (`web/src/connect.ts:124`), which reads the cached access token and *proactively* refreshes when it's within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30 s) of expiry, then sets `Authorization: Bearer <token>`. On a `Code.Unauthenticated` response it reactively refreshes once, replays the request with an `X-Retry: true` marker to prevent loops, and on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- **Token storage/kinds (frontend)** — `web/src/auth-state.ts`: access token + expiry in `localStorage` under `memos_access_token` / `memos_token_expires_at`, mirrored in memory and synced across tabs via a `memos_token_sync` BroadcastChannel. The refresh token is never touched by JS — it's an HttpOnly cookie; refresh goes through a *separate* transport with no interceptors (`web/src/connect.ts:65-91`) calling `AuthService.RefreshToken`, deduped by a refresh manager so focus-refresh and 401-refresh don't race.
- **Backend validation** — `server/auth` (`github.com/usememos/memos/server/auth`): `Authenticator` in `server/auth/authenticator.go` validates access tokens statelessly (`AuthenticateByAccessTokenV2`, 15 min, audience `user.access-token`), refresh tokens against the DB for revocation (`AuthenticateByRefreshToken`, 30 days, cookie `memos_refresh`), and PATs by SHA‑256 hash lookup (`AuthenticateByPAT`, prefix `memos_pat_`); constants in `server/auth/token.go`, header/cookie parsing in `server/auth/extract.go`.
- **Wiring on the server side** — `AuthInterceptor.WrapUnary` (`server/router/api/v1/connect_interceptors.go:217`) reads the `Authorization` header, delegates to `Authorizer.Authenticate` / `CheckAccess` (`server/router/api/v1/authz.go`), and stores the result via `auth.ApplyToContext`.
