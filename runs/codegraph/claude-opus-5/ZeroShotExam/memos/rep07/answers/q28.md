**Runners the server actually starts**

- **s3presign — startup one-shot + 12h `time.Ticker`** — `server/server.go:153-174` is the only thing `startBackgroundRunners` launches. It calls `s3presignRunner.RunOnce(ctx)` synchronously during `Start()`, then spawns one goroutine running `s3presign.Runner.Run`, which loops on `time.NewTicker(runnerInterval)` with `runnerInterval = 12h` (`server/runner/s3presign/runner.go:27-41`). Cancellation is via a per-runner `context.CancelFunc` stored in `backgroundRunnerCancels`, fired by `stopBackgroundRunners` on shutdown (`server/server.go:176-182`), with a `sync.WaitGroup` join in `waitBackgroundRunners`.
- **HTTP serve loop — one goroutine per process, event-driven (incoming connections)** — `go s.httpServer.Serve(listener)` at `server/server.go:124-128`. Not a scheduled runner, but it is the other goroutine `Start()` launches.
- **store cache cleanup loops (×3) — 5-minute `time.Ticker`** — started indirectly at boot, not by `startBackgroundRunners`: `store.New` builds three `cache.New(...)` instances (`store/store.go:51-53`) and `cache.New` does `go c.cleanupLoop()` (`store/cache/cache.go:76-84`), which ticks on `CleanupInterval = 5 * time.Minute` (`store/cache/cache.go:200-215`). Created in `cmd/memos/main.go` before `server.NewServer`.
- **signal-shutdown goroutine — event-driven (SIGINT/SIGTERM)** — `cmd/memos/main.go:99-103`.

Per-request goroutines/tickers (not server-lifetime runners): the SSE heartbeat `time.NewTicker(sseHeartbeatInterval)` lives inside the SSE request handler (`server/router/api/v1/sse_handler.go:63-64`), and fire-and-forget goroutines exist for PAT last-used updates (`server/auth/authenticator.go:180`), email sending (`internal/email/email.go:18`), and webhooks (`internal/webhook/webhook.go:44`).

**Unused scheduling infrastructure**

- **`internal/scheduler` (cron scheduler) is NOT used by the server.** It's a complete implementation — `Scheduler.Register/Start/Stop` with per-job goroutines and timers (`internal/scheduler/scheduler.go`), a 5/6-field cron parser with `Schedule.Next` (`internal/scheduler/parser.go`), plus `job.go`, `middleware.go`, `doc.go`, `README.md`. The only files importing `github.com/usememos/memos/internal/scheduler` are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). No production code registers a job; the one real runner uses a raw ticker instead.
- **`server/runner/memopayload.Runner` is also never started.** `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19-27`) have no production caller — only the package's `RebuildMemoPayload` helper is used, inline in request handling (`server/router/api/v1/memo_service.go:108,447`). So the `runner/` directory has two runners but only s3presign is wired into `startBackgroundRunners`.
