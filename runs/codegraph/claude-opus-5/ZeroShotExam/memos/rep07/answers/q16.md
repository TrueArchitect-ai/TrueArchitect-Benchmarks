`Store.DeleteMemo` (`store/memo.go:140`) performs these deletions before the `DELETE FROM memo` row delete in the driver:

- **`memo_relation` rows where the memo is the source** — `driver.DeleteMemoRelation(&DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
- **`memo_relation` rows where the memo is the target/related memo** — `driver.DeleteMemoRelation(&DeleteMemoRelation{RelatedMemoID: &delete.ID})` (`store/memo.go:145`)
- **Attachments linked to the memo** — listed via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and removed one-by-one with `DeleteAttachment` (`store/memo.go:149-157`), which also cleans up the blob/thumbnail on disk in `store/attachment.go`.

Only then does it call `s.driver.DeleteMemo` (`store/memo.go:158`), which is the plain `DELETE FROM memo WHERE id = ?` in each driver (`store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`).

Two things the store layer does *not* delete: reactions and memo shares. Reactions are only read (for the webhook payload) in `server/router/api/v1/memo_service.go:545`, never deleted. Comment memos are deleted by the API service before calling the store (`server/router/api/v1/memo_service.go:567-577`), not by `Store.DeleteMemo` itself.
