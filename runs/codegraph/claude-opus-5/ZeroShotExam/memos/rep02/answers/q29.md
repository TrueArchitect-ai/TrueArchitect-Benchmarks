**`web/src/connect.ts` (`authInterceptor`, lines 156–178); JWT access token (in-memory + localStorage) + HttpOnly refresh-token cookie `memos_refresh`, plus `memos_pat_` Personal Access Tokens for non-browser clients; `server/auth`**

How it works:

**Frontend** — `web/src/connect.ts:156` defines `authInterceptor`, registered on the single Connect-Web transport at `web/src/connect.ts:184-189` that backs every service client (`memoServiceClient`, `userServiceClient`, etc.). Per request it:
1. Calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, line 97).
2. Preflight-refreshes if the token is within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), so public endpoints like ListMemos don't silently degrade to anonymous.
3. On a `Code.Unauthenticated` reply, refreshes once, marks the retry with an `X-Retry` header to prevent loops, and replays; if the refresh fails it calls `redirectOnAuthFailure()`.

Refresh goes through a *separate* transport with no interceptors (`web/src/connect.ts:65-72`) to avoid recursion, and through `tokenRefreshManager` so concurrent refreshes are deduped.

**Token storage** — `web/src/auth-state.ts`: access token + expiry held in module state and mirrored to `localStorage` under `memos_access_token` / `memos_token_expires_at`, with a `BroadcastChannel` (`memos_token_sync`) so a refresh in one tab is adopted by the others. The refresh token itself is never touched by JS — it rides in a cookie sent via `credentials: "include"` (`fetchWithCredentials`, `web/src/connect.ts:57`).

**Backend** — the validating package is **`server/auth`**:
- `server/auth/authenticator.go:213` `Authenticate` → `resolveBearer` (line 149) splits on the `memos_pat_` prefix: stateless JWT validation via `AuthenticateByAccessTokenV2` (line 41) or DB-hash lookup via `AuthenticateByPAT` (line 102).
- `AuthenticateByRefreshToken` (line 61) validates the cookie token against the DB for revocation/expiry.
- `server/auth/token.go` holds the constants: `AccessTokenDuration` 15 min, `RefreshTokenDuration` 30 days, cookie `memos_refresh`, prefix `memos_pat_`.

It's wired into the request path by `AuthInterceptor.WrapUnary` (`server/router/api/v1/connect_interceptors.go:217`) via the shared `Authorizer` (`server/router/api/v1/authz.go:34-69`), which the gRPC-Gateway path and `sse_handler.go` also use so both transports enforce identical rules.
