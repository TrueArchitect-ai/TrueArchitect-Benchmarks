## Mechanism

Plain HTTP SSE (`Content-Type: text/event-stream`), not WebSockets. The endpoint is registered at `/api/v1/sse` in `server/router/api/v1/sse_handler.go:27` (`RegisterSSERoutes`, wired from `server/router/api/v1/v1.go:125`). `handleSSE` (`sse_handler.go:34`) authenticates via a Bearer token, sets SSE headers including `X-Accel-Buffering: no`, subscribes to the hub, then writes `data: <json>\n\n` frames plus a `: heartbeat` comment every 30s.

The browser side is `web/src/hooks/useLiveMemoRefresh.ts` — it uses `fetch()` + a stream reader (not `EventSource`, so it can send an `Authorization` header), with exponential-backoff reconnect, and translates each event into React Query cache invalidations.

## Hub

`server/router/api/v1/sse_hub.go` — `SSEHub` (line 56) holds a mutex-guarded set of `*SSEClient`, each with a 32-buffered `chan []byte`. `Subscribe`/`Unsubscribe`/`Close`/`Broadcast`. `Broadcast` (line 115) marshals the event once and does a non-blocking send per client, dropping events for slow clients. Per-client filtering is in `canReceive` (line 134): private memos only reach the creator or an admin. The hub instance is created in `server/router/api/v1/v1.go:57` (`NewSSEHub()`) and held by `APIV1Service.SSEHub`.
