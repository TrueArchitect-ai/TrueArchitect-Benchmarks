**Convergence for delivery**

The three plain lifecycle events (created/updated/deleted) are thin wrappers over the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook(ctx, memo, activityType)` at `server/router/api/v1/memo_service_webhooks.go:48`, which resolves the memo creator, loads their webhooks via `s.Store.GetUserWebhooks`, and builds a payload with `convertMemoToWebhookPayload` (`memo_service_webhooks.go:76`).

The comment event does *not* go through that helper — it looks up the *related memo owner's* webhooks inline (`memo_service_webhooks.go:31-44`) rather than the comment creator's.

All four converge at `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto a bounded 128-slot channel `asyncPostQueue` drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`); each calls `webhook.Post` (`internal/webhook/webhook.go:120`), the single function that marshals the payload, adds Standard Webhooks HMAC headers when a signing secret is set, and POSTs via the SSRF-guarded `safeClient`. Note `PostAsync` drops the payload with a warning if the queue is full.
