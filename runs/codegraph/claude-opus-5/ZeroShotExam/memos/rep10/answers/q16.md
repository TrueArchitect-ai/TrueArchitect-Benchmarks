The store-level `Store.DeleteMemo` (`store/memo.go:140-159`) performs this cleanup before calling the driver's `DeleteMemo`, which is the actual `DELETE FROM memo` (`store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`):

1. **Memo relation records where the memo is the source** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
2. **Memo relation records where the memo is the target/related memo** — `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and removed one by one with `DeleteAttachment` (`store/memo.go:149-157`)

Context: the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-593`) additionally deletes the memo's **comment memos** first (each via `Store.DeleteMemo`, so their own relations/attachments are cleaned up too) before deleting the target memo — but that step lives in the service layer, not the store. Reactions are read for the webhook payload but are not deleted by the store's `DeleteMemo`.
