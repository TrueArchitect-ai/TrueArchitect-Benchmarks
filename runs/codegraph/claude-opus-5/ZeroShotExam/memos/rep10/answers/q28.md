**Runners the server actually starts**

- **s3presign runner (`server/runner/s3presign/runner.go`)** — started in `Server.startBackgroundRunners` (`server/server.go:153-174`). Two triggers: one immediate synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a goroutine running `Run(s3Context)` which is driven by a plain `time.NewTicker(runnerInterval)` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27-41`). Cancelled via a per-runner `context.CancelFunc` stored in `backgroundRunnerCancels` and awaited through `backgroundRunnerWG` on shutdown (`server/server.go:176-201`).
- **Cache cleanup loops ×3 (`store/cache/cache.go:83`, `cleanupLoop` at :199)** — started implicitly by `store.New` (`store/store.go:51-53` creates `instanceSettingCache`, `userCache`, `userSettingCache`), so they are running before/independently of `Server.Start`. Trigger: `time.NewTicker(CleanupInterval)` with `CleanupInterval = 5 * time.Minute` (`store/store.go:42`).
- **Webhook dispatch pool, 4 goroutines (`internal/webhook/webhook.go:42-55`)** — started by package `init()`, not by the server. Trigger: not time-based; they block on the `asyncPostQueue` channel (buffer 128) and fire per enqueued webhook payload.
- **Email dispatch pool, 2 goroutines (`internal/email/email.go:16-35`)** — also package `init()`. Trigger: messages arriving on `asyncEmailQueue` (buffer 128).
- **HTTP serve goroutine (`server/server.go:124-128`)** and **signal-handler goroutine (`cmd/memos/main.go:99`)** — not schedulers; request-driven and SIGINT/SIGTERM-driven respectively.
- **SSE heartbeat ticker (`server/router/api/v1/sse_handler.go:64`, 30s)** — per-connection inside the request handler, not a background runner; lifetime is the client connection.

**Unused scheduling infrastructure**

- **`internal/scheduler/` is NOT used by the server.** It's a full cron-expression scheduler (`scheduler.go` with `Register`/`Start`/`Stop`/`runJobWithSchedule`, plus `job.go`, `parser.go`, `middleware.go`, `doc.go`, `README.md`), but the only non-test importers are its own tests — `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. No production code registers a job or calls `Scheduler.Start()`; the one real periodic runner uses a raw ticker instead.
- Also unused: **`memopayload.Runner` / `NewRunner` / `RunOnce` (`server/runner/memopayload/runner.go:19-72`)** is never instantiated or started anywhere. Only the free function `RebuildMemoPayload` is used, and only inline on the request path (`server/router/api/v1/memo_service.go:108` and `:447`), never on a schedule.
