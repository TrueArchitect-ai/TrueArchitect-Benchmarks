**`web/src/connect.ts` (`authInterceptor`, lines 156–178) + `web/src/auth-state.ts`; short‑lived JWT access token (V2) in `Authorization: Bearer` + HTTP‑only refresh‑token cookie, plus long‑lived Personal Access Tokens (`memos_pat_` prefix); `server/auth/`**

How it works:

- **Interceptor** — `web/src/connect.ts:156` defines `authInterceptor`, registered on the single Connect transport (`web/src/connect.ts:184-189`) that backs every service client (`memoServiceClient`, `userServiceClient`, …). On each request it calls `getRequestToken()` and sets `Authorization: Bearer <token>`. `fetchWithCredentials` (`web/src/connect.ts:57`) sends `credentials: "include"` so the refresh cookie rides along.
- **Tokens it manages** — `web/src/auth-state.ts` keeps the short-lived access token in memory + `localStorage` (`memos_access_token` / `memos_token_expires_at`), with a `BroadcastChannel` ("memos_token_sync") so tabs share refreshes. Two refresh paths: proactive preflight when `isTokenExpired(REQUEST_TOKEN_EXPIRY_BUFFER_MS)` (`connect.ts:140`), and reactive retry on `Code.Unauthenticated` with an `X-Retry` header guard (`connect.ts:164-176`), falling back to `redirectOnAuthFailure()`. Refresh goes through `AuthService.RefreshToken` on a *separate* interceptor-free transport (`connect.ts:65-72`) to avoid recursion, deduped by `tokenRefreshManager`. The refresh token itself is never touched by JS — it's the cookie. PATs (`web/src/components/Settings/AccessTokenSection.tsx`) are the third kind, for programmatic clients.
- **Backend validation** — package **`server/auth`** (`server/auth/authenticator.go`, `token.go`, `extract.go`, `context.go`): `Authenticator.AuthenticateByAccessTokenV2` (stateless JWT parse, `authenticator.go:41`), `AuthenticateByRefreshToken` (DB revocation + expiry check, `:61`), `AuthenticateByPAT` (SHA‑256 hash lookup, `:102`), dispatched by `resolveBearer`/`Authenticate` (`:149`, `:213`). It's wired in via `Authorizer` in `server/router/api/v1/authz.go:34,44`, which the Connect interceptor (`server/router/api/v1/connect_interceptors.go`) and the SSE handler (`server/router/api/v1/sse_handler.go`) both use.
