**Engine + path:** Google CEL (`github.com/google/cel-go`), wrapped by the in-repo filter engine at `internal/filter/` — `engine.go` (Engine/Program/`DefaultEngine`), `schema.go` (CEL env + field metadata + `DialectName`), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL). Documented in `internal/filter/README.md`.

**Mechanism (one sentence):** `Engine.Compile` type-checks the filter string against a memo-specific CEL environment (`NewSchema()`, `internal/filter/schema.go:89` — declares `content`, `tag(s)`, `pinned`, `visibility`, `creator_id`, `created_ts`, `has_link`, `now`, …), `buildCondition` (`internal/filter/parser.go:18`) lowers the CEL AST into a dialect-agnostic IR of conditions, and `Program.Render` walks that IR through a per-dialect renderer (`internal/filter/render.go:32`) that emits the SQL fragment plus bound args, switching on `DialectSQLite`/`DialectMySQL`/`DialectPostgres` for JSON access (`JSON_EXTRACT` vs `->>`), boolean encoding (`addBoolArg`, SQLite 1/0), identifier quoting (`qualifyColumn`, backticks vs bare), `LIKE` vs `ILIKE`/regex (`~*` vs `REGEXP`), and placeholders (`$N` vs `?`, `addArg` at `render.go:842`).

**Wiring:** the RPC validates the filter via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`) and stashes it in `memoFind.Filters` (`server/router/api/v1/memo_service.go:211-216`); each store driver then calls `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` (`internal/filter/helpers.go:9`), which wraps each rendered fragment in parens and appends it to the `WHERE` clause — see `store/db/sqlite/memo.go:57-63`, `store/db/mysql/memo.go:65-71`, `store/db/postgres/memo.go:54-60` (the Postgres call passes `PlaceholderOffset: len(*args)` so `$N` numbering stays consistent).
