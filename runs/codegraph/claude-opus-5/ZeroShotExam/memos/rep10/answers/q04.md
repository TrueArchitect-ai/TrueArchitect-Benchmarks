**`APIV1Service.SignIn` — `server/router/api/v1/auth_service.go:51`**

That's the actual business logic: it handles both password credentials (bcrypt compare, `DisallowPasswordAuth` check) and SSO credentials (`resolveSSOIdentity` → `resolveSSOUser`), then calls `doSignIn` to mint the access token.

The Connect/gRPC transport entry point is a thin wrapper: `ConnectServiceHandler.SignIn` at `server/router/api/v1/connect_services.go:78`, which wraps the call in `connectWithHeaderCarrier` so the service can set the refresh-token cookie header, then delegates to `APIV1Service.SignIn`.
