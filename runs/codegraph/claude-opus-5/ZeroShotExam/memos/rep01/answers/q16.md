The store-layer `Store.DeleteMemo` (`store/memo.go:140-159`) removes two kinds of records before issuing the memo-row `DELETE`:

1. **`memo_relation` rows** — deleted twice, once where the memo is the source (`MemoID`) and once where it is the target (`RelatedMemoID`) — `store/memo.go:142-147`
2. **`attachment` rows** — every attachment linked to the memo is listed via `ListAttachments{MemoID: ...}` and deleted one by one with `Store.DeleteAttachment` (which also cleans up the backing local file/thumbnail cache) — `store/memo.go:149-157`, `store/attachment.go`

Only then does it call `s.driver.DeleteMemo` to delete the memo row itself (`store/memo.go:158`; driver impls at `store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`).

Not done by the store layer: reactions and child comment memos. Comments are deleted by the API service before it calls `Store.DeleteMemo` for the parent (`server/router/api/v1/memo_service.go:567-582`); reactions are only listed there for the webhook payload, not deleted.
