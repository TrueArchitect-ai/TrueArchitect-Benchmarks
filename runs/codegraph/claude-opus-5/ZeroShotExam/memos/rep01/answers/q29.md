**`web/src/connect.ts` (`authInterceptor`, line 156); JWT access token (in-memory + localStorage, `memos_access_token`) + HttpOnly refresh-token cookie (`memos_refresh`), plus PATs (`memos_pat_…`) as an alternative Bearer credential; `server/auth/`**

**How it works**

- `web/src/connect.ts:184-189` builds a single `createConnectTransport` (Connect-RPC over `window.location.origin`, `credentials: "include"`) with `authInterceptor` installed; every service client (`memoServiceClient`, `userServiceClient`, …) is created from that transport, so all frontend RPCs go through it.
- `authInterceptor` (`web/src/connect.ts:156-178`):
  1. `getRequestToken()` returns the current access token, preflight-refreshing when it's within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry (`web/src/connect.ts:124-150`).
  2. Sets `Authorization: Bearer <token>` (`web/src/connect.ts:97-100`).
  3. On a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry: true` header guard, and on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- Refresh uses a **separate transport with no interceptors** to avoid recursion (`web/src/connect.ts:65-83`), calling `AuthService.RefreshToken` — the refresh token itself is never touched by JS; it rides along as an HttpOnly cookie thanks to `credentials: "include"`. Concurrent refreshes are deduped by `tokenRefreshManager` (`web/src/connect.ts:30-91`).
- Token storage: `web/src/auth-state.ts` — access token + expiry in memory and `localStorage` (`memos_access_token` / `memos_token_expires_at`), synced across tabs via a `BroadcastChannel` named `memos_token_sync`.

**Backend validation** — `server/auth/`:
- `Authenticator.Authenticate` (`server/auth/authenticator.go:213`) extracts the Bearer token and dispatches in `resolveBearer` (`:149`): tokens with the `memos_pat_` prefix go to `AuthenticateByPAT` (SHA-256 hash lookup, `:102`), everything else to `AuthenticateByAccessTokenV2` (stateless JWT parse, `:41`).
- `AuthenticateByRefreshToken` (`:61`) validates the cookie token against the DB for revocation/expiry; cookie name `memos_refresh` and PAT prefix are defined in `server/auth/token.go:49-52`.
- It's wired into the request path by `Authorizer` in `server/router/api/v1/authz.go:44` (`Authenticate` + `CheckAccess`), shared by the Connect interceptor (`server/router/api/v1/connect_interceptors.go`) and the file server.
