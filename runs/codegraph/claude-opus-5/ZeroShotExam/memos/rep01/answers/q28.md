**Runners the server actually starts**

- **s3presign runner** — `server/server.go:153-174` (`startBackgroundRunners`, called from `Start` at `server/server.go:129`). Runs once synchronously at boot (`s3presignRunner.RunOnce(ctx)`, line 163), then a goroutine runs `Run` which is driven by a plain `time.NewTicker(runnerInterval)` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27-41`). Shutdown via its own cancelable context stored in `backgroundRunnerCancels` + WaitGroup (`server/server.go:176-201`).
- **HTTP serve goroutine** — `server/server.go:124-128`; event-driven (accepts connections), stopped by `http.Server.Shutdown`.
- **Store cache cleanup loops (×3)** — started implicitly by `cache.New` (`store/cache/cache.go:76-85`, `go c.cleanupLoop()`) for `instanceSettingCache`, `userCache`, `userSettingCache` in `store.New` (`store/store.go:40-53`); driven by `time.NewTicker(CleanupInterval)` = 5 minutes (`store/cache/cache.go:201`, config at `store/store.go:41-43`).
- **Webhook dispatch worker pool (4 goroutines)** — `internal/webhook/webhook.go:42-54`, started in `init()` when the package is linked in (imported by `server/router/api/v1/memo_service_webhooks.go`, `user_service_webhooks.go`); driven by messages on the `asyncPostQueue` channel, not by a timer.
- **Email send worker pool (2 goroutines)** — `internal/email/email.go:15-28`, also `init()`-started; driven by the `asyncEmailQueue` channel (fed via `server/notification/email.go`).
- **Signal-handler goroutine** — `cmd/memos/main.go:99-103`; triggered by SIGINT/SIGTERM, calls `s.Shutdown`.

Request-scoped, not startup workers: the SSE heartbeat `time.NewTicker(sseHeartbeatInterval)` lives per connection in `server/router/api/v1/sse_handler.go:64`, and PAT last-used updates are one-shot goroutines per request (`server/auth/authenticator.go:180`).

**Unused scheduling infrastructure**

- **`internal/scheduler` is entirely unused by the server.** It's a full cron implementation — cron-expression parser (`internal/scheduler/parser.go`), `Job`/`Schedule` types (`internal/scheduler/job.go`), timezone support, middleware, graceful shutdown (`internal/scheduler/scheduler.go`, documented in `internal/scheduler/doc.go`) — but the only imports of `github.com/usememos/memos/internal/scheduler` anywhere in the repo are its own `integration_test.go` and `example_test.go`. No production code registers a job with it. The one real periodic runner (s3presign) uses a hand-rolled `time.Ticker` instead.
- **`server/runner/memopayload`'s `Runner` is never instantiated.** `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19-27`) have no callers; `startBackgroundRunners` does not create it. Only the free function `memopayload.RebuildMemoPayload` is used, inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447`.
