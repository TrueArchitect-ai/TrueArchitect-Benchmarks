**Memo lifecycle events that dispatch webhooks** — all defined in `server/router/api/v1/memo_service_webhooks.go`:

```
memos.memo.created:         (*APIV1Service).DispatchMemoCreatedWebhook          (memo_service_webhooks.go:15)

memos.memo.comment.created: (*APIV1Service).DispatchMemoCommentCreatedWebhook   (memo_service_webhooks.go:30)
```

**Convergence for delivery**

The first three are thin wrappers over the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks via `Store.GetUserWebhooks`, builds a payload with `convertMemoToWebhookPayload`, and calls `webhook.PostAsync`. `DispatchMemoCommentCreatedWebhook` bypasses that helper (it targets the *related* memo's owner, not the comment's creator) but ends at the same `webhook.PostAsync` call.

So all four converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the buffered `asyncPostQueue` (cap 128, dropping with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`) drain that queue and perform the actual HTTP delivery in `webhook.Post` (`internal/webhook/webhook.go:120`) — JSON marshal, optional HMAC-SHA256 Standard-Webhooks signing headers, POST via the SSRF-guarded `safeClient`.
