**`web/src/connect.ts`; JWT access token (in-memory + localStorage, sent as `Authorization: Bearer`) + HttpOnly refresh-token cookie (`memos_refresh`), with PATs (`memos_pat_`) as the same-header alternative for programmatic clients; `server/auth`**

How it fits together:

**Frontend interceptor — `web/src/connect.ts:156`**
- `authInterceptor` is registered on the single Connect-Web transport (`web/src/connect.ts:184-189`), so every generated service client (`memoServiceClient`, `userServiceClient`, …) goes through it.
- Per request it calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, line 97).
- Proactive refresh: if the cached token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry it refreshes first — needed so public endpoints like `ListMemos` don't silently return guest-scoped data.
- Reactive refresh: on `Code.Unauthenticated` it refreshes once, replays the request with an `X-Retry: true` marker to prevent loops, and on failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- Refresh itself runs on a *separate* transport with no interceptors (`web/src/connect.ts:65-72`) to avoid recursion, calls `AuthService.RefreshToken`, and is deduplicated across concurrent callers by `tokenRefreshManager` (line 30).
- `fetch` is wrapped with `credentials: "include"` (line 57) so the HttpOnly refresh cookie rides along.

**Token storage — `web/src/auth-state.ts`**
- Access token + expiry in module state, mirrored to `localStorage` under `memos_access_token` / `memos_token_expires_at`, with a `BroadcastChannel` (`memos_token_sync`) so tabs adopt a sibling tab's refreshed token instead of racing their own refresh.

**Backend validation — `server/auth/`**
- `server/auth/token.go` defines the token kinds: access tokens (15 min, audience `user.access-token`), refresh tokens (30 days, cookie `memos_refresh`), and PATs (prefix `memos_pat_`).
- `server/auth/authenticator.go` validates them: `AuthenticateByAccessTokenV2` (stateless JWT signature check), `AuthenticateByRefreshToken` (DB-backed revocation/expiry check), `AuthenticateByPAT` (hash lookup via `GetUserByPATHash`).
- The wiring is `server/router/api/v1/connect_interceptors.go:217` (`AuthInterceptor.WrapUnary` reads the `Authorization` header) → `server/router/api/v1/authz.go:44` (`Authorizer.Authenticate`, which owns an `auth.Authenticator`) → `CheckAccess` for the anonymous/public-method policy. The same `server/auth` package also backs the gRPC-Gateway middleware, the SSE handler, and `server/router/fileserver`.
