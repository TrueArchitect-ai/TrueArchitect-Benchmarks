`Store.DeleteMemo` (`store/memo.go:140-159`) removes two kinds of records before issuing the memo `DELETE`:

1. **Memo relation records** — `memo_relation` rows where the memo is the **source** (`MemoID`), then rows where it is the **target** (`RelatedMemoID`) (`store/memo.go:141-147`).
2. **Attachment records** — every attachment linked to the memo is listed via `ListAttachments(FindAttachment{MemoID})` and deleted one by one with `DeleteAttachment` (`store/memo.go:148-157`). `Store.DeleteAttachment` also removes the attachment's backing blob/file from storage before deleting the row (`store/attachment.go:131-148`).

Only then does it call `s.driver.DeleteMemo`, which is the plain `DELETE FROM memo WHERE id = ?` (e.g. `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`, `store/db/sqlite/memo.go:237`).

Note on scope: reactions are **not** deleted by the store layer — the API handler only *lists* them for the webhook payload (`server/router/api/v1/memo_service.go:545-550`). Comment memos are deleted by the API handler before the parent, not by the store (`server/router/api/v1/memo_service.go:567-577`), and each of those recurses through the same store-level relation/attachment cleanup.
