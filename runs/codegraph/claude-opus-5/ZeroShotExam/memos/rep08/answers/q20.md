**Server-Sent Events (SSE) over HTTP `text/event-stream`; `server/router/api/v1/sse_hub.go`; CreateMemo, UpdateMemo, DeleteMemo, CreateMemoComment, UpsertMemoReaction, DeleteMemoReaction (plus SetMemoRelations and SetMemoAttachments, which emit `memo.updated` via the shared `dispatchMemoUpdatedSideEffects` helper).**

### Mechanism
SSE, not WebSockets. The endpoint is `GET /api/v1/sse`, implemented in `server/router/api/v1/sse_handler.go:34` (`handleSSE`) — sets `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`, sends `: connected`, then writes `data: %s\n\n` frames plus a 30s `: heartbeat` comment. Auth is a Bearer token checked before subscribing (`sse_handler.go:36-44`). Routes are registered at `server/router/api/v1/v1.go:125`.

The browser side is `web/src/hooks/useLiveMemoRefresh.ts`, which uses `fetch` + a stream reader (not `EventSource`, so it can send the `Authorization` header), with exponential-backoff reconnect and React Query cache invalidation per event type.

### Hub
`server/router/api/v1/sse_hub.go` — `SSEHub` (line 56) holds a `map[*SSEClient]struct{}` guarded by an `RWMutex`, with `Subscribe`/`Unsubscribe`/`Close`/`Broadcast`. Each client gets a 32-buffered channel; `Broadcast` (line 115) drops events for slow clients rather than blocking, and filters per-client via `canReceive` (line 134) so `Private` memos only reach the creator or an admin. Constructed once in `v1.go:57` and held by `APIV1Service.SSEHub` (`v1.go:36`); `server/server.go:77` keeps a reference to close connections at shutdown.
