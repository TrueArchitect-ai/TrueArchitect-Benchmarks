**Runners/workers the server actually starts**

- **s3presign runner — startup one-shot + 12h `time.Ticker`** — `server/server.go:153-174` (`startBackgroundRunners`) calls `s3presign.NewRunner(s.Store)`, runs `RunOnce(ctx)` synchronously at boot, then launches `Run(s3Context)` in a goroutine tracked by `backgroundRunnerWG`; the loop is a `time.NewTicker(runnerInterval)` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27-41`). It is the *only* thing `startBackgroundRunners` starts, cancelled via the stored `context.CancelFunc` on `Shutdown` (`server/server.go:140,176-182`).
- **HTTP server goroutine — one-shot, lives for process lifetime** — `go s.httpServer.Serve(listener)` in `Server.Start` (`server/server.go:124-128`).
- **Store cache cleanup loops (×3) — 5-minute `time.Ticker`** — `cache.New` starts `go c.cleanupLoop()` (`store/cache/cache.go:76-86,199-212`); `store.New` creates three caches (instance settings, users, user settings) with `CleanupInterval: 5 * time.Minute` (`store/store.go:38-53`), stopped by `Store.Close()` (`store/store.go:72-79`).
- **Webhook dispatch pool (4 workers) — queue-driven, no timer** — package `init()` spawns 4 goroutines draining `asyncPostQueue` (buffered 128) (`internal/webhook/webhook.go:38-55`). Started by package init, not by the server explicitly.
- **Email dispatch pool (2 workers) — queue-driven, no timer** — package `init()` spawns 2 goroutines draining `asyncEmailQueue` (buffered 128) (`internal/email/email.go:14-35`). Also init-time, not server-driven.
- **Signal-shutdown goroutine — waits on the OS signal channel** — `cmd/memos/main.go:99-103`.
- **Per-connection SSE heartbeat — 
`time.Ticker` per client request** — `server/router/api/v1/sse_handler.go:64`; request-scoped, not a background worker.

**Unused scheduling infrastructure**

- `internal/scheduler` — a full cron scheduler (5/6-field cron parsing `internal/scheduler/parser.go`, job registry/runner `internal/scheduler/scheduler.go`, `internal/scheduler/job.go`, middleware `internal/scheduler/middleware.go`, docs `internal/scheduler/doc.go`) — is **never used by the server**. Grepping for its import path outside the package yields only `internal/scheduler/integration_test.go` and `internal/scheduler/example_test.go`. Nothing in `server/` calls `scheduler.New`/`Register`/`Start`; the one real periodic job (s3presign) uses a hand-rolled ticker instead.
- Secondary: `server/runner/memopayload` has a `Runner` type with `NewRunner`/`RunOnce` (batch rebuild of all memo payloads, `server/runner/memopayload/runner.go:14-27`) that is **never instantiated or scheduled** — `startBackgroundRunners` doesn't touch it. Only the free function `memopayload.RebuildMemoPayload` is used, inline on the request path (`server/router/api/v1/memo_service.go:108,447`).
