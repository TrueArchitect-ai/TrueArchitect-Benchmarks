**Engine:** Google CEL (`github.com/google/cel-go`), wrapped by the in-repo package `internal/filter/` — `engine.go` (CEL env + `Compile`/`CompileToStatement`), `schema.go` (CEL variable declarations + per-dialect column metadata), `parser.go` (CEL AST → condition IR), `ir.go` (IR node types), `render.go` (IR → dialect SQL), `helpers.go` (`AppendConditions`).

**Mechanism (one sentence):** `Engine.Compile` type-checks the filter string against a schema-derived CEL environment and lowers the resulting CEL AST into a dialect-agnostic condition tree (`buildCondition` in `internal/filter/parser.go`), which `Program.Render` then walks with a dialect-parameterized renderer (`internal/filter/render.go`) to emit a parameterized SQL `WHERE` fragment plus args that each driver's `ListMemos` appends via `filter.AppendConditions`.

Details worth noting:

- **Entry point:** `server/router/api/v1/memo_service.go:211-215` validates `request.Filter` (`validateFilter`, defined at `server/router/api/v1/shortcut_service.go:336`, which compiles against the running driver's dialect) and appends it to `store.FindMemo.Filters`.
- **Per-dialect divergence** lives in two places, not in three separate parsers:
  - Schema-level SQL expression templates keyed by dialect, e.g. `creator` → `('users/' || %s)` for SQLite/Postgres vs `CONCAT('users/', %s)` for MySQL, and `created_ts` → `UNIX_TIMESTAMP(%s)` for MySQL vs `%s` for Postgres/SQLite (`internal/filter/schema.go:99-150`).
  - Renderer helpers: `qualifyColumn` (backticks for MySQL/SQLite, bare `table.col` for Postgres, `render.go:919`), `jsonExtractExpr` (`JSON_EXTRACT` vs Postgres JSON operators, `render.go:932`), and `addArg` (`$N` numbered placeholders for Postgres, `?` otherwise, `render.go:842`).
- **Wiring per driver:** `store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo.go:65-69`, `store/db/postgres/memo.go:54-58` each call `filter.DefaultEngine()` then `filter.AppendConditions(..., filter.Dialect<X>, &where, &args)`; `PlaceholderOffset: len(*args)` keeps Postgres `$N` numbering aligned with the surrounding query.
- Special results: a filter that folds to constant true renders empty SQL (skipped), constant false renders `1 = 0` (`render.go:42-58`).
