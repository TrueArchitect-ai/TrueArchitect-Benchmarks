The store-layer `Store.DeleteMemo` (`/bench/home/work/store/memo.go:140-159`) deletes, in this order, before calling `s.driver.DeleteMemo` on the memo row:

1. **Memo relations where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relations where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments{MemoID: ...}` and removed one by one with `Store.DeleteAttachment` (`store/memo.go:148-157`), which also deletes the underlying stored file/blob (`store/attachment.go:132-149`).

Related but outside `Store.DeleteMemo`: the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:566-577`) first recursively calls `Store.DeleteMemo` for each comment memo (relations of type `MemoRelationComment`) before deleting the memo itself. Reactions are only *read* there for the webhook payload — they are not explicitly deleted by the store layer.
