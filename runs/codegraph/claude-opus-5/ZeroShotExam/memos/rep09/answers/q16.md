`Store.DeleteMemo` (`store/memo.go:140-159`) performs this cleanup before issuing the `DELETE FROM memo` (driver-level, e.g. `store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`):

1. **Memo relation records where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relation records where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `FindAttachment{MemoID: &delete.ID}` and removed one by one with `Store.DeleteAttachment` (`store/memo.go:148-157`), which also deletes the backing file/thumbnail from storage (`store/attachment.go:131+`)

Notes on scope:
- Reactions are *not* removed by the store layer; the API handler only reads them to build the webhook payload (`server/router/api/v1/memo_service.go:545-565`).
- Child comment memos are deleted by the API handler before the parent, each through the same `Store.DeleteMemo` path (`server/router/api/v1/memo_service.go:567-577`).
