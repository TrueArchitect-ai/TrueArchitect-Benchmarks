— False premise: neither NATS nor RabbitMQ (nor any message broker) is used; there is no queue declaration.

Actual mechanism: an in-process Go channel. `asyncPostQueue` is a buffered channel of capacity 128 (`internal/webhook/webhook.go:39`), drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each calling `Post` (`:46`). Producers call `PostAsync` (`:184`), which does a non-blocking send and **drops** the webhook with a warning when the buffer is full (`:189-195`). Delivery is best-effort in-memory only — nothing is persisted, so queued webhooks are lost on restart.
