Premise is wrong: there is no Redis anywhere in the codebase (no `redis` import or dependency). Caching is an in-process, in-memory map with TTL: `store/cache/cache.go` (`Cache`, `Config`, `Set`/`SetWithTTL`, background cleanup). Configured in `store.New` — `store/store.go:40-53`: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, with three caches (`instanceSettingCache`, `userCache`, `userSettingCache`). User entries therefore live in `userCache` with the 10-minute default TTL (`store/user.go:88-167`), and are invalidated explicitly on delete (`store/user_delete.go:40`).
