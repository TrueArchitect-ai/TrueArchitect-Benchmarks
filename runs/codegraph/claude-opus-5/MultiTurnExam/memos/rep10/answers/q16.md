Inside `Store.DeleteMemo` (`store/memo.go:140-159`), before the memo row is deleted:

1. **memo_relation rows where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **memo_relation rows where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **attachment rows linked to the memo** — listed via `ListAttachments{MemoID}` and deleted one by one (`store/memo.go:149-157`); each `Store.DeleteAttachment` also removes the underlying stored blob/local file first (`store/attachment.go:132-148`)

Then `s.driver.DeleteMemo` removes the memo row (`store/memo.go:158`).

The API handler adds one step above the store: it first deletes each comment memo (relations of type `comment` pointing at this memo) via its own `Store.DeleteMemo` call, so those cascade the same way — `server/router/api/v1/memo_service.go:566-577`. Reactions are read there only to build the webhook payload; they aren't deleted in this path.
