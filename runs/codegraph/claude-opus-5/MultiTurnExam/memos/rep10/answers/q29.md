**Interceptor path:** `web/src/connect.ts` — `authInterceptor` (`web/src/connect.ts:156-178`), installed on the Connect transport (:184-189). Supporting token state is in `web/src/auth-state.ts`.

**Token kinds it manages:**
- **Short-lived access token (JWT, "Access Token V2")** — held in memory/storage by `auth-state.ts`, attached as `Authorization: Bearer <token>` on every request (`connect.ts:97-100,158-159`), with a preflight refresh when within the expiry buffer (`connect.ts:136-147`).
- **Refresh token (HTTP-only cookie)** — never read by JS; sent because the transport uses `credentials: "include"` (`connect.ts:57-62`). Used by `refreshAccessToken` → `AuthService.RefreshToken` over a separate interceptor-free transport to avoid recursion (`connect.ts:65-91`), deduplicated via a refresh manager (:30-51). On a `Code.Unauthenticated` response the interceptor refreshes once, retries with an `X-Retry` marker, and otherwise redirects to sign-in (`connect.ts:161-177`).
- Personal Access Tokens are supported by the backend for programmatic clients but are not issued or attached by this interceptor.

**Backend validation package:** `server/auth/` — `Authenticator.Authenticate` / `resolveBearer` dispatching to `AuthenticateByAccessTokenV2`, `AuthenticateByPAT`, and `AuthenticateByRefreshToken` (`server/auth/authenticator.go:41,61,102,149,213`), with token parsing/hashing in `server/auth/token.go` and header/cookie extraction in `server/auth/extract.go`. It is wired into the RPC path by `server/router/api/v1/authz.go:44` (used from `server/router/api/v1/connect_interceptors.go` and the gateway middleware in `server/router/api/v1/v1.go`).
