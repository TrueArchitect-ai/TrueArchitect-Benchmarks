**Interceptor path:** `web/src/connect.ts` — `authInterceptor` (line 156), installed on the shared Connect transport (line 188). Token state lives beside it in `web/src/auth-state.ts`.

**Token kinds:**
- **Short-lived JWT access token** — held in memory + `localStorage` (`memos_access_token`), sent as `Authorization: Bearer <token>` on every request. The interceptor refreshes it preflight when it's within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`) and reactively once on a `Code.Unauthenticated` response, retrying the call with an `X-Retry` marker to prevent loops; failure triggers `redirectOnAuthFailure`. Refreshes are deduplicated across concurrent calls by `tokenRefreshManager` and shared between tabs over a `BroadcastChannel`.
- **Refresh token** — an HTTP-only cookie (`memos_refresh`, `server/auth/token.go:49`), never read by JS; it rides along because the transport sets `credentials: "include"` (`fetchWithCredentials`, line 57). Refresh calls go through a separate interceptor-free client (line 72) to avoid recursion.
- **Personal Access Tokens** are also accepted by the server on the `Authorization` header, but they're for programmatic clients, not the web app.

**Backend package:** `server/auth` — `Authenticator` (`server/auth/authenticator.go`) validates all three: `AuthenticateByAccessTokenV2` (JWT via `ParseAccessTokenV2`, `token.go`), `AuthenticateByRefreshToken` (JWT + DB lookup for revocation/expiry), and `AuthenticateByPAT` (hash lookup, `GetUserByPATHash`); `extract.go` pulls the bearer/cookie values and `context.go` attaches the identity.

It's invoked from the API layer's authorizer (`server/router/api/v1/authz.go:44`), which both transports share: the Connect auth interceptor (`server/router/api/v1/connect_interceptors.go`) and the gRPC-Gateway middleware in `server/router/api/v1/v1.go:69-93`.
