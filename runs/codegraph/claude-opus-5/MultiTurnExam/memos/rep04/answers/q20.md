**Mechanism:** Server-Sent Events (SSE) — an in-process fan-out hub over a long-lived `text/event-stream` HTTP response at `GET /api/v1/sse`.

**Hub path:** `server/router/api/v1/sse_hub.go` — defines `SSEHub`, the `SSEEvent` payload, and the event types (`memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`). Supporting files: `server/router/api/v1/sse_handler.go` (the `RegisterSSERoutes`/streaming endpoint, with per-client visibility filtering and flushing) and `server/router/api/v1/sse_event_helpers.go` (event builders). The hub is constructed in `NewAPIV1Service` (`server/router/api/v1/v1.go:57`) and the route registered from `RegisterGateway` (`v1.go:125`).

**Handlers that broadcast:**
- `APIV1Service.CreateMemo` — `server/router/api/v1/memo_service.go:163` (`memo.created`)
- `APIV1Service.DeleteMemo` — `server/router/api/v1/memo_service.go:585` (`memo.deleted`)
- `APIV1Service.UpdateMemo` — via `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:71`), called from `memo_service.go:513`; the same helper is reused by `SetMemoRelations` (`memo_relation_service.go:48`) and `SetMemoAttachments` (`memo_attachment_service.go:48`) (`memo.updated`)
- `APIV1Service.CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:126` (`memo.comment.created`)
- `APIV1Service.UpsertMemoReaction` / `DeleteMemoReaction` — `server/router/api/v1/reaction_service.go:106` and `:161`

Note `CreateMemo` can be called with SSE suppressed (`withSuppressSSE`, `memo_service.go:30`) — that's how comment creation avoids emitting a duplicate `memo.created`. The browser side consumes the stream in `web/src/hooks/useLiveMemoRefresh.ts`.
