- **`memo`** — the row itself, plus any **comment memos** (memos related by `MemoRelationComment`), which the API handler deletes with their own `Store.DeleteMemo` calls (`server/router/api/v1/memo_service.go:566-577`); the actual `DELETE FROM memo` is in `store/db/sqlite/memo.go` (and the postgres/mysql equivalents)
- **`memo_relation`** — two explicit deletes, one for rows where the memo is the source (`memo_id`) and one where it's the target (`related_memo_id`) (`store/memo.go`, in `Store.DeleteMemo`)
- **`attachment`** — every attachment with `memo_id` = the memo is listed and deleted via `Store.DeleteAttachment` (`store/attachment.go`), which also removes the backing blob/local file from storage
- **`memo_share`** — not touched by Go code, but removed by a schema-level `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:110`, mirrored in the postgres/mysql schemas)

Not affected: **`reaction`** rows. The handler only *reads* them to build the webhook payload; reactions are keyed by `content_id` (the memo resource name) with no FK, so they are orphaned rather than deleted.
