**Engine:** Google CEL (`github.com/google/cel-go`), wrapped by the project's own filter package at **`internal/filter/`** — `engine.go` (CEL env + `Compile`/`CompileToStatement`, plus the cached `DefaultEngine()`), `parser.go` (CEL AST → dialect-agnostic IR), `ir.go` (the `Condition` tree), `schema.go` (allowed fields, their types/kinds, and the `DialectSQLite`/`DialectMySQL`/`DialectPostgres` constants), `render.go` (IR → SQL), and `helpers.go`.

**Mechanism:** each dialect's `ListMemos` grabs `filter.DefaultEngine()` and calls `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` (`store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`), which compiles the CEL string once into a shared condition tree and then renders it per-dialect into a parameterized `WHERE` fragment plus args — the renderer handles dialect differences like placeholder style (`?` vs `$N`, via `PlaceholderOffset`) and JSON field access, and collapses always-true/always-false filters to `""`/`1 = 0`.

The API side passes `request.Filter` through to `store.FindMemo.Filters` in `APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:178`); `internal/filter/README.md` and `MAINTENANCE.md` document the supported grammar and how to add fields.
