**Engine + path:** Google CEL (Common Expression Language) via `github.com/google/cel-go`, wrapped by the in-repo `internal/filter` package — `Engine`/`NewEngine`/`Compile` in `internal/filter/engine.go:14-116` (with the process-wide `DefaultEngine()` at line 111), the CEL environment and exposed field metadata in `internal/filter/schema.go`, AST→condition-tree conversion in `internal/filter/parser.go` and `internal/filter/ir.go`, and the SQL renderer in `internal/filter/render.go`. Docs: `internal/filter/README.md`, `internal/filter/MAINTENANCE.md`.

**Mechanism (one sentence):** the filter string is compiled by CEL into a dialect-agnostic condition tree (`Engine.Compile`), then `Engine.CompileToStatement` renders that tree per target dialect via `renderer` (`internal/filter/render.go`, which branches on `DialectSQLite`/`DialectMySQL`/`DialectPostgres` for things like JSON access, timestamp extraction, string length, and placeholder style), and `filter.AppendConditions` (`internal/filter/helpers.go:9`) appends the resulting SQL fragment plus bound args to the query's WHERE clause — called from each driver's `ListMemos`, e.g. `store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`.

The API side validates the expression before it reaches the store (e.g. `APIV1Service.validateFilter` in `server/router/api/v1/shortcut_service.go:341`), and `find.Filters` is carried through `store.FindMemo`.
