**Interceptor path:** `web/src/connect.ts` — `authInterceptor` (line 156) is installed on the Connect transport (line 184-189). It attaches `Authorization: Bearer <access token>` (`setAuthorizationHeader`, line 97), pre-emptively refreshes when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` of expiry (`getRequestToken`, line 124), and on a `Code.Unauthenticated` response refreshes once and replays the request with an `X-Retry` marker, redirecting to sign-in if that fails (lines 161-177). Token storage/expiry and cross-tab sync live in `web/src/auth-state.ts`; the refresh call itself uses a separate interceptor-free client (`refreshAuthClient`, line 72) to avoid recursion, plus `web/src/hooks/useTokenRefreshOnFocus.ts` for focus-time refresh.

**Token kinds:**
- Short-lived JWT **access token** — held in memory/localStorage, sent in the `Authorization` header.
- **Refresh token** — an HTTP-only cookie sent with `credentials: "include"` (`fetchWithCredentials`, `web/src/connect.ts:57`), exchanged via `AuthService.RefreshToken`; validated against the DB for revocation/expiry.
- **Personal Access Token (PAT)** — `memos_pat_…` prefixed, for programmatic clients rather than the web UI, also passed as a bearer token.
