**Interceptor path** — `web/src/connect.ts`: the Connect `authInterceptor` (`:156-178`) is attached to the shared transport (`:184-189`). Token state lives in `web/src/auth-state.ts` (`getAccessToken`, `setAccessToken`, `isTokenExpired`, `hasStoredToken`), with 401-redirect handling in `web/src/utils/auth-redirect.ts`.

**Token kinds it manages:**
- **Short-lived JWT access token** — read via `getRequestToken()` and sent as `Authorization: Bearer <token>` (`web/src/connect.ts:97-99, 158-159`); 15-minute lifetime (`server/auth/token.go:39-40`).
- **Refresh token** — an HTTP-only cookie (`memos_refresh`, `server/auth/token.go:48-49`), never touched by JS; the interceptor triggers `AuthService.RefreshToken` through a separate interceptor-free client (`refreshAuthClient`, `web/src/connect.ts:65-83`) both proactively (preflight when the access token is near expiry, `:140-147`) and reactively on a `Code.Unauthenticated` response, retrying once with an `X-Retry` marker (`:161-177`). Concurrent refreshes are deduplicated by `tokenRefreshManager` (`:30-51`).

The backend also accepts **personal access tokens** (`memos_pat_` prefix, `server/auth/token.go:51-52`) on the same `Authorization` header, though the web client doesn't issue them.

**Backend validation package** — `server/auth` (`server/auth/authenticator.go`: `Authenticate`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`; `server/auth/token.go`: JWT generation/parsing and PAT hashing; `server/auth/extract.go`, `context.go`). It's driven by the shared `Authorizer` in `server/router/api/v1/authz.go:26-68`, which both transports use — the Connect interceptor (`server/router/api/v1/connect_interceptors.go`) and the gRPC-Gateway middleware (`server/router/api/v1/v1.go`).
