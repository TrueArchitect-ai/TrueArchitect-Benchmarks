**Convergence points** — two stages:

1. The three memo-lifecycle dispatchers funnel into the private helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the creator, loads their hooks via `Store.GetUserWebhooks`, and stamps the activity type. `DispatchMemoCommentCreatedWebhook` bypasses this helper — it looks up the *parent* memo owner's hooks directly (`:31-44`) — but builds the same payload.
2. All four then call **`webhook.PostAsync`** (`internal/webhook/webhook.go:184`), which enqueues onto a 128-slot channel drained by four goroutines started in `init()` (`:42-54`); each delivers via **`webhook.Post`** (`internal/webhook/webhook.go:120`) — the single HTTP-delivery function, which signs the request with HMAC-SHA256 Standard Webhooks headers.
