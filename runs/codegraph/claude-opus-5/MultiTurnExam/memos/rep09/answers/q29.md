The flow the interceptor implements (`web/src/connect.ts`):

- Before each request, `getRequestToken` (`:124`) attaches the stored access token, proactively refreshing if it's within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`, `web/src/auth-state.ts:18`).
- On an `Unauthenticated` response it refreshes once, retries with an `X-Retry` marker to prevent loops, and on failure calls `redirectOnAuthFailure` (`:164-177`).
- Refresh itself goes through a **separate interceptor-free transport** and `refreshAuthClient` (`:65-72`) calling `AuthService.RefreshToken`, avoiding recursion; concurrent refreshes are deduplicated by `tokenRefreshManager` (`:30-51`).

Server-side, that header is checked in two places, both sharing one `Authorizer` (`server/router/api/v1/authz.go:44`): the Connect `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:213-231`) and the gRPC-Gateway middleware in `server/router/api/v1/v1.go:68-92`, which then apply the identity to the request context via `auth.ApplyToContext`.
