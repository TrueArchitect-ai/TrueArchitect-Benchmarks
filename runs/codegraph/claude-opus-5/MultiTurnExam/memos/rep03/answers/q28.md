**Runners the server actually starts** (`Server.startBackgroundRunners`, `server/server.go:153-174`):

```
s3presign.Runner — time.Ticker every 12h (runnerInterval, server/runner/s3presign/runner.go:26,29-39),
                   plus one immediate RunOnce at startup (server/server.go:164); re-presigns expiring
                   S3 attachment URLs. Cancelled via its own context on shutdown.
```

That is the only long-running background runner. Two other pieces of periodic/async work exist but aren't "runners" started at boot:

```
SSE heartbeat — per-connection time.Ticker inside handleSSE (server/router/api/v1/sse_handler.go:64),
                lives for the duration of each client's /api/v1/sse stream
webhook.PostAsync — fire-and-forget goroutine per webhook delivery (internal/webhook/webhook.go:184),
                event-triggered, not scheduled
```

**Unused infrastructure:**
- `internal/scheduler/` — a complete GitHub-Actions-style cron scheduler (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`, plus README/doc.go and tests) is **not referenced anywhere outside its own package and tests**; the server never constructs a `scheduler.New()`.
- `server/runner/memopayload` has a `Runner` with `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19,27`) that is **never started**; only its free function `RebuildMemoPayload` is used, called inline from the memo handlers (`server/router/api/v1/memo_service.go:108,447`).
