`Store.DeleteMemo` (`store/memo.go:140-159`) deletes, in order, before the memo row:

1. **memo_relation rows where this memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **memo_relation rows where this memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **attachments linked to the memo** — listed via `ListAttachments{MemoID}` then deleted one by one (`store/memo.go:149-157`); `Store.DeleteAttachment` also removes the backing local/S3 file.

Then `driver.DeleteMemo` removes the memo row itself (`store/memo.go:158`).

Additionally, the API handler `APIV1Service.DeleteMemo` first deletes **comment memos** — every memo related to this one with type `MemoRelationComment` — by calling `Store.DeleteMemo` on each (`server/router/api/v1/memo_service.go:566-576`), so each comment goes through the same relation/attachment cleanup. Reactions are read for the webhook payload (`memo_service.go:545`) but are not explicitly deleted in this path.
