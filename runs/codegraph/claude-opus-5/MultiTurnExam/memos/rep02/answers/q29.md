**Interceptor path:** `web/src/connect.ts` — `authInterceptor` (:156), installed on the shared Connect transport (:184-189). Supporting state lives in `web/src/auth-state.ts`; the redirect-on-failure helper in `web/src/utils/auth-redirect.ts`.

**Token kinds it manages:**
- **Access token (JWT, "Access Token V2")** — held in memory + `localStorage` (`memos_access_token`), attached as `Authorization: Bearer <token>`. The interceptor refreshes it preemptively when within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), and reactively once on a `Code.Unauthenticated` response (marked with an `X-Retry` header to prevent loops). Concurrent refreshes are deduped by `tokenRefreshManager` (`connect.ts:30`) and shared across tabs via a `BroadcastChannel` (`auth-state.ts`).
- **Refresh token** — an HttpOnly cookie (`memos_refresh`, `server/auth/token.go:49`), never read by JS; sent because the transport uses `credentials: "include"` (`connect.ts:57-62`). It's exchanged via `AuthService.RefreshToken` on a *separate*, interceptor-free transport (`connect.ts:65-72`) to avoid recursion.
- The backend additionally accepts **Personal Access Tokens** on the same `Authorization: Bearer` header for programmatic clients, though the web app itself doesn't issue them.

**Backend validation package:** `server/auth/` — `Authenticator` in `server/auth/authenticator.go` (`AuthenticateByAccessTokenV2` :41, `AuthenticateByRefreshToken` :61, `AuthenticateByPAT` :102, `resolveBearer` :149, `Authenticate` :213), with JWT parsing/constants in `token.go` and header/cookie extraction in `extract.go`. It's invoked per-request by the Connect `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:213-231`) and by the gRPC-Gateway middleware, both routed through the `Authorizer`/`Authenticate` + `CheckAccess` pair in `server/router/api/v1/authz.go:44`.
