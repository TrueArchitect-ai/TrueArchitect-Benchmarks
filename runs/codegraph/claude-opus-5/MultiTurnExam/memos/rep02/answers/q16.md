`Store.DeleteMemo` (`store/memo.go`) does this cleanup before issuing the memo row delete via `s.driver.DeleteMemo`:

1. **`memo_relation` rows where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}`
2. **`memo_relation` rows where the memo is the target** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}`
3. **`attachment` rows linked to the memo** — listed via `ListAttachments{MemoID}` and deleted one at a time through `Store.DeleteAttachment`, which also **removes the backing file/object from storage** (local file or S3) before the DB row (`store/attachment.go`).

Additionally, at the API layer `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) first deletes **comment memos** — each memo related to this one with type `MemoRelationComment` gets its own `Store.DeleteMemo` call (which repeats steps 1–3 for that comment) — then deletes the target memo. Reactions are listed there only to build the webhook payload; they are not explicitly deleted by the store path.
