**Engine: Google CEL (`github.com/google/cel-go`) wrapped by the in-repo `filter` package — internal/filter/ (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`)**

**Mechanism:** `filter.Engine.Compile` compiles the CEL expression against a field schema into a dialect-agnostic condition tree (`internal/filter/engine.go:14-60`, IR in `ir.go`), and `CompileToStatement`/`renderer.Render` then emit dialect-specific SQL fragments plus bound args by switching on `RenderOptions.Dialect` (`DialectSQLite` / `DialectMySQL` / `DialectPostgres`, `internal/filter/schema.go:11-17`; per-dialect JSON/timestamp/string handling throughout `internal/filter/render.go`, e.g. lines 231-237, 365-402, 452-464) — so each driver calls the same engine with its own dialect constant, e.g. `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args)` in `store/db/sqlite/memo.go:57-61`, with the postgres/mysql equivalents in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`, and the resulting predicates appended to the `ListMemos` WHERE clause.

The API-layer entry is `APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:178`), which passes `request.Filter` into `store.FindMemo.Filters`; shortcut filters are validated the same way at `server/router/api/v1/shortcut_service.go:356`.
