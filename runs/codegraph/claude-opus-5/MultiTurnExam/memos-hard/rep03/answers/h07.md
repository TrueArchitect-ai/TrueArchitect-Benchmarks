The browser hits `/file/users/{username}/avatar` — the URL the API itself hands out, since `convertUserToProto` rewrites a base64 `AvatarURL` into `/file/{user.Name}/avatar` (`server/router/api/v1/user_service_converters.go:32-38`). Avatars are stored as data-URI strings in the `user.avatar_url` column, not as blobs or files.

Hops:

- `NewFileServerService(...).RegisterRoutes` registers the route `GET /file/users/:identifier/avatar` — `server/router/fileserver/fileserver.go:124` (wired at server startup, `server/server.go:81-82`)
- `FileServerService.serveUserAvatar` (handler) — `server/router/fileserver/fileserver.go:168`
- `FileServerService.getCurrentUser` (only when `!s.Profile.AllowAnonymous()`; 401 for anonymous viewers on a private instance) — `server/router/fileserver/fileserver.go:174`
- `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715`
- `store.Store.GetUser` (checks `userCache` only for ID lookups; this is a username lookup, so it falls through) — `store/user.go:148`
- `store.Store.ListUsers` (populates `userCache` from the result) — `store/user.go:136`
- `store.Driver.ListUsers` (interface) — `store/driver.go:47`
- `sqlite.DB.ListUsers` / `postgres.DB.ListUsers` / `mysql.DB.ListUsers` — `store/db/sqlite/user.go:88`, `store/db/postgres/user.go`, `store/db/mysql/user.go` (SELECT includes `avatar_url`, scanned into `user.AvatarURL` at `store/db/sqlite/user.go:159,189`)

Back out, in the handler: `parseDataURI` decodes the `data:<mime>;base64,...` string (`server/router/fileserver/fileserver.go:737`), the MIME type is checked against `avatarAllowedTypes` (`fileserver.go:75`, `201`), `setSecurityHeaders` plus `Cache-Control` are set (`fileserver.go:205-207`), and the bytes go out via `c.Blob` (`fileserver.go:209`).

One note on the question's framing: this path does not check *whose* profile is requested — any user's avatar is served to any authenticated viewer (or to anyone at all when `AllowAnonymous()` is true). The only gate is the instance-level anonymous check at `fileserver.go:173`.
