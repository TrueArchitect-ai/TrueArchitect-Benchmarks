**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard at dial time via `safeDialContext`/`isReservedIP` on the shared `safeClient` transport — `internal/webhook/webhook.go:59` + `internal/webhook/validate.go:44`**

How it fits together:

- **Trigger**: `dispatchMemoRelatedWebhook` / `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48,30`) build a payload per user webhook and call `webhook.PostAsync` (`memo_service_webhooks.go:43,71`).
- **Queueing**: `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel (`webhook.go:39`), dropping with a warning if full. The actual HTTP request is made by 4 worker goroutines started in `init()` (`webhook.go:42-55`), each calling `Post`.
- **Delivery**: `Post` (`internal/webhook/webhook.go:120`) marshals the payload, optionally adds Standard-Webhooks HMAC headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, `webhook.go:133-150`), and issues `safeClient.Do(req)` at `internal/webhook/webhook.go:152` with a 30s timeout and a 1 MiB response read cap.
- **Protection**: `safeClient`'s transport uses `safeDialContext` (`internal/webhook/webhook.go:32-37,59-77`), which resolves the host at dial time and refuses the connection if *any* resolved address is reserved/private — this is what defeats DNS rebinding, since the check happens on the address actually being dialed rather than at config time. The range list is `reservedCIDRs` in `internal/webhook/validate.go:14-23` (loopback, RFC-1918, link-local incl. 169.254.169.254 IMDS, and IPv6 equivalents), parsed once in `init()` and tested by `isReservedIP` (`validate.go:44`).
- **Second layer (config time)**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-IP hostnames when a webhook is created or its URL updated (`server/router/api/v1/user_service_webhooks.go:74,161,182`).
- **Escape hatch**: the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) disables both checks. Note it is never assigned anywhere in non-test code — I grepped the whole repo and the only non-test hits are its declaration and use — so it is effectively always `false` at runtime today; there's no env var or profile flag wired to it.
