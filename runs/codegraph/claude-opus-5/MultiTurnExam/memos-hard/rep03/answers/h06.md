**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` (all on `APIV1Service`); convergence: `webhook.Post` — `internal/webhook/webhook.go:120` (all handler paths funnel into `webhook.PostAsync`, `internal/webhook/webhook.go:184`, which is the single enqueue point; `Post` is the one function that actually issues the request)**

The paths, all ending at a user-configured webhook URL (`hook.Url`, created/updated via `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`):

|---|---|---|
| `CreateMemo` (`server/router/api/v1/memo_service.go:157`) | `DispatchMemoCreatedWebhook` | `memos.memo.created` |
| `UpdateMemo` (`server/router/api/v1/memo_service.go:513`) | `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` | `memos.memo.updated` |

Convergence chain:

1. The three "updated" handlers share the helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66-67`), which calls `DispatchMemoUpdatedWebhook`.
2. `DispatchMemoCreatedWebhook` / `DispatchMemoUpdatedWebhook` / `DispatchMemoDeletedWebhook` are thin wrappers over `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15-27,48`), which loads the creator's webhooks and calls `webhook.PostAsync` at `memo_service_webhooks.go:71`. `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`) skips that helper — it targets the *parent memo owner's* webhooks — but calls the same `webhook.PostAsync` at `memo_service_webhooks.go:43`.
3. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a 128-slot channel; the four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) call **`webhook.Post`** (`internal/webhook/webhook.go:120`), which is where the HTTP POST is issued via `safeClient.Do` (`internal/webhook/webhook.go:152`).

So `PostAsync` is the last function on the handler goroutine and `Post` is the sole delivery function — every one of these RPCs reaches the network only through it. (Because delivery is async, a webhook fires even if the handler later returns an error; dispatch failures are only logged, e.g. `memo_service.go:158`.)
