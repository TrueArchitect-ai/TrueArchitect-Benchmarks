**Explicit Go code — two `DELETE FROM reaction` statements inside each driver's `DeleteUser` transaction. There is no database-level cascade for reactions.**

What I checked:

**1. The Go delete path.** `store.Store.DeleteUser` delegates to the driver's `DeleteUser`, which runs everything in one transaction. In each driver, `deleteUserTargetsTx` calls two reaction cleanups:

- `deleteReactionsByContentIDsTx` — removes reactions *on* the deleted user's memos, keyed by `content_id` of the form `"memos/"+uid` (built by `memoContentIDsFromRefs`): `store/db/sqlite/user_delete.go:379-387`, `store/db/postgres/user_delete.go:380-388`, `store/db/mysql/user_delete.go:417-425`.
- `deleteReactionsByCreatorTx` — removes reactions *made by* the user: `DELETE FROM reaction WHERE creator_id = ?` at `store/db/sqlite/user_delete.go:398-401`, `store/db/postgres/user_delete.go:400-402`, `store/db/mysql/user_delete.go:437-439`.

Both are invoked from `deleteUserTargetsTx` (sqlite `store/db/sqlite/user_delete.go:88-120`; postgres `store/db/postgres/user_delete.go:96,102`; mysql `store/db/mysql/user_delete.go:96,102`) — reactions-by-content first, reactions-by-creator third, before memos and the user row are deleted. All three drivers implement it identically.

**2. The schema, to rule out a DB rule.** The `reaction` table has no foreign key at all — `creator_id` and `content_id` are plain columns with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint: `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-97`, `store/migration/mysql/LATEST.sql:91-98`. Grepping `REFERENCES|ON DELETE` across all three `LATEST.sql` files returns exactly one hit each — `memo_share.memo_id → memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`) — so reactions are not covered by any cascade. The `0.23/00__reactions.sql` migrations are only emoji-value rewrites, not constraints.

Note the by-content deletion is string-keyed on memo UID rather than an FK, which is why the Go code has to collect the full memo tree (including other users' comments on those memos, via `listDeleteUserMemoTreeRecursive`) before deleting.
