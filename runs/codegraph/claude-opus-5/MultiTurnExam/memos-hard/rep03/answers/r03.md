**Premise correction: there is no nightly database-cleanup job — and, more fundamentally, the cron scheduler is never used by the server at all. So there is no scheduled time to report.**

Two separate corrections:

1. **No cleanup job exists.** There is no scheduled task that vacuums, prunes, purges, or otherwise cleans the database on any interval. Searching for `cleanup|vacuum|prune|purge` in `server/`, `store/`, `cmd/`, and `internal/` turns up only inline, request-scoped work: attachment blob cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`), relation/attachment cleanup inside `DeleteMemo` (`server/router/api/v1/memo_service.go:579`, `store/memo.go:140-158`), and a best-effort rollback of a provisional SSO user (`server/router/api/v1/auth_service_sso.go:76`). The only recurring "Cleanup" in the codebase is the in-memory cache sweeper (`CleanupInterval: 5 * time.Minute`, `store/store.go:41`), which touches no database.

2. **The `internal/scheduler` package is dead code.** It is a complete, working cron implementation — `Scheduler` with `Register`/`Start`/`Stop` (`internal/scheduler/scheduler.go:12,70,91,169`), 5-field cron parsing via `ParseCronExpression` (`internal/scheduler/parser.go`), `Job` definitions (`internal/scheduler/job.go:14`), and Recovery/Logging/Timeout middleware — but nothing outside the package imports it. `grep -rln "internal/scheduler"` matches only `internal/scheduler/integration_test.go` and `internal/scheduler/example_test.go`. No `scheduler.New(...)` or `Register(&scheduler.Job{...})` call exists in `cmd/` or `server/`, so no job of any kind is registered and `Start()` is never called in production.

The cron strings you may have seen — e.g. `"0 9 * * *" // 9 AM` at `internal/scheduler/integration_test.go:183` — are test fixtures, not application configuration.

What the server *does* run in the background is one hardcoded ticker, not a cron job: the S3 presign refresher, every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27`), started at `server/server.go:162-171`. That is the only recurring background work in the process.
