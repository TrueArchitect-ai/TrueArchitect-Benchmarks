**Premise correction: there is no per-user API rate-limiting middleware in this codebase. No such middleware is registered anywhere, and no request-per-interval limits exist — so there is no registration site or limit values to report.**

What I checked:

- `grep -rniE "ratelimit|rate_limit|rate limit|throttl|limiter|golang.org/x/time/rate"` across all Go files returns exactly one hit, and it's a comment in documentation prose: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse" — a suggestion, not an implementation).
- `go.mod` contains no rate-limiting dependency (`golang.org/x/time`, `ulule/limiter`, `didip/tollbooth`, etc.).
- The full Echo middleware chain is two entries, neither of which limits rates: `middleware.Recover()` and `newCORSMiddleware(profile)` at `server/server.go:51-52`.
- The full Connect interceptor chain is four entries — `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` — registered at `server/router/api/v1/v1.go:133-138` (definitions in `server/router/api/v1/connect_interceptors.go`). Again, none is a limiter.

What *does* exist, in case one of these is what you were thinking of — these are size and concurrency caps, not per-user request rates:

- **Request body size cap**: `maxAPIRequestBytes = 256 << 20` (256 MiB), `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` to the gateway and Connect routes (`v1.go:126,144`) and via `connect.WithReadMaxBytes` (`v1.go:141`).
- **Concurrency semaphores** (process-wide, not per user): thumbnail generation limited to 3 and image processing to 2 in `server/router/api/v1/v1.go:59-60`; `maxConcurrentThumbnails = 3` in the file server, `server/router/fileserver/fileserver.go:46,116`.
- **Webhook queue backpressure**: the 128-slot async dispatch channel that drops on overflow, `internal/webhook/webhook.go:39,189-195`.
- **Memo content length limit**: instance-setting-driven, enforced in `CreateMemo`/`UpdateMemo` at `server/router/api/v1/memo_service.go:101-106,439-444`.

If you want per-user rate limiting, it would need to be added — the natural insertion points are a new Connect interceptor in the chain at `server/router/api/v1/v1.go:133` (it has authenticated identity available after `NewAuthInterceptor`) and an Echo middleware at `server/server.go:52` for the non-Connect `/file/*` and RSS routes.
