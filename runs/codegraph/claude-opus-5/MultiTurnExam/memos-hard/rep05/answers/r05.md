**Premise correction: there is no GraphQL in this repository.** No `.graphql` or `.gql` files exist, no `gqlgen`/`graphql-go` dependency appears in `go.mod`, and a case-insensitive search for `graphql` across the Go, TypeScript, and manifest files returns zero hits. There is no schema file, resolver layer, or `/graphql` endpoint to point to.

**Actual API surface: Protobuf-defined RPC services, exposed over three transports plus an MCP tool layer.**

**Schema of record — `.proto` files in `proto/api/v1/`:**

| File | Service |
|---|---|
| `proto/api/v1/memo_service.proto` | memos, comments, relations, attachments-on-memos, reactions |
| `proto/api/v1/user_service.proto` | users, settings, webhooks, access tokens, stats |
| `proto/api/v1/auth_service.proto` | sessions, SSO |
| `proto/api/v1/attachment_service.proto` | attachments |
| `proto/api/v1/instance_service.proto` | instance settings/profile |
| `proto/api/v1/shortcut_service.proto`, `idp_service.proto`, `ai_service.proto`, `common.proto` | shortcuts, identity providers, AI, shared types |

**Code generation** is driven by Buf (`proto/buf.gen.yaml`), which runs five plugins: `protocolbuffers/go` and `grpc/go` (Go types + gRPC stubs → `proto/gen/`), `connectrpc/go` (Connect handlers), `grpc-ecosystem/gateway` (REST/JSON transcoding), `community/google-gnostic-openapi` (→ `proto/gen/openapi.yaml`), and `bufbuild/es` (TypeScript types → `web/src/types/proto`, which is how the frontend consumes the API).

**Runtime transports**, all registered in `server/router/api/v1/v1.go`:

- **gRPC-Gateway / REST-JSON** — `runtime.NewServeMux` with `gatewayAuthMiddleware` (`v1.go:95-97`), each service registered via `RegisterXxxServiceHandlerServer` (lines 99-121), mounted at `/api/v1/*` and `/file/*` (lines 126-127). This is the public HTTP API.
- **Connect RPC** — `connectHandler.RegisterConnectHandlers` with the interceptor chain `Metadata → Logging → Recovery → Auth` (`v1.go:133-141`).
- **Server-Sent Events** — `RegisterSSERoutes` (`v1.go:124`) for real-time push, outside the protobuf definitions.

**Also present, and the nearest thing to a "schema for the public API":** the generated OpenAPI document `proto/gen/openapi.yaml`, embedded into the binary via `proto/openapi_embed.go` and served/consumed by the MCP layer in `server/router/mcp/` (see `openapi.go`, `catalog.go`), which exposes the API as MCP tools with JSON Schema per operation.

Non-protobuf HTTP surfaces exist too: the file server at `/file/...` (`server/router/fileserver/fileserver.go:121-125`), RSS feeds (`server/router/rss/rss.go`), the sitemap and SPA fallback (`server/router/frontend/frontend.go`), and `/healthz` (`server/server.go:67`).
