**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at line 152); protection is the SSRF-guarding dialer `safeDialContext` + `isReservedIP`/reserved-CIDR list — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:14-54`, with an admission-time check `webhook.ValidateURL` — `internal/webhook/validate.go:62`.**

How it fits together:

- **Trigger path** — memo changes call `DispatchMemoCreatedWebhook` / `DispatchMemoUpdatedWebhook` / `DispatchMemoDeletedWebhook` / `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15-30`), which funnel into `dispatchMemoRelatedWebhook` (line 48) and enqueue via `webhook.PostAsync` (lines 43 and 71).
- **Queue → delivery** — `PostAsync` (`internal/webhook/webhook.go:184`) pushes onto a bounded 128-slot channel `asyncPostQueue`, dropping with a warning when full; four goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it and call `Post`. So `Post` is where the outbound HTTP request is built, HMAC-signed (Standard Webhooks `webhook-id`/`webhook-timestamp`/`webhook-signature` headers, lines 133-150), and executed.
- **Primary SSRF protection (dial time)** — the shared `safeClient` (`internal/webhook/webhook.go:32-37`) uses a `Transport` whose `DialContext` is `safeDialContext` (line 59). It resolves the hostname itself and rejects the connection if *any* resolved address falls in a reserved range. Because the check happens at dial time rather than at save time, it also defeats DNS rebinding (the comment at lines 30-31 says so explicitly).
- **Blocked ranges** — `reservedCIDRs` in `internal/webhook/validate.go:14-23`: IPv4 loopback `127.0.0.0/8`, RFC-1918 `10/8`, `172.16/12`, `192.168/16`, link-local `169.254.0.0/16` (which covers cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`. Parsed once in `init()` into `reservedNetworks` and tested by `isReservedIP` (line 44).
- **Secondary check (config time)** — `ValidateURL` (`internal/webhook/validate.go:62`) runs when a user registers or edits a webhook, enforcing absolute URL, http/https scheme only, and non-reserved resolution. It's called from `CreateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:74`) and `UpdateUserWebhook` (lines 161 and 182).
- **Escape hatch** — `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted setups targeting LAN services. Note that in the current tree this variable is only ever assigned in tests (`internal/webhook/webhook_test.go:91,142`) — no flag, env var, or config path sets it, so in a running server it stays `false`.
