**No — the MySQL driver is constructed in exactly one place, the factory.**

Evidence:

- `mysql.NewDB` (`store/db/mysql/mysql.go:20`) is the driver's only constructor, and a repo-wide grep for it turns up a single call site: `store/db/db.go:22`, inside the `switch profile.Driver` in `NewDBDriver` (`store/db/db.go:14-27`).
- Nothing else imports `github.com/usememos/memos/store/db/mysql`. The only import of that path in the tree is `store/db/db.go:8`.
- Every other database entry point goes through the factory instead: `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(profile)`.
- Two grep hits look like counterexamples but aren't. `store/test/containers.go:42,101-105` uses `mysql.Run(...)`/`mysql.WithDatabase(...)` from `github.com/testcontainers/testcontainers-go/modules/mysql` (imported at line 20) — that spins up a MySQL *container* for tests, not the store driver. Similarly, `mysql.ParseDSN` / `mysql.Config` at `store/db/mysql/mysql.go:17,30,73` refer to `github.com/go-sql-driver/mysql`, the upstream SQL driver library.

One qualification: within the `mysql` package itself, a unit test builds the struct literal directly — `db := &DB{}` at `store/db/mysql/auth_config_test.go:12` — to exercise `IsRetryableAuthenticationMutationError` without a live connection. That's an unexported-field-free zero value in the same package, not an outside construction of a usable driver; the only other `DB{...}` literal is inside `NewDB` itself (`store/db/mysql/mysql.go:29`).
