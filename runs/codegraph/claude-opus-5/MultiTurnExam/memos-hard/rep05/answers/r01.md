**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive search for `redis` across all Go sources returns zero hits, and `go.mod` has no Redis client dependency (no `go-redis`, `redigo`, or similar). There is no external cache server, no connection string, and no cache-related flag or env var in `cmd/memos/main.go`. So there is nothing to configure.

**Actual mechanism: a process-local, in-memory cache with a 10-minute TTL for user entries.**

- **Implementation** — `store/cache/cache.go`. `Cache` (line 67) is a `sync.Map` guarded by an atomic item counter, with per-item expiration timestamps (`item.expiration`, line 37) and a background `cleanupLoop` goroutine started in `New` (line 83). It satisfies a local `Interface` (line 11) with `Set`/`SetWithTTL`/`Get`/`Delete`/`Clear`/`Size`/`Close`.
- **Where it's "configured"** — in code, not config: `store.New` builds the `cache.Config` literal at `store/store.go:39-45` and passes it to three separate cache instances (lines 51-53):
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  Note this duplicates `cache.DefaultConfig()` (`store/cache/cache.go:57-64`) rather than calling it — same values, written out twice.
- **TTL for user entries: 10 minutes.** The user cache is `Store.userCache` (`store/store.go:28`), keyed by `userCacheKey(userID)` (`store/user.go:88`). Every write goes through plain `Set`, which applies `c.config.DefaultTTL` (`store/cache/cache.go:93-95`) — there is no per-entry override anywhere, since `SetWithTTL` has no callers outside the cache package itself. Writes happen at `store/user.go:98,122,132,143,167`; reads at `store/user.go:150`; explicit invalidation on user deletion at `store/user_delete.go:40`.
- **Bounds and lifecycle** — capped at 1000 items per cache, with `cleanupOldest` triggered on overflow (`store/cache/cache.go:117-119`) and a sweep every 5 minutes. All three caches are shut down by `Store.Close` (`store/store.go:73-76`).

One practical consequence: because this is in-process memory, the cache is per-instance and not shared. Running multiple Memos processes against one database means each has its own copy, and a user record updated by one process can be served stale by another for up to 10 minutes.
