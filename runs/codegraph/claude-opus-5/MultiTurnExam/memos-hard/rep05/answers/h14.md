**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, which delegates the actual parse to `(*service).ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: `CreateMemo`, `UpdateMemo` (only when the update mask includes `content`), and `CreateMemoComment` (indirectly). Extracted: `Tags` plus the five `Property` fields — `Title`, `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks`.**

**Where it's computed.** `RebuildMemoPayload` is thin — it ensures `memo.Payload` is non-nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, and assigns the two derived fields:

```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```
(`server/runner/memopayload/runner.go:74-87`). The result is persisted in the `memo.payload` JSON column as `storepb.MemoPayload` (`proto/gen/store/memo.pb.go:24-31`), whose fields are `Property`, `Location`, and `Tags`. Note `Location` is *not* derived — it's user-supplied and written separately at `server/router/api/v1/memo_service.go:110-112`, after the rebuild, which is why the rebuild must run first.

**What `ExtractAll` extracts**, in a single goldmark AST walk (`internal/markdown/markdown.go:356-420`):

| Output | Source | Line |
|---|---|---|
| `Tags []string` | `#tag` nodes from the custom tag extension, deduplicated preserving original case | 376-378, 418 |
| `Property.Title` | text of the first block-level child *only if* it's an H1 heading | 383-389 |
| `Property.HasLink` | any `gast.KindLink` node | 393-394 |
| `Property.HasCode` | any code block, fenced code block, or code span | 396-397 |
| `Property.HasTaskList` | any `east.KindTaskCheckBox` | 399-400 |
| `Property.HasIncompleteTasks` | a task checkbox with `IsChecked == false` | 401-405 |

`ExtractAll` also returns `Mentions` (lowercased `@username` nodes, line 379-381), but `RebuildMemoPayload` **discards** it — mentions aren't part of the stored payload. They're consumed separately at request time for notifications via `server/router/api/v1/memo_mention_helpers.go:32`.

**Triggers (the only three).** Grepping for callers of `RebuildMemoPayload` yields exactly two direct sites, both in the API layer:

1. `CreateMemo` — `server/router/api/v1/memo_service.go:108` (after the content-length check, before `Store.CreateMemo`).
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, inside the update-mask loop and guarded by `if path == "content"`. The recomputed payload is then attached to the update at line 452 (`update.Payload = memo.Payload`). Consequence: changing visibility, pinning, or location does **not** recompute; only a content edit does.
3. `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:56` reaches it indirectly by calling `s.CreateMemo(...)`, so comments get the same treatment.

The `memopayload.Runner` in the same file (`runner.go:14-72`) is a batch backfill that would rebuild every memo's payload, but as established it has no production caller — nothing constructs it, so it never runs.

**One related derived value that is *not* stored:** `Snippet`. It's computed at read time on each conversion via `GenerateSnippet(content, 64)` — `server/router/api/v1/memo_service_webhooks.go:83-85`, called from `server/router/api/v1/memo_service_converter.go:76` and `:225` — rather than persisted in the payload. So for list/preview rendering, tags and properties come from stored payload, while the snippet is regenerated per response.
