The last three of these are easy to miss: `SetMemoAttachments` and `SetMemoRelations` don't mention webhooks at all — they call the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which internally calls `DispatchMemoUpdatedWebhook` (`memo_update_helpers.go:67`).

**Convergence.** All four `Dispatch*Webhook` entry points (`server/router/api/v1/memo_service_webhooks.go:15-46`) funnel into `webhook.PostAsync` (`memo_service_webhooks.go:43`, `:71`) with `payload.URL = hook.Url` taken from the user's stored webhook rows (`s.Store.GetUserWebhooks`). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto the bounded `asyncPostQueue`; four background workers started in `init()` (`webhook.go:42-55`) drain it and call **`webhook.Post`** — `internal/webhook/webhook.go:120` — which is where the single outbound `safeClient.Do(req)` lives (`webhook.go:152`). Every handler above converges there.

Note the delivery is asynchronous, so the outbound request happens on a worker goroutine after the RPC has already returned; a full queue silently drops the dispatch (`webhook.go:191-195`).
