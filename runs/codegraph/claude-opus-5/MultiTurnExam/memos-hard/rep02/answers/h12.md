**`(*DB).CreateMemo` in the sqlite package — `store/db/sqlite/memo.go:16`; determined by tracing the driver-selection switch back to the CLI's default flag value, not by reading the call graph alone.**

The runtime path when a memo is saved:

1. `APIV1Service.CreateMemo` → `s.Store.CreateMemo` — `server/router/api/v1/memo_service.go:70`
2. `Store.CreateMemo` validates the UID then delegates to the interface: `return s.driver.CreateMemo(ctx, create)` — `store/memo.go:109-114`
3. `s.driver` is a `store.Driver` interface, so three implementations are candidates: `store/db/sqlite/memo.go:16`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`.
4. On sqlite the INSERT is built and executed at `store/db/sqlite/memo.go:41-49` — `INSERT INTO memo (...) VALUES (...) RETURNING id, created_ts, updated_ts, row_status`, run via `d.db.QueryRowContext`.

**How the candidate was disambiguated** — the interface hides it, so I resolved the concrete type by following where the driver value is constructed:

- The only place `store.Driver` is built is `db.NewDBDriver`, a `switch profile.Driver` over `"sqlite" | "mysql" | "postgres"` — `store/db/db.go:14-31`.
- `profile.Driver` comes from `viper.GetString("driver")` — `cmd/memos/main.go:43` — and that driver is handed to `db.NewDBDriver` at `cmd/memos/main.go:57`, then into `store.New` at `:64`.
- The default is registered twice, both `"sqlite"`: `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the flag default `rootCmd.PersistentFlags().String("driver", "sqlite", "database driver")` (`cmd/memos/main.go:130`), bound at `:151`.
- Corroborating: `Profile.Validate` has a sqlite-specific branch that synthesizes the DSN as `<data>/memos_prod.db` when `Driver == "sqlite" && DSN == ""` (`internal/profile/profile.go:110-117`) — i.e. a flagless install is expected to land on sqlite with a file DSN.

So with no `--driver`/`--dsn` flags, the switch takes `case "sqlite": sqlite.NewDB(profile)` and every `s.driver.X` call dispatches to `store/db/sqlite/*`.
