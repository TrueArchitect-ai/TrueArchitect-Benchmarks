**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard at dial time via `safeDialContext`/`isReservedIP` — `internal/webhook/webhook.go:59` + `internal/webhook/validate.go:44` (with `ValidateURL` at config time — `internal/webhook/validate.go:62`).**

How it fits together:

**Delivery path**
- Memo create/update/delete/comment events call `DispatchMemo*Webhook` in `server/router/api/v1/memo_service_webhooks.go:15-46`, which builds the payload and calls `webhook.PostAsync` (`memo_service_webhooks.go:43`, `:71`).
- `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel `asyncPostQueue` (`webhook.go:39`), dropping with a warning if full.
- Four worker goroutines started in `init()` (`webhook.go:42-55`) drain that queue and call `Post` — so the actual outbound HTTP POST executes in `Post` at `internal/webhook/webhook.go:120`, on a background worker, not on the request goroutine. `Post` marshals the JSON body, optionally adds Standard Webhooks HMAC headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, `webhook.go:133-150`), and issues `safeClient.Do(req)` at `webhook.go:152`.

**Protection against internal addresses (two layers)**
1. *Dial-time (the real enforcement):* `safeClient` (`webhook.go:32-37`) uses a `http.Transport` whose `DialContext` is `safeDialContext` (`webhook.go:59-77`). It resolves the host itself and refuses to dial if **any** resolved IP is reserved. Because the check happens on the actual connection attempt, it also defeats DNS rebinding and redirect-to-internal, which a URL-only check would miss.
2. *Config-time:* `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and hostnames resolving to reserved IPs when a webhook is created/updated — called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

Both share `isReservedIP` (`validate.go:44`) against the `reservedCIDRs` list (`validate.go:14-23`): IPv4 loopback, RFC-1918 ranges, link-local `169.254.0.0/16` (cloud IMDS), and the IPv6 equivalents (`::1/128`, `fc00::/7`, `fe80::/10`), parsed once in `init()` (`validate.go:28`).

One caveat worth noting: the exported `webhook.AllowPrivateIPs` flag (`validate.go:41`) disables both layers when true, but I found no code in the repo that ever sets it — no flag, env var, or config wires it up — so in practice it stays `false`.
