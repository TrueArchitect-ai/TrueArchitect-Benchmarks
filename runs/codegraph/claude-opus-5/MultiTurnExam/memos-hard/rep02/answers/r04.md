**Premise correction: neither. There is no message broker in this repository at all.** Grepping case-insensitively for `nats|rabbitmq|amqp|kafka|streadway|pubsub` across all Go sources, `go.mod`, and `go.sum` returns zero hits — no broker client is even a dependency, so there is no queue declaration to point to.

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool**, all inside `internal/webhook/webhook.go`:

- **The "queue"** is a package-level channel with a hard capacity of 128:
  `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`.
- **The "workers"** are 4 goroutines started in the package `init()` — `internal/webhook/webhook.go:42-55` — each looping `for payload := range asyncPostQueue` and calling `Post(payload)`, logging a warning on failure.
- **Producers** call `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send: if the buffer is full, the payload is **dropped** with a warning rather than blocking or retrying (`webhook.go:189-195`). Callers are the memo dispatch helpers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120`) via the shared SSRF-guarded `safeClient` (`webhook.go:32-37`).

Practical consequences of it being a channel rather than a broker: the queue is per-process and in-memory, so it isn't shared across replicas; nothing is persisted, so a restart loses anything still buffered; there are no retries, acks, or dead-lettering — a failed `Post` is logged and discarded; and overflow silently drops events at 128 pending items.
