h03.

**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`) — OAuth 2.0 / OIDC is the only concrete implementation.**

Details:

- **Abstraction package** — `internal/idp` (`internal/idp/idp.go:1-8`). It's deliberately thin: no Go interface, just the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider normalizes to. That struct is the contract consumers depend on — `resolveSSOUser` in `server/router/api/v1/auth_service_sso.go:19` takes it as a parameter and never touches provider-specific types.
- **Implementation package** — `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`). It defines its own `IdentityProvider` type (`oauth2.go:20`), a constructor from the stored config (`NewIdentityProvider(*storepb.OAuth2Config)`, `oauth2.go:27`), `ExchangeToken(ctx, redirectURL, code, codeVerifier)` with PKCE support (`oauth2.go:47`), and `UserInfo(ctx, token)` returning `*idp.IdentityProviderUserInfo` (`oauth2.go:83`). It is the only subdirectory of `internal/idp`.

Dispatch happens in `server/router/api/v1/auth_service_sso.go:120-134`: `resolveSSOIdentity` branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` and constructs the oauth2 provider. That `if` (rather than a registry or interface lookup) is the extension point where another protocol — SAML, LDAP — would be added; today no other branch exists, so a provider row of any other type would fall through with `userInfo` nil.
