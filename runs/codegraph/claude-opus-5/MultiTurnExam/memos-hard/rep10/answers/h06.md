All four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go`. The three memo-lifecycle ones funnel through the unexported `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:47`); the comment one has its own loop (`:30`) because it targets the *related* memo owner's webhooks rather than the actor's. Both loops end at the same call: `webhook.PostAsync(payload)` (`memo_service_webhooks.go:41` and `:70`).

`PostAsync` (`internal/webhook/webhook.go:184`) is therefore the single function every handler path converges on. It only enqueues onto a bounded 128-slot channel (`webhook.go:39`), dropping with a warning if full; four worker goroutines started in `init` (`webhook.go:42-55`) dequeue and call `Post` (`webhook.go:120`), which builds the signed request and executes it via `safeClient.Do` (`webhook.go:152`). So if you want the function that performs delivery itself rather than the last shared caller before it, that's `Post`.
