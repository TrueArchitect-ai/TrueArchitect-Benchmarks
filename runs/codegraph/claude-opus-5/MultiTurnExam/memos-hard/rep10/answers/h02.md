**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); SSRF guard = `safeDialContext` reserved-IP check at dial time — `internal/webhook/webhook.go:59-77`, backed by `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go:14-54`**

How it fits together:

- **Trigger → delivery**: memo changes call the dispatch helpers in `server/router/api/v1/memo_service_webhooks.go` (e.g. `dispatchMemoRelatedWebhook`, `DispatchMemoCommentCreatedWebhook`), which call `webhook.PostAsync` (`internal/webhook/webhook.go:184`). That only enqueues onto a bounded 128-slot channel (`webhook.go:39`, drops with a warning when full); four worker goroutines started in `init` (`webhook.go:42-55`) pop the queue and call `Post`. So `Post` is where the outbound HTTP request is built, HMAC-signed (Standard Webhooks `webhook-id`/`webhook-timestamp`/`webhook-signature` headers), and executed.
- **Primary protection (dial time)**: all dispatches go through the shared `safeClient` (`internal/webhook/webhook.go:32-37`) whose `Transport.DialContext` is `safeDialContext`. It splits host/port, resolves the host itself, and refuses to dial if *any* resolved address falls in a reserved range. Because the check happens at connect time on the addresses actually resolved, it also defeats DNS rebinding and redirect-to-internal — noted in the comment at `webhook.go:30-31`.
- **Secondary protection (config time)**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and hostnames resolving to reserved IPs when a webhook is created or updated — `server/router/api/v1/user_service_webhooks.go:74` and `:161`/`:182`.
- **Blocked ranges**: loopback, RFC-1918, link-local incl. cloud IMDS `169.254.169.254`, plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10` (`internal/webhook/validate.go:14-23`), parsed once in `init` (`validate.go:28-36`).
- **Escape hatch**: the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted setups. Note it is declared but never assigned anywhere in non-test code — no CLI flag or env var currently sets it, so it stays `false` in practice.
