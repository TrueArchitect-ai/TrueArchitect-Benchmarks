**Premise correction: neither. There is no message broker in this repository at all — no NATS, no RabbitMQ, no Kafka, no AMQP client. A case-insensitive search of all Go sources and `go.mod` for `nats`, `rabbitmq`, `amqp`, `kafka`, `streadway`, and `pubsub` returns zero hits. There is no queue declaration to point to, because there is no external queue.**

**Actual mechanism — an in-process buffered Go channel with a fixed worker pool, all in `internal/webhook/webhook.go`:**

- **The "queue"** is a package-level Go channel with a hard capacity of 128:
  `var asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`. It lives in the server process's memory; nothing is persisted, so anything still queued at shutdown is silently lost, and it is not shared across replicas.
- **The workers** are 4 goroutines started in the package's `init()` — `internal/webhook/webhook.go:42-55`. Each loops `for payload := range asyncPostQueue` and calls `Post(payload)`, logging a warning on failure. They are started by package initialization rather than wired into `Server.Start`, and there is no shutdown path that drains or stops them.
- **The producer** is `PostAsync` — `internal/webhook/webhook.go:184-196`. It does a non-blocking `select` send: if the channel is full, the `default` branch drops the delivery and logs `"Dropped webhook dispatch because the async queue is full"` (`:191-195`). So overflow is discarded, not spooled — there is no persistence, no retry, no dead-letter, and no redelivery of any kind.
- **Delivery itself** happens in `Post` — `internal/webhook/webhook.go:120`, which marshals the payload, adds Standard Webhooks HMAC headers when a signing secret is set, and executes the request via the SSRF-guarded `safeClient` (`webhook.go:32-37`, `:152`).
- **Who enqueues**: the memo lifecycle dispatchers in `server/router/api/v1/memo_service_webhooks.go` — `dispatchMemoRelatedWebhook` (`:70`) for created/updated/deleted, and `DispatchMemoCommentCreatedWebhook` (`:41`) for comments.

So the "workers consume from" relationship is real, but the thing they consume from is `asyncPostQueue`, a 128-slot in-memory channel declared at `internal/webhook/webhook.go:39` — not a broker topic or queue binding.
