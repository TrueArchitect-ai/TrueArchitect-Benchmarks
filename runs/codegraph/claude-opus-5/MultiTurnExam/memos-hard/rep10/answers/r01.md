**Premise correction: there is no Redis anywhere in this repository.** The word "redis" does not appear in any `.go`, `.mod`, `.sum`, `.yaml`, or frontend source file, and `go.mod` lists no Redis client (no `go-redis`, `redigo`, or similar). The cache layer is a hand-rolled, in-process, in-memory cache — nothing is configured, connected, or persisted externally, and cached data does not survive a restart or get shared between instances.

**Actual mechanism:**

- **Implementation**: `store/cache/cache.go` — a `Cache` struct backed by a `sync.Map` plus an atomic item counter (`store/cache/cache.go:67-73`), satisfying the local `Interface` (`cache.go:11-32`). Entries are `item{value, expiration, size}` (`cache.go:35-39`); expiry is enforced lazily on read (`Get` deletes and reports a miss if `time.Now().After(itm.expiration)`, `cache.go:132-146`) and by a background cleanup goroutine, with `cleanupOldest` evicting when `MaxItems` is exceeded (`cache.go:117-119`).
- **Where it's configured**: `store.New` in `store/store.go:38-61`. The `cache.Config` literal there is the only configuration point — there is no flag, env var, or config file for it:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

  Three caches are built from that same config: `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`). Note `cache.DefaultConfig()` (`cache.go:57-64`) declares identical values but is not what `store.New` uses.

- **TTL for user entries: 10 minutes.** Every user write goes through `Set`, not `SetWithTTL` — `store/user.go:98`, `:122`, `:132`, `:143`, `:167` — and `Set` applies `c.config.DefaultTTL` (`store/cache/cache.go:93-95`), i.e. the 10 minutes from `store/store.go:41`. No call site anywhere passes a custom TTL for users.
- **Keying and invalidation**: the key is just the decimal user ID (`userCacheKey`, `store/user.go:88-90`) — so lookups only hit the cache when finding by ID (`Store.GetUser`, `store/user.go:149-156`); username/email lookups always fall through to the driver. Entries are explicitly evicted on user deletion (`store/user_delete.go:40`), and all three caches are shut down in `Store.Close` (`store/store.go:74-76`).

There is one other, unrelated cache in the backend: a small in-process RSS response cache in `server/router/rss/rss.go` (`cacheEntry` at `:35`, `putInCache`) — also memory-only, also not Redis.
