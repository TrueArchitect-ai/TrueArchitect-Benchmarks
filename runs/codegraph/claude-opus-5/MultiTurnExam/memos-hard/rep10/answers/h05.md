h05.

**Explicit Go code — two `DELETE FROM reaction` statements inside the per-driver `DeleteUser` transaction, in all three drivers. There is no database-level cascade for reactions.**

Evidence locations:

**1. The Go code that does it.** `Store.DeleteUser` (`store/user.go:171`) delegates to `s.driver.DeleteUser`, and each driver's `deleteUserTargetsTx` runs two reaction deletes before removing the user row:

- `store/db/sqlite/user_delete.go` — `deleteReactionsByContentIDsTx` and `deleteReactionsByCreatorTx` called at lines 93 and 102 of `deleteUserTargetsTx`; implementations at `deleteReactionsByContentIDsTx` (`DELETE FROM reaction WHERE content_id IN (...)`, batched at 500) and `deleteReactionsByCreatorTx` (`DELETE FROM reaction WHERE creator_id = ?`).
- `store/db/mysql/user_delete.go:96` and `:102` (implementations at `:417` and `:437`).
- `store/db/postgres/user_delete.go:96` and `:102` (implementations at `:380` and `:400`).

The two deletes cover different things: *by content ID* removes everyone's reactions on the deleted user's memos (content IDs built as `"memos/"+memo.UID` by `memoContentIDsFromRefs`, over the recursive memo+comment tree); *by creator ID* removes the deleted user's own reactions on other people's memos. All of it runs inside the single `BeginTx`/`Commit` in `DeleteUser`.

**2. The schema, showing no DB-level rule.** The `reaction` table has no foreign key and no `ON DELETE CASCADE` in any dialect:

- `store/migration/sqlite/LATEST.sql:92-99`
- `store/migration/mysql/LATEST.sql:91-98`
- `store/migration/postgres/LATEST.sql:91-98`

Each declares only `id`, `created_ts`, `creator_id`, `content_id`, `reaction_type` plus a `UNIQUE(creator_id, content_id, reaction_type)` — `creator_id` is a plain `INTEGER NOT NULL`, not a reference to `user(id)`. Grepping `REFERENCES|CASCADE` across `store/migration/` returns cascades only for `memo_share`, `memo_resource`, `user_setting`, etc., never for `reaction`. (Note `content_id` is a text resource name like `memos/<uid>`, not an integer FK, so a cascade from `memo` isn't even expressible here.)

Test confirmation.** `server/router/api/v1/test/user_service_delete_test.go` seeds reactions on the user's own memo, on their comment on a foreign memo, and a peer's reaction on a foreign memo (lines 188-209), then after deletion asserts the first two sets are empty and the unrelated peer reaction survives (lines 287-298).
