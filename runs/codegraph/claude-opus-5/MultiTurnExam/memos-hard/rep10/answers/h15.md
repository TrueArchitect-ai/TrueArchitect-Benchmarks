Two things worth calling out:

- **The rules are re-implemented, not shared.** The API layer's shape is "`!= Public` → require auth; `== Private` → require creator or super-user" (`memo_service.go:55-66`), but `fileserver.checkAttachmentPermission` uses `user.Role != store.RoleAdmin` directly instead of `isSuperUser`, and additionally gates public memos on `s.Profile.AllowAnonymous()` (`fileserver.go:677`). `canViewerAccessMemo` exists twice with slightly different admin checks — `isSuperUser(viewer)` in `user_service_notifications.go:305` vs. `viewer.Role == store.RoleAdmin` in `notification/email.go:309`.
- **Two deliberate bypasses.** Share tokens skip visibility entirely: `GetMemoByShare` (`server/router/api/v1/memo_share_service.go:153`) authorizes on an unexpired `MemoShare` and never consults `memo.Visibility` (it only rejects archived/missing memos), and `fileserver.go:684-689` accepts a `?share_token=` query param for attachments on private/protected memos.
