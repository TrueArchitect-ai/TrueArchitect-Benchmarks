**`internal/idp` (package `idp`, `internal/idp/idp.go`); `internal/idp/oauth2` (package `oauth2`, `internal/idp/oauth2/oauth2.go`) — OAuth2 is the only concrete protocol implementation that ships**

Details:

- **Abstraction package**: `internal/idp` — `internal/idp/idp.go:3` defines the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider must produce. Note the abstraction is thin: it's a common result type, not a Go interface — there is no `IdentityProvider` interface in the package.
- **Implementation package**: `internal/idp/oauth2` — `internal/idp/oauth2/oauth2.go` provides `IdentityProvider` (line 20), `NewIdentityProvider` (line 27, validates `clientId`/`clientSecret`/`tokenUrl`/`userInfoUrl`/`fieldMapping.identifier`), `ExchangeToken` (line 47, with PKCE `code_verifier` support), and `UserInfo` (line 83, maps provider claims into `idp.IdentityProviderUserInfo` via the configured field mapping).
- **Corroborating evidence that OAuth2 is the only one**: the provider type enum has exactly one non-unspecified value, `OAUTH2 = 1` (`proto/gen/api/v1/idp_service.pb.go` `IdentityProvider_Type`; `proto/gen/store/idp.pb.go`), and `IdentityProviderConfig` is a oneof with a single `oauth2_config` member. `internal/idp/` contains only `idp.go` and the `oauth2/` subdirectory.
- **Call site**: `resolveSSOIdentity` in `server/router/api/v1/auth_service_sso.go` constructs the OAuth2 provider and calls `ExchangeToken` then `UserInfo`.
