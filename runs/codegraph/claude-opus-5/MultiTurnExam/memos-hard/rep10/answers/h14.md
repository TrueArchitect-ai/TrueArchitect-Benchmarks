**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `markdown.Service.ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: memo create and content-update. Extracted: `tags` plus the `Property` set — `title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`.**

**Where it's computed.** `RebuildMemoPayload(_ ctx, memo *store.Memo, markdownService markdown.Service)` (`server/runner/memopayload/runner.go:74-87`) initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, and assigns the two derived fields:

```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```

(`runner.go:85-86` — the only place in the codebase that writes either field.) The actual work is a single goldmark AST walk in `(*service).ExtractAll` (`internal/markdown/markdown.go:356-422`). The payload is persisted as protojson in the memo row's `payload` column (e.g. `store/db/sqlite/memo.go:17-27`).

**Triggers.** Only two production call sites, both in the memo RPC layer:

- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, run on the `store.Memo` before `s.Store.CreateMemo`.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, inside the `if path == "content"` branch of the update-mask loop, so recomputation happens **only** when `content` is in the field mask; the fresh payload is then assigned to `update.Payload` (`:450`). Updates to visibility, pinned, etc. do not recompute.

A third caller exists but is dead: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:52`) would rebuild every memo in 100-row batches, but nothing constructs `memopayload.NewRunner` outside the package — unlike the s3presign runner, it is not wired into `startBackgroundRunners` (`server/server.go:153`). So there is no backfill path in a running server.

**What's extracted** (`internal/markdown/markdown.go:362-421`):

- `Tags` — text of every `mast.TagNode` (`#tag`), skipping tags nested inside links/images (`asMemoTagNode`, `markdown.go:130`), deduplicated case-preservingly.
- `Property.Title` — text of the first block-level child of the document if it is an H1 heading (`markdown.go:383-389`).
- `Property.HasLink` — any `gast.KindLink` node.
- `Property.HasCode` — any code block, fenced code block, or code span.
- `Property.HasTaskList` — any `east.KindTaskCheckBox`; and `Property.HasIncompleteTasks` when such a checkbox is unchecked.

The proto shape is `MemoPayload.Property` in `proto/store/memo.proto:15-22` (`has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, `title`), with `tags` as `MemoPayload.tags` (`:12`).

`ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` does not store them — mentions are consumed separately at read/notify time via `s.MarkdownService.ExtractAll` in `server/router/api/v1/memo_mention_helpers.go:32`.

**Consumers** (why it exists): `convertMemoFromStore` copies `Payload.Tags` and `Payload.Property` onto the API `Memo` (`server/router/api/v1/memo_service_converter.go:48-49`), and user stats aggregate them (`server/router/api/v1/user_service_stats.go:138-148`). Note the list/preview *snippet* is a different thing — it is computed on read, not stored, via `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-88`, used at `memo_service_converter.go:76` and `:225`).
