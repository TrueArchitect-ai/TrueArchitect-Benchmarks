**Premise correction: no nightly database-cleanup job exists, and the cron scheduler is never used by the server at all — so there is no schedule time to report.**

Two separate corrections:

**1. The `internal/scheduler` package is dead code in production.** It's a complete, tested cron implementation — `Scheduler` (`internal/scheduler/scheduler.go:12`), `Job` (`internal/scheduler/job.go:14`), `ParseCronExpression`/`Schedule` (`internal/scheduler/parser.go:13`), with timezone and middleware options (`WithTimezone`, `WithMiddleware`, `Logging`, `Recovery`). But grepping every call site of `scheduler.New(` and `.Register(` outside the package yields **zero** production callers: all hits are in `internal/scheduler/example_test.go`, `internal/scheduler/scheduler_test.go`, `internal/scheduler/integration_test.go`, and doc comments (`internal/scheduler/doc.go`). Nothing under `server/`, `cmd/`, or `store/` imports the package. `Scheduler.Start` is never called, so no cron expression is ever parsed at runtime.

**2. There is no database-cleanup job of any kind.** Grepping for `cleanup`/`vacuum`/`prune`/`purge` across the backend turns up only *event-driven* cleanup, not scheduled: attachment-storage cleanup after user deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`), a best-effort rollback of a provisional SSO user (`server/router/api/v1/auth_service_sso.go:76`), and relation/attachment cleanup on memo delete (`server/router/api/v1/memo_service.go:579`). The string `"daily-cleanup"` does appear at `internal/scheduler/doc.go:15` — but that's an illustrative example inside a package doc comment, not a registered job.

**What actually runs on a timer.** The server's only background scheduling is in `Server.startBackgroundRunners` (`server/server.go:153-174`), and it uses a plain `time.Ticker`, not the cron package. Exactly one runner is started: the S3 presign refresher, on a fixed 12-hour interval (`runnerInterval` at `server/runner/s3presign/runner.go:27`, ticker at `:30`), plus one immediate pass at boot (`server/server.go:163`). That's an interval, not a wall-clock time — it fires 12 hours after startup, not at any fixed hour. The only other periodic work is the in-memory cache sweep every 5 minutes (`CleanupInterval` in `store/store.go:41`), which touches no database.
