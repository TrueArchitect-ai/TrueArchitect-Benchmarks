h15.

Nine distinct enforcement sites, across five server surfaces:

```
checkMemoReadAccess (gRPC memo reads: GetMemo, ListMemoComments, …) — server/router/api/v1/memo_service.go:39
ListMemos visibility scoping (query-level filter) — server/router/api/v1/memo_service.go:218-227
ListMemoComments comment-list filter — server/router/api/v1/memo_service_comments.go:158-162
ListMemoReactions gate — server/router/api/v1/reaction_service.go:29-41 (and UpsertMemoReaction at :83)
ListMemoAttachments gate — server/router/api/v1/memo_attachment_service.go:213-225
checkAttachmentAccess (attachment RPCs) — server/router/api/v1/attachment_service.go:445-452
checkAttachmentPermission (HTTP /file/attachments/...) — server/router/fileserver/fileserver.go:666-701
SSEClient.canReceive (live event fan-out) — server/router/api/v1/sse_hub.go:134
User-stats visibility scoping — server/router/api/v1/user_service_stats.go:84-90 and :218-220
```

Plus two surfaces that enforce by construction — they only ever query `PUBLIC`:

```
RSS feeds (GetExploreRSS / GetUserRSS) — server/router/rss/rss.go:90 and :141
Sitemap generation — server/router/frontend/frontend.go:150
```

How the sites differ:

- **`checkMemoReadAccess`** (`memo_service.go:39-68`) is the canonical single-memo gate: archived memos are creator-only; non-`PUBLIC` requires authentication; `PRIVATE` requires being the creator. Note it does *not* grant admins access to others' private memos, unlike the attachment gates.
- **Query-level scoping** rather than post-filtering is used for list endpoints: anonymous callers get `VisibilityList = [PUBLIC]`, authenticated callers get a CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` (`memo_service.go:218-227`; same pattern for comments at `memo_service_comments.go:158-162`, and for stats at `user_service_stats.go`).
- **Attachment surfaces** re-derive the check from the owning memo, since attachments inherit their memo's visibility — once for gRPC (`attachment_service.go:445`, `memo_attachment_service.go:213`) and again for raw HTTP file serving (`fileserver.go:666`). The HTTP path is the most permissive: it short-circuits for `PUBLIC` only when `Profile.AllowAnonymous()` (`fileserver.go:677`), and adds a **share-token bypass** — a valid, unexpired `?share_token=` bound to that memo grants access to private/protected content (`fileserver.go:684-689`).
- **`SSEClient.canReceive`** (`sse_hub.go:134-144`) enforces at push time, filtering each broadcast per connected client; unknown visibility values fail closed.
- **`GetMemoByShare`** (`memo_share_service.go:153`) is the deliberate exception: it bypasses visibility entirely — a valid share token returns the memo regardless of `PRIVATE`/`PROTECTED` — and enforces only token validity/expiry (`getActiveMemoShare`, `:199`) and archived status.
