**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation — OAuth2, the only one that ships)**

Details:

- **Abstraction:** `internal/idp/idp.go` — a deliberately thin package. It defines only the shared normalized result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) at `internal/idp/idp.go:3-8`. There is no Go `interface` here; the "abstraction" is that common user-info struct plus the protobuf config union in `proto/gen/store` (`IdentityProviderConfig`, whose only variant is `OAuth2Config`).

- **Implementation:** `internal/idp/oauth2/oauth2.go` — package comment at line 1 says "implements the OAuth2 identity provider integration." It provides `IdentityProvider` (line 20), `NewIdentityProvider` with required-field validation (line 27), `ExchangeToken` with optional PKCE `code_verifier` support (line 47), and `UserInfo`, which calls the configured userinfo endpoint with a bearer token and maps claims onto `idp.IdentityProviderUserInfo` using the config's `FieldMapping` (line 83). Tests live alongside at `internal/idp/oauth2/oauth2_test.go`.

- OAuth2 is the sole concrete protocol — `internal/idp/` contains only `idp.go` and the `oauth2/` subdirectory; no OIDC-specific or SAML package exists. Callers wire it up in the API layer (`server/router/api/v1/`, e.g. the auth SSO sign-in path and `UpdateIdentityProvider`).
