**Premise correction: neither. There is no message broker in this repository — no NATS, RabbitMQ, AMQP, Kafka, or pub/sub client appears anywhere in the Go sources, `go.mod`, or `go.sum`. Consequently there is no queue declaration to point at.**

The actual mechanism is a purely in-process Go channel fan-out, entirely inside `internal/webhook/webhook.go`:

- **The "queue"** is a package-level buffered channel with a fixed capacity of 128, declared at `internal/webhook/webhook.go:39`:
  `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`
  It lives in the same process as the API server — nothing is serialized to a broker, and nothing survives a restart.

- **The "workers"** are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over `asyncPostQueue` and calls `Post(payload)`, logging a warning on failure. Because they're launched from `init()`, the pool spins up on package import, not from any explicit server wiring — there's no start/stop control and no graceful drain at shutdown (`Server.Shutdown` at `server/server.go:134` doesn't touch them).

- **Enqueue** happens in `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send. On a full queue it takes the `default` branch and **drops the event**, logging `"Dropped webhook dispatch because the async queue is full"` with the URL and activity type. So overflow is silent data loss, not backpressure — the API handler never blocks. Producers are the memo dispatch paths at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

- **Delivery** is `Post` (`internal/webhook/webhook.go:120`), issuing the HTTP POST via `safeClient.Do(req)` at line 152, with a 30-second timeout and SSRF-blocking dialer.

There is also no retry, dead-letter, or acknowledgement layer: a failed `Post` is logged and discarded (`internal/webhook/webhook.go:46-51`). The only durable record of a webhook is its *configuration* — the user's registered URL and signing secret in the `WebhooksUserSetting` user setting, managed by `server/router/api/v1/user_service_webhooks.go` — not any pending delivery.
