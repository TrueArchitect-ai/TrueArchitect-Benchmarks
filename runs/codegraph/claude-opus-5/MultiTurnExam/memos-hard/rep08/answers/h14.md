**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`; triggers: memo create and memo-content update; extracted: `tags` plus the `Property` set — `title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-87`) ensures `memo.Payload` is non-nil, calls `markdownService.ExtractAll([]byte(memo.Content))` — explicitly "in a single pass (more efficient)" — and assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property`. The real work is `ExtractAll` (`internal/markdown/markdown.go:356`), which parses the content once with goldmark and does a single `gast.Walk`. The result is persisted in the memo's `payload` JSON column (shape defined at `proto/store/memo.proto:7-29`).

**Triggers — exactly two production call sites**, both in the v1 memo service:
1. `CreateMemo` — `server/router/api/v1/memo_service.go:108`, run after the content-length check and before `s.Store.CreateMemo` (line 114).
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, inside the `if path == "content"` branch of the update-mask loop; the rebuilt payload is then attached to the update via `update.Payload = memo.Payload` (line 452). Update masks that touch only `visibility`, `pinned`, etc. do *not* recompute it.

A third, latent trigger exists but never fires: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) rebuilds payloads for every memo in batches of 100 — a backfill path — but `memopayload.NewRunner` has no production caller (`server/server.go:162` constructs only the s3presign runner), so nothing invokes it.

**What's extracted** (`internal/markdown/markdown.go:356-421`):
- **`Tags`** — every `#tag` (custom `TagNode` from the tag extension), deduplicated with original case preserved via `uniquePreserveCase`.
- **`Property.Title`** — text of the document's first block-level child *if* it is an H1 heading (lines 383-389).
- **`Property.HasLink`** — any `gast.KindLink` node.
- **`Property.HasCode`** — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- **`Property.HasTaskList`** — any `east.KindTaskCheckBox`; and **`Property.HasIncompleteTasks`** when such a checkbox has `IsChecked == false`.

`ExtractAll` also collects `Mentions` (lowercased `@username`), but `RebuildMemoPayload` does not store them — mentions are consumed separately at request time by `server/router/api/v1/memo_mention_helpers.go:32` for notifications. `ExtractProperties` (`internal/markdown/markdown.go:193`) duplicates the property logic standalone but isn't on this path.

**Related but different: the preview snippet.** The `Memo.snippet` shown in list responses is *not* stored in the payload — it's computed per response by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-89`), called from the store→proto converter at `server/router/api/v1/memo_service_converter.go:76-80` (also used for relation previews at `memo_relation_service.go:154,162` and notification payloads at `user_service_notifications.go:323`). So tags/properties are persisted at write time, while the snippet is derived at read time.
