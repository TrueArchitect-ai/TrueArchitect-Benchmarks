How it fits together:

**Delivery path**
- Memo create/update/delete and comment-created events call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43` and `:71`, which only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:39`, `184-196`) and drops the event with a warning if the queue is full.
- Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, which is where the actual HTTP POST executes — building the request, adding Standard Webhooks HMAC-SHA256 headers when a signing secret is set (`webhook.go:133-150`), and issuing `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

**Protection against internal addresses** — two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against the parsed `reservedCIDRs` list covering IPv4 loopback, RFC-1918, link-local/cloud IMDS `169.254.0.0/16`, and the IPv6 equivalents (`validate.go:14-36`):
1. **At configuration time**: `ValidateURL` (`internal/webhook/validate.go:62`) requires an absolute http/https URL and rejects one whose hostname resolves to a reserved range. It's called when users add or update webhooks — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.
2. **At dial time** (the one that actually protects delivery): `safeClient` uses a `Transport` whose `DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`, `59-77`). It re-resolves the host on every connection and refuses to dial if any resolved IP is reserved — so it also defeats DNS rebinding, where a hostname passes `ValidateURL` and later re-resolves to a private address.

One caveat worth noting: `AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both layers when true, but grepping the tree shows nothing outside `validate.go` and the tests ever assigns it — there is no config/flag wiring, so it stays at its `false` default in a real deployment.
