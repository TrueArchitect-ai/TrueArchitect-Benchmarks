**Explicit Go code (per-driver `DeleteUser` transaction) — there is no database-level FK/cascade on the `reaction` table in any dialect.**

What I checked:

**1. The Go delete path.** `DeleteUser` opens one transaction and calls `deleteUserTargetsTx`, which removes reactions in *two* passes before the user row goes away:
- `deleteReactionsByContentIDsTx` — `DELETE FROM reaction WHERE content_id IN (...)` for every memo in the deleted user's memo tree (including comment descendants), i.e. *other people's* reactions on this user's content. sqlite `store/db/sqlite/user_delete.go:96` / impl `:380`; postgres `store/db/postgres/user_delete.go:96` / `:380`; mysql `store/db/mysql/user_delete.go:96` / `:417`.
- `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?`, i.e. *this user's* reactions anywhere, including on memos they don't own. sqlite `store/db/sqlite/user_delete.go:102` / impl `:400`; postgres `:102` / `:400`; mysql `:102` / `:437`.

Content IDs are derived as `"memos/" + memo.UID` (`store/db/sqlite/user_delete.go:512-518`), matching how reactions store `content_id`. Both deletes run inside the same tx that later removes memos and the user row (`store/db/sqlite/user_delete.go:120-125`, commit at `:51`).

**2. The schema — no cascade exists to do this implicitly.** The `reaction` table has no foreign key at all in any dialect: `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98` — each is just `id`, `created_ts`, `creator_id`, `content_id`, `reaction_type`, plus a `UNIQUE(creator_id, content_id, reaction_type)`. Grepping `REFERENCES|CASCADE` across `store/migration/` shows FKs on `memo_share`, `user_setting`, etc., but never on `reaction`. (Also note `content_id` is a text resource name, not an integer memo id, so an FK isn't even expressible here.)

Test coverage confirms the intent.** `server/router/api/v1/test/user_service_delete_test.go` seeds reactions from the target user and from a peer (`:188-209`) and asserts the deleted user's memo reactions are empty afterward (`:287-289`); `store/test/user_delete_test.go` covers the store layer.
