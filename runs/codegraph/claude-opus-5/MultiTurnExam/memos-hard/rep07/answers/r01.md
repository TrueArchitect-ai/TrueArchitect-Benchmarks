**Premise correction: there is no Redis anywhere in this repository** — no `redis` string in any file (`grep -rli "redis"` across the tree, excluding `node_modules`/`.git`, returns nothing), no Redis dependency in `go.mod`, and no external cache service in any compose/config file. The cache layer is a hand-rolled, in-process, in-memory cache, so there is no connection to configure.

**Actual mechanism:**

- **Implementation**: `store/cache/cache.go` — a `sync.Map`-backed `Cache` (`cache.go:66`) with per-item expiration (`item.expiration`, `cache.go:35-38`), an atomic item counter, and a background `cleanupLoop` goroutine started in `cache.New` (`cache.go:74-83`). It satisfies the `cache.Interface` declared at `store/cache/cache.go:11`.
- **Configuration site**: `store.New` — `store/store.go:38-53`. It builds one `cache.Config` inline and passes it to three separate cache instances: `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`, `:50-52`). Settings are hardcoded, not read from flags/env:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000` (over-limit inserts trigger `cleanupOldest`, `cache.go:116-118`)
  - `OnEviction: nil`

  The same values are duplicated in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), though `store.New` doesn't call it — it re-declares the literal.

- **TTL for user entries: 10 minutes.** Every write to the user cache goes through `Set` (`store/user.go:98`, `:122`, `:132`, `:143`, `:167`), which applies `c.config.DefaultTTL` (`store/cache/cache.go:90-92`). Nothing calls `SetWithTTL` for users, so there's no per-user override.

Two behavioral notes: entries are also invalidated eagerly rather than waiting out the TTL — `Store.UpdateUser` re-`Set`s the fresh row (`store/user.go:132`) and user deletion calls `userCache.Delete` (`store/user_delete.go:40`). And the cache only helps on ID lookups: `Store.GetUser` consults it only when `find.ID` is set (`store/user.go:149-156`), so username/email lookups always hit the database.
