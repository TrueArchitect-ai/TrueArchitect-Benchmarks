**1st: `store.User` — ~7 packages outside `store/`; 2nd: `store.Memo` — ~6 packages.**

Method: for each persistent entity struct declared in the data layer (`store/*.go` — `User`, `Memo`, `Attachment`, `Reaction`, `Inbox`, `MemoRelation`, `MemoShare`, `UserIdentity`, `UserSetting`, `InstanceSetting`, `IdentityProvider`; see `store/user.go:29`, `store/memo.go:35`, `store/attachment.go:16`, etc.), I counted distinct Go packages containing `store.<Type>` references, excluding the `store/` tree itself (which includes the driver packages `store/db/{sqlite,postgres,mysql}` and `store/test`) and generated `proto/`.

Full ranking:

| Type | Pkgs | Packages |
|---|---|---|
| **`User`** | **7** | `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss` |
| **`Memo`** | **6** | `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload` |
| `Attachment` | 4 | `server/router/api/v1`, `.../test`, `server/router/fileserver`, `server/router/rss` |
| `MemoShare` / `MemoRelation` / `Inbox` | 3 each | — |
| `UserIdentity` / `Reaction` | 2 each | — |
| `UserSetting` / `InstanceSetting` / `IdentityProvider` | 0 | consumers use the protobuf `storepb.*` forms instead |

Two caveats on the numbers:

- Counting only non-test packages the gap holds but narrows: `User` 6, `Memo` 5 — `server/router/api/v1/test` drops from both.
- `User` leads mainly because authentication touches it everywhere: it's the only entity used by `server/auth` (e.g. the authenticator resolving the caller) and by `server/router/fileserver` for avatar serving (`server/router/fileserver/fileserver.go:715`), on top of the API, RSS, frontend, and notification packages that also handle memos.
