Two things worth flagging:

- The rules differ by surface. `checkMemoReadAccess` (`memo_service.go:39`) treats PROTECTED as "any authenticated user" and additionally hides *archived* memos from non-creators; the file server instead keys the public short-circuit on `Profile.AllowAnonymous()` (`fileserver.go:677`) and accepts a valid `share_token` as an alternative to authentication (`fileserver.go:683-689`), which the API path does not.
- Memo *share* management (`server/router/api/v1/memo_share_service.go:43`, `:92`, `:133`) gates on creator/admin ownership rather than visibility, so I've excluded it from the list above — it controls who may create or revoke a share link, not who may view a memo.
