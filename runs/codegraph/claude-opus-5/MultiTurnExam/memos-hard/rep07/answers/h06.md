**Convergence.** All four `Dispatch*Webhook` methods (`memo_service_webhooks.go:15-46`) load the creator's configured webhooks via `s.Store.GetUserWebhooks`, stamp `payload.URL = hook.Url` from user configuration, and call `webhook.PostAsync` (`memo_service_webhooks.go:43` and `:71`). `PostAsync` only enqueues onto a 128-slot channel (`internal/webhook/webhook.go:184-196`); the four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain it and call **`webhook.Post`** — the single function where every path converges, and where the actual `safeClient.Do(req)` fires at `internal/webhook/webhook.go:152`.

Two notes on scope:
- Because delivery is queued and asynchronous, the HTTP request happens on a worker goroutine after the RPC returns — the handlers *cause* it but don't await it, and a full queue silently drops the event (`webhook.go:191-195`).
- If you count *any* user-supplied URL rather than user-*configured* webhooks, the AI service handlers in `server/router/api/v1/ai_service.go` and the link-preview fetcher in `internal/httpgetter` also make outbound requests, but those don't pass through `webhook.Post` and aren't driven by stored webhook configuration.
