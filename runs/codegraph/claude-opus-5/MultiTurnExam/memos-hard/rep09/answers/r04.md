**Premise correction: neither. There is no message broker in this repository — no NATS, no RabbitMQ, no AMQP, no Kafka. A case-insensitive grep for `nats|rabbitmq|amqp|kafka` across all Go sources and `go.mod` returns zero hits, so there is no queue declaration to point to.**

**Actual mechanism — an in-process buffered Go channel with a fixed worker pool, all in `internal/webhook/webhook.go`:**

- **The "queue"** is a package-level buffered channel holding 128 payloads: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`. It is created at package-variable initialization; there is no broker connection, no declaration step, and no configuration knob.
- **The "workers"** are four goroutines started in the package `init()` — `internal/webhook/webhook.go:42-55`. Each ranges over the channel and calls `Post(payload)`, logging a warning on failure. They live for the process lifetime; there is no shutdown path that drains them.
- **Producing** goes through `PostAsync` — `internal/webhook/webhook.go:184`. It is a non-blocking `select` with a `default` branch: if the buffer is full, the payload is **dropped** with a warning (lines 189-195), not retried or persisted.
- **Delivery** is `Post` — `internal/webhook/webhook.go:120` — which marshals the payload, optionally signs it (Standard Webhooks HMAC-SHA256 headers), and issues `safeClient.Do(req)` at line 152 with a 30-second timeout and the SSRF-guarding dialer.
- **Callers**: the memo webhook dispatchers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

Operational consequences that follow from this being a channel rather than a broker: delivery is at-most-once with no retry on failure (a non-2xx response just logs), the backlog is bounded at 128 and silently lossy beyond that, and everything is lost on process restart since nothing is persisted. Queue depth and worker count are compile-time constants, not settings.
