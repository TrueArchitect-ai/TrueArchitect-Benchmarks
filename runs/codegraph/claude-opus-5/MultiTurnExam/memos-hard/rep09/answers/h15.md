Distinct enforcement sites, grouped by surface:

**gRPC/Connect API (`server/router/api/v1/`)**
```
checkMemoReadAccess (single-memo read gate: GetMemo, GetMemoByUid/parent, ListMemoComments) — server/router/api/v1/memo_service.go:39 (called at :356, :367 and memo_service_comments.go:148)
ListMemos query-scoping (anonymous → PUBLIC only; authed → own-creator OR PUBLIC/PROTECTED filter) — server/router/api/v1/memo_service.go:218-227
CreateMemoComment gate on the parent memo — server/router/api/v1/memo_service_comments.go:41 (plus comment-visibility rule at :100)
Reaction gates (upsert and delete) — server/router/api/v1/reaction_service.go:38 and :83
ListMemoAttachments gate — server/router/api/v1/memo_attachment_service.go:222
Attachment access check (linked attachment inherits parent memo visibility) — server/router/api/v1/attachment_service.go:445-452
```

**HTTP file server (`/file/...`, Echo, outside gRPC)**
```
checkAttachmentPermission — server/router/fileserver/fileserver.go:677 (PUBLIC + anonymous allowed), :684-690 (share-token bypass), :699 (PRIVATE → creator or admin)
```

**SSE broadcast fan-out**
```
SSEClient.canReceive — server/router/api/v1/sse_hub.go:134 (per-subscriber filter; PRIVATE events go only to creator or admin), fed by sse_event_helpers.go:29-37
```

**Public/unauthenticated read surfaces (store-query scoping)**
```
RSS feeds (instance + per-user) — server/router/rss/rss.go:90 and :141 (VisibilityList = PUBLIC)
Sitemap XML — server/router/frontend/frontend.go:150 (VisibilityList = PUBLIC)
```

**Notification/mention side channels** (visibility decides whether a user is told a memo exists)
```
Mention-target eligibility — server/router/api/v1/memo_mention_helpers.go:62, :67
Email notification gating — server/router/api/v1/user_service_notifications.go:309-312 and server/notification/email.go:313-316
```

Two cross-cutting notes: the enforcement rules are not identical across sites — `checkMemoReadAccess` (memo_service.go:39) additionally hides **archived** memos from non-creators and returns `Unauthenticated` for anonymous access to non-public memos, whereas the fileserver path (fileserver.go:677) grants anonymous access to PUBLIC memos only when `Profile.AllowAnonymous()` and accepts a `share_token` query param as a bypass for PRIVATE/PROTECTED memos; the API-side attachment check (attachment_service.go:445) has no share-token equivalent. And `store.Protected` is never rejected outright by the single-memo gates — it only requires *some* authenticated user, so any logged-in account can read a PROTECTED memo.
