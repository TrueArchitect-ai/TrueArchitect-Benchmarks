**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard at dial time via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path.** Memo create/update/delete events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:39`, `184`) and drops with a warning when full. Four goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, which is where the outbound HTTP request actually executes — it marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, lines 133-150), and issues `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

**Protection.** Two layers:

1. *Dial-time (the real enforcement)*: `safeClient` is an `http.Client` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (line 59) resolves the hostname itself and refuses the connection if **any** resolved IP is in a reserved range. Because the check happens per-dial rather than at save time, it also covers redirects and DNS-rebinding attacks — the comment at lines 30-31 says exactly this.
2. *Save-time validation*: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`), returning a gRPC `InvalidArgument`.

Both share `isReservedIP` (`internal/webhook/validate.go:44`) against the `reservedCIDRs` list (lines 14-23): IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (cloud IMDS), plus `::1/128`, `fc00::/7`, `fe80::/10`. The list is parsed once into `reservedNetworks` at package init (lines 28-36).

**Escape hatch**: the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling both layers for self-hosted deployments targeting LAN services. Note it is declared but never assigned anywhere in non-test code — no CLI flag or config setting currently wires it up, so it is effectively always `false` in production.
