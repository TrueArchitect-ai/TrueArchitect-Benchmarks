**Explicit Go code — two explicit `DELETE FROM reaction` statements inside the per-driver `DeleteUser` transaction. There is no database-level rule (no FK/cascade on the `reaction` table).**

Evidence locations:

**1. The explicit deletes.** Each driver's `deleteUserTargetsTx` calls two reaction cleanups within one transaction:

- `deleteReactionsByContentIDsTx` — removes reactions *on* the user's memos (and their comment subtree), batched 500 at a time: `store/db/sqlite/user_delete.go:379`, `store/db/postgres/user_delete.go:383`, `store/db/mysql/user_delete.go:420`.
- `deleteReactionsByCreatorTx` — removes reactions the user *left on other people's* memos: `store/db/sqlite/user_delete.go:398`, `store/db/postgres/user_delete.go:401`, `store/db/mysql/user_delete.go:438`.

Both are invoked from the ordered cleanup list in `deleteUserTargetsTx` (sqlite `store/db/sqlite/user_delete.go:88-122`; same shape in the other two drivers), which runs inside the transaction opened by `DeleteUser` (`store/db/sqlite/user_delete.go:29`, `store/db/postgres/user_delete.go:29`, `store/db/mysql/user_delete.go:29`).

The content-ID join is by string, not integer FK: `memoContentIDsFromRefs` builds `"memos/" + memo.UID` values to match `reaction.content_id` (`store/db/sqlite/user_delete.go` — `memoContentIDsFromRefs`), and the memo set comes from a recursive CTE that walks `memo_relation` COMMENT edges so comment threads are included (`listDeleteUserMemoTreeRecursive`).

**2. No DB-level rule.** The `reaction` table is declared with no foreign keys at all in any dialect — `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98` list only `id`, `created_ts`, `creator_id`, `content_id`, `reaction_type`, and a `UNIQUE(creator_id, content_id, reaction_type)`. A repo-wide `grep -rni "foreign key\|on delete" store/migration` returns cascades for `memo_share`, `user_setting`, `memo_relation`, etc., but never for `reaction`. That's structurally unavoidable here: `content_id` is a text string (`"memos/<uid>"`), so it can't be a foreign key to `memo(id)` even in principle.

**3. Entry point.** `APIV1Service.DeleteUser` (`server/router/api/v1/user_service.go:414`) and the SSO rollback path (`server/router/api/v1/auth_service_sso.go:77`) both route through `store.DeleteUser` (`store/user.go:171`) → the driver interface method (`store/driver.go:48`), so every deletion path hits this code.
