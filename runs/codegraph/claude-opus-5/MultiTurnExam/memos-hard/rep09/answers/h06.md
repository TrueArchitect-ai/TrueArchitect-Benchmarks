**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`; convergence function — `webhook.Post`, `internal/webhook/webhook.go:120`** (all six enqueue through the single call site `webhook.PostAsync`, `internal/webhook/webhook.go:184`, whose worker pool then calls `Post` — the only place an outbound request is actually issued).

| Handler | Path to dispatch |
|---|---|

The last three of those funnel through `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`) → `DispatchMemoUpdatedWebhook`.

Convergence chain: the four `Dispatch*Webhook` methods (`memo_service_webhooks.go:15`, `:20`, `:25`, `:30`) all resolve the target user's webhooks via `s.Store.GetUserWebhooks`, set `payload.URL = hook.Url` — the user-configured URL from their webhook settings — and call `webhook.PostAsync` (`memo_service_webhooks.go:43` and `:71`). `PostAsync` only enqueues onto a 128-slot channel; four worker goroutines started in the package `init()` (`internal/webhook/webhook.go:42-55`) drain it and call **`webhook.Post`**, which builds the request, signs it, and issues `safeClient.Do` at `internal/webhook/webhook.go:152`.

Note the RPCs are reachable over both gRPC and Connect — `ConnectServiceHandler` wraps the same `APIV1Service` methods (`server/router/api/v1/connect_services.go`) — but the Go handler methods above are the single implementation.
