Notes on each hop:

- **`serveUserAvatar`** (`fileserver.go:168`) first gates access: on a private instance (`!s.Profile.AllowAnonymous()`) it requires a session/access token/PAT via `s.getCurrentUser`, returning 401 otherwise (lines 173-181). Anonymous reads are allowed only on public instances.
- **`getUserByUsername`** (`fileserver.go:715`) is a one-line wrapper: `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`. The `:identifier` path param is matched against `username`, not ID.
- **`Store.GetUser`** (`store/user.go:148`) has a cache fast path, but it only applies when `find.ID != nil`. Because this lookup is by username, it always falls through to `ListUsers`; the row fetched is then written into `userCache` keyed by ID (line 167).
- **`Store.ListUsers`** (`store/user.go:136`) delegates to `s.driver.ListUsers` and warms the cache for every returned row.
- **Data layer**: the driver-specific `ListUsers` builds the `WHERE username = ?` clause and queries the `user` table (`store/db/sqlite/user.go:88`, plus the postgres/mysql equivalents; the concrete driver is chosen by `NewDBDriver` in `store/db/db.go:14`).

After the data hop, the handler doesn't read a file or object store — the avatar bytes live in the user row itself. `user.AvatarURL` is a data URI, decoded by `s.parseDataURI` (`fileserver.go:196`), checked against `avatarAllowedTypes` (PNG/JPEG/GIF/WebP only, `fileserver.go:75,201`) to block XSS-capable types like SVG, then written with security headers and a cache-control max-age via `c.Blob` (`fileserver.go:205-209`).
