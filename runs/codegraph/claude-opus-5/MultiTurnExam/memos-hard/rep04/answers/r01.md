**Premise correction: there is no Redis anywhere in this repo.** A case-insensitive grep for `redis` across all Go sources, `go.mod`, YAML, and Markdown returns zero hits — no client dependency, no connection string, no config flag. The cache layer is purely in-process.

**Actual mechanism.** It's a hand-rolled in-memory cache in `store/cache/cache.go`: a `Cache` struct backed by a `sync.Map` plus an atomic item counter (`store/cache/cache.go:66-73`), created by `cache.New(config)` (line 75). It implements the `cache.Interface` declared at `store/cache/cache.go:11`, with a background cleanup goroutine that `Close()` stops (line 187).

Three instances are created in `store.New` — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`) — all sharing one config literal defined inline at `store/store.go:39-44`:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`
- `OnEviction: nil`

**TTL for user entries: 10 minutes.** Every user write goes through `s.userCache.Set(...)` (`store/user.go:98, 122, 132, 143, 167`), and `Set` forwards to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:94`). Nothing in the store calls `SetWithTTL` directly, so the 10-minute default is the only TTL user entries ever get. Expiry is enforced lazily on read — `Get` deletes and misses when `time.Now().After(itm.expiration)` (`store/cache/cache.go:134`) — plus the periodic sweep every 5 minutes and an LRU-ish `cleanupOldest()` when the 1000-item cap is exceeded (`store/cache/cache.go:117-119`).

Note the same values are duplicated in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), but `store.New` builds its own literal rather than calling it, so changing `DefaultConfig` alone would not affect user caching.

One consequence worth knowing: because this is per-process memory, running multiple memos instances behind a load balancer gives each its own cache with no invalidation across them — the deliberate mitigation being that writes update the local cache immediately and entries age out within 10 minutes.
