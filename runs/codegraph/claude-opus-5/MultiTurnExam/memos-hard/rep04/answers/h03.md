**`internal/idp` (abstraction) — `internal/idp/idp.go`; `internal/idp/oauth2` (implementation) — `internal/idp/oauth2/oauth2.go`**

Details:

- **Abstraction**: `internal/idp/idp.go` is the whole package — it defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider must normalize its user profile into. It's a data contract rather than a Go `interface`; there is no `Provider` interface declared.
- **Implementation**: `internal/idp/oauth2/oauth2.go` — the only concrete protocol that ships. It provides `NewIdentityProvider(*storepb.OAuth2Config)` (`oauth2.go:27`), `ExchangeToken` for the authorization-code exchange including PKCE `codeVerifier` support (`oauth2.go:47`), and `UserInfo` which maps the provider's response back into `idp.IdentityProviderUserInfo` via the configured field mapping (`oauth2.go:83`).
- **Consumer**: `server/router/api/v1/auth_service_sso.go` is the sole caller — `resolveSSOIdentity` (line 104) switches on the provider config and constructs the OAuth2 provider at line 121, then `resolveSSOUser` (line 19) provisions/links the local account.
- **Corroborating**: the API enum has exactly one non-unspecified value, `OAUTH2 = 1` (`proto/api/v1/idp_service.proto:79`), so OAuth2/OIDC-style flow is the only supported protocol — no SAML or LDAP implementation exists in the tree.
