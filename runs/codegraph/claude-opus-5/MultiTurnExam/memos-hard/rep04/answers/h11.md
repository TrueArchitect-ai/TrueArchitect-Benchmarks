**1st: `store.User` — ~7 packages outside the store layer; 2nd: `store.Memo` — ~6 packages**

Method: I counted distinct Go packages (directories) outside `store/` and its `store/db/*` + `store/test` subpackages that reference each entity type as `store.<Type>`.

**1st — `store.User`** (`store/user.go:29`), referenced from 7 packages:
- `server/auth` — session/token subject resolution
- `server/notification`
- `server/router/api/v1` — the bulk of the API surface
- `server/router/api/v1/test`
- `server/router/fileserver` — e.g. `getUserByUsername` returning `*store.User` (`server/router/fileserver/fileserver.go:715`)
- `server/router/frontend`
- `server/router/rss`

**2nd — `store.Memo`** (`store/memo.go:35`), referenced from 6 packages:
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/frontend`
- `server/router/rss`
- `server/runner/memopayload` — e.g. `RebuildMemoPayload(_ context.Context, memo *store.Memo, ...)` (`server/runner/memopayload/runner.go:74`)

Runners-up for context: `store.Attachment` (`store/attachment.go:16`) at 4 packages (`api/v1`, `api/v1/test`, `fileserver`, `rss`); `store.MemoShare` and `store.MemoRelation` at 3 each; `store.Inbox`, `store.Reaction`, `store.UserIdentity` at 2–3.

Two notes on the counting: if you exclude the `server/router/api/v1/test` package as non-production, the ranking is unchanged (User 6, Memo 5). And types like `store.IdentityProvider`, `store.UserSetting`, and `store.InstanceSetting` look artificially low here because the API layer works with their protobuf forms (`storepb.*` from `proto/gen/store`) rather than the store structs — the store structs mostly stay inside the driver packages.
