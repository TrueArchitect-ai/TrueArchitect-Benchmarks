**`(*sqlite.DB).CreateMemo` — `store/db/sqlite/memo.go:16` (the `INSERT INTO \`memo\` ...` at line 41); determination: traced the runtime driver-selection chain from the CLI default `driver=sqlite` through the one place the interface is bound to a concrete type.**

The concrete SQL execution is at `store/db/sqlite/memo.go:41-49` — it builds the field/placeholder lists, marshals `payload` to protojson, and runs `d.db.QueryRowContext(ctx, stmt, args...)` with `INSERT INTO memo (...) VALUES (...) RETURNING id, created_ts, updated_ts, row_status`.

How I determined it's the sqlite one and not postgres/mysql:

1. **The default is sqlite, and it comes from two independent places in the CLI.** `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the flag's own default value in `rootCmd.PersistentFlags().String("driver", "sqlite", "database driver")` (`cmd/memos/main.go:130`). With no `--driver` flag and no `MEMOS_DRIVER` env var (`viper.SetEnvPrefix("memos")` + `AutomaticEnv`, lines 167-169), `viper.GetString("driver")` returns `"sqlite"`, which is assigned to `Profile.Driver` at `cmd/memos/main.go:43`.

2. **The interface is bound to a concrete type in exactly one place.** `db.NewDBDriver(instanceProfile)` is called at `cmd/memos/main.go:57`, and its body (`store/db/db.go:14-25`) is a plain switch on `profile.Driver`: `"sqlite"` → `sqlite.NewDB(profile)` (`store/db/db.go:20`). That returned `store.Driver` is handed to `store.New(dbDriver, instanceProfile)` at `cmd/memos/main.go:64` and never reassigned. This is the same single-construction-site fact established in h04 — each `NewDB` is reachable only through this switch.

3. **The call path to the insert is a straight delegation.** The `CreateMemo` RPC handler (`server/router/api/v1/memo_service.go:70`) calls `s.Store.CreateMemo`, which validates the UID against `base.UIDMatcher` and then does `return s.driver.CreateMemo(ctx, create)` (`store/memo.go:109-114`). `s.driver` is the interface field holding the value from step 2, so the dynamic dispatch resolves to the sqlite implementation.

4. **Ruling out the other candidates.** `CreateMemo` is declared on all three drivers — `store/db/sqlite/memo.go:16`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go` — all satisfying `store.Driver` (`store/driver.go`). They're unreachable in a default install because the switch never selects them; reaching postgres or mysql requires explicitly passing `--driver` (or `MEMOS_DRIVER`) plus a `--dsn`, and `sqlite.NewDB` itself errors out with `"dsn required"` if the DSN is empty (`store/db/sqlite/sqlite.go:25-27`).

One implementation detail worth noting: the sqlite driver is `modernc.org/sqlite`, registered via `functions.go` rather than a blank import in `sqlite.go` (see the comment at `store/db/sqlite/sqlite.go:9-10`), because the code also registers custom scalar functions (`ensureUnicodeLowerRegistered`, `ensureRegexpRegistered` at lines 29-35).
