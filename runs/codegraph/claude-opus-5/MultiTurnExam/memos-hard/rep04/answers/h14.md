**Computation site: `RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, which delegates to `(*service).ExtractAll` — `internal/markdown/markdown.go:356`; Triggers: `CreateMemo` and `UpdateMemo` (content-path only); Extracted: `Tags` plus the `Property` set — `title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`.**

**Where it's computed.** `RebuildMemoPayload(_ context.Context, memo *store.Memo, markdownService markdown.Service)` (`server/runner/memopayload/runner.go:74`) initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (lines 85-86). Those two assignments are the *only* writes to `Payload.Tags`/`Payload.Property` in the entire backend. The real work is one goldmark AST walk in `ExtractAll` (`internal/markdown/markdown.go:356`).

**Triggers — exactly two production call sites**, both in `server/router/api/v1/memo_service.go`:
- `CreateMemo` — line 108, after the content-length check and before `s.Store.CreateMemo`.
- `UpdateMemo` — line 447, inside the `path == "content"` branch of the field-mask loop; the result is written through as `update.Payload = memo.Payload` (line 451). Other update paths (`visibility`, `pinned`, etc.) don't recompute, which is correct since nothing but content affects the derived values.

Note that `Payload.Location` is *not* derived — it's set separately from the user's request (`memo_service.go:110-112`), which is why `RebuildMemoPayload` only overwrites `Tags` and `Property`.

There's also a batch recompute path, `(*memopayload.Runner).RunOnce` (`server/runner/memopayload/runner.go:27`), which walks all memos in batches of 100 and rebuilds each — but as established in h08 it has no caller, so it never runs.

**What `ExtractAll` extracts** (`internal/markdown/markdown.go:356-420`), in a single `gast.Walk`:
- **Tags** — from custom `TagNode`s (`#tag` syntax), deduplicated with original case preserved via `uniquePreserveCase`.
- **Mentions** — `@username`, lowercased and deduped. Collected into `ExtractedData` but *discarded* by `RebuildMemoPayload`; they're used separately for notifications (`server/router/api/v1/memo_mention_helpers.go:32` calls `ExtractAll` directly).
- **`Property.Title`** — text of the first block-level child if it's an H1 heading.
- **`Property.HasLink`** — any `gast.KindLink` node.
- **`Property.HasCode`** — any code block, fenced code block, or code span.
- **`Property.HasTaskList`** — any task checkbox; and **`Property.HasIncompleteTasks`** if any checkbox is unchecked.

The proto definition is `MemoPayload.Property` (`proto/store/memo.proto:15-22`).

**Consumers** (the "lists/previews" use): `convertMemoFromStoreWithCreators` copies `Tags` and `Property` onto the API `Memo` message (`server/router/api/v1/memo_service_converter.go:48-49`), and the user-stats endpoint aggregates tag counts and the four booleans (`server/router/api/v1/user_service_stats.go:138-151, 254-267`).
