**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection: SSRF-guarded dialer `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

- **Trigger → delivery**: memo create/update/delete call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43,71`), which enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:39`) drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`). Each worker calls `Post`, which marshals the payload, optionally adds Standard Webhooks HMAC headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, lines 133-150), and does the POST with a 30s-timeout shared client.
- **Primary protection (dial time)**: `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37,59-77`). It resolves the hostname itself and refuses the connection if *any* resolved IP is reserved. Because the check happens at dial time rather than at config time, it also defeats DNS rebinding — the comment at `webhook.go:29-31` says as much.
- **Secondary protection (config time)**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user saves a webhook, called from `server/router/api/v1/user_service_webhooks.go:74,161,182`.
- **Blocked ranges**: `reservedCIDRs` in `internal/webhook/validate.go:14-23` — IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), and the IPv6 equivalents (`::1/128`, `fc00::/7`, `fe80::/10`), parsed once in `init()` (`validate.go:28-36`).
- **Escape hatch**: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` for self-hosted setups. Note that in this working tree nothing outside the package's own tests assigns it — the `--allow-private-webhooks` flag mentioned in `CHANGELOG.md:121` has no corresponding wiring in the current Go sources, so the guard is effectively always on at runtime.
