All four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go`; three of them delegate to the shared `dispatchMemoRelatedWebhook` (line 48), and the comment variant has its own loop (line 30) because it targets the *parent* memo owner's hooks rather than the actor's. Each loads the recipient's configured hooks via `s.Store.GetUserWebhooks`, sets `payload.URL = hook.Url` (the user-configured URL), and calls `webhook.PostAsync` — line 71 and line 43 respectively. Those two call sites are the only `PostAsync` callers in the server.

`PostAsync` enqueues onto a 128-slot buffered channel drained by four worker goroutines started in `init()` (`internal/webhook/webhook.go:39-55`), each of which calls `Post` — so `Post` is where the HTTP request is actually issued, via the SSRF-guarded `safeClient` at line 152.

One near-miss worth ruling out: `CreateUserWebhook`/`UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:74,161,182`) touch the user-supplied URL but only call `webhook.ValidateURL`, which does a DNS resolution — no outbound HTTP.
