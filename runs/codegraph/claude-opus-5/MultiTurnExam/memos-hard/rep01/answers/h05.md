**Explicit Go code — two hand-written `DELETE FROM reaction` statements per driver, inside the delete-user transaction. There is no database-level cascade for reactions.**

Evidence:

**1. Explicit Go deletes (all three drivers, same shape)**

Inside `deleteUserTargetsTx`, reactions are removed twice — once by the memos being deleted, once by the user's own reactions on *other* people's memos:

- SQLite: `store/db/sqlite/user_delete.go` — `deleteReactionsByContentIDsTx` (`DELETE FROM reaction WHERE content_id IN (...)`, batched at 500) and `deleteReactionsByCreatorTx` (`DELETE FROM reaction WHERE creator_id = ?`), called from `deleteUserTargetsTx`.
- Postgres: `store/db/postgres/user_delete.go:96` and `:102`, implementations at `:380` and `:400`.
- MySQL: `store/db/mysql/user_delete.go:96` and `:102`, implementations at `:417` and `:437`.

The `content_id` values come from `memoContentIDsFromRefs`, which builds `"memos/" + memo.UID` for every memo in the recursive memo tree (the user's memos plus descendant comments) — that's how reactions on the deleted user's content by *other* users get cleaned up. All of it runs in one `tx` opened in `DeleteUser` and committed at the end, so it's atomic with the `DELETE FROM user` row removal.

**2. No DB-level rule to fall back on**

The `reaction` table has no foreign key at all — `creator_id` and `content_id` are plain `INTEGER`/`TEXT` columns with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint:

- `store/migration/sqlite/LATEST.sql:91-99`
- `store/migration/postgres/LATEST.sql:90-98`
- `store/migration/mysql/LATEST.sql:91-98`
- Original creation: `store/migration/{sqlite,postgres,mysql}/0.20/00__reaction.sql`

Grepping `CASCADE|REFERENCES|FOREIGN KEY` across `store/migration/` shows cascades exist for other tables (e.g. `memo_share` → `memo` in `store/migration/*/0.27/04__memo_share.sql`, and the older `0.5/00__regenerate_foreign_keys.sql` set), but `reaction` never appears among them. Note also `content_id` is a string key (`memos/<uid>`), which couldn't participate in a FK to `memo(id)` anyway — so the Go code is the only mechanism.
