**`webhook.Post` — `internal/webhook/webhook.go:120`; dial-time reserved/private-IP blocking via `safeDialContext` on the shared `safeClient` transport — `internal/webhook/webhook.go:59` (ranges + check in `internal/webhook/validate.go:14-54`)**

How it fits together:

- **Trigger**: memo change events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which just enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:184`) and drops with a warning when full.
- **Actual delivery**: four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post` (`:120`), which marshals the payload, adds Standard Webhooks HMAC-SHA256 headers when a signing secret is set, and issues the request through `safeClient.Do` (`:152`).
- **SSRF protection (enforcement point)**: `safeClient` is built with `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`:59`) resolves the hostname itself and refuses the connection if *any* resolved address is reserved, then dials the host — done at dial time specifically so DNS rebinding can't slip past a pre-flight check.
- **Reserved ranges**: `reservedCIDRs` / `isReservedIP` in `internal/webhook/validate.go:14-54` — IPv4 loopback, RFC-1918, link-local (incl. 169.254.169.254 IMDS), and IPv6 loopback/ULA/link-local.
- **Secondary, config-time check**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hosts when a webhook is created or updated (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`).
- **Escape hatch**: the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) disables both checks, but grep shows nothing outside tests assigns it — no CLI flag or profile setting wires it up, so it is effectively always `false` in production builds.
