**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive grep for `redis` across all Go sources, `go.mod`, and YAML config returns zero hits — no client dependency, no connection string, no config flag. The cache layer is entirely in-process.

**Actual mechanism**

- **Implementation**: a hand-rolled, thread-safe in-memory cache in `store/cache/cache.go` — a `sync.Map` of `item{value, expiration, size}` behind the `cache.Interface` (`store/cache/cache.go:11`), with a background cleanup goroutine and a `MaxItems` eviction path (`cleanupOldest`). State is per-process and lost on restart; nothing is shared across instances.
- **Configuration site**: `store.New` in `store/store.go:36-59`. The config is a literal built inline at `store/store.go:40-45` — it is not read from flags, env, or a config file:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  Three separate `cache.New(cacheConfig)` instances are created from it — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`). The same values are also the package defaults in `cache.DefaultConfig()` (`store/cache/cache.go:57`), though `store.New` doesn't call it.
- **TTL for user entries: 10 minutes.** Every user write goes through `s.userCache.Set(...)` (`store/user.go:98`, `:122`, `:132`, `:143`, `:167`), and `Set` forwards the config default: `c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)` at `store/cache/cache.go:94`. Nothing in the store calls `SetWithTTL` directly, so users get exactly the 10-minute default — with no per-entity override. Expiry is lazy-plus-sweep: `Get` drops an entry whose `expiration` has passed (`cache.go:135`), and the cleanup loop sweeps every 5 minutes.
- **Lifecycle**: all three caches are shut down via `Store.Close` (`store/store.go:72-78`), reached from `Server.Shutdown` at `server/server.go:146`.
