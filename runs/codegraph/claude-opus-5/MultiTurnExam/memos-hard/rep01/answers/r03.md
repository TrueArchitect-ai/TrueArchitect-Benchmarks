**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never started in the server — so there is no scheduled time to report.**

Two separate parts of the premise are wrong:

**1. The cron scheduler exists but is entirely unused in production.** `internal/scheduler/` is a complete, tested cron implementation (`scheduler.New` at `internal/scheduler/scheduler.go:54`, `Register`, `ParseCronExpression` at `internal/scheduler/parser.go`, middleware at `internal/scheduler/middleware.go`). But grepping for importers of `github.com/usememos/memos/internal/scheduler` outside the package itself returns nothing, and every call to `scheduler.New(...)` / `.Register(...)` is in `internal/scheduler/example_test.go` and `internal/scheduler/scheduler_test.go`. No cron expression is registered anywhere in `server/` or `cmd/`, so no job — nightly or otherwise — is scheduled.

**2. There is no database-cleanup/vacuum/prune job at all.** Grepping for `cleanup|vacuum|prune|purge` across `server/`, `store/`, and `cmd/` turns up only:
- **Cache** eviction, not database: `cleanupLoop` / `cleanupOldest` in `store/cache/cache.go:83`, `:118`, running on the in-memory cache's 5-minute `CleanupInterval` (`store/store.go:42`).
- **Transactional, event-driven** deletion, not scheduled: attachment/relation cleanup during `DeleteMemo` (`server/router/api/v1/memo_service.go:579`), S3 object cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`), and best-effort SSO row cleanup (`server/router/api/v1/auth_service_sso.go:76`).

**What actually runs on a schedule in the server**: exactly one background runner, and it doesn't use the cron package. `Server.startBackgroundRunners` (`server/server.go:153-174`) starts the S3 presign runner — one immediate `RunOnce(ctx)` at `server/server.go:163`, then a `time.Ticker` loop every 12 hours (`runnerInterval` at `server/runner/s3presign/runner.go:27`). It refreshes presigned attachment URLs; it deletes nothing.
