**Premise correction: neither. There is no message broker in this repository at all — no NATS, RabbitMQ/AMQP, Kafka, SQS, or pub/sub client. A case-insensitive grep for `nats|rabbitmq|amqp|kafka|streadway|sqs|pubsub` across all Go sources, `go.mod`, and YAML config returns zero hits. There is no queue declaration to point at, because there is no external queue.**

**Actual mechanism — an in-process Go channel with a fixed worker pool, all in `internal/webhook/webhook.go`:**

- **The "queue"**: a package-level buffered channel, `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39`. Capacity 128, in-memory only — nothing is persisted, so anything still queued is lost on process exit.
- **The workers**: four goroutines started in the package `init()` at `internal/webhook/webhook.go:42-55`. Each ranges over `asyncPostQueue` and calls `Post(payload)`, logging a warning on failure. There is no retry and no dead-letter path — a failed delivery is logged and dropped.
- **The producer**: `PostAsync` at `internal/webhook/webhook.go:184` does a non-blocking `select` send onto the channel. If the buffer is full, the `default` branch **drops the event** with a `slog.Warn("Dropped webhook dispatch because the async queue is full", ...)` — backpressure is shed, not applied. Callers are the memo lifecycle handlers via `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.
- **Delivery**: `Post` at `internal/webhook/webhook.go:120` marshals the payload, adds Standard Webhooks HMAC-SHA256 headers when a signing secret is configured, and POSTs through the shared `safeClient` (30s timeout, SSRF-guarded dialer) at line 152.

Practical consequence of there being no broker: dispatch is best-effort and single-process. Nothing survives a restart, nothing is retried, and in a multi-replica deployment each replica has its own independent 128-slot channel and four workers.
