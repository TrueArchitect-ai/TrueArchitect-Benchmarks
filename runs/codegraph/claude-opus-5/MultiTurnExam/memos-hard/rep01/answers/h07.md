Notes on the hops:

- **Wiring**: the file server is constructed and its routes registered before the gRPC gateway, at `server/server.go:81-82`.
- **Access control**: `serveUserAvatar` only requires auth when `s.Profile.AllowAnonymous()` is false (`fileserver.go:173-181`) — it authenticates via `authenticator.AuthenticateToUser` (Bearer access token/PAT, else refresh-token cookie). There is no per-user check: any authenticated viewer (or anyone at all on a public instance) may fetch any user's avatar.
- **Lookup key**: the `:identifier` path param is treated as a username only — `store.FindUser{Username: &identifier}` (`fileserver.go:716`); IDs are not accepted here.
- **Where the bytes live**: the image is not a file on disk or in S3. It's stored inline on the user row in the `avatar_url` column as a base64 data URI (`store/db/sqlite/user.go:14`, `:159`), read into `store.User.AvatarURL`, then split into MIME type + decoded bytes by `parseDataURI` and gated against `avatarAllowedTypes` (`fileserver.go:75`, checked at `:201`) before `c.Blob` writes it with security and `Cache-Control` headers.
- **Cache layer**: `Store.GetUser` consults `s.userCache` only when looking up by ID; a username lookup always falls through to `ListUsers` → driver SQL, and results are then populated into the cache (`store/user.go:142-144`, `:167`).
