Visibility is enforced across five surfaces — the gRPC/Connect API, the HTTP file server, the SSE broadcast hub, the RSS/sitemap routes, and the notification-targeting logic. Distinct enforcement sites:

**gRPC/Connect API (`server/router/api/v1/`)**
```
checkMemoReadAccess (shared read gate: archived + non-public + private) — server/router/api/v1/memo_service.go:39 (visibility branch at :55-65)
ListMemos (query-level filter: VisibilityList = [PUBLIC] anon / [PUBLIC,PROTECTED] others) — server/router/api/v1/memo_service.go:219-225
ListAllUserStats / GetUserStats (same VisibilityList narrowing) — server/router/api/v1/user_service_stats.go:84-90 (and :254 region)
checkAttachmentAccess (memo-visibility gate for attachments) — server/router/api/v1/attachment_service.go:445-451
ListMemoAttachments — server/router/api/v1/memo_attachment_service.go:214-222
ListMemoReactions — server/router/api/v1/reaction_service.go:30-38
UpsertMemoReaction — server/router/api/v1/reaction_service.go:83
CreateMemoComment (private parent memo) — server/router/api/v1/memo_service_comments.go:41
```

**HTTP file server (`server/router/fileserver/`)**
```
checkAttachmentPermission (public+anonymous shortcut, share-token fallback, private check) — server/router/fileserver/fileserver.go:650 (checks at :677 and :699)
```

**SSE broadcast (`server/router/api/v1/`)**
```
SSEClient.canReceive (per-connection delivery filter; PRIVATE → creator or admin only, unknown value denied) — server/router/api/v1/sse_hub.go:134-143 (event visibility populated at server/router/api/v1/sse_event_helpers.go:29-37)
```

**Public unauthenticated feeds (`server/router/rss/`, `server/router/frontend/`)**
```
GetExploreRSS (VisibilityList = [PUBLIC]) — server/router/rss/rss.go:90
GetUserRSS (VisibilityList = [PUBLIC]) — server/router/rss/rss.go:141
getSitemapXML (VisibilityList = [PUBLIC]) — server/router/frontend/frontend.go:150
```

**Notification targeting (who may be told about a memo)**
```
canViewerAccessMemo (mention/comment notifications) — server/router/api/v1/user_service_notifications.go:309-316
canViewerAccessMemo (email notifications) — server/notification/email.go:313-316
canUserAccessMentionContext — server/router/api/v1/memo_mention_helpers.go:62-84
```

Two structural notes: the checks come in two flavors — *post-fetch gates* that reject an already-loaded memo (`checkMemoReadAccess`, `checkAttachmentPermission`, `canReceive`) and *pre-query filters* that narrow `store.FindMemo.VisibilityList` so restricted rows are never read (`ListMemos`, stats, RSS, sitemap). Also, `server/router/fileserver/fileserver.go:684-690` is the one place where a valid non-expired `share_token` bypasses the private/protected check for a specific memo's attachments; the last two entries under notification targeting are duplicate implementations of the same `canViewerAccessMemo` predicate in two packages.
