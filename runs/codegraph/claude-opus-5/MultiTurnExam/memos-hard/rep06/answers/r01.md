**Premise correction: there is no Redis anywhere in this repository.** No Redis client dependency in `go.mod`, no `redis` import, no connection string, no config flag — a case-insensitive grep for "redis" across all Go, mod, YAML, and Markdown files (excluding `web/`) returns zero hits. The cache layer is a hand-rolled, process-local in-memory cache; nothing is shared across instances.

**Actual mechanism:**

- The cache implementation is `store/cache/cache.go` — a `sync.Map`-backed `Cache` (`store/cache/cache.go:66`) with per-item expiry, an atomic item counter, a `MaxItems` eviction bound, and a background cleanup goroutine. It satisfies the local `cache.Interface` (`store/cache/cache.go:11-32`).
- Configuration is a plain Go struct literal in `store.New` — `store/store.go:38-44` — not external config: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, `OnEviction: nil`. The same `cacheConfig` is used to construct all three caches at `store/store.go:50-52`: `instanceSettingCache`, `userCache`, `userSettingCache` (fields at `store/store.go:27-29`). `cache.DefaultConfig()` (`store/cache/cache.go:57`) happens to carry identical values but isn't the one used here.
- **TTL for user entries: 10 minutes.** Every user write goes through `s.userCache.Set(...)` (`store/user.go:98,122,132,143,167`), and `Cache.Set` forwards to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`) — so users inherit the shared 10-minute default. No caller uses `SetWithTTL` with a custom duration, so there is no user-specific TTL override.
- Invalidation is explicit rather than TTL-driven in the one case that matters: `Store.DeleteUser` removes the entry via `s.userCache.Delete(ctx, userCacheKey(userID))` (`store/user_delete.go:40`). Reads only consult the cache when looking up by ID — `Store.GetUser` checks it at `store/user.go:150` and otherwise falls through to `ListUsers` and the SQL driver.
- Lifecycle: the caches' cleanup goroutines are stopped by `Store.Close` (`store/store.go:74-76`), which runs during server shutdown (`server/server.go:146`).
