**No — the MySQL driver is constructed only inside the factory.**

Evidence:

- `mysql.NewDB` (`store/db/mysql/mysql.go:20`) is the sole constructor for the MySQL `store.Driver`, and it has exactly one call site in the entire repo: `store/db/db.go:22`, inside the `switch profile.Driver` of `NewDBDriver` (`store/db/db.go:14`).
- A repo-wide grep for the import path `github.com/usememos/memos/store/db/mysql` returns a single hit — `store/db/db.go:8`. Since Go requires an import to reference the package, no other file (including tests, `cmd/`, and benchmarks) can construct it. The internal `DB` struct (`store/db/mysql/mysql.go:14`) is instantiated only within `NewDB` itself (`mysql.go:29`).
- Every other entry point goes through the factory instead: `store/test/store.go:28,50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(profile)` and let the `profile.Driver` string pick the backend.

The same holds symmetrically for `sqlite.NewDB` (`store/db/sqlite/sqlite.go:24`) and `postgres.NewDB` (`store/db/postgres/postgres.go:21`) — all three are reached only from `store/db/db.go`.
