**Triggers (recomputation happens only when content changes):**

- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the `if path == "content"` branch of the update-mask loop (`memo_service.go:435-452`); the recomputed payload is then written via `update.Payload = memo.Payload` at `:451`. - `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:56` — inherits it by delegating to `s.CreateMemo`.

**What it extracts** (single goldmark AST walk in `ExtractAll`, `internal/markdown/markdown.go:370-410`), stored on `store.Memo.Payload`:

- `Tags` — every `#tag` node, deduplicated case-preserving via `uniquePreserveCase` (`internal/markdown/markdown.go:417`) → `memo.Payload.Tags` (`runner.go:85`).
- `Property` (`storepb.MemoPayload_Property`, schema at `proto/store/memo.proto:14-22`) → `memo.Payload.Property` (`runner.go:86`):
  - `Title` — text of the first block-level H1, if the document starts with one (`markdown.go:382-388`)
  - `HasLink` — any link node (`markdown.go:392`)
  - `HasCode` — code block, fenced code block, or code span (`markdown.go:395`)
  - `HasTaskList` — any task checkbox (`markdown.go:398`)
  - `HasIncompleteTasks` — at least one unchecked checkbox (`markdown.go:400-402`)
- `Mentions` — also collected by `ExtractAll`, but `RebuildMemoPayload` discards them; they're consumed separately for mention notifications (`server/router/api/v1/memo_mention_helpers.go:32`).

Consumers, matching the "lists/previews" use: the API converter copies `Tags` and `Property` onto the response (`server/router/api/v1/memo_service_converter.go:47-49`, `convertMemoPropertyFromStore` at `:315`), and user stats aggregate the same flags (`server/router/api/v1/user_service_stats.go:138-152,254-268`). Note the preview `Snippet` is *not* part of this stored payload — it's generated per-response from the content by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet` (`server/router/api/v1/memo_service_webhooks.go:85`, used at `memo_service_converter.go:76,225,248`).
