**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection: the SSRF-guarded dialer `safeDialContext` on the shared `safeClient` transport — `internal/webhook/webhook.go:31-76`, backed by the reserved-CIDR list and `isReservedIP` in `internal/webhook/validate.go:14-54`**

How it fits together:

- **Trigger**: memo create/update/delete and comment-created events call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:41,69`. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel; four worker goroutines started in `init()` (`internal/webhook/webhook.go:41-54`) drain it and call `Post`, so delivery executes on those workers, not the request goroutine.
- **Delivery**: `Post` marshals the payload, adds Standard Webhooks HMAC-SHA256 headers when a signing secret is set, and issues the POST through `safeClient` at `internal/webhook/webhook.go:152` (30s timeout, response body capped at 1 MiB).
- **Protection — two layers**:
  1. *Dial-time* (the real enforcement): `safeClient`'s transport uses `safeDialContext` (`internal/webhook/webhook.go:58-76`), which resolves the host itself and refuses to connect if any resolved IP falls in a reserved range. Because the check happens at connection time on the addresses actually dialed, it also defeats DNS rebinding — noted in the comment at `internal/webhook/webhook.go:28-30`.
  2. *Config-time*: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and hostnames resolving to reserved IPs when a user registers or updates a webhook — called from `server/router/api/v1/user_service_webhooks.go:74,161,182`.
- **Reserved ranges** are `reservedCIDRs` at `internal/webhook/validate.go:14-23` (IPv4 loopback, RFC-1918, link-local incl. 169.254.169.254 IMDS, plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`), parsed once in `init()` and matched by `isReservedIP` (`internal/webhook/validate.go:44`).
- **Escape hatch**: the package-level `AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted setups. Note that in this tree nothing outside tests assigns it — the `--allow-private-webhooks` flag mentioned in `CHANGELOG.md:121` has no wiring I can find in the current Go sources, so the guard is effectively always on at runtime.
