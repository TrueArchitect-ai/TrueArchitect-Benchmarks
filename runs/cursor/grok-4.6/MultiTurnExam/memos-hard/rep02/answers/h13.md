markdown.service — markdown.NewService in server/router/api/v1/v1.go (NewAPIV1Service) — APIV1Service, RSSService (and memopayload.Runner)

The interface is `markdown.Service` in `internal/markdown/markdown.go`. The only implementation is the unexported `service` struct returned by `NewService`. Production builds it once in `NewAPIV1Service` (`server/router/api/v1/v1.go`) with `WithTagExtension` and `WithMentionExtension`, and stores it on `APIV1Service.MarkdownService`. `server/server.go` passes that same instance into `rss.NewRSSService`. `memopayload.Runner` also has a `markdown.Service` field, but `NewRunner` is not wired into server startup; API memo save/update calls `RebuildMemoPayload` with `s.MarkdownService` instead. Tests construct additional `NewService` instances (`test_helper.go`, `rss_test.go`, markdown unit tests).
