memo, memo_relation, attachment, memo_share

`Store.DeleteMemo` in `store/memo.go` deletes `memo_relation` rows (source and target) and linked `attachment` rows, then `DELETE`s the `memo` row. `memo_share` is defined with `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in the LATEST schemas (e.g. `store/migration/sqlite/LATEST.sql`). SQLite opens with `foreign_keys(0)` in `store/db/sqlite/sqlite.go`, so that cascade applies on MySQL/Postgres, not SQLite. Reactions and inbox rows are not cleaned up. The API handler also deletes comment memos first (`server/router/api/v1/memo_service.go`), which hits the same tables again.
