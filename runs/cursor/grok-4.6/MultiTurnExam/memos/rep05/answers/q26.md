memo, memo_relation, attachment, memo_share

`Store.DeleteMemo` in `store/memo.go` deletes `memo_relation` rows (memo as source or target), then `attachment` rows via `DeleteAttachment`, then the `memo` row (`store/db/sqlite/memo.go` and the other dialects). `memo_share` is removed by `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in each `LATEST.sql`. The API handler in `server/router/api/v1/memo_service.go` first runs the same store delete on comment memos. Reactions and inbox rows are not deleted.
