memo, memo_relation, attachment, memo_share

`Store.DeleteMemo` in `store/memo.go` deletes `memo_relation` rows (both directions) and linked `attachment` rows, then deletes the `memo` row. `memo_share` is removed by `ON DELETE CASCADE` in the MySQL/Postgres schemas (`store/migration/mysql/LATEST.sql`, `store/migration/postgres/LATEST.sql`). SQLite defines the same FK in `store/migration/sqlite/LATEST.sql` but opens with `foreign_keys(0)` in `store/db/sqlite/sqlite.go`, so that cascade does not run there. Reactions and inbox rows are not deleted.
