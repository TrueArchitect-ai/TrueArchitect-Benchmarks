The question assumes a per-user API rate-limiting middleware exists; it does not.

HTTP middleware registered in `server/server.go` is only Echo `Recover` and CORS. API auth is applied in `server/router/api/v1/v1.go` (gRPC-Gateway middleware plus Connect interceptors for metadata, logging, recovery, and auth). None of those enforce a per-user request quota.

The only nearby numeric “limits” are not request-rate limits: `maxAPIRequestBytes` is 256 MiB in `server/router/api/v1/v1.go`, and thumbnail/image work uses concurrency semaphores (3 and 2) in the same file. Rate limiting appears only as an email-sending recommendation in `internal/email/README.md`, not as registered API middleware.
