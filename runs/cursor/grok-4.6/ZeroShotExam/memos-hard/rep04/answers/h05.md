explicit Go code; `store/db/sqlite/user_delete.go`, `store/db/postgres/user_delete.go`, `store/db/mysql/user_delete.go` (`deleteReactionsByCreatorTx` / `deleteUserTargetsTx`); schema check in `store/migration/{sqlite,postgres,mysql}/LATEST.sql`

`DeleteUser` runs a transaction that deletes the user's reactions in Go with `DELETE FROM reaction WHERE creator_id = …` (`deleteReactionsByCreatorTx`). The same path also deletes reactions on that user's memos via `deleteReactionsByContentIDsTx`. The `reaction` table has a `creator_id` column and a uniqueness constraint, but no foreign key or `ON DELETE` rule (unlike `memo_share`, which does have `ON DELETE CASCADE`). Store and API tests assert the user's reactions are gone after delete (`store/test/user_delete_test.go`, `server/router/api/v1/test/user_service_delete_test.go`).
