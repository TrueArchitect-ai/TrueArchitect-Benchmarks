The question assumes this repo registers per-user API rate-limiting middleware with numeric request limits. That premise is wrong.

There is no per-user (or global) API rate-limiting middleware in this codebase, so there are no request-count/window limits to report. The HTTP/API stack in `server/server.go` and `server/router/api/v1/v1.go` only registers recover, CORS, gateway auth, and Connect interceptors (metadata, logging, recovery, auth) from `server/router/api/v1/connect_interceptors.go`. Nearby limits are not rate limits: `maxAPIRequestBytes` in `server/router/api/v1/v1.go` caps request body size at 256 MiB, and weighted semaphores in that same file cap concurrent thumbnail/image work. The only “rate limit” text is an unimplemented email-sending example in `internal/email/README.md` (10 emails/second), not API middleware.
