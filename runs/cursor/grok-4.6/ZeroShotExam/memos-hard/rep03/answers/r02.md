The question assumes this repo registers per-user API rate-limiting middleware with numeric request limits. That middleware is not present, so there are no such limits to report.

HTTP middleware actually registered in `server/server.go` is only `middleware.Recover()` and CORS (`newCORSMiddleware`). API auth is applied in `server/router/api/v1/v1.go` as gRPC-Gateway `gatewayAuthMiddleware` and Connect interceptors (`NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` in `server/router/api/v1/connect_interceptors.go`). None of those implement per-user request rate limits.

Nearby limits that are not per-user API rate limiting: a 256 MiB request-body cap (`maxAPIRequestBytes` in `server/router/api/v1/v1.go`), and process-wide concurrency semaphores for thumbnails (3) and image processing (2) in `NewAPIV1Service`. Email rate limiting appears only as an unimplemented example in `internal/email/README.md` (10 emails/second).
