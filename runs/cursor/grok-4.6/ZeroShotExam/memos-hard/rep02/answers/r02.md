The question assumes a per-user API rate-limiting middleware exists with request-count limits. That is not present in this repository.

`server/server.go` registers only `middleware.Recover()` and CORS (`newCORSMiddleware`). `server/router/api/v1/v1.go` adds gateway auth middleware and Connect interceptors (metadata, logging, recovery, auth). None of those enforce per-user request rates.

The only API request bound nearby is a **size** cap, not a rate: `maxAPIRequestBytes = 256 << 20` (256 MiB) via `http.MaxBytesHandler` in `server/router/api/v1/v1.go`. Semaphores in `NewAPIV1Service` cap concurrent thumbnail generation (3) and image processing (2); that is process-wide concurrency, not per-user QPS. Email rate limiting appears only as a docs suggestion in `internal/email/README.md` and `internal/email/doc.go`, not as registered HTTP middleware.
