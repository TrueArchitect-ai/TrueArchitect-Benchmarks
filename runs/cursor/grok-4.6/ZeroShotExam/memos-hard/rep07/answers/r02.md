The question assumes this repo registers per-user API rate-limiting middleware with numeric request limits. That is not the case.

There is no per-user API rate-limiting middleware, interceptor, or limiter package in this codebase. HTTP middleware registered in `server/server.go` is only Echo `Recover` and CORS. Connect interceptors registered in `server/router/api/v1/v1.go` are metadata, logging, panic recovery, and auth.

What looks similar is not a per-user request quota:
- Global concurrency semaphores in `server/router/api/v1/v1.go` cap thumbnail generation at 3 and image processing at 2.
- Rate limiting is only mentioned as a recommended (unimplemented) practice for SMTP in `internal/email/README.md` and `internal/email/doc.go`, with an example of 10 emails per second.
