`memo`, `memo_relation`, `attachment`

`store.DeleteMemo` in `store/memo.go` deletes the memo row, then explicitly cascades by deleting `memo_relation` rows (where the memo is source or target) and linked `attachment` rows via `DeleteAttachment`. The API handler in `server/router/api/v1/memo_service.go` also deletes comment memos through the same path, so it still only hits those three tables.

`memo_share` is not in that cascade code; it only has a schema `ON DELETE CASCADE` FK, and SQLite runs with foreign keys off (`store/db/sqlite/sqlite.go`). Reactions and inbox rows are not deleted.
