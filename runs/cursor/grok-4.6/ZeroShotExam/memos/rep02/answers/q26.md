`memo`, `memo_relation`, `attachment`

`store.DeleteMemo` in `store/memo.go` deletes related `memo_relation` rows (source and target), then linked `attachment` rows via `DeleteAttachment`, then the `memo` row itself (`DELETE FROM memo` in `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, and `store/db/mysql/memo.go`). API `DeleteMemo` in `server/router/api/v1/memo_service.go` first deletes comment memos through the same store path, so it still only hits those three tables.

`memo_share` has `ON DELETE CASCADE` in schema, but `DeleteMemo` does not delete it in application code, and SQLite runs with foreign keys off (`store/db/sqlite/sqlite.go`), so it is not part of this explicit cascade.
