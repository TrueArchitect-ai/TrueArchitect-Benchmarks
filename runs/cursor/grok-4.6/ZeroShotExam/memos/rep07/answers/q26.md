**memo**, **memo_relation**, **attachment**

`store.DeleteMemo` in `store/memo.go` deletes those tables itself: it calls `DeleteMemoRelation` (source and related memo), then `DeleteAttachment` for linked files, then `DELETE FROM memo`. The API handler in `server/router/api/v1/memo_service.go` also deletes comment memos first via the same store path, so it still only hits those three tables. `memo_share` is not in that Go cascade; it only has a schema `ON DELETE CASCADE` (and SQLite runs with foreign keys off).
