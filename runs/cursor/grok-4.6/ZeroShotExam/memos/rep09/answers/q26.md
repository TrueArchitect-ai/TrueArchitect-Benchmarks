**memo, memo_relation, attachment**

`store.DeleteMemo` in `store/memo.go` first deletes `memo_relation` rows where the memo is source or target, then deletes linked `attachment` rows via `DeleteAttachment`, then deletes the `memo` row (`store/db/sqlite/memo.go`, and the same `DELETE FROM memo` in the Postgres/MySQL drivers). API `DeleteMemo` in `server/router/api/v1/memo_service.go` only adds recursive `store.DeleteMemo` calls for comment memos, so it still only hits those three tables.

`memo_share` has `ON DELETE CASCADE` in the schema, but DeleteMemo does not clean it up in code, and SQLite runs with foreign keys off (`store/db/sqlite/sqlite.go`). Reactions and inbox rows are not deleted.
