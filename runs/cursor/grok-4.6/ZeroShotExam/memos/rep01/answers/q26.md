**memo, memo_relation, attachment**

`store.DeleteMemo` (`store/memo.go`) deletes those tables: it removes `memo_relation` rows where the memo is source or target, deletes linked `attachment` rows, then deletes the `memo` row. Driver SQL is `DELETE FROM memo` (`store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`).

The API handler (`server/router/api/v1/memo_service.go`) also deletes comment memos first via the same store path, so it still only hits those three tables. `memo_share` has `ON DELETE CASCADE` in schema, but DeleteMemo has no Go cleanup for it, and SQLite runs with foreign keys off (`store/db/sqlite/sqlite.go`). Reactions and inbox rows are not deleted.
