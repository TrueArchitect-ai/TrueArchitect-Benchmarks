**memo, memo_relation, attachment**

`store.DeleteMemo` in `store/memo.go` deletes those tables in that cascade:

1. **memo_relation** — explicit cleanup of rows where the memo is source or target (`DeleteMemoRelation`).
2. **attachment** — explicit cleanup of linked rows (`DeleteAttachment`).
3. **memo** — direct `DELETE FROM memo` in the SQLite/MySQL/Postgres drivers (`store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`).

API `DeleteMemo` in `server/router/api/v1/memo_service.go` only adds more `store.DeleteMemo` calls for comment memos, so it still hits the same three tables. `memo_share` is not in that code; it is only dropped by the SQL `ON DELETE CASCADE` FK, not by explicit cascade code.
