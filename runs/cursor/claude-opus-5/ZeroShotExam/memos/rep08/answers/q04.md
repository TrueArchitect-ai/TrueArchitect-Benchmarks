**`APIV1Service.SignIn` — `server/router/api/v1/auth_service.go`** (defined at line 51) is the function that implements the SignIn RPC.

It handles two credential types: password-based sign-in (bcrypt comparison against the stored hash, plus a `DisallowPasswordAuth` check for non-admin roles) and SSO/OAuth2 sign-in (via `resolveSSOIdentity` and `resolveSSOUser`). After rejecting archived users, it delegates token issuance to `doSignIn` and returns the user, access token, and expiry.

One thing worth knowing: the Connect protocol entry point is a thin wrapper, `ConnectServiceHandler.SignIn` in `server/router/api/v1/connect_services.go` (line 78). It only wraps the call in `connectWithHeaderCarrier` so the service can set the refresh-token cookie header, then forwards to `APIV1Service.SignIn`. The real logic lives in `auth_service.go`.
