**Answer:** `web/src/connect.ts` (with token storage in `web/src/auth-state.ts`); short-lived JWT access tokens in localStorage plus an HTTP-only refresh-token cookie (`memos_refresh`), and Personal Access Tokens as an alternative bearer credential; validated by `server/auth`.

How it works:

- **Interceptor.** `authInterceptor` in `web/src/connect.ts` is installed on the shared Connect-Web transport (`createConnectTransport({ ..., interceptors: [authInterceptor] })`), so every generated service client (memo, user, attachment, etc.) runs through it. It calls `getRequestToken()` and sets `Authorization: Bearer <token>`. On a `Code.Unauthenticated` error it refreshes once, marks the retry with an `X-Retry` header to prevent loops, and calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`) if the refresh fails. A second transport with `interceptors: []` is used for the refresh call itself to avoid recursion.

- **Tokens managed.** `web/src/auth-state.ts` holds the JWT access token in memory and in `localStorage` (`memos_access_token` / `memos_token_expires_at`), tracks expiry with a 30-second preflight buffer, and syncs freshly refreshed tokens across tabs via a `BroadcastChannel` (`memos_token_sync`). The refresh token is never touched by JS — it rides as a cookie, which is why `fetch` is wrapped with `credentials: "include"`. A `useTokenRefreshOnFocus` hook (`web/src/hooks/useTokenRefreshOnFocus.ts`) refreshes proactively on tab focus using a 2-minute buffer, deduplicated against the interceptor by `tokenRefreshManager`.

- **Backend validation.** The `server/auth` package owns all token logic: `token.go` generates and parses tokens (HS256, issuer `memos`, `kid: v1`, 15-minute access tokens with audience `user.access-token`, 30-day refresh tokens, `memos_pat_`-prefixed PATs), `extract.go` pulls the bearer token or refresh cookie, and `authenticator.go` resolves credentials to a user — access tokens statelessly by signature, refresh tokens checked against the store for revocation, PATs by SHA-256 hash lookup. The Connect `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` reads the `Authorization` header and delegates to that package via the `Authorizer`, then attaches the result with `auth.ApplyToContext`.
