**Mechanism:** Server-Sent Events (SSE) over a plain HTTP GET stream at `/api/v1/sse` (`Content-Type: text/event-stream`, 30s heartbeat comments, Bearer-token auth in the `Authorization` header). Because auth uses a header, the browser client streams it with `fetch` rather than `EventSource` (`web/src/hooks/useLiveMemoRefresh.ts`).

**Hub path:** `server/router/api/v1/sse_hub.go` — defines `SSEHub` (a mutex-guarded `map[*SSEClient]struct{}` with `Subscribe`/`Unsubscribe`/`Broadcast`/`Close`, 32-event buffer per client, dropping events for slow clients). The HTTP endpoint that pumps the hub into the response lives in `server/router/api/v1/sse_handler.go` (`RegisterSSERoutes`/`handleSSE`), it is wired up in `server/router/api/v1/v1.go` (`NewSSEHub()`, `RegisterSSERoutes(gwGroup, s.SSEHub, ...)`), and closed on shutdown in `server/server.go`.

**Handler names that broadcast:**

| Handler | File | Event type |
| --- | --- | --- |
| `CreateMemo` | `server/router/api/v1/memo_service.go:163` | `memo.created` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:126` | `memo.comment.created` |
| `UpsertMemoReaction` | `server/router/api/v1/reaction_service.go:106` | `reaction.upserted` |
| `DeleteMemoReaction` | `server/router/api/v1/reaction_service.go:161` | `reaction.deleted` |

The `memo.updated` event is broadcast indirectly through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:71`), which is called by `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`).

Events carry `Visibility` and `CreatorID` that are not serialized; they are used by `SSEClient.canReceive` to filter private-memo events to the owner or an admin.
