`DispatchMemoCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go` delegates to `dispatchMemoRelatedWebhook` with the activity type `"memos.memo.created"`. That helper resolves the memo's creator, loads that user's webhooks via `s.Store.GetUserWebhooks`, and for each hook builds a `webhook.WebhookRequestPayload` carrying the memo, the hook URL, and the hook's signing secret, then hands it to `webhook.PostAsync`.

Delivery lives in the `internal/webhook` package (`internal/webhook/webhook.go`). `PostAsync` enqueues onto a buffered channel of size 128 drained by four worker goroutines started in `init()`, dropping the payload with a warning if the queue is full. The workers call `Post`, which marshals the payload to JSON and POSTs it with Go's `net/http` through a shared `safeClient` — a 30-second-timeout client whose transport uses `safeDialContext` to reject connections to reserved/private IPs (SSRF and DNS-rebinding protection, with the ranges and the `AllowPrivateIPs` escape hatch defined in `internal/webhook/validate.go`).

Signing follows the Standard Webhooks scheme. When the hook has a signing secret, `Post` derives the key with `resolveSigningKey` (base64-decoding the body of a `whsec_<base64>` secret, otherwise using the raw string), generates `msg_<uuid>` and a Unix timestamp, and computes HMAC-SHA256 over `msgID + "." + timestamp + "."` concatenated with the JSON body. The base64 result is sent as three headers: `webhook-id`, `webhook-timestamp`, and `webhook-signature` set to `v1,<signature>`. Secrets are generated by `GenerateSigningSecret` from 32 random bytes in the same `whsec_` form.
