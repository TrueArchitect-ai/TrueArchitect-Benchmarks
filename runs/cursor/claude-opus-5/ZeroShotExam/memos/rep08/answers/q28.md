**Workers the server actually starts, and what drives each:**

- **`s3presign` runner — startup pass + 12-hour ticker.** `Server.startBackgroundRunners` calls `s3presignRunner.RunOnce(ctx)` synchronously, then launches `Run` in a tracked goroutine (`server/server.go:155-176`); `Run` loops on `time.NewTicker(runnerInterval)` with `runnerInterval = 12h` (`server/runner/s3presign/runner.go:28-40`). It is the only entry in `backgroundRunnerCancels`/`backgroundRunnerWG`, so it's also the only runner cancelled and waited on during shutdown.
- **HTTP serve loop — one goroutine, event-driven by incoming connections.** `go s.httpServer.Serve(listener)` (`server/server.go:122-128`); not ticker-based.
- **Three store cache cleanup loops — 5-minute ticker each.** `store.New` builds `instanceSettingCache`, `userCache`, `userSettingCache` via `cache.New` (`store/store.go:38-53`), and `cache.New` unconditionally starts `go c.cleanupLoop()` with `CleanupInterval = 5 * time.Minute` (`store/cache/cache.go:75-85`, `store/cache/cache.go:199-213`). These start when `main` constructs the store (`cmd/memos/main.go`), not from `startBackgroundRunners`, and stop via `Store.Close` (`store/store.go:72-79`).
- **Webhook dispatch pool (4 goroutines) — queue-driven, no timer.** Started in `internal/webhook/webhook.go:42-54` package `init()`, consuming `asyncPostQueue` (buffer 128); work is enqueued by `PostAsync` from memo activity (`server/router/api/v1/memo_service_webhooks.go:43,71`).
- **Email sender pool (2 goroutines) — queue-driven, no timer.** Started in `internal/email/email.go:16-30` package `init()`, consuming `asyncEmailQueue`; fed by `SendAsync`, wired in `server/notification/email.go:30`.
- **SSE heartbeat — 30-second ticker, but request-scoped, not a server worker.** Created per connected client inside the stream handler (`server/router/api/v1/sse_handler.go:17,63-65`). `SSEHub` itself has no background loop; it only holds a client set (`server/router/api/v1/sse_hub.go:63-93`).

**Unused scheduling infrastructure:**

- **`internal/scheduler` is dead as far as the server is concerned.** It's a full cron-style scheduler (6/5-field cron parser, timezone support, middleware chain, graceful `Stop`) in `internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`, documented in `internal/scheduler/README.md`, but the only imports of `github.com/usememos/memos/internal/scheduler` anywhere in the repo are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). Nothing in `server/` or `cmd/` constructs or starts it; the one scheduled job that exists uses a hand-rolled ticker instead.
- **`server/runner/memopayload`'s `Runner` is never started.** `NewRunner`/`RunOnce` (the batched rebuild of every memo's payload, `server/runner/memopayload/runner.go:16-72`) has no callers outside the package; only the standalone helper `RebuildMemoPayload` is used, and it's called synchronously per request in `server/router/api/v1/memo_service.go:108,447`.
