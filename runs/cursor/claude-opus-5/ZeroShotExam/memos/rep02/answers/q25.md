**Engine:** Google CEL (`github.com/google/cel-go` v0.28.1, declared in `go.mod:13`), wrapped by the in-repo filter package at `internal/filter/` — `engine.go` (entry point / `DefaultEngine()`), `schema.go` (allowed fields + CEL env), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL), `helpers.go` (store glue). The package's own docs are at `internal/filter/README.md`.

**Mechanism:** `ListMemos` in `server/router/api/v1/memo_service.go:211-216` validates `request.Filter` via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`) and appends the raw string to `memoFind.Filters`; each store driver then calls `filter.DefaultEngine()` and `filter.AppendConditions(...)` with its dialect constant (`store/db/sqlite/memo.go:57-63`, `store/db/postgres/memo.go:54-60`, `store/db/mysql/memo.go:65-71`), which runs the three-phase pipeline — `env.Compile` against the memo CEL environment, `buildCondition` normalizing the AST into IR, and the dialect-aware `renderer` — producing a parenthesized SQL fragment plus bound args that get appended to the query's `WHERE` list.

Some details worth knowing:

- The CEL environment only declares memo-specific variables (`content`, `creator_id`, `created_ts`, `tags`, `visibility`, `has_task_list`, `now`, …) plus `ext.Sets()` and `cel.ValidateRegexLiterals()` (`internal/filter/schema.go:232-249`), so unknown identifiers fail at compile time rather than reaching SQL. There's a parallel `NewAttachmentSchema()` for attachment filters.
- Dialect differences live entirely in the renderer: placeholders are `?` for SQLite/MySQL and `$n` for Postgres with an offset so fragments compose with pre-existing args (`internal/filter/render.go:842-850`), column quoting is backtick-vs-bare (`render.go:919-926`), and JSON/tag predicates diverge per engine (SQLite `LIKE`/`json_each`, MySQL `JSON_CONTAINS`/`JSON_TABLE`, Postgres `@>`/`jsonb_array_elements_text`). Schema fields can also override their column expression per dialect, e.g. `UNIX_TIMESTAMP(%s)` for MySQL's `attachment.created_ts` (`schema.go:282-288`).
- Timestamps (`now`, `duration(...)`, `timestamp(...)`) and arithmetic constant-fold to epoch seconds at compile time, with `now` frozen once per compile via the engine's injectable clock (`internal/filter/engine.go:16-33, 62`).
- The server also injects its own visibility filter as a CEL string through the same path (`memo_service.go:222`), so ACL enforcement reuses the identical compiler.
