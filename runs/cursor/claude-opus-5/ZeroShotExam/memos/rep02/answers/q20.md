**Answer: Server-Sent Events (SSE) over a long-lived HTTP stream; hub at `server/router/api/v1/sse_hub.go`; broadcasting handlers are `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`, `UpsertMemoReaction`, and `DeleteMemoReaction`.**

### Mechanism

SSE, not WebSockets. The endpoint `GET /api/v1/sse` is registered in `server/router/api/v1/sse_handler.go` (wired up at `server/router/api/v1/v1.go:125`) and streams `text/event-stream` with `Cache-Control: no-cache`, `X-Accel-Buffering: no`, an initial `: connected` comment, and a `: heartbeat` comment every 30 seconds. Authentication is a Bearer token in the `Authorization` header rather than a cookie, so the browser side uses `fetch` with a manual stream reader instead of `EventSource` — see `web/src/hooks/useLiveMemoRefresh.ts`, which parses `data:` lines and invalidates the corresponding React Query caches, reconnecting with exponential backoff.

### Hub

`server/router/api/v1/sse_hub.go` defines `SSEHub`, a mutex-guarded set of `SSEClient` connections, each holding a 32-event buffered channel. `Broadcast` marshals the event once and does a non-blocking send per client, dropping events for slow consumers rather than blocking:

```115:132:/bench/repo/server/router/api/v1/sse_hub.go
func (h *SSEHub) Broadcast(event *SSEEvent) {
	data := event.JSON()
	if len(data) == 0 {
		return
	}
	h.mu.RLock()
	defer h.mu.RUnlock()
	for c := range h.clients {
		if !c.canReceive(event) {
			continue
		}
		select {
		case c.events <- data:
		default:
			// Drop event for slow client to avoid blocking.
		}
	}
}
```

Delivery filtering happens in `canReceive`: private memos only reach the creator or an admin. The hub instance lives on `APIV1Service.SSEHub` (`server/router/api/v1/v1.go:36,57`) and is closed on shutdown via `server/server.go:205`.
