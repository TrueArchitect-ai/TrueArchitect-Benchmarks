**Runners the server actually starts**

- **S3 presign runner (`s3presign.Runner`) — one immediate `RunOnce` at startup, then a plain `time.Ticker` every 12 hours.** `Server.startBackgroundRunners` builds it with `s3presign.NewRunner(s.Store)`, calls `RunOnce(ctx)` synchronously, then launches `Run(s3Context)` in a tracked goroutine (`server/server.go` lines 153–174). The interval is the package constant `runnerInterval = 12 * time.Hour` in `server/runner/s3presign/runner.go` (line 27); `Run` is a `select` over `ticker.C` and `ctx.Done()`. This is the *only* thing registered in `backgroundRunnerCancels` / `backgroundRunnerWG`, so it's also the only runner participating in graceful shutdown (`stopBackgroundRunners` / `waitBackgroundRunners`).

- **Store cache cleanup loops (3 of them) — `time.Ticker` every 5 minutes, started implicitly at store construction, not by `Start`.** `store.New` creates `instanceSettingCache`, `userCache`, and `userSettingCache` via `cache.New(cacheConfig)` with `CleanupInterval: 5 * time.Minute` (`store/store.go` lines 40–58); `cache.New` fires `go c.cleanupLoop()` (`store/cache/cache.go` line 83). They're stopped by `Store.Close()`, which the server calls at the end of `Shutdown`.

- **HTTP serve goroutine — event-driven, not scheduled.** `go s.httpServer.Serve(listener)` in `server/server.go` line 124. Not a periodic worker; included only because it's the other goroutine `Start` spawns.

Request-scoped tickers/goroutines that are not startup workers: the SSE heartbeat ticker lives inside the per-connection handler `handleSSE` (`server/router/api/v1/sse_handler.go` line 64), and PAT last-used updates are fire-and-forget goroutines per authenticated request (`server/auth/authenticator.go` line 180).

**Unused scheduling infrastructure**

- **`internal/scheduler` is entirely unused by the server.** It's a full cron implementation — `scheduler.go`, `parser.go` (5- and 6-field cron), `job.go`, `middleware.go` (Recovery/Logging/Timeout), timezone support, graceful `Stop` — documented in `internal/scheduler/README.md` and `internal/scheduler/doc.go`. The only importers are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). Nothing in `server/`, `cmd/`, or `store/` imports it, and the S3 presign runner uses a hand-rolled `time.Ticker` rather than a registered cron job.

- **`memopayload.Runner` is constructed nowhere.** `server/runner/memopayload/runner.go` defines `NewRunner` and a batch `RunOnce` that rebuilds all memo payloads, but no caller exists. Only the free function `memopayload.RebuildMemoPayload` is used, called inline on memo create/update paths in `server/router/api/v1/memo_service.go` (lines 108 and 447). So the package's batch/backfill entry point is dead code from the server's perspective, even though `AGENTS.md` line 64 describes `server/runner/` as "background memo processing and S3 presign refresh."
