**Tables written (rows deleted) when `DeleteMemo` runs: `memo`, `memo_relation`, `attachment`, and — on MySQL/Postgres only — `memo_share`.**

Details, following the call chain from the API handler:

- **`memo`** — the target memo row, plus one row per direct comment memo. The handler first lists comment relations and deletes each comment memo, then deletes the memo itself (`server/router/api/v1/memo_service.go:567`-`582`); the driver issues `DELETE FROM memo WHERE id = ?` (`store/db/sqlite/memo.go:237`, and the Postgres/MySQL equivalents at `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`).
- **`memo_relation`** — `store.DeleteMemo` explicitly clears relations in both directions (`memo_id` and `related_memo_id`) before deleting the memo row (`store/memo.go:140`-`147`).
- **`attachment`** — the same store method lists attachments by `memo_id` and deletes each one, which also removes the underlying file/object from storage (`store/memo.go:148`-`157`, `store/attachment.go:132`, `store/db/sqlite/attachment.go:211`).
- **`memo_share`** — no Go code deletes these; they go away only through the schema-level `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`). Worth flagging: the SQLite driver opens the database with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so on SQLite that cascade never fires and share rows are left orphaned. On Postgres and MySQL the cascade does apply.

Two things that are *not* affected, which are easy to assume otherwise:

- **`reaction`** — the handler reads reactions for the webhook payload but never deletes them (`server/router/api/v1/memo_service.go:545`-`550`), and reactions are keyed by the string `content_id` with no foreign key (`store/migration/sqlite/LATEST.sql:92`-`99`), so no cascade either. Reaction rows for a deleted memo are left behind.
- **`user` / `user_setting`** — read only, to resolve the current user and the creator's webhook list (`store/user_setting.go:312`); nothing is written.
