`store/migration/sqlite/LATEST.sql`

On a fresh (uninitialized) database, the migrator skips the incremental version-by-version migrations and applies a single full-schema file instead. The filename is defined as a constant and the driver-specific directory is chosen at runtime:

```54:56:/bench/repo/store/migrator.go
	// LatestSchemaFileName is the name of the latest schema file.
	// This file is used to initialize fresh installations with the current schema.
	LatestSchemaFileName = "LATEST.sql"
```

The header comment in the same file spells out the flow: "preMigrate: Check if DB is initialized. If not, apply LATEST.sql" and "LATEST.sql: Full schema for new installations (faster than incremental migrations)" (`store/migrator.go` lines 27 and 42). Migration files live under `store/migration/{driver}/`, so for SQLite that resolves to `store/migration/sqlite/LATEST.sql`, which exists in the repo. The equivalent files for the other drivers are `store/migration/postgres/LATEST.sql` and `store/migration/mysql/LATEST.sql`.

Note that `store/seed/sqlite/01__dump.sql` is a different thing — it is demo-mode seed data applied only when `profile.Demo` is set, not the schema.
