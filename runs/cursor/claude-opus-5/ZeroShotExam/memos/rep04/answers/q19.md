MemoService is exposed over **REST/HTTP-JSON via grpc-gateway** and over **Connect RPC** (connectrpc). There is no native gRPC listener in this repo — the only `grpc.NewServer` call is absent, and the generated `RegisterMemoServiceServer` in `proto/gen/api/v1/memo_service_grpc.pb.go` is never invoked. Both surfaces are mounted onto the same Echo server inside `APIV1Service.RegisterGateway`.

The wrapper type `ConnectServiceHandler` embeds `*APIV1Service` and each Connect method delegates to the gRPC implementation in `server/router/api/v1/connect_services.go` (the MemoService block starts at line 304). One thing worth flagging since it can look like a third protocol: `server/router/mcp/catalog.go` lists MemoService methods as MCP tools, but that MCP router is a bridge built on top of the OpenAPI/gateway surface rather than a separate transport registration for the service itself.
