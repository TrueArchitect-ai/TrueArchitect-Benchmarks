`web/src/connect.ts` (auth state helpers in `web/src/auth-state.ts`); short-lived JWT access tokens (Bearer header, localStorage + cross-tab BroadcastChannel sync) and long-lived JWT refresh tokens sent as the `memos_refresh` HttpOnly cookie, plus Personal Access Tokens (`memos_pat_`) accepted by the backend for programmatic clients; `server/auth`

How it fits together:

- **Interceptor**: `authInterceptor` is defined in `web/src/connect.ts` and registered on the Connect-Web transport (`createConnectTransport({ ..., interceptors: [authInterceptor] })`) that backs every service client (memo, user, auth, attachment, etc.). It calls `getRequestToken()`, sets `Authorization: Bearer <token>`, and on a `Code.Unauthenticated` error refreshes once, marks the retry with an `X-Retry` header, and replays the request; if the refresh fails it calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).

- **Tokens managed**: `web/src/auth-state.ts` holds the access token in memory and mirrors it to `localStorage` under `memos_access_token` / `memos_token_expires_at`, with a 30s pre-expiry buffer for requests and a 2min buffer on tab focus. Refresh tokens are never touched by JS — the refresh call goes through a separate interceptor-free transport using `fetch` with `credentials: "include"` so the browser sends the cookie, which avoids recursion. A `BroadcastChannel` named `memos_token_sync` shares newly refreshed tokens across tabs so only one tab hits the refresh endpoint.

- **Backend validation**: the `server/auth` package. Its `Authenticator` (`server/auth/authenticator.go`) exposes `AuthenticateByAccessTokenV2` (stateless signature-only validation), `AuthenticateByRefreshToken` (validated against the database), and PAT authentication. Token constants and parsing live in `server/auth/token.go` (`AccessTokenDuration` 15 minutes, `RefreshTokenDuration` 30 days, `RefreshTokenCookieName = "memos_refresh"`, `PersonalAccessTokenPrefix = "memos_pat_"`), and header/cookie extraction in `server/auth/extract.go`. The Connect interceptor at `server/router/api/v1/connect_interceptors.go:220` reads the `Authorization` header and applies the resulting claims to the request context; `server/router/fileserver` reuses the same package.
