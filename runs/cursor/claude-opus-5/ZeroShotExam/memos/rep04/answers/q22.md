`DispatchMemoCreatedWebhook` — `server/router/api/v1/memo_service_webhooks.go`; `internal/webhook` (package `webhook`, `internal/webhook/webhook.go`); Standard Webhooks HMAC-SHA256 signature over `msg_id.timestamp.body`, sent as `webhook-id` / `webhook-timestamp` / `webhook-signature: v1,<base64>` headers.

How it fits together:

- `CreateMemo` calls the dispatcher best-effort after converting the stored memo, logging a warning on failure rather than failing the request (`server/router/api/v1/memo_service.go:157`).
- `DispatchMemoCreatedWebhook` delegates to `dispatchMemoRelatedWebhook` with activity type `memos.memo.created`. That helper resolves the memo's creator, loads their registered hooks via `s.Store.GetUserWebhooks`, and for each hook builds a payload (`convertMemoToWebhookPayload`), sets `URL` and `SigningSecret`, then calls `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:16`, `:48-73`).
- `webhook.PostAsync` enqueues onto a buffered channel of 128 drained by four goroutines started in `init`, dropping the event with a warning if the queue is full; each worker calls `Post`, which does the actual HTTP POST (`internal/webhook/webhook.go:39-55`, `:184-196`).
- `Post` marshals the payload as JSON and, when a signing secret is present, derives the HMAC key (`whsec_`-prefixed secrets are base64-decoded by `resolveSigningKey`), computes `HMAC-SHA256(msgID + "." + timestamp + "." + body)`, and sets the three `webhook-*` headers. Delivery uses a shared `http.Client` with a 30s timeout whose transport blocks dialing reserved/private IPs to prevent SSRF and DNS rebinding (`internal/webhook/webhook.go:120-152`, `:32-37`, `:59-77`).

Secrets are generated as 32 random bytes in the Standard Webhooks `whsec_<base64>` form by `GenerateSigningSecret` (`internal/webhook/webhook.go:111`).
