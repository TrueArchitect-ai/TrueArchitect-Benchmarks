**Mechanism:** Server-Sent Events (SSE) over a plain HTTP streaming endpoint at `GET /api/v1/sse` (`Content-Type: text/event-stream`, 30s heartbeat comments, `X-Accel-Buffering: no`). It is not WebSockets. The browser side reads the stream with `fetch` plus a manual body reader rather than `EventSource`, because the request needs a Bearer token header (`web/src/hooks/useLiveMemoRefresh.ts`).

**Hub:** `server/router/api/v1/sse_hub.go` — the `SSEHub` type holds a mutex-guarded set of `SSEClient`s, each with a 32-event buffered channel; `Broadcast` marshals the event once and drops it for clients whose buffer is full so a slow reader can't block. Delivery filtering happens in `SSEClient.canReceive`: private-memo events only reach the creator or an admin. The HTTP handler that subscribes/unsubscribes clients lives in `server/router/api/v1/sse_handler.go`, and the hub is constructed and wired into the router in `server/router/api/v1/v1.go` (fields `SSEHub`, `RegisterSSERoutes`), with `server/server.go` holding a reference so it can be closed on shutdown.

**Handlers that broadcast:**

| Handler | File | Event type |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:163` | `memo.created` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:126` | `memo.comment.created` |
| `UpsertMemoReaction` | `server/router/api/v1/reaction_service.go:106` | `reaction.upserted` |
| `DeleteMemoReaction` | `server/router/api/v1/reaction_service.go:161` | `reaction.deleted` |

Update events go through one shared helper, `dispatchMemoUpdatedSideEffects` in `server/router/api/v1/memo_update_helpers.go:66`, which emits `memo.updated` and is called by three handlers: `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`).

One subtlety worth knowing: `CreateMemoComment` internally reuses `CreateMemo`, so it wraps the call in `withSuppressSSE` and `CreateMemo` checks `isSSESuppressed(ctx)` before broadcasting. That way a new comment produces a single `memo.comment.created` event for the parent memo instead of also firing a `memo.created`.
