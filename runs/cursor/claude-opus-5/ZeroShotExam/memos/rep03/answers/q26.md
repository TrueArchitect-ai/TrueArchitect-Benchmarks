Two things worth flagging:

The SQLite connection is opened with foreign keys turned off (`_pragma=foreign_keys(0)` in `store/db/sqlite/sqlite.go` line 53), so on the default SQLite backend the `memo_share` cascade never fires and share rows are orphaned. Postgres and MySQL enforce it.

The `reaction` table is only read (`ListReactions` for the webhook payload) and never cleaned up — reactions are keyed by the string `content_id` (`memos/{uid}`) with no foreign key, so they too are left orphaned after deletion.
