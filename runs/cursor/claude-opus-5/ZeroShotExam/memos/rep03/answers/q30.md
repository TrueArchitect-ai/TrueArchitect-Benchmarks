All four dispatchers are defined in `server/router/api/v1/memo_service_webhooks.go`. The first three are thin wrappers over the shared private helper `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator, loads that user's webhooks via `s.Store.GetUserWebhooks`, builds a payload with `convertMemoToWebhookPayload`, and calls `webhook.PostAsync` per hook. `DispatchMemoCommentCreatedWebhook` bypasses that helper because it targets the *related* memo owner's hooks rather than the comment creator's, but it builds the same payload and also ends at `webhook.PostAsync`.

In `internal/webhook/webhook.go`, `PostAsync` (line 184) drops the payload with a warning if it's nil or the 128-slot queue is full; otherwise one of four `init`-spawned workers (line 42) calls `Post` (line 120), which marshals the JSON body, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and sends it through `safeClient`, whose `safeDialContext` rejects reserved/private IPs to guard against SSRF.
