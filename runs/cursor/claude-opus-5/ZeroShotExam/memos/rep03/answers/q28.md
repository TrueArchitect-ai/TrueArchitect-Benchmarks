The server starts exactly one background runner, and a full cron scheduler package sits in the tree completely unused.

**Runners the server actually starts** (`server/server.go`, `startBackgroundRunners`, lines 153–174, called from `Start` at line 129):

- s3presign runner (`server/runner/s3presign/runner.go`) — one synchronous `RunOnce(ctx)` at startup, then a goroutine running `Run(s3Context)` driven by a plain `time.NewTicker` with `runnerInterval = 12 * time.Hour`. Each tick re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days. It gets its own cancelable context registered in `backgroundRunnerCancels` and is tracked by `backgroundRunnerWG` for graceful shutdown.

That's the entire list from `startBackgroundRunners`. Two other periodic goroutines exist but are not server runners:

- Store cache janitors (`store/cache/cache.go:83`, `cleanupLoop`) — started implicitly by `cache.New` for the three caches created in `store/store.go:51-53`, ticking on `CleanupInterval = 5 * time.Minute`. These are created by `store.New` in `cmd/memos/main.go:64`, not by the server, and stop via `Store.Close()`.
- SSE heartbeat (`server/router/api/v1/sse_handler.go:64`) — a 30-second ticker created per client connection inside the request handler, so it is request-scoped rather than a background worker.

**Unused scheduling infrastructure:**

- `internal/scheduler` — a full cron scheduler (cron expression parser for 5- and 6-field formats, timezone support, middleware such as `Recovery`/`Logging`, graceful shutdown) documented in `internal/scheduler/doc.go` and `internal/scheduler/README.md`. The only files importing it are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). Nothing in `server/`, `cmd/`, or `store/` references it, and the one real runner uses a raw ticker instead.
- `server/runner/memopayload` — the package has a `Runner` type with `RunOnce` (batch rebuild of all memo payloads), but `NewRunner`/`RunOnce` are never called anywhere. Only the standalone helper `RebuildMemoPayload` is used, inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447`. So this runner is defined but never started or scheduled.
