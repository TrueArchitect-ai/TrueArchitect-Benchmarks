It handles password credentials (username lookup plus bcrypt comparison, and rejects password sign-in for regular users when `DisallowPasswordAuth` is set) and SSO credentials (OAuth2 code exchange via `resolveSSOIdentity`/`resolveSSOUser`), then delegates token/session creation to `doSignIn` in `server/router/api/v1/auth_service_session.go`.

One thing worth knowing if you're tracing the call path: requests actually arrive at the thin Connect wrapper `ConnectServiceHandler.SignIn` in `server/router/api/v1/connect_services.go` (line 78), which wraps the call in `connectWithHeaderCarrier` so the service can set the refresh-token cookie protocol-agnostically before forwarding to `APIV1Service.SignIn`.
