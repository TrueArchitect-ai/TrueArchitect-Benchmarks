Two notes on the edges of this chain. First, the SQL layer is triplicated because each supported driver keeps its own consolidated schema, so a column change to `memo` has to land in all three `LATEST.sql` files plus a versioned migration under each `store/migration/<driver>/<version>/` directory. Second, the `payload` column is itself a proto-defined blob: `proto/store/memo.proto` declares `MemoPayload`, generated into Go at `proto/gen/store/memo.pb.go`, and that's the type of the `Payload` field on the store model. The Go API-facing message lives at `proto/gen/api/v1/memo_service.pb.go`, and `server/router/api/v1/memo_service_converter.go` is where the store model is translated into the API message.
