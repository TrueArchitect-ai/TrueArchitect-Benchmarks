**Server-Sent Events (SSE) over a plain `GET /api/v1/sse` stream; hub in `server/router/api/v1/sse_hub.go` (`SSEHub`), streamed by `server/router/api/v1/sse_handler.go`; broadcasting handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` (the last three via `dispatchMemoUpdatedSideEffects`), plus `UpsertMemoReaction` and `DeleteMemoReaction`.**

Details:

**Mechanism.** Not WebSockets. The server holds a long-lived HTTP response with `Content-Type: text/event-stream`, writing `data: <json>\n\n` frames plus `: heartbeat` comments every 30 seconds, and setting `X-Accel-Buffering: no` to defeat nginx buffering. The route is registered by `RegisterSSERoutes` on the same Echo group as the rest of `/api/v1` so CORS matches (`server/router/api/v1/v1.go:125`), and authentication is a Bearer token in the `Authorization` header rather than a cookie, because the browser side uses `fetch` + a stream reader instead of `EventSource` (`web/src/hooks/useLiveMemoRefresh.ts`, which reconnects with exponential backoff and invalidates React Query caches).

**Hub.** `server/router/api/v1/sse_hub.go` defines `SSEHub` as a mutex-guarded set of `SSEClient`s, each with a 32-event buffered channel. `Broadcast` marshals the event once, then does a non-blocking send per client, dropping events for slow clients rather than blocking the writer. Delivery is filtered per client by `canReceive`: private memos only reach the creator or an admin, while public/protected go to everyone. The hub instance is created in `NewAPIV1Service` and closed on server shutdown (`server/server.go:205`).

**Handlers.** Event types are `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`.

| Handler | File | Event |
| --- | --- | --- |
| `CreateMemo` | `server/router/api/v1/memo_service.go:163` | `memo.created` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:126` | `memo.comment.created` |
| `UpdateMemo`, `SetMemoAttachments`, `SetMemoRelations` | via `dispatchMemoUpdatedSideEffects`, `server/router/api/v1/memo_update_helpers.go:71` | `memo.updated` |
| `UpsertMemoReaction` / `DeleteMemoReaction` | `server/router/api/v1/reaction_service.go:106` and `:161` | `reaction.upserted` / `reaction.deleted` |

One subtlety worth knowing: `CreateMemo`'s broadcast is wrapped in `if !isSSESuppressed(ctx)`, because `CreateMemoComment` calls `CreateMemo` internally and suppresses the nested `memo.created` so only the single `memo.comment.created` event goes out.
