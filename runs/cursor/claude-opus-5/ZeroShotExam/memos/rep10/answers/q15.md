The three tables are backed by plain Go structs in the `store` package (there's no ORM/tag-based mapping here — the SQL is hand-written in the per-dialect drivers under `store/db/{sqlite,postgres,mysql}/`, and each driver scans rows into these structs).

| Struct — path |
| --- |
| `store.User` — `store/user.go` (line 29) |
| `store.Attachment` — `store/attachment.go` (line 16) |
| `store.Reaction` — `store/reaction.go` (line 7) |

How I confirmed the table correspondence: the SQLite driver's statements name the tables directly and scan into those structs, e.g. `INSERT INTO user (...)` and `FROM user` in `store/db/sqlite/user.go`, `INSERT INTO \`attachment\`` in `store/db/sqlite/attachment.go`, and `INSERT INTO \`reaction\`` in `store/db/sqlite/reaction.go`. Equivalent statements exist in `store/db/postgres/` and `store/db/mysql/`.

One caveat worth noting: the `user` table also has satellite tables (`user_setting`, `user_identity`) handled by separate structs in `store/user_setting.go` and `store/user_identity.go`, so `store.User` maps only to the `user` table itself, not the full user aggregate.
