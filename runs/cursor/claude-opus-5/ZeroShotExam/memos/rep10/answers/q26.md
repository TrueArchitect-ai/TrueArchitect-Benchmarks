Two caveats worth knowing:

`memo_share` declares `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in all three schemas (`store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`), and no Go code deletes shares when a memo is deleted. So shares are cleaned up by the engine on Postgres and MySQL, but the SQLite driver opens the connection with foreign keys turned off, so share rows are orphaned there:
