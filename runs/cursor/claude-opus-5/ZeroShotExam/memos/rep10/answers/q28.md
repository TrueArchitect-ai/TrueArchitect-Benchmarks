The server starts exactly one true background runner; everything else that loops in the background is either a per-connection goroutine or a cache housekeeping goroutine started by the store, not by `Server.Start`.

**s3presign runner** — started in `startBackgroundRunners` (`server/server.go` lines 153-174). It runs `RunOnce(ctx)` synchronously once at startup, then a goroutine runs `Run(s3Context)`, which is driven by a fixed `time.NewTicker` of 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go` lines 26-41). It gets its own cancelable context whose cancel func is stored in `backgroundRunnerCancels`, and the goroutine is tracked by `backgroundRunnerWG` so `Shutdown` can wait on it.

**HTTP serve goroutine** — `server/server.go` lines 124-128, started by `Start`; it isn't scheduled, it just runs `httpServer.Serve(listener)` until shutdown.

**Store cache cleanup loops (3 of them)** — not started by the server but by `store.New`, which builds `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go` lines 40-58); each `cache.New` spawns `go c.cleanupLoop()` (`store/cache/cache.go` line 83), ticking on `CleanupInterval` = 5 minutes.

**SSE heartbeat** — per-connection, not a server-wide worker: each `handleSSE` request creates a 30-second ticker (`sseHeartbeatInterval = 30 * time.Second`, `server/router/api/v1/sse_handler.go` lines 17 and 63-65) that lives only as long as that client's request context.

Unused-infra notes:

- `internal/scheduler` is a full cron scheduler (5- and 6-field cron expressions, timezone support, middleware, graceful shutdown, per `internal/scheduler/doc.go` and `internal/scheduler/README.md`), but **nothing in the server uses it**. The only imports of `github.com/usememos/memos/internal/scheduler` are its own `example_test.go` and `integration_test.go`. The s3presign runner uses a hand-rolled ticker instead. `AGENTS.md` line 69 still advertises "scheduler, cron" as app-private packages.
- The `memopayload` runner (`server/runner/memopayload/runner.go`) is defined with a `NewRunner` constructor and a batch `RunOnce`, but the server never constructs or starts it. Only its exported helper `RebuildMemoPayload` is used, called inline from `server/router/api/v1/memo_service.go` (lines 108 and 447) during memo create/update.
