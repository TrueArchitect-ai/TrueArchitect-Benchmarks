It handles both password credentials (bcrypt comparison against the stored hash) and SSO credentials, then calls `doSignIn` (defined in `server/router/api/v1/auth_service_session.go`) to mint the access token and set the refresh-token cookie.

One thing worth knowing: requests don't reach it directly. The Connect/gRPC transport entry point is the thin wrapper `ConnectServiceHandler.SignIn` in `server/router/api/v1/connect_services.go` (lines 78-82), which wraps the call in `connectWithHeaderCarrier` so the inner service can set response cookies, then delegates to `APIV1Service.SignIn`.
