**Engine: Google CEL (`github.com/google/cel-go`), wrapped by the in-repo filter engine at `internal/filter/`** (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`).

**Mechanism (one sentence):** The `filter` field of `ListMemos` is a CEL expression (declared as such in `proto/api/v1/memo_service.proto` line 326) that `internal/filter/engine.go` compiles with `cel-go` against a memo-specific CEL environment, normalizes into a dialect-agnostic condition IR (`internal/filter/parser.go` → `internal/filter/ir.go`), and then renders into a SQL fragment plus placeholder args for a specific dialect (`internal/filter/render.go`), which each store driver appends to its `WHERE` clause via `filter.AppendConditions`.

Supporting details:

- API layer: `server/router/api/v1/memo_service.go` (`ListMemos`, lines ~211-215) validates the expression through `validateFilter` (defined in `server/router/api/v1/shortcut_service.go:336`, which picks the dialect from `s.Profile.Driver` and does a trial `CompileToStatement`), then pushes the raw string onto `store.FindMemo.Filters`. It also appends its own synthesized CEL for visibility, e.g. `creator_id == %d || visibility in ["PUBLIC", "PROTECTED"]`.
- Schema/environment: `internal/filter/schema.go` declares the allowed variables (`content`, `creator_id`, `created_ts`, `tags`, `visibility`, `has_task_list`, `now`, …), their backing columns, and enables `ext.Sets()`; anything outside the schema is rejected at compile time. A separate `NewAttachmentSchema`/`DefaultAttachmentEngine` exists for attachment filters.
- Per-dialect SQL: the three drivers call the same engine with their own dialect enum — `store/db/sqlite/memo.go:57-61` (`filter.DialectSQLite`), `store/db/mysql/memo.go:65-69` (`filter.DialectMySQL`), `store/db/postgres/memo.go:54-58` (`filter.DialectPostgres`). `internal/filter/helpers.go` compiles each filter with a `PlaceholderOffset` equal to the current arg count and wraps the fragment in parentheses.
- Dialect differences are confined to `render.go`: `?` vs `$n` placeholders, JSON access (`json_extract` / `JSON_EXTRACT` / `->`/`->>`), tag containment (`LIKE` vs `JSON_CONTAINS` vs `@>`), `LIKE` vs `ILIKE`, and regex (`REGEXP` vs `~`, with SQLite's `regexp` implemented in Go at `store/db/sqlite/functions.go`). Timestamp expressions involving `now`/`duration(...)` constant-fold to epoch seconds at compile time.

`internal/filter/README.md` documents this three-phase pipeline (parse → normalize to IR → render) directly.
