**`web/src/connect.ts` (`authInterceptor`, with token storage in `web/src/auth-state.ts`); short-lived JWT access token in the `Authorization: Bearer` header plus an HTTP-only refresh-token cookie (`memos_refresh`) used to mint new access tokens — Personal Access Tokens (`memos_pat_…`) are the third accepted credential; validated by `server/auth`.**

How it works end to end:

**Frontend interceptor.** All Connect-RPC service clients share one transport whose only interceptor is `authInterceptor`:

```156:189:web/src/connect.ts
const authInterceptor: Interceptor = (next) => async (req) => {
  const isRetryAttempt = req.header.get(RETRY_HEADER) === RETRY_HEADER_VALUE;
  const token = await getRequestToken();
  setAuthorizationHeader(req, token);
  // ... on Code.Unauthenticated: refresh once, set X-Retry, replay ...
```

It does a preflight refresh when the access token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` of expiry, and a reactive refresh on a `Code.Unauthenticated` error, retrying the request exactly once (guarded by the `X-Retry` header) before calling `redirectOnAuthFailure()`. Refreshes go through a separate transport with `interceptors: []` so `AuthService.RefreshToken` can't recurse into the interceptor, and `fetchWithCredentials` sets `credentials: "include"` so the refresh cookie is sent. A `tokenRefreshManager` deduplicates concurrent refreshes.

**Tokens it manages.** `web/src/auth-state.ts` holds the access token in memory plus `localStorage` (`memos_access_token` / `memos_token_expires_at`), and broadcasts new tokens to other tabs over a `BroadcastChannel` (`memos_token_sync`). The refresh token itself is never touched by JS — it lives in the cookie that `RefreshToken` reads.

**Backend validation.** Package `auth` in `server/auth` (`token.go`, `authenticator.go`) is the shared validator: `ParseAccessTokenV2` verifies HS256 signature, `kid=v1`, issuer `memos`, audience `user.access-token`, and `type=access` statelessly; `ParseRefreshToken` + `AuthenticateByRefreshToken` additionally check the DB for revocation/expiry; `AuthenticateByPAT` hashes the token with SHA-256 and looks it up. Access tokens last 15 minutes, refresh tokens 30 days. The Connect handler path reaches it via `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`, which delegates to the `Authorizer` (`server/router/api/v1/authz.go`) wrapping `auth.Authenticator`; `server/router/fileserver` uses the same package.
