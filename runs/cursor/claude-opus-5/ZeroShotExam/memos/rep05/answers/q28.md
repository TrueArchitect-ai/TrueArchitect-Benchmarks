**Runners the server actually starts** (`server/server.go`, `startBackgroundRunners` at lines 153–174 — this is the only place the server spawns background work):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — one synchronous `RunOnce(ctx)` at startup, then a goroutine running `Run(ctx)` on a `time.NewTicker` of 12 hours (`runnerInterval = time.Hour * 12`, line 27); cancelled via its own `context.CancelFunc` and awaited on `backgroundRunnerWG` during `Shutdown`.

**Other long-lived goroutines the process ends up running** (not registered in `startBackgroundRunners`, but started as a side effect of construction or package init):

- **HTTP serve loop** (`server/server.go:124`) — goroutine wrapping `httpServer.Serve(listener)`, driven by incoming connections.
- **Cache cleanup loops, three of them** (`store/cache/cache.go:83`, `cleanupLoop` at line 200) — one per cache created in `store.New` (`store/store.go:51-53`: instance settings, users, user settings), each on a ticker of `CleanupInterval = 5 * time.Minute`; stopped by `Store.Close`.
- **Webhook dispatch pool, 4 workers** (`internal/webhook/webhook.go:42-55`) — started in `init()`, so they exist merely because the package is imported; each drains the buffered `asyncPostQueue` channel (capacity 128), fed event-driven by `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43,71`.
- **Email send pool, 2 workers** (`internal/email/email.go:16-36`) — also `init()`-started, draining `asyncEmailQueue` (capacity 128), fed by `email.SendAsync` wired in as the sender in `server/notification/email.go:30`.
- **Per-request/per-event goroutines**: the SSE connection loop's 30-second heartbeat ticker (`server/router/api/v1/sse_handler.go:17,64`), the fire-and-forget PAT last-used update (`server/auth/authenticator.go:180`), and the shutdown-signal watcher in `cmd/memos/main.go:99`. These are triggered by request/signal activity rather than a schedule.

**Unused scheduling infrastructure:**

- **`internal/scheduler`** — a full cron scheduler (cron expression parser in `parser.go`, job registration and per-job timer loops in `scheduler.go`, middleware in `middleware.go`, plus a `README.md` describing it as "production-ready") is **never used by the server**. The only non-test file referencing it is its own `doc.go`; the only importers are `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. Nothing under `cmd/`, `server/`, or `store/` imports it, so `Scheduler.Start()` is never called in a running instance.
- **`memopayload.Runner`** (`server/runner/memopayload/runner.go`) — the runner type and its `RunOnce` bulk payload-rebuild are never invoked; `server/router/api/v1/memo_service.go:108,447` only calls the package-level `RebuildMemoPayload` helper inline during memo create/update. Note this package has no periodic `Run` loop at all, so it is dead runner scaffolding rather than an unscheduled timer.
