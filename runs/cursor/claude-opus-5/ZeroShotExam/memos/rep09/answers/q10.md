`store/migration/sqlite/LATEST.sql`

For a fresh install, the migrator detects an uninitialized database and applies the driver-specific `LATEST.sql` rather than replaying the incremental migrations. In `store/migrator.go` the constant `LatestSchemaFileName = "LATEST.sql"` is joined with the base path `fmt.Sprintf("migration/%s/", s.profile.Driver)`, so for SQLite that resolves to `store/migration/sqlite/LATEST.sql` (embedded via `//go:embed migration`). That file contains the complete current schema — `system_setting`, `user`, `user_setting`, `memo`, and the rest of the tables and indexes. The comment at line 42 of `store/migrator.go` states this explicitly: "LATEST.sql: Full schema for new installations (faster than incremental migrations)."

Note that `store/seed/sqlite/01__dump.sql` is separate; it only seeds demo data and is applied in demo mode after migration.
