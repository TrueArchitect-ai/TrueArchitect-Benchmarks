**Server-Sent Events (SSE) over a plain HTTP `GET /api/v1/sse` stream; hub at `server/router/api/v1/sse_hub.go` (`SSEHub`); broadcasting memo handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `UpsertMemoReaction`, `DeleteMemoReaction`, plus `SetMemoAttachments` and `SetMemoRelations` (both via `dispatchMemoUpdatedSideEffects`).**

Details:

**Mechanism.** SSE, not WebSockets. The endpoint is registered by `RegisterSSERoutes` and served by `handleSSE` in `server/router/api/v1/sse_handler.go`, which authenticates a Bearer token, sets `Content-Type: text/event-stream` (plus `Cache-Control: no-cache`, `X-Accel-Buffering: no`), and then writes `data: <json>\n\n` frames with a `: heartbeat` comment every 30 seconds. The browser side is `web/src/hooks/useLiveMemoRefresh.ts`, which uses `fetch("/api/v1/sse")` with a manual reader rather than `EventSource` (so it can send the `Authorization` header), reconnects with exponential backoff, and invalidates React Query caches per event type.

**Hub.** `server/router/api/v1/sse_hub.go` defines `SSEHub` with a mutex-guarded `clients` map, `Subscribe`/`Unsubscribe`/`Close`, and `Broadcast`. Each `SSEClient` has a 32-event buffered channel; events are dropped for slow clients rather than blocking the broadcaster. `canReceive` filters delivery: `store.Private` events only reach the creator or an admin, while public/protected go to everyone. The hub is held on the API service and closed during shutdown from `server/server.go` (`s.sseHub.Close()`).

**Broadcasting handlers.** Direct `s.SSEHub.Broadcast` calls:

| Handler | File:line | Event |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:163` | `memo.created` (skipped when `isSSESuppressed(ctx)`, i.e. called from `CreateMemoComment`) |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:585` | `memo.deleted` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:126` | `memo.comment.created` |
| `UpsertMemoReaction` | `server/router/api/v1/reaction_service.go:106` | `reaction.upserted` |
| `DeleteMemoReaction` | `server/router/api/v1/reaction_service.go:161` | `reaction.deleted` |

The `memo.updated` event is emitted from the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:71`), which is called by `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`).

Event payloads are built with helpers in `server/router/api/v1/sse_event_helpers.go` (`resolveSSECreatorID`, `buildMemoReactionSSEEvent`), which map a comment's events onto the parent memo's owner so private-parent events stay scoped correctly.
