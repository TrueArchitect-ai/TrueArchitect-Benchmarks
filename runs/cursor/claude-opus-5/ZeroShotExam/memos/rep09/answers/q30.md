- Delivery: `webhook.PostAsync` → `webhook.Post` in `repo/internal/webhook/webhook.go`

All four dispatchers are defined in `repo/server/router/api/v1/memo_service_webhooks.go`. The three plain memo events are thin wrappers over the shared helper `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator, loads that user's webhooks via `s.Store.GetUserWebhooks`, and builds a payload per hook. The comment case is separate because it targets the *parent* memo owner (`relatedMemoCreatorID`) rather than the comment creator, so it has its own loop, but it builds the same `webhook.WebhookRequestPayload`.

Every one of them ends at `webhook.PostAsync(payload)`, which enqueues onto the bounded `asyncPostQueue` channel (capacity 128, dropping with a warning when full). Four worker goroutines started in `init()` drain that queue and call `webhook.Post`, which does the JSON marshal, optional Standard Webhooks HMAC-SHA256 signing (`webhook-id`/`webhook-timestamp`/`webhook-signature` headers), and the actual HTTP POST through the SSRF-guarded `safeClient`.

Call sites, for reference: created at `repo/server/router/api/v1/memo_service.go:157`, deleted at `memo_service.go:562`, updated at `repo/server/router/api/v1/memo_update_helpers.go:67`, and comment created at `repo/server/router/api/v1/memo_service_comments.go:119`. All four log a warning on failure rather than failing the request.
