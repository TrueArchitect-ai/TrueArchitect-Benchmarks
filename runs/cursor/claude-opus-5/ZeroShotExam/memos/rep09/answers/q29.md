**How it works**

The frontend talks to the server over Connect-RPC. `web/src/connect.ts` defines a single `authInterceptor` that is attached to the shared transport used by every service client (`memoServiceClient`, `userServiceClient`, etc.):

```156:189:web/src/connect.ts
const authInterceptor: Interceptor = (next) => async (req) => {
  const isRetryAttempt = req.header.get(RETRY_HEADER) === RETRY_HEADER_VALUE;
  const token = await getRequestToken();
  setAuthorizationHeader(req, token);
  // ... on Unauthenticated: refresh, set X-Retry, retry once, else redirectOnAuthFailure()
```

It sets `Authorization: Bearer <accessToken>`, does a preflight refresh when the token is within 30s of expiry, and on a `Code.Unauthenticated` response refreshes once and retries with an `X-Retry` header before redirecting to login. Refreshes go through a separate `refreshTransport` with no interceptors (to avoid recursion) and are deduplicated by `tokenRefreshManager`.

Token state lives in `web/src/auth-state.ts`: the access token is cached in memory and persisted to `localStorage` (`memos_access_token` / `memos_token_expires_at`), and shared across tabs via a `memos_token_sync` BroadcastChannel. The refresh token itself is never handled by JS — it rides in an HttpOnly cookie, which is why the transport uses `credentials: "include"`. `web/src/hooks/useTokenRefreshOnFocus.ts` additionally refreshes proactively on tab focus with a 2-minute buffer.

**Backend validation**

`server/auth` owns validation. `server/auth/token.go` defines the token kinds and their parsers: access tokens (`ParseAccessTokenV2`, 15 min, audience `user.access-token`, HS256 with `kid: v1`), refresh tokens (`ParseRefreshToken`, 30 days, cookie `memos_refresh`), and Personal Access Tokens (prefix `memos_pat_`, SHA-256 hashed). `server/auth/authenticator.go` resolves a request: bearer tokens are validated statelessly for access tokens or looked up by hash for PATs, while refresh tokens are checked against the database for revocation and expiry. `server/auth/extract.go` pulls the bearer token from the header and the refresh token from the cookie.

That package is consumed by the API interceptor in `server/router/api/v1/authz.go`, plus `server/router/api/v1/sse_handler.go`, `server/router/api/v1/auth_service_session.go`, and `server/router/fileserver/fileserver.go`.
