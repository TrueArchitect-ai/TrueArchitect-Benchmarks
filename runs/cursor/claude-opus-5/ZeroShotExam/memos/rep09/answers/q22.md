The helper resolves the memo's creator, loads that user's webhooks with `s.Store.GetUserWebhooks`, and for each hook builds a payload carrying the hook's URL and signing secret.

**Delivery package.** Delivery is handled by `internal/webhook`. The helper calls `webhook.PostAsync(payload)`, which enqueues onto a buffered channel (`asyncPostQueue`, capacity 128) drained by four goroutines started in `init`; each worker calls `webhook.Post`, which does the actual `http.POST`. Overflow is dropped with a warning rather than blocking the request. The HTTP client is a shared `safeClient` with a 30-second timeout and a custom `safeDialContext` that resolves the host and refuses reserved/private IPs, which blocks SSRF and DNS rebinding (`internal/webhook/webhook.go`).

**Signing.** In `Post`, when the hook has a signing secret, the payload is signed with HMAC-SHA256 over `msgID + "." + timestamp + "." + body`:

```142:149:internal/webhook/webhook.go

		mac.Write([]byte(msgID + "." + timestamp + "."))
		mac.Write(body)
		signature := base64.StdEncoding.EncodeToString(mac.Sum(nil))
```

The key comes from `resolveSigningKey`, which base64-decodes secrets carrying the Standard Webhooks `whsec_` prefix and otherwise uses the secret bytes verbatim; `GenerateSigningSecret` mints new secrets as `whsec_<base64 of 32 random bytes>`.
