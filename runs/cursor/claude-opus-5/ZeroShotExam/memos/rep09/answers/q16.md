`Store.DeleteMemo` cleans up two kinds of dependent records before issuing the actual `DELETE FROM memo`:

- **Memo relations, in both directions** — one call removes rows where the memo is the source (`MemoID`), a second removes rows where it is the target (`RelatedMemoID`).
- **Attachments linked to the memo** — it lists attachments by `MemoID` and deletes each one through `Store.DeleteAttachment`, which also removes the backing file/object from storage (`store/attachment.go` lines 132–149) before deleting the attachment row.

Only after both of those does it call `s.driver.DeleteMemo`, which runs the plain `DELETE FROM memo WHERE id = ?` (see `store/db/sqlite/memo.go` line 237, with equivalents in the postgres and mysql drivers).
