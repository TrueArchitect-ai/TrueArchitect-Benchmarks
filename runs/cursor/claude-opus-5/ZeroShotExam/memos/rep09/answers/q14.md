`ShortcutService` has five RPCs, all implemented in a single backend file.

**RPCs** (defined in `proto/api/v1/shortcut_service.proto`, lines 14–52):

| RPC | Request → Response | HTTP mapping |
| --- | --- | --- |
| `ListShortcuts` | `ListShortcutsRequest` → `ListShortcutsResponse` | `GET /api/v1/{parent=users/*}/shortcuts` |
| `GetShortcut` | `GetShortcutRequest` → `Shortcut` | `GET /api/v1/{name=users/*/shortcuts/*}` |
| `CreateShortcut` | `CreateShortcutRequest` → `Shortcut` | `POST /api/v1/{parent=users/*}/shortcuts` |
| `UpdateShortcut` | `UpdateShortcutRequest` → `Shortcut` | `PATCH /api/v1/{shortcut.name=users/*/shortcuts/*}` |
| `DeleteShortcut` | `DeleteShortcutRequest` → `google.protobuf.Empty` | `DELETE /api/v1/{name=users/*/shortcuts/*}` |

**Implementing file:** `server/router/api/v1/shortcut_service.go` — all five are methods on `*APIV1Service` (`ListShortcuts` at line 49, `GetShortcut` at 95, `CreateShortcut` at 135, `UpdateShortcut` at 211, `DeleteShortcut` at 284).

Two things worth noting about the implementation: shortcuts aren't stored in their own table (the `shortcut` table was dropped in `store/migration/sqlite/0.16/01__drop_shortcut_table.sql`) but as a `UserSetting_SHORTCUTS` user setting, and the same file also holds the helpers `extractUserAndShortcutIDFromName`, `constructShortcutName`, and `validateFilter`, which compiles the CEL filter against the active SQL dialect. Generated stubs live in `proto/gen/api/v1/shortcut_service_grpc.pb.go` and `proto/gen/api/v1/shortcut_service.pb.gw.go`, and tests are in `server/router/api/v1/test/shortcut_service_test.go`.
