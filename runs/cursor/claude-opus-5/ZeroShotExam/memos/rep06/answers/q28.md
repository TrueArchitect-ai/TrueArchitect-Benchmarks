**Runners the server actually starts** (`Server.Start` → `startBackgroundRunners`, `server/server.go:101-174`):

- **HTTP/Echo server** (`server/server.go:123-128`) — event-driven; goroutine blocks in `httpServer.Serve(listener)`, woken by incoming connections. Torn down by `shutdownHTTPServer` (`server/server.go:142`).
- **s3presign runner, one-shot pass** (`server/server.go:162-163`) — runs synchronously exactly once at startup via `s3presignRunner.RunOnce(ctx)`, so freshly-started instances re-presign attachment URLs immediately instead of waiting for the first tick.
- **s3presign runner, periodic loop** (`server/server.go:166-171`, implemented at `server/runner/s3presign/runner.go:29-41`) — `time.NewTicker` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27`), each tick calling `RunOnce`; exits on its own cancelable context, which `stopBackgroundRunners` cancels (`server/server.go:156-159, 176-182`).

This is the entire content of `startBackgroundRunners`: **s3presign is the only named runner the server registers.**

**Workers started elsewhere in the same process** (not by `startBackgroundRunners`, but live whenever the binary runs):

- **Three store cache cleanup loops** — instance settings, users, user settings (`store/store.go:51-53`, each spawning `go c.cleanupLoop()` at `store/cache/cache.go:83`, loop at `store/cache/cache.go:199-214`) — `time.NewTicker(CleanupInterval)`, configured to 5 minutes at `store/store.go:42`. Started from `store.New()`, called in `cmd/memos/main.go:64`.
- **Webhook dispatch pool, 4 goroutines** (`internal/webhook/webhook.go:42-55`) — package `init()`, so it starts on import (`cmd/memos/main.go:18`); queue-driven, ranging over the 128-buffered `asyncPostQueue` channel fed by `PostAsync`.
- **Email send pool, 2 goroutines** (`internal/email/email.go:16-36`) — also package `init()`, pulled in transitively via `server/notification/email.go:11`; queue-driven over the 128-buffered `asyncEmailQueue`.
- **Signal handler** (`cmd/memos/main.go:99-103`) — blocks on the `signal.Notify` channel for SIGINT/SIGTERM, then calls `Shutdown`.

**Unused scheduling infrastructure:** `internal/scheduler/` is a complete cron-style job scheduler — `Scheduler` with `Register`/`Start`/`Stop` and per-job goroutines (`internal/scheduler/scheduler.go`), a `Job` type carrying a cron `Schedule` string (`internal/scheduler/job.go`), a 5- and 6-field cron expression parser (`internal/scheduler/parser.go`), recovery/logging/timeout middleware (`internal/scheduler/middleware.go`), plus docs (`internal/scheduler/doc.go`, `internal/scheduler/README.md`). **The server never uses it.** Grepping the module for its import path returns hits only from its own tests, `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13` — nothing in `server/`, `cmd/`, or `store/`. The server's one periodic job uses a hand-rolled `time.Ticker` instead of this scheduler.

One related note: `server/runner/memopayload/` also sits under the runner directory and defines `NewRunner`/`RunOnce` for a batch rebuild of all memo payloads (`server/runner/memopayload/runner.go:19-72`), but that `Runner` is never instantiated anywhere. Only its free function `RebuildMemoPayload` is used, called synchronously inside memo create/update handlers (`server/router/api/v1/memo_service.go:108` and `:447`).
