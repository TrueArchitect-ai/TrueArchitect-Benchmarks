**Engine:** Google's CEL (Common Expression Language) via `github.com/google/cel-go`, wrapped by the in-repo filter engine at `internal/filter/` (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`, `helpers.go`).

**Mechanism (one sentence):** `Engine.Compile` type-checks the filter string against a memo-specific CEL environment (`internal/filter/schema.go`, which declares variables like `content`, `tags`, `visibility`, `created_ts`, `now`, plus `ext.Sets()`), converts the CEL AST into a dialect-agnostic condition IR (`internal/filter/parser.go` → `internal/filter/ir.go`), and then `Program.Render` walks that IR with a dialect-aware renderer (`internal/filter/render.go`) to emit a SQL fragment plus bound args for `DialectSQLite`, `DialectMySQL`, or `DialectPostgres`.

How it hangs together end to end:

- `ListMemos` in `server/router/api/v1/memo_service.go` (around line 211) validates `request.Filter` via `validateFilter` (defined in `server/router/api/v1/shortcut_service.go:336`, which compiles the filter against the engine using the driver's dialect) and appends it to `memoFind.Filters`; it also injects a synthesized visibility filter like `creator_id == %d || visibility in ["PUBLIC", "PROTECTED"]` using the same syntax.
- Each store driver — `store/db/sqlite/memo.go:57`, `store/db/postgres/memo.go:54`, `store/db/mysql/memo.go:65` — grabs `filter.DefaultEngine()` and calls `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)`.
- `AppendConditions` in `internal/filter/helpers.go` calls `CompileToStatement` per filter with a `PlaceholderOffset` equal to the current arg count, then appends `(<sql>)` to the WHERE list and the args to the arg list. The offset is what makes Postgres `$n` numbering line up with pre-existing args, while SQLite/MySQL use `?`.
- Dialect differences are localized in the renderer: JSON tag membership becomes `LIKE` patterns on SQLite, `JSON_CONTAINS` on MySQL, and `@>` on Postgres; regex becomes `REGEXP` vs `~`; string length becomes `LENGTH` vs `CHAR_LENGTH`. A few field expressions are also dialect-templated directly in the schema (e.g. `creator` maps to `('users/' || %s)` on SQLite and `CONCAT('users/', %s)` on MySQL, per `internal/filter/schema.go:104`).

One detail worth noting: time expressions (`now`, `duration("24h")`, `timestamp(...)`) are constant-folded to epoch seconds at compile time, with `now` frozen once per compile so a single filter sees one instant. `internal/filter/README.md` documents the three-phase pipeline and the per-dialect SQL generation rules in detail.
