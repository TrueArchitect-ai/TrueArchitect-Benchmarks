**Convergence for delivery**

The first three are thin wrappers over the shared helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the memo creator, loads their webhooks via `s.Store.GetUserWebhooks`, and builds a payload per hook. The comment event doesn't use that helper (it looks up the *related* memo owner's hooks instead), but it builds the same payload.

Every one of the four then converges on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue` channel. Four worker goroutines started in that package's `init` drain the queue and perform the actual HTTP delivery through `webhook.Post` (`internal/webhook/webhook.go:120`), where the request is signed (Standard Webhooks `webhook-id` / `webhook-timestamp` / `webhook-signature` headers) and sent via the SSRF-guarded `safeClient`.
