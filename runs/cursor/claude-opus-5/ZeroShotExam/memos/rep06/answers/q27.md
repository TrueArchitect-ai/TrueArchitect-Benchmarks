**Answer: Go `embed.FS` (compiled into the binary) served by Echo's static middleware with an SPA fallback; `server/router/frontend/frontend.go`**

How it works end to end:

1. **Build step writes into the Go package.** `pnpm release` in `web/package.json` runs `vite build --mode release --outDir=../server/router/frontend/dist --emptyOutDir`, so the compiled SPA lands in `server/router/frontend/dist` (documented in `AGENTS.md` line 46, and uploaded/downloaded as the `frontend-dist` artifact by `.github/workflows/release.yml` and `.github/workflows/build-canary-image.yml`).

2. **The directory is embedded into the binary** at compile time:

```20:21:server/router/frontend/frontend.go
//go:embed dist/*
var embeddedFiles embed.FS
```

The repo checks in a placeholder `server/router/frontend/dist/index.html` reading "No embeddable frontend found." so the embed directive still compiles when the frontend hasn't been built.

3. **It's served over HTTP** by `FrontendService.Serve`, which subs the embedded FS at `dist` and registers Echo's static middleware plus a fallback that returns `index.html` for any 404 on a non-asset path (client-side routing), while skipping `/api`, `/file`, Connect RPC paths, `robots.txt`, `sitemap.xml`, and `rss.xml`:

```41:61:server/router/frontend/frontend.go
func (s *FrontendService) Serve(_ context.Context, e *echo.Echo) {
	frontendFS := getFileSystem("dist")
	// ... cache-header skipper ...
	e.Use(middleware.StaticWithConfig(middleware.StaticConfig{
		Filesystem: frontendFS,
		Skipper:    skipper,
	}))

	e.Use(spaFallbackMiddleware(frontendFS))
	s.registerRoutes(e)
}
```

4. **Wired into the server** at startup in `server/server.go`:

```71:72:server/server.go
	// Serve frontend static files.
	frontend.NewFrontendService(profile, store).Serve(ctx, echoServer)
```

Cache policy is set alongside: HTML gets `no-cache, no-store, must-revalidate`, hashed files under `/assets/` get `public, max-age=3600, immutable`, other static files get `public, max-age=3600` (`server/router/frontend/frontend.go` lines 23-27, 92-105). There is no separate nginx or CDN layer in the repo — the same Go binary serves both the API and the frontend.
