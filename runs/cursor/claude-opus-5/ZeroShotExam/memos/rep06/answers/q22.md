HTTP delivery is done by the `internal/webhook` package (`github.com/usememos/memos/internal/webhook`) in `internal/webhook/webhook.go`. `PostAsync` enqueues onto a buffered channel of size 128 drained by four background goroutines that call `Post`; if the queue is full the dispatch is dropped with a warning. `Post` marshals the payload to JSON and POSTs it with Go's `net/http` through a shared `safeClient` whose 30-second timeout and custom `safeDialContext` reject connections that resolve to reserved or private IP ranges (SSRF and DNS-rebinding protection).

Signing follows the Standard Webhooks scheme with HMAC-SHA256. Secrets are generated as `whsec_<base64 of 32 random bytes>` by `GenerateSigningSecret`, and `resolveSigningKey` base64-decodes the `whsec_` payload to raw key bytes (erroring loudly on invalid base64). The MAC is computed over `msgID + "." + timestamp + "." + body`, and the result is base64-encoded into three headers:

```147:149:internal/webhook/webhook.go
		req.Header.Set("webhook-id", msgID)
		req.Header.Set("webhook-timestamp", timestamp)
		req.Header.Set("webhook-signature", "v1,"+signature)
```

Signing is skipped when the hook has no `SigningSecret`. Comment creation uses a sibling dispatcher, `DispatchMemoCommentCreatedWebhook`, in the same file, which notifies the parent memo owner's webhooks with activity type `memos.memo.comment.created`.
