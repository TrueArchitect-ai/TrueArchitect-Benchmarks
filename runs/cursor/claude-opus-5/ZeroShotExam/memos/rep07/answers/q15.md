The three tables map to plain Go structs in the `store` package (this codebase writes raw SQL per driver rather than using an ORM with `TableName()` methods).

| Table | Struct — path |
| --- | --- |
| `user` | `store.User` — `store/user.go` (lines 29–45) |
| `attachment` | `store.Attachment` — `store/attachment.go` (lines 16–41) |
| `reaction` | `store.Reaction` — `store/reaction.go` (lines 7–14) |

How I confirmed the mapping: the tables are declared in `store/migration/sqlite/LATEST.sql` (`CREATE TABLE user`, `attachment`, `reaction`), and the driver layers scan those rows directly into these structs — for example `store/db/sqlite/user.go` selects `FROM user` into `store.User`, `store/db/sqlite/attachment.go` populates `store.Attachment`, and `store/db/sqlite/reaction.go` selects `FROM reaction` into `store.Reaction`. The Postgres driver under `store/db/postgres/` mirrors the same mapping.

Two details worth noting: `store.Attachment` includes a composed field `MemoUID` that comes from a join rather than the `attachment` table itself, and `store.User` is separate from the related-but-distinct `user_setting` and `user_identity` tables, which have their own structs in `store/user_setting.go` and `store/user_identity.go`.
