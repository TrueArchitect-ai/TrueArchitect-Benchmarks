**Runners the server actually starts**

- **HTTP/Echo server goroutine** — event-driven; blocks on `http.Server.Serve(listener)` and wakes per incoming connection. Started unconditionally in `Start()` (`server/server.go:123-128`).
- **S3 presign runner, boot pass** — run-once at startup. `startBackgroundRunners` calls `s3presignRunner.RunOnce(ctx)` synchronously before launching the loop (`server/server.go:162-163`).
- **S3 presign runner, periodic loop** — `time.NewTicker` at a fixed 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`), launched as a goroutine at `server/server.go:166-171`. Because it's a plain ticker, the first tick is 12h after boot; the immediate work is covered by the separate `RunOnce` above. It's always started (no demo-mode or feature gate); only the work inside `CheckAndPresign` is skipped when storage isn't S3.

**Background workers running in the process but not started by `Start()`**

- **Three store cache cleanup loops** (instance settings, users, user settings) — `time.NewTicker` at `CleanupInterval = 5 * time.Minute`, started by `cache.New` from `store.New` before the server exists (`store/store.go:38-53`, `store/cache/cache.go:83`, `store/cache/cache.go:199-201`). Stopped via `Store.Close()` during shutdown.
- **Two async email workers** — channel-driven, draining a buffered `chan asyncEmailRequest` of capacity 128; spawned in a package `init()` (`internal/email/email.go:14-35`).
- **Four async webhook workers** — channel-driven on `chan *WebhookRequestPayload` (capacity 128), also spawned in a package `init()` (`internal/webhook/webhook.go:39-54`).
- **Signal handler goroutine** — waits on SIGINT/SIGTERM to call `Shutdown` (`cmd/memos/main.go:99-103`). Not periodic.
- **SSE heartbeat ticker** — 30 seconds, but per connected client rather than a server singleton (`server/router/api/v1/sse_handler.go:17,64`).

**Unused scheduling infrastructure**

There is a complete cron scheduler package at `internal/scheduler/` (`scheduler.go` with `Start`/`Stop` and per-job `time.NewTimer`, `parser.go` for 5- and 6-field cron expressions, `job.go`, `middleware.go`, plus a README and doc.go) that the server never touches. The only non-test importers are its own tests: `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. Nothing under `server/`, `cmd/`, or `store/` calls `scheduler.New`, `Register`, or `Start`, so all real scheduling is done with ad-hoc `time.Ticker` loops instead.

Relatedly, `server/runner/memopayload/` is a "runner" in name only — it exposes just `RunOnce`/`RebuildMemoPayload` with no loop or ticker, and it's invoked inline from request handlers in `server/router/api/v1/memo_service.go`, not from `startBackgroundRunners`. There are no third-party cron dependencies (`robfig/cron`, `gocron`, etc.) in `go.mod` or `go.sum`.
