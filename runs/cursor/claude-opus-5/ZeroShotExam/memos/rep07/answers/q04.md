`APIV1Service.SignIn` — `server/router/api/v1/auth_service.go` (line 51) is the function that implements the SignIn RPC's business logic.

How it fits together:

- The Connect RPC entry point is `ConnectServiceHandler.SignIn` in `server/router/api/v1/connect_services.go` (line 78), but it is a thin wrapper: it wraps the context with `connectWithHeaderCarrier` (so cookies can be set protocol-agnostically) and immediately delegates to `s.APIV1Service.SignIn(ctx, req.Msg)`.
- `APIV1Service.SignIn` does the real work: password authentication via `bcrypt.CompareHashAndPassword` plus a `DisallowPasswordAuth` check, or SSO authentication via `resolveSSOIdentity`/`resolveSSOUser`, then rejects archived users and calls `doSignIn` (in `server/router/api/v1/auth_service_session.go`) to mint the access token and refresh cookie.
- Everything under `proto/gen/api/v1/` (`auth_service.connect.go`, `auth_service_grpc.pb.go`) is generated stub/interface code, not the handler.
