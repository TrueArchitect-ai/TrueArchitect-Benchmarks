**Engine:** Google CEL (`cel-go` v0.28.1, per `go.mod:13`), wrapped by the in-house filter engine at `internal/filter/` (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`, `helpers.go`).

**Mechanism in one sentence:** The filter string is compiled by `cel-go` against a memo-specific CEL environment/field schema, normalized into a dialect-agnostic condition IR, then walked by a renderer that emits a dialect-specific SQL fragment plus bind args, which each driver appends to its `WHERE` clause.

How that plays out concretely:

- `ListMemos` in `server/router/api/v1/memo_service.go:211-216` validates `request.Filter` via `validateFilter` (defined at `server/router/api/v1/shortcut_service.go:336`, which compiles it against the driver's dialect as an early argument check) and then stashes the raw string in `store.FindMemo.Filters`.
- Compilation happens in `internal/filter/engine.go`: `Engine.Compile` runs `env.Compile(filter)`, converts to a parsed expr, and calls `buildCondition` (`parser.go`) to produce the IR from `ir.go`, enforcing schema rules from `schema.go` (only declared fields, allowed operators, type checks). `DefaultEngine()` is a process-wide lazily built engine using `NewSchema()`.
- Rendering happens in `internal/filter/render.go`: `Program.Render` creates a `renderer` carrying the `DialectName` (`sqlite`, `mysql`, `postgres` from `schema.go:14-16`) and a placeholder counter/offset, returning `Statement{SQL, Args}`.
- Each driver calls `filter.DefaultEngine()` then `filter.AppendConditions(...)` (`internal/filter/helpers.go:9`) with its own dialect constant: `store/db/sqlite/memo.go:57-61` (`DialectSQLite`), `store/db/postgres/memo.go:54-58` (`DialectPostgres`), `store/db/mysql/memo.go:65-69` (`DialectMySQL`). `AppendConditions` wraps each fragment in parentheses, appends it to the `where` slice, and passes `PlaceholderOffset: len(args)` so Postgres `$n` numbering lines up with the args already accumulated.
- Dialect differences are encapsulated in renderer helpers: `?` vs `$n` placeholders, JSON access on `memo.payload` (`json_extract` / `->>` / `JSON_CONTAINS` / `@>`), `LIKE` vs `ILIKE`, `LENGTH` vs `CHAR_LENGTH`, regex `~` vs `REGEXP` (SQLite's `regexp` is a Go-backed function registered in `store/db/sqlite/functions.go`), and date-part extraction (`strftime` / `EXTRACT` / `YEAR`). Timestamp expressions using `now`, `duration(...)`, and `timestamp(...)` are constant-folded to epoch seconds at compile time. This is all documented in `internal/filter/README.md`.
