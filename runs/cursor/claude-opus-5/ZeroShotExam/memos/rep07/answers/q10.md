**`store/migration/sqlite/LATEST.sql`**

On a fresh (uninitialized) SQLite database, the migrator applies this single file as the full schema instead of replaying the incremental version directories. The relevant logic lives in `store/migrator.go`, which documents the flow and defines the filename constant:

```42:56:/bench/repo/store/migrator.go
// - LATEST.sql: Full schema for new installations (faster than incremental migrations)
...
	LatestSchemaFileName = "LATEST.sql"
```

The per-driver migration files are embedded under `store/migration/<driver>/`, so the SQLite copy is `store/migration/sqlite/LATEST.sql` (the Postgres and MySQL equivalents are `store/migration/postgres/LATEST.sql` and `store/migration/mysql/LATEST.sql`). This is also the contract described in `AGENTS.md`, which requires updating each driver's `LATEST.sql` alongside any new migration, and it's exercised by `TestFreshInstall` in `store/test/migrator_test.go`.
