`ShortcutService` has five RPCs, all implemented in a single backend file.

**RPCs** (declared in `proto/api/v1/shortcut_service.proto`, lines 14–52):

| RPC | HTTP mapping | Response |
| --- | --- | --- |
| `ListShortcuts` | `GET /api/v1/{parent=users/*}/shortcuts` | `ListShortcutsResponse` |
| `GetShortcut` | `GET /api/v1/{name=users/*/shortcuts/*}` | `Shortcut` |
| `CreateShortcut` | `POST /api/v1/{parent=users/*}/shortcuts` | `Shortcut` |
| `UpdateShortcut` | `PATCH /api/v1/{shortcut.name=users/*/shortcuts/*}` | `Shortcut` |
| `DeleteShortcut` | `DELETE /api/v1/{name=users/*/shortcuts/*}` | `google.protobuf.Empty` |

**Implementing file:** `server/router/api/v1/shortcut_service.go` — all five are methods on `*APIV1Service` there (`ListShortcuts` at line 49, `GetShortcut` at 95, `CreateShortcut` at 135, `UpdateShortcut` at 211, `DeleteShortcut` at 284). The same file also holds the helpers `extractUserAndShortcutIDFromName`, `constructShortcutName`, and `validateFilter`.

Worth noting for context: shortcuts are not stored in their own table (it was dropped in `store/migration/sqlite/0.16/01__drop_shortcut_table.sql`); they persist inside the user setting `UserSetting_SHORTCUTS`, which is why every handler goes through `s.Store.GetUserSetting`/`UpsertUserSetting`. The generated code lives in `proto/gen/api/v1/shortcut_service_grpc.pb.go`, `proto/gen/api/v1/shortcut_service.pb.gw.go`, and `proto/gen/api/v1/apiv1connect/shortcut_service.connect.go`, and tests are in `server/router/api/v1/test/shortcut_service_test.go`.
