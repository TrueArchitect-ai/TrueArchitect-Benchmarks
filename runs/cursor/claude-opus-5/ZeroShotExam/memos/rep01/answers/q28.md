**The only thing `Server.Start` explicitly starts is the S3 presign runner** — everything else that runs in the background comes up as a side effect of package `init()` or object construction, and the repo's own cron scheduler package is entirely unused.

**Started by the server's own startup path** (`server/server.go:129` → `startBackgroundRunners`, lines 153–174):

- s3presign runner — `RunOnce` fires once synchronously at startup, then a goroutine loops on a 12-hour `time.Ticker` (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`); it gets its own cancelable child context, cancelled in `stopBackgroundRunners` and awaited via `backgroundRunnerWG`.
- HTTP serve goroutine — `server/server.go:124`, not scheduled; it just serves the listener until `Shutdown`.

**Background goroutines that come up with the process, outside `startBackgroundRunners`:**

- Store cache cleanup loops (3 of them: instance settings, users, user settings) — 5-minute `CleanupInterval` ticker; each is launched by `cache.New` itself (`store/cache/cache.go:83`, loop at 199–215) when `store.New` builds the caches (`store/store.go:40-53`), and stopped by `Store.Close` (`store/store.go:72-79`).
- Webhook dispatch worker pool (4 workers) — started in `internal/webhook/webhook.go:42-55` package `init()`; queue-driven, consuming a 128-buffered channel fed by `webhook.PostAsync` from memo create/update/delete events (`server/router/api/v1/memo_service_webhooks.go:43,71`).
- Email send worker pool (2 workers) — started in `internal/email/email.go:16-36` package `init()`; queue-driven off a 128-buffered channel fed by `email.SendAsync` (`server/notification/email.go:30`).
- SSE heartbeat ticker — 30-second `sseHeartbeatInterval` ticker created per connected client inside the request handler (`server/router/api/v1/sse_handler.go:17,64`), so it is request-scoped rather than a server-wide worker.
- PAT last-used timestamp update — a one-shot goroutine spawned per authenticated request (`server/auth/authenticator.go:179-185`), fire-and-forget with no scheduling.

**Unused scheduling infrastructure:**

- `internal/scheduler` — a full cron scheduler (5- and 6-field cron parser, timezone support, middleware, graceful shutdown; `scheduler.go`, `parser.go`, `middleware.go`, documented in `internal/scheduler/README.md`) is never imported outside its own package. Grepping the whole tree for `scheduler` finds hits only inside `internal/scheduler/` itself plus its README example, so no job is ever registered and `Scheduler.Start` is never called by the server. The one recurring server job, s3presign, uses a hand-rolled `time.Ticker` instead.
- `memopayload.Runner` — `NewRunner`/`RunOnce`, which rebuild payloads for all memos in batches (`server/runner/memopayload/runner.go:19-72`), are never instantiated or started anywhere. Only the free function `memopayload.RebuildMemoPayload` is used, called inline during memo create and update (`server/router/api/v1/memo_service.go:108,447`). So `server/runner/` contains two runners but just one is actually run as a runner.
