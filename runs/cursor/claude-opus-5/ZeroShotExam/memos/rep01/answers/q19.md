MemoService is exposed over **gRPC-Gateway REST/HTTP-JSON** and **Connect RPC** (Connect protocol over HTTP, which also accepts gRPC/gRPC-Web wire formats). Both are wired up in `RegisterGateway`:

**gRPC-Gateway (REST/HTTP-JSON) — `server/router/api/v1/v1.go`**

The generated gateway handler is registered directly against the service implementation on the `runtime.ServeMux`, which is then mounted onto Echo at `/api/v1/*` and `/file/*`:

```108:110:server/router/api/v1/v1.go
	if err := v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s); err != nil {
		return err
	}
```

The generated gateway code itself lives in `proto/gen/api/v1/memo_service.pb.gw.go`.

**Connect RPC — `server/router/api/v1/connect_handler.go`** (plus the per-method wrappers in `server/router/api/v1/connect_services.go`)

`ConnectServiceHandler` embeds `*APIV1Service` and each Connect method unwraps `req.Msg`, delegates to the gRPC implementation, and re-wraps the result (see the `// MemoService` section starting at line 304 of `connect_services.go`). Registration happens here:

```40:40:server/router/api/v1/connect_handler.go
		wrap(apiv1connect.NewMemoServiceHandler(s, opts...)),
```

The resulting `http.ServeMux` is mounted on Echo under the `/memos.api.v1.*` path prefix in `v1.go` (line 144), and the generated Connect handler constructor is in `proto/gen/api/v1/apiv1connect/memo_service.connect.go`.

Two things worth noting: there is no plain gRPC socket listener in this repo — `APIV1Service` embeds `v1pb.UnimplementedMemoServiceServer` and is used as the shared implementation for both HTTP surfaces rather than being registered on a `grpc.Server`. And the MCP router (`server/router/mcp/catalog.go`) allow-lists `MemoService_*` operation IDs, but those are derived from the generated OpenAPI spec and proxy through the REST gateway above, so MCP is not a third independent registration of the service.
