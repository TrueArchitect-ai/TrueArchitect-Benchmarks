**`APIV1Service.SignIn` — `server/router/api/v1/auth_service.go`** (defined at line 51)

This is the real implementation of the `SignIn` RPC declared in the `AuthService` proto. It handles both authentication paths — password credentials (username lookup plus a bcrypt comparison, gated by the `DisallowPasswordAuth` instance setting) and SSO/OAuth2 credentials (via `resolveSSOIdentity` and `resolveSSOUser`) — then rejects archived users and calls `doSignIn` to mint the access token.

Two related pieces of plumbing worth knowing about:

- `server/router/api/v1/connect_services.go` line 78 has `ConnectServiceHandler.SignIn`, but it is only a thin Connect-protocol adapter that wraps the call in `connectWithHeaderCarrier` (so the service can set the refresh-token cookie header) and delegates straight to `s.APIV1Service.SignIn`.
- `server/router/api/v1/auth_service_session.go` line 24 holds the `doSignIn` helper that generates the token and creates the session.

Everything under `proto/gen/api/v1/` is generated code (interfaces, stubs, and the gRPC/gateway dispatch functions), not the handler itself.
