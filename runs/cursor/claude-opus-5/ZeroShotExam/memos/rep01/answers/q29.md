**Answer:** `web/src/connect.ts` (the `authInterceptor`, with token storage in `web/src/auth-state.ts`); short‑lived JWT access tokens (sent as `Authorization: Bearer`) plus an HTTP‑only refresh‑token cookie (`memos_refresh`), with Personal Access Tokens also accepted as bearer credentials; `server/auth`.

### How it works

The frontend talks to the backend over Connect RPC. A single `Interceptor` named `authInterceptor` is registered on the shared transport, so every service client goes through it:

```156:189:web/src/connect.ts
const authInterceptor: Interceptor = (next) => async (req) => {
  const isRetryAttempt = req.header.get(RETRY_HEADER) === RETRY_HEADER_VALUE;
  const token = await getRequestToken();
  setAuthorizationHeader(req, token);

  try {
    return await next(req);
  } catch (error) {
    // ... on Unauthenticated: refresh once, set X-Retry, retry ...
  }
};

const transport = createConnectTransport({
  baseUrl: window.location.origin,
  useBinaryFormat: true,
  fetch: fetchWithCredentials,
  interceptors: [authInterceptor],
});
```

The interceptor attaches `Authorization: Bearer <access token>`, refreshes proactively when the token is within 30 seconds of expiry, and reactively refreshes once on a `Code.Unauthenticated` error before redirecting via `redirectOnAuthFailure()`. Refreshes go through a dedicated `refreshTransport` with no interceptors to avoid recursion, and a `tokenRefreshManager` deduplicates concurrent refreshes.

Tokens are managed in `web/src/auth-state.ts`: the access token and its expiry are cached in memory and persisted to `localStorage` under `memos_access_token` / `memos_token_expires_at`, and a `BroadcastChannel` (`memos_token_sync`) shares newly refreshed tokens across tabs. The refresh token itself is never handled by JavaScript — it rides along as a cookie because `fetchWithCredentials` sets `credentials: "include"`.

### Backend validation

The `server/auth` package owns validation, and its own docstring states it serves both the Connect/gRPC interceptors and the file server:

```1:52:server/auth/token.go
// Package auth provides authentication and authorization for the Memos server.
//
// Authentication methods supported:
// - JWT access tokens: Short-lived tokens (15 minutes) for API access
// - JWT refresh tokens: Long-lived tokens (30 days) for obtaining new access tokens
// - Personal Access Tokens (PAT): Long-lived tokens for programmatic access
```

Access tokens are validated statelessly by signature (`AuthenticateByAccessTokenV2`), while refresh tokens are checked against the database for revocation (`AuthenticateByRefreshToken`). `server/auth/extract.go` pulls the bearer token from the header and the refresh token from the `memos_refresh` cookie. The request path is `AuthInterceptor.WrapUnary` in `server/router/api/v1/connect_interceptors.go`, which delegates to the `Authorizer` in `server/router/api/v1/authz.go`, which in turn calls `auth.Authenticator.Authenticate` and stores the result on the context with `auth.ApplyToContext`.
