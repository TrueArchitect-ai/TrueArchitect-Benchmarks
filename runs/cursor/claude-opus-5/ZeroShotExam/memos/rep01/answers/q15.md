There's no ORM here — the models are plain structs in the `store` package, and the per-dialect drivers under `store/db/{sqlite,postgres,mysql}` write the raw SQL that names the tables and scan rows into those same structs.

| Table | Struct — path |
| --- | --- |
| `user` | `store.User` — `store/user.go` (line 29) |
| `attachment` | `store.Attachment` — `store/attachment.go` (line 16) |
| `reaction` | `store.Reaction` — `store/reaction.go` (line 7) |

The mapping is confirmed by the driver code, where the SQL statement naming each table reads into or writes from the corresponding struct: `INSERT INTO user ...` / `FROM user` with `store.User` in `store/db/sqlite/user.go`, `FROM attachment` with `store.Attachment` in `store/db/sqlite/attachment.go` (and `store/db/postgres/attachment.go`), and `FROM reaction` with `store.Reaction` in `store/db/sqlite/reaction.go` (and the postgres/mysql equivalents).
