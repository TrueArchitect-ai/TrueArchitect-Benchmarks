**Mechanism:** Server-Sent Events (SSE) over plain HTTP — a `GET /api/v1/sse` endpoint that sets `Content-Type: text/event-stream`, authenticates via the `Authorization` Bearer header, and keeps the connection open with a `: heartbeat` comment every 30 seconds (`server/router/api/v1/sse_handler.go`). The browser side consumes it with an `EventSource`-style connection in `web/src/hooks/useLiveMemoRefresh.ts`.

**Hub path:** `server/router/api/v1/sse_hub.go` — defines `SSEHub` (a mutex-guarded set of `SSEClient`s), `NewSSEHub`, `Subscribe`/`Unsubscribe`/`Close`, and `Broadcast`, which marshals an `SSEEvent` to JSON and fans it out to every client whose `canReceive` check passes (private memos only reach the creator or an admin). Each client has a 32-event buffer and events are dropped rather than blocking a slow reader. The hub is constructed in `server/router/api/v1/v1.go` and routes are registered there via `RegisterSSERoutes`.
