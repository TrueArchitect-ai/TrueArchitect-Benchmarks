**Go `embed.FS` (compiled-in static files served by Echo's static middleware plus an SPA `index.html` fallback); `server/router/frontend/frontend.go`**

The details:

- `server/router/frontend/frontend.go` declares `//go:embed dist/*` into an `embed.FS`, so the built assets are compiled directly into the `memos` binary — there is no separate web server or external static directory.
- `FrontendService.Serve` takes an `fs.Sub` of that embedded tree rooted at `dist`, registers it with `middleware.StaticWithConfig`, and adds `spaFallbackMiddleware`, which serves `index.html` on any 404 for extension-less paths so client-side routes work. API-ish prefixes (`/api`, `/file`, `/memos.api.v1...`), plus `robots.txt`, `sitemap.xml`, and `rss.xml`, are skipped so they fall through to real handlers. Cache headers are set per path: no-store for HTML, one hour for static files, and one hour immutable for hashed assets under `/assets/`.
- It's wired into the server at `server/server.go:72` via `frontend.NewFrontendService(profile, store).Serve(ctx, echoServer)`.
- The `dist` directory is populated before the Go build: `web/package.json` has `"release": "vite build --mode release --outDir=../server/router/frontend/dist --emptyOutDir"`, and `scripts/Dockerfile` notes at line 15 that the frontend must be built first. The release workflows upload/download that path as the `frontend-dist` artifact (`.github/workflows/release.yml`).
