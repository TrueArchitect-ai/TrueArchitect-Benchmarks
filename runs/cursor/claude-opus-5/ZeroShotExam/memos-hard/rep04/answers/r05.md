**Premise correction:** There is no GraphQL schema in this repository. A case-insensitive search across the entire tree (excluding `.git`) for "graphql"/"gql" returns zero matches, and there are no `.graphql`, `.gql`, or `.graphqls` files. This is Memos, and `README.md` line 22 describes it as offering "full REST and gRPC APIs" — no GraphQL layer exists.

**Actual API surface:** The public API is defined as Protocol Buffers service definitions in `proto/api/v1/`, all under the package `memos.api.v1`. Eight services live there, one per file:

| Service | File |
| --- | --- |
| `AIService` | `proto/api/v1/ai_service.proto` |
| `AttachmentService` | `proto/api/v1/attachment_service.proto` |
| `AuthService` | `proto/api/v1/auth_service.proto` |
| `IdentityProviderService` | `proto/api/v1/idp_service.proto` |
| `InstanceService` | `proto/api/v1/instance_service.proto` |
| `MemoService` | `proto/api/v1/memo_service.proto` |
| `ShortcutService` | `proto/api/v1/shortcut_service.proto` |
| `UserService` | `proto/api/v1/user_service.proto` |

Shared message types are in `proto/api/v1/common.proto`, and `proto/api/v1/README.md` states the design follows the Google API Improvement Proposals.

The REST surface is not written by hand; it comes from `google.api.http` annotations on each RPC. For example, in `proto/api/v1/memo_service.proto`:

```21:31:proto/api/v1/memo_service.proto
  rpc CreateMemo(CreateMemoRequest) returns (Memo) {
    option (google.api.http) = {
      post: "/api/v1/memos"
      body: "memo"
    };
    option (google.api.method_signature) = "memo";
  }
  // ListMemos lists memos with pagination and filter.
  rpc ListMemos(ListMemosRequest) returns (ListMemosResponse) {
    option (google.api.http) = {get: "/api/v1/memos"};
    option (google.api.method_signature) = "";
  }
```

Code generation is driven by `buf`, configured in `proto/buf.gen.yaml`: Go protobuf, gRPC, Connect RPC, and gRPC-Gateway stubs land in `proto/gen/` (see `proto/gen/api/v1/` and `proto/gen/api/v1/apiv1connect`), an OpenAPI 3.0.3 spec is generated to `proto/gen/openapi.yaml` (embedded into the binary by `proto/openapi_embed.go` and consumed by the MCP server in `server/router/mcp/service.go`), and TypeScript clients go to `web/src/types/proto/api/v1/`. Per `AGENTS.md`, generated outputs must never be hand-edited — change the `.proto` files and run `buf generate`.

Server-side implementations and route wiring are in `server/router/api/v1/`. `server/router/api/v1/v1.go` registers the gRPC-Gateway handlers and mounts them at `/api/v1/*` and `/file/*`, and mounts Connect handlers at `/memos.api.v1.*` for browser clients. Authentication policy for the public API is centralized in `server/router/api/v1/acl_config.go`, whose `PublicMethods` map is the documented single source of truth for unauthenticated endpoints (keyed by full gRPC procedure paths like `/memos.api.v1.MemoService/ListMemos`).

Beyond the proto-defined API, there are a few adjacent HTTP surfaces registered in `server/server.go`: a `/healthz` endpoint, an SSE endpoint (`server/router/api/v1/sse_handler.go`), plus separate RSS (`server/router/rss/`), MCP (`server/router/mcp/`), file-server (`server/router/fileserver/`), and frontend static (`server/router/frontend/`) routers. Internal storage messages, which are not part of the public API, are defined separately in `proto/store/`.
