h15.

Memo visibility is enforced independently in several server surfaces, not through one shared authorizer. There are two general patterns: per-object checks (fetch the memo, then compare `Visibility`/`CreatorID` against the caller) and query-scoped checks (constrain `store.FindMemo.VisibilityList` or a CEL filter so restricted memos never come back from the store).

Enforcement sites:

GetMemo / parent-memo read gate (`checkMemoReadAccess`) — `server/router/api/v1/memo_service.go` (lines 39–68, called at 356 and 367)
ListMemos query scoping (anonymous → PUBLIC only; authed → `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go` (lines 218–227)
ListMemoComments (read gate plus a comment-level visibility filter) and CreateMemoComment private-parent check — `server/router/api/v1/memo_service_comments.go` (lines 41, 148, 156–161)
ListMemoRelations related-memo filter — `server/router/api/v1/memo_relation_service.go` (lines 107–112)
ListMemoReactions and UpsertMemoReaction — `server/router/api/v1/reaction_service.go` (lines 30–41, 83)
ListMemoAttachments — `server/router/api/v1/memo_attachment_service.go` (lines 213–225)
Attachment API access via the owning memo (`checkAttachmentAccess`) — `server/router/api/v1/attachment_service.go` (lines 422–455)
Raw file/attachment HTTP server (`checkAttachmentPermission`, including the `share_token` fallback and anonymous-instance rule) — `server/router/fileserver/fileserver.go` (lines 650–704)
SSE event delivery filter (`SSEClient.canReceive`) — `server/router/api/v1/sse_hub.go` (lines 134–144)
User stats aggregation (ListAllUserStats and per-user stats) — `server/router/api/v1/user_service_stats.go` (lines 83–92, 216–221)
In-app notification rendering (`canViewerAccessMemo`) — `server/router/api/v1/user_service_notifications.go` (lines 302–316, used at 337, 342, 370, 385)
Email notification rendering (a second, separate `canViewerAccessMemo`) — `server/notification/email.go` (lines 306–320, used at 155 and 187)
Mention notification targeting (`canUserAccessMentionContext`) — `server/router/api/v1/memo_mention_helpers.go` (lines 56–89)
RSS feeds (explore and per-user, PUBLIC only) — `server/router/rss/rss.go` (lines 90, 141)
Sitemap generation (PUBLIC only) — `server/router/frontend/frontend.go` (lines 149–151)

Two related things worth knowing. The query-scoped sites all bottom out in the same store code that translates `VisibilityList` into SQL, in `store/db/sqlite/memo.go` (line 96), `store/db/postgres/memo.go` (line 89), and `store/db/mysql/memo.go` (line 104); that is the shared primitive rather than an independent policy decision. And `GetMemoByShare` in `server/router/api/v1/memo_share_service.go` (lines 153–192) is a deliberate bypass: a valid, unexpired share token returns the memo regardless of visibility, checking only that the memo is not archived. The MCP router (`server/router/mcp/`) adds no checks of its own — it proxies to the v1 API with the caller's Authorization header, so it inherits the API-side enforcement.
