The premise is incorrect: this repository has no nightly database-cleanup job. The `internal/scheduler` package is a standalone, general-purpose cron library, and nothing in the production code registers any job with it — the only importers are its own tests (`internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`). No caller exists in `cmd/`, `server/`, or `store/`.

What likely caused the confusion is that "2 AM daily" cleanup appears repeatedly as illustrative documentation, never as a real registered job:

- `internal/scheduler/doc.go` (lines 15-18): a package doc example registering `"daily-cleanup"` with `Schedule: "0 2 * * *"`.
- `internal/scheduler/README.md` (lines 34-37): the same `"daily-cleanup"` at `"0 2 * * *"` in the quick-start snippet; line 244 shows a different sample, `"stale-session-cleanup"` at `"0 3 * * *"`; and line 268 actually warns that `"0 2 * * *"` is "often overloaded."
- `internal/scheduler/example_test.go` (lines 97-106): an `Example_multipleJobs` function registering a `"cleanup"` job at `"0 2 * * *"`, which runs only under `go test`.

None of these touch the database; the example handlers just print text.

The one real recurring background job in the server is the S3 presign refresher, and it is interval-based rather than cron-scheduled: `server/server.go` (lines 153-174) starts `s3presign.NewRunner(...)`, which runs once at startup and then every 12 hours per `runnerInterval` in `server/runner/s3presign/runner.go` (line 27). The only genuine cron expression in the repo is in CI, `.github/workflows/stale.yml` (line 5), `"0 */8 * * *"` for the stale-issue workflow.
