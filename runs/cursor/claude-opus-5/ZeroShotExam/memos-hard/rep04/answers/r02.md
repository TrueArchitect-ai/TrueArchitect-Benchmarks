The premise is incorrect: this repository (the Memos server) has no per-user API rate-limiting middleware at all. There is no rate limiter registered anywhere in the HTTP or RPC stacks, and no rate-limiting library (`golang.org/x/time/rate`, tollbooth, ulule/limiter, etc.) in `go.mod`. Searching the Go, TypeScript, proto, docs, and CI files for "rate limit"/"throttle" turns up only aspirational prose in `internal/email/README.md` and `internal/email/doc.go` suggesting that outbound email sending *should* be rate limited — no implementation.

Here is what actually is registered, in case one of these is what you had in mind:

**Global Echo middleware** (`server/server.go` lines 51-52) is just panic recovery and CORS:

```50:53:server/server.go
	echoServer := echo.New()
	echoServer.Use(middleware.Recover())
	echoServer.Use(newCORSMiddleware(profile))
	s.echoServer = echoServer
```

**Connect RPC interceptors** (`server/router/api/v1/v1.go` lines 133-138) are metadata conversion, logging, panic recovery, and authentication — no throttling:

```133:138:server/router/api/v1/v1.go
	connectInterceptors := connect.WithInterceptors(
		NewMetadataInterceptor(), // Convert HTTP headers to gRPC metadata first
		NewLoggingInterceptor(logStacktraces),
		NewRecoveryInterceptor(logStacktraces),
		NewAuthInterceptor(authorizer),
	)
```

The gRPC-Gateway similarly gets only `gatewayAuthMiddleware` (`server/router/api/v1/v1.go` lines 69-98).

The only request "limits" in the codebase are size and concurrency caps, and all of them are process-wide rather than per user:

- Request body size is capped at `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` to `/api/v1/*`, `/file/*`, and the Connect routes, plus `connect.WithReadMaxBytes` (`server/router/api/v1/v1.go` lines 20, 126-144).
- Concurrency semaphores, not rate limits: 3 concurrent thumbnail generations and 2 concurrent image-processing (EXIF stripping) operations, shared across the whole instance (`server/router/api/v1/v1.go` lines 59-60, `server/router/api/v1/attachment_service_image.go` lines 67-77). Callers block until a slot frees; exceeding the wait only surfaces as `ResourceExhausted` "too many image processing requests" if the context is cancelled (`server/router/api/v1/attachment_service.go` line 160). The file server has its own separate `maxConcurrentThumbnails = 3` (`server/router/fileserver/fileserver.go` lines 45-46, 116).
- Upload size is bounded per instance by the admin-configured `UploadSizeLimitMb` setting (`server/router/api/v1/attachment_service.go` lines 120-126).

There is also no login attempt throttling or lockout in `server/router/api/v1/auth_service*.go` or `server/auth/`.
