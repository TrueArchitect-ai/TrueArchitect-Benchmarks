`internal/idp`; `internal/idp/oauth2`

The abstraction lives in `internal/idp/idp.go`, which is deliberately minimal — it declares only the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any provider must produce, rather than a Go interface.

The single concrete implementation is `internal/idp/oauth2/oauth2.go` ("Package oauth2 implements the OAuth2 identity provider integration"). It defines an `IdentityProvider` type wrapping `storepb.OAuth2Config`, with `ExchangeToken` (supporting PKCE via `codeVerifier`) and user-info retrieval that maps remote fields into `idp.IdentityProviderUserInfo`.

Two things confirm OAuth2 is the only shipping protocol: the only non-test consumer of these packages is `server/router/api/v1/auth_service_sso.go`, which imports just `internal/idp` and `internal/idp/oauth2`; and the `IdentityProviderConfig` oneof in `proto/api/v1/idp_service.proto` has exactly one variant, `OAuth2Config oauth2_config = 1`. There is no SAML or dedicated OIDC implementation — OIDC providers would be configured through the generic OAuth2 endpoints (`authUrl`, `tokenUrl`, `userInfoUrl`) plus field mapping.
