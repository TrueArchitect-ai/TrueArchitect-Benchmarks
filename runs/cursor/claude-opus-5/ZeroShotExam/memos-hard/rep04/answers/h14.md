**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go` (line 74), which delegates the actual parsing to `ExtractAll` in `internal/markdown/markdown.go` (line 356). It fills `memo.Payload.Tags` and `memo.Payload.Property` on the store model, leaving other payload fields (like the user-set `Location`) untouched.

**Triggers:**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before the memo is written to the store. This also covers comments, since `CreateMemoComment` (`server/router/api/v1/memo_service_comments.go:56`) routes through `CreateMemo`.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only when the update mask contains `content`; the recomputed payload is then written alongside the new content (`update.Payload = memo.Payload`). Other mask paths such as `location`, `pinned`, or `visibility` do not re-derive tags or properties.
- `Runner.RunOnce` — `server/runner/memopayload/runner.go:27`, a batch backfill that walks every memo in pages of 100 and rewrites its payload. Note that this runner is defined but not currently wired into `server/server.go` (only the `s3presign` runner is started there), so in practice it's a maintenance/migration path rather than a live trigger.

**Extracted properties:** a single goldmark AST walk yields
- `Tags`: every `#tag` node, deduplicated while preserving original case (`uniquePreserveCase`), skipping tags inside links.
- `Property.HasLink`: any link node.
- `Property.HasCode`: any code block, fenced code block, or inline code span.
- `Property.HasTaskList`: any task checkbox.
- `Property.HasIncompleteTasks`: any unchecked task checkbox.
- `Property.Title`: plain text of the first block-level child of the document when it is an H1 heading.

These fields are defined in `proto/store/memo.proto` (`MemoPayload.Property`) and surfaced to clients in `server/router/api/v1/memo_service_converter.go:47-50`. `ExtractAll` also returns `Mentions`, but `RebuildMemoPayload` discards them; mentions are consumed separately by `server/router/api/v1/memo_mention_helpers.go:32` for notifications.

One related distinction: the preview text (`Memo.snippet`) is *not* part of the stored payload. It's generated per response by `getMemoContentSnippet` (`server/router/api/v1/memo_service_webhooks.go:83`) calling `GenerateSnippet(content, 64)`, so it's recomputed on every read rather than on write. The stored payload is what backs list filtering, via the CEL filter schema mapping `tags`, `has_link`, `has_task_list`, etc. onto payload JSON paths in `internal/filter/schema.go`.
