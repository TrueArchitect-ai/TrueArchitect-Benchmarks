The premise is incorrect: this repository (Memos) has **no per-user API rate-limiting middleware at all**, so there are no request limits to report. A repo-wide search for `rate limit`, `throttle`, `429`, `RateLimiter`, token buckets, and quotas turns up only two aspirational mentions in email docs — `internal/email/README.md:286` ("### 5. Implement Rate Limiting", as a suggested hardening step for callers) and `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") — plus an incidental match inside a base64 image blob in `store/seed/sqlite/01__dump.sql`. `golang.org/x/time` appears in `go.mod` only as an indirect dependency, and no rate-limiter library (tollbooth, ulule/limiter, etc.) is present.

What actually exists in the middleware/interceptor chain:

- Echo-level middleware is registered in `server/server.go:51-52`: only `middleware.Recover()` and the CORS middleware from `server/cors.go`.
- Connect RPC interceptors are registered in `server/router/api/v1/v1.go:133-138`: metadata, logging, recovery, and auth. The gRPC-Gateway path gets the equivalent auth middleware at `server/router/api/v1/v1.go:69-98`. All of these are authentication/authorization and observability concerns, not rate limiting.

The only request "limits" in the codebase are size and concurrency caps, which are global rather than per user:

- A 256 MiB request body cap, `maxAPIRequestBytes = 256 << 20` in `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` at `server/router/api/v1/v1.go:126-144`.
- Process-wide concurrency semaphores in `server/router/api/v1/v1.go:59-60`: 3 concurrent thumbnail generations and 2 concurrent image-processing operations.

If you want per-user rate limiting, it would need to be added — the natural insertion points are a new Echo middleware next to the CORS registration in `server/server.go`, or a new Connect interceptor alongside `NewAuthInterceptor` in `server/router/api/v1/v1.go`, keyed off the identity that `server/auth` puts into the request context.
