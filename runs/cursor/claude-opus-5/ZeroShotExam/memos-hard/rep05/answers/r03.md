The premise is wrong: there is no nightly database-cleanup job registered anywhere in this repository, so it has no scheduled run time.

What actually exists:

- `internal/scheduler/` is a self-contained, general-purpose cron library (a "GitHub Actions-inspired cron job scheduler," per `internal/scheduler/doc.go`). It provides `Scheduler`, `Job`, parsing, and middleware, but it registers no jobs of its own. Nothing outside that package imports it — a grep for `internal/scheduler` across all `.go` files returns matches only inside the package itself, so the scheduler isn't wired into the running server at all.
- The "2 AM daily cleanup" you may be thinking of is documentation, not a real job. `internal/scheduler/README.md` line 35 shows `Schedule: "0 2 * * *", // 2 AM daily` in its Quick Start, `internal/scheduler/doc.go` line 16 repeats the same snippet, and `internal/scheduler/example_test.go` lines 97-100 define a job literally named `cleanup` on `0 2 * * *` as an illustrative example. These are sample code for the library, not application wiring, and none of them touch the database.
- The only background work the server actually starts is in `server/server.go` (`startBackgroundRunners`, lines 153-173), which launches the S3 presign runner from `server/runner/s3presign/runner.go`. That runner uses a plain `time.Ticker` with `runnerInterval = time.Hour * 12` (line 27), not a cron expression, so it fires every 12 hours from process start rather than at a fixed clock time. Its job is refreshing presigned S3 URLs, not database cleanup.
