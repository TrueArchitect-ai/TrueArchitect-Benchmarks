**Handlers (all on `APIV1Service`, gRPC `MemoService`):** `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, plus `SetMemoAttachments` and `SetMemoRelations`.
**Convergence function:** `webhook.Post` — `internal/webhook/webhook.go:120` (reached through the single shared enqueue point `webhook.PostAsync` at `internal/webhook/webhook.go:184`).

### How each handler reaches the network

- `CreateMemo` (`server/router/api/v1/memo_service.go:70`) calls `DispatchMemoCreatedWebhook` at `memo_service.go:157`.
- `UpdateMemo` (`memo_service.go:401`) calls `dispatchMemoUpdatedSideEffects` at `memo_service.go:513`, which calls `DispatchMemoUpdatedWebhook` (`server/router/api/v1/memo_update_helpers.go:67`).
- `DeleteMemo` (`memo_service.go:518`) calls `DispatchMemoDeletedWebhook` at `memo_service.go:562`.
- `CreateMemoComment` (`server/router/api/v1/memo_service_comments.go:20`) calls `DispatchMemoCommentCreatedWebhook` at `memo_service_comments.go:119`, targeting the *parent* memo owner's webhooks.
- `SetMemoAttachments` (`server/router/api/v1/memo_attachment_service.go:16`) and `SetMemoRelations` (`server/router/api/v1/memo_relation_service.go:16`) both reach the same updated-memo side effects at line 48 of their respective files.

The three `Dispatch*` wrappers funnel into `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which loads the target URLs with `Store.GetUserWebhooks` (`store/user_setting.go:312`) and calls `webhook.PostAsync`. The comment variant calls `PostAsync` directly (`memo_service_webhooks.go:43`), so `dispatchMemoRelatedWebhook` is *not* a full convergence point — `PostAsync` is, and the queue's four worker goroutines (`internal/webhook/webhook.go:42-55`) hand every payload to `Post`, the only place the outbound `http.NewRequest("POST", requestPayload.URL, ...)` is built and executed via `safeClient.Do`.

### Where the URL comes from, and its guardrails

The URL is user-supplied through `CreateUserWebhook` / `UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53` and `:106`), validated by `webhook.ValidateURL` (`internal/webhook/validate.go`) at configuration time. At dial time, `safeDialContext` (`internal/webhook/webhook.go:59`) re-resolves the host and rejects reserved/private IPs, which is what closes the DNS-rebinding gap that URL-only validation would leave open.

For completeness, two other outbound HTTP paths exist but don't converge here: OAuth identity-provider userinfo fetches (`internal/idp/oauth2/oauth2.go:85`) and link/image fetching in `internal/httpgetter/image.go:21`.
