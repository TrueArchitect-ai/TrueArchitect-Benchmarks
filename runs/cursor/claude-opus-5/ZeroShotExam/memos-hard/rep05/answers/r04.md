**Premise correction:** Neither. This repository (memos) has no message broker at all — there is no NATS, RabbitMQ/AMQP, Kafka, Redis, or task-queue dependency anywhere in `go.mod`, and no broker client code in the tree. The only matches for "nats" in the repo are an unrelated substring inside `web/src/locales/ca.json`. So there is no externally declared queue to point at.

**Actual mechanism:** Webhook delivery is entirely in-process, using a buffered Go channel plus a fixed pool of goroutines, all inside `internal/webhook/webhook.go`.

- The "queue" is a package-level buffered channel with capacity 128, declared alongside the shared HTTP client:

```39:39:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

- The "workers" are four goroutines started in the package `init()` function, each looping over the channel and calling the synchronous `Post`:

```42:55:internal/webhook/webhook.go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously", ...)
				}
			}
		}()
	}
}
```

- Producers call `webhook.PostAsync`, which does a non-blocking send into the channel and **drops** the payload with a warning log if the buffer is full (`internal/webhook/webhook.go` lines 184–196). The callers are in `server/router/api/v1/memo_service_webhooks.go`, which loads a user's webhooks via `s.Store.GetUserWebhooks` and enqueues one payload per hook for events like `memos.memo.created`, `memos.memo.updated`, `memos.memo.deleted`, and `memos.memo.comment.created`.

- Actual delivery is a plain HTTP POST from `Post` (`internal/webhook/webhook.go` lines 120–180) using a shared `http.Client` whose transport blocks reserved/private IPs at dial time for SSRF protection, with optional Standard Webhooks HMAC-SHA256 signing (`webhook-id` / `webhook-timestamp` / `webhook-signature` headers).

Two practical consequences of this design: the queue is per-process and in-memory, so it is not durable across restarts and does not coordinate across multiple server instances, and there is no retry — a failed `Post` is only logged.
