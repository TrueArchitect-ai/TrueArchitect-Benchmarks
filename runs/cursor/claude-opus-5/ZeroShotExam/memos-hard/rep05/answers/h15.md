h15.

Memo visibility is enforced in many places rather than a single chokepoint — there is no shared authorization layer, so each surface re-implements the "public / protected / private" rule (with the store only providing the SQL filtering primitives `FindMemo.VisibilityList` and `FindMemoRelation.MemoFilter`).

Single-memo read check (`checkMemoReadAccess`, used by `GetMemo`, parent-memo check, and `ListMemoComments`) — `server/router/api/v1/memo_service.go` (lines 39–68, called at 356/367 and from `server/router/api/v1/memo_service_comments.go:148`)
Memo list query filter (`ListMemos` builds `VisibilityList`/CEL filter for anonymous vs. authenticated callers) — `server/router/api/v1/memo_service.go` (lines 218–227)
Comment creation parent-visibility check (`CreateMemoComment` rejects commenting on someone else's private memo) — `server/router/api/v1/memo_service_comments.go` (line 41); comment listing also re-applies a visibility CEL filter at line 160
Memo relation filtering (related/referenced memos are filtered by a visibility CEL filter before being returned) — `server/router/api/v1/memo_service_converter.go` (lines ~183–187) and `server/router/api/v1/memo_relation_service.go` (lines ~107–112)
Reaction service (upsert and delete both re-check the target memo's visibility) — `server/router/api/v1/reaction_service.go` (lines 38 and 83)
Attachment API access (`checkAttachmentAccess` derives attachment access from the owning memo's visibility) — `server/router/api/v1/attachment_service.go` (lines 419–455), plus the same inline check in `server/router/api/v1/memo_attachment_service.go` (line 222)
Raw file serving (`checkAttachmentPermission`, separate Echo route, adds the anonymous-instance and `share_token` cases) — `server/router/fileserver/fileserver.go` (lines 649–704)
SSE live-event delivery filtering (`canReceive` decides which connected clients get a memo event) — `server/router/api/v1/sse_hub.go` (lines 134–144), with the event's visibility populated in `server/router/api/v1/sse_event_helpers.go`
User stats aggregation (both `ListAllUserStats` and per-user stats re-apply the visibility filter) — `server/router/api/v1/user_service_stats.go` (lines 82–91 and 216–221)
RSS feeds (explore and per-user feeds restrict to `store.Public`) — `server/router/rss/rss.go` (lines 90 and 141)
Sitemap generation (public memos only) — `server/router/frontend/frontend.go` (line 150)
Notification/inbox visibility (`canViewerAccessMemo` gates what a viewer sees of a memo in notifications) — `server/router/api/v1/user_service_notifications.go` (lines ~302–316) and a duplicate copy for email in `server/notification/email.go` (lines ~306–320)
Mention notification eligibility (`canUserAccessMentionContext` / `shouldSkipMentionInbox`) — `server/router/api/v1/memo_mention_helpers.go` (lines 56–89)

Two deliberate bypasses worth noting: `GetMemoByShare` returns a memo without any visibility check once a valid, unexpired share token resolves (`server/router/api/v1/memo_share_service.go`, lines 153–197), and the file server honors the same `share_token` query parameter (`server/router/fileserver/fileserver.go`, lines 681–689). The MCP router (`server/router/mcp/`) is not a distinct site — it dispatches to `MemoService_ListMemos`/`MemoService_GetMemo` and inherits their checks.
