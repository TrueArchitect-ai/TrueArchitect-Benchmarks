The browser hits `GET /file/users/{username}/avatar`, which the native Echo file server handles by loading the user row and decoding the base64 data URI stored in `user.avatar_url` — the avatar bytes live in the `user` table, not on disk or S3.

Two details worth noting: the service is constructed and its routes are registered before the gRPC-Gateway in `server/server.go:81`, and despite what `server/router/fileserver/README.md` says about accepting an ID or a username, `getUserByUsername` resolves the `:identifier` param by username only. The MIME type from the data URI must also be in `avatarAllowedTypes` (`server/router/fileserver/fileserver.go:75`) or the request is rejected with 400.
