**Answer: `internal/idp`; `internal/idp/oauth2`**

The abstraction lives in `internal/idp` (`internal/idp/idp.go`), which is deliberately minimal — it defines only the shared `IdentityProviderUserInfo` struct (identifier, display name, email, avatar URL) that any provider must produce so the rest of the server can consume SSO results without knowing the protocol.

The single concrete implementation is `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`), whose package comment reads "Package oauth2 implements the OAuth2 identity provider integration." It exposes `NewIdentityProvider(*storepb.OAuth2Config)`, `ExchangeToken` (with optional PKCE code verifier support), and user-info retrieval that maps remote fields via the configured `FieldMapping`.

The wiring confirms there is nothing else: the only non-test consumer of these packages is `server/router/api/v1/auth_service_sso.go`, which imports both `internal/idp` and `internal/idp/oauth2` and constructs the OAuth2 provider from the stored `storepb.IdentityProvider` config before calling `resolveSSOUser`. No SAML, LDAP, or dedicated OIDC package exists in the repo.
