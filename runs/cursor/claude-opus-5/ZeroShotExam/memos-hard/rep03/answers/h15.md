Memo visibility is enforced in many places rather than a single choke point — the store layer only provides the `VisibilityList`/filter mechanism (`store/memo.go`, `store/db/{sqlite,postgres,mysql}/memo.go`), so each surface applies the policy itself. Here are the distinct enforcement sites:

Single-memo read check (`checkMemoReadAccess`, used by `GetMemo`, `ListMemoComments`) — `server/router/api/v1/memo_service.go` (lines 39-68, 356, 367)
Memo list query scoping (`ListMemos`: anonymous gets PUBLIC only; authenticated gets own + PUBLIC/PROTECTED) — `server/router/api/v1/memo_service.go` (lines 218-227)
Comment list scoping (visibility filter on the relation query, on top of the parent-memo check) — `server/router/api/v1/memo_service_comments.go` (lines 41, 148-161)
Reaction read/write checks (`ListMemoReactions`, `UpsertMemoReaction`) — `server/router/api/v1/reaction_service.go` (lines 30-41, 83)
Memo attachment listing check (`ListMemoAttachments`) — `server/router/api/v1/memo_attachment_service.go` (lines 214-225)
Attachment access via API (`checkAttachmentAccess`, follows the linked memo's visibility) — `server/router/api/v1/attachment_service.go` (lines 422-455)
Attachment/file HTTP serving (`checkAttachmentPermission`, incl. anonymous-instance and share-token fallbacks) — `server/router/fileserver/fileserver.go` (lines 650-704)
User stats aggregation scoping (`ListAllUserStats` and per-user stats) — `server/router/api/v1/user_service_stats.go` (lines 84-90, 218-220)
SSE live-event delivery filtering (`canReceive`: private events only to creator or admin) — `server/router/api/v1/sse_hub.go` (lines 134-144), with the event's visibility populated in `server/router/api/v1/sse_event_helpers.go`
Notification payload redaction (`canViewerAccessMemo`) — `server/router/api/v1/user_service_notifications.go` (lines 302-316)
Email notification content gating (its own copy of `canViewerAccessMemo`) — `server/notification/email.go` (lines 306-320)
Mention notification recipient filtering (`canUserAccessMentionContext`) — `server/router/api/v1/memo_mention_helpers.go` (lines 56-89)
RSS feeds (explore and per-user, PUBLIC only) — `server/router/rss/rss.go` (lines 90, 141)
Sitemap generation (PUBLIC only) — `server/router/frontend/frontend.go` (line 150)

Two related notes: `GetMemoByShare` in `server/router/api/v1/memo_share_service.go` deliberately bypasses visibility — a valid, unexpired share token grants read access to private/protected memos, gated only by token validity and archived state (lines 153-166); the matching bypass exists in the file server's `share_token` branch. And the MCP surface (`server/router/mcp/`) doesn't check visibility itself; it proxies to the API v1 handlers above.
