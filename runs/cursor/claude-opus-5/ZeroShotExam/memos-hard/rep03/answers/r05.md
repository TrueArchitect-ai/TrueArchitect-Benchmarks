**Premise correction:** There is no GraphQL schema in this repository. A case-insensitive search across the whole tree (excluding `.git`, `node_modules`, and `go.sum`) for `graphql`, `gqlgen`, and `apollo` returns zero matches — no SDL files, no `typeDefs`, no schema-stitching layer, and no GraphQL server dependency in `go.mod`. This is Memos, and its public API is defined with Protocol Buffers, served over Connect RPC / gRPC and a RESTful gRPC-Gateway.

**Actual API surface**

The schema source of truth is the `.proto` files in `proto/api/v1/`, one per service: `ai_service.proto`, `attachment_service.proto`, `auth_service.proto`, `common.proto`, `idp_service.proto`, `instance_service.proto`, `memo_service.proto`, `shortcut_service.proto`, and `user_service.proto`. All are in the `memos.api.v1` package and follow the [Google API Improvement Proposals](https://google.aip.dev/), as noted in `proto/api/v1/README.md`. Internal storage messages live separately in `proto/store/` and are not part of the public surface.

REST routes are declared inline on each RPC via `google.api.http` annotations rather than in a separate routing table. For example, in `proto/api/v1/memo_service.proto`:

```17:32:proto/api/v1/memo_service.proto
service MemoService {
  // CreateMemo creates a memo. The request body is a Memo; set its content
  // (Markdown) and visibility (PRIVATE | PROTECTED | PUBLIC, default PRIVATE).
  // The memo is owned by the authenticated user; requires authentication.
  rpc CreateMemo(CreateMemoRequest) returns (Memo) {
    option (google.api.http) = {
      post: "/api/v1/memos"
      body: "memo"
    };
    option (google.api.method_signature) = "memo";
  }
  // ListMemos lists memos with pagination and filter.
  rpc ListMemos(ListMemosRequest) returns (ListMemosResponse) {
    option (google.api.http) = {get: "/api/v1/memos"};
    option (google.api.method_signature) = "";
  }
```

Code generation is driven by `proto/buf.gen.yaml` (run with `cd proto && buf generate`), which emits Go protobuf/gRPC/Connect/gateway stubs into `proto/gen/`, an OpenAPI document at `proto/gen/openapi.yaml`, and TypeScript clients into `web/src/types/proto/`. That OpenAPI file is the closest analogue to the "schema document" you were asking about, and it is embedded into the binary by `proto/openapi_embed.go` and consumed by the MCP server in `server/router/mcp/service.go`.

Serving happens in `server/router/api/v1/v1.go`, where `RegisterGateway` wires up two protocol front-ends against a single set of service implementations: a gRPC-Gateway mux mounted at `/api/v1/*` and `/file/*`, and Connect handlers mounted at `/memos.api.v1.*` for browser clients (registered in `server/router/api/v1/connect_handler.go`). Business logic lives in the per-service Go files in `server/router/api/v1/` (`memo_service.go`, `user_service.go`, and so on), with anonymous-access rules configured in `server/router/api/v1/acl_config.go`. Non-RPC surfaces alongside these are RSS (`server/router/rss/`), MCP (`server/router/mcp/`), and an SSE endpoint registered in the same CORS group as `/api/v1`.
