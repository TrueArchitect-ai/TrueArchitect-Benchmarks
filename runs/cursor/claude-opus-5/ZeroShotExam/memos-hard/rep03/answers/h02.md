The SSRF protection lives at the dial layer rather than only at the URL layer:

```59:77:/bench/repo/internal/webhook/webhook.go
func safeDialContext(ctx context.Context, network, addr string) (net.Conn, error) {
	host, port, err := net.SplitHostPort(addr)
	// ...
	ips, err := net.DefaultResolver.LookupHost(ctx, host)
	// ...
	for _, ipStr := range ips {
		if ip := net.ParseIP(ipStr); ip != nil && isReservedIP(ip) {
			return nil, errors.Errorf("webhook: connection to reserved/private IP address is not allowed")
		}
	}
	return (&net.Dialer{}).DialContext(ctx, network, net.JoinHostPort(host, port))
}
```

`isReservedIP` checks the resolved address against `reservedCIDRs` in `internal/webhook/validate.go:14-23`: IPv4 loopback, all three RFC-1918 ranges, link-local `169.254.0.0/16` (explicitly covering the cloud metadata endpoint `169.254.169.254`), plus IPv6 loopback, unique-local, and link-local. Because the check runs at dial time on every connection, it also defeats DNS rebinding.

Two supporting details worth knowing:

- There is a second, earlier check: `ValidateURL` (`internal/webhook/validate.go:62`) rejects non-`http`/`https` schemes and reserved-IP resolutions when a user registers or updates a webhook, called from `server/router/api/v1/user_service_webhooks.go` at lines 74, 161, and 182. This is validation-time only and therefore time-of-check/time-of-use racy on its own; the dial-time guard is what actually protects delivery.
- The protection is intentionally defeatable by the operator: the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, and it is set from the `allow-private-webhooks` config value at `cmd/memos/main.go:49` for self-hosted setups that want to target LAN services.
