The premise is incorrect: this repository (Memos) has no per-user API rate-limiting middleware at all, so there is nothing registered and no request limits to report. I searched the whole Go and TypeScript tree for rate limiting, throttling, and limiter terminology, and the only hits are documentation prose — `internal/email/README.md` suggests adding `golang.org/x/time/rate` around email sending as a future improvement, and `internal/email/doc.go` lists "Rate limit email sending" as an aspiration. `golang.org/x/time` appears in `go.mod` only as an indirect dependency, never imported by first-party code.

The actual middleware chain confirms this. At the Echo level, `server/server.go` registers only panic recovery and CORS:

```50:53:/bench/repo/server/server.go
	echoServer := echo.New()
	echoServer.Use(middleware.Recover())
	echoServer.Use(newCORSMiddleware(profile))
	s.echoServer = echoServer
```

At the API level, `server/router/api/v1/v1.go` installs a single gRPC-Gateway middleware for authentication and access policy, plus four Connect interceptors — metadata, logging, recovery, and auth (defined in `server/router/api/v1/connect_interceptors.go`). None of them counts requests per user.

What does exist are other kinds of resource limits, which may be what you were thinking of:

- A 256 MiB request body cap (`maxAPIRequestBytes` in `server/router/api/v1/v1.go`), applied via `http.MaxBytesHandler` to `/api/v1/*`, `/file/*`, and the Connect routes.
- Process-wide concurrency semaphores, not per-user: 3 concurrent thumbnail generations and 2 concurrent image processing operations in `server/router/api/v1/v1.go`, and a matching limit of 3 in `server/router/fileserver/fileserver.go`. Exceeding the image one returns `ResourceExhausted` ("too many image processing requests") from `server/router/api/v1/attachment_service.go`.
- Per-call batch size caps: 100 users in `user_service.go`, 100 instance settings in `instance_service.go`, 100 attachment deletes in `attachment_service.go`, and 10 link-metadata URLs in `memo_service.go`.

If you need per-user rate limiting, it would have to be added — the natural insertion points are the gateway middleware and the Connect interceptor list in `server/router/api/v1/v1.go`, or a global `echoServer.Use(...)` in `server/server.go`.
