The premise doesn't hold: this repository has no nightly database-cleanup job scheduled anywhere, so there is no time to report.

What actually exists:

**A cron scheduler library with zero registered jobs.** `internal/scheduler/` is a self-contained, GitHub Actions-inspired cron package (`scheduler.go`, `parser.go`, `job.go`, `middleware.go`) that supports 5- and 6-field cron expressions. But nothing in the application imports it — grepping for `internal/scheduler` across all `.go` files returns matches only from inside the package itself. It is dead code from the server's perspective, so no job of any kind is scheduled through it.

**The "2 AM cleanup" you may be thinking of is documentation, not a real job.** A `daily-cleanup` job at `0 2 * * *` appears in the package's own docs and examples: the package doc comment (`internal/scheduler/doc.go` lines 14-21), the quick-start snippet in `internal/scheduler/README.md` lines 33-40, and an example function in `internal/scheduler/example_test.go` lines 98-106, where the handler just prints "Cleaning up old data..." Those handlers touch no database. The README also warns against scheduling exactly on the hour and suggests `5 2 * * *` instead, which is advice rather than configuration.

**The real background work is interval-based, not cron-based, and does no cleanup.** `server/server.go` starts background runners in `startBackgroundRunners` (line 153); the only one wired up is the S3 presign runner, which re-signs S3 attachment URLs on a `time.Ticker` every 12 hours (`server/runner/s3presign/runner.go` line 27). There is also an in-memory cache eviction loop that runs every 5 minutes (`store/cache/cache.go` lines 46-60 and 199-218), but that expires cache entries rather than cleaning the database.

**The only genuine cron expression in the repo is in CI.** `.github/workflows/stale.yml` line 5 sets `- cron: "0 */8 * * *"` for the stale issue/PR bot, which runs every 8 hours and has nothing to do with the database.

So if you were expecting a scheduled database-cleanup task, it would need to be written and registered; the scheduler infrastructure is present but unused.
