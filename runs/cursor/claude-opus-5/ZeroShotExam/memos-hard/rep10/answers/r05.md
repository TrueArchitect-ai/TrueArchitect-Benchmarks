### The actual API surface: Protocol Buffers

The public API is defined as protobuf service definitions in `proto/api/v1/`, one file per service:

| File | Service |
| --- | --- |
| `proto/api/v1/memo_service.proto` | `MemoService` |
| `proto/api/v1/user_service.proto` | `UserService` |
| `proto/api/v1/auth_service.proto` | `AuthService` |
| `proto/api/v1/attachment_service.proto` | `AttachmentService` |
| `proto/api/v1/instance_service.proto` | `InstanceService` |
| `proto/api/v1/shortcut_service.proto` | `ShortcutService` |
| `proto/api/v1/idp_service.proto` | `IdentityProviderService` |
| `proto/api/v1/ai_service.proto` | `AIService` |
| `proto/api/v1/common.proto` | Shared enums/messages |

`AGENTS.md` confirms the split: `proto/api/v1/` holds "Public API service definitions" while `proto/store/` holds "Internal storage proto messages" (lines 67–68).

Each RPC carries a `google.api.http` annotation that defines its REST mapping, so the protobuf file is simultaneously the source of truth for gRPC, Connect, and REST. From `MemoService`:

```22:32:proto/api/v1/memo_service.proto
  rpc CreateMemo(CreateMemoRequest) returns (Memo) {
    option (google.api.http) = {
      post: "/api/v1/memos"
      body: "memo"
    };
    option (google.api.method_signature) = "memo";
  }
  // ListMemos lists memos with pagination and filter.
  rpc ListMemos(ListMemosRequest) returns (ListMemosResponse) {
    option (google.api.http) = {get: "/api/v1/memos"};
    option (google.api.method_signature) = "";
  }
```

The design follows [Google's API Improvement Proposals](https://google.aip.dev/), per `proto/api/v1/README.md`.

### Code generation

`proto/buf.gen.yaml` fans the `.proto` sources out to five targets via `buf generate`: Go message types, gRPC stubs, Connect handlers, gRPC-Gateway REST shims (all into `proto/gen/`), plus TypeScript for the web client into `web/src/types/proto/`. It also emits an **OpenAPI/Swagger spec** — `proto/gen/openapi.yaml` — which is the closest analogue to the "schema document" you were probably looking for. That spec is embedded into the binary by `proto/openapi_embed.go` and consumed at runtime by the MCP server (`server/router/mcp/service.go:78`).

### Serving

Business logic lives in `server/router/api/v1/` (e.g. `memo_service.go`, `user_service.go`). `server/router/api/v1/connect_services.go` provides the Connect handler methods, each delegating to the gRPC implementation, and `connect_handler.go:37-44` registers all eight services. `server/server.go:88` mounts the gRPC-Gateway under `/api/v1`. Public unauthenticated routes are allowlisted in `server/router/api/v1/acl_config.go`.

To change the API you edit the `.proto` file and run `cd proto && buf generate` — generated outputs must not be hand-edited (`AGENTS.md:19`).
