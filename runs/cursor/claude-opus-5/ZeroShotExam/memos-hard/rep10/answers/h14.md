**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go` (lines 74-88), which delegates the actual parsing to the goldmark-based markdown service — `(*service).ExtractAll` in `internal/markdown/markdown.go` (lines 356-422). It writes the result onto `memo.Payload.Tags` and `memo.Payload.Property` (the `MemoPayload.Property` message defined in `proto/store/memo.proto`, generated into `proto/gen/store/memo.pb.go`). A standalone equivalent, `(*service).ExtractProperties` (`internal/markdown/markdown.go` lines 193-241), exists on the interface but nothing in the server calls it; production always goes through `ExtractAll` for the single-pass version.

**Triggers:**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, called before `Store.CreateMemo`. Comment creation goes through this same path (`server/router/api/v1/memo_service_comments.go:56` calls `s.CreateMemo`).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the `path == "content"` branch of the update-mask loop, and the recomputed payload is then assigned to `update.Payload` (line 451). Other update-mask paths do not recompute; notably the `"location"` branch (lines 481-484) mutates `memo.Payload.Location` and reuses the existing derived `Property` as-is.
- A bulk backfill: `Runner.RunOnce` in `server/runner/memopayload/runner.go` (lines 27-72) pages through all memos in batches of 100, rebuilds each payload, and persists it via `Store.UpdateMemo`. Note this runner is currently not wired up anywhere — `memopayload.NewRunner` has no call sites, and `server/server.go:163` only invokes the s3presign runner.

**Extracted properties** (all derived from the parsed markdown AST in one walk):
- `Title` — the plain text of the first block-level child of the document, but only when it is an H1 heading (`heading.Level == 1`); text is flattened recursively by `extractHeadingText`/`extractTextFromNode`.
- `HasLink` — true if any `gast.KindLink` node is present.
- `HasCode` — true for any indented code block, fenced code block, or inline code span (`KindCodeBlock`, `KindFencedCodeBlock`, `KindCodeSpan`).
- `HasTaskList` — true if any GFM task checkbox node exists.
- `HasIncompleteTasks` — true if any task checkbox has `IsChecked == false`.

The same pass also collects `Tags` (deduplicated, case preserved, skipping `#tag` nodes nested inside links/images per `isTagNodeInLinkOrImage`) which is stored alongside `Property`, plus `Mentions`, which `RebuildMemoPayload` discards (mentions are consumed separately in `server/router/api/v1/memo_mention_helpers.go:32`).

These stored properties feed list/preview and filter features: `convertMemoPropertyFromStore` in `server/router/api/v1/memo_service_converter.go:49`, user stats aggregation in `server/router/api/v1/user_service_stats.go` (lines 141-152, 257-268), and filter factors like `property.hasLink` in `web/src/hooks/useMemoFilters.ts`. The `snippet` field, by contrast, is not persisted — it is generated per-response via `getMemoContentSnippet` at `server/router/api/v1/memo_service_converter.go:76`.
