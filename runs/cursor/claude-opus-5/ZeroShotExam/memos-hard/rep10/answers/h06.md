**Handlers (six, all on `APIV1Service`):** `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` — **convergence function: `webhook.Post`** at `internal/webhook/webhook.go:120` (reached via the shared enqueue point `webhook.PostAsync`, same file, line 184).

The user-configured URL is a per-user webhook stored in user settings (created/validated by `CreateUserWebhook`/`UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go`), and it's read back at dispatch time via `s.Store.GetUserWebhooks`.

Here's how each handler reaches delivery:

| Handler | File:line of dispatch | Path to `Post` |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:157` | `DispatchMemoCreatedWebhook` → `dispatchMemoRelatedWebhook` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:513` | `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` → `dispatchMemoRelatedWebhook` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:562` | `DispatchMemoDeletedWebhook` → `dispatchMemoRelatedWebhook` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:119` | `DispatchMemoCommentCreatedWebhook` (and, nested, its internal `CreateMemo` call at line 55) |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:48` | `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:48` | `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` |

The four dispatcher wrappers live in `server/router/api/v1/memo_service_webhooks.go`; three of them delegate to `dispatchMemoRelatedWebhook` (line 48), which loops over the user's webhooks and calls `webhook.PostAsync` (line 71), while `DispatchMemoCommentCreatedWebhook` calls `PostAsync` directly (line 43). `PostAsync` only enqueues onto the bounded `asyncPostQueue`; four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, which is the sole place the outbound request is built and executed via `safeClient.Do` (line 152).

Two details worth noting on that final hop: outbound requests use `safeClient`, whose transport installs `safeDialContext` to reject connections resolving to reserved or private IPs (guarding against SSRF and DNS rebinding), and `Post` optionally adds Standard Webhooks HMAC headers when the stored webhook has a signing secret.

For completeness, the webhook CRUD handlers in `user_service_webhooks.go` do *not* make outbound requests — they only call `webhook.ValidateURL`/`ValidateSigningSecret` (`internal/webhook/validate.go`). Separately, `GetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go`, via `internal/httpgetter`) does fetch an arbitrary URL, but that URL comes from the request itself rather than from stored user configuration, and it does not pass through `webhook.Post`.
