**delivery function — `internal/webhook/webhook.go` (`Post`, lines 120–180, reached asynchronously via `PostAsync` at lines 184–196 and the four queue-draining goroutines in `init`); protection mechanism — `internal/webhook/validate.go` (`isReservedIP`/`reservedCIDRs` + `ValidateURL`), enforced at dial time by `safeDialContext` and `safeClient` in `internal/webhook/webhook.go` (lines 29–77)**

How it fits together:

- **Trigger**: memo create/update/delete and comment-created events call `s.Store.GetUserWebhooks(...)` and then `webhook.PostAsync(payload)` for each registered hook, in `server/router/api/v1/memo_service_webhooks.go`. That only enqueues onto a bounded 128-slot channel (dropping with a warning when full), so no HTTP happens on the request goroutine.
- **Actual outbound HTTP**: `Post` in `internal/webhook/webhook.go` marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and issues `safeClient.Do(req)`. Responses are read through a 1 MiB `io.LimitReader`.
- **SSRF protection, two layers**:
  1. *Registration time*: `webhook.ValidateURL` in `internal/webhook/validate.go` rejects non-`http(s)` schemes and hostnames resolving into reserved ranges. It's called when webhooks are created/updated in `server/router/api/v1/user_service_webhooks.go` (lines 74, 161, 182).
  2. *Dial time*: `safeDialContext` re-resolves the host on every connection and refuses any address matching `reservedNetworks`, which is what actually defeats DNS rebinding (a URL that validated as public but later resolves to `169.254.169.254` or an RFC-1918 address). The blocked ranges are IPv4 loopback, the three RFC-1918 blocks, link-local/cloud IMDS `169.254.0.0/16`, plus IPv6 `::1/128`, `fc00::/7`, and `fe80::/10`.

One caveat worth knowing: both layers share the `AllowPrivateIPs` switch in `internal/webhook/validate.go`, set from the `allow-private-webhooks` config in `cmd/memos/main.go` (line 49). When enabled, `isReservedIP` always returns false and the SSRF protection is fully disabled for self-hosted setups targeting LAN services.
