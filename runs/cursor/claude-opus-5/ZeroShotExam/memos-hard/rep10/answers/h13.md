**`*markdown.service` (the single unexported struct returned by `markdown.NewService`) — constructed once in `NewAPIV1Service` with the tag + mention extensions — held by `APIV1Service`, `rss.RSSService`, and `memopayload.Runner`.**

Details:

The interface is `markdown.Service` in `internal/markdown/markdown.go` (lines 31–55), declaring `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, and `RenameTag`.

There is exactly one concrete implementation in the whole repo: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:57-60`). No mock, fake, or alternate implementation exists — the test suites all use the real one.

Runtime construction happens in a single place:

```47:62:server/router/api/v1/v1.go
func NewAPIV1Service(secret string, profile *profile.Profile, store *store.Store) *APIV1Service {
	markdownService := markdown.NewService(
		markdown.WithTagExtension(),
		markdown.WithMentionExtension(),
	)
```

`NewService` (`internal/markdown/markdown.go:85`) always builds goldmark with GFM plus whichever custom extensions the options enable, so the production instance has both `#tag` and `@mention` parsing on.

That one instance is then shared: `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService`, so the RSS router does not create its own.

The interface-typed fields (the holders) are:
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`), used for mention extraction (`memo_mention_helpers.go:32`), webhook snippets (`memo_service_webhooks.go:85`), and payload rebuilds (`memo_service.go:108,447`).
- `RSSService.MarkdownService` (`server/router/rss/rss.go:45`), used only for `RenderHTML` on feed items (`rss.go:339`).
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) — note that `NewRunner` has no callers anywhere in the codebase, so this holder is currently dead at runtime; the payload rebuild path that actually executes is the package-level function `RebuildMemoPayload(ctx, memo, markdownService)` called directly by the memo service with the API service's instance.

Other constructions of `NewService` are test-only: `server/router/api/v1/test/test_helper.go:44`, `server/router/rss/rss_test.go:54`, `server/router/fileserver/fileserver_test.go:427`, and `internal/markdown/markdown_test.go`.

Worth noting for scope: this interface covers backend markdown only. The frontend renders markdown independently through React components under `web/src/components/MemoContent/` (e.g. `MemoMarkdownRenderer.tsx`) and is not behind this interface — the backend's `RenderHTML` exists mainly for RSS, as the interface's own doc comment states.
