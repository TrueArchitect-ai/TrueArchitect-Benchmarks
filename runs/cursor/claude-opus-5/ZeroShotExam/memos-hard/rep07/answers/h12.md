### How I picked the one that runs

I followed the concrete value assigned to the interface, rather than guessing from the call site:

1. **The default is `sqlite`, set in two places that agree.** `cmd/memos/main.go:122` has `viper.SetDefault("driver", "sqlite")`, and the bound flag at line 130 also defaults to `"sqlite"`. With no flags passed, `viper.GetString("driver")` yields `sqlite`, which populates `profile.Driver` at `cmd/memos/main.go:43`.
2. **That string is the only thing that selects the implementation.** The `switch profile.Driver` in `NewDBDriver` (`store/db/db.go:18-27`) maps `"sqlite"` to `sqlite.NewDB(profile)`; the Postgres and MySQL branches are reachable only via an explicit `--driver` flag or the `MEMOS_DRIVER` environment variable (env binding at `cmd/memos/main.go:167-169`).
3. **Nothing wraps or intercepts the memo write.** `store.New` (`store/store.go:38-61`) stores the driver as-is; its three caches cover instance settings, users, and user settings only — there is no memo cache or decorating driver. `Store.CreateMemo` (`store/memo.go:109-114`) validates the UID and delegates straight to `s.driver.CreateMemo`, which is the SQLite method. The API handler reaches it via `s.Store.CreateMemo` at `server/router/api/v1/memo_service.go:115`.
4. **No build tags shift the choice.** A search for `go:build` across `store/` and `internal/` returned nothing, so all three drivers compile into the binary and the selection is purely the runtime `switch` above — not a compile-time variant.

Two corroborating details: `profile.Validate` special-cases `p.Driver == "sqlite"` to derive the default DSN `<data>/memos_prod.db` (`internal/profile/profile.go:110-117`), which only makes sense as the default path; and the sole occurrence of `MEMOS_DRIVER` in the repo is in the test harness `store/test/containers.go`, not in any production packaging that would override the default.

One caveat on method: I intended to confirm this empirically by printing the concrete type returned by `NewDBDriver` for a default profile, but the workspace is mounted read-only so I couldn't add or run that program. The conclusion rests on the static trace above, which has no ambiguity in it — a single `switch` on a single string with a default set consistently in two places.
