**S3 presign background runner — every 12 hours (plus one immediate run at startup) — wired in `server/server.go:162`–`171` (inside `startBackgroundRunners`, itself called from `Start` at `server/server.go:129`)**

The component is `s3presign.Runner`, defined in `server/runner/s3presign/runner.go:16`. It exists because attachments stored in S3 keep a presigned URL in their `reference` column, and presigned URLs expire — so the runner periodically re-signs them before they go stale.

How it works:

- `runnerInterval` is 12 hours (`server/runner/s3presign/runner.go:27`), and `Run` drives a ticker that calls `RunOnce` on each tick until its context is cancelled (`runner.go:29`–`45`).
- `CheckAndPresign` pages through attachments whose storage type is `S3` in batches of 100, and for each one re-signs the object key and writes the new URL back via `UpdateAttachment`, also stamping `LastPresignedTime` (`runner.go:47`–`131`).
- It skips work that isn't needed yet: if `LastPresignedTime` is less than 4 days old, the attachment is left alone (`runner.go:85`–`91`). That 4-day threshold pairs with the 5-day expiry set when signing in `internal/storage/s3/s3.go:79`, leaving roughly a day of margin before a URL would actually expire.

Startup wiring detail worth noting: `startBackgroundRunners` calls `s3presignRunner.RunOnce(ctx)` synchronously first (`server/server.go:163`), so a refresh pass happens on every boot rather than waiting 12 hours for the first tick. The looping runner then runs on its own cancellable context tracked in `backgroundRunnerCancels` and `backgroundRunnerWG`, which `Shutdown` uses to stop and wait for it (`server/server.go:140`–`143`).
