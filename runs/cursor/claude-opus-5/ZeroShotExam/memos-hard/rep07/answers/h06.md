**Handlers:** `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`; **convergence function** — `webhook.Post` in `internal/webhook/webhook.go` (all callers reach it via `webhook.PostAsync`).

Every one of these RPCs on `APIV1Service` ends up sending an HTTP POST to a URL the user stored via `CreateUserWebhook`/`UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go`), which the store returns through `GetUserWebhooks`.

How each handler gets there:

- `CreateMemo` calls `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service.go:157`).
- `DeleteMemo` calls `DispatchMemoDeletedWebhook` (`server/router/api/v1/memo_service.go:562`).
- `UpdateMemo`, `SetMemoAttachments`, and `SetMemoRelations` all funnel through the shared helper `dispatchMemoUpdatedSideEffects`, which calls `DispatchMemoUpdatedWebhook` (`server/router/api/v1/memo_update_helpers.go:66`; callers at `memo_service.go:513`, `memo_attachment_service.go:48`, `memo_relation_service.go:48`).
- `CreateMemoComment` calls `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_comments.go:119`).

Those four `Dispatch*` methods live in `server/router/api/v1/memo_service_webhooks.go`; three of them delegate to `dispatchMemoRelatedWebhook`, and all of them set `payload.URL = hook.Url` before calling `webhook.PostAsync`. `PostAsync` only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:184`); four background workers started in `init()` drain that queue and invoke `Post`, which is the single place the request is marshalled, optionally HMAC-signed, and actually sent via `safeClient.Do` (`internal/webhook/webhook.go:152`).

Note that the memo-creation path also runs for comments, since `CreateMemoComment` internally creates a memo, so a comment can trigger both the `memos.memo.created` and `memos.memo.comment.created` deliveries.
