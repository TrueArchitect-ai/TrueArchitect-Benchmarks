**Answer: `RebuildMemoPayload` in `server/runner/memopayload/runner.go` (backed by `markdown.Service.ExtractAll` in `internal/markdown/markdown.go`); triggered on memo creation, on update when `content` is in the field mask, and by the batch payload runner; it extracts tags plus the content properties `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`, and `title`.**

Computation site: `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) fills `memo.Payload.Tags` and `memo.Payload.Property` from a single markdown parse. The actual AST walk lives in `internal/markdown/markdown.go` — `ExtractAll` (lines 356-422), which mirrors the standalone `ExtractProperties` (lines 193-241).

Triggers:
- `CreateMemo` calls it on the new `store.Memo` before insert (`server/router/api/v1/memo_service.go:108`). Comment creation goes through the same path, since `CreateMemoComment` delegates to `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
- `UpdateMemo` calls it only when the update mask contains `content`, then writes the refreshed payload with the new content (`server/router/api/v1/memo_service.go:436-451`). Other mask paths such as `visibility`, `pinned`, or `location` do not recompute it.
- `Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) walks every memo in batches of 100 and rebuilds/persists the payload — useful for backfills. Note that this runner is not currently wired into `server/server.go` (only the S3 presign runner is registered there), so in practice recomputation happens on create and content-update.

Extracted properties: from `proto/store/memo.proto:15-22`, `MemoPayload.Property` holds `has_link`, `has_task_list`, `has_code`, `has_incomplete_tasks`, and `title`. The walk sets `HasLink` for `KindLink` nodes, `HasCode` for code blocks, fenced code blocks, and inline code spans, `HasTaskList` for any GFM task checkbox with `HasIncompleteTasks` when a checkbox is unchecked, and `Title` from the first block-level child of the document only when it is an H1 heading (plain text of the heading). Tags are collected from tag nodes (skipping tags inside links/images) and deduplicated preserving case; mentions are extracted too but `RebuildMemoPayload` discards them.

These stored values surface on the API as `Memo.tags` and `Memo.property` (`server/router/api/v1/memo_service_converter.go:47-51`, `315-325`) and drive user stats aggregation (`server/router/api/v1/user_service_stats.go:138-155`) plus filtering (`store/memo.go`). The list preview text (`Memo.snippet`) is a separate derived field computed per response by `GenerateSnippet` rather than stored (`server/router/api/v1/memo_service_webhooks.go:83-90`, used at `memo_service_converter.go:76-80`).
