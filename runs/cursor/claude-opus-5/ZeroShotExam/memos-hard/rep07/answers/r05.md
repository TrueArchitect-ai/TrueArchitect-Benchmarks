**Premise correction:** There is no GraphQL schema in this repository. A case-insensitive search for `graphql` / `gql` across the entire tree (excluding `.git`) returns zero matches, and neither `go.mod` nor `web/package.json` pulls in any GraphQL, Apollo, or Relay dependency. Memos has never exposed a GraphQL endpoint — the README advertises "full REST and gRPC APIs," not GraphQL.

**What the public API surface actually is:** the schema is defined in Protocol Buffers under `proto/api/v1/`, in package `memos.api.v1`. Eight service definitions live there, one per file:

| File | Service |
| --- | --- |
| `proto/api/v1/memo_service.proto` | `MemoService` |
| `proto/api/v1/user_service.proto` | `UserService` |
| `proto/api/v1/auth_service.proto` | `AuthService` |
| `proto/api/v1/instance_service.proto` | `InstanceService` |
| `proto/api/v1/attachment_service.proto` | `AttachmentService` |
| `proto/api/v1/shortcut_service.proto` | `ShortcutService` |
| `proto/api/v1/idp_service.proto` | `IdentityProviderService` |
| `proto/api/v1/ai_service.proto` | `AIService` |

Shared message types are in `proto/api/v1/common.proto`, and `proto/store/` holds internal storage messages that are not part of the public API.

REST paths are declared inline on each RPC via `google.api.http` annotations rather than in a separate routing file. For example, `ListMemos` is annotated `get: "/api/v1/memos"` and `GetMemo` is `get: "/api/v1/{name=memos/*}"` in `proto/api/v1/memo_service.proto`.

Code generation is driven by `proto/buf.gen.yaml` (run with `cd proto && buf generate`), which fans out to Go structs and gRPC stubs, Connect handlers, grpc-gateway REST shims, an OpenAPI document, and TypeScript clients. Outputs land in `proto/gen/api/v1/` (including `apiv1connect/`), the spec at `proto/gen/openapi.yaml`, and TypeScript types at `web/src/types/proto/`. Per `AGENTS.md`, these generated files must not be hand-edited.

At runtime the same service implementations are served over two protocols, wired up in `server/router/api/v1/v1.go`. The grpc-gateway mux handles the REST surface at `/api/v1/*` and `/file/*` (lines 123-129), while Connect RPC handlers are mounted at `/memos.api.v1.*` for browser clients, replacing grpc-web (lines 139-144). The Connect layer in `server/router/api/v1/connect_handler.go` and `connect_services.go` is a thin wrapper that delegates each method to the underlying gRPC implementation, keeping a single source of truth for business logic.

Two things sit outside the proto-generated surface: Server-Sent Events, registered separately via `RegisterSSERoutes` in `server/router/api/v1/sse_handler.go`, and the MCP server in `server/router/mcp/`, which derives its tool catalog by parsing the generated `proto/gen/openapi.yaml`. Unauthenticated public routes are allow-listed in `server/router/api/v1/acl_config.go`.
