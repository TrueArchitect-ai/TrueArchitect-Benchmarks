h15.

Memo visibility is not centralized in one authorizer — each surface that can expose memo data re-implements the same PUBLIC / PROTECTED / PRIVATE rule. Here are the distinct enforcement sites:

Single-memo read check (`checkMemoReadAccess`, used by `GetMemo` and `ListMemoComments`) — `server/router/api/v1/memo_service.go` (lines 39–68, called at 356/367 and from `memo_service_comments.go:148`)
Memo list query scoping (`ListMemos` builds a viewer-scoped `VisibilityList` / CEL filter) — `server/router/api/v1/memo_service.go` (lines 218–227)
Comment creation and comment list scoping (`CreateMemoComment` private check; `ListMemoComments` per-viewer `memoFilter`) — `server/router/api/v1/memo_service_comments.go` (lines 41–43, 156–161)
Reaction service (`ListMemoReactions`, `UpsertMemoReaction`, `DeleteMemoReaction`) — `server/router/api/v1/reaction_service.go` (lines 29–41, 82–85, 130–140)
Memo attachment listing (`ListMemoAttachments`) — `server/router/api/v1/memo_attachment_service.go` (lines 213–225)
Attachment metadata access via API (`checkAttachmentAccess`, used by `GetAttachment`) — `server/router/api/v1/attachment_service.go` (lines 419–455)
Raw blob/thumbnail serving over HTTP (`checkAttachmentPermission`, includes the anonymous-instance and `share_token` branches) — `server/router/fileserver/fileserver.go` (lines 650–704)
SSE event fan-out filter (`SSEClient.canReceive`) — `server/router/api/v1/sse_hub.go` (lines 134–144)
User stats aggregation (`ListAllUserStats`, `GetUserStats`) — `server/router/api/v1/user_service_stats.go` (lines 83–92, 217–221)
Notification payload redaction (`canViewerAccessMemo` gating inbox notification content) — `server/router/api/v1/user_service_notifications.go` (lines 302–316, used at 337/342/370/385)
Email notification dispatch (its own duplicate `canViewerAccessMemo`) — `server/notification/email.go` (lines 306–320, used at 155/187)
Mention-notification eligibility (private memos/comments don't notify others) — `server/router/api/v1/memo_mention_helpers.go` (lines 62–84)
Public feed surfaces, which hard-code `VisibilityList: {Public}` — `server/router/rss/rss.go` (lines 90, 141) and `server/router/frontend/frontend.go` (sitemap, line 150)
Share-token bypass path (`GetMemoByShare` returns a memo of any visibility once the token is valid and unexpired; token creation restricted to creator/admin) — `server/router/api/v1/memo_share_service.go` (lines 23–45, 151–208)

The query-scoping sites all funnel into the same store mechanism, which translates `FindMemo.VisibilityList` into a SQL `IN` clause per driver: `store/memo.go:69`, `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`. That is the shared mechanism, not an independent decision point — the decision of which visibilities to allow is made in each caller listed above.
