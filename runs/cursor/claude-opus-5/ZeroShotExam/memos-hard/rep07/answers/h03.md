`internal/idp`; `internal/idp/oauth2`

The abstraction lives in `internal/idp/idp.go`, which is a tiny package holding just the shared `IdentityProviderUserInfo` struct (identifier, display name, email, avatar URL) that any provider must produce. The only concrete implementation shipped is OAuth2, in `internal/idp/oauth2/oauth2.go`, whose `IdentityProvider` type wraps a `storepb.OAuth2Config` and implements `ExchangeToken` (with optional PKCE `code_verifier`) plus user-info fetching via configurable field mapping.

Both are consumed from a single place, `server/router/api/v1/auth_service_sso.go`, which imports the abstraction and the OAuth2 implementation to handle SSO sign-in. There is no SAML, LDAP, or generic OIDC package in the repo — OIDC-style providers are configured as OAuth2 with explicit auth/token/user-info URLs, and the stored config type is `storepb.OAuth2Config` (see `store/idp.go`).
