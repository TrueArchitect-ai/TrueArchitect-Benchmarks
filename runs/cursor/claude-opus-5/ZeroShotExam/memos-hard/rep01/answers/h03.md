`internal/idp` (Go package `idp`) defines the identity-provider abstraction, and `internal/idp/oauth2` is the only concrete protocol implementation that ships.

The abstraction package is deliberately thin: `internal/idp/idp.go` contains just the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider must produce. There is no Go interface type — the contract is the normalized user-info struct plus the de facto `ExchangeToken` / `UserInfo` method pair.

`internal/idp/oauth2/oauth2.go` implements that contract for OAuth2. Its `IdentityProvider` type wraps a `storepb.OAuth2Config`, does the authorization-code exchange via `golang.org/x/oauth2` (with optional PKCE `code_verifier`), then calls the configured `UserInfoUrl` and maps raw claims into `idp.IdentityProviderUserInfo` using the config's `FieldMapping`.

The only consumer is `server/router/api/v1/auth_service_sso.go`, which imports both packages and constructs the OAuth2 provider to resolve or create the SSO-linked user. Note that OIDC is not a separate package here — OIDC providers are handled through the same generic OAuth2 implementation by pointing `UserInfoUrl` and the field mappings at the OIDC endpoints, and there are no SAML or LDAP implementations in the tree.
