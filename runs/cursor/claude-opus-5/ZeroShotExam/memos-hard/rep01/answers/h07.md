The browser hits the native file-server route `GET /file/users/{username}/avatar`, and the image bytes come from the `avatar_url` column of the `user` table, stored as a base64 data URI and decoded at serve time.

Two things worth noting. There is no separate avatar table or blob store; the avatar lives entirely in `user.avatar_url` as a `data:image/...;base64,...` string, which is why the last hop is a regex parse plus base64 decode rather than a file or S3 read. Separately, the React `UserAvatar` component renders `avatarUrl` from the user proto directly (web/src/components/UserAvatar.tsx), so in most of the UI the image arrives inline with the user JSON rather than through this endpoint. The `"/memos.api.v1.UserService/GetUserAvatar"` entry in server/router/api/v1/acl_config.go:25 is stale — no such RPC exists in the proto or service code.
