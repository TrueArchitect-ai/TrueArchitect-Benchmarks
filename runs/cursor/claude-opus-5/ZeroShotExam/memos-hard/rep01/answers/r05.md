**Premise correction:** There is no GraphQL schema in this repository. I searched the whole tree (excluding `.git`) for `graphql`/`gqlgen` and for `*.graphql`/`*.graphqls`/`*.gql` files and found zero matches. Memos has never exposed a GraphQL API; its public API is defined in Protocol Buffers.

**Where the public API surface actually lives**

The single source of truth is the `.proto` files in `proto/api/v1/`, package `memos.api.v1`. Eight services are declared there:

| File | Service |
| --- | --- |
| `proto/api/v1/memo_service.proto` | `MemoService` |
| `proto/api/v1/user_service.proto` | `UserService` |
| `proto/api/v1/auth_service.proto` | `AuthService` |
| `proto/api/v1/instance_service.proto` | `InstanceService` |
| `proto/api/v1/attachment_service.proto` | `AttachmentService` |
| `proto/api/v1/shortcut_service.proto` | `ShortcutService` |
| `proto/api/v1/idp_service.proto` | `IdentityProviderService` |
| `proto/api/v1/ai_service.proto` | `AIService` |

Shared message types live in `proto/api/v1/common.proto`. Each RPC carries a `google.api.http` annotation that defines its REST mapping, for example `CreateMemo` maps to `POST /api/v1/memos` and `GetMemo` to `GET /api/v1/{name=memos/*}` (`proto/api/v1/memo_service.proto` lines 17–45). The design deliberately follows Google's API Improvement Proposals, as stated in `proto/api/v1/README.md`.

**How it's generated and served**

Code generation is driven by `buf` (`proto/buf.gen.yaml`, run via `cd proto && buf generate`). It emits Go protobuf/gRPC/Connect/grpc-gateway stubs into `proto/gen/api/v1/`, an OpenAPI 3.0.3 spec at `proto/gen/openapi.yaml`, and TypeScript clients into `web/src/types/proto/` for the frontend. The OpenAPI file is the closest analogue to a "schema document" for the public API; it is embedded into the binary by `proto/openapi_embed.go` and consumed at runtime by the MCP router (`server/router/mcp/service.go`) to build its tool catalog.

At runtime the server exposes three protocol front ends, all wired in `server/router/api/v1/v1.go` (`RegisterGateway`, called from `server/server.go:88`):

- REST/JSON through grpc-gateway, mounted at `/api/v1/*` and `/file/*` (lines 96–129).
- Connect RPC for the browser client, mounted at `/memos.api.v1.*` (lines 139–144), with handlers in `server/router/api/v1/connect_handler.go` and method bodies in `server/router/api/v1/connect_services.go`.
- Native gRPC, since the same `APIV1Service` implements the generated gRPC server interfaces.

Two useful related notes: unauthenticated/public route policy is configured in `server/router/api/v1/acl_config.go`, and `proto/store/` holds internal storage messages that are *not* part of the public API. `AGENTS.md` (lines 10, 61, 67–68) documents this same layering.
