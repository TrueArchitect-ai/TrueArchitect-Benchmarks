### How I determined which one actually runs

I followed the concrete value that gets bound to the interface, rather than the interface itself:

1. **The default driver name is `"sqlite"`.** In `cmd/memos/main.go` the flag and the viper default both hardcode it (`viper.SetDefault("driver", "sqlite")` at line 122, `rootCmd.PersistentFlags().String("driver", "sqlite", ...)` at line 130). With no flags supplied, `viper.GetString("driver")` therefore yields `"sqlite"` into `profile.Driver` (line 43). I also checked that nothing else silently changes this default: `scripts/entrypoint.sh` only handles `MEMOS_DSN`, and the only `MEMOS_DRIVER` assignments in the repo are in test container plumbing (`store/test/containers.go`), not the shipped runtime.

2. **That string picks the implementation via a switch.** `db.NewDBDriver` in `store/db/db.go:18-27` dispatches on `profile.Driver`, so `"sqlite"` returns `sqlite.NewDB(profile)`, which constructs a `&sqlite.DB{...}` (`store/db/sqlite/sqlite.go:58-60`) using the `modernc.org/sqlite` `sql.Open("sqlite", ...)` connection.

3. **That single concrete value is the store's only driver.** `main.go:64` passes it to `store.New(dbDriver, instanceProfile)`, which stashes it in the unexported `driver Driver` field (`store/store.go:38-58`). There is no decorator, cache layer, or transaction wrapper around writes — the caches in `Store` are only for instance settings, users, and user settings.

4. **The save path reaches that field with no other insert route.** Saving a memo goes `APIV1Service.CreateMemo` → `s.Store.CreateMemo` (`server/router/api/v1/memo_service.go:115`) → `s.driver.CreateMemo(ctx, create)` (`store/memo.go:113`), whose only work of its own is UID validation. Grepping every non-test `CreateMemo` reference confirmed the store method is the sole entry point, so the dynamic dispatch at `store/memo.go:113` lands on the SQLite method.

A useful corroborating detail: the error handling at `memo_service.go:119-121` checks for `"UNIQUE constraint failed"` (SQLite's wording) alongside the Postgres and MySQL variants, which is consistent with SQLite being the default-path backend.
