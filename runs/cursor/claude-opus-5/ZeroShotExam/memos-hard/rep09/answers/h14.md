h14.

**Computation site:** `memopayload.RebuildMemoPayload` in `server/runner/memopayload/runner.go` (lines 74-88) is the single entry point. It delegates the actual parsing to the markdown service's `ExtractAll`, implemented with a goldmark AST walk in `internal/markdown/markdown.go` (lines 356-422); the equivalent standalone path is `ExtractProperties` (lines 193-241). The result is stored in the memo's `payload` column as `MemoPayload.Property` plus `MemoPayload.Tags`, defined in `proto/store/memo.proto` (lines 7-22) and surfaced to the API as `Memo.Property` (output-only) in `proto/api/v1/memo_service.proto` (lines 256, 271-279).

**Triggers:**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, called on the new `store.Memo` before insertion (comment creation and any other memo creation flow through this same RPC).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:435-451`, but only when `content` is present in the update mask; the rebuilt payload is then assigned to `update.Payload` alongside the new content. Updates that touch only `visibility`, `pinned`, `state`, timestamps, or `location` do not recompute it, and `touchMemoUpdatedTimestamp` in `server/router/api/v1/memo_update_helpers.go:16-25` leaves the payload untouched.
- Bulk backfill — `Runner.RunOnce` in `server/runner/memopayload/runner.go:27-72` rebuilds and persists payloads for every memo in batches of 100. Note that nothing currently calls it; `server/server.go:163` only wires up the `s3presign` runner, so this path is effectively dormant.

**Extracted properties:** `has_link` (any link node), `has_code` (code block, fenced code block, or inline code span), `has_task_list` (any GFM task checkbox), `has_incomplete_tasks` (a checkbox with `IsChecked == false`), and `title` (plain text of the first block-level child of the document, only if it is an H1 heading). The same pass also collects deduplicated `tags` from `#tag` nodes, skipping tags nested inside links or images (`asMemoTagNode`/`isTagNodeInLinkOrImage`, `internal/markdown/markdown.go:122-140`), and mentions, though `RebuildMemoPayload` persists only tags and property.

One clarification about "previews": the `Memo.snippet` field is *not* part of this stored payload. It is computed on every response by `getMemoContentSnippet` (`server/router/api/v1/memo_service_webhooks.go:83-90`), which calls `GenerateSnippet(content, 64)` and is invoked from the converter at `server/router/api/v1/memo_service_converter.go:76-80`, from relation conversion (lines 221-273), and from notification payloads (`server/router/api/v1/user_service_notifications.go:318-323`).
