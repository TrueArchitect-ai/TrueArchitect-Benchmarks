**Premise correction:** This repository (Memos, `usememos/memos`) has no GraphQL API at all. A case-insensitive full-text search across the whole tree for `graphql`, `gql`, and `apollo` returns zero matches, and there are no `.graphql`/`.gql`/`.graphqls` schema files. There is no GraphQL server library in `go.mod` and no GraphQL client in the web app. So there is no GraphQL schema to point at.

**The actual API surface: Protocol Buffers.** The public API is defined as protobuf service definitions in `proto/api/v1/`, one file per service:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto` (shared messages)

`AGENTS.md` confirms the split: `proto/api/v1/` is "Public API service definitions" while `proto/store/` holds "Internal storage proto messages". The design follows Google's API Improvement Proposals, per `proto/api/v1/README.md`.

Each RPC carries a `google.api.http` annotation that defines its REST mapping, so the REST surface is derived from the proto rather than declared separately:

```17:30:proto/api/v1/memo_service.proto
service MemoService {
  // CreateMemo creates a memo. The request body is a Memo; set its content
  // (Markdown) and visibility (PRIVATE | PROTECTED | PUBLIC, default PRIVATE).
  // The memo is owned by the authenticated user; requires authentication.
  rpc CreateMemo(CreateMemoRequest) returns (Memo) {
    option (google.api.http) = {
      post: "/api/v1/memos"
      body: "memo"
    };
```

**Code generation.** `proto/buf.gen.yaml` drives `buf generate`, emitting Go message/gRPC/Connect/grpc-gateway code into `proto/gen/api/v1/`, an OpenAPI spec at `proto/gen/openapi.yaml`, and TypeScript types into `web/src/types/proto/`. These outputs are generated, not hand-edited.

**How it's served.** `server/router/api/v1/v1.go` registers every service twice: through a grpc-gateway mux mounted at `/api/v1/*` and `/file/*` for REST clients (lines 96–129), and through Connect RPC handlers mounted at `/memos.api.v1.*` for the browser client (lines 131–144). The Connect handlers are wired up in `server/router/api/v1/connect_handler.go` and delegate to the same gRPC implementations via `server/router/api/v1/connect_services.go`, keeping one source of business logic. Public (unauthenticated) endpoints are allowlisted in `server/router/api/v1/acl_config.go`.

Two adjacent non-protobuf surfaces exist as well: an MCP server in `server/router/mcp/` that builds its tool catalog by parsing the embedded `proto/gen/openapi.yaml` (see `proto/openapi_embed.go` and `server/router/mcp/service.go`), and an RSS feed in `server/router/rss/rss.go`.
