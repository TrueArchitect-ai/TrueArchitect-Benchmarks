h15.

Memo visibility is not centralized in a single helper — it is re-implemented at each surface that can expose a memo (or memo-derived data). Below are the distinct enforcement sites, with the primary ones first.

`checkMemoReadAccess` helper (single-memo read gate for `GetMemo`, parent-memo check, and `ListMemoComments`; also handles archived-memo visibility) — `server/router/api/v1/memo_service.go` (helper at line 39, used at lines 356/367 and `server/router/api/v1/memo_service_comments.go:148`)
`ListMemos` query-level visibility filter (anonymous gets `VisibilityList = [PUBLIC]`; authenticated gets a CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:218-227`
HTTP file server attachment gate `checkAttachmentPermission` (memo visibility for attachment blobs, plus anonymous-instance rule and `share_token` bypass) — `server/router/fileserver/fileserver.go:650-704`
gRPC/Connect attachment gate `checkAttachmentAccess` — `server/router/api/v1/attachment_service.go:422-455`
`ListMemoAttachments` inline visibility check — `server/router/api/v1/memo_attachment_service.go:214-225`
Reaction endpoints inline visibility checks (`ListMemoReactions`, `UpsertMemoReaction`) — `server/router/api/v1/reaction_service.go:30-41` and `:83-85`
`CreateMemoComment` parent-memo visibility check, and `ListMemoComments` comment-level CEL filter — `server/router/api/v1/memo_service_comments.go:41-43` and `:156-161`
Memo relation listing filter (`ListMemoRelations`) — `server/router/api/v1/memo_relation_service.go:107-118`
Batch relation loading filter used by memo conversion — `server/router/api/v1/memo_service_converter.go:182-206`
SSE delivery filter `SSEClient.canReceive` (per-subscriber gate on broadcast events) — `server/router/api/v1/sse_hub.go:134-144` (event visibility populated in `server/router/api/v1/sse_event_helpers.go:29-37`)
User stats visibility filters (`ListAllUserStats` and `GetUserStats`) — `server/router/api/v1/user_service_stats.go:84-91` and `:216-221`
RSS feeds restricted to public memos (explore and per-user) — `server/router/rss/rss.go:90` and `:141`
Sitemap restricted to public memos — `server/router/frontend/frontend.go:150`
Share-token capability path that intentionally bypasses visibility (token validity/expiry replaces the visibility check) — `server/router/api/v1/memo_share_service.go:153-208`
Notification payload gating `canViewerAccessMemo` (whether a notification recipient may see memo content) — `server/router/api/v1/user_service_notifications.go:302-316`
Email notification gating `canViewerAccessMemo` (duplicate implementation for outbound email) — `server/notification/email.go:306-320`
Mention notification access gate `canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-89`

The store layer only provides the mechanism, not the policy: `VisibilityList` and CEL filters are translated to SQL in `store/memo.go:69` and the per-dialect builders (`store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`), so every caller above must opt in to the correct filter itself.
