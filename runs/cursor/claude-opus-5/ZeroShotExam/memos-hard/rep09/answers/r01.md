**Premise correction:** There is no Redis in this repository, and no Redis connection to configure. A case-insensitive search for "redis" across the whole tree (excluding `.git`) returns zero matches — nothing in `go.mod`, no client dependency, no config field, no environment variable, and no compose/deployment file referencing it. The cache layer is a hand-rolled, in-process, in-memory cache, so there is no connection string, host, port, or auth to point anywhere.

**Actual mechanism.** The cache implementation lives in `store/cache/cache.go`: a `Cache` struct backed by a `sync.Map` with an `atomic.Int64` item counter, plus a background goroutine (`cleanupLoop`) that sweeps expired entries on a ticker. Each stored `item` carries an absolute `expiration` timestamp set at write time, and `Get` lazily evicts an entry it finds past expiry. Because state lives inside the process, caches are not shared across server instances and are lost on restart.

The caches are constructed once in `store.New` in `store/store.go`, where a single `cache.Config` is built and reused for all three caches — instance settings, users, and user settings:

```40:53:store/store.go
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

**TTL for user entries: 10 minutes.** Every write path for users in `store/user.go` (`CreateUser`, `CreateUserIfNoUsers`, `UpdateUser`, `ListUsers`, and `GetUser`) calls `s.userCache.Set(...)`, and `Set` delegates to `SetWithTTL` using the config's `DefaultTTL` (`store/cache/cache.go` lines 92-95). No caller ever passes a custom TTL — `SetWithTTL` is only invoked directly from tests. That 10-minute value is hard-coded in `store/store.go`; it is not read from configuration or environment, and it happens to match the package default in `cache.DefaultConfig()`.

Two related details worth knowing. Entries can be evicted before the TTL elapses: `MaxItems` is 1000, and exceeding it triggers `cleanupOldest`, which drops roughly 20% of entries. Separately, users are only served from cache when the lookup is by ID — `GetUser` checks `userCache` only if `find.ID != nil`, so lookups by username or email always hit the database (`store/user.go` lines 148-156). Invalidation on delete is explicit, via `deleteUserCache` in `store/user_delete.go`, which removes the user key and the associated user-setting keys.

For completeness, the only other TTL-bearing cache in the codebase is unrelated to users: `instanceStatsCacheTTL = 60 * time.Second` in `server/router/api/v1/instance_stats.go`, a small memoization of `GetInstanceStats`.
