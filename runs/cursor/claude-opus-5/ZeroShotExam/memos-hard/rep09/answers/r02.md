The premise is incorrect: this repository (Memos) has no per-user API rate-limiting middleware at all, so there are no request limits to report. I searched the whole Go tree for rate limiting, throttling, and the usual libraries (`golang.org/x/time/rate`, tollbooth, etc.) and found nothing wired into the request path. `golang.org/x/time v0.15.0` appears in `go.mod` only as an indirect dependency, and the only mentions of rate limiting are aspirational notes in the email package docs (`internal/email/README.md` line 286 and `internal/email/doc.go` line 86), describing email-send rate limiting as a future/consumer concern rather than implemented code.

What is actually registered in the request path:

- Echo-level middleware in `server/server.go` (lines 51–52): only `middleware.Recover()` and the CORS middleware from `server/cors.go`.
- Static-file and SPA-fallback middleware in `server/router/frontend/frontend.go` (lines 54–59).
- A gRPC-Gateway auth middleware and four Connect interceptors registered in `server/router/api/v1/v1.go` (lines 69–98 and 133–138): `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor`, all defined in `server/router/api/v1/connect_interceptors.go`. These handle header-to-metadata conversion, logging, panic recovery, and authentication — none of them count or reject requests by volume.

The closest things to "limits," none of which are per-user rate limits:

- A 256 MiB cap on request body size, `maxAPIRequestBytes = 256 << 20`, applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` in `server/router/api/v1/v1.go` (lines 20, 126, 141, 144).
- Global concurrency semaphores, not per-user: 3 concurrent thumbnail generations and 2 concurrent image processing operations in `server/router/api/v1/v1.go` (lines 59–60), plus `maxConcurrentThumbnails = 3` in `server/router/fileserver/fileserver.go` (line 46).
- A memo content-length limit read from instance settings in `server/router/api/v1/memo_service.go` (lines 101–106, 595–601), which bounds payload size per memo rather than request frequency.

So if you need per-user rate limiting, it would have to be added; nothing exists to point you at today.
