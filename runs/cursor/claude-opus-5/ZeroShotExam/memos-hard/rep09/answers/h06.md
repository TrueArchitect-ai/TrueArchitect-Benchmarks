**Answer:** `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` — all converge on `webhook.Post` in `internal/webhook/webhook.go` (line 120), which is the only place an `http.Request` is built and sent to the stored URL.

### The paths

Each handler dispatches to a per-activity helper in `server/router/api/v1/memo_service_webhooks.go`, which loads the user's saved webhooks via `s.Store.GetUserWebhooks` and hands each payload to `webhook.PostAsync`:

| RPC handler | Call site | Dispatcher |
| --- | --- | --- |
| `CreateMemo` | `server/router/api/v1/memo_service.go:157` | `DispatchMemoCreatedWebhook` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:513` | `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:562` | `DispatchMemoDeletedWebhook` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:119` | `DispatchMemoCommentCreatedWebhook` |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:48` | `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:48` | `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` |

`SetMemoAttachments` and `SetMemoRelations` reach the dispatcher through the shared helper `dispatchMemoUpdatedSideEffects` in `server/router/api/v1/memo_update_helpers.go:66`.

### Convergence point

Both `webhook.PostAsync` call sites (`memo_service_webhooks.go:43` and `:71`) enqueue onto the bounded `asyncPostQueue`, and the four worker goroutines started in `internal/webhook/webhook.go`'s `init()` each call `Post`. So `Post` is the single funnel: it marshals the payload, adds the optional `webhook-signature` HMAC headers, and issues the request through `safeClient`, whose `safeDialContext` rejects reserved/private IPs at dial time.

If you want the enqueue-side funnel rather than the delivery-side one, that is `webhook.PostAsync` (`internal/webhook/webhook.go:184`) — but the actual HTTP request only happens in `Post`.

### Related but distinct

Two other handler families make outbound HTTP requests to configured URLs, and they do *not* pass through `webhook.Post`:

- `GetLinkMetadata` and `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go`) fetch a caller-supplied URL via `httpgetter.GetHTMLMeta`.
- The SSO exchange in `server/router/api/v1/auth_service_sso.go:121` calls the admin-configured `UserInfoUrl` in `internal/idp/oauth2/oauth2.go:85`.

Also note that the webhook management handlers (`CreateUserWebhook`, `UpdateUserWebhook`) only do a DNS resolution inside `webhook.ValidateURL` (`internal/webhook/validate.go`), not an HTTP request.
