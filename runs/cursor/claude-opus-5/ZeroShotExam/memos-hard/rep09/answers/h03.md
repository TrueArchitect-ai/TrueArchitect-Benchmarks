**`internal/idp`; `internal/idp/oauth2`**

The abstraction lives in the `internal/idp` package, which is deliberately tiny — it only declares the provider-neutral user shape that any identity provider must produce:

```3:8:/bench/repo/internal/idp/idp.go
type IdentityProviderUserInfo struct {
	Identifier  string
	DisplayName string
	Email       string
	AvatarURL   string
}
```

The single concrete protocol implementation is OAuth2, in `internal/idp/oauth2`. It defines an `IdentityProvider` backed by `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (including optional PKCE `code_verifier` support), and `UserInfo`, which maps provider claims into `idp.IdentityProviderUserInfo` via the configured field mapping (`internal/idp/oauth2/oauth2.go`).

Two things confirm OAuth2 is the only implementation shipped: `internal/idp` contains just `idp.go` plus the `oauth2/` subdirectory, and the only consumer is the SSO login path in `server/router/api/v1/auth_service_sso.go`, which imports exactly those two packages. On the schema side, the provider config in `proto/store/idp.proto` has `OAuth2Config oauth2_config = 1;` as its sole config variant, so there is no SAML or dedicated OIDC provider in the codebase (OIDC providers are handled generically through the OAuth2 userinfo endpoint and field mapping).
