Neither — the premise is off. This repository (memos) has no external message broker at all. There is no NATS, RabbitMQ, AMQP, Kafka, or SQS dependency anywhere: `go.mod` contains none of those, and grepping the whole tree for those names only hits vendored git pack files, a locale string, and the SQLite seed dump.

The actual mechanism is an in-process buffered Go channel with a fixed pool of goroutine workers, all declared inside the single file `internal/webhook/webhook.go`:

```39:55:/bench/repo/internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
)

func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

So the "queue" is the package-level `asyncPostQueue` channel with a capacity of 128, and the four consuming goroutines are started from that package's `init()` function, meaning they exist for the lifetime of the process as soon as the package is linked in. Each worker just calls `Post`, which does the actual HTTP POST through `safeClient` (a client whose transport blocks reserved/private IPs to prevent SSRF) and optionally adds Standard Webhooks HMAC-SHA256 headers.

Producers enqueue via `PostAsync` in the same file (lines 184–196), which does a non-blocking `select` send and logs a warning to drop the payload when the buffer is full. Callers are the memo webhook dispatchers in `server/router/api/v1/memo_service_webhooks.go` (`webhook.PostAsync(payload)` at lines 43 and 71), invoked for the `memos.memo.created`, `memos.memo.updated`, `memos.memo.deleted`, and `memos.memo.comment.created` activity types.

Two consequences worth noting, since they follow directly from there being no broker: delivery is best-effort and in-memory only, so anything still sitting in the channel is lost on process restart, and there is no retry or dead-letter path — a failed `Post` is only logged.
