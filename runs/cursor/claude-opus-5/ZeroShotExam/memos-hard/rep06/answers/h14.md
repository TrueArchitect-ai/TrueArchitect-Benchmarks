**Answer (computation site; triggers; extracted properties):**

`memopayload.RebuildMemoPayload` → `markdown.Service.ExtractAll` (`server/runner/memopayload/runner.go:74`, `internal/markdown/markdown.go:356`); memo create, memo update when the `content` field is in the update mask, and the batch `Runner.RunOnce` backfill; tags plus the `MemoPayload.Property` fields `title`, `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`.

Details:

- **Where.** `RebuildMemoPayload` in `server/runner/memopayload/runner.go` is the single entry point. It ensures `memo.Payload` is non-nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, and assigns `memo.Payload.Tags` and `memo.Payload.Property`. The actual work is one goldmark AST walk in `ExtractAll` (`internal/markdown/markdown.go:356-422`); `ExtractProperties` (line 193) is the equivalent standalone version. The markdown service is built with the tag and mention extensions in `server/router/api/v1/v1.go:48`.

- **Triggers.**
  - `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before `Store.CreateMemo`. This also covers comments, since `CreateMemoComment` delegates to `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
  - `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only inside the `path == "content"` branch of the update-mask loop, and the rebuilt payload is written via `update.Payload = memo.Payload`. Other mask paths (visibility, pinned, state, timestamps) do not recompute it.
  - `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) rebuilds payloads for every memo in batches of 100 and persists each with `Store.UpdateMemo`. Note this runner type is defined but I found no call site wiring it into startup — `server/server.go:163` only runs the s3presign runner — so it is currently a backfill utility rather than an automatic trigger.

- **What is extracted.** From the single walk: `#tags` (deduplicated, case preserved; tag nodes nested inside links or images are skipped, `internal/markdown/markdown.go:122-140`), and the `Property` message: `Title` from the document's first block-level child only when it is an H1 heading, `HasLink` for link nodes, `HasCode` for code blocks, fenced code blocks, and inline code spans, `HasTaskList` for GFM task checkboxes, and `HasIncompleteTasks` when any checkbox is unchecked. `ExtractAll` also collects lowercased `@mentions` into `ExtractedData.Mentions`, but `RebuildMemoPayload` does not persist those into the payload. The property is surfaced to the API by `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315`) and drives the `property.hasLink` / `hasTaskList` / `hasCode` list filters in the web client (`web/src/contexts/MemoFilterContext.tsx:11`).

One adjacent thing worth separating out: the list/preview `snippet` is *not* part of this stored payload. It is computed on every read in `getMemoContentSnippet` (`server/router/api/v1/memo_service_webhooks.go:83`), which calls `GenerateSnippet(content, 64)` (`internal/markdown/markdown.go:264`) to produce plain text with code blocks skipped and truncation at a word boundary.
