The premise is incorrect: there is no nightly database-cleanup job in this repository, so it has no scheduled run time.

What actually exists:

- `internal/scheduler/` is a self-contained cron scheduler library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). Nothing outside that package imports it — a search for `internal/scheduler` across the Go sources returns only files inside the package itself, so no jobs of any kind are registered at runtime.
- The only "cleanup" job you'll find is illustrative documentation, not live code. The package doc shows a `daily-cleanup` job at `"0 2 * * *"` (2 AM daily) in `internal/scheduler/doc.go` lines 14-21, and `internal/scheduler/README.md` repeats that example plus a `stale-session-cleanup` at `"0 3 * * *"`. Similar schedules appear only in test files such as `internal/scheduler/example_test.go`.
- The application's actual background work isn't cron-driven at all. `server/server.go` (`startBackgroundRunners`, lines 153-174) starts only the S3 presign runner, which does one immediate pass and then loops on its own interval in `server/runner/s3presign/runner.go`. There is no database-cleanup runner.
- The one real cron expression in the repo is CI-related, not database-related: the stale-issue workflow at `.github/workflows/stale.yml` line 5 runs `"0 */8 * * *"` (every 8 hours).

If you're thinking of the 2 AM figure, that comes from the scheduler package's example snippet, which is never wired into the server.
