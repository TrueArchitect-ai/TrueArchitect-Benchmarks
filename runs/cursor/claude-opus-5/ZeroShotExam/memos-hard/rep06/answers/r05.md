**Premise correction:** There is no GraphQL schema in this repository. Memos has no GraphQL layer at all — no `.graphql`/`.gql` files, no `typeDefs`/`gql` template literals, no Apollo/graphql-js dependency in `web/package.json`, and zero case-insensitive matches for "graphql" anywhere outside `.git`. The public API is defined in **Protocol Buffers**, and the REST surface is derived from those `.proto` files rather than hand-written.

**Where the schema actually lives**

The single source of truth is `proto/api/v1/`, one file per service:

| File | Service |
|---|---|
| `proto/api/v1/memo_service.proto` | `MemoService` |
| `proto/api/v1/user_service.proto` | `UserService` |
| `proto/api/v1/auth_service.proto` | `AuthService` |
| `proto/api/v1/instance_service.proto` | `InstanceService` |
| `proto/api/v1/attachment_service.proto` | `AttachmentService` |
| `proto/api/v1/shortcut_service.proto` | `ShortcutService` |
| `proto/api/v1/idp_service.proto` | `IdentityProviderService` |
| `proto/api/v1/ai_service.proto` | `AIService` |
| `proto/api/v1/common.proto` | shared messages/enums |

All are in proto package `memos.api.v1` and follow the [Google API Improvement Proposals](https://google.aip.dev/), as stated in `proto/api/v1/README.md`. REST routes are attached inline via `google.api.http` annotations — for example, `CreateMemo` declares `post: "/api/v1/memos"` and `GetMemo` declares `get: "/api/v1/{name=memos/*}"`:

```21:37:proto/api/v1/memo_service.proto
  rpc CreateMemo(CreateMemoRequest) returns (Memo) {
    option (google.api.http) = {
      post: "/api/v1/memos"
      body: "memo"
    };
    option (google.api.method_signature) = "memo";
  }
  // ListMemos lists memos with pagination and filter.
  rpc ListMemos(ListMemosRequest) returns (ListMemosResponse) {
    option (google.api.http) = {get: "/api/v1/memos"};
    option (google.api.method_signature) = "";
  }
  // GetMemo gets a memo.
  rpc GetMemo(GetMemoRequest) returns (Memo) {
    option (google.api.http) = {get: "/api/v1/{name=memos/*}"};
    option (google.api.method_signature) = "name";
  }
```

**Code generation**

`proto/buf.gen.yaml` runs five plugins over those files: Go structs, gRPC stubs, ConnectRPC handlers, and a gRPC-Gateway into `proto/gen/`, plus TypeScript clients emitted directly into `web/src/types/proto`. A sixth plugin (`google-gnostic-openapi`) produces `proto/gen/openapi.yaml`, which is the closest thing to a machine-readable schema document for the public API. It is embedded into the binary by `proto/openapi_embed.go` and consumed at runtime by the MCP router in `server/router/mcp/service.go` to build its tool catalog.

**How the API is served**

`server/router/api/v1/v1.go` exposes the same protobuf-defined services over three transports, all mounted on one Echo HTTP server (`server/server.go`):

- **REST/JSON** via gRPC-Gateway on `/api/v1/*` and `/file/*` (`v1.go` lines 96–129)
- **ConnectRPC** on `/memos.api.v1.*`, used by the web client, registered in `server/router/api/v1/connect_handler.go` with per-method wrappers in `connect_services.go` (line 144)
- **Native gRPC** stubs, since `APIV1Service` embeds the generated `Unimplemented*Server` types (lines 22–30)

Alongside these, the server mounts non-protobuf surfaces: RSS (`server/router/rss`), a static file server (`server/router/fileserver`), Server-Sent Events (`server/router/api/v1/sse_handler.go`), MCP (`server/router/mcp`), and `/healthz`. The `README.md` describes this accurately as "full REST and gRPC APIs" — no GraphQL is claimed or implemented.
