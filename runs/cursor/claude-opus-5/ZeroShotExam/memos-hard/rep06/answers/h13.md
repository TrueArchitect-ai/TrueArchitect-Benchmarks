**`*markdown.service` (the only concrete impl) — built once by `markdown.NewService(WithTagExtension(), WithMentionExtension())` inside `NewAPIV1Service` — held by `APIV1Service`, `rss.RSSService`, and `memopayload.Runner`.**

**The interface**

`markdown.Service` is declared in `internal/markdown/markdown.go` (lines 31–55) with methods `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, and `RenameTag`.

**Implementation**

There is exactly one implementer: the unexported `service` struct wrapping a `goldmark.Markdown` instance (`internal/markdown/markdown.go` lines 57–60). No mocks, fakes, or alternate implementations exist anywhere in the repo — a search for other `ExtractAll` method definitions returns only this one. So `*service` is what always executes at runtime; the interface exists for dependency injection and testability rather than for swapping behavior.

Note that the parse/render pipeline behind it is configurable rather than polymorphic: `WithTagExtension()` and `WithMentionExtension()` (lines 71–82) append `extensions.TagExtension` / `extensions.MentionExtension` to the goldmark extender list alongside `extension.GFM`, and `RenderMarkdown`/`RenameTag` delegate to a separately constructed `renderer.NewMarkdownRenderer()` (`internal/markdown/renderer/markdown_renderer.go`), which is a plain struct, not an interface.

**Construction**

The single production construction site is `NewAPIV1Service` in `server/router/api/v1/v1.go` (lines 47–62), which enables both the tag and mention extensions. `server/server.go` line 85 then passes that same instance into `rss.NewRSSService(...)`, so the REST/gRPC API and the RSS feed share one service value.

Test-only constructions exist in `server/router/api/v1/test/test_helper.go` (lines 44–52, tags + mentions), `server/router/fileserver/fileserver_test.go` line 427 (tags only), and `server/router/rss/rss_test.go` line 54 (`markdown.NewService()` with no extensions).

**Holders**

- `APIV1Service.MarkdownService` — `server/router/api/v1/v1.go` line 35. Used for `ExtractAll` in `memo_mention_helpers.go` line 32, `GenerateSnippet` in `memo_service_webhooks.go` line 85, and passed to `memopayload.RebuildMemoPayload` in `memo_service.go` lines 108 and 447.
- `RSSService.MarkdownService` — `server/router/rss/rss.go` line 45, calling `RenderHTML` at line 339 for feed item bodies.
- `memopayload.Runner.MarkdownService` — `server/runner/memopayload/runner.go` line 16, consumed by `RunOnce` at line 52.

One caveat on that third holder: `memopayload.NewRunner` (line 19) has no caller outside its own definition — `server/server.go` only wires `s3presign.NewRunner`. The `Runner` field is therefore effectively dead wiring today; the code path that actually runs is the free function `RebuildMemoPayload(ctx, memo, markdownService)` (line 74), which takes the interface as a parameter rather than through a struct field.

Frontend markdown rendering (`web/src/components/MemoContent/`, react-markdown plus the `remark-tag`/`remark-mention` plugins) is entirely separate and does not sit behind this Go interface, as the doc comment at lines 28–30 of `internal/markdown/markdown.go` notes.
