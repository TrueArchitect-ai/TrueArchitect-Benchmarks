h02.

**delivery function — `Post` in `internal/webhook/webhook.go`; protection mechanism — `safeDialContext` + `isReservedIP` (dial-time IP blocklist) in `internal/webhook/webhook.go` and `internal/webhook/validate.go`**

Details:

**Where delivery executes.** `Post` (`internal/webhook/webhook.go`, lines 120–180) is the only place an outbound HTTP request is actually made: it marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and calls `safeClient.Do(req)`.

Content-change events don't call it directly. `server/router/api/v1/memo_service_webhooks.go` handles memo created/updated/deleted and comment-created events, looks up the creator's webhooks via `s.Store.GetUserWebhooks`, and calls `webhook.PostAsync(payload)` (lines 43 and 71). `PostAsync` just enqueues onto a buffered channel (`asyncPostQueue`, capacity 128, dropping with a warning when full); four worker goroutines started in the package `init()` pull from that channel and invoke `Post`. So the request leaves the process on a background worker goroutine, not the request goroutine.

**What protects it from internal addresses.** Two layers, both keyed on `isReservedIP` in `internal/webhook/validate.go`:

1. Dial-time enforcement (the real protection): `safeClient` is a shared `http.Client` whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go`, lines 32–37 and 59–77). It splits host/port, resolves the host with `net.DefaultResolver.LookupHost`, and refuses to dial if *any* resolved IP is in a reserved range. Because the check happens at dial time rather than at save time, it also defeats DNS rebinding.
2. Validation at configuration time: `webhook.ValidateURL` (`internal/webhook/validate.go`, lines 62–83) is called when a user creates or updates a webhook (`server/router/api/v1/user_service_webhooks.go`, lines 74, 161, 182). It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument`.

The blocklist is `reservedCIDRs` (`internal/webhook/validate.go`, lines 14–23): IPv4 loopback, the three RFC-1918 ranges, `169.254.0.0/16` (link-local, covering cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, and `fe80::/10`, parsed once into `reservedNetworks` at startup.

**Escape hatch.** The package-level `AllowPrivateIPs` flag short-circuits `isReservedIP` to always return false, disabling both layers. It's set from the `--allow-private-webhooks` CLI flag (default `false`) in `cmd/memos/main.go` (line 49, flag defined at line 133), intended for self-hosted deployments targeting LAN services.

One gap worth noting: the CIDR list does not include `0.0.0.0/8`, the IPv4-mapped IPv6 range (`::ffff:0:0/96`), or carrier-grade NAT `100.64.0.0/10`, so addresses like `0.0.0.0` or `::ffff:127.0.0.1` are not caught by `isReservedIP`.
