**No** — outside the driver-selection factory, no production or cross-package code constructs the MySQL driver. The only exception is a single in-package unit test that builds a zero-value struct literal to exercise a pure helper method.

Evidence:

The factory is the sole caller of the MySQL constructor:

```18:27:store/db/db.go
	switch profile.Driver {
	case "sqlite":
		driver, err = sqlite.NewDB(profile)
	case "mysql":
		driver, err = mysql.NewDB(profile)
	case "postgres":
		driver, err = postgres.NewDB(profile)
	default:
		return nil, errors.New("unknown db driver")
	}
```

- A repo-wide search for `store/db/mysql` imports and `mysql.NewDB(` calls in Go files returns exactly two hits, both in `store/db/db.go` (the import on line 8 and the call on line 22). No other package imports `github.com/usememos/memos/store/db/mysql`, so `mysql.NewDB` and the exported `mysql.DB` type are unreachable elsewhere.
- Everything that needs a driver goes through the factory instead: `cmd/memos/main.go:57`, `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(...)`.
- Inside the package, the constructor itself is the only place that builds the struct for real use (`store/db/mysql/mysql.go:29`, `driver := DB{profile: profile}`).

The one direct construction outside `NewDB` is a test in the same package:

```11:16:store/db/mysql/auth_config_test.go
func TestIsRetryableAuthenticationMutationError(t *testing.T) {
```

One thing worth clarifying to avoid a false positive: `store/test/containers.go` references `mysql.Run`, `mysql.WithDatabase`, and similar (lines 101–105), but those come from the testcontainers MySQL module, not the memos MySQL driver package — that code spins up a MySQL server container and then still obtains its driver through `db.NewDBDriver`.
