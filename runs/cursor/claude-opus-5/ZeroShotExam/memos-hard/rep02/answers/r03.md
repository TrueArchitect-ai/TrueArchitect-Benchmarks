r03. The premise is incorrect: there is no nightly database-cleanup job scheduled in this repository. The `internal/scheduler` package is a standalone, unused cron library — nothing outside the package ever calls `scheduler.New()` or `Register()`, so no jobs (cleanup or otherwise) are actually scheduled at runtime.

`internal/scheduler/README.md` also shows a `stale-session-cleanup` example at `0 3 * * *` (line 244), which is likewise illustrative only. None of these touch the database.

The periodic work that does run in this codebase is interval-based rather than cron-scheduled, and none of it is a nightly database cleanup:

- `server/runner/s3presign/runner.go` refreshes S3 presigned links on a 12-hour ticker (`runnerInterval = time.Hour * 12`), started from `server/server.go` lines 163 and 169.
- `store/cache/cache.go` expires in-memory cache entries every 5 minutes (`CleanupInterval`, defaulted in `store/store.go:42`).
- The only real cron expression in the repo is in CI: `.github/workflows/stale.yml` runs `0 */8 * * *` for stale issue triage.
