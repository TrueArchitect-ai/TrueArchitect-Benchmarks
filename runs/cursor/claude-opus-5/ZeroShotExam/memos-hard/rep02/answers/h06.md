All four `Dispatch*Webhook` methods end in `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which only enqueues onto a bounded channel; the four worker goroutines started in that package's `init()` (lines 42–55) drain the queue and call `Post`, which is the single place the outbound `http.NewRequest("POST", requestPayload.URL, ...)` is built and executed via `safeClient.Do`. So `Post` is the convergence point, with `PostAsync` as the shared enqueue step just before it.

Worth noting for scoping: SSRF protection lives on both sides of this boundary — `ValidateURL` rejects reserved/private addresses at configuration time, and `safeDialContext` re-checks at dial time to defeat DNS rebinding (`internal/webhook/validate.go`, `internal/webhook/webhook.go:59`). Other outbound HTTP in the repo (the `internal/httpgetter` link-metadata fetch and `internal/ai`) is driven by per-request or instance-level configuration rather than the stored webhook URL, and does not pass through `Post`.
