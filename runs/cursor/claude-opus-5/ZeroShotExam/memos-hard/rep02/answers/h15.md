h15.

Memo visibility is enforced independently in several places rather than through one shared gate. Here are the distinct enforcement sites:

`checkMemoReadAccess` (single-memo read gate for GetMemo, parent-memo check, ListMemoComments) — `server/router/api/v1/memo_service.go:39-68`, called at `memo_service.go:356,367` and `server/router/api/v1/memo_service_comments.go:148`
ListMemos query-level visibility narrowing (anonymous → PUBLIC only; signed-in → own memos plus PUBLIC/PROTECTED) — `server/router/api/v1/memo_service.go:218-227`
ListMemoComments comment-level visibility filter passed to the store — `server/router/api/v1/memo_service_comments.go:156-161`
CreateMemoComment parent-visibility check (private parent restricted to creator/admin) — `server/router/api/v1/memo_service_comments.go:41`
Reaction service inline visibility checks (`ListMemoReactions`, `UpsertMemoReaction`) — `server/router/api/v1/reaction_service.go:30-41,83`
`ListMemoAttachments` inline visibility check — `server/router/api/v1/memo_attachment_service.go:213-225`
`checkAttachmentAccess` (attachment metadata via API, derives access from linked memo visibility) — `server/router/api/v1/attachment_service.go:419-455`, called at `attachment_service.go:256`
`checkAttachmentPermission` (raw HTTP file serving at `/file/attachments/...`, including anonymous-instance rule and `share_token` fallback) — `server/router/fileserver/fileserver.go:649-704`, called at `fileserver.go:149`
User stats aggregation visibility filters (`ListAllUserStats`, per-user stats) — `server/router/api/v1/user_service_stats.go:84-90,217-221`
SSE delivery filtering (`SSEClient.canReceive`, drops private-memo events for non-creator/non-admin subscribers) — `server/router/api/v1/sse_hub.go:134-144`, with event visibility populated in `server/router/api/v1/sse_event_helpers.go:29-37`
Notification listing/conversion gate `canViewerAccessMemo` — `server/router/api/v1/user_service_notifications.go:302-316` (used at lines 337, 342, 370, 385)
Email notification gate `canViewerAccessMemo` (separate copy of the same rules) — `server/notification/email.go:306-320` (used at lines 155, 187)
Mention-notification eligibility based on memo visibility — `server/router/api/v1/memo_mention_helpers.go:62-84`
RSS feeds restricted to PUBLIC memos (explore and per-user feeds) — `server/router/rss/rss.go:90,141`
Sitemap restricted to PUBLIC memos — `server/router/frontend/frontend.go:149-151`
Share-token path that intentionally bypasses visibility (`GetMemoByShare` / `getActiveMemoShare`, archived and expired treated as not found) — `server/router/api/v1/memo_share_service.go:151-208`

Two supporting notes: the actual SQL filtering for `VisibilityList`/CEL filters lives in the store drivers (`store/db/sqlite/memo.go:96-102`, and the postgres/mysql equivalents), so the API sites above are what decide the filter values; and the MCP surface does not have its own check — its catalog only exposes `MemoService_ListMemos`/`MemoService_GetMemo` (`server/router/mcp/catalog.go:12-14`), which reuse the API v1 enforcement.
