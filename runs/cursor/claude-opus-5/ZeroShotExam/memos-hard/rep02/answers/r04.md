Neither. This repository (memos) has no external message broker at all — no NATS, no RabbitMQ, no Kafka, and nothing broker-like in `go.mod`. A repo-wide search for `nats`/`rabbitmq`/`amqp` turns up only an unrelated substring match inside `web/src/locales/ca.json`. So the premise that webhook delivery workers "consume from" a broker is incorrect.

The actual mechanism is an in-process Go channel with a fixed pool of goroutines, all inside the single `memos` binary:

- The "queue" is declared as a package-level buffered channel of capacity 128 in `internal/webhook/webhook.go`:

```39:40:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
)
```

- The "workers" are four goroutines started from that package's `init()`, each ranging over the channel and calling `Post` (a plain HTTP POST) for every payload, logging a warning on failure:

```42:55:internal/webhook/webhook.go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously", ...)
				}
			}
		}()
	}
}
```

- Producers enqueue via `PostAsync`, which does a non-blocking send and *drops* the delivery (with a warning) when the buffer is full:

```189:195:internal/webhook/webhook.go
	select {
	case asyncPostQueue <- requestPayload:
	default:
		slog.Warn("Dropped webhook dispatch because the async queue is full",
			slog.String("url", requestPayload.URL),
			slog.String("activityType", requestPayload.ActivityType))
	}
```

Callers are the memo lifecycle dispatchers in `server/router/api/v1/memo_service_webhooks.go` (created/updated/deleted/comment-created), which look up each user's webhooks from the store and call `webhook.PostAsync` per hook.

Two consequences worth noting, since they differ from broker semantics: the queue is purely in-memory, so pending deliveries are lost on process restart, and there are no retries or acknowledgements — a failed `Post` is only logged. Actual sending happens over a shared `http.Client` with a 30-second timeout and an SSRF-guarding dialer, with optional Standard Webhooks HMAC-SHA256 signing headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`).
