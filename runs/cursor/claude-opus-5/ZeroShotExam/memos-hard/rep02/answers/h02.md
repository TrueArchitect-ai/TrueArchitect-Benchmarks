h02.

**delivery function — `Post` in `internal/webhook/webhook.go`; protection mechanism — dial-time SSRF guard `safeDialContext`/`isReservedIP` in `internal/webhook/webhook.go` and `internal/webhook/validate.go`**

Here's how it fits together.

**Where delivery executes.** `Post` (`internal/webhook/webhook.go`, lines 120–180) is the only place an outbound HTTP request is actually made. It marshals the payload, builds a `POST`, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), then calls `safeClient.Do(req)` and validates the response status and body.

Callers never dial directly. The API layer calls `webhook.PostAsync`, which enqueues onto a bounded 128-slot channel drained by four goroutines started in `init()`; each worker calls `Post`. Content-change events enter through `DispatchMemoCreatedWebhook`, `DispatchMemoUpdatedWebhook`, `DispatchMemoDeletedWebhook`, and `DispatchMemoCommentCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go`, which look up the creator's registered webhooks and enqueue one payload each.

**What protects it.** The real enforcement is at dial time. The shared `safeClient` installs a custom `http.Transport` whose `DialContext` is `safeDialContext` (lines 32–37, 59–77). That function splits host/port, resolves the hostname via `net.DefaultResolver.LookupHost`, and rejects the connection if *any* returned address is reserved. Because the check happens on the address actually being dialed rather than on the URL string, it also defeats DNS rebinding — a hostname that passed validation at save time can't later resolve to `127.0.0.1` and get through.

The reserved ranges live in `internal/webhook/validate.go` (lines 14–23): IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (explicitly covering the cloud IMDS address `169.254.169.254`), plus the IPv6 equivalents `::1/128`, `fc00::/7`, and `fe80::/10`. They're parsed once at startup into `reservedNetworks`, and `isReservedIP` does the containment test.

There's a second, weaker layer at configuration time: `ValidateURL` (`internal/webhook/validate.go`, lines 62–83) requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument`. It runs when users register or update webhooks in `server/router/api/v1/user_service_webhooks.go` (lines 74, 161, 182). This is best treated as early user feedback, not the security boundary, since it's subject to the TOCTOU gap the dialer guard closes.

**One caveat worth flagging.** Both layers are globally disabled by the `AllowPrivateIPs` flag — `isReservedIP` returns `false` immediately when it's set (`internal/webhook/validate.go`, lines 41–46). It's wired to the `allow-private-webhooks` CLI/config option in `cmd/memos/main.go` line 49, intended for self-hosted deployments targeting LAN services. Turning it on removes the SSRF protection entirely rather than narrowing it to specific allowed ranges.
