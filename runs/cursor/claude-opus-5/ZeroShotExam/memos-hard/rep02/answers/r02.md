**Premise correction: this repository (Memos) has no per-user API rate-limiting middleware at all.** There is nothing registered anywhere that counts requests per user, per token, or per IP, and therefore no request limits to report.

Here is what actually sits in the request path, in case one of these is what you had in mind:

The Echo middleware stack is registered in `server/server.go` and contains only panic recovery and CORS:

```50:53:/bench/repo/server/server.go
	echoServer := echo.New()
	echoServer.Use(middleware.Recover())
	echoServer.Use(newCORSMiddleware(profile))
	s.echoServer = echoServer
```

The Connect RPC interceptor chain is registered in `server/router/api/v1/v1.go`, and it is metadata forwarding, logging, panic recovery, and authentication — no limiter:

```133:138:/bench/repo/server/router/api/v1/v1.go
	connectInterceptors := connect.WithInterceptors(
		NewMetadataInterceptor(), // Convert HTTP headers to gRPC metadata first
		NewLoggingInterceptor(logStacktraces),
		NewRecoveryInterceptor(logStacktraces),
		NewAuthInterceptor(authorizer),
	)
```

The gRPC-Gateway path likewise gets only `gatewayAuthMiddleware` (`server/router/api/v1/v1.go`, around lines 69–98).

The closest thing to a "limit" that rejects requests is a **global concurrency semaphore**, not a rate limit. `APIV1Service` holds `imageProcessingSemaphore` sized at 2 and `thumbnailSemaphore` sized at 3 (`server/router/api/v1/v1.go` lines 59–60), and `server/router/fileserver/fileserver.go` has its own thumbnail semaphore with `maxConcurrentThumbnails = 3`. When EXIF stripping can't get a slot, `CreateAttachment` returns `ResourceExhausted` with the message "too many image processing requests" (`server/router/api/v1/attachment_service.go` line 160). That cap is process-wide and applies to in-flight work, so a single user can hold both slots and any user can be rejected regardless of their own request rate.

Separately, there are size caps rather than rate caps: `maxAPIRequestBytes = 256 << 20` (256 MiB) applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` in `server/router/api/v1/v1.go`, and an upload limit from the instance storage setting falling back to `MaxUploadBufferSizeBytes = 32 << 20` in `server/router/api/v1/attachment_service.go`.

The only mentions of rate limiting in the codebase are aspirational documentation for email sending, in `internal/email/README.md` (section "5. Implement Rate Limiting") and `internal/email/doc.go`; neither is implemented.
