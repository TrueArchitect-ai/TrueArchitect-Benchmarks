**1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages)**

The data layer is the `store` package (`/bench/repo/store`), whose persistent entity types are defined one-per-file: `User` (`store/user.go:29`), `Memo` (`store/memo.go:35`), `Attachment` (`store/attachment.go:16`), `Inbox`, `MemoRelation`, `MemoShare`, `Reaction`, `UserSetting`, `UserIdentity`, `IdentityProvider`, and `InstanceSetting`.

Counting distinct Go packages outside `store/` (and its sub-packages like `store/db`, `store/cache`, `store/migration`) that reference each type:

| Type | External packages | External references |
|---|---|---|
| `User` | 7 | ~99 |
| `Memo` | 6 | ~73 |
| `Attachment` | 4 | ~43 |

`store.User` is referenced from `server/router/api/v1`, `server/router/api/v1/test`, `server/router/rss`, `server/router/fileserver`, `server/auth`, `server/router/frontend`, and `server/notification`.

`store.Memo` is referenced from `server/router/api/v1`, `server/router/api/v1/test`, `server/router/rss`, `server/runner/memopayload`, `server/router/frontend`, and `server/notification` — the same set minus `server/auth` and `server/router/fileserver`, plus `server/runner/memopayload`.

Two notes on the counts: `User` leads partly because it is the authentication subject, so `server/auth` and the file server both need it, whereas `Memo` has the higher per-package usage density in the API layer. If you exclude the test helper package `server/router/api/v1/test`, the counts drop to 6 and 5 respectively, but the ranking is unchanged. `Attachment` is a clear third in both packages and raw references.
