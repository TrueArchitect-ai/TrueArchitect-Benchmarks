h03.

`github.com/usememos/memos/internal/idp`; `github.com/usememos/memos/internal/idp/oauth2`

The abstraction lives in `internal/idp/idp.go`, which is a minimal package defining just the `IdentityProviderUserInfo` struct (identifier, display name, email, avatar URL) that any provider must produce. The only concrete implementation shipped is OAuth2, in `internal/idp/oauth2/oauth2.go`, whose `IdentityProvider` type wraps a `storepb.OAuth2Config` and provides `ExchangeToken` (with optional PKCE `code_verifier`) and `UserInfo`, mapping arbitrary claims onto the shared struct via the configured field mapping.

That OAuth2 is the sole protocol is confirmed by two places: `proto/store/idp.proto` declares the `IdentityProvider.Type` enum with only `TYPE_UNSPECIFIED` and `OAUTH2`, and `IdentityProviderConfig` is a `oneof` containing only `oauth2_config`. The single consumer is `server/router/api/v1/auth_service_sso.go`, which imports both packages and calls `oauth2.NewIdentityProvider(...)` to handle SSO login and account linking. No OIDC-specific or SAML implementation exists anywhere in the Go tree.
