`internal/idp`; `internal/idp/oauth2`

The abstraction lives in `internal/idp/idp.go`, which is deliberately minimal — it defines only the shared `IdentityProviderUserInfo` struct (identifier, display name, email, avatar URL) that every provider must produce:

```3:8:internal/idp/idp.go
type IdentityProviderUserInfo struct {
	Identifier  string
	DisplayName string
	Email       string
	AvatarURL   string
}
```

The single concrete implementation is `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`), whose `IdentityProvider` type wraps a `storepb.OAuth2Config` and provides `NewIdentityProvider`, `ExchangeToken` (with optional PKCE `code_verifier`), and `UserInfo`, which maps arbitrary claims onto the shared struct via the configured `FieldMapping`.

Two things confirm OAuth2 is the only protocol that ships: the sole consumer, `server/router/api/v1/auth_service_sso.go`, imports just `internal/idp` and `internal/idp/oauth2`, and the provider config messages in `proto/store/idp.proto` and `proto/api/v1/idp_service.proto` contain a one-variant oneof holding only `OAuth2Config`. There is no SAML, LDAP, or dedicated OIDC implementation in the repository.
