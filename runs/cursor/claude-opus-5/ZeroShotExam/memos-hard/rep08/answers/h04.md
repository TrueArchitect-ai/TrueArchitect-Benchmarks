**No** — outside the `NewDBDriver` factory, the MySQL store driver is never constructed anywhere in production or test code (the one exception is a zero-value struct literal in a same-package unit test, which never opens a connection).

Evidence:

1. **Only one file imports the package.** Grepping for the import path `github.com/usememos/memos/store/db/mysql` across all `.go` files returns exactly one hit, the factory itself:

```7:11:store/db/db.go
	"github.com/usememos/memos/internal/profile"
	"github.com/usememos/memos/store"
	"github.com/usememos/memos/store/db/mysql"
	"github.com/usememos/memos/store/db/postgres"
	"github.com/usememos/memos/store/db/sqlite"
```

Since nothing else imports it, no other package can call `mysql.NewDB` or name the `mysql.DB` type at all.

2. **`mysql.NewDB` has exactly one call site**, inside the switch in the factory:

```19:26:store/db/db.go
	case "mysql":
		driver, err = mysql.NewDB(profile)
	case "postgres":
		driver, err = postgres.NewDB(profile)
	default:
		return nil, errors.New("unknown db driver")
	}
```

3. **Every consumer routes through the factory.** All callers of `db.NewDBDriver` are `cmd/memos/main.go:57`, `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70`. The test harness in `store/test/store.go` picks MySQL only by setting `profile.Driver` (see `getTestingProfileForDriver` around line 88), then hands the profile to `NewDBDriver` — it does not construct the driver itself. Note that the two direct-`NewDB` calls that do exist in tests, `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416`, are `sqlite.NewDB`, not MySQL.

4. **Direct `DB{}` struct literals** appear in only two places, both inside `package mysql`: `store/db/mysql/mysql.go:29` (`driver := DB{profile: profile}`, which is the body of `NewDB` itself) and `store/db/mysql/auth_config_test.go:12`. The latter is `db := &DB{}`, a zero-value receiver used purely to exercise `IsRetryableAuthenticationMutationError`, a function that classifies MySQL error codes and touches no connection fields. That is a same-package test helper rather than a real driver instantiation, so it doesn't bypass the factory in any meaningful sense.

One thing worth distinguishing: `store/test/containers.go` does call `sql.Open("mysql", dsn)` (line 145) and imports `github.com/go-sql-driver/mysql` (line 16), but that is the low-level SQL driver used to wait on and provision the TestContainers MySQL instance, not the Memos `store.Driver` implementation in `store/db/mysql/`.
