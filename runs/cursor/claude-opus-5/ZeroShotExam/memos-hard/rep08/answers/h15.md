h15.

Memo visibility is enforced independently in several places rather than through one central gate. The core rule (public = anyone, protected = any authenticated user, private = creator only, with admin/super-user exceptions in some surfaces) is re-implemented at each site below.

**Primary enforcement sites (per-memo access checks)**

`checkMemoReadAccess` — gRPC/Connect memo read path (GetMemo, parent-memo check, ListMemoComments) — `server/router/api/v1/memo_service.go` (lines 39–68, called at 356/367 and from `server/router/api/v1/memo_service_comments.go:148`)

`checkAttachmentPermission` — public HTTP file server serving attachment blobs, including the anonymous-access and `share_token` fallbacks — `server/router/fileserver/fileserver.go` (lines 650–704)

`checkAttachmentAccess` — attachment API (v1 Attachment service), derives access from the linked memo's visibility — `server/router/api/v1/attachment_service.go` (lines 419–455)

`ListMemoAttachments` inline check — `server/router/api/v1/memo_attachment_service.go` (lines 213–225)

Reaction service checks — `UpsertMemoReaction`/reaction listing re-check memo visibility before allowing reactions — `server/router/api/v1/reaction_service.go` (lines 29–41, 82–85)

`CreateMemoComment` parent check — private parent memo blocks commenting by non-creators — `server/router/api/v1/memo_service_comments.go` (line 41)

**List/query-level enforcement (visibility injected into the store query)**

`ListMemos` viewer filter — `VisibilityList` for anonymous, CEL `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` for authenticated — `server/router/api/v1/memo_service.go` (lines 218–227)

`ListMemoComments` comment filter — `server/router/api/v1/memo_service_comments.go` (lines 156–161)

Memo relation filters — `server/router/api/v1/memo_relation_service.go` (lines 107–112) and `batchConvertMemoRelations` in `server/router/api/v1/memo_service_converter.go` (lines 182–187)

User stats (`GetUserStats` / `ListAllUserStats`) — `server/router/api/v1/user_service_stats.go` (lines 84–90, 218–220)

RSS feeds — restricted to `store.Public` only — `server/router/rss/rss.go` (lines 90, 141)

Sitemap / frontend SSR — public-only memo listing — `server/router/frontend/frontend.go` (line 150)

SQL `WHERE` construction for `VisibilityList` — `store/db/sqlite/memo.go` (≈line 98), `store/db/postgres/memo.go`, `store/db/mysql/memo.go`

**Notification/delivery-side enforcement**

SSE broadcast filtering `SSEClient.canReceive` — drops private-memo events for non-creators/non-admins, denies unknown visibility — `server/router/api/v1/sse_hub.go` (lines 134–144), with event visibility populated in `server/router/api/v1/sse_event_helpers.go`

`canViewerAccessMemo` for in-app notification payloads — `server/router/api/v1/user_service_notifications.go` (lines 302–316)

`canViewerAccessMemo` for email notification content (separate duplicate implementation) — `server/notification/email.go` (lines 306–320)

Mention notification access gate `canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go` (lines 56–89)

**Deliberate bypass worth noting**

`GetMemoByShare` intentionally skips visibility entirely — a valid, unexpired share token grants read access to private/protected memos; only archived/missing memos are rejected — `server/router/api/v1/memo_share_service.go` (lines 153–192). The file server honors the same token at `server/router/fileserver/fileserver.go` (lines 684–689).
