The premise is incorrect: there is no nightly database-cleanup job scheduled anywhere in this repository. The cron scheduler in `internal/scheduler` is a self-contained library package — nothing in `cmd/`, `server/`, or `store/` imports it. The only files importing `github.com/usememos/memos/internal/scheduler` are its own tests, `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`, so no jobs are registered in the running application at all.

What likely inspired the question is illustrative sample code that never executes in production:

- `internal/scheduler/example_test.go` registers a job named `cleanup` with schedule `"0 2 * * *"` (2 AM daily) whose handler just prints "Cleaning up old data..." — it touches no database.
- `internal/scheduler/doc.go` uses the same `"0 2 * * *"` expression in a package-doc snippet named `daily-cleanup`.
- `internal/scheduler/README.md` shows a `daily-cleanup` example and a `stale-session-cleanup` example.
- `internal/scheduler/parser_test.go` uses `"0 2 * * *"` as a parser test case.

The actual recurring background work in the codebase is interval-based, not cron-scheduled:

- `store/cache/cache.go` runs an in-memory cache janitor every 5 minutes (`CleanupInterval`, also set in `store/store.go`), which expires cache entries rather than cleaning the database.
- `server/runner/s3presign/runner.go` re-signs S3 URLs on a 12-hour ticker (`runnerInterval`).

The only real cron expression that runs is in CI: `.github/workflows/stale.yml` uses `"0 */8 * * *"` to mark stale issues every 8 hours.
