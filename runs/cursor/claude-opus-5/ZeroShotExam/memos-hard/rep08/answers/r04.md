**Premise correction:** Neither. This repository (memos) has no message broker at all — there is no NATS, RabbitMQ, AMQP, Kafka, or Redis dependency anywhere in `go.mod`/`go.sum`, and no broker client code in the tree. There is also no separate "worker" process; `cmd/memos/main.go` is the only binary.

**Actual mechanism:** Webhook delivery is done in-process using a buffered Go channel and a fixed pool of goroutines, all inside `internal/webhook/webhook.go`:

- The "queue" is a plain Go channel with a capacity of 128, declared as a package-level variable:

```39:40:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
)
```

- The "workers" are four goroutines started from the package `init()` function, each reading payloads off that channel and calling `Post` to make the HTTP request:

```42:55:internal/webhook/webhook.go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously", ...)
				}
			}
		}()
	}
}
```

- Enqueueing happens in `PostAsync` (lines 184–196), which uses a `select` with a `default` branch, so the delivery is **lossy under load**: if the 128-slot channel is full, the payload is dropped with a warning log rather than blocked or retried. There is no persistence, no retry, and no dead-letter behavior — a process restart loses anything still queued.

- Producers are the memo API handlers in `server/router/api/v1/memo_service_webhooks.go`, which look up the user's webhooks via `s.Store.GetUserWebhooks` and call `webhook.PostAsync(payload)` (lines 43 and 71) for activity types like `memos.memo.created`, `memos.memo.updated`, `memos.memo.deleted`, and `memos.memo.comment.created`.

The actual HTTP delivery in `Post` (lines 120–180) signs the request with Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`) when a signing secret is configured, and uses a shared `http.Client` whose `DialContext` rejects reserved/private IPs to guard against SSRF.

The only place the word "queue" maps to a broker-like concept in the config is nothing — webhook URLs and signing secrets are stored as user settings (`proto/store/user_setting.proto`, `WebhooksUserSetting`), managed through `server/router/api/v1/user_service_webhooks.go`.
