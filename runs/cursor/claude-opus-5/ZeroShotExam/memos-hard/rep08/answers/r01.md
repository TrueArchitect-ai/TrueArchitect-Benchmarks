**Premise correction:** There is no Redis anywhere in this repository — no Redis connection, client library, config, or environment variable. A case-insensitive search for "redis" across the whole tree (including `go.mod`/`go.sum`, Docker files, and `docs/`) returns zero matches. The cache layer is entirely in-process and in-memory, so there is nothing to "connect" to.

**Actual mechanism**

The cache is a hand-rolled, thread-safe in-memory cache in `store/cache/cache.go`. It stores entries in a `sync.Map` with an `atomic.Int64` item counter, and each entry carries an absolute `expiration` timestamp plus a rough size estimate:

```66:73:/bench/repo/store/cache/cache.go
// Cache is a thread-safe in-memory cache with TTL and memory management.
type Cache struct {
	itemCount  atomic.Int64 // Use atomic operations to track item count
	data       sync.Map
	config     Config
	stopChan   chan struct{}
	closedChan chan struct{}
}
```

Configuration happens in the store constructor, `store.New` in `store/store.go`, which builds one `cache.Config` and uses it for all three caches — instance settings, users, and user settings:

```39:53:/bench/repo/store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

**TTL for user entries: 10 minutes.** All writes to `userCache` in `store/user.go` (from `CreateUser`, `CreateUserIfNoUsers`, `UpdateUser`, `ListUsers`, and `GetUser`) call plain `Set`, which delegates to `SetWithTTL` using the configured `DefaultTTL`:

```92:95:/bench/repo/store/cache/cache.go
// Set adds a value to the cache with the default TTL.
func (c *Cache) Set(ctx context.Context, key string, value any) {
	c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)
}
```

No caller anywhere in the non-test code invokes `SetWithTTL` with a custom duration, so 10 minutes is the effective TTL for every user entry. Cache keys are just the stringified user ID (`userCacheKey` in `store/user.go`), and only lookups by ID hit the cache — `GetUser` consults `userCache` solely when `find.ID != nil`.

Two details worth noting about expiry. Beyond the TTL, entries are evicted eagerly on read (`Get` deletes and misses if `time.Now()` is past the expiration), by a background sweep every 5 minutes (`cleanupLoop`/`cleanup`), and by a capacity trim that drops roughly 20% of `MaxItems` once the 1000-item limit is exceeded (`cleanupOldest`). Deletions are also explicit: `deleteUserCache` in `store/user_delete.go` removes the user's entry and its associated user-setting entries.

Separately, `store/cache.go` only holds the `getUserSettingCacheKey` helper, and there is one unrelated cache at the API layer — `instanceStatsCache` with a 60-second TTL in `server/router/api/v1/instance_stats.go` — which caches instance statistics, not user entries.
