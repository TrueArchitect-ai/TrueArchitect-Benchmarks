**Premise correction:** There is no GraphQL schema in this repository. A case-insensitive search across the entire tree (excluding `.git`) for `graphql`, `apollo`, `typeDefs`, `gqlgen`, and `graphene` returns zero matches, there are no `.graphql`/`.gql`/`.graphqls` files, and neither `go.mod` nor the frontend's `web/package.json` pulls in a GraphQL library. This is Memos, a self-hosted markdown note-taking server written in Go, and its public API is defined in **Protocol Buffers**, then served as REST JSON and Connect RPC.

**The actual API surface**

The single source of truth is the proto directory `proto/api/v1/`, which declares eight services across eight `.proto` files: `ai_service.proto`, `attachment_service.proto`, `auth_service.proto`, `idp_service.proto`, `instance_service.proto`, `memo_service.proto`, `shortcut_service.proto`, and `user_service.proto` (plus `common.proto` for shared types). Each RPC carries a `google.api.http` annotation that defines its REST path and method, so the HTTP surface is generated from the same declarations rather than written by hand:

```17:32:proto/api/v1/memo_service.proto
service MemoService {
  // CreateMemo creates a memo. The request body is a Memo; set its content
  // (Markdown) and visibility (PRIVATE | PROTECTED | PUBLIC, default PRIVATE).
  // The memo is owned by the authenticated user; requires authentication.
  rpc CreateMemo(CreateMemoRequest) returns (Memo) {
    option (google.api.http) = {
      post: "/api/v1/memos"
      body: "memo"
    };
    option (google.api.method_signature) = "memo";
  }
  // ListMemos lists memos with pagination and filter.
  rpc ListMemos(ListMemosRequest) returns (ListMemosResponse) {
    option (google.api.http) = {get: "/api/v1/memos"};
    option (google.api.method_signature) = "";
  }
```

Code generation is driven by Buf, configured in `proto/buf.gen.yaml` and documented in `proto/README.md` (run `buf generate`). The generated output lands in `proto/gen/`, which includes `proto/gen/openapi.yaml` — an OpenAPI 3.0.3 document covering 45 REST paths. That file is the closest analogue to the "schema" you were asking about, and it is generated, not authored.

The two runtime surfaces are wired up in `server/router/api/v1/v1.go`. The REST layer registers all eight services onto a gRPC-Gateway mux and mounts it at `/api/v1/*` (lines 95–129), while the Connect RPC layer for the browser client is mounted at `/memos.api.v1.*` (lines 139–144), with the handler list in `server/router/api/v1/connect_handler.go`. Service implementations live alongside as `server/router/api/v1/*_service.go`.

Beyond that core, `server/server.go` registers several auxiliary HTTP endpoints: server-sent events at `/api/v1/sse` (`server/router/api/v1/sse_handler.go`), binary attachment and avatar serving under `/file/*` (`server/router/fileserver/fileserver.go`), RSS feeds at `/explore/rss.xml` and `/u/:username/rss.xml` (`server/router/rss/rss.go`), and an MCP endpoint at `/mcp` for AI agents (`server/router/mcp/service.go`, with its tool catalog in `server/router/mcp/catalog.go`). A separate `proto/store/` tree exists but describes internal persistence types and is not exposed over HTTP.

If you're integrating against this project, start from `proto/api/v1/` for the contract or `proto/gen/openapi.yaml` for the REST view.
