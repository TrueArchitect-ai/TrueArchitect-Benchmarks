**1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages)**

The data layer is the `store/` package, where each persistent entity is a Go struct backed by a table in `store/migration/sqlite/LATEST.sql` (`user`, `memo`, `attachment`, `memo_relation`, `memo_share`, `inbox`, `reaction`, `idp`, `user_setting`, `user_identity`, `system_setting`).

- `server/auth` (`server/auth/authenticator.go:61`, `server/auth/context.go:55`)
- `server/router/rss` (`server/router/rss/rss.go:162`)
- `server/router/fileserver` (`server/router/fileserver/fileserver.go:708`)
- `server/notification` (`server/notification/email.go:270`)

`store.Memo` (`store/memo.go:35`) is referenced from 6 packages outside `store/`: the same set minus `server/auth` and `server/router/fileserver`, plus `server/runner/memopayload` (`server/runner/memopayload/runner.go:74`).

Third place is `store.Attachment` (`store/attachment.go:16`) at about 4 packages, then `store.Inbox`, `store.MemoRelation`, and `store.MemoShare` at roughly 3 each. The ranking holds whether or not `_test.go` files are counted (excluding tests gives 6 packages for `User` and 4 for `Memo`), and `User` also leads on raw reference count (~99 vs ~73).

Two caveats worth noting. `store.UserSetting`, `store.InstanceSetting`, and `store.IdentityProvider` have zero external package references, because the server layer works with the proto counterparts (`storepb.UserSetting`, etc.) rather than the store structs. Relatedly, the only apparent external hits for those three come from `proto/gen/store/*.pb.go`, which are false positives: they are fully-qualified protobuf names like `memos.store.UserSetting` embedded in generated descriptor strings, not Go references to the data-layer types.
