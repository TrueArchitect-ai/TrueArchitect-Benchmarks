**s3presign runner — a 12-hour `time.Ticker`, plus one immediate synchronous pass at startup**

That is the only long-running background worker the server starts:

```161:171:server/server.go
	// Create and start S3 presign runner
	s3presignRunner := s3presign.NewRunner(s.Store)
	s3presignRunner.RunOnce(ctx)

	// Start continuous S3 presign runner
	s.backgroundRunnerWG.Add(1)
	go func() {
		defer s.backgroundRunnerWG.Done()
		s3presignRunner.Run(s3Context)
		slog.Info("s3presign runner stopped")
	}()
```

`Run` loops on `time.NewTicker(runnerInterval)` where `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27-30`), refreshing expiring S3 presigned URLs via `CheckAndPresign`. It gets its own cancellable context so `Shutdown` can stop it and wait on the WaitGroup.

The other package under `server/runner` is not a scheduled worker: `memopayload` only exposes `RunOnce` and `RebuildMemoPayload`, and it's invoked inline from the memo handlers on create and update (`server/router/api/v1/memo_service.go`, lines 108 and 447), not from a timer.

**Unused infrastructure:** `internal/scheduler` — a full cron scheduler (5/6-field cron parsing, timezone handling, middleware, graceful shutdown; see `internal/scheduler/README.md`, `scheduler.go`, `parser.go`, `job.go`, `middleware.go`) is present but never imported outside its own package and tests, so nothing in the server uses it. The 12-hour cadence above is a hand-rolled ticker rather than a scheduler job.

For completeness, two other goroutines exist but aren't workers: `recordPATUsage` fires a one-shot goroutine per authenticated request to update a token's last-used timestamp (`server/auth/authenticator.go:180`), and `cmd/memos/main.go:99` is the signal handler for shutdown.
