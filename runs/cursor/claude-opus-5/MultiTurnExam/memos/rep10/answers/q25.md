**Engine: Google CEL (Common Expression Language) via `cel-go`, wrapped by the in-house `filter` package at `repo/internal/filter/` (entry point `engine.go`)**

**Mechanism:** the CEL expression is compiled once into a dialect-agnostic condition tree, which a per-dialect renderer then turns into a parameterized SQL `WHERE` fragment plus bound args that each driver appends to its query.

The engine builds a CEL environment from a field schema and compiles filter strings into an intermediate representation rather than evaluating them:

```13:21:repo/internal/filter/engine.go
// Engine parses CEL filters into a dialect-agnostic condition tree.
type Engine struct {
	schema Schema
	env    *cel.Env
	// nowFunc resolves the value of the `now` variable. It is frozen once per
	// Compile so a single filter sees a single instant, and is overridable in
	// tests for deterministic folding.
	nowFunc func() time.Time
}
```

The MySQL and PostgreSQL drivers do the same with `filter.DialectMySQL` and `filter.DialectPostgres`. Attachments have a parallel schema and engine (`DefaultAttachmentEngine`, line 119). Since values always come back as bound arguments rather than interpolated SQL, user-supplied filters can't inject SQL.
