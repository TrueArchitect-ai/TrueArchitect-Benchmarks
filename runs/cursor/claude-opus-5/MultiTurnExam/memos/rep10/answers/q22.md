```14:17:repo/server/router/api/v1/memo_service_webhooks.go
// DispatchMemoCreatedWebhook dispatches a webhook when a memo is created.
func (s *APIV1Service) DispatchMemoCreatedWebhook(ctx context.Context, memo *v1pb.Memo) error {
	return s.dispatchMemoRelatedWebhook(ctx, memo, "memos.memo.created")
}
```

`dispatchMemoRelatedWebhook` resolves the memo's creator via `ResolveUserByName`, loads that user's hooks with `s.Store.GetUserWebhooks`, and for each one builds a payload carrying the memo, the activity type `memos.memo.created`, the hook URL, and the hook's signing secret — then hands it to `webhook.PostAsync`.

Delivery lives in `repo/internal/webhook/webhook.go`. `PostAsync` (line 184) is non-blocking: it enqueues onto a bounded `asyncPostQueue` and logs a warning if the queue is full, so webhook delivery never stalls or fails the memo creation. The actual HTTP POST happens in `Post` (line 120).

Signing is HMAC-SHA256 over `"<msgID>.<timestamp>."` concatenated with the JSON body, base64-encoded and sent as three Standard Webhooks headers:


Signing is skipped entirely when the hook has no secret. Keys follow the `whsec_<base64>` convention — `resolveSigningKey` (line 97) base64-decodes that prefix to raw bytes and uses any other secret verbatim, while `GenerateSigningSecret` (line 111) mints 32 random bytes in that form.
