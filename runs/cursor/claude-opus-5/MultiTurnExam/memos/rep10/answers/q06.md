**`memo_relation`**

The table is defined in all three dialect schemas with the same three-column shape — the source memo, the target memo, and a relation type:

```46:52:repo/store/migration/sqlite/LATEST.sql
CREATE TABLE memo_relation (
  memo_id INTEGER NOT NULL,
  related_memo_id INTEGER NOT NULL,
  type TEXT NOT NULL,
  UNIQUE(memo_id, related_memo_id, type)
);
```

The MySQL and PostgreSQL equivalents are at `repo/store/migration/mysql/LATEST.sql:46` and `repo/store/migration/postgres/LATEST.sql:46`. The `type` column plus the composite `UNIQUE(memo_id, related_memo_id, type)` constraint means a single memo pair can be linked more than once under different relation types (for example a reference versus a comment link).

On the Go side, access to this table goes through `repo/store/memo_relation.go`, with the per-dialect SQL in `repo/store/db/postgres/memo_relation.go`, `repo/store/db/mysql/memo_relation.go`, and `repo/store/db/sqlite/memo_relation.go`.
