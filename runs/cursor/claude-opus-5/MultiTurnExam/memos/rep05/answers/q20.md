**Mechanism:** Server-Sent Events (SSE) over HTTP — `server/router/api/v1/sse_handler.go` sets `Content-Type: text/event-stream` and `RegisterSSERoutes` mounts the endpoint alongside the rest of `/api/v1` (wired in from `RegisterGateway` in `server/router/api/v1/v1.go`, line 125).

**Hub:** `server/router/api/v1/sse_hub.go` — defines `SSEHub` with `NewSSEHub`, `Subscribe(userID, role)`, `Unsubscribe`, `Broadcast(event)`, and `Close`, plus the `SSEEvent` payload and `SSEClient.canReceive`, which filters delivery per client using the event's `Visibility` and `CreatorID` (both excluded from the JSON sent to browsers). Event helpers live in `server/router/api/v1/sse_event_helpers.go`.

**Handlers that broadcast:**

`APIV1Service.CreateMemo` — `server/router/api/v1/memo_service.go` line 163, emits `memo.created`
`APIV1Service.DeleteMemo` — `server/router/api/v1/memo_service.go` line 585, emits `memo.deleted`
`APIV1Service.CreateMemoComment` — `server/router/api/v1/memo_service_comments.go` line 126, emits `memo.comment.created`
`APIV1Service.UpsertMemoReaction` — `server/router/api/v1/reaction_service.go` line 106, emits `reaction.upserted`
`APIV1Service.DeleteMemoReaction` — `server/router/api/v1/reaction_service.go` line 161, emits `reaction.deleted`

The `memo.updated` event is broadcast indirectly: `dispatchMemoUpdatedSideEffects` in `server/router/api/v1/memo_update_helpers.go` (line 71) does the actual `Broadcast` call, and three handlers route through it — `APIV1Service.UpdateMemo` (`memo_service.go` line 513), `SetMemoAttachments` (`memo_attachment_service.go` line 48), and `SetMemoRelations` (`memo_relation_service.go` line 48).

One behavioral note: `CreateMemo` checks `isSSESuppressed(ctx)` before broadcasting, which is how `CreateMemoComment` swaps the generic `memo.created` event for `memo.comment.created` on the parent (it calls `CreateMemo` under `withSuppressSSE`).
