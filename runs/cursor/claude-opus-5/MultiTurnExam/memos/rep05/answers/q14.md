**RPCs (5):** `ListShortcuts`, `GetShortcut`, `CreateShortcut`, `UpdateShortcut`, `DeleteShortcut`

**Implementing file:** `server/router/api/v1/shortcut_service.go`

All five are declared in `proto/api/v1/shortcut_service.proto` and implemented as methods on `APIV1Service` in that one file:

| RPC | REST mapping | Implementation line |
|---|---|---|
| `ListShortcuts` | `GET /api/v1/{parent=users/*}/shortcuts` | 49 |
| `GetShortcut` | `GET /api/v1/{name=users/*/shortcuts/*}` | 95 |
| `CreateShortcut` | `POST /api/v1/{parent=users/*}/shortcuts` | 135 |
| `UpdateShortcut` | `PATCH /api/v1/{shortcut.name=users/*/shortcuts/*}` | 211 |
| `DeleteShortcut` | `DELETE /api/v1/{name=users/*/shortcuts/*}` | 284 |

Note that shortcuts are user-scoped resources, so every path is nested under `users/*`.

As with the other services, `server/router/api/v1/connect_services.go` (lines 528–566) contains matching `ConnectServiceHandler` methods, but those are transport wrappers that unwrap the Connect request and delegate to the `APIV1Service` methods above rather than a second implementation.
