**`APIV1Service.SignIn` — `server/router/api/v1/auth_service.go`** (line 51)

That's where the actual authentication logic lives. It handles two credential types: password-based sign-in (looks up the user by username, then `bcrypt.CompareHashAndPassword`, and rejects non-admin users when the instance setting `DisallowPasswordAuth` is on) and SSO/OAuth2 sign-in (via `resolveSSOIdentity` and `resolveSSOUser`). It rejects archived users, then calls `s.doSignIn` to mint the access token and set the refresh-token cookie, returning the converted user plus token and expiry.

Worth knowing there is also a thin transport wrapper, `ConnectServiceHandler.SignIn` in `server/router/api/v1/connect_services.go` (line 78), which unwraps the Connect request and delegates straight to `APIV1Service.SignIn` inside `connectWithHeaderCarrier` so the service can set response headers protocol-agnostically. It contains no business logic of its own.
