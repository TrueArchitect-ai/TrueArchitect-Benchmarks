**`web/src/connect.ts`**

All eight service clients are created there with `createClient(Service, transport)` and exported for the rest of the app (lines 192–203): `instanceServiceClient`, `authServiceClient`, `userServiceClient`, `memoServiceClient`, `attachmentServiceClient`, `aiServiceClient`, `shortcutServiceClient`, and `identityProviderServiceClient`.

They share a single `createConnectTransport` pointed at `window.location.origin` using the binary format, with `credentials: "include"` so the refresh-token cookie is sent, and an auth interceptor that attaches the `Authorization: Bearer` header:

```184:194:/bench/repo/web/src/connect.ts
const transport = createConnectTransport({
  baseUrl: window.location.origin,
  useBinaryFormat: true,
  fetch: fetchWithCredentials,
  interceptors: [authInterceptor],
});

// Core service clients
export const instanceServiceClient = createClient(InstanceService, transport);
export const authServiceClient = createClient(AuthService, transport);
export const userServiceClient = createClient(UserService, transport);
```

One detail worth noting: the same file also creates a ninth, non-exported client, `refreshAuthClient` (line 72), on a separate interceptor-free transport. That exists so token refresh calls don't recurse back through `authInterceptor`.
