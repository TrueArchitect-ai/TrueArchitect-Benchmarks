**Engine: Google CEL (Common Expression Language) via `github.com/google/cel-go`, wrapped by the `filter` package at `internal/filter/` — chiefly `internal/filter/engine.go`, `internal/filter/parser.go`, and `internal/filter/render.go`**

**Mechanism in one sentence:** the CEL expression is compiled to an AST and lowered into a dialect-agnostic condition tree, which a renderer then walks with a `DialectName` (`sqlite`/`mysql`/`postgres`) to emit a parameterized SQL fragment plus args that each dialect driver appends to its `WHERE` clause.

The details, in order. `Engine.Compile` in `internal/filter/engine.go` builds a `cel.Env` from a schema, compiles the filter string, and converts the AST into a `Condition` tree — the doc comment describes it as parsing "CEL filters into a dialect-agnostic condition tree":


The dialect split happens in the renderer. `internal/filter/schema.go` defines the three `DialectName` constants, and `internal/filter/render.go` switches on them at roughly 30 sites to handle per-backend differences — JSON extraction, string-length functions (`stringLengthExpr` special-cases MySQL), and placeholder style (Postgres uses positional placeholders, hence the `PlaceholderOffset` bookkeeping).

The driver-facing entry point is `AppendConditions`:

```9:23:internal/filter/helpers.go
func AppendConditions(ctx context.Context, engine *Engine, filters []string, dialect DialectName, where *[]string, args *[]any) error {
	for _, filterStr := range filters {
		stmt, err := engine.CompileToStatement(ctx, filterStr, RenderOptions{
			Dialect:           dialect,
			PlaceholderOffset: len(*args),
		})
		...
		*where = append(*where, fmt.Sprintf("(%s)", stmt.SQL))
		*args = append(*args, stmt.Args...)
	}
	return nil
}
```

Each dialect's `ListMemos` calls it with its own constant — `store/db/sqlite/memo.go:61` passes `filter.DialectSQLite`, with the parallel calls in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`. Because values come back as bound `Args` rather than interpolated text, user-supplied filters can't inject SQL.

This is also the syntax behind saved shortcuts: `proto/api/v1/shortcut_service.proto` notes that a `Shortcut.filter` is a reusable CEL filter meant to be passed straight to the `ListMemos` `filter` argument.
