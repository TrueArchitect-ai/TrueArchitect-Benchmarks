That mux is then mounted on the Echo server for `/api/v1/*` and `/file/*` (line 128), which is what turns the proto `google.api.http` annotations into real REST routes such as `POST /api/v1/memos`. The generated translation code is `proto/gen/api/v1/memo_service.pb.gw.go`.

For Connect, `connect_handler.go` registers the handler on an `http.ServeMux`:

```40:40:server/router/api/v1/connect_handler.go
		wrap(apiv1connect.NewMemoServiceHandler(s, opts...)),
```

The `s` here is a `ConnectServiceHandler`, which embeds `*APIV1Service` and supplies the Connect-shaped method signatures in `connect_services.go` (for instance `ConnectServiceHandler.CreateMemo` at line 306, unwrapping `req.Msg` and delegating). The generated bindings live in `proto/gen/api/v1/apiv1connect` and `proto/gen/api/v1/memo_service.connect.go`.

Both protocols share one implementation — the comment at the top of `connect_handler.go` states this explicitly, calling out that the wrapper pattern keeps a single source of truth for business logic while supporting both. Worth noting that `RegisterMemoServiceHandlerServer` is the in-process gateway variant, so REST calls invoke the service directly rather than dialing a separate gRPC listener.
