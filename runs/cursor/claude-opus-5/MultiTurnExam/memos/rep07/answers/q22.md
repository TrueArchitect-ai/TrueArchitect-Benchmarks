The shared `dispatchMemoRelatedWebhook` resolves the memo's creator via `ResolveUserByName`, fetches that user's registered hooks with `s.Store.GetUserWebhooks(ctx, creatorID)`, and for each one builds a payload carrying the memo, the activity type, the target URL, and the hook's signing secret, then hands it off with `webhook.PostAsync(payload)` — so delivery is asynchronous and doesn't block the create response.

HTTP delivery lives in `internal/webhook` (`internal/webhook/webhook.go`, with SSRF/URL validation in `internal/webhook/validate.go`). `Post` marshals the payload as JSON and POSTs it through a `safeClient`, treating any non-2xx as an error and limiting the response read to 1 MiB.

Signing follows the Standard Webhooks convention. When the hook has a signing secret, the key is derived by `resolveSigningKey`, then:
