Two things to keep in mind while reviewing. First, `store/driver.go` is the interface that declares `CreateMemo`/`ListMemos`/`UpdateMemo` in terms of `*Memo`, so a signature-affecting change there forces all three dialect implementations to change in lockstep. Second, `memo_service_converter.go` is where the struct is translated to the protobuf `v1pb.Memo`, so any added or renamed field likely also implies a change in `proto/api/v1/memo_service.proto` and the SQL schema in `store/migration/*/LATEST.sql` plus a new migration — those are outside the Go reference list but are part of the same change.

Note also that `Payload *storepb.MemoPayload` is a separate protobuf-generated type; if the change is to the payload rather than the outer struct, `server/runner/memopayload/runner.go` (whose `RebuildMemoPayload` takes a `*store.Memo`) becomes the primary site.
