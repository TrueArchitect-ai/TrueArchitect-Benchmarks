**`web/src/hooks/useMemoQueries.ts`; `memoServiceClient`**

That module holds the full set of memo queries and mutations as TanStack Query hooks, all driving the same generated client:

| Hook | Client call |
|---|---|
| `useMemos` / `useInfiniteMemos` | `memoServiceClient.listMemos` |
| `useMemo` | `memoServiceClient.getMemo` |
| `useCreateMemo` | `memoServiceClient.createMemo` |
| `useUpdateMemo` | `memoServiceClient.updateMemo` |
| `useDeleteMemo` | `memoServiceClient.deleteMemo` |
| `useMemoComments` / `useInfiniteMemoComments` | `memoServiceClient.listMemoComments` |
| `useLinkMetadata` | `memoServiceClient.getLinkMetadata` |

The client itself is created in `web/src/connect.ts` as `createClient(MemoService, transport)`, and the request/response types plus schemas come from the generated bindings in `web/src/types/proto/api/v1/memo_service_pb.ts`.

The file also carries cache-maintenance helpers around these hooks — a `memoKeys` key factory and functions like `patchMemoInCollectionQueries` and `findMemoInListResponse` that patch memos in place across both plain list and infinite-query cache shapes, so mutations update existing pages instead of forcing a refetch.
