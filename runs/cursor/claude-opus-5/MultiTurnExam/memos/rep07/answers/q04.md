It handles two authentication paths: password credentials (looked up via `s.Store.GetUser`, verified with `bcrypt.CompareHashAndPassword`, and gated by the `DisallowPasswordAuth` instance setting) and SSO/OAuth2 credentials (resolved through `s.resolveSSOIdentity` and `s.resolveSSOUser`). On success it returns an access token and sets a refresh token cookie.

There is a second `SignIn` in `server/router/api/v1/connect_services.go` at line 78, but it's only a thin Connect-protocol wrapper — `ConnectServiceHandler.SignIn` unwraps the request message and delegates straight to `s.APIV1Service.SignIn`, using `connectWithHeaderCarrier` so the inner method can set response headers like the refresh cookie.
