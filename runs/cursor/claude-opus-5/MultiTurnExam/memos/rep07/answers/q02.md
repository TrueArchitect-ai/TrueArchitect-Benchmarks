**sqlite, mysql, postgres**

The migrations live under `store/migration/`, which contains exactly three dialect subdirectories — `sqlite/`, `mysql/`, and `postgres/` — each with per-version folders (e.g. `store/migration/mysql/0.30/00__user_tag_setting.sql`) plus a `LATEST.sql` schema file for fresh installs.

This matches the database drivers the project supports. `store/migrator.go` embeds the whole `migration` directory:

```44:48:store/migrator.go
//go:embed migration
var migrationFS embed.FS
```

And `store/db/db.go` dispatches on the configured driver with cases for `"sqlite"`, `"mysql"`, and `"postgres"`, with corresponding implementation packages in `store/db/sqlite`, `store/db/mysql`, and `store/db/postgres`.

One thing worth noting: the dialects don't all have the same migration history depth. SQLite has migrations going back to version 0.10, MySQL starts at 0.17, and Postgres starts at 0.19, reflecting when each backend was added.
