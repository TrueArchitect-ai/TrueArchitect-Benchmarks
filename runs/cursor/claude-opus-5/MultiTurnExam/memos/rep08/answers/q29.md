**Interceptor: `web/src/connect.ts` (`authInterceptor`, line 156); tokens: a short-lived JWT access token sent as `Authorization: Bearer` plus an httpOnly refresh-token cookie (and Personal Access Tokens for non-browser clients); backend validation: `server/auth`**

On the frontend, the interceptor is attached to the shared Connect transport and runs on every RPC. It fetches a token via `getRequestToken()`, sets the `Authorization` header, and on a `Code.Unauthenticated` response refreshes once and replays the request with an `X-Retry` marker, redirecting to login if the refresh fails:

Token state lives in `web/src/auth-state.ts`: the access token is cached in memory and `localStorage` with an expiry, refreshed preemptively when within 30 s of expiring (2 min on tab focus), and shared across tabs over a `BroadcastChannel` so only one tab calls the refresh endpoint. The refresh token itself is never touched by JS — it's a cookie, which is why the transport uses `credentials: "include"` and why `refreshToken` calls go through a separate interceptor-free transport to avoid recursion.

Server-side validation is `server/auth` (`authenticator.go`, `token.go`, `extract.go`, `context.go`). `Authenticator.resolveBearer` tries an Access Token V2 first (`AuthenticateByAccessTokenV2`, HMAC-verified with the instance secret) then falls back to a PAT (`AuthenticateByPAT`, looked up by hash via `Store.GetUserByPATHash`, with expiry and last-used tracking); `AuthenticateByRefreshToken` additionally checks the database so revoked sessions fail. It's wired into requests two ways — `NewAuthInterceptor(authorizer)` for Connect (`server/router/api/v1/connect_interceptors.go`, configured at `server/router/api/v1/v1.go:137`) and the gateway auth middleware in `v1.go`, with per-method public/private rules in `server/router/api/v1/acl_config.go` and `authz.go`.
