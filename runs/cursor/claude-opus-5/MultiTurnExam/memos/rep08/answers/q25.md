**Engine: Google CEL (Common Expression Language) via `github.com/google/cel-go`, wrapped by the in-house package `internal/filter` (`internal/filter/engine.go`)**

**Mechanism:** each dialect driver's `ListMemos` grabs the process-wide engine and calls `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect{SQLite,MySQL,Postgres}, &where, &args)`, which compiles the CEL string into a dialect-agnostic condition tree and then renders that tree into a parameterized SQL `WHERE` fragment plus args for the requested dialect, so one parser feeds three SQL emitters.

The package splits cleanly into stages: `engine.go` builds the `cel.Env` from the schema and compiles the filter to an AST; `parser.go` walks the CEL AST into `Condition` nodes (`ir.go`); `render.go` turns those nodes into SQL; `schema.go` declares the allowed identifiers and their types.

func (e *Engine) Compile(_ context.Context, filter string) (*Program, error) {
	if strings.TrimSpace(filter) == "" {
		return nil, errors.New("filter expression is empty")
	}

	ast, issues := e.env.Compile(filter)
	if issues != nil && issues.Err() != nil {
		return nil, errors.Wrap(issues.Err(), "failed to compile filter")
	}

Dialect divergence is confined to `render.go`, which switches on `DialectName` in a dozen places — JSON extraction, string-length functions (`CHAR_LENGTH` on MySQL vs `LENGTH` elsewhere), and placeholder style (`?` for SQLite/MySQL, `$N` for PostgreSQL, hence the `PlaceholderOffset` render option). Call sites are `store/db/sqlite/memo.go:61`, `store/db/mysql/memo.go:69`, and `store/db/postgres/memo.go:58`.

Two related details: `DefaultEngine()` memoizes the memo engine with `sync.Once`, and a separate `DefaultAttachmentEngine()` exists for attachment filters. The `now` variable is frozen at compile time so one filter observes a single instant. The same CEL grammar backs shortcuts — `APIV1Service.validateFilter` in `server/router/api/v1/shortcut_service.go` validates saved filter strings against it.
