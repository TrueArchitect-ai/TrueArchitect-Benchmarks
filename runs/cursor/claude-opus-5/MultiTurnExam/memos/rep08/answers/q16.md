The store layer deletes two kinds of records before the memo row:

- **`memo_relation` rows** — removed twice, once where the memo is the source (`MemoID`) and once where it's the target (`RelatedMemoID`), so both reference links and comment links pointing at it are cleared.
- **`attachment` rows** — every attachment linked to the memo is listed and deleted one at a time via `Store.DeleteAttachment` (which also handles blob/external-storage cleanup).

This cascade is in `Store.DeleteMemo`, which does the cleanup itself and only then delegates the row deletion to the driver:

```140:158:store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	if err != nil {
		return err
	}
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

The dialect method underneath is a plain single-table `DELETE FROM memo WHERE id = ?` (`store/db/sqlite/memo.go:237`), so all cascading is done in Go rather than SQL — with one exception: `memo_share` rows are cleaned up by a database-level `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`).

Two things happen a layer above, in `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`), not in the store: child memos linked by `MemoRelationComment` are deleted first in a loop at line 573 (each recursing through the same store cascade), and reactions are only *listed* for the webhook payload — I don't see reaction rows being deleted on this path, so those appear to be left behind.
