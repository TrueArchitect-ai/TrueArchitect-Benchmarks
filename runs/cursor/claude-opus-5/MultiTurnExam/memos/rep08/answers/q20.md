**Mechanism: Server-Sent Events (SSE)**, exposed as `GET /api/v1/sse` — registered by `RegisterSSERoutes` in `server/router/api/v1/sse_handler.go`, which authenticates via the `Authorization` bearer token and keeps connections alive with a 30-second heartbeat.

**Hub: `server/router/api/v1/sse_hub.go`** — defines `SSEHub` (a mutex-guarded set of `*SSEClient`, each with a buffered event channel plus the client's `userID` and `role` for delivery filtering), the `SSEEvent` payload, the six `SSEEventType` constants, and `Broadcast` at line 115.

**Handlers that broadcast:**

- `APIV1Service.CreateMemo` — `server/router/api/v1/memo_service.go:163`, emits `memo.created` (guarded by `isSSESuppressed(ctx)`)
- `APIV1Service.DeleteMemo` — `server/router/api/v1/memo_service.go:585`, emits `memo.deleted`
- `APIV1Service.CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:126`, emits `memo.comment.created`
- `APIV1Service.UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:106`, emits `reaction.upserted`
- `APIV1Service.DeleteMemoReaction` — `server/router/api/v1/reaction_service.go:161`, emits `reaction.deleted`
- `APIV1Service.UpdateMemo`, `SetMemoAttachments`, and `SetMemoRelations` — these emit `memo.updated` indirectly through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:71`), called from `memo_service.go:513`, `memo_attachment_service.go:48`, and `memo_relation_service.go:48`

One detail worth knowing: `CreateMemoComment` calls `CreateMemo` with SSE suppressed via `withSuppressSSE(ctx)` so a comment produces only the parent's `memo.comment.created` event rather than a duplicate `memo.created`. Helpers for building events, including `resolveSSECreatorID` and `buildMemoReactionSSEEvent`, live in `server/router/api/v1/sse_event_helpers.go`.
