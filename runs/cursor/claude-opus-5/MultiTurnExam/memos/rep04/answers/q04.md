**APIV1Service.SignIn — `server/router/api/v1/auth_service.go`**

Defined at line 51 of `/bench/repo/server/router/api/v1/auth_service.go`. It's the real implementation: it handles two credential types — password-based (bcrypt comparison against `user.PasswordHash`, plus a `DisallowPasswordAuth` policy check) and SSO/OAuth2 (via `resolveSSOIdentity` and `resolveSSOUser`) — then rejects archived users and issues a token.

One thing worth flagging since a search turns it up: `ConnectServiceHandler.SignIn` in `server/router/api/v1/connect_services.go` (line 78) is *not* a separate implementation. It's a thin Connect-protocol adapter that unwraps the request and delegates straight to `APIV1Service.SignIn`, wrapped in `connectWithHeaderCarrier` so the service can set response headers protocol-agnostically. Token minting itself lives in a third place, `APIV1Service.doSignIn` in `server/router/api/v1/auth_service_session.go`, which `SignIn` calls to produce the access token and expiry.
