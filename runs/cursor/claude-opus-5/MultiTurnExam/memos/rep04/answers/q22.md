HTTP delivery lives in **`internal/webhook`** (`webhook.go`, with URL checks in `validate.go`). `Post` marshals the payload to JSON and sends it via `safeClient`, capping the response read at 1 MiB and treating any non-2xx status as an error.

Signing follows **Standard Webhooks**: when a signing secret is present, `resolveSigningKey` strips the `whsec_` prefix and base64-decodes it to raw key bytes (failing loudly rather than signing with the wrong key), then an HMAC-SHA256 is computed over `msgID + "." + timestamp + "." + body`. The result is base64-encoded and sent as three headers — `webhook-id`, `webhook-timestamp`, and `webhook-signature` with the `v1,` version prefix. Including the ID and timestamp in the signed string is what lets receivers reject replays. Secrets are minted by `GenerateSigningSecret` from 32 random bytes; if a hook has no secret, the request is sent unsigned.
