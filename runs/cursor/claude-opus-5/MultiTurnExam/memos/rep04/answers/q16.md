Both directions of the relation cleanup matter because the `memo_relation` table from q06 stores a directed `memo_id` → `related_memo_id` pair, and a memo can appear on either side.

One layer up, `APIV1Service.DeleteMemo` in `server/router/api/v1/memo_service.go` first deletes the memo's **comments** — it finds relations of type `MemoRelationComment` pointing at this memo and calls `Store.DeleteMemo` on each child (lines 567–577), so each comment gets the same relation/attachment cleanup recursively. That happens in the API layer, not the store layer.

Note that reactions are *not* deleted. The handler lists them at line 545, but only to build the webhook payload passed to `DispatchMemoDeletedWebhook`.
