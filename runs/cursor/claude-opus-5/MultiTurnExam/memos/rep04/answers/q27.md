**Go `embed.FS` — the compiled assets are baked into the server binary at build time and served by Echo static middleware with SPA fallback; wired in `server/router/frontend/frontend.go`**

The embed directive and the backing variable are at lines 20–21:

```20:21:/bench/repo/server/router/frontend/frontend.go
//go:embed dist/*
var embeddedFiles embed.FS
```

`FrontendService.Serve` (line 41) derives an `fs.FS` rooted at `dist` and installs two middlewares: `middleware.StaticWithConfig` to serve files straight out of the embedded filesystem, and `spaFallbackMiddleware`, which catches 404s on non-asset paths and returns `index.html` instead so client-side routes resolve on a hard refresh.

Cache headers are set per request by `setFrontendCacheHeaders` using the three constants at lines 24–26: HTML is `no-cache, no-store, must-revalidate`, plain static assets get one hour, and content-hashed assets get one hour plus `immutable`. A `shouldSkipFrontendStatic` check keeps API routes out of the static handler.

Because the assets are compiled into the binary, production needs no separate web server or asset directory — but it does mean `server/router/frontend/dist/` must be populated by the frontend build before `go build` runs. In this checkout that directory holds only `index.html`, i.e. a placeholder rather than a real Vite build output. There's no Dockerfile at the repo root, so I couldn't confirm from here which build step copies the real `web/` build into `dist`.
