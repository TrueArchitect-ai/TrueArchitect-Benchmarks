Each is declared in the `store` package in a file named after its table: `User` at line 29 of `store/user.go`, `Attachment` at line 16 of `store/attachment.go`, and `Reaction` at line 7 of `store/reaction.go`. The naming and layout follow the same convention as `store.Memo` in `store/memo.go` (q13) — each file pairs the row struct with its `Find*`/`Update*`/`Delete*` query companions, and the corresponding `CREATE TABLE` statements live in `store/migration/{dialect}/LATEST.sql`.

Two details worth flagging. `Attachment` carries `Blob []byte` alongside a `StorageType` and `Reference`, so a row may hold file bytes inline in the database or just point at external storage depending on the configured backend. And `Reaction` is not scoped to memos specifically — it links via a generic `ContentID string` (commented "the id of the content that the reaction is for") rather than a `MemoID` foreign key, so reactions are reusable across content types.
