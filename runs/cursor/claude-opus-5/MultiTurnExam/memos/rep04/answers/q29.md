**Interceptor:** `web/src/connect.ts` (the `authInterceptor` at line 156, with token storage helpers in `web/src/auth-state.ts`)
**Token kinds:** short-lived access token (JWT, `Authorization: Bearer`), refresh token (HTTP-only cookie), and Personal Access Tokens (PAT, also Bearer — for programmatic clients, not issued by the browser flow)
**Backend package:** `server/auth/`

The interceptor is installed on the shared Connect transport (q07) and does two things. Before each call, `getRequestToken()` returns the current access token and *preflight-refreshes* it if `isTokenExpired(REQUEST_TOKEN_EXPIRY_BUFFER_MS)`. The comment at lines 136–139 explains why that matters: on public endpoints like `ListMemos`, an expired token would otherwise be silently treated as anonymous and return guest-scoped data rather than 401'ing.

After the call, it reacts to failures:


The `X-Retry` header caps this at a single retry. Refreshes go through `tokenRefreshManager`, which deduplicates concurrent calls so the proactive on-focus refresh and the reactive 401 path can't both fire and collide with server-side token rotation. The refresh call itself uses the separate `refreshTransport` with no interceptors (line 65) to avoid recursion, and `fetchWithCredentials` sets `credentials: "include"` so the refresh cookie is sent.

On the backend, `server/auth/` validates all three. `Authenticator.AuthenticateToUser` (`authenticator.go:190`) tries the `Authorization` header first via `resolveBearer`, which attempts `AuthenticateByAccessTokenV2` (JWT signature check) and falls back to `AuthenticateByPAT` (SHA-hash lookup through `Store.GetUserByPATHash`, plus expiry check and async last-used recording). If no bearer succeeds, it falls back to `ExtractRefreshTokenFromCookie` and `AuthenticateByRefreshToken`, which parses the JWT *and* verifies the token still exists in the database — so refresh tokens are revocable, unlike the stateless access token. Supporting files are `token.go` (mint/parse), `extract.go` (header and cookie parsing), and `context.go`.

This authenticator is wired into both protocols from q19: `gatewayAuthMiddleware` on the gRPC-Gateway mux, and the Connect handler options.
