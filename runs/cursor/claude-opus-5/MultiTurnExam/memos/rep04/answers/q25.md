**Engine:** Google CEL (Common Expression Language, `github.com/google/cel-go`), wrapped by the in-repo filter engine at **`internal/filter/`** — `engine.go` (compile), `parser.go` (CEL AST → condition tree), `render.go` (tree → SQL), `schema.go` (field/dialect definitions).

**Mechanism:** The filter string is compiled once by CEL into an AST, lowered into a dialect-agnostic intermediate condition tree, and only then rendered into a dialect-specific parameterized SQL fragment plus bind args, which each driver appends to its `WHERE` clause.

The two-stage split is the key design point. `Engine.Compile` runs `e.env.Compile(filter)` and hands the parsed expression to `buildCondition`, producing a `Program` that holds a `Condition` tree with no SQL in it. Rendering is a separate step parameterized by dialect:

```96:99:/bench/repo/internal/filter/engine.go
func (p *Program) Render(opts RenderOptions) (Statement, error) {
	renderer := newRenderer(p.schema, opts)
	return renderer.Render(p.condition)
}
```

`RenderOptions.Dialect` is a `DialectName` — one of `DialectSQLite`, `DialectMySQL`, `DialectPostgres` (`schema.go` lines 14–16). The renderer branches on it for the constructs that genuinely differ across engines: `stringLengthExpr`, `qualifyColumn`, `jsonExtractExpr`, `jsonArrayExpr`, and `jsonArrayLengthExpr` in `render.go`. JSON access is the main divergence, since memo payload fields are queried out of a JSON column.

Drivers consume it through one shared helper. `store/db/sqlite/memo.go` (q12) grabs the process-wide engine via `filter.DefaultEngine()` and calls:

```61:63:/bench/repo/store/db/sqlite/memo.go
	if err := filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args); err != nil {
		return nil, err
	}
```

`AppendConditions` (`internal/filter/helpers.go`) compiles each filter, wraps the fragment in parentheses, and appends it to the driver's own `where`/`args` slices. `PlaceholderOffset: len(*args)` is what lets the fragment interleave with hand-written conditions in the same query — necessary because Postgres uses positional `$1`, `$2` placeholders while SQLite and MySQL use `?`. Everything is bound as args rather than interpolated, so user filter text never reaches the SQL string.

`DefaultEngine` is a `sync.Once` singleton built from `NewSchema()`; a sibling `DefaultAttachmentEngine` provides the same machinery over an attachment schema. Note these are the same filter strings that `ShortcutService` persists as saved views (q14).
