The SQL layer is three files rather than one — each dialect ships its own `LATEST.sql` (q02, q10), and MySQL quotes the table name as `` `memo` `` which is why it needs a slightly different search. All three must change together for a schema edit, along with a new versioned migration directory under each dialect.

Two layers not asked about but sitting in the same chain: the generated **Go** protobuf type in `proto/gen/api/v1/memo_service.pb.go`, and the conversion seam `server/router/api/v1/memo_service_converter.go` that maps `store.Memo` onto the protobuf `Memo`. That converter is where the store model and the API model are reconciled, so a field added at one end stays invisible at the other until it's handled there (the same point that came up in q13).
