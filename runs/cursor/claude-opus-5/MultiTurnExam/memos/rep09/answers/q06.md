**`memo_relation`**

The table has three columns — `memo_id`, `related_memo_id`, and `type` — with a uniqueness constraint across all three, so a given pair of memos can be linked once per relation type:

```47:52:/bench/repo/store/migration/sqlite/LATEST.sql
CREATE TABLE memo_relation (
  memo_id INTEGER NOT NULL,
  related_memo_id INTEGER NOT NULL,
  type TEXT NOT NULL,
  UNIQUE(memo_id, related_memo_id, type)
);
```

The definition is identical across all three dialects, at `/bench/repo/store/migration/postgres/LATEST.sql` (line 46) and `/bench/repo/store/migration/mysql/LATEST.sql` (line 46, with backtick-quoted identifiers and `VARCHAR(256)` for `type`).

The store layer reads and writes it in the per-dialect `memo_relation.go` files, for example `/bench/repo/store/db/postgres/memo_relation.go`, which issues `INSERT INTO memo_relation`, `FROM memo_relation`, and `DELETE FROM memo_relation`. The `type` column is what distinguishes a plain reference from a comment link, since comments are modeled as a relation between the child memo and its parent.
