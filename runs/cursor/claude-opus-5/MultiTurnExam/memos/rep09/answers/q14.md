**RPCs: ListShortcuts, GetShortcut, CreateShortcut, UpdateShortcut, DeleteShortcut**

**Implementing file: `/bench/repo/server/router/api/v1/shortcut_service.go`**

The five RPCs are declared in `/bench/repo/proto/api/v1/shortcut_service.proto` (service block at line 14) with these REST mappings:

| RPC | HTTP mapping |
|---|---|
| `ListShortcuts` | `GET /api/v1/{parent=users/*}/shortcuts` |
| `GetShortcut` | `GET /api/v1/{name=users/*/shortcuts/*}` |
| `CreateShortcut` | `POST /api/v1/{parent=users/*}/shortcuts` |
| `UpdateShortcut` | `PATCH /api/v1/{shortcut.name=users/*/shortcuts/*}` |
| `DeleteShortcut` | `DELETE /api/v1/{name=users/*/shortcuts/*}` |

All five are implemented as `APIV1Service` methods in that single file, at lines 49, 95, 135, 211, and 284 respectively. As with the other services, `/bench/repo/server/router/api/v1/connect_services.go` holds the thin `ConnectServiceHandler` wrappers that forward to them.

A shortcut is a named, reusable CEL filter scoped to a user — the `filter` field uses the same grammar as the `ListMemos` filter argument, so the stored string can be passed straight through to `ListMemos` to reproduce a saved view.
