**Engine: CEL (Google Common Expression Language) via `cel-go`, in `/bench/repo/internal/filter/` — entry point `/bench/repo/internal/filter/engine.go`**

**Mechanism: the CEL expression is compiled to an AST, lowered into a dialect-agnostic condition tree (an intermediate representation), and then each dialect driver renders that tree into a parameterized SQL `WHERE` fragment plus args by passing its own `DialectName` to the renderer.**

The engine wraps a `cel.Env` built from a schema, and `Compile` turns the filter string into the IR:

```53:65:/bench/repo/internal/filter/engine.go
	ast, issues := e.env.Compile(filter)
	if issues != nil && issues.Err() != nil {
		return nil, errors.Wrap(issues.Err(), "failed to compile filter")
	}
	parsed, err := cel.AstToParsedExpr(ast)
	if err != nil {
		return nil, errors.Wrap(err, "failed to convert AST")
	}

	cond, err := buildCondition(parsed.GetExpr(), parseContext{schema: e.schema, now: e.nowFunc()})
	if err != nil {
		return nil, err
	}
```

Rendering is the dialect-specific half. `RenderOptions` carries `Dialect`, `PlaceholderOffset`, and `DisableNullChecks` (line 83), and `Render` returns a `Statement{SQL, Args}` — so values are always bound as placeholders rather than interpolated. The offset field exists because Postgres uses positional `$N` placeholders that must continue numbering from the surrounding query.

The dialect drivers each grab the shared engine and pass their own dialect constant:

with `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args)` at line 61 appending into the query's `where`/`args` slices. The Postgres and MySQL equivalents do the same at line 54 of `/bench/repo/store/db/postgres/memo.go` and line 65 of `/bench/repo/store/db/mysql/memo.go` with their respective constants.

`/bench/repo/internal/filter/render.go` is where the per-dialect divergence actually lives — it switches on `DialectSQLite`, `DialectMySQL`, and `DialectPostgres` at roughly two dozen points to handle things like JSON extraction from the `payload` column, string length (`stringLengthExpr` special-cases MySQL at line 297), and boolean and timestamp representations.

Supporting pieces in the package: `schema.go` defines the CEL environment and the allowed fields (`NewSchema` for memos, `NewAttachmentSchema` for attachments, each exposed as a process-wide singleton via `sync.Once` at lines 111 and 119 of `engine.go`), `parser.go` and `ir.go` build the condition tree, and `helpers.go` holds `AppendConditions`. The `now` variable is frozen once per `Compile` so a single filter evaluates against one instant.

The same filter grammar is reused elsewhere: shortcuts store a CEL string in their `filter` field for replay through `ListMemos` (see `/bench/repo/proto/api/v1/shortcut_service.proto`), and the API-layer wrappers are `/bench/repo/server/router/api/v1/memo_service_filter.go` and `user_service_filter.go`.
