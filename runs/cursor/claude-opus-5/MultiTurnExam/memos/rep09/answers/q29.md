The frontend `authInterceptor` (line 156) is installed on the shared Connect transport. It attaches the bearer token, and on an `Unauthenticated` response refreshes once and replays the request, tagging the retry so it can't loop:

```156:178:/bench/repo/web/src/connect.ts
const authInterceptor: Interceptor = (next) => async (req) => {
  const isRetryAttempt = req.header.get(RETRY_HEADER) === RETRY_HEADER_VALUE;
  const token = await getRequestToken();
  setAuthorizationHeader(req, token);

  try {
    return await next(req);
  } catch (error) {
    if (!shouldHandleUnauthenticatedRetry(error, isRetryAttempt)) {
      throw error;
    }

    try {
      const newToken = await refreshAndGetAccessToken();
      setAuthorizationHeader(req, newToken);
      req.header.set(RETRY_HEADER, RETRY_HEADER_VALUE);
      return await next(req);
    } catch (refreshError) {
      redirectOnAuthFailure();
      throw refreshError;
    }
  }
};
```

Three design details in that file are worth knowing. `getRequestToken` (line 124) also does a *preflight* refresh when the token is within an expiry buffer — the comment explains this matters for public endpoints like `ListMemos`, where an expired token would silently return guest-scoped data instead of a 401. Refreshes funnel through `tokenRefreshManager` (line 51) to deduplicate concurrent attempts that would otherwise conflict with server-side token rotation. And the refresh call itself uses a *separate* transport with no interceptors (line 65) to prevent recursion; the refresh token travels as a cookie, which is why both transports use `fetchWithCredentials` with `credentials: "include"`.

On the backend, `/bench/repo/server/auth/authenticator.go` defines `Authenticator` with one method per token kind: `AuthenticateByAccessTokenV2` (line 41) validates the JWT statelessly with no database query, `AuthenticateByRefreshToken` (line 61) parses the token then checks it against the database for revocation, expiry, and archived users, and `AuthenticateByPAT` (line 102) matches a prefixed token by hash via `GetUserByPATHash`. Its doc comment notes access tokens are 15-minute JWTs and that the same struct backs the gRPC interceptor, the Connect interceptor, and the file server so behavior stays consistent.

The wiring into request handling is in `/bench/repo/server/router/api/v1/v1.go`, where the gateway mux gets an auth middleware that calls `authorizer.CheckAccess` and applies the resolved identity to the request context via `auth.ApplyToContext`.
