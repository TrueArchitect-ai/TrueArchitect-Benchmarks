**Unused infrastructure:** the entire `internal/scheduler` package — a cron-style scheduler with `scheduler.go`, `parser.go`, `job.go`, and `middleware.go` — is never imported outside its own package and its tests. A repo-wide search for `internal/scheduler` imports returns no hits from `server/`, `store/`, or `bin/`, so nothing in the running server uses it.

Details on what the server actually wires up: `Server.Start` calls `startBackgroundRunners` at `server/server.go:129`, and that function (lines 153–174) creates only the s3presign runner, calls `RunOnce(ctx)` synchronously, then launches `Run(s3Context)` in a goroutine tracked by a `WaitGroup` with its own cancel func for graceful shutdown. The loop interval is `const runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27`); each pass re-presigns S3 attachment URLs that are close to expiring.

Two things that look like runners but aren't scheduled: the other package under `server/runner/`, `memopayload`, is not a background loop at all — its `RebuildMemoPayload` is called inline from the memo create/update handlers (`server/router/api/v1/memo_service.go:108` and `:447`). And the SSE hub (`server/router/api/v1/sse_hub.go`) spawns per-connection goroutines on demand rather than being a scheduled worker.
