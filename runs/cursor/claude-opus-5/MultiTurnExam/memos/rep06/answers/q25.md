**Engine: CEL (Common Expression Language, via `github.com/google/cel-go`) — `internal/filter/`, entry point `internal/filter/engine.go`**

**Mechanism:** the filter string is compiled by a CEL environment into an AST, lowered into a dialect-independent condition tree (intermediate representation), and then rendered into a parameterized SQL `WHERE` fragment by a dialect-aware renderer that each driver invokes with its own `DialectName`.

How the pieces fit together:

- `Engine.Compile` builds a CEL AST (`cel.NewEnv` at line 25, `cel.AstToParsedExpr` at line 57 of `internal/filter/engine.go`); the allowed fields and functions come from `internal/filter/schema.go`, with `DefaultEngine()` supplying the memo schema.
- `internal/filter/parser.go` and `internal/filter/ir.go` convert the parsed expression into a `Condition` tree.
- `internal/filter/render.go` turns that tree into SQL, branching per dialect. For example, date-part extraction differs three ways:

```231:239:internal/filter/render.go
	case DialectSQLite:
		base = fmt.Sprintf("CAST(strftime('%s', %s, 'unixepoch') AS INTEGER)", spec.sqlite, col)
		off = spec.off[0]
	case DialectPostgres:
		base = fmt.Sprintf("CAST(EXTRACT(%s FROM to_timestamp(%s) AT TIME ZONE 'UTC') AS INTEGER)", spec.pg, col)
		off = spec.off[1]
	case DialectMySQL:
		base = fmt.Sprintf("%s(%s)", spec.mysql, col)
```

Placeholder style and string-length functions (`LENGTH` vs `CHAR_LENGTH`, line 297) are handled the same way.

- Drivers call the shared helper `filter.AppendConditions` (`internal/filter/helpers.go:9`), which compiles each filter with `CompileToStatement` and appends the resulting SQL and bound args to the query's `where`/`args` slices. The call sites are `store/db/sqlite/memo.go:57–61` (with `filter.DialectSQLite`), `store/db/postgres/memo.go:54`, and `store/db/mysql/memo.go:65`.

The filter reaches this path from `APIV1Service.ListMemos` in `server/router/api/v1/memo_service.go`, which puts the expression into `store.FindMemo.Filters`. The same CEL machinery backs saved shortcuts (`Shortcut.filter` in `proto/api/v1/shortcut_service.proto`) and user filtering in `server/router/api/v1/user_service_filter.go`; supported syntax is documented in `internal/filter/README.md`.
