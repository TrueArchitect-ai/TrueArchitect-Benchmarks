Interceptor: **`web/src/connect.ts`** (the `authInterceptor`, backed by token storage in `web/src/auth-state.ts`)
Token kinds: **short-lived JWT access token** (sent as `Authorization: Bearer`, stored in `localStorage`) and **refresh token** (an httpOnly cookie sent automatically via `credentials: "include"`); the backend additionally accepts **Personal Access Tokens** on the same bearer header for programmatic clients
Backend package: **`server/auth`** (`authenticator.go`, `token.go`, `extract.go`)

The interceptor attaches the access token to every Connect call, and on an `Unauthenticated` response refreshes once and retries the same request with a marker header to prevent loops:

```156:178:web/src/connect.ts
const authInterceptor: Interceptor = (next) => async (req) => {
  const isRetryAttempt = req.header.get(RETRY_HEADER) === RETRY_HEADER_VALUE;
  const token = await getRequestToken();
  setAuthorizationHeader(req, token);

  try {
    return await next(req);
  } catch (error) {
    if (!shouldHandleUnauthenticatedRetry(error, isRetryAttempt)) {
      throw error;
    }

    try {
      const newToken = await refreshAndGetAccessToken();
      setAuthorizationHeader(req, newToken);
      req.header.set(RETRY_HEADER, RETRY_HEADER_VALUE);
      return await next(req);
    } catch (refreshError) {
      redirectOnAuthFailure();
      throw refreshError;
    }
  }
};
```

There's also a proactive refresh: `getRequestToken` checks `isTokenExpired` against a 30-second buffer and refreshes before sending, which matters for public endpoints like `ListMemos` where an expired token would otherwise be silently treated as anonymous. Concurrent refreshes are deduplicated by the `tokenRefreshManager`, and the refresh call itself uses a separate interceptor-free transport to avoid recursion.

On the server, `server/auth/authenticator.go` resolves credentials: `resolveBearer` tries an access-token JWT first (`AuthenticateByAccessTokenV2`) then falls back to a PAT (`AuthenticateByPAT`, which hashes the token and looks it up, checking expiry and recording last-used), while `AuthenticateByRefreshToken` parses the cookie JWT and verifies it against the stored token row. `server/auth/token.go` holds JWT generation/parsing with distinct audience claims — `user.access-token` versus `user.refresh-token` — so a refresh token can't be replayed as an access token. The middleware that invokes this sits in `server/router/api/v1/v1.go` for the REST gateway and in the Connect interceptors registered at line 141 of the same file.
