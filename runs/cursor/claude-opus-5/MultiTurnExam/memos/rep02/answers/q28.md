**s3presign — one immediate run at startup, then a 12-hour `time.Ticker`, until its context is cancelled on shutdown**

That is the only background runner the server starts. `startBackgroundRunners` gives it its own cancellable context, calls `RunOnce` synchronously, then loops it in a goroutine tracked by a `WaitGroup`:

```161:171:server/server.go
	// Create and start S3 presign runner
	s3presignRunner := s3presign.NewRunner(s.Store)
	s3presignRunner.RunOnce(ctx)

	// Start continuous S3 presign runner
	s.backgroundRunnerWG.Add(1)
	go func() {
		defer s.backgroundRunnerWG.Done()
		s3presignRunner.Run(s3Context)
		slog.Info("s3presign runner stopped")
	}()
```

The interval is a package constant, and the loop exits on context cancellation:

```26:41:server/runner/s3presign/runner.go
// Schedule runner every 12 hours.
const runnerInterval = time.Hour * 12

func (r *Runner) Run(ctx context.Context) {
	ticker := time.NewTicker(runnerInterval)
	defer ticker.Stop()

	for {
		select {
		case <-ticker.C:
			r.RunOnce(ctx)
		case <-ctx.Done():
			return
		}
	}
}
```

Its job is refreshing presigned URLs for S3-backed attachments in batches (`CheckAndPresign`).

**Unused scheduling infrastructure — two pieces:**

`internal/scheduler` is a complete, tested, cron-expression job scheduler (`scheduler.go`, `parser.go`, `job.go`, `middleware.go`, its own README and integration tests, described in `internal/scheduler/doc.go` as "a GitHub Actions-inspired cron job scheduler"), but nothing imports it — a repo-wide search for `internal/scheduler` returns hits only inside the package itself. The server does not use cron at all.

`server/runner/memopayload` has a `Runner` type with `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go`) that is never constructed or scheduled. Only its standalone `RebuildMemoPayload` function is used, called inline from the memo handlers at `server/router/api/v1/memo_service.go:108` (create) and line 447 (update). So payload rebuilding happens on the request path, not as a background pass.

For completeness, two other concurrent things run but aren't scheduled runners: the Echo HTTP server goroutine (`server/server.go:124`) and per-event webhook delivery goroutines via `webhook.PostAsync`; the SSE hub is likewise event-driven and merely closed during shutdown.
