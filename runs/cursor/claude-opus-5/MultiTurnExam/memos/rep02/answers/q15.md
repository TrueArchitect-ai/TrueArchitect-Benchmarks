All three follow the same convention as `store.Memo`: a plain Go struct in the `store` package, with `Find*`/`Update*`/`Delete*` companion types in the same file, and hand-written SQL per dialect in `store/db/sqlite/`, `store/db/postgres/`, and `store/db/mysql/` (e.g. `store/db/sqlite/user.go`, `attachment.go`, `reaction.go`). The tables themselves are declared in `store/migration/{dialect}/LATEST.sql`.

```7:14:store/reaction.go
type Reaction struct {
	ID        int32
	CreatedTs int64
	CreatorID int32
	// ContentID is the id of the content that the reaction is for.
	ContentID    string
	ReactionType string
}
```

Two details worth flagging. `Reaction.ContentID` is a string rather than a memo foreign key, so reactions aren't limited to memos structurally. And `Attachment` carries both an inline `Blob []byte` and a `StorageType`/`Reference` pair, since a file may live in the database, on local disk, or in external storage.
