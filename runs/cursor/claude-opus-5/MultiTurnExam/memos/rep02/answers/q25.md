**CEL (Google Common Expression Language), via `cel-go`, wrapped by the `Engine` in `internal/filter/engine.go` (package `internal/filter`)**

Mechanism: the engine compiles the filter string into a dialect-agnostic condition tree (`internal/filter/parser.go` walking the CEL AST into `Condition` nodes from `internal/filter/ir.go`), and a renderer then emits dialect-specific SQL with bound placeholders by switching on `DialectSQLite`/`DialectPostgres`/`DialectMySQL` (`internal/filter/render.go`), which each driver appends to its `WHERE` clause via `filter.AppendConditions`.

The CEL environment is built from a schema that declares the allowed identifiers and functions:

```23:33:internal/filter/engine.go
// NewEngine builds a new Engine for the provided schema.
func NewEngine(schema Schema) (*Engine, error) {
	env, err := cel.NewEnv(schema.EnvOptions...)
	if err != nil {
		return nil, errors.Wrap(err, "failed to create CEL environment")
	}
	return &Engine{
		schema:  schema,
		env:     env,
		nowFunc: time.Now,
	}, nil
}
```

The three dialect names are constants in `internal/filter/schema.go` (lines 14-16), and the shared helper keeps SQL injection off the table by only ever appending parameterized fragments plus their args:

```9:23:internal/filter/helpers.go
func AppendConditions(ctx context.Context, engine *Engine, filters []string, dialect DialectName, where *[]string, args *[]any) error {
	for _, filterStr := range filters {
		stmt, err := engine.CompileToStatement(ctx, filterStr, RenderOptions{
			Dialect:           dialect,
			PlaceholderOffset: len(*args),
		})
		if err != nil {
			return err
		}
		if stmt.SQL == "" {
			continue
		}
		*where = append(*where, fmt.Sprintf("(%s)", stmt.SQL))
		*args = append(*args, stmt.Args...)
	}
	return nil
}
```

The call site is each driver's `ListMemos` — for example `store/db/sqlite/memo.go:61` passes `find.Filters` with `filter.DialectSQLite`. `PlaceholderOffset` exists because Postgres uses numbered placeholders (`$1`, `$2`) while SQLite and MySQL use `?`, so the renderer must know how many args were already bound.

Two details worth knowing: unknown identifiers are rejected at compile time against the schema (`parser.go` returns `unknown identifier %q`), so filters can only reference whitelisted fields; and the `now` variable is frozen once per compile so a single filter observes one instant. The same compiled-filter mechanism backs saved shortcuts, since a `Shortcut.filter` is just a CEL string passed through to `ListMemos`.
