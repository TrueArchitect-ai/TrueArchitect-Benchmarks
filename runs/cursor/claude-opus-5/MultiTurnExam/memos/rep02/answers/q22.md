`dispatchMemoRelatedWebhook` resolves the memo's creator through `ResolveUserByName`, loads that user's webhooks via `Store.GetUserWebhooks`, and for each one builds a payload carrying the memo, the activity type, the target URL, and the hook's signing secret, then hands it to `webhook.PostAsync` so delivery happens off the request path.

Actual HTTP delivery lives in `internal/webhook/webhook.go`. When a signing secret is configured, `Post` computes the MAC over `msgID + "." + timestamp + "."` concatenated with the JSON body and sets three headers:

```142:149:internal/webhook/webhook.go

		mac.Write([]byte(msgID + "." + timestamp + "."))
		mac.Write(body)
		signature := base64.StdEncoding.EncodeToString(mac.Sum(nil))

		req.Header.Set("webhook-id", msgID)
		req.Header.Set("webhook-timestamp", timestamp)
		req.Header.Set("webhook-signature", "v1,"+signature)
```

Secrets are generated as `whsec_<base64>` over 32 random bytes (`GenerateSigningSecret`) and base64-decoded back to raw key bytes before signing. Signing is optional — with an empty secret the request goes out unsigned. Requests also go through a `safeClient` and URLs are validated by `internal/webhook/validate.go`, which is the SSRF guard for user-supplied endpoints.
