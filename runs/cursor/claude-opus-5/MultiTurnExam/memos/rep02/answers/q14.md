`ShortcutService` has **5** RPCs, defined in `proto/api/v1/shortcut_service.proto`:

| RPC | REST mapping |
| --- | --- |
| `ListShortcuts` | `GET /api/v1/{parent=users/*}/shortcuts` |
| `GetShortcut` | `GET /api/v1/{name=users/*/shortcuts/*}` |
| `CreateShortcut` | `POST /api/v1/{parent=users/*}/shortcuts` |
| `UpdateShortcut` | `PATCH /api/v1/{shortcut.name=users/*/shortcuts/*}` |
| `DeleteShortcut` | `DELETE /api/v1/{name=users/*/shortcuts/*}` |

All five are implemented in **`server/router/api/v1/shortcut_service.go`**, as methods on `APIV1Service` at lines 49, 95, 135, 211, and 284 respectively.

The Connect-protocol wrappers for these live in `server/router/api/v1/connect_services.go`, and the generated bindings are in `proto/gen/api/v1/apiv1connect/shortcut_service.connect.go`. Worth noting from the proto comments: a shortcut is essentially a saved CEL filter string that the client passes straight into the `ListMemos` `filter` argument.
