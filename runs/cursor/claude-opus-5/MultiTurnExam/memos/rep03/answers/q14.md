**RPCs (5): ListShortcuts, GetShortcut, CreateShortcut, UpdateShortcut, DeleteShortcut**

**Implementing file: `server/router/api/v1/shortcut_service.go`**

All five are declared in `proto/api/v1/shortcut_service.proto` (service at line 14) and implemented as `APIV1Service` methods in that single Go file:

| RPC | REST mapping | Handler line |
|---|---|---|
| `ListShortcuts` | `GET /api/v1/{parent=users/*}/shortcuts` | 49 |
| `GetShortcut` | `GET /api/v1/{name=users/*/shortcuts/*}` | 95 |
| `CreateShortcut` | `POST /api/v1/{parent=users/*}/shortcuts` | 135 |
| `UpdateShortcut` | `PATCH /api/v1/{shortcut.name=users/*/shortcuts/*}` | 211 |
| `DeleteShortcut` | `DELETE /api/v1/{name=users/*/shortcuts/*}` | 284 |

The same file also holds three unexported helpers used by those handlers — `extractUserAndShortcutIDFromName`, `constructShortcutName`, and `validateFilter` (a shortcut is a named CEL filter string, so creates and updates validate it).

As with the other services, Connect-protocol requests arrive through thin delegating wrappers on `ConnectServiceHandler` in `server/router/api/v1/connect_services.go`, which contain no logic of their own.
