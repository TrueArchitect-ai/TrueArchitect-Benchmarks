On the frontend, `authInterceptor` (line 156 of `connect.ts`) is attached to the shared Connect transport. It fetches a token, sets the header, and on an `Unauthenticated` response refreshes once and replays the request exactly one time, marked with an `X-Retry` header:

Token storage and expiry live in `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken` back onto `localStorage`, with `REQUEST_TOKEN_EXPIRY_BUFFER_MS` driving a preflight refresh so expired tokens aren't sent to public endpoints). The refresh token itself is never read by JS — all requests use `credentials: "include"` so the cookie rides along, and refresh goes through a separate interceptor-free `refreshTransport`/`refreshAuthClient` (lines 65–72) to avoid recursion. A `tokenRefreshManager` de-duplicates concurrent refreshes.

Server-side validation is `server/auth/authenticator.go`. `resolveBearer` (line 149) tries `AuthenticateByAccessTokenV2` (JWT signed with the instance secret) and falls back to `AuthenticateByPAT` (line 102), which hashes the token and looks it up via `Store.GetUserByPATHash`, checks expiry, and records last-used asynchronously. `AuthenticateByRefreshToken` (line 61) parses the refresh JWT and additionally verifies it against the database (`GetUserRefreshTokenByID`), so refresh tokens are revocable. Header/cookie parsing is in `server/auth/extract.go`, JWT signing and parsing in `server/auth/token.go`, and identity propagation in `server/auth/context.go`.

Both serving protocols funnel into that package: the Connect path uses `NewAuthInterceptor(authorizer)` and the REST gateway uses `gatewayAuthMiddleware`, both wired in `server/router/api/v1/v1.go`, with per-method public/private rules in `server/router/api/v1/acl_config.go`. The SSE endpoint authenticates separately in `server/router/api/v1/sse_handler.go`.
