REST / gRPC-Gateway (HTTP+JSON) — `server/router/api/v1/v1.go`
ConnectRPC — `server/router/api/v1/connect_handler.go` (registration) and `server/router/api/v1/connect_services.go` (per-RPC wrapping), wired up in `server/router/api/v1/v1.go`

Both are backed by the same `APIV1Service` methods, so there's one copy of the business logic.

For REST, the gateway is registered in-process onto a `runtime.ServeMux` (no network gRPC hop) and mounted on the Echo server under `/api/v1/*`:

```108:110:server/router/api/v1/v1.go
	if err := v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s); err != nil {
		return err
	}
```

This is what turns the `google.api.http` annotations in the proto into paths like `POST /api/v1/memos`. Auth is applied through `gatewayAuthMiddleware`.

For Connect, `RegisterConnectHandlers` mounts the generated handler on its own mux:

```40:40:server/router/api/v1/connect_handler.go
		wrap(apiv1connect.NewMemoServiceHandler(s, opts...)),
```

That mux is served at `/memos.api.v1.*` with its own interceptor chain (metadata, logging, recovery, auth), per lines 131–144 of `v1.go`. The `ConnectServiceHandler` type embeds `*APIV1Service` and each RPC has a thin adapter in `connect_services.go` (e.g. `CreateMemo` at line 307) that unwraps `connect.Request`, calls the shared method, and converts gRPC status errors to Connect codes via `convertGRPCError`.

Note there is no native gRPC listener — no `grpc.NewServer` anywhere in the tree — so these two HTTP-based protocols are the complete set. Connect is what the web frontend uses via `web/src/connect.ts`.
