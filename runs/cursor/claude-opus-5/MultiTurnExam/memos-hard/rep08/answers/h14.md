**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, which delegates to `markdown.Service.ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: memo creation (`CreateMemo`) and content updates (`UpdateMemo` when `content` is in the update mask); comment creation inherits it via `CreateMemo`. Extracted: `Tags` plus five `Property` flags/values — `Title`, `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks`.**

**Where it's computed.** `RebuildMemoPayload` initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`server/runner/memopayload/runner.go:74-88`). The actual parsing is a single goldmark AST walk in `ExtractAll` — the comment at line 355 notes the single-parse design is deliberate for efficiency.

**What gets extracted**, from the walk at `internal/markdown/markdown.go:371-408`:

- `Tags` — every `#tag` node, via `asMemoTagNode`. Note the helper `isTagNodeInLinkOrImage` exists so tags inside links/images aren't treated as tags.
- `Property.Title` — the text of the first block-level child of the document, but only if it's an H1 heading (lines 384-389).
- `Property.HasLink` — any `KindLink` node.
- `Property.HasCode` — any code block, fenced code block, or inline code span.
- `Property.HasTaskList` — any task checkbox; and `Property.HasIncompleteTasks` when at least one checkbox is unchecked.

Those five are exactly the fields of `storepb.MemoPayload_Property` (`proto/gen/store/memo.pb.go:85-95`). `ExtractAll` also collects `Mentions`, but `RebuildMemoPayload` doesn't persist them — mentions are used for notifications rather than stored metadata.

**Triggers.** Only two production call sites:

- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, run after the content-length check and before `Store.CreateMemo`, so the payload is written in the same INSERT.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, inside the `if path == "content"` branch of the update-mask loop; it then sets both `update.Content` and `update.Payload`. This is the key detail: recomputation happens *only* when `content` is being updated. Changing visibility, pinning, or timestamps leaves the derived metadata untouched.

`CreateMemoComment` also triggers it, but indirectly — it calls `s.CreateMemo(...)` at `server/router/api/v1/memo_service_comments.go:56`, so it inherits the create-path computation rather than having its own.

There is also a batch backfill in `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) that rebuilds payloads for all memos in batches of 100, but as noted earlier that runner is never constructed in production, so it isn't a live trigger.

**One nuance about "previews."** The list/preview `Snippet` field is *not* part of this stored payload — it's computed on read by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-90`), called during conversion at `server/router/api/v1/memo_service_converter.go:76` and `:225`, and for relation previews at `server/router/api/v1/memo_relation_service.go:154,162`. So tags and properties are persisted derived metadata; the snippet is derived per response.
