**`internal/idp` (package `idp`, file `internal/idp/idp.go`); `internal/idp/oauth2` (package `oauth2`, file `internal/idp/oauth2/oauth2.go`) — OAuth 2.0 is the only concrete implementation.**

A few things worth noting about how thin the abstraction actually is:

The `idp` package is deliberately minimal — `internal/idp/idp.go` is nine lines and defines exactly one type, `IdentityProviderUserInfo`, with `Identifier`, `DisplayName`, `Email`, and `AvatarURL`. There is no Go `interface` for providers; the shared contract is just this normalized user-info struct that every provider implementation must produce.

The OAuth2 implementation is `oauth2.IdentityProvider` (`internal/idp/oauth2/oauth2.go:20`), built from a `storepb.OAuth2Config` via `NewIdentityProvider`, which validates that `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier` are all non-empty. It exposes two methods: `ExchangeToken` (line 47), which trades the authorization code for an access token using `golang.org/x/oauth2` and supports PKCE by passing `code_verifier`, and `UserInfo` (line 83), which calls the userinfo endpoint with a bearer token and maps arbitrary JSON claims into `idp.IdentityProviderUserInfo` using the configured field mapping.

That OAuth2 is the sole protocol is confirmed from two directions. The stored provider type enum has only one non-unspecified value, `IdentityProvider_OAUTH2 = 1` (`proto/gen/store/idp.pb.go:27-28`), and the single consumer dispatches on it with a lone branch — `if identityProvider.Type == storepb.IdentityProvider_OAUTH2` in `resolveSSOIdentity` at `server/router/api/v1/auth_service_sso.go:120-134`. No OIDC-specific, SAML, or LDAP provider package exists under `internal/`.
