**Premise correction: there is no Redis in this repository.** A case-insensitive search for "redis" across all Go files, `go.mod`, and `go.sum` returns zero matches, and there's no memcached or other external cache dependency either. Nothing to configure — no connection string, host/port setting, or client library exists.

**Actual mechanism: a process-local, in-memory cache implemented in `store/cache/cache.go`.**

`cache.Cache` (`store/cache/cache.go:67-73`) is a thread-safe map built on `sync.Map` plus an atomic item counter. It supports TTL expiry, a max-item cap with eviction, and a background cleanup goroutine (`cleanupLoop`, line 200). Because it lives inside the process, it is not shared across replicas — each instance has its own copy, and cache invalidation is purely local.

There are three separate cache instances, all constructed in `store.New` (`store/store.go:47-56`): `instanceSettingCache`, `userCache`, and `userSettingCache`.

**TTL for user entries: 10 minutes.** All three caches share one `cache.Config` literal defined inline in `store.New` (`store/store.go:38-43`) with `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`, and no eviction callback. Every write to the user cache goes through `Set` — `store/user.go:98, 122, 132, 143, 167` — and `Set` applies `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). Nothing in the repo calls `SetWithTTL` with a custom duration, so 10 minutes is the effective TTL for user entries with no exceptions.

Two details about how that TTL actually behaves:

Expiry is enforced both lazily and eagerly. `Get` checks `time.Now().After(itm.expiration)` and deletes on read (`store/cache/cache.go:135-144`), while the cleanup goroutine sweeps expired entries every 5 minutes (`cleanup`, line 218). Entries can also be dropped early: if the count exceeds `MaxItems` (1000), `cleanupOldest` (line 253) removes roughly 20% of the cap.

Separately, cached users are explicitly invalidated rather than waited out. `Store.DeleteUser` calls `deleteUserCache`, which does `s.userCache.Delete(...)` (`store/user_delete.go:40`), and `Store.Close` shuts down all three caches' goroutines (`store/store.go:74-76`).

Worth noting for the read path: `Store.GetUser` only consults `userCache` when looking up by ID (`store/user.go:149-156`), so username-based lookups — like avatar serving — always miss the cache and hit the database.

Note also that `cache.Config` values are hardcoded in Go, not exposed through any flag or config file, so the 10-minute TTL isn't tunable at runtime. There is a separate `cache.DefaultConfig()` helper (`store/cache/cache.go:57`) with identical values, but `store.New` doesn't use it — it declares its own equivalent literal.
