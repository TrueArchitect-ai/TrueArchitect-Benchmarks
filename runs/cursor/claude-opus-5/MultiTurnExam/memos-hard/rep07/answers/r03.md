**Premise correction: no nightly database-cleanup job exists, and the cron scheduler is never started. The `internal/scheduler` package is dead code — nothing outside it imports or uses it — so there is no schedule to report.**

Evidence:

**Nothing registers a job.** Searching the whole repo for `scheduler.` outside `internal/scheduler/` itself returns no matches. There are no calls to `scheduler.New`, `Register`, or `Start` anywhere in `cmd/`, `server/`, or `store/`. The package ships a complete implementation (`scheduler.go`, `job.go`, a cron expression parser in `parser.go`, and middleware in `middleware.go`) plus tests, but no production caller.

**The "2 AM daily cleanup" is documentation, not configuration.** The only place in the codebase where a nightly cleanup schedule appears is an illustrative example in the package doc comment:

```14:21:internal/scheduler/doc.go
//	s.Register(&scheduler.Job{
//		Name:     "daily-cleanup",
//		Schedule: "0 2 * * *", // 2 AM daily
//		Handler: func(ctx context.Context) error {
//			// Your cleanup logic here
//			return nil
//		},
//	})
```

That is a usage snippet showing how the API would be called; it registers nothing and never executes. If the premise came from having seen `0 2 * * *` in this repo, that comment is the source.

**What actually runs on a timer.** The server's only scheduled background work is the S3 presign runner, and it uses a plain `time.Ticker` rather than the cron scheduler: it runs once at startup and then every 12 hours (`server/runner/s3presign/runner.go:27-41`), wired in at `server/server.go:162-171`. Separately, each in-memory cache runs a 5-minute sweep of expired entries (`store/cache/cache.go:200-215`, interval set at `store/store.go:42`), but that is process-local memory eviction, not database cleanup.

**Database cleanup is event-driven, not scheduled.** Removal of dependent rows happens inline when a user or memo is deleted — for example the transactional cascade in `store/db/sqlite/user_delete.go:92-127` and attachment storage cleanup in `store/attachment.go:171` — triggered by API calls rather than by a clock.
