**No — outside the factory, `store/db/mysql` is never imported and `mysql.NewDB` is never called; the only direct `&DB{}` construction is an in-package unit test that does not go through the driver package's public entry point.**

Evidence:

1. **Exactly one importer.** Grepping the whole tree for the import path `github.com/usememos/memos/store/db/mysql` returns a single hit, the factory itself at `store/db/db.go:8`. Since Go requires an import to reference a package, no other package can construct the MySQL driver.

2. **Exactly one call site.** `mysql.NewDB(profile)` appears once, in the driver-selection switch:

```18:27:store/db/db.go
	switch profile.Driver {
	case "sqlite":
		driver, err = sqlite.NewDB(profile)
	case "mysql":
		driver, err = mysql.NewDB(profile)
	case "postgres":
		driver, err = postgres.NewDB(profile)
	default:
		return nil, errors.New("unknown db driver")
	}
```

3. **Test helpers also route through the factory.** The store test harness builds a profile with `Driver: "mysql"` and then calls `db.NewDBDriver(profile)` (`store/test/store.go:28` and `:50`, with the DSN chosen at `store/test/store.go:88-89`). It never touches the `mysql` package directly. `store/test/containers.go` imports `github.com/go-sql-driver/mysql` and the testcontainers MySQL module — those are the upstream third-party packages used to spin up and probe the container, not this repo's driver.

4. **The one literal struct construction is intra-package.** `store/db/mysql/auth_config_test.go:12` does `db := &DB{}`, but that file is `package mysql`, so it is inside the driver package rather than outside it, and it builds a zero-value struct purely to exercise `IsRetryableAuthenticationMutationError` — no connection is opened. (For contrast, the Postgres driver has the same pattern in `store/db/postgres/auth_config_test.go:12` and `store/db/postgres/user_setting_test.go`.)

One nuance worth flagging: `store/db/mysql/mysql.go:35` calls `sql.Open("mysql", dsn)`, which relies on the `github.com/go-sql-driver/mysql` package being registered with `database/sql`. That registration happens via that library's own `init()`, imported at `store/db/mysql/mysql.go:7` for `mysql.ParseDSN` and `mysql.Config` — again inside the driver package.
