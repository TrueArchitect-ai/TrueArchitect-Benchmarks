**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`; convergence function: `webhook.PostAsync` — `internal/webhook/webhook.go:184` (which hands off to `webhook.Post` at `internal/webhook/webhook.go:120`, where the HTTP request is actually issued).**

The six handlers and how each reaches the webhook layer:

| Handler | Location | Path to dispatch |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:70` | `DispatchMemoCreatedWebhook` at `:157` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:401` | `dispatchMemoUpdatedSideEffects` at `:513` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:518` | `DispatchMemoDeletedWebhook` at `:562` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` at `:119` |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:16` | `dispatchMemoUpdatedSideEffects` at `:48` |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:16` | `dispatchMemoUpdatedSideEffects` at `:48` |

The last three of those funnel through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` — so editing a memo's attachments or relations fires the same `memos.memo.updated` webhook as editing its content.

The four `Dispatch*Webhook` methods in turn all collapse into two loops in `server/router/api/v1/memo_service_webhooks.go`: `dispatchMemoRelatedWebhook` (`:48`) for created/updated/deleted, and `DispatchMemoCommentCreatedWebhook` (`:30`) for comments, which notifies the *parent* memo's owner rather than the commenter. Both load the target user's webhook rows with `s.Store.GetUserWebhooks`, set `payload.URL = hook.Url` and `payload.SigningSecret = hook.SigningSecret`, and call `webhook.PostAsync(payload)` — the two call sites at `server/router/api/v1/memo_service_webhooks.go:43` and `:71` are the only `PostAsync` callers in the repo.

`PostAsync` is the single convergence point: it enqueues onto a bounded 128-entry channel drained by four worker goroutines started in `init()` (`internal/webhook/webhook.go:39-55`), each of which calls `Post`. So delivery is off the request goroutine — a slow or hostile endpoint can't block the RPC, and an over-full queue drops the event with a warning rather than applying backpressure.

Two things worth distinguishing: the URL is user-configured per-account (validated on save by `webhook.ValidateURL`, `server/router/api/v1/user_service_webhooks.go:74`), and it's the *memo creator's* webhooks that fire, not the caller's — so `SetMemoRelations` invoked by one user can trigger an outbound request to another user's endpoint. Separately, `server/router/api/v1/memo_service.go:28` wires `httpgetter.GetHTMLMeta` for link previews; that also makes outbound HTTP, but to a URL pasted in memo content rather than a configured webhook target, and it does not go through `webhook.Post`.
