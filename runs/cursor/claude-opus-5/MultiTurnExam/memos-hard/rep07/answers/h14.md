**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating the actual parse to `(*markdown.service).ExtractAll` at `internal/markdown/markdown.go:356`; triggers: memo creation, memo update when the field mask includes `content`, and comment creation (which routes through creation); extracted: the deduplicated tag list plus five computed properties — `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`, and `title`.**

**Where it's computed.** `RebuildMemoPayload` is a thin wrapper that writes two fields onto the memo's `storepb.MemoPayload`:

```74:88:server/runner/memopayload/runner.go
func RebuildMemoPayload(_ context.Context, memo *store.Memo, markdownService markdown.Service) error {
	if memo.Payload == nil {
		memo.Payload = &storepb.MemoPayload{}
	}

	// Use goldmark service to extract all metadata in a single pass (more efficient)
	data, err := markdownService.ExtractAll([]byte(memo.Content))
	if err != nil {
		return errors.Wrap(err, "failed to extract markdown metadata")
	}

	memo.Payload.Tags = data.Tags
	memo.Payload.Property = data.Property
	return nil
}
```

Note it only overwrites `Tags` and `Property`; `Payload.Location` is left alone, because location is user-supplied rather than derived (set separately at `server/router/api/v1/memo_service.go:112`).

**Triggers.** There are exactly three call sites in the repo:

- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, run after the content-length check and before `Store.CreateMemo`, so the payload is persisted with the initial INSERT.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, inside the `path == "content"` branch of the update-mask loop. Changing only visibility, pinned state, or row status does not recompute anything.
- `CreateMemoComment` — indirectly, since it delegates to `s.CreateMemo` at `server/router/api/v1/memo_service_comments.go:56`.

A fourth call exists in the batch backfill `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:52`), but that runner is never constructed in production, so it doesn't fire at runtime.

**What gets extracted.** `ExtractAll` parses once and does a single AST walk (`internal/markdown/markdown.go:356-422`), collecting:

- **Tags** — from custom `TagNode`s, deduplicated with original case preserved via `uniquePreserveCase` (`internal/markdown/markdown.go:418`).
- **`Title`** — the text of the first block-level child of the document, but only when it is an H1 heading (`internal/markdown/markdown.go:383-389`).
- **`HasLink`** — any `KindLink` node.
- **`HasCode`** — any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`.
- **`HasTaskList`** and **`HasIncompleteTasks`** — the former for any task checkbox, the latter when at least one checkbox is unchecked (`internal/markdown/markdown.go:399-405`).

The shape is fixed by `MemoPayload.Property` in `proto/store/memo.proto:15-22`, with tags at field 3.

**How it's consumed.** The stored payload is read back straight onto the API response in `convertMemoFromStore` (`server/router/api/v1/memo_service_converter.go:48-50`), which is what lets list views show tags and badges without re-parsing markdown. Worth distinguishing: the `Snippet` field on the same response is *not* part of this derived payload — it's generated per-request from `memo.Content` via `getMemoContentSnippet` (`server/router/api/v1/memo_service_converter.go:76`).

`ExtractAll` also returns `Mentions`, but `RebuildMemoPayload` discards them; mentions are consumed separately for notifications at `server/router/api/v1/memo_mention_helpers.go:32`.
