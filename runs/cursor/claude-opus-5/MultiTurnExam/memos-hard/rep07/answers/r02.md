**Premise correction: this repository has no rate-limiting middleware at all — per-user or otherwise — so there is no registration site and no request limits to report.**

What I checked:

- A case-insensitive search across all Go sources for `ratelimit`, `rate_limit`, "rate limit", `throttl`, `golang.org/x/time/rate`, and `Limiter` returns exactly one hit, and it's an aspirational comment in documentation rather than code: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a future consideration.
- `go.mod` has no rate-limiting dependency; `golang.org/x/time` is not required at all.
- The Echo middleware stack is two entries, neither of which throttles: `echoServer.Use(middleware.Recover())` and `echoServer.Use(newCORSMiddleware(profile))` at `server/server.go:51-52`. Echo v5's `middleware.RateLimiter` is available in the imported package but is never used.
- The Connect/gRPC interceptor chain in `server/router/api/v1/connect_interceptors.go` consists of `MetadataInterceptor` (header-to-metadata conversion, `:22`), `LoggingInterceptor` (`:98`), and `RecoveryInterceptor` (panic recovery, `:165`). Authentication and authorization run through `NewAuthorizer` (`server/router/api/v1/v1.go:68`) and the ACL config in `server/router/api/v1/acl_config.go`, but none of these count or reject requests by frequency.

**The nearest things that do exist** are concurrency limiters, not rate limiters — they cap how many operations run *simultaneously* rather than how many a user may issue over time, and they are global rather than per-user:

- `thumbnailSemaphore` on the file server, `semaphore.NewWeighted(maxConcurrentThumbnails)` — `server/router/fileserver/fileserver.go:107`, `:116`, acquired at `:447`.
- `thumbnailSemaphore` (weight 3) and `imageProcessingSemaphore` (weight 2) on the API service — `server/router/api/v1/v1.go:40-41`, constructed at `:59-60`.

There are also unrelated per-request size and pagination bounds — the memo content-length limit checked in `CreateMemo`/`UpdateMemo` (`server/router/api/v1/memo_service.go:101-107`) and `MaxPageSize` clamping in `ListMemos` (`server/router/api/v1/memo_service.go:240`) — plus the bounded 128-slot webhook dispatch queue (`internal/webhook/webhook.go:39`), which sheds load by dropping events. None of these is a per-user API rate limit.
