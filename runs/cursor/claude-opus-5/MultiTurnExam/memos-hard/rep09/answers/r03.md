**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never used by the running server — so there is no schedule time to report.**

Two separate parts of the premise are false:

**No cron job is registered anywhere in production.** The package `internal/scheduler` does implement a real cron system (a spec parser in `internal/scheduler/parser.go`, jobs in `internal/scheduler/job.go`, and `Scheduler.Register`/`Start` in `internal/scheduler/scheduler.go`), but the only files that import `github.com/usememos/memos/internal/scheduler` are its own tests — `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. No file under `cmd/`, `server/`, or `store/` references it, so no cron expression is ever registered and the scheduler never starts. This matches the earlier finding that `Scheduler.Register` has callers only in tests plus one documentation example (`internal/scheduler/doc.go`).

**There is no database-cleanup task at all.** Searching for cleanup/vacuum/prune/purge in `server/`, `store/`, and `cmd/` turns up only inline cleanup that happens synchronously within request handling — attachment blob cleanup during user deletion (`server/router/api/v1/user_service.go:421-450`), relation/attachment cleanup inside memo deletion (`server/router/api/v1/memo_service.go:579`), and a best-effort rollback of an orphaned SSO user row (`server/router/api/v1/auth_service_sso.go:76`). None of these is scheduled.

For completeness, the only recurring background work in the server is time-interval based rather than cron/clock based, so neither runs at a fixed nightly hour:

- The S3 presign runner, every 12 hours from process start (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27`), started at `server/server.go:163-171`.
- The in-memory cache's expired-item sweep, every 5 minutes (`CleanupInterval`, `store/store.go:42`; loop at `store/cache/cache.go:199-210`). This evicts cache entries, not database rows.
