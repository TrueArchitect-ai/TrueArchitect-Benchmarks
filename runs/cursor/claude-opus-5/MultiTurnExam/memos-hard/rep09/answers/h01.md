**S3 presign runner (`s3presign.Runner`) — every 12 hours (plus one immediate pass at startup) — `server/server.go:163` (immediate `RunOnce`) and `server/server.go:169` (the recurring loop), both inside `startBackgroundRunners`, which is called from `Server.Start` at `server/server.go:129`.**

How it works:

- The component lives in `server/runner/s3presign/runner.go`. Its interval is a package constant, `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27`), driving a `time.NewTicker` loop in `Run` that calls `RunOnce` on each tick and exits when its context is cancelled.
- `CheckAndPresign` pages through attachments whose storage type is `AttachmentStorageType_S3` in batches of 100, and for each S3 object it regenerates a presigned GET URL via `s3.NewClient(...).PresignGetObject(...)`, then writes the new URL into the attachment's `Reference` field along with an updated `LastPresignedTime`. That's what keeps the stored links from going stale.
- The refresh is deliberately ahead of expiry: an attachment is skipped if its `LastPresignedTime` is less than 4 days old, because the presigned URLs are issued with a 5-day expiration (`server/runner/s3presign/runner.go:85-91`).
- Wiring detail worth noting: the startup `RunOnce(ctx)` at line 163 runs synchronously on the caller's context, so the first presign sweep completes before `Start` returns; only the ticker loop gets the separate cancellable `s3Context` (registered for shutdown at `server/server.go:156-159`) and runs in a goroutine tracked by `backgroundRunnerWG`.
