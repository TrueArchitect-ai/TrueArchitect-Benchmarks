**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at line 152); protection is the dial-time reserved-IP check `safeDialContext`/`isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`, with an admission-time check in `webhook.ValidateURL` — `internal/webhook/validate.go:62`.**

The delivery path in detail:

- API handlers don't send the request themselves. `dispatchMemoRelatedWebhook` and `DispatchMemoCommentCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go` build the payload per registered hook and call `webhook.PostAsync` (lines 43 and 71), which only enqueues onto a buffered channel (`asyncPostQueue`, capacity 128) and drops the event with a warning if the queue is full.
- Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, so `Post` is where marshalling, optional HMAC-SHA256 signing (Standard Webhooks `webhook-id`/`webhook-timestamp`/`webhook-signature` headers), the outbound POST, and response handling all happen.

The SSRF protection has two layers:

- The enforcing layer is at the transport level: `safeClient` is built with a custom `DialContext: safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` resolves the hostname itself and refuses to dial if *any* resolved address is in a reserved range. Because this runs at dial time rather than at registration time, it also defeats DNS rebinding, which a URL-validation-only approach would miss.
- The earlier, friendlier layer is `webhook.ValidateURL`, called when users create or update webhooks in `server/router/api/v1/user_service_webhooks.go` (lines 74, 161, 182). It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument` error.
- Both layers share `isReservedIP`, which tests against `reservedCIDRs` — loopback, RFC-1918, link-local (explicitly covering the cloud metadata address 169.254.169.254), and the IPv6 equivalents (`internal/webhook/validate.go:14-23`).

One caveat worth knowing: the whole protection can be turned off. `isReservedIP` returns `false` unconditionally when the package-level `webhook.AllowPrivateIPs` is set, which is bound to the `allow-private-webhooks` flag at `cmd/memos/main.go:49` for self-hosted setups that intentionally target LAN services.
