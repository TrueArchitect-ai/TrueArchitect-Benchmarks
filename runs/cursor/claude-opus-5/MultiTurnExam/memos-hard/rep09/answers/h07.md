The browser hits a plain REST route (not gRPC), and the avatar bytes come out of the `user` table row itself, because avatars are stored as base64 data URIs in `user.avatar_url` rather than as files.

Hops, in order:

- Route registration: `FileServerService.RegisterRoutes` → `GET /file/users/:identifier/avatar` — `server/router/fileserver/fileserver.go:124` (wired at `server/server.go:81-82`)
- URL the browser was given: `convertUserFromStore` rewrites `AvatarUrl` to `/file/{users/username}/avatar` — `server/router/api/v1/user_service_converters.go:36`, using `BuildUserName` — `server/router/api/v1/user_resource_name.go:13`
- Serving handler: `FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
- Optional auth gate (only on private instances): `FileServerService.getCurrentUser` → `auth.Authenticator.AuthenticateToUser` — `server/router/fileserver/fileserver.go:708-711`
- Lookup helper: `FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715`
- Store facade: `Store.GetUser` (checks `userCache` only when finding by ID, so a username lookup always falls through) — `store/user.go:148`
- Store list wrapper: `Store.ListUsers` (populates `userCache` with results) — `store/user.go:136`
- Driver interface: `Driver.ListUsers` — `store/driver.go:47`
- Data layer: `DB.ListUsers` builds `WHERE username = ?` and selects `avatar_url` from the `user` table — `store/db/sqlite/user.go:88`, filter at line 128, query at lines 151-165 (MySQL and Postgres equivalents in `store/db/mysql/user.go` and `store/db/postgres/user.go`)
- Decode and respond: `FileServerService.parseDataURI` decodes the `data:<mime>;base64,...` value — `server/router/fileserver/fileserver.go:737`, then the handler validates the MIME against `avatarAllowedTypes` (`fileserver.go:75`), sets security and cache headers, and writes the blob at `fileserver.go:209`

Two things worth noting: there is no filesystem or S3 hop at all for avatars — the image bytes live in the user row, so the "data layer" is the final stop. And access control differs from attachments: if `Profile.AllowAnonymous()` is true (an instance URL is configured), `serveUserAvatar` skips authentication entirely and any user's avatar is public; otherwise any authenticated viewer can fetch any user's avatar, with no per-user authorization check.
