**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` (all `MemoService` methods on `APIV1Service`); convergence function: `webhook.Post` — `internal/webhook/webhook.go:120` (the HTTP send is `safeClient.Do` at line 152).**

The six handlers and how each reaches the webhook layer:

| Handler | Path to dispatch |
| --- | --- |
| `CreateMemo` (`server/router/api/v1/memo_service.go:70`) | `DispatchMemoCreatedWebhook` at line 157 |
| `UpdateMemo` (`server/router/api/v1/memo_service.go:401`) | `dispatchMemoUpdatedSideEffects` at line 513 |
| `DeleteMemo` (`server/router/api/v1/memo_service.go:518`) | `DispatchMemoDeletedWebhook` at line 562 |
| `CreateMemoComment` (`server/router/api/v1/memo_service_comments.go:20`) | `DispatchMemoCommentCreatedWebhook` at line 119 |
| `SetMemoAttachments` (`server/router/api/v1/memo_attachment_service.go:16`) | `dispatchMemoUpdatedSideEffects` at line 48 |
| `SetMemoRelations` (`server/router/api/v1/memo_relation_service.go:16`) | `dispatchMemoUpdatedSideEffects` at line 48 |

Three of these share the intermediate helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook`. Note also that `CreateMemoComment` fires twice' worth of webhooks: it calls `s.CreateMemo` internally at line 56, so a comment produces both a `memos.memo.created` and a `memos.memo.comment.created` delivery.

The convergence: all four `Dispatch*Webhook` entry points funnel into `dispatchMemoRelatedWebhook` or `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go`), which look up the target user's registered hooks via `s.Store.GetUserWebhooks` and call `webhook.PostAsync` (lines 43 and 71). `PostAsync` only enqueues onto a bounded channel; the four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) then call `webhook.Post`, which is the single function that marshals the payload, signs it, and performs the outbound POST to the user-configured URL. So `Post` is the sole delivery choke point, and its SSRF guard (`safeDialContext`, `internal/webhook/webhook.go:59`) covers every one of these handler paths.

One adjacent path worth flagging since it also does outbound HTTP to a user-supplied URL, but does *not* converge on `webhook.Post`: `GetLinkMetadata` and `BatchGetLinkMetadata` (`proto/api/v1/memo_service.proto:137,141`) fetch arbitrary URLs through the separate `internal/httpgetter` package. If your interest is webhook delivery specifically, those are out of scope; if it's outbound requests generally, they're a second, independently-guarded path.
