Visibility is enforced in eleven distinct places across five surfaces. Two are query-scoping (restrict what the DB returns), the rest are per-memo permission checks.

**gRPC/Connect API (`server/router/api/v1`)**

- `checkMemoReadAccess` (shared read gate for `GetMemo`, its parent memo, and `ListMemoComments`) — `server/router/api/v1/memo_service.go:39`, called at `:356`, `:367`, and `server/router/api/v1/memo_service_comments.go:148`
- `ListMemos` query scoping (anonymous → PUBLIC only; authenticated → own memos plus PUBLIC/PROTECTED) — `server/router/api/v1/memo_service.go:218-227`
- `ListAllUserStats` and `GetUserStats` query scoping — `server/router/api/v1/user_service_stats.go:83-92` and `:217-221`
- `ListMemoReactions` — `server/router/api/v1/reaction_service.go:30-41`
- `UpsertMemoReaction` (and the delete path sharing it) — `server/router/api/v1/reaction_service.go:83`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-225`
- `checkAttachmentAccess` (visibility of the memo an attachment is linked to) — `server/router/api/v1/attachment_service.go:436-454`
- `CreateMemoComment` (may not comment on someone else's private memo) — `server/router/api/v1/memo_service_comments.go:41`

**Static file serving (`server/router/fileserver`)**

- `checkAttachmentPermission` — `server/router/fileserver/fileserver.go:677` (public + anonymous-allowed shortcut) and `:699` (private restricted to creator/admin), with a share-token bypass at `:684`

**Server-sent events (`server/router/api/v1`)**

- `SSEClient.canReceive`, applied per subscriber in `SSEHub.Broadcast` — `server/router/api/v1/sse_hub.go:134-144` (private events go only to the creator or an admin)

**Public feeds**

- RSS feeds hard-scope to public memos — `server/router/rss/rss.go:90` and `:141`
- Sitemap hard-scopes to public memos — `server/router/frontend/frontend.go:150`

**Notifications** (email/inbox content, same predicate duplicated in two packages)

- `canViewerAccessMemo` — `server/notification/email.go:313-316` and `server/router/api/v1/user_service_notifications.go:309-312`
- `canUserAccessMentionContext` (whether a mentioned user may be notified about a memo) — `server/router/api/v1/memo_mention_helpers.go:62-84`

Two notes on the boundaries of this list. The MCP surface is *not* a separate enforcement site: `NewMCPService` proxies tool calls in-process through the existing Echo API routes via `newAPIAdapter(echoServer)` (`server/router/mcp/service.go:26-52`), so `MemoService_ListMemos`/`MemoService_GetMemo` (`server/router/mcp/catalog.go:12-14`) inherit the API checks. And `GetMemoByShare` (`server/router/api/v1/memo_share_service.go:153-192`) deliberately bypasses visibility — a valid, unexpired share token grants access regardless of PRIVATE/PROTECTED status, with only archived/missing memos rejected.
