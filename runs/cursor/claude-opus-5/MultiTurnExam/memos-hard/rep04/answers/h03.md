**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

Notes:

- The abstraction package is deliberately thin: `internal/idp/idp.go` contains only the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any provider must return — there's no Go interface type, so the "abstraction" is this common user-info contract plus the `NewIdentityProvider`/`ExchangeToken`/`UserInfo` method shape that consumers call.
- OAuth2 is the only concrete implementation that ships. `internal/idp/oauth2/oauth2.go` defines `IdentityProvider` over a `storepb.OAuth2Config`, does the authorization-code exchange with optional PKCE `code_verifier` support (`internal/idp/oauth2/oauth2.go:47`), then fetches and field-maps claims from the configured userinfo endpoint into `idp.IdentityProviderUserInfo` (`internal/idp/oauth2/oauth2.go:83`).
- This matches the stored enum, which has exactly one real member: `IdentityProvider_OAUTH2 = 1` alongside `TYPE_UNSPECIFIED` (`proto/gen/store/idp.pb.go:27`–`28`). OIDC providers are handled through the same generic OAuth2 path rather than a separate package.
- The consumer is the SSO auth path, which imports both packages together at `server/router/api/v1/auth_service_sso.go:12`–`13` and passes the resulting `*idp.IdentityProviderUserInfo` into `resolveSSOUser` to link or provision the local user.
