**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`; convergence function: `webhook.PostAsync` — `internal/webhook/webhook.go:184` (which hands off to the actual deliverer `webhook.Post` at `internal/webhook/webhook.go:120`).**

The six handler paths, all in `server/router/api/v1`:

| Handler | Definition | Dispatch site |
|---|---|---|
| `CreateMemo` | `memo_service.go:70` | `memo_service.go:157` → `DispatchMemoCreatedWebhook` |
| `UpdateMemo` | `memo_service.go:401` | `memo_service.go:513` → `dispatchMemoUpdatedSideEffects` |
| `DeleteMemo` | `memo_service.go:518` | `memo_service.go:562` → `DispatchMemoDeletedWebhook` |
| `CreateMemoComment` | `memo_service_comments.go:20` | `memo_service_comments.go:119` → `DispatchMemoCommentCreatedWebhook` |
| `SetMemoAttachments` | `memo_attachment_service.go:16` | `memo_attachment_service.go:48` → `dispatchMemoUpdatedSideEffects` |
| `SetMemoRelations` | `memo_relation_service.go:16` | `memo_relation_service.go:48` → `dispatchMemoUpdatedSideEffects` |

The last three of those go through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` and logs failures rather than failing the RPC — so `SetMemoAttachments` and `SetMemoRelations` fire a `memos.memo.updated` webhook even though they aren't the obvious "update" RPC.

Every one of the four `Dispatch*Webhook` wrappers (`server/router/api/v1/memo_service_webhooks.go:15`–`74`) loads the memo owner's configured hooks via `s.Store.GetUserWebhooks`, copies `hook.Url` and `hook.SigningSecret` into the payload, and calls `webhook.PostAsync` (`memo_service_webhooks.go:43` and `:71`). That's the single convergence point: `PostAsync` drops the payload onto a bounded 128-entry channel, and four worker goroutines started in the package `init()` (`internal/webhook/webhook.go:42`–`55`) pull from it and invoke `Post`, where the request is signed and executed against the user-supplied URL through the SSRF-guarded `safeClient`.
