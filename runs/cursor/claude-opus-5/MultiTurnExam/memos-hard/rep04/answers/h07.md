Route: `GET /file/users/:identifier/avatar`. The URL the browser uses is minted server-side — `convertUserToProto` rewrites a base64 avatar into `/file/{user.Name}/avatar` instead of inlining the data (`server/router/api/v1/user_service_converters.go:36`).

Two things worth noting on this path. The avatar is not a file on disk or in object storage: it's stored inline as a base64 `data:` URI in the `user.avatar_url` column, which is why the last hop is a regex parse rather than a blob fetch. And the response is gated twice — `getUserByUsername` is looked up by username, then the decoded MIME type must be in `avatarAllowedTypes` (`server/router/fileserver/fileserver.go:75`) or the request is rejected with 400. The driver hop shown is SQLite; `store/db/postgres/user.go` and `store/db/mysql/user.go` implement the same interface method for the other dialects. The route is registered during startup at `server/server.go:81`–`82`, ahead of the gRPC gateway.
