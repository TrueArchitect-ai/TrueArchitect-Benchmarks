**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, which delegates to `markdown.Service.ExtractAll` (`internal/markdown/markdown.go:356`); triggers: `CreateMemo` (`server/router/api/v1/memo_service.go:108`), `UpdateMemo` but only when `content` is in the update mask (`server/router/api/v1/memo_service.go:447`), and transitively `CreateMemoComment` (`server/router/api/v1/memo_service_comments.go:56`); extracted: `tags` plus the `Property` set — `title` (first H1), `has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`.**

How it works:

- `RebuildMemoPayload` initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))` for a single-pass parse, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`server/runner/memopayload/runner.go:74`–`88`). It deliberately does *not* touch `Payload.Location`, which is user-supplied — `CreateMemo` sets that separately right after the rebuild (`server/router/api/v1/memo_service.go:111`–`113`).
- The extraction itself is one `gast.Walk` over the goldmark AST (`internal/markdown/markdown.go:356`–`422`): tag nodes become `Tags` (skipping tags nested inside links/images via `asMemoTagNode`, deduplicated case-preserving), a level-1 heading as the document's first block becomes `Property.Title`, and node kinds set `HasLink` (`KindLink`), `HasCode` (code block, fenced code block, or code span), `HasTaskList` (`KindTaskCheckBox`), and `HasIncompleteTasks` (an unchecked checkbox). Mentions are extracted in the same pass but are used for notifications, not stored in the payload.
- The stored shape is `MemoPayload` in `proto/store/memo.proto:7`, with the derived subset documented there as "the calculated properties from the memo content" (`proto/store/memo.proto:14`–`22`).
- Trigger specifics: on create, the rebuild runs before `Store.CreateMemo` so the payload is inserted with the row. On update, it's inside the `path == "content"` branch of the update-mask loop, and the recomputed payload is attached via `update.Payload = memo.Payload` (`server/router/api/v1/memo_service.go:451`) — so changing only visibility, pinned state, or timestamps will not recompute it. `CreateMemoComment` inherits the behavior because it calls `s.CreateMemo` internally.
- Consumption path (the "lists/previews" use): the converter copies `memo.Payload.Tags` to `memoMessage.Tags` and maps the property struct via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:48`–`49`, `:315`), and user tag statistics aggregate over `memo.Payload.Tags` (`server/router/api/v1/user_service_stats.go:138` and `:254`). Note the preview `Snippet` is a separate, non-persisted value computed per response by `getMemoContentSnippet` (`server/router/api/v1/memo_service_converter.go:76`).
- One caveat: there is a batch backfill that would recompute payloads for all memos, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), but nothing constructs that runner, so it never executes.
