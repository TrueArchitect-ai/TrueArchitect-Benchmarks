**Abstraction: `internal/idp` (`internal/idp/idp.go`); implementation: `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`).**

The abstraction is deliberately thin. `internal/idp/idp.go` defines only the `IdentityProviderUserInfo` struct — `Identifier`, `DisplayName`, `Email`, `AvatarURL` — which is the normalized shape every provider must produce. There is no Go interface; the "contract" is that return type plus the provider's config oneof.

OAuth 2.0 is the only concrete protocol that ships. `internal/idp/oauth2/oauth2.go` defines `IdentityProvider` with `NewIdentityProvider(config *storepb.OAuth2Config)` (line 27), `ExchangeToken` (line 47, which accepts a PKCE `codeVerifier`), and `UserInfo` (line 83) returning the shared `*idp.IdentityProviderUserInfo`.

The schema confirms it's the sole option: the `IdentityProviderConfig` oneof in `proto/store/idp.proto` has exactly one member, `oauth2_config` (see the generated `IdentityProviderConfig_Oauth2Config` in `proto/gen/store/idp.pb.go:158-218`). Correspondingly, the SSO login path in `server/router/api/v1/auth_service_sso.go:121` switches on the provider config and only ever constructs `oauth2.NewIdentityProvider(...)`.
