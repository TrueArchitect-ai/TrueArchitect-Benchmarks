**Premise correction: there is no GraphQL in this repository. Searching all Go, TypeScript, JSON, and module files for "graphql" returns zero hits, and there are no `.graphql` or `.gql` schema files anywhere. No schema, resolvers, or GraphQL server exist.**

**Actual API surface: Protocol Buffers / gRPC, exposed over HTTP through a gRPC-Gateway and Connect handlers, plus a few hand-written REST-ish routes.**

The schema lives in `proto/api/v1/`, one `.proto` file per service: `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `ai_service.proto`, and shared types in `common.proto`. Storage-layer messages live separately in `proto/store/`. Generated Go code (including gateway and Connect bindings) is in `proto/gen/`.

Everything is assembled in `NewServer` (`server/server.go:44-98`):

- The gRPC-Gateway and Connect handlers are registered by `apiV1Service.RegisterGateway(ctx, echoServer)` at `server/server.go:85`; the implementation is `server/router/api/v1/v1.go:65`, with the Connect service wiring in `server/router/api/v1/connect_services.go`. Handler methods are ordinary Go methods on `APIV1Service` that satisfy the generated service interfaces.
- Non-gRPC HTTP routes exist alongside it: the file server at `/file/...` (`server/router/fileserver/fileserver.go:121`), RSS feeds (`server/router/rss/rss.go:67`), a `/healthz` endpoint (`server/server.go:65`), the frontend static server (line 71), and an MCP endpoint (`server/router/mcp/service.go:108`).

So the closest analogue to "where the public API is defined" is the `.proto` files in `proto/api/v1/`, which are the single source of truth for request/response shapes and method names.
