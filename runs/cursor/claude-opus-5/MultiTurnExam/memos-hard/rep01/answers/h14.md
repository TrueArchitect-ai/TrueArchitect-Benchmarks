`ExtractAll` does a single goldmark AST walk (deliberately, per its comment, to avoid multiple parses). During the walk it collects tag nodes and mention nodes, then sets properties by node kind: `KindLink` sets `HasLink` (line 393), code blocks/spans set `HasCode` (line 396), and a `TaskCheckBox` sets `HasTaskList` plus `HasIncompleteTasks` when the box is unchecked (lines 399-405). Separately, if the document's first block-level child is an H1 heading, its text becomes `Property.Title` (lines 384-388). Tags are deduplicated with case preserved (line 418).

Note that `ExtractAll` also returns `Mentions`, but `RebuildMemoPayload` doesn't persist those — mentions are consumed live by `server/router/api/v1/memo_mention_helpers.go:32` for notifications.

**The stored shape** is `MemoPayload` in `proto/store/memo.proto:7-29`: `property`, `location`, and `tags`. The nested `Property` message is documented there as "the calculated properties from the memo content" and holds exactly the five fields listed above. `location` is the one payload field that is user-set rather than derived — `memo_service.go:111-113` assigns it from the request after the rebuild.

**The triggers.** Only two call sites invoke the rebuild in production. On create, `memo_service.go:108` runs it after the content-length check and before `Store.CreateMemo`. On update, it runs only inside the `if path == "content"` branch at `memo_service.go:447`, and the refreshed payload is attached to the update via `update.Payload = memo.Payload` — so changing a memo's visibility, pinned state, or attachments does not recompute metadata, which is correct since none of those affect content-derived values.

`CreateMemoComment` is a third trigger by delegation rather than a separate code path: it calls `s.CreateMemo(...)` at `memo_service_comments.go:56` to persist the comment memo, so the comment's payload is computed through the same route.

A fourth, dormant trigger exists: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) would rebuild the payload of every memo in batches, but nothing ever constructs that runner, so it never executes.

**How it's used for lists and previews.** The stored tags are surfaced in API responses at `server/router/api/v1/memo_service_converter.go:48` (`memoMessage.Tags = memo.Payload.Tags`) and aggregated for user tag statistics at `user_service_stats.go:138` and `:254`. Snippets, by contrast, are not part of this payload — `GenerateSnippet` (`internal/markdown/markdown.go:264`) is computed on demand rather than persisted.
