The browser doesn't fetch a stored image file — the avatar is a base64 data URI kept in the `user` row, decoded at serve time. Here is the chain:

h07.
`GET /file/users/:identifier/avatar` (route registration) — `server/router/fileserver/fileserver.go:124`
`FileServerService.serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
`FileServerService.getUserByUsername` — `server/router/fileserver/fileserver.go:715`
`Store.GetUser` — `store/user.go:148`
`Store.ListUsers` — `store/user.go:136`
`Driver.ListUsers` (interface dispatch) — `store/driver.go`
`(*DB).ListUsers` (SQL `SELECT ... avatar_url ... FROM user`) — `store/db/sqlite/user.go:88` (mirrored in `store/db/postgres/user.go` and `store/db/mysql/user.go`)

Notes on the hops:

The route is mounted on the `/file` group and wired into startup at `server/server.go:81-82`, where `NewFileServerService` is constructed and `RegisterRoutes` is called.

Before any lookup, `serveUserAvatar` applies an access gate: if `s.Profile.AllowAnonymous()` is false (a private instance with no `InstanceURL`), it resolves the caller via `getCurrentUser` and returns 401 if there's no valid session, access token, or PAT (lines 173-181). On a public instance, anyone may fetch any user's avatar.

`getUserByUsername` is a one-line wrapper that calls `Store.GetUser` with `FindUser{Username: &identifier}`. Worth noting for the caching hop: `Store.GetUser` only consults `userCache` when the lookup is by `ID` (line 149), so the avatar path — which looks up by username — always falls through to `ListUsers` and hits the database, though it does populate the cache on the way back (line 167).

The image bytes themselves never come from disk or S3. `user.AvatarURL` holds a `data:` URI, which `parseDataURI` (`server/router/fileserver/fileserver.go:737`) splits into MIME type and decoded bytes via `dataURIRegex`. The type is then checked against `avatarAllowedTypes` (line 75, enforced at line 201) and the bytes are written with `c.Blob` plus security headers and a cache-control header (lines 205-209).

For context on why the browser requests this URL at all: `server/router/api/v1/user_service_converters.go:32-38` rewrites a user's avatar field in API responses to the path `/file/{user.Name}/avatar` when the stored value is base64, rather than inlining the raw image data.
