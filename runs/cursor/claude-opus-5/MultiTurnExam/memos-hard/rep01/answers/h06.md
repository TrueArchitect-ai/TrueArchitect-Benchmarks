**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`. Convergence function: `webhook.Post` — `internal/webhook/webhook.go:120`.**

The six RPC handlers and how each reaches a webhook:

| Handler | Path |
|---|---|
| `CreateMemo` (`server/router/api/v1/memo_service.go:70`) | calls `DispatchMemoCreatedWebhook` at line 157 |
| `UpdateMemo` (`memo_service.go:401`) | calls `dispatchMemoUpdatedSideEffects` at line 513 |
| `DeleteMemo` (`memo_service.go:518`) | calls `DispatchMemoDeletedWebhook` at line 562 |
| `CreateMemoComment` (`memo_service_comments.go:20`) | calls `DispatchMemoCommentCreatedWebhook` at line 119 |
| `SetMemoAttachments` (`memo_attachment_service.go:16`) | calls `dispatchMemoUpdatedSideEffects` at line 48 |
| `SetMemoRelations` (`memo_relation_service.go:16`) | calls `dispatchMemoUpdatedSideEffects` at line 48 |

The last three memo-mutating handlers share a helper: `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`) calls `DispatchMemoUpdatedWebhook` at line 67, so editing a memo's attachments or relations fires a webhook just as editing its content does.

Those dispatchers then funnel through `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator, loads that user's configured webhooks via `Store.GetUserWebhooks`, and calls `webhook.PostAsync` per hook (line 71). The comment case is the one exception to that helper — `DispatchMemoCommentCreatedWebhook` (line 30) looks up the *related memo owner's* webhooks instead of the comment author's, then calls `PostAsync` at line 43.

Why `webhook.Post` is the convergence point rather than `PostAsync`: `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded channel. The four worker goroutines started in `init` (lines 42-55) drain that queue and call `Post`, which is where the request is built, optionally HMAC-signed, and actually sent via `safeClient.Do` at line 152. Every handler above ends there.

The URL is user-supplied — it comes from the user's webhook settings, managed by `server/router/api/v1/user_service_webhooks.go`, which is why `webhook.ValidateURL` gates it on save and `safeDialContext` re-checks the resolved IP at dial time.
