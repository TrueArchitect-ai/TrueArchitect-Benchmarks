The three mutation handlers in the middle group are worth calling out because their route is indirect: each calls the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), whose first action is `DispatchMemoUpdatedWebhook` before it broadcasts the SSE event. So setting attachments or relations on a memo fires an outbound `memos.memo.updated` webhook just like an ordinary edit does.

Convergence happens in two stages. The four memo-lifecycle events funnel through `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which resolves the creator, loads their webhooks, and fills in `payload.URL`/`payload.SigningSecret` per hook — but the comment-created path does *not* go through that helper; `DispatchMemoCommentCreatedWebhook` (line 30) loads the related memo owner's webhooks and dispatches on its own. The single point where every path meets is therefore one level lower:

```43:43:/bench/repo/server/router/api/v1/memo_service_webhooks.go
		webhook.PostAsync(payload)
```

and


`PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a 128-slot buffered channel, dropping with a warning if full; four worker goroutines started in `init` (lines 42-55) then call `Post` (line 120), which signs the body and issues the request via `safeClient.Do` at line 152. If you define "delivery" as the syscall-level send, `Post` is the sole sender; if you define convergence as the last shared call the handlers themselves make, it is `PostAsync`.

Two things I ruled out. There is no "test webhook" RPC — `user_service_webhooks.go` only lists, creates, updates, deletes, and reveals the signing secret, and the create/update handlers merely validate the URL (`webhook.ValidateURL` at lines 74, 161, 182) rather than pinging it. Separately, `memo_service.go:28` aliases `httpgetter.GetHTMLMeta` for link-preview fetching, which is outbound HTTP to a URL supplied in the request rather than a stored user-configured endpoint, so it is a different mechanism and does not pass through `webhook.Post`.
