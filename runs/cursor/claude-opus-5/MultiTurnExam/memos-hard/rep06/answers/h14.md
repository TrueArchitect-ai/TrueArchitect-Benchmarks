**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*service).ExtractAll` — `internal/markdown/markdown.go:356`; triggers: memo creation and content-changing updates (comments inherit creation); extracted: tags plus five derived properties (title, hasLink, hasCode, hasTaskList, hasIncompleteTasks)**

The derived metadata is the memo's stored `payload`, persisted alongside the content as protojson in the `memo` row. It's computed by:

```74:88:/bench/repo/server/runner/memopayload/runner.go
func RebuildMemoPayload(_ context.Context, memo *store.Memo, markdownService markdown.Service) error {
	if memo.Payload == nil {
		memo.Payload = &storepb.MemoPayload{}
	}

	// Use goldmark service to extract all metadata in a single pass (more efficient)
	data, err := markdownService.ExtractAll([]byte(memo.Content))
	if err != nil {
		return errors.Wrap(err, "failed to extract markdown metadata")
	}

	memo.Payload.Tags = data.Tags
	memo.Payload.Property = data.Property
	return nil
}
```

Note it assigns only `Tags` and `Property`, leaving other payload fields (such as `Location`) untouched — which is why `CreateMemo` sets the location *after* calling it (`server/router/api/v1/memo_service.go:111-113`).

Triggers, all in the API layer:

- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the `if path == "content"` branch of the update-mask loop. Changing visibility, pinned state, or other fields does not recompute the payload, which is correct since nothing else affects derived content metadata.
- `CreateMemoComment` — indirectly, since it delegates to `s.CreateMemo` at `server/router/api/v1/memo_service_comments.go:56`.

There is also a batch entry point, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`), which would rebuild every memo's payload in pages of 100 — but nothing constructs that `Runner`, so it never executes.

What `ExtractAll` extracts in its single AST walk (`internal/markdown/markdown.go:356-421`):

- **Tags** — every custom tag node, deduplicated via `uniquePreserveCase` while keeping original casing. Mentions are collected too (lowercased), but `RebuildMemoPayload` discards them; they're consumed separately by the mention-notification path.
- **Title** — the text of an H1 heading only when it is the document's first block-level child (lines 383-389).
- **HasLink** — any `KindLink` node.
- **HasCode** — indented code blocks, fenced code blocks, or inline code spans.
- **HasTaskList** — any task checkbox.
- **HasIncompleteTasks** — set when a checkbox is unchecked (lines 399-404).

These five live on `storepb.MemoPayload_Property` (`proto/gen/store/memo.pb.go:85-92`).

One distinction worth drawing, since previews were mentioned: the short text snippet used in lists and notifications is *not* part of this stored payload. It's generated per-request by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-90`), called from the memo converter (`memo_service_converter.go:76`, `:225`, `:248`), relation service, and notifications. So tags/properties are computed on write and stored; snippets are computed on read and not stored.
