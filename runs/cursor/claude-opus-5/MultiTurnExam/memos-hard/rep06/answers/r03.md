**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never used by the running server — so there is no scheduled time to report.**

The premise is half-true in a way that makes it worth being precise about. A fully implemented cron scheduler *does* exist at `internal/scheduler` (`scheduler.go`, `parser.go`, `job.go`, `middleware.go`, plus a README), supporting 5- and 6-field cron expressions, timezones, and middleware. But nothing in the production code imports it. Searching for `internal/scheduler` across all Go files returns only two hits, both inside the package's own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No job of any kind is registered anywhere outside those tests, so `Scheduler.Register` and `Start` never run in the server.

The likely source of the premise is the package documentation, which uses a daily cleanup as its illustrative example:

```14:21:/bench/repo/internal/scheduler/doc.go
//	s.Register(&scheduler.Job{
//		Name:     "daily-cleanup",
//		Schedule: "0 2 * * *", // 2 AM daily
//		Handler: func(ctx context.Context) error {
//			// Your cleanup logic here
//			return nil
//		},
//	})
```

That `"0 2 * * *"` (2 AM) is sample code in a doc comment with an empty handler, not a registered job. Similarly, `"0 0 * * *"` and `"0 9 * * *"` appear only as parser test fixtures in `internal/scheduler/parser_test.go`.

What the server actually schedules is a single background task, and it is not cron-based and not a cleanup: the S3 presign runner started at `server/server.go:162-171`, which uses a plain `time.Ticker` at 12-hour intervals (`server/runner/s3presign/runner.go:27`) to refresh expiring presigned attachment URLs.

The only other recurring background work is in-process cache eviction — `cleanupLoop` on a 5-minute ticker (`store/cache/cache.go:200-201`, interval from `store/store.go:42`). That touches only in-memory cache entries, not the database. Database cleanup happens synchronously in request handlers instead: for example, cascading deletes inside the delete-user transaction (`store/db/sqlite/user_delete.go:92-127`) and attachment cleanup during memo deletion (`server/router/api/v1/memo_service.go:579`).
