**1st: `store.User` (~7 packages, 6 excluding test-only packages); 2nd: `store.Memo` (~6 packages, 5 excluding test-only)**

`store.User` (`store/user.go:29`) is referenced from these packages outside the data layer: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, and `server/router/rss`. That is 21 files if you also count test files.

`store.Memo` (`store/memo.go:35`) reaches `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, and `server/runner/memopayload` — 15 files with tests included.

The rest fall off quickly: `store.Attachment` (`store/attachment.go:16`) at 4 packages, then `store.Inbox`, `store.MemoRelation`, and `store.MemoShare` at 3 each, `store.Reaction` and `store.UserIdentity` at 2.

What separates first from second is that `store.User` is the only entity that crosses into the authentication layer — `server/auth` resolves tokens to a `*store.User` — while `store.Memo` picks up `server/runner/memopayload` instead. Both appear in the API, notification, and RSS layers.

Two caveats on the counts. Depending on whether you count test-only packages, the numbers shift: `server/router/api/v1/test` contributes to both types, and `server/router/frontend`'s references live solely in `server/router/frontend/frontend_test.go`, so on a production-only basis User drops to 5 packages (`server/auth`, `server/notification`, `server/router/api/v1`, `server/router/fileserver`, `server/router/rss`) and Memo to 4. The ordering is unchanged either way.

Also, `store.IdentityProvider`, `store.InstanceSetting`, and `store.UserSetting` appear to have one external referencing package each, but that hit is `proto/gen/store`, whose generated files also declare `package store` — so those matches are self-references within the generated package rather than genuine outside consumers. Their true external fan-out is effectively zero for the bare entity type, since consumers use the protobuf variants instead.
