For the s3presign runner there are two call sites. `Server.startBackgroundRunners` calls `s3presignRunner.RunOnce(ctx)` synchronously at `server/server.go:163` so presigned URLs are refreshed immediately at boot, and the method is also called on each tick of the 12-hour ticker inside the runner's own `Run` loop at `server/runner/s3presign/runner.go:36`. Both are production paths.

The `memopayload` version is dead code. A repo-wide grep for `RunOnce` returns only the five lines above, none of which reference `memopayload`, and searching for `memopayload.NewRunner` or `memopayload.Runner` returns no hits at all — the `Runner` type is never even constructed. The package has no test file either (its directory contains only `runner.go`), so the method isn't exercised from tests.

Worth distinguishing, since it makes the package look live: `memopayload` *is* imported and used in production, but only for its package-level function `RebuildMemoPayload`, called from `server/router/api/v1/memo_service.go:108` (memo creation) and `:447` (memo update). That function is what `RunOnce` loops over at line 52, so the batch-rebuild-everything entry point is unused while the per-memo helper it wraps is on the hot path.
