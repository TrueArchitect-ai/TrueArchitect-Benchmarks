**Premise correction: neither. There is no message broker in this repository at all** — searching all Go files and `go.mod` for `nats`, `rabbitmq`, `amqp`, `kafka`, `pubsub`, `sqs`, and `streadway` returns zero matches. Consequently there is no queue declaration in the broker sense: no exchange, subject, stream, or topic is ever declared.

**Actual mechanism: an in-process buffered Go channel with a fixed pool of goroutine workers**, all inside `internal/webhook/webhook.go`.

The "queue" is a package-level channel with a capacity of 128, declared at `internal/webhook/webhook.go:39`:

```39:39:/bench/repo/internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The "consumers" are four goroutines started in the package's `init` function (lines 42-55). Each ranges over the channel and calls `Post` for every payload, logging a warning on failure. Because they are launched from `init`, they start when the package is first loaded rather than being wired into server startup — there is no registration site in `server/server.go` for them.

Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), called from the memo event dispatchers in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

Several properties follow from this being a plain channel rather than a broker, and they matter operationally:

- **Delivery is best-effort with silent-ish drops.** `PostAsync` uses a `select` with a `default` branch, so when all 128 slots are full the payload is discarded with a warning rather than blocking the request or being retried.
- **No persistence and no redelivery.** Anything still buffered is lost on process exit, and there is no acknowledgement, dead-letter path, or retry — a failed `Post` is only logged.
- **No cross-process fan-out.** The channel is local to the process, so in a multi-replica deployment each instance dispatches only the events it generated.
- **Concurrency is capped at 4 in-flight deliveries**, each bounded by the shared client's 30-second timeout (lines 27, 32-37).
