The evidence in detail:

- The factory is the sole constructor path:

```18:27:store/db/db.go
	switch profile.Driver {
	case "sqlite":
		driver, err = sqlite.NewDB(profile)
	case "mysql":
		driver, err = mysql.NewDB(profile)
	case "postgres":
		driver, err = postgres.NewDB(profile)
	default:
		return nil, errors.New("unknown db driver")
	}
```

- Grepping for the import path `usememos/memos/store/db/mysql` across all `.go` files yields a single hit, the factory's own import at `store/db/db.go:8`. Since `NewDB` and the `DB` type are only reachable via that import, no production code, command, test helper, or migration path outside `store/db/db.go` can construct it. Notably, even the integration tests go through the factory: `store/test/store.go` builds a `profile.Profile` with `Driver: "mysql"` (`store/test/store.go:88-101`) and lets `NewDBDriver` pick the driver, rather than calling `mysql.NewDB` itself.

- For contrast, SQLite *is* constructed directly outside the factory in two tests (`store/demo_seed_test.go:24` and `store/deployment_config_test.go:416` call `sqlite.NewDB(p)`), which confirms the search would have surfaced equivalent MySQL call sites had any existed.
