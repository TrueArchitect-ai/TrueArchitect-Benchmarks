The premise is incorrect: there is no per-user API rate-limiting middleware in this repository, so there is nothing registered and no request limits to report.

Evidence for the absence:

- A case-insensitive search across all Go files for `ratelimit`, `rate_limit`, "rate limit", `throttl`, `limiter`, and `golang.org/x/time/rate` produces exactly one hit, and it is an aspirational comment in package documentation rather than an implementation: `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a future consideration.
- `go.mod` contains no rate-limiting dependency (no `golang.org/x/time`, no `echo` rate-limiter package, nothing matching `rate`/`limit`/`throttl`).
- The full set of middleware registered on the Echo server is `middleware.Recover()` and the CORS middleware (`server/server.go:51-52`, with the CORS config at `server/cors.go:14`), plus static-file and SPA-fallback middleware for the frontend (`server/router/frontend/frontend.go:54`, `:59`). No limiter is in that chain. Request authorization happens in the gateway middleware and Connect interceptor set up in `RegisterGateway` (`server/router/api/v1/v1.go:65`), which authenticates but does not count or throttle requests.
- There is also no login-attempt throttling or account lockout; searching the auth code for "attempt", "lockout", "backoff", and "too many" only turns up comments and a result struct name (`server/router/api/v1/auth_service_session.go:277`, `server/auth/authenticator.go:126`).

What does exist, in case one of these is what you were thinking of — these are concurrency and size bounds, not per-user request rates:

- **Concurrency semaphores for expensive media work:** thumbnail generation is capped at 3 concurrent operations in the file server (`server/router/fileserver/fileserver.go:45-46`, `:116`) and at 3 in the API service, with image processing capped at 2 (`server/router/api/v1/v1.go:59-60`). These are global caps, not per-user.
- **Pagination cap:** list responses are clamped to `MaxPageSize = 1000` (`server/router/api/v1/common.go:17`).
- **Bounded webhook dispatch queue:** outbound webhooks go onto a 128-slot channel drained by 4 workers, and payloads are dropped when it's full (`internal/webhook/webhook.go:39-55`, `:184-196`).
- **SSE backpressure:** events for slow clients are dropped rather than blocking the hub (`server/router/api/v1/sse_hub.go:126-131`).
- **Content size limit:** memo content length is checked against an instance setting on create and update (`server/router/api/v1/memo_service.go:101-107`, `:442-449`).
