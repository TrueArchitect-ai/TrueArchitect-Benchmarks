The browser hits `GET /file/users/{username}/avatar`, which is served by the file server (not the gRPC API) and reaches the `user.avatar_url` column; the image bytes are stored inline as a base64 data URI in that column rather than as a file on disk or in object storage.

Since `userpb.Name` is `BuildUserName(user.Username)` (i.e. `users/{username}`), the emitted path is exactly `/file/users/{username}/avatar`, matching the registered route. If the stored value is an external URL instead, it's passed through and no server hop happens at all.

- **Handler.** `serveUserAvatar` first gates anonymous access: on a private instance (`!s.Profile.AllowAnonymous()`) it requires a session, access token, or PAT via `getCurrentUser`, returning 401 otherwise (`server/router/fileserver/fileserver.go:173-181`). There is no per-user authorization beyond that, so any permitted viewer can fetch any other user's avatar.

- **Lookup hop.** The `:identifier` path segment is treated as a username, wrapped into a `FindUser`:

- **Store hops.** `GetUser` consults `s.userCache` only when looking up by ID, so a username lookup always falls through to `ListUsers` (`store/user.go:148-168`), which delegates to `s.driver.ListUsers` and populates the cache on the way back (`store/user.go:136-146`).

- **Data layer.** The active driver builds the `WHERE username = ?` clause and selects `avatar_url` among the user columns (`store/db/sqlite/user.go:128-130`, `:150-165`); the MySQL and Postgres drivers have equivalent `ListUsers` implementations in `store/db/mysql/user.go` and `store/db/postgres/user.go`. The driver is chosen by the factory at `store/db/db.go:14`.

- **Response.** Back in the handler, `parseDataURI` splits the stored data URI into MIME type and decoded bytes, the type is checked against `avatarAllowedTypes` (`server/router/fileserver/fileserver.go:75`) to block XSS-capable formats, security and cache headers are set, and the bytes are written with `c.Blob` (`server/router/fileserver/fileserver.go:196-209`).

- **Wiring.** The file server itself is constructed and mounted during server setup at `server/server.go:81-82`.
