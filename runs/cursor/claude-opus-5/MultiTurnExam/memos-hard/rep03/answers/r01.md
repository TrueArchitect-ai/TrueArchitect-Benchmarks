There is no Redis anywhere in this repository — the premise doesn't hold. A case-insensitive search for "redis" across all files (Go sources, `go.mod`, `go.sum`, Docker/compose files, configs, docs) returns zero matches, so there is no Redis connection to configure and no external cache server involved.

**Actual mechanism: the cache layer is a process-local, in-memory cache implemented in `store/cache/cache.go`, and user entries use the default 10-minute TTL configured once in `store/store.go:40-45`.**

Details:

- **What the cache actually is.** `cache.Cache` is a thread-safe in-memory store built on `sync.Map` plus an atomic item counter, with per-entry expiration timestamps (`store/cache/cache.go:66-73`). It's created by `cache.New`, which spawns a background `cleanupLoop` goroutine (`store/cache/cache.go:76-85`, `:200-215`). Nothing is serialized or sent over a network; the data lives in the server process, so it is not shared across replicas.

- **Where it's "configured."** In code, not in any connection string or config file. `store.New` builds one `cache.Config` and hands the same values to three separate cache instances:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

These values are hardcoded — there is no flag, environment variable, or setting that overrides them. `cache.DefaultConfig()` (`store/cache/cache.go:57-64`) declares the identical defaults, though `store.New` specifies its own copy rather than calling it.

- **The TTL for user entries: 10 minutes.** All user writes go through `Set`, never `SetWithTTL` (a search for `SetWithTTL` outside the cache package itself returns no hits), and `Set` applies the configured default:

```92:95:store/cache/cache.go
// Set adds a value to the cache with the default TTL.
func (c *Cache) Set(ctx context.Context, key string, value any) {
	c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)
}
```

Call sites populating the user cache are `store/user.go:98`, `:122`, `:132`, `:143`, and `:167`, keyed by `userCacheKey(user.ID)` (`store/user.go:88`).

- **How expiry is realized.** Two ways: lazily on read, where `Get` deletes and reports a miss for an expired item (`store/cache/cache.go:135-144`), and proactively by the cleanup goroutine every 5 minutes (`store/cache/cache.go:218-250`). There's also a capacity bound — once the instance exceeds 1000 items, `cleanupOldest` drops roughly 20% of `MaxItems` (`store/cache/cache.go:117-119`, `:253-313`), so user entries can be evicted before their TTL expires.

- **Invalidation beyond TTL.** User deletion explicitly removes the entry (`store/user_delete.go:40`), and shutdown stops the cleanup goroutines via `Store.Close` (`store/store.go:74-76`). Note that lookups only consult the cache when finding by ID (`store/user.go:149-156`); username or email lookups always hit the database.
