The premise is incorrect on two counts: there is no nightly database-cleanup job anywhere in the codebase, and the cron scheduler that exists is never used by the running server — no production code imports it, so it has no registered jobs at all.

Evidence:

- **The scheduler is unwired.** `internal/scheduler` implements a full cron system (`internal/scheduler/scheduler.go`, with a five-field cron parser in `internal/scheduler/parser.go`, job types in `internal/scheduler/job.go`, and middleware in `internal/scheduler/middleware.go`), but a search for the import path `github.com/usememos/memos/internal/scheduler` returns only two hits, both inside the package's own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. Neither `cmd/`, `server/`, nor `store/` references it, so `scheduler.New`, `Register`, and `Start` never run in a live server.

- **No cleanup job exists to schedule.** The only cron-looking strings in non-test Go code are illustrative comments, not registrations: `"0 * * * *"` / `"0 0 * * *"` as examples in `internal/scheduler/job.go:21`, and `Schedule: "0 2 * * *", // 2 AM daily` in the package doc example at `internal/scheduler/doc.go:16`. That 2 AM value is documentation for how to write a job, not a configured job. Searching for cleanup/nightly/cron terms across `server/`, `cmd/`, and `store/` turns up only unrelated things: inline resource cleanup during memo and user deletion (`server/router/api/v1/memo_service.go:579`, `server/router/api/v1/user_service.go:421-450`), best-effort SSO rollback (`server/router/api/v1/auth_service_sso.go:76`), and test teardown helpers (`server/router/api/v1/test/test_helper.go:65`).

What actually runs on a schedule in the server, none of it cron-driven and none of it database cleanup:

- **The S3 presign runner**, the only background runner started at boot: one immediate pass plus a `time.Ticker` every 12 hours, refreshing presigned attachment URLs (`server/runner/s3presign/runner.go:27-41`, wired at `server/server.go:161-171`).
- **In-memory cache eviction**, a per-cache goroutine ticking every 5 minutes to drop expired entries (`store/cache/cache.go:60`, `:200-215`). This evicts process memory, not database rows.

There is also a second unused runner, `memopayload.Runner`, whose `RunOnce` would rebuild all memo payloads in batches, but its constructor has no call sites (`server/runner/memopayload/runner.go:19`).
