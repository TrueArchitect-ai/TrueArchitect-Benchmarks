How it fits together:

- `Post` marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 signature headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), then sends via a package-level `safeClient` with a 30-second timeout. Memo create/update events reach it through `webhook.PostAsync`, which enqueues onto a bounded 128-slot channel drained by four worker goroutines (`internal/webhook/webhook.go:39-55`, `184-196`); the callers are in `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

- The protection is enforced at connection time rather than only at URL-validation time, which is what makes it resistant to DNS rebinding:

```29:37:internal/webhook/webhook.go
	// safeClient is the shared HTTP client used for all webhook dispatches.
	// Its Transport guards against SSRF by blocking connections to reserved/private
	// IP addresses at dial time, which also defeats DNS rebinding attacks.
	safeClient = &http.Client{
		Timeout: timeout,
		Transport: &http.Transport{
			DialContext: safeDialContext,
		},
	}
```

`safeDialContext` resolves the host itself and refuses the dial if any resolved address falls in a reserved range (`internal/webhook/webhook.go:59-77`). The blocked ranges cover IPv4 loopback, all three RFC-1918 blocks, link-local including the cloud metadata endpoint `169.254.169.254`, plus IPv6 loopback, unique-local, and link-local (`internal/webhook/validate.go:14-23`).

- There is a second, earlier layer: `webhook.ValidateURL` rejects non-http(s) schemes and reserved-IP targets when a user registers or updates a webhook (`internal/webhook/validate.go:62`), called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`.

- Both layers can be turned off deliberately for self-hosted setups via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`), which short-circuits `isReservedIP` and is set from the `allow-private-webhooks` config option at `cmd/memos/main.go:49`.
