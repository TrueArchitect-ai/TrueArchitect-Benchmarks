There is no GraphQL in this repository — the premise doesn't hold. Searching every file (excluding `.git`) for `graphql`, `gqlgen`, `apollo`, and `.graphql`/`.gql` extensions returns no GraphQL artifacts; the only matches are unrelated uses of the word "resolver" (Go's DNS `net.DefaultResolver` at `internal/webhook/webhook.go:65` and `internal/httpgetter/html_meta.go:23`, plus design-doc prose). There is no schema file, no schema-first codegen config, and no GraphQL dependency in `go.mod`.

**Actual API surface: a Protobuf/gRPC service definition set under `proto/api/v1/`, exposed over HTTP three ways — a REST-style JSON gateway at `/api/v1/*` (grpc-gateway, driven by `google.api.http` annotations in the `.proto` files), Connect RPC at `/memos.api.v1.*`, and an SSE endpoint — all registered in `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`).**

Where the schema actually lives:

- Eight services are declared in `proto/api/v1/`: `AIService` (`ai_service.proto:11`), `AttachmentService` (`attachment_service.proto:15`), `AuthService` (`auth_service.proto:13`), `IdentityProviderService` (`idp_service.proto:14`), `InstanceService` (`instance_service.proto:17`), `MemoService` (`memo_service.proto:17`), `ShortcutService` (`shortcut_service.proto:14`), and `UserService` (`user_service.proto:17`). Persistence-side message types live separately in `proto/store/`.

- REST paths are defined by annotations on each RPC rather than by a separate routing table:

```21:36:proto/api/v1/memo_service.proto
  rpc CreateMemo(CreateMemoRequest) returns (Memo) {
    option (google.api.http) = {
      post: "/api/v1/memos"
      body: "memo"
    };
    option (google.api.method_signature) = "memo";
  }
  // ListMemos lists memos with pagination and filter.
  rpc ListMemos(ListMemosRequest) returns (ListMemosResponse) {
    option (google.api.http) = {get: "/api/v1/memos"};
    option (google.api.method_signature) = "";
  }
  // GetMemo gets a memo.
  rpc GetMemo(GetMemoRequest) returns (Memo) {
    option (google.api.http) = {get: "/api/v1/{name=memos/*}"};
    option (google.api.method_signature) = "name";
  }
```

The style is AIP-flavored resource naming (`memos/{uid}`, `users/{username}`) rather than GraphQL queries.

- Generated Go code sits in `proto/gen/api/v1/` (gateway stubs in `*.pb.gw.go`, gRPC stubs in `*_grpc.pb.go`, Connect handlers in `proto/gen/api/v1/apiv1connect/`).

- Serving is wired up in one place: the gateway mux gets each service registered (`server/router/api/v1/v1.go:102-121`) and is mounted on `/api/v1/*` and `/file/*` (`server/router/api/v1/v1.go:128-130`), while the Connect mux handles `/memos.api.v1.*` for browser clients, replacing grpc-web (`server/router/api/v1/v1.go:139-144`). SSE routes are registered alongside at `server/router/api/v1/v1.go:125`.

Two smaller HTTP surfaces exist outside the proto API: the file server for attachments and avatars (`server/router/fileserver/fileserver.go:121-125`) and RSS feeds (`server/router/rss/rss.go:67`). There is also an MCP endpoint that re-exposes a subset of the same RPCs (`server/router/mcp/service.go:108`, catalog at `server/router/mcp/catalog.go`).
