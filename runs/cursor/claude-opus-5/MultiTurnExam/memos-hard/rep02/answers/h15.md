**h15.**

Visibility is enforced in twelve distinct places across five surfaces — the gRPC/Connect API, the raw HTTP file server, the RSS and frontend routers, the SSE push hub, and the email notifier.

Notes on the shapes these take, since they aren't all the same kind of check:

- **Point checks on a fetched memo.** `checkMemoReadAccess` is the canonical one: public passes, non-public requires a user, private requires being the creator (it also gates archived memos to their creator). The reaction, memo-attachment, and attachment variants repeat that logic nearly verbatim rather than calling the shared helper — the notable difference being that they extend the private case with `!isSuperUser(user)`, so admins can read private memos there but `checkMemoReadAccess` has no admin bypass.

- **Query-level scoping** rather than per-row rejection. `ListMemos` either pins `VisibilityList` to `PUBLIC` (anonymous), or appends the CEL filter `creator_id == N || visibility in ["PUBLIC", "PROTECTED"]`, or narrows to `PUBLIC, PROTECTED` when browsing another user's memos. The two relation sites push an equivalent `memoFilter` string into the store query so related memos the viewer can't see are dropped.

- **Non-API HTTP surfaces.** `checkAttachmentPermission` is the most involved: public + anonymous-allowed instance passes, then a `share_token` query-param fallback validates a non-expired `MemoShare` bound to that memo, then falls back to requiring an authenticated user and rejects private memos for non-creator non-admins. RSS and the sitemap enforce structurally, by only ever asking the store for `store.Public` memos.

- **Push and notification paths**, which are easy to miss because no request is being authorized. `SSEClient.canReceive` filters broadcasts so a private-memo event only reaches its creator or an admin, and it fails closed on an unrecognized visibility. `canViewerAccessMemo` decides whether a comment/mention email may be sent: admin always, private only to the creator, protected to any signed-in user.

One deliberate bypass worth flagging: `GetMemoByShare` (`server/router/api/v1/memo_share_service.go:153`) does not consult visibility at all — it authorizes on a valid non-expired share token via `getActiveMemoShare` (`:199`), which is the mechanism the file server's `share_token` branch mirrors.
