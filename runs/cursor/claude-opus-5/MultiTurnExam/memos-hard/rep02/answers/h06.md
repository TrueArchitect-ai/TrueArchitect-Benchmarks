**h06.**

Six RPC handlers can trigger a webhook POST to a user-supplied URL, and every path funnels into `webhook.Post`.

**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`; convergence function: `webhook.Post` — `internal/webhook/webhook.go:120`**

The three `Dispatch*` entry points in `server/router/api/v1/memo_service_webhooks.go` all reduce to the same shape: look up the target user's configured hooks via `s.Store.GetUserWebhooks`, then enqueue one payload per hook. For memo create/update/delete that's `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo's creator and dispatches with activity type `memos.memo.created` / `.updated` / `.deleted`. For comments, `DispatchMemoCommentCreatedWebhook` (`memo_service_webhooks.go:30`) is the exception worth noting: it targets the *related memo owner's* webhooks rather than the commenter's, with activity type `memos.memo.comment.created`.

Note that the three attachment/relation/update handlers share a single fan-in helper before that:

```66:69:server/router/api/v1/memo_update_helpers.go
func (s *APIV1Service) dispatchMemoUpdatedSideEffects(ctx context.Context, memo *store.Memo, parentMemo *store.Memo, memoMessage *v1pb.Memo) {
	if err := s.DispatchMemoUpdatedWebhook(ctx, memoMessage); err != nil {
		slog.Warn("Failed to dispatch memo updated webhook", slog.Any("err", err))
	}
```

On convergence: the two call sites at `memo_service_webhooks.go:43` and `:71` both call `webhook.PostAsync`, but that function performs no I/O — it only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:184-196`). The four worker goroutines started in that package's `init` drain the queue and call `Post` (`internal/webhook/webhook.go:42-55`), which is where the request is built, signed, and sent via `safeClient.Do` at `internal/webhook/webhook.go:152`. So `Post` is the single function all delivery passes through, and `PostAsync` is the single enqueue point if you want the boundary on the handler side.

Two things that look like candidates but aren't: `CreateUserWebhook` and `UpdateUserWebhook` (`server/router/api/v1/user_service_webhooks.go:53`, `:106`) touch the user-configured URL, but only run `webhook.ValidateURL`, which does a DNS resolution and no HTTP request. There is also no "test webhook" RPC in this service.
