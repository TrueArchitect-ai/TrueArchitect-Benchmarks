**h02.**

Outbound webhook delivery happens in `webhook.Post`, and the SSRF guard is a custom `DialContext` on the shared HTTP client that rejects reserved/private IPs at dial time.

**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection: `safeDialContext` + `isReservedIP`/`reservedCIDRs` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:14-54`**

How it fits together:

- `Post` marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and sends via the package-level `safeClient` (30s timeout). Response reading is capped at 1 MiB.

- `PostAsync` (`internal/webhook/webhook.go:184`) doesn't do its own I/O; it enqueues onto a bounded 128-slot channel drained by 4 goroutines started in `init`, each of which calls `Post`. So all delivery funnels through `Post`.

- The protection is enforced at connection time rather than only at URL-validation time:

```32:37:internal/webhook/webhook.go
	safeClient = &http.Client{
		Timeout: timeout,
		Transport: &http.Transport{
			DialContext: safeDialContext,
		},
	}
```

`safeDialContext` resolves the hostname itself and refuses to dial if *any* returned address is reserved, which is what makes it resistant to DNS rebinding (a check done only at save time could pass validation and then resolve to `127.0.0.1` later).

- The blocked ranges are in `internal/webhook/validate.go:14-23`: IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (covering cloud IMDS at 169.254.169.254), plus IPv6 loopback, unique-local, and link-local.

There is a second, earlier layer: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-IP hostnames when a user creates or updates a webhook, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`.

Both layers share the `isReservedIP` helper, and both can be turned off by the `AllowPrivateIPs` escape hatch (`internal/webhook/validate.go:41`), set from the `allow-private-webhooks` config flag at `cmd/memos/main.go:49` for self-hosted setups targeting LAN services.
