**h14.**

The derived metadata is the memo's stored `payload` — tags plus a set of boolean content properties and an extracted title — computed by `RebuildMemoPayload` on every content write.

**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, which delegates the actual parsing to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`; Triggers: `CreateMemo` (`server/router/api/v1/memo_service.go:108`), `CreateMemoComment` (via `CreateMemo` at `server/router/api/v1/memo_service_comments.go:56`), and `UpdateMemo` only when the update mask contains `content` (`server/router/api/v1/memo_service.go:436-451`); Extracted: deduplicated `tags`, and `Property{has_link, has_task_list, has_code, has_incomplete_tasks, title}`**

The computation:

```74:88:server/runner/memopayload/runner.go
func RebuildMemoPayload(_ context.Context, memo *store.Memo, markdownService markdown.Service) error {
	if memo.Payload == nil {
		memo.Payload = &storepb.MemoPayload{}
	}

	// Use goldmark service to extract all metadata in a single pass (more efficient)
	data, err := markdownService.ExtractAll([]byte(memo.Content))
	if err != nil {
		return errors.Wrap(err, "failed to extract markdown metadata")
	}

	memo.Payload.Tags = data.Tags
	memo.Payload.Property = data.Property
	return nil
}
```

Note it assigns only `Tags` and `Property`, deliberately leaving `Payload.Location` untouched — location is the user-set part of the same payload message (`proto/store/memo.proto:24-28`), written separately at `memo_service.go:112` on create and `memo_service.go:482-484` on update.

`ExtractAll` does one goldmark AST walk and sets, per node kind (`internal/markdown/markdown.go:390-407`):

| Field | Condition |
| --- | --- |
| `tags` | each `#tag` node, then deduplicated preserving original case via `uniquePreserveCase` |
| `has_link` | any `KindLink` node |
| `has_code` | any `KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan` |
| `has_task_list` | any `KindTaskCheckBox` |
| `has_incomplete_tasks` | a task checkbox with `IsChecked == false` |
| `title` | text of the first block-level child if it's an H1 heading |

The proto definition of these five is at `proto/store/memo.proto:15-22`, commented "The calculated properties from the memo content."

On triggers, two details matter:

- **Update is mask-gated.** Recomputation happens inside the `if path == "content"` branch, so changing visibility, pin state, location, or attachments does *not* re-derive tags/properties. That's correct here since none of those change the content, but it means a payload can only drift if content is mutated outside this handler.
- **Comments go through the same path.** `CreateMemoComment` doesn't compute anything itself; it calls `s.CreateMemo` with suppressed SSE/mention notifications (`memo_service_comments.go:56`), inheriting the rebuild.

There's also a dormant third trigger: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) walks all memos in batches of 100 and rebuilds each payload, but that runner is never constructed anywhere, so it doesn't execute.

Two related things that are *not* part of the stored payload: `ExtractAll` also returns `Mentions`, which `RebuildMemoPayload` discards — mentions are consumed separately for inbox notifications at `server/router/api/v1/memo_mention_helpers.go:32-42`. And the list/preview `snippet` is computed on read rather than stored, via `getMemoContentSnippet` → `MarkdownService.GenerateSnippet` at `server/router/api/v1/memo_service_converter.go:76` and `server/router/api/v1/memo_relation_service.go:154`. Reads surface the stored payload through `convertMemoFromStore` (`memo_service_converter.go:47-50`).
