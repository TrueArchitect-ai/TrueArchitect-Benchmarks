**Actual mechanism:** webhook delivery uses an in-process buffered Go channel with a fixed pool of goroutines, all inside `internal/webhook/webhook.go`.

The "queue" is a package-level channel with a capacity of 128:

```39:39:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The "workers" are four goroutines started in the package's `init`, which block on range over that channel and call `Post` for each payload:

```42:55:internal/webhook/webhook.go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

Producers enqueue through `PostAsync` (`internal/webhook/webhook.go:184`), which is non-blocking: a `select` with a `default` branch means that when the 128 slots are full the payload is **dropped** with a warning rather than backpressured or retried (`internal/webhook/webhook.go:189-195`). Callers are the memo dispatch helpers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.

Consequences worth noting given the premise: because the queue is a plain in-memory channel, there is no durability, no acknowledgement, no retry, and no cross-instance distribution — pending webhooks are lost on process exit, and each server instance dispatches only what it enqueued. Delivery failures are logged and discarded; the HTTP send itself is `safeClient.Do` in `Post` (`internal/webhook/webhook.go:152`) with a 30-second timeout.
