**What computes it.** `RebuildMemoPayload` is small: it ensures `memo.Payload` exists, runs one markdown parse, and copies two fields onto the payload.

```74:88:server/runner/memopayload/runner.go
func RebuildMemoPayload(_ context.Context, memo *store.Memo, markdownService markdown.Service) error {
	if memo.Payload == nil {
		memo.Payload = &storepb.MemoPayload{}
	}

	// Use goldmark service to extract all metadata in a single pass (more efficient)
	data, err := markdownService.ExtractAll([]byte(memo.Content))
	if err != nil {
		return errors.Wrap(err, "failed to extract markdown metadata")
	}

	memo.Payload.Tags = data.Tags
	memo.Payload.Property = data.Property
	return nil
}
```

The real work happens in `ExtractAll`, which walks the goldmark AST once (`internal/markdown/markdown.go:356-422`): it collects `#tag` nodes (skipping tags inside links or images, via `asMemoTagNode`), sets `Title` from a leading H1 heading, and flips `HasLink`, `HasCode` (code blocks, fenced blocks, or code spans), `HasTaskList`, and `HasIncompleteTasks` (any unchecked checkbox). Tags are deduplicated with case preserved.

**Where it's stored.** The result is the persisted `MemoPayload` proto (`proto/store/memo.proto:7-22`), whose `Property` submessage is documented as "The calculated properties from the memo content." Note that `Location` lives on the same payload but is *not* derived — `CreateMemo` sets it from the request right after the rebuild (`server/router/api/v1/memo_service.go:111-113`), which is why the rebuild only overwrites `Tags` and `Property`.

**Triggers.**

- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the `path == "content"` branch of the update mask; the recomputed payload is then assigned to `update.Payload` at line 451. Changing visibility, pinned state, or row status does not recompute anything.
- `memopayload.Runner.RunOnce` — `server/runner/memopayload/runner.go:27`, a batch backfill over all memos. It exists but is dead code: nothing calls `memopayload.NewRunner`.

**One thing that is *not* persisted.** `ExtractAll` also returns `Mentions`, which `RebuildMemoPayload` discards. Mentions are read separately at request time for inbox notifications (`server/router/api/v1/memo_mention_helpers.go:32`). Likewise the preview `snippet` on the API `Memo` message is generated per-response by `getMemoContentSnippet` (`server/router/api/v1/memo_service_webhooks.go:83`), called from the converter at `server/router/api/v1/memo_service_converter.go:76` and for relation previews at `server/router/api/v1/memo_relation_service.go:154`. So of the list/preview metadata, tags and properties are precomputed and stored, while snippets are computed on read.
