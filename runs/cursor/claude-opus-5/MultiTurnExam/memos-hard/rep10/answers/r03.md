**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never used by the server at all — so there is no scheduled time to report.**

Two separate corrections are packed in here:

**The cron scheduler exists but is dead code.** `internal/scheduler` is a complete, self-contained cron implementation — `scheduler.go`, `job.go`, `parser.go`, `middleware.go` — supporting 5- and 6-field cron expressions, timezones, and middleware. But the only files anywhere in the repository that import `github.com/usememos/memos/internal/scheduler` are its own tests, `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No production code constructs a `Scheduler`, registers a `Job`, or calls `Start`. Correspondingly, a search for cron expressions outside that package returns nothing.

**The "daily-cleanup" you may be thinking of is documentation, not a registered job.** The package doc shows a usage example with exactly that name and a 2 AM schedule:

```14:21:internal/scheduler/doc.go
//	s.Register(&scheduler.Job{
//		Name:     "daily-cleanup",
//		Schedule: "0 2 * * *", // 2 AM daily
//		Handler: func(ctx context.Context) error {
//			// Your cleanup logic here
//			return nil
//		},
//	})
```

That is an illustrative comment inside `doc.go`. It registers nothing and does not run.

**What actually runs on a timer.** The server's only real periodic work is the S3 presign runner, started in `Server.startBackgroundRunners` (`server/server.go:162-171`), which uses a plain `time.Ticker` at a fixed 12-hour interval rather than a cron expression (`server/runner/s3presign/runner.go:27-41`). The other recurring timer is the in-memory cache sweep, every 5 minutes via `cleanupLoop` (`store/cache/cache.go:201-210`) — that expires cached entries in process memory and touches no database rows.

Database cleanup in this codebase is event-driven rather than scheduled: for example, deleting a user removes reactions, attachments, memos, and related rows transactionally in `DeleteUser` (`store/db/sqlite/user_delete.go:92-127`), and memo deletion handles its own relation and attachment cleanup (`server/router/api/v1/memo_service.go:579`).
