**`github.com/usememos/memos/internal/idp` (`internal/idp/idp.go`); `github.com/usememos/memos/internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

A note on how thin the abstraction is: `internal/idp` does not declare a Go interface. The entire package is a single shared type, `IdentityProviderUserInfo` (`internal/idp/idp.go:3-8`), with `Identifier`, `DisplayName`, `Email`, and `AvatarURL`. That struct is the common currency every provider must produce, so it is the abstraction in practice, but provider selection is done with an explicit type switch rather than polymorphism.

OAuth2 is the only concrete protocol implementation that ships. `internal/idp/oauth2/oauth2.go` defines an `IdentityProvider` struct wrapping a `storepb.OAuth2Config` and gives it two methods: `ExchangeToken` (authorization-code exchange via `golang.org/x/oauth2`, with optional PKCE `code_verifier` support) and `UserInfo`, which calls the configured userinfo endpoint and maps arbitrary JSON claims onto `idp.IdentityProviderUserInfo` using the provider's configurable `FieldMapping`.

This is confirmed at both the schema and call-site level. The proto `IdentityProviderConfig` oneof has exactly one variant, `oauth2_config`, and the `Type` enum has only `TYPE_UNSPECIFIED` and `OAUTH2` (`proto/api/v1/idp_service.proto:76-87`). The single consumer, `resolveSSOIdentity` in `server/router/api/v1/auth_service_sso.go:104-134`, branches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` and constructs the OAuth2 provider directly at line 121 — there is no registry or dispatch table, so adding another protocol would mean extending both the oneof and that conditional.
