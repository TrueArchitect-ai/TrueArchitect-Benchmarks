Visibility is checked in three broad ways — per-object read guards, query-level scoping that never loads hidden rows, and delivery filters on push/notification paths. Every distinct site:

`checkMemoReadAccess` (shared read guard; also handles archived memos) — `server/router/api/v1/memo_service.go:39-68`, called from `GetMemo` (line 356), its parent-memo check (line 367), and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)
`ListMemos` query scoping — `server/router/api/v1/memo_service.go:219-225` (anonymous sees `PUBLIC`; other users' memos limited to `PUBLIC`+`PROTECTED`)
`ListAllUserStats` and `GetUserStats` query scoping — `server/router/api/v1/user_service_stats.go:84` and `:218-220`
`checkAttachmentAccess` (attachment inherits its memo's visibility) — `server/router/api/v1/attachment_service.go:437-461`
`ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-222`
`ListMemoReactions` — `server/router/api/v1/reaction_service.go:30-38`
`UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:83`
`CreateMemoComment` (private parent blocks commenting; line 100 gates the inbox notification) — `server/router/api/v1/memo_service_comments.go:41` and `:100`
`FileServerService.checkAttachmentPermission` (raw HTTP file path, independent of gRPC) — `server/router/fileserver/fileserver.go:677` and `:699`, with a share-token fallback at `:684-689`

Two things worth flagging. The rules are duplicated rather than centralized: `checkMemoReadAccess`, `checkAttachmentAccess`, and `checkAttachmentPermission` each re-implement the same "public is open, private is creator-only, protected requires auth" logic with slightly different admin handling — the file server and attachment service grant admins access to private memos (`user.Role != store.RoleAdmin`, `isSuperUser(user)`), while `checkMemoReadAccess` does not. And there are two independent `canViewerAccessMemo` functions with the same name in different packages.

The MCP router (`server/router/mcp/`) contains no visibility logic of its own; it proxies through the v1 API and inherits those checks.
