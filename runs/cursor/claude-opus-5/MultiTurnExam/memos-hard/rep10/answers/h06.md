The last three columns are worth expanding, because two of these are the non-obvious ones. `SetMemoAttachments` and `SetMemoRelations` don't mention webhooks anywhere in their own bodies — they reach delivery through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at line 67. That's the same helper `UpdateMemo` uses, so attaching a file or linking two memos fires a `memos.memo.updated` webhook just as a content edit does.

The four `Dispatch*Webhook` entry points in `server/router/api/v1/memo_service_webhooks.go` all resolve the memo creator, load that user's configured hooks via `s.Store.GetUserWebhooks`, and then funnel into the same call. Three of them share `dispatchMemoRelatedWebhook` (line 48, differing only in the activity-type string), while `DispatchMemoCommentCreatedWebhook` (line 30) is separate because it targets the *related* memo's owner rather than the comment author. Both converge on `webhook.PostAsync`:

```61:72:server/router/api/v1/memo_service_webhooks.go
	for _, hook := range webhooks {
		payload, err := convertMemoToWebhookPayload(memo)
		if err != nil {
			return errors.Wrap(err, "failed to convert memo to webhook payload")
		}
		payload.ActivityType = activityType
		payload.URL = hook.Url
		payload.SigningSecret = hook.SigningSecret

		// Use asynchronous webhook dispatch
		webhook.PostAsync(payload)
	}
```

`PostAsync` is the single choke point: it enqueues onto a bounded 128-slot channel (dropping with a warning if full) drained by four goroutines that call `Post`, where the request is signed and sent via `safeClient.Do`. So `PostAsync` is where the handler paths converge, and `Post` is where delivery happens — no handler reaches `Post` by any other route.

One clarification on scope: these are the paths to *user*-configured URLs. Other outbound HTTP exists but is driven by admin/instance configuration rather than per-user webhooks, notably the SSO userinfo fetch in `internal/idp/oauth2/oauth2.go:83` reached from the sign-in-with-SSO path, and S3 presigning in `server/runner/s3presign/runner.go`.
