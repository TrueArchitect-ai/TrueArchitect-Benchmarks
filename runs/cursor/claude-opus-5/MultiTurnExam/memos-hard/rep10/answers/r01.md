**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive search for "redis" across the Go sources, `go.mod`, `go.sum`, and YAML config turns up zero hits — no client library, no connection settings, no config key. The cache layer is process-local and in-memory only, so there is nothing to point at an external cache server and no way to share cache state across instances.

**The actual mechanism.** Caching is a hand-rolled in-memory cache in `store/cache/cache.go`. `Cache` (line 67) is a `sync.Map` plus an atomic item counter, with a background `cleanupLoop` goroutine started in `cache.New` (line 83). Its `Config` (line 42) has four knobs: `DefaultTTL`, `CleanupInterval`, `MaxItems`, and an optional `OnEviction` callback.

The `Store` owns three separate instances — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`) — all constructed in `store.New` from one shared config:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

**TTL for user entries: 10 minutes.** Every write to the user cache goes through `Set` — at `store/user.go:98`, `:122`, `:132`, `:143`, and `:167` — and `Cache.Set` forwards to `SetWithTTL` using `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). Nothing in the store calls `SetWithTTL` directly, so users get the flat 10-minute default with no per-entry override. Note the same 10-minute value is hardcoded twice: in `store.New` and again in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), though `DefaultConfig` isn't what the store actually uses.

Two related behaviors worth knowing: expired entries are swept every 5 minutes by the cleanup loop, and the cache caps at 1000 items, dropping the oldest via `cleanupOldest` when exceeded (`store/cache/cache.go:117-119`). Cached users are also invalidated eagerly — reads by ID consult the cache first (`store/user.go:150`), and deletion removes the key at `store/user_delete.go:40`.
