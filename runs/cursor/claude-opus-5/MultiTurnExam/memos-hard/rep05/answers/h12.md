How I narrowed it down. Three types declare a `CreateMemo` method with an identical signature — `store/db/sqlite/memo.go:16`, `store/db/mysql/memo.go:16`, and `store/db/postgres/memo.go:16` — and the call site can't tell you which one runs, because `Store.CreateMemo` validates the UID and then dispatches through an interface:

```109:114:store/memo.go
func (s *Store) CreateMemo(ctx context.Context, create *Memo) (*Memo, error) {
	if !base.UIDMatcher.MatchString(create.UID) {
		return nil, errors.New("invalid uid")
	}
	return s.driver.CreateMemo(ctx, create)
}
```

`s.driver` is the `store.Driver` interface, which declares `CreateMemo` at `store/driver.go:29`. So resolving the concrete implementation means resolving which driver was constructed at startup, and that comes down to configuration rather than code structure:

1. `cmd/memos/main.go:122` sets `viper.SetDefault("driver", "sqlite")`, and the flag itself defaults to the same value at line 130 (`rootCmd.PersistentFlags().String("driver", "sqlite", ...)`), so with no flags or env overrides `profile.Driver == "sqlite"` (read at `cmd/memos/main.go:43`).
2. `profile.Validate` confirms this is a complete configuration on its own — for `Driver == "sqlite"` with an empty DSN it synthesizes a file path like `memos_prod.db` under the data directory (`internal/profile/profile.go:110-117`), so a default install needs no database flags.
3. `NewDBDriver` switches on that string and takes the `case "sqlite"` branch, calling `sqlite.NewDB(profile)` (`store/db/db.go:19-20`); the resulting `store.Driver` is handed to `store.New` at `cmd/memos/main.go:57-64`.

That makes the SQLite `*DB` the value behind `s.driver` for the whole process lifetime, so its `CreateMemo` is the code that runs. It assembles the column and placeholder lists dynamically, appending `created_ts`/`updated_ts` only when the caller supplied non-zero values (lines 30-39), marshals the memo payload to protojson, and uses `QueryRowContext` with a `RETURNING` clause to read back `id`, `created_ts`, `updated_ts`, and `row_status` in the same round trip.
