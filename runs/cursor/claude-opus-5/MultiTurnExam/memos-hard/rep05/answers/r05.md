**Premise correction: there is no GraphQL in this repository. Searching all Go, TypeScript, JSON, YAML, and module files for `graphql`, `gqlgen`, `apollo`, or `.graphql`/`.gql` schema files returns zero matches, and no GraphQL library appears in `go.mod`. There is no GraphQL schema to locate.**

The actual API surface is Protocol Buffers with `google.api.http` annotations, from which three HTTP surfaces plus an OpenAPI document are generated.

**Schema definitions** live in `proto/api/v1/`: `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, and `common.proto`. Each RPC carries its REST mapping inline — for example `CreateMemo` is annotated `post: "/api/v1/memos"` with `body: "memo"` (`proto/api/v1/memo_service.proto:21-26`) and `ListMemos` maps to `get: "/api/v1/memos"`. Persistence-side message types are separate, under `proto/store/`. Code generation is driven by `proto/buf.gen.yaml` and `proto/buf.yaml`, with output committed to `proto/gen/`.

**Runtime surfaces**, all registered in `RegisterGateway` (`server/router/api/v1/v1.go:65-147`):

REST via grpc-gateway — eight service handlers registered on a `runtime.NewServeMux` (lines 99-122), mounted at `/api/v1/*` and `/file/*` (lines 128-129).

Connect RPC for browser clients, explicitly replacing grpc-web, mounted at `/memos.api.v1.*` (lines 139-144) with metadata, logging, recovery, and auth interceptors.

Server-Sent Events for live updates, registered alongside the gateway group at line 125 so it shares the same CORS treatment.

Outside that package there are three more non-gRPC HTTP surfaces: the file server routes for attachments and avatars (`server/router/fileserver/fileserver.go:121-125`), RSS feeds (`server/router/rss/rss.go`), and an MCP endpoint (`server/router/mcp/`), all wired in `server/server.go:81-96`.

**Machine-readable spec:** an OpenAPI 3 document generated from the protos at `proto/gen/openapi.yaml`, embedded into the binary via `go:embed` in `proto/openapi_embed.go`. That is the closest analogue to the schema artifact the question was after — a REST/OpenAPI contract rather than a GraphQL SDL.
