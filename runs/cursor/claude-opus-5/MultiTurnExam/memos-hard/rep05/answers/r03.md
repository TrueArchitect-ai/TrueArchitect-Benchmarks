**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never used in production. The `internal/scheduler` package exists and implements a full cron scheduler, but nothing in the running server ever imports it, constructs it, or registers a job with it — so there is no schedule to report.**

Evidence:

The only files importing `github.com/usememos/memos/internal/scheduler` are its own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No file under `cmd/`, `server/`, or `store/` references the package at all.

Every `scheduler.Job` registration in the repository lives in test files or documentation. The `0 2 * * *` ("2 AM daily") expression that most resembles a nightly cleanup appears only as an illustrative snippet in `internal/scheduler/README.md:35`, where the job is literally named `daily-cleanup` and its handler just prints "Running cleanup...", and again in an example at `internal/scheduler/example_test.go:100`. Other schedules in those tests include `*/5 * * * *`, `0 9 * * *`, `0 */2 * * *`, and `0 1 * * 0`, all similarly illustrative.

What actually runs on a schedule is one background runner, and it uses a plain ticker rather than cron: the S3 presign runner executes once at startup and then every 12 hours (`runnerInterval = time.Hour * 12` at `server/runner/s3presign/runner.go:27`), wired in at `server/server.go:162-171`. It refreshes presigned attachment URLs and deletes nothing.

The only other recurring background work is the in-memory cache sweep, also ticker-driven, running every 5 minutes per `CleanupInterval` (`store/cache/cache.go:60`, loop at line 200). That evicts expired cache entries in process memory and never touches the database.

Database cleanup in this codebase is event-driven instead of scheduled: cascading deletes happen inline when a user or memo is removed, for example the transactional multi-table delete in `store/db/sqlite/user_delete.go` and the memo relation/attachment cleanup noted at `server/router/api/v1/memo_service.go:579`. There is no `VACUUM`, retention sweep, or orphan-row reaper anywhere.
