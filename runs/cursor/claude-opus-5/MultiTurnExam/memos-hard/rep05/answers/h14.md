`RebuildMemoPayload` is deliberately thin: it ensures a non-nil `MemoPayload`, calls `ExtractAll` once on the memo content, and assigns just two fields:

```84:87:server/runner/memopayload/runner.go
	memo.Payload.Tags = data.Tags

```

Note it overwrites only `Tags` and `Property`, leaving `Payload.Location` intact — which matters because `CreateMemo` sets `create.Payload.Location` from the request immediately *after* the rebuild (`memo_service.go:111-113`), so user-supplied location survives while derived fields are always recomputed from content.

The extraction itself is a single goldmark AST walk (`internal/markdown/markdown.go:371-411`) that collects everything in one pass rather than parsing repeatedly. Per the schema in `proto/store/memo.proto:15-22`, the derived properties are: `has_link` (any `KindLink` node), `has_code` (`KindCodeBlock`, `KindFencedCodeBlock`, or `KindCodeSpan`), `has_task_list` (any GFM task checkbox), `has_incomplete_tasks` (a checkbox with `IsChecked == false`), and `title` (text of the first block-level child of the document, only if it's an H1). Tags come from custom `TagNode`s and are deduplicated case-preservingly via `uniquePreserveCase` (line 418). `ExtractAll` also returns mentions, but `RebuildMemoPayload` discards them — mentions are consumed separately for notifications at `memo_mention_helpers.go:32`.

On triggers, the update path is gated: `UpdateMemo` loops over `request.UpdateMask.Paths` and only recomputes inside the `path == "content"` branch, where it assigns the new content, rebuilds, and then sets both `update.Content` and `update.Payload` (lines 436-451). Changing visibility, pinned state, or timestamps does not recompute. Comment creation reuses the same code path by calling `s.CreateMemo` with suppressed SSE and mention notifications, so comments get their payload built identically.

There is also a bulk backfill, `Runner.RunOnce` at `server/runner/memopayload/runner.go:27`, which walks all memos in batches of 100 calling `RebuildMemoPayload` and persisting each — but nothing constructs that runner, so it never executes in production.

Downstream, this metadata is what makes list and preview queries cheap: `memo_service_converter.go:48-49` copies `Payload.Tags` and `Property` straight into the API response, and `user_service_stats.go` aggregates tag counts and the four booleans (lines 138-151 and 254-267) without re-parsing any markdown.
