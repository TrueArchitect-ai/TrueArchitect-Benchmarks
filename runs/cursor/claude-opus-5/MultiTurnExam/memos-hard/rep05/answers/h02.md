**`webhook.Post` — `internal/webhook/webhook.go:120` (the function that builds and sends the HTTP POST; line 152 is the actual `safeClient.Do(req)` call); protection is a dial-time SSRF guard, `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`, with a store-time check via `webhook.ValidateURL` — `internal/webhook/validate.go:62`**

How it fits together:

**Delivery.** Memo create/update/delete and comment-created events call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43` and `:71`. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a buffered channel of 128, dropping with a warning when full. Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, so the real outbound request always executes on a background worker, never on the request goroutine. `Post` marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`), and issues the request through `safeClient`.

**Protection.** The primary defense is at the transport layer rather than the URL layer. `safeClient` (`internal/webhook/webhook.go:32-37`) is built with a `http.Transport` whose `DialContext` is `safeDialContext`. That function splits the host/port, resolves the hostname itself via `net.DefaultResolver.LookupHost`, and refuses to dial if any resolved address is in a reserved range. Because the check happens at dial time on the addresses actually being connected to, it also defeats DNS rebinding, where a hostname passes validation at save time and later resolves to something internal.

The reserved ranges are declared in `internal/webhook/validate.go:14-23` and cover IPv4 loopback, all three RFC-1918 private blocks, link-local `169.254.0.0/16` (which includes the cloud instance metadata endpoint at `169.254.169.254`), plus the IPv6 equivalents (`::1/128`, `fc00::/7`, `fe80::/10`). They're parsed once in an `init()` at line 28, which panics on a malformed CIDR.

There's also a secondary check at configuration time: `webhook.ValidateURL` is called before webhooks are persisted, from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`. It requires an absolute `http`/`https` URL and rejects hostnames resolving into reserved ranges, giving the user an `InvalidArgument` error up front instead of a silent delivery failure later.

Both layers share the `isReservedIP` helper (`internal/webhook/validate.go:44`), which has a global escape hatch: the exported `AllowPrivateIPs` flag disables the SSRF protection entirely when true. It's wired to the `allow-private-webhooks` config option in `cmd/memos/main.go:49`, intended for self-hosted setups whose webhook targets legitimately live on the local network.
