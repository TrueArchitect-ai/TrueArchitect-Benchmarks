**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

The abstraction in `internal/idp` is deliberately thin: `idp.go` is a nine-line file that defines only the `IdentityProviderUserInfo` struct with `Identifier`, `DisplayName`, `Email`, and `AvatarURL`. There is no Go interface declaring `ExchangeToken`/`UserInfo` methods, so the shared contract is the normalized user-info type that every provider must produce, not a polymorphic interface.

OAuth2 is the only concrete protocol that ships. `internal/idp/oauth2/oauth2.go` defines an `IdentityProvider` wrapping a `storepb.OAuth2Config`, with `NewIdentityProvider` validating that client ID, client secret, token URL, user-info URL, and the identifier field mapping are all non-empty (lines 27-43). `ExchangeToken` (line 47) performs the authorization-code exchange via `golang.org/x/oauth2` and supports PKCE by passing `code_verifier` when supplied. `UserInfo` (line 83) calls the user-info endpoint with a 10-second timeout and a bearer token, then maps arbitrary JSON claims onto `idp.IdentityProviderUserInfo` using the configured `FieldMapping`, failing if the identifier claim is missing and defaulting display name to the identifier.

The single-implementation design shows up in the schema and the caller too. `proto/store/idp.proto` declares `IdentityProvider.Type` with only `TYPE_UNSPECIFIED` and `OAUTH2` (lines 11-14), and `IdentityProviderConfig` is a `oneof` with just `oauth2_config`. The consumer, `resolveSSOIdentity` in `server/router/api/v1/auth_service_sso.go`, dispatches with a plain `if identityProvider.Type == storepb.IdentityProvider_OAUTH2` at line 120 and constructs `oauth2.NewIdentityProvider` directly rather than resolving through a registry — the only two files importing `internal/idp` are the oauth2 package itself and this SSO handler.
