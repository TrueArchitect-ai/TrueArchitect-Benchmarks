**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`; convergence function: `webhook.Post` — `internal/webhook/webhook.go:120` (the actual send is `safeClient.Do(req)` at line 152)**

The user-configured URL comes from each user's stored webhook records (`hook.Url`, read via `s.Store.GetUserWebhooks`), so any handler that reaches a dispatch helper can cause an outbound POST to an address the user chose.

The six handlers, all in `server/router/api/v1`:

| Handler | Path | How it reaches the webhook |
| --- | --- | --- |
| `CreateMemo` | `memo_service.go:70` | `DispatchMemoCreatedWebhook` at line 157 |
| `UpdateMemo` | `memo_service.go:401` | `dispatchMemoUpdatedSideEffects` at line 513 |
| `DeleteMemo` | `memo_service.go:518` | `DispatchMemoDeletedWebhook` at line 562 |
| `CreateMemoComment` | `memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` at line 119 |
| `SetMemoAttachments` | `memo_attachment_service.go:16` | `dispatchMemoUpdatedSideEffects` at line 48 |
| `SetMemoRelations` | `memo_relation_service.go:16` | `dispatchMemoUpdatedSideEffects` at line 48 |

The last three of those four "updated" paths are worth calling out because the webhook is not obvious from the handler name: `SetMemoAttachments` and `SetMemoRelations` both call the shared helper `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`), which fires `DispatchMemoUpdatedWebhook` before broadcasting the SSE event. So changing a memo's attachment list or relations emits a `memos.memo.updated` webhook just as `UpdateMemo` does.

The funnel below the handlers is narrow. The four `Dispatch*Webhook` methods in `server/router/api/v1/memo_service_webhooks.go` all resolve the owner's webhooks and call `webhook.PostAsync` (lines 43 and 71). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a 128-slot buffered channel; four worker goroutines started in `init()` (lines 42-55) drain it and every one of them calls `Post`. `Post` is therefore the single chokepoint where the request is built, optionally HMAC-signed, and sent — which is also why the SSRF guard is installed there, on the shared `safeClient`'s dialer rather than at each call site.

One adjacent path I ruled out: `httpgetter.GetHTMLMeta` is aliased as `fetchHTMLMeta` at `server/router/api/v1/memo_service.go:28` and also makes outbound HTTP, but that targets URLs found in memo content for link previews rather than a configured webhook endpoint, and it does not pass through `webhook.Post`.
