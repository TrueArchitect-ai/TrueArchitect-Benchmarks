**1st: `store.User` (~7 packages, 6 of them non-test); 2nd: `store.Memo` (~6 packages, 4 non-test)**

`store.User` is defined at `store/user.go:29` and `store.Memo` at `store/memo.go:35`. Counting distinct directories outside the `store/` tree that reference each type:

`store.User` — `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend` (test file only), `server/router/rss`. Roughly 99 references across those files.

`store.Memo` — `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend` (test file only), `server/router/rss`, `server/runner/memopayload`. Roughly 73 references.

Third place is `store.Attachment` (`store/attachment.go`) at 4 packages — `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/rss` — then `store.MemoShare`, `store.MemoRelation`, and `store.Inbox` at 3 each, and `store.Reaction` and `store.UserIdentity` at 2 (API layer plus its test package only).

The reason `User` edges out `Memo` is authentication: `server/auth` resolves tokens and sessions to a `*store.User` and doesn't deal in memos at all, and `server/router/fileserver` needs `store.User` both for avatar lookups and for viewer permission checks while touching `store.Attachment` rather than `store.Memo` directly. `Memo` picks up one package `User` lacks, `server/runner/memopayload`, which rebuilds memo payloads.

Method note: I matched `\bstore\.User\b`-style references in all `.go` files, excluding the `store/` tree itself and `web/`, then reduced file paths to their directories. I ignored the `proto/gen/store` hits that showed up for `UserSetting`, `InstanceSetting`, and `IdentityProvider`, since those are generated protobuf types in a package coincidentally named `store` rather than references to the data-layer entities. I also excluded the query-parameter structs (`FindUser`, `UpdateMemo`, `DeleteAttachment`, and similar), which are not persistent entity types; those are more widely referenced still, but they're request descriptors rather than entities.
