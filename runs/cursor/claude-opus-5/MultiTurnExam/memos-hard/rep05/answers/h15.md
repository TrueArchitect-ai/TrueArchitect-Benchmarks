Two structural notes. The API layer uses two different mechanisms: list endpoints push visibility into the query as a CEL filter string like `creator_id == %d || visibility in ["PUBLIC", "PROTECTED"]`, while single-object endpoints do an explicit post-fetch check; the ACL comment at `server/router/api/v1/acl_config.go:32` records that this is intentional ("visibility filtering done in service layer") since the ACL allowlist itself permits anonymous access to memo endpoints.

The file server is the one surface with an extra bypass: `checkAttachmentPermission` accepts a `share_token` query parameter and grants access to a private or protected memo's attachments when the token matches a non-expired `MemoShare` for that exact memo (`fileserver.go:684-689`). Notably `server/router/api/v1/memo_share_service.go` contains no visibility check of its own.
