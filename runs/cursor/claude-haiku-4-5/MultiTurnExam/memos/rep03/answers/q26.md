I notice that the reaction table stores `content_id` as TEXT (the memo resource name like "memos/1"), not as an INTEGER foreign key. So reactions are not automatically cascaded - they would need to be manually deleted or cleaned up by the application layer. However, since they store the resource name as a string, they won't be cleaned up by database constraints.

Based on my analysis, here are the tables affected by DeleteMemo:

1. **memo** - directly deleted
2. **memo_relation** - explicitly deleted (where memo is source or target)
3. **attachment** - explicitly deleted (all attached to memo)
4. **memo_share** - cascaded delete (via ON DELETE CASCADE foreign key)

Reactions are listed but there's no explicit deletion code in the store layer - they appear to be handled implicitly through the resource name reference.
