**Premise correction**: Neither NATS nor RabbitMQ is used. There is no message broker for webhook delivery.

**Actual mechanism**:
- **Queue type**: In-memory buffered Go channel
- **Queue declaration**: `internal/webhook/webhook.go:39`
- **Queue capacity**: 128 requests
- **Worker pool**: 4 goroutines spawned at init time (`internal/webhook/webhook.go:42-55`)

The webhook delivery system uses a simple in-memory architecture:
1. Requests are enqueued to `asyncPostQueue` channel via `PostAsync()`
2. 4 worker goroutines initialized at package load time consume from the channel
3. Each worker calls `Post()` to execute the HTTP delivery
4. If the channel buffer is full (128 requests), new requests are dropped with a warning

This is a simple, non-persistent queue implementation with no external message broker.
