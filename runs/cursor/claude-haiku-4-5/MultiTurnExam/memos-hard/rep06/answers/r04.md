**Premise correction + Actual mechanism:** The question assumes a message broker (either NATS or RabbitMQ) is used, but neither is present in the codebase. Webhook delivery workers consume from an **in-memory Go channel** instead of an external message broker.

The queue is declared in `internal/webhook/webhook.go:39` as:
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The mechanism works as follows:
- The queue is declared as a package-level unbuffered Go channel with a buffer size of 128 items
- Four worker goroutines are spawned in the `init()` function (lines 42-54) that continuously range over this channel
- When `PostAsync()` is called (line 190), webhook payloads are sent to the channel via `asyncPostQueue <- requestPayload`
- Each worker processes payloads sequentially by calling `Post(payload)` (lines 45-51)
- If the queue is full, the send is dropped with a warning (lines 189-195)

This is entirely in-process and ephemeral—if the server restarts, any pending webhooks in the queue are lost. No external message broker is used.
