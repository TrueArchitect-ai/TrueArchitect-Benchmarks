**Premise correction:** Neither NATS nor RabbitMQ is used. The webhook delivery workers do not consume from a message broker.

**Actual mechanism:** Webhook delivery uses an in-memory Go channel for queuing. The queue is declared at `/bench/repo/internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a buffered channel with capacity of 128 messages.

**Worker implementation:** Four goroutine workers are spawned in the `init()` function (lines 42-55) that consume from this channel:

```go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					// error handling
				}
			}
		}()
	}
}
```

These workers are initialized at package startup and continuously read from the `asyncPostQueue` channel, calling `Post()` to deliver each webhook asynchronously. If the queue fills (exceeds 128 messages), new webhook dispatches are dropped with a warning (line 192).
