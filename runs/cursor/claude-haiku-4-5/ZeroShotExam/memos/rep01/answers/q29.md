The frontend authentication interceptor is defined in `connect.ts` (lines 156-178) as the `authInterceptor` function. It manages two token types:

1. **Access Token** - A short-lived JWT (15 minutes) extracted from the `Authorization` header as a Bearer token, automatically refreshed proactively when nearly expired or reactively on 401 responses
2. **Refresh Token** - A long-lived JWT (30 days) stored in cookies for obtaining new access tokens

The backend `server/auth` package validates these tokens through the `Authenticator` struct:
- `AuthenticateByAccessTokenV2()` validates access tokens (stateless JWT validation)
- `AuthenticateByRefreshToken()` validates refresh tokens (stateless JWT + database revocation check)
- `AuthenticateByPAT()` validates Personal Access Tokens
- The `Authenticate()` and `AuthenticateToUser()` methods orchestrate validation of Bearer tokens from the Authorization header
