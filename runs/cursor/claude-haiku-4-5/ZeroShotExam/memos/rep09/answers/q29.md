Based on my analysis of the repository:

**Interceptor path:** `web/src/connect.ts` (the `authInterceptor` is defined at line 156)

**Token kinds managed:** 
1. Access tokens (short-lived JWT tokens, 15 minutes duration)
2. Refresh tokens (long-lived JWT tokens, 30 days duration, stored in cookies)
3. Personal Access Tokens (PAT, long-lived tokens for programmatic access)

**Backend package that validates them:** `server/auth`

The auth interceptor in `web/src/connect.ts` manages Bearer token authorization in the `Authorization` header, extracts tokens via `getRequestToken()`, and handles token refresh on 401 responses. The backend `server/auth` package validates these tokens through its `Authenticator` type, which provides `AuthenticateByAccessTokenV2()` for stateless access token validation and `AuthenticateByPAT()` for personal access token validation, with refresh token validation handled via `AuthenticateByRefreshToken()`.
