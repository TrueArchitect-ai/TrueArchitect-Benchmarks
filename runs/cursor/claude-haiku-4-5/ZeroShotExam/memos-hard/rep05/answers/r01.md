**Premise Correction:** The repository does not use Redis for the cache layer. There is no Redis connection configured anywhere in the codebase.

**Actual Mechanism:** The cache layer uses an in-memory cache implementation. The configuration is located in `store/store.go` (lines 38-60), where the Store is instantiated with a `cache.Config` that applies to all cache layers including user settings. The cache implementation is defined in `store/cache/cache.go`.

For user entries specifically, the `userSettingCache` is configured with:
- **TTL: 10 minutes** (set in `store/store.go` line 41: `DefaultTTL: 10 * time.Minute`)
- **CleanupInterval:** 5 minutes
- **MaxItems:** 1000

User settings are cached using keys generated by the `getUserSettingCacheKey()` function in `store/cache.go`, and are accessed through methods in `store/user_setting.go` (e.g., `GetUserSetting()`, `UpsertUserSetting()`, `ListUserSettings()`).
