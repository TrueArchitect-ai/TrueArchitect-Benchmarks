**Premise correction:** The assumption that there is a Redis connection is incorrect.

**Actual mechanism:** The cache layer is not configured with Redis. Instead, the repository uses an **in-memory cache** (`cache.Cache`) implemented in Go (`/bench/repo/store/cache/cache.go`).

**Location of user entry cache configuration:** `/bench/repo/store/store.go` (lines 38-60), specifically in the `New()` function where the Store is initialized.

**TTL for user entries:** **10 minutes** (`10 * time.Minute`) — this is set in the `cacheConfig` at line 41 of `/bench/repo/store/store.go`, which is then applied to the `userCache` that stores user entries (line 52). When users are cached at lines 98, 122, 132, 143, and 167 of `/bench/repo/store/user.go`, they use the default TTL from this configuration via the `Set()` method (which internally calls `SetWithTTL()` with the `DefaultTTL`).
