**memo, memo_relation, attachment**

`Store.DeleteMemo` in `store/memo.go` explicitly cleans up related rows before deleting the memo:

```140:158:store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	// ...
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

That maps to:

| Table | How |
|---|---|
| **memo_relation** | `DELETE FROM memo_relation` where `memo_id` or `related_memo_id` matches (`store/db/sqlite/memo_relation.go`) |
| **attachment** | `DELETE FROM attachment` for each linked attachment (`store/attachment.go` → `store/db/sqlite/attachment.go`) |
| **memo** | `DELETE FROM memo` where `id` matches (`store/db/sqlite/memo.go`) |

**Not** removed by this explicit cascade code: `reaction`, `inbox`, and similar tables.

**Note:** `memo_share` defines `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in `store/migration/sqlite/LATEST.sql` (and the postgres/mysql schemas), so shares can be removed by the database when the memo row is deleted — but that is not part of the Go cascade logic in `DeleteMemo`.

At the API layer (`server/router/api/v1/memo_service.go`), comment memos are deleted first via recursive `Store.DeleteMemo` calls, which hits the same three tables for each comment before the parent memo is deleted.
