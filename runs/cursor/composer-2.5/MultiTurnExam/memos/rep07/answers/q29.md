web/src/connect.ts; access token (Bearer `Authorization` header, stored in `localStorage` via `web/src/auth-state.ts`) and refresh token (HTTP cookie, sent with `credentials: "include"` for refresh); server/auth

The Connect **`authInterceptor`** in `web/src/connect.ts` attaches auth to every API request:

1. **Access token** — read from memory/`localStorage` (`web/src/auth-state.ts`), sent as `Authorization: Bearer <token>`.
2. **Refresh token** — not in JS; the browser sends it as an **HTTP cookie** because fetch uses `credentials: "include"`. On expiry or 401, `refreshAccessToken()` calls `AuthService.RefreshToken` over a separate transport without the auth interceptor.

On the backend, Connect requests are validated by **`AuthInterceptor`** in `server/router/api/v1/connect_interceptors.go`, which delegates to **`Authorizer`** → **`server/auth.Authenticator`** (`server/auth/authenticator.go`). That validates **JWT access tokens (Access Token V2)** and **Personal Access Tokens (PAT)** from the `Authorization` header; refresh tokens are validated separately in auth session handlers (e.g. `server/router/api/v1/auth_service_session.go`).
