CEL (cel-go) memo filter engine — internal/filter/; the API passes the filter string into `FindMemo.Filters`, each dialect's `ListMemos` calls `filter.AppendConditions` (`internal/filter/helpers.go`), which compiles CEL with `cel-go` against the memo schema (`internal/filter/schema.go`), builds a dialect-agnostic IR (`internal/filter/parser.go`, `internal/filter/ir.go`), and `internal/filter/render.go` turns that IR into SQL fragments and bound args for the target dialect (`DialectSQLite`, `DialectMySQL`, or `DialectPostgres`) that are appended to the query's `WHERE` clause.

The `ListMemosRequest.filter` field is documented as a CEL expression in `proto/api/v1/memo_service.proto` (lines 326–339). The engine entry point is `filter.DefaultEngine()` in `internal/filter/engine.go`; integration in drivers is shown in `store/db/sqlite/memo.go` (lines 57–62), with parallel usage in `store/db/mysql/memo.go` and `store/db/postgres/memo.go`. Details are in `internal/filter/README.md`.
