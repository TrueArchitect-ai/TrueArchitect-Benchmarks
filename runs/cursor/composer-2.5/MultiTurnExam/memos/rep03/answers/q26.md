**memo, memo_relation, attachment, memo_share**

When `Store.DeleteMemo` runs (`store/memo.go`), it explicitly deletes from:

- **memo_relation** — rows where the memo is source or target (`DeleteMemoRelation`)
- **attachment** — rows linked to the memo (`DeleteAttachment`)
- **memo** — the memo row itself (`driver.DeleteMemo` in e.g. `store/db/sqlite/memo.go`)

**memo_share** rows are removed by the database `ON DELETE CASCADE` on `memo_id` when the memo row is deleted (`store/migration/sqlite/LATEST.sql`, lines 102–109; same in postgres/mysql).

Via the API handler (`server/router/api/v1/memo_service.go`, lines 567–580), comment memos are deleted first with recursive `Store.DeleteMemo` calls, so the same tables are affected for each comment memo row.

**Not affected** by `DeleteMemo`: `reaction` (listed for webhooks before delete but not removed), `inbox`, and other tables.
