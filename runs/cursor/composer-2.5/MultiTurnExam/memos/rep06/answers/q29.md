web/src/connect.ts; access token (Bearer, stored in memory/localStorage) and refresh token (HttpOnly cookie via `credentials: "include"`); server/auth

The Connect transport in `web/src/connect.ts` uses an `authInterceptor` that:

1. Gets a token via `getRequestToken()` from `web/src/auth-state.ts`
2. Sets `Authorization: Bearer <accessToken>` on each request
3. On `Unauthenticated`, calls `refreshAccessToken()` (which hits `AuthService.refreshToken` with cookies included) and retries once

**Access token** — held in memory and `localStorage` (`memos_access_token` / `memos_token_expires_at` in `web/src/auth-state.ts`), sent as a Bearer token.

**Refresh token** — HttpOnly cookie (`memos_refresh`), sent automatically with `fetch(..., { credentials: "include" })`; the interceptor does not read it in JS.

Backend validation is in **`server/auth`** via `auth.Authenticator` (JWT access tokens and PATs per `server/auth/authenticator.go`). It is wired for Connect through `Authorizer` / `AuthInterceptor` in `server/router/api/v1/authz.go` and `server/router/api/v1/connect_interceptors.go`.
