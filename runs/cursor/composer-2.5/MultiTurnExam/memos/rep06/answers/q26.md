memo_relation, attachment, memo

`Store.DeleteMemo` in `store/memo.go` explicitly removes rows from these tables before deleting the memo itself:

1. **memo_relation** — rows where the memo is source (`memo_id`) or target (`related_memo_id`), via `DeleteMemoRelation` (`store/db/sqlite/memo_relation.go` and equivalents).
2. **attachment** — rows linked to the memo, via `ListAttachments` + `DeleteAttachment` (`store/attachment.go` → `DELETE FROM attachment`).
3. **memo** — the memo row, via `driver.DeleteMemo` (`store/db/sqlite/memo.go`).

`Store.DeleteMemo` does **not** delete from `reaction`, `memo_share`, or other tables. The API handler in `server/router/api/v1/memo_service.go` recursively calls `Store.DeleteMemo` on comment memos first; each call affects the same three tables for that memo ID.
