CEL (cel-go) memo filter engine — internal/filter; each filter string is parsed with `cel-go`, normalized to a dialect-agnostic IR, then rendered to SQL WHERE fragments by `render.go` for the target dialect (`DialectSQLite`, `DialectMySQL`, or `DialectPostgres`) and appended via `filter.AppendConditions` in each driver's `ListMemos`.

The `ListMemos` handler passes the filter through to `store.FindMemo.Filters` after validation with `filter.DefaultEngine()` in `server/router/api/v1/shortcut_service.go` (`validateFilter`). At query time, each dialect driver (for example `store/db/sqlite/memo.go`) calls `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args)` to compile filters into parameterized SQL.

Details are documented in `internal/filter/README.md`: parse (CEL via `cel-go` + memo schema in `schema.go`) → normalize to IR (`parser.go`, `ir.go`) → render SQL (`render.go` with dialect-specific placeholders, JSON access, `LIKE`/`ILIKE`, etc.).
