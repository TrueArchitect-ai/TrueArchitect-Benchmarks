Frontend Connect requests use `authInterceptor` in `web/src/connect.ts`. It attaches the access token as `Authorization: Bearer <token>`, refreshes it when needed, and retries once on `Unauthenticated`:

Token handling:

- **Access token** — stored in memory/localStorage via `web/src/auth-state.ts`, sent as a Bearer token on each request.
- **Refresh token** — sent as an HTTP cookie (`fetch` uses `credentials: "include"`); the interceptor calls `AuthService.refreshToken` to obtain a new access token when the current one is missing or expired.

Backend validation lives in `server/auth`. The Connect `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` delegates to `Authorizer.Authenticate`, which uses `server/auth/authenticator.go` to validate access tokens (Access Token V2) and personal access tokens from the Bearer header.
