The frontend Connect client attaches auth in `web/src/connect.ts` via `authInterceptor`. It reads the access token from `web/src/auth-state.ts` (localStorage), sets `Authorization: Bearer <token>`, and on expiry or `Unauthenticated` refreshes using the refresh-token cookie:

Refresh uses a separate transport with `credentials: "include"` and `AuthService.refreshToken` (lines 57–72, 74–83).

On the backend, Connect requests are validated by `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`, which delegates to `Authorizer` in `server/router/api/v1/authz.go` and then to `auth.Authenticator` in `server/auth/authenticator.go` — validating access tokens (V2 JWT) and PATs from the `Authorization` header. Refresh tokens are validated when the frontend calls `RefreshToken`, not on every API request.
