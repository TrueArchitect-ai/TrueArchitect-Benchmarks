**web/src/connect.ts; access token (Bearer) and refresh token (HTTP cookie); server/auth**

The Connect transport in `web/src/connect.ts` uses `authInterceptor`, which:

1. Gets an access token via `getRequestToken()` (from `web/src/auth-state.ts` / localStorage).
2. Sets `Authorization: Bearer <accessToken>`.
3. On expiry or missing token, calls `refreshAccessToken()` → `AuthService.refreshToken` with `credentials: "include"` so the refresh cookie is sent.
4. Retries once on `Unauthenticated`.

**Tokens:**

- **Access token** — stored in localStorage (`web/src/auth-state.ts`), sent as `Authorization: Bearer …`.
- **Refresh token** — HTTP-only cookie; refresh uses `fetchWithCredentials` and `refreshAuthClient.refreshToken` (`web/src/connect.ts`).

**Backend validation:**

Connect/gRPC-Gateway use `Authorizer` in `server/router/api/v1/authz.go`, which delegates to `auth.Authenticator` in **`server/auth`** (`server/auth/authenticator.go`). That validates JWT access tokens and personal access tokens from the `Authorization` header, and refresh tokens from cookies during `RefreshToken` (`server/router/api/v1/auth_service_session.go`).
