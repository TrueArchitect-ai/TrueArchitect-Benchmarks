**memo_relation, attachment**

In `Store.DeleteMemo` (`store/memo.go`), the store layer removes related rows before deleting the memo itself:

```140:158:store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	// ...
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

So before the `memo` row is deleted, it removes:

1. **`memo_relation`** — rows where the memo is source (`memo_id`) or target (`related_memo_id`)
2. **`attachment`** — rows linked to the memo (via `DeleteAttachment` in `store/attachment.go`)

The API handler in `server/router/api/v1/memo_service.go` also deletes comment memos first by calling `Store.DeleteMemo` recursively on each comment; that is separate memo deletion, not additional record types cleaned up for the parent memo at the store layer. Reactions, inbox entries, and memo shares are not deleted in `Store.DeleteMemo`.
