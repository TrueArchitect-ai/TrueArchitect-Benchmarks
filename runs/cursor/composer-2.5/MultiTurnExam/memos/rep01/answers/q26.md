**memo, memo_relation, attachment**

`Store.DeleteMemo` in `store/memo.go` explicitly removes rows from these three tables (no DB-level `ON DELETE CASCADE`):

```140:158:store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	// ...
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

1. **`memo_relation`** — deleted where the memo is source or target (`store/db/sqlite/memo_relation.go`: `DELETE FROM memo_relation`).
2. **`attachment`** — each linked attachment is removed via `DeleteAttachment` (`store/db/sqlite/attachment.go`: `DELETE FROM attachment`).
3. **`memo`** — the memo row itself (`store/db/sqlite/memo.go`: `DELETE FROM memo`).

The API handler in `server/router/api/v1/memo_service.go` may call `Store.DeleteMemo` recursively for comment memos first, but each call still only touches these three tables.

`Store.DeleteMemo` does **not** delete **`reaction`** or **`memo_share`** rows.
