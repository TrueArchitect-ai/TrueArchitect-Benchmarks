CEL (Common Expression Language, via `google/cel-go`) — `internal/filter/`; each dialect driver’s `ListMemos` calls `filter.AppendConditions` with its `DialectName` (`DialectSQLite`, `DialectPostgres`, or `DialectMySQL`), which compiles the CEL string through `Engine.CompileToStatement` and appends the rendered SQL fragments and bind args to the query `WHERE` clause.

The filter syntax is **CEL**, documented on the `filter` field in `proto/api/v1/memo_service.proto` (e.g. `content`, `creator_id`, `visibility`, `tags`, combined with `&&` / `||`).

The engine lives under **`internal/filter/`**:
- `internal/filter/engine.go` — `Engine` uses `cel-go` to compile filters
- `internal/filter/schema.go` — memo field schema and dialect constants
- `internal/filter/parser.go` — AST → condition tree
- `internal/filter/render.go` — condition tree → dialect-specific SQL
- `internal/filter/helpers.go` — `AppendConditions`

At request time, `ListMemos` in `server/router/api/v1/memo_service.go` validates via `validateFilter` (`server/router/api/v1/shortcut_service.go`) and stores the string in `memoFind.Filters`. Each driver (e.g. `store/db/sqlite/memo.go` lines 57–62) calls `filter.DefaultEngine()` and `filter.AppendConditions(..., filter.DialectSQLite, &where, &args)` to turn CEL into SQL for that dialect.
