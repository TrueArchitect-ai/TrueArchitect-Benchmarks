web/src/connect.ts; access token (Bearer) and refresh token (HTTP cookie); server/auth

The Connect **`authInterceptor`** in `web/src/connect.ts` (lines 156–178) runs on every API request via the shared transport (line 188). It:

1. Obtains an **access token** through `getRequestToken()` (from memory/`localStorage` via `web/src/auth-state.ts`)
2. Sets `Authorization: Bearer <access token>`
3. Refreshes proactively if the token is near expiry, or on `Unauthenticated` by calling `refreshToken` over a separate transport with `credentials: "include"` (lines 57–61, 74–82)
4. Retries the request once with the new token

**Token kinds the frontend manages:**

- **Access token (JWT)** — sent as a Bearer header; stored in `localStorage` (`web/src/auth-state.ts`)
- **Refresh token** — sent as an **HTTP cookie** (`fetch` uses `credentials: "include"`); used only to obtain new access tokens, not attached as a Bearer header

Backend validation is in **`server/auth`** (`Authenticator` in `server/auth/authenticator.go`), which validates JWT access tokens (`AuthenticateByAccessTokenV2`) and PATs (`AuthenticateByPAT`) from the Authorization header. Connect requests go through **`Authorizer`** / **`AuthInterceptor`** in `server/router/api/v1/authz.go` and `server/router/api/v1/connect_interceptors.go`, which delegate to `auth.Authenticator`.
