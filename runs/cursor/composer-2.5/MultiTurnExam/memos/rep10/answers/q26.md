**memo, memo_relation, attachment**

`Store.DeleteMemo` in `store/memo.go` explicitly cleans up related rows before deleting the memo:

```140:158:store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	// ...
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

Those map to:

- **`memo_relation`** — deleted when the memo is source (`memo_id`) or target (`related_memo_id`) (`store/db/sqlite/memo_relation.go`)
- **`attachment`** — deleted via `DeleteAttachment` (`store/db/sqlite/attachment.go`)
- **`memo`** — the row itself (`store/db/sqlite/memo.go`)

The API `DeleteMemo` handler in `server/router/api/v1/memo_service.go` also recursively calls `Store.DeleteMemo` for comment memos first, but each call still only touches these three tables.

`Store.DeleteMemo` does not delete **`reaction`**, **`memo_share`**, or **`inbox`** rows. `memo_share` has `ON DELETE CASCADE` in `store/migration/postgres/LATEST.sql`, but SQLite runs with foreign keys disabled (`store/db/sqlite/sqlite.go`), so that DB-level cascade is not active there.
