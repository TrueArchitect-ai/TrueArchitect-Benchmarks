**Premise correction:** This repository does not implement per-user API rate-limiting middleware. A repo-wide search finds no `RateLimit`/`Limiter` types, no rate-limit dependency in `go.mod`, and no HTTP 429 handling for request quotas.

**What is registered instead:** API traffic is wired in `server/server.go` and `server/router/api/v1/v1.go` with:

- Echo: `middleware.Recover()` and CORS (`server/server.go`, `server/cors.go`)
- gRPC-Gateway: `gatewayAuthMiddleware` (auth/anonymous access via `Authorizer`) in `server/router/api/v1/v1.go`
- Connect: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` in `server/router/api/v1/connect_interceptors.go` and `v1.go`
- Request body cap: `http.MaxBytesHandler(..., maxAPIRequestBytes)` where `maxAPIRequestBytes = 256 << 20` in `server/router/api/v1/v1.go`

The only “rate limit” mentions are future guidance for email sending in `internal/email/doc.go` and `internal/email/README.md`, not API middleware.

**Request limits:** There are no per-user request-rate limits (requests per second/minute, burst, etc.) in this codebase. Related limits that do exist are per-endpoint or resource caps (e.g. batch size checks in `server/router/api/v1/test/user_search_test.go`, pagination in `server/router/api/v1/common.go`, concurrent semaphores in `v1.go`), not user-scoped rate limiting.
