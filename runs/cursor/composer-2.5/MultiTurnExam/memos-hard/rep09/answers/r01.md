**Premise correction:** This repo does not use Redis for caching. A repo-wide search finds no Redis references.

**Actual mechanism:** The cache is an in-process, in-memory implementation in `store/cache/cache.go` (`sync.Map` + TTL). It is configured when `Store` is created in `store/store.go`:

```39:53:store/store.go
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}
	// ...
		userCache:            cache.New(cacheConfig),
```

User entries go into `userCache` via `userCache.Set()` in `store/user.go` (e.g. lines 122, 132, 143). `Set()` uses the cache’s `DefaultTTL`:

```92:94:store/cache/cache.go
func (c *Cache) Set(ctx context.Context, key string, value any) {
	c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)
}
```

So user cache entries use the same **10-minute TTL** as other caches (`instanceSettingCache`, `userSettingCache`). There is no separate user TTL and no Redis connection to configure.
