**Serving handler:** `serveUserAvatar` — `server/router/fileserver/fileserver.go`

The browser loads another user’s avatar via `<img src="/file/users/{username}/avatar">` (`web/src/components/UserAvatar.tsx`). That URL is set when user records are converted for the API: base64 avatars become `/file/{name}/avatar` (i.e. `/file/users/{username}/avatar`) in `convertUserFromStore` — `server/router/api/v1/user_service_converters.go`.

Hop chain from HTTP request to stored data:

```
RegisterRoutes (GET /file/users/:identifier/avatar) — server/router/fileserver/fileserver.go
serveUserAvatar — server/router/fileserver/fileserver.go
getUserByUsername — server/router/fileserver/fileserver.go
Store.GetUser — store/user.go
Store.ListUsers — store/user.go
DB.ListUsers — store/db/sqlite/user.go (also store/db/mysql/user.go, store/db/postgres/user.go)
SQL SELECT … avatar_url … FROM user — store/db/sqlite/user.go
user.avatar_url column — store/migration/sqlite/LATEST.sql
```

After the row is read, `serveUserAvatar` decodes the stored base64 data URI via `parseDataURI` and returns the bytes with `c.Blob` — both in `server/router/fileserver/fileserver.go`.

On a private instance (no public `instance_url`), `serveUserAvatar` first calls `getCurrentUser` → `authenticator.AuthenticateToUser` (`server/router/fileserver/fileserver.go`, `server/auth/authenticator.go`) before loading the user row.

Route registration at startup: `fileServerService.RegisterRoutes(echoServer)` — `server/server.go`.
