**1st: `store.User`; 2nd: `store.Memo` (~7 and ~6 external packages)**

Persistent entity types live in the `store` package (e.g. `User` in `store/user.go`, `Memo` in `store/memo.go`). Counting distinct Go packages outside `store/` that reference `store.User` or `store.Memo` (via `store.Type`):

| Rank | Type | External packages (approx.) |
|------|------|----------------------------|
| 1st | `store.User` | ~7 |
| 2nd | `store.Memo` | ~6 |

**`store.User` (~7 packages):**
- `server/auth`
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/fileserver`
- `server/router/frontend` (test file only)
- `server/router/rss`

**`store.Memo` (~6 packages):**
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test`
- `server/router/frontend` (test file only)
- `server/router/rss`
- `server/runner/memopayload`

Excluding test-only packages (`*/test/*`, `*_test.go`), the counts are roughly **5** for `User` and **4** for `Memo`; the ranking is unchanged.

**Methodology:** Searched for `store.User` and `store.Memo` in all `.go` files outside `store/`, `web/`, and `proto/gen/`, then counted unique package directories. Other table-mapped types (`Attachment`, `Reaction`, `Inbox`, etc.) appear in fewer packages; proto-backed settings types (`storepb.IdentityProvider`, etc.) are used instead of the Go `store` structs in outer layers.
