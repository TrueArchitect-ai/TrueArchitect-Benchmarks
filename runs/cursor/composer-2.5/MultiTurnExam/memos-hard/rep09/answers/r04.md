**Premise correction:** Webhook delivery does not use NATS or RabbitMQ. There are no references to either broker in Go code or in `go.mod`.

**Actual mechanism:** Delivery is in-process via a buffered Go channel and fixed worker goroutines in `internal/webhook/webhook.go`:

```39:54:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
)

func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

The “queue” is `asyncPostQueue` — a channel with capacity **128**, declared at package init in `internal/webhook/webhook.go`. Producers call `PostAsync()` (same file), which enqueues payloads; four goroutines started in `init()` consume from the channel and call `Post()` for synchronous HTTP delivery.

Callers enqueue from memo webhook helpers in `server/router/api/v1/memo_service_webhooks.go` via `webhook.PostAsync(payload)`. There is no external broker queue declaration.
