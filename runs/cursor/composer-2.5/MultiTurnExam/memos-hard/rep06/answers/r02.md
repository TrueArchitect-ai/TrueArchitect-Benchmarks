**Premise correction:** This repository does not register per-user API rate-limiting middleware, and there are no configured per-user request limits for that purpose.

On the main Echo server, only recovery and CORS middleware are registered (`server/server.go`, `server/cors.go`). The API gateway uses auth/authorizer middleware (`server/router/api/v1/v1.go`), not rate limiting. A repo-wide search finds no `RateLimiter`, rate-limit middleware, or HTTP 429 handling tied to per-user API throttling.

Limits that do exist are unrelated to per-user API rate limiting: memo content length (`server/router/api/v1/memo_service.go`), upload size (`server/router/api/v1/attachment_service.go`), pagination caps, RSS item counts, and concurrency semaphores for thumbnails/image processing (`server/router/api/v1/v1.go`). None of these implement per-user API request rate limits.
