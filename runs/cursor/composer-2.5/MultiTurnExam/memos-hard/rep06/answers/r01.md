**Premise correction:** This repository does not configure a Redis connection for caching. A repo-wide search finds no Redis client, URL, or dependency; the cache layer is an in-process memory cache.

**Actual mechanism:** `store.New` builds three `*cache.Cache` instances (`userCache`, `userSettingCache`, `instanceSettingCache`) using `cache.New` with a shared `cache.Config` in ```38:53:store/store.go```. The implementation is a thread-safe in-memory `sync.Map` cache in ```66:73:store/cache/cache.go```, not Redis.

**User entry TTL:** **10 minutes**. `userCache` uses the shared `DefaultTTL: 10 * time.Minute` (```40:41:store/store.go```, also ```57:59:store/cache/cache.go```). User rows are stored via `userCache.Set` (e.g. ```150:167:store/user.go```), which calls `SetWithTTL` with that default TTL (```92:94:store/cache/cache.go```). Expired entries are removed on read and by a background cleanup loop every **5 minutes** (`CleanupInterval`, ```42:42:store/store.go```).
