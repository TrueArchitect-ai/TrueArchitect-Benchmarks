The browser loads `/file/users/{username}/avatar` (set in API responses by `convertUserFromStore` at `server/router/api/v1/user_service_converters.go:36`, then used as `<img src>` in `web/src/components/UserAvatar.tsx:14`). That GET is handled as follows:

RegisterRoutes — `server/router/fileserver/fileserver.go`  
serveUserAvatar — `server/router/fileserver/fileserver.go`  
getCurrentUser — `server/router/fileserver/fileserver.go` (private instances only; auth before serving)  
getUserByUsername — `server/router/fileserver/fileserver.go`  
Store.GetUser — `store/user.go`  
Store.ListUsers — `store/user.go`  
(*DB).ListUsers — `store/db/sqlite/user.go` (same pattern in `store/db/mysql/user.go`, `store/db/postgres/user.go`)  
SQL SELECT `avatar_url` FROM `user` WHERE `username = ?` — `store/db/sqlite/user.go`  
`user.avatar_url` column — `store/migration/sqlite/LATEST.sql`  
parseDataURI — `server/router/fileserver/fileserver.go`  
c.Blob — `server/router/fileserver/fileserver.go` (returns decoded image bytes to the browser)

Routes are wired at server startup in `server/server.go:81-82`. Avatars are stored as data URIs in `user.avatar_url`, not as separate files; `serveUserAvatar` reads that column and decodes it before responding.
