**Premise correction:** This repo does not use Redis for caching. A repo-wide search finds no Redis client, config, or connection strings.

**Actual mechanism:** Caching is in-process memory via `store/cache.Cache`, wired in `store/store.go` when `Store` is created. User entries go into `userCache` with the shared default TTL of **10 minutes**.

Configuration is set in `store.New`:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}
	// ...
		userCache:            cache.New(cacheConfig),
```

The cache implementation is an in-memory `sync.Map` with TTL, not Redis:


User entries are stored via `userCache.Set`, which uses the cache’s default TTL (no per-user override):

```92:95:store/cache/cache.go

	c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)
```

**Summary:** No Redis connection exists. User cache TTL is **10 minutes**, from `cache.Config.DefaultTTL` in `store/store.go`, applied through `store/cache/cache.go`. Expired entries are removed on read and by a background cleanup every **5 minutes** (`CleanupInterval`).
