h07.
The browser loads another user's avatar via `<img src={avatarUrl}>` in `web/src/components/UserAvatar.tsx`. That URL comes from the API as `/file/users/{username}/avatar` (rewritten from a stored data URI in `convertUserFromStore` — `server/router/api/v1/user_service_converters.go`).

Request path to stored data:

RegisterRoutes — `server/router/fileserver/fileserver.go`  
serveUserAvatar — `server/router/fileserver/fileserver.go`  
getUserByUsername — `server/router/fileserver/fileserver.go`  
GetUser — `store/user.go`  
ListUsers — `store/user.go`  
ListUsers — `store/db/sqlite/user.go` (same pattern in `store/db/mysql/user.go` and `store/db/postgres/user.go`)  
`user.avatar_url` — `store/migration/sqlite/LATEST.sql`

**Details**

1. **Route wiring:** `FileServerService.RegisterRoutes` maps `GET /file/users/:identifier/avatar` to `serveUserAvatar` (`server/router/fileserver/fileserver.go:121-124`), registered from `server/server.go:81-82`.

2. **Handler:** `serveUserAvatar` reads `:identifier` as the username, optionally requires auth on private instances, loads the user, and decodes `user.AvatarURL` (a base64 data URI) with `parseDataURI` before responding (`server/router/fileserver/fileserver.go:167-209`).

3. **Store lookup:** `getUserByUsername` calls `Store.GetUser(ctx, &store.FindUser{Username: &identifier})` (`server/router/fileserver/fileserver.go:714-716`).

4. **Store layer:** `GetUser` delegates to `ListUsers`, which calls the DB driver (`store/user.go:148-168`, `136-145`).

5. **Driver / SQL:** `ListUsers` runs `SELECT ... avatar_url ... FROM user WHERE username = ?` (`store/db/sqlite/user.go:151-173`).

6. **Storage:** Avatar image bytes live in the `avatar_url` TEXT column on the `user` table (`store/migration/sqlite/LATEST.sql:20`); they are not separate attachment files.
