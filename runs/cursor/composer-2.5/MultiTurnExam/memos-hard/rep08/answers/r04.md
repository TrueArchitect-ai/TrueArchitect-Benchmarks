**Premise correction:** Webhook delivery does not use NATS or RabbitMQ. A repo-wide search finds no NATS, RabbitMQ, AMQP, Kafka, or similar broker client or dependency.

**Actual mechanism:** Delivery is in-process via a bounded Go channel and fixed worker pool in `internal/webhook/webhook.go`.

The queue is declared as a package-level buffered channel:

```39:39:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are started in `init()` and consume from that channel, calling `Post` for each payload:

```42:55:internal/webhook/webhook.go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

Producers enqueue via `PostAsync`, which sends to `asyncPostQueue` (or drops the payload if the buffer is full):

```182:195:internal/webhook/webhook.go

	default:

```

RPC handlers trigger delivery through `webhook.PostAsync` in `server/router/api/v1/memo_service_webhooks.go`. HTTP dispatch itself is synchronous `Post` in the same file, using `safeClient` with SSRF-safe dialing.
