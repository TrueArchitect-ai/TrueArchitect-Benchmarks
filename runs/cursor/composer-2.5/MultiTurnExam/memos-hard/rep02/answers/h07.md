Profile images stored as base64 data URIs are exposed to the browser as `/file/users/{username}/avatar` (set in `convertUserFromStore` in `server/router/api/v1/user_service_converters.go`), then loaded via `<img src={avatarUrl}>` in `web/src/components/UserAvatar.tsx`. The HTTP serving chain is:

RegisterRoutes — `server/router/fileserver/fileserver.go`  
serveUserAvatar — `server/router/fileserver/fileserver.go`  
getUserByUsername — `server/router/fileserver/fileserver.go`  
Store.GetUser — `store/user.go`  
Store.ListUsers — `store/user.go`  
DB.ListUsers — `store/db/sqlite/user.go` (or `store/db/mysql/user.go` / `store/db/postgres/user.go`, depending on configured driver)  
parseDataURI — `server/router/fileserver/fileserver.go`  
c.Blob — `server/router/fileserver/fileserver.go`

**Details:**

1. **Route wiring** — `RegisterRoutes` binds `GET /file/users/:identifier/avatar` to `serveUserAvatar` (`server/router/fileserver/fileserver.go:121–124`), registered from `server/server.go:81–82`.

2. **Handler** — `serveUserAvatar` reads `:identifier` (username), optionally checks auth on private instances via `getCurrentUser`, loads the user, parses `user.AvatarURL`, and returns the decoded bytes.

3. **User lookup** — `getUserByUsername` calls `Store.GetUser` with `FindUser{Username: &identifier}` (`server/router/fileserver/fileserver.go:714–716`).

4. **Store layer** — `Store.GetUser` delegates to `Store.ListUsers` (username lookups bypass the ID cache) (`store/user.go:148–168`).

5. **Data layer** — `DB.ListUsers` runs `SELECT … avatar_url … FROM user WHERE username = ?` and scans into `user.AvatarURL` (`store/db/sqlite/user.go:151–189`; same pattern in mysql/postgres drivers).

6. **Response** — `parseDataURI` decodes the `data:image/…;base64,…` string from `avatar_url`; `c.Blob` sends the image to the browser (`server/router/fileserver/fileserver.go:196–209`).

**Stored data:** the `avatar_url` column on the `user` table (`store/migration/sqlite/LATEST.sql`), holding a data URI—not a separate filesystem object. If `avatar_url` is an external URL (not a data URI), `convertUserFromStore` leaves it unchanged and the browser fetches it directly, outside this `/file/…/avatar` path.
