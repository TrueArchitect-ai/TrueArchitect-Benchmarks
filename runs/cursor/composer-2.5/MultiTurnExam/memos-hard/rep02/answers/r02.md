**Premise correction:** This repository does not register per-user API rate-limiting middleware, and there are no configured per-user request limits for the HTTP/RPC API.

A repo-wide search finds no rate-limiter middleware, no `rate.Limiter` (or similar) on API routes, and no per-user quota settings. What *is* registered on the server:

- **Global Echo middleware** in `server/server.go`: `middleware.Recover()` and `newCORSMiddleware` (`server/cors.go`) — panic recovery and CORS only.
- **API auth**, not throttling: gRPC-Gateway `gatewayAuthMiddleware` and Connect interceptors (`MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor`) in `server/router/api/v1/v1.go` and `server/router/api/v1/connect_interceptors.go`.
- **Request body cap**, not rate limit: `http.MaxBytesHandler(..., maxAPIRequestBytes)` with `maxAPIRequestBytes = 256 << 20` (256 MiB) in `server/router/api/v1/v1.go`.
- **Concurrency caps** for thumbnail/image work via semaphores in `APIV1Service` (`server/router/api/v1/v1.go`) — not per-user API request limits.

The only rate-limit mention in the codebase is documentation for **outbound email** (`internal/email/doc.go`, `internal/email/README.md`), not inbound API traffic. Per-user API rate limiting would need to be added externally (e.g., reverse proxy) or implemented in the application; it is not present here.
