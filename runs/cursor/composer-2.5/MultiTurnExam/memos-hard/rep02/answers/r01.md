**Premise correction:** This repository does not use Redis for caching. A repo-wide search finds no Redis references; the cache layer is an in-process, in-memory implementation.

**Actual mechanism:** Caching is configured when `store.New` builds three `cache.Cache` instances in `store/store.go`, using a shared `cache.Config` with **`DefaultTTL: 10 * time.Minute`**, **`CleanupInterval: 5 * time.Minute`**, and **`MaxItems: 1000`**. The cache itself is `store/cache/cache.go` — a thread-safe `sync.Map`-backed structure with a background cleanup goroutine, not an external store.

User entries go into `userCache`, created with that same config:

```39:53:store/store.go

		OnEviction:      nil,
	}
	// ...
		userCache:            cache.New(cacheConfig),
```
