The browser loads another user's avatar at `GET /file/users/{username}/avatar` (URL built in `server/router/api/v1/user_service_converters.go:36`). Image bytes live in the `user.avatar_url` column as a base64 data URI, not as a separate file.

**Notes:**
- Route wiring: `RegisterRoutes` registers `/file/users/:identifier/avatar` (`fileserver.go:121-124`), called from `server.NewServer` (`server/server.go:81-82`).
- `getCurrentUser` runs only on private instances (`fileserver.go:173-180`); it calls `auth.Authenticator.AuthenticateToUser` (`fileserver.go:708-711`).
- `getUserByUsername` calls `Store.GetUser` with `FindUser.Username` (`fileserver.go:715-716`).
- `Store.GetUser` delegates to `ListUsers` when there is no ID cache hit (`store/user.go:148-168`).
- `ListUsers` runs `SELECT ... avatar_url ... FROM user` (`store/db/sqlite/user.go:151-165`); schema column is `avatar_url` in `store/migration/sqlite/LATEST.sql:20`.
- `parseDataURI` decodes the stored data URI from `user.AvatarURL`; `c.Blob` returns the image (`fileserver.go:196-209`).
