**1st: User (~5–6 packages); 2nd: Memo (~4 packages)**

Persistent entity types live as Go structs in the top-level `store/` package (e.g. `User` in `store/user.go`, `Memo` in `store/memo.go`, `Attachment` in `store/attachment.go`). The data layer is `store/` and its subpackages (`store/db/`, `store/cache/`, etc.).

Counting non-test references to `store.<Type>` from packages outside `store/`:

| Rank | Type | External packages (approx.) | Packages |
|---|---|---|---|
| **1st** | **User** | **~5–6** | `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/fileserver`, `server/router/rss` (+ `server/router/api/v1/test` if test packages count) |
| **2nd** | **Memo** | **~4** | `server/notification`, `server/router/api/v1`, `server/router/rss`, `server/runner/memopayload` |
| 3rd | Attachment | ~3 | `server/router/api/v1`, `server/router/fileserver`, `server/router/rss` |

**Evidence:** `store.User` appears across auth (`server/auth/authenticator.go`), notifications (`server/notification/email.go`), the API layer (`server/router/api/v1/user_service.go` and related files), file serving (`server/router/fileserver/fileserver.go`), and RSS (`server/router/rss/rss.go`). `store.Memo` is referenced in notification, API v1 memo handlers, RSS, and the memo payload runner (`server/runner/memopayload/runner.go`).

Other store entities (`Inbox`, `MemoShare`, `Attachment`, etc.) reach fewer external packages; `IdentityProvider`, `UserSetting`, and `InstanceSetting` are not referenced as `store.<Type>` outside the data layer (those areas use `storepb` protobuf types instead).
