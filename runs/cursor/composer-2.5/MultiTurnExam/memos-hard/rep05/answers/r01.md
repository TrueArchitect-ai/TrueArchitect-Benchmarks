**Premise correction:** There is no Redis connection for the cache layer in this repository (a repo-wide search finds no Redis references).

**Actual mechanism:** The cache is an in-process TTL cache in `store/cache/cache.go`. It is configured when the store is created in `store/store.go`: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (lines 40–45). The same config is passed to `userCache` via `cache.New(cacheConfig)` (`store/store.go:52`). User entries are stored with that default TTL through `userCache.Set` in `store/user.go` (e.g. `CreateUser`, `GetUser`), which calls `Cache.Set` and therefore `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:92-94`). So user cache TTL is **10 minutes**, with expired entries removed on access and by a background cleanup loop every 5 minutes (`store/cache/cache.go:199-214`).
