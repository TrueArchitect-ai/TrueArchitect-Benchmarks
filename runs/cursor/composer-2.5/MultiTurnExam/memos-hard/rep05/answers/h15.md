Memo visibility is not enforced in one place. The main patterns are:

1. **Per-memo read checks** — `checkMemoReadAccess` (`memo_service.go:39-67`) used by `GetMemo`, `ListMemoComments`, etc.
2. **List/query filtering** — `ListMemos` applies `VisibilityList` and CEL filters (`memo_service.go:218-226`); similar filters appear in comments, relations, and stats handlers.
3. **Sub-resource handlers** — attachments, reactions, and comments each re-check visibility inline or via shared helpers.
4. **Non-gRPC HTTP surfaces** — the file server checks memo visibility when serving linked attachments (`fileserver.go:649-703`); RSS and the frontend sitemap only load `store.Public` memos (`rss.go:88-90`, `frontend.go:149-150`).

**Note:** Share links use a separate access path (`GetMemoByShare` in `memo_share_service.go`, share tokens in `fileserver.go:684-688`) rather than normal visibility rules.
