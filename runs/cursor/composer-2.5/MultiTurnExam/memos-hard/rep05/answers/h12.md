**How the running implementation was chosen**

1. **Default driver is SQLite** — `cmd/memos/main.go` sets `viper.SetDefault("driver", "sqlite")` and the `--driver` flag default is `"sqlite"` (lines 122, 130). With no DB flags, `profile.Driver` stays `"sqlite"`.

2. **Factory selects the SQLite driver** — `db.NewDBDriver` in `store/db/db.go` switches on `profile.Driver`; the `"sqlite"` branch calls `sqlite.NewDB(profile)` (lines 18–20). MySQL and Postgres branches are not taken.

3. **Call chain reaches that concrete method** — saving a memo goes:
   - `APIV1Service.CreateMemo` → `s.Store.CreateMemo` (`server/router/api/v1/memo_service.go:115`)
   - `Store.CreateMemo` → `s.driver.CreateMemo` (`store/memo.go:109-113`)
   - interface method on `store.Driver` (`store/driver.go:29`)
   - SQLite implementation `(*DB).CreateMemo` (`store/db/sqlite/memo.go:16`)

4. **Why not the other candidates** — `(*DB).CreateMemo` also exists in `store/db/mysql/memo.go:16` and `store/db/postgres/memo.go:16`, but those are only wired when `--driver mysql` or `--driver postgres` is set. Default install never selects them via `store/db/db.go`.
