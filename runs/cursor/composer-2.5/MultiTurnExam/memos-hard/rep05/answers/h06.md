**handlers:** `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` (also `GetLinkMetadata` / `BatchGetLinkMetadata` for user-supplied link URLs, via a separate path); **convergence function:** `webhook.PostAsync` — `internal/webhook/webhook.go`

Memo RPC handlers trigger outbound HTTP to user-configured webhook URLs through the dispatch helpers in `server/router/api/v1/memo_service_webhooks.go`:

| Handler | Path |
|---|---|
| `CreateMemo` | `DispatchMemoCreatedWebhook` → `dispatchMemoRelatedWebhook` (`memo_service.go:157`) |
| `UpdateMemo` | `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` (`memo_service.go:513`) |
| `DeleteMemo` | `DispatchMemoDeletedWebhook` (`memo_service.go:562`) |
| `CreateMemoComment` | `DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`); also calls `CreateMemo` internally, which can fire `memos.memo.created` |
| `SetMemoAttachments` | `dispatchMemoUpdatedSideEffects` (`memo_attachment_service.go:48`) |
| `SetMemoRelations` | `dispatchMemoUpdatedSideEffects` (`memo_relation_service.go:48`) |

Those webhook paths converge at `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues payloads whose `URL` comes from user webhook settings (`memo_service_webhooks.go:41-42,67-71`). Background workers then call `webhook.Post` (`internal/webhook/webhook.go:46`) for the actual HTTP POST.

Separately, `GetLinkMetadata` and `BatchGetLinkMetadata` fetch user-supplied URLs via `getLinkMetadata` → `fetchHTMLMeta` (`memo_service_link_metadata.go:15-46`), converging on `httpgetter.GetHTMLMeta` rather than the webhook pipeline.
