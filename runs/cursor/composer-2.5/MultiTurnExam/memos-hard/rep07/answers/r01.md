**Premise correction:** This repository does not configure a Redis connection for caching. A repo-wide search finds no Redis references; the cache is an in-process implementation.

**Actual mechanism:** User caching is set up in `store/store.go` when `store.New` creates `userCache` via `cache.New(cacheConfig)` (`store/store.go:28-29, 52-53`). The backend is the thread-safe in-memory `cache.Cache` in `store/cache/cache.go:66-73`, backed by a `sync.Map` with TTL-based expiry.

User entries use the shared `cacheConfig.DefaultTTL` of **10 minutes** (`store/store.go:40-41`, also `store/cache/cache.go:57-59`). `store/user.go` stores users with `s.userCache.Set(...)`, which calls `SetWithTTL` with that default (`store/cache/cache.go:92-94`); there is no separate user-specific TTL override.
