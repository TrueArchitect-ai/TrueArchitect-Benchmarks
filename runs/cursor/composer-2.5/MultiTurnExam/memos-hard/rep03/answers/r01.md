**Premise correction:** This repo does not use Redis for caching. A repo-wide search finds no Redis references; the cache layer is an in-process memory cache.

**Actual mechanism:** Cache behavior is configured in `store/store.go` when `Store` is created. Three `*cache.Cache` instances (`instanceSettingCache`, `userCache`, `userSettingCache`) are built with a shared `cache.Config` whose `DefaultTTL` is **10 minutes**:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}
	// ...
		userCache:            cache.New(cacheConfig),
```

The cache implementation is in `store/cache/cache.go`: a thread-safe in-memory `sync.Map` with TTL expiry, not a remote store. `Set` applies `DefaultTTL`:

```92:95:store/cache/cache.go
func (c *Cache) Set(ctx context.Context, key string, value any) {
	c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)
}
```

User entries go through `userCache.Set` in `store/user.go` (e.g. after create/update/list/get), which uses that default TTL — there is no separate user-specific TTL override. Expired entries are removed on read and by a background cleanup loop every `CleanupInterval` (5 minutes), also set in `store/store.go`.
