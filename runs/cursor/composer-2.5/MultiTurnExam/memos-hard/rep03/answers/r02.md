**Premise correction:** This repository does not implement per-user API rate-limiting middleware. A codebase search finds no rate limiter, token bucket, or request-quota middleware, and no dependency wired for that purpose.

**What is registered instead:**

Global Echo middleware in `server/server.go` is only `middleware.Recover()` and `newCORSMiddleware()` — no rate limiting:

```50:52:server/server.go
	echoServer := echo.New()
	echoServer.Use(middleware.Recover())
	echoServer.Use(newCORSMiddleware(profile))
```

API traffic goes through `APIV1Service.RegisterGateway()` in `server/router/api/v1/v1.go`:

- **gRPC-Gateway:** `gatewayAuthMiddleware` (authentication/authorization via `Authorizer` in `server/router/api/v1/authz.go`), plus `http.MaxBytesHandler(..., maxAPIRequestBytes)` where `maxAPIRequestBytes = 256 << 20` (256 MiB request body cap — not a per-user request rate).
- **Connect RPC:** interceptors in `server/router/api/v1/connect_interceptors.go` — `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` — again, no rate limiting.

The only “rate limit” mention is a comment in `internal/email/doc.go` about limiting email sends; it is not implemented HTTP middleware.

**Conclusion:** There is nowhere a per-user API rate-limit middleware is registered, and there are no per-user request limits (requests/minute, burst, etc.) defined in this codebase. Any such protection would need to live outside the app (e.g. reverse proxy) or be added here.
