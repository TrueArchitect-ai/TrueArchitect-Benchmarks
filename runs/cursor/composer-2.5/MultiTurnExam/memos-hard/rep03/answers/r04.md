**Premise correction:** Webhook delivery does not use NATS or RabbitMQ. There are no references to either broker in the Go codebase or in `go.mod`, and there are no external webhook delivery workers consuming from a message queue.

**Actual mechanism:** Delivery is in-process via a buffered Go channel and four goroutine workers in `internal/webhook/webhook.go`.

The queue is declared as a package-level channel with capacity 128:

```39:40:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
)
```

Workers are started in `init()` — four goroutines read from that channel and call `Post()`:

```42:55:internal/webhook/webhook.go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

Producers enqueue via `PostAsync()`, which sends to `asyncPostQueue` (or drops the payload if the channel is full):

```182:196:internal/webhook/webhook.go
func PostAsync(requestPayload *WebhookRequestPayload) {
	// ...
	select {
	case asyncPostQueue <- requestPayload:
	default:
		slog.Warn("Dropped webhook dispatch because the async queue is full",
			// ...
		)
	}
}
```

Memo-related RPC handlers trigger dispatch from `server/router/api/v1/memo_service_webhooks.go` (e.g. `DispatchMemoCreatedWebhook`, `DispatchMemoUpdatedWebhook`), which call `webhook.PostAsync(payload)`. Actual HTTP delivery is synchronous inside each worker via `Post()` using `safeClient` in the same file — not via a broker.
