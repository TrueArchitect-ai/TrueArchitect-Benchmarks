Memo visibility is enforced in multiple places, not only in one shared helper.

**API memo read (per-memo):** `checkMemoReadAccess` blocks non-public memos for unauthenticated callers and private memos for non-creators (`server/router/api/v1/memo_service.go:39-67`). Used by `GetMemo`, `ListMemoComments`, etc.

**API memo list (query-time):** `ListMemos` restricts results with `VisibilityList` and CEL filters for anonymous vs authenticated users (`server/router/api/v1/memo_service.go:218-226`).

**API attachments:** `checkAttachmentAccess` applies memo visibility rules to linked attachments (`server/router/api/v1/attachment_service.go:419-454`).

**HTTP file serving:** `checkAttachmentPermission` in the file server enforces the same rules (plus share-token bypass) when serving attachment bytes (`server/router/fileserver/fileserver.go:649-703`).

**Reactions:** `UpsertMemoReaction` / related handlers re-check visibility inline (`server/router/api/v1/reaction_service.go:29-39`, `:82-84`).

**Memo attachments API:** `ListMemoAttachments` has its own visibility block (`server/router/api/v1/memo_attachment_service.go:213-224`).

**Comments:** `CreateMemoComment` checks the parent memo before allowing a comment (`server/router/api/v1/memo_service_comments.go:33-42`).

**Notifications & email:** separate `canViewerAccessMemo` helpers gate inbox payloads and email content (`server/router/api/v1/user_service_notifications.go:302-316`, `server/notification/email.go:306+`).

**Mentions:** `canUserAccessMentionContext` skips mentions the target user could not view (`server/router/api/v1/memo_mention_helpers.go:56-71`).

**RSS & sitemap:** only `PUBLIC` memos are queried (`server/router/rss/rss.go:88-90`, `server/router/frontend/frontend.go:149-150`).

**User stats:** stats endpoints scope memo queries the same way as list (`server/router/api/v1/user_service_stats.go:84-90`, `:218-220`).
