**1st: `User` (~5 packages); 2nd: `Memo` (~4 packages)**

Persistent entity types live in the `store/` package (e.g. `User` in `store/user.go`, `Memo` in `store/memo.go`). I counted distinct Go packages **outside `store/`** that reference each type as `store.Type` or `*store.Type`, excluding test files and test directories.

| Rank | Type | Definition | External packages (≈count) |
|---|---|---|---|
| **1st** | **`User`** | `store/user.go` | **5** — `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/fileserver`, `server/router/rss` |
| **2nd** | **`Memo`** | `store/memo.go` | **4** — `server/notification`, `server/router/api/v1`, `server/router/rss`, `server/runner/memopayload` |

**3rd:** `Attachment` (~3) — `server/router/api/v1`, `server/router/fileserver`, `server/router/rss`

Other entity types (`Reaction`, `Inbox`, `MemoShare`, `UserIdentity`, etc.) are referenced from fewer packages (1–2). `UserSetting`, `IdentityProvider`, and `InstanceSetting` had no `store.<Type>` references outside `store/` in non-test code (server code uses protobuf store types or API types instead).

**Checked:** all `type` declarations in `store/*.go` (excluding `store/db/`, `store/test/`, `store/cache/`), then repo-wide grep for `store.<EntityName>` outside `store/`.
