**Premise correction:** This repository does not register per-user API rate-limiting middleware, and there are no configured per-user request limits for the API.

Echo middleware in `server/server.go` is limited to recovery and CORS:

```50:52:server/server.go
	echoServer := echo.New()
	echoServer.Use(middleware.Recover())
	echoServer.Use(newCORSMiddleware(profile))
```

The API layer uses auth middleware/interceptors (`gatewayAuthMiddleware` in `server/router/api/v1/v1.go`, `Authorizer` in `server/router/api/v1/authz.go`), not rate limiting.

A repo-wide search for `rate limit`, `ratelimit`, `RateLimit`, `throttle`, and `limiter` in Go code finds no API rate-limiting implementation. The only related mention is a comment in `internal/email/doc.go` about possibly rate-limiting email sends — not HTTP API middleware.

There are concurrency caps (e.g. `thumbnailSemaphore` and `imageProcessingSemaphore` in `server/router/api/v1/v1.go`), but those limit concurrent thumbnail/image work, not requests per user over time.
