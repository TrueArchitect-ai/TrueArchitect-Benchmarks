**Premise correction:** There is no Redis connection for the cache layer. A search of the repository finds no Redis client, URL, or configuration anywhere.

**Actual mechanism:** Caching is an in-process, in-memory layer in `store/cache/cache.go` (`sync.Map` plus per-entry expiration). It is wired when the store is created in `store/store.go`: `Store.New` builds a shared `cache.Config` and instantiates three caches (`instanceSettingCache`, `userCache`, `userSettingCache`) via `cache.New(cacheConfig)`.

User entries go through `userCache` in `store/user.go` (`CreateUser`, `UpdateUser`, `GetUser`, etc.), which calls `userCache.Set(...)` with no custom TTL. That uses the cache default from `cache.Cache.Set` → `SetWithTTL(..., c.config.DefaultTTL)`.

**User-entry TTL:** **10 minutes**, set in `store/store.go` (`DefaultTTL: 10 * time.Minute`) and mirrored in `store/cache/cache.go` (`DefaultConfig()`). Cleanup runs every 5 minutes (`CleanupInterval: 5 * time.Minute`).
