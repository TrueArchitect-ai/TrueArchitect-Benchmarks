**Premise correction:** This repository does not implement or register per-user API rate-limiting middleware. There is no rate-limit middleware, no `x/time/rate` (or similar) usage, and no HTTP 429 / “too many requests” handling in the server code.

What is registered instead:

- Global Echo middleware in `server/server.go`: `middleware.Recover()` and `newCORSMiddleware()` (CORS only).
- API auth (not rate limiting) in `server/router/api/v1/v1.go`:
  - `gatewayAuthMiddleware` on the gRPC-Gateway mux
  - Connect interceptors in `server/router/api/v1/connect_interceptors.go`: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor`
- A request **body size** cap via `http.MaxBytesHandler(..., maxAPIRequestBytes)` in `server/router/api/v1/v1.go` (`maxAPIRequestBytes = 256 << 20`), which is not per-user request-rate limiting.

There are therefore no per-user API request limits (requests/sec, burst, etc.) to report.
