**CEL (via `github.com/google/cel-go`) + `internal/filter/`** (`engine.go`, `parser.go`, `render.go`, `schema.go`; documented in `proto/api/v1/memo_service.proto`).

The filter string is compiled by `cel-go` into a CEL AST, walked in `internal/filter/parser.go` to build a dialect-agnostic condition tree (`internal/filter/ir.go`), then rendered in `internal/filter/render.go` into a SQL `WHERE` fragment for the active dialect (SQLite, MySQL, or Postgres) using field/column metadata from `internal/filter/schema.go`, with each dialect’s store layer (e.g. `store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`) calling `filter.AppendConditions` / `filter.DefaultEngine().CompileToStatement` with the matching `filter.Dialect*` constant to append that SQL and its bound args to the list query.
