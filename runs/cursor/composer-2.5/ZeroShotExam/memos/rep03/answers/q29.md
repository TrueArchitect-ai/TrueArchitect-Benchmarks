**`web/src/connect.ts`**; **JWT access token** (sent as `Authorization: Bearer`, stored in `web/src/auth-state.ts`) and **refresh token** (HttpOnly cookie, used via `credentials: "include"` when calling `refreshToken`); **`server/auth`**

Frontend API calls go through Connect RPC clients in `web/src/connect.ts`. The `authInterceptor` there calls `getRequestToken()` to attach a Bearer access token, proactively refreshes it when near expiry, and on `Unauthenticated` retries once after `refreshAccessToken()`. Refresh uses a separate transport without the interceptor and relies on the browser sending the refresh cookie. Token state lives in `web/src/auth-state.ts` (access token in memory/localStorage; refresh token is cookie-only).

On the backend, `server/router/api/v1/connect_interceptors.go` defines `AuthInterceptor`, which delegates to `Authorizer.Authenticate()` and ultimately `server/auth.Authenticator.Authenticate()` in `server/auth/authenticator.go`. That package validates JWT access tokens and personal access tokens from the `Authorization` header (`server/auth/token.go`).
