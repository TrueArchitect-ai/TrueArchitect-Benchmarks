When a memo is deleted through the API, the handler in `server/router/api/v1/memo_service.go` calls `Store.DeleteMemo`. In the store layer (`store/memo.go`), these record kinds are deleted **before** the memo row itself:

- **`memo_relation`** — relations where the memo is the source (`MemoID`) and where it is the target (`RelatedMemoID`)
- **`attachment`** — attachments linked to the memo (`MemoID`)

Only after that does it call `s.driver.DeleteMemo` to remove the memo row (see `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, and `store/db/mysql/memo.go`).

Note: the API also deletes comment memos first by calling `Store.DeleteMemo` on each comment (`server/router/api/v1/memo_service.go`), but those are other **memo** rows, not separate record kinds cleaned up inside `Store.DeleteMemo`. The store layer does **not** delete reactions or memo shares as part of `DeleteMemo`.
