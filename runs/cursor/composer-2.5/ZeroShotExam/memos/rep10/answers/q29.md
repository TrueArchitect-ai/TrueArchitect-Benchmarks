**`web/src/connect.ts`; access token (JWT) and refresh token (HTTP cookie); `server/auth`**

The frontend auth interceptor is `authInterceptor` in `web/src/connect.ts`. It is registered on the Connect transport and runs on every RPC call:

```156:189:web/src/connect.ts
const authInterceptor: Interceptor = (next) => async (req) => {
  const isRetryAttempt = req.header.get(RETRY_HEADER) === RETRY_HEADER_VALUE;
  const token = await getRequestToken();
  setAuthorizationHeader(req, token);
  // ... refresh on 401 and retry ...
};

const transport = createConnectTransport({
  baseUrl: window.location.origin,
  useBinaryFormat: true,
  fetch: fetchWithCredentials,
  interceptors: [authInterceptor],
});
```

**Tokens it manages:**

1. **Access token (JWT)** — read from in-memory/`localStorage` via `web/src/auth-state.ts`, attached as `Authorization: Bearer <token>`, refreshed when expired or on 401.
2. **Refresh token (HTTP cookie)** — not stored in JS; sent with `credentials: "include"` to `AuthService.refreshToken` (see `fetchWithCredentials` and `refreshTransport` in the same file). The backend uses the `memos_refresh` cookie (`server/auth/token.go`).

**Backend validation:** `server/auth` (`Authenticator` in `server/auth/authenticator.go`) validates Bearer JWT access tokens and, on the server side, Personal Access Tokens. Connect requests are enforced by `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`, which delegates to `Authorizer` → `auth.Authenticator`.
