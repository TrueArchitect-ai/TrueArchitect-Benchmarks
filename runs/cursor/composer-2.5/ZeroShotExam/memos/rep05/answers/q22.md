**DispatchMemoCreatedWebhook** — `server/router/api/v1/memo_service_webhooks.go`; **`internal/webhook`**; **Standard Webhooks HMAC-SHA256**

When a memo is created, the `CreateMemo` handler in `server/router/api/v1/memo_service.go` calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)` after persisting and converting the memo. That function lives in `server/router/api/v1/memo_service_webhooks.go` and delegates to `dispatchMemoRelatedWebhook`, which loads the creator’s registered webhooks and enqueues delivery via `webhook.PostAsync` for each hook.

HTTP delivery is implemented in `internal/webhook/webhook.go`: worker goroutines started in `init()` drain the async queue and call `Post`, which builds a JSON POST with the standard library `net/http` client (`safeClient`).

If a webhook has a signing secret, `Post` signs the payload using the Standard Webhooks scheme: HMAC-SHA256 over `webhook-id + "." + webhook-timestamp + "." + body`, with headers `webhook-id`, `webhook-timestamp`, and `webhook-signature` (`v1,<base64>`). Secrets in `whsec_<base64>` form are base64-decoded before signing (`resolveSigningKey` in the same file).
