When a memo is deleted through the API, the handler calls `Store.DeleteMemo` (see `server/router/api/v1/memo_service.go`). In the store layer, `DeleteMemo` removes these other record kinds **before** deleting the memo row itself (`store/memo.go`):

- **memo_relation** — relations where the memo is either the source (`memo_id`) or the target (`related_memo_id`)
- **attachment** — attachments linked to the memo (via `DeleteAttachment`)

```140:158:store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	if err != nil {
		return err
	}
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

Note: the API also deletes comment memos first by calling `Store.DeleteMemo` on each comment (`server/router/api/v1/memo_service.go`), but those are other **memo** rows, not a different record kind. The store layer does not delete reactions, memo shares, or inbox records as part of `DeleteMemo`.
