web/src/connect.ts; JWT access tokens (Bearer `Authorization` header) and refresh tokens (HTTP cookie via `credentials: "include"`); server/auth

Frontend API calls go through the Connect RPC transport in `web/src/connect.ts`. The `authInterceptor` there calls `getRequestToken()` to attach a Bearer access token from `web/src/auth-state.ts` (stored in `localStorage` as `memos_access_token`). If the token is missing or near expiry, or a request returns `Unauthenticated`, it calls `refreshAccessToken()`, which hits `AuthService.refreshToken` over a separate transport that sends cookies but no auth header. The main transport uses `fetchWithCredentials` so the refresh cookie (`memos_refresh` on the server) is included on all requests.

On the backend, the Connect `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` delegates to `Authorizer`, which uses `auth.Authenticator` from `server/auth` (`server/auth/authenticator.go`, `server/auth/token.go`) to validate JWT access tokens and, where applicable, refresh tokens and personal access tokens.
