**memo, memo_relation, attachment**

When `DeleteMemo` runs, these three tables have rows removed:

1. **`memo`** — deleted directly by the driver (`DELETE FROM memo`), including comment memos deleted first by the API handler in `server/router/api/v1/memo_service.go` (lines 567–580).

2. **`memo_relation`** — explicit cascade in `store/memo.go` (lines 141–146) via `DeleteMemoRelation` for both `memo_id` and `related_memo_id` (`DELETE FROM memo_relation` in e.g. `store/db/sqlite/memo_relation.go` line 149).

3. **`attachment`** — explicit cascade in `store/memo.go` (lines 148–156) via `DeleteAttachment` (`DELETE FROM attachment` in e.g. `store/db/sqlite/attachment.go` line 212).

**Not affected by `DeleteMemo` (in application code):**

- **`reaction`** — listed in `server/router/api/v1/memo_service.go` (545–547) only for webhook payload; never deleted.
- **`memo_share`** — `LATEST.sql` defines `ON DELETE CASCADE` on `memo_id`, but there is no explicit cascade in the `DeleteMemo` code path, and SQLite disables foreign keys (`store/db/sqlite/sqlite.go` line 53: `foreign_keys(0)`).
