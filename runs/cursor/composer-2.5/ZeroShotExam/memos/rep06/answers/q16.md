When the API deletes a memo, it calls `Store.DeleteMemo` in `store/memo.go`. Before removing the memo row itself, the store layer deletes these other record kinds:

- **memo_relation** — rows where the memo is either the source (`memo_id`) or the target (`related_memo_id`) (`store/memo.go`, lines 141–147)
- **attachment** — rows linked to the memo via `memo_id` (`store/memo.go`, lines 148–157)

The memo row is deleted last via `s.driver.DeleteMemo` (`store/memo.go`, line 158).

Note: comment memos are deleted separately at the API layer in `server/router/api/v1/memo_service.go` (lines 567–577), each via another `Store.DeleteMemo` call. That is not part of a single memo’s store-layer cleanup. The store layer does not delete reactions, memo shares, or inbox records as part of `DeleteMemo`.
