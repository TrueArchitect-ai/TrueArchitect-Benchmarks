When a memo is deleted through the API, the handler calls `Store.DeleteMemo` (see `server/router/api/v1/memo_service.go`). In the store layer, `DeleteMemo` in `store/memo.go` removes these record kinds **before** deleting the memo row itself:

- **memo_relation** — relations where the memo is either the source (`MemoID`) or the target (`RelatedMemoID`)
- **attachment** — attachments linked to the memo via `MemoID`

Relevant code:

```140:158:store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	if err != nil {
		return err
	}
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

Note: the API layer also recursively deletes comment memos (other memo rows) before deleting the target memo (`server/router/api/v1/memo_service.go` lines 567–577), but those are memo records, not separate record kinds cleaned up inside `Store.DeleteMemo`.
