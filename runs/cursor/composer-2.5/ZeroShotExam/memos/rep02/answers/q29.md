`web/src/connect.ts`; access token (JWT Bearer in `Authorization`) and refresh token (HTTP cookie via `credentials: "include"`); `server/auth`

The Connect RPC auth interceptor is defined in `web/src/connect.ts` as `authInterceptor`. It attaches credentials on every request and refreshes them when needed.

**How it works**

1. **Access token** — `getRequestToken()` reads the JWT from `web/src/auth-state.ts` (localStorage/in-memory). The interceptor sets `Authorization: Bearer <token>` via `setAuthorizationHeader()`.
2. **Refresh token** — Not stored in JS. Requests use `fetchWithCredentials` (`credentials: "include"`), so the browser sends the `memos_refresh` cookie. On expiry or `Unauthenticated`, `refreshAccessToken()` calls `AuthService.refreshToken` on a separate transport without the auth interceptor to avoid recursion.
3. **Retry** — After refresh, it retries the original request with the new access token.

**Backend validation**

Connect requests hit `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`, which delegates to `Authorizer.Authenticate()` in `server/router/api/v1/authz.go`. That uses `auth.Authenticator` from `server/auth` (`server/auth/authenticator.go`, `server/auth/token.go`) to validate JWT access tokens and Personal Access Tokens from the `Authorization` header. Refresh tokens are validated in `AuthenticateByRefreshToken()` when the refresh endpoint reads the cookie.
