q20. SSE (Server-Sent Events); `server/router/api/v1/sse_hub.go`; CreateMemo, UpdateMemo, DeleteMemo, CreateMemoComment, SetMemoAttachments, SetMemoRelations

The server uses **Server-Sent Events (SSE)** for live push. Clients connect to `/api/v1/sse` via `server/router/api/v1/sse_handler.go`, which sets `Content-Type: text/event-stream` and streams `data:` frames from subscribed clients. The hub is the `SSEHub` type in `server/router/api/v1/sse_hub.go`, which manages client subscriptions and `Broadcast`s JSON events to connected browsers.

These memo API handlers broadcast through `SSEHub`:

| Handler | File | Event |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go` | `memo.created` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go` | `memo.updated` (via `dispatchMemoUpdatedSideEffects` in `memo_update_helpers.go`) |
| `DeleteMemo` | `server/router/api/v1/memo_service.go` | `memo.deleted` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go` | `memo.comment.created` |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go` | `memo.updated` (via `dispatchMemoUpdatedSideEffects`) |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go` | `memo.updated` (via `dispatchMemoUpdatedSideEffects`) |

`UpdateMemo`, `SetMemoAttachments`, and `SetMemoRelations` do not call `SSEHub.Broadcast` directly; they go through `dispatchMemoUpdatedSideEffects` in `server/router/api/v1/memo_update_helpers.go`. Reaction handlers in `server/router/api/v1/reaction_service.go` also broadcast, but those are not memo handlers.
