**web/src/connect.ts**; **access token (JWT, sent as `Authorization: Bearer`, stored in `web/src/auth-state.ts`) and refresh token (HttpOnly cookie, sent via `credentials: "include"` on refresh)**; **server/auth**

The `authInterceptor` in `web/src/connect.ts` attaches the access token to outgoing Connect RPC requests and, on expiry or `Unauthenticated`, calls `refreshAccessToken()`, which hits `AuthService.refreshToken` using cookie credentials (see `fetchWithCredentials` and the separate refresh transport without the interceptor to avoid recursion). The backend `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` delegates to `Authorizer.Authenticate`, which uses `server/auth.Authenticator` to validate Bearer access tokens (Access Token V2 JWTs) and Personal Access Tokens; refresh tokens are validated separately via cookie in the refresh flow (`server/router/api/v1/auth_service_session.go`, `server/auth/authenticator.go`).
