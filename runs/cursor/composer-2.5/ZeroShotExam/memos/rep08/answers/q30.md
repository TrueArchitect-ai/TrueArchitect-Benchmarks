Four memo lifecycle events dispatch webhooks, defined in `server/router/api/v1/memo_service_webhooks.go`:

memos.memo.created: DispatchMemoCreatedWebhook (called from `server/router/api/v1/memo_service.go`)
memos.memo.updated: DispatchMemoUpdatedWebhook (called from `server/router/api/v1/memo_update_helpers.go`)
memos.memo.deleted: DispatchMemoDeletedWebhook (called from `server/router/api/v1/memo_service.go`)
memos.memo.comment.created: DispatchMemoCommentCreatedWebhook (called from `server/router/api/v1/memo_service_comments.go`)

All four converge on `webhook.PostAsync` in `internal/webhook/webhook.go`, which enqueues payloads on `asyncPostQueue`; background workers then call `webhook.Post` in the same file for the actual HTTP delivery. The create/update/delete paths go through the shared helper `dispatchMemoRelatedWebhook` in `server/router/api/v1/memo_service_webhooks.go` before reaching `PostAsync`; comment-created builds its payload separately but also calls `PostAsync` directly.
