The browser loads another user’s profile (e.g. `web/src/pages/UserProfile.tsx` via `useUser`), gets `avatarUrl` rewritten to `/file/users/{username}/avatar`, and `<img src={avatarUrl}>` in `UserAvatar` issues `GET /file/users/{username}/avatar`. Echo routes that to `serveUserAvatar`, which looks up the user by username, reads the `avatar_url` column from the `user` table (via `GetUser` → `ListUsers` → the DB driver), decodes the stored data-URI string with `parseDataURI`, and returns the image bytes with `c.Blob`. Avatar bytes live in the DB column as a base64 data URI, not as a separate file on disk. (Postgres/MySQL use the same pattern in `store/db/postgres/user.go` and `store/db/mysql/user.go`.)
