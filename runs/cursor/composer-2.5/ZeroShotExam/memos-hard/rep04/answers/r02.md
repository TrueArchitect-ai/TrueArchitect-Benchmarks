**Premise correction:** This repository does not register any per-user API rate-limiting middleware, and there are no per-user request-rate limits defined in the codebase.

What is registered instead:

**Global Echo middleware** in `server/server.go`:
- `middleware.Recover()` (panic recovery)
- `newCORSMiddleware(profile)` from `server/cors.go` (CORS)

**API auth middleware** (not rate limiting) in `server/router/api/v1/v1.go`:
- `gatewayAuthMiddleware` on the gRPC-Gateway mux via `runtime.WithMiddlewares(gatewayAuthMiddleware)` (lines 69–98, 96–98)
- Connect interceptors: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` (lines 133–138)

**Request size cap** (not per-user rate limiting) in `server/router/api/v1/v1.go`:
- `maxAPIRequestBytes = 256 << 20` (256 MiB), applied with `http.MaxBytesHandler(...)` on both the gRPC-Gateway and Connect handlers (lines 20, 126, 141, 144)

The only “rate limit” mention is a suggested future improvement for email sending in `internal/email/README.md` and `internal/email/doc.go`; it is not implemented API middleware.

No rate-limiting library (e.g. `golang.org/x/time/rate`) appears in `go.mod`, and a repo-wide search finds no `RateLimit`, `RateLimiter`, or HTTP 429 handling for API requests.
