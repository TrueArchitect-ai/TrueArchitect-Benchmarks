**Computation site:** Markdown parsing and extraction live in `internal/markdown/markdown.go` — `ExtractAll()` walks the goldmark AST in one pass and returns tags, mentions, and `MemoPayload_Property`. Those results are written into stored payload by `RebuildMemoPayload()` in `server/runner/memopayload/runner.go` (`memo.Payload.Tags`, `memo.Payload.Property`). Plain-text previews are computed separately at response time: `GenerateSnippet()` in `internal/markdown/markdown.go`, called via `getMemoContentSnippet()` in `server/router/api/v1/memo_service_webhooks.go`, and attached to API `Memo` messages in `server/router/api/v1/memo_service_converter.go`. Schema for stored derived fields is in `proto/store/memo.proto`; API output-only fields are in `proto/api/v1/memo_service.proto`.

**Triggers:** Persisted payload (`tags`, `property`) is recomputed by `RebuildMemoPayload()` on `CreateMemo` (`server/router/api/v1/memo_service.go`), on `UpdateMemo` when the update mask includes `"content"` (same file), and indirectly on comment creation because `CreateMemoComment` delegates to `CreateMemo` (`server/router/api/v1/memo_service_comments.go`). A batch rebuild of all memos exists as `memopayload.Runner.RunOnce()` (`server/runner/memopayload/runner.go`) but is not wired from `server/server.go`. `snippet` is not stored; it is recomputed whenever memos are converted for API responses (e.g. `ListMemos`, `GetMemo`) in `memo_service_converter.go`.

**Extracted properties:** From content into stored payload — `#tags` (excluding tags inside links/images); `property.title` (text of the first top-level H1); `property.has_link`; `property.has_code`; `property.has_task_list`; `property.has_incomplete_tasks`. At response time — `snippet` (plain-text summary, max 64 characters, word-truncated). `ExtractAll()` also extracts `@mentions`, but those are used for mention notifications (`server/router/api/v1/memo_mention_helpers.go`) and are not persisted in `MemoPayload`.
