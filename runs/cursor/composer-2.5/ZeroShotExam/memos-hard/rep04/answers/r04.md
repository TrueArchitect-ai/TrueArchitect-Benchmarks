**Premise correction:** Neither NATS nor RabbitMQ is used for webhook delivery in this repository. `go.mod` lists no NATS or RabbitMQ client dependencies, and a repo-wide search finds no references to either broker in application code.

**Actual mechanism:** Webhook delivery workers are four in-process goroutines started in `init()` that consume from a bounded in-memory Go channel, not an external message broker. The queue is declared in `internal/webhook/webhook.go`:

```39:54:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
)

func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

Producers enqueue via `PostAsync()` in the same file (lines 184–196), which performs a non-blocking send to `asyncPostQueue` and drops the payload if the buffer is full. Call sites include `server/router/api/v1/memo_service_webhooks.go`, which invokes `webhook.PostAsync(payload)` when memo lifecycle events trigger webhooks.
