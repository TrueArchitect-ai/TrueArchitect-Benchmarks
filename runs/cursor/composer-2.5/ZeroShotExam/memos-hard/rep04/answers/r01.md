**Premise correction:** This repository does not configure a Redis connection for its cache layer. A search of the codebase finds no Redis references; the store cache is an in-process, in-memory implementation in `store/cache/cache.go`, not a Redis-backed cache.

**Actual mechanism:** The cache layer is wired in `store/store.go` inside `New()`. It builds a shared `cache.Config` and instantiates `userCache` (along with `instanceSettingCache` and `userSettingCache`) via `cache.New(cacheConfig)`:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

User entries are cached in `store/user.go` with `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. on create, update, list, and get). `Set()` delegates to `SetWithTTL` using the config’s `DefaultTTL`:

```92:95:store/cache/cache.go
func (c *Cache) Set(ctx context.Context, key string, value any) {
	c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)
}
```

The TTL for user entries is therefore the shared default: **10 minutes** (`10 * time.Minute`), defined in `store/store.go` and mirrored in `store/cache/cache.go`’s `DefaultConfig()`. User writes do not pass a custom TTL.
