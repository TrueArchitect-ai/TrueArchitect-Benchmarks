**Premise correction:** Webhook delivery workers in this repository do not consume from NATS or RabbitMQ. A search of the codebase finds no NATS, RabbitMQ, AMQP, or JetStream usage; the only “nats” matches are unrelated Catalan locale strings in `web/web/src/locales/ca.json`.

**Actual mechanism:** Delivery is handled in-process via a bounded Go channel and four goroutine workers declared in `internal/webhook/webhook.go`. The queue is `asyncPostQueue`, created as `make(chan *WebhookRequestPayload, 128)` (line 39). The `init()` function (lines 42–54) starts four workers that read from that channel and call `Post()`. Producers enqueue via `PostAsync()` (lines 184–196), which sends to `asyncPostQueue` (or drops the payload if the channel is full). Call sites such as `server/router/api/v1/memo_service_webhooks.go` invoke `webhook.PostAsync(payload)` when memo-related events should trigger webhooks.
