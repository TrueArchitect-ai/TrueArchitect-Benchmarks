**impl — construction — holders**

- **impl:** The only runtime concrete type is the unexported `service` struct in `internal/markdown/markdown.go`, which implements `markdown.Service` using goldmark (GFM plus optional tag/mention extensions). There are no other production implementations of that interface.

- **construction:** `markdown.NewService(...)` in `internal/markdown/markdown.go` builds and returns the `service` value as a `markdown.Service`. In production it is created once inside `NewAPIV1Service` in `server/router/api/v1/v1.go` with `WithTagExtension()` and `WithMentionExtension()`. `server/server.go` passes that same instance into `rss.NewRSSService(...)`. Tests construct their own instances in files such as `server/router/api/v1/test/test_helper.go` and `server/router/rss/rss_test.go`.

- **holders:** Components that store the `markdown.Service` interface are:
  - `APIV1Service.MarkdownService` — `server/router/api/v1/v1.go` (primary owner; used from `memo_service.go`, `memo_mention_helpers.go`, `memo_service_webhooks.go`)
  - `RSSService.MarkdownService` — `server/router/rss/rss.go` (receives the shared instance from `server/server.go`)
  - `memopayload.Runner.MarkdownService` — `server/runner/memopayload/runner.go` (field exists, but `NewRunner` is not wired in production; `RebuildMemoPayload(..., markdownService)` instead receives the interface from `APIV1Service` in `server/router/api/v1/memo_service.go`)

Note: `renderer.MarkdownRenderer` in `internal/markdown/renderer/markdown_renderer.go` is a separate concrete helper (not behind `markdown.Service`); it is instantiated locally inside `service.RenderMarkdown` and `service.RenameTag` rather than injected as the interface.
