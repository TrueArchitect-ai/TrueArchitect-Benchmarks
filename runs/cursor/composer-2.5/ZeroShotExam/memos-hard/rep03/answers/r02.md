**Premise correction:** This repository does not register any per-user API rate-limiting middleware, so there is no registration site and no per-user request limits to report.

The HTTP/API stack uses other middleware and interceptors instead:

- In `server/server.go`, Echo gets `middleware.Recover()` and `newCORSMiddleware()` — not rate limiting.
- In `server/router/api/v1/v1.go`, API traffic is wrapped with:
  - `gatewayAuthMiddleware` on the gRPC-Gateway mux (authentication/authorization)
  - Connect interceptors: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (see `server/router/api/v1/connect_interceptors.go`)
  - `http.MaxBytesHandler(..., maxAPIRequestBytes)` with a 256 MiB body cap (`maxAPIRequestBytes = 256 << 20` in `server/router/api/v1/v1.go`)

The only “rate limiting” mention in the repo is documentation for **email sending**, not the HTTP API: `internal/email/doc.go` lists it as a security consideration, and `internal/email/README.md` shows an example of `golang.org/x/time/rate` (10 emails/second) as guidance — not implemented API middleware.

There are also non-rate-limit guards such as concurrency semaphores for thumbnail/image processing in `server/router/api/v1/v1.go` and per-endpoint batch/page size checks in service handlers (e.g. `server/router/api/v1/user_service.go`, `server/router/api/v1/memo_service_link_metadata.go`), but those are not per-user request-rate middleware.
