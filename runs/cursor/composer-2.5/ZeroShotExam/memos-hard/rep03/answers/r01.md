**Premise correction:** This repository does not configure a Redis connection for the cache layer. There are no Redis references anywhere in the codebase; the store cache is an in-process, in-memory implementation.

**Actual mechanism:** Cache setup lives in `store/store.go`, where `Store.New()` builds a shared `cache.Config` and instantiates three `*cache.Cache` instances (including `userCache`):

```38:54:store/store.go
func New(driver Driver, profile *profile.Profile) *Store {
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

The cache itself is defined in `store/cache/cache.go` as a thread-safe in-memory map with TTL-based expiration. `Set()` delegates to `SetWithTTL` using `config.DefaultTTL`:

User entries are written via `s.userCache.Set()` in `store/user.go` (e.g. on create, update, list, and get). Those calls use the default TTL only—no custom TTL is passed for users—so **user cache entries expire after 10 minutes**.
