For an uploaded avatar (stored as a base64 data URI in the DB, exposed to the browser as `GET /file/users/{username}/avatar` via `convertUserFromStore` in `server/router/api/v1/user_service_converters.go`), the request path from the browser to stored data is:

http.Server.Serve — server/server.go
middleware.Recover — server/server.go
newCORSMiddleware — server/cors.go
shouldSkipFrontendStatic — server/router/frontend/frontend.go
FileServerService.RegisterRoutes — server/router/fileserver/fileserver.go
FileServerService.serveUserAvatar — server/router/fileserver/fileserver.go
Profile.AllowAnonymous — internal/profile/profile.go
FileServerService.getCurrentUser — server/router/fileserver/fileserver.go
Authenticator.AuthenticateToUser — server/auth/authenticator.go
FileServerService.getUserByUsername — server/router/fileserver/fileserver.go
Store.GetUser — store/user.go
Store.ListUsers — store/user.go
(*sqlite.DB).ListUsers — store/db/sqlite/user.go
(*sql.DB).QueryContext — store/db/sqlite/user.go
user.avatar_url — store/migration/sqlite/LATEST.sql

Notes:

- `serveUserAvatar` is the serving handler; it reads `user.AvatarURL` from the query result, decodes it with `FileServerService.parseDataURI` in `server/router/fileserver/fileserver.go`, and returns the bytes via `echo.Context.Blob`.
- Auth hops (`getCurrentUser` → `AuthenticateToUser`) run only on private instances where `Profile.AllowAnonymous()` is false (`internal/profile/profile.go`).
- The DB driver file varies by deployment (`store/db/postgres/user.go` or `store/db/mysql/user.go` instead of sqlite).
- External/SSO avatar URLs (`https://…`) are returned as-is from the API and loaded by the browser directly; they do not hit `/file/users/.../avatar`.
