h11.

Persistent entity types live in the `store/` data layer as Go structs (e.g. `User` in `store/user.go`, `Memo` in `store/memo.go`), backed by tables in `store/migration/sqlite/LATEST.sql` (`user`, `memo`, etc.).

Counting Go packages **outside** `store/` that import `github.com/usememos/memos/store` and reference each entity type (`store.User`, `store.Memo`, …):

**1st: User (~7 packages)** — `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`

**2nd: Memo (~6 packages)** — `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`

User leads because auth, file serving, RSS, and frontend layers all need the user record; Memo is next as the core content type used across API, notification, RSS, frontend, and memo processing. Third is `Attachment` at ~4 packages. Several other entities (`UserSetting`, `IdentityProvider`, `InstanceSetting`) are mostly handled via protobuf types in `proto/gen/store/` rather than the `store.*` structs, so they rank lower.
