**Premise correction:** This repository does not register per-user API rate-limiting middleware, and there are no per-user request limits defined for the HTTP/API layer.

Echo middleware is wired in `server/server.go` as `middleware.Recover()` and `newCORSMiddleware()` from `server/cors.go`. The frontend adds static/SPA middleware in `server/router/frontend/frontend.go`. API auth is handled by `gatewayAuthMiddleware` in `server/router/api/v1/v1.go` and by Connect interceptors (`MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor`) in `server/router/api/v1/connect_interceptors.go` — none of these enforce per-user request quotas.

A repo-wide search finds no `RateLimiter`, `rate.Limit`, or similar per-user API throttling. The closest limits are unrelated to per-user request rates:

- **Request body size:** `maxAPIRequestBytes = 256 << 20` in `server/router/api/v1/v1.go`
- **Concurrency caps:** semaphores for thumbnail/image processing in `server/router/api/v1/v1.go` and `server/router/fileserver/fileserver.go` (e.g., 3 concurrent thumbnails, 2 concurrent image-processing slots)
- **Documentation only:** `internal/email/README.md` suggests email rate limiting as a future consideration, not as implemented API middleware

So the question assumes middleware that is not present in this codebase.
