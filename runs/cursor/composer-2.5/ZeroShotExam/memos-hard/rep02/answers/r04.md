**Premise correction:** Webhook delivery workers do **not** consume from NATS or RabbitMQ. This repository has no NATS or RabbitMQ dependencies (`go.mod`) and no references to either broker in webhook code.

**Actual mechanism:** Delivery is handled **in-process** by four goroutine workers that read from a bounded Go channel, `asyncPostQueue`, declared in `internal/webhook/webhook.go`:

```39:54:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
)

func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

Producers enqueue via `PostAsync()` (same file, lines 182–196), which sends to that channel with a non-blocking `select` and drops work if the buffer is full. Call sites include `server/router/api/v1/memo_service_webhooks.go`, which invokes `webhook.PostAsync(payload)` when memo-related webhooks are dispatched.
