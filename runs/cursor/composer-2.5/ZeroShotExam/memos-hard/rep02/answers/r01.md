**Premise correction:** This repository does not configure a Redis connection for the cache layer. A search of the codebase finds no Redis client, URL, or dependency. The cache is an in-process, in-memory implementation in `store/cache/cache.go`.

**Actual mechanism:** Cache instances (including `userCache`) are created in `store/store.go` when `Store.New` runs. All three caches share one `cache.Config` with `DefaultTTL: 10 * time.Minute` (plus `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000`):

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

User entries are written via `userCache.Set(...)` in `store/user.go` (e.g. on create, update, list, and get). `Set` delegates to `SetWithTTL` with the cache’s `DefaultTTL`:

```92:95:store/cache/cache.go
// Set adds a value to the cache with the default TTL.
func (c *Cache) Set(ctx context.Context, key string, value any) {
	c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)
}
```

So user cache entries expire after **10 minutes** unless evicted earlier by `MaxItems` or explicit `Delete` (e.g. in `store/user_delete.go`). There is no separate or user-specific TTL override.
