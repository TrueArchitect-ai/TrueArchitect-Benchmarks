The browser issues `GET /file/users/:identifier/avatar` (registered in `RegisterRoutes` in `server/router/fileserver/fileserver.go`), typically from an `<img src={avatarUrl}>` in `web/src/components/UserAvatar.tsx` where `avatarUrl` is `/file/users/{username}/avatar` (set by `convertUserFromStore` in `server/router/api/v1/user_service_converters.go`).

`serveUserAvatar` is the serving handler. On a private instance it first calls `getCurrentUser` → `AuthenticateToUser` (`server/auth/authenticator.go`) to require a session/token; on an open instance that gate is skipped.

To load the target user's avatar, `getUserByUsername` calls `Store.GetUser` with `{Username: identifier}`, which delegates to `Store.ListUsers` and then the DB driver's `ListUsers` (e.g. `store/db/sqlite/user.go`; Postgres/MySQL use `store/db/postgres/user.go` or `store/db/mysql/user.go`). That runs `SELECT ... avatar_url ... FROM user WHERE username = ?` and scans the value into `store.User.AvatarURL`.

Back in `serveUserAvatar`, `parseDataURI` decodes that stored base64 data URI and `c.Blob` writes the image bytes to the response.
