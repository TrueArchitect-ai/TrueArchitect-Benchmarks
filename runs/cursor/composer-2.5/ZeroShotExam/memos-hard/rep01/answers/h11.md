The data layer is the `store/` package (store facade, cache, migrations, and DB drivers), per [`AGENTS.md`](AGENTS.md). Persistent entity types are the domain structs defined there—e.g. `User` in [`store/user.go`](store/user.go), `Memo` in [`store/memo.go`](store/memo.go), plus `Attachment`, `MemoRelation`, `MemoShare`, `Inbox`, `Reaction`, `UserIdentity`, `UserSetting`, `IdentityProvider`, and `InstanceSetting` in the corresponding files under [`store/`](store/) (also reflected in the `Driver` interface in [`store/driver.go`](store/driver.go)).

Counting Go packages **outside** `store/` that reference each entity struct as `store.<Type>`:

**1st: User (~7 packages)** — [`server/auth/`](server/auth/), [`server/notification/`](server/notification/), [`server/router/api/v1/`](server/router/api/v1/), [`server/router/api/v1/test/`](server/router/api/v1/test/), [`server/router/fileserver/`](server/router/fileserver/), [`server/router/frontend/`](server/router/frontend/), [`server/router/rss/`](server/router/rss/)

**2nd: Memo (~6 packages)** — [`server/notification/`](server/notification/), [`server/router/api/v1/`](server/router/api/v1/), [`server/router/api/v1/test/`](server/router/api/v1/test/), [`server/router/frontend/`](server/router/frontend/), [`server/router/rss/`](server/router/rss/), [`server/runner/memopayload/`](server/runner/memopayload/)

`User` leads because it appears in auth and file-serving paths (e.g. [`server/auth/authenticator.go`](server/auth/authenticator.go), [`server/router/fileserver/fileserver.go`](server/router/fileserver/fileserver.go)) that `Memo` does not. Next after those two is `Attachment` at roughly 4 packages ([`server/router/api/v1/`](server/router/api/v1/), [`server/router/fileserver/`](server/router/fileserver/), [`server/router/rss/`](server/router/rss/), plus tests).
