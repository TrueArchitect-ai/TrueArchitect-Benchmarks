**handlers (≥3):** `CreateMemo`, `UpdateMemo`, `DeleteMemo` — plus `CreateMemoComment`, `SetMemoAttachments`, and `SetMemoRelations` on the same path.

**convergence function — path:** `Post` — `internal/webhook/webhook.go`

These RPC handlers load user-configured webhook URLs from the store and enqueue delivery via `webhook.PostAsync` in `server/router/api/v1/memo_service_webhooks.go` (or, for comments, `DispatchMemoCommentCreatedWebhook` in the same file). Background workers in `internal/webhook/webhook.go` dequeue those payloads and all call `Post`, which issues the outbound HTTP POST to `requestPayload.URL` with `safeClient.Do(req)`.

| Handler | Entry file | Chain |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go` | `DispatchMemoCreatedWebhook` → `dispatchMemoRelatedWebhook` → `PostAsync` → `Post` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go` | `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` → `dispatchMemoRelatedWebhook` → `PostAsync` → `Post` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go` | `DispatchMemoDeletedWebhook` → `dispatchMemoRelatedWebhook` → `PostAsync` → `Post` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go` | `DispatchMemoCommentCreatedWebhook` → `PostAsync` → `Post` |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go` | `dispatchMemoUpdatedSideEffects` → … → `Post` |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go` | `dispatchMemoUpdatedSideEffects` → … → `Post` |

Webhook CRUD handlers (`CreateUserWebhook`, `UpdateUserWebhook`, etc.) only persist URLs; they do not send HTTP. Only memo lifecycle handlers transitively trigger outbound requests to those stored URLs.
