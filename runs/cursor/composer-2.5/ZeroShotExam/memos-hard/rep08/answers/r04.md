**Premise correction:** Webhook delivery workers in this repo do not consume from NATS or RabbitMQ. There is no message broker for webhooks anywhere in the codebase — `go.mod` has no NATS/RabbitMQ/AMQP dependencies, and a repo-wide search finds no broker integration.

**Actual mechanism:** Webhook delivery uses an in-process, bounded Go channel and goroutine workers in `internal/webhook/webhook.go`. The queue is declared as package-level variable `asyncPostQueue`:

```39:39:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four background goroutines are started in `init()` and consume from that channel, calling `Post()` for each payload:

```42:55:internal/webhook/webhook.go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

Producers enqueue via `PostAsync()`, which sends on `asyncPostQueue` (non-blocking; drops if full):

```184:196:internal/webhook/webhook.go
func PostAsync(requestPayload *WebhookRequestPayload) {
	if requestPayload == nil {
		slog.Warn("Dropped webhook dispatch because payload is nil")
		return
	}
	select {
	case asyncPostQueue <- requestPayload:
	default:
		slog.Warn("Dropped webhook dispatch because the async queue is full",
			slog.String("url", requestPayload.URL),
			slog.String("activityType", requestPayload.ActivityType))
	}
}
```

Memo-related webhook events call `webhook.PostAsync()` from `server/router/api/v1/memo_service_webhooks.go` (e.g. lines 43 and 71).
