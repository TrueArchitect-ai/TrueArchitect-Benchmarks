**Computation site:** Derived content metadata is parsed in `internal/markdown/markdown.go` — primarily `ExtractAll()` (single goldmark AST walk; also exposed as `ExtractTags()` / `ExtractProperties()`), which fills `MemoPayload` via `RebuildMemoPayload()` in `server/runner/memopayload/runner.go`. The persisted shape is defined in `proto/store/memo.proto` (`MemoPayload.tags`, `MemoPayload.Property`). List previews also get a plain-text `snippet` at read time via `getMemoContentSnippet()` → `MarkdownService.GenerateSnippet()` in `server/router/api/v1/memo_service_webhooks.go` (not stored in `MemoPayload`).

**Triggers:** Recomputation runs on memo create (`CreateMemo` in `server/router/api/v1/memo_service.go`), on content update (`UpdateMemo` when the update mask includes `"content"`), and indirectly when creating comments (`CreateMemoComment` in `server/router/api/v1/memo_service_comments.go` calls `CreateMemo`). A batch path `Runner.RunOnce()` in `server/runner/memopayload/runner.go` can rebuild all memos but is not wired into server startup in `server/server.go`. Snippet is regenerated on each API conversion in `server/router/api/v1/memo_service_converter.go`, not on a separate trigger.

**Extracted properties:** From markdown content into persisted `MemoPayload`: `tags` (`#tag` nodes, deduplicated, skipping tags inside links/images); `Property.has_link`, `Property.has_task_list`, `Property.has_code`, `Property.has_incomplete_tasks`, and `Property.title` (text of the first block-level H1). `ExtractAll()` also collects `@mention` usernames (used for notifications in `server/router/api/v1/memo_mention_helpers.go`, not written into `MemoPayload` by `RebuildMemoPayload`). At response time, `snippet` is a truncated plain-text summary for list/link previews. User-set fields such as `MemoPayload.location` are not part of this computation.
