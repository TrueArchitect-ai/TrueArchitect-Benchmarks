**Premise correction:** This repository does not configure a Redis connection for the cache layer. A search of the codebase finds no Redis references; caching is implemented as an in-process, in-memory cache in `store/cache/cache.go`.

**Actual mechanism:** Cache setup happens in `store/store.go` inside `Store.New()`, which builds a shared `cache.Config` and instantiates `userCache` (along with `instanceSettingCache` and `userSettingCache`) via `cache.New(cacheConfig)`:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		// ...
		userCache:            cache.New(cacheConfig),
```

User entries are written with `userCache.Set()` in `store/user.go` (e.g. on create, update, list, and get). `Set()` delegates to `SetWithTTL` using the cache’s `DefaultTTL` (`store/cache/cache.go`), and user code never passes a custom TTL. **The TTL for user entries is therefore 10 minutes**, matching the shared `DefaultTTL` in `store/store.go` (also defined as the default in `store/cache/cache.go`’s `DefaultConfig()`).
