`convertUserFromStore` (rewrites stored base64 to `/file/users/{username}/avatar`) — `server/router/api/v1/user_service_converters.go`  
`RegisterRoutes` (registers `GET /file/users/:identifier/avatar`) — `server/router/fileserver/fileserver.go`  
`NewServer` (calls `fileServerService.RegisterRoutes`) — `server/server.go`  
`serveUserAvatar` (HTTP serving handler) — `server/router/fileserver/fileserver.go`  
`getUserByUsername` — `server/router/fileserver/fileserver.go`  
`GetUser` — `store/user.go`  
`ListUsers` — `store/user.go`  
`ListUsers` (DB driver; sqlite/postgres/mysql) — `store/db/sqlite/user.go`  
SQL `SELECT … avatar_url … FROM user WHERE username = ?` — `store/db/sqlite/user.go`  
`user.avatar_url` column (stored data: `data:image/...;base64,...` string) — `store/migration/sqlite/LATEST.sql`  
`parseDataURI` (decodes `user.AvatarURL` into image bytes) — `server/router/fileserver/fileserver.go`  
`c.Blob` (writes decoded bytes to the HTTP response) — `server/router/fileserver/fileserver.go`

Profile images are not read from the filesystem or S3; the handler loads the base64 data URI from the `user.avatar_url` DB column and serves the decoded bytes.
