**No**

The MySQL store driver is not constructed directly outside the driver-selection factory.

**Evidence**

1. **The factory is the only caller of `mysql.NewDB`.** `store/db/db.go` defines `NewDBDriver`, which selects the backend and is the sole place that invokes `mysql.NewDB(profile)`:

```18:24:/bench/repo/store/db/db.go
	switch profile.Driver {
	case "sqlite":
		driver, err = sqlite.NewDB(profile)
	case "mysql":
		driver, err = mysql.NewDB(profile)
	case "postgres":
		driver, err = postgres.NewDB(profile)
```

2. **`store/db/mysql` is imported only by the factory.** A repo-wide search shows `github.com/usememos/memos/store/db/mysql` is imported only in `/bench/repo/store/db/db.go`. No other file references that package.

3. **All other driver creation goes through `db.NewDBDriver`.** Call sites include:
   - `/bench/repo/cmd/memos/main.go`
   - `/bench/repo/store/test/store.go` (lines 28 and 50)
   - `/bench/repo/server/router/api/v1/test/memo_service_benchmark_test.go`

4. **Contrast with SQLite.** The SQLite driver *is* constructed directly outside the factory in `/bench/repo/store/demo_seed_test.go` and `/bench/repo/store/deployment_config_test.go` via `sqlite.NewDB(p)`. There is no analogous direct `mysql.NewDB(...)` call anywhere else in the codebase.

**Note:** `/bench/repo/store/db/mysql/auth_config_test.go` uses `db := &DB{}` as a zero-value stub to test error-classification logic without a real DB connection. That is not a full driver construction via `mysql.NewDB`, and it does not appear outside the `mysql` package. `/bench/repo/store/test/containers.go` uses `sql.Open("mysql", dsn)` only to create test databases against a container, not to construct the memos `store/db/mysql` driver.
