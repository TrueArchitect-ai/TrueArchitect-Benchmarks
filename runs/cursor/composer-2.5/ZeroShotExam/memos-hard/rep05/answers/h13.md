The interface is `markdown.Service` in `internal/markdown/markdown.go`.

**impl — construction — holders**

- **`service`** (`internal/markdown/markdown.go`, unexported struct implementing `Service`) — **`markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())`** in `NewAPIV1Service` (`server/router/api/v1/v1.go`), which `NewServer` calls (`server/server.go`) — **`APIV1Service.MarkdownService`** (`server/router/api/v1/v1.go`) and **`RSSService.MarkdownService`** (`server/router/rss/rss.go`), the latter receiving the same instance from `apiV1Service.MarkdownService` in `server/server.go`.

At runtime this is the only `Service` implementation wired in production. `memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go`) takes `markdown.Service` as a parameter but does not own it; callers pass `s.MarkdownService` from `APIV1Service` (e.g. `server/router/api/v1/memo_service.go`). The `memopayload.Runner` struct also declares a `MarkdownService` field, but `NewRunner` is not invoked anywhere in non-test code.

Internally, `service` delegates to goldmark (GFM + tag/mention extensions) and, for AST-to-markdown round-trips, to `renderer.MarkdownRenderer` (`internal/markdown/renderer/markdown_renderer.go`), which is constructed per call inside `service.RenderMarkdown` and `service.RenameTag`, not held behind the `Service` interface.
