**Premise correction:** This repository does not configure a Redis connection for the cache layer. There are no Redis references in the codebase or in `go.mod`; storage is SQLite, MySQL, or PostgreSQL per `AGENTS.md`.

**Actual mechanism:** The store cache is an in-process, in-memory cache in `store/cache/cache.go`. It is wired up in `store/store.go` when `Store` is created via `store.New()`.

Configuration lives in `store/store.go`:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

The same defaults are also defined in `store/cache/cache.go` (`DefaultConfig()`).

**User entry TTL:** User entries use `userCache` with the shared `DefaultTTL` of **10 minutes**. In `store/user.go`, writes call `s.userCache.Set(...)`, which in `store/cache/cache.go` delegates to `SetWithTTL` using `c.config.DefaultTTL` — no per-user override. Keys are user IDs via `userCacheKey()` in `store/user.go`. Expired entries are removed on read and by a background cleanup loop every 5 minutes (`CleanupInterval`).
