**Premise correction:** This repository does **not** register any per-user API rate-limiting middleware, and there are no per-user request limits (requests/minute, burst, etc.) defined for the API.

What is registered instead:

**Global Echo middleware** in `server/server.go`:
- `middleware.Recover()` (panic recovery)
- `newCORSMiddleware(profile)` from `server/cors.go` (CORS)

**API v1 middleware/interceptors** in `server/router/api/v1/v1.go`:
- gRPC-Gateway: `gatewayAuthMiddleware` (authentication/authorization), registered via `runtime.WithMiddlewares(gatewayAuthMiddleware)` in `RegisterGateway`
- Connect RPC: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` in `connect_interceptors.go`, wired in `RegisterGateway`
- Request body cap: `maxAPIRequestBytes = 256 << 20` (256 MiB) via `http.MaxBytesHandler`, not a per-user rate limit

**Related but not per-user rate limiting:**
- Concurrency semaphores in `server/router/api/v1/v1.go` (`thumbnailSemaphore`: 3, `imageProcessingSemaphore`: 2) limit concurrent image work instance-wide
- `internal/email/README.md` and `internal/email/doc.go` mention rate limiting only as guidance for email sending, not as API middleware

So the question’s premise — that per-user API rate-limiting middleware exists with defined request limits — does not match this codebase.
