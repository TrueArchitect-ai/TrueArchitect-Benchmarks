**Premise correction:** This repository does not configure a Redis connection for the cache layer. A search of the codebase finds no Redis references; storage is SQLite, MySQL, or PostgreSQL (`AGENTS.md`), and caching is handled in-process.

**Actual mechanism:** The cache layer is an in-memory implementation in `store/cache/cache.go`, wired up when the store is created in `store/store.go`. In `Store.New()`, a shared `cache.Config` is built and passed to three cache instances, including `userCache`:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		// ...
		userCache:            cache.New(cacheConfig),
```

User entries are stored via `userCache.Set()` in `store/user.go` (e.g. on create, update, list, and get). That calls `Set`, which applies the cache’s `DefaultTTL`:

```92:95:store/cache/cache.go
// Set adds a value to the cache with the default TTL.
func (c *Cache) Set(ctx context.Context, key string, value any) {
	c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)
}
```

So user entries use a **10-minute TTL**, with keys like `"<userID>"` from `userCacheKey()` in `store/user.go`. There is no separate Redis host, URL, or connection string to configure.
