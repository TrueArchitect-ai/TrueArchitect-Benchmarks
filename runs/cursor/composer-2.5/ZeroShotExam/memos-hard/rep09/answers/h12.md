**Determination method:** Traced the save path from the API handler through the store layer to the driver, then used the default-installation driver selection to pick among the three driver implementations.

Call chain for a new memo:

1. `APIV1Service.CreateMemo` calls `s.Store.CreateMemo` — `server/router/api/v1/memo_service.go` (line 115)
2. `Store.CreateMemo` delegates to `s.driver.CreateMemo` — `store/memo.go` (line 113)
3. With no database flags, the driver is SQLite:
   - Default driver: `viper.SetDefault("driver", "sqlite")` — `cmd/memos/main.go` (line 122)
   - Factory routing: `case "sqlite": driver, err = sqlite.NewDB(profile)` — `store/db/db.go` (lines 18–20)
   - DSN default for SQLite: `profile.Validate()` sets `p.DSN` when empty — `internal/profile/profile.go` (lines 110–116)

**Multiple candidates:** Three `CreateMemo` implementations each build and run an INSERT — `store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, and `store/db/postgres/memo.go`. Only the SQLite one runs on default install because `profile.Driver` defaults to `"sqlite"` and `NewDBDriver` selects that branch.

**Note:** Editing an existing memo goes through `UpdateMemo` (UPDATE, not INSERT) in the same driver files; INSERT applies to creating a new memo.
