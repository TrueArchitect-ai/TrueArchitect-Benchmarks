r02. **Premise correction:** This repository does not register any per-user API rate-limiting middleware, so there are no per-user request limits to report.

The HTTP/API stack uses other middleware and interceptors instead:

- Global Echo middleware in `server/server.go`: `middleware.Recover()` and `newCORSMiddleware()` from `server/cors.go`.
- API auth in `server/router/api/v1/v1.go`: a gRPC-Gateway auth middleware (`gatewayAuthMiddleware`) and Connect interceptors (`MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`).
- A request body cap via `http.MaxBytesHandler(..., maxAPIRequestBytes)` in `server/router/api/v1/v1.go`, where `maxAPIRequestBytes = 256 << 20` (256 MiB). That is a size limit, not a per-user request rate.

There is no use of Echo’s `RateLimiter`, `golang.org/x/time/rate`, or similar API throttling code anywhere under `server/`. The only rate-limiting mention is for email sending as a planned/future concern in `internal/email/doc.go` and `internal/email/README.md`, not for HTTP API traffic.
