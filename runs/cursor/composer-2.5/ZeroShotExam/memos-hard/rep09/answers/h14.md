**Computation site:** Markdown is parsed and metadata is extracted in `internal/markdown/markdown.go` (`ExtractAll`, `ExtractProperties`, `ExtractTags`, and `GenerateSnippet` for plain-text snippets). Persisted payload fields are assembled in `server/runner/memopayload/runner.go` via `RebuildMemoPayload`, which calls `ExtractAll` and writes into `MemoPayload` (`proto/store/memo.proto`). API responses add a live `snippet` in `server/router/api/v1/memo_service_converter.go` through `getMemoContentSnippet` (`server/router/api/v1/memo_service_webhooks.go`), which calls `GenerateSnippet` (64-character limit).

**Triggers:** `RebuildMemoPayload` runs on `CreateMemo` (including comments via `CreateMemoComment` → `CreateMemo`) in `server/router/api/v1/memo_service.go`, and on `UpdateMemo` only when the update mask includes `"content"` in the same file. `snippet` is recomputed on every memo read/list conversion (not stored). `server/runner/memopayload/runner.go` `RunOnce` can batch-rebuild all memo payloads, but it is not wired into server startup in `server/server.go`.

**Extracted properties:** From content into stored `MemoPayload`: `tags` (`#tag` tokens, excluding tags inside links/images); `property.has_link`, `property.has_task_list`, `property.has_code`, `property.has_incomplete_tasks`; and `property.title` (text of the first block-level H1, if present). At read time (not persisted): `snippet` (plain-text preview, code blocks omitted, truncated). `ExtractAll` also collects `@mentions`, but `RebuildMemoPayload` does not persist them—they are used separately for mention notifications in `server/router/api/v1/memo_mention_helpers.go`.
