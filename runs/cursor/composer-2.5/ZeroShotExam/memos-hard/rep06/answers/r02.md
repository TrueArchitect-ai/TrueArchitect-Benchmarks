**Premise correction:** This repository does not implement or register per-user API rate-limiting middleware. There is no middleware that tracks request counts per user or returns HTTP 429 for API rate limits.

What *is* registered for API traffic:

**Global Echo middleware** in `server/server.go`:
- `middleware.Recover()` (line 51)
- `newCORSMiddleware(profile)` from `server/cors.go` (line 52)

**API-specific middleware/interceptors** in `server/router/api/v1/v1.go` inside `RegisterGateway`:
- `gatewayAuthMiddleware` on the gRPC-Gateway mux (lines 69–98) — authentication/authorization only
- `http.MaxBytesHandler(..., maxAPIRequestBytes)` (lines 126, 144) — caps request body size at 256 MiB (`maxAPIRequestBytes = 256 << 20`), not a per-user request rate
- Connect interceptors (lines 133–137): `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go`

The only rate-limiting mention in the repo is a suggested pattern for email sending in `internal/email/README.md` and a comment in `internal/email/doc.go`; neither is wired into the HTTP API stack. No `golang.org/x/time/rate` usage or Echo `RateLimiter` middleware appears anywhere in the Go codebase.
