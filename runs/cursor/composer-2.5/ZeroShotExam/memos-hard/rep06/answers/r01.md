**Premise correction:** This repository does not configure a Redis connection for the cache layer. There are no Redis references anywhere in the codebase; the cache is an in-process, in-memory implementation.

**Actual mechanism:** The cache layer lives in `store/cache/cache.go` (`cache.New`, `cache.Config`, `DefaultConfig`). It is wired into the store in `store/store.go`: `store.New` builds a shared `cacheConfig` and passes it to three separate caches, including `userCache`:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

The default TTL is also defined in `store/cache/cache.go` (`DefaultConfig()` sets `DefaultTTL: 10 * time.Minute`).

User entries are cached in `store/user.go` via `s.userCache.Set(...)`, which calls `SetWithTTL` with the cache’s `DefaultTTL` (see `store/cache/cache.go` lines 92–94). There is no per-user override, so **user cache entries expire after 10 minutes**.
