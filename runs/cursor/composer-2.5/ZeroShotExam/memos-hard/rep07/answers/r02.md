**Premise correction:** This repository does not implement or register per-user API rate-limiting middleware. There is no middleware that caps requests per user over time (no `RateLimiter`, no `golang.org/x/time/rate`, and no per-user 429/throttle logic in the server code).

What *is* registered for API traffic:

- **Global Echo middleware** in `server/server.go`: `middleware.Recover()` and `newCORSMiddleware()` (`server/cors.go`).
- **API auth middleware/interceptors** in `server/router/api/v1/v1.go`:
  - gRPC-Gateway: `gatewayAuthMiddleware` via `runtime.WithMiddlewares(...)` (authentication/authorization, not rate limiting).
  - Connect RPC: `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, and `NewAuthInterceptor()` (`server/router/api/v1/connect_interceptors.go`).
- **Request body size cap** (not a per-user rate limit): `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` and `connect.WithReadMaxBytes(...)` in `server/router/api/v1/v1.go`.

Related but different limits:

- **Concurrency semaphores** in `server/router/api/v1/v1.go`: 3 concurrent thumbnail jobs and 2 concurrent image-processing jobs (instance-wide, not per user).
- **Email rate limiting** is only described as a future idea in `internal/email/README.md` and `internal/email/doc.go`; it is not wired into the HTTP API.

So there is no registration site for per-user API rate limiting, and therefore no per-user request limits to report.
