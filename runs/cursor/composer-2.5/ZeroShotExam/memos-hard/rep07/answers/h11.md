The data layer is the `store` package under [`/bench/repo/store/`](store/), which defines persistent entity structs mapped to database tables (e.g. [`User`](store/user.go), [`Memo`](store/memo.go), [`Attachment`](store/attachment.go), etc.).

Counting distinct Go packages **outside** `store/`, `proto/store/`, and `proto/gen/store/` that reference each entity type (via `store.Entity`, `store.FindEntity`, `store.UpdateEntity`, or `store.DeleteEntity`):

| Entity | Packages (outside data layer) |
|---|---|
| **User** | 7 |
| **Memo** | 7 |
| Attachment | 5 |
| Inbox, MemoRelation, MemoShare | 3 each |
| Reaction, UserIdentity, UserSetting, IdentityProvider | 2 each |
| InstanceSetting | 0 (external code uses `storepb.InstanceSetting` instead) |

**User** packages: `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`

**Memo** packages: same set except `server/auth`, plus `server/runner/memopayload`

**1st: User (~7 packages); 2nd: Memo (~7 packages)**

They tie at the package level. User is listed first because it appears in more files outside the data layer (40 vs 31) and uniquely reaches `server/auth` (e.g. [`server/auth/authenticator.go`](server/auth/authenticator.go)). Memo uniquely reaches `server/runner/memopayload` (e.g. [`server/runner/memopayload/runner.go`](server/runner/memopayload/runner.go)). The clear third place is **Attachment** at ~5 packages.
