**Premise correction:** This repository does not configure a Redis connection for the cache layer. There are no Redis references in the codebase; caching is done with an in-process, in-memory implementation in `store/cache/cache.go`.

**Actual mechanism:** The cache layer is wired up in `store/store.go` when `Store.New()` builds three `*cache.Cache` instances (including `userCache`). It passes a `cache.Config` with `DefaultTTL: 10 * time.Minute` (along with `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000`). The same defaults are defined in `cache.DefaultConfig()` in `store/cache/cache.go`.

User entries use that default TTL because `store/user.go` stores users via `s.userCache.Set(...)`, which calls `SetWithTTL` with `c.config.DefaultTTL` (see `store/cache/cache.go`). There is no per-user TTL override.

**Summary:** No Redis — cache config lives in `store/store.go`; user cache TTL is **10 minutes**.
