The browser loads another user's avatar with `GET /file/users/{username}/avatar` (URL set by `convertUserFromStore` in `server/router/api/v1/user_service_converters.go` and rendered by `<img src={avatarUrl}>` in `web/src/components/UserAvatar.tsx`). Avatar bytes are not stored as a separate file; they live in the `user.avatar_url` column as a base64 data URI.

Serving handler → data layer (request path):

FileServerService.serveUserAvatar — server/router/fileserver/fileserver.go
Profile.AllowAnonymous — internal/profile/profile.go
FileServerService.getCurrentUser — server/router/fileserver/fileserver.go
Authenticator.AuthenticateToUser — server/auth/authenticator.go
FileServerService.getUserByUsername — server/router/fileserver/fileserver.go
Store.GetUser — store/user.go
Store.ListUsers — store/user.go
Driver.ListUsers — store/driver.go
DB.ListUsers — store/db/sqlite/user.go
DB.QueryContext — store/db/sqlite/user.go
user.avatar_url — store/migration/sqlite/0.11/00__user_avatar.sql

Notes:
- Route registration: `fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)` in `FileServerService.RegisterRoutes` — server/router/fileserver/fileserver.go (wired from `server/server.go`).
- Auth hops (`getCurrentUser` → `AuthenticateToUser`) run only when `Profile.AllowAnonymous()` is false (private instance).
- `GetUser` with a username skips ID cache and delegates to `ListUsers`, which filters `username = ?`.
- On Postgres/MySQL, `DB.ListUsers` is the parallel file under `store/db/postgres/user.go` or `store/db/mysql/user.go`; the store interface is the same.
- After fetch, `serveUserAvatar` reads `store.User.AvatarURL`, decodes it via `FileServerService.parseDataURI`, and returns bytes with `echo.Context.Blob` — that is response encoding, not additional storage.
