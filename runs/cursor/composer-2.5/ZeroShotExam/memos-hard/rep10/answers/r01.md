**Premise correction:** This repository does not use Redis for the cache layer. A search of the codebase finds no Redis references; Memos uses an in-process, in-memory cache instead.

**Actual mechanism:** The cache layer is implemented in `store/cache/cache.go` as a thread-safe in-memory `sync.Map` cache with TTL and eviction. It is wired up when the store is created in `store/store.go`: `New()` builds a shared `cache.Config` and passes it to three separate caches, including `userCache`:

```39:53:store/store.go
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

The default TTL is also defined in `store/cache/cache.go` (`DefaultConfig()` sets `DefaultTTL: 10 * time.Minute`).

User entries are cached in `store/user.go` via `s.userCache.Set(...)`, which calls `Set()` without a custom TTL, so each user entry inherits the store-wide default of **10 minutes**:

```92:99:store/cache/cache.go
// Set adds a value to the cache with the default TTL.
func (c *Cache) Set(ctx context.Context, key string, value any) {
	c.SetWithTTL(ctx, key, value, c.config.DefaultTTL)
}
```

Example from `store/user.go`:

```98:98:store/user.go
	s.userCache.Set(ctx, userCacheKey(user.ID), user)
```

User cache keys are the numeric user ID as a string (`userCacheKey` in `store/user.go`). Expired entries are removed on read and by a background cleanup loop every 5 minutes (`CleanupInterval` in `store/store.go`).
