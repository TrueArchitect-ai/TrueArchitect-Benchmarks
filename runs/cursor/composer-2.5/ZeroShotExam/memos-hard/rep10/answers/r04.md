**Premise correction:** Neither. This repository does not use NATS or RabbitMQ for webhook delivery. There are no NATS/RabbitMQ dependencies in `go.mod`, and no broker-related imports anywhere in the webhook code.

**Actual mechanism:** Webhook delivery is handled in-process via a bounded Go channel and goroutine workers in `internal/webhook/webhook.go`.

The queue is declared as a package-level buffered channel:

```39:39:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are started in `init()` and consume from that channel, calling `Post()` for each payload:

```42:54:internal/webhook/webhook.go
func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

Producers enqueue via `PostAsync()`, which sends to `asyncPostQueue` (non-blocking; drops if full):

```184:195:internal/webhook/webhook.go
func PostAsync(requestPayload *WebhookRequestPayload) {
	if requestPayload == nil {
		slog.Warn("Dropped webhook dispatch because payload is nil")
		return
	}
	select {
	case asyncPostQueue <- requestPayload:
	default:
		slog.Warn("Dropped webhook dispatch because the async queue is full",
			slog.String("url", requestPayload.URL),
			slog.String("activityType", requestPayload.ActivityType))
	}
}
```

Call sites that trigger async delivery are in `server/router/api/v1/memo_service_webhooks.go` via `webhook.PostAsync(payload)`.
