**impl — construction — holders**

- **impl:** The unexported `service` struct in `internal/markdown/markdown.go` is the only concrete type implementing `markdown.Service`. At runtime it uses goldmark for parse/convert/HTML and delegates AST→markdown round-trips to `renderer.MarkdownRenderer` in `internal/markdown/renderer/markdown_renderer.go` (that renderer is not behind the interface).

- **construction:** Production code constructs a single instance via `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())` inside `NewAPIV1Service()` in `server/router/api/v1/v1.go`. `server/server.go` passes that same instance into `rss.NewRSSService(...)`.

- **holders:** Components that store `markdown.Service` as a field and use it at runtime:
  - `APIV1Service.MarkdownService` — `server/router/api/v1/v1.go` (used from `memo_service.go`, `memo_mention_helpers.go`, `memo_service_webhooks.go`; `ConnectServiceHandler` in `connect_handler.go` embeds `*APIV1Service` and inherits it)
  - `RSSService.MarkdownService` — `server/router/rss/rss.go` (calls `RenderHTML`)

`memopayload.Runner` in `server/runner/memopayload/runner.go` also declares a `MarkdownService` field, but `memopayload.NewRunner` is not called anywhere in production wiring; memo payload rebuilding instead passes `s.MarkdownService` from `APIV1Service` into the standalone `RebuildMemoPayload(...)` function.
