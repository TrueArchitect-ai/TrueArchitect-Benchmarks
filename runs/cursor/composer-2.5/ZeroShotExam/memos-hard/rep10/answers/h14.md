**Computation site:** Content-derived metadata is parsed in `internal/markdown/markdown.go` (`ExtractAll` / `ExtractProperties` walk the goldmark/GFM AST; tags use the custom parser in `internal/markdown/parser/tag.go`). It is assembled and written to the stored `MemoPayload` in `server/runner/memopayload/runner.go` via `RebuildMemoPayload`, which sets `memo.Payload.Tags` and `memo.Payload.Property` (schema in `proto/store/memo.proto`). List/preview snippets are computed separately at API response time in `server/router/api/v1/memo_service_webhooks.go` (`getMemoContentSnippet` → `GenerateSnippet` in `internal/markdown/markdown.go`), e.g. from `server/router/api/v1/memo_service_converter.go`.

**Triggers:** `RebuildMemoPayload` runs on `CreateMemo` (always, before persist) in `server/router/api/v1/memo_service.go`; on `UpdateMemo` when the update mask includes `"content"` in the same file; and indirectly on `CreateMemoComment`, which calls `CreateMemo` in `server/router/api/v1/memo_service_comments.go`. There is also a batch backfill path, `Runner.RunOnce` in `server/runner/memopayload/runner.go`, that rebuilds payloads for all memos. Snippets are recomputed on every memo read/conversion, not stored in the payload.

**Extracted properties:** From content into persisted payload — `tags` (`#tag` tokens, deduplicated, excluding tags inside links/images); `property.has_link` (link nodes); `property.has_code` (code block / fenced block / inline code); `property.has_task_list` (GFM task checkboxes); `property.has_incomplete_tasks` (unchecked task boxes); `property.title` (plain text of the first block-level H1, if any). At response time (not user-set, not in payload): `snippet` — plain-text summary truncated to 64 characters. `location` in `MemoPayload` is user-provided, not content-derived.
