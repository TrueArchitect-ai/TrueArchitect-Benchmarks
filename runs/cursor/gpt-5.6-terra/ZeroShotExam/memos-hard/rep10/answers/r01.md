Premise correction: Redis is not configured for this cache layer; it uses an in-process, `sync.Map`-backed cache.

Actual mechanism: `Store.New` creates `userCache` with a 10-minute default TTL in `store/store.go`. User create/update/read paths call `userCache.Set`, so user entries receive that default TTL in `store/user.go`; expiry is enforced by the cache implementation in `store/cache/cache.go`.
