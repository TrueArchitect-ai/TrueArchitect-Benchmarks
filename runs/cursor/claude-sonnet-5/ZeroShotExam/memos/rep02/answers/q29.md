q29.
- **Interceptor path:** The frontend auth interceptor is `authInterceptor` in `web/src/connect.ts` (defined at `web/src/connect.ts:156-178`, wired into the Connect transport at `web/src/connect.ts:184-189`). It reads/writes tokens via `web/src/auth-state.ts`.
- **Token kinds it manages:** A short-lived JWT **access token** (kept in memory + `localStorage` under `memos_access_token`, added as `Authorization: Bearer <token>` header — see `web/src/auth-state.ts:1-97` and `setAuthorizationHeader` in `web/src/connect.ts:97-100`), plus a **refresh token** carried as an httpOnly cookie (sent via `credentials: "include"` in `fetchWithCredentials`, `web/src/connect.ts:57-62`) that the interceptor uses to silently refresh the access token on expiry or on a `401 Unauthenticated` response (`refreshAccessToken`/`doRefreshAccessToken`, `web/src/connect.ts:74-91`).
- **Backend package that validates them:** `server/auth` (see `server/auth/authenticator.go`), whose `Authenticator` validates JWT access tokens (`AuthenticateByAccessTokenV2`), refresh tokens (`AuthenticateByRefreshToken`, checked against `store` for revocation/expiry), and Personal Access Tokens (`AuthenticateByPAT`). It's invoked by the Connect interceptor in `server/router/api/v1/connect_interceptors.go` and the authorization logic in `server/router/api/v1/authz.go`.
