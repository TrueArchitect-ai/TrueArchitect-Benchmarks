When `CreateMemo` (`server/router/api/v1/memo_service.go:157`) finishes creating a memo, it calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)`, defined in `server/router/api/v1/memo_service_webhooks.go:14-17`, which delegates to the shared `dispatchMemoRelatedWebhook` helper (`server/router/api/v1/memo_service_webhooks.go:48-74`). That helper looks up the creator's registered webhooks via `s.Store.GetUserWebhooks`, builds a `webhook.WebhookRequestPayload`, and calls `webhook.PostAsync(payload)` (`internal/webhook/webhook.go:184-196`), which enqueues the payload for one of several background workers that call `webhook.Post` (`internal/webhook/webhook.go:42-55, 119-180`) to actually perform the HTTP `POST` to the hook's URL using a shared `safeClient` `*http.Client` (SSRF-guarded dialer) — i.e., Go's standard-library `net/http` package does the delivery.

Each outgoing request is signed following the Standard Webhooks convention: if a `SigningSecret` is set, `webhook.Post` derives the raw HMAC key via `resolveSigningKey` (decoding `whsec_`-prefixed base64 secrets), computes an HMAC-SHA256 over `"{msgID}.{timestamp}."+body`, base64-encodes it, and sets the `webhook-id`, `webhook-timestamp`, and `webhook-signature: v1,<sig>` headers (`internal/webhook/webhook.go:92-117, 133-150`).
