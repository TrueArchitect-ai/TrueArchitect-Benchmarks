When `Store.DeleteMemo` is called (invoked from the `DeleteMemo` API handler in `server/router/api/v1/memo_service.go:580`), the store layer deletes the following records before deleting the memo row itself:

1. **Memo relations** where the memo is the source (`memo_relation` rows with `memo_id = delete.ID`)
2. **Memo relations** where the memo is the target/related memo (`memo_relation` rows with `related_memo_id = delete.ID`)
3. **Attachments** linked to the memo (each attachment found via `ListAttachments` is individually deleted via `DeleteAttachment`)

This is implemented in:

```140:159:/bench/repo/store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	if err != nil {
		return err
	}
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

Note: at the API-handler level (`server/router/api/v1/memo_service.go:567-577`), any child "comment" memos (memo relations of type `MemoRelationComment`) are also deleted first, but that deletion is itself just a recursive call into this same `Store.DeleteMemo` function — so the actual record types the store layer deletes before removing a memo row are limited to memo relations and attachments as listed above.
