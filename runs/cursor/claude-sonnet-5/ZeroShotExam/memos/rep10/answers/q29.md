q29.

**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (a Connect-ES `Interceptor`) is installed on the main Connect transport (`createConnectTransport({ ..., interceptors: [authInterceptor] })`). It reads the current token via `getRequestToken()`, sets it on requests with `setAuthorizationHeader()` (`Authorization: Bearer <token>`), and on an `Unauthenticated` response it calls `refreshAccessToken()` and retries once (tagged via the `X-Retry` header) before redirecting via `web/src/utils/auth-redirect.ts` if refresh fails. Token state (in-memory + `localStorage`, cross-tab sync via `BroadcastChannel`) lives in `web/src/auth-state.ts`, and proactive refresh-on-focus is in `web/src/hooks/useTokenRefreshOnFocus.ts`.

**Token kinds it manages:**
- **JWT access token** (short-lived, 15 min) — held client-side in memory/`localStorage` (`memos_access_token`), sent as `Authorization: Bearer <token>`.
- **JWT refresh token** (long-lived, 30 days) — not directly touched by JS; it's an httpOnly cookie (`memos_refresh`) sent automatically because the fetch is configured with `credentials: "include"` (`fetchWithCredentials` in `web/src/connect.ts`); used only to call `AuthService.refreshToken` to mint a new access token.
- (Backend also supports a third kind, Personal Access Tokens/PATs, but these aren't managed by this interceptor — they're for programmatic/API clients.)

**Backend package that validates them:** `server/auth` (`github.com/usememos/memos/server/auth`), specifically:
- `server/auth/token.go` — JWT generation/parsing (`GenerateAccessTokenV2`, `ParseAccessTokenV2`, `GenerateRefreshToken`, `ParseRefreshToken`, PAT hashing) and constants like `RefreshTokenCookieName = "memos_refresh"`.
- `server/auth/authenticator.go` — the `Authenticator` type with `AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`, and `AuthenticateToUser`/`Authenticate`, which resolve the `Authorization` header (Bearer access token or PAT) and fall back to the `memos_refresh` cookie.

This `server/auth` package is consumed by the Connect/gRPC interceptors and file server in `server/router/api/v1/connect_interceptors.go` and `server/router/fileserver`, and the actual login/refresh endpoints are implemented in `server/router/api/v1/auth_service.go` and `server/router/api/v1/auth_service_session.go`.

Answer format: `web/src/connect.ts` (`authInterceptor`); JWT access token (`memos_access_token`, Bearer header) + JWT refresh token (`memos_refresh` httpOnly cookie); `server/auth`
