q28.
The server (`server/server.go`) starts exactly **one** background worker in `startBackgroundRunners` (called from `Server.Start`):

- s3presign runner (`server/runner/s3presign/runner.go`) — self-driven `time.Ticker` on a fixed 12-hour interval (`runnerInterval = time.Hour * 12` in `runner.go:27`); it also runs once immediately at startup via `s3presignRunner.RunOnce(ctx)` before the ticker loop begins (`server/server.go:161-171`).

Notes on infrastructure that exists but is **not** used to drive any server-started worker:

- `server/runner/memopayload/runner.go` defines a `Runner` with `NewRunner`/`RunOnce` that batch-rebuilds all memo payloads, but it is never constructed or scheduled anywhere (`grep` shows `memopayload.NewRunner` has zero callers). The server only calls the package-level helper `memopayload.RebuildMemoPayload` synchronously inside request handlers in `server/router/api/v1/memo_service.go` (lines 108 and 447), i.e. it runs on-demand per API request, not as a background/scheduled runner.
- `internal/scheduler` (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`) implements a full cron-style job scheduler ("GitHub Actions-inspired," per `internal/scheduler/doc.go`) with cron expression parsing, timezones, and middleware. It is exercised only by its own package tests (`example_test.go`, `integration_test.go`) — there are no imports of `github.com/usememos/memos/internal/scheduler` anywhere under `server/` or `cmd/`, so this scheduling infrastructure is entirely unused by the running server.
