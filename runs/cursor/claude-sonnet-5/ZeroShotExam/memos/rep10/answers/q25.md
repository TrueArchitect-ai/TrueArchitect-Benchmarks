**Engine**: Google's [`cel-go`](https://github.com/google/cel-go) (Common Expression Language) implementation, wrapped in a custom three-phase filter engine at `internal/filter/` (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`).

**Mechanism**: `ListMemos` (`server/router/api/v1/memo_service.go:211-216`) appends the raw CEL filter string to `store.FindMemo.Filters` (after validating it via `validateFilter` in `server/router/api/v1/shortcut_service.go:336-360`, which calls `filter.DefaultEngine()`); each dialect-specific store implementation (`store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`) then calls `filter.AppendConditions` (`internal/filter/helpers.go`), which for each filter string invokes `Engine.CompileToStatement` (`internal/filter/engine.go:74-80`) — this parses the CEL expression against the memo schema's `cel.Env` (`schema.go`) into a CEL AST, converts it into a dialect-agnostic intermediate representation (`ir.go`/`parser.go`), and finally the renderer in `render.go` walks that IR to emit a SQL fragment plus placeholder args tailored to `DialectSQLite`, `DialectMySQL`, or `DialectPostgres` (handling things like JSON extraction operators, `?`/`$n` placeholders, and `LIKE`/`ILIKE`/`REGEXP` differences per dialect), which is then appended to the `WHERE` clause.
