Memo lifecycle events that dispatch webhooks, and their dispatch functions (all in `server/router/api/v1/memo_service_webhooks.go`, called from the sites noted):

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook` — called from `CreateMemo` in `server/router/api/v1/memo_service.go:157`
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook` — called from `server/router/api/v1/memo_update_helpers.go:67`
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook` — called from `DeleteMemo` in `server/router/api/v1/memo_service.go:562`
- memo comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook` — called from `CreateMemoComment` in `server/router/api/v1/memo_service_comments.go:119`

Note: `DispatchMemoCreatedWebhook`, `DispatchMemoUpdatedWebhook`, and `DispatchMemoDeletedWebhook` are thin wrappers that all call the shared helper `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48-74`), which builds the payload and passes the given `activityType`.

Delivery convergence: all four dispatch paths end up calling `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`), which enqueues the `WebhookRequestPayload` onto a bounded channel (`asyncPostQueue`). A pool of worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) reads from that channel and performs the actual HTTP delivery via `webhook.Post` (`internal/webhook/webhook.go:120-180`), which signs (if a secret is set) and POSTs the payload to the target URL. So `webhook.Post` (invoked asynchronously through `webhook.PostAsync`) in `internal/webhook/webhook.go` is the single convergence point for delivery.
