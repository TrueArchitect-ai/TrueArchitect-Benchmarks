Background workers actually started by the server (`server/server.go` → `startBackgroundRunners`, called from `Start`):

- S3 presign runner (`server/runner/s3presign/runner.go`) — trigger: time-based polling loop. `startBackgroundRunners` (`server/server.go:161-171`) creates `s3presign.NewRunner(s.Store)`, runs `RunOnce` immediately, then launches `s3presignRunner.Run(s3Context)` in a goroutine, which uses a `time.NewTicker(runnerInterval)` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:26-41`) to re-scan/re-presign S3 attachments every 12 hours until its context is cancelled on shutdown.

- Webhook async dispatch pool (`internal/webhook/webhook.go:39-55`) — trigger: not time-scheduled at all; it's a fixed pool of 4 goroutines spun up in the package's `init()` (so it starts as soon as the binary loads, not via `server.Start`), each ranging over a buffered channel `asyncPostQueue` and firing `Post()` whenever a webhook payload is pushed onto the queue (event/queue-driven, triggered by activity events elsewhere in the app).

Not actually started as a background loop:

- `server/runner/memopayload/runner.go` defines a `Runner` type with `RunOnce`/`RebuildMemoPayload`, structured just like `s3presign`'s runner, but the server never instantiates `memopayload.NewRunner` or calls its `RunOnce` as a background job — only the standalone `memopayload.RebuildMemoPayload(...)` function is called synchronously inline from `server/router/api/v1/memo_service.go` (lines 108 and 447) during memo create/update requests. So this "runner" exists but isn't scheduled/started as a worker.

Unused scheduling infrastructure note:

- `internal/scheduler` (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`, etc.) implements a full cron-style job scheduler ("GitHub Actions-inspired", per `internal/scheduler/doc.go`) with cron expression parsing, timezone support, and middleware. It is never imported by `server/`, `cmd/memos/`, or any runner package — the only references to it are within its own test files (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). This entire package is dead/unused infrastructure as far as the running server is concerned; the server relies solely on a hand-rolled `time.Ticker` inside `s3presign.Runner.Run` for its one periodic job.
