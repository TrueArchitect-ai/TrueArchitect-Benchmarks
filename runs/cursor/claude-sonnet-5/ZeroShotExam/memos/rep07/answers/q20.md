- **Mechanism**: Server-Sent Events (SSE) over a long-lived `GET /api/v1/sse` HTTP endpoint (`text/event-stream`), authenticated via Bearer token, with periodic heartbeats. The browser side consumes it via a `fetch`-based streaming reader in `web/src/hooks/useLiveMemoRefresh.ts`.

- **Hub path**: `server/router/api/v1/sse_hub.go` — defines `SSEHub` (client registry, `Subscribe`/`Unsubscribe`/`Broadcast`, with per-client visibility filtering via `canReceive`). The HTTP streaming loop that reads from a subscribed client's channel and writes `data: ...` lines is in `server/router/api/v1/sse_handler.go` (`RegisterSSERoutes`/`handleSSE`).

- **Handlers that broadcast through it** (all call `s.SSEHub.Broadcast(...)` in package `server/router/api/v1`):
  - `CreateMemo` (`memo_service.go`) — broadcasts `memo.created`
  - `DeleteMemo` (`memo_service.go`) — broadcasts `memo.deleted`
  - `CreateMemoComment` (`memo_service_comments.go`) — broadcasts `memo.comment.created`
  - `UpsertMemoReaction` (`reaction_service.go`) — broadcasts `reaction.upserted`
  - `DeleteMemoReaction` (`reaction_service.go`) — broadcasts `reaction.deleted`
  - `UpdateMemo` (`memo_service.go`), `SetMemoAttachments` (`memo_attachment_service.go`), and `SetMemoRelations` (`memo_relation_service.go`) — all funnel through the shared helper `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go`), which broadcasts `memo.updated`
