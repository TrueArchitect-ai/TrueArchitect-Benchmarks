**Engine + path:** The filter is parsed by a custom CEL (Common Expression Language, via `google/cel-go`) engine that lives in `internal/filter/` (`internal/filter/engine.go`, `internal/filter/parser.go`, `internal/filter/ir.go`, `internal/filter/render.go`, `internal/filter/schema.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-215`) passes `request.Filter` through `validateFilter` (`server/router/api/v1/shortcut_service.go:336-359`) and into `store.FindMemo.Filters`, and at query time (e.g. `store/db/sqlite/memo.go:57-61`, and the analogous postgres/mysql `memo.go`) each dialect store calls `filter.DefaultEngine()` and `filter.AppendConditions`, which for each filter string calls `Engine.CompileToStatement`: this first parses/type-checks the CEL expression against the memo `Schema` (`internal/filter/schema.go`) via `cel-go` and lowers the resulting AST into a dialect-agnostic condition tree (IR, `internal/filter/parser.go`/`ir.go`), then the `render.go` renderer walks that IR and emits dialect-specific SQL/args (`DialectSQLite`, `DialectMySQL`, `DialectPostgres` branches in `internal/filter/render.go`, e.g. differing placeholders `?` vs `$n`, JSON access functions, `LIKE`/`ILIKE`/`REGEXP`/`~`, etc.), which is then appended as a parenthesized fragment to the `WHERE` clause built by each dialect's store package.
