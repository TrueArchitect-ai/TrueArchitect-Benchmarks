q16.

Before deleting the memo row itself, the store layer (`Store.DeleteMemo` in `store/memo.go`) deletes:

1. **Memo relation records** where the memo is the source memo (`memo_relation` rows with `memo_id = <id>`) — via `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})`.
2. **Memo relation records** where the memo is the related/target memo (`memo_relation` rows with `related_memo_id = <id>`, e.g. comment/reference links) — via `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})`.
3. **Attachments** linked to the memo — it lists them with `s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})` and deletes each one individually via `s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID})` (which also removes the underlying attachment storage/file, then the attachment row).

Only after these deletions does it call `s.driver.DeleteMemo(ctx, delete)`, which issues the actual `DELETE FROM memo WHERE id = ?` (see e.g. `store/db/sqlite/memo.go:237-248`, and equivalently in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`).

Reference:

```140:159:store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	if err != nil {
		return err
	}
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

Note: reaction cleanup and cascading deletion of comment memos (which are themselves memos linked via a "comment" `memo_relation`) are handled one level up, in the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-580`), not inside the store layer's `DeleteMemo` itself.
