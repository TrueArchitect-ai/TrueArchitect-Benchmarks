- **Auth interceptor**: `authInterceptor`, defined and wired into the Connect-RPC transport in `web/src/connect.ts` (lines 156–189). It attaches `Authorization: Bearer <token>` headers to outgoing requests, and on an `Unauthenticated` response, triggers a token refresh (via `refreshAccessToken()`/`web/src/auth-state.ts`) and retries once before redirecting to login on failure (`web/src/utils/auth-redirect.ts`).
- **Tokens it manages**: short-lived JWT **access tokens** (kept in memory + `localStorage`, managed by `web/src/auth-state.ts`, refreshed proactively on tab focus via `web/src/hooks/useTokenRefreshOnFocus.ts`) and, indirectly, the **refresh token**, which is stored as an HTTP-only cookie and used only via the dedicated `AuthService.refreshToken` call (`refreshAuthClient` in `web/src/connect.ts`) — not read/set directly by JS.
- **Backend validation package**: `server/auth` (specifically `server/auth/authenticator.go`), whose `Authenticator` validates JWT access tokens (`AuthenticateByAccessTokenV2`), refresh-token cookies (`AuthenticateByRefreshToken`), and Personal Access Tokens (`AuthenticateByPAT`), and is shared across the gRPC/Connect interceptors and file server for consistent auth handling.
