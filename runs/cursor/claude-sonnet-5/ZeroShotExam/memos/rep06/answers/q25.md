**Engine + path:** Google's [CEL](https://github.com/google/cel-go) (Common Expression Language), wrapped by a custom filter engine at `internal/filter/` (`engine.go`, `parser.go`/`ir.go` for AST→IR conversion, `render.go` for SQL rendering, `schema.go` for field mappings).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-216`, validated via `validateFilter` in `server/router/api/v1/shortcut_service.go:336`) takes `request.Filter` and appends it to `store.FindMemo.Filters`; each store backend (`store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`) then calls `filter.AppendConditions` (`internal/filter/helpers.go`), which uses the process-wide `filter.DefaultEngine()` (`internal/filter/engine.go`) to `cel.Env.Compile` the filter string into a CEL AST, converts that AST into a dialect-agnostic `Condition` tree (via `buildCondition` in the parser), and then a `renderer` (`internal/filter/render.go`) walks that tree to emit dialect-specific SQL fragments and placeholder args — e.g. `?`-style placeholders and backtick-quoted columns/JSON_EXTRACT for SQLite/MySQL vs. `$N`-style placeholders, `->>`/`->` JSONB operators and `ILIKE`/POSIX `~` for Postgres — selected by the `DialectName` (`DialectSQLite`/`DialectPostgres`/`DialectMySQL`) passed into `RenderOptions`.
