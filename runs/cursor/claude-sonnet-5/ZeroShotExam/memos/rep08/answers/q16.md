When `Store.DeleteMemo` is called (invoked by the API's `DeleteMemo` handler in `server/router/api/v1/memo_service.go`), the store layer deletes the following kinds of records **before** deleting the `memo` row itself:

1. **Memo relations** where the memo is the source (`memo_relation` rows matching `MemoID`), via `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})`
2. **Memo relations** where the memo is the target/related memo (`memo_relation` rows matching `RelatedMemoID`), via `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})`
3. **Attachments** linked to the memo — it lists all attachments for the memo and deletes each one individually via `s.DeleteAttachment` (which also removes the attachment's underlying storage file/object before removing its DB row)

Only after these cleanups does it call `s.driver.DeleteMemo(ctx, delete)` to remove the memo row itself.

```140:159:/bench/repo/store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	if err != nil {
		return err
	}
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```
