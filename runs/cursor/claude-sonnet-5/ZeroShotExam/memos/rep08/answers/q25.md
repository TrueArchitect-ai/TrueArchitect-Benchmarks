**Engine + path:** The filter is CEL (Common Expression Language, via `github.com/google/cel-go`), wrapped by a custom engine in `internal/filter` (`Engine`/`Program`/`renderer` types in `internal/filter/engine.go`, `internal/filter/ir.go`, and `internal/filter/render.go`, with the field schema in `internal/filter/schema.go`).

**Mechanism (one sentence):** `ListMemos` (`server/router/api/v1/memo_service.go:211-216`) validates `request.Filter` via `s.validateFilter` (`server/router/api/v1/shortcut_service.go:336-359`), which grabs the process-wide `filter.DefaultEngine()`; that engine's `Compile` (`internal/filter/engine.go:48-71`) uses the CEL environment (`cel.NewEnv`) to parse the expression into a CEL AST and then walks it (`buildCondition`) into a dialect-agnostic `Condition` intermediate-representation tree, and later, inside each store backend's `ListMemos` (`store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`), `filter.AppendConditions` (`internal/filter/helpers.go:9-25`) calls `engine.CompileToStatement(..., RenderOptions{Dialect: ...})`, whose `renderer` (`internal/filter/render.go`) walks that IR and emits dialect-specific SQL fragments/placeholders (e.g. `$1` vs `?`, `JSON_EXTRACT` vs `->>`, `ILIKE`/`REGEXP`/`~`, etc.) that get appended to the query's `WHERE` clause.
