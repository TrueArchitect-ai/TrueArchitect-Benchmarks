q28.

The server's `Start` method calls `startBackgroundRunners`, which starts exactly one background worker:

- **S3 presign runner** (`server/runner/s3presign/runner.go`, wired in `server/server.go:161-171`) — triggered on an internal `time.NewTicker(12 * time.Hour)` inside `Runner.Run` (`server/runner/s3presign/runner.go:26-41`). It's also run once synchronously at startup via `s3presignRunner.RunOnce(ctx)` (`server/server.go:163`) before the ticker loop is launched in a goroutine (`server/server.go:166-171`).

That is the only goroutine/worker actually started by `Server.Start`/`startBackgroundRunners` (`server/server.go:153-174`); `main.go` (`cmd/memos/main.go:76-106`) does nothing beyond calling `server.NewServer` and `s.Start(ctx)`, then blocks on the shutdown signal — it doesn't spin up any other scheduled workers.

Notably NOT started as a background worker:
- **Memo payload rebuild runner** (`server/runner/memopayload/runner.go`) has a `Runner` type with a batch-processing `RunOnce(ctx)` method, but `memopayload.NewRunner` is never called anywhere in the server. Only its standalone helper function `RebuildMemoPayload` is used, and only synchronously inline inside request handling in `server/router/api/v1/memo_service.go:108` and `:447` (when a memo is created/updated) — not as a scheduled/background job.

Unused scheduling infrastructure:
- `internal/scheduler` (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`) implements a full cron-style job scheduler ("GitHub Actions-inspired cron job scheduler" per `internal/scheduler/doc.go`) with cron-expression parsing, timezone support, and middleware. It is a general-purpose, ready-to-use package, but it is referenced only from its own tests/examples (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`) — no file under `server/` or `cmd/` imports `internal/scheduler`, so this scheduling infrastructure is present in the codebase but not actually used by the running server.
