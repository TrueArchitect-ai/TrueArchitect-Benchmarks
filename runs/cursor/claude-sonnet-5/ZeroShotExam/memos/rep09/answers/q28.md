The server (`server/server.go`) starts exactly one background worker:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — trigger: run once immediately at startup (`s3presignRunner.RunOnce(ctx)` in `startBackgroundRunners`, `server/server.go:163`), then re-triggered by an internal `time.NewTicker(runnerInterval)` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27-40`), looping until its dedicated context is cancelled on shutdown.

That's it — `Server.startBackgroundRunners` (`server/server.go:153-174`) only ever creates/launches this one goroutine (tracked via `backgroundRunnerWG`/`backgroundRunnerCancels`).

Unused scheduling infrastructure present in the codebase but not wired into the server:

- `internal/scheduler` (`scheduler.go`, `job.go`, `parser.go`, `doc.go`) is a full cron-style job scheduler (cron-expression parsing, timezone support, middleware, `Start`/`Stop`), but it is referenced only from its own `example_test.go`/`integration_test.go` — no production code (`server/`, `cmd/`) ever calls `scheduler.New()` or registers a job with it.
- `server/runner/memopayload` (`runner.go`) defines a `Runner` type with a `RunOnce` method meant to batch-rebuild payloads for *all* memos, but nothing ever constructs it via `memopayload.NewRunner(...)` or calls `Runner.RunOnce` outside its own tests — it has no `Run`/ticker loop at all, and it is never registered in `startBackgroundRunners`. The only production use of this package is the plain function `memopayload.RebuildMemoPayload`, called synchronously inline on individual memo create/update requests in `server/router/api/v1/memo_service.go:108,447` — not as a scheduled/background job.
