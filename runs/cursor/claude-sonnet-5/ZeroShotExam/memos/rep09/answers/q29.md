q29.

- **Interceptor path**: The frontend auth interceptor is `authInterceptor` defined in `web/src/connect.ts` (lines 156–178), registered on the Connect-RPC transport at `web/src/connect.ts:184-189`. It attaches the `Authorization: Bearer <token>` header (`setAuthorizationHeader`, `connect.ts:97-100`) and reactively refreshes on a `Code.Unauthenticated` response before retrying once (`connect.ts:161-177`).
- **Tokens it manages**: 
  - A short-lived **JWT access token**, held in memory and persisted to `localStorage` (keys `memos_access_token` / `memos_token_expires_at`), managed via `web/src/auth-state.ts` (`getAccessToken`, `setAccessToken`, `isTokenExpired`, `clearAccessToken`), and synced across tabs with a `BroadcastChannel` (`auth-state.ts:9-50`).
  - A **refresh token**, sent as an HttpOnly cookie automatically via `credentials: "include"` (`fetchWithCredentials`, `connect.ts:57-62`) and exchanged for a new access token by calling `AuthService.refreshToken` on a separate, interceptor-free transport (`connect.ts:64-83`) to avoid recursive auth loops.
- **Backend package that validates them**: `server/auth` (specifically `server/auth/authenticator.go`'s `Authenticator` type, with `AuthenticateByAccessTokenV2` for the JWT access token and `AuthenticateByRefreshToken` for the refresh-token cookie, plus `AuthenticateByPAT` for personal access tokens). This `Authenticator` is constructed via `NewAuthenticator` and used by the API middleware/handlers such as `server/router/api/v1/authz.go`, `server/router/api/v1/auth_service_session.go`, `server/router/api/v1/sse_handler.go`, and `server/router/fileserver/fileserver.go`.

**Answer format**: `web/src/connect.ts` (authInterceptor); JWT access token (localStorage) + refresh token (HttpOnly cookie), plus PAT support server-side; `server/auth`
