**Engine:** Google's `cel-go` (Common Expression Language), wrapped by a custom filter engine that lives in `internal/filter/` (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:178-215`) puts `request.Filter` into `store.FindMemo.Filters` (after validating it via `s.validateFilter`, `server/router/api/v1/shortcut_service.go:336`); the shared `filter.Engine` (obtained from `filter.DefaultEngine()`, `internal/filter/engine.go:110`) parses the CEL string with `cel-go` against the memo `Schema` (`internal/filter/schema.go`), builds a dialect-agnostic condition tree in `parser.go`/`ir.go`, and then each store driver (`store/db/sqlite/memo.go:61`, `store/db/mysql/memo.go:69`, `store/db/postgres/memo.go:58`) calls `filter.AppendConditions`, which invokes `engine.CompileToStatement` with `DialectSQLite`/`DialectMySQL`/`DialectPostgres` so the renderer in `internal/filter/render.go` walks that same IR and emits dialect-specific SQL (placeholders, JSON access, `LIKE`/`REGEXP`/`~`, etc.) plus args that get appended to the `WHERE` clause.
