q20. The server uses **Server-Sent Events (SSE)** over HTTP (`text/event-stream`, endpoint `GET /api/v1/sse`) to push live events to browsers — not WebSockets.

- **Mechanism**: SSE. Clients connect to `/api/v1/sse` (registered in `server/router/api/v1/sse_handler.go`), authenticate via bearer token, subscribe to the hub, and the handler loop writes `data: ...\n\n` frames (plus periodic heartbeats) to the response as events arrive on the client's channel (`server/router/api/v1/sse_handler.go:27-110`).
- **Hub implementation**: `server/router/api/v1/sse_hub.go` — the `SSEHub` type (`NewSSEHub`, `Subscribe`, `Unsubscribe`, `Close`, `Broadcast`) maintains the set of connected `SSEClient`s and fans out `SSEEvent`s to them, filtering by visibility/creator via `canReceive`.
- **Memo/reaction handlers that broadcast through it** (all in `server/router/api/v1`, calling `s.SSEHub.Broadcast(...)`):
  - `CreateMemo` — `memo_service.go:163` (broadcasts `memo.created`)
  - `DeleteMemo` — `memo_service.go:585` (broadcasts `memo.deleted`)
  - `dispatchMemoUpdatedSideEffects` — `memo_update_helpers.go:71` (broadcasts `memo.updated`; called by `UpdateMemo` in `memo_service.go:513`, and also from `memo_attachment_service.go:48` and `memo_relation_service.go:48` when attachments/relations change)
  - `CreateMemoComment` — `memo_service_comments.go:126` (broadcasts `memo.comment.created`)
  - `UpsertMemoReaction` — `reaction_service.go:106` (broadcasts `reaction.upserted`)
  - `DeleteMemoReaction` — `reaction_service.go:161` (broadcasts `reaction.deleted`)
