**Engine + path:** The filter syntax is Google's [CEL](https://github.com/google/cel-go) (Common Expression Language), parsed by the custom filter engine in `internal/filter` (`internal/filter/engine.go`, `internal/filter/parser.go`, `internal/filter/ir.go`, `internal/filter/render.go`, `internal/filter/schema.go`), which memos calls via `filter.DefaultEngine()`.

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-216`) puts `request.Filter` into `store.FindMemo.Filters` after validating it with `validateFilter` (`server/router/api/v1/shortcut_service.go:336-359`), and each dialect's store implementation (`store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`) calls `filter.AppendConditions`, which uses the shared `Engine` to `cel.Env.Compile` the expression into a CEL AST, convert it (via `buildCondition` in `parser.go`) into a dialect-agnostic IR (`ir.go`) validated against the memo `Schema`, and finally render that IR (`render.go`) into a SQL fragment + placeholder args tailored to the target dialect (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`, e.g. `?` vs `$n` placeholders, `JSON_EXTRACT`/`->>`/`JSON_TABLE`, `LIKE`/`ILIKE`/`REGEXP`/`~`), which is then appended to the `WHERE` clause of the memo query.
