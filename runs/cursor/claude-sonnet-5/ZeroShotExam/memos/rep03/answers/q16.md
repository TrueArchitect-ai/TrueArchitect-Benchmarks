At the store layer, `Store.DeleteMemo` (`store/memo.go`) deletes the following records before removing the `memo` row itself:

1. **Memo relation records** where the memo is the source (`memo_relation` rows with `memo_id` = the deleted memo's ID) — via `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})`.
2. **Memo relation records** where the memo is the target/related memo (`memo_relation` rows with `related_memo_id` = the deleted memo's ID) — via `s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})`.
3. **Attachment records** linked to the memo — it lists all attachments for the memo (`s.ListAttachments` with `MemoID`) and calls `s.DeleteAttachment` for each one, which also deletes the attachment's underlying storage (local file or S3 object) and derived caches, in addition to the `attachment` row itself.

Only after these deletions does it call `s.driver.DeleteMemo(ctx, delete)`, which issues the actual `DELETE FROM memo WHERE id = ?`.

```140:159:/bench/repo/store/memo.go
func (s *Store) DeleteMemo(ctx context.Context, delete *DeleteMemo) error {
	// Clean up memo_relation records where this memo is either the source or target.
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID}); err != nil {
		return err
	}
	if err := s.driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID}); err != nil {
		return err
	}
	// Clean up attachments linked to this memo.
	attachments, err := s.ListAttachments(ctx, &FindAttachment{MemoID: &delete.ID})
	if err != nil {
		return err
	}
	for _, attachment := range attachments {
		if err := s.DeleteAttachment(ctx, &DeleteAttachment{ID: attachment.ID}); err != nil {
			return err
		}
	}
	return s.driver.DeleteMemo(ctx, delete)
}
```

(Note: at the API layer, `server/router/api/v1/memo_service.go`'s `DeleteMemo` also deletes any "comment" memo relations by calling `Store.DeleteMemo` recursively for each comment memo *before* deleting the target memo, but that is API-layer orchestration, not something the store's `DeleteMemo` itself does internally.)
