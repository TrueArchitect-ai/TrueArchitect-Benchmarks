MemoService is exposed over two protocols:

1. **gRPC-Gateway (REST/JSON-over-HTTP)** — registered via `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` in `server/router/api/v1/v1.go` (line 108), which wires the service into the `grpc-gateway` mux (generated gateway code lives in `proto/gen/api/v1/memo_service.pb.gw.go`, but the registration call itself is in `v1.go`).

2. **Connect protocol** — registered via `apiv1connect.NewMemoServiceHandler(s, opts...)` inside `RegisterConnectHandlers` in `server/router/api/v1/connect_handler.go` (line 40), with the `ConnectServiceHandler` wrapping/adapting each MemoService method (e.g. `CreateMemo`, `ListMemos`, etc.) in `server/router/api/v1/connect_services.go` (lines 304–464).

Both are mounted onto the same Echo server in `RegisterGateway` (`server/router/api/v1/v1.go`, lines 65–147): the gateway mux is mounted at `/api/v1/*` and `/file/*`, while the Connect mux is mounted at `/memos.api.v1.*`.

Answer format:
- gRPC-Gateway (REST/JSON) — `server/router/api/v1/v1.go`
- Connect — `server/router/api/v1/connect_handler.go`
