q19. MemoService is served over two protocols:

1. **gRPC-Gateway (REST/JSON-over-HTTP)** — registration happens via `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` in `server/router/api/v1/v1.go` (line 108, inside `RegisterGateway`), mounted at `/api/v1/*`.

2. **Connect protocol (Connect-RPC, also usable as gRPC/gRPC-Web over HTTP)** — the wrapping/registration happens via `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` in `server/router/api/v1/connect_handler.go` (line 40, inside `RegisterConnectHandlers`), mounted at `/memos.api.v1.*` (set up from `server/router/api/v1/v1.go` lines 139-144). The actual method implementations that adapt Connect requests to the shared `APIV1Service` (e.g. `CreateMemo`, `ListMemos`, etc.) live in `server/router/api/v1/connect_services.go` (lines 304-464, "MemoService" section).

Both paths ultimately delegate to the same `APIV1Service` gRPC-style method implementations (single source of truth), so there is no separate/third native `grpc.NewServer` — only these two protocol front-ends exist.
