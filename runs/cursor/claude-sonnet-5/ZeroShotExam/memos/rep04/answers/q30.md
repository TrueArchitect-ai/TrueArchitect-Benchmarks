Convergence for delivery:

- `DispatchMemoCreatedWebhook` and `DispatchMemoUpdatedWebhook` both funnel through the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which builds a `webhook.WebhookRequestPayload` per registered webhook and calls `webhook.PostAsync`.
- `DispatchMemoDeletedWebhook` also calls `dispatchMemoRelatedWebhook`, and `DispatchMemoCommentCreatedWebhook` builds its payload inline but likewise calls `webhook.PostAsync` directly — so **every** event ultimately funnels into `webhook.PostAsync` (`internal/webhook/webhook.go:184`).
- `webhook.PostAsync` enqueues the payload onto `asyncPostQueue`, a buffered channel serviced by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:39-55`), each of which calls `webhook.Post` (`internal/webhook/webhook.go:120`) to perform the actual signed HTTP POST to the webhook URL via the SSRF-guarded `safeClient`.

So the single true delivery convergence point is `webhook.Post` in `internal/webhook/webhook.go`, reached asynchronously through `webhook.PostAsync` and the internal `asyncPostQueue` worker pool.
