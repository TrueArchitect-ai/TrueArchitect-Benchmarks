**Mechanism:** Server-Sent Events (SSE) over HTTP (`text/event-stream`), served at the `GET /api/v1/sse` endpoint with periodic heartbeat pings; the browser side would consume this via `EventSource`.

**Hub path:** `server/router/api/v1/sse_hub.go` (the `SSEHub` type, with `Subscribe`/`Unsubscribe`/`Broadcast`/`Close` methods and per-client visibility filtering in `canReceive`). The connection loop that reads from the hub and writes `data: ...` lines to the response is in `server/router/api/v1/sse_handler.go` (`handleSSE`, registered via `RegisterSSERoutes`).

**Handler names that broadcast through the hub** (all in `server/router/api/v1`, calling `s.SSEHub.Broadcast(...)`):
- `APIV1Service.CreateMemo` (`memo_service.go`) — emits `memo.created`
- `APIV1Service.DeleteMemo` (`memo_service.go`) — emits `memo.deleted`
- `APIV1Service.CreateMemoComment` (`memo_service_comments.go`) — emits `memo.comment.created`
- `APIV1Service.UpsertMemoReaction` (`reaction_service.go`) — emits `reaction.upserted`
- `APIV1Service.DeleteMemoReaction` (`reaction_service.go`) — emits `reaction.deleted`
- `APIV1Service.dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go`), a shared helper that emits `memo.updated` and is invoked by `UpdateMemo` (`memo_service.go`), `SetMemoAttachments` (`memo_attachment_service.go`), and `SetMemoRelations` (`memo_relation_service.go`)
