The server (`server/server.go`) starts exactly one background worker, driven by `startBackgroundRunners`:

- **S3 presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:161-171`), which calls `s3presignRunner.RunOnce(ctx)` once immediately and then launches `s3presignRunner.Run(s3Context)` in a goroutine. Its scheduling is a plain `time.NewTicker(runnerInterval)` with `runnerInterval = time.Hour * 12` (`server/runner/s3presign/runner.go:27-40`), i.e. it re-presigns S3 attachment URLs every 12 hours until its context is cancelled on shutdown.

That is the only actual background runner the server starts. Two pieces of related scheduling infrastructure exist in the codebase but are **not used** to drive any server-started worker:

- `server/runner/memopayload.Runner` (`server/runner/memopayload/runner.go`) defines a `NewRunner`/`RunOnce` batch job to rebuild all memo payloads, but `NewRunner` is never called anywhere in the repo and `Runner.RunOnce` is never invoked by the server. Only the unrelated helper function `memopayload.RebuildMemoPayload` is used, and it's called synchronously inline from the memo create/update HTTP handlers in `server/router/api/v1/memo_service.go:108` and `:447` — not as a scheduled/background job.
- `internal/scheduler` (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`) is a complete, GitHub-Actions-style cron scheduler (cron expression parsing, timezone support, middleware, graceful shutdown — see `internal/scheduler/README.md`) with its own test suite, but it is referenced only from its own `_test.go` files; `server/server.go` and `cmd/memos` never import or instantiate it, so no job in the running server is actually scheduled by it.
