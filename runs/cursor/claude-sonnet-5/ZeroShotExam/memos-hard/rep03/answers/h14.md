**Computation site**

The derived metadata lives in `MemoPayload.Property` (proto: `Property` message with a comment "The calculated properties from the memo content", `proto/store/memo.proto:14-22`, generated Go type `storepb.MemoPayload_Property` in `proto/gen/store/memo.pb.go:85-95`).

It is computed by the markdown service's single-pass extractor, `ExtractAll`, in `internal/markdown/markdown.go:356-422` (there's also a standalone `ExtractProperties` doing the same walk at `internal/markdown/markdown.go:193-241`, but `ExtractAll` is what's actually wired into the memo write path since it extracts tags, mentions, and properties together "in a single parse for efficiency").

That result is applied to a memo via `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`, which calls `markdownService.ExtractAll(memo.Content)` and overwrites `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers**

`RebuildMemoPayload` is invoked in exactly two places in the memo API service, `server/router/api/v1/memo_service.go`:
- `CreateMemo` — always run right after building the new memo, before persisting (`memo_service.go:108`).
- `UpdateMemo` — only when the update mask includes the `content` field, i.e. whenever a memo's content is edited (`memo_service.go:435-449`, the `RebuildMemoPayload` call is inside `if path == "content"`).

There's also a batch backfill path, `Runner.RunOnce` in `server/runner/memopayload/runner.go:26-72`, which pages through all memos and calls `RebuildMemoPayload` + `Store.UpdateMemo` for each — intended for bulk/maintenance rebuilds — though I did not find any current call site wiring this runner into server startup or a CLI command (only `RebuildMemoPayload` itself is referenced from `memo_service.go`), so I can't confirm it's actively triggered anywhere at present.

**Extracted properties**

Walking the goldmark AST of the memo's markdown content, the extractor derives:
- `has_link` — set when a `Link` node is encountered (`markdown.go:392-394`).
- `has_code` — set when a `CodeBlock`, `FencedCodeBlock`, or `CodeSpan` node is encountered (`markdown.go:396-397`).
- `has_task_list` / `has_incomplete_tasks` — set when a `TaskCheckBox` node is encountered; `has_incomplete_tasks` is additionally set if that checkbox is unchecked (`markdown.go:399-405`).
- `title` — extracted plain text of the first block-level child of the document if it's an H1 heading (`markdown.go:384-389`, using `extractHeadingText`).
- `tags` (stored alongside `Property` on `MemoPayload`, not inside `Property` itself) — collected from `#tag` AST nodes (`markdown.go:376-378`), deduplicated case-preservingly before being written to `data.Tags` (`markdown.go:418`).
