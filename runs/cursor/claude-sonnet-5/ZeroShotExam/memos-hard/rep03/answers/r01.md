**Premise correction:** There is no Redis in this codebase at all — a repo-wide search finds zero references to `redis` in any Go source file. The cache layer for user entries is a custom, thread-safe, in-process (in-memory) cache, not Redis.

**Actual mechanism:** The cache is implemented in `store/cache/cache.go` as a `sync.Map`-backed `Cache` type with TTL expiration and a background cleanup goroutine (`cleanupLoop`/`cleanup`). It's wired into the store layer, not a network service:

- The `Store` struct holds three such in-memory caches, including `userCache *cache.Cache`, constructed in `New()`:

```37:61:/bench/repo/store/store.go
func New(driver Driver, profile *profile.Profile) *Store {
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
		...
	}

	return store
}
```

- `Store.GetUser`/`CreateUser`/`UpdateUser`/`ListUsers` populate `userCache` via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. `store/user.go:122,132,143,167`), which calls the cache's `Set` method — not `SetWithTTL` — so it always uses the configured `DefaultTTL`.

- **TTL for user entries: 10 minutes** (`DefaultTTL: 10 * time.Minute` in `store/store.go:41`), with expired entries swept every 5 minutes by the cleanup goroutine, and a cap of 1000 items (`MaxItems: 1000`) after which the oldest ~20% are evicted (`store/cache/cache.go:56-64` `DefaultConfig()` shows the same defaults used elsewhere, e.g. by `cache.NewDefault()`).
