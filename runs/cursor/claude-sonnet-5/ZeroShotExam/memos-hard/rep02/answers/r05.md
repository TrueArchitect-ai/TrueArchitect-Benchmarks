**Premise correction:** There is no GraphQL schema in this repository — a repo-wide search finds zero `.graphql`/`.gql` files and no occurrence of the string "graphql" anywhere in the source. This project (structurally the `usememos/memos` codebase) does not use GraphQL for its public API at all.

**Actual API surface:** The public API is defined using Protocol Buffers (protobuf), not GraphQL:

- Service/message definitions live in `proto/api/v1/*.proto` — e.g. `proto/api/v1/memo_service.proto`, `proto/api/v1/user_service.proto`, `proto/api/v1/auth_service.proto`, `proto/api/v1/attachment_service.proto`, `proto/api/v1/instance_service.proto`, `proto/api/v1/idp_service.proto`, `proto/api/v1/shortcut_service.proto`, `proto/api/v1/ai_service.proto`, plus shared types in `proto/api/v1/common.proto`.
- These are compiled (via `buf`, configured in `proto/buf.yaml` / `proto/buf.gen.yaml`) into Go code under `proto/gen/api/v1/`.
- The services are exposed both as gRPC and, via grpc-gateway annotations, as a REST/JSON API; the resulting OpenAPI description is embedded through `proto/openapi_embed.go`.
- A separate internal proto set for storage models exists under `proto/store/` (generated into `proto/gen/store/`), which is unrelated to the public API.

So if you're looking for a "GraphQL schema," it doesn't exist here — the equivalent schema-defining artifacts are the `.proto` files in `proto/api/v1/`.
