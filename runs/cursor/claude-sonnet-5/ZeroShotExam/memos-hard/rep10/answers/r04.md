**Actual mechanism:** Webhook delivery is done with a bounded in-process Go channel, not a message broker. In `internal/webhook/webhook.go`, an unbuffered "queue" is really a buffered channel:

```39:55:internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
)

func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

- The "queue" is declared as a package-level Go channel `asyncPostQueue` (capacity 128) at `internal/webhook/webhook.go:39`.
- Four goroutine workers are spawned in `init()` (`internal/webhook/webhook.go:42-54`) that range over this channel and call `Post()` to actually deliver each webhook via `http.Client` (`internal/webhook/webhook.go:120-180`).
- Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send on the same channel and drops/logs a warning if the buffer is full.

So delivery is entirely in-memory/in-process — there's no external broker, no AMQP/NATS client, and no persistence or cross-process queueing involved.
