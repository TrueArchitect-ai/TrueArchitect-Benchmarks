**Computation site**: `RebuildMemoPayload()` in `server/runner/memopayload/runner.go` (lines 74‑88). It calls `markdownService.ExtractAll(content)` — implemented in `internal/markdown/markdown.go` (`ExtractAll`, lines 355‑422, which internally reuses the tag/property‑walking logic also exposed standalone as `ExtractTags`/`ExtractProperties`) — and stores the result into `memo.Payload.Tags` / `memo.Payload.Property` (a `storepb.MemoPayload` message, defined in `proto/store/memo.proto`).

**Triggers** (recomputation happens only when memo content changes, never set directly by the client):
- `CreateMemo` in `server/router/api/v1/memo_service.go` (line 108) calls `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` right after building the new memo from request content (this also covers memo comments, since `CreateMemoComment` creates memos via the same `CreateMemo` path).
- `UpdateMemo` in `server/router/api/v1/memo_service.go` (lines 436‑451): only when the update mask includes the `"content"` path does it set `memo.Content` and then call `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)` again — i.e. any content edit invalidates and recomputes the payload; updates to visibility/pinned/state/timestamps do not.
- Additionally, `Runner.RunOnce` in the same `runner.go` file (lines 27‑72) batch-rebuilds the payload for every memo in the store by calling the same `RebuildMemoPayload` — a maintenance/backfill routine over `ListMemos`, used to regenerate this derived data en masse (e.g. after logic changes), separate from the per-request triggers above.

**Extracted properties** (per `proto/store/memo.proto` `MemoPayload.Property` and `MemoPayload.tags`, all derived purely from parsing the markdown AST of `memo.Content`, never user-supplied):
- `tags` — all `#tag` occurrences (deduplicated, case preserved).
- `property.title` — text of the first H1 heading if the document's first block is one.
- `property.has_link` — whether any markdown link node exists.
- `property.has_code` — whether any code block/fenced code block/code span exists.
- `property.has_task_list` — whether any task checkbox exists.
- `property.has_incomplete_tasks` — whether any task checkbox is unchecked.

These derived fields (tags, title, has_link, has_code, has_task_list, has_incomplete_tasks) plus the separately-generated `snippet` (via `MarkdownService.GenerateSnippet`, called from `getMemoContentSnippet` in `server/router/api/v1/memo_service_webhooks.go`) are what the API surfaces for memo lists/previews (e.g. `v1pb.Memo.Snippet`, tag filters in `web/src/components/MemoFilters.tsx` / `web/src/hooks/useMemoFilters.ts`), while `Payload.Location` is user-set and not part of this derived computation.
