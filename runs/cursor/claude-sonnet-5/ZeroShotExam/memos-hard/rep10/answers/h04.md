**Answer: No — the MySQL *store driver* (`mysql.DB` / `mysql.NewDB`) is never constructed directly outside the factory.**

Evidence:
- The driver-selection factory is `NewDBDriver` in `store/db/db.go`, which calls `mysql.NewDB(profile)` for the `"mysql"` case (`db.go:14-32`).
- `mysql.NewDB` is defined in `store/db/mysql/mysql.go:20-41`, returning a `store.Driver` backed by `mysql.DB{...}`.
- A repo-wide search shows `store/db/mysql` (the package containing `NewDB`/`DB`) is imported by exactly one file: `store/db/db.go`. No other `.go` file imports this package or calls `mysql.NewDB`/constructs a `mysql.DB{}` literal directly.
- There is one other raw `sql.Open("mysql", dsn)` call outside the factory, in `store/test/containers.go:145`, but this is unrelated to constructing the `store.Driver` — it's test-harness plumbing (`GetMySQLDSN`) that opens a throwaway low-level `*sql.DB` connection just to run `CREATE DATABASE ...` for a fresh test database using the underlying `go-sql-driver/mysql` driver, not the `store/db/mysql.DB` store driver. The actual test store driver is still obtained via the same factory (`store/test/store.go:28,50` call `db.NewDBDriver(profile)`).
