**Actual mechanism:** The "cache layer" is a custom in-process, in-memory cache implemented in Go using `sync.Map`, not Redis or any external service.

- The cache implementation lives in `store/cache/cache.go`, which defines a thread-safe `Cache` struct backed by `sync.Map` with TTL-based expiration, a background cleanup goroutine, and an item-count eviction policy (`store/cache/cache.go:66-120`).
- It is instantiated and wired up in the `Store` constructor in `store/store.go`. Three separate cache instances are created there — `instanceSettingCache`, `userCache`, and `userSettingCache` — all using the same `cacheConfig`:

```37:61:/bench/repo/store/store.go
func New(driver Driver, profile *profile.Profile) *Store {
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
		...
	}

	return store
}
```

- **TTL for user entries**: The `userCache` uses this same `cacheConfig`, so entries have a **default TTL of 10 minutes** (`DefaultTTL: 10 * time.Minute`), with a cleanup sweep every 5 minutes (`CleanupInterval`) and a cap of 1000 items (`MaxItems`) before oldest-entry eviction kicks in.
- User records are read/written into this cache in `store/user.go` (e.g. `s.userCache.Set(ctx, userCacheKey(user.ID), user)` and `s.userCache.Get(ctx, userCacheKey(*find.ID))`), keyed by `userCacheKey(userID int32)`. Since `Set` (not `SetWithTTL`) is used, these entries inherit the store-wide default TTL of 10 minutes rather than any custom per-entry TTL.
