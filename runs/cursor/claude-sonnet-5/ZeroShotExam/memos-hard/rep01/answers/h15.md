Memo visibility ("who may view a memo") is checked independently in several separate server surfaces rather than through one shared gatekeeper. The distinct enforcement sites are:

1. gRPC/HTTP API v1 memo service (`checkMemoReadAccess`, used by `GetMemo` and memo-comment listing) — `server/router/api/v1/memo_service.go`

```39:68:server/router/api/v1/memo_service.go
func (s *APIV1Service) checkMemoReadAccess(ctx context.Context, memo *store.Memo) error {
	if memo == nil {
		return status.Errorf(codes.NotFound, "memo not found")
	}
	...
	if memo.Visibility != store.Public {
		user, err := s.fetchCurrentUser(ctx)
		...
		if memo.Visibility == store.Private && memo.CreatorID != user.ID {
			return status.Errorf(codes.PermissionDenied, "permission denied")
		}
	}
	return nil
}
```

(also called from `server/router/api/v1/memo_service_comments.go:148`, and `ListMemos` builds its own `VisibilityList`/filter restriction at `server/router/api/v1/memo_service.go:218-227`)

2. RSS feed endpoints (`/explore/rss.xml`, `/u/:username/rss.xml`) — `server/router/rss/rss.go`, which hard-restricts the memo query to `VisibilityList: []store.Visibility{store.Public}` (lines 88-93 and 138-144), independently of the API service's check.

3. Sitemap generator (`/sitemap.xml`) — `server/router/frontend/frontend.go`, which likewise restricts `Store.ListMemos` to `VisibilityList: []store.Visibility{store.Public}` (lines 149-151).

4. File server attachment download (`/file/attachments/:uid/:filename`) — `server/router/fileserver/fileserver.go`, function `checkAttachmentPermission` (lines 649-704), which loads the parent memo and independently re-implements the Public/Protected/Private visibility rule (including a share-token bypass) before streaming the file.

5. SSE real-time event delivery — `server/router/api/v1/sse_hub.go`, function `canReceive` (lines 134-144), which filters which connected clients receive a broadcasted memo event based on `event.Visibility` and `event.CreatorID`.

Additional duplicate re-implementations of the same check exist within the API v1 surface (not separate transport surfaces, but separate code paths that re-derive the rule instead of calling `checkMemoReadAccess`): `server/router/api/v1/reaction_service.go` (lines 29-41, 82-85), `server/router/api/v1/attachment_service.go` (`checkAttachmentAccess`, lines 422-455), and `server/router/api/v1/memo_attachment_service.go` (lines 213-225).
