Memo visibility is not centralized in one place — the `Visibility != Public` / `Visibility == Private` gate (checking the requester against `memo.CreatorID`, admin/super-user status, etc.) is independently re-implemented at each of the following server surfaces:

Core Memo API (GetMemo / ListMemos read-access) — `server/router/api/v1/memo_service.go` (`checkMemoReadAccess`, used by `GetMemo`; visibility filter inlined in `ListMemos`)
Memo comments API (CreateMemoComment / ListMemoComments) — `server/router/api/v1/memo_service_comments.go` (inline check at line 41; `ListMemoComments` reuses `checkMemoReadAccess`)
Memo reactions API (UpsertMemoReaction / ListMemoReactions) — `server/router/api/v1/reaction_service.go` (inline checks at lines 38 and 83)
Attachment gRPC service (GetAttachment) — `server/router/api/v1/attachment_service.go` (`checkAttachmentAccess`, lines 445/451)
Memo-scoped attachment listing (ListMemoAttachments) — `server/router/api/v1/memo_attachment_service.go` (inline check at line 222, duplicate of the above rather than a shared call)
Raw HTTP file/blob server (`/file/...` downloads) — `server/router/fileserver/fileserver.go` (`checkAttachmentPermission`, lines 677/699, plus share-token bypass)
Real-time SSE push hub — `server/router/api/v1/sse_hub.go` (`canReceive`, lines 134-144, filters which connected clients receive a memo event)
Mention notifications — `server/router/api/v1/memo_mention_helpers.go` (`canUserAccessMentionContext`, lines 56-72)
In-app/push notification payloads — `server/router/api/v1/user_service_notifications.go` (lines 309/312, decides whether notification reveals memo content)
Email notifications — `server/notification/email.go` (lines 313/316, same private/protected redaction decision for email bodies)
RSS/Atom feed generation — `server/router/rss/rss.go` (`GetExploreRSS`/`GetUserRSS` restrict `VisibilityList` to `store.Public` only, lines 90/141)
Sitemap generation — `server/router/frontend/frontend.go` (`getSitemapXML` restricts to `store.Public` only, line 150)

All of these ultimately branch on the same `store.Public` / `store.Protected` / `store.Private` values (defined in `store/memo.go`), but each surface re-implements the actual authorization decision independently rather than calling a single shared helper — e.g. `memo_attachment_service.go` and `attachment_service.go` duplicate the same "private → creator or super-user only" rule verbatim in two different files, and `memo_mention_helpers.go`'s version omits the super-user/admin bypass that the others have.
