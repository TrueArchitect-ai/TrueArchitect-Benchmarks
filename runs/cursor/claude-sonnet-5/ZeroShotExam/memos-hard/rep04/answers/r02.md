**Premise correction:** There is no per-user API rate-limiting middleware in this repository, so it isn't "registered" anywhere and has no request limits to report.

What I found instead:

- The global Echo middleware stack is set up in `server/server.go` (`middleware.Recover()` and a CORS middleware from `server/cors.go`) — no rate limiter.
- The frontend router (`server/router/frontend/frontend.go`) only adds static-file and SPA-fallback middleware.
- The API layer (`server/router/api/v1/v1.go`, lines ~130-137) registers a Connect RPC interceptor chain: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` (defined in `server/router/api/v1/connect_interceptors.go`), plus a gRPC-Gateway auth middleware. These handle header propagation, logging, panic recovery, and authentication/authorization — none implement request throttling or per-user quotas.
- The only occurrence of the phrase "rate limit" anywhere in the codebase is a single bullet point in a doc comment/README for the SMTP email package (`internal/email/doc.go`, line 86 and `internal/email/README.md`), which merely recommends as a best practice that callers "Rate limit email sending to prevent abuse" — it is not an implementation and is unrelated to the general API.

A repo-wide search for `ratelimit`, `rate limit`, `limiter`, `throttle`, and `429` across all directories (`internal/`, `server/`, `store/`, `web/`) turned up nothing else, so I'm confident this middleware does not exist in the codebase as of this commit.
