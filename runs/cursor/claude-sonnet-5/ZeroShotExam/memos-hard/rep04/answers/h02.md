Delivery function — `Post` in `/bench/repo/internal/webhook/webhook.go` (lines 119-180, actual send at line 152: `safeClient.Do(req)`). It's invoked synchronously or queued via `PostAsync` (lines 182-196), whose 4 worker goroutines started in `init()` (lines 42-55) pull off `asyncPostQueue` and call `Post`.

Protection mechanism — the `safeClient`'s custom `http.Transport.DialContext`, set to `safeDialContext` in `/bench/repo/internal/webhook/webhook.go` (lines 32-37, function defined at lines 57-77). Before dialing, it resolves the target host via `net.DefaultResolver.LookupHost` and rejects the connection if any resolved IP is reserved, per `isReservedIP` in `/bench/repo/internal/webhook/validate.go` (lines 44-54), which checks against the `reservedCIDRs`/`reservedNetworks` list (loopback, RFC-1918 private ranges, link-local/cloud IMDS `169.254.0.0/16`, and IPv6 equivalents, lines 14-36). This dial-time check (rather than a one-time check of the submitted URL) is what defeats DNS-rebinding attacks. A separate, earlier check — `ValidateURL` (lines 62-83, same file) — performs the same reserved-IP check at webhook-registration time via `net.LookupHost`, so invalid targets are rejected before being saved, but it's `safeDialContext` that actually guards every outbound delivery attempt at request time.

Note: this protection can be disabled by the `AllowPrivateIPs` package variable (`/bench/repo/internal/webhook/validate.go` line 41), intended for self-hosted deployments targeting local-network services.
