Yes — the MySQL driver is opened directly outside the `NewDBDriver` factory, in the test-container helper.

The factory lives in `store/db/db.go`, which dispatches to `mysql.NewDB(profile)` for the `"mysql"` case:

```18:24:/bench/repo/store/db/db.go

	case "sqlite":
		driver, err = sqlite.NewDB(profile)

		driver, err = mysql.NewDB(profile)

		driver, err = postgres.NewDB(profile)
```

That in turn calls `sql.Open("mysql", dsn)` inside `store/db/mysql/mysql.go`'s `NewDB` — the only production-path construction.

Both of these call `sql.Open("mysql", …)` directly using the imported `github.com/go-sql-driver/mysql` package (aliased `mysqldriver` in that file's imports), bypassing `store/db/db.go`'s `NewDBDriver` factory and `store/db/mysql.NewDB` entirely. A repo-wide search (`grep -rn "mysql.NewDB"` and `grep -rn "sql.Open(\"mysql\""`) confirms these are the only two direct-construction sites outside the factory, and both are test-only utility code, not production code paths.
