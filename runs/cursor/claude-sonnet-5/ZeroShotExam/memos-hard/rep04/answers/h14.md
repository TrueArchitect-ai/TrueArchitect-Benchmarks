**Computation site:** `internal/markdown/markdown.go`, in `(*service).ExtractAll` (`internal/markdown/markdown.go:356-420`), which is invoked through the shared helper `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`. `ExtractAll` parses the memo's Markdown content into a goldmark AST and walks it once to derive metadata; `RebuildMemoPayload` then writes the results into `memo.Payload.Tags` and `memo.Payload.Property` (`storepb.MemoPayload`, defined in `proto/store/memo.proto:7-22`). (A near-duplicate single-purpose helper, `ExtractProperties`, exists at `internal/markdown/markdown.go:193-241` for computing just the `Property` sub-message.)

**Triggers (recomputation points):**
- Creating a memo: `APIV1Service.CreateMemo` calls `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` before persisting (`server/router/api/v1/memo_service.go:108`).
- Updating a memo's content: `APIV1Service.UpdateMemo` calls the same `RebuildMemoPayload` only when the update mask includes the `"content"` path, i.e. whenever the memo body is edited (`server/router/api/v1/memo_service.go:436-451`). Other update paths (`visibility`, `pinned`, `state`, `location`, `attachments`, `relations`, timestamps) do not trigger recomputation, confirming these derived fields track content specifically, not user-settable fields.
- Bulk/batch recomputation: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27-72`) lists all memos in batches and calls `RebuildMemoPayload` + `Store.UpdateMemo` for each — intended for backfilling/rebuilding payloads en masse, though no current call site wires this runner into server startup or a CLI command in this codebase.

**Extracted properties** (single AST walk in `ExtractAll`, `internal/markdown/markdown.go:356-420`):
- `Tags` — `#tag` nodes found via `asMemoTagNode` (also independently available via `ExtractTags`, lines 143-170).
- `Property.Title` — text of the first H1 heading if it's the document's first block-level child.
- `Property.HasLink` — set when a `gast.KindLink` node is encountered.
- `Property.HasCode` — set for code blocks, fenced code blocks, or code spans.
- `Property.HasTaskList` — set when a task checkbox node (`east.KindTaskCheckBox`) exists.
- `Property.HasIncompleteTasks` — set when an unchecked task checkbox is found.
- (`Mentions` is also collected in the same pass for `@username` mentions, used for notifications rather than list/preview display.)

These `Tags`/`Property` fields (plus the separately generated `GenerateSnippet`, `internal/markdown/markdown.go:264-346`, used for preview text) are what the frontend/API rely on to render memo list icons (link/code/task indicators), titles, and tag filters without the user manually specifying them.
