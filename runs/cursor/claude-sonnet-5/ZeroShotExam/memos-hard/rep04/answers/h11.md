The persistent entity types live in the `store` package (Go "data layer" for this repo, Memos), e.g. `store.go`, `user.go`, `memo.go`, `attachment.go`, `reaction.go`, `inbox.go`, `idp.go`, `user_identity.go`, `user_setting.go`, `memo_relation.go`, `memo_share.go`, `instance_setting.go`.

Counting distinct Go packages outside `store/` that reference each core entity type (`store.<Type>`) via `grep -rl` across the repo:

- `store.User`: 7 packages — `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`
- `store.Memo`: 6 packages — `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`
- `store.Attachment`: 4 packages
- `store.Inbox` / `store.MemoRelation` / `store.MemoShare`: 3 packages each
- `store.Reaction` / `store.UserIdentity`: 2 packages each
- `store.IdentityProvider` / `store.InstanceSetting` / `store.UserSetting`: 1 package each

**Answer: 1st: `User` (~7 packages); 2nd: `Memo` (~6 packages)**

Both are defined in the `store` package (`store/user.go`, `store/memo.go`) and are consumed across most of the `server/router/...` sub-packages plus `server/auth`/`server/notification` (for `User`) and `server/runner/memopayload` (for `Memo`), reflecting their central role as the app's core identity and content entities.
