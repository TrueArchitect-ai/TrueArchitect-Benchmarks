**Mechanism: Explicit Go code (application-level), not a database-level rule.**

When a user is deleted, `store.Store.DeleteUser` delegates to the driver-specific `DeleteUser` implementation, which runs a single transaction that explicitly issues `DELETE FROM reaction ...` statements before deleting the `user` row itself. There is no `ON DELETE CASCADE` (or any `FOREIGN KEY` at all) on the `reaction` table, so nothing at the database level would remove reactions automatically.
