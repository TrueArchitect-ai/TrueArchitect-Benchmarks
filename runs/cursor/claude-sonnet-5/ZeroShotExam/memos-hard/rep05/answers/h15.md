Memo visibility (`PUBLIC`/`PROTECTED`/`PRIVATE`) is checked independently in many places rather than through one shared gate. The pattern is almost always the same inline logic — "if `Private` and viewer isn't the creator/admin, deny" — but it is duplicated across the codebase instead of being centralized, so each of the following is a genuinely separate enforcement site:

**Core memo access (gRPC API v1)**
- Single-memo read gate `checkMemoReadAccess` (used by `GetMemo`, and reused by `ListMemoComments`) — `server/router/api/v1/memo_service.go` (lines 39-68)
- List-query visibility filtering for `ListMemos` (`VisibilityList`/creator filter build-up) — `server/router/api/v1/memo_service.go` (lines 218-227)
- Inline check before allowing a comment on a memo, `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go` (lines 33-43)

**Related-resource access (each re-implements the same check instead of calling `checkMemoReadAccess`)**
- `ListMemoAttachments` visibility check — `server/router/api/v1/memo_attachment_service.go` (lines 213-225)
- `checkAttachmentAccess` (used by `GetAttachment`) — `server/router/api/v1/attachment_service.go` (lines 419-455)
- `ListMemoReactions` / `UpsertMemoReaction` visibility checks — `server/router/api/v1/reaction_service.go` (lines 29-41, 82-85)

**Notification content gating (a `canViewerAccessMemo` helper, duplicated in two subsystems)**
- In-app notification rendering — `server/router/api/v1/user_service_notifications.go` (lines 302-316, called at 337/342/370/385)
- Outbound email dispatch — `server/notification/email.go` (lines 306-320, called at 155/187)

**Raw file / attachment serving (HTTP, not gRPC)**
- `checkAttachmentPermission` gating blob downloads by the linked memo's visibility — `server/router/fileserver/fileserver.go` (lines 649-704)

**Real-time delivery**
- `SSEClient.canReceive` filtering which connected clients receive a broadcast memo event based on its visibility — `server/router/api/v1/sse_hub.go` (lines 134-144)

**Public-only surfaces (enforce visibility by construction, restricting the query itself to `Public`)**
- RSS feed generation — `server/router/rss/rss.go` (lines 88-90, 141)
- `sitemap.xml` generation — `server/router/frontend/frontend.go` (lines 149-151)

So there are well over three distinct enforcement sites (11 by my count), spanning the gRPC API service layer, the notification/email subsystem, the raw file server, the SSE hub, and the public RSS/sitemap generators — each with its own copy of the visibility logic rather than one shared implementation.
