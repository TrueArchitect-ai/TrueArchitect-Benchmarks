**Premise correction:** There is no GraphQL schema in this repository — a repo-wide search for "graphql" returns zero matches anywhere (source, docs, or generated code). The premise of the question is incorrect.

**Actual API surface:** The public API is defined using Protocol Buffers (protobuf) service definitions, not GraphQL. The schema files live in:

- `proto/api/v1/*.proto` — the service definitions, e.g. `proto/api/v1/memo_service.proto`, `auth_service.proto`, `user_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus shared types in `proto/api/v1/common.proto`
- `proto/store/*.proto` — internal storage-layer protobuf messages (e.g. `memo.proto`, `user_setting.proto`, `idp.proto`)

Code generation is driven by `proto/buf.gen.yaml` (using `buf`), which fans the `.proto` definitions out into:
- Go gRPC/protobuf code and a gRPC-gateway (REST) layer under `proto/gen/`
- An OpenAPI/Swagger spec (via the `google-gnostic-openapi` plugin), embedded through `proto/openapi_embed.go`
- TypeScript client types for the web frontend under `web/src/types/proto`

So the externally-facing API is gRPC + gRPC-Gateway/REST (documented via generated OpenAPI), with its schema of truth in the `.proto` files under `proto/api/v1/`.
