**Premise correction:** There is no Redis connection in this repository. I searched the entire codebase (all file types) case-insensitively for `redis` and checked `go.mod`/`go.sum` for any Redis client dependency — there are zero matches anywhere. The cache layer is not backed by Redis at all.

**Actual mechanism:** The cache is a custom in-process, in-memory cache implemented with Go's `sync.Map` (no external service/network connection involved).

- Implementation: `Cache` struct in `store/cache/cache.go` (a thread-safe map with TTL expiration, periodic cleanup goroutine, and max-item eviction).
- Configuration/wiring for user entries: in `store/store.go`, the `Store.New()` constructor builds a shared `cache.Config` and instantiates a dedicated `userCache` (along with `instanceSettingCache` and `userSettingCache`), each via `cache.New(cacheConfig)`:
