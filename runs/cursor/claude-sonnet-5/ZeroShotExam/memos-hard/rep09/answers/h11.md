The data layer is the `store` package (`store/*.go`), which defines the persistent entity structs: `User`, `Memo`, `Attachment`, `MemoShare`, `MemoRelation`, `Inbox`, `Reaction`, `UserIdentity`, `UserSetting`, `IdentityProvider`, `InstanceSetting`. Searching all Go code outside `store/` for references to `store.<Type>` and counting the distinct packages (by Go `package` declaration) each type appears in:

| Type | # distinct outside packages |
|---|---|
| `User` | 7 |
| `Memo` | 6 |
| `Attachment` | 4 |
| `MemoShare` / `MemoRelation` / `Inbox` | 3 each |
| `UserIdentity` / `Reaction` | 2 each |
| others | 1 (or only false-positive hits inside generated protobuf string literals under `proto/gen/store/`) |

**1st: `User`; 2nd: `Memo`** (rough package counts: `User` ~7 packages, `Memo` ~6 packages)

- `User` (`store/user.go`) is referenced from: `server/auth`, `server/notification`, `server/router/frontend`, `server/router/rss`, `server/router/fileserver`, `server/router/api/v1`, and `server/router/api/v1/test` — 7 distinct packages.
- `Memo` (`store/memo.go`) is referenced from: `server/notification`, `server/runner/memopayload`, `server/router/frontend`, `server/router/rss`, `server/router/api/v1`, and `server/router/api/v1/test` — 6 distinct packages.

Both are closely followed by `Attachment` (`store/attachment.go`, ~4 packages: `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/rss`), but `User` and `Memo` are clearly the two most widely referenced entity types outside the `store` layer, which makes sense since nearly every API/router package (`server/router/api/v1`, `server/router/rss`, `server/router/frontend`, `server/notification`, `server/auth`) needs to work with users and their memos.
