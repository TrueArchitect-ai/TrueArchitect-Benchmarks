h14.

**Computation site:** The derived metadata lives in `storepb.MemoPayload.Property` (defined in `proto/store/memo.proto:7-22`, generated into `proto/gen/store/memo.pb.go`), and it is actually computed by parsing the memo's markdown content with goldmark in `internal/markdown/markdown.go`. Specifically, `Service.ExtractAll` (`internal/markdown/markdown.go:355-422`) walks the parsed AST once and fills a `*storepb.MemoPayload_Property`; there is also a standalone `ExtractProperties` (`internal/markdown/markdown.go:192-241`) that does the same walk but is currently exercised only by tests/benchmarks. Production code calls `ExtractAll` through the helper `memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`), which assigns the result to `memo.Payload.Property` (and `Payload.Tags`).

**Triggers (recomputation):** `RebuildMemoPayload` is invoked in `server/router/api/v1/memo_service.go`:
- On `CreateMemo`, right after content-length validation and before the memo is persisted (`server/router/api/v1/memo_service.go:108`).
- On `UpdateMemo`, but only when the update mask includes the `content` field, i.e. whenever the memo's content is edited (`server/router/api/v1/memo_service.go:436-449`).

There is also a batch/backfill path, `Runner.RunOnce` in `server/runner/memopayload/runner.go:27-72`, which pages through all memos and calls `RebuildMemoPayload` for each (used for bulk re-derivation, e.g. after a markdown-parsing change), though it isn't currently wired into server startup in this codebase (no callers found outside its own package).

**Extracted properties:** Per the `Property` message (`proto/store/memo.proto:15-22`) and the AST walk in `ExtractAll`/`ExtractProperties`:
- `has_link` — set when a Markdown link node (`gast.KindLink`) is encountered.
- `has_code` — set when a code block, fenced code block, or code span node is encountered.
- `has_task_list` — set when a task checkbox node (`east.KindTaskCheckBox`) is encountered.
- `has_incomplete_tasks` — set when a task checkbox is unchecked.
- `title` — the text of the first H1 heading, only if it's the very first block-level child of the document.

This computed `Property` (plus extracted `tags`) is exposed to the API/frontend via `convertMemoPropertyFromStore` (`server/router/api/v1/memo_service_converter.go:315-326`) as `v1pb.Memo_Property`, and is what the web UI's memo list/filter components (`web/src/components/MemoFilters.tsx`, `web/src/hooks/useMemoFilters.ts`, `web/src/contexts/MemoFilterContext.tsx`) read to render preview badges/filters (has link, has code, task list, incomplete tasks, title) without the user setting these fields directly.
