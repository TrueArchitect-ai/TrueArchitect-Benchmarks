h02.

- **Delivery function** — `Post` in `internal/webhook/webhook.go` (invoked synchronously, and also asynchronously via `PostAsync`/`asyncPostQueue` in the same file) is where the outbound HTTP request is actually built and sent — it marshals the payload, constructs the `POST` request, optionally signs it, and calls `safeClient.Do(req)` (see lines 120–180, `repo/internal/webhook/webhook.go`).

- **Protection mechanism** — SSRF/private-network protection is enforced at the network-dial layer, not just at input validation:
  - The shared `safeClient`'s `http.Transport.DialContext` is set to `safeDialContext` (`repo/internal/webhook/webhook.go:32-37`), which resolves the target host and rejects any resolved IP inside a reserved/private range before dialing (`repo/internal/webhook/webhook.go:59-77`). Doing this at dial time (after DNS resolution, right before connecting) is what defeats DNS-rebinding attacks that could otherwise bypass a URL-only check.
  - The reserved-range logic itself (`isReservedIP`, `reservedCIDRs`/`reservedNetworks` covering loopback, RFC-1918 private ranges, link-local/cloud metadata `169.254.0.0/16`, and IPv6 equivalents) lives in `repo/internal/webhook/validate.go:11-54`, and is shared with the separate pre-flight check `ValidateURL` (same file, lines 62-83) that's used when a webhook is created/updated in `server/router/api/v1/user_service_webhooks.go` and `server/router/api/v1/memo_service_webhooks.go`.

So: delivery — `Post` (`repo/internal/webhook/webhook.go`); protection — `safeDialContext`/`isReservedIP` (`repo/internal/webhook/webhook.go` and `repo/internal/webhook/validate.go`).
