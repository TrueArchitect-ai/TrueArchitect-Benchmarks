**Premise correction:** There is no Redis connection anywhere in this repository — it doesn't appear in `go.mod`/`go.sum` as a dependency, and no file in the codebase references Redis in any form. The cache layer is not backed by an external cache server at all.

**Actual mechanism:** The cache is a pure in-process, in-memory cache implemented from scratch at `store/cache/cache.go`, built on `sync.Map` with a background goroutine (`cleanupLoop`) that periodically evicts expired entries.

It's wired up in the `Store` constructor:

```37:61:store/store.go
func New(driver Driver, profile *profile.Profile) *Store {
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
		...
```

`userCache` is a separate `*cache.Cache` instance built with this same `cacheConfig`. In `store/user.go`, all writes to the user cache use the plain `Set` method (e.g. `s.userCache.Set(ctx, userCacheKey(user.ID), user)`), never `SetWithTTL`, so entries fall back to `DefaultTTL`.

**TTL for user entries: 10 minutes** (`DefaultTTL: 10 * time.Minute` in `store/store.go`, applied via the cache's `Set` method as seen in `store/cache/cache.go`'s `Set` → `SetWithTTL(ctx, key, value, c.config.DefaultTTL)`). Expired entries are additionally swept out every 5 minutes by the `CleanupInterval` background loop.
