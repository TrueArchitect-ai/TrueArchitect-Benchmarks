**Premise correction:** Neither. This codebase (usememos/memos) does not use NATS or RabbitMQ anywhere — a repo-wide search for `nats`, `amqp`, and `rabbitmq` turns up no broker client code at all (the only string hits are unrelated Catalan locale words in `web/src/locales/ca.json`, e.g. "e**limina**" / "recursos elimin**ats**"). There is no external message broker in this project.

**Actual mechanism:** Webhook delivery is handled entirely in-process with a buffered Go channel acting as the "queue," not any pub/sub broker.

- The queue is declared right in the webhook package itself:

```39:54:/bench/repo/internal/webhook/webhook.go
	asyncPostQueue = make(chan *WebhookRequestPayload, 128)
)

func init() {
	for range 4 {
		go func() {
			for payload := range asyncPostQueue {
				if err := Post(payload); err != nil {
					slog.Warn("Failed to dispatch webhook asynchronously",
						slog.String("url", payload.URL),
						slog.String("activityType", payload.ActivityType),
						slog.Any("err", err))
				}
			}
		}()
	}
}
```

- `asyncPostQueue` is a channel with a capacity of 128 pending payloads (`internal/webhook/webhook.go:39`).
- On package `init()`, 4 goroutines are spawned as consumer "workers" that range over this channel and call `Post()` to actually deliver the HTTP webhook (`internal/webhook/webhook.go:42-55`, `120-180`).
- Producers enqueue via `PostAsync()`, which does a non-blocking channel send and drops (with a warning log) if the channel is full (`internal/webhook/webhook.go:184-196`).

So the "broker" is really an in-memory Go channel with a fixed-size buffer and a small fixed pool of goroutine workers — there's no NATS subject or RabbitMQ queue/exchange declaration anywhere in the repo.
