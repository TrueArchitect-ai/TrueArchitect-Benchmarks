**Premise correction:** No per-user API rate-limiting middleware exists in this repository. The claim that such middleware is registered somewhere is incorrect.

What actually exists:

- The full request-handling middleware/interceptor chain for the API is registered in `server/router/api/v1/v1.go` (lines 133–137), via `connect.WithInterceptors(...)`, consisting of exactly four interceptors: `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, and `NewAuthInterceptor()` — defined in `server/router/api/v1/connect_interceptors.go`. None of these implement request throttling/rate-limiting; they handle header-to-metadata conversion, logging, panic recovery, and authentication/authorization respectively.
- The only rate-limiting-adjacent artifact in the codebase is a documentation comment in `internal/email/doc.go` (line 86: "Rate limit email sending to prevent abuse") — this is just a suggestion in doc comments, not implemented code.
- `golang.org/x/time` (which provides Go's standard `rate.Limiter`) appears in `go.mod` only as an `// indirect` dependency (line 151), meaning it's pulled in transitively by some other library, not used directly by this project's code.
- A search across the entire codebase for `limiter`, `Limiter`, `throttle`, `ratelimit`, `429`, and `TooManyRequests` in `.go` files returned no results.

So there is no per-user (or any other kind of) API rate-limiting middleware currently registered, and consequently no request limits to report.
