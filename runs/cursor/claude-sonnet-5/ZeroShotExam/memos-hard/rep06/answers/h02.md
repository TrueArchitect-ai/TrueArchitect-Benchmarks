h02.

The actual outbound HTTP delivery happens in the `Post` function (and its async wrapper `PostAsync`, which enqueues onto `asyncPostQueue` and calls `Post` from worker goroutines started in `init()`):

- delivery function — `Post` (and `PostAsync`) in `internal/webhook/webhook.go` (lines 42-55, 120-196), which builds the request and sends it via the package-level `safeClient` (`internal/webhook/webhook.go:32-37`).

Protection against SSRF/internal-address targeting is enforced at the transport layer, not just at input validation:

- protection mechanism — `safeDialContext` (used as the custom `DialContext` on `safeClient`'s `http.Transport`) in `internal/webhook/webhook.go:59-77`, which resolves the target host and rejects any dial whose resolved IP falls in a reserved/private range via `isReservedIP` in `internal/webhook/validate.go:44-54` (checked against `reservedNetworks`/`reservedCIDRs` defined at `internal/webhook/validate.go:14-36`). Because this check runs at dial time on the actual connection IP (rather than only at URL-save time), it also defeats DNS-rebinding attacks. There's also a separate pre-save check, `ValidateURL` in `internal/webhook/validate.go:62-83`, used when webhooks are created/updated, but the dial-time guard in `safeDialContext` is what actually protects each delivery.
