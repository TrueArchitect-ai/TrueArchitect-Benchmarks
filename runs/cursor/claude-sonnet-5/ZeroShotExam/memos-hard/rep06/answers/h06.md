**Handlers (gRPC `APIV1Service` methods in `server/router/api/v1/`) that transitively trigger an outbound request to a user-configured URL (a webhook URL stored per-user):**

1. `CreateMemo` — calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)` (`server/router/api/v1/memo_service.go:157`), which calls `dispatchMemoRelatedWebhook` → `webhook.PostAsync(payload)` (`server/router/api/v1/memo_service_webhooks.go:15-17,48-74`), using `payload.URL = hook.Url` from the user's stored webhooks (`s.Store.GetUserWebhooks`).

2. `UpdateMemo` — calls `s.dispatchMemoUpdatedSideEffects(...)` (`server/router/api/v1/memo_service.go:513`), which calls `s.DispatchMemoUpdatedWebhook` → `webhook.PostAsync(payload)` (`server/router/api/v1/memo_update_helpers.go:66-69`, `memo_service_webhooks.go:19-22`).

3. `DeleteMemo` — calls `s.DispatchMemoDeletedWebhook(ctx, memoMessage)` (`server/router/api/v1/memo_service.go:562`) → `webhook.PostAsync(payload)` (`memo_service_webhooks.go:24-27`).

4. `CreateMemoComment` — calls `s.DispatchMemoCommentCreatedWebhook(ctx, memoComment, relatedMemo.CreatorID)` (`server/router/api/v1/memo_service_comments.go:119`) → `webhook.PostAsync(payload)` with `payload.URL = hook.Url` (`memo_service_webhooks.go:29-46`).

(Also `SetMemoAttachments`/`SetMemoRelations`-type handlers reach the same sink via `dispatchMemoUpdatedSideEffects` in `memo_attachment_service.go:48` and `memo_relation_service.go:48`.)

**Convergence function — path:**

`Post(requestPayload *WebhookRequestPayload) error` — `internal/webhook/webhook.go:120`

All four handlers' payloads are enqueued via `webhook.PostAsync` (`internal/webhook/webhook.go:184-196`) into `asyncPostQueue`, which is drained by the fixed worker pool started in `init()` (`internal/webhook/webhook.go:42-55`); each worker calls `Post(payload)`, and `Post` is the single place that builds the `http.NewRequest` and executes `safeClient.Do(req)` (`internal/webhook/webhook.go:126-156`), i.e. the actual outbound HTTP delivery to the user-configured webhook URL.
