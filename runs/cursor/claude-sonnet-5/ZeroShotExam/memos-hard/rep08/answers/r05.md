**Premise correction:** This repository has no GraphQL schema — there is no `.graphql`/`.gql` file, no `graphql` string, and no GraphQL server library anywhere in the codebase (confirmed via a repo-wide search). The premise that the public API is GraphQL is incorrect.

**Actual API surface:** This is the [usememos/memos](https://github.com/usememos/memos) server, and its public API is defined via **Protocol Buffers**, generating both **gRPC** and **REST/OpenAPI** interfaces (as stated in the README: "full REST and gRPC APIs for integration", `README.md:22`):

- Proto service/message definitions live under `proto/api/v1/` (the public API surface) and `proto/store/` (internal store-layer protos, e.g. `proto/store/memo.proto`, `proto/store/inbox.proto`, etc.).
- Codegen config is in `proto/buf.yaml`, `proto/buf.gen.yaml`, and `proto/buf.lock` (using [buf](https://docs.buf.build/)), per `proto/README.md`.
- Generated Go code and the derived OpenAPI/REST description live in `proto/gen/api` and `proto/gen/openapi.yaml`, with `proto/openapi_embed.go` embedding the OpenAPI spec into the binary.
- The gRPC/REST service implementations that expose this API are wired up under `server/` (e.g. an API v1 router/gateway) using the generated code from `proto/gen`.

So if you're looking for "the schema of the public API," the equivalent artifact in this codebase is the `.proto` files in `proto/api/v1/` (source of truth) plus the generated `proto/gen/openapi.yaml` (REST/OpenAPI view), not a GraphQL schema.
