h02.

- **Delivery function** — `Post` in `internal/webhook/webhook.go` (lines 120–180) performs the actual outbound HTTP POST to the webhook's target URL (invoked either synchronously or via `PostAsync`, which enqueues onto `asyncPostQueue` and is drained by worker goroutines that call `Post`, `internal/webhook/webhook.go:39-54,184-196`).
- **Protection mechanism** — the shared `safeClient`'s custom `Transport.DialContext` (`safeDialContext` in `internal/webhook/webhook.go:32-77`) resolves the target host at dial time and rejects any resolved IP that is reserved/private via `isReservedIP` (`internal/webhook/validate.go:44-54`, checked against `reservedCIDRs`/`reservedNetworks` covering loopback, RFC-1918 private ranges, link-local/cloud IMDS `169.254.169.254`, and their IPv6 equivalents, defined in `internal/webhook/validate.go:14-36`). Because the check happens at dial time on the resolved IP (not just the hostname), it also defeats DNS-rebinding attacks. A companion `ValidateURL` (`internal/webhook/validate.go:62-83`) performs the same reserved-IP check up front when a webhook URL is registered/saved, but the actual runtime guard for every request lives in `safeDialContext`. (Both checks can be disabled via the `AllowPrivateIPs` flag in `internal/webhook/validate.go:41`.)
