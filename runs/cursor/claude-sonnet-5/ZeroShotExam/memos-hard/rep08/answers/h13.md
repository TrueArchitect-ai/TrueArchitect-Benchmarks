**impl — construction — holders**

- **impl**: The only production implementation is the unexported `*service` struct in `internal/markdown/markdown.go` (`type service struct{ md goldmark.Markdown }`, lines 31/58), which wraps `goldmark.Markdown` plus the custom `extensions.TagExtension`/`extensions.MentionExtension` (`internal/markdown/extensions/`) and a hand-rolled `renderer.MarkdownRenderer` (`internal/markdown/renderer/markdown_renderer.go`) for `RenderMarkdown`/`RenameTag`. No other type satisfies `markdown.Service` anywhere in the repo.

- **construction**: A single instance is built once at server start via `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())` inside `NewAPIV1Service` (`server/router/api/v1/v1.go:47-51`) and stored on `APIV1Service.MarkdownService`. That same instance is then reused (not reconstructed) when `server.go` wires up the RSS feature: `rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)` (`server/server.go:85`). Separate ad-hoc instances are also constructed the same way in test setup only (`server/router/api/v1/test/test_helper.go:44-47`, `server/router/rss/rss_test.go:54`, `server/router/fileserver/fileserver_test.go:427`).

- **holders**: The interface type `markdown.Service` (defined `internal/markdown/markdown.go:31-55`) is held by:

  - `RSSService.MarkdownService` (`server/router/rss/rss.go:45`).
