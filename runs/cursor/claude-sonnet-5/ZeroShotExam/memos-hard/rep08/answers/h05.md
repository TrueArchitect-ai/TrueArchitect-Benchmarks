**Mechanism:** Explicit Go code (application-level transaction logic), not a database-level cascade/trigger. There is no `FOREIGN KEY`/`ON DELETE CASCADE` on the `reaction` table in any supported database, so removal only happens because the Go `DeleteUser` implementation explicitly issues `DELETE FROM reaction` statements as part of the same transaction that deletes the user.

**Evidence locations:**

1. **Explicit deletion code** — each database driver's `DeleteUser` transaction calls two dedicated helpers that delete reactions before deleting the user row:
   - `deleteReactionsByContentIDsTx` deletes reactions on memos owned by the user (matched by `content_id`), and `deleteReactionsByCreatorTx` deletes reactions the user made on others' content (`creator_id = ?`). Both are invoked from `deleteUserTargetsTx` prior to `deleteUserRowTx`.
   - Identical logic (driver-specific SQL placeholders only) exists in:
     - `deleteUserTargetsTx`/`deleteReactionsByContentIDsTx`/`deleteReactionsByCreatorTx` (`96:104`, `380:403`) in `store/db/postgres/user_delete.go`
     - Same functions (`96:104`, `417:440`) in `store/db/mysql/user_delete.go`
     - Same functions (`96:104`, `380:403`) in `store/db/sqlite/user_delete.go`

2. **No DB-level cascade exists** — the `reaction` table schema in every dialect's current migration (`store/migration/{postgres,mysql,sqlite}/LATEST.sql`, originally created in `store/migration/{postgres,mysql,sqlite}/0.20/00__reaction.sql`) defines `creator_id INTEGER/INT NOT NULL` with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint — no `REFERENCES user(id)` / `FOREIGN KEY` / `ON DELETE CASCADE` clause anywhere. So the database itself would not remove reaction rows on user deletion; it must be done in application code.

3. **Test coverage confirms behavior** — `store/test/user_delete_test.go` creates reactions from both the deleted user and a "peer" user on each other's memos (lines 97-114), then after calling `DeleteUser` asserts (lines 217-220) that only the peer's own reaction on their own memo survives (`ListReactions` returns exactly 1 row, matching `peerReactionToKeep.ID`), confirming the user's reactions and reactions on the user's deleted memos are gone.
