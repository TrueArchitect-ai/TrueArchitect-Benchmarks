**Computation site**: `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`. It parses `memo.Content` once via the markdown service's `ExtractAll` (`internal/markdown/markdown.go:356-422`, which walks the goldmark AST) and stores the results into `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers** (operations that cause recomputation):
- `CreateMemo` — always recomputes for the new memo's content, at `server/router/api/v1/memo_service.go:108`.
- `UpdateMemo` — recomputes only when the update mask includes the `content` field (i.e., the memo's text is actually being changed), at `server/router/api/v1/memo_service.go:446-449`.
- (There's also a `Runner.RunOnce` batch job in `server/runner/memopayload/runner.go:27-72` that calls the same `RebuildMemoPayload` for every memo, intended as a bulk backfill/repair tool — but per my earlier finding in this session, this `Runner` type is never constructed or wired into server startup anywhere in the codebase, so in practice it is dead code and not an active trigger.)

**Extracted properties** (via `markdown.Service.ExtractAll`, `internal/markdown/markdown.go:356-422`):
- `Tags` — all `#tag` occurrences found in the content (deduplicated, case preserved), stored as `memo.Payload.Tags`.
- `Property.Title` — text of a leading H1 heading, if the first block in the document is one.
- `Property.HasLink` — whether the content contains any link.
- `Property.HasCode` — whether the content contains a code block/span (fenced, indented, or inline).
- `Property.HasTaskList` — whether the content contains a task-list checkbox.
- `Property.HasIncompleteTasks` — whether any task-list checkbox is unchecked.
- (Mentions are also extracted in the same AST pass into `ExtractedData.Mentions`, but `RebuildMemoPayload` discards that field — only `Tags` and `Property` are persisted into `memo.Payload`.)
