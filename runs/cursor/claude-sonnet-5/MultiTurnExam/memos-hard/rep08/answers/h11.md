The persistent entity types are defined in the `store` package (the data layer), e.g. `store/user.go`, `store/memo.go`, `store/attachment.go`, `store/reaction.go`, `store/inbox.go`, `store/memo_share.go`, `store/memo_relation.go`, `store/user_setting.go`, `store/user_identity.go`, `store/idp.go`, `store/instance_setting.go`.

I counted, for each entity type, the number of distinct non-`store` packages that reference it (via `store.<Type>`) across `server/`, `cmd/`, and `internal/`.

**1st: `store.User`** — referenced from ~6 packages outside the data layer: `server/auth` (`server/auth/authenticator.go`, `server/auth/context.go`), `server/notification` (`server/notification/email.go`), `server/router/api/v1` (over a dozen files, e.g. `auth_service.go`, `user_service.go`, `memo_service_converter.go`, `instance_service.go`, etc.), `server/router/fileserver` (`server/router/fileserver/fileserver.go`), `server/router/rss` (`server/router/rss/rss.go`), plus its own test package `server/router/api/v1/test`.

**2nd: `store.Memo`** — referenced from ~4 packages outside the data layer: `server/router/api/v1`, `server/router/rss` (`server/router/rss/rss.go`), `server/notification` (`server/notification/email.go`), and `server/runner/memopayload` (`server/runner/memopayload/runner.go`).

The next closest was `store.Attachment` at ~3 packages (`server/router/api/v1`, `server/router/fileserver`, `store/test`), well behind `User` and `Memo`.
