**Premise correction**: There is no Redis-backed cache anywhere in this repository — no Redis client dependency exists at all (`go.mod`/`go.sum` contain no Redis package), and there is no Redis connection configuration to find.

**Actual mechanism**: The cache layer is a self-contained, in-process, in-memory cache implemented in `store/cache/cache.go`. It's a thread-safe `sync.Map`-backed store (type `Cache`, `store/cache/cache.go:66-73`) with TTL expiration and a background cleanup goroutine — no external service or network connection involved.

For user entries specifically: `store.Store` constructs a dedicated `userCache` (along with `instanceSettingCache` and `userSettingCache`) using a shared default config in `store/store.go:37-58`:

```38:53:store/store.go
func New(driver Driver, profile *profile.Profile) *Store {
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

So user entries cached via `Store.userCache` (populated/read in `store/user.go`, e.g. `GetUser`/`ListUsers`/`UpdateUser`) get a **10-minute TTL** (`DefaultTTL: 10 * time.Minute`), with a background sweep every 5 minutes (`CleanupInterval`) evicting expired entries, and a 1000-item cap (`MaxItems`) enforced via `cleanupOldest` in `store/cache/cache.go:252-313`.
