**Premise correction:** There is no Redis anywhere in this codebase — I searched all `.go` files and `go.mod`/`go.sum` for any mention of `redis` and found zero hits. There's no Redis client, connection string, or config for it.

**Actual mechanism:** The "cache layer" is a purely in-process, in-memory cache implemented in `store/cache/cache.go` (an `Interface` backed by a map with TTL-based expiration and periodic cleanup, `store/cache/cache.go:10-60`). It's not a network service — nothing to "connect" to.

The `Store` type owns three of these in-memory caches (`instanceSettingCache`, `userCache`, `userSettingCache`), all constructed with the same default config in `store/store.go:38-61`:

```39:53:store/store.go
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

So user entries in `userCache` get the `DefaultTTL` of **10 minutes** (with a 5-minute cleanup sweep interval and a 1000-item cap), set via `Set` calls like the ones in `store/user.go` (e.g. `store/user.go:167` in `GetUser`) — there is no per-user or per-entry override of that TTL that I could find.
