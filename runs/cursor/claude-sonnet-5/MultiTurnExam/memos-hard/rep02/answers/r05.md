**Premise correction:** There is no GraphQL schema anywhere in this codebase. I searched all `.go` files, `go.mod`, and the filesystem for `graphql` and any `.graphql` schema files, and found zero matches — this project has no GraphQL dependency, resolver, or schema file at all.

**Actual API surface:** The public API is defined with Protocol Buffers and served over gRPC/Connect (plus a REST/JSON gateway), not GraphQL:

- The schema lives as `.proto` files in `proto/api/v1/` — e.g. `proto/api/v1/memo_service.proto`, `attachment_service.proto`, `auth_service.proto`, `user_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, and shared types in `proto/api/v1/common.proto` (plus persistence-layer messages in `proto/store/`).
- These are compiled into generated Go code under `proto/gen/api/v1/` (gRPC server/client stubs, Connect handlers in `proto/gen/api/v1/apiv1connect/`, and a REST gateway in the `*.pb.gw.go` files, e.g. `proto/gen/api/v1/memo_service.pb.gw.go`).
- The concrete RPC handlers implementing these services live in `server/router/api/v1/` (e.g. `memo_service.go`, `attachment_service.go`, `user_service.go`), registered via Connect in `server/router/api/v1/connect_services.go` / `connect_handler.go`.

So instead of a GraphQL schema, the "schema" for the public API is the set of `.proto` files under `proto/api/v1/`.
