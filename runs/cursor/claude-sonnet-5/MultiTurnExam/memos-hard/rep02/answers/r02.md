**Premise correction:** There is no per-user API rate-limiting middleware in this codebase. I searched the entire repo (case-insensitively) for `ratelimit`, `rate limit`, `rate_limit`, `throttle`, and `limiter`, and the only hit is a single line in a documentation comment — `internal/email/doc.go:86` — which just advises "Rate limit email sending to prevent abuse" as a best-practice recommendation for administrators; it is not code, and no such limiter is actually implemented.

I also checked the Connect RPC middleware stack directly. The only interceptors registered for the API are declared in `server/router/api/v1/connect_interceptors.go`:

- `MetadataInterceptor` (`server/router/api/v1/connect_interceptors.go:22-29`) — converts HTTP headers to gRPC metadata.
- `LoggingInterceptor` (`server/router/api/v1/connect_interceptors.go:98-107`) — logs requests.
- `RecoveryInterceptor` (`server/router/api/v1/connect_interceptors.go:165-174`) — recovers from panics.
- `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:208-217`) — enforces authentication/anonymous-access policy.

None of these implement request-count throttling or quotas. So there's no registration site to cite and no limits to report — this feature simply doesn't exist in the server today.
