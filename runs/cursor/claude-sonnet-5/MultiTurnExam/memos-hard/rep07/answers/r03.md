**Premise correction:** There is no nightly database-cleanup job in this repository, and no cron scheduler is actually wired up to run one. The codebase does contain a generic cron-style scheduler package, `internal/scheduler` (`internal/scheduler/scheduler.go`, `internal/scheduler/parser.go`, `internal/scheduler/job.go`), with `scheduler.New()` and cron-expression parsing support — but a repo-wide search shows `scheduler.New` is called only from that package's own test/example files (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`) and referenced in its documentation comment (`internal/scheduler/doc.go`). No production code anywhere in `server/`, `cmd/`, or `store/` imports or constructs an `internal/scheduler.Scheduler`, and no "cleanup" job is registered with it.

What does exist are unrelated, non-cron background mechanisms:
- The `store/cache` layer runs its own internal cleanup loop for expired cache entries every `CleanupInterval` (default 5 minutes) via `(*Cache).cleanupLoop` — `store/cache/cache.go:199-216` — but this only evicts stale in-memory cache items, not database rows, and isn't cron-scheduled or "nightly."
- The two actual periodic background runners wired into server startup (`server/server.go`) are the S3 presign refresher (`server/runner/s3presign`, every 12 hours) and the dormant/uncalled `memopayload` runner — neither is a database-cleanup job nor runs on a nightly cron schedule.

So there's no "nightly" time to report — the concept doesn't exist in this codebase.
