**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search for "redis" (case-insensitive) across all Go files returns zero hits, and there's no Redis client dependency in `go.mod`. The cache layer is not backed by an external service at all.

**Actual mechanism:** The cache is a purely in-process, in-memory cache implemented in `store/cache/cache.go` (an `Interface`/`Cache` type backed by a `sync.Map`-style store with periodic cleanup, `MaxItems` eviction, etc. — see `store/cache/cache.go:11-56`). It is constructed and wired up entirely within the `Store` type:

```37:58:store/store.go
func New(driver Driver, profile *profile.Profile) *Store {
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
		...
```

The `userCache` (`store/store.go:28`) uses this same `cacheConfig`, so **user entries get the default TTL of 10 minutes** (`DefaultTTL: 10 * time.Minute`, `store/store.go:41`), with a 5-minute background cleanup interval and a 1000-item cap. There's no separate Redis TTL configuration to point to — it's all local process memory, cleared on restart, set/read via `s.userCache.Set(...)`/`s.userCache.Get(...)` in `store/user.go`.
