h05.

**Mechanism: explicit Go code** (not a database-level cascade rule and not "not at all"). Reactions belonging to a deleted user are removed by explicit `DELETE FROM reaction ...` statements executed within the `DeleteUser` transaction, in each of the three database driver implementations (which are effectively identical logic, just per-dialect SQL).

Evidence locations:

- `store/db/postgres/user_delete.go` — `deleteUserTargetsTx` calls `deleteReactionsByContentIDsTx` (line 96) and `deleteReactionsByCreatorTx` (line 102); the latter executes `DELETE FROM reaction WHERE creator_id = $1` at `deleteReactionsByCreatorTx` (`store/db/postgres/user_delete.go:400-403`), and `deleteReactionsByContentIDsTx` executes `DELETE FROM reaction WHERE content_id IN (...)` (`store/db/postgres/user_delete.go:380-388`).
- `store/db/sqlite/user_delete.go` — identical structure: `deleteUserTargetsTx` (lines 96, 102) calls the same two helpers, `deleteReactionsByContentIDsTx` (`store/db/sqlite/user_delete.go:380-388`) and `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:400-403`), both issuing `DELETE FROM reaction ...`.
- `store/db/mysql/user_delete.go` — same pattern: `deleteUserTargetsTx` (lines 96, 102) calls `deleteReactionsByContentIDsTx` (`store/db/mysql/user_delete.go:417-425`) and `deleteReactionsByCreatorTx` (`store/db/mysql/user_delete.go:437-440`), both against the `reaction` table.

What this covers: reactions the deleted user created (`deleteReactionsByCreatorTx`, keyed on `creator_id`), and reactions on any memo/comment owned by that user (`deleteReactionsByContentIDsTx`, keyed on `content_id` derived from the user's memo tree collected in `collectDeleteUserTargets`/`listDeleteUserMemoTree`).

What I checked to rule out a DB-level rule: I inspected the higher-level `store/user_delete.go` (a thin failpoint/cache helper with no SQL) and the per-driver `user_delete.go` files, which contain the actual transactional `DELETE` statements built in Go and executed via `tx.ExecContext`. I did not find any `ON DELETE CASCADE` foreign-key clause governing `reaction.creator_id`/`content_id` in these files — the reaction rows are deleted purely because the Go code in `deleteUserTargetsTx` explicitly issues the deletes before removing the user row itself (`deleteUserRowTx`, called last in each file).
