**Premise correction:** The repository does not contain any per-user API rate-limiting middleware. I checked:

- All Go source for `ratelimit`/`rate limit`/`throttle` (case-insensitive) — the only hits are prose mentions in `internal/email/doc.go:86` and `internal/email/README.md`, which are documentation comments recommending that *operators* rate-limit outbound email sending; there is no corresponding implementation.
- The Echo middleware actually registered on the server: `middleware.CORSWithConfig` (`server/cors.go:14`), `middleware.Recover()` (`server/server.go:51`), and `middleware.StaticWithConfig` for the frontend static assets (`server/router/frontend/frontend.go:54`). None of these is a rate limiter, and Echo's own `middleware.RateLimiter`/`middleware.RateLimiterWithConfig` is never referenced anywhere in the codebase.
- The only request-concurrency controls that do exist are unrelated to per-user API rate limiting: `thumbnailSemaphore`/`imageProcessingSemaphore` (`server/router/api/v1/v1.go:40-41`) and `thumbnailSemaphore` in the file server (`server/router/fileserver/fileserver.go:106-107,116`) are global `semaphore.Weighted` limits on concurrent thumbnail/image processing work, not per-user request-rate limits, and they aren't wired in as middleware — they're acquired directly inside the specific handlers that do image processing.

So there is no middleware registration site and no request-limit numbers to report — the feature doesn't exist in this codebase.
