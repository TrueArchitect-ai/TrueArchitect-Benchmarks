**Premise correction:** There is no Redis anywhere in this codebase. I searched all Go source (case-insensitive) for `redis` and also checked `go.mod`/`go.sum` for a Redis client dependency — there are zero matches. This repository has no Redis integration at all, so there's no "Redis connection" to configure.

**Actual mechanism:** The cache layer is a custom, in-process, in-memory cache — `Cache` in `store/cache/cache.go:66-73` — backed by a `sync.Map` with per-item expiration timestamps and a periodic cleanup goroutine (`cleanupLoop`/`cleanup`, `store/cache/cache.go:199-250`). It is not a network service; nothing is "connected to."

The `Store` type maintains three separate instances of this in-memory cache — `instanceSettingCache`, `userCache`, and `userSettingCache` — constructed in `store.New` at `store/store.go:38-53`, all sharing the same `cache.Config`:

```40:45:store/store.go
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}
```

**TTL for user entries:** `userCache` (`store/store.go:28,52`) uses this same config, so cached `User` entries expire after the `DefaultTTL` of **10 minutes** (with expired-item cleanup swept every 5 minutes, and eviction of the oldest 20% of entries if the cache exceeds 1000 items — see `cleanupOldest`, `store/cache/cache.go:252-313`). Entries are written via `Cache.Set` (`store/cache/cache.go:92-95`), which applies `config.DefaultTTL` unless a caller explicitly uses `SetWithTTL`; the user-cache call sites in `store/user.go` (e.g. `s.userCache.Set(...)` in `GetUser`/`ListUsers`) use the plain `Set` method, so the 10-minute default TTL applies.
