**Implementation** — there is exactly one concrete implementation of `markdown.Service`: the unexported `*service` struct in `internal/markdown/markdown.go:58-60`, which wraps a configured `goldmark.Markdown` instance and implements all of `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, and `RenameTag` (`internal/markdown/markdown.go:31-55` for the interface, `:142-453` for the methods).

In production, it's constructed exactly once, in `NewAPIV1Service`, with both extensions enabled:

```48:51:server/router/api/v1/v1.go

		markdown.WithTagExtension(),
```

**Holders** — three components hold the `markdown.Service` interface:
1. `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — the one that actually constructs the instance, in `NewAPIV1Service` (`server/router/api/v1/v1.go:47-56`).

3. `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) — also takes the interface via constructor injection (`NewRunner`, `server/runner/memopayload/runner.go:19-24`), but per my earlier finding for [h08](h08), this runner is never actually constructed/wired from production `server/server.go`, so this holder exists in code but is currently dead at runtime.
