I have both pieces — the actual delivery function and the SSRF-guard dial context that protects it (both live in `internal/webhook`, with `isReservedIP` defined in `validate.go`).

h02.

- **delivery function** — `Post` in `internal/webhook/webhook.go:120` (the actual outbound HTTP dispatch: builds the request, optionally HMAC-signs it, and executes it via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`). It's invoked either synchronously or asynchronously through the worker pool in `PostAsync`/`asyncPostQueue` (`internal/webhook/webhook.go:39-55`, `internal/webhook/webhook.go:184-196`).
- **protection mechanism** — `safeDialContext` in `internal/webhook/webhook.go:59-77`, which is installed as the `DialContext` of the shared `safeClient`'s `http.Transport` (`internal/webhook/webhook.go:32-37`). At dial time it resolves the target host and rejects any resolved IP for which `isReservedIP` (defined in `internal/webhook/validate.go:44-54`, checking against the reserved/private CIDR list in `internal/webhook/validate.go:14-23`) returns true — this blocks both direct private-IP targets and DNS-rebinding attempts, since the check happens on the actual dialed address rather than at URL-validation time. A first-pass check of the same reserved ranges also happens earlier at webhook-creation time via `ValidateURL` (`internal/webhook/validate.go:62-83`), but `safeDialContext` is what actually protects the delivery call itself.
