**Premise correction:** there is no nightly database-cleanup job (and no cron scheduler wired into the running server at all) in this codebase.

A repo-wide search for "cleanup", "nightly", and "cron" (excluding the frontend) turns up only unrelated hits: cache-goroutine shutdown comments (`store/store.go:73`), a comment about attachment/relation cleanup that happens inline inside `DeleteMemo` when a memo is deleted (`server/router/api/v1/memo_service.go:579`), a warning-log string about S3 attachment cleanup during user deletion (`server/router/api/v1/user_service.go:447`), a best-effort provisional-user cleanup during SSO sign-in (`server/router/api/v1/auth_service_sso.go:76`), and a doc comment on `store/attachment.go:275`. None of these are scheduled/recurring jobs — they all run synchronously as part of a request handler.

There is a standalone `internal/scheduler` package (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `doc.go`) that implements a generic cron-style job scheduler, but it is never invoked anywhere outside its own package — a search for `scheduler.` usage in `server/` or `cmd/` returns zero results. It is unused, unwired code, not something actually running a nightly cleanup.

The only genuinely scheduled background task in the running server is the S3 presign refresh runner (`server/runner/s3presign/runner.go`, wired in `server/server.go:153-171`), which runs every 12 hours — but it refreshes presigned attachment URLs, not a database cleanup, and isn't cron-based (it uses a plain `time.Ticker`, so it has no fixed "time of day" — just a 12-hour interval from process start).
