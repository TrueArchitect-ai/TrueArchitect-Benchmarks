```74:88:/bench/repo/server/runner/memopayload/runner.go
func RebuildMemoPayload(_ context.Context, memo *store.Memo, markdownService markdown.Service) error {
	if memo.Payload == nil {
		memo.Payload = &storepb.MemoPayload{}
	}

	// Use goldmark service to extract all metadata in a single pass (more efficient)
	data, err := markdownService.ExtractAll([]byte(memo.Content))
	if err != nil {
		return errors.Wrap(err, "failed to extract markdown metadata")
	}

	memo.Payload.Tags = data.Tags
	memo.Payload.Property = data.Property
	return nil
}
```

**Extracted properties** (written into `MemoPayload`, defined in `internal/markdown/markdown.go:20-25` as `ExtractedData`):

- **`Tags`** — all `#tag` occurrences found in the content (via `ExtractTags`/AST tag-node walk).
- **`Property`** (a `storepb.MemoPayload_Property`), derived in the same AST walk:
  - `Title` — text of a leading H1 heading, if the first block is one.
  - `HasLink` — whether the content contains a markdown link.
  - `HasCode` — whether it contains a code block/span.
  - `HasTaskList` — whether it contains a task checkbox.
  - `HasIncompleteTasks` — whether any task checkbox is unchecked.

(`ExtractAll` also computes `Mentions`, but `RebuildMemoPayload` deliberately only persists `Tags` and `Property` into the payload — mentions are used elsewhere, e.g. for notification dispatch, not for the list/preview metadata.) These `Tags`/`Property` fields are what the list/preview UI (tag filters, title fallback, code/link/task icons) reads instead of re-parsing the raw content each time.
