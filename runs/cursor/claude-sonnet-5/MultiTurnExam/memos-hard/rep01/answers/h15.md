**Enforcement sites for memo view visibility:**

1. **`checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:39` — gates `GetMemo` (and other read paths) in the main gRPC/Connect API; denies non-public memos to unauthenticated users and private memos to non-creators.

2. **`checkAttachmentPermission`** — `server/router/fileserver/fileserver.go:650` — gates the raw HTTP file-serving endpoint (`/file/attachments/:uid/:filename`) by checking the linked memo's `Visibility` before streaming attachment bytes.

3. **`(*SSEClient).canReceive`** — `server/router/api/v1/sse_hub.go:134` — gates real-time SSE event delivery; a `Private` memo's create/update/delete/comment event is only pushed to the creator or an admin.

4. **Attachment-service visibility check** — `server/router/api/v1/attachment_service.go:445` (helper checking linked memo's visibility before serving an attachment via the API v1 `GetAttachment`/download path, separately from the file server above).

5. **Reaction-service visibility check** — `server/router/api/v1/reaction_service.go:30` (also `:83`) — gates `ListReactions`/reaction endpoints so reactions on non-public memos aren't exposed to unauthorized viewers.

6. **RSS feed router** — `server/router/rss/rss.go:90` and `:141` — hard-filters `ListMemos` to `VisibilityList: []store.Visibility{store.Public}`, so only public memos ever appear in the RSS feed.

7. **Frontend sitemap generator** — `server/router/frontend/frontend.go:149-151` — likewise restricts `ListMemos` to `store.Public` when building `sitemap.xml`, preventing private/protected memo URLs from being disclosed to crawlers.

8. **Memo-attachment listing check** — `server/router/api/v1/memo_attachment_service.go:214` — gates `ListMemoAttachments` with the same public/private/protected logic before returning a memo's attachment list.

That's at least eight distinct enforcement sites across five different server surfaces (main API v1 service, file server, SSE hub, RSS router, frontend/sitemap router).
