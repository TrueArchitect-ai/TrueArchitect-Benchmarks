**Premise correction:** There is no per-user API rate-limiting middleware anywhere in this codebase. I searched exhaustively (`ratelimit`, `rate limit`, `throttle`, `RateLimiter`, `limiter`, `bucket`, `429`, `TooManyRequests`) across all non-test Go files and found no implementation.

The only hit for "rate limit" is a documentation comment in `internal/email/doc.go:86` — a security-considerations bullet recommending that *email sending* be rate-limited — but there is no corresponding code anywhere in the repo that actually implements it, and it has nothing to do with API middleware.

The actual middleware registered on the Echo server (`server/server.go`, `server/cors.go`, `server/router/frontend/frontend.go`) consists only of:

- `middleware.Recover()` — `server/server.go:51` (panic recovery)
- `middleware.CORSWithConfig(...)` — `server/cors.go:14` (CORS policy)
- `middleware.StaticWithConfig(...)` — `server/router/frontend/frontend.go:54` (static file serving)

The only request-limiting mechanisms present at all are concurrency semaphores (`golang.org/x/sync/semaphore`) in `server/router/fileserver/fileserver.go` (limiting concurrent thumbnail generation, e.g. `maxConcurrentThumbnails = 3`) and `server/router/api/v1/v1.go` (limiting concurrent image processing) — these cap *concurrent in-flight operations* server-wide, not *requests-per-user-over-time*, so they are not a rate limiter in the sense the question presumes.

So: there is no per-user API rate-limiting middleware to point to, and therefore no request limits to report.
