**Premise correction:** There is no nightly database-cleanup job or cron scheduler wired into this server. I confirmed this by checking both possible places such a job could live:

1. **`internal/scheduler`** — this package (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `doc.go`) *is* a generic cron-expression scheduler/job-runner library, but a repo-wide search shows it is never imported or used anywhere outside its own package/tests — no `scheduler.New(...)`, `.Register(...)`, or `.Start(...)` call exists in `server/`, `cmd/`, or `store/`. It's unwired, dead code, not an active nightly job.
2. **`server/server.go`'s `startBackgroundRunners`** — the only background runner actually wired into server startup is the S3 presign runner (`server/server.go:153-174`), which runs every 12 hours (not nightly, and not a "database-cleanup" job — it refreshes presigned S3 URLs). There is no other scheduled/periodic runner registered here.

All other "cleanup"-named code I found (e.g. `attachmentCleanupErr` in `server/router/api/v1/user_service.go:421-450`, the delete-memo comment in `server/router/api/v1/memo_service.go:579`, provisional-user cleanup in `server/router/api/v1/auth_service_sso.go:76`, storage cleanup helpers in `store/attachment.go:171,262,275`) is synchronous, request-triggered cleanup that runs inline as part of handling a delete/SSO request — not a scheduled nightly job. The only periodic timer I found in the store layer is the in-memory cache's eviction sweep (`CleanupInterval: 5 * time.Minute` at `store/store.go:42`), which runs every 5 minutes to expire stale in-memory cache entries — it is not database cleanup and is not "nightly."

So there's no cron-scheduled nightly database-cleanup job in this codebase to give a time for.
