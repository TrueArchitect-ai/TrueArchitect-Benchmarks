**Delivery function:** `Post` in `internal/webhook/webhook.go:120-180` (invoked synchronously by callers, or queued via `PostAsync` at `internal/webhook/webhook.go:184-196` and drained by the worker goroutines started in `init()` at `internal/webhook/webhook.go:42-55`). The actual outbound network call happens at `resp, err := safeClient.Do(req)` — `internal/webhook/webhook.go:152`.

**Protection mechanism:** The shared `safeClient` (`internal/webhook/webhook.go:32-37`) uses a custom `http.Transport.DialContext` set to `safeDialContext` (`internal/webhook/webhook.go:59-77`). At dial time it resolves the target host and rejects the connection if any resolved IP is a reserved/private address per `isReservedIP` (`internal/webhook/validate.go:44-54`), checked against the CIDR list `reservedCIDRs`/`reservedNetworks` (`internal/webhook/validate.go:14-36`) — covering loopback, RFC‑1918 private ranges, link‑local/cloud IMDS (`169.254.0.0/16`), and their IPv6 equivalents. Because the check runs at actual dial time (not just against the URL string beforehand), it also blocks DNS‑rebinding attacks. There's an additional pre-flight check, `ValidateURL` (`internal/webhook/validate.go:62-83`), used when webhooks are created/updated (e.g. `server/router/api/v1/user_service_webhooks.go`, `server/router/api/v1/memo_service_webhooks.go`), but the dial-time guard in `safeDialContext` is what actually protects every delivery attempt, including retries against IPs that change between validation and send.
