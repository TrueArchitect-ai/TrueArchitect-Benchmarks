h14.

**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`, which calls `markdownService.ExtractAll(memo.Content)` — the actual extraction logic lives in `(*service).ExtractAll`, `internal/markdown/markdown.go:356-422` (a single goldmark AST walk).

**Triggers (recomputation):**
- **`CreateMemo`** — always rebuilds the payload for new memo content: `s.Store.CreateMemo` is preceded by `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` at `server/router/api/v1/memo_service.go:108`.
- **`UpdateMemo`** — only when the update mask includes the `content` field: inside the `path == "content"` branch, `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)` is called at `server/router/api/v1/memo_service.go:447`, right after `memo.Content = request.Memo.Content` (`server/router/api/v1/memo_service.go:446`). Updating visibility, pinned status, etc. does not retrigger it.
- (There's also a dormant `memopayload.Runner.RunOnce` batch job intended to rebuild payloads for *all* memos — `server/runner/memopayload/runner.go:27-72` — but per earlier analysis it's never constructed/invoked anywhere in production, so it's not an active trigger.)

**Extracted properties** (assigned onto `memo.Payload` — a `storepb.MemoPayload`, `proto/gen/store/memo.pb.go`):
- `Payload.Tags` — all `#tag` occurrences found in the content, deduplicated case-preserving (`memopayload/runner.go:85`, sourced from `ExtractedData.Tags`).
- `Payload.Property` (a `MemoPayload_Property`, `proto/gen/store/memo.pb.go:85-95`) — derived boolean/text flags computed purely from content structure during the AST walk:
  - `HasLink` — content contains a markdown link.
  - `HasCode` — content contains a code block/span.
  - `HasTaskList` / `HasIncompleteTasks` — content contains task checkboxes, and whether any are unchecked.
  - `Title` — text of the first H1 heading, if the document's first block is one (`internal/markdown/markdown.go:383-389`).

(Note: `ExtractAll` also computes `Mentions` in the same struct, but `RebuildMemoPayload` doesn't persist those onto `Payload`; `@mention` extraction/storage for notifications is handled separately via a direct `s.MarkdownService.ExtractAll` call in `server/router/api/v1/memo_mention_helpers.go:32`.) These `Tags`/`Property` fields are what memo list/preview UIs read to show tag chips, titles, and code/link/task icons without re-parsing the raw markdown each time.
