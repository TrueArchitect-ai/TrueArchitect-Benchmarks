**Actual mechanism:** The cache layer is a pure in-process, in-memory cache — `store/cache/cache.go` (`type Cache struct { data sync.Map; ... }`, `store/cache/cache.go:67-73`), backed by `sync.Map` with a background goroutine (`cleanupLoop`, `store/cache/cache.go:200-215`) that periodically evicts expired entries. There's no network connection to configure because there's no external cache service involved.

The `Store` holds three separate instances of this in-memory cache — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`) — all constructed with the same hardcoded configuration in `store.New`:

```37:53:store/store.go
func New(driver Driver, profile *profile.Profile) *Store {

		MaxItems:        1000,
		OnEviction:      nil,
	}

	store := &Store{
		driver:               driver,
		profile:              profile,
		cacheConfig:          cacheConfig,
		instanceSettingCache: cache.New(cacheConfig),
		userCache:            cache.New(cacheConfig),
		userSettingCache:     cache.New(cacheConfig),
```

**TTL for user entries:** `userCache` entries use the `DefaultTTL` of **10 minutes** (`store/store.go:41`), since `Set` (called via `Store.ListUsers`/`Store.GetUser`, `store/user.go:136-168`) always applies `c.config.DefaultTTL` (`store/cache/cache.go:92-95`) — there's no per-user custom TTL override anywhere in the codebase (`SetWithTTL` with a custom duration is never called for user entries).
