**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search for "redis" (across all `.go` files, `go.mod`, and `go.sum`) returns nothing. The cache layer isn't backed by an external service at all.

**Actual mechanism:** The cache is a self-contained, in-process, in-memory cache implemented in `store/cache/cache.go` (`type Cache struct` at `store/cache/cache.go:67`, backed by a `sync.Map`, with a background goroutine doing periodic expiry cleanup). It's instantiated for three separate purposes (`instanceSettingCache`, `userCache`, `userSettingCache`) in `store/store.go:51-53`, inside `store.New`.

The user cache's TTL is set by the shared `cacheConfig` built in `store/store.go:40-45`:

```39:45:store/store.go
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}
```

So `userCache` (`store/store.go:52`) entries default to a **10-minute TTL**, with expired entries swept by a cleanup loop that runs every 5 minutes (`store/cache/cache.go:200-215`), and the cache is additionally capped at 1000 items with oldest-entry eviction (`store/cache/cache.go:253-313`).
