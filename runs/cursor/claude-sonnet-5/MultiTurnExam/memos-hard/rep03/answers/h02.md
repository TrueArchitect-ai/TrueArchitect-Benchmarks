**Protection mechanism — path:**
The shared `safeClient` (`internal/webhook/webhook.go:32-37`) uses a custom `http.Transport` whose `DialContext` is set to `safeDialContext` (`internal/webhook/webhook.go:59-77`). At dial time, `safeDialContext` resolves the target hostname and rejects the connection if any resolved IP falls in a reserved/private range, using `isReservedIP` (`internal/webhook/validate.go:44-54`) against the CIDR list `reservedCIDRs`/`reservedNetworks` (loopback, RFC‑1918 private ranges, link-local/cloud IMDS `169.254.0.0/16`, and IPv6 equivalents — `internal/webhook/validate.go:14-36`). This dial-time check defeats DNS-rebinding attacks, since it validates the IP actually being connected to rather than the hostname checked earlier. A separate, earlier check, `ValidateURL` (`internal/webhook/validate.go:62-83`), performs the same reserved-IP validation at webhook-URL-registration time (scheme + hostname resolution check) so that invalid/internal URLs are rejected before ever being saved. (Both checks can be disabled for self-hosted use via the `AllowPrivateIPs` flag, `internal/webhook/validate.go:41`.)
