**Premise correction:** There is no per-user API rate-limiting middleware in this codebase — I found no such component to describe its registration site or limits.

Evidence I checked:
- A repo-wide case-insensitive search for `ratelimit`, `rate limit`, `rate_limit`, and `throttle` across all `.go` files returns only a single hit: a comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which is aspirational documentation about the *email* package, not an implemented middleware, and unrelated to API requests.
- The Echo framework used here (`github.com/labstack/echo/v5`) does ship a `middleware.RateLimiter` helper, but it is never imported or used anywhere in `server/` — the only `echo/v5/middleware` usages registered are `middleware.Recover()` (`server/server.go:51`), `middleware.CORSWithConfig` (`server/cors.go:14`), and `middleware.StaticWithConfig` for serving frontend assets (`server/router/frontend/frontend.go:54`).
- The only request-throttling-like constructs in the server are concurrency-limiting semaphores (e.g. `thumbnailSemaphore`/`imageProcessingSemaphore` in `server/router/api/v1/v1.go:40-41` and `server/router/fileserver/fileserver.go:107,116`), which cap concurrent thumbnail/image-processing work server-wide — they are not per-user, not request-count based, and not registered as middleware.

So there's no rate-limiting middleware, per-user or otherwise, to point to in this repository.
