**Premise correction:** This repository has no Redis-backed cache layer at all — there's no `redis` dependency anywhere in `go.mod`/`go.sum`, and no import of a Redis client in the codebase. There is no "Redis connection" to configure.

**Actual mechanism:** Caching (including the user cache) is an in-process, in-memory cache implemented from scratch in `store/cache/cache.go` (an `Interface`/`Cache` type backed by a `sync.Map`-style structure with background expiration/eviction, `store/cache/cache.go:11-60+`). It is instantiated per `Store` in `store/store.go:38-60`, where `Store.New` builds three separate in-memory caches — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29,51-53`) — all sharing the same `cache.Config`:

```37:45:store/store.go
func New(driver Driver, profile *profile.Profile) *Store {
	// Default cache settings
	cacheConfig := cache.Config{
		DefaultTTL:      10 * time.Minute,
		CleanupInterval: 5 * time.Minute,
		MaxItems:        1000,
		OnEviction:      nil,
	}
```

**TTL for user entries:** `userCache` uses this shared `DefaultTTL` of **10 minutes** (`store/store.go:41`), with a background cleanup sweep every 5 minutes (`CleanupInterval`, `store/store.go:42`) and a cap of 1000 items (`MaxItems`, `store/store.go:43`) enforced by the cache's own eviction logic in `store/cache/cache.go`. This cache is used, read/written via `Store.GetUser`/`Store.ListUsers`/`Store.UpdateUser` (`store/user.go:109-169`), and torn down in `Store.Close` (`store/store.go:72-79`).
