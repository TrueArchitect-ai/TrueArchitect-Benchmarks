**Premise correction:** This repository has no per-user (or any other) API rate-limiting middleware. A full search for rate-limiting terms (`ratelimit`, `rate limit`, `throttle`) across all Go files turns up exactly one hit: a comment in `internal/email/doc.go:86` that merely *suggests*, as a documentation note, that callers "Rate limit email sending to prevent abuse" — it is not an implementation. There's also no use of Echo's built-in `middleware.RateLimiter` and no import of `golang.org/x/time/rate` (or any similar limiter library) anywhere in the module.

Related but distinct mechanisms that do exist (in case one of these was the intended target):
- Concurrency limiting (not rate limiting) via `semaphore.Weighted` for thumbnail/image generation, e.g. `thumbnailSemaphore`/`imageProcessingSemaphore` in `server/router/api/v1/v1.go:39-41`.
- A per-request byte-size cap, `maxAPIRequestBytes` (`server/router/api/v1/v1.go:20`).

But no component enforces a request-count-per-time-window limit per user, so there is no registration site or limit values to report.
