**Premise correction:** There is no Redis anywhere in this codebase — no import, no client, no config option (`grep`-ing the entire repo, including `go.mod`, turns up zero references to Redis). This is a false premise.

**Actual mechanism:** The "cache layer" is a self-contained, thread-safe in-memory cache implemented in `store/cache/cache.go` (type `Cache`, `store/cache/cache.go:66`), not a Redis client. Each `Store` instance owns three separate in-process instances of it — `instanceSettingCache`, `userCache`, and `userSettingCache` — declared at `store/store.go:27-29` and constructed in `store.New` at `store/store.go:38-58`.

**TTL for user entries:** The `userCache` is constructed with the shared `cacheConfig` at `store/store.go:40-45`, which sets `DefaultTTL: 10 * time.Minute` (also `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`). All writes to `userCache` in `store/user.go` (e.g. `store/user.go:98,122,132,143,167`) call the plain `Set` method rather than `SetWithTTL`, and `Set` applies `c.config.DefaultTTL` (`store/cache/cache.go:92-94`) — so every cached user entry expires after **10 minutes**, enforced by the cache's own expiration check (`store/cache/cache.go:135`) and periodically swept by its `cleanupLoop` (`store/cache/cache.go:199-227`).
