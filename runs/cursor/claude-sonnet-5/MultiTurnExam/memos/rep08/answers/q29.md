**Token kinds managed:**
- **Access token** — a short-lived JWT kept in memory/localStorage by `repo/web/src/auth-state.ts` (`memos_access_token`), attached as a `Bearer` `Authorization` header on each request; the interceptor proactively/reactively refreshes it when expired or on a `401`.
- **Refresh token** — a longer-lived token stored server-side as an HttpOnly cookie (`memos_refresh`), sent automatically via `credentials: "include"` and exchanged via the `RefreshToken` RPC (`refreshAuthClient.refreshToken({})`) to mint new access tokens; the frontend never reads its value directly.

**Backend package that validates them:** `repo/server/auth` (e.g. `authenticator.go`, `token.go`, `extract.go`, `context.go`) — this package parses/validates the JWT access token and refresh token and applies the resulting identity to the request context, used by both the gRPC-Gateway auth middleware and the Connect auth interceptor wired in `repo/server/router/api/v1/v1.go`.
