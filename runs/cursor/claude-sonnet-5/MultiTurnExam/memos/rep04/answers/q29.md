Interceptor: `web/src/connect.ts` (`authInterceptor`); token kinds: short-lived JWT access token (Bearer, sent via `Authorization` header, held in memory/localStorage) and a refresh token (delivered via an HTTP-only cookie, sent automatically with `credentials: "include"`); backend validation package: `server/auth`

- Frontend interceptor: `authInterceptor` in `web/src/connect.ts` (lines 156-178) attaches `Authorization: Bearer <token>` to each request and, on a `401 Unauthenticated`, triggers a refresh (`refreshAccessToken`/`doRefreshAccessToken`, same file) which calls `authServiceClient.refreshToken({})` — this relies on the browser sending the refresh-token cookie automatically (`fetchWithCredentials`, `credentials: "include"`).
- Token kinds managed:
  - **Access token** — short-lived JWT, held in JS memory/`getAccessToken`/`setAccessToken` (`web/src/auth-state.ts`), sent as a Bearer token.
  - **Refresh token** — longer-lived token stored in an HTTP-only cookie, not directly touched by JS; used server-side to mint new access tokens.
- Backend validation package: `server/auth` (`server/auth/authenticator.go`, `server/auth/token.go`), e.g. `Authenticator.AuthenticateByAccessTokenV2` (validates the JWT access token) and `Authenticator.AuthenticateByRefreshToken` (validates the refresh token cookie against the database via `store.GetUserRefreshTokenByID`).
