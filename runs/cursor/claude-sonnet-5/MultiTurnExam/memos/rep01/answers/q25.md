**Engine:** CEL (Common Expression Language), implemented via a custom filter engine in `internal/filter/` (built on `cel-go`), primarily `internal/filter/engine.go` (compilation via `Engine.Compile`) and `internal/filter/render.go` (SQL rendering).

**Mechanism:** The CEL filter string is compiled into an AST/`Program` by `filter.Engine.Compile` (`internal/filter/engine.go`, `internal/filter/parser.go`), then `render.go`'s renderer walks that AST and emits dialect-specific SQL fragments/placeholders by switching on a `DialectName` (`DialectSQLite`, `DialectPostgres`, `DialectMySQL`) to produce the correct column-qualification, JSON-extraction, and string/date functions for each database (e.g. `internal/filter/render.go:230-241` for timestamp expressions, `:364-408` for JSON extraction).
