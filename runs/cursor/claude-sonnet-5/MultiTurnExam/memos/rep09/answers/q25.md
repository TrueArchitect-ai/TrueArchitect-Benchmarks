**Engine:** [CEL (Common Expression Language)](https://github.com/google/cel-go), implemented in `internal/filter/` — specifically `internal/filter/engine.go` (`Engine.Compile` parses the filter string via `cel.NewEnv`/`env.Compile` into a dialect-agnostic `Condition` tree, using `internal/filter/parser.go` and `internal/filter/ir.go`).

**Mechanism:** A shared `renderer` (`internal/filter/render.go`) walks the dialect-agnostic condition tree and emits dialect-specific SQL fragments and placeholder/argument lists by switching on a `DialectName` (`DialectSQLite`, `DialectPostgres`, `DialectMySQL`), varying details like timestamp extraction, boolean casts (e.g. Postgres `::boolean`), and string-length semantics (e.g. MySQL `CHAR_LENGTH` vs `LENGTH`) so the same CEL filter compiles to correct, dialect-appropriate `WHERE` clauses for SQLite, PostgreSQL, and MySQL.
