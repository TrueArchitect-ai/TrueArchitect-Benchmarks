**Interceptor path:** `web/src/connect.ts` (`authInterceptor`, lines 156-178) — attaches the `Authorization: Bearer <token>` header to outgoing requests and handles 401-triggered refresh/retry.

**Token kinds it manages:** an **access token** (short-lived JWT, kept in memory/state via `getAccessToken`/`setAccessToken` in `web/src/auth-state.ts`, attached as a bearer header) and a **refresh token** (stored as an HTTP-only cookie, sent via `credentials: "include"`/`fetchWithCredentials`, used through `AuthService.refreshToken` to mint new access tokens).

**Backend package that validates them:** `server/auth` (specifically `server/auth/authenticator.go`, e.g. `Authenticator.AuthenticateByAccessTokenV2`, `Authenticator.AuthenticateByRefreshToken`, and `Authenticator.Authenticate`), plus token parsing helpers in `server/auth/token.go`.
