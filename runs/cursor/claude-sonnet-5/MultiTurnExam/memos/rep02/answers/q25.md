**Mechanism:** The engine compiles the CEL filter string into a dialect-agnostic `Condition` tree (via `cel-go`), and a `renderer` in `internal/filter/render.go` then walks that tree and emits dialect-specific SQL fragments (branching on `DialectSQLite`/`DialectPostgres`/`DialectMySQL` for things like timestamp functions, JSON/tag containment checks, and regex/text matching), which each store driver (`store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`) appends into its `WHERE` clause when listing memos.
