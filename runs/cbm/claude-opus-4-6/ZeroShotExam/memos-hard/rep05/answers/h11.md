Of the persistent entity types defined in the `store` package (the data layer), the two referenced from the largest number of packages outside that layer are:

1. **Memo** — referenced from ~7 packages (`server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/router/fileserver`, `server/notification`, `server/runner/memopayload`)

2. **User** — referenced from ~7 packages (`server/router/api/v1`, `server/router/api/v1/test`, `server/router/frontend`, `server/router/rss`, `server/router/fileserver`, `server/notification`, `server/auth`)

Both are tied at 7 packages each, but `Memo` edges ahead when counting the breadth of related store types pulled in (e.g., `FindMemo`, `UpdateMemo`, `Visibility`, `FindMemoPayload`) — the `server/runner/memopayload` package is dedicated entirely to Memo processing. `User` has similar reach but via a different spread that includes `server/auth` (for `Role` and user lookups).

**1st: Memo; 2nd: User** (both ~7 packages outside the store layer)

The next closest is `Attachment` at ~5 packages, then `Inbox` at ~3.
