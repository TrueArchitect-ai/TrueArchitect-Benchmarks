The premise is incorrect — the webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain Go buffered channel** used as an in-process async queue. It is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

In the same file's `init()` function (`internal/webhook/webhook.go:42–55`), **4 goroutines** are spawned that range over this channel, each calling `Post()` to deliver the webhook via HTTP. Callers enqueue payloads by calling `PostAsync()` (`internal/webhook/webhook.go:184–196`), which does a non-blocking send into the channel (dropping the payload with a warning log if the 128-slot buffer is full).

The dispatch call sites are in `server/router/api/v1/memo_service_webhooks.go` (lines 44, 71) where `webhook.PostAsync(payload)` is called for memo-related events (created, updated, deleted, comment created). There is no NATS client, RabbitMQ/AMQP dependency, or any external queue declaration anywhere in the codebase.
