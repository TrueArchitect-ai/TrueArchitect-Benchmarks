**Protection mechanism** — SSRF protection via `safeDialContext` in `internal/webhook/webhook.go` (line 59) combined with `isReservedIP` and the `reservedCIDRs` blocklist in `internal/webhook/validate.go` (line 14).

The protection works at two layers:

1. **At registration time**: `ValidateURL` (`internal/webhook/validate.go:62`) resolves the webhook URL's hostname and rejects it if any resolved IP falls within a reserved/private CIDR range (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents).

2. **At delivery time**: The `safeClient` HTTP client (`internal/webhook/webhook.go:32`) uses a custom `Transport` whose `DialContext` is set to `safeDialContext` (`internal/webhook/webhook.go:59`). This function resolves the target hostname at dial time and checks every resolved IP against `isReservedIP` (`internal/webhook/validate.go:44`), blocking connections to reserved/private ranges. This second check at dial time also defeats DNS rebinding attacks (where a hostname resolves to a public IP at validation but a private IP at connection time).
