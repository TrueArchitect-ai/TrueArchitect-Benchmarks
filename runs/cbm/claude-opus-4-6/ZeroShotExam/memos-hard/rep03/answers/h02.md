**Protection mechanism — `safeDialContext` + `isReservedIP` in `internal/webhook/webhook.go` (line 59) and `internal/webhook/validate.go`**. Two layers guard against SSRF:

1. **At dial time** (`internal/webhook/webhook.go:59–77`): The `safeClient` HTTP client uses a custom `Transport` whose `DialContext` is `safeDialContext`. This resolves the target hostname via DNS and checks every returned IP against `isReservedIP` before establishing a connection — this also defeats DNS rebinding attacks since the check happens at connection time, not registration time.

2. **At registration time** (`internal/webhook/validate.go:62–83`): `ValidateURL` performs an upfront DNS resolution and rejects any webhook URL that resolves to a reserved/private IP, blocks non-http(s) schemes, and returns a gRPC `InvalidArgument` error.

Both layers consult the same `isReservedIP` function (`validate.go:44–54`), which checks against a list of reserved CIDRs (`validate.go:14–23`) covering IPv4 loopback, RFC-1918 private ranges, link-local/cloud IMDS (`169.254.0.0/16`), and IPv6 equivalents. An `AllowPrivateIPs` flag (`validate.go:41`) can disable this for self-hosted deployments that intentionally target local-network services.
