**Two explicit `DELETE` statements in Go handle reaction cleanup during user deletion**, both in `store/db/sqlite/user_delete.go` (shared by all DB drivers):

1. **`deleteReactionsByContentIDsTx`** (line 380–388) — deletes all reactions on the user's memos:
   ```sql
   DELETE FROM reaction WHERE content_id IN (...)
   ```
   Called at line 96 of `deleteUserTargetsTx`, passing content IDs derived from the user's memo tree.

2. **`deleteReactionsByCreatorTx`** (line 400–403) — deletes all reactions the user themselves created:
   ```sql
   DELETE FROM reaction WHERE creator_id = ?
   ```
   Called at line 102 of `deleteUserTargetsTx`.

**No database-level CASCADE exists.** The `reaction` table schema (e.g., `store/migration/sqlite/LATEST.sql:92–98`, `store/migration/postgres/LATEST.sql:91–97`) defines `creator_id` and `content_id` as plain columns with no `REFERENCES` or `ON DELETE CASCADE` constraints.

Both deletions happen inside a single transaction (`deleteUserTargetsTx`, line 92–127) that also removes attachments, memo shares, inboxes, identities, settings, memo relations, memos, and finally the user row itself.
