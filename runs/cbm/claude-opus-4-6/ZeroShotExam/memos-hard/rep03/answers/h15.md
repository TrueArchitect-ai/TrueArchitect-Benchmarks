Here are all distinct memo visibility enforcement sites on the server:

1. **GetMemo / checkMemoReadAccess** (shared helper used by GetMemo, ListMemoComments, etc.) — `server/router/api/v1/memo_service.go` (line 39)
2. **ListMemos** (query-time filter by visibility based on caller identity) — `server/router/api/v1/memo_service.go` (lines 218–227)
3. **ListMemoReactions / UpsertMemoReaction** (inline visibility check before listing or upserting reactions) — `server/router/api/v1/reaction_service.go` (lines 29–41, 82–85)
4. **CreateMemoComment** (visibility check on parent memo before allowing comment) — `server/router/api/v1/memo_service_comments.go` (lines 33–43)
5. **ListMemoComments** (visibility filter on related memos returned as comments) — `server/router/api/v1/memo_service_comments.go` (lines 148, 157–161)
6. **ListMemoAttachments** (visibility check on the owning memo) — `server/router/api/v1/memo_attachment_service.go` (lines 213–225)
7. **checkAttachmentAccess** (visibility check on the linked memo when accessing an attachment directly) — `server/router/api/v1/attachment_service.go` (lines 422–455)
8. **ListMemoRelations** (visibility filter injected into the memo relation query) — `server/router/api/v1/memo_relation_service.go` (lines 108–112)
9. **SSE hub delivery filtering** (`canReceive` filters events by visibility before delivering to SSE clients) — `server/router/api/v1/sse_hub.go` (lines 134–144)
10. **File server attachment access** (visibility check with share-token fallback for serving attachment files via HTTP) — `server/router/fileserver/fileserver.go` (lines 674–701)
11. **RSS feed** (only PUBLIC memos are included in RSS output) — `server/router/rss/rss.go` (lines 90, 141)
12. **Frontend sitemap** (only PUBLIC memos appear in the sitemap) — `server/router/frontend/frontend.go` (line 150)
