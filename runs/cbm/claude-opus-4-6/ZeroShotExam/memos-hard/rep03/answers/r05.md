The premise is incorrect — this repository does **not** use GraphQL. The public API is defined using **Protocol Buffers (protobuf)** and exposed via **Connect/gRPC-Gateway**, which provides both **gRPC** and **REST** interfaces.

The API schema is defined in `.proto` files under `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/common.proto`

These proto definitions are processed by `buf` (configured in `proto/buf.yaml` and `proto/buf.gen.yaml`) to generate:

- **Go server/client stubs** in `proto/gen/api/v1/` (e.g., `*.pb.go`)
- **TypeScript client types** in `web/src/types/proto/api/v1/` (via `@bufbuild/protobuf` / protobuf-es)
- **OpenAPI/Swagger spec** in `proto/gen/` (e.g., `openapi.yaml` / `apidocs.swagger.yaml`)

The generated handlers are wired up in `server/router/api/` as Connect RPC services, which serve both gRPC and REST (via gRPC-Gateway) on the same endpoints.
