The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is a **custom in-memory cache** (not Redis), implemented in pure Go.

**Cache implementation:** `store/cache/cache.go` defines a thread-safe in-memory cache using `sync.Map` with TTL-based expiration and a background cleanup goroutine.

**Configuration:** The `userCache` is instantiated in `store/store.go:52` via `cache.New(cacheConfig)`, where `cacheConfig` is defined at `store/store.go:40-45` with these defaults:

- **DefaultTTL: 10 minutes** (`10 * time.Minute`) — this is the TTL that applies to user entries
- CleanupInterval: 5 minutes
- MaxItems: 1000

There is no Redis dependency anywhere in the codebase. The `Store` struct (`store/store.go:13-30`) holds three in-memory caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing the same `cache.Config` with a 10-minute TTL.
