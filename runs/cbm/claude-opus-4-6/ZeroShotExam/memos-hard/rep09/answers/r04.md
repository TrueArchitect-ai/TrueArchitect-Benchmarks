The premise is incorrect — the webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The actual mechanism is a **plain Go buffered channel** used as an in-process async queue. It is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in an `init()` function in the same file (`internal/webhook/webhook.go:42–55`) that range over this channel and call `Post()` to deliver each webhook via HTTP. Callers enqueue payloads by calling `PostAsync()` (`internal/webhook/webhook.go:184–196`), which performs a non-blocking send into the channel (dropping the payload with a warning log if the 128-slot buffer is full).

There is no dependency on NATS, RabbitMQ, or any other external message broker anywhere in the codebase — webhook delivery is entirely in-process.
