**By explicit Go code**; reactions are cleaned up in application-level transactional deletion logic, not by database CASCADE rules.

## Mechanism

When a user is deleted, two explicit SQL `DELETE` statements remove reactions inside a single transaction within `deleteUserTargetsTx`:

1. **Reactions on the deleted user's memos** (by any user):  
   `DELETE FROM reaction WHERE content_id IN (...)` — removes all reactions attached to memos that are about to be deleted.

2. **Reactions the deleted user placed on others' memos**:  
   `DELETE FROM reaction WHERE creator_id = ?` — removes the deleted user's reactions elsewhere so no orphans remain.

The `reaction` table declares `creator_id INTEGER NOT NULL` and `content_id TEXT NOT NULL` but has **no `FOREIGN KEY` constraints** and therefore no `ON DELETE CASCADE`. All cleanup is done by the Go application layer within a transactional block.
