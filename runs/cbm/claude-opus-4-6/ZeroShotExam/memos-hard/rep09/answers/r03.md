The repository contains a generic cron scheduler framework (`internal/scheduler/`) that allows registering arbitrary jobs with cron expressions (`internal/scheduler/scheduler.go`, `internal/scheduler/job.go`), but no actual "database-cleanup" job is registered anywhere in the production code.

The closest thing is an **example in a test file** (`internal/scheduler/example_test.go:98-106`) that demonstrates a hypothetical `"cleanup"` job scheduled at `"0 2 * * *"` (2:00 AM) with the comment "Cleanup old data every night at 2 AM" — but this is illustrative example code in a `_test.go` file, not a real scheduled job deployed by the application. The only real GitHub Actions cron schedule in the repo is the stale-issues workflow (`.github/workflows/stale.yml`) running every 8 hours, which is unrelated to database cleanup.
