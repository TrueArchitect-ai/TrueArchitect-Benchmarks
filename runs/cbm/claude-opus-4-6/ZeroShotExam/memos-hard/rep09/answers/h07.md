`GET /file/users/:identifier/avatar` — browser request for another user's profile image:

1. `RegisterRoutes` — `server/router/fileserver/fileserver.go:121` — registers the route, binding it to `serveUserAvatar`
2. `serveUserAvatar` — `server/router/fileserver/fileserver.go:168` — HTTP handler; extracts `:identifier` param, calls `getUserByUsername`
3. `getUserByUsername` — `server/router/fileserver/fileserver.go:715` — calls `s.Store.GetUser` with a `FindUser{Username: &identifier}`
4. `Store.GetUser` — `store/user.go:148` — checks the in-memory user cache; on miss, delegates to `s.ListUsers`
5. `Store.ListUsers` — `store/user.go:136` — delegates to `s.driver.ListUsers` (the `Driver` interface defined in `store/driver.go:48`)
6. `DB.ListUsers` — `store/db/sqlite/user.go:88` (or `store/db/postgres/user.go:87` / `store/db/mysql/user.go:84`) — builds and executes `SELECT ... avatar_url ... FROM user WHERE username = ?`, returning the `User` row including `AvatarURL`

Back in `serveUserAvatar` (line 196), the handler calls `parseDataURI(user.AvatarURL)` to decode the base64 data-URI stored in the `avatar_url` column, then writes the raw image bytes to the response via `c.Blob()`.
