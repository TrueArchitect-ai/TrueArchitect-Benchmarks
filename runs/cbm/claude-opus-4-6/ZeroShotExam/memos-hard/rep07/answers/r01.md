The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is a **pure in-memory cache**, not backed by Redis or any external store.

The cache is implemented as a thread-safe Go struct using `sync.Map` in `store/cache/cache.go`. It is configured and instantiated in `store/store.go:38-45`, where the `Store.New()` constructor creates three separate in-memory cache instances (`userCache`, `instanceSettingCache`, `userSettingCache`) all sharing the same `cache.Config`.

The TTL that applies to user entries (`userCache`) is **10 minutes** (`10 * time.Minute`), set as the `DefaultTTL` in the config at `store/store.go:41`. The cleanup interval is 5 minutes and the max item count is 1000 — these apply uniformly to all three caches. There is no per-entry TTL override for users; all entries use the default TTL unless `SetWithTTL` is called explicitly with a different duration.
