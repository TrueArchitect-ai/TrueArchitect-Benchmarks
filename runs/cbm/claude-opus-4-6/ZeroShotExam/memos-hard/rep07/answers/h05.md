When a user is deleted, their emoji reactions are removed by **explicit Go code** executing SQL `DELETE` statements within a transaction. There is **no** database-level `ON DELETE CASCADE` — the `reaction` table has no foreign key constraints at all (the `creator_id` column is `NOT NULL` but has no `REFERENCES` clause).

The deletion happens in two steps inside `deleteUserTargetsTx()`:

1. **Reactions on the user's memos** are deleted by `deleteReactionsByContentIDsTx()` — this deletes all reactions (by any user) whose `content_id` matches the deleted user's memos (`store/db/sqlite/user_delete.go:96`, `store/db/sqlite/user_delete.go:380-388`):
   ```sql
   DELETE FROM reaction WHERE content_id IN (...)
   ```

2. **Reactions created by the user** (on anyone's memos) are deleted by `deleteReactionsByCreatorTx()` (`store/db/sqlite/user_delete.go:102`, `store/db/sqlite/user_delete.go:400-403`):
   ```sql
   DELETE FROM reaction WHERE creator_id = ?
   ```
