The premise is incorrect — the webhook delivery workers use **neither NATS nor RabbitMQ**. There is no external message broker at all.

The actual mechanism is a **plain Go buffered channel** used as an in-process async queue. It is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the `init()` function (`internal/webhook/webhook.go:42–55`) that consume from this channel in a `for payload := range asyncPostQueue` loop, calling `Post(payload)` to deliver each webhook via HTTP.

Callers enqueue work via the `PostAsync` function (`internal/webhook/webhook.go:184–196`), which does a non-blocking send into the channel and drops the payload with a warning log if the 128-slot buffer is full.

There is no dependency on NATS, RabbitMQ, or any other external message broker anywhere in the repository.
