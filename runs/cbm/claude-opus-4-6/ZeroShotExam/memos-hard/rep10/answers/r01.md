The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is a **custom in-memory cache** (not Redis-backed), implemented in pure Go using `sync.Map` for concurrent access.

**Cache implementation:** `store/cache/cache.go` defines a `Cache` struct that stores items in a `sync.Map` with per-entry expiration timestamps and a background cleanup goroutine.

**Configuration:** The cache is instantiated in `store/store.go:38-45`, where `Store.New()` creates a `cache.Config` with:
- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

**User entries specifically:** The `userCache` field (`store/store.go:28`) uses the same shared `cacheConfig`, so user entries get the same **10-minute TTL** as all other cached entities (instance settings, user settings). There is no Redis dependency anywhere — `go.mod` contains no Redis client library, and no Redis connection string or configuration exists in the codebase.
