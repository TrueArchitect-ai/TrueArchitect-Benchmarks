The browser hits `GET /file/users/:identifier/avatar`. Here is each hop from handler to data:

`serveUserAvatar` — `server/router/fileserver/fileserver.go:168`
`getUserByUsername` — `server/router/fileserver/fileserver.go:715`
`Store.GetUser` — `store/user.go:148`
`Store.ListUsers` — `store/user.go:136`
`Driver.ListUsers` — `store/driver.go:47` (interface), implemented e.g. in `store/db/sqlite/user.go:88`

The avatar data itself is stored inline on the `user` row as a base64 data URI in the `AvatarURL` field. Back in the handler, `parseDataURI` (`server/router/fileserver/fileserver.go:737`) decodes the base64 data URI from the user record and the raw image bytes are served directly via `c.Blob()`. There is no separate attachment/file lookup — the avatar is embedded in the `user` table, not in external storage.
