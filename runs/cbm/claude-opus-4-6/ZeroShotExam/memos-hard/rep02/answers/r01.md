The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer is a **pure in-memory Go cache**, not Redis-backed.

The cache is implemented in `store/cache/cache.go` as a thread-safe in-memory store using `sync.Map` with TTL-based expiration and a background cleanup goroutine. It is instantiated in `store/store.go:38-53`, where the `Store.New()` constructor creates three cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing the same `cache.Config`.

The **TTL for user entries is 10 minutes** (`DefaultTTL: 10 * time.Minute` at `store/store.go:41`), with a cleanup interval of 5 minutes and a max of 1000 items. This same default TTL applies to all three caches (instance settings, users, and user settings) since they share the same configuration. The cache also supports per-entry custom TTL via `SetWithTTL()` (`store/cache/cache.go:98`), though the user cache uses the default.

On the frontend side, the only "cache" is browser `localStorage` for draft memo content (`web/src/components/MemoEditor/services/cacheService.ts`) and React Query's in-memory query cache with a 30-second stale time and 5-minute GC time (`web/src/lib/query-client.ts`). None of these involve Redis either.
