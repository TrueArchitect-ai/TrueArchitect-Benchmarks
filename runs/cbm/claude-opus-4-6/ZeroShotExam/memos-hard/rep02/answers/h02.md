**Delivery function** — `Post` in `internal/webhook/webhook.go` (line 120). This is the function that actually marshals the payload to JSON and executes the outbound HTTP POST to the webhook endpoint. It is called synchronously, or via `PostAsync` (line 184) which enqueues payloads onto a buffered channel consumed by background goroutines. The service layer triggers delivery from `server/router/api/v1/memo_service_webhooks.go` via `webhook.PostAsync`.

**Protection mechanism** — SSRF protection via `safeDialContext` and `isReservedIP` in `internal/webhook/validate.go` (lines 14–54) and `internal/webhook/webhook.go` (lines 57–77). Two layers guard against internal-network targeting:

1. **At dial time** (`safeDialContext`, `webhook.go:59`): The `safeClient` HTTP client uses a custom `Transport` whose `DialContext` resolves the target hostname via DNS and checks every resolved IP against a list of reserved/private CIDR ranges (`validate.go:14–23` — loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents) before allowing the connection. This also defeats DNS rebinding attacks.

2. **At registration time** (`ValidateURL`, `validate.go:62`): When a user registers a webhook URL, the URL is pre-validated — it must use `http` or `https`, and its hostname must not resolve to any reserved IP range.

Both checks call `isReservedIP` (`validate.go:44`), which can be bypassed for self-hosted deployments via the `AllowPrivateIPs` flag (`validate.go:41`).
