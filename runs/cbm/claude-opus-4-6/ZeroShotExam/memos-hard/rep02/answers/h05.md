h05.

Emoji reactions are removed by **explicit Go code**, not by a database-level rule.

**Evidence:**

1. **No CASCADE on the `reaction` table.** The schema definitions (`store/migration/sqlite/LATEST.sql`, `store/migration/postgres/LATEST.sql`) define the `reaction` table with no `FOREIGN KEY` constraints at all — `creator_id` and `content_id` are plain columns with no `ON DELETE CASCADE`. Contrast this with `memo_share`, which does have `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE`.

2. **Explicit Go deletion in two passes.** The user deletion transaction in `store/db/sqlite/user_delete.go` performs two separate reaction-deletion steps within `deleteUserTargetsTx()`:
   - **Line 96:** `deleteReactionsByContentIDsTx(ctx, tx, contentIDs)` — deletes all reactions *on* the user's memos (by `content_id`), removing other users' reactions on content that's about to be deleted. The SQL at line 383: `DELETE FROM reaction WHERE content_id IN (...)`.
   - **Line 102:** `deleteReactionsByCreatorTx(ctx, tx, userID)` — deletes all reactions *by* the user (by `creator_id`), removing this user's reactions on other people's memos. The SQL at line 401: `DELETE FROM reaction WHERE creator_id = ?`.

**Mechanism: explicit Go code; evidence locations:** `store/db/sqlite/user_delete.go:96-103` (orchestration), `store/db/sqlite/user_delete.go:380-388` (`deleteReactionsByContentIDsTx`), `store/db/sqlite/user_delete.go:400-402` (`deleteReactionsByCreatorTx`), `store/migration/sqlite/LATEST.sql` and `store/migration/postgres/LATEST.sql` (no CASCADE on `reaction` table).
