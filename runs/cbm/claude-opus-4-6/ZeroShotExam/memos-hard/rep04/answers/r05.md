The premise is incorrect — this repository (**Memos**) does not have a GraphQL API. The public API is defined using **Protocol Buffers (gRPC) with HTTP/REST transcoding**, not GraphQL.

The API surface is defined in `.proto` files under `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto` (shared types)

These proto definitions use `google.api.http` annotations to expose RESTful endpoints (e.g., `POST /api/v1/memos`, `GET /api/v1/memos`). Code generation is configured in `proto/buf.gen.yaml`, which produces:

1. **Go gRPC server stubs** (`buf.build/protocolbuffers/go`, `buf.build/grpc/go`)
2. **ConnectRPC handlers** (`buf.build/connectrpc/go`)
3. **gRPC-Gateway reverse proxy** (`buf.build/grpc-ecosystem/gateway`) for REST transcoding
4. **OpenAPI spec** (`buf.build/community/google-gnostic-openapi`)
5. **TypeScript client types** (`buf.build/bufbuild/es`) output to `web/src/types/proto`

Generated code lands in `proto/gen/`. There are zero GraphQL dependencies or schema files anywhere in the repository.
