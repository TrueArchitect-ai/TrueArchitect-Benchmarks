The premise is incorrect — the webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The webhook dispatch mechanism is a plain **Go buffered channel** used as an in-process async queue. It is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in an `init()` function at `internal/webhook/webhook.go:42-55` that range over this channel and call `Post()` to deliver each webhook via HTTP. The public entry point is `PostAsync()` (`internal/webhook/webhook.go:184`), which performs a non-blocking send into the channel (dropping the payload with a warning if the buffer is full).

Callers like `server/router/api/v1/memo_service_webhooks.go` invoke `webhook.PostAsync(payload)` directly from the request-handling goroutine — no broker, no queue server, just an in-memory channel with a capacity of 128 items.
