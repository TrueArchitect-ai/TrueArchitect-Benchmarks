The premise is incorrect — there is no Redis connection in this repository. The cache layer uses an **in-memory cache**, not Redis.

The cache is implemented as a custom in-process `sync.Map`-based store in `store/cache/cache.go`. It is configured and instantiated in `store/store.go:38-51`, where the `Store.New()` constructor creates three separate `cache.Cache` instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing the same `cache.Config`.

The **TTL for user entries is 10 minutes** (`DefaultTTL: 10 * time.Minute`), set at `store/store.go:41`. This is the default TTL applied via `cache.Set()` (which delegates to `SetWithTTL` with the default, per `store/cache/cache.go:93-95`). The user cache uses this default TTL — all calls in `store/user.go` (e.g., lines 98, 122, 133, 143, 167) use `s.userCache.Set(ctx, ...)` without a custom TTL override.

Additional cache parameters: cleanup interval is 5 minutes, and max items per cache is 1000 (`store/store.go:42-43`).
