**Premise correction:** The webhook delivery workers consume from neither NATS nor RabbitMQ. This project uses no external message broker at all.

**Actual mechanism:** Webhook delivery uses a plain **Go buffered channel** as an in-process async queue. The "queue" is declared in `internal/webhook/webhook.go:39` as:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the `init()` function at `internal/webhook/webhook.go:42-55` — each reads from `asyncPostQueue` in a `for payload := range asyncPostQueue` loop and calls `Post()` to make a synchronous HTTP POST to the webhook URL.

Producers enqueue payloads via the `PostAsync()` function (`internal/webhook/webhook.go:184-196`), which performs a non-blocking send on the channel and drops the payload with a warning log if the 128-slot buffer is full. The callers are in `server/router/api/v1/memo_service_webhooks.go`, which calls `webhook.PostAsync(payload)` for memo created/updated/deleted/comment events.

There is no NATS, RabbitMQ, AMQP, or any other external broker dependency anywhere in the codebase.
