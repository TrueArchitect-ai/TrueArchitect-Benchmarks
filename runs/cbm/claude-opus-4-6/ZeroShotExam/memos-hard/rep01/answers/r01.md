The premise is incorrect: there is no Redis connection in this repository. The cache layer is a **pure in-memory Go implementation** using `sync.Map`, not Redis or any external cache service.

The cache is defined in `store/cache/cache.go` and is configured in `store/store.go:38-45`. The `Store.New()` constructor creates a `cache.Config` with:

- **DefaultTTL: 10 minutes** (`10 * time.Minute`) — this applies uniformly to all caches, including user entries
- CleanupInterval: 5 minutes
- MaxItems: 1000

The `userCache` field (`store/store.go:28`) is instantiated at line 52 as `cache.New(cacheConfig)` using that shared config. When user objects are cached (e.g., `store/user.go:98`), they call `s.userCache.Set(ctx, userCacheKey(user.ID), user)`, which uses the default 10-minute TTL. There is no per-user custom TTL — all user cache entries share the same 10-minute expiration.

The cache struct (`cache/cache.go:67-73`) stores items in a `sync.Map` with expiration timestamps, and a background goroutine runs every 5 minutes to evict expired entries. There is no network connection, no Redis client, and no external dependency — it is entirely process-local.
