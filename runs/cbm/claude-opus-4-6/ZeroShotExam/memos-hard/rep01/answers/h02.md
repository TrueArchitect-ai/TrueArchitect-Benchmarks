The outbound delivery executes in the `Post` function at `internal/webhook/webhook.go:120`, which marshals the payload to JSON and sends it via `safeClient.Do(req)`. Asynchronous dispatch goes through `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues into a buffered channel consumed by background goroutines that call `Post`.

SSRF protection is implemented through two complementary mechanisms, both in `internal/webhook/validate.go`:

1. **At dial time** — `safeDialContext` (`internal/webhook/webhook.go:59`) resolves the target hostname and checks every returned IP against `isReservedIP` (`internal/webhook/validate.go:44`), which compares against a list of reserved CIDRs (loopback, RFC-1918 private, link-local/cloud IMDS, IPv6 equivalents) defined at `internal/webhook/validate.go:14–23`. This is baked into the `safeClient`'s custom `Transport`, so it also defeats DNS rebinding attacks (the check happens at connection time, not just at URL registration time).

2. **At URL registration time** — `ValidateURL` (`internal/webhook/validate.go:62`) performs the same reserved-IP check eagerly when the user first configures a webhook URL, rejecting it with a gRPC `InvalidArgument` error before it is ever stored.

**Answer:** delivery function — `Post` in `internal/webhook/webhook.go`; protection mechanism — `safeDialContext` + `isReservedIP` + reserved CIDR list in `internal/webhook/validate.go`.
