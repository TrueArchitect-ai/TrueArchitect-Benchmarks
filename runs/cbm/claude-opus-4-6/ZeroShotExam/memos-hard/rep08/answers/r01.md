The premise is incorrect: there is no Redis connection in this repository. The cache layer is a **pure in-memory Go cache**, not Redis-backed.

The cache is implemented in `store/cache/cache.go` as a thread-safe in-memory store using `sync.Map` with TTL-based expiration and a background cleanup goroutine. It has no external dependencies — no Redis, Memcached, or any other external cache service.

The cache is configured in `store/store.go:40-45` when `Store.New()` is called, with these hardcoded defaults:

- **DefaultTTL: 10 minutes** (`10 * time.Minute`)
- CleanupInterval: 5 minutes
- MaxItems: 1000

The user cache (`userCache`) is one of three `*cache.Cache` instances created with this same config (`store/store.go:52`). It uses the shared 10-minute default TTL — there is no user-specific TTL override. User entries are cached on create, update, and read via `userCache.Set()` calls in `store/user.go` (lines 98, 122, 132, 143, 167), and invalidated on delete in `store/user_delete.go:40`.
