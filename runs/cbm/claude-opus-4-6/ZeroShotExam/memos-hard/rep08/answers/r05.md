The premise is incorrect — this repository has no GraphQL schema. The public API is not defined using GraphQL at all.

The actual API surface is defined using **Protocol Buffers (protobuf)** with **gRPC-Gateway**, which generates a RESTful HTTP/JSON API. The source-of-truth definitions are the `.proto` files in `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/common.proto` (shared types)

From these proto definitions, the build toolchain (configured in `proto/buf.gen.yaml`) generates:

1. **Go gRPC stubs and gateway code** in `proto/gen/api/v1/` (e.g., `*.pb.go`, `*_grpc.pb.go`, `*.pb.gw.go`)
2. **An OpenAPI 3.0 spec** at `proto/gen/openapi.yaml` (generated via `protoc-gen-openapi`)

The API is served as REST endpoints under `/api/v1/` (e.g., `/api/v1/ai:transcribe`, `/api/v1/memos`, etc.), translated from the gRPC service definitions by gRPC-Gateway.
