Here is the request path from browser to stored data, hop by hop:

```
GET /file/users/:identifier/avatar
```

1. `RegisterRoutes` — `server/router/fileserver/fileserver.go:124` — registers the route, binding the path to the handler
2. `serveUserAvatar` — `server/router/fileserver/fileserver.go:168` — HTTP handler; authenticates if non-public instance, extracts the `:identifier` param, parses the data-URI avatar, and returns the image blob
3. `getUserByUsername` — `server/router/fileserver/fileserver.go:716` — calls `s.Store.GetUser` with a `FindUser{Username: &identifier}`
4. `Store.GetUser` — `store/user.go:148` — checks the in-memory user cache; on miss delegates to `Store.ListUsers`
5. `Store.ListUsers` — `store/user.go:136` — calls `s.driver.ListUsers(ctx, find)` through the `Driver` interface (`store/driver.go:47`)
6. `DB.ListUsers` — `store/db/sqlite/user.go:88` (or `store/db/postgres/user.go:87`, or `store/db/mysql/user.go:84`) — builds and executes the SQL query against the `user` table, returning the user row including `avatar_url`

The avatar image itself is stored inline in the user's `avatar_url` column as a base64 data URI. Back in `serveUserAvatar` (line 196), `parseDataURI` (`server/router/fileserver/fileserver.go:737`) decodes the base64 data and the handler returns it as a blob response.
