The premise of the question is incorrect — there is no Redis connection in this repository. The cache layer does not use Redis (or any external cache store). Instead, it is a **pure in-memory cache** implemented with Go's `sync.Map`.

The cache is defined in `store/cache/cache.go` as a `Cache` struct backed by a `sync.Map` (line 69) with TTL-based expiration and a periodic cleanup goroutine. It is instantiated in `store/store.go:38-53`, where the `Store.New()` constructor creates three in-memory cache instances (`instanceSettingCache`, `userCache`, `userSettingCache`) all sharing the same `cache.Config`.

The **TTL that applies to user entries** (`userCache`) is **10 minutes** — set via the `DefaultTTL` field at `store/store.go:41`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```

All three caches (instance settings, users, user settings) use this same configuration. Expired items are cleaned up every 5 minutes by a background goroutine (`cache/cache.go:200-215`), and items are also lazily evicted on read if past their expiration (`cache/cache.go:135-144`).
