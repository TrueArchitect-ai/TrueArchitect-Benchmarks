The premise is incorrect — webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker involved at all.

The webhook dispatch mechanism is a plain **in-process Go channel** backed by a fixed pool of goroutines. It is declared in `internal/webhook/webhook.go`:

- **Line 39**: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered Go channel with capacity 128.
- **Lines 42–55**: The `init()` function spawns 4 goroutines that each range over `asyncPostQueue`, calling `Post()` (a synchronous HTTP POST) for each payload they receive.
- **Lines 183–196**: `PostAsync()` sends payloads into `asyncPostQueue` via a non-blocking `select`, dropping the webhook (with a warning log) if the channel is full.

Callers like `DispatchMemoCreatedWebhook` in `server/router/api/v1/memo_service_webhooks.go` enqueue payloads by calling `webhook.PostAsync(payload)` (e.g., line 71). There is no queue declaration in any broker — the "queue" is the 128-slot Go channel, and the "workers" are 4 goroutines started at package init time.
