The following database tables are affected when `DeleteMemo` runs:

- **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`)
- **`memo_relation`** — explicitly deleted in both directions (where memo is source or target) by `store.DeleteMemo` (`store/memo.go:142-146`)
- **`attachment`** — explicitly deleted for all attachments linked to the memo (`store/memo.go:149-157`, which calls `DeleteAttachment` → `DELETE FROM attachment`)
- **`memo_share`** — deleted via `ON DELETE CASCADE` foreign key constraint on `memo_id` referencing `memo(id)` (`store/migration/sqlite/LATEST.sql:109`)

Additionally, comment memos (related via `memo_relation` with type `Comment`) are recursively deleted by the service layer (`server/router/api/v1/memo_service.go:567-577`), which triggers the same cascade for each comment (affecting `memo`, `memo_relation`, `attachment`, and `memo_share` for every child comment).
