**Workers the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` at 12-hour interval (`server/runner/s3presign/runner.go:27`); started by `server.startBackgroundRunners()` in `server/server.go:153–173`
- **Webhook Dispatch Workers (×4)** — channel-driven poll on a buffered channel (size 128), started via `init()` in `internal/webhook/webhook.go:39–55`
- **Email Dispatch Workers (×2)** — channel-driven poll on a buffered channel (size 128), started via `init()` in `internal/email/email.go:14–36`
- **Cache Cleanup Goroutines (×3)** — `time.NewTicker` at 5-minute interval (`store/cache/cache.go:199–215`); one per cache instance created in `store/store.go:51–53`
- **SSE Per-Connection Heartbeat** — `time.NewTicker` at 30-second interval per connected client (`server/router/api/v1/sse_handler.go:17`)
- **PAT Last-Used Recorder** — fire-and-forget goroutine per PAT auth request (`server/auth/authenticator.go:179–185`)

**Unused scheduling infrastructure:**

- The **`internal/scheduler/` package** (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`, `doc.go`) is a fully-featured cron scheduler supporting 5/6-field cron expressions, middleware (recovery, logging, timeout), and graceful shutdown — but it is **never imported outside its own test files**. Zero production code uses it.
- The **Memo Payload Runner** (`server/runner/memopayload/runner.go`) has a `Runner` struct with a `RunOnce()` method that rebuilds all memo payloads in batches, but its constructor `NewRunner()` is never called in production. Only the standalone `RebuildMemoPayload()` function from the same package is used — inline during memo create/update in `server/router/api/v1/memo_service.go`, not as a background runner.
