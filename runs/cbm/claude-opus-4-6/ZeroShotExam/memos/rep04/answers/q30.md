Four memo lifecycle events dispatch webhooks:

- **created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

All defined in `server/router/api/v1/memo_service_webhooks.go`.

The first three converge through the shared helper `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator, fetches their webhooks, and calls `webhook.PostAsync`. The comment event (`DispatchMemoCommentCreatedWebhook`) builds its payload inline but also calls `webhook.PostAsync`.

All four ultimately converge for delivery at **`webhook.PostAsync`** (`internal/webhook/webhook.go:184`), which enqueues the payload onto a buffered channel (`asyncPostQueue`). Worker goroutines (spawned in `init()`, line 42) dequeue payloads and call the synchronous **`webhook.Post`** function (`internal/webhook/webhook.go:120`), which performs the actual HTTP POST to the webhook endpoint.

**Summary:**

| Event | Dispatch function |
|---|---|
| created | `DispatchMemoCreatedWebhook` |
| updated | `DispatchMemoUpdatedWebhook` |
| deleted | `DispatchMemoDeletedWebhook` |
| comment created | `DispatchMemoCommentCreatedWebhook` |

Delivery convergence: `webhook.PostAsync` → `webhook.Post` in `internal/webhook/webhook.go`.
