**Engine:** [Google CEL (Common Expression Language)](https://github.com/google/cel-go) via `cel-go`; **path:** `internal/filter/engine.go` (with schema in `internal/filter/schema.go`, IR in `internal/filter/ir.go`, and renderer in `internal/filter/render.go`).

**Mechanism:** The `Engine.Compile` method parses the filter string into a CEL AST, then `buildCondition` (in `internal/filter/parser.go`) lowers that AST into a dialect-agnostic intermediate condition tree (defined in `internal/filter/ir.go`), and `renderer.Render` (in `internal/filter/render.go`) walks that condition tree and emits dialect-specific SQL fragments by switching on `RenderOptions.Dialect` (`DialectSQLite`, `DialectPostgres`, `DialectMySQL`) — each render method contains per-dialect `switch` branches that produce the appropriate SQL syntax, placeholders, JSON operators, and date-extraction functions for that database.
