**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` attached to the main `createConnectTransport`. It reads the access token via `getRequestToken()`, sets the `Authorization: Bearer <token>` header on every outgoing request, and on a 401 (`Code.Unauthenticated`) retries once after refreshing the token.

**Token kinds managed:**
1. **Access token** (short-lived JWT, 15-minute TTL) — stored in-memory and `localStorage` (`memos_access_token`), managed by `web/src/auth-state.ts`. Sent as `Bearer` in the `Authorization` header.
2. **Refresh token** (long-lived JWT, 30-day TTL) — stored as an HTTP cookie (`memos_refresh`), sent with `credentials: "include"`. Used to obtain new access tokens via `AuthService.refreshToken`.
3. **Personal Access Token (PAT)** — prefixed `memos_pat_`, also sent as a `Bearer` token for programmatic API access.

**Backend validation package:** `server/auth` (Go package at `server/auth/`). Key files:
- `server/auth/authenticator.go` — `Authenticator` struct with `AuthenticateByAccessTokenV2()` (stateless JWT validation), `AuthenticateByRefreshToken()` (database-checked), and `AuthenticateByPAT()` (SHA-256 hash lookup).
- `server/auth/token.go` — JWT generation/parsing (`ParseAccessTokenV2`, `ParseRefreshToken`), constants, and PAT hashing.
