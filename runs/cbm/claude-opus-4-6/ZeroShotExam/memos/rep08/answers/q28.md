**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — 12-hour `time.NewTicker` loop (plus one synchronous `RunOnce` at startup). Renews expiring S3 presigned URLs. Started in `server/server.go:153-173`, implemented in `server/runner/s3presign/runner.go:27-41`.
- **Cache Cleanup (×3 instances)** — 5-minute `time.NewTicker` loop per cache (instanceSettingCache, userCache, userSettingCache). Evicts expired entries. Started via `cache.New()` in `store/store.go:51-53`, loop in `store/cache/cache.go:200-215`.
- **Webhook Workers (×4 goroutines)** — driven by a buffered channel (`asyncPostQueue`, cap 128); workers block on channel receive. Started via `init()` in `internal/webhook/webhook.go:42-55`.
- **Email Workers (×2 goroutines)** — driven by a buffered channel (`asyncEmailQueue`, cap 128); workers block on channel receive. Started via `init()` in `internal/email/email.go:14-36`.

**Unused scheduling infrastructure:**

The `internal/scheduler/` package is a fully-implemented cron job scheduler (with cron expression parsing, middleware, recovery, logging, timezone support) that is **never imported or used** anywhere outside its own package and tests. It is not wired into the server startup path at all.

Additionally, `server/runner/memopayload/runner.go` exists as a runner but is **not started as a background worker** — its `RebuildMemoPayload` function is only called inline during memo create/update request handling (`server/router/api/v1/memo_service.go:108,447`), not on any schedule.
