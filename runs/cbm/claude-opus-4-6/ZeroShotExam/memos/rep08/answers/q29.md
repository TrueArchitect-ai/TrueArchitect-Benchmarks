**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` access token to every outgoing request via the `Authorization` header, and handles 401 retries with automatic token refresh.

**Token kinds managed:**
1. **JWT access tokens** — short-lived (15 min), stored in-memory and localStorage (`memos_access_token`), sent as `Bearer` in the `Authorization` header. Managed in `web/src/auth-state.ts`.
2. **JWT refresh tokens** — long-lived (30 days), stored as an HTTP cookie (`memos_refresh`), sent via `credentials: "include"` and used to obtain new access tokens by calling `AuthService.refreshToken`.
3. **Personal Access Tokens (PAT)** — long-lived tokens prefixed `memos_pat_`, accepted as an alternative `Bearer` token for programmatic access.

**Backend validation package:** `server/auth` (specifically `server/auth/token.go` for JWT parsing via `ParseAccessTokenV2`/`ParseRefreshToken`, and `server/auth/authenticator.go` for the `Authenticator` that orchestrates validation). The server-side `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` (line 208) delegates to an `Authorizer` which calls into this package to verify incoming tokens.
