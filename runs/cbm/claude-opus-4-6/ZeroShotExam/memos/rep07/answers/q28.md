**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (plus one synchronous run at startup). Refreshes presigned URLs for S3-stored attachments. Launched in `server/server.go:162-171` via `startBackgroundRunners()`, implemented in `server/runner/s3presign/runner.go:27-41`.
- **Cache Cleanup (×3 goroutines)** — `time.NewTicker` every 5 minutes. One goroutine per cache instance (instanceSettingCache, userCache, userSettingCache). Started by `cache.New()` in `store/cache/cache.go:82`, wired in `store/store.go:51-53`.
- **Webhook Worker Pool (×4 goroutines)** — channel-driven (128-slot buffered channel). Consumes webhook POST payloads on demand. Started at process init time via Go `init()` in `internal/webhook/webhook.go:42-55`.
- **Email Worker Pool (×2 goroutines)** — channel-driven (128-slot buffered channel). Consumes async email send requests on demand. Started at process init time via Go `init()` in `internal/email/email.go:16-36`.

**Unused scheduling infrastructure:**

- **`internal/scheduler/` package** — a fully implemented cron job scheduler (11 files including parser, middleware, job registration, graceful shutdown) with zero non-test imports anywhere in the codebase. No file outside the package imports `github.com/usememos/memos/internal/scheduler`. The server uses manual `time.NewTicker` loops instead.
- **`server/runner/memopayload/` runner** — has a `Runner` struct with `NewRunner()` and `RunOnce()` for bulk memo payload rebuilds, but neither is called from the server startup path. Only the standalone `RebuildMemoPayload()` function is used inline per-request in `server/router/api/v1/memo_service.go`.
