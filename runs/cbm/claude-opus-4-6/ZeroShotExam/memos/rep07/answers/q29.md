The auth interceptor lives in `web/src/connect.ts` (the `authInterceptor` constant, line 156). It is a ConnectRPC `Interceptor` that attaches an `Authorization: Bearer <token>` header to every outgoing request, handles 401 retries by refreshing the token, and redirects on auth failure.

**Token kinds managed** (three kinds):

1. **Access tokens** — short-lived JWTs (15 min, audience `user.access-token`). Stored in-memory and `localStorage` by `web/src/auth-state.ts`. Sent as `Bearer` tokens in the `Authorization` header.
2. **Refresh tokens** — long-lived JWTs (30 days, audience `user.refresh-token`). Delivered as an HTTP-only cookie named `memos_refresh` (`server/auth/token.go:49`). Used by the interceptor via `refreshToken()` RPC to obtain fresh access tokens.
3. **Personal Access Tokens (PATs)** — random strings prefixed `memos_pat_`, SHA-256 hashed for storage. Used for programmatic API access.

**Backend validation package:** `server/auth` (`server/auth/token.go`, `server/auth/authenticator.go`, `server/auth/extract.go`). This package parses/validates JWTs with `ParseAccessTokenV2` and `ParseRefreshToken` using HMAC-SHA256 (`HS256`), verifies issuer/audience claims, and hashes PATs for database lookup.

**Summary format:** `web/src/connect.ts`; access token (JWT), refresh token (JWT cookie), personal access token (PAT); `server/auth/`
