The following database tables are affected when `DeleteMemo` runs:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`, `store/db/postgres/memo.go:246`)
2. **`memo_relation`** — relations where the memo is either source (`memo_id`) or target (`related_memo_id`) are explicitly deleted in `store/memo.go:142-146` via `DeleteMemoRelation`
3. **`attachment`** — attachments linked to the memo are explicitly deleted in `store/memo.go:149-156` via `DeleteAttachment`
4. **`memo_share`** — rows referencing the memo are cascade-deleted via `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql`, `store/migration/postgres/LATEST.sql`, `store/migration/mysql/LATEST.sql`)

Additionally, the service layer at `server/router/api/v1/memo_service.go:567-577` recursively deletes **comment memos** (memos related via `MemoRelationComment`), which triggers the same cascade for each comment — affecting the same four tables for each child memo.

**Table list: `memo`, `memo_relation`, `attachment`, `memo_share`**
