**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` access token to every outgoing request's `Authorization` header, and reactively refreshes it on `Unauthenticated` errors.

**Token kinds:** Three token types are managed:
1. **JWT access tokens** — short-lived (15 min), stored in-memory and localStorage by `web/src/auth-state.ts`, sent as `Bearer` in the `Authorization` header.
2. **JWT refresh tokens** — long-lived (30 days), stored as an HTTP cookie (`memos_refresh`), used to obtain new access tokens via `refreshToken()` RPC.
3. **Personal Access Tokens (PAT)** — long-lived, prefixed `memos_pat_`, for programmatic access; also sent as `Bearer` tokens.

**Backend package path:** `server/auth` — the `Authenticator` struct (`server/auth/authenticator.go`) validates all three token kinds: `ParseAccessTokenV2` and `ParseRefreshToken` for JWT verification (`server/auth/token.go`), and `AuthenticateByPAT` for personal access tokens, all using HS256 signing with a server secret.
