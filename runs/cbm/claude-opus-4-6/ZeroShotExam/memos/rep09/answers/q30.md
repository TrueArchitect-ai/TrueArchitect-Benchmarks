Four memo lifecycle events dispatch webhooks:

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

All four are defined in `server/router/api/v1/memo_service_webhooks.go`. The first three converge through the shared helper `dispatchMemoRelatedWebhook` (same file, line 48), while `DispatchMemoCommentCreatedWebhook` (line 30) inlines similar logic directly.

All of them ultimately call `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload onto a buffered channel (`asyncPostQueue`). Worker goroutines (spawned in `init()`, line 42) drain that channel and call the synchronous delivery function `webhook.Post` (`internal/webhook/webhook.go:120`), which is the single convergence point where every webhook is actually delivered via HTTP POST.

**Delivery function:** `Post` in `internal/webhook/webhook.go` (line 120), reached asynchronously via `PostAsync` (line 184).
