When `DeleteMemo` runs, the following database tables are affected:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`, `store/db/postgres/memo.go:246`)
2. **`memo_relation`** — all relation records where the memo is either source (`memo_id`) or target (`related_memo_id`) are deleted (`store/memo.go:142-146`, `store/db/sqlite/memo_relation.go:149`)
3. **`attachment`** — all attachments linked to the memo are deleted (`store/memo.go:149-157`, `store/db/sqlite/attachment.go:212`)
4. **`memo_share`** — rows referencing the memo are cascade-deleted via the `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` constraint (`store/migration/sqlite/LATEST.sql:109`)

Additionally, the service layer (`server/router/api/v1/memo_service.go:567-577`) explicitly deletes **comment memos** first by listing `memo_relation` rows of type `Comment` pointing to the memo, then recursively calling `DeleteMemo` on each comment — which in turn triggers the same cascade on `memo`, `memo_relation`, `attachment`, and `memo_share` for each comment.

**Table list:** `memo`, `memo_relation`, `attachment`, `memo_share`
