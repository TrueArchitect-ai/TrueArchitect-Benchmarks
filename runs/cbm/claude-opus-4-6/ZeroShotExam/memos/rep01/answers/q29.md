**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` token to every outgoing request's `Authorization` header and handles 401 retries with automatic token refresh.

**Token kinds managed:**
1. **Access token (JWT)** — short-lived (15 min), stored in localStorage and in-memory via `web/src/auth-state.ts`. Sent as `Bearer <token>` on every request. Validated statelessly by signature on the backend.
2. **Refresh token (JWT)** — long-lived (30 days), stored as an HTTP cookie (`memos_refresh`). Used by the interceptor to obtain a new access token when the current one expires or a 401 is received (calls `AuthService.refreshToken`).
3. **Personal Access Token (PAT)** — long-lived programmatic tokens prefixed `memos_pat_`, also sent as a Bearer token. Validated against a SHA-256 hash stored in the database.

**Backend package that validates them:** `server/auth` (files `server/auth/token.go` and `server/auth/authenticator.go`). The `Authenticator` struct exposes `AuthenticateByAccessTokenV2` (stateless JWT parse via `ParseAccessTokenV2`), `AuthenticateByRefreshToken` (JWT parse + database revocation check via `ParseRefreshToken`), and `AuthenticateByPAT` (hash lookup). These are consumed by the gRPC/Connect interceptors in `server/router/api/v1`.
