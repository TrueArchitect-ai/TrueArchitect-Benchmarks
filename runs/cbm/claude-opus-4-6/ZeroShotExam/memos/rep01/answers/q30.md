Four memo lifecycle events dispatch webhooks:

- **created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

All defined in `server/router/api/v1/memo_service_webhooks.go`.

The first three converge through the shared helper `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator, fetches their webhooks, and calls `webhook.PostAsync`. The comment event (`DispatchMemoCommentCreatedWebhook`, line 30) follows the same pattern inline (fetches webhooks for the related memo's creator and calls `webhook.PostAsync` directly) rather than going through `dispatchMemoRelatedWebhook`.

All four ultimately converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues payloads onto a buffered channel (`asyncPostQueue`). Four goroutines (started in `init()`, line 42) drain that channel and call `webhook.Post` (`internal/webhook/webhook.go:120`) for the actual HTTP delivery.

**Delivery function/path:** `webhook.Post` at `internal/webhook/webhook.go:120`
