**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` token to every outgoing request's `Authorization` header and handles 401 retry-with-refresh logic.

**Token kinds managed (three):**
1. **JWT access tokens** — short-lived (15 min), stored in-memory and localStorage (`web/src/auth-state.ts`), sent as `Bearer` in the `Authorization` header. Audience `user.access-token`.
2. **JWT refresh tokens** — long-lived (30 days), sent as an HTTP cookie (`memos_refresh`), used to obtain fresh access tokens via `AuthService.refreshToken`.
3. **Personal Access Tokens (PAT)** — long-lived tokens prefixed `memos_pat_`, also sent as `Bearer` tokens for programmatic access.

**Backend validation package:** `server/auth` (`server/auth/token.go` and `server/auth/authenticator.go`). The `Authenticator` struct validates all three token types: `ParseAccessTokenV2` for access tokens, `ParseRefreshToken` for refresh tokens, and `AuthenticateByPAT` (SHA-256 hash lookup) for PATs.
