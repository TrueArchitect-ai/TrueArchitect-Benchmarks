Four memo lifecycle events dispatch webhooks:

- **memo created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **memo updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **memo deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **memo comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

All four are defined in `server/router/api/v1/memo_service_webhooks.go`. The first three converge through the private helper `dispatchMemoRelatedWebhook` (same file, line 48), while `DispatchMemoCommentCreatedWebhook` (line 30) inlines similar logic but skips the creator-resolution step (it receives the creator ID directly).

All of them ultimately call `webhook.PostAsync()` (`internal/webhook/webhook.go:184`), which enqueues the payload onto a buffered channel (`asyncPostQueue`). Four goroutines (spawned in `init()`, line 42) drain that channel and each invocation calls the synchronous `webhook.Post()` (`internal/webhook/webhook.go:120`) — the single delivery function where all webhook dispatches converge to make the actual HTTP POST.

**Summary:**

| Event | Dispatch function |
|---|---|
| memo created | `DispatchMemoCreatedWebhook` |
| memo updated | `DispatchMemoUpdatedWebhook` |
| memo deleted | `DispatchMemoDeletedWebhook` |
| memo comment created | `DispatchMemoCommentCreatedWebhook` |

**Delivery convergence:** `webhook.Post` in `internal/webhook/webhook.go` (invoked via `webhook.PostAsync` → `asyncPostQueue` channel → `Post`).
