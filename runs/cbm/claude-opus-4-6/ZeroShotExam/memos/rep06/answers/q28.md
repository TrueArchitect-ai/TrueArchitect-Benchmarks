**Background workers the server actually starts:**

- **S3 Presign Runner** — 12-hour `time.NewTicker`; started by `Server.startBackgroundRunners()` in `server/server.go:153-173`, runs immediately then every 12 hours to re-sign expiring S3 URLs (`server/runner/s3presign/runner.go`)
- **Webhook Async Workers (×4)** — channel-driven (`asyncPostQueue`, buffered 128); started via `init()` in `internal/webhook/webhook.go:42-55`, goroutines pull webhook HTTP posts off the channel
- **Email Async Workers (×2)** — channel-driven (`asyncEmailQueue`, buffered 128); started via `init()` in `internal/email/email.go:17-36`, goroutines pull SMTP sends off the channel
- **Cache Cleanup Goroutines (×3)** — 5-minute `time.NewTicker`; started by `cache.New()` in `store/cache/cache.go:83`, one per cache (settings, users, user-settings), instantiated from `store/store.go:51-53`
- **SSE Heartbeat Tickers** — 30-second `time.NewTicker` per SSE client connection (`server/router/api/v1/sse_handler.go`)
- **PAT Usage Recorder** — fire-and-forget goroutine per personal-access-token authentication (`server/auth/authenticator.go:180`)

**Scheduling infrastructure present but NOT used by the server:**

- **`internal/scheduler/`** — A full-featured cron job scheduler (cron-expression parsing, timezone support, middleware chain with recovery/logging/timeout, graceful shutdown). It is **never imported by any production code** — only by its own test files (`example_test.go`, `integration_test.go`). The actual recurring background work (S3 presign runner) uses a plain `time.NewTicker` loop instead.
- **Memo Payload Runner (`server/runner/memopayload/runner.go`)** — Has a `Runner` struct with a batch `RunOnce()` method designed for background use, but it is **never started as a background worker**. Only its standalone `RebuildMemoPayload()` function is called synchronously inline during memo create/update in `server/router/api/v1/memo_service.go:108,447`.
