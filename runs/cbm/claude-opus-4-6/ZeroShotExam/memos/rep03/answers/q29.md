**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` access token to every outgoing request via the `Authorization` header, and reactively retries with a refreshed token on `Unauthenticated` errors.

**Token kinds managed:**
1. **JWT access tokens** — short-lived (15 min), stored in localStorage and in-memory (`web/src/auth-state.ts`), sent as `Bearer` in the `Authorization` header.
2. **JWT refresh tokens** — long-lived (30 days), stored as an HTTP cookie (`memos_refresh`), sent via `credentials: "include"` and used to obtain new access tokens through `AuthService.refreshToken`.
3. **Personal Access Tokens (PAT)** — long-lived tokens prefixed `memos_pat_`, also sent as `Bearer` tokens for programmatic access.

**Backend package that validates them:** `server/auth` (package `auth`, rooted at `server/auth/token.go` and `server/auth/authenticator.go`). The `Authenticator` struct validates access tokens statelessly via `ParseAccessTokenV2`, validates refresh tokens against the database via `AuthenticateByRefreshToken`, and validates PATs by SHA-256 hash lookup via `AuthenticateByPAT`.
