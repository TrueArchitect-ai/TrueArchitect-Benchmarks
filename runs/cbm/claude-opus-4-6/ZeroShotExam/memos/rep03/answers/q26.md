When `DeleteMemo` runs, the following database tables are affected:

1. **`memo`** — the memo row itself is deleted (`store/db/sqlite/memo.go:239`, `store/db/postgres/memo.go:246`).
2. **`memo_relation`** — relations where the memo is either `memo_id` or `related_memo_id` are explicitly deleted in `store/memo.go:142-146`.
3. **`attachment`** — attachments linked to the memo are explicitly deleted in `store/memo.go:149-156` (via `s.driver.DeleteAttachment`).
4. **`memo_share`** — rows are removed by the database's `ON DELETE CASCADE` foreign key on `memo_id` (defined in `store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`, `store/migration/mysql/LATEST.sql:108`).

Additionally, the API-level handler (`server/router/api/v1/memo_service.go:567-577`) first recursively deletes **comment memos** (memos related via `MemoRelationComment`), each of which triggers the same cascade on the above four tables.

**Table list:** `memo`, `memo_relation`, `attachment`, `memo_share`
