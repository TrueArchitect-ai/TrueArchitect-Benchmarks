Four memo lifecycle events dispatch webhooks:

- **created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

All defined in `server/router/api/v1/memo_service_webhooks.go`.

The first three converge through the private helper `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator, fetches their webhooks, and calls `webhook.PostAsync`. `DispatchMemoCommentCreatedWebhook` builds the payload inline but also calls `webhook.PostAsync`.

All four ultimately converge for delivery at **`webhook.Post`** in `internal/webhook/webhook.go:120`. `PostAsync` (line 184) enqueues payloads onto a buffered channel (`asyncPostQueue`), and background goroutines (started in `init()`, line 42) drain that channel by calling `Post`, which performs the actual HTTP POST to the webhook endpoint.
