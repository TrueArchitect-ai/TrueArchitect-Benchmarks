**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` at 12-hour interval (plus one immediate `RunOnce` at startup). Defined in `server/runner/s3presign/runner.go`, launched from `server/server.go:startBackgroundRunners`
- **Webhook dispatch workers (×4)** — channel-driven (`asyncPostQueue`, buffered 128). Started via `init()` in `internal/webhook/webhook.go`; goroutines consume from the channel whenever `PostAsync()` is called
- **Email send workers (×2)** — channel-driven (`asyncEmailQueue`, buffered 128). Started via `init()` in `internal/email/email.go`; goroutines consume from the channel whenever `SendAsync()` is called
- **Cache cleanup goroutines (×3)** — `time.NewTicker` at 5-minute `CleanupInterval` for each of the three caches (instanceSettingCache, userCache, userSettingCache) created in `store/store.go:51-53`, cleanup loop in `store/cache/cache.go:200`

**Unused scheduling infrastructure:** The `internal/scheduler/` package provides a full cron-expression-based job scheduler (with `Scheduler`, `Job`, cron parser, and middleware support), but it is **not imported or used by the server or any production code**. Similarly, `server/runner/memopayload/` defines a `Runner` with `RunOnce`, but it is never started as a background worker — its `RebuildMemoPayload` function is only called inline from memo service handlers (`server/router/api/v1/memo_service.go`), not as a scheduled runner.
