**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` token to every outgoing request's `Authorization` header and handles 401 retry-with-refresh logic.

**Token kinds managed (three):**
1. **JWT access tokens** — short-lived (15 min), stored in-memory and `localStorage` (`memos_access_token`), set via `Bearer` header. Defined in `web/src/auth-state.ts`.
2. **JWT refresh tokens** — long-lived (30 days), sent as an HTTP cookie (`memos_refresh`), used to obtain new access tokens via `AuthService.refreshToken`.
3. **Personal Access Tokens (PAT)** — long-lived programmatic tokens prefixed `memos_pat_`, also sent as `Bearer` tokens.

**Backend package that validates them:** `server/auth` (`server/auth/token.go` and `server/auth/authenticator.go`). The `Authenticator` struct validates all three token types: `ParseAccessTokenV2` for access tokens, `ParseRefreshToken` for refresh tokens, and `AuthenticateByPAT` (SHA-256 hash lookup) for personal access tokens — all using HS256/JWT via `github.com/golang-jwt/jwt/v5`.
