**Memo lifecycle events that dispatch webhooks:**

- **created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

All four are defined in `server/router/api/v1/memo_service_webhooks.go`. The first three converge through the private helper `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator's webhooks and calls `webhook.PostAsync`. The comment event (`DispatchMemoCommentCreatedWebhook`) calls `webhook.PostAsync` directly (line 43) rather than going through `dispatchMemoRelatedWebhook`, but all four ultimately converge on:

**`webhook.Post`** in `internal/webhook/webhook.go:120`

`PostAsync` (line 184) enqueues payloads onto `asyncPostQueue`, a buffered channel consumed by 4 goroutines (spawned in `init()`, line 42), each of which calls `Post`. So `Post` at `internal/webhook/webhook.go` is the single delivery function where all webhook dispatches converge for actual HTTP delivery.
