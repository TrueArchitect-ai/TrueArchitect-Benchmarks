**Background workers/runners the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (`server/runner/s3presign/runner.go:27`); launched in `server/server.go:166-171` via `startBackgroundRunners()`. Re-signs S3 attachment URLs approaching expiry.
- **Webhook Async Workers (×4)** — 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), consuming from a buffered channel (cap 128). Driven by `PostAsync()` calls when memos are created/updated/deleted.
- **Email Async Workers (×2)** — 2 goroutines started in `init()` (`internal/email/email.go:16-36`), consuming from a buffered channel (cap 128). Driven by `SendAsync()` calls for inbox notification emails.
- **Cache Cleanup (×3)** — 3 goroutines (one per cache: instance settings, users, user settings), each using `time.NewTicker` every 5 minutes (`store/cache/cache.go:77-85`). Started when the store is created in `store/store.go:38-61`.
- **SSE Heartbeat Loops (per connection)** — each active SSE client runs a `time.NewTicker` every 30 seconds (`server/router/api/v1/sse_handler.go:16, 64-109`). Not a fixed worker; one per connected client.

**Unused scheduling infrastructure:** The `internal/scheduler/` package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) is a fully-implemented cron scheduler with cron expression parsing, middleware (recovery/logging/timeout), job registration, and graceful shutdown — but it is **not imported or used anywhere** outside its own package and tests. No production code wires it into the server startup.
