The filter expression uses **CEL (Common Expression Language)** syntax, parsed by `google/cel-go`. The engine lives at `internal/filter/` — specifically `engine.go` (compilation), `parser.go` (AST-to-IR), and `render.go` (SQL generation).

The CEL expression is compiled into a dialect-agnostic condition tree (IR defined in `internal/filter/ir.go`), then `Render()` in `internal/filter/render.go` walks that tree and emits dialect-specific SQL fragments (placeholders, type casts, function names) by switching on a `DialectName` (`DialectSQLite`, `DialectPostgres`, `DialectMySQL`), which each DB driver passes via `filter.AppendConditions()` (e.g., `store/db/sqlite/memo.go:61`, `store/db/postgres/memo.go:58`, `store/db/mysql/memo.go:69`).

**Engine + path:** CEL (`google/cel-go`) in `internal/filter/`; **mechanism:** the engine compiles the CEL filter string into a dialect-agnostic IR condition tree (`parser.go`), then a renderer (`render.go`) walks that tree and emits SQL by switching on the dialect constant (`DialectSQLite`/`DialectPostgres`/`DialectMySQL`) passed by each store driver.
