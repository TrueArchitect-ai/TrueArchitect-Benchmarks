**Workers the server actually starts:**

- **S3 Presign Runner** — `time.NewTicker` every 12 hours (plus one immediate `RunOnce` at startup). Refreshes expiring S3 presigned URLs. Started in `server/server.go:153-173`, runner defined in `server/runner/s3presign/runner.go:27-41`.

- **Cache Cleanup (x3 goroutines)** — `time.NewTicker` every 5 minutes. One goroutine per cache instance (instanceSettingCache, userCache, userSettingCache). Evicts expired entries. Started via `store/cache/cache.go:83` when `store.New()` creates each cache (`store/store.go:51-53`).

- **Webhook Dispatch Workers (x4 goroutines)** — event-driven, consuming from a buffered channel (`asyncPostQueue`, capacity 128). Fire HTTP POSTs for webhook payloads on memo create/update/delete. Started in `init()` at `internal/webhook/webhook.go:42-55`.

- **Email Dispatch Workers (x2 goroutines)** — event-driven, consuming from a buffered channel (`asyncEmailQueue`, capacity 128). Send SMTP emails asynchronously. Started in `init()` at `internal/email/email.go:16-36`.

**Unused scheduling infrastructure:**

- The `internal/scheduler/` package is a fully implemented cron-based job scheduler with cron expression parsing (`parser.go`), middleware support (recovery, logging, timeout in `middleware.go`), timezone handling, and graceful shutdown (`scheduler.go`, `job.go`). It is **never imported by any production code** — only by its own test files (`example_test.go`, `integration_test.go`). The server uses simple `time.NewTicker` loops instead.

- The `server/runner/memopayload/` package defines a `Runner` struct with `NewRunner()` and `RunOnce()` methods for batch-rebuilding memo payloads, but the **Runner is never instantiated or started** by the server. Only the standalone function `memopayload.RebuildMemoPayload()` is called inline during individual API requests (`server/router/api/v1/memo_service.go:108,447`).
