Four memo lifecycle events dispatch webhooks:

- **created**: `DispatchMemoCreatedWebhook` (activity type `memos.memo.created`)
- **updated**: `DispatchMemoUpdatedWebhook` (activity type `memos.memo.updated`)
- **deleted**: `DispatchMemoDeletedWebhook` (activity type `memos.memo.deleted`)
- **comment created**: `DispatchMemoCommentCreatedWebhook` (activity type `memos.memo.comment.created`)

All defined in `server/router/api/v1/memo_service_webhooks.go`.

The first three converge through the private helper `dispatchMemoRelatedWebhook` (same file, line 48), which resolves the memo creator's webhooks and calls `webhook.PostAsync`. `DispatchMemoCommentCreatedWebhook` bypasses that helper but also calls `webhook.PostAsync` directly.

All four ultimately converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues the payload into `asyncPostQueue`. Worker goroutines (spawned in `init()`, line 42) drain that channel and call **`webhook.Post`** (`internal/webhook/webhook.go:120`) — the single delivery function where every webhook is actually sent via HTTP POST.

**Summary:**

| Event | Dispatch function |
|---|---|
| memo created | `DispatchMemoCreatedWebhook` |
| memo updated | `DispatchMemoUpdatedWebhook` |
| memo deleted | `DispatchMemoDeletedWebhook` |
| comment created | `DispatchMemoCommentCreatedWebhook` |

Delivery convergence: `webhook.PostAsync` → `webhook.Post` in `internal/webhook/webhook.go`.
