**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` access token to the `Authorization` header of every outgoing request, handles 401 retry with token refresh, and redirects on auth failure.

**Token kinds managed:**
1. **JWT access tokens** — short-lived (15 min), stored in-memory and localStorage, sent as `Bearer` in the `Authorization` header. Managed via `web/src/auth-state.ts`.
2. **JWT refresh tokens** — long-lived (30 days), stored as an HTTP cookie (`memos_refresh`), used to obtain new access tokens via `AuthService.refreshToken`.
3. **Personal Access Tokens (PAT)** — long-lived tokens prefixed with `memos_pat_`, also sent as `Bearer` tokens for programmatic access.

**Backend package that validates them:** `server/auth` (Go package at `server/auth/`). The `Authenticator` struct in `server/auth/authenticator.go` validates all three token types: `AuthenticateByAccessTokenV2` for stateless JWT access token validation, `AuthenticateByRefreshToken` for database-checked refresh tokens, and `AuthenticateByPAT` for personal access tokens. The server-side Connect interceptor that invokes this authenticator is `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go` (line 208).
