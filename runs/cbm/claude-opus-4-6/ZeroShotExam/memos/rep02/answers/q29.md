**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (line 156) is a ConnectRPC `Interceptor` that attaches a `Bearer` access token to every outgoing request's `Authorization` header, and handles 401 retries by refreshing the token.

**Token kinds managed:**
1. **Access tokens** (short-lived JWT, 15-minute lifetime) — stored in-memory and localStorage (`memos_access_token`), managed via `web/src/auth-state.ts`. Set as `Authorization: Bearer <token>` on each request.
2. **Refresh tokens** (long-lived JWT, 30-day lifetime) — sent as an HTTP-only cookie (`memos_refresh`), used to obtain new access tokens via the `AuthService.refreshToken` RPC.
3. **Personal Access Tokens (PAT)** — long-lived opaque tokens prefixed `memos_pat_`, validated by SHA-256 hash lookup (for programmatic API access).

**Backend validation package:** `server/auth` (`server/auth/token.go`) — this Go package defines token generation and parsing (`ParseAccessTokenV2`, `ParseRefreshToken`, `verifyJWTKeyFunc`) using HS256 JWTs via `github.com/golang-jwt/jwt/v5`. The gRPC/Connect interceptors in `server/router/api/v1/` call into this package to authenticate inbound requests.
