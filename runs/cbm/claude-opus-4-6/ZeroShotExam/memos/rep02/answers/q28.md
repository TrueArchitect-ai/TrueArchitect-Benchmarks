**Background workers/runners the server starts:**

- **S3 Presign Runner** — `time.Ticker` every 12 hours (`server/runner/s3presign/runner.go:27`). Started explicitly in `server.Server.startBackgroundRunners()` (`server/server.go:162-171`). Re-presigns S3 attachment URLs before they expire.

- **Webhook Worker Pool (4 goroutines)** — event-driven via a buffered channel (`asyncPostQueue`, capacity 128). Started at package `init()` time (`internal/webhook/webhook.go:42-54`). Each goroutine consumes webhook POST requests enqueued by `PostAsync()`.

- **Email Worker Pool (2 goroutines)** — event-driven via a buffered channel (`asyncEmailQueue`, capacity 128). Started at package `init()` time (`internal/email/email.go:14-36`). Each goroutine consumes email send requests enqueued by `SendAsync()`.

- **Cache Cleanup Loops (3 goroutines)** — `time.Ticker` every 5 minutes (`store/store.go:42`). One goroutine per cache instance (`instanceSettingCache`, `userCache`, `userSettingCache`), spawned inside `cache.New()` (`store/cache/cache.go:83`).

**Unused scheduling infrastructure:** The `internal/scheduler/` package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) implements a full cron-expression-based job scheduler with middleware support (recovery, logging, timeout), but it is **not imported or used anywhere in production code** — only by its own test files (`example_test.go`, `integration_test.go`). It is never wired into the server startup.
