**Engine:** Google CEL (Common Expression Language) via `github.com/google/cel-go/cel`; **Path:** `internal/filter/engine.go` (engine), `internal/filter/schema.go` (CEL variable declarations), `internal/filter/parser.go` (AST-to-IR), `internal/filter/render.go` (IR-to-SQL).

**Mechanism:** The `Engine.Compile` method parses the filter string into a CEL AST, then `buildCondition` (`parser.go`) converts that AST into a dialect-agnostic intermediate condition tree (IR types defined in `ir.go`), and `Program.Render` (`render.go`) walks that condition tree and emits dialect-specific SQL fragments by switching on `RenderOptions.Dialect` (SQLite, Postgres, or MySQL) at each node — producing the appropriate placeholder style (`?` vs `$N`), JSON operators (`JSON_EXTRACT` vs `->>`/`@>`), case-folding (`memos_unicode_lower`/`ILIKE`/`LIKE`), date-part extraction (`strftime`/`EXTRACT`/`YEAR()`), and array functions per dialect.
