The following database tables are affected when `DeleteMemo` runs:

1. **`memo_relation`** — The store-level `DeleteMemo` (`store/memo.go:140-147`) explicitly deletes from `memo_relation` twice: once where the memo is the source (`MemoID`) and once where it is the target (`RelatedMemoID`). The driver executes `DELETE FROM memo_relation` (`store/db/sqlite/memo_relation.go:148-150`).

2. **`attachment`** — The store-level `DeleteMemo` (`store/memo.go:149-157`) lists all attachments linked to the memo and deletes each one. The driver executes `DELETE FROM attachment` (`store/db/sqlite/attachment.go:212`).

3. **`memo`** — Finally, the driver's `DeleteMemo` executes `DELETE FROM memo` (`store/db/sqlite/memo.go:239`).

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (related via `MemoRelationComment`) are deleted recursively by calling `store.DeleteMemo` for each comment — which in turn cascades through the same three tables for each comment memo.

**Table list: `memo`, `memo_relation`, `attachment`**
