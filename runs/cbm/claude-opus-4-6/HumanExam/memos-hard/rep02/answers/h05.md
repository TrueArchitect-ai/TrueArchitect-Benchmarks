The `deleteUserTargetsTx` function in each DB driver explicitly deletes reactions in two passes: (1) `deleteReactionsByContentIDsTx` removes reactions on the user's memos (e.g., `store/db/mysql/user_delete.go:96`), and (2) `deleteReactionsByCreatorTx` removes reactions the user created on any content (e.g., `store/db/mysql/user_delete.go:102`). The same pattern exists in `store/db/postgres/user_delete.go` and `store/db/sqlite/user_delete.go`. The `reaction` table schema in all three backends (`store/migration/*/LATEST.sql`) has no FOREIGN KEY or ON DELETE CASCADE.
