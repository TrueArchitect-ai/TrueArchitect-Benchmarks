The following tables are affected when `DeleteMemo` runs:

- `memo_relation` — explicitly deleted in `store/memo.go:142-146` (both as source and target)
- `attachment` — explicitly deleted in `store/memo.go:149-156`
- `memo` — the memo row itself, deleted in `store/memo.go:158` via the driver
- `memo_share` — cascade-deleted via `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql`)

Additionally, at the API layer (`server/router/api/v1/memo_service.go:567-577`), comment memos (child memos linked via `memo_relation`) are recursively deleted first, which triggers the same cleanup on their own `memo_relation`, `attachment`, `memo_share`, and `memo` rows.
