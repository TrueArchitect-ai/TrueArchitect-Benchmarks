The premise is incorrect — there is no Redis connection in this codebase. The cache layer is an in-memory implementation, not Redis-backed.

The cache is defined in `store/cache/cache.go` as a generic in-memory `Cache` struct using a `sync.Map` with a background cleanup goroutine. It is instantiated in `store/store.go` where the `Store` struct holds three cache instances: `userCache`, `userSettingCache`, and `instanceSettingCache`.

There is no configurable per-entry TTL for user entries specifically. The `Cache` struct uses a single TTL for all entries, set at construction time. Looking at how `userCache` is created in `store/store.go`, whatever TTL is passed to `cache.New()` applies uniformly to all cached users — it is not user-entry-specific or Redis-based.
