Explicit Go code; reactions are removed in two ways within the `deleteUserTargetsTx` function during the user-delete transaction:

1. **`deleteReactionsByContentIDsTx`** (`store/db/sqlite/user_delete.go:96`, line 380–388) — deletes all reactions on the user's memos (by content ID derived from memo UIDs).
2. **`deleteReactionsByCreatorTx`** (`store/db/sqlite/user_delete.go:102`, line 400–403) — deletes all reactions the user themselves created (`DELETE FROM reaction WHERE creator_id = ?`).

The same pattern is present in all three driver implementations: `store/db/sqlite/user_delete.go`, `store/db/postgres/user_delete.go`, and `store/db/mysql/user_delete.go`. There are no `ON DELETE CASCADE` foreign-key constraints handling this — it is done entirely via explicit SQL `DELETE` statements in Go code within a transaction.
