The premise is incorrect — there is no message broker (neither NATS nor RabbitMQ). The webhook delivery workers consume from a plain **in-memory Go buffered channel** (`asyncPostQueue`), declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are started in `init()` (`internal/webhook/webhook.go:42–55`) that range over this channel, calling `Post()` for each payload. Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184`), which performs a non-blocking send and drops the event if the 128-slot buffer is full. There is no external queue or broker involved.
