**Delivery function** — `Post` — `internal/webhook/webhook.go:120`

The `Post` function marshals the payload to JSON, constructs an HTTP POST request (optionally HMAC-signing it), and sends it via `safeClient`. Asynchronous dispatch goes through `PostAsync` (`webhook.go:184`), which enqueues onto a buffered channel consumed by 4 background goroutines that each call `Post`.

**Protection mechanism** — SSRF guard via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`

Two layers protect against internal network targeting:

1. **At dial time** (`safeDialContext`, `webhook.go:59`): The custom `http.Transport` resolves the hostname and checks every resolved IP against `reservedNetworks` (loopback, RFC-1918, link-local/cloud IMDS, IPv6 equivalents) before allowing the TCP connection. This defeats DNS rebinding because the check happens at the moment of connection, not just at registration time.

2. **At registration time** (`ValidateURL`, `validate.go:62`): When a user creates or updates a webhook, the URL is resolved and checked against the same reserved CIDR list, rejecting it with a gRPC `InvalidArgument` error before it's ever stored.

The reserved CIDR list is defined in `validate.go:14-23` and parsed once at init (`validate.go:28`).
