Explicit Go code; reactions are removed in two ways within the same transaction during user deletion:

1. **Reactions on the user's memos** are deleted by `deleteReactionsByContentIDsTx` (`store/db/sqlite/user_delete.go:380`), which issues `DELETE FROM reaction WHERE content_id IN (...)` using the content IDs derived from the user's memo UIDs (line 96).

2. **Reactions created by the user** (including on other users' memos) are deleted by `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:400`), which issues `DELETE FROM reaction WHERE creator_id = ?` (line 401, called at line 102).

Both are called from `deleteUserTargetsTx` (`store/db/sqlite/user_delete.go:92–104`) inside the `DeleteUser` transaction. The same pattern exists in the MySQL (`store/db/mysql/user_delete.go`) and Postgres (`store/db/postgres/user_delete.go`) drivers. There are no database-level `ON DELETE CASCADE` foreign keys involved — it is all explicit Go code issuing direct SQL DELETEs within a transaction.
