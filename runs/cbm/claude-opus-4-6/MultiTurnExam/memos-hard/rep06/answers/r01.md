The premise is incorrect — there is no Redis connection. The cache layer is entirely **in-memory**, implemented as a `sync.Map`-backed cache in `store/cache/cache.go`. There is no Redis dependency anywhere in the codebase (no imports, no configuration).

The `Cache` struct (`store/cache/cache.go:67`) uses a `Config` with a `DefaultTTL`. The default configuration (`DefaultConfig()` at line 57) sets a **10-minute TTL** for all entries, including user entries. The user cache is created in `store/store.go` using this in-memory cache, and `Store.GetUser` (`store/user.go:148`) populates it via `s.userCache.Set()`, which applies the default 10-minute TTL. There is no per-type TTL differentiation — all caches (user, user settings, instance settings) share the same default configuration.
