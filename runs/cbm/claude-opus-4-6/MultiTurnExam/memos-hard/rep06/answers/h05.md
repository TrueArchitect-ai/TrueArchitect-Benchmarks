Explicit Go code; reactions are removed by two dedicated functions within the `DeleteUser` transaction across all three database drivers:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions whose `content_id` matches any of the user's memos (by memo UID). See `store/db/sqlite/user_delete.go:380`, `store/db/mysql/user_delete.go:417`, `store/db/postgres/user_delete.go:380`.

2. **`deleteReactionsByCreatorTx`** — deletes reactions where `creator_id` matches the deleted user. See `store/db/sqlite/user_delete.go:400`, `store/db/mysql/user_delete.go:437`, `store/db/postgres/user_delete.go:400`.

Both are called from `deleteUserTargetsTx` in each driver (e.g., `store/db/sqlite/user_delete.go:96-103`), which runs inside a transaction. There are no database-level foreign key cascades involved — the cleanup is entirely in application-level Go code issuing explicit `DELETE FROM reaction` statements.
