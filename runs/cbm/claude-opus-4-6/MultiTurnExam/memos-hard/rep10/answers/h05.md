Reactions are removed by **explicit Go code**, via two separate deletion steps within the user-delete transaction. In each database driver's `deleteUserTargetsTx` function:

1. **`deleteReactionsByContentIDsTx`** — deletes reactions whose `content_id` matches any of the user's memos (by memo UID). See `store/db/sqlite/user_delete.go:96`, `store/db/mysql/user_delete.go:96`, `store/db/postgres/user_delete.go:96`.

2. **`deleteReactionsByCreatorTx`** — deletes reactions where `creator_id` matches the deleted user (i.e., reactions the user themselves placed on other content). See `store/db/sqlite/user_delete.go:102`, `store/db/mysql/user_delete.go:102`, `store/db/postgres/user_delete.go:102`.

Both are explicit `DELETE FROM reaction WHERE ...` SQL statements executed in Go, not database-level cascading foreign keys. The actual SQL can be seen in functions like `deleteReactionsByContentIDsTx` (`store/db/sqlite/user_delete.go:380–388`) and `deleteReactionsByCreatorTx` (`store/db/sqlite/user_delete.go:400–402`), with identical patterns in the MySQL and Postgres drivers.
