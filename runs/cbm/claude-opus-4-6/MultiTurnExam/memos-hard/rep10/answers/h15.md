Memo visibility is enforced at these distinct sites:

1. **`checkMemoReadAccess`** (single-memo reads) — `server/router/api/v1/memo_service.go:39` — Called by `GetMemo` (line 356) and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`). Blocks unauthenticated access to non-public memos and restricts private memos to their creator.

2. **`ListMemos` query-level filtering** — `server/router/api/v1/memo_service.go:218–227` — Injects visibility constraints into the database query: anonymous users see only `PUBLIC`; authenticated users viewing others' memos see `PUBLIC`+`PROTECTED`; own memos are unfiltered.

3. **`checkAttachmentPermission`** (file serving) — `server/router/fileserver/fileserver.go:674–701` — Enforces visibility when serving attachment files via HTTP: checks `memo.Visibility` against the requesting user, with share-token fallback for shared memos.

4. **`SSEClient.canReceive`** (real-time events) — `server/router/api/v1/sse_hub.go:134` — Filters SSE event delivery: private memo events are only delivered to the creator or admins.

5. **`ListMemoReactions` / `UpsertReaction`** (reaction service) — `server/router/api/v1/reaction_service.go:30–41` and `:82–85` — Checks memo visibility before listing or creating reactions on a memo.

6. **`CreateMemoComment`** (comment service) — `server/router/api/v1/memo_service_comments.go:41` — Blocks commenting on private memos by non-owners.

7. **RSS feed** — `server/router/rss/rss.go:90,141` — Restricts RSS output to `Public`-only memos via `VisibilityList` filter.

8. **`GetUserMemoStats` / `GetUserTagStats`** — `server/router/api/v1/user_service_stats.go:84–90,218–220` — Applies visibility filtering when computing per-user memo and tag statistics.
