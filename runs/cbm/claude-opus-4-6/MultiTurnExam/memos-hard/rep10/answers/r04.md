The premise is incorrect — there is no message broker (NATS, RabbitMQ, or otherwise) involved in webhook delivery. The webhook workers consume from a plain Go buffered channel, not an external message queue.

The "queue" is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the package's `init()` function (`internal/webhook/webhook.go:42–55`) that range over this channel and call `Post()` for each payload. Producers enqueue work via `PostAsync()` (`internal/webhook/webhook.go:184`), which performs a non-blocking send on the channel, dropping the event if the buffer is full. The entire mechanism is in-process with no external dependencies.
