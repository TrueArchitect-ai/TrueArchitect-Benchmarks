**Protection mechanism — `safeDialContext`** in `internal/webhook/webhook.go:59`, backed by SSRF validation in `internal/webhook/validate.go`. Two layers work together:

1. **At dial time (runtime SSRF guard):** The `safeClient` HTTP client uses a custom `Transport` whose `DialContext` is `safeDialContext` (line 35). This function resolves the target hostname via DNS, then checks every resolved IP against `isReservedIP()` (`validate.go:44`), which compares against a list of reserved/private CIDRs — loopback, RFC-1918, link-local/cloud IMDS, and IPv6 equivalents (`validate.go:14–23`). This also defeats DNS rebinding attacks since the check happens at connection time after resolution.

2. **At registration time (input validation):** `ValidateURL` (`validate.go:62`) performs the same reserved-IP check when a webhook URL is first configured, rejecting URLs that use non-HTTP schemes or resolve to private addresses.
