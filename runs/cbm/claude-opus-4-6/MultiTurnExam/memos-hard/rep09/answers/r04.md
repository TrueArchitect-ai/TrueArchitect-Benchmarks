The premise is incorrect — there is no message broker (NATS, RabbitMQ, or otherwise) used for webhook delivery. The webhook workers consume from a plain **in-memory Go buffered channel**, declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are spawned in the package's `init()` function (`internal/webhook/webhook.go:42–55`) to consume from this channel. When `PostAsync` (line 184) is called, it enqueues the payload into the channel via a non-blocking `select` — dropping the event if the 128-slot buffer is full. There is no external queue or broker involved.
