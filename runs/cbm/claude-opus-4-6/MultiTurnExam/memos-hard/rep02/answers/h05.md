**Mechanism: explicit Go code** — reactions are removed by two explicit SQL `DELETE` statements executed within the user-deletion transaction.

**Evidence locations:**

1. **`store/db/sqlite/user_delete.go:96`** — `deleteReactionsByContentIDsTx` deletes reactions whose `content_id` matches the deleted user's memos (line 383: `DELETE FROM reaction WHERE content_id IN ...`).

2. **`store/db/sqlite/user_delete.go:102`** — `deleteReactionsByCreatorTx` deletes reactions where the deleted user is the creator (line 401: `DELETE FROM reaction WHERE creator_id = ?`).

3. Both are called from `deleteUserTargetsTx` (`store/db/sqlite/user_delete.go:92-127`), which runs inside a transaction in `DeleteUser` (`store/db/sqlite/user_delete.go:29`).

The same pattern exists in the MySQL and Postgres drivers (`store/db/mysql/user_delete.go`, `store/db/postgres/user_delete.go`). There are no database-level foreign key `ON DELETE CASCADE` rules handling this — it is done entirely in application-level Go code within the delete transaction.
