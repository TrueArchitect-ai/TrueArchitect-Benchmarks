**Delivery function** — `Post` — `internal/webhook/webhook.go:120`

This is the function that marshals the payload to JSON, constructs the HTTP POST request (optionally adding HMAC-SHA256 signatures), and sends it via `safeClient.Do()`. Asynchronous dispatch goes through `PostAsync` (line 184), which enqueues onto a buffered channel consumed by 4 worker goroutines (lines 42–55), each of which calls `Post`.

**Protection mechanism** — SSRF guard via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`

Two layers protect against Server-Side Request Forgery (SSRF) targeting internal network addresses:

1. **At dial time** (`safeDialContext`, `internal/webhook/webhook.go:59-77`): The custom `DialContext` on the shared `safeClient` resolves the target hostname via DNS and rejects any IP that falls within a reserved/private range before a connection is established. This also defeats DNS rebinding attacks.

2. **At URL registration time** (`ValidateURL`, `internal/webhook/validate.go:62-83`): When a webhook URL is first configured, it is validated to ensure it parses correctly, uses http/https, and does not resolve to a reserved IP.

Both use `isReservedIP` (`internal/webhook/validate.go:44`), which checks against a list of reserved CIDRs covering loopback, RFC-1918 private ranges, link-local (including cloud IMDS `169.254.0.0/16`), and IPv6 equivalents (`internal/webhook/validate.go:14-23`).
