Memo visibility is enforced at these distinct sites:

1. **`APIV1Service.checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:39` — guards `GetMemo`, `ListMemoComments`, and related single-memo reads; denies unauthenticated access to non-public memos and blocks non-creators from private memos.

2. **`APIV1Service.ListMemos` query-level filter** — `server/router/api/v1/memo_service.go:218-227` — injects visibility filters into the database query: anonymous users see only `PUBLIC`; authenticated users see own + `PUBLIC` + `PROTECTED`.

3. **`FileServerService.checkAttachmentPermission`** — `server/router/fileserver/fileserver.go:674-701` — enforces visibility when serving attachment files over HTTP, checking the linked memo's visibility (including share-token fallback).

4. **`APIV1Service.checkAttachmentAccess`** — `server/router/api/v1/attachment_service.go:422` — enforces visibility in the gRPC attachment service (`GetAttachment`), checking the linked memo's visibility.

5. **`SSEClient.canReceive`** — `server/router/api/v1/sse_hub.go:134` — filters real-time SSE events by visibility, only delivering private memo events to the creator or admins.

6. **Reaction service inline checks** — `server/router/api/v1/reaction_service.go:30-38` and `:82-83` — checks memo visibility before allowing reactions to be listed or created.

7. **RSS feed query filter** — `server/router/rss/rss.go:90` and `:141` — restricts RSS output to `Public`-visibility memos only.

8. **Comment creation check** — `server/router/api/v1/memo_service_comments.go:41` — blocks commenting on private memos by non-creators.
