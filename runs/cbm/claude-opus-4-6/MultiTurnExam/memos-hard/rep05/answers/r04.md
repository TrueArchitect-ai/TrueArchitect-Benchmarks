The premise is incorrect — there is no message broker (neither NATS nor RabbitMQ) involved in webhook delivery.

The webhook delivery workers consume from a plain Go buffered channel, not an external message broker. The "queue" is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four goroutine workers are started in `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post()` for each payload. Callers enqueue work via `PostAsync()` (`internal/webhook/webhook.go:184`), which does a non-blocking send to the channel (dropping the event if the buffer is full). The entire mechanism is in-process with no external dependencies.
