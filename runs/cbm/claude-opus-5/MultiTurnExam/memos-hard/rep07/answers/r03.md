**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is never used by the running server — so there is no scheduled time to report.**

Two separate corrections:

**1. No cleanup job exists.** Nothing in the codebase registers a recurring database-cleanup, vacuum, purge, or prune task. Grepping for those terms across `server/`, `store/`, and `cmd/` turns up only unrelated inline cleanup — deleting a memo's relations/attachments during `DeleteMemo` (`server/router/api/v1/memo_service.go:579`), S3 object cleanup on user deletion (`server/router/api/v1/user_service.go:421-450`, `store/attachment.go:171`), and a rolled-back provisional SSO user row (`server/router/api/v1/auth_service_sso.go:76`). All of those are triggered by a request, not by a clock.

**2. The cron scheduler isn't wired into the server at all.** `internal/scheduler` is a full cron implementation — expression parser (`internal/scheduler/parser.go`), job type (`internal/scheduler/job.go`), scheduler with `Register`/`Start`/`Stop` (`internal/scheduler/scheduler.go:54,70,91,169`), and middleware (`internal/scheduler/middleware.go`) — but grepping for `scheduler.` outside its own package in non-test code returns zero hits. Every caller of `scheduler.New` and `Register` is in `internal/scheduler`'s own tests and examples (`example_test.go`, `integration_test.go`, `scheduler_test.go`). No package imports it.

**What actually runs on a schedule.** Exactly one background timer exists in the server, and it isn't cron-based or nightly: the S3 presign runner, driven by a `time.Ticker` at `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:27,29-41`), started from `Server.startBackgroundRunners` at `server/server.go:162-171`. It refreshes presigned attachment URLs; it deletes nothing.

There is also a 5-minute in-memory cache sweep (`store/store.go:42`, `store/cache/cache.go:200-250`), which evicts expired cache entries — process memory only, no database involvement.
