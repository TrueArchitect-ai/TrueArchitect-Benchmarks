**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations`; convergence function — `webhook.Post` at `internal/webhook/webhook.go:120` (the `safeClient.Do` call at `internal/webhook/webhook.go:152`)**

The six RPC handlers and how each reaches the webhook layer:

| Handler | Location | Path to dispatch |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:70` | `DispatchMemoCreatedWebhook` at `memo_service.go:157` |
| `UpdateMemo` | `server/router/api/v1/memo_service.go:401` | `dispatchMemoUpdatedSideEffects` at `memo_service.go:513` → `DispatchMemoUpdatedWebhook` at `memo_update_helpers.go:67` |
| `DeleteMemo` | `server/router/api/v1/memo_service.go:518` | `DispatchMemoDeletedWebhook` at `memo_service.go:562` |
| `CreateMemoComment` | `server/router/api/v1/memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` at `memo_service_comments.go:119` (fires to the *parent* memo owner's webhooks) |
| `SetMemoAttachments` | `server/router/api/v1/memo_attachment_service.go:16` | `dispatchMemoUpdatedSideEffects` at `memo_attachment_service.go:48` |
| `SetMemoRelations` | `server/router/api/v1/memo_relation_service.go:16` | `dispatchMemoUpdatedSideEffects` at `memo_relation_service.go:48` |

All four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go`; three of them funnel through `dispatchMemoRelatedWebhook` (`:48`), which loads the creator's configured hooks via `s.Store.GetUserWebhooks` and sets `payload.URL = hook.Url` (`:67`).

**Convergence.** Every one of those paths calls `webhook.PostAsync` — `memo_service_webhooks.go:43` (comment) and `:71` (created/updated/deleted) — which only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:184`). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue, and the single function that every path passes through before delivery is `webhook.Post` (`internal/webhook/webhook.go:120`), which signs the body and issues the request through the SSRF-guarded `safeClient` at `internal/webhook/webhook.go:152`.

The URLs are user-configured through the webhook CRUD handlers in `server/router/api/v1/user_service_webhooks.go`, which validate them at write time via `webhook.ValidateURL` (`:74`, `:161`, `:182`).

One adjacent path worth naming, since it doesn't converge on `webhook.Post`: `GetLinkMetadata` / `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go:14` and `:19`) fetch an arbitrary caller-supplied URL through `fetchHTMLMeta` → `httpgetter.GetHTMLMeta` (`memo_service_link_metadata.go:46`, aliased at `memo_service.go:28`). That's a per-request URL rather than stored configuration, and it uses a separate client in `internal/httpgetter/html_meta.go`.
