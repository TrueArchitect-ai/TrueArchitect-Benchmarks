Back up the stack, the handler turns the stored column into bytes:

- `user.AvatarURL == ""` → 404 (`fileserver.go:192-194`).
- `FileServerService.parseDataURI` — `server/router/fileserver/fileserver.go:737` — matches `dataURIRegex` (`fileserver.go:98`) and base64-decodes the payload, yielding MIME type + raw bytes.
- MIME type is checked against `avatarAllowedTypes` (`fileserver.go:75-83`, enforced at `:201`), then `setSecurityHeaders` (`fileserver.go:758`) and `Cache-Control: public, max-age=3600` are applied and the bytes are written via `c.Blob` (`fileserver.go:209`).

Note on the access check: authentication is required only when the instance is private (`!s.Profile.AllowAnonymous()`); there's no per-user authorization, so on a public instance any visitor can fetch any user's avatar by username, which is the intended behavior for a public profile image.
