**Premise correction: there is no Redis in this repository — no client dependency, no connection config, no code reference. `grep -rni "redis"` across all Go sources, `go.mod`, and YAML/JSON config files returns zero hits. The cache layer is a hand-rolled, in-process, in-memory cache.**

**Actual mechanism.**

The cache is `store/cache/cache.go` — a `sync.Map`-backed `Cache` type (`store/cache/cache.go:67`) with per-entry expiration, an item cap, and a background cleanup goroutine. It satisfies the local `cache.Interface` (`store/cache/cache.go:11`). Because it lives in the process's memory, nothing is shared across instances — a multi-replica deployment gets independent caches.

**Where it's "configured":** in `store.New`, not in any config file or env var — the settings are hardcoded at `store/store.go:40-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

Three caches are constructed from that same config (`store/store.go:51-53`): `instanceSettingCache`, `userCache`, and `userSettingCache`. An identical set of defaults also exists in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), but `store.New` builds its own literal rather than calling it.

**TTL for user entries: 10 minutes.** Every user write goes through `Set` (not `SetWithTTL`), which applies `c.config.DefaultTTL` (`store/cache/cache.go:93-95`) — see the call sites at `store/user.go:98`, `:122`, `:132`, `:143`, and `:167`. No code anywhere calls `SetWithTTL`, so the 10-minute default is the only TTL in effect.

Behavior worth knowing beyond the TTL:

- **Lazy + periodic expiry.** `Get` checks expiration and evicts on read (`store/cache/cache.go:135-144`); a ticker goroutine sweeps every 5 minutes (`store/cache/cache.go:200-250`).
- **Capacity eviction.** Exceeding `MaxItems: 1000` triggers `cleanupOldest`, which drops roughly 20% of the cap (`store/cache/cache.go:117-119`, `:253-255`) — so on a busy instance user entries can be evicted well before 10 minutes.
- **Explicit invalidation** on user deletion: `s.userCache.Delete(ctx, userCacheKey(userID))` (`store/user_delete.go:40`).
- **Read path nuance.** `Store.GetUser` only consults the cache when the lookup is by ID (`store/user.go:148-156`); lookups by username or email always hit the driver.
- **Shutdown.** `Store.Close` stops all three cleanup goroutines before closing the DB driver (`store/store.go:72-78`).
