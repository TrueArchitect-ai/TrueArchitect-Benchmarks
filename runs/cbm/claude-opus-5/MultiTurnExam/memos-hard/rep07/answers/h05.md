**Explicit Go code — two `DELETE FROM reaction` statements inside the delete-user transaction in each of the three DB drivers. There is no database-level cascade for reactions.**

What I checked:

1. **The delete path in each driver.** `DeleteUser` opens a transaction and calls `deleteUserTargetsTx`, which runs the reaction deletes before anything else:
   - `store/db/mysql/user_delete.go:96` → `deleteReactionsByContentIDsTx` (defined at `:380`, `DELETE FROM reaction WHERE content_id IN (...)` at `:383`) — removes reactions *on* the deleted user's memos, batched 500 at a time.
   - `store/db/mysql/user_delete.go:102` → `deleteReactionsByCreatorTx` (defined at `:400`, `DELETE FROM reaction WHERE creator_id = ?` at `:401`) — removes reactions the user *made* on anyone's content.
   - Identical structure and line numbers in `store/db/sqlite/user_delete.go:96,102,380,383,400,401` and `store/db/postgres/user_delete.go:96,102,380,383,400,401`.

2. **Why both queries are needed.** The `reaction` table keys content by string, not by memo id: `memoContentIDsFromRefs` builds `"memos/" + memo.UID` (`store/db/mysql/user_delete.go`, in the helper section near the end of the file), and the memo set is gathered transitively — `listDeleteUserMemoTreeIterative` walks `memo_relation` `COMMENT` edges to include comment descendants. So content-side reactions can't be reached by any id-based FK.

3. **The schema — no cascade on reaction.** In all three `LATEST.sql` files the `reaction` table declares only `id`, `created_ts`, `creator_id`, `content_id`, `reaction_type` and a `UNIQUE(creator_id, content_id, reaction_type)` constraint — no `FOREIGN KEY`, no `ON DELETE CASCADE`: `store/migration/mysql/LATEST.sql:91-98`, `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`.

4. **The only cascade in the schema is elsewhere.** Grepping `REFERENCES|CASCADE` across all three `LATEST.sql` files yields exactly one hit each — `memo_share.memo_id → memo(id) ON DELETE CASCADE` (`store/migration/mysql/LATEST.sql:108`, `store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`) — which does not cover reactions. (The Go code deletes `memo_share` rows explicitly anyway, at `user_delete.go:105`.)
