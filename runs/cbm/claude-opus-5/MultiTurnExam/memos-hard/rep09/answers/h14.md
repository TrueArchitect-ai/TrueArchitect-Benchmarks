**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `markdown.(*service).ExtractAll` — `internal/markdown/markdown.go:356`.**

**Triggers (recomputation happens on exactly two production paths):**

1. **Memo creation** — `APIV1Service.CreateMemo`, `server/router/api/v1/memo_service.go:108`, after the content-length check and before `s.Store.CreateMemo`. This also covers **comment creation**, since `CreateMemoComment` routes through `s.CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
2. **Memo content update** — `APIV1Service.UpdateMemo`, `server/router/api/v1/memo_service.go:447`, but *only* inside the `path == "content"` branch of the update mask (`:435-451`). Updating `visibility`, `pinned`, `state`, or `create_time` leaves the stored payload untouched — correctly, since none of them change the content the metadata is derived from. The recomputed payload is attached via `update.Payload = memo.Payload` (`:451`).

A third call site exists at `server/runner/memopayload/runner.go:52` (`Runner.RunOnce`, a batch rebuild over all memos), but it is dead code — `memopayload.NewRunner` has no non-test callers, so nothing ever constructs that runner.

**What's extracted.** `RebuildMemoPayload` initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))` — a single goldmark AST walk — and assigns two fields (`runner.go:82-83`):

- **`Payload.Tags`** — `#tag` values from custom `TagNode`s, deduplicated with case preserved (`markdown.go:418`).
- **`Payload.Property`** — the derived flags, declared in `proto/store/memo.proto:15-22`:
  - `has_link` — document contains a link (`gast.KindLink`)
  - `has_code` — contains a code block, fenced code block, or code span
  - `has_task_list` — contains a task checkbox
  - `has_incomplete_tasks` — at least one checkbox is unchecked
  - `title` — text of the first H1 heading, only when it is the document's first block-level child (`markdown.go:385-390`)

Note that `ExtractAll` also collects `Mentions` (lowercased `@username`), but `RebuildMemoPayload` does **not** persist them — mentions are consumed separately for notifications at `server/router/api/v1/memo_mention_helpers.go:32`. And `Payload.Location` (`memo.proto:10`) is user-supplied, set after the rebuild at `memo_service.go:111-113`, not derived.
