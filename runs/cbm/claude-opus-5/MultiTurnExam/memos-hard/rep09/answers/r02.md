**Premise correction: no per-user API rate-limiting middleware exists in this repository.** There is nothing to register and no request limits to report.

What I checked:

- **Code search**: `rate limit`, `ratelimit`, `throttle`, `limiter` (case-insensitive) across all Go sources returns exactly one hit — a comment in `internal/email/doc.go:86` listing "Rate limit email sending to prevent abuse" as a *suggestion for callers*, not an implementation.
- **Dependencies**: `go.mod` contains no rate-limiting library — no `golang.org/x/time/rate`, no `tollbooth`, no `ulule/limiter`, and no Redis-backed limiter (there is no Redis at all).
- **Middleware chain**: the complete set of Echo middleware registered on the server is `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/server.go:51-52`), plus static-file and SPA-fallback middleware for the frontend (`server/router/frontend/frontend.go:54`, `:59`). The gRPC-Gateway mux adds only an auth middleware (`server/router/api/v1/v1.go:95`). No limiter is in any of these chains.

**What does exist — related but different mechanisms**, in case one of these is what you had in mind:

1. **Concurrency caps, not rate limits.** Weighted semaphores bound simultaneous expensive operations, process-wide rather than per user: `maxConcurrentThumbnails = 3` (`server/router/fileserver/fileserver.go:46`, applied at `:116`), and in the API service `thumbnailSemaphore` = 3 with `imageProcessingSemaphore` = 2 (`server/router/api/v1/v1.go:59-60`). These make callers wait, not fail, and don't track identity.

2. **A bounded webhook queue with drop-on-full.** `asyncPostQueue` holds 128 payloads (`internal/webhook/webhook.go:39`) drained by 4 workers (`:42-55`); overflow is dropped with a warning (`:191-195`). That's backpressure on outbound delivery, not inbound request limiting.

3. **Per-request size/content limits.** A configurable memo content-length limit enforced in `CreateMemo`/`UpdateMemo` (`server/router/api/v1/memo_service.go:105-107`, `:441-443`), and a 1 MB cap on reading webhook responses (`internal/webhook/webhook.go:158`).

If you want per-user rate limiting, it would need to be added — the natural insertion point is the Echo middleware chain at `server/server.go:51-52`, or the gateway/Connect auth interceptor in `server/router/api/v1/v1.go`, where the authenticated user is already resolved.
