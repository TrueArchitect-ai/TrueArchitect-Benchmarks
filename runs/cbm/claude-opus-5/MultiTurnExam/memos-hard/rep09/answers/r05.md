**Premise correction: there is no GraphQL in this repository.** A case-insensitive search for `graphql`/`gqlgen` across all sources, `go.mod`, and `go.sum` returns zero matches, and there are no `.graphql`/`.graphqls` schema files anywhere outside `node_modules`. No schema, resolvers, or GraphQL endpoint exist.

**Actual API surface — Protocol Buffers / gRPC, exposed over HTTP three ways:**

**Schema definition** — `.proto` files in `proto/api/v1/`, nine service definitions:

`ai_service.proto`, `attachment_service.proto`, `auth_service.proto`, `common.proto`, `idp_service.proto`, `instance_service.proto`, `memo_service.proto`, `shortcut_service.proto`, `user_service.proto`

A parallel `proto/store/` tree defines persistence-layer messages (e.g. `memo.proto`, `idp.proto`, `attachment.proto`). Generated Go lands in `proto/gen/` — `*.pb.go` (messages), `*_grpc.pb.go` (gRPC stubs), `*.pb.gw.go` (grpc-gateway REST shims), and `apiv1connect/*.connect.go` (Connect handlers).

**Serving** — all implemented by `APIV1Service` and registered in `RegisterGateway` (`server/router/api/v1/v1.go:65`):

1. **gRPC-Gateway REST/JSON** — a `runtime.NewServeMux` with an auth middleware (`v1.go:95-97`), then `v1pb.Register<Name>ServiceHandlerServer(ctx, gwMux, s)` for each service (`v1.go:98+`). HTTP paths come from `google.api.http` annotations in the protos.
2. **Connect protocol handlers** — `server/router/api/v1/connect_services.go` and `connect_handler.go`, using the generated `apiv1connect` package.
3. **Plain HTTP side-routes** outside the proto surface: the file server (`server/router/fileserver/fileserver.go:121-125` — `/file/attachments/...`, `/file/users/:identifier/avatar`), RSS (`server/router/rss/rss.go`), MCP (`server/router/mcp/`), and the SPA frontend (`server/router/frontend/frontend.go`).

Authorization is centralized in `NewAuthorizer` (`v1.go:68`), shared by the gateway middleware and the Connect interceptor, with per-method policy in `server/router/api/v1/acl_config.go`.
