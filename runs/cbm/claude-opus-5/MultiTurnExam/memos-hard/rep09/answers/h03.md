**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation).**

- **Abstraction — `internal/idp/idp.go`**: the package is deliberately thin. It defines a single provider-neutral type, `IdentityProviderUserInfo` (`idp.go:3-8`) with `Identifier`, `DisplayName`, `Email`, `AvatarURL` — the normalized shape every provider must produce. Note there is no Go `interface` here; the abstraction is the shared return type, not a polymorphic contract.

- **Implementation — `internal/idp/oauth2/oauth2.go`**: the only concrete protocol shipped. It defines `IdentityProvider` (`oauth2.go:20`), built by `NewIdentityProvider(*storepb.OAuth2Config)` (`oauth2.go:27`), with the two-step flow `ExchangeToken(ctx, redirectURL, code, codeVerifier)` (`oauth2.go:47`) — the `codeVerifier` parameter indicates PKCE support — and `UserInfo(ctx, token)` (`oauth2.go:83`), which returns `*idp.IdentityProviderUserInfo`, closing the loop back to the abstraction.

`internal/idp/oauth2` is the sole subdirectory of `internal/idp`, and the protobuf schema corroborates that OAuth2 is the only variant: `IdentityProviderConfig` is a `oneof` whose single member is `oauth2_config` in both `proto/store/idp.proto:21-23` and `proto/api/v1/idp_service.proto:83-85`.

Consumed at `server/router/api/v1/auth_service_sso.go:12-13`, which imports both packages to drive the SSO sign-in exchange.
