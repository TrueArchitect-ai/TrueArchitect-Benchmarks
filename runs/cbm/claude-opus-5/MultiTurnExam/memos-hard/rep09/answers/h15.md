h15.

Enforcement is spread across six distinct surfaces. Each independently decides who may see memo content:

```
checkMemoReadAccess (single-memo gRPC read gate) — server/router/api/v1/memo_service.go:39
ListMemos visibility scoping (query-level filter) — server/router/api/v1/memo_service.go:219-225
FileServerService.checkAttachmentPermission (HTTP binary/attachment serving) — server/router/fileserver/fileserver.go:674-701
SSEClient.canReceive (real-time event fan-out filter) — server/router/api/v1/sse_hub.go:133-143
RSSService feed queries (public-only listing) — server/router/rss/rss.go:90 and :141
FrontendService.getSitemapXML (public-only listing) — server/router/frontend/frontend.go:150
```

Detail on each:

1. **`checkMemoReadAccess`** (`memo_service.go:39`) — the canonical single-memo gate. Archived memos are creator-only (`:45-53`); non-public memos require authentication (`:55-61`); private memos require creator identity (`:63-65`). Used by memo reads and reused by adjacent services.

2. **`ListMemos` scoping** (`memo_service.go:219-225`) — enforcement by *query construction* rather than post-hoc rejection: anonymous callers get `VisibilityList = [PUBLIC]`; authenticated callers get a CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`. The same pattern is repeated in `memo_service_converter.go:184-186`, `memo_relation_service.go:109-111`, `memo_service_comments.go:158-160`, and `user_service_stats.go:84-90`.

3. **`checkAttachmentPermission`** (`fileserver.go:674-701`) — guards the non-gRPC `/file/attachments/...` route. Distinctive because it's the only site honoring a **share-token bypass**: a valid, non-expired `share_token` matching the memo grants access to private/protected content (`:684-690`). Public content is anonymous-readable only when `AllowAnonymous()` is true (`:677`).

4. **`SSEClient.canReceive`** (`sse_hub.go:133-143`) — filters outbound live events; private events reach only the creator or an admin, and unknown visibility values fail closed with a warning (`:141`).

5. **RSS feeds** (`rss.go:90`, `:141`) — hard-pinned to `[]store.Visibility{store.Public}`; no authenticated widening.

6. **Sitemap** (`frontend.go:150`) — same hard-pinned public-only query for SEO output.

Beyond read enforcement, several *write/interaction* paths re-check visibility independently rather than calling `checkMemoReadAccess`: reactions (`reaction_service.go:30-38`, `:83`), comment creation (`memo_service_comments.go:41`), memo attachment listing (`memo_attachment_service.go:214-222`), attachment access (`attachment_service.go:436-451`), mention notifications (`memo_mention_helpers.go:62`), and email notifications (`notification/email.go:313-316`).

If you want strictly the read-path surfaces, items 1–6 are the answer; the duplication in the write paths is worth noting since each re-implements the private/creator/superuser predicate by hand instead of sharing one helper.
