**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual `safeClient.Do(req)` at `webhook.go:152`); SSRF protection is `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

How it fits together:

**Delivery path.** Memo mutations call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which just enqueues onto a bounded 128-slot channel and drops on overflow (`webhook.go:184-196`). Four worker goroutines started in `init()` (`webhook.go:42-55`) drain that queue and call `Post`, which is where the outbound HTTP actually happens: it marshals the payload, optionally attaches Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`, `webhook.go:133-150`), then issues the request via the shared `safeClient` (`webhook.go:152`).

**Protection — two layers:**

1. *Dial-time (the real enforcement)*: `safeClient`'s Transport uses `safeDialContext` (`webhook.go:32-37`, `:59-77`). It splits the address, resolves the host itself, and rejects the dial if **any** returned IP is reserved. Because the check runs on every dial rather than once at config time, it also defeats DNS rebinding — the comment at `webhook.go:29-31` states this intent explicitly.

2. *Admission-time*: `webhook.ValidateURL` (`validate.go:62`) runs when a user saves a webhook — enforcing http/https scheme and rejecting hostnames resolving to reserved IPs. Called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. This is UX/early-failure, not the security boundary, since DNS can change after validation.

Both layers share `isReservedIP` (`validate.go:44`), which tests against `reservedNetworks` — loopback, RFC-1918, link-local incl. the cloud IMDS range `169.254.0.0/16`, and IPv6 equivalents (`validate.go:14-23`), parsed once in `init()` (`validate.go:28-36`).

One thing worth flagging: the escape hatch `AllowPrivateIPs` (`validate.go:41`) disables both layers when true, but nothing in non-test code ever sets it — no flag, env var, or config binding exists (only `internal/webhook/webhook_test.go:91,142` assign it). So the documented "self-hosted deployments targeting local network services" use case is currently unreachable.

Also note `safeDialContext` resolves the host and then re-dials by hostname (`webhook.go:76`), so the connection performs a second, independent resolution — the validated IPs aren't the ones pinned for the dial. That's a narrow TOCTOU window rather than a full bypass, but it means the rebinding defense is weaker than the comment claims.
