**Premise correction: there is no Redis in this repository.** A case-insensitive search for `redis` across the entire tree — Go sources, `go.mod`, `go.sum`, configs, docs — returns **zero** matches. No Redis client is imported, and there is no external cache service to configure. There is likewise no connection string, host/port setting, or cache-backend flag anywhere: `cmd/memos/main.go` registers only `demo`, `addr`, `port`, `unix-sock`, `data`, `driver`, `dsn`, `instance-url`, `allow-private-webhooks`, and `log-level`.

**Actual mechanism — a process-local in-memory cache.**

- **Implementation**: `store/cache/cache.go` — a `Cache` struct built on `sync.Map` plus an `atomic.Int64` item counter (`cache.go:66-73`), satisfying the `Interface` at `cache.go:11`. Entries are `item{value, expiration, size}` (`cache.go:35`). A background goroutine sweeps expired entries and `Close()` (`cache.go:187`) stops it.

- **Configuration site**: `store.New` in `store/store.go:39-44`, which builds one `cache.Config` literal and hands it to three caches created at `store/store.go:50-52`: `instanceSettingCache`, `userCache`, `userSettingCache`.

**TTL for user entries: 10 minutes**, with cleanup every 5 minutes and a 1000-item cap — `DefaultTTL: 10 * time.Minute` at `store/store.go:40`. The identical defaults are also expressed in `cache.DefaultConfig()` (`store/cache/cache.go:57-63`), though `store.New` inlines its own copy rather than calling it.

That 10 minutes is the *effective* TTL for users because every user write goes through the plain `Set` (which applies `DefaultTTL`) — `store/user.go:98`, `:122`, `:132`, `:143`, `:167`. `SetWithTTL` exists on the interface but has **no** call sites outside the cache package itself, so no per-entry override is ever applied.

Two practical consequences of it being in-memory rather than Redis: the cache is per-process (not shared across replicas), and it is invalidated explicitly on user deletion via `s.userCache.Delete(...)` at `store/user_delete.go:40`. Note also that `GetUser` only consults the cache when the lookup is by ID (`store/user.go:149-156`) — username-based lookups always hit the database.
