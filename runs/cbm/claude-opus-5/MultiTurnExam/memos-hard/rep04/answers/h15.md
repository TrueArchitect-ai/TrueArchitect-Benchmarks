Enforcement sites, grouped by surface:

**gRPC/Connect API (`server/router/api/v1`)**
- `checkMemoReadAccess` — single-memo read gate (`GetMemo`, comments, etc.); also hides archived memos from non-creators — `server/router/api/v1/memo_service.go:39-68`
- `ListMemos` query scoping — anonymous → `PUBLIC` only; authenticated → `creator_id == me || visibility in ["PUBLIC","PROTECTED"]` — `server/router/api/v1/memo_service.go:217-226`
- `batchConvertMemoRelations` — same visibility filter applied to related/linked memos before they're returned — `server/router/api/v1/memo_service_converter.go:182-187`
- `ListMemoRelations` — identical filter for the relations endpoint — `server/router/api/v1/memo_relation_service.go:107-112`
- User stats endpoints — visibility-scoped memo queries — `server/router/api/v1/user_service_stats.go:82-91` and `:216-221`
- `CreateMemoComment` — blocks commenting on a private memo you don't own — `server/router/api/v1/memo_service_comments.go:41`
- Reaction endpoints (`UpsertMemoReaction` / `DeleteMemoReaction`) — private-memo gate — `server/router/api/v1/reaction_service.go:30-38` and `:83`
- Attachment access check — access to a linked attachment follows its memo's visibility — `server/router/api/v1/attachment_service.go:443-452` (invoked from `:255`)

**Native file server (`server/router/fileserver`)**
- `checkAttachmentPermission` — public+anonymous fast path, share-token fallback, then private-memo owner/admin gate — `server/router/fileserver/fileserver.go:674-702`

**Server-sent events (`server/router/api/v1`)**
- `SSEClient.canReceive` — per-subscriber delivery filter on broadcast; private events go only to creator or admin, unknown visibility is denied — `server/router/api/v1/sse_hub.go:134-143` (applied in `Broadcast`, `:120-131`)

**RSS (`server/router/rss`)**
- Instance feed — `VisibilityList: []store.Visibility{store.Public}` — `server/router/rss/rss.go:90`
- Per-user feed — same restriction — `server/router/rss/rss.go:141`

**Frontend/SEO (`server/router/frontend`)**
- Sitemap generation — public memos only — `server/router/frontend/frontend.go:149-151`

**Notification paths (visibility used to suppress delivery)**
- Mention notifications — skip targets who can't see a private memo — `server/router/api/v1/memo_mention_helpers.go:62,67`
- Email notification content gating by visibility — `server/router/api/v1/user_service_notifications.go:309-312` and `server/notification/email.go:313-316`

Two structural notes: the API-layer checks fall into two shapes — post-fetch gates (`checkMemoReadAccess`, reaction/comment checks) and pre-query scoping that pushes visibility into the SQL filter (`ListMemos`, relations, stats) — so a memo you can't see is usually never fetched rather than fetched-then-rejected. And `GetMemoByShare` (`server/router/api/v1/memo_share_service.go:151-192`) is a deliberate bypass: a valid, unexpired share token returns the memo regardless of visibility, checking only that it isn't archived; the file server honors the same token at `server/router/fileserver/fileserver.go:684-690`.
