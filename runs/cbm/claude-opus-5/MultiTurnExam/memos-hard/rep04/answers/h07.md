Notes on the ends of the chain:

**Where the URL comes from.** The stored data is not a file on disk — `user.avatar_url` holds a base64 `data:` URI. `convertUserFromStore` detects that and rewrites the API-facing `AvatarUrl` to `/file/{userpb.Name}/avatar` (`server/router/api/v1/user_service_converters.go:36`) so responses don't carry inline base64; if the stored value isn't a data URI it's passed through unchanged. Since `userpb.Name` is `users/{username}`, the resulting path lands on the `:identifier` route segment, which `getUserByUsername` resolves as a username.

**Access control.** There is no per-user visibility check on avatars — the only gate is instance-level: when the instance has no `InstanceURL` (`Profile.AllowAnonymous()` false), a session/access token/PAT is required (`fileserver.go:173-181`). On a public instance any browser can fetch any user's avatar. The response is validated against `avatarAllowedTypes` (`fileserver.go:75`) to block XSS-capable types, mirroring the upload-side check at `server/router/api/v1/user_service.go:336-351`.
