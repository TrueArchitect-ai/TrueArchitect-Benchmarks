**Premise correction: neither. There is no message broker in this repository — no NATS, RabbitMQ, AMQP, Kafka, or any other queueing system — and therefore no queue declaration site.** A case-insensitive search for `nats`, `rabbit`, `amqp`, `kafka`, `pubsub`, and `sqs` across all Go sources and `go.mod` returns zero matches.

**Actual mechanism: an in-process buffered Go channel with a fixed worker pool, all inside `internal/webhook/webhook.go`.**

- **The "queue"** is a package-level buffered channel holding 128 payloads: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` at `internal/webhook/webhook.go:39`. It is declared in the same `var` block as the shared HTTP client, not in any broker config.
- **The workers** are four goroutines started in the package `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over `asyncPostQueue` and calls `Post(payload)`, logging a warning on failure. They start when the package is first loaded, not by explicit server wiring, and there is no graceful shutdown for them.
- **Producing** goes through `PostAsync` (`internal/webhook/webhook.go:184-196`), called from the memo dispatchers at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`. It does a non-blocking `select` send: if the buffer is full, the default branch **drops the webhook** with a `slog.Warn` ("Dropped webhook dispatch because the async queue is full"). A nil payload is likewise dropped with a warning.
- **Consuming/delivery** happens in `Post` (`internal/webhook/webhook.go:120`), which marshals the payload, optionally adds Standard Webhooks HMAC headers, and issues the request via `safeClient.Do` at `:152` with a 30-second timeout.

Consequences of this design worth noting, since they're exactly what a broker would change: delivery is at-most-once with no retries and no persistence — an overflow drop or a process restart loses queued webhooks silently — and the queue is per-process, so replicas do not share it.
