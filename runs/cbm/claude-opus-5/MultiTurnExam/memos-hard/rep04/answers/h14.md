**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `markdown.(*service).ExtractAll` — `internal/markdown/markdown.go:356`; Triggers: memo create and content-changing memo update; Extracted: `tags` plus the five `MemoPayload.Property` fields (`has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`, `title`).**

**Where it's computed.** `RebuildMemoPayload` initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, and assigns exactly two fields — `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`server/runner/memopayload/runner.go:74-88`). The real work is a single goldmark AST walk in `ExtractAll` (`internal/markdown/markdown.go:356-422`), so all metadata comes from one parse rather than repeated passes. The result is persisted in the memo's `payload` column as protojson (e.g. `store/db/sqlite/memo.go:20-26`).

**What it extracts** (schema at `proto/store/memo.proto:7-24`):

- `tags` — every `#tag` node, deduplicated with original case preserved via `uniquePreserveCase` (`internal/markdown/markdown.go:418`).
- `property.title` — text of the first block-level child *only if* it's an H1 heading (`internal/markdown/markdown.go:382-388`).
- `property.has_link` — any `KindLink` node.
- `property.has_code` — any code block, fenced code block, or code span.
- `property.has_task_list` — any task checkbox; and `property.has_incomplete_tasks` when at least one checkbox is unchecked (`internal/markdown/markdown.go:398-406`).

`ExtractAll` also collects `Mentions` (lowercased), but `RebuildMemoPayload` does not copy those into the payload — mentions are consumed separately for notifications (`server/router/api/v1/memo_mention_helpers.go:32`). `payload.location` is user-supplied, set alongside at `server/router/api/v1/memo_service.go:110-112`, not derived.

**Triggers.** Two production call sites:

1. `CreateMemo` — `server/router/api/v1/memo_service.go:108`, before the row is inserted. This also covers `CreateMemoComment`, which delegates to `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the `path == "content"` branch of the update mask, with the recomputed payload written via `update.Payload` (`:450`). Updates touching only visibility, pinned state, etc. leave the payload untouched.

A third call site exists at `server/runner/memopayload/runner.go:52` — a batch backfill that rebuilds every memo's payload — but that runner is never constructed or invoked in production, so it isn't a live trigger.

**Related but distinct:** the preview `snippet` shown in relations and notifications is *not* stored — it's generated on read by `GenerateSnippet(content, 64)` at `server/router/api/v1/memo_service_webhooks.go:85`, used from `server/router/api/v1/memo_relation_service.go:154,162` and `server/router/api/v1/user_service_notifications.go:323`.
