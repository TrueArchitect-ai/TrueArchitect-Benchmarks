**`internal/idp` (package `idp`, `internal/idp/idp.go`); `internal/idp/oauth2` (package `oauth2`, `internal/idp/oauth2/oauth2.go`) — OAuth2 is the only concrete protocol that ships.**

Supporting detail:

- **Abstraction.** `internal/idp/idp.go` is a single file defining `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) — the provider-neutral shape every implementation normalizes into. Note it's a shared struct rather than a Go interface; there is no `IdentityProvider` interface type. The provider *kind* is modelled in protobuf instead: `IdentityProvider.Type` in `proto/store/idp.proto:11-14`, whose enum has only `TYPE_UNSPECIFIED = 0` and `OAUTH2 = 1`, with `IdentityProviderConfig` being a `oneof` currently holding just `oauth2_config` (`proto/store/idp.proto:21-25`).

- **Implementation.** `internal/idp/oauth2/oauth2.go` defines `IdentityProvider` over `storepb.OAuth2Config`, with `NewIdentityProvider` validating required fields (line 27), `ExchangeToken` doing the authorization-code exchange with optional PKCE `code_verifier` (line 47), and `UserInfo` fetching the userinfo endpoint and mapping claims into `idp.IdentityProviderUserInfo` via the configured `FieldMapping` (line 83). It builds on `golang.org/x/oauth2`.

- **Wiring.** The sole consumer is `server/router/api/v1/auth_service_sso.go`, which imports both packages (lines 12-13) and dispatches on type in `resolveSSOIdentity`: `if identityProvider.Type == storepb.IdentityProvider_OAUTH2` → `oauth2.NewIdentityProvider(...)` → `ExchangeToken` → `UserInfo` (lines 120-134). Since OAUTH2 is the only branch, a non-OAuth2 provider would leave `userInfo` nil. The resulting user info then flows into `resolveSSOUser` (line 19) for linking or provisioning.
