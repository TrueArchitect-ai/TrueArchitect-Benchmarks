**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection: dial-time reserved/private-IP blocking via `safeDialContext` → `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

How it fits together:

**Delivery path.** Memo create/update/delete/comment events call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43` and `:71`. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel (`asyncPostQueue`, line 39), dropping with a warning if full. Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`, which marshals the payload, adds Standard Webhooks HMAC headers when a signing secret is set (lines 133-150), and performs the outbound request through `safeClient` at line 152.

**SSRF protection — two layers:**

1. *Enforcement at dial time (the one that actually guards delivery).* `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`). It splits the address, resolves the hostname itself, and refuses to dial if any resolved IP is reserved (`internal/webhook/webhook.go:59-77`). Because the check happens on the resolution used for the connection, it also defeats DNS-rebinding, which a URL-time-only check would miss.
2. *Validation when a webhook is configured.* `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called on user-supplied URLs in `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`; it enforces http/https scheme and rejects hostnames resolving into reserved ranges, returning a gRPC `InvalidArgument`.

Both layers share `isReservedIP` (`internal/webhook/validate.go:44`), backed by the `reservedCIDRs` list at `internal/webhook/validate.go:14-23`: IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), plus IPv6 loopback, unique-local, and link-local. These are parsed once in `init()` (lines 28-36).

**Escape hatch.** The package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted deployments targeting LAN services. One thing worth flagging: in the current tree nothing outside `internal/webhook/webhook_test.go` ever assigns it — `grep` for `AllowPrivateIPs` finds only the declaration, its use, and the tests, so despite the `--allow-private-webhooks` flag recorded in `CHANGELOG.md:121`, there is no CLI/config wiring present. It stays `false` (protection always on) in the built server.
