**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is not wired into the server at all — so there is no scheduled time to report.**

Two separate things are false in the premise:

**1. No cleanup job exists.** Searching for `cleanup`, `vacuum`, `purge`, `nightly`, and `cron` across `server/`, `store/`, and `cmd/` turns up no scheduled database maintenance. The `cleanup` hits are unrelated: in-memory cache expiry (`store/cache/cache.go:83,118`, on a 5-minute `CleanupInterval` set at `store/store.go:42`), and inline best-effort cleanup during request handling (e.g. attachment storage cleanup on user delete, `server/router/api/v1/user_service.go:421-450`, and the SSO provisional-user rollback at `server/router/api/v1/auth_service_sso.go:76`). None of these is a cron job.

**2. The cron scheduler is dead code in this build.** The package at `internal/scheduler/` is real and complete — it has a cron expression parser (`internal/scheduler/parser.go`), job registration (`internal/scheduler/scheduler.go`, with `Register`, `Start`, `Stop`), and middleware (`internal/scheduler/middleware.go`). But grepping for imports of `github.com/usememos/memos/internal/scheduler` across the repo returns only two files, both tests inside the package's own directory: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No production code constructs a scheduler or registers a job with it.

**What actually runs on a schedule.** The server has exactly one recurring background task, and it isn't cron-driven or nightly: the S3 presign runner, on a `time.Ticker` with a fixed 12-hour interval (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27`), plus one synchronous pass at startup. It's started in `Server.startBackgroundRunners` at `server/server.go:162-171`. Beyond that, the only periodic work is the three cache cleanup goroutines launched by `cache.New` (`store/cache/cache.go:83`).
