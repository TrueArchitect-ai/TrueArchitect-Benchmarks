Notes on each hop:

- **Registration** — the `/file` group is created in `RegisterRoutes` (`fileserver.go:121-125`), and the service is constructed and wired into Echo at `server/server.go:80-81`, deliberately before the gRPC-gateway registration (comment at `:78-79`).
- **`serveUserAvatar`** (`fileserver.go:168-210`) — first gates anonymous access: if `s.Profile.AllowAnonymous()` is false it requires a resolvable viewer via `getCurrentUser`, else 401 (`:173-181`). It then reads the `:identifier` path param (`:183`), looks up the user, and 404s when the user is missing (`:189-191`) or has no avatar (`:192-194`).
- **Data is not a file on disk** — the avatar lives in the user row as a data URI. `parseDataURI` (`fileserver.go:196`, defined at `:737`) splits it into MIME type and decoded bytes, the type is checked against `avatarAllowedTypes` (`:201`, allowlist at `:75`), security headers and `Cache-Control` are set (`:205-207`), and the bytes go out via `c.Blob` (`:209`). The URL form `/file/{user}/avatar` is what the API substitutes for raw base64 in user responses (`server/router/api/v1/user_service_converters.go:33-36`).
- **`getUserByUsername`** (`fileserver.go:715-717`) is a one-line adapter to `s.Store.GetUser` with `&store.FindUser{Username: &identifier}` — so the path segment is matched against `username`, not ID.
- **`Store.GetUser`** (`store/user.go:148-169`) consults `userCache` **only when `find.ID` is set** (`:149-156`). Because this lookup is by username, the cache is always missed and it falls through to `ListUsers`, then caches the result by ID (`:167`).
- **`Store.ListUsers`** (`store/user.go:136-146`) delegates to `s.driver.ListUsers` and warms the per-ID cache for each row.
- **Driver SQL** — `store/db/sqlite/user.go:88` builds `WHERE username = ?` (`:128-130`) and selects `avatar_url` among the columns (`:151-165`), which is the field `serveUserAvatar` ultimately decodes.
