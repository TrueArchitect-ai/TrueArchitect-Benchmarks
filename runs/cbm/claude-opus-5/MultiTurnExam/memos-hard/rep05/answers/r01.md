**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive grep for `redis` across all `.go` files, `go.mod`, `go.sum`, YAML, and Markdown returns zero matches. There is no Redis client dependency, no connection string, and no external cache server of any kind. The cache layer is entirely in-process.

**Actual mechanism**

The cache is a hand-rolled, thread-safe in-memory store in `store/cache/cache.go` — a `sync.Map` plus an atomic item counter (`store/cache/cache.go:66-73`), behind a small `Interface` (`:11-32`). It is per-process and non-shared, so it does not survive a restart and is not coherent across multiple instances.

**Configuration site.** Not a connection string but a `cache.Config` literal built in `store.New`, `store/store.go:39-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

The same config value is used to construct three separate caches at `store/store.go:51-53`: `instanceSettingCache`, `userCache`, and `userSettingCache`. These are the only caches; there is no configurable backend selection. The identical defaults are also declared in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), though `store.New` builds its own literal rather than calling it.

**TTL for user entries: 10 minutes.** Every write to the user cache goes through `Set`, never `SetWithTTL` — see `store/user.go:98`, `:122`, `:132`, `:143`, and `:167`. `Cache.Set` forwards to `SetWithTTL` using `c.config.DefaultTTL` (`store/cache/cache.go:93-95`), which is the 10 minutes configured above. So user entries expire 10 minutes after their last write, with a background cleanup goroutine sweeping expired entries every 5 minutes (started at `store/cache/cache.go:83`, stopped by `Close` at `:187`, which `Store.Close` invokes at `store/store.go:75`).

Two practical caveats: the 1000-item `MaxItems` cap is shared per cache, so a busy instance can evict users before their TTL expires; and `Store.GetUser` only consults the cache when looking up by ID (`store/user.go:149-156`), so username-based lookups always hit the database regardless of TTL.
