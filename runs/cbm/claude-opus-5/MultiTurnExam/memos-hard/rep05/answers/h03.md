**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation).**

Details:

- **Abstraction — `internal/idp/idp.go`**: the package is deliberately thin. It defines a single shared type, `IdentityProviderUserInfo` (`internal/idp/idp.go:3-8`), with `Identifier`, `DisplayName`, `Email`, and `AvatarURL`. This is the normalized user shape every provider must produce; note there's no Go `interface` here — the contract is the return type plus the `ExchangeToken`/`UserInfo` method pair that the concrete provider implements.

- **Implementation — `internal/idp/oauth2/oauth2.go`**: OAuth2 is the only concrete protocol that ships. `IdentityProvider` wraps a `storepb.OAuth2Config` (`:20-22`); `NewIdentityProvider` validates that `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier` are non-empty (`:27-43`). `ExchangeToken` (`:47`) uses `golang.org/x/oauth2` and supports PKCE by passing `code_verifier` when supplied (`:64-66`). `UserInfo` (`:83`) GETs the userinfo endpoint with a 10s timeout and a bearer token, then maps arbitrary claims onto `idp.IdentityProviderUserInfo` through the configured field mapping (`:114-140`), erroring if the identifier claim is missing.

**Wiring**: the SSO flow dispatches on provider type in `server/router/api/v1/auth_service_sso.go:120-134` — the only branch is `storepb.IdentityProvider_OAUTH2`, which constructs the OAuth2 provider, exchanges the code, and fetches user info. An identifier allowlist regex is then applied at `:136-145`. Admin CRUD for providers lives in `server/router/api/v1/idp_service.go`, which likewise only handles `Oauth2Config` (`:192-194`, `:227-229`). OIDC/SAML/LDAP providers are not implemented.
