**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard via `safeDialContext` on the shared client's `Transport`, backed by `isReservedIP`/`reservedCIDRs` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:14-54`.**

How it fits together:

**Delivery path**
- Memo create/update/delete events build the payload and call `webhook.PostAsync` at `server/router/api/v1/memo_service_webhooks.go:43` and `:71`.
- `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel (`:39`), dropping with a warning when full. Four worker goroutines started in `init()` (`:42-55`) drain the queue, and each one calls `Post`.
- `Post` (`internal/webhook/webhook.go:120`) is where the request actually goes out: it marshals the JSON body, optionally adds Standard-Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`, `:133-150`), and issues `safeClient.Do(req)` at `:152`, with the response body capped at 1 MiB (`:158`).

**Protection**
- The dispatch client is a package-level `safeClient` with a 30s timeout whose `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`).
- `safeDialContext` (`:59-77`) resolves the hostname *at dial time* and rejects the connection if **any** resolved address is in a reserved range. Because the check runs on each dial rather than only at configuration time, it also defeats DNS rebinding — the comment at `:29-31` states this intent.
- The range list is `reservedCIDRs` in `internal/webhook/validate.go:14-23`: IPv4 loopback, all three RFC-1918 blocks, link-local `169.254.0.0/16` (covering cloud IMDS at 169.254.169.254), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`. Parsed once into `reservedNetworks` in `init()` (`:28-36`) and matched by `isReservedIP` (`:44`).

**Second, earlier layer**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) runs when a user saves a webhook — scheme must be http/https and the hostname must not resolve into a reserved range. Called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. This is defense-in-depth only; the dial-time check is what actually protects delivery.

**Escape hatch**: the package var `AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` to `false`, disabling both layers for self-hosted setups. Note that in the current tree nothing outside of tests assigns it — the `--allow-private-webhooks` flag mentioned in `CHANGELOG.md:121` has no corresponding wiring in `cmd/`, so the guard is effectively always on at runtime.
