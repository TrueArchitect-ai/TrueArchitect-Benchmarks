**Premise correction: there is no rate-limiting middleware in this repository — per-user or otherwise.** No registration site exists and no request limits are defined, so the question has no answer as posed.

Evidence:

- A case-insensitive grep for `rate.?limit|ratelimit|throttl` across all Go files yields exactly one hit, and it is an aspirational comment, not code: `internal/email/doc.go:86` — `//   - Rate limit email sending to prevent abuse`. No corresponding implementation exists.
- No rate-limiting dependency is present in `go.mod` — neither `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, nor any equivalent.
- The complete Echo middleware stack is two entries, registered at `server/server.go:51-52`: `middleware.Recover()` and `newCORSMiddleware(profile)`. Neither limits request rates.
- The complete Connect interceptor chain is four entries, at `server/router/api/v1/v1.go:133-138`: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor`. The gRPC-Gateway path adds only `gatewayAuthMiddleware` (`v1.go:69`, applied at `:97`). All are auth/logging/recovery — none count or reject by frequency.

**What does exist, and is easy to mistake for rate limiting:**

- **Concurrency caps (not rate limits).** Weighted semaphores bound how many expensive operations run *simultaneously*, with no per-user dimension and no time window: `semaphore.NewWeighted(3)` for thumbnails and `semaphore.NewWeighted(2)` for image processing in `server/router/api/v1/v1.go:59-60`, plus `maxConcurrentThumbnails` in the file server at `server/router/fileserver/fileserver.go:116`. A single client can issue unlimited requests; they just queue.
- **Request size caps.** `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141` bounds body size per request, not request count.
- **A bounded work queue.** The webhook dispatch channel holds 128 items and drops overflow (`internal/webhook/webhook.go:39`, `:189-195`) — backpressure on outbound deliveries, unrelated to inbound API traffic.

If rate limiting is a requirement, it would need to be added — the natural insertion points are the Echo middleware stack at `server/server.go:51` (covers `/file`, RSS, and the gateway) and the Connect interceptor chain at `server/router/api/v1/v1.go:133`, where `NewAuthInterceptor` already resolves the caller's identity that a per-user limiter would key on.
