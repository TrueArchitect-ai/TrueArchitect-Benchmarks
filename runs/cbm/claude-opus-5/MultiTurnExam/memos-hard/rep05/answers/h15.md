h15.

Memo visibility is enforced at **14 distinct sites across 5 server surfaces**. All compare against the `store.Visibility` constants (`Public` / `Protected` / `Private`).

**gRPC/Connect API — `server/router/api/v1/`**
- `checkMemoReadAccess` (single-memo read gate; also gates archived memos) — `server/router/api/v1/memo_service.go:45-66`
- `ListMemos` (query-scoping: anonymous → `[PUBLIC]`; authenticated → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:218-227`
- `checkAttachmentAccess` — `server/router/api/v1/attachment_service.go:445-453`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:214-224`
- `ListMemoReactions` — `server/router/api/v1/reaction_service.go:30-40`
- `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:83`
- `CreateMemoComment` (parent-memo gate) — `server/router/api/v1/memo_service_comments.go:41`
- `ListAllUserStats` — `server/router/api/v1/user_service_stats.go:84-90`
- `GetUserStats` — `server/router/api/v1/user_service_stats.go:218-220`
- `canUserAccessMentionContext` (suppresses mention notifications for memos the target can't see) — `server/router/api/v1/memo_mention_helpers.go:62-84`
- `canViewerAccessMemo` (in-app notification gate) — `server/router/api/v1/user_service_notifications.go:309-312`

**SSE broadcast — `server/router/api/v1/`**
- `SSEClient.canReceive` (per-connection delivery filter; `Private` → creator or admin only, unknown visibility → deny) — `server/router/api/v1/sse_hub.go:134-144`, applied in the broadcast loop at `:120-131`

**Static file server — `server/router/fileserver/`**
- `checkAttachmentPermission` (public + anonymous-allowed → open; then share-token fallback; then authenticated user, with `Private` restricted to creator or admin) — `server/router/fileserver/fileserver.go:650`, checks at `:677` and `:699`

**RSS feeds — `server/router/rss/`**
- `GetExploreRSS` — `server/router/rss/rss.go:90` (`VisibilityList: [Public]`)
- `GetUserRSS` — `server/router/rss/rss.go:141` (`VisibilityList: [Public]`)

**Sitemap — `server/router/frontend/`**
- `getSitemapXML` — `server/router/frontend/frontend.go:150` (`VisibilityList: [Public]`)

**Email notifications — `server/notification/`**
- `canViewerAccessMemo` — `server/notification/email.go:306-320` (admin bypass; `Private` → creator only; `Protected` → any authenticated viewer)

Two things worth noting. The policy is duplicated rather than centralized — `canViewerAccessMemo` exists as two independent near-identical functions (`server/notification/email.go:306` and `server/router/api/v1/user_service_notifications.go:309`), and the admin-bypass rule is spelled differently across sites (`isSuperUser(user)` in the API service vs. `user.Role != store.RoleAdmin` in the fileserver vs. no bypass at all in `checkMemoReadAccess` at `memo_service.go:63`). Also, the fileserver is the only surface that accepts a share token as an alternative to visibility (`fileserver.go:682-689`).
