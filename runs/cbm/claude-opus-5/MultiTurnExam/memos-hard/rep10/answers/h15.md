Two structural notes. First, enforcement splits into two idioms: **post-fetch permission checks** on single-object reads (`checkMemoReadAccess`, `checkAttachmentAccess`, `checkAttachmentPermission`) and **query-level filtering** via `FindMemo.VisibilityList` on list endpoints (ListMemos, RSS, sitemap, stats) — the latter never loads non-visible rows at all. Second, `checkAttachmentPermission` is the only site with a **share-token bypass** (`server/router/fileserver/fileserver.go:682-688`): a valid, unexpired `share_token` scoped to that exact memo grants access to Private/Protected attachments, which is how the shared-memo page loads images. The MCP router (`server/router/mcp/`) contains no visibility logic of its own — grep returns nothing — so it relies on the API-layer checks above.
