**Premise correction: there is no rate-limiting middleware in this codebase — per-user or otherwise. It is not registered anywhere, so there are no request limits to report.**

Evidence:

- A case-insensitive search across all Go sources and `go.mod` for `ratelimit`, `rate_limit`, "rate limit", `throttl`, and the usual token-bucket dependency `golang.org/x/time/rate` returns exactly one hit: a comment in a doc file listing it as something a caller might want to do — `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"). No implementation accompanies it.

- The complete middleware/interceptor stack is short and contains nothing rate-related:
  - Echo level (`server/server.go:51-52`): `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go:14`).
  - Connect/gRPC level (`server/router/api/v1/v1.go:133-138`): `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor`.

What does exist nearby — worth naming, since these are the closest things to a limit and are easy to mistake for one:

- **Request body size cap**: `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` on the gateway (`server/router/api/v1/v1.go:126`) and the Connect mux (`:144`), plus `connect.WithReadMaxBytes` (`:141`). This bounds per-request size, not request frequency.
- **Concurrency semaphores**: `semaphore.NewWeighted(3)` for thumbnail generation and `semaphore.NewWeighted(2)` for image processing (`server/router/api/v1/v1.go:59-60`). These cap simultaneous CPU-heavy operations server-wide; they queue rather than reject, and are not scoped per user.
- **Webhook dispatch queue**: a bounded 128-slot channel with 4 workers that *drops* events when full (`internal/webhook/webhook.go:39`, `:189-195`) — outbound, not inbound.

So if you need per-user API rate limiting, it would be new work. The natural insertion point is the Connect interceptor chain at `server/router/api/v1/v1.go:133`, where the authenticated user is already resolved by `NewAuthInterceptor` — though note the file server (`server/router/fileserver/fileserver.go:121`) and RSS routes bypass that chain entirely and would need separate coverage.
