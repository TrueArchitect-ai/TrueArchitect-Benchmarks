**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

Details:

- **Abstraction package: `internal/idp`.** It is deliberately thin — `internal/idp/idp.go` defines only the `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`), the normalized shape every provider must produce. Note there is no Go `interface` here; the abstraction is the shared result type plus a de-facto method contract (`ExchangeToken` + `UserInfo`) that the concrete provider satisfies. The type discriminator lives in the proto layer as `IdentityProvider_Type` (`proto/gen/store/idp.pb.go:24`), whose only non-zero value is `IdentityProvider_OAUTH2 = 1`.

- **Implementation package: `internal/idp/oauth2`.** `internal/idp/oauth2/oauth2.go` implements the OAuth2 flow on top of `golang.org/x/oauth2`: `NewIdentityProvider` validates the required config fields (`:27`), `ExchangeToken` swaps the auth code for an access token with optional PKCE `code_verifier` support (`:47`), and `UserInfo` calls the configured userinfo endpoint and maps claims into `idp.IdentityProviderUserInfo` via the provider's configurable `FieldMapping` (`:83`).

- **Wiring.** `resolveSSOIdentity` in `server/router/api/v1/auth_service_sso.go:104` loads the provider record from the store, and dispatches on `identityProvider.Type == storepb.IdentityProvider_OAUTH2` (`:120`) to construct the OAuth2 provider — the single branch confirming OAuth2 is the only protocol that ships. OIDC is covered implicitly, since an OIDC provider is consumable through the generic OAuth2 config + userinfo endpoint rather than through a dedicated implementation.
