**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`. Triggers: memo creation, memo content updates, and comment creation (which routes through create). Extracted: `Tags` plus a `Property` message of `Title`, `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks`.**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`) initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, and assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`:85-86`). The real work is `ExtractAll` (`internal/markdown/markdown.go:356`), which parses the content once and does a single `gast.Walk` over the goldmark AST — deliberately one pass rather than separate extract calls per property.

**Triggers (all in the API layer):**

- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`, so the payload is persisted with the INSERT.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the `if path == "content"` branch of the update mask (`:436`). Updating visibility, pinned state, location, etc. does **not** recompute; the derived metadata is content-only by design.
- `CreateMemoComment` — indirectly: it delegates to `s.CreateMemo` (`server/router/api/v1/memo_service_comments.go:55`), so a comment's payload gets built by the same path.

Note the location field is *not* derived — `CreateMemo` sets `create.Payload.Location` separately at `memo_service.go:112` after the rebuild, so it isn't clobbered.

**What gets extracted** (`internal/markdown/markdown.go:373-410`, into `storepb.MemoPayload_Property`, `proto/gen/store/memo.pb.go:85-95`):

| Field | Derived from |
|---|---|
| `Tags []string` | `#tag` nodes from the custom tag extension, deduplicated preserving original case |
| `Property.Title` | text of the first block-level child *only if* it's an H1 heading (`:384-388`) |
| `Property.HasLink` | any `gast.KindLink` node |
| `Property.HasCode` | any code block, fenced code block, or inline code span |
| `Property.HasTaskList` | any GFM `TaskCheckBox` node |
| `Property.HasIncompleteTasks` | a `TaskCheckBox` with `IsChecked == false` |

`ExtractAll` also collects `Mentions` (lowercased `@username` nodes) into its `ExtractedData` return (`internal/markdown/markdown.go:21-25`), but `RebuildMemoPayload` discards that field — mentions are consumed separately for notifications via `s.MarkdownService.ExtractAll` in `server/router/api/v1/memo_mention_helpers.go:32`.

**One gap worth flagging:** there is no backfill path in production. `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) exists to recompute payloads for all memos in batches, but nothing constructs that runner — so memos written before a change to the extraction logic keep their stale payload until their content is next edited.
