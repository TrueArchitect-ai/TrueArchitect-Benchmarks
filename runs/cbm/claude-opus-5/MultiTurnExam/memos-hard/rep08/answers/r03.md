**Premise correction: there is no nightly database-cleanup job, and the cron scheduler is not wired into the running server at all.** There is no schedule to report.

Two separate corrections:

**1. No cleanup job exists.** Nothing in the codebase performs periodic database cleanup, vacuuming, or purging. Grepping `server/`, `store/`, and `cmd/` for `cleanup|vacuum|purge|nightly|cron` turns up only unrelated things: inline cleanup during user/memo deletion (`server/router/api/v1/user_service.go:421-450`, `server/router/api/v1/memo_service.go:579`), a test helper (`server/router/api/v1/test/test_helper.go:65`), and the in-memory cache's expiry sweep (`store/cache/cache.go:199-201`, every 5 minutes per `CleanupInterval` — an in-process map sweep, not a database job).

**2. The cron scheduler is unused.** `internal/scheduler` is a fully-built, GitHub-Actions-inspired cron package (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`, plus a README and `doc.go`), but nothing in production imports it. The only files importing `github.com/usememos/memos/internal/scheduler` are its own tests: `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No `scheduler.New()` or `scheduler.Register(...)` call exists outside the package's docs and tests, so no cron expression is ever registered.

**What actually runs on a schedule.** Exactly one background job, and it is not cleanup-related: the S3 presign refresher. `s3presign.Runner` runs on a fixed 12-hour `time.Ticker` (`runnerInterval` at `server/runner/s3presign/runner.go:27`, loop at `:29-41`), started from `Server.startBackgroundRunners` at `server/server.go:162-171` with one immediate pass at boot. It is interval-based, not clock-anchored — there is no "time of day" it fires at; the phase depends on when the process started.
