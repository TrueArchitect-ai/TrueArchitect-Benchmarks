**Premise correction: there is no Redis anywhere in this project.** Caching is entirely in-process. A case-insensitive grep for `redis` across all `.go` files returns nothing, and `go.mod` has no Redis client dependency (no `go-redis`, `redigo`, or similar). There is no connection string, host/port setting, or config flag to point at an external cache — `cmd/memos/main.go` exposes only `driver`, `dsn`, `data`, `addr`, `port`, `unix-sock`, `instance-url`, `demo`, and `allow-private-webhooks`.

**Actual mechanism.** `store/cache/cache.go` implements a self-contained, thread-safe in-memory cache: a `sync.Map` of `item{value, expiration, size}` (`cache.go:35-39`) behind the `Interface` at `cache.go:11-32`, with an atomic item counter and a background cleanup goroutine.

The `Store` creates three independent instances in `store.New` (`store/store.go:38-53`), all sharing one config literal (`store/store.go:40-45`):

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

applied to `instanceSettingCache`, `userCache`, and `userSettingCache`. The same values appear in `cache.DefaultConfig()` (`store/cache/cache.go:56-63`), though `store.New` uses its own literal rather than calling it.

**TTL for user entries: 10 minutes.** Every write to `userCache` uses the plain `Set` (`store/user.go:98,122,132,143,167`), which applies `DefaultTTL` — `SetWithTTL` is never called for users. Expiry is enforced lazily on read: `Get` compares `time.Now()` against `itm.expiration` and evicts on miss (`store/cache/cache.go:134-146`), backed by the 5-minute sweep. Entries are also capped at 1000 items, evicting oldest via `cleanupOldest` (`cache.go:116-118`), and explicitly invalidated on user deletion (`store/user_delete.go:40`).

One detail worth knowing: the user cache is keyed by ID (`userCacheKey(user.ID)`), and `Store.GetUser` only consults it when the lookup is by ID (`store/user.go:149-156`) — lookups by username or email always hit the database regardless of TTL.
