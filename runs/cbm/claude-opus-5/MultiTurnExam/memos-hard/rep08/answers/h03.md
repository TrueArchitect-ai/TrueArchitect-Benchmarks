**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction**: `internal/idp/idp.go` — the package is deliberately thin. It defines only the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) at `internal/idp/idp.go:3-8`. There is no Go `interface` type here; the abstraction is the normalized user-info shape that every provider implementation must produce, plus the `IdentityProvider_Type` enum in the store protos.

- **Implementation**: `internal/idp/oauth2/oauth2.go` — the only concrete protocol that ships. It provides `NewIdentityProvider(*storepb.OAuth2Config)` with required-field validation (`oauth2.go:26-42`), `ExchangeToken` for the authorization-code exchange with optional PKCE `code_verifier` (`oauth2.go:45-79`), and `UserInfo`, which calls the configured userinfo endpoint with a bearer token and maps arbitrary claims into `idp.IdentityProviderUserInfo` via the provider's configured `FieldMapping` (`oauth2.go:83-141`).

- **Wiring**: SSO login dispatches on provider type at `server/router/api/v1/auth_service_sso.go:120-121` — `if identityProvider.Type == storepb.IdentityProvider_OAUTH2`, then exchange token → fetch user info. Since OAuth2 is the only branch, a provider of any other type would fall through with a nil `userInfo`. Provider CRUD lives in `server/router/api/v1/idp_service.go`.
