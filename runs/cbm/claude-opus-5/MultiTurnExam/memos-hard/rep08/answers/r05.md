**Premise correction: this project has no GraphQL API.** There is no schema, no resolver layer, and no GraphQL dependency. Searching all Go, TypeScript, and module files for `graphql`/`gqlgen` returns zero hits, and `find` locates no `.graphql` or `.gql` files anywhere in the repo.

**Actual API surface: Protocol Buffers / gRPC, exposed over HTTP three ways.**

**Schema definition** — `.proto` files in `proto/api/v1/`:
- `memo_service.proto`, `user_service.proto`, `attachment_service.proto`, `auth_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto`

Internal persistence messages live separately in `proto/store/` (e.g. `proto/store/memo.proto`). Codegen is driven by buf (`proto/buf.gen.yaml`, `proto/buf.yaml`) into `proto/gen/` — producing gRPC stubs (`*_grpc.pb.go`), grpc-gateway handlers (`*.pb.gw.go`), Connect handlers (`proto/gen/api/v1/apiv1connect/`), and an embedded OpenAPI document (`proto/openapi_embed.go`).

**Runtime surfaces**, all registered in `NewServer` (`server/server.go:43-97`) on an Echo v5 server:

| Surface | Registration | Notes |
|---|---|---|
| gRPC-Gateway REST + Connect RPC | `apiV1Service.RegisterGateway(ctx, echoServer)` — `server/server.go:87`, implemented at `server/router/api/v1/v1.go:65` | The main API; shared auth via `NewAuthorizer` |
| File serving | `fileServerService.RegisterRoutes(echoServer)` — `server/server.go:82` | `/file/attachments/:uid/:filename`, `/file/users/:identifier/avatar` (`server/router/fileserver/fileserver.go:118-121`) |
| RSS feeds | `rss.NewRSSService(...).RegisterRoutes(rootGroup)` — `server/server.go:85` | `server/router/rss/rss.go` |
| MCP | `mcpService.RegisterRoutes(echoServer)` — `server/server.go:96` | Model Context Protocol bridge; whitelists existing RPCs in `server/router/mcp/catalog.go` |
| Static frontend | `frontend.NewFrontendService(...).Serve(...)` — `server/server.go:71` | SPA + sitemap |
| Health check | `echoServer.GET("/healthz", ...)` — `server/server.go:66` | |

So the closest analogue to "the schema for the public API" is `proto/api/v1/*.proto`, with the generated OpenAPI spec in `proto/gen/` as the HTTP-facing description.
