**`*markdown.service` (the single unexported goldmark-backed impl) — constructed once by `NewAPIV1Service` via `markdown.NewService(...)` — held by `APIV1Service.MarkdownService`, `RSSService.MarkdownService`, and (unused) `memopayload.Runner.MarkdownService`**

**The interface.** `markdown.Service` is declared at `internal/markdown/markdown.go:31-56` with eight methods (`ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`).

**The implementation — exactly one.** The unexported `service` struct (`internal/markdown/markdown.go:59-61`) wraps a `goldmark.Markdown` and implements all eight methods (`markdown.go:143, 193, 244, 255, 264, 349, 356, 425`). It is the only type in the repo satisfying the interface — no alternate backends and no test mocks; every reference to `markdown.Service` is a field or parameter type, never a second implementation.

**Construction.** `markdown.NewService(opts ...Option) Service` (`internal/markdown/markdown.go:85-110`) builds a goldmark instance with GFM plus optionally the repo's own tag and mention extensions, returning `&service{md: md}`. Non-test call sites:

- `server/router/api/v1/v1.go:48-51` — `NewAPIV1Service` creates it with **both** `markdown.WithTagExtension()` and `markdown.WithMentionExtension()`. This is the only production construction; the resulting value is assigned to `APIV1Service.MarkdownService` at `v1.go:55`.
- The other three calls are test-only: `server/router/rss/rss_test.go:54`, `server/router/fileserver/fileserver_test.go:427`, `server/router/api/v1/test/test_helper.go:44`.

So at runtime a single instance exists, and it is shared rather than re-created.
