**Handlers: `CreateMemo`, `UpdateMemo`, `DeleteMemo`, `CreateMemoComment`, `SetMemoAttachments`, `SetMemoRelations` — convergence: `webhook.Post` — `internal/webhook/webhook.go:120`**

All six are `APIV1Service` RPC methods that end up dispatching a user's configured webhook URLs (`store.GetUserWebhooks` → `payload.URL = hook.Url`):

| Handler | Location | Path to dispatch |
|---|---|---|
| `CreateMemo` | `server/router/api/v1/memo_service.go:70` | → `DispatchMemoCreatedWebhook` (`memo_service.go:157`) |
| `UpdateMemo` | `memo_service.go:401` | → `dispatchMemoUpdatedSideEffects` (`memo_service.go:513`) → `DispatchMemoUpdatedWebhook` (`memo_update_helpers.go:67`) |
| `DeleteMemo` | `memo_service.go:518` | → `DispatchMemoDeletedWebhook` (`memo_service.go:562`) |
| `CreateMemoComment` | `memo_service_comments.go:20` | → `DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`) |
| `SetMemoAttachments` | `memo_attachment_service.go:16` | → `dispatchMemoUpdatedSideEffects` (`memo_attachment_service.go:48`) |
| `SetMemoRelations` | `memo_relation_service.go:16` | → `dispatchMemoUpdatedSideEffects` (`memo_relation_service.go:48`) |

The four `Dispatch*Webhook` entry points all funnel through `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`) or its comment sibling (`:30`), both of which call `webhook.PostAsync` (`memo_service_webhooks.go:43,71`). `PostAsync` only enqueues onto a bounded channel (`internal/webhook/webhook.go:184`); the actual outbound request is issued by **`webhook.Post`** at `internal/webhook/webhook.go:120`, called from the four worker goroutines started in that package's `init()` (`webhook.go:42-55`). That is the single function every path passes through before delivery — and the one place `safeClient.Do` runs (`webhook.go:152`), which is why the SSRF dial guard sits there.

Two notes on scope:

- The webhook-management RPCs (`CreateUserWebhook` at `user_service_webhooks.go:53`, `UpdateUserWebhook` at `:106`) touch the user-supplied URL but do **not** make an outbound HTTP request — `webhook.ValidateURL` only parses and does a DNS resolution (`internal/webhook/validate.go:62-83`). There is no "test webhook" RPC.
- A separate outbound-HTTP path exists via `fetchHTMLMeta = httpgetter.GetHTMLMeta` (`memo_service.go:28`) for link previews, but that fetches a URL passed in the request rather than a stored user-configured endpoint, and it does not pass through `webhook.Post`.
