**`webhook.Post` — `internal/webhook/webhook.go:120`; SSRF guard via `safeDialContext` / `isReservedIP` blocklist — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path.** Memo create/update/delete/comment events call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43,71`, which only enqueues onto a bounded 128-slot channel (`webhook.go:184-196`, dropping with a warning when full). The actual HTTP POST happens in `webhook.Post` (`webhook.go:120-180`), run by four worker goroutines started in `init()` (`webhook.go:42-55`). `Post` marshals the payload, optionally adds Standard-Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, `webhook.go:133-150`), and issues the request with `safeClient.Do` (`webhook.go:152`).

**Protection.** Two layers, both keyed off `isReservedIP` (`internal/webhook/validate.go:44`), which tests the address against the parsed `reservedCIDRs` list — IPv4 loopback, RFC-1918 ranges, link-local `169.254.0.0/16` (cloud IMDS), and IPv6 `::1/128`, `fc00::/7`, `fe80::/10` (`validate.go:14-36`):

1. **Dial-time enforcement**, the one that actually protects delivery: `safeClient`'s transport uses `safeDialContext` (`webhook.go:32-37, 59-77`), which resolves the host itself and refuses the connection if any resolved IP is reserved. Because this runs at dial time on every request, it also defeats DNS rebinding and redirect-based bypasses.
2. **Admission-time validation**: `webhook.ValidateURL` (`validate.go:62`) rejects non-http(s) schemes and private-resolving hostnames when a webhook is registered or updated — `server/router/api/v1/user_service_webhooks.go:74,161,182`.

One thing worth flagging: `AllowPrivateIPs` (`validate.go:41`) disables both layers when true, but nothing in the codebase ever sets it — no flag, env var, or config wires it up, so it is effectively always `false` outside of tests.
