
Shape of the rule at each site:

- **`checkMemoReadAccess`** (`memo_service.go:39-67`) is the closest thing to a canonical gate: archived memos are creator-only; non-public memos require an authenticated user; private memos require `memo.CreatorID == user.ID`. Note it has only three callers — `GetMemo` (`memo_service.go:356`), its parent-memo check (`:367`), and `ListMemoComments` (`memo_service_comments.go:148`). Every other site below re-implements the logic rather than calling it.

- **List-style sites** enforce by narrowing the query instead of rejecting: anonymous → `VisibilityList = [PUBLIC]`; authenticated → a CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`, or `[PUBLIC, PROTECTED]` when listing another user's memos (`memo_service.go:217-226`, mirrored almost verbatim in `user_service_stats.go`).

- **The two attachment gates differ from the memo gate** in that both admit admins: `!isSuperUser(user)` in the API layer (`attachment_service.go:451`, `memo_attachment_service.go:222`) and `user.Role != store.RoleAdmin` in the file server (`fileserver.go:699`).

- **`fileserver.checkAttachmentPermission`** is the only site with a share-token bypass: a valid, unexpired `share_token` query param matching that memo grants access to private/protected attachments (`fileserver.go:684-690`). It also conditions anonymous access to public memos on `s.Profile.AllowAnonymous()` (`fileserver.go:677`).

- **`SSEClient.canReceive`** (`sse_hub.go:134`) filters push delivery: private events only to the creator or an admin; public/protected (and empty visibility) to everyone; unknown values are denied with a warning.

- The **mention/notification helpers** use visibility to decide whether someone may be told a memo exists — a disclosure gate rather than a read gate, which is why I've grouped them on one line.
