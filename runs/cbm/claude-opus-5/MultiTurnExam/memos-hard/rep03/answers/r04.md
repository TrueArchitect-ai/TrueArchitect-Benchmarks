**Premise correction: neither. There is no message broker in this repository — no NATS, RabbitMQ, AMQP, Kafka, or SQS client appears in any Go file, `go.mod`, or `go.sum`, and there is no queue declaration anywhere.** (A case-insensitive sweep for those terms returns a single incidental match inside a base64 checksum on `go.sum:63`, which is unrelated.)

**Actual mechanism — an in-process buffered Go channel with a fixed worker pool, all in `internal/webhook/webhook.go`:**

- **The "queue"** is a package-level buffered channel holding 128 payloads: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`). That line is the closest thing to a queue declaration.

- **The workers** are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over the channel and calls `Post` for every payload, logging a warning on failure. Because they're launched from `init()`, they start when the package is first loaded rather than being wired up at server startup, and there is no shutdown path that drains or stops them.

- **Enqueue** happens in `PostAsync` (`internal/webhook/webhook.go:184-196`), called from the memo dispatch helpers (`server/router/api/v1/memo_service_webhooks.go:43`, `:71`). It is a non-blocking send with a `default` branch: **when the buffer is full the payload is dropped**, with a warning naming the URL and activity type (`webhook.go:191-194`). There is no retry, no persistence, and no dead-letter path — an overloaded or slow receiver means silently lost deliveries.

- **Delivery** is `Post` (`internal/webhook/webhook.go:120`), which builds the JSON request, optionally signs it with Standard Webhooks HMAC headers, and sends via `safeClient.Do` (`webhook.go:152`) under a 30-second timeout (`webhook.go:27`).

Practical consequences of this being in-process rather than broker-backed: queued deliveries do not survive a restart, they aren't shared or load-balanced across replicas (each instance has its own 128-slot buffer and 4 workers), and back-pressure manifests as dropped events rather than as blocking or accumulation.
