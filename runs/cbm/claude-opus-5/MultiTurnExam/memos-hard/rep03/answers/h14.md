**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`; Triggers: `CreateMemo` and `UpdateMemo` (only when `content` is in the update mask); Extracted: deduplicated `Tags` plus a `Property` of `Title`, `HasLink`, `HasCode`, `HasTaskList`, `HasIncompleteTasks`.**

**Where it's computed.** `RebuildMemoPayload` (`server/runner/memopayload/runner.go:74-88`) initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, then assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`runner.go:85-86`). The real work is one goldmark AST walk in `ExtractAll` (`internal/markdown/markdown.go:356-421`) — deliberately a single parse for all metadata rather than one pass per field.

**What gets extracted** (`internal/markdown/markdown.go:373-405`, stored as `storepb.MemoPayload_Property`, `proto/gen/store/memo.pb.go:85-95`):

- `Tags` — every `#tag` node, deduplicated by `uniquePreserveCase` while preserving original casing (`markdown.go:417`)
- `Title` — text of the first H1, but only if that heading is the document's first block-level child (`markdown.go:384-390`)
- `HasLink` — any `KindLink` node
- `HasCode` — any code block, fenced code block, or inline code span
- `HasTaskList` — any task checkbox
- `HasIncompleteTasks` — a task checkbox that is unchecked (`markdown.go:400-404`)

`ExtractAll` also collects `Mentions` (lowercased) into `ExtractedData` (`markdown.go:22-25`), but `RebuildMemoPayload` doesn't persist that field — it's used elsewhere for notifications.

**Triggers — exactly two, both in the API layer:**
1. `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before the insert.
2. `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, inside the `path == "content"` branch of the field-mask loop; the recomputed payload is then attached to the update at `:451`. Editing only visibility, pinned state, etc. does **not** recompute it.

A third potential trigger is dead: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) would rebuild payloads for all memos in batches, but nothing constructs that runner.

**How it's consumed.** `convertMemoFromStoreWithCreators` copies `Tags` and `Property` onto the API response (`server/router/api/v1/memo_service_converter.go:48-49`), and `user_service_stats.go:138-151` and `:254-267` aggregate them for the stats/activity views.

One related-but-distinct thing worth separating: the memo **`Snippet`** shown in previews is *not* stored. It's generated per-request via `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_converter.go:76-80`, `server/router/api/v1/memo_service_webhooks.go:85`), so it's derived at read time rather than persisted in the payload.
