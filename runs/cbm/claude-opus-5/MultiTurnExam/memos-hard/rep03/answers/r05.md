**Premise correction: there is no GraphQL in this repository.** Searching all `.go`, `.ts`, `.tsx`, `.json`, and `go.mod` files for `graphql`/`gqlgen` returns zero matches, and there are no `.graphql` or `.gql` schema files anywhere in the tree. No resolver layer, no schema-first or code-first GraphQL server exists.

**Actual API surface — Protobuf-defined RPC services, exposed over three HTTP transports:**

**Schema definition.** The single source of truth is the `.proto` files in `proto/api/v1/`: `memo_service.proto`, `user_service.proto`, `attachment_service.proto`, `auth_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, and shared types in `common.proto`. Each declares a service with RPCs annotated by `google.api.http` bindings — e.g. `MemoService` at `proto/api/v1/memo_service.proto:17`, with `CreateMemo` bound to `POST /api/v1/memos` (`:22-25`) and `GetMemo` to `GET /api/v1/{name=memos/*}` (`:35`). The style follows Google AIP resource naming (`memos/{uid}`, `users/{username}`).

**Code generation.** `proto/buf.gen.yaml` drives buf with plugins for Go protobuf, gRPC, Connect, grpc-gateway, gnostic-openapi, and `bufbuild/es` (TypeScript). Output lands in `proto/gen/` for Go and `web/src/types/proto` for the frontend client.

**Runtime transports**, all registered in `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`):
1. **REST/JSON via grpc-gateway** — the `/api/v1/...` paths from the `google.api.http` annotations; generated handlers live in `proto/gen/api/v1/*.pb.gw.go`.
2. **Connect RPC** — mounted at `/memos.api.v1.*` (`server/router/api/v1/v1.go:139-144`), using the generated `proto/gen/api/v1/apiv1connect/` handlers.
3. **Plain HTTP file routes**, outside the proto surface: `/file/attachments/:uid/:filename` and `/file/users/:identifier/avatar` (`server/router/fileserver/fileserver.go:123-124`), plus RSS feeds under `server/router/rss/rss.go`.

**Machine-readable spec.** Instead of a GraphQL schema, the repo ships a generated OpenAPI document: `proto/gen/openapi.yaml`, embedded into the binary via `//go:embed` at `proto/openapi_embed.go:4-10`. There's also an MCP server surface (`server/router/mcp/`) that builds its tool catalog from that OpenAPI spec (`server/router/mcp/openapi.go`, `catalog.go`).
