**Premise correction: there is no rate-limiting middleware in this repository — per-user or otherwise. No such component is registered, so there are no request limits to report.**

What I checked:

- A case-insensitive search across all `.go` and `.mod` files for `ratelimit`, `rate_limit`, `rate limit`, `throttl`, `RateLimiter`, and the usual token-bucket dependency `golang.org/x/time/rate` returns exactly one hit, and it's an aspirational comment rather than code: `internal/email/doc.go:86` — `//   - Rate limit email sending to prevent abuse`. Echo's built-in `middleware.RateLimiter` is not imported anywhere.

- The full set of registered Echo middleware is small and contains nothing of the kind: `middleware.Recover()` (`server/server.go:51`), the CORS middleware (`server/server.go:52`, configured in `server/cors.go:14`), and on the frontend router `middleware.StaticWithConfig` plus `spaFallbackMiddleware` (`server/router/frontend/frontend.go:54`, `:59`). The API surface adds an auth middleware for the gRPC-Gateway and a matching Connect interceptor (`server/router/api/v1/v1.go:65-95`), which enforce authentication and access policy — not request volume.

The closest things that exist are **concurrency caps, not rate limits** — they bound simultaneous in-flight work to protect memory, and impose no per-user quota or requests-per-interval budget:

- `thumbnailSemaphore` — `semaphore.NewWeighted(3)` at `server/router/api/v1/v1.go:59` and `server/router/fileserver/fileserver.go:116` (constant `maxConcurrentThumbnails = 3`, `fileserver.go:46`)
- `imageProcessingSemaphore` — `semaphore.NewWeighted(2)` at `server/router/api/v1/v1.go:60`

Separately, there are content-size limits (the per-instance memo content-length check at `server/router/api/v1/memo_service.go:101-107`) and a 30-second timeout on outbound webhook requests (`internal/webhook/webhook.go:27`), but again, none of these throttle inbound request rates. If you need per-user rate limiting, it would have to be added — most naturally as an Echo middleware alongside the CORS registration at `server/server.go:52`.
