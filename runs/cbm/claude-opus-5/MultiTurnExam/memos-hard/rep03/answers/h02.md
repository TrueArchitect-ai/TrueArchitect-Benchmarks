**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); SSRF guard is the dial-time reserved-IP check `safeDialContext` / `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path.** Memo create/update/delete/comment events call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43` and `:71`. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel (`asyncPostQueue`, `webhook.go:39`), dropping with a warning when full. Four worker goroutines started in `init()` (`webhook.go:42-55`) pull from that queue and call `Post`, which is where the request is built, optionally HMAC-signed with Standard Webhooks headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`, `webhook.go:139-149`), and sent.

**Protection.** Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`) against a parsed CIDR list covering IPv4 loopback, RFC-1918, link-local/cloud IMDS `169.254.0.0/16`, and the IPv6 equivalents (`validate.go:14-23`):

- *At send time* — `safeClient`'s `Transport.DialContext` is `safeDialContext` (`webhook.go:32-37`, `:59`), which re-resolves the host on every dial and refuses the connection if any resolved address is reserved. Because the check happens at dial rather than at save, it also defeats DNS rebinding, where a hostname validated as public later resolves to an internal address.
- *At configuration time* — `webhook.ValidateURL` (`validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user adds or updates a webhook, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

Two caveats worth noting: `AllowPrivateIPs` (`validate.go:41`) disables both layers when true — per `CHANGELOG.md:121` this was exposed as an `--allow-private-webhooks` flag, but in the current tree nothing outside tests assigns it, so it is effectively always `false`. And `safeDialContext` validates the resolved set but then dials by hostname (`webhook.go:76`), so the connection re-resolves independently of the addresses that were checked.
