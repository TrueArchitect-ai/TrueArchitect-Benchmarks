**Premise correction: there is no Redis anywhere in this repository.** A case-insensitive search for `redis` across all `.go`, `go.mod`, YAML, and JSON files returns zero matches — no client dependency, no connection string, no config key. The cache layer is a hand-rolled, process-local, in-memory cache.

**Actual mechanism:**

- **Implementation** — `store/cache/cache.go`. `Cache` (`cache.go:67-73`) is a `sync.Map` guarded by an atomic item counter, with per-entry expiration stored on each `item` (`cache.go:35-39`). It satisfies a small `Interface` (`cache.go:11-32`), and `Cache` is the only implementation.

- **Configuration site** — `store.New`, `store/store.go:39-44`. The `cache.Config` is built inline there, not read from any flag, env var, or config file, and the same config is passed to all three caches at `store/store.go:49-51`: `instanceSettingCache`, `userCache`, `userSettingCache`.

- **TTL for user entries — 10 minutes.** `DefaultTTL: 10 * time.Minute` (`store/store.go:40`). Nothing calls `SetWithTTL` for users; `Store.GetUser` and `Store.ListUsers` use the plain `Set` (`store/user.go:143`, `:167`), which applies `c.config.DefaultTTL` (`store/cache/cache.go:93-95`). The identical default also appears in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`), though `store.New` constructs its own literal rather than calling it.

Other properties of the user cache worth noting:

- **Eviction** — a `cleanupLoop` goroutine sweeps expired entries every 5 minutes (`CleanupInterval`, `store/store.go:41`; loop at `cache.go:200-215`). Expiry is also checked lazily on read (`cache.go:135-144`).
- **Capacity** — `MaxItems: 1000` (`store/store.go:42`); exceeding it triggers `cleanupOldest`, which drops roughly 20% of capacity (`cache.go:253-255`).
- **Keying** — the user cache is keyed by ID only. `Store.GetUser` consults it solely when `find.ID != nil` (`store/user.go:149-156`), so lookups by username always hit the database.
- **Scope** — because it lives in `sync.Map` inside the process, it is not shared across instances; a multi-replica deployment would have independent, potentially divergent caches. Shutdown stops the goroutines via `Store.Close` → `cache.Close` (`store/store.go:74-76`).
