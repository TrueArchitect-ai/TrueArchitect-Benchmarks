**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- **Abstraction — `internal/idp/idp.go`**: the shared, protocol-neutral piece is the `IdentityProviderUserInfo` struct (`internal/idp/idp.go:3-8`) — `Identifier`, `DisplayName`, `Email`, `AvatarURL`. This is the normalized shape every provider must produce, and it's what the SSO flow consumes: `resolveSSOUser` and `resolveSSOIdentity` both take/return `*idp.IdentityProviderUserInfo` (`server/router/api/v1/auth_service_sso.go:19`, `:104`, `:119`). Note this is a struct-only contract, not a Go `interface` — the package defines no method set for providers to satisfy.

- **Implementation — `internal/idp/oauth2`**: `oauth2.IdentityProvider` (`internal/idp/oauth2/oauth2.go:20`) wraps a `storepb.OAuth2Config`, with `NewIdentityProvider` validating that `clientId`, `clientSecret`, `tokenUrl`, `userInfoUrl`, and `fieldMapping.identifier` are all non-empty (`oauth2.go:27-42`), and `ExchangeToken` performing the code exchange via `golang.org/x/oauth2`, with optional PKCE `code_verifier` support (`oauth2.go:46`).

OAuth2 is the only protocol that ships. The store proto backs this up: the `IdentityProvider_Type` enum has exactly one real value, `IdentityProvider_OAUTH2 = 1` (`proto/gen/store/idp.pb.go:27-28`), and the `IdentityProviderConfig` oneof has a single variant, `Oauth2Config` (`proto/gen/store/idp.pb.go:215`). Persistence lives in `store/idp.go`, and the admin-facing API in `server/router/api/v1/idp_service.go`.
