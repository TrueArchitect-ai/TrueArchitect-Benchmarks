**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); SSRF protection = a dial-time reserved/private-IP block via `safeDialContext` + `isReservedIP` — `internal/webhook/webhook.go:59-77` and `internal/webhook/validate.go:44-54`.**

How it fits together:

- **Trigger → delivery path**: memo create/update/delete/comment events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43`, `:71`), which enqueues onto a bounded 128-slot channel (`webhook.go:39`, `:184-196`, dropping with a warning when full). Four worker goroutines started in `init()` (`webhook.go:42-55`) drain the queue and call `Post`, which marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook.go:133-150`), and dispatches through the shared `safeClient` (30s timeout, `webhook.go:26-37`).

- **Primary protection (dial time)**: `safeClient`'s `Transport.DialContext` is `safeDialContext`, which re-resolves the host and refuses to connect if *any* returned address is reserved (`webhook.go:59-77`). Because the check happens at dial time rather than at URL-save time, it also defeats DNS rebinding. Blocked ranges are in `reservedCIDRs` (`internal/webhook/validate.go:14-23`): IPv4 loopback, all three RFC-1918 blocks, 169.254.0.0/16 (cloud IMDS), plus IPv6 loopback/ULA/link-local.

- **Secondary protection (config time)**: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user registers or updates a webhook — called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

- **Escape hatch**: the package-level `webhook.AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted setups targeting LAN services. Note that in this tree nothing outside tests assigns it — the `--allow-private-webhooks` flag mentioned in `CHANGELOG.md:121` has no wiring in the current source, so the protection is effectively always on at runtime.
