**Premise correction: there is no Redis in this repository.** A case-insensitive grep for `redis` across the entire tree (excluding `.git`/`node_modules`) returns zero hits, and `go.mod` has no Redis client dependency. There is no external cache server, no connection string, and nothing to configure — caching is purely in-process.

**Actual mechanism.** The cache is a hand-rolled, thread-safe in-memory cache: `cache.Cache` in `store/cache/cache.go` (backed by a `sync.Map` plus an atomic item counter, `:65-72`), behind the `cache.Interface` declared at `store/cache/cache.go:11-32`.

**Where it's "configured":** `store.New` — `store/store.go:38-54`. It builds one `cache.Config` literal and hands the *same* config to three independent cache instances:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
... instanceSettingCache, userCache, userSettingCache: cache.New(cacheConfig)
```

**TTL for user entries: 10 minutes**, with expired entries swept by a background goroutine every 5 minutes (`cleanupLoop`, `store/cache/cache.go:199`), and the cache capped at 1000 items. Note this value is hardcoded twice — in `store.New` (`store/store.go:40-45`) and identically in `cache.DefaultConfig()` (`store/cache/cache.go:56-63`) — and is not exposed via any flag, env var, or profile field.

The user cache is populated in `Store.ListUsers` (`store/user.go:143`) and `Store.GetUser` (`store/user.go:167`), read only on ID-keyed lookups (`store/user.go:149-156`), and invalidated explicitly on delete via `deleteUserCache` (`store/user_delete.go:39-47`). All three caches are shut down through `Store.Close` → `Cache.Close` (`store/store.go:74-76`), which stops the cleanup goroutines.
