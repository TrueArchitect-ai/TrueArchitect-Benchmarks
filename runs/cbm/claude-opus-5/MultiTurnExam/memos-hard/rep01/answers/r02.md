**Premise correction: there is no per-user API rate-limiting middleware in this repository. Nothing is registered, so there are no request limits to report.**

Evidence:

- A case-insensitive grep for `ratelimit` / `rate-limit` / `rate limit` / `throttle` / `limiter` across all Go, TS/TSX, Markdown, and YAML files returns only two hits, both aspirational documentation about email — `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse", in a future-work comment) and `internal/email/README.md:286-295` (a sample snippet in a "things you could implement" section). Neither is wired into anything.
- `go.mod` has no rate-limiting dependency (no `golang.org/x/time/rate`, no `echo` rate-limiter middleware, no token-bucket library).
- The full Echo middleware stack is two entries: `middleware.Recover()` and `newCORSMiddleware(profile)` — `server/server.go:51-52`. The full Connect/gRPC interceptor chain is four: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` — `server/router/api/v1/v1.go:133-138`. None of them count or bucket requests.

**What does exist** — related but different guardrails, none of them per-user or per-time-window:

- **Request body size cap**: `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` on the gateway (`server/router/api/v1/v1.go:126`, `:144`) and `connect.WithReadMaxBytes` (`:141`).
- **Concurrency semaphores** (global, not per-user): 3 concurrent thumbnail generations and 2 concurrent image processings (`server/router/api/v1/v1.go:59-60`), plus `maxConcurrentThumbnails` in the file server (`server/router/fileserver/fileserver.go:116`).
- **Pagination cap**: `MaxPageSize = 1000` (`server/router/api/v1/common.go:17`, enforced at `:52` and `server/router/api/v1/memo_service.go:240`).
- **Content length limit** per memo, from instance settings (`server/router/api/v1/memo_service.go:100-106`).

If per-user rate limiting is a requirement, it would be new work — the natural insertion points are the interceptor chain at `server/router/api/v1/v1.go:133` for API calls and `server/server.go:51` for all HTTP traffic including the file server.
