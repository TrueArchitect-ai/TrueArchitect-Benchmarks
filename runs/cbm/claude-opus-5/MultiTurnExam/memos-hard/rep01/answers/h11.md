**1st: `store.User` (~6 packages, ~65 references); 2nd: `store.Memo` (~4 packages, ~42 references).**

The data layer here is the `store` package (entities declared in `store/*.go` — `User`, `Memo`, `Attachment`, `Reaction`, `Inbox`, `MemoRelation`, `MemoShare`, `UserIdentity`, `InstanceSetting`, `IdentityProvider`). Counting distinct non-test packages outside `store/` (i.e. under `server/`, `cmd/`, `internal/`) that reference each type:

**`store.User` — 6 packages** (`store/user.go`):
- `server/auth` — `server/auth/authenticator.go` etc.
- `server/notification`
- `server/router/api/v1`
- `server/router/api/v1/test` (test-support package, not a `_test.go` file)
- `server/router/fileserver` — e.g. `getUserByUsername`, `server/router/fileserver/fileserver.go:715`
- `server/router/rss`

**`store.Memo` — 4 packages** (`store/memo.go`):
- `server/notification`
- `server/router/api/v1`
- `server/router/rss`
- `server/runner/memopayload` — e.g. `RebuildMemoPayload`, `server/runner/memopayload/runner.go:74`

Third is `store.Attachment` at 3 packages (`server/router/api/v1`, `server/router/fileserver`, `server/router/rss`, ~37 refs); everything else is ≤2 (`Inbox` and `MemoShare` at 2, `Reaction` at 1).

Two caveats on the method: (a) I excluded the three driver packages `store/db/{sqlite,mysql,postgres}`, which reference nearly every entity but are themselves part of the data layer; including them would add 3 to every row and not change the ranking. (b) If you drop the test-support package `server/router/api/v1/test`, `User` is 5 and `Memo` 4 — still the same order. `User` leads on both measures, package spread and raw reference count.
