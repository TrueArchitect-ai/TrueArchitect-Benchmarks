**No — outside `NewDBDriver`, nothing constructs the MySQL driver.**

Evidence:

1. **Single import site.** `grep -rn "store/db/mysql" --include=*.go` over the whole repo returns exactly two lines, both in the factory: the import at `store/db/db.go:8` and the call at `store/db/db.go:22` (`driver, err = mysql.NewDB(profile)`, inside the `switch profile.Driver` in `NewDBDriver`). No other package — server, cmd, store, tests, seeds — imports `github.com/usememos/memos/store/db/mysql`. Since Go requires an import to reference a package's exported identifiers, this alone rules out external construction.

2. **`mysql.NewDB` has exactly one caller**, `store/db/db.go:22`; it's defined at `store/db/mysql/mysql.go:20` and returns the `store.Driver` interface, so callers elsewhere hold it only abstractly.

3. **The two remaining `DB` literals are both inside the package itself**, not external construction:
   - `store/db/mysql/mysql.go:29` — `driver := DB{profile: profile}`, which *is* the body of `NewDB`.
   - `store/db/mysql/auth_config_test.go:12` — `db := &DB{}`, a zero-valued in-package (`package mysql`) unit test for `IsRetryableAuthenticationMutationError`, with no DSN or `*sql.DB`; it never opens a connection.

Everything else reaches MySQL only through the `store.Driver` interface handed back by `NewDBDriver` (`store/db/db.go:14`).
