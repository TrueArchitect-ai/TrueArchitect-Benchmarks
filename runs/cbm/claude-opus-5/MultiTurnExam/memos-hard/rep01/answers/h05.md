**Explicit Go code — not a database rule.** Reactions are deleted by hand inside the `DeleteUser` transaction in each of the three DB drivers; the `reaction` table has no foreign key to `user`, so nothing would cascade.

What I checked:

**1. The delete path is explicit SQL in Go.** All three drivers share the same structure, and `deleteUserTargetsTx` runs *two* reaction deletes before touching memos or the user row:
- MySQL: `store/db/mysql/user_delete.go` — `deleteReactionsByContentIDsTx` (called at `:95`, defined `:405`) then `deleteReactionsByCreatorTx` (called at `:100`, defined `:425`): `DELETE FROM reaction WHERE creator_id = ?`.
- SQLite: `store/db/sqlite/user_delete.go:96` and `:102`, definitions at `:380` and `:400`.
- Postgres: `store/db/postgres/user_delete.go:96` and `:102`, definitions at `:380` and `:400`.

The two deletes cover different things: **reactions the user *received*** (`content_id IN (...)` over `memos/{uid}` for the user's whole memo tree, including comment descendants — see `memoContentIDsFromRefs`, `store/db/mysql/user_delete.go:520`), and **reactions the user *left* on other people's memos** (`creator_id = ?`). Both run in the same transaction opened in `DeleteUser` (`store/db/mysql/user_delete.go:29-57`), which commits only after every step succeeds.

**2. The database could not do it.** The `reaction` table is declared with no FK at all — just `creator_id INTEGER NOT NULL` and a `UNIQUE(creator_id, content_id, reaction_type)`:
- `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/mysql/LATEST.sql:91-98`, `store/migration/postgres/LATEST.sql:91-98`
- Original creation migrations agree: `store/migration/{sqlite,postgres,mysql}/0.20/00__reaction.sql`

A repo-wide grep for `ON DELETE`/`FOREIGN KEY`/`REFERENCES` under `store/migration` shows cascades exist for other tables (e.g. `memo_share.memo_id → memo(id) ON DELETE CASCADE`, `store/migration/*/LATEST.sql:108-109`, and the legacy sqlite-only user cascades in `store/migration/sqlite/0.5/00__regenerate_foreign_keys.sql`) but none on `reaction`. Also note `content_id` is a text key of the form `memos/{uid}`, not an integer FK, so it isn't cascade-able as written.
