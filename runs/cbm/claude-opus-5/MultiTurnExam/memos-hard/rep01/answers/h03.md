**`internal/idp` (abstraction) — `internal/idp/oauth2` (only concrete implementation, OAuth2).**

Details:

- **Abstraction**: `internal/idp/idp.go` is the whole package — it defines the shared, protocol-neutral result type `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider normalizes to. Note it's a struct-based seam, not a Go `interface`; there's no `IdentityProvider` interface declared.

- **Implementation**: `internal/idp/oauth2/oauth2.go` — `IdentityProvider` built from `storepb.OAuth2Config` via `NewIdentityProvider` (`:27`, which requires clientId/clientSecret/tokenUrl/userInfoUrl/fieldMapping.identifier), with `ExchangeToken` (`:47`, backed by `golang.org/x/oauth2`, supports PKCE via `code_verifier`) and `UserInfo` (`:83`, GETs the userinfo endpoint with a bearer token, 10s timeout, then maps JSON claims onto `idp.IdentityProviderUserInfo` using the configured field mapping).

- **Sole consumer**: `server/router/api/v1/auth_service_sso.go:12-13` imports both packages; `resolveSSOUser` handles linking/provisioning from the returned `IdentityProviderUserInfo`.

- **Corroborating the "only one" claim**: `proto/api/v1/idp_service.proto:76-87` declares `IdentityProvider.Type` with just `TYPE_UNSPECIFIED` and `OAUTH2`, and `IdentityProviderConfig`'s oneof has a single member, `oauth2_config`. No LDAP/SAML/OIDC-specific packages exist in the tree.
