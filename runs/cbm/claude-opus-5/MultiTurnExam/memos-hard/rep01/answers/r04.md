**Premise correction: neither. There is no message broker anywhere in this repository — no NATS, no RabbitMQ/AMQP, no Kafka, no SQS, no pub/sub client of any kind. A case-insensitive grep for all of those across the Go sources, `go.mod`, and the YAML configs returns zero hits, so there is no queue to declare and no broker to consume from.**

**Actual mechanism — an in-process buffered Go channel with a fixed worker pool, all inside `internal/webhook/webhook.go`:**

- **The "queue"** is a package-level buffered channel with 128 slots, declared at `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- **The "workers"** are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`). Each ranges over the channel and calls `Post(payload)`, logging a warning on failure. They live for the lifetime of the process — there's no shutdown path, no context, and no wait group.
- **The producer** is `PostAsync` (`internal/webhook/webhook.go:184-196`), called from the memo webhook dispatchers (`server/router/api/v1/memo_service_webhooks.go:43`, `:71`).
- **Delivery** happens in `Post` (`internal/webhook/webhook.go:120`), which marshals the payload, optionally signs it with HMAC-SHA256 Standard Webhooks headers (`:133-150`), and issues the request via the shared SSRF-guarded `safeClient` (`:152`).

Consequences worth knowing, since they're exactly what a broker would otherwise provide:

- **No durability.** The queue is memory-only; a restart or crash silently loses everything pending.
- **No retries.** `Post` returns an error, and the worker only logs it (`:47-50`). A 500 from the receiver means the event is gone.
- **Lossy under backpressure.** `PostAsync` uses a non-blocking `select` with a `default` branch that drops the payload and logs a warning when all 128 slots are full (`:189-195`) — so a slow or hung endpoint can cause silent event loss for everyone, since the channel and worker pool are global, not per-endpoint.
