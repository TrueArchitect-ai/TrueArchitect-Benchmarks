**Explicit Go code — two `DELETE FROM reaction` statements per driver inside the `DeleteUser` transaction. There is no database-level rule doing it.**

What I checked:

**1. The delete path.** `DeleteUser` opens a transaction and calls `deleteUserTargetsTx`, which issues the reaction deletes before anything else:
- `store/db/mysql/user_delete.go:96` and `:102` (helpers at `:380` and `:400`)
- `store/db/sqlite/user_delete.go:96` and `:102` (helpers at `:380` and `:400`)
- `store/db/postgres/user_delete.go:96` and `:102` (helpers at `:380` and `:400`)

All three drivers are structurally identical. Two distinct statements run:
- `deleteReactionsByCreatorTx` — `DELETE FROM reaction WHERE creator_id = ?` — removes reactions the deleted user *made*, anywhere.
- `deleteReactionsByContentIDsTx` — `DELETE FROM reaction WHERE content_id IN (...)`, batched at 500 (`deleteUserBatchSize`, `user_delete.go:14`) — removes reactions *others made on* the user's content. The content IDs come from the full memo tree, including comment descendants, collected by `listDeleteUserMemoTreeIterative` (`store/db/mysql/user_delete.go:130`).

**2. Ruled out a DB-level rule.** The `reaction` table carries no foreign key at all — no `FOREIGN KEY`, no `ON DELETE CASCADE` — in any of the three current schemas:
- `store/migration/sqlite/LATEST.sql:92-99`
- `store/migration/postgres/LATEST.sql:91-98`
- `store/migration/mysql/LATEST.sql:91-98`

Grepping every `CREATE TABLE reaction` across the migration history (`store/migration/mysql/0.20/00__reaction.sql:2` and the LATEST files) for `FOREIGN KEY`/`CASCADE` returns nothing. Other tables in these schemas *do* use `ON DELETE CASCADE` (e.g. `store/migration/sqlite/LATEST.sql:109`, `store/migration/sqlite/0.5/00__regenerate_foreign_keys.sql:59`), so its absence on `reaction` is a real gap, not a grep artifact.

**3. Ruled out cascade even where FKs exist.** SQLite opens its connection with foreign keys explicitly disabled — `_pragma=foreign_keys(0)` at `store/db/sqlite/sqlite.go:53` — so even declared cascades wouldn't fire there. The Go code is the only mechanism.
