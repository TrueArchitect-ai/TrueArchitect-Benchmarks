**Convergence.** All four `Dispatch*Webhook` methods (`server/router/api/v1/memo_service_webhooks.go:15-46`) load the owner's webhooks via `s.Store.GetUserWebhooks`, set `payload.URL = hook.Url`, and call `webhook.PostAsync` — `memo_service_webhooks.go:43` (comment path) and `:71` (the shared `dispatchMemoRelatedWebhook` used by created/updated/deleted). So `PostAsync` (`internal/webhook/webhook.go:184`) is the single chokepoint every handler passes through. It only enqueues onto a 128-slot channel; the actual send happens one hop later in `webhook.Post` (`internal/webhook/webhook.go:120`, HTTP call at `:152`) on one of four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`).

One adjacent case worth naming, since it also reaches a user-supplied URL but does *not* pass through `PostAsync`: `GetLinkMetadata` and `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go:14` and `:19`) fetch arbitrary URLs from the request body via `getLinkMetadata` → `fetchHTMLMeta` → `httpgetter.GetHTMLMeta` (`memo_service_link_metadata.go:46`, indirection declared at `memo_service.go:28`). Those URLs are request parameters rather than stored user configuration, so they're a separate egress path from the webhook one.
