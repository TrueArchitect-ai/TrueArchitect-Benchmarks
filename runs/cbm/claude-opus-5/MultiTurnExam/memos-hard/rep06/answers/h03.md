**`internal/idp` (abstraction); `internal/idp/oauth2` (implementation)**

- **Abstraction:** `internal/idp/idp.go:1-8` — package `idp` is deliberately thin: it defines only the `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`), the normalized shape every provider must return. There is no Go `interface` type here; the abstraction is the shared user-info contract plus the provider-type enum in the store schema (`proto/store/idp.proto`, generated as `IdentityProvider_Type` at `proto/gen/store/idp.pb.go:24`).

- **Implementation:** `internal/idp/oauth2/oauth2.go` — package `oauth2`, "implements the OAuth2 identity provider integration" (line 1). It provides `NewIdentityProvider` (line 27, validating required `clientId`/`clientSecret`/`tokenUrl`/`userInfoUrl`/`fieldMapping.identifier`), `ExchangeToken` (line 47, with optional PKCE `code_verifier`), and `UserInfo` (line 83), which returns `*idp.IdentityProviderUserInfo`.

OAuth2 is the only concrete protocol that ships — the store enum has exactly one non-unspecified value, `IdentityProvider_OAUTH2 = 1` (`proto/gen/store/idp.pb.go:27-28`); no SAML, OIDC-specific, or LDAP package exists. The sole consumer is the SSO sign-in path, which imports both packages together at `server/router/api/v1/auth_service_sso.go:12-13`.
