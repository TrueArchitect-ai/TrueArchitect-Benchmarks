**`webhook.Post` — `internal/webhook/webhook.go:120` (the actual HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); SSRF protection is the dial-time reserved-IP check `safeDialContext`/`isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

- **Delivery path.** Memo create/update/delete/comment events call `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:43` and `:71`), which only enqueues onto a bounded 128-slot channel (`internal/webhook/webhook.go:39`, `184-196`) and drops the payload with a warning if the queue is full. Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `Post`. So `Post` is where the outbound request is built (JSON body, optional Standard-Webhooks HMAC-SHA256 headers at lines 133-150) and executed.

- **Protection.** `Post` sends through the package-level `safeClient` (`internal/webhook/webhook.go:32-37`), whose `http.Transport` installs `safeDialContext` as its `DialContext`. On every connection attempt, `safeDialContext` splits host/port, resolves the hostname itself (`internal/webhook/webhook.go:65`), and rejects the dial if *any* resolved address is reserved (`:70-74`). `isReservedIP` (`internal/webhook/validate.go:44`) tests against the CIDR list at `internal/webhook/validate.go:14-23` — IPv4 loopback, all three RFC-1918 ranges, 169.254.0.0/16 (cloud IMDS), plus IPv6 loopback, ULA, and link-local — parsed once in `init()` (`validate.go:28-36`).

Two supporting notes:

- Because the check runs at dial time rather than only at registration time, it also defeats DNS rebinding — the comment at `internal/webhook/webhook.go:30-31` says this explicitly. There is a second, earlier check: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) enforces http/https scheme and the same IP check when a webhook is created or updated (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`). That one is a UX-level guard; the dial-time check is what actually protects delivery.
- The escape hatch `webhook.AllowPrivateIPs` (`internal/webhook/validate.go:41`) short-circuits `isReservedIP` when true, but it is only ever set from tests (`internal/webhook/webhook_test.go:91`, `:142`) — no flag, env var, or config wires it, so in a running server the protection is always on.
