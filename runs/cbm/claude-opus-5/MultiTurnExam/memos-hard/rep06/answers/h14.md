**Computation site — `memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`), delegating to `(*markdown.service).ExtractAll` (`internal/markdown/markdown.go:356`); triggers — `CreateMemo` and content-changing `UpdateMemo`; extracted — `tags` plus the five `MemoPayload.Property` fields (`has_link`, `has_code`, `has_task_list`, `has_incomplete_tasks`, `title`)**

**Computation.** `RebuildMemoPayload` initializes `memo.Payload` if nil, calls `markdownService.ExtractAll([]byte(memo.Content))`, and assigns `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (`server/runner/memopayload/runner.go:74-89`). `ExtractAll` does a single goldmark AST walk (`internal/markdown/markdown.go:371-411`) so all metadata comes out of one parse. The payload is persisted as a JSON column alongside the memo row (e.g. `store/db/sqlite/memo.go:17-27`).

**Triggers.** Two, both in the v1 memo service:
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, after the content-length check and before `Store.CreateMemo`.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the `if path == "content"` branch of the update-mask loop (line 436). The refreshed payload is then attached to the update at line 452. Changing visibility, pinning, etc. does not recompute.

Note the payload is *not* recomputed on tag rename: `markdown.Service.RenameTag` (`internal/markdown/markdown.go:425`) rewrites content, and any resulting persistence goes through `UpdateMemo`'s content path. The batch backfill that would recompute for all memos, `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:27`, calling `RebuildMemoPayload` at line 52), is never invoked — `NewRunner` has no callers.

**Extracted properties** (`ExtractedData`, `internal/markdown/markdown.go:21-25`; proto shape at `proto/store/memo.proto:8-22`):

- **`tags`** — from custom `TagExtension` `#tag` nodes (`markdown.go:376-378`), deduplicated with original case preserved (`markdown.go:417`). Tags inside links/images are excluded via `isTagNodeInLinkOrImage` (`markdown.go:122`).
- **`Property.title`** — text of the first H1 heading, only if it is the document's first block-level child (`markdown.go:383-389`).
- **`Property.has_link`** — any `KindLink` node (`markdown.go:393-394`).
- **`Property.has_code`** — any code block, fenced code block, or inline code span (`markdown.go:396-397`).
- **`Property.has_task_list`** and **`Property.has_incomplete_tasks`** — any task checkbox; the latter set when a checkbox is unchecked (`markdown.go:399-405`).

`ExtractedData.Mentions` is also populated by the same walk (`markdown.go:379-381`), but `RebuildMemoPayload` doesn't store it — mentions are consumed separately for notifications via `s.MarkdownService.ExtractAll` at `server/router/api/v1/memo_mention_helpers.go:32`.
