**Premise correction: there is no per-user API rate-limiting middleware in this repository. It doesn't exist, so it isn't registered anywhere and has no request limits.**

Evidence:

- A repo-wide, case-insensitive search for `ratelimit` / `rate limit` / `throttle` (excluding `.git` and `node_modules`) returns only three hits, none of them an implementation: `internal/email/README.md:286` and `:295` and `internal/email/doc.go:86` — all *suggestions* in documentation that a deployment should rate-limit outbound email, written as future-work prose rather than code.
- No rate-limiting dependency is present: `go.mod` contains no `golang.org/x/time/rate`, no `echo` rate-limiter middleware module, and no equivalent.
- The complete Echo middleware stack is two entries, registered at `server/server.go:51-52`: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go`). Nothing else is added with `Use(...)`.
- The Connect/gRPC interceptor chain contains only `MetadataInterceptor`, `LoggingInterceptor`, and `RecoveryInterceptor` (`server/router/api/v1/connect_interceptors.go:22`, `:98`, `:164`), plus the auth/ACL authorizer wired in `RegisterGateway` (`server/router/api/v1/v1.go:65-`). No limiter among them.

What does exist — related but distinct — are *concurrency* caps and *size* caps, not per-user request-rate limits:

- **Concurrency semaphores:** thumbnail generation limited to 3 in-flight (`server/router/fileserver/fileserver.go:46`, `:116`; `server/router/api/v1/v1.go:59`) and image processing to 2 (`server/router/api/v1/v1.go:60`). These are global, not per user, and they queue rather than reject.
- **A bounded webhook dispatch queue** of 128 with 4 workers, which *drops* overflow (`internal/webhook/webhook.go:39`, `:42-55`, `:189-195`) — outbound, not inbound.
- **Content-size limits** on memos, enforced per request via `getContentLengthLimit` (`server/router/api/v1/memo_service.go:100-106`, `:438-444`).

If you need per-user rate limiting, it would have to be added — either as an Echo middleware at `server/server.go:51-52` or as a Connect interceptor alongside those in `server/router/api/v1/connect_interceptors.go` — or handled at a reverse proxy in front of the instance.
