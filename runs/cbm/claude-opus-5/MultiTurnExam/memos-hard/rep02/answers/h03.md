**`internal/idp` (`internal/idp/idp.go`); `internal/idp/oauth2` (`internal/idp/oauth2/oauth2.go`)**

- **Abstraction** — `internal/idp/idp.go` is the shared package. It's deliberately thin: it defines only `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) at `internal/idp/idp.go:3-8`, the normalized shape every provider must produce. There is no Go `interface` here — the abstraction is the common result type plus the protobuf schema in `proto/store/idp.proto`, where `IdentityProvider.Type` and the `IdentityProviderConfig` oneof are the actual extension points.

- **Implementation** — `internal/idp/oauth2` is the only concrete protocol that ships. `oauth2.IdentityProvider` (`internal/idp/oauth2/oauth2.go:20`) is built by `NewIdentityProvider` from a `storepb.OAuth2Config` (`:27`) and provides `ExchangeToken` (`:47`, supporting PKCE via `codeVerifier`) and `UserInfo` (`:83`), which maps raw provider JSON onto `idp.IdentityProviderUserInfo` using the configured `FieldMapping`.

This is corroborated on both sides: the store enum has exactly one non-unspecified value, `OAUTH2 = 1`, and the config oneof carries only `oauth2_config` (`proto/store/idp.proto:11-25`); and the sole consumer, `server/router/api/v1/auth_service_sso.go` (imports at `:13`, used in `resolveSSOIdentity` at `:104`), constructs only an OAuth2 provider. Note that OIDC isn't a separate implementation — it's covered by configuring the OAuth2 provider's `auth_url`/`token_url`/`user_info_url`.
