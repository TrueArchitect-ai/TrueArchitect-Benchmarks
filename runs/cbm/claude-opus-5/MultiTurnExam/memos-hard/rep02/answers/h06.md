The last three of those "update" handlers share the helper `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`), which calls `DispatchMemoUpdatedWebhook` at `:67`.

**Convergence.** All four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go`; each loads the target user's webhooks from `s.Store.GetUserWebhooks`, builds a payload with the user-configured `hook.Url`, and calls `webhook.PostAsync` (`memo_service_webhooks.go:43` and `:71`). `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded channel; the actual outbound HTTP request is issued by **`webhook.Post`** — `internal/webhook/webhook.go:120`, with `safeClient.Do` at `:152` — running on the worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`). Every path above funnels through that one function.

Two clarifications on scope. The URL is user-configured through the `UserService` webhook CRUD handlers (`server/router/api/v1/user_service_webhooks.go:53`, `:106`), but those handlers only validate and persist — they never post, so they aren't part of the answer. And dispatch is best-effort throughout: failures are logged via `slog.Warn` and don't fail the RPC.
