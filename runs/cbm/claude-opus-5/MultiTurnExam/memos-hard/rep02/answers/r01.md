**Premise correction: there is no Redis in this repo.** No Redis client, config, or dependency exists anywhere — `go.mod`/`go.sum` contain no Redis (or memcached/valkey) module, and a case-insensitive search for "redis" across all Go, YAML, and Markdown files returns zero hits. The cache layer is a hand-rolled, process-local in-memory cache with no external server and therefore no connection to configure.

**Actual mechanism.**

- **Implementation:** `store/cache/cache.go` — a `Cache` type backed by a `sync.Map` plus an atomic item counter (`store/cache/cache.go:66-72`), satisfying the `cache.Interface` declared at `store/cache/cache.go:11-32`. Entries carry an absolute `expiration` timestamp and a rough size estimate (`:35-39`).

- **Where it's "configured":** in Go code at `Store.New` — `store/store.go:39-53`. There are three separate cache instances, all built from one hard-coded `cache.Config`:

  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  used for `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:51-53`). Note these values are literals in `Store.New`, not read from `profile`, flags, or env — `cache.DefaultConfig()` (`store/cache/cache.go:56-63`) declares the identical values but isn't actually called by the store.

- **TTL for user entries: 10 minutes.** Every write to `userCache` goes through `Set` — `store/user.go:98`, `:122`, `:132`, `:143`, `:167` — and `Set` applies `config.DefaultTTL`; nothing in the repo calls `SetWithTTL` with a per-entry override (the only definition/uses are inside `store/cache/`). Expiry is lazy rather than scheduled: `Get` compares `time.Now()` against the entry's `expiration` and deletes on read (`store/cache/cache.go:134-146`), with a background sweep every 5 minutes and eviction of oldest entries once the 1000-item cap is exceeded (`store/cache/cache.go:116-119`).

- **Explicit invalidation** happens on user deletion, `store/user_delete.go:40`, and the cache is only consulted for lookups by ID — `Store.GetUser` skips it when finding by username (`store/user.go:149-156`).

- **Lifecycle:** `Store.Close` stops all three caches' cleanup goroutines (`store/store.go:74-76`) before closing the DB driver.
