**Premise correction: there is no nightly database-cleanup job — no cleanup job of any kind is registered with the cron scheduler, and the cron scheduler itself is never started by the server.**

What's actually there:

- **The scheduler package exists but is dead code.** `internal/scheduler` is a self-contained cron implementation (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`) supporting 5- and 6-field expressions, timezones, and middleware. Nothing in the application imports it: the only importers repo-wide are its own tests, `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. `scheduler.New`, `Register`, and `Start` (`internal/scheduler/scheduler.go:54`, `:70`, `:91`) are never called from production code, so no job list exists to schedule against.

- **The likely source of the premise** is the package's own documentation example, which uses a job literally named `"daily-cleanup"` on schedule `"0 2 * * *"` — 2 AM daily — at `internal/scheduler/doc.go:14-21`. That is illustrative sample code in a doc comment, not a registered job.

- **The server's only scheduled background work** is the S3 presign refresher, and it doesn't use cron at all: `s3presign.Runner` runs on a plain 12-hour `time.Ticker` (`server/runner/s3presign/runner.go:27`, `:30-42`), started from `Server.startBackgroundRunners` at `server/server.go:162-171`. That's the complete set of background runners registered at startup.

- **No database cleanup/vacuum/purge task exists anywhere.** Data removal is request-driven instead: the cascading `DeleteUser` transaction (`store/db/sqlite/user_delete.go` and its postgres/mysql peers) and memo deletion (`server/router/api/v1/memo_service.go:579`). The only recurring "cleanup" in the codebase is the in-memory cache's expiry sweep every 5 minutes (`store/cache/cache.go:199-218`), which touches no database.
