**`webhook.Post` — `internal/webhook/webhook.go:120` (executed by the async worker pool draining `asyncPostQueue`, `internal/webhook/webhook.go:42-55`); SSRF guard via `safeDialContext` / `isReservedIP` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`**

How it fits together:

**Delivery path.** Memo create/update/delete/comment events call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43` and `:71`. `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a bounded 128-slot channel and drops with a warning if full. The actual HTTP request is built and sent by `Post` (`internal/webhook/webhook.go:120`), which runs on one of 4 goroutines started in the package `init()` (`internal/webhook/webhook.go:42-55`). `Post` marshals the payload, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, lines 133-150), and issues the request via `safeClient.Do` at `internal/webhook/webhook.go:152`.

**Protection.** Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against the CIDR list at `internal/webhook/validate.go:14-23` (loopback, RFC-1918, 169.254.0.0/16 including cloud IMDS, and IPv6 `::1`/`fc00::/7`/`fe80::/10`):

1. *At dial time* — the real enforcement. `safeClient`'s `Transport.DialContext` is `safeDialContext` (`internal/webhook/webhook.go:32-37`, defined at `:59`). It resolves the host itself and refuses the connection if any resolved IP is reserved. Because this happens per-dial rather than at save time, it also defeats DNS rebinding — as the comment at `internal/webhook/webhook.go:29-31` notes.
2. *At configuration time* — `webhook.ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and reserved-resolving hostnames when a user registers or updates a webhook, called from `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`.

One caveat worth flagging: the escape hatch `AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables both layers, and per `CHANGELOG.md:121` it was meant to be driven by an `--allow-private-webhooks` flag — but in the current tree nothing outside `internal/webhook/webhook_test.go` ever assigns it, so the flag wiring is absent and the guard is effectively always on.
