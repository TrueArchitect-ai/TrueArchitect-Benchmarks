1. `APIV1Service.CreateMemo` calls `s.Store.CreateMemo` — `server/router/api/v1/memo_service.go:115`.
2. `Store.CreateMemo` validates the UID, then delegates to `s.driver.CreateMemo` — `store/memo.go:109-114`.
3. `driver` is the interface `store.Driver`, whose `CreateMemo` is declared at `store/driver.go:29`. Three types satisfy it: `store/db/sqlite/memo.go:16`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`.
4. The concrete type is chosen at startup by the factory `db.NewDBDriver`, which switches on `profile.Driver` — `store/db/db.go:14-26` (`"sqlite"` → `sqlite.NewDB` at `:20`).
5. `profile.Driver` comes from `viper.GetString("driver")` in `cmd/memos/main.go:43`, and the default is `"sqlite"` — set both as a viper default (`cmd/memos/main.go:122`) and as the flag's default value (`cmd/memos/main.go:130`). With no flags, no env var, and no config file, that default stands, so `NewDBDriver` returns `*sqlite.DB` and step 3 resolves to the SQLite implementation.

Note that the SQLite and MySQL implementations use identical backtick-quoted SQL text, so reading the query alone wouldn't disambiguate them — the flag default is what settles it. (Postgres differs: `$N` placeholders.)
