**1st: `store.User` (~6 packages); 2nd: `store.Memo` (~4 packages)**

The data layer is the `store` package (entity structs declared in `store/user.go`, `store/memo.go`, `store/attachment.go`, etc.). Counting distinct Go packages *outside* the `store/**` tree (so excluding the three driver packages `store/db/{sqlite,postgres,mysql}`, which reference nearly every entity by construction):

**`store.User`** — 6 packages:
- `server/auth` (`server/auth/authenticator.go`)
- `server/notification` (`server/notification/email.go`)
- `server/router/api/v1` (e.g. `server/router/api/v1/user_service.go`, `auth_service_sso.go`)
- `server/router/fileserver` (`server/router/fileserver/fileserver.go:715`)
- `server/router/rss`
- `server/router/api/v1/test` (test-helper package; 5 if you exclude it)

**`store.Memo`** — 4 packages:
- `server/notification`
- `server/router/api/v1` (e.g. `server/router/api/v1/memo_service.go`, `memo_update_helpers.go`)
- `server/router/rss`
- `server/runner/memopayload` (`server/runner/memopayload/runner.go`)

Third is `store.Attachment` at 3 (`server/router/api/v1`, `server/router/fileserver`, `server/router/rss`); everything else — `MemoShare`, `Inbox`, `MemoRelation`, `UserIdentity`, `Reaction`, `UserSetting`, `InstanceSetting`, `IdentityProvider` — sits at 1–2, essentially confined to `server/router/api/v1`.

Two notes on method: this counts type *references* (`store.User`, `store.Memo` — word-boundary matched so `store.UserSetting`/`store.MemoRelation` don't inflate the totals), not call volume; and I excluded the `Find*`/`Update*`/`Delete*` parameter structs, which aren't persistent entities. Including `_test.go` files adds `server/router/frontend` to both and `server/router/api/v1/test` to `Memo`, giving 7 vs 6 — the same ranking.
