**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74`, delegating to `(*markdown.service).ExtractAll` — `internal/markdown/markdown.go:356`**

**What it is.** The derived metadata is the memo's `payload` — `MemoPayload.tags` plus the nested `MemoPayload.Property` message (`proto/store/memo.proto:7-22`), persisted in the `memo.payload` JSON column. `RebuildMemoPayload` does one markdown parse and assigns both fields:

```go
memo.Payload.Tags = data.Tags
memo.Payload.Property = data.Property
```
(`server/runner/memopayload/runner.go:85-86`)

**Triggers — exactly two production paths, both in `server/router/api/v1/memo_service.go`:**

1. **`CreateMemo`** — `memo_service.go:107-109`, run after the content-length check and before `s.Store.CreateMemo`. This also covers **`CreateMemoComment`**, which creates its comment by calling `s.CreateMemo` internally (`server/router/api/v1/memo_service_comments.go:55`).
2. **`UpdateMemo`** — `memo_service.go:446-448`, but only when `"content"` is in the `UpdateMask` paths (`:436`); the fresh payload is then written via `update.Payload = memo.Payload` (`:452`). Updating visibility, pinning, etc. does not recompute it.

A third site exists but is dead: `memopayload.Runner.RunOnce` (`server/runner/memopayload/runner.go:52`) rebuilds payloads for all memos in batches, but neither it nor `NewRunner` is called from production code.

**What `ExtractAll` extracts** (single goldmark AST walk, `internal/markdown/markdown.go:356-424`):

- **`Tags`** — every `#tag` node, deduplicated with original case preserved via `uniquePreserveCase` (`:418`).
- **`Property.Title`** — text of the first block-level child of the document if it's an H1 heading (`:383-389`).
- **`Property.HasLink`** — any link node (`:393`).
- **`Property.HasCode`** — any code block, fenced code block, or code span (`:396`).
- **`Property.HasTaskList`** — any task checkbox (`:399`).
- **`Property.HasIncompleteTasks`** — a task checkbox that is unchecked (`:401-403`).

`ExtractAll` also collects `Mentions` (lowercased `@username` nodes, `:378`), but `RebuildMemoPayload` discards them — mentions are consumed separately for notifications (`server/router/api/v1/memo_mention_helpers.go:32`), not stored on the memo.

**Consumers.** The stored payload is copied onto the API response in `convertMemoFromStore` (`server/router/api/v1/memo_service_converter.go:48-49`) and aggregated for user stats (`server/router/api/v1/user_service_stats.go:138-151`, `:254-267`).

One distinction worth flagging, since "previews" could mean either: the memo **snippet** is *not* part of this stored metadata. It's computed on demand at read time by `getMemoContentSnippet` → `MarkdownService.GenerateSnippet(content, 64)` (`server/router/api/v1/memo_service_webhooks.go:83-85`), called from the converter (`memo_service_converter.go:76`, `:225`, `:248`), relation listing, and notification payloads — so it never goes through `RebuildMemoPayload` and has no recomputation triggers.
