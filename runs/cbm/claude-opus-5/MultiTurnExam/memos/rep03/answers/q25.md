**CEL (Google Common Expression Language, `github.com/google/cel-go` v0.28.1) — /bench/repo/internal/filter; the CEL AST is compiled into a dialect-neutral condition IR, then rendered to a parameterized SQL `WHERE` fragment plus args using per-dialect column/function templates selected by a `DialectName`.**

How it fits together:

- **Engine.** `filter.Engine` (`internal/filter/engine.go:24`) wraps a CEL environment. `Compile` (line 48) calls `e.env.Compile(filter)` and converts the AST via `cel.AstToParsedExpr` (line 57); `CompileToStatement` (line 74) does compile + render in one step. Prebuilt engines: `DefaultEngine()` (line 111) for memos, `DefaultAttachmentEngine()` (line 119).
- **Schema.** `internal/filter/schema.go:89` declares the filterable variables — `content`, `creator`, `creator_id`, `created_ts`, `updated_ts`, `pinned`, `tag`/`tags`, `visibility`, `has_task_list`, `has_link`, `has_code`, `has_incomplete_tasks`, `now` (lines 233-246) — with `cel.ValidateRegexLiterals()` enabled.
- **IR + rendering.** `internal/filter/parser.go` walks the CEL expression into the condition tree in `internal/filter/ir.go`; `internal/filter/render.go` emits SQL, branching on dialect for JSON access and string ops (`jsonExtractExpr`, `jsonArrayExpr`, `jsonArrayLengthExpr`, `stringLengthExpr`, `qualifyColumn`).
- **Dialect selection.** `DialectName` with constants `DialectSQLite`, `DialectMySQL`, `DialectPostgres` (`schema.go:11-16`); per-field templates supply the dialect-specific expression, e.g. `('users/' || %s)` for SQLite/Postgres vs `CONCAT('users/', %s)` for MySQL (`schema.go:105-107`).
- **Wiring into queries.** Each driver's `ListMemos` builds its engine and calls `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args)` — see `store/db/sqlite/memo.go:57-63`, with the postgres/mysql counterparts in `store/db/postgres/memo.go` and `store/db/mysql/memo.go`. `AppendConditions` (`internal/filter/helpers.go:9-25`) wraps each rendered fragment in parens and appends its bind args, using `PlaceholderOffset` so Postgres `$N` numbering stays correct. The same mechanism is used for attachments and memo relations.

The RPC field itself is `ListMemosRequest.filter` in `proto/api/v1/memo_service.proto`; docs for the supported expressions are in `internal/filter/README.md`.
