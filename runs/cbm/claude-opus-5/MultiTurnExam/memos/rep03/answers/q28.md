**Runners the server actually starts** (all from `Server.startBackgroundRunners`, `/bench/repo/server/server.go:153-174`, invoked at the end of `Server.Start`, `server.go:127`):

```
s3presign.Runner.RunOnce — one-shot at startup, called synchronously (server/server.go:163)
s3presign.Runner.Run — 12-hour time.Ticker loop in its own goroutine, cancelled via context on shutdown (server/server.go:166-171; interval at server/runner/s3presign/runner.go:27-41)
```

`Run` re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days (`server/runner/s3presign/runner.go:47-120`). It's the only entry in `backgroundRunnerCancels` / `backgroundRunnerWG`, torn down by `stopBackgroundRunners` / `waitBackgroundRunners` (`server.go:176-199`).

**Other background goroutines, started outside `startBackgroundRunners`:**

```
webhook async dispatch pool — 4 goroutines draining a 128-slot channel, started by package init(), fed by webhook.PostAsync (internal/webhook/webhook.go:39-54)
SSE client goroutines — per-connection, created on demand when a browser opens GET /api/v1/sse (server/router/api/v1/sse_handler.go, hub at sse_hub.go)
```

Neither is context-cancelled by `stopBackgroundRunners`; the webhook workers live for the process lifetime, and SSE clients end with their HTTP connections (`SSEHub.Close`, `sse_hub.go:99`).

**Unused infrastructure:** `server/runner/memopayload` ships a full `Runner` type — `NewRunner(store, markdownService)` and `RunOnce` (`server/runner/memopayload/runner.go:19-27`), which would rebuild payloads for all memos — but **nothing ever constructs it**. The only use of that package is the standalone function `memopayload.RebuildMemoPayload`, called inline from the API handlers on create and update (`server/router/api/v1/memo_service.go:108` and `:447`). So the memopayload *runner* is dead scheduling infrastructure; the payload rebuild happens synchronously per request instead.
