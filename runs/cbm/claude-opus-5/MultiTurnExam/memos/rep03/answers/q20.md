**Server-Sent Events (SSE) over `GET /api/v1/sse`; /bench/repo/server/router/api/v1/sse_hub.go; CreateMemo, DeleteMemo, CreateMemoComment, UpsertMemoReaction, DeleteMemoReaction, and (via `dispatchMemoUpdatedSideEffects`) UpdateMemo / SetMemoAttachments / SetMemoRelations**

**Mechanism.** SSE, not WebSockets. The endpoint is registered at `sse_handler.go:25-30` (`RegisterSSERoutes` → `GET /api/v1/sse`), wired into the Echo group at `v1.go:125`. `handleSSE` (`sse_handler.go:34`) authenticates via the `Authorization: Bearer` header before subscribing the client.

**Hub.** `SSEHub` is defined at `/bench/repo/server/router/api/v1/sse_hub.go:56` with constructor `NewSSEHub` (line 63) and the event types at lines 15-20: `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`. Event-construction helpers live in `sse_event_helpers.go`.

**Broadcasting handlers** (all on `APIV1Service`):

| Handler | Broadcast site |
|---|---|
| `CreateMemo` | `memo_service.go:163` |
| `DeleteMemo` | `memo_service.go:585` |
| `CreateMemoComment` | `memo_service_comments.go:126` |
| `UpsertMemoReaction` | `reaction_service.go:106` |
| `DeleteMemoReaction` | `reaction_service.go:161` |
| `dispatchMemoUpdatedSideEffects` (shared helper) | `memo_update_helpers.go:71` |

That last helper emits the `memo.updated` event and is called from three handlers: `UpdateMemo` (`memo_service.go:513`), `SetMemoAttachments` (`memo_attachment_service.go:48`), and `SetMemoRelations` (`memo_relation_service.go:48`).

Note `CreateMemoComment` calls `CreateMemo` with SSE suppressed (`withSuppressSSE`, `memo_service_comments.go:56`) so only the `memo.comment.created` event fires for the parent. On the browser side, the stream is consumed by `/bench/repo/web/src/hooks/useLiveMemoRefresh.ts`.
