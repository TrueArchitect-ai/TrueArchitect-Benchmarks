**web/src/connect.ts (`authInterceptor`, with state in web/src/auth-state.ts); short-lived JWT access token + long-lived refresh token (HTTP-only cookie) + Personal Access Tokens for programmatic clients; /bench/repo/server/auth**

**Frontend interceptor.** `authInterceptor` at `/bench/repo/web/src/connect.ts:156-178` is attached to the Connect transport (line 188). On every request it calls `getRequestToken()` (line 124) and sets `Authorization: Bearer <token>`. It handles two refresh paths:
- *Proactive* — if the stored token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` of expiry it refreshes first (`connect.ts:140-147`), so public endpoints like `ListMemos` don't silently return guest-scoped data.
- *Reactive* — on a `Code.Unauthenticated` response it refreshes, sets an `X-Retry` header to prevent loops, and retries once; on failure it calls `redirectOnAuthFailure()` (lines 163-177).

Concurrent refreshes are deduplicated by `createTokenRefreshManager` (`connect.ts:30-51`), and the refresh call itself goes through a separate interceptor-free `refreshAuthClient`/`refreshTransport` (lines 65-72) to avoid recursion. All transports use `credentials: "include"` (line 57-62) so the refresh cookie is sent.

**Tokens.**
- **Access token (V2 JWT)** — held in `localStorage` plus in-memory, managed by `/bench/repo/web/src/auth-state.ts` (`getAccessToken`, `setAccessToken`, `isTokenExpired`, with cross-tab adoption at line 35).
- **Refresh token** — never touched by JS; it's an HTTP-only cookie sent automatically, exchanged via `AuthService.RefreshToken` (`connect.ts:75`), and rotated server-side. `/bench/repo/web/src/hooks/useTokenRefreshOnFocus.ts` also refreshes on tab focus.
- **Personal Access Token (PAT)** — `memos_pat_`-prefixed bearer tokens for API clients, not used by the web app.

**Backend validation.** `/bench/repo/server/auth` — `Authenticator` in `server/auth/authenticator.go` with `AuthenticateByAccessTokenV2` (line 41), `AuthenticateByRefreshToken` (line 61, checked against `user_refresh_token` rows in the DB), and `AuthenticateByPAT` (line 102, SHA-hash lookup + expiry check + last-used recording). `resolveBearer` (line 149) dispatches on the `memos_pat_` prefix; `Authenticate` (line 213) is the entry point. Token parsing/minting lives in `server/auth/token.go`, header/cookie extraction in `server/auth/extract.go`, context plumbing in `server/auth/context.go`.

It's invoked from three places: the Connect `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:213`), the grpc-gateway middleware (`server/router/api/v1/v1.go:73-93`), and the SSE handler (`server/router/api/v1/sse_handler.go:34-44`).
