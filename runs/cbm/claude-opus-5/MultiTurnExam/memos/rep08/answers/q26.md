`memo_share` is declared `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` in all three schemas (`store/migration/sqlite/LATEST.sql:109`, `postgres/LATEST.sql:108`, `mysql/LATEST.sql:108`), and no Go code deletes those rows. That cascade fires on Postgres and MySQL — but **not on SQLite**, which opens its connection with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so share rows are left orphaned there.
