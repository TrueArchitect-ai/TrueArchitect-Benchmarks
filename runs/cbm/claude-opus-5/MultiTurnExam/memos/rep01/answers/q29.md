**Interceptor:** `web/src/connect.ts` — `authInterceptor` at line 156, attached to the shared Connect transport at line 188.

**Token kinds:** short-lived **access token** (JWT, sent as `Authorization: Bearer <token>`) + **refresh token** (httpOnly cookie), plus **personal access tokens** (PATs) accepted on the same Bearer header for non-browser clients.

**Backend package:** `server/auth/` (`authenticator.go`, `token.go`, `extract.go`, `context.go`).

How it fits together:

- On every request `authInterceptor` calls `getRequestToken()` (`web/src/connect.ts:124`) and sets the `Authorization` header (line 159). It pre-emptively refreshes when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` of expiry (line 140), and on a `Code.Unauthenticated` response it refreshes once, marks the retry with an `X-Retry` header, and replays the request — falling back to `redirectOnAuthFailure()` (line 174).
- Refresh goes over a **separate interceptor-free transport** (`connect.ts:65`) and `refreshAuthClient` (line 72) to avoid recursion; concurrent refreshes are deduplicated by `tokenRefreshManager` (line 30). All fetches use `credentials: "include"` (line 60) so the refresh cookie rides along.
- Token storage is `web/src/auth-state.ts` — localStorage-backed with an in-memory cache, plus a `BroadcastChannel` ("memos_token_sync") so a refresh in one tab is adopted by the others instead of racing.
- Server side, `Authenticator` (`server/auth/authenticator.go:32`) validates: `AuthenticateByAccessTokenV2` (line 41, via `ParseAccessTokenV2` in `server/auth/token.go`), `AuthenticateByRefreshToken` (line 61, parsed *and* checked against the DB via `GetUserRefreshTokenByID`), and `AuthenticateByPAT` (line 102, prefix + hash lookup). `resolveBearer` (line 149) picks between JWT and PAT; `AuthenticateToUser` (line 190) falls back to the cookie via `ExtractRefreshTokenFromCookie`. Helpers live in `server/auth/extract.go`.
- It's wired into the request path by the Connect interceptors in `server/router/api/v1/connect_interceptors.go` and the gateway auth middleware in `server/router/api/v1/v1.go:69`, with per-method rules in `server/router/api/v1/acl_config.go` / `authz.go`.
