**Runners the server actually starts** — all from `Server.startBackgroundRunners` (`server/server.go:153-174`):

```
s3presign.Runner — one immediate RunOnce at startup, then a 12-hour time.Ticker loop
webhook async dispatch workers — 4 goroutines draining a buffered channel (event-driven, not timed)
```

- **`s3presign.Runner`** is the only entry in `startBackgroundRunners`: `RunOnce(ctx)` fires synchronously at startup (`server/server.go:163`), then `Run` is launched in a goroutine (line 167). `Run` (`server/runner/s3presign/runner.go:29`) uses `time.NewTicker(runnerInterval)` where `runnerInterval = 12 * time.Hour` (line 27), refreshing expiring S3 presigned URLs each tick, and exits on `ctx.Done()`. It gets its own cancel func and a `WaitGroup` slot for graceful shutdown (`server/server.go:157-171`).
- **Webhook workers** aren't started by `startBackgroundRunners` — they're spawned by a package `init()` in `internal/webhook/webhook.go:42`, which launches 4 goroutines consuming `asyncPostQueue` (a 128-slot buffered channel, line 39). Trigger is a `PostAsync` enqueue from a handler, not a timer; a full queue drops the delivery with a warning.

**Unused infrastructure:**

`server/runner/memopayload` is a fully-formed runner package — `NewRunner(store, markdownService)` at `server/runner/memopayload/runner.go:19` and `RunOnce` at line 27, which sweeps all memos and rebuilds their payloads — but **`memopayload.NewRunner` is never called anywhere** in non-test code, and it is not registered in `startBackgroundRunners`. Only the package-level helper `memopayload.RebuildMemoPayload` (`runner.go:74`) is used, inline in the request path at `server/router/api/v1/memo_service.go:108` (create) and `:447` (update). So the batch-rebuild runner is dead scheduling infrastructure.
