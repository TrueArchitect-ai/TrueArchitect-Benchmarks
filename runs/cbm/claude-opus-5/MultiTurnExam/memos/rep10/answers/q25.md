**Engine: Google CEL (`github.com/google/cel-go`), wrapped by the `internal/filter` package — `internal/filter/engine.go` (with `parser.go`, `ir.go`, `render.go`, `schema.go`)**

**Mechanism:** `Engine.Compile` compiles the CEL filter string against a schema-defined CEL environment and lowers the AST into a dialect-agnostic condition tree (`internal/filter/ir.go`: `LogicalCondition`, `ComparisonCondition`, `TextMatchCondition`, `RegexCondition`, …); each dialect driver then calls `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` — e.g. `store/db/sqlite/memo.go:57-61`, plus `store/db/postgres/memo.go` and `store/db/mysql/memo.go` — and `internal/filter/render.go` renders that tree into dialect-specific SQL fragments and bound args by switching on `DialectSQLite` / `DialectPostgres` / `DialectMySQL` (e.g. lines 231-237, 365-402, 654-685), which are appended to the query's WHERE clause.

The filter grammar/fields are declared in `internal/filter/schema.go`; `internal/filter/README.md` and `MAINTENANCE.md` document the supported expressions. The same engine backs user-side filtering (`server/router/api/v1/user_service_filter.go`) and shortcuts, whose saved `filter` strings are the same CEL syntax (`proto/api/v1/shortcut_service.proto:16-18`).
