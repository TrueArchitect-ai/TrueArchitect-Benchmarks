**Interceptor: `web/src/connect.ts` (`authInterceptor`, line 156, with token state in `web/src/auth-state.ts`); tokens: short-lived JWT access token (Bearer) + HttpOnly refresh-token cookie — the backend additionally accepts long-lived Personal Access Tokens (`memos_pat_…`); backend package: `server/auth` (wired via `server/router/api/v1/connect_interceptors.go` and `server/router/api/v1/v1.go`)**

**Frontend.** `authInterceptor` (`web/src/connect.ts:156`) runs on every Connect call: it fetches a token via `getRequestToken()` (line 124) and sets `Authorization: Bearer <token>`. `getRequestToken` proactively refreshes when the access token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30 s) of expiry, and on a `Code.Unauthenticated` response the interceptor refreshes once and retries with an `X-Retry` marker, redirecting to login if that fails (lines 161-177). Refresh itself goes through `refreshAccessToken` → a deduplicating `tokenRefreshManager` (lines 30-91) and a separate interceptor-free `refreshTransport`/`refreshAuthClient` (lines 65-72) to avoid recursion; `fetchWithCredentials` sets `credentials: "include"` so the refresh cookie is sent. Token storage, expiry tracking, and cross-tab sharing via `BroadcastChannel` live in `web/src/auth-state.ts`.

**Backend.** `server/auth/authenticator.go` validates all three credential kinds: `AuthenticateByAccessTokenV2` (JWT, line 41, parsing in `server/auth/token.go`), `AuthenticateByRefreshToken` (JWT plus a DB lookup of the stored token ID, line 61), and `AuthenticateByPAT` (prefix check + hash lookup via `Store.GetUserByPATHash`, line 102). `resolveBearer` (line 149) dispatches on the token prefix; `AuthenticateToUser` (line 190) falls back to the refresh cookie via `ExtractRefreshTokenFromCookie` (`server/auth/extract.go`).

The shared `Authorizer` created in `RegisterGateway` (`server/router/api/v1/v1.go:68`) drives both protocols: `NewAuthInterceptor(authorizer)` for Connect (`server/router/api/v1/connect_interceptors.go`, applied at `v1.go:137`) and `gatewayAuthMiddleware` for the REST gateway (`v1.go:69-93`); per-method access policy lives in `server/router/api/v1/authz.go` / `acl_config.go`.
