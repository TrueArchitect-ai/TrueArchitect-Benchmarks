**Server-Sent Events (SSE) over `GET /api/v1/sse`; hub: `server/router/api/v1/sse_hub.go`; handlers: `CreateMemo`, `DeleteMemo`, `CreateMemoComment`, `UpdateMemo`, `SetMemoAttachments`, `SetMemoRelations` (plus `UpsertMemoReaction` / `DeleteMemoReaction`)**

**Mechanism.** `SSEHub` (`server/router/api/v1/sse_hub.go:54`) keeps a mutex-guarded set of `SSEClient` connections, each with a buffered event channel plus the subscriber's `userID`/`role` for delivery filtering. Events are `SSEEvent` structs (`sse_hub.go:24`) with types `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted` (`sse_hub.go:15-20`). The endpoint is registered by `RegisterSSERoutes` in `server/router/api/v1/sse_handler.go:25` (called from `RegisterGateway`, `server/router/api/v1/v1.go:125`) and served by `handleSSE`, which authenticates via a Bearer token.

**Broadcast sites:**

| Handler | Call site | Event |
|---|---|---|
| `APIV1Service.CreateMemo` | `memo_service.go:163` | `memo.created` (skipped when `isSSESuppressed`) |
| `APIV1Service.DeleteMemo` | `memo_service.go:585` | `memo.deleted` |
| `APIV1Service.CreateMemoComment` | `memo_service_comments.go:126` | `memo.comment.created` |
| `APIV1Service.UpdateMemo` | via `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:71`), called at `memo_service.go:513` | `memo.updated` |
| `APIV1Service.SetMemoAttachments` | same helper, called at `memo_attachment_service.go:48` | `memo.updated` |
| `APIV1Service.SetMemoRelations` | same helper, called at `memo_relation_service.go:48` | `memo.updated` |
| `UpsertMemoReaction` / `DeleteMemoReaction` | `reaction_service.go:106` and `:161` via `buildMemoReactionSSEEvent` | `reaction.upserted` / `reaction.deleted` |

Event shaping helpers (`resolveSSECreatorID`, `buildMemoReactionSSEEvent`) live in `server/router/api/v1/sse_event_helpers.go`.
