**`/bench/repo/web/src/connect.ts` (with `/bench/repo/web/src/auth-state.ts`); short-lived JWT access token + HttpOnly refresh-token cookie (plus PATs for programmatic clients); `/bench/repo/server/auth`**

**Frontend interceptor** — `authInterceptor` at `/bench/repo/web/src/connect.ts:156-178`, installed on the Connect transport (line 188):
- Before each call it gets a token via `getRequestToken()` (line 124) and sets `Authorization: Bearer <token>`.
- It refreshes *preemptively* when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30s) of expiry (lines 140-147) — important for public endpoints like `ListMemos`, where an expired token would silently return guest-scoped data.
- On an `Unauthenticated` (401) response it refreshes once, marks the retry with an `X-Retry` header to prevent loops, and replays the request; if that fails it calls `redirectOnAuthFailure()` (lines 163-177).
- Concurrent refreshes are deduplicated by `tokenRefreshManager` (lines 30-51), and the refresh itself goes through a *separate* interceptor-free transport `refreshAuthClient` (lines 65-72) so it can't recurse.

**Token kinds:**
- **Access token** — short-lived JWT, stored in `localStorage` with its expiry and mirrored in memory across tabs (`/bench/repo/web/src/auth-state.ts:52-97`), sent as a bearer header.
- **Refresh token** — never touched by JS; carried as an HttpOnly cookie, which is why both transports set `credentials: "include"` (`connect.ts:57-62`). `refreshAuthClient.refreshToken({})` exchanges it for a new access token (lines 74-83).
- **Personal Access Token (PAT)** — same `Authorization: Bearer` slot, distinguished by prefix; used by API/MCP clients rather than the browser.

**Backend validation** — `/bench/repo/server/auth` (`authenticator.go`, `token.go`, `extract.go`, `context.go`): `Authenticator.resolveBearer` (line 149) branches on the PAT prefix, calling `AuthenticateByAccessTokenV2` → `ParseAccessTokenV2` for JWTs (line 41) or `AuthenticateByPAT` → hash lookup + expiry check (line 102); `AuthenticateByRefreshToken` (line 61) validates the cookie against the DB. It's invoked from `AuthInterceptor` in `/bench/repo/server/router/api/v1/connect_interceptors.go` for Connect traffic and from `gatewayAuthMiddleware` (`/bench/repo/server/router/api/v1/v1.go:97`) for REST, with per-method rules in `acl_config.go` / `authz.go`.
