**Engine: CEL (Google's Common Expression Language, `github.com/google/cel-go` v0.28.1) — `/bench/repo/internal/filter/`**

**Mechanism:** `Engine.Compile` (`/bench/repo/internal/filter/engine.go:47`) compiles the filter string against a CEL env built from a `Schema`, lowers the AST into a dialect-agnostic condition tree (`ir.go`, `parser.go`), and then `renderer.Render` (`/bench/repo/internal/filter/render.go:32`) walks that tree once per target `DialectName` — `sqlite`, `mysql`, `postgres` (`schema.go:14-16`) — emitting a parameterized `WHERE` fragment plus args, with per-dialect SQL templates held in each field's `Expressions` map (e.g. string concat is `('users/' || %s)` on SQLite/Postgres but `CONCAT('users/', %s)` on MySQL, and timestamps get `UNIX_TIMESTAMP(%s)` only on MySQL — `schema.go:104-147`).

Call sites: each dialect driver grabs `filter.DefaultEngine()` and calls `filter.AppendConditions(ctx, engine, find.Filters, filter.Dialect<X>, &where, &args)` — `/bench/repo/store/db/sqlite/memo.go:57,61`, `/bench/repo/store/db/postgres/memo.go:58`, `/bench/repo/store/db/mysql/memo.go:69` (same pattern in the `attachment.go` and `memo_relation.go` files). The API-layer validation of the incoming filter string lives in `/bench/repo/server/router/api/v1/memo_service_filter.go`; `/bench/repo/internal/filter/README.md` and `MAINTENANCE.md` document the supported expression surface.

The renderer also folds trivial/unsatisfiable conditions — emitting `""` or `1 = 0` rather than SQL — and `now` is frozen once per `Compile` so a single filter observes one instant.
