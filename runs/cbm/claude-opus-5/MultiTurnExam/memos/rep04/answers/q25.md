**Engine: CEL (Google Common Expression Language, via `cel-go`) — `internal/filter/`**, with the environment built in `internal/filter/engine.go:25` (`cel.NewEnv(schema.EnvOptions...)`) and the memo field schema in `internal/filter/schema.go`.

**Mechanism:** a three-phase pipeline — `parser.go` turns the CEL AST into a dialect-agnostic IR (`ir.go`) while validating fields/types against the memo schema, then `render.go` walks that IR and emits a dialect-specific SQL fragment plus bind args (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`, `internal/filter/schema.go:14`), which each driver splices into its `WHERE` clause via `filter.AppendConditions` (`internal/filter/helpers.go:9`, called from `store/db/sqlite/memo.go:61` and the postgres/mysql equivalents).

Dialect differences handled in `render.go` include `?` vs `$n` placeholders, JSON access on `memo.payload` (`json_extract` vs `->>` vs MySQL JSON functions), `LIKE` vs `ILIKE`, and tag containment (SQLite `LIKE` patterns, MySQL `JSON_CONTAINS`, Postgres `@>`) — documented in `internal/filter/README.md`. The API side validates filters before they reach the store, e.g. `validateFilter` in `server/router/api/v1/shortcut_service.go:336`.
