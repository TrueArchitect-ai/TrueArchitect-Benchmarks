**`web/src/connect.ts` (state in `web/src/auth-state.ts`); short-lived JWT access token + HTTP-only refresh-token cookie (plus Personal Access Tokens for API clients); `server/auth`**

**Interceptor.** `authInterceptor` at `web/src/connect.ts:156-178` is attached to the Connect transport (`:184-189`). Per request it resolves a token via `getRequestToken()` (`:124-150`) and sets `Authorization: Bearer <token>`; on a `Code.Unauthenticated` response it refreshes once, marks the retry with an `X-Retry` header to prevent recursion, and replays — if the refresh fails it calls `redirectOnAuthFailure()` (`:163-177`). A second, interceptor-free client exists solely for the refresh call so refreshes can't recurse (`:65-72`). Concurrent refreshes are deduplicated by `tokenRefreshManager` (`:30-51, :89-91`).

**Tokens managed.**
- *Access token* — short-lived JWT, held in memory and mirrored to `localStorage` (`memos_access_token` / `memos_token_expires_at`), with cross-tab sharing over a `BroadcastChannel` so only one tab refreshes (`web/src/auth-state.ts:1-50`). Refreshed preemptively when within 30 s of expiry, or 2 min on tab focus (`REQUEST_TOKEN_EXPIRY_BUFFER_MS` / `FOCUS_TOKEN_EXPIRY_BUFFER_MS`).
- *Refresh token* — never touched by JS; it's a cookie sent automatically because the transport uses `fetch` with `credentials: "include"` (`web/src/connect.ts:57-62`), and is exchanged via `AuthService.RefreshToken` (`:74-83`).
- *Personal Access Token* — same `Authorization: Bearer` slot, used by non-browser clients.

**Backend validation.** `server/auth` — `Authenticator` in `server/auth/authenticator.go`: `AuthenticateByAccessTokenV2` (`:41`), `AuthenticateByRefreshToken`, which also checks the token row in the DB (`:61-73`), and `AuthenticateByPAT`, which hashes the token and looks it up with expiry checking (`:102-123`). `resolveBearer` (`:149`) dispatches between JWT and PAT on the `PersonalAccessTokenPrefix`. Header/cookie extraction is in `server/auth/extract.go` (`ExtractBearerToken` :11, `ExtractRefreshTokenFromCookie` :23), JWT parse/sign in `server/auth/token.go`, and context propagation in `server/auth/context.go`. It's wired into the REST gateway through `gatewayAuthMiddleware` (`server/router/api/v1/v1.go:86-98`), with per-RPC public/anonymous allowances listed in `server/router/api/v1/acl_config.go`.
