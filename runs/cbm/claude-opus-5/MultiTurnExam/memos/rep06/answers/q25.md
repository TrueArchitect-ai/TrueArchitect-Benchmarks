**Engine: CEL (Google's Common Expression Language, `github.com/google/cel-go`) — `internal/filter/` (entry point `internal/filter/engine.go`)**

**Mechanism (one sentence):** the CEL expression is compiled by `Engine.Compile` into a dialect-agnostic condition tree (IR), and a per-dialect renderer walks that tree to emit a parameterized SQL `WHERE` fragment plus bound args, which each driver appends to its query by passing its own `DialectName`.

Detail:
- `filter.Engine` wraps a `cel.Env` built from a `Schema` (`internal/filter/engine.go:14-33`); `Compile` runs `env.Compile` and converts the AST (`:47-60`), with parsing into IR in `internal/filter/parser.go` / `internal/filter/ir.go`.
- `internal/filter/render.go` holds the renderer, which branches on `DialectSQLite` / `DialectPostgres` / `DialectMySQL` (constants at `internal/filter/schema.go:14-16`) for things that genuinely differ — timestamp extraction (`:222-240`), JSON access (`:357-410`, `jsonExtractExpr` :932), tag membership (`:434-465`), string length (`:297-302`), and placeholder style.
- Drivers call the shared helper `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` (`internal/filter/helpers.go:9-25`), which handles placeholder offsetting; see `store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:58`, `store/db/mysql/memo.go:69`. The same path is reused for attachments (`store/db/*/attachment.go`) and memo relations (`store/db/*/memo_relation.go`).
- The RPC field is documented at `proto/api/v1/memo_service.proto` (ListMemos `filter`); shortcuts store reusable CEL strings in the same grammar (`proto/api/v1/shortcut_service.proto:69-71`). User-facing notes are in `internal/filter/README.md`.
