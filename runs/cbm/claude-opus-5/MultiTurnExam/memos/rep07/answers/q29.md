**Interceptor: `web/src/connect.ts`; tokens: short-lived JWT access token (Bearer) + long-lived refresh-token cookie, plus PATs for non-browser clients; backend validator: `server/auth/`**

Frontend:

- `authInterceptor` at `web/src/connect.ts:156-178` is installed on the shared Connect transport (`:184-189`). It sets `Authorization: Bearer <token>` on every request, and on a `Code.Unauthenticated` response it refreshes once, retries with an `X-Retry` marker, and calls `redirectOnAuthFailure()` if that fails.
- Token state lives in `web/src/auth-state.ts` — the access token is cached in memory and mirrored to `localStorage`, with a `BroadcastChannel` to sync tabs and `isTokenExpired(bufferMs)` for preflight refresh (`getRequestToken`, `web/src/connect.ts:124-150`).
- Refresh goes through `refreshAccessToken` (`web/src/connect.ts:89`), deduplicated by a token-refresh manager (`:30-51`) and issued on a **separate interceptor-free transport** `refreshAuthClient` (`:65-72`) to avoid recursion. Both transports use `credentials: "include"` (`:57-62`) so the refresh cookie is sent.

Backend:

- **`server/auth/`** — `Authenticator` in `server/auth/authenticator.go` validates access tokens (`AuthenticateByAccessTokenV2`, `:41`), refresh tokens against the DB with revocation/expiry checks (`AuthenticateByRefreshToken`, `:61`), and personal access tokens (`AuthenticateByPAT`, `:102`). `AuthenticateToUser` (`:190`) prefers the `Authorization` header and falls back to the refresh cookie.
- Token constants and JWT generation/parsing are in `server/auth/token.go`: access tokens 15 min (`:40`), refresh tokens 30 days (`:43`), cookie `memos_refresh` (`:49`), PAT prefix `memos_pat_` (`:52`). Header/cookie extraction is `server/auth/extract.go`; the resolved identity is put on the request context by `server/auth/context.go`.
- It's invoked per-request by the gateway auth middleware in `server/router/api/v1/v1.go:75-92`, which also enforces per-RPC access via `authorizer.CheckAccess`.
