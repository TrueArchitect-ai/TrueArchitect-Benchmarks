Notes on individual hops:

- The mutation's `onSuccess` (`web/src/hooks/useMemoQueries.ts:186-193`) invalidates memo lists and user stats, then seeds the detail cache.
- `ConnectServiceHandler.CreateMemo` only unwraps `connect.Request` and propagates headers; it's bypassed if the caller uses the REST gateway instead (`v1pb.RegisterMemoServiceHandlerServer`, `server/router/api/v1/v1.go:108`), which routes straight to the same `APIV1Service` method.
- The handler validates content length, rebuilds the memo payload via `memopayload.RebuildMemoPayload` (`server/runner/memopayload/runner.go:74`), then after the insert fires the webhook (`DispatchMemoCreatedWebhook`) and an SSE `memo.created` broadcast (`memo_service.go:157`, `:163`).
- `Store.CreateMemo` validates the UID against `base.UIDMatcher` before delegating — the only logic in that layer.
- The SQLite driver marshals `Payload` to JSON with `protojson` and uses `RETURNING` to populate id/timestamps. Equivalents: `store/db/postgres/memo.go` and `store/db/mysql/memo.go` (MySQL lacks `RETURNING`, so it uses `LastInsertId` + a re-read).
