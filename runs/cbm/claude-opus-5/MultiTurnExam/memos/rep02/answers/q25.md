**Engine: CEL (Google Common Expression Language, `github.com/google/cel-go`) — `internal/filter/` (`internal/filter/engine.go`, entry point `DefaultEngine()` at L111 and `Engine.CompileToStatement`)**

**Mechanism:** the CEL environment in `internal/filter/schema.go:232-248` declares the allowed memo variables (`content`, `creator`, `creator_id`, `created_ts`, `updated_ts`, `pinned`, `tag`/`tags`, `visibility`, `has_task_list`, `has_link`, `has_code`, `has_incomplete_tasks`, `now`); `internal/filter/parser.go` walks the compiled CEL AST into a dialect-neutral IR of `Condition` nodes (`internal/filter/ir.go` — `LogicalCondition`, `NotCondition`, `ComparisonCondition`, …), and `internal/filter/render.go` renders that IR into a parameterized SQL fragment, switching on `DialectName` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`, `internal/filter/schema.go:11-16`) wherever the dialects differ — JSON extraction, string length, placeholder style, regex/LIKE handling.

Where it plugs in: each driver's `ListMemos` calls `filter.DefaultEngine()` then `filter.AppendConditions(ctx, engine, find.Filters, filter.DialectSQLite, &where, &args)` (`store/db/sqlite/memo.go:57-63`; same shape at `store/db/postgres/memo.go` and `store/db/mysql/memo.go` with their own dialect constants). `AppendConditions` (`internal/filter/helpers.go:9-25`) compiles each filter string, wraps the SQL in parentheses, appends it to the `WHERE` list, and appends bound args with a `PlaceholderOffset` so numbering stays correct — values are always parameterized, never interpolated.

The API side sets `find.Filters` from `ListMemosRequest.filter` in `server/router/api/v1/memo_service_filter.go`. `internal/filter/README.md` and `MAINTENANCE.md` document the supported expression surface. Shortcuts reuse the same syntax — a saved shortcut's `filter` string is passed straight to `ListMemos` (`proto/api/v1/shortcut_service.proto:15-17`).
