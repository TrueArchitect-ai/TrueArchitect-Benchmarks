Engine: Google CEL (`github.com/google/cel-go`) wrapped by the in-repo `internal/filter` package — `internal/filter/engine.go` (compile), `parser.go`/`ir.go` (dialect-agnostic condition tree), `schema.go`, `render.go` (SQL rendering). Mechanism: the CEL expression is compiled once into a dialect-agnostic `Condition` IR, then each driver calls `filter.AppendConditions(ctx, engine, find.Filters, <Dialect>, &where, &args)` with `DialectSQLite` / `DialectPostgres` / `DialectMySQL` (`store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69`), and the renderer emits dialect-specific SQL fragments + placeholder args (e.g. JSON extraction and date-part expressions branch per dialect in `internal/filter/render.go:230-241,364-408`). API-side the string is validated first via `APIV1Service.validateFilter` (`server/router/api/v1/shortcut_service.go:336`, called from `memo_service.go:211`).
