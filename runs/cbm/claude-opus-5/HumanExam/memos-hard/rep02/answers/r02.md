— Premise is wrong: there is no per-user (or any) rate-limiting middleware in this codebase. No rate-limit package is imported (`golang.org/x/time/rate` and equivalents are absent from `go.mod`), and the only textual match for "rate limit" repo-wide is an aspirational comment in `internal/email/doc.go:86`. The Echo middleware stack is just `middleware.Recover()` and the CORS middleware (`server/server.go:51-52`); API auth is handled by `gatewayAuthMiddleware` / the Connect interceptor and `Authorizer.CheckAccess` (`server/router/api/v1/v1.go:67-90`), which do authn/authz only. The nearest thing to throttling is concurrency limiting, not request-rate limiting: weighted semaphores of 3 for thumbnails and 2 for image processing (`server/router/api/v1/v1.go:59-60`), a thumbnail semaphore in the file server (`server/router/fileserver/fileserver.go:116`), a 256 MiB body cap (`server/router/api/v1/v1.go:20`), and a 128-slot webhook dispatch queue with 4 workers (`internal/webhook/webhook.go:39-55`).
