— Premise is wrong: there is no Redis anywhere in this codebase (no `redis` import in any `.go` file or in `go.mod`). The cache is a purpose-built in-process, in-memory cache: `store/cache/cache.go` (`Cache` struct at `:67`, `sync.Map`-backed, background `cleanupLoop` at `:83`). The store holds three instances — `instanceSettingCache`, `userCache`, `userSettingCache` — constructed in `store.New` at `store/store.go:51-53` with `cacheConfig{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000}` (`store/store.go:40-45`). So user entries live **10 minutes**, keyed by user ID (`userCacheKey`, `store/user.go:88`), set on read/write paths (`store/user.go:98,122,132,143,167`) and explicitly invalidated on delete (`store/user_delete.go:40`). Entries can also be evicted early once the 1000-item cap is hit (`store/cache/cache.go:117-119`). Nothing is shared across processes.
