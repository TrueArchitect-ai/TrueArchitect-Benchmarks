— **Premise is wrong: there is no message broker of any kind — neither NATS nor RabbitMQ — and no queue is declared.** Searches for `nats`, `rabbitmq`, `amqp`, and `kafka` across the Go sources and `go.mod` return zero hits. Webhook delivery is **entirely in-process**: an unbuffered-overflow-dropping Go channel `asyncPostQueue` with capacity 128 (`internal/webhook/webhook.go:39`), drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`). Producers call `webhook.PostAsync` (`:184-196`), which does a non-blocking send and **logs-and-drops** the event when the queue is full (`:191-195`); each worker calls `Post` (`:120`) to issue the HTTP POST. Consequences: no durability, no retry, and everything is lost on process restart.
