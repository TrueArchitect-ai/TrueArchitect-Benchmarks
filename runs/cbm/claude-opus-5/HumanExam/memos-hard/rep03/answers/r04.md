**Premise is wrong on both counts: there is no message broker.** Greps for `nats`, `NATS`, `rabbit`, and `amqp` return zero hits repo-wide, and `go.mod` has no broker client. The actual mechanism is an **in-process buffered Go channel**: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`), drained by **4 goroutines** started in `init()` (`internal/webhook/webhook.go:42-55`). Producers call `webhook.PostAsync` (`:184`), which does a non-blocking send and **drops** the event with a warning when the buffer is full (`:189-195`); each worker calls `webhook.Post` (`:120`) to do the HTTP POST. The queue is therefore neither durable nor shared across processes — pending webhooks are lost on restart.
