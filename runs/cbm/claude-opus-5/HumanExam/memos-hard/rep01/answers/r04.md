— Premise is wrong: there is no message broker at all — neither NATS nor RabbitMQ (nor AMQP/Kafka) appears in go.mod or any Go source. Actual mechanism: webhook delivery is fully in-process. `asyncPostQueue` is a buffered Go channel of capacity 128 (internal/webhook/webhook.go:39), drained by 4 goroutines started in `init()` (internal/webhook/webhook.go:42-55), each calling `Post` (:120). Producers call `webhook.PostAsync` (:184-196), which drops the payload with a warning if the buffer is full — there is no durable queue, no retry, and nothing survives a restart.
