Premise is wrong: **neither.** There is no external message broker at all — no NATS, RabbitMQ, AMQP, or Kafka dependency in `go.mod` or any import. Webhook delivery uses an in-process Go channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`), drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`), each calling `Post` (`webhook.go:120`). Enqueue is non-blocking and **drops** the payload when the buffer is full (`webhook.go:189-195`). The queue is per-process and non-durable: pending webhooks are lost on restart.
