Premise is wrong: **neither — there is no message broker at all.** No NATS, RabbitMQ, AMQP, or Kafka references exist in Go source or `go.mod`, and no queue is declared anywhere. Actual mechanism: an in-process buffered Go channel — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:37`), drained by 4 goroutines started in the package `init()` (`internal/webhook/webhook.go:41-52`), each calling `webhook.Post` (`internal/webhook/webhook.go:120`). Producers use non-blocking `PostAsync` (`internal/webhook/webhook.go:184-196`), which **drops** the payload with a warning when the buffer is full. It is entirely in-memory: nothing survives a restart, and there is no retry or dead-letter path.
