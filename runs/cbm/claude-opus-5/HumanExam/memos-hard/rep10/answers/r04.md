Premise is wrong: **neither** — there is no message broker at all (no NATS, RabbitMQ, AMQP, or Kafka dependency in `go.mod` or any import). Webhook delivery uses an **in-process buffered Go channel**: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` declared at `internal/webhook/webhook.go:39`, with 4 consumer goroutines started in the package `init()` at `internal/webhook/webhook.go:42-55`. Producers call `webhook.PostAsync` (`:184`), which does a non-blocking send and **drops** the event with a warning if the queue is full (`:189-195`); consumers call `webhook.Post` (`:120`). There is no declaration site for a queue, no persistence, and no retry — pending events are lost on restart.
