**Actual mechanism:** webhook delivery uses an in-process Go buffered channel with a fixed pool of goroutine workers, all inside a single server process.

- **"Queue" declaration** — `internal/webhook/webhook.go:39`:

  A package-level buffered channel with capacity 128, declared in the same `var` block as the SSRF-guarded `safeClient`.

- **Workers** — `internal/webhook/webhook.go:42-55`: a package `init()` spawns 4 goroutines (`for range 4`), each ranging over `asyncPostQueue` and calling `Post(payload)`. Failures are logged with `slog.Warn` only — there is no retry, no ack/nack, and no dead-letter path.

Because the channel lives only in process memory, a restart also loses anything still queued.
