**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package: `internal/idp`** (`internal/idp/idp.go`) — defines the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider implementation normalizes third-party user data into. It's a deliberately thin abstraction: a common data contract rather than a Go interface.

- **Implementation package: `internal/idp/oauth2`** (`internal/idp/oauth2/oauth2.go`) — the only concrete protocol implementation. Package doc: "implements the OAuth2 identity provider integration." It provides `NewIdentityProvider(*storepb.OAuth2Config)`, `ExchangeToken(ctx, redirectURL, code, codeVerifier)` (with PKCE support via `code_verifier`), and `UserInfo(ctx, token)`.

Supporting evidence:
- `server/router/api/v1/auth_service_sso.go:12-13` is the sole consumer, importing both packages; at line 120-131 it dispatches on `storepb.IdentityProvider_OAUTH2` and calls `oauth2.NewIdentityProvider(...)`, then maps the returned `*idp.IdentityProviderUserInfo` to a local or newly provisioned user.
- `proto/store/idp.proto:11-24` confirms OAuth2 is the only shipped protocol: the `Type` enum has just `TYPE_UNSPECIFIED = 0` and `OAUTH2 = 1`, and the `IdentityProviderConfig` oneof has a single variant, `oauth2_config`.
