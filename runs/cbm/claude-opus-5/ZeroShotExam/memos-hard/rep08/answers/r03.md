**Premise correction: there is no nightly database-cleanup job registered in this repository.** The cron scheduler exists, but nothing in the running application registers a cleanup job with it.

What's actually there:

- `internal/scheduler/` is a self-contained cron library (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). Grepping for imports of `github.com/usememos/memos/internal/scheduler` outside the package itself returns only its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No code under `server/`, `cmd/`, or `store/` ever constructs a `Scheduler` or calls `Register`.
- The `0 2 * * *` ("2 AM daily") daily-cleanup you may be thinking of appears only as illustrative documentation and example code, never as a live registration:
  - `internal/scheduler/README.md:34-37` — Quick Start snippet, `Name: "daily-cleanup"`, `Schedule: "0 2 * * *"`
  - `internal/scheduler/doc.go:15-16` — same snippet in the package doc comment
  - `internal/scheduler/example_test.go:97-99` — `Example_multipleJobs`, `Name: "cleanup"`, `Schedule: "0 2 * * *"`
  - `internal/scheduler/README.md:241-245` — a different doc example, `"stale-session-cleanup"` at `0 3 * * *`

The actual background work in this codebase is interval-based, not cron-scheduled:

- `server/runner/s3presign/runner.go:30` — ticker-driven runner
- `store/cache/cache.go:201` — in-memory cache eviction on a ticker, `CleanupInterval` defaulting to 5 minutes (`store/cache/cache.go:60`, `store/store.go:42`). This is cache expiry, not database cleanup.

So if you're looking for a nightly DB cleanup to modify or verify, it doesn't exist yet — only the scheduler library that could host one.
