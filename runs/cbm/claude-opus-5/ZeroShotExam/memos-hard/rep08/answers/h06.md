**Convergence function — `Post` in `internal/webhook/webhook.go:120`**

The chain: each handler calls a `Dispatch*Webhook` method in `server/router/api/v1/memo_service_webhooks.go`, which loads the user's stored webhook rows (`s.Store.GetUserWebhooks`), sets `payload.URL = hook.Url` (the user-configured URL), and calls `webhook.PostAsync` (`memo_service_webhooks.go:43,71`). `PostAsync` (`webhook.go:184`) only enqueues onto `asyncPostQueue`; the four worker goroutines started in `init()` (`webhook.go:42-55`) call `Post`, which builds the request, adds the optional HMAC `webhook-signature` headers, and issues the actual `safeClient.Do(req)` at `webhook.go:152`. So `Post` is the single point every path passes through before delivery.

Two notes:
- `UpdateMemo`, `SetMemoRelations`, and `SetMemoAttachments` share the intermediate helper `dispatchMemoUpdatedSideEffects` (`memo_update_helpers.go:66`), so if you want the convergence point *below the handler layer but above the transport*, that helper covers three of the six; `webhook.Post` is the one that covers all six.
- A separate outbound-HTTP path exists — `GetLinkMetadata` (`memo_service_link_metadata.go:46`) → `httpgetter.GetHTMLMeta`. I excluded it because its URL comes from the request itself, not from stored user configuration, and it does not pass through `webhook.Post`.
