h15.

Memo visibility is **not** centralized — the same PUBLIC/PROTECTED/PRIVATE rule is re-implemented at each surface. Distinct enforcement sites:

**Core API (gRPC/Connect, also what MCP goes through via `server/router/mcp/adapter.go`)**

Single-memo read gate `checkMemoReadAccess` (archived → creator only; non-public → auth required; private → creator only) — `server/router/api/v1/memo_service.go:39` (called from `GetMemo` :356, parent-memo resolution :367, and `ListMemoComments` at `server/router/api/v1/memo_service_comments.go:148`)
List-query visibility filter (anonymous → `[PUBLIC]`; authed → `creator_id == me || visibility in [PUBLIC, PROTECTED]`) — `server/router/api/v1/memo_service.go:216-227`
User stats visibility filter (same rule, re-implemented twice) — `server/router/api/v1/user_service_stats.go:84-92` and `:217-221`
Comment creation gate (private parent → creator/superuser only) — `server/router/api/v1/memo_service_comments.go:32-42`
Memo attachment listing gate — `server/router/api/v1/memo_attachment_service.go:213-226`
Attachment access gate `checkAttachmentAccess` (linked attachment inherits parent memo's visibility) — `server/router/api/v1/attachment_service.go:422-455`
Reaction read gate — `server/router/api/v1/reaction_service.go:29-41`; reaction write gate — `server/router/api/v1/reaction_service.go:83`
Share-token bypass path (`GetMemoByShare` returns a memo regardless of visibility, gated only on token validity/expiry and non-archived) — `server/router/api/v1/memo_share_service.go:153-195`, helper `getActiveMemoShare` :199

**Raw file server (non-gRPC HTTP surface, separate auth extraction)**

`checkAttachmentPermission` (public + anonymous-allowed → open; else share-token fallback; else authed, private → creator/admin) — `server/router/fileserver/fileserver.go:650-704`

**SSE push delivery**

`SSEClient.canReceive` — per-client broadcast filter, private events only to creator or admin, unknown visibility denied — `server/router/api/v1/sse_hub.go:133-143`

**Unauthenticated public feeds**

RSS — hardcoded `VisibilityList: []store.Visibility{store.Public}` — `server/router/rss/rss.go:90` and `:141`
Sitemap XML — same hardcoded public-only list — `server/router/frontend/frontend.go:150`

**Notification / email delivery (visibility decides whether memo content is revealed to a recipient)**

`canViewerAccessMemo` for inbox notifications — `server/router/api/v1/user_service_notifications.go:302-320`
`canViewerAccessMemo` duplicated for email notifications — `server/notification/email.go:306-320`
Mention-notification gating `canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-89`

Note the duplication risk: `canViewerAccessMemo` exists in two packages with a subtle divergence — the API copy uses `isSuperUser(user)`, the email copy checks `viewer.Role == store.RoleAdmin` directly (`server/notification/email.go:309`).
