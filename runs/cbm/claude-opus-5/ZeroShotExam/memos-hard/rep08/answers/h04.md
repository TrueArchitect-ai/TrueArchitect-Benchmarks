**No** — outside the driver-selection factory, the MySQL driver is never constructed in production code.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:14-30`, which switches on `profile.Driver` and calls `mysql.NewDB(profile)` at `store/db/db.go:22`.
- A repo-wide grep for `mysql.NewDB`, `mysql.DB{`, and imports of `store/db/mysql` returns exactly two hits, both in the factory file: the import at `store/db/db.go:8` and the call at `store/db/db.go:22`. No other package imports `store/db/mysql`.
- The constructor itself, `mysql.NewDB` (`store/db/mysql/mysql.go:20`), is the only place a populated driver value is built (`driver := DB{profile: profile}` at `store/db/mysql/mysql.go:29`).
- All other entry points go through the factory: `store/test/store.go:28`, `store/test/store.go:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(...)`.

One caveat for completeness: there is a single direct literal in the same package, `db := &DB{}` at `store/db/mysql/auth_config_test.go:12`. It's a zero-value struct in a unit test for `IsRetryableAuthenticationMutationError` — no DSN, no `sql.Open`, no connection — so it isn't a driver construction in any functional sense, and it can't be reached from outside the package anyway.
