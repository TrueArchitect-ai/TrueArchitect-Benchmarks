Memo visibility is not centralized — each server surface re-implements it. Distinct enforcement sites:

**Core gRPC/Connect API (`server/router/api/v1/`)**

- `checkMemoReadAccess` — shared single-memo read gate (anon→PUBLIC only; PRIVATE→creator only; plus archived→creator) — `server/router/api/v1/memo_service.go:39-67`; called from `GetMemo` (`:356`), the parent-memo check in `GetMemo` (`:367`), and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)
- `ListMemos` query-level filter (anon → `VisibilityList = [PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:218-227`
- `ListMemoComments` comment-relation filter (separate from the gate above, applied to the child memos) — `server/router/api/v1/memo_service_comments.go:156-161`
- `CreateMemoComment` parent-visibility check — `server/router/api/v1/memo_service_comments.go:33-43`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:213-226`
- `checkAttachmentAccess` (attachment inherits its linked memo's visibility) — `server/router/api/v1/attachment_service.go:422-455`, used by `GetAttachment` (`:256`)
- `ListMemoReactions` — `server/router/api/v1/reaction_service.go:29-41`; and `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:82-85`
- User stats visibility scoping — `server/router/api/v1/user_service_stats.go:77-92` (`ListAllUserStats`) and `:217-221` (`GetUserStats`)
- `GetMemoByShare` — the deliberate bypass: a valid, unexpired share token grants read regardless of visibility (only archived/missing is refused) — `server/router/api/v1/memo_share_service.go:153-191`

**Non-gRPC HTTP surfaces**

- Attachment file serving (Echo handler, independent of the API check above; includes the `share_token` query-param bypass) — `server/router/fileserver/fileserver.go:666-703`
- RSS feeds — hardcoded `VisibilityList: [PUBLIC]` — `server/router/rss/rss.go:90` and `server/router/rss/rss.go:141`
- Sitemap XML — hardcoded `VisibilityList: [PUBLIC]` — `server/router/frontend/frontend.go:149-152`

**Realtime push**

- SSE broadcast filtering — `SSEClient.canReceive` (PRIVATE → creator or admin; unknown visibility denied) — `server/router/api/v1/sse_hub.go:134-143`, applied in `Broadcast` (`:122-124`)

**Notification fan-out (visibility decides who gets told a memo exists)**

- Mention-notification eligibility — `server/router/api/v1/memo_mention_helpers.go:62-84`
- In-app notification content gating — `server/router/api/v1/user_service_notifications.go:309-312`
- Email notification content gating — `server/notification/email.go:313-316`

The store layer does not enforce anything — `store/db/{sqlite,postgres,mysql}/memo.go` only translate `FindMemo.VisibilityList` / `Filters` into SQL, so every caller that skips the checks above gets unfiltered rows.
