**Convergence function: `webhook.Post` — `internal/webhook/webhook.go:120`**

All six handlers funnel into the dispatchers in `server/router/api/v1/memo_service_webhooks.go`, which load the target from `s.Store.GetUserWebhooks(...)` (the user-configured URL, stored per-user and set via `CreateUserWebhook`/`UpdateUserWebhook` in `user_service_webhooks.go`) and call `webhook.PostAsync` (lines 43 and 71). `PostAsync` only enqueues onto `asyncPostQueue`; the four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) are what call `Post`, which builds the `POST`, applies the optional HMAC-SHA256 Standard-Webhooks signature, and issues the request via `safeClient.Do` (line 152). There is no other caller of `Post` outside tests, so it is the sole delivery point.

Notes:
- `safeClient` uses `safeDialContext` (line 59), which resolves the host and rejects reserved/private IPs at dial time — SSRF/DNS-rebinding guard on top of the `webhook.ValidateURL` check done at configuration time.
- Other outbound-HTTP subsystems exist (`internal/httpgetter` for link metadata, `internal/ai`, `internal/idp`, `internal/storage`), but those are separate clients and do not pass through `webhook.Post`.
