**Premise correction:** There is no GraphQL schema in this repository. Memos has no GraphQL API at all — a case-insensitive grep for `graphql` across the entire tree (Go, TypeScript, JSON, docs, `web/package.json` deps) returns zero matches. Nothing to point at, because the API is not GraphQL-shaped.

**Actual API surface: Protocol Buffers → gRPC + Connect + REST/JSON gateway.**

The schema of record is the `.proto` files in `proto/api/v1/`:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/ai_service.proto`
- `proto/api/v1/common.proto`

Each RPC carries a `google.api.http` annotation that defines its REST route — e.g. `CreateMemo` maps to `POST /api/v1/memos` and `GetMemo` to `GET /api/v1/{name=memos/*}` (`proto/api/v1/memo_service.proto:19-33`). There is a separate, internal-only `proto/store/*.proto` set for persisted types; those are not part of the public surface.

**Codegen and wiring:**

- `proto/buf.gen.yaml` drives generation: protobuf-go, grpc-go, connect-go, and grpc-gateway into `proto/gen/`, TypeScript clients into `web/src/types/proto`, plus a gnostic-openapi plugin.
- The OpenAPI spec is the generated artifact `proto/gen/openapi.yaml`, embedded into the binary by `proto/openapi_embed.go` and consumed at runtime by the MCP server (`server/router/mcp/service.go:78`).
- Handlers live in `server/router/api/v1/` — `connect_handler.go` registers Connect handlers, and `connect_services.go` adapts the gRPC implementations so both native gRPC and Connect protocols are served.

The README states this directly: "MIT-licensed with full REST and gRPC APIs for integration" (`README.md:22`).
