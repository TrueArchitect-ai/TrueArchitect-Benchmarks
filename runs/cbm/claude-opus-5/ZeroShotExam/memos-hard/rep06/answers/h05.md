**Mechanism: explicit Go code** — two `DELETE FROM reaction` statements inside the driver's delete-user transaction. There is no database-level cascade for reactions (the `reaction` table has no foreign keys at all).

**Evidence locations**

Explicit deletes (identical in all three drivers, run inside one transaction):
- `store/db/sqlite/user_delete.go` — `deleteUserTargetsTx` calls, in order, `deleteReactionsByContentIDsTx` (reactions *on* the user's memos and their comment subtree) and `deleteReactionsByCreatorTx` (reactions the user *left*, including on other people's memos). The helpers issue `DELETE FROM reaction WHERE content_id IN (...)` and `DELETE FROM reaction WHERE creator_id = ?`.
- `store/db/postgres/user_delete.go:96,102,380-402` — same two calls/helpers.
- `store/db/mysql/user_delete.go:96,102,417-439` — same.
- Content IDs come from `memoContentIDsFromRefs`, which maps the recursive memo tree to `"memos/" + uid` — matching how reactions store `content_id`.

Entry point: `server/router/api/v1/user_service.go:414` → `store.DeleteUser` (`store/user.go:171`) → driver `DeleteUser`. Also called on SSO user cleanup at `server/router/api/v1/auth_service_sso.go:77`.

No DB-level rule:
- `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98` — `CREATE TABLE reaction` declares only id/created_ts/creator_id/content_id/reaction_type plus a UNIQUE constraint; no `FOREIGN KEY`/`ON DELETE CASCADE`. The only cascade in those schema files is `memo_share.memo_id → memo(id)` (line 108/109), not reactions. Same for the original `store/migration/*/0.20/00__reaction.sql` and `0.23/00__reactions.sql`.

Test coverage confirming the behavior:
- `store/test/user_delete_test.go:97-112,217-220` — a peer's reaction on a peer memo survives, the deleted user's do not.
- `server/router/api/v1/test/user_service_delete_test.go:188-209,287-298` — reactions on the user's own memo and on their comment are empty afterward, while another user's reaction on a foreign memo remains; `:366-431` verifies the reaction is still present after a forced pre-commit rollback (failpoint), i.e. the deletes are transactional.
