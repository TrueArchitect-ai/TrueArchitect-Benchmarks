The premise doesn't hold: there is no nightly database-cleanup job in this repository's cron scheduler.

What actually exists:

- `internal/scheduler/` is a **standalone, generic cron library** (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) with zero external dependencies. Grepping for imports of `github.com/usememos/memos/internal/scheduler` returns only its own test files (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`) — **no production code registers any job with it**, database cleanup or otherwise.
- The `0 2 * * *` ("2 AM daily") schedule you may have seen is only ever **illustrative documentation**, not a registered job:
  - `internal/scheduler/doc.go:15-16` — a package-doc example named `"daily-cleanup"`
  - `internal/scheduler/README.md:34-35` and `README.md:321`
  - `internal/scheduler/example_test.go:97-100` — `Example_multipleJobs`, a job literally named `"cleanup"` that prints `"Cleaning up old data..."`
  - `internal/scheduler/parser_test.go:82` — parser test input
  - `internal/scheduler/README.md:241-245` shows a different example (`"stale-session-cleanup"` at `0 3 * * *`), which confirms these are arbitrary doc samples rather than one real configured job.

The only recurring background work actually wired up in the server runs on plain `time.Ticker` intervals, not cron:

- `server/runner/s3presign/runner.go:30` — S3 presign refresh loop
- `store/cache/cache.go:201` — in-memory cache expiry sweep on `config.CleanupInterval` (not a database cleanup)
- `server/runner/memopayload/runner.go` — memo payload rebuild

So if you're looking for a scheduled DB-cleanup time to change or verify, there isn't one to point at; the 2 AM figure comes from example code only.
