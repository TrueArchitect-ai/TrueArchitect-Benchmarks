**No** — outside the `NewDBDriver` factory, nothing in the codebase constructs the MySQL driver.

Evidence:

1. **The factory is the only external importer of the package.** Grepping for the import path `github.com/usememos/memos/store/db/mysql` yields exactly one hit: `store/db/db.go:8`, used at `store/db/db.go:22` (`driver, err = mysql.NewDB(profile)`) inside `NewDBDriver`. No other file in the repo imports the package, so `mysql.NewDB` / `mysql.DB` are unreachable by name from anywhere else.

2. **Every other construction is inside the `mysql` package itself.** Searching for `DB{` under `store/db/mysql/` returns only two sites:
   - `store/db/mysql/mysql.go:29` — `driver := DB{profile: profile}`, i.e. the body of `NewDB` itself, the very constructor the factory calls.
   - `store/db/mysql/auth_config_test.go:12` — `db := &DB{}`, a zero-value struct in an in-package unit test for `IsRetryableAuthenticationMutationError`; it never opens a connection.

3. **All driver consumers go through the factory.** The only callers of `db.NewDBDriver` are `store/test/store.go:28` and `:50` and `server/router/api/v1/test/memo_service_benchmark_test.go:70` — including the test/container harness, which does not bypass the switch.

Note the qualifier in (2): the in-package test literal at `store/db/mysql/auth_config_test.go:12` is technically a direct construction of the `DB` type, but it's inside the driver package rather than "outside the factory" in the architectural sense, and it constructs an unusable zero value rather than a live driver. The `&DB{...}` pattern appearing in Postgres (`store/db/postgres/postgres.go:33`, plus its `user_setting_test.go`) is likewise confined to that package.
