**`*markdown.service` (the only concrete impl) — built once by `markdown.NewService(...)` inside `apiv1.NewAPIV1Service` — held by `APIV1Service`, `rss.RSSService`, and (unwired) `memopayload.Runner`.**

**The interface**
- `markdown.Service` — `internal/markdown/markdown.go:31` (ExtractAll, ExtractTags, ExtractProperties, RenderMarkdown, RenderHTML, GenerateSnippet, ValidateContent, RenameTag).

**Implementation**
- Exactly one implementation exists in the repo: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:57`), returned by the constructor `NewService(opts ...Option) Service` (`internal/markdown/markdown.go:85`). There are no mocks/fakes/alternate impls — tests use the real one.
- Internally it delegates markdown-to-markdown rendering to the concrete `renderer.MarkdownRenderer` (`internal/markdown/renderer/markdown_renderer.go:15`, constructed per call in `RenderMarkdown` and `RenameTag`), and HTML rendering to goldmark's built-in renderer.

**Construction at runtime**
- Production: a single instance is created in `apiv1.NewAPIV1Service` (`server/router/api/v1/v1.go:48`) with `markdown.WithTagExtension()` + `markdown.WithMentionExtension()` (plus GFM and auto heading IDs always on). That call happens once at server startup in `server/server.go:75`.
- That same instance is then handed to the RSS service: `rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)` (`server/server.go:85`) — so RSS and the API share one object, not two.
- Tests build their own: `server/router/api/v1/test/test_helper.go:44` (tags + mentions), `server/router/fileserver/fileserver_test.go:427` (tags only), `server/router/rss/rss_test.go:54` (no extensions).

**Holders of the interface type**
- `apiv1.APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — used for `ExtractAll` in mention resolution (`server/router/api/v1/memo_mention_helpers.go:32`), `GenerateSnippet` for webhook payloads (`server/router/api/v1/memo_service_webhooks.go:85`), and passed into `memopayload.RebuildMemoPayload` on memo create/update (`server/router/api/v1/memo_service.go:108,447`).
- `rss.RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — used for `RenderHTML` in feed item descriptions (`server/router/rss/rss.go:339`).
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) — holds the interface and uses it in `RunOnce` (line 52), but `memopayload.NewRunner` has no callers anywhere in the repo, so this holder is dead at runtime; only the package-level function `RebuildMemoPayload(ctx, memo, markdownService)` (`server/runner/memopayload/runner.go:74`) actually executes, taking the service as a parameter from `APIV1Service`.

Note: this interface covers backend markdown only. The frontend renders memo content separately with markdown-it in `web/src/components/MemoContent/MemoMarkdownRenderer.tsx`, unrelated to `markdown.Service`.
