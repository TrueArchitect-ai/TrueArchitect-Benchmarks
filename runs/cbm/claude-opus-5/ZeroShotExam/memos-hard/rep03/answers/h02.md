**delivery function — `webhook.Post`, `/bench/repo/internal/webhook/webhook.go:120`; protection mechanism — `safeDialContext` + `isReservedIP`, `/bench/repo/internal/webhook/webhook.go:59` and `/bench/repo/internal/webhook/validate.go:44`**

### Where delivery executes

- Call sites are in `server/router/api/v1/memo_service_webhooks.go:43` and `:71` — memo created/updated/deleted and comment-created events call `webhook.PostAsync(payload)` with each of the creator's registered hook URLs and signing secrets.
- `PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto a buffered channel `asyncPostQueue` (cap 128), dropping with a warning if full. The actual HTTP request is made by one of 4 worker goroutines started in `init()` (`webhook.go:42-55`), which call `Post`.
- `Post` (`webhook.go:120`) marshals the payload, builds the POST, optionally adds Standard Webhooks HMAC-SHA256 headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`), and executes via the shared `safeClient` at `webhook.go:152`.

### What protects it from internal addresses

Two layers:

1. **Dial-time enforcement (the real protection).** `safeClient` (`webhook.go:32-37`) is an `http.Client` whose `Transport.DialContext` is `safeDialContext` (`webhook.go:59`). It splits the host, resolves it with `net.DefaultResolver.LookupHost`, and refuses the connection if *any* resolved IP is reserved. Because this happens at dial time rather than at URL-registration time, it also covers redirects and DNS rebinding (the comment at `webhook.go:30-31` states this intent).
2. **Registration-time validation.** `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates or updates a webhook — `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`. It requires an absolute `http`/`https` URL and rejects hostnames resolving to reserved ranges, returning a gRPC `InvalidArgument`.

Both share `isReservedIP` (`validate.go:44`), which tests against `reservedCIDRs` (`validate.go:14-23`): IPv4 loopback, the three RFC-1918 ranges, `169.254.0.0/16` (cloud IMDS), and the IPv6 equivalents `::1/128`, `fc00::/7`, `fe80::/10`.

Two things worth flagging:

- There is an escape hatch, `webhook.AllowPrivateIPs` (`validate.go:41`), which short-circuits `isReservedIP` and disables both layers. Grepping the repo, nothing ever assigns it outside the package, so it is effectively always `false` — it's currently dead config with no flag or env wiring.
- The blocklist is explicit CIDRs, not `ip.IsLoopback()/IsPrivate()`-style checks (the approach used elsewhere, e.g. `internal/httpgetter/html_meta.go:105`). So ranges like `0.0.0.0/8`, carrier-grade NAT `100.64.0.0/10`, and IPv4-mapped IPv6 forms are not covered.
