**Premise correction: this repository has no per-user API rate-limiting middleware.** There is nothing to report limits for, because no rate limiter is registered anywhere in the request path.

**What I checked**

The only two matches for "rate limit" in the entire Go codebase are documentation suggesting it as something a *user* of the email package should implement, not something Memos does:

- `internal/email/doc.go:86` — a "Security Considerations" bullet: `Rate limit email sending to prevent abuse`
- `internal/email/README.md:286-296` — a "### 5. Implement Rate Limiting" section with an illustrative `rate.NewLimiter(rate.Every(time.Second), 10)` snippet. This is example code in a fenced block; no `.go` file imports `golang.org/x/time/rate`. That module appears in `go.mod:151` only as an `// indirect` transitive dependency.

**The actual middleware chains**

HTTP middleware (Echo v5), registered in `server/server.go:51-52`:
- `middleware.Recover()`
- `newCORSMiddleware(profile)` (defined in `server/cors.go`)

Static-file serving adds two more in `server/router/frontend/frontend.go:54,59` (`StaticWithConfig`, `spaFallbackMiddleware`).

Connect RPC interceptors, registered in `server/router/api/v1/v1.go:133-137`:
- `NewMetadataInterceptor()` — HTTP headers → gRPC metadata
- `NewLoggingInterceptor(logStacktraces)`
- `NewRecoveryInterceptor(logStacktraces)`
- `NewAuthInterceptor(authorizer)` — authentication and anonymous-access policy

All four are defined in `server/router/api/v1/connect_interceptors.go`. None performs rate limiting or per-user request accounting.

There is a separate `Middleware` type in `internal/scheduler/middleware.go`, but it wraps background `JobHandler`s, not API requests, and provides only `Recovery`, `Logging`, and `Timeout` (`internal/scheduler/middleware.go:27,51,74`).

I also swept for the usual signals of a limiter — `throttl`, `limiter`, `quota`, `429`, `too many requests` — across Go sources, and for rate-limit config in the frontend (`web/src`), docs, scripts, and YAML/Dockerfile/conf deploy files. No hits. If rate limiting is enforced for a given deployment, it would have to come from a reverse proxy in front of Memos, which is not configured in this repo.
