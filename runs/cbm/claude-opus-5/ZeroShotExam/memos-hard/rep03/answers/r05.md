**Premise correction:** There is no GraphQL schema in this repository. A repo-wide search for `graphql`/`gql` across all Go, TS/TSX, JSON, proto, and Markdown files returns zero matches, and there are no `.graphql`/`.gql` files. Memos (`github.com/usememos/memos`, per `go.mod:1`) has never exposed a GraphQL API — the README itself advertises "full REST and gRPC APIs" (`README.md:22`).

**Actual API surface — Protocol Buffers, at `proto/api/v1/`**

The public API contract is defined in eight `.proto` service definitions:

- `proto/api/v1/memo_service.proto`
- `proto/api/v1/user_service.proto`
- `proto/api/v1/auth_service.proto`
- `proto/api/v1/attachment_service.proto`
- `proto/api/v1/instance_service.proto`
- `proto/api/v1/shortcut_service.proto`
- `proto/api/v1/idp_service.proto`
- `proto/api/v1/ai_service.proto`
- plus shared types in `proto/api/v1/common.proto`

These are the single source of truth. Each RPC carries a `google.api.http` annotation that defines its REST route — e.g. `proto/api/v1/memo_service.proto:30` maps `ListMemos` to `GET /api/v1/memos`, and line 35 maps `GetMemo` to `GET /api/v1/{name=memos/*}`.

**Code generation** (`proto/buf.gen.yaml`) fans these out into four surfaces:
- protobuf-go + grpc-go + connect-go → `proto/gen/api/v1/` (Go server stubs)
- grpc-gateway → the REST/JSON transcoding layer
- gnostic-openapi → `proto/gen/openapi.yaml`, the generated OpenAPI spec (embedded via `proto/openapi_embed.go`, consumed by the MCP server at `server/router/mcp/service.go:78`)
- bufbuild/es → `web/src/types/proto` (TypeScript client types)

**Runtime wiring** is in `server/router/api/v1/v1.go`: a grpc-gateway `runtime.NewServeMux` (line 96) with each service registered (lines 98–120), mounted at `/api/v1/*` and `/file/*` (lines 126–127). Connect-RPC handlers for browser clients are set up just below (line 130 onward, implementations in `server/router/api/v1/connect_services.go`).

To regenerate after editing a `.proto`, run `buf generate` from `proto/` (`proto/README.md`).
