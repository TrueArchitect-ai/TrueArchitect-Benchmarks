**Premise correction: there is no nightly database-cleanup job in this repository.** The question presupposes a scheduled cleanup job that doesn't exist.

What's actually there:

- `internal/scheduler/` is a **standalone, generic cron-scheduler library** (GitHub-Actions-inspired, zero external deps — `internal/scheduler/doc.go:1-8`). It is not imported anywhere else in the codebase — no file outside `internal/scheduler/` references it, so no job of any kind is registered against it at runtime.
- The only "cleanup" jobs you'll find are **illustrative snippets in docs and examples**, not live registrations:
  - `internal/scheduler/doc.go:15-16` — `Name: "daily-cleanup"`, `Schedule: "0 2 * * *"` (2 AM daily), in a package-doc comment.
  - `internal/scheduler/example_test.go:97-101` — `Name: "cleanup"`, `Schedule: "0 2 * * *"`, in `Example_multipleJobs`.
  - `internal/scheduler/README.md:35`, `:244` (`"stale-session-cleanup"` at `0 3 * * *`), `:321` — README examples.

So if the "2 AM" figure is what's being referenced, it comes from example/doc code, not a configured job.

The only real background work the server schedules is in `server/server.go:162-170`: the **S3 presign runner** (`server/runner/s3presign/runner.go`), started with `RunOnce` then a long-running `Run` loop — driven by an internal interval, not by cron and not a database cleanup. The other runner, `server/runner/memopayload/runner.go`, is invoked on demand from `server/router/api/v1/memo_service.go`, not on a schedule.
