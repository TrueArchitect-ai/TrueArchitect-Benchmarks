**Premise correction:** There is no Redis in this repository. Memos is a single Go binary whose only external datastore is a SQL database (SQLite/MySQL/PostgreSQL) — `grep -ri redis` over the tree returns zero hits, and `go.mod` has no Redis client dependency. There is therefore no Redis connection string, host/port, or pool configuration to point to.

**Actual mechanism — an in-process in-memory cache:**

The cache layer is a hand-rolled, thread-safe in-memory cache in `store/cache/cache.go`. It is backed by a `sync.Map` (`store/cache/cache.go:67-73`), with per-entry expiration timestamps (`item.expiration`, `store/cache/cache.go:35-39`) and a background cleanup goroutine started in `cache.New` (`store/cache/cache.go:83`, loop at `store/cache/cache.go:200-215`). Being process-local, it is not shared across instances — each server process has its own copy.

**Where it's "configured":** in code, not in any config file or env var. `store.New` builds a `cache.Config` literal and hands the same config to all three caches (`store/store.go:40-53`):

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`
- `OnEviction: nil`

The three caches are `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`), all closed on shutdown (`store/store.go:72-79`). `cache.DefaultConfig()` at `store/cache/cache.go:57-64` holds identical values but is not what the store uses — `store.New` duplicates the literal.

**TTL for user entries: 10 minutes.** Every user write path calls `s.userCache.Set(...)`, never `SetWithTTL` — `CreateUser` (`store/user.go:98`), `CreateUserIfNoUsers` (`store/user.go:122`), `UpdateUser` (`store/user.go:132`), `ListUsers` (`store/user.go:143`), and `GetUser` (`store/user.go:167`). `Set` delegates to `SetWithTTL` with `c.config.DefaultTTL` (`store/cache/cache.go:93-95`), so users inherit the 10-minute default. `SetWithTTL` exists on the interface (`store/cache/cache.go:16`) but has no non-test caller, so no entry type in the codebase currently overrides the default.

Two details worth noting about user entries specifically:

- The cache key is just the numeric user ID as a string (`userCacheKey`, `store/user.go:88-90`), and `GetUser` only consults the cache when `find.ID` is set (`store/user.go:149-156`) — lookups by username or email always hit the database.
- Entries can be dropped before their TTL: `MaxItems: 1000` triggers `cleanupOldest`, which evicts ~20% of capacity (`store/cache/cache.go:253-255`). Deletion is explicit on user removal via `s.userCache.Delete` (`store/user_delete.go:40`).
