h15.

Memo visibility is enforced in several independent places — there is no single chokepoint. Distinct enforcement sites:

**Core memo read path (Connect/gRPC API v1)**
- `checkMemoReadAccess` (single-memo read gate: archived → creator only; non-PUBLIC → must be authed; PRIVATE → creator only) — `server/router/api/v1/memo_service.go:39-68` (called from `GetMemo` :356, parent-memo check :367, and `ListMemoComments` `server/router/api/v1/memo_service_comments.go:148`)
- `ListMemos` query scoping (anonymous → `VisibilityList = [PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`) — `server/router/api/v1/memo_service.go:218-227`
- `ListMemoComments` child-memo filter (separate from the parent gate above) — `server/router/api/v1/memo_service_comments.go:157-161`
- `CreateMemoComment` gate on the parent memo + comment-visibility rule — `server/router/api/v1/memo_service_comments.go:35-43` and `:100`
- `batchConvertMemoRelations` — related/referenced memos are filtered by the same CEL visibility filter before being embedded in a response — `server/router/api/v1/memo_service_converter.go:178-206`
- User stats (`ListAllUserStats` and per-user stats) apply their own visibility scoping — `server/router/api/v1/user_service_stats.go:83-92` and `:217-221`

**Adjacent resources that re-derive memo visibility**
- `checkAttachmentAccess` (GetAttachment) — `server/router/api/v1/attachment_service.go:419-454`
- `ListMemoAttachments` inline check — `server/router/api/v1/memo_attachment_service.go:213-226`
- Reactions: `ListMemoReactions` — `server/router/api/v1/reaction_service.go:29-41`; `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:83`

**Non-gRPC HTTP surfaces**
- Raw file/blob serving `checkAttachmentPermission` (PUBLIC + anonymous-allowed, share-token fallback, PRIVATE → creator/admin) — `server/router/fileserver/fileserver.go:650-703`
- SSE live-event fan-out `SSEClient.canReceive` (PRIVATE events only to creator or admin) — `server/router/api/v1/sse_hub.go:133-144`
- RSS feeds (explore + per-user) restricted to `store.Public` — `server/router/rss/rss.go:90` and `:141`
- Sitemap generation restricted to `store.Public` — `server/router/frontend/frontend.go:150`
- Share-link resolution `GetMemoByShare` — an intentional bypass: a valid non-expired token grants read regardless of visibility (only archived/missing is refused) — `server/router/api/v1/memo_share_service.go:151-192`

**Notification/mention surfaces (gate what a recipient is shown)**
- `canViewerAccessMemo` for in-app notifications — `server/router/api/v1/user_service_notifications.go:302-321`
- `canViewerAccessMemo` duplicated for email notifications — `server/notification/email.go:306-320`
- `canUserAccessMentionContext` / `shouldSkipMentionInbox` for @-mention delivery — `server/router/api/v1/memo_mention_helpers.go:56-90`

**Mechanism, not policy**
- `FindMemo.VisibilityList` / `Filters` are translated to SQL in `store/memo.go:69` and the drivers `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`; the CEL `visibility` field is defined in `internal/filter/schema.go:162-166`. These execute the decisions made above rather than making them.

Note: the MCP surface is not a separate enforcement site — `server/router/mcp/adapter.go:26-42` replays tool calls as HTTP requests through the same Echo server, so `MemoService_ListMemos` / `MemoService_GetMemo` (`server/router/mcp/catalog.go:12,14`) inherit the API v1 checks.
