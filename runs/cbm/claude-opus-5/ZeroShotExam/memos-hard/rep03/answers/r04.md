**Premise correction:** Neither. This repo (Memos) has no external message broker at all — there is no NATS, RabbitMQ, AMQP, Kafka, or Redis dependency anywhere. `go.mod`/`go.sum` contain no broker client library (the only near-match is `go-sql-driver/mysql`, matched on "river"), and a repo-wide search for `nats`/`amqp`/`rabbit`/`jetstream` across Go, TS, YAML, and config files returns nothing. Memos ships as a single Go binary, so webhook delivery is entirely in-process.

**Actual mechanism:** The "queue" is a plain buffered Go channel with a fixed pool of goroutine workers, declared in `internal/webhook/webhook.go`:

- **Queue declaration** — `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  A package-level buffered channel with capacity 128, holding `*WebhookRequestPayload` values.

- **Workers** — `internal/webhook/webhook.go:42-55`: a package `init()` starts 4 goroutines, each ranging over `asyncPostQueue` and calling `Post(payload)`; failures are only logged via `slog.Warn` (no retry, no dead-letter).

- **Producer** — `PostAsync` at `internal/webhook/webhook.go:184-196` does a non-blocking `select` send. If the buffer is full, the payload is **dropped** with a warning ("Dropped webhook dispatch because the async queue is full") rather than blocking or persisting. A nil payload is likewise dropped (line 185-188).

- **Call sites** — `server/router/api/v1/memo_service_webhooks.go:43` and `:71` enqueue one payload per registered user webhook for `memos.memo.created/updated/deleted` and `memos.memo.comment.created`.

- **Delivery** — `Post` (`internal/webhook/webhook.go:120`) does the actual HTTP POST through `safeClient`, whose transport uses `safeDialContext` (line 59) to reject reserved/private IPs (SSRF/DNS-rebinding guard), and optionally adds Standard Webhooks HMAC headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`).

Practical consequence: the queue is in-memory and non-durable — pending webhooks are lost on process restart, and bursts beyond 128 queued items are silently dropped apart from the log line.
