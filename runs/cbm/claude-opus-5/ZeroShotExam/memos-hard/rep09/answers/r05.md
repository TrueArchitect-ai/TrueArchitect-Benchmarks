## The actual public API surface

The public API is **defined in Protocol Buffers** and served as **gRPC + Connect + a REST/JSON gateway**.

**Schema definitions — `proto/api/v1/*.proto`** (package `memos.api.v1`), one service per file:

| File | Service |
|---|---|
| `proto/api/v1/memo_service.proto:17` | `MemoService` |
| `proto/api/v1/user_service.proto:17` | `UserService` |
| `proto/api/v1/auth_service.proto:13` | `AuthService` |
| `proto/api/v1/instance_service.proto:17` | `InstanceService` |
| `proto/api/v1/attachment_service.proto:15` | `AttachmentService` |
| `proto/api/v1/shortcut_service.proto:14` | `ShortcutService` |
| `proto/api/v1/idp_service.proto:14` | `IdentityProviderService` |
| `proto/api/v1/ai_service.proto:11` | `AIService` |

Shared types live in `proto/api/v1/common.proto`; internal storage messages (not public API) are in `proto/store/*.proto`.

**Code generation** — `proto/buf.gen.yaml` runs buf with plugins for Go structs, gRPC, Connect, grpc-gateway, gnostic-OpenAPI, and TypeScript. Outputs land in `proto/gen/api/v1/` (Go) and `web/src/types/proto/` (frontend TS). Regenerate with `buf generate` (`proto/README.md`).

**The closest thing to a "schema document" for the public API** is the generated OpenAPI 3.0.3 spec at `proto/gen/openapi.yaml`, embedded into the binary via `proto/openapi_embed.go`. It documents REST paths like `/api/v1/ai:transcribe`.

**Serving** — `server/router/api/v1/v1.go`:
- `RegisterGateway` (line 64) builds a grpc-gateway mux, registers all eight service handlers, and mounts them at `/api/v1/*` and `/file/*` (lines 128–129).
- Connect-RPC handlers for browser clients are mounted at `/memos.api.v1.*` (line 144).
- Auth is applied uniformly via a shared `Authorizer` used by both the gateway middleware and the Connect interceptor.

The service implementations are the `APIV1Service` methods in `server/router/api/v1/` (e.g. `memo_service.go`, `user_service.go`), wired up from `server/server.go:88`.
