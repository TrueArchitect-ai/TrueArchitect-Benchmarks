## Data layer

The persistent entity types are the structs defined in the `store` package (`/bench/repo/store/`), each backed by a driver method in `store/db/{sqlite,postgres,mysql}`:

`User` (`store/user.go:29`), `Memo` (`store/memo.go:35`), `Attachment` (`store/attachment.go:16`), `MemoRelation` (`store/memo_relation.go:16`), `MemoShare` (`store/memo_share.go:6`), `Inbox` (`store/inbox.go:24`), `Reaction` (`store/reaction.go:7`), `UserSetting` (`store/user_setting.go:13`), `UserIdentity` (`store/user_identity.go:8`), `IdentityProvider` (`store/idp.go:12`), `InstanceSetting` (`store/instance_setting.go:14`).

## The top two

**`store.User`** — referenced from `server/router/api/v1`, `server/router/api/v1/test`, `server/router/rss`, `server/router/fileserver`, `server/router/frontend`, `server/auth`, and `server/notification`. It is the only entity that reaches the auth package (`server/auth/`), since identity resolution is cross-cutting — every request path needs the current user.

**`store.Memo`** — referenced from `server/router/api/v1`, `server/router/api/v1/test`, `server/router/rss`, `server/router/frontend`, `server/notification`, and `server/runner/memopayload`. It's the only entity touched by a background runner (`server/runner/memopayload`), which rebuilds memo payloads.

The gap between them is one package (`server/auth` and `server/router/fileserver` use `User` but not `Memo`; `server/runner/memopayload` uses `Memo` but not `User`) — so the ranking is real but narrow. By raw reference count the gap is wider (99 vs 73). Everything below `Attachment` drops off sharply, mostly confined to `server/router/api/v1` and its test package.
