**Mechanism: explicit Go code** — reactions are deleted by hand-written `DELETE FROM reaction` statements inside the `DeleteUser` transaction, in all three DB drivers. There is no database-level cascade for reactions.

Two separate deletes run per user deletion:
1. **By content** — reactions *on* the deleted user's memos (and comment memos in their tree), keyed by `content_id = "memos/<uid>"`, batched at 500.
2. **By creator** — reactions the deleted user *left* on anyone else's content, keyed by `creator_id`.

## Evidence

**Explicit Go deletes** (same structure in each driver):
- `store/db/sqlite/user_delete.go:96` and `:102` — `deleteUserTargetsTx` calls `deleteReactionsByContentIDsTx` then `deleteReactionsByCreatorTx`; implementations at `:361` (`DELETE FROM reaction WHERE content_id IN (...)`) and `:381` (`DELETE FROM reaction WHERE creator_id = ?`). Content IDs come from `memoContentIDsFromRefs` (builds `"memos/"+memo.UID`) over the recursive memo tree in `listDeleteUserMemoTreeRecursive`.
- `store/db/postgres/user_delete.go:96`, `:102`, with bodies at `:380` and `:400`.
- `store/db/mysql/user_delete.go:96`, `:102`, with bodies at `:417` and `:437`.
- Entry points: `store/driver.go:48` (interface), `store/user.go:171` (`Store.DeleteUser`), `server/router/api/v1/user_service.go:414` (API handler). All deletes plus the user row run in one transaction that commits at the end of `DB.DeleteUser`.

**Ruling out a DB-level rule** — I grepped every `REFERENCES` clause in the three schemas:
- `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98`: the `reaction` table has `creator_id`/`content_id` as plain columns with only a `UNIQUE(creator_id, content_id, reaction_type)` constraint — no foreign key, no `ON DELETE CASCADE`, and `content_id` is a text handle (`memos/<uid>`), not a FK-able reference.
- The only cascade in the entire schema is `memo_share.memo_id → memo(id) ON DELETE CASCADE` (line ~108 in each file). Nothing cascades from `user`.

**Test coverage confirming the behavior:**
- `store/test/user_delete_test.go:97-114` seeds three reactions (peer→own memo, user→peer memo, peer→peer memo); `:217-220` asserts only the third survives — i.e. both the by-content and by-creator deletes fire, and unrelated reactions are preserved.
- `server/router/api/v1/test/user_service_delete_test.go:366` and `:429-431` assert the reaction is restored when the transaction rolls back (via the `before_commit` failpoint in `store/user_delete.go:14`), confirming the deletes are transactional rather than incidental.
