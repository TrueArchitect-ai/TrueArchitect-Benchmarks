**Premise correction: this repository (Memos) has no per-user API rate-limiting middleware.** There is no requests-per-minute/hour limit, no token bucket, no `429 Too Many Requests` response, and no rate-limiter dependency in `go.mod` (no `golang.org/x/time/rate`, tollbooth, ulule/limiter, etc.).

The complete set of middleware/interceptors registered is:

- `server/server.go:51-52` — Echo middleware: `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go:13`)
- `server/router/frontend/frontend.go:54,59` — static file serving and SPA fallback
- `server/router/api/v1/v1.go:69-97` — grpc-gateway auth middleware (authenticate + `CheckAccess`)
- `server/router/api/v1/v1.go:133-138` — Connect interceptors: metadata, logging, recovery, auth (`server/router/api/v1/connect_interceptors.go`)

None of these count or throttle requests per user.

What does exist, and is probably what the question is reaching for, are two unrelated resource guards:

1. **Request body size cap** — `maxAPIRequestBytes = 256 << 20` (256 MiB), applied at `server/router/api/v1/v1.go:20,126,141,144` via `http.MaxBytesHandler` for the gateway, `/file/*`, and the Connect mux, plus `connect.WithReadMaxBytes`. This is a per-request size limit, not a request-rate limit.

2. **Global concurrency semaphores** (process-wide, not per user) — `server/router/api/v1/v1.go:59-60`: 3 concurrent thumbnail generations and 2 concurrent image-processing (EXIF-stripping) operations; the same limit of 3 for thumbnails in `server/router/fileserver/fileserver.go:46,116`. Exceeding the image-processing slot returns `codes.ResourceExhausted` ("too many image processing requests") at `server/router/api/v1/attachment_service.go:160`. These bound simultaneous in-flight work regardless of who the caller is; a single user can issue unlimited sequential requests.

The only mentions of "rate limit" in the codebase are aspirational notes in the email package docs — `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse", listed as a caller responsibility) and `internal/email/README.md:286-295` (an example snippet showing how a caller *could* implement it). Neither is implemented.

There is also no login-attempt throttling or account lockout in `server/auth/` or `server/router/api/v1/auth_service*.go`.
