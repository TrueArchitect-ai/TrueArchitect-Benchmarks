**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package — `internal/idp`** (`/bench/repo/internal/idp/idp.go`): defines the shared `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that any provider must produce. It's the provider-neutral contract consumed by the SSO flow.

- **Implementation package — `internal/idp/oauth2`** (`/bench/repo/internal/idp/oauth2/oauth2.go`): "Package oauth2 implements the OAuth2 identity provider integration." Provides `NewIdentityProvider(*storepb.OAuth2Config)`, `ExchangeToken` (with PKCE `code_verifier` support), and `UserInfo`, mapping remote claims into `idp.IdentityProviderUserInfo` via the configured `FieldMapping`.

OAuth2 is the only protocol that ships — the proto enum `IdentityProvider.Type` has just `TYPE_UNSPECIFIED` and `OAUTH2`, and the config `oneof` has a single member `oauth2_config` (`/bench/repo/proto/api/v1/idp_service.proto:76-87`). The dispatch site confirms it: `/bench/repo/server/router/api/v1/auth_service_sso.go:120-136` branches only on `storepb.IdentityProvider_OAUTH2`. No SAML or dedicated OIDC implementation exists.
