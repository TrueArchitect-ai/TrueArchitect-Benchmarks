**The full chain:** each handler above calls one of the four `Dispatch*Webhook` wrappers in `server/router/api/v1/memo_service_webhooks.go`. Three of them funnel through `dispatchMemoRelatedWebhook` (line 48); `DispatchMemoCommentCreatedWebhook` (line 30) has its own loop. Both read the target URL from `s.Store.GetUserWebhooks(...)` — `hook.Url`, which is user-supplied via the `CreateUserWebhook`/`UpdateUserWebhook` RPCs (`server/router/api/v1/user_service_webhooks.go:53,106`). Both then call `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which only enqueues onto `asyncPostQueue`; the four worker goroutines started in `init()` (line 42–55) drain that queue and call `Post`, the single function that builds and sends the outbound request.

So `PostAsync` is the shared enqueue point and `Post` is the single function all paths pass through before the request actually leaves the process.

Two notes on the delivery path: outbound requests go through `safeClient`, whose `DialContext` is `safeDialContext` (line 59) — it resolves the host and rejects reserved/private IPs, an SSRF guard that also blocks DNS rebinding. And if the payload's `SigningSecret` is set, `Post` adds Standard Webhooks HMAC-SHA256 headers (lines 133–150).

Unrelated outbound HTTP exists elsewhere (`internal/httpgetter` for link previews, `internal/idp/oauth2`, `internal/ai/*`) but those do not converge on `webhook.Post`.
