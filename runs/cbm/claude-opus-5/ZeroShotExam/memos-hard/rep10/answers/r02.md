**Premise correction: this repository has no per-user API rate-limiting middleware.** Memos (this repo) ships no rate limiter at all — no per-user, per-IP, or global request-rate throttling — so there is nowhere it is "registered" and there are no request limits to report.

What I checked:

- **Echo middleware chain** — `server/server.go:51-52` registers only `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go:13`). The frontend service adds only static-file and SPA-fallback middleware (`server/router/frontend/frontend.go:54,59`).
- **Connect/gRPC interceptors** — `server/router/api/v1/v1.go:133-137` registers exactly four: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`, auth in `server/router/api/v1/auth_service.go`/`authz.go`). None does rate limiting.
- **gRPC-Gateway** — the only gateway middleware is `gatewayAuthMiddleware` (`server/router/api/v1/v1.go:69,97`).
- **Dependencies** — no rate-limiting library is imported. `golang.org/x/time` appears in `go.mod:151` but is marked `// indirect` and `rate.Limiter` is never used in the codebase.
- **Repo-wide search** for `rate limit`/`throttle` in Go sources returns nothing; the only hits are aspirational docs in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse", listed as a suggestion) and an illustrative snippet in `internal/email/README.md:291-295` that is example prose, not compiled code.

The limits that do exist are **size/pagination caps, not rate limits**:

- `maxAPIRequestBytes = 256 << 20` (256 MiB) applied via `http.MaxBytesHandler` to `/api/v1/*`, `/file/*`, and the Connect mux, plus `connect.WithReadMaxBytes` — `server/router/api/v1/v1.go:20,126,141,144`.
- Attachment upload cap: `MaxUploadBufferSizeBytes = 32 << 20`, overridden by the instance-level `UploadSizeLimitMb` setting — `server/router/api/v1/attachment_service.go:27,120-124`.
- Page-size cap `MaxPageSize` — `server/router/api/v1/common.go:48-52`.
- Memo `contentLengthLimit` — `server/router/api/v1/memo_service.go:105,443`.
- A concurrency semaphore of 3 for thumbnail generation — `server/router/api/v1/v1.go:59` (limits parallelism, not request rate).

If you want per-user rate limiting, the natural insertion point is a new Connect interceptor added to the list at `server/router/api/v1/v1.go:133-137` (after `NewAuthInterceptor`, so the user identity is available), mirrored by an Echo middleware in `server/server.go` for the gateway/REST path.
