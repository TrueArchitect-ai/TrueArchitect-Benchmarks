**Premise correction: there is no GraphQL in this repository.** A case-insensitive search for `graphql` across the whole tree (excluding `node_modules`) returns zero hits — no `.graphql`/`.gql` schema files, no resolvers, no Apollo/gqlgen/graphql-go dependency in `go.mod` or the web `package.json`. Memos is a Go + React app whose public API is **Protobuf/Connect-RPC**, with a REST-ish HTTP mapping and a generated OpenAPI spec.

## Actual API surface

**Source of truth — Protobuf schemas in `proto/api/v1/`:**

| File | Service |
|---|---|
| `proto/api/v1/memo_service.proto:17` | `MemoService` |
| `proto/api/v1/user_service.proto:17` | `UserService` |
| `proto/api/v1/instance_service.proto:17` | `InstanceService` |
| `proto/api/v1/attachment_service.proto:15` | `AttachmentService` |
| `proto/api/v1/shortcut_service.proto:14` | `ShortcutService` |
| `proto/api/v1/idp_service.proto:14` | `IdentityProviderService` |
| `proto/api/v1/auth_service.proto:13` | `AuthService` |
| `proto/api/v1/ai_service.proto:11` | `AIService` |

Shared types are in `proto/api/v1/common.proto`; internal persistence messages (not public API) live in `proto/store/`.

**HTTP mapping** is declared inline via `google.api.http` annotations rather than a separate route table — e.g. `proto/api/v1/memo_service.proto:22-25` maps `CreateMemo` to `POST /api/v1/memos`, and line 35 maps `GetMemo` to `GET /api/v1/{name=memos/*}`. The design explicitly follows Google's AIPs (`proto/api/v1/README.md`).

**Code generation** is driven by `proto/buf.gen.yaml` (buf v2): protobuf-go, grpc-go, connect-go, and grpc-gateway output into `proto/gen/`; the gnostic-openapi plugin emits `proto/gen/openapi.yaml` (~4,000 lines, the closest analogue to the "schema document" you were asking about); and the `bufbuild/es` plugin emits TypeScript clients into `web/src/types/proto` for the frontend.

**Serving:** Connect handlers are registered in `server/router/api/v1/connect_handler.go:30-49` (one per service), with method implementations delegating to the gRPC service impls in `server/router/api/v1/connect_services.go`. The OpenAPI spec is embedded via `proto/openapi_embed.go` and consumed by the MCP router (`server/router/mcp/service.go:78`) to build its tool catalog. Other non-RPC surfaces under `server/router/` are `fileserver`, `frontend`, `rss`, and `mcp`.

So if you're looking for "the schema," it's the `.proto` files in `proto/api/v1/` — and the generated `proto/gen/openapi.yaml` if you want a single browsable document of the HTTP surface.
