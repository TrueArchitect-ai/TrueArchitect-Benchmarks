h05.

**Mechanism: explicit Go code** — reactions are deleted by hand-written `DELETE FROM reaction` statements inside the driver-level `DeleteUser` transaction. There is **no** database-level cascade: the `reaction` table has no foreign key at all in any of the three dialects.

**Evidence locations**

Explicit deletion (two separate passes, per driver, all identical in shape):

- `store/db/sqlite/user_delete.go:92-127` — `deleteUserTargetsTx` orders the deletes; line 96 calls `deleteReactionsByContentIDsTx`, line 102 calls `deleteReactionsByCreatorTx`.
  - `store/db/sqlite/user_delete.go:380-388` — `DELETE FROM reaction WHERE content_id IN (...)` — removes *everyone's* reactions on the deleted user's memos (and their comment subtree). Content IDs are built as `"memos/" + uid` at `store/db/sqlite/user_delete.go:512-518`.
  - `store/db/sqlite/user_delete.go:400-403` — `DELETE FROM reaction WHERE creator_id = ?` — removes the deleted user's own reactions on other people's memos.
- `store/db/postgres/user_delete.go:96,102,380-403` — same two functions.
- `store/db/mysql/user_delete.go:96,102,417-439` — same two functions.

All of this runs in one transaction (`BeginTx` at `store/db/sqlite/user_delete.go:29-59`), reached via `store/user.go:171-172` → `s.driver.DeleteUser`, called from the API at `server/router/api/v1/user_service.go:414-416`.

No DB-level rule:

- `store/migration/sqlite/LATEST.sql:91-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:90-98` — the `reaction` table declares only a `UNIQUE(creator_id, content_id, reaction_type)` constraint; `creator_id` is a plain `INTEGER NOT NULL` with no `REFERENCES user(id)`.
- Same in the original creation migrations: `store/migration/sqlite/0.20/00__reaction.sql`, `store/migration/postgres/0.20/00__reaction.sql`.
- Grepping `FOREIGN KEY|ON DELETE CASCADE|REFERENCES` across `store/migration/` returns cascades only for `memo_share.memo_id` (e.g. `store/migration/sqlite/LATEST.sql:109`) and for legacy pre-0.7 tables — never for `reaction`. FKs were dropped wholesale in `store/migration/sqlite/0.7/00__remove_fk.sql`.
- Even if a constraint existed, SQLite opens with them off: `store/db/sqlite/sqlite.go:53` (`_pragma=foreign_keys(0)`).
- Note `content_id` is a text key (`"memos/<uid>"`), not an integer FK, so a cascade from `memo` isn't possible for that column either.

Behavior confirmed by test: `store/test/user_delete_test.go:97-113` seeds three reactions (peer→own memo, user→peer memo, peer→peer memo) and `:216-220` asserts only the third survives — i.e. both the by-content and by-creator deletes fire.
