This repo (memos) has no external message broker at all — no NATS, no RabbitMQ, no AMQP, no Kafka. `go.mod` contains no broker client library, and a repo-wide search for `rabbitmq`/`amqp` returns zero hits. **Actual mechanism:** Webhook delivery uses an *in-process Go buffered channel* with a fixed worker pool, all inside a single binary.

- **Queue declaration** — `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  A package-level buffered channel holding 128 payloads.

- **Workers** — `internal/webhook/webhook.go:42-55`: a package `init()` starts exactly 4 goroutines, each ranging over `asyncPostQueue` and calling `Post()` on every payload, logging a warning on failure.

- **Producer** — `PostAsync()` at `internal/webhook/webhook.go:184-196` does a non-blocking `select` send. Critically, the `default` branch **drops the webhook** when the buffer is full (logging "Dropped webhook dispatch because the async queue is full"). There is no persistence, no retry, and no redelivery — a restart or a burst past 128 queued items silently loses deliveries.

- **Call sites** — `server/router/api/v1/memo_service_webhooks.go:43` and `:71` (memo created/updated/deleted, comment created), fed by webhooks registered per-user via `s.Store.GetUserWebhooks`.

- **Delivery itself** — `Post()` at `internal/webhook/webhook.go:120` does a plain HTTP POST through `safeClient`, a shared client with a 30s timeout and an SSRF-guarding `DialContext` (`internal/webhook/webhook.go:59`) that rejects reserved/private IPs, plus optional Standard Webhooks HMAC-SHA256 signing (`webhook-id`/`webhook-timestamp`/`webhook-signature` headers).
