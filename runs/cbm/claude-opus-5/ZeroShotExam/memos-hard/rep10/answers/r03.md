**Premise correction: there is no nightly database-cleanup job in this repository.** The cron scheduler exists, but nothing registers a cleanup job with it — so there is no scheduled time to report.

What's actually there:

- `internal/scheduler/` is a standalone, zero-dependency cron scheduler package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). Grepping for imports of `github.com/usememos/memos/internal/scheduler` turns up only its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No production code registers any job with it.
- The `0 2 * * *` ("2 AM daily") cleanup schedule that a search surfaces appears **only in documentation and example code**, never in a live registration:
  - `internal/scheduler/doc.go:15-17` — package doc example, `"daily-cleanup"`
  - `internal/scheduler/README.md:34-36` — README quickstart, `"daily-cleanup"`
  - `internal/scheduler/example_test.go:97-99` — `Example_multipleJobs`, job named `"cleanup"` (a `fmt.Println`, not a DB operation)
  - `internal/scheduler/README.md:241-245` also shows a `"stale-session-cleanup"` at `0 3 * * *`, again purely illustrative.

The only real periodic background work in the app is not cron-based and not database cleanup:

- `server/runner/s3presign/runner.go:27-30` — a `time.Ticker` every 12 hours, re-presigning S3 object URLs.
- `store/cache/cache.go:201` — a ticker over `CleanupInterval` that evicts expired **in-memory cache** entries, not database rows.

If you were expecting a nightly DB cleanup, it would need to be added — the scheduler package is ready for it but currently unwired.
