h15.

Memo visibility is enforced in several independent places rather than one chokepoint. Distinct enforcement sites:

**Core API v1 (gRPC/Connect) — single-memo read gate**
- `checkMemoReadAccess` (archived → creator only; non-public → must be authed; private → creator only) — `server/router/api/v1/memo_service.go:39-76` (called from `GetMemo` and its parent-memo check at `:356`/`:367`, and from `ListMemoComments` at `server/router/api/v1/memo_service_comments.go:148`)

**Core API v1 — list-query filters (pushed into the store query)**
- `ListMemos`: anonymous → `VisibilityList = [PUBLIC]`; authed → CEL filter `creator_id == me || visibility in ["PUBLIC","PROTECTED"]` — `server/router/api/v1/memo_service.go:217-227`
- `ListMemoComments` comment filter — `server/router/api/v1/memo_service_comments.go:157-162`
- `ListMemoRelations` `MemoFilter` applied to both directions — `server/router/api/v1/memo_relation_service.go:105-133`
- User stats (`ListAllUserStats`, per-user stats) — `server/router/api/v1/user_service_stats.go:78-92` and `:217-221`
- Store-side application of these filters (the SQL `visibility IN (...)` clause) — `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`

**Attachment access (API v1)**
- `checkAttachmentAccess` — unlinked → creator only; linked → follows memo visibility — `server/router/api/v1/attachment_service.go:419-455`
- `ListMemoAttachments` has its own inline check — `server/router/api/v1/memo_attachment_service.go:213-226`

**Attachment/file HTTP surface (separate from gRPC)**
- `checkAttachmentPermission` — public + anonymous-allowed passes; share-token fallback; else authed and private → creator or admin — `server/router/fileserver/fileserver.go:650-704`

**Reactions**
- `ListMemoReactions` — `server/router/api/v1/reaction_service.go:29-41`; `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:83`

**Comment creation**
- `CreateMemoComment` blocks commenting on a private memo you don't own, and forces the comment's visibility to the parent's — `server/router/api/v1/memo_service_comments.go:33-52`, `:100`

**Real-time SSE stream**
- `SSEClient.canReceive` — private events only to creator or admin — `server/router/api/v1/sse_hub.go:134-143`

**Share links (token-based bypass of the visibility rules)**
- `GetMemoByShare` intentionally skips the visibility check, gating only on a valid non-expired share token plus non-archived state — `server/router/api/v1/memo_share_service.go:153-192`, expiry at `:195`

**Anonymous/public feed surfaces (hardcoded PUBLIC-only)**
- RSS explore + per-user feeds — `server/router/rss/rss.go:90`, `:141`
- Sitemap XML — `server/router/frontend/frontend.go:150`

**Outbound notification content**
- Mention notifications suppressed for memos the target can't see — `server/router/api/v1/memo_mention_helpers.go:62-84`
- Email body/notification gating on visibility — `server/notification/email.go:313-316`, `server/router/api/v1/user_service_notifications.go:309-312`

Note the MCP surface (`server/router/mcp/`) does not re-implement checks — it proxies through the API v1 handlers, so it inherits the above.
