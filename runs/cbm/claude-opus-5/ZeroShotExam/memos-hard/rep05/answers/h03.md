**`github.com/usememos/memos/internal/idp`; `github.com/usememos/memos/internal/idp/oauth2`**

- **Abstraction package** — `internal/idp/idp.go` (package `idp`) defines the provider-agnostic contract: the `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`) that every provider implementation must normalize its user data into.
- **Implementation package** — `internal/idp/oauth2/oauth2.go` (package `oauth2`, "implements the OAuth2 identity provider integration") is the only concrete protocol that ships. It provides `NewIdentityProvider(*storepb.OAuth2Config)`, `ExchangeToken` (with optional PKCE `code_verifier`, `internal/idp/oauth2/oauth2.go:47`), and `UserInfo` (`internal/idp/oauth2/oauth2.go:83`), which maps raw claims through `FieldMapping` into `idp.IdentityProviderUserInfo`.

Supporting evidence that OAuth2 is the sole implementation:
- `proto/store/idp.proto:11-14` — the `IdentityProvider.Type` enum contains only `TYPE_UNSPECIFIED` and `OAUTH2`; `IdentityProviderConfig` is a `oneof` with just `oauth2_config`.
- `server/router/api/v1/auth_service_sso.go:12-13` is the only non-test consumer, importing exactly these two packages to run the SSO sign-in flow (`resolveSSOUser`, etc.).

There is no SAML, OIDC-specific, or LDAP package in the tree.
