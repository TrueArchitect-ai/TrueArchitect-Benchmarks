**Premise correction:** There is no nightly database-cleanup job scheduled in this repository — so it has no scheduled run time.

What actually exists:

- `internal/scheduler/` is a **standalone, general-purpose cron library** (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) with zero external dependencies. It is never imported by any production code — the only importers are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No scheduler is instantiated in `cmd/`, `server/`, or `store/`.
- Every "cleanup" job you'd find by grepping is **documentation or example code**, not a registered job:
  - `internal/scheduler/doc.go:15-16` — package-doc example, `"daily-cleanup"` at `"0 2 * * *"` (2 AM)
  - `internal/scheduler/README.md:34-36` — same quickstart example, `"0 2 * * *"`
  - `internal/scheduler/example_test.go:97-102` — `Example_multipleJobs`, a `"cleanup"` job at `"0 2 * * *"`
  - `internal/scheduler/README.md:241-244` — a best-practices snippet, `"stale-session-cleanup"` at `"0 3 * * *"` (3 AM)

Note that the illustrative schedules disagree with each other (2 AM vs. 3 AM), which is further evidence they're doc filler rather than a real job.

The actual background work in this codebase runs on interval tickers, not cron: `server/runner/s3presign/runner.go:30` (S3 presign refresh) and `store/cache/cache.go:201` (in-memory cache expiry sweep, `CleanupInterval`) — the latter cleans a cache, not the database.
