h15.

Memo visibility is not centralized — it is re-implemented at each surface that can expose memo data. Distinct enforcement sites:

**Single-memo read gate (Connect/gRPC API v1)** — `server/router/api/v1/memo_service.go:39` (`checkMemoReadAccess`: archived → creator only; non-public → requires auth; private → creator only). Called from `GetMemo` and its parent-memo check (`memo_service.go:355`, `:367`) and from `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`).

**List-query scoping (ListMemos)** — `server/router/api/v1/memo_service.go:218-227` (anonymous → `VisibilityList = [PUBLIC]`; authed → CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]`).

**Relation/comment scoping via CEL memo filter** — `server/router/api/v1/memo_relation_service.go:107-112`, `server/router/api/v1/memo_service_comments.go:157-161`, and `server/router/api/v1/memo_service_converter.go:182-187` (`batchConvertMemoRelations`); the filter is compiled into SQL sub-selects in `store/db/sqlite/memo_relation.go:80-91` (and the postgres/mysql equivalents).

**User stats** — `server/router/api/v1/user_service_stats.go:83-92` (ListAllUserStats) and `:217-221` (GetUserStats).

**Reactions** — `server/router/api/v1/reaction_service.go:29-40` (ListMemoReactions) and `:83` (UpsertMemoReaction).

**Memo attachments (API)** — `server/router/api/v1/memo_attachment_service.go:213-226` (ListMemoAttachments) and `server/router/api/v1/attachment_service.go:436-454` (attachment access check via the linked memo's visibility).

**Raw file/blob serving (Echo file server)** — `server/router/fileserver/fileserver.go:650-704` (`checkAttachmentPermission`: public + anonymous-allowed, else share-token fallback, else authenticated user, private → creator/admin).

**SSE live broadcast filtering** — `server/router/api/v1/sse_hub.go:133-143` (`SSEClient.canReceive`; private events only to creator or admin), fed by `server/router/api/v1/sse_event_helpers.go:29-37`.

**Public-only anonymous feeds** — `server/router/rss/rss.go:90` and `:141` (instance and per-user RSS), and the sitemap in `server/router/frontend/frontend.go:149-151`.

**Notification payload/recipient gating** — `server/router/api/v1/user_service_notifications.go:302-323` (`canViewerAccessMemo`, applied at `:337`, `:342`, `:370`, `:385`), the duplicate `canViewerAccessMemo` for email in `server/notification/email.go:306-321` (applied at `:155`, `:187`), and mention-target gating in `server/router/api/v1/memo_mention_helpers.go:56-89`.

**Share-token path (deliberate bypass, gated by token + expiry + ownership)** — `server/router/api/v1/memo_share_service.go:151-192` (`GetMemoByShare` intentionally does *not* consult visibility; only archived/missing are hidden), with creation restricted to the memo owner/admin at `:43-45`; the matching attachment bypass is `server/router/fileserver/fileserver.go:684-689`.

Note the duplication: `canViewerAccessMemo` exists twice with slightly different admin checks (`user.Role == store.RoleAdmin` in `email.go:310` vs `isSuperUser(viewer)` in `user_service_notifications.go:306`), and the `Public / Private+creator / else authed` triad is hand-rolled independently in the memo, reaction, attachment, memo-attachment, and fileserver paths.
