**Delivery function — `Post()` at `internal/webhook/webhook.go:120`; protection mechanism — `safeDialContext` / `isReservedIP` at `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.**

**Where delivery executes**

- `webhook.Post()` (`internal/webhook/webhook.go:120`) is the function that actually marshals the payload, builds the POST, optionally attaches Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`), and calls `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.
- Callers never invoke it directly on the request path. `webhook.PostAsync()` (`internal/webhook/webhook.go:184`) enqueues onto a buffered channel `asyncPostQueue` (cap 128), drained by 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) — those workers are where `Post` really runs. If the queue is full the dispatch is dropped with a warning, not blocked.
- Triggers are in `server/router/api/v1/memo_service_webhooks.go`: memo created/updated/deleted via `dispatchMemoRelatedWebhook` (line 48, `PostAsync` at line 71) and comment-created via `DispatchMemoCommentCreatedWebhook` (line 30, `PostAsync` at line 43). Targets come from `s.Store.GetUserWebhooks(...)`.

**What protects it from internal addresses**

Two layers, both keyed on `isReservedIP` (`internal/webhook/validate.go:44`), which tests against the CIDR list at `internal/webhook/validate.go:14-23` — IPv4 loopback, RFC-1918 ranges, `169.254.0.0/16` (cloud IMDS), plus `::1/128`, `fc00::/7`, `fe80::/10`.

1. **Dial-time enforcement (the real guard).** `safeClient` (`internal/webhook/webhook.go:32`) uses a custom `Transport.DialContext` = `safeDialContext` (`internal/webhook/webhook.go:59`). It splits host/port, resolves the host itself, and refuses the connection if *any* returned IP is reserved. Because the check happens at dial time rather than at save time, it also defeats DNS rebinding — a hostname that validated as public when the webhook was created still can't connect if it later resolves internally.
2. **Admission-time validation.** `webhook.ValidateURL()` (`internal/webhook/validate.go:62`) rejects non-absolute URLs, non-http(s) schemes, and hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument`. It's called when webhooks are created/updated in `server/router/api/v1/user_service_webhooks.go:74`, `:161`, and `:182`.

One caveat worth flagging: `AllowPrivateIPs` (`internal/webhook/validate.go:41`) is a package-level kill switch that disables both layers when true. Grepping the tree, nothing outside `internal/webhook` (and its tests) ever assigns it — there is no flag, env var, or config binding — so it's effectively hardcoded `false` and the protection is always on. The doc comment describes it as an escape hatch for self-hosted deployments targeting LAN services, but that escape hatch is currently unreachable.
