## The paths

All six are `APIV1Service` RPC handlers in `server/router/api/v1/`:

| Handler | Dispatch call |
|---|---|
| `CreateMemo` — `memo_service.go:70` | `DispatchMemoCreatedWebhook` (`memo_service.go:157`) |
| `DeleteMemo` — `memo_service.go:518` | `DispatchMemoDeletedWebhook` (`memo_service.go:562`) |
| `UpdateMemo` — `memo_service.go:401` | `dispatchMemoUpdatedSideEffects` (`memo_service.go:513`) → `DispatchMemoUpdatedWebhook` (`memo_update_helpers.go:67`) |
| `SetMemoAttachments` — `memo_attachment_service.go:16` | same helper (`memo_attachment_service.go:48`) |
| `SetMemoRelations` — `memo_relation_service.go:16` | same helper (`memo_relation_service.go:48`) |
| `CreateMemoComment` — `memo_service_comments.go:20` | `DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`) |

The four `Dispatch*Webhook` methods live in `server/router/api/v1/memo_service_webhooks.go`. Each loads the target URLs via `s.Store.GetUserWebhooks(ctx, creatorID)` — these are the user-configured URLs, registered through `CreateUserWebhook` / `UpdateUserWebhook` in `server/router/api/v1/user_service_webhooks.go` — sets `payload.URL` / `payload.SigningSecret`, and calls `webhook.PostAsync` (`memo_service_webhooks.go:43` and `:71`).

## Convergence

`webhook.PostAsync` (`internal/webhook/webhook.go:184`) is only an enqueue onto the buffered `asyncPostQueue` (drops with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:44`) drain that queue and call **`webhook.Post`** — `internal/webhook/webhook.go:120`. That is the single function that marshals the payload, adds the Standard Webhooks HMAC-SHA256 headers, and issues the actual outbound request at `safeClient.Do(req)` (`internal/webhook/webhook.go:152`).

Two notes on adjacent code that is *not* on this path:

- `webhook.ValidateURL` (`internal/webhook/validate.go`), called by `CreateUserWebhook`/`UpdateUserWebhook`, only does a DNS `net.LookupHost` for SSRF screening — no HTTP request. So the webhook-CRUD handlers themselves don't reach an outbound URL.
- Delivery-time SSRF protection is re-applied in `safeDialContext` (`internal/webhook/webhook.go:59`), which re-resolves and rejects reserved/private IPs at dial time, guarding against DNS rebinding between validation and dispatch. It can be disabled via `webhook.AllowPrivateIPs`.

Separately, `internal/httpgetter` reaches URLs supplied per-request (link previews) rather than user-*configured* ones, so it's a different path and doesn't converge on `webhook.Post`.
