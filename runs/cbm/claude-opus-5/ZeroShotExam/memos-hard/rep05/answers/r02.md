**Premise correction: there is no per-user API rate-limiting middleware in this repository.** Memos has no request-rate limiter — no per-user, per-IP, or global request/minute quotas exist anywhere in the codebase, so there are no "request limits" to report.

**What the middleware stacks actually contain:**

- Echo HTTP middleware (`server/server.go:51-52`): only `middleware.Recover()` and `newCORSMiddleware(profile)`.
- Connect RPC interceptors (`server/router/api/v1/v1.go:133-138`): `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, `NewAuthInterceptor` — authentication/authorization, logging, and panic recovery. No limiter in the chain.
- The gRPC-Gateway path gets only an auth middleware (`server/router/api/v1/v1.go:69`, `:97`).

No rate-limiting dependency (`golang.org/x/time/rate`, tollbooth, etc.) is present in `go.mod`.

**The nearest things that might be mistaken for it — all size/concurrency caps, not rate limits:**

- `maxAPIRequestBytes = 256 << 20` (256 MB) in `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` at lines 126, 144 and `connect.WithReadMaxBytes` at line 141. This is a per-request **body size** ceiling.
- `MaxUploadBufferSizeBytes = 32 << 20` (32 MB) in `server/router/api/v1/attachment_service.go:27`.
- An **image-processing concurrency semaphore** of weight 2 (`semaphore.NewWeighted(2)` at `server/router/api/v1/v1.go:60`), acquired in `server/router/api/v1/attachment_service_image.go:67-77` and used during EXIF stripping at `server/router/api/v1/attachment_service.go:158-161`. It returns `ResourceExhausted` with the message "too many image processing requests" — this reads like a rate limit but is a server-wide cap of 2 concurrent in-flight image operations, not per-user and not time-windowed. It also blocks rather than rejects: callers wait on `Acquire` until a slot frees or the context is cancelled.

**Rate limiting appears only as an unimplemented suggestion**, in the email package documentation: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") and `internal/email/README.md:286-295` ("### 5. Implement Rate Limiting"), where the sample `errors.New("rate limit exceeded")` is illustrative example code, not wired into any handler.
