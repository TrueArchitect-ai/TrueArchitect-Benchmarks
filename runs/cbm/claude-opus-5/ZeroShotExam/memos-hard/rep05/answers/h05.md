**Mechanism: explicit Go code** — reactions are removed by hand-written `DELETE FROM reaction` statements inside the per-driver user-deletion transaction. There is **no** database-level cascade for reactions.

## Deletion path

`server/router/api/v1/user_service.go:393` (`DeleteUser`) → `s.Store.DeleteUser` at line 414 → `store/user.go:171` → driver `DeleteUser` (`store/driver.go:48`).

Each driver implements the same ordered teardown in `deleteUserTargetsTx`, which makes **two** reaction deletions:

| What | sqlite | postgres | mysql |
|---|---|---|---|
| Reactions *on* the user's memos (and comment subtree), keyed by `content_id` = `"memos/"+uid` | `store/db/sqlite/user_delete.go:96`, impl `:380` | `store/db/postgres/user_delete.go:96`, impl `:380` | `store/db/mysql/user_delete.go:96`, impl `:417` |
| Reactions *authored by* the user anywhere, keyed by `creator_id` | `store/db/sqlite/user_delete.go:102`, impl `:400` | `store/db/postgres/user_delete.go:102`, impl `:400` | `store/db/mysql/user_delete.go:102`, impl `:437` |

The memo set comes from a recursive CTE (`listDeleteUserMemoTreeRecursive`, e.g. `store/db/sqlite/user_delete.go:133`) that walks `COMMENT` relations, and `content_id` values are built by `memoContentIDsFromRefs` (`:512`). Both deletes run before the memo rows are dropped, all inside one transaction committed at `:51`.

## Why it isn't a DB rule

- The `reaction` table has **no foreign key at all** — only a `UNIQUE(creator_id, content_id, reaction_type)` constraint: `store/migration/sqlite/LATEST.sql:92-99`, `store/migration/postgres/LATEST.sql:91-98`, `store/migration/mysql/LATEST.sql:91-98`. Same in the original creation migration `store/migration/sqlite/0.20/00__reaction.sql`.
- `content_id` is a text name (`"memos/<uid>"`), not a memo FK, so a cascade from `memo` couldn't reach it anyway.
- A repo-wide grep for `FOREIGN KEY|REFERENCES|ON DELETE` under `store/migration/` returns hits only for `memo_share`, `user_setting`, `memo_relation`, etc. — never `reaction`.
- Even where FKs exist, SQLite opens with enforcement off: `_pragma=foreign_keys(0)` in `store/db/sqlite/sqlite.go:53`.

## Test coverage confirming behavior

- `store/test/user_delete_test.go:97-113, 217-220` — the deleted user's reactions go away; a peer's reaction on a peer memo survives.
- `server/router/api/v1/test/user_service_delete_test.go:188-209, 287-298` — reactions on the user's own memo and on their comment are emptied, while a peer's reaction on a foreign memo is kept; `:366-431` verifies the reaction is still present after a failpoint-induced rollback, confirming the delete is transactional.
