Notes worth flagging:
- The image bytes are **not** on disk or S3 — the avatar lives inline in the `user.avatar_url` column as a `data:<mime>;base64,...` URI (`store/user.go:43`), so the "data layer" terminus is that column, not the attachment/S3 path used by `serveAttachmentFile`.
- Authorization for *another* user's avatar is coarse: any avatar is public when `Profile.AllowAnonymous()` is true (instance URL configured); otherwise any authenticated viewer can fetch any user's avatar (`server/router/fileserver/fileserver.go:171-180`). There's no per-user check beyond that.
- MIME type is re-validated against `avatarAllowedTypes` at serve time (`server/router/fileserver/fileserver.go:72`), in addition to upload-time validation in `user_service.go:335-354`.
