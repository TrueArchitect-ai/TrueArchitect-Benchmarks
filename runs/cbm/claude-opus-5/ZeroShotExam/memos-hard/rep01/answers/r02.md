**The nearest things that do exist, none of which are rate limits:**

- **Request *size* limit** — `maxAPIRequestBytes = 256 << 20` (256 MiB) at `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` to the gateway (line 126) and Connect mux (line 144), and via `connect.WithReadMaxBytes` (line 141). This caps bytes per request, not requests per user per interval.
- **Background-job middleware** — `internal/scheduler/middleware.go` has `Recovery`, `Logging`, and `Timeout`. This is for scheduled jobs, not HTTP requests, and `Timeout` (line 74) bounds job duration rather than request rate.

If you want per-user API rate limiting, the natural insertion points would be a new Connect interceptor added to the list at `server/router/api/v1/v1.go:133`, or an Echo middleware at `server/server.go:52` — the authenticated user ID is available via `server/auth/context.go`.
