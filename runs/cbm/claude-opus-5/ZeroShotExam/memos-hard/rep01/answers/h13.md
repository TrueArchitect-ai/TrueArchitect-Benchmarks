**`*markdown.service` (goldmark-backed, the only implementation) — built once by `markdown.NewService(...)` inside `apiv1.NewAPIV1Service` — held by `APIV1Service`, `rss.RSSService`, and `memopayload.Runner`.**

### The interface
`markdown.Service` — `internal/markdown/markdown.go:31-55` (ExtractAll, ExtractTags, ExtractProperties, RenderMarkdown, RenderHTML, GenerateSnippet, ValidateContent, RenameTag).

### Concrete implementation
Exactly one type satisfies it: the unexported `service` struct wrapping a `goldmark.Markdown` (`internal/markdown/markdown.go:58-60`), returned as the interface by `NewService` (`markdown.go:86-112`). There is no second impl, mock, or fake anywhere in the tree — every method (`ExtractAll`, `GenerateSnippet`, etc.) is only defined on `*service`. Internally it delegates markdown-out rendering to the concrete `renderer.NewMarkdownRenderer()` (`internal/markdown/renderer/markdown_renderer.go:20`), which is not behind the interface, and its parser is configured with GFM plus the custom `extensions.TagExtension` / `extensions.MentionExtension` goldmark extenders.

### Construction
- **Production (single site):** `server/router/api/v1/v1.go:48-51` — `NewAPIV1Service` calls `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())`, so the runtime instance has both `#tag` and `@mention` parsing enabled. Everything else reuses that one instance: `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService(...)`.
- **Tests only:** `server/router/api/v1/test/test_helper.go:44` (tags + mentions), `server/router/fileserver/fileserver_test.go:427` (tags only), `server/router/rss/rss_test.go:54` (no extensions).

Server-side HTML rendering is only for RSS; the web frontend does its own rendering with `react-markdown` (`web/package.json:59`), independent of this Go interface.
