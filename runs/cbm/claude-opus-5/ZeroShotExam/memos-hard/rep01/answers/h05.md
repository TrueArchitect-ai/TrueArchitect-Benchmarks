**Mechanism: explicit Go code** — two `DELETE FROM reaction` statements inside the user-deletion transaction, in each of the three DB drivers. There is **no** database-level cascade for reactions.

## What the Go code does

`store.DeleteUser` delegates to the driver (`store/user.go:171-181`). Each driver runs `deleteUserTargetsTx` in a single transaction, which deletes reactions twice:

- `store/db/sqlite/user_delete.go:92-102` (identical at `store/db/postgres/user_delete.go:92-102` and `store/db/mysql/user_delete.go:92-102`):
  - `deleteReactionsByContentIDsTx` — removes **all reactions on the deleted user's memos**, including reactions left by other users (`store/db/sqlite/user_delete.go:380-388`; postgres `:380`, mysql `:417`). Content IDs are built as `"memos/"+memo.UID` (`store/db/sqlite/user_delete.go:512-518`), matching the `content_id` column format.
  - `deleteReactionsByCreatorTx` — removes **reactions the user left on anyone's memos**: `DELETE FROM reaction WHERE creator_id = ?` (`store/db/sqlite/user_delete.go:400-403`; postgres `:400`, mysql `:437`).

Both run before the memo and user rows are deleted, inside the same tx that is committed at `store/db/sqlite/user_delete.go:53-56`.

## Why it can't be a DB rule

The `reaction` table has **no foreign key at all** — no `creator_id → user(id)` and no `content_id` link (content IDs are text `memos/<uid>`, not an integer FK):

- `store/migration/sqlite/LATEST.sql`, `store/migration/postgres/LATEST.sql`, `store/migration/mysql/LATEST.sql` — the `CREATE TABLE reaction` block declares only `id`, `created_ts`, `creator_id`, `content_id`, `reaction_type`, and a `UNIQUE(creator_id, content_id, reaction_type)`.
- Same in the original migrations `store/migration/{sqlite,postgres,mysql}/0.20/00__reaction.sql` and `0.23/00__reactions.sql`.
- A repo-wide grep for `FOREIGN KEY|REFERENCES` under `store/migration/` returns cascades only for `memo_share`, `memo_relation`, `user_setting`, etc. — never for `reaction`.

## Tests confirming the behavior

- `store/test/user_delete_test.go:97-112` seeds three reactions, then asserts at `:217-220` that only the unrelated peer reaction survives.
- `server/router/api/v1/test/user_service_delete_test.go:188-209, 287-291` asserts reactions on the deleted user's own memos and on their comments are empty afterward, while a peer's reaction on a foreign memo is kept.
