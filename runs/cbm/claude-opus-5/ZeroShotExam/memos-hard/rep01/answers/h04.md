**No** — outside the factory, the MySQL driver is never constructed. The only real construction site is the factory itself.

Evidence:

1. **The factory is the single caller of `mysql.NewDB`.** `store/db/db.go:22` — inside `NewDBDriver(profile)`'s switch on `profile.Driver` — is the only occurrence of `mysql.NewDB(` in the repo (grep for `NewDB(` across `*.go` returns only the three definitions in `sqlite/postgres/mysql` plus the three call sites in `db.go`, and two `sqlite.NewDB` calls in SQLite-only tests at `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416`).

2. **`store/db/mysql` is imported by exactly one file.** Grep for `store/db/mysql` shows a single import, `store/db/db.go:8`. No other package can construct the driver, since `mysql.DB`'s fields (`db`, `profile`, `config`) are unexported (`store/db/mysql/mysql.go:14-18`) — a composite literal outside the package is impossible anyway.

3. **All production and test entry points go through the factory:** `cmd/memos/main.go:57`, `store/test/store.go:28` and `:50`, and `server/router/api/v1/test/memo_service_benchmark_test.go:70` all call `db.NewDBDriver(...)`; the test helper only selects the DSN/driver string (`store/test/store.go:84-94`) and lets the factory do the construction.

Two things that look like counterexamples but aren't:
- `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` — but that's *inside* package `mysql`, a zero-value struct used only to call the pure error-classification method `IsRetryableAuthenticationMutationError`; it opens no connection.
- `store/test/containers.go` references `mysql.Run(...)`, `mysql.WithDatabase(...)` etc. (lines 101-105) and `mysqldriver.ParseDSN` (line 363) — those are the **testcontainers** `modules/mysql` package and the `go-sql-driver/mysql` package (imported at lines 16 and 20), not this repo's driver. It spins up a MySQL server container and computes a DSN, which is then fed to the factory.
