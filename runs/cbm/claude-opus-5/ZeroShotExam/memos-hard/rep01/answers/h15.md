h15.

Memo visibility is not enforced by a single chokepoint — each read surface re-implements or re-applies the rule. Distinct enforcement sites:

**Core API (Connect/gRPC v1)**

`checkMemoReadAccess()` — the shared single-memo read gate (archived → creator only; non-public → auth required; private → creator only). Called by `GetMemo` (and again for the parent memo of a comment) and by `ListMemoComments` — server/router/api/v1/memo_service.go:39, :356, :367; server/router/api/v1/memo_service_comments.go:148

`ListMemos` query-side filter — anonymous gets `VisibilityList = [PUBLIC]`; authenticated gets CEL filter `creator_id == N || visibility in ["PUBLIC","PROTECTED"]` — server/router/api/v1/memo_service.go:218-227 (comment listing repeats the same filter at server/router/api/v1/memo_service_comments.go:157-161)

Comment creation gate on the parent memo — server/router/api/v1/memo_service_comments.go:41

Reactions — `ListMemoReactions` and `UpsertMemoReaction` each inline their own copy of the check — server/router/api/v1/reaction_service.go:29-41, :82-85

Memo attachment listing — inline copy of the check — server/router/api/v1/memo_attachment_service.go:213-226

Attachment access via the API (linked attachment inherits its memo's visibility) — server/router/api/v1/attachment_service.go:436-455

User stats (`ListAllUserStats`, `GetUserStats`) — applies the same visibility filter to the counted memo set — server/router/api/v1/user_service_stats.go:77-92, :217-221

Share-token path — `GetMemoByShare` deliberately *bypasses* visibility; access is instead gated on an existing, non-expired share token (archived/missing treated as not-found) — server/router/api/v1/memo_share_service.go:153-192, `getActiveMemoShare`/`isMemoShareExpired` at :194+

**Non-gRPC HTTP surfaces (do not go through `checkMemoReadAccess`)**

Raw file/attachment serving — its own `checkAttachmentPermission`, with an anonymous-instance rule (`AllowAnonymous()`) and a `?share_token=` fallback — server/router/fileserver/fileserver.go:650-704

RSS feeds — hard-restricted to `VisibilityList = [PUBLIC]` — server/router/rss/rss.go:90, :141

Sitemap XML — hard-restricted to `VisibilityList = [PUBLIC]` — server/router/frontend/frontend.go:150

**Push / notification surfaces**

SSE broadcast fan-out — per-client `canReceive()` drops private events unless the client is the creator or an admin; visibility is attached to the event at emit time — server/router/api/v1/sse_hub.go:134-143 (and server/router/api/v1/sse_event_helpers.go:29-37)

Inbox/notification content — `canViewerAccessMemo()` decides whether a memo snippet may be shown to the notified user; duplicated in two packages — server/router/api/v1/user_service_notifications.go:302-316 and server/notification/email.go:306-320

Mention notifications — `canUserAccessMentionContext()` / `shouldSkipMentionInbox()` suppress mentions on private memos — server/router/api/v1/memo_mention_helpers.go:56-90

**Underlying mechanism (not a policy site)**

`FindMemo.VisibilityList` / `Filters` are translated to SQL `WHERE` clauses per driver — store/memo.go:69, store/db/sqlite/memo.go:96, store/db/postgres/memo.go:89, store/db/mysql/memo.go:104

Note: the MCP router is not a separate site — server/router/mcp/catalog.go:12-14 whitelists `MemoService_ListMemos`/`MemoService_GetMemo` and dispatches into the same v1 handlers, inheriting their checks.
