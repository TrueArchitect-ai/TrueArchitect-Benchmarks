**Premise correction: there is no per-user API rate-limiting middleware in this repository.** Nothing registers a rate limiter, and there are no request-per-interval limits to report. `golang.org/x/time` appears in `go.mod:151` only as an indirect dependency, and no code imports `rate`.

What actually is registered:

- **Echo middleware** (`server/server.go:51-52`): only `middleware.Recover()` and `newCORSMiddleware(profile)`.
- **Connect RPC interceptors** (`server/router/api/v1/v1.go:133-137`): `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` — all defined in `server/router/api/v1/connect_interceptors.go`. None throttles by rate.
- **gRPC-Gateway middleware** (`server/router/api/v1/v1.go:69-97`): an inline auth middleware only.

The nearest things to "limits", none of which are per-user rates:

| Limit | Location | Value |
|---|---|---|
| Max API request body size | `server/router/api/v1/v1.go:20`, applied at lines 126, 141, 144 | 256 MiB |
| Concurrent image (EXIF-strip) processing | `server/router/api/v1/v1.go:60`, acquired in `attachment_service_image.go:68-75` | semaphore of 2, process-wide |
| Concurrent thumbnail generation | `server/router/api/v1/v1.go:59` and `server/router/fileserver/fileserver.go:46,106-116` | 3, process-wide |
| Batch-size caps | `attachment_service.go:35` (100), `instance_service.go:22` (100), `user_service.go:23` (100), `memo_service.go:26` (10) | per-request item counts |
| Upload size | `attachment_service.go:120-125` | instance setting `UploadSizeLimitMb`, else `MaxUploadBufferSizeBytes` |

The image-processing semaphore is the only path returning `ResourceExhausted` (`server/router/api/v1/attachment_service.go:160`) — it bounds concurrency globally, not requests per user per interval, so callers queue rather than being rejected by quota.

Also note: there is no login-attempt throttling or lockout in `server/auth/`, and `internal/email/doc.go:86` lists rate limiting as an unimplemented recommendation, with `internal/email/README.md:286-295` giving sample `rate.NewLimiter` code that is documentation only — not wired into the codebase.
