**`s3presign.Runner` — every 12 hours (plus one synchronous pass at boot) — `server/server.go:162-171` (invoked from `Server.Start` at `server/server.go:129`)**

**What it does** — `server/runner/s3presign/runner.go`

Attachments stored in S3 (`AttachmentStorageType_S3`) are served via presigned GET URLs, which expire. The runner refreshes them before they go stale:

- `CheckAndPresign` (`runner.go:47`) pages through S3-backed attachments via `store.ListAttachments` in batches of 100 (`runner.go:55-65`).
- For each one it reads the `S3Object` payload and **skips any URL still valid for the next 4 days** (`runner.go:85-91`) — URLs are minted with a 5-day expiry, so it only re-signs those in the last day of life.
- Otherwise it builds an S3 client from the per-attachment `S3Config` (falling back to the instance-wide storage setting, `runner.go:93-96`), calls `PresignGetObject`, and writes the new URL back as the attachment's `Reference` along with an updated `LastPresignedTime` (`runner.go:108-123`).

**Schedule** — `runner.go:27`: `const runnerInterval = time.Hour * 12`, driven by a `time.Ticker` in `Run` (`runner.go:29-41`) that exits on context cancellation.

**Wiring** — `startBackgroundRunners` (`server/server.go:153`) creates a dedicated cancellable context, registers its cancel func for shutdown, then calls `RunOnce(ctx)` **synchronously at line 163** (so a server that was down past an expiry window catches up before serving traffic) before launching `Run` on a tracked `WaitGroup` goroutine at lines 166-171. Shutdown cancels and waits on it via `stopBackgroundRunners`/`waitBackgroundRunners` (`server/server.go:140,143`).

Note this is the only background runner actually started — `server/runner/memopayload` exists but isn't wired into startup.
