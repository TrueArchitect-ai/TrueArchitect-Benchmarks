**Premise correction: there is no nightly database-cleanup job in this repository.** The question assumes a scheduled DB-cleanup job exists in the cron scheduler; it does not.

What actually exists:

**1. The cron scheduler is an unused standalone library.** `internal/scheduler/` (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`) implements a GitHub Actions-inspired cron scheduler with zero external dependencies. It is imported **only by its own tests** — `internal/scheduler/example_test.go:10` and `internal/scheduler/integration_test.go:13`. No production code imports it, and every `scheduler.Register(...)` call in the repo lives in test files or documentation.

**2. The "2 AM cleanup" you may be thinking of is documentation boilerplate, not a registered job:**
- `internal/scheduler/doc.go:14-20` — package doc example: `Name: "daily-cleanup"`, `Schedule: "0 2 * * *", // 2 AM daily`
- `internal/scheduler/README.md:34-35` — same example in the quick-start
- `internal/scheduler/example_test.go:97-100` — `Name: "cleanup"`, `Schedule: "0 2 * * *"`, which just prints "Cleaning up old data..."
- `internal/scheduler/README.md:241-245` — a *hypothetical* `stale-session-cleanup` at `"0 3 * * *"` in the best-practices section, with no such handler implemented anywhere

None of these touch a database; the handlers are `fmt.Println` stubs or prose.

**3. The real background/periodic work uses `time.Ticker`, not cron, and isn't nightly:**
- `server/runner/s3presign/runner.go:26-36` — re-signs S3 URLs on a **12-hour** interval ticker
- `server/runner/memopayload/runner.go:26-27` — `RunOnce`-style payload rebuild, no schedule attached
- `store/cache/cache.go:199-218` (with `CleanupInterval: 5 * time.Minute` at `store/cache/cache.go:60` and `store/store.go:42`) — an in-memory cache expiry loop, not a database cleanup

So the closest thing to a "cleanup at a scheduled time" is the `0 2 * * *` (2:00 AM) example in the scheduler's docs and example test — but it is illustrative sample code for an unwired library, not a job this application ever runs.
