**delivery function** — `webhook.Post` in `internal/webhook/webhook.go:120` (it builds the JSON POST, adds the Standard Webhooks HMAC headers, and calls `safeClient.Do` at `internal/webhook/webhook.go:152`). Callers don't invoke it directly: `webhook.PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto a bounded 128-slot channel drained by 4 worker goroutines started in `init()` (`internal/webhook/webhook.go:39-55`), so the actual outbound HTTP request executes on those workers. Dispatch is triggered from `server/router/api/v1/memo_service_webhooks.go:43` and `:71` on memo create/update/delete and comment-created.

**protection mechanism** — two layers, both keyed on `isReservedIP` in `internal/webhook/validate.go:44`:

1. Dial-time SSRF guard (the real enforcement): `safeDialContext` — `internal/webhook/webhook.go:59`, installed as the `Transport.DialContext` of the shared `safeClient` (`internal/webhook/webhook.go:32-37`). It resolves the host itself and refuses to dial if any resolved address falls in a reserved range. Because this runs at connect time rather than at save time, it also defeats DNS rebinding.
2. Admission-time validation: `webhook.ValidateURL` — `internal/webhook/validate.go:62`, called when a user creates/updates a webhook (`server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`). It enforces http/https scheme and rejects hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument`.

The blocked ranges are the `reservedCIDRs` list at `internal/webhook/validate.go:14-23` — IPv4 loopback, RFC-1918, 169.254.0.0/16 (cloud IMDS), plus IPv6 loopback/ULA/link-local.

One caveat worth noting: the whole guard is defeatable by design via the global `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`), set from the `--allow-private-webhooks` CLI flag at `cmd/memos/main.go:49` (declared at `:133`, bound to viper at `:160`), for self-hosters targeting LAN services.
