**Premise correction: there is no nightly database-cleanup job scheduled in this repository.**

The premise assumes the cron scheduler has a registered database-cleanup job. It doesn't. Here's what actually exists:

**1. The scheduler is an unused library, not a running system.** `internal/scheduler/` is a standalone, zero-dependency cron package (`scheduler.go`, `job.go`, `parser.go`, `middleware.go`). Grepping for imports of `github.com/usememos/memos/internal/scheduler` outside the package itself returns only its own `example_test.go:10` and `integration_test.go:13` — no production code ever calls `scheduler.New()` or `Register()`. The server's background work is wired up in `server/server.go:153` (`startBackgroundRunners`), which starts only the s3presign runner (`server/runner/s3presign/runner.go`, a 12-hour `time.Ticker` at line 27) — not the cron scheduler.

**2. The "0 2 * * *" you may have seen is documentation, not configuration.** A cleanup job at 2 AM appears three times, all as illustrative examples with no-op or placeholder handlers:
- `internal/scheduler/doc.go:14-21` — `"daily-cleanup"`, `"0 2 * * *"`, handler body is `// Your cleanup logic here; return nil`
- `internal/scheduler/example_test.go:97-100` — `"cleanup"`, `"0 2 * * *"`, commented "Cleanup old data every night at 2 AM"
- `internal/scheduler/README.md:35` and `:321` — same expression in the quickstart and a test snippet

None of these touch a database; they're generic examples. The README also shows a `"stale-session-cleanup"` at `"0 3 * * *"` (`README.md:241-244`), again purely as a docs sample for job metadata fields.

So if you're looking for the schedule of a real DB-cleanup task: it doesn't exist. If you're asking what the example cleanup job in the scheduler docs uses, that's `0 2 * * *` — 2:00 AM daily, in whatever timezone the scheduler is constructed with (default local, overridable via `WithTimezone`).
