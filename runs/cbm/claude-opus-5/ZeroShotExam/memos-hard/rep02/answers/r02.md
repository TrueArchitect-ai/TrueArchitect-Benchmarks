**Premise correction: there is no per-user API rate-limiting middleware in this repository.** No such middleware/interceptor is registered anywhere, so there are no request limits to report.

What I checked:

- **Echo middleware chain** — `server/server.go:51-52` registers only `middleware.Recover()` and `newCORSMiddleware(profile)` (`server/cors.go:14`). The frontend service adds only static-file and SPA-fallback middleware (`server/router/frontend/frontend.go:54,59`).
- **Connect/gRPC interceptors** — `server/router/api/v1/v1.go:133-137` registers exactly four: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, `AuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`). None does rate limiting.
- **Gateway middleware** — `server/router/api/v1/v1.go:69,97` wires a single `gatewayAuthMiddleware`, which is authentication, not throttling.
- **Dependencies** — `golang.org/x/time` is present in `go.mod:151` but marked `// indirect`; nothing in the repo imports `x/time/rate`, and Echo's `middleware.RateLimiter` is never imported.
- Repo-wide greps for `rate limit`, `limiter`, `quota`, `throttle`, `burst`, `429`, `RESOURCE_EXHAUSTED` across Go code, `proto/`, `docs/`, and `web/src/` turn up nothing. Git history has no rate-limit commits.

The only rate-limiting mention is aspirational documentation for email sending, not an implemented API middleware: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") and `internal/email/README.md:286-296`, which sketches an example `rate.NewLimiter(rate.Every(time.Second), 10)` as a suggestion for callers.

The nearest thing to an actual per-request limit is a **payload size** cap, not a rate cap: `maxAPIRequestBytes = 256 << 20` (256 MiB) at `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` to the gateway (`:126`) and Connect mux (`:144`), plus `connect.WithReadMaxBytes` (`:141`). Per-user enforcement in this codebase is authorization (`server/router/api/v1/authz.go`, `acl_config.go`), which controls *which* calls a user may make, not how many.
