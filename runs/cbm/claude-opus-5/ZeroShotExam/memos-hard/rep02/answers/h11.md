**1st: `store.User` (~7 packages); 2nd: `store.Memo` (~6 packages)**

The data layer is the `store` package (`/bench/repo/store/`), which defines the persistent entity structs: `User` (`store/user.go`), `Memo` (`store/memo.go`), `Attachment`, `Reaction`, `Inbox`, `MemoRelation`, `MemoShare`, `IdentityProvider`, `InstanceSetting`, `UserSetting`, `UserIdentity`.

Counting distinct Go packages outside the `store/` tree that reference each type:

| Type | Packages | Total refs |
|---|---|---|
| `store.User` | **7** | 93 |
| `store.Memo` | **6** | 64 |
| `store.Attachment` | 4 | 43 |
| `store.Inbox` / `MemoShare` / `MemoRelation` | 3 | 9–13 |

**`store.User`** — referenced from `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/auth`, `server/notification`, `server/router/rss`, `server/router/frontend`.

**`store.Memo`** — referenced from `server/router/api/v1`, `server/router/api/v1/test`, `server/notification`, `server/router/rss`, `server/router/frontend`, `server/runner/memopayload`.

Two notes on the count: `store`-internal subpackages (`store/db/{sqlite,mysql,postgres}`, `store/test`) are excluded as part of the data layer itself — including them would add 4 packages to each type without changing the ranking. If you also exclude the `_test` package, it's User at 6 and Memo at 5 — same order. `Memo` leads on raw reference density in `server/router/api/v1`, but `User` spreads across more consumers because auth, the file server, and notifications all need it.
