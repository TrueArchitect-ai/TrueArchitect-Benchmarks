**Mechanism: explicit Go code** — reactions are deleted by hand-written `DELETE FROM reaction` statements inside the delete-user transaction, in each of the three DB drivers. There is no FK/cascade or trigger on the `reaction` table.

**What I checked and what it shows**

1. **API entry point** — `server/router/api/v1/user_service.go:393` (`DeleteUser`) calls `s.Store.DeleteUser(...)` at line 414, which delegates to the driver: `store/user.go:171-181`.

2. **Driver delete logic** — the per-driver transaction runs two reaction deletes explicitly, before the memos and the user row are removed:
   - SQLite: `store/db/sqlite/user_delete.go:96` and `:102` call `deleteReactionsByContentIDsTx` (`:380-388`, `DELETE FROM reaction WHERE content_id IN (...)`, batched at 500) and `deleteReactionsByCreatorTx` (`:400-403`, `DELETE FROM reaction WHERE creator_id = ?`).
   - Postgres: `store/db/postgres/user_delete.go:96, 102, 380-403` — same pair.
   - MySQL: `store/db/mysql/user_delete.go:96, 102, 417-439` — same pair.

   So both directions are covered: reactions *authored by* the deleted user (by `creator_id`), and reactions *left by others on* the deleted user's memos and comment subtree (by `content_id`, built as `"memos/"+uid` in `memoContentIDsFromRefs`, `store/db/sqlite/user_delete.go:512-518`).

3. **Schema — no database-level rule.** The `reaction` table has no foreign keys at all:
   - `store/migration/sqlite/LATEST.sql:92-99`
   - `store/migration/postgres/LATEST.sql:91-98`
   - `store/migration/mysql/LATEST.sql:91-98`

   A repo-wide grep for `FOREIGN KEY`/`ON DELETE` across `store/migration/` returns hits only for `memo_share → memo` (LATEST files) and old pre-0.7 migrations that were superseded; none reference `reaction`. Triggers exist only in the historical 0.5 migration and were dropped in `store/migration/sqlite/0.7/01__remove_triggers.sql`.

4. **Test confirmation** — `store/test/user_delete_test.go:97-113` seeds three reactions (peer→deleted user's memo, deleted user→peer's memo, peer→peer's memo) and asserts at `:216-220` that only the third survives, i.e. the first two are removed by the explicit deletes.
