**`internal/idp`; `internal/idp/oauth2`**

- **Abstraction package: `internal/idp`** — `internal/idp/idp.go` defines the provider-neutral `IdentityProviderUserInfo` struct (`Identifier`, `DisplayName`, `Email`, `AvatarURL`), the common shape every IdP implementation must produce.
- **Implementation package: `internal/idp/oauth2`** — `internal/idp/oauth2/oauth2.go` ("Package oauth2 implements the OAuth2 identity provider integration") provides `IdentityProvider`, built from `storepb.OAuth2Config` via `NewIdentityProvider`, with `ExchangeToken` (including PKCE `codeVerifier` support) and user-info retrieval mapped through the config's `FieldMapping`.

OAuth2 is the only concrete protocol that ships — `internal/idp/` contains just `idp.go` and the `oauth2/` subpackage. The wiring lives in `server/router/api/v1/auth_service_sso.go:121`, where `resolveSSOIdentity` switches on the stored provider config and calls `oauth2.NewIdentityProvider(identityProvider.Config.GetOauth2Config())`, returning an `*idp.IdentityProviderUserInfo` that `resolveSSOUser` (`auth_service_sso.go:19`) uses to link or create the local user.
