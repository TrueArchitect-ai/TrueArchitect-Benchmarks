h15.

Memo visibility is **not** centralized in one guard — there is one shared helper for single-memo reads, but each surface that can expose memo data re-implements or re-applies the rule independently. Distinct enforcement sites:

**Core API v1 (gRPC/Connect) — single-memo read guard**
- `checkMemoReadAccess` (archived → creator-only; non-public → auth required; PRIVATE → creator only) — `server/router/api/v1/memo_service.go:39-66`, called from `GetMemo` and its parent-memo check (`server/router/api/v1/memo_service.go:355`, `:367`) and from `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`)

**List/query surfaces (filter injected into `store.FindMemo`)**
- `ListMemos` visibility filter — `server/router/api/v1/memo_service.go:217-227`
- `ListMemoComments` comment-level filter — `server/router/api/v1/memo_service_comments.go:155-161`
- `ListAllUserStats` — `server/router/api/v1/user_service_stats.go:78-92`
- `GetUserStats` — `server/router/api/v1/user_service_stats.go:216-221`
- RSS feeds (explore + per-user, public-only) — `server/router/rss/rss.go:90`, `server/router/rss/rss.go:141`
- Sitemap XML (public-only) — `server/router/frontend/frontend.go:150`
- SQL application of `VisibilityList` (mechanism, not policy) — `store/db/sqlite/memo.go:96`, `store/db/postgres/memo.go:89`, `store/db/mysql/memo.go:104`

**Sub-resource surfaces (own copy of the check)**
- `ListMemoReactions` — `server/router/api/v1/reaction_service.go:29-42`
- `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:82-85`
- `checkAttachmentAccess` (attachment metadata via memo) — `server/router/api/v1/attachment_service.go:437-455`
- `ListMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:213-226`
- `CreateMemoComment` (parent-memo visibility) — `server/router/api/v1/memo_service_comments.go:41`

**Raw file HTTP surface (non-gRPC, Echo)**
- `checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650-704` (public+anonymous allowed at `:677`, share-token fallback at `:684-689`, PRIVATE check at `:699`)

**Realtime push surface**
- `SSEClient.canReceive` — event fan-out filtered by memo visibility — `server/router/api/v1/sse_hub.go:134-145` (event visibility stamped in `SSEEvent`)

**Share-token surface (bypasses visibility by design)**
- `GetMemoByShare` / `getActiveMemoShare` — unauthenticated read of any non-archived memo holding a valid, unexpired token — `server/router/api/v1/memo_share_service.go:152-212`; creation restricted to creator/admin at `server/router/api/v1/memo_share_service.go:42-44`

**Notification/outbound surfaces (own `canViewerAccessMemo` copies)**
- Inbox notifications — `server/router/api/v1/user_service_notifications.go:302-316`
- Email notifications (separate duplicate of the same function) — `server/notification/email.go:306-320`
- Mention notifications — `canUserAccessMentionContext` / `shouldSkipMentionInbox` — `server/router/api/v1/memo_mention_helpers.go:56-88`

Note: the MCP surface is not a separate site — `server/router/mcp/adapter.go:27-92` replays tool calls as HTTP requests into the same Echo server, so `MemoService_GetMemo`/`ListMemos` (`server/router/mcp/catalog.go:12-14`) inherit the API v1 checks.
