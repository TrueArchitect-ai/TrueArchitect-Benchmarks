**The path:**

- Each handler reaches `dispatchMemoRelatedWebhook` or `DispatchMemoCommentCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48` and `:30`). `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66`) is the shared fan-in for the three update-shaped handlers.
- Both load `s.Store.GetUserWebhooks(ctx, creatorID)` and set `payload.URL = hook.Url` — the URL comes from user settings, written by the `CreateUserWebhook` / `UpdateUserWebhook` RPCs in `server/router/api/v1/user_service_webhooks.go:53,106`.
- Every call site then hands off to `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto `asyncPostQueue`; four worker goroutines started in `init()` (`:42-55`) drain it into `webhook.Post`.
- `Post` is the only place the request is built and executed: `http.NewRequest("POST", requestPayload.URL, …)` at `:126`, optional Standard-Webhooks HMAC signing at `:133-150`, and the actual send `safeClient.Do(req)` at `:152`.

Two notes on the surrounding controls: `safeClient` uses `safeDialContext` (`:59`), which re-resolves the host at dial time and rejects reserved/private IPs, so SSRF is blocked at delivery rather than only at configuration time (`internal/webhook/validate.go` `ValidateURL` covers the config-time check). That guard is bypassable by design via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`).

Separately, `GetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go`, via `internal/httpgetter`) also issues outbound HTTP to a caller-supplied URL, but that URL is per-request rather than user-configured, and it does not pass through `webhook.Post`.
