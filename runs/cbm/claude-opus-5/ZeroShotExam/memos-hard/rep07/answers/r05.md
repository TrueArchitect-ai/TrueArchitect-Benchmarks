**Premise correction:** There is no GraphQL in this repository. A case-insensitive search for `graphql`/`gql` across the entire tree returns zero source matches — the only hits are incidental base64 fragments inside integrity hashes in `web/pnpm-lock.yaml`. Memos has never exposed a GraphQL endpoint; there is no schema file, resolver layer, or GraphQL server dependency.

**Actual API surface — Protocol Buffers, in `proto/api/v1/`**

The public API is defined as protobuf service definitions, one file per service:

| Service | Schema file |

Shared types live in `proto/api/v1/common.proto`; internal storage-layer messages (not public API) are separate, in `proto/store/`.

**How one schema becomes three protocols**

Each RPC carries a `google.api.http` annotation that pins it to a REST route, so the proto is simultaneously the gRPC *and* the REST contract. From `proto/api/v1/memo_service.proto:22`:

```proto
rpc CreateMemo(CreateMemoRequest) returns (Memo) {
  option (google.api.http) = { post: "/api/v1/memos", body: "memo" };
}
```

`proto/buf.gen.yaml` fans this out to the served surfaces:
- **gRPC** — `proto/gen/api/v1/*_grpc.pb.go`
- **REST/JSON** — via grpc-gateway, `proto/gen/api/v1/*.pb.gw.go`
- **Connect RPC** — `proto/gen/api/v1/apiv1connect/*.connect.go`
- **TypeScript client** — emitted directly into `web/src/types/proto`
- **OpenAPI 3.0.3** — `proto/gen/openapi.yaml` (4057 lines), the generated spec that plays the role you may have expected GraphQL introspection to play

All three protocols are registered onto one Echo server in `RegisterGateway` at `server/router/api/v1/v1.go:65`, backed by the single `APIV1Service` struct (`server/router/api/v1/v1.go:23`) that embeds every generated service interface.

Regenerate with `buf generate` from `proto/` (see `proto/README.md`). The API follows Google's AIP resource conventions — note the `name=memos/*` resource-name path patterns — as documented in `proto/api/v1/README.md`.

Two adjacent non-GraphQL surfaces also exist: an RSS feed (`server/router/rss/rss.go`) and an MCP server (`server/router/mcp/`), the latter adapting the same v1 API for LLM tool use.
