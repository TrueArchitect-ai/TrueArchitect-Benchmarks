## How it works

**Trigger → delivery path**
- Memo create/update/delete/comment events call `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43,71`, using each user's stored webhook URL and signing secret.
- `PostAsync` (`internal/webhook/webhook.go:184`) is non-blocking — it enqueues onto a buffered channel of 128 and drops (with a warning log) if full.
- Four goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `Post`, which is where the outbound HTTP request actually executes: it marshals the payload, adds Standard Webhooks HMAC-SHA256 headers (`webhook-id` / `webhook-timestamp` / `webhook-signature`) when a signing secret is set, and does `safeClient.Do(req)` at `internal/webhook/webhook.go:152`.

**SSRF protection — two layers**
1. *At dial time (the real enforcement):* `safeClient` is built with a custom `Transport.DialContext = safeDialContext` (`internal/webhook/webhook.go:32-37`). `safeDialContext` (`:59`) resolves the hostname itself and refuses the connection if **any** resolved IP is reserved. Because the check happens per-dial rather than at save time, it also defeats DNS rebinding.
2. *At save time (early feedback):* `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a user creates/updates a webhook — `server/router/api/v1/user_service_webhooks.go:74,161,182`. It enforces http/https scheme and rejects hostnames resolving to reserved IPs, returning a gRPC `InvalidArgument`.

Both layers share `isReservedIP` (`internal/webhook/validate.go:44`), which tests against the CIDR list at `internal/webhook/validate.go:14-23`: IPv4 loopback, RFC-1918 ranges, link-local `169.254.0.0/16` (cloud IMDS), plus IPv6 `::1/128`, `fc00::/7`, `fe80::/10`.

**Escape hatch:** the package-level `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) short-circuits `isReservedIP`, disabling both layers for self-hosted setups targeting LAN services. Note that in the current tree it is only ever set from tests — the `--allow-private-webhooks` CLI flag mentioned in `CHANGELOG.md:121` has no wiring left in `cmd/`, so the toggle is effectively hardcoded off at runtime.

Secondary hardening in `Post`: the 30s client timeout (`:27`) and a 1 MiB `io.LimitReader` cap on the response body (`:158`).
