**1st: `store.User` (~7 packages outside the store layer); 2nd: `store.Memo` (~6 packages)**

**Data layer / entity definitions** — the persistent entity types live in the root `store` package (one file per entity):
- `store/user.go` (`type User struct`), `store/memo.go` (`type Memo struct`), plus `store/attachment.go`, `store/inbox.go`, `store/reaction.go`, `store/memo_relation.go`, `store/memo_share.go`, `store/user_setting.go`, `store/user_identity.go`, `store/instance_setting.go`, `store/idp.go`.

**Packages outside `store/…` that reference each type** (excluding the driver implementations in `store/db/*` and `store/test`, which are part of the data layer itself):

`store.User` — 7 packages, ~30 files:
- `server/router/api/v1` (19 files, e.g. `user_service.go`, `auth_service.go`)
- `server/router/api/v1/test`
- `server/auth` (`authenticator.go`, `context.go`)
- `server/router/rss`
- `server/router/fileserver`
- `server/router/frontend`
- `server/notification` (`email.go`)

`store.Memo` — 6 packages, ~21 files:
- `server/router/api/v1` (13 files, e.g. `memo_service.go`)
- `server/router/api/v1/test`
- `server/router/rss`
- `server/runner/memopayload`
- `server/router/frontend`
- `server/notification`

**Rest of the ranking** for context: `Attachment` 4, `MemoShare` / `MemoRelation` / `Inbox` 3 each, `UserIdentity` / `Reaction` 2, and `UserSetting`, `InstanceSetting`, `IdentityProvider` 1 each (only `server/router/api/v1`).

Note: counts are of distinct Go packages containing a `store.<Type>` reference; if you exclude test-only packages, it becomes User 6 / Memo 5, which leaves the ranking unchanged.
