**`internal/idp`; `internal/idp/oauth2`**

- `internal/idp/idp.go` — package `idp` defines the provider-agnostic abstraction: `IdentityProviderUserInfo` (`Identifier`, `DisplayName`, `Email`, `AvatarURL`), the normalized shape any IdP implementation must produce.
- `internal/idp/oauth2/oauth2.go` — package `oauth2` is the only concrete protocol implementation ("Package oauth2 implements the OAuth2 identity provider integration"). It provides `IdentityProvider` over `storepb.OAuth2Config`, with `NewIdentityProvider`, `ExchangeToken` (supports PKCE `code_verifier`), and user-info fetching mapped through `FieldMapping` into `idp.IdentityProviderUserInfo`.

Corroborating evidence:
- `server/router/api/v1/auth_service_sso.go:12-13` is the sole consumer, importing exactly those two packages.
- `proto/api/v1/idp_service.proto:76-80` — the `IdentityProvider.Type` enum has only `TYPE_UNSPECIFIED = 0` and `OAUTH2 = 1`, and `IdentityProviderConfig` has a single `oneof` member `oauth2_config`. No SAML/LDAP/OIDC-specific implementation ships.
