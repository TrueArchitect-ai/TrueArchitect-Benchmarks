**Premise correction: this repository has no per-user API rate-limiting middleware.** There is nothing to cite for "request limits" because no rate limiter, throttler, or quota middleware exists anywhere in the Go server.

What I verified:

- **No rate-limiting dependency.** `go.mod` pulls in no `golang.org/x/time/rate`, `tollbooth`, `ulule/limiter`, or similar. A repo-wide grep for `rate.?limit|ratelimit|throttl|limiter` across `*.go` matches nothing in server code — the only hits are the word "delimiter" in `web/src/components/MemoEditor/Editor/formatting.ts` / `listIndent.ts` and an aspirational comment in `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse"), which describes something not implemented.

- **The actual HTTP middleware stack** is just two entries, in `server/server.go:51-52`:
  ```go
  echoServer.Use(middleware.Recover())
  echoServer.Use(newCORSMiddleware(profile))
  ```

- **The actual Connect/gRPC interceptor chain** is registered in `server/router/api/v1/v1.go:133-137` — metadata, logging, recovery, and auth. No rate-limit interceptor:
  ```go
  connectInterceptors := connect.WithInterceptors(
      NewMetadataInterceptor(),
      NewLoggingInterceptor(logStacktraces),
      NewRecoveryInterceptor(logStacktraces),
      NewAuthInterceptor(authorizer),
  )
  ```
  `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:205-237`) enforces authentication and anonymous-access policy only — it has no counters, buckets, or per-user state.

The nearest thing to a "request limit" — and possibly what the premise conflated — is a **request *size* limit, not a request *rate* limit**, and it is global rather than per-user:

- `maxAPIRequestBytes = 256 << 20` (256 MiB), defined at `server/router/api/v1/v1.go:20`, applied via `http.MaxBytesHandler` to the grpc-gateway routes (`/api/v1/*`, `/file/*`) at `v1.go:126-129`, and to the Connect routes via both `connect.WithReadMaxBytes` and `MaxBytesHandler` at `v1.go:141` and `v1.go:144`.
- `MaxUploadBufferSizeBytes = 32 << 20` (32 MiB) at `server/router/api/v1/attachment_service.go:27` — an in-memory multipart parse buffer, used at `attachment_service.go:122`; the comment there notes the real maximum upload size is a system setting, not this constant.

So: an unauthenticated or authenticated caller can issue unlimited requests per second against this API as far as the server code is concerned; the only enforced ceiling is per-request body size.
