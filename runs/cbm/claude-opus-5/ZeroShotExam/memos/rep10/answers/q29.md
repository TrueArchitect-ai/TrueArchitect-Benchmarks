`web/src/connect.ts`; JWT access token (Bearer, localStorage) + refresh token (HttpOnly cookie) — plus PATs supported server-side; `server/auth`

**Interceptor** — `authInterceptor` in `web/src/connect.ts:156-178`, registered on the Connect-RPC transport at `web/src/connect.ts:184-189`. All service clients (memo, user, auth, attachment, etc.) are created from that transport, so every RPC goes through it.

**What it does:**
- Calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, line 97). It preflight-refreshes when the token is within 30s of expiry so public endpoints don't silently return guest-scoped data.
- On a `Code.Unauthenticated` error it refreshes once and replays the request with an `X-Retry: true` header to prevent loops; if the refresh fails it calls `redirectOnAuthFailure()`.
- The transport uses `credentials: "include"` (`fetchWithCredentials`, line 57) so the refresh cookie rides along. A second transport with **no** interceptors (`refreshTransport`, line 65) handles `AuthService.refreshToken` to avoid recursion, and `tokenRefreshManager` (line 30) dedupes concurrent refreshes.

**Tokens managed:**
- **Access token** — short-lived JWT held in memory + `localStorage` under `memos_access_token` / `memos_token_expires_at`, in `web/src/auth-state.ts`. A `BroadcastChannel` (`memos_token_sync`, line 13) shares fresh tokens across tabs. Proactive refresh on tab focus lives in `web/src/hooks/useTokenRefreshOnFocus.ts`.
- **Refresh token** — never touched by JS; it's the HttpOnly cookie `memos_refresh` sent via `credentials: "include"`.

**Backend validation** — package `server/auth`:
- `server/auth/token.go` defines the constants: access token 15 min / audience `user.access-token`, refresh token 30 days / cookie `memos_refresh`, and the PAT prefix `memos_pat_`.
- `server/auth/authenticator.go` — `Authenticator.AuthenticateByAccessTokenV2` (stateless signature check) and `AuthenticateByRefreshToken` (DB revocation + expiry check against `store.GetUserRefreshTokenByID`).
- `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie`.

It's invoked from the server-side Connect interceptor at `server/router/api/v1/connect_interceptors.go:222` via the `Authorizer` wrapper in `server/router/api/v1/authz.go:44`, with the same authenticator also used by the gRPC path (`server/router/api/v1/v1.go:78`) and the file server (`server/router/fileserver/fileserver.go`).
