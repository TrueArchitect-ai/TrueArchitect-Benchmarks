**Workers the server actually starts** (`server/server.go:153` `startBackgroundRunners`, called from `Start` at `server/server.go:129`):

- **s3presign runner (`server/runner/s3presign/runner.go`)** — started once synchronously via `RunOnce(ctx)` at server start (`server/server.go:163`), then a goroutine runs `Run(s3Context)` driven by a `time.Ticker` at a hardcoded `runnerInterval = 12h` (`runner.go:27-41`); exits on cancellation of its own per-runner context, tracked by `backgroundRunnerCancels`/`backgroundRunnerWG` for graceful shutdown. Each pass re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days.

That's the only entry in `startBackgroundRunners`. Other long-lived goroutines exist but are not scheduled workers:

- **Store cache cleanup loops (`store/cache/cache.go:83`, `cleanupLoop` at :200)** — three of them (instanceSetting, user, userSetting caches), started implicitly by `cache.New` inside `store.New` (`store/store.go:51-53`); driven by a `time.Ticker` at `CleanupInterval = 5m`, stopped via `stopChan` on `Store.Close()`.
- **Webhook dispatch pool (`internal/webhook/webhook.go:42-55`)** — 4 goroutines started in `init()`, driven by messages on the buffered `asyncPostQueue` channel (event-driven, not timed).
- **Email dispatch pool (`internal/email/email.go:16-35`)** — 2 goroutines started in `init()`, driven by `asyncEmailQueue` (event-driven).
- **HTTP serve goroutine (`server/server.go:124`)** and the **signal-handler goroutine (`cmd/memos/main.go:99`)** — request/shutdown plumbing, not periodic work.
- **SSE heartbeat (`server/router/api/v1/sse_handler.go:64`, `sseHeartbeatInterval = 30s`)** — a per-connection ticker inside the request handler, not a server-level worker. `SSEHub` itself has no background loop (`server/router/api/v1/sse_hub.go:63`).
- **PAT last-used update (`server/auth/authenticator.go:180`)** — a fire-and-forget goroutine per authenticated request.

**Unused scheduling infrastructure:**

- **`internal/scheduler` (full cron scheduler: `scheduler.go`, `job.go`, `parser.go`, `middleware.go`, plus `README.md`/`doc.go`) is NOT used by the server.** Grepping the whole repo, the only importers are `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go` — no production code registers a job or calls `scheduler.New()`. Despite its README ("included with Memos"), the running server's only periodic work is the 12h `time.Ticker` in s3presign plus the cache cleanup tickers.
- **`server/runner/memopayload`'s `Runner` (`runner.go:14-27`) is also never started** — `NewRunner`/`RunOnce` (the batch rebuild of all memo payloads) have no callers; only the plain helper `memopayload.RebuildMemoPayload` is used, inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447`.
