There's no ORM/struct-tag mapping in this repo — table binding is done by hand-written SQL in the per-dialect drivers under `store/db/{sqlite,mysql,postgres}/`. The domain structs those drivers read into/write from are:

| table | Struct — path |
|---|---|
| `user` | `User` — `store/user.go:29` |
| `attachment` | `Attachment` — `store/attachment.go:16` |
| `reaction` | `Reaction` — `store/reaction.go:7` |

Evidence of the struct↔table binding (each driver scans these tables into the struct above):

- `user`: `store/db/sqlite/user.go:17,164`, `store/db/mysql/user.go:18,147`, `store/db/postgres/user.go`
- `attachment`: `store/db/mysql/attachment.go:34,116`, `store/db/postgres/attachment.go:33,108`, `store/db/sqlite/attachment.go`
- `reaction`: `store/db/sqlite/reaction.go:16,60`, `store/db/mysql/reaction.go:16,65`, `store/db/postgres/reaction.go`

Each table also has companion input structs in the same files (e.g. `UpdateUser`, `FindAttachment`, `FindReaction`/`DeleteReaction`), but the row-mapped entity structs are the three listed above.
