**`APIV1Service.SignIn` — `server/router/api/v1/auth_service.go:51`**

This is the real implementation. It handles both credential paths defined in the RPC:
- **Password**: looks up the user, `bcrypt.CompareHashAndPassword` against `PasswordHash`, and rejects if `DisallowPasswordAuth` is set for regular users (`auth_service.go:55-77`).
- **SSO/OAuth2**: `resolveSSOIdentity` then `resolveSSOUser` (`auth_service.go:78-89`).

It then rejects archived users and delegates token minting to `APIV1Service.doSignIn` (`server/router/api/v1/auth_service_session.go:24`), which returns the access token and expiry.

Related plumbing (not the handler itself):
- `ConnectServiceHandler.SignIn` — `server/router/api/v1/connect_services.go:78` — Connect-RPC wrapper that just forwards to `APIV1Service.SignIn` via `connectWithHeaderCarrier` (so the session cookie header can be set).
