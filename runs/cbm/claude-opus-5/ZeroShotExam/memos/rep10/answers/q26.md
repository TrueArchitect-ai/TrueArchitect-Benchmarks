**Two caveats worth flagging:**

- **`memo_share` is not cascaded on SQLite.** The SQLite driver opens the DB with `_pragma=foreign_keys(0)` (`store/db/sqlite/sqlite.go:53`), so the `ON DELETE CASCADE` declared in `store/migration/sqlite/LATEST.sql:109` never fires — share rows are orphaned there. Postgres and MySQL (InnoDB) do enforce it.
- **`reaction` is *not* touched.** `DeleteMemo` calls `ListReactions` at `memo_service.go:545` only to build the webhook payload; there is no `DeleteReaction` in this path (`Store.DeleteReaction` is called only from `reaction_service.go:141`). The `reaction` table has no FK to `memo` (`content_id` is a plain text field), so reactions on a deleted memo are left behind on every backend.
