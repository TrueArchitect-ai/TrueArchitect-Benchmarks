**Background workers the server actually starts** (`server/server.go:153-174`, `startBackgroundRunners`, called from `Start` at `server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — two triggers: one synchronous `RunOnce(ctx)` inline at startup (`server/server.go:163`), then a goroutine running `Run(s3Context)` driven by a `time.Ticker` at a hardcoded 12-hour interval (`runnerInterval = time.Hour * 12`, `runner.go:27-40`). It re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days, in batches of 100. Stopped by its own `context.CancelFunc` recorded in `backgroundRunnerCancels` and awaited via `backgroundRunnerWG` on shutdown (`server/server.go:176-201`).

That is the **only** runner registered in `startBackgroundRunners`. Other long-lived goroutines exist in the process but are not registered runners:

- **store cache janitors ×3** — `cache.New` spawns `cleanupLoop` per cache (`store/cache/cache.go:75-84`, `199-213`); driven by a 5-minute `CleanupInterval` ticker; three instances created in `store.New` for `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:40-53`). Started implicitly by `store.New` in `cmd/memos/main.go:64`, not by the server.
- **webhook dispatch pool (4 goroutines)** — started in `package init()` (`internal/webhook/webhook.go:42-54`); trigger is channel-driven (`asyncPostQueue`), not timed.
- **email send pool (2 goroutines)** — started in `package init()` (`internal/email/email.go:16-35`); channel-driven (`asyncEmailQueue`).
- **HTTP serve goroutine** (`server/server.go:124`) and **signal-handler goroutine** (`cmd/memos/main.go:99`) — not workers.
- **SSE heartbeat ticker** (`server/router/api/v1/sse_handler.go:64`) — per-connection, lives inside the request handler; the hub itself has no loop, only `Close()` (`server/router/api/v1/sse_hub.go:99`).
- **PAT last-used writer** (`server/auth/authenticator.go:179-185`) — one-shot goroutine per authenticated request.

**Unused scheduling infrastructure:**

- **`internal/scheduler`** — a complete cron scheduler (5/6-field parser, timezone support, job registry, middleware for recovery/logging/timeouts, graceful `Start`/`Stop`) with README and doc.go, but it is **imported only by its own tests** (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No production code registers a job or calls `scheduler.New()`/`Start()`. The s3presign runner uses a raw `time.Ticker` instead.
- **`server/runner/memopayload.Runner`** (`server/runner/memopayload/runner.go`) — has `NewRunner`/`RunOnce` (batch memo-payload rebuild), but `NewRunner` is never called anywhere; the server never starts it. Only the package-level helper `memopayload.RebuildMemoPayload` is used, inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447`.
