**Engine:** Google CEL (`github.com/google/cel-go` v0.28.1, per `go.mod:13`), wrapped by the in-repo memo filter engine at **`internal/filter/`** — `engine.go` (Compile/Render + `DefaultEngine()`), `schema.go` (allowed fields + CEL env), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL), `helpers.go` (store glue).

**Mechanism (one sentence):** `ListMemos` validates `request.Filter` by compiling it (`server/router/api/v1/memo_service.go:211-216` → `validateFilter` in `server/router/api/v1/shortcut_service.go:336`) and appends the raw string to `memoFind.Filters`; each driver's `ListMemos` then calls `filter.DefaultEngine()` + `filter.AppendConditions(...)` with its own dialect constant (`store/db/sqlite/memo.go:57-61` → `DialectSQLite`, `store/db/mysql/memo.go:65-69` → `DialectMySQL`, `store/db/postgres/memo.go:54-58` → `DialectPostgres`), and `Engine.CompileToStatement` runs the three-phase pipeline — cel-go parses/type-checks the expression against the schema's declared variables (`content`, `tags`, `created_ts`, `visibility`, `has_task_list`, `now`, …), `buildCondition` normalizes the AST into the IR, and the dialect-aware renderer emits a parenthesized SQL fragment plus placeholder args that are ANDed into the query's `WHERE` clause.

Dialect differences live entirely in `internal/filter/render.go`: `?` vs `$n` placeholders (with `PlaceholderOffset` so args compose with pre-existing ones), JSON access (`json_extract` / `JSON_CONTAINS` / `->>` and `@>`), `LIKE` vs `ILIKE`, `REGEXP` vs `~` (SQLite's `regexp` is a Go-backed function registered in `store/db/sqlite/functions.go`), and date-part extraction (`strftime` / `EXTRACT` / `YEAR()`). `internal/filter/README.md` documents the pipeline and the per-dialect behavior. The same engine serves shortcuts and user stats; attachments use a parallel schema via `DefaultAttachmentEngine()`.
