Flow:

1. `CreateMemo` calls `s.DispatchMemoCreatedWebhook(ctx, memoMessage)` at `server/router/api/v1/memo_service.go:157` (failures are only logged via `slog.Warn`, not returned).
2. `DispatchMemoCreatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:15`) delegates to `dispatchMemoRelatedWebhook` with activity type `"memos.memo.created"` — that resolves the memo creator, loads `s.Store.GetUserWebhooks(ctx, creatorID)`, and for each hook builds a `webhook.WebhookRequestPayload` (URL + signing secret from the hook row) and calls `webhook.PostAsync(payload)` (`memo_service_webhooks.go:48-74`).
3. `internal/webhook/webhook.go` performs delivery: `PostAsync` enqueues onto a bounded 128-slot channel drained by 4 worker goroutines (dropping with a warning when full, `webhook.go:39-55`, `184-196`); each worker calls `Post`, which POSTs JSON with a 30s-timeout `safeClient` whose transport uses `safeDialContext` to reject reserved/private IPs (SSRF/DNS-rebinding guard).
4. Signing (`webhook.go:133-150`): if the hook has a signing secret, the key is resolved by `resolveSigningKey` — a `whsec_<base64>` secret is base64-decoded to raw bytes, anything else used verbatim — then `HMAC-SHA256(key, msgID + "." + timestamp + "." + body)` is base64-encoded and set as the three Standard Webhooks headers. Secrets are generated by `GenerateSigningSecret` as `whsec_` + base64 of 32 random bytes.
