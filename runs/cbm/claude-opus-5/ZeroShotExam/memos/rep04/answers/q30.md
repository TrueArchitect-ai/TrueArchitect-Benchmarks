**Convergence for delivery:** `webhook.PostAsync` in `internal/webhook/webhook.go:184`.

The first three funnel through the shared helper `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which only differs by the `activityType` string; the comment case builds its payload inline (it targets the *parent* memo's owner via `GetUserWebhooks(relatedMemoCreatorID)` rather than the comment author). All four then resolve the creator's webhooks, build a `WebhookRequestPayload`, and call `webhook.PostAsync`, which enqueues onto the buffered `asyncPostQueue` (cap 128, `webhook.go:39`). Four worker goroutines started in `init()` (`webhook.go:42-55`) drain the queue and perform the actual HTTP delivery in `webhook.Post` (`internal/webhook/webhook.go:120`) — that's where the HMAC-SHA256 Standard Webhooks signing and the SSRF-guarded `safeClient.Do` happen. Enqueues are dropped with a warning if the queue is full.
