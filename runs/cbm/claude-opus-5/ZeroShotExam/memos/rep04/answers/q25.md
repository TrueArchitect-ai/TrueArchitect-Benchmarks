**q25.**

**Engine:** Google CEL (`github.com/google/cel-go`, plus `ext.Sets()` etc.), wrapped by the in-repo filter engine at `internal/filter/` — `engine.go` (entry `filter.DefaultEngine()`), `schema.go` (CEL env + field metadata), `parser.go` (CEL AST → IR), `ir.go`, `render.go` (IR → SQL), `helpers.go`.

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:210-215`) validates `request.Filter` via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`) and appends the raw CEL string to `store.FindMemo.Filters`; each store driver then calls `filter.DefaultEngine()` + `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` (`store/db/sqlite/memo.go:57-63`, `store/db/postgres/memo.go:54-60`, `store/db/mysql/memo.go:65-71`), which runs the three-phase pipeline — `cel-go` compiles/type-checks the expression against the memo schema, `parser.go` normalizes the AST into a dialect-agnostic condition tree, and `render.go` walks that IR emitting a dialect-specific SQL fragment plus bound args (`?` for SQLite/MySQL vs `$n` for Postgres via `addArg`, `render.go:842`; JSON access, `LIKE`/`ILIKE`, regex, and timestamp extraction switch on `DialectName` from `schema.go:10-17`), and the fragment is appended to the query's `WHERE` clause.

Details of per-dialect handling are documented in `internal/filter/README.md` (JSON fields, tag predicates via `LIKE`/`JSON_CONTAINS`/`@>`, regex via `~`/`REGEXP` with SQLite's Go-backed `regexp` registered in `store/db/sqlite/functions.go`).
