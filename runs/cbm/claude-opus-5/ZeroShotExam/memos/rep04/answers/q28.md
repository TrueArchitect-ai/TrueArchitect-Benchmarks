**Background workers the server actually starts**

- **S3 presign runner** (`server/runner/s3presign/runner.go`) — the only runner started by `Server.startBackgroundRunners` (`server/server.go:153-174`). Trigger: one immediate synchronous `RunOnce(ctx)` at startup, then a `time.NewTicker` loop on a hardcoded 12-hour interval (`runnerInterval = time.Hour * 12`, `runner.go:27-41`); exits on cancellation of its own per-runner context, which `stopBackgroundRunners` cancels at shutdown (`server/server.go:176-201`).
- **HTTP serve goroutine** (`server/server.go:124-128`) — started in `Server.Start`; not periodic, driven by `http.Server.Serve(listener)` until `ErrServerClosed`.
- **Store cache cleanup loops ×3** (`store/cache/cache.go:83`, `cleanupLoop` at `:200-213`) — started implicitly by `store.New`, which creates `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:42-53`). Trigger: `time.NewTicker(CleanupInterval)` with `CleanupInterval: 5 * time.Minute`; stops on `Close()`.
- **Webhook dispatch workers ×4** (`internal/webhook/webhook.go:42-55`) — started in `func init()` when the package is imported (imported by `server/router/api/v1/memo_service_webhooks.go`, `user_service_webhooks.go`). Trigger: not time-based — each worker blocks on `asyncPostQueue` (buffered 128) and runs when `webhook.PostAsync` enqueues a payload (`webhook.go:182-190`, called on memo events at `memo_service_webhooks.go:43,71`).
- **Email send workers ×2** (`internal/email/email.go:16-34`) — also `init()`-started on import (`server/notification/email.go:11,30`). Trigger: event-driven off `asyncEmailQueue` fed by `email.SendAsync` (`email.go:52-57`).
- **Signal-handler goroutine** (`cmd/memos/main.go:99-103`) — waits on SIGINT/SIGTERM, then calls `s.Shutdown`.

Per-request/per-connection goroutines, not long-lived runners: the SSE handler's 30s heartbeat ticker exists once per open connection inside the handler (`server/router/api/v1/sse_handler.go:16-17,64`), and PAT last-used updates are one-off `go func`s (`server/auth/authenticator.go:178-184`). `SSEHub` itself has no background goroutine (`server/router/api/v1/sse_hub.go:56-67`).

**Unused scheduling infrastructure**

- `internal/scheduler` — a complete cron scheduler (5/6-field cron parsing, timezone support, middleware: Recovery/Logging/Timeout, graceful shutdown; `internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`, `doc.go`) is **not used by the server at all**. The only non-test importer of the package is nothing — grep for `github.com/usememos/memos/internal/scheduler` outside the package matches only its own tests (`integration_test.go`, `example_test.go`). Notably, the one real periodic job (s3presign) hardcodes its own `time.Ticker` rather than registering with this scheduler.
- `server/runner/memopayload` lives under `server/runner/` but is not a runner: `RebuildMemoPayload` is called inline from request handling (`server/router/api/v1/memo_service.go:108,447`), never started as a background loop.
