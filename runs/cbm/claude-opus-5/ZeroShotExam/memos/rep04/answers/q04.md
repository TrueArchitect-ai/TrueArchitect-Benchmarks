**`APIV1Service.SignIn` — `server/router/api/v1/auth_service.go:51`**

That's the function containing the actual sign-in logic:
- Password credentials path: looks up the user by username, `bcrypt.CompareHashAndPassword` against `user.PasswordHash`, and rejects if `DisallowPasswordAuth` is set for a `RoleUser` (`auth_service.go:55-77`).
- SSO credentials path: `resolveSSOIdentity` then `resolveSSOUser` (`auth_service.go:78-89`, helpers in `server/router/api/v1/auth_service_sso.go`).
- Rejects archived users, then calls `s.doSignIn` (`server/router/api/v1/auth_service_session.go:24`) to mint the access token and set the refresh-token cookie, returning a `SignInResponse`.

Related wiring, in case you need the entry point rather than the logic: the Connect/gRPC transport handler is `ConnectServiceHandler.SignIn` at `server/router/api/v1/connect_services.go:78`, which just wraps the above in a header carrier so cookies can be set protocol-agnostically. Generated service stubs live in `proto/gen/api/v1/apiv1connect/auth_service.connect.go`.
