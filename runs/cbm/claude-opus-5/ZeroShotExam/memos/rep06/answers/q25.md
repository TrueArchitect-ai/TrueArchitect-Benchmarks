**Engine + path:** Google CEL (`github.com/google/cel-go` v0.28.1), via the in-repo filter engine at `internal/filter/` — `engine.go` (entry point `filter.DefaultEngine()`), `schema.go` (allowed memo fields + CEL env), `parser.go` (CEL AST → IR), `ir.go` (dialect-agnostic condition tree), `render.go` (IR → SQL per dialect), `helpers.go` (store glue). Documented in `internal/filter/README.md`.

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:210-215`) validates the CEL string via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`) and pushes it onto `store.FindMemo.Filters` (`store/memo.go:72`); each driver then calls `filter.AppendConditions(ctx, engine, find.Filters, <dialect>, &where, &args)` — `store/db/sqlite/memo.go:57-61`, `store/db/postgres/memo.go:54-58`, `store/db/mysql/memo.go:65-69` — which runs `Engine.CompileToStatement`: cel-go compiles and type-checks the expression against the memo schema, `buildCondition` normalizes the AST into the IR (folding `now`/`duration()`/`timestamp()` to constants at compile time), and the renderer walks the IR emitting a parenthesized SQL fragment plus bound args tailored to `DialectSQLite`/`DialectMySQL`/`DialectPostgres` (`?` vs `$n` placeholders with a `PlaceholderOffset`, `json_extract` vs `->>` vs `JSON_EXTRACT`, `LIKE` vs `ILIKE`, tag membership via `LIKE` / `JSON_CONTAINS` / `@>`), which is AND-ed into the query's `WHERE` clause.

Note the same path also carries the server-injected visibility filter (`creator_id == N || visibility in ["PUBLIC","PROTECTED"]`, `memo_service.go:222`), so ACL enforcement rides the same CEL→SQL pipeline as user input.
