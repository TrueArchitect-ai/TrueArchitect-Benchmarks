**Server-Sent Events (SSE); `server/router/api/v1/sse_hub.go` (`SSEHub`); `CreateMemo`, `DeleteMemo`, `CreateMemoComment`, and — via `dispatchMemoUpdatedSideEffects` — `UpdateMemo`, `SetMemoAttachments`, `SetMemoRelations` (plus reaction handlers `UpsertMemoReaction` / `DeleteMemoReaction`)**

### Mechanism
Plain HTTP SSE (`text/event-stream`), not WebSockets. The endpoint is `GET /api/v1/sse`, registered in `server/router/api/v1/sse_handler.go:25` (`RegisterSSERoutes`, wired at `server/router/api/v1/v1.go:125`). `handleSSE` (`sse_handler.go:34`) authenticates via a `Bearer` token in the `Authorization` header, sets SSE headers including `X-Accel-Buffering: no`, writes an initial `: connected` comment, then loops writing `data: <json>` frames with a 30s `: heartbeat` keep-alive (`sseHeartbeatInterval`, line 17).

The browser side is `web/src/hooks/useLiveMemoRefresh.ts` — it uses `fetch` + a stream reader (not `EventSource`, since it needs the auth header), parses `data:` lines, and invalidates the matching React Query caches, with exponential-backoff reconnect and a full resync on reconnect.

### Hub
`server/router/api/v1/sse_hub.go`:
- `SSEHub` (line 56) — mutex-guarded `map[*SSEClient]struct{}`; `NewSSEHub`, `Subscribe` (32-event buffered channel per client), `Unsubscribe`, `Close`.
- `Broadcast` (line 115) — marshals the event once, then non-blocking sends to each client; a slow client with a full buffer has the event **dropped**.
- `canReceive` (line 134) — server-side visibility filter: `Private` events only reach the creator or an admin.
- Event types (lines 15–21): `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`.
- Lifecycle: constructed at `v1.go:57`, closed on server shutdown at `server/server.go:205-206`.
