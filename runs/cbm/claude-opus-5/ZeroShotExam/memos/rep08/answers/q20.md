**Mechanism:** Server-Sent Events (SSE) — plain `text/event-stream` over HTTP, not WebSockets. The endpoint is `GET /api/v1/sse`, registered by `RegisterSSERoutes` in `server/router/api/v1/sse_handler.go:25` (wired up at `server/router/api/v1/v1.go:125`). The handler authenticates via a Bearer token, sets `Content-Type: text/event-stream` / `Cache-Control: no-cache` / `X-Accel-Buffering: no`, writes an initial `: connected` comment, then loops writing `data: <json>\n\n` frames with a 30s `: heartbeat` comment ping (`server/router/api/v1/sse_handler.go:34-108`). The browser side is an `EventSource` client in `web/src/hooks/useLiveMemoRefresh.ts` (with reconnect backoff), consumed from `web/src/main.tsx:48` and surfaced as a status dot in `web/src/components/UserMenu.tsx`.

**Hub path:** `server/router/api/v1/sse_hub.go` — `SSEHub` (mutex-guarded `map[*SSEClient]struct{}`) with `NewSSEHub`, `Subscribe`, `Unsubscribe`, `Close`, and `Broadcast`. Each client gets a 32-slot buffered channel; events are dropped rather than blocking on a slow client, and `SSEClient.canReceive` (`sse_hub.go:134`) filters private-memo events to the creator or an admin. The hub instance lives on `APIV1Service.SSEHub` (`v1.go:36,57`) and is held by the server at `server/server.go:38,77`. Event types: `memo.created`, `memo.updated`, `memo.deleted`, `memo.comment.created`, `reaction.upserted`, `reaction.deleted`.

**Handlers that broadcast:**

- `CreateMemo` — `server/router/api/v1/memo_service.go:163` (`memo.created`; skipped when invoked via `CreateMemoComment`)
- `DeleteMemo` — `server/router/api/v1/memo_service.go:585` (`memo.deleted`)
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:126` (`memo.comment.created`)
- `UpsertMemoReaction` — `server/router/api/v1/reaction_service.go:106` (`reaction.upserted`)
- `DeleteMemoReaction` — `server/router/api/v1/reaction_service.go:161` (`reaction.deleted`)
- `UpdateMemo`, `SetMemoRelations`, and `SetMemoAttachments` — all broadcast `memo.updated` indirectly through the shared helper `dispatchMemoUpdatedSideEffects` (`server/router/api/v1/memo_update_helpers.go:66-79`), called from `memo_service.go:513`, `memo_relation_service.go:48`, and `memo_attachment_service.go:48`

Comment and reaction events use `resolveSSECreatorID` / `buildMemoReactionSSEEvent` in `server/router/api/v1/sse_event_helpers.go` so a comment's visibility filtering is scoped to the parent memo's owner.
