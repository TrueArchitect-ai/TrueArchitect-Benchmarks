**`web/src/connect.ts`; JWT access token (Bearer, localStorage) + HTTP-only refresh-token cookie (`memos_refresh`), with Personal Access Tokens as an alternative Bearer credential; `server/auth`**

## Frontend

- **Interceptor**: `authInterceptor` in `web/src/connect.ts:145` — a `@connectrpc/connect` `Interceptor` attached to the Connect transport (`web/src/connect.ts:170`) that all service clients (memo, user, auth, attachment, …) are built from.
- **What it does**: calls `getRequestToken()` to fetch the access token, sets `Authorization: Bearer <token>` (`web/src/connect.ts:96`), and on a `Code.Unauthenticated` response refreshes once, replays the request with an `X-Retry: true` marker, and on failure calls `redirectOnAuthFailure()`.
- **Token storage**: `web/src/auth-state.ts` keeps the access token in memory + `localStorage` (`memos_access_token` / `memos_token_expires_at`), does a preflight refresh 30s before expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), and syncs tokens across tabs via a `memos_token_sync` `BroadcastChannel`.
- **Refresh path**: the refresh token is never touched by JS — it's an HTTP-only cookie sent by `credentials: "include"` to `AuthService.RefreshToken`, issued through a separate interceptor-free transport (`web/src/connect.ts:66`) to avoid recursion. Concurrent refreshes are deduplicated by `tokenRefreshManager`; `web/src/hooks/useTokenRefreshOnFocus.ts` refreshes proactively on tab focus.

## Backend

- **Package**: `server/auth` — `Authenticator` (`server/auth/authenticator.go`) plus `token.go` (JWT minting/parsing) and `extract.go` (`ExtractBearerToken`, `ExtractRefreshTokenFromCookie`).
- **Token kinds** (`server/auth/token.go:26-54`): access tokens (JWT, audience `user.access-token`, 15 min, stateless signature-only validation), refresh tokens (JWT, audience `user.refresh-token`, 30 days, cookie `memos_refresh`, checked against the DB for revocation), and Personal Access Tokens (prefix `memos_pat_`, long-lived, for programmatic API use).
- **Wiring**: the Connect `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:217`) and the gRPC path (`server/router/api/v1/v1.go:78`) both read the `Authorization` header and delegate to `Authorizer.Authenticate` (`server/router/api/v1/authz.go:44`), which wraps `auth.Authenticator.Authenticate` (`server/auth/authenticator.go:213`). The same package also backs `server/router/fileserver/fileserver.go:115` and SSE (`server/router/api/v1/sse_handler.go:26`).
