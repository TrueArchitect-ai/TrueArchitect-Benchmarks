**Runners the server actually starts** (all wiring is in `server/server.go:153` `startBackgroundRunners`, called from `Server.Start` at `server/server.go:129`):

- **s3presign runner (`server/runner/s3presign/runner.go`)** — started twice-over: one synchronous `RunOnce(ctx)` at startup (`server/server.go:163`), then a long-lived goroutine `Run(s3Context)` driven by a plain `time.NewTicker(12h)` (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). Cancelled via its own `context.CancelFunc` stored in `backgroundRunnerCancels` and awaited through `backgroundRunnerWG` on shutdown (`server/server.go:156-171`, `176-201`).

That is the **only** runner in `startBackgroundRunners`. The other always-on goroutines the process has are not "runners" registered there:

- **Cache cleanup loops (`store/cache/cache.go:83` → `cleanupLoop` at :200)** — three of them, one per cache created in `store.New` (`store/store.go:51-53`), driven by `time.NewTicker(CleanupInterval)` = 5 min (`store/store.go:40-45`). Started implicitly when the store is constructed, stopped via `Cache.Close()`.
- **Webhook dispatch workers (`internal/webhook/webhook.go:41-55`)** — 4 goroutines started in `func init()`, driven by a buffered channel (`asyncPostQueue`, cap 128), fed by `webhook.PostAsync` from `server/router/api/v1/memo_service_webhooks.go:43,71`. Event-driven, not timed; never shut down.
- **Email send workers (`internal/email/email.go:16-35`)** — 2 goroutines started in `func init()`, driven by `asyncEmailQueue` (cap 128) via `email.SendAsync`, wired at `server/notification/email.go:30`. Event-driven; never shut down.
- **Per-request goroutines/tickers, not background workers:** PAT last-used writeback (`server/auth/authenticator.go:180`, fire-and-forget per authenticated request), SSE per-connection heartbeat ticker (`server/router/api/v1/sse_handler.go:64`), HTTP serve loop (`server/server.go:124`), signal-handler goroutine (`cmd/memos/main.go:99`).

**Unused scheduling infrastructure:**

- **`internal/scheduler/` is dead as far as the server is concerned.** It's a full cron scheduler — cron parser (`parser.go`), job registry + ticking loop (`scheduler.go`), middleware for recovery/logging/timeout (`middleware.go`), README and docs — but the only non-test importers are its own `example_test.go` and `integration_test.go`. No production file imports `github.com/usememos/memos/internal/scheduler`; `server.go` uses a raw `time.Ticker` in the s3presign runner instead. So no cron expression anywhere drives real work.
- **`memopayload.Runner` (`server/runner/memopayload/runner.go:14-27`) is never instantiated.** `NewRunner`/`RunOnce` (batch rebuild of all memo payloads) have no callers; only the package-level helper `RebuildMemoPayload` is used, and it's called inline on the request path from `server/router/api/v1/memo_service.go:108,447`. Despite living under `server/runner/`, nothing about it is scheduled or backgrounded.
