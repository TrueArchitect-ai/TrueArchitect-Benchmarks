**Answer (table list): `memo`, `memo_relation`, `attachment` — plus `memo_share` only via a DB-level `ON DELETE CASCADE` (and only on Postgres/MySQL).**

### Call path

`APIV1Service.DeleteMemo` — `server/router/api/v1/memo_service.go:518`
1. Lists comment relations and calls `Store.DeleteMemo` for each comment memo (`memo_service.go:568-577`) — so the whole cleanup below runs recursively for every comment.
2. Calls `Store.DeleteMemo` for the memo itself (`memo_service.go:580`).

`Store.DeleteMemo` — `store/memo.go:140-159` is where the explicit cascade code lives:

| Table | How | Location |
|---|---|---|
| `memo_relation` | Two explicit deletes: rows where the memo is the source (`MemoID`) and where it's the target (`RelatedMemoID`) | `store/memo.go:142-147` → `store/db/sqlite/memo_relation.go:137` (and postgres/mysql equivalents) |
| `attachment` | Lists attachments by `MemoID`, deletes each via `Store.DeleteAttachment` (which also removes the underlying blob/local file, not a table) | `store/memo.go:149-157`, `store/attachment.go` |
| `memo` | Final `DELETE FROM memo WHERE id = ?` | `store/memo.go:158` → `store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259` |
| `memo_share` | No Go code deletes it; the schema declares `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` | `store/migration/sqlite/LATEST.sql`, `store/migration/postgres/LATEST.sql:101-109`, `store/migration/mysql/LATEST.sql:101-109` |

### Two caveats worth flagging

- **`memo_share` is not actually cleaned up on SQLite.** The SQLite driver opens the DB with foreign keys disabled — `store/db/sqlite/sqlite.go:53` (`_pragma=foreign_keys(0)`) — so the declared cascade never fires there. On Postgres/MySQL it does.
- **`reaction` rows are left orphaned.** `DeleteMemo` reads reactions only to build the webhook payload (`memo_service.go:545-550`); nothing ever deletes them. The `reaction` table keys off `content_id` (a text memo name) with no FK (`store/migration/sqlite/LATEST.sql`), and `Store.DeleteReaction` (`store/reaction.go:39`) is called only from `server/router/api/v1/reaction_service.go:141`.

Not touched at all: `inbox`, `user`, `user_setting`, `system_setting`.
