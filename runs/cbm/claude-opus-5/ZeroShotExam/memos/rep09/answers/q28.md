**Workers the server actually starts**

- **s3presign runner** — `server/server.go:153-174` (`startBackgroundRunners`, called from `Start` at `server.go:129`). Time-driven: one synchronous `RunOnce(ctx)` at startup, then a goroutine on a `time.NewTicker(12h)` loop (`server/runner/s3presign/runner.go:27-41`), cancelled via its own context on shutdown. This is the **only** entry in `backgroundRunnerCancels`/`backgroundRunnerWG`.
- **HTTP serve goroutine** — `server/server.go:124`, `httpServer.Serve(listener)`; driven by inbound connections.
- **Store cache janitors (×3)** — `cache.New` spawns a `cleanupLoop` goroutine per cache (`store/cache/cache.go:80`, `199-212`), on a `time.NewTicker(CleanupInterval)` = 5 min; three caches (instance settings, users, user settings) created in `store.New` (`store/store.go:40-53`), stopped by `Store.Close` (`store/store.go:73-79`).
- **Webhook async dispatchers (×4)** — package `init()` in `internal/webhook/webhook.go:43-54`; event-driven, consuming the buffered `asyncPostQueue` channel (cap 128, producer at `webhook.go:190`). Started at package init, not by `Server`.
- **Email async senders (×2)** — package `init()` in `internal/email/email.go:16-35`; event-driven off `asyncEmailQueue` (cap 128, producer at `email.go:57`). Also package-init, not `Server`.
- **Signal/shutdown goroutine** — `cmd/memos/main.go:99`; triggered by SIGINT/SIGTERM, calls `s.Shutdown(ctx)`.

Per-request goroutines (not long-lived workers, but timer-driven): the SSE handler's 30s heartbeat ticker per connection (`server/router/api/v1/sse_handler.go:17,64`) — note `SSEHub` itself has no background goroutine, `Broadcast` runs on the caller (`server/router/api/v1/sse_hub.go:115`) — and the fire-and-forget PAT last-used update (`server/auth/authenticator.go:178-186`).

**Unused scheduling infrastructure**

- **`internal/scheduler`** — a complete cron scheduler (cron parser, jobs, middleware, timezone support, graceful stop: `scheduler.go`, `job.go`, `parser.go`, `middleware.go`, `doc.go`) is **never used by the server**. The only imports of `github.com/usememos/memos/internal/scheduler` in the whole repo are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). No cron expression drives anything in production; the one recurring job uses a raw ticker.
- **`server/runner/memopayload.Runner`** — `NewRunner`/`RunOnce` (`server/runner/memopayload/runner.go:19-72`) are never instantiated anywhere (no `memopayload.NewRunner` call exists, tests included). Only the free function `RebuildMemoPayload` is used, synchronously inline during memo create/update (`server/router/api/v1/memo_service.go:108`, `:447`). So it is a "runner" in name only — nothing schedules it.
