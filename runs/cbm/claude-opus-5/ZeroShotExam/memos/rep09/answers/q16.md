`store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) removes, in order, before issuing the `DELETE FROM memo` row delete:

1. **Memo relations where the memo is the source** — `driver.DeleteMemoRelation(&DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
2. **Memo relations where the memo is the target/related memo** — `driver.DeleteMemoRelation(&DeleteMemoRelation{RelatedMemoID: &delete.ID})` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and deleted one by one with `DeleteAttachment` (`store/memo.go:149-157`). `Store.DeleteAttachment` (`store/attachment.go:132-149`) also removes the attachment's backing storage/blob (local file or external object) before deleting the attachment row.

Only then does it call `driver.DeleteMemo`, which is the plain `DELETE FROM memo WHERE id = ?` (e.g. `store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`).

Note: reactions are not deleted by the store layer here — the API handler (`server/router/api/v1/memo_service.go:518-582`) only lists reactions for the webhook payload, and separately deletes comment memos (each recursing through `store.DeleteMemo`) before deleting the memo itself.
