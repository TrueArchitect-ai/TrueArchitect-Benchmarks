**Engine:** Google CEL (`github.com/google/cel-go` v0.28.1, `go.mod:13`), wrapped by the in-repo filter engine at **`internal/filter/`** (`engine.go`, `schema.go`, `parser.go`, `ir.go`, `render.go`; docs in `internal/filter/README.md`).

**Mechanism (one sentence):** `ListMemos` (`server/router/api/v1/memo_service.go:211-216`) validates `request.Filter` via `validateFilter` (`server/router/api/v1/shortcut_service.go:336`) and passes it through as `store.FindMemo.Filters`, and each dialect driver's `ListMemos` calls `filter.AppendConditions(ctx, filter.DefaultEngine(), find.Filters, filter.Dialect{SQLite,MySQL,Postgres}, &where, &args)` (`store/db/sqlite/memo.go:61`, `store/db/mysql/memo.go:69`, `store/db/postgres/memo.go:58`), which compiles the CEL string against the memo-specific CEL env into a dialect-agnostic IR condition tree and then renders it into a parameterized SQL fragment plus args for the target dialect.

Pipeline detail:
- **Parse** — `Engine.Compile` (`internal/filter/engine.go:47`) runs `env.Compile` + `cel.AstToParsedExpr`; the env declares only the allowed variables (`content`, `creator`, `creator_id`, `created_ts`, `pinned`, `tag`, `tags`, `visibility`, `has_task_list`, `has_link`, `has_code`, `has_incomplete_tasks`, `now`, …) in `internal/filter/schema.go:232-249`, so unknown fields are rejected at compile time.
- **Normalize** — `buildCondition` (`internal/filter/parser.go:18`) converts the CEL AST into the IR in `internal/filter/ir.go` (`LogicalCondition`, `ComparisonCondition`, `InCondition`, `TextMatchCondition`, `RegexCondition`, …), enforcing schema/type/operator rules and folding `now` to a single frozen instant per compile.
- **Render** — `Program.Render` / `newRenderer` (`internal/filter/render.go`) walks the IR per `RenderOptions.Dialect`. Dialect differences live in the schema's per-dialect `Expressions` map (`internal/filter/schema.go:104-135`, e.g. `('users/' || %s)` vs `CONCAT('users/', %s)`, `UNIX_TIMESTAMP(%s)` for MySQL timestamps) and in renderer helpers: JSON payload access and tag containment (`JSON_CONTAINS` for MySQL, `@> jsonb_build_array(...)` for Postgres, `json_each`-style for SQLite — `render.go:452-509`), boolean casts (`render.go:357-405`), regex (`~` on Postgres vs `REGEXP` on MySQL/SQLite, `render.go:558-568`), and placeholders (`$N` with `PlaceholderOffset` for Postgres, `?` otherwise — `render.go:842-849`).

The same engine serves attachments (`filter.DefaultAttachmentEngine`, `internal/filter/schema.go:303`); user-list filters use a separate small CEL parser at `server/router/api/v1/user_service_filter.go`.
