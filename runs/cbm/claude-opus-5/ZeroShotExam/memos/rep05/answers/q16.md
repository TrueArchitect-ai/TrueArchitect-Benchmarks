`store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) removes the following before issuing the `DELETE FROM memo` (`/bench/repo/store/db/sqlite/memo.go:237`, `postgres/memo.go:244`, `mysql/memo.go:259`):

1. **Memo relations where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`).
2. **Memo relations where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`).
3. **Attachments linked to the memo** — listed via `ListAttachments{MemoID: &delete.ID}` and deleted one by one with `DeleteAttachment` (`store/memo.go:149-157`). Each of those also deletes the attachment's backing storage (local file or blob) before the attachment row (`store/attachment.go:132-148`).

Note on the surrounding API path: `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-582`) first deletes the memo's comment memos — each via the same `store.DeleteMemo`, so their relations and attachments are cleaned up too — and then deletes the memo itself. Reactions and memo shares are only read/dispatched there, not explicitly deleted by the store layer.
