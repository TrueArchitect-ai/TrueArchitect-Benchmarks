There's no ORM/`TableName()` layer here — the mapping is via hand-written SQL in the per-driver store implementations (`store/db/sqlite/*.go`, `store/db/postgres/*.go`, `store/db/mysql/*.go`), each of which scans rows into the corresponding `store` package struct.

| table | Struct — path |
|---|---|
| `user` | `store.User` — `store/user.go:29` (SQL: `store/db/sqlite/user.go:164` `FROM user`) |
| `attachment` | `store.Attachment` — `store/attachment.go:16` (SQL: `store/db/sqlite/attachment.go:34` `INSERT INTO \`attachment\``) |
| `reaction` | `store.Reaction` — `store/reaction.go:7` (SQL: `store/db/sqlite/reaction.go:16,60`) |

Table definitions themselves live in `store/migration/sqlite/LATEST.sql` (and the postgres/mysql equivalents).
