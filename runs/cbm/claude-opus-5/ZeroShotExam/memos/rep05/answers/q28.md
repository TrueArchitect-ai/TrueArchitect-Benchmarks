**Runners the server actually starts** (all from `Server.startBackgroundRunners`, `server/server.go:153-174`, called at the end of `Server.Start`, `server/server.go:129`):

- **s3presign runner — one synchronous startup pass, then a 12-hour `time.Ticker` loop** — `s3presignRunner.RunOnce(ctx)` runs inline at `server/server.go:163`; the long-lived loop is `go s3presignRunner.Run(s3Context)` (`server/server.go:166-171`), and `Run` ticks on `runnerInterval = 12h` (`server/runner/s3presign/runner.go:26-40`). It re-presigns S3 attachment URLs whose `LastPresignedTime` is older than 4 days (5-day expiry), in batches of 100. Its context is a per-runner `context.WithCancel` whose cancel is stored for shutdown (`server/server.go:156-159`, cancelled by `stopBackgroundRunners`, awaited by `waitBackgroundRunners` via the `sync.WaitGroup`). This is the **only** entry in `backgroundRunnerCancels`/the WaitGroup.

Additional long-lived goroutines started implicitly (not part of the runner framework, no cancel registration):

- **HTTP server goroutine — event-driven** — `go s.httpServer.Serve(listener)` (`server/server.go:124-128`).
- **Store cache cleanup loops (×3) — 5-minute `time.Ticker`** — `go c.cleanupLoop()` in `cache.New` (`store/cache/cache.go:83`, ticker at `:201`), started once each for `instanceSettingCache`, `userCache`, `userSettingCache` in `store.New` (`store/store.go:48-53`, `CleanupInterval: 5 * time.Minute`). Stopped only via `Cache.Close()`.
- **Webhook dispatch workers (4) — queue-driven** — `init()` spawns 4 goroutines draining `asyncPostQueue` (`internal/webhook/webhook.go:43-54`); triggered by memo activity, not by a clock.
- **Email send workers (2) — queue-driven** — `init()` spawns 2 goroutines draining `asyncEmailQueue` (`internal/email/email.go:16-35`).
- **Shutdown-signal goroutine — SIGINT/SIGTERM** — `cmd/memos/main.go:99-103`.

Per-request goroutines/tickers (not background workers): PAT last-used writes fired per authenticated request (`server/auth/authenticator.go:178-185`) and the 30-second SSE heartbeat ticker, which lives for the duration of one SSE connection (`server/router/api/v1/sse_handler.go:15-17, 64`).

**Unused scheduling infrastructure:**

- **`internal/scheduler` (the cron scheduler) is never used by the server.** It's a full cron implementation — 5/6-field parser, timezone support, middleware chain, graceful shutdown (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `middleware.go`, plus `README.md`/`doc.go`) — but the only non-test importers are its own `internal/scheduler/example_test.go` and `internal/scheduler/integration_test.go`. No production code calls `scheduler.New`/`Register`/`Start`. All real periodicity in the server comes from raw `time.NewTicker`s instead.
- **`memopayload.Runner` is dead as a runner.** `server/runner/memopayload/runner.go` defines `NewRunner`/`RunOnce` (batch rebuild of all memo payloads), but nothing constructs it — the only production use of that package is the standalone `memopayload.RebuildMemoPayload` helper called inline on memo create/update (`server/router/api/v1/memo_service.go:108, 447`).
