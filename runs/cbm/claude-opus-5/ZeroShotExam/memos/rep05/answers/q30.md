**Convergence for delivery:**

The three lifecycle events (created/updated/deleted) first funnel through the shared helper `dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo creator and loads their webhooks. `DispatchMemoCommentCreatedWebhook` does not use that helper — it loads webhooks for the *related memo's* creator instead — but it builds the same payload via `convertMemoToWebhookPayload` (`memo_service_webhooks.go:76`).

All four then converge on `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue` (128 slots, drops with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain that queue and call `webhook.Post` (`internal/webhook/webhook.go:120`) — the single actual delivery function that marshals the payload, adds Standard Webhooks HMAC-SHA256 headers when a signing secret is set, and POSTs via the SSRF-guarded `safeClient`.
