**`web/src/connect.ts`; JWT access token (in-memory + localStorage, sent as `Authorization: Bearer`) + HttpOnly refresh-token cookie `memos_refresh` (Personal Access Tokens `memos_pat_*` also accepted server-side); `server/auth/`**

**Frontend interceptor** — `web/src/connect.ts:145` defines `authInterceptor`, wired into the ConnectRPC transport (`createConnectTransport({ ..., interceptors: [authInterceptor] })`, `web/src/connect.ts:170`) that backs every service client (memo, user, auth, attachment, etc.). Per request it:
- calls `getRequestToken()` and sets `Authorization: Bearer <token>` (`setAuthorizationHeader`, line ~92);
- preflight-refreshes when the token is within 30s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`);
- on a `Code.Unauthenticated` response, refreshes once, retries the request with an `X-Retry: true` marker to prevent loops, and otherwise calls `redirectOnAuthFailure()`;
- refreshes via a *separate* transport with no interceptors (`refreshTransport`, line ~62) calling `AuthService.refreshToken`, with `credentials: "include"` so the refresh cookie rides along; concurrent refreshes are deduped by `tokenRefreshManager`.

**Tokens managed** — `web/src/auth-state.ts` holds the short-lived JWT access token in memory plus `localStorage` keys `memos_access_token` / `memos_token_expires_at`, and syncs freshly refreshed tokens across tabs over a `BroadcastChannel` (`memos_token_sync`). The refresh token itself is never touched by JS — it's the server-set cookie. `web/src/hooks/useTokenRefreshOnFocus.ts` proactively refreshes on tab focus (2 min buffer); `web/src/lib/query-client.ts` suppresses React Query retries on `Unauthenticated` so the interceptor owns that path.

**Backend validation** — package `server/auth/`:
- `server/auth/token.go` — token kinds and constants: access token (15 min, audience `user.access-token`), refresh token (30 days, cookie `memos_refresh`), PAT prefix `memos_pat_`;
- `server/auth/authenticator.go` — `AuthenticateByAccessTokenV2` (stateless signature check), `AuthenticateByRefreshToken` (DB revocation/expiry check), `AuthenticateByPAT`, and `Authenticate` / `AuthenticateToUser`;
- `server/auth/extract.go` — `ExtractBearerToken` / `ExtractRefreshTokenFromCookie`.

It's invoked from the server-side Connect interceptor `AuthInterceptor.WrapUnary` in `server/router/api/v1/connect_interceptors.go:217` (via `Authorizer` in `server/router/api/v1/authz.go`), and also from `server/router/fileserver/fileserver.go` and `server/router/mcp/`.
