MemoService's single implementation (`APIV1Service`, methods in `server/router/api/v1/memo_service.go` and siblings) is exposed over two protocols, both wired up in `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`):

**1. HTTP/JSON REST via gRPC-Gateway** — `server/router/api/v1/v1.go:108`
```go
v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)
```
The gateway mux is created at `v1.go:96` and mounted on Echo at `/api/v1/*` and `/file/*` (`v1.go:126-129`). The generated gateway code is `proto/gen/api/v1/memo_service.pb.gw.go`.

**2. Connect RPC (connect-rpc, used by the browser client in place of grpc-web)** — `server/router/api/v1/connect_handler.go:40`
```go
wrap(apiv1connect.NewMemoServiceHandler(s, opts...)),
```
inside `ConnectServiceHandler.RegisterConnectHandlers`. That mux is built and mounted at `/memos.api.v1.*` in `v1.go:139-144`. The Connect-signature method wrappers that delegate to the gRPC implementations live in `server/router/api/v1/connect_services.go:304+` (`// MemoService` section), and the generated handler constructor is in `proto/gen/api/v1/apiv1connect/memo_service.connect.go:461`.

Note there is no native gRPC listener — `grpc.NewServer` appears nowhere in the server code; the gRPC-style service implementation is reached only through these two HTTP surfaces.
