**Workers the server actually starts** (`Server.Start` → `startBackgroundRunners`, `server/server.go:129`, `:153-174`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — runs once synchronously at startup (`RunOnce`, `server.go:163`), then a `time.NewTicker` loop on a hard-coded 12-hour interval (`runner.go:27-41`); shut down via its own `context.CancelFunc` + `WaitGroup` (`server.go:156-171`, `:176-201`). It's the only entry in `backgroundRunnerCancels`.
- **HTTP serve goroutine** (`server/server.go:124`) — not a scheduled worker; just `httpServer.Serve(listener)`.

**Background goroutines started elsewhere (not by `startBackgroundRunners`), for completeness:**

- **store cache janitors ×3** (`store/cache/cache.go:83` via `cleanupLoop`, `:199-213`) — a `time.Ticker` at `CleanupInterval` = 5 min, one per cache (`instanceSettingCache`, `userCache`, `userSettingCache`), spawned implicitly by `cache.New` in `store.New` (`store/store.go:40-53`), which `cmd/memos/main.go` calls before the server exists.
- **webhook dispatch pool ×4** (`internal/webhook/webhook.go:42-52`) — package `init()`; event-driven, drains the 128-buffered `asyncPostQueue`, no timer.
- **email send pool ×2** (`internal/email/email.go:15-23`) — package `init()`; event-driven off `asyncEmailQueue`.
- **SSE heartbeat** (`server/router/api/v1/sse_handler.go:17`, `:64`) — 30s ticker, but per-connection inside the request handler, not a server-level runner.
- **PAT last-used writer** (`server/auth/authenticator.go:180`) — one-shot goroutine per authenticated request, request-triggered.

**Unused scheduling infrastructure:**

- **`internal/scheduler` is dead in production.** It's a complete GitHub-Actions-style cron scheduler — 5/6-field cron parsing, timezone awareness, middleware (Recovery/Logging/Timeout), graceful shutdown (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`, `doc.go`, `README.md`) — but the only importers are its own tests (`internal/scheduler/example_test.go:10`, `integration_test.go:13`). Nothing in `cmd/`, `server/`, or `store/` references it; the one runner that exists uses a raw `time.Ticker` instead.
- **`server/runner/memopayload` is never started as a runner.** It sits in the runner directory and exposes `NewRunner`/`RunOnce` (batch-rebuilds every memo's payload, `server/runner/memopayload/runner.go:19-27`), but `memopayload.NewRunner`/`Runner` have zero references repo-wide. Only the package-level `RebuildMemoPayload` is used, called inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447` — so its trigger is memo create/update, not any schedule.
