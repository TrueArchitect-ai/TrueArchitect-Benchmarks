The store-layer `Store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) deletes these before issuing the `DELETE FROM memo` statement:

1. **Memo relations where the memo is the source** — `driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{MemoID: &delete.ID})` (`store/memo.go:142`)
2. **Memo relations where the memo is the target/related memo** — `driver.DeleteMemoRelation(ctx, &DeleteMemoRelation{RelatedMemoID: &delete.ID})` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments(FindAttachment{MemoID: &delete.ID})` and removed one-by-one with `Store.DeleteAttachment` (`store/memo.go:149-157`). That call also removes the attachment's backing storage (local file / S3 object) via `DeleteAttachmentStorage` before deleting the attachment row (`store/attachment.go:132-149`).

Only then does it call `driver.DeleteMemo`, which is the plain `DELETE FROM memo WHERE id = ?` per-driver (e.g. `store/db/sqlite/memo.go:237`, `store/db/postgres/memo.go:244`, `store/db/mysql/memo.go:259`).

For context on what happens above the store: the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518-582`) first deletes the memo's **comment memos** (each recursing through `Store.DeleteMemo`), then deletes the memo itself. Reactions are read for the webhook payload but are not deleted in this path.
