`Store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) deletes, in order, before the memo row itself:

1. **Memo relation records where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`)
2. **Memo relation records where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`)
3. **Attachments linked to the memo** — listed via `ListAttachments(FindAttachment{MemoID: ...})` and removed one by one with `DeleteAttachment` (`store/memo.go:149-157`). `Store.DeleteAttachment` (`store/attachment.go:132-149`) also deletes the backing storage object (local file or S3 blob) before removing the attachment row.

Only then does it call `s.driver.DeleteMemo` for the memo row (`store/memo.go:158`).

Note for context: the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:567-582`) additionally deletes comment memos first — each of those goes through the same store path — but that is the service layer, not the store. Reactions are not deleted by the store's `DeleteMemo`.
