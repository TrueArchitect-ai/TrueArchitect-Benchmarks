Details worth noting:

- **Three-phase pipeline** (`internal/filter/README.md:1-21`): parse CEL with cel-go and type-check against the memo env → normalize AST into IR conditions (`parser.go` → `ir.go`) → render to SQL (`render.go`).
- **Schema gate** (`internal/filter/schema.go:90+`): only declared identifiers are allowed — `content`, `creator`, `creator_id`, `created_ts`, `updated_ts`, `pinned`, `visibility`, `tags`/`tag` (alias), `has_task_list`, `has_link`, etc. Each `Field` carries its backing `Column`, `FieldKind` (scalar / bool column / JSON bool / JSON list / virtual alias), allowed comparison operators, and per-dialect `Expressions` templates (e.g. `creator` renders as `('users/' || %s)` on SQLite/Postgres vs `CONCAT('users/', %s)` on MySQL; `created_ts` needs `UNIX_TIMESTAMP(%s)` on MySQL only).
- **Dialect divergence lives in the renderer**: `render.go` switches on `r.dialect` for JSON access, boolean semantics, `LIKE` vs `ILIKE`, timestamp extraction (`timestampAccessorExpr`, `internal/filter/render.go:222-247`), and placeholders — `$N` for Postgres, `?` otherwise (`addArg`, `render.go:842-849`), with `PlaceholderOffset` threaded through so multiple filters concatenate correctly (`helpers.go:9-24`).
- **Output**: a `Statement{SQL, Args}`; trivially-true filters render as empty SQL (skipped), unsatisfiable ones as `1 = 0` (`render.go:32-56`).
- The engine is process-wide and lazily built via `sync.Once` (`internal/filter/engine.go:110-116`), with a parallel `DefaultAttachmentEngine()` for attachment filters.
