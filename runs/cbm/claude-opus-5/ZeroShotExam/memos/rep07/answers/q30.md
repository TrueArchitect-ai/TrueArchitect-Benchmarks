**Convergence for delivery:**

The first three funnel through the shared helper `(*APIV1Service).dispatchMemoRelatedWebhook` (`memo_service_webhooks.go:48`), which resolves the memo's creator and loads their webhooks. `DispatchMemoCommentCreatedWebhook` bypasses that helper (it targets the *related* memo's owner, not the comment creator) and builds the payload inline.

All four then converge on `webhook.PostAsync(payload)` (`internal/webhook/webhook.go:184`), which enqueues onto the bounded `asyncPostQueue` (128 slots, dropped with a warning when full). Four worker goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) drain the queue and call `webhook.Post` (`internal/webhook/webhook.go:120`) — the single point that marshals the payload, adds Standard Webhooks HMAC-SHA256 headers when a signing secret is set, and performs the HTTP POST via `safeClient`, whose `safeDialContext` blocks reserved/private IPs (SSRF/DNS-rebinding guard).

Note: `dispatchMemoRelatedWebhook` returns early on payload-conversion error, so a failure on one webhook skips the remaining hooks for that memo.
