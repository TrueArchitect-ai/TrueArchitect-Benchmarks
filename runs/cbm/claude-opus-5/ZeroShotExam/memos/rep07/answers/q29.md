**`web/src/connect.ts`; JWT access token (in-memory + localStorage) + HttpOnly refresh-token cookie, plus Personal Access Tokens (PATs) for programmatic clients; `server/auth/`**

**Interceptor** — `authInterceptor` at `web/src/connect.ts:156-178`, installed on the shared Connect-RPC transport (`web/src/connect.ts:184-189`) that backs every service client (memo, user, auth, attachment, etc.). It:
- calls `getRequestToken()` and sets `Authorization: Bearer <token>` (`connect.ts:97-100`, `124-150`), doing a *preflight* refresh when the token is within `REQUEST_TOKEN_EXPIRY_BUFFER_MS` (30 s) of expiry;
- on a `Code.Unauthenticated` response, refreshes once, retries with an `X-Retry: true` marker to prevent loops, and otherwise calls `redirectOnAuthFailure()` (`connect.ts:161-177`).

**Tokens it manages** — `web/src/auth-state.ts`:
- short-lived JWT **access token**, cached in-memory and in `localStorage` under `memos_access_token` / `memos_token_expires_at`, shared between tabs over a `memos_token_sync` BroadcastChannel;
- a **refresh token** it never touches directly — it's an HttpOnly cookie, which is why the transport uses `credentials: "include"` (`connect.ts:57-62`). Refresh goes through a separate interceptor-free transport (`connect.ts:65-72`) to avoid recursion, and `refreshAccessToken()` de-dupes concurrent refreshes (`connect.ts:30-91`) so proactive refresh (`web/src/hooks/useTokenRefreshOnFocus.ts`) and reactive 401 refresh don't race server-side token rotation.

**Backend validation** — package `server/auth` (`server/auth/authenticator.go`, `token.go`, `extract.go`):
- `Authenticator.AuthenticateByAccessTokenV2` → stateless `ParseAccessTokenV2` HMAC check (`authenticator.go:41`);
- `AuthenticateByRefreshToken` → parses, then checks the DB for revocation/expiry (`authenticator.go:61`);
- `AuthenticateByPAT` → tokens prefixed `memos_pat_`, looked up by hash (`authenticator.go:102`);
- constants: access token 15 min, refresh token 30 days, cookie `memos_refresh` (`server/auth/token.go:39-52`).

It's invoked from the Connect `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:217-231`), which delegates to `Authorizer` in `server/router/api/v1/authz.go:44`; the same `Authenticator` also backs the file server and MCP router.
