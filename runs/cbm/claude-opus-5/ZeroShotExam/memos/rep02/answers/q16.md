`Store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) removes, in this order, before deleting the memo row itself (`s.driver.DeleteMemo` at `store/memo.go:158`):

1. **Memo relations where the memo is the source** — `DeleteMemoRelation{MemoID: &delete.ID}` (`store/memo.go:142`).
2. **Memo relations where the memo is the target/related memo** — `DeleteMemoRelation{RelatedMemoID: &delete.ID}` (`store/memo.go:145`).
3. **Attachments linked to the memo** — listed via `ListAttachments(FindAttachment{MemoID: ...})` and deleted one by one with `DeleteAttachment` (`store/memo.go:149-157`). Each of those also deletes the attachment's underlying stored blob/local file via `DeleteAttachmentStorage` before the attachment row (`store/attachment.go:132-148`).

Notes on scope:
- Reactions and memo shares are *not* deleted by the store layer here; nothing in `Store.DeleteMemo` touches them.
- Comment memos are deleted at the API layer, not the store layer: `APIV1Service.DeleteMemo` first lists `MemoRelationComment` relations and calls `Store.DeleteMemo` on each comment memo, then deletes the target memo (`/bench/repo/server/router/api/v1/memo_service.go:567-582`).
