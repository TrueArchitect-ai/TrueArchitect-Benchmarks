**Answer:** `web/src/connect.ts` (with token storage in `web/src/auth-state.ts`); JWT access tokens (short-lived, sent as `Authorization: Bearer`) + HTTP-only refresh-token cookie `memos_refresh`, plus Personal Access Tokens for programmatic clients; validated by the Go package `server/auth` (wired in via `server/router/api/v1/connect_interceptors.go`).

### How it works

**Frontend interceptor — `web/src/connect.ts:156`**
- `authInterceptor` is attached to the Connect-RPC transport (`web/src/connect.ts:184-189`), so every generated service client (memo, user, attachment, AI, shortcut, IdP, instance, auth) goes through it.
- On each request it calls `getRequestToken()` (`web/src/connect.ts:124`) and sets `Authorization: Bearer <token>`.
- Preflight: if the access token is within 30 s of expiry (`REQUEST_TOKEN_EXPIRY_BUFFER_MS`), it refreshes first — this stops public endpoints like `ListMemos` from silently returning guest-scoped data.
- Reactive: on a `Code.Unauthenticated` error it refreshes once, sets `X-Retry: true`, and replays the request; a second failure calls `redirectOnAuthFailure()` (`web/src/utils/auth-redirect.ts`).
- Refreshes run through `tokenRefreshManager` (`web/src/connect.ts:30`) to dedupe concurrent calls, and use a *separate* transport with no interceptors (`web/src/connect.ts:65`) to avoid recursion. `fetch` is wrapped with `credentials: "include"` so the refresh cookie is sent.

**Token kinds**
1. **Access token (JWT)** — 15 min lifetime, held in memory and mirrored to `localStorage` under `memos_access_token` / `memos_token_expires_at` (`web/src/auth-state.ts:6-7`). A `BroadcastChannel` (`memos_token_sync`) shares freshly refreshed tokens across tabs so only one tab hits the refresh endpoint.
2. **Refresh token (JWT)** — 30 days, delivered as the HTTP-only cookie `memos_refresh` (`server/auth/token.go:49`), never touched by JS; exchanged via `AuthService.RefreshToken`.
3. **Personal Access Token (PAT)** — long-lived, DB-backed, for programmatic API use; also passed as a Bearer token.

**Backend validation — `server/auth/`**
- `server/auth/authenticator.go` is the shared `Authenticator`: `AuthenticateByAccessTokenV2` (stateless JWT parse), `AuthenticateByRefreshToken` (DB-checked), and `AuthenticateByPAT` (DB-checked, records last-used asynchronously). `ExtractBearerToken` / `ExtractRefreshTokenFromCookie` live in `server/auth/extract.go`, JWT constants and parsing in `server/auth/token.go`.
- It's invoked from `AuthInterceptor.WrapUnary` in `server/router/api/v1/connect_interceptors.go:217`, which delegates to the `Authorizer` (`server/router/api/v1/authz.go`) for the anonymous-access policy and then stashes the result on the context. The same package also backs the file server (`server/router/fileserver/fileserver.go:709`) and SSE handler (`server/router/api/v1/sse_handler.go:36`).
