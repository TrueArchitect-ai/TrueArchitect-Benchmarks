MemoService is exposed over **HTTP/REST (via grpc-gateway)** and **Connect (connectrpc, over `/memos.api.v1.*`)**. There is no standalone gRPC server listener — the `APIV1Service` gRPC implementation is bound in-process to both handlers.

- **HTTP/REST via grpc-gateway — `/bench/repo/server/router/api/v1/v1.go:108`**
  `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` registers the service directly on the gateway mux (in-process, no gRPC dial). The mux is mounted onto Echo at `/api/v1/*` and `/file/*` (`v1.go:123-127`), with auth applied by `gatewayAuthMiddleware` (`v1.go:69-92`). Generated gateway code: `/bench/repo/proto/gen/api/v1/memo_service.pb.gw.go:961`.

- **Connect (connectrpc) — `/bench/repo/server/router/api/v1/connect_handler.go:40`**
  `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` inside `RegisterConnectHandlers`, where `s` is the `ConnectServiceHandler` wrapper embedding `*APIV1Service` (`connect_handler.go:21-28`). The per-method Connect wrappers that unwrap `connect.Request` and delegate to the gRPC methods live in `/bench/repo/server/router/api/v1/connect_services.go:304+` (the `// MemoService` section). The mux is created and mounted at `/memos.api.v1.*` in `/bench/repo/server/router/api/v1/v1.go:137-143`.

Both share the same service implementation and the same `authorizer`; the gateway path uses `gatewayAuthMiddleware`, the Connect path uses `NewAuthInterceptor(authorizer)` (`v1.go:132-136`). Note the generated native gRPC registration `RegisterMemoServiceServer` (`/bench/repo/proto/gen/api/v1/memo_service_grpc.pb.go:439`) exists but is never called anywhere in `server/`.
