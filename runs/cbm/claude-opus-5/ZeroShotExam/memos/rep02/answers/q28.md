**Runners the server actually starts**

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.startBackgroundRunners` (`server/server.go:159-180`). Two triggers: `RunOnce(ctx)` synchronously once at startup, then a goroutine running `Run(s3Context)` driven by a plain `time.NewTicker` at a hardcoded `runnerInterval = 12 * time.Hour` (`s3presign/runner.go:28-42`). It re-presigns S3 attachment URLs whose 5-day presign is within 4 days of expiry, in batches of 100. Cancelled via a per-runner `context.CancelFunc` and awaited on a `sync.WaitGroup` during `Shutdown` (`server/server.go:139-147`, `182-206`).

That is the only entry in `startBackgroundRunners` — no other runner is registered there.

**Other long-lived goroutines started along the server's path** (not registered as "background runners", so not covered by the shutdown WaitGroup):

- **Store cache cleanup loops ×3** — `cache.New` spawns `go c.cleanupLoop()` (`store/cache/cache.go:83`, `199-212`), ticker-driven at `CleanupInterval = 5 * time.Minute`; three instances (instance-setting, user, user-setting caches) are created by `store.New` (`store/store.go:38-53`), which `cmd/memos/main.go:64` calls. Stopped only via `Cache.Close()` (`store/cache/cache.go:190-198`).
- **HTTP serve goroutine** — `go s.httpServer.Serve(listener)` (`server/server.go:124`), request-driven.
- **SSE heartbeat** — per-connection `time.NewTicker(sseHeartbeatInterval)` inside the SSE handler (`server/router/api/v1/sse_handler.go:64`); lives for the life of one client stream, not a global worker.
- **Signal-handler goroutine** — waits on SIGINT/SIGTERM to call `s.Shutdown` (`cmd/memos/main.go:97-101`).

Fire-and-forget one-shot goroutines (not schedulers): PAT last-used update (`server/auth/authenticator.go:180`), webhook dispatch (`internal/webhook/webhook.go:44`), email send (`internal/email/email.go:18`).

**Unused scheduling infrastructure**

- **`internal/scheduler`** — a complete, tested cron scheduler package (5- and 6-field cron parsing, timezone support, middleware/recovery/logging, graceful `Stop`; `internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`, plus `README.md`/`doc.go`) that the server **never uses**. The only importers of `github.com/usememos/memos/internal/scheduler` in the whole repo are its own tests (`internal/scheduler/example_test.go:10`, `internal/scheduler/integration_test.go:13`). Nothing in `server/`, `cmd/`, or `store/` calls `scheduler.New`/`Register`/`Start` — the one real runner uses a raw `time.Ticker` instead of this package.
- **`server/runner/memopayload`** — a runner package whose `Runner`/`RunOnce` batch-rebuild of all memo payloads is never constructed or started; `NewRunner` has no callers. Only the standalone helper `memopayload.RebuildMemoPayload` is used, called inline on the request path in `server/router/api/v1/memo_service.go:108` and `:447`.
