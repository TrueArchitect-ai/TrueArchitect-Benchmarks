**Premise correction**: The question assumes webhook delivery workers consume from a message broker (NATS or RabbitMQ), but they do not. There is no external message broker used.

**Actual mechanism**: Webhook delivery uses an in-memory Go channel for asynchronous queuing and processing:

- **Queue implementation**: A buffered Go channel declared at internal/webhook/webhook.go:39
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
  
- **Consumer workers**: 4 concurrent worker goroutines launched in the `init()` function (internal/webhook/webhook.go:42-54) that consume from the channel and dispatch webhooks synchronously using the `Post()` function

- **Producer**: Webhook events are enqueued via `PostAsync()` (internal/webhook/webhook.go:184) by sending to the channel

This is a simple in-process async queue with a bounded capacity of 128 items. If the queue fills up, new webhook events are dropped with a warning log (internal/webhook/webhook.go:192-194).
