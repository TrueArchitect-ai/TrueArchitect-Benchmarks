**Premise correction**: There is no per-user API rate-limiting middleware registered in this repository. The question assumes rate limiting exists, but it does not.

**Actual mechanism**: The server implements only two middleware in the HTTP layer:
1. Recovery middleware (server/server.go:51) — `middleware.Recover()`
2. CORS middleware (server/server.go:52) — `newCORSMiddleware(profile)`

For API requests, the only protection against resource exhaustion is:
- Page size normalization for list operations (server/router/api/v1/common.go:48-52)
- File upload size limits enforced per instance setting (server/router/api/v1/attachment_service.go:125)
- Request body size limits with `http.MaxBytesHandler` (server/router/api/v1/v1.go:126, 144)
- Concurrent thumbnail generation semaphore limiting (server/router/api/v1/v1.go:39) — not an API rate limit but a resource pool limit

There is no per-user rate limiting, no request quota tracking, and no throttling middleware anywhere in the codebase.
