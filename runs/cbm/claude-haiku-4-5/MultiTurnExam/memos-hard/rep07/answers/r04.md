**Premise correction:** There are no webhook delivery workers consuming from a message broker. The system does not use NATS or RabbitMQ for webhook delivery.

**Actual mechanism:** Webhook delivery uses an in-memory buffered channel queue (`asyncPostQueue` declared in `internal/webhook/webhook.go:39` with a capacity of 128 messages). The queue is managed by 4 concurrent goroutines initialized in the `init()` function (`internal/webhook/webhook.go:42-55`) that consume from this channel and dispatch webhooks synchronously via HTTP POST using the `Post()` function. Webhooks are enqueued by calling `PostAsync()` (`internal/webhook/webhook.go:184-196`), which attempts to send the payload to the channel or logs a warning if the queue is full.
