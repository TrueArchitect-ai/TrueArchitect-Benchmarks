**Premise correction + actual mechanism: Neither NATS nor RabbitMQ is used. Webhook delivery workers consume from an in-memory Go channel instead.**

**Mechanism:**

The webhook async queue is declared in internal/webhook/webhook.go at line 39:
```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a buffered Go channel with a capacity of 128 messages, declared as a package-level variable. Four worker goroutines are spawned in the `init()` function (lines 42-55) that consume from this channel and execute `Post()` for each webhook payload. When `PostAsync()` is called (line 184), the payload is sent to this channel; if the channel is full, the dispatch is dropped with a warning.

There are no external message brokers (NATS, RabbitMQ, Kafka, etc.) used for webhook delivery — it relies entirely on in-memory Go channels for the async queue mechanism.
