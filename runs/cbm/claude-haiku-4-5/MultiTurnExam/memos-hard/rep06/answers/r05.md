**Premise correction: There is no GraphQL schema for the public API. The API is gRPC (Protocol Buffers) based.**

**Actual API surface:**

The public API is defined using Protocol Buffer (protobuf) service definitions in proto files, located in `/bench/repo/proto/api/v1/`:

- **proto/api/v1/memo_service.proto** — Memo CRUD, comments, reactions, relations
- **proto/api/v1/user_service.proto** — User management, settings, authentication
- **proto/api/v1/auth_service.proto** — Authentication (sign-in, refresh, sign-out)
- **proto/api/v1/attachment_service.proto** — File attachments
- **proto/api/v1/instance_service.proto** — Instance configuration and settings
- **proto/api/v1/ai_service.proto** — AI services (transcription, etc.)
- **proto/api/v1/idp_service.proto** — Identity provider configuration
- **proto/api/v1/shortcut_service.proto** — Keyboard shortcuts
- **proto/api/v1/common.proto** — Shared enums and messages (State, Direction, PageToken)

These proto definitions are transpiled into:
1. **gRPC-Gateway handlers** (proto/gen/api/v1/*_service.pb.gw.go) — HTTP REST endpoints
2. **Connect RPC handlers** (proto/gen/api/v1/apiv1connect/*_service.connect.go) — JSON-RPC protocol

The API is registered via `RegisterGateway()` in server/router/api/v1/v1.go and serves both gRPC-Gateway (HTTP) and Connect (JSON-RPC) protocols.
