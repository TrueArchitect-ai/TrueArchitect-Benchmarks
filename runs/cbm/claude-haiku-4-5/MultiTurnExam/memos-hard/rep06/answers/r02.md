**Premise correction: The codebase does not implement per-user API rate-limiting middleware.**

After extensive searching through the server setup (server/server.go, server/router/api/v1/v1.go, server/router/api/v1/connect_interceptors.go, server/cors.go), the registered middleware includes only:

- **Recovery middleware** — panic recovery
- **CORS middleware** — origin validation  
- **Auth middleware** (via Authorizer) — authentication and access checks
- **Logging interceptor** — request logging
- **Metadata interceptor** — header forwarding

There is no rate-limiting middleware registered for per-user API requests. The only concurrency-limiting mechanism found is a semaphore for thumbnail generation (`thumbnailSemaphore`, `imageProcessingSemaphore` in server/router/api/v1/v1.go:39-41), not for API requests themselves.

The premise that rate-limiting is implemented appears to be incorrect.
