**Premise correction + actual mechanism:** Webhook delivery workers do not consume from NATS or RabbitMQ. Instead, they consume from an in-memory buffered Go channel named `asyncPostQueue` with capacity 128. The queue is declared at module level in **internal/webhook/webhook.go:39** as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`. The `init()` function in **internal/webhook/webhook.go:42-55** spawns 4 concurrent goroutine workers that consume from this channel and dispatch webhooks synchronously via HTTP POST. There is no external message broker dependency — the delivery queue is entirely in-process and in-memory.
