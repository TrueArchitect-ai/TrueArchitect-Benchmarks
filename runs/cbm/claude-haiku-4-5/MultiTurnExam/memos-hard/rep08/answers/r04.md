**Premise correction:** Neither NATS nor RabbitMQ is used. The webhook delivery system does not use a message broker at all.

**Actual mechanism:** Webhook delivery uses a simple in-memory Go channel-based queue declared at package initialization (internal/webhook/webhook.go:39):

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

This is a buffered channel with a capacity of 128 webhook payloads. The queue is consumed by 4 goroutines spawned during package initialization (internal/webhook/webhook.go:42-55), each continuously reading from the channel and calling the `Post()` function to deliver webhooks. When `PostAsync()` is called (internal/webhook/webhook.go:184-196), it enqueues the webhook payload into this channel, and if the channel is full, the webhook is dropped with a warning.

This is a lightweight, in-process solution with no external message broker dependency.
