**Premise correction:** There is no Redis connection configured. This repository does not use Redis for caching.

**Actual mechanism:** The cache layer uses an in-memory Go implementation (`store/cache/cache.go`), not Redis. The cache is configured in `store/store.go:38-61`, where three separate cache instances are created:
- `instanceSettingCache`
- `userCache`
- `userSettingCache`

All three use the same configuration with:
- **TTL for user entries:** 10 minutes (stored in `DefaultTTL` at `store/store.go:41`)
- Cleanup interval: 5 minutes
- Max items: 1000 per cache instance

The cache is thread-safe, uses in-memory storage with sync.Map, and includes automatic cleanup of expired entries based on TTL.
