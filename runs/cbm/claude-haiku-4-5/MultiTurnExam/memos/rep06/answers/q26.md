The memo table DELETE doesn't have any cascades. Based on my thorough analysis of the code, here's what gets deleted:

q26. memo, memo_relation, attachment

When DeleteMemo runs, these database tables are affected:
1. **memo** - the memo row itself is deleted
2. **memo_relation** - all relations where this memo is either the source (MemoID) or target (RelatedMemoID) are deleted
3. **attachment** - all attachments linked to this memo are deleted via explicit DeleteAttachment calls

Note: Reactions (reaction table) and memo shares (memo_share table) are queried but NOT deleted by the DeleteMemo function. The code retrieves them for webhook dispatching but does not perform cascade deletion.
