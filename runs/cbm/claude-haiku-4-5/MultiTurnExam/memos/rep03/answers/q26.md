The DeleteMemo implementation only deletes the memo row itself. Based on the schema and the API handler code:

q26.
memo, memo_share

When DeleteMemo runs, these tables are affected:
1. **memo** - the memo row is deleted directly
2. **memo_share** - cascade-deleted via ON DELETE CASCADE foreign key constraint on memo_id (store/migration/sqlite/LATEST.sql:109)

Note: While the API handler lists attachments, memo_relations, and reactions for webhook dispatch, these are not automatically cleaned up by the database:
- **memo_relation** table has no CASCADE constraint and is not explicitly deleted in the store layer
- **attachment** table has no foreign key constraint at all and is not explicitly deleted
- **reaction** table uses a string content_id field (not a foreign key) and is not explicitly deleted

The cascade behavior means memo_share records are automatically removed when a memo is deleted, but other related records would require explicit application-level deletion logic if needed.
