Reactions don't appear to be explicitly deleted when a memo is deleted - they're keyed by content_id (string) not memo ID, so they won't cascade. Based on my analysis:

**q26.** memo, memo_relation, attachment, memo_share

When DeleteMemo runs, these tables are affected:
1. **memo** - directly deleted (store/memo.go line 158)
2. **memo_relation** - explicitly deleted where memo is source or target (store/memo.go lines 142-147)
3. **attachment** - explicitly deleted via s.DeleteAttachment for each memo attachment (store/memo.go lines 149-157)
4. **memo_share** - cascade deleted via foreign key constraint ON DELETE CASCADE (store/migration/sqlite/LATEST.sql)

The API handler also recursively deletes comment memos first (server/router/api/v1/memo_service.go line 574), which triggers the same cascade for each comment.
