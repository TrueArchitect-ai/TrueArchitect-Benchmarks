web/src/connect.ts; access tokens and refresh tokens; server/auth

Frontend API requests get authenticated through:
1. **Auth Interceptor Location**: `web/src/connect.ts` (line 156, `authInterceptor` constant) — an interceptor that runs on every request to manage authentication
2. **Token Kinds**: 
   - **Access tokens** — short-lived JWT tokens sent in the `Authorization: Bearer <token>` header for each request
   - **Refresh tokens** — longer-lived tokens used to obtain new access tokens (managed via HTTP cookies with `credentials: "include"`)
3. **Backend Validation Package**: `server/auth/` — which contains:
   - `authenticator.go` — the `Authenticator` type that validates Bearer tokens and refresh tokens
   - `token.go` — token generation and validation logic with `AccessTokenClaims` and `RefreshTokenClaims` structures
   - `context.go` and `extract.go` — utilities for extracting and applying auth context to requests

The interceptor handles proactive token refresh before expiry (via `REQUEST_TOKEN_EXPIRY_BUFFER_MS`) and reactive refresh on 401 responses, with BroadcastChannel sync across browser tabs to avoid duplicate refresh requests.
