When DeleteMemo runs, the following database tables are affected (directly or by explicit cascade code):

1. **memo** - The main memo record is deleted (store/db/sqlite/memo.go:237-248, store/db/mysql/memo.go:259-270, store/db/postgres/memo.go:244-255)
2. **memo_relation** - Explicitly deleted via DeleteMemoRelation, removing relations where the memo is either source (memo_id) or target (related_memo_id) (store/memo.go:142-146)
3. **attachment** - Explicitly deleted via DeleteAttachment for each attachment linked to the memo (store/memo.go:149-156)
4. **memo_share** - Automatically deleted by database cascade constraint `ON DELETE CASCADE` defined in all three database migrations (store/migration/sqlite/LATEST.sql:109, store/migration/mysql/LATEST.sql:108, store/migration/postgres/LATEST.sql:108)

Additionally, memo comments (which are also memos) are recursively deleted as part of the explicit cascade logic in the API layer (server/router/api/v1/memo_service.go:569-577), which triggers the same DeleteMemo flow for each comment.
