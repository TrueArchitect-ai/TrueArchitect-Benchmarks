**Frontend API Request Authentication:**

**Interceptor location:** `web/src/connect.ts` (lines 156-178, exported as `authInterceptor`)

**Token kinds managed:** 
- Access Token (JWT, short-lived: 15 minutes)
- Refresh Token (long-lived: 30 days, stored in HTTP-only cookie)

**Backend package that validates them:** `server/auth` (specifically `server/auth/authenticator.go`)

**How it works:**
1. Frontend interceptor (`web/src/connect.ts:authInterceptor`) retrieves the access token via `getRequestToken()` and sets the `Authorization: Bearer {token}` header via `setAuthorizationHeader()` (line 99)
2. Token state is managed in `web/src/auth-state.ts` using localStorage for persistence across tabs/sessions
3. Backend `AuthInterceptor` (`server/router/api/v1/connect_interceptors.go:213-240`) extracts the Bearer token from the Authorization header and calls `authorizer.Authenticate()`
4. The `Authenticator` in `server/auth/authenticator.go` validates two token kinds:
   - **Access Token V2** (stateless JWT validation via `AuthenticateByAccessTokenV2`)
   - **Personal Access Tokens (PAT)** (database lookup via `AuthenticateByPAT`, prefixed with `memos_pat_`)
5. Additionally, refresh tokens can be sent via the `memos_refresh` cookie as a fallback authentication method
