q25.

**Engine + Path:** CEL (Common Expression Language) engine from `github.com/google/cel-go/cel` at `/bench/repo/internal/filter/engine.go`

**Mechanism:** The filter string is parsed by CEL's `env.Compile()` into an AST, then converted to a dialect-agnostic condition tree via `buildCondition()`, and finally each condition is rendered into dialect-specific SQL (SQLite/MySQL/Postgres) by the `renderer` which switches on `DialectName` for each operation (e.g., timestamp accessors use `strftime` for SQLite vs `EXTRACT` for Postgres vs function names for MySQL; regex uses `~` for Postgres vs `REGEXP` for MySQL/SQLite; JSON operations use `JSON_CONTAINS`/`@>` per dialect).
