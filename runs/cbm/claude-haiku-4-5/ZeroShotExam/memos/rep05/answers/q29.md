**Details:**

The `authInterceptor` in `web/src/connect.ts:156-178` intercepts all API requests and:
1. Gets the access token from storage via `getRequestToken()`
2. Sets the `Authorization: Bearer <token>` header
3. On 401 errors, refreshes the token via `refreshAndGetAccessToken()` and retries
4. Falls back to redirect on auth failure

The interceptor manages two token types stored in `web/src/auth-state.ts`:
- **Access tokens**: JWT tokens validated by the backend via stateless signature verification
- **Refresh tokens**: Long-lived tokens used to obtain new access tokens (stored in HTTP-only cookies)

The backend's `server/auth` package (particularly `server/auth/authenticator.go`) validates these tokens. The `AuthInterceptor` in `server/router/api/v1/connect_interceptors.go:208-230` extracts the `Authorization` header and delegates token validation to the `Authenticator` which supports:
- `AuthenticateByAccessTokenV2()`: Stateless JWT validation using signature only
- `AuthenticateByRefreshToken()`: Database-backed validation with revocation checks
- `AuthenticateByPAT()`: Personal Access Token validation
