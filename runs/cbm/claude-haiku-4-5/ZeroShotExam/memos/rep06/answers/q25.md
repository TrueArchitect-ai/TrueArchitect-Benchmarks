The **CEL (Common Expression Language)** engine lives in `internal/filter/engine.go` and parses filter expressions. The syntax is CEL, powered by Google's `github.com/google/cel-go/cel` library.

**Mechanism:** The filter is compiled via `Engine.Compile()` (line 48 in `internal/filter/engine.go`) which uses CEL to parse the expression into an AST, then builds a dialect-agnostic condition tree via `buildCondition()`. The condition tree is then rendered to SQL-specific syntax for each dialect (MySQL, PostgreSQL, SQLite) via `Engine.Render()` (line 95) or `Engine.CompileToStatement()` (line 74), which selects the appropriate SQL generation based on the `DialectName` passed in `RenderOptions` — this happens in `store/db/{mysql,postgres,sqlite}/memo.go` where `filter.AppendConditions()` converts each filter string to the target dialect's SQL fragment using the renderer at `internal/filter/render.go`.

**Path:** `internal/filter/` (engine, parser, renderer); dialects defined at `internal/filter/schema.go:14-16`; integration in `store/db/{mysql,postgres,sqlite}/memo.go:ListMemos()`
