**Premise correction:** The webhook delivery system does not use NATS or RabbitMQ.

**Actual mechanism:** The webhook delivery workers consume from a **buffered Go channel** (`asyncPostQueue`), not an external message broker.

**Where the queue is declared:** `internal/webhook/webhook.go:39`

The implementation uses an in-process channel with a capacity of 128, and the `init()` function (lines 42-55 in `internal/webhook/webhook.go`) spawns 4 goroutine workers that continuously consume payloads from this channel and dispatch them via HTTP POST requests. If the queue becomes full, new webhook dispatches are dropped with a warning log message.
