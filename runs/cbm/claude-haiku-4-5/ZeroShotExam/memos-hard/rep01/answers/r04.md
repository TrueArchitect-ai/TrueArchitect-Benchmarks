The webhook delivery workers do not consume from either NATS or RabbitMQ. The premise correction is that neither external message broker is used. 

The actual mechanism is: The webhook system uses an in-memory Go channel queue with 4 goroutine workers. The queue is declared at `internal/webhook/webhook.go:39` as:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in the `init()` function (lines 42-54 of `internal/webhook/webhook.go`) that continuously consume from this queue and dispatch webhook payloads via HTTP POST. When `PostAsync()` is called from memo creation/update events (in `server/router/api/v1/memo_service_webhooks.go`), the payload is enqueued to this channel with a default drop behavior if the queue is full.
