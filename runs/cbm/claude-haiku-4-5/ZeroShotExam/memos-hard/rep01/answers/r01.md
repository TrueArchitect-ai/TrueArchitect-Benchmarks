**Premise Correction:** The question presumes Redis is used for the cache layer, but that is incorrect.

**Actual Mechanism:** 

The Redis connection for the cache layer is **not configured** because this repository does **not use Redis**. Instead, it uses an **in-memory cache implementation**.

**Configuration Location:** `store/store.go:38-61` (store.New function)

The cache layer is implemented with:
- **Implementation**: In-memory cache with TTL and memory management (`store/cache/cache.go`)
- **Cache instances**: Three in-memory caches are initialized in the Store struct:
  - `instanceSettingCache` 
  - `userCache`
  - `userSettingCache`

**TTL for User Entries:** **10 minutes** (600 seconds)

This is configured at `store/store.go:41` where `DefaultTTL: 10 * time.Minute` is set. User entries are cached using `s.userCache.Set(ctx, key, user)` (e.g., `store/user.go:98, 132, 143`), which applies the default TTL of 10 minutes.
