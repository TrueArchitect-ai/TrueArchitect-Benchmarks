**Premise correction:** This codebase does not use Redis for the cache layer. Instead, it implements an in-memory cache.

**Actual mechanism:** The cache layer is configured in `store/store.go:38-61`, where an in-memory cache (defined in `store/cache/cache.go`) is initialized. User entries are cached using the `userCache` field with the following TTL configuration:

- **Default TTL: 10 minutes** (configured at `store/store.go:41`)
- User entries specifically use `s.userCache.Set(ctx, userCacheKey(user.ID), user)` without a custom TTL (seen in `store/user.go:98, 122, 132, 143, 167`), which means they inherit the default 10-minute TTL from `cache.DefaultConfig()` at `store/cache/cache.go:59`
