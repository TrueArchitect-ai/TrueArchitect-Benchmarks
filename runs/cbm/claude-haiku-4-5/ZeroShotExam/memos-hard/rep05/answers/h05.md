h05. **Explicit Go code; user emoji reactions are NOT removed by database-level rules.**

**Evidence locations:**

**Mechanism:** When a user is deleted, emoji reactions created by that user are removed through **explicit Go code** in the `DeleteUser` function. Specifically:

- **store/db/mysql/user_delete.go:437-439** (MySQL implementation):
```go
func deleteReactionsByCreatorTx(ctx context.Context, tx *sql.Tx, userID int32) error {
	_, err := tx.ExecContext(ctx, `DELETE FROM reaction WHERE creator_id = `+deleteUserPlaceholder(1), userID)
	return err
}
```

This function is called from `deleteUserTargetsTx` at **line 102** of the same file:
```go
if err := deleteReactionsByCreatorTx(ctx, tx, userID); err != nil {
	return err
}
```

**Additional evidence:**

- **store/db/postgres/user_delete.go:400-403** — identical implementation for PostgreSQL
- **store/db/sqlite/user_delete.go:400-403** — identical implementation for SQLite
- **store/migration/postgres/0.20/00__reaction.sql** and **store/migration/mysql/0.20/00__reaction.sql** — the `reaction` table schema has NO foreign key constraints on `creator_id`, only a unique constraint on `(creator_id, content_id, reaction_type)`. There is no cascading delete rule.

The deletion is also handled alongside related data deletion (memo content reactions, memo shares, etc.) within the same database transaction, ensuring consistency when a user is deleted.
