**Premise correction:** The cache layer does NOT use Redis — it uses an in-memory cache implementation.

**Actual mechanism:** 

The Redis connection for a cache layer is **not configured** because this application uses an in-memory cache instead of Redis. The cache is implemented in `store/cache/cache.go` as a thread-safe, in-memory cache with TTL support.

For user entries specifically:
- **Configuration location:** `store/store.go:38-61` in the `New()` function
- **User cache instance:** `userCache` field (line 28 in `store/store.go`)
- **TTL for user entries:** `10 * time.Minute` (10 minutes) as defined in the default `cacheConfig` at line 41 of `store/store.go`

The cache is initialized with a `DefaultTTL` of 10 minutes and a cleanup interval of 5 minutes. When `GetUser()` is called (`store/user.go:148-169`), it stores user entries in the cache with the default TTL via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (line 166).
