**Mechanism: Explicit Go code**

When a user is deleted, their emoji reactions are removed by explicit Go code, not by a database-level rule.

**Evidence locations:**

1. **Explicit Go deletion code:**
   - `store/db/mysql/user_delete.go:437-440`: `deleteReactionsByCreatorTx()` executes `DELETE FROM reaction WHERE creator_id = ?` with the user ID
   - `store/db/postgres/user_delete.go:400-403`: Same implementation for PostgreSQL
   - `store/db/sqlite/user_delete.go:400-403`: Same implementation for SQLite
   - `store/db/mysql/user_delete.go:92-127`: `deleteUserTargetsTx()` calls `deleteReactionsByCreatorTx()` as part of the deletion workflow

2. **No database-level constraints:**
   - `store/migration/mysql/LATEST.sql:91-98`: Reaction table has no foreign key constraints on `creator_id`
   - `store/migration/postgres/LATEST.sql:91-98`: Reaction table has no foreign key constraints on `creator_id`
   - `store/migration/sqlite/LATEST.sql:92-99`: Reaction table has no foreign key constraints on `creator_id`

The deletion happens within a SQL transaction orchestrated by the Go code (`DeleteUser` method), which explicitly calls `deleteReactionsByCreatorTx()` to remove all reactions created by the deleted user.
