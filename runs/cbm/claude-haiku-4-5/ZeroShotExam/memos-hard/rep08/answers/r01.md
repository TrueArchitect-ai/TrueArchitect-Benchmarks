**Premise correction:** This codebase does not use Redis. The cache layer is implemented as an in-memory cache, not Redis.

**Actual mechanism:**

The Redis connection for the cache layer **does not exist** — the system uses an in-memory cache instead.

**Cache Configuration Location:** `store/store.go:38-61` (Store.New function)

**User Entry TTL:** `10 * time.Minute` (10 minutes)

The user cache is configured in `store/store.go:52` where `userCache` is initialized with the default cache configuration. The default TTL is set to 10 minutes in the `cacheConfig` struct at lines 40-45:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,  // <-- TTL for user entries
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

User cache operations are in `store/user.go`, which use this cache with the default 10-minute TTL for all user entries (see lines 98, 122, 132, 143, 167 where `s.userCache.Set()` is called). The cache implementation itself is in `store/cache/cache.go`, which provides an in-memory, thread-safe cache with automatic expiration and cleanup.
