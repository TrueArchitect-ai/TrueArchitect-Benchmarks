When a memo is deleted via `DeleteMemo` (`server/router/api/v1/memo_service.go:580`), the store layer's `Store.DeleteMemo` (`store/memo.go:140-159`) deletes the following before removing the memo row itself (via `driver.DeleteMemo`):

- **Memo relations** where the memo is the source (`DeleteMemoRelation` with `MemoID`) — `store/memo.go:142`
- **Memo relations** where the memo is the related/target memo (`DeleteMemoRelation` with `RelatedMemoID`) — `store/memo.go:145`
- **Attachments** linked to the memo (listed via `ListAttachments`, then deleted one by one with `DeleteAttachment`) — `store/memo.go:148-157`

Note: at a layer above the store (in `server/router/api/v1/memo_service.go:567-577`), the API handler also deletes any memo "comment" relations (child memos linked via `MemoRelationComment`) by calling `Store.DeleteMemo` on each comment memo before deleting the parent — but that cleanup happens in the API/router layer, not inside the store's `DeleteMemo` itself.
