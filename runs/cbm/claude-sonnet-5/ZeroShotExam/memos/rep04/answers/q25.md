**Engine + path:** A custom CEL (Common Expression Language, via `github.com/google/cel-go`) based filter engine lives at `internal/filter/` (`engine.go`, `parser.go`/`ir.go`, `schema.go`, `render.go`, `helpers.go`).

**Mechanism:** `ListMemos`'s `request.Filter` string is validated/passed as `memoFind.Filters` (`server/router/api/v1/memo_service.go:211-223`), then in each dialect's store package (e.g. `store/db/sqlite/memo.go:57-61`, and the postgres/mysql equivalents) `filter.DefaultEngine()` builds a `*filter.Engine`, which uses `cel.NewEnv`/`env.Compile` to parse the CEL expression into a CEL AST, that AST is walked by `buildCondition` (`ir.go`) into a dialect-agnostic `Condition` tree against a field `Schema` (`schema.go`), and finally `filter.AppendConditions` (`helpers.go`) calls the tree's `Render` (`render.go`), which walks the `Condition` tree and, switching on `DialectName` (`DialectSQLite`/`DialectMySQL`/`DialectPostgres`), emits dialect-specific SQL fragments and placeholder args (e.g. different `LIKE`/`ILIKE`/`REGEXP`/`~` operators, `json_each`/`jsonb_array_elements_text`/`JSON_TABLE` for tag arrays) that get appended to the `WHERE` clause.
