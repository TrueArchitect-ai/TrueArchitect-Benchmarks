When `store.Store.DeleteMemo` (`/bench/repo/store/memo.go:140-159`) runs, before deleting the memo row it deletes:

1. **Memo relations where the memo is the source** — `driver.DeleteMemoRelation(&DeleteMemoRelation{MemoID: &delete.ID})` (store/memo.go:142)
2. **Memo relations where the memo is the target/related memo** — `driver.DeleteMemoRelation(&DeleteMemoRelation{RelatedMemoID: &delete.ID})` (store/memo.go:145) — this covers things like comment relations and cross-memo references
3. **Attachments belonging to the memo** — listed via `ListAttachments(&FindAttachment{MemoID: &delete.ID})` and deleted one-by-one with `DeleteAttachment` (store/memo.go:149-157)

Only after these are removed does it call `driver.DeleteMemo(ctx, delete)` (store/memo.go:158) to delete the memo row itself.

Note: at the API layer (`server/router/api/v1/memo_service.go:565-575`), `DeleteMemo` also fetches reactions/relations for the webhook payload and separately deletes child "comment" memos (via recursive `store.DeleteMemo` calls) before deleting the target memo, but the reactions themselves are not explicitly deleted by the store layer in this code path — only relations and attachments are.
