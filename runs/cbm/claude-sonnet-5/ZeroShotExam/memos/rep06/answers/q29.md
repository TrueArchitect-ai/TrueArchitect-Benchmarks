Interceptor path: `web/src/connect.ts` (the `authInterceptor` Connect-RPC interceptor, backed by token state in `web/src/auth-state.ts`) — it attaches `Authorization: Bearer <token>` headers, does preflight-expiry refresh, and retries once on a `Code.Unauthenticated` response by calling `refreshAccessToken()`.

Token kinds it manages:
- JWT **access token** — short-lived (15 min), kept in memory + `localStorage` (`memos_access_token`/`memos_token_expires_at`), sent as `Authorization: Bearer`.
- JWT **refresh token** — long-lived (30 days), stored as an httpOnly cookie (`memos_refresh`, sent via `credentials: "include"`), used only via the `AuthService.refreshToken` RPC (never touched directly by JS).

Backend package that validates them: `server/auth` (`server/auth/token.go`, `package auth`) — defines `ParseAccessTokenV2`/`ParseRefreshToken`, JWT claim types, and constants like `RefreshTokenCookieName`. It's invoked by `server/router/api/v1/authz.go`'s `Authorizer.Authenticate`, which is the gRPC/Connect interceptor validating the `Authorization` header on incoming requests.
