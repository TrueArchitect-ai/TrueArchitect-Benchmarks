**s3presign runner — `time.Ticker` every 12 hours** (`server/runner/s3presign/runner.go:27-40`, `runnerInterval = time.Hour * 12`). It's run once immediately (`RunOnce`) and then started as a `time.NewTicker`-driven loop via `s.startBackgroundRunners()` in `Server.Start()` (`server/server.go:101-170`). This is the only background runner actually started by the server.

**Email async-send workers — event-driven, not time-scheduled**: `internal/email/email.go:16-19` spins up 2 goroutines in a package `init()` that range over a buffered channel (`asyncEmailQueue`); they fire whenever something calls `email.SendAsync` (used by `server/notification/email.go:30`), not on any timer/cron. This starts automatically on package load rather than being explicitly kicked off from `Server.Start()`.

**Unused scheduling infrastructure**: `internal/scheduler` (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`) implements a full GitHub-Actions-style cron scheduler (cron expression parsing, timezone support, middleware, graceful shutdown — see `internal/scheduler/doc.go`), but it is referenced only from its own test files (`example_test.go`, `integration_test.go`) — `grep -rln "internal/scheduler"` finds no caller in `server/` or `cmd/`. The server never instantiates or registers jobs with it.

Also note: `server/runner/memopayload` (`server/runner/memopayload/runner.go`) is not a background loop despite living under `server/runner/` — its `RebuildMemoPayload` function is called synchronously inline from request handlers in `server/router/api/v1/memo_service.go:108,447`, not scheduled or started in `startBackgroundRunners`.
