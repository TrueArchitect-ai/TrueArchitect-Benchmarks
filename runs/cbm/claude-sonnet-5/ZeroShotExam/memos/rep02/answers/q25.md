**Engine + path:** CEL (Common Expression Language, `github.com/google/cel-go`), wrapped by a custom filter engine in `internal/filter/` (`engine.go`, `schema.go`, `parser.go`/`ir.go`, `render.go`).

**Mechanism:** `request.Filter` on `ListMemos` is first syntax/semantic-validated with a CEL `cel.Env` (`validateFilter` in `server/router/api/v1/shortcut_service.go` → schema built in `internal/filter/schema.go`) and then, per dialect store call (e.g. `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, `store/db/mysql/memo.go`), `filter.DefaultEngine().CompileToStatement(ctx, filterStr, filter.RenderOptions{Dialect: ...})` compiles the CEL AST into a dialect-agnostic `Condition` tree (`internal/filter/engine.go` + `ir.go`) which `render.go`'s `renderer` walks to emit dialect-specific SQL fragments/args (switching on `DialectSQLite`/`DialectMySQL`/`DialectPostgres` for things like timestamp extraction, string length, and regex operators).
