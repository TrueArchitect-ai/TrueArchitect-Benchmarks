Engine: Google's CEL (Common Expression Language), via the `cel-go` library, wrapped in a custom package at `internal/filter/` (`engine.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`).

Mechanism: `ListMemos` (server/router/api/v1/memo_service.go:178-223) passes `request.Filter` through `validateFilter`/into `memoFind.Filters`; each dialect-specific store implementation (`store/db/{sqlite,postgres,mysql}/memo.go`) then calls `filter.DefaultEngine()` to get a CEL `*Engine` (`internal/filter/engine.go`) which compiles the filter string into a CEL AST and lowers it into a dialect-agnostic `Condition` tree (`internal/filter/ir.go`), and `filter.AppendConditions` (`internal/filter/helpers.go`) renders that tree via `internal/filter/render.go`'s `renderer`, which walks the condition tree and emits dialect-specific SQL fragments/placeholders (e.g. `?` for SQLite/MySQL vs `$N` for Postgres, and dialect-specific functions like `UNIX_TIMESTAMP`/string concat operators defined in `internal/filter/schema.go`) plus bound args that get appended to the query's `WHERE` clause.
