When `Store.DeleteMemo` (store/memo.go:140-159) runs, before deleting the memo row via `driver.DeleteMemo`, it deletes:

- **Memo relation records** (`memo_relation` table) — via two calls to `driver.DeleteMemoRelation`, once matching where the memo is the source (`MemoID`) and once where it's the target (`RelatedMemoID`) (store/memo.go:142-147, store/memo_relation.go:51)
- **Attachment records** linked to the memo — fetched via `ListAttachments` and deleted one-by-one via `DeleteAttachment` (store/memo.go:149-157)

Additionally, at the API layer (server/router/api/v1/memo_service.go:566-577), before calling `Store.DeleteMemo` on the memo itself, the handler first deletes any **comment memos** (memos related via a `MemoRelationComment` relation) by recursively calling `Store.DeleteMemo` on each comment's ID — which in turn triggers the same relation/attachment cleanup for each comment.
