s3presign runner (`server/runner/s3presign/runner.go`) — trigger: `Server.startBackgroundRunners` (`server/server.go:153-174`), called from `Server.Start` (`server/server.go:129`). It runs once immediately (`s3presignRunner.RunOnce(ctx)`, `server.go:163`) then loops on a `time.NewTicker(12 * time.Hour)` inside `Runner.Run` (`server/runner/s3presign/runner.go:27-41`), re-presigning soon-to-expire S3 attachment URLs, until the runner's context is cancelled on shutdown.

That is the **only** background/scheduled runner the server actually starts — `startBackgroundRunners` wires up nothing else.

Unused scheduling infrastructure:
- `internal/scheduler` (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, `middleware.go`) is a full cron-expression job scheduler ("GitHub Actions-inspired", per `internal/scheduler/doc.go`) with timezone support, middleware, graceful shutdown, etc. It is never imported outside its own tests/examples (`grep` for `internal/scheduler"` across the repo only matches `_test.go` files) — it is dead/unused infrastructure, not wired into `server.go` or `cmd/memos/main.go` at all.
- `server/runner/memopayload` (`server/runner/memopayload/runner.go`) defines a `Runner` type with `NewRunner`/`RunOnce` meant to batch-rebuild all memo payloads, but that `Runner`/`RunOnce` is never constructed or called anywhere in the server. Only the package's standalone `RebuildMemoPayload` helper function is used, and only synchronously inside request handlers in `server/router/api/v1/memo_service.go:108,447` (on memo create/update) — not as a background/scheduled job.

Other periodic-looking constructs found are not scheduled background workers: the SSE heartbeat ticker (`server/router/api/v1/sse_handler.go`) is per-connection keep-alive, not a server-level runner; the PAT-last-used update (`server/auth/authenticator.go:180`) and webhook `PostAsync` (`internal/webhook/webhook.go:184`) are one-shot fire-and-forget goroutines triggered per-request, not recurring/scheduled runners.
