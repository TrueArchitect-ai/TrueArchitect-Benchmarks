**Engine + path**: Google's CEL (Common Expression Language, `github.com/google/cel-go/cel`), wrapped by a custom filter package at `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`).

**Mechanism**: `ListMemos` (`server/router/api/v1/memo_service.go:211-216`) validates `request.Filter` via `s.validateFilter` (`server/router/api/v1/shortcut_service.go:336`), which calls `filter.DefaultEngine()` and `engine.CompileToStatement` — `Engine.Compile` (`internal/filter/engine.go:48`) uses `cel.Env.Compile` to produce a CEL AST, then `buildCondition` (`internal/filter/parser.go`) walks the parsed CEL expression against a `Schema` (`internal/filter/schema.go`, mapping fields like `creator_id`, `visibility`, `tag`, etc. to columns) into a dialect-agnostic `Condition` IR tree (`internal/filter/ir.go`); at query time the store layer (e.g. `store/db/sqlite/memo.go:57-61`, and the mysql/postgres equivalents) calls `filter.AppendConditions`, which invokes `Program.Render(RenderOptions{Dialect: ...})` — implemented in `internal/filter/render.go` — to walk the IR and emit dialect-specific SQL fragments and placeholder args (handling differences like SQLite/MySQL/Postgres string functions, `?` vs `$N` placeholders, JSON/array operators, etc.), which are appended to the `WHERE` clause.
