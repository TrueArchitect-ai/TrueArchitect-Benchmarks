Engine: **CEL (Common Expression Language)**, via the `github.com/google/cel-go` library, wrapped in the project's own `internal/filter` package (`/bench/repo/internal/filter/engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

Mechanism: `APIV1Service.ListMemos` (`server/router/api/v1/memo_service.go:211-215`) takes `request.Filter` and calls `validateFilter`, which gets the process-wide `filter.DefaultEngine()` (`server/router/api/v1/shortcut_service.go:336-359`, engine built in `internal/filter/engine.go:24-34`); the engine's `Compile` method (`internal/filter/engine.go:48-71`) uses `cel.Env.Compile` to parse the CEL expression into an AST and then walks that AST (`buildCondition` in `internal/filter/ir.go`/`parser.go`) into a dialect-agnostic `Condition` tree, which `Program.Render` (`internal/filter/render.go`) then translates into dialect-specific SQL fragments + args by switching on `filter.DialectName` (`DialectSQLite`, `DialectMySQL`, `DialectPostgres`) at each render step (comparisons, IN-lists, regex/LIKE, JSON/tag handling, timestamp accessors, etc.).
