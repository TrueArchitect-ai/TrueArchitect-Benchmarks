q29. Frontend API requests are authenticated via a Connect-RPC interceptor (`authInterceptor`) defined in `web/src/connect.ts:156`, which attaches `Authorization: Bearer <token>` to every request and reactively refreshes on a 401 (`Code.Unauthenticated`). It manages a short-lived **JWT access token** (kept in memory + `localStorage`, managed in `web/src/auth-state.ts`) and an httpOnly **refresh token** cookie (sent via `credentials: "include"` to `AuthService.refreshToken`, see `refreshAccessToken`/`doRefreshAccessToken` in `web/src/connect.ts:74-91`). Backend validation of these tokens (JWT access tokens and Personal Access Tokens) is done by the `Authenticator` type in the Go package `server/auth` (`server/auth/authenticator.go`, `server/auth/token.go`), used consistently by the gRPC interceptor, Connect interceptor, and file server.

Answer format: `web/src/connect.ts` (authInterceptor, backed by token state in `web/src/auth-state.ts`); JWT access token (short-lived, ~15 min) + refresh token (httpOnly cookie) + Personal Access Tokens (PAT) for programmatic access; `server/auth` (Go package, see `server/auth/authenticator.go`)
