**Engine + path:** A custom CEL (Common Expression Language, via `github.com/google/cel-go`) based filter engine lives in `/bench/repo/internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`, `helpers.go`).

**Mechanism:** `ListMemos` (`server/router/api/v1/memo_service.go:211-216`) validates `request.Filter` and appends it to `store.FindMemo.Filters`; each store driver (`store/db/{sqlite,mysql,postgres}/memo.go`) then calls `filter.AppendConditions`, which uses the shared `*filter.Engine` (`internal/filter/engine.go`) to `cel.Env.Compile` the expression into a CEL AST, walks it via `buildCondition` into a dialect-agnostic `Condition`/IR tree (`internal/filter/ir.go`), and finally `Program.Render` (`internal/filter/render.go`) walks that IR to emit dialect-specific SQL fragments and placeholder args (e.g. `?` vs `$N`, `UNIX_TIMESTAMP()` for MySQL vs raw epoch columns for SQLite/Postgres, native `REGEXP` vs SQLite's registered `regexp()` function, Postgres JSON operators, etc.), keyed off the `DialectName` (`sqlite`/`mysql`/`postgres`) passed in by each driver.
