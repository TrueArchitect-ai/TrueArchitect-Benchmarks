q16. Based on `store/memo.go` (`Store.DeleteMemo`, `/bench/repo/store/memo.go:140-158`), the store layer deletes these records before deleting the memo row itself:

- **Memo relations** — deletes `memo_relation` rows where this memo is the source (`DeleteMemoRelation{MemoID: &delete.ID}`) and where it is the target/related memo (`DeleteMemoRelation{RelatedMemoID: &delete.ID}`) (`store/memo.go:142-147`).
- **Attachments** — lists all attachments linked to the memo (`ListAttachments`) and deletes each one via `DeleteAttachment` (which also removes the underlying attachment storage/blob) (`store/memo.go:148-157`, `store/attachment.go:132-149`).

Only after these are removed does it call `s.driver.DeleteMemo(ctx, delete)` to delete the memo row itself (`store/memo.go:158`, e.g. `store/db/sqlite/memo.go:237-248`).

Note: the API handler (`server/router/api/v1/memo_service.go:566-577`) additionally deletes any *comment* memos (memos related via a `MemoRelationComment` relation) by recursively calling `Store.DeleteMemo` on each — but that cleanup happens in the router/service layer, not inside the store layer's `DeleteMemo` itself. Reactions on the memo are read (for the webhook payload) but are not explicitly deleted by the store layer in this code path.
