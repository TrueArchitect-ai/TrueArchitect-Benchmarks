Premise correction: neither. This repository (usememos/memos) has no NATS or RabbitMQ integration anywhere in the codebase (no `nats`, `amqp`, or `rabbitmq` dependencies/imports exist in the Go code).

Actual mechanism: Webhook delivery is handled entirely in-process using a buffered Go channel as an in-memory work queue. The "queue" is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

It's consumed by 4 worker goroutines spawned in the package's `init()` function (`internal/webhook/webhook.go:42-55`), which range over `asyncPostQueue` and call `Post()` for each payload. Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send and drops (with a warning log) if the channel is full — there's no external broker, persistence, or cross-process delivery involved.
