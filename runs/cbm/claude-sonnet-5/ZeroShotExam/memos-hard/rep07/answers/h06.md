Each of these builds a `webhook.WebhookRequestPayload` whose `URL` comes from a user's stored webhook (`store.GetUserWebhooks`, URL originally supplied and validated in `CreateUserWebhook`/`UpdateUserWebhook`, server/router/api/v1/user_service_webhooks.go), then calls `webhook.PostAsync` (internal/webhook/webhook.go:184), which enqueues onto `asyncPostQueue`; four background workers (spawned in `init()`, internal/webhook/webhook.go) drain that queue and all call the same delivery function.

Convergence function — `Post` at `internal/webhook/webhook.go:119` (constructs the HTTP request and executes it via the shared SSRF-guarded `safeClient.Do`, internal/webhook/webhook.go:151).

Note: other, separate outbound-HTTP paths exist in this codebase (e.g. `httpgetter.GetHTMLMeta` for link-preview metadata used by `CreateMemo`/`UpdateMemo`, and OAuth `UserInfoUrl` fetches in `internal/idp/oauth2/oauth2.go` used by SSO sign-in handlers) — these use their own separate client/dial logic and do **not** converge into `webhook.Post`; only the memo/comment webhook-dispatch paths above share that single convergence point.
