h14.

**Computation site:** `internal/markdown/markdown.go` — `service.ExtractAll()` (internal/markdown/markdown.go:356‑422), which does a single goldmark AST walk over the memo content (and its sibling `ExtractProperties()` at internal/markdown/markdown.go:192‑241, which computes just the `Property` subset). This is invoked by `RebuildMemoPayload()` in `server/runner/memopayload/runner.go:74‑88`, which writes the results into `memo.Payload.Tags` and `memo.Payload.Property` (the `storepb.MemoPayload` protobuf, defined in `proto/store/memo.proto:7‑23`, whose `Property` message is explicitly commented as "the calculated properties from the memo content").

**Triggers (recomputation call sites):**
- Memo creation — `APIV1Service.CreateMemo` calls `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` (`server/router/api/v1/memo_service.go:108`).
- Memo update, but only when the update mask includes the `content` field — `APIV1Service.UpdateMemo` calls `memopayload.RebuildMemoPayload(ctx, memo, s.MarkdownService)` inside the `path == "content"` branch (`server/router/api/v1/memo_service.go:447`), so editing visibility/pin/etc. without touching content does not recompute it.
- Bulk/background rebuild — `Runner.RunOnce` (`server/runner/memopayload/runner.go:27‑72`) batches through all memos via `Store.ListMemos` and calls `RebuildMemoPayload` + `Store.UpdateMemo` for each; this reusable batch job exists in the codebase but is not currently wired into server startup or any scheduler/CLI entry point in this repo state — the only live triggers are the create/update-content paths above.

**Extracted properties** (from the AST walk, populated onto `storepb.MemoPayload_Property` and `Tags`):
- `has_link` — set when a `Link` node is encountered.
- `has_code` — set when a `CodeBlock`, `FencedCodeBlock`, or `CodeSpan` node is encountered.
- `has_task_list` — set when a `TaskCheckBox` node is encountered.
- `has_incomplete_tasks` — set when a `TaskCheckBox` node is unchecked.
- `title` — text of the first H1 heading, only if it's the very first block-level child of the document.
- `tags` (on `MemoPayload`, not `Property`) — all `#tag` mention nodes collected during the same walk, deduplicated case-preserving.
- (`ExtractAll` also collects `@mentions` in the same pass, but those aren't persisted to `Payload` — they're used separately by `resolveMentionTargets` in `server/router/api/v1/memo_mention_helpers.go:26‑54` for notification fan-out, not stored as memo metadata.)
