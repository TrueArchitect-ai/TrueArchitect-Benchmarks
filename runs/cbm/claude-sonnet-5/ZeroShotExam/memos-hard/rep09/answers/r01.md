Premise correction: there is no Redis connection or Redis-backed cache layer in this repository — I searched for `redis` across the entire codebase (Go backend, proto files, and web frontend) and found zero matches.

Actual mechanism: caching here is done client-side in the React app, not via Redis:
- `/bench/repo/web/src/components/MemoEditor/services/cacheService.ts` — an in-browser draft cache for the memo editor (keyed by memo, stored client-side, no server round-trip).
- `/bench/repo/web/src/lib/query-client.ts` — the TanStack Query client instance, which provides in-memory query caching for API responses in the browser.

Neither of these is a "user entries" cache with a Redis-style TTL — TanStack Query has its own `staleTime`/`gcTime` config (worth checking `query-client.ts` directly if you need those values), but there's no server-side Redis cache or TTL for user records. If you're looking for a specific TTL on user data, it doesn't exist in this codebase as of the current `main` branch (commit `2d01420`).
