**Premise correction:** Neither — this codebase (usememos/memos) doesn't use NATS or RabbitMQ for webhook delivery. There's no external message broker involved at all.

**Actual mechanism:** Webhook dispatch uses an in-process, in-memory Go channel as the queue. In `/bench/repo/internal/webhook/webhook.go`:

- The "queue" is declared as a buffered Go channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (webhook.go:37)
- A pool of 4 goroutines is spun up in `init()` to consume from it: `for range 4 { go func() { for payload := range asyncPostQueue { ... Post(payload) ... } }() }` (webhook.go:39-49)
- Each worker calls `Post(payload)` to actually deliver the HTTP webhook, with SSRF protections applied via `safeClient`/`safeDialContext`.

So delivery is handled entirely within the single Go process's memory — there is no NATS or RabbitMQ dependency, and consequently no external queue/exchange declaration to point to (it's just a Go `chan` literal in code).
