**Premise correction:** There is no Redis in this repository — this is the Memos codebase (Go backend + React frontend), and there is no Redis client, connection string, or dependency anywhere in `go.mod`/`go.sum`. The "cache" hits in the frontend (`web/src/...`) are unrelated React Query/localStorage caching, not Redis.

**Actual mechanism:** The cache layer is an in-process, in-memory Go cache (`sync.Map`-based, no external service) implemented in `store/cache/cache.go:66-90`. It's instantiated per-store in `store/store.go:40-53`, where `userCache` (and `userSettingCache`, `instanceSettingCache`) are created via `cache.New(cacheConfig)`.

The TTL for user entries comes from the shared `cacheConfig` defined at `store/store.go:40-43`:
```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
}
```
So user cache entries expire after **10 minutes** (`DefaultTTL`), with a background sweep every 5 minutes (`CleanupInterval`) and a 1000-item cap per cache, enforced in `SetWithTTL`/`cleanupOldest` (`store/cache/cache.go:97-120`, `252-313`). Usage of the user cache specifically is in `store/user.go:151`.
