This is the `usememos/memos` repo. Memo visibility enforcement is duplicated (independently reimplemented, not a single shared middleware) across several distinct server surfaces:

h15.
enforcement site — server/router/api/v1/memo_service.go (`checkMemoReadAccess`, lines 39-68; used by `GetMemo`/`ListMemos` and reused by comments)
enforcement site — server/router/api/v1/memo_service_comments.go (`ListMemoComments` at line 148 calls the same check, gating comment visibility on memo visibility)
enforcement site — server/router/api/v1/attachment_service.go (`checkAttachmentAccess`, lines 419-454, an independent reimplementation for the attachment gRPC service)
enforcement site — server/router/api/v1/memo_attachment_service.go (`ListMemoAttachments`, lines 213-225, another independent inline reimplementation)
enforcement site — server/router/api/v1/reaction_service.go (`ListMemoReactions` lines 29-41 and `UpsertMemoReaction` line 83, its own reimplementation gating reaction visibility)
enforcement site — server/router/fileserver/fileserver.go (`checkAttachmentPermission`, lines 650-704, HTTP file-serving layer with its own logic plus a share-token bypass)
enforcement site — server/router/rss/rss.go (lines 90, 141 — hard-filters `VisibilityList` to `Public` only, since RSS has no per-request auth)
enforcement site — server/router/frontend/frontend.go (`getSitemapXML`, line 150 — hard-filters `VisibilityList` to `Public` only for sitemap generation)

Note: `store.Visibility` (Public/Protected/Private) is the shared enum, but there is no single shared "can this user view this memo" function — each surface above independently duplicates the `Private → creator/admin only` / `Protected → authenticated only` logic, so a fix to one does not automatically fix the others.
