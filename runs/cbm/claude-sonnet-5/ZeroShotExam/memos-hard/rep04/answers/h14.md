**Computation site:** `RebuildMemoPayload()` in `server/runner/memopayload/runner.go:78-91`, which delegates the actual extraction to `(*service).ExtractAll()` in `internal/markdown/markdown.go:355-422` (a single goldmark AST walk over `memo.Content`).

**Triggers:**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` calls `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` unconditionally when a memo is created.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, only when the update mask includes the `content` path (i.e. the memo's content is actually being changed); other field updates (visibility, pinned, state, location, etc.) don't recompute it.
- A batch backfill path exists — `Runner.RunOnce()` in `server/runner/memopayload/runner.go:28-73` pages through all memos via `ListMemos` and calls `RebuildMemoPayload` + `UpdateMemo` for each — but this runner is not currently wired into server startup or any scheduler/cron (no call site for `memopayload.NewRunner`/`RunOnce` outside its own package), so in practice it's unused/available for manual invocation only.

**Extracted properties** (stored on `memo.Payload`, `storepb.MemoPayload`, fields defined in `proto/gen/store/memo.pb.go`):
- `Tags []string` — from `#tag` AST nodes (`internal/markdown/markdown.go:376-378`), deduplicated case-preserving.
- `Property.HasLink` — set when a `Link` AST node is found (`markdown.go:393-394`).
- `Property.HasCode` — set on `CodeBlock`/`FencedCodeBlock`/`CodeSpan` nodes (`markdown.go:396-397`).
- `Property.HasTaskList` / `Property.HasIncompleteTasks` — set on `TaskCheckBox` nodes, the latter when any checkbox is unchecked (`markdown.go:399-405`).
- `Property.Title` — text of the first block-level child if it's an H1 heading (`markdown.go:383-389`).

(Note: `ExtractAll` also computes `Mentions`, but `RebuildMemoPayload` only assigns `data.Tags` and `data.Property` to the stored payload — mentions are extracted separately elsewhere, e.g. `memo_mention_helpers.go`.)
