**RPC handlers that can transitively trigger an outbound HTTP request to a user-configured webhook URL** (all in `server/router/api/v1/`):

2. `APIV1Service.UpdateMemo` (`memo_service.go:401`) → calls `dispatchMemoUpdatedSideEffects` (`memo_service.go:513`, defined `memo_update_helpers.go:66`) → `DispatchMemoUpdatedWebhook` (`memo_update_helpers.go:67`)
3. `APIV1Service.DeleteMemo` (`memo_service.go:518`) → calls `DispatchMemoDeletedWebhook` (`memo_service.go:562`)
4. `APIV1Service.CreateMemoComment` (`memo_service_comments.go:20`) → calls `DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`)

Each of these `Dispatch*Webhook` functions (in `server/router/api/v1/memo_service_webhooks.go`) looks up the target user's configured webhook URLs via `s.Store.GetUserWebhooks` and calls `webhook.PostAsync(payload)`.

**Convergence function — path**: `Post` in `internal/webhook/webhook.go:120` — this is the single function that actually issues the outbound `http.Client.Do` request (via the SSRF-guarded `safeClient`) to the user-configured `payload.URL`. It's invoked either synchronously or, in all the paths above, asynchronously through `PostAsync` (`internal/webhook/webhook.go:184`), which enqueues onto `asyncPostQueue`, drained by worker goroutines that call `Post` (`internal/webhook/webhook.go:46`).
