Memo visibility is enforced independently in at least six places across the Go server:

- **API single-memo read-access check** — `server/router/api/v1/memo_service.go` (`checkMemoReadAccess`, used by `GetMemo` and parent-memo lookups)
- **API list-memos query-level filtering** — `server/router/api/v1/memo_service.go` (`ListMemos`, builds `VisibilityList`/filter expressions based on requester)
- **Memo comments access check** — `server/router/api/v1/memo_service_comments.go` (calls `checkMemoReadAccess` before returning a comment's parent memo)
- **Share-token bypass logic** — `server/router/api/v1/memo_share_service.go` (`GetMemoByShare`/`getActiveMemoShare`, grants access to non-public memos via a valid share token instead of the normal visibility check)
- **Attachment/file serving permission check** — `server/router/fileserver/fileserver.go` (`checkAttachmentPermission`, re-derives the parent memo's visibility to gate file downloads, including its own share-token fallback)
- **Realtime SSE event delivery filtering** — `server/router/api/v1/sse_hub.go` (`SSEClient.canReceive`, filters broadcast events per-connection by the event's memo visibility)
- **RSS feed** — `server/router/rss/rss.go` (hardcodes `VisibilityList: []store.Visibility{store.Public}`)
- **Sitemap generation** — `server/router/frontend/frontend.go` (`getSitemapXML`, hardcodes `VisibilityList: []store.Visibility{store.Public}`)
