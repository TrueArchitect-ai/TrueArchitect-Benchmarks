**Handlers whose paths lead to an outbound HTTP request:**

1. `CreateMemo` — `server/router/api/v1/connect_services.go:306` → `APIV1Service.CreateMemo` → `DispatchMemoCreatedWebhook` → `dispatchMemoRelatedWebhook` → `webhook.PostAsync` (`server/router/api/v1/memo_service_webhooks.go:15`, `:48`)
2. `UpdateMemo` — same chain via `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` → `dispatchMemoRelatedWebhook` → `webhook.PostAsync`
3. `DeleteMemo` — via `DispatchMemoDeletedWebhook` → `dispatchMemoRelatedWebhook` → `webhook.PostAsync`
4. `CreateMemoComment` — directly calls `DispatchMemoCommentCreatedWebhook` → `webhook.PostAsync`
5. `SetMemoAttachments` and `SetMemoRelations` — also transitively call `dispatchMemoUpdatedSideEffects` → `webhook.PostAsync`

In each case the URL comes from `s.Store.GetUserWebhooks(ctx, creatorID)` (`hook.Url`, `server/router/api/v1/memo_service_webhooks.go:56-65`) — a webhook endpoint the user configured for their account.

A second, independent family reaches the network too: `GetLinkMetadata` and `BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go:14,19`) both call `getLinkMetadata` → `fetchHTMLMeta` (= `httpgetter.GetHTMLMeta`), fetching a URL supplied directly in the request.

**Convergence function:** for the webhook family, all paths funnel through `Post` in `internal/webhook/webhook.go:120` (invoked either synchronously or via the bounded `asyncPostQueue` consumer started in `init()`, `internal/webhook/webhook.go:42-55`) — this is where the `http.NewRequest`/`safeClient.Do(req)` call actually fires. (The link-metadata family has its own separate convergence point at `httpgetter.GetHTMLMeta`, `internal/httpgetter/html_meta.go`.)
