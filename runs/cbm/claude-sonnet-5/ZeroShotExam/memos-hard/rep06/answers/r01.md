**Premise correction:** There is no Redis anywhere in this repository (this is the `usememos/memos` codebase) — a repo-wide search for "redis" turns up zero matches. The cache layer is a self-contained, in-process Go implementation, not backed by an external Redis server.

**Actual mechanism:** Caching is implemented as a thread-safe in-memory cache (`sync.Map`-based, with a background cleanup goroutine) in `/bench/repo/store/cache/cache.go`. The `Store` struct wires up three separate cache instances — including `userCache` — in `/bench/repo/store/store.go:47-58`, each constructed with the same `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

User entries are cached via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` in `/bench/repo/store/user.go` (lines 98, 122, 132, 143, 167), which uses `Cache.Set` — not `SetWithTTL` — so no custom TTL is applied. That means **user cache entries expire after the default TTL of 10 minutes**, per `DefaultTTL: 10 * time.Minute` in `store.go:41`. Expired/stale entries are swept out by a cleanup loop that runs every 5 minutes (`CleanupInterval`), and entries are also explicitly invalidated on user deletion via `s.userCache.Delete(...)` in `/bench/repo/store/user_delete.go:40`.
