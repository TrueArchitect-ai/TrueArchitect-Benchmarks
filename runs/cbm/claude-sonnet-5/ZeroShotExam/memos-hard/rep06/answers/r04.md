Premise correction: neither. Webhook delivery in this repo (usememos/memos) is not backed by NATS or RabbitMQ at all — there is no external message broker involved.

Actual mechanism: webhook dispatch uses an in-process, in-memory Go channel as the "queue." It's declared in `internal/webhook/webhook.go:39` as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, a buffered channel (capacity 128). A pool of 4 goroutines started in the `init()` function (`internal/webhook/webhook.go:42-55`) range over this channel and call `Post()` (`internal/webhook/webhook.go:120`) to deliver each payload via HTTP. `PostAsync()` (`internal/webhook/webhook.go:184-196`) enqueues into the channel with a non-blocking `select`/`default`, dropping (and logging a warning for) any webhook if the channel is full — there's no external broker, persistence, or redelivery involved.
