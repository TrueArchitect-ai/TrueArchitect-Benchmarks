Premise correction: this repo (usememos/memos) doesn't use NATS or RabbitMQ for webhook delivery — there is no external message broker at all. A repo-wide search for NATS/RabbitMQ/AMQP client libraries or config turns up nothing.

Actual mechanism: webhook dispatch uses an in-process, unbuffered-by-size Go channel as the "queue." It's declared as a package-level buffered channel `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` in `internal/webhook/webhook.go:39`. A fixed pool of 4 goroutines, spawned in that file's `init()` (`internal/webhook/webhook.go:42-54`), range over `asyncPostQueue` and call `Post(payload)` to deliver each webhook. Producers enqueue via a non-blocking send `case asyncPostQueue <- requestPayload:` at `internal/webhook/webhook.go:190`. So delivery is fully in-memory within a single process, not backed by any external broker.
