**Premise correction:** There is no Redis in this repository — this is the [usememos/memos](https://github.com/usememos/memos) Go application, and it has no Redis client, dependency, or configuration anywhere in the codebase (`go.mod`, `store/`, `server/`, `docs/` all confirmed via grep). There is no external cache backend at all.

**Actual mechanism:** The cache layer is a custom in-process, thread-safe in-memory cache backed by `sync.Map`, implemented in `store/cache/cache.go`. It's a plain Go struct (`Cache`) with its own TTL/eviction/cleanup goroutine logic — no network connection, no separate service.

- User entries specifically are cached via `userCache` (`store/store.go:28`), constructed with the store's default `cacheConfig` in `store/store.go:40-53`:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
- `store/user.go` writes to it via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. lines 98, 122, 132, 143, 167) and reads via `s.userCache.Get(...)` (line 150). `Set` always applies the cache's `DefaultTTL` (see `SetWithTTL` call inside `Set`, `store/cache/cache.go:93-95`), so **user entries expire after 10 minutes**, with a background cleanup sweep every 5 minutes (`store/cache/cache.go:200-215`) and a max of 1000 items before oldest-item eviction kicks in (`store/cache/cache.go:252-313`).
