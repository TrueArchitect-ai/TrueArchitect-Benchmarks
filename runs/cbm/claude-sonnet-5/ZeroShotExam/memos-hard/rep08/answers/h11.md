**1st: `store.User`; 2nd: `store.Memo`** (rough package counts: `User` ≈ 6-7 packages, `Memo` ≈ 4-6 packages)

The persistent entity types are defined as top-level structs in the `store` package (e.g. `store/user.go`, `store/memo.go`, `store/attachment.go`, `store/reaction.go`, `store/memo_relation.go`, `store/memo_share.go`, `store/inbox.go`, `store/idp.go`, `store/user_identity.go`, `store/user_setting.go`, `store/instance_setting.go`). Grepping for `store.<Type>` usage outside the `store/` tree itself (excluding the DB driver implementations under `store/db/*`, which are part of the data layer):

- **`store.User`** is referenced from `server/auth`, `server/notification`, `server/router/api/v1` (+ its `test` subpackage), `server/router/fileserver`, `server/router/rss`, and `server/router/frontend` (test) — the broadest reach, since user identity/auth touches nearly every subsystem.
- **`store.Memo`** is referenced from `server/notification`, `server/router/api/v1` (+ `test`), `server/router/rss`, `server/runner/memopayload`, and `server/router/frontend` (test) — the core domain entity, used by most memo-facing features.

Runner-up types are much narrower: `store.Attachment` (3 packages: `server/router/api/v1`, `server/router/fileserver`, `server/router/rss`), `store.MemoShare`/`store.Inbox` (2 packages each), and `store.Reaction`, `store.MemoRelation`, `store.UserIdentity` (1 package each, only `server/router/api/v1`).

Files consulted: `store/*.go` (type defs), and grep of `store\.<Type>\b` across `*.go` files excluding `store/`.
