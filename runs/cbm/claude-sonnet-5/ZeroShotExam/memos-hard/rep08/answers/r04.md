**Premise correction:** Neither. This repository (usememos/memos) has no NATS or RabbitMQ integration anywhere in the codebase (`grep -rli "rabbitmq\|amqp\|nats\." ` over the whole tree returns nothing).

**Actual mechanism:** Webhook delivery is not consumed from any external message broker — it's an in-process, in-memory Go channel worker pool. In `internal/webhook/webhook.go:39`, `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)`, a buffered channel (capacity 128). At `internal/webhook/webhook.go:42-55`, an `init()` function spins up 4 goroutines that range over this channel and call `Post()` (the actual HTTP dispatch, `internal/webhook/webhook.go:120`) for each payload. Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send and drops/logs a warning if the queue is full. There is no external queueing system, persistence, or broker involved — it's entirely an in-memory, single-process worker pool that does not survive process restarts.
