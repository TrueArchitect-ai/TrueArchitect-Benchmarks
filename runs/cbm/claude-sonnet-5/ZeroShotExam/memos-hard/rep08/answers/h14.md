**Computation site:** `RebuildMemoPayload` in `/bench/repo/server/runner/memopayload/runner.go:74-88`, which delegates the actual extraction to `(*service).ExtractAll` in `/bench/repo/internal/markdown/markdown.go:356-422`. `ExtractAll` does a single goldmark AST walk over the memo's markdown content and returns tags/mentions/properties, which `RebuildMemoPayload` writes into `memo.Payload.Tags` and `memo.Payload.Property` (`storepb.MemoPayload_Property`, defined in `/bench/repo/proto/gen/store/memo.pb.go:85-95`).

**Triggers (recomputation):**
- `CreateMemo` — always calls `memopayload.RebuildMemoPayload` right after building the new memo, before persisting (`/bench/repo/server/router/api/v1/memo_service.go:108`).
- `UpdateMemo` — only when the update mask includes the `content` field path; the handler sets `memo.Content` to the new value and re-derives the payload before saving (`/bench/repo/server/router/api/v1/memo_service.go:436-451`). Other update paths (visibility, pinned, state, etc.) don't touch the payload.
- A batch backfill path also exists: `Runner.RunOnce` (`/bench/repo/server/runner/memopayload/runner.go:27-72`) pages through all memos and calls `RebuildMemoPayload` on each, then persists via `Store.UpdateMemo`. (Note: in this snapshot of the codebase, this runner isn't wired into `server.go`'s scheduled runners the way e.g. `s3presignRunner` is — no call site invokes `Runner.RunOnce` currently — so the two API-triggered call sites above are the only live triggers.)

**Extracted properties** (from the single AST walk in `ExtractAll`):
- `Tags` — all `#tag` nodes (`asMemoTagNode`), deduplicated case-preserving.
- `Property.Title` — text of the first block-level H1 heading, if the document's first block is a level-1 heading (`extractHeadingText`).
- `Property.HasLink` — set on any `Link` AST node.
- `Property.HasCode` — set on any code block, fenced code block, or inline code span.
- `Property.HasTaskList` — set on any task checkbox node.
- `Property.HasIncompleteTasks` — set when a task checkbox node is unchecked.
- (`Mentions` is also collected in the same pass but not written into the payload by `RebuildMemoPayload`.)

These boolean/title properties are then consumed on the frontend for list/preview filtering (e.g. `property.hasLink`, `property.hasTaskList`, `property.hasCode` in `/bench/repo/web/src/hooks/useMemoFilters.ts:73-77` and `/bench/repo/web/src/components/MemoFilters.tsx`).
