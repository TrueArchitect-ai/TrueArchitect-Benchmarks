**Premise correction:** Neither. This repo (usememos/memos) doesn't use an external message broker (NATS or RabbitMQ) for webhook delivery at all — there's no NATS/RabbitMQ/AMQP dependency anywhere in the codebase (the only "nats"/"amqp" grep hits are false positives inside unrelated Catalan locale strings like "eliminats").

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel as a bounded queue, not a broker. In `/bench/repo/internal/webhook/webhook.go`:
- `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (line 39) declares the "queue" — a buffered Go channel with capacity 128.
- `init()` (lines 42–55) spawns 4 goroutine workers that range over `asyncPostQueue` and call `Post()` to deliver each webhook via HTTP.
- `PostAsync()` (lines 184–196) enqueues payloads with a non-blocking `select`, dropping (and logging a warning for) any webhook if the channel is full.

So delivery is entirely local to the Go process — no external broker, no persistent queue, and payloads are lost on process restart or when the channel is full.
