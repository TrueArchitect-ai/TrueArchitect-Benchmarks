**Premise correction:** There is no Redis connection in this repository — it's the "memos" application, and its cache layer is a pure in-process, in-memory cache with no external Redis dependency at all.

**Actual mechanism:** The cache is implemented in `/bench/repo/store/cache/cache.go` as a thread-safe in-memory `sync.Map`-backed store (`Cache` struct) with a background cleanup goroutine, no Redis client, socket, or connection string anywhere in the codebase.

The `Store` struct (`/bench/repo/store/store.go:23-30`) holds three separate `*cache.Cache` instances, including `userCache` for user entries. They're all constructed in `store.New()` (`/bench/repo/store/store.go:38-58`) using a shared `cache.Config`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user entries cached via `userCache.Set(...)` (e.g. `/bench/repo/store/user.go:98,122,132,143,167`) get the **10-minute default TTL**, with a background sweep every 5 minutes (`CleanupInterval`) and a cap of 1000 items per cache (`MaxItems`) before oldest-eviction kicks in.
