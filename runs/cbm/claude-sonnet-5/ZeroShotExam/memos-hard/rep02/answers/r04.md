**Premise correction:** This repository (usememos/memos) does not use NATS or RabbitMQ for webhook delivery — neither broker appears anywhere in the codebase (the only "amqp/nats/rabbitmq" hit is an unrelated string in a Catalan locale file, `web/src/locales/ca.json`).

**Actual mechanism:** Webhook delivery workers consume from an in-process Go buffered channel, not an external message broker. The queue is declared at `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post()` for each payload. Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send and drops the payload with a warning log if the channel is full — there's no persistence or external broker involved at all.
