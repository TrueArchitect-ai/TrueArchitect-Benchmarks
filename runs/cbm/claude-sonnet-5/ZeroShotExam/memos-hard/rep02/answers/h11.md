**Method:** In this repo (usememos/memos), the persistent entity types are the row structs defined in the `store` package (the data-access layer), each with a matching CRUD API on `store.Store` and per-driver implementations under `store/db/{sqlite,mysql,postgres}/`:

- `store.Memo` — `store/memo.go`
- `store.User` — `store/user.go`
- `store.Attachment` — `store/attachment.go`
- `store.Reaction` — `store/reaction.go`
- `store.Inbox` — `store/inbox.go`
- `store.MemoRelation` — `store/memo_relation.go`
- `store.MemoShare` — `store/memo_share.go`
- `store.UserIdentity` — `store/user_identity.go`
- `store.UserSetting` — `store/user_setting.go`
- `store.IdentityProvider` — `store/idp.go`
- `store.InstanceSetting` — `store/instance_setting.go`

I traced every consumer of each type's struct references and `Store.<Verb><Entity>` methods across `server/**`, `internal/**`, and `cmd/**` (grep + graph USAGE edges). Only a handful of Go packages ever touch store entities at all: `server`, `server/auth`, `server/notification`, `server/router/api/v1` (+its `test` subpkg), `server/router/fileserver`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload`, `server/runner/s3presign`.

**Results (distinct consumer packages, prod + test):**
- `Memo`: 7 — `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss`, `server/runner/memopayload` (e.g. `server/router/rss/rss.go`, `server/router/api/v1/memo_service.go`, `server/runner/memopayload/runner.go`)
- `User`: 7 — `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test`, `server/router/fileserver`, `server/router/frontend`, `server/router/rss` (e.g. `server/auth/authenticator.go`, `server/router/api/v1/auth_service.go`)
- `InstanceSetting`: 6 — adds `server` (`server/server.go`) and `server/runner/s3presign`, but not `frontend`
- `Attachment`: 5

`Memo` and `User` are tied at the package level (7 each), narrowly ahead of `InstanceSetting` (6). Breaking the tie with total reference count (non-test call/type sites): `Memo` ≈ 95 vs `User` ≈ 90, and `Memo` is the only one of the two also pulled into a dedicated background-processing package (`server/runner/memopayload`), consistent with `Memo` being the app's central domain entity (this is a memo/note-taking app) and `User` being second (referenced everywhere primarily for auth/ownership).

**Answer:** 1st: `store.Memo` (~7 packages); 2nd: `store.User` (~7 packages, essentially tied, narrowly behind by reference volume)
