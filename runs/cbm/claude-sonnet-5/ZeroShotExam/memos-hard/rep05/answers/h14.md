**Computation site:** `internal/markdown/markdown.go` — `service.ExtractAll()` (lines 356–420, with the property-extraction logic also duplicated in the standalone `ExtractProperties()`, lines 192–241). This does a single goldmark AST walk over the memo content and populates `ExtractedData{Tags, Mentions, Property}`, where `Property` is `*storepb.MemoPayload_Property`. The result is written into the memo's stored payload by `RebuildMemoPayload()` in `server/runner/memopayload/runner.go:74-88`, which sets `memo.Payload.Tags = data.Tags` and `memo.Payload.Property = data.Property` (defined in `proto/store/memo.proto:7-22` as `MemoPayload.Property`, explicitly commented "The calculated properties from the memo content").

**Triggers (recomputation):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` calls `memopayload.RebuildMemoPayload(ctx, create, s.MarkdownService)` when a memo is created.
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only when the update mask includes the `content` path (`memo_service.go:436-451`); editing other fields (visibility, pin, etc.) does not recompute it.
- A batch backfill job — `memopayload.Runner.RunOnce()` (`server/runner/memopayload/runner.go:27-72`) pages through all memos and calls `RebuildMemoPayload` + `Store.UpdateMemo` for each, for bulk/migration-style recomputation (not wired into the periodic scheduler alongside things like the S3 presign runner — it's invoked as an explicit one-off job).

**Extracted properties** (`MemoPayload.Property`, `proto/store/memo.proto:15-22`):
- `has_link` — set when a `Link` AST node is encountered
- `has_task_list` — set when a task checkbox node is encountered
- `has_incomplete_tasks` — set when a task checkbox node is unchecked
- `has_code` — set when a code block, fenced code block, or inline code span is encountered
- `title` — plain text of the first H1 heading, only if it's the very first block-level node in the document (`extractHeadingText`, `markdown.go:172-179`)
- Alongside `Property`, the same pass also derives `Tags` (from `#tag` nodes) and `Mentions` (from `@user` nodes), with `Tags` also persisted onto `memo.Payload.Tags`.

These derived fields are surfaced to the frontend as `Memo.property.hasLink/hasTaskList/hasCode` and used for memo-list filtering (`web/src/contexts/MemoFilterContext.tsx:11-13`, `web/src/components/MemoFilters.tsx:45-53`, `web/src/hooks/useMemoFilters.ts:73-77`).
