**Handlers (RPC methods on `APIV1Service`) that transitively trigger outbound HTTP requests to a user-configured URL:**

1. **`CreateMemo`** (`server/router/api/v1/memo_service.go:70`) — after creating a memo, calls `s.DispatchMemoCreatedWebhook` (`memo_service.go:157` → `server/router/api/v1/memo_service_webhooks.go:15`).
2. **`UpdateMemo`** (`server/router/api/v1/memo_service.go:401`) — calls `s.dispatchMemoUpdatedSideEffects` (`memo_service.go:513`), which calls `s.DispatchMemoUpdatedWebhook` (`memo_update_helpers.go:67`).
3. **`DeleteMemo`** (`server/router/api/v1/memo_service.go:518`) — calls `s.DispatchMemoDeletedWebhook` (`memo_service.go:562`).
4. **`CreateMemoComment`** (`server/router/api/v1/memo_service_comments.go:20`) — calls `s.DispatchMemoCommentCreatedWebhook` (`memo_service_comments.go:119`).

Each of these dispatcher methods (`memo_service_webhooks.go`) looks up the memo owner's registered webhooks via `s.Store.GetUserWebhooks` (URLs configured by the user in their account settings) and calls `webhook.PostAsync(payload)`, which enqueues onto `asyncPostQueue` and is drained by worker goroutines that call `webhook.Post`.

**Convergence function** — `Post` in `internal/webhook/webhook.go:126` (issues the actual `safeClient.Do(req)` outbound HTTP POST to `requestPayload.URL`).

Note: a separate, unrelated convergence point also exists for link-preview functionality — `GetLinkMetadata`/`BatchGetLinkMetadata` (`server/router/api/v1/memo_service_link_metadata.go`) fetch arbitrary user-supplied URLs via `fetchHTMLMeta` → `httpgetter.GetHTMLMeta` (`internal/httpgetter/html_meta.go:136`), but this is a distinct code path from the webhook system and does not share the same convergence function.
