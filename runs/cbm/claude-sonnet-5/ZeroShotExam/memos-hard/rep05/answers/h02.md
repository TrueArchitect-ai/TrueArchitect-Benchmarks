- **Delivery function** — `Post` in `internal/webhook/webhook.go:120` (invoked synchronously, or asynchronously via `PostAsync`/the `asyncPostQueue` workers at `internal/webhook/webhook.go:184` and `internal/webhook/webhook.go:42-55`). It builds the HTTP request and sends it using `safeClient` (`internal/webhook/webhook.go:32`).
- **Protection mechanism** — SSRF protection is enforced at dial time by `safeDialContext` in `internal/webhook/webhook.go:59`, which is wired into `safeClient`'s `http.Transport.DialContext` (`internal/webhook/webhook.go:32-37`). It resolves the hostname and rejects any resolved IP that `isReservedIP` (`internal/webhook/validate.go:44`) flags as loopback/RFC-1918/link-local (incl. cloud metadata `169.254.169.254`) or the IPv6 equivalents, per `reservedCIDRs` (`internal/webhook/validate.go:14-23`). Dialing on the resolved IP (rather than re-resolving after an earlier check) is what closes the DNS-rebinding gap. There's also an upfront `ValidateURL` check (`internal/webhook/validate.go:62`) used when webhook URLs are registered, but the dial-time guard in `safeDialContext` is the one that actually protects every outbound delivery. Note `AllowPrivateIPs` (`internal/webhook/validate.go:41`) is a config flag that can disable this protection for self-hosted deployments needing local-network webhooks.
