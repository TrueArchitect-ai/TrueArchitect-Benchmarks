q26. memo, memo_relation, attachment, memo_share

- `memo` — deleted directly by `store.DeleteMemo`/`DB.DeleteMemo` (store/db/sqlite/memo.go:237-247).
- `memo_relation` — explicitly deleted (as source and target) by `Store.DeleteMemo` before deleting the memo (store/memo.go:142-147).
- `attachment` — explicitly deleted per-memo via `Store.DeleteAttachment` loop in `Store.DeleteMemo` (store/memo.go:149-157).
- `memo_share` — has `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (store/migration/sqlite/LATEST.sql:109), so it cascades automatically at the DB level when the memo row is deleted.

Note: `reaction` rows referencing the memo (by `content_id`) are not deleted by `DeleteMemo` — there's no FK cascade and no explicit delete call in the code I found, so they can be orphaned.
