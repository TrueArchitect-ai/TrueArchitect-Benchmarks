q16. memo_relation records (both as source and target memo), attachments linked to the memo, and comment memos (which themselves recursively trigger relation/attachment cleanup)

Details:
- `store.Store.DeleteMemo` (store/memo.go:140-159) first deletes `memo_relation` rows where the memo is the source (`MemoID`) or target (`RelatedMemoID`), then deletes all `attachment` rows linked to the memo, before deleting the memo row itself.
- The API handler `APIV1Service.DeleteMemo` (server/router/api/v1/memo_service.go:518-582) additionally deletes comment memos (memos related via `MemoRelationComment`) before deleting the target memo — each comment deletion recursively triggers the same relation/attachment cleanup.
