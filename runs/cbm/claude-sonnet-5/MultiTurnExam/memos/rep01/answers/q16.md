No cascade FK on reaction; it's not deleted by store.DeleteMemo. So the answer based on actual store-layer deletes: memo_relation records and attachments (and, at the handler level, comment memos via nested DeleteMemo calls, which recursively delete their own relations/attachments).

q16.
Before deleting the memo row itself, `Store.DeleteMemo` (`store/memo.go:140-158`) deletes:
1. **`memo_relation`** records where the memo is the source (`MemoID`) — `store/memo.go:142`
2. **`memo_relation`** records where the memo is the target (`RelatedMemoID`) — `store/memo.go:145`
3. **`attachment`** records linked to the memo (via `ListAttachments` + `DeleteAttachment` for each) — `store/memo.go:149-157`

Additionally, at the handler level (`server/router/api/v1/memo_service.go:567-577`, `APIV1Service.DeleteMemo`), comment memos (records in `memo_relation` of type `COMMENT` pointing to this memo) are deleted first via recursive `Store.DeleteMemo` calls before the main memo is deleted.

Note: reactions are listed for webhook payload purposes (`memo_service.go:545`) but are **not** deleted by the store layer — the `reaction` table has no explicit cleanup call or DB-level cascade tied to memo deletion.
