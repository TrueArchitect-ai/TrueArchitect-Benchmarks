**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search (`grep -rli "redis"`) turns up zero hits, and there's no Redis client dependency in `go.mod`. The cache layer is not backed by an external cache server at all.

**Actual mechanism:** The cache is an in-process, in-memory implementation at `store/cache/cache.go` (`Cache` struct backed by a Go map/`item` type with a background cleanup goroutine, `store/cache/cache.go:34-59`). The `Store` constructs three separate instances of it — `instanceSettingCache`, `userCache`, `userSettingCache` — in `store/store.go:37-58`, all sharing the same `cacheConfig`. The user entry cache (`userCache`) uses `DefaultTTL: 10 * time.Minute` (`store/store.go:41`, with `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000`); that TTL is applied per entry via `Cache.Set` → `SetWithTTL(ctx, key, value, c.config.DefaultTTL)` (`store/cache/cache.go:94`).
