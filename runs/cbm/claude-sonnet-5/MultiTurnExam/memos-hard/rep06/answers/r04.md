**Premise correction:** Neither. There is no message broker involved — no NATS, no RabbitMQ, no AMQP client anywhere in `go.mod` or the source (a repo-wide search for these terms returns zero hits).

**Actual mechanism:** Webhook delivery uses an in-process, buffered Go channel as the "queue." It's declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post` for each payload. `PostAsync` (`internal/webhook/webhook.go:184-196`) enqueues onto it with a non-blocking `select`/`default`, dropping (and logging) the payload if the channel's buffer of 128 is full. This is entirely local to the server process — no external broker, persistence, or cross-process queue exists.
