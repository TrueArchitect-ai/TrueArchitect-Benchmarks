**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`. It calls `markdownService.ExtractAll([]byte(memo.Content))` — the `Service.ExtractAll` implementation lives at `internal/markdown/markdown.go:356` and internally single-pass-parses the content, delegating to `ExtractTags` (tags), the mention parser, and `ExtractProperties` (`internal/markdown/markdown.go:193-241`) — then assigns the results onto `memo.Payload.Tags` and `memo.Payload.Property` (`server/runner/memopayload/runner.go:85-86`).

**Triggers (recomputation):**
- `CreateMemo` — every new memo, at `server/router/api/v1/memo_service.go:108`.
- `UpdateMemo` — only when the update mask includes the `content` path, at `server/router/api/v1/memo_service.go:447` (inside the `if path == "content"` branch, `memo_service.go:436-449`), so editing visibility/pinned/etc. alone does not recompute it.

**Extracted properties** (via `ExtractedData` / `MemoPayload_Property`, `internal/markdown/markdown.go:20-25` and proto `storepb.MemoPayload_Property`):
- `Tags` — `#tag` occurrences (`ExtractTags`).
- `Property.Title` — text of a leading H1 heading, if the first block is one.
- `Property.HasLink` — set when a Markdown link node is present.
- `Property.HasCode` — set on code blocks/fenced code blocks/inline code spans.
- `Property.HasTaskList` / `Property.HasIncompleteTasks` — set from task-list checkboxes, with the latter true if any checkbox is unchecked.

(Mentions are also extracted by `ExtractAll` into `ExtractedData.Mentions`, but `RebuildMemoPayload` does not persist that field onto `memo.Payload` — mention notifications are handled separately, e.g. via `server/router/api/v1/memo_mention_helpers.go`.)
