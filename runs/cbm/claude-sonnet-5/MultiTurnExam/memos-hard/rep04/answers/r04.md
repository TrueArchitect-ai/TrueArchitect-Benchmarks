**Premise correction:** Neither. There is no message broker (NATS, RabbitMQ, or otherwise) in this codebase — a search for `nats`/`rabbitmq`/`amqp` across the repo turns up nothing, and I confirmed this directly while tracing webhook delivery for earlier questions.

**Actual mechanism:** Webhook dispatch uses a bounded in-process Go channel, not an external broker. It's declared as `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` in `internal/webhook/webhook.go:39`. Four worker goroutines are spawned in `init()` (`internal/webhook/webhook.go:42-55`) to drain it, calling `Post` (`internal/webhook/webhook.go:120`) for each item. `PostAsync` (`internal/webhook/webhook.go:184-196`) enqueues onto this channel with a non-blocking `select`/`default` — if the channel is full, the payload is dropped and a warning is logged, rather than backpressuring a broker. Everything is in-memory within the single server process; there's no persistent queue, no cross-process consumer, and no durability across restarts.
