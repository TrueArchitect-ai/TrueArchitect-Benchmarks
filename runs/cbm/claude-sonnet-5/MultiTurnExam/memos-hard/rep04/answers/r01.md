**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search (`grep -rli redis`) turns up zero matches. The cache layer is a pure in-process, in-memory cache, not a Redis client.

**Actual mechanism:** The cache is implemented by `cache.Cache` in `store/cache/cache.go` (a `sync`-guarded in-memory map with TTL expiration and periodic cleanup, `store/cache/cache.go:34-60`). The user cache specifically is `Store.userCache`, declared at `store/store.go:28` and constructed in `store.New` at `store/store.go:52` (`cache.New(cacheConfig)`), using the shared default config defined at `store/store.go:40-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So user cache entries expire after a **10-minute TTL**, with a background cleanup sweep every 5 minutes and a cap of 1000 items — all in-process, with no network connection or external cache service involved.
