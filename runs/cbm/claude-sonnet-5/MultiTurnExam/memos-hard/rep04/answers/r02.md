**Premise correction:** There is no per-user API rate-limiting middleware in this repository. A repo-wide search for rate-limiting/throttling code (`grep -rliE "rate.?limit|ratelimit|throttle"`) finds only a single hit: a doc comment in `internal/email/doc.go:86` listing "Rate limit email sending to prevent abuse" as an *aspirational* design note in the package documentation — there is no corresponding implementation anywhere, and it's unrelated to API request rate-limiting.

**Actual mechanism:** The server's registered middlewares are limited to CORS handling (`server/cors.go`) and frontend-serving middleware (`server/router/frontend/frontend.go`). Authentication/authorization is enforced per-request (see the `Authorizer` in `server/router/api/v1/v1.go`), but no component tracks or caps request counts per user, IP, or token. If rate limiting is needed, it would have to be added (e.g., as new Echo/Connect middleware) or handled by an external reverse proxy — it isn't present in the app today.
