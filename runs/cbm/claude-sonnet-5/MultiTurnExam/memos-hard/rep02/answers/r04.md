**Premise correction:** Neither. This codebase (usememos/memos) has no message broker at all — I searched for "NATS", "RabbitMQ", "amqp", and "nats.go"/"streadway" style imports across all Go files and `go.mod`/`go.sum`, and there are zero matches. No queue is declared anywhere.

**Actual mechanism:** Webhook delivery workers consume from an in-process, in-memory Go channel, not any external broker. It's defined in `internal/webhook/webhook.go`:
- `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39` — a bounded buffered channel (capacity 128).
- Four worker goroutines are started in the package's `init()` to range over that channel and call `Post` for each payload — `internal/webhook/webhook.go:42-55`.
- Producers enqueue via `PostAsync`, which does a non-blocking send (`select`/`default`) and drops (with a logged warning) if the channel is full — `internal/webhook/webhook.go:184-196`.

This is entirely intra-process; there is no persistence, no cross-process/service delivery, and no broker of any kind involved.
