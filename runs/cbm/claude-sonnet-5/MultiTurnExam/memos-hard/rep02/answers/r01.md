**Premise correction:** There is no Redis connection anywhere in this repository — I searched for "redis" (case-insensitive) across all Go and Markdown files and found zero matches. This codebase (usememos/memos) does not use Redis for caching at all.

**Actual mechanism:** The cache layer is an in-process, in-memory cache implemented in `store/cache/cache.go` (a `sync.Map`-backed `Cache` type with a background TTL-eviction goroutine, no network connection or external dependency of any kind). User entries are cached via `userCache`, constructed in `store.New` — `store/store.go:38-53` — with `cacheConfig := cache.Config{DefaultTTL: 10 * time.Minute, CleanupInterval: 5 * time.Minute, MaxItems: 1000, OnEviction: nil}` (`store/store.go:40-45`), the same config shared by `instanceSettingCache` and `userSettingCache`. So the TTL applying to user entries is **10 minutes**, with a cleanup sweep every 5 minutes (`store/cache/cache.go:56-64` shows this matches `cache.DefaultConfig()` too).
