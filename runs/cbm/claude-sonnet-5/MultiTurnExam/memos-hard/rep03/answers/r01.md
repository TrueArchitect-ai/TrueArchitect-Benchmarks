**Premise correction:** There is no Redis in this repository — a repo-wide search for `redis`/`Redis` returns zero matches. The cache layer is a pure in-process, in-memory cache (no external service, no network connection to configure).

**Actual mechanism:** The cache is implemented in `store/cache/cache.go` (a TTL map with background cleanup, `type Cache` / `type Interface`). `store.Store` holds three independent instances of it — `instanceSettingCache`, `userCache`, `userSettingCache` — all constructed in `store.New` at `store/store.go:38-61` with the same `cache.Config`, set at `store/store.go:40-45`:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
```

So `userCache` (`store/store.go:52`, populated by `(*Store).GetUser`/`ListUsers` in `store/user.go`) uses a **10-minute default TTL**, with a background sweep every 5 minutes evicting expired entries and a 1000-item cap.
