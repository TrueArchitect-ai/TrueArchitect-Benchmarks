**Premise correction:** This repository has no Redis dependency at all — no import, config flag, connection string, or client anywhere in the codebase (`grep -ri redis` across all Go files returns nothing). There is no Redis-backed cache layer to configure.

**Actual mechanism:** The cache layer is a custom in-process, in-memory cache — `store/cache/cache.go` (`type Cache struct { data sync.Map; ... }`, backed by `sync.Map` with a background TTL-eviction goroutine, no external service or network connection involved).

It's constructed and configured in `store/store.go:38-61` (`Store.New`), which builds a shared `cache.Config` and creates three separate `*cache.Cache` instances — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:27-29`).

**TTL for user entries:** The `userCache` uses the same `cacheConfig` as the others: `DefaultTTL: 10 * time.Minute`, with `CleanupInterval: 5 * time.Minute` and `MaxItems: 1000` (`store/store.go:40-45`, matching `cache.DefaultConfig()` in `store/cache/cache.go:57-64`). So user entries expire 10 minutes after being set, and a sweep runs every 5 minutes to evict expired entries (`Cache.cleanupLoop`, `store/cache/cache.go:200-215`).
