**Premise correction:** There is no nightly database-cleanup job, and no cron scheduler is actually wired up anywhere in this codebase.

The repo does contain an `internal/scheduler` package (with cron-like parsing/registration primitives, e.g. `internal/scheduler/scheduler.go`, `internal/scheduler/parser.go`), but it is never imported or used outside its own test files (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`) — `grep` for `internal/scheduler` across `server/` and `cmd/` returns nothing. No job is registered against it in production code.

The only background jobs actually wired into server startup (`server/server.go:startBackgroundRunners`) are:
- `s3presign.Runner` (`server/runner/s3presign/runner.go`) — re-presigns S3 attachment URLs, running once at startup and then on a fixed 12-hour interval (not a wall-clock time, just "every 12h since process start").
- `memopayload.Runner` — declared (`server/runner/memopayload/runner.go`) but never constructed or started anywhere in production code.

Neither performs database cleanup, and neither runs on a schedule tied to a specific time of day like "nightly."
