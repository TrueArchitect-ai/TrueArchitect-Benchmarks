**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel as its queue, not an external broker. It's declared in `internal/webhook/webhook.go:39`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

Four worker goroutines are started in that same file's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post` (`internal/webhook/webhook.go:120`) to deliver the request. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking channel send and drops (with a warning log) if the buffered queue of 128 is full — there's no persistence or cross-process delivery, it's entirely local to the running server process.
