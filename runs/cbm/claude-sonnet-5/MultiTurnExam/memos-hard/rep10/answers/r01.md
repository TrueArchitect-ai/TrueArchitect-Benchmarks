**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search for `redis` (case-insensitive) across all Go source returns zero hits. The cache layer is an in-process, in-memory cache, not a Redis-backed one.

**Actual mechanism:** The cache is `store/cache/cache.go`'s `Cache` type (implementing `cache.Interface`, `store/cache/cache.go:11-31`), a `sync`-protected in-memory map with TTL-based expiration and a background cleanup goroutine — no network connection or external service involved.

The user-entry cache (`Store.userCache`) is constructed in `Store.New` at `store/store.go:52` (`cache.New(cacheConfig)`), using the shared `cacheConfig` built at `store/store.go:40-45`. That config sets `DefaultTTL: 10 * time.Minute` — so user cache entries expire after **10 minutes** (with a 5-minute background cleanup sweep and a 1000-item cap).
