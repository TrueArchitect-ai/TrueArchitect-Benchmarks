**Premise correction:** There is no nightly database-cleanup job, and no cron-based scheduling is wired into the server at all. The repo does contain an `internal/scheduler` package (a cron-expression parser/scheduler, see `internal/scheduler/doc.go`), but a repo-wide search (`grep -rln "internal/scheduler" --include=*.go`) shows it is never imported or used outside its own package/tests — no job is ever registered against it in production code.

The only background job actually wired into server startup is the S3 presign refresh runner (`server/server.go:153-174`, `server/runner/s3presign/runner.go`), which runs once at boot and then every **12 hours** on a plain `time.Ticker` — not "nightly," not cron-scheduled, and not a database-cleanup job (it re-signs S3 attachment URLs, see r01/h01 context). The "cleanup" hits elsewhere in the codebase are unrelated: `store/attachment.go`'s `getAttachmentStorageCleanupInstanceSetting` is a helper for resolving S3 config during attachment deletion (not a scheduled job), and `store/cache/cache.go`'s `cleanupLoop` is the in-memory cache's own 5-minute expiry sweep (see r01), not a database job.
