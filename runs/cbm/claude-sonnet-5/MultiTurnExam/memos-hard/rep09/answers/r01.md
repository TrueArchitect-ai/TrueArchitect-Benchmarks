**Premise correction:** This repo does not use Redis for its cache layer. There's no Redis client, dependency, or connection configuration anywhere in the codebase — `go.mod`/`go.sum` contain no Redis import, and no config file, flag, or env var references a Redis address.

**Actual mechanism:** The cache layer is a custom in-process, in-memory cache implemented in `store/cache/cache.go` (a `sync.Map`-backed struct with a background TTL-eviction goroutine, `store/cache/cache.go:67-84,199-215`). It is instantiated directly in Go — no network connection/configuration step exists — via `store.New` at `store/store.go:37-59`, which constructs three separate `*cache.Cache` instances (`instanceSettingCache`, `userCache`, `userSettingCache`, `store/store.go:27-29`) each using a shared `cache.Config`.

**TTL for user entries:** The `userCache` uses the same default config as the others: `DefaultTTL: 10 * time.Minute` (`store/store.go:39-44`, matching `cache.DefaultConfig()` in `store/cache/cache.go:57-64`). Entries set via `Set` (not `SetWithTTL`) get this 10-minute default; `store/user.go` populates `userCache` via `s.userCache.Set(...)` (e.g. `store/user.go:132,143,167`), so user cache entries expire after 10 minutes.
