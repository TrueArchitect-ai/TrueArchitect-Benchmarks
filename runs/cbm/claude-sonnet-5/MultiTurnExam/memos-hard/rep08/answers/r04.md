**Premise correction:** neither NATS nor RabbitMQ (nor any external message broker) is used anywhere in this codebase — a repo-wide search for "nats"/"rabbitmq"/"amqp" returns no matches. Webhook delivery has no message broker at all.

**Actual mechanism:** webhook dispatch uses a simple in-process, buffered Go channel as its queue: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared in `internal/webhook/webhook.go:39`. Four worker goroutines are spawned in that package's `init()` (`internal/webhook/webhook.go:42-55`) which range over `asyncPostQueue` and call `Post` for each payload. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send and drops (with a warning log) if the channel is full — there's no persistence, no cross-process broker, and no durability beyond the process's lifetime.
