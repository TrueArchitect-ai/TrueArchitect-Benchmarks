**Distinct memo-visibility enforcement sites:**

- `checkMemoReadAccess` (single-memo read gate: private → creator-only, archived → creator-only) — `server/router/api/v1/memo_service.go:39-68`
- `ListMemos` visibility/query filtering (restricts the list query to Public for anonymous callers, Public+Protected for others viewing another user's memos) — `server/router/api/v1/memo_service.go:218-227`
- `checkAttachmentPermission` (gates attachment file downloads by the visibility of the memo the attachment belongs to, with a share-token fallback) — `server/router/fileserver/fileserver.go:650-704`
- `SSEClient.canReceive` (filters live SSE broadcast events per-connected-client based on event visibility/creator) — `server/router/api/v1/sse_hub.go:134-144`
- RSS feed query (`VisibilityList: []store.Visibility{store.Public}`, restricts syndicated feed to public memos only) — `server/router/rss/rss.go:90` and `rss.go:141`
- Frontend SSR/meta embedding query (`VisibilityList: []store.Visibility{store.Public}`, restricts server-rendered memo embedding to public memos) — `server/router/frontend/frontend.go:150`
- Reaction service inline visibility checks (separately duplicated private-memo gate, not routed through `checkMemoReadAccess`) — `server/router/api/v1/reaction_service.go:30-40` and `reaction_service.go:83`
