**Premise correction:** there is no Redis anywhere in this repository — a repo-wide search for "redis" turns up zero matches. The cache layer is not backed by an external cache service at all.

**Actual mechanism:** `store/cache/cache.go` implements a pure in-process, in-memory TTL cache (`Cache` struct with a `map` protected by locking, background cleanup goroutine, and item eviction — no network client). `Store.New` (`store/store.go:38-60`) constructs three separate in-memory caches — `instanceSettingCache`, `userCache`, `userSettingCache` — each via `cache.New(cacheConfig)` (store.go:51-53), all sharing one `cache.Config`.

**TTL for user entries:** the `userCache` uses the same default config as the others: `DefaultTTL: 10 * time.Minute` (store/store.go:41, mirrored in `cache.DefaultConfig()` at `store/cache/cache.go:57-61`), with a background cleanup sweep every `5 * time.Minute` (`CleanupInterval`, store.go:42) and a cap of `MaxItems: 1000` (store.go:43). Entries can also be set with a custom TTL via `SetWithTTL`, but user entries populated in `store/user.go` use the default `Set`/10-minute TTL.
