**Premise correction:** There is no nightly database-cleanup job, and no cron schedule for one. The repo does contain a generic cron scheduler package at `internal/scheduler/` (with `ParseCronExpression`, `Scheduler.Register`, etc.), but it is never imported or wired into the server — a repo-wide search shows `internal/scheduler` is referenced only from its own test files (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`), not from `server/`, `cmd/`, or any other production code. It's unused, dead infrastructure, not something actually scheduling jobs.

The only background maintenance work that does run is the two ticker-based runners in `server/runner/`: the S3 presign runner (`server/runner/s3presign/runner.go`, every 12 hours, per h01) and the `memopayload` rebuild runner (`server/runner/memopayload/runner.go`), and as established earlier, the `memopayload` runner is itself never invoked in production. Neither of these is a "database-cleanup" job, and neither runs on a fixed clock time ("nightly") — both use fixed-interval tickers relative to process start, not calendar-time cron scheduling. Other "cleanup" hits in the codebase (e.g. `server/router/api/v1/user_service.go:421-450`, `auth_service_sso.go:76`) are inline error-handling cleanup within request handlers, not scheduled jobs.
