**Delivery function:** `Post` (and its async wrapper `PostAsync`) in `internal/webhook/webhook.go:120-196` — this is where the outbound HTTP POST to the webhook URL is actually executed (via the package-level `safeClient.Do(req)` at `internal/webhook/webhook.go:152`).

**Protection mechanism:** SSRF protection happens at two layers, both in the `internal/webhook` package:
- `safeDialContext` (`internal/webhook/webhook.go:59-77`) is installed as the `DialContext` on `safeClient`'s `http.Transport` (`internal/webhook/webhook.go:32-37`). It resolves the target host at dial time and rejects any resolved IP that is reserved/private via `isReservedIP`, which defeats DNS-rebinding bypasses of a pre-request check.
- `ValidateURL` in `internal/webhook/validate.go:62-83` performs an upfront check (scheme + hostname resolution against `isReservedIP`) used at webhook-configuration time; the underlying `isReservedIP`/`reservedNetworks` logic (`internal/webhook/validate.go:14-54`) blocks loopback, RFC-1918 private ranges, and link-local/cloud-IMDS addresses (both IPv4 and IPv6), unless explicitly disabled via `AllowPrivateIPs`.
