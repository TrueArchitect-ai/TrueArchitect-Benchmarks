**Premise correction:** Neither. This codebase has no message broker at all — `go.mod`/`go.sum` contain no NATS or RabbitMQ (AMQP) client dependencies.

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go channel, not an external queue. In `internal/webhook/webhook.go:39`, `asyncPostQueue` is declared as `make(chan *WebhookRequestPayload, 128)` — a buffered channel, not a broker queue. Four worker goroutines are spawned in the package's `init()` (`internal/webhook/webhook.go:42-55`) that range over this channel and call `Post` for each payload. `PostAsync` (`internal/webhook/webhook.go:184-196`) enqueues onto this channel (non-blocking; drops and logs a warning if the channel is full). Everything is local to the single server process — there's no persistence, no cross-process consumer, and nothing survives a process restart.
