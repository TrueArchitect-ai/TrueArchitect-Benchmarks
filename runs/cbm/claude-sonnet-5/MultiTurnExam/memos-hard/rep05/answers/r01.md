**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search for "redis" (case-insensitive, across Go source and config files) returns zero hits. The server has no external cache dependency at all.

**Actual mechanism:** The cache layer is a self-contained, in-process, in-memory cache implemented in `store/cache/cache.go` (`type Cache struct` at `store/cache/cache.go:67`, backed by a `sync.Map` with a background `cleanupLoop` goroutine, no network connection of any kind).

The user cache (`userCache`) is constructed in `store/store.go:40-52`, using a shared `cache.Config` with `DefaultTTL: 10 * time.Minute` (`store/store.go:41`). So user entries in the cache expire after 10 minutes (`store/cache/cache.go:59` also shows this as the package's `DefaultConfig()` default, though `store.go` sets it explicitly rather than relying on that default).
