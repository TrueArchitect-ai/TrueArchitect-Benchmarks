The server's "notify external systems on content change" mechanism is its **webhook** subsystem (`internal/webhook/`), triggered when memos are created/updated/deleted.

**delivery function — path:**
`Post` — `internal/webhook/webhook.go:120` (the function that marshals the payload, builds the POST request, optionally HMAC-signs it, and actually executes the outbound call via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`). Async dispatch is enqueued through `PostAsync` (`internal/webhook/webhook.go:184`) and drained by worker goroutines started in `init` (`internal/webhook/webhook.go:42`), which each call `Post`.

**protection mechanism — path:**
An SSRF guard baked into the shared HTTP client's transport: `safeDialContext` — `internal/webhook/webhook.go:59`. At dial time it resolves the target host and rejects any address in a reserved/private range via `isReservedIP` (`internal/webhook/webhook.go:71`), which also defeats DNS-rebinding since the check happens on the actually-resolved IP. The reserved ranges (loopback, RFC-1918, link-local incl. cloud IMDS `169.254.169.254`, etc.) and the `isReservedIP` helper are defined in `internal/webhook/validate.go:12–` , and this dialer is wired into `safeClient` at `internal/webhook/webhook.go:32–37`.

There is also a second, earlier layer: URLs are validated when a webhook is configured via `ValidateWebhookURL` in `internal/webhook/validate.go:59` (rejects non-HTTP(S) schemes and hosts resolving to reserved IPs), with an `AllowPrivateIPs` escape hatch (`internal/webhook/validate.go:41`) for testing/self-hosted use. But the actual outbound-time protection that guards delivery itself is `safeDialContext`.
