**Premise correction:** There is no nightly database-cleanup cron job, so it has no scheduled run time. The premise is false on two counts.

1. **No cron job is registered anywhere.** The repo does contain a cron scheduler *library* (`internal/scheduler/`, a "GitHub Actions-inspired cron job scheduler" per `internal/scheduler/doc.go:1`, with `ParseCronExpression` in `internal/scheduler/parser.go` and a `Job` type in `internal/scheduler/job.go`). But no production code imports or uses it: a search for imports of `usememos/memos/internal/scheduler` outside the package itself returns nothing, and it has zero non-test consumers. The only references to a `"daily-cleanup"` job are illustrative examples in the package's own doc comment (`internal/scheduler/doc.go:15–18`) and the cron-syntax examples in `internal/scheduler/job.go:21` — not a registered job.

2. **No database-cleanup job exists at all.** The only actual background jobs run via `time.Ticker`, not the cron scheduler: the S3 presign runner (every 12 hours, `server/runner/s3presign/runner.go:27`, wired in `server/server.go`). Resource/relation cleanup happens inline during request handling (e.g. memo deletion cascades in `store.DeleteMemo`, referenced at `server/router/api/v1/memo_service.go:579`, and user-deletion attachment cleanup at `server/router/api/v1/user_service.go:421`), not on any nightly schedule.

So there is nothing to report a run time for — no such scheduled cleanup job is defined.
