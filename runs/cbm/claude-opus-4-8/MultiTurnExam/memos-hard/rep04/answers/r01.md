**Premise correction:** There is no Redis in this project. A repository-wide search for `redis` in Go source and `go.mod` returns nothing — the cache layer is **not** backed by Redis and there is no Redis connection to configure. The cache is an in-process, in-memory implementation.

**Actual mechanism:**
- The cache is a thread-safe in-memory `Cache` (backed by a `sync.Map`, with a background cleanup goroutine) defined in `store/cache/cache.go` (`type Cache struct` at store/cache/cache.go:66, constructed by `cache.New`). It's purely per-process — no external store, no network connection.
- It's wired up in `store.New` (`store/store.go:38`), which builds a single `cache.Config` and instantiates three caches: `instanceSettingCache`, `userCache`, and `userSettingCache` (store/store.go:51–53). The config used is `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (store/store.go:40–45), matching `cache.DefaultConfig()` (store/cache/cache.go:57).

**TTL for user entries:** User cache entries are written via `s.userCache.Set(...)` (e.g. in `store/user.go` `GetUser`/`ListUsers`), and `Set` uses the cache's default TTL (`store/cache/cache.go` `Set` → default). Since `userCache` was created with that config, **user entries expire after 10 minutes** (the default TTL), with expired items swept by the 5-minute cleanup interval; entries are also evicted once the cache exceeds 1000 items. There is no separate/custom TTL for users — it's the shared default.
