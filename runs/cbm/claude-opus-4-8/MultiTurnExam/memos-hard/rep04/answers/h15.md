Memo view-access is enforced across several distinct server surfaces:

- v1 API single-memo read gate — `checkMemoReadAccess` (rejects non-public memos for anonymous users and private memos of other creators) — server/router/api/v1/memo_service.go:39 (invoked by `GetMemo` at server/router/api/v1/memo_service.go:356, for a parent memo at :367, and by comment listing at server/router/api/v1/memo_service_comments.go:148)
- v1 API `ListMemos` visibility filter (constrains the query `VisibilityList` to Public for anonymous, Public+Protected for a non-owner) — server/router/api/v1/memo_service.go:219–225
- v1 API user stats/tags visibility filter (same Public / Public+Protected constraint applied to stats queries) — server/router/api/v1/user_service_stats.go:84–90 and :218–220
- Fileserver attachment-serving gate (checks the parent memo's visibility, plus an anonymous/public gate, before streaming an attachment blob) — server/router/fileserver/fileserver.go:674–699
- RSS feed generation (includes only `store.Public` memos) — server/router/rss/rss.go:90 and :141
- Frontend server-side meta rendering (only `store.Public` memos exposed) — server/router/frontend/frontend.go:150

The first three live in the v1 gRPC/Connect API; the last three are the separate fileserver, RSS, and frontend HTTP surfaces. Each independently enforces that private/protected memos are not disclosed to unauthorized viewers.
