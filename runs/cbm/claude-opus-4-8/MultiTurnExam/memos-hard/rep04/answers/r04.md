**Premise correction:** Neither. The webhook workers do not consume from any external message broker — there is no NATS, RabbitMQ, AMQP, or Kafka in this project. A repo-wide search of Go source and `go.mod` for `nats`, `rabbitmq`, `amqp`, `streadway`, and `kafka` returns zero matches. There is no broker connection and no externally-declared queue.

**Actual mechanism:** Webhook delivery is dispatched over an **in-process, in-memory Go channel** — no network broker involved. In `internal/webhook/webhook.go`:
- The "queue" is a buffered channel declared as a package-level var: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`) — capacity 128, process-local.
- The workers are 4 goroutines started in the package `init` (`internal/webhook/webhook.go:42–54`); each ranges over `asyncPostQueue` and calls `Post` to perform the outbound HTTP delivery.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking `select` send onto `asyncPostQueue` and drops the payload (logging a warning) if the buffer is full.

So the "queue" is a bounded in-memory channel local to the server process, drained by four goroutines — not a NATS/RabbitMQ subscription.
