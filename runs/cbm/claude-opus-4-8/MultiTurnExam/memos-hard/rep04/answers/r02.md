**Premise correction:** This repository has **no per-user API rate-limiting middleware** — there is nothing to register and no configured request limits. The premise is false.

Evidence:
- A repo-wide search for rate-limiting of any kind (`rate.?limit`, `ratelimit`, `throttle`, `tollbooth`, `golang.org/x/time/rate`, `limiter`) turns up zero implementation in Go source. The only hit is an aspirational comment in unrelated email docs (`internal/email/doc.go:86`: "Rate limit email sending to prevent abuse"), which describes a possible future idea, not code.
- `go.mod` pulls in no rate-limiting/throttling library.
- The API's actual request-processing chain is the set of Connect interceptors registered for the v1 API (`server/router/api/v1/connect_interceptors.go`): `MetadataInterceptor` (header→gRPC metadata, line 22), `LoggingInterceptor` (line 98), and `RecoveryInterceptor` (panic recovery, line 164) — none of which enforce per-user or per-IP request quotas.

So there is no such middleware and no limits to report. If rate limiting were desired, it would need to be added (e.g., as an additional Connect interceptor in `connect_interceptors.go` / wired where the interceptors are assembled).
