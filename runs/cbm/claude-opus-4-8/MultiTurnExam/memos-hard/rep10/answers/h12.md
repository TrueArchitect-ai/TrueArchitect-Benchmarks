Determination method — I followed the driver selection from default config down to the concrete implementation, ruling out the other two candidates:

1. **Default driver is SQLite.** With no DB flags, the `driver` value defaults to `"sqlite"` — set both as the flag default (`cmd/memos/main.go:130`) and the viper default (`cmd/memos/main.go:122`), and SQLite's zero-config DSN path is handled in `internal/profile/profile.go:110`. So `profile.Driver == "sqlite"`.

2. **The factory picks the SQLite driver.** `NewDBDriver` switches on `profile.Driver`; the `"sqlite"` case constructs `sqlite.NewDB` (`store/db/db.go`, the mysql/postgres cases are not taken). This is what disambiguates the three candidate `CreateMemo` implementations — `store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, and `store/db/postgres/memo.go` all declare one, but only the SQLite driver is instantiated.

3. **The store delegates to that driver via the interface.** `Store.CreateMemo` (`store/memo.go:109`) simply calls `s.driver.CreateMemo(ctx, create)` (`store/memo.go:113`), where `s.driver` is the `Driver` interface bound at startup to the concrete `*sqlite.DB`. Hence the SQL INSERT that actually runs is the one in `(*sqlite.DB).CreateMemo`.
