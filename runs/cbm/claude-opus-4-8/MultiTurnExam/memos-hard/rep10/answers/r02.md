**Premise correction: this repository has no per-user API rate-limiting middleware — it does not exist, so there is nothing to register and no request limits to report.**

Evidence:
- A repo-wide search for `rate.?limit`, `ratelimit`, `throttle`, `limiter`, `tollbooth`, and `golang.org/x/time/rate` across all non-test Go files returns **no** implementation. The only hit is an aspirational line in a doc comment — `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") — which describes a future idea for the email package, not an HTTP/API middleware, and is not backed by any code.
- The actual API middleware/interceptor chain is registered in `server/router/api/v1/v1.go`: for Connect RPCs the interceptors are `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` (`server/router/api/v1/v1.go:133-137`), plus a gRPC-Gateway auth middleware (`:69`, `:97`). None of these enforce a request-rate limit.
- The only request-bounding control present is a **payload size** cap, not a rate limit: `connect.WithReadMaxBytes(maxAPIRequestBytes)` (`server/router/api/v1/v1.go:141`) — that limits how large a single request body may be, not how many requests a user may make.

So there is no per-user (or per-IP) rate limiter anywhere in the server; the question's premise is incorrect.
