**Premise correction: neither. The webhook delivery workers do not consume from any message broker — there is no NATS, RabbitMQ, AMQP, or Kafka in this project** (a repo-wide search for `nats`, `rabbitmq`, `amqp`, `kafka`, etc. across all Go files returns zero matches).

**Actual mechanism:** Webhook delivery is entirely in-process, backed by a buffered **Go channel**, not an external queue:
- The "queue" is a package-level buffered channel declared in `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (capacity 128).
- The workers are 4 goroutines started in the package `init()` (`internal/webhook/webhook.go:42-55`); each ranges over `asyncPostQueue` and calls `Post` to perform the outbound HTTP delivery (`internal/webhook/webhook.go:120`, send at `:152`).
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), a non-blocking `select` that drops the payload and logs a warning if the channel buffer is full (`:189-195`).

So there's no broker and no externally-declared queue — just an in-memory Go channel with a fixed 128-slot buffer consumed by four in-process worker goroutines.
