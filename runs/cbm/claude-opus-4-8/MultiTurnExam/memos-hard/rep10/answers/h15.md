Distinct server surfaces that enforce memo view-visibility (each is an independent access-gating site):

- Memo read API — `GetMemo` access check (`Public` open, `Protected` needs auth, `Private` needs owner) — server/router/api/v1/memo_service.go:55
- Memo list API — `ListMemos` visibility filter (anonymous → Public only; authed → own + Public/Protected) — server/router/api/v1/memo_service.go:219
- User stats API — same visibility filter applied to stats queries — server/router/api/v1/user_service_stats.go:84
- Memo relations API — visibility clause on related-memo listing — server/router/api/v1/memo_relation_service.go:109
- Real-time SSE delivery — per-client `canReceive` filter by memo visibility/creator/role — server/router/api/v1/sse_hub.go:135
- Attachment binary API — `GetAttachmentBinary` gated by parent memo's visibility — server/router/api/v1/attachment_service.go:445
- File server (attachment blob) — anonymous/authed access gated by parent memo visibility — server/router/fileserver/fileserver.go:677
- RSS feed — public-only memo listing — server/router/rss/rss.go:90 (and :141)
- Frontend SSR/sitemap — public-only memo exposure — server/router/frontend/frontend.go:150

The core "who may view" enforcement lives in at least the three primary read surfaces — single-memo read (`memo_service.go:55`), memo listing (`memo_service.go:219`), and the SSE delivery filter (`sse_hub.go:135`) — with the attachment/fileserver, RSS, and frontend surfaces additionally re-checking visibility for content they expose.
