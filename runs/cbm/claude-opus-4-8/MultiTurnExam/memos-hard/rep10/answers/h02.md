**Delivery function: `Post` — `internal/webhook/webhook.go:120` (the actual outbound HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:152`); protection mechanism: `safeDialContext` — `internal/webhook/webhook.go:59` (backed by `isReservedIP`/`reservedCIDRs` in `internal/webhook/validate.go:44` and `:14`).**

Details:

- **Where delivery executes:** `Post` marshals the payload, builds the POST request (optionally adding Standard-Webhooks HMAC-SHA256 headers), and dispatches it via the shared `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. Async triggers go through `PostAsync` → a bounded queue → worker goroutines that also call `Post` (`internal/webhook/webhook.go:184`, `:42-55`).

- **What protects it (SSRF guard):** The client's `Transport.DialContext` is set to `safeDialContext` (`internal/webhook/webhook.go:32-37`, `:59-77`). At dial time it resolves the target host and refuses to connect if any resolved IP falls in a reserved/private range — this runs on the *actual* connection address, so it also defeats DNS-rebinding. The reserved ranges (loopback, RFC-1918, link-local/cloud IMDS `169.254.169.254`, and IPv6 equivalents) are defined in `internal/webhook/validate.go:14-23` and checked by `isReservedIP` at `internal/webhook/validate.go:44`.

- Secondary/creation-time protection: `ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and hostnames resolving to reserved IPs when a webhook is configured. Both guards can be disabled via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for self-hosted local-network use.
