**Mechanism: explicit Go code** (not a database-level rule). When a user is deleted, their emoji reactions are removed by explicit `DELETE FROM reaction` statements inside the transactional `DeleteUser` driver code — twice: once for reactions the user *made* (by `creator_id`), and once for reactions on the user's *content* (by `content_id`, i.e. reactions others left on the deleted user's memos).

Evidence locations:

- **Schema has no FK/cascade** — the `reaction` table declares `creator_id`/`content_id` as plain columns with no foreign key or `ON DELETE CASCADE`, so the database will not remove reactions on its own:
  - `store/migration/sqlite/0.20/00__reaction.sql`
  - `store/migration/mysql/0.20/00__reaction.sql`
  - `store/migration/postgres/0.20/00__reaction.sql`

- **Explicit deletion in Go**, in each driver's `DeleteUser` (all inside one transaction), calling two helpers:
  - by creator: `deleteReactionsByCreatorTx` → `DELETE FROM reaction WHERE creator_id = ?`
    - `store/db/sqlite/user_delete.go:400-401`
    - `store/db/mysql/user_delete.go:437-438`
    - `store/db/postgres/user_delete.go:400-401`
  - by content: `deleteReactionsByContentIDsTx` → `DELETE FROM reaction WHERE content_id IN (...)`
    - `store/db/sqlite/user_delete.go:380-383`
    - `store/db/mysql/user_delete.go:417-420`
    - `store/db/postgres/user_delete.go:380-383`
  - wired into the delete flow at `store/db/{sqlite,mysql,postgres}/user_delete.go:96` and `:102`.

- **Entry point:** `store.DeleteUser` (`store/user.go:171`) delegates to `s.driver.DeleteUser` (`store/user.go:172`), which runs the SQL above.
