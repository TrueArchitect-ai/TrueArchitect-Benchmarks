**Premise correction:** There is no nightly database-cleanup job scheduled in the cron scheduler — so there is no run time to report. The premise is false on two counts.

Evidence:
- **The cron scheduler is never wired into the running server.** The `internal/scheduler` package (a cron-style scheduler with `New`/`Register`/`Schedule.Next`, `internal/scheduler/scheduler.go`, `internal/scheduler/parser.go`) is imported **only by its own tests** (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`). No production code under `server/`, `cmd/`, or `store/` imports or instantiates it, so nothing is scheduled via cron at all.
- **No database-cleanup job exists.** There is no nightly/purge/vacuum/prune job registered anywhere. The only background work started at server startup is the S3 presign runner (a 12-hour ticker, `server/server.go:162-169`), which refreshes presigned attachment URLs — not a database cleanup, and it is interval-based, not scheduled at a clock time.
- The only "cleanup" concepts in the codebase are unrelated: cascading deletes performed inline when a user/memo is deleted (`server/router/api/v1/user_service.go:421`, `memo_service.go:579`) and the in-memory cache's 5-minute `CleanupInterval` (`store/store.go:42`) — none of which is a cron-scheduled nightly DB job.
