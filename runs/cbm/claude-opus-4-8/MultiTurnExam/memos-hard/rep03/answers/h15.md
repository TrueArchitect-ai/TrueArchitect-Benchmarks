Every distinct server surface that enforces memo view-visibility:

- Single-memo read (gRPC/Connect API `GetMemo`): `checkMemoReadAccess` — `server/router/api/v1/memo_service.go:55-66` (denies non-public memos to non-owners; requires auth for protected/private).
- Memo listing (API `ListMemos`): visibility scoping of the query — `server/router/api/v1/memo_service.go:219-227` (anonymous → `VisibilityList = [Public]`; authed → `creator_id == me || visibility in [PUBLIC, PROTECTED]`). This is realized at the data layer via the `VisibilityList`/filter WHERE clause in `store/db/{sqlite,postgres,mysql}/memo.go` (e.g. `store/db/sqlite/memo.go:96`).
- RSS feed router: restricts feeds to public memos — `server/router/rss/rss.go:90` and `server/router/rss/rss.go:141` (`VisibilityList = [store.Public]`).
- File server (attachment/avatar serving): parent-memo visibility gate — `checkAttachmentPermission` at `server/router/fileserver/fileserver.go:677` and `:699`.
- SSE real-time event delivery: per-client filtering by memo visibility — `SSEClient.canReceive` at `server/router/api/v1/sse_hub.go:135`.

Additional API actions that re-check the same view-visibility before allowing an operation (same rule, different entry points):
- Reactions: `server/router/api/v1/reaction_service.go:30` and `:83`.
- Attachment access via memo: `server/router/api/v1/attachment_service.go:445-451` and `server/router/api/v1/memo_attachment_service.go:214-222`.
- Comments: `server/router/api/v1/memo_service_comments.go:41`.
