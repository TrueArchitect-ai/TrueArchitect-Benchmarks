**Delivery function — `Post` in `internal/webhook/webhook.go` (defined at `internal/webhook/webhook.go:119`); the actual outbound HTTP send is `safeClient.Do(req)` at `internal/webhook/webhook.go:157`. (`PostAsync`/the async worker pool at `webhook.go:185`/`webhook.go:41` enqueue to it, but `Post` is where delivery executes.)**

**Protection mechanism — SSRF guard at dial time via `safeDialContext` (`internal/webhook/webhook.go:59`), installed as the `DialContext` of the shared `safeClient`'s `http.Transport` (`webhook.go:30-36`). It resolves the target hostname with `net.DefaultResolver.LookupHost` and rejects the connection if any resolved IP is reserved/private per `isReservedIP` (`internal/webhook/validate.go:44`). Because the check runs against the freshly-resolved IPs at connection time, it also defeats DNS-rebinding.**

Notes:
- The delivery uses the dedicated `safeClient` (not the default `http.Client`), which is what makes the SSRF guard unavoidable for webhook dispatches.
- `isReservedIP` in `internal/webhook/validate.go` is the enumeration of the blocked ranges (loopback, private, link-local, etc.) that `safeDialContext` enforces.
