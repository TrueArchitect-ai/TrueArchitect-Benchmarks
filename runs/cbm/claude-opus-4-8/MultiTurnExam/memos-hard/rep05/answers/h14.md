**Computation site:** `RebuildMemoPayload` at `server/runner/memopayload/runner.go:74`, which calls the markdown service's `ExtractAll` (`internal/markdown/markdown.go:356`) on `memo.Content` and writes the results into `memo.Payload` (`memo.Payload.Tags` and `memo.Payload.Property`, `runner.go:85-86`). The extraction itself is a single goldmark AST walk in `ExtractAll`.

**Triggers (recomputation):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (on every memo creation).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, but only inside the branch where the memo's `content` field is being changed (guarded by the content-update case at `:446`).
- The `memopayload.Runner` batch backfill — `server/runner/memopayload/runner.go:52` (`RunOnce` recomputes payloads for all memos in batches). Note: as established earlier, this `Runner` isn't wired into startup, so in practice the live triggers are Create/Update memo.

**Extracted properties** (from `ExtractAll`, stored in `MemoPayload`):
- `Tags` — the set of `#tags` in the content, deduplicated (case preserved).
- `Property.Title` — text of a leading H1 heading, if the document's first block is one.
- `Property.HasLink` — content contains a link.
- `Property.HasCode` — content contains a code block / fenced code / inline code span.
- `Property.HasTaskList` — content contains a task-list checkbox.
- `Property.HasIncompleteTasks` — at least one task checkbox is unchecked.

(`ExtractAll` also gathers `@mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property` into the derived payload.)
