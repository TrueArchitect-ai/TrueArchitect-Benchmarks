**Premise correction:** There is no GraphQL API. The codebase contains no GraphQL schema, resolvers, or libraries — grepping the whole repo and `go.mod` for `graphql`, `gqlgen`, `.graphql`/`.graphqls` returns nothing. So there is no GraphQL schema file to point to.

**Actual API surface:** The public API is defined with **Protocol Buffers** and served as **gRPC + Connect RPC, with a REST/JSON gateway and OpenAPI**, not GraphQL:

- Schema/service definitions live in `.proto` files under `proto/api/v1/` — e.g. `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `instance_service.proto`, plus `common.proto`. (Store-layer messages are in `proto/store/*.proto`.)
- Code generation is configured in `proto/buf.gen.yaml`, which emits Go protobuf types, gRPC (`buf.build/grpc/go`), Connect (`buf.build/connectrpc/go`), a grpc-gateway REST layer (`buf.build/grpc-ecosystem/gateway`), and a **gnostic OpenAPI** spec (`buf.build/community/google-gnostic-openapi`) — with generated output under `proto/gen/`.
- Runtime wiring confirms this: Connect/gRPC handlers are registered in `server/router/api/v1/connect_services.go` / `connect_handler.go`, and the REST gateway handlers (`RegisterMemoServiceHandlerServer`, etc.) are registered in `server/router/api/v1/v1.go:99-120`. The OpenAPI document is embedded via `proto/openapi_embed.go`.

So the "public API" is proto-defined gRPC/Connect + REST(+OpenAPI), and the closest thing to a "schema" is the set of `.proto` files in `proto/api/v1/`.
