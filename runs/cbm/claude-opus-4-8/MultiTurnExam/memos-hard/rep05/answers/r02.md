**Premise correction:** There is no per-user API rate-limiting middleware in this codebase, so there is nowhere it's registered and no request limits to report.

Evidence:
- Searching the whole Go source for rate-limiting (`rate.limit`, `ratelimit`, `throttle`, `limiter`, `golang.org/x/time/rate`, `tollbooth`, `quota`, etc.) yields no implementation — the only hit is a doc comment in `internal/email/doc.go:86` describing a *possible* future consideration for email sending, not any request-rate middleware.
- The Connect/gRPC API request pipeline registers exactly four interceptors, none of which is a rate limiter: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` — all defined in `server/router/api/v1/connect_interceptors.go` (types at lines 22, 98, 165, 208) and wired via `connect_services.go`.
- No `golang.org/x/time/rate` or any rate-limiting library appears in `go.mod`.

If a limit-like control is what's of interest, the closest real mechanisms are unrelated concurrency caps inside the API service (e.g. `semaphore.NewWeighted(3)`/`(2)` for thumbnail and image processing in `server/router/api/v1/v1.go`) and content-length validation on memos — but these are not per-user request rate limits.
