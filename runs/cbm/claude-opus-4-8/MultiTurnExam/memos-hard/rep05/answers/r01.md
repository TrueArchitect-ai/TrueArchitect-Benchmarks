**Premise correction:** There is no Redis. The repository contains no Redis client, dependency, or connection anywhere — grepping for `redis` across the Go sources returns nothing. The cache layer is a purely in-process, in-memory cache implemented in `store/cache/cache.go` (a mutex/`sync`-guarded map with per-item expiration and a background cleanup goroutine — see the `Interface`/`Config` at `store/cache/cache.go:10-53`). So there is no Redis connection to configure.

**Actual mechanism:** The `Store` creates three in-memory caches — including the user cache — in `store.New` at `store/store.go:51-53`, all sharing one `cache.Config` defined at `store/store.go:40-46`: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`. (`cache.DefaultConfig()` in `store/cache/cache.go:56` uses the same 10-minute default.)

User entries are written via `s.userCache.Set(...)` (e.g. `store/user.go:98`, `:122`, `:132`, `:143`, `:167`), and `Set` applies the cache's default TTL. So **user cache entries expire 10 minutes after they're set** (evicted lazily on access and swept by the 5-minute cleanup pass), and are also explicitly invalidated on user deletion (`store/user_delete.go:40`). "Configuration" of this cache is code-level in `store/store.go`, not a Redis connection string.
