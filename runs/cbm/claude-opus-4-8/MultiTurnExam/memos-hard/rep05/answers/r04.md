**Premise correction:** Neither. There is no external message broker at all — no NATS, no RabbitMQ (nor Kafka/AMQP). Grepping the entire codebase and `go.mod` for `nats`, `rabbitmq`, `amqp`, `kafka`, and `broker` returns zero matches. So there is no broker-declared queue to point to.

**Actual mechanism:** Webhook delivery is fully in-process. The "queue" is a buffered Go channel declared in `internal/webhook/webhook.go:38`:

```go
asyncPostQueue = make(chan *WebhookRequestPayload, 128)
```

The "workers" are 4 goroutines started in that package's `init()` (`internal/webhook/webhook.go:41-53`), each ranging over `asyncPostQueue` and calling `Post` (`internal/webhook/webhook.go:119`) to perform the actual HTTP delivery. Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:185`), which does a non-blocking send onto the channel and drops the payload with a warning if the buffer (capacity 128) is full. This is a single-process, in-memory channel — it does not survive restarts and is not backed by any broker.
