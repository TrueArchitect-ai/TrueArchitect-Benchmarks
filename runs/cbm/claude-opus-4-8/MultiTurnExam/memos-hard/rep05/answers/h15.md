Distinct server-side enforcement sites for memo view/visibility access:

- `checkMemoReadAccess` (single-memo read; denies non-owner on private/protected) — `server/router/api/v1/memo_service.go:55`
- `ListMemos` visibility filtering (restricts the query to PUBLIC / PUBLIC+PROTECTED, or `creator_id == me || visibility in [...]`) — `server/router/api/v1/memo_service.go:219` (also mirrored in stats: `server/router/api/v1/user_service_stats.go:84,90,218,220`)
- `checkAttachmentPermission` (file/media/thumbnail serving gated by the parent memo's visibility + share-token) — `server/router/fileserver/fileserver.go:650` (checks at `:677`, `:699`)
- RSS feed generation (only PUBLIC memos exposed) — `server/router/rss/rss.go:90` and `server/router/rss/rss.go:141`
- Frontend SSR / embed metadata (only PUBLIC memos exposed) — `server/router/frontend/frontend.go:150`
- Reaction service (must be able to view the memo before listing/adding reactions) — `server/router/api/v1/reaction_service.go:30`, `:38`, `:83`
- API v1 attachment access (`GetAttachmentBinary`, visibility-gated) — `server/router/api/v1/attachment_service.go:445`, `:451`
- Memo-attachment listing access (visibility-gated) — `server/router/api/v1/memo_attachment_service.go:214`, `:222`
- Memo comment listing (private related-memo gated to owner) — `server/router/api/v1/memo_service_comments.go:41`

The core three surfaces are the gRPC memo API (`memo_service.go` — both single-read `checkMemoReadAccess` and `ListMemos` filtering), the file server (`fileserver.go` `checkAttachmentPermission`), and the RSS/frontend public feeds (`rss.go`, `frontend.go`); the reaction and attachment services add further per-surface checks.
