Distinct server surfaces that enforce memo visibility (who may view a memo):

Single-memo read gate (`checkMemoReadAccess`, used by GetMemo and other single-memo reads) — server/router/api/v1/memo_service.go:39-67
Memo list/search visibility filter (injects `creator_id == X || visibility in ["PUBLIC","PROTECTED"]` / anonymous → PUBLIC only) — server/router/api/v1/memo_service.go:220-224
File server for attachment content (`checkMemoAccess` on the owning memo's visibility) — server/router/fileserver/fileserver.go:677-699
RSS feed (restricts `FindMemo.VisibilityList` to `store.Public`) — server/router/rss/rss.go:90 and rss.go:141
Frontend SSR / sitemap (lists only `store.Public` memos) — server/router/frontend/frontend.go:149-150
SSE realtime delivery filter (`canReceive` gates events by memo Visibility/CreatorID) — server/router/api/v1/sse_hub.go:135-141

Additional related enforcement sites that also key off the same memo visibility, on adjacent surfaces:
Comments: single-comment read + comment-list filter — server/router/api/v1/memo_service_comments.go:41 and comments.go:158-160
Reactions (list/create gated by memo visibility) — server/router/api/v1/reaction_service.go:30-38, reaction_service.go:83
Attachment API (memo-bound attachment access) — server/router/api/v1/attachment_service.go:445-451 and server/router/api/v1/memo_attachment_service.go:214-222
Memo relations list filter — server/router/api/v1/memo_relation_service.go:109-111
User stats visibility filter — server/router/api/v1/user_service_stats.go:87

The first six are the primary distinct view-enforcement surfaces (API single-read, API list, file server, RSS, frontend SSR, SSE); all reference the same three-level model (`store.Public` / `store.Protected` / `store.Private`) defined in the store layer.
