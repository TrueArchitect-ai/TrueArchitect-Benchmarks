**Premise correction: there is no nightly database-cleanup job (and no wired-up cron scheduler running one), so there is no scheduled time to report.**

Evidence:
- The only background runner started at server startup is the **S3 presign runner**, and it is not a cron/nightly job: it runs once immediately (`s3presignRunner.RunOnce(ctx)`) and then on a fixed **12-hour interval ticker**, not at a clock time (`server/server.go:161-171`; interval defined as `time.Hour * 12` in `server/runner/s3presign/runner.go:26-27`). `startBackgroundRunners` (`server/server.go:153`) registers no other runner.
- There **is** a cron-expression scheduler package (`internal/scheduler`, with `New`, `ParseCronExpression`, etc.), but it is **never used in production** — the only importers are its own tests (`internal/scheduler/example_test.go`, `internal/scheduler/integration_test.go`); no non-test code imports or instantiates it. So no cron schedule (nightly or otherwise) is registered anywhere.
- Database "cleanup" that does exist is **event-driven, not scheduled**: e.g. relation/attachment cleanup happens inline when a memo or user is deleted (`server/router/api/v1/memo_service.go:579`, `server/router/api/v1/user_service.go:421-450`). There is no periodic/nightly sweep.

So the described nightly cleanup cron job does not exist in this codebase.
