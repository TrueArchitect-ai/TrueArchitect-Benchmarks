**Premise correction: there is no GraphQL schema — this project does not expose a GraphQL API at all.** A repo-wide search for GraphQL artifacts (`graphql`, `gqlgen`, `.graphql` / `schema.graphqls`) finds nothing in the Go backend or the web frontend. So there is no GraphQL schema file to point to.

**Actual API surface:** The public API is defined with **Protocol Buffers** and served over **Connect (connectrpc)** + a **gRPC-Gateway** REST/JSON bridge:
- The API contract (the real "schema") is the set of `.proto` service definitions in `proto/api/v1/` — e.g. `memo_service.proto`, `user_service.proto`, `attachment_service.proto`, `auth_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, plus `common.proto`. Generated Go code lives under `proto/gen/api/v1/` (imported as `v1pb`), and the TypeScript client stubs under `web/src/types/proto/`.
- These services are wired up in `server/router/api/v1/v1.go` — `RegisterGateway` (`v1.go:65`) registers both the Connect handlers and a gRPC-Gateway mux (`connectrpc.com/connect` and `github.com/grpc-ecosystem/grpc-gateway/v2/runtime`, imported at `v1.go:7-8`), with a shared auth middleware/ACL.

So the "schema" for the public API is the protobuf service definitions in `proto/api/v1/`, exposed via Connect/gRPC and a REST gateway — not GraphQL.
