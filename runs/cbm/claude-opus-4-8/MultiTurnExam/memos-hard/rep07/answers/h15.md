Memo view-access is enforced at several distinct server surfaces:

- Single-memo read gate (gRPC/REST `GetMemo`) — `checkMemoReadAccess`, requires auth for non-public and owner-only for Private — `server/router/api/v1/memo_service.go:55` (function at line 40).
- Memo list filtering (gRPC/REST `ListMemos`) — sets `VisibilityList`/filter to Public for anonymous, and `creator_id == me || visibility in ["PUBLIC","PROTECTED"]` for authenticated viewers — `server/router/api/v1/memo_service.go:218-227`.
- User memo-stats filtering (`user_service_stats.go`) — same Public / Public+Protected visibility restriction per viewer — `server/router/api/v1/user_service_stats.go:84,90,218,220`.
- Reaction listing (`ListMemoReactions`) — its own inline visibility check before returning a memo's reactions — `server/router/api/v1/reaction_service.go:30`.
- Attachment/file server — attachment access derived from the owning memo's visibility (Public served to anonymous only when allowed; Private restricted to owner/admin, with share-token fallback) — `server/router/fileserver/fileserver.go:677,699` (in `checkAttachmentPermission`).
- Real-time SSE delivery filter — `SSEClient.canReceive` drops Private memo events unless recipient is the creator or an admin — `server/router/api/v1/sse_hub.go:135`.
- RSS feed — restricts feed items to Public memos — `server/router/rss/rss.go:90,141`.
- Frontend SSR/metadata rendering — Public-only visibility list — `server/router/frontend/frontend.go:150`.
