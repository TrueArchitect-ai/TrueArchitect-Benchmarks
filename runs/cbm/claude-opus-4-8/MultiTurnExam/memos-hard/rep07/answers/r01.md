**Premise correction:** There is no Redis anywhere in this codebase — the cache layer is not backed by Redis. A repo-wide search for `redis` returns zero hits in Go source and `go.mod`. So there is no "Redis connection" to configure; the question's premise is false.

**Actual mechanism:** The cache is an in-process, in-memory cache implemented in pure Go — `store/cache/cache.go` (a `*cache.Cache` with a background cleanup goroutine, TTL-based expiration, and a `MaxItems` cap). It holds no network connection at all.

- **Where it's configured:** in `Store.New`, `store/store.go:38-53`. A single `cache.Config` is built there (`DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`) and used to construct three separate in-memory caches, including the user cache: `userCache: cache.New(cacheConfig)` (`store/store.go:52`). The `cache.New` constructor lives in `store/cache/cache.go` (defaults in `DefaultConfig`, `store/cache/cache.go:~57`).
- **TTL for user entries:** 10 minutes. User records are inserted via `s.userCache.Set(...)` (`store/user.go`, in `GetUser`/`ListUsers`), and `Set` applies the cache's `DefaultTTL`, which is `10 * time.Minute` from the config in `store/store.go:41`. There is no per-user custom TTL (`SetWithTTL` is not used for user entries).
