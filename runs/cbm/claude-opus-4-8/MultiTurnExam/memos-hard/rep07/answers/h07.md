Route `GET /file/users/:identifier/avatar` → down to the `user.avatar_url` column (the avatar is stored as a base64 data URI on the user row):

- `RegisterRoutes` (route registration `fileGroup.GET("/users/:identifier/avatar", s.serveUserAvatar)`) — server/router/fileserver/fileserver.go:124
- `FileServerService.serveUserAvatar` (serving handler) — server/router/fileserver/fileserver.go:168
- `FileServerService.getUserByUsername` — server/router/fileserver/fileserver.go:715
- `Store.GetUser` — store/user.go:148
- `Store.ListUsers` — store/user.go (calls `s.driver.ListUsers`)
- `DB.ListUsers` (driver, per-backend SQL that selects `avatar_url` from the `user` table) — store/db/sqlite/user.go:88 (and store/db/mysql/user.go:84, store/db/postgres/user.go:87)

The handler then decodes the stored data URI via `FileServerService.parseDataURI` (server/router/fileserver/fileserver.go:737) and writes the image bytes back with `c.Blob` (fileserver.go:209). The image content itself lives in the `avatar_url` column read by the driver's `ListUsers` query (e.g. store/db/sqlite/user.go:159,189).
