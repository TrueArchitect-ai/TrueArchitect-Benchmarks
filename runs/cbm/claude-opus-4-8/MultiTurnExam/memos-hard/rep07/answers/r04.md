**Premise correction: neither. The webhook delivery workers do not consume from any external message broker — there is no NATS, RabbitMQ, AMQP, or Kafka in this codebase.** A repo-wide search for `nats`, `rabbitmq`, `amqp`, `kafka`, `streadway` returns zero hits in Go source, and `go.mod` declares no such dependency. So there is no broker-managed queue to declare.

**Actual mechanism:** Webhook delivery uses an in-process, in-memory Go buffered channel with a fixed pool of goroutine workers, all inside `internal/webhook/webhook.go`:

- The "queue" is a package-level buffered channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`).
- The workers are 4 goroutines started in `init()` that range over that channel and call `Post` for each payload (`internal/webhook/webhook.go:42-55`).
- Producers enqueue via `PostAsync`, which does a non-blocking send onto the channel and drops the request (with a warning) if the buffer is full (`internal/webhook/webhook.go:184-196`).

This is entirely in-process (bounded channel + goroutines); it is not backed by, and does not connect to, any message broker.
