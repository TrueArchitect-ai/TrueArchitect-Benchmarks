**Premise correction: there is no GraphQL schema in this project.** A repo-wide search for `graphql`/`gqlgen`/`.graphql`/`.gql` returns zero hits in Go source and no such files exist; `go.mod` declares no GraphQL dependency. So there is no GraphQL schema to point to — the premise is false.

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC services**, served over **Connect + gRPC-Gateway (REST/JSON)**:

- The schema/service definitions live in `.proto` files under `proto/api/v1/` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `instance_service.proto`, `idp_service.proto`, `shortcut_service.proto`, `ai_service.proto`, plus shared types in `common.proto` (build config in `proto/buf.yaml` / `proto/buf.gen.yaml`).
- Generated Go code is under `proto/gen/` (and store-side protos in `proto/store/`), with an embedded OpenAPI document (`proto/openapi_embed.go`) rather than a GraphQL schema.
- These services are wired into the HTTP server via Connect handlers and the gRPC-Gateway in the `server/router/api/v1` package (registration in `server/router/api/v1/v1.go`, e.g. `RegisterGateway`), implemented by the handler methods in files like `server/router/api/v1/memo_service.go`.

So the public API is a proto-defined gRPC/Connect + REST-gateway surface, not GraphQL.
