**Computation site: `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74` (delegating to `markdown.Service.ExtractAll`, `internal/markdown/markdown.go:356`).**

**Triggers (operations that recompute it):**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108` (on every memo creation).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447` (only when the memo's `content` is being changed; the call sits inside the content-update branch that also sets `memo.Content = request.Memo.Content`).

(There is also a bulk `memopayload.Runner.RunOnce` that would rebuild all memos' payloads, `server/runner/memopayload/runner.go:27`, but as established it is not wired into production — so it is not a runtime trigger.)

**Extracted properties:** `RebuildMemoPayload` runs `ExtractAll` over the memo content in a single goldmark pass and writes two derived fields into `memo.Payload`:
- `memo.Payload.Tags` — the deduplicated list of `#tags` found in the content (`runner.go:85`).
- `memo.Payload.Property` (`runner.go:86`), a `storepb.MemoPayload_Property` with:
  - `Title` — text of a leading H1 heading, if the first block is one (`internal/markdown/markdown.go:386-388`)
  - `HasLink` — content contains a link (`:393-394`)
  - `HasCode` — content contains a code block/span (`:396-397`)
  - `HasTaskList` — content contains a task checkbox (`:399-400`)
  - `HasIncompleteTasks` — at least one unchecked task item (`:401-404`)

(`ExtractAll` also computes `Mentions`, but `RebuildMemoPayload` only persists `Tags` and `Property` into the payload; mentions are handled separately.) These derived fields are what drive list/preview rendering.
