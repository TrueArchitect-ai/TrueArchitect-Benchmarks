Distinct memo-visibility enforcement sites (each gates who may view a memo, or memo-derived content, by `Visibility` PUBLIC/PROTECTED/PRIVATE):

- API v1 single-memo read gate — `checkMemoReadAccess` — `server/router/api/v1/memo_service.go:39` (non-public memos require an authenticated user; PRIVATE requires being the creator). Used by `GetMemo` (`:356`), comment reads (`server/router/api/v1/memo_service_comments.go:148`), and parent-memo checks (`memo_service.go:367`).
- API v1 memo **list** scoping — `ListMemos` — `server/router/api/v1/memo_service.go:219-225` (anonymous → PUBLIC only; authenticated → own + PUBLIC/PROTECTED). Same pattern in `server/router/api/v1/user_service_stats.go:84-90`, `:218-220` and `server/router/api/v1/memo_service_converter.go:184-186`.
- File/media server — `checkAttachmentPermission` — `server/router/fileserver/fileserver.go:650` (gates serving stored attachment bytes by parent memo visibility: `:677`, `:699`).
- RSS feed — `server/router/rss/rss.go:90` and `server/router/rss/rss.go:141` (feed restricted to `store.Public` memos).
- Frontend server-side render / OG metadata — `server/router/frontend/frontend.go:150` (only `store.Public` memos exposed).
- API v1 attachment services — `server/router/api/v1/attachment_service.go:445-451` and `server/router/api/v1/memo_attachment_service.go:214-222` (attachment access gated by owning memo's visibility).
- API v1 reaction service — `server/router/api/v1/reaction_service.go:30-38` and `:83` (reacting to / reading reactions of non-public / private memos).
- API v1 comment creation — `server/router/api/v1/memo_service_comments.go:41` (commenting on a PRIVATE memo restricted to creator/superuser).

Note: the MCP surface (`server/router/mcp/catalog.go` exposing `MemoService_ListMemos`/`GetMemo`) does not re-implement visibility — it delegates to the API v1 MemoService and inherits the `checkMemoReadAccess` / list-scoping enforcement above. The three clearly independent surfaces are the API v1 memo service, the file/media server, and the RSS feed (with the frontend SSR as a fourth).
