**Premise correction:** Neither. The webhook delivery workers do **not** consume from NATS, RabbitMQ, or any external message broker — there is no broker in this codebase. A repo-wide search for `nats`, `rabbitmq`/`amqp`, `kafka`, or `broker` in Go source and `go.mod` returns nothing.

**Actual mechanism:** Webhook dispatch is fully in-process, backed by a buffered **Go channel**, not a broker.
- The "queue" is declared as a package-level buffered channel: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39`.
- The workers are 4 goroutines started in the package `init()` (`internal/webhook/webhook.go:42-55`), each ranging over `asyncPostQueue` and calling `Post` (`internal/webhook/webhook.go:120`) to perform the outbound HTTP delivery.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184`), a non-blocking send onto the channel that drops the payload (with a warning) if the buffer of 128 is full.

So it's a single-process channel + goroutine-pool design (`internal/webhook/webhook.go`), with no NATS/RabbitMQ queue declaration anywhere.
