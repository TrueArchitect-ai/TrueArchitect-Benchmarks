**Premise correction:** There is no Redis anywhere in this codebase — a repo-wide search for "redis" in Go source returns nothing. The cache layer is a self-contained, **in-process (in-memory) cache**, not backed by Redis or any external store. So there is no "Redis connection" to configure.

**Actual mechanism:**
- The cache implementation is `store/cache/cache.go` — a plain in-memory map guarded by a mutex, with a background cleanup goroutine (`cache.Interface` / `cache.Cache`, no network client).
- It's instantiated in `store.New` at `store/store.go:38`, which builds three in-memory caches — `instanceSettingCache`, `userCache`, `userSettingCache` (`store/store.go:51-53`) — all from one `cache.Config` defined at `store/store.go:40-45`:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
- **User entries TTL:** user records are written via `s.userCache.Set(...)` (e.g. `store/user.go` in `GetUser`/`ListUsers`), and `Set` applies the cache's `DefaultTTL` — so **user entries live for 10 minutes** (with eviction sweeps every 5 minutes and a 1000-item cap). The same 10-minute default also matches `cache.DefaultConfig()` in `store/cache/cache.go`.

There is no per-user custom TTL (`SetWithTTL`) in the user path; user entries simply inherit the 10-minute default.
