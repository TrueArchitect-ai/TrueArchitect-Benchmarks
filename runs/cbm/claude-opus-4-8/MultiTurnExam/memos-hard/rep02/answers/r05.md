**Premise correction:** There is no GraphQL schema anywhere in this repository — a repo-wide search for `graphql`/`gqlgen`/`graphene` in Go source returns nothing, and there are no `.graphql`/`.gql` schema files. The public API is not GraphQL.

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC service definitions**, exposed over both gRPC-Gateway (REST/JSON) and Connect (browser) transports:
- **Schema source of truth:** `.proto` files under `proto/api/v1/` — e.g. `proto/api/v1/memo_service.proto`, `user_service.proto`, `attachment_service.proto`, `auth_service.proto`, `shortcut_service.proto`, `instance_service.proto`, `idp_service.proto`, `ai_service.proto`, plus `common.proto`. Store-layer messages live in `proto/store/*.proto`. Codegen is configured via `proto/buf.gen.yaml` / `proto/buf.yaml`, with generated Go in `proto/gen/`.
- **REST/OpenAPI:** an OpenAPI document is generated from the protos and embedded via `proto/openapi_embed.go` (the HTTP/JSON surface, not GraphQL).
- **Runtime wiring:** `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65`) mounts a gRPC-Gateway mux (`v1.go:95`) and Connect handlers (`v1.go:131-139`, using `connectrpc.com/connect`) — i.e., the public API is served as gRPC-Gateway REST + Connect-RPC, both derived from the `proto/api/v1` definitions.

So the closest analog to "the schema for the public API" is the protobuf service definitions in `proto/api/v1/`, not a GraphQL schema.
