**Premise correction:** The webhook delivery workers do not consume from NATS or RabbitMQ — neither is used anywhere in the codebase. A repo-wide search for `nats`/`rabbitmq`/`amqp`/`streadway` in Go files returns nothing, and `go.mod` declares no message-broker dependency (no NATS, RabbitMQ/AMQP, Kafka, etc.). There is no external broker at all.

**Actual mechanism:** Webhook dispatch uses a purely in-process Go **buffered channel** as its queue, declared in `internal/webhook/webhook.go`:
- Queue declaration: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — `internal/webhook/webhook.go:39` (a bounded channel, capacity 128).
- Workers: a fixed pool of 4 goroutines started in `init()` (`internal/webhook/webhook.go:42-55`) that range over `asyncPostQueue` and call `Post` to perform delivery.
- Producer: `PostAsync` (`internal/webhook/webhook.go:184`) enqueues onto the channel with a non-blocking `select`, dropping (and logging) the payload if the queue is full.

Everything lives inside the single server process; there is no broker to declare a queue on.

Answer: **Neither NATS nor RabbitMQ — the codebase has no message broker. Webhook workers consume from an in-process buffered Go channel `asyncPostQueue` (cap 128) declared at `internal/webhook/webhook.go:39`, drained by 4 goroutines started in `init` (`internal/webhook/webhook.go:42-55`) and fed by `PostAsync` (`:184`).**
