**Premise correction:** There is no nightly database-cleanup job scheduled in any cron scheduler, so there is no run time to report.

1. **A cron scheduler package exists but is never used in production.** `internal/scheduler` implements a cron scheduler (`internal/scheduler/scheduler.go`, `parser.go`, `job.go`, etc.), but a repo-wide search for any import of `usememos/memos/internal/scheduler` outside test files returns zero results — it is only referenced by its own `*_test.go` files. Nothing in the server ever registers a job with it. So no cron job of any kind (let alone a nightly cleanup) is scheduled.

Neither runs on a nightly/midnight schedule nor cleans up the database.

The database "cleanup" that does exist is **synchronous and event-driven**, not scheduled: related rows/attachments are deleted inline when a memo or user is deleted (e.g. `store.DeleteMemo`/`DeleteUser`, referenced at `server/router/api/v1/memo_service.go:579` and `server/router/api/v1/user_service.go:421-450`).

The `internal/scheduler` cron package has no production consumer (only test references); the sole background jobs are interval timers in `server/server.go:153-171` (S3 presign every 12h), and DB cleanup happens synchronously on memo/user deletion, not on a schedule.**
