**Premise correction: There is no per-user API rate-limiting middleware in this codebase — so there is nothing registered and no request limits to report.**

Evidence:
- A codebase-wide search for `rate limit`, `ratelimit`, `throttle`, `limiter`, `tollbooth`, and `golang.org/x/time/rate` finds no implementation. The only hit is an aspirational comment in an email package doc — *"Rate limit email sending to prevent abuse"* (`internal/email/doc.go:86`) — describing a future/other consideration, not code.
- `go.mod` pulls in no rate-limiting library.
- The middleware that *is* registered on the Echo server contains no limiter: `middleware.Recover()` and the CORS middleware (`server/server.go:51`–`52`, `server/cors.go:14`), plus static-file/SPA middleware on the frontend (`server/router/frontend/frontend.go:54`, `:59`) and the auth middleware on the gRPC-Gateway (`server/router/api/v1/v1.go:95`). None of these throttle requests.

The closest thing to a "limit" is **concurrency limiting, not rate limiting**, and it is not per-user: the file server uses `golang.org/x/sync/semaphore` to cap simultaneous thumbnail/image processing (`server/router/fileserver/fileserver.go:107`, `:116`, `:448`; also the `thumbnailSemaphore`/`imageProcessingSemaphore` weights of 3 and 2 set in `server/router/api/v1/v1.go`). These bound concurrent work globally to prevent memory exhaustion — they do not restrict how many requests a given user may make.
