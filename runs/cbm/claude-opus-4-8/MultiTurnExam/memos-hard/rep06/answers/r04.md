**Premise correction: Neither. The webhook delivery workers do not consume from any external message broker — there is no NATS, RabbitMQ, AMQP, or Kafka in this codebase.** A search across all Go files and `go.mod` for `nats`, `rabbitmq`, `amqp`, and `kafka` returns nothing, so there is no broker and no externally-declared queue.

**Actual mechanism (in-process Go channel + goroutine pool):**
- The "queue" is a buffered in-memory Go channel declared at package scope: `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` (`internal/webhook/webhook.go:39`) — capacity 128, no external broker.
- The "workers" are 4 goroutines started in the package `init()` that range over that channel and call `Post` for each payload (`internal/webhook/webhook.go:42`–`55`).
- Producers enqueue via `PostAsync`, a non-blocking send onto the channel that drops the payload (with a warning) if the buffer is full (`internal/webhook/webhook.go:184`–`196`).
- Each worker's `Post` performs the actual outbound HTTP POST via the shared `safeClient` (`internal/webhook/webhook.go:120`, delivery at `:152`).

So the whole pipeline — enqueue (`PostAsync`) → buffered channel (`asyncPostQueue`) → 4 consumer goroutines → `Post` — lives entirely inside the single server process in `internal/webhook/webhook.go`; nothing is consumed from or declared on a message broker.
