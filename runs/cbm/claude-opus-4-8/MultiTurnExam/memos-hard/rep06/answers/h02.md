### How the protection works

The delivery client isn't the default `http.Client`; it's a package-level `safeClient` whose transport uses `safeDialContext`. At dial time, `safeDialContext` resolves the target hostname and rejects any connection whose resolved IP falls in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`, backed by the loopback / RFC-1918 / link-local-IMDS / IPv6 CIDR list at `internal/webhook/validate.go:14`–`23`). Because the check runs on the *actual dialed address* rather than the pre-resolved URL, it also defeats DNS-rebinding (TOCTOU) attacks.

There is a second, earlier layer: `webhook.ValidateURL` (`internal/webhook/validate.go:62`) is called when a webhook is created/updated (e.g. `server/router/api/v1/user_service_webhooks.go:74`, `:161`, `:182`) to reject private-IP targets up front. Both layers can be disabled together via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`, `:45`) for self-hosted deployments that intentionally target local services.
