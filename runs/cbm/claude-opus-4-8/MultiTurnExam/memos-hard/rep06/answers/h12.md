### Determination method
There are three candidate implementations of `CreateMemo` — `store/db/sqlite/memo.go:16`, `store/db/postgres/memo.go`, and `store/db/mysql/memo.go` — each satisfying the `store.Driver` interface. I determined which actually runs by following the driver selection from configuration default down to dispatch:

1. **Default config → `"sqlite"`.** With no database flags, the `driver` setting defaults to `"sqlite"` in two places: `viper.SetDefault("driver", "sqlite")` (`cmd/memos/main.go:122`) and the flag default `rootCmd.PersistentFlags().String("driver", "sqlite", …)` (`cmd/memos/main.go:130`). This becomes `Profile.Driver` (`cmd/memos/main.go:43`, `internal/profile/profile.go:30`).

2. **Factory selects the concrete driver.** `NewDBDriver` switches on `profile.Driver`; the `"sqlite"` case constructs `sqlite.NewDB(profile)` (`store/db/db.go:14`,`:20`–`21`), so the `store.Driver` interface value is a `*sqlite.DB`.

3. **Save path dispatches through that interface.** Saving a memo calls `store.(*Store).CreateMemo` (`store/memo.go:109`), which delegates to `s.driver.CreateMemo(ctx, create)` (`store/memo.go:113`). Since `s.driver` is the `*sqlite.DB` from step 2, the interface call resolves to `sqlite.(*DB).CreateMemo`, whose body builds and executes the `INSERT` (`store/db/sqlite/memo.go:41`).

So the postgres/mysql `CreateMemo` methods are dead paths in a default install; only the SQLite one runs.
