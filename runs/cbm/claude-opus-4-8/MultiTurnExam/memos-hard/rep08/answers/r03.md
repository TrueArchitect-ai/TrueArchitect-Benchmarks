**Premise correction:** There is no nightly database-cleanup job, and nothing is registered in a cron scheduler — so there is no scheduled time to report. The premise is false on two counts.

Evidence:
- A cron scheduler library does exist at `internal/scheduler/` (`scheduler.go`, `parser.go`, `job.go`, supporting cron-expression parsing), **but it is never imported or used by any production code** — a search for imports of `usememos/memos/internal/scheduler` outside its own package and tests returns nothing, and there are no `scheduler.Register` / `scheduler.Schedule` call sites. It's effectively dead/library code.
- The server's only background work is started in `startBackgroundRunners` (`server/server.go:153-171`), which launches solely the **S3 presign runner** (`server/server.go:162-169`) on a 12-hour `time.Ticker` — not a nightly, cron-scheduled, or database-cleanup job.
- No scheduled DB cleanup/purge/vacuum exists. The `Cleanup`-named code that does exist is unrelated: the in-memory cache's `cleanupLoop`/`cleanup` for expired entries (`store/cache/cache.go:199,217`) and ordinary request-driven `DELETE` operations in the store/API (e.g. user/memo deletion), none of which is time-scheduled.

So there is no nightly database-cleanup cron job in this codebase.
