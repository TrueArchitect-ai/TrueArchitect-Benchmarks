**Premise correction:** There is no per-user API rate-limiting middleware in this repository, so there is nothing to register and no request limits to report. The premise is false.

Evidence:
- A repo-wide search for `rate limit` / `ratelimit` / `throttle` / `limiter` / the usual `golang.org/x/time/rate` dependency returns **zero** matches in Go source, and `go.mod` declares no rate-limiting/throttling library.
- The API is a Connect/gRPC service whose full interceptor chain is registered exactly once via `connect.WithInterceptors(...)` at `server/router/api/v1/v1.go:133`. The only interceptors that exist are, in `server/router/api/v1/connect_interceptors.go`: `MetadataInterceptor` (:22, header→metadata), `LoggingInterceptor` (:98), `RecoveryInterceptor` (:165, panic recovery), and `AuthInterceptor` (:208, authentication/authorization). None of them performs rate limiting or enforces per-user request quotas.
- Likewise, the Echo/HTTP layer in `server/server.go` and `server/router/fileserver/fileserver.go` registers routing/CORS/static handlers but no rate-limit middleware.

So there is no such middleware and no configured limits; the only per-user gating that exists is authentication/authorization (the `AuthInterceptor`), not rate limiting.
