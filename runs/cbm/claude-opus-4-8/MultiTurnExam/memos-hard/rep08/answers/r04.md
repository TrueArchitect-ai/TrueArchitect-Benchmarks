**Premise correction:** Neither. There is no external message broker in this codebase — no NATS and no RabbitMQ. A search confirms no such dependencies or client code exist (`go.mod` declares neither; no `nats`/`amqp`/`rabbitmq` imports anywhere). So "which broker" is a false choice, and there is no broker-declared queue.

**Actual mechanism:** Webhook delivery uses a purely in-process Go **buffered channel** as its work queue — `internal/webhook/webhook.go`:
- The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — a buffered channel with capacity 128 (`internal/webhook/webhook.go:39`).
- The "workers" are 4 goroutines started in `init()` that range over that channel and call `Post` for each payload (`internal/webhook/webhook.go:42-55`).
- Producers enqueue via `PostAsync`, which does a non-blocking `select` send onto the channel and **drops** the payload if the buffer is full (`internal/webhook/webhook.go:184-196`).
- Actual delivery is the outbound HTTP `POST` in `Post` (`internal/webhook/webhook.go:120`, sent at `:152`).

So the queue is declared in-memory in the `webhook` package itself (`internal/webhook/webhook.go:39`), consumed by in-process goroutine workers — not by any NATS/RabbitMQ broker.
