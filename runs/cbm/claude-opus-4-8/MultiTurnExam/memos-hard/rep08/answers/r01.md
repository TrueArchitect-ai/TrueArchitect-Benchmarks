**Premise correction:** There is no Redis in this codebase. A repo-wide search for `redis` returns zero matches in Go source and `go.mod` — the cache layer is **not** backed by Redis. So "where the Redis connection is configured" has no answer because no such connection exists.

**Actual mechanism:** The cache is a **thread-safe in-memory cache** implemented in `store/cache/cache.go` (`Cache` — "a thread-safe in-memory cache with TTL and memory management", `store/cache/cache.go:66`). Entries live in a Go map guarded by a mutex, with a background `cleanupLoop` (`store/cache/cache.go:199`) sweeping expired items.

- **Configuration site:** `store.New` in `store/store.go:38-53`, which builds a single `cache.Config` (`DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`) and creates three caches from it — including `userCache` (`store/store.go:52`). The same defaults are also defined in `store/cache/cache.go:59`.
- **TTL for user entries:** User records are cached via `s.userCache.Set(...)` in `Store.GetUser` (`store/user.go`), and `Set` uses the default TTL (`store/cache/cache.go:92-94`). So **user entries expire after 10 minutes** (`DefaultTTL = 10 * time.Minute`, `store/store.go:41`), with cleanup running every 5 minutes and eviction once the cache exceeds 1000 items — not a Redis TTL.
