When `DeleteMemo` runs (`store/memo.go:140-159`), the store layer explicitly deletes:
- `memo_relation` — rows where the memo is source or target (`store/memo.go:142,145`)
- `attachment` — linked attachments via `DeleteAttachment` → `DELETE FROM attachment` (`store/memo.go:153-157`, `store/db/sqlite/attachment.go:212`)
- `memo` — the memo row itself, plus comment memos deleted recursively (`store/db/sqlite/memo.go:239`; comment cascade in `server/router/api/v1/memo_service.go:573-577`)

Note: the `reaction` table is **not** touched by explicit cascade code — the API handler only lists reactions for the webhook payload (`server/router/api/v1/memo_service.go:545`), it does not delete them.
