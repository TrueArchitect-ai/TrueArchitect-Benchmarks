`memo`, `memo_relation`, `attachment`

When `Store.DeleteMemo` runs (`store/memo.go:140-158`) it explicitly deletes rows in:
- `memo_relation` — both where the memo is source and where it's the target (`store/memo.go:142,145`)
- `attachment` — every attachment linked to the memo, via `DeleteAttachment` (`store/memo.go:149-157`; the driver row delete is `store/attachment.go:148` — this also removes the backing storage file/blob, not a DB table)
- `memo` — the memo row itself (`store/memo.go:158`)

The API handler (`server/router/api/v1/memo_service.go:518-582`) also deletes comment memos first, but each goes back through `Store.DeleteMemo`, so the same three tables are involved. (Reactions are read for the webhook payload but are not deleted by this path.)
