**Interceptor path:** `web/src/connect.ts` — the `authInterceptor` (registered on the transport at line 188). It attaches the access token as a `Bearer` Authorization header, proactively refreshes near-expiry, and reactively refreshes on a 401 (helped by `web/src/auth-state.ts` for token storage and `refreshAccessToken`/`AuthService.refreshToken`).

**Token kinds:**
- Short-lived **JWT access token** (Bearer header, held in memory / auth-state; ~15 min).
- **Refresh token** (also JWT, delivered/stored as an HTTP `Set-Cookie` refresh-token cookie; rotated server-side, backed by a per-user refresh-token store record).
- (The backend also validates **Personal Access Tokens (PAT)** via the same authenticator.)

**Backend validation package:** `server/auth` — `Authenticator` in `server/auth/authenticator.go` validates them (`AuthenticateByAccessTokenV2`, `AuthenticateByRefreshToken`, `AuthenticateByPAT`), with token generation/parsing in `server/auth/token.go`.
