The interceptor manages an access token (Bearer header) and refreshes it via a refresh-token cookie. Backend validation is in `server/auth`.

q29.
- interceptor path: web/src/connect.ts (the `authInterceptor` / auth interceptor helpers; access-token attached as `Authorization: Bearer …`, refresh via `refreshAuthClient.refreshToken` with cookie `credentials: "include"`)
- token kinds: a short-lived **access token** (JWT, sent in the `Authorization: Bearer` header) and a **refresh token** (sent as an HTTP cookie, used to mint new access tokens)
- backend package path: server/auth (e.g. `server/auth/authenticator.go`, which validates the tokens)
