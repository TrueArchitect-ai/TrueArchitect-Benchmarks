**Delivery function** — `Post` in `internal/webhook/webhook.go:120`. This marshals the payload, builds the POST request (optionally adding HMAC-SHA256 Standard-Webhooks signature headers), and actually performs the outbound HTTP call via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. (Dispatch is triggered asynchronously through `PostAsync`/the worker queue, but the network send happens in `Post`.)

**Protection mechanism** — `safeDialContext` at `internal/webhook/webhook.go:59`, wired into the shared `safeClient`'s `http.Transport.DialContext` (`internal/webhook/webhook.go:29-37`). On every dial it resolves the target host and rejects any address in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`), whose CIDR list (`reservedCIDRs`, `internal/webhook/validate.go:14`) covers IPv4/IPv6 loopback, RFC-1918, and link-local including the cloud IMDS `169.254.169.254`. Because the check runs at dial time on the resolved IP, it also defeats DNS-rebinding. 

There is a second, earlier layer at webhook-configuration time — `ValidateURL` (`internal/webhook/validate.go:62`) enforces http/https scheme and the same `isReservedIP` check when a webhook is created — but the dial-time guard is the enforcement that protects the actual delivery. Both can be disabled via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for trusted self-hosted setups.
