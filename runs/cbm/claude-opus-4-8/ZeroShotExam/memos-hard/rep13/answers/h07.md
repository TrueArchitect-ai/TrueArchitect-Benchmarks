**Notes on the data layer / stored data:**
- The image itself is not a file on disk or in S3 — it is stored inline in the `user.avatar_url` column as a base64 `data:` URI (selected/scanned at `store/db/sqlite/user.go:159` and `:189`).
- Back in the handler, `serveUserAvatar` decodes that column via `parseDataURI` (fileserver.go:196 → :737), validates the MIME type against `avatarAllowedTypes`, then writes the bytes with `c.Blob` (fileserver.go:209).
- Access control before the lookup: on a non-anonymous instance, `getCurrentUser` (fileserver.go:174 → :708) requires a valid session/token; otherwise any user's avatar is served. Note `GetUser` here queries by `Username`, so the `find.ID` cache fast-path in `store/user.go:149` is skipped and it always goes through `ListUsers` to the driver/DB.
