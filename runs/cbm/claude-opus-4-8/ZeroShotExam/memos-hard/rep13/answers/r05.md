**Premise correction:** Memos does **not** have a GraphQL API, so there is no GraphQL schema to point to. A repo-wide search for `graphql` (across `.ts`, `.js`, `.json`, `.md`) returns zero matches. The README states it plainly: "Open & Extensible — MIT-licensed with full **REST and gRPC APIs** for integration" (`README.md`).

**Actual API surface** — the public API is defined in **Protocol Buffers**, not GraphQL:

- **Schema source of truth:** `proto/api/v1/*.proto` — one file per service, e.g.:
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/common.proto`
- **Build config:** `proto/buf.yaml` and `proto/buf.gen.yaml` (uses [buf](https://buf.build)).
- **Generated Go code:** `proto/gen/api/v1/*.pb.go` (messages), `*_grpc.pb.go` (gRPC), `*.pb.gw.go` (gRPC-gateway REST transcoding), and `proto/gen/api/v1/apiv1connect/*.connect.go` (Connect RPC).
- **REST/OpenAPI:** the proto HTTP annotations produce an OpenAPI spec at `proto/gen/openapi.yaml` (embedded via `proto/openapi_embed.go`).

So the API is exposed over **gRPC + Connect + REST (via gRPC-gateway)**, all generated from the `.proto` definitions in `proto/api/v1/`. Store-internal schemas live separately in `proto/store/*.proto` and are not part of the public API.
