**Determination method — how I picked the SQLite candidate among the three drivers:**

There are three implementations of `CreateMemo` with an `INSERT INTO memo`: `store/db/sqlite/memo.go`, `store/db/postgres/memo.go`, and `store/db/mysql/memo.go`. The one that actually runs is selected by driver configuration, which I traced through the call chain:

1. **Store dispatch is an interface, not a concrete choice.** `store.Store.CreateMemo` just delegates: `return s.driver.CreateMemo(ctx, create)` (`store/memo.go:113`). So the concrete implementation depends on which `store.Driver` was constructed.

2. **Driver construction is a switch on `profile.Driver`.** `db.NewDBDriver` (`store/db/db.go:14-32`) switches on `profile.Driver`: `"sqlite"` → `sqlite.NewDB`, `"mysql"` → `mysql.NewDB`, `"postgres"` → `postgres.NewDB`, else error. This driver is passed into `store.New(dbDriver, ...)` at `cmd/memos/main.go:57-64`.

3. **The default value of that flag is `sqlite`.** In `cmd/memos/main.go`, both the Viper default and the CLI flag default are `"sqlite"`: `viper.SetDefault("driver", "sqlite")` (line 122) and `rootCmd.PersistentFlags().String("driver", "sqlite", "database driver")` (line 130). With no database flags supplied, `profile.Driver == "sqlite"`.

Therefore the switch resolves to `sqlite.NewDB`, `s.driver` is the SQLite `*DB`, and the INSERT that runs is the one in `store/db/sqlite/memo.go:41-42`. The Postgres and MySQL `CreateMemo` methods exist but are unreachable in a default install because the driver switch never selects them.
