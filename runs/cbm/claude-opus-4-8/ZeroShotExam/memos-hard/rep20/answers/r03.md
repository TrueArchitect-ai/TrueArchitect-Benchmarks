**Premise correction:** There is no nightly *database-cleanup* job actually scheduled anywhere in this repository. The premise assumes such a job exists and is wired into the cron scheduler — it isn't.

What actually exists:

- `internal/scheduler/` is a general-purpose cron scheduler library (GitHub Actions-inspired), described in `internal/scheduler/doc.go`. It provides the machinery (`Register`, cron parsing, middleware) but does not itself register any application jobs.
- The only "cleanup at night" references are **illustrative documentation/test examples**, not a live job:
  - `internal/scheduler/doc.go:15-16` — a package-doc example named `"daily-cleanup"` with schedule `"0 2 * * *"` (2 AM daily).
  - `internal/scheduler/example_test.go:97-99` — an example test comment "Cleanup old data every night at 2 AM" with a job named `"cleanup"`, schedule `"0 2 * * *"`. Its handler just prints `"Cleaning up old data..."` — it touches no database.

Crucially, no production code registers a cleanup job. Searching non-test Go files for scheduler job registration turns up no `scheduler.New()` / `Register(&scheduler.Job{...})` calls in the actual server startup (`server/server.go` and elsewhere) — the scheduler library is defined but not instantiated with any real jobs.

So if you saw "2 AM" / `0 2 * * *` and inferred a real nightly DB cleanup, that value comes only from example code demonstrating the scheduler's API — there is no such job running against the database.
