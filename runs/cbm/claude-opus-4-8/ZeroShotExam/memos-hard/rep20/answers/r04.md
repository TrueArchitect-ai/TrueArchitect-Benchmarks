**Premise correction:** The question's premise is false — there is no message broker at all. The webhook delivery workers consume from neither NATS nor RabbitMQ. There is no external broker (no NATS/RabbitMQ/AMQP dependency exists anywhere in the codebase).

**Actual mechanism:** Webhook delivery is entirely in-process, using a buffered Go channel as the queue:

- The "queue" is declared in `internal/webhook/webhook.go:39` as a package-level buffered channel:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- In `init()` (`internal/webhook/webhook.go:42-55`), **4 goroutine workers** are spawned, each ranging over that channel and calling `Post()` to make the HTTP request.
- `PostAsync()` (`internal/webhook/webhook.go:184-196`) enqueues payloads with a non-blocking `select`; if the channel's 128-slot buffer is full, the dispatch is dropped with a warning rather than blocking.

So delivery is a bounded in-memory channel + fixed goroutine pool within the same server process — no broker, no external queue declaration.
