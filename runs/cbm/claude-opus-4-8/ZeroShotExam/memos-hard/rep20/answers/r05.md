**Premise correction:** The premise is mistaken — there is no GraphQL schema in this repository (`usememos/memos`). A search for `graphql` across the entire codebase returns zero matches. The public API is not a GraphQL API.

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC** service definitions, exposed over both gRPC and REST (via gRPC-gateway) and connect-web. The schema lives in:

- **`proto/api/v1/`** — the public API v1 `.proto` definitions. Each service is one file:
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/common.proto`
- **`proto/store/`** — internal storage message schemas (not the API surface).
- **`proto/gen/api/v1/`** — generated Go code, including `*.pb.gw.go` gRPC-gateway files that map the services to REST/HTTP endpoints.
- **`proto/gen/openapi.yaml`** — a generated OpenAPI (Swagger) spec derived from the protos, describing the REST surface (embedded via `proto/openapi_embed.go`).

Build config for the schema: `proto/buf.yaml` and `proto/buf.gen.yaml` (Buf toolchain). So the correct answer to "where is the API schema defined" is the Protobuf service definitions under `proto/api/v1/`, not GraphQL.
