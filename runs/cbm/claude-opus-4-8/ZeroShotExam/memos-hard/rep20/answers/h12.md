**How I determined it among the candidates:**

There are three implementations of `CreateMemo` — one per driver package: `store/db/sqlite/memo.go:16`, `store/db/mysql/memo.go`, and `store/db/postgres/memo.go`. They all satisfy the `store.Driver` interface (`CreateMemo` is declared at `store/driver.go:29`). I traced which one actually runs:

1. **Dispatch is interface-based, chosen once at startup.** `store.CreateMemo` just forwards to the driver: `store/memo.go:113` calls `s.driver.CreateMemo(ctx, create)`. The concrete `s.driver` is selected in `store/db/db.go:14` (`NewDBDriver`), which switches on `profile.Driver`: `"sqlite" → sqlite.NewDB` (`db.go:19-20`), `"mysql"`, `"postgres"`.

2. **The default driver is `sqlite`.** In `cmd/memos/main.go`, `Driver` is read from viper (`main.go:43`), whose default is set to `"sqlite"` (`main.go:122`, and the persistent flag default at `main.go:130`). With no `--driver`/`MEMOS_DRIVER` flag set, `profile.Driver == "sqlite"`. This is reinforced by `internal/profile/profile.go:110`, which only special-cases the empty DSN for the sqlite path.

So with a default install (no DB flags), `NewDBDriver` returns a `*sqlite.DB`, and the interface call in `store/memo.go:113` lands on `(*sqlite.DB).CreateMemo`, which runs the INSERT. The mysql/postgres versions are dead paths unless `--driver` is changed.
