**Premise correction:** The repository (usememos/memos) has **no per-user API rate-limiting middleware** — that premise is false. There is nothing to register and no request limits to report.

What actually exists is a Connect RPC interceptor chain, registered in `server/router/api/v1/v1.go:133-138` via `connect.WithInterceptors(...)`. It contains exactly four interceptors, all defined in `server/router/api/v1/connect_interceptors.go`:

- `NewMetadataInterceptor()` — converts HTTP headers to gRPC metadata (`connect_interceptors.go:24`)
- `NewLoggingInterceptor(...)` — request logging (`:102`)
- `NewRecoveryInterceptor(...)` — panic recovery (`:169`)
- `NewAuthInterceptor(...)` — authentication / anonymous-access policy (`:212`)

None of these performs rate limiting. Corroborating evidence:
- A repo-wide search for `ratelimit`/`rate_limit`/`throttle`/`limiter` in the Go sources returns no hits (the only "rate" match is unrelated wording in `internal/email/README.md`).
- `go.mod` pulls in no rate-limiting library (e.g. `golang.org/x/time/rate`, tollbooth, ulule/limiter).

So there is no per-user (or any) request-limit middleware, and consequently no configured request limits. The closest per-user gate is `AuthInterceptor`, which enforces authentication/authorization — not throttling.
