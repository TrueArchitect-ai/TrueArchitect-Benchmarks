**Premise correction:** There is no Redis in this repository (Memos). A repository-wide search for `redis` in Go sources returns nothing. The "cache layer" is not backed by Redis or any external cache server — it's a **thread-safe in-memory cache** implemented in pure Go using `sync.Map`.

**Actual mechanism:**

- **Where it's configured:** The cache is defined in `store/cache/cache.go` (the `Cache` type and its `Config`), and it is instantiated/configured in `store/store.go:39-53`. `Store.New()` builds a single `cache.Config` and creates three separate in-memory caches from it:
  - `instanceSettingCache`
  - `userCache`
  - `userSettingCache`

  There is no connection string, host, or port — nothing to connect to. The only "connection" is a background cleanup goroutine started per cache in `cache.New()` (`store/cache/cache.go:83`).

- **TTL that applies to user entries:** User entries live in `userCache`, which is created with the shared default config in `store/store.go:40-44`:
  ```go
  cacheConfig := cache.Config{
      DefaultTTL:      10 * time.Minute,
      CleanupInterval: 5 * time.Minute,
      MaxItems:        1000,
      OnEviction:      nil,
  }
  ```
  So user entries get a **10-minute TTL**. User writes go through `s.userCache.Set(...)` (`store/user.go:98,122,132,143,167`), and `Set` applies `DefaultTTL` (`store/cache/cache.go:93-95`). Expiration is enforced lazily on `Get` (`cache.go:135`) and proactively by the cleanup loop every 5 minutes (`cache.go:200-215`). A per-entry `SetWithTTL` override exists (`cache.go:98`) but is not used for user entries, so the effective TTL is the 10-minute default. Note there's also a `MaxItems: 1000` cap that can evict user entries early under load, independent of TTL (`cache.go:117-119`).
