**Delivery function** — `Post` in `internal/webhook/webhook.go:120` is where the outbound HTTP request actually executes (`safeClient.Do(req)` at `internal/webhook/webhook.go:152`). Deliveries are enqueued via `PostAsync` and drained by four worker goroutines started in `init()` (`internal/webhook/webhook.go:42`), each calling `Post`.

**Protection mechanism** — SSRF protection is enforced at dial time by `safeDialContext` (`internal/webhook/webhook.go:59`), wired into the shared `safeClient`'s `Transport.DialContext` (`internal/webhook/webhook.go:32`). It resolves the target hostname and rejects any address in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`), which checks against the `reservedCIDRs` list — loopback, RFC-1918, IPv6 ULA/link-local, and cloud IMDS `169.254.169.254` (`internal/webhook/validate.go:14`). Because the check runs on the *actually-resolved* IP at connection time, it also defeats DNS-rebinding attacks. This can be disabled for trusted self-hosted setups via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`).

There is also an up-front check, `ValidateURL` (`internal/webhook/validate.go:62`), applied when a webhook URL is configured (scheme + resolved-IP validation), but the authoritative runtime guard on the actual delivery is `safeDialContext`.

So: delivery function — `Post`, `internal/webhook/webhook.go:120`; protection mechanism — `safeDialContext`/`isReservedIP`, `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:44`.
