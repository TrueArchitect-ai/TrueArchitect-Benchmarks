**Delivery function** — `internal/webhook/webhook.go`

The outbound HTTP delivery executes in `Post()` (`internal/webhook/webhook.go:120`), which marshals the payload, optionally adds Standard-Webhooks HMAC-SHA256 signature headers, and performs the actual network call at `safeClient.Do(req)` (`internal/webhook/webhook.go:152`). Dispatch is normally triggered asynchronously via `PostAsync()` (line 184), whose background workers (started in `init`, lines 42–55) call `Post`.

**Protection mechanism** — `internal/webhook/webhook.go` (dial-time guard) backed by `internal/webhook/validate.go`

The `Post` call uses a shared `safeClient` whose `http.Transport` installs `safeDialContext` as its `DialContext` (`internal/webhook/webhook.go:32-37`, `59-77`). At dial time `safeDialContext` resolves the target host and rejects the connection if any resolved address falls in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44-54`), which checks against `reservedCIDRs` — loopback, RFC-1918, link-local/cloud IMDS `169.254.169.254`, and IPv6 equivalents (`internal/webhook/validate.go:14-23`). Because the check happens at dial time on the actually-resolved IP, it also defeats DNS rebinding.

Notes:
- This is toggleable: `AllowPrivateIPs` (`internal/webhook/validate.go:41`) disables the guard for self-hosted deployments that intentionally target the local network.
- There is also a creation-time check, `ValidateURL` (`internal/webhook/validate.go:62`), which validates scheme and rejects reserved IPs when a webhook URL is registered — but the enforcement that protects the *actual outbound delivery* is `safeDialContext`.
