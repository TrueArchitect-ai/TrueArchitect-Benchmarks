**How it works.** Users register webhook endpoints (an arbitrary `Url`) via the `CreateUserWebhook`/`UpdateUserWebhook` RPCs (`server/router/api/v1/user_service_webhooks.go`). Memo lifecycle RPC handlers then load those hooks with `s.Store.GetUserWebhooks(...)` and dispatch to each `hook.Url` through the `DispatchMemo*Webhook` helpers (`server/router/api/v1/memo_service_webhooks.go`), which enqueue via `webhook.PostAsync` → and ultimately deliver via `webhook.Post`.

**RPC handlers that can transitively trigger an outbound HTTP request to a user-configured URL:**

- `CreateMemo` — `server/router/api/v1/memo_service.go:70` → `DispatchMemoCreatedWebhook` (call at :157)
- `DeleteMemo` — `server/router/api/v1/memo_service.go:518` → `DispatchMemoDeletedWebhook` (call at :562)
- `UpdateMemo` — `server/router/api/v1/memo_service.go:401` → `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`
- `CreateMemoComment` — `server/router/api/v1/memo_service_comments.go:20` → `DispatchMemoCommentCreatedWebhook` (call at :119)
- `SetMemoAttachments` — `server/router/api/v1/memo_attachment_service.go:16` → `dispatchMemoUpdatedSideEffects` (call at :48)
- `SetMemoRelations` — `server/router/api/v1/memo_relation_service.go:16` → `dispatchMemoUpdatedSideEffects` (call at :48)

**Convergence function:** all paths funnel through `webhook.Post` — `internal/webhook/webhook.go:120` — which builds the request and issues the actual outbound call via `safeClient.Do(req)` at `internal/webhook/webhook.go:152`. (The handlers call `webhook.PostAsync` at `internal/webhook/webhook.go:184`, which merely enqueues onto `asyncPostQueue`; the queue workers then invoke `Post`, so `Post` is the single point where every path delivers.)
