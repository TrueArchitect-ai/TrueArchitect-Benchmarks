**No.** The MySQL driver is only constructed inside the driver-selection factory.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:14`, which switches on `profile.Driver` and calls `mysql.NewDB(profile)` at `store/db/db.go:22` for the `"mysql"` case.
- `mysql.NewDB` (defined at `store/db/mysql/mysql.go:20`) is the only exported constructor, and it returns the `*DB` driver struct (`store/db/mysql/mysql.go:14`, `:29`, `:40`). The `DB` struct itself is only instantiated internally within that function.
- Grepping every call to `NewDB` across the repo shows `mysql.NewDB` appears **only** at `store/db/db.go:22`. Direct `sqlite.NewDB` calls exist in a couple of test files, but there is no direct `mysql.NewDB` call anywhere outside the factory (including tests).
- Grepping all references to the memos `store/db/mysql` package outside the package itself yields only `store/db/db.go` (the import and the factory call). The other `mysql`-named references in `store/test/containers.go` are unrelated third‑party packages — `github.com/testcontainers/testcontainers-go/modules/mysql` and `github.com/go-sql-driver/mysql` (aliased `mysqldriver`) — not the memos MySQL driver.

So outside `NewDBDriver`, the MySQL driver is never constructed directly.
