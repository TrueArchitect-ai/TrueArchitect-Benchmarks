The premise is mistaken: there is **no nightly database-cleanup job registered in the cron scheduler**, so there is no scheduled run time to report.

What actually exists:

- `internal/scheduler/` is a standalone, general-purpose cron scheduler *library* (GitHub Actions–inspired, zero external dependencies). It provides the machinery (`Register`, `Start`, cron parsing) but registers no jobs of its own.
- The only reference to a "cleanup" job anywhere in the codebase is an **illustrative example in a doc comment**, not live code:
  - `internal/scheduler/doc.go:14-20` shows a sample `Name: "daily-cleanup"` job with `Schedule: "0 2 * * *"` (commented as "2 AM daily") and a placeholder handler (`// Your cleanup logic here`).
- Crucially, the `internal/scheduler` package is **never imported or instantiated** anywhere in the application. A search across `server/`, `cmd/`, and `internal/` (excluding the package itself and tests) finds no import of `internal/scheduler` and no `.Register(...)` call wiring up any real job — database cleanup or otherwise.

So the "2 AM" figure you may be thinking of is just the schedule string in a documentation example (`0 2 * * *`), not an actual nightly database-cleanup job running in production.
