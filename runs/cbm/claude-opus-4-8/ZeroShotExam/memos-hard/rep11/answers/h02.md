**delivery function** — `Post` in `internal/webhook/webhook.go` (lines 119–180). This is where the outbound HTTP POST actually executes: it marshals the payload, builds the request (optionally adding HMAC-SHA256 signature headers), and fires it via `safeClient.Do(req)` at line 152. `PostAsync` (line 184) merely enqueues onto a bounded channel drained by 4 background workers that call `Post`.

**protection mechanism** — `safeDialContext` in `internal/webhook/webhook.go` (lines 59–77), the `DialContext` of the shared `safeClient`'s `http.Transport` (lines 32–37). At dial time it resolves the target host and rejects any address in a reserved/private range via `isReservedIP`, which checks the CIDR list in `internal/webhook/validate.go` (lines 14–54). Because the check happens at the moment of dialing on the actually-resolved IPs, it also defeats DNS-rebinding.

This is the real SSRF guard. Note the supporting layers:
- **`ValidateURL`** — `internal/webhook/validate.go` (lines 62–83) is an up-front check at webhook-registration time (scheme must be http/https; must not resolve to a reserved IP), but it's TOCTOU-vulnerable on its own; the dial-time check is what protects the actual request.
- Both checks can be disabled by the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`, consumed in `isReservedIP` at line 45) for self-hosted deployments targeting local services.

Summary:
- delivery function — `internal/webhook/webhook.go` (`Post`, lines 119–180; dispatched via `safeClient.Do` at line 152)
