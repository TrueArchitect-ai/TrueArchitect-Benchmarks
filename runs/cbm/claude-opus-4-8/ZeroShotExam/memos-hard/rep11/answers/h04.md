**Yes — but only in a test, and only as a zero-value struct literal.**

Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14`. It is the sole caller of the MySQL driver's real constructor `mysql.NewDB` (`store/db/db.go:22`). Grepping the whole repo for `mysql.NewDB` returns exactly that one call site, so the production constructor is never invoked outside the factory.

- However, the MySQL driver's struct type itself is constructed directly in one place outside the factory: `store/db/mysql/auth_config_test.go:12` does `db := &DB{}` (an empty zero-value `mysql.DB`) to exercise the pure method `IsRetryableAuthenticationMutationError`, which needs no DB connection. This is an in-package unit test (`package mysql`), so it can reference the unexported `DB` type directly and bypass `NewDB`.

- No other direct constructions exist: grepping for `mysql.DB{` / `&mysql.DB` outside the package returns nothing, and the only `DB{...}` literal inside the package (besides the test) is `driver := DB{profile: profile}` inside `NewDB` itself (`store/db/mysql/mysql.go:29`), which is the constructor's own body.

So: no direct construction in application/production code — the factory funnels all real instantiation through `mysql.NewDB` — but yes, one direct struct-literal construction of the driver exists in a unit test.
