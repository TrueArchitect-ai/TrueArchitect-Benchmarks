**Premise correction:** The webhook delivery workers consume from *neither* NATS nor RabbitMQ. This repository (memos) uses no external message broker at all — a full-tree search for `nats`, `rabbitmq`, and `amqp` finds no such dependency or usage (the only `nats` hits are substrings inside translation JSON files).

**Actual mechanism:** Delivery is handled entirely in-process by a **buffered Go channel** acting as the queue, drained by a fixed pool of goroutine workers.

- The "queue" is declared as a package-level buffered channel in `internal/webhook/webhook.go:39`:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- The workers are 4 goroutines spawned in `init()` at `internal/webhook/webhook.go:42-55`, each looping over `asyncPostQueue` and calling `Post(payload)` to make the outbound HTTP request.
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send onto the channel and simply drops (logs a warning) the payload if the buffer of 128 is full.

So the mechanism is an in-memory, bounded channel + goroutine worker pool inside the single server process — not a distributed message broker.
