The browser requests `GET /file/users/:identifier/avatar`. The chain from serving handler to stored data:

```
serveUserAvatar — server/router/fileserver/fileserver.go:168
getUserByUsername — server/router/fileserver/fileserver.go:715
(*store.Store).GetUser — store/user.go:148
(*store.Store).ListUsers — store/user.go:136
(*sqlite.DB).ListUsers — store/db/sqlite/user.go:88
```

Details:
- **`serveUserAvatar`** (`server/router/fileserver/fileserver.go:168`) is the registered handler for the route `fileGroup.GET("/users/:identifier/avatar", ...)` (`fileserver.go:124`). For another user, it takes the `identifier` path param, does an anonymous-access check, then looks up the user and decodes `user.AvatarURL` (a base64 data URI) into image bytes served via `c.Blob` (`fileserver.go:196`–`209`).
- **`getUserByUsername`** (`fileserver.go:715`) calls `s.Store.GetUser(ctx, &store.FindUser{Username: &identifier})`.
- **`(*store.Store).GetUser`** (`store/user.go:148`) checks the in-memory `userCache` (only when finding by ID; here it's by username, so it misses) and delegates to `ListUsers`.
- **`(*store.Store).ListUsers`** (`store/user.go:136`) calls the DB driver `s.driver.ListUsers` and populates the cache.
- **`(*sqlite.DB).ListUsers`** (`store/db/sqlite/user.go:88`) builds the `WHERE username = ?` clause and executes the SQL `SELECT` (including the `avatar_url` column, per `store/db/sqlite/user.go:14`) against the database — the actual stored data. Equivalent driver implementations exist for MySQL/Postgres under `store/db/`.

The stored value is the user's `avatar_url` column (`store/user.go:43`), returned up the chain and decoded/served as the image.
