Memo-view visibility is enforced at these distinct server surfaces:

Single-memo read (GetMemo, and the parent/comment paths that reuse it) — `checkMemoReadAccess` gates archived/private/protected memos — server/router/api/v1/memo_service.go:39 (called at :356, :367 and server/router/api/v1/memo_service_comments.go:148)

Memo listing (ListMemos) — restricts results via `VisibilityList`/CEL filter (`creator_id == N || visibility in ["PUBLIC","PROTECTED"]`, or PUBLIC-only for anonymous) — server/router/api/v1/memo_service.go:218-227

RSS feed — lists only `store.Public` memos — server/router/rss/rss.go:90 (and :141)

Frontend router (sitemap / SSR) — lists only `store.Public` memos — server/router/frontend/frontend.go:150

File server (serving a memo's attachments, gated on the memo's visibility) — server/router/fileserver/fileserver.go:677,699

The first three (API single-read, API list, and the RSS/frontend public-only surfaces) are the core independent enforcement sites; the fileserver additionally re-enforces memo visibility when deciding whether to serve a memo's attachment.

Note: the batch relation converter also applies the same visibility filter when expanding memo relations — server/router/api/v1/memo_service_converter.go:182-187.
