The premise is incorrect: this repository (the `usememos/memos` server) has **no per-user API rate-limiting middleware** — there is nothing to register and there are no request limits to report.

What actually exists:

- The API request pipeline registers only four interceptors in `server/router/api/v1/v1.go:133-137` — `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor`. None of them limit request rates. The gRPC-Gateway path adds only an auth middleware (`server/router/api/v1/v1.go:69-97`), and the top-level Echo server adds only `Recover()` and CORS (`server/server.go:51-52`, `server/cors.go`).
- A repository-wide search for `rate limit / ratelimit / throttle / limiter` across all Go, TypeScript, and `go.mod` turns up **no rate-limiting logic and no rate-limiter dependency**. The only two matches are non-functional:
  - `internal/email/doc.go:86` — a documentation comment listing "Rate limit email sending to prevent abuse" as a design consideration, not an implementation.
  - A request **size** limit (not a rate limit): `maxAPIRequestBytes = 256 << 20` (256 MiB), applied via `http.MaxBytesHandler` / `connect.WithReadMaxBytes` in `server/router/api/v1/v1.go:20,126,141,144`. This caps the bytes per request body, not the number of requests per user.

So, if you were looking for per-user request-rate limits, none are configured anywhere in this codebase. The closest real control is the 256 MiB per-request byte cap in `server/router/api/v1/v1.go`.
