**Premise correction:** There is no GraphQL schema in this repository. This is the **memos** project (`github.com/usememos/memos`), a Go backend with a TypeScript/React frontend. A repository-wide search for `graphql` in tracked source returns zero matches. The public API is **not** GraphQL — it's defined with **Protocol Buffers over gRPC**, exposed additionally as REST via grpc-gateway and via Connect.

**Actual API surface:**

- **Schema source of truth:** `proto/api/v1/*.proto` — the service/message definitions for the public API, one file per service:
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/ai_service.proto`
  - `proto/api/v1/common.proto` (shared types)
  - Design conventions documented in `proto/api/v1/README.md` (follows Google AIPs).

- **Code generation:** `proto/buf.gen.yaml` drives `buf` to generate Go stubs (protobuf, grpc, connectrpc, grpc-gateway) into `proto/gen/`, an **OpenAPI** spec via the gnostic-openapi plugin, and TypeScript types into `web/src/types/proto`. (`proto/buf.yaml`, `proto/buf.lock` are the module config.)

- **Server wiring:** the generated services are served under `server/router/api/v1/`, with the gateway/OpenAPI embedding in `proto/openapi_embed.go`.

So the closest analog to "the schema for the public API" is the set of `.proto` files under `proto/api/v1/`, with an auto-generated OpenAPI (not GraphQL) description as the HTTP-facing surface.
