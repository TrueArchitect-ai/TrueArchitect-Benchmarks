**Premise correction:** There is no per-user (or any) API rate-limiting middleware registered in this repository, so it has no request limits to report. The premise is mistaken.

What the codebase actually contains:

- **The API server's middleware chain has no rate limiter.** The Connect/gRPC interceptors are registered in `server/router/api/v1/v1.go:133-138`, and the full set is: `NewMetadataInterceptor`, `NewLoggingInterceptor`, `NewRecoveryInterceptor`, and `NewAuthInterceptor` (defined in `server/router/api/v1/connect_interceptors.go`). None of these throttle requests. The only request-size guard is `maxAPIRequestBytes` via `http.MaxBytesHandler` (`server/router/api/v1/v1.go:141,144`) — a byte-size cap, not a request-rate limit.

- **The word "middleware" elsewhere refers to the background job scheduler, not HTTP.** `internal/scheduler/middleware.go` defines `Recovery` and `Logging` middleware that wrap `JobHandler`s for scheduled jobs — unrelated to API requests and containing no rate limiting.

- **The only "rate limit" string in the whole Go codebase is an aspirational doc comment**, not an implementation: `internal/email/doc.go:86` — `// - Rate limit email sending to prevent abuse`.

A repository-wide search for `rate`/`ratelimit`/`throttle`/`quota` across `internal/` and `server/` turns up no limiter registration, no per-user token bucket, and no configured request limits.
