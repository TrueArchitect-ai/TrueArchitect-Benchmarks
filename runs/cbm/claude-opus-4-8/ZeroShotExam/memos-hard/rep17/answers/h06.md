## How the paths work

Users configure webhook URLs that are stored per-user; the dispatch code reads them via `s.Store.GetUserWebhooks(...)` and copies `hook.Url` into the payload (`server/router/api/v1/memo_service_webhooks.go:67`, `:41`). That URL is entirely user-controlled.

**RPC handlers (gRPC methods on `APIV1Service`) that can transitively fire a webhook**, from the call graph:

- `CreateMemo` → `DispatchMemoCreatedWebhook`
- `UpdateMemo` / `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`
- `DeleteMemo` → `DispatchMemoDeletedWebhook`
- `CreateMemoComment` → `DispatchMemoCommentCreatedWebhook`
- `SetMemoRelations` and `SetMemoAttachments` → `DispatchMemoUpdatedWebhook`

Each `Dispatch*` method (except the comment one) funnels into `dispatchMemoRelatedWebhook` (`server/router/api/v1/memo_service_webhooks.go:48`), which builds the payload and calls `webhook.PostAsync`. The comment handler calls `webhook.PostAsync` directly (`:43`).

**Convergence before delivery:** `webhook.PostAsync` (`internal/webhook/webhook.go:184`) only enqueues onto the async dispatch queue; every enqueued payload — regardless of which handler originated it — is ultimately delivered by the single function **`webhook.Post`** (`internal/webhook/webhook.go:120`), which is where `http.NewRequest("POST", requestPayload.URL, ...)` is built and `safeClient.Do(req)` actually issues the outbound HTTP request to the user-configured URL (lines 126 and 152).
