**Premise correction:** This repository (Memos, the note-taking app) has **no GraphQL schema and no GraphQL API at all**. A repo-wide search for `graphql`/`gql` returns zero hits in source. The README explicitly describes the integration surface as "full **REST and gRPC** APIs" — GraphQL is not part of the design.

**Actual API surface:** The public API is defined as **Protocol Buffers (gRPC)** service definitions, not a GraphQL schema.

- Schema/IDL lives in `proto/api/v1/*.proto` — one `.proto` file per service:
  - `proto/api/v1/memo_service.proto`
  - `proto/api/v1/user_service.proto`
  - `proto/api/v1/auth_service.proto`
  - `proto/api/v1/attachment_service.proto`
  - `proto/api/v1/shortcut_service.proto`
  - `proto/api/v1/idp_service.proto`
  - `proto/api/v1/instance_service.proto`
  - `proto/api/v1/ai_service.proto`
  - plus `proto/api/v1/common.proto`
- Store-layer protos are under `proto/store/`.
- Build config is `proto/buf.yaml` and `proto/buf.gen.yaml` (buf toolchain), with generated Go code in `proto/gen/api/v1/`.
- The **REST** surface is layered on top of these same protos via **gRPC-gateway** annotations — e.g. `proto/api/v1/memo_service.proto` declares `option (google.api.http) = {get: "/api/v1/memos"}`. So REST endpoints are derived from the proto definitions rather than defined separately.

In short: the "GraphQL schema" doesn't exist — the equivalent API definition is the set of gRPC/protobuf service files in `proto/api/v1/`, which also generate the REST (`/api/v1/...`) endpoints.
