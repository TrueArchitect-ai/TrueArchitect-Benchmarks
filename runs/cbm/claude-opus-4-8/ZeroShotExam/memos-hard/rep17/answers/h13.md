**Interface:** `markdown.Service` — defined in `internal/markdown/markdown.go:31-55` (methods: `ExtractAll`, `ExtractTags`, `ExtractProperties`, `RenderMarkdown`, `RenderHTML`, `GenerateSnippet`, `ValidateContent`, `RenameTag`).

**impl —** There is exactly **one** concrete runtime implementation: the unexported `service` struct (`internal/markdown/markdown.go:57-60`), which wraps a `goldmark.Markdown` engine. Its methods parse content into a goldmark AST and, for `RenderMarkdown`/`RenameTag`, delegate to the concrete `renderer.NewMarkdownRenderer()` (`internal/markdown/markdown.go:250,451`); `RenderHTML` uses goldmark's built-in HTML converter (`internal/markdown/markdown.go:257`).

**construction —** `service` is only ever produced by `markdown.NewService(...)` (`internal/markdown/markdown.go:84-113`), which returns it as a `Service`. In production it is constructed once, inside `NewAPIV1Service` with the tag + mention extensions enabled:
- `server/router/api/v1/v1.go:48-51` — `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())`.

That single instance is then propagated (not re-constructed) to the other holders in `server/server.go:85` (passed to `NewRSSService`). (A separate test-only construction exists at `server/router/api/v1/test/test_helper.go:44`.)
