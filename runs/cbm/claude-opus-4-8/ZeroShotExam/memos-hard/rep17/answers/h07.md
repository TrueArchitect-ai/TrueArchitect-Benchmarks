The route `GET /file/users/:identifier/avatar` serves another user's avatar. The image bytes are not a separate file — they're stored inline in the `user.avatar_url` column as a base64 data URI, decoded at serve time. Hops from the browser request down to stored data:

- `serveUserAvatar` — server/router/fileserver/fileserver.go:168 (serving handler; route registered at fileserver.go:124)
- `getUserByUsername` — server/router/fileserver/fileserver.go:715
- `Store.GetUser` — store/user.go:148
- `Store.ListUsers` — store/user.go:136
- `DB.ListUsers` (SQLite driver) — store/db/sqlite/user.go:88 (runs `SELECT ... avatar_url ... FROM user`, the data layer)
- stored data: `user.avatar_url` column (base64 data URI), scanned into `store.User.AvatarURL` at store/db/sqlite/user.go:180-188

Back in the handler, `parseDataURI` (fileserver.go:737) decodes `user.AvatarURL` and `c.Blob` (fileserver.go:209) writes the image bytes to the response.

(Postgres/MySQL have parallel `ListUsers` drivers at store/db/postgres/user.go and store/db/mysql/user.go; SQLite shown as the representative path.)
