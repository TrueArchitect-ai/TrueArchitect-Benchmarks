I have the answer. The outbound HTTP delivery executes in `Post`, and the primary runtime protection is the SSRF-guarding dialer.

h02.

**delivery function** — `Post` in `internal/webhook/webhook.go:120` (dispatched by the async workers set up in `init`/`PostAsync`, and it calls `safeClient.Do(req)` at `internal/webhook/webhook.go:152` to actually send the HTTP POST)

**protection mechanism** — `safeDialContext` in `internal/webhook/webhook.go:59`, the custom `DialContext` on `safeClient`'s transport (`internal/webhook/webhook.go:32-37`). At dial time it resolves the target host and rejects any address in a reserved/private range via `isReservedIP` (`internal/webhook/validate.go:44`), which checks the `reservedCIDRs`/`reservedNetworks` list (loopback, RFC-1918, link-local/cloud IMDS `169.254.169.254`, and IPv6 equivalents) in `internal/webhook/validate.go:14-54`. Because the check happens at connection time, it also defeats DNS-rebinding.

Two supporting notes:
- There is also an up-front `ValidateURL` check (`internal/webhook/validate.go:62`) run when a webhook URL is configured, but the authoritative runtime guard is the dialer.
- The guard can be disabled via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for self-hosted deployments that intentionally target local services.
