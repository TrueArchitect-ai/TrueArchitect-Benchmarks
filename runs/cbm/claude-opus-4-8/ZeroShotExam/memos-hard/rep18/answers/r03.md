The premise is mistaken — there is no nightly database-cleanup job in this repository's cron scheduler.

What actually exists:

- **`internal/scheduler/`** is a standalone, GitHub-Actions-inspired cron scheduler *library* (`scheduler.go`, `job.go`, `parser.go`, etc.). It parses cron specs and can run jobs, but it is **not wired into the running server** — the only references to `internal/scheduler` outside the package itself are its own tests (`example_test.go`, `integration_test.go`). No production code calls `scheduler.New()` or `.Register(...)` with any job, cleanup or otherwise. The cron specs you see in that package (e.g. `"0 0 * * *"` at `internal/scheduler/job.go:21`) are just documentation examples.

- The only actual recurring background task the server starts is the **S3 presign runner** (`server/server.go:162-170`, `server/runner/s3presign/runner.go`), and it is not a cron job and not database cleanup: it refreshes presigned S3 URLs on a fixed interval — "Schedule runner every 12 hours" (`server/runner/s3presign/runner.go:26`), not nightly.

A search for cleanup/purge/vacuum-style scheduled work (`grep` for `cleanup|purge|vacuum|DeleteExpired|prune` across `server/`, `store/`, `internal/`) turns up only inline, request-triggered deletions (e.g. attachment cleanup on memo/user delete in `server/router/api/v1/memo_service.go` and `user_service.go`) — nothing scheduled.

So there is no scheduled time to report, because no such nightly cleanup job is registered.
