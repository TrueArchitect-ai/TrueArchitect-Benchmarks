Yes — but only in a unit test, and only as a bare zero-value struct.

Evidence:

- **The driver-selection factory** is `NewDBDriver` in `store/db/db.go:14-32`, which dispatches on `profile.Driver` and calls `mysql.NewDB(profile)` at `store/db/db.go:22`.

- **The proper MySQL driver constructor** is `mysql.NewDB` (defined at `store/db/mysql/mysql.go:20`). Grepping the whole codebase for `mysql.NewDB` returns exactly one call site — `store/db/db.go:22`, i.e. the factory itself. So the real constructor is *never* invoked directly anywhere else.

- **However**, the `DB` struct is constructed directly (not via `NewDB`) in one place: `store/db/mysql/auth_config_test.go:12`, `db := &DB{}`. This is a unit test inside the `mysql` package that creates a zero-value `DB` solely to call the pure method `IsRetryableAuthenticationMutationError`; it does not open a connection or produce a usable driver.

No other file imports/constructs the driver — the only external reference to the `store/db/mysql` package outside the package itself is the factory's import at `store/db/db.go:8`.

So: for practical purposes the MySQL driver is only ever constructed through the factory; the sole exception is a test-only bare `&DB{}` in `store/db/mysql/auth_config_test.go`.
