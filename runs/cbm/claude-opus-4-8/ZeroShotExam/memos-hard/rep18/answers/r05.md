**Premise correction:** There is no GraphQL schema in this repository. Memos (`usememos/memos`) does not expose a GraphQL API at all — a repo-wide, case-insensitive grep for `graphql`/`GraphQL` across all `.go`, `.ts`, `.js`, `.py`, `.json` etc. sources returns **zero** hits. So the question's premise is mistaken; there is nothing to point to for a "GraphQL schema."

**Actual API surface:** The public API is defined as **Protocol Buffers (gRPC), served over Connect/gRPC**, not GraphQL. The schema of record is the set of `.proto` files:

- **`proto/api/v1/`** — the public API definitions (the "schema"):
  - `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `instance_service.proto`, `ai_service.proto`, `common.proto`
- **`proto/store/`** — internal storage message definitions
- **`proto/buf.yaml`** / **`proto/buf.gen.yaml`** — buf config that governs code generation
- **`proto/gen/api/v1/`** and **`proto/gen/store/`** — the generated Go stubs produced from the protos

The generated definitions are wired up and served in **`server/router/api/v1/`**, using Connect (connectrpc) — see `server/router/api/v1/connect_services.go`, `connect_handler.go`, `connect_interceptors.go`, and `v1.go`. Additional non-GraphQL surfaces exist alongside it: `server/router/rss` (RSS feeds) and `server/router/mcp` (Model Context Protocol).

So: the "schema for the public API" lives in **`proto/api/v1/*.proto`** (protobuf/gRPC), served via Connect from `server/router/api/v1/` — there is no GraphQL involved.
