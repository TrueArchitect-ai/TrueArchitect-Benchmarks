**Premise correction:** There is no per-user API rate-limiting middleware in this repository, so there is nothing registered and no request limits to report. The question's premise is false.

What actually exists:

- The Connect/gRPC interceptor chain is registered in `server/router/api/v1/v1.go:133-137` via `connect.WithInterceptors(...)`, and it contains exactly four interceptors: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (all defined in `server/router/api/v1/connect_interceptors.go`). None of these performs rate limiting — `AuthInterceptor` does authentication/access checks, not throttling.

- A grep for rate-limiting primitives (`golang.org/x/time/rate`, `NewLimiter`, `Limiter`, `tollbooth`, `throttle`) across the Go source returns **no matches** in any implemented code. The only mentions of "rate limit" are documentation suggestions in `internal/email/README.md:286-295` and `internal/email/doc.go:86`, describing a hypothetical email-sending limiter — not an API middleware, and not wired into the server.

The closest thing to an actual "limit" applied to API requests is a **request body size cap**, not a rate cap:

- `maxAPIRequestBytes = 256 << 20` (256 MiB), defined at `server/router/api/v1/v1.go:20`, and enforced via `http.MaxBytesHandler(...)` and `connect.WithReadMaxBytes(...)` at `server/router/api/v1/v1.go:126,141,144`. This bounds per-request payload size globally, not per-user request frequency.

So: no per-user rate-limiting middleware is registered anywhere, and the only enforced API limit is a 256 MiB request-size limit.
