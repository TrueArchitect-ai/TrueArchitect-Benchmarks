**Premise correction:** There is no Redis anywhere in this repository. A `git grep` for "redis" returns zero matches. The cache layer is a purely **in-process, in-memory** cache — there is no external cache server or connection to configure.

**Actual mechanism:**

- The cache implementation is a thread-safe in-memory store built on `sync.Map` with a background TTL-cleanup goroutine, defined in `store/cache/cache.go` (`type Cache`, created via `cache.New(config)`).
- It is "configured" (not connected — instantiated) in `store/store.go:38-58`. `Store.New` builds a `cache.Config` and creates three separate cache instances, one of which is `userCache` (`store/store.go:52`, declared at `store/store.go:28`).
- The config is set inline at `store/store.go:40-45`:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
  
  (This mirrors `cache.DefaultConfig()` in `store/cache/cache.go:57-64`.)

**TTL for user entries:** User records are written to `userCache` via `s.userCache.Set(...)` (e.g. `store/user.go:98, 122, 132, 143, 167`). `Set` applies the cache's `DefaultTTL` (`store/cache/cache.go:93-95`) — so **user entries expire 10 minutes after they are written**. No per-user custom TTL (`SetWithTTL`) is used for the user cache; expired entries are removed lazily on `Get` and swept by the cleanup loop every 5 minutes.
