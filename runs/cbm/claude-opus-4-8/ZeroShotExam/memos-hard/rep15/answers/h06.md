**RPC handlers that can transitively trigger an outbound HTTP request to a user-configured webhook URL** (all `APIV1Service` methods in `server/router/api/v1/`):

- `CreateMemo` — `memo_service.go:157` → `DispatchMemoCreatedWebhook`
- `UpdateMemo` — `memo_service.go:513` → `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook` (`memo_update_helpers.go:67`)
- `DeleteMemo` — `memo_service.go:562` → `DispatchMemoDeletedWebhook`
- `CreateMemoComment` — `memo_service_comments.go:119` → `DispatchMemoCommentCreatedWebhook`
- `SetMemoAttachments` — `memo_attachment_service.go:48` → `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`
- `SetMemoRelations` — `memo_relation_service.go:48` → `dispatchMemoUpdatedSideEffects` → `DispatchMemoUpdatedWebhook`

Each `Dispatch*Webhook` helper (`server/router/api/v1/memo_service_webhooks.go`) loads the creator's configured webhooks via `s.Store.GetUserWebhooks` and calls `webhook.PostAsync`, which enqueues onto `asyncPostQueue`; the worker goroutines all invoke the same delivery function.

**Convergence function** — `webhook.Post` — `internal/webhook/webhook.go:120` (it builds the request and executes the actual outbound call via `safeClient.Do` at line 152). The in-process fan-in point just before it is `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which every handler path funnels through.
