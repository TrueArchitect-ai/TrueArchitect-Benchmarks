The premise is incorrect: **this repository (usememos/memos) has no per-user API rate-limiting middleware.** There is nothing to register and no request limits to report.

What I verified:

- **The interceptor/middleware chain has no rate limiter.** The Connect API interceptors are registered in `server/router/api/v1/v1.go:133-137` as exactly four: `NewMetadataInterceptor()`, `NewLoggingInterceptor(...)`, `NewRecoveryInterceptor(...)`, and `NewAuthInterceptor(...)`. The gRPC-Gateway path (`server/router/api/v1/v1.go:69-97`) adds only an auth middleware. None of these throttle or limit requests.

- **No rate-limiting code or dependency exists.** A repo-wide search for `rate limit / ratelimit / throttle / limiter / golang.org/x/time/rate / tollbooth` across all `.go` files, `go.mod`, and `web/src` returns no implementation. The only hit is an aspirational doc comment about email — `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse") — which describes a security consideration, not implemented code.

- The two files named `middleware*.go` (`internal/scheduler/middleware.go` and its test) belong to the background scheduler and contain no rate/throttle logic.

The closest thing to a request-size safeguard is `connect.WithReadMaxBytes(maxAPIRequestBytes)` at `server/router/api/v1/v1.go:141`, but that caps request *body size*, not request *rate*, and it is not per-user.

So there is no per-user API rate limiter, and consequently no configured request limits, in this codebase.
