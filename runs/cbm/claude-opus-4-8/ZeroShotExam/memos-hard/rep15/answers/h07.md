I have the complete chain. The avatar is stored inline as a base64 data URI in the `avatar_url` column of the `user` table, and served directly from there.

- `Store.GetUser` (cache check, then delegates) — store/user.go:148

- `(sqlite).DB.ListUsers` (`SELECT ... avatar_url ... FROM user WHERE username = ?`; scans into `user.AvatarURL`) — store/db/sqlite/user.go:88 (Postgres/MySQL equivalents at store/db/postgres/user.go:87 and store/db/mysql/user.go:84)

Note: the profile image data itself is not on disk or in object storage — it lives inline in the `user.avatar_url` column as a `data:` URI, which `serveUserAvatar` parses (`parseDataURI`, fileserver.go:737) and returns via `c.Blob`.
