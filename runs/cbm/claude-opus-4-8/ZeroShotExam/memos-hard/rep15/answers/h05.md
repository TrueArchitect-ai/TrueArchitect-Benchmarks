**Mechanism: explicit Go code** (not a database-level rule). When a user is deleted, their emoji reactions are removed by hand-written `DELETE FROM reaction` statements inside the delete-user transaction — the `reaction` table has no foreign keys or `ON DELETE CASCADE`, so the DB does nothing on its own.

Two distinct sweeps run, covering both directions:

1. **Reactions the user created** → `deleteReactionsByCreatorTx` runs `DELETE FROM reaction WHERE creator_id = ?` — `store/db/sqlite/user_delete.go:400-403`, called from `deleteUserTargetsTx` at line 102.
2. **Reactions on the user's memos** (regardless of who reacted) → `deleteReactionsByContentIDsTx` runs `DELETE FROM reaction WHERE content_id IN (...)` over the deleted user's memo tree — `store/db/sqlite/user_delete.go:380-388`, called at line 96. Content IDs are built as `"memos/"+uid` in `memoContentIDsFromRefs` (line 512).

Both execute in the same transaction as the rest of the deletion (`DeleteUser`, `store/db/sqlite/user_delete.go:29-59`).

The Postgres and MySQL drivers mirror this (`store/db/postgres/user_delete.go`, `store/db/mysql/user_delete.go` — same function names appear in the grep listing).
