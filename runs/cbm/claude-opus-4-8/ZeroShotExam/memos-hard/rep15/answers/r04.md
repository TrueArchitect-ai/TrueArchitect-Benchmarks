**Premise correction:** The webhook delivery workers consume from *neither* NATS nor RabbitMQ. Memos has no external message broker at all for webhooks — the premise that there's a broker-backed queue is incorrect.

**Actual mechanism:** Delivery is handled entirely in-process using a buffered **Go channel** with a pool of goroutine workers, all defined in `internal/webhook/webhook.go`:

- The "queue" is declared at `internal/webhook/webhook.go:39` as a package-level buffered channel:
  ```go
  asyncPostQueue = make(chan *WebhookRequestPayload, 128)
  ```
- The workers are started in `init()` at `internal/webhook/webhook.go:42-55` — a fixed pool of **4 goroutines**, each ranging over `asyncPostQueue` and calling `Post()` to dispatch the HTTP request.
- Producers enqueue via `PostAsync()` (`internal/webhook/webhook.go:184-196`), which does a non-blocking `select` send onto the channel and drops the payload (with a warning log) if the buffer of 128 is full.

So it's an in-memory, single-process worker pool over a Go channel — not a distributed message broker. (The `grep` for `nats|rabbitmq|amqp` produced only false positives in `web/src/locales/ca.json`, e.g. the Catalan word "memòries".)
