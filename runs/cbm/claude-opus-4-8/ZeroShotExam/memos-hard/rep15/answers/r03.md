**Premise correction:** There is no nightly database-cleanup job actually running in this repository's cron scheduler. The premise assumes such a scheduled job exists, but it does not.

What the codebase actually contains:

- `internal/scheduler/` is a **general-purpose, self-contained cron scheduler library** (package doc: "a GitHub Actions-inspired cron job scheduler," `internal/scheduler/doc.go:1`). It is never imported or instantiated by any production code — a search for non-test imports of `internal/scheduler` returns nothing, and the server (`server/server.go`) never wires it up.

- The only "nightly cleanup" references are **illustrative examples**, not registered jobs:
  - `internal/scheduler/example_test.go:97-105` — an `Example_multipleJobs` test registers a job named `"cleanup"` with schedule `"0 2 * * *"` and the comment "Cleanup old data every night at 2 AM." Its handler just prints `"Cleaning up old data..."` — it does nothing to any database.
  - `internal/scheduler/doc.go:14-16` — the package doc comment shows a `"daily-cleanup"` job with `Schedule: "0 2 * * *"` ("2 AM daily") purely as usage documentation.

So the closest match — 2 AM daily (`0 2 * * *`) — comes only from a doc snippet and an example test, and it's a generic "cleanup old data" placeholder, not a database-cleanup job that is scheduled to run. The one recurring task the running server actually has is unrelated: the S3 presign runner, scheduled every 12 hours (`server/runner/s3presign/runner.go:26`), which does not use this scheduler package.
