**Yes** — the MySQL driver struct is constructed directly outside the driver-selection factory, in a unit test.

Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14`, which routes `case "mysql"` to `mysql.NewDB(profile)` (`store/db/db.go:22`). That factory-called constructor `mysql.NewDB` (`store/db/mysql/mysql.go:20`) builds the driver via `driver := DB{profile: profile}` and returns `&driver`.

- `mysql.NewDB` is only ever called from the factory — the sole call site is `store/db/db.go:22` (grep for `mysql.NewDB` yields exactly that one hit).

- However, the MySQL driver type `DB` itself is instantiated directly, bypassing both the factory and `NewDB`, at `store/db/mysql/auth_config_test.go:12`:
  ```go
  db := &DB{}
  require.True(t, db.IsRetryableAuthenticationMutationError(...))
  ```
  This constructs a zero-valued `*mysql.DB` to exercise the `IsRetryableAuthenticationMutationError` method in isolation.

So, aside from that in-package test, there is no other direct construction of the MySQL driver anywhere in the codebase (grep for `&DB{` / `mysql.DB{` across `.go` files returns only the postgres package's own analogous cases and this one MySQL test).
