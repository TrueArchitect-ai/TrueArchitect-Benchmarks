**Premise correction:** The webhook delivery workers consume from **neither NATS nor RabbitMQ**. There is no external message broker in this project at all — grepping the codebase for `nats`, `rabbitmq`, and `amqp` turns up only a stray locale string (`web/src/locales/ca.json`), nothing in the delivery path.

**Actual mechanism:** Webhook delivery is handled entirely in-process using a **buffered Go channel** as the queue, with a fixed pool of goroutine workers.

In `internal/webhook/webhook.go`:

- The "queue" is declared at package scope as a buffered channel with capacity 128:
  - `internal/webhook/webhook.go:39` — `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`
- The workers are 4 goroutines started in `init()` that range over the channel and call `Post` for each payload:
  - `internal/webhook/webhook.go:42-55` — `for range 4 { go func() { for payload := range asyncPostQueue { ... Post(payload) ... } }() }`
- Producers enqueue via `PostAsync`, which does a non-blocking send and drops the payload if the channel is full:
  - `internal/webhook/webhook.go:184-196` — `select { case asyncPostQueue <- requestPayload: default: slog.Warn("Dropped webhook dispatch because the async queue is full", ...) }`

So delivery is an in-memory, bounded goroutine-pool consumer over a Go channel — not a broker-backed queue. (Callers such as `server/router/api/v1/memo_service_webhooks.go` and `user_service_webhooks.go` feed it via `PostAsync`.)
