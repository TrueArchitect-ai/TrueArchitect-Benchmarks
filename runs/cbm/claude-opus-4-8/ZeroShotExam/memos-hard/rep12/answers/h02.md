h02.

**Delivery function** — `internal/webhook/webhook.go`

The outbound HTTP delivery actually executes in `Post()` (`internal/webhook/webhook.go:120`), where the request is built and sent via `safeClient.Do(req)` at line 152. Dispatch is fed either synchronously through `Post` or asynchronously through `PostAsync` → the `asyncPostQueue` worker goroutines (lines 42-55, 184-196), but both funnel into `Post` to do the real send.

**Protection mechanism** — `internal/webhook/webhook.go` (dial-time guard) backed by `internal/webhook/validate.go`

The send uses a shared `safeClient` whose `http.Transport.DialContext` is set to `safeDialContext` (`internal/webhook/webhook.go:32-37, 59-77`). At dial time it resolves the target hostname and rejects any address in a reserved/private range via `isReservedIP`, which also defeats DNS-rebinding since the check happens on the actual dialed IP. The reserved ranges and `isReservedIP` live in `internal/webhook/validate.go:14-54` (loopback, RFC-1918, link-local/cloud IMDS `169.254.169.254`, and IPv6 equivalents). A separate up-front `ValidateURL` (`internal/webhook/validate.go:62`) applies the same check when a webhook URL is configured. Note the guard can be globally disabled by the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41-47`) for self-hosted local-network use.

So:

delivery function — `Post` (and its async workers) in `internal/webhook/webhook.go:120`; protection mechanism — SSRF-guarding `safeDialContext`/`safeClient` in `internal/webhook/webhook.go:32-77` using `isReservedIP`/reserved CIDR list in `internal/webhook/validate.go:14-54` (also enforced pre-flight by `ValidateURL`, `internal/webhook/validate.go:62`).
