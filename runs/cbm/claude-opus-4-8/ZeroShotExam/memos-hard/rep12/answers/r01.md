**Premise correction:** There is no Redis anywhere in this repository. I searched the entire tree (`grep -rniE "redis"` returns nothing outside dependencies) and found no Redis, memcached, or any external cache dependency. This is the Memos project, and its cache layer is a **thread-safe in-memory (in-process) cache**, not a Redis-backed one. So there is no "Redis connection" to configure — the premise is mistaken.

**Actual mechanism:**

- The cache implementation lives in `store/cache/cache.go` — a custom in-memory `Cache` struct guarded by a mutex, with TTL expiration and a background cleanup goroutine. It has no network/connection concept at all.
- The caches are **constructed and configured in `store/store.go:38-53`**, inside `Store.New()`. A single `cache.Config` is built there and shared across three caches, including the user cache:

```go
cacheConfig := cache.Config{
    DefaultTTL:      10 * time.Minute,
    CleanupInterval: 5 * time.Minute,
    MaxItems:        1000,
    OnEviction:      nil,
}
...
userCache: cache.New(cacheConfig),
```

- **TTL for user entries: 10 minutes.** User records are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 143, 167). `Set` uses the config's `DefaultTTL` (`store/cache/cache.go:92-94`), which is `10 * time.Minute`. Users are not given a custom TTL — nothing calls `SetWithTTL` for them — so they inherit the default. Entries are swept by the cleanup goroutine every 5 minutes (`CleanupInterval`), and the cache holds at most 1000 items (`MaxItems`).

So the answer to "where is the Redis connection configured" is: nowhere — the cache is in-memory, configured in `store/store.go`, and user entries expire after 10 minutes.
