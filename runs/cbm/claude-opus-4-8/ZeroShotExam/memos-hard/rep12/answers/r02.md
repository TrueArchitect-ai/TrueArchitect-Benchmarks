**Premise correction:** There is no per-user API rate-limiting middleware in this repository. The premise assumes one exists and is registered — it isn't.

What the codebase actually has:

- The API's Connect/gRPC interceptor chain is registered in `server/router/api/v1/v1.go:133-137` via `connect.WithInterceptors(...)`, and consists of exactly four interceptors, none of which throttle by rate or by user:
  - `NewMetadataInterceptor()` — copies HTTP headers into gRPC metadata
  - `NewLoggingInterceptor(...)` — request logging
  - `NewRecoveryInterceptor(...)` — panic recovery
  - `NewAuthInterceptor(...)` — authentication / access policy

  All four are defined in `server/router/api/v1/connect_interceptors.go`. There is no rate-limiter interceptor.

- No rate-limiting dependency is present either (grep of `go.mod`/`go.sum` for `limiter`, `tollbooth`, `throttle`, `ratelimit`, `golang.org/x/time/rate` returns nothing).

- The only "rate limit" reference in the codebase is an aspirational doc comment, not code: `internal/email/doc.go:86` ("Rate limit email sending to prevent abuse").

Limits that *do* exist are different in kind (request-size and pagination limits, not per-user request-rate limits):

- **Request body size cap:** `maxAPIRequestBytes = 256 << 20` (256 MiB), applied in `server/router/api/v1/v1.go:20` and enforced at lines 126, 141 (`connect.WithReadMaxBytes`), and 144 (`http.MaxBytesHandler`).
- **Pagination page-size defaults/caps:** e.g. `server/router/api/v1/common.go:42-55`.
- **Concurrency limits** (not rate limits): thumbnail generation semaphore of 3 in `server/router/api/v1/v1.go:59`.

So: no per-user API rate-limiting middleware is registered anywhere; the interceptor chain that *is* registered lives in `server/router/api/v1/v1.go` and contains metadata, logging, recovery, and auth interceptors only.
