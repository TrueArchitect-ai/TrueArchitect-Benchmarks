**Computation site**

The derived metadata is the memo's `Payload.Property` (`storepb.MemoPayload_Property`). It's assembled by `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which calls the markdown service's `ExtractAll` (`internal/markdown/markdown.go:356`) and assigns `memo.Payload.Property = data.Property` (line 86). The actual property extraction happens inside that single goldmark-AST walk in `ExtractAll` (`internal/markdown/markdown.go:383-410`). (A standalone `ExtractProperties` at `internal/markdown/markdown.go:193` does the same thing but isn't the one wired into the rebuild path; `ExtractAll` is the single-pass version used in production.)

**Triggers (what causes recomputation)**

Recomputation runs whenever a memo's content changes, plus a bulk rebuild:
- **Create** — `CreateMemo` at `server/router/api/v1/memo_service.go:108`
- **Update (content field)** — `UpdateMemo` at `server/router/api/v1/memo_service.go:447`, only in the `content` update-mask branch (after setting `memo.Content = request.Memo.Content`)
- **Bulk backfill** — `Runner.RunOnce` (`server/runner/memopayload/runner.go:27`) iterates all memos in batches of 100, rebuilds each payload, and persists via `Store.UpdateMemo`.

**Extracted properties** (from the memo content, via goldmark AST walk)

- `Title` — plain text of the first block-level node if it is an H1 heading (`extractHeadingText`)
- `HasLink` — true if any `KindLink` node exists
- `HasCode` — true if any code block, fenced code block, or code span (`KindCodeBlock`/`KindFencedCodeBlock`/`KindCodeSpan`) exists
- `HasTaskList` — true if any task checkbox (`east.KindTaskCheckBox`) exists
- `HasIncompleteTasks` — true if any task checkbox is unchecked

(`ExtractAll` in the same pass also derives `Tags` and `Mentions`, which `RebuildMemoPayload` uses to set `Payload.Tags`; the boolean/title set above is specifically the `Property` metadata used for lists/previews.)
