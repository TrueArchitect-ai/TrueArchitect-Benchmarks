**Premise correction:** Memos has no GraphQL API, so there is no GraphQL schema to define. A repo-wide search for "graphql" returns zero matches. The question's premise is incorrect.

**Actual API surface:** Memos exposes a **gRPC + REST API defined via Protocol Buffers**, not GraphQL. The schema of record is the set of `.proto` files:

- **Service/message definitions:** `proto/api/v1/*.proto` — e.g. `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `shortcut_service.proto`, `idp_service.proto`, `instance_service.proto`, `ai_service.proto`, plus shared types in `proto/api/v1/common.proto`. Store-layer protos live under `proto/store/`.
- **Build tooling:** [Buf](https://buf.build) drives codegen — `proto/buf.yaml`, `proto/buf.gen.yaml`, `proto/buf.lock`.
- **Generated code:** `proto/gen/` (Go: protobuf, gRPC, ConnectRPC, and a **grpc-gateway** for REST), plus TypeScript types emitted to `web/src/types/proto/`.
- **REST/OpenAPI surface:** the gateway plugin generates a REST layer, and an OpenAPI spec is produced at `proto/gen/openapi.yaml` (embedded via `proto/openapi_embed.go`).

The README confirms this: Memos advertises "full REST and gRPC APIs" (`README.md`) — there is no GraphQL layer.
