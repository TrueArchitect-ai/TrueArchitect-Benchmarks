Memo view-visibility is enforced independently in each of these server surfaces:

gRPC/REST memo API — single-memo read gate `checkMemoReadAccess` (used by GetMemo, and parent-memo checks) — server/router/api/v1/memo_service.go:39-67
gRPC/REST memo API — ListMemos query-level visibility filter (anonymous ⇒ PUBLIC only; authed non-owner ⇒ PUBLIC/PROTECTED, plus own private) — server/router/api/v1/memo_service.go:216-226
SSE realtime hub — `SSEClient.canReceive` filters live memo events by visibility (PRIVATE only to creator/admin) — server/router/api/v1/sse_hub.go:133-145
Attachment/file server — blocks serving a private memo's attachment to non-owner/non-admin (after share-token check) — server/router/fileserver/fileserver.go:699
RSS feed — instance and per-user feeds restrict to `store.Public` memos — server/router/rss/rss.go:90, server/router/rss/rss.go:141
Frontend SSR sitemap — lists only `store.Public` memos — server/router/frontend/frontend.go:150

The three primary/distinct surfaces are the API memo service (server/router/api/v1/memo_service.go), the RSS router (server/router/rss/rss.go), and the frontend SSR router (server/router/frontend/frontend.go); the SSE hub (server/router/api/v1/sse_hub.go) and file server (server/router/fileserver/fileserver.go) add two more.
