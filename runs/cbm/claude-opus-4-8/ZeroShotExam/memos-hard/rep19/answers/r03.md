The premise is mistaken: there is **no** nightly database-cleanup job actually scheduled in this repository's cron scheduler.

What exists:

- `internal/scheduler/` is a **generic, standalone cron scheduler package** ("GitHub Actions-inspired cron job scheduler," per `internal/scheduler/doc.go:1`). It is a library, not a configured set of jobs.
- The only "cleanup at 2 AM" references are **illustrative examples**, not registered jobs:
  - `internal/scheduler/doc.go:14-21` — a docstring example registering a `"daily-cleanup"` job with `Schedule: "0 2 * * *"` (commented "2 AM daily").
  - `internal/scheduler/example_test.go:97-106` — an `Example_multipleJobs` test registering a `"cleanup"` job with `Schedule: "0 2 * * *"`, whose handler just prints "Cleaning up old data..." (it does not touch the database).

Crucially, the scheduler package is **never imported or wired into the running application** — a search for non-test imports of `internal/scheduler` outside the package itself returns nothing, and nothing in `cmd/` / `server/` references it. So no cleanup job (database or otherwise) is registered or scheduled at runtime.

If the question is pointing at the `0 2 * * *` value seen in those examples, note that (a) it's example/doc code, and (b) it's labeled generically as cleaning "old data," not a database cleanup, and it's inert. There is no actual scheduled nightly database-cleanup job to report a run time for.
