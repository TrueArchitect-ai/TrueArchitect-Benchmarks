**Premise correction:** This repository (Memos, a Go/Connect-RPC backend) has **no per-user API rate-limiting middleware**. There is nothing to register and no request limits to report — the premise assumes a component that does not exist.

What actually exists:

- The API interceptor chain is registered in `server/router/api/v1/v1.go:133-141` via `connect.WithInterceptors(...)`. The registered interceptors are only: `MetadataInterceptor`, `LoggingInterceptor`, `RecoveryInterceptor`, and `AuthInterceptor` (defined in `server/router/api/v1/connect_interceptors.go`). None of these rate-limit requests, and none track per-user request counts.
- The only "limit" applied to API requests is a **request body size cap**, not a request-rate limit: `maxAPIRequestBytes = 256 << 20` (256 MiB), enforced globally (not per-user) via `http.MaxBytesHandler` and `connect.WithReadMaxBytes` (`server/router/api/v1/v1.go:20, 126, 141, 144`).
- The only rate-limiter reference anywhere in the repo is an illustrative code sample in documentation — `internal/email/README.md` shows `rate.NewLimiter(rate.Every(time.Second), 10)` as an *example* for throttling outbound email. It is documentation only, not implemented code, and unrelated to per-user API rate limiting.

So there is no per-user API rate limiting configured; if this is a requirement, it would need to be added (e.g., as a new Connect interceptor in the chain at `v1.go:133`).
