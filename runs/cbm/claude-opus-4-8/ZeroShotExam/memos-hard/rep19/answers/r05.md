**Premise correction:** This repository (`github.com/usememos/memos`, a Go project) does **not** define or use a GraphQL schema anywhere. There are no `.graphql`/`.gql` schema files, no GraphQL server library, and no GraphQL references in the codebase. The public API is **not** GraphQL-based.

**Actual API surface:** The public API is defined as **Protocol Buffers / gRPC services**, not GraphQL:

- **Service/message definitions (source of truth):** `proto/api/v1/*.proto` — e.g. `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `shortcut_service.proto`, `instance_service.proto`, `ai_service.proto`, `idp_service.proto`, and `common.proto`.
- **Generated Go code:** `proto/gen/api/v1/` (compiled from the `.proto` files via `proto/buf.gen.yaml`).
- **REST surface:** exposed through gRPC-gateway, with a generated **OpenAPI** spec at `proto/gen/openapi.yaml`, embedded via `proto/openapi_embed.go`.
- **Internal store protos** (not the public API): `proto/store/*.proto`.

This is consistent with the README (`README.md:22`), which advertises "full REST and gRPC APIs" — not GraphQL. So the closest analog to "the schema for the public API" is the set of `.proto` definitions under `proto/api/v1/`, with the OpenAPI document at `proto/gen/openapi.yaml` describing the REST bindings.
