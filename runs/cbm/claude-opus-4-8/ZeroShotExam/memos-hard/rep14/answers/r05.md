**Premise correction:** This repository (Memos) has **no GraphQL schema and no GraphQL API**. There is nothing named `.graphql`/`.gql`, no `schema.graphql`, no GraphQL server, resolvers, or dependencies anywhere in the tree. The question's premise — that a GraphQL public API exists — does not hold here.

**Actual API surface:** Memos exposes a **gRPC + REST API defined with Protocol Buffers**, not GraphQL. The README states it plainly: "full REST and gRPC APIs for integration."

- The public API contract is defined in **`proto/api/v1/`** — the `.proto` files are the source of truth:
  - `proto/api/v1/memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `ai_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `common.proto`
- Build config: `proto/buf.yaml`, `proto/buf.gen.yaml` (codegen via [buf]).
- Generated code lives in `proto/gen/` (with `proto/openapi_embed.go` embedding the spec).
- The REST surface is derived from these protos via grpc-gateway, and an **OpenAPI/Swagger** document is generated at **`proto/gen/openapi.yaml`** — that is the closest thing to a "schema for the public API," and it's OpenAPI, not GraphQL.

So: the public API is a protobuf-defined gRPC service (with a REST/OpenAPI gateway) rooted at `proto/api/v1/`; there is no GraphQL schema to point to.
