**Premise correction:** There is no Redis anywhere in this repository. The Memos backend uses no external cache server — the cache layer is a hand-rolled, thread-safe **in-memory** cache (Go `sync.Map` with a background TTL cleanup goroutine). A grep for `redis` across the codebase returns zero hits; the only "cache" references are the Go in-memory cache and unrelated frontend React Query caching (`web/src/lib/query-client.ts`, `web/src/components/MemoEditor/services/cacheService.ts`).

**Actual mechanism:**

- The cache implementation lives at `store/cache/cache.go` — `Cache` is "a thread-safe in-memory cache with TTL and memory management" backed by a `sync.Map`, with a `cleanupLoop` goroutine that periodically evicts expired items (`store/cache/cache.go:66`, `:199`).
- It is **not configured with a Redis connection string/host** — it's constructed in-process. The store wires up three separate in-memory cache instances in `store/store.go:40-53`: `instanceSettingCache`, `userCache`, and `userSettingCache`, all created via `cache.New(cacheConfig)`.
- **TTL for user entries:** There is no user-specific TTL. User entries go into `userCache`, which is created with the shared `cacheConfig` whose `DefaultTTL` is **10 minutes** (`store/store.go:41`, matching the library default at `store/cache/cache.go:59`). Writes use `s.userCache.Set(...)` (e.g. `store/user.go:98`, `:122`, `:167`), and `Set` applies the default TTL (`cache.go:92-95`), so cached users expire 10 minutes after they're written. `GetUser` checks this cache first when looking up by ID (`store/user.go:148-151`). The config also caps at `MaxItems: 1000` with a `CleanupInterval` of 5 minutes.

So: no Redis, no connection to configure — a per-process in-memory `sync.Map` cache with a flat 10-minute default TTL applied to user entries.
