**Premise correction:** There is no per-user API rate-limiting middleware in this repository, so it isn't registered anywhere and has no request limits to report.

What actually exists is the Connect/gRPC interceptor chain registered in `server/router/api/v1/v1.go:133-137`:

```go
connectInterceptors := connect.WithInterceptors(
    NewMetadataInterceptor(),      // HTTP headers → gRPC metadata
    NewLoggingInterceptor(...),    // request logging
    NewRecoveryInterceptor(...),   // panic recovery
    NewAuthInterceptor(authorizer),// authentication / ACL
)
```

Those four interceptors (defined in `server/router/api/v1/connect_interceptors.go`) handle metadata conversion, logging, panic recovery, and authentication — none of them throttle requests, and none are keyed per user for rate purposes.

The only "limit" applied to API traffic is a **request body size cap**, not a request-rate limit:
- `const maxAPIRequestBytes = 256 << 20` (256 MiB) — `server/router/api/v1/v1.go:20`
- Enforced via `http.MaxBytesHandler(...)` and `connect.WithReadMaxBytes(maxAPIRequestBytes)` — `server/router/api/v1/v1.go:126,141,144`

The only mention of rate limiting anywhere in the codebase is an aspirational suggestion in email documentation (`internal/email/README.md:286-295` and `internal/email/doc.go:86`), which proposes a `rate.NewLimiter` for outbound email sending — it is documentation, not implemented middleware, and unrelated to per-user API limits. A search for any rate-limiting library (`golang.org/x/time/rate`, `tollbooth`, `httprate`, etc.) in the server code and `go.mod` returns nothing.
