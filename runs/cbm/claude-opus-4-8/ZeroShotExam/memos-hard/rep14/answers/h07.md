Notes:
- The route is `GET /file/users/:identifier/avatar`, registered at server/router/fileserver/fileserver.go:124.
- On a private instance the handler first authenticates the viewer (fileserver.go:173-181), but the *target* user is looked up by the `:identifier` username via `getUserByUsername`.
- The image bytes are not a separate file: `serveUserAvatar` reads `user.AvatarURL` (a `data:<type>;base64,...` URI stored in the `avatar_url` column), decodes it with `parseDataURI` (fileserver.go:196, 737), and writes it with `c.Blob` (fileserver.go:209). So the data layer is the `users.avatar_url` column read by the SQL driver's `ListUsers` (store/db/sqlite/user.go:159,189 — mirrored in the postgres/mysql drivers).
- `GetUser` may short-circuit on its in-memory `userCache` only when looked up by ID; here the lookup is by username, so it falls through to `ListUsers`/the driver.
