h15.

Memo visibility (who may view a memo) is enforced across several distinct server surfaces. The distinct enforcement sites:

**Single-memo read access (gRPC/Connect API — GetMemo, GetMemoByUID, comment listing)** — `server/router/api/v1/memo_service.go:39` (`checkMemoReadAccess`, lines 39–68; called at `memo_service.go:356`, `memo_service.go:367`, and `server/router/api/v1/memo_service_comments.go:148`). Enforces: archived → creator only; non-public requires auth; private → creator only.

**List memos filtering (gRPC/Connect API — ListMemos)** — `server/router/api/v1/memo_service.go:218` (lines 218–227). Anonymous callers restricted to `[PUBLIC]`; authenticated callers get `creator_id == self || visibility in [PUBLIC, PROTECTED]`.

**Raw file/attachment server** — `server/router/fileserver/fileserver.go:650` (`checkAttachmentPermission`, visibility gate at lines 677–701). Serves a memo's attachment only if the memo is public (with anonymous allowed), a valid share token is presented, or the authenticated user is the creator/admin; private → forbidden.

**RSS feed router** — `server/router/rss/rss.go:90` and `rss.go:141` — feeds are built with `VisibilityList: [store.Public]` (instance-wide and per-user), so only public memos are exposed.

**Frontend SSR router (meta/OG tags)** — `server/router/frontend/frontend.go:150` — server-side memo rendering restricted to `VisibilityList: [store.Public]`.

Secondary API surfaces that re-apply the same memo-visibility gate before exposing memo-derived data (not the memo body itself, but they enforce the same rule):
- **Reactions API** — `server/router/api/v1/reaction_service.go:30`, `:38`, `:83`
- **Memo attachments listing API** — `server/router/api/v1/memo_attachment_service.go:214`, `:222`
- **Attachment service (GetAttachmentBinary path)** — `server/router/api/v1/attachment_service.go:445`, `:451`

The three-plus core "who may view a memo" surfaces are the single-read API (`checkMemoReadAccess`), the list API filter (`ListMemos`), and the file server (`checkAttachmentPermission`), with the RSS and frontend routers additionally restricting to public visibility.
