**Delivery function** — `Post` in `internal/webhook/webhook.go:120`. This is where the outbound HTTP POST actually executes: it marshals the payload, builds the request, optionally adds the HMAC signature headers, and fires it via `safeClient.Do(req)` at line 152. (The async workers started in `init()` just call `Post` off the `asyncPostQueue`.)

**Protection mechanism** — the SSRF guard is enforced at dial time by `safeDialContext` in `internal/webhook/webhook.go:59`, which is wired in as the `DialContext` of the `safeClient`'s transport (`internal/webhook/webhook.go:32-37`). On every connection it resolves the target hostname and rejects any address that `isReservedIP` (`internal/webhook/validate.go:44`) matches against the reserved/private CIDR list (`internal/webhook/validate.go:14-23` — loopback, RFC-1918, link-local/cloud IMDS `169.254.169.254`, and IPv6 equivalents). Because the check happens at dial time on the actually-resolved IP, it also defeats DNS-rebinding.

Note there's a second, earlier layer: `ValidateURL` (`internal/webhook/validate.go:62`) rejects non-http(s) schemes and private-resolving hosts when a webhook is configured. But that's a config-time check; the guarantee that protects the *actual delivery* is `safeDialContext`, since it runs on each real connection. Both can be disabled by the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`) for self-hosted local-network use.
