**impl** — The interface is `markdown.Service` (`internal/markdown/markdown.go:31`). The only concrete implementation is the unexported `service` struct in the same file (`internal/markdown/markdown.go:58`), which wraps a `goldmark.Markdown` instance configured with GFM plus the repo's custom tag/mention extensions (`internal/markdown/extensions/tag.go`, `mention.go`). That is what executes at runtime.

**construction** — Built by the factory `markdown.NewService(opts...)` (`internal/markdown/markdown.go:85`). The single runtime construction site is `NewAPIV1Service` in `server/router/api/v1/v1.go:48`, which calls `markdown.NewService(markdown.WithTagExtension(), markdown.WithMentionExtension())`. All other `NewService` calls are in tests (`internal/markdown/markdown_test.go`, `server/router/rss/rss_test.go`, `server/router/fileserver/fileserver_test.go`, `server/router/api/v1/test/test_helper.go`).

**holders** — Components holding the interface (all sharing that one instance):
- `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — the primary holder; used by memo handlers, e.g. `memo_service.go` passes it into `memopayload.RebuildMemoPayload` (lines 108, 447).
- `RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — receives the same instance from the API service in `server/server.go:85` (`rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)`), used for server-side HTML rendering of RSS feeds.
- `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) also declares the field, but `memopayload.NewRunner` has no callers in production code — at runtime the service reaches that package only as a parameter to the free function `RebuildMemoPayload`.

Note the interface's own doc comment: HTML rendering is mostly done on the frontend (markdown-it/react pipeline under `web/src/components/MemoContent/`); the Go `Service` exists for metadata extraction (tags, mentions, properties, snippets) and server-side rendering needs like RSS.
