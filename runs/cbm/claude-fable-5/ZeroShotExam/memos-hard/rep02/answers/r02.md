**Premise correction: there is no per-user API rate-limiting middleware in this repository.** I searched the whole codebase (Go server, middleware registrations, interceptors, and dependencies) and no rate limiter exists or is registered anywhere.

What actually exists:

- The Echo server registers only `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`, with CORS in `server/cors.go`).
- The Connect/gRPC API stack registers four interceptors — metadata, logging, recovery, and auth — plus a request-size cap (`connect.WithReadMaxBytes(maxAPIRequestBytes)`), none of which do rate limiting (`server/router/api/v1/v1.go:133-141`, `server/router/api/v1/connect_interceptors.go`).
- The only "rate limit" mentions in the repo are aspirational documentation: `internal/email/doc.go` lists "Rate limit email sending to prevent abuse" as a security consideration, and `internal/email/README.md` sketches an example rate-limiting implementation for email sending under "### 5. Implement Rate Limiting" — neither is implemented code, and neither concerns per-user API requests.

Consequently, there are no request limits to report — no rate-limiting library (e.g., `golang.org/x/time/rate`, tollbooth) appears in `go.mod` or the source.
