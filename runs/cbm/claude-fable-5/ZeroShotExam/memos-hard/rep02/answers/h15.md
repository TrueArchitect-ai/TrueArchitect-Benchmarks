Memo visibility is checked independently on several distinct server surfaces, not just in the main memo API:

- gRPC/REST API v1 memo read access — `checkMemoReadAccess` (Public/Protected/Private rules; Private restricted to the creator) in `server/router/api/v1/memo_service.go` (≈lines 39–68), plus list-side enforcement where `ListMemos` constrains `VisibilityList`/CEL filter by the current user (≈lines 215–226). The same rule is replicated for memo-adjacent API resources: `server/router/api/v1/reaction_service.go` (lines 38, 83), `server/router/api/v1/attachment_service.go` (line 451), `server/router/api/v1/memo_attachment_service.go` (line 222), and `server/router/api/v1/memo_service_comments.go` (line 41).
- Attachment/file HTTP server — before streaming an attachment's bytes it loads the owning memo and enforces visibility (anonymous only for Public on an open instance, share-token fallback, Private limited to creator/admin) in `server/router/fileserver/fileserver.go` (≈lines 660–704).
- RSS feed router — feeds are built only from memos with `VisibilityList: []store.Visibility{store.Public}` in `server/router/rss/rss.go` (lines 90 and 141).
- Frontend router (sitemap) — `getSitemapXML` lists only `store.Public` memos so non-public memo URLs are never exposed, in `server/router/frontend/frontend.go` (≈line 150).
- SSE real-time event hub — `canReceive` filters broadcast memo events per client: Private events are delivered only to the creator or an admin, in `server/router/api/v1/sse_hub.go` (≈lines 134–145).

The MCP router (`server/router/mcp/`) is not a separate enforcement site — it proxies to the v1 API, so it inherits the first site's checks.
