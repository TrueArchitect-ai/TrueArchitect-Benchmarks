**Premise correction:** There is no Redis in this repository. A search for `redis`/`ioredis` across the codebase returns nothing — the cache layer is a homegrown, thread-safe **in-memory** cache (built on `sync.Map`), not an external store. There is therefore no Redis connection to configure.

**Actual mechanism:** The cache implementation lives in `store/cache/cache.go`, which defines the `Cache` type, its `Config` (with `DefaultTTL`, `CleanupInterval`, `MaxItems`, `OnEviction`), and a background cleanup goroutine that evicts expired entries.

The caches are instantiated in `store/store.go:38-58` (`store.New`), which creates three caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing this hardcoded config:

- `DefaultTTL: 10 * time.Minute` (`store/store.go:41`)
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

**TTL for user entries:** User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167). `Set` applies the default TTL (`store/cache/cache.go:93-95`), so **user cache entries live for 10 minutes**, with expired items also swept by the cleanup loop every 5 minutes. No custom `SetWithTTL` is used for users, and the values are not configurable via environment or settings — they're fixed in code.
