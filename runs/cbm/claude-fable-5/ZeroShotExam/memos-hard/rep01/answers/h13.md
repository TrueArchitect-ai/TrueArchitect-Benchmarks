**Impl — construction — holders**

- **Concrete implementation:** the single unexported struct `service` in `internal/markdown/markdown.go:57-60`, which wraps a `goldmark.Markdown` instance (GFM plus optional custom tag/mention extensions from `internal/markdown/extensions`, custom renderer in `internal/markdown/renderer`). It is the only implementation of the `markdown.Service` interface (`internal/markdown/markdown.go:31-55`) that runs at runtime.

- **Construction:** only the factory `markdown.NewService(opts ...Option)` (`internal/markdown/markdown.go:85-113`) builds it. At runtime it is called exactly once, in `NewAPIV1Service` (`server/router/api/v1/v1.go:48-51`) with `WithTagExtension()` and `WithMentionExtension()` enabled. (A second call exists only in the test helper `server/router/api/v1/test/test_helper.go:44`.)

- **Holders of the interface:**
  - `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`) — used for payload rebuilds, mention extraction, and webhook snippets (`memo_service.go`, `memo_mention_helpers.go:32`, `memo_service_webhooks.go:85`).
  - `RSSService.MarkdownService` (`server/router/rss/rss.go:45`) — receives the *same* instance, passed along from the API service in `server/server.go:85` (`rss.NewRSSService(s.Profile, s.Store, apiV1Service.MarkdownService)`); used for `RenderHTML` in RSS feeds (`rss.go:339`).
  - `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) also declares the interface field, but `memopayload.NewRunner` is never invoked in the runtime wiring — the package is exercised at runtime only through the free function `RebuildMemoPayload(ctx, memo, markdownService)` (`runner.go:74`), which takes the interface as a parameter from the API service.

So a single goldmark-backed `service` instance, created once in `NewAPIV1Service`, is shared by the API v1 layer and the RSS router (and threaded into `memopayload.RebuildMemoPayload` per call).
