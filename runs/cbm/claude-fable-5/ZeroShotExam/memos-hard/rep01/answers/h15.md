Memo visibility is checked independently at each server surface that can expose a memo (or memo-derived data). The distinct enforcement sites are:

- gRPC/Connect memo API — `checkMemoReadAccess` gates GetMemo and comment listing, and ListMemos constrains the query with a `VisibilityList` (Public-only for anonymous, Public+Protected for other users) — `server/router/api/v1/memo_service.go` (lines 39–68, 219–225)
- Memo comments API — private-memo check before creating a comment on someone else's memo — `server/router/api/v1/memo_service_comments.go` (line 41; comment listing also reuses `checkMemoReadAccess` at line 148)
- Reactions API — visibility check on the target memo before listing/upserting/deleting reactions — `server/router/api/v1/reaction_service.go` (lines 30–38, 83)
- Attachment metadata API — `checkAttachmentAccess` resolves the owning memo and enforces its visibility — `server/router/api/v1/attachment_service.go` (lines 422–455)
- Memo-attachment binding API — same owning-memo visibility check — `server/router/api/v1/memo_attachment_service.go` (lines 214–222)
- Raw file server (HTTP downloads) — `checkAttachmentPermission` re-checks the owning memo's visibility (with anonymous-instance and share-token carve-outs) before streaming file bytes — `server/router/fileserver/fileserver.go` (lines 650–704)
- SSE real-time event stream — `SSEClient.canReceive` scopes broadcast events by the memo's visibility (private events only to the creator or an admin) — `server/router/api/v1/sse_hub.go` (lines 134–144)
- In-app notifications/inbox — `canViewerAccessMemo` filters comment/mention notifications so recipients never see content of memos they can't view — `server/router/api/v1/user_service_notifications.go` (lines 302–316, used at 337–385)
- Email notifications — a separate copy of `canViewerAccessMemo` applies the same rule before sending notification emails — `server/notification/email.go` (lines 306–320, used at 155, 187)
- RSS feeds — explore and per-user feeds are hard-filtered to `store.Public` only — `server/router/rss/rss.go` (lines 90, 141)
- Frontend sitemap — sitemap.xml only lists public memos — `server/router/frontend/frontend.go` (line 150)
- User stats API — anonymous callers get stats computed over public memos only — `server/router/api/v1/user_service_stats.go` (line 84)

The core surfaces the question likely targets are the API v1 service (`memo_service.go` and its sibling files), the raw file server (`fileserver.go`), the SSE hub, the two notification paths, and the public-only feeds (RSS/sitemap) — each enforces the visibility rule in its own code rather than sharing one gate.
