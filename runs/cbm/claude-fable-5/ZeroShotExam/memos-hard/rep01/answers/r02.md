The premise is incorrect — this repository has no per-user API rate-limiting middleware. I searched the whole codebase and no rate limiter is registered anywhere, so there are no request limits to report.

What actually exists at the middleware layer:

- `server/server.go:51-52` — the Echo server registers only `middleware.Recover()` and a custom CORS middleware (`newCORSMiddleware`, defined in `server/cors.go`).
- `server/router/api/v1/v1.go:133-141` — the Connect/gRPC API stack registers four interceptors: `NewMetadataInterceptor()`, `NewLoggingInterceptor()`, `NewRecoveryInterceptor()`, and `NewAuthInterceptor()`, plus a request-size cap (`connect.WithReadMaxBytes(maxAPIRequestBytes)`). None of these do rate limiting.

The only mentions of rate limiting in the repo are aspirational documentation for the email package — `internal/email/doc.go:86` lists "Rate limit email sending to prevent abuse" as a best practice, and `internal/email/README.md:286` sketches a hypothetical `checkRateLimit` example — neither is implemented code, and neither concerns the HTTP API. The `golang.org/x/time` package (which provides `rate.Limiter`) appears in `go.mod` only as an indirect dependency and is not used by any project source file.
