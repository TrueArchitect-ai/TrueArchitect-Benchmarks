The data layer is the `store` package (with its `store/db/*` driver sub-packages), which defines the persistent entity structs: `Memo` (store/memo.go), `User` (store/user.go), `Attachment` (store/attachment.go), `Inbox` (store/inbox.go), `IdentityProvider` (store/idp.go), `InstanceSetting` (store/instance_setting.go), `MemoShare` (store/memo_share.go), `UserIdentity` (store/user_identity.go), `Reaction` (store/reaction.go), `UserSetting` (store/user_setting.go), and `MemoRelation` (store/memo_relation.go).

Counting distinct Go packages outside `store/` that reference each type (word-boundary match on `store.<Type>`, so `store.User` doesn't count `store.UserSetting`, etc.):

**1st: User (~7 packages); 2nd: Memo (~6 packages)**

- `store.User` is referenced from: server/auth, server/notification, server/router/api/v1, server/router/api/v1/test, server/router/fileserver, server/router/frontend, server/router/rss
- `store.Memo` is referenced from: server/notification, server/router/api/v1, server/router/api/v1/test, server/router/frontend, server/router/rss, server/runner/memopayload

For context, the next tier is `Attachment` (4 packages: api/v1, api/v1/test, fileserver, rss), then `Inbox`, `MemoShare`, and `MemoRelation` at 3 each. `User` edges out `Memo` because authentication (server/auth) and file serving (server/router/fileserver) need the user entity but not the memo entity, while only the memopayload runner needs `Memo` without `User`.
