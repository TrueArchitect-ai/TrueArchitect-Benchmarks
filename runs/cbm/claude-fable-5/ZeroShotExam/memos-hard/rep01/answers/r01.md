**Premise correction:** There is no Redis in this repository. The cache layer is not Redis-backed — no Redis client appears in `go.mod`/`go.sum`, and no Redis connection is configured anywhere. The caching is done entirely in-process.

**Actual mechanism:** The cache is a thread-safe in-memory implementation in `store/cache/cache.go` (a `sync.Map`-style store with TTL expiration, a cleanup goroutine, and max-item eviction). The store wires it up in `store/store.go:38-58`, where `New()` creates three caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing one config:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

**TTL for user entries:** User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167), and `Set` applies the default TTL (`store/cache/cache.go:92-94`). So user cache entries live for **10 minutes** — nothing uses the custom `SetWithTTL` path for users.
