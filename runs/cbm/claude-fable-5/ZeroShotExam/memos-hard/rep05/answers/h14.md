**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74`, which delegates the actual content analysis to the markdown service's `ExtractAll` (`internal/markdown/markdown.go:355`) — a single goldmark AST walk over the memo's markdown content. The results are stored on `memo.Payload` (the `MemoPayload` proto, `proto/gen/store/memo.pb.go`).

**Triggers:**
- **Memo creation** — `CreateMemo` calls `memopayload.RebuildMemoPayload` before persisting (`server/router/api/v1/memo_service.go:108`).
- **Memo update, only when the `content` field is in the update mask** — `UpdateMemo` rebuilds the payload and writes it alongside the new content (`server/router/api/v1/memo_service.go:447`); updates to other fields (visibility, pinned, etc.) don't recompute it.
- **Bulk rebuild** — `memopayload.Runner.RunOnce` iterates all memos in batches of 100 and rebuilds each payload (`server/runner/memopayload/runner.go:27`). Note this runner is defined but, unlike the `s3presign` runner, it is not currently wired into the server startup in `server/server.go` — it exists as a maintenance/migration mechanism.

**Extracted properties** (set at `runner.go:85-86` from `ExtractAll`'s output):
- `Payload.Tags` — all `#tag` nodes in the content, deduplicated case-preservingly (`markdown.go:376-378`, `418`).
- `Payload.Property.Title` — text of the document's first block if it is an H1 heading (`markdown.go:384-389`).
- `Payload.Property.HasLink` — any link node (`markdown.go:393-394`).
- `Payload.Property.HasCode` — code block, fenced code block, or inline code span (`markdown.go:396-397`).
- `Payload.Property.HasTaskList` / `HasIncompleteTasks` — task checkboxes, with the latter set if any checkbox is unchecked (`markdown.go:399-405`).

`ExtractAll` also collects `@mentions`, but `RebuildMemoPayload` only copies `Tags` and `Property` into the stored payload; mentions are used elsewhere (e.g. notifications), not persisted as memo metadata.
