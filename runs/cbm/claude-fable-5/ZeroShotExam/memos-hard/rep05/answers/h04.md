**Yes — once, in a unit test inside the driver package itself.**

The driver-selection factory is `NewDBDriver` in `store/db/db.go:14-32`, which is the only caller of the MySQL constructor `mysql.NewDB` (`store/db/db.go:22`, constructor defined at `store/db/mysql/mysql.go:20`). Evidence that nothing else goes through the constructor or import:

- A repo-wide grep for `mysql.NewDB` matches only `store/db/db.go:22`.
- The only file outside `store/db/mysql/` that imports `github.com/usememos/memos/store/db/mysql` is `store/db/db.go:8`.
- The integration tests in `store/test/store.go:28,50` obtain drivers exclusively via `db.NewDBDriver`, never constructing the MySQL driver themselves.

However, there is one direct construction of the driver struct that bypasses the factory: `store/db/mysql/auth_config_test.go:12` builds the driver bare with `db := &DB{}` (no `NewDB`, no factory) in `TestIsRetryableAuthenticationMutationError`, since the test only exercises the error-classification method `IsRetryableAuthenticationMutationError` and needs no real database connection. So in production code the answer is no, but a same-package unit test does instantiate the `mysql.DB` struct directly.
