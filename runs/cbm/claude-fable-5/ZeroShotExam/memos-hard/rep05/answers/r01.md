**Premise correction:** There is no Redis in this repository. A repo-wide search for `redis`/`ioredis`/`memcache` returns zero hits — the cache layer is a custom, thread-safe **in-memory** cache, not an external store.

**Actual mechanism:**

- The cache implementation lives in `store/cache/cache.go` — a `Cache` type built on `sync.Map` with per-item TTL expiration, a periodic cleanup goroutine, and a max-item cap.
- It is configured in `store/store.go` inside `New()` (lines 38–58), which creates three caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing the same `cache.Config`:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`
- **User entries get the 10-minute default TTL.** `store/user.go` writes users via `s.userCache.Set(ctx, userCacheKey(user.ID), user)` (e.g. lines 98, 122, 132, 167), and `Set` is documented in `store/cache/cache.go` as "adds a value to the cache with the default TTL" — no custom `SetWithTTL` is used for users.

(The only other TTL'd cache in the codebase is a separate 60-second memoization of instance stats: `instanceStatsCacheTTL` in `server/router/api/v1/instance_stats.go:21`.)
