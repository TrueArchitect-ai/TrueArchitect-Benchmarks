**Premise correction:** This repository (Memos, a self-hosted note-taking app) has no GraphQL API at all — a case-insensitive search for "graphql"/"apollo" across the codebase returns zero matches, so there is no GraphQL schema anywhere.

**Actual API surface:** The public API is defined as Protocol Buffers and exposed as gRPC/Connect plus a REST/HTTP mirror:

- **Schema source of truth:** the `.proto` files in `proto/api/v1/` — e.g. `proto/api/v1/memo_service.proto`, `proto/api/v1/user_service.proto`, `proto/api/v1/auth_service.proto`, `proto/api/v1/attachment_service.proto`, `proto/api/v1/instance_service.proto`, etc. (Internal storage message schemas live separately in `proto/store/`.)
- **Code generation:** configured in `proto/buf.gen.yaml`, which generates Go gRPC/Connect stubs, grpc-gateway bindings (providing the REST endpoints), an OpenAPI spec (`proto/gen/openapi.yaml`, embedded via `proto/openapi_embed.go`), and TypeScript client types into `web/src/types/proto`.
- **Serving:** the API routes are wired up under `server/router/api/`, alongside non-API routes like `server/router/rss` and `server/router/mcp`.

So the closest analog to "the GraphQL schema" here is the protobuf definitions in `proto/api/v1/*.proto` (with `proto/gen/openapi.yaml` as the REST-facing spec).
