Memo visibility ("who may view this memo") is checked independently in several server surfaces, not just the memo API. Confirmed enforcement sites:

- gRPC/Connect memo API (read access + list filtering) — `server/router/api/v1/memo_service.go` (`checkMemoReadAccess` at lines 39–68 denies non-public memos to anonymous users and private memos to non-creators; `ListMemos` narrows `VisibilityList` to Public/Protected for anonymous or other-user queries at lines 219–225)
- Related-resource API endpoints that re-derive access from the memo's visibility — `server/router/api/v1/reaction_service.go` (lines 30–38, 83), `server/router/api/v1/memo_service_comments.go` (line 41), `server/router/api/v1/memo_attachment_service.go` (lines 214–222), and `server/router/api/v1/attachment_service.go` (`checkAttachmentAccess`, lines 422–455)
- Raw file/attachment HTTP server — `server/router/fileserver/fileserver.go` (`checkAttachmentPermission`, lines 650–704: public + anonymous-allowed passes, share-token fallback, otherwise authenticated user with private-memo creator/admin check)
- RSS feeds — `server/router/rss/rss.go` (`GetExploreRSS` and `GetUserRSS` query only `VisibilityList: []store.Visibility{store.Public}`, lines 90 and 141)
- Frontend sitemap — `server/router/frontend/frontend.go` (`getSitemapXML`, line 150, lists only Public memos)
- Server-sent-events realtime stream — `server/router/api/v1/sse_hub.go` (`canReceive`, lines 134–144: private-memo events only delivered to the creator or an admin; unknown visibility is denied)
- Notification delivery — `server/notification/email.go` (`canViewerAccessMemo`, lines 306–320, gates what email recipients may see) and the equivalent in-app check `server/router/api/v1/user_service_notifications.go` (`canViewerAccessMemo`, lines 302–316)

So beyond the primary API check, visibility is independently enforced at the file server, RSS, sitemap, SSE, and notification surfaces — each of which reimplements the Public/Protected/Private rule rather than delegating to a single shared function.
