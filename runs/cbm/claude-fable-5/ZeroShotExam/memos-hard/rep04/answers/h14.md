**Computation site:** `server/runner/memopayload/runner.go` — the `RebuildMemoPayload` function (line 74), which delegates the actual content analysis to a single goldmark AST walk in `ExtractAll` in `internal/markdown/markdown.go` (line 356). The result is stored on the memo as `memo.Payload.Tags` and `memo.Payload.Property` (schema in `proto/store/memo.proto`, `MemoPayload.Property`).

**Triggers:**
1. **Memo creation** — `CreateMemo` calls `RebuildMemoPayload` before inserting (`server/router/api/v1/memo_service.go:108`).
2. **Memo update, only when the `content` field is in the update mask** — `UpdateMemo` recomputes the payload alongside the new content (`server/router/api/v1/memo_service.go:447`); updates to visibility, pinned state, etc. don't recompute it.
3. **Bulk rebuild** — `Runner.RunOnce` in `server/runner/memopayload/runner.go:27` re-derives the payload for every memo in batches of 100 (a maintenance/migration path; note it is not currently wired into the startup sequence in `server/server.go`, which only invokes the s3presign runner).

**Extracted properties** (from the parsed markdown AST):
- `Tags` — all `#tag` nodes, deduplicated case-preservingly
- `Property.Title` — text of the first H1 heading, if it is the document's first block
- `Property.HasLink` — presence of any link node
- `Property.HasCode` — presence of code blocks, fenced code blocks, or inline code spans
- `Property.HasTaskList` — presence of task checkboxes
- `Property.HasIncompleteTasks` — at least one unchecked checkbox

(`ExtractAll` also collects `@mentions`, but those are used for notifications via `memo_mention_helpers.go`, not stored in the payload.)
