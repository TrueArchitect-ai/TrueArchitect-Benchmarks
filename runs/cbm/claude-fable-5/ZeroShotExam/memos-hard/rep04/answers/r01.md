**Premise correction:** There is no Redis in this repository — no Redis client, connection config, or dependency exists anywhere (nothing in `go.mod`, no `redis`/`ioredis` references in the codebase). The cache layer is not Redis-backed.

**Actual mechanism:** The cache is a custom thread-safe **in-memory** cache implemented in `store/cache/cache.go` (a `sync.Map` with per-item expiration, a periodic cleanup goroutine, and a max-items eviction policy). The store wires it up in `store/store.go:38-53`, where `Store.New` creates three cache instances — `instanceSettingCache`, `userCache`, and `userSettingCache` — all sharing the same hardcoded config:

- `DefaultTTL: 10 * time.Minute`
- `CleanupInterval: 5 * time.Minute`
- `MaxItems: 1000`

**TTL for user entries:** User entries are written via `s.userCache.Set(...)` (e.g. `store/user.go:98,122,132,143,167`), which delegates to `SetWithTTL` using the default TTL (`store/cache/cache.go:93-95`). So user cache entries live for **10 minutes**, with expired items also swept every 5 minutes by the cleanup loop. This is process-local memory only — nothing is externally configured, and there is no connection to configure.
