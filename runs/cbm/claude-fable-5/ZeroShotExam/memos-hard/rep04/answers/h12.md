**Concrete method:** `(*DB).CreateMemo` in `store/db/sqlite/memo.go:16` — the SQLite driver implementation, which builds and executes the `INSERT INTO memo (...)` statement.

**Determination method:** There are three candidate implementations of `CreateMemo` (in `store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, and `store/db/postgres/memo.go`), all satisfying the `store.Driver` interface that `(*Store).CreateMemo` dispatches through (`store/memo.go:113` calls `s.driver.CreateMemo`). Which one actually runs is decided at startup by runtime driver selection, not statically:

1. `cmd/memos/main.go:122` sets `viper.SetDefault("driver", "sqlite")` and line 130 defines the `--driver` flag with default `"sqlite"` — so with no database flags, the profile's `Driver` field is `"sqlite"` (and `internal/profile/profile.go:110` fills in a default SQLite DSN when none is given).
2. `store/db/db.go:18-20` (`NewDBDriver`) switches on `profile.Driver`; the `"sqlite"` case constructs `sqlite.NewDB`, so the `store.Driver` interface is bound to the SQLite `*DB`.

Therefore in a default installation, saving a memo flows API → `(*Store).CreateMemo` (`store/memo.go:109`) → the SQLite driver's `CreateMemo` (`store/db/sqlite/memo.go:16`), which executes the INSERT. The MySQL and Postgres versions are dead paths unless `--driver` is explicitly set.
