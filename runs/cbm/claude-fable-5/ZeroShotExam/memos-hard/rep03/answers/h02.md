delivery function — `Post` (with `PostAsync` queueing onto a bounded worker pool) in `internal/webhook/webhook.go`. This is where the outbound HTTP POST is built and sent (`internal/webhook/webhook.go:120`), invoked when memo content changes via `server/router/api/v1/memo_service_webhooks.go`.

protection mechanism — a two-layer SSRF guard in the `internal/webhook` package:

1. **Dial-time blocking** (`internal/webhook/webhook.go:59`): all deliveries go through `safeClient`, whose transport uses `safeDialContext`. It re-resolves the target host at connection time and refuses to dial any address matching a reserved/private range — this also defeats DNS-rebinding, since the check happens on every dial rather than only at registration.
2. **Registration-time validation** (`internal/webhook/validate.go:62`): `ValidateURL` rejects webhook URLs that aren't http/https or that resolve to reserved IPs when a webhook is created/updated.

The blocked ranges are defined in `reservedCIDRs` / `isReservedIP` in `internal/webhook/validate.go:14-54` — loopback, RFC-1918 private ranges, link-local (including the cloud metadata address 169.254.169.254), and IPv6 equivalents. An escape hatch, `AllowPrivateIPs` (`internal/webhook/validate.go:41`), lets self-hosted deployments disable the guard deliberately.
