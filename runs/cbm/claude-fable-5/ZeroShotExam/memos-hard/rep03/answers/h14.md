The derived metadata is the memo's `payload` — the `tags` list and the `Property` message (`proto/store/memo.proto:7-22`), which the proto itself annotates as "The calculated properties from the memo content."

**Computation site:** `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`. It calls `markdownService.ExtractAll` (`internal/markdown/markdown.go:356-422`), which parses the memo's markdown into a goldmark AST and walks it in a single pass, then assigns the results to `memo.Payload.Tags` and `memo.Payload.Property`.

**Triggers:**
- `CreateMemo` — `server/router/api/v1/memo_service.go:108`, run on every memo creation (before the store insert; a user-supplied `Location` is merged in afterward, since location is not derived).
- `UpdateMemo` — `server/router/api/v1/memo_service.go:447`, run only when the update mask includes the `"content"` path, so the payload is recomputed exactly when the content changes.
- Bulk rebuild: the `memopayload.Runner.RunOnce` in the same file (`runner.go:27-72`) re-derives the payload for all memos in batches of 100. Note this runner is defined but not currently wired into server startup (`server/server.go` only invokes the `s3presign` runner), so in practice it's a backfill utility.

**Extracted properties** (from the AST walk in `ExtractAll`):
- `tags` — all `#tag` nodes, deduplicated case-preservingly (`markdown.go:376-378, 418`)
- `property.title` — text of the first H1 heading, only if it's the document's first block (`markdown.go:383-389`)
- `property.has_link` — any link node (`markdown.go:393-394`)
- `property.has_code` — code block, fenced code block, or code span (`markdown.go:396-397`)
- `property.has_task_list` / `property.has_incomplete_tasks` — task checkboxes, with unchecked ones setting the incomplete flag (`markdown.go:399-405`)

(`ExtractAll` also collects `@mentions`, but `RebuildMemoPayload` stores only tags and the property struct in the payload.) These fields power list filtering/previews, e.g. via the memo filter and RSS/webhook converters.
