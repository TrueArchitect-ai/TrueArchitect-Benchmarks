**Premise correction:** There is no Redis in this repository. Nothing in the codebase references Redis, ioredis, or any external cache service — the cache layer is a purely in-process, in-memory Go cache.

**Actual mechanism:**

- The cache implementation lives in `store/cache/cache.go` — a thread-safe in-memory `Cache` type with per-entry TTLs, a background cleanup goroutine, and a max-item cap.
- The connection-free "configuration" happens in `store.New()` in `store/store.go:38-53`, where three caches are created (`instanceSettingCache`, `userCache`, `userSettingCache`) with a shared `cache.Config`:
  - `DefaultTTL: 10 * time.Minute`
  - `CleanupInterval: 5 * time.Minute`
  - `MaxItems: 1000`

**TTL for user entries:** User entries are written via `s.userCache.Set(...)` in `store/user.go` (e.g. lines 98, 122, 132, 167), which uses the default TTL — so **10 minutes**. No custom `SetWithTTL` is used for users, and no Redis endpoint or TTL setting exists anywhere in the configuration.
