**Yes — but only once, in a unit test inside the MySQL package itself; never in non-test code.**

Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go:14-32`, which constructs the MySQL driver via `mysql.NewDB(profile)` at `store/db/db.go:22` when the profile's driver is MySQL (alongside the sqlite and postgres branches).
- A repo-wide grep shows `store/db/db.go` is the **only** file that imports `github.com/usememos/memos/store/db/mysql`, so no other package can call `mysql.NewDB` or build a `mysql.DB` — and grep confirms no other call sites exist. (The only other direct `NewDB` calls in the codebase are `sqlite.NewDB` in `store/demo_seed_test.go:24` and `store/deployment_config_test.go:416`, which are the SQLite driver, not MySQL.)
- The one direct construction outside the factory is `db := &DB{}` at `store/db/mysql/auth_config_test.go:12`. This is a package-internal unit test (`package mysql`) that builds a bare `DB` struct literal — bypassing `NewDB` entirely — just to exercise the `IsRetryableAuthenticationMutationError` method against synthetic `MySQLError` values; it never opens a real connection.

So: in production code, the MySQL driver is constructed exclusively through the factory in `store/db/db.go`; the sole direct construction is the zero-value struct in the driver's own test file.
