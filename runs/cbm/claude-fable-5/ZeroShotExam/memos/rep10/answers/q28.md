The server starts exactly one background runner (see `server/server.go:153-174`, `startBackgroundRunners`, called from `Server.Start` at `server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — run once immediately at startup via `RunOnce(ctx)`, then continuously in a goroutine driven by a `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `runner.go:27-41`). It re-presigns S3 attachment URLs. Shutdown is via per-runner `context.CancelFunc` plus a `sync.WaitGroup`.

Unused scheduling infrastructure:

- **`internal/scheduler`** — a full cron-style job scheduler package (5/6-field cron parsing, timezones, middleware, graceful shutdown; see `internal/scheduler/scheduler.go` and its README). It is imported by nothing outside its own package and tests — the server never instantiates it. All actual scheduling is done with a plain `time.Ticker`.
- **`server/runner/memopayload`** (`server/runner/memopayload/runner.go`) — has the same Runner shape (`NewRunner`, `RunOnce`) but is never started as a background runner; `NewRunner` has no callers. Only its standalone helper `RebuildMemoPayload` is used, synchronously, from `server/router/api/v1/memo_service.go:108` and `:447` during memo create/update.
