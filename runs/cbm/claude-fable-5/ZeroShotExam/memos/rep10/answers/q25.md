**Engine:** CEL (Common Expression Language), via `github.com/google/cel-go`. **Path:** `internal/filter/` (`engine.go`, `parser.go`, `ir.go`, `render.go`, `schema.go`).

**Mechanism:** `ListMemos` in `server/router/api/v1/memo_service.go` passes the filter string down to the store, where each dialect driver (e.g. `store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo_relation.go`, `store/db/postgres/memo_relation.go`) calls the filter engine's `CompileToStatement` with its `filter.DialectName` (`sqlite` / `mysql` / `postgres`, defined in `internal/filter/schema.go`). The engine compiles the expression in a CEL environment built from the memo schema (`engine.go`), walks the parsed CEL AST into a dialect-agnostic `Condition` tree — folding the `now` variable to a frozen constant (`parser.go`, `ir.go`) — and then a per-dialect renderer (`render.go`) turns that tree into a parameterized SQL WHERE fragment plus args, using the schema's per-dialect column expression templates (e.g. `('users/' || %s)` for SQLite/Postgres vs `CONCAT('users/', %s)` for MySQL).
