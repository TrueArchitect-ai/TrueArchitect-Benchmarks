When the API deletes a memo (the v1 memo service calls `Store.DeleteMemo`), the store layer at `store/memo.go:140-159` deletes these records before removing the memo row itself:

- **Memo relation records** (`memo_relation`) — deleted twice: once where the memo is the source (`MemoID`) and once where it is the target (`RelatedMemoID`) of the relation (`store/memo.go:142-147`)
- **Attachment records** linked to the memo — it lists attachments with `FindAttachment{MemoID: ...}` and deletes each via `DeleteAttachment` (`store/memo.go:149-157`)

Only after those cleanups does it call `s.driver.DeleteMemo` to delete the memo row itself (`store/memo.go:158`).
