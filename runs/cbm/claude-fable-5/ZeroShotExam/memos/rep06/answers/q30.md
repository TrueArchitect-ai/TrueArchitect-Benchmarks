The memo lifecycle webhook dispatchers are all defined in `server/router/api/v1/memo_service_webhooks.go`:

- memo created (`memos.memo.created`): `DispatchMemoCreatedWebhook`
- memo updated (`memos.memo.updated`): `DispatchMemoUpdatedWebhook`
- memo deleted (`memos.memo.deleted`): `DispatchMemoDeletedWebhook`
- memo comment created (`memos.memo.comment.created`): `DispatchMemoCommentCreatedWebhook`

Delivery convergence: the first three funnel through the shared helper `dispatchMemoRelatedWebhook` (same file, line 48), and all four — including the comment dispatcher, which builds its payload directly — ultimately call `webhook.PostAsync` in `internal/webhook/webhook.go:184`. `PostAsync` enqueues the payload onto `asyncPostQueue`, whose worker goroutines (started in the package `init`) perform the actual HTTP delivery via `webhook.Post` (`internal/webhook/webhook.go:120`), which marshals the payload, signs it (HMAC-SHA256 `webhook-signature` headers when a signing secret is set), and POSTs it to the hook URL.
