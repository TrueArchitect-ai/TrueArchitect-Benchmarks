MemoService is exposed via **Connect RPC** and **REST/HTTP via gRPC-Gateway**:

- **Connect RPC** — `server/router/api/v1/connect_handler.go`, where `RegisterConnectHandlers` mounts `wrap(apiv1connect.NewMemoServiceHandler(s, opts...))` on the mux (line 40); the Connect method wrappers for MemoService live in `server/router/api/v1/connect_services.go`.
- **REST (HTTP/JSON) via gRPC-Gateway** — `server/router/api/v1/v1.go`, where `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` (line 108) registers the service on the gateway mux, served under `/api/v1/*`.

Notably, plain gRPC is not one of the two: `RegisterMemoServiceServer` is never called outside the generated code in `proto/gen/`. The comment in `connect_handler.go` confirms the wrapper pattern reuses the gRPC-style service implementations for both the Connect and gateway paths.
