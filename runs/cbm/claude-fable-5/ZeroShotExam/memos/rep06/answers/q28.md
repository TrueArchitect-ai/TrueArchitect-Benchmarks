The server starts exactly one background runner.

- **S3 presign runner** (`server/runner/s3presign/runner.go`) — started in `startBackgroundRunners` in `server/server.go:153-174`. It first executes immediately via `RunOnce(ctx)` at server startup, then runs in a goroutine driven by a plain `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). Shutdown is via per-runner `context.CancelFunc` plus a `sync.WaitGroup`.

That's it — nothing else in `Start()`/`startBackgroundRunners()` launches any other worker (the only other goroutines are the HTTP server itself and the signal-handling shutdown goroutine in `cmd/memos/main.go:99`).

Two pieces of infrastructure that look like scheduling/worker code are **not** started by the server:

- **`internal/scheduler`** — a full cron-style scheduler package (cron expression parser, timezone support, middleware, graceful shutdown; see `internal/scheduler/scheduler.go` and its README). It is not imported by any code outside its own package and tests — the server never uses it. The s3presign runner uses a raw `time.Ticker` instead.
- **`server/runner/memopayload`** (`server/runner/memopayload/runner.go`) — has the same `Runner`/`RunOnce` shape as s3presign, but it is never registered as a background runner. Only its standalone `RebuildMemoPayload` function is called, synchronously, from the API layer when memos are created/updated (`server/router/api/v1/memo_service.go:108,447`).
