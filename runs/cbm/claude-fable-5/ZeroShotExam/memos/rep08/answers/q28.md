The server starts exactly **one** background runner, in `Server.Start` → `startBackgroundRunners` (`server/server.go:129,153-174`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — run once immediately at startup via `RunOnce(ctx)`, then continuously in a goroutine via `Run(ctx)`, which is driven by a plain `time.NewTicker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `runner.go:27-41`). Shutdown is via per-runner `context.CancelFunc` plus a `sync.WaitGroup` (`server/server.go:176-201`).

Nothing else is started as a background worker — `cmd/memos/main.go` only spawns the HTTP serve goroutine and a signal-handling goroutine for graceful shutdown.

Unused infrastructure:

- **`internal/scheduler`** — a full GitHub-Actions-style cron job scheduler (cron expression parser, jitter, timeout, retry; `internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `doc.go`) is present but **never imported by the server**. Its only importers are its own tests (`internal/scheduler/example_test.go`, `integration_test.go`). The s3presign runner's 12-hour cadence uses a raw ticker, not this scheduler.
- Also worth noting: **`server/runner/memopayload`** defines a `Runner` with a batch `RunOnce` (`server/runner/memopayload/runner.go`), but the server never constructs or starts it as a runner. Only its standalone helper `RebuildMemoPayload` is called synchronously from the API layer (`server/router/api/v1/memo_service.go:108,447`).
