**Answer:** `web/src/connect.ts`; short-lived JWT access tokens (Bearer, ~15 min) plus a refresh token (30-day `memos_refresh` cookie) used to renew them; `server/auth`.

Details:

- **Interceptor:** `authInterceptor` in `web/src/connect.ts` (defined around line 156) is a Connect RPC `Interceptor` attached to the `createConnectTransport` used by all service clients. It attaches `Authorization: Bearer <access token>` to every request, does a preflight refresh if the token is within 30 s of expiry, and on a `Code.Unauthenticated` error refreshes the token once (via `X-Retry` header guard) and retries; failure redirects to login.
- **Tokens managed:** the short-lived **access token** (stored/rehydrated via `web/src/auth-state.ts` in localStorage, synced across tabs with BroadcastChannel) and the long-lived **refresh token**, which lives in an HTTP-only cookie sent with `credentials: "include"` — a separate interceptor-free transport calls `AuthService.RefreshToken` to mint new access tokens, deduplicated by a refresh manager shared with `web/src/hooks/useTokenRefreshOnFocus.ts`.
- **Backend validation:** the `server/auth` Go package (`server/auth/authenticator.go`, `server/auth/token.go`) — its `Authenticator` performs stateless JWT validation of access tokens (`AuthenticateByAccessTokenV2`/`ParseAccessTokenV2`, audience `user.access-token`), plus refresh-token and Personal Access Token (`memos_pat_` prefix) checks. It's consumed by the gRPC/Connect interceptors in `server/router/api/v1` and the file server.
