**Engine:** CEL (Common Expression Language, via `github.com/google/cel-go`); the filter engine lives in `internal/filter/`.

**Mechanism:** The `ListMemos` handler (`server/router/api/v1/memo_service.go`) validates the filter string and appends it to `memoFind.Filters`; each store driver (`store/db/sqlite/memo.go`, `store/db/mysql/memo.go`, `store/db/postgres/memo.go`) then calls `filter.DefaultEngine()` and `filter.AppendConditions(...)` with its dialect constant. Inside the package, `Engine.Compile` (`internal/filter/engine.go`) compiles the string against a CEL environment built from a field schema, the parser (`internal/filter/parser.go`) converts the CEL AST into a dialect-agnostic condition tree (IR in `internal/filter/ir.go`), and a renderer (`internal/filter/render.go`) walks that tree to emit parameterized SQL per dialect (`DialectSQLite` / `DialectMySQL` / `DialectPostgres`), using per-dialect column/expression templates from `internal/filter/schema.go` (e.g. `CONCAT` vs `||`, `UNIX_TIMESTAMP` for MySQL timestamps).

**One-sentence summary:** ListMemos filters are CEL expressions compiled by the engine in `internal/filter/` into a dialect-neutral condition tree, which each database driver renders into placeholder-parameterized WHERE clauses for SQLite, MySQL, or Postgres via schema-defined per-dialect SQL templates.
