MemoService is served over **REST/HTTP (via grpc-gateway)** and **Connect RPC** — there is no native gRPC server (no `grpc.NewServer` outside generated code).

- **REST/HTTP (grpc-gateway)** — `server/router/api/v1/v1.go`: `RegisterGateway` calls `v1pb.RegisterMemoServiceHandlerServer(ctx, gwMux, s)` (line 108) and mounts the gateway mux on Echo at `/api/v1/*`. The generated gateway code is `proto/gen/api/v1/memo_service.pb.gw.go`.
- **Connect RPC** — `server/router/api/v1/connect_handler.go`: `RegisterConnectHandlers` registers `apiv1connect.NewMemoServiceHandler(s, ...)` (line 40), mounted at `/memos.api.v1.*` in `v1.go` (line 144). The per-method wrapping that adapts the gRPC-style implementations to Connect request/response types lives in `server/router/api/v1/connect_services.go` (the `// MemoService` section starting around line 304).

Both protocols share the same underlying implementation in `APIV1Service` (`server/router/api/v1/memo_service.go`); the Connect handler is a thin wrapper over it, as documented in `connect_handler.go`'s comments ("Support both native gRPC and Connect protocols" — though in practice the gRPC methods are only exposed through the gateway and Connect).
