The server starts exactly one background runner:

- **s3presign runner** (`server/runner/s3presign/runner.go`) — started in `Server.Start` → `startBackgroundRunners` (`server/server.go:129`, `server/server.go:153-174`). Scheduling: an immediate `RunOnce(ctx)` at startup, then a continuous loop driven by a `time.NewTicker` with `runnerInterval = 12 * time.Hour` (`server/runner/s3presign/runner.go:26-41`). It is stopped via a per-runner `context.CancelFunc` and tracked with a `sync.WaitGroup` on shutdown.

Unused scheduling infrastructure:

- **`internal/scheduler`** — a full GitHub-Actions-inspired cron scheduler (cron expression parser, jobs, middleware; `internal/scheduler/scheduler.go`, `parser.go`, `job.go`, `doc.go`) is present but imported by **nothing outside its own package** (only its own tests/examples). The server does not use it; the s3presign runner uses a plain `time.Ticker` instead.
- **`server/runner/memopayload`** (`server/runner/memopayload/runner.go`) — has a `Runner` with `NewRunner`/`RunOnce` shaped like a background runner, but `NewRunner` is never called anywhere; the server never starts it. Only its standalone helper `RebuildMemoPayload` is invoked synchronously from the API layer (`server/router/api/v1/memo_service.go:108`, `:447`) during memo create/update — not on any schedule.

(Adjacent but not a server-started runner: each `store/cache.Cache` spawns its own 5-minute cleanup-ticker goroutine in `cache.New` — `store/cache/cache.go:83`, `:200-207` — but that's internal to the store's caches, not part of `startBackgroundRunners`.)
