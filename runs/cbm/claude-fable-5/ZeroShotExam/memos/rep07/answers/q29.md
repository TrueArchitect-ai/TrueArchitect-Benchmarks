Frontend requests go through a ConnectRPC transport whose auth interceptor lives in `web/src/connect.ts` (`authInterceptor`, wired into `createConnectTransport` at web/src/connect.ts:156-189). On every request it attaches the current access token as an `Authorization: Bearer` header, proactively refreshes it if expired (via `getRequestToken`), and on an `Unauthenticated` error refreshes once and retries (marked with an `X-Retry` header), redirecting to login if the refresh fails.

It manages two token kinds:
- **Short-lived JWT access tokens** (~15 min), stored via `web/src/auth-state.ts` and sent in the `Authorization` header.
- **Refresh tokens**, held in an HTTP-only cookie (all requests use `credentials: "include"`); a separate interceptor-free transport calls `AuthService.refreshToken` to rotate the access token (`refreshAccessToken` in the same file).

On the backend, validation is done by the `server/auth` package — `server/auth/authenticator.go` defines `Authenticator`, which statelessly validates JWT access tokens (`AuthenticateByAccessTokenV2`), checks refresh tokens against the database for revocation (`AuthenticateByRefreshToken`), and also supports long-lived Personal Access Tokens (PATs); token extraction from headers lives in `server/auth/extract.go`. This authenticator is shared by the gRPC/Connect interceptors and the file server.

Answer format summary: `web/src/connect.ts`; JWT access tokens + refresh tokens (plus backend-side PATs); `server/auth`.
