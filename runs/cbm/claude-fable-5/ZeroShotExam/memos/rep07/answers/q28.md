The server starts exactly one background runner, in `Server.startBackgroundRunners` (`server/server.go:153-174`), called from `Server.Start` (`server/server.go:129`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — triggered by an immediate `RunOnce(ctx)` at startup (`server/server.go:163`), then driven by a `time.NewTicker` firing every 12 hours (`runnerInterval = time.Hour * 12`, `server/runner/s3presign/runner.go:27-41`). It runs in a goroutine with its own cancellable context and is tracked by a `sync.WaitGroup` for graceful shutdown.

Unused scheduling infrastructure:

- **`internal/scheduler`** — a full cron-style job scheduler package (cron-expression parser, `Job`, `Scheduler`, middleware, docs, and tests: `internal/scheduler/scheduler.go`, `parser.go`, `job.go`, etc.) is present in the codebase but is imported by nothing outside its own package. The server never instantiates it; the s3presign runner uses a plain `time.Ticker` instead.
- **`server/runner/memopayload`** — packaged as a "runner" with a `NewRunner`/`RunOnce` batch-rebuild API (`server/runner/memopayload/runner.go:19-72`), but the server never constructs or schedules it. Only its standalone helper `RebuildMemoPayload` is called synchronously from the memo API service (`server/router/api/v1/memo_service.go:108, 447`), so its background-runner machinery is effectively dead code.

(Other tickers in the code, e.g. the SSE heartbeat in `server/router/api/v1/sse_handler.go:64`, are per-connection request handling, not server-started background workers.)
