**Engine:** CEL (Common Expression Language), parsed with the `cel-go` library. **Path:** `internal/filter/` (entry point `filter.DefaultEngine()` in `internal/filter/engine.go`).

**Mechanism:** `ListMemos` passes the filter string into `MemoFind.Filters` (after `validateFilter` in `server/router/api/v1/memo_service.go:211-215`); each store driver (`store/db/sqlite/memo.go:57-61`, `store/db/mysql/memo.go:65-69`, `store/db/postgres/memo.go:54-58`) calls `filter.AppendConditions` with its dialect, and the engine runs a three-phase pipeline — cel-go parses/validates the expression against the memo schema (`schema.go`), `parser.go` normalizes the CEL AST into a dialect-agnostic IR (`ir.go`), and `render.go` walks the IR to emit a dialect-specific SQL fragment plus placeholder args, encapsulating differences like `?` vs `$n` placeholders, `JSON_EXTRACT`/`->>` JSON access, boolean coercion, and tag containment (SQLite `LIKE`, MySQL `JSON_CONTAINS`, Postgres `@>`).
