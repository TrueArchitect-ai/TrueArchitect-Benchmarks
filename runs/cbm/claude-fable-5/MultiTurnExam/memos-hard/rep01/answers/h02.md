**Delivery function:** `Post` in `internal/webhook/webhook.go:120` — it marshals the payload, optionally signs it with HMAC-SHA256, and sends the HTTP POST via the shared `safeClient` (`webhook.go:152`). Asynchronous dispatches go through `PostAsync` (`webhook.go:184`), which enqueues onto a bounded channel drained by worker goroutines that ultimately call the same `Post`.

**Protection mechanism:** SSRF guarding at dial time. `safeClient`'s transport uses `safeDialContext` (`internal/webhook/webhook.go:59`), which resolves the target hostname and refuses to connect if any resolved address falls in a reserved/private range — checked by `isReservedIP` against `reservedCIDRs` (loopback, RFC-1918, link-local/IMDS, and IPv6 equivalents) in `internal/webhook/validate.go:14-54`. Doing the check inside the dialer also defeats DNS rebinding. There is additionally an up-front check when webhook URLs are saved, `ValidateURL` (`internal/webhook/validate.go:62`), and an escape hatch `AllowPrivateIPs` (`validate.go:41`) for self-hosted deployments that intentionally target LAN services.

**Answer:** `webhook.Post` — `internal/webhook/webhook.go:120` (dispatched via `safeClient`); dial-time reserved/private-IP blocking via `safeDialContext` + `isReservedIP`/`reservedCIDRs` — `internal/webhook/webhook.go:59` and `internal/webhook/validate.go:14-54` (plus save-time `ValidateURL` at `validate.go:62`).
