The derived metadata is the memo's **payload** (`MemoPayload.tags` + `MemoPayload.Property`, defined in `proto/store/memo.proto:10-23`), computed from the markdown content.

**Computation site:** `memopayload.RebuildMemoPayload` — `server/runner/memopayload/runner.go:74` — which delegates the actual parsing to the markdown service's single-pass AST walk `ExtractAll` (`internal/markdown/markdown.go:355` onward).

**Triggers (recomputation happens on):**
1. **Memo creation** — `CreateMemo` calls `RebuildMemoPayload` before persisting: `server/router/api/v1/memo_service.go:108`. This also covers comment creation, since `CreateMemoComment` funnels into `CreateMemo` (`server/router/api/v1/memo_service_comments.go:56`).
2. **Content update** — `UpdateMemo`, when the field mask includes `content`, rebuilds the payload: `server/router/api/v1/memo_service.go:447`.
3. **Bulk rebuild** — the `memopayload.Runner.RunOnce` batch job re-derives payloads for all memos (`server/runner/memopayload/runner.go:27-72`), though as established earlier, this runner isn't wired into server startup in production.

**Extracted properties** (from `ExtractAll`, `internal/markdown/markdown.go`):
- `Tags` — every `#tag` node in the content (stored as `payload.tags`)
- `Property.Title` — text of the first block-level H1 heading, if present
- `Property.HasLink` — any link node
- `Property.HasCode` — code block, fenced code block, or code span
- `Property.HasTaskList` — any task checkbox
- `Property.HasIncompleteTasks` — any unchecked task checkbox
- (`Mentions` are also extracted in the same pass but used for notifications, not stored in `Property`)

These booleans/title/tags are exactly what list views and previews filter and render on without reparsing content.
