**Premise correction:** there is no Redis anywhere in this codebase — a repo-wide search for "redis" in Go sources returns nothing. The cache layer is a purely **in-process, in-memory cache** (`sync.Map`-based, with TTL expiry and a background cleanup goroutine), implemented in `store/cache/cache.go`. No external cache service is configured or connectable.

**Actual mechanism:** the store constructs three of these in-memory caches — `instanceSettingCache`, `userCache`, and `userSettingCache` — in `store.New` at `store/store.go:40-53`, all sharing the same config: **`DefaultTTL: 10 * time.Minute`**, cleanup every 5 minutes, max 1000 items (`store/store.go:40-45`, mirroring `cache.DefaultConfig()` in `store/cache/cache.go:57-63`).

So the TTL that applies to user entries: **10 minutes** (user rows are cached via `s.userCache.Set(...)` using the default TTL, e.g. in `Store.GetUser`, `store/user.go:167`), enforced in-process — not via Redis.
