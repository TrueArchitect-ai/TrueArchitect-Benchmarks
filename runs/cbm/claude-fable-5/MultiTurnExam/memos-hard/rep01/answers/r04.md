**Premise correction: neither.** There is no message broker in this codebase — no NATS, RabbitMQ, Kafka, or any external queue (a repo-wide search for those terms and their client libraries returns nothing, and `go.mod` contains no broker dependency).

**Actual mechanism:** webhook delivery is asynchronous but entirely in-process, built on a **buffered Go channel**:

- The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — declared in `internal/webhook/webhook.go:39`.
- The "workers" are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over the channel and calling `Post` (`webhook.go:120`) to execute the HTTP delivery, logging a warning on failure.
- Producers call `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send; if the 128-slot buffer is full, the dispatch is **dropped** with a warning rather than queued durably — so unlike a broker-backed design, there is no persistence, retry, or redelivery.
