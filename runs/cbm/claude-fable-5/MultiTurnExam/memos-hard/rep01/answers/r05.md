**Premise correction: this project has no GraphQL API.** A repo-wide search for "graphql" across Go and frontend sources returns no code hits — no schema files, no resolvers, no GraphQL dependency.

**Actual API surface:** the public API is **gRPC-based, defined in Protocol Buffers**:

- Schema definitions live in `proto/api/v1/*.proto` — `memo_service.proto`, `user_service.proto`, `auth_service.proto`, `attachment_service.proto`, `idp_service.proto`, `instance_service.proto`, `shortcut_service.proto`, `ai_service.proto`, `common.proto` (generated code under `proto/gen/`).
- These services are exposed over HTTP in two ways from the same definitions: a **Connect protocol** handler and a **gRPC-Gateway REST** mapping, both registered via `APIV1Service.RegisterGateway` (`server/router/api/v1/v1.go:65` onward), called from server setup at `server/server.go:88`.
- Non-RPC HTTP surfaces complement it: the file server (`server/router/fileserver/fileserver.go`), RSS feeds (`server/router/rss/rss.go`), and the frontend/sitemap routes (`server/router/frontend/frontend.go`).

So there is no GraphQL schema location to cite — the equivalent role is played by the protobuf files in `proto/api/v1/`.
