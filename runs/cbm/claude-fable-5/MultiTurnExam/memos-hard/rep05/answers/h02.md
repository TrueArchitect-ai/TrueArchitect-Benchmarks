**Delivery function: `Post` (with `PostAsync` as the async entry point feeding a worker queue) — `internal/webhook/webhook.go`; protection mechanism: dial-time SSRF guard `safeDialContext` / `isReservedIP` (plus creation-time `ValidateURL`) — `internal/webhook/webhook.go` and `internal/webhook/validate.go`.**

Details:

- **Where delivery executes:** `Post` in `internal/webhook/webhook.go:120` marshals the payload, optionally adds Standard-Webhooks HMAC-SHA256 signature headers, and sends the HTTP POST via the shared `safeClient`. Callers (e.g. `server/router/api/v1/memo_service_webhooks.go`) enqueue through `PostAsync` (`internal/webhook/webhook.go:184`), and four background workers started in the package `init` drain the queue by calling `Post`.

- **What blocks internal addresses:** all requests go through `safeClient`, whose transport uses `safeDialContext` (`internal/webhook/webhook.go:59`). At dial time it resolves the hostname and rejects any address matching `isReservedIP` (`internal/webhook/validate.go:44`), which checks the `reservedCIDRs` list — loopback, RFC-1918 private ranges, link-local/cloud-IMDS `169.254.0.0/16`, and IPv6 equivalents (`internal/webhook/validate.go:14-23`). Enforcing this at dial time also defeats DNS-rebinding, since the check happens on the addresses actually used for the connection. As a first line of defense, `ValidateURL` (`internal/webhook/validate.go:62`) applies the same reserved-IP check plus scheme validation when a webhook URL is registered. Self-hosted deployments can opt out via the `AllowPrivateIPs` flag (`internal/webhook/validate.go:41`).
