**Premise correction: neither — there is no message broker in this codebase at all.** A repo-wide search for NATS, RabbitMQ/AMQP (or Kafka) in the Go sources and `go.mod` returns nothing; no broker client is imported and no external queue is declared anywhere.

**Actual mechanism:** webhook delivery is fully in-process. The "queue" is a plain buffered Go channel, `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared in `internal/webhook/webhook.go:39`. Producers call `webhook.PostAsync` (`internal/webhook/webhook.go:184`), which does a non-blocking send into that channel and logs + drops the event if the buffer is full. The "workers" are four goroutines started in the package's `init` function (`internal/webhook/webhook.go:42-55`) that range over the channel and call `Post` (`internal/webhook/webhook.go:120`) to perform the actual HTTP delivery. Consequently, queued webhook deliveries are best-effort and are lost on process shutdown — there is no durable broker-backed persistence.
