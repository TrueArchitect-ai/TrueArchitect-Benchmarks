**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** A repo-wide search for rate-limit/throttle/limiter code finds nothing except a doc comment recommending that operators rate-limit email sending (`internal/email/doc.go:86`) — no implementation exists, and nothing registers such middleware, so there are no request limits to report.

What is actually registered:

- Echo HTTP middleware: only `middleware.Recover()` and a CORS middleware — `server/server.go:51-52`.
- Connect RPC interceptors: metadata conversion, logging, and auth (`server/router/api/v1/connect_interceptors.go`, wired in `server/router/api/v1/connect_services.go`) — none of them count or limit requests.

The closest things to throttling are not per-user rate limits: bounded concurrency semaphores in the API service (3 concurrent thumbnail generations, 2 concurrent image-processing operations — `server/router/api/v1/v1.go:59-60`), a content-length limit on memo bodies, and the bounded webhook dispatch queue (`internal/webhook/webhook.go:39`). All of these are global resource caps, not per-user request-rate enforcement.
