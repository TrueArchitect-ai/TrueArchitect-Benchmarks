Distinct memo-visibility enforcement sites across server surfaces:

- **gRPC/Connect API — memo read access check**: `checkMemoReadAccess` gates `GetMemo`, parent-memo access, and comment listing — `server/router/api/v1/memo_service.go:39` (used at lines 356, 367 and `server/router/api/v1/memo_service_comments.go:148`); list endpoints additionally constrain queries with `VisibilityList` / CEL filters in `ListMemos` (`server/router/api/v1/memo_service.go:219-225`) and `ListMemoRelations` (`server/router/api/v1/memo_relation_service.go:109-111`).
- **gRPC/Connect API — reaction endpoints**: listing/creating reactions re-checks the target memo's visibility — `server/router/api/v1/reaction_service.go:30-38, 83`.
- **gRPC/Connect API — attachment endpoints**: access to attachments linked to a memo follows the memo's visibility — `server/router/api/v1/attachment_service.go:436-451` (and line 255).
- **File server (raw file downloads)**: serving attachment bytes checks the linked memo's visibility (public requires anonymous-allowed instance; private only creator/admin) — `server/router/fileserver/fileserver.go:674-699`.
- **SSE event stream**: server-side delivery filtering drops events for memos the connected client may not see — `SSEClient.canReceive`, `server/router/api/v1/sse_hub.go:134-144`.
- **RSS feeds**: only `Public` memos are queried for instance and per-user feeds — `server/router/rss/rss.go:90, 141`.
- **Frontend router (sitemap)**: sitemap.xml only includes `Public` memos — `server/router/frontend/frontend.go:149-151`.
- **Email notifications**: `canViewerAccessMemo` prevents notification emails from exposing memos the recipient can't view — `server/notification/email.go:306-320`.
