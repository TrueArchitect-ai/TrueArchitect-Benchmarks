**No.** The MySQL driver is only ever constructed through the driver-selection factory.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:14`, which calls `mysql.NewDB(profile)` at `store/db/db.go:22` when the profile's driver is `"mysql"`.
- A repo-wide grep for imports of the driver package `github.com/usememos/memos/store/db/mysql` finds exactly one import site outside the package itself: `store/db/db.go:8`. No other file in the codebase imports the package, so nothing else can call `mysql.NewDB` or otherwise construct the driver directly.
- All other places that need a MySQL-backed store go through the factory: the test helpers call `db.NewDBDriver(profile)` (`store/test/store.go:28` and `store/test/store.go:50`), as does the benchmark setup (`server/router/api/v1/test/memo_service_benchmark_test.go:70`). They select MySQL only by setting `Driver: "mysql"` in the profile (`store/test/store.go:88`).
- The only other `mysql`-named references are unrelated to the driver package: `store/test/containers.go` uses the testcontainers `mysql` module to spin up a MySQL server container for tests, and string switches on the driver name in `store/test/migrator_upgrade_test.go`.
