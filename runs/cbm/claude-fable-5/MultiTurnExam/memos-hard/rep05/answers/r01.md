**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in the Go sources returns nothing. The cache layer is a purely in-process, thread-safe in-memory cache built on `sync.Map` — `Cache` in `store/cache/cache.go` — with TTL expiration, a periodic cleanup goroutine, and an item-count cap with oldest-first eviction. No external cache service is configured or connected.

**Actual mechanism and TTL for user entries:** the store constructs three of these in-memory caches (instance settings, users, user settings) in `store.New` at `store/store.go:52`, using an inline config of `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000`. User entries are written via `s.userCache.Set(...)` in `Store.GetUser`/`Store.ListUsers` (`store/user.go:148,136`), which uses the default TTL — so **user cache entries live for 10 minutes**, with expired items lazily dropped on `Get` and swept every 5 minutes by the cleanup loop (`store/cache/cache.go:200`). The same 10-minute default is also the package default in `cache.DefaultConfig()` (`store/cache/cache.go:57-64`).
