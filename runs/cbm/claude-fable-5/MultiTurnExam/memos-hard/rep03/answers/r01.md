**Premise correction: there is no Redis in this codebase.** A repo-wide search for "redis" (Go sources and configs) finds nothing. The cache layer is a purely in-process, in-memory cache implemented in `store/cache/cache.go` — a mutex/atomic-based map with per-item expiration, background cleanup, and eviction callbacks; no external connection of any kind is configured.

**Actual mechanism and user-entry TTL:** the store constructs three of these in-memory caches in `store.New` (`store/store.go:38-52`) — `instanceSettingCache`, `userCache`, and `userSettingCache` — all with the same explicit config: `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, `MaxItems: 1000` (`store/store.go:39-44`). User entries are written with `Set` (not `SetWithTTL`) at `store/user.go:132`, `store/user.go:143`, and `store/user.go:167`, so they get the default TTL — **10 minutes** — and are also purged eagerly on user update/delete. (The `cache` package's own `DefaultConfig` in `store/cache/cache.go:57-60` happens to use the same 10-minute default, but the store passes its own config rather than relying on it.)
