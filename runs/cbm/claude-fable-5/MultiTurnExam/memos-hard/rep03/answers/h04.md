**No.** The MySQL driver is constructed only inside the driver-selection factory.

Evidence:

- The factory is `NewDBDriver` in `store/db/db.go:14`, which calls `mysql.NewDB(profile)` at `store/db/db.go:22` when the profile's driver is MySQL.
- A repo-wide search for imports of the driver package (`github.com/usememos/memos/store/db/mysql`) and calls to `mysql.NewDB` finds exactly one importer outside the package itself: `store/db/db.go:8`. No other file imports the package, so nothing else can construct its `DB` type (whose constructor `NewDB` lives in `store/db/mysql/mysql.go`).
- Places that look MySQL-related but don't construct the driver: test helpers get their driver through the same factory — `store/test/store.go:28` and `store/test/store.go:50` call `db.NewDBDriver(profile)`. `store/test/containers.go:145` opens a raw `database/sql` connection with the third-party `go-sql-driver/mysql` (for spinning up test containers and readiness checks), which is not the repo's MySQL store driver.
