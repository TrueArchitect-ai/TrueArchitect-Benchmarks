**Premise correction: neither.** There is no message broker in this codebase at all — a repo-wide search for NATS, RabbitMQ/AMQP (and Kafka) across Go sources and `go.mod` finds no client library, no connection code, and no queue declaration.

**Actual mechanism:** webhook delivery is handled entirely in-process with a buffered Go channel acting as the queue:

- The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` — declared in `internal/webhook/webhook.go:39`.
- The "workers" are four goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`), each ranging over the channel and calling `Post` to perform the HTTP delivery (`webhook.go:120`).
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send; if the 128-slot buffer is full, the dispatch is dropped and a warning is logged rather than blocking the request path.

Consequently the queue is bounded, in-memory, and non-durable — pending webhook deliveries do not survive a server restart, unlike a broker-backed setup.
