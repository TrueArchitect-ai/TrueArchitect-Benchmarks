**Premise correction: there is no per-user API rate-limiting middleware in this codebase.** A repo-wide search for rate-limiting terms (`ratelimit`, `rate limit`, `throttle`, `limiter`, Echo's `middleware.RateLimiter`) finds no such middleware and no registration site, so there are no request limits to report.

What actually exists:

- The Echo server registers only `middleware.Recover()` and a CORS middleware at `server/server.go:51-52`; the API layer adds authentication/authorization interceptors, not rate limiters.
- The closest things to throttling are **concurrency** caps, which are global rather than per-user and bound resource usage, not request rates: weighted semaphores limiting concurrent thumbnail generation (`server/router/fileserver/fileserver.go:107,116,447-449`) and image processing (3 and 2 concurrent operations, `server/router/api/v1/v1.go:40-41,59-60`), plus a bounded queue for outbound webhook dispatch (`internal/webhook/webhook.go:39`).
- The only mention of rate limiting at all is an advisory comment in documentation for the email package ("Rate limit email sending to prevent abuse", `internal/email/doc.go:86`) — it is not implemented as middleware.
