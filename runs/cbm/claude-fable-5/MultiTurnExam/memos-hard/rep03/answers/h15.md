Memo visibility is enforced independently on four server surfaces:

- **gRPC/Connect API (memo reads)** — `checkMemoReadAccess` at `server/router/api/v1/memo_service.go:39` (public → allow; otherwise require login; private → creator only), applied in `GetMemo` (`memo_service.go:356,367`) and `ListMemoComments` (`server/router/api/v1/memo_service_comments.go:148`); list queries additionally constrain `VisibilityList` to Public/Protected for non-owners in `ListMemos` (`memo_service.go:219-225`). The same rule is re-implemented for adjacent resources: reactions (`server/router/api/v1/reaction_service.go:30-38,83`), memo attachments (`server/router/api/v1/memo_attachment_service.go:214-222`, `server/router/api/v1/attachment_service.go:445-451`), and user stats (`server/router/api/v1/user_service_stats.go:84-90,218-220`).
- **File server (raw attachment/file HTTP serving)** — the access check in `server/router/fileserver/fileserver.go:666-704`: loads the owning memo, allows anonymous access only for Public memos on instances permitting anonymous visitors, accepts a valid non-expired `share_token` as a fallback, otherwise requires an authenticated user and blocks Private memos from non-creator/non-admin (`fileserver.go:677,699`).
- **RSS feeds** — the RSS router only ever queries Public memos, hard-coding `VisibilityList: []store.Visibility{store.Public}` at `server/router/rss/rss.go:90` and `rss.go:141`.
- **SSE real-time event delivery** — the hub filters events per connected client in `SSEClient.canReceive` (`server/router/api/v1/sse_hub.go:134-144`): Private-memo events are delivered only to the creator or an admin; unknown visibility values are denied. Event visibility is stamped in `server/router/api/v1/sse_event_helpers.go:29-37`.
