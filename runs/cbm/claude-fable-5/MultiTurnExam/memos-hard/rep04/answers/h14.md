**Computation site: `RebuildMemoPayload` in `server/runner/memopayload/runner.go:74-88`, which delegates the actual parsing to `markdown.Service.ExtractAll` (`internal/markdown/markdown.go:356`); triggers: memo creation and content-changing updates; extracted: tags plus derived properties (title from a leading H1, has-link, has-code, has-task-list, has-incomplete-tasks).**

Details:

- **What it is:** each memo's `Payload` (a `storepb.MemoPayload`) carries `Tags` and `Property` derived from the markdown content — used for list filtering and previews — set by `RebuildMemoPayload`, never directly by the user (`server/runner/memopayload/runner.go:85-86`).
- **Where computed:** `RebuildMemoPayload` calls the goldmark-based `ExtractAll`, which does a single AST walk (`internal/markdown/markdown.go:371-411`) collecting everything in one parse.
- **Triggers:**
  - `CreateMemo` — payload built before insert (`server/router/api/v1/memo_service.go:108`); comment creation goes through the same path.
  - `UpdateMemo` — recomputed whenever the update mask includes new content (`server/router/api/v1/memo_service.go:446-449`).
  - A batch rebuild-everything runner also exists (`memopayload.Runner.RunOnce`, `server/runner/memopayload/runner.go:27`), but it is never constructed or invoked in production code — the per-operation triggers above are the live paths.
- **What's extracted** (`internal/markdown/markdown.go:362-408`):
  - `Tags` — every `#tag` node.
  - `Property.Title` — text of an H1 heading only if it's the document's first block (`markdown.go:384-389`).
  - `Property.HasLink` (any link node), `Property.HasCode` (code block/fenced block/code span), `Property.HasTaskList` (task checkbox present), `Property.HasIncompleteTasks` (any unchecked checkbox).
  - `ExtractAll` also collects `Mentions` (lowercased `@usernames`), but `RebuildMemoPayload` doesn't persist those in the payload — mentions are used separately for notifications (`server/router/api/v1/memo_mention_helpers.go`).
