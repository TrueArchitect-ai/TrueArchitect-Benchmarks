**1st: `store.User` (~6 outside packages); 2nd: `store.Memo` (~4 outside packages)**

The persistent entities are defined in the `store` package (`store/user.go`, `store/memo.go`, `store/attachment.go`, etc.), with the data layer comprising `store` plus the `store/db/*` drivers. Counting distinct non-test packages outside that layer that reference each type:

- **`store.User` — 6 packages:** `server/auth`, `server/notification`, `server/router/api/v1`, `server/router/api/v1/test` (helper package), `server/router/fileserver`, `server/router/rss`.
- **`store.Memo` — 4 packages:** `server/notification`, `server/router/api/v1`, `server/router/rss`, `server/runner/memopayload`.

Runners-up for context: `store.Attachment` ≈ 3 outside packages, and `store.Inbox`, `store.MemoShare`, `store.Reaction`, `store.IdentityProvider`, `store.UserSetting`, `store.MemoRelation`, `store.InstanceSetting` each ≈ 1-2. (Even if the test-helper package is excluded, `User` still leads 5 to 4.) The ranking is unsurprising: nearly every server subsystem needs the current user for authorization, while memo access is concentrated in the API, RSS, notification, and payload-rebuild code.
