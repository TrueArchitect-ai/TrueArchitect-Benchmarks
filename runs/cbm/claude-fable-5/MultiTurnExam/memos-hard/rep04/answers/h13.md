Details:

- **Interface:** `markdown.Service` (`internal/markdown/markdown.go:31-55`) defines extraction/rendering operations (ExtractAll, RenderHTML, GenerateSnippet, etc.).
- **Concrete implementation at runtime:** exactly one — the unexported `service` type wrapping a `goldmark.Markdown` instance (`internal/markdown/markdown.go:57-60`), built by `NewService` (`internal/markdown/markdown.go:85`) with GFM plus optional tag/mention extensions.
- **Who constructs it:** in production, a single instance is created in `NewAPIV1Service` with both tag and mention extensions enabled (`server/router/api/v1/v1.go:48-51`). That same instance is then shared with the RSS service — `server/server.go:85` passes `apiV1Service.MarkdownService` into `rss.NewRSSService`. (Tests build their own via `markdown.NewService` in `server/router/api/v1/test/test_helper.go:44`.)
- **Holders of the interface:** `APIV1Service.MarkdownService` (`server/router/api/v1/v1.go:35`), used for payload rebuilds, mention extraction, and webhook snippets (`memo_service.go:108,447`, `memo_mention_helpers.go:32`, `memo_service_webhooks.go:85`); and `RSSService.MarkdownService` (`server/router/rss/rss.go:45`), used for HTML rendering of feeds (`rss.go:339`). A third holder exists in code — `memopayload.Runner.MarkdownService` (`server/runner/memopayload/runner.go:16`) — but `memopayload.NewRunner` has no call sites, so that holder never exists at runtime; the memopayload package's `RebuildMemoPayload` function instead receives the APIV1Service's instance as an argument.
