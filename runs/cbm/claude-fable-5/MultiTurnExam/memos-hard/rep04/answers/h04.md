**No; the MySQL driver package is imported in exactly one place — the factory — so it can only be constructed there.**

Evidence:

- The driver-selection factory is `NewDBDriver` in `store/db/db.go`, which calls `mysql.NewDB(profile)` when the profile's driver is `"mysql"` (`store/db/db.go:22`).
- A repo-wide search for imports of `github.com/usememos/memos/store/db/mysql` finds only that one import site: `store/db/db.go:8`. No other file imports the package, so no other code can call `mysql.NewDB` or reference its `DB` type directly.
- Places that do touch MySQL elsewhere are not the driver: test infrastructure in `store/test/containers.go` uses the third-party `go-sql-driver/mysql` and testcontainers to spin up a MySQL server, and tests obtain a store driver exclusively through the factory (`db.NewDBDriver` at `store/test/store.go:28` and `store/test/store.go:50`). Some unit tests construct the SQLite driver directly (e.g. `sqlite.NewDB` in `store/demo_seed_test.go:24`), but that pattern is never used for MySQL.
