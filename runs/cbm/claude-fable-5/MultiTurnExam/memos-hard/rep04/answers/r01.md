**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" finds no hits in Go code, config files, or dependencies. The cache layer is a purely in-process, thread-safe in-memory cache.

Actual mechanism:

- The cache implementation is `store/cache/cache.go` — a `sync.Map`-based `Cache` type with per-entry TTL, periodic cleanup, and a max-item cap; no external service or connection is involved.
- The user cache is one of three such caches created in `store.New` (`store/store.go:47-53`): `instanceSettingCache`, `userCache`, and `userSettingCache`.
- **TTL for user entries: 10 minutes** — the `cache.Config` built in `store.New` sets `DefaultTTL: 10 * time.Minute` with a 5-minute `CleanupInterval` and `MaxItems: 1000` (`store/store.go:40-45`, matching `DefaultConfig()` in `store/cache/cache.go:57-63`). User entries are written with this default TTL via `Set` in `Store.GetUser`/`ListUsers` (`store/user.go:132,143,167`).
