Memo visibility is enforced independently on each server surface that can expose memo content:

- **gRPC/Connect API read check: `checkMemoReadAccess`** — `server/router/api/v1/memo_service.go:39-68` (applied in `GetMemo` at `:356`/`:367` and `ListMemoComments` at `server/router/api/v1/memo_service_comments.go:148`); list queries also constrain `VisibilityList` to Public/Protected for non-owners in `ListMemos` (`server/router/api/v1/memo_service.go:219-225`).
- **Per-handler private-memo checks in the API for adjacent resources** — reactions (`server/router/api/v1/reaction_service.go:38,83`), attachments (`server/router/api/v1/attachment_service.go:445-451`, `server/router/api/v1/memo_attachment_service.go:222`), comment creation on a related memo (`server/router/api/v1/memo_service_comments.go:41`), and mention-notification targeting (`server/router/api/v1/memo_mention_helpers.go:62-67`).
- **File server (attachment binary serving): `checkAttachmentPermission`** — `server/router/fileserver/fileserver.go` (~lines 655-705): public-and-anonymous-allowed passes, otherwise a share token or authenticated user is required, and private memos' files are limited to creator or admin (`fileserver.go:677,699`).
- **SSE event delivery: `SSEClient.canReceive`** — `server/router/api/v1/sse_hub.go:134-144`: private-memo events are delivered only to the creator or an admin; event visibility is attached in `server/router/api/v1/sse_event_helpers.go:29-37`.
- **RSS feeds** — queries are hard-restricted to `store.Public` visibility only (`server/router/rss/rss.go:90` and `:141`).
- **Frontend HTML/OpenGraph rendering** — memo lookups for meta injection are Public-only (`server/router/frontend/frontend.go:150`).
- **Email notifications: `canViewerAccessMemo`** — `server/notification/email.go:306-320`: memo content is included in an email only if the recipient could view the memo (admin, creator for private, any signed-in user for protected).
