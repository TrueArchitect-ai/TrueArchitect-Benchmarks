**Premise correction: neither — there is no message broker in this codebase at all.** Searches for NATS, RabbitMQ/AMQP (and Kafka) across the Go source and `go.mod` return zero hits.

Actual mechanism: webhook delivery is asynchronous but entirely in-process, built on a buffered Go channel.

- The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)` declared in `internal/webhook/webhook.go:39`.
- The "workers" are 4 goroutines started in the package's `init()` (`internal/webhook/webhook.go:42-55`); each ranges over the channel and calls `Post` to perform the HTTP delivery (`internal/webhook/webhook.go:120`).
- Producers enqueue via `PostAsync` (`internal/webhook/webhook.go:184-196`), which does a non-blocking send — if the 128-slot buffer is full, the dispatch is dropped with a warning rather than blocking the request path.

Consequences of this design worth noting: the queue is bounded and lossy (no retries, no persistence), and pending webhook deliveries do not survive a server restart — properties a broker-backed queue would change.
