**Premise correction: neither — there is no message broker in this codebase.** No NATS, RabbitMQ, or any other external queueing system appears anywhere (no such imports or configuration exist in the Go sources).

**Actual mechanism:** webhook delivery uses a plain in-process buffered Go channel. The "queue" is `asyncPostQueue = make(chan *WebhookRequestPayload, 128)`, declared at `internal/webhook/webhook.go:39`. The package's `init()` starts 4 worker goroutines that range over this channel and call `Post` for each payload (`internal/webhook/webhook.go:42-55`). Producers enqueue via `webhook.PostAsync` (`webhook.go:184-196`), which does a non-blocking send — if the 128-slot buffer is full, the dispatch is dropped and a warning is logged rather than blocking the request path. So delivery is asynchronous but entirely in-memory within the server process: nothing is persisted, and queued webhooks are lost on restart.
