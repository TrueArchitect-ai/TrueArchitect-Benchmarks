Distinct server surfaces that enforce memo visibility:

- **gRPC/Connect API service layer** — `APIV1Service.checkMemoReadAccess` (`server/router/api/v1/memo_service.go:39-67`) gates single-memo reads (public → anyone; protected → any authenticated user; private → creator only; archived → creator only). List endpoints enforce it via query filters/`VisibilityList` (`memo_service.go:219-225`), and the same pattern is applied in `memo_relation_service.go:109-111`, `user_service_stats.go:84-90, 218-220`, plus per-operation checks in `reaction_service.go:30`, `memo_attachment_service.go:214`, and `memo_service_comments.go:33`.
- **File server (attachment/blob serving)** — the access check in `server/router/fileserver/fileserver.go:666-704` loads the linked memo and enforces its visibility for attachment downloads: public served anonymously only if the instance allows it, a valid non-expired per-memo `share_token` grants access, otherwise an authenticated user is required and private memos are limited to creator/admin.
- **RSS feeds** — `server/router/rss/rss.go:90` and `:141` restrict the instance and per-user feeds to `store.Public` memos only via `VisibilityList`.
- **Frontend router (sitemap/SEO surface)** — `getSitemapXML` in `server/router/frontend/frontend.go:149-151` lists only `store.Public` memos when generating `sitemap.xml`, so non-public memo URLs are never exposed there.

That's four distinct surfaces: the API service layer, the file server, the RSS router, and the frontend/sitemap router.
