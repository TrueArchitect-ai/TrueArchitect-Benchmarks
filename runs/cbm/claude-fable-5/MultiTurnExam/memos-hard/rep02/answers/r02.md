**Premise correction: there is no per-user API rate-limiting middleware in this codebase — nothing to register, and no request limits exist.**

Evidence: repo-wide searches for rate-limit/throttle/limiter terms in Go sources find no rate-limiting implementation. The Echo server registers only two global middlewares at startup: `middleware.Recover()` and a CORS middleware (`server/server.go:51-52`); the API layer adds authentication/authorization interceptors (`server/router/api/v1/v1.go`), but no request-rate controls anywhere.

The closest things that do exist — and are not per-user rate limiting — are internal concurrency caps: semaphores limiting simultaneous thumbnail generation and image processing (`server/router/fileserver/fileserver.go:106-116`, and `thumbnailSemaphore`/`imageProcessingSemaphore` in `server/router/api/v1/v1.go`), plus a bounded webhook dispatch queue (`internal/webhook/webhook.go:39`). These protect server resources globally; they don't count or limit requests per user.
