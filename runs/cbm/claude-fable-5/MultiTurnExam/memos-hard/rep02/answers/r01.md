**Premise correction: there is no Redis anywhere in this codebase.** A repo-wide search for "redis" in Go sources returns nothing; the cache layer is a purely in-process, thread-safe in-memory cache implemented in `store/cache/cache.go` (`Cache` struct with a `map`, TTL expiration, periodic cleanup, and max-item eviction — see the comment at `store/cache/cache.go:66`). No external cache service is configured, and there are no connection settings to configure.

**Actual mechanism and TTL for user entries:** the store constructor `store.New` builds a `cache.Config` with `DefaultTTL: 10 * time.Minute`, `CleanupInterval: 5 * time.Minute`, and `MaxItems: 1000`, and creates three separate in-memory caches from it — `instanceSettingCache`, `userCache`, and `userSettingCache` (`store/store.go:40-53`). User entries go into `userCache` via plain `Set`, which applies the default TTL (`store/cache/cache.go:92-94`). So user cache entries live for **10 minutes**, in process memory, not in Redis.
