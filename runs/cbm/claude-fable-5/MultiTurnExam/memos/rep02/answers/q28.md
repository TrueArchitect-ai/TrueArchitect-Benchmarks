Runners actually started by the server (`Server.startBackgroundRunners`, `server/server.go:153-174`):

- **s3presign runner** (`server/runner/s3presign/runner.go`) — run once at startup (`RunOnce` at `server/server.go:163`), then driven by a plain `time.Ticker` firing every 12 hours (`runnerInterval = time.Hour * 12`, ticker loop at `server/runner/s3presign/runner.go:27-41`), cancelled via context on shutdown.

That is the only background runner the server starts. Two other pieces of scheduling-adjacent infrastructure exist but are **not** started as background workers:

- **memopayload** (`server/runner/memopayload/runner.go`) has a `Runner` with `NewRunner`/`RunOnce`, but nothing instantiates it — the server only calls its `RebuildMemoPayload` helper synchronously inside API handlers (`server/router/api/v1/memo_service.go:108,447`).
- **internal/scheduler** — a full cron-style scheduler package (`internal/scheduler/scheduler.go`, `job.go`, `parser.go`, etc.) is present but imported by nothing outside its own package; the server does not use it (the s3presign runner uses a raw `time.Ticker` instead).
