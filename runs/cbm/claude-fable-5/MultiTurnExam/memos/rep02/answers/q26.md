Tables affected when DeleteMemo runs:

- **memo** — the memo row itself, plus any comment memos deleted first by the API handler (`server/router/api/v1/memo_service.go:568-585`, driver DELETE at `store/db/sqlite/memo.go:237`)
- **memo_relation** — explicitly deleted for both directions (source and target) in `Store.DeleteMemo` (`store/memo.go:142-147`)
- **attachment** — attachments linked to the memo are listed and deleted via `Store.DeleteAttachment` (`store/memo.go:148-157`, row deletion in `store/attachment.go:132-149`, which also removes the blob from local/object storage — not a table)
- **memo_share** — removed by the database itself via `FOREIGN KEY (memo_id) REFERENCES memo(id) ON DELETE CASCADE` (`store/migration/sqlite/LATEST.sql:109`, `store/migration/postgres/LATEST.sql:108`)

Notably, `reaction` rows are listed for the deleted-memo webhook payload but are not deleted by this path (`server/router/api/v1/memo_service.go:545-549`), and the reaction table has no cascade FK.
