- Interceptor: **web/src/connect.ts** — an auth interceptor sets `Authorization: Bearer <token>` on every request (`setAuthorizationHeader`, line 97) and, on 401/expiry, transparently refreshes the access token through a deduplicating token-refresh manager that calls `AuthService.RefreshToken` (lines 30–90), with token storage helpers in `web/src/auth-state.ts`.
- Token kinds managed: a **short-lived JWT access token** (kept in memory/auth-state, sent as a Bearer header) and a **refresh token** (delivered via cookie to the `refreshToken` RPC endpoint, used to mint new access tokens). The backend additionally accepts long-lived **Personal Access Tokens (PATs)** as Bearer tokens for programmatic access.
- Backend validation: **server/auth** — `Authenticator` in `server/auth/authenticator.go` validates access tokens (`AuthenticateByAccessTokenV2`), refresh tokens (`AuthenticateByRefreshToken`, checked against the database), and PATs (`AuthenticateByPAT` via hash lookup), with `resolveBearer` dispatching between JWT and PAT forms.
