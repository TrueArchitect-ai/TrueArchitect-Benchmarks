**Tables: `memo`, `memo_relation`, `attachment`**

When DeleteMemo runs:

- `memo_relation` — `Store.DeleteMemo` (`store/memo.go:142-147`) explicitly deletes relation rows where the memo is either source (`memo_id`) or target (`related_memo_id`).
- `attachment` — `store/memo.go:148-157` lists attachments bound to the memo and deletes each via `Store.DeleteAttachment` (`store/attachment.go:132`), which also removes the underlying blob from local/S3 storage (not a table).
- `memo` — the driver then deletes the memo row itself (`store/db/sqlite/memo.go:237`). Additionally, the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:568-577`) first deletes all comment memos (child rows in `memo` found via comment-type relations), each of which triggers the same `memo_relation`/`attachment` cascade.

No other tables are touched by explicit cascade code (reactions are only listed for the webhook payload, not deleted here).
