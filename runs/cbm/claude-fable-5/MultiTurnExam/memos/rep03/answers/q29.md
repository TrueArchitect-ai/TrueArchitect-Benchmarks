**Interceptor:** `web/src/connect.ts` — it defines a ConnectRPC auth `Interceptor` that attaches `Authorization: Bearer <access token>` to every request (line 99), does a preflight refresh when the access token is near expiry, and reactively refreshes-and-retries on 401, with a `tokenRefreshManager` deduplicating concurrent refreshes. Token storage helpers live in `web/src/auth-state.ts` (`getAccessToken`/`setAccessToken`).

**Token kinds managed:** a short-lived **JWT access token** (~15 minutes, sent as a Bearer header) and a **refresh token** carried in an HTTP cookie (`credentials: "include"` on the refresh transport, line 60, calling the `AuthService.RefreshToken` RPC). The backend additionally supports long-lived **Personal Access Tokens (PATs)** for programmatic access.

**Backend validation package:** `server/auth` — `server/auth/authenticator.go` defines the shared `Authenticator` that validates JWT access tokens, refresh tokens (`AuthenticateByRefreshToken`), and PATs (`AuthenticateByPAT` via `Store.GetUserByPATHash`), used by the gRPC/Connect interceptors and the file server.
