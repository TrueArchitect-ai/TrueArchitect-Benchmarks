**memo, memo_relation, attachment**

`Store.DeleteMemo` (`store/memo.go:140-159`) explicitly cascades before deleting the memo row:

- **memo_relation** — two `DeleteMemoRelation` calls remove rows where the memo is either the source (`memo_id`) or target (`related_memo_id`)
- **attachment** — attachments linked to the memo are listed and each deleted via `Store.DeleteAttachment` (`store/attachment.go:132`, which also removes the underlying file/object storage, not a DB table)
- **memo** — finally the driver's `DeleteMemo` runs `DELETE FROM memo WHERE id = ?` (`store/db/sqlite/memo.go:237`)

Note the API handler `APIV1Service.DeleteMemo` (`server/router/api/v1/memo_service.go:518`) additionally deletes comment memos first — but those are also `memo` rows going through the same `Store.DeleteMemo` cascade, so no additional tables are touched.
