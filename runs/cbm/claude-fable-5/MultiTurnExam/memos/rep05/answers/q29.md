**Interceptor:** `web/src/connect.ts` — the `authInterceptor` (a ConnectRPC `Interceptor`) attaches a `Authorization: Bearer` header to every request, does a preflight refresh when the access token is near expiry, and on a 401 reactively calls the `AuthService.RefreshToken` RPC once and retries the request (marked with an `X-Retry` header), redirecting to sign-in if refresh fails. Token state itself (in-memory access token, expiry buffers, cross-tab sharing via BroadcastChannel) lives in `web/src/auth-state.ts`.

**Tokens managed:** a short-lived **access token** (JWT bearer token, kept client-side and refreshed proactively/reactively) and a **refresh token** (sent as an HTTP cookie to the `RefreshToken` endpoint to mint new access tokens).

**Backend validation package:** `server/auth` — `Authenticator` in `server/auth/authenticator.go` validates access tokens (`AuthenticateByAccessTokenV2`), refresh tokens (`AuthenticateByRefreshToken`), and personal access tokens (`AuthenticateByPAT`), with JWT logic in `server/auth/token.go`; it's invoked from the API middleware in `server/router/api/v1/v1.go` (gateway auth middleware) and the Connect handlers.
