- **Interceptor:** `web/src/connect.ts` — the `authInterceptor` (attached to the Connect transport at line 188) sets an `Authorization: Bearer <token>` header on every request and reactively refreshes on 401 via a dedicated no-interceptor `refreshAuthClient` transport; token state (in-memory storage, cross-tab sharing via BroadcastChannel, expiry buffers) lives in `web/src/auth-state.ts`.
- **Token kinds:** a short-lived **access token** (JWT sent as a Bearer header, managed by the frontend) and a long-lived **refresh token** (HTTP cookie set by the backend, `buildRefreshTokenCookie` in `server/router/api/v1/auth_service_session.go:45`, exchanged via the `RefreshToken` RPC). Personal access tokens are also accepted as Bearer credentials on the backend.
- **Backend validation package:** `server/auth` — `server/auth/authenticator.go` (`resolveBearer` for access/PAT tokens, `AuthenticateByRefreshToken` for the cookie, checked against the store) with JWT parsing in `server/auth/token.go` and credential extraction in `server/auth/extract.go`.
